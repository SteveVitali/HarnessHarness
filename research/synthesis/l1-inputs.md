# WS-L1 ratification inputs — assembled at Phase 1 synthesis (2026-09-10)

**Purpose.** The single input document for the WS-L1 language/ecosystem ratification that the orchestrator runs right after this synthesis under the ADR-0009 procedure (WS-L1 dossier §6.3). It collects, with citations, (i) every questionnaire answer Q-L1-01…14 (OQ-040…046), (ii) the host-ecosystem *requirements* each ratified Phase 1 contract imposes (properties only — no language, runtime, package ecosystem or framework is named anywhere in this file or its sources; CF-111), (iii) the hard-gate determination, (iv) the synthesis-owned answers (ADR-0049), and (v) the procedure the ratification subagent must follow. Preconditions P1–P3 of ADR-0009 §6.3 hold: the A3/A4/A5/B1 ADRs are ratified (ADR-0015…ADR-0029), every questionnaire item is answered with citations, and R-2.12.3 is still `open`.

## 2. Host-ecosystem requirements stated by the ratified contracts (properties, no technology)

### 2.1 IR (WS-A3, ADR-0015/0016/0017 — dossier §6.11, P1–P12)
P1 closed sums for kernel enums with exhaustive-consumer checking (native or schema + registry-completeness CI); P2 immutable product records with structural equality; P3 a single source of truth for the schema from which a language-neutral schema document and any bindings are generated and CI-checked; P4 deterministic canonical serialization (JCS-class) available or implementable in a few hundred lines; P5 cryptographic hashing of byte strings; P6 explicit registration of kinds (no runtime subclass discovery); P7 opaque byte payloads with hashes; P8 graph queries over small DAGs (≤10⁴ nodes); P9 effect-coverage and monotonicity checks as graph queries (no static effect system); P10 structural diff by identity (own implementation); P11 Unicode-preserving strings; P12 out-of-process implementability of every IR operation over the canonical encoding. **Veto:** WS-A3 vetoes only a candidate that cannot produce a byte-identical canonical form (P4) or generate the neutral schema (P3).

### 2.2 Compiler (WS-A4, ADR-0019/0021 — dossier §6.5)
Deterministic canonical serialization + hashing for schema-described documents; first-class JSON-Schema manipulation (subset transforms, inclusion checks, validation — every target's tool dialect is a JSON-Schema variant); schema-first generation of protocol bindings from the three published schema sources (MCP, ACP, A2A) with CI drift checks; an interpreter for a small typed plan language with exhaustive handling of node kinds; the compiler runnable as an out-of-process component exchanging typed documents; for C2 only, a sandboxed engine for *model-authored* code (a target surface, not a kernel requirement).

### 2.3 Composition (WS-A5, ADR-0023/0025 — dossier §6.6)
Deterministic canonical encoding + schema validation + content hashing of schema-described documents (= P3–P5); an operation-shaped binding mechanism for in-process variants; a process/transport boundary able to carry the variant-host verbs (WS-L1 §6.5 discipline: single source of truth, generated bindings, version handshake, exact pinning, hash-equal canonical events, no authority widening). Nothing requires closed sum types over variant tags.

### 2.4 Run ledger (WS-B1, ADR-0026/0027/0028/0029 — dossier §6.6, ten properties)
1 ordered append-only record store with atomic multi-record append and acknowledged durable flush; 2 exclusive-writer primitive (lease/lock with stale-holder detection) across processes on one host at Stage 0–1; 3 forward/reverse sequential scan and random access by `seq`/`event_id` through a rebuildable index; 4 content-addressed blob store with dedup, size limits, delete-by-address; 5 canonical serialization of envelope + payload stable across versions and implementations; 6 schema-versioned decoding accepting every historical version; 7 streaming tail (`subscribe`) with inclusive cursors; 8 hashing with domain separation (RFC 6962-style prefixes) and optional signatures; 9 compression at rest preserving canonical bytes on decode; 10 throughput target tens of events/s per run, event ≤ 64 KiB after offload, blobs to environment-snapshot scale — no exotic storage requirement. Plus arbitrary-precision integers and a deterministic serializer without a bespoke fork (ADR-0029 consequences). **Veto:** WS-B1 vetoes only on C3 (durability fit), scored against "owned event store + reconstruction".

### 2.5 Effect model (WS-B2, ADR-0030/0031/0032)
An executor boundary that accepts `(effect_id, attempt_no, idempotency_key)`, declares `dedup_support ∈ {none, executor, target}` and `dedup_window`, reports `detached_effect_ids[]` and `postcondition_results[]`, and implements `probe` where declared; monotonic clocks for local TTLs (non-Byzantine, bounded drift); all operations implementable out-of-process (T-LCD-12).

### 2.6 Identity (WS-L4, ADR-0036/0037/0038 — dossier §6.11, H1–H10)
H1 one canonicalizer for records shared by identity, ledger hashing and bundle manifests; H2 cryptographic hashing with algorithm agility (≥ 2 standardized 256-bit-class algorithms, streaming, constant memory); H3 deterministic tree serialization of directories; H4 content-addressed blob store (= B1 property 4); H5 arbitrary-precision integers and decimal strings; H6 Unicode-preserving strings; H7 ability to read a container/VM image digest and a source-control commit id from the host environment at resolution time (a boundary is acceptable); H8 credential-redaction helpers for recorded locators; H9 out-of-process implementability; H10 append-only name history with atomic append. None fires a hard gate; H1–H3 are weighted under C3/C6.

### 2.7 Measurement (WS-I1/I2, ADR-0042/0043/0045)
Incremental subscription to the durable tail (exporters are subscribers), monotonic clock access per measuring component (`measured_at`), integer arithmetic for `Money{micro_units}` and `*_ms` durations, structured attributes on events; scorers/judges/loaders callable per run across a boundary with identical results to in-process calls.

### 2.8 Provenance and resources (WS-L3, WS-L2)
No ecosystem requirement beyond the canonical form and hashing above; the label lattice, endorsement events and budget nodes are records and projections over the ledger (ADR-0033/0034/0035, ADR-0039/0040/0041).
