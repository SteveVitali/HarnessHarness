# ADR-0191 — Shared-state ownership and inter-agent communication: one writer per coordination object, conferred at spawn and fenced by the lease generation; events and artifacts by default; peer messages as labelled wakeup occurrences

**Status:** ratified, amended (Phase 4 synthesis)
**Owner workstream(s):** WS-F5 · **Phase:** 4 · **Related:** ADR-0026, ADR-0027, ADR-0034 (P2), ADR-0035, ADR-0040, ADR-0053, ADR-0054, ADR-0080, ADR-0130, ADR-0131, ADR-0138; OQ-013, OQ-081, OQ-105; R-2.6.5, R-2.6.3; CF-406…04, CF-411, CF-413; OQ-428/03/05/07

## Context

When more than one AgentProcess runs at once, some state becomes observable or writable by more than one of them: the parent's workspace, a memory scope, a plan artifact, an external ticket or branch, a budget. Every production harness read in WS-F5 §4 either isolates children completely (RAH, Anthropic, Symphony, Codex threads, the 2026 worktree consensus) or shares through a channel with no defined owner (Prime Agent's harness-state file, rewritten whole by two processes behind an mtime check — a check-then-act race in which the last replace wins silently; RAH's shared output file, safe only because writers are disjoint by convention). No audited system records *who owns* an object, and none labels an inter-agent message with authority or taint, so a sibling that read the open web can instruct its peer as plain text. Logos states the fix as a theorem condition ("every key has exactly one writer"), Symphony as an architectural rule ("serializes state mutations through one authority"), Cloudflare as a runtime property (one single-threaded owner per durable object), and the reference runtime already has it for the run ledger (ADR-0026 §5, one fenced writer per run). The question is whether to generalise that one primitive to every object a second process could write, or to leave shared state to convention.

## Options considered

1. **Isolation only** — children never share anything; results return as values or per-child files (RAH, Anthropic). Rejected as the *only* option: it cannot express `scoped_subtree`/`share` (ADR-0138 already ratified them), gives no answer for memory scopes and named artifacts that a parent and child both legitimately write, and leaves the "shared output file" as an unowned object.
2. **Optimistic shared writes with staleness checks** — any process writes; a version/mtime check detects concurrent modification (Prime Agent `harness.py`; Fowler's optimistic offline lock). Rejected: the check-then-act race loses writes silently unless the check and the replace are atomic under a single authority, which is option 4 by another name; and it gives the model a side channel that bypasses ownership.
3. **Pure message passing, no shared objects** (AutoGen runtime). Rejected as the sole model: workspaces and memories *are* shared objects in a coding harness; message passing is adopted for the communication half only.
4. **One writer per coordination object, conferred at spawn, fenced by the existing lease generation; events/artifacts by default; messages as labelled occurrences.** Chosen.
5. **Consensus among peers (leaderless)**. Rejected: every delegation here has a root run; no precedent in any audited harness; a C3 instrument does not need it.

## Decision

1. **Coordination objects (closed sum, HIR dialect).** `CoordinationObjectKey = ledger{run_id} | workspace{env_handle_id, subtree} | memory_scope{scope, store} | artifact_name{name} | resource{key: ResourceKey} | budget_node{budget_id}`; `ResourceKey` is a closed schema `{fs_path, host, port, tracker_item, vcs_ref, secret_ref, custom(ns, bytes)}` under canonicalisation (OQ-429 for namespaces).
2. **One owner per object (O-1).** `OwnershipRecord{object, owner: RunId, mode ∈ {exclusive, shared_read}, granted_by: EventRef, lease_ref, valid, on_owner_end ∈ {return_to_grantor, detach_to_owner}}`; at most one valid record per `(object, seq)`; `exclusive` = only the owner writes; `shared_read` = the owner writes, others read through `subscribe`/`project` and may only *propose*. A key nobody owns is unwritable.
3. **Conferred, never discovered (O-2).** Ownership arrives only by `control.subagent.spawned.ownership_grants[]` (a subset of the grantor's valid ownerships — attenuation, ADR-0053 D-1), by a ledgered `control.ownership.transferred{object, from, to, basis}`, or at `open_run` for the root run (its ledger, root environment handle, `run`/`session` memory scopes, root budget node). Returned in the same ledger transaction as the child's terminal event when `on_owner_end = return_to_grantor`; `detach_to_owner` is refused for `share`/`scoped_subtree` (ADR-0138 D4).
4. **Fenced (O-3) and mode-bound (O-4).** Every write to an owned object carries the owner's current `lease_generation` (writer lease for `ledger`/`memory_scope`/`artifact_name`/`budget_node`; `resource(key)` lease for `resource` and `workspace{share}`); stale ⇒ `Fenced` (ADR-0026). `fork_snapshot` ⇒ the child owns its own handle and no key of the parent's; `scoped_subtree` ⇒ `exclusive` on `workspace{parent_handle, subtree}` with `fs.write.allow = [subtree]`; `share` ⇒ no standing ownership — each write acquires `resource{fs_path}` at `prepare` in canonical sorted order over the effect's `resource_keys[]`, bounded by `TimeoutPolicy[resource]`, refused `ResourceLockTimeout` (typed; retry class per ADR-0107); undeclared resource keys ⇒ exclusive on the whole handle.
5. **Enforcement.** The reference monitor evaluates `check_write(effect_id, object) → ok | NotOwner{owner} | Fenced` at `prepare` as an eighth check for delegation-bearing runs (extends ADR-0035's seven; CF-408); a refusal is a typed observation to the model and an audit row. `ownership_table = project(runs, ownership_view, until_seq)` is a derived view with rebuild-equality (ADR-0026). Ownership is never authority (O-6): it raises no label and confers no credential (ADR-0080 ceilings; H3 mediation).
6. **Communication by events and artifacts by default.** Task in: the spawn payload as `ContextItem`s at the parent's label (child `ctx₀ = ctx(parent)`, ADR-0054). Results out: `control.subagent.result{child_run_id, child_head, result_ref, outcome}` referencing a content-addressed `ChildResult`; the parent reads the child's ledger through `read`/`project`, never its process memory; the grantor has implicit `shared_read` on `ledger{child}`.
7. **Peer messages are labelled occurrences.** `send_message(from, to: RunId | Broadcast{children | siblings | family}, body, delivery_mode ∈ {follow_up, steer}, idempotency_key) → Receipt{message_id, status ∈ {queued, delivered, refused{reason}, undeliverable}}` is `record_occurrence` on the receiver's `peer_message` subscription (ADR-0131; `Trigger.peer_message{from}` added by dialect bump — CF-409), delivered as `Cue.woken` at the receiver's next decision point (W-1…W-5: at-least-once occurrence, idempotent fire, never mid-effect), rendered as `ContextItem{kind: peer_message}` with label `⊔(ctx(from), (delegate, ∅, Public))` (ADR-0034 P2). **M-1** a message never satisfies a validator, endorses, widens a grant or budget, or moves an ownership (ADR-0035 rule 1). **M-2** `MessagingPolicy{parent_to_child: true, child_to_parent: true, sibling: false, broadcast: false, max_pending, coalesce}` is MUST-data of the sealed definition; a refused address is `MessageRefused{policy}`. **M-3** a message to a `finished` run is `undeliverable` unless a goal-scoped subscription exists. **M-4** every message is a delivered artifact (`context.artefact.delivered`) so `activated/followed` are measurable per profile (T-LCD-13).
8. **No side channels.** A process may not communicate by writing an object it does not own; shared plan/progress files are `artifact_name` objects with one owner and `MergeProposal`s from others (ADR-0192).

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-06/-07 (hosted children are children at the Hosting ABI boundary, ADR-0053 D-4; ownership grants `n/a`; no native field added), T-LCD-08 (`MessagingPolicy` is definition data; rendering of messages is a profile surface), T-LCD-10 (objects keyed by handles, `version_id`s and canonical keys, never names), T-LCD-12 (operations; out-of-process), T-LCD-13 (messages and results are delivered artifacts), T-LCD-15 (coordination metrics class-scoped). Not applicable: T-LCD-01/-03/-04/-05/-09/-11/-14 (T-LCD-05 engages only if a profile conditions a messaging default; T-LCD-14 is ADR-0193's). ADR-0024 rungs: ownership records, fence and check MUST-code; `MessagingPolicy` and grants MUST-data.

Negative precedent: prime-agent `prime-agent-runtime/src/rlm/harness.py` L177–200, L287–320 (mtime check + whole-file replace — lost-write hazard). The `OwnershipRecord` and the labelled peer message are `no-precedent / novel`.
- (c) Disconfirming evidence considered: the field's best results use isolation with no shared objects (S-064, S-036, S-584) — the default here *is* isolation and the ownership machinery only activates for declared `scoped_subtree`/`share`/memory/artifact sharing; STORM (S-582, `provisional`) reports gains from mediated shared writes — expressible as `share` mode under leases and left to the Lab; Prime Agent's sibling/broadcast default (S-116) — admitted as a `MessagingPolicy` value, not the default, because no audited system bounds a message's authority and MAST records the misalignment modes; overhead of a per-write ownership check — one projection lookup keyed by object, bounded by key granularity.
- (d) Conditionality: C3 only; assumes ADR-0130 leases with non-Byzantine clocks and ADR-0138 `derive` modes; sibling/broadcast messaging is off by default for every model tier until AC-F5-07 reports; external `resource` keys make the *claim* exclusive, not the external system transactional.
- (e) Build-stage assignment: C3 / Stage 4 first slice (`OwnershipRecord`, grants at spawn, `fork_snapshot` only, parent-mediated messaging over `Trigger.peer_message`, AC-F5-03/-05/-09); second slice (`scoped_subtree`/`share` with `resource(key)` leases, sibling/broadcast policy, AC-F5-01 share form).

## Consequences

WS-F3's `Delegate` procedure must emit `ownership_grants[]` and `reserved_keys[]` in `control.subagent.spawned` (CF-407) and may not implement any other hand-off channel; WS-H1 adds the ownership check at `prepare`; WS-B1 adds `control.ownership.*` and `control.message.*` classes and `Trigger.peer_message`; WS-D4's memory scope leases become ownership records; WS-L8 inherits ownership records as the process-level half of accountability; the Lab gains `MessagingPolicy` as a component-level factor. A child that needs to change a parent object must propose, not write.

## Reversibility

**Medium.** The object sum and the check are small kernel additions over existing leases; relaxing to optimistic shared writes later means deleting the check, not migrating data. Adding sibling messaging by default is a policy flip. Removing `resource` keys for external systems would reintroduce the Symphony-style in-memory claim set that ADR-0130 already rejected.
