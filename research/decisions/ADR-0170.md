# ADR-0170 — The web dev-tooling is a pure projection client: view catalogue, data contracts, human-provenanced writes, rendering invariants, and the C1/C2 staging

**Status:** ratified
**Owner workstream(s):** WS-K2 (with WS-K4 for the boundary verbs; WS-K1 for one-record-two-surfaces) · **Phase:** 3 · **Related:** ADR-0026/0027 (ledger, `project`, `subscribe`), ADR-0042/0044 (trace view, sinks), ADR-0045/0046/0013 (rows, protocol, granularities), ADR-0050 D1–D3 and §8 (boundary, language-use), ADR-0066…0071 (audit, approvals), ADR-0133…0135 (branches), ADR-0139…0141 (bundles); WS-J1/J2/J3/J4/J5 proposed ADRs; CF-358/02/03; OQ-130, OQ-390; R-2.11.2, R-2.11.4; T-LCD-07/-09/-14/-15

## Context

R-2.11.2 (C2, Could) names a web-based local dev-tooling surface: assembly UI, experiment launcher, trace/time-travel viewer, comparison dashboards, debugging. Phase 1–2 fixed every record such a surface could show — the run ledger and its views (ADR-0026), spans and cost views (ADR-0042/0043), results rows and analysis reports (ADR-0045; WS-J4/J5), approval requests (ADR-0070), audit views (ADR-0066), branch records (ADR-0133) — and fixed the boundary a surface crosses (ADR-0050 D2: records, never `RuntimePlan` execution, never permission decisions, never credentials or unhashed blobs). The audited product surfaces (Codex app-server clients, goose desktop, opencode app, gemini-cli devtools, OpenHands agent-server clients, Inspect View — WS-K2 §4c) converge on one shape — a projection client consuming a durable stream plus paged reads — and diverge exactly where they keep client-side state that decides something (opencode's client-side permission auto-accept) or where a rendering collapses a distribution into a number (leaderboards without intervals). The decision is what the surface *is* (a projection), what it *may write* (typed operations with human provenance), and which invariants keep the LCD trap from re-entering at the glass.

## Options considered

1. **Pure projection client over the ADR-0050 boundary; every view a rendering of a ratified record; writes only through kernel/Lab operations with human provenance** — chosen.
2. *Surface-owned application state* (a local database of runs/rows/annotations synced from the kernel, with its own query layer) — rejected: a second book (WS-I1 F1) that must be reconciled; every audited surface that kept one had to add reconciliation or destructive paths (goose `carried_forward`, opencode revert); violates ADR-0026's materialized-view rule.
3. *Surface computes derived analytics itself* (client-side intervals, ranks, cost totals) — rejected: WS-J4 fixes "render never recomputes"; a client-side recomputation cannot carry `report_id`/`generated_from` and cannot be reproduced (KA-12).
4. *Surface holds decision state* (remembered approvals, auto-accept maps, default budgets) — rejected: a widening the reference monitor never sees (ADR-0035 rule 1; CF-362); every "remember" is an `ApprovalLease` or a `HarnessRule` on the kernel side.
5. *Defer the whole surface to Stage 6 or drop it* — rejected: sponsor-named; the read-only slice is cheap because it renders records that exist anyway, and unattended runs (ADR-0069 Π-12, async approvals) need an inbox somewhere other than the terminal.

## Decision

1. **The web tooling is a pure projection client.** It holds no state of record; every view is `project(run | rows | records, view_kind, until)` or a `render(report, RenderSpec)` result, displayed with its `derived_from` watermark / `view_hash` / `report_id` / `registry_snapshot_id`; a client-side cache is admissible only if deleting it and replaying the operations yields an identical rendering (AC-K2-1).
2. **View catalogue V1–V12 with data contracts** (WS-K2 §6.1, adopted verbatim): V1 run browser (`read`/run index, `query_rows`); V2 trace viewer (`trace_view`, `read`, `context_view@until_seq`, `effect_ledger`, `cost_view`, `turn_phase_profile`, blobs by address, `ArtifactExposure`, `ir_refs` links); V3 time-travel viewer (ADR-0171 of this workstream); V4 assembly editor (`assemble(plan)`, `plan`, `apply`, `explain`, `AssemblyDiagnostic`, `AssemblyDiff`, `lcd_report`/`opacity_report`); V5 experiment launcher and monitor (`ExperimentSpec`, refusals, `expand`, `PowerReport`, experiment-ledger projections, `register/open/pause/resume/close`); V6 comparison dashboards (`AnalysisReport` via `render`, `strata_view` default); V7 leaderboard (`LeaderboardSnapshot`, L1–L9); V8 approval inbox (`security.permission.pending`, `ApprovalRequest`, `respond`); V9 audit views (`audit_view`, `verify`, `prove_inclusion`, `redact` requests); V10 registry browser (J2 `query/resolve`); V11 bundle/reproducibility view (`validate_bundle`, `ReproReport`); V12 live run console (§6.5 verbs). A view is admitted to the catalogue only if its data contract is a ratified record type and its writes are named operations.
3. **Writes carry human provenance and cross the boundary as operations.** Every surface-initiated write invokes a kernel or Lab operation with `provenance.origin = human(author_ref, role)` and a surface-session reference; the kernel evaluates authority as for any principal input (`IllegitimateEndorsement`, `AuthorityWidening`, `UnbudgetedArm`, `ForkPointNotCoherent`, … are rendered as typed errors, never absorbed). The surface never: stores a run/row/report/definition; computes a metric, interval, rank or cost total; resolves a reference or pins a version; decides, caches or widens a permission; samples the ledger; holds a provider credential or a `SecretRef` value.
4. **One record, two surfaces.** For every view the CLI (WS-K1) prints the same record from the same operation; the two renderings differ only in presentation (AC-K2-14). No record type exists "for the web".
5. **Dashboard rendering invariants R-D-1…8** (WS-K2 §6.3) are acceptance criteria: `n/a{reason}` is typed and never `0`/blank; factor coordinates are always reachable; ranks are `indistinguishable_sets` with intervals; every number links to `report_id`, `Cell.interval{method, substituted?}` and `computed_from[]`; `confirmatory | exploratory | preview` labels on every cell and `preview` never publishable; frontiers carry origin, membership probability and cost-confidence bands; hosted rows carry class/observability/capability badges and component-level tabs render `n/a{class}`; exports show their `LoweringLossReport` first.
6. **Ephemeral discipline at the glass.** Streaming deltas and `security.permission.requested{rendering}` are shown live from `subscribe` and never persisted by the surface; reconnect is replay-from-cursor then live with dedupe by `seq` (AC-K2-5).
7. **OQ-130 confirmed in contract terms.** Every view consumes only ADR-0050 D2 records plus the surface verb group of CF-359 through a client generated from the kernel's schema source over the local transport ADR-0050 D1 row 4 names; no view needs in-process kernel access; Q-L1-14 is not narrowed and ADR-0050 revalidation trigger 6 does not fire. The ecosystem binding itself is executed by ADR-0050's declared default and is not re-argued (ADR-0050 §8).
8. **Staging.** C0/Stage 1 (owed by WS-K4/L5): the surface verb group generated from the schema source; `durability` on every crossing frame. **C1/Stage 4:** V1, V2, V3 scrub-only, V5 monitor, V6 scorecard/comparison, V7, V8, V9, V10, V11 run bundles, with the full security battery (ADR-0172 of this workstream). **C2/Stage 5:** V4, V5 launcher, V3 operations, V6 frontier/surface/strata, V11 experiment bundles, V12. **C2/Stage 6:** evolution proposals rendered through V3/V6 (no new view kind). Out of scope: multi-user hosted mode, collaborative annotations as records (OQ-390), public leaderboard hosting (WS-L6).

**T-LCD statement.** Satisfies T-LCD-15 (R-D-1; AC-K2-2/12), T-LCD-09 (R-D-2), T-LCD-14 (V5 no-bypass, AC-K2-8), T-LCD-07 (R-D-7), T-LCD-06 (no IR/native contract change for hosted rows), T-LCD-10 (V4 shows `semantic_id` beside surface names), T-LCD-02/-05 (V4 shows opacity and debt records), T-LCD-13 (V2 renders the artifact chain), T-LCD-11 (R-D-8), T-LCD-12 (out-of-process client by construction). Not addressed: T-01/-03/-04/-08 (owned elsewhere). **ADR-0024 rung:** view data contracts, `SinkPolicy`, allow-lists are MUST-data of the surface process; the rendering invariants and boundary client are MUST-code on the surface side; no `HarnessRule` and no IR entity is introduced.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** stateless projection of durable lines into UI history (S-107 `thread_history_projection.rs`); page-don't-hydrate (S-107 `thread/read` docs, `thread/list` cursor/filters); replay-then-go-live with durable/transient frames (S-110 `session_socket.py`); eager SSE subscription (S-111 `handlers/event.ts`); snapshot-then-increments for diagnostics only (S-119 devtools); polling on a watermark file and ETag/304 live buffers (S-136 `_view/{notify,fastapi_server}.py`); the view-compiler shape — one lossless record lowered into views with pointers back (S-546 VCC, `provisional`, mechanism only; S-545 TraceView, S-548 SeaView overview-to-detail); configuration-level reporting (S-062 `provisional (mech)`); rank sets accepted in practice (S-510 via WS-J4, Tier A); client-side decision state as a failure (S-111 `permission-auto-respond.ts`).
- **(b) Source-code precedent:** codex `codex-rs/app-server-protocol/src/protocol/thread_history_projection.rs`, `v2/thread.rs` (`ThreadListParams`, `ThreadReadParams`) @0735c51; software-agent-sdk `openhands-agent-server/openhands/agent_server/session_socket.py` (`DurableFrame`, `go_live`) @3fc7b22; opencode `packages/opencode/src/server/routes/instance/httpapi/handlers/event.ts`, `packages/app/src/context/server-sdk.tsx` @9f8db11; inspect_ai `src/inspect_ai/_view/fastapi_server.py` (`/events`, `/pending-samples`) @75f4891; gemini-cli `packages/devtools/src/index.ts` @ed2ac40. The integrated catalogue with typed `n/a`, rank sets, replay badges and human-provenanced writes has no audited precedent as a whole — `no-precedent / novel` as an integration; every affordance is precedented.
- **(c) Disconfirming evidence considered:** (i) research tools ship no viewer (S-062, S-078 describe none; Managed Agents/Symphony have no local UI) — accepted; hence the thin read-only slice and the rule that nothing upstream depends on the surface existing; (ii) "users want a number and an order" — rank sets are accepted practice (S-510) and J5 permits in-set sorting with the boundary drawn; (iii) client-side caches are needed for responsiveness — admitted as caches under AC-K2-1, never as stores; (iv) a browser client may need a transport different from the subprocess client — true and already provided for by ADR-0050 D1 row 4 (b)/(c); the verb gap is a contract gap (CF-359), not a narrowing of Q-L1-14. None overturns.
- **(d) Conditionality:** assumes native participants with `ledger` observability for content tabs (hosted rows render at their declared level with `n/a`); assumes WS-K4 delivers the generated client and the surface verb group at Stage 1; assumes single-principal local use (multi-user identity is out of scope); independent of model tier, task class and budget — the surface renders whatever the records say.
- **(e) Build-stage assignment:** C1/Stage 4 read-only slice (V1, V2, V3-scrub, V5-monitor, V6 scorecard/comparison, V7, V8, V9, V10, V11-run) with ADR-0172's battery; C2/Stage 5 operations (V4, V5-launcher, V3-operations, V6 frontier/surface/strata, V11-experiment, V12); C2/Stage 6 evolution renderings; prerequisite C0/Stage 1 verbs owed by WS-K4/L5.

## Consequences

- WS-K4 must add a *surface verb group* (reads, projections, subscriptions with `durability`, branch operations, `respond`, audit proofs, Lab operations) generated from the schema source (CF-359); WS-B1 gains `branch_tree` as a view kind and an `ir_refs` index (CF-360).
- WS-K1 inherits AC-K2-14: every web view has a CLI rendering of the same record.
- WS-H7 records `responder_provenance{surface_session_ref}` on decisions taken through the surface; WS-H6 sees surface reads as `sink_deliveries`.
- The surface can be dropped or rewritten without changing any record or contract; the cost of the read-only slice is rendering code only.
- Dashboards cannot "simplify" a scorecard into a single number; product pressure to do so must go through an ADR that amends R-D-2/-3.

## Reversibility

**High.** The surface owns no record and no contract; replacing it costs the rendering code. The one sticky element is the surface verb group in the boundary contract (WS-K4), which the CLI needs anyway.
