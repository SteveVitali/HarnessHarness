# ADR-0181 — The variant-host boundary (`plugin_abi/1`): one kernel↔extension protocol over a closed placement sum, closed host callbacks, invariants V1–V6 (no authority crosses inward), hooks as meet-composed narrowing guards, and the four-layer plugin conformance contract

**Status:** ratified, amended (Phase 3 synthesis)
**Owner workstream(s):** WS-L5 (consumers: WS-K4, WS-J2, WS-H5, WS-H1, WS-F1, WS-A3, WS-E5/B5, WS-D1/D2, WS-G1, WS-I1, WS-L2, WS-J3/J5, WS-I5) · **Phase:** 3 · **Related:** ADR-0001/0005/0098 (the Hosting ABI is a different binding — CF-023/CF-208), ADR-0016/0017 (`HarnessRule`, β, `HirDiff`), ADR-0019 (closed-world rule), ADR-0023 decision 5 (variant-host boundary; locality on the registration), ADR-0025 (`instantiate`, `lifecycle.component.bound`, `BindFailure`), ADR-0026/0029/0030 (ledger, canonical form, effect lifecycle), ADR-0034/0035 (labels; no widening), ADR-0039/0040 (charging, reserve-before-spend), ADR-0042/0043 (scopes, measurement points), ADR-0050 D2–D4 and §8 (boundary verbs, codegen, pinning), ADR-0053 (TCB; "may withdraw, never create"), ADR-0057 (`SecretRef`), ADR-0060/0061 (containment, egress), ADR-0063 L5–L6 (out of process; taint), ADR-0099 (probe-first), ADR-0100 (helper; "executors report, never decide"), ADR-0110 (annotate-or-reject), ADR-0136 (environment handle), ADR-0152 (conformance suites); CF-141, CF-376…05, CF-382; OQ-075, OQ-165 (L5 half), OQ-258, OQ-353/-03, OQ-407…04; R-2.12.2

## Context

ADR-0023 decision 5 required that third-party variants bind out of process "through a variant-host boundary that reuses the WS-L1 §6.5 verb discipline … and declares its operations, schemas and a change signal the way MCP declares tools"; ADR-0050 D3/D4 made that boundary a C0/Stage-1 item co-owned by WS-K4 and WS-L5 and left third-party variants free to use any ecosystem; ADR-0063 L5 and CF-141 forbade in-process third-party code. The audit (dossier §4) found that every in-process extension API in the corpus hands the extension the host's internals — goose's `PlatformExtensionContext` (a reference to the extension manager and session store), Pi's `ExtensionAPI` (`exec`, `setModel`, `sendUserMessage`), opencode's `PluginInput` (an authenticated client to the host and a shell) — and that every hook mechanism lets hooks `allow`, rewrite proposals or transform prompts silently with last-plugin-wins composition (opencode `trigger` sequential mutable output; Pi `emitToolCall` first-block; Claude Code `permissionDecision: allow`, `updatedInput`). Outside the field, VS Code runs extensions in a separate host chosen by a declared placement, Extism exposes host functions as the plugin's only channel, and the component model forbids shared memory; goose already drives in-process, subprocess, container-placed and remote extensions through one operation-shaped trait selected by a data tag. Logos (S-073, `provisional`) reports the process-per-plugin architecture with authoritative state outside every process — which is ADR-0026's ledger plus ADR-0053's kernel.

## Options considered

1. **Reuse MCP as the variant protocol** (every variant is an MCP server; `call_tool` carries operations). *Rejected:* MCP is the sole *tool-supply* channel (ADR-0096) and its vocabulary is tools/resources/prompts; class operations (`propose` a context plan, `step` a control cue, `verdict` an evidence bundle) would be smuggled through tool calls, losing the closed-world rule's typing and conflating the model-facing catalog with the kernel's component slots (WS-J2 R-NM).
2. **Reuse the Hosting ABI** (a variant is a hosted participant). *Rejected:* hosted participants are `OpaqueProcess`es with no slots (ADR-0018; T-LCD-06); a variant fills a slot with a declared class contract; conflating them is CF-208's error.
3. **In-process plugin API for "trusted" plugins, out-of-process for the rest** (goose `platform`/`stdio`; Pi project trust). *Rejected:* trust by location or by a bit is the S-103/S-104 vector (ADR-0063 L1); the readable in-process APIs are the ones that hand out internals (F4).
4. **A per-kind protocol** (one-shot stdin/stdout for hooks; sessions for variants). *Rejected as separate protocols; kept as declared capabilities:* one session protocol whose verbs a plugin declares tri-state at `hello`, with `one_shot` as a declared property (T-LCD-07), avoids the intersection trap and shares the MCP stdio transport discipline.
5. **One variant-host protocol over a closed placement sum with closed host callbacks, the WS-L1 §6.5 invariants, narrow-only meet-composed guards, and a four-layer conformance contract (chosen).**

## Decision

1. **The variant host** is Core (MUST-code) and drives every non-kernel executable contribution — component variants, hooks/guards, validators, benchmark adapters — over `plugin_abi/1`, the kernel↔extension binding of the ecosystem-boundary contract (ADR-0050 D3; same schema source and codegen/CI discipline as the kernel↔surfaces binding owned by WS-K4). It is not the Hosting ABI and not MCP; MCP servers contributed by a plugin are *launched* under the same placement and containment but *spoken to* by the MCP client (ADR-0097).
2. **Placements** (closed sum; dialect bump to grow): `in_process` — first-party variants in the `hh/` namespace of the ADR-0050 kernel ecosystem only; `subprocess_confined` — default for every third-party variant and hook: the helper (ADR-0100) launches the plugin process under its own `ContainmentPolicy` (cleared environment + declared env keys; fs allowlist = the plugin's root + declared roots, never another plugin's root; no network unless granted; resource limits; kill-on-timeout); `container` — the session/environment container (ADR-0136); `remote` — under H4 egress policy with a `ProtocolBinding` (ADR-0099). `component_model` is reserved pending WASI 1.0 (OQ-410). `host_unconfined` is inadmissible for anything the kernel invokes on a decision path (variants, hooks, validators) — a narrowing of ADR-0063 (CF-380). The mapping `placement = IsolationClass − {host_unconfined}` replaces the two-valued `locality` fields of ADR-0023/WS-J2 as the registration's primary field, with `locality` derived (CF-378).
3. **Verbs.** `hello(plugin_abi_version, plugin{version_id, content}, contract_versions_offered, capabilities: TriState) → {host_id, negotiated, registry_snapshot_id, kernel_capabilities}` (probe-first; unknown fields rejected; `ProtocolVersionMismatch`; `PinMismatch` when the plugin's `version_id` differs from the sealed pin); `bind(slot, class_id, contract_version, variant, params, profile, account, budget) → binding_id | BindFailure` (atomic per slot; emits `lifecycle.component.bound{…, placement, host_id}`; T-LCD-08 by construction); `invoke(binding_id, operation, inputs[], reservation, deadline) → outputs[] | TypedFailure` (one ledger scope per invocation; reserve-before-spend); `stream` with `seq` resume; `cancel`; `unbind`; `close`. **Host callbacks (plugin → kernel), closed:** `propose_effect(Proposal) → EffectRef` (enters ADR-0100 `resolve → authorize → …` under the plugin's Permission; the plugin never executes effects and never receives a `KernelDecision`), `read_view(view_kind, until_seq)` (only projections the plugin's grants cover; never handles, Π, or other plugins' private records), `request_budget(amount)`, `emit_diagnostic(record)` (ephemeral L3; plugins propose, the kernel appends). No callback names another extension, the agent loop, the gateway, the session store or the reference monitor.
4. **Invariants (kernel-enforced; violations are refusals plus `security.extension.violation` events, never warnings).** **V1 No authority crosses inward:** no plugin message carries a `Permission`, a label, a `KernelDecision`, a lowered risk class or a raised retryability; outputs are stamped `origin = tool(extension_ref)`, `authority ≤ delegate` (model-derived) / `≤ external` (free text), `taint ∋ extension_id` — `AuthorityCrossing`. **V2 Byte-identical documents:** what the ledger records is what crossed (canonical `idp/1`; WS-L1 I4/CF-058). **V3 One plugin, one process, one policy:** no placement hosts two plugins' code in one process; no plugin process sees another plugin's root, socket or environment. **V4 No ambient channel:** `net.mode ∈ {none, mediated}`; secrets only as `SecretRef` (ADR-0057); the attribution token is not a credential (ADR-0100 I-2). **V5 Exact pinning both ways** (WS-L1 I3). **V6 Single schema source:** class document schemas and `plugin_abi/1` are exported from the kernel; plugin-side bindings are generated and CI-checked (ADR-0050 D3 I1); schema drift is a build failure.
5. **Failure modes:** `ProtocolVersionMismatch`, `PinMismatch`, `ContractIncompatible`, `BindFailure{not-installed | trust-denied | locality-unsupported | contract-mismatch | isolation-unavailable}`, `InvocationTimeout`, `PluginCrashed` (session `detached`; re-`hello` from the ledger; proposed effects follow ADR-0030 `unknown → probe`), `UnhandledOperation`, `SchemaViolation`, `AuthorityCrossing`. A failed plugin is a `RegistryDiagnostic` and a fallback for its class (e.g. ADR-0075's ladder), never an instrument failure.
6. **Hooks are guards.** A hook contribution is a `HarnessRule` whose action is a code pointer bound at a `DecisionPoint` (ADR-0016 β; HIR placement stays with WS-F1/A3, OQ-165) and driven by `invoke(binding, guard, {decision_point, proposal | cue | context_plan, ledger_cursor})`. Output: `GuardVerdict ∈ {pass, annotate(Text ≤ external), narrow(deny(reason) | ask(reason) | attenuate(scope ⊂ requested)), propose_replacement(Proposal at ≤ hook authority), no_decision}` — never `allow`, never a mutated input, never a label. Guards at one point compose by **meet** (`deny > ask > attenuate > annotate > pass`); `propose_replacement` re-enters `resolve → authorize` as a new proposal with `derived_from` the hook; `no_decision` (timeout, crash, malformed output) is the identity unless the rule is `required`, where it is `deny`. Composition is order-independent, so parallel and sequential execution agree. A guard may `read_view` within its grants and may never `propose_effect` inside a guard invocation.
7. **Conformance** has four layers, each a `ConformanceSuite` pinned to the contract version it tests and run by the variant host in a `registry_ci` session charged `instrument` (answers OQ-354; the variant host *is* the driver): (1) protocol (`plugin_abi/1`: handshake, unknown-field refusal, canonical round trip, `seq` resume, cancel, crash recovery, closed-sum coverage); (2) isolation (undeclared fs/egress/credential/other-plugin-root/kernel-socket probes refused with ledgered refusals); (3) per-contribution contract suites (ADR-0152) plus the guard property (every output parses as `GuardVerdict`; a rewritten proposal is `AuthorityCrossing`); (4) reach (static: `requires` names only `ContractRef`s and pinned records, no path outside the package root; runtime: the hostile-plugin fixture fails every probe). The **plugin conformance kit** — one null plugin per Stage-1–3 class, the hostile plugin, the golden manifest corpus — is a Stage-3 deliverable. `publisher_claim` reports are displayed at `review` and never count toward `probed`.
8. **Answers.** OQ-258: a `control_strategy` variant may live out of process through the variant host (`invoke(step)` per control step), never through the per-run lab boundary; admissibility at C1 is subject to the OQ-075 ceiling. OQ-353: `resolve/query/catalog/slot_choices/snapshot/record_conformance` cross the kernel↔lab boundary as records, per design or per publish; `register/publish/revoke` cross as requests executed kernel-side. Boundary cost is a measured factor: every invocation carries `boundary_overhead_ms` at a proposed kernel-side measurement point M19 (CF-377) under a proposed `component_call` scope (CF-376); OQ-075's ceiling per `hot_path` class is set from Stage-3 data (AC-L5-9) and recorded as an assumption-debt record.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-12 (operations over canonical documents; every contract driven out of process; the driver is out of process), T-LCD-08 (`bind` takes the profile and account), T-LCD-07 (`hello` capabilities tri-state and probed; verbs never removed because a plugin lacks them), T-LCD-06 (no reference to the Hosting ABI; AC-L5-12), T-LCD-14 (boundary cost is budgeted and matched; AC-L5-9), T-LCD-02 (annotations are `Text` ≤ `external`), T-LCD-05 (the `hot_path` ceiling and any placement-conditioned rule carry debt records), T-LCD-15 (plugin metrics `n/a` for hosted rows), T-LCD-10 (pins are `version_id`s). Not applicable: T-LCD-01/-03/-04/-09/-11/-13. **ADR-0024 rung:** the variant host, placement enforcement, callback closure, meet composition and the conformance driver are MUST-code; `GuardVerdict` values, placements on registrations, suites and reports are MUST-data.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** one contract, many placements by data tag — goose `McpClientTrait` over `stdio|builtin|platform|streamable_http` incl. container placement (S-112, Tier B); separate extension host with declared placement — VS Code (S-562, Tier B); host functions as the only plugin→host channel and deny-by-default resources — Extism (S-561); contract-only reach and no shared memory — Component Model (S-560); transport discipline and negotiation — MCP stdio + extension negotiation (S-153 @aa8ce04); in-process APIs hand out internals and hooks can allow/rewrite — goose `PlatformExtensionContext`, Pi `ExtensionAPI`, opencode `PluginInput`/`Hooks`/`trigger`, Claude Code hooks (S-112, S-113, S-111, S-563; counter-examples, Tier B); process-per-plugin with state outside every process — Logos (S-073, `provisional`, mechanism only); "executors report, never decide" and "withdraw, never create" — ADR-0100 I-3, ADR-0053 decision 5; annotate-or-reject — ADR-0110; atomic registration — Pi `createExtensionAPI` commit/discard (S-113).
- **(b) Source-code precedent:** goose `crates/goose/src/agents/extension.rs` L157–265, `agents/extension_manager.rs` L1474–1610, `agents/mcp_client.rs` L108–142 @fae91d0 (placement dispatch; one trait); opencode `packages/plugin/src/index.ts` L222–335 (closed named hook surface), `packages/opencode/src/plugin/index.ts` L284–297 (sequential mutable output — counter-example) @9f8db11; pi-mono `packages/coding-agent/src/core/extensions/loader.ts` L247–300 (commit/discard), `core/extensions/runner.ts` L851–882, L982–1004 (inconsistent error isolation — counter-example) @400d690; MCP `docs/specification/2026-07-28/basic/transports/stdio.mdx` L11–36 @aa8ce04; codex `codex-rs/app-server-protocol/src/export.rs` (single schema source, via ADR-0050). The guard verdict sum with meet composition and the closed host-callback set are `no-precedent / novel` (Claude Code's hook protocol and gemini's narrow-only extension rules are the closest).
- **(c) Disconfirming evidence considered:** (i) out-of-process hot-path variants distort the latency the Lab measures (goose `platform` rationale) — accepted as a measured, stratified factor (M19, OQ-075, AC-L5-9); first-party variants stay in process so Stages 0–2 pay nothing; Logos' small-cost figure is `provisional` and unused; (ii) narrow-only guards make plugins toothless (opencode `tool.definition`, `system.transform`) — the three legitimate uses have typed homes (profile/`SurfaceFamily` rules with debt records; `propose_replacement` re-entry; `context_policy` variants under the role-placement invariant) and the cost is measurable; (iii) one protocol for hooks, variants and servers is an LCD trap — verbs are declared tri-state per plugin and MCP servers are not driven by it; (iv) the component model would make contract-only reach provable rather than policed — deferred to WASI 1.0 as a drop-in placement (OQ-410). None overturns.
- **(d) Conditionality:** model- and task-independent. Assumes the ADR-0100 helper can launch and keep a *persistent* plugin session (not only one-shot `exec`) — CF-382; assumes ADR-0042/0043 accept the `component_call` scope and M19 (CF-376/-02) or rule that existing per-class scopes suffice; the `hot_path` ceiling is unmeasured (OQ-075). Hook HIR placement (guard on β vs `HarnessRule` action) remains WS-F1/A3's (OQ-165).
- **(e) Build-stage assignment:** **C0 / Stage 1** — `plugin_abi/1` schema in the kernel's schema export; placement field and mapping on registrations; **C0 / Stage 2** — the variant host with `subprocess_confined` through the helper, host callbacks, V1–V6, `GuardVerdict` at the Stage-1 decision points, protocol and isolation suites, first packaged first-party variant (AC-L5-3…-7); **C0 / Stage 3** — conformance kit, reach suite, M19/`boundary_overhead`, OQ-075 measurement (AC-L5-9/-10); **C1 / Stage 4** — `remote` and `container` placements, third-party plugins under J2/H5; **C2** — `component_model` placement, cross-plugin flow with H2; **C4 / Stage 6** — evolution-service plugins under the ADR-0053 D-5 handle set.

## Consequences

- WS-K4 and WS-L5 share one boundary schema source; the SDK is the kernel↔surfaces binding, the variant host the kernel↔extension binding; neither may add a verb the other's contract lacks without a `plugin_abi` bump.
- WS-F1/A3 adopt `GuardVerdict` as the output of any hook at a `DecisionPoint`; WS-H1 admits `propose_replacement` as a new proposal with `derived_from`; WS-H7 renders `ask` verdicts as ordinary approval requests.
- WS-E5/B5 extend the helper with persistent plugin sessions and per-plugin `ContainmentPolicy`; WS-H4 applies EP3 to `remote` placements.
- WS-I1/B1 add `component_call`/`lifecycle.component.invoked` and M19 (or rule on CF-376/-02); WS-L2 attributes boundary cost to the subject by default and to `instrument` for `registry_ci`.
- WS-J2's `registry_ci` runner is the variant host; WS-J3 stratifies by `placement`; WS-J5 annotates rows with `boundary_overhead` and `placement`.
- The `locality` fields of ADR-0023 and WS-J2 become derived views of `placement` (CF-378; ontology §5c amendment).

## Reversibility

**Low** for V1–V5 and the closed callback set (reverting reopens the audited escalation paths and CF-141) · **medium** for the guard verdict sum (adding a verdict is a dialect bump; removing `allow` is the point and is not reversible without an ADR) · **medium** for the placement sum (growable by dialect bump; `component_model` is pre-reserved) · **high** for conformance-layer contents and the M19/scope naming (data and instrumentation, amendable).
