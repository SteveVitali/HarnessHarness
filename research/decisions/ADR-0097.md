# ADR-0097 — The MCP edge under the 2026-07-28 revision: a stateless canonical tool catalogue per bundle (amends ADR-0021 decision 5), a dual-era client with probe-first negotiation, `input_required` as a paused effect, and hints as claims

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-E4 (consumers: WS-K3, WS-E1, WS-E3, WS-E5, WS-H1, WS-H3, WS-H5, WS-B2) · **Phase:** 2 · **Related:** ADR-0019 (closed-world rule; `select_surfaces`), ADR-0021 (MCP tool surface C0/Stage 3), ADR-0022 (E1–E7), ADR-0030/0031/0032 (effect lifecycle; risk class), ADR-0035 (approval per `effect_id`), ADR-0042 (propagation context), ADR-0050 §8(b); CF-045, CF-047, CF-102; CF-206, CF-210; OQ-068, OQ-069, OQ-241, -04, -05, -07; R-2.5.4, R-2.11.3

## Context

ADR-0021 was ratified against `schema/2026-07-28/schema.ts` but before the revision's consequences were traced. The revision (S-153 changelog: SEP-2567, SEP-2575, SEP-2322, SEP-2577, SEP-2663, SEP-2549) removes protocol-level sessions and the `initialize` handshake, carries protocol version and client capabilities in every request's `_meta`, makes `server/discover` mandatory, replaces server-initiated requests with multi-round-trip `input_required` results carrying an opaque `requestState`, deprecates roots/sampling/logging, moves tasks to an official extension, and requires list results to be identical across connections, deterministically ordered and cacheable. ADR-0021 decision 5's "`tools/list` entries + `listChanged` when run-time selection changes" cannot be implemented as written (CF-206). Audited clients already run two eras (goose `preferred_versions: [V_2026_07_28], legacy_version: V_2025_11_25`, S-112 `mcp_client.rs` L706–722; codex `McpProtocolMode::{Legacy, V20260728}`, S-107 `protocol_mode.rs` L9–47), and the spec's compatibility matrix says a modern client against a legacy server "fails" unless `server/discover` is sent first (S-153 `versioning.mdx` L136–167).

## Options considered

1. **Serve per-run tool lists from the K3 server** (narrow `tools/list` by run or client; fire `listChanged` per selection). *Rejected:* violates SEP-2567 ("list endpoints no longer vary per-connection"), defeats client caching and prompt-cache determinism, and makes the catalogue non-content-addressable.
2. **Pin the legacy era only** (2025-11-25 `initialize` handshake, server-initiated requests). *Rejected:* twelve-month deprecation clocks are already running; modern-only servers will appear; the legacy handshake carries per-session state the ledger would have to model.
3. **Modern era only.** *Rejected:* zero audited servers confirmed modern; hosts keep legacy fallbacks; the instrument would be unable to import today's tool servers.
4. **Chosen:** stateless canonical catalogue per bundle; dual-era client with probe-first negotiation and typed mismatch; `input_required` modelled as a paused effect; annotations, `clientInfo/serverInfo` and OAuth scopes as claims; stdio at C0/Stage 3, Streamable HTTP + OAuth at C1.

## Decision

1. **Amend ADR-0021 decision 5 (MCP clause):** the MCP tool-surface document is a pure function of `bundle_id` — `ListToolsResult{tools[] in canonical order (semantic_id, then surface name), ttlMs, cacheScope: "private", resultType: "complete"}` and `DiscoverResult{supportedVersions, capabilities{tools{listChanged: true}}, instructions?}` are byte-identical for every connection of one bundle; `notifications/tools/list_changed` fires only when the served bundle changes. Per-run tool selection (WS-E3 deferred loading; `select_surfaces` under the closed-world rule) is a **client-side** concern of the consuming harness, never a server-side narrowing; cross-call state for K3's Lab operations travels as server-minted handles in ordinary tool arguments (SEP-2567).
2. **Dual-era client with probe-first negotiation.** The MCP client supports the pinned modern version and one pinned legacy version; on stdio it sends `server/discover` before any other request and selects from `supportedVersions`; a legacy-era server (no `resultType`, `initialize` required) is detected by the spec's backward-compatibility probe and driven in legacy mode; a version outside the pinned set raises `ProtocolVersionMismatch{requested, supported}` — an error, never a silent downgrade. The negotiated era and version are recorded in the run's `ProtocolBinding` (ADR-0099). Per-request `_meta` carries `io.modelcontextprotocol/{protocolVersion, clientCapabilities, clientInfo}` in modern mode; the client declares `elicitation.form` only at C0 (roots/sampling are deprecated; sampling passthrough is C2-optional).
3. **`input_required` is a paused effect.** A `tools/call` returning `resultType: "input_required"` leaves the effect in `prepared`/`committed` (never `observed`, never `failed`); the ledger records `control.decision{kind: ask}`; elicitation requests become a `message_human` effect whose answer is `principal`-authored content, not an endorsement; `requestState` is stored as an opaque blob and echoed unmodified on retry (the retry shares `effect_id` and increments `attempt_no`); sampling requests, if enabled, are `model_call` effects through the C1 gateway; roots requests are answered from `EnvironmentRef` scope only under the legacy era.
4. **Results vs protocol errors.** `CallToolResult{isError: true}` is `action.tool.completed{status: failed}` with the content as an `Observation` (the model may see it); a JSON-RPC error is `action.tool.rejected{source: protocol}`; cancellation of a non-`read_only` call yields `action.effect.unknown` then `probe` (ADR-0030). The two are never conflated in the ledger.
5. **Claims never decide.** `ToolAnnotations` lift only to `declared_claims` and, per ADR-0031, `effective_risk_class = max_by_danger(kernel_assessed, projected(declared))`; `clientInfo`/`serverInfo` are display-only (the spec's own rule); OAuth scopes and `WWW-Authenticate` challenges are H3 inputs, lifted as claims; `x-mcp-header` mirroring is disabled unless the sealed definition enables it per tool; foreign `_meta` keys are preserved in `ext` and never carry authority; `instructions` is a `Text` leaf at `≤ external` delivered only through a slot with `min_authority ≤ external` (WS-H5 §6.2).
6. **Identity across the edge.** The client keeps `surface_name → (server_ref, semantic_id)` and never parses names; own exports carry `semantic_id`/`bundle_id` in `_meta["<hh-prefix>/hir"]` (prefix per OQ-068); name collisions across servers are resolved by the profile-owned naming rule, and a rename is a profile edit (T-LCD-10).
7. **Tiers.** stdio client + stateless server: **C0 / Stage 3** (required to execute validators on the MCP target, CF-045); Streamable HTTP with `Origin` validation, OAuth 2.1 + RFC 8707 resource indicators through H3 mediation, `subscriptions/listen`: **C1 / Stage 4**; tasks extension, MCP Apps, sampling passthrough: **C2**.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: statelessness and list invariance (S-153 changelog §1–5; `RequestMetaObject` L63–118; `server/tools.mdx` L62–71 "MUST NOT vary", "SHOULD return tools in a deterministic order"); MRTR semantics and `requestState` as attacker-controlled (S-153 `patterns/mrtr.mdx` L130, L232–257); deprecations with a twelve-month window (SEP-2577); annotations untrusted (S-153 L1912–1920; `server/tools.mdx` L305); compatibility matrix and probe rule (S-153 `versioning.mdx` L136–167; `transports/stdio.mdx` L124); dual-era clients in production (S-112, S-107); `isError` looseness leaking into observations (S-119 `mcp-tool.ts` L249–265); location-trust short-circuit as the failure mode (S-119 `mcp-tool.ts` L207–216).
- (b) Source-code precedent: codex `codex-rs/rmcp-client/src/protocol_mode.rs` L9–47 @0735c51 (era enum, stdio opt-in); goose `crates/goose/src/agents/mcp_client.rs` L700–735 @fae91d0 (preferred + legacy lifecycle), `agents/extension_manager.rs` L293–330 (name mangling recovery — negative precedent) and L349–392 (foreign `_meta` stripped before trust); codex `codex-rs/core/src/mcp_tool_call.rs` L204–222 (annotation-derived policy confined to the first-party server); opencode `packages/opencode/src/mcp/index.ts` L40–50 (minimal client capabilities). The stateless canonical catalogue as an instrument property and the paused-effect model of `input_required` are `no-precedent / novel`.
- (c) Disconfirming evidence considered: (i) deferred loading wants per-session lists — answered: the closed-world rule already places selection in the consuming harness (`select_surfaces`, ADR-0019) and the K3 server must be a pure function of the bundle for T-LCD-10/-11; server-minted view handles remain possible (OQ-247). (ii) The revision is weeks old and may change — answered: the pin is in the derivation key; the dual-era client means nothing depends on modern servers existing. (iii) Elicitation through MRTR blocks the tool call for a human round trip — answered: that is precisely a paused effect under ADR-0030, and WS-H7 owns the approval UX. None overturns.
- (d) Conditionality: assumes MCP 2026-07-28 + one legacy pin (2025-11-25 or 2025-06-18, chosen at Stage 3) through Stage 4; assumes the reference monitor treats `unverified` as default-deny and `unknown` effects as `{irreversible, non_idempotent, external}` (ADR-0031); independent of model tier; no `provisional` result is load-bearing.
- (e) Build-stage assignment: **C0 / Stage 3** decisions 1–6 over stdio; **C1 / Stage 4** decision 7's HTTP/OAuth/subscriptions; **C2** extensions.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-04 (MCP target executable), T-LCD-10 (decision 6), T-LCD-11 (typed mismatch; preserved `_meta`; loss report), T-LCD-12 (client/server are separate processes exchanging documents), T-LCD-05 reflexively (the legacy-era projection carries an assumption-debt record keyed to the deprecation window). Does not address T-LCD-03. **ADR-0024 rung:** transport, negotiation and outcome classification are MUST-code; catalogue documents, era pins and per-tool header policy are MUST-data.

## Consequences

- ADR-0021 decision 5's MCP clause reads, after amendment: "`tools/list` is a pure function of `bundle_id`; `listChanged` fires on bundle change only; run-time selection is client-side".
- WS-E3 designs discovery/deferral on the client side of the edge; WS-K3 exposes Lab operations as handle-carrying tools; WS-B2 gains the `paused` outcome mapping for `input_required`; WS-H7 owns the elicitation UX; WS-H3 owns OAuth custody and the `iss`/PKCE/resource-indicator rules.
- The scope register's R-2.5.4 stage note stands (MCP slice C0/Stage 3); no tier change.

## Reversibility

**High** for era pins and tiers; **medium** for the stateless-catalogue rule (reverting it after Stage 3 would re-key stored bundles and break AC-E4-2); **low** for "claims never decide" (shared with ADR-0031/0035).
