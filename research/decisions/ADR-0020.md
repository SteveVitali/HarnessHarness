# ADR-0020 — The Model Profile contract: selector + typed capability declaration + closed rule kinds + assumption-debt record on every rule + four test suites + expiry states; C0 profile schema and two minimal profiles

**Status:** **ratified** (Phase 1 synthesis, 2026-09-10)
**Owner workstream(s):** WS-A4 (contract) → WS-C3 (rule inventory, probes, Profile Compiler), WS-I6 (debt-record manager), WS-A2 (vocabulary) · **Phase:** 1 · **Related:** ADR-0007 (T-LCD-01/-05/-08/-10/-13), ADR-0008 (Model Profile / Profile Compiler; conditioned rule / assumption-debt record), ADR-0011; ADR-0015/ADR-0016 (surface record; `HarnessRule`); CF-046, CF-049, CF-044; OQ-064, OQ-071; R-2.3.3, R-2.1.3

## Context

Ontology v0.1 ratifies the Model Profile as "a versioned, expirable object holding every model-conditioned surface decision … the sole owner of surface fields" and the Profile Compiler as the component that applies it, carrying its own assumption-debt record. Doc 2 §11 asks that the profile be "an independently testable harness component whose assumptions can expire". What has not been decided is the *contract*: what a profile declares, how its rules are constrained, how it is tested in isolation, and what "expire" means operationally. The audit found the same content expressed three ways: as per-slug data (codex `models.json`: 48 keys per slug incl. `apply_patch_tool_type`, `shell_type`, `tool_mode`, `truncation_policy`, reminder thresholds and 21k characters of instruction prose), as typed capability flags (pi `compat` interfaces, ~40 flags, an eleven-variant `thinkingFormat`; AutoGen `ModelInfo`; opencode `capabilities`), and as imperative branches on model-id substrings (opencode `system.ts` L30–52, `registry.ts` L297–300; `transform.ts`, 1,909 lines). Tier-A evidence (PA-Tool, ACL 2026) shows tool *names* are model-conditioned surfaces; Anthropic (S-037) reports namespacing effects that "varied by model"; Cursor (S-049) reports patch vs string-replacement edit tools by provider and guardrails "long gone" — assumption debt observed by inspection rather than by test.

## Options considered

1. **Profile = free-form per-model configuration map** (codex `models.json` as-is). *Rejected:* no owned-field discipline (T-LCD-01 undetectable), no debt records (T-LCD-05), prose templates un-decomposed (T-LCD-02).
2. **Profile = code (adapter subclass per provider)** (goose/opencode/pi request builders). *Rejected:* cannot be diffed, content-addressed, expired or ablated; the substring-branch failure signature.
3. **Profile = capability flags only** (pi/AutoGen). *Rejected:* flags say what a model *can* do, not what the harness *chooses* to do about it; tool shape, naming, layout and reminder policy need rules with evidence and expiry.
4. **Profile = versioned, content-addressed data document with five parts — selector, typed capability declaration (declared → probed), closed enum of conditioned-rule kinds each carrying an assumption-debt record, typed reported `ext` block, and test obligations — with explicit expiry states (chosen).**

## Decision

1. **Shape.** `ModelProfile{profile_id, version, content_hash, selector{provider_api_family, model_family, version_pattern, precedence}, extends?, capabilities: CapabilityDeclaration, rules: ProfileRule[], ext?: {<vendor-prefix>: typed block}, expiry: AssumptionDebtRecord}`. Profiles chain base → family → version by declared selector precedence; overrides may touch only profile-owned fields; resolution never uses substring tests in code.
2. **Capability declaration** is typed per model/API pair (`native_function_calling, parallel_tool_calls, strict_schema_dialect, structured_output, grammar_tools, reasoning_replay{field, opaque}, interleaved_reasoning, image_input, context_window, max_output, developer_role, cache_control_convention, tool_result_name_required, assistant_required_after_tool_result, temperature_supported, deferred_tools, tool_search`). Values start `declared`; `probe_profile(profile, model_adapter) → ConformanceRecord[]` turns them `probed` and flags `DRIFT` as experimental data; `unknown` is never coerced (mirrors T-LCD-07 for hosted participants).
3. **Rules.** `ProfileRule{rule_id, kind, owned_fields[], params, debt: AssumptionDebtRecord}` with `kind ∈ {tool_shape, naming, schema_dialect, description_template, error_format, result_render, prompt_layout, interaction_mode, transcript_render, compaction_reminder, sampling_defaults, caching_markers}` — a **closed enum per profile-schema version**, extended only by ADR. A rule may write only *surface records* (WS-A3) and profile parameters; it may never touch `Permission`, `EffectClass`, `Budget`, `Validator` or identity. `ProfileRule` is the profile-level home of *conditioned rules*; `HarnessRule.conditioned_on` is the definition-level home; both share one `AssumptionDebtRecord` schema (CF-049).
4. **Debt discipline.** Every rule and the profile itself carry `{rule_id, hypothesis, evidence_refs[], owner, expiry_condition ∈ {model_version_change, date, probe_failure, evidence_refresh_due, experiment_ref}, removal_test_ref, status ∈ {active, expiring, expired, retired}}`. The compiler *refuses* a rule with an incomplete record at link (`LinkError.missing_debt_record`), *warns* on `expired`, lists both in `lcd_report.conditioned_rules`, and exposes "retire rule R" as `relower(bundle, profile − R)` so a delete-this-rule arm is one compile away.
5. **Escape-hatch containment.** The `ext` block is typed, owner-prefixed and carries a debt record; every use is reported in `lcd_report.per_profile_diff_fields` and counted by a Lab metric, so growth of special cases is observable rather than hidden.
6. **Test obligations (independently runnable, without the rest of the harness).** (i) *static*: schema validity; owned-field discipline — compile a fixture definition under this profile and a null profile, diff ⊆ owned fields (T-LCD-01); (ii) *probe*: capability probes producing `ConformanceRecord`s; (iii) *equivalence*: every `tool_shape` rule ships the ADR-0022 evidence for the surface family it selects; (iv) *behavioural*: a compliance suite per profile computing delivered/activated/followed for its rules (T-LCD-13; S-088 mechanism), separating harness validity from compliance per profile.
7. **Expiry semantics.** A profile version is `active` while all rules are `active`; `expiring` when any rule's `expiry_condition` is met; `expired` when a probe fails or the version pattern matches no served model; `retired` by ADR after the removal test passes. Compiling under `expired` requires an explicit recorded intent in the bundle (so "dead weight" can be tested deliberately, S-047). Profiles are content-addressed: a rename or template edit yields a new profile hash and no HIR change (T-LCD-10).
8. **C0 scope.** `ModelProfile/1` schema, selector, capability declaration, `ProfileRule` with the debt record, and **two minimal profiles** that differ in `tool_shape` for `edit_file` (patch vs string replacement) and in `naming` scheme (prefix vs suffix namespacing) are C0 (Stages 1–3) — the minimum T-LCD-01/-04 can be executed against. The full rule inventory, probes, profile chains beyond two levels, transcript-renderer families and compaction/reminder rules are C1/Stage 5 (WS-C3).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: model-conditioned surfaces at every level, including names (S-177 PA-Tool, ACL 2026, Tier A: renaming to pretraining-familiar names cuts misalignment errors by 80% on small models; S-037 namespacing effects vary by model; S-049 patch vs string replacement; S-107 `models.json` per-slug tool shape/mode/truncation/reminders); format sensitivity is model-conditioned (S-176 TSCG, `provisional`, mechanism only); assumption debt discovered by inspection rather than by test (S-047); validity vs compliance separable (S-088, `provisional (mech)`); declared-vs-probed conformance as data (ADR-0004; Omnigent S-118 via WS-A1).
- (b) Source-code precedent: profile-as-data — `codex-rs/models-manager/models.json` (S-107 @0735c51, 9 slugs × 48 keys); typed capability declaration — `pi-mono/packages/ai/src/types.ts` L568–760, L843–870 (S-113 @400d690), `autogen_core/models/_model_client.py` L164 `ModelInfo` (S-145 @027ecf0), `opencode/packages/opencode/src/provider/provider.ts` L1034–1093 (S-111 @9f8db11); selector as data — `openhands-sdk/openhands/sdk/llm/utils/model_prompt_spec.py` L12–107 `ModelPromptSpec{family, variant}` (S-110 @3fc7b22); declared-loss strictness — `pi-mono/packages/ai/src/api/constrained-sampling.ts` (`strict: prefer | require`); capability-keyed fallbacks — `dspy/adapters/json_adapter.py` L57–119 (S-144 @ca54a85); negative precedent (branches) — `opencode/.../session/system.ts` L30–52, `tool/registry.ts` L297–300. The assumption-debt record on every rule, the closed rule-kind enum, the four-suite testability contract and the expiry states are `no-precedent / novel`.
- (c) Disconfirming evidence considered: the widest-coverage systems implement conditioning as code and their flag sets keep growing (opencode `transform.ts` 1,909 lines; pi ~40 flags, 11 `thinkingFormat` variants) — a closed enum will lag reality or grow an "other" field. Answered: codex proves data-only profiles drive a production harness; pi proves typed flags scale across API families; the schema is versioned and extended by ADR; the typed `ext` block is reported and metered so escape-hatch growth is observable (RK-02 residual, re-checked by WS-C3 at Phase 2). A second objection — a faithful profile of a Codex-class harness has a very high opacity ratio because its instruction template is one 21,261-character string — is accepted as a real cost of T-LCD-02 and routed to OQ-064 (profile-prose bucket in the opacity report). Neither overturns.
- (d) Conditionality: assumes at least two provider families with materially different tool conventions remain in use (true through 2026: patch vs string-replacement, strict-schema subsets, reasoning-replay formats); if conventions converge, rules retire through their own debt records and the schema stands. C0 evidence rests on Tier-A/B sources (PA-Tool accepted; codex/pi/opencode/OpenHands/AutoGen source at pinned commits); TSCG and Life-Harness numbers are illustrative only.
- (e) Build-stage assignment: **C0 / Stage 1** (schema `ModelProfile/1`, debt-record schema, link-time refusal); **C0 / Stage 3** (two minimal profiles, static + equivalence suites, T-LCD-01/-04 executable); **C1 / Stage 5** (Profile Compiler rule family, probes, chains, transcript-renderer families — WS-C3); **C4** (debt-record *manager* — WS-I6).

**T-LCD statement (ADR-0007 decision 5).** Satisfies: T-LCD-01 (owned-field discipline is a static test), T-LCD-05 (refuse/warn/retire), T-LCD-08 (the profile is an input to every component class — the contract is consumed via `instantiate(resolved, runtime, profile, accounting)` in WS-A5), T-LCD-10 (rename = profile hash change), T-LCD-13 (behavioural suite per profile). Does not by itself satisfy T-LCD-04 — mitigated by the two-profile C0 scope and the equivalence run at Stage 3.

## Consequences

- WS-C3 designs the rule inventory and probe suite *inside* this contract; new rule kinds are ADR-gated schema versions.
- WS-A2 records `ProfileRule` and the "two homes, one record" rule for conditioned rules at ontology v1 (CF-049).
- WS-I6's manager consumes `AssumptionDebtRecord.status` transitions; WS-J3's Lab gets the "retire rule R" recipe for free.
- Scope register R-2.3.3 gains a stage note splitting C0 schema + two profiles from the C1 Profile Compiler (CF-046).
- WS-C1's gateway receives profile-owned serialisation decisions as data, never as branches (CF-044).

## Reversibility

**Medium.** The rule-kind enum and capability field list are versioned and can grow by ADR at low cost. Removing the debt-record requirement or allowing profiles to write non-surface fields would silently reintroduce the LCD escape hatch and invalidate T-LCD-01/-05 gates — the costly direction.
