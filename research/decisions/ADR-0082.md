# ADR-0082 — Supersession, revocation and conflict sets for memory: the authority rule, closed revocation reasons, deterministic-core/judged-tail conflict detection, no recency tie-break, slot conflict policy, and promotion as the only ascent

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-D4 (consumers: WS-D3, WS-D1, WS-D5, WS-G3, WS-H2, WS-H7, WS-L4, WS-J2, WS-I5) · **Phase:** 2 · **Related:** ADR-0034 (P5 supersession-authority rule, P1 derivation), ADR-0035 (closed basis list: `promotion`, `approval`; the model never endorses), ADR-0037 (S1–S8; `RevocationRecord`; forks), ADR-0033 (I3 taint; authority is not evidence), ADR-0047 (judges: `charged_to = instrument`), ADR-0017 (`HirDiff` classification), ADR-0081; CF-182, CF-183; OQ-010, OQ-110, OQ-123, OQ-208/-06/-07; R-2.4.4

## Context

ADR-0034 P5 fixed that supersession requires `authority(new) ≥ authority(old)` and ADR-0037 fixed supersession as an edge on the newer immutable version with a `RevocationRecord` for revocation without replacement. What neither fixed is *how a conflict between two memories is detected and resolved*, and *who may resolve it*. The audited systems answer with a model: mem0's `DEFAULT_UPDATE_MEMORY_PROMPT` tells the LLM "If the retrieved facts contain information that contradicts the information present in the memory, then you have to delete it" (`mem0/configs/prompts.py` L264) and `_delete_memory` removes the vector; graphiti has an LLM extract `valid_at`/`invalid_at` from text and then orders contradictions by those stamps (`edge_operations.py` L565–571, L580–620), "consistently prioritiz[ing] new information" (S-357); A-Mem lets new memories "trigger updates to the contextual representations … of existing historical memories". S-106 shows why this is unsound: the revoked fact "outranks its replacement", and its own guard admits that tie-breaking "by result order … is unsound". mem0 has since moved its default to ADD-only extraction with `linked_memory_ids` (`main.py` L879–1090) — a production retreat from model-decided deletion. Under the ratified scheme, a `delegate` origin never endorses (ADR-0035) and authority is never evidence weight (ADR-0033 decision 8), so a model-judged contradiction cannot be allowed to revoke a higher-authority memory. RFC 5280 supplies the shape of a revocation vocabulary (`superseded`, `keyCompromise`, `privilegeWithdrawn`, `certificateHold`).

## Options considered

1. **Model-decided ADD/UPDATE/DELETE at write time (mem0 v1/v2, A-Mem).** *Rejected:* a `delegate` deciding to delete a `principal` memory is the endorsement the model may never make; deletion destroys audit; S-106's exposure numbers.
2. **Newest valid-time wins (graphiti).** *Rejected:* valid time is a model-extracted claim; S-106 shows the "newer" record is often not the replacement; recency across authority classes is escalation in memory form.
3. **Always coexist; never supersede automatically.** *Rejected:* keyed structured facts (recovery suggestions, closed-schema preferences) admit a deterministic contradiction test, and refusing to supersede them re-creates the "revoked outranks replacement" failure for the one case where the runtime can decide.
4. **Chosen: deterministic core (same `subject_key`, incompatible closed-schema values, writer asserts `supersedes`, authority rule holds ⇒ supersession) and judged tail (free text ⇒ conflict set that coexists annotated, is withheld per slot policy, or escalates — never supersedes); closed revocation reasons; no tie-break by recency or result order; promotion as the only path up.**

## Decision

1. **Records.** `supersede(new, old, reason ∈ {edit, revocation, expiry, migration, fork})` and `revoke(old, reason: RevocationReason, authority, replacement?) → RevocationRecord{kind = Memory, …}` per ADR-0037, each a ledger event (`context.memory.invalidated{version_id, reason, by, replacement?}`); the old version is never touched. `RevocationReason = {contradicted, principal_withdrawn, source_revoked, dependency_revoked, expired, migrated, poisoned, hold, release}` (closed; `hold`/`release` are the CRL `certificateHold` pair — `release` supersedes a `hold` record with a *new* version, never an un-revoke).
2. **Authority rule (ADR-0034 P5, restated).** `supersedes(new, old)` requires `authority(new) ≥ authority(old)` (`SupersessionAuthorityInsufficient`). `revoke` requires `authority(revoker) ≥ authority(old)`; for `old.authority ≥ principal` the revoker's origin must be `human` or `kernel` (`AuthorityInsufficient`); a `delegate` may revoke only `≤ delegate` memories in scopes ≤ `session`. `definition`-class memories are revoked only through `seal`, `pin` reversal or `promotion` reversal.
3. **Conflict sets.** `ConflictSet{conflict_id, subject_key?, members[], detector ∈ {deterministic{key_match}, judged{detector_ref, confidence}}, resolution ∈ {superseded{head}, coexist, withheld, escalated{principal_ref}}, resolved_by?}`. `SubjectKey = {schema_ref: Ref<closed schema in the sealed definition>, key: canonical bytes}`. Detection at `write`: deterministic when the new and an existing valid version share `subject_key` and their closed-schema values differ; judged when a registered `Validator{kind: judge}` (`charged_to = instrument`, calibrated per OQ-123) flags free-text incompatibility.
4. **Resolution.** (a) deterministic ∧ writer asserts `supersedes` ∧ authority rule ⇒ `superseded{head = new}`; (b) deterministic ∧ authority rule fails ⇒ the write succeeds as `coexist` (the lower-authority version never withholds the higher) and `escalated` if `MemoryPolicy.escalate_on_unresolved`; (c) judged ⇒ `coexist` (optionally `escalated`) — a judged detector never emits `supersedes` or a `RevocationRecord`; (d) equal authority without asserted `supersedes` ⇒ `coexist`. **No resolution ever depends on result order, wall-clock or model-extracted valid time**; transaction order (`seq`) is used only to choose the head *among* versions that already satisfy (a). A `coexist` set is resolved only by a later supersession satisfying the authority rule or by a `promotion`/`approval` endorsement naming the head (ADR-0035 bases; `approval` here endorses the *resolution event*, identified by `conflict_id`, not the content).
5. **Retrieval of conflict sets.** Slot `conflict_policy ∈ {deliver_all_annotated (default), withhold_all, deliver_head_if_resolved_else_withhold}`; delivered members carry `conflict_set_ref` (rendering is a profile surface); withheld members are recorded in `context.memory.read.withheld[]`.
6. **Promotion as the only ascent.** `promote(v, reviewer: human(role ∈ {reviewer, principal}), to_scope, to_authority ≤ authority(reviewer)) → v'` writes a new version with `supersedes{edit}` and the `security.label.endorsed{basis = promotion}` event in one ledger transaction (clears taint; readers as declared — WS-H2's per-basis table); no other operation raises a memory's authority or scope; a model-issued `promote` is `IllegitimateEndorsement`.
7. **Evolution.** A `HirDiff` that loosens a slot's `validity_policy`/`conflict_policy` toward admission, or a `MemoryPolicy` change toward `deliver_all`, is classified `validity_delta = loosening` and treated like `authority_delta = widening` in evolution contexts (CF-183 requests the classifier field from WS-A3).

**T-LCD statement.** Satisfies T-LCD-02 (`subject_key` schemas are sealed closed schemas; judged detectors are `Validator{kind: judge}` with profiles and expiry — T-LCD-05 reflexively), T-LCD-10 (conflict annotations are surfaces), T-LCD-12 (operations), T-LCD-13 (resolution events are observable), T-LCD-15 (judge calibration and conflict metrics class-scoped). Not applicable: T-LCD-01/-03/-04/-06/-07/-08/-09/-11/-14.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: only the owner declassifies; the model never endorses — DLM/Flume via ADR-0035 (ratified); authority ≠ evidence — ADR-0033 decision 8 (ratified); revocation reason codes and validator-side checking — RFC 5280 (S-356, Tier A); a belief is IN only while justified; contradictions retract by dependency, not by recency — Doyle TMS (S-353, Tier A); the guard "detects pairs of facts asserting incompatible values for the same subject and withholds the older" and result-order tie-breaking is "unsound" — S-106 (`provisional (mech)`); "consistently prioritizes new information" with LLM-extracted valid time — Zep/Graphiti (S-357, vendor preprint, mechanism only); model-decided deletion and its retreat to ADD-only — mem0 source (S-359).
- (b) Source-code precedent: `mem0/mem0/configs/prompts.py` L176–320 and `mem0/memory/main.py` L2038–2128 @02f7a9b (model-decided UPDATE/DELETE — the rejected pattern; append-only `history` — adopted as ledger events), `main.py` L879–1090 (ADD-only + links — the retreat); `graphiti/graphiti_core/utils/maintenance/edge_operations.py` L538–575 @4bd7287 (`resolve_edge_contradictions`: overlap test then `invalid_at = new.valid_at`, `expired_at = now`, retained — adopted for *retention*, rejected for ordering), L580–620 (LLM timestamp extraction — rejected as an ordering basis); `AIOS/aios/memory/base.py` L173–232 @292d98f (in-place update by delete-and-reinsert — rejected). **`no-precedent / novel`** for: the deterministic-core/judged-tail split with the authority rule, closed `RevocationReason` on memory, conflict sets as first-class records with slot policies, and promotion as an atomic version-plus-endorsement.
- (c) Disconfirming evidence considered: every production system resolves by recency and reports benchmark gains (Zep DMR/LongMemEval, Mem0 LOCOMO — vendor preprints, unmatched budgets) — absorbed: transaction-order recency survives *within* an authority class after the deterministic test; only cross-class and valid-time recency are refused; subject keys presume structured memory — absorbed: unkeyed memories fall to the judged tail (coexist/escalate), strictly weaker but auditable, and shape endorsement (ADR-0035 `validator`) can key facts at `environment`; coexisting contradictions confuse the model — a Stage 3 measurement (AC-D4-12) with `withhold_all` available per slot; judge calibration is unsolved (OQ-123) — judged detectors never decide, so miscalibration costs annotations, not safety. None overturns.
- (d) Conditionality: independent of model tier; assumes closed schemas for keyed kinds are declared in the sealed definition (WS-A5); judged detection requires `model_io` observability and an independent judge snapshot (ADR-0047); escalation assumes a reachable principal (unattended runs set `escalate_on_unresolved = false` and use `withhold_all` — S-104's vector, ADR-0035 (d)).
- (e) Build-stage assignment: **C0 / Stage 1** (records, `RevocationReason`, `ConflictSet`, `SubjectKey` schemas; authority rules in `write`/`supersede`/`revoke`); **C0 / Stage 2** (deterministic detection, `coexist` default, `promote`, slot `conflict_policy`; AC-D4-4/-5/-6); **C2 / Stage 3–4** (judged detectors with WS-G3, escalation UX with WS-H7, `validity_delta` in evolution gates).

## Consequences

- WS-D3 exposes `conflict_set_ref` on retrieved candidates; WS-D1 renders annotations through the profile and honours `conflict_policy`; WS-G3 registers calibrated contradiction judges as `Validator{kind: judge}`; WS-H7 owns the escalation surface (OQ-211); WS-A3 adds `validity_delta` to `HirDiff.classification` (CF-183); WS-H5 shares `RevocationReason` for extensions where applicable; WS-J2 applies OQ-110's namespace authority to shared memory registries (OQ-212); WS-I5 candidates that loosen memory policies are gated like widening.

## Reversibility

**Low** for decisions 2, 4(c) and 6 (a judged detector that could supersede, or a non-human promotion, would reopen the X-CPE/laundering path in memory form and contradict ADR-0035); **medium** for the `RevocationReason` list (dialect bump) and the default `conflict_policy` (definition data, Lab-tunable); **high** for the escalation shape.
