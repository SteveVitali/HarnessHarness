# ADR-0005 — Interoperate, don't duplicate: the comparison plane imports/exports interchange trajectories, can participate in existing evaluation planes, and its hosting ABI is neutral across the three hosting mechanisms

**Status:** ratified (Phase 0 synthesis, 2026-09-09)
**Owner workstream(s):** WS-A1 (consumers: WS-J6, WS-J5, WS-I3, WS-I4, WS-B1, WS-L2) · **Phase:** 0 (design obligation for Phase 3) · **Related:** ADR-0001, ADR-0003 (N3), ADR-0004, OQ-004, OQ-030, OQ-031, OQ-032, OQ-033, R-2.10.6, R-2.9.3, R-2.10.5

## Context

Black-box comparison planes already exist with mature artifacts: Harbor's ATIF trajectory schema (`src/harbor/models/trajectories/{trajectory,step}.py`: `Trajectory{schema_version, agent, steps, final_metrics, subagent_trajectories}`, `Step{source, model_name, reasoning_effort, message, reasoning_content, tool_calls, observation, metrics}`), Harbor job configs and trial results with cost fields, HAL result directories with Weave cost, Inspect eval logs. Three hosting mechanisms are in production use with different observability envelopes: session-ABI (ACP `schema/v2/schema.json`; Omnigent `Executor`; Codex app-server `thread/*`, `turn/*`), model-boundary interception (Inspect `agent_bridge`/`sandbox_agent_bridge`; ClawGym II proxy), and container-installed CLI (Harbor `agents/installed/*`). Building a fifth incompatible black-box plane would violate non-goal N3 and forfeit the existing corpus of trajectories.

## Options considered

1. **Own everything**: define a MetaHarness-only trajectory format and a single hosting mechanism (ACP only). Rejected: loses interop with the largest existing black-box corpora; ACP alone reaches fewer harnesses than Harbor's installed adapters; violates N3.
2. **Adopt ATIF as the native ledger format.** Rejected: ATIF is a *trajectory interchange* (steps with messages/tool calls/metrics) and cannot carry the typed effects/permissions/provenance the IR-native ledger needs (WS-B1); adopting it natively would re-import the LCD trap.
3. **Native ledger + documented bidirectional mapping to an interchange format, mechanism-neutral hosting ABI, and the ability to run as a participant in Harbor/Inspect-style planes (chosen).**

## Decision

- The run ledger (WS-B1) is native and typed; the laboratory provides `export(run) -> interchange trajectory` (ATIF-compatible or a documented superset with a lossless-for-black-box mapping) and `import(interchange) -> Run` that lands as a `product`-granularity row with `observability_level` set from what the artifact contains.
- The thin observational ABI (WS-J6) is specified as a **minimum observable event set** plus **declared capabilities**, such that each of the three hosting mechanisms can implement it; no mechanism is privileged in the analysis engine. Suggested ordering of implementation: session-ABI (ACP) → model-boundary interception → container-installed.
- MetaHarness itself must be able to **act as a participant** in an external plane (at minimum: expose an IR-native harness through an ACP-style session interface so Harbor/Omnigent/OpenHands-style hosts can run it) — this is how the reference runtime gets external validity without asking anyone to adopt it as a framework.
- Cost accounting (WS-L2) defines how usage is attributed for each hosting mechanism: measured model I/O (interception), participant-reported usage events (session-ABI), or native-log reconstruction (container-installed), each stamped with its provenance and confidence.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: S-133 (Harbor adapters; parity experiments validate that adapted infrastructure matches original implementations) `provisional (mech)`; S-074 (ACP hosting role in 6/11 systems) `provisional (mech)`; S-035 ACP v2 verbs; S-137 Inspect bridge docs (internals opaque; only externalized model calls visible); Omnigent `docs/session-compaction.md` (native compaction boundaries differ per harness — an interchange format must carry compaction markers).
- (b) Source-code precedent: Harbor `models/trajectories/` (ATIF), `agents/installed/claude_code.py:235 atif_to_native_trajectory` and `:573 _convert_event_to_step` (bidirectional native↔interchange mapping exists in practice); Harbor `bridges/base.py` (ACP bridge as one mechanism among installed agents); OpenHands `agent/acp_agent.py` (an SDK hosting external ACP agents *and* being hostable); Omnigent `inner/executor.py` capability methods. The mechanism-neutral ABI with a single analysis engine — `no-precedent / novel` in combination (Harbor has installed + ACP but not interception; Inspect has interception but not session-ABI; Omnigent has session-ABI variants but not container-installed benchmark isolation).
- (c) Disconfirming evidence considered: (i) interchange formats lose information (ATIF has no effects/permissions/provenance) — accepted; the mapping is lossless only for black-box rows, and `observability_level` makes the loss explicit. (ii) Supporting three mechanisms triples hosting surface area — mitigated by the ordering (ACP first) and by making mechanisms C2 extensions behind one Core participant contract. (iii) ATIF is a single-team RFC that may change — the decision names "ATIF-compatible *or* documented mapping", not a hard dependency.
- (d) Conditionality: assumes external harnesses continue to expose at least one of the three mechanisms; participants exposing none are excluded (consistent with ADR-0001 conditionality). Cost-attribution confidence is lower for container-installed participants.
- (e) Build-stage assignment: participant contract + `observability_level` — C0, Stage 1; export/import + ACP hosting + "act as participant" — C2, Stage 4; interception and container-installed mechanisms — C2/C3, Stage 4–5.

## Consequences

- WS-J6 designs the ABI as event-set + capability declaration rather than as a single RPC surface; OQ-004 is reframed as "minimum observable set per mechanism".
- WS-I3's reproducible bundle includes the interchange export; WS-J5's results store accepts imported rows flagged by provenance.
- WS-I4 may integrate Harbor/Inspect-hosted environments as first-class environment providers instead of re-porting benchmarks (N5).
- WS-B1 must reserve a `participant_class` and `observability_level` stamp on every ledger event.
- **Synthesis notes:** OQ-032 is resolved by this ADR (acting as a participant in an external plane is a C2 / Stage-4 obligation; WS-J6/K4 specify the surface). The relation between this event-set-plus-declaration shape and WS-L1's ecosystem-boundary verb set is settled in CF-023 (the session-ABI mechanism *is* the verb set; the Hosting ABI as a whole is the minimum observable event set + capability declaration). T-LCD-06/-07 (ADR-0007, `registers/lcd-test-battery.md`) bound the ABI: no dependency edge from IR entities into the Hosting ABI; declare/verify/stratify, never intersect. Cost-attribution confidence rules are OQ-033 (WS-L2/J4). Hosting's MoSCoW is *Should* per ADR-0010.

## Reversibility

Medium. Dropping a mechanism later is cheap; dropping interchange import/export after users have relied on it is costly; the native ledger is unaffected either way.
