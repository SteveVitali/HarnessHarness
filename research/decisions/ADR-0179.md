# ADR-0179 — Transport bindings and the OQ-130 answer: one embedding contract over three bindings (in-process for first-party surfaces, subprocess-over-stdio, local-network) validated by one conformance suite; every planned surface is servable by a generated client over the kernel's local transport, so ADR-0050's late-bound surface binding stands and revalidation trigger 6 does not fire

**Status:** ratified
**Owner workstream(s):** WS-K4 (with WS-K2 for the surface binding at Stage ≥ 5; consumers WS-K1, WS-K3, WS-J1…J5, WS-I4, WS-E4, WS-L1 role, WS-L6) · **Phase:** 3 · **Related:** ADR-0176 (I8), ADR-0050 (D1 surfaces row "late-bound"; D2 record set; D3; §5 reversibility; §6 trigger 6; §8), ADR-0049 §4 (Q-L1-14 "generated client over a local transport acceptable"), ADR-0009 (revalidation procedure), ADR-0026 (durable-before-visible), ADR-0045 §9 (per-run scorer crossing), ADR-0097 D1 (K3 server-minted handles), ADR-0098 (ACP artefact as a client), ADR-0130 (bounded restore), ADR-0136…0138 (R-NOSIDE); CF-017 (K2/K4 exposure), CF-116 (accepted tension: surface layer named but late-bound); OQ-046, OQ-130, OQ-131, OQ-401, OQ-402; R-2.11.4, R-2.12.3, R-2.11.1, R-2.11.2, R-2.11.3

## Context

ADR-0050 named the surface ecosystem on one-sided evidence and deliberately left it *late-bound*: "WS-K2/K4 confirm at Phase 3 inside the boundary contract" (D1), with revalidation trigger 6 — "WS-K2/K4 (Phase 3) find that a surface *cannot* be served by a generated client over the local transport (Q-L1-14 narrowed) — re-run for the surface layer only" (§6). CF-116 recorded the tension with ADR-0009 AC6 and ruled it accepted. OQ-130 asks WS-K2/K4 to check *every* planned surface — web dev-tooling, desktop/IDE, SDK, and by extension the Lab and the MCP server — against that criterion and either bind the ecosystem or narrow Q-L1-14. ADR-0050 D1 also fixed that the CLI is kernel-native (in the ADR-0050 kernel ecosystem), which raises the question of whether a same-ecosystem host may bypass the wire and, if so, what stops that from becoming a second contract.

The audit answers both from source. Codex runs *the same* `MessageProcessor` for stdio/websocket transports and for its in-process TUI/exec surfaces over bounded typed channels, and states the rule in the module header: "preserve app-server semantics while avoiding a process boundary"; "responses still come back through the same JSON-RPC result envelope … rather than creating a second execution contract" (S-107 `in_process.rs`, `app-server-client/README.md`). OpenHands serves one abstract conversation contract over an in-process implementation and a remote one, generates its browser client from the pinned server's OpenAPI and, for the remote case, needs a `reconcile` pass because semantics drifted (S-110). Pi keeps a rich in-process harness beside a routed protocol whose payloads the server never interprets — a deliberate two-surface design (S-113). Cloudflare exposes its runtime to hosts only through a client SDK (WebSocket/HTTP with state sync and RPC) and never embeds the runtime in a host (S-557 `client-sdk.md`). ACP fixes stdio conventions (newline-delimited JSON-RPC, stderr for logs, lifecycle messages unbatched) and a draft streamable-HTTP transport (S-035 `transports.mdx`).

## Options considered

1. **One binding only (stdio); the CLI also spawns the kernel as a subprocess.** *Rejected:* ADR-0050 D1 makes the CLI kernel-native; a subprocess hop for the first-party surface adds a boundary the decision deliberately avoided (E1 wins T1 "fewer hot-path boundaries" with zero), and Codex/goose prove the in-process facade is cheap when it is the same contract.
2. **A richer in-process API for first-party surfaces, the wire contract for everyone else** (Pi shape). *Rejected:* two contracts drift (OpenHands `reconcile` is the symptom); the CLI would exercise verbs the SDK never can, breaking "every surface is a client" and I1; a private first-party verb is the intersection trap in reverse.
3. **Bind the surface ecosystem now and derive the transport from its conventions.** *Rejected:* ADR-0050 T4 chose late binding because it is free until Stage ≥ 5; nothing found in Phase 3 changes the evidence; binding early would be sponsor judgment, which ADR-0009 step 7 reserves.
4. **Chosen:** three bindings of one contract with a shared conformance suite; in-process admitted for first-party surfaces only; the answer to OQ-130 is "every planned surface is servable by a generated client over the local transport", so the late-bound surface binding stands and trigger 6 does not fire.

## Decision

1. **Three bindings, one contract (I8).** (a) **in-process** — typed request/response channels inside a process of the ADR-0050 kernel ecosystem; bounded queues; `WouldBlock`/`Overloaded` on saturation; events fanned out with the same frame kinds; the response envelope canonicalizes byte-for-byte to the wire form; admitted for first-party surfaces (the CLI, WS-K1; the kernel's own test client; the MCP server's tool bodies, WS-K3) and never exported to third parties. (b) **subprocess over stdio** — newline-delimited JSON-RPC 2.0, UTF-8, no embedded newlines, stderr for logs only, lifecycle-sensitive messages never batched (ACP conventions adopted verbatim); the client spawns the exact pinned kernel build (I3); the default for third-party SDK bindings and the Lab's binding (ADR-0050 lab row). (c) **local-network** — the same JSON-RPC over a localhost HTTP/WebSocket pair with per-connection `hello`, session attachment routing `{server_id, session_id, attachment_id}` and multi-presentation attachment (Pi precedent), an authentication scheme owned by WS-H3/K2; the binding for web/desktop/IDE surfaces. A binding may add transport facts (connection ids, auth, frame-size limits, `lagged` accounting, drain signalling) and may never add a verb, a field or an error variant.
2. **Conformance suite (AC-K4-2).** One fixture set — every operation, every error variant, every frame kind, resume, cancel, fork, permission round trip, host-executed capability round trip, drain during submit — runs over all three bindings; the canonical envelopes are diffed; a difference fails the build. The suite is the executable form of "not a second execution contract".
3. **What each surface is built on.** CLI = (a) with the full stable set plus first-party `experimental` opt-in. Web/desktop/IDE = generated client over (c): `attach` for viewers, `open_session` for launchers, `read/project/fork/navigate` for time travel, `stream_events` with ephemeral frames for debugging, Group M assembly operations for the assembly UI, `project(results_row)` and bundle reads for dashboards. MCP server (WS-K3) = kernel-side; its Lab tools wrap Groups S/M over (a) with server-minted handles (ADR-0097 D1). Lab (WS-J1/J3/J5, WS-I4) = (b) with Group M; per-run crossing (ADR-0045 §9). ACP artefact (ADR-0098) = a client over (a) or (b) lowering Group R frames and raising Group U. Third-party SDKs = generated clients over (b) or (c) containing no runtime logic. Hosted adapters (WS-J6) use `attach`/Group R only for adapter zero; the Hosting ABI itself is a different binding (CF-023).
4. **OQ-130 answer.** Every surface in decision 3 needs only the ADR-0050 D2 record set — verbs, canonical events, HIR documents/diffs/sealed definitions as data, metric/comparison/match records, budget/cost records, `project()` results — and no surface needs an operation that returns a live object, executes kernel code client-side, or bypasses the reference monitor. Q-L1-14 is **not narrowed**; ADR-0050 trigger 6 **does not fire**; the surface layer stays late-bound with its declared default, to be bound by WS-K2 at Stage ≥ 5 when the kernel↔surfaces boundary is first exercised (ADR-0050 (e)); ADR-0050 §5's per-layer reversibility (zero until bound; low after — regenerate the client) is unchanged. The one forward-looking gap is desktop/IDE surfaces that do not yet exist; the claim about them is that nothing they *could* need is excluded by the D2 set, falsifiable at Stage ≥ 5 by AC-K4-11 (each surface lists its operations and tiers in the readiness report).
5. **Non-local hosts.** Binding (c) is localhost-only at C1; exposing it beyond the host (remote services, browser-resident hosts against a remote kernel) is OQ-401 and, if admitted, a fourth binding by ADR with WS-H3 authentication and WS-H4 egress rules — never an implicit widening of (c).
6. **Bounds are data, measured first.** Durable-backlog and ephemeral-drop limits per connection, `cancel_deadline_ms` echo, and in-flight session caps are MUST-data constants set by the `l1-spike-spec.md` S2 boundary slice (OQ-131; AC-K4-9), not chosen here; OpenHands' "PROVISIONAL … Do not treat these as tuned" constants are the negative precedent.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-12 (bindings (b)/(c) are out-of-process by construction; (a) is conformance-tested equivalent), T-LCD-06 (hosting is a separate binding; no native contract references a surface), T-LCD-07 (client capabilities declared per connection; nothing inferred from the binding), T-LCD-11 (no lowering between bindings — canonical envelopes are diffed for equality). Does not address the remaining tests (no model-facing surface, comparison or IR construct is introduced). **ADR-0024 rung:** transports and the conformance suite are MUST-code; bounds and the first-party allowlist for binding (a) are MUST-data.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** one contract over stdio/websocket and in-process typed channels with identical envelopes, bounded queues and never-dropped server requests (S-107 `codex-rs/app-server/src/in_process.rs` L1–80; `app-server-client/README.md` "Transport model", "Backpressure and shutdown"); the cost of two localities with drifting semantics (S-110 `conversation/impl/remote_conversation.py` L289–500 `RemoteEventsList.reconcile`); a deliberately two-surface design as the counter-shape (S-113 `packages/agent` vs `packages/protocol/README.md` "payloads … remain opaque service data"); runtime reachable only through a client SDK (S-557 `docs/agents/client-sdk.md`); stdio transport conventions and batch rules (S-035 `docs/protocol/v2/transports.mdx`); multi-presentation attachment and drain semantics (S-113 `packages/server/README.md`, `src/session-router.ts`); generated clients over local transports in every audited surface (ADR-0050 (b): S-110 `clients/typescript`, S-111 `packages/sdk/js`, S-107 `sdk/typescript`, S-112 `ui/desktop`); per-run Lab crossing (ADR-0045 §9; ADR-0050 D2). WS-K2's stated screen set (doc 3 §2.11: assemble harnesses, launch experiments, trace/time-travel viewer, comparison dashboards, debugging) mapped operation-by-operation in decision 3.
- **(b) Source-code precedent:** codex `codex-rs/app-server/src/in_process.rs`, `codex-rs/app-server-client/{README.md, src/lib.rs}`, `codex-rs/app-server/src/transport.rs` L1–60 (one `MessageProcessor`, three transports) @0735c51; software-agent-sdk `openhands-sdk/openhands/sdk/conversation/conversation.py` L33–160 (factory over two localities) and `clients/typescript/package.json` @3fc7b22; pi-mono `packages/server/src/{session-router.ts, types.ts}`, `packages/client/src/client.ts` @400d690; agent-client-protocol `docs/protocol/v2/transports.mdx` @9b00c27. The three-bindings-one-suite rule with a first-party-only in-process allowlist is `no-precedent / novel` as a stated contract; Codex implements it without stating it as a rule.
- **(c) Disconfirming evidence considered:** (i) Pi and Cloudflare chose two surfaces on purpose — answered: their in-process surface *is* their runtime's own API for their own harness; ours is a runtime whose harness is data, so the in-process client needs nothing the wire cannot carry (ADR-0023). (ii) Codex's facade still needs "a short bootstrap phase … to reconcile startup response data with later events" (S-107 `app-server-client/README.md`) — answered: `open_session` returns `RealizedSettings` and the manifest reference synchronously (ADR-0176 D2), removing the reconcile window. (iii) Desktop/IDE surfaces are unknown — answered in decision 4: the claim is falsifiable at Stage ≥ 5 and reversal is cheap (ADR-0050 §5). (iv) An in-process binding for the CLI could tempt a private verb — answered by decision 2 (AC-K4-2 fails it). None overturns; none narrows Q-L1-14.
- **(d) Conditionality:** independent of model tier and task class; assumes ADR-0050 D1 layers (CLI kernel-native; Lab over the per-run boundary); assumes WS-H3/K2 supply an authentication scheme for (c) at C1; bounds assume the S2 spike runs at Stage 0 (OQ-131); the OQ-130 answer assumes WS-K2's Phase-3 dossier lists no operation outside decision 3 — if it does, that operation is added to the contract as `experimental` first (ADR-0178), and only an operation that *cannot* be a record-in/record-out call would fire trigger 6.
- **(e) Build-stage assignment:** **C0 / Stage 0** binding (b) skeleton + `hello`; S2 spike (AC-K4-9). **C0 / Stage 1** bindings (a) and (b); conformance suite (AC-K4-2); CLI over (a). **C0 / Stage 3** Lab over (b) with Group M (AC-K4-10). **C1 / Stage 4** binding (c) with WS-K2/H3 auth; ACP artefact as a client. **C1 / Stage ≥ 5** WS-K2 binds the surface ecosystem and ships generated clients; AC-K4-11; the readiness report records the OQ-130 confirmation and the unfired trigger.

## Consequences

- OQ-130 is answered (no narrowing); ADR-0050's amendment log gains a Phase-3 entry recording that trigger 6 did not fire and that the surface binding is confirmed servable; CF-116's accepted tension stands unchanged.
- WS-K1 builds the CLI on binding (a) and inherits AC-K4-2; WS-K2 builds every screen on the generated client over (c) and binds the surface ecosystem at Stage ≥ 5 (ADR-0050 §5); WS-K3's Lab tools use (a); WS-J3/J5/I4 use (b).
- WS-L6 packages one kernel build plus generated clients per binding; WS-H3/K2 own the (c) authentication scheme; WS-H4's egress rules apply if OQ-401 ever admits a non-local binding.
- `l1-spike-spec.md` S2 sets the connection bounds (decision 6) and appends its measurements to ADR-0050's log (OQ-131).

## Reversibility

**High** for bounds and the first-party allowlist (data). **Medium** for admitting binding (a) at all (removing it after Stage 1 means the CLI spawns the kernel — a performance change, not a contract change). **Zero-cost until Stage ≥ 5, low after** for the surface-ecosystem binding, exactly as ADR-0050 §5 records — this ADR does not change that.
