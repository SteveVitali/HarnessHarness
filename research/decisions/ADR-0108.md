# ADR-0108 — Loop detection, output validation and the mandatory state-invariant set: semantic-keyed deterministic detectors with a nudge → deny → stop ladder (judged tier C1), `OutputValidationPolicy` with a bounded format-failure counter, INV-1…INV-9 with `invariant_violation` quarantine; everything beyond the invariant set is a declared Lab factor

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-F2 (consumers: WS-F1, WS-B1, WS-B3, WS-C3, WS-E1, WS-G1, WS-G2, WS-H6, WS-I2, WS-J3, WS-L2) · **Phase:** 2 · **Related:** ADR-0013 (factor granularity), ADR-0015 (`Validator` kinds), ADR-0016 (`ControlBoundary.guards`), ADR-0019 (`ModelSurface`, `SurfaceArgMap`, closed-world rule), ADR-0020 (profile capability `structured_output`), ADR-0026 (rebuild equality; AC-B1-3), ADR-0027 (Observation `version_id`), ADR-0030 (inv. 5 no dangling intent), ADR-0031 (INV-8 redispatch rules), ADR-0033 (nudges at `definition` authority), ADR-0035 (no widening), ADR-0040 (conservation; root-first; `ask → deny`), ADR-0044 (veto invariants; quarantine checkpoint), ADR-0045 (outcome classes), ADR-0047 (judged values C1+, `charged_to`), ADR-0050 §8; CF-005, CF-226/-05/-07; OQ-062, OQ-092, OQ-257 (answered), OQ-261/-03/-04/-05; R-2.6.2, R-2.7.2, R-2.9.2

## Context

Doc 2 §5.4 asks the program to "measure which invariants belong outside the model"; doc 2 §11 lists schema validation under the Stage-1 envelope; Dhage's five constraints (S-070, `provisional`) include output validation and bounded retry, with a first-pass harness that improved reproducibility in one model–task cell and degraded it in two. The audit found loop detection in production is three-tiered — exact repetition (gemini-cli `sha256(name:args)`, cycles 1–5 × 5; goose `RepetitionInspector`; OpenHands four patterns over 20 events with a one-time nudge before `STUCK`), content repetition (gemini 50-char chunk hashes, disabled in code blocks/tables), and a judged tier only after 30 turns at confidence ≥ 0.9 with a prompt that is mostly a list of what is *not* a loop — and that every system keys on the surface tool name. Output validation is a pipeline of typed checks (Codex `RespondToModel | Fatal`; OpenHands unparseable/unknown/`ValidationError` with parameter *names* only; SWE-agent error template + `max_requeries`), and vendor constrained decoding guarantees schema conformance for a JSON-Schema *subset* only — numeric/length constraints are stripped and validated client-side; refusals arrive outside the schema; `max_tokens` truncation yields incomplete output (S-406/07). State invariants already exist piecemeal in ratified ADRs (0026/0027/0030/0031/0035/0040), but no audited harness names invariant violation as a run outcome — they log and continue; Pi synthesises settlements on crash and OpenHands enforces view properties on rebuild. MAST puts step repetition at 15.7 % and premature termination at 6.2 % — neither pole is free. LoopTrap shows model-owned termination is attackable (S-402, `provisional (mech)`).

## Options considered

1. **No loop detection; rely on ceilings.** *Rejected:* a loop burns the whole budget before the ceiling fires; every audited coding harness that runs unattended ships a detector; the cost of a nudge is one context item.
2. **Judged loop detection at C0 (gemini's LLM tier as the primary detector).** *Rejected:* ADR-0047 forbids judged values on the C0 headline; gemini itself runs it *after* two deterministic tiers and only with a separate double-check model; a judged detector is the LoopTrap attack surface.
3. **Surface-name-keyed detection (all audited systems).** *Rejected:* a surface rename or profile change breaks detection (T-LCD-10); keying on `capability.semantic_id` + canonical args via `SurfaceArgMap` is free once ADR-0019 exists.
4. **Repair-by-default output validation (OpenHands `fix_malformed_tool_arguments`).** *Rejected as default:* repairs hide model errors and bias compliance metrics (T-LCD-13); admitted as `repair_then_strict` with every repair ledgered.
5. **Invariant checks as logs (all audited systems).** *Rejected:* a scored run with a duplicated effect or dangling intent is a false measurement; the instrument's validity depends on ledger consistency (ADR-0026, ADR-0047 veto invariants).
6. **Deterministic semantic-keyed detectors with a graded ladder; judged tier C1; strict validation with bounded format failures; closed mandatory invariant set with quarantine; all thresholds factors (chosen).**

## Decision

1. **`LoopPolicy`** `{window_events: 25, exact_repeat{cycle_max: 5, threshold: 5}, no_progress{threshold: 3}, error_streak{threshold: 3}, monologue{threshold: 3}, response_ladder: [nudge, deny, stop] (each rung once per run), judged?: {validator_ref: Ref<Validator{kind: judge}>, after_turns, interval, confidence_threshold, charged_to} (C1 only)}`. **Keys:** `loop_key = H(capability.semantic_id ∥ canonical(params via SurfaceArgMap))` — never the surface name; the **no-progress predicate** is `same loop_key ∧ same Observation.version_id` (re-running tests after an edit changes the observation ⇒ not a loop; the same tool over twenty distinct paths ⇒ distinct keys ⇒ not a loop). Defaults are the audited values (OpenHands 4/3/3/6, gemini 5) and are **factors**. The graded response — nudge (a `definition`-authority context item, delivered/activated/followed events, `kind: loop_nudge`) → deny (typed refusal Observation for the repeated call) → `stop{loop_detected{detector, pattern}}` — gives the model one typed chance and makes `loop_nudge_recovery_rate` measurable. Content-chanting detection (gemini tier 2) is an optional C1 detector variant (OQ-264). The judged tier is a registered `loop_detector` variant referencing a `Validator{kind: judge}` under ADR-0047 governance with `charged_to` declared, admitted only at C1 and never as sole grounds for a stop without a preceding deterministic nudge (OQ-062 for detectors). **This detector is the one no-progress guard** shared with WS-F1's driver (OQ-257 answered: exact-repeat, no-progress, error-streak and monologue are Core detector classes with definition-settable thresholds; F2 owns the predicate).
2. **`OutputValidationPolicy`** `{mode ∈ {strict (default), repair_then_strict}, repairs ⊆ {json_repair, arg_coercion, trailing_text_strip}, max_format_failures: 3, on_failure: respond, on_exhaustion: stop{format_failure}}`, evaluated at G-INTERPRET as a fixed pipeline: parse → surface ∈ compiled `ModelSurface` (closed-world rule, ADR-0019) → schema conformance against the compiled surface schema → `SurfaceArgMap` → WS-E1 `preconditions.param_domain` → truncation/refusal/empty detection. **Failure sum (closed):** `{unparseable, unknown_surface, schema_violation, constraint_violation, precondition_violation, truncated, refusal, empty}`. Each failure appends `control.output.rejected{model_call_id, failure_class, surface_id?, detail_ref (redaction-safe ContentAddress), repaired, format_failures_running}` and a profile-rendered refusal Observation that **contains no bytes of the rejected arguments** (OpenHands names-only precedent; injected content is never echoed). A profile's `structured_output ∈ {none, json_mode, constrained}` capability changes the *expected rate* of the first three classes, never whether the pipeline runs (vendor guarantees cover a schema subset; truncation, refusal, stripped constraints and unknown surfaces remain). Repairs are ledgered (`repaired: true`) and excluded from compliance metrics; a profile-conditioned repair rule carries an assumption-debt record (T-LCD-05). Format failures are bounded by the `format_failures` view because "retry until it parses" is the retry-loop cluster in disguise.
3. **Mandatory invariant set INV-1…INV-9 (C0; each a pure predicate over ledger records; evaluated at G-POST-EFFECT / G-DECIDE / G-RESUME):** INV-1 every opened scope is closed by exactly one terminal no later than its deadline (ADR-0026; force-closed by the envelope); INV-2 no dangling intent — every `action.effect.intended` has a terminal or `unknown` visible to the model (ADR-0030 inv. 5); INV-3 stop is a barrier (no `committed`/`model.call.requested` after `control.decision{stop}` except grace/drain); INV-4 conservation — Σ children consumed + reserved ≤ each ancestor ceiling at every charge (ADR-0040); INV-5 identity — `attempt_no` strictly increases per scope id, at most one `committed` per `(effect_id, attempt_no)`, idempotency key invariant across attempts (ADR-0031); INV-6 every feedback path is bounded — each retry, validator invocation, hook re-entry, compaction attempt and child spawn posts to a bounded counter (`retries`, `evaluator_calls`, `spawns`, `compaction_attempts` — the last a proposed extension counter, OQ-262); INV-7 the envelope never widens — every envelope-produced permission decision is `deny`, every budget event is `consumed/reserved/released/exceeded`, never a loosening `amend` (ADR-0017/0035); INV-8 no automatic redispatch of an `irreversible` effect and no redispatch of `unknown` without probe/idempotent class (ADR-0031 inv. 4); INV-9 rebuild equality at turn boundaries for the `effect_ledger` and budget `remaining` views (`project()` equals the live view; ADR-0026 AC-B1-3; every turn at Stage 1–3, sampled by policy outside experiments at Stage ≥ 4 — OQ-263). `ext.*` registered predicates may be added by a definition, never removed. **Violation ⇒** `control.invariant.violated{invariant_id, evidence_refs[], detected_at_guard}` → `stop{invariant_violation}` → outcome class `infrastructure_failure` → `security.audit.checkpoint{kind: quarantine}` (WS-H6). A run that violates its kernel invariants is not scored; it is quarantined and audited. The checker is itself under test: AC-F2-03 requires a fault-injection battery (five injected violations each detected) **and** a clean Stage-3 suite run with zero invariant events.
4. **Objective vs subjective stopping constraints.** Ceilings, deadlines, exact-repeat/no-progress loops, invariant violations and format-failure exhaustion are *objective* and code-owned: nothing the model says can extend a ceiling, a deadline or a threshold (AC-F2-07, LoopTrap resistance); `done`, `give up`, `ask` are *subjective* and belong to β (WS-F1) and are measured. Envelope nudges carry `definition` authority (ADR-0033) so they are never confused with injected content.
5. **Every behaviour beyond INV-1…9 is a declared Lab factor** (`configuration-level`, ADR-0013) with class-scoped process metrics computed from ledger events (ADR-0044/0045): `loop_stop_rate`, `loop_nudge_recovery_rate`, `format_failure_rate` (per profile), `invariant_violation_rate` (veto), `premature_stop_rate` (with WS-G2). Detector variants and validation modes are compared under a `MatchSpec` (ADR-0041; T-LCD-14). Dhage's mixed cells are the reason none of these is a Core constant.

**T-LCD statement.** T-LCD-01 (no per-model branches; thresholds conditioned only via rules with debt records — T-LCD-05); T-LCD-02 (refusals and nudges are typed items/`Text` leaves in `HarnessRule`s); T-LCD-08 (pipeline receives the profile's `structured_output` capability; same checks under every profile — AC-F2-05); T-LCD-09/-14 (thresholds, ladder, mode as declared factors; matched comparison); T-LCD-10 (loop keys derived from semantic identity, not surface names — AC-F2-01 rename test); T-LCD-13 (nudge delivered/activated/followed; repairs ledgered and excluded from compliance); T-LCD-15 (`loop_*`/`format_failure_rate` render `n/a` where tool calls are not observable). **ADR-0024 ladder:** INV-1…9, the failure sums, the ladder shape, semantic keying, quarantine = Core invariants; `LoopPolicy`/`OutputValidationPolicy` values = typed parameters; detector classes (`exact_repeat`, `no_progress`, `error_streak`, `monologue`, `content_chant`, `judged`) = registered variants of a `loop_detector` class; nudge/refusal texts = `Text` leaves.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: step repetition 15.7 %, unaware of termination 12.4 %, premature termination 6.2 % in 1,600+ annotated traces across 7 frameworks (S-403 MAST, Tier C); infinite agentic loops as unbounded feedback paths in harness code, 68 confirmed in 47 projects (S-401, `provisional (mech)`); termination poisoning 3.57× mean / 25× peak step amplification (S-402, `provisional (mech)`); constrained decoding guarantees a JSON-Schema subset only, refusals outside the schema, truncation at `max_tokens` (S-406 Anthropic, S-407 OpenAI structured-output docs — Tier B vendor documentation); schema-validated planning as an implementable, measurable constraint whose effect is model-dependent (S-070 Dhage, `provisional`, mechanism only); ratified invariants ADR-0026/0027/0030/0031/0035/0040 (the INV set is their consolidation); judged values labelled, calibrated and instrument-charged (ADR-0047). No `provisional` claim is load-bearing: the C0 decision rests on three independent Tier-B detector implementations, vendor documentation and ratified ADRs.
- (b) Source-code precedent (2026-09-10, pinned commits): google-gemini/gemini-cli @ `ed2ac40` `packages/core/src/services/loopDetectionService.ts` L29–64 (`TOOL_CALL_LOOP_THRESHOLD = 5`, `CONTENT_LOOP_THRESHOLD = 10`, `LLM_CHECK_AFTER_TURNS = 30`), L172–176 (content check disabled inside code blocks/tables), L316–345 (cycle detection lengths 1–5 over `sha256(name:args)`), L347–420 (judged check with separate model and false-positive prompt); OpenHands/software-agent-sdk @ `3fc7b221` `openhands-sdk/openhands/sdk/conversation/stuck_detector.py` L21, L104–155, L192–248, L250–300 (20-event window; action–observation repeat 4; action–error streak 3 with one nudge; monologue 3; alternating 6), `conversation/impl/local_conversation.py` L723–746 (nudge-then-stop), `agent/agent.py` L1150–1200, L1275–1310 (unparseable / unknown / `ValidationError` with parameter names only); aaif-goose/goose @ `fae91d01` `crates/goose/src/agents/tool_monitor.rs` L33–80 (`RepetitionInspector` denies identical consecutive calls), `agents/agent.rs` L88, L154–176 (stop-hook block cap — a bounded harness feedback path); SWE-agent @ `3ea751c` `sweagent/agent/agents.py` L1089–1220 (format-error template, `max_requeries`, `exit_format`); openai/codex @ `0735c519` `codex-rs/tools/src/function_call_error.rs` L5–10, `core/src/tools/router.rs` L269–273 (argument parse errors as `RespondToModel`); browser-use @ `50f2055` `browser_use/agent/service.py` L1297–1302 (consecutive-failure cap); OpenHands `conversation/state.py` and Pi (via WS-B1 F3) for view-property enforcement on rebuild. **`no-precedent / novel`:** a typed `control.loop.detected` ledger event with the offending keys; semantic-identity keying; bounding validator/hook/compaction feedback paths in general form (INV-6); invariant violation as a run outcome with quarantine.
- (c) Disconfirming evidence considered: (i) gemini-cli's judged tier and its long "what is not a loop" prompt are evidence that exact-repeat detection was insufficient *and* that content detection produced false positives — mitigated by semantic + args keying, the observation-identity no-progress predicate, the graded ladder, and measured `loop_stop_rate`; the judged tier is C1 and `provisional`; (ii) constrained decoding makes parse/schema failures rare for capable models, so validation may be dead weight — but the vendor guarantee excludes exactly the constraints agent schemas most need (`minimum`, `maxLength`), plus truncation/refusal/unknown-surface cases; the pipeline is cheap and its rate is a per-profile metric; (iii) automatic repair (OpenHands) improves throughput — admitted as a ledgered, non-default mode; (iv) quarantine on invariant violation discards possibly scoreable runs and a buggy checker halts good runs — the set is closed and small, each predicate is pure over records, AC-F2-03 tests the checker for false positives, and false halts appear as visible `infrastructure_failure{invariant_violation}` rows rather than silent drops; a false *measurement* is the worse failure for an instrument; (v) MAST's premature terminations warn against aggressive stops — the ladder stops only after a nudge and a deny, and `premature_stop_rate` is reported. None overturns.
- (d) Conditionality: independent of model tier for the invariant set; detector *thresholds* assume coding/terminal-class tasks where repeated identical calls are rarely legitimate (batch operations across distinct targets are distinct keys); output validation assumes compiled `ModelSurface` schemas (ADR-0019) and a profile that declares `structured_output`; the judged tier assumes a calibrated judge under ADR-0047 with an independent profile; hosted participants: detectors `n/a` unless tool calls are observable.
- (e) Build-stage assignment: **C0 / Stage 0** — parse/unknown-surface validation with refusal observation. **C0 / Stage 1** — INV-1…INV-9 with `control.invariant.violated` and quarantine; deterministic detectors (exact repeat, no progress, error streak, monologue) as the `loop_detector` class's C0 variant with the nudge → deny → stop ladder; `OutputValidationPolicy` strict mode with the full failure sum. **C0 / Stage 2** — nudges as `HarnessRule` artifacts with T-LCD-13 events; E1 precondition checks. **C0 / Stage 3** — AC-F2-01/03/05/07/09/10 in the Stage 3 suite; metric declarations. **C1 / Stage 4** — judged detector; content-chanting variant; `repair_then_strict`. **Stage 5** — profile-conditioned thresholds/templates with retirement tests (T-LCD-05); INV-9 sampling policy outside experiments.

## Consequences

- WS-F1: one no-progress predicate (F2's), one threshold; driver invokes the detector through `envelope.check` (CF-229; OQ-257).
- WS-B1/ADR-0026: `control.loop.detected`, `control.output.rejected`, `control.invariant.violated` added (CF-223).
- WS-H6: `security.audit.checkpoint{kind: quarantine}` consumer; `invariant_violation_rate` as a veto invariant.
- WS-I2/ADR-0045: `loop_detected`/`format_failure` as `scored` stratifiers (OQ-261); five process metrics declared.
- WS-C3: refusal/nudge rendering templates are profile artifacts (`Text` leaves) with no echo of rejected arguments.
- WS-E1: `preconditions.param_domain` is checked at G-INTERPRET; WS-G1/G3 own semantic correctness, never re-implemented here.
- WS-L2/D2/H5: OQ-262 (extension counters for compaction attempts / hook re-entries).
- WS-A4: compiled surface schemas are the validation target; no new `RuntimePlan/1` node kinds.

## Reversibility

**Medium for the invariant set, high for everything else.** Thresholds, ladder rungs, validation mode and detector variants are factors and can be re-tuned or retired by data. Removing an INV would reopen a ratified ADR's guarantee (each INV cites one); replacing quarantine with log-and-continue would require WS-I2/H6 to accept possibly inconsistent runs as scored — a change to the instrument's evidence standard (ADR-0002), not a parameter.
