# ADR-0057 — Secret-visibility invariants: credentials exist above the broker only as secret channels (`SecretRef`), never as values in definitions, contexts, ledger, environments or sinks

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-H3 (consumers WS-B1, WS-B5, WS-D1, WS-E5, WS-H1, WS-H4, WS-H6, WS-A3, WS-A4, WS-J6) · **Phase:** 2 · **Related:** ADR-0002 (iii: credential mediation outside the editable surface), ADR-0016/ADR-0048 (`secret_access` effect domain; `Permission`), ADR-0024 (MUST-code), ADR-0025 (`resolve` replaces secrets by channel names), ADR-0026 (secret values "references only"; durable-before-visible; `lifecycle.ledger.redacted`), ADR-0029 (redaction-safe hashing), ADR-0033/0034/0035 (provenance; `kernel` deriver for deterministic projections; monitor reads records only), ADR-0036/0037 (allocated ids; logical names), ADR-0042/0044 (content levels; `SinkPolicy`; audit completeness), ADR-0045/0047 (`secret leak` veto invariant), ADR-0050 §8; CF-130, CF-133; OQ-149, OQ-151; R-2.8.3; T-LCD-02/06/07/10/11/12

## Context

Doc 2 §5.6 and §11 require that "credentials should be mediated rather than injected into the model-visible environment whenever possible" and that the execution environment keep "credentials outside where possible." Phase 1 already fixed three fragments: `resolve` replaces secrets by channel names (ADR-0025), the ledger stores "secret values (references only)" (ADR-0026), and `secret leak` is a reserved veto invariant (ADR-0045/0047). None states *what a secret is* in the IR, *where its value may exist*, or *how* each surface is kept value-free. The evidence (dossier §4a F1–F5) shows the failure condition is the credential being reachable — in the environment, in files, in context — while an egress channel exists; production designs converge on "the sandbox never holds the value" (S-053, S-047) and OSS implements it (S-107 `network-proxy/src/credential_broker.rs`, S-110 `secret_registry.py`).

## Options considered

1. **Environment scrubbing plus output masking only** (Codex default excludes; OpenHands masking). *Rejected as the boundary:* name heuristics under- and over-match; masking misses encoded values (S-280, `provisional`, used for mechanism only); neither prevents a tool from reading a mounted file or a git remote.
2. **Secrets as ordinary `Text` leaves with `readers` labels enforced by IFC** (Fides/CaMeL style). *Rejected for C0:* `readers` enforcement is C2 (ADR-0033 tiering); a value in a `Text` leaf is already in the model boundary and the ledger, which is the failure.
3. **Secrets as first-class *channels*: a typed `SecretRef` in definitions/context, a value only inside the kernel-side broker, placeholders in environments, fingerprints in the ledger; every surface enforced by a deterministic invariant (chosen).**
4. **Full confidential-computing enclave for the broker** (S-287). *Rejected:* out of scope (no vault product); the broker's TCB is the kernel's TCB.

## Decision

1. **Representation.** A credential exists above the broker only as a **secret channel** (`SecretChannel{channel_id: logical name, spec, revision, provenance}`) and is referenced only by the typed leaf `SecretRef{channel_id}` — never as `Text`, `CompiledPayload`, a parameter value or an `ext` value. Channel identity is the logical name with append-only history (ADR-0037); the value and every placeholder are excluded from `semantic_id` and `version_id` (T-LCD-10). The only model-visible form is `name + description` with `authority = definition` (S-110 `get_secret_infos` precedent).
2. **Invariants SV-1…SV-10** (dossier §6.1) are kernel invariants with errors, never warnings: SV-1 value-free definitions (`seal` runs `leak_scan`; `SecretValueInDefinition`; a widening `HirDiff` that introduces a value is rejected); SV-2 value-free ledger, blobs, manifests and sink deliveries (`redact` before `append`; every delivery re-scanned regardless of `SinkPolicy.redaction`); SV-3 value-free model boundary (observations masked before model-visible; request views scanned; `context.assembled.secret_hits`); SV-4 value-free environments by default (deny-by-default allow-list from the definition; kernel non-inheritable list; placeholders ≥ 16 bytes with a recognisable prefix; snapshots/forks keep placeholders); SV-5 every use an audited effect; SV-6 lifetime ⊆ run; SV-7 delegation attenuates and hosted participants receive only declared channels; SV-8 PDP/CDP separation; SV-9 fail closed; SV-10 non-transferability best effort.
3. **Redaction-at-source.** `redact(payload, ctx) → (masked, hits[])` is a deterministic `kernel` deriver (ADR-0034 P1: labels unchanged) run on every content-bearing event before `append`, on every observation before it is model-visible, on environment snapshots and on every export delivery; detectors form the closed list `{known_value, known_value_encoded (C1), placeholder_passthrough, pattern, canary}`; masks are `SecretFingerprint{channel_id, revision, prefix}` (keyed, truncated, irreversible; parameters OQ-151) so hits correlate across events without exposing bytes. Rotated revisions stay in the mask set. `lifecycle.ledger.redacted` remains the post-hoc path (ADR-0026/0029), never the primary one.
4. **Ledger events** (extending WS-B1 §6.3 `security.credential.mediated`, CF-130): `security.credential.{bound, used, denied, revoked, rotated}`, `security.secret.redacted{target_ref, hits[]}`, `security.secret.leak_detected{location, hit, detector}` (veto). Payloads carry `binding_id`, `channel_id`, destination host, `effect_id`, `monitor_decision_ref`, fingerprints — never values, never placeholders' real counterparts; every class is audit-grade under ADR-0066 (kernel producer; content-free `audit_fields`; `security.credential.mediated` is superseded by this family — CF-130).
5. **Lowering.** A `SecretRef` lowers to a protocol target as `{scheme, channel reference}` in a typed slot; a target that needs a value at lowering time (e.g. a stdio-launched server's environment) is a declared `no_slot` loss and forces a run-time `bind` recorded in the ledger (T-LCD-11); lifting a credential-bearing payload assigns `authority = unverified` and redacts it.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: exfiltration as the canonical injection goal — S-097 (Tier A; `default_suites/v1/{slack,workspace,banking}/injection_tasks.py`); zero-click exfiltration over trusted egress — S-283 (CVE-2025-32711); vendor incident and fix "credentials never enter the sandbox" / "only passes requests carrying the VM's own provisioned session token" — S-053 (Tier B); "tokens are never reachable from the sandbox" — S-047 (Tier B); passthrough forbidden, audience binding MUST — S-153 `basic/authorization/security-considerations.mdx` (spec); PDP never touches credential material, fail-closed on audit failure — S-274 (Internet-Draft; used for mechanism); leaks arrive via debug output into context (73.5 %) — S-279 (`provisional`, corroborative only); encoding defeats naive masking — S-280 (`provisional`, motivates the C1 tier only).
- (b) Source-code precedent: `openai/codex @ 0735c51` `codex-rs/protocol/src/shell_environment.rs` L13–19 (non-inheritable list), L120–135 (default excludes), `core/src/exec_env.rs` L20–35 (`env_clear`), `network-proxy/src/credential_broker.rs` L49–80, L530–560 (placeholder virtualisation), `network-proxy/src/proxy.rs` L1139–1150 (snapshots keep placeholders), `protocol/src/config_types.rs` L575 (redacted argument type); `OpenHands/software-agent-sdk @ 3fc7b22` `openhands-sdk/openhands/sdk/conversation/secret_registry.py` L62–230 (last-value masking incl. rotated values, whole-model walk, name+description to prompt), `openhands-agent-server/openhands/agent_server/_secret_redaction.py` (export-boundary redaction incl. ciphertext), `openhands-tools/openhands/tools/terminal/impl.py` L360–377 (mask before return). The integrated invariant set with `SecretRef` in the IR and fingerprints in a hash-chained ledger is `no-precedent / novel` as a whole.
- (c) Disconfirming evidence considered: masking is incomplete under encoding and costs per-observation latency (S-280 `provisional`; S-110 60-s back-off comment) — does not overturn because masking is defence-in-depth under SV-2/3 and the boundary is SV-4; deny-by-default environments break tools (S-107 ships it as default; allow-lists are MUST-data edits); forensic debugging wants the real request — the vault's own log correlates by `binding_id` (CB4A TM-7 separate trust boundary; ADR-0026 already decided references only).
- (d) Conditionality: independent of model tier and task class; assumes an environment handle with a declared `isolation_class` (WS-B5) and an egress boundary the kernel controls (WS-H4); SV-10 depends on destination support for sender constraints; the C1 encoded-variant detectors assume the known-value set is small (tens of channels), which every audited system satisfies.
- (e) Build-stage assignment: C0 / Stage 0 (allow-list environments, gateway credential kernel-held, known-value masking, leak scan as test); C0 / Stage 1 (`SecretRef`/`SecretChannel`, `redact`/`leak_scan`/`fingerprint`, ledger events, SV-1/2/3/4/9 static and contract tests LT-01/08/10); C0 / Stage 2 (snapshot rule, rotation mask retention); C1 / Stage 3 (encoded-variant detectors, LT-12).

## Consequences

WS-A3 adds `SecretRef` as a reference kind and `SecretChannel` as a registry entity or dialect addition (OQ-149); WS-B1 amends the `security.credential.*` row; WS-E5 masks every observation; WS-D1 scans request views and renders `SecretRef` as name + description only; WS-B5 exposes `env_apply/env_snapshot/isolation_class`; WS-H6 attests fingerprints and the `used` trail; WS-I2 registers `secret_leak` as a class-scoped veto metric; WS-A4 emits `no_slot` losses for value-demanding targets. Every run in the Stage 3 suite carries at least one canary channel.

## Reversibility

**Low-to-medium.** Relaxing SV-2/3 would require rewriting ledger consumers and re-running every leak test; changing the fingerprint scheme is a bridge record (ADR-0036); adding detectors or delivery modes is additive. Reversing "channels, not values" would reopen ADR-0025/0026 and the veto metric — expensive in program terms.
