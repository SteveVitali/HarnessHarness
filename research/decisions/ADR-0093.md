# ADR-0093 — Exposure modes, the exposure plan and `callable ⇔ revealed`: the tool plane's run-time selection under the closed-world rule

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-E3 (consumers: WS-D1, WS-D2, WS-E1, WS-E2, WS-E4, WS-C3, WS-F1, WS-H1, WS-H7, WS-B1, WS-I2, WS-J3) · **Phase:** 2 · **Related:** ADR-0016 (entity 6 `ToolCapability`; `HarnessArtifact.tool_surface`), ADR-0019 (closed-world rule; run time decides *selection*; `select_surfaces`), ADR-0020 (`deferred_tools`, `tool_search`; rule kinds), ADR-0021 (`listChanged` on selection change), ADR-0022 (composite surfaces C2), ADR-0023/0024 (params are MUST-data), ADR-0034 (labels of delivered items), ADR-0039/0040 (`context.occupancy`, `tool_calls`), ADR-0045 (metric declarations); WS-D1 proposed ADR-1/ADR-2 (`Candidate.state ∈ {handle_only, expanded}`; `surfaces_revealed[]`); CF-202…CF-205; OQ-233/02/03; R-2.5.3, R-2.4.1, R-2.5.1

## Context

ADR-0019 fixes that compile time decides the existence, identity and shape of every tool surface and that run time decides *selection* — "deferred loading, tool search" — and names `select_surfaces` as the operation the tool plane executes under the closed-world rule. WS-D1 treats deferred tools as `handle_only` `tool_surface` candidates whose expansion "goes through `select_surfaces`". Nothing yet says what the closed set of exposure states is, who may narrow it, how a surface the model has never seen becomes callable without the runtime "introducing a surface", how revealed surfaces persist and are evicted, or why a call to an un-revealed surface must be a typed refusal. The audit (dossier §4c) found one complete precedent — codex's `ToolExposures {DIRECT, DEFERRED, CODE_MODE}` narrowed by server `omit_tools_from`, by `direct_only_tool_namespaces`, and by a model/provider search gate, with direct and deferred "mutually exclusive" (`codex-rs/core/src/tools/spec_plan.rs` L197–262) — and three partial ones (goose code-mode disclosure and `_meta.ui.visibility`; opencode permission-filtered catalogs; gemini-cli per-call subsets). Both vendor APIs keep the prompt prefix fixed and append discovered tools after it to preserve caching (S-379, S-380), and MCP asks servers for deterministic tool order for the same reason (S-153 `tools.mdx` L70–73). No audited system records exposure as data, refuses un-revealed calls as a typed condition, or lets a policy add a mode a source denied.

## Options considered

1. **No exposure model — every compiled surface is always in the tool list** (gemini-cli, mini-SWE-agent class). *Rejected as the only mode:* it is the C0 default (`direct_all`) but cannot express deferral, code mode or hidden app tools, so R-2.5.3 would be unspecified; T-LCD-13 needs per-surface delivery anyway.
2. **A boolean `deferred` per tool plus a search tool** (Anthropic `defer_loading`). *Rejected:* conflates *indexed* (name visible) with *absent*, has no `hidden`/`code_mode`, and leaves narrowing (who may defer what) unspecified.
3. **Let the exposure policy own the whole tool list per call** (goose `prepare_inference_tools`, pi `transformContext`-style). *Rejected:* a policy could reveal a surface the definition or profile denied, reorder the list (breaking caches and I-ORDER), or hide a pinned surface; the failure signature of T-LCD-08's "variant that must read a global or patch Core".
4. **A closed mode sum per surface per call, narrowed only (definition ∩ profile ∩ policy), produced by a kernel-wrapped policy into an append-order-stable exposure plan recorded in the ledger; a revealed set as run state; a kernel refusal `SurfaceNotRevealed` before dispatch; deferral requires a compiled discovery capability (chosen).**

## Decision

1. **Modes.** `ExposureMode ∈ {direct, indexed, deferred, code_mode, hidden}` is a closed kernel sum (registered `ext` permitted). `direct` delivers the compiled definition (a WS-D1 `expanded` `tool_surface` candidate); `indexed` delivers only the typed `IndexForm` (D1 `handle_only`), at `IndexGranularity ∈ {surface, namespace, source}`; `deferred` delivers nothing and is reachable only through the discovery capability (ADR-0094); `code_mode` is callable only from an executed program (C2, WS-E2/E5; disclosure sub-policy `{catalog, filesystem, sidecar}`); `hidden` is never delivered, indexed or model-callable. Exactly one mode per surface per plan.
2. **Narrow-only composition.** Each `CatalogEntry` carries `admitted_modes = definition_modes ∩ profile_modes ∩ policy_modes`; `pinned` (definition-declared always-direct) and `hidden` are set by the definition or kernel and are immutable to policy; `deferred` ∈ profile_modes only if the profile declares a usable discovery lowering or the kernel index is bound. A policy that returns a mode outside `admitted_modes`, or touches `pinned`, `hidden`, `label`, `permission_coverage` or `availability`, is rejected with `PolicyViolation` before any delivery.
3. **Component class and operation.** `tool_exposure_policy` is a registered component class whose contract is `rank(entries, turn_state, ModelProfile, ResourceAccount, params) → [(surface_id, mode)]`; the kernel wraps it as `select_surfaces(catalog, turn_state, profile, account, params) → ExposurePlan` performing `admit` (pinned → direct; hidden → hidden; unavailable → omitted; unsupported modes → omitted with reason) → `policy.rank` → `enforce` (budget share; I-DISCOVERY; I-ORDER). The absent-slot default is `direct_all`. Every parameter (`pinned_direct[]`, `direct_token_share`, `default_mode_by_source`, `max_direct_count`, `retention`, `permission_gate`, …) is MUST-data (ADR-0024).
4. **The exposure plan is ledger data.** `ExposurePlan{plan_id, model_call_id, catalog_id, entries[(surface_id, mode)], discovery_surface_ids[], order, budget_estimate, omitted[{surface_id, reason}], derived_from, deterministic}` is emitted as `action.tool.exposure.planned` (scope `context_assembly`; payload offloaded above the class threshold) before D1's `assemble`; omissions are data with reasons (`budget | policy | permission_uncovered | unavailable | hidden | mode_unsupported_by_profile`).
5. **Order stability.** Within a run, each plan's `order` is a prefix-extension of the previous plan's order; newly revealed surfaces are appended; the transcript renderer (D1/C3) never reorders delivered tool surfaces. Placement of the revealed block relative to the cached prefix is a profile `caching_markers`/`prompt_layout` rule.
6. **Revealed set.** `RevealedSet` is run state projected from `action.tool.surface.revealed/evicted` events, with `retention ∈ {call, turn, run, until_evicted}` (default `run`) and `cause ∈ {policy, discovery, principal, procedure, pinned}`; revealed surfaces enter subsequent plans as `direct`; `evict` is exposed to WS-D2 and to the policy; pinned surfaces are never evicted.
7. **`callable ⇔ revealed`.** Before the reference monitor evaluates a proposal, the kernel checks that the proposed surface was `direct` in the plan of the model call that produced the proposal (or `code_mode` for program-originated proposals); otherwise the proposal is refused with `SurfaceNotRevealed{hint ∈ {search, none}}` — the refusal never carries a definition — and `action.tool.call.refused` is recorded. This is the run-time face of ADR-0019's closed-world rule; it never grants authority (I-NOAUTH), and `permission_coverage` on entries is a selection input only.
8. **Deferral needs discovery.** A plan containing a `deferred` entry, or an `indexed` entry at granularity ≠ `surface`, must contain a `direct` discovery capability; otherwise `NoDiscoverySurface`. `validate_assembly` refuses a definition that admits `deferred` without binding one.
9. **Tiers.** C0 · Stage 1: the mode sum, `CatalogEntry`/`ExposurePlan`/`RevealedSet` schemas, `direct_all`, `check_callable`, the events, invariants I-CLOSED/I-NARROW/I-ONE-MODE/I-CALLABLE/I-ORDER. C1 · Stage 2/5: `indexed`/`deferred` policies with ADR-0094's index; profile-conditioned placement and shape rules (C3). C2: `code_mode` and permission-gated discovery.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: tool cardinality degrades cost, accuracy and cache economics (S-040; S-379 "degrades once you exceed 30–50 available tools"; S-380 "changing the loaded set breaks cache"; S-153 deterministic ordering "improves LLM prompt cache hit rates"); exposure as a per-surface set narrowed by source, namespace and model/provider (S-107); code mode as an exposure state (S-112; S-111); revealed tools persisting across turns and through compaction (S-379, S-380, S-107 `compact_remote_history.rs` L158); the closed-world rule (ADR-0019 §6, ratified); deferral state as observability data (S-109). Retrieval-quality risk that makes omissions-as-data necessary: S-368 (Tier A).
- (b) Source-code precedent: `codex-rs/tools/src/tool_executor.rs` L14–60 and `codex-rs/core/src/tools/spec_plan.rs` L197–262, L629–642 (S-107 @0735c51) — exposure bit-set, narrowing, provider gate, mutual exclusion; `codex-rs/core/src/tools/tool_namespaces_info.rs` L18–110 (per-turn exposure metadata); `crates/goose/src/agents/reply_parts.rs` L246–290 (S-112 @fae91d0) — code-mode disclosure removing tools from the list; `_meta.ui.visibility` filter; `packages/opencode/src/tool/registry.ts` L275–300 (S-111 @9f8db11) — permission-filtered catalog, model-conditioned surface choice; `packages/core/src/tools/tool-registry.ts` L647–730 (S-119 @ed2ac40) — explicit per-call subset; `src/claude_agent_sdk/types.py` L764–817 (S-109 @ad77094) — `isDeferred`/`isLoaded`. The narrow-only composition, plan-as-ledger-data with reasons, and `SurfaceNotRevealed` as a kernel refusal are `no-precedent / novel` (the provider's HTTP 400 for unknown `tool_reference`s, S-379, is the nearest analogue).
- (c) Disconfirming evidence considered: (i) deferral can lose to direct loading for small catalogs or when every tool is used each turn (S-379's own guidance; D1 §5 under-retrieval) — answered: `direct_all` is the C0 default and every deferral variant must win a matched-budget `ComparisonReport`; (ii) `callable ⇔ revealed` refuses a model that "remembers" a tool — answered: this is the closed-world rule; the refusal is counted (`unrevealed_call_rate`) and may hint "search"; (iii) plans per call are voluminous — answered: mode *changes* plus `catalog_id` are stored; the full vector is a projection; (iv) OpenAI namespaces mix immediate and deferred members, contradicting codex's mutual exclusion — answered: mode is per *surface*, granularity per *index entry*, so both shapes are expressible. None overturns.
- (d) Conditionality: assumes ADR-0019's compiled surfaces with stable ids and D1's candidate model; C0 content is independent of model tier and catalog size; the *benefit* of `indexed`/`deferred` is model-conditioned (models trained on namespaces/search, S-380; retrieval-aware training, S-385) and therefore lives in profile rules with assumption-debt records, never in the kernel; no `provisional` result is load-bearing.
- (e) Build-stage assignment: **C0 / Stage 1** (schemas, `direct_all`, `check_callable`, events, invariants); **C0 / Stage 3** (AC-E3-1/-4/-7 executable; MCP export reflects the plan); **C1 / Stage 2 & 5** (indexed/deferred policies; profile rules); **C2** (`code_mode`, permission-gated discovery).

**T-LCD statement (ADR-0007 decision 5).** Satisfies: T-LCD-02 (index forms and plans typed; opacity counted), T-LCD-08 (`rank` receives profile and account), T-LCD-10 (entries keyed by `surface_id`/`semantic_id`), T-LCD-12 (operations), T-LCD-13 (per-surface delivered/activated), T-LCD-15 (metrics class-scoped, ADR-0094). Does not by itself satisfy T-LCD-01/-04/-11 — those are carried by ADR-0094 (discovery capability) and ADR-0021. Rung on the ADR-0024 ladder: parameters are data; modes and invariants are Core by this ADR.

## Consequences

- WS-D1 maps `handle_only` ⇔ `indexed` and receives no candidate for `deferred`; `RenderedRequest.surfaces_revealed[]` becomes a projection of the plan (CF-203/03).
- WS-F1/WS-E5 call `check_callable` before dispatch; WS-H1's monitor runs unchanged afterwards.
- WS-D2 evicts revealed surfaces only through `evict`; WS-C3 owns placement/ordering rules under I-ORDER.
- WS-B1 registers eight `action.tool.*` event classes (OQ-235).
- WS-E1 adds `admitted_modes`/`pinned` as definition-level fields on the tool surface record and supplies the index projection fields.
- WS-J3/I2 gain the metrics and the required comparison shape.

## Reversibility

**Low for `callable ⇔ revealed` and narrow-only composition** (removing them reopens the closed-world rule and lets policies widen exposure — a governance property ADR-0002's evolution relies on); **medium for the mode set** (adding a mode is a dialect bump; collapsing `indexed` into `deferred` loses OpenAI/Cursor shapes); **high for parameters and defaults** (data).
