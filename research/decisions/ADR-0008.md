# ADR-0008 — Canonical names for the IR, participant classes, lab, ABI and compiler vocabulary

**Status:** ratified (amended at Phase 0 synthesis, 2026-09-09 — see *Amendment log*); effective at Ontology **v0.1**
**Owner workstream(s):** WS-L7 (author); WS-A2 (ontology v1 owner) ratifies vocabulary; WS-L6 owns public naming · **Phase:** 0 · **Related:** ADR-0001 (participant-class definitions unchanged); OQ-035; CF-015; R-2.12.5, R-2.1.1

## Context

Doc 3 §5 asks WS-L7 to name the IR, the participant classes, the lab and the ABI "consistent with the ontology register", and permits the product name to remain "MetaHarness". The ontology already ratifies four descriptors from ADR-0001 (*IR-native participant (white-box)*, *hosted-external participant (black-box)*, *comparison plane*, *thin observational ABI*) and uses a systems/control register (planes, policy stack, compatibility surface). The audit found that "MetaHarness"/"meta-harness" is already used by the Stanford Meta-Harness paper and reference repo (S-080, S-151), ruvnet/metaharness (a harness *generator*, S-149), SuperagenticAI/metaharness (an unofficial Meta-Harness implementation, S-150) and Omnigent's self-description (S-118); that "HTIR" is taken by HarnessFix's trace IR (S-146); that "Bench" is saturated (Harness-Bench S-062, Evo-Bench S-067, EvoHarnessBench S-091); and that doc 2's own term "Harness ABI" names precisely the universal boundary that ADR-0001 rejected as LCD-prone.

## Options considered

1. **Metaphorical proper nouns throughout** (e.g., harness-tack metaphors for IR/lab/ABI). Rejected for spec prose: inconsistent with the ontology's systems register; adds a glossary burden for every reader; brand choices belong to the sponsor/WS-L6. Offered only as optional aliases.
2. **Keep doc 2's terms verbatim** ("Harness IR", "Harness ABI", "meta-harness laboratory"). Rejected in part: "Harness ABI" imports the universal-boundary connotation ADR-0001 rejected; "meta-harness laboratory" leans on the colliding prefix.
3. **Descriptive compound nouns in the ontology's register, compiler vocabulary for the compilation pipeline, short-forms for the ratified participant classes, product name retained with a disclosed collision and an optional qualifier (chosen).**

## Decision

| concept | canonical name | short-form / notes |
|---|---|---|
| Product | **MetaHarness** (retained) | Public qualifier recommended: "MetaHarness — harness laboratory & reference runtime". Collision disclosed; sponsor decides via OQ-035. No sub-concept uses "meta-". |
| The representation | **Harness IR** | **HIR**; versioned dialects HIR/1, HIR/2. "HTIR" is reserved by HarnessFix and must not be used. |
| A harness expressed in HIR | **Harness Definition** | "harness def"; the unit WS-J1 assembles/validates and WS-J2 registers. |
| Participant classes | **native participant** · **hosted participant** | Short-forms of the ratified ADR-0001 terms; the ratified long forms and the white-box/black-box descriptors remain the definitions. |
| Comparison surface | **comparison plane** | Ratified; unchanged. |
| The laboratory | **Harness Lab** | "the Lab"; CLI/web noun. Not "Bench". |
| The boundary for hosted participants | **Hosting ABI** | Ratified descriptor *thin observational ABI* stays as definition. Not "Harness ABI". |
| Model-conditioning object and its applier | **Model Profile** · **Profile Compiler** | "profile"; "Model adapter" remains the gateway (WS-C1). |
| Compilation vocabulary | **target** · **lowering** · **lifting** · **lowering loss report** | Standard compiler register; makes T-LCD-11 nameable. |
| Factorial point / hypothesis set | **configuration** · **arm** | Extends the ratified "model–harness–environment configuration" with profile, budget, seed. |
| Pluggable slots | **component class** · **component variant** | "plugin" reserved for third-party packaging (WS-L5). |
| Model-specific rule and its record | **conditioned rule** · **assumption-debt record** | Ontology term "assumption debt" unchanged. |
| Metrics and hosted features | **class-scoped metric** · **capability declaration** · **capability vector** | From T-LCD-15 and T-LCD-07. *Capability declaration* (WS-A1) = the typed, versioned record a participant claims; *capability vector* (WS-L7) = the derived `{declared, probed, unknown}` triple the comparison engine stratifies on (CF-020). |
| The failure mode | **LCD trap** (+ **escape hatch**, **opacity ratio**, **surface vs semantic identity**) | Definitions in WS-L7.additions.md. |

Rules: (1) first use of each name in a spec section expands it; (2) "framework" is reserved for what others build on top of MetaHarness and never describes MetaHarness itself; (3) any proper-noun brand (e.g., for the Lab or the IR) is an *alias* chosen by WS-L6/sponsor and never replaces the canonical name in the spec.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** naming collisions are documented directly — S-080/S-151 (Meta-Harness as proper noun), S-149, S-150, S-118 README ("the open-source meta-harness"), S-146 (HTIR), S-062/S-067/S-091 (Bench-family). The compiler register is warranted by the design itself (doc 2 §11 "model-profile compiler", doc 3 §2.1 "compilation model", §2.3, §2.5) and by the closest precedent using the same register (DSPy adapters, S-144). The LSP/ACP/MCP precedents (S-152, S-035, S-153) call the negotiated feature set "capabilities", matching "capability vector".
- **(b) Source-code precedent:** the term *capability vector* mirrors `HarnessCapabilities` in omnigent `omnigent/harness_capabilities.py` (S-118); *Model Profile* mirrors per-slug records in codex `codex-rs/models-manager/models.json` (S-107) and `ModelInfo` in AutoGen `autogen_core/models/_model_client.py` (S-145); *component class/variant* mirrors AgentSquare's module classes with uniform IO (S-024). The name set as a whole: `no-precedent / novel` (naming is program-specific).
- **(c) Disconfirming evidence considered:** (i) "HIR" also names an internal stage in at least one mainstream compiler toolchain — accepted: different domain, always expanded on first use, and the alternative acronyms (HTIR, HBIR) are worse (taken / unpronounceable). (ii) Retaining "MetaHarness" despite four collisions risks discoverability and attribution confusion — accepted as the sponsor's call; disclosed via OQ-035 with a qualifier recommended. (iii) Short-forms "native/hosted" could be read as "runs locally / runs in the cloud" — mitigated by the rule that first use expands to the ratified long form.
- **(d) Conditionality:** none technical; names hold for any model tier or task class. The product-name decision is conditional on sponsor preference and WS-L6's OSS discoverability analysis.
- **(e) Build-stage assignment:** program tier; effective at Ontology v0.1 (Phase 0 synthesis) and confirmed/extended at v1 (WS-A2, Phase 1); binding in every spec section.

## Consequences

- The §5 ontology rows from WS-L7.additions.md and WS-A1.additions.md were appended by Phase 0 synthesis and the names on which WS-A1 and WS-L7 agree are **ratified at Ontology v0.1 now** (CF-022); WS-A2 may amend only by ADR at v1. Flagged for WS-A2: CF-020 (capability declaration vs capability vector), CF-021 (`configuration` as granularity value vs factorial point); *opacity ratio* stays `proposed` pending OQ-036. The ratified ADR-0001 definitions are not amended, only given short-forms.
- WS-A3 uses "Harness IR (HIR)" and "Harness Definition"; WS-A4/C3/E2 use target/lowering/lifting/profile; WS-J6 uses "Hosting ABI" and "capability vector"; WS-J3/J4 use configuration/arm and class-scoped metric; WS-K1/K2 surface "Lab" as the top-level noun.
- WS-L6 records the collision in the OSS/naming section and proposes the public qualifier (or a rename) to the sponsor before Phase 5.
- The readiness report's glossary check fails if a spec section introduces an unregistered synonym for any concept in the table.

## Reversibility

**High.** Names are text; changing one is a search-and-replace plus an ontology row amendment, provided it happens before the IR schema and CLI/SDK surfaces are frozen in Phase 5. After that, renaming the IR or the ABI touches public identifiers and becomes medium-cost. The product name is the most expensive to change later (OSS discoverability, package names), which is why the collision question is raised now rather than at packaging time.
