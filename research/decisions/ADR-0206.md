# ADR-0206 — The fleet reconciliation contract: `open_fleet / observe / reconcile / claim / dispatch / settle / handoff / transfer_owner / cancel`, invariants RC-1…8 (reconcile-before-dispatch, one activation per item, blocked ≠ stalled, ledger-derived timers, no memory-only state), the `WorkItemStateMap` with human-gate states enforced as Π narrowing leaves, and tracker writes as mediated external effects

**Status:** ratified
**Owner workstream(s):** WS-L8 (with WS-B3 for leases/restore/subscriptions, WS-H7/H1 for Π leaves and `ActionPattern`, WS-E1/E5 for capability patterns, WS-F2 for retry/stop, WS-B5 for workspaces, WS-K4 for the embedding verbs) · **Phase:** 4 · **Related:** ADR-0205 (records), ADR-0207 (escalation routing), ADR-0026 (durable-before-visible; views), ADR-0030/0031 (effect classes; `unknown ⇒ irreversible ∧ external`), ADR-0040 (slices; reserve-before-spend; `fan_out` gauge), ADR-0052/0053 (Π; principal-less procedures), ADR-0069 (Π-12; attendance), ADR-0071 (`ActionPattern`; policy fingerprint), ADR-0088 (lifted capabilities), ADR-0107 (retry policy), ADR-0130 (leases, `restore` R-4), ADR-0131 (suspended runs exempt; `continue_goal`), ADR-0138 (`derive`), ADR-0155 (`next/claim/launch/settle`), ADR-0176/0178 (`hh-embed/1`; experimental verbs); CF-442, CF-447; OQ-316; R-2.12.6, R-2.2.3, R-2.6.2, R-2.8.7

## Context

Symphony's orchestrator is a level-triggered control loop: every tick reconciles running and blocked issues against the tracker before dispatching (S-108 `orchestrator.ex` L256–260; SPEC §7.4, §8.1), re-validates each issue by id immediately before launch (L907–952), moves a worker that exited while input or approval was required into a `blocked` map excluded from stall restarts (L208–240, L659–666, L747–780), releases blocked issues only when the tracker moves them (L456–476), schedules a short continuation retry after a normal exit and exponential backoff after failure (L1223–1250), and stops runs whose tracker state became terminal or non-active (§8.5, §14.4). Its organizational prompt encodes a status map in which some states are human checkpoints ("Human Review -> … waiting on human approval"; "Merging -> approved by human") and instructs the model to "Move status only when the matching quality bar is met" — an invariant enforced by prose. Its scheduler state is in-memory and lost on restart (§14.3). ADR-0130/0131 supply fenced leases, phase-resolved restore, ledger-derived timers and a `suspended` run state exempt from liveness takeover; ADR-0155 supplies the `claim/launch/settle` shape over a run ledger; ADR-0069/0071 supply Π-12, `UnattendedPolicy` and the `ActionPattern` projection on which a narrowing leaf can key.

## Options considered

1. **Adopt Symphony's loop as-is (in-memory claim set, tracker refresh, timers in process).** Rejected: RC-4/RC-8 impossible; already rejected at the run level by ADR-0130 D5.
2. **Let the activation's control strategy own the organizational loop (the agent polls the tracker and decides when to stop or hand off).** Rejected: puts the claim invariant, stall detection and human-gate enforcement inside the model's policy — exactly the invariants doc 2 §4 says belong in deterministic software; Symphony's own prose-enforced "move status only when…" is the failure mode.
3. **A reconciler as a kernel-adjacent component driven through `hh-embed/1`, with every decision ledgered in the fleet run, claims as `resource` leases, state-map enforcement at Π through narrowing leaves on lifted write capabilities** — chosen.
4. **Enforce human gates by having the reconciler perform all tracker writes itself (the agent never touches the source).** Rejected as the default: it requires a principal-less writer (ADR-0053 D-5 admits it only as a sealed `policy_rule` procedure) and loses the provider-native richness Symphony deliberately preserves; kept as deferred D-5 (ADR-0207).

## Decision

1. **Operations** (records only; through `hh-embed/1` Groups S/W/R — a new verb is proposed `experimental` per ADR-0178, never a private binding; boundary placement per ADR-0050 §8 clause 4: adapters and reconciler policy out of process; `open_run`, leases, appends, `authorize` kernel-side):
   - `open_fleet(definition_ref, FleetPolicy{state_map_ref, escalation_policy_ref, scheduling: SchedulingPolicy{max_concurrent, by_state: map, order ∈ {priority_then_age (default), declared(ref)}, stall_ms, continuation_delay_ms, retry: RetryPolicy (ADR-0107 shape keyed on error_class), max_activations}, source_bindings[], trigger_rules[], cascade_policy}) → RunId` — fleet pool budget mandatory (`MissingBudget`; T-LCD-14).
   - `observe(source_ref, now) → [Occurrence]` — adapter; writes `control.wakeup.occurred` (ADR-0131 D2) for poll sources; push sources arrive through the registered ingress.
   - `reconcile(fleet, now) → [FleetAction]` — pure over the fleet ledger, the goal inbox runs and the activations' checkpoint views (ADR-0130 D1): (1) fold occurrences into `spec` (`observed` only on `spec_hash` change); (2) per `active` item: source terminal/non-active/unroutable ⇒ `stop{cancel, cascade}`; source entered a human-gate state through the agent's own effect ⇒ `handoff{state}`; source contradicts a ledgered handoff ⇒ `block{source_conflict}`; (3) stall sweep over `active` activations only (`now − last_activity > stall_ms` ⇒ `stop` + retry via `control.retry.scheduled`); (4) blocked/handoff items: re-check `spec`; escalation deadlines are `timer` subscriptions; (5) `due(now)` retries (ADR-0130 D5); (6) dispatch eligible items in `SchedulingPolicy.order` while `fan_out < max_concurrent` and the per-state cap holds. Each action is appended (`control.work_item.*`) before execution.
   - `claim(work_item_id, holder) → Lease{scope: resource(work_item_id)}` (ADR-0130 lease scope; ADR-0155 D2 precedent; no new lease kind).
   - `dispatch(work_item_id, lease) → RunId` — `get([native_id])` re-validation (Symphony L907–952; `StaleSpec` refuses); `allocate(parent = goal node, mode = slice)` for the activation root (`InsufficientBudget` before provisioning); workspace `derive` per item, preserved across activations under the item's environment lease (ADR-0138); `open_session(new | resume)` with manifest `{goal_ref, activation_no, continued_from?, attendance (fleet policy; `interactive` refused — ADR-0131 D5), principal = owner, causes[] ∋ dispatched event}`; `activation_no` and source context rendered only by `HarnessRule`s with delivery events (T-LCD-13).
   - `settle(work_item_id, run_id) → WorkOutcome` on `lifecycle.run.finished`: `completed_activation ∧ source active` ⇒ continuation retry after `continuation_delay_ms` (`continue_goal`); `stop_reason ∈ {approvals_exhausted, budget_exhausted, environment_lost, escalation_unresolved}` ⇒ `block{reason}` + escalation (ADR-0207); `lifecycle.run.suspended{awaiting_approval}` ⇒ `handoff{approval}` (not blocked; ADR-0131 D4 exempts it from liveness takeover); abnormal exit ⇒ retry with capped backoff keyed on `error_class`; activations ≥ `max_activations` ⇒ `block{max_activations}`. Settlement never deletes; superseded activations remain in the chain.
   - `handoff(work_item_id, state)`, `resume_from_handoff(work_item_id, by)`, `transfer_owner`, `acknowledge_owner`, `cancel(work_item_id, by, cascade)`, `fleet_view`, `accountability_record` (ADR-0207), `restore(fleet)` (= ADR-0130 `restore` on the fleet run; rebuilds every view).
2. **Invariants.** **RC-1** `reconcile` precedes `dispatch` on every tick and after every `restore`. **RC-2** at most one activation per work item — the claim lease; a second claim is `WouldBlock`. **RC-3** `blocked` and `handoff` items and `suspended` activations are never stalled; stall detection reads only `active` activations' `last_activity` (ledger-derived, never a clock in memory). **RC-4** every dispatch, stop, block, handoff, escalation, owner change and cancel is a `control.work_item.*` event whose `causes[]` names the occurrence or decision that caused it. **RC-5** an item without a resolvable human owner is never dispatched (`unowned_dispatch_count` is a `veto: true` trace predicate). **RC-6** the reconciler never writes to a source; every source mutation is an agent effect through Π (default) or, when enabled, a sealed `policy_rule` procedure of external effects under ADR-0053 D-5 (deferred D-5, off by default). **RC-7** capacity is the fleet pool's `fan_out` gauge (ADR-0039) with per-state caps as data; exhaustion refuses the next dispatch, never trims an activation's budget. **RC-8** `restore(fleet)` then `reconcile` over the same ledger prefix yields the same `[FleetAction]` (ADR-0130 R-4 applied to the fleet); no memory-only state exists.
3. **`WorkItemStateMap` and human gates.** MUST-data of the sealed definition: rows `{source_state: Text (normalized: trim + lowercase, Symphony §4.2), kernel_state: WorkItemState | handoff, human_gate: bool, entry_allowed_by ∈ {agent, human, either}, exit_allowed_by ∈ {agent, human, either}, terminal: bool}`; a source state absent from the map is `unknown`. Enforcement is at Π, not in prose: the lifted source-write capability declares an `ActionPattern` projection over `(native_id, target_state)` (ADR-0071 D1 shape, declared by the adapter through WS-E1's projection rule); the definition's sealed narrowing leaves are `deny` for any transition that *skips* a `human_gate` row or *exits* one with `exit_allowed_by = human`, `allow`-under-lease for transitions *into* a human-gate state or along `entry_allowed_by ∈ {agent, either}` rows, and `ask` for transitions to an `unknown` state (ADR-0031 precedence; under `unattended` this resolves by Π-12). The map is part of the policy fingerprint (ADR-0071 D2): editing it revokes leases.
4. **Tracker writes are mediated external effects.** Source mutations (state transitions, comments, links, PR merges) are ordinary effects of lifted `ToolCapability` entities (`scope = external`; `compensable` for transitions/comments with a declared compensator, `irreversible` for merges/publishes — ADR-0031 derivation, self-report only raises), executed by the executor with credentials bound through the H3 broker (`SecretRef`; proxy-injection primary), never present in the activation's environment (ADR-0057). The progress "workpad" Symphony keeps as a single tracker comment is an `Artifact` mirrored by a `compensable` effect; the ledger, not the comment, is the record.
5. **Fleet default for `ask`.** `attendance = async` with `UnattendedPolicy = defer` and an `EscalationPolicy` chain (ADR-0069 Π-12; ADR-0070 D4: the intent is parked before `prepared`, nothing re-executes); `unattended_deny` remains the headless-CLI default (ADR-0168) — two contexts, one table (CF-447). The default is a conditioned rule with an assumption-debt record whose removal test is `lab/org-policy-v1` (ADR-0207).
6. **Failure modes:** `WouldBlock, Fenced, InsufficientBudget, PoolExhausted, SourceUnavailable{source_ref} (skip dispatch this tick; keep activations), StaleSpec, UnownedWorkItem, OwnerUnacknowledged, StateMapUnknownState{state}, CascadeBlocked{children}, MaxActivations, MissingBudget`.

**T-LCD statement.** Satisfies T-LCD-05 (`continuation_delay_ms`, `stall_ms`, the `defer` default and the state-map defaults are conditioned rules with debt records and a named removal test), T-LCD-06 (hosted activations are dispatched through the Hosting ABI's declared verbs with boundary-enforced budgets — ADR-0165; no native change), T-LCD-07 (adapter `native_write_tools`/`assignee_mapping` tri-state), T-LCD-08 (the reconciler receives the fleet `ResourceAccount`; activations receive their profile through their own definition), T-LCD-11 (state lowering declared lossy per adapter; MCP-task carriers via E4), T-LCD-12 (records in/out; reconciler and adapters out of process), T-LCD-13 (`activation_no`/source context through delivery-ledgered rules), T-LCD-14 (fleet pool budget mandatory; per-state caps never trim activation budgets), T-LCD-15 (hosted activations `n/a` on ledger-only stall/recovery fields). Not applicable: T-01/-02/-03/-04/-09/-10 (carried by ADR-0205/L8-3). ADR-0024 ladder: `FleetPolicy`, `SchedulingPolicy`, `WorkItemStateMap`, retry constants are MUST-data; RC-1…8, the claim/lease path, re-validation, Π enforcement of the map and settlement are MUST-code.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: S-108 (SPEC §7.1–7.4 claim states and idempotency rules; §8.1–8.5 tick order, candidate rules, per-state concurrency, backoff, stall detection, tracker refresh; §14.4 operator intervention by tracker state; §10.5 "Approval requests and user-input-required events MUST NOT leave a run stalled indefinitely"; §11.5 writes host-side under host credentials; `WORKFLOW.md` human-gate states enforced by prose — the counter-example), S-426 (level-triggered reconciliation), S-052 (blocking is the expensive failure; PR as checkpoint — via H7), S-053 (approval fatigue — via H7), S-622 (per-function automation levels ⇒ per-state `entry/exit_allowed_by`). Ratified upstream: ADR-0026, ADR-0030/0031, ADR-0040, ADR-0052/0053, ADR-0069/0070/0071, ADR-0088, ADR-0107, ADR-0130/0131, ADR-0138, ADR-0155, ADR-0176/0178.
- (b) Source-code precedent: symphony @e0ccc83 `orchestrator.ex` L256–260 (`maybe_dispatch` = reconcile running ∘ reconcile blocked ∘ dispatch), L208–256 (`handle_agent_down` normal ⇒ continuation retry; abnormal ⇒ backoff; input-required ⇒ block), L335–360/L456–476 (`reconcile_blocked_issues`: release on terminal/non-active/unroutable, refresh when active), L581–640 (stall sweep excludes blocked), L659–666 (`input_required_blocker?`), L747–780 (`block_issue_from_entry` keeps the claim), L907–952 (re-validate by id before dispatch), L1223–1250 (`release_issue_claim`; `retry_delay` continuation vs failure); `tracker.ex` L46–60 (`bind_agent_tools` pins adapter + settings per session; tools executed host-side); ADR-0155 (ratified) `next/claim/launch/settle` over a run ledger. Enforcing an organizational state map at the reference monitor is `no-precedent / novel` (every audited system enforces it in prose or not at all).
- (c) Disconfirming evidence considered: a state map keyed on tracker state names is brittle and pushes organizational policy toward the kernel (§5 R4) — answered: the map is versioned data, unknown states are `ask`, and Π sees only an `ActionPattern` projection; `defer` as the fleet default risks items parked for days (R5) — answered by budget-bounded chains and `HealingPolicy` release; Symphony's simpler loop works in production without a ledger (R1) — but loses timers, blocked state and every "why", which R-2.8.6 forbids. None overturns.
- (d) Conditionality: assumes ADR-0131 Stage-4 triggers and `continue_goal`; assumes WS-E1's `ActionPattern` projection can express `(native_id, target_state)` for source-write capabilities (OQ-178 lineage); assumes adapters expose a stable native id; the `defer` default assumes a reachable sink (true for fleets by construction); no model-tier dependence. C4 conditionality: every default is varied under `lab/org-policy-v1` with a `MatchSpec` over `approvals.requested`, `time.human_wait_ms`, `spend`, `message_human`.
- (e) Build-stage assignment: C4 / Stage 4 (reconciler over the `memory` fixture adapter; RC-1…8; state map at Π; AC-L8-01/-02/-03/-08) → C4 / Stage 5 (real adapter plugin; webhook ingress; AC-L8-09) → C4 / Stage 6 (defaults' removal tests; AC-L8-12).

## Consequences

- WS-E1/E5: source-write capabilities need a declared `ActionPattern` over `(native_id, target_state)`; WS-H1/H7: narrowing leaves keyed on it are ordinary Π data.
- WS-F2: `stall_ms` and the fleet retry policy reuse `RetryPolicy`/`control.retry.scheduled`; no second timer.
- WS-B5: per-item derived workspaces persist across activations under the item's environment lease; `HealingPolicy` defaults for `async` apply.
- WS-K1/K2: `refresh` is `reconcile(now)` through Group W; every refresh is ledgered.
- WS-B3 kill-point battery gains KP-F1…F5 (AC-L8-01).

## Reversibility

**medium** — the reconciler is a component behind records; replacing its policy (order, stall, retry) is a data change; replacing the claim-lease design would touch ADR-0130's lease scopes (a dialect bump). Moving state-map enforcement from Π back to prose is cheap to do and is the one direction this ADR argues must never be taken silently (it would reintroduce the prose-enforced invariant the audit found).
