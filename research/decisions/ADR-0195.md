# ADR-0195 — Candidates as typed diffs with falsifiable hypotheses, and the governance invariants G1–G10 of self-modification: proposal ≠ deployment, no self-authorization, reversibility with auto-revert to a human-sealed ancestor, reflexive assumption debt, target-set exclusion, split discipline, judges never gate, complete search accounting, never delete, candidate text is external

**Owner workstream(s):** WS-I5 (consumers: WS-H1, WS-H2, WS-I6, WS-I7, WS-J1, WS-J2, WS-B4, WS-D4, WS-D5, WS-G3, WS-L5) · **Phase:** 4 · **Related:** ADR-0002 (ii)–(iv), ADR-0016 (`derived-from`), ADR-0017 (`HirDiff`, classification, `invert`, widening rule; P2 `validity_delta`), ADR-0024 (MUST-code pointers), ADR-0033/0034/0035 (authority scheme; `seal` basis; delegate never endorses), ADR-0037 (supersession/revocation; sameness), ADR-0040 (`budget_delta = loosening` unacceptable), ADR-0047 (judge governance), ADR-0053 (D-5; AT-H1-05), ADR-0056 (`classify_policy_edit`), ADR-0086 (induced procedures; promotion policy), ADR-0126 (expiry triggers; removal test), ADR-0133…0135 (rollback record; counterfactual branch), ADR-0143 (L1 `HeldOutLeak`; L3), ADR-0147 (M-2), ADR-0149 (`freeze`; `origin = evolution` never adopts L3), ADR-0177/0181/0182 (injection table; `GuardVerdict`; X6); CF-128, CF-183; OQ-008, OQ-061, OQ-216, OQ-280, OQ-127, OQ-350, OQ-147; CF-416/-05; R-2.9.5, R-2.8.1

## Context

Doc 2 §10 asks how an agent can propose and test changes "without reward hacking, disabling safeguards, overfitting a local regression suite, or silently widening permissions" (OQ-008); §11 requires the security kernel outside the editable surface and every accepted change reversible with expiry. Phases 1–3 fixed the pieces: the typed diff with authority/budget/validity deltas and `invert` (ADR-0017), the evolution service as an attenuated child with a frozen handle set whose candidates are refused on widening (ADR-0053 D-5), guards that never `allow` (ADR-0181), the held-out surface never delivered (ADR-0143 L1), the removal test (ADR-0126), lineage rules (ADR-0037/0149). The source audit found each of the failure classes doc 2 names in shipping loops: DGM's improvement judge is shown the held-out test and answer patches (`prompts/diagnose_improvement_prompt.py`); DGM's agent edits its own source in place and reconstructs versions by replaying patch chains; AFlow's acceptance is a bare `avg_score > before` over the search set; AFlow and ADAS execute generated code in-process; RHO accepts by pairwise self-preference; S-104 shows automatic reviewers approving 13/13 attacks; S-476 shows rollback that removes the record of an action while the action persists. What is missing is one place where the invariants are stated as kernel-checked rules with fixtures, and one answer to the question of *what* an accepted edit is.

## Options considered

1. **Trust the proposer's own validation** (RHO self-preference; DGM's judged score; AFlow's bare comparison). *Rejected:* ADR-0035 rule 1 (a `delegate` origin never endorses), S-104, S-068.
2. **A model-origin reviewer as the deployment gate** (Guardian-class). *Rejected:* ADR-0053 option 2; the same operating point is reachable with a human `seal` plus automatic canary/revert.
3. **In-place edits of the running definition with snapshot rollback.** *Rejected:* no deployed object distinct from the search artefact; rollback becomes a restore that can lose the record (S-476 SF5); ADR-0147 M-2 already forbids mutation.
4. **Candidates as invertible typed diffs between sealed definitions, a human `seal` as the only deployment act, auto-revert only toward a human-sealed ancestor, and every accepted edit a conditioned rule (chosen).**

## Decision

1. **Representation.** A candidate is `CandidateProposal{candidate_id = H(idp ∥ "candidate" ∥ canonical(base ∥ diff)), base: DefinitionVersionRef, diff: HirDiff, family, proposer_run_id, search_spend, provenance{origin: evolution(candidate_id, hypothesis_ref), authority: delegate}}` and nothing else; `FailureHypothesis{hypothesis_id, statement: Text ≤ external, failure_class, evidence_refs[], affected_task_ids[] ⊆ search ∪ dev, reference_trajectories?[], model_scope, predicted: PredictedEffect{deltas[{metric_ref, direction, magnitude?}], expected_flips[], cost_delta?}}` is bound to every changed node through `derived-from{hypothesis: statement, trajectories: evidence runs, candidate_id}` (ADR-0016), with the structured record referenced by the reserved `ext` key `hh.evolution/hypothesis_ref` until HIR/2 adds `hypothesis_ref` (CF-416; `ext` never decides validity — the gate reads the record). Admissible op classes: `ReplaceLeaf`/`AddNode`/`RemoveNode`/`AddEdge`/`RemoveEdge`/`Rebind`/`ReplaceField`/`ExtEdit` on non-excluded targets; `SurfaceEdit`-only diffs are profile candidates filed against the Model Profile version (ADR-0017); `CompiledPayload` candidates require a declared interface and `placement ≠ in_process`.
2. **G1 Proposal ≠ deployment.** Transition into `sealed_candidate` requires a `seal` endorsement with `origin = human`, `authority = definition` (ADR-0035); the evolution `AgentProcess` cannot append `security.label.endorsed`; `SealRefused{not_human}` otherwise; AT-H1-05 (iv) is the fixture. Canary advance and rollout are automatic only under a `RolloutPolicy` sealed with the campaign; the only non-automatable transition in the pipeline is this one.
3. **G2 No self-authorization.** `classify(diff)` at S1 and again at S7 refuses `authority_delta = widening`, `budget_delta = loosening`, `validity_delta = loosening`, any op on a MUST-code leaf, on Π rows, `authority_cap`s, pre-authorization `HarnessRule`s, the handle table, `Permission` grants (except narrowing) or `Budget.hard` (except tightening); `classify_policy_edit` must return `narrowing` for every policy leaf (ADR-0056; CF-128); candidate-authored guards emit `GuardVerdict` (never `allow` — ADR-0181); `permission_request` by the service is `deny` unattended and `ask` to the principal otherwise, never auto-resolved (ADR-0053 D-5).
4. **G3 Reversibility and auto-revert.** `invert(diff)` is verified at S1 (`apply(target, invert(diff)) = base`); the lineage head records `rollback_ref = base`; `revert(head) = apply(head, invert(diff))` lands on a human-sealed ancestor, mints no authority, and is therefore **admissible automatically** on `RolloutPolicy.abort_on` (veto trip, regression beyond margin, cost ceiling) and on an expiry veto; it is ledgered as `supersedes{reason: revocation}` mirrored in name history, live runs receive `lifecycle.run.rolled_back` with a rewind note (ADR-0133), the principal receives an escalation, and nothing is deleted. Revert is also available to the principal at any time.
5. **G4 Reflexive assumption debt (expiry).** Every accepted edit carries `AssumptionDebtRecord{rule_id = candidate_id, hypothesis = hypothesis_ref, evidence_refs = [S3–S7 report refs], owner = campaign principal, expiry_condition ∈ ADR-0126 triggers ∪ {transfer_sign_flip, superseding_candidate}, removal_test_ref = the ADR-0156 retirement design over head vs apply(head, invert(diff)), status}`; `conditioned_on` is set iff the S6 `TransferProfile` is model-conditioned; `publish` refuses `ConditionedRuleIncomplete` (T-LCD-05 reflexively). The pipeline's last stage is WS-I6's first record.
6. **G5 Target-set exclusion.** Fixed and not widenable through `ext`: every `Validator`, `OracleDeclaration` and grader executable bound by the campaign's suites (a candidate may not edit what scores it); every `Permission`, `Budget.hard`, Π/policy leaf, pre-authorization rule, `TrustRootPolicy`, `ContainmentPolicy`, `SinkPolicy`; every MUST-code pointer; **the evolution service's own definition and its registered `evolution_proposer` variants** (`SelfModificationRefused`; the service evolves only through a separate human-origin campaign — CF-419, X6 extended).
7. **G6 Split discipline.** `SplitAssignmentRecord` precedes S0 (ADR-0143 L3); `held_out`/`private` surfaces are never delivered to the proposer, any diagnoser, any selector judge or any candidate run (`HeldOutLeak` veto — L1 applied to the evolution `AgentProcess` and its judges as model-facing surfaces); `artifact_benefit` rows only from `held_out`/`private`; a candidate sealed under one split hash is re-validated, never grandfathered, under another.
8. **G7 Judges never gate.** Any `Validator{kind: judge}` — self-preference, self-validation, teacher-relative (OQ-127), agentic critic, untrusted monitor (OQ-280) — is admissible only as a *selector* inside S3–S4 (`selected_best_of_n`; `charged_to = instrument`; `CalibrationRecord` mandatory; independence from every beneficiary snapshot — ADR-0047/0117), with honeypot items in the counterexample set and a fixed human audit budget per campaign when the critic shares the beneficiary's family; it never decides S5–S7; a judge-only acceptance is `AcceptanceIncomplete{item 1}`.
9. **G8 Complete search accounting.** `SearchBudgetRecord` covers proposer, diagnoser, judge, screen and search-arm spend since S0; `unknown` makes the candidate reportable only at product level and never acceptable (ADR-0046 §7); leaderboard entries carry `selection{n_candidates_registered, rule, search_budget_ref}` where `n_candidates_registered` counts every `proposed` transition including rejections (ADR-0163 L4).
10. **G9 Never delete; always attribute.** Rejected, reverted and withdrawn candidates stay in the `exp/` lineage with their reports (DGM `keep_all` as the only policy); a re-attempt is a new `candidate_id`; the proposer's own run is ledgered (`proposer_run_id`) so its trajectory is auditable like any run.
11. **G10 Candidate text is external.** Every `Text` leaf a candidate introduces enters at `authority ≤ external` (ADR-0177 injection table) and the role-placement invariant governs canary runs; candidate content reaches `definition` authority only through the G1 `seal`.
12. **Neighbour answers fixed here.** OQ-216: promotion of an induced procedure to `definition` requires `require_transfer_test = {≥ 2 families} ∨ {1 family ∧ ≥ 1 held-out environment}`; a single-profile pass promotes to `principal` only, with `conditioned_on` and a debt record; `charged_to = instrument`. OQ-350 (evolution half): `origin = evolution` never adopts L2+ drift; evolution lineages `freeze`; a new campaign pins a fresh snapshot. OQ-061: candidates name a `base`; a moved head yields `StaleBase` and re-proposal at Stage 6a/6b; `rebase` (C1 extension) at 6c with re-entry at S5. OQ-147: no I5 requirement — the service is outside the TCB and cannot reach Π.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-05 (G4 reflexive debt records; refusal at `publish`), T-LCD-10 (identity-keyed diffs; renames are profile candidates), T-LCD-02 (G10: candidate prose is a `Text` leaf at `≤ external`), T-LCD-14 (G8: incomplete search spend is never acceptable), T-LCD-13 (item 7 chain, via ADR-0194), T-LCD-12 (records in/out; `classify`/`invert`/`revert` are kernel operations implementable out of process), T-LCD-06/-07 (hosted candidates restricted to ADR-0149 T-4 `value_change`; no native contract change), T-LCD-15 (attribution `n/a{class}` for hosted). Not applicable: T-01/-03/-04/-08/-09/-11. **ADR-0024 rung:** G1–G3, G5–G7 checks, `revert` and the exclusion set are MUST-code; `RolloutPolicy.abort_on`, margins, audit budgets and the debt-record fields are MUST-data.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** a `delegate` origin never endorses; `seal` basis; attenuating delegation; the evolution service as a threat actor with a frozen handle set and widening refusals — ADR-0035, ADR-0053 (ratified; Tier-A lineage Anderson S-251, Saltzer & Schroeder S-252, Capsicum S-256); guards never `allow` — ADR-0181, CF-121 (ratified); automatic review defeated 13/13 — S-104 (`provisional (mech)`); peer judges yield no usable signal — S-068 (`provisional`); trace-only rollback attacks (SF5: the record removed while the effect persists) — S-476 (`provisional (mech)`), answered by ADR-0133's rollback record; invertible identity-keyed diffs with authority/budget/validity deltas — ADR-0017 (ratified; GumTree S-174, Unison S-171); assumption debt on every model-specific rule — doc 2 §5.9 (Tier-B synthesis), ADR-0007 T-LCD-05, ADR-0126 (ratified); model change invalidates a tuned harness — S-096 (`provisional`), HarnessBank's model-specificity (S-087, `provisional`); bounded, auditable, reversible component-level updates — SafeEvolve S-086 (`provisional`); regression testing as the acceptance gate — Self-Harness S-585 (`provisional`); held-out never delivered — ADR-0143 L1 (ratified). No `provisional` source is load-bearing; each invariant is either ratified already or the composition of ratified rules.
- **(b) Source-code precedent:** counter-examples read at pinned commits — dgm @a565fd2 `prompts/diagnose_improvement_prompt.py` L1–95 (judge shown the held-out oracle; G6/G7 counter-example), `self_improve_step.py` L293–356 (in-place self-edit in a container; lineage by patch replay — G3 counter-example), `DGM_outer.py` L174–190 (`keep_all` archive — G9 precedent); AFlow @3f45721 `optimizer_utils/experience_utils.py` L91–95 (bare-comparison acceptance — G7/G8 counter-example), `optimizer_utils/graph_utils.py` L28–38 (in-process import — CF-418); ADAS @2702bee `_arc/search.py` L369–373 (in-process `exec`). Positive precedents for the *pieces*: codex `guardian-context/src/authorization.rs` (approvals do not transfer; via ADR-0053), `codex-rs/core/src/thread_rollout_truncation.rs` (rollback as an appended marker; via ADR-0133), opencode `snapshot/index.ts` (content-addressed workspace restore; via ADR-0133). **The invariant set as a whole — human seal as the sole deployment act, auto-revert only toward a human-sealed ancestor, reflexive debt records on accepted edits, the scorer/self exclusion set — is `no-precedent / novel`.**
- **(c) Disconfirming evidence considered:** (i) RHO improves without external grading, so requiring deterministic gates may forgo real gains — accepted at search time (judges as selectors) and refused at acceptance (S-068, S-104, ADR-0047); (ii) requiring a human seal for every accepted candidate limits throughput — the seal is one act per survivor and everything else is automatic; the alternative reopens the S-104 class; (iii) a debt record on a universally helpful edit is ceremony — the record's fields already exist as pipeline outputs, `conditioned_on` is set only when the transfer profile says so, and doc 2 §5.9's fossil-record failure is the cost of omitting it; (iv) automatic revert is a deployment decision — it targets an already human-sealed ancestor and is escalated, never silent; (v) forbidding candidates on validators blocks legitimate improvements to verification — those enter as human-origin diffs in a separate campaign whose validators are not the ones scoring it. None overturns.
- **(d) Conditionality:** independent of model tier and task class; assumes the ledger append path, the handle table and `classify` exist at Stage 1–3 (ADR-0026/0053/0017); the human-seal rule binds only when C4 is built but is specified now so the ladder can gate on AT-H1-05; hosted candidates assume enforced budget dimensions (OQ-382).
- **(e) Build-stage assignment:** the refusal checks (G2, G5, G6, G10) and `invert` verification are C0/Stage 1–3 kernel operations already ratified and are *exercised* at Stage 6a; `revert`, `RolloutPolicy` and G4's publish refusal are C4/Stage 6a; G7/G8 judge-selector and audit-budget rules are Stage 6b–6c; AT-H1-05 remains the Stage-6 precondition (ADR-0053 (e)).

## Consequences

- WS-H1/L5 extend the D-5 exclusion set with `SelfModificationRefused` (CF-419); WS-H2 confirms that `classify_policy_edit` covers every policy leaf a candidate can touch; WS-A3 schedules `derived-from.hypothesis_ref` for HIR/2 (CF-416).
- WS-I6 treats accepted edits as conditioned rules from S9 onward and owns their expiry lifecycle; WS-D5/D4 apply the OQ-216 rule in `PromotionPolicy`; WS-G3 supplies the calibration/honeypot/audit-budget shape G7 names (OQ-280 thresholds); WS-I2 registers `teacher_relative` as selector-only until its calibration protocol exists (OQ-127).
- WS-J1's `AssemblyDiff` is the mandatory review rendering at the seal; WS-J2 stores rejected/reverted candidates in `exp/` lineage (never GC'd, ADR-0037 (2)); WS-B4's rollback record and rewind note are the live-run half of `revert`.

## Reversibility

**Low for G1, G2, G5, G6, G7** (they restate ratified ADR-0002/0035/0047/0053/0143 rules; relaxing any reopens a demonstrated attack or confound class). **Medium for G3's automatic revert and G4's reflexive debt** (either can be narrowed to "human-initiated only" or "model-conditioned edits only" by campaign policy without touching stored records). **High for the hypothesis record's field list** (additive; the `ext` key migrates to a HIR/2 field by dialect bump).
