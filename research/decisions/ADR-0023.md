# ADR-0023 — A Harness Definition is a data document: the assembly grammar (slots, variants, parameters, bindings, constraints), no host-language code in definitions, and locality-neutral component binding (answers OQ-044 / Q-L1-09, Q-L1-10)

**Status:** **ratified** (Phase 1 synthesis, 2026-09-10)
**Owner workstream(s):** WS-A5 (consumers: WS-A3, WS-A4, WS-J1, WS-J2, WS-J3, WS-L1, WS-L4, WS-L5, WS-B1, WS-C3) · **Phase:** 1 · **Related:** ADR-0001, ADR-0002 (iii), ADR-0004, ADR-0006 (N1, N2, N12), ADR-0007 (T-LCD-02/-06/-08/-10/-12), ADR-0008, ADR-0009 (C6 hard gates; AC8), ADR-0011; ADR-0015 (two opaque leaf kinds, `ext`, two-id identity), ADR-0016 (`HirDocument{…, assembly?}`; `AgentProcess.native`), ADR-0018 (`OpaqueProcess` has no slots), ADR-0019 (compiler consumes the sealed definition); CF-052, CF-053, CF-054, CF-055, CF-009, CF-023; OQ-044, OQ-073, OQ-075, OQ-077, OQ-078; R-2.1.4, R-2.10.1, R-2.10.2, R-2.12.2

## Context

Doc 2 §11 asks that "enough of the harness [be exposed] as data/configuration that an optimizer can later edit it safely" and §7 records the 2026 population trend of policy migrating from prose to structured configuration (S-074 §14.5). Phase 0 made three things binding on this decision: the ontology names *Harness Definition* as "a declarative artefact in HIR that names component variants, parameters … and policies" but leaves "whether it is a pure data document" to OQ-044 (ADR-0008); the LCD battery assigns WS-A5 T-LCD-08 (every component-class contract receives the Model Profile and resource accounting) and T-LCD-12 (contracts are operations, never inheritance; implementable out-of-process) (ADR-0007); and WS-L1's language ratification is postponed by rule unless OQ-044's two halves — is a definition a data document any runtime can load (Q-L1-09), and may variants be out-of-process (Q-L1-10) — are answered language-neutrally (ADR-0009, phase-0 §5.6). ADR-0016 has since fixed that a HIR document *is* a Harness Definition (`HirDocument{hir_version, root, nodes, edges, assembly?}`) and reserved the `assembly` grammar for this workstream; ADR-0019 fixed that the compiler consumes only a sealed definition.

The WS-A5 audit read the configuration loaders of nine systems at pinned commits (dossier §3–§4). Seven independent code bases — OpenHands SDK, goose, opencode, the Claude Agent SDK, Codex, AutoGen, Open Agent Spec — converged without coordination on the same persisted shape: a typed document whose plug points are tagged unions of `{variant tag, typed parameters}`, whose cross-references are names resolved through a registry, and whose free text enters through a small number of named fields. None persists host-language object graphs or serialized closures; where code is loaded, the document carries a *pointer* (path, package, module, command) and the loader is the trusted-path check (DSPy sanitises LM state and warns; AutoGen checks a trusted namespace; Pi gates on project trust). A *complete* harness configuration — tools, prompts, permissions, hooks, subagents, MCP servers, plugins, budgets — already crosses a process boundary as data in the Claude Agent SDK, and goose binds in-process (`platform`) and out-of-process (`stdio`, `streamable_http`) extensions under one tag set. The gap the audit found: no system computes a content identity for its resolved configuration, records which layer set which field in the run record, or checks that a declared parameter space matches what the runtime reads.

## Options considered

1. **Definitions are host-language programs** (a builder API or module that constructs the harness object graph; DSPy `save_program=True`, AutoGen `provider` import, Pi extensions as the *only* form). *Rejected:* cannot be diffed structurally, content-addressed, swept or ablated without executing it; ties the Lab to the kernel's ecosystem (violates N12 and forces WS-L1 hard gate C6); every audited system that allows this path treats it as the unsafe one.
2. **Definitions are pure data with a closed, fixed slot list** (`AgentProcess.native{control_strategy, context_policy}` as the only plug points; new classes need a dialect bump). *Rejected:* every new component class (validator, router, memory, compaction, tool-registry policy…) would be a kernel change; contradicts the seven-plane scope and the Lab's need to register classes during Phase 2 (D/E/F tracks).
3. **Definitions are pure data, in-process binding only** (variants are Core-linked implementations; out-of-process is a later concern). *Rejected:* fails T-LCD-12's "implementable out-of-process" criterion and T-LCD-06's removability of hosting; makes third-party variants (WS-L5, R-2.12.2) a kernel-linking problem; goose and OpenHands show one tag set can span both localities today.
4. **Definitions are data documents with a registered slot/variant/parameter grammar; code enters only as `CompiledPayload` leaves or versioned, content-addressed code pointers; contracts are operation records so variants bind in-process or out-of-process; registry-validated open variant tags (chosen).**

## Decision

1. **Q-L1-09 — A Harness Definition is a data document loadable by any conformant runtime.** It is one HIR document (dialect `hir/1`, WS-A3) whose `assembly` section contains no host-language content: `Assembly{dialect, profile_binding, slots, parameters, values, entities, constraints, layers?, ext}`. Composition (`compose/resolve/validate_assembly/instantiate`, ADR-0025) requires runtime code, but only the Core assembler's; no host-language code appears in, or is needed to author, a definition. Code enters a definition in exactly two forms: a WS-A3 `CompiledPayload` leaf with a declared interface, or a **code-pointer leaf** — a versioned identity (package, path, module, command) that `resolve` turns into a content address plus trust record (WS-L5/H5). Inline bodies and serialized closures are invalid (`OpaqueWithoutInterface`).
2. **Grammar.** `slots: map<class_id, SlotBinding | [SlotBinding]>` keyed by **component class**, never by plane or by a fixed field list; `SlotBinding{variant: ComponentVariantRef{class_id, variant_id, version_selector | version_id}, params: map<name, Value | $param:<id> | $entity:<id>>, enabled: bool = true, locality?: in-process | out-of-process | inherit}`. A `ClassRecord{class_id, contract{operations[{name, inputs, outputs, invariants, failure_modes}]}, cardinality ∈ {exactly-one, optional, ordered-many}, required_inputs ⊇ {ModelProfile, ResourceAccount}, base_param_schema, hot_path, dialect_introduced}` is registered by Core; a `VariantRecord{variant_id, class_id, version, version_id, param_schema, implementation: CompiledPayload | {entrypoint_identity, locality}, capability_declaration, conditioned_rules[AssumptionDebtRecord], provenance/trust, dialect_range}` is stored by the registry (WS-J2). Adding a class is a `ClassRecord` registration, not a dialect bump; `AgentProcess.native`'s `control_strategy` and `context_policy` are the two Stage-1 mandatory keys of this map with `cardinality = exactly-one` (CF-052, for WS-A3 to arbitrate). Variant tags are **open, registry-validated** (a slot naming an unregistered `variant_id` is `UnresolvedRef`, never silently accepted); the kernel's own enums stay closed per ADR-0015 (no C6 hard gate fires).
3. **Parameters and text.** `parameters: map<param_id, ParameterSpec{type ∈ {int, real, bool, enum, string, duration, token_count, ref<class_id>, ref<entity_kind>}, domain, default?, required ∈ {required, optional, prompt}, unit?, sweepable, affects[], budget_relevant}>` declares the definition's parameter space; `values` is its point in that space. All free text is a typed `Text` leaf with provenance/owner/authority (T-LCD-02); AGENTS.md-class prose enters as a `ContextItem` with `provenance.origin = import` and its frontmatter as typed fields. `ext` is the only place unknown keys may live (WS-A3 rule); any other unknown key is an error.
4. **Profile is a configuration coordinate, not a definition field.** `profile_binding` is `unbound` by default; a definition may *constrain* the admissible profile set (`ProfileConstraint`); whether it may *pin* one is OQ-078. One definition therefore compiles under ≥2 profiles (T-LCD-04) and the ontology wording "names … profiles" is amended to "may constrain profiles" (CF-054).
5. **Q-L1-10 — Variants may be in-process or out-of-process.** Class contracts are operation records (T-LCD-12), so both bind. **Locality is a property of the variant registration, never of the class contract**; `SlotBinding.locality` is a hint. The default for Core variants at Stages 0–2 is in-process; out-of-process binding is mandatory for third-party variants (WS-L5) through a *variant-host boundary* that reuses the WS-L1 §6.5 verb discipline (single source of truth, generated bindings, version handshake, exact pinning, byte-identical events, no authority widening — CF-023) and declares its operations, schemas and a change signal the way MCP declares tools (`tools/list_changed`, S-153). The per-class cost ceiling above which an out-of-process binding is refused for a `hot_path` class is measured at Stage 2 (OQ-075); until then out-of-process cost is attributed (WS-L2), never assumed free.
6. **Hosted participants** (`AgentProcess.hosted = OpaqueProcess`, ADR-0018) carry no `slots`; they may declare `params` in the same `ParameterSpec` grammar at `configuration`/`product` granularity only (ADR-0004; Omnigent precedent), so one override vocabulary spans both classes while class-scoped metrics remain `n/a` where they must (T-LCD-15).
7. **Desired state only.** `dialect, slots, values, entities, constraints` describe desired state (Kubernetes `spec` convention); observed conformance lives in the run record (WS-J6), never in the definition.
8. **Requirement on the host ecosystem (for WS-L1; no ecosystem named):** deterministic canonical encoding + schema validation + content hashing of schema-described documents (WS-A3's P3–P5); an operation-shaped binding mechanism for in-process variants; a process/transport boundary able to carry the variant-host verbs. Nothing here requires closed sum types over variant tags.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: seven independent systems converge on the tagged-union-with-typed-parameters document shape (dossier F1; S-110, S-112, S-111, S-109, S-107, S-145, S-138/S-139 — all Tier B source, read at pinned commits); population-level trend "policy migrated out of prose", skills 9/11, MCP 8/11 (S-074/S-166, `provisional (mech)`, corroborated by the direct reading); a complete configuration crosses a process boundary as data (S-109); one tag set spans in-process and out-of-process bindings (S-112 `platform` beside `stdio`; S-110 `agent_kind ∈ {openhands, acp}`); an out-of-process component surface is declared as data with a change notification (S-153 `Tool` + `tools/list_changed`; S-035 `session/new{mcpServers}`); vendor rule "configuration first, export to code when configuration isn't enough" (S-058, vendor, mechanism only); desired-state documents with `kind`/`apiVersion` and defaulting that never overrides user values (S-186, Kubernetes conventions); content identifiers on descriptors (S-187, OCI). Optimisation literature agrees at mechanism level that the editable surface is a small set of named slots with typed knobs (S-061, S-066, S-092 — all `provisional`, not load-bearing).
- (b) Source-code precedent: `openhands-sdk/openhands/sdk/utils/models.py` (`DiscriminatedUnionMixin`, `kind`), `agent/base.py` L101–290, `profiles/agent_profile.py` L80–176, `context/condenser/base.py` L16–79 (one abstract operation + parameters record) (S-110 @3fc7b22); `crates/goose/src/agents/extension.rs` L160–218, `agents/extension_manager.rs` L1444–1606, `recipe/mod.rs` L42–98, L157–207 (S-112 @fae91d0); `packages/opencode/src/agent/agent.ts` L35–56, `config/agent.ts` L13 (prose-with-frontmatter → typed record) (S-111 @9f8db11); `src/claude_agent_sdk/types.py` (`ClaudeAgentOptions`), `_internal/transport/subprocess_cli.py` L569–726, `_internal/query.py` L125–157 (S-109 @ad77094); `autogen_core/_component_config.py` L18–37 (S-145 @027ecf0); `pyagentspec/src/pyagentspec/component.py` L107, L176–187 (S-139 @6f0b6ae); `packages/coding-agent/src/core/extensions/loader.ts` L252–450, L763–800 and `pi-manifest.ts` (code declared by data) (S-113 @400d690); `omnigent/docs/AGENT_YAML_SPEC.md` L22–74 (S-118 @6a069da). The combination — class-keyed slot map with registered `ClassRecord`/`VariantRecord`, declared parameter space, profile-unbound definition, locality on the registration — is `no-precedent / novel` as an integrated grammar; each part is precedented.
- (c) Disconfirming evidence considered: (i) every audited product keeps an escape hatch to code (OpenHands Jinja `system_prompt_filename`, Codex Starlark execution policy, hooks as shell commands, Pi extensions, DSPy `save_program`, AutoGen `provider` import) — answered: the hatches are code pointers or interpreted policy leaves, both representable as data of declared kind; inline bodies are exactly what DSPy and AutoGen flag as dangerous; a behaviour no variant expresses is a T-LCD-03 round-trip failure reported as `PlanError{unsupported_construct}` (ADR-0019), not hidden. (ii) Hot-path components are in-process in every audited system and goose's `platform` extensions exist because some need "direct access to the agent" — answered: the contract admits both localities, the default is in-process, and out-of-process cost is measured and stratified (OQ-075). (iii) S-074 finds no system imports a framework, so a shared definition format may be the framework nobody adopts (CF-009) — answered: the format is for native participants of a research instrument (ADR-0003/0006); hosted participants keep their own configuration (ADR-0004). None overturns.
- (d) Conditionality: independent of model tier and task class; assumes definitions are small documents (≤10⁴ nodes) so registry-validated resolution is cheap; assumes WS-A3's `CompiledPayload` leaf and two-id identity ratify as proposed; the in-process default for Core variants is conditional on Stage-2 cost measurements (OQ-075); interpreted policy leaves are deferred to C1 unless OQ-077 admits them.
- (e) Build-stage assignment: **C0 / Stage 1** (assembly grammar in the `hir/1` schema; `ClassRecord`/`VariantRecord` shapes; class catalog for control strategy and context policy; in-process `instantiate`); **C0 / Stage 2** (out-of-process variant host + `locality` binding, with the WS-L5 preview; `Text`/skill/procedure entities); **C1 / Stage 5** (`profile_binding` constraints with WS-C3). Assembly *service* and registry *service* are C1 (R-2.10.1/R-2.10.2; CF-053).

**T-LCD statement (ADR-0007 decision 5).** Satisfies: T-LCD-08 (`ClassRecord.required_inputs ⊇ {ModelProfile, ResourceAccount}`; a model-conditioned compaction variant needs no Core change), T-LCD-12 (contracts are operation records; a stub variant binds out-of-process per class), T-LCD-02 (free text only as `Text` leaves), T-LCD-06 (`OpaqueProcess` carries no slots; no IR entity depends on the Hosting ABI), T-LCD-10 (identity is WS-A3's `semantic_id`; surface excluded). Does not by itself satisfy T-LCD-03/-04 (executable; Stage 3 with WS-A4/I2) — mitigated by the definition being the input to `lcd_report` and the equivalence run.

## Consequences

- WS-A3 amends `AgentProcess.native` to carry `slots: map<class_id, …>` with `control_strategy`/`context_policy` as mandatory keys (CF-052), and the ontology's *Harness Definition* wording changes to "may constrain profiles" (CF-054); OQ-044 is answered and the WS-L1 postponement rule no longer blocks on WS-A5.
- WS-L1: the definition format imposes only canonical-encoding + schema-validation + content-hashing requirements and a process boundary for the variant host; no C6 hard gate fires from this ADR; the Lab may live in a different ecosystem from the kernel.
- WS-J2's registry stores `ClassRecord`/`VariantRecord` rows in this shape; WS-L5's plugin packaging produces `VariantRecord`s with a trust record; WS-L4 supplies `version_id` derivation.
- WS-B1 adds (or names existing) `lifecycle.component.bound{slot, class_id, variant_ref, locality, bind_result}` so the instance graph is observable (OQ-079).
- Every later dossier that introduces a pluggable behaviour registers it as a component class with an operation-shaped contract, or it is not pluggable.

## Reversibility

**Medium.** Widening the grammar (new `SlotBinding` fields, new `ParameterSpec` types, `ordered-many` semantics per OQ-073) is a dialect bump with a migration and does not invalidate stored definitions. Reversing the core commitment — admitting host-language bodies inside definitions — would invalidate content identity, structural diff and the ADR-0002 governance surface, and would re-open WS-L1's C6 gate; that direction is costly and requires a superseding ADR.
