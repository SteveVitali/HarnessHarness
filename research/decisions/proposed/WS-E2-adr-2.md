# ADR-NNNN — Wrapper synthesis and admission: a gated pipeline over ADR-0022's E1–E7 plus safety obligations S1–S4; synthesized surfaces enter a bundle only as conditioned rules with assumption-debt records; per-nested-call mediation for code-mode and shim surfaces; emulated pre-checks may veto but never grant

**Status:** proposed
**Owner workstream(s):** WS-E2 (consumers: WS-H1, WS-H2, WS-E5/B5, WS-C3, WS-I5, WS-I6, WS-I2, WS-G3, WS-L3) · **Phase:** 2 · **Related:** ADR-0002 (evolution never widens authority), ADR-0007 (T-LCD-01/-02/-05/-13/-14), ADR-0016/0017 (`AuthorityWidening`; `derived-from`), ADR-0020 (debt record; two homes CF-049), ADR-0022 (E1–E7; rule iv), ADR-0024 (MUST-code; pointer rule), ADR-0030/0031 (effect lifecycle; risk class), ADR-0033/0034/0035 (authority classes; role placement; closed endorsement basis), ADR-0047 (judge governance), ADR-0050 §8(c); WS-E2-adr-1; R-2.5.2, R-2.8.x

## Context

Doc 2 §5.2 and §12 direction 7 name "safety and semantic equivalence of generated wrappers" as the difficulty of a tool-interface compiler. The field ships synthesized interfaces unchecked: HEART (`provisional`, S-076) wraps every function "with an LLM interface that handles schema resolution and execution internally" and reports gains with no equivalence or safety check; Cursor validates surfaces only by end-to-end keep-rate; codex and opencode admit model-written orchestration programs (code-mode) that call tools. Three production mechanisms nonetheless show how code-mode is made safe: Anthropic requires per-tool opt-in (`allowed_callers`) and keeps results in the execution environment (S-040); Cloudflare routes every call from the sandbox through supervisor-held bindings so generated code never sees credentials (S-WS-E2-01); opencode derives the code-mode catalogue from the permission ruleset (`Permission.visibleTools`). goose's shim resolves tool names by similarity (`resolve_tool_name`) — a call can bind to a capability the model did not name. ToolEmu (ICLR 2024, S-098) shows an emulated adversarial pre-check finds real failures (68.8% validated) and that "even the safest LM agent exhibits such failures 23.9% of the time". ADR-0002 forbids an evolution service from widening its own authority; ADR-0022 rule (iv) already rejects a surface edit whose E2 result changes from `pass`; ADR-0035 fixes the closed endorsement basis `{seal, approval, validator, promotion, pin, policy_rule}` and says the model never endorses.

## Options considered

1. **Admit synthesized wrappers on end-to-end benchmark gain** (HEART, Cursor). *Rejected:* unmatched-budget, whole-harness evidence (S-083 discipline); cannot localise a regression or detect authority widening; contradicts ADR-0002.
2. **Forbid synthesis; only human-authored profile rules.** *Rejected:* ADR-0002 puts evolution of surfaces in scope; code-mode is a model-written mapping by definition and is a legitimate exposure mode (CodeAct, Tier A).
3. **Admit wrappers as opaque `CompiledPayload` variants behind the tool contract with run-time monitoring only.** *Rejected:* no static E1–E3, so authority widening is caught only after an attempt; no debt record, so retirement is by inspection (S-047 signature).
4. **A gated pipeline — propose → map → static E1–E3/E5–E7 → safety S1–S4 → executable E4 (per exposure mode) → admit only as a conditioned rule with a complete debt record → observe compliance → expire/retire — with per-nested-call mediation for run-time mappings and an optional emulated pre-check that may veto but never grant (chosen).**

## Decision

1. **Pipeline.** `synthesize_surface(SurfaceProposal{candidate: ToolSurface, provenance, hypothesis: AssumptionDebtRecord, target_home ∈ {profile_rule, harness_rule}}) → AdmissionResult{admitted(rule_id) | SurfaceSynthesisRefused(gate, reason)}` runs, in order: `bind` (a total `SurfaceArgMap` or `PlanMap`; else `UncheckableSurface`), `check_equivalence` (E1–E3, E5–E7 static, per branch), `check_safety` (S1–S4), E4 per WS-E2-adr-1's admissibility table, then admission. The author (`provenance.origin ∈ {human, model, evolution, import}`) never changes the gates.
2. **Admission home.** An admitted surface exists in a bundle only as a conditioned rule — a `ProfileRule` (model-conditioned) or a definition-level `HarnessRule{conditioned_on}` (task-conditioned) — sharing the one `AssumptionDebtRecord` schema (CF-049). Default `expiry_condition`: `model_version_change` for `tool_shape`/`interaction_mode`, `probe_failure` for `schema_dialect`, `experiment_ref` for any synthesized surface (the admission experiment is its evidence). The removal test is `retire_surface` (fall back to the family's `reference_variant`). The endorsement that admits is `validator` then `seal` — both in the ADR-0035 basis; no new endorsement point.
3. **Safety obligations** (attached as `SafetyEvidence{S1..S4: pass | fail | n/a(reason)}`):
   - **S1 No authority widening, statically.** `effects_bound(S) ⊆ effects(capability_refs) ⊆ grants(permission_ceiling)` by domain and scope; a `PlanMap` invokes only capabilities in the definition's `allowed_capabilities`; `resolve_name` transforms are exact-table only. Failure class `AuthorityWidening`.
   - **S2 Complete mediation of nested steps.** Every `PlanMap` `Invoke`, every nested code-mode call and every shim-parsed call is its own `Effect` (`effect_id`, `parent_effect_id` = the container/composite effect) and passes `authorize` (WS-H1) individually; an approval endorses one `effect_id` (ADR-0035) — for a composite it names the plan hash and covers only that plan's branches; batch approval of nested code-mode calls is admissible only for `effective_risk_class = read_only` and only when the governing rule declares it. The sandbox that runs model-authored programs holds no credential and no ambient authority; every tool call from it crosses the kernel boundary (host requirement per ADR-0050 §8(c); mechanism WS-E5/B5).
   - **S3 Synthesized text is labelled and placed.** Names, descriptions, examples, grammars and catalogue renderings authored by a model/evolution candidate or lifted from a foreign protocol are `Text`/`CompiledPayload` leaves with `authority ≤ delegate` (`unverified` for imports) and render only into provider roles permitted by the profile's `role_map` (ADR-0034); they can never occupy a `definition`-authority position.
   - **S4 Fail closed.** `fail` or `n/a` on E1, E2 or E3, or an untyped mapping, is `UncheckableSurface` and inadmissible at every tier; a shim-parsed call resolving to no surface is `SurfaceFailure.unknown_surface`, never a best-effort match; only E4 may be `n/a`, with a declared reason.
4. **Emulated pre-check (C2, optional).** A ToolEmu-class adversarial scenario oracle is a `Validator{kind: judge}` with `charged_to = instrument`, a calibration reference and independence from the beneficiary snapshot (ADR-0047); it may *veto* admission and never *grant* it.
5. **Observation and expiry.** Admitted surfaces are measured per profile by delivered/activated/followed (T-LCD-13) and `surface_rejection_rate` (companion ADR); an admitted rule whose E2 result changes on any re-compilation is `AuthorityWidening`-class and the rule is `expired` (ADR-0022 iv, applied continuously); WS-I6 consumes the status transitions.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: synthesized interfaces ship unchecked (S-076 `provisional`, cited only as the system omitting checks; S-049 keep-rate); code-mode mediation mechanisms exist (S-040 `allowed_callers` + results out of context; S-WS-E2-01 supervisor-held bindings, per-snippet isolates; S-111 permission-derived catalogue); emulated adversarial pre-checks find real failures (S-098 ToolEmu, ICLR 2024, Tier A); tool descriptions are an injection surface and capabilities-on-values are the antidote (S-099 CaMeL; agentdojo via WS-H1/H2); similarity-based name resolution binds calls to unnamed capabilities (S-112 `resolve_tool_name`); governance requirements are ADR-0002/0022/0035 (ratified).
- (b) Source-code precedent: `opencode/packages/opencode/src/tool/registry.ts` L280–290 (`describeCodeMode` over `Permission.visibleTools`) and `tool/code-mode.ts` (per-server sandbox tool tree; `invokeChildTool`) (S-111 @9f8db11); `codex-rs/core/src/tools/code_mode/execute_spec.rs` and `codex-rs/code-mode-protocol/src/description.rs` L251/L370 (nested tools remain compiled specs) (S-107 @0735c51); `goose/crates/goose/src/providers/toolshim.rs` (`resolve_tool_name` — the negative precedent for S1/S4) (S-112 @fae91d0); `claude-agent-sdk-python/src/claude_agent_sdk/types.py` L1806–1879 (`allowed_tools` vs `can_use_tool` — two-mechanism warning, via ADR-0024) (S-109 @ad77094). The gated pipeline with conditioned-rule admission, S1–S4 and the veto-only oracle is `no-precedent / novel` relative to HEART (no checks), Anthropic `allowed_callers` (opt-in only) and Cloudflare bindings (credential mediation only).
- (c) Disconfirming evidence considered: (i) HEART/Cursor report gains without gates, so the gates are cost without benefit — answered: their evidence is unmatched-budget and whole-harness; the gates are what make a synthesized surface attributable and its authority checkable, which ADR-0002 requires regardless of gains. (ii) Per-nested-call mediation in code-mode adds latency and approval fatigue — answered: read-only batch approval is admissible when declared; the alternative (one approval for an opaque program) is exactly the authority-widening path; Cloudflare's supervisor already mediates every call. (iii) An emulated pre-check is itself an LM judgement and can be gamed — answered: it is veto-only, instrument-charged and calibrated under ADR-0047; grants come only from static and executable checks. (iv) Requiring a `PlanMap` blocks the most valuable composites (Anthropic recommends `schedule_event`) — answered: `schedule_event` is branch-free `Invoke` sequence over three capabilities and passes; what is blocked is undeclared logic. None overturns.
- (d) Conditionality: assumes a Stage-5 sandbox with no ambient authority (WS-E5/B5; ADR-0050 §8(c) host requirement) and WS-H1's per-proposal `authorize`; assumes WS-I2's fixture suites for E4 on primitives; the emulated pre-check assumes a calibrated judge (C2); independent of model tier; no `provisional` result is load-bearing.
- (e) Build-stage assignment: **C1 / Stage 5** (pipeline for split/static composite proposals; S1–S4 static parts; admission as rules); **C2 / Stage 5+** (code-mode and shim mediation; emulated pre-check; evolution-authored proposals via WS-I5 at Stage 6).

**T-LCD statement (ADR-0007 decision 5).** Satisfies: T-LCD-01 (synthesized shapes live in profile/definition rules, never in code branches), T-LCD-02 (synthesized prose is a labelled leaf; opacity reported under `profile_prose`), T-LCD-05 (admission requires a complete debt record; `retire_surface` is the removal test; expiry defaults), T-LCD-13 (admitted surfaces are observed delivered/activated/followed), T-LCD-14 (the admission experiment is a matched-budget arm; pre-check spend is `instrument`). Does not by itself satisfy T-LCD-04/-11 (mode-level, WS-E2-adr-1) — no additional mitigation needed. **ADR-0024 ladder rung:** a synthesized surface is a *conditioned rule* (rung 3, expirable); the checkers, parsers and sandbox mediation are *Core* (rung 5).

## Consequences

- WS-H1 evaluates every nested/branch step as its own proposal; `approval` records carry the plan hash for composites; WS-H2's taint gate applies to shim-parsed arguments (`delegate` authority).
- WS-E5/B5 provide the credential-free, kernel-mediated sandbox for code-mode; the catalogue rendering is the only thing the sandbox sees.
- WS-I5's evolution pipeline emits `SurfaceProposal`s and inherits `SurfaceSynthesisRefused` as a rejected candidate; WS-I6 consumes surface-rule expiry.
- WS-G3 owns the emulated pre-check as a judge Validator; WS-I2 declares `surface_rejection_rate` and the admission experiment shape.
- WS-L3/H1: imported MCP descriptions are `unverified` leaves under S3 (consistent with ADR-0021's lifting rule).

## Reversibility

**High for the emulated pre-check and expiry defaults** (optional/adjustable by ADR). **Medium for S2 per-nested-call mediation** (relaxing it after Stage 5 needs a compensating approval-by-plan-hash scheme). **Low for "admission only as a conditioned rule" and S1/S4** — dropping them re-opens the untyped escape hatch T-LCD-01/-05 forbid and the authority-widening path ADR-0002 forbids.
