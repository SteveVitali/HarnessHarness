# ADR-NNNN — Grader integration and the Stage 3 suite: separate-verifier default, typed rewards with outcome classes, anti-gaming veto predicates, per-suite oracle declarations; a stratified, validity-annotated first-stage set with SWE-bench Verified demoted to fixture/control; harness-specific benches as planes participated in

**Status:** proposed
**Owner workstream(s):** WS-I4 (with WS-G1 Validator contract, WS-I2 outcome classes/oracle classes, WS-H4/E5/B5 verifier environment, WS-J4 reporting, WS-J6/K1 participation, WS-I5 Evo-Bench) · **Phase:** 2 · **Related:** ADR-0005 (act as participant; import/export), ADR-0006 (N13), ADR-0007 (T-LCD-03 anchor, T-LCD-14/-15), ADR-0038 (levels; validator/fixture pins), ADR-0039/0040 (`charged_to = instrument`; verifier budgets), ADR-0045 (outcome classes; `n/a{reason}`; AC-I2-5/-6), ADR-0046 (`compare`; parity), ADR-0047 (nine oracle classes; deterministic headline; `oracle_failure`; veto invariants); OQ-039 (resolved: mini-SWE-agent-class anchor), OQ-121, OQ-126, OQ-WS-I4-01/-02/-03/-06/-07/-09; CF-WS-I4-02/-05/-06; R-2.9.4, R-2.7.1, R-2.9.2

## Context

ADR-0047 restricts headline capability to deterministic oracle classes and asks WS-I4 to declare per suite which classes exist and to supply the per-suite oracle implementations; ADR-0045 fixes outcome classes and forbids "unmeasured ⇒ 0"; WS-G1 fixes the Validator contract (`bind → collect → check → emit`), `visible`/`held_out` criteria and the tamper/skip veto predicates. The audit found: Harbor rejects empty/non-numeric/non-finite rewards with typed errors and defaults to running tests in the agent's container (`shared`), with `separate` available; SWE-bench regrades in a pristine container from the image with a `git apply` chain, cross-checks the parsed test statuses against the recorded exit code, treats a skipped fail-to-pass test as non-resolution and a suite that never ran as invalid, and classifies environment faults post hoc, read-only and advisory (`infra_failure.py`); τ-bench decides by data-hash equality after replaying ground-truth actions; AgentDojo decides utility and security from pre/post environments and traces. On suite validity: Terminal-Bench 2.0 spends > 3 person-hours per task on oracle solvability, specification specificity and anti-triviality (S-WS-I4-09); SWE-bench Verified is memorised (S-WS-I4-01 accepted venue; S-WS-I4-02 `provisional`) and was retired by its heaviest user in 2026-02 after 59.4 % of audited failed hard tasks proved to have flawed tests (S-WS-I4-03); SWE-Bench Pro's public set was found ~30 % flawed with a ~70 % noise ceiling in 2026-07 (S-WS-I4-04); SWE-rebench builds temporally fresh pools (S-WS-I4-05). The brief names SWE-bench, Terminal-Bench 2.0 and τ-bench as first-stage anchors and Harness-Bench/Evo-Bench as "participants".

## Options considered

1. **Grade in the agent's environment (Harbor/Terminal-Bench default) everywhere.** Rejected as the default: the subject can alter tests, reward files or the interpreter (WS-G1 `EvidenceTampered`); SWE-bench pays the separate-container cost for this reason.
2. **Keep SWE-bench Verified as the headline coding suite (the brief's literal anchor).** Rejected: three independent lines of memorisation evidence and a vendor retirement; a headline number on it measures model memory (S-WS-I4-02's own conclusion) — but it stays as the T-LCD-03 fixture and a contamination control (option 4).
3. **Replace SWE-bench with a private, instrument-authored fresh pool.** Rejected: N13; single-team private suites carry their own flaw rates (S-WS-I4-04).
4. **Separate-verifier default where a submission kind exists; typed rewards → outcome classes; anti-gaming checks as veto predicates; per-suite oracle declarations; a stratified Stage 3 set with SWE-bench Verified demoted to fixture/control and headline coding capability from Terminal-Bench 2.0 plus a third-party fresh SWE-style pool; Harness-Bench/Evo-Bench integrated by participation and import (chosen).**

## Decision

1. **Grader placement.** `grade` (WS-I4-adr-1) binds the task's held-out validators through the WS-G1 contract with `phase = instrument`, `visibility = held_out`, `charged_to = instrument`, under `TaskRecord.instrument.verify_budget` and the `verify` network policy. **Default `verifier_isolation = separate`** wherever the family declares a `submission_kind ≠ none`: a fresh environment is materialised from the same `EnvironmentSpec`, the content-addressed `Submission` is applied (patch: apply chain + reverse check; end state: restored; action log: replayed), and validators run there. `shared` is admissible only where the family declares it (Terminal-Bench-style end states that *are* the environment) and is recorded on every verdict; under `shared` the tamper veto renders `n/a{no_detector}` (never a false pass), and OQ-WS-I4-09 asks whether a pre-verify snapshot restores a deterministic detector.
2. **Grader output contract.** A typed reward (`bool | graded decimal-string | verdict lattice | vector`) parsed under a declared parser; empty, non-numeric, non-finite or unparseable output, a crash, a timeout or a refusal ⇒ `Verdict.status = oracle_failure` ⇒ `outcome_class = oracle_failure` (ADR-0047 item 4); an environment fault matched by the **advisory infrastructure-failure detector** (SWE-bench signature set: browser launch, display, OOM, container unavailable, name resolution ⇒ `tier = environment`; missing module, no tests collected, timeout ⇒ `tier = ambiguous`) ⇒ `outcome_class = infrastructure_failure{reason, tier}` for `environment`, and `scored` with `infra_suspected{reason}` annotation for `ambiguous`; the detector is read-only and never changes which runs are graded — denominators are decided by each metric's `outcome_class_policy` (ADR-0045 item 3), never by the adapter. `submission_apply_failed` is a `scored` failure.
3. **Anti-gaming veto predicates** (join ADR-0047 item 5's list; `trace_predicate` over grader evidence): `grader_log_inconsistent` (recorded exit status non-zero while no failure parsed — SWE-bench `grading.py`), `suite_not_run` (no parsed results and no evidence the suite executed), `held_out_skipped` (a held-out fail-to-pass criterion reported *skipped*), `held_out_leak` and `benchmark_egress` (WS-I4-adr-2), plus WS-G1's `EvidenceTampered`, `VerificationSkipped`, `MetadataShortcut`. A tripped predicate yields *success-with-veto* (ADR-0045 item 6).
4. **Per-suite oracle declarations** (ADR-0047 consequence): Terminal-Bench 2.0/Harbor format — `executable` (tests → reward file), `shared` default per family record, headline-eligible; SWE-style (SWE-bench harness format) — `executable` with `resolved = F2P ∧ P2P`, `partial = P2P ∧ 0 < F2P < 1`, `separate`, headline-eligible; τ-bench — `end_state` (db hash after ground-truth replay) ∧ `output_check`, `separate`, headline-eligible, the **user simulator is an instrument model** (pinned snapshot, `NondeterminismDeclaration`, `charged_to = instrument`; CF-WS-I4-05); AgentDojo — `end_state` + `trace_predicate` (`utility`, `security`; DoS rule declared), `separate`, `utility` headline-eligible, `security` a veto-style metric; Harness-Bench and Evo-Bench — imported as published, `product` granularity only. A model-based grader anywhere is a WS-G3 judge (calibrated, independent, labelled) and never feeds the headline.
5. **Stage 3 suite** (dossier §6.7): **A** Terminal-Bench 2.0 (89 tasks, headline `coding_terminal`, n ≥ 5); **B** a third-party temporally fresh SWE-style pool graded by the SWE-bench harness format (≥ 100 tasks whose `first_public_at` postdates every Stage 3 snapshot's cutoff claim — SWE-rebench-class or re-audited SWE-Bench Pro public, OQ-WS-I4-02; `SuiteValidityRecord` mandatory before headline use; n ≥ 3); **C** SWE-bench Verified mini (50; HAL list) and full Verified for the T-LCD-03 round-trip only — `retired_for_headline = true`, stratum `contaminated_public`, the control that lets J4 measure contamination's effect on a harness effect; **D** τ-bench retail + airline (165 tasks, n ≥ 8 for pass^k); **E** AgentDojo latest version (all user × injection tasks, n ≥ 3; the H-track veto acceptance vehicle); **F** HAL-class fault and structural-perturbation profiles applied to A/D as environment-factor levels (`long_running_recovery`, portability) — no new tasks; **G** Harbor-Index (82 tasks) as an adapter CI smoke suite at `product` granularity. Deferred to C2: WebArena/OSWorld (`browser_computer`), a `search_research` suite, τ²-bench dual control, `persistent_multi_episode` as a design over any family. METR's horizon is a metric over tasks with human-time metadata, not a suite. Replicate counts are Stage 3 review items with OQ-121/OQ-WS-I4-03.
6. **Harness-specific benches as planes.** Harness-Bench (S-062) and Evo-Bench (S-067) are integrated by (a) **participation** — the native reference harness lowered to a container-installed or ACP participant their runner can invoke (ADR-0005; surface choice OQ-WS-I4-07) — and (b) **import** of their trajectories/results as `product` rows with `observability_level` from the artifact; their environments enter as families; Evo-Bench's evolution protocol and sensitivity-aware split are WS-I5's (C4) under ADR-0046's gates. Harness-Bench corpus availability is OQ-WS-I4-01.
7. **Every adapter carries a parity report before its rows are headline-eligible** (WS-I4-adr-1); oracle-failing tasks become `validity = invalid`, listed, never dropped.

**T-LCD statement.** Satisfies T-LCD-03 (fixture and anchor suite named; equivalence via ADR-0046), T-LCD-14 (grading spend is instrument-charged and outside `eval_budget` equality; parity is budget-matched), T-LCD-15 (`n/a{no_detector}` under `shared`; hosted rows `n/a{class|observability}` for ledger vetoes), T-LCD-13 (visible test invocation measurable through delivered/activated/followed). Does not address T-LCD-01/-02/-04–-12 beyond consumption. ADR-0024 rung: grader contract and predicates MUST-code; suite composition and oracle declarations MUST-data (experiment/registry records).

## Consequences

- WS-G1 supplies the Validator bindings the graders use and adds the three SWE-bench-derived predicates to its veto list; WS-I2/J4 add `applies_to_families`, the stratified headline and `infra_suspected` annotation; WS-J5 stores `verifier_isolation`, `suite_id`, `split_label`, `SuiteValidityRecord` refs per row.
- WS-B5/E5/H4 materialise the separate verifier environment under the `verify` phase policy; WS-L2 charges verifier spend to the instrument; WS-C1 exposes `training_cutoff_claim`.
- WS-J6/K1 deliver the participation surface by Stage 4; WS-I5 consumes Evo-Bench only after L3 split assignment.
- The Stage 0 spike (ADR-0050 §; `l1-spike-spec.md`) can use a single TB2 task as its sandboxed-tool-call fixture without any I4 machinery beyond `EnvironmentSpec`.

## Reversibility

**High** for suite composition (a registry/experiment change; rows carry `suite_id` so re-stratification is a re-render), **medium** for the separate-verifier default and outcome mapping (relaxing them re-admits tamper and infra-as-failure into stored headline numbers), **high** for the participation surface choice (OQ-WS-I4-07).
