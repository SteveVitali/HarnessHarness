# WS-E3-adr-3 — Catalog sync and epochs: catalog drift as ledger data, `freeze | adopt | ask`, adoption as incremental lowering with compiled identities

**Status:** proposed
**Owner workstream(s):** WS-E3 (consumers: WS-E4, WS-E1, WS-H5, WS-H7, WS-L4, WS-J5, WS-B1, WS-I2) · **Phase:** 2 · **Related:** WS-E3-adr-1/2; ADR-0019 (closed world; `relower` + `model.surface.relowered` precedent), ADR-0021 (MCP lifting: `origin = import`, `authority = unverified`; loss report), ADR-0025 (sealed definition; `registry_snapshot_id`), ADR-0026/0027 (ledger authoritative; fork by reference), ADR-0033 (`unverified` never coerced), ADR-0036/0038 (`configuration_version_id`; bundle as lock manifest; R-levels), ADR-0030/0031 (effect lifecycle for `permission_request`); S-153 (MCP 2026-07-28 `tools/list` TTL, `subscriptions/listen`, `listChanged`); OQ-WS-E3-07/08; OQ-022, OQ-107 (H5 extension trust); R-2.5.3, R-2.5.4, R-2.8.3

## Context

The catalogue a sealed definition was compiled against changes under a running harness: MCP servers emit `notifications/tools/list_changed` (now only on an opted-in `subscriptions/listen` stream, `schema.ts` L1895–1900, L1295–1317), `tools/list` results carry a `ttlMs` freshness hint with "notification acts as an immediate invalidation signal" (`caching.mdx`), the tool set "MAY vary by the authorization presented" (`tools.mdx` L60–66), servers reconnect, and principals enable or disable extensions (goose `search_available_extensions`, `extension_manager.rs` L2602–2660). Every audited client handles this by re-listing the source and silently replacing its registered tools — gemini-cli with a 500 ms verification retry because "Some servers notify before they're fully ready" (`mcp-client.ts` L719–770), opencode by re-listing and publishing `ToolsChanged` (`mcp/index.ts` L462–470), goose by bumping a cache version (`extension_manager.rs` L1899). None records the delta as data, and none reconciles the new tools with compiled identity: under ADR-0019's closed-world rule a tool that appeared after `seal` has no compiled identity and may not be delivered; under ADR-0036 a run's `configuration_version_id` must not change without a ledger event; under ADR-0038 a bundle is a lock manifest. ADR-0019 already solved the analogous problem for a mid-run model switch (`relower` + `model.surface.relowered`).

## Options considered

1. **Silent re-registration (the audited status quo).** *Rejected:* violates the closed-world rule and reproducibility (R-levels); a Lab run could gain or lose tools mid-experiment with no trace.
2. **Forbid drift: any change aborts the run.** *Rejected:* unusable interactively; MCP explicitly designs for change (TTL, notifications, per-authorization variation).
3. **Re-seal and re-compile the whole definition on every change.** *Rejected:* changes the sealed definition's identity for a source-side event the definition did not author; expensive; loses the run's factor coordinate.
4. **Catalog drift as a typed delta event; an explicit adoption step governed by `drift_policy ∈ {freeze, adopt, ask}`; adoption performed as an incremental lowering (ADR-0021 lifting) that produces compiled identities in a new catalog epoch recorded in the ledger and the run manifest; `freeze` as the experiment default (chosen).**

## Decision

1. **Sync.** WS-E4 implements `sync_source(source_ref, trigger ∈ {list_changed, ttl_expired, reconnect, extension_enabled, extension_disabled, authorization_changed}) → CatalogDelta{source_ref, cause, added[], removed[], changed[{surface_id_old, surface_id_new, diff_class}]}`, listing with pagination bounds (`IndexOverflow` beyond a declared page/byte ceiling; duplicate cursors are errors — opencode precedent), honouring `ttlMs` as a freshness hint (never a polling interval) and treating notifications as invalidation; every delta is emitted as `action.tool.catalog.delta`, including empty deltas (a notification that changed nothing is still data).
2. **Adoption policy.** `drift_policy` is MUST-data on the exposure policy with defaults **`freeze` for Lab runs** (any run under a `Design`/`PreRegistration`) and **`adopt` for interactive runs**; `ask` raises a `permission_request` effect to the principal (H7 approval budget applies). Under `freeze`: `removed` entries become `availability = unavailable(removed)` (calls fail `SurfaceUnavailable`, never silently re-routed), `added`/`changed` are recorded but not entries, and `catalog_id`/`configuration_version_id` are unchanged. Under `adopt`: added/changed surfaces are lowered incrementally — lifted per ADR-0021 with `provenance.origin = import`, `authority = unverified` (never coerced, ADR-0033), effects from hints only as a projection, `permission_coverage` recomputed (typically `uncovered` until a grant exists) — producing a `CatalogEpoch{epoch, catalog_id_prev, catalog_id, bundle_delta (new version_ids), loss_report, adopted_by}` emitted as `action.tool.catalog.epoch` and appended to the run manifest's `catalog_epochs[]`; the index is rebuilt (`action.tool.catalog.built`), and no surface from a previous epoch is revealed (`IndexStale`).
3. **Identity.** An adopted surface's compiled identity derives from the lifted `ToolCapability`'s `semantic_id` and the epoch's `bundle_delta`; `configuration_id` (semantic coordinate) is unchanged by adoption; whether `adopt` bumps `configuration_version_id` or only annotates the manifest is OQ-WS-E3-07 (WS-L4/J5) — until resolved, a run with any adopted epoch caps its reproducibility claim at the level ADR-0038 assigns to unpinned members.
4. **Trust and availability.** Attestation/pin results from WS-H5 map to `availability ∈ {available, unavailable(untrusted | unattested)}`; an unattested source's tools can be *indexed* only if the policy admits `unverified` index forms (their `Text` leaves carry `external`/`unverified` labels into `context_label`, ADR-0034), and are never `pinned`.
5. **Hosted export.** When this runtime exports an MCP tool surface (ADR-0021), a change in the exposure plan is published as `listChanged` and the exported `tools/list` sets `ttlMs` from the plan's expected stability (0 when selection is per-call) and `cacheScope = private` when the plan depends on the caller's authorization.
6. **Tiers.** C1 / Stage 2 with WS-E4 (sync, deltas, `freeze`, `unavailable`); C1 / Stage 4 (`adopt` with incremental lowering; hosted export TTL); C2 (`ask` through H7; attestation-gated indexing with H5).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: the protocol designs for change — TTL hints, opt-in list-changed subscriptions, per-authorization variation, deterministic ordering (S-153, read in source); clients re-list whole sources and race server readiness (S-119; S-111; S-112); the closed-world rule and the `relower` precedent for mid-run change (ADR-0019, ratified); lifting semantics and `unverified` authority (ADR-0021/0033, ratified); reproducibility levels and the lock-manifest bundle (ADR-0038, ratified); extension enable/disable as a model-visible discovery surface (S-112 `search_available_extensions`).
- (b) Source-code precedent: `packages/core/src/tools/mcp-client.ts` L406–420, L700–790, L1560–1572 (S-119 @ed2ac40); `packages/opencode/src/mcp/index.ts` L462–470 and `mcp/catalog.ts` L11–36 (S-111 @9f8db11); `crates/goose/src/agents/extension_manager.rs` L1834–1856, L1899–1975, L2602–2660 (S-112 @fae91d0); `modelcontextprotocol/schema/2026-07-28/schema.ts` L1081–1094, L1295–1317, L1767–1781, L1895–1900 and `docs/specification/2026-07-28/server/utilities/caching.mdx` (S-153 @aa8ce04). Delta-as-event, the `freeze | adopt | ask` policy, and epochs with compiled identities are `no-precedent / novel`.
- (c) Disconfirming evidence considered: (i) interactive users expect new tools immediately — answered: `adopt` is the interactive default and is an incremental lowering, not a re-seal; (ii) `freeze` may strand a Lab run whose required tool vanished — answered: `SurfaceUnavailable` is a typed, counted outcome (`catalog_drift_events`) and the run's outcome class can be `infrastructure_failure`, which is more honest than silent substitution; (iii) MCP's TTL says servers "MAY change the underlying data before the TTL expires", so any snapshot is approximate — answered: the epoch records what the runtime *believed*; calls against removed tools fail typed at the source and are reconciled as a delta with cause `reconnect`/`list_changed`. None overturns.
- (d) Conditionality: assumes MCP 2026-07-28 semantics (earlier servers without `ttlMs` are treated as `ttlMs = 0` per the spec) and WS-E4's transport; independent of model tier; assumes WS-H5's attestation outcome is available at sync time (otherwise `unattested`).
- (e) Build-stage assignment: **C1 / Stage 2** (sync, deltas, `freeze`, `unavailable`, events) with WS-E4; **C1 / Stage 4** (`adopt`, epochs, hosted export TTL/`listChanged`); **C2** (`ask` via H7; attestation-gated indexing via H5).

**T-LCD statement (ADR-0007 decision 5).** Satisfies: T-LCD-06 (no IR entity depends on a source or protocol; epochs are runtime records), T-LCD-07-adjacent (lifted declarations are `unverified`, never coerced), T-LCD-10 (adopted surfaces get content-derived identities; names remain surfaces), T-LCD-11 (adoption reuses ADR-0021's loss report), T-LCD-13 (delivered/activated unchanged), T-LCD-14 (`freeze` keeps arms comparable). Does not by itself satisfy T-LCD-03/-04.

## Consequences

- WS-E4 owns `sync_source` (listing, pagination, subscriptions, TTL) and delivers `CatalogDelta`s; it never mutates the catalog directly.
- WS-L4/J5 decide OQ-WS-E3-07 (manifest annotation vs version bump); WS-I2's outcome classes gain `SurfaceUnavailable` as an `infrastructure_failure` cause.
- WS-H5's attestation result becomes a catalog input; WS-H7 budgets `ask` adoptions.
- WS-B1 registers `action.tool.catalog.{built, delta, epoch}`.

## Reversibility

**High for defaults** (`freeze`/`adopt` per run kind is data); **medium for epochs** (dropping them returns to silent re-registration, which the Lab cannot tolerate — the cost is losing R-level claims for runs with drift); **low for "adoption is a lowering"** (shared with ADR-0019/0021).
