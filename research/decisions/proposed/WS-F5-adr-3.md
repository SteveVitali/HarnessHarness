# ADR-NNNN — Failure domains, spawn-time reservation and consistency declarations: the child AgentProcess as a failure domain with a closed `ChildOutcome`; the reservation order before `control.subagent.spawned`; a closed `ConsistencyLevel` sum declared per coordination object; topology as a matched-budget Lab factor

**Status:** proposed
**Owner workstream(s):** WS-F5 · **Phase:** 4 · **Related:** ADR-0027, ADR-0030/0031, ADR-0040, ADR-0046, ADR-0053, ADR-0054, ADR-0107, ADR-0113, ADR-0130, ADR-0131, ADR-0132, ADR-0133, ADR-0138, ADR-0154; OQ-013, OQ-081, OQ-092, OQ-095; R-2.6.5, R-2.6.3, R-2.6.4; CF-WS-F5-01, CF-WS-F5-02, CF-WS-F5-05, CF-WS-F5-09; OQ-WS-F5-05/07/08

## Context

Doc 2 §5.7 asks that agents be "processes with isolated state, compute budgets, capabilities, and failure domains"; the ratified runtime already makes a child a run with its own ledger and writer lease (ADR-0027 §6), environment handle (ADR-0138), budget node (ADR-0040), attenuated handles (ADR-0053) and clearance (ADR-0054), and WS-B3's recovery table says a crashed child restores itself while the parent waits. Three things are still missing. First, what the *parent* does with a child that did not return: RAH is silent, Codex exposes `NotFound`/final/in-progress, Symphony needs eleven attempt phases because "retry logic and logs differ", and MAST records premature termination and incomplete verification as the observed failures. Second, the order in which fan-out, depth, budget, ownership and shared-resource leases are reserved relative to the spawn event, so that a crash mid-spawn leaks nothing — WS-L2 found fan-out "budgeted by instruction" everywhere (Anthropic prose, Codex thread caps, Symphony slots). Third, what consistency each shared object can honestly claim: a fenced single-writer log is linearizable, a forked child sees a snapshot, a shared handle under per-key leases is serializable per key and nothing more, and two ledgers are only causally ordered — the Jepsen hierarchy names all of these, and no audited harness declares any of them. Every topology claim the Lab makes must also be matched-budget (T-LCD-14): multi-agent runs cost ≈15× chat tokens (S-036).

## Options considered

1. **Leave containment to B3 and results to convention** (RAH shape). Rejected: the parent-side gap is exactly MAST FM-3.1/3.2; an absent child must be a typed outcome.
2. **Global consistency (a shared transactional store across the tree).** Rejected: no global sequence exists (ADR-0027 §5); it would reintroduce the "single giant shared context" doc 2 §10 rules out; no precedent.
3. **Reserve after spawn / rely on caps in prose.** Rejected: the L2 evidence (fan-out overrun incidents; ADR-0040 reserve-before-spend).
4. **Closed `ChildOutcome`, a fixed reservation order before the spawn event is durable, per-object `ConsistencyLevel` declarations checked by the compiler and the Stage-4 battery, and topology as a matched-budget factor.** Chosen.

## Decision

1. **The child is a failure domain.** Own run ledger and writer lease (ADR-0026/0130), own environment handle via `derive` (ADR-0138 D1–D4), own budget node (`slice` default, `pool` by declaration; ADR-0040), own attenuated handle set and clearance (ADR-0053 D-1…D-3; ADR-0054), own subscriptions. Cross-domain edges are exactly: `control.subagent.spawned` → child `lifecycle.run.created` (`parent_anchor`), child terminal → `Trigger.child_terminal`, peer messages (ADR-1), ownership records (ADR-1). Invariants: **C-1** no child effect executes under the parent's handles or lease; **C-2** a child's irreversible or `abandoned` effect is listed in its `ChildResult.effects_irreversible[]` and the parent's completion gate treats it as its own (ADR-0113, OQ-092 rule); **C-3** killing the parent never interrupts a child's committed effect; **C-4** a child's blast radius = its handle set × its environment containment × its budget node.
2. **`ChildOutcome` (closed, HIR dialect).** `result{result_ref} | cancelled{by} | budget_exhausted{dimension} | stop{StopReason} | infrastructure_failure{cause} | unknown{last_durable_phase} | refused_at_spawn{reason}`; carried on `control.subagent.result/cancelled` and lifted for hosted children from `HostedEvent` terminals (undeclared ⇒ `unknown`, never `result` — T-LCD-07; OQ-WS-F5-08). `CoordinationPolicy.on_absent_child ∈ {block_completion (default), annotate}` decides whether an `absent` child blocks the parent's `finish` (ADR-2 G-5).
3. **Crash matrix (normative; extends WS-B3's recovery table).** Child crash ⇒ child `restore` alone; parent waits ≤ `TimeoutPolicy[subagent]` then `cancel` ⇒ `unknown`. Child `slice` exhausted ⇒ `budget_exhausted`, remainder released. `pool` root exhausted ⇒ root-first `Exceeded` to every child at its next decision point (ADR-0040 §4). Parent crash ⇒ children continue under their leases; ownership with `return_to_grantor` is held in escrow for the grantor run (OQ-WS-F5-05 for expiry); on parent `restore` open `subagent` scopes re-subscribe `child_terminal` and terminal children merge at the next decision point. Parent cancel ⇒ child cancels at its next decision point, never mid-effect (ADR-0131 W-3; WS-F2 INV-3); open effects resolved per ADR-0031. Fault-injection rows KP-S1…S4 join ADR-0132's battery (CF-WS-F5-05).
4. **Reservation order at `Delegate`** (atomic with respect to the spawn event; nothing partially held): (1) `delegation_depth + 1 ≤ cap` else `SpawnRefused{depth}` (a typed observation to the model); (2) `reserve(parent_budget, {spawns: 1, fan_out: +1})` else `SpawnRefused{fan_out}`; (3) `allocate(child_budget)` else `BudgetExceedsParent`; (4) `grant_ownership` else `NotOwned`; (5) `share` mode: `acquire(resource(key))` for every `reserved_keys[]` entry in canonical order, all-or-nothing, else `ResourceLockTimeout`; (6) `derive(parent_handle, mode)`; (7) append `control.subagent.spawned{…, ownership_grants[], reserved_keys[], consistency_declarations[], merge_policy_ref, child_handles[], parent_handle, ceiling, parent_head_at_spawn}`. A crash before (7) releases everything by lease expiry under the parent's writer lease (ADR-0040 §3). `fan_out` decrements at the child's terminal; `spawns` stays counted. External keys (`tracker_item`, `vcs_ref`, `port`) are claims only; the external system is not made transactional.
5. **Consistency levels (closed, HIR dialect).** `linearizable_single_writer | snapshot_at_fork | per_key_serializable | causal_cross_run | strong_eventual_union | conflict_set_eventual`; `ConsistencyDeclaration{object | kind-wildcard, level, staleness_bound?, readers ∈ {owner_only, grantor, family}}`. **K-1** the compiler refuses declarations inconsistent with the ownership/`derive` mode (`share` ⇏ `snapshot_at_fork`; `fork_snapshot` ⇏ `per_key_serializable`; a ledger is always `linearizable_single_writer`; keyed memory is always `conflict_set_eventual`). **K-2** anything spanning two ledgers is at most `causal_cross_run`; consistent snapshots over a tree require `hlc_required = true` — mandatory in `share` mode, optional otherwise (closes OQ-081 for delegation-bearing runs; OQ-WS-F5-07). **K-3** every level has a Stage 4 check (AC-F5-06). **K-4** `CoordinationPolicy{messaging, merge_policies, declarations, default_isolation ∈ {fork_snapshot (default), scoped_subtree, share}, depth_cap, fan_out_cap, on_absent_child}` is MUST-data of the sealed definition, `authority_cap`-layered; a `HirDiff` that relaxes a level, enables `sibling`/`broadcast`, widens `default_isolation` toward `share`, raises caps, or sets `on_absent_child = annotate` is classified `coordination_delta = loosening` (CF-WS-F5-09) and refused in evolution contexts (ADR-0053 D-5 shape).
6. **Topology is a Lab factor under matched budget.** `lab/coordination-topology-v1`: `topology ∈ {single_agent, orchestrator_worker_isolated, orchestrator_worker_share, peer_messaging}` × `merge_policy` × `default_isolation`, `MatchSpec{matched_total}` with child spend `charged_to = subject`, reporting success, `lost_write_count`, `conflicts_open_at_completion`, `absent_children`, approvals, cost and tails; every "multi-agent helps" statement is a `ComparisonReport` with `benefit_kind` and `budget_match.status` (ADR-0046); C4 gates apply to any evolved topology. Class-scoped metrics: `coordination.absent_children`, `coordination.child_outcome_profile`, `coordination.fan_out_peak`, `coordination.spawn_refused_count`, `coordination.parent_wait_ms`.

**T-LCD statement.** Satisfies T-LCD-06/-07 (hosted children lift outcomes from declared `HostedEvent`s; undeclared ⇒ `unknown`; no native field), T-LCD-08 (`CoordinationPolicy` is definition data seen by the strategy through its contract), T-LCD-09 (`topology`, `merge_policy`, `default_isolation` are explicit component-level factors; interaction with model is `contrast`-estimable), T-LCD-12 (operations; out-of-process), T-LCD-14 (matched-total comparisons; child spend is subject spend), T-LCD-15 (all coordination metrics class-scoped; hosted `n/a`), T-LCD-05 (any profile-conditioned coordination default is a conditioned rule with a debt record — reflexive). Not applicable: T-LCD-01/-02/-03/-04/-10/-11/-13. ADR-0024 rungs: outcome sum, reservation order, K-1/K-2 checks MUST-code; caps, levels, `on_absent_child` MUST-data.

## Consequences

WS-F3's `Delegate` must follow the reservation order and return `SpawnRefused` as a typed observation (no prose "effort scaling rules" as the enforcement); WS-F4 allocates within it; WS-B3 adds KP-S rows and the ownership-escrow case; WS-B1 extends `control.subagent.*` payloads; WS-J3 registers the topology exemplar; WS-I2 registers the coordination metrics with two vetoes (ADR-2); WS-J6 maps hosted terminals to `ChildOutcome`; WS-A3 adds `coordination_delta` (or reuses `validity_delta`) to `HirDiff.classification`. The Lab can now state, under matched budget, when coordination cost exceeds the value of parallelism (doc 2 §5.7's last question).

## Reversibility

**Medium-high.** The outcome sum, order and declarations are additive records and checks over existing leases and budgets; removing declarations costs nothing in data; changing the default isolation or `on_absent_child` is a policy flip; only the reservation order is load-bearing for the no-leak property and would need a superseding ADR with a new fault-injection proof.
