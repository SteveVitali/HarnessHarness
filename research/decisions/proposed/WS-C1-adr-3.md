# ADR-NNNN — Capability discovery and drift at the model boundary: tri-state transport capability declarations that are probed, discovery results as `external`-authority claims with pinned-profile precedence, served-model drift as a ledger fact priced at the served model, and a distributional fingerprint probe with `seed_honoured`

**Status:** proposed
**Owner workstream(s):** WS-C1 (with WS-C3 for the two proposed profile capability fields, WS-L4 for `ModelSnapshotRecord`, WS-I2/WS-J3/WS-J4 for drift policy in `Design`, WS-C2 for reaction to substitution, WS-L2 for pricing at the served model, WS-F2 for `estimate_tokens`) · **Phase:** 2 · **Related:** ADR-0004 (DRIFT semantics — experimental data), ADR-0007 (T-LCD-07/-09/-11/-15), ADR-0013 (probe verdicts annotate and split arms; hosted stays hosted), ADR-0020 (declared → probed capabilities; `ConformanceRecord`; `probe_profile`), ADR-0033 (authority minting; `external` for open-world endpoints), ADR-0036 (`configuration_id`), ADR-0039 (`model_ref.serving_route`; `instrument` attribution), ADR-0043 (`Money.provenance`), ADR-0045/ADR-0046 (results rows; admissibility), ADR-0048; CF-033 (model snapshot; drift detectable), CF-095, CF-WS-C1-03, OQ-048, OQ-097, OQ-111, OQ-122, OQ-WS-C1-02, OQ-WS-C2-07, OQ-WS-D3-04, OQ-WS-D4-01; R-2.3.1

## Context

Doc 3 §5 lists "capability discovery e.g. context window, modalities, caching support" in the gateway's scope. Phase 1 settled that the model is a *snapshot* with drift as a detectable fact (CF-033), that capabilities are declared then probed and never intersected (T-LCD-07; ADR-0020 `ConformanceRecord` with DRIFT), and that closed-schema values from an open-world endpoint are `authority = external` (ADR-0033). OQ-111 asks for the fingerprint-probe design and the policy on mid-experiment change; OQ-122 asks which providers honour a sampling seed; OQ-048 asks how the model coordinate is represented when a run binds several snapshots.

The audit (WS-C1 F7–F8) finds three different things called "capability" at the boundary. *Transport* capabilities live in transport records (codex `ModelProviderInfo{supports_websockets, stream_idle_timeout_ms}`, goose `DeclarativeProviderConfig{supports_streaming, dynamic_models}`, goose `CacheSemantics` chosen by a **provider-name branch**, Inspect `max_connections/connection_key`). *Model* capabilities are computed by substring rules over model ids (OpenHands `ModelFeatures`, with a comment that explicit cache markers disable one provider's implicit caching), by a `switch` on model id (gemini-cli `tokenLimits.ts`), by third-party metadata tables with substring overrides and arithmetic (OpenHands halves max-output when it equals the window, refuses windows < 16,384), or by provider listing endpoints (goose `fetch_model_info`) with a precedence chain override → configured → canonical → default. *Observed conformance* is probed by none of them. Provider-side substitution is observable everywhere and recorded nowhere as a ledger fact: codex `ServerModel` "can differ from the requested model when backend safety routing applies" (`common.rs` L89), Anthropic server-side fallback delivers a `fallback` block "at each model boundary", pi re-prices usage at the served model's cost, Inspect carries `ModelFallback{model, fallback_model, count}`, OTel separates `gen_ai.response.model` from the request model. Nondeterminism is a serving-side property the client cannot request: 1,000 temperature-0 completions of one prompt yielded 80 distinct outputs, caused by batch-size-dependent reduction order (S-WS-C1-02, Tier B, reproducible recipe; corroborated by S-WS-C1-04, `provisional`), so a seed cannot be assumed honoured and a fingerprint cannot be a single hash.

## Options considered

1. **Gateway derives model capabilities at run time (listing endpoints, metadata tables, substring rules) and the profile inherits them.** *Rejected:* every audited form is a model-id branch (T-LCD-01) or an unpinned external value; the sealed profile would no longer be the only runtime source and the two-profile compile test (T-LCD-04) would become non-reproducible.
2. **Treat provider-side substitution as an error and fail the call.** *Rejected as default:* substitution is a provider-declared behaviour under overload/safety routing; failing loses a completed, billable response. It is admitted only when the profile binding declares `substitution_allowed = false` (class `served_model_mismatch`).
3. **Fingerprint as a single hash of temperature-0 outputs over a fixed prompt set (OQ-111's sketch).** *Rejected:* nondeterminism makes a single hash flap; false DRIFT would split arms spuriously.
4. **No probes; rely on provider snapshot ids.** *Rejected:* providers change behaviour without changing ids (S-047, CF-033) and not every dialect exposes an id; ids are claims, not evidence.
5. **Transport capabilities as a gateway-owned tri-state declaration that is probed; model capabilities remain profile-owned with discovery results as `external` claims and pinned-wins precedence; served-model drift as a first-class ledger fact priced at the served model; a distributional fingerprint probe charged `instrument` whose verdict annotates and splits arms; `seed_honoured` and `substitution_allowed` proposed as profile capability fields (chosen).**

## Decision

1. **Transport capability declaration** (per `WireDialect` × endpoint; each value `{supported, unsupported, unknown}`; declared → probed → `ConformanceRecord` with DRIFT, mirroring ADR-0013/ADR-0020): `streaming, usage_in_stream, usage_on_cancel, cache_semantics, cache_state_visible, count_tokens, deferred_requests, model_listing, snapshot_id_exposed, retry_after_honoured, seed_accepted, parallel_connections{max?}, websocket`. Returned by `describe(dialect | endpoint_ref)`; never intersected with a model's declaration (T-LCD-07); `unknown` never coerced.
2. **Model capabilities stay in the Model Profile (ADR-0020).** Two fields are proposed to WS-C3: `seed_honoured ∈ {supported, unsupported, unknown}` (OQ-122; probed, never assumed from `seed_accepted`) and `substitution_allowed: bool` (whether served-model drift is tolerated for this binding). No gateway-derived value ever enters a profile automatically.
3. **Discovery yields claims.** `discover(endpoint_ref) → [ModelDiscoveryClaim{provider_model_id, context_window?, max_output?, modalities?, pricing?, snapshot_id?, provenance{origin = tool(endpoint), authority = external}}]`. Precedence is **pinned wins**: the sealed profile is the only runtime source; discovery is evidence; `declared ≠ discovered` at probe time is a `ConformanceRecord{verdict: DRIFT}` (ADR-0004 semantics) and never a profile mutation (AC-C1-9). goose's override → configured → canonical → default chain is replaced by this rule.
4. **Served-model drift is a ledger fact.** `model.call.completed{served_model, snapshot_id?, substitution ∈ {none, provider_fallback, safety_routing, unknown}}`; when `served_model ≠ model_ref.provider_model_id`, spend is derived at the served model (ADR-0039 `model_ref.serving_route`; `Money.provenance` per ADR-0043), the row is annotated for J3/J4 as configuration-level drift, and the model coordinate of that call is the served model (OQ-048 input); C2 may react (`model.rerouted`), the gateway never chooses. `ModelSnapshotRecord{provider, model_id, snapshot_id?, pinned, provenance = reported, observed_fingerprint?}` (WS-L4) is filled by the gateway from served-model/system-fingerprint fields where exposed; the gateway is the publisher of the `model snapshot id` dependency stamp (OQ-WS-D4-01). With `substitution_allowed = false` the call fails `served_model_mismatch`.
5. **Distributional fingerprint probe (OQ-111 proposal).** A pre-registered prompt set P (|P| ≈ 8–16 short deterministic-intent tasks), temperature 0, `seed_request` when `seed_accepted`, n ≥ 8 samples per prompt, run at experiment open and close (cadence per `Design`); records `{per_prompt_agreement_rate, multiset_hash, served_model, snapshot_id}` as a `ConformanceRecord` charged `instrument`; DRIFT when agreement or the modal output moves beyond the pre-registered band. Policy on drift: annotate every arm run between the two probes and split the arm at the drift boundary for reporting; never silently pool; never a gate on the run. The same record type serves embedder identity (OQ-WS-D3-04 — the `similarity` index is annotated `depends_on_drifted`, rebuild is D3's decision). Parameters (|P|, n, band, cadence, budget) are OQ-WS-C1-02.
6. **`estimate_tokens(plan) → {count, method ∈ {provider_endpoint, declared_tokenizer, heuristic}, confidence}`** uses the provider endpoint only when `count_tokens = supported`; the estimate feeds F2 reservation sizing (OQ-098) and D1's `context.occupancy` gauge and is never a charge.
7. **Accounting.** Every discovery, probe and fingerprint call is a normal `model.call.*` with `attribution.charged_to = instrument` (ADR-0039); `cache_state` is `unknown` unless `cache_state_visible` (OQ-097 input to C4/J3). For an external gateway `serving_route` (OQ-WS-C2-07) the minimum reported fields are `served_model`, `substitution`, `provider.notice{fallback_boundary}` where exposed, and cost with `provenance = gateway_reported`; candidates considered are `unknown` and the run is stratified, not refused, unless the `Design` says otherwise.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: substitution is observable and unrecorded (S-107 `common.rs` L88–90 `ServerModel`; S-WS-C1-01 server-side fallback block; S-113 `anthropic-messages.ts` L177–182, L599–605 `responseModel` re-pricing; S-136 `_model_output.py` L72 `ModelFallback`; S-212/S-228 `gen_ai.response.model` — WS-C1 F7); temperature-0 nondeterminism from batch-dependent reduction order (S-WS-C1-02; S-WS-C1-04 `provisional`, corroboration only — F7); capability derivation by model-id branches, switches and metadata tables in every audited system, none probing (S-110 `model_features.py`, `llm.py` L2396–2530; S-119 `tokenLimits.ts`; S-112 `context_limit.rs`, `cache_semantics.rs` L20–46; S-107 `ModelProviderInfo` — F8); providers change behaviour without id changes (S-047 via CF-033).
- (b) Source-code precedent: codex `codex-rs/codex-api/src/common.rs` L80–130 (0735c51) — `ServerModel`, `ModelVerifications`, `RateLimits` as stream events; pi-mono `packages/ai/src/api/anthropic-messages.ts` L599–605 (400d690) — usage priced at the served fallback model; Inspect `src/inspect_ai/model/_model_output.py` L72–80 (75f4891) — `ModelFallback` record; goose `crates/goose-providers/src/declarative.rs` L148–200 and `codex-rs/model-provider-info/src/lib.rs` L68–155 — transport capabilities as declared data; gemini-cli `packages/core/src/core/contentGenerator.ts` L215–260 (ed2ac40) — fake/recording generator for probe fixtures. Discovery-as-`external`-claims with pinned-wins precedence, served-model drift with a substitution reason and re-pricing as a ledger fact, and a distributional fingerprint with `seed_honoured` are `no-precedent / novel as integrated`; no audited system probes any transport or model capability.
- (c) Disconfirming evidence considered: fingerprints are noisy and probes cost money, and a probe can only detect, never prevent (WS-C1 §5 R5) — the probe is distributional against a pre-registered band, charged `instrument`, run at experiment boundaries, and yields DRIFT that annotates and splits (ADR-0013), never a gate; provider listing endpoints are the freshest source of context windows and prices (goose `fetch_model_info`) — kept as evidence that surfaces DRIFT, not as a runtime source, because reproducibility of the sealed definition (ADR-0036) outranks freshness. Neither overturns.
- (d) Conditionality: assumes providers surface a per-call served-model identity on at least the C0 dialects (true for every audited API; `served_model` is optional where a proxy strips it and the row is then `substitution = unknown`); the fingerprint band assumes short deterministic-intent prompts and n ≥ 8 — its parameters are unvalidated (`medium` confidence; OQ-WS-C1-02); `seed_honoured` is `unknown` until probed for every model; the quantitative nondeterminism magnitudes (80/1,000; 1.6–2.1× slowdown) are not load-bearing.
- (e) Build-stage assignment: **C0 / Stage 3** (evaluation-first: transport declaration + probes, `discover` claims with DRIFT, `served_model`/`substitution` on `model.call.completed`, fingerprint probe AC-C1-9/-12, `estimate_tokens`) → **C1 / Stage 5** (count-tokens endpoints, `seed_honoured` probes across the model set, embedder-drift annotation with D3, external-gateway `serving_route` reporting with C2/J6). ADR-0024 ladder rung: declarations and probe parameters at *parameter/entity*; DRIFT semantics are *Core* (already ratified).

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-01 (no model-id branch; capabilities are declared data), T-LCD-07 (declare/probe/never intersect, applied to transports and models), T-LCD-09 (served model and drift are factor coordinates, stratified), T-LCD-11 (OTel `gen_ai.response.model` lowering), T-LCD-15 (`unknown` class-scoped; `n/a` for cache state).

## Consequences

- WS-C3 adds `seed_honoured` and `substitution_allowed` to the profile capability vocabulary (ADR-0020 amendment at synthesis) and consumes discovery claims only through the probe/DRIFT path.
- WS-L4 accepts the gateway as the writer of `ModelSnapshotRecord.observed_fingerprint` and the publisher of the model-snapshot dependency stamp (OQ-WS-D4-01); WS-I2/WS-J3/WS-J4 add the drift policy (`annotate + split`) to `Design` and treat the served model as the call's model coordinate (OQ-048).
- WS-C2 reads `provider.notice{served_model}`/`substitution` and may reroute; WS-L2 prices at the served model; WS-F2 consumes `estimate_tokens` with its `confidence`.
- The Lab gains two class-scoped health metrics (DRIFT rate per dialect; `substitution ≠ none` rate per model) at no per-call cost.

## Reversibility

**High** for probe parameters and the declaration field list (data; dialect bump). **Medium** for pinned-wins precedence and served-model re-pricing: reversing them after the first results rows (Stage 3) would make configuration identity and spend attribution non-reproducible for those rows.
