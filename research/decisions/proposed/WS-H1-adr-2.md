# ADR-NNNN — The reference-monitor decision function: ordered checks over records, the policy table Π and its default rows (OQ-101), risk-assessment precedence with `unknown ⇒ irreversible` (OQ-086), unattended mode, and complete mediation as a ledger invariant

**Status:** proposed
**Owner workstream(s):** WS-H1 (consumers: WS-H2, WS-H4, WS-H6, WS-H7, WS-E1, WS-E5, WS-F2, WS-D1, WS-B1, WS-B2, WS-I2) · **Phase:** 2 · **Related:** ADR WS-H1-adr-1 (handles), ADR WS-H1-adr-3 (TCB, delegation), ADR-0033/0034/0035 (scheme; seven checks — implemented verbatim), ADR-0031 (`KernelDecision`, `effective_risk_class`, monotone consumption), ADR-0030 (write-ahead `committed`; `ApprovalTimedOut` is a refusal), ADR-0032 (compensator authorised at `prepare`), ADR-0040 (approvals exhaustion ⇒ deny), ADR-0022 (E2), ADR-0024 (MUST-code/MUST-data), ADR-0026/0029 (append rules; chain), ADR-0045 (security metrics), ADR-0007 (T-LCD-04/-05/-07/-10/-12/-14); CF-WS-H1-01, CF-WS-H1-03; OQ-021, OQ-086, OQ-091, OQ-101, OQ-102, OQ-WS-H1-02/-05/-06; R-2.8.1

## Context

ADR-0035 fixed the seven-check minimal monitor set and assigned WS-H1 checks 1, 2, 4 (authority component), 5, 6, 7 at C0; ADR-0031 fixed the kernel decision's shape (`{effective_risk_class, allow | ask | deny, reason, cache_key?}`) and the monotone rule for risk inputs; it left open the policy table Π (OQ-101), the precedence of risk-assessment sources and the default for an unparseable command (OQ-086), and how unattended runs configure `ask`. The audit found three deterministic decision functions in source — CaMeL's `check_policy` (`security_policy.py` L77–96: exemption → dependency deny → ordered policies → default deny), Fides' `policy(trace)` before every action (`Tutorial.ipynb` cell 29), Codex's `assess_patch_safety` (`safety.rs` L29–85: pure, three-valued, containment-based, with a hard-link caveat) — and one defeated family: risk-only confirmation keyed on a model-supplied value (OpenHands `confirmation_policy.py`, `agent.py` L1068–1092; S-104 13/13 with automatic review on). Anderson's three reference-monitor properties (S-WS-H1-01) have never been expressed as checkable invariants over an agent runtime's log; HarnessHarness's append-only ledger (ADR-0026/0030) makes that possible.

## Options considered

1. **Risk-threshold confirmation with model-supplied risk (OpenHands `ConfirmRisky`).** *Rejected:* defeated 13/13 (S-104); the model's self-report is the attacker's channel.
2. **Per-tool hand-written policies (CaMeL suites).** *Rejected:* unreviewable at scale; the audit found an inverted predicate (`workspace.py` L119–130); ADR-0035 keys Π on `EffectClass`.
3. **Command-prefix/host allow-lists only (Codex `execpolicy`).** *Rejected as sole basis:* no authority axis, no taint; retained as the `ResourcePattern`/classifier layer inside step 3.
4. **A model reviewer that decides (Codex Guardian; Anthropic auto mode).** *Rejected:* a `delegate`-origin decider cannot confer (ADR-0035 rule 1); retained as a raise-only input (ADR WS-H1-adr-3).
5. **Stateful temporal admission control as the primary engine (S-WS-H1-07).** *Rejected for C0:* `provisional`, single author; count/time constraints on grants and `HarnessRule`s cover the C0 need (OQ-WS-H1-05).
6. **An ordered, pure, deny-by-default composition of the seven checks with a domain-keyed policy table as MUST-data, raise-only risk inputs with `unknown ⇒ irreversible`, an explicit unattended mode, decision replay from recorded inputs, and complete mediation enforced at append (chosen).**

## Decision

1. **Signature.** `authorize(p: Proposal, at: Seq) → KernelDecision` with `Proposal` from `action.effect.intended` plus `args_provenance` and `self_report?`, and `KernelDecision = {effect_id, decision ∈ {allow, ask{options}, deny{reason: DenyReason}}, effective_authority, taint, effective_risk_class, handle_ids[], policy_ref: VersionedRef<PolicyTable>, checks[], assessment_inputs_ref, cache_key?, decider ∈ {policy, cache, human, pre_authorization}}` — ADR-0031's shape extended (CF-WS-H1-03). `DenyReason` is a closed sum: `MissingProvenance, UnmappedArgument, UnknownProposer, NoCoveringGrant, GrantConstraintExhausted, HandleRevoked, PolicyDenied, ScopeCeilingExceeded, AuthorityWidening, NotDelegable, BudgetExceedsParent, ApprovalsExhausted, UnattendedAsk, ApprovalTimedOut`.
2. **Order (short-circuit on first deny; every step a pure function over records; no model call and no `Text` read on this path):** (0) well-formedness — registered proposer, open model call, every argument through `SurfaceArgMap`, provenance present; (1) *authority of proposal* — `eff = min(authority(proposer), context_label.authority)`, `taint = taint(context_label) ∪ taint(args)`; nothing on this path raises a class; (2) *grant coverage and handle validity* — covering handles by domain + scope over canonical parameters, attributes narrowing, count/time constraints; (3) *effect risk class* — `max_by_danger(kernel_assessed, projected(declared))` with the precedence in decision 4; (4) *taint gate* — if `eff ≤ external ∨ taint ≠ ∅` and not (`read_only ∧ closed`), `Π(domain, effective_risk_class, eff, mode) → allow | ask | deny`; (5) *persistence ceiling* for `memory_write`/`fs_write` with a scope (ADR-0035 table); (6) *delegation attenuation* for `spawn_process`/`Delegate` (ADR WS-H1-adr-3); (7) *approval feasibility* — `ask` requires approvals-budget reservation (ADR-0040; exhaustion ⇒ `deny{ApprovalsExhausted}`); in `unattended` mode `ask ⇒ deny{UnattendedAsk}` unless a pre-authorization handle covers the effect (`decider = pre_authorization`); (8) *cache* — an H7-declared canonical action pattern with a live `approval` handle resolves `ask → allow` with `decider = cache` and the originating `permission_id`; never keyed on `effect_id`; never for `irreversible` without a declared pattern. Check 5 of ADR-0035 (endorsement legitimacy) runs at append time on `security.label.*` events, not on proposals.
3. **Outputs.** `allow → action.effect.authorized`; `deny → action.effect.refused{reason, decider}` plus a refusal `Observation{source = validator, authority = kernel}` whose text is a profile-rendered enum, never monitor-authored prose; `ask → security.permission.requested{effect_id, args_canonical_hash, options ⊆ {allow_once, allow_pattern, reject_once, reject_always}, deadline}` resolved only by an `approval` endorsement naming `(effect_id, args_canonical_hash)`; timeout is a refusal. Every decision appends `security.permission.decided` with the full record; `assessment_inputs_ref` stores the assessor inputs (resolved paths, parse tree class, host class) so the decision is **replayable**: `authorize(p, at)` recomputed from recorded inputs equals the stored decision.
4. **Risk-assessment precedence (answers OQ-086).** `kernel_assessed` is the max over, in order: (i) static `EffectAttributes` of the capability; (ii) deterministic argument analysis — path canonicalisation with symlink/hard-link resolution then writable-root containment (Codex `safety.rs` L66–69; S-053), command classification by a **closed-grammar parser** into declared command classes, host/egress classification by H4's policy; (iii) H5-admitted deterministic hooks — raise or deny only; (iv) model self-report — raise only. **Unparseable or partially parseable ⇒ `unknown ⇒ {irreversible, non_idempotent, external}`.** Untrusted server hints never lower (S-153). `reversible` additionally requires `baseline_ref` at `prepare` (ADR-0030) or degrades.
5. **Policy table Π (answers OQ-101).** `PolicyTable = {version_id, mode ∈ {attended, unattended}, rows: [{domain, risk_pattern, eff_range, taint_required?, decision}], default: deny, conditioned_on?, assumption_debt?}` — a MUST-data artifact of the sealed definition at `definition` authority, interpreted by MUST-code; a model-conditioned row is a conditioned rule requiring an assumption-debt record (T-LCD-05). **Default rows for tainted/external proposals** (after the `read_only ∧ closed` exemption): `fs_read` allow / ask(external) / ask(irreversible); `fs_write` allow inside writable roots, ask outside / ask / ask; `exec` allow inside sandbox with network restricted, ask otherwise / ask / ask; `net_egress` ask (allow only for hosts in the definition's allowlist) / ask / ask; `secret_access` ask / ask / deny; `spend` ask / ask / deny; `message_human` ask (allow when the sole recipient is the run's principal) / ask / ask; `spawn_process` allow iff attenuation holds / ask / ask; `memory_write` allow ≤ `run`, ask at `session`, deny above; `permission_request` ask / ask / ask — **never allow**; `model_call` allow (budget-gated). **Unattended override:** every `ask` above becomes `deny` except `spawn_process` (allow iff attenuation) and rows covered by a pre-authorization handle; `net_egress` deny unless a pre-authorized host set; `message_human` deny except to the principal. **Untainted `eff ≥ principal` proposals:** allow for every class except `irreversible ∧ external`, `secret_access`, `spend`, `permission_request` (ask) — ADR-0031's floor. `unknown` class always takes the `irreversible` column. Policy may narrow any cell; a change that moves any cell toward `allow` is `authority_delta = widening` on the definition diff (ADR-0017) and follows its rules.
6. **Complete mediation as an append rule.** For every `effect_id`, the ledger refuses `action.effect.committed` unless a `security.permission.decided{decision = allow}` for that `effect_id` and attempt cycle precedes it in `seq`; exactly one `decided` per attempt cycle; `audit_completeness` (ADR-0043) includes this predicate. This is Anderson's "always invoked" as a durable-log invariant.
7. **Monotonicity.** Adding information (taint, self-report, hook verdict, judge verdict, budget exhaustion) can only move a decision toward `deny`; removing a covering handle can only move toward `deny`; the only moves toward `allow` are an `approval` endorsement of this `effect_id`, a live pattern cache, or a `definition` pre-authorization — each a record with an endorser of sufficient class.
8. **Context label ownership (CF-WS-H1-01).** `context_label` used in step 1 is stamped by the kernel over the delivered-item list from which the kernel itself renders the model call; a context-builder variant supplies the list, never the label.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-12 (pure operations over records; out-of-process implementable), T-LCD-14 (approvals reserved from a budget; Π variants compared under matched budget — AT-H1-15), T-LCD-10 (decides on canonical parameters; renames change nothing), T-LCD-04 (the kernel sits below lowering; invariants identical across targets), T-LCD-05 (conditioned Π rows need debt records), T-LCD-07 (`unknown` never coerced), T-LCD-13 (decisions are separately observable events). Does not itself satisfy T-LCD-11 — mitigated by ADR-0021 loss reports. Rung on the ADR-0024 ladder: `authorize`, assessors and the Π interpreter are MUST-code; Π rows, allowlists and pre-authorizations are MUST-data.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** complete mediation, tamper-resistance, verifiability — Anderson (S-WS-H1-01, Tier A); fail-safe defaults, least privilege, economy of mechanism — Saltzer & Schroeder (S-WS-H1-02, Tier A); user-level reference monitor with declassification at endpoints — Flume (S-219); default-deny policy at the tool boundary, no-side-effect exemption, deny on private dependencies — CaMeL (S-099, source); policy over the labeled trace before every action, `current_label` join — Fides (S-101, source); deterministic containment-based safety with a three-valued result and the hard-link caveat — Codex (S-107, source); `unknown` incomparable to concrete risk levels, max-severity fusion, structural rails — OpenHands (S-110, source); annotations are hints — MCP (S-153); risk-only confirmation defeated 13/13 with automatic review — S-104 (`provisional (mech)`, corroborated by the OpenHands source path of the model-supplied risk); ~93% approvals and classifier miss rate — S-053 (Tier B); the seven checks and Π's ownership — ADR-0035; risk class and monotone consumption — ADR-0031; approvals exhaustion ⇒ deny — ADR-0040.
- **(b) Source-code precedent:** `camel-prompt-injection/src/camel/security_policy.py` L77–96 + `interpreter/interpreter.py` L2047–2065; `fides/Tutorial.ipynb` cell 29 (`self.policy(trace)` before dispatch), cells 33–36; `codex/codex-rs/core/src/safety.rs` L17–85; `codex/codex-rs/execpolicy/src/{decision.rs (Allow | Prompt | Forbidden), policy.rs L225–265 (check with heuristics fallback)}`; `codex/codex-rs/protocol/src/protocol.rs` L988–1130 (`AskForApproval::Never` — the unattended precedent; `GranularApprovalConfig` per-channel switches); `codex/codex-rs/core/src/tools/sandboxing.rs` L70–111 (`with_cached_approval`); `software-agent-sdk/openhands-sdk/openhands/sdk/security/{risk.py L8–24, confirmation_policy.py L43–61, ensemble.py L78–101, defense_in_depth/policy_rails.py}`; `agent/agent.py` L1068–1092. Complete mediation as a ledger append rule, decision replay from recorded assessor inputs, and the domain-keyed Π with an unattended mode are **`no-precedent / novel`** as an integrated contract.
- **(c) Disconfirming evidence considered:** deterministic command classification is heuristic in every production system (Codex `heuristics_fallback`; OpenHands rails) — accepted; the design is honest by defaulting to `unknown ⇒ irreversible`, and the volume cost is measured (AT-H1-15; OQ-WS-H1-02); per-effect-class policy loses per-program precision users want (`execpolicy` prefix rules) — absorbed by `ResourcePattern` scope and command classes inside step 3; stateful/temporal attacks compose valid requests (S-WS-H1-07, `provisional`) — count/time constraints on grants and `HarnessRule`s cover C0, a temporal engine is C2 (OQ-WS-H1-05); decision replay stores one blob per decision — accepted cost of auditability; a pure-function monitor adds per-proposal latency — record comparisons over small sets (CaMeL's constant-time note), measured under OQ-WS-H1-06. None overturns.
- **(d) Conditionality:** independent of model tier and task class. Assumes a sandbox with declared writable roots (ADR-0031 (d)) so `reversible` is common; assumes H4 supplies a host classifier and H5 a hook admission list; assumes a reachable principal in `attended` mode; the Π floor is a floor — a benchmark run may pre-authorize `compensable` inside the sandbox, a production deployment may not; utility cost is a Stage 3 measurement, not an assumption.
- **(e) Build-stage assignment:** **C0 / Stage 1** (steps 0–3 and 6, Π interpreter and default table both modes, complete-mediation append rule, assessors (i)–(ii), static AT-H1-10/-11); **C0 / Stage 2** (steps 5, 7–8; approval channel; decision replay; `assessment_inputs_ref`); **C0 / Stage 3** (AT-H1-01…-03, -06…-09, -12…-15 executable; Π experiments under matched budget); **C1 / Stage 4** (step 6 with subagents/hosted); **C2** (ADR-0035 check 3 and the taint component of step 4 — WS-H2; temporal policies).

## Consequences

- WS-B1 extends `security.permission.decided` (CF-WS-H1-03) and adds the committed-requires-decided append rule; WS-H6 includes it in `audit_completeness`.
- WS-D1 returns the delivered-item list; the kernel stamps `context_label` (CF-WS-H1-01).
- WS-E1 declares command classes and parameter domains the assessors classify into; WS-H4 supplies the host classifier and writable-root policy; WS-H5 admits hooks as raise-only inputs (CF-WS-H1-04).
- WS-H7 narrows Π from the floor, owns `ask` options, deadlines, the canonical-pattern cache (OQ-091) and fatigue metrics; WS-I2 registers the security `MetricDeclaration`s; WS-F2 keys retries on `effective_risk_class` and never redispatches after `deny`.
- WS-B2's `KernelDecision` gains `effective_authority`, `handle_ids[]`, `policy_ref`, `checks[]`, `assessment_inputs_ref`, `decider` — an extension, not a change.

## Reversibility

**Medium.** Π rows and precedence are data/ADR-changeable; the check order and the deny-by-default, monotone, no-model-call properties are what the adversarial battery encodes — relaxing any after Stage 2 reopens AT-H1-01/-02/-05 and should be treated as constitutional with ADR-0035.
