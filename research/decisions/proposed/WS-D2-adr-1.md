# ADR-NNNN — Compaction is one component class over a closed operation sum: the `assess / propose / execute / declare` contract, hard/soft requirements, kernel invariants, and a fallback ladder ending in the C0 `evict_oldest` compactor

**Status:** proposed
**Owner workstream(s):** WS-D2 (consumers: WS-D1, WS-F1, WS-F2, WS-B1, WS-C1, WS-C3, WS-J2, WS-J3, WS-J6) · **Phase:** 2 · **Related:** ADR-0016 (`DecisionPoint.compact`, `HarnessRule.action = set compaction policy`), ADR-0023 (`ClassRecord`, `ordered-many`), ADR-0024 (ladder), ADR-0026 (history never rewritten; compaction is an appended event), ADR-0028 (`deterministic_replay`), ADR-0029 (blobs), ADR-0034 (P1/P3), ADR-0039/0040 (charges; gauge cap `CompactionRequired`), ADR-0042/0043 (compaction span), WS-D1 ADR-1/-2 (proposed: `ContextPlan`, `legal_cut_points`, `OffloadHandle`, kernel omission item); CF-WS-D2-02/-03/-04/-05/-06; OQ-073, OQ-WS-D1-02, OQ-WS-D2-01/-04/-07; R-2.4.2, R-2.4.1, R-2.10.2

## Context

Doc 3 §1.3 names compaction as the worked example of "every subsystem ships behind a stable contract before its rich variant is built": a trivial compactor in the Core, the family as an extension. Doc 2 §5.1 and §6 rate context policy a high-confidence lever whose specific recipes go stale by model. WS-D1 fixed the builder and raises `CompactionRequired` when the required set plus reservations exceeds the window cap (ADR-0040 E5: a gauge cap refuses the next increment rather than stopping the run); it exports `legal_cut_points` and an offload contract. Nine audited codebases (Codex, Pi, OpenHands, opencode, gemini-cli, goose, Inspect, Harbor, Claude Agent SDK; WS-D2 §3) ship compaction as compositions of four primitives — evict, offload, summarise, restructure — behind one lifecycle, with typed triggers, typed failures and a fallback ladder; none types the primitives, records the proposal, or exposes the family to a comparison instrument. The Lab needs two variants' effects to be comparable at component granularity (T-LCD-09) under matched budgets (T-LCD-14).

## Options considered

1. **One `compact(view) → view'` hook per variant (OpenHands `condense`, Pi `transformContext`, gemini processors).** Rejected: a whole-view return hides illegal cuts and authority laundering (WS-D2 F2/F3), gives the monitor nothing to read, and makes variants comparable only by end state.
2. **Four component classes (summariser, offloader, evictor, restructurer) each with its own contract.** Rejected: every real strategy composes the four (WS-D2 F1: Pi = summarise + restructure + evict + retain; gemini = offload → summarise → verify); four classes would force cross-class coupling the DAG forbids and quadruple the Lab's factor space without adding a real degree of freedom.
3. **Compaction as part of the context builder (D1) rather than a separate class.** Rejected: D1 decides what fits per call and is `exactly-one`; compaction is a decision point (`compact` ∈ Δ) that may call a model, needs a pipeline (`ordered-many`), a fallback ladder and its own events; folding it into D1 would make the C0 builder depend on a summariser.
4. **One class, a closed operation sum, an `assess/propose/execute/declare` contract with kernel invariants and a kernel fallback ladder ending in a deterministic C0 evictor (chosen).**

## Decision

1. **Class.** `compaction_strategy` is a registered component class (`ClassRecord{class_id: compaction_strategy, cardinality: ordered-many, required_inputs ⊇ {ModelProfile, ResourceAccount}, hot_path: false}`). An `ordered-many` binding is a pipeline: the kernel evaluates `assess` once, then calls `propose` on elements in order and applies the **first proposal that satisfies the requirement**; the firing `pipeline_index` is recorded (OQ-073 answered for this class; pipeline semantics beyond first-satisfying are OQ-WS-D2-01).
2. **Operations.** `assess(AssessInput) → Assessment{requirement ∈ {none, soft, hard}, reasons[], target_reclaim, min_reclaim}`; `propose(ProposeInput) → CompactionProposal{proposal_id, ops: [CompactionOp], expected_reclaim, requires_model_call, summarizer_profile?, max_summary_tokens?, fallback: [CompactionOp]}`; `execute(proposal, account, gateway?) → CompactionRecord`; `declare() → VariantDeclaration{variant_id, op_kinds, deterministic, control_boundary_compact ∈ {code, model}, capabilities{incremental_summary, split_turn, hard_reset, handles_requests, reactive_overflow}, model_conditioned_rules[with AssumptionDebtRecord], required_inputs, fallback_variant?}`. `assess` and `propose` are pure; only `execute` may call a model, and only through the gateway as an ordinary `model.call.*`.
3. **Operation sum (closed per dialect; `ext` registered with a declared deriver and consumed set).** `Evict{item_ids[], placeholder ∈ {kernel_omission, none}}` · `Offload{item_ids[], handle: OffloadHandle, excerpt_policy}` · `Summarize{input_ids[], schema_ref?, insert_at, previous_summary_ref?, instructions_ref: Ref<Text>}` · `Restructure{input_ids[], schema_ref, extractor ∈ {deterministic{projection_ref}, model{instructions_ref}}, outputs: [ContextItem]}`. Every op names the items it consumes.
4. **Triggers.** `CompactionTrigger = {occupancy_hard, occupancy_soft{rule_id}, overflow_reactive{error_ref}, request_principal, request_model{tool_call_id}, schedule{rule_id}, relower{dropped_items[]}}` (closed). `occupancy_hard` is the kernel gauge cap (`CompactionRequired`, ADR-0040 E5); `overflow_reactive` and `request_*` are `hard`; `occupancy_soft` and `schedule` are `soft` and exist only as conditioned rules (`HarnessRule{action: set compaction policy}` or `ProfileRule{compaction_reminder}`) with assumption-debt records (T-LCD-05). At C0 there are no soft rules (CF-WS-D2-03 resolution).
5. **Kernel invariants (errors, never warnings).** I-CUT (op boundaries ∈ D1 `legal_cut_points`; the post-compaction plan satisfies I-PAIR/I-ATOM); I-REQ (no op consumes a `required` item; the most recent principal message and every `kernel`/`definition` item are `required`); I-NOWIDEN (no op sets `authority`, `validity`, `readers`, `retention`; output labels per ADR-NNNN+1); I-LEDGER (the ledger is untouched — `context.compaction.started` precedes any model call; `context.compaction.completed{forgotten, applied_ops[], artifact/handle refs, status}` is the only durable effect; the compacted view is `project(run, context_view)` interpreting it); I-RECLAIM (`tokens_after ≤ tokens_before − min_reclaim` else `status = ineffective` and the proposal is discarded); I-LABEL (the context label is recomputed by the next `assemble`; the record states `context_label_after`); I-BUDGET (`execute` reserves the summariser call; `InsufficientBudget ⇒ BudgetRefused ⇒ fallback`; soft thresholds re-arm only after `context.compaction.completed` — CF-WS-D2-06); I-DET (`assess`/`propose` pure; a `deterministic` variant never requires a model call and is admissible under `deterministic_replay`, ADR-0028); I-FALLBACK (on `hard`: variant failure or ineffectiveness ⇒ `proposal.fallback` ⇒ `fallback_variant` ⇒ C0 `evict_oldest` ⇒ `CompactionImpossible` to F2 with `stop_reason = context_exhausted`, CF-WS-D2-05; on `soft`: return the view unchanged, record the failure).
6. **Failure sum.** `CompactionImpossible, CompactionIneffective, SummarizerOverflow` (handled by a declared, recorded `InputReduction ∈ {trim_oldest, drop_tool_results_middle_out{percent}, shrink_strings{factor}}`), `SummarizationFailed{reason ∈ {error, empty, aborted}}, IllegalCut, PolicyViolation{required_item | authority | retention}, BudgetRefused, Aborted{principal | hook | cancel}, UnresolvedSummarizer`.
7. **C0 trivial compactor `evict_oldest`.** `deterministic = true`, `op_kinds = {evict, offload}`, no model call: on a `hard` requirement, walk `optional` items oldest-first in kernel `PriorityClass` order `image → observation_old → commentary → procedure_body → memory → observation_recent → transcript_tail` (OQ-WS-D1-02 answered: the kernel set suffices; `ext` classes declare a total order per variant); emit `Offload` where a handle already exists, else `Evict{kernel_omission}` (one omission item per contiguous range, `kernel` authority); stop at the first legal cut at or after `occupancy ≤ window_cap × target_fraction` (default 0.5; OQ-WS-D2-07). It is the Stage-2 default and the universal last rung.
8. **Events and accounting.** `context.compaction.started{trigger, requirement, strategy_variant_ref, pipeline_index, proposal_id, occupancy_before}`; `context.compaction.completed{compaction_id, proposal_id, applied_ops[{kind, consumed_ids, artifact_refs, handle_refs, model_call_ids}], forgotten, tokens_before, tokens_after, occupancy_after, context_label_after, status, input_reduction_applied?, fallback_step?, summariser_usage?, duration_ms{measured_at}}` (payload extension of WS-B1's rows, CF-WS-D2-02; envelope unchanged; `scope_kind = compaction` span per ADR-0042). Summariser calls are `model_call`s charged `subject` with attribution class `harness_overhead.compaction` (ADR-0039 R-ACC-3, ADR-0044 cost view); provider-side compaction iterations post their own charge.
9. **Hosted participants.** No IR field is added for hosting. Where a hosted mechanism emits a compaction marker (Inspect `CompactionEvent{summary | edit | trim}`, Claude Code `compact_boundary`), J6 lifts it into `context.compaction.completed{applied_ops[{kind}], tokens_before/after}` with `origin = participant`, `authority = unverified`; component-level compaction metrics are `n/a{reason: class}` (T-LCD-15).

The closed op sum with a recorded proposal, kernel invariants and a kernel fallback ladder is `no-precedent / novel` as an integrated contract; every element is precedented as listed.
- (c) Disconfirming evidence considered: whole-view hooks are simpler and shipped by three systems (answered: they are where illegal cuts and laundering live; the op record is what the monitor and the Lab need); "eviction without summary destroys progress" (answered: every system ships eviction as floor or fallback; its inadequacy is the canonical experiment's H1, not a reason to make a model call Core); folds/graph rewrites may need ops nobody typed (answered: `ext` ops with a declared deriver and consumed set; a fold is `Summarize + Evict`); summary volume is not prompt-controllable (S-WS-D2-07, `provisional` — answered by structural controls: `max_summary_tokens`, I-RECLAIM, schema-typed `Restructure`). None overturns.
- (d) Conditionality: the contract assumes a provider whose context limit is declared in the profile (`window_cap`) and a builder that exports cut points; it assumes nothing about model tier — the C0 evictor works for any model, and every model-conditioned behaviour is a parameter or conditioned rule (ADR-NNNN+1). - (e) Build-stage assignment: **C0 / Stage 1** (schemas, `ClassRecord`, event payloads; `CompactionRequired` handled as stop); **C0 / Stage 2** (`evict_oldest`, invariants, fallback rule, events, accounting; AC-D2-1…5, -7); **C0 / Stage 3** (first C1 variant `clear_tool_results` so a two-arm comparison runs evaluation-first); **C1 / Stage 5** (the family); **C2 / Stage 4** (hosted lift with J6).

Not applicable: T-LCD-01/-03/-04/-07/-09/-11/-14 (owned by ADR-NNNN+1/+2 and A4/C1). **Ladder rung (ADR-0024):** Core (contract, op sum, invariants — by this ADR); `evict_oldest` a registered variant; `target_fraction`/`min_reclaim` parameters.

## Consequences

- WS-D1's Stage-0/1 `ContextWindowExceeded → stop` becomes `→ CompactionRequired → evict_oldest` at Stage 2; D1 keeps exporting `legal_cut_points` and the kernel omission item.
- WS-F1 calls `assess`/`propose`/`execute` at `DecisionPoint = compact`; WS-F2 gains `stop_reason = context_exhausted` and re-arms soft thresholds on `context.compaction.completed`.
- WS-B1 extends the two `context.compaction.*` payloads; WS-I1's `compaction` span and `turn_phase_profile.compaction` bind to them.
- WS-C1 transports summariser requests as data and exposes provider compaction as a declared capability whose iteration usage is charged separately (OQ-WS-D2-05).
- WS-J2 registers the class; WS-J3 treats `compaction_strategy` as a component-level factor (ADR-NNNN+2).
- Every compaction is inspectable: proposal, ops, forgotten set, artifacts, cost and status are ledger data, so ablation and attribution (ADR-0002) apply to compaction like any other component.

## Reversibility

**Medium.** Adding an op kind or trigger is a dialect bump with migration; changing pipeline semantics (OQ-WS-D2-01) is a class-record edit; replacing the C0 evictor with a summarising default would make Stage 2 depend on a model call and break `deterministic_replay` admissibility — costly, requires a superseding ADR. The invariants are consequences of ratified ADRs and cannot be reversed here.
