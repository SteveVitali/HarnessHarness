# WS-E4-adr-3 — The ACP edge: a native harness as an ACP v2 agent with a v1 compatibility profile and an exhaustive event-class lowering table; permission transport; `_hh/*` extension methods; the Hosting ABI's session-ABI mechanism adopts ACP v2's stable core as its baseline

**Status:** proposed
**Owner workstream(s):** WS-E4 (consumers: WS-K4, WS-J6, WS-B1, WS-F1, WS-H1, WS-H7, WS-L2, WS-C3, WS-D2) · **Phase:** 2 · **Related:** ADR-0005 (act as a participant), ADR-0013 (total ABI projection; class declared), ADR-0018 (`OpaqueProcess`, tri-state record), ADR-0019 (`relower` on model switch), ADR-0021 (ACP session artefact C1/Stage 4), ADR-0026 (event classes declare their lowering), ADR-0027 (inclusive cursors; fork by reference), ADR-0030 (durable-before-visible; effect lifecycle), ADR-0035 (approval per `effect_id`), ADR-0039/0043 (`Money{micro_units}`; token roles), ADR-0007 (T-LCD-05/-07/-11/-15); CF-023, CF-027, CF-051, CF-073, CF-091; CF-WS-E4-02, CF-WS-E4-03; OQ-004, OQ-038, OQ-WS-E4-02, -06; R-2.5.4, R-2.11.4, R-2.10.6

## Context

ADR-0021 placed the ACP session artefact at C1/Stage 4 assuming "ACP v2 remains the served version". The audit finds every implementation on v1 (goose `ProtocolVersion::V1`; gemini-cli `session/set_mode`, `tool_call`; opencode `protocolVersion: 1`; Omnigent and OpenHands drive v1 methods), while the spec repository serves v2 (2.0.0-alpha.3) with removals: `session/load`, modes, `tool_call`, client `fs/*`/`terminal/*` (S-035 `migration.mdx`). ACP v2's stable surface is nine methods and seven update kinds; `steer`, `account`, subagents and model calls have no verbs (goose supplies `_goose/unstable/session/steer`; opencode/goose derive `usage_update` from per-message cost), and `fork`/`compaction_update` are unstable. CF-023 assumed a verb set including `steer` and `account`. ADR-0026 requires every ledger event class to declare its lowering to the Hosting-ABI vocabulary but no table exists yet. Hosting precedents diverge on permissions (Omnigent policy-first; OpenHands auto-approve) and on durability (no host sequences `idle` after persistence).

## Options considered

1. **Target ACP v2 only.** *Rejected:* no host can drive it today; the "act as a participant" obligation (ADR-0005, OQ-032) would be unmet at Stage 4.
2. **Target ACP v1 only.** *Rejected:* v1 is being retired; its client fs/terminal surface would pull environment execution to the client side, contradicting the environment boundary (WS-B5/E5) and the single-tool-channel rule (WS-E4-adr-1).
3. **Invent a HarnessHarness session RPC and bridge.** *Rejected:* N5; CF-023 fixed shape-sharing, not a new protocol.
4. **Chosen:** v2 artefact with a v1 compatibility profile (declared loss + assumption-debt record), an exhaustive event-class lowering table, permission transport bound to the reference monitor, a small `_hh/*` extension set with removal tests, and the Hosting ABI's session-ABI baseline defined as ACP v2's stable core with everything else capability-declared.

## Decision

1. **Artefact.** The compiler emits, from the sealed definition: `InitializeResponse{protocolVersion: 2, agentCapabilities{session{prompt, mcp, delete?, additionalDirectories?}, auth?, _meta{<hh-prefix>: {ledger_read, account, participant_describe, replay_cursor}}}, authMethods, info}`; `configOptions[]` from session-variable parameters (categories `model`, `mode`, `thought_level`, `model_config`) with mandatory defaults, a `model` change being `relower` + `model.surface.relowered`; and a **v1 compatibility profile** (`loadSession`, `session/set_mode`, `tool_call`, `current_mode_update`; no fs/terminal) whose `LoweringLossReport` lists the renamed/removed items and whose assumption-debt record's removal test is "no v1 host in the participant registry" (OQ-WS-E4-02 fixes the v2 pin).
2. **Event-class lowering table** (WS-E4 §6.2) is the concrete form of ADR-0026's obligation: `lifecycle.turn.started → state_update{running}`; `lifecycle.turn.finished{stop_reason} → state_update{idle, stopReason}` with the narrowing `budget_exhausted → max_tokens | max_turn_requests` by dimension, `refused → refusal`, `infrastructure_failure → _hh_infrastructure_failure`; `action.tool.proposed → tool_call_update{pending, kind}`; `action.effect.committing/observed → {in_progress}` (phase `unknown` rendered `in_progress` with `_meta.hh.phase`); `action.tool.completed/rejected → {completed | failed | cancelled}`; `context.observation.recorded → tool_call_update.content / tool_call_content_chunk`; `model.stream.delta → agent_message_chunk / agent_thought_chunk` (ephemeral); `control.decision{plan} → plan_update` (`hint_only`); `control.budget.consumed{tokens} + measurement.cost.attributed → usage_update{used, size, cost}` (`Money{micro_units}` → float declared in the telemetry loss report, CF-091); `security.permission.requested{decider: human} → session/request_permission`; `lifecycle.run.forked → session/fork` (unstable, declared); `context.compaction.* → compaction_update` (unstable, declared); every other class → `none`. `ToolKind` is the fixed projection of `EffectDomain` (`fs_read → read`; `fs_write → edit | delete | move`; `exec → execute`; `net_egress → fetch | search`; `model_call → think`; `spawn_process → _hh_delegate`; others → `other`). Every emitted update carries `_meta.hh.event_id`; `trace_map` is total over emitted updates; **`state_update{idle}` is emitted only after `lifecycle.turn.finished` is durable**.
3. **Permission transport.** Outbound: `session/request_permission{subject: tool_call | command, options: [allow_once, reject_once]}` is emitted iff `security.permission.requested{decider: human}`; `selected` → `security.permission.decided`; `cancelled` → `action.effect.refused`; nothing dispatches before `decided`. `allow_always`/`reject_always` are offered only when WS-H7 defines the ledgered policy amendment (OQ-WS-E4-06); until then the artefact omits them (goose's fallback to `allow_once` is the precedent). Inbound (hosting): a hosted agent's request is a proposal evaluated by Π first (`decider: policy`); a human is asked only on `ask`; adapter-level auto-approval is inadmissible.
4. **Tool supply through the edge.** `session/new.mcpServers[]` from a client is admitted into a native run only through WS-H5 `resolve → review → seal` (tools arrive `unverified`, default-deny) — never as a direct extension add; for hosted participants `OpaqueProcess.supplies.tools` lowers to `mcpServers[]` pointing at the Lab's sealed MCP surface (WS-E4-adr-1).
5. **Extension methods.** Exactly three at C1: `_hh/ledger/read{from_seq} → stream of ledger events (canonical bytes)`, `_hh/account → ResourceAccount`, `_hh/participant/describe → ParticipantDescriptor`; each carries an assumption-debt record and a removal test (T-LCD-05 reflexive); advertised in `agentCapabilities._meta`; unknown `_`-methods answered with JSON-RPC −32601.
6. **Hosting ABI baseline (for WS-J6).** The session-ABI mechanism's baseline is ACP v2's stable core: `initialize, session/new, session/resume{replayFrom}, session/prompt, session/cancel, session/close, session/request_permission, session/update{state_update, tool_call_update, tool_call_content_chunk, agent_message*, usage_update, config_option_update}` plus Lab-side probing. `steer`, `account` (exact), `fork`, `compaction`, `subagents`, `trajectory_export`, `instruction_delivery` (advisory budgets, CF-073) and every `configOptions` coordinate are **capability-declared**, default `unknown`; omitted wire capabilities re-map to `unknown` (CF-027). Session-ABI hosting yields `observability_level = {events, end_state}`; `model_io` requires interception (OQ-038); `usage_update` yields `CostProvenance = reported`. v1 hosts enter through the compatibility profile with `unknown` for every removed or renamed feature.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: v2 surface and removals (S-035 `schema/v2/schema.json` method/update unions; `migration.mdx` L42–72, L189–191, L557–627, L721–741); all-v1 population (S-112 `acp/server.rs` L3514; S-119 `acpRpcDispatcher.ts` L84, `acpSession.ts` L207–240; S-111 `acp/service.ts` L94–140; S-118 `acp_executor.py` L169; S-110 `acp_agent.py` L550–660); no steer/account verbs and vendor substitutes (S-112 `custom_requests.rs` L221; S-111 `acp/usage.ts` L86–115); prompt lifecycle and durability semantics (S-035 `prompt-lifecycle.mdx`: `session/prompt` returns on acceptance; completion via `state_update`); permission option semantics and host divergence (S-035 `tool-calls.mdx`; S-118 L775–950; S-110 L1579–1596; S-112 `acp/common.rs` L70–115); capability advertisement in `_meta` (S-112 `server.rs` L388–398; S-035 `extensibility.mdx`).
- (b) Source-code precedent: goose `crates/goose/src/acp/server.rs` L742–815 (usage/stop-reason lowering), L1526–1600 (tool request/response/permission bridging) @fae91d0; opencode `packages/opencode/src/acp/{event.ts L95–140, permission.ts L17–80, usage.ts L86–115, config-option.ts L31–115}` @9f8db11; gemini-cli `packages/cli/src/acp/acpUtils.ts` L202–222 (`toAcpToolKind`) @ed2ac40; omnigent `omnigent/inner/acp_executor.py` L775–950 (policy-first permission) @6a069da; software-agent-sdk `openhands-sdk/openhands/sdk/agent/acp_agent.py` L912–953 (usage provenance) and `clients/typescript/scripts/check-acp-drift.py` @3fc7b22. The exhaustive lowering table with loss classes, the durable-before-`idle` rule and the reflexive debt records on `_hh/*` are `no-precedent / novel`.
- (c) Disconfirming evidence considered: (i) v2 is alpha and may change again — answered: the pin is in the derivation key; the table is versioned with it; the compatibility profile mechanism handles the next major the same way. (ii) The lowering is lossy so "declared loss" may be trivial — answered: the granularity ceiling `configuration` is the product; component metrics on ACP-observed rows are `n/a` (T-LCD-15); loss classes are per class, not global. (iii) Zed-centric update kinds (`plan_update`, `available_commands_update`) are irrelevant to a lab — answered: they are `hint_only`/optional; omitting them is spec-conformant. (iv) Requiring durability before `idle` slows the edge — answered: it is the ledger's existing durable-before-visible invariant (ADR-0026) applied at the edge; the cost is one fsync per turn. None overturns.
- (d) Conditionality: assumes ACP v2 stabilises within Stage 4 (OQ-WS-E4-02); assumes WS-H7 defines approval persistence (until then no `allow_always`); assumes WS-B1 accepts `protocol_bindings` in the run manifest (WS-E4-adr-4); independent of model tier; S-166 adoption counts are `provisional (mech)` and not load-bearing.
- (e) Build-stage assignment: **C1 / Stage 4** decisions 1–5 (artefact + transport, CF-051 tier split confirmed); **C2 / Stage 4** decision 6's hosting adapter and probes (ADR-0010; WS-J6); v1 compatibility profile expires by its debt record.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-05 (reflexive debt records on the v1 profile and `_hh/*` methods), T-LCD-06 (the artefact is compiler output; no IR field for ACP), T-LCD-07 (baseline + declared capabilities; `unknown` never coerced), T-LCD-11 (exhaustive lowering with loss classes; `_meta.hh.event_id` makes lifting total for own exports), T-LCD-15 (`configuration` ceiling). Does not by itself satisfy T-LCD-03/-13. **ADR-0024 rung:** `render_session`, negotiation and permission transport are MUST-code; the lowering table, `configOptions`, capability advertisement and compatibility profile are MUST-data.

## Consequences

- WS-J6 inherits decision 6 as the session-ABI baseline and must publish the probe suite for the declared capabilities; WS-K4 implements the transport (stdio stable; Streamable HTTP when ACP stabilises it); WS-B1 records the lowering table per class in its amendment log; WS-L2 marks ACP-observed cost `reported`; WS-H7 answers OQ-WS-E4-06; WS-C3 owns which parameters are session-variable.
- CF-023's verb list is corrected: `steer` and `account` are declared capabilities, not baseline (CF-WS-E4-03).
- ADR-0021 (d) conditionality is amended to "ACP v2 pinned; v1 profile until its removal test passes" (CF-WS-E4-02).

## Reversibility

**High** for the extension-method set and the v1 profile (both expire by test); **medium** for the lowering table (changing a projection re-labels stored hosted rows' loss reports); **low** for durable-before-`idle` (an ADR-0026 invariant).
