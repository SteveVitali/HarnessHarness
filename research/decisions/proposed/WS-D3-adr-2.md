# ADR-NNNN — The retrieval contract: a closed query-kind sum (deterministic kinds at C0/C1, similarity at C2), the ADR-0034 filter order applied before a ranker component class that cannot widen, budgeted whole-item return with provenance and a retrieval report, a read-your-writes watermark, and retrieval events

**Status:** proposed
**Owner workstream(s):** WS-D3 (consumers: WS-D1, WS-D4, WS-D5, WS-E3, WS-H1, WS-H2, WS-B1, WS-I1, WS-I2, WS-J3, WS-L2, WS-C1) · **Phase:** 2 · **Related:** WS-D3 ADR-1; ADR-0034 (P5 retrieval order — implemented verbatim; P3 context label), ADR-0033 (label; `readers` carried at C0, enforced at C2), ADR-0035 (monitor reads records only), ADR-0037 (`resolve` modes; `StaleIndex`; revocation enforced in retrieval — AC-L4-7), ADR-0014 (three-valued `validity()`), ADR-0026/0027 (`project()` watermark; `seq`), ADR-0036 (embedder as `ModelSnapshotRecord`), ADR-0039/0040 (accounting; reserve-before-spend), ADR-0023/0025 (variant registration), ADR-0045/0046 (matched-budget arms), ADR-0007 (T-LCD-05/-08/-12/-13/-14/-15); CF-008, OQ-020, OQ-049; R-2.4.3, R-2.4.1, R-2.4.4, R-2.5.3

## Context

ADR-0034 P5 fixes that retrieval "applies, in this order and as part of the contract: validity → authority → readers → relevance" and names `NoAuthoritativeItems`; ADR-0037 S3 puts the revocation guard "in the resolver and in D4's retrieval, not in the model"; ADR-0048's stage note makes the order a C0 contract of D1/D3. What Phase 1 did not fix is the rest of the contract: which *kinds* of query exist, what a ranker is and what it may see, how a budget cuts the result, what the result carries so D1's admission and the Lab's compliance chain can consume it, how retrieval is ordered against concurrent memory writes, and what the ledger records. The WS-D3 audit found: every coding harness read in source retrieves with functions of the store's bytes alone — address, name, path/glob, upward/JIT directory discovery, substring/regex search (Codex `line.contains(query)`), structural graph ranking (Aider PageRank with budget fit), keyword/path triggers (OpenHands, Claude Code `paths:`) — corroborating S-166's "none retrieves code with vector embeddings … deterministic retrieval (ripgrep, tree-sitter, glob, auto-discovered Markdown context files)" (`provisional (mech)`) in five of its eleven systems; the embedding lineage (MemGPT archival search, Generative Agents' additive score, AIOS top-k cosine, Mem0, A-MEM) carries no validity or authority in the retrieval path, and AIOS injects the top-k at the system position; S-106 shows a visible-but-unenforced revocation label lets the revoked fact outrank its replacement; AIOS's write barrier shows read-your-writes across the memory boundary is a real hazard with a small ordering fix; no audited system records what retrieval *filtered out*.

## Options considered

1. **Relevance-first with a post-filter** (the AIOS/Mem0 shape). *Rejected* by ADR-0034 option 5 — the post-filter is the part every system skipped (S-106).
2. **Embedding similarity as the primary retrieval mechanism with metadata filters** (vector-DB pattern). *Rejected for C0/C1:* the embedder is a model whose identity is a claim (ADR-0036 F7), so results are neither reproducible across snapshots nor auditable; every audited coding harness avoided it; kept as a **C2 ranker variant** that scores already-filtered candidates.
3. **Per-layer retrieval APIs** (a memory API, a file API, a skill API). *Rejected:* the filter order would be implemented three times and bypassed once (dossier F4 negative results); D1 needs one candidate shape.
4. **Retrieval as a free-form policy hook returning items** (Pi `transformContext` shape). *Rejected:* it is where the assembly bug lives; the monitor could not read the record; nothing is ablatable.
5. **One `retrieve` operation with a closed query-kind sum, a fixed filter-then-rank pipeline where the ranker is a component variant that receives only filtered candidates and a kernel-fixed feature vocabulary, a budgeted whole-item cut, a typed result with provenance and a report, a watermark for read-your-writes, and retrieval events (chosen).**

## Decision

1. **`retrieve(request) → RetrievalResult | RetrievalError`** with `RetrievalRequest = {model_call_id, at: (run_id, seq), layers ⊆ {A, E, P, S}, query: RetrievalQuery, constraints: SlotConstraints, reader, budget{tokens, k}, ranker: RankerRef, profile, account, mode ∈ {execute, audit}}`.
2. **`RetrievalQuery`** is a closed sum per dialect with registered `ext`: `by_address`, `by_name`, `by_path_glob`, `by_run`, `lexical{terms, match_mode ∈ {any, all_same_line, all_within{n}}, context_lines, case_sensitive, normalized}`, `discover{path, direction ∈ {upward, jit_downward}, filenames, ceiling ∈ {workspace_root, git_root}}`, `trigger{message | path_touched | explicit}`, `structural{anchors, mentioned_idents}` (C1), `similarity{text, embedder: ProfileRef}` (C2). Every kind but `similarity` is a pure function of the store state at `at` and the request; `similarity` declares `deterministic = false`, its embedder must have a `ModelSnapshotRecord` (`EmbedderUnpinned` otherwise) and each embedding is a `model_call` effect reserved before spend (ADR-0040) and charged to the retrieving process.
3. **Pipeline, fixed:** `enumerate` → filter `validity(item, at) ∈ constraints.validity_required` (superseded, revoked, expired and `stale-by-dependency` excluded in `execute`; ADR-0037 S3/S4) → filter `authority ≥ slot_min_authority` → filter `reader ∈ readers` (carried C0, enforced C2) → `ranker.score(filtered, query, profile, account, params)` → stable cut by `(score desc, version_id)` while `Σ tokens ≤ budget.tokens ∧ count ≤ k` → return. `SlotConstraints` are copied from the target slot's declaration (WS-D1) and are inputs, never ranker outputs.
4. **Ranker = component class `retrieval_ranker`** (`score(...) → [(candidate_id, score: decimal_string, features)]`, `declare() → {variant_id, deterministic, features_used, required_inputs ⊇ {ModelProfile, ResourceAccount}, model_conditioned_rules with AssumptionDebtRecord}`) over a **kernel-fixed feature vocabulary** `{lexical_hits_meta, lexical_hits_body, recency_created, recency_last_read, read_count, importance, structural_rank, similarity, kind, scope}` (closed; registered `ext`). `authority`, `validity`, `readers` and `retention` are **not** features: a ranker cannot read or set them (R1/R2 in type form). C0 variant `deterministic_default` (exact address/name → path-glob order → lexical hits → recency; ties by `version_id`); C1 `lexical_weighted`, `structural_pagerank`, `recency_importance`; C2 `similarity_rerank`. A slot may declare `requires_deterministic_ranker`; a non-deterministic ranker there is `RankerNotDeterministic`.
5. **Result and report.** `RetrievedItem` = WS-D1 `Candidate` + `{layer, address, provenance, validity{state, check_ref}, rank_evidence{ranker_ref, score?, features}, handle?}`; `RetrievalReport = {request_hash, watermark, enumerated, filtered{validity, authority, readers}, ranked, returned, omitted_by_budget[], no_authoritative_items, ranker_ref, deterministic, cost}`. Over-budget items are omitted whole, never truncated. `no_authoritative_items = true` iff `enumerated > 0 ∧ returned = 0 ∧ filtered.authority > 0` — distinct from an empty enumeration (ADR-0034 `NoAuthoritativeItems`).
6. **Invariants R1–R9** (dossier §6.3): filters before rank and no re-admission; never widen (`label(item) = label(stored)`); determinism for deterministic rankers (two implementations agree on order and `request_hash`); **read-your-writes** — the store has applied every `context.memory.written` with `seq ≤ at` or fails `StaleStore{applied_seq, requested}` (never fail-open); budget; provenance on every item; closed world (every item has an identity — `by_run` ranges carry a content address); distinct empties; `audit` mode returns invalid items with status and never into an `execute` slot.
7. **Failure modes:** `StaleStore`, `UnknownLayer`, `InvalidQueryKind`, `RankerNotDeterministic`, `EmbedderUnpinned`, `BudgetExhausted`, `MissingProvenance`, `IndexUnavailable{view_kind}`. Errors, never warnings.
8. **Events:** new class `context.retrieval.completed{model_call_id, request_hash, query_kind, layers, watermark, report}` (P1, `durability = ledger`); `context.memory.read` extended with `{layer, delivery_id?, rank_evidence, validity{state, check_ref}}`; retrieval cost posts `control.budget.consumed` with `charged_to = subject` and a proposed `harness_overhead.retrieval` attribution class (CF-WS-D3-02/-03).
9. **D1 re-checks.** The builder re-applies I-ORDER at admission (WS-D1 ADR-1); this ADR's filters are the *first* application and the report is what makes a bypass visible (a policy that admits an item absent from any `context.retrieval.completed` report is auditable).

**T-LCD statement.** Satisfies T-LCD-08 (`retrieve` and rankers receive `(ModelProfile, ResourceAccount)`), T-LCD-12 (operations; out-of-process store and ranker), T-LCD-13 (items carry `delivery_id` on delivery; `context.memory.read` links retrieval to the chain), T-LCD-14 (retrieval and embedder cost accounted; AC-D3-10 is a matched-budget arm), T-LCD-15 (hosted participants emit no retrieval events ⇒ `n/a{observability}`), T-LCD-05 (ranker thresholds, weights and index budgets are conditioned rules with debt records), T-LCD-10 (rank evidence never keys on names; identity by `version_id`). Not applicable: T-LCD-01/-02 (D1 owns opacity)/-03/-04/-06/-07/-09/-11.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** revoked items outrank replacements when the filter is not in the contract — S-106 (`provisional (mech)`), corroborated by the source audit (no filter in AIOS/OpenHarness/Codex read paths); deterministic retrieval is what mature coding harnesses use — S-074/S-166 (`provisional (mech)`), corroborated by Codex `line.contains`, OpenHands triggers, gemini-cli discovery, Aider PageRank, Claude Code docs (S-WS-D3-05), all Tier B read in source or vendor docs; additive recency/importance/relevance ranking with a context-window cut — Generative Agents (S-017, 2023); tiered search (date/text for recall, cosine for archival) — MemGPT (S-016); heuristic weighted lexical ranking with usage and recency — OpenHarness (S-117); structural PageRank with budget fit — Aider (S-121); read-your-writes barrier by sequence number — AIOS (S-031); provider model identity is a claim, never an identity — ADR-0036 F7 (ratified); reserve-before-spend — ADR-0040 (ratified); validity deterministic where a stamp exists — S-077 (`provisional (mech)`), consumed via ADR-0014.
- **(b) Source-code precedent:** `codex/codex-rs/ext/memories/src/local/search.rs` L284–330 (`matched_query_flags`: `line.contains(query)`; `SearchComparison` case/normalization), `ext/memories/src/backend.rs` (`SearchMatchMode{Any, AllOnSameLine, AllWithinLines}`, `ReadMemoryRequest{line_offset, max_lines, max_tokens}`), `memories/read/src/usage.rs` (reads classified from shell commands) @0735c51; `software-agent-sdk/openhands-sdk/openhands/sdk/skills/trigger.py`, `skills/skill.py` L56–95, L164–176 @3fc7b22 (path globs, whole-token keywords); `gemini-cli/packages/core/src/utils/memoryDiscovery.ts` L458–570, `tools/jit-context.ts` @ed2ac40 (upward/JIT discovery under its `trustedRoots` configuration list); `aider/aider/repomap.py` L365–575, L629–708 @5dc9490 (`get_ranked_tags`, binary-search budget fit); `OpenHarness/src/openharness/memory/search.py` L15–71 @9b2efd7 (weighted lexical score); `AIOS/aios/memory/write_barrier.py` L1–70 @292d98f (barrier snapshot; fail-open rejected), `aios/memory/base.py` L255–328 + `context_injector.py` L46–51, L477 (the negative fixture). **`no-precedent / novel`** for: the closed query-kind sum spanning five layers; the ranker feature vocabulary that excludes authority/validity/readers by construction; `RetrievalReport` with filtered-out counts as a ledger event; `StaleStore` as a hard failure.
- **(c) Disconfirming evidence considered:** embedding memory systems report real gains (Mem0 +26 % LoCoMo, S-WS-D3-02; MemGPT DMR; A-MEM) and Cursor ships semantic search (S-050) — absorbed: similarity is a C2 ranker variant, expressible as a Lab arm under matched budget (AC-D3-10), never the filter; deterministic mutation cannot canonicalize (S-WS-D3-04, `provisional`) — that is the mutation plane (ADR-3), not recall; a hard `StaleStore` can block on a slow consolidation — the watermark is the local ledger `seq`, so the check is local and the envelope decides; the closed query sum may lack a kind a domain needs (browser/computer-use) — registered `ext` and dialect bump. None overturns.
- **(d) Conditionality:** independent of model tier for the contract; the *benefit* of each ranker is model- and task-conditioned and is measured, not assumed; assumes D1's slot declarations carry `min_authority`/`validity_required` (WS-D1 ADR-1/-3); assumes the ledger `seq` is available to the store (ADR-0027); `similarity` assumes C1 exposes embedder snapshots (OQ-WS-D3-04).
- **(e) Build-stage assignment:** **C0 / Stage 1** — `retrieve` with `by_address`/`by_name`/`by_path_glob`/`by_run`/`lexical`, authority filter, R2/R5/R6/R7, `deterministic_default`, events; **C0 / Stage 2** — validity and `StaleIndex` filters (AC-D3-1/-3), read-your-writes (AC-D3-4), `trigger`/`discover` kinds, report consumed by D1; **C0 / Stage 3** — two-implementation determinism (AC-D3-6), `structural_pagerank` as a Lab arm, T-LCD-13 memory chain; **C1 / Stage 5** — ranker family; **C2** — `similarity_rerank`, readers enforcement (H2), AC-D3-10.

## Consequences

- WS-D1 receives `RetrievedItem`s as candidates with `slot_hint` and `rank_evidence`, and gets the report for `opacity_dynamic`/omission metrics; the AIOS-shaped policy remains inexpressible (AC-D1-1).
- WS-D4 owns `validity()` for memories and the conflict-set semantics; this ADR only fixes where and in what order they are applied.
- WS-E3 may reuse `lexical`/`trigger` for tool-surface search; WS-D5 supplies procedure triggers.
- WS-B1 registers the new class and payload extensions; WS-I1/L2 add the `retrieval` overhead class; WS-J3 treats the ranker as a component-level factor.
- A Lab recipe "deterministic vs similarity ranker under matched budget on memory-dependent tasks" becomes a standard Stage 5 arm.

## Reversibility

**Low** for R1/R2/R9 and the ranker's feature exclusion (they are the S-106 defence and mirror ratified ADR-0034 P5); **medium** for the query-kind sum and feature vocabulary (dialect bump); **high** for individual ranker variants and the budget cut rule (registered variants; a truncating variant would need a D1 change).
