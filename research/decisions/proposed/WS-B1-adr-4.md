# ADR-NNNN — Canonical byte form for hashing, per-run hash chain, and payload offload above a class-declared threshold (answers OQ-041 for ledger events; co-owned with WS-A3 for IR documents, WS-H6 for attestation, WS-L4 for artifact identity)

**Status:** proposed
**Owner workstream(s):** WS-B1 (co-owners WS-A3, WS-H6, WS-L4; consumer WS-L1) · **Phase:** 1 · **Related:** ADR-0007 (T-LCD-10/-11), ADR-0009 (WS-L1 criteria C3/C6/C12); OQ-041, OQ-WS-B1-01, OQ-WS-B1-04, OQ-WS-A3-03, OQ-WS-A3-07; CF-WS-B1-02; R-2.2.1, R-2.8.6, R-2.12.1; WS-A3-adr-1, WS-B1-adr-1, WS-B1-adr-2

## Context

Three consumers need bytes that hash identically across implementations and ecosystems: content addressing of artifacts, configurations and context items (WS-L4, T-LCD-10), tamper evidence over the ledger (WS-H6, R-2.8.6 C0/Must), and the cross-boundary invariant that events on the wire equal events in the ledger (WS-L1 §6.5 I4). WS-L1 registered the question as OQ-041 and made it a ratification blocker (WS-A3 and WS-B1 must answer). WS-A3 §6.1 has answered for IR documents ("hash over a canonical form; JCS-class deterministic serialization"). Separately, doc 2 §11 requires that large artifacts stay out of the event stream, and every scaled system audited offloads payloads (WS-B1 §4a F6). No audited harness chains its log.

## Options considered

1. **No canonical form; hash the stored bytes as written.** *Rejected:* two implementations (or two versions of one) produce different bytes for the same event; hashes stop agreeing across the WS-L1 boundary and across ecosystems; compression or re-serialization breaks the chain.
2. **Mandate one wire/storage encoding (a specific canonical JSON, deterministic CBOR, or schema-compiled binary) for storage and hashing alike.** *Rejected at Phase 1:* it is an ecosystem-level choice that belongs to WS-L1 (naming it here would be a leak, RK-09); the ledger's requirement is only that a canonical form *exists* and is implementation-independent.
3. **Hash over a canonical form with declared properties; storage/wire encoding free (chosen).** Plus a per-run hash chain at Stage 1 and Merkle tree heads / attestation with WS-H6 at Stage 2.
4. **Inline all payloads; no offload.** *Rejected:* transcript becomes the database; reverse-scan reconstruction and streaming degrade with payload size; large blobs cannot be redacted without rewriting history.
5. **Offload everything to blobs; events carry only references.** *Rejected:* every read becomes two reads; small payloads (decisions, usage, ids) dominate and are needed inline for projections.

## Decision

1. **Canonical form (properties, not a named format):** a deterministic serialization of a JSON-model data tree — members sorted by code point, no insignificant whitespace, UTF-8, fixed string escaping, no Unicode normalization, no duplicate keys, integers of arbitrary precision without exponent, *decimal strings* for fractional values, no IEEE-754 doubles (answers OQ-WS-A3-07 jointly with WS-A3), explicit `null` vs absent distinction, byte strings as a declared encoding. Two independent implementations must agree byte-for-byte on a shared corpus (AC-6 of WS-A3 extended to events). The canonical-form version and hash algorithm are pinned in the run manifest (rotation per OQ-WS-A3-03 / OQ-WS-B1-04).
2. **What is hashed:** `hash = H(domain_tag_leaf ∥ canonical(envelope − {hash}) ∥ prev_hash)` per event, with RFC 6962-style domain separation (distinct leaf/node prefixes) so leaves and interior nodes can never collide; `ContentAddress = (hash_algorithm, digest, media_type, size)` for blobs, hashed over the raw bytes with a blob domain tag. The stored and wire encodings may differ from the canonical form as long as `canonicalize(decode(bytes))` reproduces it (CF-WS-B1-02 wording: "byte-identical *canonical* form").
3. **Per-run hash chain at C0/Stage 1:** every event carries `prev_hash`; `verify(run, from, to) → ok | Tampered(at_seq)` recomputes the chain; a forked run's first event anchors to `forked_from.source_head_hash`. **Audit checkpoints (`security.audit.checkpoint{seq_range, chain_hash, tree_head?, attestation_ref?}`) and inclusion/consistency proofs are WS-H6's at Stage 2**; B1 supplies the leaves.
4. **Redaction-safe hashing:** an event's hash covers the *content address* of any offloaded payload, not its bytes, so `redact` (tombstone event + blob deletion) leaves every chain verifiable; a `Missing` blob is distinguishable from a tampered one.
5. **Payload offload:** every event class declares an inline size threshold (default 64 KiB canonical; class-tunable — OQ-WS-B1-01); payloads above it are stored as blobs and referenced in `refs`; `model.call.requested.request_ref` / `completed.response_ref` (present iff `observability_level ⊇ model_io`), `context.observation.recorded` (inline ≤ threshold, else ref), `context.assembled.items` (OQ-WS-B1-05), compaction summaries, world-state snapshots and hosted native records are always references. Dedup is by address (same bytes → same address). Compression at rest must round-trip to identical canonical bytes.

**T-LCD statement.** Satisfies T-LCD-10 (content-addressed identity derived from canonical semantics; surfaces excluded by WS-A3's projection rule), T-LCD-11 (the canonical form carries typed extension slots (`_meta`-style) through lowering so lifted events re-canonicalize identically; loss is reported, never silent), T-LCD-12 (properties, not a library). Not applicable: the remaining tests.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** RFC 8785 JCS S-WS-A3-03 / S-WS-B1-04 (a canonical byte form makes hashing/signing implementation-independent; I-JSON number limits motivate the integer/decimal-string rule); RFC 6962 S-WS-B1-03 (domain-separated Merkle hashing; consistency proofs demonstrate append-only); doc 2 §11 (S-doc2: "store content-addressed artifact references instead"); Shepherd S-078 (`provisional`, mechanism: content-hashed CoW snapshots, fork cost independent of image size); Unison S-WS-A3-02 (content-addressed definitions, names as metadata) via WS-A3.
- **(b) Source-code precedent:** payload offload and outside-the-log state — Codex S-107 @0735c51 `codex-rs/history/src/lib.rs` (`CompactedItem{replacement_history, window_number, compaction_response_id}`), `rollout/src/compression.rs` (compression at rest), `rollout/src/reverse_jsonl_scanner.rs` (tail-first reads), `protocol/src/protocol.rs` `WorldStateItem{full, state}`; opencode S-111 @9f8db11 `packages/opencode/src/snapshot/index.ts` (workspace snapshots as git objects in a separate gitdir — content-addressed storage outside the log); OpenHands S-110 @3fc7b22 `openhands-sdk/openhands/sdk/event/condenser.py` (`Condensation{forgotten_event_ids, summary}` — the projection forgets, the log keeps); Logos S-073 (`provisional`: long tool results pruned in the projection only). Canonical form + hash chain over a harness ledger: `no-precedent / novel` among audited harnesses; the primitives are standards (RFC 6962/8785) and git object storage.
- **(c) Disconfirming evidence considered:** cost — every event is serialized canonically to hash and possibly again to store; JCS-class forms force big integers/decimals into strings; chains complicate forks and redaction; none of the five audited harnesses chains its log and all are widely used; Kiehl S-WS-B1-09 warns that ledger machinery rarely pays for itself. *Why it does not overturn:* R-2.8.6 makes tamper evidence C0/Must and WS-H6 cannot retrofit it cheaply; the hash is over the canonical form only, so the stored form stays free (WS-L1 decides); the fork anchor and redaction rule are specified here so the chain survives both; and the offload rule caps the per-event canonicalization cost at 64 KiB. The choice of *format* is deliberately deferred to WS-L1 (properties only), which is the mitigation for the "named-format" risk.
- **(d) Conditionality:** independent of model tier and task class; assumes hash-algorithm agility via manifest pinning (rotation is OQ-WS-B1-04/OQ-WS-A3-03); assumes a JSON-model data tree is expressive enough for every payload (binary payloads go to blobs, never inline). The 64 KiB default assumes coding-agent payload profiles and is tunable per class.
- **(e) Build-stage assignment:** C0 / Stage 1 (canonical form, `hash`/`prev_hash`, `verify`, blob store with dedup, offload thresholds, golden-corpus byte-equality test shared with WS-A3); C0 / Stage 2 (audit checkpoints, tree heads, attestation — WS-H6; redaction tombstones; compression at rest).

## Consequences

- One canonicalizer serves IR documents, events and context items; WS-A3 and WS-B1 share the golden corpus and the byte-equality acceptance test (two independent implementations).
- WS-L1 receives storage properties 4, 5, 8 and 9 (WS-B1 §6.6) as ratification inputs; a candidate ecosystem must provide arbitrary-precision integer handling and a deterministic serializer without a bespoke fork.
- WS-H6 designs inclusion/consistency proofs and attestation over the leaf hashes defined here; WS-I3 stores tree heads in bundles.
- WS-D1 and WS-I2 must tolerate `refs` in place of inline payloads (OQ-WS-B1-01, -05).
- Every event class schema declares its threshold and which fields may be offloaded; the readiness report lists them.

## Reversibility

**Low for the canonical-form rule** (changing number or ordering rules invalidates every stored hash; only manifest-pinned rotation with re-hashing migrates a corpus). **Medium for the chain** (can be recomputed if the canonical form is stable). **High for thresholds** (per-class constants).
