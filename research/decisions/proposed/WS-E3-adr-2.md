# WS-E3-adr-2 — The discovery capability and the `catalog_index` component class: one capability, two lowerings, an offline retrieval suite, and class-scoped selection metrics

**Status:** proposed
**Owner workstream(s):** WS-E3 (consumers: WS-E1, WS-E2, WS-E4, WS-C1, WS-C3, WS-D1, WS-I2, WS-J3/J4, WS-L2, WS-L6) · **Phase:** 2 · **Related:** WS-E3-adr-1; ADR-0016 (`ToolCapability`, `Text` leaves), ADR-0019 (closed world), ADR-0020 (`CapabilityDeclaration.{deferred_tools, tool_search}`; `tool_shape`/`naming`/`description_template` rules with debt records), ADR-0021 (provider tool-API target carries deferral flags; loss classes; lifting = `unverified`), ADR-0022 (E1–E7), ADR-0039/0043 (`tool_calls`, `model_calls`, cost provenance), ADR-0041/0045/0046/0047 (matched comparison, `MetricDeclaration`, judges as instrument); OQ-WS-E3-04/05/06; CF-WS-E3-01; R-2.5.3, R-2.3.3

## Context

Deferral only works if the model can find what it needs. Both vendors expose *search* as a tool with a model-conditioned query form — regex patterns (≤200 chars, `re.search` semantics) or natural language (≤500 chars) at Anthropic (S-WS-E3-01), hosted or client-executed `tool_search_call` at OpenAI (S-WS-E3-02) — over a fixed field set (names, descriptions, argument names and descriptions); codex executes a BM25 search in the kernel over a derived text (`codex-rs/tools/src/tool_search.rs` L87–150; `core/src/tools/handlers/tool_search.rs` L138–245) yet lowers it to the provider's native `tool_search` type when the model and provider support it (`tool_spec.rs` L27–33; `spec_plan.rs` L629–642). Cursor and goose's filesystem disclosure replace the search tool with files the model greps (S-050; `code_execution.rs` L585–605). Retrieval quality is the binding constraint: on ToolRet the best embedding model reaches nDCG@10 ≈ 34–43 and a weak retriever costs 11.4 pass-rate points downstream (S-WS-E3-03, Tier A); RAG-MCP reports precision decaying at thousands of tools (S-WS-E3-04, `provisional`). The pi issue #7709 shows the provider round-trip of a deferred call dropping `namespace` (S-WS-E3-09). Every reported lift is vendor or `provisional` and unmatched (dossier §4b). The contract must therefore make the index a measured, swappable component and make "deferral helps" a Lab result.

## Options considered

1. **Kernel magic: a built-in search the runtime injects, unnamed in the IR.** *Rejected:* violates the closed-world rule (a surface without compiled identity), T-LCD-10 (name = identity), T-LCD-13 (no delivery id), and T-LCD-01 (query form would be an `if model` branch in the kernel).
2. **Always use the provider's hosted search when available; no kernel index.** *Rejected:* opaque (no scores, unmetered cost, provider-set result ceilings), lossy at the boundary (S-WS-E3-09), unavailable for most models, and unusable as the Lab's reference variant.
3. **Always index-only disclosure (names visible, model expands by name), no search.** *Rejected as the only design:* it is the `indexed` mode (WS-E3-adr-1) and scales to hundreds, not thousands (S-WS-E3-01 "3–5 tools" out of 200+); fully `deferred` surfaces need search.
4. **A kernel-provided `ToolCapability` `discover_surfaces` with a profile-owned surface, answered by a registered `catalog_index` variant when kernel-executed and lowered to the provider's native search when the profile declares it, each lowering with equivalence evidence and a loss report; index variants ship an offline retrieval suite; selection metrics declared per ADR-0045 (chosen).**

## Decision

1. **The discovery capability.** `discover_surfaces` is a `ToolCapability` with `effects = pure` (kernel-state read; no `EffectDomain`), `input_schema = DiscoveryQuery{form ∈ {regex, natural_language, structured{namespace?, effect_filter?, tags?, source?}}, text, limit?}`, `output_schema = DiscoveryResult{hits[{surface_id, rank, score?}], truncated, executed_by, cost}` returning index forms only — never definitions. The resolver adds it to any sealed definition that admits `deferred`; it is `pinned` (`direct`) whenever a plan defers. Its surface (name, query form, description template, optional bounded source listing counted in the opacity report) is profile-owned via `tool_shape`/`naming`/`description_template` rules with assumption-debt records (T-LCD-01/-05).
2. **Two lowerings, one contract.** (a) *Kernel-executed* (C0 reference): a function surface whose handler calls `catalog_index.query`. (b) *Provider-hosted*: when `CapabilityDeclaration.tool_search` is `declared → probed` for the profile, the provider tool-API target emits the provider's native search tool and the catalog's deferred definitions with deferral flags; provider references are *lifted* to `surface_id`s with `score = n/a`, `executed_by = provider`, `cost.confidence = bounded` (search is unmetered, S-WS-E3-01); the `LoweringLossReport` declares `{score: no_slot, hidden_filter: narrowed (hidden/omitted definitions are withheld from the request), limit: narrowed (provider ceiling), namespace/deferral markers: round_trip_required}`, and the Stage-3 round-trip test replays a revealed deferred call through the target and back (T-LCD-11; the S-WS-E3-09 regression). `discovery_executor_preference ∈ {kernel, provider, provider_if_declared}` is policy data.
3. **Equivalence evidence** (ADR-0022) per lowering: E1 `pass` (pure), E2 `pass` (`SurfaceArgMap` total: `pattern | query → text`, `limit → limit`), E3 `narrowed` (length ceilings), E4 `n/a(kernel_state)`, E5/E6 `pass`, E7 `pass`.
4. **`catalog_index` component class.** Contract: `build(catalog, profile, account, params) → index_ref` (content-addressed; charged `instrument`), `query(index_ref, DiscoveryQuery, limit, profile, account) → DiscoveryResult` (charged `subject`), `deterministic: bool`, `search_text_fields ⊆ {name, name_split, description, param_names, param_descriptions, namespace_name, namespace_description, examples, effect_summary}` declared. Results are keyed by `surface_id` (T-LCD-10); `hidden` entries are never indexed; hits are bounded by `min(query.limit, max_reveal_per_search)` (default 8, codex precedent; ceiling 32 unless amended by ADR); an empty result is a normal result. Variants: **C0** `exact_name`, `static_allowlist`; **C1** `lexical_regex`, `bm25`, `hierarchical`; **C2** `embedding` (embedding model = instrument-charged `model_call` with its own `ProfileRef`; `deterministic` false unless the embedding artefact is content-pinned), `model_ranked` (a `Validator{kind: judge}`-class ranker under ADR-0047 governance), `filesystem` (catalog materialised as files; discovery becomes `fs_read` through declared capabilities and the discovery capability is absent).
5. **Offline retrieval suite.** Every variant ships `retrieval_eval(index_ref, labelled_queries[{query, required_surface_ids}]) → {recall@k, nDCG@k}` over Lab-labelled fixtures in the ToolRet shape; results are component-level metrics (native only, `charged_to = instrument`); the only gate is a pre-registered `recall@8` floor for exact-name queries (AC-E3-11).
6. **Lab metrics** are registered as `MetricDeclaration`s computed from ledger events (ADR-0044/0045): `tool_surface_tokens`, `catalog_exposure_ratio`, `discovery_calls/tokens/latency_ms`, `selection_recall@need`, `selection_precision`, `unrevealed_need`, `unrevealed_call_rate`, `first_call_success_after_reveal`, `reveal_to_use_distance`, `catalog_drift_events`, `index_recall@k`/`index_ndcg@k` (dossier §6.7), with `applies_to_classes` = native (hosted only where `model_io` observability lifts provider search items; otherwise `n/a{observability}`). `selection_recall@need`/`unrevealed_need` require a task oracle `required_surfaces[]` (OQ-WS-E3-05).
7. **Comparison shape.** Any "deferral/index X beats Y" is a `ComparisonReport{benefit_kind = artifact_benefit, budget_match.status}` between arms differing only in the `tool_exposure_policy`/`catalog_index` slots, matched (`matched_cap`) on `tokens`, `model_calls`, `tool_calls`, `time.wall_ms`, stratified by catalog size class `{≤10, 11–50, 51–200, >200}` and `executed_by`, with Pareto (tokens × `selection_recall@need` × task score) and tails reported.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: search as a model-facing tool with model-conditioned query forms and a fixed indexed field set (S-WS-E3-01; S-WS-E3-02; S-107); kernel-vs-provider execution of the same search (S-107 `tool_spec.rs` L27–33 + `handlers/tool_search.rs`; S-WS-E3-02 hosted vs client); filesystem catalogs as an alternative disclosure (S-050; S-112 `ToolDisclosure::Filesystem`); hierarchical routing (S-WS-E3-05 `provisional`, S-WS-E3-02 namespaces); retrieval quality as the binding constraint and its downstream cost (S-WS-E3-03, Tier A; S-WS-E3-04 `provisional`); retriever-in-the-loop as a 2023 mechanism whose payoff is trained-in (S-WS-E3-07, S-WS-E3-08); lowering loss at the provider boundary (S-WS-E3-09); MCP annotations are hints, so `effect_summary` in index forms is a projection, not authority (S-153 `schema.ts` L1904–1910; ADR-0021 decision 3).
- (b) Source-code precedent: `codex-rs/tools/src/tool_search.rs` L23–150 (index text and deferred re-emission), `codex-rs/core/src/tools/handlers/tool_search.rs` L138–245 (BM25 engine, `limit`, empty-query error), `codex-rs/tools/src/tool_discovery.rs` L6–7 (`TOOL_SEARCH_DEFAULT_LIMIT = 8`), `codex-rs/core/src/tools/handlers/tool_search_spec.rs` L8–62 (bounded source listing in the search tool's description), `codex-rs/tools/src/tool_spec.rs` L22–33 (native provider search type) (S-107 @0735c51); `crates/goose/src/agents/extension_manager.rs` L2602–2660 (`search_available_extensions`) and `platform_extensions/code_execution.rs` L585–630 (S-112 @fae91d0); `packages/opencode/src/tool/code-mode.ts` L37–60 (catalog grouped by server) (S-111 @9f8db11). The single capability with two lowerings, the loss report for provider-hosted search, and the mandatory offline retrieval suite are `no-precedent / novel`.
- (c) Disconfirming evidence considered: (i) a bad index is worse than no deferral (S-WS-E3-03 −11.4 pass-rate points; S-WS-E3-04 decay at scale) — answered: the index is a measured component with an offline suite and the Lab reports `unrevealed_need`; the C0 default remains `direct_all`; (ii) provider-hosted search may outperform any kernel index because the model was trained on it (S-WS-E3-02 "trained primarily on those surfaces") — answered: it is admitted as a lowering with declared loss and is stratified in comparisons, not banned; (iii) index-only disclosure plus grep needs no search tool (S-050) — answered: the `filesystem` variant and `indexed` mode admit it; (iv) vendor lifts (49 → 74 %, −46.9 %) are unmatched single-model numbers — answered: not load-bearing; the comparison shape in decision 7 is what would establish them. None overturns.
- (d) Conditionality: assumes ADR-0020's capability probes for `tool_search`/`deferred_tools`; kernel variants are independent of model tier; the *query form* and the benefit of search are model-conditioned and live in profile rules with expiry; `embedding`/`model_ranked` assume an instrument budget and ADR-0047 judge governance; no `provisional` result is load-bearing (ToolRet is Tier A).
- (e) Build-stage assignment: **C0 / Stage 1** (`discover_surfaces` capability schema; `exact_name`/`static_allowlist`; metric declarations); **C0 / Stage 3** (AC-E3-5/-6 executable: two-profile compile and provider round-trip; metric computation on fixtures); **C1 / Stage 2** (`lexical_regex`, `bm25`, `hierarchical`; retrieval suite); **C1 / Stage 5** (profile rules and probes); **C2** (`embedding`, `model_ranked`, `filesystem`).

**T-LCD statement (ADR-0007 decision 5).** Satisfies: T-LCD-01 (one capability, two profiles, divergence only in profile-owned fields), T-LCD-02 (description template and source listing are `Text` leaves in the opacity report), T-LCD-04 (kernel function surface and provider-hosted target from one definition), T-LCD-05 (query-form and naming rules carry debt records — owned by C3), T-LCD-08, T-LCD-10 (hits keyed by `surface_id`), T-LCD-11 (loss report + round trip), T-LCD-14/-15 (matched comparison; `n/a` for hosted). Does not by itself satisfy T-LCD-03.

## Consequences

- WS-C3 adds to ADR-0020's capability declaration the fields provider-hosted search needs (`tool_search_variants`, `max_deferred_tools`, `namespace_tools`, per-server deferral) — OQ-WS-E3-06 — and owns the query-form/naming rules.
- WS-E4/WS-C1: the provider request plan carries deferral flags and the lifted search items; the gateway owns transport only (CF-044).
- WS-L6 names the discovery capability's default surface names; WS-I2/J3 add `required_surfaces[]` to task fixtures.
- WS-E2 inherits `code_mode` disclosure and composite surfaces; WS-D5 may reuse the same machinery for `procedure_index` expansion.

## Reversibility

**High for variants and defaults** (registered components; `max_reveal_per_search` is data); **medium for the two-lowerings rule** (dropping provider-hosted search only removes a lowering; dropping the kernel reference removes the Lab's control arm); **low for "the discovery surface is a compiled `ToolCapability`"** (shared with the closed-world rule).
