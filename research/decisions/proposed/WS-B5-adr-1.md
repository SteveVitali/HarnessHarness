# WS-B5-adr-1 — The environment handle: harness-outside topology, one environment protocol over three backend placements (OQ-045 final, B5 half), environment classes, the kernel-owned handle record with its lifecycle state machine, and self-heal as ledgered replacement

**Status:** proposed
**Owner workstream(s):** WS-B5 (consumers: WS-B3, WS-B4, WS-E5, WS-H4, WS-H3, WS-H1, WS-F3, WS-G2, WS-I3, WS-I4, WS-J3, WS-J6, WS-K2/K4, WS-L2, WS-A3) · **Phase:** 2 · **Related:** ADR-0001/0005/0013 (participant classes; `container-installed` mechanism), ADR-0016 (`AgentProcess.native.environment: EnvironmentRef`), ADR-0024 (MUST-code/MUST-data), ADR-0026/0027 (durable-before-visible; allocated ids), ADR-0028 (environment reads reproducible from snapshots), ADR-0030/0031 (`env_handle` on effect events; `unknown{cause}`; downgrade rules), ADR-0035 (monitor reads records only), ADR-0040 (hard ceilings at decision points), ADR-0042 (`environment_op` scope), ADR-0049/0050 (OQ-045 provisional; helper layer; §8 language-use constraint), WS-E5-adr-1 (execution contract; helper protocol minimum; `on_kernel_loss`), WS-H4-adr-1/-3 (`containment` slot; `ContainmentReport`; fail-closed), WS-H3-adr-1/-2 (SV-4; `env_apply`); CF-WS-B5-01, CF-WS-B5-03, CF-WS-B5-04, CF-WS-B5-05, CF-WS-H4-01, CF-WS-E5-01; OQ-045, OQ-WS-B5-01, OQ-WS-B5-03, OQ-WS-B5-05; R-2.2.5, R-2.2.3, R-2.5.5, R-2.8.4

## Context

Doc 2 §11 requires "ephemeral sandbox/VM handles separate from harness process" and its canonical v2 additions separate the semantic control plane from execution workers that "own ephemeral filesystem/browser/shell state and expose effectful operations through narrow handles". Phase 1 ratified the pieces the handle must fit: the ledger outside the environment (ADR-0026), `env_handle` on every effect event and `unknown` on loss (ADR-0030), the monitor reading records only (ADR-0035), the helper provisionally out-of-process (ADR-0049). Phase 2 neighbours wrote the per-effect execution contract (WS-E5), the containment policy the handle must carry (WS-H4) and the credential discipline (WS-H3) before this workstream ran, and each pre-registered a conflict asking B5 to adopt or counter-propose. The source audit (dossier §4) found two production placements of the harness process — outside the environment (Managed Agents, Cursor, Codex exec-server) and inside it (OpenHands agent-server, Harbor container-installed agents) — and found that every scaled system separates a stable environment identity from a process-local session and heals by replacement from a recipe, not by repairing an instance.

## Options considered

1. **Harness-inside: run the reference runtime in the sandbox and expose a thin client** (OpenHands agent-server). *Rejected:* puts the ledger writer, permission decisions, broker values and gateway credential inside the blast radius, contradicting ADR-0026/0035 and WS-H3 SV-4; kept only as the hosted `container-installed` mechanism.
2. **No kernel lifecycle model: call each provider's API directly and record only an environment id string** (Codex cloud tasks `environment_id`; Symphony in-memory scheduler). *Rejected:* provider state models do not align, `env.*` accounting becomes incomparable across backends (T-LCD-09/-14), and the effect model cannot distinguish `unreachable` from `replaced` when deciding `probe` vs `unknown`.
3. **Repair-in-place self-heal** (restart processes, retry the container). *Rejected as the lifecycle rule:* "nursing failed containers back to health" is what Managed Agents removed; process repair remains E5's `terminate_detached` inside a healthy handle, not a handle transition.
4. **A single fixed backend (containers only).** *Rejected:* the Lab must compare the same harness on a host sandbox, a container and a provider platform; the environment is an experimental factor, and provider platforms (E2B, Modal, Cursor) own capabilities (memory snapshots, hibernation) a container backend lacks.
5. **Kernel-owned handle with a lifecycle state machine, harness-outside, one protocol over three placements, replace-not-repair (chosen).**

## Decision

1. **Topology.** The native runtime is *harness-outside*: the ADR-0050 kernel layer never executes inside an execution environment; environments are reachable only through an **environment handle** the kernel holds, and the model reaches them only through `ToolCapability`s whose executors dispatch through the handle under the WS-E5 execution contract. Harness-inside placements are admissible only as hosted participants (`hosting_mechanism = container-installed`).
2. **One protocol, three placements (OQ-045 final, B5 half).** The kernel's sandbox *driver* (MUST-code) speaks the WS-E5 §6.7 verb set plus the lifecycle verbs below to (a) a local helper binary on the kernel host, (b) the same helper inside a container/VM over a bridged channel, (c) a provider adapter implementing the verbs over a platform API with declared loss. The helper is out-of-process (ADR-0049 confirmed; no ADR-0050 revalidation trigger fires). Backend selection, image, recipe, limits, policy references, `on_loss` and `snapshot_cadence` are MUST-data on the `EnvironmentRecord` (WS-B5-adr-2).
3. **Environment classes** (closed per dialect): `{local_host, local_sandboxed, local_container, remote_ephemeral, remote_persistent, provider_hosted}`; `local_host` (`isolation_class = none`) only at Stage 0 or under an `authority_cap`-reviewed definition; `remote_persistent` never deletes on teardown.
4. **Handle record** (kernel runtime record, never an IR entity): `EnvHandle{env_handle_id (allocated), run_id, environment_ref, class, state, health, session?{session_id, helper_identity (claim), lease_generation}, capabilities (tri-state), containment{policy, report} (WS-H4), credential_bindings (WS-H3, placeholders only), roots{workspace_roots, writable_roots, cwd}, limits + budget_node_refs, meters, snapshots[], parent?{env_handle_id, mode, on_parent_end}, fault_profile_ref?, connection_info?, on_loss, provenance{origin = kernel}}`.
5. **Lifecycle** `declared → provisioning → ready ⇄ {detached, suspended} → unreachable → {reattached → ready | replaced | failed}`, terminal `{replaced, failed, torn_down}`; operations `provision, attach, detach(keep), suspend, resume, reattach, replace(from), teardown(reason), health(), status()`. Invariants: **L1** one `ready` handle per `(run_id, environment_ref)` (`AlreadyAttached`); **L2** every effect event carries its `env_handle_id`; **L3** `unreachable`/`replace` mark every `committed` effect on the handle `unknown{cause: worker_lost | environment_replaced}` (B3 procedure); **L4** `replace` appends `action.world_state.discontinuity{from, to, restored_from, lost_range, continuity ∈ {byte_identical, restored_from_snapshot, fresh}}`; **L5** transitions are ledgered before the backend call (except the observed `unreachable`); **L6** `teardown` runs `before_remove` hooks as budgeted effects; **L7** the handle never stores a credential value, kernel identity or lease token.
6. **Self-heal = `heal(env_handle)`:** reattach within `capabilities.reattach_window_ms` → `resume` if suspended → per `on_loss ∈ {fail_run, replace_from_snapshot, replace_from_image}` → `replaced` + discontinuity → B3 resumes from the last durable effect phase. `snapshot_cadence ∈ {on_turn_end, every_n_effects, on_idle, never}` is MUST-data; recovery snapshots are `charged_to = subject`.
7. **Events** (additions to the ADR-0026 taxonomy, no renames): `action.environment.{declared, provisioning, attached (references security.containment.applied — CF-WS-H4-05 accepted), selected, detached, suspended, resumed, unreachable, reattached, snapshot, restored, derived, replaced, failed, torn_down, meters_sampled}` and `action.world_state.discontinuity`; all `durability = ledger`, `observability_level ≥ events`, `origin = kernel` (hosted rows `origin = participant`).
8. **T-LCD statement:** satisfies T-06 (no IR field for hosted participants), T-07 (tri-state capabilities; conformance never coerces), T-09 (environment factor = record, never instance), T-11 (per-backend lowering-loss report), T-12 (operations; out-of-process by construction), T-14/-15 via WS-B5-adr-3's counters; T-05 applies to `on_loss`/`snapshot_cadence` defaults (debt records). ADR-0024 rung: driver/state machine MUST-code; class/recipe/policy refs MUST-data.

Doc 2 §5.5, §11 (S-130).
- **(b) Source-code precedent:** codex `codex-rs/exec-server/src/environment.rs` (`EnvironmentManager`, `EnvironmentObservedStatus`, provisioning reports), `exec-server-protocol/src/protocol.rs` (`InitializeParams{resume_session_id}`, `EnvironmentInfo`, `EnvironmentCapabilities`), `core/src/environment_selection.rs` + `protocol/src/protocol.rs` L154–165 (`TurnEnvironmentSelection`); software-agent-sdk `openhands-workspace/openhands/workspace/{docker,cloud,remote_api}/workspace.py` (`pause/resume`, resume-by-id, health wait); harbor `src/harbor/environments/base.py` L92–110, L231–242, L909–915; inspect_ai `environment.py` L416–510 (`sample_init/sample_cleanup(interrupted)`); symphony `SPEC.md` §4.1.4, §5.3.4 (hooks). The integrated state machine with L3/L4 and the three-placement driver is `no-precedent / novel` as a whole.
- **(c) Disconfirming evidence considered:** OpenHands' harness-inside design is simpler and avoids per-operation round trips (S-110 `docker/workspace.py`, `remote/base.py`); Symphony and Codex cloud tasks get by with an id string and no kernel state model (S-108 §14.3; S-107 `cloud-tasks-client/src/api.rs` L42–45); replacement discards un-snapshotted state on long runs. *Why it does not overturn:* the TCB placement is fixed by ratified ADRs and by the instrument's audit purpose; Managed Agents reports latency fell after decoupling; provider states do not align so a kernel machine is the lowest common *semantic*; loss under replacement is made visible (L4) and bounded by `snapshot_cadence`, and process repair stays available inside a healthy handle.
- **(d) Conditionality:** model- and task-independent; assumes the coding/terminal domain first (browser/GUI classes reuse the machine with `provider_hosted` adapters — S-122); assumes backends expose at least `exec` + file transfer + liveness; `suspended`, `replace` and provider adapters are C1 and need no Stage-1 backend to support them (tri-state). Assumes the ADR-0050 helper layer for the local placement; a helper in another ecosystem is a drop-in behind the same protocol (ADR-0050 §5).
- **(e) Build-stage assignment:** **C0 / Stage 0** (`local_host`, record, `declared → ready → torn_down`); **C0 / Stage 1** (full machine minus `suspended`; `local_sandboxed` via the helper; fail-closed attach; events; AC-B5-01/-05/-06); **C0 / Stage 2** (`local_container`; `unreachable/reattach/replace/heal`; AC-B5-02/-03); **C0 / Stage 3** (conformance across backends; AC-B5-11/-12); **C1 / Stage 4** (`remote_*`, `provider_hosted`, `suspended`, hosted mapping); **C2** (attested microVM images with WS-H4 E1).

## Consequences

- WS-B3 implements `heal` and consumes `reattach_window_ms`, `on_loss`, `snapshot_cadence` and the `detached` state for checkpoints; WS-E5's `on_kernel_loss = preserve_until(ttl)` must satisfy `ttl ≥ reattach_window_ms`.
- WS-G2 treats `world_state.discontinuity` as evidence invalidating unverified workspace claims after `lost_range`; WS-J5 annotates results rows of runs with a non-`byte_identical` discontinuity (never hidden, ADR-0037 style).
- WS-A3 adds `EnvHandleId` to the allocated-id list and fixes `EnvironmentRef` resolution; WS-B1's taxonomy gains the verbs in decision 7 by amendment.
- WS-H4/H3/E5 pre-registered conflicts CF-WS-H4-01 / CF-WS-E5-01 close as "adopted"; the three isolation vocabularies are reconciled per CF-WS-B5-01.
- Hosted `container-installed` participants get a handle with `origin = participant` rows only for observable transitions; no native contract changes (T-LCD-06).

## Reversibility

**Medium.** The record, events and state machine are data and can be extended (new classes, new transitions) by dialect bump; reversing the harness-outside rule would relocate the ledger, monitor and broker and is effectively a re-architecture (low reversibility for decision 1); reversing replace-not-repair costs only the `heal` procedure and the discontinuity record (high).
