# ADR-NNNN — Effect lifecycle as typed ledger events: write-ahead commit record, explicit `unknown`/`probe`, fencing inherited from the run writer lease

**Status:** proposed
**Owner workstream(s):** WS-B2 (consumers: WS-B1, WS-B3, WS-B4, WS-E5, WS-H1, WS-H6, WS-G2, WS-A3) · **Phase:** 1 · **Related:** ADR-0001, ADR-0006 (novelty claim c: doc 2 §12 mechanisms as integrated contracts), ADR-0007 (T-LCD-06/-07/-12), ADR-0008, ADR-0011; WS-B1 proposed ADR on the run ledger (event log authoritative; writer lease with fencing token); WS-A3-adr-1 (`Effect` record, `EffectClass`); CF-WS-B2-02, CF-WS-B2-03, CF-WS-B2-04, CF-WS-B2-06; OQ-015, OQ-042, OQ-WS-B2-05, OQ-WS-B2-07; R-2.2.2, R-2.2.1, R-2.2.3

## Context

Doc 2 §5.5 motivates "separating *intent*, *prepared action*, *commit*, and *observed result* in the event model" because the decision-maker is nondeterministic and long-running agents crash, retry and get cancelled. The WS-B2 source audit (dossier §4a M1) found that every audited harness has code for at least one of four loss/duplication boundaries — cancellation mid-execution (Codex `parallel.rs`, OpenHands `_emit_orphaned_action_errors`), process death between dispatch and observation (OpenHands `event_service.py` L1161–1190; Codex `normalize.rs`), retry that re-runs a partially executed command (Codex `orchestrator.rs` "Second attempt"), and replay of unobserved actions (OpenHands `Agent.step()` "implicit confirmation") — and that none writes a durable record *before* dispatch that would let recovery distinguish "never dispatched" from "dispatched, outcome unknown". WS-B1 has decided that the run ledger is authoritative, appends are durable-before-visible, and one writer per run holds a lease with a `fencing_token`; it requires `effect_id` on four effect phases and delegates their semantics to WS-B2. This ADR fixes those semantics.

## Options considered

1. **No runtime-owned effect lifecycle; tool errors are returned to the model, which decides whether to retry** (Managed Agents S-047; Symphony S-108). *Rejected as the general rule:* safe only for reversible/reprovisionable workspace effects; gives the recovery procedure no way to tell "not dispatched" from "outcome unknown" for external effects.
2. **Begin/End event pairs without a dispatch barrier** (Codex `ExecCommandBegin/End`; OpenHands action/observation matching). *Rejected:* an event written after the fact cannot bound the window in which an effect happened but was not recorded; OpenHands' own comments describe exactly that window.
3. **Replay unobserved actions on resume** (OpenHands `get_unmatched_actions` → execute). *Rejected:* duplicates non-idempotent effects by construction.
4. **Full deterministic replay of the control loop** (Temporal workflow model, S-WS-B1-07 via WS-B1). *Rejected for C0:* WS-B1 makes deterministic replay a declared capability of control-strategy variants, not a Core guarantee; the effect model must work with event reconstruction alone.
5. **Typed lifecycle with a write-ahead commit record, explicit `unknown` + `probe`, synthetic terminal records for the model, and fencing inherited from the run writer lease (chosen).**

## Decision

1. **States and events.** An effect (`effect_id`, allocated at `action.effect.intent`, never re-minted) moves through `intended → authorized | refused → prepared → committed → observed(applied | not_applied | partial) | unknown → probed → observed | compensated | reverted | abandoned`. Event classes follow WS-B1's `action.effect.<phase>` naming; `refused, unknown, probed, compensated, reverted, abandoned` are added to B1's taxonomy (CF-WS-B2-04). Authorization is recorded on WS-B1's `security.permission.decided` with `effect_id` and `effective_risk_class` added. Terminal set: `refused, observed(applied|not_applied), compensated, reverted, abandoned`.
2. **Write-ahead barrier.** For every effect whose reversibility is not `read_only`, `action.effect.committed{effect_id, attempt_no, fencing_token, dispatched_at}` is durable (WS-B1 durable-before-visible append) before the executor receives the request. `committed` means "commit record durable", never "applied" (CF-WS-B2-06).
3. **Every commit resolves; nothing is silently dropped.** Every `committed` is followed by exactly one terminal event. Lease expiry, cancellation, timeout, worker loss and executor error produce `action.effect.unknown{cause}`; `unknown` is resolved by `probe` (verdict `applied | not_applied | undeterminable`), by class policy (ADR-2), or by `abandon` — never by silent redispatch.
4. **The model always sees a terminal or an explicit `unknown`.** The model-facing history contains a refusal, observation, or "may have partially executed / unknown" record for every intended effect (Codex `normalize.rs` and `turn_aborted.rs`; OpenHands `_emit_orphaned_action_errors` precedents).
5. **Retries share identity.** A retry is `attempt_no + 1` on the same `effect_id`; the idempotency key (ADR-2) is a function of `effect_id`, never of `attempt_no`. Exactly one `observed` per `(effect_id, attempt_no)`.
6. **Fencing.** Every effect event after `prepared` carries the run writer lease's `fencing_token` (WS-B1); the ledger refuses stale tokens (`Fenced`). Effect- and resource-scoped leases with progress payloads are a C1 extension of the same contract. Clock assumption: non-Byzantine, bounded drift; monotonic clocks for local TTLs; renewal at ≤ ttl/3.
7. **Detached children are recorded.** An executor that leaves a process/job running reports `detached_effect_ids[]`; each is an effect in `committed` under the run's lease (OQ-WS-B2-05 decides ownership of termination).
8. **Contract surface** (operations, language-neutral): `begin_effect, authorize, prepare, commit, observe, mark_unknown, probe, compensate, revert, abandon, effect_state, effects_in_state`; `project(run, effect_ledger)` (WS-B1) must equal the live view. Failure modes: `CapabilityMissing, PolicyDenied, ApprovalTimedOut, BaselineUnavailable, CompensatorMissing, ResourceLockTimeout, Fenced, NotPrepared`.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: the four loss/duplication boundaries exist in production code — S-107 (`parallel.rs` L177–190, `turn_aborted.rs` L10–11, `normalize.rs` L46–134, `orchestrator.rs` L322/L483), S-110 (`event_service.py` L1161–1190, `agent/agent.py` L644–650, `local_conversation.py` L2646); coordinators must record checkpoints reliably before acting — Sagas S-WS-B2-01 (Tier A); leases bound recovery delay under a stated clock assumption — S-WS-B2-02 (Tier A); Start-To-Close timeout as the recovery bound and heartbeat details for resume — S-WS-B2-05 (Tier B); durable-before-visible settlement and "no repeated action" on resume — S-073 (`provisional`, corroborating only); explicit intent/outcome pairs with a reversibility class — S-078 (`provisional`, corroborating only); event-sourced wake and client rewind on retried steps — S-047, S-052 (Tier B). The non-atomic failure model of S-WS-B2-08 is `provisional` and used only as a name for a class the production code already exhibits.
- (b) Source-code precedent: `codex/codex-rs/core/src/context_manager/normalize.rs` (synthetic terminal outputs), `codex-rs/core/src/context/turn_aborted.rs` (model-facing partial-execution notice), `codex-rs/core/src/tools/parallel.rs` (cancel → aborted response), `codex-rs/protocol/src/protocol.rs` (Begin/End pairs); `software-agent-sdk/openhands-agent-server/openhands/agent_server/conversation_lease.py` (generation-fenced ownership lease), `event_service.py` L1161–1190 (restart backfill, no replay), `openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py` (`_emit_orphaned_action_errors`, `reject_pending_actions`); `symphony/SPEC.md` §7.4, §8.5, §14.3 (single mutating authority; reconcile before dispatch; stall timeout). The *write-ahead commit record gating dispatch* and the *explicit `unknown` + `probe` states* are `no-precedent / novel` as an integrated harness contract; each part is precedented at the database/workflow layer.
- (c) Disconfirming evidence considered: Managed Agents and Symphony run at scale with no effect lifecycle (S-047, S-108) — does not overturn: both operate on reversible/reprovisionable workspace effects and neither claims safety for external irreversible effects; the lifecycle costs nothing for `read_only`. No audited harness gates dispatch on a durable record and the barrier adds a write per effectful call — does not overturn: WS-B1's write path is already durable-before-visible, and the barrier is the only way to distinguish "never dispatched" from "unknown" for compensable/irreversible classes. Leases fail under paused-but-alive workers (S-WS-B2-02 clock assumption; S-052 hibernation) — does not overturn: that is why the fencing token, not expiry, is the safety mechanism. Logos' "no repeated action" (S-073) is a no-replay result, not a dedup-under-retry result — recorded as N1; not load-bearing.
- (d) Conditionality: independent of model tier and task class. Assumes WS-B1's storage properties (atomic durable append; exclusive-writer primitive across processes on one host at Stage 0–1). Assumes executors can report `detached_effect_ids` and, for `probe`, that a read-only postcondition check exists for the capability (otherwise `undeterminable` → escalation). Hosted participants map their five-state tool-call status onto the lifecycle (`cancelled → unknown`) with no native field added (T-LCD-06).
- (e) Build-stage assignment: **C0 / Stage 1** — event family, state machine, write-ahead barrier, `unknown`/`probe`, fencing inheritance, static checks AC-B2-03/-07; **Stage 3** — fault-injection battery AC-B2-01/-02/-06/-08 (shared kill points with WS-B1 AC-B1-2); **C1 / Stage 2** — effect/resource-scoped leases with progress payloads.

**T-LCD statement (ADR-0007 decision 5).** Satisfies: T-LCD-06 (no dependency edge from effect entities to the Hosting ABI; hosted status is *mapped onto* the lifecycle), T-LCD-07 (undeclared classes stay `unknown`, never coerced), T-LCD-12 (operations/inputs/outputs/invariants, implementable out-of-process), T-LCD-10 (effect identity is runtime-allocated; provider ids are `surface_ids` aliases, per WS-B1). Does not by itself satisfy T-LCD-11 (carrying `effect_id`/class through protocol targets) — mitigated by the WS-A4/E4 lowering loss report obligation and AC-B2-09.

## Consequences

- WS-B1 adds six `action.effect.*` classes and two payload fields to `security.permission.decided` (CF-WS-B2-04); `read_only` joins the reversibility enum (CF-WS-B2-06).
- WS-B3's recovery procedure must emit `action.effect.unknown` for every effect in `committed` on resume/lease expiry and record the decision in `lifecycle.run.resumed.recovery_decision`.
- WS-E5 executors must accept `(effect_id, attempt_no, idempotency_key)` and report `detached_effect_ids[]`, `postcondition_results[]`; they must implement `probe` for capabilities that declare it.
- WS-G2 treats an `abandoned` or unresolved `unknown` effect as a completion blocker or annotation (OQ-WS-B2-07). WS-H6 audits `abandoned` and `Fenced` events.
- WS-A3's `Effect` record carries `{state, attempt_no, fencing_token, compensation_plan_id?, baseline_ref?}` in place of the placeholder `transaction?`.

## Reversibility

**Medium.** The event family and barrier are additive over WS-B1's ledger; dropping the barrier later is a one-line policy change per class. Removing the `unknown`/`probe` states after WS-B3/G2 depend on them would force those consumers to re-derive outcome uncertainty from Begin/End pairs — the exact ambiguity this ADR removes — so that direction is costly.
