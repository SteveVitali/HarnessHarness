# ADR-NNNN — Downstream inheritance of invalidation via kernel-stamped memory justifications and a derived `MemoryStaleIndex` (OQ-020, retrieval half); memory validity-vs-compliance metrics and veto invariants (OQ-049 memory row; OQ-128 input)

**Status:** proposed
**Owner workstream(s):** WS-D4 (consumers: WS-D3, WS-D1, WS-D2, WS-B1, WS-B3, WS-H6, WS-I1, WS-I2, WS-G1, WS-G3, WS-J4, WS-J5, WS-F3) · **Phase:** 2 · **Related:** ADR-0037 (S4 `StaleIndex`, `depends_on_revoked` annotated never hidden), ADR-0033/ADR-0034 (`derived_from`, P1 derivation join, P3 context label), ADR-0026 (derived views, rebuild equality), ADR-0014 (chain; `activation_observable`), ADR-0045/ADR-0046/ADR-0047 (metrics, matched budget, judges), ADR-0042/ADR-0043 (`memory_op` scope, M14), WS-D4-adr-1/-2; CF-WS-D4-01, CF-WS-D4-06; OQ-020, OQ-049, OQ-128, OQ-WS-D4-04/-05; R-2.4.4, R-2.9.2

## Context

Doc 2 §10 asks "How should downstream artifacts inherit invalidation, and what should be immutable for audit?" (OQ-020). ADR-0037 answered the identity half for sealed definitions and bundles (`StaleIndex`, results annotated `depends_on_revoked`). The retrieval half is harder because memories derive from memories through the model: S-106's most important limitation is the **write-back vulnerability** — an agent that read a revoked fact and journaled a conclusion produces a fresh record no store-level filter can recognise, so revocation is defeated one hop later. Doyle's truth-maintenance system is the classical answer: a belief stays IN only while a justification stays valid, and dependency-directed maintenance retracts dependants when a justification is retracted. The runtime already has the justification data without model cooperation: ADR-0034 P1 requires `derived_from` on every derivation, and WS-B1 records every item delivered to each model call (`context.assembled.items[]`). Separately, ADR-0014 requires validity and compliance to be measured as a pair, and S-077 shows compliance with identical memory bytes ranging from 100 % to ≤ 11 % across models and flipping sign across versions of one family — a memory that is *valid* is not necessarily *followed*, and the two must never be reported as one number. OQ-049 asks which memory kinds have deterministic detectors; OQ-128 asks which memory-related vetoes are C0 vs C2.

## Options considered

1. **Trust the writer to declare its inputs (`derived_from` from the model).** *Rejected:* exactly the write-back hole; a `delegate` cannot be the source of the justification that would later withhold its own output.
2. **No propagation; treat each memory as independent (every audited system).** *Rejected:* S-106 write-back; ADR-0037 S4 already propagates for definitions and the asymmetry would be indefensible.
3. **Propagate along similarity links (mem0 `linked_memory_ids`).** *Rejected:* similarity is not dependency; it both over- and under-propagates unpredictably and is model/embedding-conditioned.
4. **Chosen: kernel-stamped justifications = the memory versions delivered (and handles expanded) in the model call that produced the write, plus declared inputs that may only add; revocation propagates transitively along kernel-stamped justifications into a derived `MemoryStaleIndex`; stale dependants are withheld by default and annotated never hidden; a C2 narrowing (`subject_overlap`) is admissible only from a matched-budget Lab result. Metrics: deterministic validity vetoes at C0; class-scoped compliance metrics with named deterministic detectors for two memory kinds.**

## Decision

1. **Justifications.** Every `Memory` version carries `justifications: [Justification{kind ∈ {delivered_memory, expanded_handle, declared_input, dependency_stamp}, ref: VersionedRef, at: EventRef}]`, stamped by the kernel at `write`: `delivered_memory` = every memory version in `context.assembled.items[kind = memory]` of the producing model call; `expanded_handle` = handles expanded in that call; `declared_input` = writer-declared (add-only); `dependency_stamp` = the contract's stamps (WS-D4-adr-1). `derived_from` (ADR-0033) records the derivation kind alongside; `justifications` is its kernel-verified subset.
2. **Propagation rules.** J1: `lifecycle_state(v) = stale_by_dependency` iff some justification `j` with `kind ≠ declared_input` has `lifecycle_state(j) ∈ {revoked, stale_by_dependency}` (transitive). J2: `supersedes{edit}` does not propagate; `RevocationRecord` and `supersedes{revocation}` do; `expired` propagates only where the dependant's contract declares `dependency_changed` on that stamp. J3: since withheld memories are never delivered (E1/E2), a memory cannot be justified by a memory that was already revoked at write time; the pre-revocation case is caught by J1 — closing both halves of the S-106 write-back.
3. **Index.** `MemoryStaleIndex = project(runs, memory_stale_index, until_seq) : version_id → [{revoked_ancestor, reason, since: EventRef}]` — derived, rebuildable, rebuild-equality tested (ADR-0026); the memory analogue of ADR-0037's `StaleIndex`. Stale versions are withheld by default (WS-D4-adr-1 decision 4), delivered only under `admit_stale_by_dependency` with the annotation, and results rows that consumed them carry `depends_on_revoked = true` (ADR-0037 S4 shape).
4. **Narrowing (C2 option).** `MemoryPolicy.justification_scope ∈ {delivered (default), subject_overlap}`; `subject_overlap` restricts `delivered_memory` justifications to delivered memories sharing a `subject_key` with the new version; admissible in a sealed definition only after AC-D4-12's `ComparisonReport` (matched budget) shows the default's utility cost; `declared_only` is never admissible (escape hatch, T-LCD-01 in memory form).
5. **Immutable for audit (OQ-020).** Every memory version's bytes for WS-H6's floors; every `supersedes` edge, `RevocationRecord`, `ConflictSet` and justification list forever (ADR-0037 S8); content may be redacted by endorsed tombstone (WS-H6), lifecycle records never.
6. **Metrics (ADR-0045 form; `computed_from` ledger events; native only, hosted `n/a{class}`).** Deterministic vetoes at C0/Stage 2: `memory.revoked_delivered` (a delivered memory version `revoked | superseded` at that `seq`) and `memory.stale_delivered` (`invalid{dependency_changed | expired}` at delivery) — both `veto: true`, "revoked memory never surfaces" / "stale version never acted on (delivery form)". C2: `memory.stale_by_dependency_delivered` (veto) and `memory.stale_acted_on` (a `committed` effect whose args provenance cites a memory `invalid` at the proposing call — the `revoked-policy action` row of OQ-128 for memories; `veto: true`). Non-veto: `memory.validity_rate`, `memory.unknown_admitted_rate`, `memory.over_invalidation` (table-granularity firings; stale versions later revalidated unchanged), and the compliance chain `memory.activated` / `memory.followed`.
7. **Detectors (OQ-049 memory row).** `activation_observable = true` for handle-only deliveries (`signal = loaded`) and for kinds with a `subject_key` or suggested call (`signal = cited` when a proposal references it); `followed` is deterministic for `recovery` (next proposal's canonical args equal the suggestion — S-077's first-try compliance) and `procedure_pointer` (the procedure is invoked); judged (`model_io`, ADR-0047) for `fact`/`preference`/`episode`/`summary`/`journal`; `diagnosis` is `n/a{no_detector}` unless it names a validator. Reporting shape is ADR-0014's decomposition keyed by model snapshot; any "memory helps" claim is a `ComparisonReport` with `benefit_kind` and `budget_match.status` (ADR-0046).
8. **OQ-128 input.** `memory.revoked_delivered` and `memory.stale_delivered` are C0/Stage 2 vetoes (their enforcement is the C0 retrieval order, ADR-0048 stage note); `stale_by_dependency` and `stale_acted_on` are C2 with the C0 special case that a `revoked` ancestor is detectable at C0 once the index exists at Stage 2.

**T-LCD statement.** Satisfies T-LCD-13 (memory delivered/activated/followed with named detector classes per kind), T-LCD-14 (the narrowing is admitted only from a matched-budget report), T-LCD-15 (all memory metrics class-scoped; hosted `n/a`), T-LCD-12 (index is a derived view; operations pure), T-LCD-10 (justifications reference `version_id`s; no surface fields). Not applicable: T-LCD-01…-09, -11 (T-LCD-05 applies only if a profile overrides `justification_scope`, which is then a conditioned rule).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: beliefs justified by dependencies; retraction propagates along justifications — Doyle TMS (S-WS-D4-01, Tier A); stale-by-dependency for pinned closures with annotation never exclusion — ADR-0037 S4 (ratified); derivation joins inputs and the compaction `forgotten` list as `derived_from` — ADR-0034 P1 (ratified); delivered items recorded per call — ADR-0026/WS-B1 `context.assembled` (ratified); the write-back vulnerability defeats store-level filters — S-106 (`provisional (mech)`); validity and compliance separate, compliance non-monotone in capability and flipping across versions — S-077 (`provisional (mech)`), corroborated by S-088 via ADR-0014 (ratified); cache invalidation of dependants after an unsafe write — RFC 9111 §4.4 (S-WS-D4-03, Tier A).
- (b) Source-code precedent: `mem0/mem0/memory/main.py` L604–700, L1150–1180 @02f7a9b (`linked_memory_ids` maintained on write and pruned on delete — a link graph, rejected as a justification basis but the nearest shape); `AIOS/aios/memory/base.py` L48–70 @292d98f (`evolution_history` prose — negative); `codex/codex-rs/core/src/context/memory.rs` L1–45 @0735c51 (`memories.extraction_evidence` — an evidence kind distinct from instructions, supporting the `kind` split behind detector choice); `AIOS/aios/memory/injection_log_parser.py` (via ADR-0014: delivered records parsed back deterministically). **`no-precedent / novel`** for: kernel-stamped justifications from the delivered-item list, transitive `MemoryStaleIndex`, the `stale_acted_on` veto, and deterministic `followed` for `recovery` memories as a registered metric.
- (c) Disconfirming evidence considered: conservative justifications over-invalidate (TMS thrashing; a journal written beside an unrelated delivered memory is staled with it) — accepted as the sound default; mitigated by annotation-not-exclusion, `admit_stale_by_dependency`, and the measured C2 narrowing; storage and index cost per write — one row per delivered memory per write, derived and rebuildable; compliance judges are unreliable (doc 2 §8) — judged stages carry detector provenance and never feed validity; S-077's magnitudes may not replicate — no number is reused, only the separation. None overturns.
- (d) Conditionality: requires native observability (`events` for validity/activation, `model_io` for judged following); assumes WS-D1 lists delivered memory versions per call and WS-B1 stores them (inline or by blob, OQ-084); the utility cost of `delivered` justifications is task-distribution-dependent — a Stage 3 factor, not an assumption; deterministic `followed` assumes canonical-argument comparison through `SurfaceArgMap` (ADR-0022).
- (e) Build-stage assignment: **C0 / Stage 1** (`Justification` schema; metric declarations registered); **C0 / Stage 2** (kernel stamping at `write`, `MemoryStaleIndex` projection with rebuild test, default withholding, the two C0 vetoes; AC-D4-3/-10); **C0 / Stage 3** (deterministic `activated`/`followed` detectors for `recovery`/`procedure_pointer`; AC-D4-11/-12 recipes); **C2 / Stage 3–4** (`subject_overlap`, `stale_acted_on` and `stale_by_dependency_delivered` vetoes, judged detectors with WS-G3).

## Consequences

- WS-D1 exposes the delivered memory list to `write` (via the `WriteContext` or the ledger view) and marks handle expansions; WS-B1 extends `context.memory.written` with `justifications[]` (CF-WS-D4-01); WS-I1 adds `withheld_count`/`invalidation_reason` to M14 (CF-WS-D4-06); WS-I2 registers the metrics and the two C0 vetoes; WS-G1 supplies the canonical-args `followed` detector; WS-J5 annotates result rows; WS-B3 recomputes the index on resume; WS-D2 compaction summaries of memories inherit justifications through `derived_from` (ADR-0034 P1) and are therefore stale when their inputs are revoked.
- OQ-049's memory row and OQ-128's memory rows are answered here for synthesis to ratify.

## Reversibility

**Medium.** Dropping kernel stamping reopens the write-back hole but touches no stored version (justifications are additive fields); the index is derived and can be redefined; metric declarations are registry rows. The one load-bearing rule is J1's use of kernel-stamped (not writer-declared) justifications.
