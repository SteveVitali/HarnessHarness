# ADR-NNNN — Retry versus reroute: attempt-level retry owned by the control envelope, target-level reroute owned by the router; a closed error-class → action table; compaction-then-relower ordering; health/cooldown as a ledger projection; fail-fast default for pre-registered experiments; replayed-trajectory routing comparisons refused

**Status:** proposed
**Owner workstream(s):** WS-C2 (with WS-F2 as enforcer, WS-C1 as error-class emitter, WS-A4/WS-D1 for `relower`, WS-D2 for compaction, WS-B1/I1 for events and spans, WS-B2 for in-flight effects, WS-I2/J3 for the evaluation rule) · **Phase:** 2 · **Related:** ADR-0019 (AC-9 re-lowering), ADR-0020 (capabilities incl. `reasoning_replay{opaque}`), ADR-0026 (event classes; `model.rerouted`; `model.call.attempt.*`), ADR-0028 (reconstruction vs replay), ADR-0030/0031 (every commit resolves; no automatic retry of irreversible effects), ADR-0040 (reserve; never amend), ADR-0042/0043 (no telemetry store; `model_attempt` spans; M3/M4), ADR-0045/0046 (outcome classes; admissibility), ADR-0007 (T-LCD-01/-05/-09/-14); OQ-067; CF-WS-C2-01/04/05/06; OQ-WS-C2-04/06; R-2.3.2, R-2.6.2

## Context

Every audited system separates a same-target retry from a cross-target fallback but draws the line differently and classifies errors by free text: opencode retries on seven message regexes plus 5xx/429 and never on context overflow (`session/retry.ts`); goose retries transient classes and refuses on a permanent-marker list that documents a provider rejecting a replayed transcript after the thinking configuration changed (`goose-provider-types/src/retry.rs`); litellm retries inside a deployment group and falls back across groups by typed exception class with separate context-window and content-policy lists, cooling a deployment down on 429 or a >50 % failure rate over a minimum request count, and returning the attempted fallbacks as headers (`router.py`, `cooldown_handlers.py`); codex, on a model downshift with the previous model's limit reached, compacts with the previous model and falls back to the current one only for a closed model-specific error set, counting `codex.compaction.model_fallback` (`compact_model_fallback.rs`, `compact_remote_v2.rs`). The ratified contracts already fix the span shape — a logical `model_call` with child `model_attempt` spans and `attempts` (ADR-0043) — and the event `model.rerouted{from, to, reason}` owned by C2 (WS-B1 table), plus `model.surface.relowered` on profile change (ADR-0019). What is undecided is who owns which transition, on which classes, in what order, and how a rerouted run is evaluated. The Replay Gap (`provisional (mech)`) shows that scoring a switch by replaying a logged trajectory under another model evaluates "the wrong world" (0.00–0.11 similarity to live outcomes).

## Options considered

1. **Router owns retries too (litellm shape: retries and fallbacks in one function).** *Rejected:* the envelope already owns attempt counting, backoff and the stop rule (WS-F2, ADR-0040 decision points); two counters for one logical call would double-count `retries` (ADR-0039).
2. **Envelope owns fallback too (router only picks the initial target).** *Rejected:* the envelope would need the compatibility guard and the pricing/health inputs — routing knowledge duplicated across two classes.
3. **Classify errors by message text in the router (opencode/goose markers).** *Rejected:* message text is a provider surface (T-LCD-01/-10); the gateway classifies once into a closed enum and the router reads the class.
4. **Transparent fallback with no ledger mark (OpenRouter "a request never fails").** *Rejected:* destroys attribution and lets model-conditioned runs pool silently (S-062; Replay Gap).
5. **Split by transition: same target ⇒ attempt (envelope); new target ⇒ reroute (router), with a closed class → action table in the policy, compaction-then-relower ordering, ledger-derived health, deviation-aware evaluation and a fail-fast default for experiments (chosen).**

## Decision

1. **Ownership.** A *retry* is a new `model_attempt` on the same `ModelRef` under the same `model_call_id`; WS-F2 owns the attempt count, backoff (honouring provider `retry-after` as a typed field the gateway lifts), the `retries` charge and the stop rule. A *reroute* is a new `ModelRef` for the same `model_call_id`; the router owns target choice through `on_attempt_failed(decision, class, attempt_no, …) → Continue{same_target, not_before} | Reroute{new_decision} | GiveUp{reason}`, which the envelope calls after every failed attempt and obeys.
2. **Closed class → action table.** `ModelErrorClass` (emitted by C1; minimum set: `transient{rate_limit, overloaded, server_error, network, timeout, stream_interrupted}`, `permanent{invalid_request, context_overflow, content_policy, auth, not_found, unsupported_capability, transcript_incompatible}`, `budget{insufficient, exhausted}`, `unknown`). `RoutingPolicy.error_actions: map<ModelErrorClass, {retry_same{max}, reroute, compact_then_retry, give_up}>` is part of the policy's `content_hash`. Defaults: transient → `retry_same` then `reroute`; `context_overflow` → `compact_then_retry` (executed by F2 via D2) then `reroute` to a larger-window candidate; `content_policy` → policy choice (`reroute` or `give_up`); `auth`/`not_found`/`unsupported_capability`/`transcript_incompatible` → `reroute`, **never** `retry_same`; `invalid_request` → `give_up` (a profile bug, CF-044); `budget.*` → `give_up` (never `amend`, ADR-0040); `unknown` → `give_up`. A message-text regex anywhere in the router or policy is a defect.
3. **Reroute ordering (kernel-enforced).** For a cross-profile reroute the ledger shows, in `seq` order: `model.call.attempt.failed` → optional `context.compaction.*` **under the old profile** when the failure class was `context_overflow` or the old profile's window is smaller than the new occupancy (codex `ModelDownshift` precedent) → `model.surface.relowered{dropped_items[], rewritten_items[]}` (ADR-0019) → `model.rerouted{model_call_id, from, to, reason, attempt_no, relowered = true, relower_event_ref, decision_ref}` → `model.call.attempt.started` under the new `profile_ref`. A same-profile reroute has `relowered = false` and no relower event. The reroute *waits* for any proposed effect to reach a terminal or `unknown` state (ADR-0030) and releases the old reservation before holding the new one (ADR-0040). `max_migration_loss` (ADR-1 G-3) is checked on the projected `TranscriptMigration`; exceeding it is `MigrationLossExceeded` → next candidate or `GiveUp`.
4. **Health and cooldown are projections.** `HealthView = project(ledger, view_kind = health, window)` over `model.call.attempt.*` per `(provider_model_id, serving_route)`: attempt/failure counts by class, latency quantiles, `cooldown_until?`; default rule parameters mirror the litellm precedent (429 ⇒ cooldown; failure rate > θ over ≥ n attempts ⇒ cooldown; never for a role with a single candidate). No separate health store is authoritative (ADR-0042); a runtime cache is a view with a `derived_from` watermark (ADR-0026).
5. **Evaluation rule.** A run with any reroute has `routing.deviation = true` in its manifest and results row (ADR-1). Pre-registered `Design`s default to `routing_policy = fail_fast` (every role's `fallback_chain = []`), so a provider failure yields `outcome_class = infrastructure_failure` (ADR-0045) instead of a silent model change; a `Design` that admits reroutes must state the deviation policy. A `ComparisonReport` whose arms were scored by replaying logged trajectories under a substituted model is refused with `budget_match.status`-class reason `replayed_trajectory`; routing-policy comparisons are live, paired and matched-total (ADR-0041/0046).
6. **Streaming partials.** A `stream_interrupted` failure after the model has emitted a tool call leaves that call as a committed observation (ADR-0030); the reroute applies only to the *remainder* of the logical call and the new attempt's transcript includes the partial as an `Observation` with `authority = delegate` (policy for continuation vs restart is OQ-WS-C2-06).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: providers reject replayed transcripts after a mid-conversation model-config change so identical retries can never succeed (S-112 `retry.rs` markers; ADR-0020 `reasoning_replay{opaque}`); context overflow is never a transparent retry (S-111 `retry.ts`; S-107 compaction fallback); cross-group fallback by typed error class with cooldown works at production scale (S-WS-C2-13); a model switch is a named event with an ordering rule in exactly one audited harness (S-107 `ModelDownshift`); replay-scored switching mis-ranks routers and swaps rewrite 61–94 % of post-fork actions (S-WS-C2-10 `provisional (mech)`); harness effects are model-conditioned (S-062 `provisional (mech)`); every commit must resolve before the run moves on (ADR-0030).
- (b) Source-code precedent: litellm `litellm/router.py` L7887–7950 (`should_retry_this_error` — class-typed retry vs fallback), `router_utils/cooldown_handlers.py` L318–420 (`_should_cooldown_deployment`), `router_utils/fallback_event_handlers.py` (`AttemptedFallbackTargets`) (c1a83fc); codex `codex-rs/core/src/compact_model_fallback.rs` (closed model-specific error set; `record_model_fallback`), `core/src/compact_remote_v2.rs` L240–290, `core/src/session/turn.rs` L1330–1370 (0735c51); goose `crates/goose-provider-types/src/retry.rs` (transient set; permanent markers; jittered backoff) (fae91d0); opencode `packages/opencode/src/session/retry.ts` (`retry-after(-ms)`; overflow excluded) (9f8db11). The kernel-enforced ordering (compact under old profile → relower → reroute), the closed action table as policy data, health as a ledger projection and the replayed-trajectory refusal are `no-precedent / novel as integrated`.
- (c) Disconfirming evidence considered: reroute changes the world (R2) — accepted and made loud rather than forbidden; fail-fast is the experiment default and deviation is stratified. Message-regex classification is what ships today (opencode, goose) and catches provider quirks a closed enum lags — answered: the enum lives in C1 and is extended by ADR; `unknown` maps to `give_up`, never to a guess. Gateways already implement all of this (R4) — answered: they do not know profiles, cannot order compaction/relower, and do not write our ledger. None overturns.
- (d) Conditionality: assumes provider errors are classifiable at the gateway (true for all audited APIs — status codes plus typed error bodies); assumes `relower` exists (ADR-0019 C0/Stage 3) — before Stage 3 only same-profile reroutes are admissible; independent of model tier and task class; the compaction-first rule assumes a compaction variant is bound (Stage 2+), else the action degrades to `reroute` to a larger-window candidate.
- (e) Build-stage assignment: **C0 / Stage 1** (ownership split, `ModelErrorClass` minimum set with C1, `error_actions` schema, `model.rerouted` payload, `GiveUp` closing `model.call.failed{error.class, attempts}`) → **C0 / Stage 3** (ordering test AC-C2-4; `routing.deviation` in rows; replay refusal in the engine) → **C1 / Stage 5** (`HealthView`, `compact_then_retry`, cross-profile reroute with `relower`, streaming partial handling). ADR-0024 rung: the action table is *parameter/entity*; ordering, ownership and the refusal are *Core*.

**T-LCD statement.** Satisfies T-LCD-01 (no message-text branches; class enum owned by C1), T-LCD-05 (family-keyed fallback chains carry debt records via ADR-1), T-LCD-09 (deviation is a factor), T-LCD-14 (replayed comparisons refused; routing comparisons matched-total), T-LCD-12. Does not address T-LCD-07/-15 beyond inheriting ADR-1 G-7 (hosted rows `n/a`).

## Consequences

- WS-F2's envelope calls `on_attempt_failed` and executes `compact_then_retry` through D2; its exhaustion battery gains a "reroute during exhaustion" case (`budget.* → give_up`).
- WS-C1 emits `ModelErrorClass` and lifts `retry-after` as a typed field; a gateway that needs a model-id branch to classify is a profile bug (CF-044).
- WS-B1 extends `model.rerouted` (CF-WS-C2-03); WS-I1's M3 `rerouted?` becomes a count with reasons; `cost_view.harness_overhead.retries` and `.routing` are populated from attempts and reroutes respectively.
- WS-I2/J3 add `replayed_trajectory` to the engine's refusal reasons and `fail_fast` as the pre-registered default.
- WS-D1/D2 answer OQ-067 knowing the router's `max_migration_loss` consumes their `TranscriptMigration` classes.

## Reversibility

**Medium.** Action-table defaults and cooldown parameters are data. Moving retry ownership back into the router, or allowing unlogged reroutes, would double-count `retries` and silently pool deviated runs — low reversibility for the split and the event, which is why both are C0/Stage 1.
