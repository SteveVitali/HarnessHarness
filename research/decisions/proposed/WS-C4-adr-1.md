# ADR-NNNN — Cache taxonomy and declared cache semantics; prefix-stable layout constraints as kernel invariants; the `caching_markers` rule parameters

**Status:** proposed
**Owner workstream(s):** WS-C4 (with WS-C1 for the `WireDialect.cache_semantics` field, WS-C3 for per-family marker rules, WS-D1 for `link`/`assemble` checks, WS-E3 for tool-surface order) · **Phase:** 2 · **Related:** ADR-0007 (T-LCD-01/-05/-08/-11/-12), ADR-0019 (derivation key; `relower`), ADR-0020 (`caching_markers` rule kind; `cache_control_convention` capability), ADR-0039 (cache roles), ADR-0043, ADR-0048 (CF-026: cache is a boundary component), ADR-0050 §8; WS-C1-adr-2 (`WireDialect` descriptor), WS-D1-adr-3 (`cache_tier`), WS-E3 AC-E3-4; CF-WS-C4-01, CF-WS-C4-04; OQ-WS-C4-01/-02; R-2.3.4, R-2.3.3, R-2.4.1

## Context

Provider prompt caches (KV/prefix caches) are keyed on exact bytes in a fixed hierarchy (tools → system → messages) with a marker cap, a lookback window and a per-model minimum length (S-213), or on a hash of the initial tokens plus an optional affinity key (S-215), or on a server-side resource (S-WS-C4-08); serving stacks reuse prefixes by default (S-WS-C4-02) and can reuse non-prefix segments (S-WS-C4-03). The audited harnesses re-derive the same layout rule — stable material first, volatile last, one marker per tier — but encode *which semantics apply* as a provider-name branch (goose `cache_semantics.rs for_model`) or a code constant (opencode `RESPECTS_INLINE_HINTS`), drop excess markers with a log line (opencode), and place markers by heuristics that expire with the provider (goose's 20-block anchor, "last two user messages"). WS-D1 has already fixed `cache_tier` on slots and reserved volatile kernel items; WS-E3 requires order-stable tool surfaces; WS-C1 reserves `cache_semantics` on the dialect descriptor. What is undecided is the closed set of semantics, which layout facts are kernel invariants versus profile rules, and how cap/lookback violations are handled.

## Options considered

1. **Leave caching to the provider; no layout constraints, no markers.** *Rejected:* every vendor documents that layout determines hit rate; a harness that reorders tool surfaces or injects volatile values into the static tier pays full price silently and the Lab cannot attribute why (cost-observability cluster, S-209).
2. **Select semantics and place markers in the gateway per provider (goose/opencode as-is).** *Rejected:* a provider/model branch in the gateway is the T-LCD-01 failure signature (CF-044 ruling); heuristics without debt records violate T-LCD-05.
3. **Make marker placement a fully profile-owned rule with no kernel invariants.** *Rejected:* tier order, volatile-item exclusion and order-stable tool surfaces are not model-conditioned — they hold for every semantics kind; leaving them to profiles lets one profile silently defeat E3's prefix-extension invariant.
4. **Closed `CacheSemantics` sum as dialect/profile data + kernel layout invariants LC-1…LC-9 + a parameterised `caching_markers` rule with debt records + cap/lookback handled as recorded data (chosen).**

## Decision

1. **Taxonomy.** Six cache kinds exist between the kernel and a model snapshot: K1 provider prefix cache (observed, shaped), K2 compile cache (ADR-0019 derivation key), K3 catalog cache (WS-E3, MCP `ttlMs`/`cacheScope`), K4 tool-result/retrieval cache, K5 exact-match response cache, K6 similarity-keyed semantic cache. K4–K6 are decided in WS-C4-adr-3; K1's shaping is decided here; all six account through WS-C4-adr-2.
2. **Declared semantics.** `CacheSemantics = explicit_breakpoints{max_markers, lookback_positions?, position_rule ∈ {block, run_of_same_kind}, retention_classes, min_cacheable_tokens?, isolation} | implicit_prefix{strictness ∈ {tolerant, strict}, affinity_key ∈ {supported{max_key_length}, unsupported}, retention_classes, min_cacheable_tokens?, reporting_granularity_tokens?} | explicit_resource{ttl_classes, storage_priced, reference_form} | uncached | unknown` — a closed kernel sum per dialect version, carried as data on `WireDialect.cache_semantics` (default) and overridable per model through the profile's `cache_control_convention` capability (ADR-0020); values are `declared → probed` (WS-C1 §6.5). `RetentionClass{class_id ∈ {short, long, extended}, nominal_ms, guaranteed}` is lowered per dialect. **No kernel or codec code branches on a provider or model identifier to choose semantics.** `unknown` is the safe default (no markers; state `unknown`).
3. **Kernel layout invariants (checked at `link` for the `Layout`, at `assemble` for each `ContextPlan`; errors, never warnings):** LC-1 tier order `static → dynamic → transcript`; LC-2 static-tier bytes identical across consecutive same-purpose calls unless an invalidating event intervenes (`static_hash` per call; `PrefixInstability` otherwise); LC-3 no volatile `CandidateKind` (`budget_reminder`, `environment_state`, current time, occupancy, turn counters) in a `static` slot (`VolatileInStaticTier`); LC-4 tool-surface order is a prefix-extension of the previous plan's (WS-E3 AC-E3-4 restated); LC-5 dialect-listed prefix-affecting parameters (`tool_choice`, images, reasoning effort/verbosity, response format, sampling) enter `static_hash`; LC-6 calls with `purpose ≠ main` never extend the main prefix; LC-7 the transcript is append-only between compaction/context-edit events, which stamp `cache_invalidating = true`; LC-8 D1's reserved volatile items render in the first `dynamic` slot; LC-9 markers attach only to dialect-eligible carrier blocks.
4. **Profile rule.** `caching_markers{enabled, marker_positions: [tier_boundary(static) | tier_boundary(dynamic) | transcript_tail{n_recent_user_turns | last_cacheable}], anchor_distance_positions?, retention_class_by_position, ttl_mix_allowed, max_markers ≤ dialect.max_markers, by_reference_default}` — writes marker positions on the plan only (a surface record); the renderer (WS-D1, OQ-063) evaluates it; each per-family value carries an `AssumptionDebtRecord` whose removal test is a golden fixture plus the `cache.expectation_agreement` metric (WS-C4-adr-2).
5. **Cap, lookback and eligibility are data, and violations are ledger facts.** `place_markers(plan, rule, dialect) → {markers, dropped[{position, reason}], substituted[]}` is pure; the codec enforces `max_markers` by invalidation priority (static → dynamic → transcript tail), substitutes the nearest eligible earlier carrier, and never emits a request the provider would reject for markers; every drop/substitution is recorded on `model.call.requested.cache` (never only a log). A prefix estimated below `min_cacheable_tokens` is recorded `expected_state = uncacheable`.
6. **T-LCD statement.** Satisfies T-LCD-01 (semantics/markers are data; AC-C4-1 static gate), T-LCD-05 (debt records on marker rules and retention classes), T-LCD-08 (rules receive `(profile, accounting)`), T-LCD-11 (marker lowering per dialect; `no_slot` loss for dialects without markers), T-LCD-12 (operations). Does not address T-LCD-03/-04/-13 (owned elsewhere). Rung on the ADR-0024 ladder: semantics and marker policy are **data** (parameter/entity rung); layout invariants are **Core** (MUST-code: contracts and algorithms).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** exact-byte, hierarchical prefix invalidation with cap 4, 20-position lookback, per-model minimum and silent non-caching below it (S-213, vendor doc, re-opened 2026-09-10); hash-of-initial-tokens routing, affinity key, retention classes, invalidation by effort/verbosity (S-215); implicit-by-default and explicit-resource caching with "common contents at the beginning" (S-WS-C4-08); prefix sharing as the serving default with no miss overhead (S-WS-C4-02, NeurIPS 2024, Tier A); non-prefix reuse is implementable (S-WS-C4-03, EuroSys 2025, Tier A) — so semantics must be declared, not assumed; declared modules need positional accuracy (S-WS-C4-01, MLSys 2024, Tier A); volatile prompt values invalidate the prefix (S-214); explicit markers can defeat implicit caching at high cost (S-110 code comment, anecdotal).
- **(b) Source-code precedent:** goose `crates/goose-provider-types/src/cache_semantics.rs` L8–46 (four-kind sum + safe default — adopted as data, branch rejected), L53–83 (lookback anchor), L131–154 (carrier eligibility), `formats/anthropic.rs` L474–560 (marker placement); opencode `packages/llm/src/cache-policy.ts` L18–111 (policy-as-data, protocol-neutral hints), `protocols/anthropic-messages.ts` L234–251, L512–537 (cap counted; invalidation-ordered shedding), `utils/cache.ts` L1–16 (TTL buckets), `packages/opencode/src/provider/transform.ts` L205–218 (unsigned reasoning excluded before cache points); pi-mono `packages/ai/src/types.ts` L108, L626–694 (retention preference; per-model compat flags), `api/anthropic-messages.ts` L1373–1385; codex `codex-rs/core/src/client.rs` L296–355 (exhaustive list of reuse-breaking request properties). The closed sum as dialect data, the kernel invariants LC-1…LC-9 and recorded drops are `novel as integrated`.
- **(c) Disconfirming evidence considered:** implicit-caching providers make markers pointless (opencode comment) or harmful (S-110) — answered by emitting markers only under `explicit_breakpoints`; non-prefix reuse (S-WS-C4-03) means prefix layout is not universally optimal — answered by the `ext`/`unknown` slots and by the fact that static-first layout helps every documented semantics; "more diagnostics nobody reads" — answered by opencode's silent drop being exactly the unattributable-cost failure a research instrument cannot accept (WS-C4 §5 R1, R7). None overturns.
- **(d) Conditionality:** holds for any model tier and task class; assumes at least one provider family retains explicit markers and at least one caches implicitly (true through 2026); if all providers converge on implicit prefix caching, the marker rule retires through its debt record and LC-1…LC-9 stand unchanged.
- **(e) Build-stage assignment:** C0 / Stage 1 (`CacheSemantics` on `WireDialect/1` with `unknown` default; LC-1/LC-3/LC-8 at `link`; `place_markers` for the Stage-0 dialect) → C0 / Stage 2 (LC-2/LC-4/LC-5/LC-7 at `assemble`; `static_hash`) → C0 / Stage 3 (second dialect exercises a second semantics kind; AC-C4-1/2/4) → C1 / Stage 5 (per-family marker rules and probes with WS-C3; `explicit_resource`).

## Consequences

- WS-C1 fills `WireDialect.cache_semantics` with the decision-2 sum and its codec implements cap/eligibility enforcement with recorded drops; WS-C3 authors per-family `caching_markers` values with debt records; WS-D1 adds LC-1…LC-9 to `link`/`assemble` and carries `static_hash` and marker positions on `ContextPlan` (CF-WS-C4-04 asks D1 how volatility is expressed); WS-E3's AC-E3-4 becomes a shared criterion; WS-D2 stamps `cache_invalidating` on compaction/context-edit events.
- Scope register R-2.3.4 gains a stage note: shaping/observation C0 (Stages 1–3), `explicit_resource` and per-family rules C1.

## Reversibility

**High** for the sum's members and rule parameters (dialect bump). **Medium** for the layout invariants once Stage-2 plans and Stage-3 fixtures exist: relaxing LC-2/LC-4 later would invalidate stored prefix-stability expectations and the cache metrics' interpretability across bundle versions.
