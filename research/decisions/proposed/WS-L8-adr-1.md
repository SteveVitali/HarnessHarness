# ADR-NNNN — Work items, sources and the fleet run: a `WorkItem` with desired/observed halves over a HIR `Goal`, tri-state source adapters, trigger rules over ADR-0131 triggers, `run_kind = fleet`, the `control.work_item.*` event family, the ownership graph, and the source-of-truth split

**Status:** proposed
**Owner workstream(s):** WS-L8 (with WS-B3 for triggers/inbox runs, WS-B1 for the event family, WS-H6 for audit obligations, WS-F3 for the activation seam, WS-K1/K2 for rendering, WS-L5 for adapter plugins) · **Phase:** 4 · **Related:** ADR-0016 (`Goal`), ADR-0026/0027 (ledger, ids, `causes[]`), ADR-0033/0035 (`principal` minting; external never endorses), ADR-0040 (goal-scoped budget nodes), ADR-0131 (subscriptions, occurrences, inbox runs, `continue_goal`), ADR-0155 (an experiment is a run), ADR-0174 (service callers), ADR-0183 (`run_kind`); CF-WS-L8-01, CF-WS-L8-02, CF-WS-L8-03, CF-WS-L8-04, CF-WS-L8-08; OQ-017, OQ-027, OQ-313, OQ-390, OQ-WS-L8-01, OQ-WS-L8-04, OQ-WS-L8-05; R-2.12.6, R-2.2.3, R-2.6.3

## Context

Doc 2 §10 asks what "accountability, escalation, ownership, and audit model should govern fleets of agents acting as persistent organizational processes" when work is "triggered by issues, schedules, webhooks, PRs, messages". ADR-0131 already made a `Goal` outlive its runs (activations chained by `continued_from`, goal-scoped subscriptions, inbox runs, ingress adapters) and ADR-0155 already showed the pattern for a control plane that is itself a run with claim leases and projected views. What is missing is the *organizational* object: which external thing a goal answers to, who is accountable for it, what state it is in from the organization's point of view, and how those facts are recorded. Symphony (S-108 @ e0ccc83) is the reference: a normalized `Issue{id, native_ref, identifier, title, state, assignee_id, blocked_by[], labels[], dispatchable, …}` read through two adapter operations, a claim set as the single mutation authority, reconcile-before-dispatch, and an organizational prompt (`elixir/WORKFLOW.md`) whose status map places human checkpoints (`Human Review`, `Merging`) between automated states — but with in-memory scheduler state (§14.3), no accountability record and provider blocker metadata it refuses to interpret. Cursor's agents self-subscribe to the PRs they open and hold `/goal` objectives (S-054) with no stated ownership model. Kubernetes' owner references (S-WS-L8-04) supply the ownership-graph semantics production controllers converged on.

## Options considered

1. **The tracker is the control plane; the runtime keeps only what it needs to run (Symphony shape).** Rejected: no ledger record of why an item was dispatched, stopped or escalated (R-2.8.6); timers and blocked state lost on restart (already rejected by ADR-0130 D5/ADR-0131); ownership and accountability unrecorded (N1).
2. **Extend the HIR `Goal` entity with source, owner and state fields.** Rejected: source identifiers and ownership are runtime facts that change without a definition edit (owner handoff, new PR binding), `semantic_id` must not move on a re-assignment, and ADR-0016's kernel invariants are complete without them; putting them in `ext` would make `ext` decide dispatch, which ADR-0016 forbids.
3. **A separate organizational store (a work database) synchronized with the ledger.** Rejected: a second authoritative store (ADR-0026 forbids), a second identity kind (ADR-0036 forbids), and a synchronization seam that is exactly the split-brain the layer must avoid.
4. **A `WorkItem` runtime record with typed desired/observed halves in a fleet run's ledger, over an unchanged `Goal`; sources as tri-state adapters; triggers as ADR-0131 triggers plus data-declared rules; ownership as a fleet-local owner-reference forest** — chosen.

## Decision

1. **The fleet is a run.** `run_kind` gains `fleet` by dialect bump (ADR-0183 §C.1 rule: no `configuration_id`, environment or metric cells; own fenced writer; chains by `continued_from`; never enters subject aggregates; `charged_to = instrument` for reconciler work). Its ledger holds every `WorkItem` record and every reconciler decision as the event family `control.work_item.{created, observed, claimed, dispatched, settled, stopped, blocked, unblocked, handoff, resumed, owner_changed, owner_acknowledged, cancelled, annotated, child_created}` (all `durability = ledger`; producer = the reconciler through the kernel; audit-grade set per OQ-WS-L8-05). Activations are `agent` runs whose `lifecycle.run.created.causes[]` names the fleet's `dispatched` event; the edge is anchored both ways like `spawned/created` (AuditPolicy obligation, CF-WS-L8-04).
2. **`WorkItem` record.** `WorkItem{work_item_id (allocated id), fleet_run, goal_ref: VersionedRef<Goal>, definition_ref, owner: PrincipalRef, owner_ref?: {parent, block_parent_completion}, sources: [WorkSourceBinding], spec: WorkSpec, status: WorkStatus, policy: {state_map_ref, escalation_policy_ref, attendance ∈ {async, unattended}, scheduling}, provenance}`. `spec` is the **desired** half — `{title, body: Text, priority?, labels[], source_state, routable, blocked_by[], spec_hash, observed_at, provenance{origin: ingress(source_ref), authority ≤ external}}` — rewritten only by `control.work_item.observed` when `spec_hash` changes; `status` is the **observed** half — a projection `{state ∈ WorkItemState, activation?, activation_no, claim?, blocked?, handoff?, budget (ADR-0040 goal node view), last_activity, external_effects[], open_children[]}`. `WorkItemState = discovered → claimed → active ⇄ suspended → handoff{state} → active | done | cancelled | blocked{BlockReason} → active | cancelled` (closed; kernel-owned). `BlockReason = {missing_owner, missing_access, approval_pending_expired, approvals_exhausted, budget_exhausted, environment_lost, source_conflict, ambiguity, max_activations, escalation_unresolved, child_blocking}`.
3. **Source-of-truth split.** The source is authoritative for *intent* (what the organization wants); the ledger is authoritative for *fact* (what the runtime observed, decided and did). A source value enters only as `spec` with `authority ≤ external` (owner-attested values through a surface carry `principal`); it can wake, reprioritize, cancel or create an item and can never endorse, widen a permission or satisfy a validator (ADR-0033/0035, ADR-0131 D2). A source move that contradicts a ledgered handoff is `blocked{source_conflict}`, escalated, never auto-resolved.
4. **Sources are tri-state adapters.** `WorkSourceAdapter` (registered component class; out of process) declares `capabilities{push_delivery_id, poll, native_write_tools, assignee_mapping, blocker_metadata} ∈ {declared, probed, unknown}` and implements the read minimum `list(states[]) → [WorkSourceRecord]`, `get(native_ids[]) → [WorkSourceRecord]` (omission = no longer visible; malformed requested record ⇒ error, never silent omission — Symphony §11.1). `WorkSourceRecord{native_id, native_ref?: ext (opaque, non-secret), title, body, state, priority?, labels[], assignee?, blocked_by[], routable: bool (adapter-derived, explicit), created_at?, updated_at?}`. Writes to a source are never adapter operations of the reconciler: they are lifted `ToolCapability` entities (`source_kind`, `unverified` provenance, ADR-0088) with declared effect classes (`scope = external`), executed by the agent through the H3 broker (credentials never reach the activation's environment — ADR-0057/0058; Symphony §10.5 boundary). Adapter credentials, scope selection, pagination and rate limits are adapter-owned; no cross-provider CRUD is standardized (T-LCD-07).
5. **Triggers are ADR-0131 triggers; rules are data.** `WorkTriggerRule{on: TriggerFilter over Trigger ∈ {external{source_ref, filter}, schedule, manual, timer, child_terminal, permission_decided}, action ∈ {create_work_item{owner_rule}, wake, reprioritize, cancel, annotate, bind_source}}` is MUST-data of the fleet policy. `owner_rule ∈ {source_assignee, fixed(PrincipalRef), unowned}`; an item whose owner does not resolve to a human is `blocked{missing_owner}` and never dispatched. Occurrence keys (OQ-313): push sources use the source-declared delivery id namespaced by `source_ref`; otherwise `H(canonical(payload − volatile_fields))` with `volatile_fields` declared by the adapter; poll sources use `H(native_id ∥ normalized(state) ∥ updated_at)`; replay window `max(2 × poll_interval, 24 h)` bounded by the inbox run's retention floor; inside the window duplicates are `skipped{duplicate_occurrence}`, outside it a stale re-delivery is a no-op by `spec_hash` (level-triggered). A PR or thread the agent opens becomes a `WorkSourceBinding{role: subscription}` on the same item (Cursor self-subscription), never a new item.
6. **Ownership graph.** `owner_ref` forms a forest within one fleet run; cross-fleet references and cycles are refused at creation (`CrossFleetOwner`, `OwnerCycle`). A child created by an agent effect (a follow-up issue) is created on `observed{applied}` with `owner = parent.owner` unless the source assigns otherwise. `CascadePolicy ∈ {foreground (default: children cancelled first), background, orphan}` applies on parent cancellation; a parent with an open `block_parent_completion` child cannot enter `done` (reconciler check; provider blocker metadata is display-only).
7. **Human annotations (OQ-390 input).** `control.work_item.annotated{subject: EventRef | RunId | row_ref, text_ref: ContentAddress of Text{authority ∈ {principal, external}}, readers}` in the fleet run (plane 5); never delivered to a model except through a `HarnessRule` that lifts it into a `ContextItem` with `context.artefact.delivered` events (T-LCD-13).
8. **Contract surface (records only; T-LCD-12):** `create_work_item, observe, bind_source, transfer_owner, acknowledge_owner, cancel, annotate, work_item(id) → WorkItem, list(fleet, filter)`; failures `UnownedWorkItem, CrossFleetOwner, OwnerCycle, StateMapUnknownState, SourceUnavailable, StaleSpec, Fenced, WouldBlock`.

**T-LCD statement.** Satisfies T-LCD-02 (every source string is a `Text{authority ≤ external}` leaf; `native_ref` is opaque `ext` that never decides), T-LCD-06 (no IR entity gains a field; hosted activations bind through the Hosting ABI unchanged), T-LCD-07 (adapter capabilities tri-state, probed, `unknown` never coerced; no LCD CRUD), T-LCD-10 (work-item identity is an allocated id; source identifiers are surface aliases), T-LCD-11 (state lowering to source states declares loss per adapter), T-LCD-12 (records in/out; adapters and the fleet reconciler out of process), T-LCD-13 (source context reaches a model only through delivery-ledgered rules), T-LCD-15 (hosted activations render ledger-only fields `n/a`). Not applicable: T-01/-03/-04/-05/-08/-09/-14 (no model-facing surface, conditioned rule or comparison introduced here; ADR-L8-3 carries T-05/T-14). ADR-0024 ladder: trigger rules, owner rules, cascade policy and adapter declarations are MUST-data; the record schema, the source-of-truth split, occurrence-key derivation and the ownership-graph checks are MUST-code. ADR-0183 rule: `run_kind` grows by dialect bump.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: S-108 (Symphony SPEC §4.1.1 normalized issue with opaque `id`/`native_ref` and explicit `dispatchable`; §11.1 two read operations, omission ≠ synthetic state; §11.5 writes by the agent under host credentials; `WORKFLOW.md` follow-up issues with `blockedBy`), S-054 (Cursor self-subscribed PRs; `/goal`), S-426 (level-triggered controllers), S-WS-L8-04 (Kubernetes owner references, `blockOwnerDeletion`, cascade modes, cross-namespace refusal), S-WS-L8-03 (SRE single accountable owner), S-WS-L8-06 (`provisional`, framing: governance as permission/tool/memory/change configuration). Ratified upstream: ADR-0016, ADR-0026/0027, ADR-0033/0035, ADR-0040, ADR-0131, ADR-0155, ADR-0174, ADR-0183.
- (b) Source-code precedent: symphony @e0ccc83 `elixir/lib/symphony_elixir/tracker/issue.ex` L1–67 (normalized record; `routable?`), `tracker.ex` L20–60 (behaviour: `fetch_issues_by_states`, `fetch_issues_by_ids`; optional `agent_tool_specs`/`execute_agent_tool`/`secret_environment_names`; `bind_agent_tools` pins adapter per session), `orchestrator.ex` L907–952 (re-validate by id before dispatch), `elixir/WORKFLOW.md` (status map; follow-up issues); ADR-0155 (experiment-as-run, ratified) for the fleet-run shape; Kubernetes owner references (docs, S-WS-L8-04). The desired/observed split with authority labels and the ledgered ownership graph are `no-precedent / novel` as an integrated record.
- (c) Disconfirming evidence considered: Symphony runs production fleets with no durable orchestrator state and no ownership record, and it is simpler (§5 R1) — but its own §14.3 lists the losses ADR-0130/0131 already rejected, and the audit requirement (R-2.8.6) forbids unrecorded dispatch/escalation decisions; two sources of truth invite split-brain (R2) — answered by typing the halves and escalating conflicts rather than resolving them; provider blocker semantics are unreliable (Symphony §11.3) — which is why the ownership graph is kernel-recorded, never inferred. None overturns.
- (d) Conditionality: assumes ADR-0131's Stage-4 items (`external`/`schedule` triggers, `continue_goal`, inbox runs) and ADR-0130 leases; assumes a source adapter can supply a stable native id and an assignee mapping (otherwise items are `blocked{missing_owner}` by design); no model-tier dependence; task classes: any long-lived work with an external system of record. C4 conditionality: no default here rests on a comparison; the fleet's policies are compared only under ADR-L8-3's matched-budget recipe.
- (e) Build-stage assignment: C4 / Stage 4 (`run_kind = fleet`, `WorkItem` record and event family, `memory` tracker fixture adapter, trigger rules, ownership graph; AC-L8-01/-04/-07/-08) → C4 / Stage 5 (generic signed-webhook ingress with capability probes, one tracker adapter as an L5 plugin; AC-L8-09).

## Consequences

- WS-B1 taxonomy gains the `control.work_item.*` family and the `fleet` run kind (CF-WS-L8-01/-04); WS-H6 gains the fleet-anchor obligation and the audit-grade subset (OQ-WS-L8-05).
- WS-F3: an activation is the unit L8 opens; subagents live inside it; the seam is `causes[]` + `goal_ref` (OQ-WS-L8-04; CF-WS-L8-08 pre-registered).
- WS-K1/K2 render `WorkItem`/`FleetView`; WS-E4/K3 lower work-item state to tracker/MCP-task carriers with loss reports.
- WS-L2: fleet totals are views over goal-scoped nodes; nothing new to account.
- The `Goal.origin` vocabulary is left unchanged (CF-WS-L8-03): tracker/PR/message items are `origin = human`, schedules `origin = scheduled`; the source binding lives on the work item.

## Reversibility

**medium** — the fleet run kind and the event family are additive (a build without the organizational tier has no fleet runs and no `control.work_item.*` events — T-LCD-06-style removability); the record schema can change by dialect bump while ids stay stable. Reversing the source-of-truth split (making the tracker authoritative) would require rewriting audit obligations and is the one choice that would be expensive to undo — which is why it is the choice ADR-0026 already forces.
