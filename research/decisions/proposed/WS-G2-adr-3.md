# ADR-NNNN — Execution-alignment metrics as class-scoped `MetricDeclaration`s in the grounding dimension; `false_completion_rate` is veto-eligible; divergence severities are owned by WS-G2 (OQ-125); the reconciler is a C2 component class evaluated as a matched-budget Lab factor

**Status:** proposed
**Owner workstream(s):** WS-G2 (consumers: WS-I1, WS-I2, WS-J3, WS-J4, WS-J5, WS-G3, WS-C3, WS-I4, WS-H1, WS-L2) · **Phase:** 2 · **Related:** WS-G2 ADR-1/-2, ADR-0045 (`MetricDeclaration`; outcome classes; `n/a` typed), ADR-0044 (metrics are computations over ledger events; grounding catalogue), ADR-0047 (oracle classes; veto invariants; judged labelling; `teacher_relative` as the precedent for `provisional` metric labelling), ADR-0014 (detector provenance; realized-benefit decomposition), ADR-0039 (`charged_to`), ADR-0041 (`MatchSpec`; `UnbudgetedArm`), ADR-0046 (benefit kinds), ADR-0013 (participant class, granularities), ADR-0023/0025 (component class registration), ADR-0007 (T-LCD-05/-08/-09/-14/-15); OQ-125, OQ-102, OQ-WS-G2-03/-04/-08; CF-WS-G2-02/-04/-05; R-2.7.2, R-2.9.2, R-2.10.3

## Context

Doc 2 §10's scorecard names the grounding dimension as "validator pass, state/claim consistency, evidence traceability — is reasoning synchronized with the world?". WS-I1 and WS-I2 (ratified ADR-0044/0045) already list `claim_state_agreement`, `evidence_traceability`, `execution_alignment_failure_rate` ("G2 detector (deterministic) or judge (S-062 class)") and `belief_divergence` (C2) with G2 as the producer, but without definitions; WS-I2 opened OQ-125 asking who owns the severity taxonomy behind `catastrophic_failure_rate`. Harness-Bench reports failure categories without a per-harness breakdown (S-062); the false-success study defines the quantity a harness most needs — completion claims contradicted by programmatic state — and its honest-failure complement (S-WS-G2-01, `provisional`); BIWM defines a belief-divergence vector with arrival/growth terms (S-148, `provisional (mech)`); Anthropic's harness shows the cost side (22× on a simple app; S-046). R-2.7.2 is C2/Could; the ledger substrate is C0 (WS-G2 ADR-1). The Lab must be able to ask "does the reconciler's intervention help model M more than N under matched budget" (T-LCD-09/-14).

## Options considered

1. **One scalar "grounding score".** Rejected: collapses agreement, traceability, false completion and honest failure — which move independently (S-WS-G2-01's HF vs FS) — and hides detector class (CF-029's masquerade risk, ADR-0047 option 1).
2. **Judged execution-alignment rate (S-062-style annotation) as the headline.** Rejected: judges ≤ 0.65 AUROC on exactly this task (S-WS-G2-01 §4.3); ADR-0047 §2 restricts headline oracles to deterministic classes; admitted as a separately named judged variant.
3. **Severity taxonomy in a shared register owned by synthesis.** Rejected as sole answer: divergence severities depend on the claim/effect semantics G2 defines, security severities on H-track semantics; a shared *record shape* with per-register ownership keeps both computable by I2.
4. **Reconciler always on, as a kernel guardrail.** Rejected: its benefit is model-conditioned (S-046) and must be measurable under matched budgets; a permanent guardrail cannot be an arm.
5. **Named class-scoped declarations computed over G2's ledger events; deterministic definitions for headline-eligible metrics; judged/probed variants under separate names; `false_completion_rate` veto-eligible; severities owned per register with a shared record; the reconciler registered as a C2 component class whose interventions are a Lab factor (chosen).**

## Decision

1. **Declarations** (ADR-0045 form; `dimension = grounding` unless noted; `level = run` reduced per ADR-0045 reducers; `computed_from` per WS-G2 ADR-1/-2 events):
   - `claim_state_agreement` — agree ÷ (agree + diverge) over `verification.claim.reconciled`; `requires_observability = ledger`; `applies_to_classes = native`; `detector_classes_allowed = deterministic`; Wilson intervals; `unverifiable`/`stale` excluded from the denominator and reported as counts.
   - `evidence_traceability` — claims with `evidence_refs ≠ ∅` ÷ claims over `verification.claim.recorded`; native; deterministic.
   - `execution_alignment_failure_rate` — runs with ≥ 1 `diverge ∈ {D2, D3, D5, D6}` on the completion claim ÷ scored runs; `requires_observability = ledger` (native) or `end_state` (hosted, D5 only); both classes; deterministic. `execution_alignment_failure_rate_judged` is a distinct name with `detector_classes_allowed = judged`, `requires_observability ⊇ model_io`, never merged.
   - `false_completion_rate` — completion claims of kind `achieved` whose gate verdict is `hold`/`veto`, or which a deterministic suite oracle contradicts, ÷ completion claims; both classes; deterministic; **`veto: true`** (the `false_completion` invariant — CF-WS-G2-05); `direction = lower`.
   - `honest_failure_rate` — `unachievable` claims with agreement ≠ diverge ÷ failed runs; both classes; `direction = higher` among failures; reported beside `false_completion_rate`, never averaged with it.
   - `divergence_profile` — vector by `(class, severity)`; native; deterministic; reported as distributions and tails, never a scalar.
   - `gate_hold_count`, `reconciliation_cost` — from `verification.gate.evaluated` and `control.budget.consumed{attribution.charged_to}`; `dimension = efficiency`; native; the cost of alignment.
   - `notice_followed_rate` — ADR-0014 chain over `kernel_notice` artifacts; `dimension = compliance`; native; both detector classes allowed with stage reporting.
   - `belief_divergence` — C2; probed/judged; `requires_observability = model_io`; both classes; vector with arrival/growth terms (S-148 shape); every report labels it `provisional` until corroborated outside its origin (the ADR-0047 §6 `teacher_relative` precedent).
2. **Headline rule.** Only the deterministic declarations may feed headline grounding; judged/probed values render under their own names (ADR-0047 §2). Inapplicable metric × class × observability ⇒ `n/a{reason}` (T-LCD-15).
3. **Severity (OQ-125).** `SeverityRecord{source_register ∈ {execution_alignment, security, effect}, level ∈ {info, low, medium, high, critical}, rule_ref}` is the shared shape; WS-G2 owns the execution-alignment register (`critical` = false completion with irreversible external effects claimed; `high` = D2/D3/D5 on the completion claim; `medium` = mid-run D2/D3/deterministic D9; `low` = D4/D7/D8; `info` = first D10 hit); the H-track owns security levels; WS-B2 owns effect-level ones. `catastrophic_failure_rate` (WS-I2) counts `critical` from any register.
4. **Component class.** `execution_alignment` is a registered component class (ADR-0023 `ClassRecord`) with the operation contract of WS-G2 ADR-1 (`extract/bind/reconcile/gate/intervene/declare`), `required_inputs ⊇ {ModelProfile, ResourceAccount}` (T-LCD-08), variant tags for detector sets and Γ tables, `enabled` as the ablation switch, and `charged_to` semantics (bound variant ⇒ `subject`; Lab detector ⇒ `instrument`). The C0 kernel floors (WS-G2 ADR-2) exist even when no variant is bound; the C2 variant adds D1/D4/D7–D10, probes, notices and belief probes.
5. **Lab factor.** "Interventions on vs off" (and Γ variants) is a legitimate arm only with a `MatchSpec` covering probe, notice, validator-run and hold costs (ADR-0041); results are `ComparisonReport`s with `benefit_kind` and the model × harness interaction (T-LCD-09); pre-registered H-G2-1: interventions reduce `false_completion_rate` more for lower-tier models and the gap shrinks with capability.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-09 (interaction effects representable for the reconciler factor), T-LCD-14 (no un-budgeted on/off comparison), T-LCD-15 (every declaration class-scoped; `n/a` typed), T-LCD-08 (class contract receives profile and account), T-LCD-05 (variants and Γ rows conditioned on profiles carry debt records; `belief_divergence`'s probe rule expires). Not applicable: T-LCD-01/-02/-03/-04/-06/-07/-10/-11/-12/-13 beyond what ADR-1/-2 already state.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: false success and honest failure are separable quantities and judges cannot measure the former — S-WS-G2-01 (`provisional`); execution-alignment categories exist but need per-configuration reporting — S-062 (`provisional (mech)`; its own recommendation to report at the model–harness configuration level); belief divergence is a vector with distinct arrival/growth dynamics — S-148 (`provisional (mech)`); deterministic checks are the reliable detector class — S-WS-G2-06 (`provisional`); evaluator benefit is model-conditioned and costly — S-046 (Tier B); metric form, outcome classes, `n/a`, veto and headline rules — ADR-0044/0045/0047 (ratified); matched budgets — ADR-0041 (ratified), S-083 (Tier B via doc 2 §8). No `provisional` number is load-bearing: the declarations define computations, not thresholds.
- (b) Source-code precedent: HAL `hal/utils/compliance_checkers.py` @ 16bb03e (`ComplianceViolation.severity ∈ {low, medium, high, critical}` on deterministic findings) and `hal/utils/llm_log_analyzer.py` (judged analysis kept separate — via ADR-0047); browser-use `browser_use/agent/service.py` L1628–1660 @ 50f2055 (self-report vs judge both emitted "so the eval platform can compare agent vs judge"); AgentDojo `src/agentdojo/benchmark.py` (utility/security as separate booleans — via ADR-0047, S-241); OpenHands `openhands-sdk/openhands/sdk/critic/result.py` @ 3fc7b22 (a scalar "success likelihood" — the rejected shape). The named deterministic definitions, the veto-eligible `false_completion_rate`, the per-register severity ownership with a shared record, and the reconciler as a budget-matched Lab factor are `no-precedent / novel` as an integrated set.
- (c) Disconfirming evidence considered: harness process metrics go stale as capability changes (doc 2 §8; Cursor's per-model baselines) — absorbed: declarations are computations keyed by configuration, and the reconciler variant carries expiry; a veto on `false_completion` may over-trigger on benign cases (an `achieved` claim later contradicted by a flaky oracle) — absorbed: the invariant fires only on a *deterministic* oracle contradiction after a `pass`, flaky oracles are `oracle_failure` outcome class (ADR-0047 §4), and success-with-veto is a column, not an exclusion from the dataset; belief probes are `provisional` and single-origin — absorbed by C2 placement and the `provisional` label rule; severity levels are inherently judgement — absorbed by making the rule reference (`rule_ref`) part of the record so I2 can re-bucket.
- (d) Conditionality: deterministic declarations assume native `ledger` observability or, for hosted rows, an `end_state` oracle for D5; `belief_divergence` assumes `model_io` and a calibrated probe (OQ-WS-G2-03); the Lab factor assumes ≥ 2 model snapshots for the interaction claim; default severities and hold caps are per-suite overrides (OQ-WS-G2-08).
- (e) Build-stage assignment: **C0 / Stage 1** — declarations registered; `SeverityRecord`; `false_completion` veto flag; class registration of `execution_alignment` with floors-only default. **C0 / Stage 3** — deterministic metrics computed on the reference suite; severity buckets on D2/D3/D5/D6. **C2 / Stage 4** — the variant with full detectors; judged variants under separate names; the on/off Lab factor (AC-G2-9). **C2 / Stage 5** — `belief_divergence` probes as profile rules. Rung on the ADR-0024 ladder: declarations and the severity record are Core data schemas; variant choice and Γ are MUST-data.

## Consequences

- WS-I2's registry rows for `claim_state_agreement`, `evidence_traceability`, `execution_alignment_failure_rate`, `belief_divergence` are completed with these definitions (CF-WS-G2-04); `false_completion_rate`, `honest_failure_rate`, `divergence_profile`, `gate_hold_count`, `reconciliation_cost`, `notice_followed_rate` are added.
- ADR-0047's veto list gains `false_completion` (or synthesis rules otherwise — CF-WS-G2-05); WS-J4 renders it as a veto column.
- OQ-125 is answered: per-register ownership with a shared `SeverityRecord`; WS-I2's `catastrophic_failure_rate` reads all registers.
- WS-J3 can run the reconciler on/off factor only with a `MatchSpec` covering alignment costs; WS-L2 attributes probe/notice/validator-run costs by `charged_to`.
- WS-G3 supplies the judged variants' calibration; WS-C3 owns belief-probe rules.

## Reversibility

**High for declarations (additive registry rows; historical values keep their oracle class), medium for the veto flag** (flipping it re-renders scorecards without loss because every value carries its oracle class — ADR-0047's own argument), **high for severity ownership** (a register move is a `rule_ref` remap).
