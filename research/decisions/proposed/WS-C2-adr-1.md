# ADR-NNNN — The router is a policy component at the model boundary: role table as the unit of routing, typed routing request/decision, closed policy kinds as data with assumption-debt records, a composed compatibility guard, and the realized model set as a Lab factor

**Status:** proposed
**Owner workstream(s):** WS-C2 (with WS-C1 for error classes and `model_ref`, WS-C3 for profile resolution and expiry, WS-L2 for reservation/pricing, WS-F2 for enforcement, WS-B1 for event classes, WS-J3/J4 for the deviation factor) · **Phase:** 2 · **Related:** ADR-0012 (boundary components, β, compatibility surface), ADR-0013 (interception keeps a participant hosted), ADR-0016 (`AgentProcess.native.slots`; `DecisionPoint`), ADR-0019 (`relower`, `model.surface.relowered`), ADR-0020 (profile selector, capabilities, expiry), ADR-0023/0024 (policy is data), ADR-0026/0027 (event classes, manifest), ADR-0033/0034 (lifted preferences), ADR-0036 (`configuration_id`), ADR-0039/0040/0041 (charges, reserve, matched budget), ADR-0043 (`harness_overhead.routing`), ADR-0045/0046 (results rows, admissibility), ADR-0007 (T-LCD-01/-05/-06/-08/-09/-11/-12/-14/-15); CF-026, CF-044, OQ-048, OQ-071; CF-WS-C2-01/02/03; OQ-WS-C2-01/02/03; R-2.3.2

## Context

Doc 3 §2.3 names the model router (C1, sponsor-named) as "capability/cost/latency/quality-aware routing; fallback; ensembling". Ontology v1 places it as a *boundary component* at the model boundary (ADR-0012 / CF-026) and defines the *model set* as "the set of model snapshots a harness binds in one run (primary, router alternates, subagents, judges)" while ADR-0036's `configuration_id` carries a singular `model_ref` (OQ-048 open). The source audit (WS-C2 §4) finds three routing regimes that never coexist in one system: gateway routing on operational signals (litellm `router.py`, OpenRouter, AIOS), harness-internal utility routing by role/task class as config plus code branches (opencode `getSmallModel` with a per-provider family list and a provider-id branch; codex `models.json` `upgrade`), and academic per-query/per-step routing on predicted difficulty (RouteLLM, Hybrid LLM, AgentRouter). No audited system records which candidates were considered or why they were rejected; none checks a *profile* before switching; the field's 2026 benchmark reports that most routers, including commercial ones, "fail to reliably outperform a simple baseline" (LLMRouterBench, `provisional`). The ratified contracts already supply every guard ingredient: profile selector/capabilities/expiry (ADR-0020), `relower` with a `TranscriptMigration` (ADR-0019), `reserve` and `InsufficientBudget` (ADR-0040), `NoPrice` (ADR-0039), `model_ref{serving_route}` on every charge (ADR-0039), and `harness_overhead.routing` attribution (ADR-0043).

## Options considered

1. **Routing inside the gateway (litellm/OpenRouter shape).** *Rejected:* the gateway owns transport only (CF-044); it has no notion of profiles, budgets as ledger objects, or Lab factors, and its choices are unattributable in our ledger.
2. **Routing inside the control strategy (F1 chooses the model per step).** *Rejected:* couples model choice to one strategy variant; the Lab could not vary routing policy independently of control strategy (T-LCD-09), and the strategy would need per-model knowledge (T-LCD-01).
3. **A single learned router as the default (RouteLLM-class).** *Rejected as default:* disconfirming evidence (LLMRouterBench; TMLR survey open problems) and no matched-budget artifact benefit on our task distributions; admitted only as a schema kind gated to C4.
4. **No router: one model per run, switching only by user action.** *Rejected:* forbids role-shaped binding (Anthropic lead/subagent, S-036; AgentCore mid-session switching, S-058), utility-model routing that every audited harness performs, and any fallback — every provider outage becomes an `infrastructure_failure`.
5. **A registered `router` component class at the model boundary, invoked per logical model call with a typed request, returning a typed decision that passed a composed compatibility guard; policies as data with a closed kind enum and debt records; the role table as the configured model set and the realized set as a run fact (chosen).**

## Decision

1. **Class and placement.** `router` is a registered component class, `home = model_boundary`, cardinality `exactly-one` in `AgentProcess.native.slots` (ADR-0016/CF-052). Its contract receives `(ModelProfile resolver, ResourceAccount)` (T-LCD-08) and is `select(RoutingRequest, profile_env, account, HealthView, RoutingPolicy) → RoutingDecision | RoutingRefusal`, pure over its inputs; plus `on_attempt_failed` (ADR-2), `explain`, `lower/lift`.
2. **Unit of routing = the logical model call, keyed by role.** `ModelRoleTable = map<ModelRole, RoleBinding{primary, alternates[], policy_ref}>`, `ModelRole ∈ {primary, utility, compaction, subagent, judge, router_predictor}` (closed per dialect). The configured table is data in the sealed Harness Definition and is what ADR-0036's `configuration_id.model_ref` denotes (as the table's `semantic_id` — CF-WS-C2-02). The **realized** table (`model_set_realized`) is a run-manifest end-state fact; `routing.deviation = (any role served by a non-primary)` is a run-level boolean.
3. **Typed request and decision.** `RoutingRequest{model_call_id, role, task_class?, required_capabilities (compiler-derived from the `ModelSurface` this call renders — never hand-written), budget_view, latency_target?, quality_prior_ref?, trajectory_digest? (kernel-computed from the ledger), preferences? (lifted, `authority ≤ external`), context_label}`. `RoutingDecision{selected: ModelRef{profile_ref, provider_model_id, serving_route, effort?}, reservation_id, policy_ref{variant_ref, version_id}, rule_ids_fired[], candidates_considered[{model_ref, verdict ∈ {selected, rejected{reason}}}], inputs_read[], deviation, relower_required}`. Invariant: every candidate in the role's binding appears with a verdict; the charge's `model_ref` equals `selected` (ledger projection test).
4. **Policies are data with closed kinds.** `RoutingPolicy{kind ∈ {static, role_table, fallback_chain, capability_filter, cost_cap, latency_cap, quality_target, health_aware, learned}, params, error_actions, max_migration_loss, allow_unknown?, conditioned_rules[]}` — MUST-data (ADR-0024); composable as an `ordered-many` pipeline (order is a semantic op); the kind enum is extended only by ADR. Any rule keyed on a model family, provider or serving route is a conditioned `HarnessRule` with an `AssumptionDebtRecord` whose `expiry_condition` includes `model_version_change`; `link` refuses a policy with an incomplete record (ADR-0020 decision 4 pattern). Routing preferences lifted from protocols may *exclude* candidates but never *add* one outside the role table (attenuation, ADR-0034).
5. **Compatibility guard (all must hold before a call under a target).** G-1 exactly one profile resolves and `expiry.status ∈ {active, expiring}` (`expired` only with a recorded `intent_ref`; `retired` never) — `NoProfile` / `ExpiredProfile`; G-2 `required_capabilities` all `supported` (declared or probed); `unknown` ⇒ `CapabilityUnknown` unless a debt-recorded `allow_unknown` rule exists; `DRIFT` refused pending OQ-WS-C2-02 — `CapabilityUnmet`; G-3 projected `TranscriptMigration` within `max_migration_loss`, and never while a proposed effect is unresolved — `MigrationLossExceeded`; G-4 `reserve` succeeds — `InsufficientBudget` (a cheaper candidate may be tried; `amend` never); G-5 a pricing row exists when the policy reads cost — `NoPrice`; G-6 authority attenuation on lifted preferences; G-7 hosted participants are out of scope (interception override is `configuration-level`, ADR-0013; routing metrics `n/a`). Refusals are typed errors, never warnings or silent fallback to the primary.
6. **Events and factors.** New class `model.route.decided` (payload = decision; `durable`; min observability `ledger`; Hosting-ABI lowering `none`); `model.rerouted` payload extended (ADR-2); manifest gains `model_set_realized`, `routing.deviation`. Results rows (ADR-0045) carry both; a pre-registered `Design` states `{exclude_deviated, stratify, pool_with_flag}`; the report generator refuses to pool deviated and non-deviated rows without it. A learned policy's predictor calls are `model_call`s charged `subject` under `harness_overhead.routing` (ADR-0043).
7. **Tiering.** C0/Stage 0–1: class contract, `static` + `role_table`, G-1/G-2/G-4, `model.route.decided`, `model_set_realized`. C0/Stage 3: executable projection tests. C1/Stage 5: the remaining kinds, G-3 with `relower`, `HealthView`, MCP/ACP lowering. C4: `learned` deployed only through the evolution pipeline with a `SearchBudgetRecord` and held-out artifact benefit (ADR-0046).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: three routing regimes route on different inputs and never coexist (WS-C2 F1; S-WS-C2-13 litellm strategies, S-111 opencode `getSmallModel`, S-WS-C2-01/03/12); role-shaped binding is a production feature (S-036 lead/subagent split; S-058 mid-session switching); decisions are unattributable without candidate-bearing records (S-WS-C2-13 headers, S-107 counter — WS-C2 F4); the guard composes ratified objects (ADR-0019/0020/0039/0040 — WS-C2 F5); mid-run switching is a factor change (S-WS-C2-10 `provisional (mech)`, S-062 `provisional (mech)`, goose permanent markers S-112 — WS-C2 F3); MCP `ModelPreferences` is the only protocol vocabulary and is lossy (S-153 L2500–2560).
- (b) Source-code precedent: litellm `litellm/router.py` L7522–7660 and `router_strategy/{budget_limiter,lowest_cost,lowest_latency,tag_based_routing}.py` (c1a83fc) — strategy family + budget filter over candidates; opencode `packages/opencode/src/provider/provider.ts` L1939–1990, `session/prompt.ts` L215–235 (9f8db11) — role/task-class utility routing as data; codex `codex-rs/models-manager/models.json` `upgrade` (0735c51) — successor model as data; MCP `schema/2026-07-28/schema.ts` `ModelPreferences` (aa8ce04). The typed request over three input families, the closed policy-kind enum with debt records, the composed profile-aware guard and the realized-set/deviation factor are `no-precedent / novel as integrated`.
- (c) Disconfirming evidence considered: routers rarely beat simple baselines (S-WS-C2-05 `provisional`; S-WS-C2-06 survey) — the contract makes routing measurable and defaults to `static`, gating learned kinds to C4; gateways already do operational routing well (R4) — an external gateway stays admissible as a `serving_route` with reported-only candidates, stratified; quality priors are circular under shift (R5) — priors carry `n`, interval, `valid_until`, `unknown` refused (ADR-0012). None overturns.
- (d) Conditionality: assumes ≥2 admissible model snapshots per deployment for anything beyond `static` (true for every audited system); assumes providers surface a per-call served-model identity (S-WS-C2-14, S-153 `CreateMessageResult.model`, all audited APIs); holds for any task class; `trajectory_digest` inputs are C1+ and assume ledger access at `ledger` observability.
- (e) Build-stage assignment: **C0 / Stage 0–1** (contract, `static`/`role_table`, G-1/G-2/G-4, decision event, manifest fields) → **C0 / Stage 3** (AC-C2-3/-4/-8 executable) → **C1 / Stage 5** (policy family, G-3, `HealthView`, lowering) → **C4** (`learned` via evolution pipeline). ADR-0024 ladder rung: policies enter at *parameter/entity* and *variant*; the guard and event classes are *Core*.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-01 (family/provider keys are conditioned rules in data), T-LCD-05, T-LCD-06 (no hosting edge; G-7), T-LCD-08, T-LCD-09 (`model_set_realized`, `routing.deviation`, policy as component-level factor), T-LCD-11 (MCP/ACP lowering with loss), T-LCD-12, T-LCD-14 (learned-policy claims need matched-total budget), T-LCD-15 (routing metrics class-scoped). Does not satisfy T-LCD-13 by itself — mitigated: a model-facing "request a stronger model" artifact is a `ContextItem` with delivered/activated/followed events (OQ-WS-C2-01).

## Consequences

- WS-C1 hands the gateway a *target* (`ModelRef`) chosen here and emits the `ModelErrorClass` the router consumes (CF-WS-C2-01); WS-C3 exposes `resolve_profile` and `expiry.status` and considers `successor_ref` (OQ-WS-C2-03); WS-B1 adds `model.route.decided` and the manifest fields (CF-WS-C2-03); WS-L4/J3 read `configuration_id.model_ref` as the role table's `semantic_id` (CF-WS-C2-02); WS-J3/J4 add the deviation policy to `Design`; WS-F2 calls `on_attempt_failed` (ADR-2); WS-F4 may call `select` but never bypasses the guard.
- Scope register R-2.3.2 gains a stage note: C0 static slice (contract, guard, event) inside a C1 item — the CF-046 pattern.

## Reversibility

**Medium.** Adding policy kinds, roles or request fields is an ADR-gated schema bump. Dropping the guard or the decision event after Stage 1 would make every reroute unattributable and every deviated run poolable by mistake — the costly direction; the role-table reading of `configuration_id` must be fixed before the first results rows exist (Stage 3), after which it is a key migration.
