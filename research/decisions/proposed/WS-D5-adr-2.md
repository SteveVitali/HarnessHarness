# ADR-NNNN — Three compilation targets for a Procedure (`instruction`, `workflow_node`, `subagent_task`), a total selection rule from bindability, risk and isolation, feasibility errors, the `procedure_target` profile rule kind, and per-target compliance detectors

**Status:** proposed
**Owner workstream(s):** WS-D5 (consumers: WS-A4, WS-C3, WS-D1, WS-F1, WS-F3, WS-G1, WS-H1, WS-J3, WS-I2, WS-E2) · **Phase:** 2 · **Related:** ADR-0007 (T-LCD-01/-04/-05/-09/-13), ADR-0014 (compliance chain), ADR-0016 (entity 5 surface `compile_hint`; `delegated-to` attenuation; `Loop` bounded), ADR-0019 (stages 2–3; `RuntimePlan/1` closed node kinds; closed-world rule; `UnexpressibleSurface`), ADR-0020 (closed `ProfileRule.kind` enum; debt record), ADR-0022 (composite surfaces need a plan), ADR-0031 (`effective_risk_class`), ADR-0034 P2/P3 (delegation; context label), ADR-0035 (Π), ADR-0045/0046 (factors; matched budgets); CF-WS-D5-01, CF-WS-D5-06; OQ-049, OQ-066, OQ-WS-D5-02/-03; R-2.4.5, R-2.6.x

## Context

Doc 2 §11: "A Procedure should be able to compile to instructions, a deterministic workflow node, or a subagent task depending on model profile and risk." ADR-0016 made `compile_hint ∈ {instruction, workflow_node, subagent_task}` a *surface* field "selected by profile and risk" without fixing the rule, and ADR-0019 requires that compile time decide "existence, identity, shape, layout, policy, budget and mode" with expressiveness gaps surfacing as errors, never silent fallback. The audit (dossier §4) shows the three targets living apart in different systems: every harness delivers skills as instructions (one `Text` body; gemini `activate-skill.ts`, opencode `tool/skill.ts`, OpenHands `invoke_skill.py`); AFlow/ADAS execute procedures as code graphs (`round_N/graph.py`; archive `{thought, name, code}`); hooks run scripts at decision points (codex `hook_runtime.rs`; Claude SDK `PreToolUse`); subagents run clean-context tasks (F3). No system chooses among them by rule; the choice is whichever mechanism the author reached for. Evidence for a deterministic-versus-model-owned default is split (S-065, S-070, `provisional`), and the Skill Imitation Trap (S-WS-D5-01, `provisional`) shows the choice interacts with retrieval quality.

## Options considered

1. **Author-chosen `compile_hint` only** (a free field). *Rejected:* a hint the compiler cannot honour becomes silent degradation (ADR-0019 forbids); no Lab factor.
2. **Always `instruction`** (the industry default). *Rejected:* forfeits deterministic execution of fully bindable procedures and makes `followed` judged-only; hook bodies and composite surfaces (ADR-0022) need the plan form.
3. **Always `workflow_node` where possible, by profile branch in the compiler.** *Rejected:* per-model branches in code are T-LCD-01 defects; the deterministic default's benefit is an empirical interaction (T-LCD-09), not a given.
4. **A total, pure selection rule over three kernel-computed predicates (bindable, risk, isolation-needed), honouring an author override only when feasible, with typed refusals, a `procedure_target` profile rule kind (debt-recorded) for model-conditioned overrides, the target recorded in the bundle as a Lab factor, and a risk floor that never changes an effect's authority (chosen).**

## Decision

1. **Predicates (kernel, pure, on the sealed Procedure `P`).** `B(P)` *bindable*: every `Invoke` fully bound from `parameters`, prior step outputs with closed schemas, or constants; every `Branch` predicate is a checkable `Predicate` or `Ref<Validator>`; every `Loop` Budget-bounded; `Instruction` steps only as bodies of bounded `model_call` sub-steps with closed output schemas. `R(P)` = `max_by_danger` over `effective_risk_class` of `P.effects` (ADR-0031). `I(P)` *isolation-needed*: `P` contains `Delegate`, or `size(body) > profile.procedure_inline_budget`, or `target_override = subagent_task`, or the definition's context policy marks `P` isolated.
2. **Rule (total).** (i) honour `target_override` if feasible, else `TargetInfeasible(P, hint, reason)`; (ii) `workflow_node` if `B(P)` and the bound control strategy declares `workflow_execution`; (iii) `subagent_task` if `I(P)` and the definition binds subagents and the profile declares `subagents`; (iv) `instruction`, unless `size(body) > procedure_inline_budget` with no subagent path — `UnexpressibleSurface(P, profile, exceeds_inline_budget)`. (v) **Risk floor:** if `R(P)` contains `irreversible` or `scope = external`, `expected_evidence ≠ ∅` is mandatory (`ProcedureUnverifiable`) and every such `Invoke` passes Π at the proposer's effective authority — the target never changes who may command an effect.
3. **Lowerings** (ADR-0019 stages 2–3, each with `hir_node_id` and a total trace map): `instruction` → `procedure_body` `ContextItem` rendered by the profile's `procedure_render` rule (index + `Text` leaves + typed step listing via `SurfaceArgMap`); referenced Validators stay kernel obligations at `verify`; β(`plan`, `act`) = model. `workflow_node` → `RuntimePlan/1` nodes (`step`, `branch-on-validator`, `loop`, `delegate`, `stop-rule`); β(`act`, `verify`) = code. `subagent_task` → `Delegate` to an `AgentProcess.native` child (Goal = `P` + bound parameters; `Permission ⊆` grants over `allowed_capabilities`; `Budget ≤` parent; fresh context; result re-enters `≤ delegate`, `derived_from.kind = subagent_result`); hosted participants receive it via `OpaqueProcess.supplies.procedures`.
4. **Refusals (errors, never warnings):** `TargetInfeasible`, `UnexpressibleAsWorkflow(step, reason ∈ {unbound_arg, uncheckable_branch, unbounded_loop, opaque_without_interface})`, `DelegationUnavailable`, `ProcedureUnverifiable`, plus ADR-0019's `UnexpressibleSurface`.
5. **Profile conditioning.** Model-conditioned overrides live only in `ProfileRule{kind: procedure_target, owned_fields: [compile_hint], params: {selector over procedure semantic ids or tags}, debt}` — one new kind requested of ADR-0020's closed enum (CF-WS-D5-01) — and `procedure_render` / `procedure_inline_budget` are profile parameters (OQ-WS-D5-02). No per-model branch exists in the rule.
6. **Observability.** The bundle records `procedure_targets[]: {hir_node_id, target, predicates{B, R, I}, rule_id?}`; `context.artefact.delivered{kind: procedure, target}` carries it; the target is a component-level factor (T-LCD-09).
7. **Compliance detectors per target (OQ-049, procedure kind).** `activated`: expansion (D1) for `instruction`; plan entry for `workflow_node`; child spawn for `subagent_task` — all deterministic. `followed`: `instruction` → deterministic `trace_predicate` "≥1 subsequent `Invoke` of an `allowed_capabilities` member or read of a bundled artifact with the procedure's `delivery_id ∈ causes[]`" (codex implicit-invocation precedent); `workflow_node` → by construction; `subagent_task` → the child's outcome class. Judged following (G3) is optional and labelled `judged`.
8. **Default under uncertainty.** Until Stage-3 interaction data exists, rule (ii) is the default; the Lab's first procedure experiment is `target ∈ {instruction, workflow_node} × profile` (OQ-WS-D5-03).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: the three forms exist separately in production and research — instruction delivery in every audited harness (S-107/S-110/S-111/S-112/S-113/S-119/S-117); workflow-as-code with a closed operator vocabulary (S-025 AFlow; S-170 ADAS); decision-point scripts (S-107 hooks; S-109 hook outputs); clean-context delegation (doc 2 §5.7, Tier B; S-047); deterministic envelopes around stochastic cognition (doc 2 §5.4, Tier B); model-conditioned behaviour of the same artifact (S-088 mechanism, `provisional`; S-049 Tier B); execution-alignment failures when the model narrates rather than executes (S-062, `provisional (mech)`); the LCD antidote "declare + per-target compile + typed errors" (ADR-0007 evidence, S-152/S-035/S-153).
- (b) Source-code precedent: `gemini-cli/packages/core/src/tools/activate-skill.ts` L100–150 (instruction delivery as a tool result, S-119 @ed2ac40); `AFlow/scripts/optimizer_utils/graph_utils.py` L26–60, L115–140 (procedure as executable graph per round, S-025 @3f45721); `codex-rs/skills/src/invocation.rs` L27–80 and `core/src/skills.rs` L121–209 (implicit invocation detection = `followed` detector, S-107 @0735c51); `codex-rs/core/src/tools/spec_plan.rs` (compile-time plan vs surface stages, via ADR-0019). The total selection rule, the predicates and the risk floor are `no-precedent / novel`.
- (c) Disconfirming evidence considered: (i) deterministic execution loses the flexibility that makes skills valuable (S-065/S-070 split, `provisional`) — answered: `workflow_node` is chosen only when every step is bindable, and the target is a measured factor, not an assumption; (ii) the Skill Imitation Trap gets worse if a wrong procedure executes deterministically — answered: checkable preconditions gate `workflow_node` entry (`PreconditionFailed` → handlers) and the risk floor keeps Π in the loop for dangerous effects; (iii) a closed enum of rule kinds will lag (ADR-0020 (c)) — answered: one kind is requested by ADR, the ADR-0020 mechanism. None overturns.
- (d) Conditionality: assumes profiles declare `subagents` and control strategies declare `workflow_execution` (Stage 3–4 capabilities); assumes F3 delegation exists for target (iii) — before Stage 4 the rule degrades to (ii)/(iv) with `DelegationUnavailable` as the honest refusal; independent of model tier; the deterministic default is a hypothesis to be tested (OQ-WS-D5-03).
- (e) Build-stage assignment: **C0 / Stage 2** (`instruction` target; predicates computed and recorded; refusals); **C1 / Stage 3** (`workflow_node`; `procedure_target` rule kind; deterministic `followed` detector; the two-factor Lab experiment); **C2 / Stage 4** (`subagent_task`; hosted `supplies.procedures`).

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-01 (no model identity in the rule; overrides are profile rules), T-LCD-04 (one Procedure → three lowerings with identical permission/effect/budget tables from one `RuntimePlan`), T-LCD-05 (`procedure_target` rules carry debt records), T-LCD-09 (target is an explicit factor), T-LCD-13 (deterministic `activated`/`followed` per target), T-LCD-15 (hosted procedure metrics `n/a` at component level). Does not by itself satisfy T-LCD-03 (Stage 3 executable, AC-D5-4) nor T-LCD-11 (ADR WS-D5-adr-3). **ADR-0024 rung:** `workflow_node` is the entity→variant transition (rung 3→4).

## Consequences

- WS-A4: stage 2 gains `select_target`; stage 3 gains `procedure_render`; the bundle gains `procedure_targets[]`.
- WS-C3: `procedure_target` enters the rule inventory (ADR-0020 amendment requested); `procedure_inline_budget` and `procedure_render` are profile parameters.
- WS-F1: β assignments for procedures are derived from the target; hooks' actions are `workflow_node` procedures (ADR WS-D5-adr-3 §6).
- WS-F3: `Delegate` from a `subagent_task` uses the F3 spawn contract with attenuation.
- WS-G1: the trace-predicate detector family; WS-I2: `followed` for procedures is deterministic for two of three targets.
- WS-E2: a composite surface's mapping is a `workflow_node` procedure; if `B(P)` fails it is inadmissible at C0 (OQ-066 partial answer).

## Reversibility

**High** for the default order of rules (ii)–(iv) (a policy edit); **medium** for the predicate definitions (changing `B` re-labels existing bundles); **low** for "typed refusal instead of fallback" (shared with ADR-0019).
