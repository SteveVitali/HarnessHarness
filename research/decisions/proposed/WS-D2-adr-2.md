# ADR-NNNN — Provenance and validity of compaction derivations, and the three homes of model-conditioned compaction: summaries are `delegate`-derived and never authoritative; offloads and deterministic restructures preserve labels; conditioning lives only in variant parameters, conditioned `HarnessRule`s and `ProfileRule{compaction_reminder}`; model-owned compaction is a variant with β(compact) = model

**Status:** proposed
**Owner workstream(s):** WS-D2 (consumers: WS-D1, WS-D3, WS-D4, WS-C3, WS-C1, WS-F1, WS-H1, WS-I5, WS-I6, WS-J6) · **Phase:** 2 · **Related:** ADR-0016 (`HarnessRule.action = set compaction policy`, `conditioned_on`, `Artifact`, `Memory`), ADR-0020 (`ProfileRule{kind: compaction_reminder}`, `role_map`, closed rule kinds), ADR-0014 (three-valued validity), ADR-0033 (minting rules: `environment` only for closed-schema closed-world values; `delegate` for every AgentProcess output), ADR-0034 (P1 derivation, P3 context label, P6 never-widen, P7 lifting), ADR-0035 (endorsement list; `promotion`), ADR-0037 (supersession), ADR-0045 (`opacity_dynamic`), WS-D1 ADR-1/-3 (proposed: I-RP, reserved slots, `role_map` rendering); CF-WS-D2-01/-04/-07; OQ-104, OQ-105, OQ-067, OQ-WS-D2-02/-04/-08; R-2.4.2, R-2.4.4, R-2.3.3

## Context

A compaction summary is the archetypal derivation ADR-0034 P1 governs ("summaries, compactions, extractions … where an untrusted source is laundered into a fresh, apparently model-authored artifact"). Every audited implementation raises the summary's standing: OpenHands stamps `Condensation.source = "environment"`; goose re-roles it `User`; gemini inserts it as a `user` turn with a fabricated `model` acknowledgement; Codex prefixes "Another language model started to solve this problem" and renders it as a user fragment; opencode records an assistant message with `summary: true`. Only OpenHands names the forgotten ids; none carries validity. Model-conditioning of compaction is likewise real and pervasive — Codex `models.json.token_budget` per model, gemini's `switch` selecting a per-model summariser, Anthropic's model-specific thinking-retention defaults, "the model is trained to see the compaction summary as the last item" — and doc 2 §5.1 records that such rules go stale (S-047, S-049). Model-owned compaction exists in production (Codex `notes` + `new_context`) and in the literature (MemGPT paging; Context-Folding/AgentFold folds, `provisional`). The brief requires "a summary is a derivation with lower authority than its sources".

## Options considered

1. **Summaries inherit the authority of the highest input (or `environment`, OpenHands).** Rejected: contradicts ADR-0033 minting (`environment` is closed-schema closed-world only; every AgentProcess output is `delegate`) and reproduces S-103's X-CPE (session content re-entering above its origin).
2. **Summaries are always `unverified`.** Rejected: over-strict — `unverified` is reserved for imported/lifted/attestation-failed content (ADR-0033); a summary of `definition`-authored items produced by the run's own model is legitimately `delegate`, and a summary of `external` items is `external`; the join already yields the right answer.
3. **Model-conditioning as a `compaction_policy` field on the profile, or per-model branches inside variants (gemini `switch`).** Rejected: the first needs a new closed `ProfileRule` kind that would let a profile write non-surface behaviour (ADR-0020 forbids); the second is the T-LCD-01 defect.
4. **Derivation by the ratified join with per-op deriver; three fixed homes for conditioning; model-owned compaction as a variant with β = model (chosen).**

## Decision

1. **Per-operation provenance (ADR-0034 P1 applied).** `Summarize` and `Restructure{extractor: model}` outputs are `derive(kind = compaction, inputs = forgotten items, deriver = delegate, deterministic = false)`: `authority = min(⊔ inputs, delegate)` — **never above `delegate`**, taint = ∪ inputs, `readers` = ∩ inputs, `derived_from` = the forgotten ids + `model_call_id` + `instructions_ref`. `Offload` and `Restructure{extractor: deterministic}` outputs are `derive(kind = projection, deriver = kernel, deterministic = true)`: label = ⊔ inputs (unchanged). `Evict` produces only the kernel omission item (`kernel` authority, a `Text` leaf of the sealed definition).
2. **Validity.** A model-produced summary or checkpoint has `validity = unknown` (ADR-0014) until a `Validator` sets it; it is never `valid` by construction. A deterministic restructure whose projection is total is `valid`. A summary written into memory (D3/D4) enters at its derived label with `scope ≤ run` unless a ledgered `promotion` (ADR-0035) raises it; X-CPE is impossible by construction.
3. **Placement.** The summary is a `ContextItem{payload: Artifact{kind: compaction_summary | compaction_checkpoint}}` admitted only into slots with `min_authority ≤ delegate` (the `transcript` or `external` reserved slot, WS-D1); its rendered provider role is `role_map(authority)` (ADR-0034 RP; C3). Any "prior work" preamble (Codex `SUMMARY_PREFIX`, gemini's acknowledgement) is a profile-owned demotion/annotation wrapper — a `Text` leaf with an assumption-debt record (OQ-104/OQ-WS-D2-02), never an authority.
4. **Label reset (OQ-105, with WS-D1).** Eviction or offload of `external` items restores the next call's context label; a summary of `external` items is `external` with the union taint and does *not* restore it; the compaction record states `context_label_after` for both cases. Isolation (a fresh sub-agent context, ADR-0034 P2) remains the only other reset.
5. **Opacity and compliance.** The summary's text counts in `opacity_dynamic` (ADR-0045); the compaction prompt (`instructions_ref`) is a `Text` leaf in the static opacity report and on the migration ladder (ADR-0024: prose → parameterised schema-typed `Restructure`); summary and omission items are delivered artifacts (`context.artefact.delivered`) so *following* a summary is a compliance measurement (T-LCD-13).
6. **Three homes of model-conditioning, no fourth.** (i) **Variant parameters** bound in the Harness Definition (`keep_recent_tokens`, `reserve_tokens`, `summarizer_profile: ProfileRef`, `retain_principal_tokens`, `max_summary_tokens`, `retained_image_count`, `thinking_retention`, `input_reduction`, `target_fraction`); (ii) **definition-level conditioned rules** `HarnessRule{trigger: profile predicate, action: set compaction policy{param overrides | soft threshold}, conditioned_on: ProfileRef, assumption_debt}` (ADR-0016 entity 13 — Codex `token_budget` per model is the precedent shape, now with a debt record and expiry); (iii) **profile-level surface rules** `ProfileRule{kind: compaction_reminder}` for reminder text and placement, `transcript_render` for summary position and thinking-block handling, and `role_map` for the rendered role (ADR-0020). `summarizer_profile` makes "which model summarises" a component-level factor and a member of the run's *model set* (ADR-0012). A variant containing a model-identity branch fails registration (T-LCD-01); gemini `modelStringToModelConfigAlias` is the named defect.
7. **Model-owned compaction.** A variant may declare `control_boundary_compact = model` (Ontology v1 β(compact) = model): its ops are proposed by the model through declared `ToolCapability`s (`offload_note` → `Offload`/`memory_write`, `new_window` → `Evict{all optional}`, `fold` → `Summarize + Evict`), each invocation an effect the reference monitor evaluates; the kernel applies every ADR-NNNN invariant (I-REQ, I-NOWIDEN, I-CUT, I-RECLAIM) to what the model proposes and refuses violations with `PolicyViolation`. The reminder that prompts the model (Codex `reminder_message_template`) is a `ProfileRule{compaction_reminder}` with a debt record. β is thereby a component-level Lab factor (WS-F1 to confirm ownership, OQ-WS-D2-04).
8. **Provider-side compaction** (`compact_20260112`, Codex remote) is a variant whose `execute` delegates to a gateway capability the profile declares; the summary it returns is `delegate`-derived with `derived_from` = every block before the returned compaction block; if the provider cannot report the forgotten set, the ledger records the full pre-compaction view hash and marks `forgotten = {range: all_prior}`; the loss is listed in the profile's lowering loss report (T-LCD-11, OQ-WS-D2-05).

## Consequences

- WS-D1 admits summaries only into `transcript`/`external`; WS-C3 owns their rendered role and any preamble wrapper (with debt records); WS-D3/D4 receive summaries as `≤ delegate`, `scope ≤ run` memory candidates.
- WS-H1's `effective_authority` sees a summary as `delegate` at best; a run whose only instructions are a compacted summary of external content proposes at `external`.
- WS-I6's debt manager and WS-I5's optimiser treat compaction prompts as `Text` leaves and thresholds as parameters; ACON-style guideline optimisation is a C4 experiment over a leaf, under `SearchBudgetRecord`.
- WS-F1 gains a component-level factor β(compact) ∈ {code, model}.
- WS-J6 lifts hosted compaction markers as `participant`/`unverified`.

## Reversibility

**Low for the derivation rule** (it is ADR-0034 P1 applied; reversing it reverses the authority scheme). **Medium for the three-home rule** (a future `ProfileRule` kind for compaction policy would need an ADR amending ADR-0020's closed enum and a migration of conditioned `HarnessRule`s). **High for model-owned compaction's placement** (moving it to F1 is a class-record change; the contract and invariants are unchanged).
