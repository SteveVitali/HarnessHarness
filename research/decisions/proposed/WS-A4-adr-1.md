# ADR-NNNN — Staged, pure, content-addressed compilation of HIR; compiled control structures are runtime-interpreted data; the closed-world rule; re-lowering on model switch

**Status:** proposed
**Owner workstream(s):** WS-A4 (consumers: WS-A3, WS-A5, WS-B1, WS-C1, WS-C3, WS-D1, WS-E3, WS-F1, WS-I3, WS-L1, WS-L4) · **Phase:** 1 · **Related:** ADR-0003, ADR-0005, ADR-0007 (T-LCD-01/-02/-05/-10/-11/-12/-13), ADR-0008, ADR-0009 (Q-L1-07), ADR-0011; WS-A3-adr-1 (canonical form, two-id identity), WS-A5 (`ResolvedDefinition`); CF-WS-A4-01, CF-WS-A4-07; OQ-043, OQ-041, OQ-WS-A4-01, OQ-WS-A4-05, OQ-WS-A4-10; R-2.1.3, R-2.12.1

## Context

Doc 2 §11 asks for a runtime that "compiles the IR into model-facing context and executable control structures" and for a control plane separated from the execution plane; doc 3 §5 asks WS-A4 to fix the compilation stages, the compile-time/run-time split, determinism and content addressing, and traceability from compiled artefacts to IR nodes. WS-L1's ratification questionnaire (Q-L1-07) needs to know whether compiled control structures are data interpreted by the runtime or code emitted in a host language, because the answer decides whether the kernel language is also the compile-target language. The source audit (WS-A4 dossier §4) found that every mature harness already contains an unnamed compiler with three consistent boundaries — plan (what exists for this model), surface (how it is rendered) and transport (how bytes go out) — that none of them content-addresses its compiled surface, none records a mid-run model switch as a surface change, and that model-conditioned transcript transforms are applied every turn (opencode `normalizeMessages`, goose `thinking_block_is_stale`, pi `downgradeUnsupportedImages`). Reproducible-builds practice and Nix RFC 0062 supply the engineering meaning of determinism and of input- vs content-addressed identity; MLIR supplies the precedent for provenance threaded through progressive lowering.

## Options considered

1. **No explicit compiler — the runtime interprets HIR directly and each provider adapter renders surfaces on the fly** (goose/opencode shape). *Rejected:* the compiled surface has no identity, so delivered/activated/followed events (T-LCD-13) cannot name what the model saw; profile knowledge migrates into adapter code branches (T-LCD-01 failure signature); no reproducibility.
2. **Compiler emits host-language code** (Agent Spec → LangGraph graphs; DSPy `save_program=True` pickles). *Rejected:* ties the compile target to the kernel language (Q-L1-07 penalty), makes artefacts non-portable and unsafe to load (DSPy's own warning that saved programs "can run arbitrary code"), and defeats out-of-process implementability (T-LCD-12).
3. **Single-stage compiler (definition + profile → provider request)** with no intermediate runtime plan. *Rejected:* policy/budget tables would be re-derived per profile and per target, so T-LCD-04's "permission/effect/budget invariants identical across targets" becomes a hope rather than a construction.
4. **Staged pipeline — accept → link → lower-native → lower-profile → lower-target(s) → seal — as a pure function of declared inputs, emitting runtime-interpreted data with a total trace map and two content addresses; compile time decides existence/identity/shape/layout/policy/mode, run time decides selection/filling/ordering/triggering/authority/transcript rendering; a mid-run model switch is an explicit re-lowering (chosen).**

## Decision

1. **Input.** The compiler consumes WS-A5's `ResolvedDefinition` (= WS-A3's *sealed definition*: every reference pinned to a `version_id`, ids computed, secret-free, canonical). It does not re-implement `validate`; a non-sealed or non-canonical input is refused (`NotSealed`, `NonCanonicalInput`).
2. **Stages** (each a pure operation on typed documents; the pipeline is itself a `Compiler` component class, T-LCD-08/-12): **0 accept** → **1 link** (bind profile chain and target specs — profile is a configuration coordinate bound here, not in the definition; refuse any conditioned rule lacking a complete assumption-debt record, T-LCD-05) → **2 lower-native** → `RuntimePlan` (closed plan-node kinds; tool table; policy tables derived only from `Permission`/`EffectClass`/`Budget` entities; every node carries `hir_node_id`) → **3 lower-profile** → `ModelSurface` (static surface + transcript renderer spec; `UnexpressibleSurface(entity, profile, reason)` is an error) → **4 lower-target** → `(TargetArtefact, LoweringLossReport)` per target → **5 seal** → `CompiledBundle`.
3. **Compiled control structures are runtime-interpreted data** (answer to OQ-043 part 1 / Q-L1-07): `RuntimePlan/1` is a versioned, closed set of plan-node kinds interpreted by the reference runtime; the compiler never emits host-language source. Expressiveness gaps surface as `PlanError{unsupported_construct(node)}` and are resolved by component variants behind class contracts (WS-A5) or a dialect bump — never by an escape hatch.
4. **Purity and two identities.** `compile(inputs) → bundle` reads only its declared inputs (definition `version_id`, variant digests, profile hashes, target-spec versions, compiler version); no clock, randomness, environment or network. `derivation_key = H(canonical(inputs))` (input address; caching and early cut-off) and `bundle_id = H(canonical(outputs))` (content address; experiment identity, WS-I3 bundle). Canonical form = WS-A3's JCS-class form; any target-relevant ordering is represented as array order, never object-key order.
5. **Trace map is total.** Every model-facing token span and every emitted target field resolves through `trace(bundle, locator) → {hir_node_ids[], rule_ids[], target_rule_ids[]}`; WS-B1's `context.artifact.delivered.rendering_ref` is `{bundle_id, locator}`.
6. **Closed-world rule.** Compile time decides *existence, identity, shape, layout, policy, budget and mode*; run time decides *selection* (deferred loading, tool search), *filling* (declared slots: cwd, date, task text, retrieved items), *ordering within declared layout*, *triggering* (compaction, reminders, retries, stop rules), *authority* (reference monitor) and *transcript rendering* under the compiled renderer spec. No run-time operation may deliver to a model, or expose to an external system, an artefact without a compiled identity.
7. **Re-lowering.** A mid-run model-binding change (router fallback, user switch) is `relower(bundle, new_profile)`: stages 3–5 re-run, `runtime_plan` unchanged, a new `bundle_id` is issued, the new transcript renderer is applied (profile-opaque items such as another model's reasoning signatures are dropped or rewritten per OQ-WS-A4-05), and `model.surface.relowered{old_bundle_id, new_bundle_id, old_profile_ref, new_profile_ref, dropped_items[], rewritten_items[]}` is appended to the ledger (WS-B1).
8. **Host-ecosystem requirements** (for WS-L1, no language named): deterministic canonical serialisation + hashing for schema-described documents; first-class JSON-Schema manipulation (subset transforms, inclusion checks, validation); an interpreter for a small typed plan language with exhaustive handling of node kinds; the compiler runnable out-of-process exchanging typed documents.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: the three-boundary structure of production harnesses (S-107 codex plan/serialise split; S-112 goose `Provider::stream` above `formats/*.rs`; S-111 opencode; S-113 pi typed `compat` + request builders); transcript surfaces re-rendered per model per turn (S-111 `normalizeMessages`, S-112 `thinking_block_is_stale`, S-113 `transform-messages.ts`); compile-then-freeze as the mechanism that makes harness edits testable and transferable (S-013/S-144 `Teleprompter.compile` + `dump_state`; S-WS-A4-03 Life-Harness, `provisional`, mechanism only); determinism and dual identity (S-WS-A4-06 reproducible builds; S-WS-A4-07 Nix RFC 0062); provenance through lowering (S-WS-A4-04 MLIR, Tier A); model-conditioned surfaces exist and matter (S-049, S-047, S-037, S-WS-A4-02 ACL 2026).
- (b) Source-code precedent: `codex-rs/core/src/tools/spec_plan.rs` L273–360, L531–600, L1255–1258 and `codex-rs/tools/src/tool_spec.rs` L22–140 (plan vs serialisation stages, S-107 @0735c51); `crates/goose-provider-types/src/base.rs` L464–530 + `formats/anthropic.rs` L110 (S-112 @fae91d0); `packages/opencode/src/provider/transform.ts` (S-111 @9f8db11); `dspy/teleprompt/teleprompt.py` L64, `dspy/primitives/base_module.py` L156–194 (S-144 @ca54a85); `pyagentspec/.../adapters/langgraph/_langgraphconverter.py` L210–304 (per-kind converter table, S-139 @6f0b6ae). The integrated pipeline with a content-addressed bundle, total trace map, closed-world rule and re-lowering event is `no-precedent / novel` (no audited system content-addresses its compiled surface or records a model switch as a surface change).
- (c) Disconfirming evidence considered: (i) the most capable 2026 control strategies are code-shaped (code-mode in codex/opencode; S-065 agentic programming, `provisional`) — answered: that code is *model-authored* and sandboxed, a C2 target surface, not host-language output of the compiler; DSPy's pickled programs show why interpreted data is safer and portable. (ii) Determinism of compilation does not reproduce a stochastic run and prompt caches make byte layout cost-relevant — answered: compiler determinism is necessary not sufficient (doc 2 §8 bundle adds model snapshot/seeds/traces), and byte-stable prefixes are what makes caching work, hence derivation key vs bundle id. (iii) A closed plan-node set may hit the expressiveness ceiling (OQ-002) — answered: `PlanError` is an error, variants absorb the gap (WS-A5), dialect bumps extend the set. None overturns.
- (d) Conditionality: independent of model tier and task class; assumes profiles stay necessary (if frontier tool conventions converge, stage 3 shrinks but the pipeline stands); assumes WS-A3's canonical form and WS-A5's `ResolvedDefinition` ratify as proposed; C0 admits `native_fc` interaction mode only.
- (e) Build-stage assignment: **C0 / Stage 1** (stages 0–2 and 5; `RuntimePlan/1`; trace map; derivation key + bundle id; static `lcd_report` parts); **C0 / Stage 3** (stage 3 with two minimal profiles, stage 4 with two targets, `relower`, executable T-LCD-03/-04/-11); C1/C2 extensions per WS-A4-adr-2/-3/-4.

**T-LCD statement (ADR-0007 decision 5).** Satisfies: T-LCD-01 (profile-owned diff is checkable per bundle), T-LCD-02 (opacity report stored in every bundle via WS-A3's `opacity`), T-LCD-05 (link refuses undocumented conditioned rules), T-LCD-10 (bundle identity is content-derived; rename changes profile hash only), T-LCD-11 (loss report per target), T-LCD-12 (compiler is an operation-shaped, out-of-process-capable component), T-LCD-13 (every delivered artefact has a compiled identity). Does not by itself satisfy T-LCD-03/-04 (executable at Stage 3) — mitigated by AC-7/AC-8 of the dossier and the equivalence-run gate.

## Consequences

- WS-A5's `export(resolved, target)` is this compiler's stages 1–5; WS-A5's `validate` stage (6) propagates `UnexpressibleSurface`.
- WS-B1 adds `model.surface.relowered` and types `rendering_ref` as `{bundle_id, locator}`; `lifecycle.run.created.manifest` carries `bundle_id` alongside `model_profile_ref`.
- WS-D1 executes the transcript renderer spec (ownership confirmed in OQ-WS-A4-01); WS-E3 executes `select_surfaces` under the closed-world rule; WS-C1's gateway consumes the provider request plan as data (CF-WS-A4-01).
- WS-I3's reproducible harness bundle references `bundle_id`; WS-J3's `configuration` id includes it.
- WS-L1: Q-L1-07 answered — interpreted data; the kernel language is not the compile-target language.

## Reversibility

**Medium.** Adding stages, plan-node kinds or targets is a dialect bump (`RuntimePlan/2`) with migration. Reversing "interpreted data" to "emitted code" after Stage 1 would invalidate the trace map, the out-of-process compiler and the L1 answer — the costly direction, hence decided now.
