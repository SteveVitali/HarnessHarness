# ADR-NNNN — Speculative-effect containment: risk-class-driven execution or deferral inside branches, the `deferred` phase, promotion-time re-authorization, discard as restore-plus-saga, `SpeculationPolicy` as data with a non-overridable `defer_irreversible`

**Status:** proposed
**Owner workstream(s):** WS-B4 (with WS-B2 for the `deferred` phase, WS-H1/H7 for re-authorization, WS-E5 for executor behaviour, WS-F2 for budget slices) · **Phase:** 2 · **Related:** ADR-0030, ADR-0031, ADR-0032, ADR-0034, ADR-0035, ADR-0039, ADR-0040, ADR-0024, ADR-0007 (T-LCD-08/-14/-15); OQ-090, OQ-092, OQ-WS-B4-06; CF-WS-B4-02; R-2.2.4, R-2.2.2, R-2.8.7

## Context

Doc 3 §5 asks that "only reversible/compensable effects may run speculatively". ADR-0031 already derives an `effective_risk_class` `{reversibility, repeat_safety, scope}` for every effect with "no automatic retry ever" for `irreversible`; ADR-0032 makes compensation an audited best-effort saga with an `abandoned` terminal; ADR-0035 makes an approval endorse exactly one `effect_id`. What is missing is what a *branch* does with an effect it may not run: Shepherd (`provisional`) lets irreversible effects "materialize on emission" and only records them for audit — inside a speculative branch that is the duplicate-payment attack of *Safe to Resume?* SF5 (`provisional`); Crab (`provisional`) speculates only inside the sandbox and discards or commits the fork; no audited harness defers an effect inside a branch. Revisable-by-Design (S-205, `provisional`, theorem admissible) shows the impossibility is a property of the action space, so containment must be decided by class before dispatch, not repaired after.

## Options considered

1. **Run everything in branches; rely on compensation on discard.** *Rejected:* compensation is an approximation (Sagas) and does not exist for `irreversible`; SF5 attack.
2. **Forbid all non-`read_only` effects in branches.** *Rejected:* makes speculation useless for coding tasks, whose effects are mostly `workspace_local reversible` and covered by the snapshot.
3. **Let the model decide per effect (self-reported risk).** *Rejected:* ADR-0031 forbids self-report lowering the class; gameable by injection.
4. **Block the branch at the first non-runnable effect.** *Partially adopted:* blocking is the fallback when the capability declares the effect's output is needed downstream; otherwise the branch continues with a deferred effect so best-of-K comparisons still complete.
5. **Class-driven execution/deferral table with a `deferred` phase, promotion-time re-authorization and discard as restore-plus-saga; policy as data with a non-overridable irreversible rule (chosen).**

## Decision

1. **Containment table** (by `effective_risk_class`, ADR-0031): `read_only` runs; `reversible ∧ workspace_local ∧ target ⊆ EnvSnapshot.coverage` runs and is undone by `restore` on discard (recorded as `action.effect.reverted{baseline_ref = snapshot}`); `reversible` outside coverage or `external` is treated as `compensable`; `compensable` runs only if `SpeculationPolicy.allow_classes ∋ compensable` and a `CompensationPlan` is registered at `prepare` (ADR-0032), default **deny** ⇒ deferred; `irreversible`, any non-compensable `external`, `unknown`, `message_human` and `permission_request` are **deferred**; `model_call` runs and is charged to the branch's budget slice (`attribution = subject` for harness-initiated speculation, `instrument` for Lab/I7 branches, ADR-0039).
2. **The `deferred` phase** (amends ADR-0030's lifecycle; CF-WS-B4-02): non-terminal, entered from `prepared` by `action.effect.deferred{effect_id, reason ∈ {speculative_branch, awaiting_promotion}, branch_id}`, left only to `committed` (on promotion, after fresh authorization) or `refused{branch_discarded}` (on discard/abandon). A deferred effect is never `committed` inside the branch; the model receives an explicit "deferred until this branch is promoted" observation and never a fabricated success (WS-G2 treats it as not applied). The branch continues past a deferred effect only if the capability declares its output non-blocking; otherwise the branch pauses `awaiting_promotion`.
3. **Promotion releases, never inherits.** On `promote`, deferred effects are re-authorized with a fresh `security.permission.decided` (an approval on the parent never covers a branch effect — new `effect_id`s, ADR-0035), then `committed` in branch order; a refused release yields `refused` and the promotion still completes.
4. **Discard = restore + saga.** Applied effects on a discarded branch are undone in reverse commit order: `reversible` by the environment restore, `compensable` by `compensate` (failure ⇒ `abandoned` + escalation), `deferred` ⇒ `refused`; the disposition lists `compensated[]` and `uncompensable[]`; any `irreversible` effect found `observed(applied)` on a discarded branch is an `uncompensable[]` entry that is always escalated and audited (it can only arise from misclassification and is a defect signal).
5. **Policy as data with a hard floor.** `SpeculationPolicy{allow_classes, require_compensator = true, max_concurrent_branches, budget_fraction, coverage_required, defer_irreversible = true}` is a `HarnessRule`-class artifact (MUST-data, ADR-0024) whose delivery/activation/following is measurable; `defer_irreversible` is not overridable by any composition layer (`authority_cap`, ADR-0024) or by evolution (`authority_delta = widening` is unacceptable, ADR-0017/0046). A branch may only narrow its parent's policy (OQ-WS-B4-06 asks whether a human may widen mid-run).
6. **Authority, budget and detached processes.** A branch inherits the parent's `context_label` and permissions attenuated (ADR-0034); its spend posts to a `slice` with reserve-before-spend and root-first exhaustion (ADR-0040) — exhaustion disposes the branch `abandoned{budget_exhausted}` after open effects close; detached processes started on a branch are terminated on discard and re-parented on promote (WS-E5 confirms, OQ-090).

**T-LCD statement.** Satisfies T-LCD-08 (the policy is a component-contract input receiving `(ModelProfile, ResourceAccount)`; per-model speculation variants live inside the contract), T-LCD-14 (branch spend is budgeted per slice; `n/a` never 0 for undeclared participants), T-LCD-15 (deferred/compensated counts are class-scoped process metrics), T-LCD-06 (no native change for hosted participants — a hosted participant without `fork` never has branches), T-LCD-02 (the deferral observation is a typed record, not free text). Not applicable: T-01/-03/-04/-05/-09/-10/-11/-12(satisfied by the companion ADR)/-13. **ADR-0024 rung:** the table, the `deferred` phase and release/discard are MUST-code; `SpeculationPolicy` values are MUST-data.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** S-078 Shepherd (`provisional`; three tiers; irreversible effects "materialize on emission, and the stream can only record them for audit"); S-WS-B4-02 *Safe to Resume?* (`provisional`; SF5 duplicate payment when rollback removes the record of a committed external action; lesson: bind progress to "durable effect records"); S-WS-B4-01 Crab (`provisional`; speculative action execution confined to the forked sandbox: "discard or commit the fork"); S-205 Revisable-by-Design (`provisional`, theorem: conflicting irreversible actions defeat every algorithm); S-197 Sagas (Tier A; compensation is a semantic approximation, coordinator records reliably); S-053 approval-fatigue telemetry (Tier B; why the human gate on `compensable` speculation is weak and the default is deny); ADR-0031/0032/0035 (the ratified classes, saga and approval scope this projects).
- **(b) Source-code precedent:** codex S-107 @0735c51 `codex-rs/core/src/tools/orchestrator.rs` L121–540 (approval → sandbox → attempt lifecycle the deferral slots into), `core/src/tools/sandboxing.rs` L70–111 (`ApprovedForSession` cache keyed on canonical action — why branch approvals are re-requested rather than inherited), `core/src/context/turn_aborted.rs` (model-facing "may have partially executed" — the shape of the deferral observation); software-agent-sdk S-110 @3fc7b22 `openhands-sdk/openhands/sdk/security/confirmation_policy.py` (`ConfirmRisky` with incomparable `UNKNOWN` — `unknown ⇒ defer`); opencode S-111 @9f8db11 `packages/opencode/src/snapshot/index.ts` `revert(patches)` (mechanical undo of workspace effects on discard). Deferral of effects inside a branch with promotion-time release: `no-precedent / novel` (partial precedent: Shepherd's audit-only tier; Crab's commit-or-discard of a sandbox fork).
- **(c) Disconfirming evidence considered:** Sagas guarantee only approximation, compensators fail, and rate-limit/notification residue survives a compensated PR (why it does not overturn: default deny for `compensable`; opt-in requires a registered compensator and every compensation is listed on the disposition); deferral may starve a branch whose next step needs the deferred output (why not: the branch pauses `awaiting_promotion` — an honest partial result the Lab can score as `budget_exhausted`/`cancelled`, not a fabricated one); approval fatigue means re-authorization on promotion adds prompts (why not: promotion is rare relative to speculation, ADR-0035 forbids inheriting an approval across `effect_id`s, and WS-H7 may cache by canonical action pattern, not by branch).
- **(d) Conditionality:** independent of model tier; assumes ADR-0031's kernel-assessed classification is available before dispatch (shell-command classification quality is OQ-086's, WS-H1/E5); assumes a snapshot with declared coverage exists for the `reversible` row (companion ADR); the `instrument` attribution assumes the Lab opened the branch (ADR-0039 `charged_to`).
- **(e) Build-stage assignment:** `deferred` phase, `action.effect.deferred` event class and the containment table's *schema* — C0 / Stage 2 (with the companion ADR's slice); execution of the table with concurrent branches, promotion release and discard saga — C2 / Stage 4; fault-injection tests AC-B4-5/-6 joined with WS-B2 AC-B2-01 — Stage 3 suite (they exercise the schema before Stage 4 lands the concurrency).

## Consequences

- WS-B2's ADR-0030 lifecycle gains one non-terminal state; the "every commit resolves" invariant is untouched because a deferred effect is never committed.
- WS-E5 executors must accept a `deferred` outcome for a prepared effect and must not dispatch it; they report detached processes per branch.
- WS-H7 re-issues approvals on promotion; WS-H6 audits every `uncompensable[]` and every release.
- WS-G2 blocks or annotates completion claims that depend on a `deferred` effect (OQ-092).
- WS-J4 reports branch spend and deferred/compensated counts as class-scoped process metrics.

## Reversibility

**Medium.** Allowing `compensable` by default later is a policy default change (MUST-data); removing the `deferred` phase would force option 1 or 4 and re-open SF5 — not recommended; the hard floor `defer_irreversible` is the one line that should never be reversed without a superseding ADR citing new evidence.
