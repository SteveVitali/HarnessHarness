# ADR-NNNN — The control envelope is Core kernel code interpreting one sealed `EnvelopePolicy` record: six enforcement points on the harness step, a closed `StopReason` sum with outcome-class projection, and stop as barrier + drain

**Status:** proposed
**Owner workstream(s):** WS-F2 (consumers: WS-F1, WS-F3, WS-B1, WS-B3, WS-D2, WS-E4, WS-E5, WS-G2, WS-H1, WS-H6, WS-H7, WS-I1, WS-I2, WS-J5, WS-J6, WS-K1) · **Phase:** 2 · **Related:** ADR-0012 (β, harness step), ADR-0016 (`ControlBoundary{assignments, guards}`, `DecisionPoint`, `Loop` bounded by Budget; OQ-051), ADR-0019 (`RuntimePlan/1` `stop-rule` and `budget envelope` nodes; closed-world rule), ADR-0023/0024 (MUST-data / MUST-code; ladder), ADR-0026/0027 (ledger authoritative; scope terminals; `control.*` classes), ADR-0030 (effect terminals incl. `unknown`; every commit resolves), ADR-0033 (`kernel`/`definition` authority of envelope-produced items), ADR-0035 (no widening), ADR-0039/0040 (dimensions; hard ceilings fire only at decision points; root-first; `ask → deny`), ADR-0042 (scope kinds), ADR-0045 (outcome classes), ADR-0050 §8; CF-005, CF-061, CF-WS-D2-05/-06, CF-WS-F1-01/-03, CF-WS-F2-01/-02/-03/-06/-07; OQ-051, OQ-062, OQ-092, OQ-119, OQ-WS-F2-02/-06; R-2.6.2 (owner); constrains R-2.6.1, R-2.6.3, R-2.7.2, R-2.8.7, R-2.9.2

## Context

Doc 2 §4 fixes the design principle — hard invariants in deterministic software, open-ended search in the model — and §11 names the Stage-1 "control envelope" (explicit token/tool/time budgets, retry/timeout, stop conditions, idempotency, schema validation). Phase 1 typed the pieces: `ControlBoundary{assignments, guards}` on `AgentProcess.native` (ADR-0016; OQ-051 left the representation of `guards` open), hard ceilings that fire only at decision points and end the run with `stop_reason = budget_exhausted` after open effects close (ADR-0040), a closed effect terminal set with explicit `unknown` (ADR-0030), and outcome classes on the scorecard (ADR-0045). Phase-1 §6.9 assigned WS-F2 "implements `check`/`reserve` and the exhaustion rule". WS-F1 (concurrent) fixed the seam: the strategy *proposes*, the envelope *checks*, the driver *executes* (WS-F1-adr-1 I5: `authorize`, budget/context/cancel stops and infrastructure retries are always `code`).

What remained undecided was (i) the **typed content** of `guards` and whether it can reference models or text; (ii) **where** on the harness step the envelope runs relative to `authorize` (WS-H1) and `interpret`; (iii) the **closed vocabulary of stop reasons** that WS-D2 (`context_exhausted`), WS-H7 (`approvals_exhausted`), WS-E4 (ACP lowering) and WS-I2 (outcome classes) each began spelling independently; (iv) whether a stop is an exception or a protocol. The WS-F2 audit (Codex, OpenHands, goose, SWE-agent, gemini-cli, browser-use, Inspect, LangGraph, AutoGen, Claude SDK at pinned commits; ACP/MCP/A2A specs) found every mature system has a closed stop vocabulary, none of them bounds harness-internal feedback paths systematically, and the protocol edges already require cancel to be a barrier followed by a drain (ACP `session/cancel`; MCP cancellation race).

## Options considered

1. **No envelope beyond hard budget ceilings; leave retries, stops and validation to the strategy and the model (Codex / Managed Agents shape).** *Rejected:* the IAL study, LoopTrap and the retry-loop incident cluster (S-WS-F2-01/-02, S-209, all `provisional (mech)`, corroborated by MAST's 15.7 % step repetition, Tier C) show unbounded feedback paths fail when the human is absent — the Lab's normal condition; and it would make the envelope's presence unmeasurable rather than a factor.
2. **Envelope behaviours as per-strategy code (each `control_strategy` variant ships its own stop/retry/validation).** *Rejected:* violates T-LCD-08/-09 (envelope behaviour would be entangled with the β factor), makes AC-F2-09 (β-independence) impossible, and duplicates the seam WS-F1 fixed.
3. **Guards as arbitrary predicates that may call a model (judged stops at C0).** *Rejected:* ADR-0047 forbids judged values on the C0 headline; a model-owned termination check is the LoopTrap attack surface; gemini-cli's judged tier is explicitly a *late* tier after two deterministic ones.
4. **Stop as an exception that unwinds the runtime immediately.** *Rejected:* contradicts ADR-0040 E1 (a ceiling never interrupts a committed effect) and ADR-0030 (every commit resolves); ACP/MCP require pending requests to be answered after cancel.
5. **Core MUST-code envelope interpreting one sealed MUST-data record, six fixed guards on the harness step, closed `StopReason` sum, stop = barrier + drain (chosen).**

## Decision

1. **Position.** The control envelope is Core MUST-code (ADR-0024) that interprets one MUST-data record, **`EnvelopePolicy`**, which *is* the typed content of `AgentProcess.native.control_boundary.guards` (resolves OQ-051 for guards). `EnvelopePolicy{policy_id (content-addressed, sealed with the definition), budget_ref, stop_rules[], retry, timeouts, loop, output_validation, invariants, exhaustion, conditioned_rules[]}` (WS-F2 §6.2). The compiler lowers it into the `RuntimePlan/1` `budget envelope` and `stop-rule` nodes (ADR-0019); the reference runtime interprets them. A control-strategy variant cannot disable a guard; a sealed definition may only set parameters within kernel-admissible ranges and may only *add* stop rules, never remove kernel ones.
2. **The envelope only stops, refuses, delays or tightens.** It never chooses the next action, never grants, never widens (ADR-0035 endorsement list; ADR-0040 `ask → deny`, never `allow`). Every output is a typed ledger event or a typed Observation rendered through the Model Profile; no output is free text (T-LCD-02). Envelope-produced context items carry `kernel` or `definition` authority (ADR-0033).
3. **Guard predicates reference ledger records only.** At C0 a `StopRule.trigger` is a closed predicate grammar over counters, gauges, scope-kind terminal events, deterministic detector verdicts and invariant ids; it never reads `Text` and never calls a model (OQ-062 for guards). A `Validator{kind: judge}` may be referenced only by the C1 judged loop detector (WS-F2-adr-3), never as sole grounds for a stop.
4. **Six enforcement points on the harness step** (`render → propose → interpret → authorize → execute → verify → persist → decide`, ADR-0012), each a pure function of the durable ledger prefix and the policy: **G-PRE-CALL** (before every model call incl. compaction/validator calls: root-first `check`, run/turn deadline, gauge caps, `reserve(model_call)`, ladder state), **G-INTERPRET** (after the model response, before `action.tool.proposed`: output validation pipeline, loop detectors, empty-response ladder), **G-PRE-DISPATCH** (after `authorize` = `allow`, before `commit`: retry eligibility, deadline assignment, `reserve(tool_attempt)`, stop-barrier check), **G-POST-EFFECT** (after each effect/model-call terminal incl. `unknown`: hard-ceiling exhaustion, invariants, no-progress evidence, timeout bookkeeping), **G-DECIDE** (before β's `decide` and on any `stop` proposal: kernel stop rules by priority `invariant > cancel > exhaustion > loop/format > definition rules > β`; completion admissibility), **G-RESUME** (re-arm from the manifest's `envelope_policy_ref`, recompute every counter from the ledger). The envelope runs *before* `authorize` for budget/loop/format (a call that cannot be paid for is never authorized) and *after* it for retry eligibility and deadlines; WS-H1 step 7 reserves the approvals budget itself. WS-F1's `envelope.check(decision) → admitted | refused{reason}` is the driver-facing view of these guards (`pass ≡ admitted`; `respond | stop ≡ refused`, returned as the `envelope_signal{refused}` cue) — CF-WS-F2-07.
5. **Interface.** `arm(run, envelope_policy_ref, lease) → EnvelopeState`; `guard(run, lease, point, input) → pass{reservation_id?, deadline?} | respond{Observation, events[]} | stop{StopReason, events[]}`; `stop(run, lease, reason, triggered_by) → DrainReport`; `loop_state(run)` / `validation_state(run)` as materialized views (`project`), never stored counters (ADR-0026). Invariant: two evaluations of `guard` at the same ledger `seq` yield the same verdict (AC-F2-10). Failures: `Fenced`, `ScopeNotOpen`, `UnknownDecisionPoint`, `PolicyUnsealed`, `DrainTimeout`.
6. **Closed `StopReason` sum (HIR/1 dialect, owned by WS-F2):** `completed` · `budget_exhausted{budget_id, dimension}` (covers `turns`, `model_calls`, `retries`, `time.*`, `spend`, `approvals.requested` — WS-H7's `approvals_exhausted` is the alias `budget_exhausted{approvals.requested}`, CF-WS-F2-02; every "max turns / max iterations / recursion limit" of the audited systems is this reason with a dimension) · `context_exhausted{required_tokens, cap}` (CF-WS-D2-05, adopted verbatim) · `loop_detected{detector, pattern}` · `format_failure{count}` · `invariant_violation{invariant_id}` · `refused{blocking_effect_id}` · `cancelled{by ∈ {principal, parent, hosting, operator}}` · `infrastructure_failure{error_class}`. Extension is by dialect bump (CF-107 rule). WS-F1's `guard_tripped(id)`, `error(class)`, `cannot_proceed` fold into this sum (CF-WS-F2-07).
7. **Total projection onto ADR-0045 outcome classes:** `completed | loop_detected | format_failure → scored` (the end-state oracle scores whatever exists — SWE-agent autosubmission; reason is a stratifier; confirmation requested from WS-I2/J5, OQ-WS-F2-02); `budget_exhausted | context_exhausted → budget_exhausted`; `refused → refused`; `cancelled → cancelled`; `invariant_violation | infrastructure_failure → infrastructure_failure`. **Declared-lossy lowering (T-LCD-11):** ACP `completed → end_turn`, `budget_exhausted{tokens.* | spend} → max_tokens`, `budget_exhausted{turns | model_calls | retries} → max_turn_requests`, `refused → refusal`, `cancelled → cancelled`, else `end_turn` + `_meta.hh.stop_reason` (loss class `narrowed`, extends WS-E4's table); A2A `COMPLETED / CANCELED / REJECTED / FAILED` + metadata. Lifting a hosted participant's stop reason assigns `authority = unverified` and `max_tokens/max_turn_requests → budget_exhausted{dimension: unknown}` (T-LCD-07).
8. **Stop is a barrier followed by a drain, never an exception.** `stop()` runs the **stop protocol**: (1) append `control.decision{kind: stop, reason, decider, triggered_by}` — from here no new `action.effect.committed` or `model.call.requested` in the run except declared `grace` calls and drain operations (INV-3); (2) cancel children (`control.subagent.cancelled{reason: parent_stop}`; parent waits ≤ `TimeoutPolicy[subagent].hard_max`); (3) resolve every pending permission `cancelled` (ACP obligation; WS-H7 `respond`); (4) let in-flight effects reach a terminal or `unknown` (ADR-0040 E1; `expire` at deadline); (5) run the declared `grace` call if any (ADR-0040 E3); (6) release reservations; (7) append `lifecycle.turn.finished{stop_reason}` / `lifecycle.run.finished{status, stop_reason, outcome_class, unresolved_effects[], drain_report_ref}`; only then is `idle` lowered to hosting surfaces (durable-before-visible). `DrainTimeout` ⇒ `unknown` recorded, run finishes `infrastructure_failure{drain_timeout}` with the original reason preserved in `causes[]`. `CompactionImpossible` runs this protocol with `context_exhausted` — "F2 stops the run" reads "F2 runs the stop protocol" (CF-WS-F2-03). Soft thresholds and the occupancy gauge cap are re-armed only after `context.compaction.completed{status: ok}` is durable (CF-WS-D2-06).
9. **Completion admissibility (G-DECIDE, OQ-092 partial).** β's `stop{completed}` is refused while any effect is non-terminal (`intended/authorized/prepared/committed/unknown/probed(undeterminable)`) — the envelope forces probe/escalation first (ADR-0030 "every commit resolves"); `abandoned` is terminal, does not block, and is listed in `unresolved_effects[]` for WS-G2 to adjudicate.
10. **Envelope event family** (plane `control`, `durability = ledger`, minimum observability `events`): `control.decision` **extended** with `decider ∈ {strategy, envelope, principal, parent, hosting}`, `reason: StopReason?`, `triggered_by: EventRef?`; `control.retry.scheduled` **extended** (WS-F2-adr-2); new `control.timeout.fired`, `control.loop.detected`, `control.output.rejected`, `control.invariant.violated`; `lifecycle.run.finished` **extended** with `outcome_class`, `unresolved_effects[]`, `drain_report_ref`; `lifecycle.run.created.manifest` **extended** with `envelope_policy_ref` (CF-WS-F2-01 — payload extensions and additions to the ADR-0026 table; envelope fields unchanged). WS-F1's `control.guard.fired` is `control.decision{decider: envelope, triggered_by}` for definition rules (CF-WS-F2-07). Nudges are `context.artefact.delivered/activated` + `verification.artefact.followed` with `kind: loop_nudge` (T-LCD-13).
11. **Everything beyond the mandatory invariant set is a declared Lab factor** (`configuration-level`, ADR-0013): ceiling values, retry/timeout parameters, loop thresholds, validation mode, grace, exhaustion action. Comparisons across them are `ComparisonReport`s under a `MatchSpec` (ADR-0041, T-LCD-14). This operationalises doc 2 §5.4 "measure which invariants belong outside the model" without deciding CF-005.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-01 (no per-model branch; profile-conditioned parameters only via `conditioned_rules` with debt records, T-LCD-05), T-LCD-02 (typed outputs only), T-LCD-06/-07 (no dependency on the Hosting ABI; hosted stop reasons lifted as `unverified`, dimension `unknown`), T-LCD-08 (`EnvelopePolicy` receives profile/account through the runtime; AC-F2-09 β-independence), T-LCD-09/-14 (every parameter a declared factor; matched-budget comparison), T-LCD-11 (declared-lossy lowering table), T-LCD-12 (operations over canonical records; out-of-process implementable), T-LCD-13 (nudges are delivered/activated/followed events), T-LCD-15 (`loop_*`/`format_failure_rate` render `n/a` below `events` observability). Does not itself satisfy T-LCD-03/-04 (Stage 3 suite; AC-F2-01…10 are the tests). **ADR-0024 ladder:** guard set, `StopReason` sum, projection, stop protocol = Core invariants (by this ADR); `EnvelopePolicy` = MUST-data typed parameters; detector variants = registered variants (WS-F2-adr-3); nudge/refusal texts = `Text` leaves.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: runaway loops are frequent and arise in harness code as well as in models — MAST FM-1.3 step repetition 15.7 %, FM-1.5 unaware of termination 12.4 %, FM-3.1 premature termination 6.2 % (S-WS-F2-03, Tier C, 2025 annotated corpus); IAL study, 68 confirmed loops / 47 projects (S-WS-F2-01, `provisional (mech)`); termination poisoning 3.57× mean step amplification (S-WS-F2-02, `provisional (mech)`); retry loops the largest budget-overrun cluster 27/63 (S-209, `provisional (mech)`); closed stop vocabularies in every mature system (S-114 SWE-agent nine `exit_*`; S-109 Claude SDK four `terminal_reason`s; S-110 OpenHands status sum; S-136 Inspect eight limit types; S-035 ACP five `StopReason`s; S-156 A2A four terminal states — Tier B); cancel as barrier + drain required by protocol (S-035 ACP `session/cancel`; S-153 MCP cancellation race, disconnect = cancel); hard ceilings fire only at decision points (ADR-0040, ratified; S-214 advisory-budget refusal behaviour). Doc 2 §4/§11 (Tier B). No `provisional` claim is load-bearing: the C0 decision rests on ratified ADRs, Tier-B precedents and protocol requirements.
- (b) Source-code precedent (read 2026-09-10 at pinned commits under `/tmp/hh-repos/`): openai/codex @ `0735c519` `codex-rs/core/src/session/turn.rs` L397 (no per-turn cap), `core/src/exec.rs` L995–1046 (cancel: TERM → grace → KILL), `tools/src/function_call_error.rs` L5–10 (`RespondToModel | Fatal` — every failure is respond-or-stop); OpenHands/software-agent-sdk @ `3fc7b221` `conversation/impl/local_conversation.py` L217, L2020–2040 (`max_iteration_per_run = 500` → `MaxIterationsReached`; `max_budget_per_run`), `conversation/state.py` L48–60 (status sum incl. `STUCK`); aaif-goose/goose @ `fae91d01` `crates/goose/src/agents/state_machine/ops_maxturns.rs` L14–67 (max-turns as a state-machine op that yields a question), `agents/agent.rs` L87–92, L154–176 (`DEFAULT_STOP_HOOK_BLOCK_CAP = 8` — a deterministic feedback path bounded); SWE-agent @ `3ea751c` `sweagent/agent/agents.py` L1089–1220 (closed `exit_*` vocabulary with autosubmission); inspect_ai @ `75f4891` `src/inspect_ai/util/_limit.py` L40–75 (`LimitExceededError{type, value, limit, source}`); langgraph @ `e539ac1` `pregel/main.py` L3005–3011 (`recursion_limit`); autogen @ `027ecf0` `conditions/_terminations.py` (composable termination conditions); claude-agent-sdk-python @ `ad77094` `types.py` L1343–1350, L2015–2025 (`terminal_reason`, `max_turns`, `max_budget_usd`); ACP @ `9b00c27` `schema/v2/schema.json` L440–447, L488, L4215 (`StopReason`; pending permissions answered `cancelled`); MCP @ `aa8ce049` `docs/specification/draft/basic/patterns/cancellation.mdx` L40–119. **`no-precedent / novel` (integrated form):** a single sealed policy record wrapping any strategy; `StopReason` with a total outcome-class projection; a typed stop protocol with a drain report; guard determinism as a rebuild-equality test.
- (c) Disconfirming evidence considered: (i) Managed Agents (S-047) and Codex run at scale with no per-turn cap and model-decided retries — both operate with reversible, reprovisionable effects and a human present; the envelope costs nothing when ceilings are high and its *existence as a ledgered factor* is what lets the Lab test the "no cap" policy; (ii) hard ceilings cause premature stops (MAST 6.2 %, S-214 refusal-like behaviour, S-135 non-monotone effort–accuracy) — mitigated by decision-point-only firing, optional grace, `escalate` on exhaustion in attended mode (goose's question), and reporting `budget_utilization`; ceiling values are factors, not constants; (iii) Agentic Programming (S-065, `provisional`) says all control belongs in code and Dhage (S-070, `provisional`) shows constraints can hurt — the envelope owns only objective constraints and leaves `plan/act/retrieve/verify/delegate` and `stop{completed}` to β, so CF-005 stays a Lab target; (iv) quarantining on invariant violation discards scoreable runs (WS-F2-adr-3 (c)). None overturns.
- (d) Conditionality: independent of model tier (it is a contract and a factor); assumes native participants (hosted participants get the boundary envelope only — budgets and cancellation through the Hosting ABI, AC-F2-11); assumes a durable, fenced ledger (ADR-0026/0030) — if the ledger is wrong the envelope's counters are wrong, which INV-9 detects; assumes coding/terminal-class environments for Stage 0–3 instances; the `escalate`-on-exhaustion action assumes an attended principal (WS-H7 attendance modes).
- (e) Build-stage assignment: **C0 / Stage 0** — ceilings on `turns`, `model_calls`, `time.wall_ms` with `check` at G-PRE-CALL/G-POST-EFFECT and `stop_reason = budget_exhausted`; tool timeout with kill; parse/unknown-surface validation. **C0 / Stage 1** — `EnvelopePolicy` sealed with the definition and referenced from the manifest; full `StopReason` sum + projection; six guards; event classes; stop protocol with drain; G-RESUME. **C0 / Stage 2** — `context_exhausted` wiring with WS-D2; approval deadlines with WS-H7 attendance modes. **C0 / Stage 3** — AC-F2-01…10 in the Stage 3 suite under recorded `model_io`; process metrics as `MetricDeclaration`s (ADR-0044/0045). **C1 / Stage 4** — `escalate` on exhaustion (attended); subagent cancel/drain with WS-F3. **C2 / Stage 4** — hosted boundary envelope with WS-J6.

## Consequences

- WS-F1: `envelope.check` is implemented by G-PRE-CALL/G-PRE-DISPATCH/G-DECIDE; the driver's no-progress guard is F2's `no_progress` detector (one predicate, one threshold); `StopReason` spellings converge on this sum (CF-WS-F2-07).
- WS-B1/ADR-0026: payload extensions to `control.decision`, `control.retry.scheduled`, `lifecycle.run.finished`, `lifecycle.run.created.manifest`; four new `control.*` classes (CF-WS-F2-01).
- WS-H7: `approvals_exhausted` becomes a rendering of `budget_exhausted{approvals.requested}`; pending permissions are resolved `cancelled` by the stop protocol (CF-WS-F2-02).
- WS-D2: `CompactionImpossible` → stop protocol with `context_exhausted`; re-arm after `completed` (CF-WS-F2-03, CF-WS-D2-06).
- WS-E4/K1/J6: lowering/lifting tables for `StopReason` (T-LCD-11/-07).
- WS-I2/J5: outcome-class projection; `loop_detected`/`format_failure` as `scored` stratifiers pending OQ-WS-F2-02.
- WS-G2: `unresolved_effects[]` on `lifecycle.run.finished` is its input for completion-claim reconciliation.
- WS-A4: `EnvelopePolicy` lowers into existing `RuntimePlan/1` node kinds; no new kinds.

## Reversibility

**Medium.** The record, the sum and the guards are small data/contract changes (dialect bump to extend); reversing the *position* — letting strategies own stops, or making guards model-callable — would unpick WS-F1 I5, ADR-0040's decision-point rule, ADR-0047's headline discipline and the β factor the Lab depends on. Reversing the stop protocol (exception instead of drain) would violate ADR-0030/0040 and the ACP/MCP obligations at the surface.
