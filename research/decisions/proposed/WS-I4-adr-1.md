# ADR-NNNN — Environment families, the three-surface task record and the `benchmark_adapter` component contract (integrate, never author)

**Status:** proposed
**Owner workstream(s):** WS-I4 (consumers: WS-B5 handle requirements, WS-J3 environment factor, WS-J5 results rows, WS-I3 bundle members, WS-J6/K1 participation surface, WS-G1 validators, WS-H4 network policy lowering) · **Phase:** 2 · **Related:** ADR-0005 (interoperate; act as participant), ADR-0006 (N13, N4, N5), ADR-0007 (T-LCD-06/-07/-09/-10/-11/-12/-13/-15), ADR-0015/0016 (dialect sums; `Text` leaves; `Validator`), ADR-0018 (`origin = import`, `authority = unverified`), ADR-0023/0024/0025 (component class; data definitions; `seal`), ADR-0036/0037/0038 (identity; foreign digests as claims; bundle members; CF-087), ADR-0045/0046/0047 (factors; matched budgets; oracle classes); CF-WS-I4-01, CF-WS-I4-04, CF-WS-I4-07; OQ-016, OQ-039, OQ-109, OQ-WS-I4-01/-05/-06/-08; R-2.9.4, R-2.2.5, R-2.10.3

## Context

Doc 2 §8 requires a suite "stratified by environment rather than averaged into one opaque score" across seven families, each with success and process metrics; ADR-0006 forbids authoring benchmarks (N13) and ADR-0005 obliges the plane to import/export and to act as a participant in Harbor/Inspect-style planes. ADR-0045 keys every result row by an environment factor `(image digest + fault/perturbation profile)` and a task `with split label`; ADR-0038 makes `EnvironmentRecord`/`TaskDataRecord` bundle members and rules that foreign version strings are claims (CF-087); ADR-0047 asks WS-I4 to declare per suite which oracle classes exist. The audit (dossier §4c) found that every mature plane separates a task into a visible instruction, a materialised environment and grader-only assets (Harbor `instruction.md / environment / solution / tests`, tests uploaded only at verify time; SWE-bench exposing `problem_statement`/`base_commit`/image and keeping `test_patch`; HAL `_strip_ground_truth`), that runner interfaces converge on `setup → run(instruction, environment, context) → verify`, that adapters are validated by parity experiments (Terminal-Bench `adapters/swebench/parity_experiment.json`; Harbor Adapters S-133), and that no plane content-addresses images or task data (tags/strings everywhere).

## Options considered

1. **Adopt Harbor's task package and `BaseAgent` interface as the instrument's native task/runner model.** Rejected: image is a tag, version a string, no split/validity/contamination annotations, no kernel-enforced held-out separation, and it would couple the native runtime to one plane's process model (N1/N2 spirit; T-LCD-06).
2. **Treat tasks as Inspect-style `Sample{input, target, sandbox, files}` inside the Harness Definition.** Rejected: `target` sits beside `input` readable by the solver (leakage shape), and putting tasks in the definition makes the environment factor a definition edit rather than a factor level (T-LCD-09).
3. **Families inferred from task metadata; adapters as untyped scripts per benchmark.** Rejected: inference is the T-LCD-07 coercion signature; untyped adapters cannot carry parity, lift-loss or validity records into the bundle.
4. **A closed family sum with declared handle requirements; a three-surface `TaskRecord` with foreign identity as claims; one operation-shaped `benchmark_adapter` class whose admissibility is a parity report (chosen).**

## Decision

1. **`EnvironmentFamily = {coding_terminal, browser_computer, search_research, structured_tool, persistent_multi_episode, adversarial_security, long_running_recovery}`** is a closed dialect sum (ADR-0015; grows by ADR). `EnvironmentFamilyRecord{family_id, version, requires: HandleRequirements (tri-state names the WS-B5 handle declares), oracle_classes_available, submission_kind ∈ {patch, end_state, output, action_log, none}, verifier_isolation_default, process_metrics[], fault_profiles_admissible[], perturbation_profiles_admissible[], episode_model, provenance}` is a registry record. `MetricDeclaration` gains `applies_to_families` beside `applies_to_classes` (OQ-WS-I4-08 decides HIR/1 amendment vs registry scoping). A family whose requirements the handle cannot declare `supported` is refused at `materialize` (`FamilyUnsupported{missing}`).
2. **`TaskRecord`** (dossier §6.3) has three disjoint surfaces: `visible` (instruction `Text` leaves with `origin = import`, `authority = unverified`; attachments; `task_metadata_scope`), `held_out` (validators by `VersionedRef`, fixtures, goal state, oracle solution — `never_delivered: true`), `instrument` (grader spec, budgets, `TaskValidity`, contamination stratum, canary, human-time metadata). `foreign{suite_ref, foreign_id, foreign_digest?, version_label?, first_public_at?}` is a claims block excluded from `semantic_id` (CF-087; ADR-0036 N4). `environment: EnvironmentSpec{image: ContentAddress | foreign_digest_claim, build_context?, workspace, network{setup, agent, verify}, resources, services?}`; an unresolved image lands in the bundle's `unpinned[]` and caps `claimed_level` (ADR-0038). `SuiteManifest{…, splits with split_hash, validity: SuiteValidityRecord, adapter_ref, parity}` and `SplitAssignmentRecord` are content-addressed records; the run manifest gains `task_ref{task_id, suite_id, split_label}` (CF-WS-I4-07).
3. **`benchmark_adapter` is a registered component class** (`cardinality = one-per-suite`, `required_inputs ⊇ {ModelProfile, ResourceAccount}`, default locality out-of-process) with operations `declare`, `discover(suite_source) → SuiteManifest`, `import_task(foreign) → {TaskRecord, LiftReport}`, `materialize(task_id, env_handle) → WorkspaceReady`, `expose(task_id, profile) → VisibleSurface` (the only profile-aware operation; items carry `delivery_id`s), `collect_submission(task_id, env_handle, cursor) → Submission`, `grade(task_id, submission | env_handle, cursor) → [Verdict]` (through the WS-G1 Validator contract; details in WS-I4-adr-3), `export(run | experiment, format) → ForeignArtifact + LoweringLossReport`, `parity(adapter, original_runner_ref, participant, model_ref, budget, design) → ParityReport` (an ADR-0046 `compare`, `benefit_kind = artifact`, pre-registered margin). Invariants: only `grade` reads `held_out`; no participant holds a capability to call `grade`/`collect_submission` (kernel-scheduled `environment_op` spans); `grade` never consumes `model_claim` observations; `held_out` and `instrument` records are byte-identical across profiles (E1–E3); every lifted `Text` leaf is `unverified`; an adapter without a `ParityReport` admits only `product`-granularity smoke runs flagged `parity = none`; oracle-failing tasks are recorded `validity = invalid` in `SuiteValidityRecord.flawed_task_ids`, never dropped.
4. **Integrate, never author.** The instrument imports suites, records validity, and participates in external planes (native harness lowered to a container-installed/ACP participant; foreign trajectories/results imported as `product` rows with `observability_level` from the artifact); it never edits tasks or publishes task sets.
5. **Requirements on the WS-B5 environment handle** (CF-WS-I4-01): `open(EnvironmentSpec)` resolving image digests and emitting `action.environment.attached{image_ref = digest}`; `upload`/`download` by content address; `exec` via the E5 executor; `set_phase(setup | agent | verify, NetPolicy)` refused unless `per_phase_network_policy` is declared; `snapshot` where declared; `default_user`; `close`.

**T-LCD statement.** Satisfies T-LCD-06 (task records and adapters add no field to native contracts; hosted participants consume the same records), T-LCD-07 (tri-state requirements and declarations), T-LCD-09 (environment factor levels are digests + profiles), T-LCD-10 (foreign labels excluded from identity), T-LCD-11 (lift and export loss reports), T-LCD-12 (operation contract, out-of-process), T-LCD-13 (visible items carry `delivery_id`s), T-LCD-14 (task budget defaults are `eval_budget` inputs; parity is budget-matched), T-LCD-15 (`applies_to_families`). Does not address T-LCD-01/-02/-04/-05/-08 beyond consumption. ADR-0024 rung: records are MUST-data; the two import static checks and the `deliver` predicate are MUST-code.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: stratification by environment family and factorial keying — doc 2 §8 (Tier-B synthesis), ADR-0045 (ratified); three-surface separation and grader-only assets — S-132 Harbor task layout and verify-time upload, S-124/S-WS-I4-09 Terminal-Bench Dockerfile reference check and canary (Tier C; process, not a performance claim), S-134 HAL ground-truth stripping (Tier B), S-123/S-162 SWE-bench (Tier A: agent sees problem statement/base commit/image); parity as adapter validation — S-133 (`provisional (mech)`), S-WS-I4-08 `parity_experiment.json` (Tier B source); identity by digest, not tag — ADR-0036/0038 (ratified), WS-L4 F8; participation in external planes — ADR-0005 (ratified), S-062 Harness-Bench as a product-granularity plane (`provisional (mech)`).
- (b) Source-code precedent: harbor `src/harbor/models/task/{paths.py L15–24, task.py L35–90, config.py L421–470, L554–615, L795–820}`, `verifier/verifier.py L166–200`, `environments/{base.py L908–960, L846, capabilities.py}`, `agents/base.py L339–400`; terminal-bench `terminal_bench/handlers/trial_handler.py L29–170`, `adapters/swebench/{adapter.py L59–125, parity_experiment.json}`; SWE-agent `sweagent/run/batch_instances.py L32–36, L87–194`; mini-swe-agent `src/minisweagent/run/benchmarks/swebench.py L68–178`; inspect_ai `src/inspect_ai/util/_sandbox/environment.py L138–530`, `dataset/_dataset.py L29–115`; hal-harness `hal/benchmarks/base_benchmark.py L61–100`; SWE-bench `swebench/image_builder/image_spec.py L37–47`, `harness/run_evaluation.py L479–512`. The closed family sum with handle requirements, the three-surface record with validity/contamination annotations, and parity as a typed admissibility precondition are **`no-precedent / novel`** as an integrated contract; each part is precedented.
- (c) Disconfirming evidence considered: (i) Harbor/Inspect run 80+ benchmarks with no family notion — answered: families are the scope of `applies_to_families` (T-LCD-15) and a closed sum that grows by ADR, with primary family + tags for overlap; (ii) parity rows in the field are n = 1 with no intervals and full parity costs a benchmark run — answered: parity is an ADR-0046 `compare` on a pre-registered subset with `estimated{…}` admitted; missing parity degrades to smoke-only, not refusal of import; (iii) forcing digests may make some suites unimportable — answered: `foreign_digest_claim` + `unpinned[]` keeps them at R0/R1/R3 rather than excluded; (iv) out-of-process adapters add latency per task — answered: the boundary is the same one ADR-0045 item 9 already fixes for scorers (per run, not per step). None overturns.
- (d) Conditionality: coding/terminal and structured-tool families at Stage 3; browser/computer and search families depend on WS-B5 declaring `browser_handle`/`display` capabilities (C2); assumes a task's environment can be expressed as an image + workspace tree (true for TB2/SWE-bench/Harbor; τ-bench/AgentDojo need no container and use an executor of class `kernel_internal`/`remote_server`).
- (e) Build-stage assignment: **C0 / Stage 1** — enums, `TaskRecord`/`SuiteManifest`/`SuiteValidityRecord`/`SplitAssignmentRecord` schemas, `task_ref` manifest field, `applies_to_families`; **C0 / Stage 3** — the four Stage 3 adapters, `materialize`/`expose`/`collect_submission`/`grade`, parity reports; **C1 / Stage 4** — hosted participants over the same adapters, `export`, participation surface, foreign trajectory import; **C2 / Stage 5** — browser/search families, `probe_memorization`; **C4 / Stage 6** — Evo-Bench environments for WS-I5.

## Consequences

- WS-B5 adopts or counter-proposes the handle requirements (CF-WS-I4-01); WS-B1/I3 add `task_ref` to the run manifest and `TaskRecord`/`SuiteManifest`/`ParityReport` to the bundle member list (CF-WS-I4-07).
- WS-J3 takes environment factor levels from `EnvironmentSpec` digests and profiles; WS-J5 carries `suite_id`, `split_label`, `SuiteValidityRecord` and `parity_status` on rows; WS-J4 scopes metrics by family.
- WS-G1 consumes `visible.task_metadata_scope` for `MetadataShortcut` (CF-WS-I4-04) and binds the `held_out.validators` through its contract; WS-H4 receives the task's per-phase network claims as layers under its meet.
- WS-J6/K1 own the participant surface used for AC-I4-10; WS-I5 inherits `split_label` discipline.

## Reversibility

**Medium.** The family enum and task record are cheap to extend (additive) but expensive to reshape once results rows and bundles carry them; the adapter contract is operation-shaped and can be re-bound per suite; dropping the parity precondition later is a one-line policy change that would re-admit unvalidated adapters into headline rows.
