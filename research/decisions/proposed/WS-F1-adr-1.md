# ADR-NNNN — Control lives behind one pluggable `control_strategy` contract inside a code-owned envelope (resolves CF-005 as "pluggable + envelope")

**Status:** proposed
**Owner workstream(s):** WS-F1 (consumers: WS-F2, WS-F3, WS-B3, WS-B4, WS-D1, WS-D2, WS-G1, WS-G2, WS-H1, WS-H7, WS-J3, WS-J4, WS-K1) · **Phase:** 2 · **Related:** ADR-0012 (β ∈ θ, decision 6), ADR-0016 (`AgentProcess.native.slots["control_strategy"]`, `ControlBoundary`, `DecisionPoint`, `Loop` bounded), ADR-0019 (`RuntimePlan/1` control nodes, closed-world rule), ADR-0023/0024 (class contracts as operations; MUST-code/MUST-data), ADR-0026 (`control.decision`, `lifecycle.turn.*`), ADR-0028 (`deterministic_replay` declared), ADR-0030 (effect lifecycle), ADR-0040 (hard ceilings at decision points), ADR-0047 (deterministic headline; judges), ADR-0050 §8; CF-005, CF-107, CF-WS-F1-01…05; OQ-062, OQ-092, OQ-WS-F1-01…05; R-2.6.1 (constrains R-2.6.2, R-2.6.3)

## Context

Doc 2 §4 asks "where should control live?" and answers with a design principle (hard invariants in deterministic software; open-ended search in the model; "move the boundary only when evaluation demonstrates a benefit"), while §5.4 and §6 record that whether "a fully deterministic outer program is superior to model-owned orchestration" is an **open question** with only `provisional` evidence on the deterministic side (S-065, S-070). CF-005 pre-registered the resolution shape: a pluggable control-strategy family (F1) plus a control envelope of hard invariants (F2), with the boundary a Lab comparison target. Phase 1 made the pieces typed: β : `DecisionPoint → {code, model, human}` is a component-level factor (ADR-0012), `ControlBoundary{assignments, guards}` is a record on `AgentProcess.native` whose `slots` map has `control_strategy` as a Stage-1-mandatory key (ADR-0016), compiled control structures are the closed `RuntimePlan/1` node set (ADR-0019), and deterministic replay is a declared capability of control-strategy variants (ADR-0028). What remained was the **contract** those variants implement and the proof that ReAct, plan-execute, FSM/workflow and deterministic-envelope styles fit one contract without an escape hatch. The WS-F1 audit (mini-SWE-agent, Codex, Pi, OpenHands, LangGraph, Inspect, Gemini CLI at pinned commits) found every loop to be the same decision set with different owners, and found the pure-decide/gated-effect/persisted-state shape already implemented in production (Pi).

## Options considered

1. **Fix the boundary: model-owned ReAct loop as Core, everything else an extension.** *Rejected:* makes CF-005 a C0 decision resting on doc 2's "open question"; forecloses the Lab's cheapest component-level factor (β); contradicts ADR-0012 decision 6.
2. **Fix the boundary the other way: deterministic program with LLM-as-Code nodes as Core.** *Rejected:* rests on `provisional` S-065/S-070 (forbidden for C0 by doc 3 §3.1); Dhage's own cells show constraints can degrade reproducibility; no audited coding harness ships it.
3. **Four independent contracts (loop, planner/executor, graph engine, program runtime) sharing only the ledger.** *Rejected:* four seams for F2/H1/D1 to instrument, no common decision vocabulary for β or `boundary_drift`, and the audit shows containment (LangGraph's ReAct is a two-node graph; Codex/Pi loops are state machines over the same leaves).
4. **One `control_strategy` component-class contract with a Core driver and a code-owned envelope; the four styles are variants distinguished by β presets and plan provenance (chosen).**

## Decision

1. **The seam.** Control is split into three parties: a **strategy** (registered variant of class `control_strategy`; MUST-code algorithm under ADR-0024; receives `(ModelProfile, ResourceAccount)`), a **driver** (Core, MUST-code) that executes the strategy's decisions through the plane operators of the harness step, and the **envelope** (WS-F2, Core) that checks every decision before execution. The strategy *proposes*, the envelope *checks*, the driver *executes*.
2. **Contract (operations).** `capabilities(variant) → ControlCapabilities{deterministic_replay, steering, follow_up, parallel_effects, delegation, model_emitted_plan, resumable_mid_effect, decision_points_owned, boundary_preset, requires{goal, procedure?}}` (declared record); `open(ControlContext) → ControlState₀ | ControlError`; `observe(state, events[]) → state'` (pure fold of durable ledger events); `decide(state, cue: Cue) → (state', ControlDecision)` (pure, total over the closed `Cue` sum); `terminate(state, reason) → FinalReport{stop_reason, submission_ref?, unresolved_effects[], boundary_observed}` (pure; no effects); `checkpoint(state) → bytes` / `restore(bytes, ctx) → state` (canonical form). `ControlState` is a closed sum per variant with a common header `{variant_ref, cursor: PlanCursor over RuntimePlan/1 control nodes, decision_count, open_effects[], last_cue_seq, boundary_view}`.
3. **Closed sums.** `Cue = {run_opened, resumed, model_completed{stop_reason}, effects_settled, verification_completed, retrieval_completed, compaction_completed, delegation_completed, human_input{steer | follow_up | approval | interrupt}, envelope_signal{soft_threshold | refused | retryable_error | cancel_requested}, guard_fired}`; `ControlDecision = {propose, act{mode}, retrieve, compact, verify, delegate, retry, escalate, wait, stop{proposed_reason}}`, each stamped `{decision_point: DecisionPoint, owner ∈ {code, model, human}}`; `StopReason = {completed, cannot_proceed, budget_exhausted{dimension}, context_exhausted, guard_tripped(guard_id), cancelled, error(class)}`. Extension is by dialect bump (CF-107 rule).
4. **Driver loop.** `restore | open` → repeat { `cue ← next_cue(ledger, inbox)`; `(state, d) ← decide`; `verdict ← envelope.check(d)`; append `control.decision{decision_id, decision_point, owner, kind, reason, strategy_variant_ref, checkpoint_ref, cursor, verdict, budget_remaining}`; `refused ⇒ cue ← envelope_signal{refused}` else execute `d` } until `stop`, then close open effects (ADR-0040 decision 5), `terminate`, `lifecycle.run.finished{stop_reason, unresolved_effects[]}`. The driver caps `decision_count` by the `turns` budget and applies a **no-progress guard** (identical `(state_hash, decision)` twice ⇒ `stop{guard_tripped(no_progress)}`).
5. **Invariants.** I1 decide-before-effect (`causes[] ∋ decision_id` on every `action.effect.intended`); I2 strategy purity (no model/tool/environment/ledger handle; the driver issues effects through the gate); I3 closed sums, total `decide`; I4 bounded (every `Loop` bounded by a Budget; driver cap; no-progress guard; `stop` is a value, never an exception); **I5 envelope-reserved points** — `authorize` is always `code`, `stop{budget_exhausted | context_exhausted | cancelled}` and `retry` of infrastructure errors are always `code`, and `validate`/`open` refuse a `ControlBoundary` that says otherwise (`IncompatibleBoundary`); **I6 completion is a proposal** — a `model`-owned `stop{completed}` is accepted only if open effects are closed, a required submission is present and every `stop` guard passes, else it becomes a `guard_fired` cue (bounded by `max_continue_nudges`); I7 cues are the only input (steering/follow-up/approval/hook feedback arrive as ledger-ordered cues); I8 observed β is data (`owner` per decision; `boundary_observed` vs declared `assignments` = `boundary_drift`); I9 model-conditioned behaviour only through conditioned `HarnessRule`s with debt records.
6. **The family as variants.** `react` (compiled implicit plan `Loop{propose; act}`; model owns `plan/act/retrieve`, proposes `stop`), `plan_execute` (model-emitted plan as a content-addressed `Procedure` artifact with `provenance.origin = model, authority = delegate`, schema-validated by a `Validator{kind: schema}` before execution — `control.plan.emitted{valid}`; code executes, model re-plans on `replan_on`), `workflow` (authored `Procedure` lowered to `RuntimePlan/1`; code owns every decision point; model only inside steps), `program` — the **deterministic-envelope strategy** (workflow with every model step `output_schema`-validated and `decision_points_owned = ∅` for the model). Hybrids are parameter points (`plan_provenance`, `replan_on`), not new variants. The plan language is one interpreter; F1 asks WS-A4 for three attributes on existing node kinds (`step.mode ∈ {sequential, parallel}`, `step.output_schema?`, `loop.replan_on`) — `RuntimePlan/1` stays closed (CF-WS-F1-02).
7. **Parameters (MUST-data).** `stop_rule ∈ {no_action, submit, either}`, `max_continue_nudges`, `max_consecutive_format_errors`, `max_consecutive_errors`, `tool_batch_mode`, `on_truncated_response` (default `fail_calls`), `plan_provenance`, `replan_on`, `loop_guards[]`. Nudge/reminder texts are `Text` leaves in `HarnessRule`s.
8. **OQ-062 answer.** `ControlBoundary.guards` are predicates over ledger-derived state and may reference Validators of kind `{schema, predicate, executable}` with `deterministic = true`; a `judge` Validator may enter a guard only at C2, only as an input to `escalate`, never deciding `stop`/`act`. Guards are evaluated by the envelope and ledgered as `control.guard.fired`.
9. **Ledger amendment requested (CF-WS-F1-01).** `control.decision.kind` becomes the full `ControlDecision` sum with `decision_point`, `owner`, `checkpoint_ref`, `cursor`, `verdict` (`continue ≡ propose`, `ask ≡ escalate`); new classes `control.guard.fired`, `control.plan.emitted`. `lifecycle.turn.*` stays with the strategy: a *turn* is principal-input → idle (WS-B1), a *harness step* is one `propose` cycle (ADR-0012) — CF-WS-F1-05.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-08 (contract receives profile and account; a model-conditioned variant is expressible inside it), T-LCD-12 (six operations over canonical documents; out-of-process implementable), T-LCD-09 (variant and β are explicit component-level factors; `boundary_drift` reportable), T-LCD-02/-05/-13 (nudges and reminders are `Text`-leaf `HarnessRule`s with debt records and delivered/activated/followed events), T-LCD-15 (`deterministic_replay` and other capabilities report `n/a` when undeclared), T-LCD-01 (no per-model branch; I9). Does not itself satisfy T-LCD-03 (Stage 3; WS-F1-adr-2/AC-F1-2) or T-LCD-14 (WS-F1-adr-3 and the engine). **ADR-0024 ladder:** driver and envelope seam = Core invariant (by this ADR); strategy algorithms = registered variants; stop rule, nudge caps, batch mode, guards = typed parameters; nudge texts = `Text` leaves.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: model-directed control is implementable and effective — ReAct S-006 (Tier A); code-directed graphs with step limits and interrupt points — LangGraph Pregel `tick` (S-143), Anthropic's workflows-vs-agents distinction and five patterns (S-032, Tier B); plan-then-execute as a typed artifact — Plan-and-Solve S-WS-F1-01 (ACL 2023), LLMCompiler S-WS-F1-02 (planner → executor DAG); the deterministic pole is implementable — PAL S-007, LLM-as-Code S-065 (`provisional`, mechanism only), Dhage S-070 (`provisional`: schema-validated planning is a lever *and* constraints can hurt — both hypotheses, neither a design constant); loop pathologies exist and are guarded in code everywhere — OpenHands `StuckDetector`, Gemini CLI `LoopDetectionService`, Inspect content-filter cap (S-110, S-119, S-136); production loops compose primitives and "loop sophistication does not predict benchmark performance" — S-074/S-166 (`provisional (mech)`); completion claims need state reconciliation — Harness-Bench S-062 (`provisional (mech)`) with doc 2 §5.3 (Tier B); pure decision + gated effect + persisted state machine — Pi (S-113, Tier B, in source).
- (b) Source-code precedent (all re-read at the pinned commits on 2026-09-10): `pi-mono/packages/agent/src/harness/runtime/drive.ts` (13-leaf dispatcher, no-progress invariant), `harness/session/types.ts` L119–121 (`Continuation = need_assistant | may_finish`), L155–160 (`ToolCall` phases), L316–329 (`OperationState`), `harness/execution/effect-gate.ts` (`gate.admit`), `harness/runtime/drive/boundary.ts` L164–230 (`before_run_end` follow-up); `codex/codex-rs/core/src/session/turn.rs` L150–162 (no-tool-call ⇒ turn complete), L430–700 (`needs_follow_up`, roll-over compaction, stop hooks that block with a prompt), `tasks/regular.rs` L85–105 (outer loop over pending input), `protocol/src/protocol.rs` L4191 (`TurnAbortReason`); `mini-swe-agent/src/minisweagent/agents/default.py` L88–157 (the four operations and three exits), `environments/local.py` L43–56 (`Submitted`); `software-agent-sdk/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py` L1908–2050 (stop hooks may deny stopping; stuck check; confirmation state); `langgraph/libs/langgraph/langgraph/pregel/_loop.py` L599–681 (`out_of_steps`, `interrupt_before`), `libs/prebuilt/langgraph/prebuilt/chat_agent_executor.py` L831–850 (`should_continue`); `inspect_ai/src/inspect_ai/agent/_react.py` L52–140, L242–330 (`submit`/`on_continue`/`attempts`). **`no-precedent / novel`** for: `owner` recorded on every decision (β observable as data), one interpreter running authored and model-emitted plans, stop rule as a parameter compared at matched budget, and hook/steering overrides typed as cues with owners.
- (c) Disconfirming evidence considered: (i) "one contract is the LCD trap" — the contract is the union of decision points, not an intersection of features; unsupported constructs surface as `PlanError`/opaque bodies whose share is measured (ADR-0015 ceiling); (ii) "just fix the boundary" — the envelope *is* fixed (I5); only the model-vs-code ownership of `plan/act/verify/compact/stop{completed}` varies, because fixing those would rest on `provisional` evidence; (iii) model-owned `stop` invites ungrounded completion — mitigated by I6 (completion is a proposal) and by `stop` guards that may reference deterministic Validators (decision 8), with G2 reconciliation at Stage 3; (iv) deterministic replay constrains variants — already settled as declared-only by ADR-0028; this ADR only makes `decide` pure, which Pi shows costs nothing. None overturns.
- (d) Conditionality: independent of model tier (it is a contract and a factor, not a performance claim); assumes native participants (hosted participants expose no `control_strategy` slot — `n/a`, T-LCD-06/-15); assumes coding/terminal-class environments for the Stage-0/3 instances; the `program` and `plan_execute` variants assume models that reliably emit schema-valid output under the profile (a conditioned rule with a debt record where it is not the case).
- (e) Build-stage assignment: **C0 / Stage 0** — driver with hard-ceiling checks, effect gate, ledgered decisions, `react/minimal` (WS-F1-adr-2); **C0 / Stage 1** — full contract, `checkpoint/restore`, cue inbox, `control.decision` payload, F2 seam; **C1 / Stage 2–3** — `react/steerable`, `plan_execute`, replay driver, AC-F1-4; **C1–C2 / Stage 4** — `workflow`, `program`, `delegate` via F3; β-ablation as evolution candidates at Stage 5–6.

## Consequences

- WS-F2 implements `check(decision) → admitted | refused{reason}` and the refusal-as-cue rule; it owns guard evaluation and `control.guard.fired`.
- WS-B1/ADR-0026: `control.decision` payload widened and two classes added (CF-WS-F1-01); WS-A4/ADR-0019: three node attributes (CF-WS-F1-02); WS-A2 ontology: "deterministic-envelope strategy" vs "control envelope"; "turn" vs "harness step" (CF-WS-F1-03/-05).
- WS-B3 resumes by `restore(checkpoint_ref)` then `observe` of the tail; WS-B4/I7 use `capabilities.deterministic_replay` to label replay mode.
- WS-J3/J4 treat `control_strategy` variant and `ControlBoundary.assignments` as component-level factors and compute `boundary_drift`.
- WS-K1/K4 lower `control.decision{stop}` to ACP `state_update{idle, stopReason}` and `escalate{approval}` to `request_permission`.
- Any future strategy that cannot express itself as decisions over `RuntimePlan/1` triggers a dialect bump, never an escape hatch.

## Reversibility

**Medium.** The decision/cue sums and the driver are small and additive to change (dialect bump); reversing the *seam* (letting a strategy issue effects directly, or moving envelope-reserved points to the model) would unpick I1/I2/I5, ADR-0028's replay declaration, ADR-0040's decision-point enforcement and the β factor the Lab depends on — expensive in program terms, cheap in bytes.
