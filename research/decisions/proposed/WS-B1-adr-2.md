# ADR-NNNN — Ledger ID model, ordering and causality: time-ordered allocated ids, content addresses, per-run dense `seq`, parent/link causality, fork-by-reference

**Status:** proposed
**Owner workstream(s):** WS-B1 (with WS-B2 for `effect_id` derivation, WS-B4 for fork semantics, WS-L4 for artifact identity, WS-F3 for subagent lineage) · **Phase:** 1 · **Related:** ADR-0001, ADR-0004, ADR-0005, ADR-0007 (T-LCD-10), ADR-0009; OQ-030, OQ-WS-B1-02; CF-WS-B1-01, CF-WS-B1-04; R-2.2.1, R-2.6.3, R-2.12.1; WS-B1-adr-1, WS-B1-adr-4, WS-A3-adr-1, WS-B2-adr-1

## Context

Every consumer of the ledger joins on identifiers: WS-B2 joins effect phases on `effect_id`; WS-D1 pairs tool calls with observations; WS-H6 chains events; WS-J5 keys results by configuration; WS-F3 links a child run to the event that spawned it; WS-I3 exports lineage; hosted-participant rows must be identifiable by provenance (phase-0 §5.5). T-LCD-10 requires that names be surfaces and identities semantic — provider-issued ids (response ids, provider tool-call ids that "reset each session") cannot be the identity. Four audited harnesses use time-ordered allocated ids for runtime-created things and two research systems address immutable values by content hash (WS-B1 §4a F5); two fork designs exist — copy the prefix (OpenHands, Pi) or reference it (Codex) — and two systems rewrite history on revert (WS-B1 F4).

## Options considered

1. **Provider/surface ids as identity** (tool-call id from the model API, response id). *Rejected:* not unique across sessions or providers; violates T-LCD-10; a re-parsed response after a crash gets different ids.
2. **Content addresses for everything, including runs and events.** *Rejected:* two identical events at different times must be distinct; events need an identity before their hash exists (an event is referenced by later events in the same batch); runs are experimental observations, not values.
3. **Random unordered ids for everything.** *Rejected:* loses index locality and creation-order sortability that Codex ("some use cases rely on that") and Pi depend on; no cross-run ordering hint.
4. **Global sequence across runs.** *Rejected:* requires a global writer or coordinator; subagent runs on other hosts would block; partial order plus optional hybrid clocks suffices.
5. **Fork by copy** (OpenHands `fork`, Pi `runJsonlFork`). *Rejected for the ledger* (adopted for bundle export): duplicates bytes and hashes; a fork of a long run is O(n); lineage becomes implicit.
6. **Allocated time-ordered ids for runtime-created scopes + content addresses for immutable values + surface ids as aliases; per-run dense `seq`; parent tree + causal links; fork by reference with hash-anchored lineage (chosen).**

## Decision

1. **Allocated ids** (`RunId`, `EventId`, `TurnId`, `ModelCallId`, `ToolCallId`, `PermissionId`, `LeaseId`): opaque, globally unique, creation-time-sortable (UUIDv7-class semantics with RFC 9562 monotonicity within a generator); allocated once at the scope's opening event; never reused; each scope closed by exactly one terminal event. Nesting: `run_id ⊃ turn_id ⊃ model_call_id ⊃ tool_call_id` (alias pair with WS-B2's `step_id`/`call_id` — CF-WS-B1-04).
2. **Derived ids:** `EffectId` is minted deterministically by the runtime from `(run_id, model_call_id, tool_call_id, ordinal)` (WS-B2 §6.1) so a re-parsed response cannot create a duplicate intent; `ConfigurationId`, `HarnessDefinitionRef`, `ModelProfileRef`, `ComponentVariantRef` are content addresses over canonical IR (`semantic_id`/`version_id`, WS-A3); `ArtifactId` and `ContextItemId` are content addresses (`ContextItemId` over `(bytes, provenance)` so identical text from different authorities is a different item).
3. **Surface ids are aliases:** provider response ids, provider tool-call ids, hosted-participant native ids are stored in `surface_ids{}` and indexed as aliases, never used as join keys.
4. **Ordering within a run:** `seq` is per-run, dense (`0..n`), strictly increasing, assigned only at durable append; `(run_id, seq)` totally orders one run. `event_id` and `hash` are separate: an event may be referenced before it is hashed and audited after (`hash = H(canonical(envelope − {hash}) ∥ prev_hash)`).
5. **Causality:** `parent_event_id` forms the branch tree (reserved root sentinel; HEAD moves by `lifecycle.head.moved`); `causes: [EventRef]` carries non-tree causal links, OTel-link style, and may cross runs; `EventRef = (run_id, event_id | seq)`. Across runs the order is partial (spawn/result/link edges); an optional hybrid logical clock field supports consistent-snapshot queries over subagent trees (OQ-WS-B1-02 decides whether it becomes mandatory for subagent-bearing runs). Uniqueness rule: `(run_id, event_id)` is unique; `(participant_ref, surface_id)` is an alias index (CloudEvents `source + id` shape).
6. **Fork and lineage:** a fork is a new run whose `lifecycle.run.created` carries `forked_from{run_id, at_seq, source_head_hash}`; the source is untouched and its referenced prefix is pinned against garbage collection while any fork is retained; `lineage(run)` resolves the chain root-first; the bundle export (WS-I3) materializes lineage so exported runs are self-contained. Child runs carry `parent_run_id` and `spawn_event: EventRef`; their `lifecycle.run.created` causally follows `control.subagent.spawned`.
7. **Interchange identifiability:** imported rows carry `provenance = imported{format, source}` and `participant_class = hosted`; exported runs round-trip `RunId`, `configuration_id`, lineage and `observability_level` (OQ-030 stays J6's for the format).

**T-LCD statement.** Satisfies T-LCD-10 (ledger identities are allocated or content-addressed; provider names are aliases), T-LCD-06 (hosted ids are aliases inside the native envelope), T-LCD-15 (per-event stamps preserved under fork/export). Not applicable: the remaining tests (no model-facing surface is introduced).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** RFC 9562 S-WS-B1-05 (time-ordered ids, monotonicity methods, index locality); OpenTelemetry Trace API S-WS-B1-01 (one parent, many links, immutable after end); CloudEvents S-WS-B1-02 (`source + id` uniqueness); Hybrid Logical Clocks S-WS-B1-06 (causality-preserving timestamps bounded by clock uncertainty); Shepherd S-078 (`provisional`, mechanism only: forks and filesystem layers addressed by content hash, siblings share their prefix); T-LCD-10 rationale (S-doc2 §9; ADR-0007).
- **(b) Source-code precedent:** Codex S-107 @0735c51 `codex-rs/protocol/src/thread_id.rs` (`Uuid::now_v7()`, "some use cases rely on that"), `protocol/src/protocol.rs` `SessionMeta{forked_from_id, forked_from_ordinal_exclusive, history_base}` ("Revert may replace the physical history base while retaining this fork boundary"), `core/src/session/session.rs` `ForkPersistence::Referenced{history_base}`; Pi S-113 @400d690 `packages/agent/src/harness/session/session.ts` (`idGenerator` default `uuidv7`), `session/types.ts` `EntryBase{id, parentId, seq}`; OpenHands S-110 @3fc7b22 `openhands-sdk/openhands/sdk/event/base.py` (`Event{id, parent_id}`), `conversation/state.py` (`leaf_event_id`, `navigate_to`, `path_to_root`), `conversation/impl/local_conversation.py` `fork` ("Events are copied so the source remains immutable" — the copy alternative); opencode S-111 @9f8db11 `packages/core/src/session/sql.ts` (`parent_id` on sessions for subagents; prefixed `msg…`/`prt…` ids); OpenHands `openhands-sdk/openhands/sdk/event/resume_transcript.py` L224 docstring (sandboxes "reset ``tool_call_id`` counters each session" — why surface ids are aliases). Fork-by-reference with a hash anchor and alias-indexed surface ids: partial precedent (Codex), the hash anchor is `novel` as a contract.
- **(c) Disconfirming evidence considered:** time-ordered ids leak creation time and are guessable within a millisecond window; allocated ids are not stable across re-runs so a re-executed run cannot be matched by id; referenced forks are not self-contained and break if the source is deleted (which is why Pi and OpenHands copy). *Why it does not overturn:* runs are distinct observations by design and are matched by `configuration_id` + `seed`; ids are opaque to consumers so the generator can be swapped; GC pinning of referenced prefixes and materializing export remove the self-containment risk where it matters (bundles).
- **(d) Conditionality:** independent of model tier and task class; assumes a monotonic generator per writer process (satisfied by the single-writer lease); the HLC option assumes bounded clock skew between hosts running subagents.
- **(e) Build-stage assignment:** C0 / Stage 1 (allocated ids, `seq`, `parent_event_id`, `causes`, surface aliases, content-addressed configuration refs); C0 / Stage 2 (fork-by-reference, lineage, HEAD navigation, GC pinning); C1 / Stage 4 (subagent lineage, HLC if adopted, interchange round-trip).

## Consequences

- WS-B2 emits every effect phase with the same derived `effect_id`; WS-D1's tool-call pairing uses `tool_call_id`, never the provider id.
- WS-L4's artifact registry maps names to lists of content addresses; the ledger stores addresses only.
- WS-I3's bundle exporter resolves `lineage(run)` and copies referenced prefixes; WS-J6's importer must supply `provenance = imported{...}`.
- Synthesis must pick one spelling for the structural-id alias pair (CF-WS-B1-04) and record it in the ontology.

## Reversibility

**Medium.** Switching the allocated-id generator or adding a global clock is cheap (ids are opaque). Switching fork-by-reference to fork-by-copy after Stage 2 is medium (lineage resolution disappears; exports unaffected). Replacing content addresses for configuration identity would break results keying and T-LCD-10 — effectively irreversible.
