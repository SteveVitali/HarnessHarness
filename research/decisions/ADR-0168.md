# ADR-0168 — CLI safety defaults: attendance is declared and recorded, unattended means `deny`, bypass requires containment evidence, ad-hoc overrides are materialised layers with human-origin gating; OQ-265 and OQ-076 answered for the CLI

**Status:** ratified
**Owner workstream(s):** WS-K1 (with WS-H7 as owner of the approval model, WS-H1 for Π narrowing leaves, WS-F2 for `ExhaustionPolicy`, WS-J1 for the override layer, WS-B5 for containment evidence) · **Phase:** 3 · **Related:** ADR-0069 (attendance as a manifest fact; Π-12; never-auto set; `bypass` only with `containment.sandboxed`; approval modes as typed parameters), ADR-0070 (`decided{decider: policy}`), ADR-0071 (policy fingerprint; exhaustion safeguard), ADR-0040 (hard ceilings; ledgered `amend`), ADR-0017/0037 (widening requires human origin), ADR-0024/0025 (layers; override grammar), ADR-0136…0138 (`enforcement_evidence`), ADR-0033 (minting rules), WS-J1 D2; OQ-076, OQ-265, OQ-246, OQ-387; CF-354, CF-355; R-2.11.1, R-2.8.7

## Context
All six anchor CLIs infer whether a human is present from the terminal (TTY) and then change safety behaviour on that inference: gemini excludes prompting tools and downgrades approval mode in untrusted folders; codex `exec` sets `AskForApproval::Never`; opencode auto-rejects permission requests without ledgering a decision; mini-swe-agent decides whether a limit may be raised; goose reads one line from a pipe. Each ships a "bypass everything" flag named as dangerous, but only codex records "already inside an external sandbox" as a distinct state, and Claude Code warns that `bypassPermissions` shadows its permission callback. Ad-hoc overrides (`-c key=value`, `--model`, `--approval-mode`) are universal and un-attributed. ADR-0069 already made attendance a run-manifest fact and made `bypass` conditional on recorded containment; WS-J1 D2 already answered OQ-076 for the assembly service. The CLI is where these facts are *set*, so its defaults are the operational form of the H7 decisions.

## Options considered
1. **Attendance declared with a recorded source (TTY inference as the default source); headless ⇒ `unattended` + `unattended_deny`; bypass preset refused without `enforcement_evidence = enforced`; every CLI override list desugars to one content-addressed `experiment` layer; widening overrides accepted only from a human at a TTY or with attestation; turn exhaustion `escalate` when attended, `defer` when async, `stop` when unattended/Lab.** — chosen.
2. **Infer attendance at every decision point from the TTY** (all precedents). Rejected: the inference is not in the ledger, changes between resume and restore, and lets the same sealed definition behave differently without a manifest difference (T-LCD-10 risk; ADR-0069 decision 6 already forbids it).
3. **Exclude prompting tools when unattended** (gemini). Rejected: changes the compiled tool surface and hence `configuration_id`; Π-12 already resolves `ask` without touching the surface.
4. **Discourage rather than gate bypass** (codex docs deprecate; opencode hides aliases). Rejected: ADR-0069 decision 3 makes containment a precondition, and the kernel-minted evidence exists (ADR-0136); discouragement leaves the never-auto set unprotected in scripts.
5. **Silently auto-reject in unattended mode** (opencode). Rejected in form only: the behaviour is kept, but each conversion is a `security.permission.decided{decider: policy, reason: unattended}` event so `denial_rate` and the repeated-denial fallback (ADR-0071 decision 5) see it.
6. **Allow `-l 0`-style unlimited budgets for convenience** (mini-swe-agent). Rejected: every AgentProcess references a Budget (ADR-0016); the CLI refuses `MissingBudget` rather than defaulting to unlimited.

## Decision
1. **Attendance.** The CLI writes `AttendanceDeclaration{value ∈ {interactive, async, unattended}, source ∈ {declared, tty_inferred, forced}}` into the run manifest before `open_run`: an explicit flag ⇒ `declared`; a `--no-input`-class flag ⇒ `forced(unattended)`; otherwise `tty_inferred` from stdin **and** stdout/stderr being terminals. **S-1:** no approval, exhaustion or elicitation decision re-derives attendance; the kernel reads the manifest. `interactive` without a TTY is an `InvocationError` (never a hang on a pipe). A later transition (continue interactively after headless input; a human attaching to a suspended run) is a ledgered `amend(attendance)` and, like any policy-fingerprint change, revokes leases (ADR-0071).
2. **Defaults per mode.** `attended terminal` ⇒ `approval_mode = tiered` (Π floor with `ask` rendered to the principal; `manual` on request). `headless` ⇒ `attendance = unattended`, `approval_mode = unattended_deny`; `unattended_defer` only when a notification sink is configured (`async`); `auto_review` only when a calibrated reviewer variant is named. Lab-launched runs take the experiment's values and the CLI cannot override them. Every Π-12 `deny` is `security.permission.decided{decider: policy, reason: unattended}`; a run blocked by such denials ends `approvals_exhausted`/blocked and maps to exit class `approval_denied_unattended`.
3. **Presets are lowerings.** Any precedent-style mode spelling the CLI offers is a `SurfacePreset{name, approval_mode, narrowing_leaves[], requires_containment}` (MUST-data) that lowers to one `approval_mode` value plus Π narrowing leaves — `plan`-class ⇒ `pre_approved_only` + `fs_write/exec` deny leaves; `auto-edit`-class ⇒ `tiered` + an `allow` lease pattern over `fs_write ∧ workspace_local`. A preset that makes a hook, reviewer or callback unreachable emits a warning naming the shadowed component (Claude precedent). The bypass preset is accepted only when the manifest records `containment.enforcement_evidence = enforced` from the environment handle (`BypassWithoutContainment` otherwise); it still excludes the never-auto set, its prompts cannot be suppressed, and its flag is deliberately long and hidden from completion.
4. **Overrides (OQ-076: yes, always).** Every CLI override list desugars through WS-J1 D2 into exactly one content-addressed layer with `LayerProvenance{source_kind: experiment}`; identical override lists from a terminal, a script or a sweep are one `overrides_layer_id`. **I-1:** an override whose `HirDiff.classification.authority_delta = widening` or `budget_delta = loosening` is accepted only when the invocation's principal is a human at a TTY (`declared`/`tty_inferred` interactive) or carries an attestation; from an unattended invocation it is refused with `AuthorityWideningRequiresHuman` before any run opens.
5. **Budgets are mandatory.** `run start` with no `Budget` from the definition, a named preset or a flag is refused with `MissingBudget`; there is no "unlimited" spelling.
6. **Exhaustion (OQ-265).** For turn and every other ceiling: `attendance = interactive` ⇒ `escalate` — the run reaches its decision point, closes open effects, and the CLI offers a ledgered `amend(budget)` or `stop`; `async` ⇒ `defer` (suspend + wakeup on `amend`); `unattended` and every Lab-launched run ⇒ `stop{budget_exhausted}`. The default is a `HarnessRule` leaf so the Lab can vary it; a Lab arm's `eval_budget` is never loosened.
7. **Workspace trust and credentials.** The CLI records `workspace_trust ∈ {trusted, untrusted, unknown}` from the H5 trust store as a manifest claim; any downgrade is a Π narrowing leaf keyed on it (OQ-387), never CLI logic. In unattended runs whose environment executes repository-controlled code the CLI warns when credentials are supplied through job-level environment and points at the broker binding (ADR-0058).

**T-LCD statement.** Satisfies T-LCD-10 (attendance and presets never change `configuration_id`; AC-K1-05), T-LCD-14 (budgets mandatory; Lab budgets untouchable; no trimming), T-LCD-02 (presets are typed leaves, no prose), T-LCD-05 (each preset's narrowing leaves are conditioned rules with debt records via the definition), T-LCD-13 (unattended denials are observable decisions). Not applicable: T-01/-03/-04/-06/-07/-08/-09/-11/-12/-15. ADR-0024 rung: `SurfacePreset` table, default `approval_mode` per mode, `ExhaustionPolicy` default are MUST-data; the attendance declaration, `BypassWithoutContainment`, `MissingBudget`, I-1 checks are MUST-code.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)
- (a) Mechanism evidence: ADR-0069 (attendance as manifest fact; Π-12; never-auto set; bypass ⇒ containment), ADR-0070/0071 (decisions ledgered; fingerprint revocation; exhaustion safeguard), ADR-0017/0037 (widening only from human origin), ADR-0136 (`enforcement_evidence`); [S-107] headless ⇒ `AskForApproval::Never` and `SandboxPolicy::ExternalSandbox` as a recorded state; [S-111] unattended auto-reject; [S-119] TTY-derived mode and untrusted-folder downgrade; [S-115] limit-raising gated on a TTY; [S-109] bypass shadowing warning; [S-535] `--no-input`, confirmation tiers; [S-327] prompt design affects adherence; [S-314]/[S-103] piped/imported text as an injection vector (why widening from a pipe is refused).
- (b) Source-code precedent: S-107 `codex-rs/exec/src/lib.rs` L562–571, L745–775 and `codex-rs/protocol/src/protocol.rs` L1088–1096 @0735c51; S-111 `packages/opencode/src/cli/cmd/run.ts` L801–820, L244–260 @9f8db11; S-119 `packages/cli/src/config/config.ts` L698–733, L759–763, L782–797 @ed2ac40; S-115 `src/minisweagent/agents/interactive.py` L80–110 @04d809c; S-109 `src/claude_agent_sdk/types.py` L1838–1843, L1991–2012 @ad77094; S-112 `crates/goose-cli/src/session/elicitation.rs` L32, L262 @fae91d0. The materialised override layer is WS-J1 D2 (no shipping precedent attributes ad-hoc overrides — `novel` relative to S-115 `-c` merging and S-107 `-c` overrides).
- (c) Disconfirming evidence considered: TTY inference is universal and usually right, so a declaration is ceremony (S-119, S-115, S-112) — kept as the *default source*, only recorded and frozen; vendors discourage rather than gate bypass (S-537 deprecates; S-111 hides) and a hard gate may invite faked evidence — the evidence is kernel-minted or a visible claim capping the bundle at R0, and ADR-0069 decision 3 already requires the gate; refusing widening from scripts blocks legitimate CI workflows — mitigated by attestations (ADR-0037) and by the fact that a sealed definition carrying the wider authority needs no override.
- (d) Conditionality: assumes ADR-0136's `enforcement_evidence` is available at `open_run` (true for every backend placement at C0); assumes OQ-246 stays open (only `allow_once`/`deny_once` are offered) — the preset table grows when it closes; independent of model tier and task class; budget presets are per deployment (MUST-data).
- (e) Build-stage assignment: C0/Stage 0 (`unattended` + `unattended_deny` + `MissingBudget`), C0/Stage 1 (attendance declaration and source; attended `tiered`; ledgered unattended denials; I-1; exhaustion `escalate`/`stop`), C1/Stage 2 (preset table incl. bypass gating; `amend(attendance)`; `workspace_trust` claim), C1/Stage 4 (`async`/`defer` with notification sinks).

## Consequences
- The same sealed definition runs attended and unattended under one `configuration_id`; attendance and denials are visible as ledger rows, so "does harness H degrade unattended?" is a Lab question with data (AC-K1-05/06).
- Script authors lose "unlimited" and "yolo without a sandbox" as spellings; they gain reproducible, attributable runs and a refusal that names the missing containment.
- WS-H1 receives two narrowing-leaf inputs (`workspace_trust`, preset leaves); WS-F2 receives the `ExhaustionPolicy` default rule; WS-B1 receives `attendance_source` and `overrides_layer_id` as manifest fields.

## Reversibility
**Medium.** The defaults are MUST-data and flip cheaply; the attendance declaration and I-1 are manifest/validation rules that later runs depend on for comparability — reversing them after Stage 3 invalidates cross-run comparisons of attended vs unattended behaviour.
