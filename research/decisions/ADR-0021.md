# ADR-0021 — Protocol targets are emitted as schema-conformant data documents carrying a minimum set of HIR metadata through typed extension slots; MCP tool surface at C0/Stage 3, ACP session at C1/Stage 4, A2A and Open Agent Spec at C2

**Status:** **ratified, amended** (Phase 2 synthesis, 2026-09-10); previously: **ratified, amended** (Phase 1 synthesis, 2026-09-10)
**Owner workstream(s):** WS-A4 (lowering/lifting mechanism) → WS-E4 (protocol edges), WS-K3 (MCP surface), WS-J6/WS-K4 (participation), WS-L6 (`_meta` prefix) · **Phase:** 1 · **Related:** ADR-0005 ("act as a participant"), ADR-0006 (N5: no new protocol), ADR-0007 (T-LCD-04/-06/-11), ADR-0008 (target / lowering / lifting / lowering loss report), ADR-0009 (Q-L1-08), ADR-0011; ADR-0015/ADR-0018 (extension slots; Agent Spec as declared-lossy target; `EffectClass`); CF-045, CF-047, CF-048, CF-051; OQ-043, OQ-031, OQ-068, OQ-069, OQ-070; R-2.1.3, R-2.5.4, R-2.10.6

## Context

Phase 0 settled that ACP, MCP, A2A and provider tool APIs are *lowering targets* and that the compiler must be able to expose a native harness through an ACP-style session interface (ADR-0005; phase-0 §5.5). T-LCD-11 requires lowering to be lossless-or-declared-lossy, with metadata carried through typed extension slots and lifting recovering everything not declared lost; T-LCD-04 requires two targets at Stage 3. WS-L1 asks (Q-L1-08) whether the compiler must emit MCP schemas, A2A AgentCards and ACP session config. The three protocol specs were read in source: MCP 2026-07-28 (`Tool{name, title, description, inputSchema, outputSchema, annotations, _meta}`; annotations are hints that clients "should never make tool use decisions" on from untrusted servers; `_meta` keys are reverse-DNS prefixed), ACP v2 (`_meta` on every type; no custom root fields; config options with categories `mode`/`model`/`_custom`; unknown option types MUST be preserved and otherwise ignored; agents MUST provide defaults) and A2A (`AgentCard` with `AgentExtension{uri, params, required}` and `AgentSkill`, `Task`/`Message`/`Artifact` with `metadata`; no per-tool concept). Open Agent Spec has `Component.metadata` as its only free slot, random uuid identity, and no permission/effect/validator/budget/provenance entities (WS-A3 §6.8).

## Options considered

1. **Protocol bindings hand-written per target inside the runtime; no compiler involvement.** *Rejected:* metadata loss is silent (T-LCD-11 failure signature); no round-trip test possible; effect/permission semantics diverge per binding.
2. **Emit host-language server/client code per target** (Agent Spec adapter shape). *Rejected:* same reasons as ADR-0019 option 2; also ties WS-E4's transport choice to the compiler.
3. **Carry all HIR metadata by inventing new protocol fields or a new protocol.** *Rejected:* violates non-goal N5 (ADR-0006) and the specs' own rules (ACP forbids custom root fields; MCP reserves unprefixed `_meta`).
4. **Emit schema-conformant target documents from the published schema sources; carry a fixed minimum set of HIR metadata in each target's sanctioned extension slot; classify and report every loss; lift on import with imported authority; degrade to `product` granularity when the minimum set cannot travel (chosen).**

## Decision

1. **Artefacts are data.** Stage 4 emits, per target, a document conforming to the target's published schema (MCP `schema/2026-07-28/schema.ts`/`schema.json`; ACP `schema/v2/schema.json`; A2A `a2a.proto`/JSON; Agent Spec's schema), never host-language code (OQ-043 part 2 / Q-L1-08: **yes, the compiler must emit them**). Protocol bindings are generated from those schema sources with CI drift checks (WS-L1 §6.5 pattern; WS-E4 implements transport).
2. **Minimum carried set.** `{semantic_id + bundle_id, effects (WS-A3 EffectClass set), permission class, provenance pointer (origin + authority class), budget reference}` must travel in the target's typed extension slot — MCP `_meta["<hh-prefix>/hir"]`, ACP `_meta` on every emitted type, A2A `AgentExtension{uri: <hh-hir-uri>, params}` at card/skill level — or the export is admitted only at `product` granularity (ontology *comparison granularity*). Whether cost/risk classes join the set is OQ-069; the prefix/URI is WS-L6's (OQ-068).
3. **Effect projection.** MCP hints are a fixed projection of `EffectClass` (a projection of each class's `EffectAttributes` per ADR-0016 entity 8: `readOnlyHint ⇐ ∀ effects: mutability = read_only`; `destructiveHint ⇐ ∃ effect with mutability = destructive`; `idempotentHint ⇐ ∀ effects: repeat_safety = idempotent`; `openWorldHint ⇐ ∃ effect with world = open ∨ resources.declared = false`; domain spelling `fs_read, fs_write, …` — CF-102/CF-047). Authority never flows through hints: hints alone lift to `provenance.origin = import`, `authority = unverified` (CF-082), which the reference monitor treats as default-deny until probed.
4. **Loss reports are typed.** `LoweringLossReport{target, target_version, entries[{hir_node_id, field, class ∈ {no_slot, hint_only, untyped_slot, narrowed, truncated}, severity ∈ {info, narrowed, lost}}], granularity_ceiling ∈ {component, configuration, product}}` is part of the bundle; `lift(lower(x)) ∪ loss_report = x` is a round-trip test for every target the compiler itself produced (T-LCD-11). Silent coercion (e.g. inventing `type: "string"` for an unsupported schema, the opencode `sanitizeOpenAISchema` behaviour) is forbidden; a narrowing is either declared `narrowed` or raised as `UnexpressibleSurface` per the profile's `strict: prefer | require` policy.
5. **Per-target mapping.** *Provider tool API* (per profile): request plan in the profile's dialect (function / custom-freeform / namespace / strict subset), layout, sampling, cache markers, deferral — consumed by the model, not lifted. *MCP tool surface*: `tools/list` entries + `listChanged` when run-time selection changes; permission enforcement location, budgets and validators are declared `no_slot`. *ACP session*: `initialize` capabilities from the definition's capability declaration; session-variable HIR parameters (model, mode, reasoning level) → `configOptions` in categories `model`/`mode`/`_hh_*` with mandatory defaults; ledger events → `session/update`; reference-monitor decisions → `requestPermission`; `_meta` ids on every type; `_`-prefixed extension methods for ledger export. *A2A*: `AgentCard{skills ← exported Procedures/Goals by semantic id, capabilities.extensions[hh-hir], version ← bundle_id, signatures}`; `Task` states ← run states (`INPUT_REQUIRED` ← permission/elicitation, `AUTH_REQUIRED`, `REJECTED` ← policy denial); all per-tool metadata lost by construction. *Open Agent Spec*: the WS-A3 §6.8 mapping; `Component.metadata` carries the ids; the seven-plane surplus is listed lost; import lifts to default-deny, `authority = imported`; `product` granularity only.
6. **Tiers and stages.** MCP tool-surface lowering + lifting + loss report: **C0 / Stage 3** (the second target T-LCD-04 needs; CF-045 stage note on R-2.5.4). ACP session artefact: **C1 / Stage 4** (ADR-0005 participation; running as a hosted participant in foreign planes stays C2 — CF-051). A2A card/task and Agent Spec export/import: **C2**.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: typed extension slots plus "preserve unknown, never coerce" as the LCD antidote in three independent protocol specs (S-153 MCP `_meta` + hint semantics; S-035 ACP extensibility and config-option rules; S-180/S-156 A2A `AgentExtension`/`metadata`), corroborated by LSP capability negotiation (S-152) and the AWT/WORA history (S-154, via WS-L7); silent lowering loss as an observed failure (S-111 `sanitizeOpenAISchema` drops keywords and invents types; S-113 `makeStrictJsonSchema` instead throws a typed error — the declared-loss pattern); lifting precedent (S-139 `LangGraphToAgentSpecConverter`); interop-not-duplicate stance (ADR-0005).
- (b) Source-code precedent: `modelcontextprotocol/schema/2026-07-28/schema.ts` L954–970, L1907–2016 and `docs/specification/2026-07-28/basic/index.mdx` (`_meta` prefix grammar, reserved prefixes) (S-153 @aa8ce04); `agent-client-protocol/schema/v2/schema.json` (175 definitions) and `docs/protocol/v2/{session-config-options,extensibility}.mdx` (S-035 @9b00c27); `a2a/specification/a2a.proto` L158–470 (S-180 @98853be); `pyagentspec/src/pyagentspec/component.py` L157–174 (`extra="forbid"`, uuid id, `metadata`) and `adapters/langgraph/{_langgraphconverter,_agentspecconverter}.py` (S-139 @6f0b6ae); `codex-rs/tools/src/tool_spec.rs` L22–100 and `responses_api.rs` L16–43 (provider tool-API dialects as a target, S-107 @0735c51); `crates/goose/src/providers/claude_acp.rs` L70–102 (an ACP agent consumed *as a provider*, with a mode-mapping table — evidence that ACP config options are the right carrier for session-variable parameters, S-112 @fae91d0). The minimum carried set, the loss-class enum and the granularity ceiling are `no-precedent / novel`.
- (c) Disconfirming evidence considered: (i) A2A carries no per-tool metadata, MCP forbids trusting annotations, ACP has no budget/validator concept — so lifting recovers little and T-LCD-11 risks being satisfied trivially. Answered: the purpose of protocol targets is participation at `product`/`configuration` granularity (ADR-0005), the minimum carried set is fixed and non-trivial for MCP/ACP, and the comparison engine already refuses component-level metrics on such rows (T-LCD-15). (ii) Agent Spec has six runtime adapters, so export would seem to unlock six more targets (WS-A1 OQ-031 framing) — answered: two-hop lowering compounds loss and silently changes permission/effect semantics; export is C2 `product`-granularity only (CF-048, consistent with WS-A3 CF-040). (iii) Provider tool APIs change faster than any spec version pin — answered: the provider target is per profile and the profile carries the debt record and expiry; pins are in the derivation key. None overturns.
- (d) Conditionality: assumes MCP 2026-07-28, ACP v2 and A2A 1.0.0 remain the served versions through Stage 4 (target-spec versions are inputs to the derivation key; a bump is a recompile plus a loss-report diff); assumes the reference monitor treats `imported` authority as default-deny (WS-H1/L3, CF-006); independent of model tier.
- (e) Build-stage assignment: **C0 / Stage 3** MCP tool-surface lowering/lifting/loss report + provider tool-API target for two profiles (T-LCD-04/-11 executable); **C1 / Stage 4** ACP session artefact; **C2** A2A, Agent Spec, code-mode and grammar-constrained dialects (WS-E2/E4).

**T-LCD statement (ADR-0007 decision 5).** Satisfies: T-LCD-04 (two targets from one definition with identical policy tables, by construction from the shared `RuntimePlan`), T-LCD-06 (targets are outputs; no IR entity depends on any protocol), T-LCD-07-adjacent (lifted declarations are `imported`, never coerced to facts), T-LCD-11 (typed loss report + round-trip test), T-LCD-15 (granularity ceiling feeds `applies_to`). Does not by itself satisfy T-LCD-03 — not applicable to targets; covered by ADR-0019.

## Consequences

- WS-E4 implements transports against compiler-emitted documents and owns nothing model-conditioned; WS-K3's MCP surface is `lower_target(…, mcp)` plus a server.
- WS-L6 must allocate and collision-check the reverse-DNS prefix and A2A extension URI before Stage 3 fixtures are frozen.
- WS-H1/L3: imported/lifted content is `origin = import`, `authority = unverified` (ADR-0033 fixes the seven classes; CF-082).
- Scope register: stage notes on R-2.5.4 (CF-045); tier split confirmed at synthesis: the ACP session *artefact* is C1/Stage 4, *running* as a hosted participant in foreign planes is C2/Stage 4 (CF-051).
- WS-L1: Q-L1-08 answered — yes; the ecosystem needs schema-first generation of bindings from three published schema sources with CI drift checks, and first-class JSON-Schema manipulation.

## Reversibility

**High for tiers** (a target can be moved between C0/C1/C2 by ADR without touching the mechanism); **medium for the minimum carried set** (shrinking it after Stage 3 changes which experiment rows keep `configuration` granularity and must be re-labelled); **low for "data not code"** (shared with ADR-0019).
