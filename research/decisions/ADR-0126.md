# ADR-0126 — The expiry/revalidation contract: observable-based expiry triggers, the profile status state machine as ledger events, compatibility-token change as a re-lowering trigger, the removal test as a matched-budget non-inferiority `ComparisonReport`, `expired` compilation only with recorded intent, and reflexive expiry of the Profile Compiler

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-C3 (consumers: WS-I6, WS-C2, WS-C1, WS-A4, WS-B1, WS-J3, WS-I2, WS-I5) · **Phase:** 2 · **Related:** ADR-0002 (evolution edits surfaces; retirement test), ADR-0007 (T-LCD-05/-09/-14), ADR-0013 (DRIFT stratification), ADR-0017 (`HirDiff` / profile diffs), ADR-0019 (`relower`, `model.surface.relowered`), **ADR-0020 §4/§7 (debt discipline and expiry states this ADR makes operational)**, ADR-0026/0027 (events, `causes[]`), ADR-0036/0037 (immutable records, supersession), ADR-0041/ADR-0046 (`MatchSpec`, `ComparisonReport`, `benefit_kind`), ADR-0045 (distributional reporting, per-task `(c, n)`); ADR-WS-C1-3 proposed (`served_model`, discovery claims, fingerprint); CF-268; OQ-071, OQ-294, OQ-301, OQ-304, OQ-305; R-2.3.3, R-2.9.6, R-2.9.5

## Context

ADR-0020 fixed `expiry_condition ∈ {model_version_change, date, probe_failure, evidence_refresh_due, experiment_ref}`, four states and the compiler's refuse/warn/retire behaviour, and named "retire rule R" as `relower(bundle, profile − R)`. What it did not fix is *what observation fires each condition*, how transitions are recorded, and what a removal test must show. The mechanism evidence is unambiguous: the "same" model service changes behaviour substantially within months, including formatting compliance (S-460); production teams find workarounds have become dead weight only by inspection (S-047; S-049 "mostly long gone"); aggregate gains hide reliably regressed subsets (S-461, `provisional`), so a removal test judged by a net figure can retire a rule that a subset of tasks still needs. The audit found exactly one system that treats "the model changed under me" as an event with a handler: codex carries a provider-supplied *compaction compatibility hash* per slug (`models.json` `comp_hash`) and, when it differs from the previous turn's, runs compaction under the **previous** model before the new one samples (`core/src/session/turn.rs` L1233–1300; `CompactionReason::CompHashChanged`); codex also encodes deprecation as data (`upgrade{model, migration_markdown, retirement_at}`) — a scheduled expiry. WS-C1 provides the other observables (`served_model ≠ requested`, discovery claims, a distributional fingerprint, `seed_honoured`). Nobody records profile status transitions.

## Options considered

1. **Expiry by hand-edited version strings and calendar reviews** (status quo). *Rejected:* the version string does not change when behaviour does (S-460); dead weight found by reading (S-047).
2. **Expiry fires on any DRIFT and blocks compilation.** *Rejected:* stops the Lab on irrelevant drift; ADR-0013 makes DRIFT a stratification fact.
3. **Removal test = mean improvement on a benchmark.** *Rejected:* unmatched budget (S-083) and hidden per-item regressions (S-461); retires rules a subset still needs.
4. **Retirement by automatic deletion when a removal test passes.** *Rejected:* ADR-0020 §7 requires ADR for `retired`; automatic deletion is an evolution edit subject to ADR-0002 governance.
5. **Observables per condition; a small state machine whose only consequential transitions (`expired`, `retired`) are gated by recorded intent or a passed removal test; transitions as ledger events with `causes[]`; compatibility-token change as a re-lowering trigger; removal test as a paired, matched-budget non-inferiority `ComparisonReport` with per-item reliability; reflexive records on the compiler (chosen).**

## Decision

1. **Observables per trigger.** `model_version_change` ⇐ (i) `served_model ≠ model_ref.provider_model_id` on ≥ 1 call of the binding (C1 `model.call.completed`), (ii) `capabilities.compatibility_token` ≠ the token in the latest discovery claim (C1 `discover`), (iii) fingerprint `DRIFT` (C1 probe), (iv) `resolve_profile` finds no listed model for the selector for longer than `grace_period`; `date` ⇐ `now ≥ expiry.until` or `selector.retirement_at` passed; `probe_failure` ⇐ `ConformanceRecord{verdict ∈ {DRIFT, UNSUPPORTED}}` for a capability in the rule's *dependency set* (each rule kind declares which capabilities it depends on; e.g. `caching_markers` → `cache_control_convention`, `max_cache_breakpoints`); `evidence_refresh_due` ⇐ `max(age(evidence_refs)) > evidence_max_age` (default OQ-304); `experiment_ref` ⇐ a `ComparisonReport` for the rule's removal design reporting non-inferiority of the removal arm. Version strings never fire a trigger.
2. **State machine (per rule; the profile's status is the worst of its rules'):** `active → expiring` on any trigger; `expiring → active` on `revalidated{evidence_ref}` (a passed probe or compliance report newer than the trigger); `active | expiring → expired` on dependency `probe_failure`, on (iv) beyond `grace_period`, or on `retirement_at`; `expired → retired` only by ADR after a passed removal test; `expired → active` only on a fresh evidence refresh **and** a probe pass. `evaluate_expiry(profile, observables, now)` is pure and proposes transitions; the registry appends them.
3. **Events (WS-B1 `model` category; payload extension proposals):** `model.profile.status.changed{profile_ref, rule_id?, from, to, trigger, evidence_ref, causes[]}`, `model.profile.probed{profile_ref, probe_run_id, records[]}`, `model.profile.expired_used{profile_ref, intent_ref}` (appended to any run compiled under `expired` with recorded intent). Runs are stratified by profile status like any DRIFT (ADR-0013); `expired_used` runs are excluded from headline claims unless the `Design` names dead-weight testing as its purpose (S-047).
4. **Compatibility-token change is a re-lowering trigger.** On (ii) the runtime performs `relower(bundle, same_profile)` before the next call and appends `model.surface.relowered{…, reason: compatibility_token_changed}` (new `reason` value proposed to ADR-0019/WS-B1); whether compaction under the previous profile must precede it (codex behaviour) is OQ-305 with D2/A4.
5. **Removal test.** `RemovalTest{rule_id, design_ref}` where the `Design` has two arms, `P` and `P − R` (from `retire_rule`; `relower` one call away), the same model snapshot(s) with roles, the same seeds, `MatchSpec{mode: matched_cap}` and equal `eval_budget`; verdict = non-inferiority of `P − R` on every headline metric within a pre-registered margin (two one-sided tests over the paired per-task distribution, ADR-0045 intervals) **and** the share of tasks reliably regressed (per-task `(c, n)` classification) below a pre-registered bound (OQ-301); reported as `ComparisonReport{benefit_kind: artifact_benefit, budget_match.status}`. Pass ⇒ eligible for `retired` by ADR; fail ⇒ `revalidated` with the report as new `evidence_refs`. Retirement of a *profile* requires every rule retired or a successor profile (`successor_ref`) whose removal test over the whole chain passes.
6. **Compile under `expired`** requires `intent_ref` (a `Design` or an operator record) in the bundle inputs; without it `link` refuses (`LinkError{expired_without_intent}`); `expiring` only warns and is listed in `lcd_report.conditioned_rules`.
7. **Reflexivity.** The Profile Compiler carries `AssumptionDebtRecord{hypothesis: "≥ 2 provider families with materially different tool/transcript conventions are in use", expiry_condition: evidence_refresh_due, removal_test_ref: "compile every registered definition under the null profile and pass the Stage-3 suite"}`; every C1 `WireDialect` and every profile carry their own; `retired` for the compiler is the honest end state if conventions converge (ADR-0020 §(d)).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: behaviour changes under a stable id and formatting compliance is among what changes (S-460 Tier B); dead weight is discovered by inspection today (S-047, S-049 Tier B); a provider-supplied compatibility token is treated as an event in production (S-107); scheduled retirement is practice (S-107 `upgrade.retirement_at`; S-462 `provisional`, corroborating only); aggregate verdicts hide reliable per-item regressions (S-461 `provisional`, mechanism only); matched-budget and paired, distributional comparison are ratified (ADR-0041/0045/0046; S-083); served-model drift and fingerprint are observable at the gateway (WS-C1 §6.5; S-441 Tier B).
- (b) Source-code precedent: `codex-rs/models-manager/models.json` (`comp_hash`; `upgrade{model, migration_markdown, retirement_at: "2026-08-31T19:00:00Z"}` on `gpt-5.4`), `codex-rs/core/src/session/turn.rs` L1233–1300 (`comp_hash_changed`, `maybe_run_previous_model_inline_compact`), `codex-rs/core/src/compact_model_fallback.rs` L1–60 (`CompactionReason::{ModelDownshift, CompHashChanged}`, `should_retry_with_current_model` "failures that may be model-specific") (S-107 @0735c51); `goose/crates/goose-provider-types/src/formats/anthropic.rs` L110 `thinking_block_is_stale(message, current_model)` (S-112 @fae91d0, via ADR-0019); served-model drift as data — `codex-api/src/common.rs` `ServerModel`, pi `responseModel`, Inspect `ModelFallback` (via WS-C1). The status state machine as ledger events, observable-typed triggers, the non-inferiority removal test and reflexive compiler expiry are `no-precedent / novel`.
- (c) Disconfirming evidence considered: (i) triggers will fire constantly under monthly churn and `expiring` becomes noise — answered: `expiring` gates nothing; only `expired`/`retired` are consequential and both are evidence-gated; the stratification is what the Lab needs anyway (ADR-0013); (ii) removal tests are expensive and providers change during them — answered: one paired design per rule under `matched_cap`, run at experiment boundaries beside probes; a fingerprint DRIFT inside the design splits the arm (C1 policy), never pools; (iii) codex's compatibility token is a single-provider artefact — answered: the field is optional (`compatibility_token?`), the trigger set has three other observables, and the re-lowering handler generalises goose's stale-signature drop; (iv) non-inferiority margins are arbitrary — answered: pre-registered per `Design` (ADR-0045 `PreRegistration`), with OQ-301 fixing defaults with I2. None overturns.
- (d) Conditionality: assumes providers expose at least `served_model` per call (true for every audited dialect; `unknown` otherwise, which fires nothing); assumes the Lab can afford paired removal designs for rules under review (a C1/Stage-5 capability; rules without a design simply never reach `retired`); independent of model tier; no `provisional` claim is load-bearing — S-461/-04 shape the verdict and corroborate scheduling only.
- (e) Build-stage assignment: **C0 / Stage 1** (event classes; `RemovalTest`/dependency-set schemas; `LinkError{expired_without_intent, capability_drift}`); **C0 / Stage 3** (manual `evaluate_expiry` with injected observables on the two minimal profiles; `expired` intent path; `retire_rule` arm compiles); **C1 / Stage 5** (automatic trigger evaluation from C1 observables, compatibility-token re-lowering, removal-test recipe wired to J3, `successor_ref` retirement path with C2); **C4** (WS-I6 manager: scheduling, owners, fleet policy; WS-I5 uses the removal test as its retirement gate).

**T-LCD statement (ADR-0007 decision 5).** Satisfies: T-LCD-05 (every trigger is an observable; refuse/warn/retire operational; "retire rule R" is a `Design`; reflexive on the compiler and dialects), T-LCD-09 (removal tests are per model snapshot, so rule × model interaction is reported), T-LCD-14 (`MatchSpec` mandatory; `benefit_kind` and `budget_match.status` on every report), T-LCD-13 (revalidation evidence includes compliance reports). Does not by itself satisfy T-LCD-01/-10 (ADR-1 of this workstream). Rung on the ADR-0024 ladder: records, triggers and designs are MUST-data; `evaluate_expiry` is MUST-code (kernel algorithm).

## Consequences

- WS-I6's manager consumes `model.profile.status.changed` and schedules probes/removal tests; WS-I5's retirement gate is this removal test.
- WS-B1 adds three `model.profile.*` event classes; WS-A4/WS-B1 add `reason: compatibility_token_changed` to `model.surface.relowered`.
- WS-C1 surfaces the compatibility token in discovery claims where available; WS-C2 treats `retirement_at` and `expired` as guard inputs.
- WS-J3 provides the paired removal `Design` template; WS-I2 fixes margins (OQ-301).

## Reversibility

**Medium.** Trigger observables and margins are data and can be tuned by ADR at low cost. Removing the intent requirement for `expired` compilation, or accepting mean-based removal verdicts, would silently reintroduce inspection-based dead-weight discovery and the unmatched-budget trap — the costly direction. The compatibility-token re-lowering can be disabled per dialect without contract change.
