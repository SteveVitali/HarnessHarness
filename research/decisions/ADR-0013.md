# ADR-0013 — Participant-class formalization: class = transparency of H; participant descriptor; admissible granularities; total ABI projection; class never inferred from mechanism

**Status:** **ratified** (Phase 1 synthesis, 2026-09-10)
**Owner workstream(s):** WS-A2 (with WS-J6 for the Hosting ABI, WS-A3 for `OpaqueProcess`, WS-J4 for admissibility) · **Phase:** 1 · **Related:** ADR-0001 (ratified; formalized, not amended), ADR-0004, ADR-0005, ADR-0007 (T-LCD-06/-07/-15), ADR-0010; CF-003, CF-010, CF-020, CF-023, CF-027, CF-031 (settles CF-059); OQ-004, OQ-034, OQ-038, OQ-048; R-2.10.4, R-2.10.6

## Context

ADR-0001 ratified two participant classes and its consequences ask WS-A2 to formalize them "together with comparison granularity and observability level". Phase 0 folded three hosting mechanisms and four observability levels into v0.1, and WS-A3 now types a hosted participant as `AgentProcess.hosted = OpaqueProcess` with a tri-state capability record. What remained undefined is the *criterion* that makes something native or hosted. The audits show the criterion cannot be observability: model-boundary interception (Inspect bridge, ClawGym II; OQ-038) yields complete model I/O for a participant whose internals are unknown, and a native harness run through the Hosting ABI (ADR-0005 "act as a participant") looks hosted from outside. Without a criterion, class would be inferred from mechanism, `ledger` could be claimed by declaration, and component-level metrics could leak onto opaque participants — the T-LCD-15 failure signature.

## Options considered

1. **Class = observability level** (white-box iff `model_io` or `ledger` available). Rejected: grey-box interposition yields `model_io` without decomposability; a full native-shaped export from a hosted product is still an opaque H.
2. **Class = hosting mechanism** (native iff `mechanism = none`). Rejected: a native harness exposed through the session-ABI (ADR-0005) would flip class by deployment choice; class must be a property of θ, not of plumbing.
3. **Three classes (native / grey-box / hosted).** Rejected: grey-box differs from hosted only in observability; a third class would make every MetricDeclaration and every comparison stratify on a mechanism detail and invite further classes per mechanism (the intersection trap in reverse).
4. **Chosen: class = transparency of H**, with observability and mechanism as orthogonal fields of a participant descriptor, admissible granularities derived from class and capability vector, and a total ABI projection for native runs.

## Decision

1. **Class criterion.** A participant P is **native** iff its θ is a Harness Definition h in HIR known to the Lab, so H = compile(h, p) is transparent and component-level variation is meaningful. Otherwise P is **hosted**: H is opaque and θ_hosted = product version + ABI-settable coordinates. ADR-0001's definitions are unchanged; this is their formal reading. Typed form: `AgentProcess.native` / `AgentProcess.hosted = OpaqueProcess` (WS-A3).
2. **Participant descriptor** (instrument level, immutable per run, stored in the run manifest): `{class ∈ {native, hosted}, hosting_mechanism ∈ {none, session-abi, model-boundary-intercept, container-installed}, capability_declaration, version_identity, observability_level ⊆ {events, model_io, end_state, ledger}, model_binding ∈ {bound(M-set), self-selected}}`. **Class is declared, never inferred** from mechanism or observability (`ClassUndeclared` is an error). **`ledger ∈ observability_level ⇔ class = native`** — `ledger` is entailed, never declarable (settles CF-059). Grey-box = `hosted` with `observability_level ⊇ {model_io}`.
3. **Capability declaration vs vector** (CF-020 confirmed): the declaration is the claimed record; `capability_vector = reconcile(capability_declaration, probes) → {declared, probed, unknown}`; DRIFT only when both sides are concrete and differ (symmetric); an omitted wire capability (ACP "UNSUPPORTED") is re-mapped to `unknown` at the analysis layer (CF-027).
4. **Admissible granularities.** `admissible_granularities(P)`: native ⊇ {component-level, configuration-level, product-level}; hosted ⊆ {configuration-level restricted to coordinates whose capability-vector entry is SUPPORTED, product-level}. The experiment engine refuses a factor outside the set (`InadmissibleFactor`); the report renders `n/a`, never 0 and never a configuration-level proxy (T-LCD-15).
5. **ABI projection.** `proj_ABI : native ledger → minimum observable event set` is total: every native run can be presented as a hosted run (ADR-0005), and there is no edge from any HIR entity to the Hosting ABI (T-LCD-06). A native harness observed by a lab that does not own its definition is *hosted for that lab* — class is relative to the Lab's knowledge of θ, which is why it must be declared.

**T-LCD statement.** Satisfies T-LCD-06 (projection direction; no reverse edge), T-LCD-07 (declare/verify/stratify; `unknown` never coerced in either direction), T-LCD-15 (admissible granularities ⇒ `n/a`). Does not address T-LCD-03/-04 (native-side expressibility, WS-A3/A4).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: hosts see very different things about a participant depending on mechanism but never know H (WS-A1 F2 on Harbor/Omnigent/Inspect; S-136/S-137, S-132, S-118); declared and observed capability are distinct objects with a reconciliation rule (Omnigent S-118; ACP S-035 negotiation; Harbor frozen capabilities S-132); model-boundary interception exists as a grey-box option (OQ-038; S-137, S-140 via WS-L7); the LCD failure signature "a hosted participant scoring 0 on attribution" (ADR-0007 T-LCD-15) is what the admissibility rule prevents; the comparison plane spanning both classes is *precedented* (ADR-0004; HAL S-135 Tier A) — this ADR claims no novelty for the plane, only for the criterion and the admissibility derivation (novelty items (ii)/(iii) of ADR-0004).
- (b) Source-code precedent: `omnigent/omnigent/harness_capabilities.py` (`None ⇒ UNKNOWN`), `omnigent/tests/harness_bench/verdict.py` (`reconcile`, symmetric DRIFT), `harbor/src/harbor/agents/capabilities.py` (frozen `AgentCapabilities`) and `agents/base.py` (`BaseAgent.capabilities` ClassVar; `setup/run/resume/load/handoff`), `agent-client-protocol/schema/v2/schema.json` (`AgentCapabilities`, `ClientCapabilities`) and `docs/protocol/v2/initialization.mdx` ("omitted … UNSUPPORTED"); `software-agent-sdk` `AgentProfile{openhands | acp}` (via WS-A3). The *transparency-of-H criterion* and *class-relative-to-Lab* rule are `no-precedent / novel`; the descriptor is `renamed + narrowed` from WS-A1 §6.4.
- (c) Disconfirming evidence considered: (i) grey-box participants blur the dichotomy — absorbed by making observability a level, not a class; (ii) a native harness through the ABI looks hosted — absorbed by class-relative-to-Lab and by declaring class; (iii) ADR-0001 (c) notes the ABI may be too thin to hold context policy fixed across hosted participants — this ADR makes that limitation explicit as "configuration-level restricted to SUPPORTED coordinates" rather than hiding it; (iv) WS-A1's descriptor let hosted participants declare any observability level — overruled for `ledger` only, because a native-shaped export does not make H transparent.
- (d) Conditionality: independent of model tier and task class; assumes hosted participants can at minimum start/stream/cancel and account cost (ADR-0001 conditionality); assumes the capability vector's probes exist by the time hosted participants join (C2 / Stage 4 per ADR-0010) — until then, every hosted entry is `unknown` and admissible granularities collapse to `product-level`.
- (e) Build-stage assignment: C0 / Stage 1 — descriptor schema, class field, `admissible_granularities` as an engine precondition, `MetricDeclaration.applies_to_classes`; C2 / Stage 4 — capability declarations, probes, conformance records, proj_ABI implementation (WS-J6/K4).

## Consequences

- WS-J6's ABI descriptor must *lower to* the participant descriptor and WS-A3's `OpaqueProcess`; it may not add fields to native entities (T-LCD-06).
- WS-B1 derives the `ledger` stamp from `participant_class` and stores the descriptor in `lifecycle.run.created`.
- WS-J4's report generator consumes `admissible_granularities` and `MetricDeclaration.applies_to_classes`; a mixed-class fixture is an acceptance test (AC-A2-4).
- OQ-038 is reframed: model-call interposition is an observability upgrade for a hosted participant, never a class change.
- OQ-048: when the Lab overrides a hosted participant's model via interception, the participant stays hosted (H still opaque) and the model coordinate becomes `configuration-level` for that role only.

## Reversibility

**Medium.** Adding a third class later is a schema and register change plus re-stratification of stored results; removing the `ledger ⇔ native` entailment is a one-line rule change but would require re-auditing every component-level metric ever reported on a hosted row. The criterion itself is definitional and cheap to restate; its cost of reversal is the loss of T-LCD-15's guarantee.
