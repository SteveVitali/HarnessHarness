# ADR-0025 — The assembly validation contract and sealed-definition identity: staged diagnostics with layer provenance, one resolver feeding the compiler's `link`, configuration identity from `semantic_id`, `HirDiff` as the edit unit, resume verification, and a declared parameter space with a Hydra-class override grammar

**Status:** **ratified, amended** (Phase 1 synthesis, 2026-09-10)
**Owner workstream(s):** WS-A5 (consumers: WS-A3, WS-A4, WS-B1, WS-L4, WS-J1, WS-J2, WS-J3, WS-J5, WS-I3, WS-I5, WS-I7, WS-C3) · **Phase:** 1 · **Related:** ADR-0002, ADR-0004, ADR-0007 (T-LCD-02/-05/-06/-08/-10/-12/-14), ADR-0008, ADR-0011; ADR-0023, ADR-0024; ADR-0015 (`validate`, `canonicalize`, `identity`, `seal`; `UnresolvedRef`), ADR-0016 (kernel invariants; only resolved documents sealable), ADR-0017 (`HirDiff`, `Rebind`, `SurfaceEdit`), ADR-0019 (stage 0 `accept` / stage 1 `link`; `NotSealed`; `derivation_key`/`bundle_id`), ADR-0026/ADR-0027 (`configuration_id` in the manifest; content addresses; `measurement.experiment.bound`), ADR-0029 (canonical byte form); CF-052, CF-056, CF-053; OQ-041, OQ-056, OQ-073, OQ-074, OQ-076, OQ-079; R-2.1.4, R-2.10.1, R-2.10.3, R-2.12.1

## Context

Once a Harness Definition is a data document (ADR-0023), the instrument needs the operations that turn authored fragments into the object results are keyed by, and the guarantees those operations give the Lab. Three neighbours have already fixed the surrounding pieces: WS-A3 owns `validate` (kernel invariants), `canonicalize`, the two-id `identity` and `seal` over HIR documents and states that unpinned selectors are legal only in the assembly section and must be resolved before sealing; ADR-0019 consumes only a sealed definition, refuses non-sealed input (`NotSealed`), binds the profile chain and target specs at `link`, and keys bundles by `derivation_key`/`bundle_id`; WS-B1 keys every run by a content-addressed `configuration_id` and stamps `harness_def_ref` and `component_variant_ref`s on the manifest and on every event's `producer`. The ontology defines *configuration* as one point in model × harness definition × profile × environment × budget × seed. T-LCD-14 requires per-arm `search_budget`/`eval_budget`; T-LCD-10 requires identity to exclude surface fields.

The audit supplies the mechanisms and the gaps. OpenHands separates a secret-free *profile* (references) from *resolved settings* (embedded), offers `resolve_agent_profile_dry_run → AgentProfileDiagnostics` with `DanglingMcpServerRef`/`ProfileNotFound`, pins plugin refs to a commit SHA "to ensure deterministic behavior across pause/resume", persists the agent configuration as "the single source of truth", and on resume runs `verify()`: same agent class, tools add-only because "the LLM may have already been told about them". goose validates a recipe's template against its declared parameters in both directions, requires defaults on optional parameters and forbids defaults on file parameters. opencode's compatibility lowering emits `Diagnostic{kind ∈ {invalid, unsupported, conflict}, path, message}`; Codex generates and commits a JSON schema from its config type and names the `requirement_source` in constraint errors. Hydra's override grammar (`key=v`, `+key`, `++key`, `~key`, `key=a,b`) distinguishes config-group overrides from value overrides. The gaps: no audited system content-addresses its resolved configuration (goose recipe ids hash the *path*; OpenHands and Agent Spec use random UUIDs), none records which layer set which field in a run artifact, and none checks that the declared parameter space matches what the runtime reads.

## Options considered

1. **Two resolvers** — the assembler resolves for the Lab, the compiler's `link` re-resolves for compilation (WS-A4 dossier §6.1 as first drafted). *Rejected:* a compiler-side resolution can diverge from the sealed definition the Lab keys results by; one registry snapshot must bind both.
2. **Fail-fast validation returning the first error; unknown fields ignored** (Claude Code manifest style). *Rejected:* an experiment enumerating hundreds of points needs every diagnostic with a path at once; ignoring unknown fields is the LCD escape hatch (WS-L7 F1; OpenHands' "mongrel profile" argument).
3. **Key results by the authored file (path/UUID) and a version counter** (goose, OpenHands, Agent Spec). *Rejected:* two authoring paths that resolve identically would be two configurations; a rename would be a new configuration (fails T-LCD-10); reproducibility across machines is not guaranteed.
4. **A bespoke assembly diff and a bespoke sweep language.** *Rejected:* ADR-0017 already defines `HirDiff` with `Rebind`/`ReplaceField` and authority classification; Hydra's grammar is mature, documented and already distinguishes group from value overrides.
5. **One resolver producing a sealed definition consumed by `link`; staged, complete, provenance-bearing diagnostics; identity = WS-A3's `semantic_id` of the root with layer provenance excluded; assembly edits are `HirDiff` ops; resume verification with typed reasons; a declared parameter space enumerated through a Hydra-class override grammar (chosen).**

## Decision

1. **Operations (language-agnostic; all pure over their inputs and runnable out-of-process over the canonical encoding, T-LCD-12):**
   - `load(bytes, expected_dialect?) → Assembly | ParseError{path, reason} | UnknownDialect{found}` — decoding via WS-A3's canonical form; unknown non-`ext` keys are errors; `load(encode(a)) = a`.
   - `compose(layers[], merge_policy) → Assembly` — per ADR-0024 (5)–(6); deterministic and order-defined; output carries `layers[]`; fails with `AuthorityViolation{path, attempted, cap, source}`.
   - `resolve(assembly, registry_view, environment) → SealedDefinition | UnresolvedRef{path, ref} | AmbiguousVersion{path, candidates} | DialectIncompatible{variant, range}` — pins every `ComponentVariantRef` and entity `Ref` to a `version_id`, substitutes every `$param`, replaces secrets by *channel names* (never values), records `registry_snapshot_id` and `resolved_at`, then passes the document through WS-A3 `seal`. Invariants: the result is *closed* (no environment lookups remain), *secret-free* and *idempotent* (`resolve(sealed) = sealed`).
   - `validate_assembly(assembly | sealed, class_catalog, profiles?) → ValidationReport{status, diagnostics[Diagnostic{code, severity ∈ {error, warning, info}, path, source_layer?, detail}], derived{opacity_ratio?, identity_stability, hosting_edges}}` — seven stages, **all run and all reported, never fail-fast**: (1) schema; (2) class conformance (`variant.class_id = slot.class_id`; cardinality; `params` against `base_param_schema ∪ variant.param_schema`; unknown param → error); (3) parameter space (every `values` key declared; every `sweepable` parameter has a domain; every `$param` used is declared **and** every declared parameter is used — the goose bidirectional rule); (4) constraints; (5) kernel validation delegated to WS-A3 `validate` (entity typing, V-EFF, provenance on every `Text` leaf, assumption-debt record on every conditioned rule); (6) profile compatibility (each variant's `capability_declaration` and `dialect_range` against each named profile; WS-A4's `UnexpressibleSurface` propagated as an **error**); (7) LCD static checks (T-02 opacity via WS-A3 `opacity`; T-06 `hosting_edges = []`; T-10 identity excludes surface; T-12 no contract in the catalog requires inheritance).
   - `identity(sealed) → {semantic_id, version_id}` — WS-A3's two ids of the definition root. The `harness_definition` coordinate of **`configuration_id`** = `H(idp ∥ "configuration" ∥ canonical{model_ref, harness_def.semantic_id, profile.semantic_id, environment_ref, budget.semantic_id})` (ADR-0036; seed excluded — seeds are replicates, CF-083/CF-115) is the root's **`semantic_id`**, while the run manifest's exact-bytes key is **`configuration_version_id`** (the same over `version_id`s plus seed) — surface fields excluded (T-LCD-10) and **`layers[]` provenance excluded**, so two authoring paths that resolve identically are one configuration — while the run bundle also records `version_id`, `registry_snapshot_id` and `layers[]` for provenance. Registry storage uses an OCI-descriptor-style record `{kind, dialect, digest, size}`; hash pinning and rotation are WS-L4's (OQ-056, OQ-041).
   - `instantiate(sealed, runtime, profile, accounting) → HarnessInstance | BindFailure{slot, variant, reason ∈ {not-installed, trust-denied, locality-unsupported, contract-mismatch}}` — every class receives `(profile, accounting)` (T-LCD-08); each binding appends `lifecycle.component.bound{slot, class_id, variant_ref, locality, bind_result}` to the ledger (OQ-079) so the run record shows the exact instance graph.
   - `diff(sealed_a, sealed_b) → HirDiff` — **not a separate object**: assembly edits are ADR-0017 ops (`Rebind` for slot-variant changes; `ReplaceField` for `params`/`values`/`enabled`; `AddNode`/`RemoveNode` for entities and constraints) with `classification.authority_delta` computed from `authority_cap` changes. This is the unit the evolution service edits and attribution reasons over (ADR-0002).
   - `verify_resume(persisted, current, ledger_view) → Compatible | Incompatible{reasons[{path, rule}]}` — Core rules: dialect equal; every slot's `class_id` equal; tool/capability inventory add-only where the ledger shows a `context.artefact.delivered` event referencing a removed item (the OpenHands rule generalised through T-LCD-13 events); budgets may only decrease mid-run if accounting allows; every other change is accepted and recorded as `lifecycle.definition.changed{diff_ref}`. Resume is a compatibility check, never a merge; the persisted sealed definition is the source of truth.
   - `space(sealed) → ParameterSpace{params, slot_choices: map<class_id, [ComponentVariantRef]>, constraints}` and `enumerate(space, design ∈ {FullFactorial, Fractional{…}, OverrideList[Override]}) → [SealedDefinition]` — `Override` uses the Hydra-class grammar: `path=v` set, `+path=v` append, `++path=v` append-or-override, `~path` delete, `path=v1,v2` choice sweep; `class_id=variant_id` is a **group override** on `slots`, other paths manipulate `values`/`enabled`; every enumerated point passes `validate_assembly` before budget is spent; each point carries `search_budget`/`eval_budget` placeholders that WS-J3 must fill before a run is admitted (T-LCD-14); the identity of each point is `identity()`.
   - `export(sealed, target)` is WS-A4's compiler (stages 1–5); the sealed definition is `lcd_report`'s input.
2. **One resolver, two callers (CF-056).** `compose → resolve → validate_assembly → seal` is the only path to a sealed definition. WS-A4 stage 0 `accept` *calls* `validate_assembly`; stage 1 `link` *consumes* the sealed definition, resolves only what WS-A5 does not own (profile chain, target-spec versions — as ADR-0019 decision 2 already states), and refuses an unpinned selector with `LinkError{unbound_slot}` rather than resolving it. ADR-0019's `ResolvedDefinition` and this ADR's `SealedDefinition` are one object; the canonical name is WS-A3's **sealed definition** (ontology tie-break), and "resolved definition" is retired as an alias.
3. **Diagnostics carry provenance.** Every `Diagnostic` names a `path` and, when the field came from a layer, its `source_layer`; validation returns errors and never silently corrects (S-186). Schema is a derived artifact of the `hir/1` type definitions (Codex precedent), published for editors, never hand-maintained.
4. **Acceptance criteria** (Spec §3/§6): AC-3 `resolve` is closed and secret-free and `identity(resolve(a))` is stable across machines for one registry snapshot; two authoring paths with identical resolved content yield one `semantic_id`. AC-4 the Stage-0 reference definition validates with zero errors and an opacity ratio. AC-5 `compose` rejects an experiment-layer widening with `AuthorityViolation` naming the capping layer. AC-6 a compiled-tool rename under a profile yields only `SurfaceEdit` ops and no `semantic_id` change; an `enabled=false` ablation is exactly one `ReplaceField`. AC-7 `verify_resume` refuses removal of a delivered tool and accepts additions. AC-8 `enumerate` output carries per-arm budget placeholders. AC-10 `link` refuses an unpinned selector.

Content-addressed configuration identity with layer provenance excluded, the seven-stage complete-report validator, `verify_resume` generalised through delivery events, and a declared parameter space checked against the runtime's reads are `no-precedent / novel` as integrated contracts (no audited system does any of the four); each mechanism is precedented as cited.
- (c) Disconfirming evidence considered: (i) the OpenHands authors chose a deny-list for skills because catalogs drift, so strict pinning may make definitions unusable across machines — answered: authored references may be selectors and deny-lists; only the *sealed* artifact is pinned, and the cost (environment-dependent resolution) is recorded as `registry_snapshot_id` provenance. (ii) A complete-report validator is slower and more complex than fail-fast — accepted: the Lab validates hundreds of enumerated points and must see every path; cost is bounded by small documents. (iii) Excluding `layers[]` from identity loses "who set it" — answered: provenance is kept in the bundle beside `version_id`; identity must not fork on authoring path or T-LCD-10's spirit fails at the configuration level. (iv) The add-only tool rule can block legitimate mid-run tightening — answered: it applies only to items with a `delivered` event; everything else is accepted and recorded as `lifecycle.definition.changed`. (v) Reusing Hydra's grammar imports its ambiguities (append vs override) — answered: `+`/`++`/`~` are given fixed meanings over a typed space and every result is validated before use. None overturns.
- (d) Conditionality: independent of model tier and task class; assumes WS-A3's canonical form, two-id identity and `seal` ratify as proposed (identity derivation changes would require re-sealing stored definitions); assumes WS-B1 admits `lifecycle.component.bound`/`lifecycle.definition.changed` or names equivalents (OQ-079; blocking for AC-3/AC-7); `registry_snapshot_id` semantics are OQ-074; `ordered-many` identity/ablation semantics are OQ-073; profile-compatibility stage (6) is conditional on WS-C3's schema (Stage 5).
- (e) Build-stage assignment: **C0 / Stage 1** (`load`, `validate_assembly` stages 1–5 and 7, `resolve`, `identity`, `diff` via `HirDiff`, in-process `instantiate` with `lifecycle.component.bound`, `verify_resume`); **C0 / Stage 3** (`compose` with layers; `space`/`enumerate` with the override grammar, jointly with WS-J3; opacity ratio in the bundle); **C1 / Stage 5** (stage 6 profile compatibility with WS-C3). The assembly/registry *services* and sweep *scheduling* are C1 (R-2.10.1–3; CF-053).

**T-LCD statement (ADR-0007 decision 5).** Satisfies: T-LCD-10 (configuration identity is `semantic_id`; rename is a `SurfaceEdit`; AC-6), T-LCD-12 (every operation is a pure function over canonical documents, out-of-process capable), T-LCD-08 (`instantiate` passes profile and accounting to every class), T-LCD-02 (opacity computed at stage 7 and stored), T-LCD-06 (`hosting_edges = []` checked), T-LCD-05 (stage 5 refuses conditioned rules without records), T-LCD-14 (per-arm budget placeholders; `AuthorityViolation` on budget widening). Does not address T-LCD-03/-04/-11 (executable, WS-A4/I2) — mitigated by the sealed definition being the sole input to `lcd_report` and the equivalence run.

## Consequences

- WS-A4: `ResolvedDefinition` is renamed *sealed definition* in ADR-0019 at synthesis (same object; CF-056 closed); stage 0 calls `validate_assembly`; `link` gains `LinkError{unbound_slot}`.
- WS-A3: `seal` is invoked by `resolve` and only by it; `HirDiff` gains no new op kinds (assembly edits map onto `Rebind`/`ReplaceField`/`AddNode`/`RemoveNode`); CF-052's `slots` map is the field `Rebind` addresses.
- WS-B1/I3: the manifest's `harness_def_ref` is `{semantic_id, version_id}`; the bundle stores the sealed definition, `ValidationReport`, `registry_snapshot_id` and `layers[]`; two new lifecycle event classes are confirmed or mapped (OQ-079).
- WS-L4: owns hash pinning/rotation and the `{kind, dialect, digest, size}` registry record; `registry_snapshot_id` semantics (OQ-074).
- WS-J3/J5: result rows are keyed by `configuration_version_id` and aggregated by `configuration_id` (ADR-0036); overrides are `experiment` layers; `enumerate` output is not runnable until budgets are filled; per-slot budget concentration is expressible so the S-061/S-092 disagreement is testable.
- WS-I5/I7: the evolution service edits and attributes over `HirDiff`s of sealed definitions, never over authored files.

## Reversibility

**Medium.** Adding validation stages, diagnostic codes or override forms is additive. Changing what `ConfigurationId` hashes (e.g. including `layers[]` or `version_id`) would re-key every stored result and requires a results migration; changing the one-resolver rule would re-open divergence between compiled bundles and keyed configurations — both directions need a superseding ADR and a WS-L4 migration.
