# ADR-0073 — Context budget discipline and offloading: required/optional retention with kernel priority eviction, reserve-before-select, whole-item omission with a kernel notice, `ContextWindowExceeded → CompactionRequired`; offload as labelled excerpt + content-addressed handle + declared read; handle-only candidates with deterministic activation

**Status:** **ratified, amended** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-D1 (consumers: WS-D2, WS-D3, WS-E1, WS-E3, WS-E5, WS-F2, WS-H1, WS-L2, WS-B1, WS-I2, WS-C3) · **Phase:** 2 · **Related:** WS-D1 ADR-1; ADR-0039/0040 (`context.occupancy` gauge, `advise`, gauge caps refuse the next increment, `CompactionRequired`), ADR-0029 (offload above a class threshold; content addresses; redaction-safe hashing), ADR-0034 (P1 derivation; P7 lifting never raises authority), ADR-0016 (`Artifact`, `Observation`, `ToolCapability.effects`), ADR-0019/0020 (`result_render` rule kind; closed-world rule), ADR-0014 (`activation_observable`; OQ-049), ADR-0022 (composite/executed surfaces are C2), ADR-0007 (T-LCD-05/-08/-11/-13/-14); CF-161; OQ-184/-02/-03, OQ-080, OQ-084, OQ-067; R-2.4.1, R-2.4.2, R-2.5.3

## Context

The builder must fit a working set under a window cap that WS-L2 defines as a gauge (`context.occupancy`, ADR-0039) whose cap "refuse[s] the next increment (`CompactionRequired`) rather than stopping the run" (ADR-0040 E5), while WS-L2 also requires kernel-mandated reminders (`advise`) to be rendered through the profile. The audit found one production budgeting discipline worth adopting wholesale: Codex's guardian context types every content item `required` or `optional(priority)`, evicts optional items that cannot fit first and then by `(priority, age)`, refuses when the required set alone overflows, reserves the serialized cost of reminders and input framing "before choosing optional evidence", and inserts a bounded omission notice that says "omissions do not authorize actions" (`guardian-context/src/enforcement.rs`, `core/src/guardian/input_budget.rs`, `core/src/context/guardian_budget_omission.rs`). Every audited system bounds tool output at record time by lines and bytes (Pi 2000 lines / 50 KiB; Codex per-tool `TruncationPolicy`; browser-use 40 000 chars of DOM), and production write-ups converge on offloading the full payload outside the window with a handle the model can read (Cursor files, Anthropic tool-result clearing and `defer_loading`, Codex `WorldStateItem{full, state}`, Pi `retainedTail`, OpenHands `Condensation{forgotten_event_ids, summary}`). None labels the excerpt or the handle, and none makes the read of a handle a visible effect. ADR-0029 already stores payloads above 64 KiB as blobs; ADR-0034 P7 already says lifted content never gains authority.

## Options considered

1. **Truncate everything proportionally to fit** (OpenHands memory fair-share; browser-use char caps on every slot). *Rejected for required items:* a partially delivered instruction, permission ceiling or task statement is worse than a refusal (Codex `retained_context.rs`: "An omitted payload records incomplete evidence, rather than keeping a partial grant"); kept for *excerpting* optional content at record time.
2. **Overflow ⇒ stop the run.** *Rejected:* ADR-0040 already fixes gauge-cap semantics as refusal of the next increment; a builder that stops the run bypasses D2 and F2.
3. **Silent drop of oversized items** (opencode-style sanitiser precedent for schemas, WS-A4 §4 F4). *Rejected:* undeclared loss; the model must be told what is missing without being told anything that authorizes (Codex notice).
4. **Offload by summary only** (compaction as the sole mechanism). *Rejected:* summaries are lossy and model-authored (`delegate` deriver, ADR-0034 P1); Cursor and Anthropic both keep the *exact* bytes reachable; ADR-0029 already keeps them.
5. **Required/optional retention with a kernel-fixed priority order, reserve-before-select, whole-item eviction with a kernel omission item, `ContextWindowExceeded → CompactionRequired`; offload as excerpt + labelled content-addressed handle readable only through a declared capability; handle-only candidates whose expansion is an observable effect (chosen).**

## Decision

1. **Retention.** Every candidate carries `retention ∈ {required, optional(PriorityClass)}`. `required` is set only by the kernel (reserved-slot content from the sealed definition, the principal's current message, the paired observation of any tool call in the current turn, the omission item) or by a definition-level `HarnessRule` at ≥ `definition` authority — never by the policy (WS-D1 ADR-1 I-NOWIDEN). `PriorityClass` is a kernel-fixed closed set `{commentary, observation_old, observation_recent, image, memory, procedure_body, transcript_tail}` plus registered `ext`, so evictions are comparable across policy variants in the Lab.
2. **Budget and reservations.** `ContextBudget = {window_cap (the profile's declared context window as the `context.occupancy` cap), margin, reservations[], hard: Ref<BudgetNode>}`. `reserve_mandatory` runs **before** `policy.select` and reserves the estimated tokens of: the omission item, every soft-budget `advise` reminder pending for this window (ADR-0040; CF-161 — the reservation is the builder's, F2 remains the enforcer of the hard budget), a current-time item if the profile declares one, and the framing cost of every `required` item.
3. **Eviction.** `enforce_budget` evicts only `optional` items, whole, in this order: items that cannot fit even alone (so they do not evict useful smaller items), then by `(PriorityClass, age)` as ordered by the policy's `evict_order` within the kernel's class order. It never truncates a required item. If the required set plus reservations exceeds `window_cap − margin`, `assemble` fails with `ContextWindowExceeded{required_tokens, cap}` and the runtime raises `CompactionRequired` (ADR-0040 E5) to D2/F2; the builder never emits `stop`.
4. **Omission item.** Whenever `omitted ≠ ∅`, the plan contains one kernel-authored item in the `kernel` slot whose text is a `Text` leaf of the sealed definition (opacity-counted) stating that optional evidence was omitted and that omissions do not authorize actions; the structured `omitted[]` list is in `context.assembled`. The item's authority is `kernel`; it names counts, never content.
5. **Offload contract.** `offload(observation | artifact, policy: ExcerptPolicy{max_lines, max_bytes, max_tokens?, mode ∈ {head, tail, head_tail}}, label) → {excerpt: Candidate{kind: artifact_excerpt, tokens ≤ policy}, handle: OffloadHandle{content_address, media_type, size, label, excerpt_report{truncated_by, total_lines, total_bytes, retained_range}, read_capability: Ref<ToolCapability>}}`. It is applied at *record* time to every tool observation above the profile's `result_render` threshold (which must be ≤ ADR-0029's class threshold, so the ledger blob and the handle share one content address), and on demand for **tool-result clearing** (an already-delivered observation replaced by its handle; `derived_from = projection`, `deriver = kernel`). Excerpt, handle and any later read carry the **same label** (ADR-0034 P1 with a `kernel` deriver; P7 on read — never higher). A read of the handle is an effect through the declared `read_capability` present in the sealed definition (closed world; the monitor sees it — OQ-186 decides whether that capability is a kernel `read_artifact` or per-tool). A handle without a declared read capability makes the candidate `Omission{unidentified}`.
6. **Handle-only candidates (just-in-time context).** `Candidate.state ∈ {handle_only, expanded}`. Handle-only renders the index form (name, description, size, handle) — the shape of Pi/OpenHands skill indexes and Cursor/Anthropic tool catalogs. Expansion is an effect (`fs_read`/`memory_write`-domain read for artifacts and memories; E3 `select_surfaces` for tool surfaces) producing an `expanded` candidate that shares `artefact_id` and receives a new `delivery_id`; the kernel emits `context.artefact.activated{detector: deterministic}` on expansion (answers OQ-049 for `procedure`, `tool_surface`, `memory` kinds). Which kinds default to handle-only is a policy/profile parameter with a debt record (T-LCD-05).
7. **Out of C0.** Executed offload (results consumed by model-authored code in a sandbox and never delivered) is a C2 variant of E2/E5 (ADR-0022); the contract admits it trivially (no `PlannedItem`).
8. **Accounting.** Assembly and offload cost post to the run's budget `charged_to = subject` (ADR-0039 R-ACC-3, compaction precedent); `assembly_ms{measured_at}` is M5 (ADR-0043).

**T-LCD statement.** Satisfies T-LCD-08 (thresholds and priorities are policy/profile parameters received with the profile), T-LCD-05 (every threshold, excerpt mode and handle-only default is a conditioned rule), T-LCD-11 (a lowered handle whose target cannot carry `hir/provenance` records `LabelLoss` in the loss report — mechanics A4/E4), T-LCD-13 (expansion emits deterministic `activated`), T-LCD-14 (assembly cost is accounted, so "handle-only vs expanded" arms compare under matched budgets), T-LCD-02 (the omission item is an opacity-counted leaf). Not applicable: T-LCD-01/-03/-04/-06/-07/-09/-10/-12 (T-LCD-12 covered by ADR-1). **ADR-0024 rung:** eviction algorithm and offload mechanics = MUST-code; thresholds, priorities, excerpt modes, handle-only defaults = MUST-data.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** context occupancy is a gauge whose cap refuses the next increment — ADR-0039/0040 (ratified; Codex `percent_of_context_window_remaining`, opencode `isOverflow`, ACP `UsageUpdate`); reserve-before-spend as the cure for overshoot — ADR-0040 (S-209 `provisional (mech)`, Codex guardian precedent); "attention budget" and tool-result clearing as "one of the safest lightest touch forms of compaction" — S-038 (vendor); files as the offload primitive with `tail`/read, summarization keeping a reference to the history file — S-050 (vendor); deferred loading and tool search — S-040 (vendor); large payloads stay out of the event stream, content-addressed — ADR-0029 (ratified; doc 2 §11); lifted/derived content never gains authority — ADR-0034 P1/P7; a partial grant is worse than an explicit omission — Codex `history/src/retained_context.rs` L26–44; distractors degrade performance with length — S-336 (vendor research; motivates eviction of low-priority observations).
- **(b) Source-code precedent:** `codex/codex-rs/guardian-context/src/enforcement.rs` L15–180 (`BudgetPriority{Commentary, Tool, Image}`, `Budgeted{required | optional}`, unfit-first then priority/age eviction, `EvidenceLimitExceeded`); `codex/codex-rs/core/src/guardian/input_budget.rs` L60–150 (reserve reminders and input framing before optional evidence; `ContextWindowExceeded`); `codex/codex-rs/core/src/context/guardian_budget_omission.rs` (omission notice disclaiming authority); `codex/codex-rs/core/src/context_manager/history.rs` L350–380 (per-tool `TruncationPolicy` at record time); `pi-mono/packages/agent/src/harness/utils/truncate.ts` L1–50 (two-limit truncation with a typed report); `pi-mono/packages/agent/src/harness/system-prompt.ts` (skills as name/description/location); `software-agent-sdk/openhands-sdk/openhands/sdk/context/memory.py` L60–106 (fair-share char budget, truncate from top); `software-agent-sdk/.../context/prompts/sections/dynamic.py` L96–110 (`invoke_skill` progressive disclosure); `browser-use/browser_use/agent/message_manager/service.py` L153–190 (first + omitted-marker + last N), L104–150 (DOM cap 40 000 chars). The labelled handle with a declared read capability and deterministic activation on expansion is `no-precedent / novel`; each other element is precedented as cited.
- **(c) Disconfirming evidence considered:** partial truncation keeps more signal than whole-item eviction — absorbed by separating record-time excerpting (bounded candidates with handles) from eviction of whole bounded items, and by forbidding truncation only for `required` items; handle-only context slows exploration and models under-retrieve (S-038 concedes it; S-336 similarity effect) — absorbed by making handle-only a policy default per kind with a debt record and by making expansion observable, so the Cursor/Anthropic savings are Lab arms not assumptions; reservation over-reserves and starves optional content — bounded because reservations are only for kernel-mandated items whose cost is exact after rendering (Codex measures them); executed offload is where the largest savings are (S-040 −37 %) — deferred to C2 by ADR-0022, not denied. None overturns.
- **(d) Conditionality:** independent of model tier; assumes the profile declares a context window and a `result_render` threshold (ADR-0020); assumes every tool observation is recorded through the ledger with a content address (ADR-0029); the value of handle-only defaults is conditional on task distribution and model retrieval behaviour (a Lab factor).
- **(e) Build-stage assignment:** **Stage 0** (per-tool excerpt policy; window cap; `ContextWindowExceeded` → stop until D2 exists); **C0 / Stage 1** (retention classes, `PriorityClass`, `reserve_mandatory`, `enforce_budget`, omission item, `ContextBudget` schema; AC-D1-6/-8); **C0 / Stage 2** (offload handles with `read_capability`, tool-result clearing, handle-only candidates and deterministic `activated`; AC-D1-9/-10); **C0 / Stage 3** (matched-budget arms "handle-only vs expanded", "clearing on/off"; AC-D1-12); **C1 / Stage 5** (`priority_eviction`/`jit_handles` variants with profile-conditioned thresholds); **C2** (executed offload via E2/E5; readers enforcement on excerpts via H2).

## Consequences

- WS-D2's compaction variants receive `CompactionRequired` with `legal_cut_points` and may use tool-result clearing (handle substitution) as their cheapest strategy; summaries they produce are candidates at `⊔ label(inputs) ⊔ delegate`.
- WS-E1 declares `result_render` thresholds per capability surface and the `read_capability` for handles (OQ-186); WS-E3's deferred tools are handle-only `tool_surface` candidates whose expansion goes through `select_surfaces`.
- WS-L2/F2: the builder reserves; F2 enforces the hard budget; `advise` reminders are candidates in the `kernel` slot with `required` retention for the window in which they fire (ADR-0040 E4).
- WS-H1 sees every handle read as an effect and applies Π to it like any other read; a read never raises the content's authority.
- WS-I2 gains process metrics: omission rate, excerpt ratio, expansion rate (`activated` / handle-only delivered), assembly cost.
- WS-B1: `context.observation.recorded` already carries `truncated`; the excerpt report and handle reference are payload extensions (with CF-159).

## Reversibility

**Medium.** Priority classes and thresholds are data; the retention split and the omission item are small kernel rules whose removal after Stage 2 would reintroduce partial-grant and silent-drop failures the fixtures encode. The offload handle is built on ADR-0029's blob store, so reverting it costs nothing in storage; removing the declared-read rule would make handle reads invisible to the monitor and is the one element to treat as load-bearing.
