# ADR-0155 — The scheduler and lifecycle contract: the experiment is a run whose ledger projects every scheduler view; claim/launch/settle/close over the B3 leases; pools over resource classes; task-blocked, arm-interleaved seeded order with drift bracketing; experiment and instrument budget nodes with four matched-budget enforcement points; outcome-class settlement with bounded, never-deleting re-attempts; experiment kill points in the shared battery

**Status:** ratified, amended (Phase 3 synthesis)
**Owner workstream(s):** WS-J3 (with WS-B1 for the event family, WS-B3 for leases/restore, WS-L2 for budget nodes, WS-B5 for provisioning, WS-I2/J4 for `compare` preconditions, WS-J5 for rows, WS-J6 for hosted launch) · **Phase:** 3 · **Related:** ADR-0026/0027 (ledger authoritative; views; run kinds), ADR-0040/0041 (budget nodes; `MatchSpec`; refusal), ADR-0045/0046 (outcome classes; replicate axis; `compare`), ADR-0106 (`StopReason` → outcome class; stop protocol), ADR-0120 (fingerprint probe), ADR-0128 (`cache_policy` salt), ADR-0130/0131/0132 (checkpoint/restore; lease scopes; kill-point battery), ADR-0136–0138 (handle; `derive(fresh_from_image)`), ADR-0139–0141 (bundle kinds; regrade), ADR-0144 (`grade`; `infra_suspected`), ADR-0098 (ACP session verbs for hosted launch), ADR-0050 §8 (boundary placement); OQ-314, OQ-286, OQ-121, OQ-124; CF-331/-02/-05; R-2.10.3

## Context

Every audited batch runner keeps its scheduling state either in process memory (Symphony §14.3: "No retry timers are restored from prior process memory"; SWE-agent/mini thread pools) or reconstructs it by scanning output directories (Harbor `_maybe_init_existing_job`; Inspect `list_latest_eval_logs`; HAL `get_remaining_tasks`); three of five delete partial state to recover (Harbor `rmtree`, SWE-agent `unlink`, mini `remove_from_preds_file`), none records why a unit was re-run, none separates an infrastructure re-attempt from an intended replicate in stored state, and none randomises the order in which arms visit tasks — every runner iterates one configuration over all tasks, then the next, which confounds the paired harness effect with provider drift and cache warmth (WS-C1 F7; ADR-0128). Concurrency, where bounded, is bounded at two levels over a shared resource (Harbor per-agent pools with an agreement rule; Symphony per-state limits; Inspect `max_tasks/max_samples/max_sandboxes`). Retry, where typed, is by failure class with capped exponential backoff (Harbor, Symphony, Inspect). Phase 1–2 already supplies the ledger, `project`, leases, `restore`, budget nodes, environment derivation and the outcome-class projection; what is missing is the contract that composes them into a sweep engine without a second store.

## Options considered

1. **A separate scheduler database (queue table + job table) beside the ledger.** Rejected: a second authoritative store contradicts ADR-0026; its consistency with the ledger would need exactly the reconciliation machinery the ledger already provides.
2. **No experiment-level state; each subject run carries its own experiment tag and the scheduler re-scans results on start (Inspect/Harbor shape).** Rejected: attempt history and re-attempt reasons are lost; claims cannot be fenced across workers; pause/resume has no durable record.
3. **The experiment is a run of a declared kind; scheduler views are ledger projections; claims are B3 leases; settlement is an outcome-class rule; order and pools are policy data (chosen).**

## Decision

1. **The experiment is a run.** `open_experiment(experiment_id) → RunId` opens a ledger with `kind = experiment`, no control strategy and no effects; the manifest carries `{experiment_id, plan_id, scheduling_policy, reattempt_policy, budgets}`. Its event family `measurement.experiment.{registered, run_planned, run_claimed, claim_expired, run_launched, run_settled, run_replanned, paused, resumed, drift_bracket, closed, bundled}` (all `durability = ledger`; producer = the engine; `registered/closed/paused{operator}/run_replanned` audit-grade) is an addition to the ADR-0026 table (CF-331); subject runs stamp `measurement.experiment.bound{experiment_id, arm_id, configuration_id, cell_id, replicate_index, attempt_no, budget_id}`. Every scheduler view (`eligible`, `claimed`, `in_flight`, `settled`, `outcome_counts`) is `project(experiment_run, view, until_seq)` with rebuild equality (ADR-0026). Long sweeps continue by `continued_from` chains (ADR-0131) — the same strategy-less shape as B3's inbox runs; synthesis rules OQ-314 once for both (CF-332).
2. **Operations.** `next(experiment, capacity) → [RunPlan]` (pure over the ledger; reconcile-before-dispatch), `claim(run_plan_id, holder) → Lease{scope: resource(run_plan_id)}` (ADR-0130's existing scope; no new lease kind — CF-335), `launch(run_plan, lease) → RunId` (allocate the subject root `BudgetNode` as a `slice` of the experiment pool equal to the arm's `eval_budget`; `provision`/`derive(fresh_from_image)`; `open_run` with the experiment manifest fields, seed material, `cache_policy` salt; hosted levels through the Hosting ABI session verbs with the ADR-0040 boundary budget), `settle(run_plan, run_id) → RunOutcome` (on `lifecycle.run.finished`: outcome class per ADR-0106, `grade` per ADR-0144 charged `instrument`, utilisation posted, accept/supersede per item 5, claim released, slice remainder returned), `pause/resume`, `close → ExperimentReport` (drift bracket closed, coverage and `outcome_counts` recorded, `bundle(kind = experiment)`, results watermark handed to J4/J5). Invariants: S-1 no memory-only state; S-2 at most one accepted run per `run_plan_id`; S-3 root budget equals `eval_budget` dimension-wise; S-4 no launch after `paused`/`closed`; S-5 every bound run is settled or in flight; S-6 order reproducible from `permutation_seed`. Failures: `WouldBlock`, `Fenced`, `InsufficientBudget`, `PoolExhausted`, `EnvironmentUnavailable`, `SpecMismatch`, `PlanNotFound`, `ExperimentClosed`.
3. **Pools and order are data.** `SchedulingPolicy{max_concurrent_runs, pools: [Pool{key ∈ {model_snapshot(ref), environment_class, instrument, participant(ref)}, limit ≤ max_concurrent_runs}], order ∈ {interleaved_blocked (default), by_configuration{reason}}, permutation_seed, start_stagger_ms, deadline?, priority?}`; `fan_out` is a gauge cap on the experiment node. Default order blocks by task and interleaves arms under the recorded permutation (classical randomisation within blocks); `by_configuration` is admitted for `exploratory` experiments or with a declared reason. The fingerprint probe (ADR-0120) runs at open and close (`drift_bracket`), and a changed fingerprint annotates the affected rows `provider_drift = observed` — never deletes or invalidates silently.
4. **Budgets and matched-budget enforcement at four points.** Two nodes per experiment (ADR-0040 `scope: Experiment`): a subject `pool` bounding Σ subject `eval_budget`s and an `instrument` node for graders, probes, detectors and re-attempt waste. E-1 `register` (ADR-0154 refusals); E-2 `launch` (root budget = `eval_budget`; `MatchSpec`, `cache_policy`, `limits_enforced` in the manifest; exhaustion of the experiment pool pauses scheduling and never trims a run's budget); E-3 `settle` (utilisation distributions; `under_utilised` annotation per ADR-0041 M1); E-4 `close` (ADR-0046 `compare` preconditions re-checked over realised runs: `UnmatchedBudget`, `budget_match.status` at the OQ-124 tolerance, `InsufficientReplicates` ⇒ `n/a{not_run}`, drift strata). Hosted arms whose token/spend limits are reported rather than enforced carry `limits_enforced = partial` with wall-clock and `env.*` ceilings enforced at the environment boundary (ADR-0046 (d)).
5. **Settlement by outcome class; re-attempts never delete.** `scored`, `budget_exhausted`, `refused` ⇒ accepted, final. `oracle_failure` ⇒ row kept, regrade only (ADR-0141 `derived-from{regrade}`; the agent is never re-run for a grader fault). `infrastructure_failure` ⇒ superseded and re-planned under `ReattemptPolicy{max_per_plan (default 2), max_fraction_of_plans (default 0.10), backoff{min_ms, multiplier, max_ms}, error_classes_included?}` keyed on the ADR-0102/0119 `error_class`; the new run has `attempt_no + 1` and the *same* `seed_material` (it is the same replicate); the superseded run stays in the ledger with its consumption reported as `instrument` waste (`wasted_runs`, `reattempt_rate`); exceeding `max_fraction_of_plans` ⇒ `paused{infrastructure_suspected}`. `cancelled{by ∈ {operator, hosting}}` ⇒ re-plannable when `reattempt.on_cancel = replan`; `cancelled{by ∈ {principal, parent}}` ⇒ final. A crashed subject run is restored by ADR-0130 under its own lease; the engine treats it as `infrastructure_failure` only when its `recovery_decision` is `stop{infrastructure_failure}` or its lease expires unrecoverably — the engine never re-drives a restorable run. `attempt_no` and `replicate_index` are orthogonal; results rows key by `replicate_index` and carry `attempt_no`; a superseded run never enters a replicate count (ADR-0045 "n = independent runs").
6. **Experiment kill points join the shared battery (ADR-0132).** KP-E1 after `run_planned` before `claim`; KP-E2 after `claim` before `open_run`; KP-E3 after `open_run` before `bound`; KP-E4 after the subject's `finished` before `run_settled`; KP-E5 during `close`/`bundle`. Oracle: after `restore(experiment)`, exactly one accepted run per plan or an eligible plan; no duplicated subject run; scheduler view rebuilt from the ledger equals the live view.
7. **Boundary placement (ADR-0050 §8 clause 4).** `register/expand/next/close` and the strategies run on the lab side; `open_run`, allocation, provisioning, leases and appends on the kernel side; `ExperimentSpec`, `CellPlan`, `RunPlan`, run manifests, `RunOutcome` and `ExperimentReport` cross as whole records (D2); the experiment ledger is written through the ordinary `open_run/append` verbs.

**T-LCD statement.** Satisfies **T-LCD-14** (enforcement points E-1…E-4; subject root budget equals the arm's `eval_budget`; re-attempt waste reported, never absorbed), **T-LCD-09** (order, drift and attempt metadata keep every row attributable to its factor tuple), **T-LCD-15** (`limits_enforced = partial`; hosted cells `n/a`; recovery/waste metrics class-scoped), **T-LCD-06/-07** (hosted launch through declared session verbs; no native contract changes), **T-LCD-12** (operations over canonical records; out-of-process by boundary placement), **T-LCD-05** (order/pool/re-attempt defaults are data with declared reasons). Not applicable: T-01/-02/-03/-04/-08/-10/-11/-13. **ADR-0024 rung:** `SchedulingPolicy`, `ReattemptPolicy`, budgets and defaults are MUST-data; `next`, `claim`, `launch`, `settle`, the settlement table and the views are MUST-code.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: restart loses memory-only scheduler state — Symphony `SPEC.md` §14.3 (Tier B, self-documented), goose forget-on-restart (WS-B3 F2); deletion as recovery loses attempt history — Harbor/SWE-agent/mini (Tier B, source); randomisation within blocks controls confounding — S-506 (Tier A), S-167/S-234 (via A2/I2); provider drift and cache warmth are confounds — WS-C1 F7 (S-441, Tier B), ADR-0128 (ratified); typed, bounded, backed-off retry — Harbor/Symphony/Inspect (Tier B, source); two-level concurrency over shared resources — Harbor/Symphony/Inspect (Tier B, source); "unmeasured ⇒ failed" as a resume hazard — HAL `get_remaining_tasks` (Tier B, source); cost scale — S-135 (Tier A). ADR-0026/0106/0130/0132 supply the ratified substrate. No `provisional` number is load-bearing.
- (b) Source-code precedent: harbor @7d5285b `src/harbor/trial/queue.py` L19–49, L83–110, L194–237 (semaphore + per-agent pools; class-typed retry with capped backoff; **rejected** deletion at L221), `models/job/config.py` L487–521 (pool agreement rule), `job.py` L242–370 (config-equality refusal; **rejected** `rmtree` at L268–270); inspect_ai @75f4891 `src/inspect_ai/_eval/evalset.py` L315, L1040–1100, L1130–1140 (retry immediately; reuse completed units; exponential wait), `run.py` L464–470 (parallel task × model units); symphony @e0ccc83 `SPEC.md` §4.1.5, §4.1.8, §8.1–8.5 (attempt counter; claim set; tick order; per-state limits; backoff; stall detection), §14.3 (**rejected** in-memory timers); SWE-agent @3ea751c `sweagent/run/run_batch.py` L89–94, L295–297 (staggered start), L314–318 (batch abort on cost cap — adapted to pause); hal-harness @16bb03e `hal/agent_runner.py` L178–222 (**rejected** error-string resume). **`no-precedent / novel`:** ledger-projected scheduler state with fenced claims; outcome-class settlement that never deletes and separates `attempt_no` from `replicate_index`; task-blocked arm-interleaved seeded order with drift bracketing; four-point matched-budget enforcement; experiment kill points.
- (c) Disconfirming evidence considered: (i) "a directory of outputs is enough" (Harbor/Inspect/SWE-agent/HAL ship science this way) — answered: attempt history, re-attempt reasons and fenced claims are lost, and the ledger machinery already exists; (ii) interleaving increases environment churn and defeats per-arm priming — answered: `fresh_from_image` per replicate is mandatory regardless (ADR-0138), priming is a declared `cache_policy`, and `by_configuration` is admitted with a reason; (iii) automatic re-attempts can burn budget on a systematic fault — answered by per-plan and per-experiment bounds, instrument attribution and the `infrastructure_suspected` pause; (iv) the experiment-as-run stretches ADR-0026's single-writer design — answered by B3's inbox-run precedent and continuation chains, recorded as CF-332 for a single ruling. None overturns.
- (d) Conditionality: assumes ADR-0130 leases and `restore`, ADR-0040 `slice`/`pool` nodes and ADR-0138 `derive` exist at Stage 3; hosted launch assumes WS-J6's session verbs (C2); drift bracketing assumes a fingerprint probe per model level (OQ-286 parameters); defaults (`max_per_plan = 2`, `max_fraction = 0.10`, 10 % tolerance) are Stage-3 review items (OQ-360, OQ-124).
- (e) Build-stage assignment: **C0 / Stage 3** — experiment run kind, `measurement.experiment.*`, single-worker `next/launch/settle/close`, settlement rule, enforcement points, KP-E1…E5 in the shared battery; **C1 / Stage 4** — multi-worker `claim` leases, pools, interleaved order at scale, `pause/resume`, re-attempt service, experiment bundles; **C2 / Stage 4** — hosted launch; **C4 / Stage 6** — matched-total arms for WS-I5.

## Consequences

- WS-B1 extends the ADR-0026 table with the `measurement.experiment.*` family and the `bound` payload (CF-331); WS-H6 adds the four audit-grade classes.
- WS-B3 confirms `resource(run_plan_id)` as the claim scope (CF-335) and rules OQ-314 for inbox and experiment runs together (CF-332).
- WS-L2 confirms the two experiment-scoped nodes and instrument attribution of re-attempt waste; WS-I2 registers `wasted_runs`, `reattempt_rate`, `under_utilised` as declarations; WS-J4 consumes `provider_drift` and order metadata as strata.
- WS-B5/I4 provision one fresh environment per run plan; WS-J6 provides the hosted launch path and `limits_enforced`.
- The ADR-0132 battery gains KP-E1…E5 with the exactly-once-settlement oracle.

## Reversibility

**Medium.** The event family and views are additive and cheap to keep; replacing the experiment-as-run with a separate store would require migrating every experiment ledger and re-deriving claims; relaxing "never delete" cannot be undone for runs already dropped, which is why the rule lands at Stage 3.
