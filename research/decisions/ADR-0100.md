# ADR-0100 — The execution contract: seven kernel-owned stages over the ADR-0030 lifecycle, the `tool_executor` component contract ("executors report, never decide"), and the sandbox helper as a separate binary behind a narrow protocol (OQ-045 final)

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-E5 (consumers: WS-B5, WS-B3, WS-H1, WS-H4, WS-H3, WS-H7, WS-F2, WS-G2, WS-H6, WS-E4, WS-K4/L5, WS-J6) · **Phase:** 2 · **Related:** ADR-0030, ADR-0031, ADR-0032 (lifecycle, risk class, compensation); ADR-0022 (`SurfaceArgMap`); ADR-0023/0024 (component classes; MUST-code); ADR-0026/0027 (ledger, ids); ADR-0035 (monitor reads records only); ADR-0040 (reserve-before-spend); ADR-0049 (OQ-045 provisional answer; revalidation trigger 2 of ADR-0050 §6); ADR-0050 §8 (language-use constraint); ADR-0052/-3 (decision function; TCB rule 7); ADR-0062 (enforcement points; fail-closed); WS-E1 (`bind`, `execution_requirement`); CF-017, CF-212, CF-214, CF-216, CF-217; OQ-045, OQ-090, OQ-249, OQ-252; R-2.5.5, R-2.2.5, R-2.8.1

## Context

Doc 2 §11 Stage 1 requires "sandbox handles … make every side effect attributable to a run and tool call"; §5.6 requires that "credentials stay outside untrusted execution environments" and that "high-risk effects be auditable even if the model or extension layer is compromised". ADR-0030 fixed the effect lifecycle and the write-ahead `committed` record but delegated to WS-E5 the executor's obligations (`(effect_id, attempt_no, idempotency_key)`, `dedup_support`, `detached_effect_ids[]`, `probe`). WS-H1 placed executors *outside* the TCB ("they report, the kernel decides") and named the sandbox helper invocation as an enforcement point that "lives out-of-process per OQ-045". WS-H4 fixed the `ContainmentReport` and egress round trip that must ride the helper protocol. ADR-0049 answered OQ-045 provisionally (separate helper binary) and asked WS-B5/E5 for the final answer with a revalidation trigger if it moves in-process. The source audit (dossier §4a F1, F2, F10) found that every product-grade harness runs an ordered pipeline with the decision outside the executor, that the one shipped helper protocol (Codex `exec-server`) already separates attribution metadata from authorization, reports its sandbox type as an optional self-report, fails closed on missing network details and supports session resume — and that none records the pipeline as durable phases or gates dispatch on a durable record.

## Options considered

1. **Executor-owned pipeline** (the tool implementation approves, sandboxes and retries itself — OpenHands `ToolExecutor.__call__` shape, browser-use `execute_action`). *Rejected:* puts policy in untrusted code; no durable phase boundary; the audit (WS-H6 F7) requires kernel producers for audit-grade events.
2. **Kernel pipeline without a helper boundary** (in-process sandbox driver; the kernel links syscall filters). *Rejected:* contradicts every audited product harness (Codex `linux-sandbox`/`exec-server`, sandbox-runtime, OpenHands workspaces), WS-H1's TCB rule 7 and T-LCD-12; would fire ADR-0050 revalidation trigger 2 for a C4 score change with no evidence of benefit beyond per-call latency.
3. **Kernel pipeline with the helper as an enforcement point but dispatch ungated** (Codex today: `ExecCommandBegin` written after the fact). *Rejected by ADR-0030 already:* cannot distinguish "never dispatched" from "unknown".
4. **Seven kernel-owned stages mapped onto ADR-0030, executors as an operation-shaped component class that reports and never decides, dispatch gated by a `CommitToken` the helper verifies, helper out-of-process behind a narrow resumable protocol (chosen).**

## Decision

1. **Stages.** Tool execution is the ordered, per-effect sequence `resolve → authorize → prepare → commit → execute → capture → observe`, mapped onto ADR-0030 as: `resolve` (after `intended`, before `authorized`: `SurfaceArgMap` → canonical params; pinned capability + `ExecutorBinding`; executor-registered deterministic assessors run *by the kernel* with inputs recorded by content address; `declared: EffectClass`, `resource_keys`, `deadline`), `authorize` (WS-H1 `authorize` + WS-H4 `admits`; E5 supplies the `Proposal`, consumes the `KernelDecision`), `prepare` (= ADR-0030 `prepared`: resource keys, `baseline_ref`, `CompensationPlan`, `idempotency_key`, **attribution token**, credential placeholders, `deadline/grace_ms/drain_ms/output_policy`, budget reservation), `commit` (= `committed`, durable before return; skipped for `read_only`), `execute` (dispatch through the helper; one per `(effect_id, attempt_no)`), `capture` (concurrent observed-effect stream, ADR-0101), `observe` (= `observed | unknown`; ADR-0102). The brief's five-verb order is refined, not contradicted (CF-216): `resolve` is pre-authorization, `prepare` post-authorization.
2. **Invariants (kernel-enforced errors, never warnings).** I-1 *No unmediated effect*: for every non-`read_only` effect, `security.permission.decided{allow}` ≺ `action.effect.committed` ≺ `action.tool.started` in `seq`, and the helper refuses `exec` without a valid `CommitToken` for that `(effect_id, attempt_no)` (`NotCommitted`) or with an `attribution_token` that does not match its `env_handle` (`AttributionMismatch`). I-2 *No ambient channel*: `net.mode ∈ {none, mediated}`, placeholders only, no kernel identity material in the environment; the attribution token is not a credential. I-3 *Executors report, never decide*: no executor operation returns a permission, an authority label, a risk class that lowers, or a retryability that raises. I-4 *One observation per attempt*; a late report after `unknown` is `probed`, never a second `observed`. I-5 *Completeness is explicit* (`complete | partial{reasons} | unknown` on every `observed`). I-6 *Deadline dominance*: `deadline ≤` the environment's liveness bound, enforced by the helper locally.
3. **The `tool_executor` component contract** (registered class, ADR-0023 slot; receives `(ModelProfile, ResourceAccount)` per T-LCD-08 — the profile selects only the `result_renderer` surface): `declare() → ExecutorDeclaration{environment_class, isolation_min, capture_kinds, interrupt ∈ {supported, unsupported, unknown}, partial_application, streaming, dedup_support, dedup_window?, probe_support ∈ {read_back, postcondition, none}, detached_processes, meters, on_kernel_loss ∈ {terminate, preserve_until(ttl)}, assessors[]}` (tri-state fields never coerced), `prepare`, `execute(ExecutionRequest) → execution_id`, `capture(execution_id, after_seq) → Stream<CaptureItem>`, `interrupt(execution_id, graceful | kill)`, `write_input`, `probe`, `snapshot/diff` (where declared), `list_detached/terminate_detached`, `close`. `ExecutionRequest = {effect_id, attempt_no, execution_id (kernel-chosen), commit_token | read_only_marker, capability_version, canonical_args, env_handle, containment_policy_ref, attribution_token, credential_bindings[] (placeholders), deadline, grace_ms, drain_ms, output_policy, resource_reservation_ref, idempotency_key, dedup_hint}`. Failure modes: `NotCommitted, AttributionMismatch, EnvironmentUnavailable, InvalidRequest, BaselineUnavailable, Unsupported`.
4. **Concurrency.** Effects of one model call run in parallel iff `resources.declared = true` and `resource_keys` are disjoint (sorted acquisition, per-key timeout); `declared = false` serializes the capability; a `world_changed` capture item re-validates queued siblings' static/`state_requires` preconditions and refuses stale ones (`PreconditionViolated{stale_after: effect_id}`).
5. **OQ-045 final answer.** The sandbox helper is a **separate helper binary behind a narrow protocol**; the kernel drives OS isolation primitives through it (ADR-0050 §8 (c): hostable in-thread in the ADR-0050 helper ecosystem). ADR-0049's provisional answer stands; ADR-0050 revalidation trigger 2 does **not** fire. Protocol requirements (properties for WS-K4/L5's boundary grammar): one persistent, resumable session per environment handle (`hello(resume_session_id?)`); request/response plus ordered notifications; byte-exact chunks with per-execution `seq`; canonical encoding for hashed records; version handshake with a capability declaration. Minimum verbs: `hello, attach(env_handle, ContainmentPolicy) → ContainmentReport, exec, read, write_input, signal(interrupt | terminate | kill), terminate, fs.{read, write, canonicalize, metadata, read_dir, remove}, snapshot/diff, egress.decision_request (helper → kernel, fail closed), list_detached, detach`. Every helper report carries `enforcement_evidence` per field group and a lowering-loss list (WS-H4). Process handles are kernel-chosen `execution_id`s, never OS pids.
6. **Recovery hooks.** On kernel restart (WS-B3) the dispatcher `resume`s each helper session and resolves every `committed` effect by `probe` = `read(execution_id)` for exec-class capabilities; `on_kernel_loss` (Stage 1 default `terminate`) decides whether the helper keeps processes alive across the gap.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: complete mediation and fail-safe defaults — S-252 (Tier A); coordinator checkpoint before action, leases, idempotence is the receiver's obligation — S-197, S-198, S-199 (Tier A); the pipeline shape and the executor/authorization split in production — S-107 `orchestrator.rs` L3–7, L121–531, `sandboxing.rs` L342–405, `exec-server-protocol/src/protocol.rs` L271–361 (attribution "not authorization"; optional self-reported sandbox type; fail-closed managed network; `resume_session_id`); interruption from another thread and declared resources — S-110 `tool.py` L250–327, `parallel_executor.py` L193–310; executors outside the TCB — WS-H1 §6.5 (ADR-0035 minting rules, Tier A lineage S-216–S-219); isolation is OS-level and process-tree-wide, applied by a separate process — S-288, S-290, S-293 (Landlock: stackable, only-more-restrictive), S-393/-03 (microVM / user-space-kernel classes exist with measured overhead); the brain/hands split — S-047, S-052 (Tier B). Doc 2 §11 Stage 1 and §5.6 (map, not authority).
- (b) Source-code precedent: `codex/codex-rs/core/src/tools/orchestrator.rs` (ordered pipeline), `codex-rs/exec-server-protocol/src/protocol.rs` + `codex-rs/exec-server/README.md` (helper protocol; separate binary; resumable session), `codex-rs/linux-sandbox/src/main.rs` (separate sandbox binary), `codex-rs/core/src/unified_exec/process_manager.rs` (kernel-chosen process keys; termination on session end); `software-agent-sdk/openhands-sdk/openhands/sdk/tool/tool.py` (`ToolExecutor` with `interrupt`; `DeclaredResources`), `openhands-sdk/openhands/sdk/agent/parallel_executor.py` (resource locking; synthetic cancellation); `anthropic-experimental/sandbox-runtime/src/sandbox/sandbox-manager.ts` + `README.md` (separate wrapper process; single bridged channel); `browser-use/browser_use/tools/registry/views.py` (`terminates_sequence`). The *commit-token-gated* dispatch verified by the helper, the kernel-run assessors and the integrated declaration record are `no-precedent / novel`; each part is precedented above.
- (c) Disconfirming evidence considered: in-process drivers are cheaper per call and polyglot boundaries have real cost (ADR-0049 (c); S-394 gVisor overheads) — does not overturn: the helper session is persistent, per-call cost is a Stage-3 M-point measurement (AC-E5-11), and every product harness pays it; hooks and model self-report *decide* in Codex/Claude SDK/OpenHands (S-109 `types.py` L416–421; S-110 `security_risk`) — does not overturn: they are admitted as raise-only inputs at `resolve`/`capture` (ADR-0031 decision 2; CF-121), nothing they can do today becomes impossible except granting; Managed Agents runs with no runtime lifecycle (S-047) — holds only for reversible workspace effects (CF-062); Stage-0 baselines cannot afford a helper — accommodated by recording `enforcement_evidence = unknown` and failing closed for writes unless `warn_and_degrade` is declared (WS-H4 AC-H4-08).
- (d) Conditionality: independent of model tier and task class. Assumes WS-B1's durable-before-visible append, WS-H1's `authorize` and WS-H4's `attach/ContainmentReport` exist; assumes the coding/terminal environment class first (browser/GUI executors satisfy the contract with a reduced `capture_kinds` set — OQ-250). The helper placement assumes the ADR-0050 helper ecosystem can host OS primitives in-thread (ADR-0050 (a)); a future WASI-based helper (ADR-0050 trigger 3) changes the binary, not the contract.
- (e) Build-stage assignment: **C0 / Stage 1** — stages, invariants, `tool_executor` contract and declaration, helper protocol *schema* + conformance suite, AC-E5-02(a)/-03/-12; **C0 / Stage 2** — helper binary, `attach`, deadline enforcement in the helper, detached termination, AC-E5-02(b)/-07/-10; **C0 / Stage 3** — fault battery AC-E5-02(c), overhead AC-E5-11; **C1** — `preserve_until` + B3 resume, remote executors; the ADR-0049 spike S1 is the Stage-0 acceptance check for the boundary.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-04 (contract sits below every lowering target), T-LCD-06/-15 (hosted participants map onto the lifecycle; capture metrics `n/a` where unobservable), T-LCD-07 (tri-state declarations; `unknown` never coerced), T-LCD-08 (`(ModelProfile, ResourceAccount)` inputs), T-LCD-10 (execution keyed on capability identity; no surface name crosses the helper), T-LCD-12 (operations only; out-of-process by decision), T-LCD-14 (helper overhead measured under matched budget). Does not by itself satisfy T-LCD-11 (execution ids/attribution through protocol targets) — mitigated by ADR-0101's `_meta` carriage + loss report. Ladder rung (ADR-0024): dispatcher, assessor runner, helper protocol handlers = MUST-code; executor variants = registered component variants; grace/drain/idle-ratio = MUST-data.

## Consequences

- WS-B5 must expose `attach/detach/snapshot/diff/list_detached` on the environment handle and adopt `on_kernel_loss` (CF-212); WS-K4/L5 fold the helper verbs into the WS-L1 §6.5 boundary grammar (CF-017 exposure: the placement is stated as a contract, not an ecosystem).
- WS-B1 gains `action.tool.started{execution_id, attribution_token_hash}` (CF-214); WS-H6 classifies it audit-grade with producer = dispatcher.
- WS-H1's assessor precedence (i)–(iv) is executed at `resolve` by the kernel over executor-registered pure functions; WS-H4's `admits()` is the `authorize` precondition; WS-H3 bindings are `prepare` inputs.
- WS-F2 keys retries on the derived `retryable` and never cancels mid-effect for budget (ADR-0040); WS-G2 consumes `completeness` and `world_changed`.
- The ADR-0050 revalidation trigger 2 is not fired; the readiness report records the final OQ-045 answer.

## Reversibility

**Medium.** The stage order and invariants are additive over ADR-0030; the helper protocol is data (schema-versioned) and a helper in another ecosystem is a drop-in (ADR-0050 §5 "Sandbox helper: low"). Moving the helper in-process later would fire ADR-0050 trigger 2 and require re-deriving WS-H1's TCB rule 7 — costly in review, cheap in code. Removing the commit-token gate after B3/G2 rely on `NotCommitted` refusals would re-open the "never dispatched vs unknown" ambiguity ADR-0030 closed.
