# ADR-0150 — Hosted participants as opaque definitions: authoring desugaring from the meta-harness document shape onto `AgentProcess.hosted`, a degraded validation profile as a rule over stages, boundary-enforced budget and permission, and `n/a` outcomes — with no change to any native contract

**Status:** ratified, amended (Phase 3 synthesis)
**Owner workstream(s):** WS-J1 (with WS-J6; consumers: WS-J2, WS-J3, WS-J4, WS-J5, WS-K1, WS-B1) · **Phase:** 3 · **Related:** ADR-0001, ADR-0004, ADR-0005, ADR-0007 (T-LCD-06/-07/-15), ADR-0010, ADR-0013 (participant descriptor; admissible granularities; `InadmissibleFactor`), ADR-0016 (kernel invariants; `hosted` has no components), ADR-0018 (`OpaqueProcess`; tri-state capabilities), ADR-0023 (6) (hosted `params` at configuration/product granularity), ADR-0025, ADR-0033, ADR-0037 (c), ADR-0039 (`charged_to = instrument`), ADR-0045 (`n/a{reason}`), ADR-0057, ADR-0098; OQ-348; R-2.10.1, R-2.10.6

## Context

The brief asks for "assembly of hosted-external participants (ADR-0001) as opaque definitions with ABI capabilities". Phase 1 fixed the IR side: `AgentProcess.hosted = OpaqueProcess{participant_ref, declared_capabilities (tri-state), observability_levels, version_identity, hosting_mechanism, supplies, budget, permissions}` with no component sub-entities (ADR-0018), the participant descriptor with class *declared* and granularities restricted to `SUPPORTED` coordinates (ADR-0013), and hosted `params` in the same `ParameterSpec` grammar (ADR-0023 (6)). What is undecided is how such a definition is *authored, sealed and validated* by the same service as native ones without adding a field to any native contract (T-LCD-06's failure signature) and without reporting "pass" for stages that cannot apply. The precedents are direct: Omnigent runs a black-box harness from one YAML with `executor{harness, model, auth}`, `params` ("typed user parameters"), `tools` and `policies`, and offers no static validation ("run the YAML", `docs/AGENT_YAML_SPEC.md` L13–62, L475–487); OpenHands' `ACPAgentProfile` has "no `llm_profile_ref` and no embedded credential" and no skill selection because "ACP agents own their tooling and prompt construction" (`agent_profile.py` L212–227); Harbor and Inspect host black boxes with capability records (ADR-0018 (b)).

## Options considered

1. **Hosted participants are configured outside the assembly service** (a J6-only descriptor). *Rejected:* budgets, permissions, supplied context/tools and `params` would escape `resolve`/`validate_assembly`, breaking M-1 (every run keys on a sealed registry record) and cross-class factorials in one `Design`.
2. **Run the full seven-stage validation and report "pass" on inapplicable stages.** *Rejected:* T-LCD-15's failure signature (component-level facts on a black box); a "pass" on class conformance would be a false claim of transparency.
3. **A separate hosted grammar and validator.** *Rejected:* two authoring vocabularies for one comparison plane; ADR-0023 (6) already shares the `ParameterSpec` grammar; a second validator drifts.
4. **Same `AssemblySource`, same pipeline; the hosted root selects `OpaqueProcess`; desugaring maps the meta-harness shape onto ratified fields; a degraded validation profile is a rule over which stages run and which return `n/a{class}`; budget and permission are enforced at the boundary (chosen).**

## Decision

1. **Authoring.** `AssemblySource{root_kind = hosted}` desugars: `executor.harness → participant_ref` (a registry name selector for a `ParticipantRecord`, WS-J6/J2); `executor.model → model_binding` on the ADR-0013 descriptor (`bound(M-set) | self-selected`); `auth → SecretRef` channel names only (ADR-0057; a value is `C-SEC-1`); `tools → supplies.tools` (references to `ToolCapability` versions the instrument supplies through the ABI); `instructions/prompt → supplies.context` as `ContextItem`s with `Text{authority ≤ external, origin = import | human}`; `policies → HarnessRule`/`Permission` entities; `params → ParameterSpec` with `affects ⊆ {configuration, product}` and `sweepable` admissible only over coordinates whose capability-vector entry is `SUPPORTED` (ADR-0013 (4); `enumerate` refuses others with `InadmissibleFactor`). `slots` and `profile_binding` are refused (`C-CLASS-6 SlotsOnHosted`).
2. **Sealing.** `resolve` pins `participant_ref` to a `ParticipantRecord.version_id`, records `version_identity = H(declaration ∥ participant_version)` as a claim (ADR-0018/0037 (c)), pins every `supplies` reference and the `Budget`/`Permission` entities, and produces an ordinary sealed HIR document with `semantic_id`/`version_id`; `configuration_id` uses the same coordinate rule (ADR-0036) with `profile.semantic_id` absent (`n/a`, never a placeholder hash).
3. **Degraded validation profile** (a rule over stages; no schema change): stage 1 schema runs; stage 2 class conformance is `n/a{class}` except `C-CLASS-6`; stage 3 parameter space runs unchanged (bidirectional rule); stage 4 constraints run (`authority_cap`s bound the boundary-enforced `Budget`/`Permission`); stage 5 kernel invariants run for the entities present (budget containment, delegation attenuation into the hosted process, provenance on every `Text`, `Permission.issuer ≠ model_claim`); stage 6 profile compatibility is `n/a{class}`; stage 7: `hosting_edges` runs and must be empty (the definition references only the kernel-owned `OpaqueProcess`; the ABI lowers *to* it, ADR-0018), identity stability runs, opacity is `n/a{class}`. Reports carry `n/a` rows exactly as ADR-0045 renders inapplicable metrics — never `pass`, never 0.
4. **Instantiation.** `instantiate` binds no component; it hands the sealed definition and descriptor to the hosting mechanism's driver, an **instrument** component (`charged_to = instrument`, ADR-0039), and the run manifest carries the ADR-0013 descriptor; `budget` and `permissions` are enforced at the boundary by the reference runtime, never by the participant's self-report (ADR-0018 invariant). Whether the driver binding is ledgered as `lifecycle.component.bound{class_id = hosting_adapter, …}` is OQ-348 (recommended: yes — instance graphs total across classes, no IR field added).
5. **Diffs** follow ADR-0149 T-4 (`L0 | L4`; coordinate and claim changes only).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: a black-box harness configured as one data document with typed params, tools and policies (S-118 `docs/AGENT_YAML_SPEC.md` L13–62); black-box profile variants with fewer fields and no credential, refusing foreign fields (S-110 `agent_profile.py` L67–76, L212–227); declared-vs-probed capabilities with `unknown ≠ unsupported` (S-118 `harness_capabilities.py`, Harbor `capabilities.py` via ADR-0018; S-035 ACP, S-152 LSP via ADR-0007); class-scoped `n/a` (ADR-0045, T-LCD-15); boundary-enforced budget/permission for delegated processes (ADR-0016 delegation attenuation; ADR-0053 attenuating delegation for hosted participants); ACP v2 stable core as the session baseline (ADR-0098).
- (b) Source-code precedent: `omnigent/docs/AGENT_YAML_SPEC.md` L13–62, L475–487 (S-118 @6a069da); `openhands-sdk/openhands/sdk/profiles/agent_profile.py` L212–227, L296–310 and `profiles/resolver.py` L262–291 (`_build_acp_settings`: command split, no credential, no project skills) (S-110 @3fc7b22). The shared-pipeline authoring with a degraded validation profile expressed as `n/a` stage outcomes is `no-precedent / novel`; the document shape and the black-box variant are precedented.
- (c) Disconfirming evidence considered: (i) hosted participants may need fields the record lacks as hosting mechanisms evolve — answered by ADR-0018: additions go through `ext` or a dialect bump, dependency direction ABI → IR; (ii) validating a black box "is theatre" — answered: what is validated is exactly the instrument-owned part (budget, permission, supplied artefacts, parameter space, secrets), which is where hosted runs fail in practice (dangling MCP refs and missing secret channels are the two errors OpenHands' dry-run reports for its ACP profile, `resolver.py` L64–100); (iii) Harbor/HAL/Inspect host black boxes without any of this — accepted per ADR-0004: the point is joint native/hosted `Design`s with typed budgets and `n/a` discipline, not hosting itself. None overturns.
- (d) Conditionality: assumes hosted participants can at minimum start/stream/cancel and account cost (ADR-0001) and that WS-J6's `ParticipantRecord` carries `declared_capabilities` and `participant_version`; assumes `model_binding = bound` requires the ABI's `model_family` coordinate `SUPPORTED`, else the coordinate is `n/a`.
- (e) Build-stage assignment: **C1 / Stage 3** (root selection, `C-CLASS-6`, the stage rule and `n/a` rows — so the plane is class-aware from the first sweep, ADR-0010); **C2 / Stage 4** (desugaring populated against real hosting mechanisms; driver binding; OQ-348) with WS-J6.

**T-LCD statement (ADR-0007 decision 5).** Satisfies: T-LCD-06 (no native contract changes; the profile is a rule over stages; `hosting_edges = []` checked; with hosting disabled the native suite is unchanged), T-LCD-07 (`sweepable` only over `SUPPORTED` coordinates; `unknown` never coerced; declaration vs vector kept distinct), T-LCD-15 (`n/a{class}` for stages 2/6/7-opacity; component-level facts never reported), T-LCD-14 (hosted `Budget` sealed and boundary-enforced; matched budgets apply uniformly), T-LCD-12 (same pure operations). Does not address T-LCD-03/-04 (native executable tests). **ADR-0024 rung:** the stage rule is MUST-code; the hosted authoring fields are MUST-data.

## Consequences

- WS-J6 designs the `ParticipantRecord` and hosting drivers so that D5/this ADR's mappings are total, and confirms the `hosting_adapter` binding event with WS-B1 (OQ-348); WS-J3 enforces `InadmissibleFactor` at `enumerate` for hosted `sweepable` params; WS-J4/J5 receive `n/a` rows unchanged; WS-K1 offers one `assemble` verb for both classes.
- Ontology: `degraded validation profile (hosted)` proposed (sidecar).

## Reversibility

**High.** The profile is a rule table over ratified stages; removing it returns hosted definitions to option 1 (J6-only), which costs M-1 but no stored object. The desugaring map is a data table revisable by ADR as hosting mechanisms change.
