# ADR-0128 — Prefix affinity key, expected-vs-observed cache state, cache accounting events and metrics, and cache warmth as a mandatory Lab factor (answers OQ-097)

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-C4 (with WS-C1 for stamping, WS-B1 for the event class, WS-L2/WS-I1 for charges and provenance, WS-I2/WS-J3/WS-J4 for the factor and refusal) · **Phase:** 2 · **Related:** ADR-0026/0027/0029 (ledger, ids, canonical form), ADR-0038 (R2 reproducibility of spend), ADR-0039 (R-ACC-1/2/3; "semantic caches that skip a model call still post a `model_calls` charge of 0 with `cache_hit = true`"; "cache warmth controlled or stratified"), ADR-0040, ADR-0041 (`MatchSpec`; T-LCD-14), ADR-0042 (export is lowering; loss report), ADR-0043 (`estimated_from_pricing`; `pricing_ref`), ADR-0044/0045 (metric declarations), ADR-0007 (T-LCD-10/-11/-14/-15); ADR-0118 (`cache_state_hint`, E-U3/E-U4); CF-274, CF-275, CF-278; OQ-097 (answered), OQ-117, OQ-306; R-2.3.4, R-2.1.6, R-2.9.1, R-2.10.3

## Context

ADR-0039 made cache roles first-class and defined the hit-rate denominator, and asked WS-C4 to "declare cache state (`warm | cold | unknown`) on `model.call.requested` so J3 can control or stratify on warmth (OQ-097)". WS-C1 found that no audited gateway exposes cache state per call (N1) and left `cache_state_hint` to be filled by C4. The audit shows: every harness sends a raw session id as the provider affinity key (opencode, pi), two scope auxiliary calls to their own key (codex guardian/reviewer; pi compaction), one clamps the key to 64 characters (pi); vendor TTLs run from request start and entries appear only after first byte (S-213), retention is best-effort (S-215); no harness records what it *expected*, what it *avoided* when a harness-level cache hit, or why a miss happened; Inspect skips usage recording entirely on a cache hit (`_model.py` L1464–1471), which ADR-0039 R-ACC-2 forbids. Cache warmth is therefore an uncontrolled experimental factor today: two arms with identical bytes pay different spend depending on run order (WS-L2 F2).

## Options considered

1. **Send the session/run id as the affinity key; record nothing beyond usage roles.** *Rejected:* leaks an allocated id onto the wire as a name (T-LCD-10), gives auxiliary calls the main prefix, and leaves warmth unattributable.
2. **Force cold start on every run and drop the question.** *Rejected as sole policy:* unrepresentative of production and doubles write spend; the Lab needs `natural` runs with warmth *reported* (S-036-class production comparisons).
3. **Record only observed hits (from usage) and stratify post hoc.** *Rejected as sole mechanism:* a zero cache-read cannot distinguish "below minimum length", "TTL elapsed", "concurrent sibling" and "prefix changed by compaction"; attribution needs an expectation and a cause.
4. **Kernel-derived affinity key with purpose scoping; `expected_state` derived from the ledger under lease semantics beside `observed_state`; one `model.cache.resolved` event and zero-amount charges with `cache_hit` for harness-level hits; avoided cost as an estimate with provenance; class-scoped cache metrics; `cache_policy` mandatory on every arm with engine refusal (chosen).**

## Decision

1. **Affinity key.** `derive_affinity_key(scope: RunId | root RunId, static_hash, purpose ∈ {main, compaction, probe, judge, subagent(id)}) → AffinityKey{full: ContentAddress, wire: prefix ≤ dialect.max_key_length, scope, purpose}`; deterministic across processes; the wire form is a surface alias recorded in `surface_ids.affinity_key`; never a raw session id, credential, principal identifier or `readers`-restricted content; `purpose ≠ main` never equals a `main` key; omitted (and recorded) when the dialect declares `affinity_key = unsupported`. `cache_policy = cold_start` salts `scope` with `configuration_version_id` and the replicate index.
2. **Expected vs observed.** `expect_cache_state(run, key, static_hash, request_sent_at) → {expected ∈ {warm, cold, uncacheable, unknown}, basis}` is a pure projection of the durable prefix: `warm` iff a prior completed same-`(key, static_hash)` call exists whose `request_sent + nominal_ms − margin_ms > now` and no `cache_invalidating` event lies between (lease rule: earlier clock wins; TTL from request start); `cold{concurrent_sibling}` if opened before the prior call's first byte; `uncacheable` below `min_cacheable_tokens`; `unknown` when semantics or retention are undeclared. The gateway stamps `observed ∈ {warm, cold, unknown}` from `cache_read > 0` (`unknown` iff `usage.available = false`). `model.call.requested` gains `cache{semantics_kind, affinity_key, affinity_wire_len, static_hash, purpose, expected_state, basis, markers, markers_dropped[], markers_substituted, retention_classes_requested}`; `model.call.completed` gains `cache_observation{observed, read, write_by_class, hit_ratio, write_ratio}`; the projection adds `agreement` and `miss_reason ∈ {ttl_elapsed, concurrent_sibling, provider_eviction, parameter_change, compaction, context_edit, relower, profile_version, definition_version, tool_set_change, marker_policy, dialect_change, unknown}` as a view (raw roles stay on the producing event, R-ACC-1). WS-C1's `cache_state_hint` is filled from `expected_state`.
3. **Accounting of harness-level caches (K2–K6).** One event class `model.cache.resolved{cache_kind, key, scope, outcome ∈ {hit, miss, bypass, stale_withheld, refused}, reason, entry_ref?, verifier_verdict?, avoided{model_calls?, tokens: ResourceVector, spend: Money{provenance = estimated_from_pricing, confidence = estimate, pricing_ref}}, attribution}` per lookup, hits *and* misses. A hit that replaces a model or tool call posts `control.budget.consumed{dimension: model_calls | tool_calls, amount: 0, attribution.cache = {kind, hit: true, avoided_ref}}` and zero-amount token-role charges (nothing unaccounted); verifier calls are ordinary `model.call.*` with `charged_to` per R-ACC-3. Avoided cost is derived from the entry's recorded roles under the pinned pricing table and reported beside realised spend in a `cost_totals` group `avoided_by_cache_kind` — never subtracted.
4. **Metric declarations** (ADR-0045 form; dimension `efficiency`; `computed_from` ledger; class-scoped, `n/a{observability}` for rows without usage roles): `cache.prefix_hit_ratio` (= Σ cache_read / Σ input.total), `cache.prefix_write_ratio[ttl_class]`, `cache.expectation_agreement`, `cache.prefix_churn` (by `miss_reason`), `cache.markers_dropped_total`, `cache.hit_rate[kind]`, `cache.false_hit_rate[semantic]` (C2), `cache.avoided_spend` / `cache.avoided_model_calls` (`confidence = estimate`, with band), `cache.spend_share_cached`. `cache.expectation_agreement` is the removal signal for retention-class debt records (T-LCD-05).
5. **Lab factor (OQ-097).** `cache_policy ∈ {cold_start, natural, primed{prime_ref}}` is mandatory on every arm (`MatchSpec` amendment, CF-278): `cold_start` is the default for `matched_cap`/`iso_cost` (the only policy whose spend re-derives at ADR-0038 R2); `natural` records `expected/observed` and the comparison engine stratifies by `cache.prefix_hit_ratio` bands; `primed` runs a declared priming call charged `instrument`. The engine refuses `IncommensurableMatch` when arms differ in `cache_policy` or when a `natural` arm runs on a dialect with `cache_state_visible = unsupported` without `n/a` stratification. Results rows carry `cache_policy`, `cache.prefix_hit_ratio` and `served_from_cache_count`.
6. **Export.** Roles lower to OTel `gen_ai.usage.cache_read/cache_write.input_tokens`; `expected_state`, `affinity_key`, `miss_reason`, `model.cache.resolved` and avoided cost are declared loss in the telemetry loss report.
7. **T-LCD statement.** Satisfies T-LCD-10 (wire key is a surface alias of a content-derived id), T-LCD-11 (declared export loss), T-LCD-14 (`cache_policy` mandatory; refusal on mixing), T-LCD-15 (class-scoped metrics; `n/a` never 0), T-LCD-05 (agreement metric as removal test), T-LCD-12 (operations). Does not address T-LCD-13 (no artefact delivered). Rung on the ADR-0024 ladder: key derivation, state projection and accounting are **Core** (MUST-code: ledger, budget enforcement, algorithms); `cache_policy` and margins are **data** (parameters).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** TTL measured from request start; entry available only after first byte; workspace isolation (S-213); best-effort retention "typically 5–10 minutes", affinity key as an accounting aid layered on the prefix hash, organization/region isolation (S-215); lease semantics — validity until the earlier clock's expiry (S-198, SOSP 1989, Tier A); cache warmth as an experimental confound (WS-L2 F2; ADR-0039 §4 consumer note); cost-observability as the largest budget-incident cluster (S-209, `provisional (mech)`, incident catalogue auditable); no gateway exposes pre-call cache state (WS-C1 N1); nondeterministic outputs mean a served cached response is one sample (S-441, Tier B) — why served-from-cache rows carry `timing = n/a` and a count.
- **(b) Source-code precedent:** codex `codex-rs/core/src/client.rs` L491–505, `core/src/guardian/review_session.rs` L302–314, `ext/guardian-v2/src/async_scorer/sampler.rs` L340 (purpose-scoped affinity keys); pi-mono `packages/ai/src/api/openai-prompt-cache.ts` L1–8 (key clamped to provider length), `packages/agent/src/harness/compaction/compaction.ts` L117–144 (summaries isolated from the main key), `packages/ai/src/api/anthropic-messages.ts` L555–556 (no key when retention `none`); opencode `packages/opencode/src/provider/transform.ts` L1310–1322 (session id as key — the rejected shape); codex `core/src/guardian/metrics.rs` L79–84, `ext/goal/src/accounting.rs` L511–530 (cache roles in goal/guardian accounting); inspect_ai `src/inspect_ai/model/_model.py` L1455–1471, L1666 (cache fetch/store around generate — usage skipped on hit, the rejected shape); litellm `litellm/caching/caching.py` L332–382 (namespaced, hashed keys). `expected_state`, `miss_reason`, `model.cache.resolved` with avoided-cost provenance and `cache_policy` refusal are `no-precedent / novel`.
- **(c) Disconfirming evidence considered:** the provider's cache is shared, best-effort infrastructure and any expectation will be wrong sometimes — answered by storing expectation and observation side by side and treating the disagreement rate as the descriptor-health metric rather than as truth; cold start is expensive and unrepresentative — answered by making policy a declared factor with `natural` admissible under stratification; extra payload per call — answered by ADR-0044 L1 always-on structural facts and by the unattributable-cost failure of the alternative (WS-C4 §5 R2, R5, R7). None overturns.
- **(d) Conditionality:** assumes providers report per-call cache-read counts (true for the three audited APIs; `observed = unknown` otherwise) and declare or let us probe a nominal retention (else `expected = unknown` and the metric is `n/a`); independent of model tier and task class; `primed` assumes the priming call is priced at the same snapshot (served-model drift annotates).
- **(e) Build-stage assignment:** C0 / Stage 1 (`derive_affinity_key`; `model.call.requested.cache{…}` and `cache_observation` schema; `model.cache.resolved` schema) → C0 / Stage 2 (`expect_cache_state` projection; `miss_reason`; K3/K4 accounting) → C0 / Stage 3 (metric declarations in the registry; `cache_policy` on arms with refusal; AC-C4-3/5/6/10) → C1 / Stage 5 (retention probes; avoided-cost reporting in J4; `primed` policy).

## Consequences

- WS-C1 stamps `observed` and fills `cache_state_hint` from `expected_state`; WS-B1 adds `model.cache.resolved` and the two payload extensions (CF-274); WS-L2/J3 amend `MatchSpec` with `cache_policy` (CF-278); WS-I2 registers the metric declarations; WS-J4 reports avoided cost beside spend, never netted; WS-I1 lists the declared losses; WS-F3 gives each subagent root `purpose = subagent(id)` so children never extend the parent's prefix.
- OQ-097 is closed by decision 5; OQ-117 receives the custody proposal (retention classes → dialect descriptor; `pricing_ref` → bundle).

## Reversibility

**Medium.** The key derivation and event payloads can be extended by dialect bump; removing `expected_state`/`miss_reason` later loses nothing stored elsewhere but blinds the churn metric; making `cache_policy` optional later would re-admit the warmth confound into matched comparisons (low reversibility for that rule, which is why it is a refusal at Stage 3).
