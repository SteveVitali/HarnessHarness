# ADR-0067 — Tamper-evidence contract: per-run chain, compact-range tree heads, kernel-signed checkpoints, inclusion/consistency proofs, cross-run anchors and independent auditors; witnesses and receiver receipts deferred to C2

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-H6 (with WS-B1, WS-L4, WS-I1, WS-J5, WS-I3, WS-F3, WS-J6, WS-H3) · **Phase:** 2 · **Related:** ADR-0029 (canonical form, per-run chain, leaf tag, redaction-safe hashing), ADR-0027 (fork-by-reference, `source_head_hash`, `causes[]`), ADR-0036 (identity profile, rotation checkpoint), ADR-0038 (bundle `audit_tree_head`, attestation subject), ADR-0042 (propagation context; `audit_view`), ADR-0026 (single fenced writer), ADR-0050 §8(a)/(c) (kernel/helper primitives); CF-058; OQ-169/-02/-03/-07, OQ-107; R-2.8.6, R-2.12.1, R-2.9.3, R-2.10.5

## Context

ADR-0029 gave every run a hash chain (`hash = H(leaf_tag ∥ canonical(envelope − hash) ∥ prev_hash)`) and left "audit checkpoints and inclusion/consistency proofs" to WS-H6 at Stage 2. A chain by itself proves nothing to anyone but its writer: Schneier & Kelsey show that forward security holds only for entries written before compromise and only when a trusted verifier later reads the log, that deletion of the tail is merely *detectable*, and that the primary weakness is a compromised writer that keeps writing (S-315); Crosby & Wallach define tamper evidence by what an auditor can demand — membership and consistency proofs — and show hash-chain proofs are linear while history-tree proofs are logarithmic (S-316); Certificate Transparency (S-190), Rekor/C2SP (S-318/05/06) and CloudTrail (S-321) all commit *periodically* with signatures and let others hold the commitments. HarnessHarness additionally branches (forks, ADR-0027), delegates (subagent run trees) and imports hosted rows — the split-view problem VCT (S-325) and C2SP address. The threat model must be stated: which adversaries a C0 research instrument detects, and which need parties outside it.

## Options considered

1. **Chain only (status quo after ADR-0029).** *Rejected:* O(n) verification for any citation; no way for a results row, bundle or parent run to cite a child event verifiably; truncation after the last event undetectable without an external head; equivocation across forks/children undetectable.
2. **Per-event signatures.** *Rejected:* cost per event (Crosby & Wallach: signing is the bottleneck, 1,750 vs 10,500 events/s), still linear proofs, no consistency semantics.
3. **A single lab-wide transparency log that every run appends to.** *Rejected:* a second store and a second identity (ADR-0026); cross-host coupling at Stage 1; conflicts with per-run fencing; the lab-wide *index of heads* (auditor store) gives the same benefit without a second log.
4. **External anchoring (blockchain/timestamping) at C0.** *Rejected at C0:* introduces an external dependency and availability window (S-322's own limitation), and a research instrument's disputes are intra-lab; admitted at C2 as witness cosignatures.
5. **Per-run chain + compact-range Merkle tree over leaf hashes + kernel-signed checkpoints at a declared cadence + logarithmic proofs + cross-run anchors + independent auditors holding heads (chosen); witnesses and receiver receipts as C2 capabilities.**

## Decision

1. **Leaves and nodes.** Leaf *i* of run *r* is event `hash` at `seq = i` (already domain-tagged, ADR-0029). Node hash = `H(node_tag ∥ left ∥ right)`; empty tree = `H(∅)`; tree head at size *n* = RFC 6962 root over leaves `[0, n)`. The writer keeps a **compact range** (the minimal perfect-subtree roots covering `[0, seq]`) and merges on every append, so a head costs O(log n) and no history is re-read.
2. **Checkpoints.** `security.audit.checkpoint{kind ∈ {periodic, effect_terminal, final, rotation, on_demand}, origin: run_id, tree_size, tree_head, chain_hash, prev_checkpoint{ref, tree_size, tree_head}?, consistency_proof?, cross_run_anchors[], idp, rehash? (rotation), signatures[]{signer_name, key_id, alg_ref, sig}, witness_cosignatures[] (C2), audit_policy_ref}` is an audit-grade ledger event (ADR-0066 Rule C; nothing offloaded). Cadence is MUST-data (`AuditPolicy.cadence`): `at_finish` and `on_rotation` are fixed; defaults proposed: every terminal of an `irreversible` or `compensable` effect, every *N* events, and a `max_unsigned_ms`. The **kernel signer** (a `KernelSignerRecord` in the run manifest and `InstrumentRecord`; private key readable only by the kernel process/helper — an H3 credential with `readers = {kernel}`) signs the canonical checkpoint payload. **No-inconsistency rule (C2SP):** the signer never signs a head that is not a consistency-verified extension of the last head it signed for that run; violation is `InconsistentHead` and the run is flagged, never signed.
3. **Proofs.** `prove_inclusion(run, event, at) → InclusionProof`, `prove_consistency(run, from, to) → ConsistencyProof`, with `verify_inclusion` / `verify_consistency` as pure functions (RFC 6962 / S-317 `proof/verify.go` semantics). A citation anywhere in the instrument is an `audit_ref{run_id, seq, hash, checkpoint_ref, inclusion_proof?}`; results rows (WS-J5), bundle members (WS-I3/L4), viewer links (WS-K2) and metric `computed_from[]` (ADR-0044) cite by `audit_ref`.
4. **Cross-run anchors.** `control.subagent.spawned` carries `parent_head_at_spawn{seq, hash}`; the child's `lifecycle.run.created` carries `parent_anchor{run_id, seq, hash}`; `control.subagent.result | cancelled` carries the child's `final` checkpoint head; `lifecycle.run.forked.forked_from.source_head_hash` (ADR-0027) must equal the source's head at `at_seq`; every checkpoint lists the anchors in its range. `verify` follows anchors; a mismatch is `Tampered{fork_equivocation}`.
5. **Auditors.** An **auditor** is a subscriber (`subscribe`, ADR-0026) that recomputes heads independently, compares them with signed checkpoints and stores `(run_id, checkpoint_ref, tree_size, tree_head, signatures)` where the run's writer cannot write: the results-store row (J5), the bundle manifest (`traces.audit_tree_head`, ADR-0038), the parent run (anchor), and a lab-wide audit index. Two auditors holding different heads for one `(run, tree_size)` is `Equivocation`. Verification of a run at rest = chain + every checkpoint signature + consistency between consecutive checkpoints + anchors + producer rule (ADR-0066) → `ok | Tampered{at_seq, kind ∈ {edit, delete, reorder, truncate, late_insert, fork_equivocation, bad_signature, producer}}`; hashes verify under each id's own `idp` (ADR-0036); a `rotation` checkpoint carries `rehash` and is co-signed by old and new keys.
6. **Threat model (binding statement).** Detected at C0: T1 post-hoc storage tampering (edit/delete/reorder/truncate/late insert/prefix replacement); T2 misbehaviour of any in-run component below the kernel (model, tools, hooks, extensions, executors, hosted participants) — they cannot produce or alter audit-grade events and every kernel-mediated act is recorded; T3 stale/rogue writers (fencing + kernel-only signing); T4 split views across forks and delegation trees within the instrument. **Out of scope at C0, stated:** T5 a compromised kernel or exfiltrated signer key (forward security covers only pre-compromise entries whose heads an auditor already holds); T6 actions that bypass the kernel entirely (containment's job, WS-H4/E5/B5). C2 extensions: witness cosignatures from a process outside the host (C2SP `tlog-cosignature` shape: timestamped signature over the same note; quorum policy in `AuditPolicy.witness_policy`), and **receiver-attested receipts** for open-world effects (S-324 shape) as a hosting-mechanism/executor *capability* (`capability_vector` entry `receipts`, T-LCD-07), lifted as `unverified`/`external` links — never a native-contract change (T-LCD-06).

**T-LCD statement.** Satisfies T-LCD-12 (proof and verify are pure record functions; auditors run out-of-process over the WS-L1 §6.5 boundary), T-LCD-11 (checkpoints/proofs are listed in export loss reports when a sink cannot carry them), T-LCD-06/-07 (receipts and witnesses are declared capabilities, never intersections or IR fields), T-LCD-15 (hosted rows' checkpoint status is `n/a` where the adapter cannot supply leaves). Not applicable: T-01/-02/-03/-04/-05/-08/-09/-10/-13/-14. **ADR-0024 rung:** hashing/signing/proofs/anchors are MUST-code; cadence, witness policy and signer records are MUST-data.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** Schneier & Kelsey S-315 (Tier A: forward-secure chained log; tail deletion detectable only via an external verifier; abnormal-shutdown vs truncation; compromised-writer limitation); Crosby & Wallach S-316 (Tier A: audit semantics = membership + consistency proofs; hash chains need linear audits, trees logarithmic; forking-inconsistent views must be detected across commitments; 1,750 → 10,500 events/s when signing is offloaded); RFC 6962 S-190 (domain-separated tree hashing, STH, inclusion and consistency proofs); C2SP tlog-checkpoint S-319 ("MUST not sign any checkpoint which is inconsistent with any checkpoint it previously signed"; extension lines "not auditable by log monitors" — why the typed canonical payload is used instead) and tlog-cosignature S-320 (witness = timestamped signature over the same note; quorum prevents split view); CloudTrail S-321 (periodic signed digests chaining to the previous digest; "assert positively that no log files were delivered … during a given period"); ADR-0029 (leaf hash; redaction-safe hashing); ADR-0027 (fork anchors). Fresh corroboration, mechanism only: Agent Flight Recorder S-322 (`provisional`: chain + Merkle batching + chained epochs; edit/delete/reorder/fork battery), VCT S-325 (`provisional`: branch chains → session roots; fork detection by gossip), Notarized Agents S-324 (`provisional`: receiver receipts). No provisional source is load-bearing.
- **(b) Source-code precedent:** transparency-dev/merkle @a09734c `rfc6962/rfc6962.go` (`HashLeaf` H(0x00‖leaf), `HashChildren` H(0x01‖l‖r), `EmptyRoot`), `proof/verify.go` (`VerifyInclusion`, `RootFromInclusionProof`, `VerifyConsistency`, `VerifySubtreeConsistency`), `compact/range.go` (`RangeFactory.NewRange`/`NewEmptyRange`: "minimal set of perfect sub-trees covering the [begin, end) leaves range" — the writer's compact range); sigstore/rekor @1ddb2c2 `pkg/util/checkpoint.go` (`Checkpoint{Origin, Size, Hash, OtherContent}`; three-line text form), `pkg/util/signed_note.go` (`SignedNote{Note, Signatures[]}`; `Sign` appends `{Name, Hash(pk), Base64}`; `Verify` matches key hash then signature — the multi-signer checkpoint shape); Codex S-107 `codex-rs/protocol/src/protocol.rs` `SessionMeta{forked_from_id, forked_from_ordinal_exclusive}` (fork lineage; no hash — the gap the anchor fills); Logos S-073 observer node (independent second recorder — the auditor role, `provisional`). Chain + tree heads + signed checkpoints + cross-run anchors over a *harness* ledger: `no-precedent / novel` among audited harnesses; every primitive is a standard.
- **(c) Disconfirming evidence considered:** no audited harness chains or signs (Managed Agents S-047 and Logos ship plain append-only files); Kiehl S-195; per-checkpoint signing cost; the "logger is the logged entity" objection (S-324) that no self-signed record is evidence against its author; anchoring availability windows (S-322). *Why not overturning:* R-2.8.6 is C0/Must and ADR-0029's chain was ratified on the premise that H6 attests it; tree heads are a derived structure (compact range, O(log n)) and signing is per checkpoint at a data-declared cadence; the trust boundary is already the kernel TCB (doc 2 §5.6, ADR-0035), so the objection applies only to T5, which is stated out of scope at C0 with C2 mitigations; the auditor-held heads (results store, bundle, parent run) give Crosby–Wallach's gossip inside the lab without external dependencies.
- **(d) Conditionality:** independent of model tier and task class. Assumes WS-B1's Stage-1 throughput (tens of events/s per run) — three orders below the Tier-A figures; assumes a kernel-held signing key with `readers = {kernel}` custody (OQ-170) and the ADR-0050 kernel/helper ecosystem's signature and hashing primitives (ADR-0050 §8(a)/(c) — properties only); assumes single-host runs at Stage 1–2 (multi-host auditors are Stage 4). Witness quorum and receipts assume parties outside the instrument and are C2.
- **(e) Build-stage assignment:** C0 / Stage 1 (`verify` over the chain — ADR-0029; `KernelSignerRecord` and `audit_policy_ref` in the manifest); C0 / Stage 2 (compact range, checkpoints, signatures, proofs, cross-run anchors, auditor subscriber storing heads to the results store and parent runs); C0 / Stage 3 (AC-H6-1/-6/-7/-8/-11 in the suite; `audit_ref` on results rows); C1 / Stage 4 (bundle attestation with checkpoint refs; lab-wide audit index; rotation end-to-end with WS-L4 AC-L4-6; hosted rows `n/a`); C2 / Stage 4+ (witness cosignatures; receiver receipts as a capability-vector entry).

## Consequences

- WS-B1 adds the compact range to the writer state (rebuildable from the chain) and the two anchor fields to `control.subagent.*` / `lifecycle.run.created`; `verify` gains the checkpoint and anchor checks.
- WS-J5 rows and WS-I3 bundles carry `audit_ref` / checkpoint heads; WS-L4's bundle attestation predicate lists the `final` checkpoint; WS-K2's viewer verifies `audit_ref`s client-side.
- WS-H3 provisions and isolates the kernel signer key; rotation is a `supersedes` on `KernelSignerRecord` plus a co-signed `rotation` checkpoint (with ADR-0036's `idp` rotation when both change).
- WS-F3 records `parent_head_at_spawn` / child heads; WS-J6 adapters append leaves for hosted rows and report checkpoint status as `n/a` where leaves are unavailable.
- WS-I2 gains `checkpoint_interval_events`, `unsigned_tail_events` as declared metrics.

## Reversibility

**Medium.** Checkpoints and proofs are derived from the ADR-0029 chain, so they can be recomputed or dropped without touching stored events; removing kernel signing after Stage 2 would invalidate the auditor role, AC-H6-1 (d)/(h) and every `audit_ref` citation, and the C2 witness/receipt path depends on signed checkpoints existing.
