# ADR-0040 — Hierarchical budget contract: budget nodes with dynamic containment, slice/pool delegation, reserve-before-spend, root-first exhaustion, and soft-vs-hard budgets

**Status:** **ratified, amended** (Phase 2 synthesis, 2026-09-10); previously: **ratified, amended** (Phase 1 synthesis, 2026-09-10)
**Owner workstream(s):** WS-L2 (with WS-F2 as enforcer, WS-F3 for delegation, WS-A3 for the `Budget` entity and `HirDiff.budget_delta`, WS-B2 for effect-boundary semantics, WS-C3/D1 for advisory rendering, WS-H7 for approval budgets) · **Phase:** 1 · **Related:** ADR-0002 (governance: no self-loosening), ADR-0007 (T-LCD-05, -08, -13, -14); ADR-0016/ADR-0017, ADR-0030/ADR-0031, ADR-0026; CF-071, CF-072, CF-073; OQ-012, OQ-013, OQ-095, OQ-096, OQ-098, OQ-099, OQ-100; R-2.1.6, R-2.6.2, R-2.6.3, R-2.6.4, R-2.8.7

## Context

Doc 2 §4's design principle puts budgets among the hard invariants that belong in deterministic software, and §11 Stage 0 requires "explicit token/tool/time budgets". WS-A3 fixed the definition-time `Budget` entity (dimensions with hard/soft bounds, `scope`, `parent`, `child ≤ parent`) and `delegated-to` edges carrying `Ref<Budget> ≤ parent`; WS-B2 fixed the effect lifecycle whose invariants a budget must not break (no blind redispatch; every intent reaches a terminal or `unknown`); WS-B1 reserved `control.budget.consumed/exceeded`.

The audit found two budget *semantics* coexisting in production — advisory (Claude SDK `task_budget`, Codex `<rollout_budget>` reminders, Anthropic's server-side countdown, which the vendor documents as "a soft hint, not a hard cap" that can cause "refusal-like behavior" when too small) and enforced (Claude SDK `max_budget_usd`, Codex `SessionBudgetExceeded`, Inspect `LimitExceededError`) — and two *delegation* shapes: Inspect's nested exclusive limit scopes with ancestor propagation and root-first checks "preventing certain sub-agent architectures from ending up in an infinite loop", and Codex's single weighted pool "for one root-thread session tree" with a fan-out cap. The 2026 incident catalogue documents the failure when neither is done carefully: the delegation-fanout race (11/63 incidents; concurrent children sharing one budget object "overshoot 30/30" without reservation), and recommends reserve-before-spend, a single accounting authority and affine budget handles (S-209, mechanism). Agent Contracts states the conservation invariant Σ_j c_j(r) ≤ B(r) and terminates on any violated dimension (S-208, `provisional`).

## Options considered

1. **Flat per-run budget only; subagents unbudgeted (or prose-instructed, as S-036's "effort scaling rules").** *Rejected:* fan-out is the dominant cost multiplier (≈15× tokens) and prose is not an invariant; OQ-013 asks for resource reservation across agents.
2. **Exclusive slices only (Inspect).** *Rejected as sole mode:* over-partitioning starves children with uneven work; Codex's shared pool is a legitimate, deployed alternative.
3. **Shared pool only (Codex).** *Rejected as sole mode:* without reservation a shared pool is exactly the delegation-fanout race.
4. **Hard caps that interrupt mid-effect.** *Rejected:* violates WS-B2 invariants (a committed irreversible effect would be left `unknown` by the budget itself) and produces the "premature stopping" failure.
5. **Advisory only (model self-regulation).** *Rejected:* vendor docs say the model "may occasionally exceed the budget"; the Lab needs a deterministic bound (T-LCD-14).
6. **Budget nodes as a tree with dynamic containment, both `slice` and `pool` modes under a conservation invariant, reserve-before-spend, root-first checks, soft budgets as measurable artifacts and hard budgets enforced only at effect boundaries (chosen).**

## Decision

1. **Runtime object.** `BudgetNode{budget_id, scope, parent?, mode ∈ {slice, pool}, dimensions: map<DimensionId, {hard: Ceiling?, soft: [Threshold], metering: MeteringFormula?, grace?}>}` instantiates a WS-A3 `Budget` for one run/process/procedure/experiment; views `consumed`, `reserved`, `remaining` are projections of `control.budget.*` events. One root node per run; a single accounting authority (the run ledger's writer lease) posts every charge.
2. **Containment is dynamic.** `allocate(parent, spec)` succeeds only if `child.hard ≤ parent.remaining` dimension-wise at allocation time. In `slice` mode the child's ceiling is moved out of the parent's available amount and the unspent remainder is moved back on child completion (affine: never aliased, never dropped); in `pool` mode the child shares the parent's pool and may only tighten. Charges in a child propagate to every ancestor, so a parent's `remaining` is always the truth.
3. **Reserve-before-spend.** `reserve(budget_id, quantity, holder, ttl) → reservation_id` precedes every model call (sized by the profile's declared `max_output` bound and, for tools, by the capability's `cost_model`) and every spawn. Invariant: Σ reservations + consumed ≤ hard ceiling along the whole ancestor chain (the conservation law applied to reservations). Reservations die with the holder's lease; a charge consumes its reservation and releases the excess; consumption beyond a reservation is charged and flagged, never refused after the fact. `InsufficientBudget` is a typed pre-dispatch refusal.
4. **Root-first exhaustion.** `check` evaluates ancestors before descendants; the outermost exceeded node is the one reported, so a child cannot spin on its own exhaustion while the root is spent.
5. **Two semantics, never conflated.** A **soft** threshold's action is a `HarnessRule` (`insert ContextItem`) rendered by the Model Profile as a budget reminder; its delivery/activation/following are `context.artefact.*`/`verification.artefact.followed` events (T-LCD-13), so *budget compliance* is a class-scoped metric; soft thresholds are recorded once per (budget, threshold, context window) and re-armed after compaction. A **hard** ceiling is enforced by the control envelope (WS-F2) only at decision points: before a call (reservation refusal) and after an effect's terminal event; the envelope then appends `control.budget.exceeded` and `control.decision{stop, reason: budget_exhausted{dimension}}` and the run ends with `stop_reason = budget_exhausted`, every open effect closed per WS-B2. A per-dimension `grace` allowance may permit one terminal summarising call; grace is a soft threshold action, not a ceiling widening. Gauge caps (`fan_out`, `delegation_depth`, `context.occupancy`) refuse the next increment (`SpawnRefused`, `CompactionRequired`) rather than stopping the run.
6. **Amendment and governance.** `amend(budget_id, delta, authority)` is ledgered; permitted on the root by an operator/human authority (live retune) and on a child by its parent within the parent's remaining. A harness edit whose `HirDiff.budget_delta = loosening` is unacceptable in an evolution context (ADR-0002 governance, parallel to `AuthorityWidening`). Exhaustion of an *approvals* budget converts the next `ask` into `deny`, never into `allow`.
7. **Hosted participants** receive a boundary budget (WS-A3 `OpaqueProcess.budget`): the hosting adapter charges what the mechanism can observe, `check` runs at the boundary, exhaustion cancels through the Hosting ABI; the participant's internal advisory budget is supplied only if its capability declaration admits instruction delivery, else `unknown` (T-LCD-07). No native contract changes for them (T-LCD-06).
8. **T-LCD statement.** Satisfies T-LCD-08 (accounting handle given to every component), T-LCD-13 (soft budgets are artifacts with delivered/activated/followed), T-LCD-14 (hard ceilings are the enforceable matched budget), T-LCD-05 (a profile-conditioned reminder template is a conditioned rule with an assumption-debt record), T-LCD-06/-07 for hosted boundaries. Does not itself decide reservation sizing (OQ-098) — mitigated by the containment invariant, which holds for any sizing.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** advisory budgets are soft and can induce refusal (S-214, vendor doc; S-109 `TaskBudget` docstring); shared budgets without reservation overshoot under concurrent fan-out, with real losses (S-209, `provisional (mech)`, incident-level evidence); conservation across delegation is implementable with zero violations in a 50-trial pipeline (S-208, `provisional`); fan-out dominates cost (S-036, production); root-first checking prevents sub-agent loops (Inspect code comment, S-136); reserving before selecting is practised at request build (Codex guardian, S-107); budget exhaustion must respect the effect lifecycle (WS-B2 §6.1 invariants; S-078 intent/outcome pairs).
- **(b) Source-code precedent:** inspect_ai `src/inspect_ai/util/_limit.py` (`_Tree`, `_TokenLimit.record/check` root-to-leaf, `apply_limits`, `_limit_overrides.py` root-only live overrides); codex `codex-rs/core/src/rollout_budget.rs` (shared weighted pool per session tree; threshold reminders per thread/window; `rearm_reminder`), `core/src/session/rollout_budget.rs` (`SessionBudgetExceeded`), `core/src/guardian/input_budget.rs` (reserve then enforce), `core/src/agent/control/execution.rs` (`AgentExecutionLimiter`); claude-agent-sdk-python `types.py` (`TaskBudget` vs `max_budget_usd` → `error_max_budget_usd`); symphony `SPEC.md` §4.1.8 (`max_concurrent_agents`); autogen `conditions/_terminations.py TokenUsageTermination`. The integrated tree + slice/pool + reservation + soft/hard split is `novel as integrated`; each element is precedented.
- **(c) Disconfirming evidence considered:** hard token caps can hurt (HAL S-135: more effort often lowers accuracy; Anthropic: too-small budgets cause refusals) — addressed by enforcing only at effect boundaries and measuring compliance rather than pretending soft = hard; reservation reduces utilisation and no audited harness reserves per model call — addressed by staging (containment at Stage 0–3, reservation required only for concurrent `pool` children at Stage 4) and OQ-098; leases assume bounded clocks (WS-B2 R6) — reservations inherit the writer lease's fencing. None overturns.
- **(d) Conditionality:** the soft/hard split assumes models respond to countdown artifacts (model-conditioned; measured per profile via T-LCD-13, so the assumption is tested, not assumed); `pool` mode assumes concurrent children under one root ledger (Phase 4 F3/F5); holds for any task class.
- **(e) Build-stage assignment:** C0 / Stage 0 (one root node, hard ceilings on blended tokens/model calls/wall time, `check` at decision points, `stop_reason = budget_exhausted`) → Stage 1 (node schema, `allocated/reserved/consumed/released/exceeded/amended` events, dynamic containment, soft thresholds as HarnessRules) → Stage 3 (compliance metric, exhaustion battery AC-L2-4/5) → C1 (`amend` live retune, reservation sizing policy) → C3 / Stage 4 (`slice`/`pool` delegation with WS-F3; hosted boundary budgets with WS-J6) → Stage 4–6 (WS-F4 value-of-compute as a policy over `allocate/reserve`).

## Consequences

- WS-F2 implements `check`/`reserve` at decision points and the exhaustion rule; WS-B2's four-kill-point battery gains a budget-exhaustion case (AC-L2-4).
- WS-F3's `control.subagent.spawned{budget_slice}` becomes an `allocate` with an explicit `mode`; WS-F5's resource-reservation question (OQ-013) is answered by the reservation invariant.
- WS-C3/D1 render soft budgets through the profile; the reminder template is a conditioned rule with an assumption-debt record (T-LCD-05).
- WS-B1 adds `control.budget.allocated/reserved/released/amended` (CF-068); WS-A3's `child ≤ parent` becomes "≤ parent.remaining at allocation" (CF-067 note).
- WS-J6 must declare per participant whether an internal advisory budget can be delivered (CF-073).

## Reversibility

**Medium.** Dropping `pool` mode or reservation later is a simplification with no data loss; adding them after Stage 1 without the event classes would require a ledger schema migration. Merging soft and hard semantics later would destroy the compliance signal — low reversibility for that split, which is why it is fixed at C0.
