# ADR-0003 — Positioning: MetaHarness is a research instrument + reference runtime, not a general orchestration framework (explicit non-goals)

**Status:** ratified (amended at Phase 0 synthesis, 2026-09-09 — see *Amendment log*)
**Owner workstream(s):** WS-A1 (with WS-L7) · **Phase:** 0 · **Related:** ADR-0001, ADR-0002, CF-009, CF-012, CF-013, R-2.12.5, R-2.1.1, OQ-032

## Context

The sponsor's brief asks for "the most sophisticated, generic, modular, extensible meta-harness framework on the market." Doc 3 §1.1 already restates the thesis as a *comparison instrument + reference runtime*. CF-009 records the tension: the 11-system source-code study (S-074) finds that no mature coding harness imports a general-purpose agent framework for its core loop, and this dossier's direct reading of OpenHands, Pi, Codex (app-server), Omnigent, Prime Agent, Claude Agent SDK and OpenHarness confirms every one hand-rolls its loop while converging on *external* contracts (ACP, MCP, skills, typed hooks, declarative config). Meanwhile, the "compare everyone's" function is already served by Harbor, HAL, Inspect AI and Harness-Bench (dossier §4a F1), and "declarative agent definition compiled to many runtimes" is served by Open Agent Spec (F4). A positioning that competes on framework adoption or on black-box leaderboards has no whitespace; a positioning on component-level harness science with a portable behavioral IR does.

## Options considered

1. **General orchestration framework** ("most generic framework on the market"). Rejected: CF-009/S-074 show mature harnesses will not adopt an external loop; the market slot is occupied (LangGraph, AutoGen, Agent Framework, Agent Spec); the LCD trap (doc 2 §5.11/§12) is maximal here.
2. **Black-box evaluation harness / leaderboard** (a fifth Harbor/HAL). Rejected: already served at product granularity; adds no component-level science; conflicts with ADR-0001's native-primary stance.
3. **Managed hosting product** (Omnigent/AgentCore plane: sessions, collaboration, sandboxes, policies over many harnesses). Rejected: not a research instrument; name collision with Omnigent's "meta-harness"; operational scope outside the sponsor's laboratory intent.
4. **Research instrument + reference runtime with explicit non-goals (chosen).** The runtime exists to make IR-native (white-box) participants ablatable and attributable; the instrument compares white-box and black-box participants on one plane; adoption pressure sits on the IR's external edges (ACP/MCP/interchange/export), not on the loop.

## Decision

- Spec §1 states: *MetaHarness is a research instrument and reference runtime for harness engineering whose load-bearing capability is comparability under a portable behavioral representation.*
- Spec §1 carries **one canonical non-goals list, N1–N13, ratified in ADR-0006** (CF-019). The five non-goals this audit derived are members of that list: not a general agent-building framework for application developers (**N1**); not a universal Harness ABI that treats hosted participants as decomposable (**N2**, ADR-0001); not a hosted collaboration / managed multi-device hosting product (**N3**); not a standalone leaderboard service — hosting exists for joint native/hosted science and interoperation with existing planes (**N4**, ADR-0005); not a benchmark author — environments/benchmarks are integrated, not invented (**N13**, WS-I4).
- Every §2 item marked ⊕ NEW / ↑ EXT carries a `precedent | renamed | novel` annotation in the spec, sourced from WS-A1 §4c/§6.2/§6.3, so the spec never claims novelty the audit does not support.
- The reference runtime is **opinionated and minimal** (doc 2 §11 Stage 0–3 first); it does not aim to host third-party core loops.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: S-074 (no general framework in 11 core loops; ACP hosting role; prose→config migration) `provisional (mech)`; direct source audit — `openhands-sdk/openhands/sdk/agent/base.py` (frozen config-defined agent with own loop), `pi-mono/packages/agent/src/harness/runtime/harness.ts` (own `Harness` runtime), `codex-rs/app-server-protocol/src/protocol/v2/thread.rs` (hosting verbs, opaque internals), `omnigent/inner/executor.py:611` (hosting ABI over 12+ harnesses); S-045 (LangChain: harness = everything outside the model; LangGraph as a harness-*building* library); S-058/S-059/S-056 (vendors expose config-declared harnesses and runtime/harness splits, not comparison instruments).
- (b) Source-code precedent: for the *instrument* role — Harbor `src/harbor/models/job/config.py` + `agents/base.py` (S-132), HAL `hal/agent_runner.py` (S-134), Inspect `src/inspect_ai/agent/_bridge/bridge.py` (S-136); for the *reference runtime* role — mini-SWE-agent/SWE-agent lineage (S-114/S-115) and Harbor's own `terminus_2` as a native reference agent. The *combination* (IR-decomposable reference runtime inside the instrument) — `no-precedent / novel`.
- (c) Disconfirming evidence considered: (i) a reference runtime nobody adopts could be dead weight — answered by scoping its purpose to instrument validity, not adoption; (ii) Harbor/HAL already "compare everyone's" — answered by N3 and ADR-0005 (interoperate); (iii) S-083/S-092 suggest harness benefit is localized and budget-conditional, reducing the payoff of full decomposition — answered by keeping C0 minimal and evaluation-first (Stage 3 before Stages 4–6). None overturns the decision.
- (d) Conditionality: holds for any model tier and task class; assumes the ecosystem keeps converging on ACP/MCP/skills/config as external edges (S-074 trend). If a dominant open loop framework emerged that mature harnesses adopted, N1 would be revisited.
- (e) Build-stage assignment: program-level (Spec §1); no code stage. Annotation obligation applies at Phase 5 assembly.

## Consequences

- WS-L7 inherited the novelty/renamed lists (converged: ADR-0006 decision 2) and disclosed the naming collision with Omnigent's "meta-harness" (CF-013 → ADR-0008; sponsor decides the public qualifier via OQ-035).
- WS-A3 must deliver the seven-plane entity set with provenance, or novelty claim 1 in the dossier reverts to "renamed" and this ADR's positioning weakens to option 2.
- WS-K4 (SDK/embedding) is scoped as *embedding the instrument/runtime in a host app*, not as a framework for building arbitrary agents (scope.md R-2.11.4 note). CF-009 is **resolved** by this ADR together with ADR-0006.
- Readiness Report must show every ⊕ NEW/↑ EXT item annotated.

## Reversibility

Medium. Positioning text is cheap to change, but downstream scoping (K4 surface, J6 ABI depth, L7 naming) would need re-derivation if the project later chose option 1 or 3.
