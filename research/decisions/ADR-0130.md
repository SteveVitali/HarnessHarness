# ADR-0130 — The durability contract: checkpoint as a projection, phase-resolved restore, replay rules, and four fenced lease scopes

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-B3 (with WS-B1, WS-B2, WS-F1, WS-F2, WS-E5) · **Phase:** 2 · **Related:** ADR-0026, ADR-0027, ADR-0028, ADR-0029, ADR-0030, ADR-0031, ADR-0032, ADR-0037, ADR-0040, ADR-0042, ADR-0025; CF-017, CF-280, CF-285; OQ-081, OQ-090, OQ-119, OQ-252, OQ-134; R-2.2.3, R-2.2.1, R-2.2.2, R-2.2.5

## Context

ADR-0026 makes the run ledger the sole authoritative record and mandates one fenced writer per run; ADR-0028 fixes durability as *event reconstruction* and confines deterministic replay to declaring variants; ADR-0030 gives every effect a write-ahead `committed` record and an explicit `unknown`; phase-1 §6.9 binds WS-B3 to "resume from the last durable effect phase and emit `action.effect.unknown` for every `committed` effect on resume". What is still unspecified is the *procedure*: what a checkpoint is, what `restore` does to every open scope kind, which replays are forbidden, and how leases beyond the writer lease behave. Production systems that run agents for days restore by reading a log and resuming through the normal path (Codex daemon recovery `daemon_snapshot.rs`; Managed Agents `wake(sessionId)`; Cursor on a durable-execution engine), while systems that checkpoint at code granularity re-execute side effects on resume (LangGraph `interrupt`; Cloudflare fibers "The original lambda is gone"). Symphony deliberately does not restore timers or in-flight sessions after a restart (SPEC §14.3), which is the gap a research runtime with compensable/irreversible effects cannot leave open. Leases in OpenHands and prime-agent converge on `{holder, generation, expires_at}` with same-host liveness probing and start-id-hardened identity.

## Options considered

1. **Snapshot-based checkpoints of control state (LangGraph/Cloudflare-fiber shape), resume by re-running the step.** Rejected: re-executes side effects between the checkpoint and the crash; contradicts ADR-0028 and the no-repeated-action requirement.
2. **Deterministic replay of the control loop from the event history (Temporal shape) as the Core mechanism.** Rejected: ADR-0028 already confines determinism to declaring variants; it constrains every control-strategy variant the Lab wants to vary.
3. **No runtime-owned recovery; reconcile against an external source of truth and let the model decide retries (Symphony/Managed Agents shape).** Rejected as the Core choice: safe only for reprovisionable, workspace-local effects; loses timers and in-flight state; the reconciliation *pattern* is kept for environment verification.
4. **Checkpoint as a ledger projection; restore as a phase-resolved procedure with a normative per-scope recovery table; four lease scopes sharing one generation fence** — chosen.

## Decision

1. **Checkpoint is a view.** `checkpoint(run, until?) = project(run, checkpoint_view, until)` = `{run_id, seq, head_hash, control_state_ref (WS-F1 checkpoint_ref of the last admitted control.decision), effect_summary[], open_scopes[], env_handles[], subscriptions[], budget{consumed, reserved}, resume_set_heads[], pending_permissions[], view_hash}`. It may be materialised as a content-addressed blob and cited (WS-H6 `child_head.checkpoint_ref`), but restore from the blob and from the raw prefix must produce the same `RecoveryPlan` (AC-B3-02). No separate checkpoint store; no process-memory snapshot; no eternal run.
2. **Restore is a procedure with an auditable decision.** `restore(run, holder, mode ∈ {takeover, continue}) → RecoveryPlan{lease, from_seq, recovery_decision{last_durable_phase, action ∈ {continue, resolve_unknowns, suspend, stop{reason}}, cause}, actions[]}`: acquire the writer lease (takeover per decision 4) → `verify(run)` (ADR-0029; `Tampered` aborts) → build the checkpoint view → apply the **recovery table** (WS-B3 dossier §6.3; normative) to every open scope → append exactly one `lifecycle.run.resumed{from_seq, lease, recovery_decision, holder, cause}` → execute every `RecoveryAction` as its own ledgered event → `envelope.arm` (WS-F2 G-RESUME) → deliver `Cue.resumed{last_durable, recovery_decision}` (WS-F1). Resume verification of the sealed definition applies (ADR-0025 `verify_resume`: add-only proceeds with `lifecycle.definition.changed`; otherwise `DefinitionChanged`); `resolve(mode = execute)` refuses revoked heads (ADR-0037).
3. **Replay rules (operationalising ADR-0028).** R-1 no `committed` effect is dispatched again with the same `attempt_no`; every `committed` effect without a terminal receives `action.effect.unknown{cause: worker_lost}` and is resolved by `probe` and the ADR-0031 class table (`read_only` redispatch; `reversible` probe-or-revert-and-redo; `compensable` probe then same-key retry only on `not_applied`; `irreversible` never redispatched, escalated). R-2 no model call is issued to rebuild a view; an open `model_call` becomes `model.call.failed{error_class: worker_lost}` and its retry is an ordinary `model_attempt` under the envelope's `RetryPolicy` with the same `model_call_id` (partial streams were ephemeral; surfaces rewind). R-3 exactly one `lifecycle.run.resumed` per restore. R-4 restore is idempotent: each `RecoveryAction` is keyed by scope id and durable before the next, so a crash during restore (KP-13) and a second restore produce the same ledger. R-5 every appended event carries the new `lease_generation`. Pure scopes (`context_assembly`, `compaction`) are discarded and redone; `validation` is re-run; `permission pending` stays pending (deadline ⇒ `refused`, never `unknown`); child runs recover under their own leases; scopes past deadline are force-closed by WS-F2 INV-1 with the default deadline = hard `time.wall_ms` ceiling + manifest `grace_ms` (answers OQ-119 / OQ-174); tool-call intents are re-parsed from the durable response and yield the same `effect_id` (ADR-0027 derivation), so no duplicate intent exists.
4. **Four lease scopes, one fence.** `Lease{lease_id, scope ∈ {writer(run), effect(effect_id), resource(key), environment(handle), wakeup(subscription_id, occurrence_key)}, holder: HolderIdentity{host, pid?, start_id?, participant_ref, instance_id}, generation, acquired_at, expires_at, progress?}`; operations `acquire/renew(progress?)/release/probe_holder/takeover`. Invariants: L-1 the ledger refuses stale generations (`Fenced`, ADR-0026); L-2 ttl per scope is a manifest constant, renewal ≤ ttl/3, clocks non-Byzantine (ADR-0030 §6); L-3 writer-lease expiry triggers `restore(mode = takeover)`; L-4 an environment lease's expiry never destroys the environment before `verify_environment` runs under the new writer lease; L-5 reservations held under the lease convert or release at takeover (ADR-0040). **Liveness-probe shortening:** takeover before `expires_at` is permitted only when `probe_holder = dead` for a holder on the *same host* whose recorded `pid` is gone or whose `start_id` no longer matches (OpenHands `_owner_is_dead`; prime-agent `isLeaseOwnerAlive`); off-host holders wait for expiry; a paused-but-alive holder is defeated by the fence, never by the clock. Every transition is a `lifecycle.lease.*` event with `scope` (CF-280).
5. **Retry timers are ledger-derived.** `control.retry.scheduled{scope_id, attempt_no, not_before}` (WS-F2) is the timer; on restore `due()` recomputes every pending retry from the ledger; a retry whose scope has terminated is `skipped{scope_closed}`. Process memory is never the only copy of a timer (rejects Symphony §14.3 as the Core behaviour).
6. **Detached children.** On restore the runtime re-attaches to the helper session (`hello(resume_session_id)`, WS-E5) and reconciles every `detached_effect_ids[]` entry in `committed` to `observed | unknown | terminated`; a helper `preserve_until(ttl)` must satisfy `ttl ≥ writer_lease.ttl + recovery_grace` (answers OQ-252); terminals are written by the resuming writer, never by the helper.
7. **Contract surface** (language-neutral): `checkpoint, restore, acquire, renew, release, probe_holder, takeover, due, reconcile_detached`; failure modes `UnknownRun, SourceIncomplete, Fenced, Tampered, WouldBlock(active_holder), HolderUnknown, ManifestUnresolvable, DefinitionChanged`.

**T-LCD statement.** Satisfies T-LCD-06 (no IR entity changes; hosted participants declare `resume`), T-LCD-07 (`resume`/`interrupt` tri-state), T-LCD-08 (variants see the profile and accounting through `Cue.resumed`; no global), T-LCD-12 (all operations implementable out-of-process; the recovery driver is a kernel component but the executor and wakeup service are separate processes), T-LCD-15 (recovery metrics class-scoped, `n/a` for undeclared). Not applicable: T-01/-02/-03/-04/-10/-11/-13/-14 (no model-facing surface, lowering or comparison introduced). ADR-0024 ladder: ttl constants, `grace_ms` and deadline policy are MUST-data; the recovery procedure and fence are MUST-code.

Scope note (CF-285): R-2.2.3 stays C1/Should with a C0 stage note for the single-run recovery slice.

## Consequences

- WS-B1 adds `scope` to `lifecycle.lease.*` payloads and `cause`/`holder` to `lifecycle.run.resumed` (CF-280); WS-H6 lists `lifecycle.run.resumed` as audit-grade (already) and the recovery actions as ordinary audit-grade terminals.
- WS-F2 owns the deadline default confirmed here (OQ-119) and re-arms after `lifecycle.run.resumed`; WS-F1's `Cue.resumed` carries `recovery_decision` unchanged.
- WS-E5/B5 satisfy `ttl ≥ writer_lease.ttl + recovery_grace` for preserved children and expose `hello(resume_session_id)`.
- WS-K4 must make `restore` idempotent across the boundary (a client `resume` while a restore is in flight returns `WouldBlock(active_holder)`, Codex precedent).
- Every hosted participant declares `resume ∈ {declared, probed, unknown}`; recovery metrics render `n/a` for `unknown`.

## Reversibility

**medium** — the checkpoint view and recovery table are additive over ratified ADRs and can be changed by editing the table (an ADR amendment) without touching the ledger schema; changing the lease model (e.g. removing liveness shortening or collapsing scopes) costs a `lifecycle.lease.*` payload version bump and a battery re-run; abandoning phase-resolved restore for replay would contradict ADR-0028 and is not reversible without superseding it.
