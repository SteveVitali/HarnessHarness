# ADR-0007 — Adopt the LCD-trap test battery (T-LCD-01…15) as binding acceptance criteria

**Status:** ratified (Phase 0 synthesis, 2026-09-09). **Named artifact:** `research/registers/lcd-test-battery.md` (the citable copy of the battery; ontology §7 points to it).
**Owner workstream(s):** WS-L7 (author); enforced on WS-A3, WS-A4, WS-C3, WS-E2, WS-J6, and by extension WS-A5/J2 (component contracts), WS-I2/J3/J4/J5 (eval/experiment/results), WS-B1/I1 (event taxonomy), WS-L5 (plugin contracts) · **Phase:** 0 (defined) → 1–3 (enforced) · **Related:** ADR-0001; CF-001, CF-003; OQ-002, OQ-004, OQ-036, OQ-037, OQ-039; RK-02; R-2.1.2, R-2.1.3, R-2.3.3, R-2.5.2, R-2.10.6, R-2.9.2, R-2.10.3, R-2.10.4

## Context

The program's stated stance against the LCD trap is "stable semantic interface + model-conditioned compilation" (doc 3 §1.2), but a stance is not a check. The historical record of portability layers (AWT/WORA, S-154) and the counter-examples that avoided the trap (LSP S-152; ACP S-035; MCP S-153) show that the failure has three recognisable signatures — **feature intersection**, **untyped escape hatches**, and **silent loss on lowering** — and one known antidote — **capability declaration + verified probing + typed extension slots + per-target compilation**. Production harnesses already store the model-specific surfaces the trap would hide as data (codex `models.json`; OpenHands `ModelSpecificSection`; AutoGen `ModelInfo`; Cursor S-049), and already suffer assumption debt they detect only by inspection (S-047). Omnigent, hosting 23 harnesses, learned to declare and probe capabilities and to report unknowns as unknown rather than unsupported (S-118 `designs/harness-capabilities-bench-seam.md`). Without concrete tests, WS-A3/A4/C3/E2/J6 will each resolve CF-001/CF-003 differently.

## Options considered

1. **Leave the stance as a principle; rely on synthesis review.** Rejected: unenforceable across five workstreams and a Phase 5 coherence review that has no criterion to review against; the AWT lesson is that the trap is invisible until it is expensive.
2. **A single "round-trip a reference harness" test only.** Rejected: necessary but late (needs Stage 3) and non-diagnostic — it says *that* behaviour was lost, not *where*; misses the hosting-boundary failure entirely.
3. **A battery of static/schema, contract, and executable tests mapped to owners and build stages (chosen).** Fifteen tests (WS-L7 §6.3): T-01 model-specific tool shape without escape hatch; T-02 opacity budget; T-03 behavioural round-trip; T-04 two profiles × two targets; T-05 every conditioned rule expires; T-06 hosted participants never weaken native contracts; T-07 declare-verify-stratify, never intersect; T-08 component contracts receive the profile; T-09 interaction effects representable; T-10 names are surfaces, identities semantic; T-11 lowering lossless-or-declared-lossy; T-12 contracts are operations not inheritance; T-13 compliance observable separately from validity; T-14 no un-budgeted comparison; T-15 class-scoped metrics.

## Decision

1. The fifteen T-LCD criteria in WS-L7 §6.3 — lifted verbatim into `registers/lcd-test-battery.md`, which is the citable reference from now on — are **binding acceptance criteria**. Each owning subsystem's Spec §7.2 #5 section must contain an acceptance-criterion line that encodes its T-LCD tests, and the readiness report must carry a 15-row LCD matrix (test → subsystem section → criterion line → build stage → status).
2. Stage placement: T-01/-02/-06/-10/-12 are schema/static checks at **C0 Stage 1**; T-05/-08/-09/-14/-15 are contract checks enforced by compiler/engine preconditions at **C0 Stages 1–3**; T-03/-04/-11/-13 are executable checks at **Stage 3 (evaluation-first)**, which the build ladder must place before Stage 5 (profiles) and Stage 6 (evolution); T-07 lands with hosting (**C2**, Phase 3 design).
3. The compiler exposes `lcd_report(harness_def, profiles[], targets[]) → LcdReport` and treats `UnexpressibleSurface(entity, profile)` as a first-class **error**, never a warning; the experiment engine refuses un-budgeted arms (T-14) as a precondition; the metric registry carries `applies_to` (T-15).
4. `LcdReport` (opacity ratio, per-profile diff fields, lowering loss per target, conditioned-rule ledger, identity stability, hosting edges) is stored in the reproducible harness bundle (WS-I3).
5. Any future ADR that introduces an abstraction spanning models, targets or participants must state which T-LCD tests it satisfies and which it does not; a "does not" without a mitigating test is grounds for rejection at synthesis.
6. The battery applies reflexively: the profile compiler and the Hosting ABI each carry an assumption-debt record (T-05) so that convergence of model conventions, or of hosted-participant internals, triggers a documented descoping rather than dead weight.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** LCD mechanism and antidote — S-154 (AWT peer model limited to intersection; WORA decay), S-152 (LSP capabilities; unknown properties ignored; `experimental`; `$/`), S-035 (ACP v2: all capabilities OPTIONAL, omitted = UNSUPPORTED, `_meta` everywhere, `_` extension methods), S-153 (MCP prefixed `_meta`). Model-conditioned surfaces exist and matter — S-049 (patch vs string-replace by training), S-047 (dead-weight resets), S-062/S-072/S-088/S-148 (`provisional`, corroborating). Validity vs compliance separable — S-088 (`provisional (mech)`), doc 2 §1. Matched-budget necessity — S-083 (`provisional`, counter-evidence class), doc 2 §8.
- **(b) Source-code precedent:** openai/codex `codex-rs/models-manager/models.json` + `codex-rs/core/src/tools/spec_plan.rs` L1255–1258 (tool registered from profile data — T-01/T-08 pattern); OpenHands `openhands-sdk/openhands/sdk/context/prompts/sections/static.py` L480–500 (guarded family-keyed surface — T-10 pattern); omnigent `omnigent/harness_capabilities.py` + `designs/harness-capabilities-bench-seam.md` (declared vs probed; `None` → UNKNOWN — T-07); DSPy `dspy/adapters/base.py` L34–60 (semantic contract + per-model rendering — T-04 on one plane); AutoGen `autogen_core/models/_model_client.py` L164–183 (typed model capability record — T-05 shape, minus evidence/expiry). The *battery as a whole* and `LcdReport`/`UnexpressibleSurface` are `no-precedent / novel`.
- **(c) Disconfirming evidence considered:** (i) "You cannot test for the absence of an abstraction failure" — accepted; the battery is a floor built from the three known signatures plus a behavioural round-trip, and RK-02 stays open with Phase 2 validation. (ii) The battery could over-constrain the IR and push WS-A3 toward a bloated schema that types everything — mitigated by T-02 (opacity *budget*, not opacity zero) which permits typed text leaves, and by OQ-002 (WS-A3 sets the expressiveness ceiling). (iii) Model conventions may converge, making profiles redundant — reflexive T-05 makes that a documented descoping. (iv) Omnigent's registry proposal shows declared capabilities still leave imperative per-harness dispatch in the host — T-07 is necessary but not sufficient for J6; the ABI depth decision (OQ-004) remains J6's.
- **(d) Conditionality:** static and contract tests are unconditional; executable tests (T-03/-04/-13) assume the Stage 3 suite and event ledger exist and are evaluated on the coding/terminal domain first (sponsor choice); equivalence margins for T-03 must be pre-registered per suite and are model-tier dependent. No `provisional` number is load-bearing: the tests check *expressibility, declaration and reporting*, not performance.
- **(e) Build-stage assignment:** C0 Stage 1 (static), C0 Stages 1–3 (contract), Stage 3 (executable), C2/Phase 3 (T-07).

## Consequences

- WS-A3 must design identity derivation excluding surface fields (T-10), typed text leaves with provenance (T-02), and no per-model branches (T-01); WS-A4 must emit lowering loss reports and `UnexpressibleSurface`; WS-C3 must make profile schemas the sole owner of surface fields and require assumption-debt records; WS-E2 must demonstrate patch-vs-string-replace edit shapes from one capability; WS-J6 must adopt declare/verify/stratify and prove no upward edges; WS-I2/J3/J4/J5 must model factors, interaction effects, budgets and class-scoped metrics; WS-B1/I1 must add artefact delivered/activated/followed events; WS-A5/J2/L5 must pass the profile into every component-class contract and forbid inheritance-based contracts.
- The assumption-debt *record schema* becomes a C0/Stage-1 requirement even though the *manager* (WS-I6) is C4 — recorded in scope.md as a stage note on R-2.9.6 (no new item; Phase 0 synthesis).
- Phase 5 readiness cannot pass with any T-LCD row marked "not encoded".

## Reversibility

**High for individual tests, low for the battery's existence.** Any single test can be amended or dropped by a later ADR with a recorded rationale (e.g., if the opacity-ratio definition proves unmeasurable). Removing the battery altogether would leave CF-001/CF-003 with no enforcement mechanism and is the reversal this ADR exists to prevent; its cost is the re-emergence of the LCD trap discovered, as in AWT, only after downstream tiers depend on the abstraction.
