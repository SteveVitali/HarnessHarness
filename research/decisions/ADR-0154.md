# ADR-0154 — The experiment definition: `ExperimentSpec` as content-addressed data; closed design kinds with declared generators and resolution; pure `expand` into a cell plan with content-derived run-plan ids; the `experiment` layer rule (OQ-076); non-portable pinned definitions (OQ-078); and the registration refusal set (T-LCD-09/-14/-15 as engine preconditions)

**Status:** ratified
**Owner workstream(s):** WS-J3 (consumers: WS-J4, WS-J5, WS-I5, WS-K1/K2/K4, WS-J1/J2, WS-J6) · **Phase:** 3 · **Related:** ADR-0007 (T-LCD-09/-14/-15), ADR-0013 (admissible granularities), ADR-0024/0025 (MUST-data; `experiment` layer; override grammar; `compose → resolve → validate_assembly → seal`), ADR-0036 (`configuration_id` / `configuration_version_id`), ADR-0037 (amendment by supersession), ADR-0041 (`MatchSpec`, refusal semantics), ADR-0045 (`Design`, `PreRegistration`, `Arm`, replicate axis), ADR-0046 (`eval_budget`/`search_budget`, `LeakedSplit`), ADR-0128 (`cache_policy`), ADR-0143 (`SplitAssignmentRecord` before search), ADR-0077/0105 (exemplars); OQ-076, OQ-078, OQ-121, OQ-124, OQ-339; CF-108; R-2.10.3

## Context

Phase 1 ratified *what* an experiment reports (ADR-0045/0046) and *what "matched" means* (ADR-0041) but left the experiment as an abstract `Design` plus `Arm`s with no operational definition of how factors and levels become cells and runs, how a fractional design declares what it confounds, or which checks fire before any run opens. The source audit (WS-J3 §4) shows every batch runner derives its work list either as an ordered cartesian product (Harbor `build_trial_configs`, Hydra multirun, W&B `grid`) or as a filtered instance list (SWE-agent, mini-swe-agent, HAL), with resume decided by scanning outputs; only Inspect pairs planned work with prior logs through a versioned, content-derived `task_identifier`, and only Harbor refuses resume when the stored configuration differs. No audited runner plans a fractional design, refuses an un-budgeted comparison, or records the overrides that produced a configuration beside the definition's own request (Inspect's capture manifest is the partial precedent). ADR-0025 already fixed that experiment overrides are an `experiment` layer in a layered definition; OQ-076 asks whether that is *always* so.

## Options considered

1. **Adopt a sweep-configuration format from an existing tool (W&B/Hydra shape) and generate runs on the fly.** Rejected: no factor kinds, no participant class, no budget or split semantics, no pre-registration boundary; the plan would not exist before the first run, so pre-registration immutability (ADR-0045) could not be checked.
2. **Keep the experiment implicit in the results store (rows tagged post hoc with arm/experiment ids).** Rejected: T-LCD-14 requires refusal *before running*; a post-hoc tag cannot refuse.
3. **`ExperimentSpec` as content-addressed MUST-data with closed design kinds, a pure `expand` into a complete `CellPlan`, content-derived run-plan ids, the always-an-`experiment`-layer rule, and a typed refusal set at `register` (chosen).**

## Decision

1. **`ExperimentSpec` (dialect `hh-experiment/1`) is a data document** `{kind ∈ {comparative, exploratory, equivalence, retirement, reproduction}, design: Design (ADR-0045), pre_registration (required unless exploratory), factors: [FactorSpec{kind ∈ six ratified kinds, granularity?, role?, levels: [LevelSpec{level_id, ref, overrides?, label, class, non_portable?}]}], arms: [ArmSpec{arm_id, hypothesis, level_assignment, eval_budget, search_budget, match_spec (with cache_policy), artifact_ref, model_role_table_ref}], suite: SuiteBinding{suite_ref, split_labels_used, split_assignment_ref?}, replicates_per_cell, seed_policy, validation_strategy, scheduling, reattempt, budgets{experiment, instrument}, bundle_policy, ext}`; `experiment_id = H(canonical(spec))` under the pinned identity profile; the spec is immutable after `register`; amendment is a new spec with `derived-from{amendment}` (ADR-0037).
2. **Design kinds have fixed operational semantics.** `full_factorial` = cartesian product of level sets; `fractional_factorial` requires `generators[]` and `resolution ∈ {III, IV, V}` and is refused (`ResolutionInsufficient`) when the pre-registration names an effect the resolution cannot estimate unconfounded (any two-factor interaction requires ≥ IV; mutually unconfounded two-factor interactions require V); the aliasing table is part of the plan; `paired` = one varied factor, pairing by task; `one_factor_at_a_time` = a base cell plus single-level perturbations; `adaptive_search` = search-split arms chosen by a `ValidationStrategy` inside `search_budget`.
3. **`expand(spec) → CellPlan` is pure and total.** It yields `cells[(cell_id, arm_id, configuration_id, configuration_version_id, task_id, split_label)]` and `run_plans[RunPlan{run_plan_id = H(experiment_id ∥ arm_id ∥ configuration_version_id ∥ task_id ∥ replicate_index), replicate_index, seed_material, environment_derivation = fresh_from_image, cache_scope_salt}]` plus an `OrderPlan{permutation_seed, blocks}`; the plan is content-addressed and exists before any run opens. Scheduling and transport fields never enter `run_plan_id` (Inspect precedent).
4. **Every configuration in a plan is sealed through ADR-0025 with an `experiment` layer.** `compose(layers + {fragment: overrides, provenance: LayerProvenance{source_kind: experiment, id: experiment_id}}) → resolve → validate_assembly → seal`; **OQ-076 is answered "always"**: an ad-hoc override issued from a surface (CLI/SDK/web) is an implicit `exploratory` experiment of one cell, so attribution can always name the override.
5. **Pinned profiles are non-portable, not silently re-lowered (OQ-078, J3 half).** A definition whose `profile_binding` pins one profile is admissible only with `non_portable = true` and only in arms where the profile is not the varied factor; placing it in a cross-profile factor is refused (`ProfilePinnedAcrossProfiles`).
6. **Registration refuses, never warns.** `register(spec) → experiment_id | Refusal` with the closed refusal set `{MissingMatchSpec, UnbudgetedArm, UnmatchedBudget, IncommensurableMatch, MissingPricingTable, InadmissibleFactor, MissingPreRegistration, SplitUnassigned, LeakedSplit, UnsealedArtifact, InsufficientReplicates, ResolutionInsufficient, ProfilePinnedAcrossProfiles} ∪ {every validate_assembly/seal error per cell}`. `exploratory` experiments run without `MatchSpec`/`PreRegistration` and every row they produce carries `comparable = false`, which `compare` (ADR-0046) rejects — the ADR-0041 (c) "run but never report" line, made a schema fact.
7. **Engine defaults are data, not constants.** `tolerance = 0.10` per dimension (OQ-124 placeholder), `replicates_per_cell ≥ 5` for the Stage-3 exemplars (OQ-121/OQ-339 input), `cache_policy = cold_start` (ADR-0128), `order = interleaved_blocked` (ADR-0155) live in packaged-default layers and are overridable per experiment with the override recorded.

**T-LCD statement (ADR-0007 decision 5).** Satisfies **T-LCD-09** (six factor kinds explicit; rows keyed by the full tuple; interaction-estimability checked against design resolution), **T-LCD-14** (`MatchSpec`/`eval_budget`/`search_budget` mandatory on comparable arms; refusal at `register`; `comparable = false` rows never enter a comparison), **T-LCD-15** (`InadmissibleFactor` for hosted levels at component granularity; class stamped on every level), **T-LCD-06/-07** (hosted levels reference a participant descriptor and its capability vector; no native entity changes), **T-LCD-05** (the `retirement` kind is the "delete this rule" recipe), **T-LCD-10** (levels reference semantic ids; labels are surface), **T-LCD-12** (operations over canonical documents). Not applicable: T-01/-02/-03/-04/-08/-11/-13 (no model-facing surface or lowering introduced; T-03 is executed by the `equivalence` kind under ADR-0046's operation). **ADR-0024 rung:** `ExperimentSpec`, levels, policies and defaults are MUST-data; `expand`, `run_plan_id` derivation and the refusal checks are MUST-code.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: doc 2 §8 ("treat model, harness, environment image, task, resource budget, and random seed as explicit factors"; "freeze versions and release them together"; paired/factorial comparisons); fractional-factorial theory — generators, defining relation, aliasing, resolution, sparsity of effects (S-506, Tier A: Montgomery 2013; Box, Hunter & Hunter 2005); pairing and clustering by task (S-234, Tier C via I2); budget × harness interaction and search/artifact separation (S-072, S-083 — `provisional`, consumed through ratified ADR-0046); shared environments/budgets/protocols as the benchmark norm (S-062, `provisional (mech)`); sweep definition as data separate from execution (Hydra sweeper/launcher S-507, W&B sweep config S-505 — production, Tier B). No `provisional` number is load-bearing; the C0 slice rests on ratified ADRs, Tier-A theory and pinned-commit audits.
- (b) Source-code precedent: inspect_ai @75f4891 `src/inspect_ai/_eval/evalset.py` L2019–2075 (`task_identifier` — versioned, content-derived work identity excluding transport options), L1943–1975 (prerequisites: unique identifiers; log dir owned by the set), `eval_set_manifest.py` L125–140 (definition vs overrides captured separately); harbor @7d5285b `src/harbor/job.py` L254–262 (config-equality refusal on resume), `job_plan.py` L140–165 (agents × tasks × `n_attempts` plan); SWE-agent @3ea751c `sweagent/run/batch_instances.py` L67–85 and mini-swe-agent @04d809c `src/minisweagent/run/benchmarks/swebench.py` L180–197 (seeded shuffle, filter, slice as the instance-selection grammar); Hydra multirun (S-507) and ADR-0025's override grammar. **`no-precedent / novel`:** a content-addressed experiment plan over the six ratified factor kinds with declared generators/resolution and an engine-level refusal set; the always-an-`experiment`-layer rule; non-portable exclusion of pinned definitions.
- (c) Disconfirming evidence considered: (i) strict registration slows exploration (W&B/Hydra impose nothing) — answered by the `exploratory` kind with `comparable = false`, matching ADR-0041 (c); (ii) fractional designs are rare in agent evaluation and categorical multi-level factors do not fit `l^(k−p)` neatly — answered by admitting two-level generators at C1 and recording the multi-level orthogonal-array question (OQ-361); (iii) content-derived run-plan ids break when the identity profile rotates — answered by ADR-0036's rotation procedure and Inspect's versioned identifier precedent (recompute on version change); (iv) pinned-profile exclusion reduces cross-profile coverage — accepted: a definition valid under one profile is by definition not a cross-profile subject, and hiding that would violate T-LCD-04's intent. None overturns.
- (d) Conditionality: independent of model tier and task class; assumes ADR-0025 sealing and ADR-0036 identity are available at Stage 1; fractional designs assume sparsity of effects, which the pre-registration must state; hosted levels assume WS-J6's capability vector (C2).
- (e) Build-stage assignment: **C0 / Stage 1** — `ExperimentSpec`/`CellPlan`/`RunPlan` schemas, `run_plan_id` derivation, refusal codes as schema constraints; **C0 / Stage 3** — `register`/`expand` with the full refusal set, the `experiment` layer rule, the two exemplars; **C1 / Stage 4–5** — `fractional_factorial` with aliasing tables, `retirement`/`equivalence` kinds; **C2 / Stage 4** — hosted levels; **C4 / Stage 6** — `adaptive_search`.

## Consequences

- WS-J5 keys rows by `(configuration_version_id, run_id)` and carries `experiment_id, arm_id, cell_id, replicate_index, attempt_no, comparable`; WS-J4 consumes `OrderPlan`, aliasing tables and `provider_drift` strata.
- WS-K1/K2/K4 surfaces create experiments through `register` only; an ad-hoc override creates an implicit exploratory experiment (OQ-076 closed).
- WS-A5/J1 confirm that `compose` accepts an `experiment` layer with `id = experiment_id`; WS-C3 confirms the `non_portable` reading of pinned `profile_binding` (OQ-078 closed on the J3 side).
- WS-I5 inherits `adaptive_search` and the `SplitUnassigned`/`LeakedSplit` refusals; WS-I3 receives `results.design/pre_registration/arm/match_spec/search_budget` members from the plan.

## Reversibility

**High for the schema, medium for stored plans.** Fields and design kinds are additive; relaxing a refusal to a warning is a one-line policy change that would re-admit un-budgeted rows into the results store (the cost ADR-0041 exists to avoid); changing `run_plan_id` derivation requires recomputing persisted plans under the identity-profile rotation procedure.
