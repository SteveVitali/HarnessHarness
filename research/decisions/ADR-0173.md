# ADR-0173 — One serving path for the MCP server: a K3 server instance serves exactly one compiled bundle's MCP target; the Lab catalogue is the MCP artefact of a sealed **exposure definition** whose `ToolCapability` entities wrap Lab operations by identity; composition only by sealed slots; no server-minted view handles

**Status:** ratified
**Owner workstream(s):** WS-K3 (consumers: WS-J6, WS-K4, WS-K1, WS-E3, WS-E4, WS-A4, WS-L5, WS-L6) · **Phase:** 3 · **Related:** ADR-0019 (closed-world rule; `CompiledBundle.target_artefacts`), ADR-0021 (MCP tool-surface document, C0/Stage 3), ADR-0023/0025 (definition is data; `compose → resolve → validate_assembly → seal`), ADR-0024 (MUST-code / MUST-data), ADR-0090/0092 (surface families; `ResultRenderSpec`), ADR-0093/0094 (exposure modes; discovery capability), ADR-0096 (one tool-supply channel), ADR-0097 (stateless canonical catalogue per bundle; K3 Lab operations as handle-carrying tools), ADR-0038 (`InstrumentRecord`), ADR-0050 §8 (layer placement), ADR-0007 (T-LCD-04/-06/-10/-11/-12); CF-206, CF-365, CF-366, CF-368, CF-369; OQ-247, OQ-393, OQ-400; R-2.11.3, R-2.5.4, R-2.10.6

## Context

ADR-0097 fixed that a K3 server's `tools/list` is a pure function of `bundle_id`, fires `listChanged` only on bundle change, and that "K3's Lab operations are ordinary tools whose run identity is a server-minted handle argument" — but left open *what artefact* the Lab operations' tool definitions come from. Every audited product that exposes its own capabilities over MCP hand-writes a tool router separate from its model-facing tool definitions: goose's built-in servers (S-112 `crates/goose-mcp/src/lib.rs`, `mcp_server_runner.rs`), the Claude SDK's in-process server from decorated functions (S-109 `src/claude_agent_sdk/__init__.py` L491–560), Inspect's `BridgedToolsSpec` (S-136 `tool/_mcp/_tools_bridge/bridge.py`), and Codex's non-MCP app server with 150+ bespoke methods (S-107 `app-server-protocol/src/protocol/common.rs`). Two definitions of one tool — with the name as the only shared identity and no loss report between them — are the T-LCD-10/-11 failure signatures WS-E4 recorded for foreign tools (negative result iv). The 2026-07-28 spec forbids per-connection variation of list results and says caches "MUST NOT" be relied on for access control (S-153 `server/tools.mdx` L62–71; `server/utilities/caching.mdx` L173–179), so a server that served a per-caller union of catalogues could not be both cacheable and correct. HarnessHarness already compiles one tool-document kind per bundle (`lower_target(bundle, mcp)`), and every Lab operation exists as a language-neutral operation record with typed refusals (WS-J1 §6.2, J2 §6.2, J3 §6.3, J4 §6.2, J5 §6.6).

## Options considered

1. **Hand-written Lab server** (goose / Claude SDK / Inspect shape): a tool router per Lab operation, names as identity. *Rejected:* a second tool-definition path outside the compiler and outside the tool-interface compiler's `SurfaceArgMap` (ADR-0022 E2 — the reference monitor could not evaluate Lab-tool proposals on capability parameters); renames change identity (T-LCD-10); no loss report (T-LCD-11).
2. **A bespoke JSON-RPC Lab protocol** with an MCP shim (Codex app-server shape). *Rejected:* non-goal N5 (ADR-0006); ACP already is the session boundary (ADR-0096) and the internal boundary (WS-L1 §6.5) already exists; a third verb set triples the lowering tables.
3. **One multiplexing server serving many bundles under namespaced names, narrowed per caller.** *Rejected:* violates SEP-2567 list invariance and `cacheScope` safety; namespacing is name-as-identity (goose `owner__name`, gemini-cli `mcp_<server>_<tool>` — WS-E4 4c negative precedents).
4. **Server-minted view handles** (a tool returning a narrowed sub-catalogue) for deferred loading (OQ-247). *Rejected for K3:* the closed-world rule already places selection in the consuming harness (`select_surfaces`, ADR-0019/0093; CF-206); a view would need its own identity and cache scope; the ADR-0094 discovery capability, lowered to an ordinary tool, gives callers with small contexts the same effect without narrowing the list.
5. **Chosen:** one serving path `serve(bundle)`; the Lab catalogue is the MCP artefact of a sealed exposure definition; one instance ↔ one bundle; composition by sealed slots; exposure modes are the caller's concern; discovery as an ordinary tool.

## Decision

1. **One serving path.** `serve(bundle_ref, transport ∈ {stdio, streamable_http}, caller_binding_source) → ServerHandle{bundle_id, catalogue_hash, transport, protocol_binding, opened_at}` serves `CompiledBundle.target_artefacts[mcp]` of exactly one bundle: `DiscoverResult` and `ListToolsResult` (and, at C2, `ListResourcesResult`/`ListResourceTemplatesResult`) are byte-identical for every connection of that bundle, in canonical order, with `ttlMs`/`cacheScope` per ADR-0097 decision 1; `notifications/tools/list_changed` fires only when the served bundle is replaced. No tool reaches the wire by any other route (the MUST-code list gains "K3 catalogue serving"; adding a wire tool outside a bundle is a defect).
2. **Two bundle kinds, one path.** (a) A harness bundle's **supply surface**: its compiled tool surfaces minus `hidden` (ADR-0093 decision 1), served to a hosted participant (WS-J6 `HostedRunSpec.supplies.tools`) or another external agent; every `tools/call` is a native effect in the run named by the caller binding, executed by WS-E5 under the reference monitor with the caller as proposer; results rendered by the bundle's `ResultRenderSpec` (ADR-0092). (b) The **Lab catalogue**: the MCP artefact of an **exposure definition** — a sealed Harness Definition (ADR-0023 `Assembly` grammar) whose `ToolCapability` entities wrap Lab operations **by identity** (`semantic.purpose` names one operation record of WS-J1/J2/J3/J4/J5/B1/B3/H7; `input_schema`/`output_schema` are the operation's records; `effects` derived from what the operation does; surface fields owned by the exposure definition's profile binding). The canonical exposure definition `hh-lab/<n>` ships with each release and is pinned in the `InstrumentRecord` (ADR-0038); its tool groups and tiers are WS-K3 §6.3.
3. **Exposure definitions are data.** `ExposureDefinition = Assembly{dialect, profile_binding (default: the null profile — OQ-393), slots{lab_operations: [ToolCapability ref], supply_surfaces?: [bundle_ref]}, entities{Permission[], Budget[], HarnessRule[]}, policy: ExposurePolicy, caller_bindings: [CallerBinding], ext}`, sealed only through `compose → resolve → validate_assembly → seal` (ADR-0025) and compiled through `compile` (ADR-0019) with E1–E7 evidence per surface (ADR-0022; E4 `n/a{read_only}` for pure reads). Serving "Lab + this harness" together is a **sealed composition** (the harness bundle's surfaces as a slot of one exposure definition, one `bundle_id`), never a per-connection union.
4. **Identity and naming.** Every served tool carries `_meta["<hh-prefix>/hir"]{semantic_id, bundle_id}` (ADR-0021 minimum set; prefix per OQ-068); a Lab tool's `semantic_id` changes only when the wrapped operation's record changes; renames and description edits are profile edits of the exposure definition (T-LCD-10) and re-key the bundle (`listChanged`).
5. **Exposure modes are the caller's concern; no view handles.** The K3 server never narrows a list per caller or per run; a caller whose context cannot hold the catalogue uses `ListToolsResult` pagination and the `discover_surfaces` tool — the MCP lowering of the ADR-0094 discovery capability over the served catalogue, returning `IndexForm`s with `semantic_id`s. This closes the K3 half of OQ-247 (client-side `select_surfaces` suffices; CF-206 stands).
6. **Dependency direction and placement.** No HIR entity, ledger event class or operation record references the server; the server imports the compiled documents and the protocol schema only (ADR-0096 decision 5; T-LCD-06). Transport, caller resolution, catalogue serving and monitor interposition sit in the ADR-0050 **kernel layer** (an MCP server-role SDK exists there, ADR-0050 §8(b), S-155); Lab-operation handlers sit where the operations sit (ADR-0050 lab layer) and are reached over the D2 boundary as records — a `tools/call` crosses as the operation's input record and returns its output record.
7. **Tiers.** `serve(bundle)` over stdio for harness bundles: **C0 / Stage 3** (already required by ADR-0097 decision 7 to execute validators on the MCP target). The exposure definition `hh-lab/1` read/launch/experiment/results groups over stdio and Streamable HTTP: **C1 / Stage 4**. Analysis, write tools, `serve_bundle`, resources, tasks: **C2 / Stage 5**. R-2.11.3 stays C2 / Could; the C0/C1 slices are stage notes (CF-368).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: list invariance and cache-scope rules (S-153 `server/tools.mdx` L62–71, `server/resources.mdx` L74–83, `server/utilities/caching.mdx` L95–101, L173–179); "Stateful Tools" — cross-call state as explicit handles in ordinary arguments (S-153 `tools.mdx` L683–737); the compiled MCP artefact and its loss report (ADR-0019/0021; ADR-0097 decision 1); definitions as data and the only path to a sealed definition (ADR-0023/0025); exposure selection is client-side under the closed-world rule (ADR-0093 decision 7; CF-206); one discovery capability with per-target lowerings (ADR-0094); two-definition drift and name-as-identity as observed failure modes (WS-E4 4c negative precedents; negative result iv); poisoned tool metadata as an attack surface for *any* served catalogue (S-302 `provisional (mech)`, S-370 `provisional`, S-371 peer-reviewed) — hence descriptions are `definition`-authored `Text` leaves of a sealed document.
- (b) Source-code precedent: goose `crates/goose-mcp/src/lib.rs` L1–70 and `mcp_server_runner.rs` @fae91d0 (application capabilities as MCP servers over in-memory duplex and stdio — shape adopted, router mechanism rejected); claude-agent-sdk-python `src/claude_agent_sdk/__init__.py` L491–560 @ad77094 (in-process capability server; documented limits); inspect_ai `src/inspect_ai/tool/_mcp/_tools_bridge/bridge.py` L1–45 and `_sandbox.py` L54–120 @75f4891 (host tools supplied to a sandboxed agent via MCP — the supply surface); codex `codex-rs/codex-mcp/src/binding.rs` L30–100, L168–305 @0735c51 (a frozen catalogue revision bound to each call — adopted as the `(bundle_id, catalogue_hash)` stamp); omnigent `omnigent/inner/_acp_omnigent_mcp.py` @6a069da (via ADR-0096). The exposure definition — Lab operations as compiled `ToolCapability` entities served by the same path as harness bundles — is `no-precedent / novel`.
- (c) Disconfirming evidence considered: (i) every shipping product hand-writes its capability server and the compiled route adds E1–E7 obligations to operations with no model-conditioned surface — answered: the obligations are mechanical for record-shaped inputs and are exactly what makes renames profile edits and losses declared; the cost is one small definition per release. (ii) A multiplexing server is operationally simpler — answered: it breaks list invariance, `cacheScope` safety and AC-E4-2, and reintroduces name-as-identity; sealed composition gives the same operational result with one `bundle_id`. (iii) Large harness bundles may exceed an external agent's context — answered: pagination and the discovery tool exist; narrowing belongs to the consumer (ADR-0093). None overturns.
- (d) Conditionality: independent of model tier and task class; assumes MCP 2026-07-28 (with ADR-0097's legacy-era projection) through Stage 5; assumes the null profile (ADR-0125) is admissible as a `profile_binding` for surfaces no model consumes directly (OQ-393); assumes WS-J1/J2/J3/J4/J5 operation records ratify at Phase 3 in the shapes their dossiers give (tool schemas are derived from them); no `provisional` result is load-bearing.
- (e) Build-stage assignment: **C0 / Stage 3** decision 1 over stdio for harness bundles (ADR-0097's fixture server); **C1 / Stage 4** decisions 2(b)–6 for `hh-lab/1`'s read/launch/experiment/results groups; **C2 / Stage 5** analysis and write groups, `serve_bundle`, resources and tasks.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-04 (both bundle kinds are the MCP target exercised end-to-end), T-LCD-06 (decision 6; DAG check AC-E4-8 extended to the server), T-LCD-10 (decision 4; AC-K3-1), T-LCD-11 (the exposure definition's loss report; `lift(lower(exposure_def, mcp)) ∪ loss = exposure_def`), T-LCD-12 (the server is a separate process exchanging documents; AC-K3-11), T-LCD-02 (descriptions/instructions are `Text` leaves counted in the exposure definition's opacity ratio). Does not address T-LCD-03/-13 (ADR-0019/0026 obligations). **ADR-0024 rung:** `serve`, caller resolution, catalogue serving, monitor interposition are MUST-code; the exposure definition, its profile binding, `ExposurePolicy` and slots are MUST-data with `authority_cap`.

## Consequences

- WS-J6 supplies tools to hosted participants as `(bundle_id, profile_binding)` and writes the caller binding at `open` (CF-365; OQ-400); WS-K1 gains a `serve` verb over a bundle ref; WS-K4's generated client and K3's Lab catalogue wrap the same operation records (CF-363).
- WS-E3's `discover_surfaces` gains an MCP lowering over a served catalogue; WS-A4/C3 confirm the null profile as a legal `profile_binding` for exposure definitions.
- WS-L6 allocates the `_meta` prefix (OQ-068) before `hh-lab/1` is frozen; WS-L5 treats exposure definitions as a plugin-authored kind (third parties may ship their own).
- Scope register: stage notes on R-2.11.3 (C0 fixture; C1 Lab catalogue); tier unchanged.

## Reversibility

**High** for tiers and the tool groups (data); **medium** for "one instance ↔ one bundle" (a later multiplexing mode would need a new cache/identity rule and would re-key stored catalogue hashes); **low** for "no wire tool outside a bundle" (shared with ADR-0019's closed-world rule and ADR-0096 decision 1).
