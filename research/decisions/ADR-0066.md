# ADR-0066 — The audit trail is the run ledger read through `audit_view`: the audit-grade event catalogue with content-free envelopes, kernel-only producers and declared obligations

**Status:** **ratified, amended** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-H6 (consumers: WS-H1, WS-H3, WS-H4, WS-H5, WS-H7, WS-B2, WS-B3, WS-F2, WS-I2, WS-I5, WS-J5, WS-K2, WS-J6) · **Phase:** 2 · **Related:** ADR-0026, ADR-0027, ADR-0029 (ledger, ids, chain), ADR-0030/0031/0032 (effect lifecycle), ADR-0033/0034/0035 (provenance, endorsement bases, mandatory-provenance table), ADR-0016/0017 (`HirDiff`, `authority_delta`), ADR-0024 (audit is MUST-code), ADR-0042/0044 (`audit_view`, sink policy), ADR-0007 (T-LCD-06/-11/-12/-13/-15); CF-146, CF-147, CF-150, CF-151; OQ-176, OQ-092, OQ-128; R-2.8.6 (primary), R-2.8.1, R-2.8.3, R-2.8.7, R-2.2.1

## Context

The sponsor requires "deep audit trails at all levels" (R-2.8.6, C0/Must). Phase 1 fixed the substrate: the typed append-only run ledger is the sole authoritative record (ADR-0026), every event is hash-chained over a canonical form (ADR-0029), `audit_view` is a projection of it (ADR-0042/0044), the provenance record and the endorsement bases are mandatory on content-bearing and security events (ADR-0035). What Phase 1 did not fix is *which* events constitute the audit record, what each must carry so that it remains interpretable after redaction, who may produce them, and what an auditor checks for completeness. The source audit shows the gap in production: Codex's persistence policy treats approval requests, hook runs and automated-reviewer assessments as transient and routes the human's decision only to an optional telemetry sink (`codex-rs/rollout/src/policy.rs` L94–200; `otel/src/events/session_telemetry.rs` L1098); OpenHands persists rejections (`UserRejectObservation`) but not acceptances or the policy in force; both Codex (`ReviewDecision::*Amendment`, `ApprovedForSession`) and the Claude Agent SDK (`PermissionResultAllow.updated_permissions[]`) turn one approval into persisted authority outside any ledger. Independent 2026 designs converge on the same catalogue — intent, policy evaluation, human approval, execution, effects, context/code/delegation provenance (S-322); `tool_call, decision, delegation, escalation, error, lifecycle` (S-323) — and every item already exists in WS-B1's taxonomy as amended.

## Options considered

1. **A separate audit log written by an audit component** (the classic "audit subsystem"). *Rejected:* two books that drift (WS-I1 F1's goose/opencode reconciliation paths); duplicates identity; the ledger already is append-only and chained; ADR-0026 forbids a second authoritative record.
2. **Everything in the ledger is audit-grade; no distinction.** *Rejected:* measurement events (artefact exposure, metric emissions, cost rows) and content payloads are not what an auditor asks about, and treating them as audit-grade would force inline retention of large or judged content; it also hides the validity/compliance-vs-audit distinction WS-A2/I2 need.
3. **Audit-grade = whatever the security plane emits; content included by value.** *Rejected:* fails after redaction (envelopes would lose meaning), and leaves decisions/delegations/evolution edits (control, lifecycle, measurement planes) uncovered.
4. **A closed audit-grade class list across planes, each with a content-free `audit_fields` partition, a kernel-only producer set and declared obligations, read through `audit_view` (chosen).**

## Decision

1. **No second store.** The audit trail of a run is `audit_view(run)` over the run ledger (ADR-0026) plus the checkpoints of ADR-0067, which are themselves ledger events. No audit identity, sampling or write path exists outside `append`.
2. **Audit-grade classes.** The following classes are audit-grade (`durability = ledger` forced; may never be declared `ephemeral`): `control.decision`; `action.tool.proposed`; every `action.effect.*` phase (ADR-0030); `security.permission.decided / granted / revoked`; `security.label.applied / endorsed / declassified`; `security.policy.evaluated`; `security.credential.mediated`; `security.egress.attempted / blocked`; `security.extension.loaded`; `control.subagent.spawned / result / cancelled`; `lifecycle.run.created / finished / resumed / forked / rolled_back`, `lifecycle.head.moved`; `lifecycle.lease.*`; `lifecycle.escalation.raised / resolved` (**new class**); `control.budget.exceeded / amended`; `measurement.harness_edit.proposed / applied`; `context.memory.written / invalidated` (structural fields); `lifecycle.ledger.redacted`; `lifecycle.ledger.gc` (**new class**); `security.audit.checkpoint`; `measurement.export.delivered`; `model.call.requested / completed / failed` (structural fields); `lifecycle.hosted.native_record`. Adding or removing a class is a dialect bump. Not audit-grade: the `context.artefact.*` chain, `verification.*`, `measurement.metric.emitted`, `measurement.cost.attributed`, `context.assembled` item lists and every `ephemeral` class — they remain hashed leaves and are citable by `audit_ref`.
3. **Rule C — content-free envelope.** Every audit-grade class schema partitions its payload into `audit_fields` (inline, canonical, hashed, never offloaded, never redactable; only ids, hashes, closed enums, integers, `ContentAddress`es and provenance records — no `Text` leaf) and `content_refs` (`ContentAddress`es, redactable by tombstone). An `audit_fields` set that would exceed the class offload threshold is a schema error `AuditFieldsTooLarge`, never an offload. The dossier §6.1 table fixes the initial `audit_fields` per class.
4. **Rule P — producer.** `append` refuses an audit-grade event unless `producer.component_class ∈ class.producers` (kernel components: ledger, reference monitor, effect runtime/executor path, recovery, control envelope, orchestrator, credential mediator, egress policy, extension loader, model adapter, hosting adapter) **and** the event's provenance `authority = kernel` — failure `AuditProducerInvalid`. Deciders (`decider ∈ {policy, human, hook, cache, judge}`), proposers and endorsers are fields with their own provenance, never producers. A hook, tool, extension, model or hosted participant can cause an audit-grade event only through the kernel.
5. **Rule O — obligations.** Each audit-grade class declares `AuditObligation{id, class, quantifier, target_class, link_field, terminal_only?}` records evaluated by `audit_view.coverage`; the initial set: every non-`read_only` `action.tool.proposed` has exactly one `security.permission.decided` **or** an `action.effect.refused`; every `effect_id` closes with one terminal (ADR-0030); every `security.permission.decided{decision_scope ≠ once}` has a `security.permission.granted{scope}`; every `granted{authority_delta = widening, scope = persisted}` has a `lifecycle.definition.changed{diff_ref}` with human origin (ADR-0017); every `security.credential.mediated` references an `effect_id` with an `action.effect.*`; every `control.subagent.spawned` has a child `lifecycle.run.created{spawn_event, parent_anchor}` and a `result | cancelled` carrying the child head; every `action.effect.abandoned`, every `unknown` open at `finished` and every `control.budget.exceeded{hard}` has a `lifecycle.escalation.raised`; every `measurement.harness_edit.applied` has a `proposed` with `hypothesis_ref` and `evidence_refs`; every `security.label.endorsed` has a basis from the ADR-0035 list; every `producer.component_variant_ref` in the run resolves to a `security.extension.loaded` with a pin attestation or to a sealed-definition member. Obligations are MUST-data (`AuditPolicy.obligations`), versioned in the bundle.
6. **Permission decisions are complete records.** `security.permission.decided` carries `permission_id, proposal: EventRef, effect_id, requested_at, effective_risk_class, options_presented[], rendering_ref, decider, decider_ref, decider_provenance, decision ∈ {allow, deny, timeout, abandoned}, decision_scope ∈ {once, session, persisted}, rule_ref?, originating_permission_id?, wait_ms`. `security.permission.requested` may stay `ephemeral` (ADR-0026 policy table) **because** nothing audit-grade lives only there; a request that is never answered is closed by `decided{decision ∈ {timeout, abandoned}}` at timeout, abort or `finished` (resolves CF-146).
7. **Authority never widens silently.** Any change to permission rules in force — cached session approvals, persisted amendments, hook-installed allowances — is `security.permission.granted{scope, rule_ref, basis, endorser, authority_delta}` (or `revoked`); a persisted widening additionally appears as `lifecycle.definition.changed{diff_ref}` (CF-147). An `ask` resolution that raises a label produces `security.label.endorsed{basis = approval, basis_ref = permission_id}` **referencing** the `decided` event — one act, two linked events, one `permission_id` (CF-150).

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-12 (rules are record checks at `append`; `audit_view` is a pure projection; implementable out-of-process), T-LCD-15 (hosted rows carry the native envelope; obligations that need `ledger` observability render `n/a`), T-LCD-06 (no class or field exists for hosted participants), T-LCD-13 (the compliance chain stays measured, not audited, so the distinction is observable), T-LCD-11 (audit export is a WS-I1 lowering with a loss report). Not applicable: T-01/-02/-03/-04/-05/-07/-08/-09/-10/-14. **ADR-0024 rung:** Rules C/P/O enforcement is MUST-code; the class list is dialect schema; the obligation set is MUST-data.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** doc 2 §5.6 (S-130: "high-risk effects should be auditable even if the model or extension layer is compromised"; the monitor needs provenance, capability scope, policy, target effect, approval points) and §11 ("make every side effect attributable to a run and tool call"); Schneier & Kelsey S-315 (Tier A: per-entry *type* field with permission masks; the log must survive the machine's compromise — the producer/TCB separation); Crosby & Wallach S-316 (Tier A: audit semantics are defined by what an auditor can check); ADR-0035 (closed endorsement bases; approval endorses one `effect_id`); S-053 (~93 % approvals — why decision scope and decider must be recorded); S-103/S-104 (`provisional (mech)`: authority acquired by re-serialization/persistence — why persisted widening must be a ledger event); Agent Flight Recorder S-322 and IETF draft S-323 (`provisional`: independent convergence on the catalogue; "if an action bypasses the instrumented gateway, the recorder never sees it" — the producer rule's rationale). No provisional claim is load-bearing: every rule follows from ratified ADRs plus Tier-A sources.
- **(b) Source-code precedent:** Codex S-107 @0735c51 `codex-rs/rollout/src/policy.rs` L94–200 (persistence policy: approval requests, hooks, guardian assessments transient — the gap), `codex-rs/protocol/src/protocol.rs` L4074–4131 (`ReviewDecision` incl. `ApprovedExecpolicyAmendment`, `ApprovedForSession`, `NetworkPolicyAmendment`, `TimedOut`, `Abort` — the decision-scope and timeout fixture set), `codex-rs/otel/src/lib.rs` L44–48 + `otel/src/events/session_telemetry.rs` L1098–1125 (`ToolDecisionSource{AutomatedReviewer, Config, User}` — decider enum shape); OpenHands S-110 @3fc7b22 `openhands-sdk/openhands/sdk/event/llm_convertible/observation.py` L86–125 (`UserRejectObservation{rejection_source ∈ {user, hook}, action_id}` — a durable decision event with source and link); Claude Agent SDK S-109 @ad77094 `src/claude_agent_sdk/types.py` L109–255 (`PermissionUpdate` destinations; `PermissionResultAllow.updated_permissions` — persisted widening as approval side effect); Codex `otel/src/targets.rs` `log_only`/`trace_safe` split (via ADR-0044) as the content-free-field precedent. The audit-grade catalogue with Rules C/P/O as an integrated contract is `no-precedent / novel`.
- **(c) Disconfirming evidence considered:** Kiehl S-195 (more ledger machinery rarely pays); "audit needs the arguments" (content-free envelopes lose forensic detail); hooks legitimately decide today (Rule P looks like lost function). *Why not overturning:* the classes and fields already exist (ADR-0026 as amended) — this ADR adds constraints, not a store; arguments remain by `ContentAddress` until redaction and the envelope keeps `args_canonical_hash`, capability id, class, risk class, decider and outcome; a hook's decision is recorded with `decider = hook` — nothing a hook can do becomes impossible, only writing an approval the monitor never saw.
- **(d) Conditionality:** independent of model tier and task class. Assumes ADR-0035's producer/authority minting (only the runtime mints `kernel`) and ADR-0026's `producer` stamp. Assumes the offload threshold (64 KiB default) comfortably exceeds any `audit_fields` set (largest: `decided` with `options_presented[]`; bounded enums). For hosted participants the adapter is the producer and obligations needing `ledger` observability are `n/a`.
- **(e) Build-stage assignment:** C0 / Stage 1 (class list, `audit_fields`/`content_refs` partition, Rule P at `append`, completed `decided`/`granted` payloads, `AuditObligation` records evaluated in `audit_view`); C0 / Stage 2 (`lifecycle.escalation.*`, `lifecycle.ledger.gc`, coverage report wired to ADR-0068's completeness metric); C0 / Stage 3 (AC-H6-2/-3/-4/-5 in the suite); C1 / Stage 4 (hosted rows).

## Consequences

- WS-H1 emits `security.permission.decided/granted/revoked` with the fields above and treats hook/policy/cache decisions as `decider` values; WS-H7 owns timeout/abort closure and reports `permission_decisions_by_decider_and_scope`.
- WS-B2/F2/G2 emit `lifecycle.escalation.raised/resolved` for `abandoned`, open `unknown` at finish and hard budget exhaustion (answers the audit half of OQ-092: the escalation *record* is mandatory; whether it blocks completion stays G2/F1's).
- WS-H3/H4/H5 emit `credential.mediated`, `egress.*`, `extension.loaded` with the listed `audit_fields`; WS-I5 links `applied` to `proposed`.
- WS-B1's schema gains the `audit_fields`/`content_refs` partition and the two new classes; the persistence-policy table marks audit-grade classes non-overridable.
- WS-I2 imports `coverage_unmet_count` and the decision metrics; WS-K2 renders `audit_view` and refuses to show a redacted `content_ref` as absent-by-default.

## Reversibility

**Low-to-medium.** Relaxing Rule P or Rule C after Stage 2 silently reopens the Codex/Claude-SDK gap (unrecorded or unreadable approvals) and invalidates AC-H6-2/-3; adding classes or obligations is cheap (dialect bump / MUST-data).
