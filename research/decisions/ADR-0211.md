# ADR-0211 — Ratification of the organizational-layer deferrals D-1…D-6 (ADR-0207 D7) with entry tests for every item, including D-4 and D-6

**Status:** ratified (Phase 5 synthesis-authored deferral ADR)
**Owner workstream(s):** WS-L8 (D-1, D-2, D-3, D-5), WS-F4 (D-4), WS-F5 (D-6); Phase 5 synthesis · **Phase:** 5 · **Related:** ADR-0207 D5/D7 (as amended), ADR-0208 §D, ADR-0209 D2 (CF-464), ADR-0174 D6, ADR-0191 D1/D5, ADR-0193 D3, ADR-0188 D8, ADR-0190, ADR-0039 Phase-4 log (CF-445), ADR-0198; OQ-461, OQ-462, OQ-463, OQ-431; R-2.12.6, R-2.6.4, R-2.6.5; Spec §5i, §11.3

## Context

ADR-0207 D7 partitions the organizational layer into a C4 specification and six deferrals recorded rather than silent. Four carry entry tests (D-1 `PrincipalDirectory` by ADR with two out-of-process precedents; D-2 a tenant boundary as a `readers` partition with no new authority class; D-3 a pricing rule with a debt record and a `ComparisonReport{benefit_kind = artifact_benefit}` against the unit counter; D-5 AC-L8-06 with the procedure's effects recorded); two — D-4 dispatch prioritization by expected value and D-6 cross-item shared-state coordination — name only their owning workstream. Spec §11.3 flags both as gaps. Doc 3 §8 requires every deferral to be an ADR with an entry test; the phase-4 memo (§5, §6.3 item 5) instructs Phase 5 to ratify "one ADR for the six deferrals".

## Options considered

1. **Leave D-4/D-6 with "per R-2.6.4 / per R-2.6.5" as their tests.** Rejected: a deferral without an entry test is refused as a conditioned rule without a removal test is refused at `seal` (ADR-0197 D6; Spec §11.6 rule 1).
2. **Fold D-4 into R-2.6.4 and D-6 into R-2.6.5 as specified C3 mechanisms.** Rejected: neither owning ADR specifies the mechanism (ADR-0188 D8 keeps `SchedulingPolicy.order` as data with `declared(ref)` as the slot; ADR-0191 D1 fixes ownership per coordination object within one activation); specifying them here would invent decisions outside the ratified record.
3. **Ratify D-1…D-6 as deferrals with the four given tests verbatim and supply D-4/D-6 tests derived from their owning ADRs' existing gates (chosen).**

Every row is a `registers/spec-debt.md` entry with `removal_test{kind: revalidation_review}` and the entry test as `expiry_condition` (ADR-0198 D1). D-1…D-6 stay outside the build ladder (Spec §9.7; ADR-0209 D2).
