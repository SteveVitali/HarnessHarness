## Context

Thirty-one Phase 2 dossiers were written concurrently against the Phase 1 settled list (`synthesis/phase-1.md` §6). Their 94 proposed ADRs are individually sound and every one carries the doc 3 §3.3 five evidence fields and a T-LCD statement (verified at synthesis; `registers/lcd-test-battery.md` Phase 2 record). Where two dossiers touched the same seam they sometimes spelled one object two ways, pre-defined a neighbour's slot in that neighbour's absence (WS-H4/E5/I4 → WS-B5; WS-E2/E4 → WS-E1; WS-G2/G3 → WS-G1), or proposed an amendment to a ratified Phase 1 ADR that only synthesis may apply (doc 3 §7.1). The phase brief fixes the priority order: (1) the CF-006 convergence of H1/H2/D1/D4 on WS-L3's scheme; (2) the effect path B2 ↔ E5 ↔ H1 ↔ H4 ↔ B5; (3) the context chain D1 ↔ D2 ↔ D3 ↔ D4 ↔ C3 ↔ C4; (4) the compilation chain A4 ↔ C3 ↔ E2 ↔ E4 with the LCD battery applied to C3 and E2; (5) CONTROL (F1 resolves CF-005; F2's envelope agrees with L2's budgets and H7's approvals); (6) G1/G2/G3 verdict provenance into I2's grounding metrics; (7) no C0 ADR on provisional evidence; (8) every subsystem ADR states its C0 minimal variant and extension family. This ADR records the rulings that make the 94 ADRs one contract. The mechanics of each ruling live in the cited CF rows of `registers/conflicts.md` (CF-118…CF-310 workstream-flagged, CF-311…CF-321 synthesis-raised) and in the per-ADR amendment logs; this ADR states the composed result and the amendments to ratified text.

## Options considered

1. **Ratify each ADR as written and leave seams to Phase 5.** Rejected: Phase 3 (J1–J6, K1–K4, L5) builds the laboratory and surfaces on these seams; a Hosting ABI written against two spellings of `StopReason` or two `decider` sums would need re-work at every host.
2. **Reject the ADRs that pre-defined a neighbour's slot and re-run them.** Rejected: in every such case the neighbour adopted the pre-definition verbatim (WS-B5 adopted H4's containment slot and E5's handle operations; WS-C3 confirmed E2's reference-by-id; WS-G1's verdict record satisfies G2's `bind()` and G3's `build_evidence`), so a re-run would reproduce the same text.
3. **Rule seam by seam under doc 3 §7.1 (ontology is the tie-breaker; one declaration per seam per ADR-0048), amend ratified text only where a Phase 2 ADR is otherwise inexpressible, and record every ruling with its CF id (chosen).**

## Decision

**A. CF-006 closure — the authority scheme has one owner and four conforming consumers.**
1. ADR-0051…0053 (H1), ADR-0054…0056 (H2), ADR-0072…0074 (D1) and ADR-0081…0083 (D4) cite ADR-0033/0034/0035 and introduce no second class, label or lattice; ADR-0080 (D3) does not either. The only changes to the scheme are amendments to ratified text, applied by this ADR: ADR-0034 P3 — `context_label` is stamped by the **kernel** from the delivered-item list the builder variant returns (CF-118); items delivered `as handle` do not join the label (CF-311). ADR-0035 — check 3 domains gain `fs_write ∧ world = open` and `memory_write` to scope ≥ `project` (CF-124); the `pin` basis requires `attestation_status = verified` (CF-142); decision 3 gains `store ∈ {instructions, memory}` with the memory-store row (write ceiling `delegate`, label cap `external`/`environment`) (CF-172); `UnattendedPolicy ∈ {deny, defer, auto_review}` with `auto_review` an admissible `policy_rule` issued by the sealed definition and the reviewer verdict a raise-only input (CF-154, CF-119); `security.label.endorsed{basis: approval}` carries `basis_ref = permission_id` (CF-150); every persisted approval is a `security.permission.granted{scope}` event (CF-147).

## T-LCD statement

Every ruling above removes a per-model, per-target or per-participant branch rather than adding one: one `decider` sum, one `StopReason` sum, one request document, one role table, one verdict record (T-LCD-01, -10, -13); every closed sum that grows does so by dialect bump with the `ext` rule intact (T-LCD-02, -05); `n/a` stays a first-class value in `audit_completeness` and the stratified views (T-LCD-15); unknown protocol data is preserved at edges and rejected at the ecosystem boundary (T-LCD-07). Executable at Stage 3 through the C3/E2 fixtures recorded in the battery.

## Evidence

- **(a) Mechanism:** each ruling is a consequence of a ratified ADR applied to two dossiers' text (ADR-0019 closed-world rule → kernel stamps the label; ADR-0026 one-declaration-per-seam → one verdict record; ADR-0015 dialect rule → every sum growth); no ruling rests on a new empirical claim.
- **(b) Precedent-or-novel:** ADR-0048 is the Phase 1 precedent for this form; the seam rulings mirror what the audited systems do in code (Codex and OpenHands single approval-decision records; Pi/Codex single stop-reason enums) expressed as data.
- **(c) Disconfirming evidence:** none found; the only tensions (H2 quarantine vs D1 label reset; H1 vs H7 `decider`; C2 vs C3 role tables) were resolved without changing either party's substance. If Stage 3 shows that handle-delivered items *do* leak content into model context through renderers, CF-311's ruling reverts to "everything in the `external` slot joins".
- **(d) Conditionality:** the amendments to ADR-0026 and ADR-0035 assume WS-B1's persistence table and WS-L3's scheme as ratified; a Phase 3 Hosting-ABI finding that a host cannot carry `security.permission.pending` durably would reopen CF-152 (not the scheme).
- **(e) Build-stage:** C0 / Stage 1 for the spellings and the kernel-stamp rule; Stage 3 for the executable checks; the amended enums land in the HIR/1 dialect at the next schema publication.

## Consequences

Phase 3 briefs cite this ADR and `synthesis/phase-2.md` §6 as binding; the ontology is at **v2**; 21 Phase 1 ADRs carry Phase 2 amendment logs; the LEDGER ADR index marks them `ratified, amended (P2)`.

## Reversibility

Each ruling is reversible by a superseding ADR naming the CF row; the amended Phase 1 ADRs keep their Phase 1 text intact above the log, so a reversal is a log entry, not a rewrite.
