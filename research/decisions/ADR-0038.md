# ADR-0038 — Reproducibility levels R0–R3, the reproducible harness bundle as a lock manifest, and identity keys for the results store and audit

**Status:** **ratified, amended** (Phase 2 synthesis, 2026-09-10); previously: **ratified** (Phase 1 synthesis, 2026-09-10)
**Owner workstream(s):** WS-L4 (consumers WS-I3, WS-I2, WS-J3, WS-J5, WS-H6, WS-C1, WS-C3, WS-B5, WS-J6) · **Phase:** 1 · **Related:** ADR-0001/0004/0005 (two participant classes; class-scoped metrics), ADR-0007 (T-LCD-09/-14/-15), ADR-0026/ADR-0028/ADR-0029 (rebuildability; deterministic replay as declared capability; canonical form), ADR-0025 (sealed definition, `registry_snapshot_id`), ADR-0036; OQ-074, OQ-082, OQ-111/-04/-05; CF-087; R-2.12.1, R-2.9.3, R-2.10.5, R-2.8.6

## Context

Doc 2 §8 asks for a "reproducible harness bundle" — model snapshot, harness commit, profile, instructions, tool schemas/versions, skills, environment image, permissions, context/memory policies, budgets, grader code, task data, raw traces — "analogous to a containerized benchmark submission", and insists on distributions, matched budgets and separating search-time from artifact benefit. WS-B1 established that durability at Core is event *reconstruction* and that deterministic control-loop replay is a declared capability of some variants, not a Core invariant (ADR-0028). The audit found the two evaluation harnesses with real lock files (Harbor `JobLock`/`TrialLock`; Inspect `EvalSpec`/`EvalRevision`) converge on per-input digests, a schema version, the instrument's own version and source commit, and a lineage pointer — and that both leave the container image as a tag, the agent/task version as a string, and the provider-side model as a name. Reproducible-builds defines "bit-by-bit identical … given the same source, build environment and build instructions"; SLSA records `resolvedDependencies` by digest; Nix separates input-addressed from content-addressed outputs. A single binary "reproducible: yes/no" would therefore either be always false (stochastic re-execution) or always vacuous.

## Options considered

1. **Binary reproducibility flag on runs.** *Rejected:* vacuous for stochastic systems; hides which inputs were unpinned.
2. **Trajectory-interchange bundle only** (ATIF-shaped traces + job config, Harbor/HAL style). *Rejected as the native form:* ADR-0005 keeps the ledger native and typed; the interchange export is an I3/J6 obligation, not the bundle's identity; it does not carry profile, permissions, policies or provenance (WS-A1 §6.3 "novel only in bundling…").
3. **Full environment/model snapshotting at every run** (attempt bit-exact re-execution). *Rejected:* provider-side models cannot be content-addressed by us; the cost is unbounded; WS-B1 F8 shows no audited harness replays deterministically.
4. **Ordered reproducibility levels with explicit pinning requirements, declared per bundle; the bundle as a lock manifest whose members are content-addressed and whose unpinned members are explicit claims (chosen).**

## Decision

1. **Levels.** **R0 recorded**: every consumed input is content-identified or listed as an explicit `unpinned[]` claim and raw traces are present; `check_completeness = ok`. **R1 bit-exact (derivation)**: every derived object (views, summaries, effect ledger, results rows, opacity/LCD reports, the bundle manifest itself) re-derives from the recorded ledger to equal hashes; for variants declaring `deterministic_replay`, the `control.decision` sequence too (WS-B1 AC-B1-3/-4 lifted to the bundle). **R2 semantic (re-execution)**: re-running the pinned `configuration_version_id` with the recorded seed yields equal validator verdicts and end-state class; requires `ModelSnapshotRecord.pinned = true`, environment image by digest, tools/skills/validators pinned, `NondeterminismDeclaration[]`; verified by paired re-runs against a pre-registered margin with the validator set named in the `ReproReport`. **R3 statistical**: metric distributions over `n ≥ k` seeds equivalent within a pre-registered margin under matched `search_budget`/`eval_budget` (T-LCD-14); the model may be unpinned but must be named with an `observed_fingerprint` recorded before and after. Rules: a bundle declares `claimed_level`; a claim exceeding what its pins allow is `ReproClaimUnsupported`; `pinned = false ⇒ claimed_level ∈ {R0, R1, R3}`; levels a participant class cannot supply are reported `n/a`, never 0 (T-LCD-15); hosted participants claim R0/R3 and R2 only when their mechanism supplies `end_state`.
2. **Bundle = lock manifest** (`BundleManifest`, dossier §6.5): a versioned record whose `version_id` is the bundle id, with sections `subject` (run ids, head hashes, lineage), `definition` (sealed definition `version_id` + `semantic_id`, dialect, validation/LCD/opacity reports), `configuration` (both configuration ids, seed, budget, profile, `EnvironmentRecord{image digest | foreign_digest, build context tree, snapshot refs}`, permissions, policies), `resolved_dependencies` (variant-record closure, `registry_snapshot_id`, name bindings, tools with per-profile surface hashes, procedures/skills, text leaves, compiled payloads + trust records, validators/graders, `TaskDataRecord{manifest, tree, foreign_digest?}`, extensions + signatures), `model` (`ModelSnapshotRecord{provider, model_id, snapshot_id?, pinned, provenance = reported, observed_fingerprint?}`), `instrument` (`InstrumentRecord{version, source_commit, dirty, component_versions, idp}`; `dirty = true ⇒ claimed_level = R0`), `traces` (canonical ledger export, blobs, audit tree head, attestation), `results` (rows, metric declarations), `reproducibility` (`claimed_level`, `ReproReport?`, `unpinned[]`), `ext`. Invariants: every member is a `version_id`/`ContentAddress` or an explicit unpinned claim; `check_completeness` fails on any run-manifest reference missing from `resolved_dependencies`; the manifest is a Merkle tree over member addresses; export materializes fork lineage (WS-B1); `registry_snapshot_id` is over the referenced closure (OQ-074), a `catalog_id` may be recorded as a claim.
3. **Results store keys (WS-J5):** row key `(configuration_version_id, run_id)`; aggregation by `configuration_id` and the explicit factor tuple (T-LCD-09); every row carries `bundle_ref` and `claimed_level`; `depends_on_revoked` rows are annotated; leaderboards never key by name alone.
4. **Audit keys (WS-H6):** ledger `ir_refs[]` carry `{semantic_id, version_id}` (WS-B1); the attestation subject is the bundle manifest `version_id` (SLSA `subject.digest`); rotation checkpoints per ADR-0036.
5. **Operations:** `bundle`, `check_completeness`, `reproduce(bundle, level, seeds?)` → `ReproReport{level, verdict, per_member_hash_checks, validators[], distributions?, nondeterminism_sources[]}`; `reproduce` refuses unmatched budgets.

**T-LCD statement.** Satisfies T-LCD-14 (`reproduce` and the bundle carry per-arm budgets and refuse unmatched comparisons), T-LCD-15 (levels are class-scoped; `n/a` never 0), T-LCD-09 (results keyed by the explicit factor tuple, never by harness or model alone), T-LCD-11 (foreign digests and lowering loss reports are bundle members, never dropped), T-LCD-06 (no bundle member exists only for hosted participants; `participant_version` is an `OpaqueProcess` claim defined by WS-A3). Not addressed: T-01…05, T-07, T-08, T-10 (adr-1), T-12/-13.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** bit-exact reproducibility as a property of derivation from recorded inputs — reproducible-builds definition (S-181), Nix input- vs content-addressing (S-225), SLSA `resolvedDependencies` by digest (S-223); durability = reconstruction, deterministic replay = declared capability — WS-B1 F8/adr-3 (Temporal S-193, Codex/OpenHands/Pi source); distributions and matched budgets — doc 2 §8, S-083 (Tier B/C); model drift under fixed harness — S-047, S-049 (Tier B); provider identity recorded as a claim — Codex `models.json`, Harbor `ModelInfo`, Inspect `EvalSpec.model` (S-107/S-132/S-136); lock-file convergence — Harbor `JobLock`/`TrialLock`, Inspect `EvalSpec`/`EvalRevision{dirty}` (S-132/S-136); environment fork feasibility by content hash — Shepherd (S-078, `provisional`, mechanism only).
- **(b) Source-code precedent:** harbor `src/harbor/models/job/lock.py` @7d5285b (`JobLock{schema_version: 3, harbor{version, git_commit_hash, is_editable}, trials[]}`, `TrialLock{schema_version: 2, task{digest}, skills[{digest}], extra_instructions[{digest}], environment, verifier, source_trial}`), `src/harbor/skills.py` L214–223, `src/harbor/publisher/packager.py` L83–95, `src/harbor/models/dataset/manifest.py` L245–262 (tree/dataset digests), `src/harbor/models/trial/result.py` L53–97 (`AgentInfo{version: str}`, `TrialResult{task_checksum}`); inspect_ai `src/inspect_ai/log/_log.py` L993–1100 @75f4891 (`EvalRevision{commit, dirty}`, `packages`, stable derived `eval_id`), `src/inspect_ai/_util/git.py` L31–56; codex `codex-rs/protocol/src/protocol.rs` L3050–3100, L3220–3250 @0735c51 (`cli_version`, per-turn model/sandbox/permission context). **`no-precedent / novel`** for: declared, class-scoped reproducibility levels with pin-derived maximum claims; a bundle carrying profile, permissions, policies, provenance, LCD/opacity reports and both configuration ids (consistent with WS-A1 §6.3 "novel only in bundling model profile + permissions + policies + provenance").
- **(c) Disconfirming evidence considered:** "semantic reproducibility" may be mistaken for reproducibility while hiding unobserved behavioural differences; Harbor and Inspect ship useful science with images as tags and versions as strings, so full pinning may be unnecessary; the model-fingerprint probe is a heuristic that can miss drift; bundles of full ledgers and blobs are large. *Why none overturns:* R2 is subordinate to R1 in the ordering and must name its validator set, so its scope is visible; partial pinning is legal and is exactly what the `unpinned[]` list and the level cap make explicit rather than forbid; the fingerprint is evidence of drift, never identity (N7), and a missed drift degrades an R3 claim to a documented risk, not to a false R2; size is bounded by WS-B1's offload/GC tiers and by Merkle partial verification (OQ-112).
- **(d) Conditionality:** R2 is achievable only for providers that expose pinned snapshots and for environments with digest-addressable images (coding/terminal environments first, per sponsor domain choice); the R2/R3 margins are pre-registered per suite (OQ-113, with WS-I2); hosted participants' maximum level depends on their observability level (ADR-0005).
- **(e) Build-stage assignment:** **C0 / Stage 1** (both configuration ids in the run manifest; `InstrumentRecord`; results row keys); **C0 / Stage 2** (`EnvironmentRecord` digests with WS-B5; `ModelSnapshotRecord` + fingerprint probe with WS-C1); **C0 / Stage 3 (evaluation-first)** (`BundleManifest`, `check_completeness`, `reproduce` at R0/R1/R3 with WS-I3/I2/J3; AC-L4-8…10); **C1 / Stage 4** (hosted-participant bundles, lineage export); **C2 / Stage 5** (R2 gated on profile pinning with WS-C3).

## Consequences

- WS-I3 owns the bundle *format* but inherits the member list, completeness contract and level semantics; the interchange export (ATIF-compatible) is one `traces` member, never the bundle identity.
- WS-J5's schema carries `claimed_level` and `bundle_ref` on every row; WS-J4 reports levels alongside distributions and refuses cross-level pooling without annotation.
- WS-C1 must expose provider snapshot ids where available and run the fingerprint probe; WS-B5 must return image digests, not tags; WS-I4 imports Harbor/Inspect version strings as claims (CF-087).
- The Readiness Report lists, per subsystem, which reproducibility level its acceptance tests exercise.

## Reversibility

**Medium** for the level definitions (renaming or merging levels changes reports, not stored records); **low** for the bundle-as-lock-manifest rule and the results-store keys (every stored bundle and row depends on them); **high** for the fingerprint probe and margin parameters.
