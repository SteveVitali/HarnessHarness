# ADR-0104 — The Stage-0 minimal control strategy `react/minimal` (mini-SWE-agent-class; T-LCD-03 anchor)

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-F1 (consumers: WS-A3/A4 for T-LCD-03, WS-B1/B3 for AC-B1-4, WS-F2, WS-E1/E5, WS-I2/I4, `decompose-spec` Stage 0) · **Phase:** 2 · **Related:** ADR-0103 (the contract), ADR-0007 (T-LCD-03), ADR-0015 dossier §6.9 / OQ-039 (mini-SWE-agent-class Stage-0 baseline anchors T-LCD-03), ADR-0016 (`Loop` bounded; `HarnessRule` debt record), ADR-0028 (`deterministic_replay`; AC-B1-4), ADR-0030 (`unknown` outcome rendered), ADR-0039/0040 (dimensions; hard ceilings at decision points), ADR-0049/0050 and `synthesis/l1-spike-spec.md` (Stage 0 kernel slice); CF-221; OQ-045, OQ-255; R-2.6.1

## Context

Doc 2 §11 Stage 0: "Implement a ReAct-style loop with filesystem, shell/code execution, one structured tool API, explicit token/tool/time budgets, and a complete trace. Keep it small enough to understand line by line." OQ-039 (resolved) anchors T-LCD-03 on a mini-SWE-agent-class Stage-0 baseline. WS-F1 read mini-SWE-agent at commit 04d809c: `run: while True: step()`; `step = execute_actions(query())`; `query` checks `step_limit`/`cost_limit`/`wall_time_limit_seconds` *before* the model call; the environment raises `Submitted` on the `COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT` marker with `returncode == 0`; a response without an action is a `FormatError` fed back as a message and capped by `max_consecutive_format_errors`; exits are `role = "exit"` messages with `exit_status ∈ {Submitted, LimitsExceeded, TimeExceeded, RepeatedFormatError, …}`. This ADR fixes that shape as the first variant of the ADR-0103 contract, expressed in HIR/1 without new constructs, so that Stage 0 produces both the doc 2 baseline and the T-LCD-03 anchor.

## Options considered

1. **Codex/Pi-style "no tool call ⇒ stop" as the Stage-0 default.** *Rejected as the anchor configuration:* the anchor's own rule is submit-marker + format-error nudge; adopting a different stop rule would make the T-LCD-03 round-trip measure the stop rule rather than the IR. It remains one parameter away (`stop_rule = no_action`) and is the Lab's first ablation (ADR-0105 H4).
2. **Submission detected by the environment (as in mini-SWE-agent).** *Rejected:* the environment must stay effect-only (execution plane separate from control, ADR-0012/ADR-0030); detection moves into the driver over the observed output, preserving behaviour.
3. **A dedicated `submit` ToolCapability (Inspect style).** *Deferred (OQ-255):* cleaner for E1's tool table but changes the anchor's model-facing surface; evaluate at Stage 3 as a surface variant under T-LCD-01.
4. **Marker-based submit in the driver, `stop_rule = submit`, format-error nudge as a conditioned `HarnessRule`, three hard ceilings, no compaction/delegation/retrieval (chosen).**

## Decision

1. **Definition (HIR/1 only).** `Goal{statement: Text(task), success_criteria: [], unverifiable_reason: "Stage 0"}`; one `ToolCapability{effects: {exec{mutability: destructive, repeat_safety: non_idempotent, world: closed, reversibility: irreversible}}, input_schema: {command}, output_schema: {output, returncode}}` executed via the sandbox helper (OQ-045 provisional); `Budget{dimensions: {model_calls.hard, spend.hard, time.wall_ms.hard, turns.hard}}` (the anchor's `step_limit`, `cost_limit`, `wall_time_limit_seconds`); two `Text` leaves (system template, instance template — `authority = definition`, opacity counted); one `HarnessRule{trigger: response_without_action, action: insert ContextItem(Text nudge), conditioned_on: profile family, assumption_debt: {hypothesis: "this family omits actions under long transcripts", evidence_refs: [anchor config], owner: WS-F1, expiry_condition: nudge never fires over N runs, removal_test_ref: AC-F1-8}}`; `Procedure` implicit: `Loop(bound: Budget){step{propose}; step{act}}`; `ControlBoundary = react` preset (`plan/act/retrieve = model`, `compact/verify/authorize/retry = code`, `stop = model→code`, `escalate = human`); slot `control_strategy = react/minimal`.
2. **Parameters.** `stop_rule = submit` (`submission_marker` compared against the first line of the effect's observed output with `returncode == 0`), `max_consecutive_format_errors = 3`, `max_continue_nudges = 0`, `tool_batch_mode = sequential`, `on_truncated_response = fail_calls`, `loop_guards = []` (the driver's no-progress guard still applies), no `compact` (gauge `context.occupancy` cap ⇒ `stop{context_exhausted}`), no `delegate`, no `retrieve`, no `verify` beyond submission presence.
3. **Decision table.** `run_opened → propose{act}`; `model_completed{tool_use, intents} → act{intents, sequential}`; `model_completed{end, no intents} → guard_fired[format_error]` (nudge; streak++), streak ≥ 3 ⇒ `stop{guard_tripped(format_error)}`; `model_completed{length} → fail_calls` then `propose`; `effects_settled{all_terminal, submission observed} → stop{completed, submission_ref}`; `effects_settled{terminal, no submission} → propose` (streak reset); `effects_settled{unknown} → propose` with the explicit `unknown` rendered (ADR-0030); `envelope_signal{refused: InsufficientBudget} → stop{budget_exhausted{dimension}}`; `envelope_signal{retryable_error} → retry{model_call}` up to the profile's bound, then `stop{error(class)}`; `human_input{interrupt} → stop{cancelled}`; `resumed{last_durable} → observe` then `propose` — a `committed` effect is never re-issued.
4. **`deterministic_replay = true`.** State = `{cursor, decision_count, open_effects, format_error_streak, last_cue_seq}`; every nondeterministic input is a recorded event; `decide` is the table above. AC-B1-4 applies at Stage 3.
5. **Stage-0 driver subset.** Hard-ceiling checks only (reserve-before-spend sized by `profile.max_output`), effect gate, `control.decision` and `lifecycle.turn.*` events, no envelope guards beyond the format-error streak and no-progress; the S1 kernel slice of `l1-spike-spec.md` is its consumer (stubbed model, `echo`/`true` tool).

**T-LCD statement.** Satisfies T-LCD-02 (two `Text` leaves + one nudge leaf; opacity reported), T-LCD-05 (the nudge is a conditioned rule with a complete debt record), T-LCD-13 (nudge delivery/activation/following ledgered), T-LCD-14 (Budget on the Goal and process), T-LCD-15 (`deterministic_replay` declared true; other capabilities false, never `unknown` for a native variant), T-LCD-01 (no model branch; the nudge is profile-conditioned through the rule). T-LCD-03 is the Stage-3 executable test this ADR exists to anchor (AC-F1-2). **ADR-0024 ladder:** the loop = registered variant; the four limits and stop rule = typed parameters; templates and nudge = `Text` leaves.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: doc 2 §11 Stage 0 (Tier B synthesis); ReAct S-006 (Tier A) for the loop; Anthropic S-032 ("stopping conditions (such as a maximum number of iterations)"; "ground truth from the environment at each step"); the anchor's documented control flow S-400 ("`Agent.run(task)` repeatedly calls `Agent.step()`"; exits by `role="exit"`); Barbaste S-074/S-166 (`provisional (mech)`: the "minimal linear loop" reaches "the same range" as event-sourced engines — a reason to *start* here, not a performance claim); ADR-0028 (reconstruction is Core; replay declared).
- (b) Source-code precedent: `mini-swe-agent/src/minisweagent/agents/default.py` L19–35 (`AgentConfig` limits), L88–124 (`run`), L126–157 (`step/query/execute_actions`), `exceptions.py` L1–26, `environments/local.py` L43–56 (`_check_finished`), `config/mini.yaml` (templates; submit instruction) at 04d809c; corroborating "limits before the call" and "no-tool-call handling": `codex/codex-rs/core/src/session/turn.rs` L150–162, `inspect_ai/src/inspect_ai/agent/_react.py` L81–83 (submit ⇒ nudge, no submit ⇒ terminate), `pi-mono/packages/agent/src/agent-loop.ts` L226–235 (`length` ⇒ fail the batch). `no-precedent / novel`: submission detection in the control driver rather than the environment; the nudge as a debt-recorded conditioned rule.
- (c) Disconfirming evidence considered: four production loops stop on "no tool call" (Codex, Pi, OpenHands, LangGraph) — resolved as a parameter, with the anchor's rule as the anchor configuration and H4 in ADR-0105 to measure the difference; a marker-in-output convention is fragile (a program could print the marker) — mitigated by the `returncode == 0` + first-line rule the anchor uses and by OQ-255 (dedicated submit capability evaluated at Stage 3); "Stage 0 proves little" (WS-A3 §5) — accepted; the rich anchor at Phase 3 (OpenHands) is the opacity measurement, this is the kernel proof.
- (d) Conditionality: coding/terminal tasks with a shell-class tool; a model family that follows the submit instruction (the nudge rule carries the debt record for the ones that do not); no long-context assumption (no compaction; the run stops when the window fills).
- (e) Build-stage assignment: **C0 / Stage 0** (definition, driver subset, S1 consumer); **C0 / Stage 3** — T-LCD-03 round-trip (AC-F1-2) and AC-B1-4 replay (AC-F1-4).

## Consequences

- `decompose-spec` gets a line-by-line-sized Stage-0 ticket: one definition document, one driver, one tool executor via the helper boundary, one budget node, ledgered decisions.
- WS-I4's Stage-3 suite must include the anchor's own tasks (SWE-bench-class) so the paired T-LCD-03 comparison is fair.
- WS-E1 registers `exec` with the attribute set above; WS-E5/B5 provide the helper; WS-F2 provides the hard-ceiling `check/reserve`.
- Every later variant is measured against this one (ADR-0105 H0).

## Reversibility

**High.** Changing the stop rule, limits or nudge is a parameter or `Text`-leaf diff; replacing the variant is a slot rebinding. Only the driver subset is Core, and it is a strict subset of the Stage-1 driver.
