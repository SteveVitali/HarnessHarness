# ADR-0054 — C2 propagation semantics per derivation type: prospective post-call label, admission, quarantine handle, label-seeded branches; the deterministic/advisory split (one lattice, two enforcement depths)

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-H2 (consumers: WS-H1, WS-D1, WS-D2, WS-D3, WS-D4, WS-E1, WS-F3, WS-A4/E4, WS-J6, WS-I2) · **Phase:** 2 · **Related:** ADR-0033, ADR-0034, ADR-0035 (base — cited, not re-decided), ADR-0016 (`ContextItem`, `Observation.taint`, `ToolCapability`), ADR-0022 (`SurfaceArgMap`), ADR-0026/ADR-0030/ADR-0031 (views, effect phases, kernel decision record), ADR-0002 (iii), ADR-0007 (T-LCD-02/-06/-07/-08/-10/-11/-12/-13/-15), ADR-0024 (ladder), ADR-0050 §8; CF-124/-03/-04/-05; OQ-105 (answered), OQ-140/-06/-08; R-2.8.2, R-2.4.1, R-2.4.4, R-2.5.1

## Context

Phase 1 ratified one label `(authority, taint, readers)` on one provenance record, with `authority` enforced at C0 and `taint`/`readers` "carried at C0, enforced at C2 (H2)" (phase-1 §6.2; ADR-0033 decision 4; CF-078). The brief asks for the propagation semantics of every derivation type — summarize, compact, retrieve, delegate, tool-call, tool-result — with the two set-valued components load-bearing, and for the line between deterministic and advisory enforcement. The audit found three mechanisms the C0 rules do not yet state: (i) a **composite tool** (read + send in one call) is authorized against a stale label unless the monitor checks the *prospective* post-call label from a declared contribution (APPA necessity proposition; Fides' rule joins the tool's read set; CaMeL `inner_sources`); (ii) the per-call context label over-taints unless a value above it can be **kept out of the label without being lost** (Fides `Hide`; CaMeL variables; LIO labeled values; APPA child branch) — the measured difference between a ≈ 40-point and a ≈ 24.5-point utility drop under policy; (iii) a **child trajectory seeded at top** is a laundering path, so branches inherit the parent's label and their approvals never transfer (APPA; CapScope per-issuer). Separately, several 2024–2026 methods *lower* labels by model judgement (permissive propagation, semantic taint); adopted deterministically they would break no-sensitive-upgrade soundness.

## Options considered

1. **Keep C0 semantics and add only the readers check at egress.** *Rejected:* unsound for composite tools (reactive checking) and blind to per-argument provenance; every audited policy checks parameters, not whole calls.
2. **CaMeL-style per-value dependency interpreter at C2.** *Rejected as the default:* 2.8× tokens, a model-programmed interpreter and per-tool code policies (S-099); retained as a component variant a definition may bind (the contract admits per-leaf labels).
3. **Fides-style abort-on-violation loop with hiding.** *Rejected in its abort form:* utility loss is what decides adoption; the hiding half is adopted (quarantine handle).
4. **Model-estimated labels (permissive/semantic propagation) as enforcement.** *Rejected:* label lowering by a `delegate` origin is declassification without an endorser (ADR-0035 rule 1); admitted as advisory only.
5. **Per-derivation-type join semantics with a declared tool contribution (prospective label + admission), a typed quarantine handle, label-seeded branches with non-transferable approvals, and an explicit deterministic/advisory enforcement class (chosen).**

## Decision

1. **Derivation table (binding; dossier §6.2).** `summarize`/model `compact`: `⊔ L(inputs) ⊔ (delegate, ∅, Public)`. Deterministic `compact`/projection: `⊔ L(retained)`, never lower; `ctx` is recomputed from what is delivered (compaction that drops external items restores it — OQ-105 part 1). `retrieve`: stored label unchanged; joins into `ctx` unless delivered as a handle. `delegate`: child `ctx₀ = ctx(parent at spawn)`, clearance = parent's effective authority; results re-enter at `⊔ L(child outputs) ⊔ (delegate, ∅, Public)` with `derived_from.kind = subagent_result`; **child approvals/rulings never transfer**. `tool-call`: C0 `L(p) = ctx(c) ⊔ ⊔ L(args)`; **C2 prospective** `L⁺(p) = L(p) ⊔ d_τ` from the capability's `FlowContract.contribution`; checks evaluate on `L⁺(p)` and on per-parameter labels (through `SurfaceArgMap`). `tool-result`: whole-result `L(r) = L⁺(p) ⊔ default_authority(tool, world)`; if `labels_leaves`, each typed leaf carries its own record and the whole is the join of leaves; **admission** re-validates the realized result against `d_τ` (realized more restrictive → admitted as realized; less restrictive → admitted at declared, `AdmissionNarrowed` recorded); unannotated open-world results: `unverified`, `taint = {tool}`, readers from the declared `reads`.
2. **Flow contract.** Every `ToolCapability` with `world = open` or an effect domain in `{net_egress, message_human, fs_read, memory_write}` carries `FlowContract{contribution{taint_tags, readers_from}, reads[], recipient_params[], content_params[], labels_leaves, resolve_recipients?}`; `seal` refuses otherwise (`ContributionUndeclared`). (CF-125 to WS-E1.)
3. **Quarantine handle.** `quarantine(item) → QuarantineHandle{handle_id, label, schema?, capacity_bits?, blob_ref}`; a `ContextItem.rendering ∈ {inline, handle}`; a handle's content is never rendered into a model-facing `Text` (`HandleLeaked`); a handle passed as an argument contributes its label to `L(args)` but not to `ctx` of later calls; `reveal` only into a branch or an endorsement. (CF-126 to WS-D1; answers OQ-105.)
4. **Label branch.** `spawn_process` with `isolation = label_branch`: exits `abandon | labeled_return | attested_return(validator_ref)`; the parent's `ctx` never changes while a child is open (`BranchTaintEscaped`); clearance enforced (`ClearanceExceeded`).
5. **Enforcement class.** `EnforcementClass ∈ {deterministic, advisory}` on every check and every input to a decision. Deterministic: lattice ops, `ctx`, prospective label, admission, per-parameter labels, endorsement legitimacy, branch seeding/re-entry. Advisory (may add rows to Π's inputs or *propose* a remedy; never sets a label or a decision class): model risk self-reports, judge verdicts, permissive label minimization, semantic-taint detectors, model-drafted policies. Rule: an advisory input that would lower a label is a declassification and must pass an endorsement point; one that only raises restriction may apply directly (no-sensitive-upgrade).
6. **Guarantee statement (spec may claim exactly this):** integrity non-interference at the effect boundary, explicit secrecy for confidentiality, no laundering through any derivation; **not claimed:** implicit flows through effect sequences, timing/exception channels, text-to-text harms, semantic correctness of endorsed values.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-02 (handles are typed leaves; labels never prose), T-LCD-06/-07/-15 (hosted rows `n/a` with reason; nothing native changes), T-LCD-10 (contracts keyed on capability parameters/`EffectClass`), T-LCD-11 (taint/readers via `_meta`; loss reported), T-LCD-12 (operations; out-of-process; AC-H2-12), T-LCD-13 (admission/endorsement/branch events observable). T-LCD-08: the monitor is deliberately profile-blind (a "does not" mitigated by AC-H2-12: decisions invariant under profile change); sanitizers/validators do receive `(ModelProfile, ResourceAccount)`. Not applicable: T-LCD-01/-03/-04/-05/-09/-14 (T-LCD-14 engaged by ADR-2's remedy budgeting). ADR-0024 rung: contracts and renderings are MUST-data; admission, quarantine and branch lifecycle are MUST-code.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** lattice join over data and control flow — Denning (S-216), Biba low-water mark (S-217); floating label bounded by clearance and labeled values passed without raising the current label — LIO (S-266, Tier A); no-sensitive-upgrade for purely dynamic monitors — Austin & Flanagan (S-267, Tier A); tool-result join over the read set, `Hide` keeps values out of the conversation label, type-capacity lattice — Fides (S-101, 2025); readers ∩ / sources ∪ over dependencies, `inner_sources`, STRICT control-flow dependencies, quarantined extraction — CaMeL (S-099/S-100, 2025, code); prospective post-call label necessity, admission gate, label-seeded child branches, non-transferable rulings — APPA (S-258, `provisional`); argument-level provenance — PACT (S-261, `provisional`); per-issuer capability checks — CapScope (S-105, `provisional`); provenance oracle at the boundary as the failure point — S-259 (`provisional`); model-side label lowering is unsound by construction — S-263 (2024), S-260 (`provisional`); base rules — ADR-0033/0034/0035.
- **(b) Source-code precedent:** `fides/Tutorial.ipynb` cells 22–27 (`MetaValue` per-leaf labels; tool joins), cell 29 (`current_label = label(result).join(current_label)`); `camel-prompt-injection/src/camel/capabilities/utils.py` L15–73 (readers ∩, sources ∪), `interpreter/interpreter.py` L2050 (`check_policy` before every call), L2067 (Q-LLM args as dependencies), `quarantined_llm.py` L25–99 (schema-forced extraction, refusal). Quarantine handle, prospective label, admission and label branches: `no-precedent / novel` as running code (Fides `Hide` and APPA are paper-only).
- **(c) Disconfirming evidence considered:** taint analysis "fundamentally fails" for NL propagation (S-260) — it fails in *precision*, not soundness; the scheme never tracks inside a model call; the granularity mismatch (S-261) — absorbed by per-parameter labels and handles; utility loss (S-099 77/84; S-101 DD tasks 10–25%) — why the taint gate's default class is a Stage 3 measurement; Fides/APPA are notebook/paper only — accepted, hence `medium` confidence on the running mechanisms. None overturns.
- **(d) Conditionality:** independent of model tier. Assumes capabilities declare `world` and (at C2) a `FlowContract`; assumes native participants enumerate delivered items per call (hosted: `n/a`); assumes reader universes are small per run; the benefit of handles/branches depends on task decomposability (a Lab factor).
- **(e) Build-stage assignment:** **C2 / Stage 2** (flow contracts with E1; prospective label + admission; handle with D1; enforcement-class field); **C2 / Stage 3** (Lab recipe AC-H2-10 decides the taint gate's default class); **C2 / Stage 4** (label branches with F3). No C0 change.

## Consequences

- WS-E1 adds `FlowContract`; WS-D1 renders handles and declares `deliver_as = handle` per slot; WS-D2 variants call `derive(kind = compaction)`; WS-D3/D4 retrieve handles under the P5 order; WS-F3 implements branch seeding/exits; WS-H1's `authorize` evaluates on `L⁺(p)`; WS-B1/H1 accept the payload extensions in CF-127; WS-J6 renders `n/a` per observability level; WS-I2 registers `taint_precision` and the AC-H2-10 recipe.
- Every advisory input in a later dossier must name its enforcement class; "the classifier decided" is never a label change.

## Reversibility

**Medium.** Each rule is a pure function over records; prospective labels and admission can be relaxed to the C0 form by ADR without touching stored records. Removing the quarantine handle after Stage 2 re-introduces the over-tainting the C0 context label is known to cause (AC-H2-10 measures the difference), and removing label seeding reopens the laundering path — those two are the load-bearing rules.
