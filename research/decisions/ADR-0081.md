# ADR-0081 — Memory lifecycle as derived state over immutable versions: the invalidation contract (closed dependency kinds, cache hints, freshness, validators, minimum-contract rule), three kernel enforcement points with withheld records, and model-free validity

**Status:** **ratified, amended** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-D4 (consumers: WS-D3, WS-D1, WS-D5, WS-B1, WS-B3, WS-H1, WS-H2, WS-H5, WS-H6, WS-I2, WS-J5) · **Phase:** 2 · **Related:** ADR-0014 (three-valued validity; D4 obligation), ADR-0016 (`Memory`, `validates`, `supersedes`), ADR-0026/ADR-0027 (derived views, `seq`), ADR-0033/ADR-0034 (labels; P4, P5 retrieval order), ADR-0035 (persistence ceilings), ADR-0036/ADR-0037 (identity; I1–I5; `RevocationRecord`; `resolve` modes), ADR-0048 (R-2.4.4 stage note); CF-008, CF-028, CF-179, CF-181, CF-182; OQ-010, OQ-020, OQ-206/-02; R-2.4.4, R-2.4.3, R-2.4.1

## Context

Doc 2 §5.1 asks a long-lived agent's memory to answer "Is this record still true? Which version supersedes it? Was it revoked? … When should it expire?" and diagnoses these as "database, cache-coherence, truth-maintenance, and security questions rather than embedding questions". ADR-0014 obliges WS-D4 to require a validity check or interval on every memory artifact; ADR-0034 P5 fixes the retrieval order validity → authority → readers → relevance as a C0 contract of D1/D3; ADR-0037 supplies immutable versions, supersession edges, `RevocationRecord` and resolver-enforced revocation. What was missing is *the predicate*: what makes a memory version `valid` at a given point, decided by records alone. The source audit shows the failure that results when the predicate is not in the read contract: graphiti stores `expired_at`/`invalid_at` but `search(search_filter = None)` applies no validity filter (`graphiti_core/search/search_filters.py` L65; `graphiti.py` L1586–1595); mem0 records deletion in a `history` table the retrieval path never reads; goose instructs the model to "remove it from the system instructions"; langgraph's store expires by best-effort sweep and refreshes TTL on read. S-106 measures the consequence (revoked facts returned in 81/81 scenarios by two of five systems; a store-level filter takes unsafe actions from 43.1 % to 0.0 %) and S-077 shows the remedy's shape (per-dependency version stamps plus a cacheability hint give "zero contract failures" and validity verdicts identical across seven models). RFC 9111 has had the same structure for decades: freshness lifetime, validators, `must-revalidate`, mandatory invalidation after an unsafe method.

## Options considered

1. **Mutable `status` flag on the memory record, set on revoke/expire.** *Rejected:* violates ADR-0037 I1 and the S-106 signature (a flag "visible to the retrieval layer" that nobody checks); no audit of *who* set it.
2. **TTL-only expiry with deletion sweeps (langgraph store).** *Rejected:* deletes history (I3), refresh-on-read makes popular stale items immortal, and no stamp says *why* a memory is invalid.
3. **Model-checked validity (deliver the memory with its timestamps and let the model judge).** *Rejected:* S-106 prompt hardening leaves 37.2 % unsafe actions; contradicts doc 2 §5.1 "enforced by the retrieval/control layer" and ADR-0035 (the model never endorses).
4. **Validity as one more label component.** *Rejected by ADR-0033 decision 5:* validity is orthogonal to authority; a revoked item keeps its label and loses its validity.
5. **Chosen: lifecycle state derived by a pure function over immutable records; a mandatory `InvalidationContract` with a closed set of stamp sources; validity three-valued with `unknown` only when nothing checkable was declared; enforcement at `retrieve`, `admit` and `resolve(mode = execute)` with withheld records written to the ledger.**

## Decision

1. **Derived state.** `lifecycle_state(v: VersionedRef<Memory>, at: Seq) → valid | superseded{by} | revoked{record} | expired{reason} | stale_by_dependency{revoked_inputs[]} | unknown`, a pure function of: `supersedes` edges into `v`, any `RevocationRecord` naming `v`, `v.validity`, `check_contract(v.contract, at)`, and the derived `MemoryStaleIndex` (ADR-0083). Precedence `revoked > superseded > expired > stale_by_dependency > valid > unknown`. `validity(v, at)` (ADR-0014) is its projection with `check_ref`. No memory version is ever mutated; every transition is an appended record or event (`context.memory.written / invalidated`, `RevocationRecord`, `supersedes`).
2. **Invalidation contract** on every `Memory` version: `InvalidationContract{dependencies: [DependencyStamp{kind: DependencyKind, ref, stamp, granularity ∈ {row, table}}], cache_hint ∈ {cacheable, recompute, no_store}, validator_ref?, freshness?: {valid_until} | {max_age, from}, invalidation_condition?: dependency_changed | ttl_elapsed | validator_fails | superseded | scope_ended(scope) | replacement_published(name), revalidation ∈ {must_revalidate, stale_ok{max_stale}, never}}`. `DependencyKind` is a closed sum `{registry_name, definition_version, procedure_version, tool_capability_version, environment_image, model_snapshot, memory_version, artifact, external_resource{validator_ref}}`; stamps are read from kernel/registry records (ADR-0036/0037; E1/B5/C1 records), never from the memory's text. **Validity rule:** `valid` iff every stamp equals its dependency's current stamp at `at` ∧ freshness not elapsed ∧ (no validator or last verdict `pass`) ∧ no condition holds; `unknown` iff the contract declares nothing checkable. `recompute` memories never persist beyond `turn`; `no_store` never persist. Reads never extend freshness; revalidation is a new version with `supersedes{edit}`.
3. **Minimum-contract rule (ADR-0014 obligation).** `write` refuses a version whose contract is empty in all four checkable fields unless `scope ∈ {run, turn}` (`MissingContract`); the sealed definition's `MemoryPolicy{per_kind_defaults, …}` (MUST-data, `authority_cap`-layered) supplies per-kind defaults, e.g. `scope_ended(session)` for `external`/`delegate` extracts. A profile may override a default only as a conditioned rule with an assumption-debt record (T-LCD-05).
4. **Enforcement points (kernel, records only).** E1 `retrieve` (WS-D3): step (i) of ADR-0034 P5 is `lifecycle_state(v, until_seq) ∈ slot.validity_policy.admitted_states` (default `{valid}`; `unknown` only with `admit_unknown_validity`; `stale_by_dependency` only with `admit_stale_by_dependency`; `superseded | revoked | expired` never in `mode = execute`); withheld candidates are recorded as `context.memory.read.withheld[{version_id, state, reason}]` and never delivered. E2 `admit` (WS-D1 I-ORDER) re-evaluates at the model call's `seq` and again at handle expansion. E3 `resolve(mode = execute)` (ADR-0037 S3) for pinned memory refs. E4 `write` applies the scope ceiling, label join, and contract rule. No memory check is added to the reference monitor (CF-006: no second scheme).
5. **Model-free validity (V-DET).** `validity` and `lifecycle_state` read no `Text` leaf and consult no model; they are identical for the same `(v, at)` across configurations, processes and a rebuilt index (property test AC-D4-9). Model-conditioned *usefulness* of a memory is a `HarnessRule` conditioned on a `ProfileRef` or simply a compliance measurement keyed by snapshot (ADR-0014); `Memory` carries no model identity.
6. **Slot policy (CF-181).** `SlotDeclaration.validity_policy{admitted_states ⊆ {valid, unknown, stale_by_dependency}, conflict_policy, max_stale?}` supersedes the boolean `admit_unknown_validity`; a policy may never admit `revoked | superseded | expired` (`InvalidLayout`).

**T-LCD statement.** Satisfies T-LCD-02 (memory bodies are `Text` leaves or closed-schema values; stamps are typed), T-LCD-05 (per-kind defaults are definition data; overrides are conditioned rules), T-LCD-08 (the memory component class receives the profile and account; validity is profile-independent by V-DET), T-LCD-10 (state is derived over content-addressed versions; annotations are surfaces), T-LCD-12 (pure operations, out-of-process), T-LCD-13 (withheld vs delivered is observable per artifact), T-LCD-15 (hosted rows `n/a`). Not applicable: T-LCD-01/-03/-04/-06/-07/-09/-11/-14 (T-LCD-14 is engaged by ADR-0083's Lab recipe).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: cache validity as validators + freshness + explicit invalidation — RFC 9111 §4.2–4.4, §5.2.2 (S-355, Tier A: "MUST NOT reuse … until it has been successfully validated"; "MUST invalidate the target URI … unsafe request method"); revocation checked by the relying party's validator, never the subject, with dated signed records and reason codes — RFC 5280 §5–6 (S-356, Tier A); valid time vs transaction time — Jensen & Snodgrass (S-354, Tier A); per-dependency version stamps make validity deterministic and model-independent, and granularity decides over-invalidation — S-077 (`provisional (mech)`); revoked facts returned and acted on unless a store-level filter withholds them; prompt-based revocation insufficient — S-106 (`provisional (mech)`), corroborated in source by graphiti's opt-in `expired_at` filter and goose's instruction-based forgetting; doc 2 §5.1 second-pass ledger (Tier B synthesis, "medium-high, rapidly strengthening"); retrieval order as contract — ADR-0034 P5 (ratified); immutable versions with resolver-enforced revocation — ADR-0037 (ratified).
- (b) Source-code precedent: `graphiti/graphiti_core/edges.py` L271–284 @4bd7287 (bi-temporal fields — adopted shape) and `search/search_filters.py` L55–65, `graphiti.py` L1586–1595 (no default filter — the negative fixture); `langgraph/libs/checkpoint/langgraph/store/base/__init__.py` L526–575 @e539ac1 (`ttl`, `TTLConfig.refresh_on_read` — rejected semantics); `mem0/mem0/memory/storage.py` L150–235 @02f7a9b (append-only `history` with `is_deleted` — the record-not-mutation half); `AIOS/aios/memory/write_barrier.py` L25–60 @292d98f (read-your-writes watermark → `until_seq`); `goose/crates/goose-mcp/src/memory/mod.rs` L136–175 @fae91d0 (model-entrusted revocation — rejected). **`no-precedent / novel`** for: a closed `DependencyKind` contract on memory, `lifecycle_state` as a pure derived function with precedence, withheld records in the ledger, and V-DET as a tested invariant.
- (c) Disconfirming evidence considered: most memory kinds have nothing to stamp, so strict `{valid}` slots would starve the model (MemGPT/Generative Agents/Reflexion memory is all free text) — absorbed by the minimum-contract rule (an interval always suffices), `admit_unknown_validity` per slot, and AC-D4-12's utility measurement; TTL-with-deletion is simpler and ships in production (langgraph, mem0) — rejected because it destroys audit (ADR-0037 I3) and history, and WS-H6's redaction path already handles the storage/privacy concern; S-077/S-106 are single-team 2026 preprints with authored domains — used for mechanism and fixture shape only, the design rests on RFC 9111/5280, temporal-DB theory and ratified ADRs; a per-call re-check at `admit` adds a kernel hop — one indexed lookup per delivered memory over derived views. None overturns.
- (d) Conditionality: independent of model tier and task class; assumes dependency stamps exist for the closed kinds (registry, environment, tool, model records — Stage 1 artifacts of L4/B5/E1/C1); assumes the context builder can enumerate delivered items (native participants; hosted ⇒ `n/a`); the *value* of strict validity policies is a Stage 3 measurement, not an assumption.
- (e) Build-stage assignment: **C0 / Stage 1** (schemas: `InvalidationContract`, `DependencyKind`, `MemoryPolicy`, `validity_policy`; `validity`/`lifecycle_state` functions; `write` refusals); **C0 / Stage 2** (E1–E4 enforcement in D3/D1/L4 paths per ADR-0048's stage note; `context.memory.*` payloads; expiry projection; AC-D4-1/-2/-7/-9/-10); **C0 / Stage 3** (V-DET across two profiles; vetoes registered); **C2 / Stage 2–4** (`stale_ok`, `admit_stale_by_dependency`, external-resource validators, taint/readers enforcement via H2).

## Consequences

- WS-D3 implements `filter_for_slot` inside `retrieve` and passes `until_seq`; WS-D1 replaces `admit_unknown_validity` with `validity_policy` and re-checks at the call's `seq` and at expansion; WS-B1 extends `context.memory.written/invalidated/read` payloads (CF-179); WS-H6 treats `context.memory.read.withheld[]` as audit-grade (CF-180); WS-B3 re-evaluates `lifecycle_state` at the resumed `seq`; WS-E1/B5/C1/J2 publish the stamps for their `DependencyKind`s (OQ-206); WS-D5 procedures inherit the same contract and enforcement points; WS-I2 registers `memory.revoked_delivered` and `memory.stale_delivered` as veto metrics (ADR-0083).
- The S-106 scenario and the S-077 drift scenario become regression fixtures (AC-D4-1/-2; AC-L4-7).

## Reversibility

**Low** for decisions 1, 4 and 5 (derived state, enforcement in the read contract, model-free validity are load-bearing for the safety property and for ADR-0014's measurement); **medium** for the contract's field list and `DependencyKind` (extensible by dialect bump; stored contracts migrate); **high** for per-kind defaults and slot policy vocabulary (definition data, re-cut by ADR without touching stored versions).
