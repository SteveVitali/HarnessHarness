# ADR-0015 — HIR type discipline and expressiveness ceiling (typed envelope, two opaque leaf kinds, content-addressed identity, canonical encoding)

**Status:** **ratified** (Phase 1 synthesis, 2026-09-10)
**Owner workstream(s):** WS-A3 (consumers: WS-A4, WS-A5, WS-B1, WS-L4, WS-C3, WS-I2, WS-L1) · **Phase:** 1 · **Related:** ADR-0001, ADR-0004, ADR-0006 (novelty claim a), ADR-0007 (T-LCD-01/-02/-06/-10/-12), ADR-0008, ADR-0009 (C6 hard gates), ADR-0011; ADR-0029 (co-owned canonical form); CF-001, CF-011, CF-034/-04/-06/-08/-09, CF-047, CF-052; OQ-002, OQ-006, OQ-036, OQ-040, OQ-041; R-2.1.2, R-2.12.1

## Context

Doc 2 §11 sketches a Harness IR of thirteen typed entities and six edges but says nothing about *how* typed: which constructs are closed sums, where opaque code and prose are allowed, how identity and versions are derived, or what a host ecosystem must provide. Phase 0 made this decision load-bearing three times over: the narrowed novelty claim (a) requires "provenance/authority on every entity and profile-compiled lowering" (ADR-0004/0006, CF-011); the LCD battery makes T-LCD-01/-02/-06/-10/-12 static C0/Stage-1 checks on the IR schema (ADR-0007); and WS-L1's language ratification has two conditional hard gates (C6) that fire only if WS-A3 *requires* closed sums with exhaustiveness checking or statically checked effect typing (ADR-0009, OQ-040), plus a joint question on canonical byte encoding (OQ-041). The source audit (WS-A3 dossier §4) shows that every productive structure-search system (ADAS, AFlow, GPTSwarm) wraps an opaque payload in a typed envelope, that production SDKs use open subclass-registered unions with silent-failure risk, that DSPy puts surface wording into identity, and that Unison/JCS/MLIR supply mature mechanisms for content addressing, canonical bytes and typed-IR-with-opaque-islands.

## Options considered

1. **Fully typed, no opaque constructs** — every behaviour expressed as kernel nodes. *Rejected:* excludes the code-shaped search spaces ADAS/AFlow/Meta-Harness use and forbids custom validators/tools; would fail T-LCD-03 on any real harness.
2. **Open schema-validated records everywhere** (OpenHands/Agent Spec style; kinds discovered by registration). *Rejected:* exhaustive consumers (compiler, verifier, diff classifier) cannot be proven complete; unknown kinds fail silently or late; extension by accident becomes the escape hatch T-LCD-01 forbids.
3. **Statically effect-typed IR** requiring a host type system with effect rows (Koka-class). *Rejected:* forces a hard gate on WS-L1 for a guarantee the reference monitor must re-check at runtime anyway (MCP annotations are hints; misdeclaration is not caught by typing).
4. **Random-UUID identity + version counters** (Agent Spec). *Rejected:* rename/re-serialization changes nothing detectable, but neither does a semantic change; T-LCD-10 needs identity derived from content with surfaces excluded.
5. **Closed kernel sums per dialect + registered prefixed extension slots; exactly two opaque leaf kinds (`Text`, `CompiledPayload`) each with declared interface/owner/authority; two content-addressed ids (semantic, version) over a canonical form; effects recorded and consistency-checked at validation, enforced at runtime (chosen).**

## Decision

1. **Meta-model.** A HIR document is a DAG of nodes `{version_id, semantic_id, kind, dialect, version, provenance, semantic, surface?, ext}` and edges `{kind, from, to, provenance, fields}`. `EntityKind`, `EdgeKind`, `EffectDomain` and the `EffectAttributes` sums (whose product is `EffectClass`), `AuthorityClass` (shape; values per CF-006), `ValidityState`, `OpaqueKind`, `ProcedureStepKind`, `ValidatorKind`, `AgentProcessKind`, `DecisionPoint` are **closed sums per dialect**; every node carries a derived `home_plane` (WS-A2); adding a variant is a dialect bump with a migration.
2. **Extension slots** `ext: map<PrefixedKey, TypedValue>` use reverse-DNS prefixes with a reserved `hir/` namespace (MCP `_meta` rule); each key registers a schema; unknown keys are preserved byte-for-byte and never interpreted. **No extension slot may decide authority, budget or validity** — those are kernel fields (the type-level form of "no escape hatch", T-LCD-01).
3. **Expressiveness ceiling.** A construct must be typed if it crosses a plane boundary, is the object of an authority/budget/validity decision, must be ablated/attributed/diffed/stratified by the Lab, or must survive lowering to ≥2 targets/profiles. A construct may be opaque only as a `Text{content, owner, authority, provenance}` leaf or a `CompiledPayload{format_tag, bytes_hash, declared_interface{inputs, outputs, effects, deterministic, target}, owner, provenance}` leaf — i.e. only as the *body* of something whose interface is declared, never as a decider of authority/budget/validity, and always individually addressable. Anything else string-shaped is invalid (`OpaqueWithoutInterface` / `UnexpressibleSurface`).
4. **Surface records are profile-owned**: model-facing names, description templates, argument order/naming, error rendering and placement live in `surface`, are excluded from `semantic_id`, and are writable only by the Profile Compiler. The kernel schema has no field typed by model identity outside `ProfileRef`.
5. **Identity.** `version_id = H(canonical(node))`; `semantic_id = H(canonical(kind ∥ semantic ∥ refs-by-semantic_id))` with surface, provenance, ext and version records excluded and `Text` leaves contributing their content hash (Unison construction). Rename ⇒ `semantic_id` unchanged.
6. **Canonical form (OQ-041, joint with WS-B1).** Required. Class: *hash over a canonical form* — a JCS-class deterministic serialization of a JSON-model tree (sorted keys, no whitespace, UTF-8, integers or decimal strings, no Unicode normalization, no duplicate keys). Storage/wire encodings are free if they round-trip losslessly; hash function and canonical-form version are pinned per dialect (rotation: WS-L4).
7. **Effects.** `ToolCapability.effects: set<EffectClass>` with `EffectClass = {domain, attributes}` is an authoritative provenance-stamped declaration; `Procedure.effects` is derived; validation enforces V-EFF (`derived_effects ⊆ ∪ authorizes in scope`, coverage by domain + scope) as a graph query; MCP `ToolAnnotations` are a lowering *projection* of `attributes` (CF-047 confirmed, CF-041). **No static effect type system is required of the host language**; observed effects are enforced by the reference monitor (WS-H1).
8. **Answers for WS-L1 (OQ-040):** Q-L1-01 — closed sums required *as a property*, satisfiable by native exhaustiveness *or* schema validation + registry-completeness CI test ⇒ **C6 hard gate not triggered**; Q-L1-02 — recorded and consistency-checked, not statically effect-typed ⇒ **C6 hard gate not triggered**; Q-L1-03 — canonical form required, class as in (6); Q-L1-04 — structural diffs by identity; no IR↔source round-trip required.
9. **Opacity ratio (OQ-036):** `tokens of the compiled model-facing surface contributed by Text leaves ÷ total surface tokens`, per sealed definition per profile, tokenized by the profile's tokenizer or declared proxy; tool `purpose` prose counts as Text; reported with per-owner-class breakdown and `compiled_payload_count`.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: typed envelope around an opaque searched payload — ADAS archive `{thought, name, code, fitness, generation}` (S-023/S-170), AFlow `GraphOptimize{modification, graph, prompt}` + `operator.json` (S-015/S-025), GPTSwarm node/edge optimisation (S-020, ICML 2024); typed edit slots suffice for optimisers — DSPy `with_instructions`/`demos` (S-013/S-144); open unions fail late — OpenHands `DiscriminatedUnionMixin.resolve_kind` raises on unknown kind (S-110); protocol effects are hints, not declarations — MCP `ToolAnnotations` (S-153); content addressing with names as metadata — Unison (S-171); deterministic bytes — RFC 8785 (S-172); typed IR with unregistered ops and per-op verifiers — MLIR (S-173); enforcement outside the model — CaMeL (S-099); model-conditioned surfaces exist and matter — S-049, S-047, codex `models.json` (S-107, Tier B, via WS-L7).
- (b) Source-code precedent: `dspy/signatures/signature.py` L505–547 and `dspy/predict/predict.py` L71–120 (typed state slots; identity counter-example); `openhands-sdk/openhands/sdk/utils/models.py` L192–380 (open union), `tool/tool.py` L215–282 (annotations + tri-state resources); `modelcontextprotocol/schema/2026-07-28/schema.ts` L35–60, L1900–2016; `pyagentspec/src/pyagentspec/{component.py,versioning.py}` (dialect versioning, uuid identity); `pi-mono/packages/ai/src/types.ts` L345–450 (typed opaque provider leaves). The *combination* (closed kernel + registered ext + two opaque leaves + two-id identity + canonical form) is `no-precedent / novel` as an integrated discipline; each part is precedented.
- (c) Disconfirming evidence considered: "search spaces are code" (S-023, S-015, S-080) — answered by admitting `CompiledPayload` with declared interface; semantic identity is undecidable — answered by defining identity over the canonical semantic *projection*, not equivalence (CF-034); open unions work in production (S-110, S-139) — answered by layering (closed kernel, registered ext); static effect typing gives false confidence (S-153 hints; S-099 utility cost) — answered by consistency-check-at-validation + runtime enforcement; DSPy's identity-includes-instructions is arguably right for LM programs — answered by hashing `Text` *content* but not rendering (CF-039). None overturns: each objection is absorbed by a rule of the decision rather than contradicting it.
- (d) Conditionality: independent of model tier and task class; assumes definitions are small DAGs (≤10⁴ nodes) so graph-query validation is cheap; assumes profiles remain necessary (if frontier tool conventions converge, `surface` records shrink but the discipline stands — T-LCD-05 applies reflexively); the opacity metric assumes a tokenizer or declared proxy per profile.
- (e) Build-stage assignment: **C0 / Stage 1** (schema, `validate`, `canonicalize`, `identity`, `seal`); `opacity` at Stage 3 with T-LCD-02/-03; dialect migrations as needed from Phase 2 onward.

**T-LCD statement (ADR-0007 decision 5).** Satisfies: T-LCD-01 (no model-identity field outside `ProfileRef`/`surface`; no escape hatch in `ext`), T-LCD-02 (only two opaque leaf kinds; opacity ratio defined), T-LCD-06 (no dependency on the Hosting ABI), T-LCD-10 (identity excludes surface), T-LCD-12 (operations, not inheritance). Does not by itself satisfy T-LCD-03/-04 (executable, Stage 3, with WS-A4) — mitigated by AC-8 in the dossier and the equivalence-run gate.

## Consequences

- WS-A4 lowers `semantic` + `surface` per profile/target and must raise `UnexpressibleSurface` when a profile difference cannot be expressed in `surface` fields; extension slots carry non-LCD metadata through targets (T-LCD-11).
- WS-A5's component variants are `CompiledPayload`s behind Core contracts; their parameters and decisions are typed.
- WS-B1 stamps `semantic_id`/`version_id` of referenced entities on events and adopts the same canonical form (OQ-041 joint).
- WS-L4 pins hash function and canonical-form version per dialect and owns rotation.
- WS-L1: neither C6 hard gate fires; C6 is scored on how well an ecosystem delivers properties P1–P12 (dossier §6.11); WS-A3's veto is limited to P3/P4 failures.
- Every string-shaped construct in any later dossier must be declared as a `Text` or `CompiledPayload` leaf or be typed; "system prompt: string" is invalid.

## Reversibility

**Medium.** The closed-kernel/registered-ext split can be relaxed by ADR without touching stored documents; changing the canonical form or hash after Stage 1 invalidates every stored `semantic_id`/`version_id` and requires an identity migration (WS-L4), which is the costly direction — hence pinning per dialect from the first release.
