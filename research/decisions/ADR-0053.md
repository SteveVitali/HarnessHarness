# ADR-0053 — The reference-monitor TCB boundary (OQ-021), attenuating delegation for subagents, hosted participants and the evolution service, the self-modifying policy layer as an explicit threat actor, and pre-authorization in place of model-origin conferral

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-H1 (consumers: WS-H2, WS-H3, WS-H4, WS-H5, WS-H6, WS-H7, WS-F3, WS-I5, WS-I6, WS-J6, WS-K4, WS-D1, WS-B3, WS-B5, WS-E5, WS-A4/C3) · **Phase:** 2 · **Related:** ADR-0002 (ii, iii, iv — evolution cannot self-deploy or self-widen), ADR-0051/-2, ADR-0033/0034 (P2 delegation; RP invariant), ADR-0035 (rule 1: a `delegate` origin never endorses; `policy_rule` basis), ADR-0016/0017 (`delegated-to`; `AuthorityWidening`; MUST-code pointers), ADR-0019 (closed-world rule), ADR-0024 (MUST-code list), ADR-0040 (`budget_delta = loosening`), ADR-0046 (C4 admissibility), ADR-0049/0050 (sandbox helper out-of-process; ADR-0050 §8 clause (c)), ADR-0007 (T-LCD-05/-06/-07/-12/-14/-15); CF-118, CF-119, CF-121; OQ-021, OQ-045, OQ-135/-05/-07; R-2.8.1, R-2.8.5, R-2.8.7, R-2.9.5

## Context

Doc 2 §5.6 asks the harness to "minimize its trusted computing base" and lists what the monitor must know (provenance, capability scope, policy, target effect, approval points) and must not (task semantics); §11 requires the security kernel to be "outside the editable policy surface" before autonomous self-modification; ADR-0002 makes the evolution service a first-class threat actor for WS-H1 and forbids self-widening and self-deployment. OQ-021 asks for the smallest deterministic TCB. Production evidence pulls both ways: Anthropic's containment design ("environment layer first, then steer behavior at the model layer" — S-053) agrees on where enforcement sits, but shipping products let model-origin components confer authority — Claude auto mode (S-053: ~83% catch, ~17% miss) and Codex's synchronous Guardian reviewer (`core/src/guardian/decision.rs`: a model review returns a `ReviewDecision`; "no contributor is never an implicit allow"; `guardian-context/src/authorization.rs`: "Approval for an exact parent action does not grant general child permission"). S-104 (`provisional (mech)`) reports 13/13 objectives succeeding on every harness with automatic permission review enabled. Delegation lineage exists in Codex (`SubAgentSource::ThreadSpawn{parent_thread_id, depth}`) but no audited runtime checks `child ⊆ parent`; CapScope isolates per-issuer capability sets (S-105, `provisional`); Capsicum attenuates delegated rights and refuses re-widening (S-256, Tier A).

## Options considered

1. **Whole runtime in the TCB (monolithic trust).** *Rejected:* unverifiable; every variant, hook and MCP server would sit inside the TCB — the supply-chain failure doc 2 §5.6 names.
2. **Model-origin reviewer may confer (Guardian / auto mode as designed).** *Rejected:* violates ADR-0035 rule 1; S-104 shows automatic review stopping nothing; the same operating point is reachable by `definition` pre-authorization with the reviewer as a raise-only input.
3. **Evolution service edits policy under a "safety check" it runs itself.** *Rejected:* ADR-0002 (ii)/(iii); the checker would be on the surface the optimizer edits.
4. **Delegation by copying the parent's permissions (no attenuation record).** *Rejected:* widening by default; no cascade on revocation; ADR-0034 P2 already requires attenuation.
5. **Context builder stamps `context_label` as part of its variant contract.** *Rejected:* a swappable component would then be inside the TCB for the monitor's most important input (CF-118).
6. **An enumerated MUST-code TCB with the three Anderson properties as invariants; kernel-owned `context_label` stamping; a `delegate` operation with an attenuation chain covering subagents, hosted participants and the evolution service; evolution's root handle set fixed at `seal` with no self-widening path; `definition`-issued pre-authorization with model reviewers as raise-only inputs (chosen).**

## Decision

1. **TCB (inside; MUST-code; no `Text` leaf; no model call):** (i) the handle table projection, `mint_root_handles`, `authorize`, `delegate`, `revoke`; (ii) the label operations consumed from ADR-0033/0034 and the kernel's `context_label` stamp over the delivered-item list from which the kernel renders the model call (ADR-0019 closed-world rule); (iii) the deterministic risk assessors (path canonicalisation + containment, closed-grammar command classifier, host classifier) with recorded inputs; (iv) the Π interpreter; (v) endorsement-legitimacy and persistence-ceiling checks in the ledger append path (writer lease, fencing, canonical encoding — WS-B1); (vi) the approval verb (`security.permission.requested/decided`; approval-endorsement validation) — not its UX; (vii) the enforcement points the decision binds to: the effect gate (`authorized/refused` before `committed`), the out-of-process sandbox helper invocation (OQ-045; isolation primitives hostable in the ADR-0050 helper ecosystem — H4 designs them), the credential broker call (H3), the egress policy (H4); (viii) the `SurfaceArgMap` evaluator. **Outside:** the model and all prompts; every `Text`/`CompiledPayload` leaf; tools, executors, MCP servers, skills, hooks, plugins; the Profile Compiler (RP is defence-in-depth re-checked by a kernel validator on the compiled request); every component-class variant (context builder, compaction, control strategy, validators); judges/classifiers; the evolution service and the Lab; hosted participants; humans other than the run's principal (they act only through endorsement events the kernel validates). Spec §3's MUST-code list enumerates the TCB; adding to it is an ADR.
2. **Three properties as invariants.** *Complete mediation:* `committed` refused at append without a preceding `decided{allow}` for the `effect_id` (ADR-0052 decision 6). *Tamper-resistance:* handle table and Π reconstructible only from endorsement-validated events; `HirDiff.authority_delta = widening` rejected outside `human` origin; MUST-code pointers are content-addressed and on no layer's editable surface (ADR-0024). *Verifiability:* a static check proves the `authorize` path references no model-call operation and no `Text` reader (AT-H1-11); decisions replay from recorded inputs (AT-H1-07); the TCB is enumerated.
3. **`delegate(parent, child_spec, requested: [Grant], budget_req, at) → {child_handles} | AuthorityWidening | NotDelegable | BudgetExceedsParent | CeilingExceeded`.** D-1 every requested grant is covered by a `delegable` parent handle valid at `at` — scope-wise subset, attributes narrowing, constraints tightening; `child.ceiling = min(requested, eff(parent at spawn))` (ADR-0034 P2); requests are attenuated to what is coverable, never rounded up; D-2 child handles carry `parent_handle`; revocation cascades; parent `count` exhaustion exhausts children; D-3 child outputs enter the parent at `≤ delegate` with union taint; a parent proposal whose arguments derive from a child result is gated as tainted; D-4 hosted participants are children at the Hosting ABI boundary — the kernel holds their handles, refuses uncovered calls at the boundary, lowers `security.permission.requested` to the ABI permission verb (ACP `RequestPermissionRequest`) and lifts `allow_always` only to an H7 pattern cache, never a persisted grant; nothing native changes (T-LCD-06).
4. **The evolution service as a threat actor (D-5).** An evolution AgentProcess (`origin = evolution`, class `delegate`) receives a root handle set fixed at `seal`: `fs_read` on trajectories/ledger views, `memory_write` at scope `run` to the candidate store, `model_call`, `exec` in an isolated sandbox without network; **no** `permission_request` grant that could auto-resolve, no `delegable` grant, no scope covering the definition, Π, the handle table or any MUST-code pointer. Its outputs are `HirDiff`s; the kernel rejects `authority_delta = widening` (any grant widening or Π cell moving toward `allow`), `budget_delta = loosening` (ADR-0040), and any op on a MUST-code leaf; it cannot append `security.label.endorsed` (ADR-0035 rule 1); deployment is a `seal` endorsement by a `definition`-class human, never by the proposer (ADR-0002 ii). AT-H1-05 passing is a precondition for Stage 6 on the build ladder.
5. **Pre-authorization instead of model-origin conferral.** Unattended or low-friction operation is expressed as `definition`-issued handles minted at `seal` under a `policy_rule` basis from a `HarnessRule{trigger: EffectClass pattern ∧ risk pattern ∧ eff range, action: pre_authorize(scope, lifetime)}`, bounded by `authority_cap`, with an assumption-debt record when model-conditioned (T-LCD-05). A classifier, judge (`Validator{kind: judge}`) or Guardian-style reviewer may **withdraw** a pre-authorization for one proposal (raise to `ask`/`deny`) and may feed Π as a raise-only input; it can never create authority or resolve `ask → allow`. Extension hooks are admitted (WS-H5) under the same rule (CF-121).
6. **Delegation and hosting events.** `control.subagent.spawned` carries `child_handles[]`, `parent_handle`, `ceiling`; `lifecycle.hosted.*` rows carry the participant's handle ids; `security.permission.revoked.cascade[]` lists descendants.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-12 (operations; the monitor is implementable out-of-process — Flume precedent), T-LCD-06/-07/-15 (hosted children need no native change; undeclared capabilities are `unknown` and never granted; per-item checks `n/a` under low observability), T-LCD-14 (child budgets ≤ parent; evolution cannot loosen), T-LCD-05 (pre-authorization rules carry debt records), T-LCD-02 (no authority in any `Text` leaf). Not applicable: T-LCD-01/-03/-04/-08/-09/-10/-11/-13. Rung on the ADR-0024 ladder: TCB items are MUST-code; pre-authorization rules, allowlists and delegation requests are MUST-data.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** small, always-invoked, tamper-resistant, verifiable monitor — Anderson (S-251, Tier A); economy of mechanism, separation of privilege — Saltzer & Schroeder (S-252, Tier A); user-level monitor with untrusted computing processes — Flume (S-219, Tier A); attenuating delegation of rights, no re-widening — Capsicum (S-256, Tier A); object-capability attenuation — Miller (S-254, Tier A); "environment layer first" and classifier miss rates — S-053 (Tier B); automatic review defeated 13/13; persistent goals and scheduled tasks as vectors — S-104 (`provisional (mech)`); per-issuer isolated capability sets — CapScope (S-105, `provisional`, corroborating); a `delegate` origin never endorses; `policy_rule` basis — ADR-0035; child ceiling ≤ parent effective authority — ADR-0034 P2; evolution governance — ADR-0002; MUST-code list — ADR-0024; matched-budget evolution gates — ADR-0046.
- **(b) Source-code precedent:** `codex/codex-rs/core/src/guardian/{mod.rs, decision.rs}` and `guardian-context/src/{authorization.rs, reviews.rs}` (a model reviewer as approval contributor; non-transfer of approvals to children; per-action review scope — the counter-example decision 5 reshapes); `codex/codex-rs/protocol/src/protocol.rs` L2835–2850 (`SubAgentSource::ThreadSpawn` lineage, via ADR-0034) and L1103–1130 (`WritableRoot` protected subpaths — attenuation inside a delegated root); `software-agent-sdk/openhands-sdk/openhands/sdk/security/{ensemble.py, defense_in_depth/policy_rails.py}` (raise-only fusion); `agentdojo/src/agentdojo/agent_pipeline/pi_detector.py` (detector as a pipeline element); `claude-agent-sdk-python/src/claude_agent_sdk/types.py` L247–252 (`PermissionResultDeny.interrupt` — a deny that halts); `agent-client-protocol/schema/v2/schema.json` L487–545, L2031–2052, L6648. The enumerated TCB with the three properties as ledger invariants, the attenuation chain, the evolution root-handle rule and pre-authorization-with-raise-only-reviewers are **`no-precedent / novel`** as an integrated design.
- **(c) Disconfirming evidence considered:** model reviewers ship and reach a usable operating point (S-053; Codex Guardian) — the same point is reachable with the authority held by the definition author, and S-104 shows the alternative's failure mode; a kernel-owned `context_label` constrains context-builder variants — they keep full freedom over *what* to deliver, losing only the ability to mislabel it; delegation attenuation forbids legitimate "escalate to parent" patterns — expressed as a `permission_request` effect decided by the principal, never by the parent process; evolution under these constraints may be slower to find improvements — ADR-0002's governance is scope, not option; the sandbox helper being out-of-process adds a boundary to the TCB — accepted per OQ-045/ADR-0049 and revalidated by WS-B5/E5. None overturns.
- **(d) Conditionality:** independent of model tier and task class; assumes the ledger append path is fenced and durable-before-visible (ADR-0026/0029); assumes WS-H4/H3 enforcement points exist at Stage 1 in minimal form; delegation with subagents assumes WS-F3 (Stage 4); the evolution constraints bind only when C4 is built (Stage 6) but are specified now so the ladder can gate on them.
- **(e) Build-stage assignment:** **C0 / Stage 1** (TCB enumeration in Spec §3; kernel `context_label` stamp; no-text/no-model static check; complete-mediation append rule); **C0 / Stage 2** (pre-authorization handles; reviewer/hook raise-only admission; audit fields); **C0 / Stage 3** (AT-H1-05/-06/-07/-11/-13 executable); **C1 / Stage 4** (`delegate` with subagents and hosted participants; AT-H1-04); **Stage 6 gate** (AT-H1-05 must pass before evolution is reachable).

## Consequences

- WS-D1's contract returns the delivered-item list; the kernel stamps `context_label` (CF-118); WS-D1/C3 keep RP as defence-in-depth.
- WS-H7 designs fatigue mitigation as pre-authorization rules and pattern caches, never as a model approver (CF-119); WS-H5 admits hooks as raise-only (CF-121); WS-G3 judges feed Π upward only.
- WS-F3 calls `delegate` and never copies permissions; WS-J6/K4 enforce at the boundary and lower the permission verb; WS-I5 inherits D-5 and AT-H1-05 as admission criteria alongside ADR-0046's gates; WS-I6's assumption-debt records cover pre-authorization rules.
- Spec §3 carries the TCB enumeration; Spec §9's build ladder marks AT-H1-05 as the Stage 6 precondition (ADR-0002 consequence).

## Reversibility

**Low for decisions 2, 4 and 5** (removing complete mediation, letting evolution widen, or letting a `delegate`-origin component confer would contradict ratified ADR-0002 and ADR-0035 and reopen the S-104 class); **medium for the TCB enumeration** (items can move in or out by ADR with a static-check update) and **for the delegation operation** (attenuation rules can be tightened or extended by dialect bump).
