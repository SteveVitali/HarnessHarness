# ADR-0143 — Anti-leakage rules: benchmark policy never enters the harness (held-out surface never delivered; benchmark-conditioned rules refused at seal; split assignment before search; agent-phase egress `none`; contamination stratified, never pooled unannotated)

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-I4 (with WS-G1 held-out criteria and `MetadataShortcut`, WS-A5/A4 static checks at `seal`/`lcd_report`, WS-H4 network policy, WS-J4 report strata, WS-C1/L4 `training_cutoff_claim`, WS-I5 split discipline) · **Phase:** 2 · **Related:** ADR-0007 (T-LCD-01 analogue, T-LCD-05, T-LCD-13), ADR-0015/0016 (`ext` never decides validity; `Text` leaves), ADR-0018/0033 (`origin = import`, `authority = unverified`), ADR-0025 (`validate_assembly → seal`), ADR-0034 (persistence ceilings), ADR-0035 (endorsement basis; `principal` for `public` network), ADR-0038 (levels; pooling rule), ADR-0045/0046 (`LeakedSplit`, `task_split_hash`, outcome classes), ADR-0047 (veto invariants); WS-G1 (`HeldOutLeak`, `visible`/`held_out`, `reward_hacking_gap`), WS-H4 (`NetPolicy`, `residual_channels`); CF-305/-04/-08; OQ-016, OQ-340; R-2.9.4, R-2.9.2, R-2.8.4

## Context

OQ-016 asks how to measure harness effects "without leaking benchmark policy into the harness". Four distinct channels exist. (L1) Grader assets reach the run: Inspect's `Sample.target` sits beside `input`; τ-bench holds ground truth in the environment object; Harbor prevents it only by uploading `tests/` at verify time and Terminal-Bench by a static Dockerfile check; HAL strips declared ground-truth keys (dossier F1). (L2) Suite-specific rules live inside the harness: production harnesses carry SWE-bench-specific prompt scaffolds (Terminal-Bench's `task_openhands.yaml` template reproduces OpenHands' SWE-bench prompt), so a measured "harness effect" can be a benchmark-identity effect. (L3) Search on the evaluation split: ADR-0046 already refuses `artifact_benefit` on a split whose hash postdates the search (`LeakedSplit`) but nothing fixes *when* splits are assigned. (L4) Run-time egress: an agent can fetch the upstream fix; Harbor's default `NetworkMode` is `public`, Terminal-Bench forbids LLM access from inside the environment, WS-H4 defaults `net.mode = none`. (L5) Model contamination: SWE-bench Verified is memorised — 76 % buggy-file identification from issue text alone vs 53 % on external repositories (S-492, accepted venue), 3× localisation advantage vs fresh pools (S-493, `provisional`), and models reproducing problem statements and fix code (S-494, vendor audit, 2026-02) — which no instrument can prevent. WS-G1 already fixes `visible`/`held_out` criterion visibility, `HeldOutLeak` at `deliver`, the `reward_hacking_gap` metric and a `MetadataShortcut` veto over "a declared task-metadata scope — I4 declares the scope".

## Options considered

1. **Adapter discipline only (no kernel checks).** Rejected: the audited planes that rely on it expose leak-shaped records (Inspect `target`); evolving harnesses (WS-I5) read whatever the workspace exposes; leakage would be a convention, not a veto.
2. **Forbid any family- or task-conditioned behaviour in a definition.** Rejected: legitimate family-conditioned variants exist (browser vs terminal tool surfaces); forbidding them pushes conditioning into opaque `Text` (the T-LCD-02 failure) or into hosted participants only.
3. **Attempt contamination prevention (private tasks only, fresh tasks only).** Rejected as the sole rule: private suites are single-team artifacts with their own ~30 % flaw rates (S-495); fresh pools age; the instrument cannot author tasks (N13). Contamination must be *measured and stratified*.
4. **Five rules — three preventive kernel/static checks, one run-time containment default, one measured stratum (chosen).**

## Decision

1. **L1 — the held-out surface is never delivered.** `TaskRecord.held_out.*` (validators, fixtures, goal states, oracle solutions) never appears as a `context.artefact.delivered` payload (kernel predicate at `deliver`: `HeldOutLeak` — error and veto, WS-G1 I2), never sits in the materialised environment (`HeldOutInEnvironment` — import error; Terminal-Bench's Dockerfile reference check generalised to build context + workspace tree), and is excluded from `visible.task_metadata_scope`, which is the scope WS-G1's `MetadataShortcut` veto reads (CF-306). During the agent phase the grader mount is `fs.read.deny` in the effective H4 policy.
2. **L2 — `BenchmarkConditionedRule`.** A sealed Harness Definition (ADR-0025 `seal`) and its bound Model Profile (ADR-0020) may not contain a `HarnessRule`, `ProfileRule`, `Text` leaf, slot binding, parameter value or `ext` entry that references a `suite_id`, `task_id`, `foreign_id`, split label or family identifier **as a condition or selector**. Family-conditioned behaviour is expressible only as a registered variant whose `VariantRecord.applies_to_families` is chosen by the experiment and therefore appears as a factor level in every results row. Benchmark-specific instructions enter as task content through `expose()` with `origin = import`, `authority = unverified` — never as `definition` authority. The check runs in `validate_assembly`/`seal` and its findings are listed in `lcd_report.benchmark_conditioned_rules[]`; it is an **error, never a warning** (the T-LCD-01 analogue: `if suite == X` is the suite-conditioned counterpart of `if model == X`). Hosted participants are not checked (opaque); their capability declaration carries `benchmark_tuned ∈ {declared, undeclared, unknown}` and J4 stratifies on it.
3. **L3 — split assignment precedes search.** `SplitAssignmentRecord{suite_id, rule, seed, splits: map<split_label, [task_id]>, split_hash, registered_at}` is appended to the ledger before the first run of any experiment whose `Design.kind = adaptive_search` or whose arm has `search_budget > 0`; ADR-0046 `LeakedSplit` compares against this record; a task's `split_label` is immutable for the suite version (`SplitMutated` otherwise). `artifact_benefit` rows use only `held_out`/`private` labels; `search`/`dev` rows are reported as `search_time_benefit`.
4. **L4 — agent-phase egress defaults to `none`.** The task's declared network needs (`EnvironmentSpec.network{setup, agent, verify}`, lifted from Harbor `NetworkMode`/`allowed_hosts` or Terminal-Bench flags) are **claims** lowered into WS-H4 `NetPolicy` layers with `provenance.authority = unverified` and met with the kernel default; `allowlist` is honoured only for hosts the layer names; `public` requires a `principal`-endorsed amendment (ADR-0035 basis `approval`; H4 N4) and a `residual_channels` entry. Model calls leave through the kernel's gateway (WS-C1), never from inside the environment. `benchmark_egress` is a `trace_predicate` veto over `security.egress.attempted/blocked` during the agent phase to a non-allowlisted destination.
5. **L5 — contamination is measured and stratified.** Every `TaskRecord` carries `instrument.contamination{first_public_at?, stratum ∈ {private_held_out, fresh_temporal, public_dated, contaminated_public, unknown}}`; every `ModelSnapshotRecord` carries `training_cutoff_claim{value?, provenance}` (CF-310); `SuiteValidityRecord{audit_ref, audited_at, flawed_task_ids[], noise_ceiling?, retired_for_headline, reason?}` is a dated, content-addressed record referenced by every results row. The report generator renders capability **per stratum**, refuses to pool strata without an annotation (`StrataPooledUnannotated`, the ADR-0038 cross-level pooling rule applied to contamination), renders `n/a{observability}` when the cutoff claim is `unknown`, and renders headline capability `n/a{not_run}` for suites with `retired_for_headline = true` (they appear in round-trip and control rows only). An optional C2 diagnostic (`probe_memorization`, dossier §6.4) supplies *evidence* for a stratum, never a verdict (OQ-340).

**T-LCD statement.** Satisfies T-LCD-01 by analogue (L2 is the suite-conditioned branch check), T-LCD-05 (a family-conditioned variant is a declared component with an assumption-debt record, not a hidden rule), T-LCD-13 (delivery of visible items is the observable L1 relies on), T-LCD-14 (L3 keeps search and artifact benefit separable), T-LCD-15 (`n/a` for unknown cutoffs and retired suites; hosted `benchmark_tuned` is tri-state, T-LCD-07). Does not address T-LCD-03/-04/-11. ADR-0024 rung: L1/L2 checks are MUST-code in the kernel/assembler; L3/L5 records are MUST-data; L4 is a data default over H4's MUST-code mediator.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: held-out separation as the anti-hacking floor — WS-G1 F5 (SpecBench visible-vs-held-out gap, S-412 `provisional (mech)`), Harbor verify-time upload and Terminal-Bench Dockerfile check (Tier B/C source and process), HAL ground-truth stripping (Tier B source); benchmark-tuned scaffolds exist in production harnesses — S-490 `adapters/swebench/template/task_openhands.yaml` (Tier B source), S-133 "one of three native harnesses" (`provisional (mech)`), doc 2 §9 "names are surfaces"; search leakage — ADR-0046 (ratified), S-083 (`provisional (counter)`); egress as a leakage channel — WS-H4 F5 (Tier B), S-132 per-phase `NetworkMode` (Tier B); memorisation — S-492 (accepted venue, single team: 76 % vs 53 %), S-493 (`provisional`), S-494/-04 (vendor audits via secondary sources), S-496 (temporal decontamination as the field's response). C0 slices (L1 predicate, L2 static check, L3 record, L4 default) assert no performance number and rest on ratified ADRs plus Tier-A/B source; L5 is a *reporting* rule whose motivation is the accepted-venue paper corroborated by two further sources.
- (b) Source-code precedent: harbor `src/harbor/verifier/verifier.py L166–200` (tests uploaded at verify time), `models/task/config.py L36–70, L218–260` (per-phase `NetworkMode`, `allowed_hosts` normalisation), `trial/trial.py L191–262` (phase switch refused without `dynamic_network_policy`); terminal-bench `original-tasks/*/task.yaml` (canary header), TB2 validation "Dockerfile Reference Check" (S-124); hal-harness `hal/benchmarks/base_benchmark.py L84–100` (`_strip_ground_truth`, `_sanitize_attachment_paths`); SWE-bench `swebench/harness/run_evaluation.py L479–512` (run metadata records dataset/split). **`no-precedent / novel`:** the `BenchmarkConditionedRule` static check; `SplitAssignmentRecord` as a ledger precondition; contamination strata and `SuiteValidityRecord` as results-row annotations with a pooling refusal.
- (c) Disconfirming evidence considered: (i) legitimate family conditioning — answered by the variant/`applies_to_families` path and by refusing only identifier-conditioned rules; (ii) the static check may miss conditioning hidden in opaque `Text` (a prompt saying "on SWE-bench tasks…") — accepted: opaque leaves are already the T-LCD-02 opacity cost, the check scans `Text` for registered suite/task identifiers (string match on `foreign_id`/`suite_id` namespaces), and the residual is reported in the opacity ratio, not hidden; (iii) `none` egress breaks tasks that need package registries — answered by task-declared `allowlist` layers met with H4 and by Harbor's own `no-network` default for verified tasks; (iv) training cutoffs are unverifiable — answered: claims with provenance, `unknown` ⇒ `n/a`, and the stratified view is *beside* the pooled-with-annotation view, never replacing it; (v) contamination stratification could be read as authoring a decontaminated benchmark (N13) — answered: the instrument annotates and imports; the fresh pool is a third party's (SWE-rebench-class) and `retired_for_headline` is a *reporting* state, not an edit to any task. None overturns.
- (d) Conditionality: L1–L4 are model- and task-independent; L5 assumes `first_public_at` is recoverable for a suite (true for SWE-style tasks by commit date and for TB2 by release date; `unknown` otherwise); L4 assumes the kernel gateway is the only model path (C1 contract) — hosted participants with in-environment model calls (container-installed) obtain a `mediated` layer for the provider endpoint only, recorded as a residual channel.
- (e) Build-stage assignment: **C0 / Stage 1** — `HeldOutLeak` predicate, `HeldOutInEnvironment` and `BenchmarkConditionedRule` static checks, `SplitAssignmentRecord`, `SuiteValidityRecord`, contamination fields, `training_cutoff_claim`; **C0 / Stage 3** — L4 default wired through B5/H4 with the `benchmark_egress` veto, stratified reporting in J4, AC-I4-1/-2/-5/-7/-8; **C2 / Stage 5** — `probe_memorization` diagnostic; **C4 / Stage 6** — L3 enforced against WS-I5's search runs.

## Consequences

- WS-A5/A4 add the `BenchmarkConditionedRule` check to `validate_assembly`/`seal` and the finding list to `lcd_report`; WS-A3 confirms that `applies_to_families` on a `VariantRecord` is registry-level (OQ-344).
- WS-G1 consumes `task_metadata_scope`; WS-H4 accepts task network layers as `unverified` claims; WS-C1/L4 add `training_cutoff_claim` to `ModelSnapshotRecord` (CF-310); WS-J4 implements the per-stratum view and the pooling refusal; WS-J5 stores `SuiteValidityRecord` refs.
- WS-I5 inherits L3: no evolution run opens before the suite's `SplitAssignmentRecord` exists.
- Every "harness effect on suite A" claim in a HarnessHarness report carries `lcd_report.benchmark_conditioned_rules = []` for the arm and a contamination stratum for the tasks.

## Reversibility

**High for L3/L5 (records and reporting rules), medium for L1/L4 (kernel predicate and containment default — relaxing them silently re-admits tamper and fetch-the-fix runs into stored results), medium for L2 (dropping the static check is one line but would make every stored "harness effect" un-auditable against benchmark conditioning).**

## Amendment log (Phase 3 synthesis, 2026-09-10)

- L5 wording (CF-339; ADR-0157): `unknown` is its own stratum row in the strata view; the configuration headline is `n/a{observability}` only when *no* stratum is decidable (cutoff claim `unknown` for the snapshot); pooling any stratum with `unknown` requires the annotation (`StrataPooledUnannotated`). `probe_memorization` (OQ-340) is executed by WS-I4/C1 as an instrument-level diagnostic and rendered by WS-J4 as stratum evidence, never a verdict; no new `OracleDeclaration` class.
