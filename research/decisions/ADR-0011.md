# ADR-0011 — Product name: **HarnessHarness** (resolves OQ-035 / CF-013)

**Status:** ratified (sponsor decision, 2026-09-09, recorded by the orchestrator before Phase 1 launch)
**Owner workstream(s):** WS-L7 (naming), WS-L6 (packaging/OSS), WS-A2 (ontology v1) · **Phase:** 0→1 boundary · **Related:** ADR-0008 (canonical names), CF-013, OQ-035, S-118, S-149, S-150, S-080/S-151

## Context

WS-A1 and WS-L7 found that "MetaHarness" collides with at least four existing uses: ruvnet/metaharness (S-149), SuperagenticAI/metaharness (S-150), the Stanford *Meta-Harness* optimizer paper and repo (S-080/S-151), and Omnigent's self-description as "the open-source meta-harness" (S-118), where "meta-harness" already denotes a *hosting/control layer over many harnesses* — which is explicitly a non-goal (N3, ADR-0006). ADR-0008 retained the name provisionally with a public qualifier and escalated the choice to the sponsor (OQ-035).

## Options considered

1. Retain "MetaHarness" unqualified — *rejected:* four collisions, one of them the market meaning we disclaim.
2. Retain with a public qualifier — *rejected by sponsor:* still shares the token "meta-harness" with the hosting-layer meaning.
3. **Rename to "HarnessHarness" (chosen by sponsor).** The name names the thing: a harness (research instrument + reference runtime) *for* harnesses, without the "meta-" token that the market uses for hosting layers and optimizers.

## Decision

- The product/project name is **HarnessHarness**. The canonical-name table (ontology §6, ADR-0008) row "Product" is updated accordingly; all other canonical names (Harness IR/HIR, Harness Definition, native/hosted participant, comparison plane, Harness Lab, Hosting ABI, Model Profile/Profile Compiler, …) are unchanged.
- Rule: "HarnessHarness" is the proper noun; it never replaces canonical concept names in the spec (ADR-0008 rule 3). Where a spec sentence needs the product name, use "HarnessHarness"; where it needs the runtime, use "the reference runtime"; where it needs the instrument, use "the Harness Lab".
- Legacy references: the repository directory, docs 1–3, and Phase-0 artifacts keep the literal string "MetaHarness" as historical text; the Canonical Spec and every Phase ≥1 artifact use "HarnessHarness". Phase 5 assembly performs a glossary check (ADR-0008 rule 4) that flags any residual "MetaHarness" outside historical citations.
- WS-L6 owns the public-facing naming package (qualifier line, repository/package identifiers) in Phase 5; no sub-concept may use "meta-".

## Evidence (doc 3 §3.3)

- **(a) Mechanism evidence:** name collision is a market-positioning mechanism, not a performance claim; the collisions are directly observed (WS-A1 §competitive matrix; WS-L7 naming table; S-118 README, S-149, S-150, S-080/S-151).
- **(b) Source-code precedent:** n/a for a naming decision; the precedent surveyed is the set of colliding repos/papers above. Flag: `no-precedent / sponsor choice`.
- **(c) Disconfirming evidence considered:** "HarnessHarness" is unusual and may read as a typo; mitigated by the qualifier line WS-L6 will publish and by first-use expansion in the spec (ADR-0008 rule 1). No existing project of that name was found by WS-A1/L7 at 2026-09-09 (WS-L6 to re-verify before publication — OQ-035 follow-up).
- **(d) Conditionality:** none; a name is not model- or task-conditional.
- **(e) Build-stage assignment:** program-level; effective immediately for all Phase ≥1 artifacts; packaging identifiers at Phase 5 (WS-L6).

## Consequences

- Ontology §6 updated; OQ-035 resolved; CF-013 resolved.
- WS-A2 (ontology v1) and every Phase 1 dossier/ADR use "HarnessHarness".
- WS-L6 must run a collision re-check for "HarnessHarness" (repos, packages, trademarks) before Phase 5 publication planning.

## Reversibility

High before Phase 5 (a string substitution in program artifacts); medium after packaging identifiers are published.
