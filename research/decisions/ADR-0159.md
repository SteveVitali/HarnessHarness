# ADR-0159 — Frontier, transfer and benefit analyses: Pareto with origin, frontier-membership probability, cost-provenance strata and cost-of-pass; cross-model commensurability (OQ-094); transfer ratio, sign stability and conditionality region; synthesized search-time baselines from stored replicates; realized-benefit stages

**Status:** ratified
**Owner workstream(s):** WS-J4 (with WS-L2 cost/`MatchSpec`, WS-I2 benefit kinds, WS-I5 gates, WS-J6 hosted cost provenance, WS-K2 rendering) · **Phase:** 3 · **Related:** ADR-0046 (decisions 3–4, 6–7: consumption imbalance, three benefit kinds, adaptive selection, C4 gates), ADR-0041 (`MatchSpec` modes; `cross_model` admissible dimensions), ADR-0043 (`Money` provenance/confidence; "never averages provenance away"), ADR-0039 (kernel dimensions), ADR-0012 (portability = sign stability; conditionality region), ADR-0014 (realized-benefit decomposition), ADR-0045 (per-task (c, n) stored), ADR-0143 (split discipline; `LeakedSplit`), ADR-0007 (T-LCD-07/-09/-14/-15); OQ-033 (resolved; J4 confirms), OQ-094, OQ-124, OQ-370; CF-338; R-2.10.4, R-2.9.5

## Context

ADR-0046 fixed the matched-budget protocol and named three reportable benefit kinds, deferring estimation to WS-J4 and noting that "WS-J4's Pareto and surface views consume `budget_match.status` and cost confidence; mixed-confidence rows are stratified (OQ-033)". HAL includes the origin in its cost–accuracy frontier and pins the pricing date but reports no intervals (S-135, Tier A); Kapoor et al. show accuracy-only leaderboards select needlessly expensive agents (S-207); cost-of-pass formalizes the expected cost of one correct solution and its frontier over systems (S-509, ICLR 2026); Fowler et al. show that a frontier taken as a max over noisy samples is upward-biased (S-514, `provisional`). ADR-0043 gives every cost a provenance and a confidence; ADR-0041 admits `cross_model` matching only on spend/time/calls/approvals and refuses token matching (`IncommensurableMatch`). ADR-0046 decision 4 requires `search_time_benefit` "against a baseline given the same `SearchBudgetRecord` (test-time-scaling/discovery baseline per S-083, e.g. best-of-N with equal rollouts)" but no audited plane constructs such a baseline; the per-task (c, n) counts ADR-0045 stores make one computable. ADR-0012 defines portability as sign stability along the model axis and conditionality as the region where Δ > 0 with stated confidence.

## Options considered

1. **A scalar efficiency score (success per dollar) per configuration.** Rejected: collapses the frontier, hides provenance and uncertainty; is the "single harness score" T-LCD-09 forbids in another unit.
2. **Deterministic frontier over point estimates only (HAL practice).** Rejected as the *only* view: two configurations whose intervals overlap trade frontier positions by noise; mixed-provenance rows (participant-reported vs measured) would decide membership against each other.
3. **Frontier over point estimates with origin, plus per-configuration intervals, bootstrap frontier-membership probability, provenance strata and cost-of-pass; transfer profile with ratio/sign stability/region; synthesized, labelled search baselines; realized-benefit stages (chosen).**

## Decision

1. **Frontier.** `frontier(configurations[], capability_metric, cost_metric ∈ {spend, tokens, wall_ms, model_latency_ms}) → FrontierReport{points[{configuration_id, class, capability{point, interval}, cost{point, interval, provenance, confidence}, on_frontier, membership_probability, dominated_by[]}], origin: (0, 0), cost_of_pass[{configuration_id, point, interval}], strata{by confidence, by class, by capability_vector}, price_table_version, MatchSpec_ref}`. Invariants: the origin is always a frontier point (S-135); `on_frontier` is computed over point estimates; `membership_probability` = fraction of task-resamples (shared `ResamplePlan`) in which the point is non-dominated; rows with cost `confidence ≠ exact` are rendered as bands and **never decide membership against an `exact` row** (they may dominate or be dominated only within their own stratum, or when the band's worst case still dominates); a latency frontier is a separate `cost_metric`, never merged with spend; no point may be a max over samples unless that selection is itself an arm with its own cost (S-514 mechanism); `cost_of_pass = E[cost per attempt] / P(success)` per configuration (task-averaged, bootstrap interval), `n/a{estimator_undefined}` when the success interval includes 0.
2. **Cross-model commensurability (OQ-094).** Under `model_scope = cross_model` the engine differences or frontiers only on `spend` (pinned table), `time.*`, `model_calls`, `tool_calls`, `approvals.*` (ADR-0041 M1); token metrics are rendered per snapshot side-by-side and a request to difference them is `IncommensurableMatch`; no token-level normalization is admissible. Confirms OQ-033: Pareto and comparison views stratify by `CostProvenance` class and minimum `confidence` and render bands for non-exact rows.
3. **Imbalance display (OQ-124, display half).** Every `imbalanced` comparison attaches the frontier over the same rows as its cost-adjusted view; `budget_utilization` per dimension is shown beside; hosted arms with `limits_enforced = partial` carry a badge and a consumption band; tolerance values remain J3/L2's.
4. **Transfer.** `transfer(arm, baseline, held_out_factor, levels[]) → ComparisonReport{benefit_kind = transfer}[] + TransferProfile{transfer_ratio{point, interval} per level, sign_stability, conditionality_region, unknown_levels[]}` where `transfer_ratio = Δ_held_out / Δ_in` with a paired bootstrap interval, `n/a{estimator_undefined}` when Δ_in's interval includes 0; `sign_stability` = fraction of held-out levels whose Δ has the same sign as Δ_in with an interval excluding 0; `conditionality_region` = the probed levels where Δ > 0 with the interval excluding 0 (ADR-0012); a portability verdict on the model axis requires ≥ 2 families and ≥ 1 held-out level (AC-I2-10) and, for hosted rows, `model_override = SUPPORTED`.
5. **Benefit decomposition.** `benefit_decomposition(arm, baseline, splits)` computes ADR-0046's three rows from stored rows and adds: `search_baseline{kind ∈ {oracle_best_of_n, selected_best_of_n{selector_ref}}, n}` — `oracle_best_of_n` = pass@N of the baseline arm's replicates (S-235; an **upper bound**, labelled as such), `selected_best_of_n` only when the arm recorded a selector (majority/judge with `charged_to = instrument`); N = the search arm's rollouts per task from its `SearchBudgetRecord`; `n/a{estimator_undefined}` when the baseline has fewer than N replicates. Rows from adaptive selection carry `estimated{estimator = hajek, inclusion_probabilities_ref}` (ADR-0046 decision 6). The realized-benefit decomposition (ADR-0014 decision 3) is reported as four stages `P(valid) · P(activated | delivered, valid) · P(followed | activated) · E[Δ | followed]`, each with detector class, interval and n; judged stages require `model_io` and are `n/a{observability}` otherwise; no single "compliance score" is emitted.
6. **Hosted rows on frontiers (OQ-370, proposed).** Hosted arms with `search_budget = unknown` may appear on a frontier and in product-level comparisons flagged `search_unknown`; they never appear in artifact/search-time rows (ADR-0046 decision 1).

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-14 (three benefit rows computed; search baseline at equal search budget; `IncommensurableMatch` refusals), T-LCD-15 (bands and `n/a` for non-exact/hosted costs; realized-benefit stages `n/a` by observability), T-LCD-07 (frontier strata by `capability_vector`; `unknown` never coerced), T-LCD-09 (transfer over explicit factor levels; conditionality region over probed levels only), T-LCD-12. Not applicable: T-LCD-01/-02/-03/-04/-05/-06/-08/-10/-11/-13. **ADR-0024 rung:** frontier/transfer/decomposition algorithms and the commensurability refusal are MUST-code; admissible dimension lists, price tables and tolerance are MUST-data.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: frontier with origin and pinned prices — S-135 (Tier A); accuracy-only selection is costly — S-207 (Tier C, replicated); cost-of-pass — S-509 (accepted, single team); max-over-samples bias — S-514 (`provisional`, mechanism only); cost provenance must be stratified, never averaged — ADR-0043 (ratified); cross-model token matching ill-defined — ADR-0041 (ratified); search must be compared at equal feedback/inference budget with held-out transfer — S-083 (`provisional (counter)`), doc 2 §8 (Tier B), ADR-0002/0046 (ratified); pass@k as the oracle best-of-N — S-235 (Tier A); adaptive inclusion needs Hájek/IPW — S-082 (`provisional`); realized-benefit stages — ADR-0014 (S-077/S-088 `provisional (mech)`); conditionality/portability definitions — ADR-0012 (ratified); the PRISM shape "lift under budget, worst condition, repeatability" — S-093 (`provisional`), adopted only as the arrangement of already-computed fields.
- (b) Source-code precedent: `hal-harness/hal/benchmarks/base_benchmark.py` `process_results` @ 16bb03e (cost, latency, wall-clock per agent; the frontier's inputs) and S-135 text (origin); `hal-harness/reliability_eval/metrics/robustness.py` L32–58 @ 16bb03e (ratio `Acc(perturbed)/Acc(baseline)` clamped — the `transfer_ratio` shape; resampling corrected to paired); `inspect_ai/src/inspect_ai/scorer/_reducer/reducer.py` L164–189 @ 75f4891 (`pass_at` = oracle best-of-N from epochs; NaN below k); `METR/eval-analysis-public/src/horizon/plot/cost.py` @ 52cb829 (cost views beside success curves); `lmarena/arena-hard-auto/show_result.py` L124–222 @ 196f6b8 (covariate-adjusted comparison — the style-control precedent for `adjust_for` at C2). **`no-precedent / novel`:** frontier-membership probability; provenance-stratified frontier with band rows that cannot decide membership; a synthesized, labelled search baseline computed from stored replicates; `TransferProfile` with sign stability and conditionality region as a report.
- (c) Disconfirming evidence considered: (i) cost-of-pass is undefined/explosive near P(success) = 0 — answered by `n/a` when the success interval includes 0 and by the frontier view beside it; (ii) membership probability may crown undeployable points — answered: it is a field beside the deterministic frontier, with intervals visible and the origin present; (iii) oracle best-of-N is an unattainable baseline that makes search look bad — answered: labelled `oracle`/upper bound, with `selected_best_of_n` when a selector exists; the row's purpose is to bound the claim (ADR-0046 decision 4); (iv) spend depends on a price table that drifts — answered by `price_table_version` on every report and `pricing_ref` per estimated cost (ADR-0043); raw-resource frontiers (`time.*`, calls) need no table; (v) sign stability with two families is a coarse verdict — accepted; the region lists levels explicitly and the verdict carries its n; (vi) S-514's 82 % figure is single-team 2026 — not used. None overturns.
- (d) Conditionality: independent of model tier; assumes ADR-0043 cost records with provenance/confidence and pinned pricing exist per run (ratified; hosted rows may be `participant_reported`/`reconstructed` — rendered as bands); assumes ≥ N replicates in the baseline arm for a search baseline (else `n/a`); the model axis on hosted rows requires `model_override = SUPPORTED` (ADR-0013).
- (e) Build-stage assignment: **C0 / Stage 3** — `transfer` rows and `transfer_ratio` (ADR-0046's C0 operations), realized-benefit stages for deterministic detectors, `IncommensurableMatch` at report time. **C1 / Stage 3–4** — `FrontierReport` with membership probability, strata, cost-of-pass; `search_baseline` synthesis; KA-3/-6/-11. **C2 / Stage 4–5** — hosted strata by `capability_vector` (J6), judged realized-benefit stages (G3), `adjust_for` nuisance coordinates. **C4 / Stage 6** — I5 gates consume the artifact/search/transfer rows unchanged.

## Consequences

- WS-I2's `pareto_position` metric becomes an A4 report field (CF-338); `cost_per_success` is retained as a per-configuration metric and cost-of-pass is its interval-bearing frontier form.
- WS-J5 stores `FrontierReport`/`TransferProfile` with the reports' `price_table_version`; WS-K2 renders bands for non-exact rows and never a single "efficiency" number.
- WS-J3 records `SearchBudgetRecord.rollouts` per task so N is known and schedules ≥ N baseline replicates when a search-time row is pre-registered.
- WS-I5's gate "transfer on ≥ 1 held-out model family reported with sign and interval" reads `TransferProfile`; "search_time_benefit is reported" is satisfiable from stored rows without a separate baseline experiment when a selector or the oracle bound suffices for the claim.
- OQ-033 is confirmed resolved; OQ-094 is answered (spend/time/calls only); OQ-124's display half is answered; OQ-370 is proposed-answered (decision 6).

## Reversibility

**High for report fields (additive), medium for the commensurability refusal.** Admitting a token-normalization scheme later is a data change under ADR-0041 (C1 pending OQ-094) and would re-render stored frontiers without loss because per-snapshot token figures are stored; dropping membership probability or strata would silently re-admit noise-driven and provenance-mixed frontier claims, which is the cost the decision avoids.
