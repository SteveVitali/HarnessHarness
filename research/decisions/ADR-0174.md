# ADR-0174 — The external-caller model for the MCP server: `CallerBinding` → an `OpaqueProcess` caller at `delegate` by default (`principal` only for sealed human-principal bindings); identity from the transport binding, never from the request; handles are names with kernel-held authority; reads are `ExposurePolicy` sinks with `readers` enforcement and export accounting; the surface session is a `kind: surface` run with `charged_to` split and budgeted rate limiting

**Status:** ratified, amended (Phase 3 synthesis)
**Owner workstream(s):** WS-K3 (consumers: WS-H1, WS-H3, WS-H5, WS-H6, WS-H7, WS-L2, WS-L3, WS-I1, WS-B1, WS-J5, WS-J6, WS-K4) · **Phase:** 3 · **Related:** ADR-0018 (`OpaqueProcess`), ADR-0027 (`surface_ids`; `causes[]`), ADR-0026/0029 (surface session as a run; offload), ADR-0030/0031 (effect lifecycle; risk class), ADR-0033/0034/0035 (authority classes; `delegate` never endorses; `readers`), ADR-0039/0040/0041 (charges; budget nodes; `charged_to`), ADR-0042/0044 (views; sinks; `measurement.export.delivered`), ADR-0051/0052/0053 (handles H-1…H-7; `authorize`; hosted children at the boundary D-4), ADR-0057/0058 (`SecretRef`; broker), ADR-0063/0064 (`TrustRootPolicy`), ADR-0068 (tombstones; retention floors), ADR-0070/0071 (approvals; `ApproverGrant`; approvals budget), ADR-0097/0099 (claims never decide; `ProtocolBinding`), ADR-0130 (idempotent work injection), ADR-0141 (`PublicationPolicy`), ADR-0050 D3; CF-364, CF-367; OQ-103/OQ-139, OQ-246, OQ-395, -04, -06, -07; R-2.11.3, R-2.8.1, R-2.1 (resource accounting)

## Context

An MCP server has no session and no protocol-level notion of a caller: MCP 2026-07-28 says cross-call state is an explicit handle that is "a name, not a capability" whose authorization the server "should validate … on every call" (S-153 `server/tools.mdx` L683–737); the tasks extension makes it a MUST ("servers MUST perform authentication and authorization checks on each task-related request"; task ids as bearer tokens only with sufficient entropy — S-554 L900–905); servers "MUST … implement proper access controls [and] rate limit tool invocations" (S-153 `tools.mdx` L789–793); on HTTP the caller is an OAuth 2.1 bearer whose token's audience must be this server and must never be passed through, while on stdio OAuth "SHOULD NOT" be used (S-153 `basic/authorization/index.mdx` L21, L283–297). Machine callers with "no user present" authenticate as clients (S-555), and a *model provider* can be the MCP client of an evaluation harness's server (S-136 `tool/_mcp/server.py` `execution = "remote"`). HarnessHarness mints `principal` "only for the run's human principal" and `delegate` "for every AgentProcess output" (ADR-0033); "a `delegate` origin never endorses" (ADR-0035 rule 1); hosted participants are children whose handles the kernel holds at the boundary (ADR-0053 D-4); every accountable event posts a charge with `charged_to ∈ {subject, instrument}` (ADR-0039); every delivery to a sink is `measurement.export.delivered` under a `SinkPolicy` (ADR-0044); a peer-reviewed census shows agents assembling legitimate read tools into disclosure chains for want of least privilege (S-371). The only audited case of caller context in `_meta` is confined to a first-party stdio server, read-only, zero-argument tools (S-107 `codex-mcp/src/trusted_access.rs` L26–62); the audited auto-approval adapter (S-110 `acp_agent.py` L1579–1596) is the failure mode in the other direction.

## Options considered

1. **Caller identity and privileges from request content** (`clientInfo`, declared capabilities, a HarnessHarness-prefixed `_meta` key, or a handle string itself as a bearer capability). *Rejected:* forbidden by the spec's own display-only and untrusted-hint rules and by ADR-0099 T2; handle-as-capability is what ADR-0051 H-1 forbids.
2. **Caller = the run's `principal` whenever it presents the principal's token** (the OAuth default). *Rejected:* the token authenticates an account, not authorship; the content an agent authors is model output (`delegate`, ADR-0033) and letting it approve its own run's `ask` is S-104's "automatic review approved 13/13" by another route (ADR-0053 decision 5).
3. **Caller = `unverified` for everything not human-driven.** *Rejected:* an `unverified` proposer could never launch anything under ADR-0052's defaults, making the surface useless for its primary callers (agents, CI, providers); `delegate` with kernel-held, non-delegable handles is the least privilege that still works.
4. **Per-caller narrowing of the catalogue as the authorization mechanism.** *Rejected:* violates list invariance (ADR-0097; ADR-0173 decision 5); listing is not authorization.
5. **Unaccounted server work** (charge only launched runs). *Rejected:* ADR-0039 R-ACC-2 "nothing is unaccounted"; judged analyses and compile calls spend real resources; without a surface-session ledger the S-371 disclosure chain is unauditable.
6. **Chosen:** `CallerBinding` sealed data → `OpaqueProcess` caller; class by binding kind with `delegate` default; identity from the transport binding; handles as `surface_ids` names with kernel-held authority; reads as policy-governed sinks; the surface session as a run; rate limits as budgets.

## Decision

1. **Records.** `CallerBinding{binding_id, credential: {stdio_launch(launched_by: PrincipalRef, launch_event: EventRef) | oauth(issuer_ref, subject_kind ∈ {user, client}, audience = canonical server uri) | mtls(cert_ref)} (secret values only as H3 `SecretRef`), principal_ref: PrincipalRef, caller_kind ∈ {agent, human_principal, provider_client, service}, authority_cap ≤ principal, permissions: [Permission ref] ⊆ the exposure definition's, budget_node: Ref<BudgetNode>, readers_identity: PrincipalRef, rate_policy?: HarnessRule ref, expires_at?}` — sealed in the exposure definition (ADR-0173) or minted at `seal` from a `TrustRootPolicy` row for an OAuth issuer (ADR-0063). On first call the kernel creates `CallerProcess = AgentProcess.hosted = OpaqueProcess{participant_ref: binding_id, hosting_mechanism: session_abi, declared_capabilities ← ProtocolBinding.capabilities_declared (tri-state, ADR-0099 N3), observability_levels: {events}, supplies: ∅, budget: binding.budget_node, permissions: binding.permissions}` — a hosted child at the boundary in ADR-0053 D-4's sense; nothing native changes (T-LCD-06).
2. **Identity from the binding, never from the request (R-1).** stdio: the caller is the spawner named by a `stdio_launch` record the spawner (CLI surface, J6 adapter, or a kernel `spawn_process` effect) writes before the server accepts its first request; no OAuth on stdio. Streamable HTTP: per request, the H3 broker validates the bearer token (issuer-keyed; audience = this server's canonical URI, RFC 8707; never passed through; `insufficient_scope` answered with the spec's step-up challenge) and maps it to a `CallerBinding`; the mapping may be cached by token digest for ≤ the token's lifetime; there is no session (SEP-2567). A `subject_kind = client` issuer (client credentials) can bind only `caller_kind ∈ {service, provider_client}`. An unbound request is refused at the transport (HTTP 401/403 per spec; stdio: the server exits).
3. **Authority class (R-2).** `authority(caller) = min(binding.authority_cap, kind_ceiling)` with `kind_ceiling(agent | provider_client | service) = delegate` and `kind_ceiling(human_principal) = principal`. Caller-authored content enters as `Text{authority ≤ external}` for `delegate` callers (ADR-0033 minting: free text from a delegate is `external`) and as `principal`-authored content only for `human_principal` bindings. A `delegate` caller never endorses: `respond_approval` (and a `tasks/update` or MRTR answer that would resolve an `ask`) from such a caller is `IllegitimateEndorsement` (ADR-0035 rule 1; ADR-0070 decision 3), including for runs it launched; approvals route to the run's principal through H7 or to a caller holding an `ApproverGrant` (ADR-0070 decision 6). `service` bindings run in `unattended` mode (`ask → deny`, ADR-0052 check 7). This is the mirror of ADR-0097 decision 3 (HarnessHarness as *client*): an elicited answer is `principal`-authored only when the answering party is a human principal (CF-364).
4. **Claims never decide (R-3).** Inbound `_meta` is read only for `io.modelcontextprotocol/protocolVersion` and `clientCapabilities` (result-shape gating: MRTR only with `elicitation.form`; task results only with the tasks extension — S-554 L61) and for `traceparent/tracestate/baggage` (lifted into `causes[]`, ADR-0042); every other key is preserved in `ext` with no authority (ADR-0099 N4/T2); `clientInfo` is display-only. No caller-supplied entitlement or context key exists in K3 (the codex precedent is the ceiling, not a template).
5. **Handles are names; authority is the kernel's (R-4).** Lab tools return **surface handles** (`run_handle`, `experiment_handle`, `session_handle`, `plan_handle`, page cursors) that are `surface_ids` aliases of allocated ids (ADR-0027) — opaque; high-entropy and short-lived on unauthenticated stdio; bounded by the surface session's lifetime or the object's retention floor (ADR-0068). A call carrying a handle is a proposal evaluated by `authorize` (ADR-0052) with the handle resolved to its allocated id and matched by `ResourcePattern` over canonical parameters (ADR-0051 H-5): a caller holds a covering `AuthorityHandle` only for objects its own `CallerProcess` created (minted at creation, `origin_basis = delegation`, `parent_handle` = the binding's root handle, `delegable = false`) or that a sealed `Permission` grants (e.g. `scope: runs_of(principal_ref)`, `readers`-checked). Unknown/expired handles are tool execution errors (`isError`, `structuredContent.refusal ∈ {UnknownHandle, HandleExpired}`), never protocol errors. `HandleId`s of authority handles never appear in any result (H-1; `HandleLeak` static check on the exposure definition's `model_surface` and runtime check on every rendered result).
6. **The surface session is a run.** On first call the server opens a ledger with `run_kind = surface` (the WS-J3 "experiment is a run" shape; discriminator proposed to WS-B1, CF-367): manifest `{binding_id, bundle_id, catalogue_hash, protocol_bindings[], caller_process}`; each `tools/call` is a turn with the ADR-0030 effect lifecycle (`security.permission.decided` before any `committed`; write-ahead `committed` before dispatch for non-`read_only` classes) and the frozen `(bundle_id, catalogue_hash)` on the turn; runs/experiments it launches carry `causes[] ∋ EventRef(surface session, launching effect)` on `lifecycle.run.created` (no new field). The server holds no state that is not a projection of this ledger. Work-injecting tools carry an `idempotency_key` (ADR-0050 D3 as amended; ADR-0130) and a repeat returns the recorded result.
7. **Charges and budgets.** Every accountable event in a surface-session turn posts `control.budget.consumed` against `binding.budget_node` (ADR-0039 R-ACC-2): server work (catalogue serving, assembly/validation, queries, judged analyses) is `charged_to = instrument`; a launched run's root `BudgetNode` is `allocate(parent = binding.budget_node, mode = slice, spec = launch.budget)` (ADR-0040) and its consumption is `charged_to = subject` on the child, visible to the binding's pool by containment only. `InsufficientBudget` at `allocate` refuses a launch before any environment is provisioned; a launch without a `BudgetSpec` is `MissingBudget` (T-LCD-14). Rate limiting (the spec's MUST) is the binding's budget: `tool_calls`, `time.wall_ms`, `spend`, `approvals.requested` with `reserve` before dispatch; exhaustion is an `isError` result `budget_exhausted{dimension}`, never a protocol error (a windowed gauge, if needed, is OQ-399). Results of spending tools and `run_status` carry `structuredContent.account = ResourceAccount{consumed, remaining (hard dimensions), spend{Money{micro_units, currency}, confidence}}` — the declared `narrowed` lowering of a `TokenVector` (`NoPrice` → `n/a{reason}`, never 0).
8. **Reads are sinks.** `ExposurePolicy = PublicationPolicy{readers, content_classes ⊆ {accounting, structural, content} (default {accounting, structural}; `content` by `readers` only; `diagnostic` never), redaction, requires_consent (hosted L2), page_limit, max_field_bytes}` (ADR-0141 decision 4 / ADR-0044 `SinkPolicy` shape; MUST-data under `authority_cap`). Every `read_ledger`/`query_rows`/`get_trace`/`export_rows` page (a) withholds items whose `readers ∌ binding.readers_identity` and lists them as `withheld[{ref, reason ∈ {readers, content_class, consent, redacted}}]` — never silently and never as an empty page for an existing object (S-153 `resources.mdx` L410); (b) serves redacted items as tombstones (ADR-0068); (c) appends `measurement.export.delivered{sink: mcp_surface(binding_id), items, content_classes, loss_report_ref}` to every cited run (ADR-0044; granularity OQ-396). The server is a declared exporter and subscriber, never a store (ADR-0042).
9. **Supply surfaces.** For a harness bundle served to a hosted participant, the J6 adapter writes the binding at `open` (`launched_by` = the hosted run's `OpaqueProcess`); the proposer of every `tools/call` is that process; its handles are the ones ADR-0053 D-4 says the kernel holds; `callable ⇔ revealed` holds because the served surface is the whole compiled surface minus `hidden` (ADR-0093); results follow the bundle's `ResultRenderSpec` under the surface's profile binding (OQ-393).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: handle-as-name with per-call authorization, opacity, bounded lifetime and expiry as execution errors (S-153 `server/tools.mdx` L683–737); auth binding on every task request; task ids as bearer tokens only with entropy; "a task is not a higher-trust channel" (S-554 L900–905); access control, rate limiting and output sanitisation as server MUSTs (S-153 `tools.mdx` L789–793; `resources.mdx` L428–434); OAuth 2.1 audience binding, no passthrough, stdio without OAuth (S-153 `authorization/index.mdx` L16–26, L283–297; `security-considerations.mdx` L107–128); machine callers as clients (S-555); provider-as-client (S-136 `server.py` `execution = "remote"`); the read-tool disclosure-chain failure mode and its least-privilege root cause (S-371, peer-reviewed); authority is a kernel record, never a string (ADR-0051 H-1/H-5; S-253/S-254/S-255 via ADR-0051); `delegate` never endorses (ADR-0035); approvals per `effect_id`, `ApproverGrant` (ADR-0070); nothing unaccounted and `charged_to` (ADR-0039); every delivery is `export.delivered` under a sink policy (ADR-0044); `readers` labels (ADR-0033); hosted children at the boundary (ADR-0053 D-4).
- (b) Source-code precedent: codex `codex-rs/codex-mcp/src/trusted_access.rs` L26–62 and `client_capabilities.rs` L11–31 @0735c51 (caller context confined to first-party/read-only/zero-arg; foreign extension namespaces dropped — adopted as the ceiling); codex `codex-rs/app-server-protocol/src/protocol/common.rs` L1741–1777 @0735c51 (`item/*/requestApproval` are requests to the *client*, i.e. the human surface, never answered by the agent); codex `codex-mcp/src/binding.rs` L168–305 (`PreparedMcpCall` bound to an exact permission profile and output budget); software-agent-sdk `openhands-sdk/openhands/sdk/agent/acp_agent.py` L1579–1596 @3fc7b22 (adapter auto-approval — the counter-example decision 3 forbids); gemini-cli `packages/core/src/tools/mcp-tool.ts` L207–216 @ed2ac40 (location-trust short-circuit, via ADR-0097 — counter-example); inspect_ai `src/inspect_ai/tool/_mcp/server.py` L14–110 @75f4891 (provider as MCP client). The `CallerBinding` → `OpaqueProcess` model, the surface-session ledger and the `charged_to` split for an exposed surface are `no-precedent / novel`; the read-as-sink rule is ADR-0044/0141 applied.
- (c) Disconfirming evidence considered: (i) human-operated MCP clients hold the principal's token and want to approve in-band — answered: `caller_kind = human_principal` is a sealed binding kind that enables exactly that (MRTR/`tasks/update` become the ADR-0070 lowering); the default is `delegate` because the audited caller population is agents and "the model may propose, only the runtime confers" must survive the agent holding the human's token. (ii) `delegate` callers cannot self-serve approvals, slowing unattended pipelines — answered: unattended operation is `definition`-issued pre-authorization (ADR-0053 decision 5), never caller-side approval. (iii) Per-page export events inflate the ledger — answered: L0/L1 envelopes, offload above threshold (ADR-0029), and the only auditable defence against the S-371 chain; granularity is OQ-396. (iv) A surface-session run per binding is heavier than a stateless request log — answered: it is the same shape J3 chose for experiments and the only way to satisfy R-ACC-2 and `audit_completeness` for external use. None overturns.
- (d) Conditionality: independent of model tier; assumes H3's broker and issuer keying exist at the HTTP tier (ADR-0097 decision 7); assumes `PrincipalRef` forms per OQ-139 (an OAuth `subject_kind = user` maps to `user(id)`, a client id to `tenant(id)` or a `service` record — OQ-395); assumes WS-B1 accepts `run_kind = surface`; assumes WS-J3's launch step shape (allocate before provision) ratifies; the entropy/lifetime rule for stdio handles assumes an unauthenticated local caller population; no `provisional` result is load-bearing.
- (e) Build-stage assignment: **C0 / Stage 3** `stdio_launch` bindings for the fixture server, R-3, R-4 for run handles, `HandleLeak` checks; **C1 / Stage 4** OAuth bindings via H3, the surface-session ledger, charges and budgets (decisions 6–7), `ExposurePolicy` reads (decision 8), supply-surface bindings (decision 9); **C2 / Stage 5** `human_principal` approval channels over MRTR/tasks, `provider_client`/`service` bindings via client credentials, resource subscriptions bound to bindings.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-06 (callers are `OpaqueProcess` children; no native contract changes), T-LCD-07 (declared client capabilities are tri-state claims; `unknown` never coerced), T-LCD-10 (authorization over canonical parameters and allocated ids, never over tool or handle names), T-LCD-12 (records-in/records-out; the binding table and surface session are projections), T-LCD-14 (no unbudgeted launch; budgets contain), T-LCD-15 (`withheld[]` and `n/a` are typed, never 0 or empty), T-LCD-02 (no authority in any `Text` leaf; handles never in text). Does not by itself satisfy T-LCD-11 (carried by ADR-0173/-3's loss reports) or T-LCD-03/-13. **ADR-0024 rung:** caller resolution, `authorize` interposition, handle aliasing, the surface-session ledger, charge posting and sink enforcement are MUST-code; `CallerBinding`s, `ExposurePolicy`, Π rows, budget specs and rate policies are MUST-data with `authority_cap` (widening a binding's `authority_cap` or `readers` set by a non-human origin is `AuthorityWidening`).

## Consequences

- WS-B1 adds `run_kind = surface`; WS-H1 confirms `origin_basis = delegation` handles for caller-created objects and the `runs_of(principal_ref)` pattern (OQ-132 grammar); WS-H3 owns issuer keying, audience validation, step-up and client-credential issuers; WS-H7 owns the routing of a launched run's `ask` to its principal when the launcher is a `delegate`; WS-L3/H2 answer OQ-395 with OQ-139.
- WS-L2 confirms rate limits as budget dimensions (OQ-399); WS-I1/H6 confirm per-page `export.delivered` and whether subscriptions are sinks (OQ-396).
- WS-J6 writes supply-surface bindings at `open` and inherits AC-K3-9 as the server-side half of AC-J6-4; WS-K4's SDK client is a `human_principal` or `agent` binding like any other caller.
- OQ-246 (approval persistence across an edge) gains a K3 constraint: `allow_always`-class answers are admissible only from `human_principal` bindings and are ledgered policy amendments scoped ≤ run.

## Reversibility

**Low** for decisions 3–5 (they are ADR-0033/0035/0051/0053/0070 applied; reversing them reopens the S-104 class through the MCP edge); **medium** for the surface-session run (removing it orphans charges and export accounting for external use; adding fields is a schema bump); **high** for binding kinds, policy defaults and rate dimensions (data).
