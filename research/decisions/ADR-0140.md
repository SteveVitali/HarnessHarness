# ADR-0140 — Bundle validation and reproducibility-level contract: staged `validate_bundle` with complete-vs-valid status, a basis-derived `max_supported_level`, per-level `reproduce` procedures, and `ReproReport` with independent reproduction

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-I3 (consumers: WS-I2, WS-J3, WS-J4, WS-J5, WS-J6, WS-I4, WS-I5, WS-I7, WS-B4, WS-H6, WS-C1, WS-C3, WS-B5) · **Phase:** 2 · **Related:** ADR-0038 (levels R0–R3, `check_completeness`, `reproduce`, `ReproReport` — refined, not superseded), ADR-0036 (identity, `idp`), ADR-0028 (deterministic replay as declared capability), ADR-0026/0029 (rebuildability, chain), ADR-0045/0046/0047 (rows, `compare`, margins, budgets, oracles), ADR-0020 (profile expiry), ADR-0019 (`derivation_key`), ADR-0025 (`validate_assembly` discipline), ADR-0044 (audit completeness), ADR-0007 (T-LCD-09/-12/-14/-15); ADR-0139; OQ-113 (margins), OQ-111 (fingerprint), OQ-082 (counterfactual validity), OQ-334/-06; R-2.9.3, R-2.10.5

## Context

ADR-0038 defined R0 recorded / R1 bit-exact (derivation) / R2 semantic (re-execution) / R3 statistical, the rule that a claim above what pins allow is `ReproClaimUnsupported`, and the operations `check_completeness` and `reproduce`. It did not say how the maximum supportable level is *derived*, what a validator checks in what order, what a reproduction procedure does per level, or who may call a result reproduced. The audit finds the derivation rung practised (Harbor `regrade`: re-verify from recorded outputs if "every artifact required by the updated verifier was collected"; SWE-bench `submit verify`: re-grade from recorded test output), the validation rung practised as a *lifecycle* (SWE-bench checklist and `checked`; Terminal-Bench 2.1's five trials, CI validation and maintainer trajectory review), and the vocabulary already standardized: ACM v1.1 distinguishes repeatability (same team, same setup), reproducibility (different team, same artefacts) and replicability (different team, different setup) "with stated precision", with badges *Artifacts Available / Evaluated / Results Reproduced*. Provider nondeterminism at temperature 0 (WS-C1 F7) and silent provider drift (S-047) mean re-execution can only be semantic or statistical. WS-A5's `validate_assembly` fixed the discipline that every stage runs and reports, never fail-fast.

## Options considered

1. **Binary `check_completeness` only** (ADR-0038 minimum). *Rejected as insufficient:* it cannot tell a consumer which level they may claim, which member blocks a higher level, or whether payload integrity holds; it conflates complete with valid.
2. **Level assigned by the producer's assertion, verified only by re-execution.** *Rejected:* re-execution is expensive and stochastic; the maximum must be derivable statically from pins so that a claim is refused before budget is spent (T-LCD-14 discipline applied to reproduction).
3. **Reproduced status by self-report.** *Rejected:* a producer re-running its own artefacts is repeatability, not reproducibility (ACM); the status must require a distinct installation and signer.
4. **Staged validator with derived maximum level and per-level procedures; `ReproReport` with `independent`; ACM mapping (chosen).**

## Decision

1. **`validate_bundle(bundle, mode, policy?) → BundleValidationReport`** runs the requested stages **S1 structural, S2 self-identity, S3 integrity, S4 completeness, S5 closure, S6 ledger, S7 level, S8 policy, S9 cross-section** (dossier §6.4 table with failure codes), all reported, never fail-fast; reads only bundle bytes (plus `fetch` if permitted); `status ∈ {valid, complete_not_valid, incomplete, invalid}`; `derived{max_supported_level, basis[], missing[], fetchable[], foreign[], unpinned[], redacted[], gc[], payload_size}`; the report is a versioned sidecar record with `view_hash`, and two implementations agree on it for the golden corpus. `check_completeness` (ADR-0038) is `validate_bundle` with `{S1, S2, S4, S7}`.
2. **Basis-derived maximum.** `reproducibility.basis[]` lists `LevelBasis{level, requirement_id, satisfied_by: MemberRef | Unpinned}` for the closed requirement set `B-R0-{traces, complete, instrument}`, `B-R1-{canonical, derivations, replay}`, `B-R2-{model, environment, closure, seed, nondeterminism}`, `B-R3-{budget, fingerprint, design}` (dossier §6.5); `max_supported_level` is the highest level whose every requirement is satisfied by a **member** (a claim or foreign digest never satisfies a requirement above R0); the ADR-0038 rules remain the semantics (`pinned = false ⇒ no R2`; `dirty ⇒ R0`; hosted ⇒ R2 only with `end_state`); class-inapplicable requirements are `n/a{class}` and neither block nor count. `claimed_level > max_supported_level` is `ReproClaimUnsupported` at S7.
3. **`reproduce(bundle, level, seeds?, reproducer) → ReproReport`** per level: **R0** full validation; **R1** delete-and-re-derive every view, results row, report, the compiled bundle from pinned inputs, and the manifest, comparing hashes, plus the ADR-0028 replay driver for declared variants (`control.decision` and `view_hash` sequences); **R2** `open_run` from the bundle's `configuration_version_id` materials, `n ≥ pre_registration.min_n` paired re-runs with the recorded seed material, `compare` (ADR-0046) on the named validator set and end-state class against the pre-registered margin; **R3** the R2 procedure over `seeds[]`, model roles allowed unpinned with `observed_fingerprint` before and after, distributions compared under `MatchSpec`. Invariants: refuses `UnmatchedBudget` (T-LCD-14); every re-run is an ordinary ledger run charged `attribution.charged_to = instrument` and linked `causes[] → bundle_ref`; the bundle is never mutated; margins come only from `pre_registration` (OQ-113), never from the caller.
4. **`ReproReport`** = `{report_id, bundle_ref, level, procedure: version_id, reproducer: ProvenanceRecord, reproducer_instrument: InstrumentRecord, independent: bool, verdict ∈ {reproduced, not_reproduced, inconclusive, n/a{reason}}, per_member_hash_checks[], per_validator_agreement[]: {validator, (c, n)}, end_state_diff_ref?, distributions?: ComparisonReport{benefit_kind = artifact}, nondeterminism_sources_observed[], budget_match, seeds[], cost}`; `independent = true` iff the reproducer's installation and signer differ from the producer's (attested under WS-H6; how distinctness is established is OQ-334). Disagreements are inspectable (`end_state_diff_ref`, per-validator counts), never averaged away.
5. **ACM mapping.** `verdict = reproduced ∧ independent = false` is *repeatability*; `∧ independent = true` is *reproducibility* and is the only basis for `BundleStatusRecord.status = reproduced` (adr-3); *replicability* is never a bundle status — it is a `transfer` `ComparisonReport` (ADR-0046) between bundles. Level names stay ADR-0038's; the mapping is reported alongside.
6. **Acceptance criterion "re-run from bundle reproduces at declared level"** is AC-I3-3…7 (dossier §6.11): level-derivation fixtures (a)–(d); R1 re-derivation equality; R2 agreement report; R3 comparison with budget match and fingerprint drift; independence by signer.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-14 (`reproduce` and S9 refuse unmatched budgets; R3 requires `MatchSpec`), T-LCD-15 (requirements class-scoped; `n/a` never 0), T-LCD-09 (S9 keys rows to subject runs by `configuration_version_id`), T-LCD-12 (pure operations over bundle bytes; out-of-process), T-LCD-11 (S3/S4 carry `foreign[]` explicitly). Not applicable: T-01/-02/-03/-04/-05/-06/-07/-08/-10/-13 (T-03's `equivalence_run` is reused, not redefined). **ADR-0024 rung:** validator stages and `reproduce` are MUST-code; the requirement set is dialect schema (extension by ADR); margins, `min_n`, seeds and `fetch` permission are MUST-data via `PreRegistration`/`BundlePolicy`.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** derivation re-run from recorded evidence, preconditioned on capture — Harbor `regrade` doc and `SourceTrialLock` (S-132 @7d5285b), SWE-bench `submit verify` (S-488); complete vs valid — RFC 8493 (S-486); all-stages-reported validation — ADR-0025 `validate_assembly`; reproducibility vocabulary and "stated precision" — ACM v1.1 (S-484); re-execution is not bit-exact — WS-C1 F7 (S-441, Tier B), provider drift S-047 (Tier B); rebuild-equality as the R1 test — ADR-0026/0029 (`project` purity, AC-B1-3/-4), reproducible-builds definition (S-181); statistical reproduction under matched budget — ADR-0046 (S-083 via WS-I2); submission validation as a lifecycle with reviewer trust — SWE-bench checklist/`checked`, Terminal-Bench 2.1 (S-489).
- **(b) Source-code precedent:** harbor `src/harbor/models/job/lock.py` @7d5285b L91–121, L300–360 (regrade lineage copies source locks), `docs-mintlify/core-concepts/jobs/regrade.mdx` (requirements: `result.json`, `artifacts/manifest.json`, "every artifact required … was collected"); SWE-bench `swebench/harness/reporting.py` @02e7a74 L30–150 (outcome id-sets before scores); inspect_ai `src/inspect_ai/log/_edit.py` @75f4891 L13–30 (`ProvenanceData{timestamp, author, reason}` as the annotation shape); ADR-0025 `validate_assembly` seven-stage discipline. **`no-precedent / novel`** for: a basis-derived maximum level; per-level `reproduce` procedures with a typed report; `independent` reproduction as a recorded, signer-checked field; `n/a{class}` requirements.
- **(c) Disconfirming evidence considered:** static derivation of a level from pins can over-promise (pinned inputs may still fail to re-execute — an image digest that no longer pulls); R2 "agreement on validators" can hide behavioural drift; nine validation stages are heavy for a research lab; independent reproduction is rare in practice and Terminal-Bench simply closed community submissions. *Why none overturns:* the derived maximum is a *ceiling on claims*, and `reproduce` failures (`EnvironmentUnavailable`, `MemberUnavailable`) are typed outcomes, not false verdicts; R2 names its validator set and exposes per-validator counts and end-state diffs; stages are independently selectable (`mode`) and `check_completeness` remains the cheap subset; `independent` is a recorded fact that most bundles will lack — the status merely refuses to call repeatability reproducibility.
- **(d) Conditionality:** R2 requires providers with pinned snapshots and digest-addressable images (coding/terminal first); margins and `min_n` are per suite (OQ-113); the replay driver exists only for control-strategy variants declaring `deterministic_replay` (ADR-0028); hosted participants' maximum depends on observability level; independence attestation depends on WS-H6 signer custody (OQ-170).
- **(e) Build-stage assignment:** **C0 / Stage 3** (`validate_bundle` S1–S7, `reproduce` R0/R1/R3 for native runs, basis derivation, AC-I3-3/-4/-6); **C1 / Stage 4** (S8–S9, `ReproReport` sidecar records, `independent`, AC-I3-5 dry run on a pinned fixture, AC-I3-7); **C2 / Stage 5** (R2 gated on WS-C3 profile pinning and WS-B5 digests; hosted `end_state` R2).

## Consequences

- WS-J4 reports levels beside distributions and refuses cross-level pooling without annotation (ADR-0038 consequence, now with the validation report as the source of the level).
- WS-J3 calls `validate_bundle` at sweep close and refuses to publish an arm whose bundles are not `valid`.
- WS-I2 supplies `pre_registration.equivalence_margin`/`min_n` per suite (OQ-113) and the `compare` operation `reproduce` R2/R3 uses.
- WS-B4/WS-I7 state which mode (replay vs re-execution) each counterfactual used (OQ-082) by citing the bundle's `basis[]`.
- WS-H6 attests `BundleValidationReport`/`ReproReport` signers; the auditor store keeps reproducer heads.
- The Readiness Report lists per subsystem the level its acceptance tests exercise (ADR-0038 consequence) using the requirement ids above.

## Reversibility

**Medium** for the stage catalogue and requirement ids (renaming or splitting changes reports, not stored bundles); **low** for complete-vs-valid semantics and "claims never satisfy a requirement above R0" (every level claim depends on them); **high** for the ACM mapping and `independent` attestation mechanics.
