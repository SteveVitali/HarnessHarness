# ADR-0210 — Deferral of R-2.12.4 (packaging, licensing, OSS governance, docs and community; WS-L6) with entry tests over the program-level open questions it owns

**Status:** ratified (Phase 5 synthesis-authored deferral ADR; doc 3 §1.4/§7.3/§8)
**Owner workstream(s):** WS-L6 (deferred owner), Phase 5 synthesis · **Phase:** 5 · **Related:** ADR-0011 (product name; OQ-035 follow-up), ADR-0050 §7 (WS-L6 scheduled after the language decision), ADR-0198 D4 (post-Phase-5 revalidation owner), ADR-0182 X2/X4, ADR-0207 D7, ADR-0209; OQ-035 (follow-up), OQ-068, OQ-093, OQ-162, OQ-173, OQ-218, OQ-332, OQ-383, OQ-384, OQ-389, OQ-394, OQ-411, OQ-445; R-2.12.4; Spec §1.7, §3, §5d, §5g, §7, §8, §11.3

## Context

`registers/scope.md` closes Phase 4 with one row outside the doc 3 §1.4 rule — R-2.12.4 *Packaging, licensing, OSS governance, docs & community* is `open` with no specification and no deferral ADR (Spec §11.3). WS-L6 was scheduled for Phase 5 after the language decision (ADR-0050 §7) and did not run during spec assembly; the sections nevertheless cite twelve open questions whose only owner is WS-L6: the product-name qualifier and collision re-check (OQ-035 follow-up, ADR-0011), the `<hh-prefix>`/`_hh/`/`hh://`/A2A extension URI allocations (OQ-068, OQ-394, OQ-218), pricing-table governance (OQ-093), the extension trust root and signing custody (OQ-162), audit-envelope retention durations and legal hold (OQ-173), detached-payload trust and fetch expiry (OQ-332), the executable name and shell spelling (OQ-383), the exit-code numerals (OQ-384, with WS-K1/K4), capability-token delivery for surface launches (OQ-389, with WS-K4), `ContractVersionPolicy` sunset defaults (OQ-411) and spec-debt revalidation ownership after Phase 5 (OQ-445; ADR-0198 D4). None of them changes a contract: every consuming section states the record shape and the rule and leaves the value or the allocation as MUST-data (ADR-0024).

## Options considered

1. **Run WS-L6 inside Phase 5 spec assembly.** Rejected: WS-L6 needs the assembled spec as its input (packaging follows the contract set) and its outputs are program artefacts, not contracts; running it mid-assembly would ratify values no section was written against.
2. **Mark R-2.12.4 `specified` by declaring the twelve placeholders MUST-data.** Rejected: MUST-data without an owner and an entry test is a conditioned rule without a removal test (ADR-0197 D6; T-LCD-05 reflexively) and would leave the doc 3 §8 obligation undischarged.
3. **Defer R-2.12.4 by ADR with one entry test per owned question, interim rules as ratified, and a spec-debt row (chosen).**

## Decision

1. `registers/scope.md` R-2.12.4 status → **`deferred(ADR-0210)`**; MoSCoW Should unchanged; no tier (program-level). WS-L6 remains `todo` in the LEDGER and is the deferred owner.
2. **Entry tests and interim rules** (each a row in `registers/spec-debt.md` with `removal_test{kind: revalidation_review}`; ADR-0198 D1):

| OQ | Interim rule in force (ratified home) | Entry test — the deferral closes when |

| OQ-068 / OQ-394 / OQ-218 | sections use the placeholders `<hh-prefix>`, `_hh/`, `hh://` and the A2A extension URI placeholder (ADR-0021 minimum set; ADR-0173 D4; ADR-0175 D2; ADR-0086) | one allocation record naming the reverse-DNS prefix, the method namespace, the resource-URI scheme and the A2A extension URI, collision-checked, appended before the Stage-3 fixtures freeze |

3. **Consequences for the ladder.** None of the entry tests gates a C0 slice; Stage 1 needs OQ-384's numerals and Stage 3 needs the OQ-068 allocations (§9.1, §9.2, §9.4) — both are MUST-data set without a contract change. Re-entry of R-2.12.4 as `specified` is a scope ADR that cites this row's entry tests as satisfied.

**T-LCD statement.** T-LCD-05 reflexively (every placeholder is a conditioned rule with a removal test); T-LCD-12 (no entry test names a language, package or tool). Not applicable: the rest. **ADR-0024 rung:** every deferred value is MUST-data.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: the ratified homes of each interim rule (ADR-0011, ADR-0021, ADR-0035, ADR-0036, ADR-0039, ADR-0063, ADR-0068, ADR-0139, ADR-0163, ADR-0169, ADR-0172, ADR-0173, ADR-0175, ADR-0180, ADR-0198); the `registers/open-questions.md` rows cited above.
- (b) Source-code precedent: `no-precedent / novel` for the deferral form; the interim rules cite their ADRs' precedents.
- (c) Disconfirming evidence considered: leaving R-2.12.4 `open` (violates doc 3 §1.4); declaring it specified without an owner (a conditioned rule without a removal test). Neither overturns.
- (d) Conditionality: independent of model tier, task class and budget; program-level.
- (e) Build-stage assignment: outside the C-tiers; entry tests due at Stage 0–1 (OQ-384), Stage 3 (OQ-068/394/218), Stage 4 (OQ-389), and at the first post-Phase-5 revalidation pass (the rest).
