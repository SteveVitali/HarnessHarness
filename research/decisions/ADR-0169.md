# ADR-0169 — CLI I/O contract: stdout/stderr split, `human | json | jsonl` with JSONL as the canonical ledger projection, typed stdin, idempotent invocations, and a closed exit-class table derived from `outcome_class × StopReason`

**Status:** ratified
**Owner workstream(s):** WS-K1 (with WS-B1 for the `lifecycle.surface.invoked` class, WS-I1 for `SinkPolicy`, WS-F2 for `StopReason`, WS-I2 for `outcome_class`, WS-L4 for the canonical encoding, WS-A4/E4 for loss reports) · **Phase:** 3 · **Related:** ADR-0026 (ledger authoritative; `project()` views), ADR-0029/0036 (canonical form, `idp/1`), ADR-0042/0044 (trace views; `SinkPolicy`; exporters are subscribers; the ledger is never sampled), ADR-0021 (lowering loss reports), ADR-0141 (export as lowering), ADR-0045 (outcome classes; `n/a` typed), ADR-0106 (`StopReason`), ADR-0047 (veto), ADR-0130 / ADR-0050 D3 (idempotency keys), ADR-0033 (minting rules for stdin text), ADR-0048/0145 (one declaration per seam); OQ-384, OQ-385; R-2.11.1

## Context
All anchors converged on a machine format triple (`text | json | stream-json` in gemini, goose and Claude Code; `--json` JSONL in codex; `--format json` in opencode) and on progress-to-stderr / result-to-stdout (codex docs). But each ships a **curated, product-specific event vocabulary** (`ThreadEvent`/`ThreadItem`; `init/message/tool_use/tool_result/error/result`; `{type, timestamp, sessionID}`) that is neither the runtime's own record nor stable across versions, and exit codes are either flat (`exit(1)` everywhere in goose and opencode) or a small typed table (gemini 0/1/42/53 from `FatalError.exitCode`). Stdin is untyped everywhere (codex appends piped text as a `<stdin>` block). HarnessHarness already has the objects a CLI stream and an exit table should be derived from: canonical ledger events with dense `seq` and provenance, `outcome_class`, `StopReason`, `SinkPolicy`, lowering loss reports, and the JCS-class canonical encoding. A CLI-private vocabulary would be a second declaration of the same facts.

## Options considered
1. **stdout = result, stderr = messaging; `human | json | jsonl`; `jsonl` = canonical ledger events under a `SinkPolicy`-filtered identity projection plus one `result` record; a `compact` stream only as a declared-lossy projection with a loss report; stdin typed by origin; every work-injecting invocation idempotent with a recorded invocation record; exit classes derived from `outcome_class × StopReason` with numerals in a reserved band.** — chosen.
2. **A curated CLI event vocabulary as the default machine format** (codex/gemini/opencode/Claude shape). Rejected as default: lossy without a loss report (T-LCD-11), a second sum for facts the ledger already declares (ADR-0048), and not replayable into the ledger; kept as the optional `compact` view.
3. **Flat exit codes** (goose, opencode). Rejected: scripts cannot branch on `budget_exhausted` vs `infrastructure_failure` vs `approval_denied_unattended`, which the Lab's outcome classes already distinguish.
4. **CLI-private exit taxonomy** (gemini `Fatal*` subclasses). Rejected in form: adopted as the *shape* but derived from the ratified sums so that no new sum is introduced.
5. **A `--output-schema` CLI feature for structured final answers** (codex, Claude). Rejected as a CLI feature: it is a `Validator{kind: output_check}` in the sealed definition whose result is in the ledger; the CLI renders `last_message_ref`.

## Decision
1. **Streams.** stdout carries only the command's result; stderr carries progress, warnings, deprecations and prompts. Colour and decoration are disabled when stdout is not a terminal, when `NO_COLOR` is set, when `TERM=dumb`, or on request; they never appear in `json`/`jsonl`.
2. **Formats.** `OutputFormat ∈ {human, json, jsonl}`; default `human` on a TTY; when stdout is not a TTY the default is `jsonl` for streaming commands and `json` for single-record commands. `json` = exactly one typed result record in the canonical encoding (hashable by the receiver). `human` renders `n/a{reason}` distinctly from `0` and blank (T-LCD-15) and uses Terraform-class diff lines for definition plans/diffs.
3. **The JSONL stream is the ledger.** For streaming commands the stream is `project(run, cli_stream_view, until_seq)` where `cli_stream_view` is the identity projection over durable events filtered by a `SinkPolicy{content_classes}` (default L0 + L1 + L2-by-address; L3 never), each line a canonical event envelope, followed by exactly one terminal `ResultRecord{run_id, configuration_version_id, stop_reason, outcome_class, resource_account, last_message_ref?, bundle_ref?, exit_class, veto_tripped[]}`. **O-1:** the stream minus `result` is byte-identical to `run events` over the same cursor range (AC-K1-03). Ephemeral classes never appear in `jsonl`. A `compact` view (message/tool/effect/approval/cost items) is an optional declared-lossy projection shipped with a `LoweringLossReport` and is never the machine default.
4. **Stdin and files are typed by origin.** Prompt text typed by the human principal at a TTY ⇒ `Text{authority = principal, origin = human}`; a `-` sentinel forces stdin as the prompt; piped stdin alongside a positional prompt is a separate `ContextItem` `Text{authority = external, origin = import}` with provenance naming the pipe; attached files enter by content address as `external` (ADR-0033 minting rules).
5. **Idempotent invocations.** Every work-injecting command carries `idempotency_key = H(idp ∥ "cli" ∥ canonical(InvocationRecord))` unless supplied; a repeat returns the recorded result and exit class. `InvocationRecord{argv_canonical, cwd_ref, principal, attendance declaration, output_format, stdin_digest?, overrides_layer_id?, instrument_record, idempotency_key}` is appended as `lifecycle.surface.invoked` — durable when the invocation opens or amends a run, ephemeral otherwise (OQ-385 for WS-B1's confirmation).
6. **Exit classes.** `ExitClass ∈ {ok, invocation_error, validation_error, refused_by_kernel, budget_exhausted, refused, cancelled, infrastructure_failure, oracle_failure, approval_denied_unattended, tampered}` derived totally from `outcome_class × StopReason` (`scored ∧ completed → ok`; `budget_exhausted`; `refused`; `cancelled{by}`; `infrastructure_failure`; `oracle_failure`; approvals-exhausted/blocked-by-unattended-deny → `approval_denied_unattended`; `Tampered → tampered`) plus the two pre-ledger classes (`invocation_error` for flag conflicts, missing TTY, unknown format, `MissingBudget`; `validation_error` for `AssemblyDiagnostic{error}` and engine refusals) which never open a run. Success-with-veto is `ok` with `veto_tripped` in `result` and an opt-in distinct code. Numerals live in a band avoiding 1, 2, 126–165 and 255 (OQ-384); the `result.exit_class` is authoritative. `InvocationError{code, path?, remedy}` mirrors the `AssemblyDiagnostic` shape.
7. **Configuration precedence** follows clig (flags > environment > project > user > packaged) mapped onto ADR-0024's layers (flags = `session`; override lists = `experiment`); `config explain` is WS-J1 `explain`.

**T-LCD statement.** Satisfies T-LCD-11 (JSONL lossless by construction; `compact` declared-lossy with a loss report; AC-K1-03), T-LCD-15 (`n/a` rendering; export never lowers `n/a` to 0 — J5 `export_rows` rule reused), T-LCD-02 (stdin/file text enters only as typed `Text` leaves with provenance), T-LCD-12 (the stream is a projection any client can compute), T-LCD-13 (nothing is sampled; delivery events unaffected). Not applicable: T-01/-03/-04/-05/-06/-07/-08/-09/-10/-14. ADR-0024 rung: `SinkPolicy` default, exit-code numerals, `compact` view definition are MUST-data; stream projection, stdin typing, idempotency-key derivation, exit-class derivation are MUST-code.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)
- (a) Mechanism evidence: ADR-0026/0042/0044 (views are projections; exporters are subscribers; `SinkPolicy`; the ledger is never sampled), ADR-0021/0141 (export is lowering with a loss report), ADR-0045/0106 (`outcome_class`, `StopReason` as closed sums), ADR-0130 (idempotency), ADR-0033 (authority minting for free text); [S-535] TTY heuristic, stdout/stderr, `--json`/`--plain`, `NO_COLOR`, exit codes; [S-537] stderr progress / stdout result, JSONL, stdin patterns; [S-536] a shipped exit-code table and JSON envelope; [S-103]/[S-314] why piped text must not enter at `principal`.
- (b) Source-code precedent: S-107 `codex-rs/exec/src/cli.rs` L47–80, `exec/src/lib.rs` L187–199 (`StdinPromptBehavior`), `exec/src/exec_events.rs` L10–40 @0735c51; S-119 `packages/cli/src/config/config.ts` L467–473, `packages/core/src/utils/errors.ts` L71–123, `docs/cli/headless.md` @ed2ac40; S-112 `crates/goose-cli/src/cli.rs` L297–314 @fae91d0; S-111 `packages/opencode/src/cli/cmd/run.ts` L174–178, L679–690, L837–873 @9f8db11; S-109 `_internal/transport/subprocess_cli.py` L566, L783 (bidirectional `stream-json`) @ad77094; S-115 `src/minisweagent/agents/default.py` L164–174 (`exit_status` in the trajectory) @04d809c; [S-200] idempotency-key replay. The "JSONL = canonical ledger events" rule itself is `no-precedent / novel` relative to every audited CLI (all ship curated vocabularies).
- (c) Disconfirming evidence considered: every precedent curates its machine stream because raw runtime events are too fine-grained and version-sensitive for script authors (S-107 `ThreadItem`, S-119 stream-json, S-109 consumers) — the usability cost is real; it does not overturn the decision because only the canonical stream is lossless (T-LCD-11), the event classes are already versioned per dialect (ADR-0015 rule), and the `compact` view recovers the ergonomics as a declared-lossy projection. Rich exit codes collide with shell conventions and most scripts only test non-zero — mitigated by the reserved band and by `result.exit_class` being authoritative.
- (d) Conditionality: assumes the ADR-0026 event table and the ADR-0106/0045 sums are stable through Stage 3 (closed-sum growth is a dialect bump, which the stream inherits); assumes WS-B1 accepts `lifecycle.surface.invoked` (otherwise the invocation record is a manifest field); independent of model tier, task class and budget.
- (e) Build-stage assignment: C0/Stage 0 (`human` + `jsonl` with `result`; stdout/stderr split; `invocation_error`/`validation_error`/`ok`/`infrastructure_failure`/`budget_exhausted`); C0/Stage 1 (full exit-class table; `json`; stdin typing; `InvocationRecord` + idempotency); C1/Stage 2 (`compact` view with loss report; `config explain`); C1/Stage 3 (paged `results` output with watermark sets; export targets).

## Consequences
- A script that consumes the JSONL stream can `import` it back losslessly; conversely nothing a script sees is missing from the ledger, so CLI bugs are ledger-visible.
- Script authors must handle `n/a` as a value and `exit_class` as a string; numerals are a convenience.
- WS-K2/K3 reuse `cli_stream_view` and the `compact` view; WS-K4's client exposes the same `ResultRecord`.

## Reversibility
**High for formats and numerals (MUST-data), medium for O-1.** Dropping the lossless rule later would re-open T-LCD-11 for the surface and break `import` round-trips that Stage-3 fixtures depend on.
