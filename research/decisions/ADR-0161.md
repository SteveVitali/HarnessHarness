# ADR-0161 — The results store is a projection layer: `ResultsRow/1` data model, row versions by supersession under a fixed key, the derived annotation index and cell table, the bundle catalogue, and the watermarked query/verify/export contract

**Status:** ratified
**Owner workstream(s):** WS-J5 (consumers WS-J3, WS-J4, WS-K2, WS-K3, WS-J6, WS-I5/I7, WS-H6, WS-L6, WS-L5) · **Phase:** 3 · **Related:** ADR-0026/0027/0029 (project, `derived_from`, `view_hash`, canonical form), ADR-0036/0037/0038 (identity, supersession, row keys), ADR-0039/0041/0043 (consumption, `MatchSpec`, cost provenance), ADR-0045/0046/0047 (`MetricDeclaration`, cells, reports), ADR-0067/0068 (`audit_ref`, retention, gc), ADR-0139/0140/0141 (bundle, catalogue, CF-298 annotation rule), ADR-0107/0131/0133/0135/0136 (attempts, activations, branches, discontinuities), ADR-0007 (T-LCD-09/-10/-11/-12/-14/-15), ADR-0050 §8; CF-298, CF-344, CF-345; OQ-239, OQ-321, OQ-261/0272, OQ-373/-05; R-2.10.5, R-2.9.2, R-2.12.1, R-2.2.1

## Context

ADR-0026 made the run ledger the sole authoritative record and named `results_row` a `project()` view; ADR-0038 fixed the row key `(configuration_version_id, run_id)` and aggregation by `configuration_id`; ADR-0141 (CF-298) made `bundle_ref`/`claimed_level` derived annotations outside row bytes and assigned WS-J5 the bundle catalogue. What remained open was the row's *content*, what happens when a run is re-scored (Harbor regrade, validator supersession, pricing re-snapshot, registry bump), how J4 obtains per-task (c, n) cells with exclusions visible, and what read contract J4/K2/K3 get. The source audit (WS-J5 §4) shows two shapes in the field: HELM builds every table by summarizing write-once run directories through a declarative schema (`runner.py` skips completed runs; `summarize.py: read_run`), while Terminal-Bench keeps a mutable `accuracy` column with cascade deletes and Harbor Hub patches leaderboard rows in place with a `hide` status and replaceable trial links. Every audited plane keys aggregates by names and picks "latest attempt wins" by convention; Inspect had to add a versioned identity function to pair planned cells with produced logs across retries. Mature experiment trackers (MLflow, W&B) make inputs immutable but containers deletable.

## Options considered

1. **A mutable results table (Terminal-Bench / Harbor Hub shape): one row per run, updated in place, deletable.** *Rejected:* violates ADR-0037 I1 and ADR-0068 R1; cannot cite `audit_ref`s or render `n/a{reason}`; loses history on regrade.
2. **Rows as bundle members only, no store (query the bundles).** *Rejected:* every J4 aggregate would re-read manifests; no cell table, no watermarked pagination; ADR-0026 already places `results_row` as a Stage-3 view.
3. **Re-scoring mutates the row under an etag (Inspect `log_updates`).** *Rejected:* in-place mutation; the row `version_id` a bundle pinned would no longer verify (ADR-0140 R1).
4. **Re-scoring changes the key (add a `scoring_id` key component).** *Rejected:* contradicts the ratified ADR-0038 key; breaks every consumer keyed on `(configuration_version_id, run_id)`.
5. **Projection layer with a fixed key, row *versions* by supersession, a derived annotation index and cell table, the catalogue, and a watermarked read contract (chosen).**

## Decision

1. **`ResultsRow/1` = `project(run, results_row, until_seq, scoring: ScoringContext)`**, a canonical record under `idp` with `version_id = H(idp ∥ "results_row" ∥ canonical(row))` and sections `key{configuration_version_id, run_id}`, `coordinates` (the ADR-0045 factor tuple with both configuration ids, model snapshots per role, harness at declared granularity by `semantic_id`/`version_id`, profile, environment, task with split hash, budget with `eval_budget`/`search_budget`/`match_spec`/`cache_policy` refs, replicate with seed material, participant class and observability level), `experiment?` (bound cell), `outcome` (outcome class, `StopReason`, status, `veto_tripped[]`, activation/continuation), `cells[]` (one per metric in the pinned registry version — `value | n/a{reason}`, detector, oracle, `evidence[]: audit_ref`), `consumption` (per-dimension totals with utilization; spend with `CostProvenance`, confidence, `pricing_ref`; subject/instrument split), `cache`, `lineage` (branch kind, fork point, replay mode, `superseded_by_run`, goal ref), `annotations_from_ledger` (discontinuities, routing deviation, catalog epochs, suite validity ref), `audit{head: audit_ref, audit_completeness}`, `scoring`, `derived_from{run_id, seq, overlay_watermarks[]}`, `view_hash`. Rules R-ROW-1…8 (WS-J5 §6.2): purity; no display names; total cell list; primaries never derived totals; hosted rows same schema with `n/a`; every cell cites an `audit_ref`; decimal strings/integers only; large members by content address.
2. **Row versions, fixed key.** Re-scoring produces a new `RowVersion{key, version_id, scoring, supersedes, derived_from_reason ∈ {initial, regrade, validator_superseded, pricing_resnapshot, registry_bump, redaction}}`; `head(key)` is the newest version whose scoring members are not revoked; no version is deleted; aggregation uses heads unless an analysis pins versions. A regrade is an **overlay run** — an ordinary instrument run whose `verification.validator.verdict` events target the subject by `audit_ref` and `causes[]`; it never appends to the subject's ledger; `ScoringContext.overlay_runs[]` names it.
3. **Derived objects (never authoritative, always rebuildable, each stamped with a watermark set and `view_hash`):** the **annotation index** (`bundle_refs[]{bundle_id, kind, claimed_level, status, level_now, verifiable_by[]}`, `depends_on_revoked`, `bundle_retracted`, `excluded_by[]`, `leaderboard_memberships[]`, `analysis_refs[]`, `flags[]` with `reason_ref`), the **cell table** (`cell_id = (arm_id, configuration_id, task_id)`; row heads with `included`/`excluded_reason`; per-metric (c, n), values, outcome counts, veto count), and the **bundle catalogue** (`BundleCatalogueEntry{bundle_id, kind, subject_runs[], configuration_ids[], experiment_run_id?, claimed_level, max_supported_level, status, readers, name_bindings[], size, created_at, producer}`).
4. **Read contract.** `get_row`, `row_history`, `query_rows(QuerySpec{typed filter, projection, at?: watermark_set, page, order}) → Page{rows, next_cursor, watermark_set, view_hash}`, `cells`, `distribution`, `catalogue`, `subscribe`, `verify_row`, `verify_snapshot`, `verify_citation`, `export_rows(…, target, PublicationPolicy) → (artefact, LoweringLossReport, measurement.export.delivered)`. Invariants: every read returns the watermark set it was served at and is byte-repeatable at that set; there is no update or delete operation; failures are typed (`RunNotDurable`, `WatermarkAhead`, `UnknownField`, `UnknownCursor`, `Tampered`, `OverlayNotTargeting`, `NoChange`, `RevokedValidator`, `MissingMatchSpec`), never warnings; only `ledger_native_rows` export is lossless and `n/a{reason}` never lowers to 0 or empty.
5. **Neighbour rulings folded in:** OQ-321 — a promoted fork's parent that finished `superseded_by{run_id}` is one cell observation (parent row auto-excluded `superseded_by_fork`); OQ-239 — `configuration_version_id` is fixed at `open_run`, mid-run `adopt` is a `configuration_drift` flag with `catalog_epochs[]`, excluded from pooling unless declared a factor level; OQ-261/OQ-272 — `loop_detected`/`format_failure`/`failed_honestly` are `scored` stratified by `stop_reason`, `unreconciled_claims` is `budget_exhausted`; ADR-0133's `branch_kind`/`fork_point`/`replay_mode` are row fields, not key components (CF-345).

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-09 (rows keyed by the full factor tuple; grouping by any factor; interaction query executable over `cells`), T-LCD-10 (identity content-derived; names only as display bindings in the catalogue), T-LCD-14 (rows carry `eval_budget`/`search_budget`/`match_spec`; `build_cells` refuses a design without `MatchSpec`), T-LCD-15 (total cell list with typed `n/a{reason}`), T-LCD-06 (hosted rows are the same schema filling a subset; no hosted-only field), T-LCD-11 (exports carry a typed loss report), T-LCD-12 (operations over the canonical encoding, out-of-process). Not applicable: T-01…05, T-07, T-08, T-13. **ADR-0024 rung:** `project_row`, `rescore`, `build_cells`, `annotate`, `catalogue_refresh`, `verify_*`, `export_rows` are MUST-code; `ResultsRow/1`, `RowVersion`, `CellTable`, `BundleCatalogueEntry` are dialect schema; export targets and the registry version pinned per scoring are MUST-data.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** rows as pure projections with rebuild equality — ADR-0026/0029 (Tier-B source convergence: OpenHands `View.from_events`, Codex reconstruction; Logos `provisional` corroboration only); leaderboards derived from write-once run objects — HELM S-525/-04 (Tier A/B; `runner._is_run_completed`, `summarize.read_run`); inputs immutable / observations append-only — MLflow S-527 ("Run params are immutable … to ensure the reproducibility of an experiment run"); versioned identity pairing planned cells with produced logs across retries — Inspect `task_identifier`/`TASK_IDENTIFIER_VERSION` (S-136); "latest attempt wins" as an unrecorded convention — Harbor Hub `relaunch_trials`/`cancel_trials` (S-132), Inspect `_retry.py` (S-136); regrade as lineage — Harbor `source_trial{regrade}` via ADR-0140; citations verify through inclusion proofs — ADR-0067 (RFC 6962, Tier A); per-task (c, n) storage so estimators are recomputable — ADR-0045 (S-127 Tier A, S-235); cost provenance — ADR-0039/0043.
- **(b) Source-code precedent:** helm `src/helm/benchmark/runner.py` @63754d0 L193–240, `presentation/summarize.py` L93–108, L395–412, L726–760 (adopted: leaderboard = summarizer over immutable run records); inspect_ai `src/inspect_ai/_eval/evalset.py` @75f4891 L2005–2075 and `log/_file.py` L51–115, L498–540 (adapted: versioned identity, header-only manifest); harbor `src/harbor/hub/models.py` @7d5285b L223–275 (`ComparisonGrid` cells — adapted to (c, n) cells), L359–390 (attempt fields — adopted); **negative precedents rejected:** harbor `hub/leaderboards.py` L107–130, L217–300 (patchable rows, `hide`, replaceable trial links), terminal-bench `terminal_bench/db.py` @d28711d L27–60 (`accuracy` column, `commit_hash = "unknown"`, cascade delete), `hub/client.py` L272–360 and inspect `log/_retry.py` (implicit latest-wins). **`no-precedent / novel`** as an integrated contract: row versions under a fixed key with overlay-run scoring; a derived annotation index; exclusions as recorded reasons; watermark-set-repeatable reads.
- **(c) Disconfirming evidence considered:** Kiehl S-195 (each projection multiplies code; a history table gets most of the value) and the fact that Harbor/Terminal-Bench ship credible leaderboards from mutable tables; the cost of storing every row version; MLflow/W&B deletable runs as the industry default. *Why not overturning:* the row projection and the catalogue are already mandated (ADR-0026/0141) — this ADR adds one derived table and no store; a mutable row cannot cite an `audit_ref`, render `n/a{reason}` or survive a regrade with history; row versions dedupe by content address and arise only from genuine re-scorings; deletable containers are exactly what ADR-0068 R1 forbids for an audited instrument. Conceded: Stage 3 ships only rows + catalogue + cells (the "history table"); the annotation index and versions are Stage 3–4 work.
- **(d) Conditionality:** independent of model tier and task class; assumes ADR-0067 checkpoints exist so `audit_ref`s verify (Stage 2); assumes the metric registry is versioned (ADR-0045); hosted rows' cell coverage depends on the hosting mechanism's observability (ADR-0013); cell-table cost on large sweeps is measured at Stage 4 (OQ-376 with OQ-333).
- **(e) Build-stage assignment:** **C0 / Stage 3** — `project_row`, row versions + `head`, `build_cells`, `get_row`/`query_rows`/`cells`/`distribution`, bundle catalogue + `bundle_refs` annotation, `verify_row`, AC-J5-1/-2/-5/-6/-12; **C1 / Stage 3–4** — full annotation index (StaleIndex, exclusions, flags), `rescore` with overlay runs, `subscribe`, `export_rows`, AC-J5-11; **C2 / Stage 4–5** — hosted strata, `verifiable_by` per reader set.

## Consequences

- WS-J3 must append `measurement.experiment.run.excluded` rather than relying on "latest attempt"; WS-J4 reads `CellTable` (with exclusions) and may pin row versions in analysis records; WS-K2 links every cell to its `audit_ref`; WS-K3 exposes `catalogue`/`get_row`/`leaderboard` statelessly.
- WS-B1's manifest gains no field from this ADR (the `run_kind` field is ADR-0162's, CF-343); ADR-0133 decision 7 is read as naming row fields (CF-345, wording).
- WS-I5/I7 obtain counterfactual scorings as overlay runs producing row versions, never edits.
- WS-L5 holds custody of `hh-results-row/N` golden fixtures (with OQ-335's bundle schema governance).

## Reversibility

**Low** for "projection, never a store" and the fixed key with versions (every consumer and every bundle-pinned row depends on them); **medium** for the row's section list (additive by dialect bump; removing a section would orphan bundle-pinned rows); **high** for the export target list, filter grammar and cell-table layout (derived; rebuildable).
