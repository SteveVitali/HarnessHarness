# ADR-0162 — The experiment ledger is a run ledger of kind `experiment` with a closed `measurement.experiment/analysis/leaderboard.*` event family; analyses are immutable records with cited inputs and a pre-registered/exploratory label

**Status:** ratified, amended (Phase 3 synthesis)
**Owner workstream(s):** WS-J5 (producer WS-J3; consumers WS-J4, WS-I3, WS-K2, WS-H6, WS-I5) · **Phase:** 3 · **Related:** ADR-0026/0027/0029 (append-only ledger, fenced writer, chain), ADR-0067/0068 (checkpoints, retention floors), ADR-0039/0040 (`charged_to = instrument`, root budget node), ADR-0045/0046 (`Design`, `PreRegistration` immutable once the first run opens; `ComparisonReport` with `budget_match`/`benefit_kind`), ADR-0041 (refusals), ADR-0131 (long-lived runs), ADR-0139/0141 (`experiment`/`arm` bundle kinds; S9 containment equality; `PreRegistrationLate`), ADR-0037 (supersession), ADR-0024 (procedure as data/pointer), ADR-0007 (T-LCD-12/-14); CF-343; OQ-372/-06; R-2.10.5, R-2.10.3, R-2.10.4

## Context

The brief asks for "an immutable record of experiments and their analyses". Phase 2 settled that every subsystem adds *projections, never stores* over the one run ledger (phase-2 §6.2). ADR-0045 already makes `Design`/`PreRegistration` immutable once an experiment's first run opens, and WS-B1 already has `measurement.experiment.bound` on subject runs; but nothing records *arm declaration before results*, *exclusions with reasons*, *amendments*, *which analyses were computed from which inputs*, or *what was published*. The audit finds only partial precedents: Inspect writes a static `EvalSetCapture` manifest before running and `eval-set.json` after, as a versioned wire format with golden tests; Harbor writes a job lock; MLflow/W&B model experiments as deletable containers; no plane records analyses or exclusions. *The Leaderboard Illusion* (preprint, mechanism only) shows what the absence of such a record permits at scale: private variants tested and retracted, selective disclosure. SWE-bench's checklist demands disclosure of all best@k rollouts and the selection rule.

## Options considered

1. **A separate append-only experiment store with its own schema.** *Rejected:* a second store per seam (phase-2 §6.2); would re-implement chain, checkpoints, fencing, redaction, export and attestation.
2. **Experiment bookkeeping only in the bundle (`experiment` kind) assembled at sweep close.** *Rejected:* a bundle is written once at the end; it cannot prove what was declared *before* results existed nor record exclusions and analyses as they happen; ADR-0141 S9 needs a pre-existing `PreRegistration` to check `PreRegistrationLate`.
3. **Mutable experiment records with an etag (Inspect `log_updates`; MLflow containers).** *Rejected:* ADR-0037 I1; loses the audit of who excluded/amended what.
4. **An experiment is a run (`run_kind = experiment`) whose durable events form a closed `measurement.experiment/analysis/leaderboard.*` family written by the sweep engine as the single fenced writer; analyses are immutable versioned records (chosen).**

## Decision

1. **Run kind.** The run manifest gains an additive field `run_kind ∈ {subject, instrument, experiment}` (ADR-0026 dialect bump; CF-343). An experiment run has `participant_class = native`, `observability_level = {events, ledger}`, `charged_to = instrument`, a root budget node, no `configuration_id`, no environment, no metric cells; it is excluded from every subject aggregate by construction and is exported, chained, checkpointed, redacted and attested like any run (ADR-0026/0029/0067/0068). The sweep engine (WS-J3) holds its writer lease.
2. **Closed durable event family** (plane `measurement`, `durability = ledger`): `measurement.experiment.declared{design_ref, pre_registration_ref, arms[]{arm_id, artifact_ref, eval_budget_ref, search_budget_ref, match_spec_ref}, cells[]{cell_id, arm_id, configuration_id, task_id, replicates_planned}}` — exactly one per experiment run and **before** any subject run is bound (`DeclarationLate`; `PreRegistrationLate` if `registered_at` postdates a bound run); `measurement.experiment.run.bound{run_id, cell_id, replicate_index, subject_head: audit_ref}` (mirror of the subject's own `measurement.experiment.bound`, whose chain is the proof); `measurement.experiment.run.excluded{run_id, reason ∈ {infrastructure_retry, duplicate_attempt, superseded_by_fork, pre_registered_exclusion, budget_unmatched, consent_withdrawn, analyst_exclusion}, evidence?, authority}` (analyst exclusions require `origin = human`); `measurement.experiment.cell.completed`; `measurement.experiment.amended{diff_ref, reason, authority}`; `measurement.analysis.recorded{AnalysisRecord}`; `measurement.analysis.superseded{old, new, reason}`; `measurement.experiment.closed{watermark_set, summary_ref}`; `measurement.experiment.bundle.assembled{bundle_id, kind}`; `measurement.leaderboard.published{definition_ref, snapshot_id, view_hash, readers, export_ref?}`; `measurement.leaderboard.entry.retracted{definition_ref, configuration_id, reason_ref, authority}`. Growth of the family is a dialect bump, never `ext`.
3. **`AnalysisRecord{analysis_id = version_id, experiment_run_id?, kind ∈ {scorecard_report, comparison_report, equivalence_report, interaction_report, fitted_surface, pareto_frontier, rank_report, custom}, procedure: version_id, inputs: {row_versions[] | query + watermark_set}, metric_registry_version, price_table_version, oracle_ids[], judge_snapshots[], report: ContentAddress, pre_registered: bool, registered_analysis_ref?, post_amendment: bool, provenance, cost}`.** Invariants: same inputs + procedure ⇒ same `report` address and `analysis_id` (ADR-0045 AC-I2-12 lifted); a `ComparisonReport` lacking `budget_match`/`benefit_kind` is refused (`UnmatchedBudget`/`MissingMatchSpec`, ADR-0041/0046); `pre_registered = true` only when kind, metric refs and procedure match the `PreRegistration` plan by identity (`NotPreRegistered` otherwise); any analysis recorded after an `amended` event carries `post_amendment = true`; supersession only (ADR-0037 S1), never edit.
4. **Immutability rules I-LED-1/-2** (WS-J5 §6.3): events obey ADR-0026 (append-only, fenced, durable-before-visible, chained); a second `declared` is a `SchemaViolation`; amendments are events that mark later analyses.
5. **Disclosure is derivable.** From the family above the results store computes, per experiment and per leaderboard entry, `DisclosureSummary{arms_registered, arms_published, arms_restricted, exclusions, analyses_pre_registered, analyses_exploratory}` (consumed by ADR-0163 L6). A restricted/private arm is still *registered* — it counts.
6. **Producer contract for WS-J3:** `open_experiment(manifest)`, `declare(…)`, `bind(run_id, cell_id)`, `exclude(run_id, reason, evidence?, authority)`, `amend(…)`, `record_analysis(AnalysisRecord)`, `close(…)`; the results store validates every append against decisions 2–4 and refuses with typed errors.

**T-LCD statement.** Satisfies T-LCD-14 (every `ComparisonReport` recorded carries `budget_match`/`benefit_kind`; arms declare `eval_budget`/`search_budget`/`match_spec` before results), T-LCD-12 (event and record contracts; out-of-process producers), T-LCD-06 (no hosted-only event; hosted subject runs bind like native ones), T-LCD-15 (exclusions and disclosure counts are typed, never inferred). Not applicable: T-01…05, T-07…11, T-13. **ADR-0024 rung:** event validation, `DisclosureSummary` derivation and `AnalysisRecord` identity are MUST-code; the event family, `AnalysisRecord` and `run_kind` are dialect schema; exclusion reasons that require human authority and the analysis-kind list are MUST-data.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** one authoritative append-only log with projections, no second store — ADR-0026 (Tier-B convergence) and phase-2 §6.2; long-lived, multi-activation runs are a supported shape — ADR-0131; pre-registration immutable once runs open — ADR-0045; analyses must cite versions and inputs — lm-eval "Lessons from the trenches" S-524 (Tier C: share exact code/prompts, report versions and significance), HELM `runs.json`/`run_specs.json`/`costs.json` beside tables (S-526), ADR-0045 AC-I2-12; manifest written before running with a versioned identity — Inspect `EvalSetCapture` (S-136 `eval_set_manifest.py` L1–150: "versioned wire format … Schema changes require a version bump and corresponding golden-test updates"); disclosure failures as a documented leaderboard failure class — *The Leaderboard Illusion* S-523 (preprint; mechanism only: private variants tested and retracted, selective disclosure), SWE-bench checklist S-488 (best@k must disclose all rollouts and the selection mechanism), T-LCD-14 (search-time vs artifact benefit, ratified).
- **(b) Source-code precedent:** inspect_ai `src/inspect_ai/_eval/eval_set_manifest.py` @75f4891 L1–150 (`EvalSetCapture`), `_eval/evalset.py` L2306–2345 (`write_eval_set_info` → `eval-set.json`) — adapted (declaration before running; identity by `configuration_id` + task + replicate instead of a second function); helm `presentation/summarize.py` @63754d0 L726–760 (derived reports beside tables) — adopted shape for `AnalysisRecord.report`; harbor `src/harbor/models/job/lock.py` @7d5285b (job lock; via ADR-0139) — the lock is the *bundle*, the ledger is the *history*. **`no-precedent / novel`:** exclusions and amendments as chained events with reasons and authority; pre-registered vs exploratory analysis labels; a derivable disclosure summary; an experiment as a run kind sharing the ledger contract.
- **(c) Disconfirming evidence considered:** overloading `run` for a weeks-long analyst-driven record risks confusing subject metrics with bookkeeping; MLflow/W&B and Inspect chose containers/manifests; analysts iterate and immutable analysis records inflate; pre-registration friction and gaming (register everything); the Leaderboard Illusion is a 2025 preprint about a preference arena. *Why not overturning:* `run_kind` keeps experiment runs out of every subject aggregate; a separate store would re-implement five ratified contracts; analysis records dedupe by content address so only genuinely different analyses create records; the disclosure summary is descriptive (counts what exists) and refuses nothing except `undisclosed` leaderboard entries under a publisher-chosen policy; the preprint supplies only the failure signature already motivated by T-LCD-14 and S-488.
- **(d) Conditionality:** independent of model tier and task class; assumes WS-J3 exists as the single writer (Stage 3–4) and that ADR-0045's `Design`/`PreRegistration` records are content-addressed (Stage 1); assumes ADR-0068 floors so experiment envelopes outlive blob GC; the `run_kind` field needs WS-B1/A2 confirmation (CF-343); whether an imported foreign job yields an experiment run with `provenance = imported` is OQ-377.
- **(e) Build-stage assignment:** **C0 / Stage 1** — `run_kind` in the manifest (with WS-B1); **C1 / Stage 3–4** — experiment runs, the event family, `AnalysisRecord`, producer contract and refusals, `DisclosureSummary`, AC-J5-8/-10; **C2 / Stage 4–5** — hosted-participant experiments and imported experiment runs (OQ-377).

## Consequences

- WS-J3 opens an experiment run per sweep, declares before binding, records exclusions instead of relying on latest-attempt, and assembles `arm`/`experiment` bundles that S9-validate against the declaration (ADR-0141).
- WS-J4 records every report as an `AnalysisRecord`; exploratory analyses are labelled, never hidden; pinned row versions make reports re-derivable (ADR-0140 R1).
- WS-B1's ADR-0026 gains the `run_kind` field and the new event classes in its amendment log at synthesis; WS-H6 attests experiment runs like subject runs; the auditor may store heads in the results store (ADR-0067).
- WS-K2 renders the experiment timeline (declared → bound → excluded → analysed → closed → published) from the ledger; WS-K3 exposes `DisclosureSummary` read-only.

## Reversibility

**Medium.** The event family is additive (removable without touching subject runs — T-LCD-06 style); reverting "experiment = run" after Stage 4 would require migrating experiment histories into a new store and re-anchoring every `AnalysisRecord` and disclosure summary; the `pre_registered` label and exclusion reasons are cheap to extend (dialect bump) but expensive to drop once leaderboards cite them.
