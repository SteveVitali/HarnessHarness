# ADR-0167 — The CLI is a generated client with a noun·verb taxonomy over ontology objects and no CLI-only semantics; four presentation modes over one command set

**Status:** ratified, amended (Phase 3 synthesis)
**Owner workstream(s):** WS-K1 (with WS-K4 for the client/transport, WS-L5 for the verb set, WS-K2/K3 as sibling surfaces) · **Phase:** 3 · **Related:** ADR-0050 (E3 surface layer via generated client; §8 language-use), ADR-0049 §4 (Q-L1-14 provisional), ADR-0130 (idempotency on work-injecting verbs), ADR-0025 / WS-J1 (assembly operations), WS-J2/J3/J5/J6 operation contracts, ADR-0098 (ACP artefact), ADR-0048/0145 (one declaration per seam); CF-353, CF-356, CF-357, CF-322; OQ-383, OQ-130; R-2.11.1

## Context
Every anchor CLI that started as a thin driver has grown behaviour that lives only in the CLI (opencode's unattended auto-reject, gemini's tool exclusion when non-interactive, codex `exec`'s approval-policy rebuild). Such behaviour is invisible to the ledger and therefore to the Lab, and it makes the CLI a second implementation of semantics that the kernel/Lab contracts already own. At the same time, opencode (`run` as in-process-server-or-attach client), the Claude Agent SDK (subprocess client of the CLI's JSONL) and codex (`app-server`) show that a client-shaped surface is production practice, and ADR-0050 already binds HarnessHarness surfaces to a generated client over the kernel's local transport. The command *taxonomy* has no precedent for the laboratory nouns (no anchor exposes experiments, comparisons or leaderboards); for run-plane nouns the precedents converge on session-lifecycle verbs (`resume`, `fork`, `queue`, `export/import`).

## Options considered
1. **Thin generated client; noun·verb over ontology objects; every command a boundary verb or projection; one command set under four presentation modes (attended terminal, headless, serve, acp).** — chosen.
2. **CLI embeds the kernel (in-process runtime) with its own event vocabulary** (gemini/goose shape). Rejected: violates ADR-0050 layering and T-LCD-12; CLI-only behaviour escapes the ledger; two implementations of approval defaults.
3. **Separate binaries per concern** (a `run` tool, a `lab` tool, an `acp` tool). Rejected: duplicates argument mapping and rendering; the precedents that split (codex `exec`, `app-server`, `exec-server`) still ship one binary; presentation modes are cheaper than products.
4. **Verb·noun ordering with a catch-all "smart" command.** Rejected by clig's future-proofing rules (no catch-all, no abbreviation matching) and by ADR-0048's one-declaration-per-seam rule (a catch-all is a second router).

## Decision
1. **Three kinds of CLI code only:** argument mapping to typed boundary records; invocation of exactly one boundary verb / Lab operation per command (with `idempotency_key` on every work-injecting call, ADR-0130); rendering of ledger projections, prompts and terminal chrome. **K-1:** for every command there is a boundary verb sequence with byte-identical ledger effects (AC-K1-02). **K-2:** the CLI never links kernel code; it attaches to a running local service or spawns one per invocation, indistinguishably in the ledger. **K-3:** additive surface — commands, flags and output records are only added; removals are deprecation cycles announced on stderr.
2. **Taxonomy:** run-plane nouns `run, approval, env, bundle, profile` and Lab nouns `definition, registry, experiment, results, compare, leaderboard, participant`, plus program commands `doctor, version, completion, config, serve, acp`, with the verb tables of WS-K1 dossier §6.2. **N-1** no catch-all, no abbreviations; **N-2** a verb name equals the owning operation's name where one exists, renames enumerated in the spec; **N-3** Lab nouns add no semantics (`no-precedent / novel` at this layer); **N-4** `run` carries `resume, fork, submit/steer, cancel, export, import, archive, amend` with ledger semantics.
3. **Modes:** one command set is served in `attended terminal`, `headless`, `serve` (local service for K2/K4/attach) and `acp` (ADR-0098 artefact) presentation modes; mode is a surface property never written to the ledger except through the attendance declaration (ADR-0168).
4. **Boundary placement (ADR-0050 D2):** argument mapping and rendering are surface-layer; verbs are served by the Lab layer or the kernel layer through their existing contracts; the §6.5 verb set must be extended with the Lab operations (assembly, registry, experiment, results, hosting) as generated bindings — CF-356, extending CF-322.

**T-LCD statement.** Satisfies T-LCD-06 (`participant` noun additive; hosting-tier removal changes nothing else), T-LCD-10 (presentation never touches `configuration_id`), T-LCD-12 (out-of-process by construction), T-LCD-15 (renderers distinguish `n/a`). Not applicable: T-01/-02/-03/-04/-05/-07/-08/-09/-11/-13/-14 (no model-facing surface, no lowering, no comparison introduced here; T-11 is ADR-0169). ADR-0024 rung: verb tables and renames are MUST-data of the spec; argument mapping and idempotency-key derivation are MUST-code.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)
- (a) Mechanism evidence: [S-111] opencode `run` as a client of the same server the TUI/web use (`packages/opencode/src/cli/cmd/run.ts` L1–16, L192; `cmd/serve.ts`, `cmd/attach.ts`); [S-109] the Claude Agent SDK as a JSONL client of the CLI (`_internal/transport/subprocess_cli.py` L566–783); [S-107] codex `app-server`/daemon (`codex-rs/cli/src/main.rs` L170–174); [S-112] goose `serve`/`acp` (`crates/goose-cli/src/cli.rs` L829–860); [S-535] clig.dev future-proofing and noun·verb rules; ADR-0049 §4 / ADR-0050 (generated client, E3).
- (b) Source-code precedent: S-111 `packages/opencode/src/cli/cmd/run.ts` @9f8db11 (client-of-server shape); S-107 `codex-rs/cli/src/main.rs` L148–240 @0735c51 and S-112 `crates/goose-cli/src/cli.rs` L803–1110 @fae91d0 (noun-rich taxonomies; session-lifecycle verbs); Lab nouns: `no-precedent / novel` at the CLI layer (semantics from WS-J1/J2/J3/J5/J6).
- (c) Disconfirming evidence considered: the two most mature CLIs keep substantial control logic in the CLI layer (S-107 `exec/src/lib.rs` L562–571, L745–775; S-119 `packages/cli/src/config/config.ts` L782–797) and opencode's client grew CLI-only behaviour (`run.ts` L801–820) — the thin-client rule may slow operator conveniences. It does not overturn the decision: presentation conveniences stay in the CLI; anything that changes a ledger fact is a verb, and AC-K1-02 is the enforcement; ADR-0050 already fixes the layering and CF-017 pre-registers the exposure.
- (d) Conditionality: assumes WS-K4 confirms Q-L1-14 (generated client over a local transport) — if K4 narrows to in-process embedding for some surfaces, K-2 is re-stated for the CLI only (it remains out-of-process); assumes the §6.5 verb set is extended to the Lab operations (CF-356); independent of model tier, task class and budget.
- (e) Build-stage assignment: C0/Stage 0 driver slice (`run start/events/status`, `definition validate`, `version`, `doctor`); C0/Stage 1 attended mode and `approval`/`run` lifecycle verbs; C1/Stage 3 Lab nouns; C1/Stage 4 `serve`/`acp`; C2 `participant`.

## Consequences
- WS-K4/WS-L5 must add generated bindings for every Lab operation the CLI names (assembly, registry, experiment, results, leaderboard, hosting) — the CLI cannot ship a Lab noun before its binding exists.
- Every CLI behaviour that is not pure presentation gets a ledger event or a manifest field; there is no CLI configuration that changes a run without appearing in `configuration_version_id`, a layer, or an `amend`.
- WS-K2 and WS-K3 reuse the same rendering fixtures (`n/a`, diff lines, approval rendering) and the same transport; a divergence between surfaces is a conformance failure, not a design choice.

## Reversibility
**High for the taxonomy, medium for the client rule.** Renaming or regrouping nouns is additive under K-3; abandoning the generated-client rule would require re-implementing verbs inside the CLI and re-deriving AC-K1-02 fixtures — cheap before Stage 3, expensive after the Lab nouns ship.
