# ADR-0135 — Nondeterminism recording rules and replay validity: the source table, four validity modes, the `ReplayValidityReport`, the intervention record, and the mandatory factual re-execution arm for counterfactual comparisons

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-B4 (with WS-I7 for attribution, WS-I2 for the paired protocol, WS-F1 for declaring variants, WS-L4 for the nondeterminism declaration, WS-C1 for the model fingerprint) · **Phase:** 2 · **Related:** ADR-0028, ADR-0029, ADR-0036, ADR-0038, ADR-0041, ADR-0045, ADR-0046, ADR-0017, ADR-0039, ADR-0007 (T-LCD-09/-14/-15); OQ-082, OQ-024, OQ-113, OQ-111, OQ-322, OQ-323; CF-288, CF-290; R-2.2.4, R-2.9.7, R-2.12.1

## Context

ADR-0028 makes deterministic replay a declared capability of control-strategy variants and requires WS-B4 and WS-I7 to "label every replay-derived result with its mode"; OQ-082 asks how a comparison against a re-executed branch is admissible when the variant does not declare it; OQ-024 asks where nondeterminism makes counterfactual attribution invalid. ADR-0038 already defines `NondeterminismDeclaration{source ∈ {provider_sampling, wall_clock, network, filesystem_order, concurrency}, confined_to_events}` for bundles and R1 "bit-exact" as a claim about *derivations*. The systems precedent for the boundary is rr (Tier B): record every nondeterministic input at a narrow boundary, re-execute everything else, and name what breaks it (unrecorded shared memory, parallelism); Temporal applies the same rule to workflows. Among agent systems, Shepherd (`provisional`) reconstructs the prefix byte-exactly and re-executes the suffix with fresh samples; Forgetting-Without-Restarting (`provisional`) obtains a deterministic transition system by recording model outputs; *Safe to Resume?* (`provisional`) names SF4 "unbound nondeterministic replay" and asks for "enough execution constraints to narrow replay to a well-defined continuation". No audited harness records a replay mode on a fork.

## Options considered

1. **Assume deterministic replay from snapshots (doc 3 §2.2's wording read literally).** *Rejected:* snapshots make reconstruction deterministic, not decisions (ADR-0028); CF-290.
2. **Report only a boolean `deterministic` flag.** *Rejected:* hides *which* source broke determinism and whether the world moved (fingerprint, external probes) — the SF4 failure.
3. **Forbid counterfactual comparisons unless deterministic.** *Rejected:* excludes every stochastic control strategy from I7 (ADR-0028 option 1's objection).
4. **A per-source recording table, a four-valued validity verdict computed from what the prefix actually recorded, an intervention record, and a mandatory factual re-execution arm under matched budget (chosen).**

## Decision

1. **Nondeterminism sources** (extends ADR-0038; CF-288): `NondeterminismSource = {provider_sampling, wall_clock, randomness, network, filesystem_order, concurrency, environment_state, human_input, external_service}`. Each is either *confined to events* (recorded and substitutable) or *declared* (`confined_to_events = false`).
2. **Recording rules.** `provider_sampling`: `model.call.requested.request_ref` and `model.call.completed.response_ref` at `observability_level ⊇ model_io` (ADR-0029), `ModelSnapshotRecord` with `observed_fingerprint` (ADR-0038/OQ-111), seed in the manifest. `wall_clock` and `randomness`: a control strategy obtains time and randomness only from the runtime; a variant declaring `deterministic_replay` has every read logged as `control.clock.read{value}` / `control.random.read{value}` (new classes, `durability = ledger` for declaring variants, `ephemeral` otherwise — OQ-322 asks whether to make them always durable); the PRNG is seeded from `configuration_version_id.seed ∥ branch_id`. `environment_state`: an `EnvSnapshot` at the fork point (companion ADR); uncovered reads are `degraded`. `network`/`external_service`: tool observations are `context.observation.recorded`; deterministic replay substitutes them; live branches re-issue and record `external_dependencies[].verdict` via `probe` (ADR-0030). `human_input`: `security.permission.decided{decider: human}` and principal turn inputs are substituted in deterministic mode and **never reused** for new effects on a live branch. `filesystem_order`/`concurrency`: declared only; a prefix containing parallel scopes is never `deterministic` unless the variant declares single-scope scheduling.
3. **Replay driver rule.** `replay(deterministic)` feeds recorded responses, observations and decisions to a declaring variant and dispatches **no** effect (the external-gateway rule); a call the record does not contain is `ReplayDiverged(at_seq, expected, got)` and makes the branch `invalid`. `replay(reconstruct)` rebuilds views and the environment without re-executing anything (ADR-0028 §1).
4. **Validity verdict** — `ReplayValidityReport{mode, variant_declares_deterministic_replay, sources[{source, confined_to_events, substituted}], env{binding, coverage, uncaptured[]}, model{snapshot_record, fingerprint_match}, external_dependencies[], reasons[]}`, pure over the branch record, the source prefix and the bundle, recorded on every branch and on every results row derived from one: `deterministic` iff the variant declares it, every source consumed in the prefix is confined to events, the fork point is coherent, `fingerprint_match ≠ mismatch`, and the driver reproduced the recorded `control.decision` and `view_hash` sequences to the fork point (AC-B1-4 as precondition) — it is a claim about decisions and derived views (ADR-0038 R1), never about re-sampled outcomes; `re_executed` iff the fork point is coherent and the environment is snapshot-coupled but some source is unrecorded or the variant undeclared; `degraded` when the world moved (fingerprint mismatch, a probe contradicting a recorded observation, uncovered environment reads) — reported, never hidden, excluded from `artifact_benefit` rows by default; `invalid` for an incoherent fork point, a `trace_only` branch that executed a non-`read_only` effect, `ReplayDiverged`, or an intervention preceding the fork point. The mode is the minimum over sources.
5. **Intervention record** (the WS-I7 hook): `InterventionRecord{kind ∈ {definition_diff, profile_diff, response_substitution, observation_substitution, decision_override, budget_change, permission_change}, target, payload_ref (a `HirDiff` for definition/profile kinds, ADR-0017), earliest_affected_seq (derived from `ir_refs[]`, ADR-0027), coupling_assumption ∈ {weak, declared_strong}, hypothesis, provenance}`; `counterfactual(run, at, intervention, design)` refuses `at > earliest_affected_seq` and refuses without a `MatchSpec` (ADR-0041, T-LCD-14).
6. **Admissibility of counterfactual comparisons (OQ-082 at the B4 level).** A counterfactual claim is a `ComparisonReport` whose arms are `n ≥ k` factual re-executions from the fork point (no intervention) and `n ≥ k` counterfactual branches from the same fork point and snapshot, seeds as the replicate axis (ADR-0045), matched on the suffix budget, distributions reported with `replay_mode` on every row, all `branch_kind = counterfactual`, `charged_to = instrument` (ADR-0039); the factual arm's dispersion is the noise floor and is always reported; `k = 1` suffices for the decision sequence in `deterministic` mode but never for outcomes. WS-I7 fixes `k`, the margin and the statistic (OQ-323, jointly with OQ-113).
7. **Reproducibility interaction.** A bundle's `claimed_level` for a branch is capped by its validity mode: `invalid` ⇒ R0; `degraded`/`re_executed` ⇒ ≤ R3 (statistical) or R2 where ADR-0038's pins allow; `deterministic` ⇒ R1 for decisions and views.

**T-LCD statement.** Satisfies T-LCD-14 (`counterfactual` refuses un-budgeted arms; search/eval budgets separated by ADR-0046), T-LCD-09 (branch rows carry factor coordinates plus `branch_kind`, `fork_point`, `replay_mode` so interaction effects remain representable), T-LCD-15 (validity and replay metrics are `n/a` for participants without `model_io`/`fork`), T-LCD-08 (deterministic replay is declared per variant inside its contract; the driver is supplied by Core), T-LCD-12 (operations). Not applicable: T-01/-02/-03/-04/-05/-06/-07/-10/-11/-13. **ADR-0024 rung:** recording rules, driver and verdict are MUST-code; `k`, margins and `coupling_assumption` defaults are MUST-data (experiment `Design`).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** S-480 rr (Tier B; nondeterministic inputs recorded at the syscall/signal boundary, deterministic computation re-executed, single-CPU constraint, unrecorded shared memory and parallelism break replay); S-193 Temporal determinism constraints (Tier B; via ADR-0028); S-078 Shepherd (`provisional`; byte-exact prefix reconstruction + re-executed suffix; "weak coupling" assumption App. A.1); S-479 Forgetting-Without-Restarting (`provisional`; deterministic transition system given recorded model outputs; suffix "irreducibly tainted without token-level attribution"); S-476 *Safe to Resume?* (`provisional`; SF4 unbound nondeterministic replay; "narrow replay to a well-defined continuation"); S-481 Firecracker (Tier B; clock, network and entropy are not preserved by VM snapshots); ADR-0028 (c) (re-executed branches carry sampling noise; handled statistically by paired runs and seeds); ADR-0038 F7 (provider-side model identity is a claim; fingerprint as drift evidence).
- **(b) Source-code precedent:** langgraph S-143 @e539ac1 `libs/checkpoint/langgraph/checkpoint/base/__init__.py` L93–147 (`versions_seen` per node — the per-source bookkeeping idea behind `sources[]`), `libs/langgraph/langgraph/_internal/_replay.py` (`ReplayState`: first visit restores the pre-replay checkpoint, later visits load fresh ones — replay-vs-live distinction inside one run); codex S-107 @0735c51 `codex-rs/core/src/context_manager/normalize.rs` L19–134 (synthetic terminal records with stable ids "to preserve prompt-cache reuse" — byte-identical prefixes as the cache-warm replay substrate) and `core/src/thread_manager.rs` L166–197 (coherent fork points as the precondition); pi-mono S-113 @400d690 `packages/agent/src/harness/session/types.ts` (`effect_pending{replay: "never" | "safe"}` — a per-effect replay-safety declaration); the replay mode label, validity report and factual re-execution arm are `no-precedent / novel` as a contract (partial precedent: Shepherd's counterfactual search, Temporal's nondeterminism errors).
- **(c) Disconfirming evidence considered:** even recorded model I/O cannot be re-sampled identically after a provider update, so `deterministic` may be unattainable in practice for long-lived runs (why it does not overturn: the verdict is computed from the fingerprint and is `degraded` when it moves; the claim is about decisions and derived views, which need no re-sampling); logging clock/random reads adds events to every declaring variant (why not: durability is conditional on declaration; non-declaring variants pay nothing); the factual arm doubles the cost of every counterfactual (why not: without it the attributed effect includes sampling noise of unknown size — ADR-0046's matched-budget discipline applied to attribution; `k` is I7's knob); the weak-coupling assumption may be false for definition-level interventions (why not: it is recorded on the intervention, the fork point is forced to precede `earliest_affected_seq`, and I7 may require `declared_strong` designs to fork at run start).
- **(d) Conditionality:** `deterministic` is available only to native participants (and model-boundary-intercepted hosted ones) with `model_io` recorded and a declaring variant; `re_executed` requires only the companion ADR's snapshot coupling; the counterfactual protocol assumes ADR-0045/0046's replicate and budget machinery and the ADR-0036 keys; single-scope scheduling assumptions hold only for variants that declare them.
- **(e) Build-stage assignment:** C0 / Stage 3 (evaluation-first) — recording rules for declaring variants, both replay-driver modes, `validity`/`ReplayValidityReport`, `counterfactual` hook with the factual arm, AC-B4-7/-8; C0 / Stage 3 shares the replay driver with ADR-0028's AC-B1-4; C4 / Stage 6 — WS-I7 attribution statistics and evolution proposals evaluated as counterfactual arms (WS-I5).

## Consequences

- WS-F1 declaring variants must obtain time and randomness through the runtime and pass recorded inputs through their contract (T-LCD-08); WS-A5 passes them in the same way ADR-0028 requires for recorded I/O.
- WS-L4's `NondeterminismDeclaration` set grows by four values; bundles record `ReplayValidityReport`s for branch members.
- WS-I2/I7 consume `replay_mode` on every row; `degraded` rows are excluded from `artifact_benefit` by default and reported separately.
- WS-C1's fingerprint probe (OQ-111) becomes an input to a runtime verdict, not only a bundle annotation.
- Doc 3 §2.2's phrase "deterministic environment snapshots improve replay" is read as improving *reconstruction* (CF-290).

## Reversibility

**High.** Adding sources or verdict values is additive; making clock/random reads always durable is a persistence-policy change; dropping the factual arm would be a documentation change that weakens I7's evidence standard and is not recommended. Nothing in Core storage changes either way.
