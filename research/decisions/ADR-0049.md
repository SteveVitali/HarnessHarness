## Context

ADR-0009 postpones the language decision by rule unless every questionnaire item Q-L1-01…14 (OQ-040…046) is answered language-neutrally and the A3/A4/A5/B1 ADRs are ratified. Both preconditions are now met (ADR-0015…0029). Two questionnaire items were assigned to this synthesis rather than to a Phase 1 workstream: the provisional sandbox-helper placement (Q-L1-12 / OQ-045, whose final owner is WS-B5/E5 in Phase 2) and the repo-local ecosystem tally (Q-L1-11 / OQ-046, which WS-A1 listed but did not count); OQ-047 asks how the two spikes are run without ecosystem bias. `research/synthesis/l1-inputs.md` assembles every answer with its citation; this ADR fixes the three synthesis-owned answers and the gate determination so the ratification subagent can run ADR-0009 §6.3 mechanically.

## Options considered

1. **Postpone ratification to the Phase 2 gate** because OQ-045 is provisional. Rejected: ADR-0009 explicitly asks for a *provisional* Q-L1-12 answer at end of Phase 1 and carries a revalidation trigger if WS-B5/E5 move the helper.
2. **Answer Q-L1-12 "in-process"** (seccomp/Landlock driver linked into the kernel). Rejected on the audited evidence: every product-grade harness read in source drives the sandbox from outside the process that owns the loop (Codex ships `codex-rs/linux-sandbox` as a separate binary; Claude Code drives Seatbelt/bubblewrap without in-process bindings; OpenHands runs a Docker workspace over a boundary — S-107, S-053, S-110), and an out-of-process helper is what T-LCD-12 and the ADR-0009 boundary contract already assume for third-party components.
3. **Record the provisional answer "separate helper binary behind a narrow protocol", tally Q-L1-11 from the repositories actually opened, and fix the spike plan (chosen).**

## Decision

1. **Hard gates (CF-112):** none fires. C6 — WS-A3 requires closed sums *as a property* satisfiable by schema validation plus a registry-completeness CI test, and effects are recorded and consistency-checked at validation, not statically typed (ADR-0015); WS-A5 requires no closed sums over variant tags (ADR-0023). C4 — provisional answer below. C3 — relaxed: an owned event store with reconstruction; durable-execution-library determinism applies only to the optional replay driver (ADR-0028). C2 stays unconditional (no Tier-1/official MCP SDK and no official ACP library ⇒ excluded for the kernel).
2. **OQ-045 provisional answer (Q-L1-12):** the sandbox helper lives **outside the kernel process as a separate helper binary behind a narrow protocol**; the kernel *drives* OS primitives (seccomp/Landlock/Seatbelt/job objects/containers) through that boundary. Consequence: the C4 hard gate does not fire; C4 is scored on "drive" capability. Final answer WS-B5/E5 (Phase 2); if they move the helper in-process, the ADR-0009 revalidation trigger re-runs steps 3–7.
3. **Q-L1-11 repo-local tally** (repositories opened in source at pinned commits in Phases 0–1; ecosystem classes per ADR-0009 — kernel layer and product-surface layer counted separately; exact counts are a repo-local measure, not a population statistic — CF-018 caveat stands):
   - *Kernel / core-loop layer:* E1 compiled memory-safe: 2 (codex `codex-rs`, goose `crates`); E2 managed-runtime dynamically-typed research: 20 (OpenHands software-agent-sdk, claude-agent-sdk-python, AIOS, Omnigent, DSPy, LangGraph, AutoGen (python), oracle/agent-spec `pyagentspec`, CaMeL, Fides, ADAS, AFlow, Harbor, Inspect AI, HAL, SWE-bench harness, tau-bench, agentdojo, mini-SWE-agent, Aider — of which six are the evaluation/laboratory tools the J/I tracks will touch constantly); E3 managed-runtime gradually-typed web-native: 2 (pi-mono, opencode); E4: 0 audited; other (BEAM): 1 (openai/symphony).
   - *Product-surface layer (CLI/SDK/UI in a different class from the kernel):* E3: 4 (codex CLI + TS SDK, goose desktop, Claude Code CLI, agent-spec `tsagentspec`); E2: 1 (codex `sdk/python-runtime`).
   - *Reading:* the systems the program must read/port are concentrated in E2; the two compiled kernels and the two web-native kernels are the product-grade reference loops; every product-grade system is polyglot at a surface boundary (WS-L1 M3). C10 is scored from this tally plus the population statistics S-163/S-164.
4. **Q-L1-14 provisional answer (K4 preview):** a generated client over a local transport is acceptable for the SDK/embedding API (the Codex app-server / OpenHands agent-server / opencode shape, S-107/S-110/S-111); WS-K4 confirms or narrows in Phase 3. C9/C12 are scored accordingly.
5. **Spike execution plan (OQ-047):** the orchestrator spawns a **WS-L1 ratification subagent** that (i) freezes and logs the C1–C12 weights *before* opening any candidate evidence; (ii) writes one spike spec (`research/synthesis/l1-spike-spec.md`) covering S1 (kernel slice: append-only ledger with the ADR-0027 id model, one `project()` view, one sandboxed tool call through a helper-binary boundary, one MCP client call, one ACP stdio session at N=1 and N=50) and S2 (boundary slice for E5 candidates); (iii) runs each candidate's spikes in a **fresh subagent per candidate** from the same spec, time-boxed, throwaway; (iv) has each spike reviewed by a reviewer briefed on a *different* candidate; (v) scores with citations, runs the sensitivity sweep, applies the ≥ 0.8 win-share rule and tie-breakers, and writes the ratifying ADR with the ADR-0009 §6.6 data model. The sponsor decides; the subagent recommends.
6. **Language-leak audit, Phase 1 (CF-111):** clean — recorded for AC8 of ADR-0009.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** sandbox primitives are OS-level and drivable from any ecosystem, with in-process syscall filtering the exception (WS-L1 M7, S-053); product harnesses isolate the sandbox driver in a separate binary or container (S-107 `codex-rs/linux-sandbox/src/landlock.rs`, `codex-rs/exec-server/README.md`; S-110 `openhands-workspace/.../docker/workspace.py`; S-109 `_internal/transport/subprocess_cli.py`); the questionnaire answers rest on ADR-0015/0019/0021/0023/0026/0028/0029/0036/0045 (ratified, Tier-A/B evidence).
- **(b) Source-code precedent:** paths above (audited at codex 0735c51, software-agent-sdk 3fc7b22, claude-agent-sdk-python ad77094); the pre-registered blind-weight spike procedure is ADR-0009's and is `no-precedent / novel` in this domain.
- **(c) Disconfirming evidence considered:** an in-process helper gives the lowest per-call overhead and the AIOS `aios-rs` scaffold shows polyglot cost is real (WS-L1 §5) — accepted as a C12/C7 scoring input, not a gate; the repo-local tally over-weights E2 because evaluation tools dominate the audited set — mitigated by counting kernels and surfaces separately and by the population statistics.
- **(d) Conditionality:** the OQ-045 answer is provisional on WS-B5/E5 (Phase 2) and on the coding/terminal environment class chosen by the sponsor; the tally is a 2026-09 snapshot.
- **(e) Build-stage assignment:** program-level input to the WS-L1 ratification (prerequisite for Stage 0 of the build ladder); no C-tier item.
