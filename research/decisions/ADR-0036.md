# ADR-0036 — Unified identity model: five identity kinds, self-describing digests under a pinned identity profile, and the hash/canonical-form rotation procedure

**Status:** **ratified, amended** (Phase 2 synthesis, 2026-09-10); previously: **ratified** (Phase 1 synthesis, 2026-09-10)
**Owner workstream(s):** WS-L4 (co-owners WS-A3, WS-B1; consumers WS-A5, WS-I3, WS-J2, WS-J5, WS-H6, WS-D4, WS-H5, WS-C3, WS-L1) · **Phase:** 1 · **Related:** ADR-0007 (T-LCD-10/-11/-12/-15), ADR-0008, ADR-0009 (WS-L1 criteria C3/C6), ADR-0011; ADR-0015/ADR-0017, ADR-0027/ADR-0029, ADR-0025; OQ-041, OQ-056, OQ-083, OQ-074; CF-083, CF-085, CF-086; R-2.12.1, R-2.2.1, R-2.8.6, R-2.10.2, R-2.10.5

## Context

WS-A3 fixed two content-addressed identities per HIR node (`version_id` over the canonical form; `semantic_id` over the semantic projection) and a JCS-class canonical form; WS-B1 fixed `ContentAddress` for blobs, allocated time-ordered ids for runs/events and a per-run hash chain; WS-A5 fixed sealing (all references pinned) and a `ConfigurationId`. Three things were left open and assigned to WS-L4: which hash algorithm and canonical-form version are pinned and how either is rotated without invalidating a corpus (OQ-056 / OQ-083, the algorithm half of OQ-041); how identities extend beyond HIR nodes to variants, profiles, policies, budgets, graders, task data, environment images and bundles; and how *names* and *version labels* relate to identities. WS-A5 keys `ConfigurationId` by `semantic_id` while WS-A3 §6.14 and WS-B1 require manifest ids to be `version_id`s (CF-083).

The audit found that every mature content-addressing system uses a domain tag + canonical bytes + hash (git object headers, Nix fingerprints, RFC 6962 prefixes), that systems without an algorithm tag paid for it later (git's multi-year SHA-1 transition), that OCI and multihash self-describe the algorithm, that Harbor/Inspect/OpenHands/Codex all record inputs by digest or commit *at the moment of use* while leaving provider-side model identity as a claim, and that mature systems disagree on whether the *name* enters identity (Nix yes, Unison no).

## Options considered

1. **One fixed algorithm, untagged ids** (git 2005). *Rejected:* rotation becomes an object-format migration; ids cannot be verified without out-of-band knowledge; contradicts OCI/multihash practice.
2. **Names inside identity** (Nix store paths). *Rejected for the IR layer:* violates T-LCD-10 (rename must not change identity) and the ratified `surface vs semantic identity`; **adopted at the registry layer** as a hashed name-binding record.
3. **Random/allocated ids for definitions and variants** (Agent Spec UUIDs, OpenHands profile ids). *Rejected:* identity not tied to content; two machines cannot agree; kept only for runtime observations (WS-B1).
4. **Path- or label-based identity** (goose recipe path hash; Harbor `AgentInfo.version` string). *Rejected:* not content-anchored; Harbor itself keys lock equality by digest.
5. **Five identity kinds with domain separation, self-describing digests under a pinned, rotatable identity profile; names as append-only histories bound to versions by hashed records (chosen).**

## Decision

1. **Five identity kinds** with fixed domains (dossier §6.1): *content address* (raw bytes and directory trees via one tree rule), *version id* (every authored typed record: HIR nodes/sealed definitions, variant records, Model Profile versions, permission policies, budgets, Validators/graders, task-data manifests, capability declarations, run manifests, bundle manifests, name-binding records, identity profiles), *semantic id* (HIR kinds only, WS-A3 verbatim), *allocated id* (WS-B1 verbatim), *logical name* with append-only name history. One reference type, `VersionedRef{kind, version_id, semantic_id?, name?, resolved_from?, supersedes?, provenance, idp}`.
2. **Identity profile.** `IdentityProfile{idp_id, hash_algorithm, digest_length, canonical_form_version, domain_tags, tree_rule_version, id_text_form}` is a versioned record; every id is `(idp, domain_tag, digest)` and is rendered `<algorithm>:<lowercase hex>` (OCI grammar). Exactly one idp is mandatory-writable at a time; all prior idps remain readable; there is no default a consumer may assume. `idp/1` requires a 256-bit, standardized, collision-resistant hash with streaming computation and ubiquitous independent implementations — the algorithm OCI mandates satisfies this; naming a cryptographic standard is not an ecosystem commitment (RK-09 unaffected).
3. **Invariants N1–N8:** full digests only (no truncation); self-describing; domain separation (blob ≠ node ≠ tree with equal bytes); equality by digest never by name/path; sealed/executed/published forms contain only pinned ids; semantic ids are the comparison coordinate and version ids the execution coordinate — hence **two configuration ids** (`configuration_id` over semantic ids without seed as the factor coordinate; `configuration_version_id` over version ids with seed as the manifest key), resolving CF-083; provider ids (model snapshot ids, container tags, provider tool-call ids) are surfaces/claims with `provenance = reported`; one tree rule, foreign digests recorded as claims.
4. **Rotation (contract fixed now, operated at Phase 2+):** ids are never rewritten; a bridge record for the new idp is hashed under the old; every live run and bundle receives a rotation checkpoint (`security.audit.checkpoint` with `rehash{idp', chain_hash', tree_head'}` and the bridge reference — RFC 6962 consistency shape) attested by WS-H6; mixed-idp reference graphs are legal; an `IdMigration` map is derived on demand from stored canonical bytes and is itself a versioned record; `alt_ids[]` during dual-write are never identity. Canonical-form changes are rotations with the same algorithm. Failure modes: `UnknownIdentityProfile`, `AlgorithmMismatch`, `DigestLengthInvalid`, `TruncatedId`, `IdpNotWritable`, `BridgeMissing`.
5. **`registry_snapshot_id`** (OQ-074) hashes the sorted `(namespace, name, resolved version_id)` triples of the transitive closure actually referenced — not the catalog; a `catalog_id` may be recorded as a claim.
6. **WS-B1 `ContentAddress`** gains the `idp` field (or `hash_algorithm` is defined as the idp reference) — CF-086, WS-B1 to confirm.

**T-LCD statement.** Satisfies T-LCD-10 (identity excludes surfaces at the IR layer and names at the registry layer; AC-L4-3), T-LCD-11 (foreign digests carried as typed claims, never dropped), T-LCD-12 (operations over the canonical encoding; out-of-process), T-LCD-15 (identity kinds apply uniformly; hosted `version_identity` is a `version_id` over a declaration). Not applicable: the remaining tests.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** domain-tagged content addressing — git object headers (S-224), Nix store-path fingerprints with input- vs content-addressing (S-225), RFC 6962 leaf/node prefixes (S-190); self-describing agile digests — multihash (S-226), OCI descriptors (S-187: SHA-256 mandatory, unrecognized algorithms pass through, content must not change identifiers); canonical byte form — RFC 8785 (S-172); names as metadata — Unison (S-171); pinning at moment of use — OpenHands `ResolvedPluginSource` (S-110), Codex `SessionMeta{cli_version, git}` (S-107), Harbor lock digests (S-132), Inspect `EvalRevision`/`packages` (S-136); provider identity as a claim — Codex `models.json` slug, Harbor `ModelInfo`, Inspect `model` (S-107/S-132/S-136) and model-drift reports S-047/S-049 (Tier B); provenance envelopes by digest — SLSA v1 (S-223).
- **(b) Source-code precedent:** harbor `src/harbor/models/job/lock.py` @7d5285b (`TaskLock{digest}`, `AgentSkillLock{digest}`, equality by digest; `_validate_digest` requires `sha256:` + 64 hex), `src/harbor/models/trial/config.py` L176–188 (config content key over canonical JSON), `src/harbor/models/task/id.py` L41–54 (digest refs); inspect_ai `src/inspect_ai/log/_log.py` L993–1100 @75f4891; software-agent-sdk `openhands-sdk/openhands/sdk/plugin/types.py` L118–197, `plugin/fetch.py` L70–120 @3fc7b22; codex `codex-rs/protocol/src/protocol.rs` L3050–3100, L3352–3367 @0735c51; opencontainers/image-spec `descriptor.md`; multiformats/multihash README. **`no-precedent / novel`** for: an identity profile record with an in-band rotation checkpoint over an agent ledger; two configuration ids (semantic coordinate vs exact-bytes key); the `VersionedRef` carrying provenance across all record kinds.
- **(c) Disconfirming evidence considered:** git ran on one untagged algorithm for over a decade and most audited harnesses use no algorithm tag at all — agility may be dead weight; Nix's inclusion of the name in identity argues that "same bytes, different name" can be different things; content addressing everything is bookkeeping that Harbor and Inspect only partially keep (tags for images, strings for versions). *Why none overturns:* git's SHA-1 transition is the measured cost of omitting the tag and OCI/multihash are the post-hoc corrections; the name disagreement is resolved by layer (excluded from IR identity per T-LCD-10, present as a hashed binding at the registry); partial pinning is made legal and visible through the reproducibility levels (ADR-0038) rather than forbidden, so the bookkeeping cost is paid only where a claim is made.
- **(d) Conditionality:** model- and task-independent; assumes the WS-A3/B1 canonical form is stable through Stage 1 (a change is a rotation); assumes a 256-bit standardized hash remains collision-resistant for the program's horizon (rotation exists for when it does not); the tree rule assumes filesystem-shaped artifacts (large binary corpora may use per-file addressing plus a manifest).
- **(e) Build-stage assignment:** **C0 / Stage 1** (`idp/1`, `address`/`identify`/`verify`, `VersionedRef`, both configuration ids in the run manifest, golden corpus AC-L4-1…5); **C0 / Stage 2** (`snapshot_registry`, environment/model records); **C1 / Stage 4** (`rotate`/`migrate_id` end-to-end with WS-H6, AC-L4-6).

## Consequences

- WS-A3's `identity()` and WS-B1's `put_blob` become two entry points of one identity service sharing one canonicalizer, one idp and one golden corpus; WS-B1's `ContentAddress` carries `idp`.
- WS-A5's `resolve` mints `registry_snapshot_id` over the closure and pins both configuration ids; WS-J5 aggregates by `configuration_id` and keys rows by `configuration_version_id`.
- WS-H6's audit checkpoint schema gains the rotation fields; WS-I3's bundle manifest carries `idp`.
- WS-L1 receives H1–H3 (canonicalizer, agile streaming hash, deterministic tree serialization) as weighted criteria; no hard gate fires.
- Every consumer that displays ids must derive abbreviations at render time; stored abbreviations are a defect.

## Reversibility

**Low** for the invariants N1–N5 and the pinned-form rule (every stored id and manifest depends on them); **medium** for the idp record and rotation procedure (unused until a rotation; a simpler procedure could replace it before the first rotation); **high** for the two-configuration-id split (a naming/aggregation convention in the results store).
