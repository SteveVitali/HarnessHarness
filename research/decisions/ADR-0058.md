# ADR-0058 — The credential broker contract: register/grant/bind/mediate/mint/revoke/rotate; broker delivers, reference monitor decides; proxy-injection primary, minted scoped token secondary, wrapped long-lived credential only as an authorized and revoked exception; lifetime ⊆ run; fail closed

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-H3 (with WS-H4 for `mediate` at the egress proxy; WS-B5 for the environment handle; WS-H1 for the grant and Π) · **Phase:** 2 · **Related:** ADR-0057 (invariants), ADR-0016 (`Permission{holder, grants, issuer}`, delegation attenuates), ADR-0024 (MUST-code vs MUST-data), ADR-0026 (writer lease; durable-before-visible), ADR-0030/0031/0032 (effect lifecycle; risk class; compensation), ADR-0035 (monitor reads records only; approval endorses one `effect_id`), ADR-0039/0040 (budgets; approvals exhaustion `ask → deny`), ADR-0049 (OQ-045 helper boundary), ADR-0050 D2 (no raw provider credentials cross the lab/surface boundary), ADR-0005/ADR-0010 (Hosting ABI); CF-131, CF-132; OQ-101, OQ-148, OQ-150, OQ-152; R-2.8.3, R-2.8.4, R-2.2.5; T-LCD-06/07/11/12

## Context

ADR-0057 says where a value may exist; this ADR says how an authenticated action happens without the value leaving the kernel side. Three delivery models are documented in the field (CB4A S-274; S-275/03): A proxy-injection (agent never holds a credential), B minted scoped token (agent holds a short-lived audience-bound token), C wrapped long-lived credential with scheduled revocation. Production designs implement A (S-053 in-VM proxy; S-047 vault + session-keyed MCP proxy; S-107 `network-proxy` credential broker; S-278) and B (S-053 per-session scoped-down token; S-282 per-job OIDC JWT); C survives where destinations offer nothing else (S-047 git token wired into the remote; S-107 `restore_brokered_credentials` when a child "intentionally leaves managed networking"). CB4A additionally separates the policy decision point from the credential delivery point and makes audit failure fail-closed; Codex scopes every proxy decision to an execution registered by the executor and refuses to widen strict allow-lists through approval callbacks; Anthropic's 93 % approval rate (S-053) means an `ask` row is not a control for secret use.

## Options considered

1. **Model B primary (CB4A's recommendation).** *Rejected as primary for native environments:* the agent holds a real token in an environment whose tools and files are model-reachable; most audited destinations (model providers, git hosting, MCP servers) are bearer-header APIs without token exchange (S-275); kept as the secondary mode for exchange-capable or signature-based destinations.
2. **Model A only.** *Rejected:* cannot serve signature-based schemes, certificate-pinned or non-HTTP clients (S-277; dossier §5); some destinations must be reachable.
3. **Model C by default with revocation (OpenHands whole-registry injection for opaque consumers; Harbor/Inspect env passthrough).** *Rejected:* the value is in the environment for the run's duration; S-110's own comment calls least-privilege scoping "deferred."
4. **Broker decides its own policy (single component).** *Rejected:* violates ADR-0035 (monitor reads records only) and CB4A PDP/CDP separation; would put credential material in the component that reasons about authority.
5. **A primary, B secondary, C authorized exception; broker as CDP behind the H1 monitor as PDP; declarative per-channel mode allow-list; lifetime ⊆ run; fail closed (chosen).**

## Decision

1. **Placement.** The Credential Broker is MUST-code (ADR-0024) in the kernel, on the kernel side of the OQ-045 helper boundary (ADR-0049), never inside an environment handle and never on the optimizer's editable surface (ADR-0002 iii). Channel specs, allow-lists, destination bindings and mode lists are MUST-data in the sealed definition. Nothing crosses the ADR-0050 D2 boundaries but references and events.
2. **Operations** (dossier §6.3): `register_channel(spec) → channel_id | ChannelExists | InvalidBinding`; `grant(run_id, holder, channel_id, scope ⊆ spec.destinations, constraints) → Permission | ScopeExceedsChannel | IssuerAuthorityInsufficient` (issued by WS-H1's monitor with `issuer.authority ≥ principal | definition`, never `delegate`; ledger `security.permission.granted`); `bind(run_id, env_handle, channel_id, mode, monitor_decision_ref) → Binding | NoGrant | ModeNotAllowed | DecisionMissing | EnvironmentNotIsolated`; `mediate(binding_id, RequestDescriptor{destination, method, path, carrier_slots}) → Injected{carrier} | Refused{expired | revoked | out_of_scope | ambiguous_path | sender_constraint_unmet | broker_unavailable | audit_unavailable | canary}`; `mint(binding_id, destination) → Token{expires_at, audience, sender_key?}`; `revoke(binding_id | channel_id, reason)`; `rotate(channel_id, expected_revision, new_source_ref) → revision' | Conflict{current}`; `kernel_use(channel_id, purpose ∈ {ledger_signing, gateway_auth, vault_auth}, caller) → Used | Refused` for **kernel-internal channels** (`bindable = false`, never bound into any environment — the ADR-0067 signer key, the WS-C1 gateway credential per OQ-148, the vault credential; callers restricted to kernel components). Every operation appends its `security.credential.*` event durably before its result is visible (ADR-0026).
3. **Delivery modes.** `DeliveryMode = {proxy_injected, minted_scoped, wrapped_long_lived}`, declared per channel as an ordered allow-list; the kernel selects the first allowed mode that the destination supports in the fixed preference `proxy_injected` (header-carried schemes via H4's proxy) > `minted_scoped` (exchange-capable sources, signature-based auth; non-renewable; `ttl ≤ min(max_lifetime, run.remaining)`; `audience = destination`; sender-constrained where verified) > `wrapped_long_lived` (only with `allow` from a `principal`/`definition`-issued rule naming channel and destination; never `ask` in unattended mode; a compensating revocation effect registered at `prepare` per ADR-0032; `EnvironmentNotIsolated` unless the handle's `isolation_class` — ADR-0060's `ContainmentPolicy/1` field — is at least `process_sandbox`). Bindings and masked mounts are realised as `ContainmentPolicy/1.credential_bindings` (ADR-0060: H3 fills them).
4. **PDP/CDP separation.** The broker refuses any `bind`/`mediate` without a `security.permission.decided{effect_id, decision = allow}` record for a `secret_access` grant covering the destination; the monitor never receives a value; a model-authored justification is not an input (CB4A TM-5). Approval, where a definition permits it, endorses one `effect_id` (ADR-0035) and never widens a destination scope (S-107 `execution_scope.rs`: strict allow-lists cannot be expanded through approval callbacks).
5. **Scoping and attribution.** Bindings are scoped to `(run_id, env_handle, permission_id)` and identified by an allocated `binding_id` (ADR-0036); `mediate` normalises the destination host, matches the channel's `DestinationBinding` (scheme, host pattern, port, path prefix), refuses ambiguous paths (S-107 `authorization_path.rs`), and records `binding_id`, destination, `effect_id` and `monitor_decision_ref` on `security.credential.used`. Credential use rides the `net_egress` effect it decorates (CF-130 proposal; H4 confirms) so retries share `effect_id` and idempotency keys (ADR-0031).
6. **Lifetime and rotation.** SV-6: a binding dies at the earliest of run terminal event, writer-lease fencing, environment detach, `Permission` revocation, rotation, `expires_at`; nothing is renewable. `rotate` is compare-and-swap on the channel revision (S-110 `credential.py` precedent); old revisions remain in the mask set; all bindings on the channel are revoked and rebound.
7. **Delegation and hosting.** SV-7: a child `AgentProcess` holds channels ⊆ parent's with scope ⊆ parent's (ADR-0016). A hosted participant receives bindings only for channels declared in its `credential_supply` capability declaration, probed like any other (T-LCD-07); whole-registry injection is forbidden (CF-131).
8. **Fail closed.** SV-9: broker, vault or ledger writer unavailable ⇒ `Refused`; no environment fallback; the model receives a terminal `SecretUnavailable{channel, reason}` observation (ADR-0030: the model always sees a terminal or explicit `unknown`).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: proxy-injection and per-session scoped tokens in production — S-053, S-047 (Tier B); three delivery models, PDP/CDP separation, non-renewable absolute TTL, fail-closed audit, threat list TM-1…TM-11 — S-274 (Internet-Draft, mechanism only), S-275/03 (production write-ups); audience binding and passthrough prohibition — S-153 spec + RFC 8707 (S-284); token exchange and sender constraints — RFC 8693 (S-286), RFC 9449 (S-285); per-job non-renewable identity tokens with subject/audience claims — S-282; approval fatigue makes `ask` a non-control — S-053 (93 %); delegation attenuates — ADR-0016 (ratified).
- (b) Source-code precedent: `openai/codex @ 0735c51` `codex-rs/network-proxy/src/credential_broker.rs` L1269–1330 (`inject_request_headers_for_environment`: host normalisation, binding match, path safety), L530–560 / L995–1015 (virtualise / restore), `credential_broker/provider_config.rs` L5–40 (declarative channel: env, patterns, url_prefixes, auth carrier, header, prefix), `credential_broker/providers.rs` L15–60 (host-binding sum), `network-proxy/src/proxy/execution_scope.rs` L1–60 (execution-scoped attribution; no widening via approval), `network-proxy/src/runtime.rs` L455–560 (discover → virtualise → mediate → restore lifecycle), `rmcp-client/src/oauth/credential_store.rs` (refresh under exclusive guard); `OpenHands/software-agent-sdk @ 3fc7b22` `openhands-sdk/openhands/sdk/credential.py` L11–14, L44–120 (`ResolvedCredential{value, version}`, `load`/`replace(expected_version)` with `Conflict`), `openhands-agent-server/openhands/agent_server/credential_binding.py` (activation record with bounded headers); `Infisical/agent-vault` README (placeholder + host/path-scoped injection, independent re-derivation). The PDP/CDP split between an IR-recorded `Permission`, a ledger decision record and a value-holding broker, with credential use bound to the ADR-0030 effect lifecycle, is `no-precedent / novel` as an integrated contract.
- (c) Disconfirming evidence considered: proxy-injection needs TLS termination and cannot serve pinned, non-HTTP or signature-based clients (S-275, S-277; S-107 `mitm.rs`/`certs.rs` show the cost) — not overturning because modes are per-channel declarations with B and C as declared fallbacks; the broker is the highest-value target (CB4A TM-1) — not overturning because it caches nothing past mediation and shares the kernel TCB already holding ledger and monitor; CB4A recommends B primary — disagreement recorded (CF-132) because a kernel-controlled environment makes "the agent holds nothing" achievable where CB4A's cloud-agent setting cannot assume an interception point; the utility cost of brokering is unmeasured (S-110's deferral comment) — becomes a Lab `ComparisonReport` (OQ-153) rather than an assumption.
- (d) Conditionality: independent of model tier; assumes H4's egress proxy is the only network path from an environment handle (broker bypass, CB4A TM-11, is H4's invariant), a B5 handle with declared `isolation_class`, and destinations that are header-carried (mode A) or exchange-capable (mode B); unattended runs assume `ask` is unavailable (ADR-0039 approvals exhaustion) and rely on definition-time rules.
- (e) Build-stage assignment: C0 / Stage 1 (`register_channel`, `grant` via H1, `bind`, `revoke`, ledger events, fail-closed, LT-01/10); C0 / Stage 2 (`mediate` at H4's proxy, `minted_scoped`, `rotate`, snapshot virtualisation, LT-02/05/06/09); C0 / Stage 3 (LT-03/11 as veto metrics; utility `ComparisonReport`); C1 / Stage 3–4 (`wrapped_long_lived` with compensating revocation; hosted `credential_supply`; LT-07).

## Consequences

WS-H4's proxy calls `mediate` per outbound request and owns bypass prevention; WS-H1 issues `secret_access` grants and adopts the proposed `PolicyTable` rows (ADR-0059; ADR-0052 shape); WS-H6 obtains its signer key through `kernel_use`; WS-B5 adds `env_apply`, `env_snapshot`, `isolation_class`; WS-B2/E5 accept a `credential_binding_id` on `net_egress` effects; WS-C1 registers the provider credential as a channel (OQ-148); WS-J6 adds `credential_supply` to the capability declaration; WS-H7 treats secret use as non-askable in unattended mode; WS-A4 lowers channels as scheme + reference with `no_slot` losses.

## Reversibility

**Medium.** Mode preference and the Π row are data (a definition or policy edit); adding a delivery mode is additive; moving the broker into the environment or merging it with the monitor would reopen ADR-0024/0035 and the leak battery — expensive.
