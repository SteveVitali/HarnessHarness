# ADR-0129 — Harness-level caches with validity semantics: tool-result cache as a memory kind with dependency stamps; response cache admissible only for reproduction and declared replay; similarity-keyed semantic cache deferred to C2 with a mandatory verifier; invalidation rules over WS-L4 identities

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-C4 (with WS-D4 for the `InvalidationContract` and enforcement points, WS-E1 for `cacheable` on capabilities, WS-E5/B5 for the environment mutation epoch, WS-L4 for `StaleIndex`, WS-G3/I2 for verifier calibration, WS-H2 for `readers` scoping) · **Phase:** 2 · **Related:** ADR-0002 (no self-loosening), ADR-0028 (deterministic replay as a declared capability), ADR-0031 (risk class; `repeat_safety`), ADR-0033/0034/0035 (labels; narrow-or-preserve; endorsement), ADR-0036/0037/0038 (identities; `StaleIndex`; `reproduce`), ADR-0039 (R-ACC-2/3), ADR-0047 (judges), ADR-0007 (T-LCD-09/-13/-14/-15); ADR-0081 (`InvalidationContract`, `DependencyKind`), ADR-0120 (served-model drift; recording gateway), WS-C1 AC-C1-11; CF-275, CF-277, CF-183; OQ-310/-06/-07; R-2.3.4, R-2.4.4

## Context

Doc 2 §5.1 and Invalidation Contracts (S-077) establish that cross-episode memory "behaves like a cache" and needs version stamps and cacheability hints so stale entries are evicted deterministically; "Revoked but Still Authoritative" (S-106) shows TTL-and-similarity systems keep serving revoked facts. WS-D4 has turned that into an `InvalidationContract` with closed dependency kinds and three enforcement points, and WS-L4 into `RevocationRecord`/`StaleIndex` enforced in `resolve(mode = execute)`. The audited harness-level caches show the two ends of the spectrum: Inspect's response cache keys on the request-semantic partition with an expiry (`_cache.py`), dspy/langgraph hash the request with TTL-only expiry, litellm offers exact and similarity-keyed caches with a mandatory threshold and tenant scope but no stamps or verifier. The literature on similarity-keyed caches reports false hits of 9–23 % on unique queries (S-466, IPDPS 2025) and a black-box key-collision attack that hijacks 86 % of responses and "induce[s] malicious behaviors in LLM agents" (S-467, ICML 2026, `provisional`); the proposed mitigation is off-path verification before promotion (S-468, `provisional`). ADR-0039 already requires that a cache which skips a model call still accounts for it. What is undecided is which harness-level caches are admissible at which tier, what they key on, and how a version change or revocation reaches them.

## Options considered

1. **No harness-level caches; rely on provider prefix caching only.** *Rejected:* repeated idempotent reads and repeated retrievals are real spend (WS-D3/E3 evidence) and the Lab needs to measure caching variants; the compile cache already exists (ADR-0019).
2. **TTL-only exact-match caches (langgraph/litellm shape).** *Rejected:* TTL luck is the S-106 failure; a profile or capability version change must be a deterministic miss and a revocation must withhold, which needs stamps (S-077 mechanism; ADR-0037).
3. **Similarity-keyed semantic cache at C1 as a spend optimisation.** *Rejected at C0/C1:* measurable false-hit rate (Tier B) and a cross-principal write path (`provisional`) under an authority scheme where delivered items join the context label; admissible only as a C2 measured variant with a verifier and scoping.
4. **Response cache enabled by default in the Lab.** *Rejected:* a cached response is one sample presented as re-drawn; it fakes variance across replicates (WS-C1 S-441).
5. **Tool-result cache as a WS-D4 `Memory` kind with dependency stamps and an environment mutation epoch (C1/Stage 2); exact-match response cache keyed on the request-semantic partition plus replicate and configuration ids, admissible only for `reproduce`, recording gateways and declared `deterministic_replay` (C1/Stage 5, Lab default off); similarity-keyed cache at C2 with verifier, `readers` scoping and pre-registered threshold; invalidation rules IR-1…IR-6 over WS-L4 identities (chosen).**

## Decision

1. **K4 tool-result / retrieval cache is a `Memory{kind: tool_result}` under WS-D4's lifecycle — no second scheme.** Written by the kernel at `action.tool.completed` only when the capability's `effective_risk_class` is `{reversibility = read_only, repeat_safety = idempotent}` (ADR-0031; `unknown` never qualifies) and the capability declares `cacheable = true` (E1 record; default false). Key `H(capability semantic_id ∥ capability version_id ∥ canonical(args) ∥ environment_stamp ∥ readers)`; entry carries the observation's `ContentAddress`, its full label, `recorded_usage`, and `InvalidationContract{dependencies: [{tool_capability_version}, {environment_image / mutation epoch}, {external_resource{validator_ref}}?], cache_hint = cacheable, freshness?, invalidation_condition = dependency_changed, revalidation = must_revalidate}`, `scope ∈ {turn, run, session}`. A hit is delivered as an `Observation` with `provenance.origin = cache(entry_ref)`, `derived_from = [entry_ref]`, authority = the entry's authority (never raised), through D1's ordinary delivery events (T-LCD-13 by construction). **Environment mutation epoch (IR-3):** the kernel increments `mutation_epoch(environment_ref)` on every committed effect with `domain ∈ {fs_write, exec, net_egress, spawn_process}` in that environment; entries stamped on an earlier epoch are `stale_withheld` (RFC 9111 "invalidate after unsafe methods", conservative). Retrieval results (D3) use the same kind with index-watermark stamps.
2. **K5 exact-match response cache (C1 / Stage 5).** Key `H(plan_hash ∥ model_ref{provider_model_id, served_model?, snapshot_id?} ∥ replicate ∥ configuration_version_id)`; value = canonical `ModelMessage` + usage + timing; contract stamps `{model_snapshot, profile_version, definition_version}`. `AttemptPolicy`, deadlines, observability flags and `cache_state_hint` never enter the key; a new plan field defaults to *in* the key. Admissible uses: `reproduce(bundle, level ≥ R1)`, the recording/fake gateway variant (its corpus *is* a K5 cache), and control-strategy variants declaring `deterministic_replay`. A hit stamps `model.call.completed{served_from_cache: entry_ref}` with `timing = n/a{not_run}`; results rows carry `served_from_cache_count`; an arm enabling K5 outside `reproduce` without declaring it as a factor fails `PreRegistration` validation (T-LCD-09/-14). Served-model drift or fingerprint DRIFT (IR-4) marks earlier entries `stale_by_dependency`.
3. **K6 similarity-keyed semantic cache is C2 and a component variant, never kernel.** `lookup(request_embedding, threshold, scope{principal, readers}) → exact_hit | marginal{entry, similarity} | miss`; a `marginal` is served only after `verify(entry, request) → pass` by a registered `Validator` (deterministic where a subject key exists, else `kind: judge` with calibration and independence per ADR-0047) and is then promoted; entries carry the writer's full label and are readable only within `readers`; threshold and verifier are part of the sealed definition and the `PreRegistration`; `cache.false_hit_rate` is a mandatory class-scoped metric; a `delegate`/`external` writer's entry is never served into a higher-authority context (ADR-0034 narrow-or-preserve).
4. **Invalidation rules.** IR-1 (K1) the first miss after `relower`, sealed-definition change, tool-set change, marker-rule version change, dialect change, compaction/context edit or prefix-affecting parameter change is attributed to that event (`miss_reason`). IR-2 (K2–K6) every key includes the `version_id`s it depends on (deterministic miss on version change) and every entry carries a D4 contract whose stamps let a `RevocationRecord` → `StaleIndex` withhold matching keys (`resolve(mode = execute)` never serves; `mode = audit` returns annotated). IR-3 as in decision 1; `scope_ended` at run end unless `session` scope is declared and the label admits it. IR-4 as in decision 2. IR-5 (K3) MCP `ttlMs`/`cacheScope`/`list_changed` per WS-E3 with `model.cache.resolved{kind: catalog}` on expiry/change. IR-6 an edit that loosens a cache contract (widens `readers`, lengthens `freshness`, lowers a K6 threshold, or sets `cacheable = true` on a non-`read_only ∧ idempotent` capability) is `validity_delta = loosening` (CF-183) and unacceptable from non-human origins in an evolution context (ADR-0002).
5. **Accounting.** Every lookup emits `model.cache.resolved` and every served hit posts zero-amount charges with `cache_hit = true` (ADR-0128); K5/K6 entry storage charges `ext.bytes_stored` only if declared.
6. **T-LCD statement.** Satisfies T-LCD-09/-14 (K5 and K6 are declared factors; refusal otherwise), T-LCD-13 (K4 hits reuse delivery events), T-LCD-15 (`false_hit_rate`, `hit_rate[kind]` class-scoped), T-LCD-10 (K4 key uses the capability's `semantic_id` plus `version_id`; a surface rename alone is not a K4 miss), T-LCD-12 (operations; K4/K5/K6 implementable out-of-process over canonical documents). Rung on the ADR-0024 ladder: K4 and IR-1…IR-6 are **Core** (MUST-code: effect model, resolver guard); `cacheable`, scopes, thresholds are **data**; K6 is a **variant**.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** version stamps + cacheability hints make validity deterministic at the protocol layer (S-077, `provisional (mech)`); TTL/similarity systems serve revoked facts unless a guard sits below the model (S-106, `provisional (mech)`); HTTP caching's freshness/validators/`no-store`/invalidate-after-unsafe rules (S-355 RFC 9111, Tier A); lease expiry semantics (S-198, Tier A); false hits 89 vs 233 per 1,000 and precision-over-recall (S-466, IPDPS 2025, Tier B); semantic keys as fuzzy hashes with an 86 % black-box hijack rate transferring across embeddings (S-467, ICML 2026, `provisional`); off-path verification and promotion (S-468, `provisional`); temperature-0 nondeterminism (S-441, Tier B) — a cached response is one sample; risk class as a projection of `EffectAttributes` with `unknown ⇒ irreversible` (ADR-0031).
- **(b) Source-code precedent:** inspect_ai `src/inspect_ai/model/_cache.py` L101–200 (request-semantic key partition with transport knobs dropped, expiry beside entry, `per_epoch`), `model/_model.py` L1455–1471, L1666 (fetch/store around generate); dspy `dspy/clients/cache.py` L104–147 (canonical-request hash; corrupt entries deleted); langgraph `libs/langgraph/langgraph/types.py` L521–531 (`CachePolicy{key_func, ttl | never}` — TTL-only, rejected shape); litellm `litellm/caching/caching.py` L332–382 (param-hashed, namespaced keys), `caching/redis_semantic_cache.py` L54–106, L441–500 (mandatory `similarity_threshold`, per-entry `ttl`, tenant scope); MCP `schema/2026-07-28/schema.ts` L1081–1109 (`CacheableResult{ttlMs, cacheScope}`); WS-D4 §6.2 (`InvalidationContract`), WS-L4 §6.3 (`StaleIndex`, `resolve` modes). The K4-as-memory rule, the environment mutation epoch, the K5 admissibility rule and the K6 verifier/scoping contract are `novel as integrated` (each element precedented as listed).
- **(c) Disconfirming evidence considered:** workspace state changes under the agent so tool-result caching is inherently risky — answered by admitting only `read_only ∧ idempotent` capabilities and by the conservative epoch rule that over-invalidates; a response cache is what every eval harness uses to save money — answered by admitting it exactly there (`reproduce`, recorded gateways) and refusing it as a hidden Lab factor; the semantic-cache attack is a 2026 preprint — answered by resting the C2 gate on the Tier-B false-hit evidence and the authority scheme, with the attack as corroboration only; over-invalidation wastes the cache's benefit — answered by measuring `hit_rate[tool_result]` and avoided cost so a useless variant is visible (WS-C4 §5 R3, R4, R6). None overturns.
- **(d) Conditionality:** K4 assumes capabilities declare `EffectAttributes` honestly (ADR-0031 lets kernel assessment only raise risk) and that E5 can attribute committed effects to an environment scope; K5 assumes canonical `ModelMessage`s (WS-C1 G5); K6 assumes an embedding model and a calibrated verifier exist for the domain (C2, measured); holds for any model tier.
- **(e) Build-stage assignment:** C1 / Stage 2 (K4 as `Memory{kind: tool_result}` with stamps and the mutation epoch; IR-2/IR-3; AC-C4-7/8) → C0 / Stage 3 (refusal rules for K5 in `PreRegistration`; AC-C4-11 shape) → C1 / Stage 5 (K5 for `reproduce`/recording gateway/`deterministic_replay`; IR-4) → C2 (K6 with verifier calibration, `readers` scoping via WS-H2; AC-C4-12).

## Consequences

- WS-D4 gains a memory kind `tool_result` and a dependency granularity for the environment mutation epoch (CF-277); WS-E1 adds `cacheable` and an optional `staleness_bound` to the capability cost record; WS-E5/B5 expose committed-effect domains per environment so the epoch can be maintained; WS-L4's `StaleIndex` gains cache entries as dependants; WS-I2/J3 validate `PreRegistration` against K5/K6 enablement; WS-G3 supplies the K6 verifier calibration; WS-H2 enforces `readers` on entries at C2.
- The `validity_delta` diff class proposed by WS-D4 (CF-183) is adopted for cache-contract loosening.

## Reversibility

**Medium.** Adding K5/K6 later costs nothing if the `model.cache.resolved` schema exists from Stage 1; removing K4 is a simplification with no data loss; weakening the K6 gate (dropping the verifier) later is cheap technically but reintroduces a cross-principal write path — low reversibility for that rule, which is why it is fixed here rather than at C2.
