# ADR-0133 — Branch model and the fork / snapshot / rollback contract: two branch granularities, coherent fork points, atomic trace–environment coupling with declared coverage, rollback as an appended record

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-B4 (with WS-B1 for ledger event classes, WS-B5 for the snapshot mechanism, WS-B3 for the rollback step of recovery, WS-F3 for delegation forks) · **Phase:** 2 · **Related:** ADR-0026, ADR-0027, ADR-0028, ADR-0030, ADR-0031, ADR-0032, ADR-0036, ADR-0037, ADR-0038, ADR-0040, ADR-0050 §8; OQ-089, OQ-024, OQ-319, OQ-321; CF-286, CF-289, CF-290; R-2.2.4, R-2.2.3, R-2.2.5, R-2.9.7

## Context

ADR-0027 fixes that a fork is a new run with `forked_from{run_id, at_seq, source_head_hash}` and that HEAD moves inside a run by `lifecycle.head.moved`; ADR-0026 fixes that rollback and compaction are appended events; ADR-0028 fixes that durability is reconstruction and deterministic replay is a declared variant capability. None of them says *where* a fork may start, *what happens to the environment* when the trace forks, or what a rollback must record beyond `to_event_id`. Production code answers the first two questions inconsistently: Codex forks only at turn boundaries and synthesizes an interrupt marker when asked to fork mid-turn; the Claude Agent SDK refuses a truncating resume whose discarded range is not attributable to one turn; OpenHands forks the event log but keeps one live workspace shared between both conversations; LangGraph checkpoints framework state with no environment at all. A 2026 security study (`provisional`) demonstrates duplicate payments and unauthorized mail forwarding against precisely the last two designs (WS-B4 §4a F2). Shepherd (`provisional`) forks "the agent and its environment … atomically" and discards leave "the parent byte-identical".

## Options considered

1. **Trace-only forks (OpenHands / LangGraph shape); environment is the caller's problem.** *Rejected:* the demonstrated SF2/SF3/SF5 failure class; every Lab experiment would re-invent the coupling.
2. **Environment-only checkpoints keyed by message id with a destructively truncated transcript (opencode / gemini-cli shape).** *Rejected:* violates ADR-0026 append-only; loses the audit record of the discarded attempt.
3. **Snapshots embedded in the event stream (Codex's retired `ghost_snapshot` items).** *Rejected:* Codex removed them and strips them on load; ADR-0026 keeps environment state out of the log.
4. **Forks allowed at any `seq`.** *Rejected:* a fork inside an open model-call or effect scope cannot be continued coherently (Codex TODO; Claude SDK refusal); the ledger already records scope boundaries, so coherence is computable.
5. **One granularity only (always a new run).** *Rejected:* short speculation (best-of-K tool execution, retry-with-rollback) would allocate a run per attempt and break results keying; ADR-0027 already provides the intra-run tree.
6. **Two granularities, coherent fork points, atomic trace–environment coupling with declared coverage, rollback as an appended record with restore (chosen).**

## Decision

1. **Two branch granularities, one record.** An *intra-run branch* is a `parent_event_id` subtree opened by `lifecycle.branch.opened{BranchRecord}` under the run's single writer lease and closed by `lifecycle.branch.disposed{BranchDisposition}`; promotion and discard are `lifecycle.head.moved`. An *inter-run fork* is a new run per ADR-0027 §6 whose `lifecycle.run.forked` carries the same `BranchRecord`. `BranchRecord = {branch_id, fork_point (run_id, seq), source_head_hash, branch_kind ∈ {speculative, counterfactual, exploration, recovery, delegation}, env_binding ∈ {snapshot: EnvSnapshotRef, trace_only}, replay_mode, intervention_ref?, speculation_policy_ref, budget_id (a `slice`, ADR-0040), permissions (attenuated, ADR-0034), seed, provenance, disposition?}`; `BranchDisposition ∈ {promoted{at_seq}, discarded{reason, restored_to, compensated[], uncompensable[]}, abandoned{reason}, merged{into_run_id, merge_ref}}` (merge semantics are WS-F3's). Every branch has exactly one disposition; open branches at run end are disposed `abandoned{run_finished}`.
2. **Coherent fork points.** `fork(run, at: seq)` is admitted only where every `model_call_id` scope opened at or before `seq` is closed and every `effect_id` scope opened at or before `seq` is terminal, `deferred`, or listed in `detached_effect_ids[]`. Otherwise `ForkPointNotCoherent(seq, open_scopes[])`; with `coerce_to_boundary` the fork moves to the nearest earlier coherent seq and the parent gains a synthesized `lifecycle.turn.finished{stop_reason: forked}`. `coherent_fork_points(run)` is a pure projection over the durable prefix (ADR-0026).
3. **Atomic trace–environment coupling.** A fork with `env_binding = snapshot` requires an `EnvSnapshot` whose `taken_at.seq` equals the fork point; the branch runs on a fresh environment handle restored from it. `EnvSnapshot = {snapshot_id: ContentAddress (tree rule, ADR-0036 N8, for `workspace_tree`; `foreign_digest` claim for other kinds), env_handle, taken_at: EventRef, kind ∈ {workspace_tree, fs_layer, process_image, full_vm}, coverage ⊆ {workspace_files, filesystem, processes, memory, devices}, uncaptured[] ⊇ {network_connections, wall_clock, entropy, external_services, secrets} as applicable, cost, idp}`; it is a content-addressed record referenced by `action.environment.snapshot` and never an event payload. A fork with `env_binding = trace_only` is admitted but its `SpeculationPolicy.allow_classes` is forced to `{read_only}`; sharing a live environment between two branches that may write is a refusal, not a default.
4. **Snapshot / restore semantics.** `snapshot` is idempotent for an unchanged environment (equal covered state ⇒ equal `snapshot_id`), refused while a non-`read_only` effect on that handle is between `committed` and its terminal (`EnvBusy`); `restore` yields a handle whose covered state equals the snapshot and whose identity material outside coverage is fresh (the same snapshot may be restored many times into distinct handles); a GC'd snapshot returns `SnapshotMissing` with a still-verifiable hash (ADR-0026 §6.5). Coverage bounds the `reversible` class: an effect whose target lies outside coverage is treated as `compensable` (ADR-0031 scope rule); `BaselineUnavailable`/`CoverageInsufficient` downgrade, never proceed silently (answers OQ-089's contract half; the per-kind mechanism is WS-B5's).
5. **Rollback is an appended record with a restore.** `rollback(run, to)` appends `lifecycle.run.rolled_back{to_event_id, env_restore_ref, compensated[], uncompensable[], reason}` and `lifecycle.head.moved`, restores the environment from the snapshot at `to`, compensates `compensable` effects applied after `to` in reverse order (ADR-0032), lists every effect it could not undo, and renders a **rewind note** (a typed `Text` leaf, `authority = kernel`) into the model-facing view naming the persisted external effects and the discarded attempt. Discarded events remain readable and hash-chained; they are excluded from `project(context_view)` by HEAD, never deleted.
6. **Source immutability under every operation.** Fork, promote, discard and rollback leave the source prefix's head hash at the fork point unchanged; referenced prefixes and their snapshots are pinned against GC while any branch or bundle references them (ADR-0027 §6 extended to snapshots).
7. **Consumers.** Stream subscribers treat `head.moved` as a rewind (Cursor precedent; WS-K2/K4); the results store keys branch rows by `(configuration_version_id, run_id)` plus `branch_kind`, `fork_point`, `replay_mode` (WS-J5); the bundle (WS-I3) includes referenced `EnvSnapshot`s as members with `coverage` recorded.

**T-LCD statement.** Satisfies T-LCD-06/07 (no native field for hosted participants; `fork` is a declared capability, `n/a` otherwise), T-LCD-10 (snapshot identity is content-addressed; handles are surfaces), T-LCD-12 (operations, out-of-process implementable), T-LCD-15 (branch metrics class-scoped), T-LCD-02 (rewind note is a typed `Text` leaf). Not applicable: T-01/-03/-04/-05/-08/-09/-11/-13/-14 (no model-facing surface or comparison is introduced here; T-14 is handled by the companion ADR on replay validity). **ADR-0024 rung:** `fork/snapshot/restore/rollback` are MUST-code (kernel); `coverage_required` and the rewind-note template are MUST-data.

- **(b) Source-code precedent:** codex S-107 @0735c51 `codex-rs/core/src/thread_manager.rs` L166–197 (`ForkSnapshot{TruncateBeforeNthUserMessage, Interrupted}` — coherent fork points, synthesized interrupt marker), `core/src/thread_rollout_truncation.rs` L34–140 (`ThreadRolledBack` applied at index time), `protocol/src/protocol.rs` L3193–3208 (`WorldStateItem{full, state}`), `rollout/src/recorder.rs` L1216–1277 (retired `ghost_snapshot` items stripped on load); claude-agent-sdk-python S-109 @ad77094 `src/claude_agent_sdk/types.py` L2170–2205 (`resume_session_at` + `resume_drops_turn` validation — fork-point refusal), L2317 (`enable_file_checkpointing`), `client.py` L335–365 (`rewind_files`); opencode S-111 @9f8db11 `packages/opencode/src/snapshot/index.ts` (`track` = `write-tree` into a separate git dir; `restore` = `read-tree` + `checkout-index -a -f`); gemini-cli S-119 @ed2ac40 `packages/core/src/services/gitService.ts` L53–220 and `commands/restore.ts` (shadow-repo commit paired with conversation history; fails closed when the commit is gone); software-agent-sdk S-110 @3fc7b22 `openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py` L776–880 (the shared-workspace counter-example) and `conversation/state.py` L176–334 (HEAD navigation); pi-mono S-113 @400d690 `packages/agent/src/harness/session/fork.ts` (declared fork scope, branch tips); langgraph S-143 @e539ac1 `libs/checkpoint/langgraph/checkpoint/base/__init__.py` L93–147 (snapshot chain with `parent_config`, no environment). The coupled `BranchRecord` (trace position + content-addressed snapshot + coverage + disposition) is partial-precedent (gemini-cli, Shepherd in memory) and `novel` as a ledger contract.
- **(c) Disconfirming evidence considered:** Managed Agents S-047 and Symphony S-108 ship without branching and let the model retry (why it does not overturn: their effects are workspace-local and reprovisionable; the Stage-2 slice is what they already do with git, and R-2.2.4 stays C2/Could beyond it); coupling makes forks as expensive as the environment's slowest rung and most turns produce no recovery-relevant state (S-475) (why not: coverage is declared and bounds `reversible`; snapshots are taken at fork points and effect terminals, not per event; the workspace-tree rung is cheap and is what four harnesses ship); multiple restores duplicate once-only identity material (S-481) (why not: invariant 4 gives every restore fresh identity outside coverage and lists `entropy` as uncaptured); researchers may want mid-scope forks (why not: `coerce_to_boundary` and synthesized terminals reproduce the Codex `Interrupted` behaviour; finer coherent points become available as scopes close).
- **(d) Conditionality:** independent of model tier; assumes an environment handle model (WS-B5) that can produce at least a `workspace_tree` snapshot; the `fs_layer`/`process_image`/`full_vm` rungs assume a sandbox whose isolation primitives expose checkpoint facilities (referenced only by property; ADR-0050 §8(c)); inter-run forks assume the ADR-0027 lineage pinning; hosted participants only where their capability declaration says `fork = supported` and their hosting mechanism can snapshot at declared coverage.
- **(e) Build-stage assignment:** C0 / Stage 2 — `coherent_fork_points`, inter-run `fork` with `snapshot | trace_only`, `EnvSnapshot{workspace_tree}`, `snapshot`/`restore`, `rollback` with restore and rewind note, new event classes; C2 / Stage 4 — intra-run branches under one lease with K concurrent handles and budget slices, promote/discard, layer/VM rungs behind the same contract; C4 / Stage 6 — counterfactual branches consumed by WS-I7.

## Consequences

- WS-B1 adds `lifecycle.branch.opened/disposed`, `action.environment.restored` and an optional `scope.branch_id` (ADR-0026 amendment log; CF-286); the persistence policy table lists them as `ledger`.
- WS-B5 implements `snapshot`/`restore` per environment kind and declares `coverage`/`uncaptured[]` on every record; the per-kind choice for the `reversible` class (OQ-089) is B5's within this contract.
- WS-B3's recovery procedure may call `rollback`; its `recovery_decision` references the `RollbackRecord`.
- WS-D1 excludes discarded subtrees by HEAD and renders the rewind note; WS-G2 reads `uncompensable[]` when reconciling completion claims.
- WS-K2's time-travel viewer is a viewer over `BranchRecord`s and dispositions; WS-J5 rows gain three fields; WS-I3 bundles gain snapshot members.
- The OpenHands-style shared-workspace fork becomes a restricted `trace_only` mode with `read_only` effects only.

## Reversibility

**Medium.** Relaxing coherence (admitting mid-scope forks) is additive once the ledger can synthesize terminals; dropping the snapshot coupling would re-open the SF2/SF3/SF5 class and is not recommended; the branch record fields are additive to ADR-0027's `forked_from`, so removing the intra-run granularity later costs only the `branch.opened/disposed` classes and their projections. Changing snapshot kinds is free because the contract names coverage, not mechanism.
