# ADR-0045 — Scorecard and experimental-design contract: metrics as registry objects with a full `MetricDeclaration`; six explicit factors plus a replicate axis; outcome classes; distributional reporting; class-scoped `n/a{reason}`; minimum design as Stage 3 acceptance criteria

**Status:** **ratified** (Phase 1 synthesis, 2026-09-10)
**Owner workstream(s):** WS-I2 (with WS-J3 enforcement, WS-J4 estimation, WS-J5 storage, WS-B1 event payloads, WS-A2 vocabulary) · **Phase:** 1 · **Related:** ADR-0004 (`MetricDeclaration` novelty item), ADR-0007 (T-LCD-02/-09/-13/-15), ADR-0001/0010 (two classes on one plane), ADR-0002 (evidence standard); ADR-0013/ADR-0014; ADR-0026/ADR-0028; CF-094, -02, -04, -05; OQ-016, OQ-036, OQ-037, OQ-046, OQ-121/-02/-05/-09; R-2.9.2, R-2.10.3/4/5

## Context

Doc 2 §8 fixes the eight scorecard dimensions and demands factorial design, process metrics, distributions not means, and executable oracles; phase-0 §5.5 makes `MetricDeclaration` C0/Stage 1 with `n/a` never 0; T-LCD-09/-15 are binding. Three partial declarations exist on disk (WS-L7 `applies_to`; WS-A1 `requires_observability, applies_to_classes`; WS-A2 `admissible_granularities, detector_classes_allowed`). The source audit (WS-I2 §4) shows every mature plane implements the replicate → task → configuration ladder but only Inspect computes intervals, only τ-bench/Inspect compute pass^k, none pairs by task, none reports interaction effects, and Harbor/DSPy/AgentDojo coerce unmeasured runs to 0 — the T-LCD-15 failure signature in another guise. The field has also documented a live pass@k misuse (n = unit tests instead of independent runs, S-238) and horizon-dependent divergence between capability and reliability (S-236, S-127).

## Options considered

1. **Adopt an existing plane's result model wholesale (Harbor `TrialResult` + `mean`, or HAL's summary).** Rejected: no factor beyond agent × task × attempt, no intervals, unmeasured ⇒ 0, no class scoping (WS-A1 F6; WS-I2 F1/F6).
2. **Scorecard as a fixed eight-column type with one number per dimension.** Rejected: collapses distributions, hides `n/a`, cannot express veto invariants or judged/deterministic provenance; is the "single harness score" T-LCD-09 forbids.
3. **Metrics as first-class registry objects, dimensions as tags, full declaration, six factors + replicate axis, outcome classes, mandatory distributional reporting (chosen).**

## Decision

1. **`MetricDeclaration` (C0/Stage 1) is the single complete form:** `{name, dimension ∈ {capability, reliability, grounding, efficiency, autonomy, security, portability, evolvability, compliance}, level ∈ {run, task, configuration, arm, comparison}, value_type ∈ {bool, decimal, verdict{C,I,P,N}, vector, n/a{reason}}, direction, unit, requires_observability ⊆ {events, model_io, end_state, ledger}, applies_to_classes ⊆ {native, hosted}, admissible_granularities, detector_classes_allowed ⊆ {deterministic, judged}, oracle_classes_allowed, replicate_reducer ∈ {mean, median, max, at_least(n), pass_at(k), pass_k(k), collect}, interval_method ∈ {clt, clustered_clt(task), wilson, bootstrap, bayesian_beta}, outcome_class_policy: map<outcome_class, count_as_failure | exclude | report_beside>, headline: bool, veto: bool, cost_attribution}`. It reconciles and supersedes the three partial forms (CF-094). Adding a metric is a registry entry; adding a dimension is an ADR.
2. **Factors and replication.** Every result row is keyed by `(model_snapshot(s) with roles, harness at a declared granularity, environment image + fault/perturbation profile, task with split label, budget vector, replicate index)`; `replicate` carries seed material (harness RNG, requested sampling seed, image digest) and pairing across arms is by task, by replicate only where all participants declare `seed_honoured` (CF-095). `Design{kind, factors, blocking, replicates_per_cell, pairing, seed_policy, held_out_split_ref, pre_registration}` and `PreRegistration{hypothesis, primary_metrics, equivalence_margin?, min_n, task_split_hash}` are first-class and immutable once the experiment's first run opens.
3. **Outcome classes precede metrics.** `outcome_class ∈ {scored, budget_exhausted, infrastructure_failure, oracle_failure, refused, cancelled}` is derived from ledger facts for every run; each metric's `outcome_class_policy` decides denominators; default for capability = `scored ∪ budget_exhausted`, other classes excluded and counted beside; nothing is coerced to 0.
4. **Distributional reporting is mandatory.** Per configuration and metric the scorecard stores point estimate, interval (named method; clustered-by-task by default for task-level binary metrics), per-task distribution, per-task success counts (c, n) so pass^k (τ-bench estimator C(c,k)/C(n,k)) and pass@k (Chen 2021) are recomputable for all k ≤ n, tail statistics (P95/P99/max; catastrophic-failure rate) and n per cell. pass^k for k > n renders `n/a{estimator_undefined}`; n is always the number of independent runs, never sub-units of one run.
5. **`n/a{reason ∈ {class, observability, estimator_undefined, not_run, no_detector}}`** is a typed value; the report generator enforces it for inadmissible class × metric cells (T-LCD-15) and never substitutes 0 or a configuration-level proxy.
6. **Veto invariants** (`veto: true`; e.g. secret leak, duplicate side effect, authority widening, irreversible effect out of scope) are evaluated on every run with a ledger; a run that trips one is *success-with-veto*, excluded from headline success and counted beside it.
7. **Dynamic opacity** (OQ-036 dynamic half) is computed per model call from `context.assembled` and reported beside WS-A3's static ratio.
8. **Minimum design = Stage 3 acceptance criteria AC-I2-1…12** (WS-I2 §6.6), including the OQ-037 split: T-LCD-09/-14/-15, `n/a` and outcome-class rules are automated gates; T-LCD-03/-13 are executable tests whose margins/judged-kind choices are review items; no I2 obligation is checklist-only.
9. **Scorer boundary (OQ-046):** oracles/judges/loaders are invoked **per run over a boundary** (end-state handle + ledger cursor + artifact refs → typed `MetricValue`s appended as `measurement.metric.emitted`); in-process per-sample calls are an optimization that must yield identical values.

**T-LCD statement.** Satisfies T-LCD-02 (dynamic half; static is WS-A3/A4), T-LCD-09 (factors + interaction analysis executable), T-LCD-13 (compliance stages computable as class-scoped metrics from B1 events; consumes ADR-0014), T-LCD-15 (full declaration; `n/a{reason}`). Does not itself supply deterministic `followed` detectors for every artifact kind (OQ-049, WS-G1/D4) nor the statistical model forms for interaction/surface estimation (WS-J4).

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: reliability is a separate, horizon-dependent dimension and single-run means mislead — S-127 (Tier A: pass^k definition, 61 % → 25 %), S-135 (Tier A: interaction effects at 21,730 rollouts; no intervals reported), S-236 (`provisional`: capability/reliability rank divergence), S-238 (`provisional`: pass@k operationalization error); intervals and pairing — S-234 (Miller 2024, CLT/clustered/paired), S-128 (bootstrap CIs on a fitted horizon); process metrics and failure classes — S-062 (`provisional (mech)`), S-148 (`provisional (mech)`), doc 2 §8 (Tier-B synthesis); budget × harness interaction — S-072 (`provisional`). C0 content rests on the Tier-A definitions, classical statistics, ratified ADR-0004/0007 and source audits; preprints corroborate mechanism only.
- (b) Source-code precedent: `inspect_ai/src/inspect_ai/scorer/_reducer/reducer.py` (`pass_at`, `pass_k` with NaN when epochs < k; `mean/median/max/at_least`), `scorer/_metrics/std.py` (`stderr(cluster=)`, `_clustered_stderr` with finite-cluster correction, `bootstrap_stderr`), `scorer/_metric.py` (`CORRECT/INCORRECT/PARTIAL/NOANSWER`); `tau-bench/tau_bench/run.py` L181–203 (pass^k reference); `harbor/src/harbor/models/trial/result.py` (`TrialResult`, `compute_token_cost_totals`), `harbor/src/harbor/models/job/config.py` (`n_attempts`, `metrics[]`); `hal-harness/hal/utils/error_classifier.py` (`calculate_S_tail`), `hal/utils/fault_injection.py` (`FaultEvent`), `hal/benchmarks/base_benchmark.py` (cost, latency, wall-clock, agent hash); `omnigent/tests/harness_bench/verdict.py` (`NOT_APPLICABLE`/`UNKNOWN`). **Negative precedents rejected:** `harbor/src/harbor/metrics/base.py` (`None ⇒ 0`), `dspy/dspy/evaluate/evaluate.py` (`failure_score = 0.0`), `agentdojo/src/agentdojo/benchmark.py` (provider error ⇒ `utility=False`). The six-factor result model with interaction reporting, outcome classes and the full class-scoped declaration are `novel` as an integrated contract (WS-A1 F6; ADR-0004 novelty items ii).
- (c) Disconfirming evidence considered: (i) cost — HAL ran once per cell for ≈ $40 k; answered by allowing n = 1 cells that render wide/`n/a` rather than omitting, admitting adaptive selection inside search, and the Bayesian reporter (S-239) as an alternative interval method (OQ-129); (ii) pass^k instability at small n (S-239) — answered by storing (c, n) so any estimator is recomputable; (iii) eight dimensions overlap and new ones appear — answered by making dimensions tags on metrics; (iv) seeds are not honoured by providers — answered by the replicate-axis reading (CF-095); (v) hosted participants with `model_io` look handicapped — answered by typed `n/a{reason}` so the handicap is visible and by ADR-0013's class criterion.
- (d) Conditionality: independent of model tier and task class; assumes deterministic oracles exist for the Stage 3 suite (coding/terminal — WS-I4) so headline capability is populated; replicate defaults (OQ-121) are cost-conditional and set per stage; interval methods assume tasks are the sampling unit (super-population framing, S-234) — a fixed-task-set reading reports the same intervals labelled "task-sampling".
- (e) Build-stage assignment: C0 / Stage 1 — `MetricDeclaration`, `Factor/Design/Arm/PreRegistration`, outcome-class derivation, `n/a{reason}` type, metric event payload; C0 / Stage 3 — reporting ladder, pass^k/intervals/tails, veto separation, dynamic opacity, AC-I2-1…12; C1/C2 Stages 3–4 — J3/J4/J5 realisations, judged metrics with WS-G3.

## Consequences

- WS-B1 extends `measurement.metric.emitted` with `oracle_ref`, `detector`, `confidence`, `evidence_ref`, and derives `outcome_class` into the `results_row` projection; `control.budget.consumed` totals feed budget-consumption distributions.
- WS-J3 refuses experiments without a `Design`/`PreRegistration`; WS-J4 implements the interval methods and the interaction analysis; WS-J5 stores per-task (c, n) and distributions, not only means.
- WS-A2 folds the ontology terms (replicate, cell, outcome class, headline/veto metric, `n/a{reason}`) into v1; WS-L7's `applies_to` and WS-A1's partial forms are superseded by the full declaration.
- WS-I5/I7 inherit the outcome-class and veto rules; WS-G3's judges must emit `detector = judged` values under distinct metric names.
- The readiness report's LCD matrix rows T-02/-09/-13/-15 cite AC-I2-1/-3/-4/-7/-8.

## Reversibility

**High for the schema, medium for stored results.** Fields can be added freely; removing outcome classes or `n/a{reason}` would silently re-coerce unmeasured runs to 0 in every stored scorecard and would require re-labelling every published number — which is the cost the decision exists to avoid.
