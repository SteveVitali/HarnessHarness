# ADR-0080 — Memory writes and consolidation: agent-authored memories are immutable versions in a runtime-owned memory store with a `delegate` write ceiling and a `≤ external` label cap (supersedes one row of ADR-0035's persistence-ceiling table); manifests are name-bound records; consolidation is supersession under a writer lease; promotion and retirement are endorsement and supersession

**Status:** **ratified, amended** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-D3 (consumers: WS-D4, WS-H1, WS-H7, WS-L3, WS-D1, WS-B1, WS-B3, WS-I5, WS-F2) · **Phase:** 2 · **Related:** WS-D3 ADR-1/ADR-2; ADR-0035 (ceilings; `promotion` basis; check 6), ADR-0033 (R-TEXT; minting rules), ADR-0034 (P4 persistence; RP), ADR-0037 (I1–I5; S1–S8; `RevocationRecord`), ADR-0026 (writer lease shape; history never rewritten), ADR-0016 (`EffectDomain.memory_write`; `Memory` invariants), ADR-0031 (`memory_write` risk class), ADR-0040 (budget guard), ADR-0002 (iii: no self-widening), ADR-0007 (T-LCD-05/-12/-13); CF-172, OQ-201/-07, OQ-020, OQ-049; R-2.4.3, R-2.4.4, R-2.8.1

## Context

ADR-0035 decision 3 fixes persistence-scope write ceilings as the X-CPE defence: "writing to `scope = user` requires effective authority ≥ `principal` and an `approval`; `project` ≥ `principal`; `session`/`run` ≥ `delegate`; `definition` only via `seal`." A model's proposals have effective authority ≤ `delegate` (ADR-0034 P3), so under the table as written no AgentProcess can persist anything that survives beyond a session at project or user scope. Every production memory pipeline the WS-D3 audit read does exactly that: Codex's background pipeline writes `~/.codex/memories/` (user scope) from rollouts and lets the model append ad-hoc notes; Claude Code's auto memory writes `~/.claude/projects/<project>/memory/` ("notes Claude writes itself"); OpenHands and OpenHarness let the agent maintain `.openhands/memory/MEMORY.md` / `.openharness` memory files; goose's memory extension writes global or local category files. S-103's X-CPE vector is real — session content re-entering at *instruction* privilege — but the mechanism that makes it an escalation is *delivery* (a discovered file rendered into a high role), which ADR-0034's role-placement invariant already closes, not persistence as such. Meanwhile the mutation side of memory is where the non-coding lineage puts an LLM editing records in place (A-MEM, Letta, Mem0) and where Codex puts a locked, watermarked, diff-producing consolidation sub-agent "with no approvals, no network, and local write access only" whose outputs the model may not edit directly.

## Options considered

1. **Keep ADR-0035's table unchanged; agent memory requires an `approval` per write.** *Rejected:* approval fatigue (S-053, ~93 % approved) makes the endorsement worthless while making every audited memory pipeline unusable; the escalation it guards against is already closed at delivery by RP.
2. **Agent memory only at `session`/`run` scope.** *Rejected:* memory that does not survive the run is not memory; Claude Code/Codex per-repository memory has no `session` equivalent; S-103's σ_session is one session.
3. **A new `PersistenceScope` value `memory`.** *Rejected:* scope is *where an item lives* (ADR-0033) and agent memory lives at project or user locations; adding a scope conflates location with store and needs a lattice change everywhere.
4. **A store dimension on persistence: `store ∈ {instructions, memory}` orthogonal to scope, with a memory-store row in the ceiling table: write ceiling `delegate`, label cap `external` (chosen).**
5. For mutation: **LLM edits records in place** (A-MEM/Letta/Mem0). *Rejected* by ADR-0037 I1 and S-106. **Consolidation as a locked Procedure whose only writes are new versions with `supersedes` (chosen).**

## Decision

1. **Persistence has a `store` dimension.** Every `memory_write`/`fs_write` effect to a persistent scope declares `store ∈ {instructions, memory}`: `instructions` covers definition-class files, settings, skill directories and any location the sealed definition or a profile can *discover and deliver as instructions*; `memory` covers the runtime-owned `MemoryStore` (ADR-1) at scopes `project`/`user`/`session`/`run`, whose items reach a model only as `memory`-kind candidates through `retrieve` (ADR-2) and D1 admission.
2. **Superseding row for ADR-0035 decision 3 (memory store only):** `store = memory, scope ∈ {project, user}`: write ceiling **`delegate`**; the persisted label is `⊔(context_label, label(writer))` **capped at `external`** for free text (R-TEXT — unchanged) and at `environment` for closed-schema `StructuredValue`s endorsed by a `kernel` validator; a memory can reach `principal`/`definition` only by `promotion`/`seal`/`pin` (ADR-0035 bases — unchanged). The `instructions` rows keep ADR-0035's ceilings verbatim. Rationale: the cap makes the write unable to raise what the item may command; RP at delivery keeps the item out of every slot with `min_authority > external`; the write remains an effect the monitor sees (grant coverage by `memory_write{scope, store}`, taint gate per Π — OQ-201 asks H1/H7 whether Π exempts memory-store writes because of the cap).
3. **Every memory write is a new immutable version** (`MemoryStore.put → version_id`) with the ADR-0033 record (`origin = model(run_ref, response_id) | evolution | human`, `derived_from`, `scope`, `created_at`), a `supersedes{reason}` edge when it replaces a named entry, and a `context.memory.written` event carrying the memory scope's `lease_generation`. In-place edits do not exist; the model's "remember/forget/correct" requests are ad-hoc notes (new versions) that consolidation applies (Codex `extensions/ad_hoc/notes` precedent).
4. **Manifests are name-bound records** (`MemoryManifest`, ADR-1) rewritten only by `bind` with `supersedes{reason: consolidation}`; a manifest entry's removal never removes the version or its ledger sources (ADR-0037 I2, S8).
5. **Consolidation is a `Procedure`** (`compile_hint = subagent_task` by default) run by an AgentProcess at `delegate` under a `memory_write{scope, store: memory}` grant and a writer lease on the memory scope (one consolidation per scope at a time; `lease_generation` on every `put`; a fenced write is refused — ADR-0026 shape), whose inputs are `stale_candidates`, `memory_usage`, the manifest and the episodic layer via `retrieve(mode = audit)`, and whose outputs are only `put`/`bind`/`revoke`; its watermark (`input_watermark`, `last_success_watermark`) and diff (an artifact by content address) are ledgered. Its cadence and budget guard (session start / idle / rate-limit floor — Codex `guard.rs`) are `HarnessRule`s with assumption-debt records (OQ-205). Cost is charged `subject` under `harness_overhead.consolidation` (CF-174).
6. **Promotion** is `put` of a new version with the raised label plus the `security.label.endorsed{basis: promotion}` event naming the reviewer (`principal`) or `seal` (`definition`); `semantic_id` unchanged, `version_id` changed, `supersedes{reason: edit}`. **Retirement** is `supersedes{reason: expiry}` or a `RevocationRecord`; bytes are GC'd only under WS-B1 §6.5 with a tombstone. **Revocation propagates** through `StaleIndex` (ADR-0037 S4) to every manifest and definition pinning the revoked version.
7. **Extraction** (Codex Phase 1 shape) is the same Procedure class over a *claimed* set of ledger ranges (a per-range lease in the store so concurrent extractors never duplicate), reading the ledger through `project()` with a declared provenance-tier order and `kernel` redaction (ADR-0034 P1 deterministic deriver), writing distilled records with `derived_from` = the ranges and `source_trajectories` = the runs; it never writes to the ledger.

**T-LCD statement.** Satisfies T-LCD-05 (index budgets, consolidation cadence, provenance-tier orders and extraction caps are conditioned rules with debt records), T-LCD-12 (store, extraction and consolidation are operations/Procedures implementable out-of-process), T-LCD-13 (every memory version has an identity so `delivered/activated/followed` are computable), T-LCD-14 (consolidation and extraction cost are budgeted and attributed), T-LCD-10 (promotion changes `version_id`, never `semantic_id`). Not applicable: T-LCD-01/-02/-03/-04/-06/-07/-08/-09/-11/-15.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** agent-maintained memory pipelines in production — Codex (S-107, read in source: leases, watermark, git-baselined directory, consolidation agent "no approvals, no network, local write access only", "Do not edit generated memory files directly; consolidation applies these notes"), Claude Code docs (S-351: "notes Claude writes itself"; "context, not enforced configuration"; delivered as a user message), OpenHands (S-110), OpenHarness (S-117: content-signature dedup under a file lock; stale candidates), goose (S-112); cross-scope persistence as an attack — S-103 X-CPE (`provisional (mech)`, via ADR-0033/0035) with the defence at *delivery* (ADR-0034 RP, ratified); approval fatigue bounds per-write approval — S-053 (Tier B via WS-L3 F7); in-place mutation as the counter-lineage — A-MEM (S-347), Letta (S-352), Mem0 (S-348); mutation-plane placement matters — S-350 (`provisional`); revocation must be a record the guard enforces — S-106/S-077 (`provisional (mech)`), consumed via ratified ADR-0037.
- **(b) Source-code precedent:** `codex/codex-rs/memories/README.md`, `state/memory_migrations/0001_memories.sql` (`jobs{lease_until, ownership_token, retry_at, input_watermark, last_success_watermark}`), `memories/write/src/phase2.rs` L60–80 (global claim before touching the workspace), `memories/write/src/guard.rs` (rate-limit floor as a startup guard), `memories/write/src/rollout_input.rs` L26–35 (provenance tiers; secret redaction), `ext/memories/templates/memories/read_path_v2.md` (ad-hoc notes; no direct edits) @0735c51; `OpenHarness/src/openharness/memory/manager.py` L38–80 (signature dedup under `exclusive_file_lock`), `memory/usage.py` (`find_stale_memory_candidates`), `memory/schema.py` L277–292 (`disabled`, `ttl_days` expiry) @9b2efd7; `claude-agent-sdk-python/src/claude_agent_sdk/types.py` L109–112 (`PermissionUpdateDestination` — the instruction-store write targets ADR-0035's rows keep governing, via WS-L3) @ad77094. **`no-precedent / novel`** for: the `store` dimension on persistence with a label-capped memory row; consolidation constrained to `put/bind/revoke` under a ledgered lease; promotion as a new version plus endorsement event.
- **(c) Disconfirming evidence considered:** loosening any ceiling reopens X-CPE — the memory row lowers *who may write*, not *what the item may command*, and RP is unchanged; "the model should be allowed to edit its memory directly" (Letta/A-MEM) — rejected by ratified I1 and by S-106; per-write approval is the conservative reading of ADR-0035 — rejected as fatigue-bound and as making the rich T-LCD-03 anchor inexpressible; a `store` dimension is one more field on every persistence effect — one enum, defaulting to `instructions`. None overturns; the deviation is proposed as a superseding row for synthesis with WS-L3/H1 (CF-172).
- **(d) Conditionality:** independent of model tier; assumes the `MemoryStore` is runtime-owned (an out-of-process store variant must still enforce the cap — it receives the label from the kernel and cannot raise it, T-LCD-12); assumes H1's Π can key on `store` (OQ-201); the value of consolidation cadence and of distilled vs verbatim memory is model-conditioned and measured.
- **(e) Build-stage assignment:** **C0 / Stage 1** — `put/bind/revoke` with the cap and the `store` field on effects; **C0 / Stage 2** — the ceiling row enforced by H1 check 6, extraction and consolidation Procedures under leases, promotion/retirement events, AC-D3-8; **C1 / Stage 4–5** — cadence/guard rules as variants, subagent-run consolidation with isolation (ADR-0034 P2); **C2** — D4 lifecycle policies (conflict sets, expiry defaults), H2 readers on memory items.

## Consequences

- WS-L3/H1: ADR-0035 decision 3 gains a `store` column and one row; check 6 reads `store`; Π decides the taint gate for memory-store writes (OQ-201).
- WS-D4 owns which memories consolidation retires and how conflicts are represented; it builds on `supersedes{reason ∈ {consolidation, expiry}}` and `RevocationRecord`, never on flags.
- WS-D1 renders agent-authored memories only into slots with `min_authority ≤ external`; the Lab measures the compliance cost (AC-D3-9).
- WS-I5 reads the episodic layer and `derived_from` ranges as evidence for harness edits; candidates it writes are `evolution`-origin memories at `delegate`/`external`, never wider (ADR-0002 iii).
- WS-B1 records `context.memory.written{lease_generation, store, scope, supersedes?}` and the consolidation watermark events.

## Reversibility

**Medium.** Removing the memory row returns to per-write approval with no schema change (memories already written keep their `external` cap). Removing the `store` field after Stage 2 would force every memory write back through the instruction ceilings and break the Codex/Claude-Code-class anchors. The consolidation-as-supersession rule is **low** reversibility because it is ADR-0037 I1 applied to memory and the S-106 regression depends on it.
