# ADR-0107 — Retry and timeout policy: `RetryPolicy` keyed by `(scope_kind, error_class)` over ADR-0031 delivery semantics, shared identity across attempts with a recorded `attempt_delta`, `TimeoutPolicy` per scope kind with typed terminals, and derived scope deadlines

**Status:** **ratified** (Phase 2 synthesis, 2026-09-10)
**Owner workstream(s):** WS-F2 (consumers: WS-B2, WS-B3, WS-C1, WS-C2, WS-D2, WS-E1, WS-E5, WS-H1, WS-H6, WS-H7, WS-F3, WS-I1, WS-L2) · **Phase:** 2 · **Related:** ADR-0027 (`model_call_id`/`tool_call_id` with `attempt_no`), ADR-0030 (terminal set incl. `unknown`; retries share identity), ADR-0031 (risk class × repeat-safety; per-class redispatch; idempotency-key derivation — CF-061/062/063), ADR-0039 (`retries`, `time.working_ms`, `time.wall_ms`, `spend` dimensions; human wait excluded), ADR-0040 (hard ceilings at decision points; reserve-before-spend; grace), ADR-0042 (scope kinds `model_call, tool_attempt, effect, permission, subagent, compaction, validation`; `open scope past deadline`), ADR-0044 (`audit_completeness`), ADR-0020 (profile capability `max_output`, `structured_output`), ADR-0050 §8; CF-061, CF-062, CF-063, CF-226; OQ-098 (answered), OQ-119 (answered), OQ-260/-03; R-2.6.2, R-2.2.2, R-2.8.6

## Context

ADR-0031 fixed per-risk-class delivery semantics and idempotency-key derivation and left "attempt counts, backoff and deadlines" to WS-F2 (CF-061). ADR-0040 requires `reserve` before spend and left reservation sizing open (OQ-098); ADR-0042/0044 defined `open scope past deadline` as an audit condition and left the deadline policy open (OQ-119). The audit found retry implemented in four distinct layers with different error classes, identities and bounds: transport/model-call retry (Codex: request 4 / stream 5 with exponential backoff × jitter, provider `retry_delay` honoured, transport fallback, and an *unbounded* connection-retry feature flag; OpenHands: 5× exponential 8–64 s with temperature raised to 1.0 on an empty response; goose: 3 empty-turn resamples), format retry (SWE-agent `max_requeries = 3`), effect retry (governed by class; Codex re-runs a sandbox-denied command unsandboxed after approval — the CF-062/063 hazard), and task-level retry (goose recipe retry with history reset; SWE-agent `RetryAgent`). Timeouts are per scope kind with typed outcomes (Codex exec 10 s → process-group kill → synthetic exit 124; MCP tool 300 s; stream idle 300 s), and MCP's lifecycle text prescribes "SHOULD time out every request … MAY reset on progress … SHOULD always enforce a maximum timeout, regardless of progress". Temporal's production contract bounds retries by Schedule-To-Close time with unlimited attempts and marks permanent failures non-retryable. ToolMaze (`provisional`) reports agents "trapped in futile trial-and-error loops" under implicit failures; the incident catalogue's largest overrun cluster is retry loops (S-209, `provisional (mech)`).

## Options considered

1. **Model-decided retry with no envelope policy (Managed Agents shape; Codex tool errors fed back for the model to retry).** *Rejected as sole mechanism:* unbounded except by budgets; LoopTrap/ToolMaze show model-decided retry is an attack and futility surface; admitted *inside* the ceilings for `read_only`/`reversible` classes (CF-062).
2. **Single global `max_retries` and `timeout` (browser-use / Claude SDK shape).** *Rejected:* conflates transport, format, effect and permission scopes whose correct terminal outcomes differ (`model.call.failed` vs `action.effect.unknown` vs `security.permission.decided{timed_out}`); cannot express Temporal's non-retryable classes or Codex's per-kind timeouts.
3. **Unlimited attempts bounded only by time (Temporal default).** *Accepted in part:* expressible as `max_attempts = unbounded` under the `time.*`/`spend`/`retries` ceilings; **rejected** as the default because Codex's `UnboundedConnectionRetries` shows escape hatches that bypass every counter but wall time appear even in disciplined codebases (T-LCD-01 applied to control).
4. **Deadlines as manifest constants per scope (OQ-119 option A).** *Rejected:* a constant cannot respect the remaining `time.*` ceiling on the ancestor chain, so a scope could legitimately outlive its run.
5. **`RetryPolicy` × `ErrorClass` × ADR-0031 class with shared identity; `TimeoutPolicy` per scope kind with typed terminals; derived deadlines (chosen).**

## Decision

1. **`RetryPolicy`** = map over `(scope_kind ∈ {model_call, tool_attempt, compaction, validator, subagent, permission}, error_class) → RetrySpec{max_attempts: int | unbounded, backoff{initial_ms, factor, max_ms, jitter ∈ [0,1]}, honour_retry_after: bool, attempt_delta_allowed: [DeltaKind]}`. **`ErrorClass` (closed):** `transport_transient, rate_limited, server_overloaded, stream_idle, auth_expired, context_window_exceeded, invalid_request, content_policy, empty, timeout, executor_lost, sandbox_denied, cancelled`. Kernel constraints that no definition may relax: `context_window_exceeded` is never retried with the same request (handed to WS-D2's trigger); `invalid_request` and `content_policy` are non-retryable (surface, do not retry); `sandbox_denied` is never auto-escalated to a wider sandbox — that is an `authorize` decision of WS-H1/H7, never a retry (CF-062/063); `cancelled` is never retried.
2. **Effect retries consume ADR-0031, never re-decide it.** Redispatch after `unknown` follows the ratified per-class rule (probe first; idempotent classes redispatch with the same key; `irreversible` never redispatched — INV-8); the envelope supplies only attempt counts, delays and deadlines. Task-level retry (reset + re-run under a split budget) is an orchestrator/Lab pattern (WS-F3/I5) under a `MatchSpec`, not an envelope feature.
3. **Shared identity across attempts.** Every retry keeps the scope id (`model_call_id`, `effect_id`) and strictly increments `attempt_no` (ADR-0027; INV-5); the ledger records `control.retry.scheduled{scope_kind, scope_id, attempt_no, error_class, delay_ms, policy_ref, attempt_delta?}` and the span projection (ADR-0042) shows `model_attempt`/`tool_attempt` children. **A retry that changes the request is a recorded `attempt_delta`, never silent:** `DeltaKind ∈ {transport, sampling_temperature, model_fallback(profile_ref)}` (OpenHands' temperature raise; Codex's transport fallback; WS-C2 fallback at C1). Every attempt at every layer posts to the single `retries` counter (ADR-0039) so no layer can loop outside the budget (INV-6); `give_up` writes the scope's terminal with the `error_class` and G-POST-EFFECT decides (`infrastructure_failure{error_class}` for model calls after exhaustion; per-class ADR-0031 for effects).
4. **`TimeoutPolicy`** = map over ADR-0042 scope kinds → `{default_ms, extend_on_progress: bool, hard_max_ms, on_expiry: ScopeTerminal}`, where the terminal is fixed per kind by the kernel: `model_call → model.call.failed{error_class: timeout}`; `tool_attempt/effect → action.effect.unknown{cause: timeout}` for non-`read_only` classes, `observed(not_applied)` for `read_only`, with the executor asked to kill the process group and report `detached_effect_ids[]` (WS-E5); `permission → security.permission.decided{decision: deny, decider: policy, reason: timed_out}` → `action.effect.refused` (WS-H7 AC-H7-06; deadline defaults to `none` in `attended` mode — human wait is excluded from `time.working_ms` — and to the `UnattendedPolicy` resolution otherwise); `subagent → control.subagent.cancelled{reason: deadline}` then the child's own drain; `compaction → context.compaction.completed{status: failed}` → WS-D2 fallback ladder; `validation → verification.validator.verdict{verdict: oracle_failure}`. `extend_on_progress` may extend up to and never beyond `hard_max_ms` (MCP lifecycle rule). `control.timeout.fired{scope_kind, scope_id, deadline, hard_max, terminal_event, action}` is appended alongside the terminal. A fired timeout is a typed terminal for that scope, never an exception.
5. **Derived scope deadlines (answers OQ-119).** `deadline(scope) = min(TimeoutPolicy[kind].hard_max, remaining of every time.* hard ceiling on the ancestor chain)`; an effect's deadline is additionally capped by the remaining `time.working_ms`. INV-1 force-closes any scope at its deadline with the kind's terminal, so WS-H6's `open scope past deadline` / `audit_completeness = false` can only arise through an envelope failure, which is itself an invariant violation. Timeouts are therefore neither manifest constants nor per-scope-kind constants alone. WS-E1 is asked whether `ToolCapability` should declare a `timeout_class`/`expected_duration` so `TimeoutPolicy[tool_attempt]` can be per capability (OQ-260).
6. **Reservation sizing (answers OQ-098).** Sequential execution: `reserve(model_call, min(profile-declared max_output bound, remaining))`. Concurrent children under `pool`: `min(declared bound, learned p95 output for (profile, scope_kind) from this run's own ledger, remaining ÷ active_children)`. Over-consumption beyond a reservation is charged and flagged (ADR-0040 §3), so under-reservation cannot violate conservation — it only risks a later refusal, which is the correct failure. Starvation is reported as `reservation_refusal_rate` per child; WS-F4 may replace the sizing rule with a value-of-compute estimate (C3) without changing the contract. `reserve(tool_attempt, E1 cost_model estimate)` at G-PRE-DISPATCH.
7. **Empty and stalled responses.** `error_class = empty` has its own `RetrySpec` (goose 3, OpenHands with temperature delta); `stream_idle` fires `TimeoutPolicy[model_call]` (Codex 300 s precedent) then the retry ladder. `context_window_exceeded` on a retry counts as a compaction trigger, not a retry.

**T-LCD statement.** T-LCD-01 (no per-model retry branches; profile-conditioned parameters only through `conditioned_rules` with debt records — T-LCD-05); T-LCD-06/-07 (hosted participants: retries/timeouts render `n/a` unless their observability exposes attempts); T-LCD-08 (policy receives the profile's `max_output`/`structured_output` capabilities via the runtime); T-LCD-09/-14 (every parameter a declared factor; Temporal-shape vs bounded-attempt policies compared under `MatchSpec`); T-LCD-10 (attempt identity excludes surface fields); T-LCD-12 (operations over records); T-LCD-13 (a retry is never a hidden re-prompt: `attempt_delta` and `control.retry.scheduled` are ledgered). **ADR-0024 ladder:** shared identity, `ErrorClass` kernel constraints, per-kind terminals, derived deadlines, INV-5/6/8 = Core invariants; `RetrySpec`/`TimeoutPolicy` values = typed parameters.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- (a) Mechanism evidence: retries produce duplicates and idempotence is the application's obligation (S-199 Helland; S-200 Stripe — Tier A/B, via WS-B2); retry loops are the largest overrun cluster (S-209, `provisional (mech)`); non-retryable error classes and time-bounded retry as a mature production contract (S-408 Temporal retry policies; S-201 — Tier B); every request should time out with reset-on-progress and an always-enforced maximum, disconnect = cancel, cancel/complete race tolerated (S-153 MCP lifecycle + cancellation pattern — protocol, Tier A/B); ACP requires every cancelled request answered (S-035); post-dispatch timeouts and delayed visibility are a distinct failure model needing verify-before-retry (S-204, `provisional`, via WS-B2); implicit/permanent tool failures trap agents in trial-and-error loops (S-404 ToolMaze, `provisional`, mechanism only); ratified per-class delivery semantics (ADR-0031). No `provisional` claim is load-bearing — the kernel constraints follow from ADR-0030/0031 and the protocol requirements.
- (b) Source-code precedent (2026-09-10, pinned commits): openai/codex @ `0735c519` `codex-rs/core/src/responses_retry.rs` L17–18, L44–133 (bounded stream/request retries; exponential backoff; `retry_delay` honoured; unbounded connection retries behind a flag — the counter-example), `core/src/util.rs` L86–91 (jitter 0.9–1.1), `model-provider-info/src/lib.rs` L29–31, L416–433 (`DEFAULT_REQUEST_MAX_RETRIES = 4`, `DEFAULT_STREAM_MAX_RETRIES = 5`), `core/src/exec.rs` L61–68, L995–1046 (exec timeout 10 s → process-group kill → synthetic exit 124; TERM → grace → KILL), `codex-mcp/src/rmcp_client.rs` L103 (MCP tool timeout 300 s), `core/src/session/turn.rs` L1536–1545 (`ContextWindowExceeded`/`UsageLimitReached` non-retryable); OpenHands/software-agent-sdk @ `3fc7b221` `openhands-sdk/openhands/sdk/llm/utils/retry_mixin.py` L45–98 (5× exponential 8–64 s; temperature → 1.0 on empty response), `llm/llm.py` L347–356; aaif-goose/goose @ `fae91d01` `crates/goose/src/agents/agent.rs` L90–92, L3437–3454 (`MAX_EMPTY_TURN_RETRIES = 3`), `agents/retry.rs` L17–130 (task-level retry against shell checks — *not* adopted as envelope feature); SWE-agent @ `3ea751c` `sweagent/agent/agents.py` L158, L1107 (`max_requeries = 3`), L307–310 (`RetryAgent` cost split); browser-use @ `50f2055` `browser_use/agent/service.py` L172, L1297–1302 (`max_failures = 5` consecutive, reset on success); inspect_ai @ `75f4891` `src/inspect_ai/util/_limit.py` (time/working limits); MCP @ `aa8ce049` `docs/specification/2025-11-25/basic/lifecycle.mdx` L246–261. **`no-precedent / novel`:** a single `retries` counter shared by every layer (INV-6); `attempt_delta` as a ledgered record; deadlines derived from the ancestor chain's remaining time ceilings; timeouts as kind-fixed typed terminals rather than exceptions.
- (c) Disconfirming evidence considered: (i) Temporal's unlimited-attempts default is a mature contract — expressible here (`unbounded` under time/spend ceilings) but not the default, because Codex's own unbounded-connection flag shows counters get bypassed; (ii) OpenHands/Codex feed tool errors back and let the model retry without a per-error bound, and it works in practice — admitted for `read_only`/`reversible` classes within the `retries` ceiling (CF-062), so the shape survives as a parameter point; (iii) a temperature-raising retry (OpenHands) arguably improves recovery — kept, but as a recorded `attempt_delta` so replay (ADR-0028) and compliance metrics stay honest; (iv) per-capability timeouts (OQ-260) may be needed for long builds/tests — `extend_on_progress` + `hard_max` cover the MCP shape today; E1 decides the declaration. None overturns.
- (d) Conditionality: assumes a provider gateway that classifies errors into `ErrorClass` (WS-C1 `normalizer_ref`) and exposes `retry-after`; assumes executors that can kill a process group and report detached children (WS-E5); assumes attended vs unattended mode is declared (WS-H7) for the `permission` deadline; independent of model tier; hosted participants: `n/a` beyond boundary cancellation.
- (e) Build-stage assignment: **C0 / Stage 0** — transport retry with bounded exponential backoff; tool timeout with kill and synthetic status. **C0 / Stage 1** — `RetryPolicy` × `ErrorClass` × ADR-0031 class; shared identity + `attempt_delta`; `TimeoutPolicy` with `expire` per scope kind; derived deadlines; reservation sizing rule. **C0 / Stage 2** — approval deadlines with WS-H7 attendance modes; compaction/validator scope timeouts. **C0 / Stage 3** — AC-F2-04/06 in the Stage 3 suite; `retry_rate`, `timeout_rate`, `reservation_refusal_rate` metric declarations. **C1 / Stage 4** — `model_fallback` delta via WS-C2; subagent deadlines with WS-F3.

## Consequences

- WS-B2/ADR-0031: unchanged; the envelope supplies counts/delays/deadlines and INV-5 is its only idempotency obligation (CF-228).
- WS-B1/ADR-0026: `control.retry.scheduled` payload extended; `control.timeout.fired` added (CF-223).
- WS-L2/ADR-0040: OQ-098 answered; `retries` is the single shared counter; OQ-262 asks whether `compaction_attempts`/`hook_reentries` are extension counters or `retries{scope_kind}`.
- WS-I1/ADR-0042/0044: OQ-119 answered — `open scope past deadline` is unreachable without an invariant violation.
- WS-H7: `permission` deadline semantics and `timed_out → deny` refusal (AC-H7-06) confirmed; never `unknown`.
- WS-C1/C2: `ErrorClass` is the gateway's normalisation target; `model_fallback` is an `attempt_delta`.
- WS-E1/E5: OQ-260 (per-capability timeout class); kill + `detached_effect_ids[]` contract.

## Reversibility

**Medium.** Parameter shapes are additive (new `ErrorClass` or `DeltaKind` = dialect bump). Reversing shared identity or the single `retries` counter would break ADR-0027/0042 span projection and INV-6; reversing derived deadlines would reopen OQ-119 and make `audit_completeness` a soft property again.
