# ADR-0177 — Injection discipline at the embedding boundary: what a host may supply and the authority each injection carries; host-executed capabilities as out-of-process executor variants under the effect lifecycle; host hooks raise-only; approvals as principal endorsement per `effect_id`; no environment handle, policy, budget widening or credential crosses

**Status:** ratified
**Owner workstream(s):** WS-K4 (consumers WS-E1, WS-E5, WS-L5, WS-H1, WS-H3, WS-H5, WS-H7, WS-D1, WS-B1, WS-B5, WS-K1, WS-K2, WS-J6) · **Phase:** 3 · **Related:** ADR-0176 (the contract), ADR-0016 (`Permission`, `DecisionPoint`), ADR-0019 (closed-world rule), ADR-0023 D5 (out-of-process variants; variant-host boundary), ADR-0024 (MUST-code/data; `authority_cap`; pointer rule), ADR-0025 (`compose` with layers; `Override`), ADR-0030/0031 (write-ahead `committing`; every commit resolves; delivery per class), ADR-0033/0034/0035 (minting rules; `external` for host text; approval endorses one `effect_id`; `delegate` never endorses), ADR-0051…0053 (handles out-of-band; `authorize`; hooks raise-only — CF-121; pre-authorization instead of conferral; unattended mode), ADR-0057/0058 (credential channels), ADR-0087/0088 (capability record; `execution_requirement`; `bind`), ADR-0096/0098 (MCP sole tool channel; `mcpServers[]` admitted via H5), ADR-0097 (elicitation as `message_human`), ADR-0136…0138 (R-NOSIDE; `connection_info`; `derive`); CF-121, CF-372, CF-373; OQ-246, OQ-404, OQ-405; R-2.11.4, R-2.8.1, R-2.5.1

## Context

Every audited embedding surface lets the host inject the things it owns, and every one of them lets those injections carry authority silently: OpenHands executes client-defined tools host-side and "returns an acknowledgment observation immediately" (S-110 `tool/client_tool.py`), so the runtime has no terminal for the effect; Pi's `before_tool` hook may rewrite `args` or `block` (S-113 `hooks.ts`); Cloudflare's `beforeToolCall` may `block | modify | substitute` while insisting "Approved action input cannot be changed by beforeToolCall" (S-557 `think.ts` L596); the Claude SDK's `can_use_tool` may return `PermissionResultAllow{updated_input, updated_permissions}` that persists rules to settings scopes (S-109 `types.py` L238–257) and its hooks arrive unlabelled; OpenHands' `confirmation_policy` can auto-approve. WS-H1 catalogued these as the M-CPE/X-CPE channel (authority inferred from where content sits) and ADR-0053 ruled hooks raise-only (CF-121) and model-origin/adapter-origin conferral inadmissible; ADR-0138 fixed that surfaces receive `connection_info`, never a handle; ADR-0023 D5 fixed that out-of-process variants bind through a variant-host boundary reusing the §6.5 discipline; ADR-0096 fixed MCP as the sole standardized tool-supply channel; ADR-0035 fixed that an approval endorses one `effect_id` and that a `delegate` origin never endorses. What is undecided is the *table*: for each injection point of the embedding contract, what crosses, which provenance label it gets on entry, and which invariant keeps the host from becoming an unmediated authority path.

## Options considered

1. **Trust the host (host = principal for everything it injects).** *Rejected:* the host process is frequently a web server, an IDE plugin or a test runner whose inputs come from files, tool outputs and other users; ADR-0034's minting rules (`principal` only for the run's human principal; `external` for all free text not from kernel/definition/principal) already forbid it; S-103/S-104-class escalations (via WS-H1, `provisional (mech)`) are this failure.
2. **Host-executed tools as fire-and-forget upcalls with an immediate acknowledgment** (OpenHands shape). *Rejected:* leaves no terminal event; contradicts ADR-0030 ("every commit resolves; the model always sees a terminal or an explicit `unknown`") and ADR-0031 delivery classes; makes `duplicate_effect_rate` unmeasurable on the host path.
3. **Host hooks with full powers (allow, rewrite args, substitute results).** *Rejected:* ADR-0053/CF-121 (raise-only) is ratified; argument rewriting after `authorize` is a second proposal without a decision; result substitution is an unlabelled `Observation` above `external`.
4. **Chosen:** an injection table in which every host input is typed by the authority it may carry; host tools are out-of-process executor variants under the full effect lifecycle; hooks are raise-only observers; approvals are principal endorsements per `effect_id`; environment, policy, budget-widening and credentials never cross; every rule is a restatement of a ratified ADR at this boundary.

## Decision

1. **Definitions and overrides.** `open_session.new` carries a `Ref<SealedDefinition>` or a HIR document plus `Override[]` (ADR-0025 Hydra-class grammar); sealing is kernel-side; the host's document is `human(author)` until `seal`; `authority_cap`s of higher-precedence layers bound every override (`AuthorityViolation` names the capping layer, ADR-0024 D6). A host never mints `definition` or `kernel`.
2. **Context and procedures.** `supplies.context[]`, `supplies.procedures[]` and `submit.input` enter as `ContextItem`/`Procedure` records: `principal` only when the host declares `serves_principal_channel` for this run and the item is principal-authored; `import` + `external` for forwarded files/prose; `unverified` for lifted content. Free text is a `Text` leaf (T-LCD-02) rendered only under `role_map(authority)` (ADR-0034 RP); every supplied item yields `context.artefact.delivered` (T-LCD-13).
3. **Host-executed capabilities.** A host may register `ToolCapability` records with `source = native_variant(host_executor)` and `execution_requirement.environment_class = host_process` (a value proposed to WS-E1 — OQ-404) at `open_session`; they are sealed with the definition (closed-world rule; no `inject_tool` after open). At run time each call is an ordinary proposal: `authorize` (ADR-0052) → `action.effect.committing` written durably → upcall `invoke_host_capability(effect_id, attempt_no, idempotency_key, capability_ref, params_canonical, execution_request)` → host executes → `report_host_effect{outcome ∈ {observed{applied | not_applied | partial}, failed{error_class}, unknown}}`. The host executor is an `ExecutorDeclaration` (WS-E5 shape) bound by WS-E1 `bind` with declared `dedup_support`, `interrupt` and `concurrency`; a `compensable` capability requires `dedup_support ≥ executor`. The result's `Observation.authority` is `external` (the kernel cannot observe the host's world) unless OQ-404 admits a sealed closed-schema exception. A host that never reports leaves the effect `unknown` at restore (ADR-0130 R-1 probe/escalate by class); a report after takeover is `Fenced` and discarded; duplicate reports are idempotent. Host tools reachable as MCP servers are supplied as `ExtensionRecord{kind: mcp_server}` refs and admitted only through WS-H5 `resolve → review → seal` (ADR-0098 D4) — one tool channel (ADR-0096).
4. **Hooks.** `notify_hook` fires at hook points mapped onto ADR-0016 `DecisionPoint`s (`before_turn, before_model_call, before_tool, after_tool, before_compaction, before_run_end, on_recovery` — the union of Pi/Claude/Cloudflare placements) with a `HookInvocation{hook_point, run_id, turn_id?, proposal_ref?, inputs_hash}`; the `HookResult` sum is `raise{risk_level, reason} | deny{reason} | annotate{TypedValue} | none`. A hook **never** returns `allow`, never rewrites arguments or results, never injects model-visible content; a hook that wants a different action submits a new proposal (new `effect_id`). Timeouts resolve to `none` and are ledgered (`control.guard.fired{…, timed_out}`); every hook outcome is a `control.guard.fired` event. This is ADR-0053/CF-121 restated for hosts (CF-373).
5. **Approvals.** The host is an approval *channel*: `request_permission` is emitted only for `security.permission.requested{decider: human}` and only to a host that declared `serves_permission_channel`; `respond_permission{selected | cancelled}` records an `approval` endorsement naming `(effect_id, args_canonical_hash)` (ADR-0035 basis 2; ADR-0052 output handling) with options limited to those offered (`OptionNotOffered` otherwise); `cancelled` → `action.effect.refused`. No host may auto-answer; unattended operation is the definition's sealed `policy_rule` pre-authorization (ADR-0053 §6.6) or `mode = unattended` (`ask ⇒ deny`); `allow_pattern`-class options appear only once OQ-246 is answered (OQ-405). An `attach`-mode session cannot answer (`CapabilityNotDeclared`).
6. **Elicitation.** `elicit` is the `message_human` effect of ADR-0097 D3; the answer enters as `principal`-authored content, never as an endorsement.
7. **Environment.** `open_session.environment` is an `EnvironmentRef` (record identity, ADR-0137) or a provider adapter's `connection_info`; the kernel provisions and holds the `EnvHandle`; the contract exposes `connection_info/health/meters` via `describe` and nothing else (R-NOSIDE; ADR-0138 consequences). `derive`, `snapshot`, `set_phase` are kernel/Lab operations reachable only through Group M with `instrument` charging.
8. **Budget.** `open_session.budget` is a `Ref<Budget>` or a `BudgetNode` slice under monotone containment (ADR-0016); overrides may only tighten (ADR-0024 D6); `account` is a view (ADR-0039).
9. **Policy and credentials never cross.** No `set_policy`, `grant`, `deliver_credential`, `set_budget`-widening or `inject_tool` verbs exist (the WS-J6 §6.1 exclusions applied to hosts); Π rows, pre-authorizations and allowlists enter only inside the definition; secret values in any payload are refused (`SecretInPayload`) and ledgered `security.secret.leak_detected`; credentials reach the environment only through WS-H3 channels.
10. **Coordinates.** `set_coordinate(session, coordinate, value)` covers the session-variable parameters WS-C3 names (`model`, `mode`, `thought_level`, profile constraints); a `model` change is `relower` + `model.surface.relowered` (ADR-0019/0098); unknown coordinates are `UnknownCoordinate`, never ignored.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-06 (no native contract changes; the host executor is a variant of an existing class), T-LCD-12 (host executors and hooks are out-of-process by construction), T-LCD-02 (host text as labelled leaves), T-LCD-10 (capabilities referenced by identity; host names are surfaces), T-LCD-13 (supplied items produce `delivered`), T-LCD-07 (host capabilities declared; tri-state kinds never coerced), T-LCD-14 (budget overrides tighten only). Does not address T-LCD-01/-03/-04/-05/-08/-09/-11/-15. **ADR-0024 rung:** the lifecycle gating of host effects, the hook-result sum and the endorsement validation are MUST-code; the injection table's labels and the hook-point list are MUST-data declarations.

## Evidence (doc 3 §3.3 synthesis contract — all five mandatory)

- **(a) Mechanism evidence:** host injections arrive unlabelled and are trusted by placement in every audited SDK (S-109 `types.py` L238–257 `updated_permissions`; S-110 `client_tool.py` acknowledgment-first; S-113 `hooks.ts` `before_tool{args?, block?}`; S-557 `think.ts` `beforeToolCall` `block | modify | substitute`) — the M-CPE/X-CPE channel WS-H1 F1 documents (S-103/S-104 `provisional (mech)`, corroborated by source); the one production system that closes part of it states the rule ("Approved action input cannot be changed", S-557 `think.ts` L596); host-executed effects without a runtime terminal are the `duplicate_effect` hazard ADR-0030/0031 close; stable invocation identity across replay (S-113 `harness/types.ts` L95–112) is the shape `(effect_id, attempt_no, idempotency_key)` provides; policy-first permission handling at a boundary is unanimous in hosting (WS-J6 F4: S-118, S-060, S-137) and ratified (ADR-0098 D3).
- **(b) Source-code precedent:** claude-agent-sdk-python `_internal/query.py` L469–600 (upcall subtypes `can_use_tool`, `hook_callback`, `mcp_message`) and `_internal/sdk_mcp_bridge.py` (host MCP server bridged over the control channel) @ad77094; software-agent-sdk `openhands-sdk/openhands/sdk/tool/client_tool.py` L1–120 (client tools registered via JSON; the negative acknowledgment-first shape) and `conversation/request.py` L100–320 (`ConversationConfig{client_tools, hook_config, plugins, secrets, confirmation_policy, security_analyzer}`) @3fc7b22; pi-mono `packages/agent/src/harness/hooks.ts` L1–120 (`runWithGate`: hooks only after the effect gate — adopted placement) @400d690; cloudflare/agents `packages/think/src/think.ts` L2503–2620, L5531–5640 (`beforeToolCall` decision sum; approved input immutable) @b9142be; codex `codex-rs/core/src/tools/handlers/request_permissions.rs` (via ADR-0051 — `permission_request` answered by policy first). The typed injection table with per-point authority labels and the host executor under the full effect lifecycle are `no-precedent / novel` as an integrated contract.
- **(c) Disconfirming evidence considered:** (i) every audited host allows hooks to allow/rewrite and users expect it — answered: the operating points are reachable through sealed pre-authorization and new proposals (ADR-0053 §6.6); only the *silent* form is lost, and that form is the escalation channel. (ii) Requiring `committing` before the upcall and a terminal report adds a round trip and a host obligation OpenHands avoids — answered: `read_only` effects skip the write-ahead barrier (ADR-0031) and the obligation is one message; the alternative is an unmeasurable host path. (iii) Labelling host context `external` will place it in low-privilege roles and may reduce compliance — answered: a host that *is* the principal channel declares it and its principal-authored items are `principal`; everything else being `external` is ADR-0034's rule, and compliance is measured (T-LCD-13), not assumed. None overturns.
- **(d) Conditionality:** independent of model tier and task class; assumes WS-E1 admits `environment_class = host_process` (OQ-404) and WS-E5's `ExecutorDeclaration` shape; assumes OQ-246 unanswered (no `allow_pattern` options); hook points assume ADR-0016's `DecisionPoint` set — a new decision point is a HIR dialect matter, not a contract change.
- **(e) Build-stage assignment:** **C0 / Stage 1** decisions 1, 2, 5 (attended `respond_permission`), 7, 8, 9 (schema-level refusals; AC-K4-4). **C0 / Stage 2** decision 3 (host executor over the variant-host boundary; AC-K4-5), decision 4 (hooks raise-only), decision 6. **C1 / Stage 4** decision 10 (`set_coordinate` with `relower`); `allow_pattern` options when OQ-246 lands.

## Consequences

- WS-E1 adds `host_process` to `execution_requirement.environment_class` (or rules on OQ-404); WS-E5 accepts a host executor as an `ExecutorDeclaration` with `(effect_id, attempt_no, idempotency_key)`; WS-L5's variant-host boundary is the transport for it.
- WS-H1/H7: `respond_permission` is the only host-side path to an `approval` endorsement; adapter/host auto-approval fails admission statically (as ADR-0098 AC-E4-7 for adapters); WS-H7 owns the option set and OQ-246.
- WS-D1 labels host-supplied items per decision 2 and emits `delivered`; WS-B1 ledgers `control.guard.fired` for every hook outcome and the host-effect chain with `executor_class = host_process`.
- WS-K1/K2: the CLI and web launcher may offer "auto-approve X" only by sealing a pre-authorization into the definition they open — a visible, diffable, ablatable edit (ADR-0024 ladder), never a runtime switch.
- WS-J6: the same table governs what a hosting adapter may supply to a *native* run it observes via `attach` (nothing but reads).

## Reversibility

**Low** for decisions 4, 5 and 9 (they restate ratified ADR-0035/0053/0138; reversing them reopens the escalation channel and needs superseding ADRs). **Medium** for decision 3's lifecycle placement (moving the upcall before `committing` for `read_only` classes is already allowed; admitting acknowledgment-first for any other class would contradict ADR-0030). **High** for the hook-point list and the coordinate set (MUST-data).
