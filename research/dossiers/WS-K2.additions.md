## Ontology terms

| term | definition | notes |
|---|---|---|
| surface session | An authenticated browser/shell session with a local surface process, identified by a per-launch capability token and a session id; the `responder_provenance{surface_session_ref}` on decisions and the `provenance` of surface-initiated writes cite it. | WS-K2; H7 stamps it |
| surface verb group | The generated set of boundary operations a surface needs beyond the §6.5 hot-path verbs: reads/projections/subscriptions, branch operations, `respond`, audit proofs, Lab operations. | CF-359; owner WS-K4 |
| capability token (surface) | Per-launch random secret (≥ 128 bits) minted by the launcher and required on every request to the surface process, including loopback; delivered out of band; never in URLs or logs. | ADR-0172 P2/P9; precedent Jupyter, MCP Inspector 0.14.1, Codex `--ws-auth` |
| viewer session | The surface's client-side read model `{run_id, head, cursor, until_seq, filters, open_scopes[], pending_ephemeral[]}` — a cache that must be rebuildable to an identical rendering from `read`/`project`; never a store. | AC-K2-1 |
| scrub vs fork | *Scrub*: `project(run, view, until_seq)` — pure, nothing runs. *Fork*: an ADR-0133 operation creating a branch under a budget slice with human provenance. The viewer never conflates them. | ADR-0171 decision 1 |
| durable frame / transient frame | Subscription frames carrying a `seq` (ledger-durable, replayable from an inclusive cursor) vs frames without one (ephemeral: deltas, `requested{rendering}`); the surface persists only durable state and dedupes on reconnect by `seq`. | precedent S-110 `session_socket.py`; ADR-0026 `durability` |
| rewind (rendering obligation) | On `lifecycle.head.moved`, `lifecycle.run.rolled_back` or `lifecycle.branch.disposed{discarded}` a subscriber switches its rendered path to the new HEAD without removing the discarded subtree, and shows the rewind note at the next assembled context. | ADR-0027/0133; S-052 |
| replay-mode badge | Mandatory rendering of `replay_mode` and `ReplayValidityReport.mode` with `reasons[]` on every branch and branch-derived row. | ADR-0135; `no-precedent` as a UI element |
| rendering invariant (R-D) | Acceptance-tested rules R-D-1…8 that a dashboard cannot undo a ratified data invariant (`n/a` typed; factor coordinates visible; rank sets; report citations; labels; frontier bands; class badges; export loss reports). | WS-K2 §6.3; T-LCD-09/-15 |
| local web surface posture (P1–P13) | The floor of rules a HarnessHarness local surface must meet (loopback, token always, Host/Origin, fetch-metadata, no advertisement, hardening, sink policy, no URL tokens, no far-side decisions, shell pinning/SSH, ledgered writes, same-origin UI). | ADR-0172 |
| one record, two surfaces | The rule that CLI and web render the same records through the same operations; no record type exists for one surface only. | AC-K2-14; joint K1/K2 |
