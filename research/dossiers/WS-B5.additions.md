## Ontology terms

| term | definition | notes |
|---|---|---|
| environment handle (`EnvHandle`) | The kernel-owned runtime record for one execution-environment *instance*: allocated `env_handle_id`, owner run, `environment_ref`, class, lifecycle state, health, helper session, tri-state capabilities, containment slot, credential bindings (placeholders), roots, limits, meters, snapshots, parent link, `on_loss`. Never an IR entity; never the harness process. | WS-B5; distinct from *environment boundary* (Ontology v1 §2b) and from *environment (E)* |
| environment class | Closed sum `{local_host, local_sandboxed, local_container, remote_ephemeral, remote_persistent, provider_hosted}` naming where the instance runs and which backend placement the driver uses. | WS-B5 |
| environment record (`EnvironmentRecord`) | The versioned, content-addressed *definition* of an environment (image digest or `foreign_digest`, build context, platform, provisioning recipe, containment policy ref, limits, nondeterminism declarations, expected capabilities). Its `semantic_id` is the environment factor coordinate (`environment_ref`); its `version_id` is pinned in the run manifest. | WS-B5 / WS-L4 / WS-I3 |
| `env_handle_id` | Allocated, time-ordered, opaque id minted at `provision`; identifies one instance; on every effect event; never a factor coordinate. | ADR-0027 class; WS-A3 list amendment |
| handle state | `declared / provisioning / ready / detached / suspended / unreachable / replaced / failed / torn_down`. | WS-B5-adr-1 |
| harness-outside / harness-inside placement | Whether the harness process (kernel) runs outside the execution environment and reaches it through a handle, or inside it with a thin client outside. Native = outside; inside only as hosted `container-installed`. | WS-B5; S-047 vs S-110 |
| sandbox driver / provider adapter | The kernel-side component speaking the environment protocol (driver) and the backend implementation of that protocol over a platform API (adapter). The *sandbox helper* (WS-E5) is the out-of-process binary the driver speaks to for local and container placements. | WS-B5 / WS-E5 |
| reattach window (`reattach_window_ms`) | Declared capability: how long after session loss a `hello(resume_session_id)` can recover the same instance without loss. | Codex 30 s retention precedent |
| self-heal (replace-not-repair) | The `heal` procedure: reattach → resume → replace from snapshot or image per `on_loss`; a replacement is a new instance under the same record, with in-flight effects `unknown` and a discontinuity record. | WS-B5 / WS-B3 |
| world-state discontinuity | Ledger record `action.world_state.discontinuity{from, to, restored_from, lost_range, continuity ∈ {byte_identical, restored_from_snapshot, fresh}}` appended on replacement; evidence for WS-G2; annotation for WS-J5. | WS-B5 |
| snapshot record / `SnapshotRef` | Content-addressed record of an environment *state* (`kind`, `base`, content address or `foreign_digest`, roots, quiesced, taker, expiry). | WS-B5-adr-2 |
| snapshot kind | Closed sum `{path_baseline, fs_tree, fs_layer, memory, shell_state}`; only `fs_tree` is instrument-addressable; `shell_state` is never identity. | WS-B5-adr-2 |
| quiesced | Precondition for `memory`/`fs_layer` snapshots: no running exec and no detached children on the handle (Modal rule). | WS-B5 / WS-E5 |
| derive (+ modes) | `derive(parent, mode ∈ {fresh_from_image, fork_snapshot, share, scoped_subtree})`: the single isolation primitive behind subagents, verifiers, replicates and branches, with invariants D1–D6. | WS-B5-adr-3 / WS-F3 |
| `on_parent_end` | `{teardown, detach_to_child}` — whether a derived child is torn down with its parent or ownership transfers to the child run. | Cursor "subagent may outlive its parent" |
| environment capability declaration (`EnvCapabilityDeclaration`) | Tri-state record of what a backend supports: snapshot kinds, suspend kind, restore_in_place, fork, detached survival, reattach window, meters (with provenance), isolation class, output overflow behaviour. Undeclared = `unknown`. | T-LCD-07; Harbor/Codex precedents |
| effect-operation surface / R-NOSIDE / R-NONET | The closed, effect-domain-tagged set of handle operations; the rule that only the kernel dispatcher can invoke effectful members; the rule that the handle has no network operation. | WS-B5-adr-3 |
| `env.reserved_ms` / `env.active_ms` / `env.suspended_ms` | Kernel-clock counters: instance provisioned; instance `ready` with a live session; instance `suspended`. `reserved ≥ active + suspended`. | WS-B5 / WS-L2 (OQ-095) |
| connection info | Read-only handle field `{shell_command | ports[] | live_url | none}` for surfaces and human hand-off; never a credential. | Inspect `SandboxConnection`; browser-use `live_url` |
