## 1. Scope & boundary

This workstream decides **what a resource is inside HarnessHarness, how every unit of it is measured and charged, how budgets over it are allocated, reserved, consumed, inherited and exhausted, and what "matched budget" means for the Harness Lab.** Concretely it fixes: (i) the **resource taxonomy** — the closed catalogue of resource dimensions with units, measurement points and producer components; (ii) the **accounting contract** — where raw usage is recorded (on the producing ledger event), how charges are posted against budget nodes, how spend is *derived* from usage with provenance and confidence (answering OQ-033), and the subject-vs-instrument ledger split (answering OQ-059 / OQ-053); (iii) the **budget contract** — allocation, reservation, consumption, inheritance across delegation, soft (advisory) vs hard (enforced) semantics, and exhaustion behaviour; (iv) the **matched-budget comparison definitions** the experiment engine enforces (T-LCD-14) and the capability-cost Pareto framing the comparison engine reports; (v) how the control envelope (WS-F2), router (WS-C2), cache (WS-C4), value-of-compute scheduler (WS-F4), experiment engine (WS-J3), scorecard (WS-I2) and approval policy (WS-H7) consume the model.

It explicitly leaves to neighbours: the typed `Budget` entity's place in the HIR and the monotone-containment validation rule (**WS-A3** — this dossier supplies the dimension catalogue and the runtime semantics; A3 arbitrates the kernel field list, CF-067); the event envelope, ID model and the `control.budget.*` / `measurement.cost.attributed` event classes' *envelope* (**WS-B1** — this dossier fixes their payloads and adds two classes by convention, CF-068); the `cost` field on effect records (**WS-B2**, CF-069); retry/timeout/stop *policy* (**WS-F2** — it enforces the hard budget this dossier defines); routing decisions (**WS-C2**), cache implementation (**WS-C4**), marginal-value estimation (**WS-F4**), factorial design and arm semantics (**WS-J3**), metric declarations and scorecard rendering (**WS-I2/WS-J4**), pricing-table packaging in the bundle (**WS-I3/WS-L4**), approval UX (**WS-H7**), sandbox lifecycle (**WS-B5**), and every language/runtime/storage choice (**WS-L1**). Nothing here names a language, runtime, package ecosystem or framework; every precedent path is cited as evidence, not as a dependency (T-LCD-12).

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — "Tokens" is not one number: every audited system splits input into at least three roles, and providers disagree on whether the cached roles are inside or outside `input`.** Codex `TokenUsage{input, cached_input, cache_write_input, output, reasoning_output, total}` computes `non_cached_input = input − cached_input` — its `input_tokens` is *inclusive* of cached tokens (the OpenAI dialect), which is why it subtracts; Inspect `ModelUsage.input_tokens` is documented as "charged at full rate (excludes cached tokens)" and the true total is `input + cache_read + cache_write`; HAL's `_normalize_usage` special-cases three dialects (`prompt_tokens` inclusive; `input_tokens` exclusive; Bedrock names); OpenHands' `cache_hit_rate` chooses its denominator by inspecting which convention the numbers imply; opencode's overflow test sums all four roles "or total". The vendor docs confirm the split: Anthropic's `input_tokens` is "tokens after the last cache breakpoint", OpenAI's `cached_tokens` is a subset of the prompt count (S-213/09). **Implication:** the taxonomy must define a *canonical exclusive* decomposition (`input.uncached`, `input.cache_read`, `input.cache_write[ttl]`, `output.visible`, `output.reasoning`) with `input.total` and `output.total` *derived*, and every model adapter (WS-C1) must lower provider usage into it with a declared mapping — otherwise cache-hit metrics and matched-token comparisons silently compare different quantities.

**F2 — Cache economics change both the price and the meaning of a token, and the cache is stateful across runs.** Cache reads are billed at 0.1× (or 0.025×) and writes at 1.25×/2× depending on TTL, so `blended_total = non_cached_input + output` (Codex) or a *metering formula* over roles (Inspect `TokenLimit.type` accepts `"(input * 0.1) + output"`) is what a budget actually meters. Inspect prices cache writes by TTL at computation time (`CACHE_WRITE_1H_MULTIPLIER = 2.0/1.25`, `model/_model.py` L3027) and its model-data comment warns not to "pre-bake a longer-TTL rate … or it will be double-applied"; opencode tiers prices by context size. Because the TTL clock runs from request *start* (S-213) and a cache prefix survives across runs sharing a prefix, **cache warmth is an experimental confound**: two arms with byte-identical prompts pay different spend depending on which ran first. Anthropic's task-budget doc adds a second confound: mutating a budget value in the prompt invalidates the cache prefix. **Implication:** cache role counts must be first-class, spend derivation must be pinned to a versioned pricing table *and* TTL, and the experiment engine must either control cache state or record it (OQ-097).

**F3 — Advisory and enforced budgets are different mechanisms and both exist in production; the advisory one is a model-facing artifact whose compliance is measurable.** Claude SDK exposes `task_budget{total}` ("the model is made aware of its remaining token budget so it can pace") next to `max_budget_usd` ("the query will stop … `error_max_budget_usd`"). Codex delivers `<rollout_budget>You have N weighted tokens left…</rollout_budget>` developer messages at configured remaining-token thresholds *per thread and per context window* (`rollout_budget.rs pending_reminder/mark_reminder_delivered`, re-armed after compaction) and separately raises `SessionBudgetExceeded` when the weighted total crosses the limit (`session/rollout_budget.rs`); its per-model `ModelTokenBudgetConfig{reminder_threshold_tokens, reminder_message_template}` is a *profile-conditioned* reminder. Anthropic's server-side countdown is "advisory, not enforced … Claude may occasionally exceed the budget", and "a budget that is too small … can cause refusal-like behavior" (S-214). Agent Contracts names the same pair: "soft enforcement through budget-aware prompts … and hard enforcement via structural monitoring" (S-208, `provisional`). **Implication:** the soft budget is a `HarnessRule` action (`insert ContextItem`) whose delivered artifact gets `measurement.artifact.delivered/activated/followed` events (T-LCD-13) — *budget compliance* becomes a class-scoped metric — while the hard budget lives in the control envelope (WS-F2) as a deterministic invariant (doc 2 §4 design principle). The two must never be conflated in the schema.

**F4 — Hierarchical budgets are implemented as trees with ancestor propagation, and the check order matters for termination.** Inspect's `_Tree` keeps one leaf per execution context per dimension; `record()` adds to the node and recursively to its parent; `check()` calls the parent first "so that if multiple limits are simultaneously exceeded, the outermost (closest to root) one raises the error, preventing certain sub-agent architectures from ending up in an infinite loop" (`_limit.py` L1085–1093, repeated for cost/turn/working). Codex instead keeps **one shared pool** for "one root-thread session tree" (`RolloutBudget` doc comment) and a per-session fan-out cap (`AgentExecutionLimiter{max_threads}`). Agent Contracts states the conservation invariant Σ_j c_j(r) ≤ B(r) for every dimension and terminates the contract on the first violated dimension (`ACTIVE → VIOLATED: ∃r_i: c_i ≥ b_i`). The incident catalogue (S-209) reports the failure when this is absent: the **delegation-fanout race** — "multiple sub-agents receive references to the same budget object" — appears in 11 of 63 incidents and "overshoots 30/30" under cooperative concurrency without reservation. **Implication:** two delegation modes exist (exclusive *slice* vs *shared pool*) and both are legitimate; what must hold in either is (a) a single accounting authority per root run, (b) reservation before spend so concurrent children cannot jointly overshoot, (c) child budgets bounded by the parent's *remaining*, and (d) root-first exhaustion checks.

**F5 — Reserve-before-spend is already practised at the request level and is the only known cure for concurrent overshoot.** Codex's guardian `input_budget.rs` estimates the request's token cost, *reserves* the serialized cost of reminders "before choosing optional evidence", then `enforce_budget` drops optional items or fails with `ContextWindowExceeded`; Inspect's `LimitExceededError` docstring notes a check "may be raised when `value >= limit` to prevent another operation which is guaranteed to exceed the limit from being wastefully performed". The catalogue's three principles — "reserve-before-spend", "single accounting authority (no double-spend)", "affine capability handling (budget values must not be aliased, reused post-delegation, or dropped)" — are the distributed-systems translation (S-209). **Implication (§6.3):** the budget contract has a `reserve → charge/release` cycle keyed by the effect/model-call id, with reservations bounded by the model call's declared `max_output` and the executor's declared cost model (WS-E1 `cost_model`).

**F6 — Wall-clock, working time and environment minutes are three different clocks.** Inspect defines *working time* as wall time minus time spent waiting on rate limits/semaphores (`_util/working.py sample_working_time`; `report_sample_waiting_time` propagates to the working-limit tree), so a throttled provider does not exhaust a working budget. Codex records `duration_ms` and `duration_api_ms` separately in the SDK result (S-109); Cursor hibernates VMs between messages and checkpoints/forks images (S-052), so an environment handle has *reserved*, *active* and *hibernated* time. Harbor records `environment_setup`, `agent_setup`, `agent_execution`, `verifier` timings separately (`trial/result.py`). **Implication:** the taxonomy has `time.wall`, `time.working` (= wall − waiting), `time.model_latency`, `time.human_wait`, and `env.active_minutes` vs `env.reserved_minutes`; matched wall-clock comparisons that ignore waiting time confound provider throttling with harness efficiency.

**F7 — Money is a *derived* resource with provenance, and only one audited harness records that provenance per row.** goose's `usage_ledger` stores `cost` with `cost_source ∈ {provider_reported, estimated}` and `is_compaction`; opencode overrides table-priced cost with a provider-reported unit when present; Claude SDK returns `costUSD` computed by the CLI with `canonicalModel` and `provider` (the serving route changes price); Codex reports `estimated_usage_credits_micros` and optional `estimated_usage_usd_micros`; HAL and Harbor reconstruct or estimate cost after the fact with no flag. Harbor's Claude Code adapter shows all three hosting mechanisms' provenance at once: parse the participant's `total_cost_usd` (reported) → else estimate from steps (reconstructed+priced) → native agents priced from measured usage. **Implication (OQ-033):** spend carries `{provenance ∈ {measured, reported, reconstructed}, derivation ∈ {provider_priced, table_priced{table_ref, version, ttl}}, confidence}` and the comparison engine stratifies on it (§6.4).

**F8 — Fan-out is the dominant cost multiplier and is being budgeted by *instruction*, not by contract.** Anthropic reports 4×/15× token multipliers and gives the orchestrator prose "effort scaling rules" (S-036); Codex caps threads; Symphony caps `max_concurrent_agents` and aggregates `codex_totals` across workers. None passes a typed budget with the delegation except Claude's `task_budget` (per request) and prime-agent's goal `token_budget` (a skill argument, unenforced). **Implication:** `delegated-to` edges carry `Ref<Budget>` (WS-A3 already requires `≤ parent`) and the runtime *enforces* it at the child's root node; `fan_out` (concurrent children) and `delegation_depth` are *levels* with caps, `spawns` is a flow.

**F9 — Evaluation itself is a budgeted resource with two ledgers.** HAL stops trace logging before running the judge "to avoid lm as judge to produce additional cost"; Inspect offers `suspend_token_limit()` for "one-shot summarization, routing, or auxiliary planning calls" whose usage "should not count against an agent's budget"; Task-CoEvolve treats validation evaluations as the scarce quantity (S-082). **Implication:** every charge names a ledger `charged_to ∈ {subject, instrument}`; nothing is ever *unaccounted* (Inspect's suspension removes usage from the budget *and* from the record, which the Lab cannot accept), only *re-attributed* (§6.2). This answers OQ-059 / OQ-053.

**F10 — Context occupancy is a level, not a flow, and it drives a different control action.** Codex `percent_of_context_window_remaining` subtracts a 12k-token baseline; opencode `isOverflow` compares occupancy to `usable = input_limit − reserved`; ACP `UsageUpdate{used, size}` exposes only occupancy; OpenHands `TokenUsage.context_window` is combined by `max`, not `+`. **Implication:** the taxonomy distinguishes *counters* (monotone, summable across children) from *gauges* (instantaneous, cap-bounded, aggregated by max), and the compaction trigger (WS-D2) consumes a gauge while the budget consumes counters.

**F11 — Scheduling and budgeting are separable concerns; the "harness as scheduler" claim is about allocation policy, not a kernel.** AIOS schedules syscalls for throughput and GPU fit (2.1× on one GPU with RR time slices) and treats cost only as a routing input via live prices (`routing.py get_cost_per_token`); BAMAS treats budget as an optimisation constraint over model selection and topology. **Implication:** the C0 model provides the *accounting and enforcement substrate*; allocation policy (who gets the next unit — F4's value-of-compute, C2's routing) is a consumer, staged later.

## 5. Disconfirming evidence & negative results

**Against a rich closed taxonomy (R1).** Autogen ships with two token fields and a termination condition; langgraph with a recursion limit; both are widely used. A 20-dimension catalogue is cost without evidence of benefit. *Why it does not overturn:* the incident catalogue's largest clusters are precisely "cost-observability" (22) and "budget-primitive-missing" (12) — frameworks that count little overrun most; and the Lab's efficiency scorecard (doc 2 §8) needs the roles to compute cache hit rate and $/success at all. The mitigation is *tiering*: the C0 kernel dimensions are the nine WS-A3 already lists (refined in §6.1), everything else is a registered extension dimension that a component may emit and a budget may bound, without a dialect bump.

**Against hard enforcement of token budgets (R2).** Anthropic documents that a visibly insufficient budget makes the model "decline to attempt the task at all, scope it down aggressively, or stop early"; HAL finds more reasoning effort often *hurts*; Codex chose reminders plus a session-level cap rather than per-call caps. A hard cap that fires mid-action is the "premature stopping" failure of plane 3. *Why it does not overturn:* the recommendation separates the two (F3): soft budgets are model-facing artifacts with measured compliance; hard budgets fire only at effect boundaries (§6.3 exhaustion rule) and produce a typed `control.decision{stop, reason: budget_exhausted}` rather than an exception mid-effect. The refusal risk becomes a *measurable* compliance/validity effect (T-LCD-13), which is what the instrument is for.

**Against cross-model matched *token* budgets (R3).** Tokens are tokenizer- and model-specific; a Codex "weighted token" and an Anthropic "task-budget token" (novel tokens seen) are different units even on the same model; provider-priced credits are opaque (`codex_rollout_budget_units`). Matching on tokens across models is therefore not well-defined. *Accepted:* matching dimensions must be declared per experiment; cross-model arms match on `spend` (with a pinned pricing table) or on `wall/working time`, and token matching is admitted only within one model snapshot. The engine refuses undeclared or ill-typed matches (§6.5).

**Against spend as a primary axis (R4).** Prices change, differ by serving route (`provider` in Claude SDK; tiers in opencode; TTL in Inspect), and provider-reported costs are not auditable; Rethinking (S-083) matches *feedback and inference* budgets, not dollars. *Why it does not overturn:* spend is derived, never raw; the pricing table is a versioned bundle artifact (WS-I3/L4) so a comparison is reproducible *at that table*; provenance/confidence stratification keeps reported and estimated rows from being averaged into one point (§6.4). The Lab reports *both* raw-resource and spend frontiers.

**Against reservation (R5).** Over-reservation (reserving `max_output` per call) starves sibling subagents and lowers utilisation; no audited harness reserves per model call; reservation adds a ledger write per call. *Why it does not overturn:* the delegation-fanout race is documented 11 times with real losses and "overshoots 30/30" without reservation (S-209, mechanism); reservation is required only where children run *concurrently under a shared pool*; sequential children and exclusive slices need only the containment check; reservation sizing is an open question (OQ-098) and a C1 refinement, but the *contract* must admit it from C0 or it cannot be added later without changing the event schema.

**Against subject/instrument ledger separation (R6).** It doubles attribution decisions and invites gaming (declare expensive verification "instrument" to look cheap). *Why it does not overturn:* the alternative — Inspect's suspension — makes the cost *disappear*, which is worse for a research instrument; the rule is mechanical (§6.2): a validator/judge invoked by the *harness definition's own loop* is subject cost; one invoked by the *experiment's grader* is instrument cost; both are always recorded and the split is a reported field, so gaming is visible.

**Against making budget compliance a metric (R7).** Compliance with a countdown is a narrow, model-conditioned behaviour; Anthropic's countdown is invisible to the client so `followed` cannot be computed for hosted rows. *Accepted:* the metric is class-scoped (T-LCD-15): `requires_observability ⊇ {events}` for delivered/activated and `model_io` for followed; hosted rows render `n/a`.

**Negative results.** (N1) No audited system exposes *human approvals* as a budgeted resource beyond counting prompts; the ~93 % approval rate (S-053) is telemetry, not a budget — `approvals` as a dimension is `no-precedent` as a budget and precedented only as a count. (N2) No audited system charges environment minutes to a budget; all treat sandbox time as infrastructure. (N3) OTel GenAI has no cost attribute — spend cannot be exported losslessly to it (declared loss, T-LCD-11 pattern). (N4) `max_budget_per_task` in OpenHands is stored but no enforcement site was found in the SDK at the pinned commit — a "budget primitive present but inert" instance of the catalogue's cluster 5.

## 6. Recommendation for the spec

### 6.1 Resource taxonomy (C0 kernel dimensions + registered extensions)

**Two kinds.** A **counter** (flow) is monotone, summable across children and time, and bounded by a *ceiling*. A **gauge** (level) is instantaneous, aggregated by `max`, and bounded by a *cap*. Budgets bound counters; caps bound gauges; the ledger records both.

**Units and encoding.** Integers for counts; scaled integers for money (`micro` of a declared currency) and time (`ms`); decimal strings where a ratio must be stored — consistent with the WS-B1/A3 canonical-number rule. Every quantity is `ResourceQuantity{dimension: DimensionId, amount: int | decimal-string, unit, model_ref?, measured_at: EventRef}`.

**Kernel dimensions (HIR/1, closed; refines WS-A3 entity 12 — CF-067).** *Counters:* `tokens.input.uncached`, `tokens.input.cache_read`, `tokens.input.cache_write` (sub-keyed by `ttl_class`), `tokens.output.visible`, `tokens.output.reasoning` (derived totals: `tokens.input.total`, `tokens.output.total`, `tokens.blended` = a metering formula), `model_calls`, `tool_calls`, `turns`, `retries`, `spawns`, `approvals.requested`, `approvals.granted`, `evaluator_calls` (validator invocations; judge model calls also appear under `tokens.*` with `charged_to = instrument`), `network.calls` (+ optional `network.bytes_egress`), `time.wall_ms`, `time.working_ms` (= wall − waiting, F6), `time.model_latency_ms`, `time.human_wait_ms`, `env.active_ms`, `env.reserved_ms`, `spend` (derived; §6.2). *Gauges:* `context.occupancy` (tokens in the model's window, with the profile's declared window as cap), `fan_out` (concurrent live child processes), `delegation_depth`. WS-A3's nine names map onto these (`tokens_in` → `tokens.input.total`, `tokens_out` → `tokens.output.total`, `wall_clock` → `time.wall_ms`, `env_minutes` → `env.active_ms`, `network_calls`, `fan_out`, `approvals` → `approvals.requested`, `model_calls`, `spend`); the kernel list is the union and is closed per dialect. **Extension dimensions** (`ext` namespace, registered schema, never budgetable by the kernel without a dialect bump): e.g. `gpu_ms`, `browser_actions`, `bytes_stored`.

**Measurement points (producer → event; WS-B1 classes).** Model adapter (C1) → `model.call.completed.usage` carries the *raw provider usage* **and** the canonical role decomposition with the profile's declared `usage_mapping{dialect ∈ {input_inclusive, input_exclusive}, …}`; tool executor (E5) → `action.tool.completed{duration, network_calls}` and `action.effect.observed.cost{env_ms, network}`; environment service (B5) → `action.environment.attached/detached{reserved_ms, active_ms, hibernated_ms}`; control strategy/envelope (F1/F2) → `lifecycle.turn.*`, `control.retry.scheduled`; orchestrator (F3) → `control.subagent.spawned{budget_slice}`; reference monitor/approval (H1/H7) → `security.permission.requested/decided{latency}` → `approvals.*`, `time.human_wait_ms`; validators/judges (G1/G3) → `verification.validator.invoked` + their own `model.call.*`; context builder (D1) → `context.assembled{tokens}` → `context.occupancy`. **Rule R-ACC-1: raw usage lives on the producing event; it is never duplicated into a separate usage event.** The accounting layer *reads* those events and posts charges (§6.2).

### 6.2 Accounting contract (charges, spend derivation, attribution)

**Operations (language-agnostic).**
- `charge(run, lease, budget_id, quantity: ResourceQuantity, source: EventRef, attribution) → SeqRange` — appends `control.budget.consumed{budget_id, dimension, amount, running_total, limit?, source_event, attribution, reservation_id?}`; idempotent on `(source_event, dimension)` (a re-parsed usage after crash never double-charges — same rule WS-B2 uses for `effect_id`). Failure: `UnknownBudget`, `DimensionNotBudgetable`, `Fenced`.
- `attribute_spend(run, lease, source: EventRef, pricing: PricingTableRef, cache_ttl?) → SeqRange` — appends `measurement.cost.attributed{resource: "spend", amount_micros, currency, provenance ∈ {measured, reported, reconstructed}, derivation ∈ {provider_priced{unit, rate_ref?}, table_priced{table_ref, table_version, tier?, ttl_class?}}, confidence ∈ {exact, bounded{lo, hi}, estimate}, coverage: decimal, source_event, model_ref, attribution}`. **Provenance** says who observed the *quantity* (the runtime measured the call — native adapter or model-boundary interception; the participant *reported* it — ACP `usage_update`, Claude Code `total_cost_usd`; it was *reconstructed* from a native log — container-installed mechanism). **Derivation** says how money was obtained from the quantity. **Confidence** is `exact` only for `measured × provider_priced` or `measured × table_priced` with full coverage; `reported` rows are `estimate` unless the participant's capability declaration marks cost accounting `supported` and probing confirmed it (T-LCD-07); `reconstructed` rows carry `bounded` from the reconstruction's own uncertainty; `coverage` = fraction of the run's model calls with usage available (a hosted run at `events` level with usage on 60 % of calls reports 0.6 and is never summed as if complete). This answers **OQ-033** and phase-0 §5.5.
- `totals(run | budget_id | experiment_id, group_by: {dimension, model_ref, charged_to, component_variant_ref, participant}) → ResourceVector` — a **materialized view** (`cost_totals`, WS-B1 §6.1) rebuilt from `control.budget.consumed` + `measurement.cost.attributed`; never a stored counter (opencode's signed projector is rejected: reverts and rollbacks are events; charges are never subtracted, they are *excluded by the view* when the projection's branch excludes their source events).

**Attribution record (on every charge and spend row).** `attribution{run_id, participant_ref, charged_to ∈ {subject, instrument}, budget_id, component_class?, component_variant_ref?, binding_locality?, model_ref{profile_ref, provider_model_id, serving_route, effort?}, ir_refs[]}`. **Rule R-ACC-2 (nothing unaccounted):** every `model.call.completed`, `action.tool.completed`, `action.effect.observed`, `security.permission.decided`, `verification.validator.invoked` and `action.environment.*` event yields ≥1 charge; an event with no charge is a validation error of the ledger projection (AC-L2-2). **Rule R-ACC-3 (subject vs instrument):** `charged_to = subject` when the producing component is bound in the run's sealed Harness Definition (including validators the definition invokes, judges the definition's control strategy calls, compaction/summarisation calls — Codex/goose count compaction, and the Lab must too); `charged_to = instrument` when the producer is the experiment's grader, a conformance probe, a Lab-side judge for `activated/followed` detection (WS-A2 detectors), or the hosting adapter's own calls. Both are recorded; scorecard efficiency metrics default to `subject` and report `instrument` separately (OQ-059 / OQ-053 answered). **Rule R-ACC-4 (boundary cost):** an out-of-process component binding (WS-A5 `binding locality`) charges its marshalling latency to `time.working_ms` with `component_variant_ref` set, so the Lab can stratify on locality (OQ-075 input).

**Pricing table.** `PricingTable{table_id, version, currency, rows[{model_ref, input_uncached, input_cache_read, input_cache_write{by ttl_class}, output_visible, output_reasoning?, tiers[{threshold_tokens, rates}]?, valid_from, source}]}` — a content-addressed bundle artifact (WS-I3/L4); `attribute_spend` refuses a model with no row (`NoPrice`) rather than pricing at zero (AIOS' and Harbor's zero-cost fallbacks are rejected as silent errors).

### 6.3 Budget contract (allocation, reservation, consumption, inheritance, exhaustion)

**Data model.** `BudgetNode{budget_id, scope: Ref<Goal | AgentProcess | Procedure | Experiment>, parent: budget_id?, mode ∈ {slice, pool}, dimensions: map<DimensionId, {hard: Ceiling?, soft: [Threshold], metering: MeteringFormula?}>, remaining: ResourceVector (view), reserved: ResourceVector (view), created_by: EventRef, amendments: [EventRef]}`. This is the runtime instantiation of WS-A3's `Budget` entity (whose `accounting: Ref` points at this contract). `Ceiling{limit, unit}`; `Threshold{at_remaining | at_fraction, action: Ref<HarnessRule>}` (soft); `MeteringFormula{expr over role counters}` — e.g. Codex's `w_s·output + w_p·input.uncached` or Inspect's `(input*0.1)+output` — declared per dimension, with the identity formula as default; a provider-supplied unit (`codex_rollout_budget_units`) is a `metering = provider_unit{name}` variant whose rows are `provenance = reported`.

**Operations.**
- `allocate(parent: budget_id?, scope, spec: BudgetSpec) → budget_id` — appends `control.budget.allocated{…}` (new class, proposed to WS-B1). *Invariants:* `child.hard ≤ parent.remaining` dimension-wise at allocation (WS-A3's `child ≤ parent` made dynamic: containment is against the parent's **remaining**, not its original ceiling); in `slice` mode the child's ceiling is *subtracted* from the parent's available amount (exclusive); in `pool` mode the child shares the parent's pool and may only set a *tighter* ceiling. Failure: `BudgetExceedsParent`, `DimensionUnknown`.
- `reserve(budget_id, quantity, holder: EffectId | ModelCallId, ttl) → reservation_id` — appends `control.budget.reserved{…}` (new class). *Invariants:* Σ reservations + consumed ≤ hard ceiling along the whole ancestor chain (Agent Contracts' conservation law applied to reservations, so concurrent children under a `pool` cannot jointly overshoot — F4/F5); reservations expire with the holder's lease (WS-B2 `unknown` resolution releases or converts them). Failure: `InsufficientBudget{dimension, requested, available}` — a typed refusal *before* dispatch, the reserve-before-spend rule.
- `charge(...)` as in §6.2 — consumes against the reservation if present (`reservation_id`), releasing any excess (`control.budget.released`); over-consumption beyond a reservation is charged and flagged `over_reservation = true` (never refused after the fact — the effect already happened).
- `check(budget_id) → [Exceeded{budget_id, dimension, value, limit}]` — evaluates **root-to-leaf** (Inspect precedent); the outermost exceeded node wins so a child cannot loop on its own exhaustion while the parent is already spent.
- `amend(budget_id, delta, authority) → SeqRange` — appends `control.budget.amended{old, new, authority}`; permitted on the run's root budget by a human/operator authority (Inspect live override precedent, C1) and on a child budget by its parent's process only within the parent's remaining; **an evolution diff that loosens a budget is `budget_delta = loosening` in WS-A3's `HirDiff` classification and is rejected in an evolution context** (ADR-0002 governance, mirrored from `AuthorityWidening`).
- `advise(budget_id) → ContextItem` — renders the soft budget as a model-facing artifact through the Model Profile (Codex `reminder_message_template`, Anthropic countdown); delivery appends `measurement.artifact.delivered{kind: budget_reminder}`; activation/following per WS-A2 detectors (T-LCD-13). Never affects `check`.

**Inheritance across delegation.** A `delegated-to` edge carries `Ref<Budget>`; at `control.subagent.spawned{budget_slice}` the runtime calls `allocate(parent = spawner's budget, mode = slice | pool)`; the child run's `lifecycle.run.created.manifest.budget` references the allocated node; charges in the child post to the child node and propagate to ancestors (`record()` semantics) so the parent's `remaining` view is always the truth; on `control.subagent.result/cancelled`, a `slice` child's unspent remainder is released to the parent (`control.budget.released{reason: child_finished}`) — *affine* handling: a slice is moved to the child and moved back, never aliased (S-209 principle 3). Hosted participants receive a budget only as a *boundary* enforcement (WS-A3 `OpaqueProcess.budget`): the hosting adapter charges what the mechanism can observe, `check` runs at the boundary, and exhaustion cancels the participant through the Hosting ABI; the participant's own internal budget (e.g. its `task_budget`) is `supplies.context` if the capability declaration allows instruction delivery, otherwise `unknown` (T-LCD-07).

**Exhaustion behaviour (the rule WS-F2 enforces).** (E1) A hard ceiling is evaluated at **decision points only** — before a model call (`reserve` refusal) and after each effect's terminal event — never by interrupting a committed non-`read_only` effect: WS-B2 invariants 1–5 hold regardless of budget, so an irreversible effect in `committing` runs to `observed | unknown` and *then* the envelope stops. (E2) On `Exceeded`, the envelope appends `control.budget.exceeded{budget_id, dimension, value, limit}` and `control.decision{kind: stop, reason: budget_exhausted{dimension}}`; the run finishes with `stop_reason = budget_exhausted` and every open effect closed per WS-B2 (no dangling intent). (E3) A `grace` allowance (per dimension, default zero) may be declared so a terminal *report* model call can still run after exhaustion (Anthropic's "finish gracefully"; Codex reminders at 75/50/25 remaining) — grace is a *soft* threshold whose action is `request final summary`, not a widening of the hard ceiling. (E4) Soft thresholds fire `advise`; crossing is recorded once per (budget, threshold, context window) and re-armed after compaction (Codex `rearm_reminder`). (E5) Gauge caps (`fan_out`, `delegation_depth`, `context.occupancy`) refuse the *next* increment (`SpawnRefused`, `CompactionRequired`) rather than stopping the run.

### 6.4 Consumers (how each subsystem uses the model)

- **WS-F2 control envelope:** owns `check` at decision points, `reserve` before model calls (reservation = min(`max_output` declared by the profile, remaining)), turn/retry counters, and the exhaustion rule E1–E5; retries of `unknown` effects re-use the same reservation (idempotency key), never a second one.
- **WS-C2 router:** reads `remaining` (per dimension) and the pricing table to choose a model within budget (BAMAS-style constraint); every reroute appends `model.rerouted{reason: budget | cost | latency}` and the charge's `model_ref.serving_route` reflects the actual route.
- **WS-C4 cache:** emits `cache_read/cache_write[ttl]` roles through the adapter; cache-hit rate = `cache_read / input.total` on the canonical decomposition; declares cache state (`warm | cold | unknown`) on `model.call.requested` so J3 can control or stratify on warmth (OQ-097); semantic caches that skip a model call still post a `model_calls` charge of 0 with `cache_hit = true` — nothing unaccounted.
- **WS-F4 value-of-compute scheduler (C3):** consumes per-decision `control.decision{budget_remaining}` and per-arm outcome distributions to estimate marginal success per unit; it is a *policy over* `allocate/reserve`, never a bypass; evaluation calls it schedules are `charged_to = instrument` when Lab-side, `subject` when in-loop.
- **WS-J3 experiment engine:** every arm carries `search_budget: BudgetSpec`, `eval_budget: BudgetSpec`, `matching: MatchSpec` (§6.5); refuses to run or report without them (T-LCD-14); allocates one root `BudgetNode` per configuration run from the arm's spec; records `measurement.experiment.bound{budget_id}`.
- **WS-I2 scorecard / WS-J4 comparison:** efficiency dimension computed from `cost_totals` grouped by `charged_to = subject`; class-scoped declarations: token-role metrics require `model_io` or `events`-with-usage; spend metrics require `coverage = 1` for `exact`, else render with a band; `budget_utilization = consumed / hard` and `exhaustion_rate` are process metrics; budget *compliance* (soft) is a T-LCD-13 metric.
- **WS-H7 approvals:** `approvals.requested/granted` counters and `time.human_wait_ms` come from `security.permission.*`; a budget may cap approvals (an "autonomy budget", doc 2 §8 autonomy dimension); exhaustion of the approvals budget converts the next `ask` into `deny` — never into `allow` (no authority widening by budget).
- **WS-I1 telemetry:** lowers token roles to OTel `gen_ai.usage.*` (cache read/write, reasoning) and declares `spend`, `charged_to`, provenance as loss (no OTel slot) carried in attributes.

### 6.5 Matched-budget comparison definitions for the Lab (T-LCD-14)

`MatchSpec{dimensions: [DimensionId], mode ∈ {matched_cap, iso_cost, matched_total}, tolerance, pricing_table_ref?, model_scope ∈ {same_snapshot, cross_model}}`. **Definitions:**
- **M1 matched-cap:** all arms run under identical *hard ceilings* on the declared dimensions; the report shows per-arm consumption distributions and `budget_utilization`; a result is comparable only if every arm's utilisation is reported (an arm that used 20 % of the cap is not "cheaper", it is under-utilised). Admissible for any dimension within `same_snapshot`; for `cross_model`, admissible only on `spend`, `time.*`, `model_calls`, `tool_calls`, `approvals.*` (R3).
- **M2 iso-cost (cost-controlled frontier):** arms are compared at equal *realized* consumption by fitting `P(success | consumed ≤ c)` curves per arm and reporting the capability-cost Pareto frontier (Kapoor; HAL); requires per-run totals with `confidence ≠ estimate` on the matching dimension or the row is stratified out; the frontier is reported per provenance class and combined only with bands.
- **M3 matched-total (adaptive/evolving methods; S-083):** `total = search_budget + eval_budget + inference_budget` is equal across arms; the persistent artifact produced by search is *frozen* and evaluated under `eval_budget` alone (artifact benefit); search-time benefit is reported separately; a baseline arm receives the same total as test-time compute (e.g. k samples). The results schema keeps `search_budget`, `eval_budget` and `artifact_ref` per arm (T-LCD-14 field requirement).
- **Invariants:** the engine refuses (`UnbudgetedArm`, `IncommensurableMatch`, `MissingPricingTable`) rather than warns; matched dimensions use the same `MeteringFormula` across arms; heavy tails are reported (exhaustion rate, p95/p99 consumption), never only means (doc 2 §8).

### 6.6 Acceptance-criteria sketch

- **AC-L2-1 Canonical roles.** For every Model Profile adapter, a golden usage payload in each provider dialect lowers to the canonical decomposition with `input.total = uncached + cache_read + cache_write` and the declared `usage_mapping`; the same payload priced by two independent implementations of `attribute_spend` agrees to the micro-unit.
- **AC-L2-2 Nothing unaccounted.** Projecting a Stage 3 run yields ≥1 charge for every accountable event class; the projection validator lists zero orphan events; instrument and subject totals sum to the raw totals.
- **AC-L2-3 Containment & conservation.** Under a `pool` parent with N concurrent children, fault injection (children spending at the same instant) never yields Σ children consumed > parent ceiling; under `slice`, a child's ceiling never exceeds the parent's remaining at allocation and the remainder is released on child completion; `allocate` refusals are ledgered.
- **AC-L2-4 Exhaustion at effect boundaries.** With a hard ceiling set to exhaust mid-effect for each WS-B2 risk class, the committed effect always reaches a terminal or `unknown` state before `control.budget.exceeded`; the run ends with `stop_reason = budget_exhausted`; no dangling intent (WS-B2 AC-B2-03 shared battery).
- **AC-L2-5 Root-first.** A child whose budget is exhausted while the parent is also exhausted receives the *parent's* `Exceeded`; a subagent architecture that retries on its own exhaustion terminates.
- **AC-L2-6 Idempotent charging.** Re-projecting after a crash between `model.call.completed` and its charge yields exactly one `control.budget.consumed` per `(source_event, dimension)`.
- **AC-L2-7 Provenance stratification.** A comparison containing `reported` and `measured` spend rows renders separate frontiers plus a combined band; a `coverage < 1` row is never summed as complete.
- **AC-L2-8 Refusal.** The experiment engine refuses an arm lacking a `MatchSpec`, a cross-model token match, or a model without a pricing row (T-LCD-14).
- **AC-L2-9 Soft-budget compliance.** The Stage 3 reference harness emits `measurement.artifact.delivered/activated/followed` for budget reminders, and a per-profile compliance metric is computable (T-LCD-13).
- **AC-L2-10 Working time.** A run throttled by injected provider rate-limit waits shows `time.wall_ms − time.working_ms` equal to the injected waiting time within tolerance.

### 6.7 Build-stage suggestion

- **Stage 0 (minimal baseline):** the taxonomy's token roles, `model_calls`, `tool_calls`, `turns`, `time.wall_ms` recorded on producing events; one root `BudgetNode` with hard ceilings on `tokens.blended`, `model_calls`, `time.wall_ms`; `check` at decision points; `stop_reason = budget_exhausted` (doc 2 §11 "explicit token/tool/time budgets").
- **C0 / Stage 1:** full kernel dimension list; `control.budget.allocated/reserved/consumed/released/exceeded/amended` and `measurement.cost.attributed` payload schemas; `attribution` record; `PricingTable` schema; `cost_totals` view; canonical usage lowering per adapter (AC-L2-1/2/6); soft thresholds as HarnessRule actions.
- **C0 / Stage 2:** `env.*` and `network.*` from B5/E5; approvals and human wait from H7; `context.occupancy` gauge to D2; cache roles from C4; `advise` rendering via the profile.
- **C0 / Stage 3 (evaluation-first):** `MatchSpec` M1–M3 enforced by J3; frontiers and stratification in J4; AC-L2-3/4/5/7/8/9/10 in the Stage 3 suite; budget compliance metric.
- **C1:** `amend` (live retune), reservation sizing policy, pricing-table governance (OQ-093), semantic-cache accounting.
- **C3 / Stage 4:** delegation inheritance (`slice`/`pool`) with F3; hosted-participant boundary budgets with J6; **C3 / Stage 4–6:** F4 value-of-compute as a policy over `allocate/reserve`; matched-total (M3) used by I5's evolution gates.

## 10. Confidence

**High** for the taxonomy's token-role decomposition, the flow/gauge split, working-vs-wall time, spend as derived-with-provenance, and the tree/containment/root-first budget mechanics: each has ≥2 Tier-B source-code precedents read at pinned commits (Inspect, Codex, opencode, goose, Claude SDK, HAL/Harbor) and vendor documentation, and the neighbouring Phase 1 dossiers already reserve the slots (A3 `Budget`, B1 events, A5 `(profile, accounting)`). **Medium** for reserve-before-spend and the `slice`/`pool` delegation modes as C0 contracts: the failure mode is documented (incident catalogue, mechanism-grade) and request-level reservation exists (Codex guardian), but no audited harness reserves per model call — the contract is `novel as integrated`; staged so Stage 0–3 need only containment. **Medium** for the matched-budget definitions M1–M3: M1/M2 have Tier-A/B practice (HAL, Kapoor), M3 rests on a `provisional (counter)` preprint plus doc 2 §8's explicit standard. **Low** on any quantitative claim (token multipliers, overrun rates, cost reductions) — all `provisional` or product-specific and none load-bearing. Reflexively: this dossier assumes provider usage reports are truthful and complete; the `coverage`/`confidence` fields exist because that assumption fails for hosted participants.
