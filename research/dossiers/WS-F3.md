## 1. Scope & boundary

This workstream decides **what a subagent *is* to the reference runtime and the one path by which a run may create, isolate, wait for, and absorb the work of another run**: (i) the **spawn contract** — the kernel operation that composes four ratified primitives into one atomic, ledgered act: ADR-0053's `delegate` (authority narrows-or-preserves), ADR-0040's `allocate` (budget is conserved as a `slice` or `pool`), ADR-0138's `derive` (workspace isolation modes) and ADR-0130's writer lease (the child is a run with its own ledger and lease); (ii) the **isolation rules** — context, environment, memory, credentials and labels for a child; (iii) the **merge contract** — how a child's work re-enters the parent *as artifacts and typed events*, never as a transcript; (iv) the **topology catalogue** — the closed set of delegation shapes the runtime executes as data (orchestrator–worker, pipeline, recursive full-harness, independent verifier, background/detached, hosted peer), each a preset over the same contract; (v) **failure containment** — what a child's death, a parent's death, exhaustion, cancellation and revocation do to the other side; (vi) subagents as **`AgentProcess` IR entities** reached by `delegated-to` edges (ADR-0016) — the answer to OQ-135; (vii) the **"is multi-agent justified" decision inputs** WS-F4 will estimate over, and the canonical Lab comparison that makes doc 2 §11 Stage 4 ("subagents only for measurable reasons") a measured claim; (viii) acceptance criteria: delegation never widens authority, budgets are conserved, failures are contained.

It explicitly leaves to neighbours: the authority handle, `authorize`, `delegate` and its preconditions D-1…D-5 (**WS-H1**, ADR-0051…0053 — consumed verbatim; nothing here re-decides an attenuation rule); budget nodes, `slice`/`pool`, reservation and root-first exhaustion (**WS-L2**, ADR-0040 — consumed; this dossier fixes only *which* mode a topology uses and when the remainder is released); the environment handle, `derive` modes and D1–D6, especially D5 "merge is never implicit" (**WS-B5**, ADR-0138 — consumed; this dossier supplies the merge *policy* record F5 refines); leases, `suspend`, `child_terminal` wakeups and the recovery table's `subagent` row (**WS-B3**, ADR-0130…0132 — consumed); the `delegate` decision point, its owner in β and the `delegation_completed` cue (**WS-F1**, ADR-0103); the stop protocol's child-cancel step and `TimeoutPolicy[subagent]` (**WS-F2**, ADR-0106/0107); shared-state ownership, belief merge across a run tree and conflict resolution *algorithms* (**WS-F5** — this dossier fixes the merge *contract* and the conflict *record*, not the resolution policy); the value-of-compute estimator (**WS-F4** — this dossier supplies its inputs and the `delegation_reason` field it predicts over); critic isolation and independence (**WS-G3**, ADR-0116 — a critic is one topology preset here); the `subagent_task` compilation target and its selection rule (**WS-D5**, ADR-0085); the A2A delegation edge and hosted peers (**WS-E4**/**WS-J6**, ADR-0096/0164); the `subagent_result` candidate kind and its slot (**WS-D1**, ADR-0074); cross-run audit anchors (**WS-H6**, ADR-0067); the `ModelRole.subagent` binding (**WS-C2**, ADR-0121); every language, runtime and storage choice (**WS-L1**).

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Every audited runtime spawns a subagent as a *new session with a fresh context* and passes a small, typed record — instruction, tool subset, model, and sometimes a turn cap — and nothing else.** Claude SDK: `AgentDefinition{description, prompt, tools | disallowedTools, model (alias or "inherit"), skills, memory scope, mcpServers, maxTurns, background, effort, permissionMode}` (S-109 L87–107). opencode: `Agent{mode: subagent, model?, permission ruleset, steps}` plus a per-call `prompt`; "Each agent invocation starts with a fresh context unless you provide `task_id`" (S-111 `task.txt` rule 4). Pi/prime-agent extension: a separate OS process with `--no-session`, `--tools` allowlist, `--model`, an appended system prompt (S-113 L300–338). Codex: a new thread with `SubAgentSource::ThreadSpawn{parent_thread_id, depth, agent_role}`, a config built from the *turn* context, and `fork_turns ∈ {none, all, n}` controlling how much parent transcript the child sees (S-107). Prime Agent's native `rlm(prompt, name=, model=)`: "a normal child `AgentSession` with an independent context and session directory" that "inherits the parent model, provider configuration, skills, tools, retry policy" (S-116 `docs/rlm.md`). AOrchestra states the same four slots ⟨Instruction, Context, Tools, Model⟩ as the whole abstraction (S-WS-F3-02, `provisional`). **Implication:** the `SubagentSpec` (§6.2) is a *goal + supplies + attenuated grants + budget + isolation + return contract* record; clean context is the default *by construction* (the child's context is assembled only from `supplies`), and Codex's `fork_turns` is the one precedent for passing selected parent transcript items — expressible as `supplies.context_items` at `≤ delegate` authority, never as a copied transcript.

**F2 — Authority at spawn is *not* attenuated in any audited runtime; the ones that try do it by deny-list inheritance or by re-reading the parent's policy object.** opencode's `deriveSubagentSessionPermission` inherits only the parent session's `deny` rules and `external_directory` rules; the comment is explicit: "Parent agent restrictions only govern that agent; the subagent's own permissions determine its capabilities" (S-111 `subagent-permissions.ts` L8–12) — a child whose *own* ruleset allows more than the parent's session widens by design. Codex hands the child the parent's exec-policy manager only when `child_uses_parent_exec_policy` (S-107 `control.rs` L801–812) and the parent's environment snapshot unconditionally (L778–799). Claude SDK lets an `AgentDefinition` set its own `permissionMode` (S-109 L107). Pi's extension passes a `--tools` allowlist — a subset by construction, but the child process is a fresh `pi` with the user's full settings. **Implication:** ADR-0053 D-1 (`child.grants ⊆ delegable parent handles`, ceiling ≤ effective authority at spawn) is `no-precedent` in shipped runtimes — the audit reconfirms WS-H1 F5 — and the spawn contract must make attenuation a kernel precondition of run creation, not a property of the child's definition. A `SubagentSpec.requested_grants` that exceeds the parent's coverage is attenuated (never rounded up) and the attenuation is recorded on `control.subagent.spawned`.

**F3 — Budgets cross the spawn boundary as *caps and roll-ups*, never as allocations; fan-out and depth are the two limits every runtime enforces in code.** opencode: `subagent_depth` (default 1) enforced by walking `parentID` (S-111 `task.ts` L100–112) and a per-agent `steps` cap. Codex: `AgentExecutionLimiter{max_threads}` → `AgentLimitReached` (S-107 `execution.rs`), `depth` on the source record, and one shared weighted rollout pool per root-thread tree (via ADR-0040). Pi: `MAX_PARALLEL_TASKS = 8`, `MAX_CONCURRENCY = 4` (S-113). Prime Agent: `rlmDepth`/`rlmMaxDepth` on the child runtime options; "Child usage is attributed to the parent session while remaining distinguishable in context-tree reporting" (S-116). Claude SDK: `maxTurns` per definition; usage rolls up into the parent's `ResultMessage`. None passes a *typed allocation* with the task; the incident catalogue's delegation-fanout race (S-209, 11/63 incidents, via ADR-0040) is the failure this produces under concurrency. **Implication:** `spawn` calls `allocate(parent_budget, mode)` and `reserve` for the spawn itself (ADR-0040 decisions 2–3); `fan_out` and `delegation_depth` are the ratified gauges whose caps refuse the *next* spawn (`SpawnRefused`, ADR-0040 decision 5); Codex's pool and opencode's per-child caps are the two ratified modes.

**F4 — Results return through exactly one of three channels, and the transcript is never one of them in a well-designed system: a single final message, files/artifacts by reference, or a message queue.** opencode: the tool result is the *last text part* of the child's final assistant message; "The result returned by the agent is not visible to the user" (S-111 `task.ts` L214–226; `task.txt` rule 3). Claude SDK: subagent transcripts live in a separate `subpath`; by default "only `tool_use` / `tool_result` blocks from subagents" are forwarded, text is opt-in (S-109 L2158–2166). Pi chain: only `getFinalOutput(messages)` — the last assistant text — becomes `{previous}` (S-113). Prime Agent: "Results arrive only through explicit `agent_message` replies or files, never as an `rlm()` return value" (S-116). Anthropic: subagents "store their work in external systems, then pass lightweight references back to the coordinator" to avoid the "game of telephone" (S-036). Symphony: workers never return anything to an orchestrator context — the tracker state and the per-issue workspace *are* the result (S-108). OrchBench finds "cross-agent information transfers and their retention ratios" — what survives the hand-off — to be the dominant lever, ahead of agent count (S-WS-F3-01, `provisional`). **Implication (§6.4):** a `SubagentResult` is `{outcome_class, artifacts by content address, an optional summary artifact at ≤ delegate, claims by reference, usage}`; the parent's context receives one `subagent_result` candidate (ADR-0074) rendered by the profile; the child's ledger is reachable by reference for humans, surfaces and validators, never as context; the *return contract* (which artifacts, what summary schema, what size) is declared at spawn so retention is a measured property (T-LCD-13 on the summary artifact).

**F5 — Merge into a shared workspace is either absent (isolated copies, nothing merged) or implicit (same directory, last write wins); no audited runtime records a merge as the parent's own attributable effects.** Cursor subagents get "an isolated copy of the project" (S-054) and the changelog does not say how results return; Cursor's earlier design shares the environment (S-052) — concurrent mutation with no arbitration. opencode subagents share the parent's directory. Claude SDK subagents share the working tree. Pi spawns child processes in `cwd ?? defaultCwd`. Symphony gives each *issue* its own workspace and merges through git/PRs outside the orchestrator. Prime Agent returns files by path. The only ratified rule is ADR-0138 D5: a `fork_snapshot`/`fresh_from_image` child returns artifacts by content address and "the parent applies them as its own `fs_write` effects with a `baseline_ref`". **Implication:** §6.4 fixes the merge *contract* — parent-applied, baselined, conflict-detected against the parent's current snapshot, ledgered as `control.subagent.merged` — and leaves the conflict-resolution *policy* variants to WS-F5.

**F6 — Failure of a child is reported to the parent as data in every runtime, but parent failure is handled inconsistently: cancel-cascade (opencode, Pi), detach (Cursor, Prime Agent daemon children), or undefined.** opencode: `Effect.onInterrupt(() => ops.cancel(child))` and on parent abort both `cancel` and `background.cancel` (S-111 L330–367); a failed child becomes `Subagent failed (task_id …)` — an error *result*, not an exception in the parent loop. Pi: `SIGTERM` then `SIGKILL` after 5 s on abort; a chain "stopped at step i" is an `isError` result. Prime Agent: "Successfully completed daemon-backed children remain addressable while their parent session is open"; deletion is explicit; "The child remains available only until its parent session closes" (S-116 `agent-message`). Cursor: "A subagent might even outlive its parent". Codex: `AgentLimitReached` is a typed error; child threads are excluded from daemon recovery candidates (via WS-B3: "only root, non-ephemeral threads"). **Implication:** containment rules C-1…C-10 (§6.5) — child outcome is always a cue, never an exception; parent stop cancels children (ADR-0106 step 2) unless `on_parent_end = detach_to_child` was declared at spawn; parent crash leaves the child running under its own lease and the parent resubscribes `child_terminal` on restore (ADR-0130 table, ADR-0131).

**F7 — Recursive full-harness delegation is the same contract with the child's definition equal to the parent's; the runtimes that support it enforce only depth.** RAH's unit "is a full agent harness with filesystem tools, code execution, and planning rather than a model call" and children can spawn children (S-064). Prime Agent's `rlm()` creates "a normal child `AgentSession`" that inherits the parent's whole configuration; depth is configured (S-116). Codex `ThreadSpawn{depth}` with `depth == 1` registering the root (S-107). opencode `subagent_depth` (S-111). None changes any other rule at depth > 1. **Implication:** *recursive full-harness delegation* is topology T3 (§6.3): `SubagentSpec.process.harness_def` may be the parent's own sealed definition (`semantic_id` equal), grants and budget still attenuate/contain per level, and `delegation_depth` is a gauge cap; there is no second spawn path.

**F8 — Inter-agent communication, where it exists, is family-scoped, identity-stamped by the runtime, and delivered as steering at decision points.** Prime Agent: "parent, siblings, and direct children only"; "Sender identity is daemon-derived and cannot be spoofed from Python"; "Messages always use steering delivery"; daemon-enforced size, rate and queue limits (S-116). opencode background tasks inject a synthetic completion message into the parent session (`inject`, S-111 L232–262). Claude SDK subagent messages carry `parent_tool_use_id`/`parent_agent_id` (S-109). Codex has explicit wait/send verbs on the multi-agent tool surface (`multi_agents_common.rs`). Anthropic's early agents were "distracting each other with excessive updates" (S-036). **Implication:** messaging is C1 and *tree-local* (§6.3): `control.subagent.message` with a kernel-derived sender, delivered as a `human_input`-class cue with `delivery_mode ∈ {steer, follow_up}` (ADR-0131 vocabulary), rate-bounded by the approvals-style gauge; no broadcast beyond the family; no shared mutable context.

**F9 — The strongest evidence about *when* to delegate is negative and mechanism-grade.** MAST: gains "often minimal"; 14 failure modes, most in system design and inter-agent misalignment (S-403, Tier C). Anthropic: coding "involve[s] fewer truly parallelizable tasks than research"; models "are not yet great at coordinating and delegating … in real time"; the cost multiplier is ≈15× (S-036). OrchBench: "benefits of parallelism diminish as coordination failures accumulate" (S-WS-F3-01, `provisional`). Doc 2 §5.7: "Separate agents earn their complexity when isolation or concurrency is itself an architectural requirement." **Implication:** the runtime cannot decide this; it must make the *reason* for a spawn typed (`delegation_reason ∈ {parallelism, clean_context, isolation, independent_check, specialization}`) and recorded on the `delegate` decision so the Lab computes realized benefit per reason (§6.6) — the inputs WS-F4 estimates over.

## 5. Disconfirming evidence & negative results

**Against building an orchestrator at all (R1).** MAST shows minimal gains and a taxonomy of failures that are architectural (S-403); Anthropic says coding is poorly parallelizable and models delegate badly (S-036); doc 2 §11 puts subagents at Stage 4 "only for measurable reasons"; R-2.6.3 is C3/Could. *Why it does not overturn:* three ratified contracts already require a child `AgentProcess` at Stage 4 — critics run "as attenuated read-only processes with their own budgets" (ADR-0116), `delegate` with subagents is C1/Stage 4 (ADR-0053 (e)), and the `subagent_task` target needs a spawn path (ADR-0085). The orchestrator is therefore split: a **C1/Stage 4 kernel slice** (`spawn`, `merge`, events, invariants — needed regardless of whether anyone builds a research swarm) and the **C3 orchestrator component class** (topologies, messaging, the Lab study). The negative evidence becomes the null hypothesis of §6.6, not a reason to leave the seam unspecified.

**Against attenuation at spawn (R2).** opencode deliberately lets a subagent's own ruleset govern ("Parent agent restrictions only govern that agent"), and Claude SDK lets a definition set `permissionMode` — because a *specialist* child may legitimately need a tool the generalist parent does not use. *Why it does not overturn:* ADR-0034 P2 and ADR-0053 D-1 are ratified and constitutional; the legitimate case is expressed by the *definition author* granting the parent a `delegable` handle covering the child's needs at `seal`, or by the child's `permission_request` decided by the principal — never by the parent process widening. The cost (authors must think about delegable grants) is the same cost H1 accepted for evolution.

**Against "fresh context by construction" (R3).** Codex's `fork_turns = all` and Claude Code's forked subagents copy the parent transcript because a child that lacks it re-discovers the same facts (S-036's duplicated searches; OrchBench's retention finding). *Why it does not overturn:* the mechanism is kept — `supplies.context_items` may carry any parent items — but as typed `ContextItem`s with their own provenance and labels, so the child's `context_label` is computed honestly (ADR-0074) and the Lab can measure what retention buys; a byte-copied transcript would re-import the label-laundering channel ADR-0034 closes (subagent outputs are a *derivation*).

**Against the parent-applied merge (R4).** Requiring the parent to re-apply every child write as its own `fs_write` effect doubles I/O for large changes and is slower than a shared directory; Cursor and opencode share the working tree. *Why it does not overturn:* ADR-0138 D5 is ratified for isolated modes; `share`/`scoped_subtree` modes exist precisely for the shared-tree case and attribute each write to the child's `attribution_token` (ADR-0101) with E5 resource keys — no merge step is needed there, and the cost of each mode is measured (AC-F3-10). What is refused is *implicit* merge: writes nobody can attribute.

**Against typed `delegation_reason` (R5).** The model chooses to delegate; forcing it to name a reason is prose in a different coat, and models will pick the reason that unlocks the spawn. *Accepted, with the mitigation that makes it useful:* the reason is a parameter of a `control.decision{delegate}` whose owner may be `code` (a `HarnessRule` or the F4 scheduler) or `model`; when `model`, the reason is a `model_claim` with `authority = delegate` — the Lab measures whether delegations tagged `parallelism` actually reduced wall time at equal tokens (realized-benefit decomposition, ADR-0014). Gaming shows up as a divergence, not as a hidden cost.

**Against tree-local messaging (R6).** Prime Agent's peer communication is what its authors credit for coordination; restricting to parent/siblings/children forbids grandchild relays and swarms. *Why it does not overturn:* Prime Agent's own daemon enforces exactly the family scope ("relay through an intermediate child"); broadcast beyond the family is the "distracting each other with excessive updates" failure (S-036); a swarm over shared external state is topology T6 (Symphony), which needs no messaging.

**Against a closed topology sum (R7).** Orchestration research produces new shapes monthly (AOrchestra's dynamic sub-agent creation; OrchBench DAG plans). *Why it does not overturn:* every shape in the audit is a composition of the six presets over one contract (§6.3), including AOrchestra's (orchestrator–worker with per-call `SubagentSpec` synthesis) and DAG plans (`pipeline` with `wait ∈ {all, any}` on `Procedure` step graphs); a new *primitive* is a dialect bump, never an `ext` escape (ADR-0015).

**Negative results from the audit.** (N1) No audited runtime records the *attenuation delta* at spawn or checks `child ⊆ parent` (reconfirms WS-H1 F5). (N2) None allocates a typed budget with the task; all cap and roll up. (N3) None ledgers a merge as parent-attributable effects. (N4) None records *why* a spawn happened. (N5) Cursor's changelog documents isolated-VM subagents without saying how results return. (N6) Codex and Claude SDK exclude child threads/transcripts from daemon recovery — child durability is `n/a` in production, which is exactly what ADR-0130's own-lease rule adds.

## 6. Recommendation for the spec

### 6.1 Position

1. **A subagent is a run.** It is an `AgentProcess` (native or `hosted`) reached by a `delegated-to` edge (ADR-0016), executed as its own run with its own ledger, writer lease, budget node, environment handle (or scoped handle) and handle set — `run_kind = agent`, `parent_run_id` and `spawn_event` set (ADR-0027 decision 6). Nothing about a child run differs from a root run except that it was created by `spawn` and its authority, budget and containment are bounded by its parent's at spawn.
2. **One spawn path.** Every child — orchestrator worker, pipeline stage, recursive full harness, critic, ensemble member, background worker, hosted peer — is created by the kernel operation `spawn`, which composes `delegate` (ADR-0053), `allocate`/`reserve` (ADR-0040), `derive` (ADR-0138) and `acquire(writer)` (ADR-0130) atomically and appends one `control.subagent.spawned`. A `Delegate` step (ADR-0016 entity 5), a `subagent_task` lowering (ADR-0085), an `EnsembleProcedure` (ADR-0123) and an A2A task (ADR-0096) all reach it.
3. **Isolation is the default, not an option.** The child's context is assembled from `supplies` only; its environment is a `derive` of the parent's (or fresh); its memory namespace is its own; its credentials are placeholders ⊆ the parent's; its label ceiling is the parent's effective authority at spawn.
4. **Results are artifacts and events.** The child returns a `SubagentResult` — outcome class, content-addressed artifacts, an optional summary artifact at `≤ delegate`, claims by reference, usage — and the parent receives one `subagent_result` candidate. The child's transcript is never delivered to the parent's model.
5. **Merge is the parent's act.** Workspace changes enter the parent only as the parent's own baselined `fs_write` effects (ADR-0138 D5) or, in `share` modes, as child-attributed effects under resource keys; conflicts are typed records; resolution policy is WS-F5's.
6. **Failure is a cue.** A child's death, exhaustion, refusal or cancellation reaches the parent as `Cue.delegation_completed{outcome_class}`; a parent's stop cancels children unless ownership was transferred; a parent's crash never kills a child.
7. **Topology is data.** Six presets over the contract, selected in the definition (`Procedure` step graphs, `RuntimePlan/1 delegate` nodes) and bounded by the `fan_out`/`delegation_depth` gauges.
8. **"Whether to delegate" is measured, not asserted.** Every spawn carries a `delegation_reason`; the Lab's `lab/delegation-v1` compares single-agent and delegating configurations under matched-total budget; WS-F4 predicts over the same inputs.

### 6.2 The spawn contract (C1 / Stage 4 kernel slice) — ADR (proposed) WS-F3-adr-1

**`spawn(parent: RunId, lease: Lease{writer}, decision: DecisionRef, spec: SubagentSpec, at: Seq) → Spawned{child_run_id, child_handles: [HandleId], budget_id, env_handle_id?, spawn_event: EventRef} | SpawnRefused{reason}`**

`SubagentSpec` (MUST-data; a typed record on the `Delegate` step or emitted by the control strategy's `delegate` decision):
- `process: AgentProcessSpec` — `native{harness_def: VersionedRef (may equal the parent's `semantic_id` — recursive full-harness), profile_binding (default: the parent's `subagent` role binding, ADR-0121/0124), control_strategy?, slots?}` | `hosted(Ref<OpaqueProcess>)`.
- `goal: Goal` — `statement: Text{authority ≤ delegate when authored by the parent model; ≤ definition when compiled from a Procedure}`, `success_criteria: [Ref<Validator>]`, `budget: Ref<Budget>`, `origin = delegated`, `parent: parent Goal` (ADR-0016 entity 1).
- `role: ModelRole ∈ {subagent, judge}` (ADR-0121; `judge` selects ADR-0116's critic isolation floor).
- `requested_grants: [Grant]` — attenuated by `delegate` to what the parent's `delegable` handles cover (ADR-0053 D-1); the delta is recorded.
- `budget: {spec: BudgetSpec, mode ∈ {slice, pool}}` — `allocate(parent_budget, spec)` must satisfy `hard ≤ parent.remaining` (ADR-0040 decision 2); a `reserve` for the spawn's own cost precedes it.
- `isolation: {context: fresh (fixed), environment: none | derive{mode ∈ {fresh_from_image, fork_snapshot, share, scoped_subtree}, spec} (ADR-0138 §3), memory_namespace: child (fixed; writes at `scope ≤ run` in the child's namespace, ADR-0080)}`.
- `supplies: {context_items: [Ref<ContextItem>], procedures: [Ref<Procedure>], tools: [Ref<ToolCapability>] ⊆ parent's sealed tool table, memories: [Ref<Memory>]}` — every item keeps its own provenance and label; `context_items` is the typed form of Codex `fork_turns` and Claude `initialPrompt`.
- `return_contract: ReturnContract{artifacts: [{kind, schema?: Ref<Validator>, required: bool}], summary: {schema?: Ref<Validator{kind: schema}>, max_tokens} | none, claims: bool}` — what the parent will accept; sizes are caps the child's envelope enforces.
- `wait: {mode ∈ {await, background}, timeout: TimeoutPolicy[subagent] (ADR-0107)}`; `on_parent_end ∈ {cancel, detach_to_child}` (ADR-0138 D4; `detach_to_child` refused for `share`/`scoped_subtree`).
- `delegation_reason ∈ {parallelism, clean_context, isolation, independent_check, specialization}` with `owner ∈ {code, model}` inherited from the `control.decision{delegate}`.
- `topology_ref?: Ref<TopologyPreset>` (§6.3) and `stage_index?` for pipelines.

Procedure (atomic; every step ledgered under the parent's writer lease before the child exists; failure at any step releases everything — idempotent on `(decision, spec hash)` so a crash mid-spawn re-runs to the same outcome, R-4 of ADR-0130):
1. Envelope check (ADR-0106 G-PRE-CALL analogue): `fan_out + 1 ≤ cap`, `delegation_depth(parent) + 1 ≤ cap`, `reserve(spawns, 1)`; else `SpawnRefused{fan_out | depth | InsufficientBudget}`.
2. `authorize` the spawn as a `spawn_process`-domain proposal with `scope = ResourcePattern{kind: agent_process, harness_def_ref, depth}` (§6.7, OQ-135); Π row `spawn_process` — "allow if attenuation holds" attended and unattended (ADR-0052).
3. `delegate(parent, child_spec, requested_grants, budget_req, at) → child_handles` (ADR-0053 D-1/D-2) — `AuthorityWidening`/`NotDelegable`/`BudgetExceedsParent` refuse the spawn.
4. `allocate(parent_budget, budget.spec, mode) → budget_id` (ADR-0040).
5. `derive(parent_env, mode, spec) → env_handle_id` if requested (ADR-0138) — containment `= effective(parent ⊓ child)`, bindings ⊆ parent's.
6. Create the child run: manifest `{configuration_version_id (child's sealed definition + profile binding + environment_ref + budget), parent_run_id, spawn_event, activation_no = 1, attendance = parent's, envelope_policy_ref, delegation_ref}`; `acquire(writer(child))` by the orchestrator's worker; child `lifecycle.run.created{parent_anchor{run_id, seq, hash}}` (ADR-0067).
7. Append `control.subagent.spawned{child_run_id, delegation_ref, child_handles[], parent_handle, ceiling, attenuation_delta, budget_id, mode, isolation_mode, env_handle_id?, supplies_digest, return_contract_ref, delegation_reason, owner, topology_ref?, wait_mode, on_parent_end, depth, parent_head_at_spawn{seq, hash}}` (consolidating ADR-0053 D-6 and ADR-0067 decision 4; payload additions proposed as CF-WS-F3-01) and `subscribe(parent, child_terminal{child_run_id})` (ADR-0131).
8. If `wait.mode = await`: the parent's strategy receives `Cue.wait{until: delegation_completed}`; the parent run may `suspend{awaiting_child}` (ADR-0131) so its lease lapses deliberately.

**Invariants (kernel-enforced; errors never warnings).**
- **SP-1 Never widen.** `child_handles ⊆ delegable(parent)` scope-wise; `ceiling ≤ eff(parent at spawn)`; a child's `permission_request` is decided by the principal, never by the parent process (ADR-0053 (c)). Static form: `validate` rejects a `Delegate` step whose `requested_grants ⊄ authorizes(parent)` (`AuthorityWidening`, ADR-0016).
- **SP-2 Conserved budget.** `Σ children.hard (slice) + parent.consumed + reserved ≤ parent.hard`; charges in the child post to the child node and propagate; a `slice` remainder is released on `result | cancelled`; a `pool` child may only tighten (ADR-0040).
- **SP-3 Fresh context.** The child's first `context.assembled` contains only items reachable from `supplies` ∪ the child's sealed definition ∪ kernel notices; `context_label ≤ ceiling`; no parent transcript bytes are copied (a parent item enters only as a `ContextItem` with its own `delivery_id`).
- **SP-4 Bounded fan-out and depth.** Gauges refuse the next spawn (`SpawnRefused`), never stop the run (ADR-0040 decision 5).
- **SP-5 Own lease, own ledger.** A child's events carry its `run_id` and its own `lease_generation`; the parent never appends to the child's ledger and vice versa; cross-run causality is `causes[]` + anchors (ADR-0027/0067).
- **SP-6 One decision per spawn.** `causes[] ∋ control.decision{kind: delegate, owner, delegation_reason}` (ADR-0103 I1); the F4 scheduler or a `HarnessRule` may own the decision (`code`), the model may propose it (`model`).
- **SP-7 Definition-sealed children.** `process.harness_def` resolves to a sealed definition or a registered variant; repo-supplied agent text enters only as `Text{authority ≤ external}` inside a sealed definition (ADR-0063/0064; the Pi project-trust precedent).
- **SP-8 Hosted children need no native change.** A hosted child is an `OpaqueProcess` spawned through the same operation with boundary-enforced budget and handles (ADR-0040 decision 7; ADR-0053 D-4); a subagent spawned *inside* a hosted participant is `control.subagent.spawned{observed: true}` with no child run (ADR-0164).

**Failure modes (typed):** `SpawnRefused{fan_out | depth | InsufficientBudget | AuthorityWidening | NotDelegable | BudgetExceedsParent | ModeUnsupported | DefinitionUnresolvable | DelegationUnavailable (Stage < 4) | UnattendedAsk}`.

### 6.3 The topology catalogue (C3 / Stage 4–5; presets are MUST-data) — ADR (proposed) WS-F3-adr-2

`TopologyPreset` is a closed sum (HIR/1 dialect; a new shape is a dialect bump) that a definition binds through the `orchestrator` component class or directly as `Procedure` step graphs:

| id | preset | shape (over `spawn`) | β / owner of `delegate` | precedents | stage |
|---|---|---|---|---|---|
| **T0 `single`** | no delegation; `delegate` refused (`DelegationUnavailable`) | — | — | mini-SWE-agent; every Stage-0 harness | C0 (the control arm of every comparison) |
| **T1 `orchestrator_worker`** | parent authors k goals, spawns ≤ `fan_out` children in parallel, `wait ∈ {all, any, quorum(k)}`, merges results; children never spawn (`depth_cap = 1` default) | `model` (lead agent) or `code` (F4 scheduler) | S-036; Claude SDK Agent tool; opencode `task`; Codex `spawn_agent`; Pi parallel mode | C3 / Stage 4 |
| **T2 `pipeline`** | ordered stages; stage i+1's `supplies` ∋ stage i's returned artifacts; failure at stage i stops the chain (`outcome_class` propagates); may loop under a `Loop(bound)` | `code` (compiled `Procedure`) | Pi/prime-agent chain `{previous}`; Anthropic prompt chaining; HoH iterations (S-079, `provisional`) | C3 / Stage 4 |

**Communication (C1, all presets):** `send_message(from_run, to: parent | child(id) | sibling(id), payload: Text{authority ≤ delegate} | ArtifactRef, delivery_mode ∈ {steer, follow_up})` appends `control.subagent.message{sender (kernel-derived), receiver, payload_ref, delivery_mode}` on *both* ledgers (`causes[]` linked) and is delivered as a `human_input`-class cue with `kind = message` at a decision point (ADR-0131 delivery rule; the F1 `Cue` sum gains `peer_message` — CF-WS-F3-02). Reach is tree-local (parent, direct children, siblings); rate/size are gauges with caps (`SpawnRefused`-style refusal, never drop); no message ever endorses or widens (ADR-0035). No shared mutable context exists between runs; shared *state* is artifacts, environments and the F5 ownership model.

**Non-topologies.** Persona role-play sharing one context is "phases of one policy" (doc 2 §5.7) and is representable as `Procedure` steps under T0; it is not a topology and produces no child run.

### 6.4 Merge semantics via artifacts and events (C1 / Stage 4) — ADR (proposed) WS-F3-adr-3

**`SubagentResult`** (the payload of `control.subagent.result`, written by the orchestrator under the *parent's* lease after the child's terminal event; content-addressed):
`{child_run_id, delegation_ref, outcome_class (ADR-0045: scored | budget_exhausted | infrastructure_failure | refused | cancelled | oracle_failure), stop_reason (ADR-0106 sum), child_head{seq, hash, checkpoint_ref} (ADR-0067), artifacts: [ArtifactRef] (content addresses; `produced-by` the child; labels as produced), fs_changes?: FsChangeSet | SnapshotRef (for isolated environment modes), summary?: Ref<Artifact{kind: subagent_summary}> (authority = min(⊔ child inputs, delegate); validated against `return_contract.summary.schema` when declared), claims: [ClaimRef] (the child's G2 claim ledger, by reference), usage: ResourceVector + `budget_released`, verdicts: [VerdictRef] (validators the child ran), return_contract_satisfied: bool, violations: [{field, reason}]}`.

**Rules.**
- **M-1 One candidate, never a transcript.** The parent's context builder receives exactly one `Candidate{kind: subagent_result}` (ADR-0074) per result, rendered by the profile from `summary` + artifact handles; `authority ≤ delegate`, `taint ⊇` the child's accumulated taint, `derived_from.kind = subagent_result` (ADR-0034 P2). The child's ledger, transcript view and full artifacts are reachable **by reference** (handles) for the parent's validators, the surfaces and humans — `context.artefact.delivered` on the summary carries the T-LCD-13 chain so *retention* (OrchBench's lever) is measurable per profile.
- **M-2 Return contracts are enforced by the child's envelope.** A required artifact missing, a summary over `max_tokens`, or a schema failure yields `return_contract_satisfied = false` with typed `violations` — the parent decides (retry the delegation under `RetryPolicy[subagent]` with a new child run and `attempt_no`, or proceed); the kernel never truncates a summary silently (ADR-0092 discipline).
- **M-3 Workspace merge is the parent's effect.** For `fresh_from_image`/`fork_snapshot` children: `merge(parent, result, policy: MergePolicy) → [effect_id] | MergeConflict{paths[], conflict_record}` computes `diff(child_snapshot, child_baseline)` → `FsChangeSet`, checks each path against the parent's *current* `path_baseline`/`fs_tree` (ADR-0137), and applies non-conflicting changes as the parent's own `fs_write` effects with `baseline_ref` (revertable; ADR-0138 D5) through `authorize` (a child's write into a path the parent may not write is refused *here*, closing the "child as deputy" channel). Conflicting paths produce a `MergeConflictRecord{path, parent_baseline, child_before, child_after, parent_current}` and `control.subagent.merged{child_run_id, effect_ids[], conflicts[], policy}`. `MergePolicy ∈ {refuse, parent_wins, child_wins, three_way(Ref<Procedure>), ask}` — the closed sum is fixed here; the *semantics and defaults* of `three_way` and the ownership model behind `parent_wins/child_wins` are WS-F5's (OQ-WS-F3-02). For `share`/`scoped_subtree` children no merge exists: every child write is already a ledgered effect under the child's `attribution_token` and E5 resource keys; the parent's next `verify` sees the world state.
- **M-4 Claims (OQ-278 answer).** A parent `achieved` claim citing a child's `achieved` binds to the child's reconciliation records through `claims[]` + `child_head.checkpoint_ref`; the parent's completion gate (ADR-0113) re-reconciles only claims about handles the parent *itself* commits at merge (the paths in `effect_ids[]`) and any claim whose subject changed after `child_head.seq` (`stale_belief`, D4); child claims about the child's own isolated environment are consumed as `reconciled` evidence at `evidence_class = reconciled` with `origin = subagent`. `divergence_profile` aggregates over the run tree by summing per-run profiles keyed by `run_id` (never averaged).
- **M-5 Budget settlement.** On `result | cancelled`, the `slice` remainder is released (`control.budget.released{reason: child_finished}`); `usage` is the child node's `consumed` view; `harness_overhead.subagent` in `cost_view` counts child cost once under the parent's `subagent` scope (ADR-0044 term).
- **M-6 Environment settlement.** `on_parent_end = cancel`: the child's derived environment is torn down after `merge` (or after `download` of declared artifacts); `detach_to_child`: ownership transfer ledgered (`action.environment.derived` + `control.subagent.detached{child_run_id}`), the parent's teardown leaves it.

### 6.5 Failure containment (C1 / Stage 4) — in WS-F3-adr-3

- **C-1 Child outcome is a cue.** Every child terminal (`scored`, `budget_exhausted`, `infrastructure_failure`, `refused`, `cancelled`, `oracle_failure`) reaches the parent as `Cue.delegation_completed{child_run_id, result_ref, outcome_class}` (ADR-0103) after `control.subagent.result`; the parent's strategy decides (`retry{target: delegation}` under `RetryPolicy[subagent]`, `stop{cannot_proceed}`, or continue); the orchestrator never raises into the parent loop.
- **C-2 Parent stop cascades.** ADR-0106 stop-protocol step 2: `control.subagent.cancelled{reason: parent_stop}` to every child with `on_parent_end = cancel`; each child runs its own stop protocol; the parent drains ≤ `TimeoutPolicy[subagent].hard_max_ms`; a child that has not reached a terminal by then is recorded `unknown` on the parent side (`result.outcome_class = infrastructure_failure{child_unresponsive}`) and its lease expiry finishes it (ADR-0130 L-3).
- **C-3 Parent crash never kills a child.** The child holds its own writer lease; on parent `restore`, the recovery table's `subagent` row applies: keep; resubscribe `child_terminal`; if the child's lease has expired, the child restores independently (ADR-0130 §6.3). A child that finished while the parent was down has written `occurred` to the parent's ledger (or goal inbox, `run_kind = inbox`, ADR-0183), so the result is never lost (AC-B3-07).
- **C-4 Child crash is the child's recovery.** The child's own KP battery applies; the parent sees at most a delay bounded by the `subagent` scope deadline (ADR-0107). A child stuck past `hard_max` is cancelled by the parent's envelope (`control.subagent.cancelled{reason: timeout}`), never killed silently.
- **C-5 Blast radius.** Child containment `= effective(parent ⊓ child_layer)` (ADR-0138 D1; ADR-0060 deny-wins); credentials ⊆ parent's placeholders (ADR-0058 SV-7); egress under the parent's `NetPolicy` (ADR-0061); a child cannot reach an environment the parent does not hold (no handle reference crosses — R-NOSIDE).
- **C-6 Exhaustion is root-first.** A child whose parent is spent receives the parent's `Exceeded` and stops; a child cannot loop on its own exhaustion (ADR-0040 decision 4; AC-L2-5).
- **C-7 Revocation cascades.** Revoking a parent handle revokes every descendant in the same ledger transaction (ADR-0051 H-6; `security.permission.revoked.cascade[]`).
- **C-8 Caps refuse, never kill.** `fan_out`/`delegation_depth`/message-rate caps refuse the next increment (`SpawnRefused`, `MessageRefused`), leaving running children untouched.
- **C-9 Detached children are goal-scoped.** A `detach_to_child` child's completion targets the parent's *goal* subscription (ADR-0131 goal-scoped subscriptions); if the goal is finished the occurrence is `skipped{run_finished}` and audited, never dropped (W-4).
- **C-10 Hosted children fail at the boundary.** A hosted child's exhaustion cancels through the Hosting ABI (`cancel`), its uncovered calls are refused at the boundary, and its `result` carries `mediation` and cost `confidence` (ADR-0165); an observed-only subagent inside a hosted H has no containment claim (`n/a`).

### 6.6 "Is multi-agent justified" — decision inputs for WS-F4 and the canonical comparison (C3 / Stage 4–5) — in WS-F3-adr-2

**Typed inputs available at the `delegate` decision point** (all ledger-derived; none is a `Text` read): (i) `context.occupancy` and the distance to `CompactionRequired` (clean-context pressure); (ii) the candidate subtask's `Procedure` predicates `B(P)`, `R(P)`, `I(P)` (ADR-0085) and its declared `effects` — isolation need and risk; (iii) the parent's `remaining` per dimension and the child `BudgetSpec` (ADR-0040) plus the profile's declared `subagents` capability and `procedure_inline_budget`; (iv) independence requirements from a bound `Validator{kind: judge}` (`IndependenceVector` minimums, ADR-0116); (v) the `context_label`/taint of the material to be processed (quarantine value: isolation is the only label exemption, ADR-0074); (vi) an estimated dependency structure among candidate subtasks (`Procedure` step graph fan-in/out; a `share`-mode requirement signals shared-state coupling); (vii) the history of realized benefit per `delegation_reason` for this `(profile, environment family)` cell from the results store (ADR-0161) — the F4 estimator's training signal; (viii) the wall-time vs token trade-off declared in the arm's `MatchSpec` (a Lab arm matched on `time.wall_ms` values parallelism; one matched on `spend` does not).

**The rule the runtime enforces:** a `delegate` decision without a `delegation_reason` is `refused{MissingDelegationReason}` by the envelope; the reason is a factor in every results row involving a child run; the F4 scheduler (C3) is a *policy over these inputs* that emits `delegate` decisions with `owner = code`, never a bypass of `spawn`.

**`lab/delegation-v1`** (registered `ExperimentSpec`, ADR-0154/0156; pre-registered): factors `topology ∈ {T0 single, T1 orchestrator_worker(fan_out ∈ {2, 4}), T2 pipeline, T3 recursive(depth 2)}` (component-level; the definition supplies a `Goal` + a decomposable `Procedure` so every arm binds) × model snapshot (≥ 2 families) × environment (the Stage-3 coding suite and a research/long-context suite, WS-I4) × budget (`MatchSpec{mode: matched_total on {tokens.blended, spend}}` **and** a second `MatchSpec{matched_cap on time.wall_ms}` arm set) × seed (≥ 5). Hypotheses: **H0** (S-403, S-036) no headline difference between T0 and any delegating topology at matched total on the coding suite; **H1** (S-036, S-399) T1 lowers `time.wall_ms` at equal tokens where subtasks are independent; **H2** (S-064, `provisional`; OrchBench retention) T3's benefit grows with task context length and depends on `return_contract` retention; **H3** (T-LCD-09) model × topology interaction is non-zero; **H4** `delegation_reason = clean_context` decisions reduce `context_exhausted` and compaction counts more than headline. Metrics: headline executable oracle; `time.wall_ms`, `tokens.*`, `spend`; `harness_overhead.subagent`; `merge_conflict_rate`; `return_contract_violation_rate`; `subagent_retention` (T-LCD-13 on the summary artifact); `duplicate_work_rate` (identical `effect_id` derivations across siblings — MAST FM-1.3 recast); `fan_out`/`delegation_depth` distributions; `realized_benefit_by_reason` (ADR-0014 decomposition). Reported as distributions; `n/a` never 0.

### 6.8 Acceptance-criteria sketch

- **AC-F3-01 Never widen (static + Stage 4).** `validate` rejects a `Delegate` step with grants outside the parent's `authorizes` closure; at run time AT-H1-04's full form passes through `spawn` (widening, non-delegable, depth-3 monotone ceilings, cascade revocation, tainted child results); `attenuation_delta` is recorded on every spawn.
- **AC-F3-02 Conserved (Stage 4).** AC-L2-3 executed through `spawn`: N concurrent `pool` children under fault injection never exceed the parent's ceiling; `slice` remainders are released on every terminal; root-first exhaustion (AC-L2-5) holds across depth 3.
- **AC-F3-03 Fresh context (Stage 4).** The child's first `context.assembled` item set ⊆ `supplies` ∪ definition ∪ kernel notices; a parent transcript item enters only as a `ContextItem` with its own `delivery_id`; `context_label ≤ ceiling`; a child fed `external`-labelled supplies produces a result at `≤ delegate` with union taint.
- **AC-F3-04 Results are artifacts (Stage 4).** No `Text` produced by the child appears in the parent's context except the rendered summary candidate; the parent's model surface contains no child transcript bytes (static check on `context.assembled`); the summary artifact carries `delivered/activated/followed` events.
- **AC-F3-05 Merge is attributable (Stage 4).** Every byte changed in the parent's workspace by a `fork_snapshot`/`fresh_from_image` child has a parent `fs_write` effect with `baseline_ref`; a child write outside the parent's writable roots is refused at merge; conflicts produce `MergeConflictRecord`s and `control.subagent.merged`; reverting the merge restores the parent's baseline.
- **AC-F3-06 Containment battery (Stage 4; extends the B3 kill-point matrix).** KP-14 (child running, parent killed): child completes, its `occurred` reaches the restored parent; KP-16 (parent stop with running children): `cancelled{parent_stop}` on each `cancel` child within `hard_max`, `detach_to_child` children untouched; KP-17 (child killed mid-effect): child restores under its own lease, parent waits ≤ deadline; KP-18 (child exhausts while parent spent): child stops with the parent's `Exceeded`; KP-19 (parent handle revoked mid-run): child's next covered proposal is `NoCoveringGrant`.
- **AC-F3-07 Caps refuse (Stage 4).** `fan_out`, `delegation_depth` and message-rate caps produce `SpawnRefused`/`MessageRefused` cues; running children are unaffected; a definition with `depth_cap = 1` cannot create grandchildren.
- **AC-F3-08 One path (Stage 4).** A fuzz harness cannot create a child run except through `spawn`; `subagent_task`, `EnsembleProcedure`, critic invocation and A2A tasks all produce `control.subagent.spawned` with the same payload schema.
- **AC-F3-09 Hosted (Stage 4).** A hosted child spawned through `spawn` gets boundary budget/handles; a subagent inside a hosted participant yields `spawned{observed: true}` and every child-level metric `n/a{class}` (T-LCD-06/-15).
- **AC-F3-10 Overhead measured (Stage 4–5).** `spawn` latency, merge I/O per mode, `harness_overhead.subagent` and `subagent_retention` are reported per topology under matched budget; `lab/delegation-v1` refuses without a `MatchSpec` and reports the model × topology interaction (T-LCD-09/-14).
- **AC-F3-11 Reason is a factor (Stage 4).** A `delegate` decision without `delegation_reason` is refused; results rows carry it; `realized_benefit_by_reason` is computable.
- **AC-F3-12 Recovery (Stage 4).** `spawn` interrupted at each of its eight steps re-runs to the same `Spawned` or a clean `SpawnRefused` with everything released (R-4); no orphan child run, budget node or environment handle survives.

**T-LCD statement (ADR-0007 decision 5).** Satisfies T-LCD-06 (hosted children through the same operation with no native field; observed-only subagents add nothing), T-LCD-07 (`subagents` capability tri-state on hosted; `n/a` never coerced), T-LCD-08 (the `orchestrator` class receives `(ModelProfile, ResourceAccount)`; the per-role `subagent` profile binding is data), T-LCD-09 (topology, `fan_out`, `delegation_reason` are explicit factors), T-LCD-12 (operations over records; the orchestrator worker is out-of-process by construction — it holds a writer lease like any worker), T-LCD-13 (summary artifacts carry the delivery chain), T-LCD-14 (matched-total comparison; child budgets inside the arm's `MatchSpec`), T-LCD-15 (child metrics class-scoped), T-LCD-05 (a profile-conditioned `delegation` default — e.g. "this model family delegates well" — is a conditioned rule with a debt record), T-LCD-02 (goals and summaries are `Text` leaves with provenance). Not applicable: T-LCD-01/-03/-04/-10/-11 (no model-facing surface or lowering is introduced by F3; the `subagent_result` rendering is D1/C3's). ADR-0024 rungs: `spawn`, `merge`, invariants SP-1…SP-8, containment C-1…C-10 are MUST-code; `SubagentSpec`, `TopologyPreset`, `ReturnContract`, `MergePolicy`, caps and defaults are MUST-data.

## 10. Confidence

**High** for the spawn contract's composition and invariants: every element is a ratified ADR applied at one seam (H1 `delegate`, L2 `allocate`, B5 `derive`, B3 leases, H6 anchors, F1 decisions), and the source audit of five runtimes at pinned commits converges on the same spawn record and result channels; the negative results (no attenuation, no allocation, no attributable merge, no recorded reason) are exactly the gaps the ratified contracts close. **High** for "results as artifacts, never transcript" (four production systems and OrchBench's retention finding agree; the only counter-practice, transcript forking, is representable as typed supplies). **Medium** for the merge contract and containment rules: D5 is ratified but the conflict record, `MergePolicy` sum and the parent-stop/child-detach interplay are this dossier's integration, unexercised until Stage 4, and the resolution policy is deferred to F5. **Medium** for the topology catalogue as a *closed* sum: the six presets cover every audited shape, but T3 and T6 rest partly on `provisional` systems (RAH, Prime Agent) and on Cursor's under-documented changelog. **Low** on every quantitative claim (RAH's +9.6 pp, Anthropic's 15×, MAST's mode rates): none is load-bearing; the `lab/delegation-v1` design exists because the field's own evidence is split. Reflexively: this dossier assumes the F1 `delegate` decision and the D1 `subagent_result` candidate exist as ratified; if CF-WS-F3-02 is rejected, messaging degrades to `follow_up`-only delivery through occurrences (ADR-0131), which the C1 slice does not need.
