## 1. Scope & boundary

This workstream decides the **web-based local developer tooling** as a *client* of the kernel and of the Harness Lab: (i) the **view catalogue** — which views exist, what each renders, which data contract (ledger view kind, results/analysis record, registry record, sealed definition) each consumes, and which kernel/Lab operation each *invokes* when it writes; (ii) the **time-travel viewer's requirements on WS-B1/WS-B4** — the read, projection, subscription and branch operations the ledger and branch model must expose so that "what did the model see at seq *s*", "fork here", "why was this rewound" are computable from records, never from UI state; (iii) the **local security posture** of a web surface that sits on a developer machine next to a kernel that can execute effects; (iv) **acceptance criteria** and a **build-stage placement** that says what is C2 and what comes later; (v) an answer to OQ-130 (surface ecosystem binding) *in contract terms only*; and (vi) the T-LCD tests the web surface must pass as a rendering of the Lab (T-LCD-09/-14/-15 are where a dashboard can silently re-introduce the LCD trap).

It explicitly leaves to neighbours: the ledger envelope, view kinds and `subscribe` cursor semantics (**WS-B1**, ADR-0026/0027 — consumed verbatim; extensions requested in §8); the branch model, coherent fork points and replay validity (**WS-B4**, ADR-0133…0135 — consumed verbatim; the viewer renders, never re-derives); spans, cost views and sink policies (**WS-I1**, ADR-0042/0044 — the surface is a *sink* under a `SinkPolicy`); audit proofs and redaction authority (**WS-H6**, ADR-0066…0068); the escalation policy, request/response contract and fatigue mitigations (**WS-H7**, ADR-0069…0071 — the inbox is a renderer of `security.permission.pending` and a caller of `respond`); the assembly pipeline, diagnostic taxonomy and `AssemblyDiff` (**WS-J1**); registry records and discovery (**WS-J2**); `ExperimentSpec`, refusals and the scheduler (**WS-J3**); analysis operations and `RenderSpec` (**WS-J4** — "render never recomputes"); results rows, leaderboard rules and the results `subscribe` (**WS-J5**); the boundary contract, generated client and verb set (**WS-K4** with WS-L5, ADR-0050 D3 — this dossier states which verbs the web surface needs and flags the gaps); the CLI (**WS-K1** — shares every data contract here; the two surfaces must be *renderings of the same records*); the MCP server surface (**WS-K3**); and every language, runtime, UI framework, transport library or rendering technology choice (ADR-0050 §8; no UI framework is named or implied).

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Every audited surface is a *projection client*: it holds no state of record, consumes a durable stream plus paged reads, and re-derives its view from the runtime's records; the ones that keep client-side state either bound it as a cache or introduce a second policy.** Codex projects rollout lines statelessly into UI history changes (`thread_history_projection.rs`: "Project one durable rollout line without reconstructing earlier history … invoke it once per line, in ordinal order") and tells clients to page (`thread/turns/list`, `thread/items/list`) rather than hydrate; OpenHands replays the on-disk log by index then goes live and dedupes by `seq` (`session_socket.py: go_live(through_seq)`); Inspect's viewer reads log files and buffers and polls a single "last eval" timestamp (`notify.py`); opencode's app consumes an SSE stream through a generated client into a local queue with reconnect (`server-sdk.tsx` L255–310); gemini devtools pushes "a full snapshot on connect" then increments and keeps only ring buffers. The two counter-examples are instructive: gemini devtools keeps the last 10 network logs *in memory only* (a diagnostic sink, acceptable), and opencode's app keeps a **client-side auto-accept map** for permissions keyed by session/directory lineage (`permission-auto-respond.ts`) — a widening decision made on the far side of the boundary that the server's monitor never records as a policy. **Implication:** the web tooling is `project()` + `subscribe` + typed operations, nothing else (ADR-0026 materialized-view rule applied to the surface); any "remember my answer" must be a *ledgered lease* (ADR-0070 `ApprovalLease`), never UI state.

**F2 — Durable vs ephemeral is a wire-level distinction in the mature surfaces, and reconnect correctness depends on it.** OpenHands separates `DurableFrame{seq}` from `TransientFrame` and states "Deltas never ride the durable channel"; Codex's persistence policy excludes deltas and approval *requests* from the rollout (WS-B1 F1) while the app-server still delivers them as `item/*/delta` and `item/*/requestApproval` notifications; opencode's SSE handler registers its listener eagerly "so events published after this point cannot be lost while the HTTP body fiber is starting". This is ADR-0026's `durability ∈ {ledger, ephemeral}` and AC-B1-12 seen from the client: a reconnecting client must be able to say `replayFrom(seq)` for durable events (ACP inclusive cursor; WS-B1 `subscribe`) and must *not* expect deltas or permission renderings to be replayable. **Implication:** the surface's live channel is `subscribe(run, from: Cursor)` for durable events plus the ephemeral tail; after reconnect, `read(run, cursor)` up to head and then the tail — the OpenHands replay-then-go-live shape, with the durable/ephemeral flag on every frame.

**F3 — Rewind is a first-class client obligation, and no audited surface hides history on rewind.** Cursor's clients "rewind [the] stream" when a retried step replaces partial output (S-052); Codex `thread/rollback` "only modifies the thread's history and does not revert local file changes … Clients are responsible for reverting these changes" (the trace-only rollback WS-B4 F2 identifies as the SF3/SF5 failure — the reference runtime couples environment restore in `rollback`, ADR-0133); LangGraph forking "creates a new checkpoint that branches from the specified point. The original execution history remains intact." ADR-0027 makes rollback and branch moves appended events (`lifecycle.head.moved`, `lifecycle.run.rolled_back`); WS-B4 §4c requires subscribers to "handle `head.moved` as a rewind". **Implication:** the viewer's model is a *tree with a HEAD*, never a list; a `head.moved` frame moves the rendered path and keeps the discarded subtree reachable (greyed, with the disposition and the rewind note), which is also what makes the discarded attempt inspectable for attribution.

**F4 — Users assume replay is a cache read; the shipping product that offers time travel has to say in its docs that it is not.** LangGraph: "Replay re-executes nodes—it doesn't just read from cache", interrupts re-trigger, external calls fire again. ADR-0028/0135 already fix the semantics (reconstruction by default; `deterministic` only for declaring variants; a `ReplayValidityReport` on every branch). **Implication:** the time-travel viewer must render `replay_mode` and the validity verdict as a badge on every branch and every branch-derived row, and must label the two affordances differently: **scrub** (pure `project(run, view, until_seq)` — nothing runs) versus **fork** (`fork(run, at, …)` — a new run under a budget slice, with the env-binding and speculation policy shown before confirmation).

**F5 — The localhost developer web tool has a documented, exploited attack surface, and the defences converge.** CVE-2025-49596 (MCP Inspector, CVSS 9.4): no authentication between the browser client and the local proxy that spawns stdio processes; exploitable from the LAN when bound to 0.0.0.0 *and* from any web page even when bound to 127.0.0.1 ("DNS rebinding, malicious ads, phishing pages"); fixed by "per-run session tokens … Origin and Host checks (strict CORS). Safer defaults (127.0.0.1 binding)". The MCP transport spec now states the `Origin` MUST and the loopback SHOULD. Chrome 142 ships Local Network Access, which asks the user before a public site may reach a loopback server — a browser-side mitigation that only helps when the UI is served from the same local origin as the API. The audited surfaces implement, with gaps: Inspect (loopback default; non-loopback refused without a token; exact Host + Origin + `Sec-Fetch-Site` checks; custom header + `Sec-Fetch-Dest: empty` on mutations; `frame-ancestors 'none'`); Codex (loopback websocket listener rejects any request with an `Origin` header — browsers excluded by construction; non-loopback requires capability token or signed bearer; unix control socket 0600); goose (secret required to start; cert-fingerprint pinning by the shell; exact non-wildcard origins); OpenHands (session key; first-message WS auth to keep tokens out of logs; loopback CORS); gemini devtools (loopback + same-origin CORS, **no auth** on a POST that triggers a debugger); opencode (Basic auth from an env password with an explicit "server is unsecured" warning when unset; loopback origins allowed; **mDNS advertisement**). Jupyter, the oldest such tool, requires a token even on loopback and documents that "access to the Jupyter Server means access to running arbitrary code". **Implication:** the posture in §6.4 is a *floor*: loopback bind, per-launch capability token required on every request including loopback, exact Host and Origin allow-lists, fetch-metadata checks on mutations, tokens never in URLs, no discovery advertisement by default, and no far-side decisions.

**F6 — Secrets reach UIs through logs and exports unless the boundary redacts.** gemini devtools' own comment: cross-origin access "would let arbitrary websites exfiltrate logs (which may contain API keys/headers)"; OpenHands redacts secret fields *and any ciphertext produced with the server key* at export boundaries (`_secret_redaction.py`); Codex's telemetry splits `log_only` from `trace_safe` (WS-I1 F3). HarnessHarness already forbids secret values in records (`SecretRef`, ADR-0057; SV-1…10) and classifies sinks by content class (ADR-0044). **Implication:** the web surface is a *sink* with a `SinkPolicy`; `content`-class delivery requires the session's reader set to cover the item's `readers` label (ADR-0034); the leak battery LT-01…12 (ADR-0059) applies to the surface's responses.

**F7 — The permission prompt is the one place a surface *writes* authority, and the audited surfaces route it server → client as a request with typed options.** Codex `item/commandExecution/requestApproval` / `item/permissions/requestApproval` (server-initiated, with `availableDecisions`); goose and OpenHands equivalents; ACP `session/request_permission` (ADR-0098). H7 fixed the record: durable `security.permission.pending`, ephemeral `requested{rendering}`, one `ApprovalResponse` per `permission_id`, `decider.kind = human` with `responder_provenance`, batches by class, the never-auto set, leases with fingerprint invalidation, async suspension with wakeup. The opencode client-side auto-accept (F1) is the anti-pattern: a widening the monitor never sees. **Implication:** the inbox renders pending records and calls `respond`; every "always" is `allow_lease` (ledgered, scoped, expiring); the surface never batches `irreversible` items and never offers an option outside `ApprovalRequest.options[]`.

**F8 — Dashboards are where the LCD trap re-enters by rendering.** HAL's leaderboard shows no intervals (WS-J4 F1); Inspect's `evals_df` carries one headline number; every audited plane sorts point estimates. WS-J4 A9/A16 and WS-J5 L2/L5 already require rank *sets*, `n/a{reason}` cells, class strata and `report_id` citations. **Implication:** the web dashboards are renderers of `AnalysisReport`/`LeaderboardSnapshot` with a small set of *rendering invariants* (§6.3) that are acceptance-tested: `n/a` never blank or zero; no total order over overlapping intervals; every number links to its `report_id` and `computed_from[]`; factor coordinates always visible (T-LCD-09).

**F9 — "Trace visualization" in the 2026 literature is a *view compiler over one lossless record*, not a second store — and none of it is a time-travel debugger.** VCC lowers one JSONL log into Full/UI/Adaptive views with pointers back to the full view's coordinates; TraceView and SeaView are overview-to-detail drill-downs over trajectory files; AgentDebugX ships the same loop as CLI + web console + skill; zero-replay debugging ranks branch points from the trace without re-execution. None fork, restore an environment, or show replay validity; Harness-Bench and Shepherd describe no viewer at all. The mature time-travel precedent is the omniscient-debugging line (TOD): index the whole trace on disk, support partial traces, guarantee interactive query time. **Implication:** the viewer's novelty claim is confined to *rendering the B4 branch model with replay validity and the D1 context view at any seq* — the rest is precedented, and the acceptance criteria are drawn from TOD's requirements (random access by seq, filtered reads, bounded query latency on long runs).

## 5. Disconfirming evidence & negative results

**Against building a web surface at all at C2 ("the CLI plus a trace file is enough; every product surface here is a large-team investment").** Managed Agents and Symphony expose no local UI; Harness-Bench and Shepherd ship no viewer; Inspect's viewer is the only research-tool viewer audited and it is read-only. *Why it does not overturn:* R-2.11.2 is sponsor-named (Could, C2); the recommendation is deliberately a **thin projection client** whose every view is a rendering of a record another workstream already ratified — no view computes, stores or decides. The C2 slice (§6.6) is the read-only viewer + inbox + report renderer; the interactive assembly editor and time-travel *operations* are later stages. If the surface is never built, nothing upstream changes (the contracts are owed to K1 anyway).

**Against "token required even on loopback" (Inspect allows unauthenticated loopback; Codex's loopback listener needs no token because browsers cannot connect).** *Why it does not overturn:* Codex achieves loopback safety by rejecting every browser (`Origin`) request — impossible for a *web* surface; Inspect's viewer is read-only over log files and still narrows access to one directory. Our surface can `respond` to approvals, `fork`, `register` experiments and `apply` definitions — the CVE-2025-49596 precondition (a browser-reachable local endpoint that can start processes). Jupyter and the MCP Inspector fix both require the token on loopback. The cost (a token in the launch URL fragment / shell handoff) is one paste.

**Against fetch-metadata and Origin checks ("DNS rebinding is mitigated by Host validation alone; Chrome's LNA will make this moot").** Host validation defeats rebinding but not CSRF from a page that already runs on an allowed origin (e.g. another local dev server on `localhost:<other port>` is a *different* origin but a loopback host); LNA is one browser, ships gated by a permission the user may grant, and does not cover same-host different-port pages. *Why it does not overturn:* the checks are cheap and layered (Inspect implements all three); P3/P4 keep exact-origin semantics (host **and** port), which is why opencode's `startsWith("http://localhost:")` allow-any-port rule is listed as a counter-example.

**Against rendering `n/a`, rank sets and report hashes everywhere ("users want a number and an ordering; the dashboards will be unreadable").** *Why it does not overturn:* ADR-0045/0047/0013 and WS-J4/J5 already fix these as data invariants; the surface merely must not *undo* them. Chatbot Arena's practice (Tier A, via WS-J4) shows rank sets are accepted; sorting *within* a set by point estimate is permitted by J5 provided the set boundary is rendered.

**Against a tree-with-HEAD viewer ("transcripts are linear; branches confuse users").** Codex, OpenHands and Pi all ship branch/fork/rollback in their session models (WS-B1 F4); LangGraph Studio ships fork-from-checkpoint. *Why it does not overturn:* the default rendering is the HEAD path (linear); discarded subtrees are folded and appear only when a `head.moved`/`branch.disposed` event exists at that point.

**Against reusing the ADR-0050 generated client for the web surface (OQ-130) ("a browser client needs a different transport than a subprocess/JSON-RPC client; the verb set lacks the reads a UI needs").** Both halves are true and neither narrows Q-L1-14: (i) ADR-0050 D1 row 4 already names the surface boundary as "(b) localhost HTTP/WebSocket exposing the same verb set + `stream_events`; (c) a generated client from the kernel's schema source"; every audited surface (Codex app-server clients, OpenHands `clients/`, opencode `packages/sdk`) is such a generated client; (ii) the missing verbs are a *contract gap* (CF-359: `read/project/subscribe` by view kind, branch operations, `respond`, audit proofs, Lab operations) that WS-K4 must fill from the kernel's schema source — the same gap WS-J1 flagged for assembly verbs (CF-322). No view in §6.1 needs in-process access to kernel state. OQ-130 is therefore answered *confirmed, no narrowing* — in contract terms only; the ecosystem binding itself is executed by ADR-0050's declared default and is not re-argued here (ADR-0050 §8).

**Negative results.** No audited surface renders a replay-validity or replay-mode indicator — `no-precedent` (the LangGraph docs warn in prose instead). No audited surface shows *which rule/capability* produced an event (an `ir_refs[]` link) — `no-precedent`; ADR-0027 stamps `ir_refs[]` so it is computable. No audited surface displays `n/a` as a typed value — `no-precedent`. No audited surface requires the token on loopback *and* validates Origin *and* fetch metadata *and* keeps tokens out of URLs — each is implemented somewhere, none everywhere (the posture is a union, not a copy). Harness-Bench and Shepherd — the brief's "trace visualization" anchors — describe no visualization.

## 6. Recommendation for the spec

### 6.0 Position

1. **The web tooling is a pure projection client.** It holds no state of record; every view is `project(run | rows | records, view_kind, until)` rendered with its `derived_from` watermark / `view_hash` / `report_id` visible; every write is a typed kernel or Lab operation carrying `provenance.origin = human(author_ref, role)` and a surface-session reference; nothing on the far side computes a metric, resolves an assembly, decides a permission, or samples the ledger (ADR-0026, ADR-0042, ADR-0050 D2, WS-J4 A16 "render never recomputes").
2. **One record, two surfaces.** The CLI (WS-K1) and the web surface render the same records through the same generated client; a view exists in the catalogue only if its data contract is a ratified record type. Anything the web surface can show, the CLI can print (possibly less prettily); anything the web surface can do, the CLI can do.
3. **Time travel is scrubbing plus B4.** *Scrub* = `project(run, view, until_seq)` for any coherent or incoherent seq (pure; nothing runs). *Fork/rollback/discard/promote/replay* = the ADR-0133–0135 operations, invoked with human provenance, rendered with `replay_mode`, `ReplayValidityReport.mode`, `env_binding` and the speculation policy visible **before** confirmation.
4. **The surface is a sink and a principal channel, not an authority.** It receives content under a `SinkPolicy` scoped by the session's reader set (ADR-0044/0034) and it carries a human's decision to `respond` (ADR-0070); it never widens anything on its own.
5. **Local security posture is a floor, encoded as acceptance tests** (§6.4, ADR-0172): loopback bind, per-launch capability token on every request, exact Host/Origin allow-lists, fetch-metadata checks on mutations, tokens never in URLs, no LAN advertisement, no far-side decisions, audit of every surface-initiated write.
6. **C2 is the read-only instrument plus the two things unattended runs need** (inbox, launcher progress); editing and time-travel *operations* are Stage 5+ (§6.6).

### 6.2 The time-travel viewer's requirements on WS-B1 / WS-B4 (and what is already satisfied)

Language-neutral requirements the ledger and branch contracts must meet for V3 to be a pure client. "sat." = satisfied by a ratified ADR as written; "req." = requested (CF/OQ in §7–8).

- **R-TT-1 Random access and reverse scan by `seq`** (TOD; Codex reverse scanner). sat. ADR-0026 `read(cursor{from_seq | from_event_id}, direction fwd|rev, limit)`, storage property 3.
- **R-TT-2 Filtered reads by plane / class / scope / `ir_refs`** so a 10⁵-event run can be navigated by "all permission decisions", "everything in this tool call", "every event this rule touched". sat. for `{plane, class, scope}` (ADR-0026 `read.filter`); **req.** `ir_refs` as a filter key and a rebuildable index over it (derived view; CF-360).
- **R-TT-3 Projection at an arbitrary `until_seq`** — `project(run, context_view | effect_ledger | cost_view | trace_view, until_seq = s)` for *any* durable `s`, so scrubbing is pure and "what did the model see" is the D1 view whose `view_hash` matches `context.assembled.view_hash` at that call. sat. ADR-0026 `project(run, view_kind, until?)`; the equality is AC-K2-3.

- **R-D-2** No view renders a "harness score" or "model score" without its factor coordinates (`model snapshot(s) with roles, harness at granularity, environment image + profile, task/split, budget vector, replicate index`) visible or one click away (T-LCD-09).

### 6.4 Local security posture (the floor; ADR-0172)

Threat model (stated per §3.3 (d)): **T1** drive-by browser attacks on a loopback service (DNS rebinding, CSRF, malicious ads — CVE-2025-49596); **T2** LAN exposure when bound off-loopback or advertised; **T3** other local users/processes on a shared host; **T4** the surface acquiring authority it should not have (widening on the far side; ambient credentials; replayed approvals); **T5** secret or content leakage through the surface's responses, exports and logs; **T6** a compromised or spoofed surface process feeding the kernel (out of scope beyond the token and the ledgered human provenance — the kernel's monitor still evaluates every proposal; ADR-0052).

Posture rules (each is an acceptance test in §6.5; precedents in §4c):
- **P1 Loopback by default.** The surface's server binds a loopback address and an ephemeral or configured port; off-loopback binds are an explicit, logged choice (MCP spec SHOULD; Inspect; Codex; goose; gemini devtools).
- **P2 Capability token on every request, including loopback.** A per-launch random token (≥ 128 bits of entropy) minted by the launcher, delivered out of band (launch URL fragment, environment of the spawning shell, or a mode-0600 file); constant-time comparison; missing/invalid → 401 with no body detail (Jupyter; MCP Inspector fix; Codex non-loopback; goose). A host-local socket with owner-only permissions is an admissible alternative transport for non-browser clients (Codex 0600 control socket).
- **P3 Exact Host and Origin allow-lists.** The `Host` authority must match the bound authority (host **and** port); browser requests must carry an `Origin` exactly in the allow-list (the served UI's own origin by default; desktop-shell origins only when registered at launch; `null`/opaque origins rejected; wildcard refused) (Inspect; goose; MCP spec MUST; opencode's any-port loopback rule is the counter-example).
- **P4 Fetch-metadata and header checks on mutations.** Any operation that writes (`respond`, `fork`, `apply`, `register`, `redact`, `submit`, …) requires `Sec-Fetch-Site ∈ {same-origin, none}` (when the browser sends it), `Sec-Fetch-Dest: empty`, and a custom request header the browser only sets from script (Inspect `_validate_mutating_request`); simple-form POSTs are refused.
- **P5 Off-loopback requires both auth and explicit trusted origins;** a wildcard bind without them refuses to start; an explicit `unsafe` acknowledgement is the only override and prints a warning on every start (Inspect; Codex "refusing to start non-loopback websocket listener … without auth"; goose `--dangerously-unauthenticated`).
- **P6 No discovery advertisement by default** (mDNS/LAN announcement is an explicit, off-by-default option and implies P5) — opencode is the counter-example.
- **P7 Response hardening:** `frame-ancestors 'none'`, a content-security policy that forbids inline script and third-party origins for the served UI, no caching of API responses, no referrer leakage of tokens (Inspect `SecurityHeadersMiddleware`).
- **P8 The surface is a sink.** It declares a `SinkPolicy{content_classes, redaction, max_field_bytes, requires_consent}` (ADR-0044); `content`-class items are delivered only when the session's reader set covers the item's `readers` label (ADR-0034); `SecretRef` values never appear (SV-1…10, ADR-0057); exports pass through J5/H6 lowering with redaction and a loss report; every delivery to the surface is `measurement.export.delivered` (so audit knows what the human saw — H6 correlation rule 5).
- **P9 Tokens never in URLs or logs.** Bearer/authorization header or first-message websocket auth (OpenHands); query-string tokens are refused (goose's `?token=` is the counter-example); server logs redact authorization headers.
- **P10 No far-side decisions, no ambient credentials.** The surface calls `respond` with a human's decision under an authenticated surface session; the kernel records `decider.kind = human`, `responder_provenance{surface_session_ref}` and evaluates authority (`IllegitimateEndorsement` for a responder below `principal` without an `ApproverGrant`); "always" is `allow_lease` (ledgered, scoped, expiring, fingerprint-invalidated); the surface holds no provider credentials and cannot mint permissions (opencode's client-side auto-accept is the counter-example).
- **P11 Desktop shells and remote access.** A packaged shell that embeds the surface pins the local server's certificate fingerprint or uses a host-local socket (goose); remote access is by SSH port-forwarding (Inspect, Codex note), never by opening the bind (P5) — a hosted, multi-user mode is out of scope (§6.6).
- **P12 Every surface-initiated write is ledgered with human provenance** (`origin = human(author_ref, role)`, surface session ref, request id), so the audit view can list what the surface changed; surface *reads* of content are `measurement.export.delivered` rows (P8).
- **P13 Same-origin UI.** The UI is served by the same local origin as the API it calls, so browser local-network permissions (Chrome LNA) are not needed and a public-origin UI reaching a local kernel — the pattern LNA blocks — is not the design.

Boundary placement (ADR-0050 §8 clause 4): the web surface's server is a process on the **surfaces side** of the kernel↔surfaces boundary; it terminates the browser session (P2–P9) and speaks the §6.5 verb set + surface verbs to the kernel/Lab as a generated client. The kernel's raw transport keeps its strict profile (Codex: browsers cannot connect to it).

### 6.5 Acceptance-criteria sketch

- **AC-K2-1 No state of record.** Clear every client-side store; every view re-renders byte-identically from `read`/`project`/`query_rows`/`render` at the same watermarks; no operation exists on the surface that mutates a record without a kernel/Lab call.
- **AC-K2-2 Render parity.** For a fixture `AnalysisReport`/`LeaderboardSnapshot`/`ValidationReport`, the rendered values equal the record's; `n/a{reason}` cells render the reason (never `0`/blank); indistinguishable sets are drawn; `report_id`/`view_hash` visible (R-D-1…8).
- **AC-K2-3 Scrub equality.** For every `context.assembled` event in a Stage-3 run, `project(context_view, until_seq = that seq).view_hash` equals the event's `view_hash`; the viewer shows the same items the model received.
- **AC-K2-4 Rewind handling.** On `head.moved`/`rolled_back`/`branch.disposed{discarded}`, the rendered path switches to the new HEAD, the discarded subtree remains reachable and marked, and the rewind note appears at the next assembled context.
- **AC-K2-5 Reconnect.** Kill the connection mid-run; on reconnect the client replays from its cursor, dedupes by `seq`, and its durable event list equals `read(run)`; ephemeral frames are absent from any persisted client state.
- **AC-K2-6 Security battery.** (a) request with foreign `Host` → 400; (b) request with an `Origin` outside the allow-list, `null`, or `Sec-Fetch-Site: cross-site` → 403; (c) missing/invalid token → 401 on loopback too; (d) token in query string → refused; (e) simple-form POST to a mutating route → 403; (f) off-loopback bind without auth+origins → refuses to start; (g) LT-01…12 leak fixtures (ADR-0059) produce no secret bytes in any surface response or export; (h) `X-Frame-Options`/`frame-ancestors` present; (i) a DNS-rebinding simulation (correct IP, wrong `Host`) fails at (a).
- **AC-K2-7 Approval round trip.** A pending request renders only its `options[]`; a never-auto item shows no lease option; a batch of N renders one prompt and produces N `security.permission.decided` events; a response from a responder below `principal` without a grant yields `IllegitimateEndorsement` and no effect proceeds; an exhausted `approvals.requested` budget renders the single `amend | stop` prompt; a decision made from the CLI shows as `AlreadyDecided` in the inbox.
- **AC-K2-8 Launcher refusal parity.** Every WS-J3 registration refusal renders as a typed error; no surface path opens a run outside an experiment (the ad-hoc run is an `exploratory` one-cell experiment and is labelled so).
- **AC-K2-9 Assembly plan parity.** The plan the editor shows is byte-equal to `assemble(source, snapshot, plan)`'s `report`/`plan`/`identity`; a widening diff requires and records human attestation; `explain(path)` names the layer.
- **AC-K2-10 Audit deep link.** Any rendered `audit_ref` verifies through `verify_inclusion`; a tampered fixture renders `Tampered{kind}`; the surface's own reads appear as `sink_deliveries` in `audit_view`.
- **AC-K2-11 Time-travel operations.** `fork` from the viewer at an incoherent seq returns `ForkPointNotCoherent` with the open scopes listed and offers the nearest coherent points; the created branch shows its `replay_mode` and validity verdict; `deterministic` is offered only for a declaring variant with `model_io`; `discard` renders `compensated[]`/`uncompensable[]`.
- **AC-K2-12 Class scoping.** A hosted run at `observability_level = {events}` renders `n/a{observability}` for content tabs and `n/a{class}` for component-level analyses; badges present on every row (T-LCD-15/-07).
- **AC-K2-13 Query latency (with B1).** `read(filter)` and `project(until_seq)` on a 10⁵-event fixture return within a bound proportional to the result size, not the run length (R-TT-9; the bound is OQ-388).
- **AC-K2-14 One record, two surfaces.** For every view in §6.1, the CLI (WS-K1) can print the same record from the same operation; a fixture diff between the two renderings shows only presentation differences.
