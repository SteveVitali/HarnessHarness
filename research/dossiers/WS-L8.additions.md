## Ontology terms

| term | definition | notes |
|---|---|---|
| work item | The durable organizational object binding a HIR `Goal` to sources, an accountable human owner, a kernel state and the chain of activations that execute it; a runtime record in a fleet run's ledger, never an IR entity. | WS-L8 · ADR-0205 |
| work-source binding / work-source adapter | A binding `{source_ref, native_id, native_ref?: ext, kind, role ∈ {origin, mirror, subscription}}` to an external system of record; the adapter is a registered out-of-process component with tri-state capabilities and a two-operation read minimum (`list`, `get`); writes are never adapter operations of the reconciler. | Symphony `tracker.ex` shape; T-LCD-07 |
| desired vs observed work state (`spec` / `status`) | `spec` = what the source says the organization wants (authority ≤ external; rewritten only on `spec_hash` change); `status` = what the ledger shows (a projection). The source is authoritative for intent, the ledger for fact. | Kubernetes spec/status; resolves CF-442 |
| work-item state map / human-gate state | MUST-data rows mapping normalized source states to kernel `WorkItemState` with `human_gate`, `entry_allowed_by`, `exit_allowed_by`, `terminal`; a human-gate state is one whose exit is a human act; skipping one is denied at Π by a narrowing leaf on the lifted write capability's `ActionPattern`. | ADR-0206 decision 3 |
| handoff (state) | The work-item state in which an activation is correctly waiting on a human (review, approval, merge decision); never stalled; exited only by a legitimate human act. | ADR-0206 |
| blocked (work item) / block reason | An abnormal condition with a closed `BlockReason` and an escalation; distinct from `handoff` and from a stalled activation. | Symphony `blocked` map generalized |
| fleet run / fleet reconciler / fleet policy | The run (`run_kind = fleet`) whose ledger holds work items and reconciler decisions; the level-triggered component that reconciles desired vs observed state before every dispatch; the MUST-data policy `{state_map, escalation_policy, scheduling, trigger_rules, cascade}`. | ADR-0205/L8-2; ADR-0155 shape |
| work-item claim | The `resource(work_item_id)` lease guaranteeing at most one activation per item. | ADR-0130 scope; RC-2 |
| owner (accountable principal) / owner-as-principal | The single human `PrincipalRef` accountable for a work item; the `principal` of every activation of that item; issuer of every `ApproverGrant` used on it; first escalation target. | ADR-0207 O-1…5; SRE incident commander |
| ownership handoff (acknowledged) | The two-event transfer `owner_changed → owner_acknowledged`; dispatch blocked and leases revoked in between. | SRE "firm acknowledgment of handoff" |
| owner reference / cascade policy | `owner_ref{parent, block_parent_completion}` forming a fleet-local forest of work items; `CascadePolicy ∈ {foreground, background, orphan}` on parent cancellation. | Kubernetes owner references |
| escalation policy / escalation target / escalation chain / escalation cause | MUST-data ordered targets `{ref, after_ms, on, evidence}` with `final` and `max_open_per_owner`; each notification a budgeted `message_human` effect; `EscalationCause` is the closed extension of ADR-0066's obligations; resolution only by a legitimate responder. | ADR-0207 E-1…8 |
| accountability record | The projection of a work item's owner history, activations, decisions, external effects, escalations, handoffs, budget and audit completeness — every element an `EventRef`; verified through chains and the fleet anchor. | ADR-0207 decision 2 |
| fleet view | The `project`-pure `FleetView` record (items, capacity, escalations, totals by owner/source/state, watermark) surfaces render; nothing sampled. | ADR-0207 decision 4 |
| irreversibility ceiling | An optional hard ceiling on the owner pool's `effects.external_irreversible` counter; exhaustion denies the marginal effect at `reserve` and escalates; the unit-priced form of fleet risk admission control. | S-626 shape; pricing deferred |
| org-policy comparison (`lab/org-policy-v1`) | The recipe comparing state maps, unattended policies, escalation chains and activation caps under a `MatchSpec` over approvals, human wait, spend and `message_human`; the removal test for every fleet default. | ADR-0207 decision 6 |
