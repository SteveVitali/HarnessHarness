## 1. Scope & boundary

This workstream decides **how the reference runtime turns a set of candidate items — instructions, transcript history, retrieved memories, tool results, artifacts, procedures/skills, budget reminders — into the typed, ordered, provenance-preserving working set that one model call sees, under a token budget, without ever changing what any item is allowed to command.** Concretely it fixes: (a) the **builder contract** — inputs (a candidate set whose every member carries the ADR-0033 provenance record, a declared validity, a token estimate and a retention class; the window cap and reservations; the Model Profile; the resource account; the ledger's context view), outputs (a `ContextPlan`: ordered, slot-typed, with omissions and a `context_label`), and invariants; (b) the split between a **kernel admission** step that is not pluggable and a **selection policy** component class that is — the C0 trivial builder is the kernel plus a fixed default policy, the C1 family is the same kernel with policy variants; (c) the **slot model** through which layout and provider roles are delegated to the Model Profile (ADR-0020/ADR-0034 `role_map`) while the builder enforces the role-placement invariant; (d) the **offloading and just-in-time contract** — how large observations become content-addressed handles with excerpts, how handle-only candidates support progressive disclosure, and how nothing re-enters at higher authority; (e) the **assembly bug class** (context-privilege escalation, S-103/S-104) as a set of admission invariants and executable privilege-preservation tests; (f) ownership of run-time transcript rendering (OQ-063) and the context-label reset semantics (OQ-105); (g) the `context.assembled` payload the builder emits and the T-LCD-13 `context.artefact.delivered` events.

It explicitly leaves to neighbours: **WS-D2** — the compaction strategy family (what to summarize/evict; this dossier fixes only the trigger interface the builder raises, `CompactionRequired`, and the label rule summaries must obey via ADR-0034 P1); **WS-D3** — retrieval and the memory hierarchy (which candidates are *proposed*; this dossier fixes the admission checks every proposed candidate must pass again); **WS-D4** — validity/supersession records (consumed through `validity(item, now)`); **WS-C3** — the layout, `role_map`, transcript-renderer rule inventory and demotion wrappers (this dossier fixes what a slot declaration must contain and that the builder executes the compiled renderer spec); **WS-C1** — transport (the gateway receives rendered messages as data, CF-044); **WS-E3** — which compiled tool surfaces are revealed this turn (`select_surfaces`; the builder admits what E3 reveals as `tool_surface` candidates); **WS-H1** — the reference monitor that reads `context_label` (ADR-0035 checks); **WS-F2** — the control envelope that owns hard budget exhaustion (the builder refuses; F2 decides what happens next); **WS-B1** — the event envelope (this dossier proposes payload extensions only); **WS-I2** — the `opacity_dynamic` metric computed from `context.assembled`.

1. 3. (Phase 1 hand-offs) OQ-063 — who executes the compiled transcript-renderer spec; OQ-105 — context-label reset across compaction, turns and isolation, and whether a quarantine slot exists; OQ-084 — inline vs blob storage of `context.assembled.items`; OQ-080 — may the builder read inline observations without a blob round-trip; OQ-058 — ablation semantics of `Text` leaves; OQ-067 (with D2/C2) — re-lowering policy for profile-opaque transcript items; OQ-101's read-only/closed exemption input.

6. (added) Is ordering within the window a model-conditioned surface (a profile rule with an expiry) or a stable semantic property — what does the position-effect literature say?

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Every audited builder is a slot-and-projection machine, and the slots already carry the attributes the contract needs — except authority.** Codex renders 54 typed fragment kinds through one trait (`role`, `content_kind`, `requires_separate_message`, `markers`, `body`) and persists a stable `content_kind` such as `token_budget.context_window` or `memories.instructions` on every model-visible item; OpenHands assembles system prompts from `PromptSection{name, cache_tier, guard, render}` into exactly two blocks (`static`, cache-stable; `dynamic`, per-conversation) and derives the transcript as a projection of the event tree with invariants enforced to a fixpoint; browser-use keeps three fixed slots (`system`, `state`, `context[]`) and rebuilds `state` from the world every step; Pi projects the session tree to "last compaction + tail". Each of these has *kind*, *position/tier*, *cache tier* and *truncation policy* on an item; **none has authority** on it — the same negative result WS-L3 F5 recorded from the security side. **Implication:** the builder contract is a small extension of shapes that exist (slot declarations with kind, cache tier, cardinality, budget class) plus the one field the audit shows is missing (`min_authority` on the slot, `authority` on the item) and the one check none performs (role-placement, ADR-0034 RP). This is implementable at C0 without novel machinery.

**F2 — Content acquires model-facing privilege by *location* and by *role* in every audited system; the kernel admission step must refuse exactly these two moves.** Codex renders `MemoryContextFragment::ReadInstructions` at role `developer` and injects AGENTS.md as `developer` items (WS-L3 F5; `session/inject.rs` marks `client_authored` developer messages but does not label content); OpenHands' `load_project_skills` makes "resolved project skills … authoritative: a project skill overrides a same-named skill already present", and `RepoContextSection`/`MemoryContextSection` defend only with a `<UNTRUSTED_CONTENT>` **text banner** inside the system block; AIOS `ContextInjector` prepends retrieved memories "as a system message at index 0" after a relevance threshold only; browser-use marks `compacted_memory` "Treat as unverified context" in text. Codex is the only system with a *structural* defence: `load_project_instructions` returns no project docs when `active_project.is_untrusted()`, and `is_api_message` never retains raw `system`-role items from the API. S-103's 282 sources and S-104's 13/13 objectives are the `provisional (mech)` confirmation that banners are not enough; the ratified scheme (ADR-0033 option 4 rejected "monitor reads the model-facing text") already says the defence must be a record, not a string. **Implication (§6.2 I-RP, I-SLOT):** admission is a function of `(authority(item), slot.min_authority, role_map)` and nothing else; a builder that would place a lower-authority item into a higher slot returns `Omission{reason: authority}` or a profile-declared demotion, never a promotion — and the text banners become optional profile-owned *surface* decorations of an already-correct placement, not the defence.

**F3 — Required-versus-optional retention with priority eviction, and reserve-before-select, are the production budgeting discipline; whole-item eviction with a bounded omission notice is preferred to partial truncation of required items.** Codex's guardian context types every content item as `Budgeted{required | optional(BudgetPriority ∈ {Commentary, Tool, Image})}`; `enforce_budget` first removes optional items that cannot fit at all ("without evicting useful smaller entries on its behalf"), then evicts by `(priority, age)`, refuses with `EvidenceLimitExceeded` if the required set alone exceeds the budget, and inserts a `budget_omission` notice whose text says "omissions do not authorize actions"; `input_budget.rs` reserves the serialized cost of the time and rollout-budget reminders "before choosing optional evidence" and treats the framing cost of every user input as required. Pi truncates tool outputs by two independent limits (2000 lines / 50 KiB) and returns a typed `TruncationResult`; Codex applies a per-tool `TruncationPolicy` at *record* time so history never holds an unbounded payload; OpenHands' memory loader gives each tier a fair share of a 6000-char budget and truncates from the top; browser-use hard-truncates the DOM at 40 000 characters and keeps `first item + omitted marker + last N` history items. **Implication (§6.3):** the C0 builder carries `retention ∈ {required, optional(priority)}` on every candidate, reserves kernel-mandated items (soft-budget reminders from ADR-0040 `advise`, current-time, omission notice) before optional selection, evicts optional items whole by a declared priority order, never truncates a required item, and refuses (`ContextWindowExceeded`) when the required set alone does not fit — which is the `context.occupancy` gauge cap refusing the next increment (ADR-0040 E5, `CompactionRequired`) rather than a run stop.

**F4 — Structural invariants of the transcript are enforced as declared properties with a fixpoint, and the cut points for eviction/compaction are derived from those properties.** OpenHands: `ToolCallMatchingProperty` ("exactly one observation-like event for each action `tool_call_id`"), `BatchAtomicity`, `ToolLoopAtomicity`, `ObservationUniqueness`, each with `enforce` and `manipulation_indices`; `View.manipulation_indices` is the intersection and the summarizing condenser starts forgetting at the first manipulation index ≥ `keep_first`. Codex `normalize_history` enforces the same pairing ("every call has a corresponding output"; orphan outputs removed) and strips media the model cannot accept. Pi's `findCutPoint` cuts only at turn boundaries and excludes aborted/errored assistant messages from context. **Implication (§6.2 I-PAIR, §6.6):** pairing, atomicity and media-support are *kernel* invariants of the `ContextPlan` (a plan violating them is invalid, never silently fixed at the gateway), and the set of legal cut indices is exported to D2 so compaction variants cannot produce an invalid plan.

**F5 — Steady-state diffing of world state is a real, novel-in-production mechanism that trades reinjection tokens for staleness risk, and it is model-conditioned.** Codex `WorldStateSection{ID, Snapshot, render_diff(previous ∈ {Absent, Unknown, Known})}` re-renders a section only when its snapshot changed, hashes the model-visible fragment (`WorldStateHash`) and falls back to "full reinjection" when a mixed bundle was trimmed by rollback (`trim_pre_turn_context_updates`); OpenHands puts the same knowledge into cache tiers (`STATIC` vs `DYNAMIC` block) instead. **Implication:** "diff vs reinject" is a *selection-policy* choice over a declared slot (`cache_tier`, `diffable`), not a kernel behaviour; the kernel must make it *safe* — the plan records which sections were delivered by reference to an earlier delivery (`derived_from = projection`, `delivery_id` of the previous render) so T-LCD-13's `delivered` remains computable when a section is *not* re-sent.

**F6 — Offloading is converging on one shape: full payload content-addressed outside the window, a bounded excerpt inside, a handle the model can read on demand.** Cursor writes long tool outputs, terminal sessions and MCP catalogs to files and gives the agent `tail`/grep/read; Anthropic's tool-result clearing removes raw results "deep in message history"; programmatic tool calling keeps intermediate results out of the window entirely; Codex truncates at record time and keeps `WorldStateItem{full, state}`; Pi keeps `retainedTail` on the compaction entry; OpenHands `Condensation{forgotten_event_ids, summary}` forgets in the projection while the log keeps everything (ADR-0029 already offloads `context.observation.recorded` above 64 KiB). **Implication (§6.4):** offload is one contract with three parts — `OffloadHandle{content_address, media_type, size, label, retrieval_capability}`, an *excerpt policy* (head/tail/lines/bytes, declared per tool surface by the profile's `result_render` rule), and a *closed-world read* (the handle is readable only through a declared `ToolCapability` in the sealed definition, so the read is an effect the monitor sees). The excerpt and the handle carry the *same* label; a later read re-enters at that label (ADR-0034 P7 lifting rule: never higher).

**F7 — Just-in-time context is a candidate *state*, not a different builder.** Pi and OpenHands render skills as name/description/location and load the body on demand; Anthropic's `defer_loading` and Cursor's synced catalogs do the same for tools; Anthropic frames the general principle as "lightweight identifiers … progressive disclosure". **Implication:** every candidate is `handle_only | expanded`; expansion is an *effect* (a read through a declared capability for artifacts/skills, `select_surfaces` for tools — E3) that produces a new, expanded candidate with its own delivery; the kernel treats the index line and the body as two items with one `artefact_id` and two `delivery_id`s, so compliance (`activated` = the body was requested) becomes observable exactly as ADR-0014 wants (OQ-049: skills/tool surfaces have deterministic activation).

**F8 — Ordering within the window is a model-conditioned surface with Tier-A evidence, so it belongs to the profile as a conditioned rule with an assumption-debt record, never to the kernel.** Liu et al. (S-335, TACL 2024) show a U-shaped position effect; Chroma (S-336, 18 models) shows non-uniform degradation with length, distractor sensitivity that differs by provider, and the counter-intuitive finding that *shuffled* haystacks outperform coherent ones; OpenHands encodes the folk rule "the later position gets more model attention" in code; Codex places reminders as separate `developer` messages at the tail. **Implication (§6.5):** the kernel fixes only *partial* order (slot precedence declared by the profile layout; within a slot, the policy's declared comparator); every "put X last" or "reminder at N tokens remaining" is a `ProfileRule{kind: prompt_layout | compaction_reminder}` with a debt record (ADR-0020), deletable by the Lab (T-LCD-05).

**F9 — The C0 trivial builder already exists in every audited system as the degenerate case of the same machine.** Browser-use (`system + state + context[]`, rebuilt from state), Pi (`last compaction + tail`), and mini-SWE-agent-class loops all reduce to: fixed slots in declared order, required items, a recency tail, per-tool truncation, no retrieval. That is the Stage 0 baseline of doc 2 §11 and the T-LCD-03 anchor. **Implication (§6.7):** the C0 deliverable is the *kernel admission* (invariants) plus a `default` selection policy; every richer behaviour in F3/F5/F6/F7/F8 is a variant of the same `ContextPolicy` class with the same contract (T-LCD-08: the variant receives the profile and the account).

**F10 — Redaction and sensitive-value handling happen at the slot boundary, not in the model.** Browser-use `_filter_sensitive_data` rewrites the `state` message (the only slot that can contain action results); OpenHands advertises secret *names* and masks values in output. **Implication:** `readers` (ADR-0033 C2 component) is carried on every candidate at C0 and *checked* at C2 (WS-H2); the builder's slot boundary is where a `readers`-filter or redaction projection (`deriver = kernel`, ADR-0034 P1) is applied — the hook exists at C0 even though enforcement is C2.

## 5. Disconfirming evidence & negative results

**Against a kernel/policy split at all ("just give the policy the whole message list").** Pi's only hook is `transformContext(messages)`; OpenHands' condenser returns a whole `View`; browser-use rebuilds everything in one class. A full-list hook is simpler and is what three of five systems ship. *Why this does not overturn:* a whole-list hook is precisely where S-103's assembly bugs live — nothing stops the transform from moving a tool result into the system block. The split costs one data structure (`ContextPlan`) and gives the monitor a record to read (ADR-0035 "reads records only"), the Lab an ablatable unit (T-LCD-02), and D2 a legal-cut-point set. The policy still sees the whole candidate list; it loses only the ability to change slots' authority, which is the point. The cost is measured (`assembly_ms{measured_at}`, CF-092) not hidden.

**Against `min_authority` slots: they will starve the model of useful content.** Under RP, discovered AGENTS.md files, project skills and agent-written memories all land at `external` and can only be rendered into roles ≤ `role_map(external)` (typically the `user`-quoted or `tool` role), which may reduce compliance with legitimate project conventions — OpenHands deliberately makes project skills authoritative. *Why this does not overturn:* the scheme provides the legitimate path up — `seal` (author places the file in the definition), `pin` (WS-H5 attestation), `promotion` (human review) — each a ledger event; the Codex precedent already refuses project docs for untrusted projects, i.e. production accepts a stricter rule than this one. Whether `external`-role delivery lowers *compliance* is exactly the T-LCD-13 measurement the Lab exists to make (AC-D1-12); the design makes the trade visible instead of silently unsafe.

**Against required/optional whole-item eviction: partial truncation keeps more signal.** Cursor's `tail` + read is strictly more informative than dropping an item; OpenHands truncates memory line-wise rather than dropping a tier. *Why this does not overturn:* the contract separates the two mechanisms — **excerpting** (§6.4) is applied at *record/offload* time to produce a bounded candidate with a handle, so what the eviction step sees is already bounded; eviction then removes whole *bounded* items in priority order. Truncating a *required* item is still forbidden because a partially delivered instruction or permission ceiling is worse than a refusal (Codex `retained_context.rs`: "An omitted payload records incomplete evidence, rather than keeping a partial grant").

**Against deterministic assembly: token counts are not deterministic across hosts, and provider-side caching makes byte layout performance-relevant.** Codex estimates tokens from bytes (`estimate_item_token_count`), Pi from characters (`ESTIMATED_IMAGE_CHARS = 4800`); the real count is only known after the call (`model.call.completed.usage`). *Why this does not overturn:* determinism is required over *declared inputs* — the plan hash is over `(view watermark, candidate ids, retention, estimates as recorded, budget, profile hash, policy params)`, and the estimate is itself a recorded input with a `estimator_ref` (the profile's tokenizer or declared proxy, ADR-0015 opacity convention). Two hosts with the same estimator produce the same plan; a different estimator is a different profile version. Cache-relevant byte order is the renderer spec's business (ADR-0019 array-order rule), not the plan's.

**Against the closed-world rule for context: exploratory agents produce content nobody compiled.** Every tool result, every model message, every retrieved memory is "uncompiled". *Why this does not overturn:* the closed-world rule requires a *compiled identity or a ledger content address* — run-time observations have `version_id = H(canonical(observation))` on `context.observation.recorded` (ADR-0029), memories have `semantic_id`/`version_id`, model messages have `model_call_id`; the rule refuses only items with *no* identity (an ad-hoc string assembled in code), which is exactly the untyped-blob failure T-LCD-02 targets.

**Against handle-only (JIT) context: exploration is slower and models under-retrieve.** Anthropic concedes "runtime exploration is slower than retrieving pre-computed data"; Chroma shows lower needle–question similarity worsens retrieval; a model may never open the handle. *Why this does not overturn:* handle-only is a *policy* choice per candidate kind, not a kernel default; the kernel only guarantees that expansion is an observable effect, which is what makes "did it open the handle" (`activated`) measurable — Cursor's 46.9 % and Anthropic's tool-search numbers are then Lab arms under matched budgets (T-LCD-14), not assumptions.

**Against ordering rules in the profile: the position effect is universal enough to be a kernel default.** *Why this does not overturn:* Chroma's shuffle result and provider-divergent distractor rates show the effect's *shape* varies by model; Cursor reports deleting layout guardrails as models improved. A rule that is universal today is still a conditioned rule with an expiry (T-LCD-05); the kernel fixes partial order only.

**Negative results from the audit.** (i) No audited builder carries an authority class on a candidate or checks placement against one; (ii) none records *omissions* as data — Codex renders a notice, browser-use a marker, OpenHands a warning log; (iii) none content-addresses the assembled context per call (`context.assembled.view_hash` is novel as a per-call record); (iv) AIOS's "context manager" is a generation snapshot for scheduling, not assembly — the OS metaphor does not supply a builder; (v) none exposes legal cut points to its compaction strategy except OpenHands (`manipulation_indices`), which is why its condenser is the only one that cannot produce an unpaired tool call.

## 6. Recommendation for the spec

### 6.1 Position of the builder (what it is, what it is not)

The context builder is **one component class, `context_policy`** (Stage-1 mandatory slot key of `AgentProcess.native.slots`, CF-052/ADR-0016), whose *kernel part* is fixed by this dossier and whose *policy part* is a registered variant. It runs once per model call at `DecisionPoint = retrieve` and `plan` (Ontology v1 β), after E3's `select_surfaces` and D3's `retrieve` have produced candidates and before the reference monitor evaluates any proposal made in the call. It owns three operations — `assemble`, `render`, `offload` — and emits `context.assembled`, `context.artefact.delivered` and (proposed) the `omitted[]` payload. It does **not** decide what to compact (D2), what to retrieve (D3), what is valid (D4), what a slot's provider role is (C3/`role_map`), or what happens when the window cannot be made to fit (F2/D2 via `CompactionRequired`).

### 6.2 The builder contract (operations · inputs/outputs · invariants · failure modes)

**`assemble(request: AssemblyRequest) → ContextPlan | AssemblyError`**

- `AssemblyRequest = {model_call_id, view: ContextView, candidates: [Candidate], layout: Layout, budget: ContextBudget, profile: ProfileRef, account: AccountingHandle, policy_params, estimator_ref}`.
  - `ContextView` = `project(run, context_view, until_seq)` (ADR-0026) — the transcript as the ledger currently says it is, with compactions applied, carrying `derived_from{run_id, seq, view_policy_version}`; the builder never reads the ledger around the view.
  - `Candidate = {candidate_id, context_item: Ref<ContextItem> (ADR-0016 entity 3: payload ref, provenance, validity, priority, delivery_id?, activation_observable), kind: CandidateKind, state ∈ {handle_only, expanded}, retention ∈ {required, optional(priority: PriorityClass)}, estimate: {tokens, estimator_ref}, source_event: EventRef, slot_hint?: SlotId, readers?}`. `CandidateKind` (closed per dialect, registered `ext`): `kernel_notice, definition_instruction, principal_message, procedure_index, procedure_body, tool_surface, memory, observation, artifact_excerpt, transcript_item, budget_reminder, environment_state, subagent_result`. The kind is Codex's `content_kind` made a closed sum; it never encodes role.
  - `Layout` (from the compiled `ModelSurface.layout`, ADR-0019/0020, profile-owned): ordered `[SlotDeclaration{slot_id, min_authority: AuthorityClass, admit_unknown_validity: bool, admits: set<CandidateKind>, cardinality, cache_tier ∈ {static, dynamic, transcript}, diffable: bool, budget_share?, order: {precedence: int, within_slot: ComparatorRef}}]`. **Kernel-reserved slots** that every layout must declare (a layout without them fails `link`, ADR-0019 stage 1): `kernel` (`min_authority = kernel`), `definition` (`definition`), `principal` (`principal`), `transcript` (`delegate`; model outputs and paired observations), `external` (`external`; the "quarantine" slot of OQ-105), `unverified` (`unverified`; lifted/imported content). A profile may declare further slots (e.g. `memory`, `procedures`, `environment`) with any `min_authority` ≥ `unverified`.
  - `ContextBudget = {window_cap: tokens (the `context.occupancy` gauge cap from the profile's declared context window), margin: tokens, reservations: [{holder, tokens}] (kernel-mandated items — omission notice, soft-budget `advise` reminders, current-time), hard: Ref<BudgetNode>}` (ADR-0040).
- `ContextPlan = {plan_id = H(canonical(plan − plan_id)), model_call_id, derived_from (the view watermark), slots: [SlotFill{slot_id, items: [PlannedItem]}], omitted: [Omission], context_label: Label, occupancy_estimate: {tokens, estimator_ref}, legal_cut_points: [index], reserved: tokens}`; `PlannedItem = {candidate_id, context_item_id, artefact_id, delivery_id (fresh, or the previous delivery's id when `delivered_by_reference`), authority, label, tokens, state, delivered_by_reference: bool, derived_from?: [DeliveryRef]}`; `Omission = {candidate_id, reason ∈ {authority, validity, readers, budget, dedup, media_unsupported, cardinality, unidentified}, evidence}`.

**Kernel admission invariants (checked by `assemble`; violation is an `AssemblyError`, never a warning):**

- **I-ID (closed world, ADR-0019 §6):** every `PlannedItem` has a compiled identity (`trace_map` locator) or a ledger content address; a candidate with neither is `Omission{unidentified}` and `UndeliverableArtifact` is raised if it was `required`.
- **I-RP (role placement, ADR-0034 RP, verbatim):** an item is placed only in a slot with `slot.min_authority ≤ authority(item)`; `role_map(slot.min_authority)` is the *maximum* provider role the renderer may use for it; an item below every admitting slot is `Omission{authority}` unless the profile declares a demotion wrapper (OQ-104) that renders it into the `external` slot. The builder never promotes.
- **I-ORDER (ADR-0034 P5, re-applied at admission):** for every admitted candidate `validity(item, now) ∈ slot.validity_required` (default `{valid}`; `unknown` only if `admit_unknown_validity`), then `authority ≥ min_authority`, then `reader ∈ readers(item)` (C2 enforcement; carried at C0), before any relevance-based selection by the policy. D3's retrieval applies the same order; the builder re-checks so a policy bug cannot bypass it.
- **I-LABEL (ADR-0034 P3):** `context_label = ⊔ label(items admitted)`; recomputed from the plan, never carried over; an item delivered by reference contributes its label as if delivered.
- **I-BUDGET:** `Σ tokens(admitted) + reserved ≤ window_cap − margin`; `required` items are never truncated or evicted; if the required set plus reservations alone exceeds the cap, `assemble` fails with `ContextWindowExceeded{required_tokens, cap}` and the runtime raises `CompactionRequired` to D2/F2 (ADR-0040 E5) — the builder never stops the run.
- **I-PAIR / I-ATOM / I-MEDIA (F4):** every tool-call item in `transcript` has exactly one paired observation and vice versa; batch and tool-loop atomicity hold; media the profile's capability declaration does not accept is replaced by a typed placeholder item (`deriver = kernel`, `derived_from = projection`), never silently dropped.
- **I-NOSYS:** raw provider `system`-role items from a previous response are never admitted as candidates (Codex `is_api_message`); only compiled `kernel`/`definition` slot content reaches the top role.
- **I-DET:** `assemble` is a pure function of `AssemblyRequest`; two implementations agree on `plan_id` (canonical form per ADR-0015/0029).
- **I-NOWIDEN:** the policy interface (§6.3) cannot set or change `authority`, `label`, `validity`, `slot.min_authority` or `retention = required`; any attempt is `PolicyViolation` and the plan is rejected.

**Failure modes:** `UndeliverableArtifact`, `ContextWindowExceeded`, `PolicyViolation`, `InvalidLayout{missing_reserved_slot | min_authority_below_unverified}`, `StaleView{view.derived_from < required}`, `MissingProvenance`, `EstimatorMismatch`.

**`render(plan: ContextPlan, renderer_spec: RendererSpec, profile) → RenderedRequest{messages: [ModelMessage], surfaces_revealed[], trace: [(span → delivery_id)]} | UnexpressibleSurface`** — executes the compiled transcript-renderer spec (ADR-0019 `ModelSurface.transcript_renderer`) **inside the builder** (resolves OQ-063 as synthesis guided): role assignment strictly through `role_map` bounded by I-RP; id normalization, empty-part filtering, reasoning-signature placement, image downgrade, tool-result naming — all rule-driven (`ProfileRule{kind: transcript_render}`); every rendered span traces to a `delivery_id`. The output is data consumed by the C1 gateway (CF-044); the gateway may not re-order, merge or re-role. `relower` (ADR-0019 §7) re-runs `render` under the new spec; items the new profile cannot represent become `Omission{media_unsupported | profile_opaque}` and are listed in `model.surface.relowered.dropped_items[]` (OQ-067 default: drop with a typed placeholder; summarising is a D2 variant).

**`emit`:** after `render`, the builder appends `context.assembled{model_call_id, plan_id, view_hash = derived_from hash, items[{context_item_id, delivery_id, slot_id, provenance, authority, tokens, kind, state, delivered_by_reference}], omitted[], context_label, occupancy_estimate, reserved, assembly_ms{measured_at}, compaction_state, estimator_ref}` (payload extension to WS-B1's row — CF-D1-02; OQ-084 answered: items inline when canonical size ≤ the class threshold, else by content address with counts inline) and one `context.artefact.delivered{artefact_id, delivery_id, kind, rendering_ref = trace locator, by_reference}` per admitted item that is a harness artifact (ADR-0014; `by_reference` marks steady-state diffs). Every item's `provenance` is mandatory (ADR-0035 table).

### 6.3 The policy family interface (component class `context_policy`)

`ContextPolicy` is an operation-shaped contract (T-LCD-12) receiving the profile and the account (T-LCD-08):

- `select(candidates: [Candidate] (post-admission, each annotated with `admissible_slots[]`), layout, budget_remaining, profile, account, params) → Selection{chosen: [(candidate_id, slot_id)], order: map<slot_id, [candidate_id]>, evict_order: [candidate_id] (optional items in eviction order), by_reference: [candidate_id], expand_requests: [candidate_id]}`. The policy chooses *which optional candidates*, *which admissible slot* among those the kernel allows, *the order within a slot* (through the slot's declared comparator or its own registered one), *which diffable sections to deliver by reference*, and *which handle-only candidates it wants expanded next turn*. It cannot touch anything in I-NOWIDEN.
- `priority(candidate) → PriorityClass` — the policy's eviction ordering over a **kernel-fixed closed set** `PriorityClass = {commentary, observation_old, observation_recent, image, memory, procedure_body, transcript_tail}` (registered `ext` allowed; Codex's three-valued enum generalised) so two policies' evictions are comparable in the Lab.
- `declare() → {variant_id, deterministic: bool, model_conditioned_rules: [rule_id with AssumptionDebtRecord], required_inputs ⊇ {ModelProfile, ResourceAccount}}` (ADR-0023 §5; T-LCD-05 on every conditioned rule).

**Kernel steps around the policy (fixed order):** `admit` (I-ID, I-RP, I-ORDER, I-MEDIA, I-NOSYS) → `reserve_mandatory` (kernel items: omission notice slot, `advise` reminders, current-time if declared — Codex precedent) → `policy.select` → `enforce_budget` (evict `optional` items the policy ordered; unfit-first, then `(priority, age)`; refuse if `required` alone overflows) → `check_invariants` (I-PAIR/I-ATOM/I-LABEL/I-DET) → `plan`. The omission notice is a `kernel`-authority item whose text is a `Text` leaf in the sealed definition ("omitted evidence does not authorize actions"), counted in the opacity report.

**C0 `default` policy (the trivial builder):** admit everything the kernel admits; slots in layout precedence; within `transcript`, ledger order (recency tail); `optional` = observations older than the last N turns and `commentary`; no by-reference delivery; no expansion requests; excerpt policy from the profile's `result_render` rule. This is the Stage 0/1 builder and the T-LCD-03 anchor's builder.

**C1 variants (Stage 5, named for the Lab):** `priority_eviction` (Codex guardian class), `world_state_diff` (F5, `diffable` slots by reference with hash check), `jit_handles` (F7: memories/procedures/tool catalogs handle-only, expansion on request), `recency_plus_pins` (browser-use first+last-N), `retrieval_augmented` (D3 candidates admitted into a `memory` slot with `budget_share`), and every compaction-trigger policy D2 defines. Each is a `VariantRecord` with `binding_locality` (in-process default; out-of-process allowed, OQ-075 hot-path budget applies).

### 6.4 The offloading and just-in-time contract

`offload(observation | artifact, policy: ExcerptPolicy, label) → {excerpt: Candidate{kind: artifact_excerpt, state: expanded, tokens ≤ policy.max}, handle: OffloadHandle{content_address (ADR-0029 blob), media_type, size, label, excerpt_report: {truncated_by ∈ {lines, bytes, tokens}, total_lines, total_bytes, retained_range}, read_capability: Ref<ToolCapability>}}`.

- **When:** at *record* time for every tool observation above the profile's `result_render` threshold (Codex/Pi precedent; ADR-0029 already offloads the ledger payload above 64 KiB — the builder's threshold is ≤ the ledger's), and on demand by a policy/compaction decision ("tool-result clearing": replace an already-delivered observation by its handle, `derived_from = projection`, `deriver = kernel`).
- **Label preservation:** excerpt, handle and any later read carry the *same* label (`⊔` of source and `kernel` deriver — no change); a read of the handle is an effect through `read_capability` declared in the sealed definition (closed world; the monitor sees it; `environment` authority is *not* granted by reading — the content re-enters at its recorded label, ADR-0034 P7).
- **Handle-only candidates (progressive disclosure):** `Candidate.state = handle_only` renders the *index form* (name, description, size, handle) — Pi/OpenHands skills, Cursor/Anthropic tool catalogs; `expand` is an effect (`fs_read`/`memory_read` domain, or E3 `select_surfaces` for tools) that yields an `expanded` candidate sharing `artefact_id` and receiving a new `delivery_id`; `context.artefact.activated` is emitted deterministically on expansion (OQ-049: `procedure`, `tool_surface`, `memory` kinds have deterministic activation; instructions inside rendered prompts do not).
- **Programmatic/executed offload** (results consumed in a sandbox and never delivered): a C2 variant of E2/E5 (ADR-0022 composite surfaces), out of C0; the contract admits it because a never-delivered result simply has no `PlannedItem`.
- **Failure modes:** `ExcerptTooLarge` (policy max above the slot budget), `HandleUnreadable` (no declared read capability — the candidate is omitted `unidentified`), `LabelLoss` (a lowered handle whose target cannot carry `hir/provenance` — declared in the loss report, T-LCD-11).

### 6.5 Layout, ordering and reset semantics (what the profile owns; what the kernel fixes)

- The **profile owns**: slot declarations beyond the six reserved ones, `min_authority` of its own slots (never below `unverified`, never above the kernel's ceiling for the kind — e.g. a `memory` slot may not declare `min_authority = definition` and then admit an `external` memory; I-RP makes that a `cardinality`-empty slot, not an escalation), slot precedence, within-slot comparators, `cache_tier`, `diffable`, `role_map`, demotion wrappers, reminder placement, excerpt thresholds — every one a `ProfileRule` with an assumption-debt record (F8; T-LCD-05).
- The **kernel fixes**: the six reserved slots and their `min_authority`; that slot precedence is total but within-slot order is the policy's; that `kernel` and `definition` slots are `static` cache tier and the `transcript` slot is `transcript`; and that no rule may change an item's slot after admission.
- **Reset semantics (OQ-105 answered):** the `context_label` is recomputed from the plan on every call; compaction that removes `external` items restores it (ADR-0034 P3); the `external` slot **is** the quarantine slot and its items **do** join the label — there is no label-exempt slot, because the model reads it (Fides/Biba semantics); isolation (a fresh subagent context, ADR-0034 P2) is the only exemption; a new principal message never raises the label. Items delivered by reference (F5) join the label as if delivered.

### 6.6 Data-model sketch (summary)

`Candidate{…}` · `CandidateKind` (closed + `ext`) · `Retention = required | optional(PriorityClass)` · `PriorityClass` (closed + `ext`) · `SlotDeclaration{slot_id, min_authority, admit_unknown_validity, admits, cardinality, cache_tier, diffable, budget_share?, order}` · `Layout = [SlotDeclaration]` with six reserved ids · `ContextBudget{window_cap, margin, reservations[], hard}` · `ContextPlan{plan_id, model_call_id, derived_from, slots[], omitted[], context_label, occupancy_estimate, legal_cut_points[], reserved}` · `PlannedItem{…}` · `Omission{candidate_id, reason, evidence}` · `OffloadHandle{content_address, media_type, size, label, excerpt_report, read_capability}` · `ExcerptPolicy{max_lines, max_bytes, max_tokens?, mode ∈ {head, tail, head_tail}}` · `RenderedRequest{messages[], surfaces_revealed[], trace[]}` · `Selection{…}` · events `context.assembled` (extended payload), `context.artefact.delivered{…, by_reference}`, `context.artefact.activated` (on expansion). `ContextItem.placement_policy: Ref<HarnessRule>?` (ADR-0016) remains the definition-level "insert ContextItem" action that *produces* a candidate with a `slot_hint`; the hint is advisory — admission decides.

### 6.7 Acceptance-criteria sketch (privilege-preservation tests are AC-D1-1…5)

- **AC-D1-1 M-CPE fixture (S-103 vector; AC-L3-3 executable form).** Candidates: a runtime-discovered instruction file (`origin = tool(fs_read)`, free text ⇒ `external`), a tool observation with an injected filename, a project skill body loaded from a workspace path, a retrieved memory written by a previous run (`≤ external`). Expected: none appears in `kernel`/`definition`/`principal` slots; each is in `external` (or omitted `authority`); `render` places them only in roles ≤ `role_map(external)`; `context_label.authority = external`; the AIOS-shaped variant (relevance-first injection at the top role) is *impossible to express* as a policy (`PolicyViolation`). (C0/Stage 2; executable Stage 3)
- **AC-D1-2 X-CPE fixture (AC-L3-4 form).** After a run that read external content, the memory it wrote carries `≤ external`; on the next run the builder never admits it into a slot with `min_authority ≥ principal`; a `promotion` endorsement event (ADR-0035) is the only way it later reaches a `principal` slot, and the test verifies the endorsement's presence in the ledger. (C0/Stage 2)
- **AC-D1-3 Label monotonicity.** Property test over random candidate sets: `context_label(plan) = ⊔ label(items)`; adding a candidate never raises the label; removing the last `external` item restores it; `delivered_by_reference` items count. (C0/Stage 1)
- **AC-D1-4 No-widen policy interface.** A fuzzed policy that returns a slot not in `admissible_slots`, sets `retention = required`, or edits `authority` is rejected with `PolicyViolation` and no plan is emitted. (C0/Stage 1)
- **AC-D1-5 Closed world.** A candidate without compiled identity or content address is omitted `unidentified`; the same as `required` raises `UndeliverableArtifact`; 100 % of rendered spans trace to a `delivery_id` (with ADR-0019 AC-3). (C0/Stage 1)
- **AC-D1-6 Budget discipline.** With reservations for the omission notice and an `advise` reminder: (a) optional items are evicted unfit-first then by `(priority, age)` deterministically; (b) `required` alone overflowing yields `ContextWindowExceeded` and `CompactionRequired`, never a truncated required item and never `stop`; (c) the omission item is present whenever `omitted ≠ ∅` and carries `kernel` authority. (C0/Stage 1–2)
- **AC-D1-7 Structural invariants.** Random deletions of transcript candidates are corrected only at `legal_cut_points`; a plan with an unpaired tool call, a split batch, or unsupported media without a placeholder is invalid; D2's variants, given `legal_cut_points`, cannot produce an invalid plan (shared battery with D2). (C0/Stage 2)
- **AC-D1-8 Determinism.** Same `AssemblyRequest` on two hosts and two implementations ⇒ equal `plan_id`; changing only `estimator_ref` changes the plan hash and is recorded. (C0/Stage 1)
- **AC-D1-9 Offload round-trip.** An observation above threshold yields an excerpt ≤ policy max plus a handle whose content address dereferences to the full bytes; excerpt, handle and a later read carry identical labels; the read appears as an `action.effect.*` chain through the declared capability; a handle without a declared read capability is omitted. (C0/Stage 2)
- **AC-D1-10 Compliance chain (T-LCD-13).** Every admitted harness artifact emits `context.artefact.delivered` with `delivery_id`; expansion of a handle-only `procedure`/`tool_surface`/`memory` emits a deterministic `context.artefact.activated`; by-reference deliveries are marked; `opacity_dynamic` (ADR-0045) is computable from `context.assembled.items`. (C0/Stage 2–3)
- **AC-D1-11 Profile-conditioned variant without Core change (T-LCD-08).** A `world_state_diff` or reminder-placement variant differing by profile (Codex `reminder_threshold_tokens` shape) is registered as a `context_policy` variant plus `ProfileRule`s with debt records; the Core is untouched; "retire rule R" produces a valid arm. (C1/Stage 5; contract check at Stage 1)
- **AC-D1-12 Utility measurement (with AC-L3-10).** The Lab runs "RP on vs banner-only" and "handle-only vs expanded catalogs" under matched budgets, reporting success, compliance, approvals and cost (T-LCD-14). (C0/Stage 3)
- **AC-D1-13 Re-lowering.** A mid-run profile switch re-renders the same plan; profile-opaque items appear in `model.surface.relowered.dropped_items[]` with typed placeholders; the plan hash is unchanged (only `render` differs). (C0/Stage 3)

## 10. Confidence

**High** for the kernel admission invariants (I-ID, I-RP, I-ORDER, I-LABEL, I-NOWIDEN): they are direct consequences of ratified ADR-0019/0033/0034/0035 applied to a structure (slots with kinds and tiers) that every audited builder already has; the only new field is `min_authority`. **High** for required/optional retention with priority eviction, reserve-before-select and whole-item omission with a kernel notice: read in production source (Codex guardian) and consistent with Pi/OpenHands/browser-use truncation practice. **High** for the offload shape (excerpt + content-addressed handle + declared read): Cursor, Anthropic, Codex, Pi and OpenHands converge on it and ADR-0029 already stores the bytes. **Medium** for the specific closed sets (`CandidateKind`, `PriorityClass`, six reserved slots): shapes are precedented, membership may need a dialect bump once D2/D3/C3 design against them. **Medium** for placing `render` in the builder (OQ-063): synthesis guidance and the CF-044 split support it, but C1's transport needs may push id-normalization rules to the gateway — the contract survives either placement because rules are data. **Low-to-medium** for anything quantitative (token savings, position effects' magnitude, compliance costs of RP): all vendor or single-team, none load-bearing; the contract makes each a Lab arm.
