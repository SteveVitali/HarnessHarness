## 1. Scope & boundary

This workstream decides **what happens when the working set the context builder wants to deliver does not fit — or should not fill — the model's window**: the *compaction contract* every strategy variant satisfies; the closed set of *compaction operations* (`Evict`, `Offload`, `Summarize`, `Restructure`) any variant composes; the *provenance and validity obligations* of each operation (a summary is a `delegate`-authored derivation with authority ≤ its sources, never above; an offload preserves the source label; an eviction leaves a `kernel` omission record); the *trigger and budget* interface (hard `CompactionRequired` from the builder; soft occupancy thresholds and reminders as conditioned rules; explicit principal/model requests; reactive overflow); *model-conditioning* (every threshold, summariser choice, retained-tail size, thinking/image handling is a parameter of a registered variant or a conditioned rule with an assumption-debt record — never a per-model branch); the *C0 trivial compactor* (a deterministic evictor that needs no model call); the *ledger events* the family emits; and the *canonical laboratory comparison* — the pre-registered experiment the J-track runs first, because compaction is the sponsor's own example of a pluggable family (doc 3 §1.3, §2.4) and the mechanism with the strongest evidence of model-conditioned effects (doc 2 §5.1, §6).

It explicitly leaves to neighbours: **WS-D1** — assembly, admission, slots, `legal_cut_points`, offload excerpt policy (this dossier consumes `ContextPlan`, `ContextView`, `OffloadHandle` and raises nothing above `delegate`); **WS-D3/D4** — what becomes durable memory (a summary written to memory is a `Memory` entity D4 governs; this dossier only fixes the label it carries in); **WS-C3** — the reminder surface (`ProfileRule{kind: compaction_reminder}`), `role_map`, the rule inventory; **WS-C1** — transport of a summariser request and provider-side compaction (`compact_20260112`, Codex remote compaction) as a gateway capability; **WS-F1/F2** — who calls `assess`/`propose` at `DecisionPoint = compact`, and what happens on `CompactionImpossible` (F2's stop rule); **WS-F3** — sub-agent result distillation (a delegation, not a compaction); **WS-B1** — the event envelope (payload extensions proposed here, CF-165); **WS-G1/I2** — deterministic fidelity detectors and judged fidelity (this dossier specifies the metrics and oracle classes; G1 builds the detectors); **WS-J3/J4/J5** — running, analysing and storing the canonical experiment (this dossier writes the design; J3 executes it).

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Production ships four *operations*, not four strategies, and every real strategy composes them.** Across nine codebases the primitives are: *evict* (opencode `prune` marks tool outputs `time.compacted` and renders "[Old tool result content cleared]"; gemini `toolOutputMaskingService` masks with a tag; Anthropic `clear_tool_uses` replaces results with placeholder text; Harbor strips old screenshots first; Codex `new_context` starts a fresh window "without summarizing"); *offload* (gemini saves truncated outputs and masked tool outputs to files; Cursor writes history and tool outputs to files the agent can `tail`/search; Codex `notes` + read-only `history{read_item, list_items, search_contents}` recover items by `[id: …]`); *summarise* (all, with a previous-summary update loop in Pi, opencode, gemini `<state_snapshot>` and OpenHands' prompt "which will include previous summaries"); *restructure* (goose `StructuredSummary` schema; gemini file-level `FULL | PARTIAL | SUMMARY | EXCLUDED` routing and `<intent_summary>` "Active Bridge"; Pi's deterministic `readFiles/modifiedFiles` extracted from tool-call arguments; Codex's tool-*schema* compaction passes; Codex world-state re-render). Named strategies are *sequences* of these: Pi = summarise(prefix) + restructure(file lists) + evict(everything before the cut) + retain(tail); gemini chat compression = evict/offload(old function responses over 50k) → summarise → verify → inflation check; Codex token-budget = model-owned offload(notes) → evict(all); Anthropic server-side = summarise + evict(all prior blocks). **Implication (§6.2):** the contract defines a closed `CompactionOp` sum and a *proposal* as an ordered list of ops; variants differ in how they choose ops, never in the op vocabulary. This is what makes two variants' effects comparable in the Lab (T-LCD-09) and what lets a deterministic C0 variant and a model-backed C1 variant satisfy one contract (doc 3 §1.3).

**F2 — A summary is model-produced, non-deterministic content whose authority every audited system silently *raises*; the ratified scheme forbids this and the fix is one derivation call.** OpenHands stamps `Condensation.source = "environment"`; goose re-roles the summary as `User`; gemini inserts the snapshot as a `user` turn followed by a fabricated `model` acknowledgement ("Got it. Thanks for the additional context!"); Codex prefixes "Another language model started to solve this problem …" and renders it as a user fragment (`CompactionSummary` via `ContextualUserFragment`); opencode records it as an assistant message with `summary: true`. Only OpenHands names what was forgotten (`forgotten_event_ids`); Codex keeps `compaction_response_id` and `compaction_model_hash`; gemini's graph carries `abstractsIds`/`replacesId`. Under ADR-0034 P1 a compaction summary is `derive(kind = compaction, inputs = forgotten, deriver = delegate)`: `label = ⊔ label(inputs) ⊔ delegate`, so it is **≤ `delegate`**, carries the union taint, and can never re-enter a `kernel`/`definition`/`principal` slot (D1 I-RP). Which *provider role* renders it is a `role_map` surface (C3), not an authority. **Implication (§6.3):** every `Summarize`/model-`Restructure` op must produce an `Artifact` with a full provenance record whose `derived_from` lists the forgotten ids — the ledger already stores them (`context.compaction.completed.forgotten`). The four production role choices become *profile* decisions with assumption-debt records, not kernel behaviour. Mechanism of the risk: S-103's X-CPE (via WS-L3 F5) is precisely a summary of external content re-entering at a higher scope.

**F3 — Every mature implementation has a fallback ladder because compaction itself fails, and the failures are typed.** Codex trims the oldest history item and retries on `ContextWindowExceeded` while summarising (cache-prefix preserving), aborts on `SessionBudgetExceeded`, and installs an *un-summarised* fresh window when the model runs out of budget (`auto_compact_fallback_prompt`); goose retries with 10/20/50/100 % of tool responses removed from the middle outwards and fails fast when none exist; OpenHands distinguishes `SOFT` (return the uncondensed view) from `HARD` (hard context reset with 20 % string shrinking per attempt, max 5) and refuses condensations below `minimum_progress`; gemini falls back to truncation-only after one failed summarisation, refuses an *inflated* result (`COMPRESSION_FAILED_INFLATED_TOKEN_COUNT`) and an empty summary, and restores the uncompressed history when the call/response adjacency invariant breaks; opencode strips media and replays the last user message on provider overflow and stops with `ContextOverflowError` when the session cannot be compacted; Harbor runs "progressively simpler fallbacks". **Implication (§6.2, §6.4):** the contract fixes the failure sum `{CompactionImpossible, CompactionIneffective, SummarizerOverflow, SummarizationFailed, IllegalCut, PolicyViolation, BudgetRefused, Aborted}` and a *kernel* fallback rule: on a `hard` requirement, if the bound variant fails, the runtime invokes the variant's declared deterministic fallback, and finally the C0 evictor; only when the `required` set alone exceeds the cap does F2 stop the run. Ineffectiveness (no reclaim, or reclaim below a declared minimum) is a failure, never silently accepted.

**F4 — Triggers are of four kinds and two strengths, and the *hard* one is a gauge cap, not a budget.** Proactive occupancy thresholds (Pi `window − reserve`; opencode `usable = input_limit − reserved`; gemini 0.5 × limit; goose 0.8; OpenHands token cap = min(condenser cap, agent input limit); Anthropic 150k/100k input tokens; Claude Code `autoCompactThreshold`), reactive overflow (opencode `overflow`, Harbor "reactive", Inspect `overflow`, Codex `ContextWindowExceeded`), explicit requests (OpenHands `CondensationRequest`; Codex `Manual`; Pi/opencode slash commands; the *model's own* `new_context` call), and schedules/counts (OpenHands `max_size` events; browser-use every N steps, via WS-D1). OpenHands makes the strength explicit (`HARD | SOFT`) and the reasoning is instructive: "Token pressure is a hard requirement … sending the next request can fail before the recovery path has a chance to run. Treat event-count pressure as soft." This is exactly WS-L2's split — `context.occupancy` is a *gauge* whose cap "refuses the next increment (`CompactionRequired`) rather than stopping the run" (ADR-0040 E5) — and D1's `ContextWindowExceeded → CompactionRequired`. **Implication (§6.2):** `CompactionTrigger = {occupancy_hard, occupancy_soft, overflow_reactive, request_principal, request_model, schedule, relower}` (closed), `requirement ∈ {none, soft, hard}`; the *hard* trigger is kernel-owned (D1/F2), every *soft* threshold is a conditioned rule (`HarnessRule{action: set compaction policy}` or `ProfileRule{kind: compaction_reminder}`) with an assumption-debt record (T-LCD-05; ADR-0040 decision 5's "re-armed after compaction" is preserved by emitting `context.compaction.completed` before F2 re-arms).

**F5 — Model-conditioning of compaction is real, pervasive, and expressed today as per-model branches.** Codex `models.json` carries per-model `token_budget{reminder_threshold_tokens, reminder_message_template, auto_compact_fallback_buffer_tokens}` and `auto_compact_token_limit`; gemini selects a summariser by a `switch` on the model string (`modelStringToModelConfigAlias`) and runs distillation on a fixed `gemini-3-flash-base`; Anthropic's thinking-block retention default differs by model family ("keep all" vs "last turn"), and on Fable 5.1/Mythos 5.1 "thinking blocks from before a compaction block aren't carried forward"; Codex comments that "the model is trained to see the compaction summary as the last item in history after mid-turn compaction"; opencode lets the `compaction` agent choose its own model; OpenHands uses an "independent LLM" for summaries. Doc 2 §5.1's two production reports (S-047, S-049) say these rules go stale. **Implication (§6.5):** the variant contract receives `(ModelProfile, ResourceAccount)` (T-LCD-08); the summariser is a `ProfileRef` parameter (`summarizer_profile`, default = the run's profile); thresholds/tail sizes/thinking and image retention are parameters bound by definition-level conditioned `HarnessRule`s (ADR-0016 action `set compaction policy`) with debt records; the reminder text is a `ProfileRule{kind: compaction_reminder}` (ADR-0020). No `if model == X` survives in a variant.

**F6 — Model-owned compaction exists in production and in the 2026 literature, and it is a *control-boundary* choice over the same contract, not a different subsystem.** Codex's token-budget mode makes the *model* write `notes` (offload) and call `new_context` (evict-all) — β(compact) = model — while the harness still records the lifecycle as compaction; MemGPT's self-directed paging (S-016) and Context-Folding/AgentFold's learned `fold`/`branch`/`return` (S-338/-03, `provisional`) are the academic form. Harness-owned compaction (every other audited variant) is β(compact) = code. Ontology v1 already has `DecisionPoint.compact` and β : Δ → {code, model, human}. **Implication (§6.2, §6.5):** a model-owned variant declares `control_boundary.compact = model` and exposes its `CompactionOp`s as `ToolCapability`s (`compact`, `offload_note`, `new_window`) whose invocation is an effect (`memory_write`/`fs_write` domains) the monitor sees; the *kernel* still applies every op-level invariant (no widening, legal cuts, required items untouched, reclaim check) to what the model proposes. The Lab can then compare β = code vs β = model as a component-level factor (CF-005 in Phase 0's words).

**F7 — What compaction costs is not visible in task success; three ledger-computable process metrics capture it.** S-341 (`provisional`) finds completion unchanged while retrieval calls triple; S-340 (`provisional`) finds increased blocked actions and repeated exploration; Codex warns users that "multiple compactions can cause the model to be less accurate"; Cursor reports "fewer unnecessary summarizations" as a benefit; Anthropic warns of "loss of subtle but critical context whose importance only becomes apparent later". All three mechanisms are *observable in the run ledger without a judge*: (i) **re-acquisition** — a later delivery (`context.artefact.delivered` or an `fs_read`/`memory_read` effect) whose content address or `artefact_id` matches an item in a prior compaction's `forgotten` set; (ii) **repeated action** — an `action.effect.*` chain after compaction whose idempotency key (`H(run_id, effect_id, canonical(args), capability_version)`, ADR-0031) collides with one before it; (iii) **compaction overhead** — `harness_overhead.compaction` share of `tokens.*`, `model_calls` and `turn_phase_profile.compaction` ms (ADR-0043/0044). **Implication (§6.6):** these are `MetricDeclaration`s with `oracle_classes_allowed = {trace_predicate}`, `applies_to_classes = {native}`, admissible at C0 headline level (ADR-0047), alongside a *deterministic recall probe* over facts extractable from tool arguments (paths, ids, error strings — Pi's `details` shows the extraction is deterministic).

**F8 — Summary *volume* is not controllable by prompt alone; structural controls are.** S-343 (`provisional`) reports summary output "largely input- and prompt-invariant"; gemini and OpenHands both add *structural* guards (inflation refusal; `minimum_progress`); Pi caps the summariser's `maxTokens` at 0.8 × `reserveTokens`; goose orders schema sections "most-important-first so … experiments that truncate sections can cut from the tail". **Implication (§6.2):** `target_reclaim` and `max_summary_tokens` are contract inputs; the reclaim check (`tokens_after ≤ tokens_before − minimum_reclaim`) is a kernel invariant; schema-typed (`Restructure`) outputs are preferred where truncation must be predictable.

**F9 — Validation of a compaction at the boundary is implementable with ratified primitives.** gemini already runs a second "critically evaluate the snapshot you just generated" turn; Slipstream and TRACE (`provisional`) validate a summary against the agent's continued execution from the *same pre-compaction state*. ADR-0027's fork-by-reference (`forked_from{run_id, at_seq, source_head_hash}`) and ADR-0046's paired comparison give the Lab a *boundary-local paired continuation* recipe: fork at the compaction event, continue k steps with and without the proposal, compare process metrics. **Implication (§6.6):** the canonical experiment has a run-level design (whole-task, matched budget) and a boundary-level companion (paired continuations) — the latter is how compaction *prompts* (Text leaves) are ablated and, at C4, optimised (ACON's mechanism) without unmatched-budget claims.

**F10 — Hosted participants expose compaction only as a declared capability plus, sometimes, an event; nothing component-level is observable.** Inspect emits `CompactionEvent{type ∈ {summary, edit, trim}, tokens_before, tokens_after, source}`; Claude Code marks `isCompactSummary`/`compact_boundary`; ACP exposes only `UsageUpdate{used, size}`; OTel GenAI has `gen_ai.conversation.compacted`. **Implication:** the Hosting ABI's `capability_declaration.compaction` (tri-state, already in Ontology v1) is joined by an optional *observed* `compaction` event lifted to `context.compaction.completed{ops: [{kind}], tokens_before/after}` with `origin = participant`, `authority = unverified`; every component-level compaction metric is `n/a{reason: class}` for hosted rows (T-LCD-15); `summary → Summarize`, `trim → Evict`, `edit → Restructure | Evict` is the lifting table (OQ-030 input).

## 5. Disconfirming evidence & negative results

**Against a closed op sum ("strategies are too diverse; let each variant return a new view").** OpenHands, Pi and gemini's graph processors all return a *whole* transformed view/list — simpler, and it accommodates folds and graph rewrites nobody has typed yet. *Why this does not overturn:* a whole-view return is where authority laundering and illegal cuts hide (F2, F3), and it makes two variants' effects incomparable except by end-state. The op sum is small (four kinds, each with a `kernel`/`delegate` deriver rule) and open through `ext` for genuinely new kinds (a registered `ext` op must still declare its deriver and its forgotten set); a fold (S-339) is `Summarize{inputs = sub-trajectory} + Evict`. Cost: one proposal record per compaction, which the ledger wants anyway.

**Against forbidding authority above `delegate` for summaries ("the summary must be authoritative or the model ignores it").** Codex prefixes the summary as prior work "you also have access to"; gemini fabricates a model acknowledgement; every system renders it near the top role — arguably because a summary treated as untrusted text is discounted. *Why this does not overturn:* authority governs what a summary may *command* (the monitor's `effective_authority`, ADR-0034 P3), not where it renders — the profile's `role_map(delegate)` still decides the role, and compliance with the summary is exactly what T-LCD-13 measures. The alternative — a summary of external content re-entering as `principal` — is the X-CPE bug (S-103). If a principal wants a summary to carry weight, `promotion` (ADR-0035) is the ledgered path.

**Against a deterministic C0 evictor as the Core default ("eviction without summary destroys progress; nobody ships it").** Codex ships it (token-budget fresh window), Anthropic ships it (`clear_tool_uses`), opencode ships it (prune), gemini ships it (masking) — but *always* paired with a summary or notes. *Why this does not overturn:* C0 must satisfy the contract without a model call (ADR-0028 replay; Stage 0–2 have no summariser budget), and the evictor is also the universal *fallback* (F3). Its inadequacy for long tasks is the point of the canonical experiment (§6.6 H1), not a reason to make summarisation Core.

**Against ledger-computed fidelity metrics ("only a judge can tell whether the summary lost what mattered").** S-341's fact-preserving vs dropping operators were judged by outcome; Slipstream and gemini use a model to validate. *Why this does not overturn:* re-acquisition and repeated-action are *behavioural* consequences that need no judge and are the costs the 2026 studies report; the deterministic recall probe covers the extractable subset (paths, ids, literals); judged fidelity is admitted as a C1 `Validator{kind: judge}` with calibration and `charged_to = instrument` (ADR-0047) — labelled, never headline.

**Against model-owned compaction in the family ("it is a control strategy, not a compaction").** Codex implements it in the compaction lifecycle; F1 might claim it. *Why this does not overturn:* the ops are the same and the invariants must hold on what the model proposes; placing it in `compaction_strategy` with `control_boundary.compact = model` keeps one contract and makes β a factor. F1 is asked to confirm (OQ-194).

**Against a `hard` trigger from a gauge cap rather than a budget node.** Anthropic's server-side compaction and Claude Code's `autoCompactThreshold` are token thresholds; one might model the window as a `BudgetNode`. *Why this does not overturn:* ADR-0039/0040 already decided occupancy is a gauge (max-aggregated, cap-bounded) and a cap "refuses the next increment (`CompactionRequired`) rather than stopping the run"; a budget would exhaust the run. The soft thresholds remain conditioned rules.

**Negative results from the audit.** (i) No audited system attaches authority or validity to a summary; one (OpenHands) marks it `environment`, i.e. *above* model output. (ii) None records the *proposal* (what would be compacted) separately from the *result*; only OpenHands and gemini's graph record the forgotten set. (iii) None measures re-acquisition or repeated action; goose and Codex are the only ones that account the compaction call's cost per row. (iv) gemini's `switch` on the model string and Codex's per-model `token_budget` are the two forms per-model conditioning takes — the first is the T-LCD-01 defect, the second the shape a conditioned rule should have but without a debt record. (v) No system exposes cut points to its strategy except OpenHands (`manipulation_indices`) — the same negative WS-D1 recorded.

## 6. Recommendation for the spec

### 6.1 Position of the family

`compaction_strategy` is **one registered component class** (ADR-0023 `ClassRecord`), `cardinality = ordered-many` (a pipeline; OQ-073 answered for this class), `required_inputs ⊇ {ModelProfile, ResourceAccount}`, `hot_path = false`, invoked by the control strategy at `DecisionPoint = compact` (Ontology v1 β) whenever the builder raises `CompactionRequired` (hard), a conditioned rule fires (soft), a principal or the model requests it, or a re-lowering drops items (OQ-067). It reads the D1 `ContextView`/`ContextPlan` and `legal_cut_points`; it writes **only** ledger events, artifacts and blobs — never the ledger's history (ADR-0026 decision 4: compaction is an appended event projections interpret). It is *not* the builder (D1 decides what fits), *not* memory (D3/D4 decide what persists), *not* the gateway (C1 transports a summariser request or a provider compaction).

### 6.2 The compaction contract (operations · inputs/outputs · invariants · failure modes)

**`assess(input: AssessInput) → Assessment`** — pure.
- `AssessInput = {view: ContextView, plan?: ContextPlan, occupancy: {tokens, estimator_ref}, window_cap, trigger: CompactionTrigger, budget: Ref<BudgetNode>, profile: ProfileRef, account: AccountingHandle, params}`; `CompactionTrigger = {occupancy_hard, occupancy_soft{rule_id}, overflow_reactive{error_ref}, request_principal, request_model{tool_call_id}, schedule{rule_id}, relower{dropped_items[]}}` (closed per dialect).
- `Assessment = {requirement ∈ {none, soft, hard}, reasons: [TriggerReason], target_reclaim: tokens, min_reclaim: tokens}`. Kernel rule: `occupancy_hard`, `overflow_reactive`, `request_principal` ⇒ `hard`; `request_model` ⇒ `hard` unless the profile declares otherwise; `occupancy_soft`/`schedule` ⇒ `soft` (OpenHands precedent).

**`propose(input: ProposeInput) → CompactionProposal | ProposeError`** — pure and deterministic over its inputs (the *selection* never depends on a model call).
- `ProposeInput = AssessInput + {assessment, legal_cut_points: [index], candidates: [PlannedItem] (retention, PriorityClass, label, tokens, artefact_id), previous: Ref<CompactionRecord>?}`.
- `CompactionProposal = {proposal_id = H(canonical(proposal − proposal_id)), ops: [CompactionOp], expected_reclaim: tokens, requires_model_call: bool, summarizer_profile?: ProfileRef, max_summary_tokens?, fallback: [CompactionOp] (deterministic only)}`.
- `CompactionOp` (closed sum + registered `ext`):
  - `Evict{item_ids[], placeholder ∈ {kernel_omission, none}}` — remove whole items from the view; a `kernel_omission` item ("omitted evidence does not authorize actions", the D1 kernel notice, a `Text` leaf in the sealed definition) is inserted at the cut.
  - `Offload{item_ids[], handle: OffloadHandle, excerpt_policy: ExcerptPolicy}` — replace items by their content-addressed handle + excerpt (D1 §6.4); the read path is the declared `read_capability`.
  - `Summarize{input_ids[], schema_ref?, insert_at: index, previous_summary_ref?, instructions_ref: Ref<Text>}` — a model call producing an `Artifact{kind: compaction_summary}`; `input_ids` are the forgotten set.
  - `Restructure{input_ids[], schema_ref, extractor ∈ {deterministic{projection_ref}, model{instructions_ref}}, outputs: [ContextItem]}` — replace items by a typed structure (file lists, task tables, world-state diffs, per-file `FULL | PARTIAL | SUMMARY | EXCLUDED` levels).
- Every op names the items it consumes; `Σ consumed ⊆ legal ranges`; an op may not consume a `required` item.

**`execute(proposal, account, gateway?) → CompactionRecord | ExecuteError`** — the only operation that may call a model (through C1, as an ordinary `model.call.*` with `charged_to = subject`, attribution class `harness_overhead.compaction`, and `context_label` of the summariser call = ⊔ inputs).
- `CompactionRecord = {compaction_id, proposal_id, applied_ops: [AppliedOp{op, artifacts[], handles[], model_call_ids[]}], forgotten: {ids | range}, tokens_before, tokens_after, occupancy_after, context_label_after, status ∈ {applied, ineffective, failed, aborted, fallback_applied{step}}, summariser_usage?, duration_ms{measured_at}}`.

**`declare() → VariantDeclaration{variant_id, op_kinds ⊆ {evict, offload, summarize, restructure}, deterministic: bool, control_boundary_compact ∈ {code, model}, capabilities{incremental_summary, split_turn, hard_reset, handles_requests, reactive_overflow}, model_conditioned_rules: [rule_id with AssumptionDebtRecord], required_inputs ⊇ {ModelProfile, ResourceAccount}, fallback_variant?: ComponentVariantRef}`** (ADR-0023 §5; T-LCD-05/-08).

**Kernel invariants (checked by the runtime around every variant; violation is an error, never a warning):**
- **I-CUT:** every op boundary ∈ `legal_cut_points`; a plan produced from the compacted view satisfies D1's I-PAIR/I-ATOM (shared battery AC-D1-7).
- **I-REQ:** no op consumes a `required` item; the most recent `principal` message and every `kernel`/`definition` slot item are `required` by construction; older principal messages are `optional(transcript_tail)` unless a rule pins them (Codex retains them up to a budget — a variant parameter, `retain_principal_tokens`).
- **I-NOWIDEN (ADR-0034 P1/P6):** `label(output of Summarize | model-Restructure) = ⊔ label(inputs) ⊔ delegate`; `label(Offload | deterministic-Restructure output) = ⊔ label(inputs)` (deriver `kernel`); `Evict` outputs only the `kernel` omission item. No op may set `authority`, `validity`, `readers` or `retention`.
- **I-LEDGER (ADR-0026):** the ledger is untouched; `context.compaction.started` precedes any model call; `context.compaction.completed` carries `forgotten` and every artifact/handle reference; the compacted view is `project(run, context_view, until_seq)` interpreting the event (Pi/OpenHands/Codex reconstruction precedent).
- **I-RECLAIM:** `tokens_after ≤ tokens_before − min_reclaim` else `status = ineffective` and the proposal is discarded (gemini inflation guard; OpenHands `minimum_progress`); for `hard`, the fallback ladder continues.
- **I-LABEL (ADR-0034 P3; OQ-105):** `context_label_after` is recomputed by the next `assemble`; compaction that removes `external` items restores it; a summary of external content keeps `external` and the union taint, so it *does not* restore it — the record states both.
- **I-BUDGET (ADR-0040):** `execute` reserves the summariser call (`reserve` before dispatch); `InsufficientBudget` ⇒ `BudgetRefused` ⇒ fallback (deterministic ops need no reservation beyond `tokens.*` = 0); soft thresholds re-arm only after `context.compaction.completed`.
- **I-DET:** `assess` and `propose` are pure functions of their inputs (two implementations agree on `proposal_id`); a variant with `deterministic = true` has `requires_model_call = false` for every proposal and is eligible under a control strategy that declares `deterministic_replay` (ADR-0028).
- **I-FALLBACK (kernel rule):** on `requirement = hard`, if `execute` fails or is `ineffective`, apply `proposal.fallback`; if that fails, the variant's `fallback_variant`; finally the C0 `evict_oldest`; if the `required` set alone exceeds `window_cap − margin`, raise `CompactionImpossible` to F2 (`stop_reason = context_exhausted` — a new stop reason for F2, CF-168). On `soft`, failure returns the view unchanged and is recorded.

**Failure modes:** `CompactionImpossible{required_tokens, cap}`, `CompactionIneffective{tokens_before, tokens_after, min_reclaim}`, `SummarizerOverflow{input_tokens, summarizer_cap}` (handled by a declared `InputReduction ∈ {trim_oldest, drop_tool_results_middle_out{percent}, shrink_strings{factor}}` — recorded as `input_reduction_applied`), `SummarizationFailed{model_call_id, reason ∈ {error, empty, aborted}}`, `IllegalCut{index}`, `PolicyViolation{op, reason ∈ {required_item, authority, retention}}`, `BudgetRefused{dimension}`, `Aborted{by ∈ {principal, hook, cancel}}`, `UnresolvedSummarizer{profile_ref}`.

### 6.3 Per-operation provenance and validity rules

| op | deriver (ADR-0034 P1) | authority of output | `derived_from` | validity (ADR-0014) | what the model later sees |
|---|---|---|---|---|---|
| `Evict` | none (omission) | the omission item is `kernel` | — (the `forgotten` set is on the event) | n/a | a kernel notice; nothing else |
| `Offload` | `kernel`, deterministic | = ⊔ inputs (unchanged) | inputs | inherits each input's validity | excerpt + handle; a read is an effect at the recorded label (ADR-0034 P7) |
| `Summarize` | `delegate` (model) | ⊔ inputs ⊔ delegate ⇒ **≤ delegate**; taint = ∪ | the forgotten ids + `model_call_id` + `instructions_ref` | `unknown` unless a Validator sets it; never `valid` by construction | a `ContextItem{payload: Artifact{compaction_summary}}` admitted only into slots with `min_authority ≤ delegate` (`transcript` or `external`); rendered role per `role_map` (C3) |
| `Restructure` (deterministic) | `kernel` | ⊔ inputs | inputs + `projection_ref` | deterministic check ⇒ `valid` when the projection is total | typed items (file lists, world-state diff) |
| `Restructure` (model) | `delegate` | ≤ delegate | as `Summarize` | `unknown` | schema-typed items, each field a `Text` leaf or typed value |

Rules that follow: a summary written into memory (D3/D4) enters with this label and `scope ≤ run` unless promoted (ADR-0035 `promotion`) — X-CPE is impossible by construction; a summary's `Text` counts in `opacity_dynamic` (ADR-0045) and its `instructions_ref` (the compaction prompt) counts in the static opacity report (T-LCD-02); the summary artifact and the omission notice are harness artifacts with `context.artefact.delivered` events, so *compliance with a summary* ("followed") is measurable (T-LCD-13); `Summarize.instructions_ref` is a `Text` leaf on the migration ladder (ADR-0024) — prose today, parameterised (schema-typed `Restructure`) when it earns it.

### 6.4 The C0 trivial compactor — `evict_oldest`

`VariantDeclaration{variant_id: evict_oldest, op_kinds: {evict, offload}, deterministic: true, control_boundary_compact: code, capabilities: {reactive_overflow}, model_conditioned_rules: []}`. `assess`: `hard` on `occupancy_hard | overflow_reactive | request_*`, else `none` (no soft rules at C0). `propose`: target `occupancy ≤ window_cap × target_fraction` (parameter, default 0.5 — gemini/OpenHands "half the cap" precedent); walk `optional` items oldest-first in kernel `PriorityClass` order `image → observation_old → commentary → procedure_body → memory → observation_recent → transcript_tail` (Harbor/Codex media-first; D1's set — OQ-185 answered: sufficient, with `ext` classes orderable by a declared total order per variant); for each item with an `OffloadHandle` already recorded (`context.observation.recorded` above the threshold) emit `Offload` (tool-result clearing with a handle), otherwise `Evict{placeholder: kernel_omission}` — one omission item per contiguous evicted range; stop at the first legal cut point at or after the target; never touch `required`. `execute`: no model call; emits the two events. Precedent: opencode `prune`, gemini masking, Anthropic `clear_tool_uses{keep}`, Codex fresh window. It is also the universal last-rung fallback. Stage: **C0 / Stage 2** (ADR-0026 (e) places compaction events at Stage 2; Stage 0–1's `ContextWindowExceeded → stop` (WS-D1 §6.9) is replaced by `evict_oldest` at Stage 2).

### 6.5 The C1 family (Stage 5) and model-conditioning

Registered variants, each a `VariantRecord` with `param_schema` and `conditioned_rules` (T-LCD-05): `clear_tool_results{keep_recent_uses, exclude_capabilities[], clear_at_least, clear_inputs}` (Anthropic/opencode); `summarize_rolling{keep_recent_tokens, reserve_tokens, summarizer_profile, instructions_ref, incremental: bool, split_turn: bool, retain_principal_tokens, max_summary_tokens, input_reduction}` (Pi/Codex/OpenHands/gemini); `offload_then_summarize` (Cursor: the forgotten range is written as an artifact with a handle *before* summarising; the summary cites the handle); `structured_checkpoint{schema_ref, section_order}` (goose/gemini snapshot/Codex notes as `Restructure{model}` + deterministic file-op extraction); `fresh_window_with_notes{reminder_rule, note_capability, history_capability, fallback_buffer_tokens}` (Codex token-budget; `control_boundary_compact = model`; ops proposed by the model through `ToolCapability`s and validated by the kernel); `world_state_refresh` (Codex `render_diff` full reinjection after compaction — a deterministic `Restructure`); `relower_summarize` (OQ-067: summarise profile-opaque items instead of dropping — C2); `fold_on_return` (S-338/-03: `Summarize + Evict` of a completed sub-trajectory at a Procedure step boundary — C2/Stage 4, needs D5/F3 boundaries); `provider_compaction` (Anthropic `compact_20260112`, Codex remote v2 — `execute` delegates to a gateway capability; the ledger records `forgotten` = every block before the returned compaction block and the summary artifact at `delegate`; iteration usage is posted as its own charge; declared `capability_declaration.compaction = supported` on the profile).

Model-conditioning has exactly three homes and no fourth: (1) **variant parameters** bound in the Harness Definition (values are data, ADR-0023); (2) **definition-level conditioned rules** `HarnessRule{trigger: profile predicate, action: set compaction policy{variant params overrides | soft threshold}, conditioned_on: ProfileRef, assumption_debt}` (ADR-0016 entity 13 — Codex `models.json.token_budget` is the precedent, now with a debt record); (3) **profile-level surface rules** `ProfileRule{kind: compaction_reminder}` for reminder text/placement and, via `role_map`, the summary's rendered role (ADR-0020; Anthropic thinking-retention defaults and Codex's "summary last" comment are `transcript_render`/`compaction_reminder` rules). `summarizer_profile` is a `ProfileRef` parameter (gemini's per-model aliases and OpenHands' independent LLM), making "summariser model" a component-level factor and a *model set* member (ADR-0012). The gemini `switch` on model string is the defect this removes (T-LCD-01).

### 6.6 The canonical laboratory comparison (for WS-J3; `Design` + `PreRegistration`, ADR-0045)

**Name:** `lab/compaction-family-v1`. **Granularity:** `component-level` (native only; hosted rows admitted at `product-level` stratified by `capability_declaration.compaction`). **Factors (T-LCD-09):** `model` ∈ ≥2 families × ≥2 capability tiers; `compaction_strategy` ∈ {`evict_oldest` (C0), `clear_tool_results`, `summarize_rolling`, `structured_checkpoint`, `offload_then_summarize`} plus, where the profile allows, a `window_ceiling` arm (same model, larger declared window, `compaction = none`) as the reference the others are measured against; `environment` ∈ {coding/terminal long-horizon (SWE-bench-Verified-class, Terminal-Bench-class), research/browse (BrowseComp-class), multi-episode structured tool tasks (AppWorld-class)} — the three families the 2026 studies used; `budget` — `MatchSpec{dimensions: [tokens.input.total, tokens.output.total, model_calls, time.wall_ms], mode: matched_cap, tolerance: 0.10}` with **compaction calls charged to the subject** (ADR-0039 R-ACC-3), so a summarising arm pays for its summaries; `seed` = replicate axis (≥5). Every arm declares `search_budget = 0` (no optimisation); the compaction prompt is frozen and its `Text` leaf hash is in the arm's `configuration_id`.

**Metrics (`MetricDeclaration`s; `applies_to_classes = {native}` unless noted):** headline `capability.task_success` (oracle `executable | end_state`, `charged_to = subject`), `reliability.pass^k` and per-task variance (ADR-0045), `efficiency.tokens_total`, `efficiency.spend`, `efficiency.harness_overhead.compaction_share`, `efficiency.compaction_latency_ms` (`turn_phase_profile.compaction`), **`grounding.reacquisition_rate`** = |deliveries or reads after compaction c whose content address/`artefact_id` ∈ forgotten(c)| ÷ |forgotten(c)| (oracle `trace_predicate`), **`reliability.repeated_action_rate`** = |effects after c with an idempotency key equal to one before c| ÷ |effects after c| (`trace_predicate`), **`grounding.recall_probe@compaction`** = fraction of deterministically extractable facts (paths, ids, error literals — Pi `details` extractor as `projection_ref`) from forgotten(c) present in the summary artifact or reachable by a handle (`trace_predicate`; the *extractable* subset only), `security.label_restored` (context label after compaction vs before), `grounding.summary_followed` (T-LCD-13 `verification.artefact.followed` on the summary artifact, `detector ∈ {deterministic, judged}`), `opacity_dynamic` delta, and `compaction.count`, `compaction.ineffective_count`, `compaction.fallback_count`. Optional C1 judged fidelity: `Validator{kind: judge}` with `calibration_ref`, independent of every beneficiary snapshot, `charged_to = instrument` (ADR-0047) — reported, never headline. Hosted rows: component-level metrics `n/a{reason: class}`; `compaction.count` from lifted events where present.

**Pre-registered hypotheses:** H1 — at matched cap, `summarize_rolling` ≥ `evict_oldest` on task success for lower-tier models and the gap shrinks for higher-tier models (the model-conditioning claim; a canned interaction analysis "does variant V help model M more than N", T-LCD-09); H2 — `reacquisition_rate` and `repeated_action_rate` are the costs that separate variants when task success does not (S-341/-04 mechanism); H3 — `offload_then_summarize` lowers `reacquisition` cost per re-acquired item without raising `spend` beyond tolerance; H4 — `structured_checkpoint` lowers `repeated_action_rate` vs free-text summaries. **Equivalence margin** pre-registered per environment (WS-I2 R2/R3 with OQ-113). **Outcome classes** per ADR-0045 (`budget_exhausted` runs are reported, never dropped). **Boundary-level companion (`lab/compaction-boundary-v1`, C2):** at every `context.compaction.started` in a run, `fork_by_reference` (ADR-0027) and continue k = 5 turns with and without the proposal; report `reacquisition`, `repeated_action`, next-effect agreement — the TRACE/Slipstream shape with ratified primitives; this is the recipe for ablating compaction prompts (`Text` leaves, OQ-058 placeholder semantics) and, at C4, for ACON-style guideline optimisation under `search_budget` accounting (ADR-0046). **Robustness across capability change** (doc 2 §8): the design is re-run on every new profile version; a variant whose benefit disappears is marked conditional and its rule's `expiry_condition` fires (T-LCD-05; "retire rule R").

### 6.7 Data-model sketch (summary)

`CompactionTrigger` (closed) · `Assessment{requirement, reasons, target_reclaim, min_reclaim}` · `CompactionOp = Evict | Offload | Summarize | Restructure | ext` · `CompactionProposal{proposal_id, ops[], expected_reclaim, requires_model_call, summarizer_profile?, max_summary_tokens?, fallback[]}` · `CompactionRecord{compaction_id, proposal_id, applied_ops[], forgotten, tokens_before/after, occupancy_after, context_label_after, status, summariser_usage?, duration_ms}` · `VariantDeclaration{…}` · `InputReduction` (closed) · `Artifact{kind: compaction_summary | compaction_checkpoint, provenance{origin: model, authority ≤ delegate, derived_from: forgotten ids + model_call_id + instructions_ref}}` · events `context.compaction.started{trigger, requirement, strategy_variant_ref, pipeline_index, proposal_id, occupancy_before}` and `context.compaction.completed{…record…, applied_ops[{kind, consumed_ids, artifact_refs, handle_refs, model_call_ids}], input_reduction_applied?, fallback_step?}` (payload extension to WS-B1's row — CF-165); `control.decision{kind: compact}` unchanged; `context.artefact.delivered` for the summary and the omission item; hosted lift `CompactionEvent{type} → applied_ops[{kind}]`.

### 6.8 Acceptance-criteria sketch

- **AC-D2-1 Contract conformance.** Every registered `compaction_strategy` variant passes a shared battery: `assess`/`propose` purity (equal `proposal_id` across two hosts, AC-D1-8 style); ops only at `legal_cut_points` (fuzzed views with unpaired calls, batches; shared with AC-D1-7); no op consumes a `required` item; `declare().required_inputs ⊇ {ModelProfile, ResourceAccount}`; implementable out-of-process (T-LCD-08/-12). (C0/Stage 2)
- **AC-D2-2 Provenance of derivations.** Property test: for random forgotten sets with mixed labels, a `Summarize`/model-`Restructure` output has `authority = min(⊔ inputs, delegate)` and taint = ∪; `Offload`/deterministic-`Restructure` outputs equal ⊔ inputs; the summary is never admitted into `kernel`/`definition`/`principal` slots (with AC-D1-1); a summary written to memory carries `≤ delegate` and `scope ≤ run` (with AC-D1-2/AC-L3-4). (C0/Stage 2)
- **AC-D2-3 Ledger discipline.** After compaction: no durable event mutated; `context.compaction.completed.forgotten` ∪ view = pre-compaction view; `project(run, context_view)` rebuild equality holds (ADR-0026); every summary artifact resolves by content address; `derived_from` lists every forgotten id. (C0/Stage 2)
- **AC-D2-4 Reclaim and fallback.** Fixtures: (a) inflated summary ⇒ `ineffective`, proposal discarded, fallback applied; (b) summariser overflow ⇒ declared `InputReduction` applied and recorded, then success or fallback; (c) `required` set alone exceeds cap ⇒ `CompactionImpossible` reaches F2, no truncated required item, no dangling effect; (d) `soft` failure returns the view unchanged; (e) budget refusal on the summariser ⇒ deterministic fallback, no unaccounted call. (C0/Stage 2)
- **AC-D2-5 C0 evictor.** `evict_oldest` needs no model call, is `deterministic`, reclaims to `target_fraction`, evicts in the kernel priority order media-first, emits one omission item per range at `kernel` authority, and restores the context label when the evicted items were the only `external` ones. (C0/Stage 2)
- **AC-D2-6 Model-conditioned variant without Core change (T-LCD-08/-05/-01).** A `summarize_rolling` configuration that differs per profile (thresholds, `summarizer_profile`, reminder) is expressed entirely as variant params + conditioned `HarnessRule`s + `ProfileRule{compaction_reminder}` with debt records; `lcd_report.conditioned_rules` lists them; "retire rule R" yields a valid arm; a variant containing a model-identity branch fails registration. (C1/Stage 5; contract check Stage 1)
- **AC-D2-7 Accounting.** Every summariser call posts `control.budget.consumed` with `charged_to = subject` and attribution class `harness_overhead.compaction`; provider-compaction iteration usage is posted as its own charge; `turn_phase_profile.compaction` sums to the compaction span. (C0/Stage 2 with L2/I1)
- **AC-D2-8 Process metrics computable from the ledger.** On a synthetic run with known forgotten sets, `reacquisition_rate`, `repeated_action_rate` and `recall_probe@compaction` are computed by `trace_predicate` oracles from events alone and match hand-computed values; hosted rows yield `n/a{class}`. (C0/Stage 3)
- **AC-D2-9 Canonical experiment executes.** `lab/compaction-family-v1` runs with ≥2 models × ≥3 variants × ≥1 environment under `matched_cap`; the engine refuses an arm without `MatchSpec` (T-LCD-14); the report is a `ComparisonReport` with `benefit_kind = artifact_benefit`, `budget_match.status`, per-configuration distributions and the H1 interaction analysis (T-LCD-09). (C1/Stage 3 for evictor vs `clear_tool_results`; Stage 5 full family)
- **AC-D2-10 Model-owned compaction.** `fresh_window_with_notes` runs with `control_boundary.compact = model`; the model's `offload_note`/`new_window` calls appear as effects the monitor evaluated; kernel invariants I-REQ/I-NOWIDEN/I-RECLAIM are applied to the model's proposal; a proposal violating them is refused with `PolicyViolation` and recorded. (C1/Stage 5)
- **AC-D2-11 Hosted lift.** An Inspect-style `CompactionEvent` and a Claude-Code-style `compact_boundary` lift to `context.compaction.completed{applied_ops[{kind}], tokens_before/after}` with `origin = participant`, `authority = unverified`; component-level metrics are `n/a`. (C2/Stage 4 with J6)
- **AC-D2-12 Boundary-local companion.** Forking at a compaction event and continuing k turns with/without the proposal produces paired rows keyed by `forked_from`; the recipe refuses unequal budgets. (C2/Stage 4)

## 10. Confidence

**High** for the op sum, the hard/soft requirement split, the kernel invariants and the fallback rule: nine Tier-B codebases at pinned commits converge on the same primitives and failure handling, and the invariants are direct consequences of ratified ADR-0026/0033/0034/0040 applied to them. **High** for the C0 evictor: it is what every system ships as the floor or fallback and needs no model. **High** for the provenance rules: one derivation call (ADR-0034 P1) settles them; the only novelty is refusing what production does (F2). **Medium** for the canonical experiment's *metric definitions* — the mechanisms (re-acquisition, repeated action, boundary-local evaluation) come from 2026 preprints tagged `provisional`, but each metric is computed from ratified ledger events, so the design is valid even if the papers' numbers do not replicate; which metric separates variants is what the experiment exists to learn. **Medium** for placing model-owned compaction inside this class (F1 may prefer to own β = model; the contract survives either placement). **Low-to-medium** for anything quantitative (thresholds, tail sizes, reclaim fractions): every constant above is a parameter with a precedent, not a design commitment. No C0 recommendation rests on a `provisional` performance claim.

## 11. ADRs produced

- ADR-0075 (proposed) — Compaction is one component class with a closed operation sum (`Evict`/`Offload`/`Summarize`/`Restructure`), an `assess/propose/execute/declare` contract, hard/soft requirements, kernel invariants (legal cuts, required items, no widening, ledger untouched, reclaim, label, budget, determinism) and a kernel fallback ladder ending in the C0 `evict_oldest` compactor.
- ADR-0076 (proposed) — Provenance and validity of compaction derivations: summaries and model restructures are `delegate`-derived (authority ≤ delegate, union taint, `unknown` validity, `derived_from` = forgotten set); offloads and deterministic restructures are `kernel`-derived and label-preserving; model-conditioning lives only in variant parameters, conditioned `HarnessRule{set compaction policy}` and `ProfileRule{compaction_reminder}`; model-owned compaction is a variant with β(compact) = model.
- ADR-0077 (proposed) — The canonical laboratory comparison `lab/compaction-family-v1`: factors, matched-cap `MatchSpec` with compaction charged to the subject, ledger-computed process metrics (`reacquisition_rate`, `repeated_action_rate`, `recall_probe@compaction`, overhead share, latency), oracle classes, pre-registered hypotheses, and the boundary-local paired-continuation companion.
