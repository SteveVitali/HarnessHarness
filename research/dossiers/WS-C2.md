## 1. Scope & boundary

This workstream decides **how HarnessHarness chooses which model snapshot serves a given model call, what happens when that call fails, and how "more than one model per call" (ensembles) is represented** — and it decides these as a *policy component at the model boundary* (Ontology v1: *boundary component*, `home = model_boundary`, ADR-0012 decision 3 / CF-026), never as logic inside the gateway (WS-C1) or the control strategy (WS-F1). Concretely it fixes: (i) the **router contract** — operations, inputs (the *routing request*), outputs (the *routing decision*), invariants and failure modes; (ii) the **policy model** — routing policies as typed data with a closed kind enum, each conditioned rule carrying an `AssumptionDebtRecord` (ADR-0020, T-LCD-05); (iii) **fallback and retry semantics** — the split between a same-model *attempt* and a cross-model *reroute*, the closed error-class → action table, and health/cooldown as a ledger-derived view; (iv) **routing decisions as ledger events** (`model.route.decided`, `model.rerouted`, and the existing `model.surface.relowered` from ADR-0019) so that attribution (WS-B1/I1/J4) and the Lab's factor bookkeeping (ADR-0036 `configuration_id`) stay honest; (v) the **compatibility guard** — a target model is admissible only if an `active`/`expiring` Model Profile matches it, its capability declaration covers what the compiled bundle requires, and the transcript can be re-lowered within a declared loss bound; (vi) **ensembles** (voting, self-consistency, mixture-of-agents) as explicit, budgeted control-plane `Procedure`s rather than router internals.

It explicitly leaves to neighbours: the provider-agnostic inference contract, error classes as *emitted* by the gateway, streaming and usage normalisation (**WS-C1** — this dossier consumes C1's error class enum and adds the per-class *routing action*; where C1's dossier does not yet exist, §6.3 states the minimum error-class set the router needs, flagged as CF); the profile schema, rule inventory, probes and expiry (**WS-C3** inside ADR-0020 — the router only *reads* `ModelProfile.capabilities`, `expiry.status` and `selector`); the resource taxonomy, budget nodes, `reserve/check` and pricing tables (**WS-L2**, ADR-0039/0040/0041 — the router is a *consumer* of `remaining` and the pricing table, as WS-L2 §6.4 already stipulates); retry/timeout *enforcement* and the exhaustion rule (**WS-F2** — the router *proposes* an alternate target; the envelope owns attempt counting and the stop rule); the DecisionPoint set and the `ControlBoundary` record (**WS-A3/WS-F1**, ADR-0012 decision 6 — this dossier raises, not decides, whether `route` becomes a DecisionPoint at HIR/2); subagent spawning and value-of-compute (**WS-F3/F4** — ensembles reuse F3's `delegate` machinery; F4 decides *whether* to spend, the router decides *on what model*); the event envelope (**WS-B1** — payload extensions to `model.rerouted` are requested as CF, envelope untouched); re-lowering itself (**WS-A4/WS-D1** — `relower` and the transcript renderer; this dossier fixes only *when* the router may call it and what it must refuse); the Hosting ABI's `model-override` capability (**WS-J6**; ADR-0013 rules model-boundary interception keeps a participant `hosted`); and every language/runtime/storage choice (ADR-0050 §8). Nothing here names a language, runtime, package ecosystem or framework; every precedent path is evidence, not a dependency (T-LCD-12).

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Three routing regimes exist in practice and route on different information; only one of them is a "model router" in the sponsor's sense.** (a) *Gateway routing* (litellm, OpenRouter, AIOS) routes on **operational** signals — health, rate limits, cost per token, latency, provider budgets — with the request treated as opaque; it is deployment-level load balancing with typed fallbacks. (b) *Harness-internal utility routing* (opencode `getSmallModel`, codex compaction model, Anthropic lead/subagent roles) routes on **role or task class** — title, summary, compaction, subagent, judge — to a cheaper model, and is written as data (`small_model`, family priority lists, `models.json`) plus a few code branches. (c) *Academic routing* (RouteLLM, Hybrid LLM, FrugalGPT, AgentRouter, SWE-Router) routes on **predicted difficulty or quality** per query or per step. **Implication:** the router contract must accept all three input families as *typed routing-request fields* — `role`, `task_class`, `required_capabilities`, `budget_remaining`, `latency_target`, `health_view`, `quality_prior` — and policies must declare which fields they read, so the Lab can ablate a policy's inputs (T-LCD-08/-09). No audited system separates the three.

**F2 — Retry and reroute are different operations with different owners, and every production system already encodes the split.** litellm retries *inside* a model group and falls back *across* groups by error class; opencode retries with backoff but *never* on context overflow; goose retries transient errors and refuses on a permanent-marker list; codex retries compaction with the current model only for a closed model-specific error set. **Implication:** a same-target retry is a new `model_attempt` under the same `model_call_id` (ADR-0043 point 3; WS-F2 owns the count and backoff); a reroute is a *new target for the same logical call*, recorded by `model.rerouted` (WS-B1 table, owner C2) and, when the target's profile differs, preceded by `model.surface.relowered` (ADR-0019). Error class → action is a closed table (§6.3), never a regex over message text (opencode's `RETRYABLE_MESSAGE_PATTERNS` is the negative precedent: seven regexes over free text).

**F3 — Mid-run model switching invalidates transcript state and rewrites the trajectory; it is a factor change, not a transparent substitution.** Mechanism at the byte level: goose's permanent-failure markers show that a provider rejects a replayed transcript once the thinking configuration changes ("blocks in the latest assistant message cannot be modified"); goose `thinking_block_is_stale` and pi's placeholder rule (WS-A4 F3) exist because reasoning signatures and provider tool-call ids do not transfer. Mechanism at the behaviour level: The Replay Gap (`provisional (mech)`) forks *live* trajectories and finds 61–94 % of post-fork actions rewritten and first-action divergence 74–77 % vs 6–35 % in same-model controls; Harness-Bench (S-062) shows harness effects are model-conditioned and non-monotone. Codex is the only audited harness that names the event (`CompactionReason::ModelDownshift`) and reacts to it (compact with the previous model first). **Implication:** (i) every reroute across profiles is `relower` + `model.surface.relowered` (already ADR-0019 AC-9); (ii) the *realized* model set of a run is a recorded fact distinct from the *configured* one, and a run whose realized set deviates from its configured primary carries `routing.deviation = true`, which the Lab treats like DRIFT (ADR-0004 — a fact about the run, stratified, never silently pooled); (iii) evaluating routing policies by replaying logged trajectories under a different model is invalid — routing experiments must be live (`equivalence_run`-class, paired, matched budget).

**F4 — Routing decisions are unattributable unless recorded as typed events with candidates and reasons.** litellm carries attempted fallbacks in request metadata and returns them as response headers; codex records a counter with `reason/implementation/outcome`; OpenRouter returns the served `model`; no audited system records *which candidates were considered and why they were rejected*. WS-L2 already requires `model_ref.serving_route` on every charge and `model.rerouted{reason}` on every reroute; WS-I1 already attributes `harness_overhead.routing` in `cost_view`. **Implication:** the decision event must carry the candidate list with per-candidate verdicts and reason codes, the policy variant ref, and a digest of the inputs read — otherwise "did the router help?" cannot be answered and a learned router's own model calls cannot be charged (they are `subject`, `harness_overhead.routing`).

**F5 — The compatibility guard is derivable from ratified objects; nothing new is needed except the refusal rules.** ADR-0020 gives `ModelProfile.selector`, `capabilities` (declared → probed, `unknown` never coerced) and `expiry.status ∈ {active, expiring, expired, retired}` with "compiling under `expired` requires an explicit recorded intent"; ADR-0019 gives `relower(bundle, new_profile) → CompiledBundle' + TranscriptMigration{dropped_items[], rewritten_items[]}` and `UnexpressibleSurface` as an error; ADR-0040 gives `reserve` sized by the profile's `max_output` and `InsufficientBudget` as a pre-dispatch refusal; ADR-0039 gives `NoPrice`. The router composes these: a candidate is admissible iff a profile resolves (`NoProfile` otherwise), its status is `active` or `expiring` (`expired` only with recorded intent — `ExpiredProfile`), every capability the compiled `ModelSurface` requires is `declared`/`probed` `supported` (`CapabilityUnmet`; `unknown` refused unless the policy carries an `allow_unknown` conditioned rule with a debt record), the projected `TranscriptMigration` stays within the policy's declared loss bound (`MigrationLossExceeded`), a reservation succeeds (`InsufficientBudget`), and a price row exists when the policy reads cost (`NoPrice`).

**F6 — Ensembles are control-plane procedures that spend budget k-fold, and their benefit is non-monotone.** Self-consistency samples k paths and votes; MoA layers proposers under an aggregator; Chen et al. (NeurIPS 2024) prove Vote/Filter-Vote performance can *fall* with k on hard-query mixes; LLMRouterBench (`provisional`) reports diminishing returns for larger ensembles versus curation; Anthropic reports ~15× tokens for multi-agent. **Implication:** an ensemble is *not* a router policy; it is an explicit `Procedure` at the `delegate` decision point that issues k ledgered model calls (each routed individually), aggregates through a deterministic reducer or a `Validator{kind: judge}` (ADR-0047 governance applies), and is only ever compared under matched-total budget (ADR-0041/0046). The router's only job inside an ensemble is to pick each member's model.

**F7 — Learned routers are instruments with their own evidence obligations, and the field's own benchmarks say most do not beat simple baselines.** RouteLLM transfers across model pairs (accepted venue); LLMRouterBench (`provisional`) finds commercial and recent routers "fail to reliably outperform a simple baseline"; the TMLR survey lists generalisation, distribution shift, router latency and multi-turn settings as open. Per-step agentic routers (AgentRouter, SWE-Router) are 2026 single-team results. **Implication:** a `learned{predictor_ref}` policy kind is admitted to the schema at C1 but its *deployment* is a C4 evolution-pipeline artifact (ADR-0002; ADR-0046 admissibility gates with a `SearchBudgetRecord`), and every learned policy is a conditioned rule with an expiry condition of `model_version_change` — a router trained on one model pair is assumption debt against the next pair.

**F8 — Protocol routing vocabulary is thin and lossy.** MCP `ModelPreferences` carries three unit-interval priorities and substring hints that "MAY" map across providers; ACP carries a `model` config option. Neither carries capability requirements, budgets or profile identity. **Implication:** the routing request lowers to `ModelPreferences` with a loss report (T-LCD-11), and inbound `ModelPreferences`/`model` options *lift* to a routing request with `authority = external`/`unverified` inputs that a policy may read only as *preferences*, never as capability facts.

## 5. Disconfirming evidence & negative results

- **R1 — "Routers don't beat baselines" (against any learned policy at C1).** LLMRouterBench (`provisional`) finds many routers, including commercial ones, fail to beat a simple baseline; the TMLR survey lists generalisation and multi-turn as open; RouteLLM's transfer result is the exception, not the rule. *Why it does not overturn:* the C0/C1 contract does not assume routing *helps*; it makes routing a measurable, ablatable component with a static default. Learned policies are schema-admitted but deployment-gated to C4 under ADR-0046 admissibility (artifact benefit on a held-out split at matched budget) — the disconfirming evidence is exactly why the gate exists.
- **R2 — "Mid-run switching is not a transparent operation" (against reroute-on-failure at all).** The Replay Gap (`provisional (mech)`), goose's permanent-failure markers and Harness-Bench together say a cross-family reroute changes the trajectory and may break the transcript. *Why it does not overturn:* the alternative — a run dying on a transient provider outage — is worse for both users and the instrument (an `infrastructure_failure` outcome class, ADR-0045). The decision is to make reroute *lawful but loud*: profile-guarded, re-lowered, ledgered, and stratified (`routing.deviation`) so the Lab never pools rerouted and non-rerouted runs silently. Policies may also set `fallback_chain = []` (fail fast) per role — the instrument's default for pre-registered experiments (§6.6 AC-C2-9).
- **R3 — "Ensembles can hurt" (against ensembles as a router feature).** Chen et al. (NeurIPS 2024) show non-monotone returns; LLMRouterBench shows diminishing returns; Anthropic's 15× token multiplier and "value of the task is high enough" caveat. *Why it does not overturn:* ensembles are removed from the router entirely and made explicit budgeted procedures compared only under matched-total budget (T-LCD-14); the router never fans out on its own.
- **R4 — "Operational routing is a gateway concern; don't duplicate litellm" (against a native router).** litellm's router is 14 k lines of production-hardened logic; goose and opencode delegate multi-provider routing to gateway products; OpenRouter promises "a request never fails because routing infrastructure hiccuped". *Why it does not overturn:* the instrument needs (i) candidate-bearing decision *events* in its own ledger, (ii) the compatibility guard against *profiles* (a concept gateways lack), and (iii) the `routing.deviation` factor. An external gateway remains admissible as a *serving route* (`model_ref.serving_route`, ADR-0039) whose internal choice is recorded as `serving_route_reported` with `unknown` candidates — stratified, not hidden (T-LCD-07 pattern).
- **R5 — "Routing on quality priors from the Lab is circular" (against `quality_prior` as an input).** The compatibility surface is a derived view with `unknown` at unprobed levels (ADR-0012), and priors estimated on one task distribution shift on another (survey; AgentRouter's claim that single-turn routers miss trajectory dependencies). *Why it does not overturn:* the prior is a typed input with `source_ref`, `n`, interval and `valid_until`; a policy that reads it is a conditioned rule with an `evidence_refresh_due` expiry; `unknown` levels are refused, never interpolated (ADR-0012 verbatim).
- **R6 — Negative results from the audit.** (i) No audited system records the candidates considered and the reasons for rejection. (ii) No audited harness has a cross-provider fallback inside the harness; all delegate to a gateway or fail. (iii) opencode's task-class routing is one config key plus a code branch on provider id (T-LCD-01 failure signature). (iv) AIOS prices unknown models at zero. (v) MCP's `ModelHint` substring matching is explicitly permitted to cross providers "as long as it fills a similar niche" — an untyped escape hatch by design.

## 6. Recommendation for the spec

### 6.1 Position and unit of routing

The **router** is a registered component class (`class_id = router`, `home = model_boundary`, cardinality `exactly-one`, bound in `AgentProcess.native.slots` per ADR-0016/CF-052) whose contract, like every class contract, receives `(ModelProfile, ResourceAccount)` (T-LCD-08). It is invoked **once per logical model call** (`model_call_id`) *before* the gateway is called, and again on attempt failure. It never issues model calls itself except as a declared `learned` policy's predictor call, which is a ledgered `model_call` charged `subject` under `harness_overhead.routing` (ADR-0043 `cost_view.by_attribution`).

**Unit of routing = the logical model call, keyed by role.** The Ontology v1 *model set* is realised as a **role table**: `ModelRoleTable = map<ModelRole, RoleBinding{primary: ModelRef, alternates: [ModelRef], policy: RoutingPolicyRef}>` with `ModelRole ∈ {primary, utility, compaction, subagent, judge, router_predictor}` (closed per dialect; `judge` bindings must satisfy ADR-0047 independence). The *configured* role table is part of the sealed Harness Definition (data, ADR-0023) and therefore of `configuration_id`; the **realized** role table — the multiset of `ModelRef`s that actually served calls per role — is a run-manifest end-state fact (`model_set_realized`), and `routing.deviation = (realized ⊄ configured primaries)` is a run-level boolean that the Lab stratifies on (§6.5). This resolves the singular `model_ref` in ADR-0036's `configuration_id` by reading it as the configured role table's `semantic_id` (CF raised).

### 6.2 Router contract (operations · inputs/outputs · invariants · failure modes)

- `select(request: RoutingRequest, profile_env: ProfileResolver, account: AccountingHandle, health: HealthView, policy: RoutingPolicy) → RoutingDecision | RoutingRefusal` — pure over its inputs (no clock, no I/O beyond the resolver and the ledger-derived views), so two calls with equal inputs yield equal decisions (deterministic-replay friendly, ADR-0028). *Invariants:* R-1 the selected target passed the **compatibility guard** (§6.4); R-2 a reservation exists for the selected target before the decision is returned (`reservation_id` in the decision; ADR-0040 reserve-before-spend); R-3 every candidate in `policy.candidates(role)` appears in `candidates_considered[]` with a verdict; R-4 the decision carries `policy_ref` (variant ref + `version_id`) and `inputs_read[]` (the request fields the policy actually consumed).
- `on_attempt_failed(decision, error: ModelErrorClass, attempt_no, account, health, policy) → Continue{same_target, not_before} | Reroute{new_decision} | GiveUp{reason}` — consulted by the control envelope (WS-F2) after each failed `model_attempt`. *Invariants:* R-5 `Reroute` across profiles is legal only if `relower` has been *projected* and its `TranscriptMigration` is within `policy.max_migration_loss`; the envelope must append `model.surface.relowered` **before** the first attempt under the new target, and if the old profile's context limit was the failure cause, compaction under the *old* profile precedes migration (codex `ModelDownshift` precedent); R-6 the action for an error class is read from the policy's closed `error_actions` table (§6.3), never from message text; R-7 a `Reroute` releases the old reservation and holds a new one; R-8 `GiveUp` is returned when the chain is exhausted or the class is `permanent` with no fallback — the envelope then closes the logical call `model.call.failed{error.class, attempts}` (ADR-0026 table).
- `on_call_completed(decision, usage, timing, account, health) → ()` — posts nothing itself; the gateway's `model.call.completed` and the charge already carry `model_ref{profile_ref, provider_model_id, serving_route, effort?}` (ADR-0039 decision 3). The router's only obligation is that `model_ref` on the charge equals `decision.selected` (AC-C2-3).
- `explain(decision_ref) → RoutingExplanation` — a projection over `model.route.decided` and `model.rerouted` events for the trace viewer (WS-K2) and the Lab (J4); no new state.
- `lower(request, target ∈ {mcp_model_preferences, acp_model_option}) → target document + LoweringLossReport` / `lift(document, origin) → RoutingRequest` — routing preferences arriving over a protocol lift with `authority ≤ external` (ADR-0033 minting rules) and are consumable only by policy fields typed as *preferences*.

**Failure modes (typed, never warnings):** `NoProfile{model_ref}`, `ExpiredProfile{profile_ref, status}` (unless `intent_ref` recorded), `CapabilityUnmet{model_ref, missing[]}`, `CapabilityUnknown{model_ref, unknown[]}` (refused unless the policy's `allow_unknown` conditioned rule exists), `MigrationLossExceeded{dropped, bound}`, `InsufficientBudget{dimension}` (from `reserve`), `NoPrice{model_ref}` (only when the policy reads cost), `ChainExhausted{attempted[]}`, `PolicyInvalid{rule_id, reason}` (link-time: missing debt record, unknown kind, candidate outside the role table).

### 6.3 Data-model sketch

- `RoutingRequest{model_call_id, run_id, role: ModelRole, task_class?: TaskClassRef, required_capabilities: set<CapabilityKey> (derived by the compiler from the `ModelSurface` this call will render: e.g. `native_function_calling`, `image_input` if the assembled context carries images, `context_window ≥ occupancy + reserve`, `structured_output` if a validator demands it — never hand-written), budget_view: {remaining: ResourceVector, budget_id}, latency_target?: {p50_ms?, p95_ms?, ttft_ms?}, quality_prior_ref?: Ref<QualityPrior>, trajectory_digest?: {turns, tool_error_rate, validator_fail_count, last_stop_reason} (SWE-Router/AgentRouter-class inputs; typed, computed by the kernel from the ledger), preferences?: {cost_priority?, speed_priority?, intelligence_priority?, hints[]} (lifted, `authority ≤ external`), context_label: Label (ADR-0034 — routing on tainted preferences is a flow the monitor sees)}`.
- `RoutingDecision{decision_id, model_call_id, role, selected: ModelRef{profile_ref, provider_model_id, serving_route, effort?}, reservation_id, policy_ref: {variant_ref, version_id}, rule_ids_fired[], candidates_considered: [{model_ref, verdict ∈ {selected, rejected{reason ∈ {no_profile, expired_profile, capability_unmet, capability_unknown, migration_loss, insufficient_budget, no_price, cooldown, policy_excluded, lower_score}}}, score?: decimal-string}], inputs_read[], deviation: bool (selected ≠ configured primary for role), relower_required: bool}`.
- `RoutingPolicy{policy_id, version, content_hash, role_scope: set<ModelRole>, kind ∈ {static, role_table, fallback_chain, capability_filter, cost_cap, latency_cap, quality_target, health_aware, learned}, params (per kind; e.g. `fallback_chain{targets[], max_reroutes, allowed_classes[]}`, `cost_cap{max_spend_per_call: Money, pricing_table_ref}`, `latency_cap{p95_ms, health_window}`, `quality_target{metric, min_estimate, prior_ref}`, `learned{predictor_ref: ModelRef | Validator, feature_set[], threshold}`), error_actions: map<ModelErrorClass, {retry_same{max}, reroute, compact_then_retry, give_up}>, max_migration_loss: {dropped_items ≤ n, no_in_flight_tool_call: true}, allow_unknown?: ConditionedRule, conditioned_rules: [HarnessRule with AssumptionDebtRecord], ext?}` — a **data document** (ADR-0023/0024: MUST-data), composable as an `ordered-many` pipeline (`capability_filter → health_aware → cost_cap → quality_target → fallback_chain`) whose element order is a semantic op (OQ-073). Every kind that keys on a model family or provider (`role_table` family priorities, `learned`) is a conditioned rule with a debt record whose `expiry_condition` includes `model_version_change` (T-LCD-05).
- `ModelErrorClass` (minimum set the router needs; C1 owns the emitted enum — CF raised): `transient{rate_limit, overloaded, server_error, network, timeout, stream_interrupted}`, `permanent{invalid_request, context_overflow, content_policy, auth, not_found, unsupported_capability, transcript_incompatible}`, `budget{insufficient, exhausted}`, `unknown`. Default `error_actions`: `transient → retry_same{max from F2} then reroute`; `context_overflow → compact_then_retry then reroute to a larger-window candidate`; `content_policy → reroute` (litellm) or `give_up` (policy choice); `auth/not_found/unsupported_capability/transcript_incompatible → reroute` (never retry_same — goose markers); `invalid_request → give_up` (a profile bug, CF-044); `budget → give_up` (never loosen; ADR-0040).
- `HealthView` — a materialized view (ADR-0026 `project(run | fleet, view_kind = health)`) over `model.call.attempt.*` events (ADR-0043 M4): per `(provider_model_id, serving_route)`: `attempts, failures_by_class` in a sliding window, `p50/p95 latency_ms`, `cooldown_until?` with the litellm rule as default parameters (429 ⇒ cooldown; failure rate > θ over ≥ n requests ⇒ cooldown; never for a role with one candidate). Never a separate store of truth (ADR-0042).
- `QualityPrior{prior_id, scope: {model_ref, task_class?, harness_def.semantic_id?}, metric: MetricDeclaration ref, estimate, interval, n, source_ref: FittedSurfaceReport | ComparisonReport, valid_until, unknown_levels[]}` — produced by J4 from the compatibility surface (ADR-0012); consumed read-only; `unknown` refused.
- **Ledger events** (`model` category, `plane = model_boundary` per CF-030): `model.route.decided{…RoutingDecision fields…}` (new class; `durability = durable`; min observability `ledger`; lowering to the Hosting ABI: `none`); `model.rerouted{model_call_id, from: ModelRef, to: ModelRef, reason ∈ {transient_exhausted, permanent{class}, budget, cost, latency, capability_unmet, operator, policy}, attempt_no, relowered: bool, relower_event_ref?, decision_ref}` (payload extension of the WS-B1 row — CF); `model.surface.relowered` unchanged (ADR-0019). Run-manifest end state gains `model_set_realized` and `routing.deviation` (CF to B1/L4).
- **Ensemble procedure** (C2): `EnsembleProcedure{kind ∈ {sample_k_vote, mixture_of_agents, cascade}, members: [{role, count, model_binding: ModelRole}], reducer ∈ {majority_deterministic, validator_ref (judge, ADR-0047), first_passing_validator (cascade)}, budget: Ref<Budget> (slice mode, ADR-0040), stop_rule}` — a HIR `Procedure` at the `delegate` decision point (ADR-0012 β); each member call is its own `model_call_id` routed by `select`; the reducer's verdict is a `verification.validator.verdict`; the ensemble never runs inside `select`.

### 6.4 Compatibility guard (must hold before any call under a new target)

G-1 **Profile exists and is live:** `resolve_profile(model_ref)` yields exactly one profile by selector precedence (ADR-0020 decision 1); `expiry.status ∈ {active, expiring}`; `expired` admissible only with `intent_ref` recorded in the decision (ADR-0020 decision 7); `retired` never. G-2 **Capability coverage:** `required_capabilities ⊆ {c : capabilities[c] ∈ {declared: supported, probed: supported}}`; `unknown` ⇒ `CapabilityUnknown` unless `allow_unknown` (conditioned, debt-recorded); `DRIFT` ⇒ refused, mirroring OQ-071's pending answer for compilation (OQ raised). G-3 **Transcript migration bound:** projected `relower` `TranscriptMigration` must satisfy `max_migration_loss`; an in-flight tool call (proposed, not yet observed) is never dropped — the reroute waits for the effect's terminal event (ADR-0030: every commit resolves). G-4 **Budget:** `reserve(budget_id, max_output(profile), holder)` succeeds; on `InsufficientBudget` the policy may try a cheaper candidate but never `amend` (ADR-0040 decision 6). G-5 **Price:** a pricing row exists when the policy reads cost (ADR-0039 `NoPrice`). G-6 **Authority:** a routing preference of `authority ≤ external` can *exclude* candidates it names but never *add* a candidate outside the role table (attenuation, ADR-0034). G-7 **Hosted participants:** the router is native-only; for `OpaqueProcess` the only model coordinate is the interception override (ADR-0013), recorded as `configuration-level`; routing metrics are `n/a` (T-LCD-15).

### 6.5 Routing as a Lab factor

`model_set_realized` and `routing.deviation` join the results row (ADR-0045) as *observed* fields; a pre-registered `Design` states one of `{exclude_deviated, stratify, pool_with_flag}` (parallel to OQ-034 for DRIFT). Routing experiments compare *policies* as component-level factors under matched-total budget with `benefit_kind = artifact_benefit` (ADR-0046); replay-based routing scores are inadmissible (`ComparisonReport.budget_match.status = unmatched`-class refusal, new reason `replayed_trajectory`) — Replay Gap mechanism. `harness_overhead.routing` is always reported beside task cost (ADR-0043).

### 6.6 Acceptance-criteria sketch

- **AC-C2-1 Static route (C0/Stage 0).** With a one-entry role table and `policy.kind = static`, every model call yields exactly one `model.route.decided` with `candidates_considered = [selected]`, `deviation = false`, and a `reservation_id`; the run's `model_set_realized` equals the configured table.
- **AC-C2-2 Guard refusals are typed.** For each of G-1…G-6 a fixture produces the named `RoutingRefusal`; none is emitted as a warning or as a silent fallback to the primary.
- **AC-C2-3 Charge equals decision.** For every `model.call.completed`, the charge's `model_ref` equals the `selected` of the latest `model.route.decided`/`model.rerouted` for that `model_call_id` (ledger projection test; fails the ledger otherwise — R-ACC-2 pattern).
- **AC-C2-4 Reroute ordering.** A cross-profile reroute appends, in `seq` order: `model.call.attempt.failed` → (optional `context.compaction.*` under the old profile) → `model.surface.relowered` → `model.rerouted{relowered = true}` → `model.call.attempt.started` under the new `profile_ref`; a same-profile reroute has `relowered = false` and no `relowered` event.
- **AC-C2-5 No retry on permanent classes.** A `transcript_incompatible`/`unsupported_capability`/`invalid_request` failure never produces a second attempt on the same target (goose marker mechanism, as a class, not a substring).
- **AC-C2-6 Error actions are data.** The `error_actions` table is part of the policy document's `content_hash`; changing an action is a `HirDiff` semantic op; a message-text regex anywhere in the router is a T-LCD-01-class defect.
- **AC-C2-7 Debt on every conditioned routing rule.** `link` refuses a `role_table`/`learned` policy whose family- or provider-keyed rule lacks an `AssumptionDebtRecord` (`LinkError.missing_debt_record`, ADR-0020 decision 4); "retire routing rule R" is one `relower`-class recompile.
- **AC-C2-8 Deviation is a factor.** Two arms differing only in `fallback_chain` produce results rows with `routing.deviation` populated; the report generator refuses to pool `deviation = true` and `false` rows without a pre-registered policy.
- **AC-C2-9 Fail-fast default for experiments.** A pre-registered `Design` with `routing_policy = fail_fast` yields `outcome_class = infrastructure_failure` on provider failure rather than a silent reroute; the stratified report shows both arms' outage counts.
- **AC-C2-10 Ensembles are k ledgered calls.** An `EnsembleProcedure{sample_k_vote, k}` produces exactly k `model_call_id`s, each with its own `model.route.decided`, one `verification.validator.verdict` from the reducer, and a `budget_slice` whose consumption equals the sum of member charges; a comparison of k vs 1 is refused without `MatchSpec.mode = matched_total`.
- **AC-C2-11 Determinism.** `select` on identical `(request, views, policy)` yields identical `decision` minus `decision_id`/`reservation_id` (supports `deterministic_replay` variants, ADR-0028).
- **AC-C2-12 Protocol round-trip.** `lower(request, mcp_model_preferences)` then `lift` recovers `preferences` exactly and reports `required_capabilities`, `budget_view`, `role` as `no_slot` loss (T-LCD-11).

### 6.7 Build-stage suggestion and dependencies

- **C0 / Stage 0–1:** `router` class contract, `RoutingRequest`/`RoutingDecision` schemas, `static` + `role_table` kinds, compatibility guard G-1/G-2/G-4, `model.route.decided`, `ModelErrorClass` minimum set (with C1), `model_set_realized` in the run manifest. This is the "ships behind a stable contract" slice (doc 3 §1.3) — the Stage 0 loop must bind *a* model and the trivial router is how it does so.
- **C0 / Stage 3:** AC-C2-3/-4/-8 executable; `routing.deviation` in results rows; `HealthView` projection.
- **C1 / Stage 5 (with C3 profiles):** `fallback_chain`, `capability_filter`, `cost_cap`, `latency_cap`, `quality_target`, `health_aware` kinds; G-3 migration bound with `relower`; `on_attempt_failed` wired to F2; `explain`; MCP/ACP lowering (with E4).
- **C2 / Stage 4+ (with F3):** `EnsembleProcedure` kinds; cascade with validator-first reducer; hosted interception override recorded as `configuration-level` (J6).
- **C4:** `learned` policies deployed only through the evolution pipeline (I5) with `SearchBudgetRecord`, held-out artifact benefit and `model_version_change` expiry; F4's value-of-compute may *call* `select` but never replaces the guard.

Depends on: WS-C1 (error classes, `model_ref.serving_route`, attempt events — OQ-072/CF-044 must resolve so the router hands the gateway a *target*, not serialisation knowledge), WS-C3 (profile resolution, `capabilities`, expiry, `successor_ref` proposal), WS-L2 (`reserve`, pricing table, `remaining`), WS-F2 (attempt counting, backoff, stop rule; calls `on_attempt_failed`), WS-A4/D1 (`relower`, `TranscriptMigration`, OQ-067), WS-B1 (event classes and manifest fields), WS-I1 (M3/M4, `harness_overhead.routing`), WS-I2/J3/J4 (`routing.deviation` in `Design`/results; `QualityPrior` from fitted surfaces), WS-F3 (ensemble delegation), WS-H1 (routing on lifted preferences is a flow check), WS-J6 (interception override), WS-E4 (MCP/ACP lowering). Nothing here depends on the ADR-0050 ecosystems; the only host-ecosystem requirement is that the kernel can compute a sliding-window projection over its own ledger — satisfied by the ADR-0050 kernel ecosystem by construction of ADR-0026.

**T-LCD statement.** Satisfies T-LCD-01 (routing rules are data; provider/family branches are conditioned rules), T-LCD-05 (debt on every conditioned routing rule; expiry `model_version_change`), T-LCD-06 (no hosting edge; hosted rows `n/a`), T-LCD-08 (contract receives profile + accounting), T-LCD-09 (`model_set_realized`, `routing.deviation`, policy as component-level factor), T-LCD-11 (MCP/ACP lowering with loss), T-LCD-12 (operations only), T-LCD-14 (ensembles and routing comparisons refuse unmatched budgets; replay refused), T-LCD-15 (routing metrics class-scoped). Does not itself satisfy T-LCD-13 — mitigated: when a policy asks the *model* to request escalation (β = model at a hypothetical `route` point), that request is a `ContextItem` artifact with delivered/activated/followed events (OQ raised on the DecisionPoint).

## 10. Confidence

**Medium-high** for the contract shape and the C0 slice: the retry/reroute split, typed fallback by error class, cooldown as derived state, served-model attribution and role-shaped utility routing are each precedented in Tier-B production source at pinned commits (litellm, opencode, goose, codex), and the guard composes only ratified objects (ADR-0019/0020/0039/0040). **Medium** for the routing-deviation factor and the live-only evaluation rule: the mechanism is corroborated by three independent lines (provider transcript rejection, Harness-Bench model-conditioning, The Replay Gap) but the strongest quantitative source is a 2026 single-author `provisional` preprint. **Low** for any claim that routing *improves* outcomes: the field's own 2026 benchmark says most routers do not beat simple baselines, which is why learned policies are C4-gated and no performance number is load-bearing.
