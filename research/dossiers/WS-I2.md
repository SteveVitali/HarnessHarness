## 1. Scope & boundary

This workstream decides the **C0 measurement backbone**: (i) the abstract **experiment/factor model** — how model × harness × environment × task × budget × seed are represented as explicit factors, cells, replicates and arms, and what a "design" is as data; (ii) the **scorecard specification** — for each of the eight doc 2 §8 dimensions (capability, reliability, grounding, efficiency, autonomy, security, portability, evolvability) the concrete metrics, the ledger events or oracles they are measured from, the aggregation ladder (replicate → task → configuration → arm → comparison) and the mandatory **distributional reporting** (pass^k, CIs, tails, per-task distributions); (iii) the **oracle taxonomy** (executable, end-state, output-check, trace-predicate, protocol-check, judge, human, teacher-relative, reference-relative) with a declaration schema and admissibility rules; (iv) the **matched-budget comparison protocol** as a normative contract, including the separation of search-time benefit from artifact benefit and transfer; (v) the **minimum experimental design** as acceptance criteria for the Harness Lab at Stage 3; (vi) **class-aware metric applicability** so that native and hosted participants (ADR-0001) are scored on one plane with `n/a` never 0 (T-LCD-15); (vii) answers to OQ-016, OQ-018 (measurement half), OQ-037 (gate vs checklist), OQ-046 (per-sample vs per-run scorer boundary) and the dynamic half of OQ-036 (opacity telemetry).

It explicitly leaves to neighbours: the typed `Validator`, `Budget`, `Observation` entities (WS-A3 — this dossier consumes A3's `Validator.kind ∈ {executable, schema, predicate, judge, human}` and A3's static `opacity_ratio`); the event envelope and the `measurement.*` / artifact-chain event classes (WS-B1 — consumed verbatim); the budget-vector dimensions and cost provenance/confidence (WS-L2 — not yet on disk; A3's `Budget.dimensions` used as the working list); telemetry emission and OTel export (WS-I1); the bundle format that pins task data, grader code and traces (WS-I3); benchmark/environment adapters and which suites are integrated (WS-I4 — non-goal N13: never author benchmarks); the sweep engine's scheduling and budget enforcement machinery (WS-J3); the analysis engine's statistical model forms, Pareto and surface fitting (WS-J4 — this dossier fixes *what must be reported*, J4 fixes *how estimated*); the results store schema (WS-J5); judge/critic components (WS-G3); execution-alignment detectors (WS-G2); the Hosting ABI and capability probes (WS-J6); evolution-service gates that *apply* the protocol here (WS-I5); every language/runtime question (WS-L1). ## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Every mature evaluation plane implements the same three-level aggregation ladder, and the differences between them are exactly the decisions this dossier must fix.** Inspect (S-136) scores each *sample* once per *epoch*, reduces epochs with a declared reducer (`mean`, `max`, `pass_at(k)`, `pass_k(k)`, `at_least(n)`, `median`, `mode`), then computes dataset metrics with an SE (`stderr`, `stderr(cluster=)`, `bootstrap_stderr`). τ-bench (S-127/S-240) runs `num_trials` per task and reports average reward plus pass^k for every k ≤ n. Harbor (S-132) runs `n_attempts` per task and reduces rewards with `mean/max/min/sum` over `RewardDict`s. HAL (S-134) runs once per task by default and reports accuracy, total cost, latencies and wall-clock. AgentDojo (S-241) computes a plain mean over (user task × injection task) booleans. **Only Inspect computes a standard error; only τ-bench and Inspect compute pass^k; none pairs by task across arms; none matches budgets.** The ladder (replicate → task → configuration → arm) is therefore precedented and cheap; the *reporting obligations* (CI, pairing, distribution, budget match) are the new contract, and doc 2 §8 already demands them.

**F2 — pass^k and pass@k are duals with known unbiased estimators, and the field has documented a live misuse.** τ-bench defines pass^k = E_task[C(c,k)/C(n,k)] (S-127; implemented at `tau_bench/run.py` L194–199); Chen et al. define pass@k = 1 − C(n−c,k)/C(n,k) (S-235; implemented at Inspect `reducer.py` L176–189 with an explicit NaN when fewer than k epochs exist). S-238 shows benchmarks substituting the number of unit tests for n, inflating 0.96–0.98 to 0.00–0.12 when corrected, and shows single-rollout proxies rank agents poorly (ρ = 0.417). Mechanism conclusions: (i) n must be *independent runs* of the same (configuration, task), never sub-units of one run; (ii) the estimator is undefined for k > n and must render `n/a`, not 1.0 or 0; (iii) reporting pass^k requires n ≥ k replicates, so the replicate count is a design parameter, not a default. Inspect's NaN and Omnigent's `NOT_APPLICABLE` are the source precedents for the `n/a` rule that T-LCD-15 already requires for class inapplicability; this dossier extends it to *estimator-undefined* cells.

**F3 — Variance is large, heavy-tailed, and horizon-dependent, so a mean without an interval is not a measurement.** τ-bench: 61 % pass^1 → 25 % pass^8 for one model (S-127, Tier A). S-236: capability and reliability rankings diverge as task duration grows; higher-capability models show *higher* failure rates on long tasks; a "meltdown onset point" exists. HAL found reasoning effort *reducing* accuracy in most runs and agents gaming tasks (S-135) — behaviours only visible in logs and tails. HAL's own utilities compute `S_tail` at P50–P99/max over error severities and `FaultEvent{recovered, recovery_time}` under injected faults (S-134), which is production evidence that tails and recovery are measurable from traces. METR fits a logistic curve of success vs human task time with bootstrap CIs (S-128). Miller (S-234) gives the CLT/clustered/paired formulas; Inspect implements the clustered SE with a finite-cluster correction. Mechanism conclusion: the scorecard must carry, for every metric, a point estimate, an interval (CLT or clustered-by-task, bootstrap where the estimator is non-linear such as pass^k), the per-task distribution, and tail statistics; and reliability is its own dimension, not a footnote on capability.

**F4 — Budget is a factor that interacts with harness, and search budget is a distinct resource from evaluation budget.** S-072 is the cleanest instance: the same treatment moves F2PF from 28 % to 49 % at a 20 k window and vanishes at wide windows. S-083 reframes evolution as search and shows that once *feedback and inference budgets* are matched against test-time scaling, evolution's advantage is inconsistent and transfers weakly. S-092 shows that *how* a search budget is allocated across components changes outcomes (uniform splitting freezes every slot). PRISM (S-093) reports lift *as a function of budget* (`RelLift95(B)`) and repeatability. All four are `provisional`, but they converge with doc 2 §8 (Tier-B synthesis) and with the ratified T-LCD-14 on one mechanism: a comparison is only interpretable if (a) the per-run evaluation budget is identical across arms, (b) the search budget that produced each arm's artifact is recorded separately and, for search-vs-search claims, matched, and (c) benefit is measured on a frozen artifact on held-out tasks. HAL's cost accounting (unified token counting, pinned price date) and Harbor's per-attempt `cost_usd` are the source precedents for *measuring* consumption; no audited plane *enforces* matching — the engine precondition is `novel` as an enforced rule.

**F5 — Deterministic oracles exist for most coding/terminal/tool tasks and for security, and the field keeps judges physically separate.** Terminal-Bench 2.0 (S-124) ships "comprehensive tests for verification" per task; Harbor reads a numeric reward file the verifier writes; τ-bench compares end-state database equality plus an output substring check; AgentDojo decides utility and security from `(model_output, pre_environment, post_environment)` or from traces; SWE-bench runs fail-to-pass/pass-to-pass tests (S-123/S-162). Judges appear as *separate* scorers (Inspect `model_graded_*`), separate analysis jobs (Harbor `analyze`), or separate modules (HAL `llm_log_analyzer` vs `compliance_checkers`). Two failure modes are documented for judges: correlation with the tested agent's failure modes (doc 2 §8), and *no usable signal* between similarly powered models (S-068). Mechanism conclusion: oracle class is a property every metric must declare; headline capability at C0 uses deterministic classes only; judged metrics carry `detector = judged` with a judge configuration that is itself a Validator of `judge` kind with a `ProfileRef` and assumption-debt record (WS-A3 §6.1 item 10; WS-A2 ADR-3).

**F6 — Error handling in evaluation code silently converts "not measured" into "failed", and the scorecard must forbid it.** Harbor `aggregate_reward_dicts` maps a `None` reward to 0; DSPy `Evaluate` scores exceptions as `failure_score = 0.0`; AgentDojo maps provider errors to `utility=False, security=True`; HAL flattens prompt-sensitivity variants into a mean. Each is defensible for a leaderboard and wrong for an instrument: an infrastructure failure, a budget exhaustion, a verifier crash and a genuine wrong answer are different outcomes that must stay distinguishable (Harbor does keep `exception_info` and `n_errors` separately; τ-bench keeps reward and trials separately). The ledger already gives the distinguishing facts (`lifecycle.run.finished{status, stop_reason}`, `control.budget.exceeded`, `verification.validator.verdict`). Mechanism conclusion: every run has an **outcome class** `{scored, budget_exhausted, infrastructure_failure, oracle_failure, refused, cancelled}` and every metric declares how each class enters its aggregate (counted as failure / excluded / reported separately); the default for non-`scored` classes is *excluded with a denominator note*, never silently 0.

**F7 — Process metrics are computable from the B1 ledger without new instrumentation, for native participants; for hosted participants their availability is exactly the observability level.** Tool-error rate (`action.tool.completed{status}`), invalid-action rate (`action.tool.rejected`), retries (`control.retry.scheduled`), context usage and opacity per call (`context.assembled{items, opacity_ratio}`), evidence alignment (`verification.claim.reconciled{agreement}`), state divergence (`action.world_state.patch` vs claims), budget consumption (`control.budget.consumed`), interventions (`security.permission.decided{decider=human}`), duplicate effects (two `action.effect.committing` for one `idempotency_key` without `compensated`), crash/recovery (`lifecycle.run.resumed{recovery_decision}`), compliance chain (`artefact.delivered/activated/followed`). Hosted participants supply `events` (session-ABI: tool calls, permission requests, usage), `model_io` (interception) or `end_state` (container-installed) — WS-A1 F2 — so each process metric's `requires_observability` determines its availability; the B1 rule "expected at observability level X, else `n/a`" applies unchanged.

**F8 — Adaptive and reduced evaluation is real and useful for *search*, but it estimates rank, not effect.** Task-CoEvolve cuts search-time evaluations ~80 % with Hájek/anchored estimators but its estimator's rank correlation with full-set scores is 0.13 at ρ = 7 % (S-082); S-237 preserves *rank* fidelity with 44–70 % fewer tasks while absolute scores shift under scaffold change. Mechanism conclusion: adaptive selection is admissible inside an arm's `search_budget`; a reported *artifact benefit* must come from the full pre-registered held-out set, or carry an `estimated` flag with the inclusion probabilities and estimator named. This is the measurement-side counterpart of ADR-0002's "separate search-time from artifact benefit".

**F9 — Compliance is measurable as a chain (OQ-018, measurement half), and its deterministic stages are class-scoped by observability.** WS-A2 fixed the semantics; the source precedents (OpenHands `SystemPromptEvent`/`activated_skills`, AIOS injection log) exist for delivered/activated; `followed` is deterministic only via a `validates` edge. The metrics are therefore: delivery rate (trivially 1 for native; for hosted = fraction of supplied artifacts the ABI confirms delivered), activation rate `P(activated | delivered, valid)` (deterministic for skills/retrievals/tool surfaces; `n/a` for kinds with `activation_observable = false`), following rate `P(followed | activated)` (deterministic via validator else judged), and Pass-When-Activated (outcome-conditional, deterministic — S-088's companion). Prediction of compliance (the other half of OQ-018) remains open with WS-C3.

**F10 — Teacher-relative lift is an oracle class for label-free settings, admissible only as a calibrated, provisional C4 tool.** S-068 shows convergence-toward-teacher correlates with a gold standard in one domain while peer LLM judging gives no signal. It is not a substitute for executable oracles where they exist; it is a way to score *learning harnesses* (WS-I8/I5) when labels are sparse. Mechanism status: single team, one domain → `provisional`; representable now as an `OracleDeclaration{class: teacher_relative}` with a mandatory calibration record.

## 5. Disconfirming evidence & negative results

**Against distributional reporting as a C0 requirement ("it is too expensive").** HAL ran 21,730 rollouts for ≈ $40 k with *one* run per cell and no CIs (S-135); Harbor defaults to `n_attempts = 1`; Terminal-Bench 2.0 reports single leaderboard numbers. Requiring n ≥ 5 replicates multiplies the bill and the wall-clock. *Why this does not overturn:* the instrument's purpose is attribution, and F2/F3 show that single-run numbers rank agents with ρ ≈ 0.42 and hide 2–3× reliability gaps; a cheaper design is still a *design* (pre-registered, with its n recorded) and the contract lets a cell be reported with n = 1 provided pass^k and intervals render `n/a`/wide rather than being omitted. Adaptive/reduced evaluation is admitted inside search budgets (F8). The residual cost is real and is carried as an open question on default replicate counts per stage (OQ-121) and as the Bayesian alternative reporter (S-239) that converges with fewer samples.

**Against pass^k as the canonical reliability metric.** S-239 argues pass@k-style rankings are unstable at small n and proposes posterior estimates with credible intervals; pass^k is also undefined for k > n and degenerate at n = 1. *Why this does not overturn:* pass^k is a Tier-A definition with a reference implementation and an intuitive operational meaning ("succeeds every time in k tries"); the Bayesian reporter is admitted as an alternative *aggregation* over the same per-task success counts (the data model stores c and n per task, so any estimator can be recomputed), and the `n/a` rule handles undefined cells. The contract fixes *what is stored* (per-task success counts and per-run values), not one estimator.

**Against matched-budget comparison as an engine precondition.** (i) Budgets are multi-dimensional and arms rarely consume identical amounts even when limits match; strict equality would refuse most real comparisons. (ii) Some claims are legitimately about *cost-efficiency* — a harness that spends more to succeed more is a Pareto question, not a matched-budget question. (iii) S-092 shows that allocation *within* a search budget matters, so "matched total" can still be unfair. *Why this does not overturn:* the precondition is on declared **limits** (hard caps identical across arms — `UnmatchedBudget`), while *consumption* is measured, reported as a distribution, and flagged `budget-imbalanced` beyond a declared tolerance; cost-efficiency claims are expressed as Pareto/cost-adjusted views on the same runs (HAL precedent), never as a bare "A beats B"; allocation is recorded as part of the arm's `search_budget` record so S-092-style critiques become checkable. The rule is exactly what T-LCD-14 ratified; this dossier gives it a tolerance and a reporting shape.

**Against deterministic-only headline oracles.** Many valuable dimensions (quality of a refactor, clarity of a report, "did it follow the skill") have no executable oracle; refusing judges removes most of the grounding and compliance signal at Stage 3 (WS-A2's own third-link risk). HAL's LLM log analysis found behaviours no verifier caught (S-135). *Why this does not overturn:* judges are admitted for every dimension, with three obligations — `detector = judged` labelling, a judge snapshot distinct from the beneficiary model, and a calibration record against a deterministic oracle on a subset — and they are excluded only from the *headline* capability number at C0. S-068's finding that peer judges give no signal is the reason calibration is mandatory rather than optional.

**Against a fixed eight-dimension scorecard.** Dimensions overlap (reliability vs grounding vs security), some are hard to populate for hosted participants (evolvability is mostly `n/a`), and new dimensions (belief divergence S-148, horizon reliability S-236) keep appearing. *Why this does not overturn:* the eight dimensions are doc 2 §8's ratified frame and are a *reporting grouping*, not a closed type: metrics are the first-class objects; a dimension is a tag on a `MetricDeclaration`; adding a dimension is an ADR, adding a metric is a registry entry. Sparse hosted columns are the correct picture (T-LCD-15), not a defect.

**Against "seed" as a factor.** Provider-hosted models may not honour sampling seeds; even when honoured, environment nondeterminism (timing, network) and non-replayable control loops (WS-B1 ADR-3) make two runs with the same seed different. *Why this does not overturn:* the factor is formalized as a **replicate index** with recorded seed material (harness RNG seed, requested sampling seed, environment image digest); pairing across arms is by *task* (and by replicate index only where all arms' participants declare `seed_honoured`); this keeps WS-A2's κ tuple intact while stating honestly what a seed controls (CF-095).

**Against class-scoped `n/a` (from the hosted side).** A hosted participant with model-boundary interception has *complete* model I/O; refusing it component-level metrics looks like an artificial handicap. *Why this does not overturn:* WS-A2 ADR-2 settled that class is transparency of H; `model_io` upgrades observability, so judged compliance and cost metrics become available, but attribution to a component the Lab cannot name stays `n/a`. The scorecard reports *why* a cell is `n/a` (`reason ∈ {class, observability, estimator_undefined, not_run}`) so the handicap is visible and typed.

**Negative results from the audit.** (i) No audited plane pairs arms by task or reports paired differences; (ii) none enforces budget matching; (iii) none records outcome classes distinctly in its aggregate (Harbor/DSPy/AgentDojo coerce to 0/False); (iv) none reports interaction effects; (v) HAL — the strongest Tier-A plane — reports no intervals at all. The contract's novelty is therefore in enforcement and reporting discipline, not in any estimator.

## 6. Recommendation for the spec

### 6.1 Structural decisions

1. **Metrics are first-class registry objects; dimensions are tags.** The scorecard is the projection of the metric registry onto the eight doc 2 §8 dimensions. Every metric has exactly one `MetricDeclaration` (C0/Stage 1 per phase-0 §5.5), which is the *complete* declaration reconciling the three partial forms on disk (WS-L7 `applies_to`; WS-A1/A2 `requires_observability, applies_to_classes, admissible_granularities, detector_classes_allowed`) plus the fields this dossier adds: dimension, level, value type and direction, `oracle_classes_allowed`, `replicate_reducer`, `interval_method`, `outcome_class_policy`, `headline: bool`, `veto: bool`, cost. (CF-094 records the reconciliation.)
2. **Six explicit factors, one replicate axis.** `model_snapshot` (with roles, per WS-A2 CF-08), `harness` (at a declared comparison granularity: component-level variant/parameter, configuration-level coordinate, or product-level version), `environment` (image digest + fault/perturbation profile), `task` (suite → task → instance, with split label), `budget` (the vector of hard limits), `replicate` (index with recorded seed material). κ = (M, h, p, E, B, seed) from WS-A2 is preserved; `seed` is read as the replicate axis (§5). Interaction effects are representable because every result row is keyed by the full tuple (T-LCD-09).
3. **Outcome classes before metrics.** Every run carries `outcome_class ∈ {scored, budget_exhausted, infrastructure_failure, oracle_failure, refused, cancelled}` derived from ledger facts; each metric declares how each class enters its denominator. Default: only `scored` (and `budget_exhausted` for capability, since running out of budget *is* a harness outcome) count; others are excluded and their counts reported beside the metric.
4. **Oracles are declared components with a class.** `OracleDeclaration{class ∈ {executable, end_state, output_check, trace_predicate, protocol_check, judge, human, teacher_relative, reference_relative}, deterministic, requires_observability, verdict_type, evidence_out, cost_attribution, calibration_ref?}`. Headline capability at C0 admits only `{executable, end_state, output_check, trace_predicate, protocol_check}`. Judge oracles are WS-A3 `Validator{kind: judge}` with their own `ProfileRef` and assumption-debt record (T-LCD-05 reflexively).
5. **Distributions are the reported object; the mean is one summary.** For every metric at configuration level the report carries: point estimate; interval (`interval_method`); per-task distribution (histogram/quantiles); for binary metrics the per-task success counts (c, n) so pass^k for all k ≤ n and any alternative estimator can be recomputed; tail statistics (P95/P99/max of cost, wall-clock, severity; catastrophic-failure rate); and `n` per cell. A report that omits any of these is not a scorecard.
6. **Comparisons are paired and budget-matched, and search is accounted separately.** The only reportable effect is WS-A2's paired Δ at matched budget (T-LCD-14). Every arm carries `eval_budget` (per-run hard limits, identical across compared arms) and `search_budget` (everything spent producing the arm's artifact: rollouts, feedback labels, judge calls, optimizer model calls). Artifact benefit, search-time benefit and transfer are three distinct rows (§6.4).
7. **Veto invariants are separate from averaged dimensions.** Security and durability properties that doc 2 §8 says can fail independently of task success — secret leakage, authority widening, irreversible effect outside scope, duplicate side effect after retry, inconsistent durable state, revoked-policy action — are `veto: true` metrics: a run that trips one is reported as *success-with-veto* and excluded from the headline success rate, never silently counted as success (AgentDojo's utility/security split generalized).
8. **Both classes on one plane.** A scorecard row per configuration regardless of class; cells render a value or `n/a{reason}`; hosted rows additionally carry `capability_vector` strata and cost `confidence` (WS-L2, OQ-033); component-level and ledger-dependent metrics are `n/a{class}` for hosted rows (T-LCD-15; WS-A2 admissible granularities).

### 6.2 Experiment/factor model (abstract data model)

- `Factor{name, kind ∈ {model_snapshot, harness, environment, task, budget, replicate}, granularity? ∈ {component-level, configuration-level, product-level} (harness only), levels: [Level], role? (model_snapshot: primary | router_alternate | subagent | judge)}`; `Level{id, ref (content address of the thing varied — variant, profile, image, suite, budget vector), label}`.
- `Design{id, kind ∈ {paired, full_factorial, fractional_factorial, one_factor_at_a_time, adaptive_search}, factors: [Factor], blocking: [FactorName] (default [task]), replicates_per_cell: n ≥ 1, pairing: by_task | by_task_and_replicate, seed_policy: {harness_rng, requested_sampling_seed, seed_honoured_required: bool}, held_out_split_ref?, pre_registration: PreRegistration}`.
- `PreRegistration{registered_at, hypothesis, primary_metrics[], equivalence_margin? (T-LCD-03), min_n, analysis_plan_ref, task_split_hash}` — immutable once the first run of the experiment opens (`measurement.experiment.bound` in B1 references it).
- `Configuration` (WS-A2 §6.4, unchanged): `{id, model_snapshot(s) with roles, harness_definition_ref | product_version, profile_ref, environment_image, budget_vector, seed_material}`; `id` is a content address.
- `Arm{id, hypothesis, design_ref, configurations[], eval_budget: BudgetVector (hard limits), search_budget: SearchBudgetRecord, artifact_ref (frozen harness def / product version under test), provenance}`; `SearchBudgetRecord{rollouts, model_calls, tokens, feedback_labels_used, judge_calls, wall_clock, allocation: map<component|slot, share>, adaptive_selection?: {estimator, inclusion_probabilities_ref}}`.
- `Cell = (Arm, Configuration, Task)`; `Run` = one replicate of a cell (B1 `RunId`; manifest carries `configuration_id`, `arm_id`, `replicate_index`, `seed_material`, `budget`).
- `RunOutcome{run_id, outcome_class, stop_reason, budget_consumed: BudgetVector, veto_tripped: [MetricName]}` — a materialized view over B1 `lifecycle.run.finished`, `control.budget.*`, `security.*`, `action.effect.*`.
- `MetricValue` = B1 `measurement.metric.emitted{metric_ref, value, applies_to, oracle_ref?, detector?, confidence?, evidence_ref?}` — one per (run, metric); values are typed (`bool | decimal | verdict ∈ {C, I, P, N} | vector | n/a{reason}`).
- `ResultsRow` (J5 projection): `(configuration_id, arm_id, task_id, replicate_index) → {outcome, metric values, budget consumed, cost{amount, provenance, confidence}}`.
- `ScorecardReport{experiment_ref, rows: [ConfigurationSummary], comparisons: [ComparisonReport], generated_from: (run_ids, results watermark), price_table_version, metric_registry_version}`; `ConfigurationSummary{configuration_id, class, n_runs, outcome_counts, per_metric: {point, interval{method, level, lo, hi}, distribution_ref, tails, success_counts (c,n) per task, n_a_reason?}}`.
- `ComparisonReport{arm_a, arm_b, metric, pairing, paired_effect{point, interval, method}, per_task_effects_ref, budget_match: {limits_equal: bool, consumption_imbalance: ratio, tolerance, status ∈ {matched, imbalanced, unmatched}}, benefit_kind ∈ {artifact, search_time, transfer}, held_out: bool, estimated?: {estimator, inclusion_probabilities_ref}}`.
- `EquivalenceReport` (LCD battery): a `ComparisonReport` with `benefit_kind = artifact`, `pre_registered_margin`, `verdict ∈ {equivalent, not_equivalent, inconclusive}` per dimension.

| | `opacity_ratio` (static, A3) and `opacity_dynamic` | bundle report; `context.assembled{opacity_ratio}` per call | static value; per-call distribution (median, P95) | — | native / `ledger` |
| **Compliance (cross-cutting; A2 chain)** | `activation_rate`, `following_rate`, `pass_when_activated` | `artefact.delivered/activated/followed{detector}` | conditional rates | Wilson | per A2: deterministic → `events`; judged → `model_io` |

**Dynamic opacity (OQ-036, dynamic half).** `opacity_dynamic(run)` = distribution over model calls of (tokens in the assembled context originating from `Text` leaves or unstructured observations ÷ total context tokens), from `context.assembled{items[{kind, tokens}]}`; reported as median and P95 with the static ratio beside it; `n/a` for hosted rows.

**Outcome-class policy defaults.** Capability metrics: denominator = `scored ∪ budget_exhausted`; `infrastructure_failure`/`oracle_failure`/`cancelled` excluded and counted beside; `refused` counted as failure only when the metric declares `refusal_is_failure`. Efficiency: `scored` only. Veto metrics: evaluated on every run with a ledger.

### 6.4 Matched-budget comparison protocol (normative contract)

Operations (inputs → outputs; invariants; failure modes):

- `declare_arm(hypothesis, configurations[], eval_budget, search_budget, artifact_ref) → ArmId` — invariants: every configuration's `budget_vector` equals `eval_budget` dimension-wise; `artifact_ref` is a sealed definition or a product version (content-addressed); `search_budget` is complete (all optimizer/judge/rollout spend) or marked `unknown` (then the arm may only appear in `product-level` comparisons flagged `search_unknown`). Failures: `BudgetMissing`, `BudgetMismatchWithinArm`, `ArtifactUnsealed`.
- `compare(arm_a, arm_b, metrics[], design) → ComparisonReport[]` — preconditions: `arm_a.eval_budget == arm_b.eval_budget` (hard limits, every dimension) else `UnmatchedBudget` (T-LCD-14; engine refuses to run *and* to report); same task set and split; same environment image and fault/perturbation profile unless it is the varied factor; same model snapshot(s) per role unless model is the varied factor; `n ≥ design.replicates_per_cell` in both arms per task or `InsufficientReplicates(task)` renders that task's cells `n/a{not_run}`. Effects are paired by task (and by replicate only when both participants declare `seed_honoured`). Output carries `budget_match.status`: `matched` if actual consumption medians differ by ≤ tolerance (default 10 % per dimension, OQ-124), else `imbalanced` — reported, not refused, with the cost-adjusted view attached.
- `artifact_benefit(arm, baseline_arm, held_out_split) → ComparisonReport{benefit_kind = artifact, held_out = true}` — invariants: the artifact is frozen (no search spend during evaluation; `search_budget` of the evaluation phase = 0); the held-out split hash predates the search (`PreRegistration.task_split_hash` older than any `measurement.harness_edit.proposed` on the arm); failure `LeakedSplit`.
- `search_time_benefit(arm, baseline_arm) → ComparisonReport{benefit_kind = search_time}` — the performance *during* search (best-observed or final on the search set) against a baseline given the same `search_budget` (test-time scaling / discovery baseline per S-083: e.g. best-of-N with N rollouts equal to the arm's rollouts); failure `UnmatchedSearchBudget`. Reporting both rows is what separates "useful test-time search" from "portable harness learning" (doc 2 §8; ADR-0002 evidence standard).
- `transfer(arm, baseline_arm, held_out_factor ∈ {model_snapshot, environment, task_family}) → ComparisonReport{benefit_kind = transfer}` — paired Δ on the held-out level; `transfer_ratio` derived.
- `equivalence_run(reference_participant, native_harness_def, suite, budget, seeds[]) → EquivalenceReport` (LCD gate contract, unchanged) — a `compare` with a pre-registered margin per dimension; refuses unequal budgets; `inconclusive` when the interval straddles the margin.
- `render_scorecard(experiment) → ScorecardReport` — invariants: every metric in the registry has a cell for every configuration (`value | n/a{reason}`); no cell is 0 by default; the report names `metric_registry_version`, `price_table_version` and the results watermark; veto-tripped runs are excluded from headline success and counted beside it.

Admissibility rules for C4 claims (inherited by WS-I5 as gates): an evolution proposal is *accepted* only if `artifact_benefit` on held-out tasks has an interval excluding zero at the pre-registered level, `search_time_benefit` is reported, `transfer` on ≥ 1 held-out model family is reported (sign and interval), no veto metric regresses, `retention` Δ ≥ −margin, and the proposal's `search_budget` is complete. Adaptive task selection is admissible inside `search_budget` (Task-CoEvolve/IRT estimators) but an `artifact_benefit` row computed from a sampled set must carry `estimated{estimator, inclusion_probabilities_ref}` and may not be the sole basis of acceptance.

### 6.5 Oracle taxonomy (declaration + admissibility)

| class | decides from | deterministic | requires_observability | headline at C0 | precedent | notes |
|---|---|---|---|---|---|---|
| `executable` | tests/verifier run in the trial environment | yes | `end_state` | yes | Harbor verifier; SWE-bench; Terminal-Bench | verifier output schema validated; verifier crash ⇒ `oracle_failure` |
| `end_state` | environment/db state vs goal state | yes | `end_state` | yes | τ-bench; AgentDojo `post_environment` | goal state content-addressed in the bundle |
| `output_check` | final output vs pattern/schema/substring | yes | `end_state` | yes | τ-bench `r_output`; Inspect `match/pattern` | weakest deterministic class; declare pattern provenance |
| `trace_predicate` | predicate over ledger events | yes | `events` or `ledger` | yes (process metrics) | AgentDojo `*_from_traces`; HAL `compliance_checkers` | class-scoped by the events it reads |
| `protocol_check` | version stamps / validity intervals (A2 `validity()`) | yes | `events` | yes (validity) | S-077 via A2 | model-free by construction |
| `judge` | model over transcript/output with rubric | no | `model_io` (transcript) or `end_state` (output-only rubric) | **no** (labelled only) | Inspect `model_graded_*`; Harbor `analyze`; HAL `llm_log_analyzer` | judge = A3 `Validator{kind: judge, ProfileRef}`; snapshot ≠ beneficiary; calibration record mandatory; cost attributed to the instrument (OQ-053) |
| `human` | human rater | no | any | no | — | rater id, rubric version, agreement |
| `teacher_relative` | convergence toward a stronger teacher's sparse corrections (S-068) | no | `model_io` | no; C4 only | none in OSS | `provisional`; calibration against a labelled subset required before use as a gate |
| `reference_relative` | paired equivalence vs a reference participant (T-LCD-03) | derived | as underlying metrics | n/a (verdict) | LCD battery | margin pre-registered |

`OracleDeclaration{oracle_id, class, deterministic, requires_observability, verdict_type ∈ {bool, graded, verdict_lattice{C,I,P,N}, vector}, evidence_out: ArtifactKind, cost_attribution ∈ {harness_under_test, instrument}, calibration_ref?, provenance}`. Invariants: a metric's `oracle_classes_allowed` ⊇ the classes of every oracle that fed it; a judged value is never merged with a deterministic value under one metric name (they are two metrics or two labelled stages — A2's decomposition); an oracle may not consume `model_claim` observations as its only evidence (A3 Validator invariant).

### 6.6 Minimum experimental design — acceptance criteria for the Harness Lab (Stage 3)

- **AC-I2-1 (T-LCD-09, gate).** The results schema keys every row by the full configuration tuple; the canned analysis "does variant V help model M₁ more than M₂?" executes against a fixture with 2 models × 2 variants × ≥ 3 tasks × n ≥ 3 and returns an interaction estimate with an interval.
- **AC-I2-2 (T-LCD-14, gate).** `compare` refuses arms with unequal hard limits (`UnmatchedBudget`); the results schema carries `search_budget` and `eval_budget` per arm; a fixture arm with `search_budget = unknown` cannot appear in a component-level comparison.
- **AC-I2-3 (T-LCD-15, gate).** Every registry metric carries the full `MetricDeclaration`; a mixed native/hosted fixture renders `n/a{class}` for component-level cells and `n/a{observability}` for `model_io`-dependent cells on a session-ABI participant; no cell is 0 by default.
- **AC-I2-4 (distributions, gate).** For every configuration the scorecard stores per-task (c, n), pass^k for k ≤ n, an interval with named method, quantiles, and tail statistics; pass^k for k > n renders `n/a{estimator_undefined}`.
- **AC-I2-5 (outcome classes, gate).** A fixture with one infrastructure failure, one budget exhaustion and one verifier crash yields headline success computed over the declared denominator and the three counts reported beside it; the naive mean (all as 0) is demonstrably *not* what is reported.
- **AC-I2-6 (T-LCD-03, executable + review).** The Stage-0 reference harness round-trips within the pre-registered margin on the Stage 3 suite: paired runs, fixed model/seed material/budget, n ≥ 5, verdict per dimension; the margin is a review item recorded in `PreRegistration`.
- **AC-I2-7 (T-LCD-13, executable).** Activation and following rates are computed from ledger events for the reference harness for every artifact kind with `activation_observable = true`; judged following is labelled and reported with judge calibration.
- **AC-I2-8 (T-LCD-02 dynamic).** `opacity_dynamic` is computed per model call from `context.assembled` and reported beside the static ratio.
- **AC-I2-9 (veto separation).** A run that succeeds on the task but trips `secret_leak` or `duplicate_effect_rate` appears as success-with-veto, excluded from headline success.
- **AC-I2-10 (portability minimum).** Any portability claim in a report cites ≥ 2 model snapshots from ≥ 2 families and ≥ 1 held-out level; otherwise the portability cells render `n/a{not_run}`.
- **AC-I2-11 (oracle boundary; OQ-046).** An oracle implemented out-of-process, invoked once per run with `(trial end-state handle, ledger read cursor, artifact refs)`, produces identical `MetricValue`s to an in-process invocation on a fixture.
- **AC-I2-12 (reproducibility hooks).** `ScorecardReport` records `metric_registry_version`, `price_table_version`, oracle ids, judge snapshots and the results watermark; regenerating from the same runs yields an equal report hash (B1 `project` purity).

**OQ-037 answer (gate vs checklist).** Automated gates (engine/report-generator preconditions): T-LCD-09, -14, -15 (AC-1/2/3), the `n/a` and outcome-class rules (AC-4/5), T-LCD-02 static (compile-time, A4) and dynamic (AC-8). Executable tests with a review item: T-LCD-03 (margin pre-registration is human-reviewed; the run is automated), T-LCD-13 (deterministic stages automated; the *choice* of judged kinds and calibration is reviewed). Checklist-only in the readiness report: none of I2's tests — every I2 obligation has a machine check.

**OQ-046 answer (scorer boundary).** The contract is **per run over a boundary**: an oracle/judge/loader is a component variant (WS-A5 locality property) invoked once per run with the trial's end-state handle, a ledger read cursor and artifact references, returning typed `MetricValue`s that the runtime appends as `measurement.metric.emitted`. Per-sample in-process calls are an optimization that must produce identical values (AC-11). Rationale: verifiers already run in the trial environment as separate processes (Harbor, SWE-bench, Terminal-Bench), judges are model calls with their own cost attribution, and the boundary makes hosted and native runs score identically.
