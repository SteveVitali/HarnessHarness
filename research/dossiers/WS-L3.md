## 1. Scope & boundary

This workstream designs the **single provenance/authority scheme** that the security kernel (WS-H1), information-flow control (WS-H2), the context builder (WS-D1) and the memory lifecycle (WS-D4) all consume — the CF-006 convergence obligation — and answers OQ-054 (the values of the closed `AuthorityClass` sum WS-A3 reserved on every `Observation`, `ContextItem`, `Memory`, `Permission` issuer and `Text` leaf). Concretely it fixes: (a) the **provenance record** schema on every HIR node/edge and every content-bearing ledger event, as a superset of WS-A3's `{origin, authority, created_at, attestation?}`; (b) the **label lattice** — authority classes (total order), taint set, reader set — with ordering, join, meet; (c) the closed list of **endorsement/declassification points** and who may exercise them; (d) **propagation rules** through derivations (summaries, compactions, extractions, subagent outputs), delegation, persistence and lowering — narrow-or-preserve, never widen; (e) how provenance is **recorded in the event store** and which event classes must carry it; (f) the **retrieval filter order** (validity → authority → readers → relevance); (g) the **minimal check set a reference monitor needs**; (h) acceptance criteria that replicate the two 2026 attack classes (message-role and cross-scope context privilege escalation) and the revoked-memory failure as tests.

It explicitly leaves to neighbours: **WS-H1** — the authority-handle (object-capability) runtime, the policy table that turns the label into allow/deny/ask decisions per effect class, TCB minimality (OQ-021); **WS-H2** — the enforcement of taint/reader sets at C2, per-tool flow policies, explicit-secrecy vs non-interference choices; **WS-H3/H4** — credential and egress mediation (they consume `readers` and `external`); **WS-H5** — pin/sign/attest of extensions (the `seal`/`pin` endorsement basis); **WS-H6** — the attestation protocol over the ledger chain (the `attestation` field's verification); **WS-H7** — approval-fatigue policy (approval is an endorsement point here, its cadence is H7's); **WS-D1** — slot design and rendering (this dossier fixes the role-placement invariant and the `context_label` stamp, not the working-set policy); **WS-D4** — conflict sets, supersession, expiry (this dossier fixes the filter order and the supersession-authority rule); **WS-A3** — the IR shape (values supplied here; two small shape amendments proposed as conflicts); **WS-B1** — the envelope (this dossier fixes which classes carry provenance and two event-class renames); **WS-A4/C3** — the class→message-role mapping as a profile surface and its lowering loss; **WS-L4** — identity (provenance is excluded from `semantic_id`, included in `version_id`, per WS-A3). Nothing here names a language, runtime, package ecosystem or framework; every precedent path is evidence, not a dependency.

## 2. Key questions

1. (doc 3 §5, verbatim) Design the first-class provenance/authority model: origin, version, authority class, trust/taint on every context item, memory, tool result, artifact, instruction, and delegated capability; the authority lattice the security kernel (H1), IFC (H2), context builder (D1), and memory lifecycle (D4) will ALL consume — one scheme, not three.
2. (doc 3 §5, verbatim) How provenance is recorded in the event store and propagated through derivations (summaries, compactions, subagent outputs); declassification/endorsement points.
3. (Phase 1 brief) Propose the `AuthorityClass` values (OQ-054); the lattice (classes, ordering, join/meet, endorsement/declassification rules); propagation through derivations and delegation (narrow-or-preserve, never widen); how retrieval filters by authority before relevance; the minimal set of checks a reference monitor needs; an ADR for the single scheme written so H1/H2/D1/D4 can cite it.
4. (added) Which of the three things the field calls "trust" — *who produced it* (origin), *how much may it command* (integrity/authority), *where may it flow* (confidentiality) — must be lattice elements and which are facts, and how does *validity* (still in force?) relate to authority without being folded into it?
5. (added) What exactly do CaMeL and Fides put on a value, how do labels move through data and control flow, and where do they lose utility — so the C0/C2 split lands where the evidence says the cost is?
6. (added) What do the 2026 context-privilege-escalation studies say the harness *assembly* bug is, and which single invariant on the context builder would have prevented the reported classes?
7. (added) Do mature provenance/attestation standards outside this field (PROV, in-toto/SLSA, JCS-signed AgentCards) supply the record shape and the trust-anchor rule, so the design is not novel where it need not be?

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Two independent 2025 systems with code converge on the same label shape: a product of an integrity component and a confidentiality component, joined conservatively, checked at the tool boundary by a deterministic monitor.** CaMeL's `Capabilities` is `{sources_set: frozenset[Source], readers_set: Readers}` where `Source = SourceEnum{CaMeL, User, Assistant, TrustedToolSource} | Tool{tool_name, inner_sources}` and `Readers = frozenset | Public` (`capabilities.py` L23–38, `sources.py` L22–42, `readers.py` L21–45). Sources *union* over the dependency graph (`utils.py: get_all_sources`, L40–52) and readers *intersect* (`get_all_readers`, L15–26; `Public.__and__` returns the other operand, L32–40). Trust is a predicate over the union: `is_trusted(value) = all(source ∈ TRUSTED_SET ∨ (Tool with non-empty inner_sources ⊆ TRUSTED_SET))` (L55–73). Fides' notebook defines a `Lattice` ABC with `leq/join/meet`, a two-point `IntegrityLabel{TRUSTED, UNTRUSTED}`, a two-point `ConfidentialityLabel`, a `PowersetLattice` (join = union), a `ProductLabel` (component-wise), and an `InverseLattice` so that a *set of readers* orders by reverse inclusion (cells 17–20), then instantiates `ProductLabel[IntegrityLabel, InverseLattice[PowersetLattice[str]]]` for the email assistant (cell 25: `readers_label(readers) = Inverse(Powerset(readers))`; an email is `trusted` iff its sender is in-domain). Both therefore agree: **integrity/authority is a join-toward-lower-trust component, confidentiality is a join-toward-fewer-readers component, and the pair is a product lattice.** Neither has a *third* component for validity or a per-item version — those come from the memory literature (F4).

**F2 — Labels must flow through control as well as data, and the systems differ only in how conservative they are.** CaMeL's interpreter threads a `dependencies` list through evaluation; `_eval_if` appends the branch `test` to the dependencies of the body and removes it afterwards (`interpreter.py` L1667–1706), `_eval_if_exp` additionally re-attaches the inner dependencies to the resulting value (L1709–1750); `MetadataEvalMode.STRICT` "will propagate metadata in a more conservative way" (L116–130) and, at a tool call, `check_policy(tool_name, kwargs, dependencies)` is invoked with the *ambient* dependencies so a state-changing tool that "depends on private values" is denied (`security_policy.py` L77–96; call site `interpreter.py` L2047–2065). The paper names the cost: tasks fail when "the actions to take depend on untrusted data". Fides' planning loop keeps a single `current_label` that is joined with every tool result's label (`current_label = metadata_to_label(result).join(current_label)`, cell 29) and passes the *trace of (action, label)* to a policy on every step — Biba's low-water mark applied to the whole conversation. Fides' formal result is that this yields non-interference for integrity and only *explicit secrecy* for confidentiality ("does not prevent implicit flows"). **Implication:** a per-model-call **context label** (join of everything delivered) is the cheapest sound approximation of control-flow taint at the harness level; finer, per-value dependency tracking (CaMeL) needs an interpreter the model programs against and is a C2 option, not a C0 requirement.

**F3 — Typed shape is a legitimate basis for raising the usable authority of untrusted content without raising its integrity.** Fides labels a quarantined-LLM output with the product (ℓ, ν) of a security label and an *output-type* label — a constrained schema bounds what the value can do; CaMeL's `query_quarantined_llm` forces a schema with a mandatory `have_enough_information` field and raises `NotEnoughInformationError` rather than guessing (`quarantined_llm.py` L37–103), and in STRICT mode adds every argument as a dependency of the result (`interpreter.py` L2067–2068). The escalation paper's filename/git-log vector (S-103) is the same point from the attack side: *free text* from the environment is the injection channel, a validated integer or enum is not. **Design consequence (§6.2 rule R-TEXT):** free text from any origin other than the kernel, the sealed definition or the human principal is at most `external`; structured values validated against a closed schema declared in the sealed definition may carry `environment`. This is the only place "shape" enters the scheme, and it is an endorsement point with a validator as endorser, not a default.

**F4 — Validity is orthogonal to authority and must be a separate filter in the retrieval contract.** S-106's failure is precisely a revoked fact that *keeps its authority*: it "is returned wherever the revocation label is visible to the retrieval layer, outranks its replacement, and leads agents to the unsafe action." The fix that worked was a guard *between* agent and memory that withholds revoked or conflicting records — enforcement in the contract, not a flag in the text. S-077 shows validity can be made deterministic where an artifact carries a version stamp. WS-A2 already makes validity three-valued and WS-A3 carries the declared interval on `Memory`/`ContextItem`/`Permission`. **Implication:** the label never encodes validity; `retrieve` applies validity first, authority second, readers third, relevance last (§6.4), and supersession requires authority ≥ the superseded item's (a `delegate` note cannot revoke a `principal` instruction).

**F5 — Production harnesses carry *origin* and *scope* but no *authority* on content, decide permissions from risk or name patterns, and load persistent instruction files by location — which is exactly the assembly bug S-103/S-104 exploit.** OpenHands: `SourceType = "agent" | "user" | "environment" | "hook"` on every event (`event/types.py` L5), an LLM-predicted `SecurityRisk{UNKNOWN, LOW, MEDIUM, HIGH}` whose `UNKNOWN` is deliberately non-comparable (`risk.py`), and confirmation policies keyed on that risk (`confirmation_policy.py: ConfirmRisky.should_confirm`) — provenance never reaches the decision; skills load from `~/.openhands/skills/`, the public extensions repository and the workspace with flags but no trust class (`agent_context.py` L93–150). Codex: `SessionSource{Cli, VSCode, Exec, Mcp, Custom, Internal, SubAgent(SubAgentSource{Review, Compact, ThreadSpawn{parent_thread_id, depth, agent_role}, MemoryConsolidation}), Unknown}` (`protocol.rs` L2751–2850) is a rich *origin* with subagent lineage; `TrustLevel{Trusted, Untrusted}` per project switches `AskForApproval::UnlessTrusted` ("commands require approval unless an explicit exec policy rule allows them", L988–993) — a binary *scope trust* that gates effects but never labels content; AGENTS.md instructions are injected as `developer`-role items (`session/inject.rs` L102) — the M-CPE precondition. Claude Agent SDK: `SettingSource = user | project | local` and `PermissionUpdateDestination = userSettings | projectSettings | localSettings | session` (`types.py` L33, L109–112) — the three persistence scopes of S-103 (σ_user > σ_project > σ_session) as first-class *write targets*, with `_SubagentContextMixin{agent_id, agent_type}` on hook inputs for attribution. opencode/goose decide allow/deny/ask on tool-name patterns. **Negative result, corroborating WS-B1 §5 and WS-A1 F6:** no audited runtime attaches an authority class to a context item, memory or tool result; the two 2026 studies report end-to-end compromise on all systems they tested. The mechanism is established independently of the provisional attack rates: origin ≠ authority, and location-based elevation is the bug.

**F6 — Mature standards already give the record shape and the trust-anchor rule; the scheme need not invent them.** PROV-DM's `wasDerivedFrom` (with revision/quotation/primary-source subtypes), `wasAttributedTo` and `actedOnBehalfOf` ("assignment of authority and responsibility to an agent … as a delegate or representative") are exactly derivation, attribution and delegation lineage. in-toto/SLSA fix the rule that authority is anchored on the *signer–builder pair* verified from the envelope, never on self-declared predicate content: "Consumers MUST accept only specific signer-builder pairs." MCP says the same for tool annotations ("never make tool use decisions based on `ToolAnnotations` received from untrusted servers", `schema.ts` L1903–1910) and reserves `_meta` for prefixed extension keys; A2A signs AgentCards as JWS over a JCS-canonical form with the `signatures` field excluded — the same canonical-form class WS-A3/WS-B1 adopted, so an attestation over a HIR node or ledger event needs no new machinery. **Implication:** `attestation` is a verified fact about `origin`; the *authority class is derived* from verified origin + scope + endorsement events and is never read from an imported item's own claim (lifting yields `unverified`, WS-A3 F4).

**F7 — Approval is an endorsement of one effect, not of content, and its value is bounded.** Anthropic's containment telemetry (S-053 via doc 2 §5.6: ~93% of permission prompts approved) means a human approval cannot be treated as raising the authority of the *content* that motivated the action; CapScope's per-issuing-agent check and CaMeL's per-tool policies both scope the decision to one call with canonical arguments. The isolation pattern in production (Managed Agents/Cursor subagents with clean contexts, doc 2 §5.7) is the utility-recovery mechanism under a low-water-mark context label: a subagent that reads external content returns a typed, tainted result while the parent's context label stays high.

## 5. Disconfirming evidence & negative results

**Against labels at all: the model-side instruction hierarchy already handles this.** Wallace et al. (S-220) train models to privilege system over user over third-party text and report large robustness gains. *Why this does not overturn:* S-104 shows that "agent harnesses construct context for each model invocation [and] this construction can elevate low-level content to a higher instruction level," defeating the hierarchy on every harness tested, and S-103 finds 282 assembly-level vulnerabilities. A model-side hierarchy is only as good as the roles the harness assigns; the scheme here is what makes those assignments correct (role-placement invariant, §6.3) and is complementary. It also adds what the model-side hierarchy cannot: a ledger record the reference monitor and the Lab can read.

**Against strict IFC: it costs utility and policy-authoring effort, and does not close implicit flows.** CaMeL loses 7 points on AgentDojo and fails tasks whose actions depend on untrusted data; its authors say users must "codify and specify security policies and maintain them"; Fides admits explicit secrecy only and "illicit flows through model mistakes." *Why this does not overturn:* the C0 scheme is the *authority axis only* (one enum per item, one join, one per-call context label) — the part every precedent shares and the part that stops M-CPE/X-CPE; taint sets, reader sets and per-value dependency tracking are C2 (WS-H2) and switchable per effect class. The utility-recovery path is architectural (subagent isolation with typed returns; shape endorsement) and is a Lab experiment (§6.7), not an assumption. The implicit-flow limit is stated as a non-goal of the C0 scheme (explicit secrecy, Fides' result), and the policy-authoring burden is bounded by making the *default* policy a function of `EffectClass` (WS-A3) rather than of tool names (CaMeL's per-tool policies).

**Against a total order for authority: decentralized models (DLM) show that "who owns the policy" is not one axis.** Multiple principals (a Lab with several users, tools with their own owners, third-party skills) do not sort linearly. *Why this does not overturn:* the total order governs *command authority over the harness* — the one axis every precedent linearizes (Biba levels, instruction-hierarchy roles, S-103's r0…r4 and σ_user…σ_session, CaMeL's trusted set vs tools) — while ownership and audience live in the two set-valued components (`taint` = which origins influenced, `readers` = who may see), which are decentralized in exactly DLM's sense. Multi-principal Labs are represented by per-run `principal` plus reader sets, not by extra classes.

**Against Biba low-water mark: label creep.** After a single open-world read the context label is `external` for the rest of the call and, if the content is summarized into memory, for later runs; Biba's low-water-mark is known to degrade subjects to the bottom quickly. *Why this does not overturn:* this is the correct security semantics (S-103's X-CPE is exactly a summary of session content re-entering at user scope); the mitigation is not to weaken the join but to (i) scope the context label per model call (it is recomputed from what is delivered, so compaction that drops external items restores the label), (ii) isolate reads in subagents (F7), (iii) let read-only closed-world effects proceed at any label (CaMeL's no-side-effect set), and (iv) make the effect-class × context-label policy table explicit and measurable (OQ-101). The cost is measured by the Lab as approval count and task success under the same budget, not hidden.

**Against `environment` as a distinct class between `delegate` and `external`.** The evidence for treating any environment content as more trustworthy than the web is thin: S-103's vectors include filenames, directory trees and git logs — i.e. the workspace *is* external content for instruction purposes. *Why this does not overturn:* the class is restricted by rule R-TEXT to closed-schema structured values produced by in-definition closed-world tools (exit codes, counts, validator verdict fields, diff statistics) — never free text — which is the Fides (ℓ, ν) construction. If Phase 2 finds no consumer that needs the distinction, `environment` collapses into `external` by dialect migration (OQ-102); it is kept now because the reference monitor's read-only/closed-world exemption and WS-G2's execution-alignment layer both need a class for "the runtime measured this."

**Against putting `delegate` (model output) above `environment`/`external`.** CaMeL treats `Assistant` as trusted and the instruction hierarchy puts assistant above tool, but WS-A3 says a `model_claim` "can never satisfy a Validator by itself." *Why this does not overturn:* the two statements are about different axes. Authority class is *command* authority (may this content instruct the harness); evidentiary weight is WS-A2's detector provenance and WS-G2's reconciliation. A model output that repeats external instructions is tainted by them (join = `external`), so laundering is impossible under the join rule; a model output that is its own plan is `delegate` and may propose but never confer (WS-A3 `authority(issuer) ≠ model_claim`). The scheme therefore keeps `delegate > environment > external` and forbids conflating authority with evidence (ontology term "evidence class", §9).

**Against provenance on every event and node: verbosity, and no audited runtime does it.** WS-B1 §5 records the negative result. *Why this does not overturn:* at C0 the mandatory content is `origin` (already required by WS-A3), `authority` (one enum), `scope` (one enum) and `created_at`; taint/readers default to ∅/Public and are omitted from the canonical form when default. The ledger already carries `provenance?` (WS-B1 envelope) and the context view already lists per-item `authority` (`context.assembled`), so the marginal cost is one enum and one join per delivered item.

**Against relying on approvals as endorsement.** ~93% approval rates (S-053) mean approval fatigue can turn the endorsement point into a rubber stamp. *Why this does not overturn:* approval endorses exactly one effect with canonical arguments (never content, never a class), is recorded with its basis, and WS-H7 owns fatigue policy; the scheme makes approval count a first-class cost so the Lab can compare policies (T-LCD-14 budgets include approvals).

**Negative results from the audit.** (i) No audited runtime (OpenHands, Codex, Claude SDK, opencode, goose, Pi, Omnigent) attaches an authority class to a context item, memory or tool result, nor stamps a per-call context label; (ii) none records who endorsed a persistence write; (iii) Codex's `attestation.rs` attests the *client*, not content; (iv) Fides is a notebook, not a library — no production-grade IFC runtime for agents exists in the audited corpus; (v) neither CaMeL nor Fides carries validity/version on values, confirming F4's separation.

## 6. Recommendation for the spec

### 6.1 The provenance record (every HIR node and edge; every content-bearing ledger event)

`ProvenanceRecord = { origin: Origin, authority: AuthorityClass, taint: set<TaintTag> = ∅, readers: ReaderSet = Public, scope: PersistenceScope, derived_from: [Derivation] = [], created_at, attestation?: Attestation }`.

- `Origin` (WS-A3's sum, with two additions proposed in CF-074): `human(author_ref, role ∈ {author, principal, reviewer}) | model(model_ref, run_ref, response_id) | tool(Ref<ToolCapability>, invocation_ref, inner_source?: TaintTag) | evolution(candidate_id, hypothesis_ref) | import(source_system, mapping_version) | migration(from_dialect) | kernel(component_ref) | participant(participant_ref, hosting_mechanism)`. `inner_source` is CaMeL's `Tool.inner_sources` (e.g. the sender of an ingested message).
- `AuthorityClass` (closed total order, answers OQ-054): **`kernel > definition > principal > delegate > environment > external > unverified`**. Meaning: how much the item may *command* the harness. Minting rules: `kernel` only by the reference runtime (ledger facts, monitor decisions, validator verdicts); `definition` only at `seal` for content the harness author placed in the Harness Definition (or endorsed via pin/attest, WS-H5); `principal` only for content from the run's human principal (task statement, replies, approvals) and for memories a principal promoted; `delegate` for outputs of any AgentProcess (model claims, plans, subagent results, evolution candidates, hosted-participant claims); `environment` only for closed-schema structured values from in-definition closed-world tools (rule R-TEXT); `external` for everything read from open-world sources and for *all free text* not from kernel/definition/principal; `unverified` for imported, lifted, migrated or attestation-failed content and for hosted-participant content whose origin the ABI cannot vouch for.
- `TaintTag = Origin-ref at class ≤ external` (tool + inner source, participant, import source). `ReaderSet = Public | set<PrincipalRef>`.
- `PersistenceScope ∈ {definition, user, project, session, run, turn}` (S-103's σ plus the sealed definition and the ledger's own units) — where the item *lives*, distinct from its authority.
- `Derivation = {kind ∈ {summary, compaction, extraction, quotation, revision, translation, subagent_result, projection}, inputs: [Ref], deriver: Origin, deterministic: bool}` (PROV `wasDerivedFrom` subtypes).
- `Attestation = {kind ∈ {seal, hash_chain, signature, pin}, subject_hash, anchor: SignerRef | ChainRef, verified_by: kernel(component_ref), verified_at}` — a verified fact about `origin`; never self-declared (in-toto/SLSA signer–builder rule; MCP hints rule).

**Invariants.** I1 `authority ≤ default_authority(origin, scope, attestation)` unless an endorsement event (§6.3) names this item; I2 free-text rule R-TEXT: `kind = Text ∧ origin ∉ {kernel, definition-at-seal, human(principal)} ⇒ authority ≤ external`; I3 `taint ≠ ∅ ⇒ authority ≤ external`; I4 provenance is excluded from `semantic_id`, included in `version_id` (WS-A3 §6.1 — unchanged); I5 an item's `authority` never exceeds its `scope`'s write ceiling (§6.3 table); I6 `derived_from ≠ [] ⇒ label(item) ⊑ ⊔ label(inputs) ⊔ label(deriver)` (P1). Failure modes at validation/append: `MissingProvenance`, `AuthorityExceedsOrigin`, `TextAboveExternal`, `TaintedAboveExternal`, `IllegitimateEndorsement`, `ScopeCeilingExceeded`.

### 6.2 The label lattice — ADR-0033

`Label = (authority, taint, readers)`; `L₁ ⊑ L₂` ("L₁ may flow to L₂"; L₂ at least as restricted) iff `authority₁ ≥ authority₂ ∧ taint₁ ⊆ taint₂ ∧ readers₁ ⊇ readers₂`. **Join** `L₁ ⊔ L₂ = (min(authority), taint₁ ∪ taint₂, readers₁ ∩ readers₂)` (Public is the identity of ∩); **meet** `= (max, ∩, ∪)`; top (least restricted) `= (kernel, ∅, Public)`, bottom `= (unverified, U, ∅)`. The product is exactly Fides' `ProductLabel[IntegrityLabel, Inverse[Powerset]]` with the two-point integrity lattice replaced by the seven-class chain and CaMeL's `sources_set` added as the taint component. At **C0** only `authority` is enforced (taint/readers are carried with defaults and joined, but no monitor check reads them); at **C2** WS-H2 enforces all three. The lattice is *closed per HIR dialect*: adding a class is a dialect bump with a migration (WS-A3 §6.1).

### 6.3 Endorsement and declassification points — ADR-0035

The only operations that may move a label *up* (raise authority, drop taint, widen readers). Each is a ledger event `security.label.endorsed{subject_ref, from: Label, to: Label, endorser: ProvenanceRecord, basis, basis_ref}` (or `security.label.declassified` for readers) and is valid only if `authority(endorser) ≥ authority(to)` and `basis` is in this closed list:

| basis | endorser class | what it may do | precedent |
|---|---|---|---|
| `seal` | `definition` (harness author at `seal`) | content placed in the Harness Definition → `definition`; imported skills/instructions → `definition` only with a `pin` attestation (WS-H5) | codex/Claude SDK settings sources; S-103 defence "scope-bound loading" |
| `approval` | `principal` (human) | endorses **one Effect intent** identified by `(effect_id, args_canonical_hash)`; never content, never a class | ACP `RequestPermission`; CaMeL `is_trusted(recipients)`; S-053 |
| `validator` | `kernel` (deterministic Validator) | shape endorsement: an `external` value validated against a **closed schema** declared in the sealed definition → `environment`; free text never | Fides (ℓ, ν); CaMeL Q-LLM schema |
| `promotion` | `principal` or `definition` | a memory/procedure reviewed by a human → `principal`/`definition` (D4 lifecycle) | doc 2 §5.1 lifecycle memory |
| `pin` | `definition` via WS-H5 | third-party extension content with verified signature/hash → `definition` or `principal` per policy | in-toto/SLSA signer–builder rule; A2A JWS |
| `policy_rule` | `kernel` executing a `HarnessRule` whose issuer is `definition` | declassify readers to a named recipient set (e.g. recipients of an outgoing message) | CaMeL `send_email_policy`; Fides `policy_no_untrusted_declassification` |

A `delegate` origin (any model, subagent, evolution candidate, hosted participant) can **never** be an endorser — the type-level form of "the model can reason about permission but cannot grant itself permission" (doc 2 §5.6) and of DLM's "only the owner can declassify its own policy." **Persistence-scope write ceilings** (X-CPE defence): writing to `scope = user` requires effective authority ≥ `principal` *and* an `approval`; `project` ≥ `principal`; `session`/`run` ≥ `delegate`; `definition` only through `seal`. The written item's label is `⊔(context_label, label(writer))` — never higher than what the writer could command at that moment.

### 6.4 Propagation rules — ADR-0034

- **P1 Derivation.** `label(out) = ⊔ label(inputs) ⊔ label(deriver)`; `deriver = delegate` for any model-produced summary/compaction/extraction, `kernel` for deterministic projections (truncation, redaction, structured projection). A compaction summary of external content is `external` with the union taint; `derived_from` lists the forgotten ids (WS-B1 `context.compaction.completed{forgotten, summary_ref}`).
- **P2 Delegation** (`delegated-to` edge, WS-A3): child `Permission ⊆` parent's, child `Budget ≤` parent's (already A3 invariants); **child authority ceiling ≤ parent's effective authority at spawn**; everything the child returns enters the parent at `≤ delegate` with `taint ⊇ child's accumulated taint` and `derived_from = subagent_result`. Hosted participants: identical, with `origin = participant`.
- **P3 Context label.** For every model call, `context_label = ⊔ label(items delivered)` (Fides `current_label`; Biba low-water mark), stamped on `context.assembled`. **Effective authority of a proposal** `= min(authority(proposer), context_label.authority)`; taint of a proposal `= taint(context_label) ∪ taint(args)`. Recomputed per call from what is delivered (compaction that drops external items restores it); reset otherwise only by isolation (fresh subagent context) — never by a new principal message alone, which would be an escalation.
- **P4 Persistence.** Any write to a persistent scope is an effect of domain `memory_write`/`fs_write` with `scope`; the written item's label per §6.3; the scope ceiling is checked by the monitor (check 6).
- **P5 Retrieval — authority before relevance.** `retrieve(query, slot_min_authority, validity_required = {valid}, reader: PrincipalRef, k) → [Item]`: filter `validity(item, now) ∈ validity_required` (three-valued, WS-A2; revoked/superseded items excluded by default — S-106's guard), then `authority(item) ≥ slot_min_authority`, then `reader ∈ readers(item)`, **then** rank by relevance. `unknown` validity is admitted only if the slot declares `admit_unknown_validity` (CF-028 aligned). Supersession: `supersedes(new, old)` requires `authority(new) ≥ authority(old)` (`SupersessionAuthorityInsufficient` otherwise).
- **P6 Never widen.** No operation outside §6.3 may increase `authority`, shrink `taint` or widen `readers`; the ledger refuses an append whose provenance is above what P1–P4 permit without a paired endorsement event (`IllegitimateEndorsement`); a `HirDiff` with `authority_delta = widening` is rejected in evolution contexts (WS-A3 §6.4, unchanged).
- **P7 Lowering/lifting.** Lowering to MCP/A2A/ACP/provider tool APIs carries `hir/provenance` (origin ref, authority, scope, taint tags) in the target's typed extension slot; targets that cannot carry it record the loss (T-LCD-11); **lifting** assigns `origin = import|participant|tool` with `authority = unverified` (or `external` for open-world tool results whose tool is in the sealed definition) and never reads a class from the lifted payload.

### 6.5 Role-placement invariant (WS-D1 / WS-A4 / WS-C3)

The Profile Compiler owns a surface field `role_map: AuthorityClass → ProviderRole` (e.g. `kernel/definition → system|developer`, `principal → user`, `delegate → assistant`, `environment/external/unverified → tool|user-quoted`). **Invariant RP:** an item is rendered only into a role whose privilege ≤ `role_map(authority(item))`; an item below a slot's `min_authority` is rejected or rendered through a demotion wrapper declared by the profile — never silently promoted. Targets with fewer roles collapse classes and the lowering loss report records the collapse (T-LCD-11). This is the single invariant that closes M-CPE (S-103) and the "developer-role AGENTS.md" pattern (codex `session/inject.rs` L102) unless the file was sealed or pinned.

### 6.6 Recording in the event store (WS-B1)

Provenance is **mandatory** on: `context.assembled` (per item `provenance`, plus `context_label`), `context.artefact.delivered/activated/followed` (WS-A2 naming), `context.memory.read/written/invalidated`, `context.observation.recorded`, `context.compaction.completed` (summary artefact provenance with `derived_from`), `model.call.requested/completed` (label of the request view; response label = `⊔(context_label, delegate)`), `action.tool.proposed` (proposal label per P3), `action.effect.*` (args label), `security.permission.*`, `security.label.applied/endorsed/declassified` (rename of B1's `security.taint.*`, CF-077), `security.extension.loaded` (pin attestation), `measurement.harness_edit.proposed` (`origin = evolution`, `delegate`), `lifecycle.hosted.native_record` (`participant`, `unverified`), `lifecycle.ledger.redacted` (endorser). Optional elsewhere. Derivation lineage is the `derived_from` list inside the record plus B1's `causes[]`; the ledger's hash chain (ADR-0029) is the `hash_chain` attestation anchor for every stamped record, so WS-H6 attests provenance for free.

### 6.7 Minimal reference-monitor check set (WS-H1 consumes; WS-H2 adds 3)

For a proposal `p` (tool call / effect intent) from AgentProcess `A` in model call `c`:
1. **Authority of proposal.** `eff = min(authority(A), context_label(c).authority)`; `A` at `delegate` may only *propose*; conferral requires a valid `Permission` whose `issuer.authority ≥ principal`.
2. **Grant coverage and permission validity.** `declared EffectClass(p) ⊆ grants(Permission(A))` by domain + scope, attributes only narrowing; the Permission's `validity` is `valid` at `c` (revoked/expired ⇒ deny) — CapScope's per-issuer check, V-EFF's runtime form.
3. **Flow (C2).** For `world = open` effects or domains `net_egress`, `message_human`, `spend`: `readers(args) ⊇ destination principals` unless declassified by `policy_rule`/`principal` (CaMeL `send_email`).
4. **Taint gate.** If `eff ≤ external` (or `taint(p) ≠ ∅`) and `EffectClass(p)` is not (`mutability = read_only ∧ world = closed`): decide by the policy table `Π(EffectClass, eff) → allow | ask | deny` (WS-H1/H7 own Π; OQ-101); `ask` resolves through an `approval` endorsement of this `effect_id`.
5. **Endorsement legitimacy.** Every `security.label.endorsed/declassified` names an endorser with `authority ≥ to.authority` and a basis from §6.3; otherwise `IllegitimateEndorsement`.
6. **Persistence ceiling.** Writes to scope σ satisfy §6.3's ceiling; the written label is `⊔(context_label, label(writer))`.
7. **Delegation attenuation.** At `control.subagent.spawned`: child ceiling ≤ parent's `eff`, child `Permission ⊆` parent's, child `Budget ≤` parent's.
Everything else (task semantics, risk prediction, judge verdicts) is *outside* the monitor: WS-A3's `risk_assessment` stays model-authored and non-authoritative; OpenHands' `SecurityRisk` is an input to `Π` at most, never to classes.

### 6.8 Interface-contract sketch (language-agnostic; operations, inputs/outputs, invariants, failure modes)

- `default_authority(origin, scope, attestation?) → AuthorityClass` — total; pure; the table in §6.1. Failure: none (returns `unverified` for anything unmatched).
- `join(l₁, l₂) → Label`, `meet`, `leq(l₁, l₂) → bool` — lattice laws hold (idempotent, commutative, associative; `leq` is a partial order); tested by property tests.
- `derive(kind, inputs: [ProvenanceRecord], deriver: Origin, deterministic) → ProvenanceRecord` — P1; failure `DeriverBelowInputs` is impossible by construction (join).
- `context_label(items: [ProvenanceRecord]) → Label` — P3; stamped by the context builder; failure `MissingProvenance`.
- `effective_authority(proposer: ProvenanceRecord, ctx: Label, args: [ProvenanceRecord]) → {authority, taint}` — P3.
- `endorse(subject, to: Label, endorser: ProvenanceRecord, basis, basis_ref) → EndorsementEvent` — §6.3; failures `IllegitimateEndorsement`, `BasisNotAllowed(basis, kind)` (e.g. `validator` on free text), `EndorserBelowTarget`.
- `check_persist(writer_ctx: Label, scope, item) → ok | ScopeCeilingExceeded`.
- `retrieve(query, slot_min_authority, validity_required, reader, k) → [Item]` — P5; invariant: every returned item satisfies the three filters; the *order of application* is part of the contract; failure `NoAuthoritativeItems` (distinct from empty relevance).
- `lower_provenance(record, target) → ext_payload | LoweringLoss`; `lift_provenance(target_payload) → ProvenanceRecord` — P7; `lift` never yields authority > `external`.
- `verify_attestation(record) → verified | AttestationFailed` — anchors on signer/chain, never on the record's own claim.
All operations are implementable out-of-process over the canonical encoding (T-LCD-12).

### 6.9 Acceptance-criteria sketch

- **AC-L3-1 Coverage.** Every HIR node/edge and every event in §6.6's mandatory list carries a `ProvenanceRecord`; `validate`/`append` fail with `MissingProvenance` otherwise. (C0/Stage 1)
- **AC-L3-2 Monotonicity.** Property test over random derivation/delegation/persistence sequences with no endorsement events: `label(out) ⊑ ⊔ label(inputs)` always; any upward move without a paired legitimate endorsement is rejected. (C0/Stage 1)
- **AC-L3-3 M-CPE fixture.** A tool result and a workspace file containing instruction text and an injected filename are delivered; the compiled context places them only in roles ≤ `role_map(external)`; `context_label = external`; a destructive/open-world effect proposed in that call is `ask`/`deny` per Π, and its `approval` (if given) endorses only that `effect_id`. (C0/Stage 2–3)
- **AC-L3-4 X-CPE fixture.** After reading external content the model writes a memory and attempts a user-scope config write: the memory persists with `authority ≤ external`; the user-scope write is refused without `approval`; on the next run the memory is never rendered into a `definition`/`principal` slot and `retrieve(slot_min_authority = principal)` excludes it. (C0/Stage 2)
- **AC-L3-5 Revocation.** A revoked memory with higher relevance than its replacement is never returned under default `validity_required` (S-106 scenario); with `admit_unknown_validity` a memory with no check is returned flagged `unknown`. (C0/Stage 2 filter; C2 lifecycle)
- **AC-L3-6 Delegation.** Child permissions ⊆ parent; child results enter the parent at `≤ delegate` with union taint; a parent effect using child-tainted args is gated as tainted; a hosted participant's rows carry `origin = participant`. (C1/Stage 4)
- **AC-L3-7 Lowering.** MCP lowering carries `hir/provenance` in `_meta`; lifting an MCP result yields `unverified` (server not in definition) or `external` (declared open-world tool); the loss report names the role collapse for a two-role target. (C0/Stage 3 with T-LCD-11)
- **AC-L3-8 Text leaves.** Every `Text` leaf has an authority class; the opacity report breaks down by class (T-LCD-02). (C0/Stage 1)
- **AC-L3-9 Endorsement audit.** Every label increase in a run is traceable to a `security.label.endorsed/declassified` event with a basis from §6.3 and an endorser of sufficient class; the chain verifies. (C0/Stage 2 with WS-H6)
- **AC-L3-10 Utility measurement.** The Lab can run "same task, same budget, with vs without the taint gate / with subagent isolation" and report success, approvals and cost (T-LCD-14). (C0/Stage 3)

### 6.10 Build-stage suggestion

## 10. Confidence

**High** for the lattice shape (product of a command-authority chain, a taint set and a reader set with min/∪/∩ join): it is the shared construction of CaMeL and Fides read in source, of DLM/Biba/Denning (Tier A), and every 2026 attack paper's privilege model is a chain. **High** for validity-before-authority-before-relevance as a contract order and for "the model can never endorse": S-106's mechanism, WS-A2's three-valued validity and doc 2 §5.6 agree, and no audited system contradicts them. **Medium-high** for the seven specific class values: the top four and the bottom two map one-to-one onto precedents (instruction-hierarchy roles, S-103 r0…r4, CaMeL sources, WS-A3 `imported/unverified`); `environment` is the least-evidenced and is explicitly reversible (OQ-102). **Medium** for the per-call context label as the C0 control-flow approximation: Fides proves the mechanism sound for explicit secrecy and integrity non-interference, but its utility cost in a coding harness is unmeasured until Stage 3 (AC-L3-10). **Medium** for the closed endorsement list: the six bases cover every precedent found, but WS-H5/H7 may need additional bases (recorded as dialect-bump territory). No C0 recommendation rests on a `provisional` performance number; S-103/S-104/S-105/S-106 are used for mechanism existence only.
