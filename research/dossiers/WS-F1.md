## 1. Scope & boundary

This workstream decides **where control lives and how the answer is made pluggable**: (i) the **Control contract** — the operation-shaped contract of the `control_strategy` component class (ADR-0016 names it a Stage-1-mandatory slot key on `AgentProcess.native`), its state, its invariants and its failure modes; (ii) the **kernel driver** that executes any strategy's decisions through the plane operators of the harness step (`render → propose → interpret → authorize → execute → verify → persist → decide`, ADR-0012); (iii) the **family mapping** — how ReAct-style model-directed loops, plan-execute, FSM/workflow graphs and the deterministic-envelope ("agentic programming") style are each one *variant* behind the same contract, distinguished by their **control-boundary preset** β : `DecisionPoint → {code, model, human}` and by whether their plan structure is fixed at compile time or emitted by the model at run time; (iv) the **Stage-0 minimal strategy** (doc 2 §11 Stage 0; the T-LCD-03 anchor, OQ-039); (v) how strategies are **IR-expressible** (WS-A3 `Procedure`/`Loop` steps and the WS-A4 `RuntimePlan/1` control section) and what F1 asks A4 to carry; (vi) the **canonical Lab comparison experiment** that makes CF-005 a measured question rather than a fixed decision; (vii) answers to OQ-062 (may guards reference Validators) and a stance on OQ-092.

It explicitly leaves to neighbours: **WS-F2** — the control envelope itself (budget `check`/`reserve`, hard-ceiling exhaustion, retry/timeout policy, idempotency, state invariants, schema validation) — this dossier only fixes the *seam* through which every decision passes the envelope; **WS-F3** — the sub-agent orchestrator behind the `delegate` decision (spawn/isolate/merge, topology); **WS-F4/F5** — value-of-compute scheduling and multi-agent consistency; **WS-D1/D2** — what `render` produces and when `compact` fires (F1 only routes the `compact` decision); **WS-G1/G2/G3** — validators, execution alignment and critics behind the `verify` decision; **WS-H1/H7** — the reference monitor behind `authorize` and the approval surface behind `escalate`; **WS-B3/B4** — recovery and replay drivers (F1 supplies `checkpoint/restore` and the `deterministic_replay` declaration ADR-0028 asks for); **WS-D5** — the rich Procedure IR beyond the HIR/1 kernel; **WS-J3/J4** — the experiment engine and analysis that run the comparison designed here.

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — The minimal loop is four operations and three exits, and every one of its guards is a budget dimension the program already has.** mini-SWE-agent's entire control strategy is `run: while True: step(); step = execute_actions(query())` (`default.py` L88–128). `query` checks `step_limit`, `cost_limit` and `wall_time_limit_seconds` *before* the model call and raises `LimitsExceeded`/`TimeExceeded` (L130–147); `execute_actions` executes every action the model emitted and formats observations (L154–157); the environment — not the agent — raises `Submitted` when the output begins with the submit marker and `returncode == 0` (`local.py` L43–56); a `FormatError` (no action in the response) is fed back as a message and counted, and `max_consecutive_format_errors` converts repeated format errors into an exit (L100–114). Exits are messages with `role = "exit"` carrying `exit_status ∈ {Submitted, LimitsExceeded, TimeExceeded, RepeatedFormatError, <exception name>}` and a `submission` (L122–124; `handle_uncaught_exception`). Its three limits map one-to-one onto ADR-0039 kernel counters (`model_calls`, `spend`, `time.wall_ms`); its format-error counter is a `retry` decision-point guard; its submit marker is an environment-detected `stop` signal. This is the Stage-0 shape doc 2 §11 asks for, and it is expressible with **no construct outside HIR/1**: one `Goal`, one `ToolCapability{exec}`, one `Budget`, one `Loop(bound = Budget){propose; act}`, two `Text` leaves (system and instance templates), and a `ControlBoundary` preset (§6.3).

**F2 — Production loops are the same loop with four additions: a steering/follow-up queue, a compaction trigger, a stop hook, and a retry envelope around sampling — and the "no action ⇒ stop" rule is stated in code.** Codex's `run_turn` docstring: "If the model requests a function call, we execute it and send the output back to the model in the next sampling request. If the model sends only an assistant message, we record it … and consider the turn complete" (`turn.rs` L150–162). The inner loop (L430–700) is: drain pending user input → deliver a budget reminder as a context item (`rollout_budget.rs`) → capture the step context (tools, permissions) once per sampling request → `run_sampling_request` (a retry loop, L1508–1640, with `ContextWindowExceeded` and `UsageLimitReached` non-retryable) → `needs_follow_up = model_needs_follow_up || has_pending_input` (L539) → if the context window is full, run mid-turn compaction and `continue` (L574–613) → if no follow-up is needed, run **stop hooks**, which may `should_block` and inject a continuation prompt (L616–660) → break. The outer task loop re-enters `run_turn` while the input queue has pending input (`regular.rs` L85–105). Abort reasons are a closed enum `{Interrupted, Replaced, ReviewEnded, BudgetLimited}` (`protocol.rs` L4191) and a session budget converts into a typed error (`SessionBudgetExceeded`). Every one of these is a **decision** at a named point: `stop` (model: no tool call; code: budget; human/hook: block-and-continue), `compact` (code: token status), `retry` (code: retryable stream error), `escalate` (approval requests), and the steering queue is a **cue** the strategy consumes, never a mutation of its state from outside.

**F3 — Pi separates the *pure decision* from the *effect*, persists the operation state machine, and admits effects through a gate: this is the contract shape.** Pi's older `agent-loop.ts` is Codex's loop in functional form (outer loop over follow-ups, inner loop over tool calls and steering; `shouldStopAfterTurn`; a `length` stop reason fails every tool call in the batch "instead of executing potentially borked calls", L226–235). Its newer harness runtime is more instructive: the durable `OperationState` is "one flat union" of 13 leaves (`starting → checkpoint → assistant.ready → assistant.effect_pending → tools → …` plus summary/deferred/navigation leaves, `session/types.ts` L316–329); the `Continuation` at a checkpoint is exactly `need_assistant | may_finish` (L119–121); a response with tool calls becomes `tools{batch}`, a response without becomes `checkpoint{may_finish}` (`response.ts` L300–320), and each tool call carries `planned → effect_pending{replay: never|safe} → outcome_ready → completed` (L155–160). `driveOperation` is a dispatcher that must make progress on every pass ("Drive procedure made no progress from …" is an invariant error, `drive.ts` L102–104), and every model call or tool call is issued through `gate.admit(...)`, where a requested cancellation *wins* admission (`effect-gate.ts`). A `before_run_end` hook may inject a follow-up user message and return the operation to `assistant.ready` (`boundary.ts` L174–230) — the same "stop hook may block" mechanism as Codex, expressed as a state transition. Three lessons the contract adopts: (i) the strategy's state is a **closed sum** that is persisted, so resume is "dispatch on the leaf" (Stage 1 needs this for ADR-0028/ADR-0030); (ii) *deciding* and *effecting* are different operations — the decision is pure and committed first, the effect is admitted through a gate that the envelope and cancellation control; (iii) `may_finish` is a *proposal* that the boundary (hooks, inbox, compaction threshold) may override — completion is a decision the code owns even when the model triggered it.

**F4 — Loop pathologies are real and every mature harness carries a code-owned `stop` guard for them.** OpenHands' `StuckDetector` checks four patterns (repeating action/observation, repeating action/error, monologue, alternating pattern, plus context-window errors) with per-pattern thresholds, and the run loop consults it every iteration (`local_conversation.py` L1985; `stuck_detector.py`); Gemini CLI's `LoopDetectionService` combines a hash-based check for five consecutive identical tool calls, a content-chanting detector (ten repeats at near-constant period) and an LLM judge over the last twenty turns; Codex and OpenHands both bound the run by `max_iteration_per_run`/session budget; Inspect breaks after three consecutive `content_filter` responses (`_react.py` L262–271). OpenHands additionally lets a **stop hook deny stopping** with feedback fed back as an environment message (L1948–1975) — the "premature stopping" failure of doc 2 §4 P3 handled by code. Consequence: `stop` is a decision point whose `code` owner is mandatory even in model-directed variants; the guards are typed predicates over the ledger (repeat counts, error streaks, budget), and a `judge`-class guard is admissible only as an *escalation* input (ADR-0047 headline discipline).

**F5 — The FSM/workflow pole is a graph interpreter with a step budget and interrupt points; ReAct is one two-node graph in it; plan-execute is that graph plus a validated plan artifact.** LangGraph's Pregel `tick` returns `out_of_steps` when `step > stop` (derived from `recursion_limit`), `done` when no tasks remain, and raises `GraphInterrupt` at declared `interrupt_before/after` nodes (`_loop.py` L599–681); the prebuilt ReAct agent is two nodes and one conditional edge whose `should_continue` returns `END` when the last message has no tool calls (`chat_agent_executor.py` L831–850), with optional `pre_model_hook`/`post_model_hook` nodes — i.e. the model-directed loop is a *special case* of the code-directed graph. Inspect's `react` makes the stop rule a **parameter**: with a `submit` tool the model is nudged when it stops calling tools; without one, no tool call terminates; `attempts` turns a scored submission into "continue with an `incorrect_message`" (`_react.py` L74–101, L280–330). Anthropic's five workflow patterns (prompt chaining, routing, parallelisation, orchestrator-workers, evaluator-optimiser) are all expressible as `Procedure` step graphs over `Instruction/Invoke/Branch/Loop/Delegate/Verify` (S-032; ADR-0016 entity 5). Plan-and-Solve and LLMCompiler add the missing piece: a **model-emitted plan as a typed artifact** (a list of sub-tasks; a DAG of function calls) that code then executes — sequentially or in parallel — and re-plans on failure. Dhage's only unambiguous positive result is precisely this: *schema-validated* structured planning raised reproducibility to 1.000 in 3/4 cells (`provisional`). Consequence: the four family members are one plan language (`RuntimePlan/1` control nodes) under two switches — β presets and **plan provenance** (`compiled` vs `model_emitted`, the latter schema-validated before execution).

**F6 — "Where control lives" is empirically model- and task-conditioned, and the evidence base for the deterministic pole is thin.** Dhage's basic harness improved reproducibility in one cell, degraded it in two, and split latency by model (`provisional`); LLM-as-Code offers a case study without a matched baseline (`provisional`); Barbaste finds that "loop sophistication does not predict benchmark performance" and that provider-native systems compose primitives (ReAct + plan-execute + generate-test-repair + retry) rather than pick one (`provisional (mech)`); doc 2 §6 rates "a fully deterministic outer program is superior" as an **open question**. Consequence for the design: the program may not *decide* CF-005; it must make β a first-class, cheaply variable factor (ADR-0012 decision 6) and ship the comparison as a Lab recipe with pre-registered hypotheses that include the null. This is the "pluggable + envelope" resolution CF-005 already anticipates.

**F7 — Every loop read here reserves a set of decisions for code regardless of style, and that set is the control envelope.** Budget checks before the call (mini-SWE-agent, Codex, OpenHands, LangGraph `recursion_limit`, Inspect `message_limit/token_limit`), cancellation winning effect admission (Pi gate; Codex cancellation tokens), retry of retryable stream errors with bounded attempts (Codex, Pi `retry_wait` leaves), refusal to execute tool calls from a truncated response (Pi `length`), compaction on overflow (Codex, Pi `summary.deciding`, Inspect `_handle_overflow`), and a human confirmation state (mini-SWE-agent `confirm` mode; OpenHands `WAITING_FOR_CONFIRMATION`). None of these is delegated to the model in any system. This is doc 2 §4's design principle observed seven times, and it fixes the seam: the strategy *proposes* decisions; the envelope *checks* them; the driver *executes* them.

## 5. Disconfirming evidence & negative results

**Against one contract for four strategies ("they are different things").** Workflow engines (LangGraph) are graph interpreters with channels and supersteps; ReAct loops are a `while`; plan-execute needs a planner/executor split; agentic programming wants the program to own everything. Forcing them behind one contract could be the LCD trap (feature intersection, T-LCD-07's failure signature). *Why it does not overturn:* the audit shows the opposite direction of containment — LangGraph's prebuilt ReAct is a two-node graph (F5), Codex/Pi loops are state machines whose leaves are exactly `propose / act / compact / retry / stop` (F2/F3), and Barbaste finds production systems *composing* these primitives. The contract in §6.1 is not the intersection of features; it is the **union of decision points** (the closed `DecisionPoint` sum) plus a plan cursor over `RuntimePlan/1` nodes, and each variant declares which points it owns. A variant that needs a construct the plan language lacks raises `PlanError{unsupported_construct}` (ADR-0019) and is either a dialect bump or a `CompiledPayload` body behind the same contract — never an escape hatch. The cost is that exotic control (e.g. Pregel channels) is an opaque body at C0; that cost is measured (opacity report), not hidden.

**Against making the boundary variable ("just decide it").** Doc 2 §4's principle (invariants in code, search in the model) is well supported (F7), and a research runtime that varies β multiplies configurations. *Why it does not overturn:* the principle fixes the **envelope**, not the strategy — every β preset keeps `authorize`, budget-`stop`, `retry`-of-infrastructure-errors and cancellation in code (§6.1 invariant I5). What varies is who owns `plan`, `act`-selection, `verify`-triggering, `compact`-triggering and *task-completion* `stop`. Dhage's mixed cells and doc 2 §6's "open question" verdict mean fixing those would be a C0 decision resting on `provisional` evidence — forbidden by doc 3 §3.1.

**Against "no action ⇒ stop" as the Stage-0 default.** mini-SWE-agent (the T-LCD-03 anchor) does the opposite: a response without an action is a `FormatError` and the model is nudged; only the submit marker stops the run. Inspect defaults to a submit tool with nudges. Codex, Pi, OpenHands and LangGraph stop on no-tool-call. *Resolution:* the stop rule is a typed parameter of the Stage-0 variant (`stop_rule ∈ {no_action, submit, either}`, with `max_nudges`), not a variant; the T-LCD-03 anchor configuration uses `submit` with a format-error nudge cap, matching mini-SWE-agent exactly (§6.3). Every nudge is a `HarnessRule{insert ContextItem}` whose text is a `Text` leaf and whose delivery/activation/following are T-LCD-13 events.

**Against model-owned `stop` at all (execution-alignment risk).** Harness-Bench's failure class (S-062, via doc 2 §5.3) is the model claiming completion that the state does not support; letting the model trigger `stop{completed}` bakes that in. *Why it does not overturn:* under ADR-0016 a `model_claim` never satisfies a Validator alone, and under ADR-0047 the headline oracle is deterministic. The contract therefore makes model-triggered completion a *proposal* (`may_finish`, Pi's word) that code may reject: at Stage 0 the only checks are budget and open-effect closure; at Stage 3 WS-G2's reconciliation and WS-G1's task-contract validators become guards at `stop` (OQ-062 answer, §6.5). Whether the model or a validator "owns" `stop` is itself a β coordinate the Lab varies.

**Against deterministic replay in the contract.** It constrains variants (Temporal-style determinism, S-193) and no audited coding harness does it. *Why it does not overturn:* ADR-0028 already settled this as a *declared* capability with `n/a` semantics; F1 only adds the two operations a declaring variant needs (`checkpoint/restore` and a pure `decide`) and makes `decide` pure for *all* variants (the driver, not the strategy, issues effects) because that costs nothing and is what Pi already does.

**Negative results from the audit.** No audited harness (i) records *which party owned each decision* as data — β is observable only indirectly (Harbor `llm_call_count == 0`, ADR-0012); (ii) treats the stop rule as a swappable parameter of one loop *and* runs the alternatives under matched budget; (iii) executes a model-emitted plan through the same interpreter that runs authored workflows; (iv) exposes its steering/follow-up/hook overrides as typed decisions with owners. Items (i)–(iv) are what §6 adds, each `no-precedent / novel` in the narrow sense and precedented in parts (Pi's `Continuation`, Inspect's parameters, LangGraph's graph, LLMCompiler's planner).

## 6. Recommendation for the spec

### 6.1 The Control contract (component class `control_strategy`; operations · inputs/outputs · invariants · failure modes)

The class is registered per ADR-0023 with `required_inputs ⊇ {ModelProfile, ResourceAccount}` (T-LCD-08), operation-shaped (T-LCD-12), implementable out-of-process (a variant may run on the lab side of the ADR-0050 boundary if it declares `latency_class = per_turn`; the Stage-0 variant is kernel-side). Two parties: the **strategy** (variant, MUST-code algorithm, ADR-0024 rung "registered variant") and the **driver** (Core, MUST-code).

**Runtime records.**
- `ControlContext{process_ref: Ref<AgentProcess.native>, plan: RuntimePlan.control (closed node kinds, ADR-0019), boundary: ControlBoundary{assignments, guards} (ADR-0016), profile: ModelProfile, account: ResourceAccount, budget: BudgetNode ref (ADR-0040), envelope: EnvelopeHandle (WS-F2), parameters: typed values from the definition, capabilities_available: {delegation, compaction, verification, steering} (what the assembled harness can do)}`.
- `ControlState` — a **closed sum per variant** (Pi precedent) with a mandatory common header `{variant_ref, cursor: PlanCursor{node_id, iteration, bound_ref}, decision_count, open_effects: [effect_id], last_cue_seq, boundary_view: map<DecisionPoint, owner>}` and a variant-private body; canonical-serialisable (`checkpoint`), never containing secrets, model I/O bytes or environment state (references only).
- `Cue` (input to `decide`; closed sum): `run_opened{goal_ref, inputs}` · `resumed{last_durable: EffectPhase | DecisionRef, recovery_decision}` · `model_completed{model_call_id, response_ref, stop_reason ∈ {end, tool_use, length, content_filter, error, aborted}}` · `effects_settled{[ {effect_id, outcome: terminal | unknown} ], all_terminal: bool}` · `verification_completed{validation_id, verdicts}` · `retrieval_completed{…}` · `compaction_completed{view_hash}` · `delegation_completed{child_run_id, result_ref}` · `human_input{kind ∈ {steer, follow_up, approval{effect_id, allow|deny}, interrupt}, ref}` · `envelope_signal{kind ∈ {soft_threshold, refused{decision_ref, reason}, retryable_error{class, attempt}, cancel_requested}}` · `guard_fired{decision_point, guard_id}`.
- `ControlDecision` (output; closed sum keyed by `DecisionPoint`): `propose{decision_point: plan|act, context_request: ContextRequest, expected_output: free | schema(Ref<Validator{kind: schema}>)}` (one model call) · `act{intents: [EffectIntent], mode ∈ {sequential, parallel}, on_partial ∈ {continue, stop}}` · `retrieve{query}` · `compact{reason ∈ {threshold, overflow, manual}}` · `verify{validator_refs, subject}` · `delegate{spec: AgentProcessSpec, budget_slice, permissions}` · `retry{target: model_call | effect_id | plan_node, attempt, not_before?}` · `escalate{ask: approval{effect_id} | question{Text} | handoff}` · `wait{until: cue_kind | deadline}` · `stop{proposed_reason ∈ {completed, cannot_proceed, budget_exhausted, context_exhausted, guard_tripped(guard_id), cancelled, error(class)}, submission_ref?}`. Every decision carries `{decision_point, owner ∈ {code, model, human}, rationale_ref?}` — `owner` is the value of β at that point *as exercised*, so DRIFT between declared and observed β is computable.

**Operations.**
1. `capabilities(variant) → ControlCapabilities{deterministic_replay: bool, steering: bool, follow_up: bool, parallel_effects: bool, delegation: bool, model_emitted_plan: bool, resumable_mid_effect: bool, decision_points_owned: set<DecisionPoint>, boundary_preset: ControlBoundary, requires: {procedure?: bool, goal: bool}}` — a declared record (ADR-0028 decision 2; T-LCD-07 discipline applied to native variants: declared then tested, `n/a` when absent).
2. `open(ctx: ControlContext) → ControlState₀ | ControlError{IncompatibleBoundary, MissingProcedure, UnsupportedPlanNode(node)}` — pure; refuses a `ControlBoundary` that assigns an envelope-reserved point (I5) to `model`.
3. `observe(state, events: [Event]) → state'` — pure fold of durable ledger events (`seq`-ordered) into state; idempotent on re-delivery (`last_cue_seq`).
4. `decide(state, cue: Cue) → (state', ControlDecision)` — pure; total over `Cue`; must return `stop` when `cursor.bound` is exhausted; must not return `act` while `open_effects ≠ ∅` unless `capabilities.parallel_effects`.
5. `terminate(state, reason: StopReason) → FinalReport{stop_reason, submission_ref?, unresolved_effects: [effect_id], decisions: count, boundary_observed: map<DecisionPoint, owner>}` — pure; called by the driver after the envelope has closed every open effect; the strategy may not issue effects here.
6. `checkpoint(state) → bytes` / `restore(bytes, ctx) → state | RestoreError{VariantMismatch, DialectMismatch}` — canonical form (ADR-0029 class); the driver persists a checkpoint reference on every `control.decision`.

**The driver (Core).** `drive(run, strategy, ctx)`: `state ← restore | open`; loop: `cue ← next_cue(ledger, inbox)`; `(state, d) ← decide(state, cue)`; `verdict ← envelope.check(d, budget, boundary.guards)` (WS-F2: reserve-before-spend for `propose`/`delegate`, guard evaluation, gauge caps, permission pre-check for `act` via H1); append `control.decision{decision_id, decision_point, owner, kind, reason, checkpoint_ref, verdict}`; if `refused` → `cue ← envelope_signal{refused}`; else execute `d` through the plane operators (`render`+`propose` → model boundary; `interpret`+`authorize`+`execute` → effects lifecycle per ADR-0030; `verify` → WS-G1; `persist` → ledger) producing the next cue; on `stop` → close open effects (ADR-0040 decision 5), `terminate`, append `lifecycle.run.finished{stop_reason}`. The driver bounds its own loop by `decision_count ≤ Budget.dimensions.turns.hard × k` and by a **no-progress check** (two consecutive identical `(state_hash, decision)` pairs ⇒ `stop{guard_tripped(no_progress)}`, Pi precedent).

**Invariants.**
- **I1 Decide-before-effect.** Every effect intent is preceded in the ledger by the `control.decision` that produced it (`causes[] ∋ decision_id`); no effect without a decision, no decision without an owner.
- **I2 Strategy purity.** `observe`/`decide`/`terminate` read only their arguments; a strategy never holds a model, tool, environment or ledger handle — the driver issues every effect through the envelope (Pi gate). This is what makes `deterministic_replay` a declaration rather than a rewrite (ADR-0028 (c)).
- **I3 Closed sums, total decide.** `Cue`, `ControlDecision`, `StopReason` are closed per dialect; `decide` handles every `Cue` (a variant may answer `wait`); unknown cue ⇒ `ControlError{UnhandledCue}` at conformance test, never at run time.
- **I4 Bounded.** Every `Loop` in the plan is bounded by a Budget (ADR-0016); the driver's own cap and the no-progress check hold for every variant; `stop` is a decision, never an exception (mini-SWE-agent's exceptions are its *internal* idiom; at the contract boundary they are `stop{reason}` values).
- **I5 Envelope-reserved points.** `authorize` is always `code` (H1 monitor; `human` only via `escalate`); `stop{budget_exhausted | context_exhausted | cancelled}` and `retry` of infrastructure errors are always `code`; the envelope's verdict is final (`refused` returns to the strategy as a cue). A `ControlBoundary` violating this is `IncompatibleBoundary` at `open` and `validate` (HIR).
- **I6 Completion is a proposal.** `stop{completed}` from a `model`-owned point is accepted only if `open_effects = ∅` after closure, the submission (if the definition requires one) is present, and every `stop` guard passes (§6.5); otherwise the driver converts it into `cue = guard_fired` (Codex stop-hook block; OpenHands stop-hook denial; Inspect `on_continue`). The number of conversions is bounded by a typed parameter (`max_continue_nudges`).
- **I7 Cues are the only input.** Steering, follow-ups, approvals and hook feedback enter as `human_input`/`envelope_signal` cues drawn from the ledger inbox — never by mutating state (Codex `input_queue`, Pi inbox). Delivery order is ledger order.
- **I8 Observed β is data.** `boundary_observed` in `FinalReport` and `owner` on each decision are what WS-J4 compares to `ControlBoundary.assignments` (declared) — DRIFT is reported, never silently corrected.
- **I9 Profile and account are inputs** (T-LCD-08); a variant that needs model-conditioned behaviour reads `profile.capabilities` and expresses it as a conditioned `HarnessRule` with an assumption-debt record (T-LCD-05) — never an `if model == X` (T-LCD-01).

**Failure modes (typed).** `ControlError{IncompatibleBoundary, MissingProcedure, UnsupportedPlanNode, UnhandledCue, VariantMismatch, DialectMismatch}`; driver-level `stop{guard_tripped(no_progress | max_continue_nudges | loop_detected(kind) | consecutive_errors)}`, `stop{budget_exhausted{dimension}}` (ADR-0040 wording), `stop{context_exhausted}` when `context.occupancy` gauge refuses and no `compact` capability is available, `stop{error(class)}` for non-retryable model/infrastructure errors (`ContextWindowExceeded` after one compaction attempt, `UsageLimitReached`, provider fatal — Codex classes).

### 6.2 Data-model sketch (ledger and IR touch points)

- **Ledger.** `control.decision{decision_id, decision_point: DecisionPoint, owner ∈ {code, model, human}, kind: ControlDecision.kind, reason, strategy_variant_ref, checkpoint_ref: ContentAddress, cursor: PlanCursor, verdict ∈ {admitted, refused{reason}}, budget_remaining}` — extends WS-B1's row (ADR-0026 table: `kind ∈ {continue, stop, delegate, retry, ask, compact}`) to the full `ControlDecision` sum with `decision_point`/`owner`/`checkpoint_ref`; `continue` ≡ `propose`, `ask` ≡ `escalate` — proposed as an amendment to ADR-0026's event table (CF-WS-F1-01). `control.guard.fired{decision_point, guard_id, predicate_ref, inputs_hash}`; `control.plan.emitted{plan_ref: ContentAddress, schema_validator_ref, valid: bool}` (plan-execute; the model-emitted plan is a content-addressed `Procedure` artifact with `provenance.origin = model`, `authority = delegate`); `control.nudge.delivered` is not a new class — a nudge is `context.artefact.delivered` with `artefact_kind = rule` (T-LCD-13). `lifecycle.turn.started/finished` remain the strategy's to emit (WS-B1): a **turn** = principal input → idle (Codex/B1 sense); a **harness step** = one `propose` cycle (ADR-0012 sense) — the two are distinct scope kinds (`turn` ⊃ `model_call`).
- **IR.** No new entity. `AgentProcess.native.slots["control_strategy"] = SlotBinding{variant_ref, parameters}`; `ControlBoundary{assignments, guards}` as ratified; `Procedure` steps and `Loop(bound)` as ratified; `RuntimePlan/1` control nodes `{loop, step, branch-on-validator, delegate, stop-rule}` (ADR-0019) consumed as the `PlanCursor` domain. Two small requests to WS-A4/WS-A3 (CF-WS-F1-02): a `step` node carries `mode ∈ {sequential, parallel}` and `output_schema?: Ref<Validator{kind: schema}>` (LLMCompiler/Dhage), and a `loop` node carries `replan_on ∈ {never, failure, always}`; both are attributes on existing kinds, not new kinds, so `RuntimePlan/1` stays closed.
- **Parameters (MUST-data, ADR-0024).** `stop_rule ∈ {no_action, submit, either}` · `max_continue_nudges: int` · `max_consecutive_format_errors: int` · `max_consecutive_errors: int` · `tool_batch_mode ∈ {sequential, parallel}` · `on_truncated_response ∈ {fail_calls, execute}` (default `fail_calls`, Pi) · `plan_provenance ∈ {compiled, model_emitted}` · `replan_on` · `loop_guards: [{kind ∈ {identical_action(n), action_error_streak(n), content_period(n), alternating(n)}, threshold}]`. Nudge and reminder texts are `Text` leaves in `HarnessRule`s (T-LCD-02/-05/-13).

### 6.3 The family mapping (four variants, one contract)

| variant | plan provenance | β preset (`plan / act / retrieve / compact / verify / delegate / authorize / retry / stop / escalate`) | precedents | notes |
|---|---|---|---|---|
| `react` | compiled: `Loop(bound){step{propose}; step{act}}` (implicit plan) | model / model / model / code / code / model / **code** / code / model→code (I6) / human | mini-SWE-agent, Codex, Pi, OpenHands, LangGraph prebuilt, Inspect | Stage-0 preset `react/minimal` (§6.4); `react/steerable` adds steering, follow-ups, compaction and stop hooks (C1) |
| `plan_execute` | **model-emitted**: `Loop{step{propose(plan), output_schema}; loop(replan_on){step{execute plan step}}; verify}` | model / code (executor selects the tool the plan names) / code / code / code / model-or-code / code / **model at replan**, code otherwise / code (plan exhausted + verify) / human | Plan-and-Solve, LLMCompiler (parallel DAG), Dhage structured planning, Codex/Claude Code "plan mode" (S-166) | the plan is a `Procedure` artifact validated by a schema Validator before any step executes; `parallel` mode for DAG plans |
| `workflow` (FSM/graph) | compiled: the authored `Procedure` lowered to `RuntimePlan` nodes | code / code / code / code / code / code / code / code / code / human at interrupt nodes | LangGraph Pregel, Anthropic workflow patterns, AFlow/GPTSwarm graphs | the model is invoked only inside `Instruction`/`Invoke` steps; `Branch(Predicate)` and `branch-on-validator` are the transitions |

Two consequences. (a) `program ⊂ workflow ⊂ (plan_execute ∪ react)` in *plan language*; the family is one `RuntimePlan/1` interpreter under two switches, so a definition that supplies both a `Goal` and a `Procedure` can be run under all four variants and compared at component granularity (the comparison design in §6.6 requires this). (b) Hybrids in production (Barbaste: "plan-execute grafted onto ReAct") are `react` with `plan_provenance = model_emitted` and `replan_on = failure` — a parameter point, not a fifth variant.

### 6.4 The Stage-0 minimal strategy (`react/minimal`; doc 2 §11 Stage 0; T-LCD-03 anchor)

- **Definition.** One `Goal` (task text as a `Text` leaf), one `ToolCapability{effects: {exec}}` executed through the sandbox helper (OQ-045 provisional; WS-B5/E5), one `Budget{model_calls.hard, spend.hard, time.wall_ms.hard, turns.hard}`, two `Text` leaves (system, instance), one `HarnessRule{trigger: no_action_in_response, action: insert ContextItem(format-error nudge)}` with a debt record (it is conditioned on models that omit actions), `ControlBoundary = react` preset, `stop_rule = submit` with `submission_marker` detected by the driver on the effect's observed output (mini-SWE-agent `_check_finished` moved from the environment into the driver, so the environment stays effect-only), `max_consecutive_format_errors = 3`, `max_continue_nudges = 0`, `tool_batch_mode = sequential`, `on_truncated_response = fail_calls`, no compaction (`context.occupancy` cap ⇒ `stop{context_exhausted}`), no delegation, no retrieval, `verify` = none beyond submission presence.
- **Decision table.** `run_opened → propose{act}`; `model_completed{tool_use} → act{intents}`; `model_completed{end, no intents} → (stop_rule = submit ? nudge via guard_fired[format_error] : stop{completed})`; `effects_settled{terminal} → (submission observed ? stop{completed, submission_ref} : propose)`; `effects_settled{unknown} → propose` with the unknown outcome rendered (ADR-0030: the model always sees a terminal or explicit `unknown`); `envelope_signal{refused: InsufficientBudget} → stop{budget_exhausted}`; `envelope_signal{retryable_error} → retry{model_call}` up to the profile's `max_retries`, then `stop{error}`; `human_input{interrupt} → stop{cancelled}`; `resumed → observe` then `propose` (never re-issue a `committed` effect — ADR-0028/0030).
- **Why this and not "no action ⇒ stop".** It is the anchor's own rule (F1) and it makes the T-LCD-03 round-trip a faithful comparison; the alternative is one parameter away and is the first β/parameter ablation the Lab runs (§6.6 H4).
- **Deterministic replay.** `react/minimal` **declares `deterministic_replay = true`**: its state is `{cursor, decision_count, open_effects, format_error_streak, last_cue_seq}`; every nondeterministic input (model response, effect outcome, clock via `time.wall_ms` charges) is a recorded event; `decide` is a pure table. AC-B1-4 therefore applies to it at Stage 3 — the first variant to exercise ADR-0028's replay driver.

### 6.5 OQ-062 — guards, and OQ-092 — unresolved effects at completion

- **Guards.** `ControlBoundary.guards: map<DecisionPoint, Predicate>` where at C0 a `Predicate` is a closed expression over ledger-derived state (counters, gauges, last `stop_reason`, effect states, repeat counts) and **may reference a Validator only of kind `{schema, predicate, executable}` with `deterministic = true`**; a `judge` Validator may appear in a guard only at C2 and only with `veto: false` semantics feeding `escalate` (never deciding `stop` or `act`), per ADR-0047's headline discipline and the Gemini precedent (an LLM loop check is one signal among two deterministic ones). Guard evaluation is the envelope's (WS-F2) and is ledgered as `control.guard.fired`.
- **OQ-092 stance (owner WS-G2, decided with F1).** An `unknown` effect blocks `stop{completed}` until probed or `abandoned` (ADR-0040 decision 5: "every open effect closed"); an `abandoned` effect does **not** block completion but forces `lifecycle.run.finished{stop_reason: completed, unresolved_effects: [..]}` and an outcome-class annotation for WS-I2 (`scored` with `veto` from the G2 reconciliation validator when present). Rationale: blocking forever converts an environment fault into an unbounded run, which violates I4.

### 6.6 The canonical control-strategy comparison (CF-005 as a Lab target; feeds WS-J3/J4)

A pre-registered `Design` (ADR-0045) shipped as a Lab recipe:
- **Factors.** `control_strategy ∈ {react/minimal, react/steerable, plan_execute, workflow, program}` (component-level; the definition supplies both `Goal` and `Procedure` so all five bind) × `model snapshot` (≥ 2 families; roles fixed) × `environment` (a coding suite and a terminal suite at Stage 3, WS-I4) × `budget` (`MatchSpec{mode: matched_cap on {model_calls, tokens.output.visible, time.wall_ms}}` plus an `iso_cost` arm, ADR-0041) × `seed` (≥ 5 replicates; `seed_honoured` declared per variant).
- **β-ablation recipe.** Hold the variant fixed and move **one** decision point's owner (`stop`, then `plan`, then `compact`) between `model` and `code`; each move is a `HirDiff` touching only `ControlBoundary.assignments` (surface? no — semantic, classified `semantic_ops`) and is compared pairwise at matched budget. This operationalises doc 2 §4: "move the boundary only when evaluation demonstrates a benefit", and phase-1 §6.9's rule that every "X beats baseline" is a `ComparisonReport{benefit_kind, budget_match.status}`.
- **Metrics (`MetricDeclaration`s, all `applies_to_classes = {native}` at component granularity; hosted participants `n/a{reason: class}`).** headline: executable oracle pass rate with per-task `(c, n)`; process: `reproducibility` (agreement of `control.decision` sequences across seeds — Dhage's Determinism Index recast as a ledger metric), `efficiency` (tokens, model_calls, wall), `reliability` (`budget_exhausted`/`guard_tripped` rates, loop-detector fires), `grounding` (G2 divergence at `stop`), `autonomy` (approvals requested), `budget discipline` (soft-threshold compliance via T-LCD-13), plus `boundary_drift` (declared vs observed β).
- **Pre-registered hypotheses.** H0 (Barbaste): no headline difference between `react/minimal` and richer variants at matched budget; H1 (Dhage, `provisional`): `program`/`plan_execute` raise `reproducibility` and may lower headline on open-ended tasks; H2 (LLMCompiler): `parallel` mode lowers wall time at equal tokens; H3: model × variant interaction is non-zero (T-LCD-09); H4: `stop_rule = submit` vs `no_action` changes `budget_exhausted` rate more than headline. Reported as distributions with clustered-by-task intervals (ADR-0045); `n/a` never 0.
- **Stage.** Design and metric declarations C0/Stage 3 (evaluation-first, with T-LCD-03/-14); execution as the Lab's first component-level study at Stage 3–4; β-ablation over `plan`/`compact` needs `plan_execute` and D2 compaction (C1).

### 6.7 Acceptance-criteria sketch

- **AC-F1-1 (T-LCD-12/-08).** The contract's six operations are specified as operations/inputs/outputs/invariants/failure modes; a conformance suite drives a variant out-of-process over canonical `Cue`/`ControlDecision` documents; every variant receives `(ModelProfile, ResourceAccount)`.
- **AC-F1-2 (T-LCD-03, Stage 3).** `react/minimal` on the Stage-0 definition round-trips mini-SWE-agent behaviourally within the pre-registered margin (paired runs, fixed model/seed/budget); the definition's `opacity_ratio` is reported.
- **AC-F1-3 (I1/I8).** In every native run, each `action.effect.intended` has `causes[] ∋` a `control.decision` with `owner`; `boundary_observed` is computable and equals `ControlBoundary.assignments` for `react/minimal` (DRIFT = ∅).
- **AC-F1-4 (ADR-0028 AC-B1-4).** Re-driving `react/minimal` against recorded model I/O reproduces the `control.decision` sequence and `context.assembled.view_hash` sequence; a non-declaring variant reports `n/a`.
- **AC-F1-5 (I4, fault injection).** Under a stub model that (a) always emits tool calls, (b) never emits tool calls, (c) alternates two identical calls, (d) returns `length`, every variant terminates with `stop{budget_exhausted | guard_tripped | context_exhausted}` within the budget, with zero re-executed `committed` effects across a mid-effect kill and resume.
- **AC-F1-6 (I5).** A definition whose `ControlBoundary` assigns `authorize` or budget-`stop` to `model` fails `validate` (`IncompatibleBoundary`); the same envelope refuses an over-budget `propose` identically for all four variants (`InsufficientBudget`).
- **AC-F1-7 (family).** One sealed definition with `Goal` + `Procedure` binds and runs under all four variants; `plan_execute` refuses an invalid model-emitted plan (`control.plan.emitted{valid: false}`) and re-plans within `max_continue_nudges`.
- **AC-F1-8 (T-LCD-13/-05).** Every nudge/reminder is a `HarnessRule` with a debt record whose delivery/activation/following are ledgered; the "retire rule" recipe removes it and the comparison reruns.
- **AC-F1-9 (T-LCD-14/-09).** The §6.6 recipe is refused without a `MatchSpec` and reports the model × variant interaction.

## 10. Confidence

**High** for the contract shape (pure `decide` + gated effects + persisted closed-sum state + ledgered decisions with owners): it is Pi's runtime in the abstract, matches Codex's and OpenHands' loops operation-for-operation, and every invariant is a restatement of a ratified ADR (0016, 0019, 0026, 0028, 0030, 0040) or of behaviour seen in ≥ 3 audited systems. **High** for the Stage-0 strategy: it is mini-SWE-agent read line by line and expressed in HIR/1 without new constructs. **Medium** for the family mapping: `react`/`workflow` are precedented in source; `plan_execute` rests on Plan-and-Solve/LLMCompiler (Tier A/B) plus Dhage (`provisional`, mechanism only); `program` rests on LLM-as-Code (`provisional`) and PAL — the *expressibility* claim is safe, the *value* claim is deliberately left to the Lab. **Medium** for the comparison design: the metrics exist in the ratified catalogue, but `reproducibility`'s exact definition (OQ-WS-F1-02) and the Stage-3 suites (WS-I4) are open. Nothing `provisional` is load-bearing for a C0 decision; S-065/S-070/S-074 appear only as mechanism, competitor evidence or hypotheses.
