## 1. Scope & boundary

This workstream decides the **observability backbone** of HarnessHarness: (i) the **trace/span model** — what a "span" is for a model call, a tool call, an effect, a context assembly, a verification, a subagent, an environment operation, a permission wait — and its mapping onto the run ledger's identifiers (WS-B1); (ii) the **cost and latency measurement points**, their units, clocks, and the provenance/confidence stamp every measured number carries; (iii) the **process-metric catalogue** the scorecard (WS-I2) consumes, each with its `MetricDeclaration{requires_observability, applies_to_classes}` and the ledger events it is computed from; (iv) the **audit-level requirements** — what is always-on, what is sampled, what is content vs accounting, and how export sinks are classified so the sponsor's "deep audit at all levels" is met without turning telemetry into a second, weaker copy of the ledger; (v) **cross-process correlation** (subprocess tools, MCP servers, ACP participants, subagents) so every externally observed span links back to a ledger event; (vi) **export/interop** to trace/metric conventions, described abstractly as a lowering with a loss report (T-LCD-11 applied to telemetry); and (vii) acceptance criteria and build-stage placement.

The binding position, taken up front: **the span/trace model is a deterministic projection over the WS-B1 run ledger, never a second store.** Every span is derived from a scope-opening ledger event and closed by that scope's terminal event; every accounting number lives in a ledger event payload; every exported trace or metric is `project(run, trace_view | metric_view)`. Telemetry adds no identity that the ledger does not already have.

It explicitly leaves to neighbours: the ledger envelope, ID model, persistence policy, hash chain and derived-view contract (WS-B1 — adopted verbatim; disagreements flagged in §8); the effect lifecycle and its cost fields (WS-B2 — adopted); the **resource taxonomy and cost-attribution rules per hosting mechanism** (WS-L2, OQ-033 — this dossier fixes the *measurement points* and the *provenance vocabulary* by convention and hands L2 the attribution/rollup semantics); metric definitions beyond the process catalogue, factor design, statistical treatment and the `n/a` rule (WS-I2); the tamper-evidence attestation protocol (WS-H6 — this dossier specifies what audit must be able to *see*, H6 specifies how it is *proved*); the trace/time-travel viewer (WS-K2 — consumes `trace_view`); the interchange mapping (WS-J6/I3, OQ-030); pricing-table custody in the reproducible bundle (WS-I3); the Hosting ABI's observability levels (WS-J6, OQ-004/OQ-038); the model gateway that is the natural emitter of per-call usage (WS-C1); and every language/runtime/exporter-library choice (WS-L1). No telemetry library, SDK or backend is chosen here.

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Every audited harness derives its telemetry from the same events that drive the loop; none keeps an independent trace store, and the two that keep a separate accounting table both had to add reconciliation paths.** Codex's `SessionTelemetry` is called from the loop at the same points that produce protocol events (`record_responses` on `ResponseEvent::Completed`, `tool_result_with_tags` around the tool future, `record_turn_cost` from a worker fed by the rollout); the OTel spans are a *view* over the loop, exported and forgotten. goose keeps `usage_ledger` rows *and* per-session accumulators and reconciles drift with synthetic `'carried_forward'` rows (`session_manager.rs: record_usage_metrics`, tests `test_usage_totals_read_through_unreconciled_drift`). opencode projects usage from `step-finish` parts into `SessionTable` columns and must subtract on revert (`projector.ts: applyUsage(sign)`). OpenHands accumulates `Metrics{costs[], response_latencies[], token_usages[]}` in memory beside the event log and snapshots it. **Implication:** two books diverge; a research instrument must have one — the ledger — and every total must be `project(run, cost_view)`. This is WS-B1's materialized-view rule applied to telemetry, and it is why this dossier defines no telemetry store.

**F2 — The industry attribute vocabulary for model/tool/agent spans has converged enough to be a lowering target, but not enough to be the native model.** goose adopts `gen_ai.operation.name ∈ {invoke_agent, execute_tool}`, `gen_ai.usage.*`, `gen_ai.tool.call.{id,arguments,result}`, `gen_ai.conversation.id` verbatim (`agent.rs:1059-1070, 2003-2015, 2474-2494`); Codex mixes `gen_ai.usage.*` with `codex.*` names; OpenHands emits Laminar `LLM`/`TOOL` span types plus `gen_ai.usage.cost`; Arize normalizes `gen_ai.*` ↔ OpenInference. The OTel GenAI conventions are *Development* stability, define no cost attribute, no effect lifecycle, no permission wait, no compaction span (only a boolean `gen_ai.conversation.compacted` that may never be set to `false`), and their content-reference mechanism is a `TODO`. **Implication:** the native span model must be richer than any convention (effects, permissions, context assembly, verification, budget, provenance) and lower to `gen_ai.*`/OpenInference with a declared loss report — T-LCD-11 applied to telemetry.

**F3 — Content capture and sensitivity are handled by *sink classification*, not by sampling.** Codex routes every telemetry event to two targets, `codex_otel.log_only` (may carry `arguments`, `output`, `user.email`, `mcp_servers`) and `codex_otel.trace_safe` (carries only lengths, counts, booleans: `arguments_length`, `output_line_count`, `mcp_tool`) — `events/shared.rs` macros, `targets.rs`. goose gates `gen_ai.input.messages`, `gen_ai.tool.call.arguments`, `gen_ai.tool.call.result` behind an explicit opt-in and records tool results *only on success* (`gen_ai_telemetry.rs: record_tool_result`). OpenHands' product-analytics contract forbids bare strings in any property ("a plain `str` field can hold a prompt, a traceback, or an API key"), buckets magnitudes, pseudonymizes identifiers, and resolves consent with a kill switch (`telemetry/{models,policy,sanitizer}.py`). OTel GenAI defines three content modes and requires the upload hook to run regardless of sampling. **Implication:** the spec needs a *telemetry sink policy* with declared content classes per sink, and the ledger — not any sink — is where content lives (by reference above B1's offload threshold).

**F4 — Latency is multi-point, and the audited systems measure it at different points with different clocks.** Codex distinguishes turn e2e, TTFT (first token), TTFM (first message), API request duration per attempt, SSE event durations, responses-API "overhead" vs "inference time" vs engine TTFT/TBT, and a per-turn *phase profile* `{before_first_sampling, sampling, compaction, between_sampling_overhead, tool_blocking, pending_idle_after_sampling, sampling_request_count, sampling_retry_count}` (`core/src/turn_timing.rs`). OpenHands measures one wall-clock latency per completion *inside the retry attempt* (`telemetry.py: on_request/on_response`), so retries produce several latencies for one logical call. Codex's sandbox outcome records `initial_duration_ms` and `escalated_duration_ms` separately (re-execution outside the sandbox). OTel defines `operation.duration`, `time_to_first_chunk`, `time_per_output_chunk` in *seconds*; Codex and goose use integer milliseconds. **Implication:** the spec must name each measurement point, its clock (monotonic for durations, wall for timestamps), and its unit, and must record attempt-level latencies as children of the logical call — otherwise "latency" is not comparable across harnesses.

**F5 — Cost has provenance, and the provenance changes what a number means.** OpenHands: proxy header `x-litellm-response-cost` ("already cache-aware and priced by the real backend") → pricing library → custom per-token overrides; zero costs are *not recorded*. goose: `CostSource::{ProviderReported, Estimated}` on every usage row. HAL: a static in-repo pricing table keyed by model string (`weave_utils.py`). Harbor: `cost_usd` optional per step, summed with `None` propagation. Codex: `estimated_usd` string parsed into integer micro-USD with explicit rounding (`record_turn_cost`). Inspect: no cost field, only tokens. **Implication:** every cost datum must carry `{provenance, pricing_ref, confidence}`; the *integer micro-unit* representation (Codex) is the only one compatible with WS-B1's canonical-number rule; and the Hosting ABI's three mechanisms map onto three provenance classes (OQ-033) — measured at the model boundary, reported by the participant, reconstructed from a native log.

**F6 — Token accounting conventions contradict across mature systems.** OTel: `input_tokens` *includes* cached tokens; Harbor ATIF: `prompt_tokens` "including cached and non-cached"; Inspect: `input_tokens` "*excludes* cached tokens", true total = `input + cache_read + cache_write`; OpenHands: `prompt_tokens` inclusive for litellm shapes but ACP "reports them separately, so when `cache_read_tokens` exceeds `prompt_tokens` the denominator is their sum" (`metrics.py: cache_hit_rate`) — a runtime heuristic to guess the convention. Provider shapes differ further (`prompt_tokens_details.cached_tokens` vs `cache_read_input_tokens` vs `cached_tokens`; `_cache_creation_input_tokens` private attr). **Implication:** a cache-hit rate or a cost is *wrong by up to the cached fraction* if the convention is not stamped. The spec fixes one canonical convention on the ledger and requires the model adapter (WS-C1) to normalize with a per-provider rule whose identity is recorded.

**F7 — Cross-process correlation already flows through typed extension slots and process environment.** Codex puts `W3cTraceContext{traceparent, tracestate}` in its protocol types, reads `TRACEPARENT`/`TRACESTATE` from the environment at startup, and injects headers on outbound model requests (`trace_context.rs`). The OTel MCP conventions (SEP-414) write `traceparent`/`tracestate`/`baggage` unprefixed into `params._meta`, parent the server span on it, and *link* the transport context. OpenHands re-emits ACP notifications as native-shaped spans with `agent_kind=acp` metadata (`acp_tracing.py`). **Implication:** HarnessHarness needs no new field on any IR entity (T-LCD-06): lowering to MCP/ACP/subprocess injects a trace context whose `tracestate` member carries `(run_id, event_id)`; lifting recovers it into `causes[]`; a hosted participant's spans join the same trace by the same rule.

**F8 — Subagent cost rollup is a tree query, and it is where double counting happens.** goose's `get_session_usage_totals` walks `parent_session_id` recursively and sums both the accumulators and the ledger rows per node, then merges (`session_manager.rs:2375+`); OpenHands' `Metrics.deep_copy()` snapshots per conversation. Codex tags `TokenUsageRecord` with `turn_id` and `root_turn_id` so nested turns can be attributed to the root. **Implication:** cost views must be defined per run *and* per run-tree, with a rule that a child run's cost is attributed to the parent's `control.subagent.spawned` scope exactly once, and that `is_compaction` (goose) / `compaction_response_id` (Codex) calls are attributed to the *harness* (overhead) rather than to task work — a distinction the efficiency dimension of the scorecard needs.

**F9 — Compliance is not instrumented anywhere.** No audited system records that a delivered artefact (skill, rule, memory, tool description) was *activated* or *followed*; Managed Agents found stale guardrails by noticing behaviour across model versions; Codex counts `skills.enabled_total`/`kept_total`/`truncated` (delivery only). This corroborates WS-B1's negative result and makes the `artifact.delivered/activated/followed` chain `no-precedent` (T-LCD-13).

**F10 — Sampling is an export concern; the audited harnesses do not sample their own logs.** goose and opencode configure no sampler (OTel default `ParentBased(AlwaysOn)`); Codex's OTel provider exposes no sampler configuration; all three write their session record unconditionally. OTel decides sampling at span start and pushes tail-based decisions to a collector — impossible for a system whose heavy-tail failures (doc 2 §8) are exactly the runs that must be complete. **Implication:** the ledger is never sampled; sampling and rate limiting apply to *export sinks* and to *ephemeral diagnostics* only.

### 4b. Performance evidence (benchmark lifts) — each tagged `provisional` if 2026 single-team/preprint

- AHE (S-061, `provisional`): Terminal-Bench 2 Pass@1 69.7 → 77.0 over ten iterations; SWE-bench-verified with "12% fewer tokens than the seed"; +5.1…+10.1 pp on three other model families. **Use:** none of these numbers is load-bearing; the *mechanism* (edit ↔ prediction ↔ verified effect) motivates a linkage between `measurement.harness_edit.proposed` and later metric views, consumed by I5/I7 at C4.
- Harness-Bench (S-062, `provisional (mech)`): 5,194 trajectories, 106 tasks, "substantial variation in completion, process quality, efficiency, and failure behavior across model-harness pairings". **Use:** justifies stratifying every process metric by configuration (T-LCD-09); no effect size is used.
- Cursor (S-049, Tier-B production, single team): A/B measures latency, token efficiency, tool-call count, cache-hit rate; per-tool × per-model error baselines. **Use:** engineering evidence that these four are the operationally load-bearing metrics; product-specific thresholds not adopted.
- No benchmark measures "ledger-projected telemetry vs SDK-span telemetry". The C0 recommendation rests on mechanism convergence in four Tier-B codebases and the OTel/MCP specifications, not on any 2026 performance number.

## 5. Disconfirming evidence & negative results

**Against "spans are a projection of the ledger, no second store" (ADR-0042).** (a) Every audited harness *does* run an in-process span pipeline (OTel SDK, Laminar, Langfuse) in addition to its session record, because exporters need spans open while the work happens, with attributes recorded incrementally (`Span.record`), and because backends expect spans, not events. (b) Deriving spans after the fact loses in-flight visibility: a hung tool call is visible as an open span in a live tracer but only as an unclosed scope in the ledger until a terminal event arrives. (c) Kiehl's cost argument applies: `trace_view`, `cost_view`, `metric_view`, `turn_phase_profile` are four more projections over the stream. **Why it does not overturn:** (a) the projection can be computed *incrementally on the durable tail* (WS-B1 `subscribe`) — an exporter is just a subscriber that opens a span at a scope-opening event and closes it at the terminal event, which is precisely what OpenHands' `ACPTurnTrace` does for events it does not own; nothing requires spans to be born before the event; (b) "unclosed scope past its deadline" is itself a first-class view state (`open_scopes`) and is more honest than a span that dies with the process (the audited systems lose that span on crash; the ledger keeps the opening event); (c) the projections are few, fixed, and pure functions of the durable prefix with `view_hash` (AC-B1-3), so the multiplication is bounded and testable. The residual cost — exporters must be written as ledger subscribers rather than instrumented call sites — is carried as a consequence in the ADR.

**Against always-on `model_io` content capture in the ledger.** OTel's default is *not* to capture instructions/messages; goose and Codex gate content behind opt-in; OpenHands' analytics forbids bare strings entirely; privacy regulation, storage cost and access-control separation are the stated reasons. A research ledger that stores every request/response blob for every run is expensive and a liability. **Why it does not overturn:** the instrument's purpose (attribution, replay for declared variants — WS-B1 AC-B1-4, T-LCD-02 opacity, T-LCD-13 compliance judging) is impossible without model I/O for native participants; the mitigation is structural, not a default flip: content lives *only* in the content-addressed blob store (never in spans or metrics), export sinks default to the `accounting` and `structural` classes, redaction is a tombstone (WS-B1 `redact`), retention is experiment-scoped (WS-B1 §6.5), and hosted participants supply `model_io` only when their mechanism and consent allow (OQ-116).

**Against integer micro-currency and integer milliseconds.** Every interchange format and pricing library uses floating USD (Harbor `cost_usd`, HAL, OpenHands, opencode `cost: real`), and OTel histograms are in seconds. Converting at the boundary adds a lossy step and a class of unit bugs. **Why it does not overturn:** WS-B1's canonical form forbids IEEE doubles in hashed payloads (OQ-041), so the ledger *cannot* carry floats without breaking tamper evidence; Codex already does the exact conversion (`record_turn_cost`), and micro-units preserve six decimals, more than any pricing table publishes. The unit conversion is centralized in export lowering and tested (AC-I1-6).

**Against fixing one token-accounting convention.** Providers will keep changing usage shapes; a fixed convention forces a normalization table that rots (assumption debt). **Why it does not overturn:** the alternative (OpenHands' runtime heuristic `cache_read > prompt ⇒ separate`) is a guess that silently mis-states cache-hit rate; the normalization rule is a *conditioned rule* with an assumption-debt record and a `normalizer_ref` stamp, so rot is visible and testable (T-LCD-05 applied reflexively).

**Against a large process-metric catalogue at C0.** doc 2 §8 warns that harness metrics become stale as model capability changes; Cursor's baselines are per-tool × per-model precisely because absolute thresholds do not transfer; S-083 shows apparent gains reverse under matched budgets. **Why it does not overturn:** the catalogue defines *computations over ledger events*, not thresholds or targets; each metric is class-scoped (T-LCD-15) and reported as a distribution per configuration (T-LCD-09); nothing in it is a "good harness" claim. The C0 obligation is only that the events exist to compute them (Stage 1) and that the registry exists (Stage 1); the metrics themselves are Stage 3.

**Negative results recorded:** no audited system records permission-wait latency as a metric (Codex logs `tool_decision` without duration) — `no-precedent` for the autonomy dimension's `approval_wait_ms`; no audited system separates search-time from artifact-time cost — `no-precedent` (T-LCD-14 needs it); no audited system stamps a normalization rule on usage; no audited system exports a loss report when lowering to a convention; OTel GenAI has no cost attribute and an open `TODO` for content references (S-228 §Uploading content) — HarnessHarness must define its own reference form and declare it lossy on export.

## 6. Recommendation for the spec

### 6.1 Position

1. **One record, many views.** The run ledger (WS-B1) is the only store of observations, accounting numbers and content references. Telemetry is the family of *materialized views* `trace_view`, `cost_view`, `metric_view`, `turn_phase_profile`, `open_scopes`, `audit_view` — each a pure function of the durable prefix, stamped `derived_from(run_id, seq)`, with `view_hash` (WS-B1 §6.2 `project`). Exporters are `subscribe` consumers that render views incrementally. There is no telemetry write path.
2. **Spans are scopes.** A span is `(opening_event, terminal_event | open)` for one ledger scope id; span identity is the opening event's identity; the span tree is the ledger's `scope{}` nesting; non-tree causality is `causes[]`. Trace identity is the *root run* of a run tree.
3. **Every number carries its measurement point, unit, clock and provenance.** Latency in integer milliseconds from a monotonic clock, stamped with the point it was measured at; cost as integer micro-units of a declared currency, stamped with provenance, pricing snapshot and confidence; tokens as integer buckets under one declared convention with the normalizer identity.
4. **The ledger is never sampled; sinks are classified.** Always-on: every `durability = ledger` event (WS-B1 persistence policy), including `model_io` blobs for native participants. Sampled or rate-limited: only export sinks and `ephemeral` diagnostics. Each sink declares the content classes it may receive (`accounting`, `structural`, `content`, `diagnostic`) and its redaction policy.
5. **Export is lowering.** Rendering `trace_view` to any external trace/metric convention is a lowering with a *telemetry loss report* (T-LCD-11); lifting an external span (MCP server, subprocess, hosted participant) recovers a `causes[]` link, never a new identity.
6. **Compliance is measured from the ledger** (T-LCD-13): the `measurement.artifact.delivered/activated/followed` chain (WS-B1) is the sole input to compliance metrics; validity comes from `verification.validator.verdict` and is never inferred from compliance.

### 6.2 Interface-contract sketch (language-agnostic)

**Views (all are `project(run, view_kind, until?)` per WS-B1; listed with their invariants).**

- `trace_view(run, until?) → Trace{trace_id, root_run_id, spans: [Span], links: [Link], open_scopes: [Span], loss: none}` — *Invariants:* one `Span` per scope-opening event with `scope_kind ∈ {run, turn, model_call, model_attempt, context_assembly, compaction, tool_call, tool_attempt, effect, permission, validation, subagent, environment_op, memory_op, wakeup}`; `Span.parent` is the nearest enclosing scope by the envelope's `scope{}` fields (`run ⊃ turn ⊃ model_call ⊃ tool_call ⊃ effect`; `subagent` spans parent on the `control.subagent.spawned` event and *link* to the child run's `run.created`); `Span.end` is the scope's unique terminal event (WS-B1 "exactly one terminal event closes each scope id") or absent (`open_scopes`); rolled-back and forgotten ranges are *marked*, never removed; two rebuilds yield equal `view_hash`. *Failures:* `UnknownRun`, `ViewPolicyVersionMismatch`.
- `cost_view(run | run_tree, until?, attribution_policy_ref) → CostSummary{by_scope: map<ScopeId, ResourceVector>, by_attribution: {task, harness_overhead: {compaction, verification, routing, retries}, search_time?}, totals: ResourceVector, provenance_mix: map<CostProvenance, share>, confidence: min|weighted}` — *Invariants:* a child run's `ResourceVector` is counted exactly once, under the parent's `subagent` scope (goose tree precedent); compaction calls are `harness_overhead.compaction` (goose `is_compaction`, Codex `compaction_response_id`); provenance and confidence are never averaged away — the mix is reported (OQ-033); every money field is `Money{micro_units, currency}`; view refuses (`MixedCurrency`) rather than converting.
- `metric_view(run | arm, MetricDeclaration[]) → [MetricValue{name, value | n/a, applies_to, requires_observability, computed_from: [EventRef], provenance}]` — *Invariants:* a metric whose `requires_observability ⊄ run.observability_level` or whose `applies_to_classes ∌ run.participant_class` renders `n/a`, never 0 (T-LCD-15); `computed_from` lists the events so every scorecard number is auditable back to the chain (H6).
- `turn_phase_profile(run, turn_id) → {before_first_sampling_ms, sampling_ms, compaction_ms, tool_blocking_ms, permission_wait_ms, between_sampling_overhead_ms, idle_after_sampling_ms, sampling_requests, sampling_retries}` — Codex `TurnProfile` generalized with the permission-wait phase; phases partition the turn's wall time; `Σ phases = turn_e2e_ms ± clock_tolerance`.
- `audit_view(run, from?, to?) → {events_seen: seq_range, chain_ok: bool, scopes_unclosed: [ScopeId], content_refs_missing: [ContentAddress], redactions: [EventRef], sink_deliveries: [SinkDelivery]}` — what H6 attests over; `sink_deliveries` is itself recorded (see `measurement.export.delivered` below) so the audit knows *what left the system*.

**Measurement emission (who appends what — these are ledger events, produced by the named component; WS-B1 classes reused, payload extensions flagged in §8).**

- `emit_call_timing(model_call_id, attempt_no, timing: Timing{request_sent_ms, first_byte_ms?, first_token_ms?, last_byte_ms, clock: monotonic, measured_at ∈ {adapter, gateway, interceptor}})` — appended by the model adapter (WS-C1) into `model.call.completed/failed` (logical call) and `model.call.attempt.completed/failed` (per attempt; **new class proposed to B1**, CF-089).
- `emit_usage(model_call_id, usage: TokenVector, convention_ref, normalizer_ref)` — the adapter normalizes provider usage once (OpenHands single-source precedent) and stamps the rule it applied.
- `emit_cost(model_call_id | tool_call_id | env_op_id, Money, provenance: CostProvenance, pricing_ref?: ContentAddress, confidence ∈ {exact, high, estimated, unknown})` — appended by the component that *observed* the cost (adapter for model calls, environment service for VM/network meters, hosting adapter for participant reports); lands in `measurement.cost.attributed` (WS-B1) with the extended provenance enum (CF-090); WS-L2 owns the attribution policy that `cost_view` applies.
- `emit_measurement(subject: EventRef | ScopeId, metric_ref, value, unit, detector_ref)` — `measurement.metric.emitted` **restricted** to observations not derivable from other events (external meters, judge scores, environment resource samples) — CF-088.
- `emit_export_delivery(sink_id, view_kind, seq_range, content_classes, loss_report_ref)` — `measurement.export.delivered` (**new class**) so audit can prove which content classes reached which sink.

**Propagation contract (crosses every seam without touching IR entities — T-LCD-06).**

- `outbound_context(run_id, event_id) → PropagationContext{traceparent: (trace_id = H(root_run_id)[0:16], span_id = H(event_id)[0:8], sampled = 1), tracestate: "hh=run:<run_id>;ev:<event_id>", baggage?: {hh.configuration_id}}` — injected by lowering into MCP `params._meta` (unprefixed keys per SEP-414), ACP `_meta`, subprocess environment (`TRACEPARENT`/`TRACESTATE` — Codex precedent), and HTTP headers of model/gateway calls. *Invariant:* the rendered ids are `surface_ids` aliases (WS-B1 F5); the ledger identity remains `(run_id, event_id)`.
- `inbound_context(ctx) → Link{run_id?, event_id?, external_span_id, external_trace_id}` — lifting: if `tracestate` carries an `hh` member the link resolves to an `EventRef` in `causes[]`; otherwise the external ids are stored as aliases on the lifting event (`lifecycle.external_span.linked`, **new class** or a payload field on the receiving event — B1 to choose).
- *Failure modes:* `PropagationUnsupported(target)` → recorded in the target's lowering loss report (WS-A4), never silent; `InvalidInboundContext` → ignored with a `structural`-class diagnostic (Codex "must not fall back to an unrelated active span").

**Export contract.**

- `export(view: trace_view | metric_view, sink: SinkPolicy) → Delivery{seq_range, loss_report: TelemetryLossReport{dropped_fields[], truncated_fields[{field, max_bytes}], unit_conversions[{field, from, to}], unmappable_scopes[]}}` — the sink's convention (e.g. a `gen_ai.*`-shaped tracer, an OpenInference-shaped tracer, a metrics pipeline, a plain structured-log sink) is a *target*; the mapping table per scope kind is declared data; anything the target cannot carry is in the loss report; conversions (ms→s, micro-units→decimal) are listed.
- `SinkPolicy{sink_id, content_classes ⊆ {accounting, structural, content, diagnostic}, redaction ∈ {none, allowlist, pseudonymize}, sampling: {mode ∈ {all, ratio, parent_based}, ratio?}, rate_limit?, max_field_bytes, requires_consent: bool}` — *Invariants:* a sink with `content ∉ content_classes` can never receive a `ContentAddress`-dereferenced payload, only the address; `accounting` sinks accept only constrained scalars and bucketed magnitudes (OpenHands contract); sampling < `all` is refused for the ledger itself (not a sink) and for any sink that a metric in `metric_view` is computed *from* (metrics are computed from the ledger, so this is vacuous by construction — recorded as an invariant so a future shortcut cannot compute a scorecard from an exported sample).

### 6.5 Instrumentation levels and always-on vs sampled (audit-level requirements)

| level | content class | what | always-on? | where it lives |
|---|---|---|---|---|
| L0 | `accounting` | counts, `TokenVector`, `Money`, durations, bucketed magnitudes, error classes, ids — never free text | **always** | ledger event payloads |
| L1 | `structural` | every `durability = ledger` event: scopes, decisions, effects, permissions, validator verdicts, artefact exposures, budget, lineage | **always** | ledger |
| L2 | `content` | model requests/responses, tool arguments/observations, context items, judged evidence — by `ContentAddress` above the offload threshold | **always for native participants**; per capability declaration + consent for hosted; redactable by tombstone | blob store (WS-B1) |
| L3 | `diagnostic` | streaming deltas, permission *requests*, exporter previews, process-level stats | sampled / rate-limited / off | `ephemeral` (WS-B1 AC-B1-12) or sinks only |

Audit requirements ("deep audit at all levels", R-2.8.6 with H6): (a) for every scope kind M1–M18 the opening and terminal events are `ledger`-durable — a span can never exist only in a sink; (b) every exported datum is traceable to `computed_from` events; (c) `measurement.export.delivered` records what left the system, with content classes and loss report; (d) `audit_view.audit_completeness` is a computable metric per run and is `false` if any scope is unclosed past its deadline, any referenced blob is missing without a tombstone, or the chain fails; (e) hosted runs are audited at their declared `observability_level`, and the audit view reports the level rather than pretending completeness.

### 6.6 Acceptance-criteria sketch

- **AC-I1-1 Projection purity.** `trace_view`, `cost_view`, `metric_view`, `turn_phase_profile`, `audit_view` rebuilt from log + blobs after deleting every cache yield identical `view_hash` (extends WS-B1 AC-B1-3).
- **AC-I1-2 Span ↔ scope bijection.** For every scope-opening event in a Stage 3 run there is exactly one span; every closed span's end is the scope's unique terminal event; unclosed scopes appear in `open_scopes` and, past their deadline, flip `audit_completeness` to `false`.
- **AC-I1-3 Attempt fidelity.** A model call with N retries yields one logical span with `attempts = N+1` child spans; the logical `latency_ms` equals the successful attempt's request→last-byte; a run with a sandbox escalation yields a tool span with two attempt children carrying distinct `isolation_mode`.
- **AC-I1-4 Cost provenance.** 100% of `Money` values carry `provenance`, `confidence`, `currency`; `estimated_from_pricing` values carry a `pricing_ref` that resolves in the bundle; a run mixing two currencies makes `cost_view` return `MixedCurrency`, never a sum.
- **AC-I1-5 Token convention.** For a fixture of provider usage shapes (inclusive-cached, exclusive-cached, details-nested, flat), the adapter produces `TokenVector`s satisfying `input_total = input_uncached + cache_read + cache_write` and stamps `normalizer_ref`; `cache_hit_rate` is identical for the same logical usage across shapes.
- **AC-I1-6 Export loss report.** Lowering a Stage 3 trace to a `gen_ai.*`-shaped sink and to an OpenInference-shaped sink produces loss reports that list effect-phase, permission, provenance and micro-unit fields as dropped/converted; lifting the sink's ids back resolves every span to its `EventRef`.
- **AC-I1-7 Propagation.** A tool call lowered to an MCP server and to a subprocess carries `traceparent`/`tracestate` with the `hh` member; the server-side or child-side span, when re-ingested, links to the originating `action.tool.proposed` event; an invalid inbound context is ignored and logged as `structural`, never parented to an unrelated span.
- **AC-I1-8 Sink classification.** A sink declared `{accounting}` never receives a byte of any `ContentAddress` payload (fixture with a secret in a tool result: only length and digest appear); a sink declared `{content}` requires `requires_consent = true` to be satisfied in the manifest.
- **AC-I1-9 Subagent rollup.** In a run tree with a child that itself spawns a child, `cost_view(run_tree).totals` equals the sum of the three runs' `cost_view(run).totals`, and each child appears exactly once under its parent's `subagent` scope.
- **AC-I1-10 Compliance computability (T-LCD-13, with WS-B1 AC-B1-6).** For the Stage 3 reference harness, `artifact_activation_rate` and `artifact_follow_rate` are computable per Model Profile and stratified by `detector`; a fixture with a delivered-but-never-activated skill produces a nonzero `delivered_but_never_activated`.
- **AC-I1-11 Ledger never sampled.** Under any `SinkPolicy.sampling`, `read(run)` returns every `ledger`-durable event; `metric_view` values are unchanged by the sink configuration.
- **AC-I1-12 Class scoping.** Running `metric_view` over a hosted run at `observability_level = {events}` renders every `model_io`/`ledger`-requiring metric as `n/a`, never 0 (T-LCD-15).
- **AC-I1-13 Clock discipline.** Durations in payloads come from monotonic clocks; `trace_view` flags any span whose payload duration and `ts` difference disagree beyond `clock_tolerance_ms`; a fixture with a stepped wall clock yields correct durations and a `clock_skew_flag`.

- **C0 / Stage 0:** M1, M3, M7 payloads (tokens, `Money` with provenance, `latency_ms`, tool `error.class`) written into the single-file trace; `cost_view` and a minimal `trace_view` (run/turn/model_call/tool_call) as the "complete trace" doc 2 §11 asks for.

## 10. Confidence

**High** that the trace/span model must be a projection of the ledger with scope-derived identity: four Tier-B codebases derive telemetry from loop events and the two that kept a second book needed reconciliation; OTel's own SDK limits and start-time sampling make an SDK span store unfit as an audit record; nothing here rests on a 2026 preprint. **High** for the units/clock/provenance conventions: direct precedent (Codex micro-USD, goose `CostSource`, OpenHands precedence, OTel inclusive-token rule) plus WS-B1's canonical-number constraint. **Medium** for the measurement-point table's completeness on planes whose producers (H1, G2, B5, D1) are Phase 2 designs, and for the propagation contract's `tracestate` member shape (precedented mechanism, unprecedented payload). **Medium** for the process-metric catalogue: names and requirements are well-precedented (doc 2 §8, Cursor, Codex metric names, Harness-Bench families), but grounding/compliance/evolvability metrics have no source-code precedent and depend on G1/G2/I5 landing. **Low-to-medium** on anything quantitative from AHE/Harness-Bench; none is load-bearing.
