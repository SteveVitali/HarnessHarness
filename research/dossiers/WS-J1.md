# WS-J1 — Harness assembly & declarative definition; validation against the IR (the C1 assembly service)

**Track:** J · **Phase:** 3 · **Tier(s) fed:** C1 (over the C0 grammar/contracts of ADR-0023/0024/0025) · **Status:** done (Phase 3 synthesis, 2026-09-10; ADR-0147, ADR-0148, ADR-0149, ADR-0150)

**Feeds spec section(s):** §7.2 #6 (laboratory: assembly), #3 (IR & compilation — pipeline seam), #5 (assembly subsystem row), #9 (build ladder Stage 3) · **Scope register items:** R-2.10.1 (with the R-2.1.4 stage note of ADR-0048 / CF-053)

## 1. Scope & boundary

Phase 1 fixed everything *below* this workstream: the Harness Definition is one HIR document whose `assembly` section is a data grammar (ADR-0023); MUST-code/MUST-data, the migration ladder, the pointer rule and layered composition with per-field merge policy and monotone `authority_cap`s (ADR-0024); the kernel operations `load / compose / resolve / validate_assembly / identity / instantiate / diff / verify_resume / space / enumerate` with the one-resolver rule feeding the compiler's `link` (ADR-0025, CF-056); `HirDiff` as the unit of edit (ADR-0017); `AgentProcess.hosted = OpaqueProcess` (ADR-0018); the identity model, sameness ladder and bundle (ADR-0036…0038, ADR-0139…0141). CF-053 (ADR-0048) then split the item: the grammar and those contracts are **C0/Stage 1 under R-2.1.4 (WS-A5)**; R-2.10.1 is the **C1 assembly *service*** — the Lab-facing capability that turns the C0 operations into the sponsor's central "meta" capability.

This dossier therefore decides: (1) the **authoring layer** above the sealed grammar — what an operator or optimizer writes (`AssemblySource`: a base reference plus layers, selectors, overrides, imports of prose) and how every authoring form *desugars* to ADR-0023/0024 constructs so that nothing new becomes sealable; (2) the **service pipeline** `assemble → plan → apply/publish` over the kernel operations and the compiler, with dry-run parity, caching by derivation key, and the invariant that no run exists without a sealed definition and no sealed definition exists except through the one resolver; (3) the **validation contract as a closed diagnostic taxonomy** — every rejection carries a stable code, a path, a source layer and a remedy class, with a complete (never fail-fast) report; (4) **typed-diff semantics for assemblies** — an `AssemblyDiff` view derived losslessly from `HirDiff`, snapshot-drift detection, a plan rendering, and the mapping onto the L0–L4 sameness ladder; (5) the assembly of **hosted participants as opaque definitions** (root `AgentProcess.hosted`) with the same authoring vocabulary and a declared degraded validation profile, without touching any native contract (T-LCD-06); (6) acceptance criteria (round-trips; invalid assemblies rejected with reasons) and the Stage-3 build slice.

It leaves to neighbours: the registry *service*, `ClassRecord`/`VariantRecord` storage, name histories and discovery (WS-J2 — this dossier fixes only what it calls); sweep scheduling, budgets per arm and `Design` (WS-J3 — this dossier fixes what `enumerate` hands over and how ad-hoc overrides are materialised); results keys and leaderboards (WS-J5); the Hosting ABI, capability probing and hosting mechanisms (WS-J6 — this dossier fixes only how a hosted definition is *authored, sealed and validated*); CLI verbs and SDK bindings (WS-K1/K4 — this dossier names the operations they expose and flags the boundary-verb gap, CF-322); plugin packaging and trust (WS-L5/H5). Nothing here names a language, runtime or package ecosystem; ADR-0050's layer split is referenced by ADR id and layer only (§6.8).

## 2. Key questions

1. (doc 3 §5, verbatim) "Design the laboratory's assembly layer: a declarative harness definition (composition model from A5 instantiated over the component registry J2) that compiles (A4) to a runnable IR-native harness; validation against the IR (A3) and against the component contracts; assembly diffs as typed IR diffs; assembly as the sponsor's central 'meta' capability; assembly of hosted-external participants (ADR-0001) as opaque definitions with ABI capabilities."
2. (brief) The harness-definition grammar (abstract) bound to the composition model; the validation contract and error taxonomy; the assembly → IR → compiled-runtime pipeline; typed-diff semantics for assemblies; acceptance criteria (round-trip; invalid assemblies rejected with reasons).
3. (added) What is *authoring* that is not *sealing*? Which conveniences (base + overrides, templates, selectors, prose imports, ad-hoc CLI overrides) must exist for the Lab to be usable, and how does each desugar to a ratified construct so the sealed grammar stays closed?
4. (added) What does "rejected with reasons" mean operationally — one taxonomy across load/compose/resolve/validate/link/lower/instantiate/resume, or a per-stage bag of errors? Which rejections are fail-closed, which are complete-report, which degrade to `n/a`?
5. (added) What is the *diff* of two assemblies for a human, an optimizer and the attribution engine, given that `HirDiff` is already the stored unit — and what is the diff between "the same authored source resolved twice" (registry drift)?
6. (added) What does the service add beyond calling the kernel operations in order — and what must it *never* add (a second resolver, a second identity, a mutable definition store)?
7. (added) How does a black-box participant get a definition at all, and which validation stages are `n/a` for it rather than "pass"?

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Authoring and sealing are different documents in every mature system, and the gap between them is where determinism is lost.** OpenHands separates the reference-bearing, secret-free `AgentProfile` from the resolved `AgentSettingsConfig` (`agent_profile.py` L1–7) and resolves through one function with a dry-run twin; goose validates a *template* and renders it with parameter values into a `Recipe` (`validate_recipe.rs` L25–32); opencode merges eight layers in a fixed order into one `Info` (`config.ts` L413–547). None of the three keys anything by the *resolved content*: OpenHands profiles carry a UUID + `revision` counter (L85–91), goose hashes the file path (`manifest.rs` L18–24), opencode keys by file. ADR-0025 already fixes content identity of the sealed form; the service-level consequence this dossier draws is that **authoring forms are sugar over layers and must never be sealable** — every convenience desugars before `resolve`, so exactly one document shape reaches `seal` (§6.1).

**F2 — Dry-run parity is achievable and the best precedent is explicit about it.** `resolve_agent_profile_dry_run` "mirrors `resolve_agent_profile`'s composition but records dangling … refs as diagnostics instead of raising" and its verdict "match[es] exactly what a real resolve produces" (`resolver.py` L325–336); Kubernetes runs admission and validation on `dryRun=All` under the same authorization (S-501). The failure mode this closes is the *editor lies*: an assembly that validates in the UI but fails at run time. ADR-0025's operations are pure, so parity is a property, not a promise: `plan` is `compose → resolve → validate_assembly` with the registry snapshot pinned and the `seal` output discarded or retained (§6.2).

**F3 — Complete reports with typed codes exist in production; fail-fast single errors are the older pattern.** opencode's compatibility lowering accumulates `Diagnostic{kind, path, message}` and, for a hard incompatibility, throws one `InvalidError` carrying an `issues[]` list with per-path messages (`v2-compat.ts` L10–18, L100–109); goose reports both missing and unnecessary parameter definitions in one message (`validate_recipe.rs` L156–181); OpenHands' diagnostics object lists every dangling ref and every unset secret channel (L64–100). What no audited system has is a *closed* code list shared across load, resolve, validate, compile and resume — each stage invents its own strings. The failure mode is un-testable rejection: a Lab that enumerates hundreds of points cannot assert "this point was rejected for reason R at path P" without stable codes (§6.3).

**F4 — Layer provenance and conflict detection are first-class server state in the strongest infrastructure precedent.** Kubernetes `managedFields` records the field manager per path; an apply that touches a field owned by another manager is a *conflict*, and ownership transfer requires an explicit `force` (S-500). opencode keeps the winning source only for plugins (`plugin_origins`, L112–116) and otherwise deep-merges with array concatenation for `instructions` (L41–50); OpenHands' plugin loader documents three different merge rules for three kinds (skills last-wins by name, MCP by key, hooks concatenate — `loader.py` L31–35). ADR-0024 (5)–(6) already requires per-field merge policy and `layers[]` provenance; this dossier adds the *conflict* concept the Lab needs: two layers of equal precedence setting one path is `LayerConflict`, never silent last-wins, mirroring `NameCollision` in ADR-0064 (§6.3, code C-COMP-3).

**F5 — Selectors that can dangle are handled by three different disciplines, and each is right in its own regime.** OpenHands uses an allow-list for MCP servers because the catalog is complete and persisted, and a deny-list for skills because their catalog "is discovered from many incomplete, drifting sources" (`agent_profile.py` L97–115, L160–171); OpenHands pins plugin refs to a commit SHA for resume (`plugin/types.py` L119–150); goose refuses a template that names an undeclared parameter (L156–181). The service consequence: an authored source may carry selectors, deny-lists and defaults; `resolve` pins them under one `registry_snapshot_id` (ADR-0036); and a *later* resolution of the same source is a first-class, typed event — **snapshot drift** — reported as an `AssemblyDiff` whose ops are all `Rebind`, never applied silently to a pinned arm (§6.4). Terraform's `-refresh-only` plan is the same shape for infrastructure (S-499).

**F6 — Typed change plans are how operators trust declarative systems.** Terraform's plan reports each resource with one of four action classes and distinguishes "no changes" (exit 0) from "changes present" (exit 2) from "error" (exit 1) (S-499). `HirDiff` (ADR-0017) is finer than an operator or an optimizer wants to read at the assembly level; a derived projection into `slot_rebind / slot_toggle / param_change / entity_add / entity_remove / cap_change / profile_constraint_change / surface_only / provenance_only` with the ADR-0017 classification carried through is lossless (every `DiffOp` lands in exactly one bucket) and is what `plan` renders (§6.4). This is a *view* of `HirDiff`, never a second diff object — ADR-0025 decision 1 (`diff`) is untouched.

**F7 — Silent correction is the recurring anti-pattern and the precedents themselves flag it.** goose's `ensure_analyze_for_developer` appends a `platform` extension to a recipe that names the builtin `developer` extension (`mod.rs` L216–245) — a defaulting that adds a slot the author did not write; OpenHands' union uses `extra="forbid"` precisely to refuse "silently dropping the foreign field into a mongrel profile" (L67–76); Kubernetes conventions say validation errors, never silent correction (S-186). Consequence: the service's `plan` output lists every *defaulted* path separately from every *authored* path (Kubernetes dry-run returns generated values), so an operator can see what the kernel filled in, and no slot is ever added by defaulting — a required slot without a binding is `SlotUnbound`, an error (§6.3).

**F8 — A hosted participant's definition is already a data document in the meta-harness precedent.** Omnigent runs Claude Code, Codex, Cursor, Pi and others from one YAML whose `executor{harness, model, auth}` names the black box and whose `params` are "typed user parameters" (S-118 L37–62); OpenHands' `ACPAgentProfile` has "no `llm_profile_ref` and no embedded credential" and no skill selection because "ACP agents own their tooling and prompt construction" (L212–227). Both confirm ADR-0018/0023 (6): a hosted definition is the same document kind with root `AgentProcess.hosted`, no `slots`, and `params` at configuration/product granularity. Omnigent's only validation advice is "run the YAML" (L475–487) — the gap the degraded validation profile of §6.5 fills without adding IR fields (T-LCD-06).

**F9 — Modular search spaces need uniform slot interfaces and a fixed *contract*, not a fixed *set* of slots.** AgentSquare's four modules with uniform interfaces are what make "module recombination" a search operator (S-024); its module *set* is closed, which is exactly the LCD signature ADR-0023 option 2 rejected. The service inherits the right half — recombination is `enumerate` over `slot_choices` per registered class (ADR-0025) — and its surrogate predictor is a WS-I5/J3 concern, not an assembly one.

## 5. Disconfirming evidence & negative results

**Against a separate C1 "assembly service" at all.** ADR-0025 already specifies every operation, and ADR-0050 D2(iii) says the lab "composes by calling the kernel's `compose → resolve → validate_assembly → seal`". A service layer could become a second implementation that drifts (the exact failure CF-056 closed). *Why this does not overturn:* the service is defined here as an **orchestration with no semantics of its own** — it may only sequence, cache, persist and render the kernel's outputs (§6.2 invariant S-3: every `SealedDefinition`, `ValidationReport` and `HirDiff` the service returns is byte-identical to a kernel call with the same inputs; a conformance test re-runs the kernel and compares hashes). What C1 adds is the Lab-facing surface (plan/apply/publish, batch validation, drift reports, the diagnostic taxonomy) that C0 deliberately does not have.

**Against a closed diagnostic code list.** Codes proliferate; a closed list forces a dialect bump for every new check and invites a catch-all `Other`. *Why this does not overturn:* the list is closed *per dialect* exactly as HIR kernel sums are (ADR-0015 decision 1 — growth by dialect bump, never `ext`), classes are few and stable (§6.3, twelve), and the rule "no catch-all; an uncoded rejection is itself a defect (`C-INT-1`)" makes the gap visible rather than hidden. The cost is real (every new upstream failure mode registers a code); it is the price of AC-J1-3 (one fixture per code).

**Against snapshot drift as a typed diff.** Drift may be noise (a variant patch release) and reporting every `Rebind` could bury operators. *Why this does not overturn:* the report is classified through ADR-0037's sameness ladder — drift to an L1 successor (surface-only) is `info`; L2 is `warning`; L3 (authority widening / budget loosening) is `error` and never adopted without human origin. The Lab keeps pins regardless (a `Design` is immutable once the first run opens, ADR-0045); drift affects only *new* arms. The residual cost is registry churn, which J2 owns.

**Against materialising every ad-hoc override as an `experiment` layer (OQ-076).** Single-run CLI overrides are ephemeral; recording each as a layer bloats provenance. *Why this does not overturn:* the layer is content-addressed (`id = H(canonical(overrides))`), so identical overrides are one record; ADR-0024 (5) and ADR-0025 decision 1 (`identity` excludes `layers[]`) mean it never forks `configuration_id`; and without it attribution cannot name the override (WS-I7). The recommendation is therefore *always materialise* — the alternative (a run whose sealed definition differs from every registry record with no provenance of why) is exactly the "who set it" gap the WS-A5 audit found in every system.

**Against a degraded validation profile for hosted definitions.** One could argue hosted participants need no validation — J6 probes them. *Why this does not overturn:* a hosted definition still carries a `Budget`, a `Permission`, `supplies{}` references, a `capability_declaration` and `params`, all of which can dangle, widen or exceed a cap; ADR-0016's kernel invariants apply to them (budget containment, delegation attenuation). What must be `n/a` — class conformance, profile compatibility, opacity — is declared `n/a{reason: class}` (ADR-0045 vocabulary), never "pass" and never 0 (T-LCD-15). No IR field is added; the profile is a *rule over which stages run* (T-LCD-06).

**Against the AssemblyDiff view.** A second diff representation invites divergence from `HirDiff`. *Why this does not overturn:* it is defined as a total, injective bucketing of `DiffOp`s — every op lands in exactly one bucket and the bucket carries the op — and it is never stored (AC-J1-6 checks `flatten(project(d)) = d.ops`). It is the same relation ADR-0042 uses between spans and ledger events: a projection, never a store.

**Negative results from the audit.** No audited system has dry-run *and* content identity *and* layer provenance together (OpenHands has the first, none has the second, Codex has the third in memory only); no audited system emits a stable, cross-stage diagnostic code (every one uses message strings — opencode's `kind` triple is the closest); no audited system detects registry drift for a persisted configuration as a typed change (OpenHands pins SHAs and stops there; opencode re-merges on every load). These are the gaps the service fills and the `novel`-as-integration parts of §6.

## 6. Recommendation for the spec

### 6.1 The authoring grammar (abstract) and its desugaring — Spec §6.1

The **sealed** grammar is ADR-0023's `Assembly{dialect, profile_binding, slots, parameters, values, entities, constraints, layers?, ext}` and is not changed. The service introduces one **authoring** document kind above it, `AssemblySource`, whose every production desugars to a ratified construct *before* `resolve`, so that no authoring form is ever sealable:

```
AssemblySource
  dialect        : "hir/1"
  root_kind      : native | hosted                         # selects AgentProcess.native | AgentProcess.hosted at the root
  base?          : DefinitionRef                            # a sealed definition (by version_id, semantic_id, or name selector)
  layers         : [ Layer ]                                # ADR-0024 (5): {fragment, provenance: LayerProvenance}
  overrides?     : [ Override ]                             # ADR-0025 Hydra-class grammar; sugar for one `experiment` layer
  imports?       : [ Import ]                               # prose/skill/procedure files → typed entities with origin = import
  ext            : ExtensionSlots

Layer.fragment  : partial Assembly (any subset of the sealed fields; selectors and $param refs allowed)
Import          : { path_or_ref, as ∈ {ContextItem, Procedure(skill), Text}, frontmatter_schema? }
Override        : path=v | +path=v | ++path=v | ~path | path=v1,v2 | class_id=variant_id   (ADR-0025 decision 1)
```

Desugaring rules (deterministic, order-defined, all C1/Stage 3):
- **D1 `base`.** A `base` is loaded as the lowest-precedence layer with `LayerProvenance{source_kind = packaged-default, id = base.version_id}` — a sealed definition is a complete fragment. The precedence ordering of ADR-0024 (5) is unchanged: `packaged-default < organisation < user < project < experiment < session`.
- **D2 `overrides`.** The override list becomes exactly one layer `{fragment = apply_overrides(∅, overrides), provenance{source_kind = experiment, id = H(idp ∥ "override-layer" ∥ canonical(overrides)), precedence = experiment}}`. This is the recommended answer to OQ-076: **always materialised, content-addressed, so identical ad-hoc overrides from CLI/SDK/sweep are one record** and attribution can name them (WS-I7). `class_id=variant_id` is a group override on `slots`; `~slots.<class_id>` is refused for a `cardinality = exactly-one` class (`C-CLASS-2`), use `enabled=false`.
- **D3 `imports`.** A prose file with frontmatter becomes a `ContextItem` whose body is a `Text{authority = external, provenance.origin = import}` leaf and whose frontmatter is validated against `frontmatter_schema` into typed fields (opencode `config/agent.ts` L11–31; ADR-0023 (3)); a skill tree becomes a `Procedure` through ADR-0086's lifting with its loss report; an import never carries authority above `external` (ADR-0033) and never names an executable except by the pointer rule (ADR-0024 (4)).
- **D4 selectors.** `version_selector`, deny-lists (`~slots.<class>.…`) and `head` are legal only in layers; `resolve` pins them (ADR-0025). A deny-list over a drifting catalog is *not* an error when a denied name is absent (OpenHands rule) — it is an `info` diagnostic `C-REF-5 DenyListNoop`.
- **D5 `root_kind = hosted`.** The fragment's root is an `OpaqueProcess` (ADR-0018); `slots` is refused (`C-CLASS-6 SlotsOnHosted`, error); `params` are declared in the same `ParameterSpec` grammar with `affects` restricted to `configuration`/`product` coordinates (ADR-0023 (6)); `executor`-style fields of the Omnigent shape map onto `participant_ref`, `hosting_mechanism`, `model_binding` (ADR-0013 descriptor). See §6.5.

Invariant A-1: `desugar(source)` is pure and total; its output is a `[Layer]` list that `compose` (ADR-0025) consumes unchanged. Invariant A-2: `desugar` introduces no construct absent from the sealed grammar — a fixture test enumerates every production and checks the output validates against the `hir/1` schema alone. Invariant A-3: two sources with equal desugared layers compose identically (`compose` is deterministic, ADR-0025).

### 6.2 The assembly service pipeline (assembly → IR → compiled runtime) — Spec §6.1/§6.2

The service is a **thin orchestrator** over kernel operations. Language-neutral contract (every operation pure over declared inputs, runnable out-of-process over the canonical encoding — T-LCD-12; the service holds no state that is not a registry record or a cache keyed by content):

- `assemble(source: AssemblySource, registry_snapshot: registry_snapshot_id | "head", mode ∈ {plan, seal}) → AssemblyResult{status ∈ {ok, error}, sealed?: SealedDefinition, identity?: {semantic_id, version_id}, report: ValidationReport, plan: AssemblyPlan, snapshot: registry_snapshot_id, derivation_key}` — sequence: `desugar` → `compose(layers, merge_policy)` → `resolve(assembly, registry_view(snapshot), environment)` → `validate_assembly(sealed, class_catalog, profiles?)` → (`mode = seal` only) retain the sealed document. `derivation_key = H(idp ∥ "assemble" ∥ canonical(desugared layers ∥ snapshot ∥ class_catalog.version ∥ assembler.version))` — cache key (ADR-0019 decision 4 shape). **Invariant S-1 (dry-run parity):** `assemble(s, snap, plan)` and `assemble(s, snap, seal)` yield identical `report`, `plan`, `identity` and `snapshot`; only the retained document differs (OpenHands dry-run rule; Kubernetes `dryRun=All`). **Invariant S-2 (one resolver):** the service calls the kernel's `resolve`; it never pins a reference itself (CF-056). **Invariant S-3 (no semantics):** every output object equals the corresponding kernel output byte-for-byte on the same inputs (conformance test). **Invariant S-4 (closed and secret-free):** the sealed output contains no environment lookups and no secret values, only channel names (ADR-0025, ADR-0057). Failure: an `error` status returns the complete `report` (never fail-fast) and no `sealed`.
- `plan(source | sealed_a, sealed_b | source, snapshot') → AssemblyPlan{diff: AssemblyDiff, defaulted_paths[], authored_paths[], layer_map: path → LayerProvenance, drift?: AssemblyDiff, exit ∈ {no_changes, changes, error}, sameness: L0..L4}` — the Terraform-plan shape (S-499): for a source it is `assemble(…, plan)` plus a diff against `base` (or against the current head of the named lineage); for two sealed definitions it is `diff` (ADR-0025 → `HirDiff`) projected to `AssemblyDiff` (§6.4); `drift` is present when re-resolving a source under a newer snapshot changes any pin (§6.4). `defaulted_paths` lists every value the kernel filled from `ParameterSpec.default` or `ClassRecord.base_param_schema` defaults (Kubernetes dry-run "generated values"); defaulting never adds a slot (F7).
- `apply(source, snapshot, publish: PublishSpec?) → {sealed, identity, report, published?: NameHistoryEntry}` — `assemble(…, seal)` followed, when `publish` is given, by the registry's `publish(namespace, name, version_id, label?, supersedes?, provenance)` (ADR-0037 operation; WS-J2 service). **Invariant S-5:** `apply` refuses when `plan.exit = error`; **S-6:** a publish whose `HirDiff` vs `supersedes` classifies `authority_delta = widening` or `budget_delta = loosening` requires `provenance.origin = human` with attestation (ADR-0037 S-rule; ADR-0017) — the service forwards the classification, it does not decide; **S-7:** the sealed definition, its `ValidationReport`, `registry_snapshot_id` and `layers[]` are stored together as registry records (ADR-0025 consequences; ADR-0139 definition member).
- `validate_batch(points: [SealedDefinition | AssemblySource], snapshot) → [ValidationReport]` — the Lab's pre-spend gate for `enumerate` output (ADR-0025: every point validates before budget is spent; T-LCD-14 placeholders untouched). Deterministic; reports are independent per point; identical points (by `derivation_key`) are validated once.
- `explain(sealed, path | node_id) → {value, layer: LayerProvenance, defaulted: bool, diagnostics[]}` — the "who set it" query over `layers[]` (Kubernetes `managedFields`; Codex `requirement_source`).
- `instantiate` and `verify_resume` are kernel operations (ADR-0025) invoked by the runtime, not by the service; the service exposes `compile(sealed, profile_chain, targets) → CompiledBundle` only as a pass-through to the compiler's `accept → link → … → seal` (ADR-0019) so that the Lab can obtain `lcd_report` and `opacity_report` at plan time (`C-LCD-*` diagnostics).

**Pipeline (the "meta" invariant, Spec §6 lead paragraph).** `AssemblySource ─desugar→ [Layer] ─compose→ Assembly ─resolve→ SealedDefinition (HIR document; ids) ─validate_assembly→ ValidationReport ─[publish]→ registry record with name history ─compile→ CompiledBundle ─instantiate→ HarnessInstance ─run→ ledger`. Two invariants make assembly the sponsor's central capability rather than one feature among many: **M-1** no run manifest references a definition that is not a sealed registry record produced by this pipeline (`configuration_version_id` keys on its `version_id`, ADR-0036); **M-2** every Lab operation that changes a harness — sweep point, ablation, evolution candidate, promotion on the ladder, hosted-participant re-declaration — is expressed as a `HirDiff` between sealed definitions, applied through `apply(base, diff)` and re-validated, never as a mutation of an authored file. The sealed definition is thereby the sole exchange object between assembly (J1), registry (J2), experiments (J3), results (J5), evolution (I5/I7) and surfaces (K1/K4), across the ADR-0050 boundary as data (D2(iii)).

**Placement across the ADR-0050 layers (by ADR id and layer only).** `desugar/compose/resolve/validate_assembly/seal/identity/diff` execute in the **kernel / reference-runtime layer** (ADR-0050 D1 row 1: "assembler/resolver (ADR-0023…0025)"); the service's orchestration, caching, batch validation, plan rendering and registry publication live in the **laboratory layer** (D1 row 3) and reach the kernel over the D2 boundary as HIR documents, `HirDiff`s and sealed definitions "as data" (D2(iii)). The §6.5 verb set of that boundary does not yet name assembly operations; this is CF-322 for WS-K4/L5 (they must add `assemble/plan/validate/diff/identity` verbs or equivalent, generated from the kernel's schema source per D3).

### 6.3 Validation contract and the diagnostic taxonomy — Spec §6.1 (and §5 "failure modes")

`validate_assembly` (ADR-0025) returns `ValidationReport{status, diagnostics[], derived}`; this dossier fixes the **diagnostic record** and the **closed code list** every stage of the pipeline uses, so that "rejected with reasons" is testable:

```
AssemblyDiagnostic
  code          : DiagnosticCode                       # closed per dialect (below); no catch-all
  class         : {syntax, dialect, reference, class_conformance, parameter_space, constraint,
                   kernel_invariant, authority, budget, profile_compat, lcd, locality, trust, resume, internal}
  severity      : {error, warning, info}               # error ⇒ status = error; warnings/info never block
  path          : JSON-pointer into the (composed | sealed) document
  source_layer? : LayerProvenance                      # when the offending value came from a layer
  subject       : {node_id?, slot?: class_id, ref?: VersionedRef | selector, param?: param_id}
  stage         : {desugar, compose, resolve, validate:1..7, link, lower, instantiate, resume}
  detail        : Text{owner = kernel}                 # human message; never the identity of the diagnostic
  remedy        : {edit_path, choose_variant, pin_version, narrow_cap, add_debt_record, add_param,
                   remove_param, declare_capability, human_attestation, none}
  owner_adr     : ADR id that defines the rule
```

**Severity rule.** `error` = the document cannot be sealed, linked, instantiated or resumed; `warning` = sealable but the Lab should know (expired debt record, drift to an L2 successor, deprecated variant, defaulted budget-relevant parameter); `info` = provenance facts (deny-list no-op, defaulted non-budget path, surface-only drift). A report is **complete**: every stage runs and every diagnostic is returned (ADR-0025 decision 1); `status = error ⇔ ∃ severity = error`.

### 6.4 Typed-diff semantics for assemblies — Spec §6.1 (edit unit) and §3

The stored unit is `HirDiff` (ADR-0017), taken only over sealed definitions (ADR-0025). The service adds a **derived projection** and three rules.

```
AssemblyDiff = project(HirDiff)                        # total, injective bucketing of DiffOp; never stored
  slot_rebind        [{class_id, index?, old: ComponentVariantRef, new}]         ← Rebind on assembly.slots.*.variant
  slot_toggle        [{class_id, index?, enabled: old → new}]                     ← ReplaceField on …enabled
  slot_param_change  [{class_id, name, old, new}]                                 ← ReplaceField on …params.*
  value_change       [{param_id, old, new}]                                        ← ReplaceField on assembly.values.*
  space_change       [{param_id, kind ∈ {added, removed, domain, default}}]        ← Add/Remove/ReplaceField on assembly.parameters.*
  entity_add / entity_remove / entity_change [{node_id, kind, semantic: bool}]     ← AddNode/RemoveNode/ReplaceField/ReplaceLeaf on entities
  edge_change        [{edge kind, from, to}]                                       ← AddEdge/RemoveEdge
  cap_change         [{path, direction ∈ {narrowing, widening}, source_layer}]     ← ReplaceField on constraints[authority_cap] (drives authority_delta)
  profile_constraint_change [{old, new}]                                           ← ReplaceField on assembly.profile_binding
  surface_only       [SurfaceEdit]                                                 ← profile-owned fields (T-LCD-10)
  ext_only           [ExtEdit]                                                     ← ext keys
  provenance_only    [DiffOp]                                                      ← provenance/layers[] fields
  classification     : HirDiff.classification (verbatim)   # {semantic_ops, surface_ops, provenance_only_ops, ext_ops, authority_delta, budget_delta, validity_delta, touches_conditioned_rules}
  sameness           : L0 | L1 | L2 | L3 | L4                # ADR-0037 ladder computed from classification + lineage
  rendering          : Terraform-class lines  `+` add · `-` remove · `~` change · `-/+` rebind · `≈` surface-only · `·` provenance-only
```

Rules: **T-1 (lossless view)** `flatten(project(d)) = d.ops` as a multiset; `apply` remains `HirDiff.apply` (ADR-0017); `invert(project(d)) = project(invert(d))`. **T-2 (sealed only)** `plan` diffs authored sources only by desugaring both to sealed forms under one snapshot; textual diffs of authored files are never produced by the service (they are the editor's business). **T-3 (snapshot drift)** `drift(source, snap_old, snap_new) = project(diff(resolve(source, snap_old), resolve(source, snap_new)))`; by construction its ops are `Rebind`/`ReplaceLeaf` on pinned references only; it is reported as `C-REF-6` with severity by sameness level (L1 info, L2 warning, L3 error) and is **never applied to an arm whose `Design` has opened** (ADR-0045 immutability); adopting drift for *new* arms is an explicit `apply` with `provenance.origin = human | evolution` under ADR-0017's widening rule. This is the definition-level analogue of ADR-0095's catalog epochs (`freeze | adopt | ask`), with `freeze` as the only Lab default. **T-4 (hosted)** for `AgentProcess.hosted` the projection admits only `value_change`, `space_change`, `entity_change` on `declared_capabilities`/`supplies`/`budget`/`permissions`, and `participant_version_change` (a *claim*, ADR-0037 rule (c)); `sameness ∈ {L0, L4}` only; a `declared_capabilities` change that flips a coordinate `supported → unknown|unsupported` is `warning` (it removes admissible factors, ADR-0013 (4)). **T-5 (ablation)** `enabled=false` on one binding is exactly one `slot_toggle` (ADR-0025 AC-6); WS-A3 `ablate(sealed, node_id)` is one `entity_remove` with `derived-from{hypothesis: "ablation"}`; both are L2 successors in an experiment-scoped namespace (ADR-0037 (b)).

### 6.5 Hosted participants as opaque definitions — Spec §6.5 (with WS-J6)

A hosted participant's definition is a HIR document whose root is `AgentProcess.hosted = OpaqueProcess{participant_ref, declared_capabilities, observability_levels, version_identity, hosting_mechanism, supplies{context, tools, procedures}, budget, permissions}` (ADR-0018) plus an `assembly` section restricted to `{dialect, parameters, values, entities, constraints, layers?, ext}` — **no `slots`, no `profile_binding`** (profile is meaningless for a black box; `model_binding` lives on the participant descriptor, ADR-0013). Authoring: the Omnigent shape (`executor{harness, model, auth}`, `params`, `tools`, `policies`) desugars as `executor.harness → participant_ref` (a registry name selector for a `ParticipantRecord`, WS-J6/J2), `executor.model → model_binding` (descriptor), `auth → SecretRef` channel names only (ADR-0057), `tools → supplies.tools` (references to `ToolCapability` versions the instrument *supplies through the ABI*), `policies → HarnessRule`/`Permission` entities enforced **at the boundary by the reference runtime** (ADR-0018 invariant), `params → ParameterSpec` with `affects ⊆ {configuration, product}` coordinates and `sweepable` only over coordinates whose capability-vector entry is `SUPPORTED` (ADR-0013 (4); enforced at `enumerate`, `InadmissibleFactor`).

Degraded validation profile (a *rule over stages*, no IR change — T-LCD-06): stage 1 schema **runs**; stage 2 class conformance **`n/a{class}`** except `C-CLASS-6`; stage 3 parameter space **runs** (same bidirectional rule); stage 4 constraints **run** (`authority_cap`s bound the boundary-enforced `Budget`/`Permission`); stage 5 kernel invariants **run** for the entities present (budget containment, delegation attenuation, provenance on every `Text` in `supplies.context`, `Permission.issuer ≠ model_claim`); stage 6 profile compatibility **`n/a{class}`**; stage 7 LCD: `hosting_edges` **runs** (and must be empty — a hosted definition *references* the ABI's descriptor type only through the kernel-owned `OpaqueProcess`, never the reverse), opacity **`n/a{class}`**, identity stability **runs**. `resolve` pins `participant_ref` to a `ParticipantRecord.version_id` and records `version_identity = H(declaration ∥ participant_version)` as a claim (ADR-0018/0037). `instantiate` binds no component; it hands the sealed definition to the hosting mechanism's driver — an **instrument** component (`charged_to = instrument`, ADR-0039) — and the run manifest carries the ADR-0013 participant descriptor; whether a `lifecycle.component.bound{class_id = hosting_adapter}` row is emitted for the driver is OQ-348 for WS-J6/B1 (recommended: yes, so the instance graph is total across classes without adding IR fields).

### 6.6 Data-model sketch

`AssemblySource`, `Layer`, `Import`, `Override` (§6.1) · `AssemblyResult{status, sealed?, identity?, report, plan, snapshot, derivation_key}` · `AssemblyPlan{diff, defaulted_paths[], authored_paths[], layer_map, drift?, exit, sameness}` · `AssemblyDiagnostic` and `DiagnosticCode` (§6.3) · `AssemblyDiff` (§6.4; derived, never stored) · `PublishSpec{namespace, name, label?, supersedes?, provenance}` (ADR-0037) · registry records stored per sealed definition: `{sealed: version_id + semantic_id, validation_report: ContentAddress, registry_snapshot_id, layers[]: ContentAddress, derivation_key}` (ADR-0025 consequences; ADR-0139 `definition` member) · `ParticipantRecord` (WS-J6/J2 shape; this dossier requires only `{participant_ref, version_id, declared_capabilities, hosting_mechanism}`) · events: none new for runs; a registry-side `lifecycle.definition.published{version_id, semantic_id, name_entry}` is OQ-349 for WS-B1/J2.

### 6.7 Acceptance-criteria sketch (Spec §6 acceptance rows; each names its T-LCD test)

- **AC-J1-1 (round-trip, encoding).** For a corpus of ≥100 authored sources (native and hosted; every §6.1 production covered): `load(encode(compose(desugar(s)))) = compose(desugar(s))`; `encode(decode(sealed)) = sealed` byte-for-byte in canonical form; the registry record read back re-hashes to its `version_id` (ADR-0036 N-invariants). T-LCD-10/-12.
- **AC-J1-2 (round-trip, identity).** Two authoring paths with identical resolved content (base+overrides vs a single fragment; different layer orders that compose equally) yield one `semantic_id` and one `configuration_id` coordinate; `layers[]` differ and are recorded (ADR-0025 AC-3). T-LCD-10.
- **AC-J1-3 (rejected with reasons).** An invalid-fixture corpus with **exactly one fixture per code** in §6.3 (native and, where applicable, hosted): each is rejected with that code, a resolving `path`, and — where a layer set the value — the correct `source_layer`; the report contains every diagnostic the fixture plants (complete, not first-error); no fixture yields `C-INT-1`; a fuzzed corpus of random edits to valid fixtures yields no `C-INT-1`. T-LCD-02/-05/-06/-08/-10/-12/-14 via the mapped codes.
- **AC-J1-4 (defaulting never corrects).** A fixture with an unbound `exactly-one` slot fails `C-CLASS-2`; no plan ever lists a `slot_*` entry under `defaulted_paths`; every defaulted value appears in `defaulted_paths` with its source (goose counter-example encoded as a must-fail).
- **AC-J1-5 (dry-run parity).** For the valid and invalid corpora, `assemble(s, snap, plan)` and `assemble(s, snap, seal)` produce equal `report`, `plan`, `identity`, `snapshot`; the sealed document of `seal` mode equals the kernel's `resolve` output on the same inputs (S-1, S-3).
- **AC-J1-6 (diff view lossless).** For every pair in the corpus, `flatten(project(diff(a, b))) = diff(a, b).ops`, `apply(a, diff(a, b)) = b`, `invert` round-trips (ADR-0017 AC), a compiled-tool rename yields only `surface_only` entries and unchanged `semantic_id`, and `enabled=false` yields exactly one `slot_toggle` (ADR-0025 AC-6). T-LCD-10.
- **AC-J1-7 (snapshot drift).** Re-resolving a source under a snapshot in which one referenced variant has an L1 successor yields `C-REF-6` at `info` with a drift diff of one `slot_rebind`; with an L3 successor (widening) at `error`; an opened `Design`'s arms are unchanged in both cases; adopting drift for a new arm produces a `HirDiff` with the right `authority_delta` and is refused for `origin = evolution` when widening (ADR-0017).
- **AC-J1-8 (hosted degraded profile).** A hosted fixture with `slots` fails `C-CLASS-6`; stages 2/6/7-opacity report `n/a{class}` (never pass, never 0); a `Budget` exceeding its parent fails the kernel invariant exactly as for a native fixture; `hosting_edges = []` holds; `sweepable` over an `unknown` coordinate is refused at `enumerate`. T-LCD-06/-07/-15.
- **AC-J1-9 (materialised overrides).** Two ad-hoc override lists with equal canonical content produce one `experiment` layer id; `explain(sealed, path)` names it; `configuration_id` is unchanged by the layer's presence (identity excludes `layers[]`).
- **AC-J1-10 (out-of-process service).** The service runs in a separate process from the kernel exchanging only the ADR-0050 D2 objects; AC-J1-1…9 are unchanged. T-LCD-12.
- **AC-J1-11 (Stage-0 anchor).** The mini-SWE-agent-class reference definition (OQ-039) authored as `AssemblySource` with a `base` and one `experiment` layer assembles with zero errors, publishes, compiles under both minimal profiles (ADR-0020) and yields a `plan` with `exit = no_changes` against its own registry head.
