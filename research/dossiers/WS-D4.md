**Track:** D · **Phase:** 2 · **Tier(s) fed:** C2 (with the C0 slices fixed by ADR-0048's stage note on R-2.4.4: retrieval order and the supersession/revocation records) · **Status:** dossier-written

## 1. Scope & boundary

This workstream decides **what it means for a memory record of the HarnessHarness reference runtime to be valid, superseded, revoked, expired, in conflict, tainted, or readable — and where those facts are enforced**. It fixes (i) the memory record lifecycle as a *derived* state over immutable versions (never a mutable flag), (ii) the invalidation contract every memory version must carry (dependency stamps, cacheability, validators, expiry), (iii) conflict-set handling and the authority rule for supersession, (iv) downstream inheritance of invalidation across memories derived from a revoked memory (OQ-020, retrieval half), (v) the three enforcement points at which a stale or revoked version is withheld (retrieval, context admission, resolution) so that revocation is enforced by the control layer and never entrusted to the model, and (vi) the separate measurement of memory *validity* (model-free) and memory *compliance* (model-conditioned) with the veto invariants that make "revoked memory never surfaces" and "stale version never acted on" testable.

It explicitly leaves to neighbours: **WS-D3** — the memory hierarchy (working/artifact/episodic/procedural/durable), the `retrieve` operation itself, relevance ranking, embeddings and storage layout (D4 supplies the `validity()`/`lifecycle_state()` predicates and the filter semantics that `retrieve` applies in ADR-0034 P5 order); **WS-D1** — admission of retrieved memories into slots (D4 fixes what `validity_required` and the conflict policy on a slot mean); **WS-D5** — procedures/skills as procedural memory (D4's lifecycle applies to them through the same `supersedes`/`RevocationRecord` records; their typed pre/postconditions are D5's); **WS-L4** — identity, immutability I1–I5, supersession S1–S8, `RevocationRecord`, `StaleIndex` for *sealed definitions and bundles* (ADR-0036/0037 — adopted verbatim; D4 extends the stale-by-dependency idea to memory-to-memory derivation); **WS-L3/H1/H2** — the single authority/label scheme (ADR-0033/0034/0035 — cited, never re-decided), the reference monitor, the taint gate Π and readers enforcement at C2; **WS-H6** — retention floors and audit-grade classification of memory events; **WS-B1** — the `context.memory.*` event envelope (D4 requests payload extensions, CF-WS-D4-01); **WS-I2/G1/G3** — metric declarations and detectors (D4 declares the memory metrics and names deterministic detectors where they exist); **WS-H5** — extension revocation (same records, its own lifecycle). Nothing here names a language, runtime or framework; precedent paths are evidence, not dependencies (ADR-0050 §8).

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Representation is not enforcement: every audited system that *records* invalidation still *returns* invalidated memory unless the filter is in the read contract.** Graphiti stores four timestamps and computes `invalid_at`/`expired_at` on contradiction (`edge_operations.py` L565–571), yet `search()` takes `search_filter: SearchFilters | None = None` and `SearchFilters.expired_at` defaults to `None` (`search_filters.py` L65; `graphiti.py` L1592) — no default query excludes expired edges; S-106 observed exactly this (81/81 exposure). mem0's delete path removes the vector but the replacement relation lives only in the `history` table, which the retrieval path never reads (`storage.py` L227–235 is consulted only by `Memory.history()`). goose asks the model to forget ("please remove it from the system instructions", `mod.rs` L152). S-106's defense ladder quantifies the gap: prompt hardening leaves 37.2 % unsafe actions, an output filter 18.1 %, a store-level filter 0.0 %. **Implication:** the validity filter is part of the *contract* of `retrieve` and `admit` (ADR-0034 P5, D1 I-ORDER), evaluated by the kernel over records, and the model is never the enforcement point. This dossier adds nothing to that rule; it fixes the *predicates* the filter evaluates and the *records* that make them decidable.

**F2 — Validity is decidable deterministically exactly where a dependency stamp exists, and the stamp granularity decides the cost.** S-077's contract is a set of `(dependency, version)` pairs plus a cacheability hint; "a cached suggestion is valid if every table it depends on still has the version the client recorded", yielding "zero contract failures" and identical validity verdicts across seven models. The same paper shows granularity is not a detail: table-level stamps "destroy co-located entries" and drop post-drift first-try success to 0 % on five of seven models, while row-level stamps keep eviction precision at 1.00. RFC 9111 has the same structure at Internet scale: freshness lifetime, validators (`ETag`), `must-revalidate` ("MUST NOT reuse … until it has been successfully validated"), and mandatory invalidation of the target after an unsafe method. **Implication:** the invalidation contract is a list of *fine-grained dependency stamps* drawn from a closed set of stamp sources the runtime already versions (registry name histories — ADR-0037; environment records and tool capability versions — ADR-0036/E1; model snapshot ids — C1), plus an optional validator and an optional freshness lifetime; `unknown` is the honest verdict when none exists (ADR-0014 decision 1, CF-028).

**F3 — Two clocks are needed and only one is sound for ordering.** Jensen & Snodgrass separate valid time (when a fact holds) from transaction time (when it was recorded). Graphiti reads *valid time* out of text with an LLM (`_extract_edge_timestamps`, L580–620) and then orders contradictions by it — which S-106 shows is unsound when the stamp is missing ("broke ties by result order"). The run ledger's `seq` (ADR-0027) is a sound transaction clock; valid time is a *claim* carried in the memory body with the authority of its writer. **Implication:** supersession is ordered by transaction time and authority (ADR-0034 P5: `authority(new) ≥ authority(old)`), never by a model-extracted valid-time stamp; valid-time stamps are `ValidityState` fields the check may consult (expiry) but never the basis for "newer wins".

**F4 — Downstream inheritance is a justification problem, and the write-back path is where it fails in practice.** S-106's third limitation: an agent that read a revoked fact and journaled a conclusion defeats every store-level filter, because the journal entry is a new record with no revocation status. Doyle's TMS is the classical answer — a belief is IN iff at least one justification is valid; retract the justification and dependency-directed maintenance retracts the dependants. ADR-0037 S4 already applies this to sealed definitions and bundles (`StaleIndex`, `depends_on_revoked` annotated never hidden). ADR-0034 P1 already requires `derived_from` on every derivation and WS-B1 records which items were delivered in each model call (`context.assembled.items[]`). **Implication:** a memory written in model call `c` carries, as kernel-stamped justifications, the memory versions delivered in `c` (deterministic, no model cooperation) plus any declared inputs; revoking a justification makes the dependant `stale_by_dependency` in a derived index that retrieval withholds by default. This is `no-precedent / novel` in the audited corpus (mem0's `linked_memory_ids` are similarity links, not justifications; AIOS's `evolution_history` is prose).

**F5 — Conflict detection has a deterministic core and a judged tail, and only the deterministic core may supersede.** S-106's guard "detects pairs of facts asserting incompatible values for the same subject" — decidable when facts carry a subject key and a value schema; mem0's `DEFAULT_UPDATE_MEMORY_PROMPT` delegates the same decision to a model ("If the retrieved facts contain information that contradicts … delete it"), which mem0 itself has since bypassed with an ADD-only extractor plus links (`ADDITIVE_EXTRACTION_PROMPT`, `linked_memory_ids`) — a production signal that model-decided deletion was too lossy to keep as the default. Under ADR-0035 a `delegate` origin never endorses and under ADR-0034 P5 supersession needs `authority(new) ≥ authority(old)`. **Implication:** deterministic contradiction (same `subject_key`, incompatible closed-schema values, `authority(new) ≥ authority(old)`, writer asserts `supersedes`) resolves as supersession; a judged contradiction (free text, model detector) may only *create a conflict set* whose members coexist annotated or are withheld per slot policy, or escalate to the principal — it can never revoke.

**F6 — TTL-as-deletion and refresh-on-read are cache semantics, not memory semantics.** langgraph's store deletes expired items "on a best-effort basis" and refreshes TTL on `get`/`search` by default (`TTLConfig.refresh_on_read`), so an item that keeps being retrieved never expires and an item that expires leaves no record. ADR-0037 I1/I3 forbid both for the reference runtime. **Implication:** expiry is a *derived state* (`validity.until < at`, or an invalidation condition true) over an immutable version; nothing is swept, and a later read of an expired version returns `invalid{expired}` with the record intact for audit. Freshness may be *extended* only by a new version (a re-validation event with its own provenance), never by reading.

**F7 — The write path is an attack surface, and relevance-first retrieval is the amplifier.** AgentPoison (>80 % ASR at <0.1 % poison rate via trigger-optimized retrieval) and MINJA (injection through ordinary queries) both rely on (i) a write path any interlocutor can reach and (ii) retrieval that ranks by similarity alone. ADR-0035's persistence-scope ceilings (`user` requires `principal` + `approval`; `project` ≥ `principal`) close (i) for scopes above `session`; ADR-0034 P5 closes (ii) by filtering authority before relevance; ADR-0033 I3 (`taint ≠ ∅ ⇒ authority ≤ external`) keeps a poisoned memory from ever commanding above `external`. **Implication:** D4 adds no new trust axis (CF-006); it adds the *scope × kind* default policy (`external`-class memories are `session`/`run`-scoped unless promoted) and makes `promotion` (ADR-0035 basis) the only path from `external`/`delegate` to `principal`/`definition`.

**F8 — Validity and compliance separate cleanly for memory, and compliance is deterministic for two memory kinds.** S-077: identical cached bytes, validity identical across models, compliance from 100 % to ≤ 11 % and a sign flip across versions of one family. For *recovery* memories (a cached fix for a failing call) `followed` is deterministic: the next proposal's canonical arguments match the suggestion (S-077's "first-try" metric); for *procedure pointer* memories `activated` is the deterministic expansion of a handle (D1 AC-D1-10). For free-text `fact`/`preference` memories, `followed` is judged (ADR-0014). **Implication:** OQ-049's memory row is answerable: `activation_observable = true` for handle-only deliveries and for kinds with a `subject_key`/suggested-call; `followed` deterministic only for `recovery` and `procedure_pointer`.

**F9 — Read authority is a filter over a reader set, precedented with safe defaults.** AIOS's `_apply_sharing_filter` applies `owner_agent`/`user_id`/`sharing_policy` after search with "missing sharing_policy → private" and "missing owner_agent → never matches any agent" (`providers/base.py` L17–116). ADR-0033's `readers` component is the same filter in lattice form, joined at C0 and enforced at C2 (WS-H2). **Implication:** P5 step (iii) is implemented over `readers` with `Public` as the identity and a *deny on missing* rule for scopes ≥ `user`.

The integrated design — derived lifecycle state over immutable versions, an invalidation contract with closed stamp sources, deterministic-core/judged-tail conflict sets with the supersession-authority rule, and justification-based inheritance of revocation across memories — is `no-precedent / novel` as a whole; each component is precedented as listed.

## 5. Disconfirming evidence & negative results

**Against requiring an invalidation contract on every memory: most memories have no dependency to stamp.** Free-text preferences and episodic reflections (MemGPT, Generative Agents, Reflexion — the field's main memory kinds) depend on nothing the runtime versions; under this dossier they are `unknown` at best, and a slot with `validity_required = {valid}` admits none of them. *Why this does not overturn:* ADR-0014 already made validity three-valued and CF-028 assigned D4 the obligation to *require* a check or interval, not to make one up. The minimum contract is an *interval* (`valid_until` or a scope-bound `invalidation_condition = scope_ended`), which every memory can carry, so such memories are `valid` until expiry and `unknown` only when the author declines even that; slots for episodic memory declare `admit_unknown_validity` (D1). The Lab measures the utility cost (AC-D4-12).

**Against justification-based inheritance (`derived_from = memories delivered in the writing call`): it over-invalidates.** A journal entry written in a call that also happened to deliver an unrelated memory becomes stale when that memory is revoked; TMS systems are known to thrash under exactly this coarseness, and Biba-style low-water marks creep. *Why this does not overturn:* the alternative — trusting the model to declare its inputs — is the write-back hole S-106 documents; the conservative rule is deterministic, auditable, and *annotated never hidden* (ADR-0037 S4 shape), so a stale dependant is still retrievable under `admit_stale_by_dependency` and its results are labelled. A deterministic narrowing (dependants only of memories sharing a `subject_key` or cited by handle expansion) is specified as a C2 option to be admitted only if the Lab shows the conservative rule costs measurable utility (OQ-WS-D4-04).

**Against refusing "newer wins": every production memory system resolves by recency and users expect it.** Graphiti "consistently prioritizes new information"; mem0's prompt updates in place; Zep and Mem0 report benchmark gains with that policy. *Why this does not overturn:* recency by *transaction* time is retained as the tie-break *within* an authority class when the writer asserts supersession; what is refused is recency by model-extracted valid time and supersession across authority classes (an `external` fact overriding a `principal` one), which is the M-CPE/X-CPE escalation in memory form. S-106 shows the recency heuristic returning the revoked fact *above* its replacement precisely because "newer" was not the replacement.

**Against deterministic subject keys: they assume structured memory; free text has no key.** *Why this does not overturn:* keys are required only for deterministic supersession; unkeyed memories fall to the judged tail (conflict sets that coexist/escalate) — a strictly weaker but still auditable outcome. Shape endorsement (ADR-0035 `validator` basis) lets a closed-schema extractor produce keyed facts at `environment` authority.

**Against never deleting: storage and privacy.** langgraph sweeps; mem0 hard-deletes; GDPR-class obligations exist. *Why this does not overturn:* ADR-0037 I3 and WS-H6's redaction/GC design (envelopes never leave; content leaves by endorsed tombstone) already resolve this — a memory's *bytes* may be redacted, its *version record and lifecycle edges* stay.

**Against the evidence base: S-077 and S-106 are single-team 2026 preprints with authored domains and nine scenarios.** *Why this does not overturn:* they are used for mechanism and failure signature only; the design rests on TMS (1979), temporal databases (1999), RFC 9111 and RFC 5280 — mature, replicated practice — and on ratified ADR-0014/0033/0034/0035/0037. No C0 slice depends on a provisional number.

**Negative results from the audit.** No audited memory system (graphiti, mem0, langgraph store, AIOS, goose, gemini-cli, codex) carries: an authority class on a memory; a dependency stamp; a justification link from a memory to the memories it was derived from; a validity filter in the default read path; or a supersession record that retrieval reads. Every one that records invalidation (graphiti, mem0 history) records it somewhere the reader does not look.

## 6. Recommendation for the spec

### 6.1 Position: lifecycle state is derived, records are immutable, enforcement is in three kernel operations

A **memory version** is a HIR `Memory` node version (ADR-0016 entity 4) with its `ProvenanceRecord` (ADR-0033) and version record; it is immutable (ADR-0037 I1). Its **lifecycle state** is never stored as a flag; it is the pure function

`lifecycle_state(v: VersionedRef<Memory>, at: Seq) → valid | superseded{by} | revoked{record} | expired{reason} | stale_by_dependency{revoked_inputs[]} | unknown`

computed from: the `supersedes` edges into `v` (ADR-0037 S1), any `RevocationRecord` naming `v`, `v.validity` and `v.contract` evaluated against the dependency stamps current at `at`, and the derived `MemoryStaleIndex` (§6.4). `validity(v, at)` (ADR-0014) is the projection `valid ↦ valid`, `superseded | revoked | expired | stale_by_dependency ↦ invalid{reason}`, `unknown ↦ unknown`, with `check_ref` naming the record or stamp that decided it. Precedence when several apply: `revoked > superseded > expired > stale_by_dependency > valid > unknown` (a revoked version is reported revoked even if also expired).

**State machine (per version; every transition is an appended record, never a mutation):**

```
written ──(contract present: stamps match, ttl not elapsed, validator passes)──▶ valid
written ──(no contract, no interval, no validator)──▶ unknown
valid | unknown ──supersede(new, v, reason=edit|migration)──▶ superseded{by=new}
valid | unknown ──revoke(v, reason, authority, replacement?) → RevocationRecord──▶ revoked
valid ──(at > validity.valid_until) | invalidation_condition true──▶ expired
valid | unknown ──(any justification j of v: lifecycle_state(j) ∈ {revoked, stale_by_dependency})──▶ stale_by_dependency
superseded | revoked ──────────────────────────────────────────── absorbing for v (the lineage continues in the successor)
expired ──revalidate(v) → new version v' with fresh contract, supersedes{reason=edit}──▶ (v superseded, v' valid)
stale_by_dependency ──(dependency replaced by a version that resolves the conflict) → new version──▶ (v superseded)
```

`expired` and `stale_by_dependency` are *recoverable only by a new version*; nothing revives `v`. Reading `v` in any state returns `v` with its state (audit/reproduce path) but **never delivers it to a model** unless the slot's validity policy admits that state.

**Enforcement points (kernel, records only, no model in the path):**

- **E1 `retrieve`** (WS-D3 operation; ADR-0034 P5): step (i) is `lifecycle_state(v, until_seq) ∈ slot.validity_policy.admitted_states` — default `{valid}`; `unknown` only with `admit_unknown_validity`; `stale_by_dependency` only with `admit_stale_by_dependency`; `superseded`/`revoked`/`expired` never in `mode = execute`. Withheld candidates are returned *to the ledger*, not to the model: `context.memory.read{…, withheld: [{version_id, state, reason}]}` (S-106's "returned separately with a reason", made an audit record).
- **E2 `admit`** (WS-D1 I-ORDER): re-evaluated at the model call's `seq` (the plan may be older than a revocation that landed between retrieval and rendering); a handle-only memory is re-checked at `expand`.
- **E3 `resolve(mode = execute)`** (ADR-0037 S3) for memories pinned by `version_id` inside a sealed definition or procedure: refuses revoked/stale heads exactly as for any versioned record.
- **E4 `write`** (D4): computes the persisted label, the scope ceiling (ADR-0035 check 6), the kernel-stamped justifications, the deterministic conflict set, and refuses `supersedes` that violate the authority rule.

A fifth point is deliberately *not* added: the reference monitor does not inspect memories at effect time — the memory that motivated a proposal already lowered the `context_label` (ADR-0034 P3), and check 4/Π handles it. Adding a memory check to `authorize` would be a second scheme (CF-006).

### 6.2 The invalidation contract (answers key questions 1, 3)

Every `Memory` version carries `contract: InvalidationContract`:

```
InvalidationContract = {
  dependencies: [DependencyStamp],          // may be empty
  cache_hint: cacheable | recompute | no_store,
  validator_ref?: Ref<Validator>,           // deterministic; a `validates` edge (ADR-0016)
  freshness?: { valid_until: Timestamp | Seq } | { max_age: Duration, from: Seq },
  invalidation_condition?: InvalidationCondition,
  revalidation: must_revalidate | stale_ok{max_stale} | never
}
DependencyStamp = { kind: DependencyKind, ref: VersionedRef | ContentAddress | NameSelector,
                    stamp: version_id | ContentAddress | registry_snapshot_id | model_snapshot_id, granularity: row | table }
DependencyKind  = registry_name | definition_version | procedure_version | tool_capability_version
                | environment_image | model_snapshot | memory_version | artifact | external_resource{validator_ref}
InvalidationCondition = dependency_changed(stamp_index) | ttl_elapsed | validator_fails(ref)
                      | superseded | scope_ended(PersistenceScope) | replacement_published(NameSelector)
```

**Semantics.** `valid` at `at` iff every `DependencyStamp` still equals the current stamp of its dependency at `at` (registry name history head — ADR-0037; environment/tool/model records — ADR-0036/C1/E1/B5) **and** `freshness` has not elapsed **and** (`validator_ref` absent or its last recorded verdict at ≤ `at` is `pass`) **and** no `invalidation_condition` holds. `unknown` iff `dependencies = []`, `freshness` absent, `validator_ref` absent and `invalidation_condition` absent — the memory declared nothing checkable. `recompute` (S-077) means the memory is *derivable from the request* and is never persisted beyond `turn` scope; `no_store` (RFC 9111) forbids persistence entirely (secrets, one-time approvals). `must_revalidate` means an elapsed `freshness` makes the memory `expired` immediately; `stale_ok{max_stale}` lets a slot admit it as `unknown` for `max_stale` (RFC 5861 shape) — only through `admit_unknown_validity`, never as `valid`. **Granularity rule (S-077 row vs table):** a stamp names the finest versioned object the memory depends on; a `table`-granularity stamp is legal but the memory kind's default policy may forbid it, and `context.memory.invalidated{reason = dependency_changed}` records which stamp fired so the Lab can measure over-invalidation. **Minimum contract:** `write` refuses a version with `dependencies = [] ∧ freshness = ∅ ∧ validator_ref = ∅ ∧ invalidation_condition = ∅` unless the writer's scope is `run`/`turn` (`MissingContract`); the definition's memory policy supplies per-kind defaults (`scope_ended(session)` for `external`/`delegate` extracts, `max_age` for `preference`). Stamps are read from kernel records, never from the memory's own text (ADR-0033 decision 6 applied to validity; T-LCD-01 "no escape hatch").

**Cross-run model conditioning (S-077's sign flip).** A memory is *valid* independently of the model; a memory whose *usefulness* is model-conditioned (a phrasing that one family follows and another refuses) is not a `Memory` with a model field — it is a `HarnessRule` conditioned on a `ProfileRef` with an assumption-debt record (T-LCD-05), or a plain memory whose compliance is simply measured per snapshot (ADR-0014 decision 4). `Memory` carries no model identity (T-LCD-01).

### 6.3 Supersession, revocation and conflict sets (answers key questions 4, 8)

**Records (adopted from ADR-0037, restated for memory).** `supersede(new, old, reason ∈ {edit, revocation, expiry, migration, fork})` is an edge on `new`; `revoke(old, reason, authority, replacement?) → RevocationRecord{kind = Memory, revokes = old, reason, validity.until = now_seq, replacement?, authority, provenance}`; both are ledger events (`context.memory.invalidated{version_id, reason, by: EventRef, replacement?}` plus the record); the old version is never touched. Revocation reasons are a closed sum modelled on RFC 5280: `{contradicted, principal_withdrawn, source_revoked, dependency_revoked, expired, migrated, poisoned, hold}`; `hold` is the CRL `certificateHold` — revocation that a later `RevocationRecord{reason = release}` may supersede with a *new* version (never by un-revoking).

**Authority rule (ADR-0034 P5, verbatim):** `supersedes(new, old)` requires `authority(new) ≥ authority(old)`, else `SupersessionAuthorityInsufficient`; `revoke` requires `authority(revoker) ≥ authority(old)` and `revoker.origin ∉ {model, evolution, participant}` for `old.authority ≥ principal` (a `delegate` may revoke only `delegate`/`external`/`unverified` memories it wrote in the same scope — its own journal). The principal revokes anything at `≤ principal`; `definition`-class memories are revoked only by `seal` of a new definition (WS-A5) or a `pin`/`promotion` reversal.

**Conflict sets.**

```
ConflictSet = { conflict_id, subject_key?: SubjectKey, members: [VersionedRef<Memory>],
                detector: deterministic{key_match} | judged{detector_ref, confidence},
                resolution: superseded{head} | coexist | withheld | escalated{principal_ref}, resolved_by?: EventRef }
SubjectKey  = { schema_ref: Ref<closed schema in the sealed definition>, key: canonical bytes }
```

Detection at `write`: **deterministic** when the new version and an existing valid version share `subject_key` and their closed-schema values differ (`environment`-class keyed facts, recovery suggestions keyed by `(capability semantic_id, error class)`, preferences keyed by a declared enum); **judged** when a registered `Validator{kind: judge}` (`charged_to = instrument`, ADR-0047) flags free-text incompatibility. Resolution: (a) deterministic + writer asserts `supersedes` + authority rule holds ⇒ `superseded{head = new}` and the old member is `superseded` (F5); (b) deterministic, authority rule fails ⇒ `write` succeeds with `resolution = coexist` and a `conflict_set_ref`, plus `escalated` if the definition's policy says so — the lower-authority write never revokes; (c) judged ⇒ `coexist` always (a judge is `delegate`-class evidence and never endorses — ADR-0035), with `escalated` optional; (d) equal authority, no `supersedes` asserted (independent writes) ⇒ `coexist`; **no tie-break by recency or result order** (S-106). Retrieval of an unresolved set follows the slot's `conflict_policy ∈ {deliver_all_annotated (default), withhold_all, deliver_head_if_resolved_else_withhold}`; a delivered member carries `conflict_set_ref` so the profile may render the annotation (a surface, T-LCD-10). A `coexist` set is *resolved* only by a later supersession that satisfies the authority rule or by a `promotion`/`approval`-basis endorsement naming the head.

### 6.4 Downstream inheritance of invalidation — memory justifications (OQ-020, retrieval half)

Every memory version carries `justifications: [Justification]`, stamped by the kernel at `write`:

```
Justification = { kind: delivered_memory | expanded_handle | declared_input | dependency_stamp,
                  ref: VersionedRef, at: EventRef }
```

`delivered_memory` = every memory version listed in `context.assembled.items[kind = memory]` for the model call that produced the write (deterministic; no model cooperation); `expanded_handle` = handles the model expanded in that call; `declared_input` = inputs the writer names (may only *add*); `dependency_stamp` = the contract's stamps. This is the TMS justification set (F4) and a refinement of ADR-0033's `derived_from` (`Derivation{kind = revision | extraction | summary, inputs, deriver}` is recorded alongside; `justifications` is its kernel-verified subset). **Rule J1:** `lifecycle_state(v) = stale_by_dependency` iff some justification `j` with `kind ≠ declared_input` has `lifecycle_state(j) ∈ {revoked, stale_by_dependency}` — revocation propagates transitively along kernel-stamped justifications, never along `declared_input` alone (a writer cannot make a memory *depend* on more to get it withheld later, but it can be *narrower* than the kernel's view only through the C2 option below). **Rule J2:** supersession with `reason = edit` does **not** propagate (a corrected wording does not stale its dependants); `reason = revocation` and `RevocationRecord` do; `expired` propagates only if the dependant's contract says `dependency_changed`. **Rule J3 (write-back closure, S-106):** a memory written while a revoked or withheld memory was *delivered* is impossible by E1/E2 (withheld items are not delivered), and a memory written before the revocation is caught by J1 — the two cases S-106's guard could not distinguish. **Index:** `MemoryStaleIndex = project(runs, memory_stale_index, until_seq)` — derived, rebuildable, rebuild-equality tested (ADR-0026), the memory analogue of ADR-0037's `StaleIndex`; results rows and `context.memory.read.withheld` carry `stale_by_dependency` with the revoked ancestor. **C2 narrowing option (OQ-WS-D4-04):** a definition may declare `justification_scope = subject_overlap`, restricting `delivered_memory` justifications to delivered memories sharing a `subject_key` with the new version — admissible only after the Lab's matched-budget comparison shows the default's utility cost, and never `declared_only`.

What stays immutable for audit (OQ-020): every memory version's canonical bytes for as long as WS-H6's floors require; every `supersedes` edge, `RevocationRecord`, `ConflictSet` and justification list forever (ADR-0037 S8); content may be redacted by endorsed tombstone (WS-H6-adr-3), the lifecycle records never.

### 6.5 Expiry, scope, readers and taint

- **Expiry** is derived (§6.1, F6): `expired` when `freshness` elapses or `invalidation_condition ∈ {ttl_elapsed, scope_ended}` holds; `expire_sweep(at)` is a *view* that lists expired versions for reporting; nothing is deleted; **reads never refresh freshness**; re-validation is a new version with `supersedes{edit}` whose provenance names the re-validating origin (a `kernel` validator, the principal, or a `delegate` — which caps the new version's authority by P1).
- **Scope** (`PersistenceScope`, ADR-0033) is where the version lives and fixes its write ceiling (ADR-0035 check 6) and its default `invalidation_condition = scope_ended(scope)` for `session`/`run`/`turn`; a memory never moves scope — promotion writes a *new* version at the higher scope with `supersedes{edit}` and the `security.label.endorsed{basis = promotion}` event (ADR-0035; H2's per-basis table: clears taint, readers as the reviewer declares).
- **Readers** (`readers`, ADR-0033): P5 step (iii); default `Public` for `run`-scoped memories of the run's own processes; for scopes ≥ `user`, a missing or `∅` reader set denies (AIOS safe default); subagents read parent memories only if `reader ∈ readers` — child results re-enter at `≤ delegate` (ADR-0034 P2). Enforced at C2 (WS-H2), carried at C0.
- **Taint**: the persisted label is `⊔(context_label, label(writer))` (ADR-0034 P4); `TaintedAboveExternal` refuses any write at higher authority; a `poisoned` revocation reason exists for the AgentPoison/MINJA case and propagates by J1 to every memory derived from the poisoned one. Retrieval never orders by relevance before authority (P5), so a poisoned `external` memory cannot outrank a `principal` one for a slot with `min_authority ≥ delegate`, and inside the `external` slot its influence is bounded by Π.
- **Low confidence** (OQ-010): `confidence` is a *writer claim* on the body (ADR-0016), never an authority input (ADR-0033 decision 8: authority is not evidence weight); slots may rank by it *after* the P5 filters.

### 6.6 Interface-contract sketch (language-agnostic; operations · inputs/outputs · invariants · failure modes)

- `write(draft: MemoryDraft{kind, body: Text | StructuredValue, subject_key?, contract, scope, declared_inputs[], supersedes?: {old, reason}, validity_claim?: ValidityState}, ctx: WriteContext{model_call_id | kernel, context_label, delivered_memories[], expanded_handles[]}) → MemoryVersion | ScopeCeilingExceeded | MissingContract | SupersessionAuthorityInsufficient | TaintedAboveExternal | MissingProvenance` — invariants: persisted label per P4; `justifications ⊇ delivered_memories ∪ expanded_handles`; deterministic conflict detection runs before commit; emits `context.memory.written` and, if a conflict set was created or resolved, its record.
- `supersede(new, old, reason, provenance) → SupersedesEdge | CycleDetected | KindMismatch | SupersessionAuthorityInsufficient` (ADR-0037).
- `revoke(old, reason: RevocationReason, authority: ProvenanceRecord, replacement?) → RevocationRecord | AuthorityInsufficient | AlreadyRevoked` — emits `context.memory.invalidated`; updates the derived indexes on the next projection.
- `lifecycle_state(v, at) → LifecycleState` and `validity(v, at) → {valid | invalid{reason, record_ref} | unknown, check_ref}` — pure over records; **invariant V-DET:** identical for the same `(v, at)` in every configuration and process (ADR-0014 property; AC-D4-9); never reads a `Text` leaf.
- `check_contract(contract, at) → {stamps_ok: bool, fired: [DependencyStamp], fresh: bool, validator: pass | fail | none}` — the S-077 `table_versions` check generalized; `UnknownDependencyKind` is a validation error at `write`, never a runtime `unknown`.
- `conflicts(v) → ConflictSet?`; `resolve_conflict(conflict_id, head, basis ∈ {supersession, promotion, approval}) → ConflictSet` — the basis must be a legitimate endorsement or a supersession satisfying the authority rule; a `delegate` cannot call it (`IllegitimateEndorsement`).
- `dependants(v) → [VersionedRef]`, `stale_index(until_seq) → MemoryStaleIndex` — derived views with rebuild-equality tests.
- `promote(v, reviewer: ProvenanceRecord{origin = human(role = reviewer | principal)}, to_scope, to_authority ≤ reviewer.authority) → MemoryVersion` — writes the new version and the `security.label.endorsed{basis = promotion}` event atomically (same ledger transaction); failure `EndorserBelowTarget`, `BasisNotAllowed` (never on a `no_store` memory).
- `filter_for_slot(candidates: [VersionedRef], slot: SlotDeclaration, reader, until_seq) → {admitted: [Candidate], withheld: [{version_id, state, reason}]}` — the D4 half of D3's `retrieve` and D1's `admit`: applies P5 (i)–(iii) with the slot's `validity_policy`, `conflict_policy`, and readers; **the order of application is the contract**; `NoAuthoritativeItems` ≠ empty relevance.
- `revalidate(v, provenance) → MemoryVersion` — new version with a fresh contract; never mutates `v`.
All operations are implementable out-of-process over the canonical encoding and typed error sums (T-LCD-12).

### 6.7 Data-model sketch

`Memory` (ADR-0016 entity 4) gains kernel fields: `kind: MemoryKind = fact | preference | episode | diagnosis | recovery | procedure_pointer | summary | journal` (+ registered `ext`); `subject_key?`; `contract: InvalidationContract`; `justifications: [Justification]`; `conflict_set_ref?`; `confidence?` (claim); existing `validity: ValidityState{valid_from, valid_until | invalidation_condition}`, `authority`, `scope`, `source_trajectories[]`, `content`. Records: `RevocationRecord` (ADR-0037, `kind = Memory`, `reason: RevocationReason`), `ConflictSet`, `SubjectKey`, `MemoryStaleIndex` (derived), `MemoryPolicy{per_kind_defaults: map<MemoryKind, {default_scope, default_contract, granularity_allowed, conflict_policy}>, justification_scope ∈ {delivered (default), subject_overlap (C2)}, escalate_on_unresolved: bool}` — a MUST-data artifact of the sealed definition (`definition` authority, `authority_cap`-layered, ADR-0024); it is not model-conditioned and carries no assumption-debt record unless a profile overrides a default (then T-LCD-05 applies). Slot extension (CF-WS-D4-03): `SlotDeclaration.validity_policy{admitted_states ⊆ {valid, unknown, stale_by_dependency}, conflict_policy, max_stale?}` replacing the boolean `admit_unknown_validity`. Ledger payloads (CF-WS-D4-01): `context.memory.written{memory_id, version_id, kind, scope, label, contract_hash, justifications[], supersedes?, conflict_set_ref?}`, `context.memory.invalidated{version_id, reason: RevocationReason | dependency_changed | expired, by: EventRef, replacement?, fired_stamp?}`, `context.memory.read{query_ref, until_seq, delivered: [version_id], withheld: [{version_id, state, reason}], filter_order_attestation}`. Scope kind `memory_op` (ADR-0042) and measurement point M14 gain `withheld_count` (CF-WS-D4-06).

### 6.8 Measurement: validity vs compliance for memory (I2; OQ-049 memory row; OQ-128 input)

`MetricDeclaration`s (ADR-0045 form), all `computed_from` ledger events, class-scoped (`applies_to_classes = {native}`; hosted ⇒ `n/a{class}`):

| metric | definition | detector | veto? | stage |
|---|---|---|---|---|
| `memory.revoked_delivered` | count of `context.artefact.delivered` whose memory version has `lifecycle_state ∈ {revoked, superseded}` at that `seq` | deterministic (kernel) | **veto: true** — "revoked memory never surfaces" | C0 / Stage 2 |
| `memory.stale_delivered` | delivered versions with `validity = invalid{dependency_changed | expired}` at delivery | deterministic | **veto: true** — "stale version never acted on" (delivery form) | C0 / Stage 2 |
| `memory.stale_by_dependency_delivered` | delivered versions in `MemoryStaleIndex` without slot admission | deterministic | veto at C2 | C2 / Stage 2–3 |
| `memory.stale_acted_on` | an effect `committed` whose `derived_from`/args provenance cites a memory that was `invalid` at the proposing call | deterministic (H1 decision record + D4) | **veto: true** — the "acted on" form; the `revoked-policy action` row of OQ-128 for memories | C2 / Stage 3 (C0 for `revoked`, since E1/E2 are C0) |
| `memory.validity_rate` | fraction of delivered memories `valid` at delivery (denominator excludes `unknown` admitted by policy, reported separately) | deterministic | no | C0 / Stage 2 |
| `memory.unknown_admitted_rate` | delivered with `unknown` under `admit_unknown_validity` | deterministic | no | C0 / Stage 2 |
| `memory.activated` | `context.artefact.activated` for memory artifacts: handle expansion (`signal = loaded`), or a proposal referencing the memory's `subject_key`/suggested call (`signal = cited`) | deterministic where `activation_observable`; else `n/a{no_detector}` | no | C0 / Stage 3 |
| `memory.followed` | `verification.artefact.followed`: for `recovery` — next proposal's canonical args equal the suggestion (S-077 first-try); for `procedure_pointer` — the procedure invoked; otherwise judged (`detector = judged`, `model_io` required) | deterministic for two kinds; judged otherwise | no | C0 / Stage 3 (deterministic kinds); C2 (judged) |
| `memory.over_invalidation` | `invalidated{reason = dependency_changed}` whose fired stamp had `granularity = table`, and stale-by-dependency versions later re-validated unchanged | deterministic | no | C1 / Stage 3 |

Reporting shape is ADR-0014's decomposition: `E[Δ] ≈ P(valid) · P(activated | delivered, valid) · P(followed | activated) · E[Δ | followed]`, keyed by model snapshot; a "memory helps" claim is a `ComparisonReport` with `benefit_kind` and `budget_match.status` (ADR-0046). **OQ-128 input:** `memory.revoked_delivered` and `memory.stale_delivered` are C0/Stage 2 vetoes (their enforcement is the C0 retrieval order); `stale_by_dependency` and taint-related vetoes are C2.

### 6.9 Acceptance-criteria sketch (AC-D4-*)

- **AC-D4-1 Revoked never surfaces (S-106 regression; AC-L4-7 executable form).** Fixture: memory `A` (principal, keyed), replacement `A'` with `supersedes{revocation}`, `A` more relevant than `A'`; after `revoke`, `retrieve` under default policy returns `A'` and lists `A` in `withheld` with `state = revoked`; `admit` at a later `seq` re-checks; `memory.revoked_delivered = 0` across the Stage 3 suite; `mode = audit` returns `A` with its state. (C0 / Stage 2)
- **AC-D4-2 Stale version never acted on (S-077 drift fixture).** A `recovery` memory stamped on `tool_capability_version = t1`; the capability is republished as `t2`; at the next `retrieve` the memory is `invalid{dependency_changed}` and withheld; a `row`-granularity sibling stamped on an unchanged row is still delivered; `memory.stale_delivered = 0`; validity verdicts are byte-identical across two model profiles (V-DET). (C0 / Stage 2–3)
- **AC-D4-3 Downstream inheritance (S-106 write-back).** Call `c₁` delivers `A`; the model writes journal `J` in `c₁`; `A` is revoked; `J` is `stale_by_dependency{A}` in `MemoryStaleIndex`, withheld by default, delivered only under `admit_stale_by_dependency` with the annotation; a journal written in a call that did not deliver `A` is unaffected; rebuild-equality of the index holds after deleting it. (C0 / Stage 2 for the index; C2 for policy admission)
- **AC-D4-4 Conflict sets.** Two `principal` facts with the same `subject_key` and different values, no `supersedes` asserted ⇒ `coexist` set; slot `conflict_policy = withhold_all` withholds both, default delivers both annotated; a judged contradiction on free text creates a set and never emits `supersedes`; an `approval`/`promotion` naming the head resolves it. No resolution ever depends on result order or wall-clock. (C0 deterministic; C2 judged)
- **AC-D4-5 Supersession authority.** An `external` memory asserting `supersedes` over a `principal` memory ⇒ `SupersessionAuthorityInsufficient`; the write persists as `coexist` and never withholds the `principal` memory; a `delegate` cannot `revoke` a `principal` memory. (C0 / Stage 2)
- **AC-D4-6 Promotion is the only way up.** After a run that read external content writes memory `M` (`≤ external`, scope `session`), `M` never enters a slot with `min_authority ≥ principal` (AC-D1-2); `promote` by a human reviewer creates `M'` at `project`/`principal` with `security.label.endorsed{basis = promotion}` and `M'.supersedes = M`; a model-issued `promote` fails `IllegitimateEndorsement`. (C0 / Stage 2)
- **AC-D4-7 Expiry without deletion.** A `preference` with `max_age` elapses ⇒ `expired`, withheld, bytes intact, `context.memory.invalidated{reason = expired}` emitted by the projection, reads do not extend freshness; `revalidate` produces a new valid version. (C0 / Stage 2)
- **AC-D4-8 Scope and readers.** A `user`-scoped memory written without `approval` is refused (`ScopeCeilingExceeded`); a memory with `readers = {p₁}` is withheld from a subagent whose reader is `p₂` (C2); a `run`-scoped memory is `expired{scope_ended}` in the next run. (C0 / C2)
- **AC-D4-9 Model-free validity (ADR-0014 property).** Property test: for random `(v, at)` over the Stage 3 corpus, `validity` and `lifecycle_state` are equal across two profiles, two processes and a rebuilt index; no operation on the path reads a `Text` leaf. (C0 / Stage 2)
- **AC-D4-10 Immutability and audit.** Every transition in §6.1 corresponds to exactly one appended record/event; no memory version's bytes change; after redaction of a memory's content the lifecycle edges, conflict sets and justifications remain and `audit_completeness` holds (WS-H6). (C0 / Stage 2)
- **AC-D4-11 Measurement decomposition.** For the Stage 3 suite, the Lab reports `memory.validity_rate`, `activated`, `followed` with detector classes per profile and the realized-benefit decomposition; `followed` is deterministic for `recovery`/`procedure_pointer` and `n/a{no_detector}` or judged elsewhere; hosted rows are `n/a{class}`. (C0 / Stage 3)
- **AC-D4-12 Utility under matched budget (T-LCD-14).** Lab recipe: `validity filter ∈ {off, on}` × `justification_scope ∈ {delivered, subject_overlap}` × `conflict_policy` under `MatchSpec`, reporting success, memories withheld, over-invalidation, approvals and cost; the C2 narrowing is admitted only from this report. (C0 / Stage 3 recipe; C2 decision)

## 10. Confidence

**High** for the enforcement-point rule, immutability, supersession-authority and the retrieval order: they are ratified (ADR-0034 P5, ADR-0035, ADR-0037) and this dossier only supplies the predicates; the failure signature is reproduced in source (graphiti default filter, goose instruction) and by S-106's defense ladder. **High** for the invalidation-contract shape: RFC 9111 and S-077 agree on validators + freshness + fine-grained invalidation, and the check is a pure record comparison. **Medium** for justification-based inheritance: the TMS mechanism is mature and the write-back hole is documented, but the conservative `delivered_memory` rule is untested for utility (AC-D4-12; `no-precedent / novel`). **Medium** for conflict-set policy defaults (`coexist` annotated; no recency tie-break): sound by construction, but every production system chooses recency and the utility comparison is a Stage 3 result. **Low** for per-kind default contracts (OQ-WS-D4-02) — they must be measured. No C0 slice rests on a provisional number; S-077/S-106 are load-bearing only for mechanism and fixture design.
