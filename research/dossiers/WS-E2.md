## 1. Scope & boundary

This workstream decides **how a set of `ToolCapability` nodes becomes the tool surface a particular model uses best, beyond the one-capability-one-function rendering WS-A4 fixed at C0**: the closed set of *exposure modes* (primitive, split, composite, freeform/grammar, code-mode, shim), the *surface family* a capability set compiles to under a profile and a declared task class, the mapping from every surface back to its capabilities for authority and attribution (`SurfaceBinding` over `SurfaceArgMap` or a `Procedure` plan), the *result-rendering* (output-compression) and *surface-failure* (error-rendering) halves of a surface, the *wrapper-synthesis* pipeline and its admission gates (ADR-0022's E1–E7 plus four safety obligations S1–S4), the assumption-debt hooks that make every model-specific shape a hypothesis with an expiry, and the acceptance criteria and T-LCD tests all of this must pass.

It explicitly leaves to neighbours: the `ToolCapability` entity, `EffectClass` and identity (WS-A3, ratified); the compilation pipeline, purity, trace map, closed-world rule, `ModelProfile/1`, protocol targets and the obligations E1–E7 themselves (WS-A4, ADR-0019…0022 — consumed, never re-decided); the concrete rule inventory, probes and the Profile Compiler that *selects* a surface family per model (WS-C3 — this dossier defines what a `tool_shape`/`result_render`/`error_format`/`interaction_mode` rule may point at, not which model gets which); capability metadata — `preconditions` as checkable domains, cost/risk/permission/observability fields, failure classes of a capability (WS-E1); run-time *selection* among compiled surfaces — deferred loading, tool search, per-turn reveal (WS-E3, under ADR-0019's closed-world rule); MCP/ACP/A2A transports and the lowering of surfaces to `tools/list` (WS-E4, ADR-0021); sandboxing and effect capture, including the sandbox that code-mode programs run in (WS-E5/B5); the reference monitor that evaluates `Permission` through `SurfaceArgMap` (WS-H1); the E4 fixture suite's budget accounting and the equivalence run (WS-I2); the evolution service that may *propose* synthesized surfaces (WS-I5) and the debt-record manager (WS-I6); every language/runtime choice (ADR-0050 §8 — nothing here names an ecosystem, and the only permitted reference is to a sandbox primitive, §6.6).

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — The tool surface has six exposure modes in production, and every one of them is selected by data keyed on the model.** Codex's per-slug `models.json` chooses `tool_mode = code_mode_only`, `apply_patch_tool_type = freeform`, `shell_type ∈ {unified_exec, shell_command}` and a `truncation_policy`; its `ToolSpec` enum serialises to five provider dialects (`function`, `namespace`, `tool_search`, `web_search`, `custom` freeform) and `create_tools_json_for_responses_lite` *re-groups* plain functions into a namespace object for one API variant. gemini-cli resolves a `ToolFamily` per model id and applies `base ⊕ override` per tool; SWE-agent loads tool *bundles* and one *parser* per configuration; goose adds an interpreter-model `toolshim` for models without native calling; opencode chooses `apply_patch` versus `edit`+`write` by a model-id substring and builds a code-mode catalogue from the permission ruleset. **Implication:** the exposure-mode set is closed and small — `{primitive, split, composite, freeform, code_mode, shim}` — and every mode is implementable as *data selected by a profile rule* (T-LCD-01), because two production systems (codex, gemini-cli) already do exactly that; opencode's substring branch is the negative precedent ADR-0024 already classifies as a defect.

**F2 — Composite and split surfaces are the norm, not the exception, and they need a mapping the kernel can evaluate.** `str_replace_editor` (SWE-agent `edit_anthropic` bundle; the Anthropic text-editor shape) is one surface with a `command ∈ {view, create, str_replace, insert, undo_edit}` enum over what HIR models as `read_file`, `write_file`, `edit_file` (and an undo procedure); Anthropic's own guidance recommends `schedule_event` over three primitives; codex's `unified_exec` merges shell execution with a resumable process session and `write_stdin`; opencode's `edit`/`write` *split* one `edit_file` capability into two surfaces with a fixed-parameter partial application. In every case the argument mapping is total and static (a `command` value selects the capability; the rest of the fields map by name) — i.e. the mapping is exactly a small typed plan with `Branch` on a surface field and `Invoke` steps. **Implication (answers OQ-066 part 1):** the ADR-0022 requirement "express the mapping as a HIR `Procedure` plan" is *sufficient* for E1–E3 on composite/split surfaces, provided the plan is restricted to the closed step kinds `Branch(Predicate over surface fields) · Invoke(Ref<ToolCapability>, ArgBinding) · Verify` with no `Opaque` and no `Loop` — every branch's effect set is then a static union, every `Invoke` has an argument map, and precondition inclusion is checked per branch. No new plan language is needed; a **`PlanMap`** is a `Procedure` under those restrictions.

**F3 — Code-mode is a container surface whose nested calls are ordinary surfaces, so E1–E7 apply per nested call at run time and the container carries only an upper bound.** In codex the code-mode surface is itself a freeform grammar tool named `exec`; nested tools are the same `ToolSpec`s with their descriptions *augmented* by a typed declaration sample (`augment_tool_definition`), and `is_code_mode_nested_tool` excludes only the container and `wait`. Anthropic requires per-tool opt-in (`allowed_callers`) and keeps results in the execution environment; Cloudflare mediates credentials through bindings that route every call to a supervisor. opencode derives the code-mode catalogue from `Permission.visibleTools`. **Implication (answers OQ-066 part 2):** a code-mode surface is admissible when (i) every nested tool is a compiled surface with its own `SurfaceBinding` (closed-world rule), (ii) each nested call is a separately monitored `Effect` with `parent_effect_id` = the container effect, and (iii) the container's declared effect set is the union of its nested tools' effects plus `exec` — E1 holds as an inclusion bound, E2/E3 are discharged per nested call by the reference monitor, and E4 is discharged on the *nested* surfaces (the program is model-authored and cannot be fixture-tested at compile time). This is the C0/C2 boundary: `unified_exec`-style composites with a static `PlanMap` are C1-admissible under a profile rule; code-mode and shim (run-time or model-written mappings) are C2 with E4 mandatory on their nested/parsed surfaces.

**F4 — Schema-dialect lowering is lossy in three distinct ways and two of the three audited systems lose silently.** pi's strict transform rejects sixteen keywords with a typed error and rewrites optional properties to `anyOf[T, null]` (declared narrowing); OpenAI's own strict mode requires every property `required` and `additionalProperties: false`; opencode's sanitiser turns a boolean schema into `{type: "string"}` and `const` into a one-element `enum`; goose's `normalize_nullable` drops the null variant ("optional-ness is already conveyed by the field being absent from `required`" — a comment that is false under strict mode). **Implication:** E3's `narrowed` loss class is necessary and the transform must be a *declared operation list* (`SchemaDialectTransform{ops[], narrowed[]}`) so `lift(lower(schema))` can name what changed; a transform whose effect on the accepted input set cannot be stated is an error, never a rewrite.

**F5 — Output compression has three production mechanisms, all model- and validator-relevant, and the field reports what it lost only sometimes.** Truncate-and-offload (opencode/pi 2000 lines / 50 KiB with the full text written to a file and a hint; codex 10,000-token `truncation_policy` and a `ToolOutput` contract whose lossy `log_output` "is not the authoritative tool result"), concision enums (`detailed | concise`, ≈⅓ tokens, S-037), and *never entering context* (programmatic tool calling; Cloudflare "only read back the final results it needs"). pi reports `truncatedBy/totalLines/totalBytes`; codex marks the authoritative result separately; opencode hints at the file. Notation Matters (`provisional`) shows token-optimized notations cost up to 14 pp accuracy and collapse parallel calls for most models. **Implication:** result rendering is a profile-owned surface (ADR-0020 `result_render`) whose *loss must be declared against validator needs* (E6) and whose offloaded remainder must be a content-addressed `Artifact` reachable through a compiled surface (closed-world rule); compression can never be a default that a validator does not see.

**F6 — Surface failures are a separate class from capability failures, are detected before execution, and are rendered per model.** SWE-agent's parser raises `missing / multiple / invalid_command / invalid_json / missing_arg / unexpected_arg` with a per-parser error template; Cursor separates `InvalidArguments` and `UnexpectedEnvironment` (model mistakes) from `ProviderError`, `UserAborted`, `Timeout`; WS-H1 already denies `UnmappedArgument` at the monitor. **Implication:** E5's surjectivity must range over two sets — capability failure classes (WS-E1) and a closed **surface-failure** set the compiler owns — and the rendering of both is the `error_format` rule; a surface failure never reaches an executor and is ledgered as its own event so that compliance metrics can count "model produced an unusable call under profile P" separately from "tool failed".

**F7 — Interface synthesis is shipping without equivalence or safety checks, and the checks are cheap relative to the evaluation the field already pays for.** HEART wraps every tool "with an LLM interface that handles schema resolution and execution internally" and reports gains without any check; Cursor validates surfaces by keep-rate; Anthropic reports 72% → 90% from *examples* in definitions. Each E-obligation is ordinary software engineering (schema inclusion, property tests, differential tests); ToolEmu shows an emulated adversarial pre-check finds real failures at scale. **Implication:** the admission pipeline of §6.5 is implementable today; its novelty is the integration with provenance, debt records and the reference monitor, cited against HEART/Cursor/gemini-cli as partial prior art (phase-0 §5.2 rule).

## 5. Disconfirming evidence & negative results

**Against per-capability compilation at all (the code-mode objection).** CodeAct (Tier A) reports that a code action space beats JSON tool calls across 17 models; Cloudflare argues models "have not seen a lot of 'tool calls'"; codex ships `code_mode_only` for its newest slugs; Anthropic's programmatic tool calling keeps results out of context. If the best surface is "a program", the unit of compilation is the *catalogue rendering* for the sandbox, not one shape per capability. *Why this does not overturn:* in every code-mode system the nested tools are still compiled surfaces — codex augments each nested tool's description with a typed declaration, opencode builds a per-server tool tree from the same MCP definitions, Anthropic gates each tool with `allowed_callers` — so the per-capability surface (name, schema, description, arg map) is what the container renders. Code-mode is therefore an *interaction mode of the same compiler* (F3), and the safety obligations become sharper, not weaker (S2: per-nested-call mediation). What changes is that E4 cannot be discharged on the container; it is discharged on the nested surfaces, and the container carries only an effect upper bound.

**Against the equivalence/safety obligations being worth their cost.** HEART, Cursor and gemini-cli ship model-specific interfaces with no such check and report gains by end-to-end evaluation; OpenAI's guidance ("pass the intern test", "fewer than 20 functions") is about simplicity, not verification. *Why this does not overturn:* ADR-0022 is ratified and already answers this for the C0 obligations (attributability and authority-widening detection are governance requirements under ADR-0002, independent of benchmark gains); WS-E2 adds S1–S4 only where synthesis or run-time mapping introduces authority that C0 surfaces cannot (a model-written program, a model-parsed call, a model-written description). The residual cost objection is accepted for E4 on composites and answered by scoping: E4 fixtures are required per *branch* of a `PlanMap`, not per composite product, and the E4 suite is inherited from the primitive surfaces where the branch's `Invoke` targets a capability that already has one.

**Against surface families as a first-class object (the "it is mostly prose" finding).** gemini-cli's two family manifests are schema-identical and differ only in descriptions; the `gemini-3` set is documented as "initially a copy" of the legacy set. If real divergence is prose, `description_template` rules with debt records suffice and a family/exposure-mode apparatus is over-engineering. *Why this does not overturn:* Cursor (patch vs string replacement) and codex (`code_mode_only`, `freeform` patch, `unified_exec` vs `shell_command`) show *shape* divergence across providers in the same year; opencode had to ship two edit surfaces; SWE-agent ships five parsers. Divergence is prose *within* a provider family and shape *across* families — both are profile-owned, and the family object is what lets a rename and a reshape be attributed separately (T-LCD-10).

**Against compression as a compiler concern.** Truncation limits are runtime constants in every audited system, and Notation Matters (`provisional`) suggests aggressive compression hurts accuracy; one could leave rendering to the context builder (WS-D1). *Why this does not overturn:* the *policy* (mode, thresholds, retained fields) is model-conditioned data — codex keys it per slug — and E6 needs the retained-field list at compile time against validator bindings; the *execution* of rendering stays at run time under the compiled spec (ADR-0019 closed-world split), which is exactly the D1 relationship WS-A4 fixed for transcript rendering (OQ-063). Notation Matters is used as the reason compression is *never a default* and token-optimized notations are inadmissible below C2.

**Against `Procedure` as the composite mapping (OQ-066).** A `Procedure` admits `Loop`, `Delegate`, `Opaque` and `Instruction` steps; a composite mapping using any of these makes E1–E3 undecidable, and `unified_exec` (a resumable process with `write_stdin`) is stateful across calls, which a per-call plan does not model. *Why this does not overturn:* the answer is the restriction, not a new language — `PlanMap` = `Procedure` restricted to `Branch/Invoke/Verify` with a declared `session_state: Ref<Artifact>?` for stateful composites; `unified_exec` then compiles as `Branch(has session_id → Invoke(process_write) ; else → Invoke(exec))` over two capabilities whose effects are static. Anything needing `Loop`/`Opaque` is code-mode by definition and goes to C2 with run-time mediation. The residual question — whether WS-H2's closed predicate language and the `Branch` predicate should be one language — is raised as an open question.

**Negative results from the audit.** (i) No audited system records *which surface version* a model saw when a tool call fails, so surface regressions are attributed by re-derivation (same gap WS-A4 found for bundles). (ii) No audited system counts surface failures (unparseable/unmapped) separately from tool failures in a form a compliance metric could use; SWE-agent's error codes are the closest and are not persisted as typed events. (iii) Two of three schema sanitisers lose silently (F4). (iv) No audited system checks that a truncation policy preserves the fields a downstream validator reads; codex's `ToolOutput` separates authoritative from lossy output but does not tie the lossy form to any consumer. (v) The shim's fuzzy name resolution (goose `resolve_tool_name`) is an undeclared transform that can bind a call to a different capability than the model named — an authority hazard S1 forbids.

## 6. Recommendation for the spec

### 6.1 Position in the compilation model (consumes ADR-0019/0020/0022; decides nothing they decided)

The tool-interface compiler is the **stage-3 sub-operation for the tools plane**: `lower_profile` (ADR-0019) calls `compile_tool_surfaces` for the capability set of the sealed definition, and the result is the `tools: ToolSurface[]` part of the `ModelSurface`. It is a component class (`ToolInterfaceCompiler`) receiving `(ModelProfile, ResourceAccount)` (T-LCD-08/-12), pure (no clock/env/network), and its outputs are content-addressed with the bundle. The C0 slice (one capability → one `native_fc` function surface with a total `SurfaceArgMap`) is WS-A4's and ships at Stage 1–3; **everything below is the C1/C2 extension that widens the exposure-mode set and adds synthesis**, admitted only through `ProfileRule`s of kinds `tool_shape`, `naming`, `schema_dialect`, `description_template`, `error_format`, `result_render`, `interaction_mode` (ADR-0020's closed enum — no new kind is needed).

### 6.2 Compiler contract (operations · inputs/outputs · invariants · failure modes)

- `compile_tool_surfaces(capabilities: [Ref<ToolCapability>], profile: ModelProfile, task_class: TaskClassDeclaration, env: EnvironmentDeclaration, permission_ceiling: Ref<Permission>, validators: [Ref<Validator>]) → SurfaceFamilySet | UnexpressibleSurface | UncheckableSurface | SurfaceSynthesisRefused`
  - *Inputs are declared, never observed:* `TaskClassDeclaration{task_class_id, labels[], expected_capabilities[]}` and `EnvironmentDeclaration{environment_count, executor_platform, session_support, capability_declaration}` are records in the sealed definition or the configuration (the codex `include_environment_id` / windows-guidance inputs made explicit); run-time state never enters (ADR-0019 purity). Run-time *selection* among compiled variants is `select_surfaces` (WS-E3).
  - *Output* `SurfaceFamilySet{families: [SurfaceFamily], bindings: [SurfaceBinding], catalogue_rendering?: CatalogueRendering, diagnostics[]}`.
  - *Invariants:* every capability in `capabilities` is reachable from ≥1 surface or listed in `diagnostics` as `unexposed{reason ∈ {policy_hidden, deferred, unsupported_mode}}`; every surface has exactly one `SurfaceBinding`; `∪ effects(bindings) ⊆ effects authorized by permission_ceiling` (S1); every `ToolSurface` carries `rule_ids[]` naming the profile rules that shaped it and each rule carries a complete `AssumptionDebtRecord` (T-LCD-05); the diff of two compilations differing only in profile ⊆ profile-owned fields (T-LCD-01); every text field of a surface is a `Text` leaf with provenance/authority (T-LCD-02).
  - *Failure modes (errors, never warnings):* `UnexpressibleSurface(capability, profile, reason)` (ADR-0019); `UncheckableSurface(surface, obligation ∈ {E1, E2, E3}, reason)` when a mapping cannot be typed (the S4 fail-closed signal); `SurfaceSynthesisRefused(candidate, gate)` from §6.5; `DialectNarrowingUndeclared(surface, keyword)` when a transform cannot state its loss.
- `bind(surface: ToolSurface) → SurfaceBinding` — total; `SurfaceBinding{surface_id, exposure_mode, capability_refs: [semantic_id], mapping: SurfaceArgMap | PlanMap, rule_ids[], evidence_ref: Ref<EquivalenceEvidence>, safety_ref: Ref<SafetyEvidence>, effects_bound: set<EffectClass>, family_id, variant_id}` — the record the trace map, the reference monitor and every `action.tool.*` event reference; E7 is the invariant that `capability_refs` are semantic ids and that no per-surface accounting exists.
- `check_equivalence(surface, capability | plan_map, suite?) → EquivalenceEvidence{E1..E7}` — ADR-0022 verbatim; for `PlanMap` mappings the checks run per branch and the evidence carries `per_branch[]`.
- `check_safety(surface, binding, permission_ceiling) → SafetyEvidence{S1..S4: pass | fail | n/a(reason)}` — §6.5.
- `render_result(observation, spec: ResultRenderSpec, validator_bindings) → RenderedResult` and `render_failure(failure: SurfaceFailure | CapabilityFailure, spec: ErrorFormatSpec) → RenderedFailure` — specified here, executed at run time by the tool plane under the compiled spec (the same compile/run split as the transcript renderer, ADR-0019 decision 6).
- `synthesize_surface(proposal: SurfaceProposal) → AdmissionResult` — §6.5 pipeline; the only path by which a surface not authored in a profile enters a bundle.
- `retire_surface(bundle, rule_id) → bundle'` — sugar for `relower(bundle, profile − rule)` (ADR-0020 decision 4): the family falls back to its `reference_variant`.

### 6.3 Data-model sketch

- `ExposureMode = primitive | split | composite | freeform | code_mode | shim` (closed; extended by ADR).
  - *primitive*: 1 surface ↔ 1 capability, `SurfaceArgMap` total (C0, WS-A4).
  - *split*: n surfaces ↔ 1 capability; each surface's `SurfaceArgMap` may bind capability parameters to constants (`transform = const`) — opencode `edit`/`write`, `str_replace_editor` decomposed.
  - *composite*: 1 surface ↔ n capabilities via `PlanMap` (§6.4) — `str_replace_editor`, `schedule_event`, `unified_exec`.
  - *freeform*: surface input is text under a grammar leaf (`grammar: CompiledPayload{format_tag: cfg | regex}`); `SurfaceArgMap` has exactly one entry whose `transform = parse(grammar_ref)`; the parser is Core (ADR-0024 MUST-code) — `apply_patch`.
  - *code_mode*: a container surface `{catalogue: [Ref<ToolSurface>], sandbox_ref: EnvironmentRef, yield_policy, result_policy ∈ {return_only, stream}}`; mapping is run-time (F3).
  - *shim*: surface is text; the mapping is a model call (`interpreter: ProfileRef`) producing a parsed call; the parsed call's arguments carry `authority = delegate` and go through the target surface's `SurfaceArgMap`.
- `SurfaceFamily{family_id, capability_refs[], reference_variant: variant_id, variants: [SurfaceVariant{variant_id, exposure_mode, surfaces: [ToolSurface], selector: VariantSelector, rule_ids[]}]}` — one family per capability *set* exposed together; `reference_variant` is always a `primitive` (or split of primitives) `native_fc` rendering — the surface E4 compares against and the fallback `retire_surface` uses. `VariantSelector{predicate over declared fields of TaskClassDeclaration ∪ EnvironmentDeclaration ∪ run-time turn-state fields the profile declares selectable}` in the closed, total, quantifier-free predicate form (proposal: the same form WS-H2 fixed for flow policies — OQ raised).
- `ToolSurface{surface_id, family_id, variant_id, hir_node_ids[], name, description: Text, examples: [Text]?, dialect: SchemaDialectTransform, schema, output_schema?, error_format: ErrorFormatSpec, result_render: ResultRenderSpec, arg_map | plan_map, equivalence: EquivalenceEvidence, safety: SafetyEvidence, rule_ids[], supersedes?: surface_id}` (extends WS-A4's `ToolSurface`; `supersedes` records surface versions within a family — pi's batched `edits[]` over the single-edit shape).
- `SurfaceArgMap.transform` **closed vocabulary (proposed to WS-A4/WS-H1):** `identity | rename | const(value) | project(path) | coerce(type, declared_loss?) | parse(grammar_ref) | unescape(policy_ref) | resolve_name(table_ref)` — every transform is a Core interpreter with no ambient authority; `resolve_name` is the *declared* form of goose's fuzzy resolution and is admissible only with an exact table, never similarity.
- `PlanMap` = `Procedure` with `steps ⊆ {Branch(pred over surface fields), Invoke(Ref<ToolCapability>, ArgBinding), Verify(Ref<Validator>)}`, no `Loop/Delegate/Opaque/Instruction`, optional `session_state: Ref<Artifact>` for stateful composites; `effects(PlanMap) = ∪ over branches`; each `Invoke` has its own `SurfaceArgMap`.
- `SchemaDialectTransform{dialect_id, strict ∈ {prefer, require}, ops: [{op ∈ {drop_keyword, rewrite_optional_nullable, require_all, forbid_additional, inline_ref, oneof_to_anyof, tuple_to_array}, path}], narrowed: [{path, from, to}]}` — every op declares whether it narrows the accepted input set; ops without a declared effect are inadmissible (F4).
- `ResultRenderSpec{mode ∈ {full, truncate{max_lines, max_bytes, max_tokens, direction}, concise{format_param?, retained_fields[]}, offload{threshold, preview_lines, artifact_kind}}, declared_loss: truncated{retained_fields[]}?, validator_reads: [field]}` — E6 is `validator_reads ⊆ retained_fields` for every bound validator; `offload` produces an `Artifact` node and a `ContextItem{payload: Ref<Artifact>}` with a `derived-from` edge, and the bundle must contain a compiled `read_artifact` surface (closed-world rule) or `offload` is `UnexpressibleSurface`.
- `SurfaceFailure ∈ {unparseable, unknown_surface, unmapped_argument, domain_violation, missing_required, multiple_calls_unsupported, grammar_violation, session_state_invalid}` (closed) — detected by the parser/monitor before dispatch; `ErrorFormatSpec{renderings: map<SurfaceFailure ∪ CapabilityFailureClass, Text template>, distinguishability: verified}` (E5); ledger event proposed to WS-B1: `action.tool.surface_rejected{surface_id, binding_ref, failure_class, raw_call_hash, model_call_id}` (no executor effect exists, so this is not an `Effect` record).
- `SafetyEvidence{S1..S4}` and `SurfaceProposal{candidate: ToolSurface, provenance, hypothesis: AssumptionDebtRecord, target_home ∈ {profile_rule, harness_rule}}` — §6.5.
- `CatalogueRendering{mode: code_mode, declarations: [Text], sandbox_ref}` — the container's model-facing catalogue (codex typed declaration samples; opencode server-grouped tree), derived from the nested `ToolSurface`s only.

### 6.4 Admissibility by exposure mode (answers OQ-066)

| mode | mapping | E1–E3 | E4 | extra | tier / stage |
|---|---|---|---|---|---|
| primitive | `SurfaceArgMap` | static | fixture (closed-world) | — | C0 · S1–3 (WS-A4) |
| split | `SurfaceArgMap` with `const` | static | inherited from the capability's fixture, per surface | — | C1 · S5 |
| composite | `PlanMap` (Branch/Invoke/Verify only) | static per branch | per branch, inherited where the branch `Invoke`s a fixture-covered capability | S2 per step | C1 · S5 (static plan); `session_state` composites C2 |
| freeform | one `parse(grammar_ref)` transform | static after parse (parser is Core) | fixture through the parser | grammar is a leaf; parser conformance test | C2 · S5 |
| code_mode | run-time per nested call | inclusion bound on the container; per nested call at the monitor | on nested surfaces; container `n/a(model-authored)` | S1–S4 all mandatory; `callable_from_code` opt-in per capability | C2 · S5+ |
| shim | model parse → target `SurfaceArgMap` | on the parsed call | on target surfaces; shim `n/a(model-parsed)` | interpreter call is a `model_call` effect; `delegate` authority | C2 · S5+ |

`unified_exec` is therefore C1 as a static composite (`Branch(session_id present)`) and its `write_stdin` companion is a split surface of the process capability; the model-written orchestration that codex's `exec` grammar tool admits is C2 code-mode.

### 6.5 Wrapper synthesis: pipeline, safety obligations, debt hooks

**Pipeline (every synthesized surface, whatever its author):** `propose → map → check_equivalence (E1–E3, E5–E7 static) → check_safety (S1–S4) → E4 (executable, per §6.4) → admit as a conditioned rule → observe (delivered/activated/followed; compliance per profile) → expire/retire`. A proposal's author may be a human, a template, or a model/evolution candidate (`provenance.origin ∈ {human, model, evolution, import}`); admission never depends on the author, only on the gates.

**Admission home.** A synthesized surface enters a bundle *only* as a conditioned rule: a `ProfileRule{kind: tool_shape | description_template | result_render | …}` when it is model-conditioned, or a definition-level `HarnessRule{action: restrict tool set / insert ContextItem, conditioned_on}` when it is task-conditioned — the two homes, one `AssumptionDebtRecord` (CF-049). This gives every synthesized shape hypothesis, evidence, owner, expiry and removal test for free, and makes the removal test concrete: `retire_surface` re-lowers with the family's `reference_variant`. The endorsement that admits it is `validator` (the equivalence/safety validators) followed by `seal` — both in the closed ADR-0035 basis list; no new endorsement point.

**Safety obligations (in addition to E1–E7):**
- **S1 — No authority widening, statically.** `effects_bound(S) ⊆ effects(capability_refs)` and `effects(capability_refs) ⊆ grants(permission_ceiling)` by domain and scope; a `PlanMap` may not `Invoke` a capability outside the definition's `allowed_capabilities`; a `resolve_name` transform is exact-table only. Failure: `AuthorityWidening` (ADR-0016/0017 class).
- **S2 — Complete mediation of nested steps.** Every `Invoke` of a `PlanMap`, every nested call in code-mode, and every parsed call from a shim is its own `Effect` with `parent_effect_id` and passes `authorize` (WS-H1) individually; an approval endorses one `effect_id` (ADR-0035) — a composite's approval is for the *plan hash* and covers only the branches that hash names; code-mode batch approval is admissible only for nested calls whose effective risk class is `read_only` and only when the profile rule declares it.
- **S3 — Synthesized text is labelled and placed.** Names, descriptions, examples, grammars and catalogue renderings produced by a model, an evolution candidate, or lifted from a foreign protocol are `Text`/`CompiledPayload` leaves with `authority ≤ delegate` (or `unverified` for imports) and render only into provider roles permitted by the profile's `role_map` (ADR-0034 role-placement invariant); a synthesized description can never occupy a `definition`-authority position. Mechanism: tool descriptions are an injection surface (CaMeL/AgentDojo lineage, via WS-H1/H2).
- **S4 — Fail closed.** A surface with `fail` or `n/a` on E1, E2 or E3, or with an untyped mapping, is `UncheckableSurface` and inadmissible at every tier (only E4 may be `n/a` and only with a declared reason); a shim's parsed call that resolves to no surface is `SurfaceFailure.unknown_surface`, never a best-effort match.

**Optional emulated pre-check (C2).** A ToolEmu-class oracle — an LM-emulated adversarial scenario set run against the candidate surface — is admissible as a `Validator{kind: judge}` charged to `instrument` with a calibration reference (ADR-0047); it can *veto* admission but never *grant* it (S4 and E-obligations are the grant).

**Debt hooks.** Every `SurfaceVariant` names its `rule_ids[]`; every rule carries `{hypothesis, evidence_refs[], owner, expiry_condition, removal_test_ref, status}`; `expiry_condition = model_version_change` is the default for `tool_shape`/`interaction_mode` rules (Cursor's "guardrails long gone" observation as a schema default), `probe_failure` for `schema_dialect` rules (a capability probe that the model accepts `anyOf` retires the narrowing), `experiment_ref` for synthesized surfaces (the admission experiment is the evidence). `lcd_report.conditioned_rules` lists every surface rule; the Lab metric "surface rules per capability per profile" makes escape-hatch growth observable (ADR-0020 decision 5).

### 6.6 Result and failure rendering (E5/E6 halves)

- Rendering is compiled (`ResultRenderSpec`, `ErrorFormatSpec` are profile-owned surface records) and executed at run time by the tool plane; the executed result is always stored authoritative and untruncated as an `Artifact` when any loss occurs (codex `ToolOutput` distinction, made mandatory), and the rendered form is what `context.artefact.delivered` names via `rendering_ref`.
- **Compression is never a default.** `mode = full` is the `reference_variant`; any other mode is a `result_render` rule with a debt record; token-optimized *notations* (non-JSON encodings of schemas or results) are inadmissible below C2 on the strength of S-WS-E2-05 (`provisional`, used as counter-evidence only) and require their own E3/E6 evidence at C2.
- Programmatic-tool-calling-style result policies (`code_mode.result_policy = return_only`) are the one case where a result never enters context; they are admissible only because the sandbox's nested calls are ledgered individually (S2) and the returned value is an `Observation` with `authority = delegate`.
- Surface failures are rendered by `ErrorFormatSpec`, ledgered as `action.tool.surface_rejected`, and counted by a class-scoped metric `surface_rejection_rate(profile, family)` — the direct, per-profile measurement of "the model cannot use this shape" that Cursor measures only indirectly by keep-rate.
- Host-ecosystem requirement (ADR-0050 §8(c), the only ecosystem reference in this dossier): code-mode requires a sandbox primitive that executes model-authored programs with *no ambient authority* and routes every tool call through the kernel (binding-mediated, credential-free — the Cloudflare mechanism); the ADR-0050 helper ecosystem's isolation primitives (WS-E5/B5 decide the mechanism) must host it out of the kernel process.

### 6.8 Acceptance-criteria sketch

- **AC-1 Owned-field discipline.** Compile a fixture capability set under two profiles differing in `tool_shape` (patch vs string replacement) and `interaction_mode` (`native_fc` vs `code_mode`): diff ⊆ owned fields; a fixture with a model-id predicate outside a `VariantSelector` fails link.
- **AC-2 Binding totality and identity.** 100% of surfaces have a `SurfaceBinding`; renaming every surface changes no `capability_refs`, no policy table and no `configuration_id` component other than the profile.
- **AC-3 Composite admissibility.** `str_replace_editor` and `unified_exec` fixtures compile as `PlanMap` composites with E1–E3 `pass` per branch and E4 inherited from `read_file`/`write_file`/`edit_file`/`execute` fixtures; a composite whose plan contains `Loop` or `Opaque` raises `UncheckableSurface`.
- **AC-4 Two profiles × two targets with composites.** The AC-3 fixtures lowered to native and MCP under both profiles pass the same validators; the MCP loss report lists the container as `no_slot` and every nested surface as carried.
- **AC-5 Declared narrowing.** Each dialect op in the fixture profile has a `narrowed[]` effect; a sanitiser that invents a type or drops nullability without an entry fails (opencode/goose negative fixtures).
- **AC-6 Result rendering.** For every bound validator, `validator_reads ⊆ retained_fields`; an `offload` mode without a compiled `read_artifact` surface raises `UnexpressibleSurface`; the untruncated artifact is content-addressed and referenced from the delivered item.
- **AC-7 Surface failures.** Each `SurfaceFailure` class has a distinguishable rendering under each profile (E5); a fixture run producing an unparseable call yields `action.tool.surface_rejected` and no `Effect` record.
- **AC-8 Synthesis gates.** A model-proposed wrapper whose `PlanMap` invokes a capability outside `allowed_capabilities` is refused with `AuthorityWidening`; one whose description would render into a `definition`-authority role is refused (S3); an admitted wrapper appears as a rule with a complete debt record and `retire_surface` yields a valid arm.
- **AC-9 Code-mode mediation.** A code-mode fixture program calling three nested tools yields three `Effect` records with `parent_effect_id` = the container effect, each authorized individually; a nested tool without `callable_from_code` is invisible in the catalogue rendering; the sandbox holds no credential.
- **AC-10 Shim.** The parsed call carries `authority = delegate`; an unresolvable name is `unknown_surface`; the interpreter call is metered as a `model_call` with a distinct token role.
- **AC-11 Out-of-process compiler.** The full suite passes with `ToolInterfaceCompiler` as a separate process (T-LCD-12).

## 10. Confidence

**High** for the exposure-mode set and for "every mode is data selected by a profile rule": read directly from five production systems at pinned commits, with two systems (codex, gemini-cli) already implementing the data form and two implementing the defect form. **High** that composite/split mappings are expressible as restricted `Procedure` plans: the audited composites are all `Branch/Invoke` shaped. **Medium** for the code-mode/shim obligations: the mediation mechanisms are precedented (Anthropic opt-in, Cloudflare bindings, opencode permission-derived catalogue) but no audited system ledgers nested calls as separate monitored effects, so S2 is a design proposal validated at Stage 5. **Medium** for result rendering as compiled data: precedented policy-as-data (codex) but the validator-aware loss (E6) is unprecedented. **Low-to-medium** for anything quantitative from 2026 preprints (HEART, Notation Matters, UniToolCall — all `provisional`, none load-bearing); CodeAct, BFCL and ToolEmu are accepted venues and used for mechanism only.
