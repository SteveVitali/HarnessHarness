## 1. Scope & boundary

This workstream decides **how the reference runtime chooses, per model call, which compiled tool surfaces the model can see and call when the catalogue is larger than the context budget allows** — the run-time *selection* that ADR-0019 §6 reserves for run time ("run time decides *selection* (deferred loading, tool search)") and that WS-A4 §6.7 names `select_surfaces(bundle, turn_state) → revealed[]`. Concretely it fixes: (i) the closed set of **exposure modes** a compiled surface can be in for one model call; (ii) the **exposure policy** component class (`tool_exposure_policy`) whose `select_surfaces` produces an **exposure plan** under the context budget; (iii) the **discovery surface** — the model-facing capability through which deferred surfaces are found — and the **catalog index** component class that answers it, with kernel-executed and provider-hosted execution as two lowerings of one contract; (iv) the **revealed set** run state and the kernel invariant `callable ⇔ revealed` (`SurfaceNotRevealed`); (v) **catalog sync and epochs** — how dynamic sources (MCP `tools/list`, `listChanged`, TTL, enable/disable of extensions) enter the closed world without breaking compiled identity or experiment reproducibility; (vi) the **Lab metric set** for tool-selection quality against context cost, and the acceptance criteria and T-LCD tests.

It explicitly leaves to neighbours: **WS-E1** — what a `ToolCapability` declares (schemas, `EffectClass`, `cost_model`, `preconditions`, `result_render` thresholds); E3 consumes E1's records and adds only the *index form* projection and per-surface `admitted_modes`. (WS-E1's dossier does not yet exist at the time of writing; E3 consumes ADR-0016 entity 6 directly and flags every assumption as an OQ.) **WS-E2** — composite/synthesized surfaces and code-mode wrappers (ADR-0022 C2); E3 only reserves the `code_mode` exposure mode and the disclosure interface E2 must satisfy. **WS-E4** — MCP transport, connection lifecycle, pagination and subscriptions; E3 fixes the `CatalogDelta` it must deliver and the adoption policy. **WS-D1** — placement of `tool_surface` candidates into slots, role placement, `context_label`, delivery events; E3 produces candidates and the plan, D1 delivers. **WS-C3** — the profile rules that decide the *shape* of the discovery surface (regex vs natural-language query), namespace/naming schemes and cache markers; E3 names the rule kinds it needs. **WS-H1/H7** — authority decisions on every call and approval budgets; E3 never decides authority. **WS-H5** — extension trust and pinning of MCP servers; E3 consumes the attestation result as `availability`. **WS-D2** — eviction of revealed surfaces during compaction (E3 exposes `evict`). **WS-I2/J4** — metric registration and comparison protocol; E3 declares metrics in ADR-0045's form.

## 2. Key questions

1. (doc 3 §5, verbatim) Design tool-space scaling: deferred loading, tool search/discovery, catalog retrieval under a context budget (L2/D1), exposure policy (how much of the catalog to reveal), and cost/quality trade-offs; interaction with MCP discovery (E4).
2. (Phase 2 brief) Deliver: discovery/deferred-loading contract; exposure policy interface; metrics for the lab (tool-selection accuracy vs context cost); acceptance criteria; ADR.
3. (added) What is the closed set of exposure modes, and which are C0? How does the closed-world rule (ADR-0019) survive tool search — i.e. how does a surface the model has never seen become callable without the runtime "introducing a surface"?
4. (added) Is the discovery surface a `ToolCapability` like any other (compiled, named by the profile, with equivalence evidence), or kernel magic? Where does it execute — kernel or provider — and what is lost in each lowering (T-LCD-11)?
5. (added) How does a catalog that changes under a sealed definition (MCP `listChanged`, TTL expiry, extension enable) enter the run without changing `configuration_version_id` silently?
6. (added) What must the Lab measure so that "deferred loading helps" is a `ComparisonReport` with `budget_match.status`, not a vendor number?
7. (added) Which parts of exposure are model-conditioned (profile-owned, with assumption-debt records) and which are kernel invariants?

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Tool cardinality is a real failure mode with three independent symptoms: context cost, selection accuracy, and cache economics.** Cost: 50+ MCP tools ≈ 72K tokens (S-040), a five-server setup ≈ 55K (S-379); codex bounds plugin MCP specs at 8,000 bytes each / 64,000 total (`mcp_tool_exposure.rs` L19–20) and the search tool's own source listing at 512 KiB (`tool_search_spec.rs` L8). Accuracy: Anthropic states degradation "once you exceed 30–50 available tools" (S-379); RAG-MCP's baseline with the full catalog in context selects correctly 13.62 % of the time (S-381, `provisional`). Cache: because the tool list is part of the cached prefix, any per-call change to it invalidates the cache — both vendors solve this by keeping the prefix fixed and appending discovered tools *after* it (S-379 "prefix is untouched"; S-380 "loaded at the end of the model's context window"), and MCP's spec text asks servers for deterministic ordering for exactly this reason (S-153 `tools.mdx` L70–73). **Implication:** the exposure plan must be *order-stable and append-only within a run* — a kernel invariant, not a policy choice.

**F2 — Every production implementation is a per-surface exposure-set narrowed by three layers: source configuration, profile/provider capability, and run-time policy.** Codex is the clearest: `ToolExposures = {DIRECT, DEFERRED, CODE_MODE}` per tool (`tool_executor.rs` L14–30); a server's `omit_tools_from` removes surfaces (`mcp_types.rs` L220–223); `code_mode.direct_only_tool_namespaces` removes `DEFERRED | CODE_MODE` for named namespaces (`spec_plan.rs` L235–243); then `search_tool_enabled = model_info.supports_search_tool ∧ provider.capabilities().namespace_tools` (L629–642) decides whether DEFERRED survives (drop DIRECT) or is discarded (drop DEFERRED) (L245–252); the final six-way match yields `Hidden | CodeModeOnly | DirectModelOnly | Direct | DeferredModelOnly | Deferred` with "direct and deferred exposure are mutually exclusive" (L255–262). Goose narrows by code-mode disclosure style and `_meta.ui.visibility` (`reply_parts.rs` L246–290); opencode by the permission ruleset (`registry.ts` L275–280); gemini-cli by `mainAgentTools` allow-list and a per-call name subset (`tool-registry.ts` L655–668, L709–730). **Implication:** `admitted_modes` is a set computed by *narrow-only* composition (definition ∩ profile ∩ policy), mirroring ADR-0034's narrow-or-preserve for labels; a policy can never add a mode the definition or profile denies (T-LCD-08 shape).

**F3 — Deferral has two distinct sub-modes in the wild: *indexed* (name + summary visible, definition absent) and *absent* (only reachable through search).** OpenAI's `defer_loading` keeps "the function name and description" visible and defers only the schema; namespace and server names are always visible (S-380). Cursor gives "names of the tools" statically (S-050). Anthropic's deferred tools are fully absent except through search, and the docs advise a system-prompt section naming *categories* (S-379). Codex's `DeferredModelOnly` is absent-except-search, but the search tool's description carries a bounded *source listing* (`tool_search_spec.rs` L34–62) — an index at source granularity. Goose's `search_available_extensions` lists *extensions*, not tools (`extension_manager.rs` L2602–2660). **Implication:** the mode set needs both `indexed` (a `handle_only` candidate in D1's terms) and `deferred` (no candidate at all), plus a *granularity* axis for the index (surface / namespace / source) — MCP-Zero's hierarchical routing (server → tool) and OpenAI's namespaces are the same idea.

**F4 — The discovery surface is itself a tool with a model-conditioned shape and a search execution location that is a lowering choice.** Anthropic ships two variants because the *query form* differs: regex (`re.search` patterns ≤200 chars) vs BM25 natural language (≤500 chars) (S-379); codex's kernel-side search is BM25 over a derived text (`handlers/tool_search.rs` L154–160) with a `limit` argument defaulting to 8 (`tool_discovery.rs` L7) and is exposed to the provider as a native `tool_search` type (`tool_spec.rs` L27–33) — i.e. the provider executes it when capable, the kernel otherwise; OpenAI documents both "hosted" and "client-executed" with identical output items (S-380). Anthropic admits custom client-side search returning `tool_reference` blocks (S-379). **Implication:** one `ToolCapability` "discover surfaces" with profile-owned surface (query form, name) and two lowerings (kernel index vs provider-hosted), each with equivalence evidence (ADR-0022) and a loss report (T-LCD-11) — exactly the T-LCD-01 shape. The kernel variant is the C0 reference; provider-hosted is a `CapabilityDeclaration` flag (ADR-0020 already lists `deferred_tools` and `tool_search`).

**F5 — The indexed text is a fixed, enumerable projection of the surface, not the surface itself.** Anthropic searches "tool names, descriptions, argument names, and argument descriptions"; codex's `default_tool_search_text` concatenates name, name with `_`→space, description, recursive schema descriptions and property names, namespace name/description, and freeform syntax (`tool_search.rs` L87–150). Retrieval difficulty is dominated by low lexical overlap between task phrasing and tool documentation (ToolRet ROUGE-L 0.06 vs 0.27–0.34, S-368) — so both vendors tell authors to add "keywords that match how users describe tasks" and to namespace names so "one search matches the whole group". **Implication:** the `IndexForm` is a typed projection with declared fields; rename (a profile surface edit, T-LCD-10) changes *retrievability* without changing identity, which is precisely why the Lab must be able to run a rename as its own experiment (doc 2 §9). Description text is a `Text` leaf that carries its provenance label into the index.

**F6 — Revealed surfaces persist across turns, are re-emitted as deferred definitions, and must survive compaction and provider round-trips.** OpenAI: loaded tools "become available for all future turns"; Anthropic expands `tool_reference` "throughout the conversation history"; codex re-emits search hits as `LoadableToolSpec::Namespace` with `defer_loading = true` and drops `output_schema` (`tool_search.rs` L34–75), tracks `tool_search_output_ids` during history normalisation (`normalize.rs` L23) and preserves `ToolSearchOutput` items across remote compaction (`compact_remote_history.rs` L158). The pi issue shows the failure when persistence is lossy: a replayed `function_call` without its `namespace` is rejected with HTTP 400 (S-386). **Implication:** the *revealed set* is run state recorded in the ledger (never inferred from the transcript), with a `retention` policy, and the provider-target lowering of a revealed-but-deferred surface must round-trip its namespace/deferral markers (a T-LCD-11 round-trip test).

**F7 — Catalog drift is a first-class event stream with three triggers, and the clients handle it by re-listing whole sources.** MCP 2026-07-28: `listChanged` notifications now arrive only on a `subscriptions/listen` stream the client opted into (`schema.ts` L1895–1900, L1295–1317); `tools/list` carries `ttlMs` and `cacheScope` (L1081–1094, L1767–1781) with "notification acts as an immediate invalidation signal" (`caching.mdx`); the set "MAY vary by the authorization presented" (`tools.mdx` L60–66). gemini-cli re-lists on notification with a 500 ms verification retry because "Some servers notify before they're fully ready", then removes and re-registers the server's tools (`mcp-client.ts` L719–770) — and listens even when the server "did not declare 'listChanged'" (L406–420); opencode re-lists and publishes `ToolsChanged` (`mcp/index.ts` L462–470); goose bumps a cache version (`extension_manager.rs` L1899). None of them records the *delta* as data or reasons about compiled identity. **Implication:** E3 needs `CatalogDelta` events and an *adoption* step that lowers new surfaces (ADR-0021 lifting, `authority = unverified`) into a new **catalog epoch** — never a silent registry mutation — with `freeze` as the experiment default.

**F8 — Code mode is an exposure mode, not a different catalog.** Goose under `ToolDisclosure::Catalog | Filesystem` removes every non-first-class tool from the model's tool list and reaches them via `list_functions`/`get_function_details`/`execute_typescript` (`reply_parts.rs` L250–262; `code_execution.rs` L585–605), while `Sidecar` keeps them in the list and appends the output schema to the description "since many model providers drop the output schema" (L263–279); codex's `CODE_MODE` bit and `code_mode_name` per function (`tool_namespaces_info.rs` L88–105); opencode's `execute` tool describes a catalog "grouped by server" filtered by permissions (`code-mode.ts` L37–60; `registry.ts` L275–280). **Implication:** `code_mode` is a fifth exposure mode whose disclosure sub-policy (catalog / filesystem / sidecar) is a variant parameter; its equivalence obligations are E2's (ADR-0022 C2).

**F9 — Retrieval quality is the binding constraint, and it is measurable offline.** ToolRet (Tier A): even the best embedding model reaches nDCG@10 ≈ 34–43 on tool retrieval and a weak retriever costs 11.4 pass-rate points downstream; RAG-MCP (`provisional`) reports precision degrading "as the tool registry scales to thousands"; ToolLLM/Gorilla (Tier A) show the retriever-in-the-loop is a 2023 mechanism whose benefit depends on the model being trained to use retrieved docs. **Implication:** the `catalog_index` must be a swappable component class with an *instrument-charged* offline retrieval suite (labelled task → required-surface sets), and every "deferral helps" claim must be a matched-budget `ComparisonReport` against a `direct_all` arm (ADR-0041/0046).

**F10 — Deferral state is already an observability object in shipped harnesses.** Claude Code's context accounting exposes per-category `isDeferred`, per-MCP-tool `isLoaded`, and `deferredBuiltinTools` (S-109 `types.py` L764–817); codex records per-turn `TurnToolNamespacesInfo{direct, deferred, code_mode_name, source}` for every visible function (`tool_namespaces_info.rs`). **Implication:** the exposure plan is ledger data (a `context_assembly`-scoped record), not a transient in-memory list.

## 5. Disconfirming evidence & negative results

**Against deferred loading as a default: the vendors themselves say it can lose.** Anthropic: use standard tool calling when "fewer than 10 tools, every tool is used in every request, or your tool definitions are small" (S-379); every search is an extra model call (latency, output tokens) before the first useful action; D1 §5 already records that "runtime exploration is slower than retrieving pre-computed data" and that models under-retrieve. *Why this does not overturn:* the C0 default is `direct_all`; deferral is a C1 policy variant that must beat `direct_all` in a matched-budget `ComparisonReport` per task class and model (ADR-0046) — the contract only guarantees that the comparison is runnable and attributable.

**Against any index: retrieval is hard and a bad index is worse than no deferral.** ToolRet's best model reaches nDCG@10 ≈ 34–43 and costs 11.4 pass-rate points versus oracle tools (S-368, Tier A); RAG-MCP's precision decays at thousands (S-381). Regex search depends on the model guessing substrings; BM25 depends on lexical overlap that ToolRet measures at ROUGE-L 0.06. *Why this does not overturn:* the index is a registered component class with an offline retrieval suite (instrument-charged) and the Lab reports `selection_recall`/`unrevealed_need` alongside token savings; the disconfirming evidence is the reason those metrics are mandatory, not optional.

**Against a model-facing search tool at all: hierarchical/indexed disclosure may suffice.** OpenAI's namespaces keep names and descriptions visible and defer only schemas; Cursor's names-only static context plus `rg` needs no bespoke search tool; MCP-Zero's routing is server-first. *Why this does not overturn:* these are the `indexed` mode at surface, namespace or source granularity — admitted as first-class modes; the discovery capability is required only when any surface is fully `deferred`, and `NoDiscoverySurface` refuses a plan that defers without one.

**Against `callable ⇔ revealed`: it punishes a model that "remembers" a tool.** A model that learned a tool name from training data or an earlier session will propose a call to an un-revealed surface and be refused; Anthropic's API expands `tool_reference` only for discovered tools and rejects unknown references with HTTP 400 — the same refusal at the provider. *Why this does not overturn:* the closed-world rule (ADR-0019) already forbids delivering an uncompiled surface; a call to an un-revealed surface is either a hallucination (a strong reliability signal worth counting) or a legitimate need the policy under-served (the `unrevealed_need` metric); the refusal message may carry a typed hint ("search for it"), never the definition.

**Against provider-hosted search: it is opaque and lossy.** The kernel cannot observe scores, cannot bound the hit count below the provider's rules (Anthropic `limit` up to 10,000), cannot enforce `hidden`/permission narrowing unless the request omits those definitions, and the round-trip has already broken once (S-386). Search is "not metered as a separate server tool" (S-379), so its cost provenance is at best `bounded`. *Why this does not overturn:* provider-hosted is a lowering the profile declares (ADR-0020 `tool_search`) with a `LoweringLossReport{score: no_slot, hidden_filter: narrowed, cost: hint_only}` and a mandatory round-trip test; the reference variant is kernel-executed; the Lab stratifies by `executed_by`.

**Against catalog epochs / `freeze`: interactive harnesses need tools the instant a server adds them.** gemini-cli, opencode and goose all re-register within one refresh. *Why this does not overturn:* `adopt` is the interactive default and is cheap (an incremental lowering of the delta with `unverified` authority); `freeze` is the experiment default because `configuration_version_id` must not change under a run without a ledger event — which is exactly what silent re-registration does today.

**Against treating exposure as ledger data: volume.** An exposure plan per model call over a thousand-entry catalog is large. *Why this does not overturn:* the plan stores mode *changes* and a `catalog_id`; the full mode vector is `project(run, view = exposure, until_seq)` (ADR-0026); ADR-0029 offloads payloads above the class threshold.

**Negative results from the audit.** (N1) No audited system records *why* a surface was or was not revealed (policy reason, budget, permission) — omissions are not data. (N2) No audited system verifies that a revealed deferred surface is semantically the same object as its catalog entry (identity by name string only; goose must *recover* names the model mangled `__` → `.`). (N3) No audited kernel refuses a call to an un-revealed surface as a typed condition; codex treats direct/deferred as mutually exclusive in the *plan* but the provider enforces callability. (N4) No audited system exposes an offline retrieval-quality suite for its index. (N5) Provider-side search cost is unmetered in both vendors' accounting.

## 6. Recommendation for the spec

### 6.1 Position

Tool exposure is **one component class, `tool_exposure_policy`**, bound in `AgentProcess.native.slots` (not Stage-1 mandatory: absent ⇒ the kernel's `direct_all`), plus **one component class `catalog_index`** (absent ⇒ no `deferred` mode is admissible). The kernel owns: the closed `ExposureMode` sum, the `Catalog` built from the compiled bundle, the `RevealedSet` run state, the `callable ⇔ revealed` check before dispatch, the discovery `ToolCapability` (a kernel-provided capability in the sealed definition whenever any surface admits `deferred`), catalog epochs, and the events. Policy variants own selection and ranking. It runs at `DecisionPoint = retrieve` (Ontology v1 β) **before** D1's `assemble` (WS-D1 §6.1 already orders it so) and consumes `(ModelProfile, ResourceAccount)` (T-LCD-08).

### 6.2 Data model

- `ExposureMode ∈ {direct, indexed, deferred, code_mode, hidden}` (closed per dialect; registered `ext` allowed): **direct** — full compiled definition delivered (D1 `expanded` candidate, `kind = tool_surface`); **indexed** — only the `IndexForm` delivered (D1 `handle_only` candidate); **deferred** — nothing delivered; reachable only through the discovery capability; **code_mode** — callable only from inside an executed program (C2, E2/E5; disclosure sub-policy `{catalog, filesystem, sidecar}`); **hidden** — registered, never delivered, never indexed, never callable by the model (MCP Apps visibility, kernel-internal tools).
- `IndexGranularity ∈ {surface, namespace, source}` — what an `indexed` entry names (a tool, an OpenAI-style namespace, an MCP server / goose extension).
- `CatalogEntry{surface_id (the surface record hash — WS-A3 §6.14: for `tool_surface` the artefact id is the surface's own hash), capability: semantic_id, version_id, source ∈ {harness(component_ref) | mcp(server_ref) | procedure(ref) | extension(ref) | kernel}, namespace?, admitted_modes: set<ExposureMode> (narrow-only: definition ∩ profile ∩ policy), pinned: bool (definition-declared "always direct"), index_form: IndexForm, size: {tokens, estimator_ref}, effect_summary (a fixed projection of `EffectClass`, ADR-0021 decision 3 — hints, never authority), permission_coverage ∈ {covered, ask, uncovered, unknown} (derived from in-scope `authorizes` edges; a selection input only), label: Label (from the surface's `Text` leaves; index forms from lifted MCP tools are `unverified`), availability ∈ {available, unavailable(reason), stale(epoch)}}`.
- `IndexForm{name (profile-owned surface), title?, summary: Ref<Text>, namespace?, tags[], search_text_fields: closed list ⊆ {name, name_split, description, param_names, param_descriptions, namespace_name, namespace_description, examples, effect_summary}}` — the projection F5 fixes; the *rendering* of an index form into context is a `ProfileRule{kind: description_template}` (ADR-0020).
- `Catalog{catalog_id = H(canonical(entries by surface_id)), epoch, bundle_id, sources[{source_ref, snapshot_hash, ttl?, listened: bool}], entries[], index_ref (catalog_index build artefact, content-addressed)}`.
- `ExposurePlan{plan_id, model_call_id, catalog_id, entries[(surface_id, mode)], discovery_surface_ids[], order: [surface_id] (append-only extension of the previous plan's order), budget_estimate{tokens, estimator_ref}, omitted[{surface_id, reason ∈ {budget, policy, permission_uncovered, unavailable, hidden, mode_unsupported_by_profile}}], derived_from, deterministic: bool}`.
- `RevealedSet{run_id, entries[{surface_id, mode, revealed_at: EventRef, cause ∈ {policy, discovery(search_event), principal, procedure(ref), pinned}, retention ∈ {call, turn, run, until_evicted}}]}` — run state, projected from events.
- `DiscoveryQuery{form ∈ {regex, natural_language, structured{namespace?, effect_filter?, tags?, source?}}, text, limit?}` · `DiscoveryResult{hits[{surface_id, rank, score?}], truncated: bool, executed_by ∈ {kernel(variant_ref), provider(profile_ref)}, cost: ResourceVector}`.
- `CatalogDelta{source_ref, cause ∈ {list_changed, ttl_expired, reconnect, extension_enabled, extension_disabled, authorization_changed}, added[], removed[], changed[{surface_id_old, surface_id_new, diff_class}]}` · `CatalogEpoch{epoch, catalog_id_prev, catalog_id, bundle_delta (new compiled identities for adopted surfaces), loss_report: LoweringLossReport, adopted_by ∈ {policy(freeze|adopt), principal(ask)}}`.
- `ExposurePolicyParams{default_mode_by_source: map<source_kind, ExposureMode>, pinned_direct[]: [semantic_id], max_direct_count?, direct_token_share: fraction of ContextBudget, index_granularity, max_reveal_per_search (default 8; ceiling 32 unless amended), retention (default run), discovery_executor_preference ∈ {kernel, provider, provider_if_declared}, drift_policy ∈ {freeze, adopt, ask} (experiments: freeze), permission_gate ∈ {none, hide_uncovered, demote_uncovered}}` — every parameter is MUST-data (ADR-0024).

### 6.3 Operations (language-neutral; T-LCD-12)

1. `build_catalog(bundle, sources_state, profile, account) → Catalog | CatalogBuildError{source_unavailable, IndexOverflow{pages | bytes}}` — pure over inputs; `admitted_modes` computed by narrow-only composition; surfaces without compiled identity are never entries (closed world); `hidden` entries are excluded from `index_ref`.
2. `select_surfaces(catalog, turn_state{model_call_id, revealed: RevealedSet, recent_calls[], goal_ref?, budget: ContextBudget share + remaining counters}, profile, account, params) → ExposurePlan | NoDiscoverySurface | ExposureBudgetExceeded | UnexpressibleExposure{mode, profile}` — the kernel step (`admit`) precedes the policy's `rank`: kernel forces `pinned → direct`, `hidden → hidden`, `unavailable → omitted`, `mode ∉ admitted_modes → omitted{mode_unsupported}`; the policy variant's `rank(entries, turn_state, profile, account, params) → [(surface_id, mode)]` may only *choose among admitted modes* and *order*; the kernel then enforces `Σ tokens(direct) + Σ tokens(indexed) ≤ direct_token_share × window_cap`, appends the plan's order to the previous plan's order, and verifies `∃ deferred | indexed(granularity ≠ surface) ⇒ ∃ direct discovery surface`.
3. `discover(catalog, query, executor, profile, account, params) → DiscoveryResult | DiscoveryQueryInvalid{too_long | empty | unsupported_form}` — hits ⊆ entries with mode ∈ {indexed, deferred} in the current plan; never `hidden`; `|hits| ≤ min(query.limit, max_reveal_per_search)`; results ranked, identified by `surface_id` (never by name); an empty result is a normal result; the kernel variant is deterministic given `(index_ref, query)`; provider execution lifts the provider's references to `surface_id`s and records `score = n/a`.
4. `reveal(revealed, hits | surface_ids, cause, retention) → revealed'` — emits one `action.tool.surface.revealed` per surface; revealed entries enter the *next* plan as `direct` in append order; a surface revealed by discovery keeps its `permission_coverage` — authority is decided by H1 at call time.
5. `evict(revealed, surface_ids, cause ∈ {compaction, policy, principal}) → revealed'` — emits `action.tool.surface.evicted`; pinned surfaces cannot be evicted; D2 calls this.
6. `check_callable(plan_of(model_call_id), proposal) → ok | SurfaceNotRevealed{surface_id?, hint ∈ {search, none}} | SurfaceUnavailable{reason}` — kernel step before the reference monitor: the proposed surface must be `direct` in the plan of the model call that produced the proposal, or `code_mode` for a proposal originating from an executed program. The response to the model never contains the definition of an un-revealed surface.
7. `sync_source(source_ref, trigger) → CatalogDelta` (E4 implements listing/pagination/subscription) and `adopt(delta, drift_policy) → CatalogEpoch | CatalogDriftRefused` — under `freeze`, `removed` entries become `unavailable`, `added` are recorded but not entries; under `adopt`, added/changed surfaces are lowered incrementally (ADR-0021 lifting: `origin = import`, `authority = unverified`) and receive compiled identities; under `ask`, a `permission_request` effect is raised to the principal; every epoch is a ledger event and the run manifest lists `catalog_epochs[]`.

**Invariants.** I-CLOSED: every entry, hit and revealed surface has a compiled identity in the current epoch. I-NARROW: `admitted_modes(policy) ⊆ admitted_modes(profile) ⊆ admitted_modes(definition)`; a policy cannot set `pinned`, `hidden`, `label`, `permission_coverage` or `availability` (`PolicyViolation`). I-ONE-MODE: exactly one mode per surface per plan. I-DISCOVERY: `deferred` entries exist only if a discovery capability is `direct`. I-CALLABLE: `callable ⇔ revealed` at the producing model call. I-ORDER: plan order is append-only across calls within a run (cache stability, F1). I-LABEL: an index form contributes its label to `context_label` as if delivered (ADR-0034 P3; D1 I-LABEL). I-BUDGET: the plan never exceeds its share; `pinned` surfaces exceeding the share are `ExposureBudgetExceeded`, never silently demoted. I-EPOCH: `catalog_id` changes only through `adopt`; no surface is revealed from a stale epoch (`IndexStale`). I-NOAUTH: nothing in E3 grants or widens authority; `permission_coverage` is advisory.

**Failure modes (closed).** `NoDiscoverySurface`, `ExposureBudgetExceeded`, `UnexpressibleExposure`, `PolicyViolation`, `SurfaceNotRevealed`, `SurfaceUnavailable`, `IndexStale`, `IndexOverflow`, `DiscoveryQueryInvalid`, `CatalogDriftRefused`, `CatalogBuildError`.

### 6.4 The discovery capability

A kernel-provided `ToolCapability` `discover_surfaces` with `effects = pure` (a read of kernel state; no `EffectDomain`), `input_schema = DiscoveryQuery`, `output_schema = DiscoveryResult` (index forms only — never definitions), included in the sealed definition whenever any surface admits `deferred` (the resolver adds it; `validate_assembly` diagnoses `deferred` without it). Its **surface** is profile-owned: name (`tool_search`, `search_tools`, …), query form (regex vs natural language — T-LCD-01: zero per-model branches in the capability; two profiles differ in a `tool_shape` rule with an assumption-debt record citing S-379's two variants), description template (may embed a bounded *source listing*, codex precedent, counted in the opacity report). Its **lowerings**: (a) kernel-executed function surface (C0 reference; the `catalog_index` variant answers); (b) provider-hosted (`CapabilityDeclaration.tool_search = declared → probed`), lowered as the provider's native search tool with the catalog's deferred definitions in the request; results are *lifted* to `DiscoveryResult` with `score = n/a`, `executed_by = provider`, `cost.confidence = bounded`; the `LoweringLossReport` declares `{score: no_slot, hidden_filter: narrowed (definitions omitted from the request instead), limit: narrowed (provider ceiling), namespace: round_trip_required}` and the Stage-3 round-trip test replays a revealed deferred call through the target and back (the S-386 regression). Equivalence evidence (ADR-0022): E1 `pass` (pure), E2 `pass` (`SurfaceArgMap` total), E3 declared `narrowed` for length limits, E4 `n/a(kernel_state)`, E5/E6 `pass`, E7 `pass`.

### 6.5 Catalog index component class

`catalog_index` variants (each receives `(ModelProfile, ResourceAccount)`, declares `deterministic`, `index_build_cost` charged to `instrument`, `query_cost` charged to `subject`): **C0** `exact_name` (lookup by name/namespace — enough for `indexed` mode expansion) and `static_allowlist`; **C1** `lexical_regex` (S-379 regex variant semantics: case-insensitive pattern over `search_text_fields`, ≤200 chars), `bm25` (codex precedent; language parameter), `hierarchical` (source/namespace first, then surface — MCP-Zero, OpenAI namespaces); **C2** `embedding` (embedding model is an instrument-charged `model_call` with its own `ProfileRef`; determinism declared false unless the embedding artefact is pinned by content address), `model_ranked` (a `Validator{kind: judge}`-class ranker, ADR-0047 governance), `filesystem` (Cursor/goose: the catalog materialised as files in the environment; discovery is an ordinary `fs_read` through declared capabilities — the discovery capability is then *absent* and `indexed(source)` mode names the folder). Every variant ships an **offline retrieval suite**: `retrieval_eval(index_ref, labelled_queries[{query, required_surface_ids}]) → {recall@k, nDCG@k, k}` over Lab-labelled task fixtures (ToolRet shape), reported as component-level metrics (native only).

### 6.6 Events (proposed to WS-B1; names follow the `action.*` plane prefix)

`action.tool.catalog.built{catalog_id, epoch, bundle_id, sources[], entry_count, index_ref}` (run start, and after each epoch) · `action.tool.catalog.delta{source_ref, cause, added, removed, changed}` · `action.tool.catalog.epoch{epoch, catalog_id_prev, catalog_id, bundle_delta_ref, loss_report_ref, adopted_by}` · `action.tool.exposure.planned{model_call_id, plan_id, catalog_id, mode_changes[], omitted[], budget_estimate}` (scope `context_assembly`; the full plan is a blob above threshold) · `action.tool.discovery.searched{tool_call_id, query_form, query_hash, executed_by, variant_ref, hits[surface_id, rank], truncated, cost}` · `action.tool.surface.revealed{surface_id, mode_from, mode_to, cause, retention}` · `action.tool.surface.evicted{surface_id, cause}` · `action.tool.call.refused{surface_id?, reason ∈ {SurfaceNotRevealed, SurfaceUnavailable}}`. Delivery of index forms and definitions remains D1's `context.artefact.delivered{kind: tool_surface, by_reference?}`; a call to a revealed surface is its `activated` (OQ-049: deterministic).

### 6.8 Acceptance criteria (sketch)

- AC-E3-1 (I-CALLABLE) A proposal naming a compiled surface that is `deferred` in the producing call's plan is refused with `SurfaceNotRevealed`; the refusal payload contains no schema or description; the event is recorded.
- AC-E3-2 (I-DISCOVERY) A definition that admits `deferred` for any surface but binds no discovery capability fails `validate_assembly`; a plan that would defer without a `direct` discovery surface fails with `NoDiscoverySurface`.
- AC-E3-3 (I-NARROW / T-LCD-08) A policy variant that returns a mode outside `admitted_modes`, or touches `pinned`/`hidden`/`label`, is rejected with `PolicyViolation` before any delivery.
- AC-E3-4 (I-ORDER) Across N model calls in one run, every plan's order is a prefix-extension of the previous one; the transcript renderer never reorders delivered tool surfaces (prompt-cache test: cache-read tokens non-decreasing on a fixture).
- AC-E3-5 (T-LCD-01) The discovery capability compiled under two profiles (regex-form vs natural-language-form) differs only in profile-owned surface fields; both satisfy E1–E3/E7.
- AC-E3-6 (T-LCD-11) Lowering a revealed deferred surface to the provider tool-API target and lifting it back preserves `surface_id`, namespace and deferral state; the loss report lists `score` as `no_slot`.
- AC-E3-7 (T-LCD-13) Every index form and definition delivered is a `context.artefact.delivered` with `artefact_id = surface_id`; every call is its `activated`; compliance per profile is computable.
- AC-E3-8 (I-EPOCH) Under `freeze`, a `list_changed` from a source produces a `catalog.delta` event and no change to `catalog_id` or `configuration_version_id`; a call to a removed surface fails `SurfaceUnavailable`. Under `adopt`, the epoch event carries a `bundle_delta` whose new surfaces have compiled identities and `authority = unverified`.
- AC-E3-9 (T-LCD-14/15) A comparison of two exposure variants refuses to run without a `MatchSpec`; `selection_recall@need` on a hosted participant renders `n/a{observability}`.
- AC-E3-10 (T-LCD-02) The opacity report counts the discovery surface's description template and source listing as `Text` leaves attributable to the profile.
- AC-E3-11 (retrieval suite) Every C1 `catalog_index` variant passes `retrieval_eval` on the Stage-3 fixture with `recall@8 ≥` a pre-registered floor for the `exact_name` baseline queries and reports nDCG@k for the natural-language set; numbers are reported, not gated, except the exact-name floor.
