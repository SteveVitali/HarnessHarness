## Ontology terms

| term | definition | notes |
|---|---|---|
| control envelope | The Core kernel guard set that wraps every control-strategy variant: evaluates `EnvelopePolicy` at fixed enforcement points of the harness step and only stops, refuses, delays or tightens — never chooses an action, grants or widens. | Object level; distinct from *run envelope* (instrument level, WS-B1 lifecycle) and from *deterministic-envelope strategy* (WS-F1 `program` variant, CF-220). Home: WS-F2 |
| envelope policy (`EnvelopePolicy`) | The sealed MUST-data record that is the typed content of `ControlBoundary.guards`: `{budget_ref, stop_rules[], retry, timeouts, loop, output_validation, invariants, exhaustion, conditioned_rules[]}`; content-addressed; referenced from the run manifest as `envelope_policy_ref`. | Resolves OQ-051 for guards; lowered into `RuntimePlan/1` budget-envelope and stop-rule nodes |
| guard / guard verdict | A pure function of the durable ledger prefix and the policy evaluated at one enforcement point; returns `pass{reservation_id?, deadline?} \| respond{Observation, events[]} \| stop{StopReason, events[]}`. Two evaluations at the same `seq` yield the same verdict. | WS-F1's `envelope.check` is the driver-facing view (CF-229) |
| enforcement point | One of the six fixed positions on the harness step where guards run: G-PRE-CALL, G-INTERPRET, G-PRE-DISPATCH, G-POST-EFFECT, G-DECIDE, G-RESUME. | Order relative to `authorize`: before it for budget/loop/format, after it for retry eligibility and deadlines |
| stop reason (`StopReason`) | The closed HIR/1-dialect sum naming why a run or turn ended: `completed, budget_exhausted{budget_id, dimension}, context_exhausted, loop_detected, format_failure, invariant_violation, refused, cancelled{by}, infrastructure_failure{error_class}`; total projection onto ADR-0045 outcome classes; declared-lossy lowering to ACP/A2A. | Owned by WS-F2; neighbours' spellings are aliases (CF-224/-03/-07) |
| stop protocol / stop barrier / drain | The stop is a *barrier* event (`control.decision{kind: stop}`; no new `committed` or `model.call.requested` after it except grace/drain — INV-3) followed by a *drain* (children cancelled, pending permissions resolved `cancelled`, in-flight effects reach a terminal or `unknown`, grace call, reservations released) and only then `lifecycle.*.finished`. | ACP `session/cancel` and Codex TERM → grace → KILL precedents; `DrainReport` is the return value |
| loop key | `H(capability.semantic_id ∥ canonical(params via SurfaceArgMap))` — the identity under which repeated calls are compared; never the surface name. | T-LCD-10; batch operations across distinct targets are distinct keys |
| no-progress predicate | `same loop_key ∧ same Observation.version_id` for consecutive attempts — the one predicate shared by the F2 detector and the F1 driver guard. | Re-running tests after an edit changes the observation ⇒ not a loop |
| response ladder / loop nudge | The graded envelope response to a detector verdict, each rung once per run: `nudge` (a `definition`-authority context item with delivered/activated/followed events, `kind: loop_nudge`) → `deny` (typed refusal of the repeated call) → `stop{loop_detected}`. | OpenHands nudge-once, goose deny, gemini stop precedents; `loop_nudge_recovery_rate` metric |
| format failure | An output-validation failure of *form* at G-INTERPRET: `unparseable, unknown_surface, schema_violation, constraint_violation, precondition_violation, truncated, refusal, empty`; bounded by `max_format_failures` with `stop{format_failure}` on exhaustion. | Semantic correctness is WS-G1/G3, not a format failure |
| output validation policy / repair | `OutputValidationPolicy{mode ∈ {strict, repair_then_strict}, repairs ⊆ {json_repair, arg_coercion, trailing_text_strip}, max_format_failures, …}`; a *repair* is a closed-list, ledgered transformation of a rejected output (`repaired: true`), excluded from compliance metrics. | CF-227 |
| error class (`ErrorClass`) | The closed classification of a failed attempt that keys `RetryPolicy`: `transport_transient, rate_limited, server_overloaded, stream_idle, auth_expired, context_window_exceeded, invalid_request, content_policy, empty, timeout, executor_lost, sandbox_denied, cancelled`. | Gateway normalisation target (WS-C1); kernel marks some non-retryable |
| retry attempt / attempt delta | A retry keeps the scope id and increments `attempt_no` (INV-5); an *attempt delta* is a recorded change to the request between attempts (`transport, sampling_temperature, model_fallback(profile_ref)`), never silent. | ADR-0027 identity; OpenHands temperature, Codex transport-fallback precedents |
| scope deadline / hard max / extend on progress | `deadline(scope) = min(TimeoutPolicy[kind].hard_max, remaining time.* ceilings on the ancestor chain)`; `extend_on_progress` may extend up to but never beyond `hard_max`; expiry writes the kind-fixed typed terminal (never an exception). | MCP lifecycle rule; answers OQ-119 |
| state invariant (INV-1…INV-9) / invariant violation / quarantine | The closed mandatory set of pure predicates over ledger records the envelope checks at G-POST-EFFECT/G-DECIDE/G-RESUME; a violation appends `control.invariant.violated`, stops with `invariant_violation`, projects to `infrastructure_failure` and raises `security.audit.checkpoint{kind: quarantine}` — the run is not scored. | Consolidates ADR-0026/0027/0030/0031/0035/0040 guarantees; checker under test (AC-F2-03) |
| objective vs subjective stopping constraint | *Objective*: ceilings, deadlines, exact-repeat/no-progress loops, invariant violations, format-failure exhaustion — code-owned, unalterable by anything the model says. *Subjective*: `done`, `give up`, `ask` — owned by β (WS-F1) and measured. | Doc 2 §4 principle applied to termination; LoopTrap resistance (AC-F2-07) |
| exhaustion policy | `ExhaustionPolicy{per dimension → on_exhaustion ∈ {stop (default), escalate (attended only)}, grace}` — whether a hard ceiling ends the run or asks the principal to `amend` or stop. | goose "continue?" precedent; OQ-265 |
