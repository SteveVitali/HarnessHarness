## 1. Scope & boundary

This workstream decides **what a side effect *is* inside HarnessHarness, how its life is recorded, and what the runtime promises about it after crashes, retries, cancellations and stale workers.** Concretely it fixes: (i) the effect lifecycle as a state machine over typed events (`intent → authorized → prepared → committing → observed | unknown → compensated/reverted/abandoned`); (ii) the effect-class taxonomy (reversibility × repeat-safety × scope) and the delivery semantics the runtime promises per class; (iii) the idempotency-key, lease/fencing and compensation contracts; (iv) how effects bind to the run ledger's identifiers (by convention with WS-B1, which is being written concurrently); (v) how the security kernel (WS-H1) and approval policy (WS-H7) consume the reversibility classification (OQ-015).

It explicitly leaves to neighbours: the event taxonomy, ID minting and materialized-view mechanics (**WS-B1**; this dossier proposes the *effect* event family and ID *usage* conventions only); restart/checkpoint/wakeup orchestration and the recovery *procedure* that consumes `unknown` outcomes (**WS-B3**); snapshot/fork/replay of environments that makes the `reversible` class cheap (**WS-B4**, **WS-B5**); the executor that actually runs a tool in a sandbox and captures its effects (**WS-E5**); retry counts, backoff and budget envelopes (**WS-F2** — it *consumes* the effect class; it does not define it); capability typing and the reference monitor (**WS-H1**); approval UX and fatigue mitigation (**WS-H7**); the `Effect` IR entity's typed shape (**WS-A3** arbitrates; this dossier supplies the fields it must carry). Nothing here commits to a language, runtime, storage engine or framework; every contract is stated as operations/inputs/outputs/invariants/failure modes (T-LCD-12).

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**M1 — Effects are lost, duplicated, or partially applied at four boundaries, and every audited harness has code for at least one of them.** (i) *Cancellation mid-execution*: Codex aborts the dispatch task and injects a synthetic output, and the next turn's context tells the model "If any tools/commands were aborted, they may have partially executed" (`core/src/tools/parallel.rs` `handle_tool_call_with_source` select-on-cancel branch; `core/src/context/turn_aborted.rs` `INTERRUPTED_GUIDANCE`). OpenHands does the same on pause (`local_conversation.py::_emit_orphaned_action_errors`: "Tool call interrupted before completion"). (ii) *Process death between dispatch and observation*: OpenHands' agent-server rewrites `RUNNING → ERROR` on load and backfills an `AgentErrorEvent` for the first unmatched action — "A restart occurred while this tool was in progress … did not complete" — explicitly noting the process "may have died between writing an event file and persisting the advanced HEAD" (`agent_server/event_service.py` ~L1157–1200). Codex's history normalizer inserts synthetic `"aborted"` outputs for any call without an output on resume (`context_manager/normalize.rs`). (iii) *Retry re-executes a partially executed command*: Codex's orchestrator runs a command under the sandbox, and on `SandboxErr::Denied` (a runtime denial, i.e. the process already ran and failed) re-runs the *same* command unsandboxed after approval (`core/src/tools/orchestrator.rs` "Second attempt") — a first-attempt partial write followed by a full second run is a duplicate-side-effect path by construction. (iv) *Replay of unobserved actions*: OpenHands' `Agent.step()` treats any `ActionEvent` without an observation as "pending" and executes it ("Confirmation mode: Executing N pending action(s)", `agent/agent.py` L644–650; `state.py::get_unmatched_actions`); if the agent-server's restart backfill did not run (e.g. the SDK used directly), an action whose effect happened but whose observation was lost is re-executed. The 2026 preprint S-WS-B2-08 names exactly this class ("timeouts after dispatch, delayed visibility, partial state updates") — mechanism corroborated by production code, so admissible; its numbers stay `provisional`.

**M2 — Exactly-once *effect* is not achievable by the runtime alone; effectively-once requires the executor or target to deduplicate.** Helland (S-WS-B2-03) and Stripe (S-WS-B2-04) establish the pattern: the caller mints a stable key, the receiver stores the first outcome and replays it. Temporal's operational contract is the same: activities are retried by default and "we recommend that it be idempotent"; only *heartbeat details* let a retry resume rather than restart (S-WS-B2-05). None of the three audited harnesses passes an idempotency key to a tool executor today; Symphony pushes the obligation to adapters ("any provider-side idempotency … expectations" must be documented, SPEC §10.5). Hence the runtime can promise **at-least-once dispatch + dedup-by-key when supported**, and must promise **at-most-once dispatch** where dedup is unsupported and the effect is not repeat-safe.

**M3 — Leases with fencing generations are the established way to bound stale workers, and one agent harness already implements them.** Gray & Cheriton (S-WS-B2-02): a lease is a time-bounded contract; "short lease terms … minimize the delay resulting from client and server failures"; correctness assumes clocks are not Byzantine. OpenHands' agent-server has a per-conversation ownership lease with `owner_instance_id`, a monotonically increasing `generation`, `expires_at` (TTL 45 s, renewal ≤ 15 s), `guarded_write(generation)` that refuses writes after a takeover, and takeover from a dead owner (`agent_server/conversation_lease.py`). Symphony's claim set + stall timeout (`SPEC.md` §7.1, §8.5) is a lease without a fencing token (safe only because a single orchestrator process is the sole mutating authority, §7.4). Temporal's Start-To-Close timeout "force[s] Activity retries" after a worker crash — the lease term *is* the recovery bound (S-WS-B2-05).

**M4 — Compensation is semantic, must be idempotent, and cannot cover every effect.** Sagas (S-WS-B2-01): compensation "will restore the world to a state which is an acceptable approximation", not the original state; the coordinator must "record checkpoints and compensations reliably". Revisable-by-Design (S-WS-B2-09, `provisional (mech)`) proves conflicting irreversible actions make specification satisfaction impossible regardless of algorithm — the classification is a property of the action space. Shepherd (S-078) concedes that reverting the trace does not undo external effects. RAC (S-WS-B2-07) shows log-based compensation can be bolted on framework-agnostically (mechanism admissible; gains `provisional`).

**M5 — Reversibility classification is already consumed by approval policy in two harnesses, but the *source* of the classification is heterogeneous and partly model self-reported.** OpenHands: `SecurityRisk{UNKNOWN, LOW, MEDIUM, HIGH}` with `UNKNOWN` deliberately incomparable and `ConfirmRisky(threshold=HIGH, confirm_unknown=True)`; the risk value is *supplied by the model* as a `security_risk` argument (only honoured when an analyzer is configured; suppressed for `readOnlyHint` tools) — `security/risk.py`, `security/confirmation_policy.py`, `agent/agent.py::_extract_security_risk`, `tool/tool.py` L704–709. Codex: `SafetyCheck{AutoApprove, AskUser, Reject}` decided from writable-root containment of a parsed patch and the sandbox availability (`safety.rs::assess_patch_safety`), an exec-policy rule engine, and a session-scoped approval cache keyed by canonicalised action (`sandboxing.rs::with_cached_approval`, `ReviewDecision::ApprovedForSession`). MCP annotations carry `readOnlyHint / destructiveHint / idempotentHint / openWorldHint` but the spec itself says clients "should never make tool use decisions based on `ToolAnnotations` received from untrusted servers" (S-153). ACP's `ToolKind` is a display vocabulary, not a safety class (S-035).

**M6 — Two structurally different recovery philosophies coexist in production and both work.** *Event-sourced*: Managed Agents (S-047) `emitEvent/getEvents/wake(sessionId)`; Logos (S-073) transcript "owned by no process"; Cursor (S-052) durable workflow engine with client-side stream *rewind* on retried steps. *Reconciliation against an external source of truth*: Symphony (S-108) keeps no durable scheduler state and recovers by re-polling the tracker and re-using preserved workspaces (§14.3). The effect model must support both: an authoritative `committing` record (event-sourced) *and* a `probe` operation that reconciles an `unknown` outcome against the environment (reconciliation).

**M7 — Detached processes outlive the effect that spawned them.** Codex's unified exec keeps background terminals alive across turn abort ("Any running unified exec processes may still be running in the background", `turn_aborted.rs`; `unified_exec/process_manager.rs` "turn cannot drop the last Arc and terminate the background process"). Cancellation of an effect therefore does not imply cessation of its side effects; the model must be told, and the ledger must record a detached child effect.

### 4b. Performance evidence (benchmark lifts) — each tagged `provisional` if 2026 single-team/preprint

- S-WS-B2-08 (Verified Tool Calls): "significantly reduces duplicate actions, while maintaining comparable task success rates" in a *simulated* environment — `provisional`; not load-bearing.
- S-WS-B2-07 (RAC, accepted ACM CAIS 2026): 1.5–8× latency/token improvement over LLM-driven recovery on τ-bench/REALM-Bench — `provisional` (single team; budget-matching unclear).
- S-073 (Logos): "eighty sessions terminated at four points of the tool-call cycle all resumed with no repeated action" — `provisional`; note this is a *no-replay* result (the resumed session does not re-issue the call), not evidence of dedup under retry.
- S-052 (Cursor): "two 9s of reliability" after moving to a durable-execution engine; > 50 M actions/day — production, vendor-reported, no baseline; mechanism only.
- S-WS-B2-09 (Revisable by Design): "quality matching a brute-force baseline while wasting an order of magnitude fewer steps" — `provisional`; the *theorem* is used here, not the number.
- No C0 decision below depends on any of these numbers.

## 5. Disconfirming evidence & negative results

- **Against a runtime-owned lifecycle at all (R1):** Managed Agents (S-047) deliberately does *not* model effects: "If the container died, the harness caught the failure as a tool-call error and passed it back to Claude … If Claude decided to retry, a new container could be reinitialized." Symphony likewise keeps scheduler state in memory and lets the tracker be the truth. Both are production systems at scale. *Why it does not overturn:* both operate on **workspace-local, reversible or reprovisionable** effects (containers, branches, tickets that the agent re-reads). Neither claims safety for external irreversible effects, and Symphony explicitly pushes idempotency to adapters. The lifecycle below costs nothing for read-only effects and is exactly the machinery those systems lack when an effect leaves the sandbox.
- **Against write-ahead `committing` records (R2):** none of the three audited harnesses writes a durable record *before* dispatch as a barrier; Codex emits `ExecCommandBegin` as an event but does not fsync-gate dispatch on it, and OpenHands' own comments describe the process dying "between writing an event file and persisting the advanced HEAD". A write-ahead barrier adds a durable write to every non-read-only tool call (latency; storage). *Why it does not overturn:* without the barrier the recovery procedure cannot distinguish "never dispatched" from "dispatched, outcome unknown", which is the whole point for compensable/irreversible classes; the barrier is skipped for read-only effects (§6), and WS-B1's storage class decides the cost.
- **Against per-class delivery semantics (R3):** exactly-once is impossible in general (Helland, S-WS-B2-03), and dedup keys only help if the executor or target honours them; for shell commands there is no target to honour a key. *Accepted:* the spec therefore promises *effectively-once* only where `dedup_support ≠ none`, and *at-most-once dispatch* otherwise; the contract is honest about the gap rather than papering over it.
- **Against classification-driven approval (R4):** reversibility of an arbitrary shell command is undecidable; Codex relies on parsed-command heuristics and writable-root containment, OpenHands on a model-predicted `security_risk` (self-report, gameable by injection), MCP annotations are untrusted hints (S-153). Conservative defaults (unknown ⇒ irreversible) raise prompt volume, and Anthropic's telemetry shows users approve ~93 % of prompts (S-053) — approval fatigue undermines the safety value. *Why it does not overturn:* the classification is still the only input a deterministic kernel can act on; the mitigation is (a) `effective_class = max(kernel-assessed, declared)` with model self-report never lowering the class, (b) scope narrowing (sandbox + writable roots make most edits `reversible`), and (c) WS-H7 owns fatigue mitigation (session-scoped caches as in Codex).
- **Against compensation as a runtime primitive (R5):** Sagas guarantees only an "acceptable approximation"; compensators can themselves fail or be irreversible; Revisable-by-Design shows conflicting irreversible actions are unrecoverable by any algorithm. *Accepted:* compensation is a *best-effort, audited* mechanism with an `abandoned` terminal state; it never lets an irreversible effect be reclassified as safe.
- **Against leases (R6):** leases assume bounded clock drift (S-WS-B2-02); a paused-but-alive worker (GC pause, VM hibernation — Cursor S-052 hibernates VMs deliberately) can wake after expiry and act on stale authority. *Why it does not overturn:* this is exactly why the fencing generation (OpenHands precedent) is mandatory: expiry alone is insufficient; every commit record carries the generation and the store rejects stale ones.
- **Negative result (N1):** the "no repeated action" claim in Logos (S-073) is achieved by *not re-issuing* the interrupted call, not by deduplicating a retried one — it does not evidence dedup under retry. **N2:** no audited harness passes idempotency keys to external tools; the "industry pattern" claims in S-WS-B2-10 are unsourced. The key contract below is therefore `no-precedent / novel` *as an integrated harness contract* relative to Stripe/Temporal-style precedents at the API layer.

## 6. Recommendation for the spec

### 6.1 Effect lifecycle state machine (C0 / Stage 1)

An **effect** is the runtime's unit of side-effect accounting: one attempt-independent identity (`effect_id`) for one semantic action the harness intends to perform on an environment or the outside world. One model tool call (`call_id`, a surface identifier) yields one or more effects (a code-mode cell or a multi-file patch may fan out; `parent_effect_id` links them).

States and the event that enters each (event names are proposals for WS-B1's taxonomy; WS-B1 owns final names):

| state | entering event | written by | invariant on entry |
|---|---|---|---|
| `intended` | `EffectIntended{effect_id, call_id, step_id, turn_id, run_id, capability_id, args_canonical_hash, declared_class, parent_effect_id?}` | runtime, on parsing the model's call | `effect_id` minted deterministically from `(run_id, step_id, call_id, ordinal)`; never re-minted on retry |
| `authorized` / `refused` | `EffectAuthorized{effect_id, effective_class, scope, decision_source ∈ {policy, cache, approval, hook}, approval_id?, capability_grant_id}` / `EffectRefused{effect_id, reason, decision_source}` | security kernel (WS-H1) + approval (WS-H7) | `effective_class ≥ kernel_assessed_class`; `refused` is terminal and is surfaced to the model as a refusal observation |
| `prepared` | `EffectPrepared{effect_id, env_handle_id, lease_generation, idempotency_key, baseline_ref?, compensation_plan_id?, resource_keys[]}` | runtime | all inputs pinned; `baseline_ref` mandatory for class `reversible`; `compensation_plan_id` mandatory for class `compensable`; resource keys acquired |
| `committing` | `EffectCommitStarted{effect_id, attempt_no, lease_generation, dispatched_at}` | runtime, **durably before dispatch** | write-ahead: no executor dispatch may precede this record's durability for any class other than `read-only` |
| `observed` | `EffectObserved{effect_id, attempt_no, outcome ∈ {applied, not_applied, partial}, exit_status, output_artifact_ids[], postcondition_results[], detached_effect_ids[], cost}` | executor (WS-E5) via runtime | exactly one `observed` per `(effect_id, attempt_no)`; `partial` is allowed only for classes that can express partial application (patches, multi-step) |
| `unknown` | `EffectOutcomeUnknown{effect_id, attempt_no, cause ∈ {cancelled, lease_expired, worker_lost, timeout, executor_error}}` | runtime or recovery (WS-B3) | must be followed by `probe` or a policy decision; never silently dropped; the model receives an explicit "may have partially executed" observation |
| `probed` | `EffectProbed{effect_id, attempt_no, verdict ∈ {applied, not_applied, undeterminable}, evidence_artifact_ids[]}` | executor/verifier | verdict `applied`/`not_applied` transitions to `observed`; `undeterminable` returns to `unknown` with `probe_count+1` |
| `compensated` / `reverted` | `EffectCompensated{effect_id, compensating_effect_id}` / `EffectReverted{effect_id, baseline_ref, revert_effect_id}` | runtime (saga coordinator, C1) / snapshot service (B4/B5) | compensating/revert effects are themselves effects with their own lifecycle and `compensates`/`reverts` edges |
| `abandoned` | `EffectAbandoned{effect_id, reason, escalation_id}` | policy / human | terminal; blocks any "task complete" claim that depends on the effect (feeds WS-G2 execution alignment); always audited (WS-H6) |

Terminal states: `refused`, `observed(applied | not_applied)`, `compensated`, `reverted`, `abandoned`. Non-terminal: `intended`, `authorized`, `prepared`, `committing`, `unknown`, `probed(undeterminable)`.

Global invariants (acceptance-checkable):
1. **No dispatch without durability.** For every class except `read-only`, `EffectCommitStarted` is durable before the executor receives the request.
2. **Every commit resolves.** Every `EffectCommitStarted` is eventually followed by exactly one terminal event for that `effect_id`; liveness is guaranteed by the lease: on lease expiry the recovery procedure (WS-B3) emits `EffectOutcomeUnknown` for every effect in `committing`.
3. **Retries share identity.** A retry is `attempt_no + 1` on the same `effect_id`; the idempotency key is a function of `effect_id`, never of `attempt_no`.
4. **No blind redispatch.** An effect in `unknown` may be redispatched only if `effective_class.repeat_safe = idempotent` or a `probe` returned `not_applied`. Irreversible effects are never automatically redispatched (see §6.2).
5. **The model always sees a terminal or an explicit `unknown`.** No `intended` effect is ever absent from the model-facing history without a refusal, observation or "unknown/partial" record (Codex `normalize.rs`; OpenHands `_emit_orphaned_action_errors`).
6. **Stale writers are fenced.** Every lifecycle event after `prepared` carries `lease_generation`; the ledger rejects an event whose generation is lower than the current generation for that run/effect scope.
7. **Compensation is itself an effect** of class no more dangerous than the original and is idempotent (running it twice has no additional effect).
8. **Detached children are recorded.** An executor that leaves a process/job running after `observed` or `unknown` must report `detached_effect_ids[]`; each detached child is an effect in `committing` under the same lease.

### 6.2 Effect-class taxonomy and delivery semantics per class (C0 / Stage 1)

Three orthogonal attributes, carried on the `ToolCapability` (declared by the tool author, WS-E1) and re-assessed per effect by the kernel (WS-H1):

- **reversibility ∈ {read-only, reversible, compensable, irreversible}** — read-only: no world change; reversible: a captured baseline can restore the prior state mechanically (file edits inside a snapshot-able workspace, git-tracked changes, VM checkpoints); compensable: no mechanical undo but a registered compensator semantically undoes it (open PR → close PR; create ticket → close ticket; reserve → release); irreversible: neither (send message, payment, publish, delete without backup, exfiltrate).
- **repeat-safety ∈ {idempotent, non-idempotent}** — whether re-execution with the same canonical arguments has no additional effect (MCP `idempotentHint` semantics).
- **scope ∈ {workspace-local, external}** — inside an environment handle (WS-B5) the runtime can snapshot/discard, or the open world (MCP `openWorldHint`).

`effective_class = max_by_danger(kernel_assessed, declared)` with `unknown` treated as `{irreversible, non-idempotent, external}`. Model-supplied risk annotations (OpenHands `security_risk` precedent) may *raise* but never *lower* the class. Declared hints from untrusted tool servers never lower it either (S-153).

| effective reversibility | dispatch semantics | on `unknown` | approval default (consumed by WS-H7; overridable by policy) | compensation / revert |
|---|---|---|---|---|
| read-only | at-least-once; free retry; no write-ahead | redispatch | auto | none |
| reversible (workspace-local) | at-least-once; effectively-once by *revert-and-redo* when a baseline exists, else by dedup key | probe by diffing against `baseline_ref`; if undeterminable, revert to baseline and redispatch | auto inside sandbox with writable-root containment (Codex `assess_patch_safety` precedent); ask outside | mechanical revert (B4/B5) |
| compensable | at-most-once dispatch per attempt with **mandatory idempotency key**; effectively-once iff executor/target `dedup_support ≠ none` | probe postcondition first ("verify-before-retry"); `not_applied` → retry same key; `applied` → observed; `undeterminable` → escalate after `max_probes` | auto iff a compensation plan is registered and the capability grant covers it; otherwise ask | run compensator (C1 saga coordinator); failure → `abandoned` |
| irreversible | at-most-once dispatch, **no automatic retry ever**; idempotency key passed to target when supported | never redispatched automatically; `unknown` is escalated with evidence to approval/human; `probe` allowed if read-only | **ask**, per-effect approval record with approver identity; session-scoped cache allowed only when the approval scope is a canonical action pattern (Codex `ApprovedForSession` precedent), never a bare call id | none — only `abandoned` or human resolution |

Repeat-safety modifies the row: an `idempotent` compensable/irreversible effect may be redispatched from `unknown` without a probe. Scope modifies approval: `external` raises the default one step (reversible-external ⇒ treated as compensable for approval).

The spec must state the promise honestly: **"at-least-once dispatch with deduplicated execution ⇒ effectively-once"** where `dedup_support ∈ {executor, target}`; **"at-most-once dispatch"** where `dedup_support = none` and the class is not repeat-safe. There is no "exactly-once effect" claim anywhere in the spec.

### 6.3 Contracts (language-agnostic)

**Effect store / ledger (projection over WS-B1 events)**
- `begin_effect(intent: EffectIntent) → effect_id` — idempotent for the same `(run_id, step_id, call_id, ordinal)`.
- `authorize(effect_id, decision: KernelDecision) → authorized | refused` — failure: `CapabilityMissing`, `PolicyDenied`, `ApprovalTimedOut` (Codex `ReviewDecision::TimedOut` precedent; timeout is a refusal, not an `unknown`).
- `prepare(effect_id, env_handle_id, lease) → PreparedEffect{idempotency_key, baseline_ref?, compensation_plan_id?, resource_keys[]}` — failure: `BaselineUnavailable` (for `reversible` this *downgrades* the class to `compensable` or `irreversible`, never proceeds silently), `CompensatorMissing`, `ResourceLockTimeout`.
- `commit(effect_id, attempt_no, lease_generation) → CommitToken` — durable before return; failure: `StaleLease` (fenced), `NotPrepared`.
- `observe(commit_token, outcome: Observation)`; `mark_unknown(effect_id, attempt_no, cause)`; `probe(effect_id) → ProbeVerdict`; `compensate(effect_id) → compensating_effect_id`; `revert(effect_id) → revert_effect_id`; `abandon(effect_id, reason, escalation_id)`.
- `effect_state(effect_id) → EffectRecord` (materialized view); `effects_in_state(run_id, state)`; `rebuild_from_events(run_id)` must equal the view (acceptance test).

**Idempotency-key contract**
- `idempotency_key = H(run_id, effect_id, canonical(args), capability_version)` — a stable content hash over *durable* state (Stripe/S-WS-B2-10 pattern); identical across restarts and attempts; canonicalisation per OQ-041 (WS-A3/B1).
- Executors declare `dedup_support ∈ {none, executor, target}` and `dedup_window` in their capability declaration; when `executor`, the executor keeps `(key → Observation)` for the window and returns the stored observation on repeat (Stripe replay); when `target`, the key is forwarded in the target's own idempotency slot (protocol lowering, WS-A4/E4, carried through `_meta`-style extension slots per T-LCD-11).
- Invariant: a repeated `commit` with the same key never yields a second `applied` observation with a different `output_artifact_ids` set when `dedup_support ≠ none`.

**Lease contract**
- `acquire(scope ∈ {run, effect, resource:<key>}, holder_id, ttl) → Lease{generation, expires_at}` — generation strictly increases per scope on every takeover (OpenHands `conversation_lease.py` precedent).
- `renew(lease) → Lease` (heartbeat; may carry a progress payload that a successor can read — Temporal heartbeat-details precedent); `release(lease)`.
- `guard(lease, write)` — rejects with `StaleLease` if `generation` is not current. Every post-`prepared` event carries the generation (invariant 6).
- Expiry policy: `ttl` short enough to bound recovery (S-WS-B2-02), renewal at ≤ ttl/3; expiry triggers WS-B3 recovery which marks in-flight effects `unknown`; clock assumption stated explicitly (non-Byzantine; monotonic clocks for local TTLs). Resource-scoped leases are the intra-worker locks of OpenHands' `ResourceLockManager` (sorted acquisition, per-prefix timeouts) generalised to lease semantics.

**Compensation contract (schema C0 / Stage 1; coordinator C1 / Stage 2)**
- `CompensationPlan{plan_id, effect_id, compensator: EffectIntentTemplate, preconditions[], idempotent: true, expires_at?, owner}` registered at `prepare`; the compensator template is a capability the kernel can authorise *now* (a compensable effect is not authorised if its compensator would be refused).
- `compensate_run(run_id | branch_id)` executes compensators in reverse commit order for effects in `observed(applied)` that are marked for undo (run abort, branch discard from WS-B4, approval revocation), each as a new effect with edge `compensates`; a failed compensator yields `abandoned` + escalation; compensators are idempotent so re-running a crashed saga is safe (S-WS-B2-01).

**Kernel/approval consumption (OQ-015 answer for WS-H1/H7)**
- Input to the kernel decision: `{declared_class, kernel_assessed_class, scope, resource_keys, capability_grant, approval_cache}`; output `KernelDecision{effective_class, allow | ask | deny, reason, cache_key?}`.
- `kernel_assessed_class` sources, in precedence: static capability metadata (WS-E1) → deterministic argument analysis (path containment, parsed command classes — Codex `safety.rs`/exec-policy precedent; network host policy) → hooks → *model self-report last and only upward*.
- Approval decisions are cached by `cache_key = H(canonical action pattern, scope)` with session/run lifetime (Codex `ApprovedForSession`), never by `effect_id`; a cached approval is recorded as `decision_source = cache` with the originating `approval_id` for audit (WS-H6).

### 6.4 Data-model sketch (fields the `Effect` IR entity must carry — for WS-A3)

`Effect{effect_id, run_id, turn_id, step_id, call_id, parent_effect_id?, capability_id, capability_version, args_canonical_hash, declared_class{reversibility, repeat_safety, scope}, effective_class, scope, state, attempt_no, lease_generation, idempotency_key, env_handle_id, baseline_ref?, compensation_plan_id?, resource_keys[], approval_id?, decision_source, outcome?, output_artifact_ids[], postcondition_results[], detached_effect_ids[], compensating_effect_id?, revert_effect_id?, cost{tokens?, wall_ms, env_ms}, provenance{origin, authority, version}}`. Edges: `produced-by` (effect → call/step), `authorizes` (capability grant → effect), `compensates`, `reverts`, `parent-of` (fan-out / detached). Every large output is an artifact reference, never inline (doc 2 §11 "event sourcing selectively").

**ID binding convention (to agree with WS-B1):** `run_id ⊃ turn_id ⊃ step_id ⊃ call_id` are the ledger's structural ids; `effect_id` is minted by the runtime (not the model, not the tool) and is the *semantic* identity that survives attempts, resumes and hosting; `event_id`s are per lifecycle event; `lease_generation` is a ledger-level field on every event written by a worker; `env_handle_id` (WS-B5), `artifact_id` (content-addressed, WS-L4), `approval_id` (WS-H7), `capability_grant_id` (WS-H1). Hosted participants (ADR-0005/0010) map their tool-call statuses (ACP `pending/in_progress/completed/failed`) onto `intended/committing/observed/observed(not_applied)`; the classes they cannot declare stay `unknown` (never coerced — T-LCD-07), and no native contract changes for them (T-LCD-06). `participant_class` and `observability_level` ride on every effect event per phase-0 §5.5.

### 6.5 Acceptance-criteria sketch (duplicate-side-effect-after-retry tests are mandatory)

- **AC-B2-01 Duplicate-after-retry, per class.** Fault injection kills the worker (a) after `prepared`, (b) after `committing` before dispatch, (c) after dispatch before `observed`, (d) after `observed` before the ledger append — for a read-only, a reversible, a compensable (with an external counter) and an irreversible probe tool. Expected: read-only re-executes; reversible ends in a state equal to a single execution; compensable ends with external counter = 1 and the second attempt returns the stored observation (`dedup_support = executor`) or is escalated (`none`); irreversible is *never* redispatched, ends in `unknown → escalation`, and the model-facing history contains an explicit "may have partially executed" observation.
- **AC-B2-02 Fencing.** Two workers hold successive generations for one run; the older worker's `commit`/`observe` after takeover is rejected with `StaleLease` and appears in the audit trail; no effect has two `applied` observations.
- **AC-B2-03 No dangling intent.** After any interruption (cancel, timeout, crash) the reconstructed model-facing history has a terminal or `unknown` record for every `intended` effect (Codex `normalize.rs` behaviour as a conformance test).
- **AC-B2-04 Compensation idempotence and order.** Aborting a run with effects E1..E3 applied runs C3, C2, C1; re-running compensation after a crash mid-saga produces no additional external effect; a failing compensator yields `abandoned` with an escalation event.
- **AC-B2-05 Classification monotonicity.** A tool declaring `readOnlyHint = true` whose arguments the kernel assesses as writing outside writable roots is executed as `compensable/irreversible`; a model-supplied "LOW" never lowers a kernel-assessed "HIGH"; `unknown` class requires approval under the default policy.
- **AC-B2-06 Replay equivalence.** `rebuild_from_events(run_id)` equals the effect view for every run in the Stage 3 suite, including runs with takeovers and compensations.
- **AC-B2-07 Key stability.** The idempotency key for an effect is byte-identical before and after a process restart and across attempts, and differs for a semantically different argument set.
- **AC-B2-08 Detached effects.** Cancelling a tool that spawned a background process yields a `detached` child effect; killing the run terminates or marks it `unknown`; the model is told.
- **AC-B2-09 Hosted mapping.** A hosted participant's tool-call status stream maps onto the lifecycle without adding a field to any native entity (T-LCD-06); undeclared classes are reported as `unknown`, not `read-only` (T-LCD-07).

### 6.6 Build-stage suggestion

- **C0 / Stage 1:** effect event family and state machine; `effect_id`/key derivation; write-ahead `committing`; `unknown` + `probe` operations; run-scoped lease with generation fencing; class attributes on `ToolCapability` and `effective_class` in the kernel decision; approval defaults per class; static acceptance checks AC-B2-03/05/07.
- **C1 / Stage 2:** compensation coordinator (saga execution, reverse order, idempotent re-run); resource-scoped leases with progress payloads; executor-side dedup store; AC-B2-04.
- **C2 / Stage 2–3 (with WS-B4/B5):** mechanical revert from `baseline_ref` (workspace snapshots, git, VM checkpoints); revert-and-redo for the reversible class.
- **Stage 3 (evaluation-first):** the fault-injection battery AC-B2-01/02/06/08 runs in the Stage 3 suite with `search_budget`/`eval_budget` recorded (T-LCD-14); duplicate-effect count and `abandoned` count become class-scoped process metrics (WS-I2, `requires_observability ⊇ {events}`).
- **Deferred:** target-side idempotency forwarding per protocol (WS-E4, Stage 4); hosted-participant mapping (WS-J6, Stage 4).

## 10. Confidence

**High** for the mechanism findings and for the lifecycle/lease/fencing/at-most-once-for-irreversible decisions: they rest on Tier-A classic results (Sagas, Leases, Helland), Tier-B production write-ups (Temporal, Stripe, Cursor, Managed Agents) and direct source reading of three harnesses at pinned commits that independently converge on the same failure modes and on two of the three mechanisms (synthetic terminal records; generation-fenced leases). **Medium** for the per-class approval defaults and the compensation coordinator: precedent exists for class-keyed confirmation (OpenHands, Codex) but every production classifier is heuristic and approval-fatigue evidence (S-053) is real; compensation as an integrated runtime primitive has only 2025–2026 preprint precedent in the agent setting (`provisional`), so it is C1 not C0. **Low** on any quantitative claim about duplicate-reduction rates — all `provisional` and none load-bearing.
