## 1. Scope & boundary

This workstream decides **what an execution environment *is* to the reference runtime and how the runtime holds it**: (i) the **environment handle** — a kernel-owned runtime record for one environment *instance* that is never the harness process and never lives inside it; (ii) the handle **lifecycle state machine** (`provision → attach → ready ⇄ suspended → detached/unreachable → replaced | torn_down`) with self-heal defined as *replacement*, not repair; (iii) the **effect-operation surface** — the narrow, typed, effect-domain-tagged operations a handle exposes, and the rule that every one of them is reached only through the WS-E5 execution contract; (iv) **environment classes** (local host, local helper-sandboxed, local container, remote ephemeral, remote persistent, provider hosted) and their declared, tri-state capability records; (v) the three **identity layers** — definition (`EnvironmentRecord`, content-addressed; the `environment_ref` factor coordinate), instance (`env_handle_id`, allocated), state (`SnapshotRef`, content-addressed) — and snapshot/restore semantics; (vi) the seams the handle *carries* for neighbours: the containment slot (WS-H4), credential bindings (WS-H3), resource limits and meters (WS-L2), workspace derivation for subagents (WS-F3) and experiment replicates (WS-J3/I4); (vii) the final WS-B5 half of OQ-045 and the answers to OQ-089, OQ-095, OQ-118.

It explicitly leaves to neighbours: the per-effect execution stages, `ExecutionRequest`, capture, timeouts, detached children and the helper *protocol minimum* (**WS-E5** — this dossier adopts its verb list and adds the lifecycle verbs); the containment policy record, `effective()` meet, egress mediation and enforcement evidence (**WS-H4** — adopted as the handle's `containment` slot, CF-134 accepted); the credential broker and placeholder discipline (**WS-H3** — `env_apply`/`env_snapshot` obligations adopted); restart/wakeup/checkpoint orchestration and the recovery *procedure* that consumes `unknown` (**WS-B3** — this dossier fixes what the handle guarantees across a kernel restart and what a replacement costs); fork/replay/counterfactual semantics over snapshots (**WS-B4** — this dossier fixes snapshot identity and kinds; B4 decides when to take them and how to branch); the reference monitor and Π (**WS-H1**); subagent topology and merge policy (**WS-F3** — this dossier fixes the `derive` operation and the isolation modes); benchmark environment images and task setup (**WS-I4**); experiment provisioning cadence (**WS-J3**); the bundle format (**WS-I3** — the `EnvironmentRecord` member is fixed here per ADR-0038); resource dimension custody (**WS-L2** — this dossier supplies the `env.*` measurement points). Nothing here names a language, runtime, package or framework; every precedent path is evidence, not a dependency (ADR-0050 §8).

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Two placements of the harness process exist in production, and only one keeps the trusted computing base outside the blast radius.** *Harness-outside:* Managed Agents' "the harness leaves the container" (S-047) with containers "called … the way it called any other tool"; Cursor's agent loop on a durable-execution engine driving dedicated VMs (S-052); Codex's `EnvironmentManager` in the kernel process holding *connections* to exec-servers that run locally or inside a remote environment, with the model-facing shell/filesystem tools available only when `default_environment().is_some()` (`exec-server/src/environment.rs` L73–90). *Harness-inside:* OpenHands' `RemoteWorkspace` is a thin HTTP client to an **agent server that runs the whole conversation inside the container** (`docker/workspace.py` runs the `agent-server` image; `remote/base.py` `get_llm`/`get_secrets`/`register_conversation` are calls *into* the box; `_get_secret_value` fetches raw secret values over that channel); Harbor's `container-installed` agents likewise run inside the task container (WS-A1). The inside placement puts the ledger writer, the permission decision, the credential value and the model gateway credential inside the environment the model controls — exactly what ADR-0026 (authoritative ledger), ADR-0035 (monitor reads records only), WS-H3 SV-4 (value-free environments) and doc 2 §5.6 forbid. Managed Agents' stated payoff is the same as ours: "Because the session log sits outside the harness, nothing in the harness needs to survive a crash", and containers become "replaceable infrastructure". **Implication:** the native runtime is *always* harness-outside; the environment is a handle the kernel holds, and "harness-inside" survives only as a hosted participant's mechanism (`container-installed`, ADR-0005/0013) where the ledger already expects reduced observability.

**F2 — Every audited system separates a *stable environment identity* from a *connection/session* and from *instance state*, and the ones that conflate them pay in recovery.** Codex: `Environment IDs have stable identity and contents. This process-local value must not be persisted: it only keeps the current connection handle alive while one model step uses the stable environment` (`resolved_capability.rs` L13–17); `EnvironmentObservedStatus` is computed "without starting a connection" and a `Failed` status "does not promise that the failure is terminal" (`environment.rs` L110–131); sessions are resumable with `resume_session_id` inside a 30-second server retention window (`client_recovery.rs` L59–62) and refuse double attachment (`SESSION_ALREADY_ATTACHED`). OpenHands cloud keeps a `sandbox_id` "to resume the existing sandbox instead of creating a new one" and treats `PAUSED` as resumable (`cloud/workspace.py` L144–150, L382–385). Harbor separates `session_id` (ephemeral handle), `context_id` (durable trial id) and `environment_id` (content hash of the environment definition + image) (`environments/base.py` L92–110, L231–242). E2B's identifier "persists across pause/resume cycles" (S-482). Symphony keys workspaces by a collision-resistant `workspace_key` derived from the issue and preserves them across runs (S-108 §4.1.4). **Implication (three identity layers, §6.3):** definition identity (content-addressed record — the experimental factor), instance identity (allocated handle id — the runtime object), state identity (content-addressed snapshot — what the filesystem/memory *is* at a moment). No audited system has all three with content addressing on the first and third; Harbor comes closest and still records the image as a mutable tag (WS-L4 F3 negative).

**F3 — Self-healing in production means *replacement from a recipe*, never repair of a sick instance; and replacement is only safe because state that matters lives outside.** Managed Agents: `provision({resources})` + "reinitialized with a standard recipe"; "We no longer had to nurse failed containers back to health"; if the container died mid-call "the harness caught the failure as a tool-call error and passed it back to Claude" (S-047; WS-B2 M6). Cursor: "prewarmed VMs", checkpoint/restore/fork pipelines, hibernate/resume "between messages" (S-052). Codex: a provisioning report "can recover a failed provisioning attempt" only by a later `Ready` report, and connection recovery retries within a bounded window then fails all in-flight work (`client_recovery.rs` `fail_all_in_flight_work`). Inspect separates "the sandbox is not running" (`SandboxUnavailableError`) from a failed command so the model is never told a provider outage was its command's output (`environment.py` L38–52). **Implication:** the handle lifecycle has an explicit `unreachable` state with a bounded reattach window, after which the only transitions are `resume` (if suspended), `replace` (new instance from the last snapshot or the image) or `fail`; every replacement changes the instance id, keeps the definition id, marks in-flight effects `unknown` (ADR-0030), and is followed by a **world-state discontinuity** record because the new instance's filesystem is not the old one unless restored from a byte-identical snapshot.

**F4 — Snapshot semantics differ by kind, and the differences are semantic, not implementation detail.** Modal distinguishes *filesystem* snapshots (delta from base image; usable as an image; forkable), *memory* snapshots ("exact clone … all running processes will still be running"; TCP connections closed; not while an exec is running; 7-day expiry) and *directory* snapshots (mountable) (S-483). E2B pause preserves memory by default, `keepMemory: false` for filesystem-only; pause costs ≈ 4 s/GiB (S-482). Shepherd forks the agent and environment "atomically" on a copy-on-write layer with image-size-independent cost and byte-identical restoration on discard (S-078, `provisional`). Codex snapshots *shell state* (exported environment + state up to 512 KiB, keyed by attachment `scope_id`, bounded cache of 16) — a fourth kind, executor-owned and non-authoritative (`shell_snapshot.rs` L36–46). Cursor checkpoints whole VM images (S-052). opencode stores workspace snapshots as git objects; Codex `turn_diff_tracker` keeps per-path baselines (WS-B1 F5, WS-B2). **Implication:** `SnapshotKind ∈ {fs_tree, fs_layer, memory, path_baseline}` is a closed sum on the snapshot record; only `fs_tree` is content-addressed by the identity profile's tree rule (ADR-0036) and therefore R1/R2-usable; `fs_layer` and `memory` carry a backend-opaque `foreign_digest` plus the *base* they delta from; `path_baseline` is the C0 minimum WS-B2 needs for `reversible`. Quiescence is a precondition for `memory` and `fs_layer` (Modal's "not while exec is running"), so `snapshot` must be able to refuse with `NotQuiescent` and the executor's `list_detached` (WS-E5) is what the kernel checks first.

**F5 — Sandbox platforms and evaluation harnesses converge on a *declared, validated capability record* per environment class rather than a common subset.** Harbor validates `EnvironmentCapabilities`/`EnvironmentResourceCapabilities` at preflight and refuses a resource mode the backend cannot enforce (`resource_policies.py` L5–40); Codex gates newer request fields on `EnvironmentCapabilities{network_proxy_launch, capability_discovery_sandbox, environment_config_read, http_header_env_vars, sandboxed_file_streaming, shell_snapshot_v2}` and reports `executor_version: "0.0.0"` when unknown (`protocol.rs` L96–155); Inspect declares `default_concurrency`, `is_docker_compatible`, and `connection()` raises `NotImplementedError` for sandboxes without one. **Implication:** the handle carries an `EnvCapabilityDeclaration` with tri-state fields (T-LCD-07); undeclared = `unknown`, never `unsupported`; the Lab stratifies on it; `bind` (WS-E1) checks `execution_requirement` against it.

**F6 — The operation surface of every environment abstraction is small and effect-shaped: execute, read/write files, upload/download, signal, and (sometimes) snapshot/pause/resume — nothing else.** OpenHands `BaseWorkspace` has seven operations; Inspect `SandboxEnvironment` has `exec / write_file / read_file / connection`; Harbor adds `upload_dir / download_dir / set_network_policy`; Codex's protocol adds `fs/*` primitives, `process/{write, signal, terminate}` and `capabilityRoots/discover`; browser-use exposes one operation (ship a function, stream its result). None exposes "run the harness here". **Implication:** the effect-operation surface (§6.4) is a closed sum whose members each name an `EffectDomain` (ADR-0016) and are invoked by the kernel dispatcher on behalf of an `effect_id` (WS-E5 I-1, complete mediation); kernel-internal operations (`health`, `meters`, `snapshot` for a Lab baseline) are `charged_to = instrument` and read-only from the model's point of view.

**F7 — Subagent and experiment isolation is a *derivation* of an environment, and production allows the child to outlive the parent.** Cursor: subagents on "isolated VMs", "A subagent might even outlive its parent, or run on a completely different kind of pod", environments shareable between parent and child (S-052); Shepherd forks scopes with byte-identical restoration on discard (S-078); Inspect creates a fresh `sample_init` environment per replicate and `sample_cleanup(interrupted)` per sample; Harbor gives the verifier its own environment session (`hello-world__bZZeEkw__verifier__grade`). **Implication:** `derive(parent, mode ∈ {fresh_from_image, fork_snapshot, share, scoped_subtree})` is the one operation behind subagents (F3), verifiers (G1: `charged_to = instrument`), experiment replicates (J3: always `fresh_from_image` or `fork_snapshot` of a pre-registered baseline) and speculative branches (B4); the child's containment is `effective(parent ⊓ child)` (WS-H4 §6.6), its credential bindings ⊆ parent's (WS-H3 SV-7), its budget a slice (ADR-0040); lifetime binding `on_parent_end ∈ {teardown, detach_to_child}` is MUST-data.

**F8 — Environment time is a lease-shaped resource with idle states, and no audited system meters it in a way a matched-budget comparison can use.** Cursor hibernates VMs between messages (S-052); E2B auto-pauses on timeout and keeps paused sandboxes "indefinitely" at storage cost only (S-482); OpenHands `APIRemoteWorkspace{keep_alive, pause_on_close}` and `resource_factor ∈ {1,2,4,8}`; Harbor `cpu_limit/cpu_request`; WS-L2 F6 already separates wall, working and environment clocks. **Implication (OQ-095, OQ-118 answers in §6.6):** three kernel-clock counters `env.reserved_ms ≥ env.active_ms + env.suspended_ms`, always-on because the kernel owns the state machine; CPU/memory/disk/network bytes are per-class declared meters with `measured | estimated | unavailable` provenance, never assumed.

**F9 — Credentials and containment are *attached to the handle*, not to the process the model runs, in every system that got security right.** Managed Agents inject repository tokens at sandbox initialization and route MCP through a proxy that fetches credentials from a vault (S-047); Codex passes `ExecEnvPolicy{inherit, exclude, set, include_only}` and a `FileSystemSandboxContext` per exec and treats `sandbox_tags` as diagnostics that "must not be used for authorization"; sandbox-runtime substitutes credential sentinels at the proxy (S-288). OpenHands' cloud workspace forwarding raw values (`forward_env`, `_get_secret_value`) is the counter-example. **Implication:** the handle *carries* WS-H4's `ContainmentPolicy/1` and WS-H3's `credential_bindings` as slots filled at `attach`; the handle never holds a value; `attach` fails closed without a `ContainmentReport` (WS-H4 §6.3).

## 5. Disconfirming evidence & negative results

**Against harness-outside as the only native topology.** OpenHands — the SDK doc 2 singles out for "production API boundaries" — puts the agent server *inside* the sandbox and gets simpler deployment, lower exec latency (no round trip per file read) and a single network surface; Harbor's whole `container-installed` mechanism assumes agents run in the task container; Prime Agent's persistent REPL lives with its state. *Why it does not overturn:* (a) the instrument's authoritative record, monitor and broker are C0/Must and must not sit inside the blast radius (ADR-0026, ADR-0035, WS-H3 SV-4); Managed Agents reached the same conclusion at scale and reports the latency went *down*, not up, because orchestration no longer waited for the box (S-047); (b) the latency cost of round trips is bounded by E5's `fs.*` primitives and detached processes (long work stays in the box); (c) harness-inside is not lost — it is exactly the hosted `container-installed` mechanism with `observability_level ⊇ {end_state}` and the Lab compares it on the same plane (ADR-0005/0013). The cost is carried honestly: an `exec` is always a boundary crossing, and AC-B5-12 measures the overhead under matched budget.

**Against a kernel-owned lifecycle state machine at all ("just call the provider's API").** E2B, Modal and Cursor already own the states; Symphony keeps "intentionally in-memory" scheduler state and recovers from the tracker + filesystem (WS-B2 M6); Codex's cloud tasks carry only an `environment_id` string. *Why it does not overturn:* the Lab needs one state model to make `env.*` accounting comparable across backends (T-LCD-09/-14), the effect model needs to know whether a `committed` effect's environment was `unreachable` or `replaced` to choose `probe` vs `unknown` (ADR-0030), and provider states are not aligned (E2B has no `unreachable`; Modal has no `paused`; Codex has no `suspended`). The kernel's machine is the *lowest common semantic*, and each backend declares which transitions it supports (tri-state), so nothing is intersected away (T-LCD-07).

**Against content-addressed snapshots and image digests.** Harbor and Inspect ship credible science with image *tags*; memory snapshots are inherently backend-opaque and expire (7 days at Modal); tree-hashing a multi-GB workspace is slow; Shepherd's CoW numbers are `provisional`. *Why it does not overturn:* ADR-0038 already requires digests for R2 and makes partial pinning legal and visible (`unpinned[]`); the design admits `foreign_digest` for opaque snapshots and caps their reproducibility claim; `fs_tree` hashing is required only at *baseline* and *bundle* points (not per effect) and only over the declared workspace roots; `path_baseline` remains the cheap C0 mechanism for the reversible class. Snapshot cost is a Stage 3 measurement (AC-B5-12), not an assumption.

**Against replace-not-repair self-heal.** Replacing an instance from an image discards everything not snapshotted; for a two-day run that is catastrophic; some failures (a wedged process) are cheaply repaired by a `terminate`. *Why it does not overturn:* the policy is data (`on_loss ∈ {fail_run, resume, replace_from_snapshot, replace_from_image}` with a `snapshot_cadence`), repair of *processes* is E5's `terminate_detached` inside a healthy handle (not a lifecycle transition), and the discontinuity record makes loss *visible* to G2 and the Lab rather than silently continuing on a different filesystem — which is the failure Managed Agents describes ("nurse failed containers") and Cursor avoids with checkpoints.

**Against `derive` as one primitive for subagents, verifiers, replicates and branches.** Their requirements differ: verifiers want the *end state* of the subject's environment (not a fork), subagents may need shared mutation, replicates need identical starts, branches need CoW. *Why it does not overturn:* the four are modes of one operation with different `mode` values and different post-conditions; unifying them lets the containment meet, credential attenuation, budget slicing and lineage recording be written once (WS-H4 §6.6, WS-H3 SV-7, ADR-0040) — and the `share` mode is explicitly the only one that admits concurrent mutation, under E5's resource keys.

**Against the effect-domain tagging of every handle operation ("a file read is not an effect").** Tagging every `fs.read` with an `effect_id`, a permission check and a ledger event is expensive; OpenHands and Inspect read files freely. *Why it does not overturn:* ADR-0031 already makes `read_only` effects free of the write-ahead barrier and free to retry; the ledger cost of a `read_only` effect is one event pair (or none if the capability declares `observation_contract.offload`), and the M-CPE/X-CPE attacks (WS-L3 F5) enter precisely through unlabelled environment reads. The rule "no side door" is what makes AC-B5-01 (no unmediated effect) checkable.

**Negative results from the audit.** (i) No audited harness content-addresses its environment image at run time (all tags); (ii) none records a world-state discontinuity when an environment is replaced (Managed Agents surfaces it as a tool error to the model only); (iii) none exposes `env.active/reserved/suspended` as accountable dimensions; (iv) Codex's `provider_id` and OpenHands' `get_server_info` identify the *executor build*, not the environment contents — helper identity is a claim (T-LCD-07); (v) no audited harness protocol has a lifecycle verb for `snapshot`/`restore` (Codex has shell snapshots only; OpenHands has `pause/resume`); the platforms (E2B, Modal, Cursor) have them, the harnesses do not — the seam this dossier closes.

## 6. Recommendation for the spec

### 6.1 Topology and placement (C0 / Stage 0–1) — ADR-0136

1. **The native runtime is harness-outside.** The kernel (ledger, monitor, broker, budget enforcement, compiler/interpreter — the ADR-0050 kernel layer) never executes inside an execution environment. An environment is reachable only through an **environment handle** held by the kernel, and the model reaches it only through `ToolCapability`s whose executors dispatch through the handle (WS-E5 I-1, complete mediation). "Harness-inside" placements are admissible only as hosted participants with `hosting_mechanism = container-installed` (ADR-0005/0013).
2. **One environment protocol, three backend placements.** The kernel's *sandbox driver* speaks one verb set (WS-E5 §6.7 minimum + the lifecycle verbs of §6.2) to: (a) a **local helper binary** on the kernel host (`local_sandboxed`; the ADR-0050 helper layer — OQ-045 final answer confirmed from the B5 side: out-of-process, same ecosystem as the kernel, no revalidation trigger fires); (b) the **same helper running inside a container/VM** reached over a bridged channel (`local_container`, `remote_ephemeral`, `remote_persistent`; Codex exec-server pattern); (c) a **provider adapter** that implements the verbs over a platform API and declares what it cannot do (`provider_hosted`; E2B/Modal/browser-use). The driver is MUST-code (ADR-0024); backend selection, image, policy and limits are MUST-data on the `EnvironmentRecord`.
3. **Environment classes** (closed per dialect): `EnvironmentClass ∈ {local_host, local_sandboxed, local_container, remote_ephemeral, remote_persistent, provider_hosted}`. `local_host` is `isolation_class = none` (WS-H4) and admissible only at Stage 0 or under an `authority_cap`-reviewed definition (WS-H5 `host_unconfined`); `remote_persistent` is the Symphony/dev-box case (attach to an existing instance; teardown never deletes); `remote_ephemeral` is provisioned per run and torn down.

### 6.2 The handle record and lifecycle state machine (C0 / Stage 1; C1 for `suspended`/`replace`) — ADR-0136

**Handle record (runtime, kernel-owned; never an IR entity — `AgentProcess.native.environment` is an `EnvironmentRef` to the record of §6.3):**

`EnvHandle{ env_handle_id: allocated id (ADR-0027 class; `EnvHandleId` added to the allocated-id list), run_id (owner), environment_ref: VersionedRef<EnvironmentRecord>, class: EnvironmentClass, state: HandleState, health ∈ {healthy, degraded, unknown}, session?: {session_id, helper_identity (claim), attached_at, lease_generation}, capabilities: EnvCapabilityDeclaration (tri-state), containment: {policy: VersionedRef<ContainmentPolicy/1>, report: ContainmentReport} (WS-H4), credential_bindings: [CredentialBinding] (WS-H3; placeholders only), roots: {workspace_roots: [Path], writable_roots: [WritableRoot], cwd}, limits: ResourceLimits (WS-H4 §6.1) with budget_node_refs (ADR-0040), meters: EnvMeters (§6.6), snapshots: [SnapshotRef] (§6.3), parent?: {env_handle_id, mode, on_parent_end}, fault_profile_ref? (WS-I2/I4), connection_info?: ConnectionInfo (read-only; Inspect `SandboxConnection` / browser-use `live_url` shape), on_loss: LossPolicy, provenance: ProvenanceRecord{origin = kernel, authority = kernel} }`.

**States and transitions** (each transition is a ledger event of the `action.environment.*` family, §6.7; each is a `scope_kind = environment_op` span, ADR-0042):

| state | meaning | enters by | leaves by |
|---|---|---|---|
| `declared` | record resolved and pinned in the run manifest; no instance | `open_run` | `provision` |
| `provisioning` | instance being created from `EnvironmentRecord` (image pull, boot, hooks `after_create`) | `provision(environment_ref, class, limits) → env_handle_id` | `ready` (`attach` succeeded) · `failed{reason}` |
| `ready` | instance alive, helper session attached, `ContainmentReport.enforcement_evidence ≠ unknown` for every governed field group | `attach` · `resume` · `reattach` | `detach` · `suspend` · `unreachable` · `teardown` |
| `detached` | instance alive, **no** session (kernel released it deliberately, e.g. hand-off to a child run or B3 checkpoint) | `detach(keep = true)` | `attach` · `teardown` · `expired` |
| `suspended` | instance paused/hibernated; state preserved per `capabilities.suspend ∈ {memory, fs_only, unknown}` | `suspend` | `resume` → `ready` · `teardown` |
| `unreachable` | session lost or health probe failed; instance status unknown | liveness loss, lease fencing, helper disconnect | `reattach` (within `capabilities.reattach_window_ms`) → `ready` · `replace` · `failed` |
| `replaced` | terminal for *this* handle; a successor handle exists | `replace(from ∈ {latest_snapshot, image})` | — |
| `failed{reason}` | terminal; no successor | provisioning failure · reattach window exhausted with `on_loss = fail_run` | — |
| `torn_down` | terminal; resources released (or, for `remote_persistent`, session closed and hooks run) | `teardown(reason ∈ {run_end, budget, principal, parent_end, error})` | — |

Invariants: **L1** exactly one `ready` handle per `(run_id, environment_ref)` at a time — `AlreadyAttached` otherwise (Codex `SESSION_ALREADY_ATTACHED`); **L2** every effect event carries the `env_handle_id` it ran on (ADR-0030 `env_handle`), so a `replace` partitions the effect history; **L3** on `unreachable` and on `replace`, every effect in `committed` on that handle is marked `action.effect.unknown{cause: worker_lost | environment_replaced}` by the recovery procedure (WS-B3) — never silently carried across; **L4** `replace` appends `action.world_state.discontinuity{from_env_handle_id, to_env_handle_id, restored_from: SnapshotRef | image, lost_range: (seq_from, seq_to)}` unless the successor was restored from an `fs_tree` snapshot whose address equals the predecessor's last recorded state (then `continuity = byte_identical`); WS-G2 treats a discontinuity as evidence that every claim about workspace state after `lost_range` must be re-verified; **L5** all lifecycle transitions are kernel-initiated and ledgered *before* the backend call (durable-before-visible, ADR-0026) except `unreachable`, which is observed; **L6** `teardown` runs `before_remove` hooks as effects under the run's budget and, for `remote_persistent`, never deletes; **L7** the handle never stores a credential value, a kernel identity, or a lease token (WS-H3 SV-4; WS-E5 I-2).

**Self-heal contract.** `heal(env_handle) → HealOutcome` is the kernel procedure invoked by B3 on `unreachable`: (1) `reattach` within `reattach_window_ms` (helper `hello(resume_session_id)`; Codex 25 s inside a 30 s retention); (2) if the backend reports `suspended`, `resume`; (3) else per `on_loss`: `fail_run` → `failed`; `replace_from_snapshot` → `provision` a successor and `restore(latest SnapshotRef)`; `replace_from_image` → successor from the image; (4) emit `replaced` + discontinuity per L4; (5) B3 resumes from the last durable effect phase. A `snapshot_cadence` (`{on_turn_end, every_n_effects, on_idle, never}`) is MUST-data and is charged to the subject when it exists for recovery, to the instrument when the Lab requests it.

### 6.3 Identity and snapshot semantics (C0 / Stage 1–2) — ADR-0137

Three identity layers, each with a different ADR-0036 identity kind:

| layer | record | identity kind | enters |
|---|---|---|---|
| **definition** | `EnvironmentRecord{ class, image: ContentAddress \| foreign_digest{scheme, value, source}, build_context?: tree ContentAddress, platform{os, arch}, provisioning: ProvisioningRecipe{backend_params (MUST-data), hooks: [Ref<Procedure>] per transition, resource_defaults}, containment_policy: semantic_id + version_id (WS-H4), limits: ResourceLimits, nondeterminism: [NondeterminismDeclaration] (ADR-0038; e.g. wall_clock, network, filesystem_order), capabilities_expected: EnvCapabilityDeclaration, ext }` | `version_id` / `semantic_id` (surface = backend spellings of paths/hosts; provenance and `ext` excluded) | `environment_ref = semantic_id` is the **environment factor coordinate** in `configuration_id`; `version_id` is pinned in `configuration_version_id` and the run manifest (ADR-0036 N6; clarification proposed in §8 so WS-L4/I2/J5 read `environment_ref` unambiguously) |
| **instance** | `EnvHandle` (§6.2) | allocated `EnvHandleId` (time-ordered, opaque) | every effect event; never a factor coordinate; never in the bundle except as `subject.env_handle_ids[]` for lineage |
| **state** | `SnapshotRecord{ snapshot_ref: ContentAddress (over this record's canonical form), env_handle_id, at_seq, kind: SnapshotKind, base: image ContentAddress \| SnapshotRef, content: tree ContentAddress (kind = fs_tree) \| foreign_digest (fs_layer, memory) \| path_baselines: [{path, ContentAddress}] (path_baseline), roots_covered: [Path], quiesced: bool, taken_by ∈ {subject, instrument}, size_bytes, expires_at? }` | content address (`idp/1`, domain tag `snapshot`) | `baseline_ref` on `action.effect.prepared` (ADR-0030); `restore`/`derive(fork_snapshot)` inputs; `EnvironmentRecord`-independent — a snapshot of instance A is restorable into a successor of A or a child of A only if `base` resolves |

`SnapshotKind ∈ {path_baseline, fs_tree, fs_layer, memory, shell_state}` (closed): `path_baseline` = per-path content addresses before a write (Codex `turn_diff_tracker`; the **C0 minimum** for the reversible class); `fs_tree` = the identity profile's tree rule over `roots_covered` (ADR-0036 N8; deterministic, deduplicating, R1/R2-grade); `fs_layer` = backend delta from `base` (Modal filesystem snapshot, Shepherd CoW; `foreign_digest`); `memory` = full VM/container state incl. processes (E2B pause, Modal memory snapshot, Cursor checkpoint; `foreign_digest`; requires `quiesced = true` — Modal refuses while an exec runs and closes TCP connections); `shell_state` = executor-owned convenience (Codex shell snapshot) — **never** a baseline and excluded from every identity.

Rules: **S1** a handle's `capabilities.snapshot ⊆ SnapshotKind` is declared; `snapshot(kind)` on an undeclared kind fails `Unsupported`, on `unknown` fails `UnknownCapability` (never coerced, T-LCD-07); **S2** `restore(snapshot_ref)` produces a **new** handle (successor) unless `capabilities.restore_in_place = supported`, in which case the in-place revert is B4's `revert` effect with a `reverts` edge (ADR-0030); **S3** two `fs_tree` snapshots with equal tree addresses are the same state (dedup; AC-B5-03), and `restore` of an `fs_tree` snapshot verifies the restored tree address (`RestoreMismatch` otherwise); **S4** reproducibility: R2 requires `image` by `ContentAddress` (not `foreign_digest`) and every snapshot the run *restored from* present in the bundle; a bundle whose environment carries only a `foreign_digest` or a memory snapshot caps at R0/R1/R3 (ADR-0038 `unpinned[]`); **S5** (OQ-089 answer) the reversible class is backed by `path_baseline` at C0/Stage 1 for every class, by `fs_tree` over `writable_roots` at Stage 2 where the tree is small enough (`limits.snapshot_bytes`), by `fs_layer`/`memory` only where declared (C1/C2 with B4); `BaselineUnavailable` (roots exceed `snapshot_bytes`, backend refuses, `NotQuiescent`) **downgrades** the effect to `compensable`/`irreversible` per ADR-0030 and is ledgered — never proceeds silently and never refuses the effect on its own; **S6** snapshots carry credential placeholders only (WS-H3 SV-4; Codex `apply_to_env_for_snapshot` precedent) and the containment policy in force (`memory` snapshots restored under a *different* policy must re-`attach` and re-verify); **S7** `SnapshotRecord.expires_at` mirrors backend expiry (Modal 7/30 days) and a bundle referencing an expired backend snapshot records it in `unpinned[]`.

### 6.4 The effect-operation surface (C0 / Stage 1) — ADR-0138

A handle exposes only the following operations; each is a member of a closed sum, names the `EffectDomain` (ADR-0016) it belongs to, and is invoked by the kernel dispatcher on behalf of an `effect_id` through the WS-E5 execution contract (the executor's `ExecutionRequest` carries the `env_handle`, `attribution_token`, `commit_token`). Kernel-internal operations carry no effect and are visible to the model only through typed observations.

| operation | inputs → outputs | domain / class | invariants · failure modes |
|---|---|---|---|
| `exec(ExecutionRequest) → execution_id` and `read / write_input / signal / terminate / list_detached / terminate_detached` | WS-E5 §6.2 verbatim | `exec`, `spawn_process` | E5 I-1…I-6; `NotCommitted`, `AttributionMismatch`, `EnvironmentUnavailable` |
| `fs.read(path, range?) → bytes \| ContentAddress`; `fs.read_dir`, `fs.metadata`, `fs.canonicalize(path) → resolved` | under the handle's sandbox context; symlinks resolved before validation (WS-H4) | `fs_read` (`read_only`) | outside `roots` ⇒ `ContainmentRefused`; size above `observation_contract.offload_above` ⇒ blob |
| `fs.write(path, bytes \| ContentAddress)`, `fs.create_dir`, `fs.remove`, `fs.copy` | `baseline_ref` taken by `prepare` for `reversible` | `fs_write` | `ProtectedPathExemption` (KERNEL_PROTECTED, H4); `BaselineUnavailable` ⇒ downgrade |
| `upload(tree ContentAddress \| bytes → path)`, `download(path → tree ContentAddress \| ContentAddress)` | kernel-side blob store ⇄ environment; used by I4 task setup, G1 evidence collection, F3 merge | `fs_write` / `fs_read` | `download` is how `end_state` evidence enters the ledger (WS-G1 `EvidenceKind.end_state(env_handle)` resolves to a `download` of `roots_covered` into an `fs_tree` address) |
| `snapshot(kind, roots?) → SnapshotRef`; `diff(baseline: SnapshotRef) → FsChangeSet{added, modified, removed: [{path, before?, after?}]}` | §6.3 | kernel-internal (`charged_to` per `taken_by`) | `Unsupported`, `NotQuiescent`, `SnapshotTooLarge(limits.snapshot_bytes)` |
| `connection_info() → ConnectionInfo{kind ∈ {shell_command, ports[], live_url, none}}` | read-only; for surfaces (K-track) and human hand-off | kernel-internal | never a credential (H3 SV-4) |
| `health() → {healthy, degraded, unknown}`; `status() → HandleState` | pure; never starts or repairs a connection (Codex `EnvironmentObservedStatus` rule) | kernel-internal | — |
| `meters() → EnvMeters` | §6.6 | kernel-internal | — |
| `env_apply(EnvSpec{allowlist, bindings[]})` | WS-H3 obligation; at `attach` only | kernel-internal (attach-time) | `EnvironmentNotIsolated` (H3) |
| `set_containment(policy)` | only through WS-H4 `amend()`; re-runs the probe battery | kernel-internal | `ContainmentWidening`, `StrictMode` |
| `derive(mode, spec) → env_handle_id` | §6.5 | `spawn_process`-adjacent kernel op; ledgered under the parent's budget slice | `ModeUnsupported`, `InsufficientBudget` |

**Rule R-NOSIDE (no side door):** no component other than the kernel dispatcher holds a reference that can invoke `exec`/`fs.*`/`upload`/`download` on a handle; executors receive an `ExecutionRequest`, not the handle; the Lab, surfaces and hosted-participant adapters receive `connection_info`, `health`, `meters`, `download` (as instrument effects) and snapshot refs only. This is what makes "no unmediated effect" (E5 I-1) a static ledger check (AC-B5-01). **Rule R-NONET:** the handle has no network operation; egress exists only as WS-H4's mediator reached from inside the environment, and `NetPolicy.mode` on the containment policy is the sole control (WS-H4 §6.4).

### 6.5 Workspace derivation for subagents, verifiers, replicates and branches (C1 / Stage 2–4) — ADR-0138

`derive(parent: env_handle_id, mode, spec) → child env_handle_id` with `mode ∈ {fresh_from_image, fork_snapshot, share, scoped_subtree}`:

- `fresh_from_image` — a new instance from the parent's `environment_ref` (same image, same policy meet, empty state); **the only mode admissible for experiment replicates** (WS-J3/I4) so that `replicate` seed material includes the image digest (ADR-0045) and no state leaks between arms.
- `fork_snapshot` — a new instance restored from a `SnapshotRef` of the parent (Shepherd CoW; Modal fork-from-filesystem-snapshot; Cursor fork); the mode for speculative branches (WS-B4), independent verifiers that must see the subject's end state without mutating it (WS-G1/G3, `taken_by = instrument`), and subagents that need the parent's workspace.
- `share` — the child attaches to the **same instance** (a second session on the same handle is refused, L1; instead the child receives a *scoped* handle whose `roots` ⊆ parent's and whose effects run under the parent's session with the child's `attribution_token`); concurrent mutation is admitted only under E5's resource keys; Cursor's "environments shareable between parent and child" case. C1.
- `scoped_subtree` — `share` restricted to a subtree with `fs.write.allow = [subtree]` in the child's containment layer; the default for subagents that edit a component of a repository.

Invariants: **D1** child `containment = effective(parent ⊓ child_layer)` — never wider (WS-H4 §6.6; ADR-0034 P2); **D2** child `credential_bindings ⊆ parent's` and a `share`/`scoped_subtree` child sees only placeholders already in the instance (WS-H3 SV-7); **D3** child budget is a `slice` of the parent's `BudgetNode` (ADR-0040) and `env.*` counters post to the child's node; **D4** `parent.on_parent_end ∈ {teardown, detach_to_child}` — Cursor's "a subagent might even outlive its parent" is `detach_to_child`, which transfers ownership (`owner run_id` changes; ledgered) and is refused for `share`/`scoped_subtree`; **D5** merge is never implicit: a `fork_snapshot`/`fresh_from_image` child returns artifacts by content address (`download`) and the parent applies them as its own `fs_write` effects with a `baseline_ref` (revert-able), or applies a `FsChangeSet` from `diff` — so every merged byte is attributable to a parent effect (WS-F3 owns conflict policy); **D6** lineage: `EnvHandle.parent` + `action.environment.derived{mode, parent_env_handle_id, snapshot_ref?}` so the Lab can reconstruct which environment a claim was made in (WS-G2 `EnvironmentStateRef{snapshot_ref, selector}` resolves through it).

### 6.6 Resource limits and meters (C0 / Stage 1 clocks; Stage 2 per-class meters) — answers OQ-095, OQ-118

- **Limits** are WS-H4's `ResourceLimits` on the containment policy, each mapped to a `BudgetNode` dimension or a registered `ext` dimension (CF-137 pending WS-L2/A3); exhaustion is a budget event at a decision point (ADR-0040), never a silent kill — the helper enforces the OS limit and reports `terminal{status: error(resource_limit)}` (E5), the kernel posts `control.budget.exceeded`.
- **Kernel-clock counters (always-on at Stage 1, `measured`, producer = the environment service, measurement points M-ENV-1…3 to be appended to ADR-0043's list by amendment):** `env.reserved_ms` (from `provisioning` entry to a terminal state — what the instance costs the provider), `env.active_ms` (time in `ready` with a live session), `env.suspended_ms` (time in `suspended`). Invariant `env.reserved_ms ≥ env.active_ms + env.suspended_ms`. **OQ-095 answer:** a third counter, `env.suspended_ms`, is recorded separately (storage-shaped cost: E2B "kept indefinitely", pause ≈ 4 s/GiB) and enters `MeteringFormula`s with a declared weight (default 0 for the compute-minutes view, pricing-table-driven for the spend view) — it is never folded into `reserved` or `active` because matched-budget comparison of an always-on harness against a hibernating one (Cursor) is meaningless otherwise (T-LCD-14).
- **Per-class declared meters (Stage 2):** `env.cpu_ms`, `env.memory_peak_bytes` (gauge), `env.disk_bytes` (gauge), `env.snapshot_bytes` (counter), `env.provision_ms` (latency, M-point), `env.snapshot_ms`, `env.resume_ms`; each declared in `EnvCapabilityDeclaration.meters` with `provenance ∈ {measured, estimated, unavailable}`; `unavailable` renders `n/a{reason: no_detector}` (ADR-0045), never 0. **OQ-118 answer:** always-on = the three kernel-clock counters + `network.calls` (WS-H4); everything else declared per class; `measured` only when the backend reports from the OS/hypervisor, `estimated` when derived from `resource_factor`-style provisioning parameters (OpenHands `resource_factor`) and flagged as such in `CostProvenance` (ADR-0043 `estimated_from_pricing`-class).
- `charged_to`: subject for the run's own instance, snapshots taken for recovery and `derive(share|scoped_subtree|fork_snapshot)` children of subagents; instrument for verifier environments, Lab-requested snapshots and probes (ADR-0039).

### 6.7 Ledger events (amendment to the ADR-0026 taxonomy — additions, no renames)

Family `action.environment.*` (home plane per WS-B1; boundary component per Ontology v1 §2b — the family declares `home = environment_boundary` if WS-A2's home rule requires a boundary value for boundary components, else stays in the action plane; CF in §8): `declared{environment_ref, class}`, `provisioning{env_handle_id, environment_ref, class, limits, image, provisioning_params_ref}`, `attached{env_handle_id, session_id, helper_identity (claim), capabilities, containment_report_ref → security.containment.applied (CF-138 accepted: one record, referenced), credential_binding_ids[], roots, connection_info?}`, `selected{turn_id, env_handle_id, cwd}` (Codex per-turn selection), `detached{env_handle_id, keep, reason}`, `suspended{…, kind ∈ {memory, fs_only, unknown}}`, `resumed{…, resume_ms}`, `unreachable{…, cause, last_seen_seq}`, `reattached{…, within_window}`, `snapshot{env_handle_id, snapshot_ref, kind, taken_by, size_bytes, at_seq}` (B1's `snapshot` verb, payload extended), `restored{to_env_handle_id, snapshot_ref, verified: bool}`, `derived{child_env_handle_id, mode, parent_env_handle_id, snapshot_ref?}`, `replaced{from, to, restored_from}`, `failed{…, reason}`, `torn_down{…, reason, hooks_run[]}`, `meters_sampled{env_handle_id, EnvMeters}` (only where not derivable from state transitions — CF-088 rule); `action.world_state.discontinuity{from_env_handle_id, to_env_handle_id, restored_from, lost_range, continuity ∈ {byte_identical, restored_from_snapshot, fresh}}` (B1's `world_state` family). All `durability = ledger`, minimum `observability_level = events`, provenance `origin = kernel`; hosted `container-installed` rows carry `origin = participant` and only the transitions the adapter can observe.

### 6.8 Acceptance-criteria sketch

- **AC-B5-01 No side door (static, C0/Stage 1).** Over the Stage-1 reference run's ledger, every `action.environment.*` and `action.effect.*` event that touched a handle has a preceding `security.permission.decided{allow}` and, for non-`read_only`, `action.effect.committed` (E5 I-1); a fuzz harness that invokes any handle operation from a non-kernel component fails to obtain a handle reference (type-level) and, over the helper protocol, is refused `NotCommitted`/`AttributionMismatch`.
- **AC-B5-02 Kernel death ≠ environment death (Stage 1–2).** Kill the kernel at each of the four effect-cycle points (AC-B1-2/AC-B2-01) while a command runs in a `local_sandboxed` and a `local_container` handle: on restart, `heal` reattaches within `reattach_window_ms`, the effect ends `observed` via `probe = read(execution_id)` (E5), no command is re-executed, and `env.active_ms` excludes the gap.
- **AC-B5-03 Replacement is visible (Stage 2).** Destroy the container under a `ready` handle: the ledger shows `unreachable → replaced`, every `committed` effect on the old handle is `unknown`, `world_state.discontinuity{continuity = fresh | restored_from_snapshot}` is appended, WS-G2 flags every post-gap claim, and the successor carries the same `environment_ref` and a new `env_handle_id`.
- **AC-B5-04 Snapshot identity (Stage 2).** Two `fs_tree` snapshots of byte-identical workspaces (different handles, different hosts) yield equal `snapshot_ref` tree addresses; `restore` verifies the address; a modified byte changes it; `shell_state` snapshots never appear in any identity or bundle.
- **AC-B5-05 Digest, not tag (Stage 1).** `resolve` of an `EnvironmentRecord` whose image is a mutable tag fails `UnresolvedRef` unless the record lists it in `unpinned[]`; the run manifest and bundle carry `image: ContentAddress | foreign_digest`; a bundle with `foreign_digest` claiming R2 is `ReproClaimUnsupported` (ADR-0038).
- **AC-B5-06 Fail-closed attach (Stage 1).** A backend whose `ContainmentReport` has `enforcement_evidence = unknown` for `fs` never reaches `ready`; the run's first `fs_write` is refused `ContainmentUnverified` (WS-H4).
- **AC-B5-07 Value-free handle and snapshots (Stage 2, with WS-H3 LT-04/05).** `leak_scan` over the handle record, every `action.environment.*` payload and an `fs_tree` snapshot of a bound environment finds only placeholders; a `memory` snapshot restored under a narrower policy re-attaches and re-verifies.
- **AC-B5-08 Derivation isolation (Stage 2–4).** A `fork_snapshot` child's writes are invisible to the parent until the parent applies the child's `FsChangeSet` as `fs_write` effects with baselines; a `scoped_subtree` child writing outside its subtree is refused `ContainmentRefused`; `detach_to_child` transfers ownership and the parent's teardown does not tear the child down; `env.*` of the child post to the child's budget slice.
- **AC-B5-09 Clocks (Stage 1).** For every handle, `reserved_ms ≥ active_ms + suspended_ms`; a `suspend`/`resume` pair moves time from `active` to `suspended`; hard `env.reserved_ms` ceilings end the run only at a decision point after open effects close (ADR-0040).
- **AC-B5-10 Capability honesty (Stage 2).** For each backend, every declared-`supported` transition and snapshot kind is exercised by a conformance suite; `unknown` fields are reported as `n/a`, never probed-and-coerced; a backend adapter that returns success for an undeclared operation fails conformance.
- **AC-B5-11 Three backends, one suite (Stage 3).** The same Stage-3 reference harness runs on `local_sandboxed`, `local_container` and one `provider_hosted` adapter with identical `configuration_id` except the environment coordinate; the results rows differ only in the environment factor and the environment lowering-loss report lists what each backend could not enforce or observe (T-LCD-09/-11).
- **AC-B5-12 Overhead is measured, not assumed (Stage 3).** `env.provision_ms`, `env.snapshot_ms`, per-effect boundary-crossing latency (`harness_overhead.execution_ms`, E5) and snapshot bytes are reported per class under matched budget; `fs_tree` snapshot cost over the reference workspace is recorded as a `ComparisonReport` input, and the `snapshot_cadence` default is chosen from it (a conditioned rule with a debt record, T-LCD-05).
- **AC-B5-13 Hosted mapping (Stage 4).** A `container-installed` hosted participant's run maps onto a handle with `origin = participant` rows, `observability_level ∌ events` for lifecycle transitions it cannot report, and no native contract changes (T-LCD-06); a session-ABI participant that runs in a kernel-provisioned environment gets the full lifecycle.
