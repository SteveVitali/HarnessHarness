## Ontology terms

| term | definition | notes |
|---|---|---|
| `HostedEvent` (typed minimum observable event set) | The envelope `{seq, session, at, kind, payload, provenance{origin, authority}, mediation, event_channel, raw_ref?, ext}` through which a hosted participant's run reaches the ledger; `kind` is the closed minimum observable event set; every hosted ledger row is a lifting of one `HostedEvent` (or a kernel-origin native row). | WS-J6; typed form of the ratified *minimum observable event set* (ADR-0005); lifting tables per mechanism carry loss classes (T-LCD-11). |
| mediation stamp | `mediation ∈ {mediated, observed, unobserved}` on every hosted event: *mediated* — the kernel produced or gated the fact and a `causes[]` link exists; *observed* — reported live by the participant over a protocol/hook channel; *unobserved* — reconstructed post hoc or synthesized. Metrics declare the mediation they require. | WS-J6; ADR-0164 D5; orthogonal to `observability_level` (what evidence exists) and to authority (who vouches). |
| hosting adapter / `AdapterRecord` | The out-of-process artefact that implements one hosting mechanism for a selector of participant versions: transport, lifting table, loss report, declaration defaults, and an assumption-debt record with expiry and removal test. | WS-J6; ADR-0166 D3; a conditioned artefact (T-LCD-05 reflexive). |
| adapter zero / ABI self-consistency test | The reference runtime attached through its own session artefact (`proj_ABI`, ADR-0005 "act as a participant"); the fixture on which probes and lifting are validated: every metric with `requires_observability ⊆ {events, end_state}` and `requires_mediation ≠ mediated(effects)` must agree between the native and the hosted presentation of the same run. | WS-J6; AC-J6-2; executable form of ADR-0013 decision 5. |
| process placement | `process_placement ∈ {in_environment, lab_host, remote_service}` — where the hosted participant's process runs relative to the Lab-provisioned environment; drives `budget_enforcement` and `enforcement_evidence`. | WS-J6; descriptor `ext hh.hosting/1`; distinct from *hosting mechanism* (how evidence is obtained) and from WS-B5's *environment class*. |
| budget enforceability | `budget_enforcement: map<dimension, {enforced, advisory, unenforceable}>` — per resource dimension, whether the Lab can stop the participant at a ceiling (enforced), only instruct it (advisory), or neither (unenforceable); consumed by `MatchSpec` validation. | WS-J6; ADR-0165 D3/D4; derived, never declared by the participant. |
| conformance dimension / probe catalogue | A named behaviour (P-01…P-16) that a Lab-side probe can exercise in a fixture session and reconcile against the capability declaration; the P0 subset gates experiment admission. | WS-J6; ADR-0166 D4; extends the ratified *observed conformance / DRIFT* term with the catalogue and the P0 rule (OQ-034). |
| event channel | `event_channel ∈ {protocol, hook, log, proxy, handle}` — the concrete channel through which a `HostedEvent` was obtained (session protocol update, vendor hook payload, native log lifter, interception proxy, kernel environment handle). | WS-J6; provenance detail for hosted rows; informs `mediation` but does not decide it. |
| `ConformanceRecord` (typed) | `{participant_version_identity, adapter_version_id, dimension, declared, observed, verdict, observed_in ∈ {probe, run}, evidence_ref, at}`; immutable; stale when `version_identity` changes (annotated, never hidden). | WS-J6; typed form of the ratified WS-A2 `ConformanceRecord` sketch; ADR-0166 D5. |
