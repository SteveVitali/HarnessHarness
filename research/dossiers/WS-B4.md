## 1. Scope & boundary

This workstream decides how the reference runtime **branches, rewinds, speculates and re-executes** on top of the run ledger (WS-B1), the effect lifecycle (WS-B2) and the identity/reproducibility model (WS-L4). Concretely it fixes: (i) the **trace/branch data model** — what a branch is at the two granularities the ledger already admits (an *intra-run branch* in the `parent_event_id` tree, an *inter-run fork* by `forked_from`), what a **fork point** is and which fork points are *coherent*; (ii) the **fork / replay / snapshot contract** — the operations, the **environment snapshot** record, and the invariant that a trace fork and an environment fork are one atomic step; (iii) the **speculative-effect policy** — which effect risk classes may run inside a speculative branch, what happens to the rest (deferral), and what *promote*, *discard* and *rollback* mean for effects that already ran; (iv) the **nondeterminism recording rules** — what a run must record for a later branch to be *deterministically replayable* versus *re-executable*, and the `ReplayValidityReport` that labels every branch-derived result (the ADR-0028 consequence "B4 must label every replay-derived result with its mode"); (v) the **counterfactual re-execution hooks** WS-I7 consumes (intervention records, the mandatory factual re-execution arm, the weak-coupling assumption); (vi) acceptance criteria, a build-stage placement and the T-LCD statement.

It explicitly leaves to neighbours: the ledger envelope, ids, `forked_from` lineage and `head.moved` mechanics (**WS-B1**, ADR-0026/0027 — consumed verbatim; one payload extension is proposed as an amendment, CF-286); effect phases, risk classes, idempotency keys and the compensation saga (**WS-B2**, ADR-0030/0031/0032 — consumed verbatim; this dossier adds one non-terminal phase, `deferred`, and flags it, CF-287); the restart/checkpoint/wakeup procedure and the `recovery_decision` (**WS-B3** — this dossier fixes only what a *rollback* must record and how it interacts with restore); the sandbox/VM handle model and the *mechanism* that implements `snapshot`/`restore`/`fork_env` per environment kind (**WS-B5**, OQ-045/OQ-089 — this dossier fixes the contract, the record and the coverage vocabulary); which control-strategy variants declare `deterministic_replay` (**WS-F1**, ADR-0028); subagent spawn/merge topology (**WS-F3** — a subagent is an inter-run fork with `branch_kind = delegation`, and F3 owns everything after the fork); the attribution statistics and admissibility rules for counterfactual comparisons (**WS-I7**, with WS-I2 — this dossier supplies the hooks and the pairing design that makes OQ-082 answerable); the trace/time-travel viewer (**WS-K2**); the experiment engine's use of branches as arms (**WS-J3**); and every language, runtime, storage or virtualization-technology choice (ADR-0050).

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Every production fork-or-rewind mechanism read here operates on a *coherent boundary*, and the two that let callers pick arbitrary points added validation or synthesized an interrupt.** Codex's `ForkSnapshot` admits exactly two cuts: before the n-th user message, or "the current persisted history as if the source thread had been interrupted now", appending "the same `<turn_aborted>` marker produced by a real interrupt" when the snapshot ends mid-turn (S-107 `thread_manager.rs` L166–197); its TODO names the missing variant, "a coherent fork from the last stable model boundary", explicitly because core "can[not] represent sampling boundaries directly" yet. The Claude Agent SDK's `resume_drops_turn` "validates at load time that every transcript entry after the `resume_session_at` point is attributable to that turn, and refuses the resume otherwise — e.g. when the discarded range contains a queued user message or task notification the session absorbed mid-turn" (S-109 `types.py` L2190–2200). Crab aligns checkpoints "with turn boundaries" (S-475). opencode and gemini-cli snapshot per message. **Implication:** a fork point is a `(run_id, seq)` at which no model-call scope and no non-detached effect scope is open (the ledger already records scope opens and closes, ADR-0027 §1); forking elsewhere is refused (`ForkPointNotCoherent`) or coerced to the nearest earlier coherent seq with a synthesized `lifecycle.turn.finished{stop_reason: forked}` — the Codex `Interrupted` semantics made explicit.

**F2 — Forking the trace without forking the environment is the documented failure signature, and it exists in shipping code.** OpenHands' `fork()` copies `path_to_root(from_event_id)` into a new conversation but constructs it with `workspace=self.workspace` — both conversations then act on one live working directory (S-110 `local_conversation.py` L843–847). LangGraph checkpoints channel values with a `parent_config` chain and no environment at all (S-143). *Safe to Resume?* names the consequences: SF2 (a checkpoint that is not "a valid causal execution cut"), SF3 (internal state restored "against an outside world under which the assumptions encoded by that state are no longer valid") and SF5 (rollback "removes the internal record that the action has occurred" while the effect persists), and demonstrates a duplicate payment against LangGraph and unauthorized mail forwarding against Cline (S-476). Shepherd's design contribution is precisely the opposite invariant — "the agent and its environment are forked atomically" and a discard leaves "the parent byte-identical to the moment of fork" (S-078). **Implication:** the fork contract couples a trace fork with an `EnvSnapshot` taken at the same seq, or records that the branch is `trace_only` with a live-shared environment and restricts it to `read_only` effects (§6.3 invariant B3).

**F3 — Rollback is an appended, interpreted record everywhere the audit record survives; the two systems that truncate lose it.** Codex `ThreadRolledBack{num_turns}` is applied while *indexing* boundaries ("we apply them here so indexing uses the post-rollback history rather than the raw stream", S-107 `thread_rollout_truncation.rs`), and its transcript-embedded `ghost_snapshot` items were retired with a loader that strips them (`recorder.rs` L1216) — evidence that snapshots do not belong inside the event stream (ADR-0026 selective sourcing). opencode's `revert` removes messages and restores a git tree (S-111 `revert.ts`); gemini-cli's `restore` reloads a saved history and checks out the shadow commit (S-119). AgentRewind keeps a "rewind memory" so the restored context knows what was tried (S-477); Codex's `<turn_aborted>` marker is the same idea for interrupts. **Implication:** `rollback` = `lifecycle.run.rolled_back{to_event_id, env_restore_ref, compensated[], uncompensable[]}` + `head.moved` (both already ADR-0026/0027 events) + an environment restore + a **rewind note** rendered to the model listing what persists (SF5 mitigation); nothing is deleted.

**F4 — Environment snapshots span a cost/coverage ladder, and each rung has a shipping precedent; none captures external state.** *Workspace tree*: opencode `write-tree` into a separate git dir with `read-tree` + `checkout-index -a -f` restore (S-111), gemini-cli shadow repository commits (S-119), Claude SDK per-file backups keyed by message (S-109), Codex per-path baselines and `WorldStateItem` baseline + patches (S-107). *Filesystem layer + processes*: Shepherd overlay copy-on-write plus "native checkpoint facilities of containerized sandboxes", 134–143 ms fork independent of image size (S-078); DeltaBox layer-switch rollback and fork-from-frozen-template, 14 ms / 5 ms (S-478); Crab eBPF-classified per-turn effects with checkpoints overlapped with model wait (S-475). *Full VM*: Firecracker memory + device state files, Cursor's checkpoint/restore/fork of VM images (S-481, S-052). What no rung covers: open network connections ("not guaranteed that the state of the network connections survives"), the guest wall clock (resumes at snapshot time), once-only identifiers and entropy (duplicated on multiple restores), and anything outside the sandbox. **Implication:** `EnvSnapshot` carries a declared `coverage` and an `uncaptured[]` list; the `reversible` class is only as wide as the coverage; a Stage-2 runtime needs the workspace-tree rung only (it is what four coding harnesses ship), the layer/VM rungs are C2 mechanisms behind the same contract (answers OQ-089's mechanism half; B5 picks per environment kind).

**F5 — The nondeterminism boundary has a mature systems answer: record every nondeterministic *input* at a narrow boundary and re-execute everything else.** rr records syscall results, signals, timestamp reads and asynchronous events, pins the recorded process to one CPU, and replays user-space computation unchanged; unrecorded shared memory and true parallelism are exactly what breaks it (S-480). Temporal's determinism rules are the same discipline applied to a workflow (S-193). Forgetting-Without-Restarting models the agent runtime "as a deterministic transition system" whose replay works because model outputs are recorded and cropping the KV cache restores state (S-479). Shepherd does *not* claim deterministic resampling; its replay is a byte-exact *prefix* reconstruction that keeps the provider prompt cache warm (~95 % hits), after which the suffix is re-executed with fresh samples (S-078). **Implication (with ADR-0028):** the runtime's nondeterministic inputs are enumerable — model responses, clock reads, randomness, environment observations, network responses, human decisions, external-service state, scheduling of concurrent scopes — and each is either *confined to events* (recorded and substitutable by a replay driver) or *declared* (`NondeterminismDeclaration`, ADR-0038). A branch's `replay_mode` is decided by which of these the prefix actually recorded, not by intent.

**F6 — Speculation over irreversible effects is a category error, and the systems that speculate say so.** Shepherd's irreversible tier "materialize[s] on emission, and the stream can only record them for audit"; Crab's speculative action execution forks a sandbox to "execute draft actions in parallel, and quickly discard or commit the fork" — all inside the sandbox; Revisable-by-Design proves conflicting irreversible actions defeat any algorithm (S-205 via WS-B2); *Safe to Resume?* SF5 is the duplicate-payment attack. ADR-0031 already forbids automatic retry of `irreversible` effects and requires a `CompensationPlan` for `compensable` ones. **Implication:** inside a speculative branch, `read_only` and `workspace_local reversible` effects run; `compensable` effects run only under an explicit policy with a registered compensator (discard = saga, ADR-0032); `irreversible` or `external` effects are **deferred** — recorded at `prepared`, never `committed`, released only on promotion, and surfaced to the model as deferred.

**F7 — Counterfactual re-execution has a stated validity condition and a cost model.** Shepherd's Appendix A.1 assumes "weak coupling between edits and side effects"; Forgetting-Without-Restarting shows that without token-level provenance "the post-target suffix is irreducibly tainted"; ADR-0028 (c) records that re-executed branches carry sampling noise. No source read here re-executes only *part* of the environment (OQ-024): every system re-executes the suffix from a snapshot and relies on cache reuse to make the prefix cheap. **Implication:** OQ-024's "without rerunning the entire environment" is answered *no for the suffix, yes for the prefix*: the prefix is reconstructed (snapshot + recorded observations), the suffix is re-executed; attribution is admissible only with the pairing design in §6.5 (a factual re-execution arm from the same fork point, n ≥ k seeds, matched budget), which is how OQ-082 is answered at the B4 level.

## 5. Disconfirming evidence & negative results

**Against runtime-owned branching at all (Managed Agents / Symphony stance).** Anthropic's Managed Agents and Symphony do not branch: a failed step is a tool error the model sees, and "the model decides whether to retry" (S-047 via WS-B2); Anthropic's long-running-harness guidance uses plain git commits as checkpoints (S-041). These are production systems at scale, and the C2/Could rating of R-2.2.4 reflects that the instrument can ship without speculation. *Why it does not overturn:* WS-I7's counterfactual attribution (R-2.9.7) and the Lab's tree-search/best-of-K arms need branches with a *valid* trace-environment cut; without a runtime contract every experiment re-invents OpenHands' shared-workspace fork. The decision is therefore staged: the Stage-2 slice is exactly what those systems already do (git-tree snapshot at turn boundaries, rollback as a record), and speculation proper is C2.

**Against environment-coupled forks (cost and coverage).** Coupling every fork to a snapshot makes forking as expensive as the slowest rung the environment supports; workspace-tree snapshots miss processes, caches and services; layer/VM snapshots miss network connections, the clock and entropy (S-481), and multiple restores duplicate once-only tokens — a security hazard of its own. Crab's finding that > 75 % of turns produce no recovery-relevant state says most snapshots are wasted. *Why it does not overturn:* coverage is *declared* on the record and bounds the `reversible` class, so an under-covering snapshot narrows what a branch may do rather than silently lying; snapshots are taken at fork points and effect terminals, not per event; the entropy/identity hazard is handled by forbidding restore-in-place of a snapshot that has already been restored (`EnvSnapshot` restores yield fresh handles with fresh identity material — invariant B6). The alternative, trace-only forks, is the demonstrated attack surface (S-476).

**Against refusing incoherent fork points.** A researcher may legitimately want to branch *inside* a model call (e.g., after the k-th tool call of a parallel batch) or mid-effect. Codex's own TODO wants "a coherent fork from the last stable model boundary" that does not exist yet. *Why it does not overturn:* the ledger records scope opens/closes, so "coherent" is computable; refusing is the safe default (Claude SDK precedent), `coerce_to_boundary` gives the nearest earlier coherent point, and finer boundaries (per tool call inside a batch) are admissible once every open scope at that seq is closed by a synthesized terminal event — which is what the Codex `Interrupted` variant does.

**Against deterministic replay as a meaningful mode (the ADR-0028 disconfirmation restated).** Even with recorded model I/O, an environment that was not fully snapshotted (network, clock, entropy) makes "deterministic" a claim about the *control decisions* only; rr shows how narrow the recordable boundary must be and how parallelism breaks it (S-480). Provider-side model changes (ADR-0038 F7) make even recorded responses unreproducible by re-sampling. *Why it does not overturn:* the `ReplayValidityReport` reports `deterministic` only for the control-decision sequence and the derived views (ADR-0038 R1's definition), never for re-sampled outcomes; every other case is `re_executed` or `degraded`, and the pairing design makes re-executed comparisons admissible statistically rather than pretending determinism.

**Against speculative execution of `compensable` effects.** Sagas guarantee only an acceptable approximation (S-197); a discarded speculative branch that opened a PR and closed it again leaves notifications, audit rows and rate-limit consumption behind; approval fatigue (S-053 via WS-B2) means the human gate on compensable effects is weak. *Why it does not overturn:* the default policy is **deny**: only `read_only` and `workspace_local reversible` effects run speculatively; `compensable` speculation is an opt-in `SpeculationPolicy` value (a `HarnessRule` artifact, MUST-data per ADR-0024) with a registered compensator, and the branch record lists every compensated effect for the lab and the audit trail.

**Against the "weak coupling" assumption of counterfactual replay.** Shepherd states it as an assumption; Forgetting-Without-Restarting shows the suffix after an intervention is "irreducibly tainted" without token-level attribution; an intervention that changes the definition (a `HirDiff`) may change what the *prefix* would have done too. *Why it does not overturn:* the assumption is *recorded* on every counterfactual branch (`InterventionRecord.coupling_assumption = weak`), the fork point is chosen at or before the earliest event the intervention could have affected (`intervention.earliest_affected_seq`, computed from `ir_refs[]` on ledger events, ADR-0027), and I7 decides admissibility; B4 only guarantees the data to decide with.

**Negative results.** No audited harness records a *replay mode* or a validity report on a fork — `no-precedent`. No audited harness defers irreversible effects inside a branch; all either run them or have no branches — `no-precedent / novel` as a contract (partial precedent: Shepherd's audit-only tier). No audited harness couples the fork record to a content-addressed environment snapshot *and* a trace position in one record — partial precedent (gemini-cli pairs a commit hash with a history; Shepherd does it in memory). OQ-024's hope of counterfactual execution "without rerunning the environment" has no precedent beyond prefix reuse.

## 6. Recommendation for the spec

### 6.1 Position

1. **Two branch granularities, one contract.** An *intra-run branch* is a subtree of the `parent_event_id` tree under one writer lease (ADR-0026/0027) — used for short speculation (best-of-K tool execution, alternative continuations, retry-with-rollback) and promoted/discarded by `lifecycle.head.moved`. An *inter-run fork* is a new run with `forked_from{run_id, at_seq, source_head_hash}` (ADR-0027 §6) — used for counterfactuals, long explorations, Lab arms and delegation. Both require a **coherent fork point** and both carry the same **branch record**.
2. **Trace and environment fork atomically.** A branch is created with an `EnvSnapshot` taken at the fork point, or is explicitly `trace_only` and restricted to `read_only` effects. Shared live environments after a fork are a refusal, not a default.
3. **Reconstruction + re-execution is the default replay mode; deterministic replay only where declared** (ADR-0028, phase-1 §6.9). Every branch records its `replay_mode` and a `ReplayValidityReport`.
4. **Speculation is contained by the effect risk class** (ADR-0031): `read_only` and `workspace_local reversible` effects run in speculative branches; `compensable` only under opt-in policy; `irreversible`/`external` are deferred until promotion and never run speculatively.
5. **Rollback never deletes.** It appends `lifecycle.run.rolled_back`, restores the environment, compensates what it can, lists what it cannot, and tells the model.
6. **Counterfactual branches carry an intervention record and are compared only against a factual re-execution arm** from the same fork point under matched budget (OQ-082 at the B4 level; WS-I7 finalizes).

### 6.2 Data-model sketch

**Fork point.** `ForkPoint = (run_id, seq)`; *coherent* iff at `seq` every `model_call_id` scope opened at or before `seq` is closed, every `effect_id` scope opened at or before `seq` is in a terminal state or in `deferred` (§6.4) or listed in `detached_effect_ids[]`, and `seq` is at or after `lifecycle.run.created`. Turn boundaries and effect terminals are always coherent; a `seq` inside a model-call scope is not. Derived, never stored: `coherent(run, seq)` is a `project`-class function over the durable prefix (ADR-0026).

**Branch record** (payload of `lifecycle.run.forked` on an inter-run fork, ADR-0027 §6; payload of the new event class `lifecycle.branch.opened` on an intra-run branch — CF-286):
`BranchRecord{ branch_id: EventId (the branch's first event; intra-run) | RunId (inter-run), fork_point: ForkPoint, source_head_hash, branch_kind ∈ {speculative, counterfactual, exploration, recovery, delegation}, env_binding ∈ {snapshot: EnvSnapshotRef, trace_only}, replay_mode ∈ {reconstruct_reexecute, deterministic}, intervention_ref?: ContentAddress (InterventionRecord), speculation_policy_ref: version_id, budget_id: BudgetNode (a slice of the parent's budget, ADR-0040 `slice`), permissions: attenuated from the parent (ADR-0034 delegation attenuates), seed: derived H(parent_seed ∥ branch_id) unless overridden, provenance: ProvenanceRecord{origin ∈ {runtime, lab, human, evolution}, authority ≤ delegate for lab/evolution}, disposition?: BranchDisposition }`.
`BranchDisposition = {promoted{at_seq} | discarded{reason, restored_to: EnvSnapshotRef, compensated: [effect_id], uncompensable: [effect_id]} | abandoned{reason} | merged{into_run_id, merge_ref} (F3 owns merge)}` — appended as `lifecycle.branch.disposed` on the parent run (intra-run) or on the fork's own ledger plus a `causes[]` link from the parent (inter-run). A branch has exactly one disposition; an open branch at run end is disposed `abandoned{run_finished}` by the runtime.

**Environment snapshot** (record the ledger references; never an event payload — F3):
`EnvSnapshot{ snapshot_id: ContentAddress (tree rule over workspace files for `workspace_tree`, per ADR-0036 N8; image/layer digest as `foreign_digest` claim for the other kinds), env_handle (WS-B5), taken_at: EventRef, kind ∈ {workspace_tree, fs_layer, process_image, full_vm}, coverage ⊆ {workspace_files, filesystem, processes, memory, devices}, uncaptured: [NondeterminismSource ∪ {network_connections, wall_clock, entropy, external_services, secrets}], restored_count: int (derived), cost{wall_ms, bytes}, idp }`. Event classes: `action.environment.snapshot{snapshot_ref}` (already in the WS-B1 table), `action.environment.restored{from: EnvSnapshotRef, new_env_handle, reason ∈ {rollback, discard, replay}}` (new, CF-286).

**Replay validity report** (stored as a blob referenced from the branch record; recomputable):
`ReplayValidityReport{ mode ∈ {deterministic, re_executed, degraded, invalid}, variant_declares_deterministic_replay: bool (ADR-0028), sources: [{source: NondeterminismSource, confined_to_events: bool, substituted: bool}], env: {binding, coverage, uncaptured[]}, model: {snapshot_record: ModelSnapshotRecord, fingerprint_match ∈ {match, mismatch, unknown}}, external_dependencies: [{effect_id, probed_at: EventRef, verdict}], reasons: [Text] }` with `NondeterminismSource = {provider_sampling, wall_clock, randomness, network, filesystem_order, concurrency, environment_state, human_input, external_service}` (extends ADR-0038's five-value set; CF-288).

**Intervention record** (the I7 hook):
`InterventionRecord{ kind ∈ {definition_diff, profile_diff, response_substitution, observation_substitution, decision_override, budget_change, permission_change}, target: EventRef | version_id, payload_ref: ContentAddress (a `HirDiff` for definition/profile kinds, ADR-0017; a recorded-event replacement otherwise), earliest_affected_seq: seq (derived from `ir_refs[]`), coupling_assumption ∈ {weak, declared_strong}, hypothesis: Text, provenance }`.

**Speculation policy** (MUST-data; a `HarnessRule`-class artifact so its delivery/activation/following is measurable, ADR-0024/0040):
`SpeculationPolicy{ allow_classes ⊆ {read_only, reversible_workspace_local, compensable}, default = {read_only, reversible_workspace_local}, require_compensator: true, max_concurrent_branches, budget_fraction, defer_irreversible: true (not overridable), coverage_required ⊆ EnvSnapshot.coverage }`.

**Rewind note** (rendered by WS-D1 into the model-facing view after a rollback or discard; a typed `Text` leaf with `authority = kernel`): `{rolled_back_to: EventRef, persisted_external_effects: [{effect_id, summary}], compensated: [effect_id], deferred_released: [effect_id], attempt_summary_ref?}`.

### 6.3 Interface-contract sketch (language-agnostic; operations · inputs → outputs · invariants · failure modes)

- `coherent_fork_points(run, from_seq?, to_seq?) → [seq]` — pure over the durable prefix.
- `fork(run, at: seq, kind, opts{env: snapshot | trace_only, replay_mode?, intervention_ref?, policy_ref, budget_slice, coerce_to_boundary: bool}) → BranchRef{branch_id | run_id, branch_record}` — inter-run: allocates a run per ADR-0027 §6 and appends `lifecycle.run.created{forked_from}` + `lifecycle.run.forked{BranchRecord}`; intra-run: appends `lifecycle.branch.opened{BranchRecord}` whose `parent_event_id = fork point` under the same lease. *Invariants:* B1 fork point coherent (or coerced, with a synthesized `lifecycle.turn.finished{stop_reason: forked}` on the parent); B2 the source prefix is untouched and pinned (ADR-0027); B3 `env_binding = snapshot` ⇒ `EnvSnapshot.taken_at.seq == fork_point.seq` and the branch runs on a *fresh* env handle restored from it; `trace_only` ⇒ the branch's `SpeculationPolicy.allow_classes = {read_only}`; B4 the branch budget is a `slice` of the parent's (reserve-before-spend, ADR-0040) and its permissions are attenuated (ADR-0034); B5 `replay_mode = deterministic` requires `variant_declares_deterministic_replay ∧ ∀ sources confined_to_events ∧ observability_level ⊇ model_io`, else the call downgrades to `reconstruct_reexecute` and records the reason. *Failures:* `ForkPointNotCoherent(seq, open_scopes[])`, `SnapshotUnavailable(kind)`, `CoverageInsufficient(required, available)`, `InsufficientBudget`, `PolicyForbids(class)`, `Fenced`, `UnknownForkPoint`.
- `snapshot(env_handle, kind?, reason) → EnvSnapshot` — content-addressed; idempotent for an unchanged environment (same tree ⇒ same `snapshot_id`); appends `action.environment.snapshot`. *Failures:* `SnapshotUnsupported(kind)`, `TooLarge(policy)`, `EnvBusy(open_effects[])` (a snapshot is refused while a non-`read_only` effect is between `committed` and its terminal on that handle).
- `restore(env_handle | new, snapshot, reason) → env_handle'` — yields a handle whose state equals the snapshot's covered state; appends `action.environment.restored`. *Invariants:* B6 a restore never reuses identity material outside coverage (fresh handle identity; `uncaptured[]` restated on the event); the same snapshot may be restored many times into distinct handles. *Failures:* `SnapshotMissing` (bytes GC'd — hash still verifiable, ADR-0026 §6.5), `CoverageMismatch`, `RestoreFailed(io)`.
- `promote(branch) → seq` — intra-run: `lifecycle.head.moved{to: branch_leaf}` + `lifecycle.branch.disposed{promoted}`; then every effect in `deferred` on the branch is re-authorized (fresh `security.permission.decided` — approvals are never inherited across branches, ADR-0035) and released `prepared → committed` in branch order; the parent's env handle becomes the branch's. Inter-run: the fork's own run continues; the parent appends `lifecycle.branch.disposed{promoted}` and either finishes with `stop_reason = superseded_by{run_id}` or continues as a sibling (Lab arms). *Failures:* `BranchNotOpen`, `DeferredEffectRefused(effect_id)` (promotion completes; the refused effect becomes `refused` and the model is told).
- `discard(branch, reason) → BranchDisposition` — `head.moved{to: fork_point}` (intra-run) or `lifecycle.run.finished{stop_reason: discarded}` (inter-run); `restore(parent_env, branch.env_snapshot)`; for every `observed(applied)` effect on the branch, in reverse commit order: `reversible` ⇒ covered by the restore (recorded as `action.effect.reverted{baseline_ref = snapshot}`), `compensable` ⇒ `compensate` (ADR-0032 saga; `abandoned` on failure, escalated), `deferred` ⇒ `action.effect.refused{reason: branch_discarded}`; the disposition lists `compensated[]`/`uncompensable[]`; a rewind note is rendered. *Invariants:* B7 the discarded events remain in the ledger and outside `path_to_root(HEAD)`; B8 no `irreversible` effect can be on a discarded branch in state `observed(applied)` unless the policy explicitly allowed `compensable` and the effect was mis-classified — such a case is `uncompensable[]`, always escalated (AC-B4-6).
- `rollback(run, to: seq, reason) → RollbackRecord` — sugar for "open a recovery branch at `to`, discard everything after it": `lifecycle.run.rolled_back{to_event_id, env_restore_ref, compensated[], uncompensable[], reason}` + `head.moved` + `restore`; B3 consumes it in its recovery procedure; Codex `ThreadRolledBack` semantics with the environment added.
- `replay(run | branch, driver_mode ∈ {reconstruct, deterministic}, until?: seq) → ReplayHandle` — `reconstruct` rebuilds views and the environment (snapshot + recorded observations) without re-executing anything (ADR-0028 §1); `deterministic` drives a declaring variant with recorded model responses and effect outcomes substituted (ADR-0028 §2) and *never dispatches* an effect (Fowler's external-gateway rule) — a divergence (the variant issues a call the record does not contain) is `ReplayDiverged(at_seq, expected, got)` and downgrades the report to `invalid`. Every replay appends `lifecycle.replay.started/finished{mode, report_ref}` on the *branch* (the source is untouched).
- `validity(branch) → ReplayValidityReport` — pure over the branch record, the source prefix and the bundle's `NondeterminismDeclaration[]`/`ModelSnapshotRecord`; the mode is the *minimum* over sources: any unrecorded source consumed in the prefix ⇒ `re_executed`; fingerprint mismatch or an external dependency whose probe verdict differs from the recorded observation ⇒ `degraded`; incoherent fork point, `trace_only` with non-`read_only` effects, or `ReplayDiverged` ⇒ `invalid`.
- `counterfactual(run, at: seq, intervention: InterventionRecord, design{n_seeds, budget: MatchSpec, factual_arm: true}) → {factual: [BranchRef], counterfactual: [BranchRef], comparison_ref}` — the I7 hook: refuses `at > intervention.earliest_affected_seq` (`InterventionPrecedesForkPoint`), refuses without a `MatchSpec` (T-LCD-14, ADR-0041), opens `n_seeds` factual re-execution branches (no intervention) and `n_seeds` counterfactual branches from the same fork point and snapshot, all `branch_kind = counterfactual`, `charged_to = instrument` (ADR-0039), and hands the pair set to WS-I2's paired protocol (ADR-0046) with `benefit_kind = artifact_benefit` and `replay_mode` on every row. Results rows are keyed by `(configuration_version_id, run_id)` (ADR-0036) and additionally carry `branch_kind`, `fork_point`, `replay_mode`.

Effect-lifecycle addition (CF-287, for ADR-0030's amendment log): a non-terminal state **`deferred`** entered from `prepared` by `action.effect.deferred{effect_id, reason ∈ {speculative_branch, awaiting_promotion}, branch_id}`, leaving only to `committed` (on promotion, after fresh authorization) or `refused` (on discard/abandon). The model receives an observation "deferred until this branch is promoted" (never a fabricated success — WS-G2 treats a deferred effect as not applied).

Hosted participants (T-LCD-06/07): a hosted participant may be forked only if its capability declaration says `fork = supported` and its hosting mechanism can supply an environment snapshot at the declared coverage; otherwise `fork` returns `n/a{reason: class}` and every branch metric is `n/a` (T-LCD-15). No native contract changes for them.

### 6.4 Speculative-effect policy (the containment table)

| effective risk class (ADR-0031) | in a speculative branch | on `promote` | on `discard` |
|---|---|---|---|
| `read_only` | runs (at-least-once) | nothing | nothing |
| `reversible`, `workspace_local`, target covered by `EnvSnapshot.coverage` | runs | nothing (the branch env becomes live) | covered by `restore`; `action.effect.reverted{baseline_ref = snapshot}` |
| `reversible` but target **not** covered (or `external`) | treated as `compensable` (ADR-0031 scope rule) | — | — |
| `compensable` | runs **only if** `SpeculationPolicy.allow_classes ∋ compensable` and a `CompensationPlan` is registered at `prepare` (ADR-0032); default **deny** ⇒ deferred | nothing | `compensate` in reverse order; failure ⇒ `abandoned` + escalation |
| `irreversible`, or any `external` effect not compensable, or `unknown` class | **deferred** at `prepared` (`action.effect.deferred`); the model is told; the branch may continue past it only if the capability declares the effect's output is not needed (else the branch pauses `awaiting_promotion`) | re-authorized (fresh approval; never inherited), then `committed` in branch order | `refused{branch_discarded}` |
| `model_call` domain (spend) | runs, charged to the branch's budget slice; `attribution = subject` for harness-initiated speculation, `instrument` for Lab/I7 branches | — | spend is not refundable; recorded as `branch_kind` cost for J4's Pareto reporting |
| `message_human`, `permission_request` | deferred (a speculative branch never interrupts the principal) | released | refused |

Rules: (a) classification uses `effective_risk_class` — a model-declared class never lowers containment (ADR-0031); (b) `defer_irreversible` is not overridable by any policy layer (`authority_cap`, ADR-0024); (c) K concurrent branches each hold a distinct env handle and a distinct budget slice; the parent's writer lease serializes their appends; (d) a branch inherits the parent's `context_label` and may only narrow it (ADR-0034); (e) approvals granted on the parent do not cover branch effects (new `effect_id`s; ADR-0035 "approval endorses one `effect_id`"); (f) detached effects (`detached_effect_ids[]`, ADR-0030) started on a branch are terminated on discard and re-parented on promote (OQ-090 owner WS-E5 to confirm).

### 6.5 Nondeterminism recording rules and replay validity (answers OQ-082 at the B4 level; input to OQ-113)

**What a run must record for each source** (the rr rule applied to the harness; every item is an existing ledger event class unless marked *new*):

| source | recorded as | required for `deterministic` | if not recorded |
|---|---|---|---|
| `provider_sampling` | `model.call.requested.request_ref` + `model.call.completed.response_ref` (ADR-0029 offload; `observability_level ⊇ model_io`) + `ModelSnapshotRecord` + seed in the manifest | yes | `re_executed` |
| `wall_clock` | the control strategy reads time only through the runtime clock; a declaring variant's reads are logged as `control.clock.read{value}` (*new*, `durability = ledger` only for declaring variants; else ephemeral) | yes | `re_executed` |
| `randomness` | PRNG seeded from `configuration_version_id.seed ∥ branch_id`; external randomness logged as `control.random.read` (*new*, same durability rule) | yes | `re_executed` |
| `environment_state` (filesystem, processes) | `EnvSnapshot` at fork points and at every effect terminal that changed covered state (Crab's "recovery-relevant" test; B5 may coalesce per turn) | snapshot at the fork point | `degraded` if the branch reads uncovered state |
| `filesystem_order`, `concurrency` | declared only (`NondeterminismDeclaration.confined_to_events = false`); the parent's writer lease fixes the *event* order, not the scheduling of parallel scopes | never | `re_executed` for any branch whose prefix contains parallel scopes, unless the variant declares single-scope scheduling |
| `network` / `external_service` | tool observations are `context.observation.recorded`; deterministic replay substitutes them; live branches re-issue and record `external_dependencies[].verdict` via `probe` (ADR-0030) | yes (substitution) | `degraded` when a probe contradicts the recorded observation |
| `human_input` | `security.permission.decided{decider: human}` and principal messages (`lifecycle.turn.started.inputs`) | substituted in `deterministic`; **never reused** for new effects on a live branch | `re_executed` (approvals re-requested) |

**Validity verdicts.** `deterministic` — every source consumed in the prefix is confined to events, the variant declares `deterministic_replay`, the fork point is coherent, `fingerprint_match ≠ mismatch`, and the replay driver reproduced the recorded `control.decision` and `view_hash` sequences up to the fork point (AC-B1-4 as a precondition); the branch's *derived views* then re-derive bit-exactly (ADR-0038 R1) and its suffix decisions are reproducible given identical model responses. `re_executed` — coherent fork point, snapshot-coupled environment, one or more sources unrecorded or the variant undeclared; outcomes differ by sampling; admissible only under the pairing design below. `degraded` — as `re_executed` but with evidence that the world moved (model fingerprint mismatch, external probe contradiction, uncovered environment reads); reported, never hidden, and excluded from `artifact_benefit` rows by default. `invalid` — incoherent fork point, `trace_only` branch that executed a non-`read_only` effect, `ReplayDiverged`, or an intervention that precedes the fork point.

**Pairing design for OQ-082 (B4 level).** A counterfactual claim is admissible only as a `ComparisonReport` (phase-1 §6.9) whose arms are (i) `n ≥ k` factual re-executions from the fork point and (ii) `n ≥ k` counterfactual branches from the same fork point and snapshot, seeds as the replicate axis (ADR-0045), `MatchSpec` matched on the suffix budget (ADR-0041), reported as distributions with `replay_mode` on every row; the factual arm's dispersion is the noise floor and is always reported. With `deterministic` mode, `k = 1` suffices for the decision sequence but not for outcomes. WS-I7 sets `k`, the margin and the attribution statistics (OQ-113 shares the margin question with WS-I2).

### 6.6 Acceptance-criteria sketch

- **AC-B4-1 Coherence.** `fork` at a seq inside an open model-call or effect scope returns `ForkPointNotCoherent` listing the open scopes; with `coerce_to_boundary` it forks at the nearest earlier coherent seq and the parent gains a synthesized `lifecycle.turn.finished{stop_reason: forked}`; `coherent_fork_points` agrees with a brute-force scan on the Stage-3 corpus.
- **AC-B4-2 Atomic coupling.** After `fork(env: snapshot)`, the branch's env handle differs from the parent's, `restore`-derived state equals the snapshot's covered state (tree hash equality for `workspace_tree`), and a write on the branch is invisible to the parent's handle; a `trace_only` fork that proposes a non-`read_only` effect gets `PolicyForbids`. (The OpenHands shared-workspace behaviour is the regression case.)
- **AC-B4-3 Source immutability.** After any fork, promote, discard or rollback, the source prefix's `head` hash at the fork point is unchanged and `verify` passes (ADR-0026 AC-B1-1/-9 lifted to branches).
- **AC-B4-4 Discard restores.** A branch that applied N `reversible` workspace effects and is discarded leaves the parent's environment tree-hash-equal to the fork snapshot; the discarded events remain readable by `read` and are absent from `project(context_view)`; the rewind note is present in the next `context.assembled`.
- **AC-B4-5 Deferral.** In a speculative branch, an `irreversible` probe tool reaches `prepared → deferred`, is never `committed`; on `promote` it is re-authorized (a new `security.permission.decided` exists; the parent's cached approval is not cited) and then committed once; on `discard` it is `refused{branch_discarded}`; the model-facing history shows "deferred" and never a success. (Duplicate-payment scenario from S-476 as a fault-injection test, joined with WS-B2 AC-B2-01.)
- **AC-B4-6 No irreversible loss on discard.** Fault injection that misclassifies a compensable effect as reversible yields an `uncompensable[]` entry in the disposition, an `abandoned` effect and an escalation event — never silence.
- **AC-B4-7 Replay modes.** For a declaring variant with `model_io` recorded, `replay(deterministic)` reproduces the `control.decision` and `view_hash` sequences and dispatches zero effects (executor call count = 0); for a non-declaring variant the report is `re_executed` and `validity` explains which sources; injecting a fingerprint mismatch or a contradicting probe yields `degraded`; forking mid-scope yields `invalid`. `n/a` (never 0) for hosted participants without `fork`.
- **AC-B4-8 Counterfactual hook.** `counterfactual` refuses without `MatchSpec` (`UnbudgetedArm`) and when `at > earliest_affected_seq`; the produced rows carry `branch_kind`, `fork_point`, `replay_mode`, `charged_to = instrument`; the factual arm's distribution is present in the `ComparisonReport`.
- **AC-B4-9 Snapshot semantics.** Two snapshots of an unchanged workspace share one `snapshot_id`; `restore` of a GC'd snapshot returns `SnapshotMissing` and the hash still verifies; restoring one snapshot twice yields two handles with distinct identity material; `uncaptured[]` on a `full_vm` snapshot includes `network_connections, wall_clock, entropy`.
- **AC-B4-10 Budget and authority containment.** Branch spend posts to the branch's slice (`control.budget.consumed`), root-first exhaustion ends open branches with `abandoned{budget_exhausted}`; a branch cannot hold an authority its parent lacks (`AuthorityWidening` at `fork`).
- **AC-B4-11 Rebuildability.** `project(branch_tree)` and every `ReplayValidityReport` rebuild from the ledger alone with equal hashes (ADR-0026 AC-B1-3).

### 6.7 Build-stage suggestion

- **C0 / Stage 2 (the reversible slice, with B1's `fork/navigate/rolled_back` and B5's handles):** `coherent_fork_points`; inter-run `fork` with `env: snapshot | trace_only`; `EnvSnapshot{kind: workspace_tree}` via `snapshot`/`restore`; `rollback` with restore, compensation list and rewind note; `lifecycle.branch.opened/disposed`, `action.environment.restored`, `action.effect.deferred` event classes; `BranchRecord`; static AC-B4-1/-3/-9.
- **C0 / Stage 3 (evaluation-first):** `replay` (both driver modes), `validity`/`ReplayValidityReport`, `NondeterminismSource` recording rules for declaring variants (`control.clock.read`, `control.random.read`), `counterfactual` hook with the pairing design; AC-B4-2/-4/-7/-8/-11 in the Stage-3 suite; this is also where ADR-0028's AC-B1-4 lands, so the replay driver is shared.
- **C2 / Stage 4 (speculative execution proper):** intra-run branches under one lease, K concurrent branches with distinct env handles and budget slices, `promote`/`discard` with deferred-effect release, `SpeculationPolicy` as a `HarnessRule`, `compensable` opt-in; `fs_layer`/`process_image`/`full_vm` snapshot rungs behind the same contract (B5 mechanism); AC-B4-5/-6/-10.
- **C4 / Stage 6:** WS-I7 attribution over counterfactual branches; evolution proposals evaluated as counterfactual arms (WS-I5).

**ADR-0024 ladder:** `fork/snapshot/restore/replay/validity` and the deferral rule are **MUST-code** (kernel: effect model, ledger, monitor); `SpeculationPolicy`, `coverage_required`, `max_concurrent_branches`, `budget_fraction` and the rewind-note template are **MUST-data** (parameters / `HarnessRule` / `Text` leaf).

**T-LCD statement.** Satisfies **T-LCD-08** (the branch policy, replay driver and validity report are contract inputs that receive `(ModelProfile, ResourceAccount)`; `deterministic_replay` is declared per control-strategy variant, never assumed), **T-LCD-06/07** (no native field exists for hosted participants; `fork` is a declared capability, `n/a` when absent), **T-LCD-15** (branch and replay metrics are class-scoped and `n/a` for hosted participants), **T-LCD-14** (`counterfactual` refuses un-budgeted arms), **T-LCD-09** (branch rows carry factor coordinates plus `branch_kind`/`fork_point`/`replay_mode`), **T-LCD-10** (snapshot identity is content-addressed, never a handle name), **T-LCD-12** (operations, out-of-process implementable), **T-LCD-02** (the rewind note is a typed `Text` leaf with `authority = kernel`). Not addressed (owned elsewhere): T-01/-03/-04/-05/-11/-13.

## 10. Confidence

**High** for the coherent-fork-point rule, source immutability, rollback-as-record and the workspace-tree snapshot rung: four coding harnesses at pinned commits converge (Codex, opencode, gemini-cli, Claude SDK), and the counter-example (OpenHands shared workspace; LangGraph environment-free checkpoints) is the exact failure class a 2026 security study demonstrates. **High** for the containment table's shape, because it is a projection of the ratified ADR-0031/0032 classes; **medium** for the `deferred` phase and promotion-time re-authorization, which have only partial precedent (Shepherd's audit-only tier) and are `novel` as a contract. **Medium** for the nondeterminism recording rules: the boundary discipline is Tier-B systems practice (rr, Temporal) and the `deterministic` mode is already scoped by ADR-0028, but the clock/random event classes and their cost are untested. **Medium-low** for the counterfactual pairing design: it follows ADR-0045/0046 mechanically, yet the admissibility margin is I7's to set and the weak-coupling assumption is a stated assumption of a `provisional` source. **Low** on every 2026 latency or correctness number; none is load-bearing. No C0/Stage-2 element rests on `provisional` evidence alone.
