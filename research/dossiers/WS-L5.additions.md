## Ontology terms

| term | definition | notes |
|---|---|---|
| plugin (amendment) | The packaging unit for third-party contributions: an extension record of kind `plugin` whose manifest (`PluginManifest/1`) is an inventory of registry-kind contributions and whose behaviour is the closure of those contributions; it has no behaviour of its own. | Amends the ADR-0008 gloss "plugin = third-party packaging"; ADR-0180 |
| plugin manifest (`PluginManifest/1`) | `{identity, requires{hir_dialect, registry_dialect, plugin_abi, contracts[], records[]}, contributions[], requests, claims, conformance_claims[], parameters?, summary, ext}`; data only; unknown non-`ext` keys and unknown contribution kinds are errors. | ADR-0180 |
| contribution | One manifest entry that resolves to one `registry/1` record (variant, capability/MCP server, procedure profile/skill, hook, validator, model profile, surface family, benchmark adapter, environment family, metric declaration, instruction file, harness rule) with its own identity and, if executable, its own trust legs. | ADR-0180; WS-J2 record kinds |
| contract reference (`ContractRef`) | `{kind ∈ {class_contract, record_kind, dialect, protocol_binding}, id, version_range}` — the only form a dependency may take; anything not reachable through one is an *internal*. | ADR-0182 X1 |
| contract version policy | `ContractVersionPolicy{contract, supported[], sunset{}, additive_only}` — a `hh/` registry record stating which contract versions the Core supports and when each sunsets; additive changes never bump a version. | ADR-0180; OQ-411 |
| plugin ABI (`plugin_abi/1`) | The kernel↔extension binding of the WS-L1 §6.5 ecosystem-boundary contract: verbs `hello/bind/invoke/stream/cancel/unbind/close`, closed host callbacks, invariants V1–V6; distinct from the Hosting ABI (CF-208) and from MCP (ADR-0096). | ADR-0181 |
| variant host | The Core component (MUST-code) that drives every non-kernel executable contribution over `plugin_abi/1`, chooses the placement, enforces V1–V6, and doubles as the `registry_ci` conformance driver. | ADR-0181 |
| placement | `{in_process (kernel-ecosystem first-party only), subprocess_confined, container, remote}` + reserved `component_model`; = isolation class minus `host_unconfined`; the primary "where does this code run" field on a variant registration; `locality` is a derived view. | CF-378 |
| binding record | `{binding_id, slot, class_id, contract_version, variant, placement, host_id, permission, budget}` — the run-time instance of a slot filled through the variant host; recorded by `lifecycle.component.bound`. | ADR-0181 |
| host callback | The closed set of plugin→kernel operations `{propose_effect, read_view, request_budget, emit_diagnostic}`; no callback names another extension, the agent loop, the gateway, the session store or the monitor. | ADR-0181 |
| guard verdict | `{pass, annotate(Text ≤ external), narrow(deny \| ask \| attenuate), propose_replacement(Proposal at ≤ hook authority), no_decision}` — the only output of a hook/guard invocation; never `allow`, never a mutated input, never a label. | ADR-0181; OQ-165 (L5 half) |
| meet composition (of guards) | Order-independent combination of guard verdicts at one decision point: `deny > ask > attenuate > annotate > pass`; `propose_replacement` re-enters authorization; `no_decision` is the identity unless the rule is `required` (then `deny`). | ADR-0181 |
| authority crossing | The violation in which a plugin message carries a permission, label, kernel decision, lowered risk class or raised retryability; refused, with `security.extension.violation`. | ADR-0181 V1 |
| reach / internal | *Reach* = what an extension may depend on or observe = the set of `ContractRef`s and pinned records it declares; an *internal* is anything else (another extension's implementation, process, files, private records; kernel projections beyond granted views; Π; the handle table). | ADR-0182 X1 |
| tier declaration / extension DAG check / removability | `tier ∈ {C0..C4}` + `depends_on: [ContractRef]` on every spec item, class record and plugin; the readiness-gate check for `tier_violations = []` and acyclicity (generalising `hosting_edges = []`); the per-tier build with higher tiers absent whose acceptance suite must be unchanged. | ADR-0182 X2/X4 |
| boundary overhead | `boundary_overhead_ms` per `(class_id, placement)` measured at the proposed M19 point on every variant-host invocation; a class-scoped metric and a Lab stratification coordinate; `n/a` for hosted participants. | CF-377; OQ-075 |
| plugin conformance kit | The Stage-3 deliverable: one null plugin per Stage-1–3 class, the hostile plugin fixture, and the golden manifest corpus, run by the variant host as `registry_ci`. | ADR-0181 §7 |
