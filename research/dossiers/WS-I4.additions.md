## Ontology terms

| term | definition | notes |
|---|---|---|
| environment family | One of the closed dialect sum `{coding_terminal, browser_computer, search_research, structured_tool, persistent_multi_episode, adversarial_security, long_running_recovery}` by which the stratified suite is organised (doc 2 §8); a task carries one primary family plus tags. | WS-I4; grows by ADR; scope of `applies_to_families`. |
| environment-family record / handle requirements | The registry record for a family: tri-state `HandleRequirements` the WS-B5 handle must declare, oracle classes available, submission kind, default verifier isolation, admissible fault/perturbation profiles, episode model. | WS-I4 / WS-B5; `FamilyUnsupported{missing}` at `materialize`. |
| benchmark adapter | The component class (`benchmark_adapter`, one per suite, out-of-process by default) with operations `declare, discover, import_task, materialize, expose, collect_submission, grade, export, parity`; participants never call `grade`. | WS-I4; precedents Harbor `BaseAgent`/verifier, terminal-bench adapters, SWE-agent instance sources. |
| task record | The typed, content-addressed import of one foreign task with three disjoint surfaces (visible / held-out / instrument), an `EnvironmentSpec`, a `split_label`, validity and contamination annotations, and foreign identity as claims. | WS-I4; `task_id` excludes `foreign`, validity, contamination and provenance. |
| visible surface / held-out surface / instrument surface | What a participant may see (instruction, attachments, declared metadata scope) / grader-only assets never delivered (validators, fixtures, goal states, oracle solutions) / adapter and grader configuration, budgets, validity, contamination. Task-level form of WS-G1's per-criterion `visible`/`held_out`. | WS-I4 / WS-G1. |
| task metadata scope | The `[ResourcePattern]` a participant may read as task metadata; the scope WS-G1's `MetadataShortcut` veto is evaluated against (CF-WS-I4-04). | WS-I4 / WS-G1. |
| suite manifest | Content-addressed record of a suite: tasks, splits with `split_hash`, `SuiteValidityRecord`, adapter ref, parity report, foreign identity claims. | WS-I4 / WS-J5 / WS-I3. |
| split label / split assignment record | `split_label ∈ {dev, search, held_out, public, private, control}` on every task; the ledger record `{rule, seed, splits, split_hash, registered_at}` that must precede the first search run (ADR-0046 `LeakedSplit`). | WS-I4 / WS-I2 / WS-I5. |
| suite validity record / noise ceiling / retired for headline | Dated record `{audit_ref, audited_at, flawed_task_ids[], noise_ceiling?, retired_for_headline, reason?}` carried beside every results row; a suite retired for headline appears only in round-trip/control rows. | WS-I4 / WS-J4; motivated by S-WS-I4-03/-04. |
| contamination stratum / training cutoff claim | `stratum ∈ {private_held_out, fresh_temporal, public_dated, contaminated_public, unknown}` per task from `first_public_at`; `training_cutoff_claim{value?, provenance}` per model snapshot; capability reported per stratum, pooling refused unannotated. | WS-I4 / WS-J4 / WS-C1 / WS-L4 (CF-WS-I4-08). |
| parity report | An ADR-0046 `ComparisonReport{benefit_kind = artifact}` between an adapter's path and the original runner on the same participant, snapshot, tasks and budget with a pre-registered margin; adapter admissibility precondition. | WS-I4; precedent terminal-bench `parity_experiment.json`, S-133. |
| verifier isolation (`separate` / `shared`) | Whether grading runs in a fresh environment materialised from the same digest with the submission applied, or in the subject's environment; `shared` is a declared weakening rendering the tamper veto `n/a{no_detector}`. | WS-I4 / WS-G1; precedent Harbor `VerifierEnvironmentMode`, SWE-bench regrade. |
| submission / submission kind | The content-addressed artifact collected after the participant's terminal event for grading: `patch, end_state, output, action_log, none`. | WS-I4; precedent mini-swe-agent `submission`, SWE-bench `model_patch`. |
| lift report | The adapter-side lowering loss report of an import: foreign fields with no typed home (preserved in `ext`), unresolved digests, undeclared scopes. | WS-I4; T-LCD-11 in the lifting direction. |
| benchmark-conditioned rule | A `HarnessRule`, `ProfileRule`, `Text` leaf, slot binding, parameter or `ext` entry in a sealed definition that references a suite/task/family identifier as a condition; refused at `seal` (`BenchmarkConditionedRule`, error). Family-conditioned variants with `applies_to_families` are the permitted form. | WS-I4 / WS-A5 / WS-A4; T-LCD-01 analogue; `no-precedent / novel`. |
| held-out leak / held-out in environment | Kernel error + veto when a held-out item reaches `context.artefact.delivered` (WS-G1 I2) / import error when the build context or workspace tree contains a held-out fixture (Terminal-Bench Dockerfile check generalised). | WS-I4 / WS-G1. |
| benchmark egress | Veto `trace_predicate`: any `security.egress.attempted/blocked` to a non-allowlisted destination during the agent phase. | WS-I4 / WS-H4. |
| infrastructure-failure classification | Read-only, advisory detector over grader logs mapping environment-fault signatures to `tier ∈ {environment, ambiguous}`; `environment` ⇒ `outcome_class = infrastructure_failure{reason, tier}`, `ambiguous` ⇒ `scored` with `infra_suspected`; denominators remain metric-owned. | WS-I4 / WS-I2; precedent SWE-bench `infra_failure.py`. |
| foreign task identity | `foreign{suite_ref, foreign_id, foreign_digest?, version_label?, first_public_at?}` — claims recorded on the task record and excluded from native identity (CF-087). | WS-I4 / WS-L4. |
| participation | Acting as a participant in an external evaluation plane (Harbor, Harness-Bench, Inspect): the native harness lowered to a container-installed or ACP participant surface, with the plane's trajectories/results imported as `product` rows. | WS-I4 / WS-J6 / WS-K1; ADR-0005. |
