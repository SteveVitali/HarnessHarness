## 1. Scope & boundary

This workstream decides **caching as a resource-model concern**: (i) a **cache taxonomy** — which caches exist between the kernel and a model snapshot, who owns each, and what "hit" means for each; (ii) the **layout constraints** handed to WS-D1/WS-C3 so that the compiled prompt layout is *prefix-stable* and provider prompt caches (KV/prefix caches) can be hit deliberately rather than accidentally; (iii) the **prefix affinity key** and **expected-vs-observed cache state** the kernel derives and records per model call (the mechanism that answers OQ-097); (iv) the **accounting** of cache reads, writes, avoided calls and avoided spend into the ADR-0039 charge model and the ADR-0044 metric catalogue; (v) the **validity semantics** of harness-level caches — a tool-result/retrieval cache expressed as a WS-D4 memory kind with an `InvalidationContract`, an exact-match response cache admissible only under declared conditions, and a verified similarity-keyed semantic cache deferred to C2; (vi) the **invalidation rules** that tie every cache key to WS-L4 version identities so a profile, definition, capability or dialect version change is a deterministic miss, never a stale hit.

It explicitly leaves to neighbours: the provider request plan, the wire codec, `usage_mapping` and the `cache_semantics`/`cache_state_visible` fields of the `WireDialect` descriptor (**WS-C1** — consumed verbatim; this dossier supplies the values those fields take and the observation fields the gateway stamps); the `caching_markers` rule inventory and probes (**WS-C3** under ADR-0020 — this dossier fixes the rule's *parameters and invariants*, C3 designs the per-family rules and their debt records); slot admission, `cache_tier` and the executed renderer spec (**WS-D1** — this dossier hands D1 the layout constraints LC-1…LC-9 and proposes one field); the memory lifecycle, `InvalidationContract`, conflict sets and enforcement points (**WS-D4** — the tool-result cache is a `Memory` kind and reuses D4's contract without a second scheme); compaction triggers and context-editing (**WS-D2** — this dossier states only what compaction must *record* about cache invalidation); tool-catalog caching and deferral (**WS-E3** — MCP `ttlMs`/`cacheScope` are E3's; this dossier fixes only their accounting); routing (**WS-C2**); budget `check/reserve` (**WS-F2**); the experiment engine's factor semantics (**WS-J3** — this dossier defines the `cache_policy` factor and the refusal rule); every language, runtime or library choice (ADR-0050 §8).

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — There are four distinct cache semantics between a harness and a model snapshot, and the audited harnesses that named them did so as a provider-name branch.** goose declares `ExplicitBreakpoints{max}` ("reuse needs an exact match of the marked bytes"), `ImplicitTolerant` ("the longest matching stored prefix is reused"), `ImplicitStrict` ("only extends a prompt reproduced byte-for-byte from the start") and `Uncached`, defaulting unknown pairs to strict "which is safe for every cache" — but selects them by `match provider_name` (`cache_semantics.rs` L23–46). opencode keeps the same partition as a set constant (`RESPECTS_INLINE_HINTS`). The vendor docs add a fifth: Gemini's explicit cache is a *server-side resource* referenced by name with its own TTL and storage price (S-WS-C4-08), which is neither a marker nor an implicit prefix. **Implication:** `CacheSemantics` is a closed kernel sum `{explicit_breakpoints, implicit_prefix, explicit_resource, uncached, unknown}` carried as *data* on the `WireDialect` descriptor (WS-C1 already reserves the field) with per-model overrides in the Model Profile's capability declaration (`cache_control_convention`, ADR-0020) — the same split as `usage_mapping` (CF-106). A provider-name branch anywhere in kernel or gateway code is the T-LCD-01 failure signature.

**F2 — Provider prefix caches are keyed on exact bytes in a fixed hierarchy, and every audited harness re-derives the same layout rule from that fact: stable material first, volatile material last, one marker per tier.** Anthropic: "Cache hits require 100% identical prompt segments"; hierarchy `tools → system → messages`; "changes at each level invalidate that level and all subsequent levels"; `tool_choice` and images invalidate system+messages; thinking/effort parameters are "model-specific" (S-213). OpenAI: routing hashes "the initial tokens … including tool definitions"; verbosity and reasoning-effort changes break the prefix (S-215). Gemini: "large and common contents at the beginning" (S-WS-C4-08). The harnesses converge: goose marks the last tool, the system block and the last two user messages; opencode's `AUTO` marks last tool + last system part + latest user message and allocates the 4-marker budget "in invalidation order: tools → system → messages", shedding message-tail markers first; pi marks the last user message's last block; codex keeps an exhaustive list of request properties whose change forbids reuse. WS-D1 already fixes that `kernel`/`definition` slots are `static` tier and `transcript` is `transcript`, and reserves volatile kernel items (current time, budget reminders) in `ContextBudget.reservations`; WS-E3 requires tool-surface order to be a prefix-extension across calls (AC-E3-4). **Implication (§6.2):** the layout constraints are kernel-level *invariants over the compiled layout* — static tier before dynamic before transcript; no volatile value in the static tier; tool surfaces order-stable; markers placed by tier boundary — while *which* boundaries get markers, the TTL class and the lookback anchor are profile `caching_markers` rules with assumption-debt records.

**F3 — The provider's cache has a lookback window and a marker cap, and violating either fails silently or with a 400.** Anthropic checks "at most 20 positions per breakpoint" and allows 4 markers; below the per-model minimum length "requests … will be processed without caching, and no error is returned" (S-213). goose implements a *secondary anchor ~20 blocks behind* the primary so that a turn with many parallel tool calls does not push the previous entry out of the window (`cache_semantics.rs` L74–83), and notes that anchoring by role "would … re-bill the growing agentic tail on every iteration"; opencode counts markers against the cap and drops the excess with a *log warning* (`anthropic-messages.ts` L534–537); pi and goose omit markers on blocks that cannot carry them (empty text, thinking). **Implication:** marker placement is a rule with parameters (`max_markers`, `lookback_positions`, `anchor_distance`, `carrier_block_kinds`) that expire with the provider (T-LCD-05); the codec enforces the cap and **records** dropped markers on `model.call.requested` (never only a log); a request under the minimum cacheable length is recorded as `expected_state = uncacheable`, so a zero cache-read is not misread as a miss.

**F4 — The affinity key is a session identity in every audited system, and two of them scope auxiliary calls to their own key to keep them off the main prefix.** opencode sets `prompt_cache_key = sessionID` for five SDK families (`transform.ts` L1310–1322); pi clamps the key to 64 characters (`openai-prompt-cache.ts`) and drops the session id entirely when retention is `none`; codex derives `"{source}:{parent_thread_id}"` for internal sub-sessions and `"guardian:{parent_thread_id}"` / `"guardian-v2:{thread_id}"` for reviewer/scorer sub-agents (`client.rs` L491–505, `review_session.rs` L302–314, `sampler.rs` L340); pi's compaction summaries use `cacheRetention: "none"` and a fresh session id "to isolate routing and avoid cache writes that cannot be reused" (`compaction.ts` L117–144). OpenAI documents the key as an accounting/segregation aid layered on the prefix hash (S-215). **Implication (§6.3):** the affinity key is a kernel-derived surface `H(scope_id ∥ static_surface_hash ∥ purpose)` — a run (or root run for a subagent tree) plus the compiled static tier plus a `purpose ∈ {main, compaction, probe, judge, subagent(id)}` — truncated for the wire per dialect (`max_key_length`) but recorded in full on the ledger; it is never a raw session id (T-LCD-10: names are surfaces), never carries a secret, and auxiliary purposes never share the main key.

**F5 — Cache warmth is predictable from the ledger under a lease-shaped model, but only as an expectation: the provider's clock, concurrency and eviction make the observation the truth.** The TTL runs from *request start* (S-213: "if a response takes 4 minutes to stream, a follow-up … must start within about 1 minute"); a cache entry "only becomes available after the first response begins", so parallel siblings miss; OpenAI retention is "typically 5–10 minutes … up to one hour" (S-215) — best-effort; no audited harness records whether it *expected* a hit (WS-C1 N1: no system exposes cache state per call). Gray & Cheriton's lease semantics say exactly how to reason about this: the grant is valid until the *earlier* of the two clocks' expiries, and the holder must treat post-expiry as invalid (S-198). **Implication (§6.3, OQ-097):** the kernel derives `expected_state ∈ {warm, cold, uncacheable, unknown}` per call from the ledger (last completed call with the same `(affinity_key, static_hash)`, its `request_sent` time, the dialect's declared retention class, minus a declared margin) and the gateway stamps `observed_state` from usage (`cache_read > 0`); both are recorded; their disagreement rate is a metric of the dialect descriptor's accuracy, and the experiment engine treats `cache_policy` as a declared factor (§6.7) rather than pretending warmth is controlled.

**F6 — Cache reads are already first-class in the accounting model; what is missing everywhere is the accounting of what a cache *avoided*.** ADR-0039 fixes the exclusive roles and the hit-rate denominator; goose, codex, opencode, pi and Inspect all carry read/write counts (and pi/Anthropic the 1h split). But no audited system records, for a harness-level cache hit, the model call, tokens or spend it did *not* incur: Inspect serves a cached `ModelOutput` and skips `record_model_usage` entirely (`_model.py` L1464–1471); litellm/dspy/langgraph return the value with no ledger footprint. ADR-0039 R-ACC-2 ("nothing unaccounted") and its WS-C4 consumer note require the opposite: a served-from-cache call posts a `model_calls` charge of 0 with `cache_hit = true`. **Implication (§6.4):** every harness-level cache resolution is a ledger event (`model.cache.resolved`) with an *avoided-cost estimate* derived from the entry's recorded usage and the pinned pricing table (`confidence = estimate`, ADR-0043 provenance `estimated_from_pricing`), so cache benefit is reported as a derived quantity with provenance — never as a missing row.

**F7 — Harness-level exact-match caches have one correct key partition: request-semantic fields in, transport knobs out, replicate axis explicit.** Inspect's `CacheEntry` hashes config, messages (ids excluded), endpoint, tools and tool choice, *drops* connection/retry/timeout knobs ("cannot change what the provider returns"), and ties the partition to the task-identity partition with a test (`_cache.py` L138–170); dspy hashes the canonical request minus declared ignored args; codex's reuse check is an exhaustive destructuring "so new request fields require an explicit reuse decision". HarnessHarness already has this partition: the `ProviderRequestPlan` is the request-semantic part (`plan_hash`, WS-C1 I2) and `AttemptPolicy`/transport are outside it. **Implication (§6.4):** the response-cache key is `H(plan_hash ∥ model_ref (served-model aware) ∥ seed_or_replicate ∥ configuration_version_id)`; `AttemptPolicy`, `deadline`, `observability` and `cache_state_hint` never enter it.

**F8 — A similarity-keyed cache is a fuzzy hash with a measurable false-hit rate and a demonstrated cross-principal write path; a verifier and per-principal scoping are the known mitigations.** MeanCache reports 89 vs 233 false hits per 1,000 queries against GPTCache and weights precision over recall because a false hit "means the user receives an incorrect cached response" (S-WS-C4-04); the ICML 2026 key-collision paper frames semantic keys as fuzzy hashes whose locality "directly undermines … collision resistance", hijacks 86 % of responses black-box and "induce[s] malicious behaviors in LLM agents" (S-WS-C4-05, `provisional`); Krites verifies marginal matches with a judge before promotion (S-WS-C4-06, `provisional`); litellm requires an explicit `similarity_threshold` and tenant-scopes semantic keys. Under ADR-0033/0034 a cached entry delivered into context is a `ContextItem` whose label joins the call's `context_label`, and a cache written by one principal and read by another is a cross-principal flow. **Implication (§6.5):** exact-match caches are admissible at C1; a similarity-keyed cache is **C2**, requires a deterministic or judged `Validator` on every marginal hit (`charged_to = instrument` when Lab-side), is scoped by `readers` and `principal`, stores the writer's label on the entry, and never raises authority — a hit is `origin = cache(entry_ref)` at the *entry's* label.

**F9 — Validity of a cached tool result or retrieval is exactly WS-D4's invalidation contract, and the audited caches that lack it (TTL-only) reproduce the S-106 failure.** Invalidation Contracts attaches version stamps and a cacheability hint so stale entries are "evicted deterministically" (S-077); D4's `InvalidationContract{dependencies: [DependencyStamp], cache_hint, validator_ref?, freshness?, invalidation_condition?, revalidation}` generalises it with dependency kinds `{registry_name, definition_version, procedure_version, tool_capability_version, environment_image, model_snapshot, memory_version, artifact, external_resource}`; RFC 9111 adds invalidation after unsafe methods. langgraph's `CachePolicy.ttl = None` "never expires" and litellm's TTL-only entries have no stamp to fire. **Implication (§6.5, §6.6):** the tool-result cache is a `Memory{kind: tool_result}` with a contract whose stamps are the capability `version_id`, the canonical arguments, and an environment/workspace stamp; any committed effect with `domain ∈ {fs_write, exec, net_egress}` in the same environment scope fires `dependency_changed` for entries stamped on that environment (the RFC 9111 rule); revocation via ADR-0037 `StaleIndex` withholds entries with `stale_withheld`. No second scheme is introduced.

**F10 — Compaction, context editing, reroutes and re-lowering are cache-invalidating by construction, and the systems that know it isolate or account for it rather than avoid it.** Codex trims the oldest history item during compaction claiming to "preserve cache (prefix-based)" (unverified claim); Anthropic advises clearing enough tokens "to make the cache invalidation worthwhile" (S-WS-D2-10); pi isolates summaries from the main key; WS-C2 rules a mid-run reroute a factor change; ADR-0019 makes a model switch a `relower` with a new plan. **Implication (§6.6):** the kernel records a `miss_reason` on the first call after any such event (`compaction`, `context_edit`, `relower`, `profile_version`, `definition_version`, `tool_set_change`, `marker_policy`, `dialect_change`, `ttl_elapsed`, `concurrent_sibling`, `unknown`), so cache churn is attributable per cause (ADR-0043 `harness_overhead.{compaction, …}` for the tokens re-written).

## 5. Disconfirming evidence & negative results

**Against harness-placed cache markers at all (R1).** Two of three major providers cache implicitly; markers there are "harmless but pointless" (opencode) or actively harmful (OpenHands' comment via WS-C1: explicit markers disable one provider's implicit caching at ~6–14× cost); CacheBlend shows serving stacks can reuse non-prefix segments, so a prefix-shaped layout is not universally optimal. *Why this does not overturn:* markers are emitted only under `cache_semantics = explicit_breakpoints` declared by the dialect/profile, never by default; the *layout* constraints (static-first, volatile-last, order-stable) benefit every semantics kind including implicit prefix caches (S-215, S-WS-C4-08 both advise exactly that); non-prefix reuse is admitted the day a dialect declares it — the sum has an `ext` slot and `unknown`.

**Against deriving an expected cache state (R2).** Provider caches are shared, best-effort infrastructure: retention is "typically" 5–10 min; entries appear only "after the first response begins"; workspace isolation and regional routing vary; the derivation will be wrong. *Why this does not overturn:* the field is named `expected_state`, stored beside `observed_state`, and the disagreement rate is the metric that tells the Lab when a dialect descriptor's retention class has rotted (T-LCD-05 applied to the descriptor); the alternative — recording nothing — is what every audited harness does and is why OQ-097 could not be answered from the gateway alone (WS-C1 N1).

**Against a harness-level response cache in a research instrument (R3).** Temperature-0 sampling yields 80 distinct outputs in 1,000 (WS-C1 S-WS-C1-02); a cached response is one sample presented as if re-drawn; serving it across replicates fakes zero variance and corrupts pass^k. Inspect's `per_epoch` flag exists precisely because users were bitten. *Why this does not overturn:* the response cache is **C1**, its key includes the replicate/seed coordinate and `configuration_version_id`, a hit is a ledger fact that the results row carries (`served_from_cache_count`), latency metrics on served calls are `n/a{reason: not_run}`, and the Lab's default `cache_policy` for the response cache is `off`; the admitted uses are reproduction (`mode = reproduce`, ADR-0038 R1), the recording/fake gateway variant (WS-C1 AC-C1-11), and declared `deterministic_replay` variants (ADR-0028).

**Against any semantic (similarity-keyed) cache (R4).** False-hit rates of 9–23 % on unique queries (S-WS-C4-04), an 86 % black-box hijack rate (S-WS-C4-05, `provisional`), and the ADR-0034 rule that delivered items join the context label make a shared semantic cache a taint conduit. *Accepted, and staged:* similarity-keyed caching is **C2**, never C0/C1; it requires a verifier on every marginal hit, `readers`/principal scoping, the writer's label on the entry and a pre-registered threshold; it is a component variant the Lab measures (false-hit rate is a class-scoped metric), not a kernel feature.

**Against cold-starting every Lab run (R5).** Cold-start salts the affinity key and forces cache writes at 1.25–2× per run — expensive, and unrepresentative of production where prefixes are warm. *Accepted:* `cache_policy ∈ {cold_start, natural, primed}` is a declared factor per arm (§6.7); arms with different policies are `IncommensurableMatch`; `natural` runs record warmth and the comparison engine stratifies; the default for matched-cap comparisons is `cold_start` because it is the only policy whose spend is reproducible at R2 (ADR-0038), and `natural` is admissible with warmth reported.

**Against caching tool results (R6).** Filesystem and process state change under the agent; a cached `read_file` is the S-106 failure in miniature; RFC 9111 requires `must-revalidate` semantics for anything an unsafe method may have changed. *Why this does not overturn:* the cache admits only `effective_risk_class.reversibility = read_only ∧ repeat_safety = idempotent` capabilities (ADR-0031), stamps every entry on the environment scope, and fires `dependency_changed` on any committed mutating effect in that scope (IR-3) — a conservative rule that over-invalidates rather than under-invalidates; the benefit is measured (avoided calls with `confidence = estimate`), so a variant that never hits is visibly useless rather than silently stale.

**Against recording dropped markers and miss reasons as ledger facts (R7).** More payload per call for a diagnostic nobody reads. *Why this does not overturn:* the cost is a few integers on an event that already carries a plan hash; opencode's log-line drop is exactly the failure a research instrument cannot accept (the arm silently paid full price and nobody can attribute why); ADR-0044 L1 already carries structural facts always-on.

**Negative results.** (N1) No audited harness records whether a call was *expected* to hit; none records dropped markers or cache-miss causes as data. (N2) No audited harness accounts the cost a cache hit avoided; Inspect skips usage recording on hits. (N3) Every audited harness uses a raw session id as the provider affinity key; none hashes it or scopes it by compiled content. (N4) goose selects cache semantics by provider-name branch; opencode by a code constant — both T-LCD-01 signatures. (N5) Codex's "trim from the beginning to preserve cache" comment could not be verified from the code read (removing the oldest item changes the prefix from that point); recorded as an unverified claim. (N6) The Gemini page fetched did not serve explicit-cache pricing (storage per token-hour) — `explicit_resource` storage accounting is an open question (OQ-WS-C4-03). (N7) OTel GenAI has slots for cache read/write tokens only — cache state, key, avoided cost and miss reason are declared loss on export.

## 6. Recommendation for the spec

### 6.1 Cache taxonomy (what exists, who owns it, what "hit" means)

| kind | where | owner | key | hit means | tier |
|---|---|---|---|---|---|
| **K1 provider prefix cache** (KV/prompt cache) | provider | provider; harness *shapes* and *observes* | exact bytes of the rendered prefix (+ affinity key + isolation scope) | `tokens.input.cache_read > 0` for the prefix | C0 (observe, layout, key); C1 (`explicit_resource`) |
| **K2 compile cache** | kernel | WS-A4 (ADR-0019 derivation key) | derivation key over canonical inputs | `compile` returns an existing bundle | C0 (exists); accounting here |
| **K3 catalog cache** (tool listings, resources) | kernel/E3 | WS-E3 (MCP `ttlMs`/`cacheScope`) | `(source, catalog epoch)` | `sync_source` served without a list call | C0/C1 (E3); accounting here |
| **K4 tool-result / retrieval cache** | kernel | this dossier; record = WS-D4 `Memory{kind: tool_result}` | `(capability semantic_id, capability version_id, canonical args, environment stamp, readers)` | a `read_only ∧ idempotent` call served from a valid entry | C1 / Stage 2 |
| **K5 response cache** (exact match) | kernel | this dossier | `H(plan_hash ∥ model_ref ∥ replicate ∥ configuration_version_id)` | a model call served from a recorded `ModelMessage` | C1 / Stage 5 (default off in the Lab) |
| **K6 semantic cache** (similarity-keyed) | kernel component variant | this dossier | embedding of the request under a pre-registered threshold + verifier | a verified near-match served | **C2** |

All six post to one accounting surface (§6.4). K1 is the only one whose hit is *observed from usage*; K2–K6 are kernel decisions and therefore ledger events.

**Cache semantics declaration (K1).** `CacheSemantics = explicit_breakpoints{max_markers, lookback_positions?, position_rule ∈ {block, run_of_same_kind}, retention_classes: [RetentionClass], min_cacheable_tokens?, isolation ∈ {workspace, organization, unknown}} | implicit_prefix{strictness ∈ {tolerant, strict}, affinity_key ∈ {supported{max_key_length}, unsupported}, retention_classes, min_cacheable_tokens?, reporting_granularity_tokens?} | explicit_resource{ttl_classes, storage_priced: bool, reference_form} | uncached | unknown`, with `RetentionClass = {class_id ∈ {short, long, extended}, nominal_ms, guaranteed: bool}` lowered per dialect (`5m`/`1h`; `in_memory`/`24h`/`30m`; `ttl` seconds). The dialect descriptor (WS-C1 §6.4) carries the default; the Model Profile's `cache_control_convention` capability (ADR-0020) overrides per model; every value is `declared → probed` (`cache_state_visible`, `affinity_key`, `retention_classes` are probeable — T-LCD-07 applied to transports, WS-C1 §6.5). **Invariant K1-1:** no kernel or codec code branches on a provider or model identifier to choose semantics (AC-C4-1; goose `for_model` is the rejected shape).

### 6.2 Layout constraints handed to WS-D1 / WS-C3 (kernel invariants + profile rules)

**Kernel invariants over the compiled `Layout` and the per-call `ContextPlan` (checked at `link` and `assemble`; errors, never warnings):**
- **LC-1 Tier order.** Slots are ordered `static` → `dynamic` → `transcript` (`SlotDeclaration.cache_tier`, WS-D1); no `static` slot follows a `dynamic` one. D1's rule that `kernel`/`definition` are `static` and `transcript` is `transcript` stands.
- **LC-2 Static-tier stability.** Within a run, the rendered bytes of the `static` tier are identical across consecutive calls with the same `purpose` unless the ledger carries a `model.surface.relowered`, `context.compacted`/context-edit, or a tool-set change event between them. The kernel computes `static_hash = H(canonical(static tier bytes ∥ tool surfaces ∥ sampling/reasoning parameters the dialect declares as prefix-affecting))` per call and checks it against the previous call's; an unexplained change is `PrefixInstability{slot, cause?}` (AC-C4-2).
- **LC-3 No volatile values in the static tier.** Items whose content changes per call or per turn — current time, `context.occupancy`, soft-budget `advise` reminders (ADR-0040), world-state diffs, turn counters — are admitted only to `dynamic` or `transcript` slots; a `static` slot that admits a `CandidateKind ∈ {budget_reminder, environment_state}` fails `link` (`VolatileInStaticTier`). Evidence: S-214 (budget value in the prompt invalidates the prefix), codex reminder re-arm per window.
- **LC-4 Order-stable tool surfaces.** The tool-surface order in a plan is a prefix-extension of the previous plan's (WS-E3 AC-E3-4, restated as a C4 invariant); deferred/revealed surfaces append after the cached prefix (E3 F7); a tool-set change is recorded and is a `miss_reason`.
- **LC-5 Prefix-affecting parameters are part of the static hash.** `tool_choice`, image presence, reasoning effort/verbosity, response format and sampling parameters that the dialect lists as `prefix_affecting[]` (S-213 table; S-215) enter `static_hash`; changing them mid-run is a recorded miss with `miss_reason = parameter_change`. D1's plan carries them; the profile cannot mark a listed parameter non-affecting.
- **LC-6 Purpose isolation.** Calls with `purpose ≠ main` (compaction summaries, probes, judges, subagent roots) render under their own affinity key and never place markers that extend the main prefix; a compaction summary call has `retention = none` where the dialect supports it (pi precedent).
- **LC-7 Append-only transcript between compactions.** Between two compaction events the `transcript` slot only appends; any in-place edit is a compaction/context-edit event (D2) stamped `cache_invalidating = true` with the tokens re-written charged `harness_overhead.compaction` (ADR-0043 §6).
- **LC-8 Reservations are dynamic.** D1's `ContextBudget.reservations` (omission notice, reminders, current time) render in the first `dynamic` slot, never inside `definition`.
- **LC-9 Marker carriers.** A marker may attach only to a block whose kind is in the dialect's `carrier_block_kinds` (non-empty text, image, tool result; never thinking/unsigned reasoning) — the codec substitutes the nearest eligible earlier block and records the substitution.

**Profile-owned rule (ADR-0020 kind `caching_markers`) — parameters fixed here, per-family values by WS-C3, each with an `AssumptionDebtRecord`:** `{enabled, marker_positions: [tier_boundary(static) | tier_boundary(dynamic) | transcript_tail{n_recent_user_turns | last_cacheable}], anchor_distance_positions?, retention_class_by_position, ttl_mix_allowed, max_markers ≤ dialect.max_markers, by_reference_default (D1 `diffable`)}`. The rule writes only marker positions on the plan (a surface record, T-LCD-01); the renderer (D1, OQ-063) evaluates it; the codec lowers positions to wire markers and enforces the cap.

### 6.3 Affinity key, expected state and the per-call cache record (C0 / Stage 1)

**Operations (language-agnostic; every one implementable out-of-process over canonical documents — T-LCD-12).**
- `derive_affinity_key(scope: RunId | root RunId, static_hash, purpose) → AffinityKey{full: ContentAddress, wire: surface string ≤ dialect.max_key_length, scope, purpose}` — deterministic; `wire` is a prefix of the hex digest (a surface alias, ADR-0027; the full address is the ledger fact); never contains a raw session id or any secret. Cold-start policy salts `scope` with the run's `configuration_version_id` and replicate index so no prior run's prefix can be hit. *Failures:* `AffinityUnsupported` (dialect declares `unsupported` → key omitted, recorded).
- `expect_cache_state(run, affinity_key, static_hash, request_sent_at) → {expected ∈ {warm, cold, uncacheable, unknown}, basis: {last_call: EventRef?, retention_class, elapsed_ms, margin_ms}}` — from the ledger only: `warm` iff a prior `model.call.completed` with equal `(affinity_key, static_hash)` exists whose `request_sent` time plus the declared `nominal_ms` minus `margin_ms` exceeds now (lease rule, S-198; TTL from request start, S-213), and no `cache_invalidating` event lies between; `uncacheable` iff the estimated prefix tokens < `min_cacheable_tokens`; `unknown` iff semantics is `unknown` or `retention_classes` are undeclared. Concurrent siblings (a call opened before the prior call's `first_byte`) are `cold{reason: concurrent_sibling}`.
- `place_markers(plan, rule: caching_markers, dialect) → {markers: [MarkerPosition], dropped: [{position, reason ∈ {cap, ineligible_carrier, below_minimum}}], substituted: [...]}` — pure; cap enforced by invalidation priority (static → dynamic → transcript tail); nothing dropped silently.
- `observe_cache(usage: canonical roles, expected) → CacheObservation{observed ∈ {warm, cold, uncacheable, unknown}, read, write_by_class, hit_ratio = read / input.total, write_ratio, agreement: bool, miss_reason?}` — `observed = warm` iff `cache_read > 0`; `unknown` iff `usage.available = false` (WS-C1 E-U3); `miss_reason` is the kernel's attribution when `expected = warm ∧ observed = cold` (`ttl_elapsed | concurrent_sibling | provider_eviction | parameter_change | unknown`) or when a known invalidating event preceded the call (`compaction | context_edit | relower | profile_version | definition_version | tool_set_change | marker_policy | dialect_change`).

**Ledger record.** `model.call.requested` (WS-C1 §6.1) gains `cache: {semantics_kind, affinity_key (full), affinity_wire_len, static_hash, purpose, expected_state, basis, markers: count, markers_dropped: [..], markers_substituted: count, retention_classes_requested: [..]}`; `model.call.completed` gains `cache_observation` as above (the gateway stamps `observed` and the roles it already emits; the kernel projection fills `agreement`/`miss_reason` — a view, so R-ACC-1 holds: raw roles stay on the producing event). `cache_state_hint` in WS-C1's `InferenceRequest` is filled from `expected_state`.

**Invariants.** CK-1 the affinity key is a function of `(scope, static_hash, purpose)` only; two calls with equal inputs get equal keys across processes (AC-C4-3). CK-2 `purpose ≠ main` never equals a `main` key. CK-3 `expected_state` is derived from the durable prefix only (ADR-0026 projection) — replayable. CK-4 the wire key never exceeds the declared length and is recorded as `surface_ids.affinity_key`. CK-5 no secret, credential, principal identifier or `readers`-restricted content enters any cache key (AC-C4-9).

### 6.4 Accounting: events, charges, derived metrics (C0 / Stage 1 schema; Stage 3 metrics)

**Event class (proposed to WS-B1, CF sidecar):** `model.cache.resolved{cache_kind ∈ {compile, catalog, tool_result, response, semantic}, key: ContentAddress, scope, outcome ∈ {hit, miss, bypass, stale_withheld, refused}, reason, entry_ref?: VersionedRef (Memory version or blob), verifier_verdict?: {validator_ref, verdict}, avoided: {model_calls?: 1, tokens: ResourceVector (from the entry's recorded usage), spend: Money{…, provenance = estimated_from_pricing, confidence = estimate, pricing_ref}}, attribution (ADR-0039)}`. K1 has no such event — its facts live on `model.call.requested/completed` (§6.3). Every K2–K6 lookup emits exactly one `resolved` event, including misses (so hit rate has a denominator) and refusals (so policy violations are visible).

**Charges (ADR-0039 R-ACC-2, nothing unaccounted).** A `hit` that replaces a model call posts `control.budget.consumed{dimension: model_calls, amount: 0, attribution.cache = {kind, hit: true, avoided_ref: EventRef}}` and zero-amount charges for the token roles; the *verifier* call of a semantic hit is a normal `model.call.*` with `charged_to` per R-ACC-3 (`subject` if the definition binds the verifier, `instrument` if Lab-side); a `tool_result` hit posts `tool_calls` 0 with the same shape; K2 hits post nothing to the run (compilation precedes the run) but `compile` records `derivation_hit = true` in the bundle diagnostics. Cache *writes* on K1 are already charged through `tokens.input.cache_write[ttl_class]`; K4/K5 entry storage charges `ext.bytes_stored` only if a definition declares that extension dimension (ADR-0039 §1).

**Avoided cost is derived, never primary.** `avoided.spend` is computed by `attribute_spend` from the entry's recorded canonical roles under the *current* pinned pricing table (`pricing_ref`), stamped `estimated_from_pricing` / `estimate` (ADR-0043 §4); totals of avoided cost are a `cost_totals` view group (`avoided_by_cache_kind`), reported beside, never subtracted from, realised spend.

**Metric declarations (ADR-0045 `MetricDeclaration`, dimension `efficiency`, `computed_from` ledger; all `charged_to = subject` by default):**
- `cache.prefix_hit_ratio = Σ tokens.input.cache_read / Σ tokens.input.total` (ADR-0039 definition) — `requires_observability ⊇ {events with usage roles}`; hosted rows without roles render `n/a{observability}`.
- `cache.prefix_write_ratio = Σ cache_write / Σ input.total`, split by `ttl_class`.
- `cache.expectation_agreement = #calls(agreement) / #calls(expected ≠ unknown)` — the dialect-descriptor health signal; `n/a` when semantics `unknown`.
- `cache.prefix_churn = #calls(expected = warm ∧ observed = cold)` with a breakdown by `miss_reason`; `cache.markers_dropped_total`.
- `cache.hit_rate[kind] = hits / (hits + misses)` per K2–K6; `cache.false_hit_rate[semantic]` = verifier rejections after a marginal match / marginal matches (C2).
- `cache.avoided_spend` and `cache.avoided_model_calls` — `confidence = estimate`, reported with a band.
- `cache.spend_share_cached = spend(cache_read + cache_write) / spend(input)` — from `measurement.cost.attributed` rows.
All are class-scoped (T-LCD-15) and computed over `subject` charges; instrument-side verifier costs are reported beside.

**Export.** `cache_read`/`cache_write` roles lower to OTel `gen_ai.usage.cache_read.input_tokens` / `cache_write.input_tokens`; `expected_state`, `affinity_key`, `miss_reason`, `model.cache.resolved` and avoided cost have no slot and are listed in the telemetry loss report (ADR-0042, T-LCD-11).

### 6.5 Harness-level caches with validity semantics (K4 C1/Stage 2; K5 C1/Stage 5; K6 C2)

**K4 tool-result / retrieval cache = `Memory{kind: tool_result}` (WS-D4) — no second lifecycle.** An entry is written by the kernel at `action.tool.completed` when (a) the capability's `effective_risk_class` is `{reversibility = read_only, repeat_safety = idempotent}` (ADR-0031; `unknown` never qualifies), (b) the capability declares `cacheable = true` in its `cost_model`/E1 record (default false), and (c) the result's label has `readers ≠ ∅-restricted` or the entry is scoped to those readers. Record: `{key = H(capability semantic_id ∥ capability version_id ∥ canonical(args) ∥ environment_stamp ∥ readers), value: ContentAddress (the observation payload), label (the observation's label — join of tool authority and inputs), recorded_usage: ResourceVector, contract: InvalidationContract{dependencies: [{tool_capability_version}, {environment_image}, {external_resource{validator_ref}}?], cache_hint = cacheable, freshness?: {max_age from the capability's declared staleness bound}, invalidation_condition = dependency_changed, revalidation = must_revalidate}, scope ∈ {turn, run, session}}`. Lookup: `resolve(mode = execute)` semantics — valid iff every stamp matches and no `context.memory.invalidated` fired; `stale_withheld` otherwise; a hit is delivered as an `Observation` with `provenance.origin = cache(entry_ref)`, authority = the entry's authority (never raised), and `derived_from = [entry_ref]`, so T-LCD-13 delivery events and the context label are computed exactly as for a fresh observation. **Environment stamp rule (IR-3):** the stamp is `(environment_ref, mutation_epoch)` where the kernel increments `mutation_epoch` on every committed effect with `domain ∈ {fs_write, exec, net_egress, spawn_process}` observed in that environment; any increment invalidates every entry stamped on the earlier epoch (RFC 9111 "invalidate after unsafe methods", conservative by design). Retrieval-result caching (D3) uses the same kind with `dependencies ⊇ {memory_version | registry_name}` stamps from D3's index watermark.

**K5 response cache (C1 / Stage 5; Lab default `off`).** Entry `{key = H(plan_hash ∥ model_ref{provider_model_id, served_model?, snapshot_id?} ∥ replicate ∥ configuration_version_id), value: ModelMessage (canonical) + usage + timing, contract: {dependencies: [{model_snapshot}, {profile_version}, {definition_version}], freshness: policy-declared, revalidation = never}}`. Admissible uses: `reproduce(bundle, level ≥ R1)` (ADR-0038); the recording/fake gateway variant (WS-C1 AC-C1-11) — its recorded corpus *is* a K5 cache; control-strategy variants declaring `deterministic_replay` (ADR-0028). A hit stamps `model.call.completed{served_from_cache: entry_ref}` with `timing = n/a{not_run}`; results rows carry `served_from_cache_count`; a Lab `Design` whose arm enables K5 outside `reproduce` fails `PreRegistration` validation unless it declares the policy as a factor (T-LCD-09/-14). `AttemptPolicy`, deadlines, observability flags and `cache_state_hint` never enter the key (Inspect partition; codex exhaustive-reuse rule: a new plan field defaults to *in* the key).

**K6 semantic cache (C2; component variant, never kernel).** Contract: `lookup(request_embedding, threshold, scope{principal, readers}) → exact_hit | marginal{entry, similarity} | miss`; a `marginal` is served only after `verify(entry, request) → pass` by a registered `Validator` (deterministic where a subject key exists — D4 conflict-set shape — else `kind: judge` with calibration, ADR-0047) and is then *promoted* (Krites shape, S-WS-C4-06); entries carry the writer's full label and are readable only by principals in `readers`; the threshold and verifier are part of the sealed definition and the `PreRegistration`; `false_hit_rate` is a mandatory class-scoped metric; a `delegate`/`external` writer can never produce an entry served to a higher-authority context (ADR-0034 narrow-or-preserve). Rationale is R4 in §5 — `provisional` evidence bars K6 from C0/C1 and the mechanism evidence (S-WS-C4-04, Tier B) suffices to require the verifier.

### 6.6 Invalidation rules (tie to WS-L4 identities; IR-1…IR-6)

- **IR-1 (K1)** The provider prefix is invalidated by construction whenever `static_hash` changes; the kernel attributes the first subsequent miss to the causing event: `model.surface.relowered` (ADR-0019 — profile or model change), a sealed-definition version change (`verify_resume`, ADR-0025), tool-set change (E3 epoch), `caching_markers` rule version change (profile `content_hash`, ADR-0020), dialect descriptor version change (WS-C1), compaction/context edit (D2), or prefix-affecting parameter change (LC-5). Nothing is *cleared* — the provider owns the store — but the reason is a ledger fact.
- **IR-2 (K2–K6)** Every harness-level key includes the `version_id`s it depends on (profile, definition, capability, dialect, model snapshot record as a claim), so a version change is a *different key* (deterministic miss), and every entry additionally carries a D4 `InvalidationContract` whose stamps let a **revocation** (ADR-0037 `RevocationRecord` → `StaleIndex`) withhold entries whose key still matches — `resolve(mode = execute)` never serves an entry with a revoked dependency (`stale_withheld`), `mode = audit` returns it annotated.
- **IR-3 (K4)** Environment mutation epoch as in §6.5; plus `scope_ended` at run end unless the capability declares `session` scope and the entry's label admits it.
- **IR-4 (K5)** `model_snapshot` stamp: a served-model drift or fingerprint DRIFT (WS-C1 §6.5) marks entries recorded before the drift `stale_by_dependency`; `reproduce` may still request them explicitly (`mode = reproduce`), annotated.
- **IR-5 (K3)** MCP `ttlMs`/`cacheScope`/`list_changed` as E3 specifies; a `cacheScope = private` catalog entry is scoped to the principal; expiry and change notifications emit `model.cache.resolved{kind: catalog, outcome: stale_withheld | miss, reason}` so re-list calls are attributable.
- **IR-6 (evolution)** A `HirDiff` or profile edit that *loosens* a cache contract — widens `readers` on entries, lengthens `freshness`, lowers a K6 threshold, or sets `cacheable = true` on a capability whose risk class is not `read_only ∧ idempotent` — is classified with D4's proposed `validity_delta = loosening` (CF-WS-D4-05) and is unacceptable from non-human origins in an evolution context (ADR-0002 governance, parallel to `AuthorityWidening`/`budget_delta = loosening`).

### 6.7 Cache warmth as a Lab factor (answers OQ-097; WS-J3/I2)

`cache_policy ∈ {cold_start, natural, primed{prime_ref}}` is a mandatory field of every arm's `BudgetSpec`/`MatchSpec` (ADR-0041): `cold_start` salts the affinity key per run so every run pays writes and no prior run's prefix is hit (the reproducible default for `matched_cap`/`iso_cost` — the only policy whose spend re-derives at R2); `natural` uses the unsalted key and records `expected/observed` per call — admissible only if every arm shares the policy and the report stratifies by `cache.prefix_hit_ratio` bands; `primed` runs a declared priming call before the first accounted call (charged `instrument`) to make the first turn warm deterministically. The engine refuses `IncommensurableMatch` when arms differ in `cache_policy`, or when a `natural` arm's `cache.expectation_agreement` is `n/a` on a dialect that declares `cache_state_visible = unsupported` (warmth cannot be stratified on a provider that never shows it). Cross-model arms (ADR-0041 R3) match on `spend`, which already prices cache roles per model. This closes OQ-097: *neither* forced cold-start nor blind recording — a declared policy, refusal on mixing, stratification when natural. Which providers expose cache state: all three audited vendor APIs report read counts per call (S-213/S-215/S-WS-C4-08), so `observed_state` is available wherever usage is; none exposes *pre-call* state, hence `expected_state` is a kernel derivation.

### 6.8 Acceptance criteria (sketch)

- **AC-C4-1 Declared semantics, no branch (T-LCD-01).** A static gate over kernel and codec sources finds no provider/model identifier deciding cache semantics; changing `WireDialect.cache_semantics` on a fixture from `explicit_breakpoints` to `implicit_prefix` changes emitted markers without a code change.
- **AC-C4-2 Prefix stability (LC-2/LC-4).** On a Stage-3 fixture run of N ≥ 20 calls with no compaction, `static_hash` is constant, the tool-surface order is a prefix-extension per call, and on an `explicit_breakpoints` fake endpoint `cache_read` is non-decreasing across calls within a turn (shares E3 AC-E3-4); injecting a volatile item into a `static` slot fails `link` with `VolatileInStaticTier`.
- **AC-C4-3 Affinity key.** Two processes deriving the key for equal `(scope, static_hash, purpose)` agree byte-for-byte; `purpose = compaction` never equals `main`; the wire form never exceeds the dialect length; a `cold_start` arm's key differs across runs; no key contains a session id, credential or principal identifier (AC-C4-9 shared).
- **AC-C4-4 Cap and lookback handled as data.** A plan requesting 6 markers on a 4-cap dialect yields 4 wire markers, 2 `markers_dropped` entries on `model.call.requested` in invalidation order, and no provider error; a marker on an ineligible carrier is substituted and recorded.
- **AC-C4-5 Expected vs observed.** On a fake endpoint with injected retention (entries expire after T, appear only after first byte), `expect_cache_state` agrees with `observed` in ≥ 95 % of calls, every disagreement carries a `miss_reason ∈ {ttl_elapsed, concurrent_sibling}`, and a call below `min_cacheable_tokens` is `uncacheable`, not `cold`.
- **AC-C4-6 Nothing unaccounted (shares AC-L2-2).** Projecting a run with K4/K5 hits yields one `model.cache.resolved` per lookup (hits and misses), a zero-amount `model_calls` charge with `cache_hit = true` per served call, `avoided.spend` with `estimated_from_pricing` provenance, and subject/instrument verifier charges summing to raw totals.
- **AC-C4-7 Invalidation on version change (IR-1/IR-2).** After `relower` (profile change), the next call is `expected = cold{reason: relower}`; a K4 entry keyed on capability `version_id` v1 is a miss under v2; revoking the profile version withholds K5 entries with `stale_withheld` in `mode = execute` and returns them annotated in `mode = audit` (shares AC-L4-7).
- **AC-C4-8 Tool-result admissibility and epoch (IR-3).** A capability with `repeat_safety ≠ idempotent` or `reversibility ≠ read_only` is refused with `NotCacheable`; after a committed `fs_write` effect in the environment, every K4 entry on the prior epoch is `stale_withheld`; a served hit carries `origin = cache(entry_ref)` and the entry's label, and emits the same `context.artefact.delivered` shape as a fresh observation.
- **AC-C4-9 No secrets, no cross-principal leakage.** Fuzzing cache keys and entries against the H3 secret pattern finds none; an entry written under `readers = {A}` never hits for principal B (K4/K6).
- **AC-C4-10 Lab refusal (T-LCD-14).** The engine refuses a comparison whose arms differ in `cache_policy`, or a `natural` arm on a dialect with `cache_state_visible = unsupported` without `n/a` stratification; results rows carry `cache_policy`, `cache.prefix_hit_ratio` and `served_from_cache_count`.
- **AC-C4-11 Response cache isolation (K5).** With K5 enabled in `reproduce` mode, a hit yields `timing = n/a{not_run}` and the results row's `served_from_cache_count` increments; enabling K5 in a non-reproduce arm without declaring it as a factor fails `PreRegistration` validation.
- **AC-C4-12 Semantic cache verifier (C2).** A marginal match is never served without a `verifier_verdict = pass`; the poisoning fixture (an entry written by a `delegate` writer under a crafted near-key) is refused for a `principal`-context read; `false_hit_rate` is computed per profile.
- **AC-C4-13 Export loss declared (T-LCD-11).** Lowering a run to OTel carries `cache_read/cache_write` and lists `expected_state`, `affinity_key`, `miss_reason`, `model.cache.resolved` and `avoided.spend` in the telemetry loss report.

## 10. Confidence

**High** for the taxonomy (K1–K6), the declared `CacheSemantics` sum and the layout constraints LC-1…LC-9: every element is read in ≥ 3 production harnesses at pinned commits and in three vendor specifications that agree on the hierarchy and exact-match rule; they compose with ADR-0019/0020/0039/0043 and with D1/E3's already-written contracts without amendment. **High** for the accounting shape (`model.cache.resolved`, zero charges with `cache_hit`, avoided cost as an estimate with provenance) — it is a direct consequence of ratified ADR-0039 rules. **Medium** for `expect_cache_state`: the lease-shaped derivation is principled (S-198) and the vendor TTL semantics are documented, but no audited harness does it and the agreement rate is unmeasured until Stage 3 (hence the metric). **Medium** for the affinity-key derivation as a kernel identity: precedent is partial (codex purpose-scoping; pi clamping) and the key's interaction with provider routing is provider-internal. **Medium** for K4 (tool-result memory): the contract reuses D4's ratified-in-shape mechanism, but the environment-epoch rule is conservative and its utility unmeasured (OQ-WS-C4-06). **Low-medium** for K6: the failure evidence is strong in direction (Tier-B false hits; `provisional` hijack), the mitigation shape (verifier + scoping) is precedented only by a preprint and litellm's threshold/tenant fields — which is why it is C2 and a measured variant. No C0 element rests on a 2026 performance number. Reflexively: this dossier assumes providers keep reporting per-call cache-read counts; `observed = unknown` and the `n/a` metrics exist because that assumption fails for proxies and some cancellations (WS-C1 E-U3).
