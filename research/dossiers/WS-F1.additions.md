## Ontology terms

| term | definition | notes |
|---|---|---|
| control strategy | The `control_strategy` component class: the pluggable owner of `decide` — a registered variant implementing `capabilities / open / observe / decide / terminate / checkpoint / restore` over closed `Cue`/`ControlDecision` sums; receives `(ModelProfile, ResourceAccount)`. | ADR-0103; home P3; slot key fixed by ADR-0016 (CF-052) |
| control driver | The Core loop that draws cues from the ledger inbox, calls `decide`, passes the decision through the control envelope, appends `control.decision`, executes admitted decisions through the plane operators, and closes the run. | MUST-code (ADR-0024); enforces I1–I8 |
| control decision (`ControlDecision`) | The typed output of `decide`: one of `propose, act, retrieve, compact, verify, delegate, retry, escalate, wait, stop`, stamped with its `DecisionPoint` and `owner ∈ {code, model, human}`. | Ledgered as `control.decision`; `owner` is β as exercised |
| cue (`Cue`) | The typed input to `decide`: a closed sum of run/model/effect/verification/retrieval/compaction/delegation completions, human inputs (steer, follow-up, approval, interrupt), envelope signals and guard firings, delivered in ledger order. | The only way state changes from outside (I7) |
| control state / plan cursor | The strategy's persisted closed-sum state with a common header `{variant_ref, cursor: PlanCursor{node_id, iteration, bound_ref}, decision_count, open_effects, last_cue_seq, boundary_view}`; canonical-serialisable; secret- and payload-free. | Pi `OperationState` precedent; resume by leaf |
| deterministic-envelope strategy | The `program` variant: an authored `Procedure` in which every model step is `output_schema`-validated and the model owns no decision point (`decision_points_owned = ∅`); LLM-as-Code / PAL lineage. | Distinct from *control envelope* (F2) — CF-220 |
| plan provenance | `compiled` (the plan is the lowered `Procedure`/implicit loop of the sealed definition) vs `model_emitted` (a run-time `Procedure` artifact with `provenance.origin = model`, `authority = delegate`, schema-validated before execution and ledgered as `control.plan.emitted`). | The second switch (with β) that distinguishes the family |
| boundary preset | A named `ControlBoundary.assignments` map shipped with a variant (`react`, `plan_execute`, `workflow`, `program`); `open` refuses presets that assign envelope-reserved points to `model`. | Presets are data; overridable per definition |
| observed control boundary / boundary drift | `boundary_observed`: the map from `DecisionPoint` to the owners actually recorded on `control.decision` events in a run; `control.boundary_drift`: its difference from the declared `ControlBoundary.assignments`, reported as a class-scoped metric, never silently corrected. | I8; consumed by WS-J4 |
| stop rule | Typed parameter `stop_rule ∈ {no_action, submit, either}` of `react/*` variants deciding how a model response without actions (or with a submission) is interpreted. | CF-221 |
| continue nudge | A `HarnessRule{action: insert ContextItem}` with an assumption-debt record that converts a proposed `stop{completed}` or an action-less response into a `guard_fired` cue; bounded by `max_continue_nudges` / `max_consecutive_format_errors`; delivery/activation/following are T-LCD-13 events. | Codex stop-hook block, OpenHands stop-hook denial, Inspect `on_continue`, mini-SWE-agent `FormatError` |
| no-progress guard | The driver's Core guard: two consecutive identical `(state_hash, decision)` pairs ⇒ `stop{guard_tripped(no_progress)}`. | Pi "Drive procedure made no progress" invariant |
| harness step vs turn | *Harness step* (ADR-0012): one `propose` cycle (render → … → decide). *Turn* (WS-B1): principal input → idle; `turn_id ⊃ model_call_id`. | CF-222 |
