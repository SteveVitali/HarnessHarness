## 1. Scope & boundary

This workstream decides **where the things a harness can remember live, how each is addressed, and the single contract by which any of them is brought back into a model call.** Concretely it fixes: (a) the **five layers** of doc 2 §5.1 — working context, artifact memory, episodic memory, procedural memory, durable session state — as *addressing classes over the stores Phase 1 already ratified* (the run ledger and its blob store, ADR-0026/0029; versioned records with names, ADR-0036/0037), not as five new databases; (b) the **derived-memory vs authoritative-record boundary** aligned to WS-B1: the ledger is the only authoritative event history; a memory is a versioned, provenance-bearing *record* derived from it by a non-deterministic deriver, distinct from a *materialized view* derived deterministically; (c) the **retrieval contract** — `retrieve(query) → filter validity → filter authority → filter readers → rank → budgeted return with provenance and a report` — applying ADR-0034 P5 verbatim and adding the query taxonomy, the ranker component class, read-your-writes, determinism and the events; (d) the finding that mature coding harnesses retrieve deterministically (S-074) as a **design input**: deterministic retrieval kinds are C0/C1, similarity ranking is a C2 ranker variant that may score but never filter; (e) the **memory write and consolidation contract** — agent-authored memories as immutable versions with `supersedes`, index files as name histories, consolidation as supersession — and the one place this dossier must deviate from a ratified ADR (the persistence ceiling for agent-authored memory, §6.6, proposed as a superseding clause in ADR-3); (f) acceptance criteria including the S-106 regression test WS-L4 assigned to this track (AC-L4-7) and the T-LCD tests the decisions must pass.

It explicitly leaves to neighbours: **WS-D1** — admission of retrieved candidates into slots, the `ContextPlan`, offload handles (this dossier produces `Candidate`s in D1's shape and re-uses D1's `OffloadHandle`); **WS-D2** — what to compact (compaction summaries are episodic-layer *inputs* here); **WS-D4** — lifecycle richness: conflict sets, expiry policies, taint, the `promotion` workflow, when consolidation runs (this dossier fixes the records D4 filters on and the operations consolidation must use); **WS-D5** — the rich Procedure IR (this dossier fixes only how procedures are indexed and retrieved, i.e. the handle form and the trigger kinds); **WS-E3** — tool-surface retrieval (`select_surfaces`); **WS-B3** — resume policy (durable session state is *read* through B3's `verify_resume`; this dossier fixes only that progress artifacts are named artifacts); **WS-H1/H2** — enforcement of `memory_write` effects and reader sets; **WS-L4** — identity (adopted verbatim); **WS-I5** — which memories to distil for harness evolution.

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Production coding harnesses separate an immutable event history from derived memories, and the derived memories are records produced by a background *pipeline*, never edits of the history.** Codex's pipeline "is triggered when a root session starts", runs "asynchronously in the background", and has two phases: Phase 1 "finds recent eligible rollouts and extracts a structured memory from each one" (rollouts *claimed* in a state DB under a lease with retry backoff; outputs stored in `stage1_outputs{thread_id, source_updated_at, raw_memory, rollout_summary, rollout_slug, generated_at, usage_count, last_usage}`), Phase 2 "claims a single global phase-2 lock", ranks eligible memories "by `usage_count` first, then by the most recent `last_usage`/`generated_at`", ignores those unused longer than `max_unused_days`, syncs them into a **git-baselined memories directory**, writes a `phase2_workspace_diff.md`, and spawns a consolidation sub-agent "with no approvals, no network, and local write access only" that rewrites `memory_summary.md`. Rollouts themselves are never modified; `rollout_input.rs` *reads* them ("Selects v2 extraction evidence by provenance, then restores chronological order", tiers `Human > Final > OtherAgent > Commentary > Context > Tool`, tool output capped at 2 000 tokens, secrets redacted). This is doc 2 §5.1's "separate immutable event history from mutable derived memories" observed in production, and it says three things the contract must keep: (i) the source of every memory is a *set of runs* (`source_trajectories`, WS-A3 `Memory`); (ii) the deriver is a model, so the output is a *record with provenance*, not a rebuildable view; (iii) consolidation is a *write of new artifacts under a lock with a watermark*, i.e. supersession, not in-place mutation — the memories directory is itself version-controlled so the diff between consolidations is an artifact.

**F2 — Retrieval in every coding harness read in source is deterministic; embeddings appear only in the chat/simulation lineage.** Codex's memory tools are `list`, `read` (line-offset, `max_tokens`) and `search`, and `search` is *substring matching*: "Search Codex memory files for substring matches, optionally normalizing separators or requiring all query substrings on the same line or within a line window" (`tools/search.rs` L61; `local/search.rs` L288 `line.contains(query)`); usage telemetry classifies memory reads by parsing the *shell commands* that touched memory paths (`usage.rs`), i.e. the model retrieves memory with ordinary file tools. OpenHands loads `MEMORY.md` indexes and leaves daily logs to on-demand reads; skills activate by whole-token keyword match or gitignore-style path globs. Gemini CLI discovers `GEMINI.md` files by walking *upward* from the working directory to the project root and *just-in-time downward* when a "high-intent" tool touches a path, bounded by its `trustedRoots` (a configuration list, not a label). Pi walks upward for `AGENTS.md`/`CLAUDE.md`. Aider's repo map ranks tree-sitter symbols with PageRank over a reference graph and fits the result to a token budget by binary search — a deterministic *structural* ranker. OpenHarness scores memories by token overlap with metadata weighted 2×, plus importance, use count and recency. Claude Code loads `CLAUDE.md` ancestors at launch and subdirectory files "when Claude reads files in those subdirectories", and reads auto-memory topic files "on demand using its standard file tools". This reproduces S-166's headline in five of its eleven systems and extends it to *memory* (S-166 says "code"): the retrieval primitives are **address, name, path/glob, upward/downward directory discovery, lexical match, structural graph rank, and trigger** — all functions of the store's bytes alone. By contrast MemGPT's archival storage "performs vector search based on cosine similarity" (S-016), Generative Agents use embedding relevance as one of three additive terms (S-017), AIOS's `retrieve_memory` is a top-k cosine query with no other filter (S-031), and Mem0/A-MEM are vector-store systems (S-WS-D3-01/02). **Implication (§6.3):** the retrieval contract's *query kinds* at C0/C1 are the deterministic set; similarity is a *ranker variant* at C2 whose embedder is a pinned, versioned, cost-accounted dependency (`model_call` effects), which may add a score but never acts as the only filter. The evidence does not say embeddings are useless; it says the field that has to be *reproducible and auditable* did not adopt them, and the program's instrument purpose (ADR-0003) sits on that side.

**F3 — The unit of persistent memory in production is a *file with a small index*, addressed by path and scope, loaded under a fixed byte/line budget; the index is the only thing loaded eagerly.** OpenHands: `MEMORY.md` in `~/.openhands/memory/` and `<workspace>/.openhands/memory/`, "Daily logs (`YYYY-MM-DD.md`) … are deliberately NOT loaded — the agent reads them on demand", 6 000-char budget split fair-share across tiers, truncated line-wise from the top. Claude Code: "The first 200 lines of `MEMORY.md`, or the first 25KB, whichever comes first, are loaded at the start of every conversation", topic files on demand, and the runtime *reminds the model to shorten the index* when it nears the limit. OpenHarness: `MAX_ENTRYPOINT_LINES = 200`, `MAX_ENTRYPOINT_BYTES = 25_000`, "Prefer concise topic files plus an index entry in MEMORY.md". Codex v2: `memory_summary.md` truncated into the developer fragment; `rollout_summaries/` read selectively ("do not retrieve history speculatively"). goose stores memories as category files behind an MCP extension with `retrieve_memories{category|"*"}`. **Implication (§6.2, §6.5):** the index/entrypoint is a **manifest** — a name-bound, versioned record listing memory addresses with one-line descriptions — and the eager load is *the manifest under a profile-owned budget rule*; bodies are `handle_only` candidates (WS-D1 F7) whose expansion is a read effect and therefore a deterministic `context.artefact.activated` (OQ-049). Budgets (200 lines / 25 KB / 6 000 chars / 8 900 bytes) differ per system and per model and are conditioned rules with an expiry (T-LCD-05), not kernel constants.

**F4 — No audited memory system carries authority, validity or version on the retrieval path; the two that carry *anything* lifecycle-shaped carry it as metadata the model is expected to read.** AIOS's `MemoryNote` has `retrieval_count`, `evolution_history`, `links` and free `metadata{owner_agent, user_id, sharing_policy, memory_type}`, yet `retrieve_memory` returns the top-k by cosine and `ContextInjector` prepends them "as a system message at index 0" above a 0.5 relevance threshold (WS-D1 F2 already names this the textbook assembly bug). OpenHarness is the only system with lifecycle fields — `ttl_days`, `disabled`, `supersedes[]`, `signature`, `importance`, `source` — and its scanner *does* exclude disabled/expired files (`scan_memory_files(include_disabled=False, include_expired=False)`), but `supersedes` is written and never enforced at retrieval, and `importance` is model-authored. Codex's read template says "Memory is not proof of current behavior … inspect the actual owning source when warranted" — validity delegated to the model in prose. Claude Code writes a `modified` timestamp "so the timestamp shows how current the fact is … to Claude when it reads the memory back" — validity as a hint. S-106 measured what happens when validity is a label the retrieval layer can see but does not enforce: the revoked fact "outranks its replacement, and leads agents to the unsafe action" in 5/5 systems. **Implication:** ADR-0034 P5's fixed order is the contract that every audited system lacks; this dossier's job is to make it *the only way* memory reaches a candidate list (§6.3 R1), with the record fields ADR-0037 already fixed (`supersedes`, `RevocationRecord`, `validity`) as the things the filter reads.

**F5 — Structural ranking of code (the repo map) is a deterministic, budgeted, personalized ranker over a rebuildable index, and it is the only "relevance" mechanism the coding lineage converged on.** Aider builds `defines[name] → files`, `references[name] → [files]` from tree-sitter tags, adds edges `referencer → definer` with weight `mul·√num_refs` (×50 when the referencer is a chat file), runs PageRank with `personalization` mass on chat files, mentioned files and mentioned identifiers, distributes each node's rank across its out-edges onto `(file, ident)` definitions, sorts, then binary-searches the prefix length so the rendered tree lands within 15 % of `max_map_tokens` (default 1 024). The tag cache is keyed by file mtime; the whole map is a function of the workspace bytes plus the *anchors* (chat files, mentions). This is exactly the shape the contract needs for the artifact layer: `structural{anchors, mentions}` queries answered by a ranker over a `StructuralIndex` **materialized view** of a workspace tree address (rebuildable, `derived_from = tree ContentAddress`), with a budgeted cut. It is also the mechanism behind Cursor's "semantic search" alternative: Cursor lists grep *and* semantic search for skills, so the Lab can compare a deterministic structural ranker against a similarity ranker under matched budget (T-LCD-14) instead of assuming either.

**F6 — Durable session state in production is a *small set of named artifacts the next session reads first*, plus the event log; the artifacts have validators.** Anthropic's long-running harness reads "the progress notes file and git commit logs" at session start, keeps a feature-list JSON that agents "edit … only by changing the status of a `passes` field", commits after every change, and runs `init.sh` — and names the failures without them (declaring the job done prematurely; "a feature half-implemented and undocumented"; environment degradation). Prime-agent persists `GoalState{objective, tokenBudget, tokensUsed, continuationsUsed, status}` as a custom *session entry* (`thread_goal_state`) and re-delivers it as `goal_context{continuation | budget_limit | objective_updated}`; its semantic-edges ledger is "written before the effects they describe" and edges are "commit-gated". Codex records `usage_count`/`last_usage` per memory and prunes rollout summaries not selected. OpenHarness keeps a `usage_index.json` and computes stale candidates (importance ≤ 1, unused ≥ 60 days) for an "auto-dream" review. **Implication (§6.2 layer S):** durable session state is not a new store — it is (a) the run ledger and its views (ADR-0026; B3 resumes from them) and (b) **named artifacts** (progress file, feature list, goal state) that are `Artifact` versions behind a logical name with a `supersedes` history (ADR-0037 I2), written as `fs_write`/`memory_write` effects, whose validity can be *deterministic* when a validator references them (a `passes` field checked by tests is a closed-schema value → `environment` via the `validator` endorsement of ADR-0035). Usage counters are `context.memory.read` events aggregated in a view, not fields the model edits.

**F7 — Read-your-writes across the memory boundary is a real ordering hazard and has a small deterministic fix.** AIOS's `MemoryWriteBarrier` exists because "a retrieval scoped to `user_id = U` cannot be served while one or more `create_memory` operations for the same `user_id` accepted before it remain uncommitted"; retrievals "capture a `barrier_snapshot` of the high-water mark and only wait on writes whose `seq_no` is at or below that snapshot", with a bounded wait that is *fail-open* (`TIMEOUT`). In HarnessHarness the ledger already has the high-water mark: `seq` (ADR-0027) and the `derived_from` watermark on every view (ADR-0026). **Implication (§6.3 R4):** `retrieve` takes an `at: (run_id, seq)` watermark from D1's `view.derived_from`; the store must have applied every `context.memory.written` ≤ that seq before answering, or return `StaleStore`; there is no fail-open — a stale store is a typed failure the control envelope sees.

**F8 — Extracted memories are lossy; the immutable history must stay retrievable alongside them.** S-WS-D3-03 (`provisional`) finds that in an identical retrieve-rerank-reason pipeline verbatim conversation chunks beat LLM-extracted typed artifacts by 16–22 points, attributing it to "lossy distillation, not structure per se", and recommends that "structured memory should augment verbatim text rather than replace it". Codex keeps `raw_memories.md` and per-rollout summaries next to the consolidated summary and tells the model to "read a matching rollout … when its additional evidence, wording, chronology, or uncertainty could change your answer"; Cursor gives the agent the *history file* during summarization "to recover" details missing from the summary. **Implication (§6.2 layer E):** the episodic layer has two addressable forms — **verbatim** (ledger ranges and offloaded observations by content address, retrievable by lexical/structural query) and **distilled** (`Memory` records with `derived_from` pointing at the ranges) — and a distilled record never replaces the range it was derived from (ADR-0026 history never rewritten).

**F9 — Mutation of memory is where the audited non-coding systems put an LLM, and where the coding systems put a locked pipeline; both are "control-plane" placements the contract must make explicit.** A-MEM's "memory evolution" updates "the contextual representations and attributes of existing historical memories" in place; Letta's memory blocks are strings the agent edits with `core_memory_replace`; Mem0 extracts and consolidates with ADD/UPDATE/DELETE-class operations. S-WS-D3-04 (`provisional`) shows the *placement* of the LLM (recall plane vs mutation) changes which forgetting failures are recovered — deterministic mutation cannot canonicalize, LLM-at-mutation recovers intent-aware deletion. Codex answers with a lock + watermark + diff + sub-agent with no network and local write access, and a rule that the model "do[es] not edit generated memory files directly; consolidation applies these notes". **Implication (§6.6):** consolidation is a *Procedure* (WS-D5) run by an AgentProcess at `delegate` authority under a `memory_write` Permission scoped to the memory store, whose every output is a new version with `supersedes{reason}` and `derived_from` — the control plane is typed and ledgered, the recall plane never mutates, and "which placement is better" is a Lab factor, not an assumption.

## 5. Disconfirming evidence & negative results

**Against deterministic-first retrieval ("the coding-harness finding is a domain artefact").** Mem0 reports +26 % on LoCoMo over full context with 90 % fewer tokens (S-WS-D3-02); A-MEM reports gains on six models; MemGPT's archival search is embedding-based and its DMR result is large; Cursor itself offers "semantic search" beside grep. Code has symbol names that lexical and structural search can exploit; conversational and preference memory does not. *Why this does not overturn:* the contract does not forbid similarity — it places it as a **ranker variant** that receives candidates already filtered by validity/authority/readers and returns *scores* (§6.3), so every result above is expressible as an arm. What it refuses is similarity as the *only* filter (AIOS shape), because that is precisely where S-106's failure lives and where reproducibility is lost (embedders drift with model versions; ADR-0036 makes the embedder a `ModelSnapshotRecord` claim, never an identity). The instrument's purpose (ADR-0003) makes deterministic-by-default the honest baseline against which similarity must *show* a benefit under matched budget (T-LCD-14), not an assumption. The cost — worse recall on non-code memory without a similarity arm — is recorded as a Lab measurement (AC-D3-10) and the C2 ranker is scheduled, not deferred indefinitely.

**Against five layers ("it is two stores wearing five hats").** Every audited system has exactly two physical stores (a log/transcript and a directory of files); OpenHands and Claude Code do not distinguish episodic from procedural memory — both are markdown; MemGPT has three tiers, not five. *Why this does not overturn:* the layers here are declared as **addressing classes over the two ratified stores**, not as stores (§6.2) — which is the audit's own structure made explicit. The distinction that matters for the Lab and the monitor is *which retrieval kinds and which validity checks apply*: an `Artifact` is valid iff its bytes resolve; a `Memory{kind: episodic}` is valid iff its `supersedes` chain is head and its source runs exist; a `Procedure` is valid iff its `validates` edge passes; a session artifact is valid iff its validator passes. Collapsing them hides exactly the checks S-106 shows are missing. If Phase 3 finds no consumer distinguishes episodic from procedural *records*, `MemoryKind` collapses by dialect bump (OQ-WS-D3-02) — the store does not change.

**Against enforcing validity at retrieval ("the model should see the revoked fact and its replacement and reason").** S-WS-D3-04 argues an LLM at the *mutation* plane recovers intent-aware deletion that deterministic rules cannot, and Codex's template trusts the model to "use judgment about drift". *Why this does not overturn:* the two planes are separated in §6.6 — an AgentProcess *may* decide what supersedes what (mutation), and that decision becomes a `supersedes` edge the resolver enforces (recall). What the contract forbids is the recall plane *presenting* a revoked head in `mode = execute`; audit mode returns it with status. The model still reasons — at write time, with the ledger as evidence — and the reasoning is a ledgered Procedure run, not a prose instruction.

**Against agent-authored memories at `external` authority (ADR-0033 R-TEXT + ADR-0034 RP).** Claude Code delivers `CLAUDE.md` "as a user message", Codex delivers memory instructions at `developer` role, and both work; rendering an agent's own learnings into an `external`-class slot may reduce compliance with legitimate learned conventions. *Why this does not overturn:* the scheme is ratified and the alternative is the X-CPE escalation S-103 exploits (a memory written after reading an injected file re-entering at instruction privilege). The legitimate path up exists (`promotion` by a human reviewer → `principal`; `seal` → `definition`), and Claude Code's own design *already* separates the two: `CLAUDE.md` (human-written) vs auto memory (Claude-written, "context, not enforced configuration"). Whether external-slot delivery lowers `followed` for `memory`-kind artifacts is the T-LCD-13 measurement AC-D3-9 makes; the contract makes the trade visible.

**Against the persistence-ceiling deviation proposed in ADR-3.** ADR-0035 sets `project ≥ principal` for writes; loosening it for a memory store reopens the door to X-CPE. *Why this does not overturn:* the deviation is narrow and structural — a runtime-owned **memory store** whose write ceiling is `delegate` *and* whose items are capped at `≤ external` by construction, so a write can never raise what the written item may command; the escalation defence is RP at delivery, which is unchanged. Without the clause, every audited production memory pipeline (Codex, Claude Code auto memory, OpenHands MEMORY.md, OpenHarness) is inexpressible as a native harness, which fails T-LCD-03's spirit for the rich anchor. The clause is proposed as a superseding ADR row, not silently assumed, and it is reversible (drop the row; agent memory then requires per-write approval).

**Against read-your-writes as a hard failure (AIOS fails open).** A stuck consolidation would block retrieval forever. *Why this does not overturn:* the watermark is the ledger `seq` D1 already carries; "applied ≤ seq" is a local check, not a wait on a remote commit; a store that cannot satisfy it returns `StaleStore` immediately and the control envelope (F2) decides to retry, retrieve at an older watermark explicitly (`at` is an input), or proceed without memory — all ledgered. Fail-open would make the retrieval report lie about what the model could have seen.

**Against verbatim ranges in the episodic layer (cost).** Keeping ledger ranges retrievable means lexical search over potentially large offloaded observations. *Why this does not overturn:* the ledger already stores them (ADR-0029); the index is a materialized view built lazily; Codex and Cursor both ship exactly this (rollout summaries + raw; history file). The Lab measures the token and latency cost as `harness_overhead.retrieval`.

**Negative results from the audit.** (i) No audited system applies an authority or validity filter before ranking (F4); (ii) none records retrieval as a structured event with what was *filtered out* — Codex's `injected`/usage metrics count reads, AIOS logs "Injected %d memories" to stdout and parses it back; (iii) none content-addresses memory records — Codex keys by `thread_id`, OpenHarness by a generated id plus a content `signature`, AIOS by UUID; (iv) none has a supersession edge that a resolver enforces — OpenHarness writes `supersedes` and ignores it at read; (v) `importance` and `usage_count` are model-editable or file-resident in every system that has them — no system derives them from an append-only record; (vi) goose's `retrieve_memories` and Codex's `list` have no relevance at all — retrieval by category/path only, which is a *stronger* deterministic claim than S-166 makes.

## 6. Recommendation for the spec

### 6.1 Position (what the memory hierarchy is)

The memory hierarchy is **five addressing classes over three ratified substrates**: the run ledger and its blob store (ADR-0026/0029 — the only authoritative event history), the versioned-record registry with name histories (ADR-0036/0037 — memories, procedures, manifests), and the workspace/environment tree addressed by content (ADR-0036 tree rule; B5 handles). It adds **one new store contract**, `MemoryStore` (a registry-shaped store of `Memory` versions and manifests, implementable in-process or out-of-process — goose's MCP memory extension and Codex's state-database-backed store are both variants), **two new materialized views** (`StructuralIndex` over a tree address; `LexicalIndex` over ledger ranges and memory bodies), and **one operation** every consumer uses, `retrieve`. Nothing here is a second authoritative record (ADR-0026 unchanged) and nothing rewrites history (ADR-0037 I1–I5 unchanged).

### 6.2 Layer definitions (storage · identity · provenance · validity · retrieval kinds)

| layer | what lives there | storage substrate | identity (ADR-0036 kind) | provenance/authority | validity check (ADR-0014) | retrieval kinds (C0 unless marked) |
|---|---|---|---|---|---|---|
| **W — working context** | the items delivered to *this* model call | none — a projection (`ContextPlan`, WS-D1) over the context view | `plan_id` (version id of the plan); items by `context_item_id` | per item, as recorded; `context_label` = join | n/a (items are re-checked at admission, D1 I-ORDER) | none — W is the *output* of retrieval, never its source |
| **A — artifact memory** | files, patches, logs, screenshots, offloaded observations, workspace trees, compaction summaries as artifacts | blob store (`put_blob`) + environment tree addresses; `Artifact` entity | `ContentAddress` (bytes/tree); named artifacts via `NameHistoryEntry` | `default_authority(origin)`: tool-produced ⇒ `external`/`environment` per ADR-0033; sealed inputs `definition` | resolves & hash verifies ⇒ `valid`; `Missing` ⇒ `invalid`; name yanked ⇒ `invalid` | `by_address`, `by_name`, `by_path_glob`, `lexical`, `discover{upward, jit_downward}`, `structural` (C1 ranker) |
| **E — episodic memory** | (verbatim) ledger ranges, offloaded observations, compaction summaries; (distilled) `Memory{kind: episodic}` records — diagnoses, corrections, decisions, rollout summaries | ledger + blobs (verbatim, authoritative, immutable); `MemoryStore` (distilled, derived records) | `EventRef` ranges / `ContentAddress` (verbatim); `version_id`+`semantic_id` (distilled) | verbatim: as recorded on the events; distilled: `origin = model(run_ref)` or `evolution`, `deriver = delegate`, `derived_from = [ranges]`, `taint ⊇` inputs, authority ≤ `external` (R-TEXT) unless promoted | verbatim: always `valid` (history); distilled: head of its `supersedes` chain ∧ not revoked ∧ `validity` interval ∧ every `source_trajectories` run exists (else `unknown`) | `by_address`, `by_run{run_id, seq_range}`, `lexical`, `by_name`; `similarity` (C2 ranker) |

**Cross-layer rules.** (L1) Every layer's items are addressable by an ADR-0036 identity or they are not retrievable (D1 I-ID closed world). (L2) A distilled record never replaces its sources: `derived_from` on a `Memory` is a list of `EventRef`/`ContentAddress` ranges that remain retrievable (F8). (L3) Layers carry no authority of their own — authority is per item (ADR-0033); "the memory slot" has a `min_authority` (D1) but membership in layer E does not raise or lower anything. (L4) A `Memory` record's `kind ∈ MemoryKind = {episodic, procedural_note, preference, reference, decision}` (OpenHarness/Claude Code `type` generalized; closed, registered `ext`; collapse by dialect bump) is a *ranker feature*, never a filter on authority or validity. (L5) Index/entrypoint files (`MEMORY.md`, `memory_summary.md`) are **manifests**: `MemoryManifest{scope, entries[{name, version_id, one_line: Text, kind}], version, provenance}` — a versioned record bound to a logical name, rebuilt by consolidation, delivered eagerly under a profile budget rule while bodies are `handle_only`.

### 6.3 The retrieval contract — ADR-2

**`retrieve(request: RetrievalRequest) → RetrievalResult | RetrievalError`**

- `RetrievalRequest = {model_call_id, at: (run_id, seq) (the context view watermark from D1), layers ⊆ {A, E, P, S}, query: RetrievalQuery, constraints: SlotConstraints, reader: PrincipalRef, budget: {tokens, k}, ranker: RankerRef (default `deterministic_default`), profile: ProfileRef, account: AccountingHandle, mode ∈ {execute, audit}}`.
- `RetrievalQuery` (closed sum per dialect; registered `ext`): `by_address{ContentAddress | version_id}` · `by_name{NameSelector}` · `by_path_glob{root, patterns[]}` · `by_run{run_id, seq_range?, classes?}` · `lexical{terms[], match_mode ∈ {any, all_same_line, all_within{n}}, context_lines, case_sensitive, normalized}` · `discover{path, direction ∈ {upward, jit_downward}, filenames[], ceiling: workspace_root | git_root}` · `trigger{event: message{text} | path_touched{path} | explicit{name}}` · `structural{anchors: [ContentAddress | path], mentioned_idents[]}` · `similarity{text, embedder: ProfileRef}` (C2). Every kind except `similarity` is a pure function of the store bytes and the request; `similarity` declares `deterministic: false` and its embedder is a `model_call` effect charged to the account.
- `SlotConstraints = {slot_min_authority: AuthorityClass, validity_required ⊆ {valid, unknown} (default {valid}), admit_unknown_validity: bool, readers_required: bool}` — copied from the target slot's declaration (D1 `SlotDeclaration`), never chosen by the ranker.
- **Pipeline (fixed order; each step is a recorded count):** `enumerate(layers, query) → [RawHit]` (layer-specific index) → **filter validity** (`validity(item, at) ∈ validity_required`; superseded/revoked/expired/`stale-by-dependency` excluded in `mode = execute`; ADR-0037 S3) → **filter authority** (`authority(item) ≥ slot_min_authority`) → **filter readers** (`reader ∈ readers(item)`; carried at C0, enforced at C2 per ADR-0033) → **rank** (`ranker.score(candidates, query, profile) → [(candidate, score, features)]`) → **budgeted cut** (stable sort by score then identity; take while `Σ tokens ≤ budget.tokens ∧ count ≤ k`; the remainder is `omitted_by_budget[]`) → **return**.
- `RetrievalResult = {items: [RetrievedItem], report: RetrievalReport}`; `RetrievedItem = Candidate (WS-D1 shape: `context_item`, `kind ∈ {memory, artifact_excerpt, procedure_index, procedure_body, environment_state, transcript_item}`, `state ∈ {handle_only, expanded}`, `retention = optional(priority)`, `estimate`, `source_event`, `slot_hint`) + {layer, address, provenance, validity{state, check_ref}, rank_evidence{ranker_ref, score?, features{...}}, handle?: OffloadHandle}`; `RetrievalReport = {request_hash, watermark: at, enumerated, filtered{validity, authority, readers}, ranked, returned, omitted_by_budget[], no_authoritative_items: bool, ranker_ref, deterministic: bool, cost{tokens_estimated, index_ms, embedder_calls}}`.
- **Invariants.** **R1 order:** the three filters run before `rank` and `rank` cannot re-admit a filtered item (a ranker sees only filtered candidates — the AIOS shape is inexpressible). **R2 never widen:** `label(RetrievedItem) = label(stored version)`; the result carries no field a ranker can set on authority, validity, readers or retention (D1 I-NOWIDEN mirrored). **R3 determinism:** for a ranker with `deterministic = true`, equal `(request, store state at `at`)` ⇒ equal `report.request_hash` and equal item order (two implementations must agree; AC-D3-6). **R4 read-your-writes:** the store has applied every `context.memory.written` with `seq ≤ at` or fails `StaleStore{applied_seq, requested}`; never fail-open. **R5 budget:** `Σ estimate.tokens(items) ≤ budget.tokens`; nothing is truncated — over-budget items are omitted whole and listed. **R6 provenance:** every item carries the ADR-0033 record; `MissingProvenance` otherwise. **R7 closed world:** every item has an identity (address or version id) — `by_run` hits are `EventRef` ranges rendered as `transcript_item` candidates with the range's content address. **R8 distinct empties:** `no_authoritative_items = true` when `enumerated > 0 ∧ returned = 0 ∧ filtered.authority > 0` (ADR-0034 P5 `NoAuthoritativeItems`); an empty enumeration is `returned = 0` with the flag false. **R9 audit mode:** `mode = audit` returns revoked/superseded items with `validity.state = invalid` and `superseded_by[]`, never into a slot (D1 refuses `invalid` unless the slot admits it — it never does in `execute`).
- **Failure modes:** `StaleStore`, `NoAuthoritativeItems` (as a flagged empty result, not an error), `UnknownLayer`, `InvalidQueryKind(kind, layer)`, `RankerNotDeterministic{ranker, slot requires deterministic}`, `EmbedderUnpinned` (a `similarity` query whose embedder has no `ModelSnapshotRecord`), `BudgetExhausted` (the account refuses the embedder call — ADR-0040 reserve-before-spend), `MissingProvenance`, `IndexUnavailable{view_kind}` (a required materialized view is not built for `at`).
- **Events (WS-B1 payload proposals, CF-WS-D3-02):** `context.retrieval.completed{model_call_id, request_hash, query_kind, layers, watermark, report}` (new class, plane P1, `durability = ledger`, producer = memory store) and, per returned item, `context.memory.read{memory_id | address, version, validity, authority, taint, layer, delivery_id?, rank_evidence}` (existing class; payload extended). Retrieval cost posts `control.budget.consumed` for `tokens`/`model_calls` (embedder) and `time.working_ms` with `attribution.charged_to = subject`; `harness_overhead_attribution` gains a `retrieval` member (CF-WS-D3-03 with WS-I1).

**Ranker component class (`retrieval_ranker`; T-LCD-08/-12).** `score(candidates, query, profile, account, params) → [(candidate_id, score: decimal_string, features: map)]` + `declare() → {variant_id, deterministic: bool, features_used[], required_inputs ⊇ {ModelProfile, ResourceAccount}, model_conditioned_rules[] (with AssumptionDebtRecord)}`. Kernel-fixed feature vocabulary (closed, registered `ext`): `lexical_hits_meta, lexical_hits_body, recency_created, recency_last_read, read_count (from context.memory.read events), importance (model-authored, origin = model), structural_rank, similarity (C2), kind, scope`. Variants at C0/C1: `deterministic_default` (address/name exact → path-glob order → lexical hits → recency; ties by `version_id`), `lexical_weighted` (OpenHarness shape), `structural_pagerank` (Aider shape over `StructuralIndex`), `recency_importance` (Generative-Agents shape *without* the relevance term). C2: `similarity_rerank` (adds a cosine feature from a pinned embedder). A ranker never reads `authority`, `validity` or `readers` (they are not in the feature vocabulary) — R1 in type form.

### 6.4 Data-model sketch

- `Memory` (ADR-0016 entity 4, unchanged fields) + this dossier's typed uses: `kind: MemoryKind`, `content: Text | StructuredValue`, `validity{valid_from, valid_until | invalidation_condition}`, `authority`, `confidence` (model-authored, `origin = model`), `source_trajectories: [RunRef]`, `derived_from: [EventRef | ContentAddress]` (in the provenance record), `scope: PersistenceScope`, `version{version_id, semantic_id, supersedes?: {version_id, reason ∈ {edit, revocation, expiry, migration, consolidation}}}` — `consolidation` is a proposed `reason` value (CF-WS-D3-04 with WS-L4/A3; dialect bump).
- `MemoryManifest{scope, entries[{name, version_id, kind, one_line: Text, last_read?: EventRef}], version, provenance}` — the index form; bound to `(namespace = memory/<scope>, name = index)`.
- `MemoryStore` operations: `put(record, writer_ctx: Label, scope) → version_id` (an effect of domain `memory_write`; label = `⊔(writer_ctx, label(sources))`, capped at `external` for free text; ADR-0035 ceiling per ADR-3) · `bind(name, version_id, supersedes?, reason)` (name history append) · `revoke(version_id, reason, authority) → RevocationRecord` (ADR-0037) · `resolve(name | version_id, mode)` (ADR-0037 S3, adopted) · `manifest(scope, at) → MemoryManifest` · `stale_candidates(scope, policy) → view` (D4 consumes) · `enumerate(layer, query, at) → [RawHit]` (the index side of `retrieve`). Every operation appends its ledger event (`context.memory.written/invalidated`, `security.label.*` for promotions) and is implementable out-of-process over the canonical encoding (T-LCD-12).
- Views (ADR-0026 `project()` kinds, rebuildable, `derived_from` watermark): `lexical_index{over: ledger ranges + memory bodies + manifests}`, `structural_index{over: tree ContentAddress; symbols, refs graph}`, `memory_usage{memory_id → {read_count, last_read}}` (from `context.memory.read`), `stale_candidates`, `resume_set{names[] → head version_id}` (layer S).
- `RetrievalRequest`, `RetrievalQuery`, `SlotConstraints`, `RetrievedItem`, `RetrievalReport`, `RankerDeclaration` as in §6.3. `StructuralIndex` and `LexicalIndex` carry the index-builder's `version_id` in `derived_from` (a builder change is a view-policy version change, AC-B1-3).

### 6.5 What is delivered eagerly vs on demand (with WS-D1)

- Eager (a `required`-or-`optional` candidate produced by a `HarnessRule{action: insert ContextItem}` in the sealed definition): the `MemoryManifest` of each declared scope, rendered under a profile rule `ProfileRule{kind: memory_index_budget, max_lines, max_bytes}` with an assumption-debt record (the 200-line/25 KB and 6 000-char constants are exactly such rules); the layer-S `resume_set` heads (progress notes, feature list, goal state) when B3 resumes; the procedural *index* (names + descriptions + triggers).
- On demand (`handle_only` → `expanded` through a declared read `ToolCapability`, D1 §6.4): memory bodies, rollout summaries, verbatim ledger ranges, procedure bodies, artifact contents. Expansion emits `context.artefact.activated{detector: deterministic, signal: tool_used}`; a `similarity`/`lexical` retrieval that injects a body directly emits `delivered` for the body with `activation_observable = true` only if the profile declares a citation detector (§6.7).
- Trigger-driven (layer P; D1 `expand_requests`): `trigger{path_touched}` fires when a tool effect names a path matching a procedure's `paths` glob (OpenHands `PathTrigger`, Claude Code `paths:`, gemini JIT), `trigger{message}` on whole-token keyword match; the procedure enters as a `procedure_index` candidate with a `slot_hint`, never appended to a tool output (the gemini-cli JIT delivery path is rejected because it launders discovered instructions into the `tool` role's content stream — the RP invariant demands a candidate with its own label).

### 6.6 Memory writes, consolidation and the derived-vs-authoritative boundary — ADR-1 / ADR-3

- **Boundary (with ADR-0026).** *Authoritative:* the ledger, blobs, manifest (unchanged). *Materialized views:* deterministic projections with `deriver = kernel`, rebuildable to equal `view_hash` — `lexical_index`, `structural_index`, `memory_usage`, `stale_candidates`, `resume_set`. *Derived memories:* records produced by a `deriver = delegate` (extraction/consolidation Procedures), **not** rebuildable to equal bytes, therefore stored as first-class immutable versions in `MemoryStore` with `derived_from` ranges, `source_trajectories`, provenance and a `supersedes` chain; they are *never* written into the ledger as events (only their `context.memory.written` fact is) and never replace their sources. The test that separates the two: `project()` twice ⇒ equal hash (view); `extract()` twice ⇒ two versions with a `supersedes{reason: consolidation}` edge between them (memory).
- **Write path.** An agent writes memory only through `MemoryStore.put`, an effect of domain `memory_write` with `scope`, subject to WS-H1's monitor: check 2 (a `Permission` granting `memory_write{scope, store: memory}` in the sealed definition), check 4 (taint gate — `memory_write` is not `read_only ∧ closed`, so a tainted context makes the write `ask`/`deny` per Π unless the policy table exempts memory-store writes because their items are capped at `external` — OQ-WS-D3-03 for H1/H7), check 6 (persistence ceiling, ADR-3's row). The written label is `⊔(context_label, label(writer))` (ADR-0034 P4) with R-TEXT applied: free text ⇒ `≤ external`. Structured records validated against a closed schema declared in the definition (a `StructuredValue` memory such as `{test_command, passes}`) may be endorsed to `environment` by a `kernel` validator (ADR-0035 `validator` basis).
- **Consolidation** (Codex Phase 2 shape) is a `Procedure` with `compile_hint = subagent_task`, run under a writer lease on the memory scope (ADR-0026's lease shape reused: `lease_generation` on every `put`), reading `stale_candidates`, `memory_usage` and the episodic layer through `retrieve(mode = audit)`, and writing only via `put` + `bind(…, supersedes, reason = consolidation)` + `revoke`. Its inputs are recorded as `derived_from`; its diff is a `HirDiff`-class record when memories are procedures, or a manifest diff otherwise (an artifact by address — Codex's `phase2_workspace_diff.md`). *When* it runs (session start, idle, budget guard — Codex `guard.rs` skips when rate limits are low) is a `HarnessRule` (D4/F2), and it is charged `subject` with `harness_overhead.consolidation` (CF-WS-D3-03).
- **Promotion** (ADR-0035 `promotion`): a human reviewer raises a memory to `principal` (or the author seals it to `definition`) — a `security.label.endorsed` event with the memory's `version_id` as subject; the record itself is unchanged (label lives in provenance; a new version is minted with the new label and `supersedes{reason: edit}`, so `version_id` changes and `semantic_id` does not).
- **Retirement**: `supersedes{reason: expiry}` from D4's policy over `stale_candidates`; never deletion (I1); GC of bytes only under WS-B1 §6.5 with a tombstone.

### 6.7 Compliance chain for `memory`-kind artifacts (OQ-049 input; T-LCD-13)

`delivered` — every eager manifest line and every expanded body (D1 emits). `activated` — deterministic `signal: tool_used` when a `handle_only` memory/procedure/artifact is expanded through its declared read `ToolCapability` (Codex `usage.rs` is the precedent: reads of memory paths are the activation signal); for bodies injected directly by retrieval, `signal: cited` when the profile declares a citation convention and the reply carries a parseable citation naming the artifact (Codex `<oai-mem-citation>`) — recorded with `origin = model`, `confidence` lower than `tool_used`, `detector = deterministic` (the parse is deterministic; the claim is the model's). `followed` — deterministic only where the memory references a `Validator` (a `passes` field, a test command); otherwise judged (G3). Kinds without an activation signal (manifest lines the model never expands) collapse the chain per ADR-0014.

### 6.8 Acceptance-criteria sketch

- **AC-D3-1 Filter order is structural (AC-L3-5 executable; AIOS negative fixture).** A store with a revoked memory of higher lexical/similarity score than its replacement, an `unverified` lifted memory, and a `principal`-promoted memory: `retrieve(slot_min_authority = principal, mode = execute)` returns only the promoted item; a ranker variant that attempts to return the revoked or unverified item cannot (it never receives them); the report's `filtered{validity ≥ 1, authority ≥ 1}` counts match. (C0/Stage 2)
- **AC-D3-2 No-widen result.** Property test: for random stores and requests, `label(item) = label(stored version)` for every returned item and no `RetrievedItem` field can carry authority/validity/readers not present on the stored record. (C0/Stage 1)
- **AC-D3-3 S-106 regression (AC-L4-7).** `revoke(v)`; a `lexical`, `structural` and (C2) `similarity` request each rank `v` above its replacement pre-filter; `execute` never returns `v` or any `StaleIndex[v]` member; `audit` returns `v` with `validity.state = invalid` and `superseded_by`. (C0/Stage 2; C2 for similarity)
- **AC-D3-4 Read-your-writes.** A `put` at `seq = n` followed by `retrieve(at = (run, n))` returns the new version; `retrieve(at = n)` against a store that has applied only `n − 1` fails `StaleStore{applied_seq = n − 1}` and never returns a partial answer. (C0/Stage 2)
- **AC-D3-5 Budgeted return.** With `budget.tokens = B`, `Σ estimate ≤ B`, no item truncated, `omitted_by_budget` lists the rest in rank order; changing `B` changes only the cut. (C0/Stage 1)
- **AC-D3-6 Determinism.** Two independent implementations of `retrieve` with `deterministic_default` on a golden store (≥ 100 memories, 20 procedures, a workspace tree, 10 runs) agree on item order and `request_hash`; `structural_pagerank` agrees on the ranked prefix for the Aider fixture. (C0/Stage 1–3)
- **AC-D3-7 Boundary test.** Delete every view; rebuild `lexical_index`, `structural_index`, `memory_usage`, `resume_set` ⇒ equal `view_hash` (AC-B1-3); run `extract` twice on the same ledger range ⇒ two `Memory` versions linked by `supersedes{reason: consolidation}`, both with identical `derived_from`; neither rebuild nor extraction changes any ledger hash. (C0/Stage 2)
- **AC-D3-8 Write ceiling and label cap (ADR-3).** An AgentProcess at `delegate` with a `memory_write{scope: project, store: memory}` grant writes a free-text memory: the write succeeds, the item's authority is `external`, and on the next run it is admitted only into slots with `min_authority ≤ external`; the same process attempting a `project`-scope write outside the memory store (an instruction file) is refused `ScopeCeilingExceeded`; a `promotion` event is the only way the memory later reaches a `principal` slot (AC-D1-2 shape). (C0/Stage 2)
- **AC-D3-9 Compliance chain (T-LCD-13).** For the memory kind: `delivered` for every manifest line and body; deterministic `activated{tool_used}` on expansion; `cited` recorded with `origin = model`; the Lab computes P(activated | delivered) per profile, and the arm "memories in an `external` slot vs the same memories `promotion`-endorsed" reports `followed` under matched budget. (C0/Stage 3)
- **AC-D3-10 Deterministic vs similarity (T-LCD-14).** A pre-registered Lab arm compares `deterministic_default`/`lexical_weighted`/`structural_pagerank` against `similarity_rerank` on a memory-dependent task family under `eval_budget` equality with the embedder's `model_call`s counted; results report distributions and `harness_overhead.retrieval`. (C2/Stage 5)
- **AC-D3-11 Layer S resume.** After a crash mid-run, B3's resume reads `resume_set` heads (progress notes, feature list with validator verdicts, goal state) by name; a feature marked `passes = true` without a matching validator verdict is delivered as `unknown` validity, never `valid`. (C1/Stage 2–3)
- **AC-D3-12 Trigger retrieval.** A tool effect naming `src/api/x.ts` produces a `procedure_index` candidate for a procedure with `paths: ["src/api/**/*.ts"]` and a `context.retrieval.completed{query_kind: trigger}` event; the procedure body is not injected into the tool output. (C0/Stage 2)
