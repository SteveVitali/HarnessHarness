## 1. Scope & boundary

This workstream decides **how a Harness Definition in HIR becomes (a) executable structures for the reference runtime, (b) model-facing surfaces under a Model Profile, and (c) protocol-target artefacts (MCP tool surfaces, ACP sessions, A2A tasks/cards, provider tool APIs)**. It fixes the compilation stages, what is decided at compile time versus run time, the Model Profile *contract* (what a profile declares, how it is tested, how it expires), the semantic-equivalence obligations a compiled tool surface must satisfy, determinism and content addressing of compiled artefacts, traceability of every compiled byte back to HIR nodes, the C0 minimal compiler versus the C1/C2 compiler family, and the host-ecosystem requirements WS-L1 needs (OQ-043), plus the Agent Spec export question (OQ-031).

It explicitly leaves to neighbours: the HIR entity/edge schema and identity derivation (WS-A3 — this dossier consumes the ontology v0.1 names and flags needed changes in §8); declarative assembly and the code-vs-config boundary (WS-A5 — the compiler takes a *linked* Harness Definition as input); the concrete rule inventory and probe suite of profiles (WS-C3 — this dossier defines the contract those rules must fit); the model gateway/adapter transport (WS-C1); the tool-interface compiler's wrapper/composite synthesis (WS-E2 — this dossier defines the obligations any synthesized surface must discharge); the protocol client/server implementations (WS-E4 — this dossier defines what the compiler *emits* to them); the event taxonomy that records surface delivery (WS-B1); the assumption-debt *manager* (WS-I6, C4); the canonical byte-encoding class (WS-A3/WS-B1, OQ-041 — this dossier states the compiler's requirement on it); and every language/runtime choice (WS-L1 — nothing here names an ecosystem; contracts are operations/inputs/outputs/invariants).

## 2. Key questions

1. (doc 3 §5, verbatim) Design the multi-target compilation model: IR → executable native runtime structures; IR → model-facing surfaces via model profiles (prompt layout, tool names/schemas, error formats, compaction policy, interaction modes); IR → protocol targets (MCP tool surfaces, ACP sessions, A2A tasks).
2. (doc 3 §5, verbatim) Define compilation stages, what is decided at compile time vs run time, how profiles are independently testable/expirable components, determinism/reproducibility of compilation (content-addressed outputs), and how compiled artifacts trace back to IR nodes for attribution.
3. (Phase-0 binding, phase-0.md §5.5) ACP, MCP, A2A and provider tool APIs are lowering targets; the compiler must be able to expose a native harness through an ACP-style session interface (ADR-0005 "act as a participant"); answer OQ-043 (interpreted data vs emitted code; protocol-target artefacts).
4. (Phase-0 binding, ADR-0007) Deliver `lcd_report`, the lowering loss report and `UnexpressibleSurface` as an *error*; own T-LCD-03/-04/-05/-11.
5. (OQ-031) Should HIR export to / import from Open Agent Spec, and what is lost?
6. (added) Which surfaces exist at all? Beyond static prompt and tool schemas, the audited systems lower a *transcript* per model on every turn (thinking-signature replay, tool-call-id normalisation, empty-message filtering). Is transcript rendering a compile-time or run-time lowering, and who owns it?
7. (added) What must a Model Profile *not* be allowed to do (escape hatches), and how does a profile schema stay closed while the audited systems show open-ended growth of per-provider special cases?
8. (added) What is the minimum metadata every protocol target must carry so that "lossless-or-declared-lossy" (T-LCD-11) does not degenerate into "everything declared lossy"?

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Every mature harness already contains a compiler; none of them names it, and most implement it as branches.** Codex has a two-stage pipeline in code: a *tool plan* (`spec_plan.rs`: which handlers exist for this model/turn, driven by `ModelInfo` fields loaded from `models.json`) followed by *serialisation* to one API dialect (`tool_spec.rs`: `ToolSpec` is literally "a valid Tool in the OpenAI Responses API"), with a third, per-model *prose* layer (`model_messages.instructions_template`, reminder templates, policy prose). goose has the same split — `Provider::stream(model_config, system, messages, tools)` above, `formats/<api>.rs` below — with the addition of an *interaction-mode* lowering (`toolshim.rs`: models without native function calling get a separate interpreter model that extracts tool calls from text). opencode has the richest inventory of per-provider transforms but expresses them as `if model.api.id.includes("gpt-")` branches (`registry.ts` L290–300, `system.ts` L30–52, `transform.ts` throughout). pi-mono expresses most of the same knowledge as *typed data* (`compat` interfaces with ~40 flags; `thinkingFormat` has eleven declared variants), with request builders parameterised by those flags. DSPy names the compile step explicitly (`Teleprompter.compile`) but its "compiler" optimises *state* (demos, instructions) while `Adapter` does model-conditioned *rendering*. **Implication:** the compilation model is implementable — the pieces exist in production — and the design question is not whether to compile but *where the boundaries are drawn and what is data*. The audited systems draw three boundaries consistently: (i) plan (what exists for this model), (ii) surface (how it is rendered for this model/API), (iii) transport (how bytes go out). This dossier adopts those three as compiler stages and adds the two the audited systems lack: a *link* stage (component variants + profiles + targets bound to a validated HIR graph) and a *seal* stage (content-addressed bundle with trace map and loss report).

**F2 — Model-facing surfaces are model-conditioned at every level, including names and formatting, and the effect is not monotone across models.** Production: patch vs string-replacement edit tools (S-049), prefix vs suffix namespacing effects "varied by model" (S-037), per-slug `apply_patch_tool_type`/`shell_type`/`tool_mode` (codex `models.json`), Claude tool-call ids restricted to `[a-zA-Z0-9_-]` and Mistral to nine alphanumerics (opencode `transform.ts` L230–300). Academic: PA-Tool (Tier A, S-WS-A4-02) shows models hallucinate tool names according to pretraining conventions and that renaming to familiar names cuts misalignment errors by 80% for small models; TSCG (`provisional`) reports models that are "operator-hungry", "operator-sensitive" and "operator-robust" to schema formatting. **Implication:** T-LCD-10 (names are surfaces) is confirmed by Tier-A evidence; the profile must own *naming rules* (character set, length, namespacing scheme) and *schema dialect*, not only tool shape. Because sensitivity differs per model version, every such rule is a conditioned rule with an assumption-debt record (T-LCD-05), never a global default.

**F3 — There are three surface kinds, not one, and one of them is lowered at run time.** (a) *Static surfaces*: system-prompt layout and the tool catalogue — compiled once per configuration. (b) *Transcript surfaces*: the model-facing message list rendered from the run ledger on every turn — opencode `normalizeMessages` (empty-content filtering for Anthropic, tool-call-id scrubbing per provider, DeepSeek's required empty reasoning field, interleaved-reasoning field placement), pi `transform-messages.ts` (images replaced by a placeholder for non-vision models), goose `thinking_block_is_stale(message, current_model)` (thinking blocks signed by a different model are dropped on model switch), pi `thinkingSignature` ("provider-specific opaque … replay data"). (c) *Protocol surfaces*: what an external client/agent sees (MCP `tools/list`, ACP `configOptions` and `session/update`, A2A `AgentCard`/`Task`). **Implication:** the compiler must produce not only static artefacts but a *transcript renderer specification* that the context builder (WS-D1) applies at run time under the profile; and a *mid-run model switch* (router fallback, WS-C2) is a **re-lowering** event with its own ledger record, not a silent parameter change. No existing system records it as such.

**F4 — Lowering to a target is lossy and the loss is structured; the antidote in every protocol read is a typed extension slot plus "unknown is preserved, not coerced".** MCP: `ToolAnnotations` carry effect *hints* but the spec says clients "should never make tool use decisions based on ToolAnnotations received from untrusted servers"; `_meta` with reverse-DNS prefixes is the sanctioned carrier for anything else. ACP: `_meta` on every type; custom root fields forbidden; unknown config-option types must be *preserved* when stored/replayed/forwarded and otherwise ignored; agents MUST provide defaults so clients that ignore options still work. A2A: `AgentExtension{uri, params, required}` on the card, `metadata` Structs on `Task`/`Message`/`Artifact`, `extensions[]` on messages; no per-tool metadata at all (A2A is skill- and task-level). Provider tool APIs: strict-schema subsets (pi `makeStrictJsonSchema` throws on `$ref`, `oneOf`, tuples, non-false `additionalProperties`; opencode `sanitizeOpenAISchema` silently *drops* unsupported keywords and *invents* a type when missing). **Implication:** T-LCD-11 is implementable exactly as the battery states — carry HIR metadata through `_meta`/extensions, declare what a target cannot carry — but the loss must be classified (`no_slot`, `hint_only`, `untyped_slot`, `narrowed`, `truncated`) and a **minimum carried set** must be fixed per target so that the report cannot degenerate into "everything lossy" (§6.3). The opencode sanitiser is also a negative example: a lowering that silently invents `type: "string"` for a boolean schema is *undeclared* loss.

**F5 — Compile-time/run-time separation is the mechanism that makes harness edits testable and transferable.** Life-Harness (`provisional`, S-WS-A4-03) evolves the harness during a search phase and then *freezes* it for evaluation; DSPy compiles once and saves state (`dump_state`) for reuse; codex's tool plan is computed per turn but from per-slug data that changes only with a model release. The evidence for *what* must be run-time is equally clear: deferred tool loading and tool search (codex `ToolSpec::ToolSearch`, pi `splitDeferredTools`, Anthropic advanced tool use S-040) decide *which* compiled surfaces to reveal per turn; compaction triggers, context-window reminders (`token_budget.reminder_threshold_tokens` in codex) and permission decisions are run-time. **Implication (§6.1):** compile time decides *existence, shape, identity, policy and layout*; run time decides *selection, filling, ordering within declared layout, and triggering*. A run-time decision may never introduce a surface the compiled bundle does not contain (closed-world invariant) — this is what makes T-LCD-13 (delivered/activated/followed) computable, because every deliverable artefact has a compiled identity.

**F6 — Determinism and content addressing have a precise engineering meaning we can adopt wholesale.** Reproducible builds (S-WS-A4-06): same source + same declared build environment + same instructions ⇒ bit-identical artefacts, verified by hash. Nix RFC 0062 (S-WS-A4-07) distinguishes *input-addressed* identity (hash of the derivation: inputs + instructions) from *content-addressed* identity (hash of outputs), the latter enabling early cut-off when an input change does not change the output. MLIR (S-WS-A4-04, Tier A) shows that location/provenance information can be threaded through progressive lowering so that every lowered operation points back to its source. DSPy's `save` records dependency versions but produces no content hash, and Agent Spec assigns random component ids — neither is reproducible in the reproducible-builds sense. **Implication (§6.4):** compilation is a pure function; a bundle has both a *derivation key* (input address over HIR hash, profile hash, target-spec versions, variant versions, compiler version) and a *bundle id* (content address over the canonical encoding of outputs); the environment is *not* an input (working directory, date, hostname are run-time slot fills), which is exactly where opencode's `SystemPrompt.environment` and DSPy's dependency-version warnings show the leak.

**F7 — No audited system verifies semantic equivalence of a compiled or synthesized tool surface; the closest precedents verify *transport* validity.** goose `validate_tool_schemas`, pi `makeStrictJsonSchema`, opencode `sanitizeOpenAISchema` check that a schema is acceptable to a provider; DSPy's adapters verify that outputs *parse*; HEART (`provisional`) synthesizes natural-language tool primitives with no equivalence or safety check reported; Cursor evaluates whole-harness variants by keep-rate, not surfaces individually. Codex's `apply_patch` and `unified_exec` are two surfaces of what the IR would call `edit_file` and `execute`, but nothing in code asserts they have the same effect class. **Implication (§6.3):** the equivalence obligations are novel as a *contract*; each individual check (effect-class equality, argument-mapping totality, differential end-state tests) has ordinary software-engineering precedent, so the novelty is the integration and the placement in the compiler.

## 5. Disconfirming evidence & negative results

**Against "profiles as closed, declarative data".** The two systems with the widest provider coverage (opencode, goose) implement conditioning as code, and opencode's `transform.ts` has grown to ~1,900 lines of special cases in one file; pi-mono's typed `compat` has ~40 flags and an eleven-way `thinkingFormat` enum, i.e. the flag set keeps growing with every provider. A closed profile schema will either lag reality or grow an "other" field that becomes the escape hatch T-LCD-01 forbids. *Why this does not overturn:* codex proves a data-only profile can drive a production harness for one provider family, and pi proves typed flags can cover many families; the design response is (i) the profile schema is *versioned* (`ModelProfile/1`, `/2`…) and extended by ADR, not by ad-hoc fields; (ii) a typed, owner-declared extension block (`ext.<vendor-prefix>.<name>` with a declared type and a debt record) is allowed but every use is reported in `lcd_report.per_profile_diff_fields` and counted by a lab metric, so escape-hatch growth is *observable*; (iii) the C0 profile schema is deliberately small (§6.2). The residual risk is recorded (RK-02 lineage) and re-checked at Phase 2 (WS-C3).

**Against determinism as a goal.** Compilation can be bit-reproducible while the model is stochastic and the provider changes silently behind a fixed model id; content-addressed bundles therefore reproduce the *input* to the model, not the run. Prompt caches (goose/pi `cache_control` on the last tool; opencode `applyCaching`) even make the byte layout of the compiled prefix *performance-relevant*, so "semantically equal" bundles with different byte order are not equivalent in cost. *Why this does not overturn:* doc 2 §8's reproducible bundle already requires model snapshot + seeds + traces alongside the harness; the compiler's determinism is a necessary, not sufficient, condition, and byte-stable prefixes are *what makes caching work* — an argument for, not against, canonical encodings. The dossier separates *derivation key* (for cache/early cut-off) from *bundle id* (identity) so that a cosmetic compiler change does not invalidate experiments (§6.4).

**Against provable semantic equivalence.** Open-world capabilities (MCP `openWorldHint`, web search) have no end-state to compare; composite surfaces (codex `unified_exec` merges shell + PTY session; code-mode lets the model write programs that call tools) map one surface to *many* capabilities; and equivalence of *rendering* (truncation policies, `concise` vs `detailed` response formats) is by construction lossy. HEART (`provisional`) ships without any such check and still reports gains, suggesting the field does not consider it necessary. *Why this does not overturn:* the obligation is scoped (§6.3): closed-world workspace capabilities (file, shell, git, structured APIs) get *executable* differential checks; open-world ones get *declared* effect/permission equivalence plus lifting; composite surfaces must carry an explicit argument/plan map the reference monitor can evaluate — otherwise they are C2 (WS-E2) and cannot be admitted to C0. Rendering loss is reported, not proven absent.

**Against "runtime-interpreted data, not emitted code" (OQ-043).** DSPy programs are code with data state; LangGraph and Agent Spec adapters *generate* runtime graphs from code; codex's `code_mode_only` and opencode's experimental code-mode put the model's *own* code at the centre of tool use; the most capable 2026 control strategies (RLM REPL in Prime Agent; agentic programming, S-065) are code-shaped. A data-only control plan may hit the expressiveness ceiling OQ-002 warns about. *Why this does not overturn:* (i) the "code" in code-mode is *model-authored* and executed in a sandbox — a target surface, not host-language code the compiler must emit; (ii) DSPy's own experience is the cautionary tale: `save_program=True` requires pickled code and the docs warn it "can run arbitrary code", i.e. non-portable and unsafe — the exact reason the reference runtime should interpret data; (iii) expressiveness gaps are handled by component *variants* implemented out-of-process behind a class contract (T-LCD-12, WS-A5), never by an IR escape hatch. Code-mode and RLM-style control are C2 targets/variants, explicitly out of C0 (§6.5).

**Against protocol targets being worth the loss.** A2A carries no per-tool metadata; MCP forbids trusting annotations; ACP has no budget or validator concept. If the minimum carried set is small, "lossless-or-declared-lossy" is satisfied trivially and lifting recovers little. *Why this does not overturn:* the purpose of protocol targets (ADR-0005) is participation in existing planes at *product/configuration* granularity, not component decomposition across the boundary; the loss report makes that explicit and the comparison engine already refuses component-level metrics for such rows (T-LCD-15). The dossier fixes a non-trivial minimum carried set (identity, effect class, permission class, provenance pointer, budget reference) and requires it to travel through `_meta`/`AgentExtension`; a target that cannot carry it is admitted only as a `product`-granularity export.

**Against Agent Spec export (OQ-031).** Agent Spec has six adapters and an evaluation package, but its converters map onto *their* runtime's semantics (e.g. LangGraph `StateGraph`), so a two-hop lowering HIR → Agent Spec → LangGraph compounds loss and silently changes permission/effect semantics. *Response:* export is recommended only as a C2 `product`-granularity target with a loss report enumerating every dropped entity class; import (lifting) yields HIR with `UNKNOWN` effect/permission classes that the reference monitor treats as untrusted — useful for comparison, not for running unattended.

**Negative results from the audit.** (i) No audited system content-addresses its compiled model-facing surface; DSPy saves version metadata, Agent Spec uses random ids, codex/goose/opencode/pi keep no artefact identity at all — a run cannot say *which* prompt bytes a model saw except by re-deriving them. (ii) No audited system records a model switch mid-run as a surface change. (iii) No audited system computes anything like an opacity ratio; codex's `instructions_template` is a single ~21,500-character string, so a faithful profile of a Codex-class harness will have a *high* opacity ratio unless the template is decomposed into typed sections — a real cost of T-LCD-02 that WS-C3 must budget for (OQ raised).

## 6. Recommendation for the spec

### 6.1 Compilation pipeline (stages, inputs, outputs, invariants)

Language-agnostic; every stage is a pure operation on typed documents; the whole pipeline is itself a **component class** (`Compiler`) satisfying T-LCD-08/-12 (receives the profile; implementable out-of-process).

```
Harness Definition (HIR doc) ──┐
Component-variant registry ────┤
Model Profile(s) ──────────────┤   ┌──────────┐   ┌───────┐   ┌──────────────┐   ┌────────────────┐   ┌──────────────────┐   ┌──────┐
Target specs (versions) ───────┼──▶│ 0 parse/ │──▶│1 link │──▶│2 lower-native│──▶│3 lower-profile │──▶│4 lower-target(s) │──▶│5 seal│──▶ Compiled Bundle
Compiler version ──────────────┘   │ validate │   └───────┘   └──────────────┘   └────────────────┘   └──────────────────┘   └──────┘   (content-addressed)
                                   └──────────┘        │              │                   │                    │
                          InvalidDefinition       LinkError     PlanError     UnexpressibleSurface    LoweringLossReport (per target)
```

| stage | input → output | decides | invariants (checked) | failure modes |
|---|---|---|---|---|
| **0 parse / validate** | HIR document → *ValidatedHIR* (typed graph; semantic ids derived) | schema validity; closed references; identity derivation over semantic fields only | T-LCD-02 (free text only as typed `Text` leaves with provenance/owner/authority); T-LCD-10 (identity excludes surface fields); T-LCD-06 (no edge to Hosting ABI) | `InvalidDefinition[]` (typed diagnostics with node ids) |
| **1 link** | ValidatedHIR × registry × profile refs × target refs → *LinkedGraph* | binds every component-class slot to a variant (class, version, content hash); resolves the profile chain (base → family → version) and target spec versions; resolves policy/budget/validator references | every slot bound; every conditioned rule in the resolved profile has a complete assumption-debt record (T-LCD-05 — refusal, not warning); expired rules produce diagnostics; profile chain overrides touch only profile-owned fields | `LinkError{unbound_slot \| version_conflict \| missing_debt_record \| unknown_target}` |
| **2 lower-native** | LinkedGraph → *Runtime Plan* | the executable-but-interpreted structures: control plan (a closed set of plan node kinds: loop, step, branch-on-validator, delegate, stop-rule), tool table (capability id → executor binding, effect/permission/cost/risk classes), policy tables for the reference monitor, budget envelope, context policy parameters, validator bindings, artefact/ledger ids | plan is data (no host-language code emitted — OQ-043); every plan node references its HIR node id; policy tables are derived only from `Permission/Effect/Budget` entities (never from surfaces) | `PlanError{unsupported_construct(node)}` — the OQ-002 ceiling surfaces here as an error, never as silent fallback |
| **3 lower-profile** | Runtime Plan × Model Profile → *Model Surface* | static surface: prompt layout (typed sections in profile-declared order, slot declarations for run-time fills), tool surfaces (name, description, schema in the profile's dialect, error format, result renderer, argument map to the capability), interaction mode, sampling/caching parameters, compaction/reminder parameters; **transcript renderer spec** (rules applied at run time by the context builder) | diff between two profiles' Model Surfaces ⊆ profile-owned fields (T-LCD-01); surface ↔ HIR identity map total; opacity ratio computed; each surface field traces to a rule id | `UnexpressibleSurface(entity, profile, reason)` — first-class error (the LCD signal) |
| **4 lower-target** (one per target) | Runtime Plan × Model Surface? → *Target Artefact* + *Lowering Loss Report* | provider tool-API payload plan (function/custom/namespace dialects, strictness, cache markers, deferral); MCP tool surface (`tools/list` entries with annotations + `_meta` HIR keys); ACP session artefact (capabilities, config options, event mapping); A2A card/task mapping; Agent Spec export (C2) | minimum carried set present or the target is downgraded to `product` granularity; every dropped field is a loss entry with class; lifting recovers everything not in the report (T-LCD-11 round-trip) | `TargetError`; loss report with `severity ∈ {info, narrowed, lost}` |
| **5 seal** | all outputs → *Compiled Bundle* | derivation key (input address), bundle id (content address), trace map, `lcd_report`, opacity ratio, loss reports, diagnostics | canonical encoding; re-running on any host yields the same bundle id; bundle references no run-time value | `SealError{non_canonical}` |

**Compile time vs run time (the closed-world rule).** Compile time decides *existence, identity, shape, layout, policy, budget and mode*. Run time decides *selection* (which compiled tool surfaces are revealed this turn — deferred loading, tool search), *filling* (slot values such as working directory, date, task text, retrieved context items — each a typed slot declared in the layout), *ordering within declared layout* (context builder packing), *triggering* (compaction, reminders, retries, stop rules), *authority* (reference-monitor decisions), and *rendering of the transcript* under the compiled renderer spec. Invariant: **no run-time operation may deliver to a model an artefact that has no compiled identity** — this is what makes T-LCD-13's delivered/activated/followed events attributable and the opacity ratio meaningful. The one sanctioned run-time compilation is **re-lowering**: when the model binding changes mid-run (router fallback, user switch), the runtime calls `relower(bundle, new_profile)`, obtains a new bundle id, applies the new transcript renderer (dropping profile-opaque items such as another model's reasoning signatures — goose `thinking_block_is_stale` precedent), and appends a `surface.relowered{old_bundle, new_bundle, dropped_items[]}` ledger event (WS-B1).

### 6.2 The Model Profile contract (feeds WS-C3)

A **Model Profile** is a versioned, content-addressed data document — the *sole owner* of surface fields (ADR-0008) — with five parts:

1. **Selector** — `{provider_api_family, model_family, version_pattern, precedence}`; profiles form a chain (`extends`) base → family → version; override semantics limited to owned fields; resolution is by declared selector precedence, never by substring tests in code (replaces opencode `system.ts`/`registry.ts` branches; precedent for the data form: codex `models.json` slugs, OpenHands `model_prompt_spec` family/variant).
2. **Capability declaration** (typed, per model/API pair) — `native_function_calling, parallel_tool_calls, strict_schema_dialect ∈ {none, subset-A, …}, structured_output, grammar_tools, reasoning_replay{field, opaque}, interleaved_reasoning, image_input, context_window, max_output, developer_role, cache_control_convention, tool_result_name_required, assistant_required_after_tool_result, temperature_supported, deferred_tools, tool_search` — precedent: pi `compat` interfaces, opencode `capabilities`, AutoGen `ModelInfo`. Values are `declared`; a **profile conformance probe** (§ below) turns them into `probed` and flags `DRIFT` exactly as the Hosting ABI does for participants (ontology *observed conformance*), so a profile is experimental data, not gospel.
3. **Conditioned rules** — each `{rule_id, kind, owned_fields[], params, debt: AssumptionDebtRecord}` with `kind ∈ {tool_shape (capability class → surface family, e.g. edit_file → patch \| string_replace), naming (charset, max length, namespace scheme prefix\|suffix), schema_dialect (strict transform, dropped keywords with declared loss), description_template, error_format, result_render (truncation policy, detailed\|concise), prompt_layout (section order, reminder placement), interaction_mode (native_fc \| freeform \| shim \| code_mode), transcript_render (id normalisation, empty-part filtering, reasoning field placement, image downgrade), compaction_reminder (thresholds, template), sampling_defaults, caching_markers}`. The kinds are a closed enum per profile-schema version; a typed, owner-declared `ext` block exists but every use is reported (see §5).
4. **Assumption-debt record on every rule and on the profile itself** — `{rule_id, hypothesis, evidence_refs[], owner, expiry_condition, removal_test_ref, status ∈ {active, expiring, expired, retired}}` (schema per lcd-test-battery; C0/Stage 1). `expiry_condition ∈ {model_version_change, date, probe_failure, evidence_refresh_due, experiment_ref}`. The compiler *refuses* a rule with a missing record, *warns* on `expired`, and exposes the lab recipe "retire rule R" as `relower(bundle, profile − R)` so a delete-this-rule arm is one compile away (T-LCD-05, reflexive: the profile carries `expiry` for the profile compiler's own existence).
5. **Test obligations** — a profile is *independently testable* by four suites, all runnable without the rest of the harness: (i) **static**: schema validity; owned-field discipline (compile a fixture HIR under this profile and a null profile; diff ⊆ owned fields — T-LCD-01); (ii) **probe**: capability probes against the live model adapter (does a dotted tool name round-trip? does strict schema accept `anyOf`? is a reasoning signature replayable?) producing `ConformanceRecord`s; (iii) **equivalence**: every `tool_shape` rule ships the equivalence evidence of §6.3 for the surface family it selects; (iv) **behavioural**: a compliance suite per profile measuring delivered/activated/followed for its conditioned rules (T-LCD-13) so that "harness validity" and "harness compliance" are separated per profile (S-088 mechanism).

**Expiry semantics.** A profile version is `active` while all its rules are `active`; `expiring` when any rule's `expiry_condition` is met; `expired` when a probe fails or the model version pattern no longer matches any served model; `retired` by ADR after a removal test passes. Compiling under an `expired` profile is allowed only with an explicit `--allow-expired` intent recorded in the bundle (so experiments can deliberately test dead weight, S-047). Profiles are content-addressed; a rename or description edit yields a new profile hash and *no* HIR change (T-LCD-10).

### 6.3 Semantic-equivalence obligations for compiled tool surfaces (feeds WS-E2)

For a `ToolCapability` C lowered under profile P to surface S (or a set of surfaces), the compiler must attach `EquivalenceEvidence` establishing, in decreasing order of strength:

| # | obligation | what must be preserved | verification level | who |
|---|---|---|---|---|
| E1 | **Effect-class equality** | `effect_class(S) = effect_class(C)` for every reachable invocation (read-only / additive / destructive / idempotent / open-world — the MCP annotation vocabulary is adopted as the *typed* effect enum in HIR, with HIR values authoritative and MCP hints derived) | static, from the argument map | compiler (C0) |
| E2 | **Authority soundness and totality** | every S argument maps to a C parameter through `SurfaceArgMap` (field → parameter, transform, declared narrowing); the reference monitor evaluates `Permission` on C's parameters only; no S argument is unmapped (totality) and no mapped value can reach a C parameter outside its declared domain (soundness) | static + property test over the argument domain | compiler (C0) |
| E3 | **Precondition-domain preservation** | accepted inputs of S's schema, after mapping, ⊆ C's precondition domain; narrowing (e.g. strict-schema subsets) is allowed but declared as loss `narrowed`; widening is an error | static (schema inclusion) | compiler (C0) |
| E4 | **Differential end-state equivalence** (closed-world capabilities) | a scripted sequence of C invocations executed through S and through the reference surface yields identical workspace end-state and identical `Effect` ledger entries on a fixture suite | executable, Stage 3 | E2 / I2 |
| E5 | **Error-class surjectivity** | every failure class of C has a rendering in S's error format; renderings are distinguishable by the model (no two classes collapse to one text) | static + rendering test | C3 |
| E6 | **Result-observation adequacy** | S's result renderer preserves every field a bound `Validator` reads; truncation/concision is declared loss `truncated` with the retained fields listed | static against validator bindings | compiler + G-track |
| E7 | **Accounting and identity** | cost/latency/approvals attributed to C's id regardless of surface; `trace_map(S) ∋ C.id`; rename changes only the profile hash | static | compiler (C0) |

Composite or synthesized surfaces (one surface ↔ many capabilities, or a wrapper with logic — codex `unified_exec`, HEART-style primitives, code-mode) must express their mapping as a *plan* (a small HIR `Procedure`) so E1–E3 remain checkable; if they cannot, they are inadmissible at C0 and belong to the C2 tool-interface compiler (WS-E2) with E4 mandatory. Open-world capabilities discharge E1–E3, E5, E7 statically and mark E4 `n/a (open-world)` in the evidence — never 0 (same rule as T-LCD-15).

### 6.4 Determinism, reproducibility, content addressing

- **Purity.** `compile(inputs) → bundle` reads nothing but its declared inputs: HIR hash, resolved variant hashes, profile chain hashes, target-spec versions (e.g. MCP `2026-07-28`, ACP v2 schema hash, A2A 1.0.0), compiler version/hash. No clock, randomness, environment or network. Environment-dependent values are *slots* filled at run time and recorded in the ledger.
- **Two identities per bundle** (Nix RFC 0062 precedent): `derivation_key = H(canonical(inputs))` for caching and early cut-off; `bundle_id = H(canonical(outputs))` for identity in experiments and the reproducible harness bundle (WS-I3). Two compiler versions producing byte-identical outputs share a `bundle_id`; an experiment's configuration id references `bundle_id`.
- **Requirement on WS-A3/WS-B1 (OQ-041):** compiled artefacts need a canonical deterministic byte encoding with a specified hash over it; the *class* of encoding is theirs to choose, but it must (a) have a total canonical form for every document type the compiler emits (including the schema dialects of the targets), (b) be checkable by an independent re-implementation (reproducible-builds discipline: "any party can recreate bit-by-bit identical copies"), (c) preserve field order where a target makes order semantically or cache-relevant (prompt-cache prefixes).
- **Acceptance:** AC-1 in §6.7.

### 6.5 Protocol targets and the minimum carried set (feeds WS-E4, WS-K3; answers OQ-043 and OQ-031)

The compiler **emits protocol-target artefacts as data documents** conforming to the target's published schema (MCP `schema.ts`/`schema.json`, ACP `schema/v2/schema.json`, A2A `a2a.proto`/JSON), never host-language code. Per target:

| target | emitted artefact | HIR → target mapping (lowering) | extension carrier | typical losses (declared) | lifting recovers |
|---|---|---|---|---|---|
| **Provider tool API** (per profile) | request plan: tool list in dialect (function / custom-freeform / namespace / strict subset), system layout, sampling, cache markers, deferral flags | ToolCapability → surface (§6.3); `Text` leaves → sections | none standardised; provider-specific fields are profile-owned | schema keywords outside the strict subset (`narrowed`), truncation (`truncated`) | n/a (this target is consumed by the model, not lifted) |
| **MCP tool surface** (server export; also the client-side import shape) | `Tool{name, title, description, inputSchema, outputSchema, annotations, _meta}` list + `listChanged` when the run-time selection changes | effect class → `annotations` hints; identity/effect/permission/cost/risk/provenance → `_meta["<hh-prefix>/hir"]` (reverse-DNS prefix per MCP rules; WS-L6 picks the prefix) | `_meta` | permission *enforcement* location (client's kernel decides), budgets (no slot), validators (no slot) | everything in `_meta`; annotations from *untrusted* servers lift to `effect_class: DECLARED_UNVERIFIED` (a capability-declaration, not a fact), which the reference monitor treats as destructive/open-world until probed |
| **ACP session** (native harness as ACP agent — ADR-0005 obligation) | `initialize` capabilities (from the Harness Definition's capability declaration), `configOptions` (HIR parameters marked session-variable: model, mode, reasoning level → categories `model`/`mode`/`_hh_*`), `session/update` mapping table from ledger events, `requestPermission` from reference-monitor decisions, `_meta` HIR ids on every emitted type | run states → prompt lifecycle; tool events → `ToolCall` with kinds; plan entries from control plan | `_meta` (every type), `_`-prefixed methods for ledger export | budgets (no slot), effect metadata beyond `ToolCallKind`, validators, provenance of content blocks | `_meta` ids; unknown option types preserved by compliant clients (ACP rule) |
| **A2A** | `AgentCard{skills ← exported Procedures/Goals (id = semantic identity), capabilities{streaming, push, extensions[AgentExtension{uri: hh-hir, params: {bundle_id, …}}]}, version ← bundle_id, signatures}`; `Task` lifecycle ← run states (`INPUT_REQUIRED` ← permission/elicitation; `AUTH_REQUIRED`; `REJECTED` ← policy denial); `Artifact` ← HIR `Artifact` | procedure-level, not tool-level | `AgentExtension`, `metadata` Structs | all per-tool metadata (A2A has no tool concept), budgets | bundle id + skill identities; rest `product` granularity |
| **Open Agent Spec** (C2; OQ-031) | `Agent/Flow/Tool/LlmConfig` document | control plan → flow nodes where a node kind exists; ToolCapability → `Tool`; profile params → `LlmConfig` | none (spec forbids extra fields: `extra="forbid"`) | `Permission, Effect, Validator, Budget, Memory` validity, `HarnessRule`, provenance — i.e. the entire seven-plane surplus; component ids are regenerated (uuid) | import = lifting to HIR with `UNKNOWN` effect/permission and `Text` leaves of owner `external`; `product` granularity only |

**Minimum carried set (per target, or the export is `product`-granularity only):** `{hir identity (semantic id + bundle_id), effect class, permission class, provenance pointer (origin + authority class), budget reference}`. MCP and ACP can carry it in `_meta`; A2A carries it at card/skill level via `AgentExtension` (tool-level is lost by construction); Agent Spec cannot carry it. T-LCD-11 is therefore satisfiable non-trivially for MCP/ACP and honestly degraded for A2A/Agent Spec.

**OQ-043 answers (for WS-L1, language-neutral).** (1) Compiled control structures are **runtime-interpreted data**: a closed, versioned set of plan-node kinds interpreted by the reference runtime; the compiler never emits host-language source. (2) The compiler **must emit** MCP tool-surface documents (C0, Stage 3 — required by T-LCD-04's second target) and ACP session artefacts (C1, Stage 4 — required by ADR-0005/OQ-032); A2A cards/tasks and Agent Spec export are C2. Host-ecosystem requirements that follow (no language named): a deterministic canonical serialisation + hashing facility for schema-described documents; first-class JSON-Schema manipulation (subset transforms, inclusion checks, validation) because every target's tool dialect is a JSON-Schema variant; schema-first generation of protocol bindings from the three published schema sources (MCP `schema.ts`/`schema.json`, ACP `schema.json`, A2A proto/JSON) with CI drift checks (WS-L1 §6.5 pattern); an interpreter for a small typed plan language with exhaustive handling of node kinds; the compiler runnable as an out-of-process component exchanging typed documents (T-LCD-12); and, for C2 only, a sandboxed engine for *model-authored* code (code-mode) — which is a target surface, not a host-language requirement of the kernel.

### 6.6 C0 minimal compiler vs the C1/C2 family

| tier / stage | scope | what exists | what is deliberately absent |

### 6.7 Interface-contract sketch (operations · inputs/outputs · invariants · failure modes)

- `validate(hir_doc) → ValidatedHIR | InvalidDefinition[]` — invariants: identity derivation excludes surface fields; typed `Text` leaves only; no Hosting-ABI edges.
- `link(validated, registry, profile_refs[], target_refs[]) → LinkedGraph | LinkError` — invariants: all slots bound; every conditioned rule has a complete debt record; profile-chain overrides ⊆ owned fields.
- `lower_native(linked) → RuntimePlan | PlanError` — invariants: plan nodes ∈ closed kind set of `RuntimePlan/1`; every node carries `hir_node_id`; policy tables derive only from `Permission/Effect/Budget` entities.
- `lower_profile(plan, profile) → ModelSurface | UnexpressibleSurface(entity, profile, reason)` — invariants: `diff(lower_profile(plan, P1), lower_profile(plan, P2)) ⊆ owned_fields(P1) ∪ owned_fields(P2)`; every surface element has `trace ∋ hir_node_id` and `rule_id`; opacity ratio computed.
- `lower_target(plan, surface?, target) → (TargetArtefact, LoweringLossReport)` — invariants: minimum carried set present or `granularity = product`; loss entries typed `{hir_node_id, field, class ∈ {no_slot, hint_only, untyped_slot, narrowed, truncated}, severity}`.
- `lift(target_artefact, target) → PartialHIR{recovered, unknown[], declared_unverified[]}` — invariant: `recovered ∪ loss_report = original` for artefacts this compiler produced (round-trip test); foreign artefacts yield `DECLARED_UNVERIFIED` effect/permission classes.
- `seal(outputs) → CompiledBundle{bundle_id, derivation_key, runtime_plan, model_surface, target_artefacts{}, trace_map, lcd_report, loss_reports{}, opacity_ratio, diagnostics[]}` — invariants: canonical encoding; `bundle_id` stable across hosts; no run-time values.
- `relower(bundle, new_profile) → CompiledBundle'` plus `TranscriptMigration{dropped_items[], rewritten_items[]}` — invariant: `runtime_plan` unchanged; only stages 3–5 re-run.
- `trace(bundle, locator) → {hir_node_ids[], rule_ids[], target_rule_ids[]}` — invariant: total over every model-facing token span and every emitted target field.
- `lcd_report(harness_def, profiles[], targets[]) → LcdReport` — as ratified in the battery; this compiler supplies `per_profile_diff_fields`, `lowering_loss`, `conditioned_rules`, `identity_stability`, `hosting_edges`, `opacity_ratio`.
- `check_equivalence(surface, capability, suite?) → EquivalenceEvidence{E1..E7: pass | fail | n/a(reason)}`.
- `probe_profile(profile, model_adapter) → ConformanceRecord[]` (C1) — invariant: `unknown` never coerced to `unsupported`.
- Run-time hooks the compiler *specifies* but does not execute: `render_transcript(ledger_view, renderer_spec) → ModelMessages` (executed by the context builder, WS-D1) and `select_surfaces(bundle, turn_state) → revealed[]` (executed by the tool plane, WS-E3) — both constrained by the closed-world rule.

### 6.8 Data-model sketch

`ModelProfile{profile_id, version, content_hash, selector, extends?, capabilities: CapabilityDeclaration, rules: ConditionedRule[], ext?: {prefix: typed block}, expiry: AssumptionDebtRecord}` · `ConditionedRule{rule_id, kind, owned_fields[], params, debt: AssumptionDebtRecord}` · `RuntimePlan{plan_version, control: PlanNode[], tools: ToolBinding[], policies, budget, context_policy, validators, ids}` · `ModelSurface{layout: Section[]{section_id, source_node_ids, slots[], text?}, tools: ToolSurface[], interaction_mode, params, transcript_renderer: RendererSpec}` · `ToolSurface{surface_name, hir_node_id, dialect, schema, description, error_format, result_render, arg_map: SurfaceArgMap, equivalence: EquivalenceEvidence}` · `SurfaceArgMap{entries[{surface_field, capability_param, transform, narrowing?}]}` · `LoweringLossReport{target, target_version, entries[], granularity_ceiling ∈ {component, configuration, product}}` · `TraceMap{locator → {hir_node_ids[], rule_ids[], target_rule_ids[]}}` · `CompiledBundle{…}` (§6.7) · `ConformanceRecord{profile_version, capability, declared, probed, verdict, probe_run_id}` · `SurfaceRelowered` ledger event (WS-B1).

### 6.9 Acceptance-criteria sketch

- **AC-1 Determinism.** Compiling the same inputs on two independent hosts yields byte-identical bundles (`bundle_id` equal); introducing a clock/env read fails a purity test.
- **AC-2 Owned-field discipline (T-LCD-01).** Fixture HIR compiled under two profiles: diff ⊆ owned fields; an `if model == X` fixture in HIR fails validation.
- **AC-3 Trace coverage.** 100% of model-facing token spans and 100% of emitted target fields resolve through `trace`.
- **AC-4 Round-trip (T-LCD-11).** For every C0/C1 target, `lift(lower(x)) ∪ loss_report = x`; a fixture that drops permission metadata *without* a loss entry fails.
- **AC-5 LCD error.** A profile requiring a surface the HIR cannot express raises `UnexpressibleSurface` (error, non-zero exit), never a warning.
- **AC-6 Debt discipline (T-LCD-05).** A rule without a complete record is refused at link; an expired rule warns and is listed in `lcd_report`; "retire rule R" produces a valid arm.
- **AC-7 Two targets × two profiles (T-LCD-04).** The Stage-0 reference harness compiled to native and MCP-export under both minimal profiles passes the same executable validators; permission/effect/budget tables identical across targets.
- **AC-8 Behavioural round-trip (T-LCD-03).** Paired runs, pre-registered margin, distributions reported (with WS-I2).
- **AC-9 Re-lowering.** A mid-run model switch yields a new `bundle_id`, a `surface.relowered` event, and a transcript with no profile-opaque items from the previous model.
- **AC-10 Equivalence evidence.** Every C0 tool surface carries E1–E3, E7 `pass`; `edit_file`/`execute`/`read_file` carry E4 `pass` on the fixture suite; open-world capabilities carry E4 `n/a(open-world)`.
- **AC-11 Out-of-process compiler (T-LCD-12).** The compiler runs as a separate process exchanging typed documents and the acceptance suite is unchanged.
- **AC-12 Opacity ratio (T-LCD-02).** Stored in every bundle; a profile whose prompt layout is one opaque leaf is reported, not rejected (definition per OQ-036).

## 10. Confidence

**High** for the pipeline shape, the compile/run-time split, and the three-surface finding: each is read directly from five production systems at pinned commits and matches a Tier-A compiler precedent (MLIR) and Tier-B build-system practice (reproducible builds, Nix). **High** that protocol lowering must go through typed extension slots and a minimum carried set: the three protocol specs say so in normative language. **Medium** for the profile contract's rule-kind enum: the *shape* is well precedented (pi, codex, AutoGen), but the closed enum may need extension at Phase 2 and the escape-hatch risk is real (§5). **Medium** for the semantic-equivalence obligations: individually ordinary, collectively unprecedented (`novel` as an integrated contract; HEART shows the field skips them); E4 is only demonstrated for closed-world workspace tools. **Low-to-medium** for anything quantitative from 2026 preprints (TSCG, Life-Harness, HEART — all `provisional`, none load-bearing); PA-Tool is accepted (ACL 2026) but single-team and small-model. No C0 recommendation depends on a provisional performance claim.
