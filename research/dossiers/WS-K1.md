## 1. Scope & boundary

This workstream decides the **command-line surface** of HarnessHarness: the abstract **command taxonomy** (nouns and verbs over the ontology's objects), the **mode model** (how one command set serves an attended terminal, an unattended script, a long-lived local service for other surfaces, and an ACP agent endpoint), the **I/O contracts** (what goes to stdout vs stderr, the human/JSON/JSONL formats, stdin typing, idempotency of work-injecting invocations, the closed exit-code table), and the **safety defaults** (how attendance, approval mode, unattended policy and containment evidence are set, recorded and refused). It answers OQ-265 (turn-exhaustion policy on the attended CLI) and takes a position on OQ-076 (ad-hoc CLI overrides as materialised layers) consistent with WS-J1.

It explicitly leaves to neighbours: every operation's semantics — assembly (WS-J1, ADR-0025), registry (WS-J2, ADR-0037/0088), experiments (WS-J3, ADR-0045/0046), results and leaderboards (WS-J5), hosting (WS-J6, ADR-0098), approvals (WS-H7, ADR-0069…0071), run lifecycle and recovery (WS-B3, ADR-0130), budgets (ADR-0039…0041), environments (ADR-0136…0138); the **SDK/embedding boundary the CLI is a client of** (WS-K4 — its dossier does not yet exist, so this dossier consumes ADR-0050's D2/D3 and ADR-0049 §4 Q-L1-14 as the provisional shape and flags CF-353); the web surface (WS-K2) and MCP server (WS-K3), which share the same local transport; packaging, naming and distribution (WS-L6); and the plugin contract (WS-L5). The CLI **owns no semantics**: every command is a boundary verb or a projection the kernel/Lab already defines, and every default the CLI applies is a typed Harness Definition parameter or run-manifest fact defined elsewhere.

## 4. Findings

### 4a. Mechanism evidence

**F1 — Every mature terminal harness is two products under one binary: an attended REPL/TUI and a headless one-shot runner, and all six anchors have converged on the same triad of machine formats.** codex `exec` (S-107), gemini `-p` (S-119), goose `run` (S-112), opencode `run` (S-111), Claude Code driven by its SDK through `--output-format stream-json` (S-109) and mini-swe-agent `-y --exit-immediately` (S-115) are all one-shot drivers; gemini, goose and Claude Code independently chose the format triple `text | json | stream-json` (codex: human vs `--json` JSONL; opencode: `default | json`). This is convergence on a **mechanism** (a durable, line-delimited typed event stream for machines; a summarised terminal record for humans), not on a vocabulary — each product's event names differ (`ThreadEvent`/`ThreadItem` vs `init/message/tool_use/tool_result/error/result` vs `{type, timestamp, sessionID}`).

**F2 — Attendance is inferred from the terminal in every precedent, and the inference silently changes safety behaviour.** gemini derives `interactive` from `-p`, positional args and TTY (`config.ts` L782–797) and then *excludes tools that require a prompt*; mini-swe-agent's `_stdin_is_interactive` decides whether a limit can be raised; goose's elicitation reads one line from a non-TTY stdin (`elicitation.rs` L262); codex `exec` sets `AskForApproval::Never` because the mode is headless (`lib.rs` L562–571); opencode `run` auto-rejects every permission request unless `--auto` (`run.ts` L801–820). None of them records *which* source decided the attendance, and none of them ledgers the resulting automatic denials as decisions. ADR-0069 already fixed the antidote: `attendance ∈ {interactive, async, unattended}` is a **run-manifest fact** and `Π-12` resolves `ask` under `UnattendedPolicy`. The CLI's job is therefore to *declare* attendance (defaulting from TTY detection, forced by an explicit flag) and to record the source of the declaration — never to let the decision point re-derive it.

**F3 — "Bypass" modes exist everywhere and are named as dangerous everywhere, but only one precedent ties the bypass to a recorded containment fact.** codex `--dangerously-bypass-approvals-and-sandbox` (deprecated in its docs, S-537), opencode `--auto` "(dangerous!)" with hidden aliases `--yolo`/`--dangerously-skip-permissions`, gemini `--yolo`, Claude `bypassPermissions` (which also *shadows* the permission callback and warns about it — S-109 L1838), mini-swe-agent `--yolo`, goose `GOOSE_MODE=auto`. Codex's `SandboxPolicy::ExternalSandbox` (S-107 `protocol.rs` L1088–1096) is the only shape that records "already inside a sandbox" as a distinct state. ADR-0069 decision 3 requires `bypass` to be admissible only with `containment.sandboxed` recorded in the run manifest and still excluding the never-auto set; the CLI must refuse the bypass flag when no `ContainmentPolicy` evidence exists (`enforcement_evidence` tri-state, ADR-0136).

**F4 — The CLI-as-client shape is now production practice.** opencode `run` boots an in-process server or attaches to a running one and drives it through the same SDK the TUI/web use (`run.ts` L1–16, L192); Claude Code's SDK is a subprocess client of the CLI's bidirectional JSONL (S-109 `subprocess_cli.py`); codex has `app-server` and a daemon (`main.rs` L170–174); goose has `serve` (ACP over HTTP/WebSocket) and `acp` (stdio). This corroborates ADR-0049 §4 / ADR-0050 (surfaces via a generated client over the kernel's local transport) and gives the CLI its architectural rule: **no command implements semantics; every command is a boundary verb or a projection**.

**F5 — Exit codes are either flat (goose, opencode: `exit(1)` everywhere) or a small typed table (gemini 0/1/42/53 from `FatalError.exitCode` subclasses; mini-swe-agent carries `exit_status` in the trajectory instead).** Scripts need the table; HarnessHarness already has the closed sums it should derive from: `StopReason` (ADR-0106) and `outcome_class` (ADR-0045). A CLI-specific error taxonomy would be a second sum for the same facts (violates the one-declaration-per-seam rule, ADR-0048/0145).

**F6 — Ad-hoc overrides are universal (`-c key=value` in mini-swe-agent and codex; `--model`, `--agent`, `--approval-mode` everywhere) and un-attributed everywhere.** WS-J1 D2 answers OQ-076: the override list becomes exactly one content-addressed `experiment`-provenance layer. The CLI is the largest source of such overrides and must feed the same desugaring, so that an ad-hoc `--budget` or slot rebind from a terminal and the same override from a sweep are one record.

**F7 — Stdin content is untyped in every precedent.** codex appends piped stdin as a `<stdin>` block to the prompt (S-537; `StdinPromptBehavior::OptionalAppend`); opencode merges it into the message; gemini appends it. Under ADR-0033 all free text not from kernel/definition/principal is `external`; text typed by the human principal at a TTY is `principal`. The CLI can distinguish the two (TTY vs pipe) and must label them differently — a piped file is exactly the "Rules File Backdoor"/context-privilege vector (S-314, S-103) if it enters at `principal`.

**F8 — Mid-run mode changes are a control message, and they invalidate cached decisions.** mini-swe-agent `/y /c /u`; Claude SDK `set_permission_mode`; gemini/goose mode toggles. ADR-0071 fixes the consequence: changing `approval_mode` changes the policy fingerprint and revokes every lease; ADR-0040 makes a budget change a ledgered `amend`. The CLI's mid-run commands therefore lower to `amend` operations, never to process-local state.

**F9 — Confirmation UX is not cosmetic.** S-327 (>25M warning impressions; adherence from 7 % to 33 % by design) plus ADR-0071's typed `Explanation` (kernel-derived risk factors; model justification rendered with distinct `delegate` provenance) mean the CLI's approval prompt is a compliance surface with acceptance criteria, not a print statement.

## 5. Disconfirming evidence & negative results

- **Against "CLI as thin generated client" (§6.1):** the two most-read production CLIs are *not* thin — codex `exec` and gemini's non-interactive path contain substantial control logic (config resolution, approval-policy rebuilds, tool exclusion) that lives in the CLI layer, and every precedent that started thin grew CLI-only behaviour (opencode's auto-reject is CLI code). The risk is that a thin CLI forces every operator convenience through the boundary contract and slows iteration. Mitigation: conveniences that are pure *presentation* (rendering, paging, colour, prompts) stay in the CLI; anything that changes a ledger fact is a verb. The test is AC-K1-02 (byte-equality of ledger effects between the CLI and a direct client call). This does not overturn the decision because ADR-0050 already binds the surface layer to a generated client and CF-017 pre-registers the exposure.
- **Against "JSONL = canonical ledger events" (§6.4):** every precedent ships a *curated* CLI event vocabulary (codex `ThreadItem`, gemini `stream-json`) precisely because raw runtime events are too fine-grained and unstable for script authors; consumers of Claude Code's `stream-json` also see a curated stream. Raw ledger events (dense `seq`, effect phases, budget postings) are noisier. Mitigation: the canonical stream is the *default machine format* because it is the only lossless one (T-LCD-11) and the ledger class list is already versioned per dialect; a `compact` view is offered as a declared-lossy projection with a loss report. The disconfirming point stands as a usability cost, not a correctness one.
- **Against "attendance declared, not inferred" (§6.3):** TTY inference is what every precedent does and it is right in the overwhelming majority of invocations; forcing a declaration adds ceremony. Mitigation: inference remains the *default source* of the declaration; the change is only that the source is recorded and frozen in the manifest. The residual cost is one manifest field.
- **Against "bypass requires containment evidence":** codex's own docs deprecate the bypass flag rather than gating it, and opencode hides its aliases — the precedents' answer is discouragement, not refusal. A hard refusal may push users to fake containment evidence. Mitigation: the evidence is kernel-minted (`ContainmentPolicy.enforcement_evidence`, ADR-0136/0138) and is a claim only where the mechanism cannot verify; a faked claim caps the bundle at R0 and is visible in the audit view. This does not overturn ADR-0069 decision 3, which the CLI merely enforces.
- **Against a closed exit-code table:** BSD `sysexits` conventions are inconsistently honoured, and shell scripts mostly test `≠ 0`. A rich table risks collisions with shell-reserved codes (126, 127, 128+signal). Mitigation: codes are assigned in a reserved band that avoids 1, 2, 126–165 and 255, and the `result` JSON record is the authoritative machine-readable outcome; the numeric code is a convenience (OQ-384).
- **Against noun-verb ordering:** clig notes both orders work; goose and codex mix them (`session list` vs `exec`, `resume`). The cost of choosing is small; the cost of mixing is a catch-all growth path. Adopted with the additive-change rule.
- **Negative result:** no anchor CLI exposes experiments, comparisons or leaderboards at all (mini-swe-agent's batch runner is the closest); the laboratory nouns in §6.2 are therefore `no-precedent / novel` at the CLI layer and inherit their semantics entirely from WS-J3/J5 — the CLI adds no claim.

## 6. Recommendation for the spec

### 6.1 Architectural rule — the CLI is a generated client and a renderer (Spec §7 lead)

The CLI is one of three surfaces (with WS-K2 web tooling and WS-K3's MCP server) over the **kernel/Lab local transport** of ADR-0050 (E3 default; Q-L1-14 provisional, WS-K4 to confirm). It consists of exactly three kinds of code: (i) **argument mapping** — flags and positionals mapped onto typed boundary records (`AssemblySource`, `Override`, `ExperimentSpec`, run manifests, `ApprovalResponse`, `QuerySpec`…); (ii) **verb invocation** — one boundary verb or Lab operation per command, with an `idempotency_key` on every work-injecting call (ADR-0050 D3 amendment, ADR-0130); (iii) **rendering** — projections of ledger views into human, JSON or JSONL output, prompts for `ApprovalRequest`s and elicitations, and terminal chrome. Invariant **K-1 (no CLI-only semantics):** for every command there exists a boundary verb sequence such that the ledger effects of the command and of the sequence are byte-identical (AC-K1-02). Invariant **K-2 (out-of-process):** the CLI never links kernel code; it attaches to a running local service or spawns one per invocation (opencode's two modes), and the choice is invisible in the ledger. Invariant **K-3 (additive surface):** commands, flags and output records are only ever added; a removal is a deprecation cycle with a warning on stderr (clig; S-535).

Boundary placement (ADR-0050 D2, by layer only): argument mapping and rendering are surface-layer; every verb is served by the Lab layer (assembly, registry, experiment, results, hosting operations) or the kernel layer (run, approval, environment, bundle, ledger reads) through their existing contracts. WS-J1 CF-322 already asks WS-K4/L5 to add assembly verbs to the §6.5 verb set; this dossier extends that request to every Lab operation named in §6.2 (CF-356).

### 6.3 Mode model

Two orthogonal axes, deliberately separated because the precedents conflate them (F2):

**Axis A — attendance (a run-manifest fact, ADR-0069):** `interactive` (a human principal can be reached synchronously at this terminal), `async` (a human can be reached later — `defer` is available; ADR-0070 decision 4), `unattended` (no human; Π-12 applies). The CLI sets it from `AttendanceDeclaration{value, source ∈ {declared, tty_inferred, forced}}`: an explicit flag ⇒ `declared`; clig's `--no-input` equivalent ⇒ `forced(unattended)`; otherwise `tty_inferred` from stdin **and** stdout/stderr being terminals (goose `elicitation.rs` L32 checks both). The declaration is frozen in the run manifest; a later transition (goose `--interactive`, gemini `-i`, or a human attaching to a suspended run) is a ledgered `amend(attendance)` that revokes leases like any policy-fingerprint change (ADR-0071).

**Axis B — presentation mode (a surface property, never in the ledger):**
- `attended terminal` — REPL/TUI; renders `ApprovalRequest`s and elicitations as prompts; supports mid-run commands (`cancel`, `steer`, `amend approval_mode`, `amend budget`, `inspect`) as boundary verbs; a first interrupt signal is `cancel` of the turn (`cancelled{by: principal}`), a second is `cancel` of the run.
- `headless` — one invocation, one run (or one Lab operation), exit on the terminal event; progress to stderr, result to stdout (S-537); stdin per §6.4.
- `serve` — a long-lived local service exposing the same transport to K2 (web), K4 clients and further CLI invocations that `attach` (opencode `serve`/`--attach`, codex `app-server`, goose `serve`); the CLI in this mode adds nothing to the transport (K-1).
- `acp` — stdio ACP agent per the ADR-0098 artefact (C1/Stage 4): a native harness acting as a participant in an editor's plane; approval transport per `effect_id`; `allow_once`/`reject_once` only until OQ-246.

Legal combinations: `attended terminal` ⇒ attendance `interactive`; `headless` ⇒ `unattended` by default, `async` when a `--defer`-class option names a notification sink, `interactive` only when forced *and* a TTY exists (mini-swe-agent's rule); `serve`/`acp` take attendance per session from the connecting client's declaration (ACP hosts are `interactive` by default). Invariant **M-1:** `attendance = interactive` with no TTY is an `InvocationError` (never a hang on a pipe — the failure mini-swe-agent's `_stdin_is_interactive` guards against). Invariant **M-2:** under `unattended`, prompting tools are not *excluded* (gemini's approach changes the tool surface and therefore the configuration identity, T-LCD-10); instead every `ask` resolves by Π-12 and is ledgered (`decider: policy, reason: unattended`), so the same sealed definition runs attended and unattended with identical `configuration_id`.

**OQ-265 answer.** Turn (and any soft/hard ceiling) exhaustion under `attendance = interactive` defaults to `escalate`: the run reaches its decision point, ends every open effect, and the CLI offers a ledgered `amend(budget)` or `stop` (ADR-0071 decision 4's attended path; mini-swe-agent L80–100, goose "continue?"). Under `async` it is `defer` (suspend + wakeup on `amend`); under `unattended` and for every Lab-launched run it is `stop` with `stop_reason = budget_exhausted` (ADR-0040 hard-ceiling rule; a Lab arm's budget is its `eval_budget` and may never be loosened — T-LCD-14). The default is a `HarnessRule` leaf (MUST-data) so the Lab can vary it.

### 6.4 I/O contracts

**Streams.** stdout carries the command's *result* only; stderr carries progress, warnings, deprecations and prompts (S-535, S-537). In `attended terminal` mode the TUI owns the terminal and both rules still hold for anything a script could capture. Colour and decoration are off when stdout is not a TTY, when `NO_COLOR` is set, when `TERM=dumb`, or on request; they never appear in `json`/`jsonl` output.

**Output formats** (`OutputFormat ∈ {human, json, jsonl}`; default `human` on a TTY, `jsonl` for streaming commands and `json` for single-record commands when stdout is not a TTY — the clig TTY heuristic):
- `human` — rendered projections; tables render `n/a{reason}` as a distinct glyph/word, never blank or `0` (T-LCD-15); Terraform-class diff lines for `definition plan/diff`.
- `json` — exactly one record: the operation's typed result (`AssemblyResult`, `RegistryEnvelope`, `Page{…}`, `ExperimentReport`, `LeaderboardSnapshot`, run summary) in the canonical encoding (ADR-0029/0036 `idp/1` JCS-class form), so a script can hash what it received.
- `jsonl` — for streaming commands (`run start/resume/tail/events`, `experiment open/status --follow`, `results subscribe`): a sequence of **canonical ledger event envelopes** exactly as `project(run, cli_stream_view, until_seq)` yields them — `cli_stream_view` is the identity projection over the run's durable events filtered by `SinkPolicy{content_classes}` (default L0 accounting + L1 structural + L2 content by address; L3 diagnostic never), each line carrying `seq`, `event_id`, `parent_event_id`, `causes[]`, `participant_class`, `observability_level`, provenance — followed by exactly one terminal **`result` record** `{run_id, configuration_version_id, stop_reason, outcome_class, resource_account (totals as views, ADR-0039), last_message_ref?, bundle_ref?, exit_class}`. Invariant **O-1 (lossless):** the JSONL stream is a `LedgerExport` prefix; `run events` over the same cursor range is byte-identical (T-LCD-11 with zero loss). A `compact` stream (codex/gemini-class item vocabulary: message, tool, effect, approval, cost) is an optional **declared-lossy** projection shipped with a `LoweringLossReport` and never the default for machines. Ephemeral classes (`model.stream.delta`, `security.permission.requested{rendering}`) appear on stderr/TUI only, never in `jsonl`, so the stream stays replayable.
- Structured final output: a `--schema`-class option (codex `--output-schema`, Claude `--json-schema`) is not a CLI feature; it is a `Validator{kind: output_check}` in the sealed definition (ADR-0047) whose result is in the ledger — the CLI only renders `last_message_ref`.

**Input.** Positional prompt text typed at a TTY by the human principal enters as `Text{authority = principal, origin = human}`; the `-` sentinel forces stdin as the prompt (codex `Forced`); piped stdin alongside a positional prompt is appended as a separate `ContextItem` (codex `OptionalAppend`) — but **typed `Text{authority = external, origin = import}`** with provenance naming the pipe (F7; ADR-0033 minting rules). Files attached by path enter by content address as `external`. Overrides (`path=v`, `class_id=variant_id`, `~path`, choice sweeps) use ADR-0025's grammar unchanged and desugar through WS-J1 D2 into one content-addressed `experiment`-provenance layer (OQ-076: **yes, always**, including single ad-hoc runs; `LayerProvenance.source_kind = experiment`, `id` = hash of the canonical override list). Invariant **I-1 (no widening from a pipe):** an override whose `HirDiff.classification.authority_delta = widening` or `budget_delta = loosening` relative to the base definition is accepted only when the invocation's principal is a human at a TTY (`declared`/`tty_inferred` interactive) or carries an attestation — from an unattended script it is refused with `AuthorityWideningRequiresHuman` (ADR-0017, ADR-0037 S-rule; the J1 S-6 rule applied at invocation time).

**Idempotency.** Every work-injecting command (`run start/submit/steer/resume/fork/amend`, `approval respond`, `experiment open/pause/resume/close`, `registry register/publish`, `definition apply`) carries `idempotency_key = H(idp ∥ "cli" ∥ canonical(invocation record))` unless the caller supplies one; a repeated invocation returns the recorded result and exit class (ADR-0130; S-200). The **invocation record** `{argv canonical, cwd_ref, principal, attendance declaration, output format, stdin digest?, instrument record}` is appended as `lifecycle.surface.invoked` (ephemeral by default; durable when it opens or amends a run — OQ-385) so that "which flags produced this run" is answerable from the ledger.

**Configuration precedence** (clig): explicit flags > environment > project-level configuration > user-level > packaged defaults — mapped one-to-one onto ADR-0024's layer precedence `packaged-default < organisation < user < project < experiment < session` (flags are the `session` layer; a CLI override list is the `experiment` layer per WS-J1 D2). `config explain <path>` is J1 `explain` (Kubernetes `managedFields` / Codex `requirement_source` shape).

### 6.5 Exit classes and invocation errors

Exit status is a **closed table derived from ledger sums**, never a CLI-private taxonomy (F5; one declaration per seam, ADR-0048/0145): `ExitClass ∈ {ok, invocation_error, refused_by_kernel, budget_exhausted, refused, cancelled, infrastructure_failure, oracle_failure, approval_denied_unattended, validation_error, tampered, veto_tripped}` with the mapping: `outcome_class = scored ∧ stop_reason = completed → ok`; `budget_exhausted → budget_exhausted`; `refused → refused`; `cancelled{by} → cancelled`; `infrastructure_failure → infrastructure_failure`; `oracle_failure → oracle_failure`; a run whose completion was blocked by an unattended `deny` (ADR-0071 decision 4 `stop_reason = approvals_exhausted` or WS-G2 blocked) → `approval_denied_unattended`; `AssemblyDiagnostic{severity: error}` / engine refusals (`UnbudgetedArm`…) → `validation_error`; `Tampered` → `tampered`; success-with-veto (ADR-0047) → `ok` with `veto_tripped` reported in `result` and a distinct code available on request. Numeric values are assigned in a band avoiding shell-reserved codes (OQ-384); the `result` record's `exit_class` is authoritative. `invocation_error` (mutually exclusive flags, `interactive` without a TTY, unknown format, missing budget) is emitted **before** any boundary verb runs, with a typed `InvocationError{code, path, remedy}` mirroring J1's `AssemblyDiagnostic` shape, and never touches the ledger.

### 6.6 Safety defaults (the "permission mode" question)

All safety behaviour is the lowering of three typed facts the CLI must set and record, none of which it may implement:

1. **`approval_mode`** (Harness Definition parameter, ADR-0069 decision 6; `manual | tiered | auto_review | pre_approved_only | unattended_deny | unattended_defer | bypass`). Defaults: `attended terminal` ⇒ `tiered` (Π floor rows with `ask` rendered to the principal; `manual` on request); `headless` ⇒ `unattended_deny` (codex `Never`, opencode auto-reject, Claude `dontAsk`) with `unattended_defer` when a notification sink is configured and `auto_review` only when a calibrated reviewer variant is named (codex's `AutoReview` rebuild); Lab-launched runs use the experiment's value and the CLI cannot override it (T-LCD-14 / ADR-0045 immutability). A CLI flag that names a precedent's mode (a `yolo`/`auto-edit`/`plan`-class spelling) is a **surface preset** that lowers to one `approval_mode` value plus Π narrowing leaves; the spec lists the lowering table so that `plan`-class read-only presets are `pre_approved_only` with an `fs_write/exec` deny leaf, and `auto-edit`-class presets are `tiered` with an `allow` lease pattern over `fs_write ∧ workspace_local` (Π-2 already allows most of it).
2. **`attendance`** (§6.3) with its recorded source. Invariant **S-1:** the CLI never re-derives attendance at an approval; the kernel reads the manifest.
3. **`bypass` gating.** The bypass preset is accepted only when the environment handle's `ContainmentPolicy.enforcement_evidence = enforced` (ADR-0136) is recorded in the run manifest; otherwise `BypassWithoutContainment` (invocation error). Bypass still excludes the never-auto set (ADR-0069 decision 3); the CLI's prompt for those requests cannot be suppressed. The flag is named to be typed deliberately (codex/opencode `dangerously-…` precedent) and is hidden from completion.

Further defaults: **unattended denials are decisions** — every Π-12 `deny` is `security.permission.decided{decider: policy, reason: unattended}` and counted in `denial_rate` (rejecting opencode's un-ledgered form, CF-355); **`ExhaustionPolicy`** per §6.3; **budgets are mandatory** — `run start` without a `Budget` from the definition, a preset or a flag is refused (`MissingBudget`), never defaulted to unlimited (mini-swe-agent's `-l 0` "disable" is rejected); **workspace trust is a claim** — the CLI records `workspace_trust ∈ {trusted, untrusted, unknown}` from the H5 trust store into the manifest; gemini's downgrade becomes a Π narrowing leaf keyed on it (OQ-387); **credentials never come from job-level environment** in unattended runs where the environment executes repository-controlled code — the CLI warns (S-537) and H3's broker binding is the only path (ADR-0058); **shadowing is surfaced** — when a preset makes a hook/reviewer/callback unreachable (Claude's `bypassPermissions` warning, S-109 L1838) the CLI emits a deprecation-class warning naming the shadowed component.

**Approval rendering** (F9, AC-H7-11): the prompt shows the kernel-derived `Explanation.risk_factors`, `effective_risk_class`, `what_would_auto_approve` hint, the exact command/args untruncated for `exec` and MCP-install subjects (SEP-1024, S-307), and the model's `model_justification` visibly labelled as `delegate`-authority text and collapsible; options are rendered with their `kind` and a lease's `pattern`/`scope` when offered; a default of `deny` on a timeout; "severe" requests (`irreversible ∧ external`) require a non-trivial confirmation (clig confirmation tiers).

### 6.7 Data-model sketch

`AttendanceDeclaration{value, source}` · `InvocationRecord{argv_canonical, cwd_ref, principal, attendance, output_format, stdin_digest?, overrides_layer_id?, instrument_record, idempotency_key}` (event `lifecycle.surface.invoked`) · `OutputFormat` · `cli_stream_view` (a `SinkPolicy`-filtered identity projection) and the `compact` projection with its `LoweringLossReport` · `ResultRecord{run_id, configuration_version_id, stop_reason, outcome_class, resource_account, last_message_ref?, bundle_ref?, exit_class, veto_tripped[]}` · `ExitClass` (closed; derived) · `InvocationError{code, path?, remedy}` · `SurfacePreset{name, approval_mode, narrowing_leaves[], requires_containment: bool}` (MUST-data; the lowering table) · manifest fields consumed: `attendance`, `attendance_source`, `approval_mode`, `unattended_policy`, `workspace_trust`, `containment.enforcement_evidence`, `overrides_layer_id`.

### 6.8 Acceptance-criteria sketch (each names its T-LCD test)

- **AC-K1-01 (T-LCD-12).** Every command is executable against a service in a separate process; the CLI process links no kernel code (build check: the surface package depends only on the generated client).
- **AC-K1-02 (T-LCD-12, K-1).** For each command, a fixture invokes it and the equivalent boundary verb sequence; the resulting ledger ranges are byte-identical after removing `lifecycle.surface.invoked`.
- **AC-K1-03 (T-LCD-11, O-1).** `run start --jsonl` output minus the final `result` line equals `run events --from 0` for the same run, byte for byte; the `compact` view ships a loss report enumerating dropped classes.
- **AC-K1-04 (T-LCD-15).** Every table/JSON rendering of a metric cell distinguishes `n/a{reason}` from `0`; a golden-file test over the J4/J5 fixtures.
- **AC-K1-05 (T-LCD-10, M-2).** The same sealed definition started attended and unattended yields one `configuration_id`; the only ledger differences are `attendance` and `decider: policy` rows.
- **AC-K1-06 (ADR-0069).** With no TTY and no declaration, `attendance = unattended`, `attendance_source = tty_inferred`; every `ask` becomes a `decided{decider: policy, reason: unattended}` event; no invocation blocks on stdin.
- **AC-K1-07 (ADR-0069 decision 3).** The bypass preset without `enforcement_evidence = enforced` is refused before any run opens; with it, a never-auto request still prompts (attended) or denies (unattended).
- **AC-K1-08 (I-1, ADR-0017).** A widening override from a piped, unattended invocation is refused with `AuthorityWideningRequiresHuman`; the same override at a TTY produces a layer with `provenance.origin = human`.
- **AC-K1-09 (OQ-076).** Two invocations with the same override list on different days produce one `overrides_layer_id`; a sweep point with the same overrides shares it.
- **AC-K1-10 (§6.5).** The exit-class table is total over `outcome_class × StopReason`; a property test enumerates the sums; a `validation_error` never opens a run.
- **AC-K1-11 (ADR-0130).** Re-running a work-injecting command with the same idempotency key returns the recorded result; the ledger shows one run.
- **AC-K1-12 (AC-H7-11, S-307).** The approval prompt renders `Explanation` fields and the untruncated command; `model_justification` is visibly `delegate`-labelled; the fixture is a golden render per subject kind.
- **AC-K1-13 (T-LCD-06).** Building without the hosting tier removes the `participant` noun and changes no other command's help, schema or fixtures.
- **AC-K1-14 (OQ-265).** Turn exhaustion attended ⇒ escalation with a ledgered `amend` or `stop`; unattended/Lab ⇒ `stop{budget_exhausted}`; no run ever exceeds its `eval_budget`.

### 6.9 Build-stage suggestion

- **C0 / Stage 0 (driver slice, needed by `l1-spike-spec.md` and T-LCD-03):** `run start` (headless only), `run events`, `run status`, `definition validate`, `version`, `doctor`; output `human` + `jsonl`; attendance `unattended` only; `approval_mode = unattended_deny`; `MissingBudget` refusal; exit classes `ok | invocation_error | validation_error | infrastructure_failure | budget_exhausted`.
- **C0 / Stage 1:** attended terminal mode with per-effect approvals (H7 G0), `approval list/show/respond`, `run resume/fork/cancel/amend`, `run inspect <view>`, the full exit-class table, `InvocationRecord`, idempotency keys, stdin typing (I-1).
