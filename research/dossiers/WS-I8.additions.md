## Ontology terms

| term | definition | notes |
|---|---|---|
| training-stack interface | The set of lowerings/liftings by which HarnessHarness exchanges records with an external trainer: `training_export/1` (exports), `SnapshotClaim` (import), harness regression suite, compatibility tags; two modes `export` / `attached`. HarnessHarness never trains, loads, merges or serves weights. | ADR-0202; not a component class, plugin or hosted participant |
| training export / training sample / reward record | `TrainingExport` = content-addressed lowering of subject bundles into `TrainingSample`s (one per `model.call.*` pair: plan hash, response, usage, labels, rewards, compliance, task/split/stratum) with a `LoweringLossReport`; `RewardRecord{value, oracle_class, validator_ref, verdict_ref, veto_tripped, charged_to, provenance}` from admissible oracle classes only. | export = `project(run, training_export)`; never held-out material; never tokens/masks/logprobs HarnessHarness did not observe |
| snapshot claim / training lineage / trained-under | `SnapshotClaim` = a trainer's reported identity for a produced model (`snapshot_id`, `base_snapshot_ref`, `training_lineage{run, step, data_refs, method, compute_claim}`, `trained_under[]{definition, profile, bundle}`, foreign `weights_digest`); lifts to a `ModelSnapshotRecord{pinned = false}`. | pins only after probes; ADR-0120 extension |
| compatibility record | `CompatibilityRecord{snapshot_ref, definition semantic_id, profile semantic_id, status ∈ {trained_under, verified, drifted{rules[]}, broken{report_ref}, unknown}, evidence_ref?, expiry_condition}` — per (snapshot, definition, profile) verification state; annotated, never rewritten. | ADR-0203; read by the guard at bind |
| harness regression suite | A pre-registered paired `ExperimentSpec` with `model_snapshot` as the varied factor (`snapshot_in` vs unbound `snapshot_out`), over headline + veto + retention + per-conditioned-rule compliance metrics under one `MatchSpec`; its verdict updates the compatibility record. | "post-training includes harness regression suites" |
| snapshot scope | `AssumptionDebtRecord.snapshot_scope[]: ModelSnapshotRef \| family(selector)` — the snapshots a conditioned rule's evidence covers; an expiry scope (`model_version_change` outside it), never a refusal; widened to `family` by a sign-stable `transfer` report. | additive field; WS-I6 owns |
| co-evolution cycle / cycle policy / plasticity rate | `CoEvolutionCycleRecord` = sidecar lineage of alternating `harness_search` (one WS-I5 pipeline invocation) and `weight_update` (external) phases with budgets and verdicts; `CyclePolicy{weight_phase_budget, harness_phase_budget, switch_rule ∈ {fixed{E, I}, patience{…}}, max_cycles, retention_set_ref}`; the two *plasticity rates* are the per-phase budgets. | no new `run_kind`/registry/design kind; WHALE `alternate.sh` typed |
| weight consolidation (vs memory consolidation) | Moving an explicit lesson's effect into weights by the trainer; proven in HarnessHarness only by the lesson's retirement experiment passing on the post-training snapshot under retention and held-out-family conditions; the lesson becomes `retired{reason: consolidated}` and stays retrievable. Distinct from ADR-0080 memory consolidation (versions within the memory store). | CF-439 |
| consolidation candidate / consolidation report | A lesson satisfying C1–C5 (active ≥ k cycles with failing removal test; sign-stable transfer; behavioural rung; economics or under-following; no veto dependence) and none of N1–N5; `ConsolidationReport{verdict ∈ {consolidated, partially_consolidated, not_consolidated}, target/retention/family reports, compliance_delta}`. | ADR-0204 |
| policy drift / snapshot span | `snapshot_span{first, last, drift}` per run derived from `model.call.completed.snapshot_id`; `drift > 0` ⇒ `policy_drift` annotation; excluded from `artifact_benefit`. | verifiers `PolicySpan`, ART policy versions |
| null trainer | A conformance fixture implementing the training-stack interface that returns the same weights under a new `snapshot_id` (and, attached, a synthetic policy counter); makes every I8 acceptance criterion executable without training. | AC-I8-1…12 |
| maturity flag | `maturity ∈ {research_grade, experimental, supported}` on a spec item and its operations; the co-evolution/consolidation layer is `research_grade`: specified, conditional, excluded from C0–C3 acceptance, no leaderboard entry without independent reproduction. | ADR-0002 (e) |
