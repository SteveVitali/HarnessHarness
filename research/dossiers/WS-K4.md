## 1. Scope & boundary

This workstream designs **how a host application embeds the HarnessHarness runtime**: the public contract through which a host (a CLI, a web dev-tool, an IDE, a test runner, a laboratory process, a script) creates and drives runs, subscribes to what happens, injects what it owns (context, tools, procedures, an environment, an approval channel), and takes the run's outputs and account — and the **stability and versioning policy** that lets that contract evolve without breaking hosts. It fixes: (a) the **embedding contract** `hh-embed/1` — operations, inputs/outputs, invariants and a closed error model — as the *single* kernel-facing public surface; (b) the **event-subscription model** (durable vs ephemeral frames, cursors, resumption, backpressure); (c) the **injection points** and the authority each one is allowed to carry; (d) the **transport bindings** (in-process, subprocess over stdio, local network) and the invariant that they are one contract, not three; (e) the **stability policy** (schema single-source, generated bindings, contract majors, capability negotiation, experimental gating, additive evolution, deprecation with expiry); (f) the rule that **every surface is a client** — CLI (WS-K1), web tooling (WS-K2), the MCP server (WS-K3), the Lab (WS-J1/J3), the ACP artefact (WS-E4/J6) and third-party SDK bindings all sit on this contract — and, with it, the answer to **OQ-130** (whether every planned surface is servable by a generated client over the kernel's local transport).

It **does not re-decide** (neighbours named): the ecosystem split itself and the layer bindings (ADR-0050 D1 — this dossier discharges D3, the boundary contract owned by WS-K4 with WS-L5); the Hosting ABI and its adapters (WS-J6 — a *different binding* with the same verb shape, CF-023/CF-209; nothing here changes a hosted participant's contract); the ACP artefact and lowering table (ADR-0098; WS-E4 — this dossier only says the ACP transport is a client of the embedding contract); plugin packaging, trust and the variant-host boundary for third-party component variants (WS-L5/H5 — this dossier consumes ADR-0023 D5's variant-host discipline for host-executed tools and flags the shared verbs in §8); the environment handle, its lifecycle and R-NOSIDE (ADR-0136…0138 — hosts receive `connection_info`, never a handle); the reference monitor, approvals and pre-authorization (ADR-0051…0053, WS-H7 — hosts are an approval *channel*, never a decider); the ledger, cursors and durability (ADR-0026/0027/0130); identity and supersession (ADR-0036/0037 — the API-stability policy is an application of them); the scorecard boundary (ADR-0045 §9 — measurement verbs cross this contract unchanged); the CLI command grammar (WS-K1), the web tooling design (WS-K2) and the MCP server's tool catalogue (WS-K3).

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Every audited embedding surface converges on the same shape: one option record, one session/thread handle, one bidirectional channel, and upcalls for the things the host owns.** OpenHands: `Conversation(agent, workspace, …)` → `send_message/run/pause/interrupt/close` plus `callbacks` and `client_tools`, with the *same* option record yielding `LocalConversation` or `RemoteConversation` by workspace type (S-110 `conversation.py` L33–160). Claude SDK: `ClaudeSDKClient(options, transport?)` → `connect/query/receive/interrupt/set_*` with host-owned `hooks`, `can_use_tool` and in-process MCP servers reached by `control_request` upcalls (S-109). Codex: `initialize` → `thread/start|resume` → `turn/start|steer|interrupt` with `permissions/requestApproval` upcalls and item notifications (S-107); the TypeScript SDK wraps this as `Codex.startThread/resumeThread` + `Thread.run/runStreamed`. Pi: `AgentHarness.create({session, models, tools, …})` → `lane(name)` → `prompt/steer/followUp/abort/resume/watch` with `hooks.on` and `events.on` (S-113). Cloudflare: `Agent` subclass with `onStart/onRequest/onConnect/onMessage` and harness hooks `beforeTurn/beforeStep/beforeToolCall/afterToolCall`, driven by `AgentClient` (S-557). The verb *intersection* is exactly WS-L1 §6.5's set — `hello` (initialize), `open_session` (start/resume), `submit` (prompt/turn start/send_message), `stream_events` (subscribe/watch/receive), `request_permission` (can_use_tool/requestApproval/confirmation), `cancel` (interrupt/abort), `account` (usage/token counts), `close` — plus `steer` (Codex `turn/steer`, Pi `steer/followUp`, OpenHands `send_message` mid-run), `fork` (OpenHands `fork`, Codex `thread/fork`, Pi `ForkOptions`) and `navigate/rewind` (OpenHands `navigate_to`, Claude `rewind_files`, Pi `navigateTree`). **Implication:** the internal boundary contract can keep its "full verb set" (phase-2 §6.7; CF-208) because every audited *native* runtime implements it; what the Hosting ABI must treat as capability-declared (steer/fork/account) is baseline here, since the kernel implements them over its own ledger (ADR-0027 `fork`, ADR-0026 `navigate`, ADR-0039 `account`). The residual verb — `steer` — needs the control strategy's cooperation (§6.1, CF-371).

**F2 — Host-owned capabilities are upcalls into the host, and every audited runtime executes them without a lifecycle the runtime controls.** OpenHands client tools: "the SDK returns an acknowledgment observation immediately" and the client executes (S-110 `client_tool.py`); Claude SDK: `mcp_message`/`hook_callback`/`can_use_tool` control requests block the CLI until the host answers (`_has_bidirectional_needs`, S-109 `_internal/query.py` L819–860); Pi `before_tool` may rewrite `args` or `block` (S-113 `hooks.ts`); Cloudflare `beforeToolCall` may `block | modify | substitute` but "Approved action input cannot be changed by beforeToolCall" (S-557 `think.ts` L596). Two consequences for HarnessHarness follow from ratified ADRs rather than from the precedents: (i) a host-executed capability is an **out-of-process component variant** of the tool-executor class bound through the variant-host boundary (ADR-0023 D5; WS-E1 `execution_requirement.environment_class`) — so its calls carry an `effect_id`, pass `authorize` (ADR-0052) and go through the ADR-0030 lifecycle with the host reporting `observed{outcome}`; the OpenHands "acknowledge immediately" shape is inadmissible because it leaves no terminal event (ADR-0030 "every commit resolves"); (ii) a host hook is a **raise-only input** (ADR-0053; CF-121): it may raise risk, `deny`, annotate or observe, never `allow` and never rewrite the arguments of an authorized proposal — argument rewriting is a *new proposal* with a new `effect_id`, which is exactly the Cloudflare rule "approved input cannot be changed" made structural (§6.3).

**F3 — Resumable subscription needs three things the audited systems each supply one or two of: a per-frame `seq`, a durable/ephemeral distinction on the frame, and an attempt number on streamed items.** OpenHands' session protocol supplies all three (`DurableFrame{seq, event}`, `TransientFrame`, `ItemStartedFrame{item_id, attempt, anchor_seq}`, `DeltaFrame{order}`, `ItemAbortedFrame`; "if a frame has [seq], it is real and resumable"; "Every `ItemStarted` is retired by exactly one `Durable` or `ItemAborted`") but exposes no version handshake ("The URL is the protocol version"); its older `/events/{id}` socket resumes by *timestamp* (`resend_mode=since&after_timestamp`), which is not a cursor and is deprecated in favour of `after_seq`. ACP resumes by inclusive `replayFrom` (ADR-0027). Codex offers per-connection `opt_out_notification_methods` so a host can refuse token-rate deltas (S-107 `v1.rs` L58–61) and drops event fan-out under saturation while "server requests are never silently abandoned" (S-107 `in_process.rs`). Cursor rewinds client streams on retried steps (S-052). **Implication (§6.2):** the contract's stream is a sequence of *frames*, each either `durable{seq, event}` (the ledger event in canonical form — I4) or `ephemeral{…}` (deltas, progress, permission renderings — never carrying `seq`), with `item_started{attempt}` / `item_aborted` brackets so a retried model attempt (ADR-0130 R-2 "surfaces rewind") does not read as new text; resumption is `stream_events(session, from_seq)` inclusive; backpressure may drop ephemeral frames only and must disconnect (never block the writer) when a durable frame cannot be delivered — the ADR-0026 durable-before-visible rule seen from the client side.

**F4 — Version negotiation and experimental gating are the mechanisms that let a production contract grow without an escape hatch, and the audited systems that lack them pay in explicit alpha disclaimers.** Codex gates every experimental method *and field* with a compile-time marker, refuses them with a typed message unless the connection declared `experimental_api` at `initialize`, filters them out of the exported bindings by default, and keeps `v1`/`v2` namespaces with a `JSON_V1_ALLOWLIST` (S-107 `experimental_api.rs`, `export.rs`, `message_processor.rs`); ACP negotiates one integer major and treats capabilities as additive (S-035); Pi's protocol has a version handshake and strict envelopes but "no compatibility guarantees" (S-113 `protocol/README.md`); OpenHands' TypeScript client ships "ALPHA … Breaking changes may occur in any release" while pinning the exact server image and failing CI on generated-schema drift (S-110 `clients/typescript`); Claude's `Transport` is exposed with a warning that it "may change or [be] remove[d] … in any future release" while the CLI is pinned by exact bundled version and probed for a minimum (S-109); Cloudflare marks its whole composition surface "Experimental … may change between releases while the composition surface stabilizes" (S-557 `lifecycle.md`). AIP-180 gives the rule set every mature API converges on: additions within a major are compatible, removals/renames/type changes/default changes/semantic changes are not (S-559). **Implication (§6.5):** stability is a *declared tier per method and per field* — `stable | experimental | internal` — with experimental items reachable only behind an opt-in capability, refused with a typed error otherwise, excluded from default bindings, and carrying an assumption-debt record whose removal test is their promotion or deletion (T-LCD-05 reflexive); a contract major bumps only on a change AIP-180 classes as breaking; a minor never removes.

**F5 — In-process embedding is admissible only as a binding of the same contract, and the one production system that does it says so in its own words.** Codex runs the same `MessageProcessor` over bounded in-memory channels for the TUI/exec surfaces: "preserve app-server semantics while avoiding a process boundary"; "responses still come back through the same JSON-RPC result envelope … rather than creating a second execution contract"; "the in-process hot path is typed" (S-107 `in_process.rs`, `app-server-client/README.md`). Pi separates the process-local `AgentHarness` (typed lanes and hooks) from the routed protocol whose payloads are opaque to the server (S-113), i.e. the in-process API is *richer* than the wire — the counter-shape that produces two contracts. OpenHands keeps one abstract `BaseConversation` with two implementations, which is the "one contract" shape but pays for it with a `RemoteEventsList.reconcile` that re-syncs because remote and local semantics drifted (S-110 `remote_conversation.py` L289–500). **Implication (§6.4):** the in-process binding exists for first-party surfaces in the kernel ecosystem (the CLI per ADR-0050 D1) and must produce the same envelopes, the same error sum and the same event frames as the stdio binding; a conformance suite runs unchanged over every binding (AC-K4-2). The SDK is never an in-process binding — it is the generated client (ADR-0050 D1 surfaces row).

**F6 — Drain, admission and lease semantics belong to the contract, not to a binding.** Codex admits work through a per-connection RPC gate and a `TurnAdmission` that returns `ServerDrainingError` once shutdown begins while letting admitted requests finish (S-107); Pi's server releases a presentation's attachment "only after admitted service calls settle" and rejects new attachments with `ServerDrainingError` (S-113 `session-router.ts`); OpenHands' agent-server holds a generation-fenced owner lease with liveness fields "absent in lease files written by older versions … consumers must treat them as optional" (S-110 `conversation_lease.py`); Pi's Session has a single mutation line (`beginMutation/mutate`, S-113 `session/types.ts`). Under HarnessHarness the writer lease and fencing are ledger facts (ADR-0026/0130), so the embedding contract must *expose* their consequences — `WouldBlock(active_holder)` on a concurrent `open_session(resume)` (ADR-0130 consequence naming WS-K4), `Draining` on submit after shutdown begins, `Fenced` never reaching a client (it is internal) — rather than invent its own.

**F7 — The environment is provisioned *by reference*, and no audited system that separates harness and environment hands the client a handle.** OpenHands passes a `workspace` (local path or `RemoteWorkspace{host}`) and the conversation binds to it; Codex `thread/start{cwd, runtime_workspace_roots, environments}` returns the realized `cwd`/sandbox and lets clients reference exec-server environments by id (`environment/add` is experimental); Pi's `ExecutionEnv extends FileSystem, Shell` is an in-process object the harness *uses* but the protocol never carries; Cloudflare's harness runs *inside* the runtime's Durable Object. ADR-0136…0138 already fix the HarnessHarness shape: hosts supply an `EnvironmentRecord` reference (or a provider adapter's `connection_info`), the kernel provisions and holds the `EnvHandle`, and surfaces "get `connection_info` for human hand-off and never a handle reference" (ADR-0138 consequences; R-NOSIDE). The embedding contract therefore has **no environment operations** beyond naming the record at `open_session` and reading `connection_info/health/meters` — the same rule WS-J6 applies to hosted participants.

**F8 — The Lab's crossing (ADR-0050 lab row) and a host's crossing are the same contract at different granularity.** ADR-0045 §9 fixes that scorers/judges/loaders cross *per run* with `(end-state handle + ledger cursor + artifact refs) → MetricValue[]` appended as `measurement.metric.emitted`; ADR-0050 D2 lists what crosses the kernel↔lab and kernel↔surfaces boundaries (verbs, canonical events, HIR documents, metric/comparison/match records, budget/cost records, `project()` results) and what never does (`RuntimePlan` execution, permission decisions, raw credentials, unhashed blobs). Nothing in the audit contradicts this list; the audited SDKs cross *less* (no definitions, no metric records) and the Lab-side eval tools cross exactly it (ADR-0050 (b): Inspect/Harbor bridge per run). **Implication:** the embedding contract carries the ADR-0050 D2 set and nothing else; the Lab is an ordinary client with the measurement verbs enabled (§6.1 group M), so the Stage-3 lab crossing exercises the same contract the Stage-≥5 surfaces will bind to, and the S2 boundary spike (`l1-spike-spec.md`) is the first acceptance run of this contract.

## 5. Disconfirming evidence & negative results

**Against "one contract for every surface" (the intersection trap in reverse).** WS-L7's AWT/WORA argument (S-154) says a single boundary spanning heterogeneous consumers decays to the intersection of their needs; Pi's split (rich in-process harness, opaque wire protocol) and Cloudflare's (harness inside the runtime, client SDK outside) show designers *choosing* two surfaces. *Why this does not overturn:* the surfaces here are not heterogeneous *runtimes* but heterogeneous *clients of one runtime*; the contract carries the ADR-0050 D2 record set (HIR documents, ledger events, metric records) which is already richer than any audited SDK, and richness that a client does not need is declined by capability (notification opt-out, tri-state features), never removed. The residual risk — a first-party surface growing a private verb — is closed by AC-K4-2 (the CLI's in-process binding must pass the same conformance suite) and by the rule that a new verb enters as `experimental` with a debt record.

**Against the in-process binding at all.** ADR-0050 D2 says "nothing else crosses" a boundary and §8 forbids naming ecosystems in contracts; an in-process binding is only available to a host in the kernel ecosystem, which could look like a privileged path the SDK cannot take, and Codex's own facade needed "a short bootstrap phase where they reconcile startup response data with later events" (S-107 `app-server-client/README.md`). *Why this does not overturn:* the binding is admitted for first-party surfaces only, produces identical envelopes, and is validated by the same suite; the SDK's inability to use it is not a capability gap but a locality choice (ADR-0023 D5: locality is a property of the binding, never of the contract). If the conformance suite ever diverges between bindings, AC-K4-2 fails the build.

**Against strict unknown-field rejection (I2).** OpenHands' session envelope is "deliberately not `extra="forbid"`: the envelope is meant to grow, and clients must ignore what they do not recognize"; ACP and MCP mandate preserving unknowns; AIP-180's additive rule presumes tolerant readers. Strictness makes every additive change a two-sided upgrade. *Why this does not overturn:* CF-209 already ruled that the ecosystem boundary rejects unknowns because its payloads are canonical ledger events whose hashes must agree on both sides (I4), while protocol edges preserve them; the contract keeps growth cheap by (i) versioning the *schema hash* on `hello` so a client learns before it sends, (ii) generating bindings from one source so both sides move together (I1), and (iii) allowing additive growth only in *optional* fields whose absence has the pre-existing default (AIP-180), so an *older* client's messages remain valid to a newer kernel; the asymmetric case (newer client, older kernel) is refused at `hello` with `SchemaMismatch`, which is what exact pinning (I3) makes rare.

**Against host hooks as raise-only.** Every audited host lets a hook do more: Pi rewrites `args`, Cloudflare substitutes results, Claude's `PermissionResultAllow.updated_permissions` persists rules, OpenHands' `confirmation_policy` auto-approves. A raise-only rule may make the SDK feel crippled next to them. *Why this does not overturn:* ADR-0035 rule 1 (a `delegate` origin never endorses) and ADR-0053 (hooks admitted as raise-only inputs; CF-121) are ratified and constitutional; the *operating points* hosts want are reachable without model-origin or hook-origin conferral — a host that wants "auto-approve class X" seals a `policy_rule` pre-authorization into the definition it opens (ADR-0053 §6.6), and a host that wants to transform arguments submits a new proposal. What is lost is only the *silent* form of those powers, which is exactly the M-CPE/X-CPE channel (WS-H1 F1).

**Against carrying HIR documents and `compose → resolve → seal` across the boundary.** No audited SDK ships a definition across its boundary; Claude's SDK ships options and lowers them to flags. Carrying whole documents costs serialization and makes the client depend on the HIR dialect. *Why this does not overturn:* ADR-0023 answered Q-L1-09 — a definition is a data document any conformant runtime loads — and ADR-0050 D2 (iii) already requires the lab to compose by calling the kernel's assembler "never by re-implementing" it; a host that wants the Claude-SDK shape passes a *reference* to a sealed definition and a small `Override` set (ADR-0025 Hydra-class grammar) and never sees the document. Both forms are one verb (`open_session{definition: Ref | document, overrides?}`).

**Against tri-state capabilities on an internal contract.** The kernel is one implementation; "unknown" capabilities are a hosting concept (T-LCD-07). *Why this does not overturn:* the *client* side is many implementations (CLI, web, SDK bindings in the late-bound surface ecosystem, the Lab, third-party hosts), and it is the client's declared capabilities (`experimental`, notification opt-outs, which upcalls it can serve — permission channel, host executor, hook observer) that the kernel must not assume; a host that declares no permission channel gets `unattended` mode (ADR-0052) rather than a hung `ask`. The kernel's own capabilities are `stable | experimental` per method, never `unknown`.

**Negative results from the audit.** (i) No audited SDK exposes a *content-addressed* identity for the configuration it starts a run with (Claude options are flags; Codex `thread/start` returns realized values but no hash; OpenHands persists `base_state.json` without an id) — the run-manifest/`configuration_version_id` obligations (ADR-0036) have no SDK precedent. (ii) No audited SDK carries provenance labels on host-supplied context or tools — every host injection arrives unlabelled and is trusted by placement (the failure ADR-0034 closes). (iii) No audited SDK declares per-item stability tiers in its *schema*; Codex marks experimental items in code and filters exports, which is the closest precedent. (iv) S-055 remains unreadable (CF-024); the App Server design is evidenced by source only.

## 6. Recommendation for the spec

### 6.1 The embedding contract `hh-embed/1` — operations (Spec §7 SDK; §4 plane split)

**Position.** The embedding contract *is* the WS-L1 §6.5 ecosystem-boundary contract adopted by ADR-0050 D3, completed into a public surface. It is the **only** way anything outside the kernel drives a run: the CLI (WS-K1, in-process binding), web dev-tooling and desktop/IDE surfaces (WS-K2, generated client over the local transport), third-party SDK bindings (generated client), the Lab (WS-J1/J3/J5, subprocess binding with the measurement group enabled), the MCP server (WS-K3, a kernel-side server whose Lab operations call this contract), and the ACP artefact (ADR-0098 `render_session` is a client that lowers this contract's frames). It is *not* the Hosting ABI (WS-J6) and not the ACP edge: those share its verb shape (CF-023) but carry lowered events, preserve unknowns and stop at `configuration` granularity; this contract carries canonical ledger events, rejects unknowns and reaches `ledger` observability — it is what makes a native run *native*.

Operations are grouped; every operation returns a typed sum (never throws, never free text) and every work-injecting operation carries an `idempotency_key` (ADR-0050 D3 amendment; ADR-0130).

**Group H — handshake and host identity.**
- `hello(contract_major: int, client: {name, version, kind ∈ {cli, web, ide, sdk, lab, mcp_server, acp_bridge, test}}, capabilities: HostCapabilities, schema_hash: ContentAddress) → Hello{kernel: {version, schema_hash, contract_major, idp}, negotiated: HostCapabilities, stability: map<method, tier>, experimental_enabled: bool} | ContractMajorUnsupported{requested, supported[]} | SchemaMismatch{client, kernel, direction ∈ {client_newer, kernel_newer}} | KernelBelowFloor{version, floor}` — the first message on every connection; every other operation before it is `NotInitialized`. `HostCapabilities{experimental: bool, opt_out_notifications: [class], serves_permission_channel: bool, serves_host_executor: bool, serves_hook_observer: bool, serves_elicitation: bool, accepts_ephemeral_frames: bool, max_in_flight_sessions?: int, extensions: map<prefixed_id, TypedValue>}` — absent means `false`, never `unknown` (the kernel is one implementation; the host declares). Invariant H-1: the negotiated set is `client ∩ kernel` per field; H-2: `experimental = true` is the *only* way an `experimental`-tier method or field becomes callable on this connection (ADR-0053-style "no implicit allow" for API surface).

**Group S — session lifecycle** (session = one client attachment to one run; a run may have several attachments — Pi multi-presentation — but exactly one *writer* per ADR-0026).
- `open_session(spec: OpenSpec, idempotency_key) → Session{session_id, run_id, attachment_id, manifest_ref, configuration_ids{configuration_id, configuration_version_id}, realized: RealizedSettings, cursor: {seq}} | InvalidDefinition[] | UnresolvedRef | AuthorityViolation | InsufficientBudget | EnvironmentUnavailable{reason} | WouldBlock(active_holder) | DefinitionChanged{reasons[]} | Draining`. `OpenSpec = new{definition: Ref<SealedDefinition> | HirDocument, overrides?: [Override], profile_binding?, environment: EnvironmentRef | connection_info(provider_adapter), budget: Ref<Budget> | BudgetNode, participant: ParticipantDescriptor (class = native for this contract), supplies?: Supplies, mode ∈ {attended, unattended}} | resume{run_id, mode ∈ {continue, takeover}, from_seq?} | attach{run_id, read_only: true}`. Semantics: `new` runs `compose → resolve → validate_assembly → seal` kernel-side (ADR-0025; ADR-0050 D2 iii), mints the root handle set (ADR-0051 H-3), provisions the environment (ADR-0136), opens the run (`open_run`, ADR-0026) and returns the manifest reference; `resume` is ADR-0130 `restore` (idempotent; a second concurrent resume returns `WouldBlock(active_holder)` — the Codex precedent ADR-0130 names for WS-K4); `attach` gives a read-only subscription (no writer lease; the ACP bridge and web viewers use it). `RealizedSettings` echoes what the kernel actually bound (model role table realized, `cwd`, containment `effective()`, Π mode) — the Codex `thread/start` response shape — so a host never infers settings from its request.
- `close(session_id, reason ∈ {done, abandon, host_shutdown}) → Closed{final: RunSummaryRef} | UnknownSession` — releases the attachment after admitted calls settle (Pi/Codex drain rule); the run itself ends only when its writer closes it (`lifecycle.run.finished`), an `attach`-mode close never ends a run.

**Group W — work** (each carries `idempotency_key`; duplicates return the recorded result — ADR-0130).
- `submit(session_id, input: [ContentBlock | ContextItem ref], idempotency_key) → Accepted{turn_id} | Refused{reason ∈ {budget_exhausted{dimension}, unattended_requires_input_class, definition_forbids, turn_active}} | Draining` — returns on *acceptance* (ACP `session/prompt` semantics); completion is the durable `lifecycle.turn.finished` frame. `turn_active` is returned when the control strategy declares `concurrent_input = queue_only`; hosts that want mid-turn input use `steer`.
- `steer(session_id, expected_turn_id, input, idempotency_key) → Accepted{queued_at ∈ {decision_point, next_turn}} | TurnMismatch{active_turn_id} | Unsupported{by: control_strategy}` — honoured per the control strategy's declared `steer_mode` (CF-371 asks WS-F1 to declare it; Codex `expected_turn_id` precedent).
- `cancel(session_id, scope ∈ {turn(turn_id), run}) → Acknowledged` — terminal `lifecycle.turn.finished{stop_reason: cancelled}` follows within the envelope's `cancel_deadline_ms` (WS-F2 INV-1); never rolls back completed effects (ADR-0030; Codex user-verification cancel note).
- `fork(session_id, at: EventRef | seq, manifest_delta?, idempotency_key) → Session` (ADR-0027 fork-by-reference) and `navigate(session_id, to: EventRef | null, idempotency_key) → Acknowledged` (ADR-0026 `head.moved`).
- `respond_permission(session_id, permission_id, outcome: selected{option_id} | cancelled, idempotency_key) → Recorded | UnknownPermission | AlreadyDecided | OptionNotOffered` — the host's answer to the `request_permission` upcall; recorded as an `approval` endorsement naming `(effect_id, args_canonical_hash)` (ADR-0035 basis 2; ADR-0052 output handling); `allow_pattern`-class options appear only once OQ-246 is answered (ADR-0098 D3).
- `respond_elicitation(session_id, elicitation_id, answer | cancelled, idempotency_key)` — the principal's answer to a `message_human` effect (ADR-0097 D3); content enters as `principal`-authored `ContextItem`.
- `report_host_effect(session_id, effect_id, attempt_no, outcome: observed{applied | not_applied | partial, output_artifacts[]} | failed{error_class} | unknown, idempotency_key) → Recorded | UnknownEffect | Fenced` — how a host-executed capability closes its effect (§6.3); `Fenced` here means the effect's attempt was superseded by a restore (ADR-0130 R-1), and the host must discard its outcome.

**Group R — read.**
- `stream_events(session_id, from_seq (inclusive), filter?: {classes[], min_observability}) → Stream<Frame>` — §6.2.
- `read(session_id, cursor, direction, limit) → Page{events, next}` (ADR-0026 `read`), `head(session_id)`, `lineage(session_id)`.
- `project(session_id, view_kind ∈ C0 set ∪ {checkpoint, handle_table, effect_ledger, audit_view, results_row, …}, until_seq?) → View{payload, derived_from, view_hash}` (ADR-0026 D2; the only way a host reads state — never a live object).
- `account(session_id, until_seq?) → ResourceAccount{consumed per dimension, reserved, remaining, cost{…, provenance, confidence}, charged_to breakdown}` (ADR-0039/0040/0043 views).
- `describe(session_id) → {manifest_ref, participant_descriptor, protocol_bindings[], realized, environment: {connection_info?, health, meters}}` — R-NOSIDE: no handle.
- `get_artifact(address) → bytes | Missing` (content-addressed only; ADR-0029 `get_blob`).

**Group M — measurement (Lab clients; `serves_measurement` capability).** `emit_metric(session_id, MetricValue[], oracle_ref, evidence_ref, idempotency_key)` (appends `measurement.metric.emitted`; ADR-0045 §9), `compose/resolve/validate_assembly/seal/space/enumerate` (ADR-0025 — kernel-side, invoked by the Lab, never re-implemented), `bundle/check_completeness/reproduce` (ADR-0038), `registry.*` read/publish operations (WS-E1 §6.3; ADR-0037). These are ordinary operations of the same contract behind a capability, not a second contract; the Lab's per-run crossing granularity (Q-L1-13) is a *usage* rule, enforced by budgeting the crossing (`charged_to = instrument`).

**Group U — upcalls (kernel → host), each gated by the host capability declared at `hello`.**
- `request_permission(session_id, permission_id, proposal_rendering, options[], deadline) → (answered via respond_permission)` — emitted iff `security.permission.requested{decider: human}` and the host `serves_permission_channel`; otherwise the run is `unattended` for that decision (ADR-0052 check 7: `ask ⇒ deny` unless pre-authorized). The kernel never auto-answers; a host may not auto-answer without a sealed pre-authorization (adapter-level auto-approval is inadmissible — ADR-0098 D3 applied to hosts).
- `invoke_host_capability(session_id, effect_id, attempt_no, idempotency_key, capability_ref, params_canonical, execution_request) → (answered via report_host_effect)` — the host as an out-of-process executor variant (§6.3); emitted only after `action.effect.committing` for non-read-only effects (ADR-0030 write-ahead).
- `notify_hook(session_id, hook_point, HookInvocation) → HookResult{raise?: {risk_level, reason} | deny{reason} | annotate{TypedValue} | none}` — raise-only (§6.3); timeouts default to `none` with `control.guard.fired{…, timed_out}`.
- `elicit(session_id, elicitation_id, question, schema) → (answered via respond_elicitation)`.

**Invariants (I1–I5 of WS-L1 §6.5 restated, plus the additions this dossier makes).** **I1** single source of truth for types: the kernel's schema export (HIR/1, ledger event schemas, `MetricDeclaration`, this contract's own message schemas) is the only hand-written type source; every binding is generated and CI-checked. **I2** unknown fields are rejected (`UnknownField{path}`), except inside registered `ext` slots and inside `HostCapabilities.extensions` (prefixed ids, preserved byte-for-byte, never deciding anything). **I3** the client pins the exact kernel version; `hello` refuses a kernel below the client's floor (`KernelBelowFloor`) instead of warning. **I4** every durable frame carries the ledger event in canonical form (`idp/1`), hash-equal on both sides (CF-058 wording); a client can `verify` the chain it received. **I5** the boundary never widens authority: no operation delivers a permission decision, a handle, a credential value or a policy into the kernel from the host except through the endorsement verbs (`respond_permission` as principal approval; `open_session.supplies` under `authority_cap`); the far side may only propose, request, observe and report. **I6** (new) every work-injecting operation is idempotent on its key across restarts (ADR-0130 R-4). **I7** (new) no operation returns a live kernel object — sessions, environments, handles and views are referenced by id/address only (R-NOSIDE generalized). **I8** (new) one contract, every binding: the operation set, error sum and frame kinds are identical over in-process, stdio and local-network bindings; a binding may only *add* transport-level facts (connection ids, auth). **I9** (new) observability is `ledger` for this contract's runs: a host on this contract is a *native* attachment, so no lowering loss report exists here (the loss reports live at the Hosting ABI/ACP edge).

### 6.2 Event-subscription model (Spec §7; consumes ADR-0026/0027/0130)

`Frame = sync{from_seq, through_seq, head_hash} | durable{seq, event: Event (canonical), hash} | ephemeral{kind ∈ {delta, progress, permission_rendering, guard_notice, log}, scope: {turn_id?, model_call_id?, tool_call_id?, effect_id?, item_id?}, attempt, order, payload} | item_started{item_id, attempt, anchor_seq} | item_aborted{item_id, attempt, reason} | lagged{dropped: {ephemeral: n}} | closed{reason}`.

Rules: (R-1) `durable` frames are exactly the ledger's durable events, in `seq` order, gap-free per session — a client that sees `seq = n` has seen every `< n`; `durable` frames are never dropped; if a client cannot keep up, the kernel emits `lagged` for dropped *ephemeral* frames and, if the durable backlog exceeds the connection's bound, disconnects the client with `closed{reason: slow_consumer}` — never blocks the writer (ADR-0026 durable-before-visible; OpenHands rule 1). (R-2) `ephemeral` frames never carry `seq`, never advance the cursor, are never in `read` (ADR-0026 D3; AC-B1-12), and a host that declared `accepts_ephemeral_frames = false` (or opted out of a class) never receives them. (R-3) Every `item_started{attempt}` is retired by exactly one `durable` (the completed item, whose `event_id` is the `item_id`) or one `item_aborted`; a higher `attempt` for the same `item_id` supersedes a lower one, so a model-attempt retry after restore (ADR-0130 R-2) rewinds the client's slot instead of duplicating text (Cursor/OpenHands precedent). (R-4) Resumption is `stream_events(session, from_seq)` inclusive; the first frame is `sync` echoing the range and the head hash so the client can verify continuity (ADR-0029 chain). (R-5) `filter.min_observability` and `filter.classes` are *client-side conveniences* implemented kernel-side; they never change what is durable. (R-6) Permission requests appear twice by design: `security.permission.pending` as a durable frame (ADR-0070; CF-152) and `permission_rendering` as an ephemeral frame carrying the profile-rendered proposal for a human (ADR-0026 amendment: `requested{rendering}` stays ephemeral); a host that missed the rendering re-derives it from `project(session, pending_permissions)`. (R-7) Cross-run frames (child runs spawned by delegation) arrive on the parent's stream only as the parent's own `control.subagent.*` events; a host subscribes to a child by `attach{run_id: child}`.

### 6.4 Transport bindings and the "one contract" rule (Spec §4; ADR-0050 D1 layers)

Three bindings, one contract (I8): **(a) in-process** — typed request/response channels inside a process of the ADR-0050 kernel ecosystem, bounded queues, `WouldBlock` on saturation, events fanned out with the same frame kinds; admitted for first-party surfaces (the CLI, WS-K1) and the kernel's own test client; the response envelope is byte-identical to the wire form after canonicalization (Codex rule: "not a second execution contract"). **(b) subprocess over stdio** — newline-delimited JSON-RPC 2.0 (ACP transport conventions: UTF-8, no embedded newlines, stderr for logs only, lifecycle-sensitive messages never batched), the kernel spawned by the client with the exact pinned version (I3); the Lab's binding (ADR-0050 lab row) and the SDK's default. **(c) local network** — the same JSON-RPC over a localhost HTTP/WebSocket pair with a per-connection `hello`, session `attach` routing `{server_id, session_id, attachment_id}` (Pi precedent) and an authentication scheme owned by WS-H3/K2 (out of scope here; OQ-401 for non-local hosts); the web/desktop surfaces' binding. Rules: a binding may add transport facts (connection id, auth, frame-size limits, `lagged` accounting) but never a verb, a field or an error variant; the **conformance suite** (AC-K4-2) runs the same fixtures over all three and diffs the canonical envelopes; `hello.stability` tells a client which methods are `stable | experimental | internal` on this kernel build; a fourth binding (e.g. a remote service) is an ADR.

**What the surfaces are built on (answers the row's "what the CLI/web/MCP surfaces are built on").** CLI = in-process client with the full stable set + first-party experimental opt-in; web/desktop/IDE = generated client over binding (c) with `attach` for viewers and `open_session` for launchers; MCP server (WS-K3) = a kernel-side server whose Lab tools are thin wrappers over Group M/S with server-minted handles (ADR-0097 D1); Lab = binding (b) with Group M; the ACP artefact = a client that lowers Group R frames into `session/update` and raises `session/request_permission` from Group U (ADR-0098 D2/D3); SDK bindings in any ecosystem = generated clients over (b) or (c) — they contain no runtime logic, no assembler, no monitor (ADR-0050 D2: nothing else crosses). Third-party *component variants* (WS-L5) use the variant-host boundary, which reuses I1–I5 but is a different endpoint (kernel → variant), and hosted participants use the Hosting ABI (WS-J6) — neither is this contract (CF-023).

**OQ-130 answer.** Every planned surface enumerated above is servable by a generated client over binding (b) or (c) under this contract: the surfaces need only the record set of ADR-0050 D2 (verified against WS-K2's stated needs — assembly UI → Group M `compose/…/seal` + registry reads; experiment launcher → `open_session` + Group M; trace/time-travel viewer → `attach` + `read/project` + `fork/navigate`; comparison dashboards → `project(results_row)` and bundle reads; debugging → `stream_events` with ephemeral frames). No surface needs an operation that returns a live object, executes kernel code client-side or bypasses the reference monitor. Q-L1-14 is therefore *not* narrowed; ADR-0050 trigger 6 does not fire; the late-bound surface ecosystem (E3 default) may be bound by WS-K2 at Stage ≥ 5 (ADR-0179).

### 6.5 API stability and versioning policy (Spec §8; applies ADR-0036/0037; L4 obligation of the row)

1. **One schema source, generated bindings, CI drift check (I1).** The kernel exports one machine-readable schema set: HIR/1, ledger event schemas, `MetricDeclaration` and every `hh-embed` message and error type; every binding in every ecosystem is generated from it; CI fails when a checked-in binding differs from a fresh generation (S-110 `check-agent-server-api.mjs`; S-107 `export.rs`). Hand-written client code is allowed *above* the generated layer only (the OpenHands "selected handwritten clients are statically checked against generated types" pattern).
2. **Identity of the contract.** `contract_major: int` (bumped only for AIP-180-breaking changes) + `schema_hash: ContentAddress` over the canonical schema export (ADR-0036 identity) + `kernel.version` (a SemVer-class label bound to a `version_id`, ADR-0037 name history). `hello` exchanges all three; the *pair* `(contract_major, schema_hash)` is what a generated client asserts; a mismatch is typed (`SchemaMismatch{direction}`) — never silent fallback (ADR-0099 N2 applied inward).
3. **Additive evolution within a major (AIP-180 rules adopted verbatim as normative).** Within one major: new methods, frame kinds, optional fields, enum values in *request* positions and error variants *may* be added; existing components *must not* be removed or renamed; types *must not* change even if wire-compatible; defaults *must not* change; a new field populated by clients *must* default to the pre-existing behaviour when absent; visible semantics *must not* change. Enum values in *response* positions (closed kernel sums: `StopReason`, `decider`, `EffectDomain`, error codes) grow only by **dialect bump** (phase-2 §6.8 rule 3), which is a minor for the contract but a dialect version for the payload — clients receive the dialect on `hello` and in every durable frame's `schema_version` (ADR-0026 AC-B1-8 "old events must always load" now reads in both directions: old *clients* must reject unknown dialects loudly, `SchemaMismatch`, never coerce).
4. **Stability tiers per method and per field.** `stable` (governed by rule 3; removal only at a major, after a deprecation window), `experimental` (callable only with `HostCapabilities.experimental = true`; refused otherwise with `ExperimentalRequired{reason: "<method>" | "<method>.<field>"}`; excluded from default generated bindings and from the `stable` conformance suite; may change or vanish in a minor; **must** carry an `AssumptionDebtRecord{hypothesis, evidence, owner, expiry_condition, removal_test}` whose removal test is "promoted to stable or deleted, and no first-party surface still references it" — T-LCD-05 reflexive), `internal` (reachable only from first-party in-process clients; never in the exported schema; the Claude `Transport`-class warning made structural). Promotion `experimental → stable` is an ADR-lite entry in the contract's changelog with the debt record closed; the CLI may ship on experimental items, third-party SDKs may not without opting in.
5. **Deprecation.** A `stable` item marked `deprecated{since, removal_major, replacement}` stays callable for the rest of the major; `hello.stability` reports it; a ledgered `lifecycle.contract.deprecated_use{method, client}` event lets the readiness report count remaining users; removal happens at the next major only when the count is zero across the participant/surface registry (the ADR-0037 "removal test" shape; Codex's `v1` namespace kept behind an allowlist is the precedent).
6. **Notification opt-out and capabilities are the only per-connection variability.** A client may decline event classes (`opt_out_notifications`) or ephemeral frames; it may not ask the kernel for a *narrower schema* — the kernel emits the full durable record (ADR-0026: the ledger is never sampled), and narrowing is a client-side filter.
7. **Exact pinning (I3) and floors.** A client package pins one exact kernel build (S-107 `python-runtime`, S-110 `agentServerImage` precedents) and declares its `kernel_floor`; `hello` refuses below the floor (`KernelBelowFloor`) rather than warning (the Claude SDK warns — rejected because a warning is an untyped escape hatch). The pinned build's `schema_hash` enters the client's own version identity so that a client and the bundle's `InstrumentRecord.component_versions` (ADR-0038) agree on what ran.
8. **Compatibility matrix as a test artifact.** Golden fixtures per `(contract_major, schema_hash)` pair are kept; the suite runs `newer client × older kernel` (expects `SchemaMismatch`), `older client × newer kernel within a major` (expects success with defaults), and cross-major (expects `ContractMajorUnsupported`). This is the readiness-report evidence for R-2.11.4.

### 6.6 Data-model sketch

`Hello`, `HostCapabilities`, `OpenSpec{new | resume | attach}`, `Supplies{context[], host_capabilities[], mcp_servers[], procedures[]}`, `Session{session_id (allocated, opaque), run_id, attachment_id, manifest_ref, configuration_ids, realized: RealizedSettings, cursor}`, `RealizedSettings{model_role_table_realized, cwd, containment_effective_ref, policy_mode, profile_bindings, protocol_bindings[]}`, `Frame` (§6.2), `HookInvocation{hook_point: DecisionPoint, run_id, turn_id?, proposal_ref?, inputs_hash}` / `HookResult{raise | deny | annotate | none}`, `ExecutionRequest` (WS-E5 shape, minus any handle), `HostEffectReport{effect_id, attempt_no, outcome, output_artifacts[], error_class?}`, `EmbedError{code, retryable, detail?, event_ref?}`, `StabilityMap = map<method, {tier, deprecated?: {since, removal_major, replacement}}>`, `ContractIdentity{contract_major, schema_hash, kernel_version_id}`. New ledger events proposed to WS-B1 (all `durability = ledger`, `origin = kernel`): `lifecycle.session.attached/detached{attachment_id, client{name, version, kind}, capabilities_negotiated, binding ∈ {in_process, stdio, local_network}, contract_identity}`, `lifecycle.contract.deprecated_use{method, client}`; `lifecycle.run.created.manifest` gains `embedding: {client, binding, contract_identity}` (a run manifest fact, like `protocol_bindings[]`, ADR-0099). ### 6.7 Acceptance-criteria sketch

- **AC-K4-1 (C0/Stage 1; T-LCD-12) Contract as records.** Every §6.1 operation is specified as operations/inputs/outputs/invariants/failure modes; the schema export contains the full message and error sums; a stub client generated from the export completes `hello → open_session(new) → submit → stream_events → close` against the Stage-1 kernel over binding (b).
- **AC-K4-2 (Stage 1; I8) One contract, every binding.** The conformance suite (fixtures for every operation, every error variant, every frame kind, resume, cancel, fork, permission round trip, host-executed capability round trip) passes with byte-identical canonical envelopes over in-process, stdio and local-network bindings; a verb reachable on one binding and not another fails the build.
- **AC-K4-3 (Stage 1; I2/I4) Strictness and hash equality.** A message with an unknown non-`ext` field is refused with `UnknownField{path}`; every `durable` frame's `hash` equals the ledger's for that `seq`; a client-side `verify` over a received range agrees with the kernel's `verify` (ADR-0029).
- **AC-K4-4 (Stage 1–2; I5) No authority crosses.** Fixtures attempt: a host `HookResult{allow}` (schema-refused); a `respond_permission` for an option not offered (`OptionNotOffered`); a `respond_permission` from an `attach`-mode session (`CapabilityNotDeclared`); a `SecretInPayload`; an `EnvHandleId` or `HandleId` anywhere in a request or response (static schema check: no such type is reachable from the contract's schema — the H-1 `HandleLeak` rule at the boundary); an `open_session.overrides` widening a cap (`AuthorityViolation` naming the capping layer). All refused; the ledger shows no `security.permission.decided{decider: human}` without a preceding upcall.
- **AC-K4-5 (Stage 2; ADR-0030/0130) Host-executed capability lifecycle.** With a host executor bound: `invoke_host_capability` arrives only after `action.effect.committing`; a host that never reports leaves the effect `unknown` at restore and the kernel probes/escalates per class; a duplicate `report_host_effect` with the same key is idempotent; a report after a takeover is `Fenced` and ignored; the result's `Observation.authority` is `external`.
- **AC-K4-6 (Stage 1–2; §6.2) Resumable subscription.** Kill the client at each of: mid-delta, after `item_started`, after a durable frame, during `respond_permission`; on `stream_events(from_seq)` the client receives `sync`, no duplicate durable frame, every open `item_started` retired, and the pending permission still answerable; a slow consumer sees `lagged{ephemeral}` and, past the bound, `closed{slow_consumer}` while the writer never stalled (measured: no `control.timeout.fired` attributable to the client).
- **AC-K4-7 (Stage 1; ADR-0130) Idempotent restore across the boundary.** Two concurrent `open_session(resume{takeover})` from two clients: exactly one succeeds, the other gets `WouldBlock(active_holder)`; a `submit` retried with the same key after a disconnect yields the same `turn_id` and one turn in the ledger.
- **AC-K4-8 (Stage 1; §6.5) Negotiation and tiers.** `hello` with an unsupported major → `ContractMajorUnsupported`; with a stale `schema_hash` → `SchemaMismatch{direction}`; a call to an `experimental` method without the capability → `ExperimentalRequired{reason}`; with it → success and the item's debt record present in the export; a deprecated method use appends `lifecycle.contract.deprecated_use`; the compatibility-matrix fixtures (§6.5 rule 8) pass.
- **AC-K4-9 (Stage 0–3; l1-spike-spec S2) Boundary cost is measured, not assumed.** The S2 slice reports per-crossing overhead, durable-frame delivery latency (p50/p95) and ephemeral-drop rates at the spike's fan-out; results append to ADR-0050's amendment log (OQ-131) and set the connection bounds that §6.2 R-1 leaves as MUST-data constants.
- **AC-K4-10 (Stage 3; F8) The Lab is an ordinary client.** WS-J3's engine and WS-I4's scorer bridge run entirely over Group S/R/M of this contract; `measurement.metric.emitted` rows appended by the Lab are indistinguishable in the ledger from any client's; no Lab code links the kernel in-process.
- **AC-K4-11 (Stage ≥ 5; OQ-130) Surface servability.** Each WS-K2 screen and each WS-K1 command is implemented over the generated client (or the in-process binding for the CLI) with no private verb; the readiness report lists, per surface, the operations used and their tiers.
- **AC-K4-12 (T-LCD-06/-07 at this boundary) Hosting is absent and unaffected.** Building with the hosting tier absent leaves this contract and AC-K4-1…11 unchanged; a hosted participant's adapter uses `attach`/Group R only for lifting and never `open_session(new)` on a native definition it does not own (class is declared by the Lab — ADR-0013).
