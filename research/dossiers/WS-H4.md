## 1. Scope & boundary

This workstream designs **deterministic containment**: the typed policy that bounds what an execution environment can *touch* (filesystem), *reach* (network), *become* (process/privilege) and *consume* (resources), the enforcement points that apply it and how far each can be trusted, the observation/audit of every egress decision, and the rule that makes containment the **floor** beneath the capability **ceiling** of the reference monitor (WS-H1). It answers doc 3 §5's row: allow-lists, proxying, DNS/egress observation, filesystem boundaries, process isolation; policy as data attached to the environment handle (WS-B5); containment as the backstop beneath probabilistic classifiers; and what Anthropic's containment telemetry (S-053: ~93% approvals; auto-mode miss rate) means for the design.

It explicitly leaves to neighbours: **WS-B5** — the environment handle itself (lifecycle, snapshot/restore, identity, image digests); this dossier fixes only the `containment` slot on the handle and the `ContainmentReport` it must return (the WS-B5 dossier was not on disk when this was written — CF-WS-H4-01). **WS-E5** — the executor that runs tool calls inside the environment and accepts `(effect_id, attempt_no, idempotency_key)`; this dossier fixes what the executor must *report* about enforcement and how the per-effect attribution token is minted. **WS-H1** — the reference monitor and the policy table Π (OQ-101); this dossier fixes the precedence rule (containment admits ∧ permission covers) and the `ContainmentReport` input the monitor consumes. **WS-H3** — credential mediation; this dossier fixes only the *binding* slot on egress rules (`credential_bindings`) and the invariant that credentials enter traffic at the mediator, never in the environment. **WS-H2** — reader-set flow checks and body-level content policy (C2). **WS-H7** — the cadence and UX of `ask` on egress and the approvals budget; this dossier fixes that egress `ask` is a budgeted approval and that "approve for the session" is a cached endorsement of a canonical pattern. **WS-H6** — attestation of the containment events; they ride the ledger chain. **WS-I4/J3** — which environment classes and images the Lab provisions and per-phase policy switching (agent vs verifier phase); this dossier fixes that a phase switch is a ledgered policy amendment. **WS-L2** — resource dimensions; this dossier proposes registered `ext` dimensions only. Nothing here names a language, runtime or package ecosystem; every precedent path is evidence, not a dependency.

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Every production containment system that enforces at the process level converges on the same four-part policy shape, expressed as data, with deny-over-allow precedence.** Codex's `SandboxPolicy` is a closed sum `{danger-full-access, read-only{network_access}, external-sandbox{network_access}, workspace-write{writable_roots, network_access, exclude_tmpdir_env_var, exclude_slash_tmp}}` (`protocol.rs` L1074–1122) refined in the newer `PermissionProfile = Managed{file_system, network} | Disabled | External{network}` (`models.rs` L419–433) with `NetworkSandboxPolicy = Restricted | Enabled` (`permissions.rs` L80–84) and a `FileSystemSandboxPolicy{kind, entries[]}` (L235–239). Its network proxy config carries `NetworkDomainPermission = None < Allow < Deny` with the comment "deny wins over allow when entries conflict" (`config.rs` L20–26) and `NetworkMode = Limited | Full` where limited "only GET/HEAD/OPTIONS are allowed" (L363–372). sandbox-runtime's schema is the same shape in another codebase: `FsReadRestrictionConfig{denyOnly, allowWithinDeny}` (deny-then-allow; "maximally permissive by default"), `FsWriteRestrictionConfig{allowOnly, denyWithinAllow}` ("empty allowOnly means NO paths are writable"), `NetworkRestrictionConfig{allowedHosts, deniedHosts}` ("deniedHosts are checked first … deny unconditionally"), plus an `ask` callback for the unmatched case (`sandbox-schemas.ts`). Harbor's Lab-side policy is `NetworkPolicy{network_mode ∈ {no-network, public, allowlist}, allowed_hosts}` with a validator that forbids hosts outside allowlist mode (`config.py` L66–78). Three independent implementations therefore agree on: read = allow-all-except, write = allow-only, network = allow-only with a default for the unmatched host, deny wins, and the whole thing is a serialisable document. **Implication:** the containment policy is a typed record (§6.1), never code, and its meet is "deny wins, allow needs every layer" (F2).

**F2 — Layered policies compose by narrowing only; inherited denials survive.** Codex's `EnvironmentNetworkPolicy.apply_to` (an environment owner's traffic restrictions applied over a controller's config) preserves "inherited denials" verbatim, keeps a socket grant only if *both* policies allow it ("'Allow all' cannot override a socket denied by either policy"), and ANDs `allow_upstream_proxy` and `allow_local_binding` — "Enable permissions only when both controller and owner allow them" (`environment_policy.rs` L40–84). Claude Code honours `mask`, `tlsTerminate` and `allowPlaintextInject` "only from settings you or your administrator control" and ignores them in repository settings; `allowManagedDomainsOnly` makes only managed entries count (S-WS-H4-02). This is the monotone-authority layering ADR-0024 already fixes for definitions and the never-widen rule of ADR-0034 P6 applied to containment: a lower-authority layer can only remove, never add. **Implication (§6.2):** `effective = ⊓ layers` with deny-wins semantics and the layer's `ProvenanceRecord.authority` deciding which fields it may *loosen* (none below `principal`; repository-scoped documents are `external` and can only narrow).

**F3 — The non-public-address guard and host normalisation are where allowlists silently fail; the source treats them as first-class.** Codex `policy.rs` classifies loopback, private, link-local, CGNAT, TEST-NET, benchmarking and reserved IPv4 ranges and unique-local/link-local/unspecified/multicast IPv6 as "non-public" explicitly "for SSRF prevention", normalises hosts (lowercase, strip brackets/ports/trailing dots, scoped IPv6 literals), expands `*.example.com` (subdomains only) vs `**.example.com` (apex and subdomains), and **refuses a global `*` in a denylist** so a denylist cannot be neutralised by a wildcard; `connect_policy.rs` re-checks the *resolved* socket address so a public hostname resolving to a private IP is rejected unless `allow_local_binding`. Claude Code documents IPv6 bracket forms and per-port matching (`"[::1]:443"`), and that `injectHosts` matches bare canonical addresses "so a bracketed, zone-ID, or differently compressed spelling never matches". Harbor's sidecar permits DNS "only to nameservers listed in resolv.conf — the same trust boundary Docker's embedded resolver has" and rejects every non-TCP protocol. **Implication (§6.4):** host matching is a specified normalisation function with property tests; DNS is egress; resolution results are re-checked; non-public destinations are denied by default.

**F4 — Attribution of each connection to the effect that caused it is implementable and is what makes egress *auditable* rather than merely *filtered*.** Codex's Linux sandbox helper writes an attribution frame (`\0CDXPXY1` + token) on every proxied connection; the proxy maps the token to an execution scope and rejects "unknown network proxy attribution token" and environment mismatches with `PermissionDenied` (`attribution.rs` L40–70); every host decision emits a policy audit event with `{scope, decision, source ∈ {baseline_policy, mode_guard, proxy_state, decider}, reason, protocol, server_address, server_port, method, client_addr, execution_id, policy_override}` (`network_policy.rs` L363–450) and the same record crosses the helper protocol as `network/policyDecision` (`exec-server-protocol/src/network_policy.rs` L30–47). sandbox-runtime stores violations under a per-invocation `commandId` "recommended … so long commands sharing a prefix would otherwise cross-attribute" (README). **Implication (§6.5):** every egress decision is a ledger event keyed by `effect_id`; unattributable connections are denied.

**F5 — Systems that stop at the container boundary have no egress policy, and the boundary itself can be misconfigured or escaped; the evaluation process is outside it.** OpenHands' Docker workspace runs `docker run -d --rm` with published ports, forwarded env vars and an optional `--network`, and nothing else (`docker/workspace.py` L215–260); its `BaseWorkspace` contract is `execute_command/file_upload/file_download/git_*` with no policy field. Inspect's default `network_mode: none` is *replaced* (not extended) by any custom compose file and "applies only to processes inside the container. It does not restrict network access from the evaluation process or model provider" (`sandboxing.qmd` L220–237). SandboxEscapeBench (S-WS-H4-10, `provisional (mech)`) shows models exploit misconfiguration and privilege-allocation errors in Docker/Kubernetes when present. S-053 corroborates from production: gVisor for multi-tenant server-side execution, a full VM for non-technical users, OS sandboxes for developers — the class of boundary is chosen per threat model, not assumed. Firecracker's own design doc states it filters no egress. **Implication (§6.3):** the *class* of the machine boundary is a declared field with enforcement evidence; the Lab's own processes (scorers, provider calls) are outside it and must be labelled so (`charged_to = instrument`, T-LCD-15).

**F6 — Approvals and classifiers are advisory; every product keeps a deterministic escape hatch that the model can *propose* but a human must *confer*.** Codex: `sandboxing.rs` computes `unsandboxed_execution_allowed` and `escalate_on_failure`, and `AskForApproval::UnlessTrusted` means "commands require approval unless an explicit exec policy rule allows them"; blocked network requests surface as `NetworkPolicyDecision::Ask` from a "decider" (`network_policy.rs` L66–70) and an approval appends an exact-host `NetworkRule` ("wildcards are not allowed", `execpolicy/src/rule.rs` L197–204). Claude Code: the model "may retry the command with the `dangerouslyDisableSandbox` parameter", which "goes through the regular permission flow", and administrators can set `allowUnsandboxedCommands: false` so the parameter is *ignored* (strict sandbox mode). S-053 quantifies why: ~93% of prompts approved; auto-mode classifier ~0.4% benign blocks and ~17% misses; "any probabilistic defense has a non-zero miss rate". Codex's `sandbox_tags.rs` is explicit that diagnostic labels "must never be used to authorize". **Implication (§6.7):** the escape hatch is an *effect* of domain `permission_request` that widens containment; it is valid only with an `approval` endorsement (ADR-0035 basis) of that one `effect_id`, is ledgered, is budgeted (ADR-0040: exhausted approvals ⇒ `deny`), and is disabled by default for Lab runs (strict mode).

**F7 — Allow-listing a destination grants a capability, not a filter; the residual is body-level exfiltration to approved hosts, which no C0 egress mediator can close.** S-053's red team exfiltrated in 24/25 attempts via an allowlisted domain's upload endpoint using attacker-supplied keys; Back-Reveal (S-WS-H4-11) exfiltrates through "disguised retrieval tool calls". Claude Code's proxy "does not terminate or inspect TLS … so the contents of encrypted connections are not examined"; Codex limited mode blocks CONNECT "unless MITM is enabled". The mitigations the products found are structural: **per-credential host binding** (sandbox-runtime's sentinel is swapped "only when the destination matches THAT credential's hosts … prevents laundering credential A through credential B's allowlisted host"; Codex `CredentialRecord.host_binding`), **method restriction** (GET/HEAD/OPTIONS), and **reader-set flow checks** (CaMeL `send_email`, ADR-0035 check 3, C2). **Implication (§6.4, §5):** an egress rule carries `methods` and `credential_bindings`; TLS termination is a declared, non-default option (OQ-WS-H4-01); the residual is stated and measured, not hidden.

**F8 — Filesystem containment has three known sharp edges that the source handles explicitly: protected metadata inside writable roots, symlink resolution order, and platform lowering loss.** Codex's `WritableRoot{root, read_only_subpaths, protected_metadata_names}` exists "to ensure that folders containing files that could be modified to escalate the privileges of the agent (e.g. `.codex`, `.git`, notably `.git/hooks`) under a writable root are not modified" (`protocol.rs` L1124–1140) and bubblewrap re-applies `--ro-bind` for `.git/.agents/.codex` after remapping through symlink targets (`bwrap.rs` L380–450, L595–645). Claude Code protects `.claude/{skills,agents,commands,hooks,workflows}`, `.mcp.json` and scheduled-task files with "no way to exempt one of these paths". S-053: "symlink resolution has to happen *before* path validation, not after" (a shipped vulnerability). Landlock cannot restrict `chdir/stat/chmod/chown`; Codex's legacy Landlock path cannot express restricted *reads*; macOS masks credential files by deny where Linux masks by bind-mount. **Implication (§6.1, §6.6):** protected-metadata names are a policy field with a kernel-supplied minimum set (the harness's own config/hook/skill directories — the X-CPE write targets of S-103); symlink-before-validate is an invariant; lowering a policy to a backend emits a **containment lowering loss report** analogous to T-LCD-11.

**F9 — The helper is out-of-process behind a narrow protocol in every audited enforcer, and in-thread primitives are used only by the helper on the child's behalf (OQ-045 input).** Codex applies `no_new_privs`, seccomp (deny `ptrace`, `process_vm_*`, `io_uring_*`, and in restricted mode `connect/bind/listen/sendto/…` with only `AF_UNIX` sockets permitted) and legacy Landlock "inside this thread so only the child inherits them, not the entire CLI process" (`landlock.rs` L36–45), launched through `codex-linux-sandbox`/bubblewrap with `--unshare-user/pid/ipc[/net] --new-session --die-with-parent` (`bwrap.rs` L270–360); the controller talks to the executor over `exec-server-protocol` whose `ExecParams` carries a "portable sandbox intent. Concrete wrapper argv is resolved by the exec-server", `enforce_managed_network` ("when … details are absent, the executor must continue to fail closed"), and a `network/policyRequest` RPC back to the controller for `Allow | Deny | Ask` (`protocol.rs` L283–362; `network_policy.rs`). sandbox-runtime wraps the command with `sandbox-exec`/`bwrap` and runs the proxies in the host process. Harbor's enforcement is a sidecar container with `NET_ADMIN`. **Implication:** the provisional answer of ADR-0049 stands from H4's side; the helper protocol must carry the policy *as data* plus an enforcement report (§6.3). ADR-0050 already notes the helper ecosystem can host seccomp/Landlock/Seatbelt in-thread, which is exactly the helper-side use.

## 5. Disconfirming evidence & negative results

**Against hard containment at all: it reduces usability and observability and still has implementation flaws.** Doc 2 §6 records exactly this caveat; S-053 adds that VM isolation "keeps host-based endpoint detection and response out", that local MCP servers must run *outside* the VM, and that the pre-trust execution of project hooks was a shipped bug. *Why this does not overturn:* the same source reports the mechanism's payoff (84% fewer prompts, i.e. less approval fatigue, the thing that makes approvals a rubber stamp) and the design principle "containment at the environment layer first, then steer behaviour at the model layer". The dossier makes the usability cost measurable (AC-H4-11) and the observability loss explicit: the boundary class is declared, so a Lab run on a VM reports `n/a{observability}` for host-side metrics rather than pretending.

**Against a bespoke egress mediator: "the software you build yourself is often the weakest layer" (S-053).** Battle-tested kernels (gVisor, seccomp, hypervisors) proved more reliable than custom proxies and allowlists. *Why this does not overturn:* the recommendation keeps custom code to a *decision function over records* (§6.4) and treats the transport (proxy, namespace, filter rules) as a replaceable backend — Harbor uses an off-the-shelf proxy behind nftables; sandbox-runtime and Codex use OS primitives for the hard boundary and a proxy only for *policy*. The escape battery (§6.8) is what catches the custom part. The dossier ranks enforcement points by the trust of their substrate (§6.3) so a reviewer can see which decisions rest on custom code.

**Against allowlists as the C0 egress mechanism: approved-domain exfiltration (24/25) and TLS opacity.** *Why this does not overturn:* the allowlist is not claimed to prevent exfiltration; it bounds *where* bytes can go and *which credential* can travel with them (method restriction + credential binding are C0), and the residual is named as an assumption-debt-style record on the policy (`residual_channels`) so WS-H2's reader-set flow check (C2) and optional TLS termination (OQ-WS-H4-01) are the declared closers. AgentDojo-style `security(pre_env, post_env)` tests exercise the residual (AC-H4-05).

**Against proxy-based filtering: it relies on well-behaved clients and misses DNS/UDP/raw sockets.** On macOS the Seatbelt profile only constrains sockets to a localhost port; the proxy is "not kernel blocking"; sandbox-runtime warns "seccomp not available – unix socket access not restricted"; Codex leaves `recvfrom` open and permits `AF_UNIX`; WSL interop sockets can launch host binaries. *Why this does not overturn:* `net.mode = none` (namespace removal / seccomp deny of `connect`) is the C0 default and is kernel-enforced; `mediated` mode is defined as *namespace-removed plus a bridged channel* (sandbox-runtime Linux model; Harbor nftables redirect) rather than "set `HTTP_PROXY` and hope"; DNS is an egress class with its own rule; the lowering loss report records what a backend cannot enforce (macOS: unix sockets unless seccomp; Landlock: no read restriction; Windows: WFP by SID) so the Lab stratifies by it (T-LCD-07 shape).

**Against TLS termination as the fix: MITM puts a CA and plaintext inside the trust boundary and breaks pinned clients.** Codex requires MITM for limited-mode CONNECT and marks plaintext injection "dangerously"; Claude Code's `tlsTerminate` is experimental and "does not add content filtering". *Why this does not overturn:* termination is a declared optional field (`tls.terminate`) whose default is off; the C0 design does not depend on inspecting bodies. Recorded as OQ-WS-H4-01.

**Against declaring a machine-boundary class: containers are escapable and the class is not a proof.** SandboxEscapeBench (provisional) exploits misconfigurations; Firecracker filters no egress; gVisor gives no side-channel protection. *Why this does not overturn:* the class field is *evidence*, not assurance — `enforcement_evidence ∈ {attested, reported, probed, unknown}` — and the escape suite (AC-H4-12) runs against the *configuration*, not the model. The dossier never claims "sandboxed ⇒ safe"; it claims "unsandboxed ⇒ refused" (fail-closed, AC-H4-08).

**Against fail-closed by default: production tools fall back to unsandboxed execution when dependencies are missing.** Claude Code "shows a warning and runs commands without sandboxing" unless `failIfUnavailable`; Codex's `PermissionProfile::Disabled` exists. *Why this does not overturn:* those are developer-ergonomics defaults for interactive use; a research instrument whose results are keyed by `environment_ref` (ADR-0036 `configuration_id`) cannot silently change the boundary between replicates without corrupting the factor. Lab runs are strict; interactive runs may declare `on_unavailable = warn_and_degrade`, which is recorded on every event of the run.

**Against putting the escape hatch behind approval: it costs the ~93%-approve prompts containment was meant to remove.** *Why this does not overturn:* the hatch is the *exception* path; the numbers say the ordinary path (sandboxed, no prompt) absorbs most volume. Where the hatch fires often, the policy is wrong and the Lab sees it (`containment.amendments` per run is a class-scoped metric). Session-scoped caching of an approved canonical pattern (ADR-0031 decision 3; Codex `ApprovedForSession`) is permitted and ledgered.

**Against a total containment record on the handle: hosted participants (container-installed mechanism) may bring their own sandbox.** Codex's `External{network}` profile and `ExternalSandbox` kind exist for exactly this. *Why this does not overturn:* `proc.isolation = external` is a value of the sum with `enforcement_evidence = reported | unknown`; the monitor treats `unknown` as unenforced; no IR field is added for hosted participants (T-LCD-06).

**Negative results from the audit.** (i) No audited system attaches an authority/provenance class to a containment policy or records who amended it; approvals are persisted as exact-host rules (Codex) or `WebFetch(domain:…)` allow rules in *local settings* (Claude Code) — the X-CPE persistence path S-103 warns about, here applied to *policy*. (ii) No audited system reports enforcement evidence to its decision layer beyond a backend enum (`ProcessSandboxType`); "sandboxed" is asserted, never probed. (iii) OpenHands and Cloudflare carry no egress policy; Inspect's default is lost by customisation. (iv) No audited system meters bytes out; Codex counts decisions, Harbor counts nothing. (v) Every audited proxy-based design leaves at least one protocol class unmediated on at least one platform.

## 6. Recommendation for the spec

### 6.1 The containment policy record (typed data on the environment handle) — ADR WS-H4-adr-1

`ContainmentPolicy/1 = { policy_id: semantic_id, version_id, provenance: ProvenanceRecord, fs: FsPolicy, net: NetPolicy, proc: ProcPolicy, resources: ResourceLimits, amendment: AmendmentPolicy, residual_channels: [ResidualChannel], ext }`. It is an HIR-adjacent data document (ADR-0023 "definitions are data"; ADR-0024 MUST-data), content-addressed under `idp/1` (ADR-0036) with `semantic_id` excluding `provenance`, `ext` and host-spelling surface (normalised patterns are semantic; T-LCD-10), and referenced from `AgentProcess.native.environment: EnvironmentRef` via the handle's `containment` slot (WS-B5). Field sketch (closed sums per dialect; `ext` registered, never authority-bearing — ADR-0015):

- `FsPolicy = { read: { mode ∈ {allow_all_except, allow_only}, deny: [PathPattern], allow_within_deny: [PathPattern] }, write: { allow: [WritableRoot], deny_within_allow: [PathPattern] }, exec: { allow: [PathPattern] | any }, protected_metadata: [Name] ⊇ KERNEL_PROTECTED, symlink_resolution: before_validation, mounts: [Mount{source: ContentAddress | HostPath, target, mode ∈ {ro, rw, masked(sentinel_ref)}}] }`; `WritableRoot = { root, read_only_subpaths: [Path], protected_metadata_names: [Name] }` (Codex shape). `KERNEL_PROTECTED` is the kernel-supplied minimum: the harness's own definition/config/hook/skill/scheduled-task locations and VCS hook directories (S-103 X-CPE write targets; Claude Code and Codex protected lists) — no policy layer may remove a name from it (`ProtectedPathExemption` error).
- `NetPolicy = { mode ∈ {none, mediated, public}, default_unmatched ∈ {deny, ask}, rules: [EgressRule], non_public_destinations ∈ {deny, allow_listed}, local_binding: bool = false, unix_sockets: { mode ∈ {deny, allow_listed, allow_all}, allow: [Path] }, dns: { resolver ∈ {mediator, listed_nameservers[], none} }, tls: { terminate: bool = false, inspect_hooks: [Ref] }, upstream_proxy?: Ref, methods_default: {GET, HEAD, OPTIONS} | any }`; `EgressRule = { host: HostPattern (exact | *.apex | **.apex; global * only in allow), ports: [PortRange] | any, protocols ⊆ {http, https_connect, socks5_tcp, socks5_udp, tcp_transparent}, methods ⊆ HttpMethods | any, decision ∈ {allow, deny}, credential_bindings: [CredentialRef] (WS-H3), justification: Text, provenance: ProvenanceRecord }`. Invariant N1: `deny` rules are evaluated before `allow`; N2: a `deny` rule never carries a global wildcard (Codex); N3: `mode = none ⇒ rules = []`; N4: `mode = public` requires `provenance.authority ≥ principal` and is recorded as a `residual_channels` entry.
- `ProcPolicy = { isolation_class ∈ {none, process_sandbox, namespaces, user_space_kernel, microvm, external}, unshare ⊆ {net, pid, ipc, user, mount}, no_new_privs: bool = true, syscall_filter: Ref | none, ptrace: deny, setuid: deny, max_processes, env: { inherit ∈ {all, core, none}, exclude: [Name], set: map, include_only: [Name] }, die_with_parent: bool = true }` (Codex bubblewrap/seccomp fields; `env` is Codex `ExecEnvPolicy`). `external` means "a boundary the runtime did not construct" and is admissible only with a reported `enforcement_evidence`.
- `ResourceLimits = { cpu_ms?, memory_bytes?, disk_bytes?, pids?, open_files?, wall_ms?, network_bytes_out?, network_calls? }` — every non-null limit maps to a `BudgetNode` dimension (ADR-0040) or a registered `ext` dimension (CF-WS-H4-04) so exhaustion is a budget event, not a silent kill.
- `AmendmentPolicy = { allowed_bases ⊆ {approval, policy_rule, seal} (ADR-0035 basis list), strict: bool (true ⇒ no run-time amendment; the escape-hatch parameter is ignored), session_cache: bool, persist_scope_ceiling ∈ PersistenceScope }`.
- `ResidualChannel = { kind ∈ {approved_host_body, tls_opaque, dns_names, unix_socket, side_channel, host_bridge}, statement: Text, closer: Ref<WS-H2 policy | tls.terminate | none>, owner }` — the containment analogue of an assumption-debt record (T-LCD-05 shape; expiry = "closer lands").

### 6.2 Effective policy: layered meet by authority (ADR-0034 P6 applied to containment)

`effective(policies: [ContainmentPolicy]) → ContainmentPolicy`: sort layers by `provenance.authority` (`kernel > definition > principal > delegate > environment > external`); start from the kernel default (`fs.read = allow_all_except(KERNEL_DENY)`, `fs.write = allow_only([])`, `net.mode = none`, `proc.isolation_class ≥ process_sandbox`, `no_new_privs`, strict amendment); each lower layer may **narrow any field** and may **loosen** only fields its class is entitled to: `principal` may set `net.mode ∈ {mediated}`, add `allow` rules and `WritableRoot`s, and set `amendment.strict = false`; `definition` (sealed) may add `allow` rules with `justification`, mounts and resource limits; `delegate`/`external`/`unverified` layers (a repository's own config file, an imported profile, a model proposal) may only narrow — an attempt to loosen is refused with `ContainmentWidening` (parallel to `AuthorityWidening`). Deny entries from any layer survive every merge (Codex `apply_to`); booleans AND; sets of allows intersect across layers of *lower* authority and union only within one layer. The result is sealed with the run manifest (`configuration_version_id` covers it; `environment_ref` in `configuration_id` covers its `semantic_id`).

### 6.3 Enforcement points and their trust — ADR WS-H4-adr-3

| point | what it enforces | substrate trusted | evidence it must report | may decide `allow`? |
|---|---|---|---|---|
| **E1 machine boundary** (`isolation_class ∈ {namespaces, user_space_kernel, microvm}`) | address space, mounts, network namespace, resource cgroups | host kernel / hypervisor; image digest (WS-B5) | `attested` (image digest + runtime identity) or `reported` | no — it has no policy; it bounds |
| **E2 process sandbox helper** (`process_sandbox`: Seatbelt / bubblewrap + seccomp / Landlock / restricted token + WFP) | fs read/write/exec, socket families, syscalls, privilege | OS kernel; helper binary identity | `ProcessSandboxType`-style backend + lowering loss report + `probed` self-test results | no |
| **E3 egress mediator** (proxy reached over a bridged channel from a namespace with no network; or transparent redirect) | host/port/protocol/method rules, non-public guard, DNS, credential binding, byte metering | kernel-class process on the host side of E1/E2 | one `security.egress.decided` per decision with `source` | yes for `allow` rules; `ask` goes to E4 |
| **E4 reference monitor** (WS-H1) | `authorize(p)`: Permission covers ∧ containment admits; resolves `ask` via `approval` endorsement | kernel | `security.permission.decided{effect_id, effective_risk_class}` (ADR-0030/0031) | yes, within the floor |
| *not an enforcement point* | classifier (`auto_review`-class), model self-report, hooks, human approval of *content* | — | inputs to Π only (ADR-0035 decision 5) | never |

**Trust rule.** A decision at E3/E4 is valid only if the E1/E2 report for the same environment has `enforcement_evidence ≠ unknown` for every field the decision relies on; otherwise the effect is refused with `ContainmentUnverified` (fail-closed). `enforcement_evidence ∈ {attested, reported, probed, unknown}` is tri-state-plus-attested and **never coerced** (T-LCD-07 shape): `reported` = the helper said so; `probed` = the kernel ran the self-test battery inside the environment at attach (write outside root fails; `connect()` fails in `none`; DNS fails; ptrace fails); `attested` = image/runtime identity verified (WS-H6/H5). The helper protocol (WS-B5/E5; OQ-045) must carry: policy in (`ContainmentPolicy` by content address + inline), `ContainmentReport` out (`{policy_version_id, backend, isolation_class, enforcement_evidence per field group, lowering_loss: [LossItem{field, backend, reason}], probes: [ProbeResult]}`), and the `egress/decision_request → allow | deny{reason} | ask{reason}` round trip (Codex `network/policyRequest`).

### 6.4 Egress decision contract — ADR WS-H4-adr-2

`decide_egress(policy, req: EgressRequest{effect_id, tool_call_id, env_handle, protocol, host_raw, host_norm = normalize(host_raw), resolved_addrs[], port, method?, credential_sentinels[]}) → EgressDecision{decision ∈ {allow, deny, ask}, source ∈ {mode_guard, deny_rule, non_public_guard, allow_rule, default_unmatched, approval_cache, monitor}, rule_ref?, reason ∈ closed list, credential_binding_applied: [CredentialRef]}` with the evaluation order fixed as a contract: (1) `mode = none ⇒ deny(mode_guard)` — and E2 must already have made this unreachable; (2) attribution: no `effect_id` ⇒ `deny(unattributed)`; (3) `deny` rules on `host_norm` **and** on every `resolved_addr`; (4) non-public guard on `resolved_addrs` unless `non_public_destinations = allow_listed` and listed; (5) protocol/port/method guard (`method_not_allowed`); (6) `allow` rule ⇒ `allow`, applying `credential_bindings` only where the sentinel's own binding names this host (anti-laundering, sandbox-runtime); (7) `approval_cache` on `H(canonical pattern, scope)` (ADR-0031 decision 6); (8) `default_unmatched` ⇒ `deny` or `ask(monitor)`, where `ask` consumes an approval from the approvals budget (ADR-0040; exhausted ⇒ `deny`) and, if granted, endorses **one `effect_id`** (ADR-0035 `approval` basis) and may append an *exact-host* `allow` rule at `scope = session | run` only (persisting to `project`/`user` scope is a `ContainmentPolicy` amendment subject to §6.7). DNS: with `dns.resolver = mediator` the environment never resolves names — the mediator resolves after the host decision, so names are not a covert channel; with `listed_nameservers` only those addresses on port 53 are reachable (Harbor); `none` ⇒ no name resolution. Every decision emits `security.egress.decided`; a denial is surfaced to the model as a typed `Observation{source: environment, authority: environment}` naming host and reason (Codex `denied_network_policy_message`) so the model can *propose* an amendment but never make one.

### 6.5 Observation and audit (WS-B1/H6/I1 seams)

New security-plane event classes (`plane.noun.verb`, ADR-0026): `security.containment.applied{env_handle, policy_version_id, effective_policy_hash, backend, isolation_class, enforcement_evidence, lowering_loss_ref, probes_ref}` at attach (WS-B5's `action.environment.attached` references it, CF-WS-H4-05); `security.egress.requested{effect_id, tool_call_id, protocol, host_norm, port, method?, bytes_out_estimate?}`; `security.egress.decided{…EgressDecision, latency_ms}`; `security.containment.violated{point, backend, kind ∈ {fs_read, fs_write, exec, net, unix_socket, syscall, privilege}, subject (path | host | syscall), evidence_kind ∈ {kernel_log, exit_signal, mediator, heuristic_output}, effect_id?}` (Codex `violation.rs`; heuristic detections are labelled as such and never authorise); `security.containment.amended{from_version_id, to_version_id, diff, basis, endorser, effect_id, scope}`; `security.containment.unverified{field_group, reason}`. All carry the mandatory `ProvenanceRecord` (ADR-0035 decision 4 extended); all are `durability = durable`, minimum `observability_level = events`; hosted rows (`container-installed` mechanism) carry `origin = participant`. Accounting: `network.calls` (ADR-0039) is posted per allowed request; proposed registered `ext` dimensions `hh.net.bytes_out`, `hh.net.bytes_in`, `hh.egress.decisions.{allowed, denied, asked}`, `hh.containment.violations` (CF-WS-H4-04); `charged_to = subject` for the agent's traffic and `instrument` for probes and Lab detectors (T-LCD-15). Class-scoped metrics: `containment.amendments_per_run`, `egress.ask_rate`, `egress.approval_rate`, `containment.violation_rate`, `classifier.miss_rate{requires_observability: end_state}` — all `MetricDeclaration`s computed from these events (ADR-0044/0045).

### 6.6 Composition with capabilities (WS-H1): floor and ceiling

`authorize(p)` (ADR-0035 checks 1–7) gains one precondition and one input: **precondition** — `ContainmentReport.enforcement_evidence ≠ unknown` for the field groups `EffectClass(p).domain` touches (`fs_write → fs`, `net_egress → net`, `exec/spawn_process → proc`, `secret_access → fs.mounts(masked) ∧ net.credential_bindings`), else `ContainmentUnverified`; **input** — `admits(effective_policy, p) → admitted | refused{reason} | amendable{amendment}`. Decision rule: `allow` requires *both* `Permission` coverage (ceiling; ADR-0035 check 2) *and* `admitted` (floor); `refused` ends as `action.effect.refused{reason: containment}` **without** consulting Π or asking, unless `amendment.strict = false` and the proposal is re-issued as a `permission_request` effect (§6.7). Containment also feeds `kernel_assessed` in ADR-0031 decision 2 (the "writable-root containment, network host policy" sources named there): `scope = workspace_local` may be assessed only when the effect's paths ⊆ `fs.write.allow` roots of the handle and `net.mode = none` (or the effect is `read_only`); otherwise `external`. Permissions never *loosen* containment and containment never *grants* a Permission: a definition with `net.mode = mediated` and no `net_egress` Permission still cannot egress (ceiling), and a `net_egress` Permission on a `none` environment is a validation warning at `seal` (`PermissionUnreachable`) so authors do not ship dead grants. Delegation (ADR-0035 check 7) carries the effective policy down: a child environment's policy is `effective(parent_policy ⊓ child_layer)` — never wider.

### 6.7 The escape hatch as an endorsed amendment

A run-time widening of containment (Codex "run without sandbox", Claude Code `dangerouslyDisableSandbox`, Harbor phase switch, Claude Code "yes, and don't ask again") is modelled as one operation: `amend(policy_version_id, diff: ContainmentDiff, basis, endorser, effect_id?) → new version | ContainmentWidening | BasisNotAllowed | StrictMode`. Validity: `basis ∈ amendment.allowed_bases`; `authority(endorser) ≥` the layer being loosened (`principal` for run-level; `definition` via `seal` for definition-level; `policy_rule` for Lab phase plans sealed in the experiment design); a `delegate` origin never endorses (ADR-0035) — the model's retry parameter is a *proposal* that the kernel turns into an `ask`; `strict = true` ⇒ ignored (`StrictMode`) and ledgered. Every amendment is a `security.containment.amended` event, counts against the approvals budget, and produces a new `version_id` so `configuration_version_id` changes — a replicate that was amended is **not the same configuration** and results rows must record `containment_amended = true` (WS-J5), mirroring `depends_on_revoked` (ADR-0037: annotated, never hidden). Default: `strict = true` for Lab runs; interactive runs may set `strict = false` with `session_cache = true`.

### 6.8 Acceptance-criteria sketch — escape and exfiltration tests (T-CON)

Each is a Lab fixture with `charged_to = instrument`, run at Stage 3 against every backend the readiness report lists; "pass" means the *boundary* held, never that a model behaved.

- **AC-H4-01 Write containment.** Inside a `WritableRoot`, a write to `read_only_subpaths` and to any `KERNEL_PROTECTED` name (VCS hooks, harness config/skills/hooks dirs) fails; a write via a symlink whose target is outside the root fails (symlink-before-validate); on each backend the failure is observed as `security.containment.violated{evidence_kind}` and never as a silent success. (C0/Stage 1 static; Stage 3 executable)
- **AC-H4-02 Read containment and credential masking.** `fs.read.deny` paths (default: credential stores) are unreadable; a `masked` mount yields the sentinel; the sentinel never appears on the wire except substituted at the mediator for a host in *that* credential's binding; a sentinel sent to another allowed host arrives unchanged (anti-laundering). (C0/Stage 2 with WS-H3)
- **AC-H4-03 `none` mode.** TCP `connect`, UDP `sendto`, raw sockets, name resolution and ICMP all fail from inside; `io_uring`, `ptrace`, `process_vm_*` denied; only `AF_UNIX` to bridged sockets (if any) succeeds; probes recorded as `probed`. (C0/Stage 1)
- **AC-H4-04 `mediated` mode decision order.** Fixtures for: deny rule beats allow rule for the same host; `*.apex` does not match apex; global `*` in deny is rejected at validation; trailing-dot, mixed-case, bracketed/zone-ID IPv6 spellings normalise identically; public hostname resolving to a private address is denied (`non_public_guard`); CONNECT to a non-listed port denied; `methods_default` blocks `POST` in limited mode; unmatched host yields `default_unmatched`; every decision is a `security.egress.decided` event with the right `source`. (C0/Stage 2)
- **AC-H4-05 Approved-host residual.** AgentDojo-style `security(pre_env, post_env)` fixture: an allowed host with an upload endpoint; assert that (i) a credential bound to another host is not injected, (ii) `POST` is denied under `methods_default`, (iii) the run's `residual_channels` names `approved_host_body`, and (iv) with WS-H2's flow check enabled (C2) the transfer of `readers ⊉ destination` content is refused. The C0 assertion is (i)–(iii); (iv) is C2. (Stage 3 / C2)
- **AC-H4-06 Attribution.** A connection without an attribution token, or with a token for another environment, is denied; every `security.egress.decided` has an `effect_id` resolvable in the ledger; `network.calls` per effect equals allowed decisions. (C0/Stage 2)
- **AC-H4-07 Escape hatch.** A model-issued "disable sandbox" parameter produces `security.permission.requested` (or `StrictMode` under strict) and never an amended policy without a `security.containment.amended` event whose endorser is ≥ `principal`; exhausting the approvals budget converts the next hatch `ask` into `deny`; an amended replicate is annotated in results. (C0/Stage 2)
- **AC-H4-08 Fail-closed.** With the helper absent, the backend unsupported, or `enforcement_evidence = unknown` for a required field group, every non-`read_only` effect is `refused{ContainmentUnverified}` and the run records `security.containment.unverified`; a declared `on_unavailable = warn_and_degrade` run stamps the degradation on every event. (C0/Stage 1)
- **AC-H4-09 Layered meet.** Property test: for random layer stacks, `effective` never contains an allow absent from every higher-authority layer, never drops a deny, never removes a `KERNEL_PROTECTED` name, and refuses `ContainmentWidening` for any loosening from a layer below `principal`. (C0/Stage 1)
- **AC-H4-10 Lowering loss.** For each backend, `ContainmentReport.lowering_loss` lists every field the backend cannot enforce (e.g. unix sockets without a syscall filter; read restriction under the legacy filesystem backend; chmod/chown under Landlock) and the Lab stratifies results on it; a loss on a field the effect relies on ⇒ AC-H4-08 behaviour. (C0/Stage 1–3)
- **AC-H4-11 Utility measurement.** Same task, same `eval_budget` (ADR-0046), arms {no sandbox + prompts, `none`, `mediated` strict, `mediated` with hatch}: report success, `approvals.requested/granted`, `egress.ask_rate`, `containment.amendments_per_run`, wall time; S-053's "84% fewer prompts" is the pre-registered hypothesis, not an assumption. (C0/Stage 3, T-LCD-14)
- **AC-H4-12 Escape suite.** A SandboxEscapeBench-class suite (nested boundary, flag outside) runs against each `isolation_class` configuration the Lab ships with **no known vulnerabilities added**; any capture is a readiness blocker for that class; the suite's cost is `instrument`. (C1/Stage 4)
- **AC-H4-13 Hosted participants.** A `container-installed` hosted participant runs under the same effective policy; its rows carry `origin = participant`, `enforcement_evidence` as reported by the mechanism, and `n/a{observability}` for per-effect attribution where the mechanism cannot supply `effect_id`. (C1/Stage 4, T-LCD-06/-15)

## 10. Confidence

**High** for the policy record shape and deny-wins layered meet: three independent enforcing implementations read in source (Codex, sandbox-runtime, Harbor) plus Landlock/Seatbelt semantics agree on read-deny/write-allow/net-allow with deny precedence, and ADR-0024/0034 already ratify monotone layering. **High** for "containment is the floor, classifiers/approvals are advisory": production telemetry (S-053), Codex's `sandbox_tags.rs` rule, and ADR-0035 all state it; no audited system contradicts it. **High** for fail-closed and per-decision audit: Codex's helper protocol fails closed on managed networking and audits every host decision; the Lab's `configuration_id` semantics require it. **Medium-high** for the enforcement-evidence tri-state and the escape hatch as endorsed amendment: precedented in parts (`ProcessSandboxType`, strict sandbox mode, `ApprovedForSession`) but the integrated contract is novel and its ergonomics in a Lab are unmeasured until AC-H4-11. **Medium** for the egress rule fields `methods`/`credential_bindings` closing enough of the approved-host residual to matter: the 24/25 figure says the residual is large; the closers are C2 (H2) and optional (TLS termination), and the dossier says so. No C0 recommendation rests on a `provisional` number; S-WS-H4-09/-10/-11 supply existence of failure modes only.
