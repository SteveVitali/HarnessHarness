## 1. Scope & boundary

This workstream decides **what a tool *is* inside HarnessHarness as a registry object** — the `ToolCapability` record ratified as an HIR/1 entity (ADR-0016 item 6) completed with its metadata fields and invariants — and **what the registry that stores, versions, resolves, imports and binds such records promises**. Concretely it fixes: (a) the semantic-vs-surface field split of `ToolCapability` so one record compiles to many model-facing shapes (T-LCD-01/-10); (b) the metadata families the brief names — effects, preconditions, cost, risk, permissions, observability, result type — each defined in terms of a ratified neighbour (effects → ADR-0016 `EffectClass`; risk → ADR-0031 derived risk class; permissions → ADR-0016 `Permission` grants and WS-H1 authority handles; cost → ADR-0039 kernel dimensions; observability → ADR-0042/0043/0044 spans, measurement points and sink policy; result type → ADR-0033 authority ceilings); (c) the registry operations (register, resolve, snapshot, import, refresh, bind, project, estimate) over ADR-0036/0037 identity and name-history rules; (d) how MCP-listed tools enter as *one source among several* with lifted, `unverified` provenance (ADR-0021, ADR-0034 P7); (e) acceptance criteria and stage placement.

It explicitly leaves to neighbours: **WS-E2** — synthesis of model-specific surfaces, composite/wrapped surfaces, semantic-equivalence evidence beyond what the registry stores (ADR-0022 E1–E7; OQ-066); **WS-E3** — catalog search ranking, deferred loading policy, large-catalog retrieval (this dossier only fixes the *hooks*: the search-text projection and the exposure-mode field); **WS-E4** — MCP/ACP/A2A transports and the client/server edges (this dossier fixes the *record* an MCP listing lifts to, not the wire); **WS-E5** — executors, sandbox helper, `dedup_support`, detached processes (this dossier fixes the *binding requirement* a capability record declares, not the executor); **WS-H1** — the decision function and handle table (this dossier fixes which capability fields the kernel reads); **WS-H5** — extension trust and `pin` attestations for third-party tool servers; **WS-C3** — the profile rules that write surface fields; **WS-A4** — the compiler stages that lower a capability into a tool table row and a model surface. Nothing here names a language, runtime, package or library; ADR-0050 §8 is respected (precedent paths are evidence only).

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Every audited harness stores a tool as a *runtime object* whose identity is its model-facing name, and hangs metadata off that name.** Codex's registry is `IndexMap<ToolName, RegisteredTool{runtime, exposure}>` keyed by a namespaced name (`registry.rs` L287–330; `ToolName.with_default_namespace()`); opencode's `Tool.Def{id, description, parameters, jsonSchema?, execute, formatValidationError?}` (`tool.ts` L60–75) is keyed by `id`; OpenHands `_REG[name] = resolver` warns on duplicate names but keeps the last (`registry.py` L140–143); goose prefixes MCP tool names with `extension__tool` and *parses the prefix back* to find the owner (`extension_manager.rs` L299–321). Three consequences the audit makes concrete: (i) renaming a tool is an identity change everywhere (the T-LCD-10 anti-pattern), (ii) collisions are handled by policy at registration (Codex records `first_collision`), and (iii) no audited registry stores *semantic* metadata independent of the surface — effects, cost and permissions live in side tables keyed by the same name (goose `PermissionConfig{always_allow, ask_before, never_allow}: Vec<String>` of names, `config/permission.rs` L29–31; Claude SDK `PermissionRuleValue{tool_name, rule_content}`, `types.py` L117–121). The registry this dossier specifies must therefore key by `semantic_id`/`version_id` (ADR-0036) and treat the name as a name-history entry (ADR-0037 I2) — a departure from every precedent, motivated by ratified decisions rather than by any audited system.

**F2 — Effect metadata exists in three shapes across the audit, and only one of them is treated as trustworthy.** (a) MCP-shaped hints: OpenHands `ToolAnnotations{readOnlyHint=False, destructiveHint=True, idempotentHint=False, openWorldHint=True}` with *conservative defaults* (`tool.py` L215–249); goose stamps the same four on its own platform tools (`platform_tools.rs` L40: `read_only(false).destructive(true).idempotent(false).open_world(false)`). (b) A closed *kind* enum: gemini-cli `Kind = {Read, Edit, Delete, Move, Search, Execute, Think, Agent, Fetch, Communicate, Plan, SwitchMode, Other}` with `MUTATOR_KINDS = {Edit, Delete, Move, Execute}` and `READ_ONLY_KINDS = {Read, Search, Fetch}` used for parallelism and confirmation (`tools.ts` L1104–1131). (c) A tri-state resource declaration: OpenHands `DeclaredResources{keys, declared}` where `declared=False` means "I haven't thought about it" and `declared=True, keys=()` means "I have, and I'm safe" (`tool.py` L251–282). Only (b) — a closed enum owned by the harness author — is used for authority decisions; (a) is used for display and parallelism, and for MCP-origin tools it is explicitly untrusted (MCP spec: "clients **MUST** consider tool annotations to be untrusted unless they come from trusted servers", `tools.mdx` L305–306; `schema.ts` L1904–1910). This is direct mechanism evidence for the ratified split: `EffectClass{domain, attributes}` is the authoritative declaration (ADR-0016), hints are a projection (CF-041/CF-047), and lifted hints carry `authority = unverified` (ADR-0034 P7). The tri-state `resources` field survives unchanged.

**F3 — Result handling is a contract with its own metadata: truncation, offload, structured output, and error typing.** opencode wraps every tool so that outputs above `MAX_LINES = 2000` / `MAX_BYTES = 50 KiB` are written to a truncation directory (7-day retention) and the model sees a preview plus a path (`truncate.ts` L11–40; `tool.ts` L99–125); invalid arguments become a typed `InvalidArgumentsError` whose message is the model-facing "rewrite the input" prose (`tool.ts` L24–37). OpenHands coerces executor output into a declared `observation_type`, validates `structured_output` against a `response_schema` (JSON-Schema draft 2020-12), and rejects untyped output (`tool.py` L560–640). MCP separates `content` from `structuredContent` validated by `outputSchema`, and requires clients to "validate tool results before passing to LLM" (`tools.mdx` L787–815). Anthropic's guidance adds a `response_format ∈ {concise, detailed}` parameter (206 vs 72 tokens in its example), pagination/range/truncation defaults, and "specific and actionable" errors (S-037). Cursor reports categorising tool failures (`InvalidArguments`, `UnexpectedEnvironment`, `ProviderError`) as the lever that pushed "all tool calls to at least 2 or often 3 9s of reliability" (S-049). Consequence: a capability record must declare an **observation contract** (result schema, size class, offload rule, error classes) so that ADR-0022 E5 (error-class surjectivity) and E6 (result-observation adequacy) are checkable and ADR-0029 payload offload applies uniformly — and `Observation.authority` for the result is fixed by ADR-0033 from the capability record's `world`/schema, not by the tool.

**F4 — Permission metadata is *never* stored on the tool in mature harnesses; it is stored on rules that reference the tool and are evaluated at call time on canonical arguments.** goose asks per request with `Permission ∈ {AllowOnce, DenyOnce, …}` routed through a per-turn confirmation state machine (`tool_confirmation_coordinator.rs` L1–70) and, notably, uses an LLM judge only to *detect read-only requests* from a set of pending calls — a raise-only "may skip confirmation" signal with untrusted instructions kept out of the judge's system prompt (`permission_judge.rs` L41–181). Claude SDK rules are `(tool_name, rule_content)` pairs with `behavior ∈ {allow, deny, ask}` plus `PermissionUpdate{addRules|replaceRules|removeRules|setMode|addDirectories|…}` and a `ToolPermissionContext{blocked_path, decision_reason, agent_id}` delivered to a `can_use_tool` callback (`types.py` L113–260). opencode evaluates `(permission, pattern, ruleset…) → {allow, deny, ask}` per call and derives `visibleTools` and `disabled` tool sets from a `*`-deny rule (`permission/index.ts` L28–216). Codex routes a "policy-stage" review context per call (`approvals.rs` L1–60). The convergent shape — *tool declares what it does; policy decides whether the holder may* — is exactly ADR-0016 (`Permission` grants by domain + scope; `authorizes` edge) plus WS-H1 (handles evaluated on `SurfaceArgMap` parameters). What no precedent supplies, and this dossier adds, is a **declared mapping from capability parameters to scope kinds** (which parameter is a path, a host, a recipient, a spend amount) so the kernel's `ResourcePattern` match (H-5) is total rather than tool-specific code.

**F5 — Model-conditioned tool shape and exposure are runtime/profile decisions in every audited system, taken *outside* the tool definition.** Codex selects `apply_patch` per `model_info.apply_patch_tool_type` (`spec_plan.rs` L1255–1258; `models.json` rows carry `"apply_patch_tool_type": "freeform"`), and the same registry entry carries an `exposure ∈ {Direct, Deferred, DeferredModelOnly, …}` with `search_info` derived from the spec (`tool_executor.rs` L51–130; `tool_search.rs` L18–32) — deferred tools are still *registered*, only their model-visible listing changes. opencode filters `apply_patch` vs `edit/write` by a model-id substring test (`registry.ts` L340–350) and lets plugins rewrite `description/parameters` through a `tool.definition` hook. gemini-cli's `ToolBuilder.getSchema(modelId?)` returns "a model-specific schema" (`tools.ts` L409–416). Cursor: "we provision each model with the tool format it had during training" (S-049). Anthropic's `defer_loading: true` and `input_examples` (S-040) and Codex's `ResponsesApiTool{strict, defer_loading}` (`responses_api.rs` L32–44) show that strictness, deferral and examples are provider-request fields. Consequence (T-LCD-01/-10 + ADR-0019 closed-world rule): `name, description, examples, strictness, error format, exposure hint` are **surface** fields written by profile rules; exposure *selection* per turn is a run-time act over compiled identities; none of these enters `semantic_id`.

**F6 — Schema normalisation is model-conditioned and lossy, so the canonical schema must be stored once and lowered per target.** goose rewrites `oneOf/anyOf` unions of string `const`s into `enum` (≈9× smaller and "rejected outright by strict validators (notably Moonshot's)"), inlines trivial `$defs`, and refuses to touch dialects that predate `const` (`tool_schema_normalize.rs` L1–80). opencode converts plugin-supplied validator objects to JSON Schema and strips boolean `exclusiveMaximum/Minimum` (`registry.ts` L395–445). Codex notes that `strict: true` requires every property to be `required` (`responses_api.rs` L35–38). MCP's `inputSchema` admits full JSON Schema 2020-12 including `$ref`/`if`/`then` (`schema.ts` L1985–1999). Consequence: the registry stores one canonical schema document with its declared dialect; narrowing for a target is ADR-0022 E3 `narrowed` loss recorded by the compiler (WS-A4 §6.5), never a mutation of the record.

**F7 — Sources of tools are heterogeneous and each source carries a different trust and lifecycle.** OpenHands distinguishes built-in classes resolved by `create(**params)` from registered instances, with an `is_usable()` environment check (`registry.py` L95–205) and a `Tool{name, params}` spec used only for server-side instantiation (`spec.py`). goose has platform tools, MCP extensions (with `__` prefixing, "first-class" unprefixed extensions, hidden extensions) and a `TRUSTED_TOOL_UPDATE_META_KEY` for trusted in-place updates (`extension_manager.rs` L190, L397–416). Codex has native handlers, dynamic tools, hosted specs (`web_search` is a provider-executed tool, `hosted_spec.rs`), MCP tools and code-mode nested tools. Consequence: `CapabilitySource` is a closed sum `{native_variant, procedure(composite), mcp_listing, provider_hosted, participant_supplied}` with per-source default provenance and lifecycle (§6.2), and the same record kind covers all of them.

**F8 — A listed tool can change under a running harness, and only content-addressed versions make the change visible.** MCP servers may emit `notifications/tools/list_changed` and clients may cache listings for `ttlMs` (`schema.ts` L1081–1096, L1895–1899; `tools.mdx` L59–73, L238–271); Codex caches MCP tool listings per turn; goose refreshes per session (`get_all_tools_cached`). The "rug pull" class (S-310/-05/-06, `provisional` for the numbers, but the mechanism follows directly from the protocol: descriptions are unauthenticated strings a client re-fetches) is the failure mode: an approved tool's description or schema is mutated after approval and the client keeps treating it as the same tool. ETDI proposes signed, versioned definitions; MCP-Scan pins hashes. Under ADR-0036/0037 the defence is free: an imported listing hashes to a `version_id`; a changed description is a new version with `supersedes{reason: edit}`; the run manifest pins the old `version_id`; `verify_resume` (ADR-0025) reports the change; and a changed listing never silently inherits a `pin` endorsement (ADR-0035 basis `pin` names a `subject_hash`).

**F9 — Observability of tool calls has a shared vocabulary that the registry can bind to without inventing one.** OTel GenAI defines an `execute_tool {gen_ai.tool.name}` span with required `gen_ai.tool.name`, recommended `gen_ai.tool.type ∈ {function, extension, datastore}`, `gen_ai.tool.call.id`, `gen_ai.tool.description`, and opt-in `gen_ai.tool.call.arguments/result` explicitly flagged "may contain sensitive information" (S-228 L1135–1215). opencode stamps `tool.name`, `session.id`, `message.id`, `tool.call_id` on a `Tool.execute` span (`tool.ts` L84–90). Consequence: a capability record's observability metadata is *not* a telemetry schema (ADR-0042: exporters are subscribers of the ledger) but a **content-class declaration** for its arguments and results (public / sensitive / secret-bearing) that ADR-0044 `SinkPolicy.content_classes` and redaction consume, plus the `gen_ai.tool.type` value it lowers to.

**F10 — Cost metadata is useful for scheduling and selection but must not be confused with accounting.** PeakBench (S-369, `provisional`) shows that exposing measured resource profiles to the planner reduces overflows; Anthropic's tool-search figures (85 % token reduction; S-040) and HEART's cost claims (S-076) are cost effects of *exposure policy*, not of the tool. ADR-0039 fixes that all accounting is measured at the producing event and totals are views. Consequence: `cost_model` on a capability record is a **declared estimate with provenance and confidence**, consumed by WS-E3 (what to reveal), WS-F4 (value-of-compute) and WS-D1 (result-size planning), and never by `control.budget.consumed` (which only records measured amounts).

## 5. Disconfirming evidence & negative results

**Against a semantic record separate from the provider schema ("the schema *is* the tool").** Every audited harness stores the JSON Schema as the tool, and Hsieh et al. show the description is what the model learns from; a semantic layer above it could be dead weight that drifts from the schema. *Why this does not overturn:* the semantic record *contains* the canonical schema (§6.2 `input_schema`); what is separated is the model-facing rendering (name, description wording, examples, strictness, dialect narrowing), which the audit shows is already rewritten per model in Codex, opencode, gemini-cli and Cursor (F5, F6). The cost is one indirection (`SurfaceArgMap`, ADR-0022 E2); the benefit is T-LCD-01/-10 and one record lowering to MCP, native function calling and provider dialects (OpenHands already does the multi-target half, F7). Drift is prevented by construction: surfaces are compiled from the record, never edited beside it.

**Against declared effects at all (misdeclaration is the norm).** MCP defaults are conservative *because* authors do not declare; goose stamps `destructive(true)` on a scheduler tool; OpenHands defaults `destructiveHint=True`. A declared `EffectClass` may be wrong in either direction. *Why this does not overturn:* ADR-0031 already makes the kernel's assessment monotone (`effective_risk_class = max_by_danger(kernel_assessed, projected(declared))`; unknown ⇒ most dangerous); a *native* declaration is `definition`-authority content the harness author is accountable for at `seal`, and a *lifted* one is `unverified` and cannot lower anything. The declaration's job is coverage checking (V-EFF) and default-deny scoping, not truth about the world; E4 differential tests (ADR-0022) catch native misdeclaration at Stage 3 for closed-world tools.

**Against a declared cost model.** Prices drift, token counts depend on the profile's tokenizer, and PeakBench is one preprint. *Why this does not overturn:* the model is optional, carries `confidence` and `provenance`, is refreshed from measured ledger percentiles (`measured_ref`), and is barred from accounting by ADR-0039. Its absence yields `unknown`, never 0 (ADR-0045 rule). The alternative — no size/latency expectation anywhere — leaves WS-E3/D1/F4 with nothing to plan on.

**Against registering MCP tools as first-class capability records.** MCP tools are ephemeral (per-session listings, `ttlMs`, `list_changed`); versioning each listing bloats the registry and pins the lab to server states it cannot reproduce. *Why this does not overturn:* the run manifest must reference *something* immutable for R1+ reproducibility (ADR-0038), and an unpinned MCP tool is exactly the `unpinned[]` claim the bundle records. Listing versions are small (a hash of the canonical `Tool` document); GC follows ADR-0037 S8 (only executed/published versions are retained). The rug-pull defence (F8) is only available if listings are versioned.

**Against a closed `preconditions` sum.** Real preconditions are arbitrary (a file must be a git repo; a token must be valid; a browser tab must exist); a closed sum forces `Opaque` predicates that the compiler cannot check. *Why this does not overturn:* the sum covers what *can* be checked statically or at `prepare` (parameter domain inclusion, path containment, environment requirement, validator reference); anything else is a `Validator` reference evaluated at `prepare` (ADR-0030 `BaselineUnavailable`-style refusal), and E3 marks it `n/a (runtime_validator)` — declared, never silent. This matches WS-A3 F9: effect checks are graph queries, not a type system.

**Against putting `scope_bindings` on the capability (H1 could parse arguments itself).** Codex parses shell commands and canonicalises paths in kernel code (`safety.rs`, cited by H1); a declared mapping could be gamed by a lifted tool. *Why this does not overturn:* the kernel keeps its deterministic assessors (H1 check 3) and treats a lifted `scope_bindings` as `unverified` — such a capability record has *no* scope-bearing parameters the kernel trusts and therefore matches only `*`-scope grants (default-deny by construction). For native tools the mapping is `definition` data checked by E2's totality property; it replaces per-tool kernel code with a declared, diffable, ablatable field (ADR-0024 ladder).

**Negative results from the audit.** No audited registry (Codex, goose, opencode, OpenHands, gemini-cli, Claude SDK) keys tools by content hash, versions MCP listings, separates semantic identity from name, declares scope-bearing parameters, or carries a cost model; only gemini-cli owns a closed effect-kind enum. The registry contract in §6 is therefore `no-precedent / novel` *as a whole*, while each field maps to a precedent listed in 4c.

## 6. Recommendation for the spec

### 6.1 Position of the registry

The **tool registry** is a C0 kernel service (MUST-code, ADR-0024) that stores immutable **capability records** (`ToolCapability` HIR nodes plus registry-only envelope fields), resolves them by ADR-0036/0037 identity and name history, imports listings from non-native sources, snapshots the closure a definition references (`registry_snapshot_id`, ADR-0038), and answers the compiler (`link`: tool table rows), the kernel (`authorize`: declared effects, scope bindings, precondition domains), executors (`bind`), the context builder and WS-E3 (search projection, exposure hints, observation contract) and the Lab (catalog views). It never renders a surface (the profile compiler does), never decides authority (WS-H1 does), never measures cost (ADR-0039 events do), and never executes (WS-E5 does). The **registry policy** — which capabilities a definition admits, which sources are trusted, how collisions and refreshes are handled — is a registered **component class** (`tool_registry_policy`) receiving `(ModelProfile, ResourceAccount)` per T-LCD-08; the store itself is not pluggable.

### 6.2 Data model — the capability record (completes ADR-0016 item 6)

`ToolCapability` (HIR/1 entity, plane 2; common node fields `version_id, semantic_id, kind, home_plane, dialect, version, provenance, ext` per ADR-0015/0016).

**Semantic fields** (hashed into `semantic_id`):
- `purpose: Text` — what the tool does, for humans and for search; a `Text` leaf with owner/authority (T-LCD-02); counts as `tool_purpose` in the opacity report.
- `input_schema: SchemaDoc{dialect: SchemaDialect, document}` — the canonical parameter schema (JSON-Schema-class, dialect declared; root `type: object`); the *only* schema stored. Target narrowing is compiler loss (ADR-0022 E3), never a second schema. Per ADR-0024 this is a declaration, not code.
- `output_schema?: SchemaDoc` — structured result shape (MCP `outputSchema` / OpenHands `observation_type` precedent); required for `closed` shape endorsement (ADR-0035 `validator` basis; OQ-106).
- `effects: set<EffectClass>` — non-empty, or the literal `pure` (which lowers to `readOnlyHint`, `world = closed`); each `EffectClass = {domain: EffectDomain, attributes: EffectAttributes}` per ADR-0016; **no separate `risk_class`, `idempotent`, `reversible` or `read_only` fields** — the effect risk class is derived (CF-104, §6.5).
- `preconditions: [PreconditionDomain]` — closed sum (answers the §6.9 obligation): `param_domain(schema_fragment)` (a narrowing of `input_schema` the capability requires — E3 inclusion check) | `path_within(param_path, ResourcePattern | "writable_roots" | "environment_root")` | `host_within(param_path, HostPattern | "definition_allowlist")` | `env_requires(EnvironmentRequirement{kind ∈ {binary, service, network_class, filesystem_feature, display}, selector})` | `state_requires(Ref<Validator>)` | `capability_requires(Ref<ToolCapability>)` (composite dependency). Static kinds (`param_domain`, `path_within`, `host_within`) are checked by the compiler and by the kernel's argument analysis; `env_requires` is checked at `bind`; `state_requires` at `prepare` (ADR-0030); `capability_requires` at `link`. An unmet static precondition is `PreconditionViolated` (a refusal, ADR-0030 `refused`), never a warning.
- `scope_bindings: [{param_path, scope_kind ∈ {fs_path, host, recipient, spend_amount, secret_ref, process_target, memory_scope, resource_key}, canonicalization ∈ {absolute_path_after_symlink_resolution, host_port, principal_ref, money, identity}}]` — declares which canonical parameters (post-`SurfaceArgMap`) carry the scope that a `Permission.grants[].scope: ResourcePattern` and an authority handle (WS-H1 H-5) match against. Totality rule: every `EffectClass.domain` in `effects` whose grants are scoped (`fs_read/fs_write` → `fs_path`; `net_egress` → `host`; `message_human` → `recipient`; `spend` → `spend_amount`; `secret_access` → `secret_ref`; `spawn_process` → `process_target`; `memory_write` → `memory_scope`) has at least one binding, or the record carries `scope_bindings_unknown = true` and can only be covered by unscoped (`*`) grants.
- `resources: {declared: bool, keys: [ResourcePattern]}` — OpenHands tri-state, unchanged; `declared = false` ⇒ serialise with itself and treat as `world = open` for the `openWorldHint` projection (WS-A4 §6.5 rule kept).
- `observation_contract: {result_schema_ref?: (= output_schema), content_class ∈ {public, sensitive, secret_bearing}, size_class ∈ {small, bounded(bytes), unbounded}, offload_policy ∈ {inline, offload_above(bytes), always_offload}, streaming: bool, error_classes: [ErrorClass]}` — `ErrorClass` is a closed sum `{invalid_arguments, precondition_violated, not_found, conflict, timeout, environment_unavailable, permission_refused, rate_limited, partial_application, executor_error}` so ADR-0022 E5 (surjectivity) is checkable; `offload_policy` defaults to ADR-0029's class threshold. The result's `Observation.authority` is **derived**: `environment` iff `∀e ∈ effects: e.attributes.world = closed ∧ output_schema is closed ∧ source ∈ {native_variant, mcp_listing with pin}` else `external`; lifted/unpinned sources yield `unverified` (ADR-0033 minting rules; ADR-0034 P7) — the capability record never sets it.
- `cost_model?: {declared: partial map<KernelDimension, Estimate{kind ∈ {constant, per_unit(param_path, unit), distribution(p50, p95)}, value, unit, confidence ∈ {exact, bounded, estimate, unknown}, provenance}>, measured_ref?: ContentAddress}` — dimensions are ADR-0039 kernel counters/gauges (`tokens.output.visible` for result size, `time.wall_ms`, `spend`, `network.calls`, `env.active_ms`); `measured_ref` points at a ledger-derived percentile view (`project(runs, tool_cost_profile)`). Invariant: never read by `control.budget.consumed`; absent ⇒ `unknown`.
- `execution_requirement: {environment_class ∈ {kernel_internal, sandbox_helper, environment_handle, remote_server, provider_hosted}, isolation_min: IsolationLevel, interrupt: {supported, unsupported, unknown}, dedup_support_required?: {none, executor, target}, concurrency ∈ {serial, parallel_safe, resource_keyed}}` — what a binding must satisfy (WS-E5/B5 supply the executor); `provider_hosted` marks tools executed by the model provider (Codex `web_search`), whose effects are still declared and whose results are `external`.
- `source: CapabilitySource = native_variant(ComponentVariantRef) | procedure(Ref<Procedure>) | mcp_listing{server_ref, listing_hash: ContentAddress, tool_name_on_server, listing_ttl_ms?, imported_at} | provider_hosted{provider_tool_kind} | participant_supplied{participant_ref}` — closed sum; default provenance per source (§6.4).
- `exposure_hint: {default ∈ {direct, deferred, on_demand_only}, search_text_projection: derived}` — a *hint* consumed by WS-E3's selection; the per-turn selection is a run-time act over compiled identities (ADR-0019 closed-world rule), so this field affects no identity of what is delivered.

**Surface fields** (profile-owned; excluded from `semantic_id`; edited only by `SurfaceEdit`, ADR-0017): `name`, `namespace`, `description_template: Text`, `argument_names_and_order`, `examples: [InputExample]`, `error_format`, `result_renderer`, `strictness`, `schema_dialect_narrowing`, `exposure_mode ∈ {primitive, composite_member, hidden}`, `display_title`, `icon_ref`. Precedent for each: Codex `ResponsesApiTool.strict/defer_loading`, Anthropic `input_examples`, goose `__` namespacing, OpenHands `to_openai_tool(add_security_risk_prediction)` (a *surface* extra field), MCP `title/icons`.

**Registry envelope** (not HIR fields; stored beside the node): `registered_at: EventRef`, `registrar: ProvenanceRecord`, `trust_record_ref` (WS-H5), `name_history_ref` (ADR-0037 I2), `dialect_range`, `status ∈ {active, deprecated, yanked}`, `usability: {probe_ref?, verdict ∈ {usable, unusable(reason), unknown}}` (OpenHands `is_usable` precedent; a `bind`-time probe result, never a semantic field).

**Invariants (kernel `validate` + registry `register`; errors, never warnings):** V-E1-1 `effects ≠ ∅ ∨ pure`; V-E1-2 every `EffectClass` uses the ADR-0016 closed sums (`UnclassifiedKind` otherwise; extension by dialect bump only — OQ-055); V-E1-3 `scope_bindings` totality or `scope_bindings_unknown`; V-E1-4 every `param_path` in `preconditions`/`scope_bindings` exists in `input_schema` (`UnmappedParameter`); V-E1-5 no field's type is a model identity, provider role or provider dialect outside `surface` (T-LCD-01); V-E1-6 `purpose` and `description_template` are `Text` leaves with provenance (T-LCD-02; ADR-0033 R-TEXT: a lifted description is `external`/`unverified`); V-E1-7 `source = mcp_listing ∧ trust_record = none ⇒ provenance.authority = unverified` on `effects`, `preconditions`, `scope_bindings`, `cost_model` (ADR-0034 P7); V-E1-8 `cost_model` never carries `exact` unless `measured_ref` is present; V-E1-9 `semantic_id` excludes every surface field, `exposure_hint`, `cost_model.measured_ref`, provenance and the registry envelope (T-LCD-10); V-E1-10 a `procedure` source references a `Procedure` whose `effects` (derived) equal the record's `effects` (ADR-0022 composite rule; C2).

### 6.3 Registry operations (interface-contract sketch; language-agnostic; T-LCD-12)

- `register(record: ToolCapability, registrar: ProvenanceRecord, trust_record?) → {version_id, semantic_id} | ValidationErrors | TrustDenied` — validates (§6.2), computes ids (ADR-0036 `identify`), stores immutably (ADR-0037 I1); idempotent on identical canonical bytes; emits `lifecycle.capability.registered{version_id, semantic_id, source_kind, registrar}` (proposed WS-B1 class, category `lifecycle`).
- `publish(namespace, name, version_id, label?, supersedes?, status) → NameHistoryEntry` — delegates to ADR-0037 `publish`; a publish whose `HirDiff` vs `supersedes` has `authority_delta = widening` (effects grew, `world` opened, `mutability` rose) requires `provenance.origin = human` + attestation (L4 rule reused; for capabilities this is the "tool got more dangerous" gate).
- `resolve(selector: NameSelector | semantic_id | version_id, registry_snapshot_id?, mode ∈ {execute, audit, reproduce}) → VersionedRef<ToolCapability> | Unresolved | Ambiguous | Revoked | Stale{depends_on_revoked}` — ADR-0037 S3 semantics; `mode = execute` never returns yanked/revoked heads.
- `lookup(ref) → CapabilityRecord`; `history(semantic_id) → DAG` (ADR-0037 `lineage`).
- `catalog(filter: {source_kind?, effect_domain?, world?, namespace?, status?, dialect?}, snapshot, page) → [CapabilitySummary]` — a read-only projection for the Lab and WS-E3; deterministic given a snapshot.
- `search_projection(version_id) → SearchDoc{semantic_id, purpose_text, parameter_names_and_descriptions, effect_domains, namespace?}` — the **surface-independent** text WS-E3 indexes (Codex `default_tool_search_text` precedent; ToolRet motivation); never includes the profile name so ranking experiments are profile-independent.
- `snapshot(refs: [VersionedRef]) → registry_snapshot_id` — ADR-0038 closure rule; recorded in the sealed definition and bundle.
- `import_listing(source: mcp_listing | provider_hosted | participant_supplied, listing_doc, server_ref, trust_record?) → [{version_id, semantic_id, lifted: LiftReport}]` — lifting per ADR-0021/ADR-0034 P7: `Tool{name, description, inputSchema, outputSchema, annotations, _meta}` → record with `purpose ← description` (as `Text`, `external`), `input_schema ← inputSchema` (dialect from `$schema`), `effects ← lift(annotations)` (projection inverse: `readOnlyHint` → `mutability = read_only`; `destructiveHint` → `destructive` else `additive`; `idempotentHint` → `repeat_safety`; `openWorldHint` → `world`; **domain** `unknown_domain` unless `_meta["<hh-prefix>/hir"]` carries the full `EffectClass` set, in which case the HIR values are recovered but still stamped `unverified` unless the `_meta` bundle id is a pinned export of this instance) — every lifted declaration `authority = unverified`; `listing_hash = H(canonical(Tool))`; name → surface field with a `NameHistoryEntry` in the server's namespace. Failures: `SchemaDialectUnsupported`, `ListingMalformed`.
- `refresh(server_ref, listing_doc) → [{old_version_id, new_version_id?, classification}]` — on `notifications/tools/list_changed`, `ttlMs` expiry or session start: re-import; unchanged `listing_hash` ⇒ no-op; changed ⇒ new version + `supersedes{reason: edit}` + `HirDiff.classification` (a description-only change is `surface_ops`; a schema/annotation change is `semantic_ops`; `authority_delta` computed); a definition that pinned the old version stays pinned (ADR-0037 I5) and `verify_resume` reports `capability_changed_under_run{old, new, classification}` (ADR-0025 extension); the run's kernel keeps using the pinned version's declarations and the *new* listing's behaviour is `unknown` — refused unless the policy re-authorises. This is the rug-pull defence (F8) without a new mechanism.
- `bind(version_id, environment: EnvironmentRef, executors: [ExecutorDeclaration]) → ExecutorBinding{capability_version, executor_ref, environment_handle_class, dedup_support, interrupt, isolation, usability} | BindFailure{env_requires_unmet | isolation_insufficient | dedup_required_unsupported | not_installed}` — called by the compiler's `link` to populate the Runtime Plan tool table (ADR-0019 stage 2) and by the runtime on environment (re)creation; every binding is ledgered as `lifecycle.component.bound` (WS-A5's proposed class, reused with `class_id = tool_executor`).
- `project_risk(version_id) → EffectRiskClass` — the CF-104 projection `{reversibility' = read_only if mutability = read_only else reversibility, repeat_safety, scope = workspace_local if world = closed else external}` per effect, reduced by `max_by_danger`; the kernel re-assesses per effect (ADR-0031).
- `required_grants(version_id) → [{domain, scope_kind, param_path?}]` — derived view for V-EFF (`validate`) and for the Lab's "what does this definition need" report; never stored.
- `estimate(version_id, canonical_args) → CostEstimate{per dimension: value | unknown, confidence, basis ∈ {declared, measured, none}}` — pure over `cost_model`; consumers: WS-E3, WS-F4, WS-D1.
- `revoke(version_id, reason, authority, replacement?) → RevocationRecord` and `yank` — ADR-0037; cascades to `StaleIndex` for definitions that pin it.

All operations are pure over their inputs plus the immutable store, implementable out-of-process over the canonical encoding; failure modes are typed errors, never warnings, except `LiftReport` and `classification`, which are declared results.

### 6.4 Sources, provenance and trust (MCP as one source)

| source | default `provenance.origin` | default authority of declarations | how it becomes trustworthy | lifecycle |
|---|---|---|---|---|
| `native_variant` | `human(author)` at authoring; `definition` at `seal` | `definition` | by construction (sealed definition; `authority_cap` applies) | versioned with the variant (WS-A5 `VariantRecord`) |
| `procedure` (composite; C2) | as its `Procedure` | derived from members (`effects` = union) | E1–E3 via the plan mapping (ADR-0022) | with the procedure |
| `mcp_listing` | `import(source_system = mcp, mapping_version)` | `unverified` (ADR-0034 P7) — kernel treats risk as `unknown` ⇒ `{irreversible, non_idempotent, external}` until pinned | WS-H5 `pin` attestation over `listing_hash` raises to `definition` for the pinned version only; unpinned refresh ⇒ back to `unverified` | `refresh` on `list_changed`/`ttlMs`; versions retained per ADR-0037 S8 |
| `provider_hosted` | `import(source_system = provider)` | `definition` for *effects declared by the harness author* about the provider tool (e.g. `net_egress`, `world = open`), `external` for results | author-declared; no pin needed (no listing to mutate) | with the profile's target spec version |
| `participant_supplied` | `participant(participant_ref, hosting_mechanism)` | `unverified` | never for authority; comparisons stratify (T-LCD-07) | with the participant's `version_identity` |

Rule: **a description is data the model reads, never a declaration the kernel reads.** Lifted `description`s are `external`-class `Text` (ADR-0033 R-TEXT) rendered only into roles ≤ `role_map(external)` (ADR-0034 RP) — the type-level form of the tool-poisoning defence: a poisoned description can persuade the model to *propose*, and the proposal is gated by handles the description cannot mint.

### 6.5 Binding to the effect model (B2) and the security kernel (H1)

- **Effects → B2.** The `Effect` record's `capability_id`/`capability_version` are this record's `semantic_id`/`version_id` (ADR-0016 §6.14); `declared: EffectClass` on `action.effect.intended` is the matching member of `effects`; `idempotency_key = H(run_id, effect_id, canonical(args), capability_version)` (ADR-0031) — hence a `refresh` that produces a new version changes keys, which is correct (a changed tool is a different effect source). `execution_requirement.dedup_support_required` must be ≤ the bound executor's `dedup_support` for `compensable` effects (ADR-0031 delivery table) — checked at `bind`. `observation_contract.error_classes ∋ partial_application` is required for any capability record that may return `observed(partial)` (ADR-0030).
- **Permissions → H1.** The record carries **no permission**; `authorizes` edges (ADR-0016) and authority handles (WS-H1 §6.1) reference it. What the kernel reads from it: `effects` (grant coverage, check 2), `scope_bindings` (H-5 `ResourcePattern` match over canonical parameters), `preconditions` of static kinds (check 0/3 argument analysis), `source` and its authority (check 1: a lifted declaration never raises), `observation_contract.content_class` (H2 taint at C2). `required_grants` is the static V-EFF query at `validate`. **Reference direction:** capabilities never reference `Permission`, `AuthorityHandle` or `Π`; the dependency edge points from plane 6 to plane 2 only (mirrors T-LCD-06's rule for hosting).
- **Result authority → L3.** As derived in §6.2 (`environment` only for closed-world, closed-schema, native-or-pinned tools; else `external`; lifted/unpinned `unverified`), and stamped by the kernel on `context.observation.recorded` — the tool implementation cannot raise it (ADR-0035 basis list has no `tool`).
- **Cost → L2/I1.** Measured usage rides `action.tool.completed`/`action.effect.observed` (M-points) and `control.budget.consumed`; `cost_model` feeds estimates only; the Lab computes `measured_ref` views with `computed_from` (ADR-0044).
- **Observability → I1.** `observation_contract.content_class` maps to `SinkPolicy.content_classes` and redaction; `execution_requirement.environment_class` and `source` lower to `gen_ai.tool.type ∈ {function, extension, datastore}` in the OTel exporter (loss report entry when the mapping collapses); the `tool_call`/`tool_attempt` spans are ledger projections (ADR-0042) whose `ir_refs[]` carry `{semantic_id, version_id}`.

### 6.6 Acceptance-criteria sketch

- **AC-E1-1 (C0/Stage 1) Schema.** `ToolCapability` carries exactly the §6.2 semantic, surface and envelope fields; V-E1-1…10 are `validate`/`register` errors; a record with a model-identity-typed field outside `surface` is refused (T-LCD-01).
- **AC-E1-2 (Stage 1) Identity.** Renaming, re-describing, re-ordering arguments, adding examples, changing strictness or exposure hint of a capability yields `semantic_ops = ∅` and an unchanged `semantic_id`; changing `effects`, `input_schema`, `preconditions` or `scope_bindings` changes it (T-LCD-10; AC-5 of WS-A3 restated for this kind).
- **AC-E1-3 (Stage 1) Effect discipline.** A record with `effects = ∅` and no `pure`, or with an attribute outside the ADR-0016 sums, or a scoped domain without a `scope_binding` and without `scope_bindings_unknown`, fails; `project_risk` on a `mutability = read_only` class yields `read_only`; on `unknown_domain` yields `{irreversible, non_idempotent, external}`.
- **AC-E1-4 (Stage 3) Two profiles, one record (T-LCD-01).** The *edit file* capability compiled under the two minimal C0 profiles (ADR-0020: patch-format vs string-replacement) differs only in surface fields; the E4 differential fixture passes on both; `SurfaceArgMap` is total and sound for both (E2).
- **AC-E1-5 (Stage 3) MCP round trip (T-LCD-04/-11).** Export of a native capability to an MCP `Tool` carries `{semantic_id, bundle_id, effects, permission class, provenance pointer, budget ref}` in `_meta` and the attribute projection in `annotations`; `import_listing` of that export recovers the record with a loss report listing exactly the non-carried fields (`cost_model.measured_ref`, `execution_requirement`, `exposure_hint`); import of a *foreign* listing yields `authority = unverified` on every declaration and `unknown_domain` effects; the kernel's decision for a foreign `readOnlyHint = true` tool under default Π is `ask`, never `allow` (AC-B2-05 corollary).
- **AC-E1-6 (Stage 3) Rug pull.** With a run pinned to version v1 of an MCP tool, the server changes the description (surface) and then the schema (semantic): `refresh` creates v2/v3 with `supersedes`, `HirDiff.classification` distinguishes them, `verify_resume` reports `capability_changed_under_run`, the run continues to use v1's declarations, and the `pin` attestation on v1's `listing_hash` does not transfer to v2/v3.
- **AC-E1-7 (Stage 1) Snapshot determinism.** `catalog`, `resolve` and `search_projection` are byte-identical across two implementations for the same `registry_snapshot_id`; `snapshot` over the same closure yields the same id.
- **AC-E1-8 (Stage 2) Binding.** A capability record with `env_requires(binary: X)` fails `bind` with `env_requires_unmet` in an environment without X and appears as `usability = unusable` in the catalog for that environment; a `compensable` capability requiring `dedup_support = executor` fails `bind` against an executor declaring `none`.
- **AC-E1-9 (Stage 3) Cost model is advisory.** A definition whose `cost_model` is absent runs with identical `control.budget.consumed` totals as one with a wrong `cost_model`; `estimate` returns `unknown` (never 0) for undeclared dimensions; the Lab reports `estimate_error` as a class-scoped metric for capabilities with `measured_ref`.
- **AC-E1-10 (Stage 1) Observation contract.** Every capability record declares `error_classes`; the compiled surface's error renderer covers each (E5); results above `offload_policy` are offloaded with a content address and the model sees the declared preview shape; `Observation.authority` on results equals the §6.2 derivation for closed-world native, open-world native, and lifted tools (three fixtures).
- **AC-E1-11 (T-LCD-12) Out-of-process.** Every §6.3 operation runs across the ADR-0050 kernel↔lab boundary over the canonical encoding with byte-identical results.

## 10. Confidence

**High** for the semantic/surface split, the derived risk class, the `unverified` treatment of lifted declarations, content-addressed versions as the rug-pull defence, and permission-as-reference (all follow from ratified ADRs and are corroborated by five source audits and the MCP spec's own trust rule). **Medium-high** for `scope_bindings` and the closed `preconditions` sum: the mechanism is a declared form of what Codex/Claude SDK do in code (`blocked_path`, path containment), but no precedent declares it and its totality rule may need domain additions. **Medium** for `cost_model` (mechanism from one `provisional` preprint plus vendor figures; deliberately optional and non-authoritative) and for `observation_contract.error_classes` (Cursor's taxonomy is anecdotal; the closed list may need a dialect bump). **Low** on any quantitative expectation about catalog scale or retrieval quality — all `provisional` or vendor-internal and none load-bearing.
