## Ontology terms

| term | definition | notes |
|---|---|---|
| embedding contract (`hh-embed/N`) | The single public kernel-facing contract through which anything outside the kernel drives a run: the WS-L1 §6.5 ecosystem-boundary contract (ADR-0050 D3) completed with operation groups H/S/W/R/M/U, invariants I1–I9, the event-frame model and a closed error sum. Distinct from the Hosting ABI and the ACP session boundary, which share its verb shape but are different bindings (CF-023). | WS-K4; ADR-0176. Supersedes the name-only use of "ecosystem boundary" contract in the ontology §5 row (WS-L1/WS-K4/WS-L5). |
| embedding host / host application | A process that drives one or more runs through the embedding contract — a CLI, web dev-tool, IDE, test runner, laboratory process or script. A host is a *native attachment*; it is never a participant class. | WS-K4. Cf. hosting adapter (WS-J6), which attaches a *hosted participant*. |
| session attachment | One client's connection to one run (`attachment_id`), either the writer attachment (`open_session{new \| resume}`, holds the writer lease through the kernel) or a read-only `attach`. A run may have several attachments; exactly one writer (ADR-0026). | WS-K4; Pi multi-presentation precedent. |
| transport binding | One of three admitted ways the embedding contract is carried: `in_process` (first-party surfaces in the ADR-0050 kernel ecosystem), `stdio` (subprocess, newline-delimited JSON-RPC), `local_network` (localhost HTTP/WebSocket). Bindings add transport facts only; never verbs, fields or errors (I8). | WS-K4; ADR-0179. |
| injection point | A typed place at which a host supplies something to a run — definition/overrides, context, procedures, host-executed capabilities, MCP servers, environment reference, budget, approvals, hooks, coordinates — each with a fixed provenance label on entry and an invariant bounding the authority it may carry. | WS-K4; ADR-0177. |
| host-executed capability / host executor | A `ToolCapability` whose executor is the embedding host, bound as an out-of-process executor variant (`execution_requirement.environment_class = host_process`, OQ-404); every call is a kernel-authorized proposal with `committing` before the `invoke_host_capability` upcall and `report_host_effect` as its terminal; results enter at `external` authority. | WS-K4; ADR-0177 D3. |
| raise-only hook (host form) | A host `notify_hook` observer whose result is `raise \| deny \| annotate \| none` — never `allow`, never argument rewriting, never model-visible injection; ledgered as `control.guard.fired`. | WS-K4; restates ADR-0053 / CF-121 for hosts. |
| event frame | The unit of `stream_events`: `sync \| durable{seq, event, hash} \| ephemeral{kind, scope, attempt, order} \| item_started{item_id, attempt, anchor_seq} \| item_aborted \| lagged \| closed`. Durable frames are canonical ledger events, gap-free and never dropped; ephemeral frames never carry `seq` and may be dropped. | WS-K4; ADR-0176 D4; OpenHands session-protocol precedent. |
| contract identity | `(contract_major, schema_hash over the canonical schema export, kernel version_id)`; exchanged at `hello`; asserted by generated clients; mismatch is typed. | WS-K4; ADR-0178. |
| stability tier | `stable \| experimental \| internal` declared per method and per field in the schema export; `experimental` requires an opt-in capability and carries an assumption-debt record with a removal test (T-LCD-05 reflexive); `internal` is unexported. | WS-K4; ADR-0178. Codex experimental-API precedent. |
| experimental opt-in | `HostCapabilities.experimental = true` at `hello`; the only way an `experimental` item becomes callable on a connection; refused otherwise with `ExperimentalRequired{reason}`. | WS-K4. |
| notification opt-out | Per-connection declaration of event classes and ephemeral frames a client declines; never narrows the durable schema. | WS-K4; Codex `opt_out_notification_methods` precedent. |
| deprecation window | The interval between marking a `stable` item `deprecated{since, removal_major, replacement}` and its removal at the next major, ending only when `lifecycle.contract.deprecated_use` counts zero across the surface/participant registry. | WS-K4; ADR-0178 rule 5. |
| realized settings | The kernel's echo, in `open_session`'s response, of what it actually bound (realized model role table, `cwd`, effective containment, Π mode, profile bindings, protocol bindings) — so a host never infers settings from its request. | WS-K4; Codex `thread/start` response precedent. |
