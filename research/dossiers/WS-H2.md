## 1. Scope & boundary

This workstream decides the **C2 enforcement depth** of the one label scheme Phase 1 ratified: (a) the **propagation semantics for every derivation type** the brief names — `summarize`, `compact`, `retrieve`, `delegate`, `tool-call`, `tool-result` — as operations over `ProvenanceRecord`s with the `taint` and `readers` components now load-bearing; (b) the **declassification/endorsement contract** at C2: the full form of reference-monitor check 3 (flow) and the taint component of check 4 (ADR-0035 §5), the `policy_rule` basis as a *bounded sanitizer* sub-kind, shape endorsement's closed-schema list (answers OQ-106), and the robust-declassification precondition; (c) the **deterministic-enforcement subset** that C0 already owes versus the **C2 policy family**, and, inside C2, what is *deterministic* versus *advisory*; (d) the **policy language** — its expressiveness ceiling chosen for decidability, total evaluation and analyzability (narrowing-vs-widening of a policy edit); (e) the **cost model of label tracking** and its acceptance criteria; (f) how IFC composes with the capability monitor (WS-H1) and the provenance scheme (WS-L3) as **one lattice, one record, one monitor with two enforcement depths**; (g) the **quarantine handle** by which a value above the context label is kept out of the context label without being lost (Fides `Hide`, CaMeL variables, APPA child branch) — proposed to WS-D1 as the answer to OQ-105.

It explicitly leaves to neighbours: **WS-H1** — the authority handle runtime, Π (OQ-101; this dossier only fixes the *taint row shape* Π must accept), checks 1, 2, 5, 6, 7, TCB minimality (OQ-021's remaining half); **WS-H3** — which values are `secret_access`-tainted and the reader set of a credential (it consumes `readers`); **WS-H4** — egress *destinations* (network policy); H2 decides whether a *value* may reach an *already-permitted* destination; **WS-H5** — `pin` attestations and extension trust; **WS-H6** — chain attestation of the endorsement events this dossier adds; **WS-H7** — the cadence, UX and budget of `ask`; H2 defines the typed remedies `ask` is one of; **WS-D1** — slot design and rendering (H2 specifies the quarantine handle's *label semantics*, D1 its placement); **WS-D2** — which compaction variants exist (H2 fixes what any variant's summary is labeled); **WS-D3/D4** — the memory hierarchy and lifecycle (H2 fixes the label a persisted/retrieved item carries, D4 the validity machinery); **WS-E1** — the tool registry (H2 asks for a `flow_contract` on `ToolCapability`, flagged as a conflict); **WS-F3** — subagent topology (H2 fixes label seeding and result re-entry, already P2 of ADR-0034, and adds the branch form); **WS-G1** — which Validators are closed-schema; **WS-J6** — hosted participants (H2 only says which checks render `n/a`). Nothing here names a language, runtime, package ecosystem or framework (ADR-0050 §8); precedent file paths are evidence, not dependencies.

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Every deployed agent-IFC policy in the audited corpus is one of four predicate shapes over labels and arguments; none needs recursion, quantification over unbounded domains, or task semantics.** CaMeL's engine (`security_policy.py` L77–96) evaluates in a fixed order — no-side-effect exemption → deny if any *dependency* is non-public → first name-matched policy → default deny — and the per-suite policies (`slack.py`, `banking.py`, `workspace.py`) instantiate only: (i) *trusted-field* — `is_trusted(arg)` for named parameters (`make_trusted_fields_policy`, `agentdojo_security_policies.py` L47–54; `update_password`, `banking.py` L99–107); (ii) *reader coverage* — `can_readers_read_value(recipients, arg)` for each content parameter, with recipients derived from an argument or from environment state (`send_direct_message` L52–64, `send_channel_message` L66–76, `send_money` L52–85); (iii) *public-only* — `is_public(arg)` (`post_webpage`, `get_webpage` L78–99); (iv) *ambient dependency* — deny a state-changing call whose control-flow dependencies include private values (engine L90–92). Fides' P-T/P-F are (i) and (ii) generalized to the whole context label (`πf = (T, ⊤)`, `πd = (⊤, R)`), and its notebook policies add a *content predicate* (`contains_url`, cell 33) and a *history predicate* (`Policy = f(trace)`, cell 29). Progent's DSL adds argument conditions "supporting comparisons, regex matching, array operations, and logical combinations" and a fallback action. APPA adds a *history predicate over committed effects* (prerequisite ordering, exactly-once) and PACT adds *per-argument roles*. The union is a **finite-domain, quantifier-free predicate language over (label components, canonical arguments, the run's effect projection)** — exactly the expressiveness Cedar showed is analyzable with a sound and complete SMT encoding and evaluable in linear time (S-269). **Implication (§6.5):** the C2 policy family can be closed at that expressiveness with no loss against every precedent found, and the closure buys the property Progent uses: a policy edit is mechanically classified `narrowing | widening`.

**F2 — Reactive checking is unsound for composite tools; the check must be against the *prospective post-call label*.** APPA (S-258, `provisional`) proves the necessity: a tool that reads and sends in one invocation would be authorized against the pre-call label before the ingestion is discovered, so the monitor must compute `c_τ(L) = L ∧ d_τ` from the tool's *declared contribution* `d_τ` and check release-side requirements against it. The mechanism is corroborated by Fides' tool-result rule (ℓ″ joins what the tool *reads*, τ(x), not only its arguments) and by CaMeL's `Tool.inner_sources` (a tool result's sources include what the tool consulted). In ADR-0033 terms the declared contribution is a partial `ProvenanceRecord` on `ToolCapability` (taint tags the tool will add, readers it restricts to, resources it reads) — a field E1 does not yet carry (CF-H2-3). Effects with `world = open` and no declaration contribute *unknown*, which APPA resolves lazily by casts and ADR-0033 already resolves as `unverified`/`external` on lift (P7).

**F3 — A value above the context label can be kept *out* of the label without being lost: the quarantine handle.** Fides' `Hide` ("generates a fresh variable to store that node … the planner can issue a Query action without updating the label of the conversation history"), CaMeL's variable-passing (values live in the interpreter, the P-LLM sees names), LIO's labeled values that "may encapsulate and pass around the results of computations with different labels" without raising the current label, and APPA's label-seeded child branch are the same mechanism at four granularities. The model receives a typed handle whose *content* it cannot read; passing the handle to a tool joins the hidden value's label into that call's argument label (so egress is still checked) but not into the context label of subsequent calls. Fides measured the utility effect: Basic planner ≈ 40 pt utility drop under policies vs ≈ 24.5 pt with hiding on reasoning models; DI tasks 75%+ vs Basic ≈ 35% (o3). **This is the C2 answer to OQ-105** and the reason the C0 per-call context label (ADR-0034 P3) does not have to over-taint everything: D1 renders a quarantine slot at a label that does not join (CF-H2-4).

**F4 — Capacity-bounded shape endorsement is sound where free-text endorsement is not, and the bound is measurable in bits.** Fides labels quarantined-LLM outputs `(ℓ, ν)` with `ν ∈ bool ⊑ enum ⊑ string` and observes that "unconstrained strings revert to full labels"; CaMeL's `query_quarantined_llm` forces a schema with a mandatory `have_enough_information` field and raises `NotEnoughInformationError` (L25–99) instead of guessing; APPA's attest-schema admits "booleans, bounded integers, closed enums, bounded arrays" and warns that "exact validation confines shape and bandwidth rather than semantics — an adversarial child may still return an allowed false value"; CXI's "typed releases carry narrow validated values" (S-273). ADR-0035's `validator` basis (external → environment for closed schemas, "free text never") is therefore the right point, and OQ-106's list can be fixed by *information capacity*: a schema qualifies iff its value space is finite and its `capacity_bits = ⌈log₂|values|⌉` is declared; taint is cleared on endorsement only up to a per-definition capacity ceiling (§6.3). The residual risk (a bounded but *false* value) is a *validity* question for WS-G1/G2, not a label question — the ADR-0033 orthogonality holds.

**F5 — Denial without remedy is what costs utility; every sound remedy is one of five typed moves, none of which widens authority.** APPA's ablation (`provisional`) is the only quantified evidence — remedies 87 → 35%, branching 87 → 56.5% — but the *mechanism* set is corroborated independently: CaMeL's Q-LLM refusal (`NotEnoughInformationError`) and its `is_trusted(recipient)` short-circuit (a principal-supplied recipient unblocks `send_money`), Fides' `Hide` and quarantined query, ACP's `RequestPermission` (S-035) and ADR-0035's `approval` of one `effect_id`, Progent's fallback actions, the doc 2 §5.7 isolation pattern. The five moves: `approval(effect_id)` (who), `sanitize(sanitizer_ref)` (what), `shape_endorse(validator_ref)` (what), `branch(child spec)` (where), `substitute(param, ≥ principal source)` / `prerequisite(EffectClass)` (when). Each is either an existing endorsement basis or a pure narrowing; the monitor can *enumerate* them deterministically because the state space is finite (APPA Theorem 5) — the run's label lattice is finite (seven classes × finite taint universe × finite reader universe) and the effect projection is a finite set.

**F6 — Robust declassification is the property that makes "the model never endorses" a *confidentiality* guarantee, and it has a checkable form.** Zdancewic & Myers (S-265): a declassification is robust iff the attacker "can influence neither the decision to disclose information nor the choice of what information is disclosed". In this scheme: the *decision* is a `policy_rule` executed by the kernel from a `HarnessRule` issued at `definition` (ADR-0035 basis 6) — its *inputs* must be at authority ≥ `definition` or be canonical arguments whose taint is ∅; the *choice of what* is fixed by the rule's declared `(from → to)` bounds (APPA sanitizer bounds; Fides' declassification policy denies "when the channel argument is untrusted"). Fides' `policy_no_untrusted_declassification` is exactly the negative case: a recipient generated while untrusted content was in context is an *untrusted declassification* and is denied. AuthGraph (S-272) rebuilds the same idea as a clean-context authorization graph. **Implication (§6.3, rule D-ROBUST):** a declassification whose recipient/parameter set has `effective_authority ≤ external` or `taint ≠ ∅` is refused regardless of the reader check.

**F7 — Item-granularity label tracking costs one join per delivered item and zero model tokens; the expensive things are architectural, not the labels.** CaMeL's 2.82×/2.73× token overhead is the dual-LLM + interpreter architecture; Fides reports no token overhead from labels themselves (Appendix D.3 compares planners). Classical numbers bound the worst case: TaintDroid's per-variable tracking costs 14% CPU on a micro-benchmark and is negligible interactively; Austin & Flanagan's sparse labeling ("explicit labels only for values that migrate between security domains") gives 30–50% over universal labeling. ADR-0033 already defaults `taint = ∅, readers = Public` and omits defaults from the canonical form, so the per-event byte cost is bounded by the number of *non-default* items. The real cost is *utility* (CaMeL 77 vs 84; Fides DD tasks 10–25%) and *policy authoring* ("users needing to codify and specify security policies") — both are Lab measurements (AC-H2-10/11), not engineering costs.

**F8 — Provenance assignment at the boundary, not the lattice, is where deployments fail; and dynamic monitors are sound only with a no-sensitive-upgrade discipline.** The adaptive-evaluation study (S-259) locates the weak point in "an oracle that assigns initial provenance … at real system boundaries"; PACT calls "provenance inference and contract synthesis" the bottleneck. ADR-0033's minting rules and P7 lift rule already make the oracle deterministic (class from verified origin, never from payload). Austin & Flanagan's no-sensitive-upgrade rule maps onto ADR-0034 P6 (never widen) plus this dossier's D-ROBUST: a label may not be *raised* as a consequence of a decision taken under a lower label. Fides' explicit-secrecy limit and CaMeL's three side channels remain: the scheme claims non-interference for *integrity at the effect boundary* and explicit secrecy for confidentiality, not more (§5).

## 5. Disconfirming evidence & negative results

**Against deterministic taint tracking at all in an NL system.** NeuroTaint (S-260, `provisional`) argues that taint analysis "fundamentally fails when applied to LLMs, where data propagation is governed by probabilistic natural language reasoning" and beats a Fides-style baseline on its own benchmark. *Why this does not overturn:* the argument is about *precision of tracking through the model*, not about soundness of tracking *around* it. The scheme never tracks inside a model call: every model output is `delegate ⊔ context_label` (ADR-0034 P1/P3) — a conservative over-approximation that is trivially sound against NL laundering because it assumes everything delivered influenced everything produced. What NeuroTaint offers is a *more precise* estimate; precision that lowers a label is by definition a declassification and belongs behind an endorsement point. It is adopted as an advisory Lab detector (`taint_precision` metric, §6.6), never as enforcement.

**Against per-item labels being enough: the granularity mismatch.** PACT (S-261, `provisional`) shows that tool-invocation-level gates force a choice between hijacked arguments and blocked benign retrieval-then-act. *Why this does not overturn:* the C2 design checks *per argument* — the proposal's label is `⊔(context_label, label(args))` at C0 but the flow rules of §6.5 select individual parameters (`trusted_param`, `recipient_params`, `content_params`) exactly as CaMeL's policies and PACT's roles do; the quarantine handle lets an argument carry its own label without tainting the call's other arguments. PACT's "provenance inference" bottleneck is absent here because provenance is minted by the kernel from verified origin (ADR-0033 rule 6), not inferred.

**Against IFC's utility cost.** CaMeL loses 7 points and fails data-dependent tasks; Fides' DD tasks score 10–25%; the adaptive-evaluation study says in-the-loop tasks "reintroduce human judgment an attacker can target". *Why this does not overturn:* it is why H2 is C2 and why the taint gate's default is a Lab outcome. The recovery design (§6.4) is the utility answer the 2026 evidence points to; if AC-H2-10 shows no recovery on the Stage 3 suite, the taint gate ships `advisory` by default and `deterministic` per definition — the contract is unchanged either way.

**Against closing the policy language (Cedar-class) instead of adopting a recursive one (Datalog/Rego).** Recursion expresses transitive relations ("any recipient reachable through a forwarding chain") that a quantifier-free language cannot. *Why this does not overturn:* the transitive relation IFC needs — "who influenced this value" — is already *materialized* in the label by the join (taint ∪, readers ∩ over `derived_from`), so policies never need to recurse over provenance; Datalog terminates but loses the sound-and-complete SMT encoding that makes `narrowing | widening` classification exact (Cedar's stated reason for its restrictions). Where a Lab experiment needs transitive queries over the ledger, that is an *analysis* over `project()` views (ADR-0026), not an enforcement policy.

**Against the model-proposed policy update (Progent) as a C2 mechanism.** A model at `delegate` proposing policies is the evolution self-widening path ADR-0002 (iii) forbids. *Why this does not overturn:* the mechanism is admitted only in its *narrowing* half — a `delegate`-origin policy edit is applied iff the classifier proves it narrowing; a widening edit is a `HirDiff` with `authority_delta = widening` and follows ADR-0017 (human origin, or rejected in evolution contexts). This is strictly Progent's rule with the approval half replaced by the existing endorsement machinery.

**Against side-channel silence.** CaMeL's authors demonstrate three side channels against their own system; Fides gives only explicit secrecy; APPA excludes covert channels from a malicious model; the adaptive study calls sound IFC "in tension with small-and-verifiable reference monitors". *Why this does not overturn:* the guarantee is stated honestly (§6.7): integrity non-interference at the effect boundary and explicit secrecy for confidentiality; implicit flows through the *sequence* of effects are bounded only by the effect projection predicates (which can deny an egress after a secret read — Fides' P-T *or* P-F) and by H4's destination policy. Timing and exception channels are a stated non-goal at C2 and an OQ for a later tier.

**Against the provisional base.** Every 2026 mechanism relied on here (APPA, PACT, CXI, AuthGraph, adaptive evaluation, NeuroTaint) is a single-team preprint, several on self-built benchmarks; the adaptive-evaluation study itself says its one result is "one small-scale data point on a weak model". *Why this does not overturn:* H2 is C2, so provisional mechanism evidence is admissible when corroborated; each 2026 mechanism is paired above with a 2025 system read in source (CaMeL/Fides) or Tier-A theory (LIO clearance, robust declassification, Austin–Flanagan, Cedar). No C0 obligation changes.

**Negative results from the audit.** (i) No audited repository implements `Hide`/quarantine, remedy enumeration, prospective post-call labels or a policy narrowing classifier — Fides is a notebook, CaMeL's policies are hand-written functions per suite; (ii) no repository declares a tool's *contribution* to labels beyond CaMeL's `inner_sources` — every open-world tool result is labeled by the caller, not by a capability declaration; (iii) no repository budgets `ask` or counts remedies; (iv) no repository classifies a policy edit.

## 6. Recommendation for the spec

### 6.1 Composition: one lattice, one record, one monitor, two depths

Nothing new is added to `Label`, `ProvenanceRecord` or `AuthorityClass` (ADR-0033). H2 *enforces* the two components C0 only carries and adds four kinds of record: a **flow contract** on `ToolCapability` (CF-H2-3), a **flow policy** as a `HarnessRule` action (CF-H2-1), a **quarantine handle** as a `ContextItem` rendering (CF-H2-4), and a **remedy** as the typed content of a monitor `deny`/`ask` decision (payload extension of ADR-0031's kernel decision record, CF-H2-5). The reference monitor (WS-H1) gains check 3 and the taint component of check 4 as *operations it calls* — H2 is a kernel component (MUST-code per ADR-0024), not a pluggable variant; its *policies* are data (`HarnessRule` at `definition`), its *sanitizers* and *shape validators* are `Validator`/`Procedure` component variants that receive `(ModelProfile, ResourceAccount)` (T-LCD-08) but whose *verdicts* enter the monitor only as records. Enforcement class per item is explicit: `EnforcementClass ∈ {deterministic, advisory}`; every deterministic decision is a pure function of ledger records; every advisory input (model risk self-report, judge verdict, semantic-taint detector, permissive-propagation suggestion) may only *add* rows to Π's inputs or *propose* a remedy, never change a label or a decision class.

Notation: `L(x)` the label; `ctx(c)` the context label of call `c`; `⊔` = `(min, ∪, ∩)`.

### 6.3 Declassification and endorsement contract (C2 form of ADR-0035)

The closed basis list is **unchanged** (`seal, approval, validator, promotion, pin, policy_rule`). H2 fixes what each basis may do to `taint`/`readers`, maps it onto the four declassification dimensions (S-264) and adds the robustness precondition.

| basis (ADR-0035) | dimension | may raise `authority` | may shrink `taint` | may widen `readers` | H2 rule |
|---|---|---|---|---|---|
| `seal` | where (definition time) | → `definition` | to ∅ | to Public | only for content the author placed; imported content needs `pin` |
| `approval` | who + when (one effect) | never (endorses the *effect*, not content) | never | never | binds to `(effect_id, args_canonical_hash)`; a remedy `approval` re-checks D-ROBUST on the recipient set before asking (an approval cannot launder an injected recipient) |
| `validator` = **shape endorsement** | what | `external → environment` | to ∅ **iff** the schema is capacity-bounded with `capacity_bits ≤ cap_max(definition)` (default 8) | never | closed schemas (OQ-106): booleans, closed enums, bounded integers/decimals with declared range, dates in a declared window, fixed-shape records and bounded arrays of those; **never** unbounded strings, free text, URLs, file paths, identifiers of unbounded alphabet |
| `promotion` | who (human reviewer) | → `principal`/`definition` | to ∅ | as reviewer declares | D4's lifecycle; requires `human(role = reviewer)` origin |
| `pin` | who (verified signer) | → `definition`/`principal` | to ∅ | Public | H5 |
| `policy_rule` — sub-kind **(a) recipient declassification** | where + what | never | never | to the *named* recipient set of one effect | CaMeL `send_email` rule; Fides P-F; the `HarnessRule` is issued at `definition`; recipients come from `recipient_params` |
| `policy_rule` — sub-kind **(b) bounded sanitizer** | what | never | may remove tags in the sanitizer's declared `removes: set<TaintTag-pattern>` | may widen to the sanitizer's declared `to.readers` | a deterministic `Validator`/`Procedure` registered in the sealed definition with `(from ⊒ …, to)` bounds (APPA sanitizer); the output is a *new* item with `derived_from.kind = projection`, `deriver = kernel`, endorsed in the same append; the monitor refuses a sanitizer whose realized output label is not ⊑ its declared `to` (`SanitizerBoundExceeded`) |

**D-ROBUST (robust declassification, S-265).** An endorsement or declassification event is refused (`RobustnessViolated`) if any *input to the decision* — the recipient parameters of a `policy_rule (a)`, the selector arguments of a sanitizer, the `subject_ref` chosen for an `approval` — has `effective_authority ≤ external` or `taint ≠ ∅`, unless that input was itself shape-endorsed. Consequence: "send the summary to the address found in the email" is denied even with a principal approval prompt available, while "send the summary to Alice" (principal-supplied recipient) is allowed with untrusted content in context — Fides cells 34–35, CaMeL `is_trusted(recipient)`.

**Prudent principles (S-264) as acceptance checks.** *Conservativity:* with no endorsement events the C2 guarantees reduce to §6.7's non-interference/explicit secrecy (AC-H2-2). *Monotonicity of release:* adding a `policy_rule` never makes a previously allowed flow denied (rules are `allow`-side declassifications; `deny` rules are flow *policies*, evaluated first — §6.5). *Non-occlusion:* an endorsement event never hides another flow — every declassified value keeps `derived_from` to its pre-declassification version (I1–I5 immutability). *Semantic consistency:* endorsement is a ledger event, so replacing a declassified value by an equivalent one does not change the decision (decisions are over records, T-LCD-12).

**Answers.** OQ-106: the capacity-bounded list above; a Q-LLM-style constrained extractor is a **`Validator{kind: judge}` whose output schema is capacity-bounded** — its verdict is `delegate`-authored and gets `environment` only through the deterministic schema check that follows it (two records, one endorsement). OQ-103 (partial): `PrincipalRef = user(id) | recipient(channel_kind, address) | tenant(id) | public`; recipients of an effect are the values of the capability's `recipient_params` resolved by the tool's declared `resolve_recipients` (channel → members, as CaMeL `send_channel_message`) — H3/J6 confirm (OQ-H2-1).

### 6.4 Recoverable denial (the remedy contract)

`authorize(p) → allow | ask(effect_id, remedies[]) | deny(reason, remedies[])` (extends ADR-0035's consequence 1). `Remedy = approval(effect_id) | sanitize(sanitizer_ref, param) | shape_endorse(validator_ref, param) | branch(spec) | substitute(param, min_authority = principal) | prerequisite(EffectClass)`. Invariants: (R1) every remedy is a *pure narrowing* or an existing endorsement basis — none introduces a new basis; (R2) the remedy list is computed by bounded search over the finite state `(Label, effect projection)` (APPA Theorem 5) and is **deterministic given the records**; (R3) a remedy consumed is a ledger event (`security.permission.*` decision with `remedy_taken`) and confers nothing beyond the one proposal (`approval`) or the one value (`sanitize`/`shape_endorse`); (R4) `ask` counts against `approvals.requested` and remedies against a new gauge only if WS-L2 admits one (OQ-H2-2) — otherwise they are ledger-derived views; (R5) unattended runs (no principal reachable) configure Π without `ask`; the remedy list then omits `approval` and the model sees `deny` with the remaining remedies (answers OQ-101's unattended row *shape*, not its content). The model *chooses* among remedies; it cannot mint one — "the model influences task utility and recovery candidate selection, but cannot manufacture authorization" (APPA).

### 6.5 The policy language (expressiveness vs decidability) — ADR-0056

**Decision.** Flow policies are `HarnessRule`s with a new action kind `flow_policy(FlowPolicy)` (CF-H2-1) whose `condition` is written in a **closed, quantifier-free, non-recursive, total predicate language** over exactly three finite domains: (i) the labels of the proposal, its parameters and the prospective post-call label; (ii) the canonical arguments of the proposal (by capability parameter, through `SurfaceArgMap`, never by surface field — ADR-0022); (iii) the run's *effect projection* (the set of committed `EffectClass`es and their canonical-argument hashes, `project(run, effects)` per ADR-0026). Atoms: `authority(x) ≥ c`, `taint(x) ⊆ T`, `taint(x) = ∅`, `readers(x) ⊇ recipients(p)`, `readers(x) = Public`, `arg(param) {=, ∈, like, <, ≤}` literal, `committed(EffectClassPattern, arg-pattern)`, `count(committed(...)) ≤ n`, `EffectClass(p) matches pattern`, `detector(validator_ref, param)` for a *deterministic* kernel Validator (URL/secret-pattern detectors — Fides `contains_url`); connectives `∧ ∨ ¬`; no variables beyond the proposal, no iteration except the built-in `∀ param ∈ params(p)` and `∀ e ∈ effects(run)` (finite, linear). Semantics: total — an error (missing field, undeclared parameter) evaluates the rule to `deny` with reason (Cedar totality, CaMeL default deny). Evaluation order (CaMeL engine, Cedar): `deny` rules first, then `allow`/declassify rules, then Π's default row; no rule matched ⇒ Π default. Complexity: linear in `|params| + |rules| + |effects(run)|`; every atom constant time over small sets; the evaluator is implementable out-of-process over the canonical encoding (T-LCD-12) and in constant time per atom to avoid a policy-timing channel (CaMeL's note).

**Analyzability.** Because the language is quantifier-free over finite domains it has a sound and complete encoding into a decidable logic (Cedar's construction), so `classify_policy_edit(P, P′) → narrowing | widening | incomparable` is exact: `narrowing ⇔ ∀ proposals. allowed(P′) ⇒ allowed(P)` (Progent's check). A `delegate`-origin edit (model, evolution) is applied iff `narrowing`; `widening`/`incomparable` is a `HirDiff` with `authority_delta = widening` (ADR-0017: human origin required; rejected in evolution contexts). The classifier itself is a kernel operation; an SMT backend versus a syntactic subsumption check is OQ-H2-3 (both are admissible implementations of the same contract).

**Rejected alternatives.** Datalog/Rego (S-270): recursion is unnecessary (provenance is materialized in the label) and forfeits exact edit classification; general code (CaMeL's Python policies): non-total, unanalyzable, an escape hatch (T-LCD-01 in policy form); model-evaluated natural-language policies: `delegate` authority, non-deterministic — admissible only as an *advisory* detector row in Π.

### 6.6 What is deterministic vs advisory (the C0 subset and the C2 family)

| layer | deterministic (pure functions of records) | advisory (may feed Π or propose a remedy; never sets a label or a decision class) |
|---|---|---|
| **C0 (owed by ADR-0033/34/35; H1 implements)** | lattice ops; `default_authority`; `ctx` per call; `effective_authority`; checks 1, 2, 5, 6, 7; endorsement legitimacy; retrieval order; role placement; lowering/lifting classes | model `risk_assessment`; judge verdicts |
| **C2 (H2)** | prospective post-call label; admission; per-parameter labels; check 3 (readers ⊇ recipients on egress domains `net_egress, message_human, spend`, plus `fs_write` with `world = open` and `memory_write` to scope ≥ `project` — CF-H2-2); taint component of check 4; flow-policy evaluation; D-ROBUST; sanitizer bound check; shape endorsement schema check; remedy enumeration; policy-edit classification; branch label seeding and re-entry | permissive label minimization (S-263) as a *suggested* `sanitize`/`shape_endorse` remedy; semantic-taint audits (S-260) as Lab metrics `taint_precision`, `flow_false_deny_rate`; LLM-drafted policies as `delegate` edits subject to the narrowing classifier; ML classifiers for content predicates only as `Validator{kind: judge}` rows with `charged_to = instrument` |

Rule: an advisory input that would *lower* a label is a declassification and must pass an endorsement point; an advisory input that would *raise* restriction may be applied directly as a narrowing (no-sensitive-upgrade discipline holds because restriction only increases).

### 6.7 Guarantee statement (what the spec may claim)

With flow contracts declared on every open-world capability, policies as in §6.5, and no endorsement events: (G1) **integrity non-interference at the effect boundary** — no effect with `EffectClass ∉ (read_only ∧ closed)` is committed whose decision depends on content at `≤ external`/`taint ≠ ∅` except through Π's explicit `allow` rows (Fides P-T; CaMeL base policy); (G2) **explicit secrecy** — no value reaches a recipient outside its reader set through an explicit argument or a declared tool contribution (Fides P-F; CaMeL reader coverage); (G3) **no laundering** — no derivation, delegation, branch, compaction, retrieval, lowering or advisory input yields a label above the join of its inputs (ADR-0034 P6 + admission + label seeding + D-ROBUST). **Not claimed:** implicit flows through the *sequence* of effects, timing/exception/loop channels (CaMeL), text-to-text harms (Fides, Progent), correctness of a shape-endorsed value (APPA), covert channels from a malicious model.

### 6.8 Interface-contract sketch (language-agnostic; operations, inputs/outputs, invariants, failure modes)

- `prospective_label(p: Proposal, contract: FlowContract) → Label` — `L(p) ⊔ d_τ`; failure `ContributionUndeclared` (at seal) / `MissingProvenance`.
- `admit(result, contract, L⁺) → ProvenanceRecord | AdmissionNarrowed` — realized label = `⊔ leaves` if `labels_leaves` else whole; never below `L⁺`'s restriction on the declared components; never reads a class from the payload.
- `check_flow(p, L⁺, params: [(param, Label)], recipients: [PrincipalRef], policies: [FlowPolicy], effects: EffectProjection, Π) → allow | ask(effect_id, remedies) | deny(reason, remedies)` — order deny → allow/declassify → Π default; total; deterministic; constant time per atom; failure of any atom ⇒ `deny(reason = EvaluationError)`.
- `enumerate_remedies(p, L⁺, decision, definition) → [Remedy]` — bounded search; returns `[]` when none is reachable; invariant R1–R3.
- `endorse(subject, to, endorser, basis, basis_ref)` (ADR-0035) with the C2 preconditions: `basis = validator ⇒ schema capacity-bounded ∧ capacity_bits ≤ cap_max`; `basis = policy_rule(b) ⇒ realized ⊑ declared to`; D-ROBUST on decision inputs; failures `BasisNotAllowed`, `SanitizerBoundExceeded`, `RobustnessViolated`, `IllegitimateEndorsement`.
- `quarantine(item) → QuarantineHandle{handle_id, label, schema?, capacity_bits?, blob_ref}` and `reveal(handle, into: branch | endorsement)` — content is never rendered into a model-facing `Text`; `HandleLeaked` otherwise.
- `spawn_branch(parent_ctx, spec) → child` with `child.ctx₀ = parent_ctx`, `clearance = effective_authority(parent)`; `return_from_branch(child, exit ∈ {abandon, labeled_return, attested_return(validator_ref)})`; failure `BranchTaintEscaped`, `ClearanceExceeded`.
- `classify_policy_edit(P, P′) → narrowing | widening | incomparable` — exact; deterministic; used by `HirDiff.classification.authority_delta` for `flow_policy` ops.
- `lower_label(record, target)` / `lift_label(payload)` — `taint`/`readers` ride `hir/provenance` in the typed extension slot (`_meta`); loss report lists dropped components; lift never yields `taint = ∅` or `readers ⊋ Public`-narrower-than-declared (T-LCD-11).
All operations are implementable out-of-process over the canonical encoding (T-LCD-12) and read only ledger records and the sealed definition.

### 6.9 Data-model sketch

- `FlowContract` (on `ToolCapability`, CF-H2-3): `{contribution: {taint_tags: set<TaintTag-pattern>, readers_from: reads | declared(set<PrincipalRef>) | Public}, reads: [ResourcePattern], recipient_params: [param path], content_params: [param path], labels_leaves: bool, resolve_recipients?: Ref<Validator | Procedure>}`; required when any effect has `world = open` or domain ∈ `{net_egress, message_human, fs_read, memory_write}`.
- `FlowPolicy`: `{policy_id, issuer: ProvenanceRecord (authority ≥ definition), scope: PersistenceScope, rules: [FlowRule]}`; `FlowRule = {selector: {effect_class?: EffectClassPattern, capability?: Ref, params?: [param]}, condition: Predicate (§6.5 grammar), decision ∈ {deny, allow, declassify(readers_to: recipients | set<PrincipalRef>), sanitize(sanitizer_ref, param)}, remedies_hint?: [RemedyKind]}`. Stored as a `HarnessRule` action (CF-H2-1); `conditioned_on ≠ null ⇒ assumption-debt record` (T-LCD-05).
- `Sanitizer` = `Validator{kind: executable | predicate, deterministic: true}` or `Procedure` with `bounds: {from: Label-pattern, to: Label, removes: set<TaintTag-pattern>}` registered in the sealed definition.
- `QuarantineHandle`: `{handle_id, label, schema?, capacity_bits?, blob_ref}`; a `ContextItem.rendering ∈ {inline, handle}` (CF-H2-4).
- `Remedy` (§6.4) inside the kernel decision record `{effective_risk_class, allow | ask | deny, reason, cache_key?, remedies[], remedy_taken?}` (CF-H2-5).
- `EffectProjection` = `project(run, effects, until_seq)` view (ADR-0026) = `{(EffectClass, args_canonical_hash, phase)}`.
- Events: no new classes; payload extensions on `security.permission.*` (remedies), `context.assembled` (per-item `rendering`), `security.label.endorsed` (`capacity_bits`, `sanitizer_ref`, `robustness_inputs[]`), `control.subagent.spawned` (`isolation = label_branch`, `ctx₀`), `context.observation.recorded` (`admission ∈ {as_declared, narrowed}`) — all flagged to WS-B1/H1 (CF-H2-5).

### 6.10 Acceptance-criteria sketch

- **AC-H2-1 Contract coverage (C2/Stage 2).** `seal` refuses a definition with an open-world or egress capability lacking a `FlowContract` (`ContributionUndeclared`); every C2 check reads only records.
- **AC-H2-2 Conservativity (C2/Stage 2).** Property test: with no endorsement events, over random sequences of the seven derivation types, `L(out) ⊑ ⊔ L(inputs)` always (extends AC-L3-2 to taint/readers, branches and admission).
- **AC-H2-3 Exfiltration fixture (C2/Stage 2–3).** An email with readers `{alice, bob}` is read; the model proposes `send_message(recipient = injected address, body = summary)`: `check_flow` → `deny(RobustnessViolated | ReaderCoverage)`; with `recipient = alice` (principal-supplied) → `allow`; with `recipient = carol` from the principal → `ask` with remedies `[approval, sanitize]`; the approval endorses only that `effect_id` (CaMeL `send_direct_message`; Fides cells 34–35).
- **AC-H2-4 Composite-tool fixture (C2/Stage 3).** A capability that reads a restricted file and posts it: the reactive label would allow, the prospective label denies (APPA necessity); the same capability split into two calls is denied at the second.
- **AC-H2-5 Quarantine fixture (C2/Stage 2).** A restricted retrieval is delivered as a handle; the next call's `ctx` is unchanged; passing the handle to an egress tool is checked at the handle's label; `HandleLeaked` fires if the blob content appears in any delivered `Text`.
- **AC-H2-6 Branch fixture (C2/Stage 4).** A child branch seeded with the parent's `ctx` reads external content and returns (a) a labeled summary → enters at `external` with union taint; (b) a shape-endorsed boolean (`capacity_bits = 1`) → enters at `environment`, taint ∅; (c) a shape-endorsed free string → `BasisNotAllowed`. The parent's `ctx` never changed; a child-side approval does not authorize the parent's effect.
- **AC-H2-7 Sanitizer bounds (C2/Stage 3).** A redaction sanitizer declared `(from: readers ⊇ {principal}, to: readers = Public, removes: {secret:*})` whose realized output still matches the secret detector → `SanitizerBoundExceeded`; a compliant output is endorsed in the same append with `derived_from` to the source.
- **AC-H2-8 Policy language (C2/Stage 3).** A corpus of every CaMeL suite policy and Fides notebook policy is expressible in §6.5's grammar (round-trip test, ≥ 100% of the audited rules); the evaluator rejects a recursive or code-bearing rule at `seal`; evaluation is total (fuzzed proposals never raise, only `deny`); p99 evaluation latency per proposal is reported at a declared measurement point (OQ-H2-2).
- **AC-H2-9 Edit classification (C2/Stage 3).** For pairs `(P, P′)` from the corpus, `classify_policy_edit` agrees with exhaustive enumeration over a finite proposal space; a `delegate`-origin widening edit is refused; a narrowing edit applies without approval.
- **AC-H2-10 Utility under matched budget (C2/Stage 3, T-LCD-14).** Lab recipe: `taint gate ∈ {off, advisory, deterministic}` × `remedies ∈ {none, ask-only, full}` × `quarantine ∈ {off, on}` under `MatchSpec` — reports success, approvals requested/granted, remedies taken, denials, cost; the default enforcement class of the taint gate is decided by this experiment (`ComparisonReport` with `benefit_kind`).
- **AC-H2-11 Precision audit (C2/Stage 3, advisory).** `taint_precision` = fraction of denied effects a semantic-taint detector (NeuroTaint-class, `Validator{kind: judge}`, `charged_to = instrument`) judges truly influenced by untrusted content; reported, never enforced.
- **AC-H2-12 Determinism and locality (C2/Stage 2, T-LCD-12).** Two independent evaluator implementations (in-process and out-of-process over the canonical encoding) produce byte-identical decision records for the same inputs; no decision changes when the Model Profile changes (the monitor is profile-independent).
- **AC-H2-13 Lowering (C2/Stage 3, T-LCD-11).** `taint`/`readers` round-trip through the MCP `_meta` slot; a target that cannot carry them appears in the loss report; hosted participants' per-item checks render `n/a` (T-LCD-15) with the observability reason.
- **AC-H2-14 Cost (C2/Stage 2).** Label bytes per event ≤ declared bound (non-default components only); monitor decision cost is linear in `|params| + |rules| + |effects(run)|` by construction and measured; zero additional model tokens attributable to labels (the only model-facing artefacts are handles and demotion wrappers, counted by the opacity report).
