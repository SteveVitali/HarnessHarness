## 1. Scope & boundary

This workstream decides the **Harness IR (HIR)**: the typed, behavioural, provenance-bearing representation of a harness across the seven planes. Concretely it fixes (a) the abstract type discipline (sum/product types, effect annotations, versioned references, opaque leaves, extension slots, dialects); (b) the entity and edge catalogue with fields, invariants, and version/provenance rules; (c) the **expressiveness ceiling** — what is typed and what is an opaque compiled payload, with the criteria (OQ-002, OQ-006); (d) the **typed diff** — what a harness edit is as an IR object; (e) how black-box hosted participants appear in the IR (an opaque `AgentProcess` variant with declared capabilities); (f) how the IR represents both harness *code* and harness *configuration* (doc 2 §7); (g) the properties the IR needs from a host language/ecosystem, stated language-neutrally for WS-L1 (OQ-040, OQ-041); (h) the arbitration of typed vocabulary against Ontology v0.1 (ADR-0008).

It explicitly leaves to neighbours: **WS-A4** — lowering/lifting, the compiler, protocol targets, the lowering loss report, `lcd_report`, interpreted-data-vs-emitted-code (OQ-043); **WS-A5** — assembly/composition, whether a Harness Definition is a pure data document (OQ-044), component-variant binding; **WS-A2** — Ontology v1, the formal policy-stack model, validity-vs-compliance; **WS-B1** — the event taxonomy, ledger envelope and write path (OQ-042; OQ-041 is joint); **WS-B2** — transaction/idempotency semantics of effects; **WS-L3 / WS-H1 / WS-H2 / WS-D1** — the single authority/label/taint scheme (CF-006; the IR reserves typed slots and fixes their *shape*, not their values); **WS-L4** — hash algorithm choice, migration of identities, artifact identity; **WS-C3** — the profile schema's contents; **WS-D5** — the rich Procedure IR (OQ-023) beyond the C0 kernel fixed here; **WS-J6** — the Hosting ABI (the IR must be independent of it, T-LCD-06). Nothing here names a language, runtime, package ecosystem or framework; every precedent path is cited as evidence, not as a dependency.

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — The semantic-contract / rendering split is precedented, but the precedent puts identity in the wrong place.** DSPy's `Signature` is a typed I/O record (`InputField`/`OutputField` with `desc`, `prefix` stored as `json_schema_extra`) plus `instructions`; the `Adapter` ("interface layer between DSPy module/signature and LMs", `adapters/base.py` L34–48) renders it per LM, including toggling native function calling (`_call_preprocess`, L83–135). The *learned state* of a `Predict` is exactly `{signature.instructions, fields[].{prefix, description}, demos, lm, traces, train}` (`predict.py` L71–90) — and every optimizer edits only two typed slots: `with_instructions(...)` and `.demos` (`mipro_optimizer_v2.py` L770/778; `gepa_utils.py` L232; `bootstrap.py` L270). This is mechanism evidence that *typed edit slots are sufficient for a productive optimizer* and that the slot set can be tiny. But `Signature.equals` (L510–521) compares `instructions` and each field's `json_schema_extra` (prefix/desc) — identity includes surface wording. Under T-LCD-10 that is the anti-pattern: a `prefix` rename changes identity.

**F2 — When agent *structure* is searched, the searched object is opaque code wrapped in a typed envelope.** ADAS stores each candidate as a JSON archive entry `{thought, name, code, fitness, generation}` where `code` is a `forward(self, taskInfo)` body (`_arc/search.py` L295–330; init archive in `arc_prompt.py`); fitness is a bootstrap confidence interval string; evaluation `exec`s the code. AFlow represents a workflow as two source files per round (`graph.py` with a `Workflow.__call__`, `prompt.py` with prompt constants) and a typed optimizer output `GraphOptimize{modification, graph, prompt}` (`optimizer.py` L26–30), over a *fixed typed operator vocabulary* (`template/operator.json`: name → `{description, interface}`); `graph_utils.py` extracts and rewrites the graph text (L38–57, L115–118). GPTSwarm types the graph (nodes = operations, edges = information flow) and optimizes node prompts and edge connectivity, leaving node bodies opaque. All three converge on the same shape: **typed metadata that the search needs (identity, lineage/generation, score, rationale, operator interface) around an opaque payload that the search mutates.** This is direct evidence for the ceiling design in §6.3: the IR types the envelope and the interface, and admits an opaque body only with a declared interface.

**F3 — A production SDK already types most of the entity set, with three instructive choices.** OpenHands' `Event` is a frozen record `{id, timestamp, source ∈ {agent,user,environment,hook}, parent_id}` (`event/base.py` L20–38; `event/types.py`) forming a *tree* with a HEAD (`state.py` L315–338, "single storage chokepoint"). `ActionEvent` carries `security_risk` (LLM-predicted, `UNKNOWN` default), `llm_response_id`, `tool_call`, `critic_result` (`action.py` L23–90). `ToolDefinition` carries MCP-shaped `ToolAnnotations` (`readOnlyHint/destructiveHint/idempotentHint/openWorldHint`, `tool.py` L215–249) and a **tri-state** `DeclaredResources{keys, declared}` where "`declared=False` means 'I haven't thought about it' while `declared=True, keys=()` means 'I have, and I'm safe'" (L251–282). `Condensation{forgotten_event_ids, summary, summary_offset, llm_response_id}` (`event/condenser.py`) is a *supersedes* relation over events. `AgentBase` is a frozen configuration with typed slots (`llm, tools, mcp_config, condenser, critic, security_analyzer, agent_context, system_prompt…`, `agent/base.py`). Polymorphism is an **open, subclass-registered discriminated union** keyed by class name (`utils/models.py` `DiscriminatedUnionMixin.resolve_kind`, L347–356: unknown kind raises). `AgentProfile` has `schema_version = 2` and an `agent_kind` discriminator with an `acp` variant that has "no `llm_profile_ref` and no embedded credential" (`profiles/agent_profile.py` L122–226) — a black-box agent as a sibling variant of the white-box one. Three lessons: (i) unknown-vs-declared-empty must be distinguishable (tri-state), (ii) supersession is an edge over immutable records, (iii) a hosted agent is representable as a variant of the same sum with fewer fields — the exact shape ADR-0001 needs.

**F4 — At the protocol boundary, effect metadata is a hint, and extension is a prefixed namespace.** MCP `ToolAnnotations` are explicitly untrusted: "Clients should never make tool use decisions based on `ToolAnnotations` received from untrusted servers" (`schema.ts` L1904–1910). `Tool` = `name/title/description/inputSchema/outputSchema/annotations/_meta` (L1973–2016). `_meta` keys are reverse-DNS prefixed with a reserved MCP namespace (L35–58). Therefore the IR cannot *derive* authoritative effects from a lowered tool; the IR's `ToolCapability.effects` is an authoritative, provenance-stamped declaration that lowers to hints plus `_meta` (T-LCD-11, WS-A4), and lifting from MCP yields `effects` with `authority: imported/unverified`.

**F5 — "Unified" model APIs carry provider-opaque payloads, typed as opaque and stamped with their owner.** Pi's `ThinkingContent.thinkingSignature` ("Provider-specific opaque or serialized reasoning replay data"), `ToolCall.thoughtSignature` (Google-specific), `TextContent.textSignature`, and `AssistantMessage{api, provider, model, responseModel}` (`types.ts` L345–450) show the right pattern for opaque leaves: an opaque string plus a typed record saying who owns it. Pi's `Tool{name, description, parameters, constrainedSampling}` and `Model{…thinkingLevelMap, compat}` show provider-conditioned fields living in a *model* record, not in the tool — profile-owned surfaces in a different vocabulary.

**F6 — A versioned declarative agent document with references exists (Agent Spec) and shows what a "document IR" needs and lacks.** `Component{id: uuid, name, description, metadata, min_agentspec_version, max_agentspec_version}`; `component_type` = class name; version enum 25.3.0 → 26.4.0; per-version field exclusion (`_versioned_model_fields_to_exclude`) and min-version inference from configuration (`tools/tool.py`: `requires_confirmation` bumps the min version to 25.4.2); serialization emits `$referenced_components` deduplicated by id. **Identity is a random UUID**, not a content hash; there is no provenance, effect, validator, budget, permission (beyond one boolean) or memory-validity construct. This bounds OQ-031: export is a lossy lowering.

**F7 — Content-addressed identity with names as separate metadata is a mature mechanism.** Unison identifies each definition "by a hash of its syntax tree" in which "all named arguments are replaced by positionally-numbered variable references, and all dependencies … are replaced by their hashes"; "names are just separately stored metadata that don't affect the function's hash", enabling non-breaking renames and no diamond-dependency problem (S-WS-A3-02). RFC 8785 (JCS) gives a deterministic byte serialization of a JSON data model (sorted keys by UTF-16 code units, ECMAScript number formatting, no whitespace, UTF-8, I-JSON constraints, no Unicode normalization) explicitly so that "cryptographic operations" are "reliably repeatable" (S-WS-A3-03). Together they make T-LCD-10 and OQ-041 implementable with off-the-shelf mechanisms: identity = hash over the canonical form of a *projection* that excludes surface fields and replaces references by their hashes.

**F8 — Typed IRs with opaque islands, dialects and per-entity verifiers are standard compiler practice.** MLIR: operations are "fully extensible (there is no fixed list of operations)"; attributes are "constant data … where a variable is never allowed"; dialects namespace operations/types/attributes; **unregistered operations coexist with registered ones** for round-tripping and gradual lowering; each operation carries its own verifier via traits/interfaces (S-WS-A3-04). This is the precedent for: a closed kernel plus registered extension dialects, opaque leaves that survive round-trip untouched, and kind-specific invariants checked at validation.

**F9 — Effects and permissions must be typed as *declared claims* checked for consistency, with enforcement outside the model.** CaMeL "explicitly extracts the control and data flows from the (trusted) query" and uses "a notion of a capability to prevent the exfiltration of private data over unauthorized data flows", enforced by an interpreter outside the model, at a 77%-vs-84% utility cost (S-099). OpenHands' `SecurityRisk` is an LLM *prediction* on an action (`risk.py`), distinct from any static declaration. Koka shows static effect typing is possible in a language (S-WS-A3-06) but nothing in the audited agent systems relies on it. Design consequence: the IR carries two different things — `EffectClass` declarations on capabilities/procedures (static, authoritative within the definition) and `Observation`-level risk assessments (runtime, model-authored, never authoritative) — and the static check is a *graph query* (every effect reachable from a Procedure is covered by an `authorizes` edge in scope), not a host-language type-system feature.

**F10 — Procedures as first-class nodes with typed relations and gated edits are supported by fresh but consistent evidence.** Procedural Graphs (S-095, `provisional`) store `(procedure, relation, procedure)` triplets, localize the active node, and let a refiner "edit the graph's topology and attributes", committing "only if they preserve or improve held-out validation performance". AFlow's `modification` field and ADAS's `thought` field are the same idea (an edit carries a rationale). Mechanism only; it motivates `Procedure` with typed steps and a `derived-from` provenance carrying hypothesis + trajectories (doc 2 §11 "every harness edit should point to the trajectories and failure hypothesis that motivated it").

**F11 — Structural diffs are mature; the IR needs a simpler case.** GumTree computes AST edit scripts with move actions using two-phase matching over structure hashes (S-WS-A3-05). The IR has stable node identities, so a diff is computed by identity rather than by tree matching — cheaper and unambiguous — while GumTree-style matching is only needed to *rebase* a diff onto a definition whose ids changed (an extension, not C0).

## 5. Disconfirming evidence & negative results

**Against typing the harness at all (the "search spaces are code" objection).** The most productive structure-search systems (ADAS, AFlow, Meta-Harness S-080) mutate *source code*; a typed IR could be a straitjacket that forbids the designs an optimizer would find. *Why this does not overturn:* the same systems keep a typed envelope (F2), and their search spaces are bounded by a fixed operator vocabulary (AFlow `operator.json`) or a fixed `forward` signature (ADAS) — i.e., they already impose an interface. The ceiling in §6.3 admits opaque payloads *with a declared interface and effect set*, so nothing ADAS/AFlow can express is excluded; what is excluded is an opaque payload with undeclared effects or an undeclared interface. The cost — that some behaviour becomes attributable only at the payload level — is measured, not hidden (opacity ratio; T-LCD-02).

**Against content-addressed "semantic identity".** Semantic equivalence is undecidable; a hash sees only a canonical *form*. Two entities with identical behaviour and different field order-independent-but-value-different encodings get different ids; a Text leaf changed by one whitespace character gets a new id. *Why this does not overturn:* the T-LCD-10 requirement is narrower than equivalence: *rename does not change identity*. Identity over the canonical form of a **semantic projection** (surface fields and provenance excluded, references replaced by hashes — Unison's construction) satisfies it exactly. I therefore arbitrate the ontology wording: "semantic identity" means *identity over the semantic projection*, never *semantic equivalence* (CF-WS-A3-01). Equivalence is what T-LCD-01's semantic-equivalence *validator* tests at run time.

**Against statically checked effects.** MCP annotations are hints (F4); tool authors misdeclare; a static check can give false confidence, and CaMeL shows enforcement costs utility. *Why this does not overturn:* the IR check is a *consistency* check (declared effects ⊆ authorized effects), cheap and language-neutral; enforcement remains the reference monitor's (WS-H1) at run time on observed effects. Declared effects are claims with provenance and an `authority` stamp; imported or unverified declarations lower to default-deny. The static check catches the common error class (a Procedure wired to a tool nobody authorized) without pretending to catch misdeclaration.

**Against requiring closed sum types.** OpenHands (`DiscriminatedUnionMixin`) and Agent Spec (`component_type` by class name) both use open, registration-based unions successfully; closed sums make third-party extension (WS-L5) a dialect-bump affair. *Why this does not overturn:* the failure mode of open unions is silent — an unknown kind is either rejected at load (OpenHands raises) or, worse, passed through — and an *exhaustive* consumer (compiler, verifier, diff classifier) cannot be proven complete against an open set. The resolution is layered: the **kernel** (entity kinds, edge kinds, effect classes, authority classes, validity states, opaque-leaf kinds) is closed per dialect; **extension** happens through typed, registered, prefixed extension slots (MCP `_meta`, MLIR dialects) that consumers must preserve but never need to interpret. WS-L1 consequence (OQ-040): exhaustiveness checking is *strongly preferred* but its absence is not a hard gate, because a schema validator plus a registry-completeness test reproduces the guarantee.

**Against DSPy-style identity (instructions in identity) — i.e., against the surface/content split.** For LM programs, the instruction *is* the semantics; excluding wording from identity could let two behaviourally different definitions share an id. *Why this does not overturn:* the split is not "text excluded" but "**rendering** excluded". A `Text` leaf's canonical content *is* semantic and *is* hashed; what the profile owns is how the leaf is placed, framed, named and formatted. A different instruction is a different leaf hash, hence a different semantic id. A renamed tool, reordered argument or reworded description-template is a surface edit.

**Against provenance on every node.** It is verbose; Agent Spec deliberately has none; production systems get by with `source` on events. *Why this does not overturn:* provenance is a compact typed record of references (origin, authority, version), not narrative; the cost is bytes, the benefit is the entire measurement-and-evolution plane (T-LCD-13, ADR-0002 governance, CF-006). The audit found that flattening sources into one stream is the shared root cause of context-privilege escalation and revoked-memory failures (doc 2 §4; S-103/S-104/S-106 `provisional (mech)`).

**Against a reference-harness round-trip at Stage 3 (T-LCD-03).** A mini-SWE-agent-class harness is so small that passing the round-trip proves little; a rich harness (OpenHands) may not be expressible without opaque payloads. *Why this does not overturn:* both are needed and staged (OQ-039 answer in §6.9): the small anchor proves the kernel; the rich anchor at Phase 3 measures the opacity ratio the IR actually achieves on production structure — a *reported* number, not a pass/fail.

**Negative results from the audit.** No audited system (DSPy, OpenHands, AFlow, ADAS, Agent Spec, Pi, MCP) has: content-addressed identity that excludes surface fields; a typed `Permission` with attenuating delegation; a `Budget` entity with monotone containment; `Memory` with validity intervals; or an assumption-debt record on rules. The seven-plane set with provenance is therefore still `novel as a set` (consistent with WS-A1 F4 and CF-011) — and still an engineering claim to be proven by T-LCD-03/-04.

## 6. Recommendation for the spec

### 6.1 Type discipline (abstract; language-neutral)

- **Meta-model.** A HIR document is a DAG of **nodes** and **edges**. `Node = {version_id, semantic_id, kind: EntityKind, dialect: HirVersion, version: VersionRecord, provenance: ProvenanceRecord, semantic: KindRecord, surface: SurfaceRecord?, ext: ExtensionSlots}`. `Edge = {kind: EdgeKind, from: Ref, to: Ref, provenance, fields: EdgeRecord}`. `KindRecord` and `EdgeRecord` are product types fixed per kind per dialect.
- **Closed sums (per dialect).** `EntityKind` (§6.2: 13 entities + 2 leaves), `EdgeKind` (7), `EffectClass`, `AuthorityClass` (values reserved for the CF-006 scheme; shape fixed here), `ValidityState`, `OpaqueKind = {Text, CompiledPayload}`, `ProcedureStepKind`, `ValidatorKind`, `AgentProcessKind = {native, hosted}`. Consumers (compiler, verifier, diff classifier) must handle every variant; adding a variant is a dialect bump with a migration.
- **Open but registered extension.** `ExtensionSlots = map<PrefixedKey, TypedValue>` with MCP-style reverse-DNS prefixes and a reserved `hir/` namespace; each key registers a schema; unknown keys are **preserved byte-for-byte on round-trip and never interpreted** (MLIR unregistered-op rule). Extension slots may not hold anything that decides authority, budget or validity (those are kernel fields) — this is the T-LCD-01 "no escape hatch" rule in type form.
- **Opaque leaves — exactly two kinds.** `Text{content, owner, authority, provenance, language?}` for model-facing prose; `CompiledPayload{format_tag, bytes_hash, declared_interface{inputs, outputs, effects: set<EffectClass>, deterministic: bool, target}, owner, provenance}` for executable bodies (validator code, custom tool implementation, control-strategy implementation). Nothing else in the kernel is a string blob. Every `Text` leaf is individually addressable (ablatable) and counted by the opacity metric.
- **Surface records are profile-owned.** `SurfaceRecord` fields (model-facing name, description template, argument naming/order, error rendering, placement/formatting) are excluded from `semantic_id` and may only be set by a Model Profile through the compiler (WS-C3/WS-A4). The kernel schema has **no field typed by model identity** outside `ProfileRef` (T-LCD-01).
- **Effect annotations.** `ToolCapability.effects: set<EffectClass>` (authoritative declaration, provenance-stamped); `Procedure.effects` is *derived* (union over steps) and stored for diffing; `Permission.grants[].effect_class`. Static consistency rule V-EFF: for every Procedure in a Harness Definition, `derived_effects ⊆ ∪{authorizes edges in scope}`; violation is `EffectUncovered` at validation. Enforcement of *observed* effects is runtime (WS-H1/B2).
- **Versioned references.** `Ref = {semantic_id, version_id | version_selector}`. Inside a *sealed* definition (what a run executes) every Ref is pinned to a `version_id`; unpinned selectors are legal only in the assembly section a Harness Definition presents to WS-A5's composer and are resolved before sealing (`UnresolvedRef` otherwise).
- **Two identities per node.** `version_id = H(canonical(node))`; `semantic_id = H(canonical(kind ∥ semantic ∥ refs-by-semantic_id))` — surface, provenance, ext and version records excluded; Text leaves contribute their content hash. Rename ⇒ `semantic_id` unchanged (T-LCD-10).
- **Canonical form (OQ-041, joint with WS-B1).** Required. Class: **hash over a canonical form**; the canonical form is a JCS-class deterministic serialization of a JSON-model data tree (sorted keys, no whitespace, UTF-8, integers only or decimal strings, no Unicode normalization, no duplicate keys). Storage/wire encodings are free provided they round-trip to the canonical form losslessly; the hash function and the canonical-form version are pinned per HIR dialect (rotation policy: WS-L4).
- **Dialects.** Every document carries `hir_version`; every kind schema carries `since`/`until` dialects; `migrate(doc, from, to)` is total or returns `MigrationLoss` (Agent Spec precedent). Unknown *kinds* are rejected; unknown *extension keys* are preserved.

### 6.2 Entity and edge catalogue (HIR/1 kernel)

Each entry: plane · semantic fields · surface fields (profile-owned) · invariants · provenance/version rules · precedent. Common to all: `version`, `provenance`, `ext`, two ids.

1. **Goal** (planes 3/4). Semantic: `statement: Text`, `success_criteria: [Ref<Validator>]`, `budget: Ref<Budget>`, `origin ∈ {human, system, delegated, scheduled}`, `parent: Ref<Goal>?`. Surface: none. Invariants: `success_criteria` non-empty or `unverifiable_reason: Text` present; `budget ≤ parent.budget` (dimension-wise). Precedent: OpenHands `AgentContext`/task; Claude SDK `TaskBudget` (S-109 via WS-A1).
2. **Observation** (plane 1; runtime-produced payload type). Semantic: `source ∈ {tool_result, environment, human, model_claim, validator}`, `producer: Ref<ToolCapability | Validator | AgentProcess>`, `content: Text | StructuredValue | Ref<Artifact>`, `authority: AuthorityClass`, `taint: set<Label>`, `risk_assessment?: {level, assessor: Ref<AgentProcess|Validator>}` (never authoritative). Invariants: `authority ≤ authority(source)` (never elevated); `model_claim` observations can never satisfy a Validator by themselves. Rule: the IR owns this payload type; WS-B1 owns the event envelope that carries it (CF-WS-A3-03). Precedent: OpenHands `ObservationEvent`, `source`; ATIF `step.source`.
3. **ContextItem** (plane 1). Semantic: `payload: Ref<Text | Memory | Observation | Artifact | Procedure | ToolCapability>`, `authority`, `validity: {from, until | condition}`, `placement_policy: Ref<HarnessRule>?`, `priority`, `delivery_id` (for delivered/activated/followed events, T-LCD-13). Surface: rendering template, position. Invariants: traceable to an origin node; opacity accounting counts `Text` payloads. Precedent: doc 2 §5.1; OpenHands `View`.
4. **Memory** (planes 5/1). Semantic: `content: Text | StructuredValue`, `validity {valid_from, valid_until | invalidation_condition}`, `authority`, `confidence`, `source_trajectories: [RunRef]`, `scope`. Invariants: retrieval filters on validity and authority before relevance (CF-008 forward); revocation = new version with `validity.until` set + `supersedes` edge; the revoked version is never deleted (audit). Precedent: S-077/S-106 mechanisms (`provisional`); no source precedent carries validity.
5. **Procedure** (plane 3; doc 2 §5.12). Semantic: `preconditions: [Ref<Validator> | Predicate]`, `steps: [ProcedureStep]` where `ProcedureStep = Instruction(Text) | Invoke(Ref<ToolCapability>, ArgBinding) | Delegate(AgentProcessSpec, Ref<Budget>, Ref<Permission>) | Branch(Predicate, then, else) | Loop(bound: Ref<Budget>, body) | Verify(Ref<Validator>) | Opaque(CompiledPayload)`, `expected_evidence: [Ref<Validator>]`, `allowed_capabilities: [Ref<ToolCapability>]`, `failure_handlers: [{on, then}]`, `effects` (derived). Surface: `compile_hint ∈ {instruction, workflow_node, subagent_task}` selected by profile and risk (doc 2 §11). Invariants: every step typed; `Opaque` steps require a declared interface; V-EFF; `Loop` bounded by a Budget. WS-D5 extends only via `ext` or a dialect bump (CF-WS-A3-05). Precedent: S-095 (`provisional`), AFlow operator vocabulary, GPTSwarm nodes/edges.
6. **ToolCapability** (plane 2). Semantic: `purpose: Text`, `input_schema`, `output_schema`, `effects: set<EffectClass>` (non-empty or explicit `pure`), `preconditions`, `resources: {declared: bool, keys: [ResourcePattern]}` (tri-state, OpenHands), `idempotent: bool`, `reversible: Ref<Procedure>?`, `cost_model: Ref`, `risk_class`, `observation_kind`. Surface: `name`, `description_template`, argument names/order, examples, error format, exposure mode (composite vs primitive). Invariants: `semantic_id` excludes surface; lowering to MCP/native function calling/shell wrapper/provider tool carries `effects` via typed extension slots (WS-A4, T-LCD-11). Precedent: MCP `Tool` + `ToolAnnotations`; OpenHands `ToolDefinition`; codex `models.json` (surface per model).
7. **Permission** (plane 6). Semantic: `principal: Ref<AgentProcess>`, `grants: [{effect_class, scope: ResourcePattern, constraints: {budget?: Ref<Budget>, time?, count?}, delegable: bool}]`, `issuer: {authority, Ref}`, `validity`, `revocation: Ref<Permission>?`. Surface: none (permissions are never model-facing text). Invariants: `authority(issuer) ≠ model_claim`; delegation only attenuates (`child.grants ⊆ parent.grants`, scope-wise); the IR records, the reference monitor enforces (WS-H1); an evolution diff that widens any grant is `AuthorityWidening` (ADR-0002 iii). Precedent: CaMeL capabilities on values (S-099); Claude SDK `PermissionUpdate` (S-109); no audited runtime carries attenuating delegation.
8. **Effect** (planes 2/5/6). Two-level: `EffectClass` (closed sum; initial list `read_fs, write_fs, exec, net_egress, secret_access, spend, message_human, spawn_process, memory_write, permission_request, model_call` — final list OQ-WS-A3-02) and the **Effect record** (runtime instance): `{class, target: ResourceRef, idempotency_key, reversibility ∈ {reversible(Ref<Procedure>), compensable, irreversible}, transaction: Ref?, produced_by}`. Invariants: every Effect record has a `produced-by` edge to an `Invoke` step or Validator run; transaction semantics are WS-B2's (CF-WS-A3-02). Precedent: MCP hints (as lowered form only); doc 2 §11 Stage 1.
9. **Artifact** (plane 5). Semantic: `content_hash`, `media_type`, `size`, `storage_ref`, `produced_by`. Immutable; new content ⇒ new node + `supersedes`. Invariant: never inlined into events larger than a threshold (doc 2 §11 "content-addressed artifact references"). Precedent: Harbor trial artifacts; git objects.
10. **Validator** (plane 4). Semantic: `kind ∈ {executable(CompiledPayload | Invoke), schema(Schema), predicate(Predicate), judge(Text rubric, ProfileRef), human}`, `inputs`, `verdict_type`, `deterministic: bool`, `cost`, `evidence_out: ArtifactKind`. Surface: rubric rendering (judge only). Invariants: `judge` ⇒ `deterministic=false` and carries its own `ProfileRef` and opacity accounting (OQ-WS-A3-06); a Validator may not consume `model_claim` observations as its only evidence. Precedent: OpenHands `CriticBase`; Harbor verifier; Inspect scorers (via WS-A1).
11. **AgentProcess** (planes 3/7). `kind = native{harness_def: Ref, profile: ProfileRef, control_strategy: ComponentVariantRef, context_policy: ComponentVariantRef, budget: Ref<Budget>, permissions: Ref<Permission>, environment: EnvironmentRef} | hosted(OpaqueProcess)` — see §6.5. Invariants: `native` has component sub-entities; `hosted` has none; both have `budget` and `permissions`; the schema of `native` contains no field that exists "so that hosted participants can fill it" (T-LCD-06). Precedent: OpenHands `AgentProfile{openhands | acp}`.
12. **Budget** (cross-cutting). Semantic: `dimensions: {tokens_in, tokens_out, model_calls, wall_clock, env_minutes, network_calls, fan_out, approvals, spend}` each `{hard?, soft?}`, `scope: Ref<Goal | AgentProcess | Procedure>`, `parent: Ref<Budget>?`, `accounting: Ref` (WS-L2). Invariants: `child ≤ parent` dimension-wise; every Goal and AgentProcess references a Budget (upstream of T-LCD-14). Precedent: Claude SDK `TaskBudget`; Harbor cost fields; doc 2 §4.
13. **HarnessRule** (planes 7/3). Semantic: `trigger: Predicate` (over state, profile, plane events), `action ∈ {insert ContextItem | restrict tool set | set compaction policy | set retry/stop policy | require Validator | request approval}`, `scope`, `conditioned_on: ProfileRef?`, `assumption_debt: AssumptionDebtRecord?`. Invariants: `conditioned_on ≠ null ⇒ assumption_debt` complete (`{rule_id, hypothesis, evidence_refs[], owner, expiry_condition, removal_test_ref, status}`, T-LCD-05) else `ConditionedRuleIncomplete`; a rule's action never references a Permission grant wider than its scope's. Precedent: codex `models.json` rows (as data); OpenHands `ModelSpecificSection` (via WS-L7); no precedent for the record.

**Leaves.** 14. **Text** and 15. **CompiledPayload** as in §6.1. Additional reference types (not entities): `ProfileRef`, `ComponentVariantRef` (WS-A5), `EnvironmentRef` (WS-B5/E5), `RunRef` (WS-B1).

**Edges (7).** `depends-on` (any→any; acyclic within a sealed definition; carries `reason`); `supersedes` (same kind; acyclic version chain; carries `reason ∈ {edit, revocation, expiry, migration}`); `authorizes` (Permission → ToolCapability | EffectClass | Procedure; carries scope); `produced-by` (Observation | Artifact | Effect | Memory → Invoke-step | Validator | AgentProcess); `validates` (Validator → Goal | Artifact | Procedure | Memory | HarnessRule); `delegated-to` (AgentProcess → AgentProcess; carries `Ref<Permission>` ⊆ parent's and `Ref<Budget>` ≤ parent's); **`derived-from`** (proposed addition: new node version → `{hypothesis: Text, trajectories: [RunRef], candidate_id?}` — the doc 2 §11 "every harness edit points to the trajectories and failure hypothesis"; consumed by the typed diff and ADR-0002's pipeline).

**Provenance record (every node and edge).** `{origin: human(author_ref) | model(model_ref, run_ref, response_id) | tool(Ref<ToolCapability>, invocation_ref) | evolution(candidate_id, hypothesis_ref) | import(source_system, mapping_version) | migration(from_dialect), authority: AuthorityClass, created_at, attestation?}`. **Version record.** `{version_id, semantic_id, dialect, supersedes: Ref?, sealed: bool}`.

### 6.3 The expressiveness ceiling (what is typed vs opaque) — ADR WS-A3-adr-1

A construct **must be typed** (a kernel entity, edge or field) if any of: (T1) it crosses a plane boundary (a tool result becoming context; a validator verdict gating a goal); (T2) it is an object of an authority, budget or validity decision; (T3) the Lab must ablate, attribute, diff or stratify on it (comparison granularity `component`); (T4) it must survive lowering to ≥2 targets or ≥2 profiles with its semantics preserved (T-LCD-04). A construct **may be opaque** (a `CompiledPayload` or `Text` leaf) only if: (O1) it is the *body* of a computation whose interface (inputs, outputs, effects, determinism, target) is declared; (O2) it does not decide authority, budget or validity; (O3) it is individually addressable so it can be ablated and its contribution measured. Anything failing both sets (an undeclared-effect script; a "system prompt: string" that mixes instruction, tool description and memory) is `UnexpressibleSurface`-class — invalid, not merely opaque.

**Consequences.** Control strategies, compaction strategies, context builders and routers are *component variants* (WS-A5) whose *implementations* are `CompiledPayload`s behind Core contracts, while their *parameters and decisions* (which ContextItems, which Budget, which HarnessRule fired) are typed and appear in the ledger. A Procedure's `Instruction` steps are `Text` leaves; its wiring is typed. Judge rubrics are `Text`; judge *verdicts* are typed Observations with `deterministic=false`. The ceiling is therefore "typed structure, typed interfaces, typed decisions; opaque bodies and prose" — and the **opacity ratio** reports how much of each definition's model-facing surface is prose.

**Opacity ratio (OQ-036, with WS-I2).** Static definition (stored in the bundle per profile): `opacity_ratio(def, profile) = tokens(surface(def, profile) contributed by Text leaves) / tokens(surface(def, profile))`, where the surface is the compiled model-facing material of the sealed definition (system/instruction material, tool surfaces, procedure instructions, memory templates) before any runtime observations; tokenized by the profile's tokenizer (or a declared proxy). Tool `purpose` texts count as Text-leaf tokens (they are prose), schema-derived tokens count as structured. Reported alongside: `opaque_leaf_count`, per-owner-class breakdown (`system, tool_purpose, procedure_instruction, memory, rule`), and `compiled_payload_count` (non-model-facing opacity). The dynamic per-turn ratio (including observations) is WS-I2 telemetry, not the bundle metric.

### 6.4 Typed diff — ADR WS-A3-adr-3

`HirDiff = {base: DefinitionVersionRef, target: DefinitionVersionRef, dialect, ops: [DiffOp], classification, provenance: derived-from}` with `DiffOp = AddNode(node) | RemoveNode(id) | ReplaceField(id, path, old, new) | ReplaceLeaf(id, old_hash, new_hash) | AddEdge(edge) | RemoveEdge(edge_id) | Rebind(id, path, old_ref, new_ref) | SurfaceEdit(profile_ref, id, path, old, new) | ExtEdit(id, key, old, new)`. Each op is tagged with `{plane, entity_kind, semantic: bool}`; `classification = {semantic_ops, surface_ops, provenance_only_ops, ext_ops, authority_delta ∈ {none, narrowing, widening}, budget_delta ∈ {none, tightening, loosening}}`. **Invariants:** computed by node identity (never by tree matching); `apply(base, diff) = target` byte-for-byte in canonical form; `invert(diff)` exists and `apply(target, invert(diff)) = base` (reversibility for ADR-0002); a rename produces only `SurfaceEdit` ops and leaves every `semantic_id` unchanged (T-LCD-10 test); `authority_delta = widening` makes the diff unacceptable in an evolution context (ADR-0002 iii) and requires human `provenance.origin` otherwise; a diff whose ops touch a `conditioned_on` rule must carry or update its assumption-debt record. **Textual diffs of Text leaves are a *rendering* of `ReplaceLeaf`**, produced on demand for humans; they are never the stored object. Answer to Q-L1-04: structural; **no** IR↔source round-trip is required (definitions are data documents; any authored surface syntax is a front end whose output is canonical HIR); the round-trip the compiler *does* owe is lower→lift per target (T-LCD-11, WS-A4).

### 6.5 Hosted participants — ADR WS-A3-adr-4

`AgentProcess.hosted = OpaqueProcess{participant_ref, declared_capabilities: CapabilityDeclarationRecord, observability_levels: set<{events, model_io, end_state, ledger}>, version_identity: content hash(declaration ∥ participant_version), supplies: {context: [Ref<ContextItem>], tools: [Ref<ToolCapability>], procedures: [Ref<Procedure>]}, budget: Ref<Budget>, permissions: Ref<Permission>, hosting_mechanism ∈ {session_abi, model_boundary_intercept, container_installed}}`. `CapabilityDeclarationRecord` is a kernel record whose field set is the ratified ontology list (streaming, interrupt, steer, live_queue, resume, fork, compaction, images, subagents, permission_surface, instruction_delivery, model_family, effort_vocabulary, trajectory_export, native_config), **each tri-state `{supported, unsupported, unknown}`** — never coerced (T-LCD-07). **Invariants:** an `OpaqueProcess` has no component sub-entities and no `ComponentVariantRef`s; metrics requiring `component` granularity are `n/a` (T-LCD-15); the IR defines this record itself and **imports nothing from the Hosting ABI** — WS-J6's ABI descriptor must *lower to* this record (T-LCD-06); `permissions` and `budget` are enforced at the boundary by the runtime, since the participant cannot be trusted to self-enforce. Edges: `delegated-to` from a native process or from a Lab experiment root; `produced-by` from the Observations the mechanism yields. Precedent: OpenHands `ACPAgentProfile` (sibling variant with fewer fields); Omnigent `HarnessCapabilities` / Harbor `AgentCapabilities` (via WS-A1).

### 6.6 Code vs configuration (doc 2 §7; feeds WS-A5)

The IR represents both with one boundary rule: **configuration** is the sealed HIR document (nodes, edges, parameters, profile/variant bindings — all typed); **code** appears only as `CompiledPayload` leaves bound into component-variant slots or `Opaque` procedure steps, each with a declared interface. The compilation boundary is therefore explicit and enumerable: `boundary(def) = {payloads: [{id, format_tag, declared_interface, owner}], text_leaves: [...]}`, and both sides are versioned, provenanced, diffable and ablatable. Skills/AGENTS.md-style prose imports lift to `Text` leaves with `provenance.origin = import` and `authority ≤ imported` (WS-H5/L3 decide the exact class). Whether a Harness Definition is *only* a data document (OQ-044) is WS-A5's call; this design makes "yes" possible.

### 6.7 Interface-contract sketch (operations; language-agnostic)

- `validate(doc) → ValidationReport | [Error]` — schema per dialect; ref resolution and pinning; kind-specific verifiers (§6.2 invariants); V-EFF effect coverage; budget monotonicity; delegation attenuation; acyclicity of `supersedes`/`delegated-to`/`depends-on`; conditioned-rule completeness; static T-LCD checks (01: no model-identity-typed field outside `ProfileRef`/`surface`; 02: only `Text`/`CompiledPayload` opaque; 06: no Hosting-ABI import; 10: identity excludes surface). Errors: `UnknownKind, DialectUnsupported, UnresolvedRef, CycleDetected, EffectUncovered, AuthorityWidening, BudgetExceedsParent, ConditionedRuleIncomplete, NonCanonicalInput, OpaqueWithoutInterface, UnexpressibleSurface` (the last is raised by WS-A4 but defined here as a first-class error type).
- `canonicalize(doc) → bytes` — deterministic; two independent implementations must agree byte-for-byte.
- `identity(node) → {semantic_id, version_id}`; `seal(doc) → SealedDefinition` (all refs pinned; ids computed; immutable).
- `diff(a, b) → HirDiff`; `apply(a, diff) → b`; `invert(diff) → HirDiff`; `classify(diff) → classification`.
- `migrate(doc, from_dialect, to_dialect) → doc | MigrationLoss`.
- `opacity(sealed, profile) → OpacityReport` (consumed by `lcd_report`, WS-A4).
- `ablate(sealed, node_id | leaf_id) → sealed'` — removes or neutralizes one node/leaf and records `derived-from{hypothesis: "ablation"}`; used by the Lab (WS-J3).
- `project(sealed, plane | kind) → sub-DAG` — read-only query for analysis.
- `export(sealed, target=agent_spec) → {document, LoweringLossReport}` / `import(agent_spec_doc) → doc` (OQ-031, §6.8).
Failure modes are typed errors, never warnings, except `MigrationLoss` and `LoweringLossReport`, which are declared losses.

### 6.8 OQ-031 — Open Agent Spec as an interop target

Export is a **lossy lowering** (WS-A4 owns the mechanism; this dossier fixes the mapping): `AgentProcess.native → Agent{llm_config ← ProfileRef binding, system_prompt ← concatenated Text leaves (opacity recorded), tools ← ToolCapability surfaces}`; `Procedure` with `compile_hint = workflow_node → Flow` nodes (agent/llm/tool/branching/map/parallel/catch-exception); `Permission` → only `Tool.requires_confirmation = true` when any grant needs approval; `Memory` (validity), `Validator`, `Budget`, `HarnessRule`/assumption debt, provenance, effects, `Observation` authority → **lost and listed in the loss report**; identities → `metadata` (Agent Spec `Component.metadata` can carry `semantic_id`/`version_id` so lifting can re-link). Import: `Agent`/`Flow` lift to `AgentProcess.native` + Procedures with `provenance.origin = import`, `Permission` = default-deny with a single `permission_request` grant, all Text leaves `authority = imported`. Stage: C2/Stage 4 (interop, ADR-0005), not C0.

### 6.9 Acceptance-criteria sketch

- AC-1 The HIR/1 schema defines exactly the 13 entities, 2 leaves, 7 edges, provenance and version records of §6.2 with every invariant encoded as a `validate` check; every kind carries `since=HIR/1`.
- AC-2 (T-LCD-01) A ToolCapability *edit file* compiled under two profiles (patch-format vs string-replacement) differs only in `surface` fields; the kernel schema contains no field whose type is a model identity outside `ProfileRef`.
- AC-3 (T-LCD-02) Static check passes: the only string-valued semantic fields are inside `Text`/`CompiledPayload`; `opacity()` returns the §6.3 report for the Stage-0 reference definition.
- AC-4 (T-LCD-06) The IR module's dependency graph (spec DAG) has no edge to the Hosting ABI; `OpaqueProcess` is defined in the IR.
- AC-5 (T-LCD-10) Renaming a compiled tool, reordering its arguments and rewording its description template yields a diff with `semantic_ops = ∅` and unchanged `semantic_id`.
- AC-6 `canonicalize` is byte-identical across two independent implementations on a corpus of ≥100 definitions; `apply(base, diff(base,target)) = target` and `apply(target, invert(diff)) = base` on the same corpus.
- AC-7 A Procedure that invokes a ToolCapability with an effect no in-scope Permission authorizes fails validation with `EffectUncovered`; a `conditioned_on` rule without a complete assumption-debt record fails with `ConditionedRuleIncomplete`; a delegation whose Permission or Budget exceeds the parent's fails.
- AC-8 (T-LCD-03, Stage 3) The mini-SWE-agent-class Stage-0 harness is expressed in HIR/1 with `opacity_ratio` reported and round-trips behaviourally within the pre-registered margin (paired runs, fixed model/seed/budget).
- AC-9 (OQ-031, Stage 4) Export to Agent Spec produces a loss report listing at least Permission, Effect, Validator, Budget, Memory-validity, HarnessRule and provenance; import yields a valid, default-deny definition.
- AC-10 (T-LCD-12) Every operation in §6.7 is specified as operations/inputs/outputs/invariants/failure modes and is implementable out-of-process over the canonical encoding.

### 6.10 Build-stage suggestion

- **C0 / Stage 1:** HIR/1 schema, `validate`, `canonicalize`, `identity`, `seal`, `diff/apply/invert/classify`, `migrate` (identity migration only), `project`. These precede typed events (WS-B1 stamps `semantic_id`/`version_id` of the entities an event references) and precede any compiler work.
- **Stage 0:** the baseline may be hand-authored as a HIR/1 document; no tooling beyond `validate`.
- **C0 / Stage 3:** `opacity`, `ablate`, T-LCD-03 round-trip on the small anchor.
- **C2 / Stage 4:** Agent Spec export/import (ADR-0005 interop); rich-anchor opacity report (OQ-039).
- **Later dialects:** HIR/2 when WS-D5 (procedures), WS-H1 (authority values), WS-B2 (transactions) require kernel changes; each is a migration, never an in-place widening.

### 6.11 Properties the IR needs from a host ecosystem (for WS-L1; names no language)

P1 **Closed sum types for kernel enums with exhaustive-consumer checking** — required *as a property of the implementation*, satisfiable either by native exhaustiveness checking or by schema validation plus a registry-completeness test in CI; **does not trigger hard gate C6** (Q-L1-01). P2 **Immutable product records** with structural equality. P3 **Single source of truth for the schema** from which a language-neutral schema document (JSON-Schema-class) and any other bindings are generated and CI-checked (MCP `check:schema` precedent, S-153; WS-L1 §6.5 I1). P4 **Deterministic canonical serialization** (JCS-class) available or implementable in a few hundred lines, with stable key ordering and I-JSON number handling (Q-L1-03: required; class = hash over canonical form). P5 **Cryptographic hashing** of byte strings. P6 **Explicit registration of kinds** — no reliance on runtime subclass discovery (the OpenHands pattern is convenient but makes the union open by accident). P7 **Opaque byte payloads** with hashes, without deserializing them. P8 **Graph queries over small DAGs** (≤10⁴ nodes) — no graph library dependency implied. P9 **Effect-coverage and monotonicity checks are graph queries**, not type-system features — **no static effect system is required of the host language; hard gate C6 is not triggered** (Q-L1-02: effects are *recorded and consistency-checked* at validation; enforced at runtime by WS-H1). P10 **Structural diff by identity** (own implementation; no source round-trip, Q-L1-04). P11 **Unicode-preserving strings** (no implicit normalization) for Text leaves. P12 **Out-of-process implementability** of every §6.7 operation over the canonical encoding (T-LCD-12). Summary for ADR-0009: **neither conditional hard gate under C6 fires on WS-A3's answers**; C6 remains a weighted criterion (how *well* an ecosystem expresses P1–P12), and WS-A3 holds the veto only if a candidate cannot produce a byte-identical canonical form (P4) or cannot generate the neutral schema (P3).

### 6.12 Vocabulary arbitration (WS-A3 arbitrates typed IR vocabulary — ADR-0008)

- **`semantic identity`** (ontology v0.1 "surface vs semantic identity"): defined as *identity over the semantic projection's canonical form* (`semantic_id`), never semantic equivalence. Ontology row to be amended in wording only; the T-LCD-10 test is unchanged (CF-WS-A3-01).
- **`Effect` vs `EffectClass`**: doc 2 §11's single entity becomes a type (`EffectClass`, closed sum) plus a runtime record (`Effect`). WS-B2 owns transaction semantics of the record (CF-WS-A3-02).
- **The word "capability"** is used for three things (ToolCapability entity; capability declaration/vector for hosted participants; object-capability handles in security). Resolution: spec prose never uses bare "capability"; `ToolCapability` (plane 2), `Permission` (plane 6 grant), `capability declaration`/`capability vector` (hosted, ratified), and **`authority handle`** for WS-H1's runtime object-capability (proposed term). CF-WS-A3-04.
- **`conditioned rule`** = a `HarnessRule` with `conditioned_on ≠ null`; the assumption-debt record is its mandatory field (consistent with ADR-0007/0008).
- **`Observation`**: the IR entity is the payload type; WS-B1's `ObservationEvent` is the ledger envelope carrying it (CF-WS-A3-03).
- **`AgentProcess` vs `participant`**: a participant is the Lab's unit; a native participant = `AgentProcess.native` + runtime; a hosted participant = `AgentProcess.hosted` (`OpaqueProcess`).
- New terms proposed (§9): `Text leaf`, `CompiledPayload`, `OpaqueProcess`, `semantic_id` / `version_id`, `surface record`, `extension slot`, `HIR dialect`, `HirDiff` / `typed diff`, `derived-from`, `effect class`, `authority handle`, `opacity report`, `sealed definition`.

## 10. Confidence

**High** for the type discipline and the expressiveness ceiling: every element has a Tier-A/B precedent read in source or in a standard (DSPy, OpenHands, MCP, Agent Spec, Unison, JCS, MLIR), and the ceiling matches how the three structure-search systems already behave. **High** that the two conditional C6 hard gates do not fire (the required properties are all implementable as validation/CI checks). **Medium** for the entity catalogue's *field lists*: the shapes are grounded, but `AuthorityClass` values, the `EffectClass` list and Procedure step richness are owned by neighbours and may force an HIR/2. **Medium** for the hosted-participant record: it mirrors ratified ontology terms but J6 has not yet designed the ABI it must lower from. **Low-to-medium** for anything resting on S-095 (Procedural Graphs) or on S-103/104/106 mechanisms — all `provisional`, used only as motivation, never as a C0 basis.
