## Ontology terms

| term | definition | notes |
|---|---|---|
| evolution campaign | A content-addressed `EvolutionCampaignSpec` (base definition, proposer family, proposal constraints, slot allocation, parent selection, suite/split binding, per-stage budgets and `MatchSpec`s, model levels, rollout policy, stop rule, pre-registration) whose execution is a run of `run_kind = experiment` and whose evaluations are derived `ExperimentSpec`s of ratified kinds. | WS-I5; no new run kind (ADR-0183 §C) |
| candidate (evolution candidate) | `CandidateProposal{candidate_id = H(base ∥ diff), base, diff: HirDiff, family, proposer_run_id, search_spend, provenance{origin: evolution}}` — the unit the pipeline gates; identity is content-derived; never a mutation of an authored file (ADR-0147 M-2). | WS-I5 / WS-A3 / WS-J1 |
| candidate state | Closed sum `proposed → classified → hypothesized → screened → searched → validated → transferred → security_checked → sealed_candidate → canary → active → expiring → {retired | revalidated}`; terminals `rejected{stage, code}`, `withdrawn`, `reverted`; transitions are `measurement.evolution.candidate.transitioned` events; the view is a ledger projection. | growth = dialect bump |
| failure hypothesis / predicted effect | `FailureHypothesis{statement, failure_class, evidence_refs[], affected_task_ids[] ⊆ search ∪ dev, reference_trajectories?, model_scope, predicted}` and `PredictedEffect{deltas[{metric_ref, direction, magnitude?}], expected_flips[], cost_delta?}`; refused as `HypothesisUnfalsifiable` when any of evidence, metric, direction or tasks is missing; verified at S3–S5. | AHE "falsifiable contract"; DGM diagnosis shape |
| counterexample set | `CounterexampleSet{tasks[] ⊆ search ∪ dev, selection_rule ∈ {hypothesis_named, disagreement_weighted, reference_aligned}, set_hash, replicates}` on which the prediction must be visible before search spend; rows `estimated`. | HarnessLens / Task-CoEvolve mechanism |
| evidence corpus | The kernel projection `project(runs, evolution_evidence_view)` a proposer reads: outcomes, ledger views, optional `model_io`/artifacts by address, prior candidates with verdicts, optional reference trajectories, per-slot search history; excludes held-out surfaces, validators, secrets; delivered read-only through the D-5 `fs_read` handle. | Meta-Harness/AHE "filesystem of prior candidates" made a projection |
| proposer adapter / proposer family | A registered variant of the component class `evolution_proposer` (`propose`, `select_parent`, `declare`) with a conformance suite; a *family* is its declared taxonomy row; non-first-party variants run under `plugin_abi/1`. | WS-I5 / WS-J2 / WS-L5 |
| target-set exclusion | The fixed set no candidate may touch: suite validators/oracles/graders, `Permission`, `Budget.hard`, Π/policy leaves, pre-authorization rules, trust/containment/sink policies, MUST-code pointers, the evolution service's own definition and proposer variants (`SelfModificationRefused`). | extends ADR-0053 D-5 / ADR-0182 X6 |
| deployment endorsement | The `seal` endorsement (ADR-0035 basis) by a `definition`-class human that moves a candidate to `sealed_candidate`; the only non-automatable pipeline transition. | ADR-0002 (ii) |
| staged exposure / rollout policy / canary mode | `RolloutPolicy{mode ∈ {shadow, split}, share, min_runs, max_duration, abort_on, advance_rule}`; `shadow` = counterfactual branch with deferred, never-released irreversible effects; `split` = the sealed candidate serves a recorded share of live goals under the principal's authority. | WS-B4 counterfactual; CF-WS-I5-07 |
| auto-revert | `revert(head) = apply(head, invert(candidate.diff))` to a human-sealed ancestor, admissible automatically on `abort_on` or an expiry veto; ledgered as `supersedes{reason: revocation}` + `lifecycle.run.rolled_back`; escalated; never a deletion. | the only automatic transition toward less exposure |
| evolution acceptance report | `{items[1..7]{status, evidence_ref}, comparisons[], portability_label, attribution_granularity, human_review}` — the seven-point standard (doc 2 §5.8; ADR-0002) as a record the seal reviews and the bundle stores. | WS-I5 / WS-I3 / WS-K2 |
| campaign stop rule | `CampaignStopRule{max_candidates, max_search_budget, max_consecutive_rejections, stop_on_no_addressable_failure}`; `NoAddressableFailure` is a typed proposer outcome. | S-094 stagnation; S-092 WebShop |
| slot allocation policy / budget-splitting trap | `SlotAllocationPolicy{floors, mode ∈ {concentrate, uniform, voi}}` governing `ProposalConstraints.target_classes`; `BudgetSplittingTrap` refuses `uniform` below the floors; `voi` is WS-F4's scheduler. | S-092 mechanism |
| parent selection policy | `{best, score_proportional{alpha, uniform_mix}, score_child_proportional{alpha, children_penalty}, pareto_per_task}` as campaign data over the `exp/` lineage. | DGM / AFlow / GEPA precedents |
| maturity flag | `maturity ∈ {instrument-grade, research-grade}` on every proposer family and campaign; `research-grade` results are `preview`-labelled and never ground a program claim; promotion requires a campaign under `matched_total` on the Stage-3 suite (OQ-WS-I5-06). | ADR-0002 (e) |
| self-improving harness taxonomy | The six classes of doc 2 §5.8 — offline harness search, continual compilation, test-time adaptation, learned harness editing, model–harness co-evolution, meta-harnessing — each mapped to a tier, a gate profile and a maturity flag (ADR-3 decision 5); two classes (continual compilation, test-time adaptation) enter the pipeline only at promotion. | doc 2 §5.8 |
| search lineage | The archive of a campaign: the `exp/<experiment_id>/` name history of sealed candidate definitions with cached `diff_ref`s and reports; keep-all is the only policy; rejected and reverted candidates remain. | ADR-0037 (4); DGM `keep_all` |
