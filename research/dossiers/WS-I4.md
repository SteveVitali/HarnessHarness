## 1. Scope & boundary

This workstream decides **how external benchmarks and their environments enter the comparison plane without becoming part of the harness**: (i) the **environment-family abstraction** — the closed list of families the stratified suite is organised by (doc 2 §8), what each family requires of an execution environment, which oracle classes exist in it, and which process metrics apply; (ii) the **`benchmark_adapter` component contract** — the operations that turn a foreign benchmark (task corpus + environment definitions + grader) into typed `TaskRecord`s, materialised environments, submissions and `Verdict`s, plus the parity obligation every adapter carries; (iii) **grader/oracle integration** — where the grader runs (shared vs separate verifier environment), what it may see, how its output is typed, and how infrastructure failure is separated from task failure; (iv) the **anti-leakage rules** — the three-surface rule (visible / held-out / instrument), the static check that a sealed Harness Definition carries no benchmark-conditioned rule, split discipline, run-time egress defaults, and contamination stratification; (v) the **first-stage (Stage 3) benchmark set** with rationale; (vi) **harness-specific benches** (Harness-Bench, Evo-Bench) as *planes HarnessHarness participates in* rather than suites it authors.

It explicitly leaves to neighbours: the environment handle itself — lifecycle, image build, snapshot/restore, upload/download, identity (**WS-B5**; requirements in §6.2 and CF-WS-I4-01); the executor and the helper boundary (**WS-E5**); the containment policy record and egress mediation (**WS-H4** — this dossier only lowers a task's declared network policy into H4's `NetPolicy`); the Validator contract, task contract, `visible`/`held_out` criteria and the `reward_hacking_gap` metric (**WS-G1** — this dossier supplies the per-suite validators and the `task_metadata_scope` G1 asked I4 to declare); judges and calibration (**WS-G3**); the factor model, matched-budget protocol and oracle taxonomy (**WS-I2**, ADR-0045…0047 — consumed verbatim); the bundle format (**WS-I3** — this dossier fixes what `TaskDataRecord` and `EnvironmentRecord` must carry for a task); the sweep engine (**WS-J3**); hosting mechanisms (**WS-J6** — this dossier fixes only that hosted participants consume the *same* `TaskRecord` and adapters); the evolution pipeline (**WS-I5** — Evo-Bench semantics); and benchmark *authorship* (N13 — never in scope).

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Every mature integration plane separates a task into the same three surfaces, but only two of the five enforce the separation in code.** Harbor's task package is `instruction.md` (visible), `environment/` (materialised), `solution/` (oracle, copied to `/solution` only by the `OracleAgent`) and `tests/` (uploaded to `/tests` **at verify time**, `verifier.py` `_resolve_tests`/`verify`); Terminal-Bench's validation adds a machine check that the Dockerfile references neither `tests/` nor the solution (S-WS-I4-09) and a canary header on every task (`original-tasks/*/task.yaml`). SWE-bench exposes `problem_statement`, `repo`, `base_commit` and the image to the agent and keeps `test_patch`/`FAIL_TO_PASS`/`PASS_TO_PASS` for the grader (SWE-agent `from_swe_bench`, mini-swe-agent `process_instance`, HAL `swebench.py` L28–50). HAL generalises this as `_strip_ground_truth` (drop declared ground-truth keys) and `_sanitize_attachment_paths` (basenames only, "identity-leaking path strings") in `base_benchmark.py` L84–100. Inspect's `Sample` carries `target` beside `input` with no enforced separation — the solver can read it. τ-bench's `Env` holds the ground-truth actions in `self.task` during the episode. Mechanism conclusion: the *visible / held-out / instrument* triple is precedented and cheap; what is new is enforcing it at the kernel (`HeldOutLeak`, WS-G1 I2) rather than by adapter discipline, and typing the third surface — the grader's own inputs — so the grader cannot read `model_claim` observations either (ADR-0016 invariant).

**F2 — Graders are separate processes reading a typed reward, and their failure is systematically distinguishable from task failure — when the harness bothers.** Harbor rejects empty, non-numeric and non-finite rewards with typed errors (`verifier.py` L67–122) and protects the reward files from the downloaded log tree; SWE-bench's `get_logs_eval` refuses a log with apply/reset/timeout markers, a log with no results *and* no sign the suite ran, and a log whose exit code contradicts its parsed statuses — and treats a *skipped* F2P test as non-resolution (`grading.py` L105–178); `infra_failure.py` classifies environment faults **post hoc, read-only, advisory** ("never decides whether an instance gets evaluated … the scoring denominator is unchanged"), in two tiers (`environment` vs `ambiguous`). SWE-bench regrades in a **pristine container from the image** with the patch applied by a `git apply` chain plus a reverse `--check` (`run_evaluation.py` L280–335), while Harbor's default verifier mode is **`shared`** (tests run in the agent's container; `separate` only when a verifier environment is declared, `verifier_mode.py`) and Terminal-Bench offers `run_tests_in_same_shell`. Mechanism conclusion: (i) the grader output contract is a typed reward with an `oracle_failure` outcome (ADR-0047 item 4, generalising Harbor); (ii) infrastructure-failure classification should be advisory and must not change denominators — but it should become an *outcome class* (`infrastructure_failure`, ADR-0045) rather than a flag beside `resolved = false`, because SWE-bench's own comment shows the denominator problem it leaves open; (iii) SWE-bench's anti-gaming checks are `trace_predicate` invariants over the verifier's own evidence and belong in the veto list (G1 `EvidenceTampered`/`VerificationSkipped`); (iv) `separate` verification is the tamper-resistant mode and `shared` is a declared weakening.

**F3 — Environment identity in every audited plane is a tag or a string, and the instrument's identity model already refuses that.** SWE-bench names images `sweb.eval.<arch>.<instance_id>:<tag>` (`image_spec.py` L37–47), SWE-agent/mini-swe-agent derive the same tag (`docker.io/swebench/…:latest`), Harbor's `EnvironmentConfig.docker_image` is a tag string and its `AgentInfo.version` a free string (CF-087), Inspect's `task_version` is an int/str. WS-L4 F8 already found Harbor computing three different ad-hoc directory digests. Mechanism conclusion (ADR-0036/0038, CF-087): an adapter must **resolve** the image digest at import (`EnvironmentRecord{image: ContentAddress | foreign_digest}`), keep the tag as a `version_label` claim, and content-address task data with the `idp/1` tree rule (`TaskDataRecord{manifest, tree, foreign_digest?}`); a task whose image cannot be resolved to a digest caps the bundle at R0 and is flagged `unpinned[]`.

**F4 — Benchmark adapters are validated by parity experiments, and the field has a machine-readable shape for them.** Terminal-Bench's SWE-bench adapter is a template (`adapters/swebench/adapter.py` `_prepare_task_from_template`: problem statement → instruction, test patch → `run-tests.sh`, gold patch → `solution.sh`, image name → compose) shipped with `parity_experiment.json` (`{adapter_name, agent, model, date, notes, forked_repo, adapter_pr, dataset_pr, metrics[{original, adapter}]}`), whose README reports 53.11 = 53.11 (Codex/o4-mini), 66.4 = 66.4, 66.8 ≈ 67.0 and names three tasks that fail *even with the oracle* for infrastructure reasons. Harbor Adapters (S-133) makes parity the acceptance rule for 80+ adapters (`provisional (mech)`). Mechanism conclusion: **an adapter is admissible only with a parity report** — a paired comparison (ADR-0046 `compare`) between the original runner and the adapted path on the same participant, model snapshot and budget, with a pre-registered margin; oracle-failing tasks are recorded as `validity = invalid` on the `TaskRecord`, never silently dropped.

**F5 — Benchmark suites have a validity lifetime, and 2026 showed both failure modes of the coding suites this workstream was asked to anchor on.** *Contamination/memorisation:* S-WS-I4-01 shows frontier models identify the buggy file from issue text alone at 76 % on SWE-bench Verified vs 53 % on repositories outside SWE-bench, with 5-gram overlap up to 35 %; S-WS-I4-02 (`provisional`) measures a 3× localisation advantage on Verified vs BeetleBox/SWE-rebench; OpenAI (S-WS-I4-03, 2026-02-23) stopped reporting Verified after finding models reproducing problem statements and fix code, and 59.4 % of audited failed hard tasks had tests that rejected functionally correct answers; SWE-rebench (S-WS-I4-05) builds a temporally fresh pool for this reason. *Task validity:* OpenAI's July 2026 audit (S-WS-I4-04) found ~30 % of SWE-Bench Pro's 731 public tasks flawed (overly strict tests, underspecified prompts, low-coverage tests, misleading prompts) with a ~70 % "noise ceiling", and retracted its own recommendation five months after making it. Terminal-Bench 2.0 documents the countermeasure at authoring time — oracle solvability, specification specificity ("tests pass iff state is correct"), anti-triviality, adversarial audit, > 3 person-hours per task — and Harbor-Index applies audit-and-fix cycles (S-133). Mechanism conclusion: (i) **suite validity is a first-class, dated record** (`SuiteValidityRecord{audit_ref, flawed_task_ids, noise_ceiling?, contamination_stratum, first_public_at, retired_for_headline?}`) that the results store carries beside every row, exactly as `claimed_level` is carried (ADR-0038); (ii) contamination cannot be prevented by the instrument, only **stratified** — every task carries `first_public_at` and every model snapshot a `training_cutoff_claim`, and capability is reported per contamination stratum; (iii) the instrument may *run* diagnostics (localisation-from-issue-text) but does not author fixes to tasks (N13) — it records `validity = invalid` and excludes with a reason.

**F6 — Network egress is the run-time leakage channel, and the audited planes treat it as a per-phase policy with declared provider support.** Harbor's `TaskConfig` carries `agent.network_mode`/`verifier.network_mode ∈ {no-network, public, allowlist}` with `allowed_hosts` normalisation, a `TrialNetworkPlan` that switches policy between the agent and verifier phases only if the provider declares `dynamic_network_policy`, and provider `EnvironmentCapabilities{disable_internet, network_allowlist*, mounted, docker_compose}` (`environments/capabilities.py`). Terminal-Bench 2.0 tasks default to no LLM access from inside the environment. WS-H4 fixes `NetPolicy{mode ∈ {none, mediated, public}, …}` with `public` requiring `principal` authority. Mechanism conclusion: a task's declared network policy is an *imported claim* that lowers into H4's `NetPolicy` per phase and is **met** with the kernel default (`none` for the agent phase at Stage 3; the model is reached through the kernel's gateway, never from inside the environment); a task requiring `public` needs a principal-endorsed amendment and is recorded as a `residual_channels` entry; the `benchmark_egress` veto reads `security.egress.*` events.

**F7 — Harness-specific benches are planes, not task sets, and "participating" has a concrete shape.** Harness-Bench (S-062) holds tasks, budgets and protocols fixed and varies the harness — precisely the instrument's own question at `product` granularity; Evo-Bench (S-067) scores a *model's* ability to evolve a harness under a sensitivity-aware split. Neither is something HarnessHarness authors. ADR-0005 already obliges the reference runtime to "act as a participant" through an ACP-style session interface or a container-installed CLI (Harbor `agents/installed/*`, `BaseAgent.run(instruction, environment, context)`). Mechanism conclusion: **participation = the native harness lowered to a Harbor-installed or ACP participant surface (WS-A4 ACP target, WS-J6/K1)**, plus **import** of the external plane's trajectories and results as `product`-granularity rows with `observability_level` set from what the artifact contains; Evo-Bench's *evolution* semantics belong to WS-I5 (C4); I4 only imports its environments and split.

**F8 — The task-facing runner interface converges on three verbs, and hosting mechanisms differ only in who calls them.** SWE-agent: `AbstractInstanceSource.get_instance_configs() → [BatchInstance{env, problem_statement}]`, `SWEEnv.start/reset`, a run hook that posts predictions; mini-swe-agent: `get_sb_environment(config, instance)`, `agent.run(task) → submission`, `preds.json`; Harbor: `BaseAgent.setup(environment)`, `run(instruction, environment, context)`, verifier after; Inspect: `sample_init` → solver → scorer; HAL: `get_dataset`, agent function, `evaluate_output`. Mechanism conclusion: the adapter contract is `import → materialize → expose → (participant runs) → collect_submission → grade → export`, and the participant — native or hosted — never calls `grade`.

## 5. Disconfirming evidence & negative results

**Against a closed environment-family enum ("families are a reporting convenience; don't type them").** Harbor runs 80+ benchmarks with one task schema and no family notion; Inspect has none; families overlap (a τ-bench task is both structured-tool and multi-turn; an AgentDojo task is both structured-tool and adversarial). *Why this does not overturn:* doc 2 §8's stratification is the ratified reporting frame and T-LCD-15 requires metrics to declare applicability — families are the thing `applies_to_families` scopes over; the enum is a closed *dialect* sum (ADR-0015) that grows by ADR, and a task may carry a primary family plus secondary tags, so overlap is representable. The alternative — inferring family from task metadata — is the T-LCD-07 coercion failure in another guise.

**Against demoting SWE-bench Verified ("the brief and doc 2 §8 name SWE-bench; the round-trip anchor needs it").** Verified is the most widely reported coding suite, mini-SWE-agent ships against it (OQ-039's T-LCD-03 anchor), and its harness (S-162) is the best-engineered grader read in this audit. *Why this does not overturn:* the evidence that it is memorised is now Tier-B/C from three independent directions (S-WS-I4-01 accepted venue; S-WS-I4-02 `provisional`; S-WS-I4-03 vendor audit) and its author community's own runner treats it as saturated. The decision is a *demotion*, not a removal: Verified (the 50-instance HAL mini and the full set) stays as (a) the T-LCD-03 round-trip fixture — paired equivalence between two arms that see identical tasks is unaffected by contamination — and (b) the `contaminated_public` stratum control that lets J4 measure how much a harness effect shrinks on fresh tasks. Headline coding capability comes from TB2 and a temporally fresh SWE-style pool. CF-WS-I4-02 records the deviation from the brief's anchor list.

**Against `separate` verification as the default ("Harbor's default is `shared`; separate doubles environment cost and breaks tasks whose state is not a patch").** Many terminal tasks have end states that are the environment itself (converted files, running services) and cannot be re-materialised from a diff; separate environments double container minutes. *Why this does not overturn:* the default is conditional — `separate` **where `collect_submission` is defined for the family** (SWE-style: a patch; τ-bench: the action log/db; AgentDojo: pre/post environment), `shared` otherwise with `verifier_isolation = shared` recorded so the tamper veto renders `n/a{no_detector}` instead of a false pass (T-LCD-15 spirit; G1 `EvidenceTampered`). SWE-bench itself pays the separate-container cost for exactly the tamper reason, and Harbor already supports `separate` with a fresh copy of the task environment.

**Against kernel-enforced anti-leakage ("adapters can just not deliver the tests").** Every audited plane relies on adapter discipline and none has been shown leaking by accident. *Why this does not overturn:* Inspect's `Sample.target` and τ-bench's in-episode ground truth show the shape that *permits* leaks; harnesses under evolution (WS-I5) will read whatever the workspace exposes (S-103 X-CPE write-target evidence via H4), and G1 already found that the visible-vs-held-out gap is the reward-hacking signal (SpecBench, S-WS-G1-04). A kernel check (`HeldOutLeak`) costs one predicate at `deliver` and one static check at import (`HeldOutInEnvironment`), and makes leakage a *veto* instead of a process convention.

**Against a static `BenchmarkConditionedRule` check ("legitimate family conditioning exists — a browser harness *should* differ from a terminal harness").** Codex and Claude Code carry benchmark-specific prompt scaffolds for SWE-bench (Terminal-Bench's `task_openhands.yaml` is one), and Harbor Adapters (S-133) evaluate each model "with Terminus-2 and one of three native harnesses" precisely because native harnesses are tuned. *Why this does not overturn:* the check forbids references to a *suite or task identifier* inside a sealed definition, not family-conditioned *variants*: a `ClassRecord`/`VariantRecord` may declare `applies_to_families` (a slot binding chosen by the experiment, visible as a factor level), and a benchmark-specific instruction enters as **task content** through the adapter's visible surface with `origin = import`, `authority = unverified` (ADR-0018 amendment; CF-082). What is refused is the T-LCD-01 analogue — `if suite == swe_bench then …` hidden inside a `HarnessRule` or `Text` leaf — because it makes the harness effect a function of the benchmark identity rather than of the task, which is the definition of leaking benchmark policy into the harness (OQ-016). Hosted participants that carry such scaffolds are simply reported at `product` granularity with `benchmark_tuned = unknown | declared` in their capability declaration.

**Against contamination stratification ("training cutoffs are unverifiable claims").** Providers rarely publish cutoffs, snapshots drift (ADR-0038 fingerprint probe is heuristic), and `first_public_at` is fuzzy for tasks derived from old commits. *Why this does not overturn:* the stratum is a **claim with provenance** (`ModelSnapshotRecord` already carries `provenance = reported`); the report shows headline capability *per stratum* and refuses to pool strata without annotation (the ADR-0038 cross-level pooling rule applied to contamination); an `unknown` cutoff yields `n/a{observability}` for the stratified view, never a coerced pooled number.

**Against parity as an adapter precondition ("n = 1 parity rows with `std_error: 0`, as Terminal-Bench ships, prove little; full parity costs a benchmark run per adapter").** *Why this does not overturn:* the obligation is the shape ADR-0046 already fixes — paired, budget-matched, with an interval and a pre-registered margin (OQ-WS-I4-06) — and it may be run on a stratified subset with `estimated{…}`; an adapter without a parity report is admissible only for `product`-granularity smoke runs flagged `parity = none`.

**Negative results from the audit.** (i) No audited plane content-addresses its environment image or task data (all tags/strings; L4 F8 confirmed for Harbor). (ii) No plane enforces held-out separation at the kernel; two (Harbor, Terminal-Bench) enforce it by upload timing and a static Dockerfile check. (iii) No plane records suite validity or contamination stratum on results rows; the 2026 audits were prose retractions. (iv) No plane distinguishes `infrastructure_failure` from failure in its *denominator* (SWE-bench flags it advisory; Harbor keeps `exception_info` beside `reward`). (v) Parity reports exist in one plane and carry no intervals.

## 6. Recommendation for the spec

### 6.1 Position (structural decisions)

1. **Integrate, never author (N13).** HarnessHarness ships *adapters* to existing benchmarks and *acts as a participant* in existing planes (ADR-0005). It never fixes a task, never publishes a task set, never hosts a public leaderboard (N4). A task found invalid is recorded as such and excluded with a reason.
2. **Environment families are a closed dialect sum, tasks carry one primary family.** `EnvironmentFamily = {coding_terminal, browser_computer, search_research, structured_tool, persistent_multi_episode, adversarial_security, long_running_recovery}` (doc 2 §8). Each family is a registry record declaring what it *requires* of the environment handle, which oracle classes exist, which process metrics apply (`MetricDeclaration.applies_to_families`, a new scoping axis parallel to `applies_to_classes`), and which fault/perturbation profiles are admissible.
3. **A task is data with three surfaces.** `TaskRecord` (§6.3) separates the **visible surface** (delivered to the participant), the **held-out surface** (grader inputs: tests, oracle solutions, goal states — never delivered; kernel-enforced `HeldOutLeak`) and the **instrument surface** (adapter/grader configuration, split, validity, contamination stratum). This is WS-G1's `visible`/`held_out` criterion split lifted to the task level.
4. **The adapter is a component class with an operation contract** (`benchmark_adapter`, ADR-0023; T-LCD-08/-12), out-of-process by default, receiving `(ModelProfile, ResourceAccount)` like every class but using the profile only to render the visible surface (never to grade). Participants never call `grade`.
5. **Grading is a G1 Validator run by the instrument** (`phase = instrument`, `visibility = held_out`, `charged_to = instrument`), per run over a boundary (ADR-0045 item 9), in a **separate** verifier environment wherever the family defines `collect_submission`, with typed rewards, `oracle_failure`/`infrastructure_failure` outcome classes, and SWE-bench's anti-gaming checks as veto `trace_predicate`s.
6. **Four leakage channels, three prevented, one measured** (§6.5): held-out surface → run (prevented: `HeldOutLeak`, `HeldOutInEnvironment`, `task_metadata_scope`); benchmark policy → definition (prevented: `BenchmarkConditionedRule`); search split → held-out split (prevented: `split_label` + ADR-0046 `LeakedSplit`); model contamination (measured: contamination strata; suite validity records).
7. **Run-time egress from the environment defaults to `none` during the agent phase**; the model is reached through the kernel gateway (C1), never from inside the environment; task-declared network needs lower into H4 `NetPolicy` and are met with the kernel default.
8. **The Stage 3 suite is stratified, dated and validity-annotated** (§6.7): Terminal-Bench 2.0 (headline `coding_terminal`), a temporally fresh SWE-style pool (headline `coding_terminal`, SWE-bench harness grading), SWE-bench Verified mini (round-trip fixture + contaminated stratum control, never headline), τ-bench retail/airline (`structured_tool`), AgentDojo (`adversarial_security`); HAL-style fault profiles over the coding suite supply `long_running_recovery` levels. Browser/computer (WebArena, OSWorld), search, persistent multi-episode: C2, after B5 declares the handle capabilities.
9. **Harness-specific benches are planes.** Harness-Bench and Evo-Bench are integrated by (a) lowering the native harness to a participant surface their runner can invoke (Harbor-installed / ACP) and (b) importing their trajectories and results as `product` rows; their task environments enter as families like any other; Evo-Bench's evolution protocol is WS-I5's.

### 6.2 Environment-family abstraction (registry records; C1/Stage 3; enum C0/Stage 1)

`EnvironmentFamilyRecord{family_id ∈ EnvironmentFamily, version, requires: HandleRequirements, oracle_classes_available ⊆ ADR-0047 classes, submission_kind ∈ {patch, end_state, output, action_log, none}, verifier_isolation_default ∈ {separate, shared}, process_metrics: [MetricRef], fault_profiles_admissible: [FaultProfileRef], perturbation_profiles_admissible: [PerturbationProfileRef], episode_model ∈ {single, multi_turn_simulated_user, multi_episode_persistent}, provenance}`.

`HandleRequirements` (what the family needs from WS-B5's environment handle; stated as tri-state capability names so B5 can declare them, T-LCD-07): `{fs_workspace, exec_shell, image_by_digest, snapshot_restore, upload_download, per_phase_network_policy, network_none, network_allowlist, detached_processes, gpu?, compose_services?, browser_handle?, display?, persistent_volume?, simulated_user_channel?}`. Family → requirements at Stage 3: `coding_terminal` = `{fs_workspace, exec_shell, image_by_digest, upload_download, per_phase_network_policy, network_none}` (+ `snapshot_restore` for `long_running_recovery` levels, `compose_services` for multi-service Harbor tasks); `structured_tool` (τ-bench) = `{simulated_user_channel}` + a tool-surface executor (E5 `remote_server`/`kernel_internal`) and **no** container; `adversarial_security` (AgentDojo) = the same plus injection-vector materialisation. Requirements the handle cannot declare `supported` refuse the family at `materialize` (`FamilyUnsupported{missing}`), never degrade silently.

**Requirements on the WS-B5 handle (CF-WS-I4-01, for B5 to adopt or counter-propose):** `open(EnvironmentSpec) → EnvHandle` resolves the image to a digest and records `action.environment.attached{env_handle, image_ref (digest), …}` (B1 taxonomy L199); `upload(tree | blob) / download(path) → ContentAddress`; `exec(command, user, env, timeout) → ExecResult` (via E5 executor); `set_phase(phase ∈ {setup, agent, verify}, NetPolicy)` with `phase.switch` refused unless the backend declares `per_phase_network_policy` (Harbor `dynamic_network_policy` precedent); `snapshot() → SnapshotRef` where declared; `default_user`; `close`. The handle's `containment` slot is H4's.

### 6.3 Task record and suite manifest (data-model sketch; schema C0/Stage 1)

```
TaskRecord {
  task_id: version_id,                      # native identity (ADR-0036); semantic_id over visible ∪ held_out ∪ environment
  foreign: { suite_ref, foreign_id, foreign_digest?: {scheme, value, source}, version_label?, first_public_at?, source_url? },   # claims (CF-087)
  family: EnvironmentFamily, tags: [FamilyTag],
  split_label ∈ {dev, search, held_out, public, private, control},
  environment: EnvironmentSpec {
      image: ContentAddress | foreign_digest_claim, build_context?: tree ContentAddress, os, resources{cpus?, memory_mb?, disk_mb?, gpus?},
      workspace: { kind ∈ {repo_snapshot, files, none}, tree?: ContentAddress, base_commit_claim? }, mcp_servers?: [Ref], healthcheck?: Text,
      network: { setup: NetPolicyRef, agent: NetPolicyRef (default none), verify: NetPolicyRef },   # lowered into H4 NetPolicy; met with kernel default
      services?: [ServiceSpec] },
  visible: { instruction: [Text{authority = unverified, origin = import}], attachments: [ContentAddress], issue_images?: [ContentAddress],
             task_metadata_scope: [ResourcePattern] },     # what the participant may read; G1 `MetadataShortcut` reads this scope
  held_out: { validators: [VersionedRef<Validator>], fixtures: [ContentAddress], goal_state?: ContentAddress, oracle_solution?: ContentAddress,
              never_delivered: true },                     # kernel: HeldOutLeak on deliver; HeldOutInEnvironment on import
  instrument: { grader: AdapterGraderSpec{ oracle_class, verifier_isolation ∈ {separate, shared}, submission_kind, timeout_ms, parser_ref?, user? },
                budget_defaults: BudgetVector (agent phase), verify_budget: BudgetVector (charged_to = instrument),
                validity: TaskValidity{ state ∈ {valid, invalid, unknown}, oracle_solution_passes: bool | unknown, anti_triviality_checked: bool, audit_ref?, reason?: Text },
                contamination: { first_public_at?, stratum ∈ {private_held_out, fresh_temporal, public_dated, contaminated_public, unknown} },
                canary?: Text, human_time_estimate_min?: { expert?, junior? }, difficulty_label?: Text },

```

`SuiteManifest{suite_id: version_id, foreign{name, version_label, source_url, digest?}, family_primary, tasks: [task_id], splits: map<split_label, [task_id]> with split_hash (ADR-0046 `task_split_hash`), validity: SuiteValidityRecord{audit_ref, audited_at, flawed_task_ids[], noise_ceiling?: decimal-string, retired_for_headline: bool, reason?}, contamination_default, adapter_ref: VersionedRef, parity: ParityReport | none, provenance}`.

Identity rules: `task_id` is computed over the canonical record excluding `foreign`, `instrument.validity/contamination` and `provenance` (they are claims and annotations, ADR-0015/0036); the environment image must be a digest for `claimed_level ≥ R2` (ADR-0038); a task with `image = foreign_digest_claim` only is admissible at R0/R1/R3 and listed in the bundle's `unpinned[]`. `split_label` and `suite_id` enter the run manifest (`lifecycle.run.created.manifest`, B1 L178, via `environment_ref` and a new `task_ref{task_id, suite_id, split_label}` field — CF-WS-I4-07 for B1/I3) so a regrade knows what it graded against (SWE-bench `write_run_metadata` precedent) and so `configuration_id`'s `environment_ref` is the digest, never the tag.

### 6.4 The `benchmark_adapter` component contract (language-agnostic; C1/Stage 3, out-of-process by default)

`ClassRecord{class_id = benchmark_adapter, cardinality = one-per-suite, required_inputs ⊇ {ModelProfile, ResourceAccount}, locality = out_of_process (default)}`. Operations:

- `declare() → AdapterDeclaration{adapter_id, version_identity, suite_family, families_supported, submission_kind, verifier_isolation_supported ⊆ {separate, shared}, export_formats[], hosting_surfaces_supported ⊆ {native_participant, container_installed, session_abi}, parity: ParityReport | none, provenance}` — tri-state fields never coerced.
- `discover(suite_source: Ref) → SuiteManifest` — enumerates foreign tasks; assigns `split_label` from the foreign split or from a pre-registered assignment (`SplitAssignmentRecord{rule, seed, registered_at}` — the search/held-out assignment is registered *before* any search run, ADR-0046 `LeakedSplit`); records `SuiteValidityRecord` from the foreign source's audit or `unknown`. Failures: `SuiteUnreachable`, `SplitUndeclared`.
- `import_task(foreign_task) → {TaskRecord, LiftReport}` — lifts foreign fields into the three surfaces; resolves the image digest (`ImageUnresolved` → `foreign_digest_claim` + `unpinned`); content-addresses task data with the `idp/1` tree rule (`TaskDataRecord`); assigns `origin = import`, `authority = unverified` to every `Text` leaf (ADR-0018 amendment, CF-082); emits a **lift loss report** naming foreign fields with no typed home (`ext` preserved byte-for-byte; T-LCD-11). Static checks at import: `HeldOutInEnvironment` (build context or workspace tree contains a held-out fixture — Terminal-Bench's Dockerfile check generalised), `CanaryMissing` (warning where the suite declares canaries), `MetadataScopeUndeclared`.
- `materialize(task_id, env_handle) → WorkspaceReady{workspace_tree: ContentAddress, phase = setup → agent}` — uploads the workspace, runs setup under the `setup` network policy, switches to the `agent` policy (`set_phase`), takes a baseline snapshot where declared. Failures: `FamilyUnsupported{missing}`, `EnvironmentUnavailable` (→ `infrastructure_failure`), `SetupFailed{evidence}`.
- `expose(task_id, profile) → VisibleSurface{context_items: [ContextItem], attachments}` — renders **only** `visible.*` into `ContextItem`s carrying `delivery_id`s (T-LCD-13) with the task's provenance; the profile chooses rendering surface only. Invariant: `∀ item ∈ VisibleSurface: item ∉ held_out` (kernel `HeldOutLeak` re-checks at `deliver`).
- `collect_submission(task_id, env_handle, run_cursor) → Submission{kind, payload: ContentAddress, collected_at_seq, evidence: [EvidenceHandle]}` — patch (`git diff` against the base tree; SWE-agent/mini-swe-agent `submission`), end-state snapshot, output artifact, or action log; content-addressed; runs after the participant's terminal event and before `verify`.
- `grade(task_id, submission | env_handle, run_cursor) → [Verdict]` — binds the task's held-out validators through the **G1 Validator contract** (`bind → collect → check → emit`), in a `separate` environment materialised from the same `EnvironmentSpec` with the submission applied (SWE-bench regrade), or `shared` where declared; runs under the `verify` network policy and `verify_budget` (`charged_to = instrument`); parses the grader's typed reward (Harbor contract: empty/non-numeric/non-finite ⇒ `OracleFailure`); evaluates the veto predicates `grader_log_inconsistent` (exit-code vs statuses), `suite_not_run`, `held_out_skipped` (SWE-bench's three checks) and `submission_apply_failed` (a `scored` failure, not infra); classifies environment faults with an advisory detector (SWE-bench `infra_failure.py` signatures) into `outcome_class = infrastructure_failure{reason, tier}` — the denominator policy is the metric's (ADR-0045), never the adapter's. Output verdicts carry `oracle_class`, `inputs_digest`, evidence handles, `verifier_isolation`.
- `export(run | experiment, format) → ForeignArtifact + LoweringLossReport` — predictions file for an external grader (`preds.json` / sb-cli), a Harbor trial directory, an Inspect log — so the *original* runner can regrade for parity and so results interoperate (ADR-0005).
- `parity(adapter, original_runner_ref, participant, model_ref, budget, design) → ParityReport` — an ADR-0046 `compare` between the original path and the adapted path on the same tasks and participant, `benefit_kind = artifact`, pre-registered margin (OQ-WS-I4-06); oracle-failing tasks land in `SuiteValidityRecord.flawed_task_ids` with `validity = invalid`, never dropped silently (Terminal-Bench README's three astropy tasks are the example).
- `probe_memorization(suite, model_ref) → DiagnosticReport` (C2, optional) — the S-WS-I4-01 localisation-from-issue-text diagnostic as an instrument-level measurement charged to the instrument; feeds the contamination stratum as evidence, never a verdict.

Invariants: (I-1) no operation other than `grade` reads `held_out`; (I-2) no participant (native or hosted) holds a capability to invoke `grade` or `collect_submission` — they are kernel-scheduled `environment_op` spans; (I-3) `grade` never consumes `model_claim` observations (ADR-0016); (I-4) the adapter is profile-blind except in `expose` (E1–E3 equivalence: the same task under two profiles yields byte-identical `held_out` and `instrument` records); (I-5) an adapter declaration without `parity` admits only `product`-granularity smoke runs flagged `parity = none`; (I-6) every lifted `Text` leaf is `origin = import`, `authority = unverified` (ADR-0033 minting rules; there is no path by which task text becomes `definition` authority except a principal `pin`).

### 6.5 Anti-leakage rules (normative; C0 slices at Stage 1, executable at Stage 3)

| channel | rule | enforcement | check / failure |
|---|---|---|---|
| **L1 held-out surface → run** | Held-out validators, fixtures, oracle solutions and goal states are never delivered, never present in the materialised environment, never reachable through `task_metadata_scope` | kernel at `deliver` (G1 I2); adapter static check at import; H4 `fs.read.deny` for the grader mount during the agent phase; G1 `MetadataShortcut` veto over the declared scope | `HeldOutLeak` (error + veto), `HeldOutInEnvironment` (import error), `metadata_shortcut` (veto) |
| **L2 benchmark policy → Harness Definition** | A sealed definition may not contain a `HarnessRule`, `ProfileRule`, `Text` leaf, slot binding or parameter value that references a `suite_id`, `task_id`, `foreign_id` or family identifier as a *condition*; family-conditioned behaviour is expressible only as a declared variant with `applies_to_families` chosen by the experiment (a visible factor level); benchmark-specific instructions are task content (visible surface, `authority = unverified`) | static check in `validate_assembly` / `seal` (ADR-0025) and in the LCD report (`lcd_report.benchmark_conditioned_rules[]`); the T-LCD-01 analogue | `BenchmarkConditionedRule{node, reference}` — error, never warning |
| **L3 search split → held-out split** | Split assignment is registered before the first search run; `artifact_benefit` rows use only `held_out`/`private` splits whose hash predates the search; a task may not change split | `SplitAssignmentRecord`; ADR-0046 `LeakedSplit`; `SuiteManifest.splits` hashed | `LeakedSplit`, `SplitMutated` |
| **L4 run-time egress** | Agent-phase `NetPolicy.mode = none` by default; `allowlist` only for task-declared registries met with H4's meet; `public` requires principal endorsement and a `residual_channels` entry; the model is reached via the kernel gateway | H4 `ContainmentPolicy` per phase; B5 `set_phase`; `security.egress.*` events | `benchmark_egress` veto (any `security.egress.blocked/attempted` to a non-allowlisted host during the agent phase) |
| **L5 model contamination (measured, not prevented)** | Every task carries `first_public_at` and a stratum; every model snapshot a `training_cutoff_claim{value?, provenance}`; headline capability is reported per stratum; pooling strata requires an annotation; suites `retired_for_headline` render capability `n/a{class}`… no: `n/a{not_run}` for headline and appear only in control/round-trip rows | J4 report generator; `SuiteValidityRecord`; ADR-0038-style level rule applied to contamination | `StrataPooledUnannotated` (report error) |

Rule L2 is the answer to OQ-016's "transfer without leaking benchmark policy into the harness": the instrument can prove *by static check* that a harness effect measured on suite A was not produced by an `A`-conditioned rule, and by *split discipline* that it was not produced by search on the evaluation tasks; it cannot prove the model never saw the tasks — that is L5's stratum.

### 6.6 Grader/oracle integration (per-suite oracle declarations — ADR-0047 consequence "WS-I4 declares, per integrated suite, which oracle classes exist")

| suite | oracle class(es) | submission | verifier isolation | headline-eligible | veto/trace predicates | precedent |

### 6.9 Acceptance-criteria sketch (Stage 3 unless stated)

- **AC-I4-1 (three surfaces, gate; Stage 1 schema).** Every `TaskRecord` validates with disjoint `visible`/`held_out`/`instrument`; a fixture task whose build context contains a held-out fixture is refused with `HeldOutInEnvironment`; a run in which a held-out item reaches `context.artefact.delivered` trips `HeldOutLeak` and the veto column.
- **AC-I4-2 (benchmark-conditioned rule, gate; Stage 1 static).** A fixture definition with a `HarnessRule` conditioned on `suite_id = tb2` fails `seal` with `BenchmarkConditionedRule`; the same behaviour expressed as a variant with `applies_to_families = {coding_terminal}` seals and appears as a factor level in the results row.
- **AC-I4-3 (parity, executable + review).** For each Stage 3 adapter (TB2/Harbor, SWE-bench harness, τ-bench, AgentDojo) a `ParityReport` exists: paired, budget-matched, n ≥ 3 per task on a pre-registered subset, verdict `equivalent` at the registered margin; oracle-failing tasks are listed in `SuiteValidityRecord.flawed_task_ids`.
- **AC-I4-4 (grader isolation and typing).** A tampering fixture (subject overwrites the reward file / edits tests) scores `fail` under `separate` isolation and renders the tamper veto `n/a{no_detector}` under `shared`; an empty/non-finite reward yields `outcome_class = oracle_failure`; a broken-image fixture yields `infrastructure_failure{reason = container_unavailable, tier = environment}` and headline success is computed over the metric's declared denominator (AC-I2-5).
- **AC-I4-5 (egress default).** During the agent phase of a TB2 fixture, an outbound request to a non-allowlisted host is blocked, emits `security.egress.blocked`, and trips `benchmark_egress`; the model call itself succeeds through the gateway.
- **AC-I4-6 (identity).** `configuration_id.environment_ref` is an image digest for every Stage 3 task; a task importable only by tag lands in `unpinned[]` and caps `claimed_level` at R1/R3; foreign version strings appear only as `version_label`/`foreign_digest` claims (CF-087).
- **AC-I4-7 (contamination strata).** The scorecard for the coding family renders capability per stratum (`fresh_temporal`, `public_dated`, `contaminated_public`); pooling without annotation is refused; a model snapshot with `training_cutoff_claim = unknown` renders the stratified view `n/a{observability}`.
- **AC-I4-8 (split discipline).** `artifact_benefit` on a fixture whose held-out split hash postdates a `measurement.harness_edit.proposed` fails with `LeakedSplit`; `SplitAssignmentRecord` precedes the first search run in the ledger.
- **AC-I4-9 (hosted parity, Stage 4).** A hosted participant (session-ABI or container-installed) consumes the same `TaskRecord` and `expose()` output as a native participant; `grade` is invoked by the kernel for both; the hosted row differs only in `n/a{class|observability}` cells (T-LCD-06/-15).
- **AC-I4-10 (act as participant, Stage 4).** The native reference harness, lowered to a container-installed/ACP participant, completes a Harbor job on a TB2 subset; the Harbor trial result imports back as a `product` row whose `task_success` equals the native run's within the parity margin.
- **AC-I4-11 (T-LCD-03 fixture).** The mini-SWE-agent-class reference harness round-trips on stratum C (SWE-bench Verified mini) per AC-I2-6; the report labels the stratum `contaminated_public` and `retired_for_headline`.

**T-LCD statement.** Satisfies T-LCD-01 by analogue (`BenchmarkConditionedRule` is the suite-conditioned counterpart of the per-model branch), T-LCD-03 (supplies the fixture and the anchor suite), T-LCD-06 (adapters and task records add no field to native contracts; hosted participants consume the same records), T-LCD-07 (family requirements and adapter declarations are tri-state), T-LCD-09 (environment factor levels are `(image digest, fault profile, perturbation profile)`), T-LCD-10 (task identity excludes foreign labels), T-LCD-11 (lift loss report per import; export loss report per foreign format), T-LCD-12 (operation-shaped adapter contract, out-of-process), T-LCD-13 (visible surface items carry `delivery_id`s; injection vectors measured through the same chain), T-LCD-14 (task budget defaults are per-arm `eval_budget` inputs; parity is a budget-matched `compare`), T-LCD-15 (`applies_to_families` beside `applies_to_classes`; `n/a` for shared-isolation tamper vetoes). Does not address T-LCD-02/-04/-05/-08 beyond consuming them (the adapter receives the profile only for `expose`).

## 10. Confidence

**High** for the three-surface task record, the adapter operation contract, separate-verifier grading with typed rewards and outcome classes, and digest-based environment identity: five planes audited at pinned commits converge on the shapes, the kernel-side enforcement rests on ratified ADRs (0016, 0033–0035, 0038, 0045–0047) and on G1's Validator contract, and no performance number is load-bearing. **High** for the L1–L4 leakage rules as mechanisms (each has a source precedent: Harbor verify-time upload, Terminal-Bench Dockerfile check, HAL ground-truth stripping, Harbor per-phase network policy, ADR-0046 `LeakedSplit`); **medium** for the `BenchmarkConditionedRule` static check, which is `no-precedent / novel` and whose false-positive rate on legitimate family conditioning is untested. **Medium** for the Stage 3 suite composition: TB2/τ-bench/AgentDojo rest on Tier-A/C benchmarks with deterministic oracles, but the fresh SWE-style pool depends on a single-team pipeline (S-WS-I4-05) or a re-audit of a suite with a documented ~30 % flaw rate (S-WS-I4-04, vendor secondary source), and the SWE-bench Verified demotion rests on one accepted-venue paper, one preprint and a vendor post read through secondary coverage (primary returned 403). **Medium-low** for harness-specific-bench participation details (Harness-Bench corpus availability unverified, OQ-WS-I4-01) and for browser/search families (not audited; C2).
