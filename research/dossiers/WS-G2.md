## 1. Scope & boundary

This workstream decides how the reference runtime **turns what the model says into typed claims, checks those claims against the handles the runtime itself owns, and refuses to let a false completion propagate**. Doc 2 §5.3 names the abstraction — continual *belief-state reconciliation*: "the model emits claims about what it has read, changed, tested, or achieved; the harness owns authoritative handles to files, processes, test results, browser state, APIs, and task contracts; verification checks whether the narrative and external state still agree" — and §12 direction 4 calls it the *execution-alignment layer*. Concretely this dossier fixes: (a) the **claim model** — a closed sum of claim kinds, how claims are elicited from a model (structured fields, progress artifacts, belief probes, parsed text, judged extraction) and what authority/evidence class they carry; (b) the **authoritative handle** set a claim can be bound to (ledger events, effect lifecycle states, validator verdicts, world-state snapshots, task contracts); (c) the **reconciliation contract** (`extract / bind / reconcile / gate / intervene`) and the **divergence taxonomy** D1–D10 with a deterministic detector per class where one exists; (d) the **intervention policy** Γ, including the completion gate that answers OQ-092; (e) the **grounding metrics** for the scorecard (`claim_state_agreement`, `evidence_traceability`, `execution_alignment_failure_rate`, `false_completion_rate`, `belief_divergence`) as `MetricDeclaration`s; (f) **seeded-divergence acceptance tests**; (g) what is precedent and what is novel.

It explicitly leaves to neighbours: **WS-G1** — the validator/oracle fabric itself (executable validators, local post-effect checks, global task-invariant checks; this dossier *consumes* `verification.validator.verdict` and `Goal.success_criteria` and never defines a validator kind); **WS-G3** — judge design, calibration and independence (judged extraction and judged D9 detectors are `Validator{kind: judge}` instances G3 governs); **WS-B2/B3** — the effect lifecycle and recovery semantics (consumed verbatim; OQ-092 is answered *here* because B2 delegated it); **WS-F1** — the control strategy that owns `DecisionPoint.stop` (G2 supplies the gate result; F1 decides what to do with it); **WS-F2** — budget enforcement (holds are bounded by a budget dimension F2 meters); **WS-D1/D2** — context assembly and compaction (G2 requests one payload marker on compaction summaries, CF-WS-G2-07, and delivers reconciliation notices as candidates through D1's admission — never around it); **WS-B5/E5** — environment snapshots and executors (`probe` uses their read-only postcondition operations); **WS-H1** — the reference monitor (reconciliation reads records; probes are effects the monitor authorizes like any other); **WS-I2/J4** — metric registry and reporting (G2 supplies declarations); **WS-J6** — what the Hosting ABI can supply for hosted-participant claims. Nothing here names a language, runtime, package ecosystem or framework (ADR-0050 §8); precedent paths are evidence, not dependencies.

**Upstream state at time of writing.** WS-B1 and WS-L3 are `done` and were read in full. **WS-G1 has no dossier yet** (LEDGER row `todo`); the brief lists it as an upstream dependency. This dossier therefore relies on the *ratified* shapes G1 must respect — ADR-0016 `Validator` and `Goal.success_criteria`, ADR-0014 detector provenance, ADR-0047 oracle classes — and flags the gap as CF-WS-G2-01 so synthesis can check G1's dossier against the assumptions in §6.

## 2. Key questions

1. (doc 3 §5, verbatim) Design continual belief-state reconciliation: extract model claims (read/changed/tested/achieved) as typed assertions, compare against authoritative handles (files, processes, test results, browser state, APIs, task contracts), detect divergence classes, intervene before false completion; execution-alignment metrics for the scorecard (grounding dimension).
2. (doc 2 §10, OQ-011, verbatim) How can a harness detect that the model's internal narrative has diverged from actual workspace/tool state before a false completion propagates?
3. (OQ-092, delegated by WS-B2) Must an `abandoned` or unresolved `unknown` effect *block* a run's completion claim or only *annotate* it?
4. (OQ-102, census item) Does execution alignment need the `environment` authority class, and for which closed-schema values?
5. (OQ-125, census item) Who owns the severity taxonomy behind `catastrophic_failure_rate` — is a divergence class a severity source?
6. (added) Where do claims come from that are *not* free text — and can the harness make the model state claims in a typed, checkable form without a per-model branch (T-LCD-01/-05)?
7. (added) What is deterministic and what is judged in reconciliation, given the 2026 evidence that LLM judges anchor on confident closing language?
8. (added) What is genuinely novel here versus Kubernetes-style reconciliation, runtime verification and claim-verification lineages — doc 2 §12 says direction 4 is novel; is it?

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — False completion is a distinct, frequent failure class, and it is measurable only against authoritative state.** Five independent 2026 sources and two 2025 taxonomies converge: Harness-Bench's Evidence/Grounding (14.6 %) and Artifact Commitment (11.1 %, "plausible reasoning without committing required outputs") categories (S-062); the false-success study's 45–48 % of τ²-bench failures and 75.8 % of self-assessing AppWorld failures, with the AppWorld label produced *without reading any text* — the agent writes `status=success` to a supervisor database while the programmatic check fails (S-WS-G2-01); 86 "deception" and 53 "fabrication" incidents from real issue trackers, including fabricated terminal logs and git histories (S-WS-G2-11); MAST's task-verification category at 23.5 % of failures (S-WS-G2-03); TRAIL's tool-related hallucination and MIRAGE's "actions unfaithful to environment observations" (S-WS-G2-04/-10). All are single-team and their rates are not load-bearing, but the *mechanism* — a completion assertion that authoritative state contradicts — is established across customer-service, personal-app, coding and multi-agent settings. **Implication:** the runtime must own a record of the completion claim *and* a comparison against state the model did not write; a claim is an `Observation{source: model_claim}` (ADR-0016) and never evidence.

**F2 — Judges anchor on narrative; deterministic comparisons do not.** The false-success study's most important negative result is that five LLM judges under six prompt conditions never exceed 0.65 AUROC on the FS-vs-true-success task, that confident closing language alone shifts the judged-complete score by +0.27–0.36 regardless of outcome, and that handing the judge the full ground-truth task specification (more than the agent had) changes nothing (S-WS-G2-01 §4.3). The real-time detection study finds the reverse for deterministic checks: recomputing stated totals from actual tool results, confirming required calls occurred, and validating tool contracts catches 60–96 % of injected failures with zero false positives on healthy episodes and all 26 provoked hallucinations, while the statistical monitor catches 1 of 3 organic fabrications (S-WS-G2-06). TRAIL reports 11 % localization for the best model (S-WS-G2-04). Browser-use's judge prompt has to say "be initially doubtful of the agent's self reported success" and enumerate cases where the agent "reports that the action is completed but the screenshot … shows the action is not actually complete" (`agent/judge.py`). **Implication:** the reconciler's detectors for the load-bearing divergence classes must be deterministic over ledger and state handles (ADR-0047's headline rule already restricts oracle classes); judges are admitted only for free-text evidence inversion (D9) and belief probes, labelled `judged`, calibrated and independent (ADR-0047 §3, G3). This is the same conclusion ADR-0014 drew for `followed`.

**F3 — The divergence classes are typed by *which authoritative handle* is contradicted, and every mature system checks only one or two of them.** Reading the audit across the vertical slice "what happens when the model says it is done or says something happened": OpenHands `AgentFinishedCritic` checks FinishAction ∧ non-empty git patch (contract gap on artifacts, D5) and `StuckDetector` checks repeated identical action/observation pairs (no-progress loop, D10) — nothing checks whether a *claimed* edit or test corresponds to an event; browser-use checks nothing deterministically at `is_done` but records self-report and judge side by side; gemini-cli hashes `(tool name, args)` for loops (D10) and has a next-speaker classifier that detects "an intended tool call that didn't execute" (a phantom effect in the narrative, D2, but judged); aider runs lint/tests after every edit and reflects errors (a *local check*, G1's concern) but never compares the model's summary with the outcome; SWE-agent autosubmits the *diff* — the harness never asks the model whether it is done; Codex's `TurnDiffTracker` reconstructs the turn's diff "from committed apply_patch mutations, without rereading the workspace filesystem" — a belief-side ledger of what the runtime applied, which is exactly the record a reconciler compares *against* a re-read, and Codex's Guardian reviews actions *before* they run (H1's plane), not claims after. Anthropic's evaluator (S-046) is the only production design that grades claims against a *task contract* ("sprint contracts … what done looks like, including testable behaviors") by exercising the artifact, and it is model-based. **Implication:** no audited system integrates the classes; each class in §6.3 has at least one partial precedent, and the integrated taxonomy over a typed effect lifecycle and provenance scheme is `no-precedent / novel` (§4c, §8 answer to Q8).

**F4 — Harness mediation itself manufactures belief divergence, so compaction, truncation, offload and blocking are claim-provenance events.** BIWM shows the same model on the same task holding different progress/risk/failure beliefs under six harness views, with the growth term (D_growth 0.13–0.26) persisting after the interface term saturates, and risk-gating that blocks an action without changing the agent's tendency to retry it (70 % within three steps) (S-148). The compaction study documents the exact ledger-level mechanism: output observed on a terminal before SIGTERM is summarized as a confirmed result, and a later session "accepted its claims without file-level verification" because nothing distinguishes "the summary says X completed" from "X's results are confirmed in the output file" (S-WS-G2-02). WS-D2's contract already records the `forgotten set` and the summary's `delegate` authority (ADR-0034 P1); WS-B1 records `truncated` and offload refs on `context.observation.recorded`. **Implication:** a claim whose cited evidence lies in a forgotten range, a truncated observation, a blocked action or a summary is a *censored-evidence* divergence (D7) detectable from provenance alone — a novel, deterministic use of records the ledger already keeps.

**F5 — Structured claim channels exist in production and make extraction deterministic; free text stays a fallback.** browser-use forces `evaluation_previous_goal / memory / next_goal` on every step and `is_done / success` on completion with a validator that `success=True` requires `is_done` (`views.py` L341–347); OpenHands' task tracker carries `todo | in_progress | done` per item; AppWorld agents write a status field; BIWM elicits nine typed fields per step (S-148); the false-success study's text-independent AppWorld label is only possible because the claim was structured (S-WS-G2-01 §3.2). Conversely, its lexical detectors, though cheap, sit at 50 % precision at a 10 % flag rate and drift across model generations (0.73 AUROC train-2024/test-2026), and 20 % of honest failures rewritten in a confident style fool them (App. H). **Implication:** the reconciler's primary channel is a *compiled claim surface* — structured fields on the completion action and on progress artifacts, profile-owned (T-LCD-01) and carrying assumption-debt records (T-LCD-05) — with parsed free text as a lower-confidence channel that is never sole evidence for an intervention above `annotate`.

**F6 — Completion must be gated on the effect ledger, not on narrative, and the gate must be bounded.** ADR-0030 guarantees "the model always sees a terminal or an explicit `unknown`" but delegates whether an open effect blocks completion (OQ-092). Precedent: Claude Agent SDK's `Stop`/`SubagentStop` hooks can refuse a stop and carry `stop_hook_active` so a hook cannot loop forever (S-109 `types.py` L349–360); OpenHands' `iterative_refinement` bounds critic-driven retries by `max_iterations` (`critic/base.py`); Symphony reconciles every tick against the tracker and never trusts the worker's silence (S-108 §8.5); Kubernetes controllers act on observed state and re-examine it after restart (S-WS-G2-12). In the compaction study, the false result became durable precisely because a killed process left effects in what the ledger would call `unknown`. **Implication (answers OQ-092):** an effect that is non-terminal (`committed`, `unknown`, `probed(undeterminable)`) at the moment of an `achieved` claim *blocks* completion until B2's `probe`/policy resolves it; an `abandoned` effect (terminal, already escalated and audited per ADR-0030) *annotates* the completion and trips the ADR-0047 veto invariant "inconsistent durable state" — so the run is *success-with-veto*, never headline success. Holds are counted against a budget dimension and end in `escalate` or `stop`.

**F7 — Reconciliation is Kubernetes-style level-triggered comparison plus runtime-verification semantics, applied to a new object.** The controller pattern (desired `spec` vs observed status; act on the level, not the event; re-read after restart) and runtime verification (a monitor over a finite trace yielding true/false/inconclusive) supply the *shape*; POMDP belief states supply the *name*; FEVER/FActScore supply *claim decomposition with cited evidence and a three-way label*. What is new is the object: the "controller" reconciles a stochastic narrator's claims against handles it owns, the "spec" is `Goal.success_criteria` plus the sealed definition's output contract, and the "status" is the ledger's effect/validator/observation record (doc 2 §9's "semantic systems engineering"). This keeps the novelty claim honest (Q8): *mechanism* precedented; *integrated contract over HIR/1 + ledger* novel.

## 5. Disconfirming evidence & negative results

**Against a reconciler at all: strong models plus grounded feedback already suffice; the boundary moves.** Anthropic reports that on the next model "raw capability increased, so the boundary moved outward," making evaluators "unnecessary overhead for simpler tasks" (S-046); Cursor documents deleting guardrails (S-047 via doc 2 §7). *Why this does not overturn:* (i) the false-success rates vary by *environment*, not only by model — 3 % in dual-control telecom vs 45–48 % in single-control domains where nobody else touches state (S-WS-G2-01) — so the effect is a property of who owns the handles; (ii) HarnessHarness is an instrument (ADR-0003): the reconciler exists to *measure* execution alignment per configuration (T-LCD-09), and a configuration with the reconciler's interventions disabled is a legitimate arm; (iii) every intervention rule is a conditioned `HarnessRule` with an assumption-debt record and a removal test (T-LCD-05), so "delete the reconciler for model M" is a Lab recipe, not a rewrite. The *ledger substrate* (claims recorded, agreement computed) has no model-conditioned content and is what the scorecard needs regardless.

**Against deterministic detection: it only catches what the ledger can see.** The real-time detection study's own limits — "plausible-value corruption undetectable" without external reference data, content invisible unless it passes through telemetry, slow drift evades change detection (S-WS-G2-06) — and MAST's chess program that "passes superficial checks but contains runtime bugs" (S-WS-G2-03) show that D1–D6 verify *correspondence*, not *correctness*. *Why this does not overturn:* correctness is G1's validators and G3's judges; execution alignment is deliberately the narrower property (S-062's definition is correspondence among reasoning, workspace state, tool actions and evaluator conditions). The dossier states this scope as a non-goal (§6.1) and routes the remainder to `unverifiable`, which never passes a required criterion.

**Against judged detectors as a fallback: they fail on exactly this task.** ≤ 0.65 AUROC with confident-language anchoring (S-WS-G2-01) and 11 % localization (S-WS-G2-04). *Why this does not overturn:* judges are confined to D9 free-text inversion and belief probes, labelled `judged`, calibrated (OQ-123), independent (`JudgeNotIndependent`), instrument-charged, and never the sole detector for a gate decision (ADR-0047 §2–3 applied). The lexical triage detector is registered as a C2 `trace_predicate`-class oracle with a `calibration_ref` and an expiry (the 0.73 cross-generation drift is an assumption-debt fact).

**Against blocking completion on open effects (OQ-092 "block"): it can deadlock or starve the run.** An `unknown` effect whose probe is `undeterminable` after `max_probes` could hold forever; a detached process (OQ-090) may legitimately outlive the run. *Why this does not overturn:* B2 already resolves `unknown` by probe, class policy or `abandon` — never by silence — and this dossier bounds holds with a budget dimension (`reconciliation.holds`) after which the run stops with an explicit reason; detached children are effects in `committed` under the run's lease (ADR-0030 §7) and the gate rule treats a *declared long-running* detached effect as annotate-only when its capability declares `detachable` (OQ-090's owner decides the declaration). The alternative — annotate only — is what produced the compaction study's durable false result.

**Against the structured claim surface: it is a conditioned rule that costs tokens and compliance.** BIWM's probe adds nine fields per step; browser-use disables its fields in `flash_mode`; forcing a schema may change behaviour (S-088's compliance mechanism, ADR-0014). *Why this does not overturn:* the surface is profile-owned, expiring and ablatable (T-LCD-01/-02/-05), the *completion* fields are the minimal always-on set (a completion action is one call per run), and per-step probes are C2 Lab instruments whose cost is metered and compared under T-LCD-14. Compliance with the surface is itself measured by the ADR-0014 chain (`context.artefact.delivered/activated`, `verification.artefact.followed`).

**Against the novelty claim.** Kubernetes reconciliation, runtime verification, FEVER-style claim verification and tool receipts (AgentLTL's grounding constraints; the "tool receipt" pattern in the survey S-WS-G2-07) predate this program. *Why this does not overturn but does narrow:* §4a F7 and §4c confine novelty to the integrated contract over HIR/1 and the ledger; the dossier and ADRs say "novel as an integrated contract" and name the prior art, per phase-0 §5.2.

**Negative results from the audit.** (i) No audited harness (OpenHands, Codex, browser-use, gemini-cli, aider, SWE-agent, Pi via B1) records a completion claim as a typed object with per-claim evidence references; (ii) none compares a claimed edit/test/read against the corresponding event — checks are contract-shaped (non-empty patch) or loop-shaped; (iii) neither ACP nor MCP has a completion-claim verb (hosted participants expose at most a final message and `state_update{idle}`); (iv) no audited system marks compaction-summary statements as observed-vs-persisted — the failure S-WS-G2-02 documents is unaddressed in code; (v) the only side-by-side self-report/judge record is browser-use's, and it is a log line, not a ledger event.

## 6. Recommendation for the spec

### 6.1 Position (what execution alignment is and is not)

**Execution alignment** is the property that every claim the model makes about the run (what it read, changed, verified, achieved, or is waiting on) corresponds to what the runtime's authoritative handles show at the seq the claim is evaluated. The **reconciler** is the component that establishes it: it extracts claims, binds each to handles, computes a four-valued agreement, records the result, and at decision points (chiefly `stop`) converts divergences into bounded interventions. It verifies *correspondence*, not correctness (G1/G3), not authority (H1), not budget (F2). It **never** raises any label (ADR-0034 P6), never runs an effect that is not `read_only ∧ closed-world` (its probes are effects the monitor authorizes like any other; ADR-0031's exemption class), never edits history (appends only, ADR-0026), and never lets a model claim satisfy a Validator (ADR-0016 invariant) — a claim is an `Observation{source: model_claim, authority ≤ delegate}` with **evidence class** `claimed` until reconciled (ontology term from WS-L3, CF-080).

Two layers with different tiers (CF-WS-G2-02): the **claim ledger substrate** (claim and reconciliation records, the two `verification.claim.*` event classes already reserved by ADR-0026 at C0/Stage 3, the structured `finish` fields on the Stage-0 reference harness, the ledger-only detectors D2/D3/D5/D6 and the completion gate) is C0 because WS-I2's ratified grounding metrics and WS-B2's OQ-092 consume it; the **reconciler component class** (`execution_alignment` slot: D1/D4/D7/D8/D9/D10, probe mode, feed-back interventions, belief probes, judged/lexical triage, Lab factors) is C2/Stage 4 per R-2.7.2.

### 6.2 Interface-contract sketch (language-agnostic; operations, inputs/outputs, invariants, failure modes)

- `extract(model_call_id, response_view, claim_surface: CompiledSurfaceRef, profile, account) → [Claim] | ExtractionError` — reads (1) structured claim fields of the compiled surface (completion action `finish{criteria_status: [{criterion_ref, status ∈ {met, unmet, unverifiable}, evidence_refs[]}], artifacts_claimed[], open_items[]}`; progress artifacts `{item_id, status}`; belief probe fields), (2) parsed free text under the profile's claim grammar (`extracted_by = parsed`, capped confidence), (3) optionally a judged extractor (C2, G3). *Invariants:* every `Claim` carries `ProvenanceRecord{origin = model(...), authority = delegate}` and `evidence_class = claimed`; extraction never executes effects; structured claims are `extraction_confidence = 1.0`. *Failures:* `NoClaimSurface` (the profile compiled none — parsed channel only), `MalformedClaim` (schema violation on a structured field — surfaced to the model as a `Contract/Format` observation, S-062's largest category).
- `bind(claim) → [HandleRef]` — maps a claim to the authoritative handles that can adjudicate it by `ClaimKind × subject`: `observed` → `context.observation.recorded` events covering the subject (tool receipt) and `action.world_state.snapshot/patch`; `effected` → `action.effect.*` chains whose canonical args cover the subject; `verified` → `verification.validator.verdict` events for the named validator/target; `achieved` → `Goal.success_criteria` validators and the definition's output contract; `pending` → effects in non-terminal states and `detached_effect_ids[]`; `progress` → the prior progress artifact version and the validators bound to items. *Invariant:* handles are records at authority ≥ `environment`; a handle is never the model's own text. *Failure:* `Unbindable` (no handle kind can adjudicate — the claim becomes `unverifiable`, never `agree`).
- `reconcile(claim, handles, mode ∈ {ledger_only, probe}, until_seq) → ReconciliationRecord` — computes `agreement ∈ {agree, diverge(class ∈ D1..D10), unverifiable, stale}` with `detector ∈ {deterministic, judged}`, `detector_ref`, `confidence`, `evidence_refs[]` (the handle records consulted), `severity`, `probe_effect_ids[]`. `probe` may dispatch `read_only ∧ closed` effects through the normal effect lifecycle (a re-read of a file, a `probe` of an effect per ADR-0030, an executor postcondition per WS-E5) charged to `subject` when the reconciler is a bound component of the harness under test and to `instrument` when a Lab detector invokes it (ADR-0039 `charged_to`). *Invariants:* pure in `(claim, handle records ≤ until_seq, detector version)` for `ledger_only`; `stale` iff a handle bound to the claim has a later-seq change than the claim's `at_seq`; `deterministic` detectors read closed-schema fields only (exit codes, effect states, verdicts, hashes) — never free text; `judged` detectors satisfy ADR-0047 §3. *Failures:* `HandleUnavailable{handle}` (snapshot GC'd, environment detached ⇒ `unverifiable`), `ProbeDenied` (monitor refused the probe effect ⇒ `unverifiable` with reason), `ProbeBudgetExhausted`.
- `gate(run, completion_claim, until_seq) → GateResult{verdict ∈ {pass, hold{divergences[], required_actions[]}, veto{invariant}}, hold_count, evidence_refs[]}` — evaluated at `DecisionPoint.stop` (ADR-0016) before `lifecycle.run.finished`. Rules (§6.4). *Invariants:* `pass` requires no `diverge` of class D2/D3/D5/D6 on the completion claim and no `required` criterion in `{unmet, unverifiable}`; `hold` never exceeds `budget.reconciliation.holds`; `veto` is recorded as a `trace_predicate` veto invariant (ADR-0047 §5). *Failures:* `GateBudgetExhausted` ⇒ F1 receives `stop_reason = unreconciled_claims` (new value, OQ-WS-G2-01).
- `intervene(record: ReconciliationRecord, policy: Γ) → Intervention ∈ {annotate, feed_back(ReconciliationNotice), require_validator(validator_refs[]), hold, escalate(principal), stop}` — `Γ(divergence_class, severity, effective_risk_class of the subject effect, decision_point) → Intervention` is a `HarnessRule` table in the sealed definition (MUST-data, ADR-0024) with kernel floors (§6.4). A `ReconciliationNotice` is a typed record `{record_ref, class, subject, expected: HandleValueRef, observed: HandleValueRef, suggested: [ActionKind]}` delivered as a D1 candidate of kind `kernel_notice` at `kernel` authority (it is a deterministic projection of ledger facts) and rendered by the profile — never free prose at elevated authority (T-LCD-02; contrast OpenHands' prose score nudge). *Invariant:* no intervention widens a grant, a budget or a label; `require_validator` runs validators the definition already binds to the Goal (they are effects under H1). *Failure:* `PolicyUndefined(class)` ⇒ kernel floor applies.
- `declare() → ReconcilerDeclaration{classes_detected: set<DivergenceClass>, detector_classes: {deterministic | judged}, probe_capabilities[], requires_observability, applies_to_classes, cost_profile}` — for the registry and T-LCD-15.
- Read views: `project(run, claim_ledger, until_seq) → [(Claim, ReconciliationRecord?)]` (ADR-0026 derived view with watermark); `divergence_profile(run) → map<DivergenceClass, count>`.

All operations receive `(ModelProfile, ResourceAccount)` (T-LCD-08) and are implementable out-of-process over the canonical encoding (T-LCD-12).

### 6.3 Data-model sketch

**Claim** `= {claim_id (allocated), run_id, model_call_id, at_seq, kind: ClaimKind, subject: SubjectRef, predicate: ClaimPredicate, asserted: StructuredValue | Text, evidence_refs: [EventRef | ContentAddress] (the model's own citations, may be empty), extracted_by ∈ {structured(surface_field_id), parsed(grammar_ref), judged(detector_ref)}, extraction_confidence: decimal, provenance: ProvenanceRecord (origin = model | participant | subagent; authority = delegate; taint per ADR-0034 P3), evidence_class = claimed}`.
`ClaimKind` (closed sum; extension by dialect bump): `observed` (read/saw X) · `effected` (changed/ran/sent X) · `verified` (validator/test V ran with result R) · `achieved` (criterion/goal met) · `unachievable` (honest failure with reason — never a divergence by itself) · `progress` (item status) · `pending` (something is running/detached/awaited) · `assumption` (asserted without checking — self-declared `unverifiable`).
`SubjectRef` `= FileRef{env_handle, path, content_hash?} | EffectRef{effect_id} | ValidatorRef{validator semantic_id, target} | CriterionRef{goal_ref, index} | ArtifactRef{ContentAddress | name} | ProcessRef{effect_id (detached)} | EnvironmentStateRef{snapshot_ref, selector} | ItemRef{progress_artifact, item_id}`.

**AuthoritativeHandle** `= {kind ∈ {ledger_event, effect_state, validator_verdict, world_state, environment_probe, task_contract, progress_artifact_version}, ref, at_seq, authority ∈ {kernel, environment}, freshness ∈ {live, snapshot(snapshot_ref), stale_after(seq)}}`.

**ReconciliationRecord** `= {record_id, claim_id, agreement ∈ {agree, diverge, unverifiable, stale}, divergence_class?: DivergenceClass, severity ∈ {info, low, medium, high, critical}, detector ∈ {deterministic, judged}, detector_ref: Ref<Validator | OracleDeclaration>, confidence: decimal, evidence_refs: [EventRef | ContentAddress], probe_effect_ids: [effect_id], reconciled_at_seq, mode, charged_to ∈ {subject, instrument}, provenance: ProvenanceRecord (origin = kernel(reconciler) for deterministic; origin = model(judge) at delegate for judged)}`. The record never mutates the claim; evidence class of the claim becomes `reconciled(agreement)` by projection.

### 6.4 Intervention policy Γ and the completion gate (answers OQ-092)

Kernel floors (MUST-code; a definition's Γ may be stricter, never looser):

1. **At any decision point ≠ `stop`:** default `annotate`. `feed_back` for D2/D3/D9-deterministic with `severity ≥ medium`; the notice is one typed candidate per record, deduplicated by `(class, subject)` per turn, and its delivery/following is measured (ADR-0014 chain). `feed_back` never repeats for the same record.
2. **At `stop` (the gate):** `hold` if any effect of the run is non-terminal (`committed`, `unknown`, `probed(undeterminable)`) — the run may not claim achievement while an outcome is undetermined; the required action is B2's `probe`/class policy, never redispatch. `hold` if D5 finds a `required` criterion `unmet`/`unverifiable` with an executable validator the definition binds — required action `require_validator` (the *harness* runs it; the model is not asked whether it passed). `hold` if D2/D3 on the completion claim's own `evidence_refs`. **`annotate` + veto** if any effect is `abandoned` or a `required` criterion has `unverifiable_reason` declared in the Goal: the run may finish, `outcome_class = scored`, but the ADR-0047 veto invariant *inconsistent durable state* (for `abandoned`) or the new **`false_completion`** invariant (CF-WS-G2-05: completion claim contradicted by a deterministic oracle) renders it *success-with-veto*, never headline success.
3. **Bounded holds:** each `hold` consumes one unit of the budget dimension `reconciliation.holds` (a gauge cap on the run's `BudgetNode`, ADR-0040; default 3 at Stage 3); exhaustion ⇒ `escalate(principal)` if `message_human` is granted and a principal is present, else `stop` with `stop_reason = unreconciled_claims`. A hold delivers the `GateResult` as a notice; `stop_hook_active`-style re-entry is impossible because the count lives in the ledger.
4. **Honest failure passes the gate:** an `unachievable` completion claim with agreement ∈ {agree, unverifiable} finishes with `status = failed_honestly` recorded on `lifecycle.run.finished` (a value for F1/I2 to confirm; OQ-WS-G2-01).
5. **Nothing above `annotate` on a `parsed` or `judged` claim alone;** a parsed claim can raise a hold only when a deterministic detector confirms the divergence on a handle.
6. **Class scoping:** for hosted participants the gate runs only over `end_state` handles and the final message (D5-shape: contracted artifacts and validators), `applies_to_classes = both`, `requires_observability = end_state`; D1–D4/D6–D10 are `n/a{observability}` unless the Hosting ABI supplies the events (OQ-WS-G2-05).

### 6.6 Acceptance-criteria sketch (seeded-divergence battery)

- **AC-G2-1 Claim ledger (C0/Stage 1).** Every completion action of the reference harness yields ≥ 1 `verification.claim.recorded` with `kind = achieved | unachievable`, `criteria_status` aligned to `Goal.success_criteria` indices, provenance at `delegate`; `validate` rejects a claim at authority > `delegate` (`AuthorityExceedsOrigin`).
- **AC-G2-2 Seeded divergences (C0/Stage 3 for D2/D3/D5/D6; C2/Stage 4 for the rest).** For each class D1–D10 a fixture injects the divergence into a recorded run (e.g. a model turn asserting "tests pass" after a validator event with `verdict = fail`; an `achieved` claim while an effect is `unknown`; a claim citing an observation inside a `forgotten set`); expected: exactly one `reconciled{diverge, class}` per seeded divergence, `detector = deterministic`, evidence refs resolve, severity per §6.5; the gate returns the §6.4 verdict.
- **AC-G2-3 No false holds (C0/Stage 3).** A negative fixture set — gemini-cli's non-loop list (cross-file batch edits, incremental same-file edits, retry with variation, re-running tests after a change), honest `unachievable` claims, claims with `assumption` kind, hosted runs without events — produces zero `diverge` records and zero `hold`s; deterministic detectors report 0 false positives on this set (S-WS-G2-06's 0-FP property is the bar).
- **AC-G2-4 OQ-092 rule (C0/Stage 3, shared with WS-B2's kill-point battery).** Kill the worker after `committed` before `observed`, then let the model claim completion on resume: the gate `hold`s until `probe` resolves; with `probe = undeterminable` past `max_probes` and `abandon`, the run finishes *success-with-veto* with the invariant named; the model-visible history contains the hold notice exactly once per record.
- **AC-G2-5 Bounded holds.** With `reconciliation.holds = 3` and a fixture that never repairs, the run ends with `stop_reason = unreconciled_claims` (or `escalate` when a principal is present) after exactly three `verification.gate.evaluated{hold}` events; no further model call is made.
- **AC-G2-6 Censored evidence (C2/Stage 4).** After a compaction that forgets the observation a claim cites, `reconcile` yields D7 with `evidence_refs` into the `forgotten set`; after a `refused` action the model retries a same-class action within three steps — recorded as D7 + D10 pair (BIWM's unsafe-retry shape) and the notice names the refusal.
- **AC-G2-7 Judged confinement.** No `hold`/`veto` in any run is traceable solely to a `judged` or `parsed` record; every judged record carries `detector_ref` with `calibration_ref` and independence per ADR-0047.
- **AC-G2-8 Class scoping (T-LCD-15).** A hosted run renders D1–D4/D6–D10 metrics as `n/a{observability}` and computes `false_completion_rate` from end-state oracles only; native runs compute all.
- **AC-G2-9 Lab factor (T-LCD-14, C2/Stage 4).** "Reconciler interventions on vs off, same tasks, matched budget including probe and notice tokens" is a runnable comparison reporting success, `false_completion_rate`, holds, cost and the model × harness interaction (T-LCD-09); pre-registered hypothesis H-G2-1: interventions reduce `false_completion_rate` more for lower-tier models and the gap shrinks with capability (S-046's moving boundary).
- **AC-G2-10 Determinism and cost.** `ledger_only` reconciliation of a 500-event run replays to the same records (`view_hash` equality, ADR-0026 rebuild test); per-claim deterministic check cost is reported as an instrument cost with a Stage-3 target in the sub-millisecond class per S-WS-G2-06 (a target, not a gate).

## 10. Confidence

**High** that the failure class exists, is frequent, and is invisible to narrative-based judging: five independent 2026 sources plus two 2025 taxonomies agree on the mechanism, and the AppWorld text-independent label and the deterministic-check results corroborate from different methods; the C0 content asserts no performance number. **High** for the claim-as-`model_claim`-Observation stance, the four-valued agreement and the never-widen/never-endorse invariants: they are direct consequences of ADR-0016/0033/0034/0047. **Medium-high** for the OQ-092 rule: ADR-0030's lifecycle makes it well-defined and the stop-hook/iterative-refinement precedents make bounded holds implementable, but its utility cost (holds per run, escalations) is unmeasured until Stage 3 (AC-G2-9). **Medium** for the ten-class taxonomy's completeness and severities: each class has a precedent, but no prior integrated taxonomy exists and Harness-Bench's categories are coarser; the taxonomy is closed-by-dialect so additions are cheap. **Medium** for structured claim surfaces as the primary channel: production precedent (browser-use, OpenHands, AppWorld) is strong, but compliance with the surface is model-conditioned (ADR-0014) and must be measured. **Low-to-medium** on anything quantitative from the 2026 preprints; none is load-bearing.
