## 1. Scope & boundary

This workstream decides **the coordination semantics under which several HarnessHarness AgentProcesses may run at once against state that more than one of them can observe or change** — without a single giant shared context (doc 2 §10 "multi-agent consistency"; OQ-013). Concretely it fixes: (i) the **ownership model** — a closed set of *coordination objects* (run ledger, workspace subtree, memory scope, named artifact, external resource key, budget node) and the rule that each has exactly one writer at a time, conferred at spawn, fenced by the lease generation the runtime already has; (ii) the **communication model** — events and artifacts by default, and *peer messages* as labelled context items delivered through the ratified wakeup machinery, never as a side channel; (iii) the **merge contract** — a typed `merge` per object kind under a closed `MergePolicy` sum, with provenance on every merged item and conflicts surfaced as records (never overwritten, never resolved by recency or arrival order), reusing D4's conflict sets and G2's claim reconciliation as the *belief* half; (iv) the **reservation contract** for fan-out and shared resources on top of ADR-0040/0130; (v) **failure containment** — the child AgentProcess as a failure domain (own ledger, writer lease, environment handle, budget node, attenuated handles) and the parent/child crash matrix; (vi) **consistency-level declarations** — a closed set of levels each coordination object declares, drawn from the classic hierarchy; and (vii) acceptance criteria whose two headline vetoes are *no lost writes* and *conflicts surfaced, not silently overwritten*.

It explicitly leaves to neighbours: **WS-F3** — the orchestrator *procedure* (when to spawn, topology shapes, the `Delegate` decision point's contract, result summarisation, recursive delegation of a full harness; F5 supplies the objects it grants at spawn and the `merge`/`MergeReport` it calls at join — F3's dossier does not yet exist, see CF-406); **WS-F4** — *whether* a spawn is worth its marginal tokens (F5 makes fan-out reservable; F4 is a policy over `allocate/reserve`); **WS-B3** — leases, restore, wakeups (adopted verbatim: ADR-0130/0131); **WS-B5** — the environment `derive` modes D1–D6 (ADR-0138, adopted; F5 says which mode each ownership mode requires); **WS-B4** — branches and snapshots (ADR-0133, adopted; a delegation branch is `branch_kind = delegation`); **WS-D4** — memory conflict sets and the authority rule (ADR-0082, adopted; F5 only says *when* concurrent processes create them and who may resolve); **WS-G2** — claims and reconciliation (ADR-0112, adopted; a child's report is a claim); **WS-H1/H2** — delegation attenuation, label branches, clearance (ADR-0053, ADR-0054, adopted); **WS-L2** — budget nodes, `slice`/`pool`, `fan_out`/`delegation_depth` gauges (ADR-0040, adopted); **WS-L8** — organisational semantics for fleets (ownership across *humans* and tickets; F5 stops at the process boundary); **WS-J3/J4** — the experiment that compares topologies (F5 only names the factor and the matched-budget obligation). Nothing here names a language, runtime, package or framework; precedent paths are evidence, not dependencies (ADR-0050 §8).

## 4. Findings

### 4a. Mechanism evidence (a failure mode exists / an architecture is implementable)

**F1 — Every production multi-agent harness read here shares state through *one of three* channels, and only one of them has a defined write owner.** (i) *Return values*: Anthropic's lead agent receives lists and synthesises them (S-036); Codex's `wait_agent` returns a child's final status/output (`multi_agents/wait.rs` L120–160); Claude SDK subagents return text. (ii) *A shared file*: RAH's children "write to a shared output file … upon completion" (S-064 §3.2) — an append-only record per child, so writes are disjoint by construction; Prime Agent's harness state is one JSON file rewritten whole by two processes (kernel and `/refine` host), guarded only by an mtime check (`harness.py` L189–199) — a check-then-act race in which the last `os.replace` wins silently. (iii) *Messages*: Prime Agent's `agent_message.send` to parent/sibling/child or `"all"` (S-116); AutoGen's `send_message`/`publish_message` (S-145); Codex's `send_input` (parent → child only). Only the *external tracker* in Symphony has a named owner for mutation ("the orchestrator serializes state mutations through one authority", §7.4; tickets mutated by the agent only through mediated tools, §11.5). **Implication:** the ownership question is unanswered in the field except by isolation ("no shared memory or communication channel exists between sibling subagents", S-064 §3.4) or by a single authority (Symphony, Cloudflare durable object). The reference runtime already has the single-authority primitive — the fenced writer lease (ADR-0026 §5; ADR-0130 L-1) — so ownership is "one writer per coordination object, fenced by generation", generalised from the run ledger to every object a second process could write.

**F2 — Concurrent writes to a single-valued object are an error unless a reducer is declared; that rule exists in shipping code and matches the CRDT result.** LangGraph's `LastValue.update` raises `InvalidUpdateError` on two values in one super-step and its message tells the author to declare a reducer (`last_value.py` L56–66); `BinaryOperatorAggregate` folds with the declared operator and still refuses two `Overwrite`s (`binop.py` L123–142); `Topic` accumulates (`topic.py` L77–86). Shapiro et al. (S-578) give the theory: only data types whose merge is commutative, associative and idempotent (grow-only sets, counters, add/remove sets with tombstones, graphs) reach the same state without coordination; a register does not. D4 reached the same conclusion for memory from the attack side: mem0's model-decided `DELETE` was too lossy and was replaced by ADD-only with links; recency is never a sound tie-break (ADR-0082 decision 4). **Implication:** the merge contract is a closed `MergePolicy` sum in which *append/union* kinds (claim lists, evidence lists, cost charges, child result records, memory version sets) merge without conflict, and *every other kind* (a file path, a named artifact head, a keyed memory value, a budget ceiling) either has one writer or produces a conflict record. There is no policy value that means "last writer wins".

**F3 — Belief merge is not a merge of texts; it is reconciliation of claims against handles, and the ratified layers already say so.** A child's report is `Observation{source: model_claim}` at `delegate` authority (ADR-0112 decision 1) and "never evidence"; the parent's belief about what a child *did* comes from the child's ledger (`control.subagent.result{child_head, result_ref}` with a cross-run anchor — WS-H6) and from authoritative handles (effect states, validator verdicts, world state), not from the child's summary. Two siblings claiming incompatible facts about the same subject therefore never "conflict" as beliefs — they are two claims to reconcile, each `agree | diverge | unverifiable`. MAST's inter-agent modes make the failure concrete: FM-2.6 reasoning–action mismatch (13.2 %), FM-2.4 information withholding, FM-2.5 ignored input (S-403). **Implication:** "belief merge" decomposes into (a) *claims* — union, then `reconcile` per ADR-0112 (parent-side, `ledger_only` by default; `probe` only read-only); (b) *memories* — union of immutable versions, then D4 conflict sets at `write` into the parent's scope, with the parent (`delegate`) able to assert `supersedes` over a sibling's `delegate` version only because equal authority satisfies the ≥ rule and the assertion is ledgered; and (c) *workspace state* — never a belief at all: an `FsChangeSet` against the fork-point snapshot, merged as the parent's own `fs_write` effects (ADR-0138 D5).

**F4 — Isolation-by-default is the field's answer, and where isolation is relaxed the shared object needs a key and a lease.** RAH: isolated workspace, no sibling channel, depth-bounded recursion (S-064 §3.2–3.4). Anthropic: subagents "explore different aspects", results returned (S-036). Codex: children are separate threads with their own rollouts; `fork_context` copies history, it does not share it (`control.rs` L85–101). Symphony: one workspace per issue, path invariants (§9.5). Worktree practice (S-584): one worktree per agent, conflicts deferred to merge. The only relaxation with a contract is OpenHands' resource keys — `file:/a.py`, `terminal`, `browser` — with sorted acquisition and per-prefix timeouts (S-110). ADR-0138 already provides the two shapes (`fork_snapshot` for isolation; `share`/`scoped_subtree` "under E5 resource keys") and ADR-0130 the `resource(key)` lease scope. **Implication:** ownership *mode* maps onto `derive` mode: `exclusive` ownership of a subtree = `scoped_subtree`; `shared` = `share` with a `resource(key)` lease per write; default isolation = `fork_snapshot`, in which the child owns *its copy* and nothing of the parent's.

**F5 — Failure containment falls out of "each child is a run" but needs an explicit outcome sum, because silent partial results are the documented failure.** Codex `wait_agent` distinguishes `NotFound`, final and in-progress statuses and times out (`wait.rs` L92–160); Symphony has eleven attempt phases with distinct terminals (`Stalled`, `CanceledByReconciliation`) because "retry logic and logs differ" (§7.2); RAH says nothing about child failure (S-064) — the parent reads whatever is in the shared output file; MAST's FM-3.1 premature termination (6.2 %) and FM-3.2 no/incomplete verification (8.2 %) are exactly a parent treating an absent or partial child result as done. The runtime already gives a child its own ledger (ADR-0027 §6 `parent_run_id`, `spawn_event`), writer lease and independent `restore` (WS-B3 recovery table row `subagent`), environment (ADR-0138 D4 `on_parent_end`), budget node (ADR-0040 `slice`/`pool`) and attenuated handles (ADR-0053 D-1…D-3). **Implication:** the missing piece is a closed `ChildOutcome` that the parent's merge consumes, with the rule that any outcome other than `result` merges as `absent{outcome}` and blocks a completion claim that depends on it (the ADR-0113 gate applied to delegation), plus the parent/child crash matrix (§6.5).

**F6 — Messaging between agents is a real mechanism in one shipping harness and a request/response primitive in another, but no audited system labels a message or bounds its authority.** Prime Agent's `send` supports parent, sibling, child and broadcast with queued receipts (S-116); AutoGen's runtime delivers typed messages point-to-point or by topic with typed delivery failures (S-145); Codex confines input injection to parent → child (`send_input`). None attaches an authority class, taint or delivery-mode; in Prime Agent a message from a sibling that read the open web reaches the receiver as plain text. Under ADR-0034 P2 anything a child returns enters the parent at `≤ delegate` with union taint; ADR-0131 already defines at-least-once occurrence / idempotent fire delivery at decision points, never mid-effect (W-3). **Implication:** a peer message is a `ContextItem` candidate of a new kind delivered through a wakeup occurrence, labelled at `⊔(label(sender ctx), delegate)`, never an endorsement, never a grant; sibling addressing is a definition-level policy (default parent-mediated), so the topology is a Lab factor rather than a fixed feature.

**F7 — Reservation, not instruction, is the only known cure for fan-out overshoot, and the primitives are ratified.** WS-L2 F8 records that fan-out is "budgeted by instruction" in Anthropic's effort-scaling prose and by a thread cap in Codex (`agent_max_threads`, `AgentExecutionLimiter`) and Symphony (`max_concurrent_agents`); ADR-0040 gives `reserve` before every spawn, `fan_out`/`delegation_depth` as gauges whose caps refuse the next increment (`SpawnRefused`), `slice` affinity and root-first exhaustion. Depth is likewise a config constant in Codex (`DEFAULT_AGENT_MAX_DEPTH = 1`, `config/mod.rs` L247) and RAH (default 3). **Implication:** F5 adds no new resource; it fixes *what* is reserved at spawn (a `spawns` charge, a `fan_out` increment, a `delegation_depth` check, the child's `slice` or `pool` allocation, and — for `share` mode — the `resource(key)` leases the child will hold) and that all of it happens before `control.subagent.spawned` is durable, so a crash between reservation and spawn releases by lease expiry.

**F8 — Consistency levels are honestly declarable per object and differ by object.** A single run ledger under one fenced writer is a linearizable append-only log (S-579; ADR-0026 §5). Across runs the order is partial — spawn → created, result → merge — with `causes[]` and cross-run anchors, i.e. causal (S-581; ADR-0027 §5; HLC optional per OQ-081). A `fork_snapshot` child sees a *snapshot at the fork point* and nothing later (ADR-0133 decision 3; ADR-0138 D6) — snapshot isolation until merge. A `share` handle under per-key leases gives serializability *per key* and no cross-key atomicity (OpenHands sorted multi-key acquisition is the only way to get atomicity over a key *set*). The memory store under D4 is strong-eventual for versions (union) with conflict sets for keys — never last-writer-wins. Jepsen's hierarchy names all of these (S-580). **Implication:** a closed `ConsistencyLevel` sum with one value per coordination object, declared in the sealed definition's `CoordinationPolicy`, checkable at Stage 4 (AC-F5-06).

## 5. Disconfirming evidence & negative results

**Against any shared-state contract at all: the field's best results come from strict isolation and file/return-value hand-off.** RAH (S-064), Anthropic (S-036), Symphony (S-108) and the 2026 worktree consensus (S-584) all avoid shared mutable state; adding ownership, `share` mode and merge policies adds surface that most harnesses never use. *Why this does not overturn:* the default topology recommended here *is* isolation (`fork_snapshot`, results as `append`-merged records, parent-mediated messages); `share`/`scoped_subtree` and sibling messaging are C3 options a definition must declare, and their value is a Lab question (AC-F5-07) under matched budget. What isolation alone does not give — a merge that surfaces overlapping edits, a parent that cannot mistake an absent child for a finished one, a message that cannot carry authority — is exactly the failure set MAST documents.

**Against single-writer ownership: it serialises the hot path and STORM claims write-time mediation over a shared workspace beats worktrees.** S-582 reports +18.7 on Commit0-Lite for mediated shared writes. *Why this does not overturn:* STORM is a single-team 2026 preprint with unstated compute matching (`provisional`); its mechanism — "conflicting edits are detected and resolved at write time" — is *expressible* here as `share` mode with `resource(key)` leases and `MergePolicy = single_writer` per path (conflicts detected at `prepare` when the lease is held by another child), so the comparison "write-time vs merge-time conflict handling" is a component-level Lab factor rather than a foreclosed design. Hot-path serialisation is bounded by key granularity (a subtree, not the workspace) and by the OpenHands-shaped timeout refusal.

**Against surfacing every conflict: parents drown in conflict records and the model resolves them worse than a textual three-way merge would.** Git resolves most overlapping edits automatically; forcing a `MergeConflict` to a `delegate` decision point costs tokens and invites FM-2.6-style mismatches. *Why this does not overturn:* the `three_way_text` policy is admitted as a *declared* merge policy whose output is a labelled derived artifact (`⊔ inputs ⊔ delegate`-free: the merge is deterministic, so `kernel`-derived) that the completion gate's validators must pass on the *merged* state; what is refused is silent overwrite and recency. Semantic conflicts — "logic that compiles but disagrees at runtime" (S-584) — survive textual merge in every system; the only defence is validators on the merged state, which ADR-0109/0113 already require before completion.

**Against strong-eventual merge for memories: `coexist` conflict sets accumulate and no one resolves them.** D4 records the same objection; every production memory system picks recency. *Why this does not overturn:* ADR-0082 decision 4 is ratified and F5 cannot re-decide it; F5 adds the one resolver that exists in a delegation tree — the parent, which at equal `delegate` authority may assert `supersedes` over a child's version with a ledgered reason, or escalate — and measures accumulation (`conflict_sets_open_at_completion`).

**Against per-object consistency declarations: no audited harness declares anything; declarations become stale documentation.** *Why this does not overturn:* each level is *checkable* (AC-F5-06: child snapshot equals fork-point snapshot; per-key serializability under fault injection; ledger linearizability by `seq`), the declaration is MUST-data the compiler validates against the `derive` mode chosen (a `share` handle cannot declare `snapshot_at_fork`), and the Lab stratifies topologies by it — the same "declare, verify, stratify" rule T-LCD-07 applies to hosted participants.

**Against making failure containment a C3 concern: it is already C0/C1 (each child is a run).** True for crash recovery; false for the *parent's* handling of a child that did not return — RAH is silent, and MAST's FM-3.1/3.2 are the observed consequence. The `ChildOutcome` sum and the `absent{outcome}` merge rule are the small C3 addition.

**Against the evidence base: the multi-agent papers are 2026 single-team preprints and MAST is 2025 single-team.** Used for mechanism only; every contract below composes ratified ADRs and Tier-A results (CRDTs, linearizability, happened-before, the Jepsen hierarchy). No C0 element is introduced.

**Negative results from the audit.** No audited harness (Codex, OpenHands, Prime Agent, Claude SDK, AutoGen, LangGraph, Symphony, Cloudflare) records *who owns* an artifact or memory scope as a durable record; none labels an inter-agent message with authority/taint; none distinguishes an absent child result from an empty one at the type level except Codex's `AgentStatus::NotFound`; none declares a consistency level; Prime Agent's shared harness file is a live lost-write hazard (`harness.py` L189–199); RAH's shared output file relies on disjoint writers by convention. The ownership record, the labelled peer message and the consistency declaration are `no-precedent`.

## 6. Recommendation for the spec

### 6.1 Position

1. **One writer per coordination object, conferred at spawn, fenced by the lease the runtime already has.** A *coordination object* is one of a closed sum of things two AgentProcesses could write; every object has exactly one `owner` at any `seq`; ownership is a ledgered `OwnershipRecord` granted at `control.subagent.spawned` (or by a ledgered transfer) and enforced by the reference monitor at `prepare` (`NotOwner` refusal), with `lease_generation` fencing inherited from ADR-0026/0130. The parent never writes a child's ledger; a child never writes the parent's; both write their own.
2. **Communicate by events and artifacts by default; messages are labelled occurrences.** A child's results are content-addressed records the parent reads after `child_terminal`; a *peer message* is a typed occurrence (ADR-0131) delivered at a decision point as a `ContextItem` at `≤ delegate` with union taint; it cannot endorse, widen or grant (ADR-0035). Sibling addressing and broadcast are declared per definition (default: parent-mediated).
3. **Merge is typed, per object kind, under a closed `MergePolicy`; conflicts are records; nothing wins by recency or arrival.** Append/union kinds merge without conflict (CRDT-safe); single-valued kinds are single-writer or produce `MergeConflict`/`ConflictSet`; belief merge = claim union + reconciliation (ADR-0112) and memory version union + D4 conflict sets; workspace merge = `FsChangeSet` three-way against the fork-point snapshot applied as the parent's own effects (ADR-0138 D5).
4. **A child is a failure domain**: own run, writer lease, environment handle, budget node, attenuated handles, label clearance. The parent consumes a closed `ChildOutcome`; anything but `result` merges as `absent` and blocks dependent completion claims (ADR-0113).
5. **Reservation precedes spawn** (ADR-0040): `spawns`, `fan_out`, `delegation_depth`, the child's budget node and — in `share` mode — its `resource(key)` leases are all reserved before `control.subagent.spawned` is durable.
6. **Every coordination object declares a consistency level** from a closed sum named after the classic hierarchy; the compiler checks the declaration against the ownership/`derive` mode; the Lab stratifies by it.

### 6.2 Ownership model

```
CoordinationObjectKey =
    ledger{run_id}                                   -- ADR-0026: writer lease
  | workspace{env_handle_id, subtree: Path}          -- ADR-0138 derive modes
  | memory_scope{scope: PersistenceScope, store}     -- ADR-0080: one consolidation lease per scope
  | artifact_name{name: LogicalName}                 -- ADR-0037: append-only name history
  | resource{key: ResourceKey}                       -- ADR-0130 resource(key) lease; ResourceKey = closed schema
                                                     --   {fs_path, host, port, tracker_item, vcs_ref, secret_ref, custom(ns, bytes)}
  | budget_node{budget_id}                           -- ADR-0040: amend only by parent/operator

OwnershipRecord = { object: CoordinationObjectKey, owner: RunId, mode ∈ {exclusive, shared_read},
                    granted_by: EventRef (spawn | transfer | root), lease_ref: LeaseId,
                    valid: ValidityState, on_owner_end ∈ {return_to_grantor, detach_to_owner} }
```

Rules (kernel-enforced; MUST-code):
- **O-1 Exactly one owner.** For every key and `seq`, at most one `OwnershipRecord` is valid. `exclusive` = only the owner may write; `shared_read` = the owner writes, others read through `subscribe`/`project` (Cloudflare shape) and may *propose* (`MergeProposal`, §6.4).
- **O-2 Conferred, never discovered.** Ownership arrives only by `control.subagent.spawned.ownership_grants[]` (subset of the grantor's own valid ownerships — attenuation, ADR-0053 D-1 applied to objects), by `control.ownership.transferred{object, from, to, basis}` (grantor → child, or child → grantor at terminal), or at `open_run` for the root (the run owns its ledger, its root workspace handle, its `run`/`session` memory scopes, its root budget node). A key nobody owns is unwritable — never "first writer wins".
- **O-3 Fenced.** Every write to an owned object carries the owner's current `lease_generation` (writer lease for `ledger`/`memory_scope`/`artifact_name`; `resource(key)` lease for `resource`/`workspace{share}`); a stale generation is `Fenced` (ADR-0026 §5).
- **O-4 Mode ↔ derive mode.** `workspace` ownership requires: `fork_snapshot` ⇒ the child owns the *child* handle exclusively and no key of the parent's; `scoped_subtree` ⇒ `exclusive` on `workspace{parent_handle, subtree}` with `fs.write.allow = [subtree]` (ADR-0138); `share` ⇒ no standing ownership — every write acquires `resource{fs_path}` at `prepare`, canonical sorted order over the effect's `resource_keys[]` (OpenHands), bounded by `TimeoutPolicy[resource]`, refused `ResourceLockTimeout` (typed, never a deadlock).
- **O-5 Return at terminal.** On `control.subagent.result | cancelled | …`, every ownership with `on_owner_end = return_to_grantor` is transferred back in the same ledger transaction as the terminal; `detach_to_owner` (ADR-0138 D4 `detach_to_child`) keeps it with the child run and is refused for `share`/`scoped_subtree`.
- **O-6 Ownership is never authority.** Owning a `memory_scope` does not raise the label of what is written there (ADR-0080 ceilings stand); owning a `resource{tracker_item}` does not confer the credential (H3 mediates, Symphony §11.5 shape).

Operations: `grant_ownership(spawn_ctx, grants[]) → [OwnershipRecord] | NotOwned(key) | ModeConflict`; `transfer_ownership(object, from, to, basis) → EventRef | NotOwner | Fenced`; `owner_of(object, at_seq) → OwnershipRecord?` (pure projection `ownership_table = project(runs, ownership_view, until_seq)`, rebuild-equality tested per ADR-0026); `check_write(effect_id, object) → ok | NotOwner{owner} | Fenced` — called by the reference monitor at `prepare` as check 8 of a delegation-bearing run (extends the ADR-0035 seven-check set; CF-408).

### 6.3 Communication model

- **Default channels.** (a) *Task in*: the parent's spawn spec (`Delegate` payload, F3) is delivered to the child as `ContextItem`s at the parent's label (ADR-0054 child `ctx₀ = ctx(parent)`); (b) *results out*: `control.subagent.result{child_run_id, child_head{seq, hash, checkpoint_ref}, result_ref: ContentAddress, outcome: ChildOutcome}` — the parent reads the referenced `ChildResult` record and, if it needs more, the child's ledger through `read`/`project` (never the child's process memory); (c) *progress*: the parent may `subscribe` to the child's ledger tail (ADR-0026) — read-only, `shared_read` on `ledger{child}` is implicit for the grantor.
- **Peer messages.** `send_message(from: RunId, to: RunId | Broadcast{scope: children | siblings | family}, body: Text | StructuredValue, delivery_mode ∈ {follow_up, steer}, idempotency_key) → Receipt{message_id, status ∈ {queued, delivered, refused{reason}, undeliverable}}`. Implemented as `record_occurrence(subscription = to.peer_message_subscription, occurrence_key = message_id, payload_ref, provenance{origin = model(from), authority = delegate, taint = taint(ctx(from))})` (ADR-0131 decision 2) and delivered as `Cue.woken{trigger: peer_message{from}, payload_ref, delivery_mode}` at the receiver's next decision point; W-1…W-5 apply (at-least-once occurrence, idempotent fire, never mid-effect). The rendered item is a `ContextItem{kind: peer_message}` with label `⊔(ctx(from), (delegate, ∅, Public))` — the ADR-0034 P2 rule for anything a process emits. **M-1** a message never satisfies a validator, endorses, widens a grant or budget, or moves an ownership (ADR-0035 rule 1; ADR-0053); **M-2** addressing is governed by `MessagingPolicy{parent_to_child: true, child_to_parent: true, sibling: bool (default false), broadcast: bool (default false), max_pending, coalesce}` — MUST-data of the sealed definition; a refused address is `MessageRefused{policy}`; **M-3** a message to a `finished` run is `undeliverable` unless the receiver has a goal-scoped subscription (ADR-0131 W-4); **M-4** every message is a `context.artefact.delivered` with an artifact id so `activated/followed` are measurable (T-LCD-13 — the detector for MAST FM-2.5 "ignored other agent's input").
- **What is not a channel.** No process may communicate by writing to an object it does not own (O-1) — in particular not by editing a shared plan file, a shared memory entry or the parent's workspace. The Prime Agent shared-file pattern is expressible only as `artifact_name` with one owner and `MergeProposal`s from others.

### 6.4 Merge contract (belief merge with provenance and conflicts)

```
MergePolicy =
    single_writer                       -- concurrent second writer is a conflict (LangGraph LastValue shape)
  | append{dedup_by: version_id | content_address}   -- multiset/set union; CRDT-safe by construction
  | conflict_set                        -- D4 ADR-0082 (keyed memory values); coexist annotated
  | three_way_text{base: SnapshotRef, tokenizer: line | ast(grammar_ref)}   -- deterministic; unresolved hunks → MergeConflict
  | validator_selected{validator_ref}   -- best-of-n over child artifacts by a deterministic Validator (instrument-charged)
  | parent_decides                      -- surfaced to the parent's decision point; choice ledgered

MergeConflict = { conflict_id, object: CoordinationObjectKey, base_ref?, sides: [{child_run_id, version_ref, label}],
                  detector ∈ {deterministic{policy}, judged{validator_ref}}, resolution?: MergeResolution, resolved_by?: EventRef }
MergeResolution = choose{side} | supersede{new_version, reason} | coexist | escalate{principal_ref} | abandon{side}

MergeReport = { merge_id, parent_run_id, children: [{child_run_id, outcome: ChildOutcome, result_ref?}],
                merged: [{object, policy, inputs[], output_ref, label}], conflicts: [MergeConflict],
                absent: [{child_run_id, outcome}], lost_write_count: 0, provenance, derived_from: [child heads] }
```

Per object kind (the *default* policy; a definition's `CoordinationPolicy.merge_policies` may choose another admissible one):

| object kind | default policy | admissible alternatives | provenance of the merged item |
|---|---|---|---|
| child result records (`ChildResult{claims[], artifacts[], memories_written[], cost}`) | `append` | — | each record keeps the child's label; the list is `kernel`-derived |
| claims | `append` then `reconcile` per ADR-0112 (`ledger_only`; `probe` read-only) | — | claims stay `delegate`; reconciliation records `kernel` |
| memory versions written by children into a scope the parent owns | `conflict_set` (ADR-0082 detection at the parent's `write`) | `parent_decides` (parent asserts `supersedes` — legal at equal authority with a ledgered reason) | version labels unchanged; `ConflictSet` record |
| workspace (`FsChangeSet` per child vs fork-point snapshot) | `three_way_text{line}` for disjoint hunks; overlapping hunks → `MergeConflict` | `single_writer` (any overlap conflicts), `validator_selected` (pick one child's tree), `parent_decides` | applied as the parent's own `fs_write` effects with `baseline_ref` (ADR-0138 D5); merged text `derived_from = [sides]`, label `⊔ sides` |
| named artifacts (plan, progress) | `single_writer` (owner) with `MergeProposal`s from others queued as `append` | `parent_decides` | new version `supersedes{edit}`; proposal ids in `derived_from` |
| budget charges / cost rows | `append` (idempotent on `(source_event, dimension)`, ADR-0039) | — | `kernel` |
| external resources | not merged — released at terminal; state re-read through the mediated tool | — | — |

Rules (MUST-code):
- **G-1 No lost writes.** Every write a child committed to an object it owned appears in `MergeReport.merged[].inputs` or in a `MergeConflict.sides[]`; `lost_write_count` is computed by the kernel as (committed child writes) − (inputs ∪ conflict sides) and **must be 0**; a non-zero count fails the merge (`MergeIncomplete`).
- **G-2 No silent overwrite.** No `MergePolicy` value resolves two writes to a `single_writer`/keyed object by `seq`, wall-clock, arrival order or child index; the only resolutions are the closed `MergeResolution` sum, each a ledgered `control.merge.resolved{conflict_id, resolution, basis, resolver}`; `choose`/`supersede` by the parent are `delegate` decisions and the result label is the join of the chosen side and the parent's `ctx`.
- **G-3 Belief is reconciled, never merged.** A child's claim about state (`effected`, `verified`, `achieved`) becomes the parent's belief only through `reconcile` against handles; two children's incompatible claims are two `ReconciliationRecord`s, and a parent claim that depends on an `unverifiable`/`diverge` child claim inherits that class (ADR-0112 decision 7 extended: `evidence_refs` must cite the child's reconciliation, not its text).
- **G-4 Validators run on the merged state.** `merge` ends with the parent's `verify` decision point over the merged workspace/artifacts; the completion gate (ADR-0113) refuses a `finish` whose criteria cite only per-child verdicts when a `three_way_text` or `parent_decides` merge touched the criterion's evidence handles (semantic-conflict defence).
- **G-5 Absent is not empty.** A child with `outcome ≠ result` contributes nothing to `merged[]` and one entry to `absent[]`; a completion claim whose `evidence_refs` include an absent child's expected artifact is `unachievable`-class, never `achieved` (MAST FM-3.1 defence).
- **G-6 Determinism.** `merge` with policies in `{append, conflict_set, three_way_text, validator_selected}` is a pure function of `(child heads, fork-point snapshot, policy)` — `merge_hash` equal on rebuild (ADR-0026 view discipline); only `parent_decides` involves a model call, and it is charged to the parent.

Operations: `merge(parent_run, lease, children: [RunId], policy: CoordinationPolicy) → MergeReport | MergeIncomplete | ForkPointMissing | NotOwner`; `propose(object, from: RunId, version_ref) → MergeProposal` (queued for the owner; `append`); `resolve_merge(conflict_id, resolution, basis) → EventRef | IllegitimateResolution` (`escalate` requires H7; `supersede` requires the ADR-0082 authority rule); `merge_report(merge_id) → MergeReport` (projection).

### 6.5 Failure containment and the parent/child crash matrix

```
ChildOutcome = result{result_ref} | cancelled{by} | budget_exhausted{dimension} | stop{StopReason}
             | infrastructure_failure{cause} | unknown{last_durable_phase} | refused_at_spawn{reason}
```

A child AgentProcess is a **failure domain** = its own run ledger and writer lease (ADR-0026/0130), its own environment handle (`derive`; ADR-0138 D1–D4), its own budget node (`slice` default, `pool` by declaration; ADR-0040), its own attenuated handle set and clearance (ADR-0053 D-1…D-3; ADR-0054), its own subscriptions. Cross-domain edges are exactly: `control.subagent.spawned` → child `lifecycle.run.created` (`parent_anchor`), child terminal → `Trigger.child_terminal` occurrence in the parent, peer messages, and ownership records.

| event | child | parent | ledger |
|---|---|---|---|
| child crashes mid-effect | child `restore` independently (B3 table row `subagent`); its `committed` effects → `unknown → probe` per ADR-0031; irreversible never redispatched | unaffected; waits ≤ `TimeoutPolicy[subagent]`, then `cancel` → `ChildOutcome.unknown` | child `lifecycle.run.resumed`; no parent event until terminal |
| child exhausts its `slice` | ends with `stop_reason = budget_exhausted`, open effects closed | `ChildOutcome.budget_exhausted` → `absent`; unspent remainder released (ADR-0040 §2) | `control.budget.released{child_finished}` |
| `pool` root exhausted | every child receives the *root's* `Exceeded` (root-first, ADR-0040 §4) and stops at its next decision point; no effect interrupted | ends the run; `MergeReport.absent = all` | one `control.budget.exceeded` per run |
| parent crashes | continues under its own lease until terminal; then `on_owner_end` decides: `return_to_grantor` ⇒ ownership held in escrow (record `valid`, owner = grantor run) until the parent restores; `detach_to_owner` ⇒ keeps | on `restore`, open `subagent` scopes re-subscribe `child_terminal`; children already terminal are merged on the next decision point; children whose lease expired restore themselves | parent `lifecycle.run.resumed{recovery_decision}` |
| parent cancels child | `cancel` at the child's next decision point (never mid-effect, ADR-0131 W-3; WS-F2 INV-3); open effects resolved per B2; environment torn down or detached per D4 | `ChildOutcome.cancelled{parent}`; ownership returned | `control.subagent.cancelled` |
| child writes an object it does not own | `prepare` refused `NotOwner`; the child sees a typed observation | audit row | `security.policy.evaluated{check: ownership, deny}` |
| two `share`-mode children need overlapping keys | canonical sorted acquisition; the second waits ≤ `TimeoutPolicy[resource]` then `ResourceLockTimeout` (typed refusal, retryable per ADR-0107) | nothing | `lifecycle.lease.*` |
| child returns tainted results | enters parent at `⊔(child outputs) ⊔ delegate`; parent effects using them are gated as tainted (ADR-0053 D-3) | Π decides | `security.label.applied` |

Containment invariants: **C-1** no child effect executes under the parent's handles or lease; **C-2** a child's irreversible effect is the child's — the parent's `MergeReport` lists it under the child's `ChildResult.effects_irreversible[]` and the parent's completion gate treats an `abandoned` child effect as its own (ADR-0113 OQ-092 rule inherited); **C-3** killing the parent never kills a child's *committed* effect mid-flight (leases are independent); **C-4** the blast radius of a child is bounded by its handle set, its environment handle's containment and its budget node — the three records the Lab reads to stratify.

### 6.6 Reservation contract (fan-out and shared resources)

At `Delegate` (before `control.subagent.spawned` is durable), the kernel performs, in order and atomically with respect to the spawn event: (1) `check(delegation_depth + 1 ≤ cap)` else `SpawnRefused{depth}` (Codex "Solve the task yourself" shape — the refusal is a typed observation to the model); (2) `reserve(parent_budget, {spawns: 1, fan_out: +1})` else `SpawnRefused{fan_out}`; (3) `allocate(parent_budget, child_scope, spec{mode: slice | pool, …})` else `BudgetExceedsParent`; (4) `grant_ownership(...)` else `NotOwned`; (5) for `share` mode, `acquire(resource(key))` for every key in `spawn_spec.reserved_keys[]` in canonical order with `TimeoutPolicy[resource]` else `ResourceLockTimeout` (nothing partially held — all-or-nothing); (6) `derive(parent_handle, mode)`; (7) append `control.subagent.spawned{child_run_id, delegation_ref, budget_slice, isolation_mode, ownership_grants[], reserved_keys[], consistency_declarations[], merge_policy_ref, child_handles[], parent_handle, ceiling, parent_head_at_spawn}`. A crash between (2) and (7) releases reservations and leases by expiry under the parent's writer lease (ADR-0040 §3: reservations die with the holder's lease). `fan_out` decrements and `spawns` remain counted at the child's terminal. External resources (`tracker_item`, `vcs_ref`, `port`) are leases only — their *state* is re-read through the mediated capability (Symphony §11.5); the lease prevents two children claiming the same ticket/branch, it does not make the external system transactional.

### 6.7 Consistency-level declarations

```
ConsistencyLevel = linearizable_single_writer   -- one fenced writer; total order by seq (ledger; artifact_name head; budget_node)
                 | snapshot_at_fork             -- reader sees the fork-point snapshot and nothing later until merge (fork_snapshot workspace; child ctx₀)
                 | per_key_serializable         -- writes to one key are totally ordered under its lease; no cross-key atomicity (share workspace; resource keys)
                 | causal_cross_run             -- happened-before via spawn/result/message edges and causes[]; concurrent events unordered (parent↔child ledgers)
                 | strong_eventual_union        -- append/union merge; same inputs ⇒ same state (result records, claim lists, memory version sets)
                 | conflict_set_eventual        -- union + deterministic conflict records; resolution only by ledgered basis (keyed memories)
ConsistencyDeclaration = { object: CoordinationObjectKey | kind-wildcard, level, staleness_bound?: Seq | Duration, readers ∈ {owner_only, grantor, family} }
```

Rules: **K-1** the compiler refuses a declaration inconsistent with the ownership/`derive` mode (`share` ⇒ not `snapshot_at_fork`; `fork_snapshot` ⇒ not `per_key_serializable`); **K-2** `causal_cross_run` is the *only* admissible level for anything spanning two ledgers — a definition may not claim linearizability across runs (no global sequence, ADR-0027 §5); if it needs consistent snapshots across a subagent tree it declares `hlc_required = true` (OQ-081 answered for delegation-bearing runs: mandatory in `share` mode, optional otherwise); **K-3** every level has a Stage 4 check (AC-F5-06); **K-4** `CoordinationPolicy{messaging: MessagingPolicy, merge_policies: map<kind, MergePolicy>, declarations: [ConsistencyDeclaration], default_isolation ∈ {fork_snapshot (default), scoped_subtree, share}, depth_cap, fan_out_cap, on_absent_child ∈ {block_completion (default), annotate}}` is MUST-data of the sealed definition (ADR-0024), `authority_cap`-layered; a `HirDiff` that moves `on_absent_child` to `annotate`, adds `sibling`/`broadcast`, or relaxes a level is classified like `validity_delta = loosening` (CF-183 shape) and refused in evolution contexts.

### 6.9 Acceptance-criteria sketch

- **AC-F5-01 No lost writes (veto).** Fixture: N ≥ 3 children under `share` on one handle, each committing writes to overlapping and disjoint keys under fault injection (kill at KP-4/KP-6 of ADR-0132 for one child; `ResourceLockTimeout` for another). After `merge`: every child-`committed` write with a terminal `observed{applied}` is in `merged[].inputs` or a `MergeConflict.sides[]`; `lost_write_count = 0`; the Prime-Agent shape (two writers passing a staleness check and both replacing) is *unrepresentable* because the second writer is `Fenced`/`NotOwner`. Metric `coordination.lost_write_count` (`veto: true`, C3/Stage 4).
- **AC-F5-02 Conflicts surfaced, never silently overwritten (veto).** Two children edit the same hunk / write the same `subject_key` / propose the same `artifact_name`: the report carries a `MergeConflict`/`ConflictSet`; no output equals either side without a ledgered `control.merge.resolved`; `merge_hash` is identical whichever child finished first. Metric `coordination.silent_overwrite_count` (`veto: true`).
- **AC-F5-03 Ownership fence.** A child attempting `fs_write` outside its `scoped_subtree`, a `memory_write` into the parent's scope, or a message to a sibling under `sibling: false` is refused with the typed reason, audited, and never applied; a stale-generation write after a transfer is `Fenced`. (C3/Stage 4)
- **AC-F5-04 Failure domains (kill-point matrix extension).** Kill the child at each KP; kill the parent while children run; kill both. Expected per the §6.5 matrix: no duplicate effect in either run; the parent's merge after restore equals the merge without crash (`merge_hash` equal) when all children reach `result`; an absent child yields `absent[]` and a blocked completion. Reuses ADR-0132's battery with `KP-S1…S4` rows (CF-410 to WS-B3).
- **AC-F5-05 Message invariants.** A peer message containing an instruction to widen permissions or claiming task completion changes no label, grant, budget or gate; delivery yields exactly one `fired` per `message_id` under duplicate sends; `context.artefact.delivered/activated/followed` exist for the message artifact so `message.followed_rate` is computable per profile (T-LCD-13).
- **AC-F5-06 Consistency declarations hold.** `snapshot_at_fork`: the child's first `context.assembled` and its handle's `snapshot` equal the fork-point records; `per_key_serializable`: under AC-F5-01's fixture every key's write history is a total order with no interleaved `observed` between another holder's `committed` and terminal; `linearizable_single_writer`: AC-B1-11; `causal_cross_run`: every child `lifecycle.run.created` causally follows its `spawned` and every `merge` follows every input head (AC-B1-10); `strong_eventual_union`: permuting child completion order leaves `merged[]` (as a set) and `merge_hash` unchanged.
- **AC-F5-07 Topology under matched budget (T-LCD-14).** Lab recipe `lab/coordination-topology-v1`: `topology ∈ {single_agent, orchestrator_worker_isolated, orchestrator_worker_share, peer_messaging}` × `merge_policy` under `MatchSpec{matched_total}` (the child spend is `subject` spend), reporting success, `lost_write_count`, conflicts open at completion, `absent` children, approvals and cost; any "multi-agent helps" claim is a `ComparisonReport` with `budget_match.status`. (C3/Stage 4 recipe; the C4 gates of ADR-0046 apply to any evolved topology.)
- **AC-F5-08 Reservation conservation.** Reuses AC-L2-3/-5 with children as the concurrent spenders; `fan_out` never exceeds its cap; a spawn refused at step (5) of §6.6 holds no key.
- **AC-F5-09 Rebuild equality.** `ownership_table` and `merge_report` views rebuilt from the ledgers equal the live views (ADR-0026).

## 10. Confidence

**High** for the ownership rule, the fence, the reservation order and the failure-domain decomposition: they are compositions of ratified ADRs (0026/0040/0053/0130/0138) whose primitives already exist, and the single-writer-per-key rule is independently reached by Logos, Symphony, Cloudflare and the run ledger itself. **High** for "no last-writer-wins, conflicts are records": Tier-A CRDT theory, LangGraph's shipped `InvalidUpdateError`, and ratified ADR-0082 agree, and the lost-write hazard is reproduced in source (Prime Agent `harness.py`). **Medium** for the default merge policy for workspaces and for parent-mediated messaging as the default: RAH/Anthropic/Symphony practice supports isolation, but STORM (`provisional`) and Prime Agent show the alternatives are live — hence Lab factors (AC-F5-07), not fixed defaults beyond Stage 4. **Medium** for the consistency-level sum: the vocabulary is Tier-A/B, but declaring levels per object is `no-precedent` in agent runtimes and its utility is unmeasured. **Low** for any quantitative claim about coordination benefit; every such number here is `provisional` or vendor-reported and none is load-bearing. No C0 element is introduced; C3 decisions carry matched-budget conditionality.
