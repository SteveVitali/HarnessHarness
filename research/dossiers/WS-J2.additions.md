## Ontology terms

| term | definition | notes |
|---|---|---|
| registry envelope | The wrapper on every registry record: `{kind, version_id, semantic_id?, registered_at, registrar, admission, name_history_ref?, trust_record_ref?, dialect_range, registry_dialect, ext}`; generalises the ADR-0087 capability-record envelope. | ADR-0151; `ext` never decides admission, conformance or authority. |
| record kind | The closed sum (`registry/1`) of things the registry stores: `class, variant, conformance_suite, conformance_report, namespace, name_history_entry, registry_snapshot, foreign_import, sealed_definition, capability, extension, model_profile, profile_test_report, wire_dialect, model_role_table, procedure_profile, surface_family, metric_declaration, validator, environment_record, environment_family, trust_root_policy, identity_profile`. | Growth by registry dialect bump; adding a component class is a `ClassRecord` registration, not a kind. |
| registry dialect | The versioned schema of the registry's record kinds and envelope (`registry/1`), distinct from the HIR dialect a record's references are valid for (`dialect_range`). | Precedent: Inspect closed `RegistryType`; MCP registry `registryType`. |
| conformance suite | A registry record pinned to a `ClassRecord` contract version: `{tests[{test_id, kind ∈ {static, contract, executable, property}, fixture_ref, driver, oracle_class, budget, verdict_rule}], required_for_status}`; the executable battery every variant of the class is driven through. | ADR-0152; deterministic oracles only at C0. |
| conformance report | An immutable registry record `{variant_ref, suite_ref, host, produced_by ∈ {registry_ci, lab, publisher_claim}, results[], probed_declaration, run_id, stale}` produced by a ledgered `instrument`-charged run. | Reports never overwrite; `publisher_claim` never counts toward `probed`. |
| variant conformance vector | The derived view `reconcile(capability_declaration, admissible reports)` → per declaration field `{declared, probed, unknown, drift}` using the Ontology v1 *observed conformance* verdicts; `unknown` never coerced. | T-LCD-07 applied reflexively to component variants; a stratification coordinate and results-row annotation, never a silent exclusion. |
| admission status / publication status / conformance status | The three orthogonal status axes of the registry: admission per record (`resolved | sealed | quarantined | revoked`, ADR-0063), publication per name-history entry (`active | deprecated | yanked`, ADR-0037), conformance per declaration field (derived). | Rule R5: a fourth status vocabulary is a schema error. |
| namespace record | `{namespace, owners: [SignerRef | PrincipalRef], policy{who_may_publish, who_may_deprecate, who_may_yank, who_may_revoke, require_signature}, provenance}`; a layered record under `authority_cap`. | Reserved namespaces `hh/` (kernel), `local/` (principal), `exp/<experiment_id>/` (lineages; the evolution service's only publish target). |
| registry policy | The MUST-data admission policy `{require_conformance ∈ {none, declared, probed}, admissible_report_producers, require_trust_record_for_origins, require_signature_for_kinds, max_age?, collision_policy = refuse, foreign_import_default_admission = quarantined, allowed_localities_by_origin, allowed_foreign_systems[]}`. | Layered per ADR-0024; the store and operations are MUST-code. |
| slot choices / substitutable | `slot_choices(class_id, constraints, snapshot) → [ComponentVariantRef]` and `substitutable(a, b, constraints)`: the registry's deterministic answer to "which variants may fill this slot in this experiment"; the source of a definition's per-slot factor levels for WS-J3. | Requires a suite when `conformance_floor ≠ none`. |
| foreign import | A registry record kind for an entry lifted from another registry (MCP registry, ACP registry, marketplace, git, archive) with `ForeignRef{system, digest?, label}`, `admission = quarantined` by default and a `LossReport`; hosted-agent manifests lift to participant descriptors, never to variants. | T-LCD-06/-11; assembly time only (closed-world rule). |
| registry diagnostic | The record + event a failed `register`/`publish`/`import` produces (`{operation, reason, subject, registrar}`); the instrument never fails to start because a contribution is malformed. | Precedent: Omnigent `load_errors`. |
| not model-facing (R-NM) | The invariant that no registry operation is a `ToolCapability`, registry text never enters a model context, and a definition binding a registry operation fails `validate_assembly`; the model-facing registry is the tool catalog (ADR-0094). | Motivated by S-301/S-310 and ADR-0002 (iii). |
