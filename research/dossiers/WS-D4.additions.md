## Ontology terms

| term | definition | notes |
|---|---|---|
| memory lifecycle state | `lifecycle_state(v, at) ∈ {valid, superseded, revoked, expired, stale_by_dependency, unknown}` — a pure function over immutable records (supersedes edges, `RevocationRecord`, validity interval, invalidation contract, `MemoryStaleIndex`), never a stored flag; precedence `revoked > superseded > expired > stale_by_dependency > valid > unknown` | WS-D4; projects onto ADR-0014's three-valued `validity` |
| invalidation contract | `InvalidationContract{dependencies: [DependencyStamp], cache_hint, validator_ref?, freshness?, invalidation_condition?, revalidation}` on every `Memory` version; valid iff every stamp matches its dependency's current stamp, freshness holds, the validator passes and no condition holds; `unknown` iff nothing checkable is declared | WS-D4; generalizes S-077's `table_versions`+`cache_hint` and RFC 9111 validators/freshness |
| dependency stamp / dependency kind | `DependencyStamp{kind: DependencyKind, ref, stamp, granularity ∈ {row, table}}`; `DependencyKind` is the closed sum of runtime-versioned objects a memory may depend on (registry name, definition/procedure/tool-capability version, environment image, model snapshot, memory version, artifact, external resource with validator); stamps are read from kernel records, never from memory text | WS-D4 with L4/E1/B5/C1 (OQ-WS-D4-01) |
| cache hint | `cacheable | recompute | no_store` — whether a memory may persist across episodes, is derivable from the request (turn-scoped only), or must never be stored | WS-D4; S-077 + RFC 9111 `no-store` |
| revocation reason | Closed sum `{contradicted, principal_withdrawn, source_revoked, dependency_revoked, expired, migrated, poisoned, hold, release}` on a memory `RevocationRecord`; `hold`/`release` model temporary revocation without un-revoking | WS-D4; RFC 5280 reason codes; shared shape with WS-H5 |
| conflict set / subject key | `ConflictSet{conflict_id, subject_key?, members[], detector ∈ {deterministic, judged}, resolution ∈ {superseded, coexist, withheld, escalated}}`; a `SubjectKey` is a canonical key under a closed schema sealed in the definition; deterministic sets may supersede under the authority rule, judged sets only coexist/escalate | WS-D4; S-106 guard shape; ADR-0035 "model never endorses" |
| memory justification / justification scope | Kernel-stamped `Justification{kind ∈ {delivered_memory, expanded_handle, declared_input, dependency_stamp}, ref, at}` on each memory version — the TMS justification set; `justification_scope ∈ {delivered (default), subject_overlap (C2)}` | WS-D4; Doyle TMS; refines ADR-0033 `derived_from` |
| stale-by-dependency (memory) / MemoryStaleIndex | A memory version some kernel-stamped justification of which is revoked or itself stale; recorded in the derived, rebuildable `MemoryStaleIndex` (memory analogue of ADR-0037's `StaleIndex`); withheld by default, annotated never hidden | WS-D4; OQ-020 retrieval half |
| withheld record | `context.memory.read.withheld[{version_id, state, reason}]` — the ledger record of every candidate the validity/authority/readers filters removed before relevance ranking; never delivered to a model | WS-D4; S-106 "returned separately with a reason" |
| validity policy (slot) / conflict policy (slot) | `SlotDeclaration.validity_policy{admitted_states ⊆ {valid, unknown, stale_by_dependency}, conflict_policy ∈ {deliver_all_annotated, withhold_all, deliver_head_if_resolved_else_withhold}, max_stale?}`; supersedes D1's boolean `admit_unknown_validity` | WS-D4 / WS-D1 (CF-WS-D4-03) |
| memory kind | `MemoryKind = fact | preference | episode | diagnosis | recovery | procedure_pointer | summary | journal` (+ registered `ext`); fixes default contract, scope, `activation_observable` and detector class | WS-D4 / WS-D3 / WS-A2 (OQ-049) |
| revalidation | Extending a memory's validity only by writing a new version with a fresh contract and `supersedes{edit}`; reads never refresh freshness | WS-D4; rejects langgraph `refresh_on_read` |
| enforcement point (memory) | The kernel operations at which lifecycle state is checked over records: E1 `retrieve`, E2 `admit` (and handle expansion), E3 `resolve(mode = execute)`, E4 `write`; the reference monitor is deliberately not one | WS-D4; ADR-0034 P5, ADR-0037 S3 |
