# ADR-0365: R4.5c dependency admission — `rustls` =0.23.46 on the `ring` provider, the `hh-tls` home, and the closed HTTPS/mTLS scope

- **Status:** Accepted
- **Date:** 2026-10-21
- **Ticket:** R4.5c
- **Requirement ids:** DF-S2.4-2 · BL-31 · R-2.8.3 · R-2.8.4 ·
  ADR-0359 (the admission pattern this ADR follows; its `ring` pin is the
  crypto provider here) · ADR-0361 (sibling-scope precedent) ·
  ADR-0364 D1 (the TLS stream mounts beneath the one `hh_wire::http`
  codec — R4.5b's `tls_pending` refusal is retired by this landing) ·
  ADR-0266 / ADR-0340 / ADR-0341 revisit triggers (fired — answered
  below) · the 2026-10-20 operator ruling "Admit rustls (ring backend)"
  (LEDGER GATE DECISIONS Round 4) · CC1 · hermetic-deps contract
  (amended here)
- **Spec:** §5g.4 (egress — `tls.terminate` honoured) · §4 (the model
  boundary's HTTPS lane)
- **Rung (ADR-0024 obligation):** C0/C1 — every behaviour verifies over
  the committed test PKI and loopback fixtures inside the
  offline/fixture ceiling; the one public-Internet leg is a USD 0
  `live-verify` evidence record, not a new claim class.

## Context

DF-S2.4-2 owed the real TLS transport the egress mediator's `tls.terminate`
member always declared but no backend could honour; R4.5b landed the
canonical HTTP/1.1 codec (`hh_wire::http`) and answered every `https:`
endpoint with a typed `tls_pending` refusal — a place-holder, never a
downgrade. The workspace's "pure std, hermetic — do not add dependencies"
contract forbade importing a TLS stack without an admission ADR. On
2026-10-20 the operator's Round-4 ruling picked **"Admit rustls (ring
backend)"**: rustls over the already-admitted `ring =0.17.14` provider —
reusing the ADR-0359 vetting instead of pulling a second crypto
implementation (`aws-lc-rs`). R4.5c is chartered to land this ADR before
or with any `Cargo.toml` dependency line, to state the admitted graph and
API scope exactly, and to name the single workspace member that may
depend on it (CC1).

## Decision

- **D1 — the admitted crates (exact `=` pins; the resolved set matches
  `Cargo.lock` verbatim).**
  | crate | pin | crates.io published | role |
  |---|---|---|---|
  | `rustls` | `=0.23.46` | 2026-10-14T09:54:15Z (exactly 7 days before selection — meets the ≥ 7-day rule at its edge; recorded, not rounded) | the TLS state machine — client + server |
  | `rustls-webpki` | `=0.103.15` | 2026-08-21T16:40:00Z (~61 days) | certificate path validation + the cert parse `peer_identity` reads |
  | `webpki-roots` | `=1.0.9` | 2026-07-18T09:30:44Z (~95 days) | the Mozilla root set (`TLS_SERVER_ROOTS`) |
  | `rustls-pki-types` | `=1.15.1` | 2026-07-23T09:56:11Z (~90 days) | PEM/DER type shims (transitive — named for the closed scope) |
  | `zeroize` | `=1.9.1` | 2026-10-06T17:49:21Z (15 days) | key-material hygiene inside rustls (transitive) |
  | `subtle` | `=2.6.1` | 2024-06-24T17:25:24Z | constant-time compare inside webpki (transitive) |
  | `untrusted` | `=0.9.0` | 2021-07-13T22:13:26Z | untrusted-input wrapper inside ring/webpki (transitive — already in the lockfile via ADR-0359) |
  | `once_cell` | `=1.21.4` | 2026-03-12T10:59:52Z | lazy root-set internals (transitive) |
  | `ring` | `=0.17.14` | (ADR-0359's pin — unchanged) | the crypto provider — rustls's `ring` backend only |

  `cargo tree -p hh-tls` shows no further runtime crate; `ring`'s
  platform-gated build closure (`cc`, `cfg-if`, `getrandom`, `libc`,
  `shlex`, `find-msvc-tools`, `wasi`, `windows-*`) is unchanged from
  ADR-0359's — only the target-relevant subset fetches/compiles.
  None of the listed versions is yanked at the selection date
  (crates.io, checked 2026-10-21).

- **D2 — feature shape.** `rustls` builds `default-features = false,
  features = ["ring", "std", "tls12"]`: the `ring` crypto provider only
  (no `aws-lc-rs`), `std` for the `StreamOwned` API, `tls12` because the
  negotiated floor is still TLS 1.2+ (a TLS 1.3-only posture is a later
  tightening, not this ticket's). No `logging` feature — `log` stays out
  of the graph.

- **D3 — admitted API scope (closed; CC1/CC3).**
  - *The client:* `ClientConfig`/`RootCertStore`/`ClientConnection` —
    webPKI verification always on (no `dangerous()` verifier overrides,
    no insecure toggle anywhere); extra trust anchors **only** via an
    explicitly named PEM file (`extra_roots_file` — the local-CA hook);
    client-certificate presentation for mTLS.
  - *The server:* `ServerConfig`/`ServerConnection` for the committed
    test-PKI fixtures and the mediator's terminating half, including
    `WebPkiClientVerifier` client-auth — plus `peer_certificates()` →
    subject-CN/SAN extraction (the `PeerIdentity` the R4.7a credential
    mediator consumes).
  - *The codec mount:* `StreamOwned`/`complete_io` over `Read+Write`
    only — the TLS stream rides **beneath** `hh_wire::http`
    (`write_request`/`read_response_full`/`read_request`); no second
    HTTP stack is admitted or built (ADR-0364 D1 honoured).
  - *Not admitted:* `rustls` QUIC/`early-data`/`key-log`/`resumption`
    knobs, `dangerous()` verifier/hook APIs, `pemfile`-style helper
    crates (PEM parsing is `hh-tls`'s own ~40-line `pem` module — one
    canonical parser), `rustls-native-certs` (the OS trust store is
    deliberately not consulted — roots are webpki-roots + the explicit
    file, never ambient platform state), and every other crate.
  - **The one crate that may name this graph is `hh-tls`** (workspace
    member; the TLS home — CC1). `hh-gateway`, `hh-env`, `hh-embed`
    consume `hh_tls::{ClientTls, ServerTls, TlsStream, ServerTlsStream,
    PeerIdentity, TlsError}` only; every other member stays
    dependency-free.

- **D4 — the offline clause is amended the same way ADR-0359 D4 amended
  it.** The lockfile's external set grows by the D1 rows; the fetch
  posture is unchanged — `cargo fetch --locked` in CI, one pinned
  registry fetch on a cold cache, `cargo build --offline` on a warm one.
  A committed vendor tree stays rejected (the D4 measurement stands;
  the rustls graph is small against `ring`'s already-admitted build
  closure).

- **D5 — `unsafe`/C-toolchain exceptions unchanged.** `hh-tls` and every
  workspace member keep `#![forbid(unsafe_code)]`; the foreign-code
  exception stays inside the ADR-0359-named crates plus the D1 set
  (rustls/webpki are safe-Rust; `ring` carries the C/asm surface this
  stack still builds on).

- **D6 — the contract amendments land in this PR, with this ADR.** The
  root `Cargo.toml` header note, the root `AGENTS.md` "Pure std,
  hermetic — modulo ADR-0359" clause and its "Don't add runtime
  dependencies" item, `crates/AGENTS.md`'s dependency-free convention,
  and `README.md`'s hermetic claim are amended to name this ADR and the
  admitted scope — the dependency is never a silent `Cargo.toml` edit.
  `docs/tickets/DEFERRALS.md` DF-S2.4-2 flips `DONE` with dated evidence;
  `docs/build/COVERAGE_MATRIX.md`'s `MET-ENGINEERED(DF-S2.4-2)`
  qualifiers on R-2.8.3/R-2.8.4 drop.

- **D7 — `tls.terminate` semantics.** `hh_env::egress::LocalTlsTransport`
  answers `terminates_tls() = true` and forwards through
  `hh_tls::ClientTls` — the mediator's TLS leg is a real terminated
  session, the `tls_terminated` member on `decided` rows reports the
  truth, and a policy requiring termination against a non-terminating
  transport still refuses `tls_terminate_unsupported` (the R2.9b
  enforce-or-refuse invariant is untouched). Revocation intents carry
  the destination's declared `scheme` (an `https` intent dispatches the
  `https_connect` leg — the revoke rides the carrier the credential
  rode).

- **D8 — fired revisit triggers answered.**
  - *ADR-0266 (D7 plain-HTTP posture):* a TLS-terminating transport has
    landed — the "plain HTTP to a checked address" posture now carries
    its intended scope: loopback/plain legs only; TLS legs terminate at
    the mediator with real verification. Dated note appended.
  - *ADR-0340 (D3 `decided_by`):* the transport lands with **no second
    endorsement channel** — `decided_by` stays monitor-or-endorsement;
    the trigger's conditional ("if a second channel appears") does not
    hold. Dated note appended.
  - *ADR-0341 (D3 `terminates_tls`):* the capability is real —
    `terminates_tls()` is now a transport property with an
    implementation, not a stub; cipher/version members of `TlsConfig`
    gain no new enforcement at this rung (recorded scope). Dated note
    appended.

## Consequences

- `hh-tls` is the workspace's one TLS home: HTTPS client sessions with
  webpki verification (extra roots via the explicit file only), mTLS
  client-cert presentation, fixture/mediator server configs, verified
  peer identity — all typed-refusal (`TlsError`), never silent degrade.
- `hh-wire::http` carries `http`/`https` schemes (default ports 80/443;
  every resolved address is tried — the dual-stack `localhost` case);
  `HttpModelTransport` mounts `ClientTls` beneath the same codec —
  R4.5b's `tls_pending` refusal is removed; `model_port.tls{}` members
  (`extra_roots_file`, `client_cert_file`+`client_key_file`) arm the
  lane.
- The committed test PKI (`crates/hh-tls/fixtures/pki`, generated by
  `scripts/gen-test-pki.sh`, openssl, ~100-year expiry) is TEST-ONLY
  material marked fake and allowlisted in `.gitleaks.toml`; its private
  keys are throwaway fixture keys, never a credential.
- LT-02/LT-05 re-run over a real terminated leg in
  `hh-env`'s egress battery; `https-reachability` joins the live-verify
  registry (one unauthenticated public GET through the real rustls
  client — USD 0, `skipped(<reason>)` when unreachable).
- Consumers R4.5d, R4.7, R4.7a, L4.6 inherit the `hh-tls` API; anything
  beyond D3's scope needs a sibling ADR.

## Alternatives considered

- **`aws-lc-rs` rustls backend** — a second C crypto stack beside
  `ring`; the operator's ruling picked `ring` and reusing ADR-0359's
  vetting is strictly less admitted surface; rejected.
- **`rustls-native-certs` (the OS trust store)** — ambient platform
  roots break the hermetic posture (a host's injected CA would be
  silently trusted); the explicit extra-roots file keeps every
  non-public root operator-declared; rejected.
- **A vendored tree or a hand-rolled TLS** — ADR-0359 measured and
  rejected vendoring; the H5/operator rulings already foreclosed
  in-workspace crypto construction; both rejected.
- **`rustls` 0.24/alpha lines** — pre-release or API-unstable; the
  maintained `0.23.x` line at its newest non-yanked point is the
  conservative pin; rejected.
- **Pinning the previous `0.23.x`** — `0.23.46` is the newest
  non-yanked release and passes the ≥ 7-day rule (exactly 7 days —
  recorded at the edge); an older pin would only buy margin against a
  rule already met; rejected.

## Revisit trigger

Reopen when: a RUSTSEC advisory lands against the D1 set (the pin bumps
by sibling ADR, never a silent `cargo update`); rustls is declared
unmaintained or the `ring` backend is dropped upstream; a consumer needs
an API outside D3's scope — QUIC, verifier overrides, the OS trust
store, or a second crate (sibling ADR); TLS < 1.3 must be refused by
policy (a `tls12` feature flip is then a contract decision, not a dep
change); or the operator chooses a committed-vendor posture.
