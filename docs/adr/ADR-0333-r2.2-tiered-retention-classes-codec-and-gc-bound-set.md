# ADR-0333: R2.2 tiered retention — `hot`/`warm`/`cold` classes, the `HHZ1` cold codec, and the bound-set GC seam

- **Status:** Accepted
- **Date:** 2026-10-06
- **Ticket:** R2.2
- **Requirement ids:** R-2.2.1 · R-2.2.4 · BL-11 · DF-S1.5-1 · DF-S2.9-1
- **Spec:** §5g.6 (GC contract + audit obligations) · §5a.1 §4 (the
  `subscribe` rewind) · ADR-0068 R3/R4 (retention floors; durable
  before-delete) · ADR-0027 §5 (head-move rows)
- **Rung (ADR-0024 obligation):** MUST-data — the ticket assigns an
  owned decision over retention class names, default residency rules,
  and the cold-tier at-rest representation; the new event class and the
  bound-set parameter are additive, no landed contract migrates.

## Context

Round 1 landed the `⁰ᵇ` halves of `fork`/`navigate`/`redact`/`gc`: a
direct `gc` op that commits `lifecycle.ledger.gc` before deleting bytes
and refuses `Pinned` against store-visible references. What did not land
is the *policy* machinery ADR-0068 R4 names — declared retention
classes, per-class residency, transition rows, and compression at rest —
plus two escalation emitters the §5g.6 §3 audit obligations already
check (`budget_hard_escalated`, `unknown_escalated`).

The ticket assigns the decisions: retention class names and default
residency rules are the implementer's to fix under the R4 floor ordering
(audit envelopes above experiment records above bundle manifests above
blob tiers); the compaction codec must preserve content addressing and
rebuildability.

## Decision

**D1 — Classes: `hot`, `warm`, `cold`; residency is a durable fact.**
`hot` is the default residency for unbound blob bytes; `warm` is the
retention-floor class for *bound* content (the caller-declared
retained-bundle/leaderboard citation set, plus store-visible pins);
`cold` is the compacted class — the last rung before `gc`. A declared
`RetentionPolicy { policy_ref, blob_residency_ms, bundle_retention_ms,
compress_cold }` drives `Store::evaluate_retention`; every transition
commits a `lifecycle.ledger.tier_transition` audit row `{address,
from_tier, to_tier, policy_ref, at_ms, compressed}` *before* the byte
mutation — the same durable-before-mutation rule `gc` obeys. The
residency clock is `at_ms` on the current-tier row; a blob's first row
reads `from_tier: "none"`. `policy_ref` is required and stamped on
every row; `bundle_retention_ms < blob_residency_ms` refuses
`SchemaViolation` — the R4 ordering is validated, never re-ordered.

**D2 — Transitions are monotone downward; `cold` is absorbing at
rest.** `none → hot → warm → cold`, with `hot ↔ warm` moves only while
the bound set says so: an unbound `warm` subject demotes to `hot`
(clock restarts); bound content cools `warm → cold` after
`bundle_retention_ms`. A citation arriving *after* a byte went cold
does not re-heat it — silent re-heating would rewrite a compacted
file for a fact the floor ordering does not require (`cold` bytes are
still served; they are not gone). A `cold` tier row over an
uncompressed file is a crash-gap the next pass repairs idempotently —
no new row (the durable intent already exists).

**D3 — A `tier_transition` row names its subject; it is not a content
dependency.** `pin_reason` skips `lifecycle.ledger.tier_transition`
rows: an audit fact about an address is not a live reference to its
bytes. Without the exclusion every retention-managed blob would pin
against `gc` forever, inverting the design (`cold` exists to be
collected). `lifecycle.ledger.gc`/`redacted` rows stay in the pin walk
— a tombstone naming an address remains a real dependency.

**D4 — The bound set enters through `gc_bounded`/`evaluate_retention`.**
Retained-bundle and leaderboard citations live on the Lab side — the
store cannot see them, so they arrive as an explicit
`&BTreeSet<String>` argument. `gc_bounded` refuses
`Pinned{bound_by_retention_policy}` for cited bytes (CF-347's rule made
executable); `gc` delegates with an empty set — byte-identical
behaviour for every existing caller.

**D5 — `HHZ1` cold-tier codec: compression under the same address.**
Cold bytes are framed `HHZ1` + u64-LE raw length + LZ token stream
(literal runs `0x00–0x7F`; matches `0x80|(len-4)` + u16-LE distance,
64 KiB window, greedy single-table pass — deterministic, pure std).
The blob file keeps the *plaintext* digest as its name;
`get_blob` decompresses then verifies the content address, so a
compacted blob answers its bytes, a corrupt frame answers
`BlobCorrupt`, and `ReplayValidityReport` — a pure fold over durable
state — rebuilds identically over a compacted prefix.

**D6 — The named escalation emitters land.** `Account::exhaust`
commits `lifecycle.escalation.raised{budget_id, kind: budget_hard}` in
the same atomic batch as `control.budget.exceeded` +
`control.decision{stop}`; the driver's `finish` folds the post-drain
prefix and raises `lifecycle.escalation.raised{effect_id, kind:
effect_unknown}` for every effect still `unknown` (drain-timeout and
`worker_lost` stragglers alike), skipping effects an earlier row
already names — a `Held`-completion re-entry never mints a duplicate.

**D7 — `subscribe` replay delivers the spec'd rewind.** A replayed
`lifecycle.head.moved` row is followed by `EventFrame::Rewind{to_seq,
to_event_id, reason}` — the same frame live subscribers receive via
`notify_rewind` (§5a.1 §4). Events never leave the store, so a
"compacted prefix" means compacted *bytes* behind durable envelopes:
the subscriber always sees the honest envelope sequence; content
absence answers typed `Missing{gc|redacted|key_unavailable}` /
`BlobCorrupt` — never a fabricated frame or body.

## Consequences

- `evaluate_retention` is an explicit scheduler call under the writer
  lease (audit rows land in a run's ledger); a periodic driver can call
  it without further machinery. The pass scans the blob pool — O(pool)
  per evaluation, acceptable at the fixture-verified stage.
- Bound-set knowledge is caller-supplied each call; nothing about a
  citation is durable beyond the tier rows it produced — a caller
  that forgets its bound set ages citations out, loudly (transition
  rows show `warm → cold`), never silently.
- `subscribe` replay now emits `Rewind` frames; a replay consumer must
  tolerate them (the live-stream contract already required it).
- DF-S1.5-1 and DF-S2.9-1 discharge; BL-11's retention/compression legs
  land (the replay-driver-under-recorded-policy leg is verified by
  `ac_r221_2` over a compacted prefix).

## Alternatives considered

- **A separate cold file name (`<digest>.cold`).** Rejected: two file
  spellings per address doubles `blob_status`/`gc`/`get_blob` bookkeeping
  and breaks the "file name is the content address" invariant; the
  `HHZ1` magic prefix keeps one spelling with a 4-byte check.
- **Re-heat `cold → warm` on late citation.** Rejected (D2): cooling is
  the durable direction; a citation extends warm residency only while
  the subject is warm. A future policy can add explicit re-heating as
  another row type without migrating anything.
- **Compression behind a flag off by default.** Rejected: `compress_cold`
  is already the policy member — an undeclared default would split the
  tier's meaning between policy text and store config.
- **Letting tier rows pin their subjects.** Rejected (D3) — it would
  fence every managed blob against collection permanently.

## Revisit trigger

Reopen if a policy needs re-heating `cold → warm/hot` (a citation arriving
after compaction), if the `HHZ1` codec is superseded by a framing with
seekable blocks or a compression dictionary, or if a second producer class
needs `lifecycle.ledger.tier_transition` (the class is kernel-producer
today — widening it is an audit-grade change, not a patch). The bound-set
contract also re-opens when retained-bundle/leaderboard consumers land
durable citation rows of their own (CF-347's store-side half).
