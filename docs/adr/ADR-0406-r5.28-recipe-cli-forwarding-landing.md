## Context

§2.1 binds the experiment chain to **one supported native recipe**:
one bounded composition drives launch → adopt → execution → grade →
projection → persisted analysis → receipt over the landed owners —
never a copied runtime, a shadow result/receipt store, forged
producer rows, a second codec/serializer, or a second runner/store.
§7.1 binds the selected `hh` wrappers to **exact forwarding**: the
`experiment` and `compare` verbs carry the `lab.experiment.*` /
`lab.analysis.*` members the boundary requires, verbatim — K-2 keeps
all semantics behind the boundary. Before this ticket `hharness`
held the facade re-exports but no versioned composition recipe, and
the `hh` wrappers invented shapes the boundary could never accept:
`cmd_experiment_op` forwarded `cell`/`run_id` only (claim/launch/
settle's required `run_plan_id`, launch's `lease_id`, the holder and
partial-close/bundle members all unreachable from the CLI),
`cmd_compare_report` sent a `{baseline, candidate}` body the
`analyze` op never declared, and `cmd_compare_scorecard` sent
`{view, experiment_id}` naming no persisted report. Meanwhile
`adopt_subject` (R5.7), the DispatchGate/scripted `EmbedModel` lane
(R5.8), `ResultsStore::project_and_record` (hh-results), persisted
`lab.analysis.analyze` (R5.16b), and `assemble_receipt` /
`population-receipt/1` (R5.23) all existed as separate owner
surfaces no supported path composed.

## Decision

1. **One versioned recipe `hh-recipe/1` lives at
   `hharness::recipe`** — `run_recipe(&mut EmbedService,
   &RecipePlan) → Result<RecipeReceipt, RecipeError>` in
   `crates/hharness/src/recipe.rs` (1,150 lines). The facade is the
   composition layer (I-02 — the recipe owns no semantics of its
   own); it drives binding (a)'s in-process `EmbedService::handle`,
   the same RPC surface the stdio/loopback bindings share, plus
   three owner-seam calls (`adopt_subject`,
   `ResultsStore::project_and_record`, `assemble_receipt`) and one
   kernel-direct commit (`surface_commit_row`). Records-in/
   records-out — the recipe mutates whatever store the caller's
   service owns (scratch stores only in the battery); no public
   RPC, no `hharness → hharness-cli` edge (the recipe never rides
   the CLI path — the split review's real-but-undocumented seam).
2. **`RecipePlan` is inputs-only over a closed member set** —
   `{hello, register, environment, host_capabilities?,
   subject_input, grade_metric, grades, analysis, weights,
   protocol_ref?, cost_version?, selection_ref?, max_drain?}`.
   `from_json` refuses any member outside the set and any authored
   record member — `slots`/`attempts`/`settlements`/`grades_done`/
   `rows`/`metrics`/`run_ids`/`success`/`receipt`/`notifications`/
   `requests` → `unsupported_shape` (authored rows never ride the
   plan; `analysis.rows` is refused specifically — the recipe fills
   it from projection); an absent required member →
   `missing_field`; a wrong-typed member → `type_mismatch`. The
   `register` body rides the boundary verbatim (its resolver
   members minus `spec` re-attach per `lab.experiment.*` op —
   `Bag::from_params` decodes per op); `host_capabilities` absent
   or empty means the notification channel is absent and records
   `n/a{no_callback_channels}`, never a faked drain.
3. **The phase chain composes the landed owners verbatim** —
   `hello` (the negotiated result kept verbatim on the receipt) →
   `lab.experiment.{register, expand, open_experiment}` → a bounded
   drain: `next` until `done` (a non-`plan`/`done` verdict or
   `max_drain` exhaustion → `drain_stalled` — the recipe never
   waits) → per plan `claim` → `launch` → **adopt** through
   `svc.adopt_subject` — the durable binding re-read, not the
   launch response's copy: `launch_binding` re-folded through
   `ExperimentView::fold`, the same view `adopt_subject` validates
   against, with the launch's own `subject_writer` lease
   re-presented → **execute** `submit` driving the scripted
   `EmbedModel` lane → the durable evidence gate:
   `lifecycle.run.finished` present **and** an observed
   `hh.submit` submission ref durable on the subject run — absent
   finish → `execution_incomplete`, finished-without-submission →
   `no_submission` (a process-only success never grades) →
   **grade**: the declared verdict `grades[arm_id][replicate_index]`
   (a bound slot with no entry → `grade_unspecified` — never a
   default success) committed as `measurement.metric.emitted`
   through `surface_commit_row` (`oracle_ref = hh-recipe/1`,
   `applies_to = run_id`, `evidence_ref = submission_ref`,
   `detector = Deterministic`) → `settle` →
   `lab.experiment.close` → **project**
   `ResultsStore::project_and_record` per settled run
   (`DerivedReason::Initial`, `LabDocs` attached — the results
   owner's own surface) → **analyze** `lab.analysis.analyze` with
   `rows[]` = the projected row key ids → **notifications**
   `drain_notifications` verbatim or `n/a{no_callback_channels}` →
   **receipt** `assemble_receipt` over the re-folded
   `ExperimentView`, `project_runs`-projected `EvalRun`s, per-run
   head pins/manifests/`LedgerFacts`, and a `DeclaredReceipt`
   derived from actual durable facts: slots from the view's plans,
   attempts per `run_plan_id`, `settlement_ref` = the durable
   `measurement.experiment.run_settled` event id, `grade_ref` =
   the emitted metric's event id, `version_id` = the projected
   `RowVersion` id, `plan_ref` = the plan coordinate, declared
   cost/selection/protocol pins riding the plan verbatim (empty
   when absent — the reconcile legs then skip member-wise equality
   honestly).
4. **Grading rides the kernel-direct commit seam, not
   `measurement.emit_metric`** — `emit_metric` serves a live
   adopted session and the subject run has already finished inside
   `submit`'s drive; `surface_commit_row` rides the run's persisted
   writer generation — the same path `measurement.export.delivered`
   uses — so the instrument verdict lands durable under the honest
   writer. The grade is the *declared* instrument verdict gated on
   real execution evidence: the recipe asserts nothing about task
   success the plan did not declare and the run did not produce.
5. **`RecipeReceipt` records what the selected client actually
   did** — `recipe_version`, the `hello` result verbatim, one
   `{method, outcome, result|error}` per boundary request
   (refusals recorded with their bodies, never re-classified), one
   `{seam, outcome, detail}` per owner invocation
   (`docs`/`adopt`/`grade`/`project`/`receipt`), the drained
   notifications or typed `n/a{no_callback_channels}`, per-slot
   coordinates (`run_plan_id`, `run_id`, `arm_id`, `attempt_no`,
   `session_id`, `submission_ref`, `grade_ref`, `outcome_class`,
   `row_key_id`, `row_version_id`), the persisted analysis
   `{record_ref, report_ref}`, `close_status`, and the
   `PopulationReceipt` itself (`closed` verdict only on a clean
   reconcile — its own failures stay readable). `to_json` emits
   canonical JSON.
6. **`RecipeError` is a closed sum, never re-classified** —
   `Refused{code, detail}` over the seven-code set
   (`unsupported_shape`, `missing_field`, `type_mismatch`,
   `execution_incomplete`, `no_submission`, `grade_unspecified`,
   `drain_stalled`); `Boundary{method, detail}` wraps the op's
   error body verbatim; `Owner{seam, detail}` wraps the owner
   interface's own error verbatim.
7. **The K-2 CLI repair forwards members verbatim** —
   `cmd_experiment_op` maps `--plan → run_plan_id`,
   `--lease → lease_id`, `--holder → holder`,
   `--subject-holder → subject_holder`, `--bundle-id → bundle_id`,
   `--reason → reason`, `--probe → probe`, `--partial →
   partial: true` beside the existing `cell`/`run_id`; absent flags
   stay absent — a missing required member answers the boundary's
   own `SchemaViolation`, never a CLI-side default.
   `cmd_compare_report` takes `<params-file>` — the canonical
   `lab.analysis.analyze` body verbatim (the `eval <verb>`
   params-file convention) — then
   `lab.analysis.render{report_id: body.report_id,
   view: "report"}`; a missing `report_id` in the boundary's answer
   is `malformed_response`, never synthesized. `cmd_compare_scorecard`
   takes `<report-id>` → `render{report_id, view: "scorecard"}`.
   `VALUE_FLAGS += plan/lease/subject-holder/bundle-id/probe`,
   `SWITCHES += partial`. The `{baseline, candidate}` and
   `{view, experiment_id}` shapes are removed — they were
   unsupported wrapper inventions the boundary could only refuse
   (the §9.3 existing-contract-fix class, same as M1/R5.10 and
   R0/R5.24); the CLI invents no selectors, spec, tasks, or report
   identity.

## Consequences

- A caller can drive the one supported composition end-to-end on an
  in-process boundary — one arm × one task × two replicates in the
  battery — and receive a `RecipeReceipt` whose `population-receipt/1`
  reconciles `closed`, with every request, owner call, coordinate and
  notification outcome recorded; absent callback channels record
  typed inapplicability rather than a fabricated drain.
- `tests/r5_28.rs` (5 checks) exercises the full chain on scratch
  stores (receipt `closed`, adopted session, durable submission +
  grade refs, projected rows, persisted report) plus the AC-2
  refusals — authored/unknown members, missing required members,
  process-only execution (`execution_incomplete` before any grade),
  and a grade map that leaves a bound slot unspecified —
  compile-red at base `a2bed920` (the module does not exist there).
  `crates/hh-cli/tests/in_process.rs` gains two boundary-shape
  regressions asserting the exact forwarded members against the
  recording boundary (assertion-red at base — the pre-repair
  wrapper never emitted `run_plan_id`/`lease_id`/`report_id`).
- REQ-E-009, REQ-A-002, REQ-A-202 and REQ-A-106 keep
  `planned; unmet` — this ticket records achieved engineered D/E
  separately from the owed legs: the named contributors R5.50
  (plugin) and R5.45 (trace) and every R/P/actual-execution
  predicate. The eleven contributing ids are stamped
  **contributing-only** — never a second ownership claim.
- No crate edge added (every recipe dependency was already a facade
  member), no schema/wire change, no new event class
  (`measurement.metric.emitted` is the registered class), no new
  dependency; the scripted `EmbedModel` lane is real execution
  through the existing runtime — actual task/provider/participant
  execution stays gated exactly as the owners leave it.
- AMEND ruling `6ff01462`: 2,005 changed source/test lines vs ≤850
  — recorded Deviation accepted (one conjunctive end-to-end
  predicate; recipe↔CLI a real but undocumented seam — the
  documentary test; leg (b) alone still ~2× over; ~2.4× inside the
  accepted band).

## Alternatives

- **A recipe crate or a second runner/store beside the facade** —
  rejected: §2.1 forbids a second runner/store and I-02 gives the
  facade the composition home; `hharness` already depends on every
  owner the chain touches.
- **Riding the recipe through `hh` CLI commands** — rejected: the
  CLI is a client/renderer over the boundary (K-2); composing
  through parse/dispatch layers would add an untyped seam and test
  the wrapper, not the composition. The two surfaces stay
  independent — which is also why the split review found no
  documented seam between them.
- **`measurement.emit_metric` for the grade leg** — rejected: it
  serves a live adopted session; the subject's run is already
  finished after `submit`. `surface_commit_row` under the persisted
  writer generation is the honest durable path (the export
  delivery record's own route).
- **Deriving or defaulting grades/rows from process exit or
  declared specs** — rejected: authored members refuse
  `unsupported_shape`, a missing grade entry refuses
  `grade_unspecified`, and process-only success refuses
  `execution_incomplete` — the receipt's declared side is built
  from actual durable refs only.
- **Keeping the `{baseline, candidate}`/`{view, experiment_id}`
  wrapper shapes and adding boundary support for them** — rejected:
  K-2 keeps semantics behind the boundary; the ops' required
  members are caller-supplied inputs, and inventing a CLI-side
  selector pair would create a second contract the spec never
  admitted.
- **Splitting the CLI repair from the recipe to fit the trigger** —
  rejected per the scoped review: decomposition row 32 binds them
  as one owner row, the recipe↔CLI seam is undocumented, leg (b)
  alone stays ~2× over, and AC-1's conjunctive predicate spans the
  cut.

## Revisit triggers

- If a later admission names a supported `hh`-level recipe command
  or a second versioned recipe (`hh-recipe/2`), amend Decision 1 —
  `hh-recipe/1` is the one supported version label today.
- If the boundary admits a grade path that serves a finished run
  (an `emit_metric` arm or a declared instrument op), revisit
  Decision 4 — `surface_commit_row` exists because `emit_metric`
  only serves a live session.
- If `lab.experiment.*` or `lab.analysis.*` required members change
  (new plan/lease/holder fields, a different render resolution),
  re-run the r5_28 + in_process batteries — the CLI forwards
  members verbatim and the recipe threads the same names.
- If a host-callback/subscription channel lands for adopted
  sessions, re-check the notifications leg — today absence of armed
  host capabilities records `n/a{no_callback_channels}` verbatim.
- If the scripted `EmbedModel` lane mints its `hh.submit`
  completion under a different durable member than
  `submission_ref`, re-read `submission_evidence`'s observed-ref
  scan — the evidence gate keys on the current mint.
