- **Status:** Accepted
- **Date:** 2026-11-02
- **Ticket:** R5.9
- **Requirement ids:** REQ-E-204, REQ-E-103 (primary); REQ-E-102 (contributing)
- **Spec:** docs/evidence-and-adoption-spec.md §2.2 steps 5–6 + AC-2-1; PADR-R5-1 (admitted GATE-G9, packet A — A.1 items 5–7, A.3, A.4, A.7); execution-partition X6; design `14_integration-design.md` F2; ticket docs/tickets/178_R5.9__selection.md
- **Rung (ADR-0024 obligation):** implementation landing record — the admitted owner-bound pure-selection contract's concrete shape on `hh-eval`; no RPC, no wire/schema change, no new event class, no new dependency

## Context

GATE-G9 admitted PADR-R5-1: shared pure grade selection — first valid
inside the frozen valid-grade set — plus authorized append-only
invalidation/immutable revisions (dossier A.1 items 5–7; A.3's record
`{revision_id, reason, supersedes, authority, watermarks[],
eligible_set_ref}`; A.4's authorized-only correction rule). The
execution-partition X6 row fixes the seam: "eval small selection module
… owner callers validate target/submission/oracle/causes/watermark …
must land callable contract first so X7 never independently reimplements
selection," and the §9.2 caution binds the authority model: "no new
principal/role or new mutation endpoint … reuse the existing authority
model; the ADR names the accepted authority proof."

## Decision

1. **The contract lives once in `hharness_eval::selection`**, pure —
   `ValidGradeSet` (the materialised frozen pins: `subject_ref`,
   `submission_ref`, `oracle_ref`, `policy_ref`, eligible `members`),
   `GradeAttempt`/`GradeOutcome` (the owner-validated durable fact),
   `SelectionRevision` + append-only `RevisionLog`, `select_grade` /
   `select_grade_at`, `plan_disposition`, `SelectionError`. No eval→
   ledger edge: the module never sees a store; the owning consumer
   (results/experiment) resolves durable verdicts into `GradeAttempt`s.
2. **First valid wins per member, in durable order.** The first
   admissible attempt carrying a decided grade wins its member; a later
   higher reward and a later `OracleFailure`/typed `n/a` cannot displace
   it — failure→valid zero→failure retains zero; wrong-but-valid is a
   valid zero. This is never best-of and never last-write-wins.
3. **Owner-validation is structural + resolved.** The contract checks
   pin equality (subject/submission/oracle/member), requires ≥1 cause
   coordinate citing the subject run and none citing a foreign run, and
   enforces durable order per run (a regressed seq refuses
   `OutOfOrder`; one `(instrument_run_id, seq)` coordinate presented
   twice identically dedupes `DuplicateInstrument`, presented with
   different facts refuses `ConflictingCoordinate`). Resolving each
   cited coordinate against the real durable prefix remains the owning
   consumer's job (owed to R5.11/R5.14, recorded in AC-3).
4. **Revisions are authorized, append-only, and set-bound.**
   `RevisionLog::append` refuses an empty `authority`
   (`UnauthorizedCorrection` — the accepted authority proof is the
   named-authority field, ADR-0162 D2's human-origin class; no new
   principal, role or endpoint was created), empty `watermarks`
   (`MissingWatermarks`), a foreign `eligible_set_ref` (`SetMismatch` —
   `eligible_set_ref()` content-addresses the canonical `ValidGradeSet`
   JSON), a `supersedes` resolving to no known attempt ref or prior
   revision (`UnknownSupersedes`), and a `revision_id` re-presented
   with different bytes (`ImmutableRecord` — identical re-append is an
   idempotent replay). `supersedes` names the invalidated
   `attempt_ref`, or a prior `revision_id` it revokes (correction of a
   correction — the revoked revision leaves the effective chain).
   Invalidated evidence is `Unavailable` until a valid replacement
   exists — never a task zero, never an erasure.
5. **Watermarks resolve history.** `select_grade_at` keeps only
   attempts at or below each run's pin and applies only revisions whose
   `watermarks` the pin covers; an attempt on an unpinned run refuses
   `WatermarkMissing`. A historical pin reproduces the historical
   selection exactly — purity gives reproducibility structurally.
6. **`plan_disposition` keeps the axes separate.** A fully-selected
   set yields `Graded{outcome_class}` with the stop-derived class
   restored verbatim (`budget_exhausted` stays `budget_exhausted`);
   raw grades, selected refs and `veto_tripped` travel as separate
   axes. A member with no admissible evidence is `Pending` — the
   `grade_pending` admission state, never a seventh outcome class; a
   member whose evidence is all failed or revoked-unreplaced is
   `Unavailable` → `OracleFailure` disposition (the real ADR-0106
   class, matching the existing overlay latch).
7. **Size deviation recorded.** The minimal faithful AC-1+AC-2 unit
   measured 959 changed source/test lines vs the ≤800 trigger; the
   worker stopped at the trigger, the scoped review ruled **AMEND**
   (44d1c7ed — atomic X6 seam, no documented sub-seam), and the
   deviation is carried conspicuously in the PR, BUILD_INDEX and PHASE
   LOG.

## Consequences

- Results/experiment consumers (`plan_disposition_at(scoring_ref)`,
  `settle_graded`, scheduler/export pending gates) compose this module
  — owed to R5.10 (sealed submission pin), R5.11 (instrument attempt
  production), R5.13 (physical side) and R5.14 (every scored consumer);
  no second selection may be written.
- The durable landing site for a revision event/record (class-table
  admission under CC10 if it lands as an event) is a consumer-ticket
  decision; this slice admits only the record's canonical form and
  append-only authority semantics.
- The strict pin/cause checks mean a caller presenting malformed or
  foreign-coordinated attempts gets typed refusals/exclusions, not a
  silently filtered selection — every presented attempt is accounted
  for in `non_winning`.

## Alternatives rejected

- **Selection inside hh-results' overlay fold** — rejected: the fold
  already latches oracle failure but has no shared first-valid/revision
  policy; embedding it there invites a second implementation for the
  experiment/scheduler consumers (X6 forbids).
- **`supersedes` naming only attempt refs** — rejected: the dossier's
  supersedes *links* plural and correction-of-a-correction read
  naturally as revision revocation; both are admitted with the
  documented effective-chain rule.
- **Mutable/by-authority-free correction** — rejected outright by A.4:
  a correction lacking the authorized field is a typed refusal, never
  a warning.
- **`Pending` as an outcome class** — rejected (A.10): `grade_pending`
  is admission state; the six ADR-0106 classes stay closed.

## Revisit trigger

- If R5.14/R5.11 need the selection bound to a different identity
  discipline than `(instrument_run_id, seq)` coordinates (e.g. event-id
  pins), revisit the dedup/conflict and `attempt_ref` convention.
- If a revision ever needs to invalidate a member wholesale rather
  than a named attempt ref, revisit the `supersedes` grammar (currently
  attempt ref | prior revision id).
