# ADR-0269: S2.7 IFC/taint rulings — the per-basis table's `approval` exemption, `seal` clears taint, fail-closed contract decode, the recorded-row batch order, and the admission/kind members

- **Status:** Accepted
- **Date:** 2026-09-19
- **Ticket:** S2.7
- **Requirement ids:** R-2.8.2 (AC-R-2.8.2-{1,2,3,5,12,14}; DF-S1.12-6
  progress note)
- **Spec:** §5g.2 (the C2 information-flow slice — `FlowContract`,
  `L⁺(p)`, `admit`, `EnforcementClass`, the per-basis effects table,
  check 3, D-ROBUST, the closed `Remedy` sum, the closed flow-policy
  language) · ADR-0054/0055/0056 (owning) · ADR-0033/0034/0035 (record,
  lattice, bases)

## Context

S2.7 lands the C2 information-flow slice: the `flow_contract` member on
`ToolCapability`, the prospective label `L⁺(p)` and result admission,
D-ROBUST, check 3 on the egress domains, the closed flow-policy language,
and the closed remedy set. The spec fixes the *what*; the mechanism
choices below were left to the ticket:

1. **How the §5g.2 §2.2 `approval` row composes with S2.6's intent
   endorsement.** The per-basis table says `approval` *never changes a
   component* — but `endorse(basis = approval, EffectIntent)` stamps a
   rising label on the intent record (S2.6, ADR-0268). Wiring the table
   blindly into `endorse` would refuse every approval endorsement.
2. **Whether `seal` *refuses* or *clears* a tainted subject.** The table
   reads "seal/pin/promotion: raise authority, **clear taint**" — the
   clearing is the basis's *effect*, but the helper could equally refuse
   and force callers to clear first.
3. **The decoder's closed-grammar discipline.** `FlowContract` is
   MUST-data validated at seal *and* re-parsed at `authorize` — a
   permissive member read would admit a malformed contract that seal
   refused.
4. **Where the `context.observation.recorded` row sits in the observe
   batch.** It scopes `tool_call_id`, which `action.tool.completed`
   closes in the same batch — order matters.
5. **What the `admission`/`label` members record.** Admission never
   reads a class from the result payload; the recorded members had to
   stay content-free.

## Decisions

**D1 — `hh_provenance::flow` is the one schema and evaluation home
(CC7).** `FlowContract::to_json`/`from_json` own the member's shape;
`hh-hir` stores the canonical `Json` verbatim and validates through
`FlowContract::from_json` at `validate_capability` (a malformed member is
`SchemaViolation`; a named parameter absent from `input_schema` is
`UnmappedParameter`) and refuses contractless gated capabilities at
`ops::seal` (`ContributionUndeclared` — `world = open` or domain ∈
`{net_egress, message_human, fs_read, memory_write}`). The monitor parses
the same member through the same decoder and fails closed with
`deny{EvaluationError}`. One label type, one lattice, one grammar — no
second encoders.

**D2 — the per-basis table governs *content* endorsements; `approval` is
intent-scoped and exempt.** `check_basis_effect` is enforced inside
`endorse` — and therefore inside `check_endorsement` at ledger append —
for `seal`/`pin`/`promotion`/`validator`: a strict authority raise with
`taint → ∅` (`validator` pinned to `external → environment`);
`policy_rule` remains readers-only via `declassify`. The table's
`approval → NoLabelChange` row is honoured *by construction*: an
`approval`-basis `endorse` is only ever emitted for
`ContentKind::EffectIntent` (the intent's own rise — ADR-0268), never for
content, so no approval-basis *content* endorsement exists to violate the
row. `policy_rule` never reaches `endorse` (refused — it declassifies
readers only).

**D3 — `seal` clears `to.taint`.** "Clear taint" is the basis's effect,
not a precondition: `endorse::seal` mints `to = (definition, ∅,
readers-as-declared)` for any subject — the kernel vouches for the
sealed definition, and the resulting label satisfies
`TaintedAboveExternal` at `definition`. A caller-supplied `to` that still
carries taint is refused (`BasisNotAllowed` via
`check_basis_effect::TaintNotCleared`), so the "clear" can never be
skipped.

**D4 — the contract decoders fail closed on non-objects and unknown
members.** `Contribution::from_json` required neither `Json::Obj` nor a
closed member set — `{"contribution": true}` decoded silently. Both
decoders now refuse a non-object and any member outside the declared
grammar (CC3); the monitor's malformed-contract path is
`deny{EvaluationError}`, removal-tested
(`malformed_flow_contract_denies_evaluation_error`).

**D5 — `context.observation.recorded` precedes `action.tool.completed`
in the observe batch.** The recorded row's scope names `tool_call_id`;
`completed` closes that scope. Ordering `[observed, recorded, completed]`
keeps the scope open at append — the batch order is the scope-lifecycle
order, not an accident.

**D6 — admission members are the recorded kind and the admitted label —
never the payload's claim.** `action.effect.observed{admission}` carries
the `AdmissionKind` spelling; `context.observation.recorded{kind:
"tool_observation", admission, label}` carries the admitted `L(r)` — ids,
enums, the label triple; content-free per the audit partition
(`EFFECT_FIELDS` + `LABEL_FIELDS` extended; the class stays non-audit —
the row already carries `kind`-discriminated payloads). An unannotated
open-world result is `unverified`/`taint = {tool}`/readers from the
declared `reads`; a less-restrictive realized label is admitted at the
declared bound and recorded `narrowed`. `label.endorsed` gains the
optional `capacity_bits`/`sanitizer_ref`/`robustness_inputs` evidence
members — honestly absent unless the endorsement ran under the bound.

**D7 — the evaluator is total and constant-time-per-atom by
construction, measured.** `And`/`Or`/`ForAllParam`/`EveryCommitted`
evaluate *every* operand (no secret-dependent early exit — the error is
the first in document order); `COND_MAX_DEPTH`/`COND_MAX_NODES` bound the
grammar at decode. AC-R-2.8.2-14 evidence: `check_flow` over 8 vs 128
non-matching rules — 9.4 µs vs 18.2 µs ×10 iterations (linear-bounded;
selector mismatch dominates); `label_bytes` of a representative tainted
label = 60 ≤ `LABEL_MAX_BYTES` (4 KiB); zero label tokens ever reach the
model (the flow plane reads canonical records only — `FlowInput` carries
no `Text`).

## Consequences

- `endorse`/`check_endorsement` now enforce the componentwise table —
  a `seal`/`pin`/`promotion`/`validator` event whose `to` keeps taint or
  fails to raise authority refuses at append (Rule-P-adjacent — a typed
  refusal, not a fabricatable row).
- The quarantine handle stays context-invisible: `handle_only` items
  contribute nothing to the context-label fold, an inlined handle is
  `AssemblyError::HandleLeaked`, and a handle argument joins the
  *argument's* label at `L(args)` — never `ctx`.
- D-ROBUST orders before any `ask` (I-F2): an endorsement-surface
  parameter at `authority ≤ external` or `taint ≠ ∅` without a shape
  endorsement denies `RobustnessViolated` with `substitute` remedies.
- Advisory inputs raise only (I-F1): a non-deny decision under
  `advisory` enforcement never applies — the evaluator falls through to
  Π's default row.
- Owed work is ledgered: DF-S2.7-1 covers `labels_leaves` per-leaf
  minting, the remedy-consumption ingress (`remedy_taken` is stamped by
  the consumer when it lands), and the runtime-validator emission of
  `shape_endorsed`; DF-S1.12-6 carries the dated progress note (the
  `approved_host_body` closer wires at the R-2.8.4² C2 stage note).

## Revisit trigger

Reopen D2 if `approval`-basis endorsement ever needs to touch *content*
labels (the current reading is intent-scoped; a spec clarification that
approval may declassify readers would re-open the table row); D3 if the
spec re-reads "clear taint" as a *precondition* (seal refusing tainted
subjects) rather than the basis's effect; D4 if `FlowContract` gains
optional members — the closed-member decode must be extended in the same
commit that lands the member (never loosened); D5 if the observe batch
gains a second scope-closing row or `recorded` moves after
`action.tool.completed` (the order is load-bearing); D7 when the
`labels_leaves` per-leaf walk lands — the leaf enumerator may change the
measured per-decision cost profile and AC-14 must be re-measured
(DF-S2.7-1).
