# ADR-0297: S4.5b protocol-edge + ACP rulings — the `input_required` pause model, shared edge vocabulary in `hh-mcp`, compiler-owned lowering tables, fail-closed Origin/OAuth guards, A2A card = bundle identity

- **Status:** Accepted
- **Date:** 2026-09-26
- **Ticket:** S4.5b (`067_S4.5b__protocol-edges-and-acp.md`)
- **Requirement ids:** R-2.5.4 (C1 — protocol edges, ACP session transport) ·
  R-2.1.3¹ (the ACP compilation target)
- **Spec:** §5d.4 (R-2.5.4 C1; ACP; A2A edge; Streamable HTTP; OAuth 2.1 +
  RFC 8707) · §3.2 (`R-2.1.3¹` target artefact); owning ADRs ADR-0096…0099 ·
  ADR-0010 · ADR-0019/0021
- **Deferral discharged:** DF-S3.9-1 (the paused MCP call's run-mapping arm)

## Context

S4.5b lands the C1 protocol edges and the ACP session artefact: the
`ProtocolBinding`/pin-set machinery on the MCP client and server item
forms, the `hh-acp-target/1` session artefact (v2 pin + v1 compatibility
profile), `render_session`, permission transport, the `_hh/*` method
surface, Streamable HTTP with `Origin` validation, OAuth 2.1 + RFC 8707
through the H3 credential seam, `target` idempotency-key forwarding, the
A2A card/TaskState edge, and the compiler lowering/lifting target
(`R-2.1.3¹`). It also carries the deferred run-mapping arm of DF-S3.9-1:
an MCP `tools/call` answering `resultType: "input_required"` inside a run.
The rulings below are the owned calls where the spec's machine text left
the shape open.

## Decision

1. **`input_required` is a non-terminal lifecycle marker, never a terminal
   outcome and never a re-dispatch.** A `tools/call` answering
   `resultType: "input_required"` lands `action.effect.input_required`
   (a new audit-grade class — `hh-ledger/src/classes.rs`,
   `hh-ledger/src/effect.rs`) on the already-committed attempt: the effect
   stays at its committed phase (never re-emits `action.effect.committed`
   for attempt 1, never moves terminal), and the dispatcher appends
   `control.decision{kind: ask, decision_point: protocol_input_required}`
   plus a `message_human` elicitation on a *separate* derived tool-call
   scope (a fresh tool-call id + `action.tool.proposed` + its own derived
   `effect_id` — the elicitation never rides the paused call's scope).
   `resume_paused` retries under the *same* `effect_id` at `attempt_no + 1`,
   echoing `requestState` byte-for-byte as opaque data the kernel never
   parses (`ExecutionRequest.request_state`). The JSON-RPC error frame
   stays on the transport plane (`isError` stays on the tool plane) — the
   two failure kinds are disjoint sums (`hh-mcp/src/executor.rs`).

2. **The generic protocol-edge vocabulary lives in `hh-mcp`; `hh-acp`
   consumes, never duplicates (CC1).** `ProtocolBinding`, the pin-set and
   version-negotiate sums, and the reconcile/discovery machinery are the
   shared edge vocabulary — `hh-acp` names the same types for the ACP
   binding (`acp_binding`, `acp_pin_set`, `negotiate_era`) rather than
   minting a parallel model. `binding.request_target` is the one binding
   member the `target` idempotency-key forwarding reads — forwarded as
   `tools/call.params.target`, deduped name-keyed at the server
   (`hh-mcp/src/server.rs`).

3. **The event-class → update-kind lowering table and the task-state /
   tool-kind projections live in `hh-compiler` — the single source the
   artefact and every client render from (CC1/CC7).**
   `hh-compiler/src/acp.rs` lowers the ledger event classes to ACP session
   update kinds (`lower_event` over `AcpDialect::{V2, V1}`), projects
   `render_session`, and lifts a session artefact back to a `PartialHIR`
   with a `LoweredTarget.loss_report{granularity: configuration}` — the
   report names every unverifiable member, never drops silently (CC3).
   `hh-acp` renders from the table; it never re-derives the mapping.

4. **The `Origin` guard is an exact-match allowlist that fails closed
   before dispatch — and the request body is always drained before any
   refusal.** `OriginPolicy` pins the declared origins verbatim (no
   wildcard, no suffix/substring admission — `http://test.local.evil.com`
   refuses); absent `Origin` refuses under `require: true` and is admitted
   only under the explicit non-browser `require: false` posture. The serve
   loop reads `Content-Length` bytes *before* the Origin/bearer guards
   answer — a socket closed with unread inbound data resets (RST) and the
   client loses the refusal; the body is inert until parsed, so draining
   first changes no security property (`hh-mcp/src/http.rs`). Non-POST
   methods → `405`; malformed requests → `400`; `initialize` mints the
   `Mcp-Session-Id` header; a `catalogue_hash` change queues
   `notifications/tools/list_changed` for the `subscriptions/listen`
   drain — queued before the next answer, never pushed eagerly.

5. **OAuth 2.1 rides the H3 credential seam: the bearer lives in
   transport/H3 custody only — a fingerprint is ledgerable, the token
   never is.** `hh-mcp/src/oauth.rs` implements the authorization-code
   flow with PKCE S256 (`pkce_pair` over `getrandom` + `sha256`), the
   RFC 8707 `resource` indicator bound to the declared audience, and the
   RFC 9207 `iss` issuer binding on the authorization response — audience
   mismatch and issuer mismatch both fail closed as typed refusals. The
   `WWW-Authenticate` challenge carries `resource_metadata` so the flow
   answers the edge's own challenge; `TokenGrant` installs the bearer into
   the transport's custody (`HttpTransport::set_bearer`) and only its
   fingerprint may reach durable surfaces (CC2/CC3 — claims are data).

6. **A2A: the card's version is the bundle id, the signature verifies
   under a declared `TrustRootPolicy` and fails closed under a wrong
   root, and the `TaskState` projection is exhaustive — never
   coerced.** `hh-acp/src/a2a.rs` renders `AgentCard{version: bundle_id}`,
   signs the canonical card bytes (`FixedSigner`/`KeyTable` fixture seam),
   and projects every ledger-reachable task state explicitly —
   `INPUT_REQUIRED` resumes the child run through the same pause trail as
   rule 1; an unmapped state is a typed gap, never a guess.

7. **`session/new.mcpServers[]` is admitted only as pending-review —
   never silently activated.** A v2 client declaring MCP servers gets
   `pending_review` (the H5-review gate), not a live server set; the
   session artefact stamps the declaration and the pending state so the
   review surface can decide later (fail-closed at the seam).

8. **v1 compatibility is a profile projection, not a second artefact.**
   `ACP_VERSION = "0.1.0"` pins v2; `negotiate_era` answers the pinned era
   or the legacy label. The v1 compatibility profile *projects* the same
   artefact — unstable update kinds filtered, `observability_level`
   reported as `{events, end_state}` with no `ledger` member, unsupported
   controls (`steer`/`fork`/`compaction`/`subagents`) reported `unknown`,
   component metrics `n/a` — so the three v1 hosts in AC-R-2.5.4-7 produce
   descriptors from one source and hosted auto-approval still routes
   through Π, never an adapter-level approval path.

## Consequences

- The paused-call trail is fully durable: a resume without the
  `input_required` + ask + elicitation prefix is a typed refusal, and the
  retry's ledger motion (same `effect_id`, `attempt_no + 1`, requestState
  echo) is replay-verified — DF-S3.9-1 closes.
- `hh-acp` is records-in/records-out (no ledger writes, no kernel
  authority) and a removable edge: nothing in the base names it, and the
  shared vocabulary stays single-sourced (CC1/CC5/CC6).
- The Origin/bearer guards run before any dispatch but after the body
  drain — the refusal is always deliverable, and untrusted origins /
  missing bearers get typed HTTP answers (403/401 + challenge), never a
  hang or a half-dispatch.
- Token material never reaches the ledger: the transport/H3 seam holds
  the bearer; the fingerprint is the only durable artefact.

## Alternatives considered

- **A second artefact for v1** (parallel ACP-v1 schema) — rejected: two
  sources for one session record invites drift; the profile projection
  keeps `render_session` single-sourced and makes the loss surface
  explicit (`edge_loss_report`).
- **Re-dispatch on `input_required`** (cancel + fresh effect) — rejected:
  it would mint a new `effect_id`, losing the audit chain and violating
  the idempotency contract the `target` key forwards; the marker +
  same-identity retry preserves the append-only record.
- **Rejecting before the body drain** — rejected: closing a socket with
  unread inbound data resets the connection and the refusal never reaches
  the client (observed as `Connection reset by peer` in the fixture).
- **Token material on the grant record** — rejected outright (CC2/CC3):
  the durable row carries the fingerprint and the flow stamps only.

## Revisit trigger

Reopen when (a) a second protocol edge needs a different `ProtocolBinding`
member set (the shared vocabulary's shape gets a real second consumer),
(b) the v1 profile needs a *divergent* session record (not a filtered
projection), (c) OAuth device-authorization or client-credentials grants
enter scope (the code grant's shape is the only landed flow), or (d) the
`input_required` marker must carry structured prompt payloads rather than
the opaque `requestState` echo.
