# ADR-0382: Retained supplemental guard — landed-evidence and diagnostic-class model

- **Status:** Accepted
- **Date:** 2026-10-30
- **Ticket:** R5.1
- **Requirement ids:** REQ-H-001, REQ-H-002, REQ-H-003, REQ-H-005, REQ-H-006, REQ-H-007, REQ-H-011, REQ-C-104, REQ-C-107, REQ-C-108
- **Spec:** docs/evidence-and-adoption-spec.md §9.4–9.5, AC-9-2
- **Rung (ADR-0024 obligation):** non-contract build-tooling record (no contract schema, wire or runtime semantics)

## Context

§9.4 requires a retained, versioned, read-only coverage/routing guard before any
product dispatch: it must check the 180 literal candidates/aliases, one primary
owner per adopted target, resolvable AC/layer/contributor hooks, unique
grammar-valid chain ids/files, backward dependencies, skeleton refusal,
full-tail roles, first-unlanded `nextTicket` against landed evidence, base/chain
ancestry and the scoped historical diagnostics. §9.5 fixes the reviewed
diagnostic baseline to exact check/path/row classes — never an arbitrary
eight-warning allowance — and keeps GATE-G1's legacy completion evidence. The
guard needed a precise, reproducible meaning for "landed evidence", "first
unlanded", "old signature" and "baseline class" so that the coordinator and the
fixture battery evaluate the same contract.

## Decision

`docs/build/tools/supplement_guard.py` (`hh-supplement-guard/1`, tool version
1.0.0) implements these recorded semantics:

1. **Completion evidence by chain kind.** Work kinds (ticket, capstone,
   reconcile, docs, skeleton) count as landed iff `BUILD_INDEX.md` carries a row
   for their ticket id or sequence. `gate` rows count complete iff the latest
   GATE DECISIONS row for the id contains `PASSED` (and not `NOT PASSABLE` /
   `FAILED`); a recorded non-PASSED decision is a `failed-gate` error, not a
   silent hold. `human` rows count complete on a recorded GATE DECISIONS row or
   a readout whose `Status:` is not `PENDING`.
2. **First-unlanded routing.** `nextTicket` must equal the lowest-sequence
   active-round row without completion evidence. A `gate`/`human` first-unlanded
   row yields `HOLD` (legal RETURN PASS state); a skeleton yields `REFUSED`
   plus a `skeleton-dispatch` error; a work row with all `Depends on`
   predecessors complete yields `DISPATCH`; unmet dependencies yield `REFUSED`
   plus `pending-gate`/`pending-prerequisite` errors. A `nextTicket` outside the
   active round is `old-gate-routing` — the legacy GATE-G1 row can never be
   selected; its readout must additionally match the baseline's recorded
   `gate_g1_completion` sha256 byte-for-byte.
3. **Baseline classes.** Each stock-checker warning is classified by
   `check | file | first five normalized message tokens` (quotes and digits
   normalized). Emitted warnings must match the reviewed baseline's classes
   one-for-one: an unmatched emission is `unexplained-diagnostic`, an
   unemitted class is `missing-historical-diagnostic`, and any violation is
   fatal. No warning count is ever consulted as a waiver.
4. **Signature freshness.** Every quoted verbatim in GATE DECISIONS rows and
   readout `Operator decision (verbatim` lines belonging to non-active-round
   ids forms the old-signature pool; an identical verbatim recorded for an
   active-round gate is `signature-reuse` — old acceptance signatures cannot
   satisfy GATE-G17's fresh acceptance.
5. **Ownership closure.** The `.md` owner table and `.json` register must agree
   row-for-row (disposition, single primary link, anchor, layer, contributors);
   aliases must keep their literal predicate bytes (`source_sha256` over
   `literal_row`) and inherit exactly their adopted target's primary owner.

## Consequences

- The guard has a deterministic, offline, read-only contract: exit 0 with a
  `DISPATCH`/`HOLD` route on a conforming tree, exit 1 with named fatal
  diagnostics otherwise. R5.2's launch-path proof can consume `--json` without
  parsing prose.
- Skipping the stock checker (`--no-checker` or a sandbox without
  `AGENT_SKILLS_ROOT`) is recorded as a `note`, never silently promoted — the
  baseline comparison is then reported skipped rather than passed.
- A fixture sandbox (no `.git`) degrades the ancestry leg to a recorded skip;
  the real checkout verifies `pinnedBaseSha` is an ancestor of `chainTip`.

## Alternatives considered

- **Reuse the stock checker's whole-chain "lowest unlanded" rule.** Rejected:
  it permanently names GATE-G1 (dispositioned by ADR-0226), so the active-round
  computation deliberately scopes to the current round's banner and treats
  passed gates/human rows as complete.
- **Match baseline warnings literally.** Rejected: the baseline itself records
  legitimate drift (nextTicket value, region line offsets); class signatures
  keep the match exact without freezing volatile tokens.
- **No ADR (README-only contract).** Rejected: the landed-evidence model is a
  decision later tickets and the orchestrator rely on; the ticket requires
  ADRs for owned decisions.

## Revisit trigger

Reopen if the manifest kind vocabulary changes, BUILD_INDEX changes shape, the
stock checker emits a `build-memory-check/3` schema, the supplement's
`hh-supplement-plan/1` register is amended, or a new round changes the
active-round scoping rule — the class table and kind map then need a matching
amendment, never a silent edit of expectations.
