# ADR-0447: `allowlist_gap` requires a non-empty `denied_hosts` — the `machinery{h_allow}` classification (§10.5 amendment row A5)

- **Status:** Accepted — operator ruling R-7, interactive 2026-11-15 (LEDGER `## GATE DECISIONS` `intervention-2026-11-15` row, verbatim)
- **Date:** 2026-11-16
- **Ticket:** R6.45i (manifest 309i — records); implemented by R6.45j's D19 classifier change (manifest 309j)
- **Amendment register item:** A5 (experiments spec §10.5, "First-pass intervention amendments")
- **Requirement ids:** REQ-XB-125 (a machinery discordance is repaired, never excluded), REQ-XH-116 (exclusions draw from the seeded order — only legitimate exclusions); §3.5's host-level deny intent
- **Spec:** experiments spec §3.5 (`allowlist_gap{host}` — "Denies are host-level"), §3.8 (discordance classes), §10.5 row A5
- **Rung (ADR-0024 obligation):** an explicit non-contract note — this ADR governs the experiments-program first pass, not the canonical kernel contract ladder.

## Context

Since Wc4, every member's H-allow cell failed with `denied_hosts: []` — nothing was ever denied; the mediator's own machinery (duplicate `Host:`, the 8 MiB body cap, the allowed-CONNECT starve) produced `reward.txt = 0` or the signature. The committed classifier nonetheless rolled these up as `exclude:runner_infeasible:allowlist_gap{unknown}` — a declared-data exclusion that, applied, would have dropped members from the manifest on a machinery defect (diagnosis D19 — CONFIRMED rule). §3.5's intent is that an allowlist gap names the denied host; the spec's machinery rule is that a machinery discordance is repaired, never excluded (REQ-XB-125). The orchestrator refused to treat them as exclusions in practice, but the committed rule would have let a later window exclude-and-replace on a machinery failure.

## Decision

R-7 (verbatim in the GATE DECISIONS row):

- `allowlist_gap` **requires a non-empty `denied_hosts`** — denies are host-level, and a gap that names no host is not a gap.
- H-allow < R/R with an **empty** `denied_hosts` is **`machinery{h_allow}`**: diagnosed and repaired, never excluded.
- The Wc4–Wc8 records' member verdicts **re-fold under this rule as an appended, dated re-classification record** — the discordance register is append-only; no landed verdict's bytes change.

## Consequences

R6.45j implements the rule in member roll-up and the `reproof` classification (regression: empty `denied_hosts` with H-allow < R/R → `machinery{h_allow}`; a named host → `allowlist_gap{host}`), plus the dated re-classification record for Wc4–Wc8. `re-scope{exclude-and-replace}` (A3's ladder) is only legitimate where this rule yields a real exclusion — a named denied host or an O-fail. The `allowlist_gap{unknown}` label produced by Wc4–Wc8 stays in the historical record; the re-fold appends the corrected reading.

## Alternatives considered

- **Keep `{unknown}` exclusions** — lets machinery defects drain the member list silently; the recorded Wc6/Wc7 outcome (0/14 covering, all `denied_hosts` empty) is exactly that failure shape. Rejected.
- **Treat empty-`denied_hosts` H-allow failures as inconclusive** — hides a repairable machinery defect behind a verdict that repairs nothing; `machinery{h_allow}` keeps the repair obligation. Rejected.

## Revisit trigger

Revisit if a future deny source reports partial or non-host-level denies (a denied shape the `denied_hosts` field cannot name), or if the re-fold of Wc4–Wc8 reveals a member whose `denied_hosts` was non-empty — its exclusion re-enters review honestly.
