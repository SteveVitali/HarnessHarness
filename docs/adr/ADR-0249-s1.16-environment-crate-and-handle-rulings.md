# ADR-0249: S1.16 environment rulings — the `hh-env` crate shape, `EnvHandle` as a runtime object, fail-closed `attach`, honest `isolation_class`, and the `action.environment.*` rows

- **Status:** Accepted
- **Date:** 2026-09-17
- **Ticket:** S1.16
- **Requirement ids:** R-2.2.5
- **Spec:** §5a.5 (the C0/Stage-1 slice per the §5a.5 §9 stage map) ·
  ADR-0136…0138 · ADR-0062 (the containment gate) · DF-S1.12-3
- **Rung (ADR-0024 obligation):** **C0** — MUST-code: the `local_host`/
  `local_sandboxed` classes, `EnvHandle` lifecycle `declared → ready →
  torn_down`, `attach` with the stored `ContainmentReport`, `env_apply`,
  the effect-operation surface, and the `action.environment.*` family are
  §5a.5 Stage-1 items; `suspended`/`restored`, live EP2 backends, and
  `upload`/`download` transport stay Stage-2 data/behaviour.

## Context
S1.16 lands the execution-environment abstraction's Stage-1 slice. The spec
fixes the position — every environment operation is kernel-mediated
(R-NOSIDE), containment evidence is fail-closed, `isolation_class` is
recorded honestly — but leaves these concrete rulings to the slice:

1. **Where the environment runtime lives.** `hh-baseline` carried a
   throwaway `EnvHandle`; the ledger owns records, `hh-containment` owns
   the policy/report machinery, `hh-monitor` owns decisions — none of them
   own the handle's lifecycle.
2. **What the `EnvHandle` is.** The spec's `EnvironmentRecord` is a sealed,
   content-addressed record; the handle is per-run state (sessions, meters,
   roots, the applied containment report) that must never itself become a
   capability the model can pass around.
3. **When `ready` is earned.** `attach` can produce a `ContainmentReport`
   whose field-group evidence is `unknown`/`degraded`; the ACs require
   `unknown` evidence never reach `ready`.
4. **How the clocks account.** AC-R-2.2.5-9's `reserved ⊇ active +
   suspended` needs the dead-kernel gap excluded from `active` — the meter
   is the kernel's observation, not the environment's claim.
5. **What an image name means.** A mutable tag (`myimage:latest`) is a
   resolution, never identity; the `EnvironmentRecord`'s R2 reproducibility
   claim requires a content address.

## Decision
- **§1 — `hh-env` is the persistent crate.** It owns `EnvironmentRecord`/
  `EnvHandle`/`EnvDriver`, the executor surface and the dispatcher
  (ADR-0250); deps are `hh-ledger`/`hh-containment`/`hh-monitor`/
  `hh-secrets`/`hh-hir`/`hh-identity`/`hh-provenance`/`hh-ontology`/
  `hh-wire` — no `Text` leaf authored. `hh-identity` gained
  `RecordKind::EnvironmentRecord` (additive, semantic projection — CC8).
- **§2 — the handle is a runtime object, not a record.** `EnvHandle` holds
  `state` (`declared|ready|unreachable|torn_down`), `roots`, `sessions`,
  `health`, `meters`, the resolved `image`, the `containment` `PolicySlot`
  (DF-S1.12-3's seam — declared now), the stored `ContainmentReport`, and
  `applied_event_ref`. It mints no capability; every mutation goes through
  `EnvDriver` and appends an `action.environment.*` row.
- **§3 — `attach` is fail-closed and the report is stored before
  `ready`.** `EnvDriver::attach` runs `hh_containment::attach`, persists
  the report on the handle, appends `security.containment.applied`/
  `unverified`, then `action.environment.attached` (naming the applied
  event) and `ready` — only when every required field group is evidenced.
  A missing backend, a degraded report, or `unknown` evidence is
  `EnvError::ContainmentUnverified`/`Attach` and the handle stays
  non-`ready` (AC-R-2.2.5-6). Seal-side `PermissionUnreachable` warnings
  are computed at attach via `unreachable_permissions()` (the DF-S1.12-3
  warning half).
- **§4 — `isolation_class` is declared per class, never coerced up.**
  `local_host` declares `IsolationClass::None` honestly; the capability
  declaration (`EnvCapabilityDeclaration::stage1_local_*`) marks unknown
  kinds `Tri::Unknown` — `snapshot_supported` refuses `Unknown`/
  `Unsupported` distinctly.
- **§5 — the three kernel clocks are the kernel's observation.**
  `EnvMeters` tracks `reserved_ms`/`active_ms`/`suspended_ms`;
  `mark_unreachable` closes the active bucket at last contact so the
  kernel-dead gap is excluded from `active_ms` — `heal` reattaches within
  the declared `reattach_window_ms` and probes, never re-executes
  (AC-R-2.2.5-2, -9).
- **§6 — image identity is content identity or nothing.**
  `ImageRef::{ContentAddress, ForeignDigest, Tag}` — `resolve` refuses a
  bare tag (`UnresolvedRef`) unless the record's `unpinned` set names it
  (honestly recorded, never R2); `ForeignDigest` is a recorded claim that
  fails `check_repro("R2")`; only a `ContentAddress` is R2 identity
  (AC-R-2.2.5-5).
- **§7 — the `action.environment.*` family is ledger-durable, non-audit.**
  The lifecycle rows (`provision.requested`/`provisioned`/`ready`/
  `fenced`/`suspend.*`/`resume.*`/`release.*`/`lost`/`probe.*`/
  `unreachable`/`reattached`/`torn_down`/`snapshot`) are `row(...)`
  kernel-origin classes — they carry handle state, not a Rule-C dossier.

## Consequences
- The handle seam DF-S1.12-3 owed this ticket is landed: `PolicySlot`,
  stored report, `attached` referencing `applied`, per-use
  `verify_environment`/`verify`. The live out-of-process EP2 backend stays
  with S2.1 (the deferral row notes the partial).
- `path_baseline` is the Stage-1 snapshot kind — the fs-diff observer's
  anchor — taken at `prepare` so a `reversible` effect's `baseline_ref` is
  the same snapshot the post-exec diff reads (ADR-0250 §3).
- A second scope field is *not* introduced: environment rows are
  run-scoped; the effect/tool-call chain is untouched.

## Alternatives considered
- **`hh-baseline` keeps the handle** — rejected: the baseline is the
  throwaway reference; the handle is a contract the persistent crates
  consume.
- **`EnvironmentRecord` doubles as the handle** — rejected: a sealed record
  is immutable identity; the handle is mutable per-run state.
- **Best-effort `attach` with a `ready` flag** — rejected: AC-R-2.2.5-6
  requires unknown evidence to fail closed, never reach `ready`.

## Revisit trigger
S2.1 lands the live EP2 helper backend (real `proc`/`fs`/`net` evidence
over a subprocess boundary); re-open if the `PolicySlot`/`ContainmentReport`
placement or the `ready` gate needs to move.
