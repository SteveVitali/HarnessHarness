# ADR-0223: S0.3 Stage-0 spike method — offline/hermetic scope, matched E1↔E1 crossing, CPU-vs-durable fan-out, and committed-throwaway trees

- **Status:** Accepted
- **Date:** 2026-09-15
- **Ticket:** S0.3
- **Requirement ids:** R-2.12.3 (measurement), R-2.5.5 (S1 spike), R-2.2.5 (S2 boundary slice)
- **Spec:** §10.6 (S1/S2 spikes, rules R1–R6), §9.1 (Stage-0 gating acceptance); `research/synthesis/l1-spike-spec.md` §3–§6; ADR-0050 §3/§6, ADR-0049 §5, ADR-0009 step 4

## Context
The Stage-0 acceptance check runs the S1 (kernel slice) and S2 (boundary slice) measurement spikes
to test ADR-0050's assumed C5/C7/C12 scores against the pre-registered `l1-spike-spec.md §5` bands
(revalidation trigger 5). The operator released the Stage-0 spike budget **offline/hermetic only,
no external spend** (LEDGER GATE DECISIONS, S0.3). Three forces shaped the method:
1. **`l1-spike-spec` R6 wants candidates E1/E2/E3 (S1) and the E5a/E5b/E5c splits (S2), each by a
   fresh executor with an R2 cross-camp reviewer.** Standing up E2/E3 kernels, the official MCP/ACP
   SDKs and a second-ecosystem reviewer needs foreign toolchains, network fetches and a human — none
   runnable hermetically, and none matchable-budget offline (CC9 forbids an unmatched comparison).
2. **The l1-spike-spec S1 slice presupposes a substantial durable event store** (ADR-0027 id model,
   hash chains, `project()`, crash recovery, blob offload) that does not exist in the persistent
   kernel at Stage 0 (§9.1) — it must be built *fresh from the spec* as throwaway spike code.
3. **A naïve fan-out / boundary-overhead measurement is confounded by the host** (12 cores, one SSD)
   in ways that are storage/host artifacts, not ecosystem properties.

## Decision
- **Measure the winning candidate offline; defer the rest with compensating controls, never
  fabricate.** Build throwaway spikes for the **E1** kernel slice (`spikes/s1-kernel-spike/`) and
  the **E5a** crossing mechanism (`spikes/s2-boundary-spike/`), reusing only the pure-std `hh-wire`
  primitives so everything runs hermetically. The non-winning candidates, official-SDK MCP/ACP
  calls, cross-candidate hash identity, two-toolchain CI and R2 review are `DEFERRALS.md` rows
  (DF-S0.3-1/-2/-3) with compensating controls. This is justified by the ADR-0050 §4 kernel-family
  robustness (E1-kernel wins 0.979 of corners; survives every adversarial sweep), which makes the
  winning-candidate measurement decision-sufficient for the trigger-5 evaluation at Stage 0.
- **Matched E1↔E1 for the crossing (CC9).** The S2 per-run overhead is the *same E1 kernel* driven
  over the stdio boundary (split) minus in-process (native) — both arms E1, so the comparison is
  same-budget and isolates the pure transport cost. The polyglot penalty (the reason E5a's assumed
  C12 = 2) is the deferred piece (DF-S0.3-2), re-scored at Stage 3 with the E2 lab.
- **CPU-vs-durable fan-out, both reported (R3 host recorded).** C5 fan-out is scored from the
  **CPU/concurrency** core-normalized ratio (the `l1-spike-spec` framing: "ideal 1.0 if perfectly
  parallel on ≥50 cores"), corroborated by achieved parallelism, cancel latency and tail lag. The
  **durable** fan-out (fsync-serialization-bound on a per-session-WAL / no-group-commit throwaway
  design) and the raw wall ratio are reported for completeness with an explicit host/storage caveat,
  not used as the C5 score.
- **N ≥ 3 repeat scoring.** Each measurement is run **N = 5** and reported as median · min–max
  (`scripts/spike-s0.3-measurement-sheet.sh`), never a single point.
- **Committed-but-throwaway trees (deviation from R4 "code deleted").** The spike trees are
  committed (outside the Cargo workspace, `exclude=["spikes"]`; not a kernel dependency) so the
  measurement sheet is reproducible and the run auditable (CC3), then deletable at the Stage-0
  boundary without breaking anything. This extends the bounded R4 deviation ADR-0220 already
  established for the S0.1 boundary harness.

## Consequences
- Good: the winning candidate has real, reproducible Stage-0 numbers; the gates are executable unit
  tests; the honesty rules hold (no fabricated candidate, no host artifact scored as an ecosystem
  property, no unmatched comparison). DF-S0.1-1 and DF-S0.2-1 are discharged with evidence.
- Cost: the cross-candidate / polyglot / official-SDK cells are not measured at Stage 0 (deferred);
  the R4 "delete the code" rule is deviated (bounded, recorded); the durable-throughput and durable
  fan-out are pessimistic vs a group-commit kernel.
- The numbers are internal tier-B (R5): they support no claim outside the ADR-0009 matrix.

## Alternatives considered
- **Stand up E2/E3 kernels + official SDKs offline.** Impossible hermetically (foreign toolchains,
  network SDK fetches); fabricating their numbers is forbidden.
- **Score C5 from the raw/durable fan-out ratio.** Rejected: it is a 12-core + fsync-serialization
  host artifact, not the concurrency mechanism C5 scores; scoring it would falsely arm trigger 5.
- **Score C12 = 5 from the favorable E1↔E1 transport measurement.** Rejected: C12 by definition
  includes the polyglot penalty (unmeasured offline); asserting 5 would falsely arm trigger 5 in the
  *positive* direction. The transport result is recorded as "consistent, not contradicting."
- **Delete the spike code per R4.** Rejected as in ADR-0220: committed-but-throwaway keeps the sheet
  reproducible and the run auditable (CC3); the trees are deletable and non-load-bearing.

## Revisit trigger
An online spike budget is released (foreign toolchains / network SDKs / a second-ecosystem
reviewer available), **or** Stage 3 exercises the kernel↔lab boundary with the real E2 lab: run the
cross-candidate S1 scoring, the E5b/E5c splits, the official MCP/ACP calls (M-S1-7), and the C12
polyglot components (M-S2-5 + cross-ecosystem serialization), then close DF-S0.3-1/-2/-3 and
re-confirm the trigger-5 evaluation in the ADR-0050 amendment log.
