# ADR-0370: R4.9 — BL-32's hermetic half: the `ForeignFormat` sum and the four remaining lifts (swebench/inspect/in-toto/OTLP)

- **Status:** Accepted
- **Date:** 2026-10-22
- **Ticket:** R4.9
- **Requirement ids:** DF-S4.2-2 (closed — **DONE** appended) · BL-32
  (hermetic half; DF-S4.2-1 remote fetch stays R4.15d's) · R-2.9.3 ·
  R-2.10.3 · R-2.10.5 · AC-R-2.9.3-8/-9 · CC1 · CC2 · CC3 · CC8 ·
  ADR-0141 (the import invariants) · ADR-0213 (OQ-030's interchange
  deferral) · ADR-0293 ruling 7 (whose deferral row this discharges)
- **Spec:** §5h.3 §2 (the import/export contract + the declared foreign
  vocabularies)
- **Rung (ADR-0024 obligation):** C1 — fixture-verified hermetic cells;
  no live legs, no remote transports, no trust fields.

## Context

§5h.3 §2 declared seven foreign artefact vocabularies; S4.2 landed two
(`harbor_trial_dir`, `harbor_job_dir`) plus the export-only
`interchange_trajectory` (its import half parked on OQ-030, ADR-0213),
and parked the remaining four — `swebench_submission`,
`inspect_eval_log`, `in_toto_bundle`, `telemetry_trace` — as DF-S4.2-2,
discharged here. Until this ticket the format axis was a `&str` +
`FOREIGN_FORMATS: [&str]` list; the AC asks for a *typed* `ForeignFormat`
(the closed sum the ticket's grammar names), lifts that mint claim and
loss records rather than bare file members, and export→import
round-trips where the format is symmetric.

Four rulings were needed: (a) the closed sum's *shape* and the
direction grammar; (b) each format's claim set — what a lift may mint,
and what stays artefact-verbatim as a named loss; (c) the symmetric
lowerings — what the export emits and what it honestly narrows;
(d) the one asymmetry that survives even a byte-stable round-trip.

## Decision

1. **`ForeignFormat` is the closed sum; `parse` is the one grammar.**
   `crates/hh-bundle/src/foreign.rs` owns the seven-member enum with
   `as_str`/`parse`/`lifts()`/`exports()` (CC1). A spelling outside the
   sum is `FormatUnknown`, never a guess; a known format asked the
   direction it does not support is the new typed
   `BundleError::ForeignDirectionRefused{format, direction}` —
   `interchange_trajectory` at `import`, `harbor_trial_dir` at
   `export`. `lift_foreign`'s signature takes the typed
   `ForeignFormat`; `kernel.import` parses once at the boundary and
   preserves the wire refusal. The two spellings beyond the ticket's
   four (`harbor_*`) keep their landed semantics.

2. **Lift claims mint only what the format's own schema names.** Each
   `lift_claims` arm parses the artefact (`hh_wire::json::parse_provider`
   — non-integer lexemes like Inspect metric floats lift verbatim as
   `Json::Str`; the kernel never re-emits them) and mints typed claims
   under the import-minted `unverified` provenance: `swebench.instance:*`
   `{model, patch_digest}`; `inspect.{version,status,task,model,
   sample:*,score:*}`; `intoto.subject:*`/`intoto.predicate:*`;
   `otel.service:*`/`otel.trace:*`/`otel.span_count`. Foreign names ride
   `name_bindings` (R-ID-4 — never pins); foreign fields with no native
   slot are `untyped_slot`/`narrowed`/`unparseable` mapping-loss rows
   (CC3 — nothing is silently absent; `unparseable` is an additive
   value in the loss `class` vocabulary, which stays an open string).

3. **An in-toto signature is a claim, never a verification.** The lift
   records `intoto.signature:<i> {keyid, status: present_unverified}` —
   counted, keyid named, never checked: no trust roots are in scope and
   `authority = unverified` is the whole point (CC2). Sigstore-shaped
   `verificationMaterial` (certificates/tlog entries) is foreign trust
   material — carried verbatim, `no_slot` loss, never adopted.

4. **The exports lower symmetrically; the asymmetries are named.**
   `swebench_submission` → `predictions.jsonl` (one row per subject
   run; `instance_id` = the run's `task_ref.task_id` else the run id
   with a `narrowed` row; `model_patch` = the newest recorded
   patch/diff payload field else `""` — the schema's documented *skip*
   marker — with a `no_slot` row, never a fabricated diff).
   `inspect_eval_log` → `eval_log.json` (the `.json` EvalLog spelling:
   scores only from `verification.validator.verdict` /
   `measurement.metric.emitted` rows, samples as minimal per-run rows —
   transcripts never fabricated). `in_toto_bundle` → one **unsigned**
   DSSE envelope (`signatures: []`) whose statement names the bundle +
   every present member as `sha256` subjects — signing is `attest()`'s
   claim, a lowering never fabricates one (the format's one
   asymmetric channel: a foreign signature lifts back as an
   `unverified` claim, ours exports empty — both named in the loss
   report). `telemetry_trace` → OTLP `traces.json`: one span per ledger
   event under one `resourceSpans` per subject run, deterministic
   digest-derived hex ids (same event ⇒ same ids), event
   payload/provenance narrowing to `hh.*` span attributes — the span
   stream cannot re-derive the event set and the loss row says so.
   Every symmetric artefact ships `manifest.json` + `digests.json`
   (the same trailer `harbor_job_dir` established) so the re-import is
   byte-stable: each artefact file returns as a `foreign:<path>` member
   at an equal content address and the declared digests verify.

5. **Fixtures are `stand-in` captures.** Each format's committed sample
   under `crates/hh-bundle/fixtures/foreign/<format>/` is hand-authored
   per its cited public schema (URL + consult date in the directory's
   `PROVENANCE.md`) — `capture_kind: stand-in`, no retrieval or
   observation dates, no upstream bytes claimed as captured.

## Consequences

- `import` now admits all seven declared vocabularies except the one
  direction ADR-0213 parked (`interchange_trajectory` in) — the typed
  refusal names it; DF-S4.2-2's cells are met and the row flips DONE.
  BL-32's remote half (DF-S4.2-1) stays R4.15d's — no transport code,
  no trust fields, no fetch changes.
- The mapping report gains a `notes` array (additive — CC8); the
  manifest gains `name_bindings` content on foreign lifts (additive).
- The loss `class` vocabulary gains one additive value, `unparseable`
  (a member line that is not the format's own grammar); the row shape
  is unchanged.
- Float-carrying foreign documents (Inspect metrics, OTLP values) lift
  through `parse_provider` — float lexemes arrive as `Json::Str`, are
  never re-emitted, and cannot corrupt a canonical hash.
- `ForeignFormat::ALL` is the closed set; a future format is an
  additive enum arm + direction-table entry, never a generalization
  (same pattern as ADR-0292's `ForeignSystem`).

## Alternatives considered

- **`&str` formats + a bigger `FOREIGN_FORMATS` list** — rejected: the
  ticket asks for the typed sum and the direction grammar; a bare
  string cannot express "known but wrong direction" without collapsing
  it into `FormatUnknown` (a lie) or a bare `Malformed` (untriaged).
- **Verifying in-toto signatures** — rejected: no trust roots are in
  scope, no key material may enter a ledger, and verifying nothing is
  worse than naming it — `present_unverified` is the honest claim.
- **Emitting a real `model_patch` from assembled members** — rejected:
  the bundle records patches as *event payload fields* when the harness
  recorded them; synthesizing a diff from member bytes would fabricate
  an artefact the run never produced. The empty patch + `no_slot` loss
  is the schema's own skip marker.
- **Refusing float-carrying documents** — rejected: Inspect logs carry
  float metric values by construction; `parse_provider` preserves the
  lexemes verbatim where strict `parse` would drop the whole document
  to "verbatim member only" and lose the typed claims the AC requires.

## Revisit trigger

Reopen ruling 1 if a new foreign vocabulary lands — the sum extends
additively (enum arm + direction-table row + lift/export arms), and a
format that is *neither* liftable nor exportable argues against joining
the sum. Reopen rulings 2–4 when DF-S4.2-1 lands: remote fetches bring
trust fields the claim set may need to name (a fetched signature's
`present_unverified` posture and the `origin = import` stamp interact
with the pending trust-field rulings). Reopen ruling 4's
unsigned-envelope arm if `attest()` ever runs *inside* a lowering —
signing-in-export would need its own authority ruling. Reopen the
`unparseable` class value if the loss vocabulary is ever made a closed
sum — the value then joins the enum deliberately.
