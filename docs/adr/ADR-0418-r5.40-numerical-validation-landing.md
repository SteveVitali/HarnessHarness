## Context

GATE-G9 admitted the seven dossier packets **as written**, including the
S.4 proposed simulation grid (`T ∈ {10,20,30} × R ∈ {5,10} × effect ∈
{0,±.05,±.10} × mixture {easy, hard, heterogeneous} × mechanism
{zero activation, informative missingness/vetoes, shared shocks}`,
≥2,000 datasets/cell, seed rule `H(canonical(scenario ∥ version ∥
replicate))`). The methods-partition freeze obligation (memo :213):
the numerical-validation protocol is not execute-grade until its exact
parameters/seeds/error tolerances are pinned **in the reviewed
method/validation admission packet** — this ADR is that packet.
R5.17's independent review found DF-R5.17-1 (a `beta{2,2}` declaration
persisted its label over `Beta(1,1)` math — `decl.prior` never entered
the conjugate update); GATE-G10 deferred its repair to this ticket.

## Decision

1. **DF-R5.17-1 repaired at the owning admission.** The declared prior
   now parameterizes the conjugate update in
   `hharness_eval::finite_manifest`: posterior mean `(c+a)/(n+a+b)` per
   arm, draws `beta_inv_ppm(u, c+a, n−c+b)`. The registered `beta{1,1}`
   arm is byte-identical (`(c+1)/(n+2)`); the `beta{2,2}` EX-02 known
   answer is posterior mean `1/9 = 111_111 ppm` (verified vs the
   deferred row's predicted seam). This is a defect repair, not a new
   method: the admitted contract always predeclared `beta{2,2}` as the
   exploratory sensitivity; persisting its label over `Beta(1,1)` math
   was the recorded mislabel.
2. **Shared core, never a second implementation.** The estimator is
   factored into `resolve_core` (validation + cell derivation +
   observed/posterior mean + canonical seed material) and `draw_deltas`
   (the seeded inverse-CDF draw loop). `finite_manifest_contrast` is
   unchanged externally (same refusals, same ladder, same report);
   `finite_manifest_headline` returns the *reported* interval/mean/
   observed at the declared 8,000 base draws — bit-identical by
   construction (same seed stream, same first draws, same quantile;
   asserted by `headline_is_estimator`). The 16k–64k doubling ladder
   stays the report's numerical-error instrumentation and is not part
   of the interval. The battery uses the headline so the ≥2,000×42-cell
   execution stays inside the D2 envelope (~7 core-hours measured vs
   ~36 for the full ladder).
3. **Frozen `sim_battery/1` protocol** (`hharness_eval::sim_battery`):
   the scenario table — `easy` grid `T{10,20,30}×R{5,10}×effect
   {0,±.05,±.10}` (30 cells); `hard` at T=20/R=10 over all five
   effects (5); `heterogeneous` at T=20×R{5,10}×mean effect {0,+.05}
   (4, per-task `δ_t ~ Uniform{−.10…+.10}`); the three mechanism legs
   at T=20/R=5/effect 0/easy; `beta{2,2}` diagnostic arms on
   T∈{10,30}/R=5/effect {0,+.05} easy cells — 42 cells × declared
   ≥2,000 datasets. Mixtures: easy `p_A ~ U{.70….90}`, hard
   `U{.10….30}`, heterogeneous `U{.30….70}` (discrete 0.05 grid).
   Generator → real `population::assemble` → the headline; seed rule
   `H(canonical(scenario ∥ sim-battery/1 ∥ replicate))` via
   `XorShift64::seeded`. Recorded per cell (integer-ppm only): declared
   vs run datasets, computed count, typed-refusal census, generator
   failures, availability, **diagnostic** coverage (labelled
   diagnostic, never a nominal frequentist guarantee — S.4/M-G), mean/
   max width, mean |posterior error|, the sharp-null sign-flip verdict
   leg (α=.05; exact ≤20 / 8,000 MC above — the `relevant` type-I
   reading on null cells), armed prior-shift, and the max binomial
   Monte Carlo error.
4. **All-or-nothing rollup, never a fallback.** `battery_rollup` reads
   `complete` only when every cell `Executed` at its declared count
   with zero generator failures; a `Stopped`/`Failed`/short/unrun cell
   can never count as method admission and partial aggregates are
   retained (AC-2). The executor caps at ≤4 worker threads and cites
   the D2 envelope (≤8 h wall / 4 cores·8 GiB / 32 core-hours / 2 GiB)
   per stage — never a pooled build allowance.
5. **Retained evidence.** The executed record lands at
   `docs/build/reports/2026-11-03-r5.40-sim-battery.json`
   (integer-canonical); the routed native report path is proven by the
   `analyze`/`analyze_and_record` legs (persisted `analysis_report_body/1`
   with the exploratory prior's params/label/repaired posterior/S.1
   metadata). No study-level, live, S1/S3, parity or confirmation claim
   is made or implied (GATE-G10 posture carried).

## Consequences

- Determinism: identical `(scenario, replicate)` yields identical
  datasets and outcomes; the whole battery recomputes byte-identically.
- DF-R5.17-1 closes DONE — the defect's verify recipe (posterior mean
  111_111 on EX-02 + independent beta{2,2} endpoint reproduction ≤20k
  ppm at 60k fresh draws) passes in `r5_40.rs`.
- `finite_manifest_headline` is an offline validation surface — callers
  still get refusals identically; it is never a report path.
- An incomplete battery blocks only its dependent method-admission
  claim; the retained record keeps owner/trigger for re-execution.

## Alternatives considered

- **Full-ladder per dataset** — rejected: ~36 core-hours estimated
  exceeds the 32 core-hour tranche; the headline shares the estimator's
  code so no fidelity is lost on the reported quantity.
- **Smaller scenario table or lower dataset count** — rejected: the S.4
  floor is ≥2,000/cell and every listed factor must appear; the 42-cell
  table is the minimal faithful instantiation.
- **Deferring the prior repair** — rejected: GATE-G10 and DF-R5.17-1
  name this ticket the follow-through owner; leaving the mislabel would
  corrupt the diagnostic prior-sensitivity evidence AC-1 requires.

## Revisit trigger

- If a later admitted prior/draw/floor set changes, the frozen table
  and headline factor move with their admission — amend this record's
  Decision 1–3, never silently (quiet-conditional → BL-47).
- If the executed battery reports systematic under-coverage,
  unavailable endpoints or generator failures, the method-admission
  claim stops for review; the record keeps the failing cells.
- If the D2 envelope interpretation changes (cores/wall accounting),
  re-check the executor's ≤4-thread cap and the recorded wall/core
  hours.
