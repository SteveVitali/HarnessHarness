# ADR-0258: S1.22 eval-framework rulings — one complete `MetricDeclaration`, the `hh-ontology::eval` vocabulary home, `MetricValue` as the emitted payload, `version_id` budget equality, and `validator` bodies as `OracleDeclaration`s

- **Status:** Accepted
- **Date:** 2026-09-18
- **Ticket:** S1.22
- **Requirement ids:** R-2.9.2
- **Spec:** §5h.2 · ADR-0045/0046/0047 · CF-094 · CF-099 · T-LCD-15
- **Rung (ADR-0024 obligation):** **C0** — MUST-code: the eval vocabulary sums,
  the complete `MetricDeclaration`, `OracleDeclaration`, the experiment
  records (`FactorDeclaration`/`Design`/`PreRegistration`/`Arm`/`Cell`/
  `RunOutcome`), `MetricValue` + typed `n/a{reason}`, `derive_outcome_class`,
  the `measurement.metric.emitted` payload, the `metric_declaration` and
  `validator` registry bodies, and every declaration-level schema check.
  `compare`/`paired_effect`/`render_scorecard`/`equivalence_run`, interval
  estimators, deterministic-oracle wiring and `LeakedSplit`/consumption-
  tolerance checks stay at their spec'd stages (DF-S1.22-1/-2).

## Context
§5h.2 defines the evaluation framework — how metrics are declared, produced
by oracles, and compared across arms under matched budgets. At this ticket's
start, three *partial* metric shapes existed side by side
(`hh-ontology::compliance::MetricDeclaration` with only applicability fields,
`hh-telemetry::catalogue::ProcessMetric` with its own fold vocabulary, and
`hh-secrets::metrics::SecretMetric` wrapping the partial declaration), the
oracle vocabulary lived in `hh-verification::vocab` (a higher plane than the
consumers that need it), `ChargedTo` lived in `hh-hir::kinds`, `ModelRole` in
`hh-compiler::profile`, and the `measurement.metric.emitted` payload carried
the §5h.1 `{subject, metric_ref, value, unit, detector_ref}` shape. The
registry's `metric_declaration`/`validator` kinds existed in the closed
`RecordKind` list but had no record bodies.

## Decision
1. **One complete `MetricDeclaration`, extended in place in
   `hh-ontology::compliance`.** All 19 declared members land on the existing
   type (CF-094 — partial forms are superseded, never kept as parallel
   shapes): `dimension`, `level`, `value_type`, `direction`, `unit`,
   `applies_to_families`, `requires_capabilities`, `requires_mediation`,
   `admissible_granularities`, `oracle_classes_allowed`, `replicate_reducer`,
   `interval_method`, `outcome_class_policy`, `headline`, `veto`,
   `charged_to` join the existing applicability fields. `Default` yields the
   implied values of the superseded partial form so existing construction
   sites keep compiling (`..MetricDeclaration::default()`), and
   `validate()` enforces the schema rules: `veto ⇒ ¬headline`, `headline ⇒
   oracle_classes_allowed ⊆ C0-deterministic ∧ detector_classes_allowed ⊆
   {deterministic}`, `interval_method = clt` never on heavy-tailed units,
   non-empty name/classes/detectors/oracles.
2. **The eval vocabulary lives in `hh-ontology::eval`; everyone else
   re-exports.** `OracleClass`, `LatticeValue`, `VerdictType`,
   `EvidenceKind` moved from `hh-verification::vocab`; `ChargedTo` from
   `hh-hir::kinds`; `ModelRole` from `hh-compiler::profile`. Every old path
   stays a working `pub use` (CC8 — no call site breaks, `name()` aliases
   preserved) while there is exactly one definition per concept (CC7 — the
   `Detector` precedent, generalized). New §5h.2 sums land beside them:
   `Dimension`, `MetricLevel`, `MetricValueType`, `Direction`,
   `ReplicateReducer`, `IntervalMethod`/`BootstrapPairedMethod`,
   `OutcomeClassPolicy`, `MediationChannel`/`MediationRequirement`,
   `FactorKind`/`FactorLevel`/`FactorDeclaration`, `DesignKind`, `Pairing`,
   `SeedPolicy`.
3. **`measurement.metric.emitted` carries the `MetricValue` record.**
   `{metric_ref, value, applies_to, oracle_ref, detector, confidence?,
   evidence_ref?}` (ADR-0045 D9 scorer boundary) supersedes the §5h.1
   `{subject, unit, detector_ref}` partial form: the unit is declared on the
   `MetricDeclaration`, the subject becomes `applies_to`, and every value
   names its producing oracle (ADR-0047 D1). `MetricValueKind::Na(NaReason)`
   is a first-class typed value — `n/a{reason}` never serializes as 0 and no
   configuration-level proxy substitutes for it (T-LCD-15).
4. **`outcome_class` grows `oracle_failure`; the class is derived, never
   authored.** `derive_outcome_class(stop_reason, oracle_failed)` puts
   `OracleFailure` ahead of the stop-reason projection — a crashed/refused/
   unparseable oracle never yields a score (ADR-0047 D4). `RunOutcome`
   carries the derived class plus `veto_tripped[]` as a view over ledger
   facts.
5. **`Arm` budget equality is enforced by `version_id` equality.**
   `declare_arm`'s "every configuration's `budget_vector` equals
   `eval_budget` dimension-wise over the kernel dimension list" (CF-099)
   resolves at the record layer to *content-address equality*: both sides are
   pinned `Ref`s, and equal `version_id`s are dimension-wise-equal vectors by
   construction. A different *version* of the same semantic vector is
   `BudgetMismatchWithinArm`, never silently matched (CC9). The
   tolerance-banded *consumption* comparison is `compare`'s engine
   precondition — Stage 3, out of scope.
6. **Registry `validator` bodies are `OracleDeclaration`s;
   `metric_declaration` bodies are `MetricDeclaration`s.** Both kinds join
   `has_stage1_schema`; `body_json`/`record_from_json` delegate to the
   ontology codecs (CC7 — the registry re-encodes, never re-schemas);
   `register` runs each declaration's own `validate()` as the admission
   gate, so a headline metric admitting a judged oracle or a `judge`
   oracle declared `deterministic`/`subject`-charged refuses at
   registration. `calibration_ref` joins the snapshot-closure edge set; a
   Validator *component* still registers as a `variant` of the `validator`
   class — the `validator` *kind* is the oracle's declaration record.
7. **The six-axis `Factor` stays in `config`; the experimental factor is a
   separate `FactorDeclaration`.** `Factor`/`FactorKind`/`FactorLevel`
   describe swept dimensions (`{kind, level{ref, label}, role?}`); the
   existing `config::Factor` enum remains the configuration-axis vocabulary.
   No conflation, no rename.

## Consequences
- Every metric in the system — process catalogue rows, `secret_*` vetoes,
  future engine metrics — compiles to the same 19-member declaration;
  `hh-telemetry::catalogue` generates full declarations from row data and
  `hh-secrets::metrics` folds `SecretMetric`/`MetricCharge`/its interim
  `MetricLevel` away entirely.
- `hh-ontology` gains an `hh-provenance` dependency (declarations carry
  `provenance`); the direction stays acyclic — provenance depends on wire
  only.
- `applies_to_families` stores family **name spellings**, matching
  `VariantRecord.applies_to.families`; the typed `EnvironmentFamily` ref is
  S1.24's and the migration is additive (DF-S1.22-3).
- Stage-3 consumers get complete inputs: `compare` reads `Arm`/`Design`/
  `PreRegistration` directly; estimators get `IntervalMethod` +
  `EstimatorSelection`; the results projection gets `MetricValue` rows with
  oracle provenance.
- Codec discipline is uniform: strict member whitelists, unknown spellings
  refuse, `Ref`/`Configuration`/`ProvenanceRecord` decode through their own
  canonical codecs.

## Alternatives considered
- **Keep `MetricDeclaration` partial and wrap it** (the old `SecretMetric`
  pattern): rejected — it is exactly the CF-094 fragmentation the spec
  forbids; three shapes would need three migrations later.
- **Keep oracle vocabulary in `hh-verification`:** rejected — eval records,
  telemetry payloads and registry bodies need it below the P4 plane
  (CC10/CC5 — the telemetry layer may not reach into verification).
- **`semantic_id` equality for arm budgets:** rejected — two versions of the
  same semantic vector can differ dimension-wise; `version_id` equality is
  the honest pinned check until `compare` can read vector bodies.
- **`Arm.eval_budget` as an embedded `BudgetVector`:** rejected — records
  reference by identity (CC3); the vector body belongs to its own record
  kind, the ref keeps the arm sealed-closure-safe.

## Revisit trigger
Reopen when the Stage-3 experiment engine lands `compare`/`declare_arm` ops
(needs the dimension-wise *content* check over real `BudgetVector` bodies and
the consumption-tolerance path), when `EnvironmentFamily` records land in
S1.24 (migrate `applies_to_families` to typed refs), or when judged oracles
become admissible at C1 (headline restriction and `calibration_ref` wiring
get their runtime halves).
