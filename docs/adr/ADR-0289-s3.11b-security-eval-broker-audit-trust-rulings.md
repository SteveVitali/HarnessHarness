# ADR-0289: S3.11b credential/egress/audit/trust/approval rulings

- **Status:** Accepted
- **Date:** 2026-09-24
- **Ticket:** S3.11b (`058_S3.11b__security-eval-broker-audit-trust.md`)
- **Requirement ids:** R-2.8.3, R-2.8.4, R-2.8.5, R-2.8.6, R-2.8.7 (S3 slices)
- **Spec:** §5g.3–§5g.7 · §8.1 · owning ADRs ADR-0059/0064/0106/0139/0140;
  closes DF-S1.15-2's remaining arms

## Context

S3.11b lands the Stage-3 credential/egress/audit/trust/approval security
executables: the `secret_leak` suite veto (LT-03/LT-11), the
`known_value_encoded` detector + `secret_detector_miss_rate` fold (LT-12),
the T-CON egress/containment battery (AC-H4-04/05/06) and the matched-budget
AC-H4-11 arms, the bundle `extensions[]` member surface and the
`audit_view.extensions` provenance fold (AC-R-2.8.5-10), and the
`audit_completeness` veto evaluated over the projected completeness vector
(DF-S1.15-2). The ticket owned these rulings:

1. **What the `secret_leak` veto reads.** LT-03/LT-11 are suite-level
   vetoes — the evaluator needs a declared input for "the run leaked",
   never a scan it invents.
2. **What the `audit_completeness` veto evaluates.** DF-S1.15-2 requires
   the veto to fire over `coverage.unmet` — but the ledger already
   projects a richer completeness verdict (`audit_view.completeness`)
   than the Stage-2 open-effects arm.
3. **How the encoded detector stays honest.** LT-12's detector must be
   deterministic and corpus-measurable — guessing encodings on untrusted
   text is unbounded and unmeasurable.
4. **Where per-effect extension provenance comes from.** AC-R-2.8.5-10
   requires `audit_view` to name, per effect, the extensions whose text
   was in the proposing call's context and whose code produced the
   effect — the fold must run over durable evidence, never a parallel
   audit store.
5. **What a bundle extension member is.** `resolved_dependencies
   .extensions[]` carries a `content` pin; the bundle must decide what a
   pin means for member bytes and for closure when the payload cannot be
   captured.
6. **How AC-H4-11's "84% fewer prompts" figure is treated.** The spec
   quotes a motivating number; the matched-budget comparison must not
   turn it into an asserted result.

## Decisions

- **D1 — `secret_leak` is a registered veto over recorded findings, never
  a rescan.** `veto_id::SECRET_LEAK` joins the closed veto-id set
  (`veto: true`, `charged_to: instrument`); `LedgerFacts` folds
  `security.secret.leak_detected` rows (`secret_leak_rows`) and
  `VetoContext.secret_scan_findings` carries the caller-projected
  `leak_scan` verdict over model request views (LT-11's surface — the
  suite declares which views it scanned; the veto never scans itself,
  CC5). A `leak_detected` row *or* a non-empty request-view finding trips
  the veto — the run's success is success-with-veto, never headline.
  (`crates/hh-eval/src/vetoes.rs`, `crates/hh-eval/src/facts.rs`)

- **D2 — `audit_completeness` reads the projected `audit_view` verdict
  via `VetoContext.audit`.** `AuditVerdict{headline, coverage_unmet[],
  failing[]}` is the caller's projection of
  `audit_view.completeness` + `coverage.unmet`
  (`AuditVerdict::from_audit_view` — the veto reads the view's own
  judgements, never recomputes them). When `audit` is `Some`, the veto
  additionally trips on `headline = false` or a non-empty
  `coverage.unmet`, naming the failing components; `None` keeps the
  Stage-2 open-effects arm (additive — CC8). `n/a` components carry their
  reason and never count as clean or as failing
  (AC-R-2.8.6-13). (`crates/hh-eval/src/vetoes.rs`)

- **D3 — `known_value_encoded` enumerates canonical encodings of mask-set
  values; it never guesses encodings on untrusted text.** The detector
  computes `encoded_forms(value)` = `{base64_std, base64_url, hex_lower,
  hex_upper, percent}` for each registered mask-set value and scans for
  those spellings — pure functions of a known value, so the detector is
  deterministic and the corpus can count planted spellings exactly.
  `ENCODED_MIN_LEN = 8` keeps short values out of the encoded arms (a
  4-byte value's base64 is a plausible word — false positives are a
  different anomaly); the verbatim `known_value` detector still covers
  them. `miss_rate(corpus, detect)` folds `planted`/`detected`/`misses`/
  `extra` (over-fires are reported under `extra`, never netted against
  misses) and reports `miss_rate_ppm`, `None` on an empty corpus —
  `n/a{estimator_undefined}`, never 0 (the canary remains the
  encoding-independent backstop; ADR-0059 D3).
  (`crates/hh-secrets/src/encoded.rs`, `crates/hh-secrets/src/redact.rs`,
  `crates/hh-secrets/src/metrics.rs`)

- **D4 — `audit_view.extensions` folds per-effect provenance from durable
  rows only.** Each effect entry
  `{effect_id, model_call_id, capability_ref, context_extensions[],
  producer_extensions[]}` is folded from: `security.extension.*`
  declarations (the run's registered extension ids),
  `lifecycle.capability.registered` producer refs (whose code produced
  the capability behind the effect), `context.assembled` extension taint
  tags ∩ run-declared extension ids (whose text was in the proposing
  call's context), and `action.effect.intended` capability refs. The fold
  is a projection of the committed prefix — no parallel audit store, no
  inferred membership (CC3/CC5).
  (`crates/hh-ledger/src/audit.rs`)

- **D5 — a bundle extension member is `{entry, bytes?}`; the `content`
  pin is the digest; absent bytes are named `unpinned{not_captured}`.**
  `AssembleInputs.extensions: Vec<ExtensionInput>` carries the
  `trust_snapshot` entry JSON
  (`{extension_id, content, trust_record, attestation_refs[],
  surface_pin?}`) plus payload bytes when the blob pool holds them.
  `assemble` deposits supplied bytes content-addressably and *recomputes*
  the pin — a mismatch refuses `BundleError::MemberMismatch` (the deposit
  is the verification, never a trust-the-caller copy). Absent bytes land
  `unpinned{role: "extension:<id>", reason: "not_captured",
  claim: <pin>}`; a `surface_pin` the caller cannot supply lands
  `extension:<id>:surface` the same way. `section_member_refs` walks
  `extensions[].content`/`surface_pin` as member refs *except* pins named
  in `unpinned[].claim` — S3 reads the declaration, never demands
  declared-absent bytes (CC3). `trust_snapshot` itself refuses
  unresolvable refs (`Unresolved`/`UnknownVersion`/`KindMismatch`) —
  entries are never silently skipped, and `snapshot_id()` re-derives over
  `idp/1` canonical JSON.
  (`crates/hh-bundle/src/assemble.rs`, `crates/hh-bundle/src/levels.rs`,
  `crates/hh-registry/src/extension.rs`, `crates/hh-embed/src/bundle_ops.rs`)

- **D6 — the AC-H4-11 "84% fewer prompts" figure is a pre-registered
  hypothesis, never an asserted result.** The four-arm matched-budget
  comparison (`{no sandbox + prompts, none, mediated strict, mediated
  with hatch}` under `MatchSpec`) reports measured
  `approvals.requested`/`granted`, `egress.ask_rate`,
  `containment.amendments_per_run`, and wall time in a `ComparisonReport`;
  the motivating figure rides the fixture as a *hypothesis* member the
  report records, so a divergent measurement is a finding, never a
  hidden failure (CC9 — matched-budget-or-refuse).
  (`crates/hh-containment/tests/s3_11b.rs`)

## Consequences

- `secret_leak`/`audit_completeness` join the closed veto-id set —
  `check_catalogue` conformance covers the new `veto.*` and process-metric
  declarations; a suite that never projects `audit_view` keeps the
  Stage-2 arm (no behaviour change for Stage-2 callers).
- Encoded detection is bounded to mask-set values ≥ 8 bytes — spellings
  under that length and encodings outside the five canonical forms are
  measured misses (`miss_rate` reports them), not silent coverage.
- `audit_view.extensions` adds a member to the view document (CC8
  additive); consumers that ignore it are unaffected, and the fold cannot
  produce an extension id the run never declared.
- Bundle manifests now name uncaptured extension pins — a reader that
  previously saw no `unpinned` rows may see `extension:*` rows; S3's
  member-ref walk is unchanged for fully-captured bundles.
- The bounded-prefix inclusion proof fix (prefix proofs are computed over
  the requested prefix, not the full leaf array) changes no API — proofs
  that were wrong now verify; no committed bytes change.

## Alternatives considered

- **The veto rescanning the run for secret patterns** — rejected: the
  evaluator is a contract-only consumer (CC5); `leak_scan` is the
  secrets plane's op and its findings are durable rows/caller-declared
  inputs, so the veto reads records like every other veto.
- **The `audit_completeness` veto recomputing obligations from facts** —
  rejected: it would duplicate `audit_view`'s judgement in a second
  implementation and invite drift (CC1); `AuditVerdict` is the one
  projection.
- **Generic encoding detection (detect "base64-looking" spans and decode
  them)** — rejected: unbounded false-positive surface and unmeasurable
  miss rate; enumerating encodings of known values is the measurable
  form LT-12 requires ("encoded forms of a *known* value").
- **Failing `assemble` when extension bytes are absent** — rejected: a
  sealed definition may pin extensions the run cannot capture (hosted,
  foreign); `unpinned{not_captured}` is the honest declaration — the pin
  is still on the record and the closure check still walks it.

## Revisit trigger

- DF-S2.4-3's remaining surfaces (blob pool, manifest,
  `measurement.export.delivered` scan domain) land: revisit whether
  `secret_leak` should read a widened scan-domain verdict rather than the
  request-view finding alone.
- A mask-set value below `ENCODED_MIN_LEN` is observed leaking in an
  encoded form: revisit the floor or add a per-value opt-in encoding arm.
- S4.14b's hosted-participant halves land (DF-S1.15-3): revisit whether
  `AuditVerdict` needs a hosted `n/a{class}` member distinct from
  `failing[]`.
