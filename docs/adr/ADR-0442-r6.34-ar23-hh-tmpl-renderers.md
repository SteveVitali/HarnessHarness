# ADR-0442: AR-23 — `hh-tmpl/1`, `json_head_tail@1`/`text_head_tail@1`, `error_format` classes, and the `hh-tmpl/1` crate home

- **Status:** Proposed
- **Date:** 2026-11-10
- **Ticket:** R6.34 (E2-T0 docs bundle, manifest row 292)
- **Requirement ids:** contributing REQ-XE-110, REQ-XE-111, REQ-XE-112 (governing); REQ-XE-113 (the runtime-fill leg it partners)
- **Spec:** `docs/experiments-spec.md` §10.5 row **AR-23** ("`hh-tmpl/1`, `json_head_tail@1` / `text_head_tail@1`, `error_format` classes", kind ADR, first needed by E2-T0); §7.3 gap list **G2, G8, G9** and the REQ-XE-110/111/112 rows; canonical §5b.3 (surface-record rows — `result_render`, `error_format`, `transcript_render`, `prompt_layout.section_templates`); `docs/design/38_hir-native-gaps.md` Part 2 rows G2/G8/G9 and Part 4 (the template-subset decision, design label ADR-E2-C — design spellings are proposals; this ADR fixes the record)
- **Rung (ADR-0024 obligation):** architecture record for the E2 block — no new dependency (the template engine is std-only over existing `Text` leaves), no schema change, no spend.

## Context

The mini-swe-agent prompt and error surfaces carry template logic HH
cannot render today. **G2:** the instance prompt is a template
(`{{task}}`, `uname.*`) and HH has no template engine; running the
original's Jinja2 inside the representation is rejected (a Python
dependency inside the harness record) and porting all of Jinja is
rejected (a large mostly-unused surface). **G8:** the tool result is
not a template-rendered string — `OutputPolicy.model_view` is declared
but unconsumed. **G9:** format-error text is a fixed `kernel_note`;
the bad assistant turn must be omitted, the error rendered from the
capability's own rendering, and batch-scope failure must be declarable.

## Decision

1. **`hh-tmpl/1` — a std-only template subset over `Text` leaves.** The
   engine renders `{{ ident(.ident)* }}` substitution and
   `{% if ident == "literal" %} … {% elif … %} … {% else %} … {% endif %}`
   with Jinja's whitespace-control `-` markers on either delimiter, under
   Jinja's default `trim_blocks = false`, `lstrip_blocks = false`,
   `keep_trailing_newline = false`. No filters, loops, or expressions
   beyond `==` on string literals. Strict undefined: a template whose
   variable set is not a subset of the section's declared slots fails
   compile as `UnexpressibleSurface`; a slot unfilled at run time is a
   typed refusal that stops before any model call — never an empty
   string. If a pinned O template uses any construct beyond the subset,
   the grammar extends under this ADR before the document lands; the
   binding golden is O's recorded bytes (the §7.4 turn-1 census), never
   a reading of Jinja. Template slot values that depend on the
   environment (uname) are filled at run time from a ledgered in-cell
   probe — REQ-XE-113 — never at compile time (compile stays pure).
2. **Typed `ResultRenderSpec` renderers.** `result_render` gains the
   variants `json_head_tail@1{threshold, head, tail,
   unit ∈ {chars, utf8_bytes}, fields, json_style}` and
   `text_head_tail@1` with typed-parameter constants (REQ-XE-110, G8) —
   the observation/error logic that cannot live in `hh-tmpl/1` becomes
   typed records, so sweep constants (the 10 000/5 000 bounds) are
   typed parameters, never string edits. `json_style =
   python_jinja_tojson` is admitted as a declared `json_style` value
   accepted only when its goldens match O's recorded bytes (the
   UNVERIFIED recollection caveat of design 38 Part 4 stands as the
   acceptance rule — hand-derived goldens are labelled
   `provenance: hand_derived`, never evidence).
3. **Typed `error_format` classes.** `error_format` maps format-failure
   classes to `Text` leaves with slots: `no_tool_calls`,
   `args_unparseable{error}`, `unknown_tool{name}`,
   `missing_param{name}`, `output_truncated{finish_reason}`; batch-scope
   failure is declarable (`format_failure_scope = batch`) (REQ-XE-111,
   G9). The Python `json.loads` error text inside
   `args_unparseable{error}` is a declared-divergence candidate — HH
   cannot reproduce it by construction and never fabricates it.
4. **The `hh-tmpl/1` home is a crate beside the consumer.** The engine
   lands in `hharness-compiler` next to `lower_layout` (the design's
   preferred home; the renderer-side alternative `hharness-context` is
   recorded as considered). One engine, one home (CC10) — no new
   dependency.

## Consequences

- R6.35/R6.36 consume the compiled `ResultRenderSpec`/`error_format`/
  `transcript_render` members through ADR-0440's single-renderer rule;
  the `hh-tmpl/1` crate lands with its consuming ticket.
- The L1 goldens for the renderers (BM1/BM2/BM15 for `json_head_tail@1`;
  BM4–BM8 for `error_format`) are O-recorded bytes at the gate; until
  the census lands, `provenance: hand_derived` labelling holds
  (REQ-XE-114 — hand-derived goldens are never evidence and are
  replaced before G-L1).
- The sweep registry's typed constants (thresholds, head/tail, unit)
  are the same members the V5 sweeps vary — the spellings this record
  fixes are load-bearing there.

## Alternatives considered

- **Pre-render at compile time** — rejected: compile is pure; uname is
  a run-time fact.
- **Run the original's Jinja2 in the cell** — rejected: a Python
  dependency inside the representation; "HIR represents X" would mean
  "HH calls mini's code".
- **Port all of Jinja** — rejected: a large surface, mostly unused.
- **String interpolation without a grammar** — rejected: no strict
  undefined leg, no whitespace fidelity, no refusal surface.

## Revisit trigger

Reopen if (a) a pinned O template requires a construct the subset cannot
express and the extension changes the engine's refusal contract; (b)
`python_jinja_tojson` goldens diverge from O's recorded bytes (the
UNVERIFIED caveat resolves against admission); or (c) the crate home
proves wrong at implementation (a second candidate is `hharness-context`,
chosen only through a new record).
