# ADR-0429: Task-declared deadlines above 900 s on a separate admitted path (AR-07)

- **Status:** Accepted
- **Date:** 2026-11-07
- **Ticket:** R6.9 (manifest 262)
- **Requirement ids:** REQ-XB-118, REQ-XB-119; alias REQ-XB-009
- **Spec:** experiments supplement §3.6/§3.3/§10.5 AR-07 (Q-X32); design/31 F13
- **Rung (ADR-0024 obligation):** C1 — a second derivation beside the frozen one; no schema addition

## Context

HH's sanctioned derivation is `min(declared, 900 s)` with a named-task
admission bounded ≤ 900 (ADR-0422). 39/89 TB 2.1 verifier timeouts
exceed 900 s (up to 12 000 s). §3.6 requires "a separately recorded
admission, never a wider silent bound" and the legacy path
byte-identical.

## Decision

1. `hh-env::task_deadline` adds `task_declared_deadline_ms(declared_sec,
   multiplier_ppm, ceiling_sec)` — `declared × multiplier / 1e6` in ms
   bounded by the *protocol-declared* ceiling. Values above the ceiling
   refuse `Unsupported{deadline.task_declared}` — excluded or
   pre-registered, never clamped. Malformed declarations (zero
   declared/multiplier, overflow) refuse.
2. `admit_task_deadlines(record, admission)` is transactional — every
   leg (named task, verbatim dataset pin/task digest/protocol, both
   enforced derivations) is checked before
   `ext["deadline_admission"]{source: "task.toml", agent{declared_sec,
   multiplier_ppm, enforced_ms}, verifier{…}, ceiling_sec, …}` stamps;
   `task_deadline_echo` yields the per-slot echo.
3. `VERIFIER_BOUND_CAP_SEC`, `verifier_deadline_ms` and
   `admit_verifier_bound` are untouched — the r5_57 battery passes
   unchanged (13/13).
4. The worker's ST0 admits `task.deadlines` through this path
   (`admission:deadline_admission` on refusal — an ST0 refusal precedes
   any run, so produced facts are cleared); `phases[]` carry declared,
   multiplier and enforced values. On agent-deadline lapse the cell
   drive terminates the agent process group (TERM→KILL) and the slot
   proceeds to verification with `end_cause: agent_timeout`
   (REQ-XB-119).

## Consequences

- Two deadline derivations coexist by design: the legacy `min`
   path for round-5 subjects and TB 1.0, the admitted task-declared
   path for TB 2.1 under a protocol ceiling.
- A multiplier pushing an enforced value over the ceiling refuses —
   a declared deviation is a new admission, never a silent bound.

## Alternatives considered

- Widening `VERIFIER_BOUND_CAP_SEC` or reusing `admit_verifier_bound`:
   rejected — §3.6 forbids a wider silent bound; the frozen §9.2
   envelope is neither amended nor reused.
- Clamping above-ceiling declarations: rejected — honest refusal.

## Revisit trigger

A second protocol needs a different ceiling or a setup multiplier other
than the declared 1.0: the ceiling and multipliers stay declared
members; the derivation is reopened by a new ADR.
