# ADR-0360: R3.7 `dpop` proof wire-shape and the `wrapped_long_lived` delivery registration

- **Status:** Accepted
- **Date:** 2026-10-15
- **Ticket:** R3.7
- **Requirement ids:** BL-19 · DF-S1.13-1 · DF-S1.13-4 · R-2.8.3 ·
  ADR-0359 (the dep admission this design rides) · ADR-0342 (D2 — the
  fail-closed posture preserved) · ADR-0032 (the `prepare`
  compensating-revocation hook) · CC1 · CC3 · SV-2
- **Spec:** §5g.3 (credential mediation — `SenderConstraint::Dpop`
  proof-of-possession; `wrapped_long_lived` delivery; the
  `RevokeIntent` destination half landed at S2.4)
- **Rung (ADR-0024 obligation):** C0/C1 — fixture-verified inside the
  offline ceiling; no live issuer, key custody or network leg
  (OQ-170).

## Context

ADR-0359 admitted `ring =0.17.14` to `hh-secrets` for asymmetric
signature verification. This ADR owns the *shape* the verification
takes and the *registration* the wrapped delivery performs — the two
design questions the dep ADR deliberately left open:

- A `dpop` proof must bind a request to a key the binding pinned — but
  this build has no JWT stack and admits none: what is the honest
  proof object, what does it sign, and how is the bound key
  identified without carrying key material into a ledger?
- `wrapped_long_lived` delivery must register its compensating
  revocation *before* the wrapped value is visible (ADR-0032's
  `prepare` hook at the credential plane): which row carries the
  registration, how is the compensation plan identified, and how does
  a revoked wrap probe `not_applied` (LT-05's leg)?

## Decision

- **D1 — the proof object is `DpopProof{alg, public_key, signature}`,
  a byte-level construction, not a JWT.** RFC 9449's JOSE envelope
  (header/payload/signature over base64url JSON) would admit a second
  canonical-JSON-plus-base64 stack the workspace does not have and
  does not need: the fixture's honesty ceiling is *a real `ring`
  signature verified against a real public key over a deterministic
  preimage*, not a DPoP-token wire codec. `alg` is the closed sum
  `DpopAlg::{Ed25519, Es256}` — exactly the two verifier algorithms
  ADR-0359 D2 admits; an unknown or unsupported alg refuses
  `SenderConstraintUnmet`, never silently downgrades.
- **D2 — every verb signs its own preimage.** The signed material is
  `dpop:v1:<verb>\x1f<verb-fields>` — `bind`, `request` (mediate /
  mediate_sentinel / deliver_wrapped), `mint`, `presentation`
  (verify_minted). The per-verb tag makes a proof forged for one
  context unverifiable in every other: a signature over the `mint`
  preimage presented at `mediate` fails verification and refuses
  `SenderConstraintUnmet`; a request proof names the binding,
  method, destination, path and effect id, so a replayed proof over
  different coordinates cannot verify.
- **D3 — the bound key is the `sender_key` coordinate, pinned at
  `bind`.** `bind` on a `dpop` channel requires a `bind`-preimage
  proof; on verification the binding pins
  `sender_key = "dpop:<alg>:<hex fingerprint of the public key>"` —
  a content-free coordinate (a hash of key material, never the key
  itself; SV-2). Every later verb re-derives the proof's
  `sender_key` and requires equality with the pin *before* signature
  verification — a foreign key's valid signature refuses, a bound
  key's signature over foreign coordinates refuses, an absent proof
  refuses. `mint` stamps the coordinate into the token;
  `verify_minted` requires a `presentation`-preimage proof by the
  bound key, so a stolen token presented under another key answers
  `Invalid`.
- **D4 — `deliver_wrapped` registers the compensating revocation
  durable-before-visible.** The `security.credential.wrapped` row —
  `{wrap_id, binding_id, channel_id, channel_revision, destination,
  effect_id, expires_at, sender_key, compensation_plan_id}` — and the
  delivery's `security.credential.used` row land in one ledger
  append (the `rotate` batch precedent): the registration is
  durable before `WrappedDelivery.value` reaches the caller, and
  both-or-neither. `compensation_plan_id` is the deterministic
  idp/1 coordinate of the plan "POST every declared
  `DestinationBinding.revocation_path` + land the kernel `revoked`
  row" — a pure function of `binding_id`, destination and the
  channel's sorted revocation paths; the executed half is the
  `RevokeIntent` machinery `revoke` already produces (S2.4), so the
  named plan is verifiable against what the compensator will
  actually do. All members are value-free — the wrapped value is
  caller-held, never durable (SV-2).
- **D5 — `probe_wrapped` is a closed verdict, a pure fold.**
  `WrapProbe::{Applied, NotApplied, Undeterminable}`: a wrap
  registered on a live binding probes `applied`; a wrap registered
  on a dead binding — the compensating revocation ran — probes
  `not_applied` (LT-05's revoked-wrap leg); a binding with no wrap
  probes `undeterminable`. The verdicts reuse the
  `action.effect.probed` vocabulary so the credential-plane probe
  spells its state in the ledger's existing words.
- **D6 — `deliver_wrapped` keeps `mediate`'s refusal order.** revoked
  → `mode_not_allowed` → `out_of_scope` (env handle, destination) →
  `canary` → `sender_constraint_unmet` → `decision_missing` →
  `broker_unavailable` → ledger failure. The
  `isolation ≥ process_sandbox` gate stays at `bind` — a wrap-mode
  binding cannot exist below it (`EnvironmentNotIsolated` fires
  there; re-asserted in `r3_7.rs`). Refusal rows land durable before
  the refusal returns (CC3 — `security.credential.denied` for the
  mediation path).

## Consequences

- `SenderConstraint::Dpop` verifies end-to-end at the broker on every
  delivery mode — fixture-signed proofs (real `ring` signatures
  generated at test time via `dpop::fixture`) verify green; every
  absent/malformed/mismatched/wrong-context/unverifying proof keeps
  the ADR-0342 D2 `SenderConstraintUnmet` refusal. DF-S1.13-1's last
  residual discharges.
- The wire-side egress mediator passes `dpop_proof: None`
  (`hh-env/src/egress.rs`): a `dpop`-constrained channel still
  refuses `sender_constraint_unmet` through the mediated-wire path —
  the fail-closed posture is preserved there; presenting proofs up
  the wire is a caller-side concern the descriptor now has a field
  for. Honest and deliberate: this ticket's leg is the verifier.
- `wrapped_long_lived` delivers: compensation registered before the
  value is visible, a revoked wrap probes `not_applied`, and the
  `RevokeIntent` destination machinery is unchanged — DF-S1.13-4's
  last residual discharges.
- A second proof algorithm, a JWT/D PoP-token codec, or any
  `ring` surface beyond ADR-0359 D2 requires a sibling ADR.
- `security.credential.wrapped` joins the ledger class table
  (audit-grade, provenance-mandatory) with its lowering — a schema
  addition, recorded here.

## Revisit trigger

- A second proof algorithm or a real DPoP-token codec (JOSE/JWT) is
  needed — the byte-level `DpopProof` is the fixture-ceiling shape;
  a standards-track wire form re-opens D1/D2 by sibling ADR.
- The egress mediator gains a wire-side proof-presentation leg
  (`RequestDescriptor.dpop_proof` stops being `None` at the
  `hh-env` call site) — revisit whether the per-verb preimage set
  covers the wire's needs or a `wire` verb joins it.
- Any `ring` surface beyond ADR-0359 D2, a second crate, or key
  custody — each is its own ADR, never a silent add.
- A wrap that must probe *post-revocation liveness* richer than
  `not_applied` (e.g. a destination-side attestation of
  non-application) — `probe_wrapped`'s fold reads binding liveness;
  a richer verdict re-opens D5.
