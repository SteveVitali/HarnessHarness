# ADR-0363: R4.5a `live-executed` evidence class — `hh-live-evidence/1` records, the $100 spend ledger, `live-verify.sh` gating

- **Status:** Accepted
- **Date:** 2026-10-21
- **Ticket:** R4.5a
- **Requirement ids:** BL-31 · the 2026-10-20 round-4 rulings (providers =
  Anthropic + OpenAI + local Ollama; live spend cap USD 100; live CI
  posture = local `live-verify.sh` + protected `workflow_dispatch`) ·
  HUMAN-H6 · CC1 · CC3 · AGENTS.md gotcha 5 + the `ignore`-rule
  (amended here) · BM-STATUS-01 (evidence layers)
- **Spec:** §5g.3 (credential mediation — the `launch_env` source kind and
  the non-inheritable env rules this runner honors)
- **Rung (ADR-0024 obligation):** non-contract record — build-evidence /
  governance surface; no ladder rung.

## Context

Round 4's re-charter admits *live* legs for the first time (providers
ruling, $100 pre-authorized cap, local + protected-workflow CI posture).
Nothing may claim `live-executed` before the machinery exists to prove it
honestly: a record format, a redaction rule, a spend ledger against the
cap, a names-only secrets surface (HUMAN-H6 provisioned
`~/.config/harnessharness/live.env` — a symlink to a gitignored `.env` in
the operator's main checkout, chmod 600 target), and a scan gate so the
first evidence commit can't leak a credential into the public repo.
R4.5a lands the framework itself and proves it on the one USD-0 leg the
stage authorizes: local Ollama reachability.

## Decision

- **D1 — the `live-executed` class.** A claim is `live-executed` only when
  a committed `hh-live-evidence/1` record (D2) proves an executed call
  against a real external or local service, run through
  `scripts/live-verify.sh`. It *never* upgrades a leg that was not
  executed; a record whose `result` is `skipped(<reason>)` is evidence of
  non-execution, not a pass. `fixture-verified` and
  `foreign-run-verified` remain distinct classes and are never conflated
  with it. `staging-verified`/`public` remain unearned (L4.6/R4.18).
- **D2 — `hh-live-evidence/1`.** Records land at
  `docs/build/reports/live/<date -u +%F>-<leg>.json` (the allowed
  `reports/` root — BM-LAYOUT-01; `docs/build/evidence/` does not exist
  as a root). Fields: `schema` (`hh-live-evidence/1`), `recorded_at`,
  `ticket`, `leg`, `provider`, `endpoint_host` (host[:port] only — never
  a path, userinfo or query), `model_reported` (id as the service reports
  it, or null), `transcript_sha256` + `transcript_path` (the *redacted*
  request/response transcript committed beside the record when ≤ 64 KiB,
  else the sha alone), `token_usage` (object or null), `cost_usd` +
  `cost_pricing` (`table`, `source`, `retrieved` — copied from the pinned
  pricing table at write time), `run_ledger_head` (`{path, sha256}` of the
  ticket's run ledger when a run is involved, else null), `result` +
  `assertions`, `git_head`, `harness`, `provided` (`{NAME: "yes"|"no"}`
  per NAME the leg used — names only, values never), `request_ids`
  (provider request id(s), may be empty), `response_headers` (D3
  allowlist only), `spend_cumulative_usd` (cumulative after this leg).
- **D3 — audit + redaction rule.** `response_headers` carries only this
  closed allowlist (names compared case-insensitively): `request-id`,
  `x-request-id`, `cf-ray`, `openai-model`, `openai-processing-ms`,
  `openai-version`, `x-served-model`, `x-processing-time`,
  `x-processing-time-ms`, `retry-after`, and the rate-limit family
  `x-ratelimit-*`/`ratelimit-*`. Never auth headers, cookies, `set-cookie`
  or any `*-key`/`*-token`/`*-secret` name — the request ids + these
  headers exist so the operator can spot-audit a record against the
  provider console (console billing is the spend authority, D4).
  Transcripts are redacted through `hh-secrets`' `redact` (the
  `hh-secret-scan` bin, D6) before write; every artifact is swept by
  `leak_scan` against a mask set built from **all** provisioned values
  plus the registered patterns; any hit refuses the write.
- **D4 — the spend ledger.** `docs/build/reports/live/SPEND.jsonl` is
  append-only `{ts, ticket, leg, cost_usd, cumulative_usd, record}` rows;
  `docs/build/reports/live/pricing.json` is the pinned table (per-model
  rates + `source` + `retrieved`; local = 0) plus `cap_usd: 100` and the
  per-ticket `allocations_usd`: **R4.5d 5 · R4.5e 5 · R4.6 15 · R4.7b 5 ·
  R4.7e 15 · L4.6 30 · reserve 25** — every other ticket's allocation is
  0. `live-verify.sh` refuses (exit 3, `SPEND CAP — ask the operator`)
  any leg whose declared `--budget` exceeds its ticket's allocation or
  pushes `cumulative + budget` past the cap. The reserve spends only on
  the operator's recorded words. `SPEND.jsonl` is an *estimate* from
  `pricing.json`; the provider consoles' billing is the authority and the
  operator reconciles the ledger total against them at GATE-G6 (recorded
  in the readout).
- **D5 — `scripts/live-verify.sh`.** Usage: `live-verify.sh <leg>
  [--budget USD]` · `live-verify.sh --check-names [<leg>|--all]`. It
  sources `live.env` (`HH_LIVE_ENV` overrides the path — tests only)
  **names-only**: plain `.` sourcing under `set +x`, never exported into
  children wholesale; a future leg's kernel broker receives exactly its
  declared names as launch env (`SecretSource::LaunchEnv`), and
  `hh-secrets`' `is_inheritable`/`KERNEL_NONINHERITABLE` keep values out
  of the broker's own children. A required NAME that is unset/empty is
  `provided: no` → exit 4 (`provision via HUMAN-H6`). Exit codes: 0 pass
  · 2 leg skipped/failed (record still written, honestly) · 3 spend-cap
  refusal · 4 missing NAME · 5 leak-scan hit (nothing written) · 6
  gitleaks staged-diff finding (STOP-and-ask) · 7 required tool absent ·
  1 usage. The leg registry lives in the script; legs are `kind: script`
  (this ticket's) or `kind: cargo-test` (D7) for later tickets.
- **D6 — leak detectors (CC1).** `hh-secret-scan`
  (`crates/hh-secrets/src/bin/`) is the thin CLI over the one canonical
  detector set — `leak_scan`/`redact` with `DetectorSet::standard` over a
  `MaskSet` built from the env file's values (`--mask-env`) and/or named
  process-env vars (`--mask-var`). No second spelling of patterns or
  masks is introduced anywhere.
- **D7 — live-test gating convention.** A network-touching Rust test is
  `#[ignore = "live — ADR-0363: scripts/live-verify.sh <leg>"]` — `cargo
  test` reports it `ignored`, never `passed`; it runs only via
  `live-verify.sh` (`cargo test -- --ignored` on the leg's declared
  filter) and reports `skipped(<reason>)` honestly in CI. AGENTS.md's
  "`ignore`d tests cite a `DF-*` row" rule is amended to "…cite a `DF-*`
  row or the live-evidence ADR". R4.5a's own leg is script-native (curl);
  later legs (R4.5b+) use the ignored-test form.
- **D8 — the secret-scan gate.** `live-verify.sh` ends every evidence run
  by staging the artifacts it wrote and running `gitleaks git --staged
  --redact -c .gitleaks.toml` (the staged-diff form for gitleaks ≥ 8.18;
  `protect`/`detect` spellings on older versions); any finding refuses
  (exit 6), unstages, commits nothing, and STOPS-and-asks. The committed
  root `.gitleaks.toml` (`[extend] useDefault` + `[[allowlists]]`) carries
  the one-off full-history baseline's known **7 fake test-fixture hits**
  (`generic-api-key` literals in `crates/hh-secrets/tests/acceptance.rs`,
  `…/sv.rs`, `crates/hh-telemetry/tests/acceptance.rs`) allowlisted by
  path + rule, each with its reason. Any baseline hit outside those 7 is
  NOT allowlisted — STOP, rotate, ask. L4.3 reuses this same
  `.gitleaks.toml` in CI (CC1 — one config).
- **D9 — validator home.** The evidence validator is
  `scripts/check-live-evidence.sh` on a `ci-mode: both` step, **not** a
  `crates/` test: the ci-gating readers scan forbids `docs/` reads under
  `crates/**`, and a fast-path docs-only head would skip a gated `cargo
  test` step entirely — a script on a both-mode step validates records on
  every head. It asserts invariants only (BM-TEST-01): every
  `hh-live-evidence/1` record parses and carries D2's fields in the right
  shape, `endpoint_host` holds no path, `transcript_sha256` is 64-hex and
  matches a committed transcript when named, `provided` values ∈
  {yes,no}, every record has its SPEND.jsonl row, cumulative spend is
  non-decreasing and ≤ `cap_usd`, and the allocation table sums ≤ cap.

## Consequences

- `live-executed` is claimable from this ticket on — only with a cited
  record; the first one is `local-reachability` (USD 0).
- Every later live ticket (R4.5b-e, R4.6, R4.7b/e, L4.6) inherits the
  record format, spend mechanics and gating convention unchanged — a new
  leg is a registry entry + its ticket's allocation, never a re-design.
- CI never sees a secret: pull_request runs keep the live tests
  `ignored`; the workflow_dispatch leg (L4.3) is bound to a protected
  Environment.
- `.gitleaks.toml` is the single scan config for local gate and CI.

## Alternatives considered

- **A crates/Rust validator** (the contract's `e.g.`): rejected per D9 —
  readers-scan forbidden and fast-path-skippable. Recorded as the ADR's
  MET-DIFFERENTLY on the "home per ADR" latitude.
- **A bash re-implementation of the detector patterns**: rejected — CC1;
  `hh-secret-scan` wraps `hh-secrets` itself.
- **`.gitleaksignore` fingerprints instead of a config**: rejected — the
  contract wants path+rule reasons in a committed config L4.3 can reuse.
- **Committing evidence inside `live-verify.sh`**: rejected — the script
  stages + gates only; the worker/orchestrator commits, keeping the
  staged-diff gate a pre-commit control, not a committer.

## Revisit trigger

Reopen when: a provider or record field the format can't express appears
(bump to `hh-live-evidence/2`); the spend cap or allocation model changes
(operator's recorded words); L4.3 needs CI-side semantics this gating
convention can't express; or a leak class escapes both the
`hh-secrets` sweep and the gitleaks gate (then the detector set and the
config are extended, never duplicated).
