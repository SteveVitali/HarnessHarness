# ADR-0339: R2.8 tool-exposure residual — the C1/C2 producer halves, the exposure-aware turn loop's emitter order, and the corpus battery

- **Status:** Accepted
- **Date:** 2026-10-07
- **Ticket:** R2.8
- **Requirement ids:** DF-S1.17-1 · DF-S1.17-2 · DF-S1.17-3 · BL-16 ·
  R-2.5.1 · R-2.5.2 · R-2.5.3 · R-2.5.4
- **Spec:** §5d.2 (bindings, families, index granularities, render specs),
  §5d.3 (catalogue lifecycle, `select_surfaces`, `check_callable`,
  discovery, drift, emitters) · ADR-0090 · ADR-0093 · ADR-0094 · ADR-0095
  · ADR-0286 (D6/D7 carry-over rulings this ticket discharges)
- **Rung (ADR-0024 obligation):** C0–C2 — the landed members are
  deterministic machinery over declared records; executor-gated index
  variants and the `from_code` call path refuse typed without their
  declared legs.

## Context

S1.17 landed the §5d declarations (closed sums, schemas, event classes);
S2.10/S3.9/S5.2 landed the static halves (index forms, `check_callable`,
`sync_source`/`adopt`, family/selector checkers, codec legs). DF-S1.17-2
parked the C1 *producers* (nothing minted a `PlanMap`/`freeform`/`shim`
binding, `family_id`/`variant_id` provenance, non-surface granularities,
`concise`/`offload` render modes); DF-S1.17-3 parked the C2 gates
(`hide_uncovered`, attestation-gated indexing, `code_mode` plans,
filesystem catalogues) plus every run-time emitter; DF-S1.17-1 parked
the executable corpus battery (≥200-surface fixture, the regex-vs-NL
*form* fixture needing a non-`native_fc` family, the S-386 provider
round-trip, the benchset-metric computations).

The owned questions: the emitter ordering inside the turn loop (the
ticket names it; the R2.5/R2.6 driver sequence sets the pattern), how
exposure state survives resume (the durable-prefix fold is the contract —
in-memory state is exactly what takeover discards), and how the
executor-gated index legs bind without the kernel fabricating rankings.

## Decision

**D1 — the armed lane's emitter order is `catalog.built` → `planned` →
`delivered`; `call.refused` precedes the effect path; `discover_surfaces`
runs in-kernel at dispatch.** `DriverConfig.exposure: Option<ExposureRuntime>`
arms the lane (`None` ⇒ byte-identical C0 lane — a disarmed run lands zero
exposure rows). Per `propose`: lazy `fold_exposure_state` (D2), once-per-run
`action.tool.catalog.built`, `select_surfaces_with` →
`action.tool.exposure.planned` *before* `assemble` (durable-before-visible —
the plan row lands ahead of the context it shaped, `DecisionPoint =
retrieve`), then `context.artefact.delivered{kind: tool_surface}` for the
plan's `direct` members, once per run per surface. Every parsed call runs
`check_callable` before output validation — a refusal mints
`action.tool.call.refused` and never reaches the effect gate. A call on the
`discover_surfaces` capability executes in-kernel at dispatch
(`action.tool.discovery.searched` with the query *hash*, never the raw text;
`action.tool.surface.revealed` per admitted hit; the hit list is the
`action.effect.observed` outcome). Retention boundaries mint
`action.tool.surface.evicted`; a called delivered surface mints
`context.artefact.activated{artefact_id = surface_id, tool_call_id}` per
call (AC-E3-7 — the delivered↔invoked join T-LCD-13 needs). A host
`sync_exposure_source` lands `catalog.delta` always; `adopt` mints
`catalog.epoch` + rebuilt `catalog.built`; `ask` mints
`security.permission.requested` and holds the catalog at its pre-sync epoch.

**D2 — exposure run state folds from the durable prefix; the in-memory
`ExposureRunState` is a cache, never authority.** On the first armed
proposal the driver folds `catalog.built`/`planned`/`revealed`/`evicted`/
`delivered` rows out of `sink.prefix()` — a resumed run reconstructs
identical state (revealed set, prior order, delivered artefacts) without a
side channel. Append paths take `self.exposure_state` owned (the borrow
never spans an append — CC3's single fenced writer).

**D3 — the executor-gated index legs bind host function pointers; an absent
leg is `ExecutorUnavailable`, never a fake ranking.**
`IndexExecutor{embedding?, model_ranked?, filesystem?}` carries `ExecutorFn`
callbacks the host (driver config, fixture, MCP-side search) supplies; the
kernel ships no engine of its own. Executor answers record
`executed_by = provider`/`kernel` per the variant; a `None`-scored hit is
rank-only, never fabricated. The same seam serves the S-386 regression: a
provider-executed search over plan members reveals the deferred surface,
which the next plan admits `direct` — the round-trip replays at fixture
layer (`r2_8_executor_legs_and_s386_provider_round_trip`).

**D4 — `surface_id`'s basis is unchanged; `family_id`/`variant_id` are
provenance members.** `bind_variant` stamps the identity-bearing
family/variant coordinates on the binding record (the codec carries them;
`check_family` requires the back-pointer) without widening the identity
basis — the basis is fixed, append-only; a variant change that alters
rendering still mints a new `surface_id` through the fields already in the
basis (mode, arg_map, mapping ref), never through the provenance members.

**D5 — `code_mode` is a producer + an admission arm, not a program
executor.** `bind_code_mode` mints `CompileExposureMode::CodeMode`
bindings; `check_callable` admits `from_code` calls on `code_mode` plan
members only (both arms tested). No run-time program originates
`from_code` calls — the code-mode *executor* is R-2.5.5's row, carried
unchanged; nothing here fabricates a program.

**D5a — the postcondition-binding seam stays with R2.15.**
The ticket permits landing the `ToolCapability.postconditions`
consumption surface here only if the two tickets would otherwise
double-own it; no R2.8 member consumes postconditions (the binding
record carries capability refs, never postcondition assertions), so
the seam is untouched and R2.15 owns it whole.

**D6 — size deviation, same class as ADR-0336 D6 / ADR-0338 D8.** The
landed diff is ~4.5k changed lines vs the ticket's 1,400-line budget; the
R2.8a/R2.8b split seam was not taken because the emitters, the corpus
battery and the C2 gates exercise one coupled `Catalog`/`ExposurePlan`
machinery — splitting mid-run would have re-verified the same surface
twice. ~1.6k of the delta is the exposure.rs semantic layer, ~0.9k the
driver's armed lane, ~1.2k acceptance batteries.

## Consequences

- DF-S1.17-2's named members are all landed and tested → DONE.
- DF-S1.17-3's named members are all landed and tested → DONE (the
  code-mode executor stays with R-2.5.5 by the row's own scope).
- DF-S1.17-1's R2.8-assigned residual is discharged (the ≥200-surface
  battery, both form fixtures, S-386, the trigger matrix, the benchset
  metrics); the row stays OPEN for the members it did not assign here
  (`provider_tool_api` deferral flags on the minimal profiles;
  `surface_rejection_rate`'s computation is AC-R-2.5.2-12's own row).
- Every new event class the driver mints was already registered in
  `hh-ledger`'s class table at S1.17/S3.9 — no new registration was
  needed (verified, not assumed).
- Unverified lifts: `lifted` entries index only under
  `SelectionGates.index_unverified`; `pinned ∧ lifted` is
  `PinBindsLifted` at both build and adopt — a pin binds an admission,
  never an unverified lift.

## Revisit trigger

Reopen if: (a) R-2.5.5 lands the code-mode *executor* — a program that
originates `from_code` calls must route them through the same
`check_callable` arm and mint the same `context.artefact.activated`
join (D5 pins the admission rule; the executor must not mint a second
spelling); (b) a live `IndexExecutor` leg binds (BL-16's provider legs,
a real embedding/model-ranked/filesystem engine) — the
`ExecutorUnavailable` refusal cut and the `executed_by` spelling must
agree with the live leg, and the S-386 fixture round-trip should be
re-verified against the real provider path; (c) the exposure lane gains
multi-turn runs — `Retention::TurnEnd`/`RunEnd` currently coincide with
the projections' run fold (D1's evict leg mints at `call` boundaries
only); (d) `surface_rejection_rate` computation lands
(AC-R-2.5.2-12's row) — it folds `surface_rejected` rows the armed lane
already mints; confirm the join keys match.
