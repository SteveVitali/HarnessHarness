# ADR-0231: S1.4 HIR crate shape — hh-hir above ontology/provenance, the classify_home table with interim leaf homes, seal computes version ids before ref pinning, and quoted diff paths

- **Status:** Accepted
- **Date:** 2026-09-15
- **Ticket:** S1.4
- **Requirement ids:** R-2.1.2 (anchors CC8, CC10); discharges DF-S1.1-1 and DF-S1.3-1
- **Spec:** §3.1 (R-2.1.2 — the HIR/1 catalogue, records, identity, validate battery,
  operations); §3.1.3 (the per-kind `classify_home` table, interim under ADR-0216 / OQ-467);
  §3.1.7 (the operation surface) · ADR-0015, ADR-0016, ADR-0017, ADR-0018 (as amended);
  ADR-0216, ADR-0228

## Context
S1.4 lands the §3.1 Harness IR — the executable HIR/1 dialect. Four decisions were owned by
this ticket:

1. **Crate placement.** The IR reads ontology home-planes (CC10), identity digests (idp/1),
   and the provenance record/endorsement machinery (§8.1), and contributes nothing those
   crates read. It must not depend on any hosting surface (AC-IR-04 / T-06).
2. **Leaf homes.** DF-S1.1-1 requires the per-kind `classify_home` table published for the
   thirteen entity kinds **and** the two opaque leaves — but §3.1.3 (interim MUST-data under
   ADR-0216, OQ-467) fixes values for the thirteen entities only; it is silent on `Text` and
   `CompiledPayload`. The deferral's close condition wants them homed anyway.
3. **Seal ordering.** §3.1 pins every `Ref` in a sealed definition to a member
   `version_id`, and `version_id = H(canonical(member))` includes the member's refs. A
   naive "compute ids, then pin, then recompute" topological pass is impossible: the
   record-ref graph is not a DAG — `Permission.holder ↔ AgentProcess.permissions` is cyclic
   by construction (CF-076). The order of id computation vs pinning had to be fixed so the
   sealed form is deterministic and self-consistent.
4. **Diff paths.** `diff`/`apply` address members by a canonical-JSON path
   (`a.b[2].c`), but legitimate map keys — budget dimension names like `tokens.total` —
   collide with the `.` separator. `apply` must resolve every path `diff` emits.

## Decision
- **`hh-hir` is a new persistent crate** (the C0/Stage-1 binding for R-2.1.2, CC4) sitting
  above `hh-ontology`, `hh-identity`, `hh-provenance`, and `hh-wire` — its only
  dependencies. No edge to the Hosting ABI exists or may be added (AC-IR-04); `hosted`
  agent processes are carried by `OpaqueProcess` records *inside* this crate. The crate is
  the dialect owner: `DIALECT = "HIR/1"`, `since = HIR/1` on every kind and edge, and
  dialect bumps + `migrate` are the CC8 enum-growth mechanism.
- **`classify_home` is published in `hh-ontology`** (`planes::IR_ENTITY_KINDS`, fifteen
  rows: 13 entities + 2 leaves) and is *total* — `classify_home`/`classify_home_identifier`
  resolve every registered kind to exactly one plane; `hh-hir` reads `home_plane()` through
  the ontology and `validate` fails `UnclassifiedKind` on any kind the table misses. The
  thirteen entity values are §3.1.3's; **the leaf homes are this ADR's interim ruling**
  under ADR-0216/OQ-467: `Text → P1 (Observation)` (opaque content observed, never
  executed) and `CompiledPayload → P2 (Action)` (an executable artifact with a declared
  interface). When WS-A2/WS-A3 ratify OQ-467 by an ADR-0048-class ruling, these two rows
  are lifted from interim together with the thirteen.
- **Seal order: ids of the authored content first, then pins.** `seal` (1) refuses a
  document carrying an `assembly` section and re-validates; (2) computes each member's
  `semantic_id`; (3) endorses every member provenance (definition scope); (4) computes each
  node's `version_id` **over the authored (pre-pin) canonical form**; (5) rewrites every
  `Ref.version` to `Pinned(target_version_id)` — including the cyclic
  `Permission ↔ AgentProcess` pair, which is why pinning cannot be a topological pass; (6)
  computes edge ids and pins edge refs; (7) pins the root; (8) computes each hosted
  `OpaqueProcess.version_identity`; (9) re-validates the sealed output. A member's version
  identity is thereby the identity of *its own sealed content*; the pin is the definition's
  binding of a `Ref` to a member identity — a graph fact, not member content. Sealing is
  deterministic and idempotent in content: re-sealing an identical document yields
  identical bytes.
- **Diff paths quote unsafe keys.** A map key containing `.`, `[`, `]`, `"` or `\` is
  emitted as `["escaped key"]` (e.g. `semantic.dimensions["tokens.total"].hard`); `apply`'s
  parser handles `.key`, `[i]`, and `["key"]` segments symmetrically. Paths are
  canonical-JSON addresses; the quoting is part of the §3.1.7 diff format from HIR/1, so no
  dialect bump is needed.

## Consequences
- Good: `classify_home` is total over all fifteen IR kinds and the totality is
  machine-checked on both sides (ontology `planes::tests` + HIR `unclassified_kind_wiring`),
  closing DF-S1.1-1; sealing is correct under the cyclic reference structures the spec
  mandates; `apply(diff)` round-trips on dimension names like `tokens.total`, proven over
  the 120-definition corpus.
- Cost: a sealed `version_id` binds the pre-pin content, so two sealed documents differing
  only in pin targets share member `version_id`s — the pin difference shows up in the
  members' canonical bytes and the definition's members table, not in the member id. This
  is the required reading of §3.1 under cyclic refs; a topological alternative cannot
  represent `Permission ↔ AgentProcess` at all.

## Alternatives considered
- **Topological pin-then-hash ordering** — fails outright: the ref graph has lawful cycles,
  so no topological order exists. Rejected as unimplementable, not merely worse.
- **Iterative fixpoint hashing** (re-hash until `version_id`s stabilise under their own
  pins) — not guaranteed to converge in one pass over cyclic structures, adds an implicit
  fixpoint semantics the spec does not define, and makes `version_id` depend on pin
  *encoding* rather than content. Rejected.
- **Leaf homes deferred to OQ-467 ratification entirely** — leaves DF-S1.1-1's close
  condition unmet (the deferral wants all fifteen rows homed and the totality check
  extended). Rejected; the interim two-row ruling is recorded here for the WS-A2/WS-A3
  ratification to confirm or amend.
- **Forbidding `.` in map keys** — changes the schema to serve the diff format; dimension
  names like `tokens.total` are the natural §3.1 spelling. Rejected.

## Revisit trigger
Reopen if WS-A2/WS-A3 ratify OQ-467 with different leaf homes (the two interim rows change
together with any entity rows that move — a `classify_home` value change is a semantic
change requiring a dialect assessment under CC8); or if a later stage needs `version_id` to
bind pin targets (would require a new ADR defining the fixpoint semantics and a dialect
bump).
