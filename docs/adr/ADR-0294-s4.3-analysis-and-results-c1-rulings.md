# ADR-0294: S4.3 analysis-engine & results-store C1 rulings — `leaderboard_definition` as an opaque registry arm, the derived results journal, `export_rows` loss reports, per-row snapshot diff keys, producer-contract refusals at `record_analysis`

  R-2.10.5 (§6.5 results-store/publication C1)
- **Spec:** §6.4 (the C1 analysis ops A4/A5/A6/A7/A9/A10/A11/A13/A15) ·

## Context

Stage 4's third ticket lands the C1 halves the run ledger claimed:
the remaining analysis ops over the durable row set, and the
results/publication surfaces — `AnalysisRecord` producer contract,
`DisclosureSummary`, the annotation index, `subscribe`, `export_rows`
with `LoweringLossReport`, and the leaderboard lifecycle
(define/snapshot/diff/verify/publish/retract/pin). Each ruling below is
the owned call where the spec's machine text left the shape open; none
is a spec deviation.

## Decision

1. **`LeaderboardDefinition` registers as a new opaque
   `RegistryRecord` arm.** The definition's canonical JSON is stored
   verbatim under `RecordKind::LeaderboardDefinition` — the same
   layering as `Participant`/`Adapter`/`EnvironmentRecord` (schema
   owned by `hh-results`, registry stores bytes, CC7). The name binds
   through `registry.publish` under ADR-0153 `NamespaceRecord`
   authority, so a rename is a name-history entry, never a new
   definition id. `RecordKind::ALL` grows 25 → 26 — a `registry/1`
   dialect addition, additive only.

2. **`subscribe` is a derived journal, never a live tap.** The
   results store emits `RowHeadChanged | AnnotationChanged |
   SnapshotPublished` only after the durable write commits (the same
   durable-before-visible rule the ledger's notify path follows). A
   subscriber can never observe a speculative head; the journal
   replays in order from a watermark because every event is minted
   from committed state.

3. **`export_rows` artifacts are LabDocs documents with an explicit
   `LoweringLossReport`.** `ledger_native_rows` carries the row set
   verbatim and round-trips to equal `version_id`s — the only
   lossless target. `interchange_table`, `csv_like_table` and
   `foreign_leaderboard_submission` enumerate every lowered field:
   `n/a{reason}` values, provenance members and interval fields that
   have no slot are reported as `no_slot`, never coerced to 0 or
   dropped silently (AC-R-2.10.5-11).

4. **`diff_snapshots` keys entries on the row `key`, reports
   `configuration_id`.** A leaderboard can list two rows under one
   configuration (distinct attempts of one configuration); keying the
   diff maps on `configuration_id` collapsed them and shadowed one
   entry's flag changes — an annotate-never-hide violation the
   AC-R-2.10.5-4 test caught. Matching is per row; the reported
   tuples still name the configuration so consumers read the same
   vocabulary as before.

5. **Annotate-never-hide admits revoked/retracted covering bundles at
   L1.** The L1 evidence gate previously dropped a row whose only
   covering bundle was retracted or member-revoked. That is hiding —
   the AC's four-flag scenario requires the entry to remain with
   `member_revoked`/`bundle_retracted`/`suite_retired`/
   `evidence_missing` marks. The gate now admits such rows and the
   annotation overlay flags them; `verify_row` still passes because
   the row bytes never changed.

6. **`record_analysis` enforces the producer contract at the engine,
   typed refusals never skipped checks.** `declare` after `bind` is
   `DeclarationLate`; a second `declared` event is refused; a
   `PreRegistration.registered_at` postdating a bound run is
   `PreRegistrationLate`; a `comparison_report` analysis without
   `budget_match` is refused; `benefit_kind` mismatches are refused;
   a record claiming `pre_registered` without an identity-matching
   registration is `NotPreRegistered`. `amend` marks subsequent
   records `post_amendment` (AC-R-2.10.5-10).

7. **Disclosure reads the status book, not the manifest.** A
   restricted arm's reader set is declared by the `restricted`
   `bundle_status_changed` record — append-only, rebuildable — never
   by manifest bytes (the manifest is immutable at deposit).
   `DisclosureSummary` classifies `restricted` by
   `BundleStatus::Restricted` or a bounded reader set without
   `public`/`*`; a row bound to no experiment is `undisclosed` under
   `require_experiment` (AC-R-2.10.5-8).

8. **Analysis records carry a compute-effort `cost` account.** The
   §6.5 record's `cost` member is the compute proxy at this tier:
   `{resampling_draws, seed, n_rows, n_tasks}` — what the analysis
   actually spent, recorded on the record rather than inferred.

## Consequences

- The registry dialect is now 26 kinds; any consumer keyed on the
  closed list must re-derive (the kind-list tests pin the count).
- The snapshot diff is row-exact: two entries under one
  `configuration_id` each report their own flag changes.
- `verify_row` requires a recorded version — projections are pure
  and never implied-recorded; publication paths that need
  `verify_row` record first (the test records explicitly).
- Restricted-disclosure classification depends on the status book's
  reader records — a bundle that never transitions to `restricted`
  reads as published/assembled regardless of manifest intent.

## Alternatives considered

- **Leaderboard definitions under a dedicated registry subsystem**
  (typed schema, registry-owned validation): rejected — the
  definition schema is `hh-results`-owned and still moving; the
  opaque arm preserves CC7 layering and needs no registry dialect
  beyond the kind.
- **Diff keyed on `configuration_id` with a secondary sort:**
  still collapses same-configuration rows; rejected for the
  annotate-never-hide violation.
- **Journal over a pre-commit hook:** would expose speculative heads
  to subscribers; rejected by the durable-before-visible rule.

## Revisit trigger

- When a ticket lands a foreign leaderboard target whose slots are a
  superset of `LoweringLossReport`'s named losses, the report
  vocabulary should be re-ratified.
- If `LeaderboardDefinition` gains registry-enforced invariants
  (cross-definition admission conflicts), lift it to a typed arm in a
  new ADR.
- If a second producer path (imported experiments, OQ-377) starts
  emitting `analysis_recorded`, the producer-contract checks should
  be re-homed to a shared gate rather than extended per path.
