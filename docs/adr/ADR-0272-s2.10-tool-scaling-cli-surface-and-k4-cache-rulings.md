# ADR-0272: S2.10 tool-scaling, CLI-surface and K4 rulings — the C1 `catalog_index` variants as pure scorers, bounded `discover` + `catalog_delta`/`adopt`, `Origin::Cache` at the `environment` ceiling, K4 keyed on the mutation epoch, `SurfacePreset` as a MUST-data lowering, `workspace_trust` as a recorded claim, env writer ops that never drain the session, and `compact` as a declared-lossy projection

- **Date:** 2026-09-19
- **Ticket:** S2.10
- **Requirement ids:** R-2.5.3, R-2.3.4¹
  (AC-R-2.5.3-{8 freeze half, 11} · AC-R-2.3.4-{8, 9 K4 half} ·
  AC-R-2.11.1-7 substance)
- **Spec:** §5d.3 (R-2.5.3 — the C1 `catalog_index` variants,
  `discover`, `catalog_delta`/`adopt`, `retrieval_eval`) · §5b.4
  (`R-2.3.4¹` — the K4 `tool_result` cache, the mutation epoch,

## Context

S2.10 lands the tool-scaling C1 halves and the Stage-2 CLI surface
slice in one ticket. The spec fixes the contracts (the index-variant
sum, the `DiscoveryQuery`/`DiscoveryResult` records, the K4 entry
shape, the `SurfacePreset` fields, the `env` verb table); the
mechanism choices below were left to the ticket:

1. **How the C1 index variants relate to the C0 catalog.** `exact_name`
   and `static_allowlist` landed at S1.17 as plan filters; the C1
   variants (`lexical_regex`, `bm25`, `hierarchical`) are *ranking*
   functions over the same entries — a wrong answer must be a bad
   ranking, never a different contract.
2. **Where the served cache record's authority comes from.** A K4 hit
   produces an observation the run consumes as if the tool had run.
   The served provenance must carry enough to satisfy I-NOAUTH
   (authority is conferred, never read from content) without widening
   the entry's label — and a forged or malformed entry must fail
   closed.
3. **How the mutation epoch invalidates.** IR-3 requires every entry
   pinned to a pre-mutation epoch to be *withheld observably*
   (`stale_withheld`), never silently missed — a plain `miss` would
   hide the invalidation from the audit projection.
4. **What a `SurfacePreset` *is*.** ADR-0168 D3 rules presets are
   lowerings (`{name, approval_mode, narrowing_leaves[],
   requires_containment}` — MUST-data), so the CLI cannot invent a
   kernel semantic; but the leaf set has to reach the lease key's
   `policy_fingerprint` or a preset change would leave stale leases
   live.
5. **Where `workspace_trust` comes from.** §7.1 §2.4 rules it a
   *recorded claim* from the H5 trust store (`trusted`/`untrusted`/
   `unknown`), never CLI logic — scanning repository contents for a
   trust verdict would be exactly the content-derived authority CC2
   forbids.
6. **How `env` mutating verbs coexist with the writer-lease model.**
   `env snapshot`/`derive`/`set-phase` run over a takeover writer
   session; closing that session after the op drains the run
   (`Draining`), so the natural "open, call, close" shape is wrong.
7. **What `compact` is.** §7.1 O-1 makes `compact` an *optional
   declared-lossy* projection shipped with a `LoweringLossReport` —
   never the machine default; it must still be a stamped `View` with
   the same watermark/view-hash discipline as every other projection.
8. **What the deferred `env` verbs answer.** `open`/`attach`/`close`/
   `diff`/`restore`/`upload`/`download` have no boundary-backed path at
   this stage; a faked success would be an unaccounted side effect.

## Decisions

**D1 — the C1 variants are pure scorers over the same filtered
candidate set.** `variant_hits` first applies the shared filters
(non-`hidden`, `matches_structured`, the caller's plan restriction)
and only then scores: `lexical_regex` compiles the query's regex arm
through the closed subset in `hh-compiler::regex` (ε-closure NFA,
search semantics, `^`/`$` at `0`/`len`); `bm25` ranks on token overlap
with the standard IDF curve over catalog statistics; `hierarchical`
scores `2 × matched_prefix_depth` (+1 on a final prefix match)
descending the `namespace ∥ name` path. `DiscoveryQueryInvalid`
(`too_long`/`empty`/`unsupported_form`) is the only refusal — a bad
query fails typed, never partially. `|hits| ≤ min(limit,
max_reveal_per_search)` (default 8, ceiling 32) bounds every variant
uniformly.

**D2 — `Origin::Cache{entry_ref}` mints at the `environment`
ceiling.** The K4 hit's served provenance is `origin = cache(entry_ref)`
with `derived_from = [entry_ref]` and authority/taint/readers **copied
verbatim** from the entry's label — the cache never raises. The mint
table supplies `environment` as the *maximum* a `tool_result` record
can hold: a cache-produced record claiming `principal`/`kernel`/
`definition` fails `AuthorityExceedsOrigin` at validate (I-NOAUTH's
cache face). `default_text_authority` still caps cached free text at
`external` (R-TEXT). The variant round-trips the canonical codec
(`"cache"` tag, `entry_ref` member).

**D3 — K4 is a thin layer over `MemoryStore`; the epoch is a
dependency stamp, the bound name omits it.** Every entry is an
ordinary `MemoryVersion{kind: tool_result}` whose
`InvalidationContract` pins `{tool_capability, environment_epoch}`
stamps — lifecycle, supersession, scope-ended expiry, leases and the
`resolve(mode = execute)` filter apply unmodified (no second store).
The canonical `entry_key` includes `environment_stamp(env_ref, epoch)`
and `readers`; the *bound name* deliberately omits the epoch so a
post-mutation lookup finds the prior-epoch entry and reports
`stale_withheld` (IR-3's observable invalidation).
`K4Cache::note_committed` bumps `stamps[environment_epoch:{env_ref}]`
on every committed effect in `MUTATION_DOMAINS = {fs_write, exec,
net_egress, spawn_process}` — conservative over-invalidation is the
declared trade (the hit-rate metric measures the cost). Admissibility
is `{reversibility: read_only, repeat_safety: idempotent, cacheable}`;
non-qualifying calls are a recorded `bypass`, not an error. Every
lookup appends exactly one `model.cache.resolved` (`hit`/`miss`/
`bypass`/`stale_withheld`/`refused`), and a served hit emits
`DispatchOutcome::ObservedCached` — `prepared`/`observed`/`completed`
terminals land with **no** `action.tool.started`/`committed`, so a
cache serve is distinguishable from an execution in the ledger by
construction. A hit whose stored value cannot rebuild an ordinary
`Observation` is a `refused{malformed_entry}`, never a partial serve.

**D4 — `SurfacePreset` is a MUST-data lowering; narrowing leaves enter
`policy_fingerprint`.** `crates/hh-cli/src/presets.rs` is the table:
`plan` ⇒ `pre_approved_only` + `fs_write`/`exec` `deny` leaves;
`auto-edit` ⇒ `tiered` + one `allow_lease{fs_write, workspace_local}`
leaf; `bypass` ⇒ `bypass` + `requires_containment` (no leaves — the
never-auto set is excluded inside the kernel chain, not declared at
the surface); `yolo` is not admitted. A `--preset`/`--approval-mode`
conflict is a pre-ledger `invocation_error`. The leaf ids are a
`policy_fingerprint` leg folded at `open_session`/`respond_permission`,
so a preset change revokes every minted lease by construction. Bypass
gates twice: the CLI's pre-ledger check refuses when the binding
cannot supply evidence (fail-closed on unknown/`ref` environments —
UX only), and `open_session` re-checks the kernel-minted
`containment.enforcement_evidence` the attach report produced,
recording `containment.bypass_admissible` on the manifest so
`amend(approval_mode → bypass)` re-reads the durable row instead of
re-probing.

**D5 — `workspace_trust` is a claim read from the user trust store,
never inferred.** `crates/hh-cli/src/trust.rs` resolves the canonical
workspace path against `$HH_TRUST_STORE` (default
`~/.hh/trust.json`): present ⇒ the mapped verdict; absent/malformed
⇒ `unknown` (fail-closed, never `trusted`). The claim travels
`OpenSpec::New` → `manifest.workspace_trust` verbatim; which Π rows it
narrows stays under OQ-387's deferral — the CLI records, the kernel
decides (ADR-0168 D7).

**D6 — env writer ops keep the takeover session open.** `env snapshot`,
`env derive` and `env set-phase` resume the run's writer session
(`takeover`) and issue the Group-M op — and then **do not** close the
session: `close` on a writer drains the run (`Draining`), which would
make a second env op on the same run impossible and misreport the run
as finished. `run amend` already keeps its session alive for the same
reason; the env verbs follow it. `env status`/`meters`/`list-detached`
are reads over `describe`/`read` and keep the ordinary attach/close
shape. `env derive` answers the derived record (kind/scope/
`on_parent_end`) and never exposes the child `EnvHandleId` (R-NOSIDE);
`env set-phase` without a sealed `per_phase_network_policy` refuses
`phase_schedule_undeclared`. The unbacked verbs
(`open`/`attach`/`close`/`diff`/`restore`/`upload`/`download`) answer a
typed `stage_pending` invocation error naming the deferral — never a
faked result (DF-S2.10-1).

**D7 — `compact` is a stamped declared-lossy `ViewKind`.**
`ViewKind::Compact` folds the durable prefix into
`{kind, folded[], item_count, loss_report}` — the loss report names
every dropped member class (`LoweringLossReport`-shaped; CC3) and the
view carries the same `derived_from` watermark + `view_hash` discipline
as `context_view`/`run_summary` (one view shape, one hashing domain —
CC7). The schema's `PROJECT_VIEW_KINDS` admits `"compact"`;
`run inspect --view compact` and the top-level `compact <run_id>` both
reach it. It is opt-in only — the `jsonl` stream stays the identity
projection (O-1).

**D8 — `amend` widens `attendance`/`approval_mode` under the same
human-gate as `budget`.** `amend{target}` now admits `attendance` and
`approval_mode` beside `budget`: each writes one durable
`control.<target>.amended{old, new}` row and revokes live approval
leases (the fingerprint leg changed). Widening — `attendance →
interactive`, or `approval_mode` toward more auto-resolution —
requires the *invoking* session's `attendance = interactive` or an
attestation (`AuthorityWideningRequiresHuman`); the invocation's own
attendance is consulted first, the session's stored value only as
fallback (an interactive takeover of an async run must not inherit the
async ceiling). `approval_mode → bypass` re-checks the manifest's
recorded `containment.bypass_admissible` — never a fresh probe.
Undeclared targets refuse `unknown_amend_target` typed.

## Consequences

- `discover` is honest about its bound: an over-limit result is
  `truncated = true`, never silently clipped.
- A K4 hit is *cheaper but never more authoritative*: the entry's
  label is copied verbatim, so a `tool`-origin observation stays
  exactly what the producing call proved. The `environment` ceiling
  means a cache can never mint a `kernel`-authority record.
- Over-invalidation is deliberate: `exec` inside a read-only-looking
  tool still bumps the epoch, so entries expire conservatively; the
  `hit_rate[tool_result]`/miss-reason telemetry makes the cost
  measurable rather than hidden.
- The preset table is data the Lab can diff; adding a preset is a spec
  change (OQ-246's close grows the lease rows).
- Leaving the writer session open after env ops means the CLI leaks no
  terminal claim — the run drains only on an explicit `close`/`cancel`
  or lease expiry, matching `run amend`'s contract.
- Deferred surface (`env open`/`attach`/`close`/`diff`/`restore`/
  `upload`/`download`; the AC-R-2.11.1-16 readers-withholding half over
  CLI output) is typed-refused and ledgered in `DEFERRALS.md`
  (DF-S2.10-1/-2), not silently absent.

## Alternatives considered

- **Separate K4 store.** Rejected — a second store would re-implement
  lifecycle/supersession/leases and create a second invalidation
  semantics to keep honest; `Memory{kind: tool_result}` makes every
  C0 mechanism apply for free (ADR-0129 d.1's intent).
- **Epoch inside the bound name.** Would turn post-mutation lookups
  into plain misses — IR-3 requires the withheld outcome to be
  *observable* (`stale_withheld`), so the epoch rides as a stamp and
  the name stays epoch-free.
- **Served record minted fresh at `tool` origin.** Rejected — it would
  launder the entry's label through a new mint; `cache(entry_ref)`
  makes the serve's provenance *name the entry*, with authority copied
  and the ceiling enforced.
- **Presets as kernel `approval_mode` members.** Rejected by ADR-0168
  D3 — a preset is a surface lowering, not a kernel semantic; the
  kernel keeps one `approval_mode` identity (T-LCD-10 keeps presets
  out of `configuration_id`).
- **Close-then-report env ops.** Rejected — writer close drains the
  run; the spec's `env *` slice is a session-level surface, so the
  session must outlive the verb.

Reopen when (a) `R-2.5.4⁰`/`sync_source` lands at S3.9 and the
`adopt` half of AC-R-2.5.3-8 is exercised against a live catalog delta;
(b) the Stage-3 fixture lands and `retrieval_eval`'s reported metrics

reader-set withholding into the CLI output path — the `compact` view's
loss report must then record withheld items rather than omitting them
silently.
