## Context

S2.3 landed the durable-execution *machinery* — `wakeup_subscribe`/
`occurred`/`fire`/`drain`/`cancel`, `Store::suspend`/`compensate_run`,
`EnvDriver::heal_with_policy` — and DF-S2.3-1 deferred the *producer*
halves to their owning tickets (the §5a.3 consumed-by assignments).
S2.6/S4.6/S4.8/S4.9 discharged `permission_decided`, `child_terminal`,
`peer_message`, and the fleet `timer`/`retry_due`/`external`/`manual`
legs. R2.3 owns the residual DF-S2.3-1 names: the `effect_terminal`
producer, the non-fleet `timer`/`retry_due` call sites, the
`suspend`/`compensate`/`heal` protocol entry points, and
`healing_policy_ref` resolution. The mechanism choices below were the
ticket's to fix.

## Decision

**D1 — the producer pass is the first move of `deliver_wakeup`.**
`Store::deliver_wakeup` opens with `wakeup_producers` — a scan of the
durable producing rows that mints the subscriptions `wakeup_due` then
reads, under the caller's writer lease:

- every `control.retry.scheduled{scope_id}` row produces one
  `retry_due` subscription per scope (`created_by` = the first
  scheduled row; a re-scheduled scope rides the same durable promise);
- a `fired` occurrence still withheld by `deliver_after` (W-3) produces
  the `effect_terminal` subscription for the blocking committed effect
  (`created_by` = the `fired` row) — so the run re-cues when the effect
  folds terminal.

Live-cover is the dedup rule: a subscription that is not
cancelled/expired and whose policy expiry has not passed covers its
trigger; a cancelled or expired one is replaced. One pass, shared with
the fleet reconciler's own machinery (CC1 — no second spelling). The
pass reads *durable* state, so a fire withheld inside the same
`deliver_wakeup` call lands its `effect_terminal` leg on the *next*
call — the honest consequence of durable-before-visible, not a missed
leg. A `SubscriptionLimit`/`TriggerUnsupported` surfaces typed; the
producing rows stay durable and the refusal is the record.

**D2 — `suspend{session_id, reasons, subscription_ids?,
resume_policy?, release_lease?}` mints the wake legs it declares.**
For each waiting reason the writer mints (or reuses live cover for)
the producing subscription — `awaiting_approval → PermissionDecided`,
`awaiting_timer → Timer`, `awaiting_child → ChildTerminal`,
`awaiting_effect → EffectTerminal` (validated against the effect fold
— an unknown effect id is `Refused`), `awaiting_event` names an
existing subscription (`Refused` on a misspelled id) —
*before* `lifecycle.run.suspended` lands; caller-named
`subscription_ids` are validated the same way. `awaiting_environment`,
`operator_pause`, `hibernated` are record-only reasons — the resuming
writer's `heal`/verify is their wake. S-1 is pre-checked (any
`prepared`/`deferred`/`committed` effect ⇒ `OpenCommittedEffects`)
*before* any subscription mints, so a refused suspend produces no
orphaned producers. `release_lease` defaults `true`; a released lease
detaches the session (`detached: "suspended"`), `false` keeps the
writer attached.

**D3 — `compensate{session_id, after_seq?, outcomes?}` takes the host's
declared dispatch.** `outcomes{<original_effect_id>: <payload> |
{"error": reason}}` is the host executor's verdict per applied,
compensable effect, walked in reverse commit order under the writer
lease. A missing entry is the honest `CompensatorMissing` leg —
`abandoned` plus `lifecycle.escalation.raised`, never a fabricated
`observed`. `after_seq` scopes the walk to the rollback cut verbatim.
The boundary reports the saga's own sums
(`compensated`/`abandoned`/`in_flight`/`escalations`), not a derived
verdict.

**D4 — `heal{session_id, policy_ref?, policy?}` resolves its ladder
through the one RegistryStore.** Policy order: inline `policy` >
`policy_ref` > `manifest.healing_policy_ref` > the attendance default
(`interactive → ask`, else `reprovision`, max_heals 3 — ADR-0132 §2).
A declared ref resolves through `EmbedService`'s `RegistryStore` only:
the record body's `healing_policy` member (opaque-body record) or
`semantic.healing_policy` (an `environment_record`) must decode as the
canonical `HealingPolicy` JSON — `HealingPolicy::to_json`/`from_json`
is the one codec (CC1). Unresolvable, policy-free, or malformed
declared refs are typed `Refused{healing_policy_ref_*}` — a default is
never substituted over a bad declaration. The live verdict is
*measured* (`verify_environment_verdict`, never the stale handle); a
non-attached `ready` handle is marked `unreachable` durable before the
ladder runs; an `attached` verdict is `Refused{environment_attached}`.
On `healed` with a successor handle the session rebinds
(`env_handle_id` updated) — R-NOSIDE: the handle never leaves the
kernel, the response carries the outcome sum only
(`healed{restored, lost_items_ref, heal_no} | ask{permission_id} |
refused{reason}`).

**D5 — `connection_info` carries the declared recovery posture at
open.** `connection_info{healing_policy_ref}` stamps
`manifest.healing_policy_ref` (the manifest names a MUST-data artifact;
§5a.1 §3). `connection_info{on_loss}` decodes the binding's declared
loss posture — `fail_run` (the Stage-1 default, preserved verbatim)
| `replace_from_image` | `replace_from_snapshot`; an unknown spelling
is a typed `EnvironmentUnavailable{on_loss:<spelling>}` at open, not a
silent `fail_run`. The heal ladder's `replace` rung opens only under a
declared replace posture.

## Consequences

- Producer legs are ordinary durable rows under the writer lease —
  crash-restart rediscovers them (a `deliver_wakeup` after a crash
  re-runs the pass against the same durable prefix; KP-11 discipline
  unchanged).
- `suspend` refuses *before* minting producers (S-1 pre-check), so a
  rejected suspend leaves no subscription residue to reconcile.
- The `timer` leg also lands at the pending-permission seam: a
  deadline-bearing `pending` mints the `Timer` subscription that
  re-cues the run to resolve `timed_out` (one live sub per deadline
  instant — deduped).
- DF-S2.3-1 reduces to the residual owned by later tickets —
  `resume_set` (R-2.4.3), `defer` (R-2.8.7), child leases (R-2.6.3),
  non-fleet ingress adapters (R-2.12.6), `heal(env_handle)` (R-2.5.5);
  BL-12's named legs land.
- Old clients see the ops as `Tier::Experimental` — `hello` without
  `experimental` answers `ExperimentalRequired`; the schema/compat
  matrix is regenerated (CC7).

## Alternatives considered

- **Mint `effect_terminal` inside `fire_one` at withhold time.**
  Rejected: the fire path would produce rows for state it just
  minted — the producer pass reads durable state only, which keeps the
  pass restart-safe and idempotent by construction (re-running sees
  the same prefix, same answer).
- **Fail-open on an unresolvable `healing_policy_ref`** (fall back to
  the attendance default). Rejected: a declared-but-broken ref is
  exactly the case a default would mask — the typed refusal is the
  honest record (fail-closed, never silent degrade).
- **Report the successor handle id on `healed`.** Rejected: R-NOSIDE —
  env handles are kernel-internal; the session's rebind makes the
  successor operative without exposing it across the boundary.
- **`on_loss` default `reprovision`-like replacement.** Rejected:
  `fail_run` is the declared Stage-1 posture — auto-replacing an
  environment the binding never declared reproducible would spend
  heals the manifest did not budget.

## Revisit trigger

Reopen if a `resume_set` producer (R-2.4.3) needs the suspend-time
subscription set carried differently than `subscription_ids`, if the
`deliver_after` withhold path grows a second blocking class beyond
committed effects (the producer scans `deliver_after` only), or if
`healing_policy_ref` gains a second home (e.g. a document-plane
artifact loader that bypasses `RegistryStore` — CC10 would then assign
the lookup elsewhere). Also reopen if `on_loss` needs a posture the
closed set does not spell (e.g. `quarantine`), or if the ops promote
to `Tier::Stable` and the error subset must freeze.
