# ADR-0342: R2.10 credential-broker legs — `audience` verifies as destination scope, `dpop` stays typed-refused, and the Stage-3 image-manifest canary member

- **Status:** Accepted
- **Date:** 2026-10-07
- **Ticket:** R2.10
- **Requirement ids:** DF-S1.13-1 · DF-S1.13-3 · R-2.8.3 · BL-19
- **Spec:** §5g.3 (credential mediation — sender constraints, canary
  channels, `mint`/`verify_minted`), §5g.3 §9 (the C1 row: "a canary
  channel in every Stage-3 environment image"), §05h I3 (the
  `environment` bundle member) · ADR-0244 (the S1.13 broker rulings this
  refines) · ADR-0059 (the canary/leak battery)
- **Rung (ADR-0024 obligation):** C0 — the verified semantics land at the
  offline/fixture ceiling; live OAuth/mTLS mediation stays R2.19's seam.

## Context

R2.10's first leg: `SenderConstraint::Audience` shared DPoP's fail-closed
cell — *any* declared sender constraint on a `minted_scoped` bind refused
`SenderConstraintUnmet`, even though `audience` is verifiable offline
(the minted token already binds `audience`; `verify_minted` already
checks it). Second: the refusal fired only on the `minted_scoped` leg —
an injected-mode bind on a `dpop` channel fell through to delivery, a
constraint the runtime cannot verify silently unenforced. Third:
DF-S1.13-3's remaining cell — "a canary channel in every Stage-3
environment image" (the §05h I3 bundle member) — had no declared member:
the broker's tripwire machinery existed (`bind`/`mediate`/`kernel_use`
refuse `canary` + `leak_detected`) but nothing obliged an image manifest
to carry one, so a Stage-3 environment could provision with no tripwire
registered on the run's broker.

## Decision

**D1 — `audience` verifies as destination-scope matching, not an OAuth
semantic.** A `sender_constraint = audience` channel admits at `bind`:
injected modes are fenced by the existing `destinations ⊆
channel.destinations` check (the audience *is* the destination), and a
`minted_scoped` binding carries the declared destination set into `mint`.
`mint` refuses `Refused{out_of_scope}` when the requested audience is not
in the binding's destinations — a token minted for an audience the
binding cannot deliver to would be an unverifiable claim, never silently
scoped. `verify_minted` is the destination-side check as landed. This is
deliberately string/set membership against the binding's declared scope —
the honest offline verification, not a claim of RFC-8707 resource
semantics.

**D2 — `dpop` refuses `SenderConstraintUnmet` on *every* delivery
mode.** Proof-of-possession needs an asymmetric signature verification
pure-std does not have and the hermetic-deps rule forbids importing; an
unverifiable constraint never fabricates an accept. The refusal moved
out of the `minted_scoped`-only gate so a `dpop` channel is fail-closed
on injected modes too — widening a refusal is fail-closed, not a
behavioral promise removed. DF-S1.13-1 keeps the typed residual with the
reason recorded; the ticket's own note names this the correct outcome
("the `dpop` cell is a trap for fabrication").

**D3 — the image manifest's canary member is `EnvironmentRecord.
canary_channels: Vec<CanaryChannel>`, identity-bearing.** Each member is
`{channel_id, spec}` where `spec.canary` must be `true` — a non-canary
entry in the tripwire list is a lie. The member participates in
`identify()` (a different canary set is a different image — the tripwire
is part of what the image *is*). `needs_adapter` (Stage-3) classes MUST
declare ≥1; `provision`/`provision_hosted` run
`check_canary_manifest` fail-closed before any adapter call or durable
row — `CanaryManifest{missing | non_canary | broker_absent}`.

**D4 — registration is a provision-time broker write, idempotent on an
identical spec.** `register_declared_canaries` calls
`broker.register_channel` for each declared member before the adapter
stands a remote up (a `register:` refusal cannot leave an unrecorded
provisioned substrate). `ChannelExists` under an identical `canary:true`
spec is satisfied — a same-image re-provision or a derived child on the
shared broker; under a different spec it is a manifest conflict and
refuses. The `action.environment.provisioned` payload records the
registered ids (never spec values — CC2: a canary's source coordinate is
broker-side only). `EnvHandle.canary_channels` carries the ids; a
derived child inherits the parent's set (the same run's broker already
holds them). Declared canaries on non-Stage-3 classes register the same
way — a declared member is never silently dropped, and declaring one
with no broker refuses `broker_absent`.

## Consequences

- `audience` channels are usable on `minted_scoped` and injected modes;
  the token's audience claim is now verified against the binding, closing
  the "verify instead of refusing" cell of DF-S1.13-1's trigger.
- A `dpop` channel's refusal surface widened (any delivery mode) — a
  deliberate fail-closed change; any prior caller relying on an
  injected-mode `dpop` bind succeeding was relying on an unenforced
  constraint.
- Every Stage-3 environment provision carries ≥1 registered canary; the
  tripwire exists from first use by construction, not by host
  convention. The injection battery exercises it (`r2_10_*` — bind on a
  manifest-registered canary lands durable `leak_detected` +
  `Refused{canary}`).
- `EnvironmentRecord` gained a member — all constructors (production +
  fixtures) name it explicitly; `provision`/`provision_hosted`/`derive`
  signatures gained the broker parameter/`canary_channels` member.
- DF-S1.13-3's canary cell discharges (the row's DONE marker records the
  evidence); DF-S1.13-1 stays OPEN with the `dpop` residual — reason
  recorded, dated.

## Alternatives considered

- **Fake a `dpop` verifier (e.g. MAC/HMAC "proof")** — rejected outright:
  a symmetric check is not proof-of-possession; a fabricated accept is
  exactly the failure the ticket names. Honest `SenderConstraintUnmet`
  is the specified outcome.
- **Audience equality against a single declared audience** — rejected:
  the channel's `destinations` set is the scope; matching against it
  reuses the landed fencing (CC1) rather than inventing a second
  audience grammar.
- **Canary registration by host convention** (callers remember to
  `register_channel` before provision) — rejected: the obligation would
  be unenforceable and untestable at the manifest; the §05h I3 member
  belongs on the record so identity, admission, and registration are one
  act.
- **Silent re-registration (`ChannelExists` always satisfied)** —
  rejected: a channel id under a different spec is a manifest conflict;
  shadowing it would let a hostile or stale image redefine a live
  tripwire.

## Revisit trigger

- A pure-std asymmetric signature verifier lands in the workspace (or the
  hermetic-deps contract is amended by ADR to admit one) → DF-S1.13-1's
  `dpop` half is implementable; the `SenderConstraintUnmet` surface
  narrows to genuinely-unmet proofs.
- §5g.3 gains standards-tracked audience semantics (RFC-8707-style
  resource indicators beyond string scope) → D1's membership check is
  replaced by the spec'd matching.
- A Stage-3 image build pipeline exists that *constructs* manifests →
  the canary declaration moves into the build recipe's emitted record
  rather than the hand-written manifest (the obligation is unchanged).
