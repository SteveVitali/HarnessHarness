# ADR-0290: S3.12 bundle completeness / reproduction / plugin-conformance / debt-retirement rulings

- **Status:** Accepted
- **Date:** 2026-09-24
- **Ticket:** S3.12 (`059_S3.12__bundle-and-plugin-conformance.md`)
- **Requirement ids:** AC-R-2.12.1-{8,9,13} · AC-R-2.12.2-{9,10} ·
  R-2.9.6⁰ᵇ (Stage-3 slice) · §8.1 M1/M2 (frontier/provenance bands under
  the R-2.1.6 gate line)
- **Spec:** §5h.3 · §5h.6 §2/§9 · §8.2 · §8.3 · §8.4; owning ADRs
  ADR-0043 (D4 provenance bands) · ADR-0152 (D3 conformance floors) ·
  ADR-0181 (D7 conformance kit) · ADR-0197 (D6/D7 retirement) ·
  ADR-0213 (duplicate-run control)

## Context

S3.12 lands the Stage-3 bundle/conformance executables: the run-manifest
reference closure inside `resolved_dependencies` (AC-R-2.12.1-8), the
bit-exact view re-derivation and deterministic R0/R1 reproduction
(AC-R-2.12.1-9), the R3 `seeds[]` budget gate + per-seed distributions +
R2 validator-set evidence (AC-R-2.12.1-13), the M1/M2 capability–cost
frontier with provenance bands (§8.2 — the M2 reporting surface the
R-2.1.6 gate line names), the four-layer plugin conformance kit and
reach suite (AC-R-2.12.2-10), the M19 `boundary_overhead_ms` measurement
with the OQ-075 `hot_path` ceiling recorded as assumption debt
(AC-R-2.12.2-9), and the `R-2.9.6⁰ᵇ` retirement machinery — removal-test
settlement, human-sealed retire, `expired_used` exclusion, the minimal
`DebtReport`. The ticket owned these rulings:

1. **What a "run-manifest reference" is and how closure is checked.**
   §5h.3's "every run-manifest reference … resolves inside
   `resolved_dependencies`" needs a vocabulary — which manifest members
   are references, and where the index lives.
2. **How `reproduce(R3, seeds[])` treats a seed arm.** A seed leg is an
   arm of a comparison — the matched-budget-or-refuse rule (CC9) has to
   say what an unbudgeted leg does.
3. **What an M2 "frontier" renders when spend provenance is partial.**
   A capability–cost point claims measured cost; estimate/unknown/
   under-covered rows must not be coerced into one (the ticket's
   no-silent-coercion rule; ADR-0043 D4).
4. **What the kit's layers probe and what a probe failure means.** The
   hostile fixture must fail *typed*, and a probe the plugin executed is
   the evidence, not just a flag.
5. **How the OQ-075 ceiling is recorded.** The measured p95 is an
   empirical claim — it must ride the assumption-debt machinery with a
   removal probe, never a comment.
6. **What "settled" does to a debt record and who may retire it.**
   §5h.6 §2's verdict effects (pass/fail/inconclusive) and the human-seal
   requirement on retirement.

## Decisions

- **D1 — `run_refs` is one flat `{dotted.field → ref}` projection of
  `RunManifest`, written by `assemble` and re-derived by `validate` from
  the exported `lifecycle.run.created` payload; the check is symmetric.**
  `manifest_refs(rm)` (`crates/hh-bundle/src/runrefs.rs`) is the single
  projection — nested members index under dotted keys
  (`experiment.design_ref`, `task_ref.task_id`, `forked_from.head_hash`,
  `spawn_event.event_id`); `signer_key_ids` indexes as one array member;
  non-reference members (`seed`, `lease_ttl`, `run_kind`) are not
  indexed — they name no external content; `extra` members are
  uninterpreted — they ride the manifest verbatim and are never claimed
  by the index (a claim the bundle cannot close is worse than no claim).
  `assemble` writes `resolved_dependencies.run_refs{run_id}`;
  `check_completeness`'s S1 stage re-derives `manifest_refs` from the
  *exported* manifest (the ledger page bytes, not the caller's copy) and
  compares both directions: a reference the manifest carries but the
  index lacks AND an index entry the manifest does not carry both fail
  `manifest_reference_unresolved` (CC3 — a stale claim is the same
  completeness break as a missing ref). Removal-sensitive in
  `crates/hh-bundle/tests/s3_12.rs` (positive closure + the two
  mutation directions).

- **D2 — R3 `seeds[]` legs are budget-matched arms; R2 verdicts name
  their validator set; `distributions[]` is per-leg rows, never a mean.**
  Every `seeds[]` member must carry `eval_budget` (and `search_budget`
  where the manifest declares one) equal to the manifest's declared
  budgets — a leg the manifest cannot budget-match refuses the whole
  reproduce as `ReproOutcome::Refused` with `UnbudgetedArm{seed <n>}`
  (matched-budget-or-refuse extends to reproduction, CC9; an unbudgeted
  leg never silently enters a distribution). The compiled
  `RuntimePlan.validators` propagate into
  `resolved_dependencies.validators[]` at assemble; an R2+ verdict's
  `validators` member names the pinned set the derivation bound — `[]`
  is the honestly empty set, never an omission. `distributions[]` is one
  `{seed, outcome, drift}` row per declared leg — the per-leg verdict —
  never an aggregate column (distributions, not means, §8.3).
  (`crates/hh-embed/src/bundle_ops.rs`,
  `crates/hh-embed/tests/conformance.rs`)

- **D3 — the M2 capability–cost frontier is a comparison surface under
  the same `validate_match` gate; confidence and coverage stratify point
  vs band; aggregation is per `(arm, provenance_class, currency)` with
  the weakest-row rule.** `frontier` is an analysis kind
  (`hh-analysis::kernel`); it runs `hh_budget::matchspec::validate_match`
  over the arm set exactly as `compare` does — matched_cap/iso_cost
  only, `mode:none` (exploratory) refuses `ExploratoryNoMatch`
  (§8.2: an exploratory analysis may execute but never reports a
  comparison); the refusal vocabulary is `CompareError::Match`, never a
  second validator (CC1). Aggregation sums spend rows *within* a
  currency only (`MixedCurrency` cells are `incommensurable`, never
  converted); the capability axis is the mean of the spec's first
  metric over contributing runs; `confidence_min`/`coverage_min_ppm`
  carry the weakest row — the minimum, never an average (the rule
  `cost_view` already applies). A cell is frontier-point admissible only
  when every contributing row is `exact`/`bounded` with `coverage = 1`;
  `estimate`/`unknown`/partial-coverage renders a *band* — reported
  provenance produces separate per-class frontiers plus a combined
  band, per AC-R-2.1.6-8 (ADR-0043 D4 carried into M2 — a band is never
  misdrawn as a point). Dominance (cost ↓, capability ↑) is computed
  among point-admissible cells of equal currency only. To feed it,
  `SpendRowFact` gains `provenance_class`/`confidence`/`coverage_ppm`/
  `currency` — the frontier stratifies on the projected fact, never a
  raw-payload rescan (CC5); the `ledger_facts/1` codec round-trips the
  new members byte-identically (CC7). The compliance metric stays in
  `hh-eval::compliance`/`hh-ontology::compliance` — `frontier` consumes
  `MetricDeclaration`, it does not re-declare one.
  (`crates/hh-analysis/src/frontier.rs`,
  `crates/hh-analysis/src/kernel.rs`, `crates/hh-eval/src/facts.rs`,
  `crates/hh-analysis/tests/kernel.rs`)

- **D4 — the four-layer kit probes are the host's typed refusals as
  evidence; `registry_ci` reports satisfy `probed`, `publisher_claim`
  never does.** The kit (`hh-varhost::kit`) is the `registry_ci` driver
  of spec §8.4's `run_conformance(plugin, layers[], placement)`
  (ADR-0181 D7): L1 `protocol` (declared-op round trip + the closed-sum
  check — an undeclared op must answer the typed `UnhandledOperation`,
  never outputs); L2 `isolation` (the mediated probe battery —
  `cross_read`/`monitor_read`/`cross_effect`/`effect`; a probe the
  plugin *executed* is the conformance failure and the host's typed
  refusal is the recorded evidence; a probe reporting `succeeded` is
  isolation absent; the raw fs/egress/exec probes are the confined
  lane's suite — `n/a{placement}` under in-process drives, never
  silently skipped); L3 `class` (the plugin's `run_conformance`
  self-report plus the guard property — a forged `allow`/rewritten
  proposal surfaces as `AuthorityCrossing` → `no_decision`, and the
  *plugin's* verdict is unsupported); L4 `reach` (static manifest
  checks + the runtime probe battery). A null plugin — `probes_live =
  false` on the fixture, no probe verbs — passes all four layers; the
  hostile fixture fails L2 and L4 typed. The report it emits is what a
  `probed` floor admits under ADR-0152 D3: `probed` refuses until a
  `registry_ci` report exists; a `PublisherClaim` report *registers*
  but never satisfies `probed` (self-report is not evidence).
  (`crates/hh-varhost/src/kit.rs`,
  `crates/hh-plugin-fixture/src/fixture.rs`,
  `crates/hh-varhost/tests/kit.rs`)

- **D5 — the OQ-075 `hot_path` ceiling is an assumption-debt record
  whose hypothesis names the measured p95.** M19's
  `boundary_overhead_ms` is measured on every confined invocation, both
  lanes (`in_process` vs `subprocess_confined`) at matched cap (same N —
  CC9), the headline compared within a pre-registered margin; the
  confined-arm p95 becomes the `hot_path` ceiling *claim* —
  `rule_id = OQ-075.hot_path_ceiling.{class_id}` with an
  `EvidenceKind::ProbeRun` ref to the content-addressed distribution
  report, `RemovalTest{ProbeRun}` (a re-probe discharges it), `Date`
  expiry (review-forced, never silently permanent), `DebtClass::
  Empirical`. The debt record is the compensating control for an
  interim ceiling — the same treatment the Stage-0/1 measurement
  deferrals took.
  (`crates/hh-varhost/tests/overhead.rs`)

- **D6 — removal-test settlement is a pure transition; a pass makes a
  record retirement-*eligible*, never retired; `retire` is
  human-sealed; `expired_used` is surfaced, never headline.** The
  Stage-3 halves are records-in/transitions-out — `settle_removal_test`
  and `retire` produce `DebtTransition`s the caller appends as
  `lifecycle.debt.status.changed` (the manager holds no authority
  handle; §5h.6 §6 D-2). The verdict effects (§5h.6 §2; ADR-0197
  D6/D7): `pass` ⇒ retirement-eligible (status unchanged until a human
  seal — D-5/D7, never automatic); `fail` ⇒ `revalidated{evidence_ref}`
  — the `ComparisonReport` becomes evidence and an `expiring`/`expired`
  record returns to `active` (a fail verdict is evidence, never a
  punishment); `inconclusive` ⇒ reschedule, no transition. `retire`
  refuses an unevidenced or non-human authority. An `expired_used`
  payload marks a record referenced after expiry — excluded from the
  headline count by `headline_admitted` and reported beside it, never
  silently dropped and never silently counted. `DebtReport` is the
  minimal derived view — bucketed counts + the excluded rows —
  records-in/records-out, never a store.
  (`crates/hh-lab/src/debt.rs`, `crates/hh-lab/tests/retirement.rs`)

## Consequences

- `resolved_dependencies` gains the `run_refs` and `validators`
  members — additive (CC8); bundles assembled before this ticket carry
  neither member and S1's closure check treats an absent index the same
  as an empty one (no retroactive incompleteness for pre-S3.12 bundles —
  the check runs over the bundle under validation, and its `run_refs`
  member is what it is).
- `ledger_facts/1` payloads carry four new `SpendRowFact` members —
  additive members decode on old readers as absent (`None`), so
  pre-S3.12 facts projections remain valid (CC8); the frontier reads
  `None` members as `unknown` provenance/`unknown` confidence — the
  honest floor, never coerced.
- The `frontier` analysis kind extends the closed `kind` vocabulary of
  `lab.analysis.analyze` — an unknown kind still refuses
  `KindNotImplemented`; `exploratory` specs still refuse comparisons.
- `probed` floors now have in-tree producers (`registry_ci` kit
  reports) — the floor's semantics are unchanged; classes that never
  named a floor are unaffected.
- The OQ-075 ceiling is now *evidence-linked* — a re-probe on different
  hardware discharges or tightens it via the removal-test path, and the
  `Date` expiry forces re-review if nobody re-probes.
- `expired_used` exclusion changes headline debt counting *for the
  minimal report only* — the ledger rows are untouched; readers wanting
  the inclusive count read the `expired_used` member.

## Alternatives considered

- **Index `RunManifest.extra` members as references** — rejected:
  `extra` is uninterpreted by definition; claiming closure over a
  vocabulary the bundle cannot read would fabricate coverage. Unindexed
  is the honest answer; the members still ride the manifest verbatim.
- **Fail the closure check only on missing refs, tolerate stale index
  entries** — rejected: a stale claim is the same completeness break
  viewed from the other direction — the bundle asserts a resolution the
  run manifest does not carry. Symmetry keeps the check monotone under
  manifest edits (CC3).
- **A mean-cost frontier with a `confidence` annotation column** —
  rejected: annotating a point does not unclaim it; the spec's shape is
  separate frontiers per provenance class plus a combined band
  (AC-R-2.1.6-8), and ADR-0043 D4 already ruled that estimate/unknown/
  under-covered spend is a band, never a point.
- **Auto-retire on a passing removal verdict** — rejected: retirement
  is an authority act (the human seal is the `retire` gate — §5h.6 §2
  D-5/D7); a verdict produces eligibility, the seal produces the
  transition. Auto-retirement would let a flaky probe silently discharge
  debt.

## Revisit trigger

- S6.1b's debt-manager service lands (live triggers, `DebtIndex`,
  scheduling): revisit whether `settle_removal_test`/`retire` stay
  pure records-in/transitions-out functions or gain a manager-side
  driver that appends `lifecycle.debt.status.changed` itself.
- A second M2 surface (e.g. a hosted `cost_view` join) wants frontier
  semantics over rows without `ledger_facts/1` provenance members:
  revisit whether `SpendRowFact`'s four new members belong in a named
  `SpendProvenance` sub-struct rather than flat options.
- OQ-075's `hot_path` ceiling is re-probed on materially different
  hardware or a new confinement lane: the `ProbeRun` removal test
  discharges or tightens the record — revisit the `Date` expiry policy
  if probes become continuous.
- GATE-G2's `benchmarkSet` lands the foreign-manifest import
  (DF-S1.24-2 residual): revisit whether `run_refs` needs a foreign
  spelling arm for manifests this implementation did not mint.
