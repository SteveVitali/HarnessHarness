# ADR-0233: S1.5 ledger crate shape — `hh-ledger` above wire/identity/provenance/ontology, WAL storage class, and the typed error additions beyond the §5a.1-named set

- **Status:** Accepted
- **Date:** 2026-09-15
- **Ticket:** S1.5
- **Requirement ids:** R-2.2.1
- **Spec:** §5a.1 (R-2.2.1 — event store / run ledger) · ADR-0026, ADR-0027, ADR-0028,
  ADR-0029, ADR-0066, ADR-0068

## Context
The run ledger is the sole authoritative record of a run (ADR-0026 §1) and every
downstream slice — effect lifecycle, checkpoints, context admission, audit, evaluation —
builds on it. The crate had to satisfy: one canonical form and one hasher (CC1, so it
sits on `hh-wire`/`hh-identity`), the provenance/authority checks at append (§8.1, so it
consumes `hh-provenance`), the plane/home ownership rule (CC10, so `hh-ontology` derives
`plane` from the class prefix), and **no** dependency on HIR (`hh-hir` must not become a
ledger dependency — `ir_refs` are carried as opaque `{semantic_id, version_id}` pairs
through `hh-identity`'s `IrRef`, CC5 contract-only reach).

Two further pressures shaped the decision. First, the provenance record's *decoder* did
not exist: `hh-provenance` owned the canonical encoder, and the ledger needs to decode
records out of stored envelopes and re-check endorsement legitimacy — a second private
schema would have violated CC7. Second, the §5a.1 §2 errors column names most but not
all refusals the implementation must type (e.g. a lifecycle/environment row with
`provenance.origin ≠ kernel`, an unresolvable `causes[]` coordinate, append after
`lifecycle.run.finished`); those needed named homes.

## Decision
- **New persistent crate `crates/hh-ledger`** (the E1 build binding for §5a.1), deps
  `hh-wire`, `hh-identity`, `hh-provenance`, `hh-ontology` only. Modules: `errors`
  (typed refusals + `Tampered`), `ids` (allocated-id model, injectable `Clock`/`IdSource`,
  derived `effect_id`), `manifest` (`RunManifest` + `open_run` validation + lineage
  anchors), `classes` (the one declared persistence-policy table — ADR-0234), `event`
  (`Event`/`EventEnvelope`/`EphemeralRecord`, cursors, filters, `EventFrame`),
  `schema` (envelope canonical form, the `schema_version` gate, the deprecation
  registry), `views` (`context_view`, `run_summary` folds), `store` (WAL + commit
  markers, the fenced writer lease, subscriptions, blobs, `verify`, `project`,
  `lineage`).
- **`hh-provenance` gains `decode.rs`** (CC8 additive): canonical `from_json` decoders
  for `ProvenanceRecord`, `Label`, `LabelEndorsed`, `EndorsementBasis`, `ContentKind`,
  `Origin`, `AuthorityClass`, `PersistenceScope`. The schema source owns its decoder —
  the ledger never maintains a private copy (CC7).
- **Storage class is a file-backed WAL** (`runs/<id>/events.wal` + `lease.json` +
  `blobs/<digest>`); every in-memory structure is a rebuildable projection of it.
  Chosen over an embedded KV store to keep the workspace pure-std and the durable form
  directly inspectable as canonical JSONL.
- **Typed error additions** beyond the §5a.1 §2 column (each is a refusal, never a
  warning): `KernelOriginRequired` (§5a.1 §6 "origin = kernel on lifecycle/environment
  rows" — the spec names the rule, not the error), `UnresolvedEventRef` (a `causes[]`
  coordinate that does not resolve — the spec's `UnknownParent` covers only the
  branch-tree parent), `BlobCorrupt` (bytes under an address fail to re-hash — storage
  corruption is typed, not served), `AttestationInvalid` (the §8.1 attestation check's
  ledger-side name), `RunFinished` (append after `lifecycle.run.finished`), `Io`
  (non-append store I/O). `Missing{gc|redacted|key_unavailable}` reserves all three
  spec reasons even though `redact`/`gc` land at Stage 2 (ADR-0068 R3 — never
  `Tampered`).

## Consequences
- Good: one canonicalizer computes every hash and content address (CC1); the decoder
  lives at the schema source (CC7); `hh-ledger` has no edge to `hh-hir`, so the ledger
  can be consumed by lower tiers without dragging the IR in; every refusal the
  acceptance battery exercises is a typed variant, so tests assert on errors, not
  strings.
- Cost: `LedgerError` is larger than the spec's named set (deviation — this record);
  the in-process `Store` relies on `&mut self` for the intra-process single-writer
  guard, so multi-*process* writer exclusion rests entirely on `lease.json` fencing
  (single-host scope — see ADR-0235).

## Alternatives considered
- **Ledger-owned provenance decoder** — rejected (CC7: a second schema copy that can
  drift from the encoder).
- **`hh-ledger` depends on `hh-hir` for `ir_refs`** — rejected (CC5/CC10: `ir_refs` are
  coordinates, not IR nodes; the ledger must sit below the IR's consumers).
- **Reuse `hh-baseline`'s Stage-0 single-file event model** — the baseline was deleted
  at the Stage-0 boundary (ADR-0221); the §5a.1 durable form is a per-run WAL with
  commit markers, not the spike's monolithic file. Rejected.

## Revisit trigger
Reopen if the storage class changes (e.g. an embedded store for multi-host access or
the Stage-4 fleet run), if a spec amendment names ledger errors that conflict with the
added variants, or if `ir_refs` acquires IR-typed semantics requiring an `hh-hir` edge.
