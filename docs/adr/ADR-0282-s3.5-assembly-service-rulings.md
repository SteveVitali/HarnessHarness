# ADR-0282: S3.5 Assembly-service rulings

- **Status:** Accepted
- **Date:** 2026-09-23
- **Ticket:** S3.5 (`051_S3.5__assembly-service.md`)
- **Requirement ids:** R-2.10.1
- **Spec:** §6.1 (the assembly service — `AssemblySource`, D1–D5,
  `assemble/plan/apply/validate_batch/explain`, S-1…S-8, M-1/M-2,
  `AssemblyDiff`, C-REF-6 + `freeze`, hosted root selection + `n/a` rows,
  the Stage-0 anchor) · ADR-0147 (pipeline + service guarantees) ·
  ADR-0148 (diagnostic record + code list + corpus) · ADR-0149
  (`AssemblyDiff` + drift) · ADR-0150 (hosted authoring) · ADR-0025 (the
  one resolver) · ADR-0037 (publish/sameness) · ADR-0210–0216 (interim
  rulings inherited verbatim)

## Context

S3.5 lands the assembly *service* — the C1 Lab-facing orchestration over
the C0 kernel (`hh-assembly` owns `compose`/`resolve`/`validate_assembly`/
`seal`; nothing semantic may move). The choices the ticket owned:

1. **The service's home.** The service borrows a `RegistryStore`, a
   `ClassCatalog`, and the kernel provenance — it is Lab instrumentation,
   not kernel semantics. Putting it in `hh-assembly` would make the
   kernel depend on the authoring-sugar grammar it must never see (A-2).
2. **The `AssemblySource` grammar shape.** §6.1 names the members
   (`dialect`, `root_kind`, `base`, `layers`, `overrides`, `imports`,
   `hosted`, `ext`, `document`); the document body had to ride an
   existing codec (CC7) and the source must never be sealable (A-3).
3. **Where desugared provenance lives on the sealed output.** A sealed
   definition may not carry unresolved layer fragments — but S-7/M-2
   require `explain` to attribute content to layers after the fact.
4. **How D2 makes one experiment layer per equal override list.** The
   experiment layer's identity must be content-addressed so two
   authoring paths producing equal overrides share one layer id (AC-9)
   while differing layers stay recorded (AC-2).
5. **What `plan` diffs against and how `exit` is computed.** The plan
   is the planning half of `apply` (S-1): same pipeline, no retention.
6. **How `AssemblyDiff` relates to `HirDiff`.** T-1 requires the
   projection to be lossless — every kernel `DiffOp` must land in a
   bucket and `flatten` must return the ops verbatim.
7. **The C-REF-6 posture.** Drift against a recorded snapshot is
   informational-by-sameness; the default is `freeze`, and `adopt` is
   an explicit authority-aware act.
8. **The Group L surface.** Which `lab.assembly.*` ops land now vs stay
   declared-pending, and what "byte-identical over the boundary" can
   mean when sealed provenance carries timestamps.
9. **The CLI `definition` verbs' parameter contract.** S3.1 wired the
   verbs to ops that did not yet exist; landing the ops made the
   pre-registered `{definition, source_path}` params a mismatch with
   the `{source, …}` contract.

## Decision

1. **Home = `hh-lab::assembly`.** `AssemblyService<'a>` borrows
   `&mut RegistryStore` + `&dyn ClassCatalog` and carries `kernel` +
   `registrar` provenance + a service-stamped `resolved_at`; it holds no
   state the registry does not own (a crash loses only the
   derivation-key cache).
2. **`AssemblySource` is a closed record** decoded by
   `AssemblySource::from_json` (fail-closed member set; `dialect` must
   be `hir/1`). `document` carries canonical `hir/1` node/edge JSON
   decoded by the one `hh_hir` codec (CC7); the assembly grammar lives
   only inside `layers[].fragment` (D4 — a document node may not carry
   registry-facing selectors). The source is never an input to `seal`.
3. **Derivation provenance rides `ext["hh.lab/assembly"]`** — a
   non-semantic extension block on the sealed document recording the
   layer stack, `derivation_key`, `source_digest`, and snapshot
   coordinate. Semantic fields carry only resolved kernel content; the
   ext block is excluded from `semantic_id`/`configuration_id` by the
   identity rule already in force.
4. **D1–D5 as written:** `base` resolves (snapshot-confined) to a
   `sealed_definition` record → lowest-precedence `packaged-default`
   layer (+ document scaffold when `document` is absent); `overrides`
   materialise as exactly one `experiment` layer whose id is
   `H(idp ‖ "override-layer" ‖ canonical(spellings))` (declared-empty
   still materialises); `imports` become document `ContextItem`/
   `Procedure` nodes whose `Text` leaves carry `authority = external,
   origin = import` (in-file `content` at C0 — the desugar performs no
   IO; missing content is a diagnostic); `root_kind = hosted`
   synthesises `AgentProcess{hosted: OpaqueProcess{…}}` from `hosted{}`
   and refuses `slots`/`profile_binding` with `C-CLASS-6`.
5. **`plan` = `assemble(mode = plan)` + `AssemblyPlan`**: the plan diffs
   the resolved definition against the base/lineage head, projects the
   `HirDiff` into `AssemblyDiff`, attaches `defaulted_paths`/
   `authored_paths`/`layer_map`, evaluates snapshot drift (`C-REF-6`),
   and sets `exit ∈ {no_changes, changes, error}`; `apply` =
   `assemble(seal)` + `register(SealedDefinition)` + `publish`
   (S-5 refuse-on-error, S-6 forwards the registry's widening gate);
   `validate_batch` dedupes points by `derivation_key`; `explain`
   replays the recorded layer stack to answer "who set it";
   `compile` is a verbatim pass-through to `hh_compiler::compile`
   (the service adds no compilation semantics).
6. **`AssemblyDiff = project(HirDiff)`** into the 14-bucket set keyed by
   assembly path (`slot_rebind`, `slot_toggle`, `slot_param_change`,
   `value_change`, `space_change`, `entity_add`, `entity_remove`,
   `entity_change`, `edge_change`, `cap_change`,
   `profile_constraint_change`, `surface_only`, `ext_only`,
   `provenance_only`); `flatten` returns the ops verbatim —
   `flatten(project(diff(a,b))) = diff(a,b).ops` (T-1, tested).
7. **C-REF-6: `freeze` is the only default.** `plan`/`drift` re-resolve
   under the named snapshot and report `project(diff(res_old,
   res_new))` at severity L1 info / L2 warning / L3 error; `adopt` is an
   explicit `apply` carrying `derived-from{hypothesis}` and refuses
   `origin = evolution` on an L3 delta (authority monotonicity).
8. **Group L:** `assemble`, `plan`, `apply`, `validate_batch`,
   `explain`, `diff`, `drift`, `adopt`, `identity` are implemented
   (`labi`) with canonical-JSON records in/out; **`compile` stays
   declared-pending** — it needs canonical codecs for `CompileInputs`/
   `CompiledBundle` and no ticket-owned ruling exists for that surface
   (DF-S3.5-1). AC-10's parity claim is over the *stable* contract
   fields (`status`, `report`, `plan` identity/diff/exit, sealed
   `semantic_id`/`configuration_id`); `resolved_at`/`seal.verified_at`
   enter `version_id`, so whole-response byte-equality across two
   service instances is not a valid oracle — each service still
   produces deterministic bytes for a fixed derivation.
9. **CLI `definition` verbs re-pointed at the implemented contract:**
   `plan`/`apply`/`validate`/`explain` send `{source: <parsed file>}`
   (the file is an `AssemblySource`); `apply` sends the CLI principal's
   `registrar` provenance + `--publish ns/name[@label]` → `publish`;
   `diff`/`identity` take sealed `version_id`s (T-2: the diff's
   endpoints are sealed definitions, never loose files);
   `compile` keeps forwarding to the pending op.

## Consequences

- The kernel is untouched semantically: `hh-assembly` changed only in
  diagnostics (`C-CLASS-2` now means slot-unbound per the corrected
  numbering) and codec visibility (layer codecs exported for the one
  decoder rule, CC7).
- S-3 byte-identity with the kernel is executable
  (`s3_byte_identity_with_kernel`); every acceptance row AC-1…AC-11 is
  executable (`crates/hh-lab/tests/assembly_service.rs` ×20 +
  `ac10_assembly_ops_run_out_of_process_over_group_l`).
- `definition plan`/`apply`/`validate`/`explain` now do real work from
  the CLI; `definition diff`/`identity` moved to version-id operands —
  an observable CLI contract change from the pre-S3.5 placeholders.
- `lab.assembly.compile` keeps refusing `stage_pending` until
  DF-S3.5-1 lands a codec decision.

## Alternatives considered

- **Service inside `hh-assembly`:** rejected — the kernel would own the
  authoring-sugar grammar and the boundary between "canonical
  `hir/1` document" and "source" would blur (A-2/A-3).
- **Layer provenance as semantic content:** rejected — unresolved
  fragments in sealed semantic fields would change `semantic_id` and
  duplicate the resolver's job (S-2/S-3).
- **Source-side diffing for `definition diff`:** rejected — T-2 pins the
  endpoints to sealed definitions; a source-level diff would need a
  second diff semantics.
- **Byte-equal AC-10 oracle:** rejected — timestamps are load-bearing in
  sealed provenance; comparing stable fields is the honest invariant.

## Revisit trigger

Reopen if (a) a canonical `CompileInputs`/`CompiledBundle` codec lands
(DF-S3.5-1 closes), (b) `resolved_at`/`verified_at` leave the sealed
identity inputs (making cross-process byte-equality a valid oracle), or
(c) a second assembly dialect is admitted (`dialect` becomes a sum).
