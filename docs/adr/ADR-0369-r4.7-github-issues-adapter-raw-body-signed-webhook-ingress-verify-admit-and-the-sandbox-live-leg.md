## Context

R4.7 discharges the Stage-5 work-source requirement for real: a GitHub
Issues `work_source_adapter/1.0` (not the Stage-4 fixture proxy), signed
webhook ingress (`X-Hub-Signature-256`, not the generic `hmac-sha256:`
canonical-JSON lane), and live legs on the private sandbox repo
`SteveVitali/hh-live-sandbox` behind a runtime `cloudflared` quick
tunnel. Four decisions are this ticket's to own: how the GitHub dialect
maps onto the canonical ingress contract, what `fleet.webhook_ingress`
*does* with a verified delivery, how the two credentials reach the
broker without ever touching a child environment or a ledger, and how
the live leg's REST/tunnel cells are orchestrated inside the sandbox's
mutation scope.

## Decision

- **D1 — the GitHub dialect is one canonical module
  (`hh_fleet::github`).** `verify_sig256(raw, "sha256=<hex>", key)`
  verifies HMAC-SHA256 over the **raw request bytes** — GitHub signs the
  wire body, so the canonical-JSON `hmac-sha256:` lane's re-serialized
  preimage would never match; anything without the `sha256=` prefix is
  `UnsupportedAlg`, a bad mac is `BadSignature`, absent is
  `MissingSignature` (fail-closed, typed). `X-GitHub-Delivery` names the
  occurrence (`gh-delivery:<id>`); `issues`/`issue_comment` payloads map
  to `external{kind:"github.issue"}` occurrences whose item is
  `gh-<repo>-<number>` (`github_item_id`); PR-marked issues and non-issue
  events are typed refusals, never silent drops. `issue_record`
  normalizes the REST issue shape to `WorkSourceRecord` (`native_id` =
  the issue number). One module serves both the boundary lane and the
  packaged plugin (CC1).
- **D2 — `fleet.webhook_ingress` verifies *and admits*.** The pre-R4.7
  op built a transient `WebhookAdapter`, called `receive`, and dropped
  it — a verified occurrence never reached `FleetEngine::observe`. The
  op now constructs the lane adapter from the request's `source` doc,
  `receive`s, and `observe`s through that same instance inside the call
  (`context.observation.recorded` + `control.wakeup.occurred` durable
  before the reply), so the next `fleet.reconcile` folds the cue into a
  `WorkItem`. Replay answers `received`/`duplicate` honestly while the
  durable fold audits the skip; a stale re-delivery records a new
  occurrence but admits `known` — item count unchanged. One op, one
  adapter, durable-before-visible.
- **D3 — `key_ref` stays a broker coordinate, end to end.** The
  `hh.fleet.webhook_source/1` doc's `webhook.key_ref` names the broker
  binding (`broker:github-webhook`); at the boundary the op resolves the
  signing key through the caller-supplied `key` — in the live leg that
  value exists only inside the test process, resolved by
  `CredentialBroker::mediate` + `drain_claim` over a
  `SecretSource::LaunchEnv` channel registered `grant → decide → bind`
  first. `HH_GITHUB_SANDBOX_TOKEN` rides a second channel the same way.
  No value prints, lands in a record, or enters a child environment —
  evidence records `provided: yes/no` only.
- **D4 — the live leg executes inside the gated test; the script
  orchestrates.** `crates/hh-embed/tests/r4_7_live.rs` carries three
  `#[ignore]`d cells (`r47_github_live`, `r47_github_cleanup`,
  `r47_github_plugin`): the test owns the loopback listener, the
  `cloudflared` quick tunnel, the GitHub REST calls (over the in-process
  `hh-tls` client — the token never reaches argv/disk), the one
  sandbox-scoped `POST /repos/…/hooks` + test issue/comment, the signed
  delivery → `webhook_ingress` → `reconcile` → `WorkItem` fold, the
  dedupe/stale cells, and the rollback (`DELETE` the hook, close +
  `hh-live-test` the issue). `scripts/live-github.sh` is the
  orchestrator `live-verify.sh github-live` invokes; its EXIT trap runs
  `r47_github_cleanup`, which re-fires the rollback for whatever
  `$HH_GH_DIR/state.json` still marks pending — the hook never outlives
  the leg, panic path included. The `hh-live-test` label is
  created-if-absent (GitHub refuses unknown label names; recorded
  `GH_LABEL created=` in the transcript).
- **D5 — sandbox scope is the whole mutation surface.** Every external
  mutation lands on `HH_GITHUB_SANDBOX_REPO` (`SteveVitali/
  hh-live-sandbox`) only: one webhook (pre-state `GET`, unconditional
  `DELETE` + verified-absent re-`GET`), the test issue + comment (issues
  are undeletable — closed + `hh-live-test`-labeled and recorded), and
  the `hh-live-test` label itself. No other repository, organization,
  user, workflow, secret or member is touched; the public launch repo
  is never named.
- **D6 — the ticket's size budget is enforced by STOP, not by
  trimming.** 4,260 changed lines excluding the recorded fixture vs the
  900 budget: the required coverage — dialect + adapter + plugin +
  manifest + boundary lane + ~880 hermetic test lines + the ~1,160-line
  live cell + leg wiring — does not decompose below it without dropping
  named acceptance cells. The run commits the completed work locally and
  stops before push/PR; the operator rules (R4.5e/R4.6 precedent).

## Consequences

- The Stage-5 fixture proxy (`hh-tracker-fixture`) stays landed as the
  hermetic stand-in — nothing about this ADR removes it — but it is no
  longer the only exercised seam: every AC-9 leg (probe, dedupe,
  stale-window no-op, out-of-process placement) now replays against the
  real adapter with no fixture in the path.
- `fleet.webhook_ingress`'s contract grows the `delivery_raw` +
  `signature` + `delivery_id` + `event` + `key` members for the GitHub
  lane; the generic `hmac-sha256:` lane is unchanged.
- A replayed or stale delivery is a durable occurrence, not a silent
  drop — replay-window labeling + the audited duplicate-skip row stand
  as the evidence shape.
- The `github-live` leg is USD 0 (GitHub API + Cloudflare quick tunnels
  are free); spend rows record 0.000000.
- The overrun surfaces to the orchestrator: the branch commits locally
  and stops; PR + LEDGER/BUILD_INDEX advancement await the ruling.

## Revisit trigger

Reopen when (a) a second tracker source joins `work_source_adapter/1.0`
(the `gh-<repo>-<n>` id shape and the `GithubTracker` dialect are
GitHub-shaped — a new source re-scopes the adapter seam rather than
silently extending it); (b) the sandbox-repo rule changes — live legs
mutate only `SteveVitali/hh-live-sandbox` under scripted trap rollback;
any wider surface is a fresh operator ruling; (c) webhook delivery
semantics change upstream (signature scheme, header names, event
payloads) — the pinned `X-Hub-Signature-256` verify path must stay the
only admission path, never a relaxed fallback.
