# ADR-0362: R4.2a — CI fast path (docs-only heads), artifact anchors, and the full-run cadence

- **Status:** Proposed
- **Date:** 2026-10-20
- **Ticket:** R4.2a
- **Requirement ids:** none (`no_req_reason: operator-decided CI cost and wait insert`; GATE DECISIONS `CI insert` D1–D7)
- **Spec:** n/a (CI infrastructure)
- **Rung (ADR-0024 obligation):** non-contract note — CI tooling record, no protocol surface.

## Context
Hosted CI is free on this public repository but the chain waits for it at every
boundary, and it takes slots from the account-wide concurrent-job limit the
operator's other repositories share. Measured 2026-10-01..20: 654 jobs, 4,406
job-minutes; 46% of minutes were `push` runs duplicating a `pull_request` run on
the same commit; 58% were heads that changed only `docs/` or `research/` and
still ran the full ≈ 11-minute job; the non-gating S2 spike is ≈ 3.3 minutes of
every full job. Round 3 averaged 4.8 PR runs per ticket, 3.6 of them docs-only.

## Decision
Recorded under the operator's GATE DECISIONS `CI insert` rows D1–D7
(2026-10-20):

- **D-A (D2).** `ci.yml` triggers are `push` on `main` only, `pull_request`,
  and `workflow_dispatch`; `permissions: contents: read, actions: read`;
  concurrency is event-scoped (`ci-<event>-<pr-number|ref>-<run-id|x>`,
  cancel-in-progress everywhere except a dispatch). A chain branch gets CI only
  through its PR — one `pull_request` run per head. `main` pushes still run
  full.
- **D-B (D2).** A docs-only fast path decided inside the job, so the check
  always reports under its own name (`build · test · fmt · drift`) and
  concludes `success`. The fingerprint is the sha256 of `git ls-tree -r -z
  --full-tree HEAD` with `docs/`/`research/`-prefixed entries removed — HEAD of
  the job's own checkout (the merge commit on `pull_request`), never
  `pull_request.head.sha`. The anchor is a repo-wide artifact
  `ci-anchor-v1-<job>-<RUNNER_OS>-<fingerprint>` uploaded (14-day retention,
  `overwrite`) only by the last two steps of a successful `full` job on a
  trusted event (`push` to `main`, `workflow_dispatch`, or a same-repository
  `pull_request`). `decide` answers `fast` only when all of D-B4 (a)–(e) hold;
  any error, empty output, unparsable JSON or missing variable answers `full`.
  Steps after `id: path` carry `if: steps.path.outputs.mode != 'fast'` or a
  `# ci-mode: both — <reason>` comment; `check-ci-gating.sh` enforces the
  convention plus the readers scan.
- **D-C (D3).** The S2 spike and its sheet upload run only on
  `workflow_dispatch` full runs; `continue-on-error` stays. ADR-0220's
  "CI-runnable (non-gating)" consequence is kept by those runs.
- **D-D (D4).** One `workflow_dispatch` full run of `ci.yml` on the chain tip
  at the GATE-G7 readout, at the GATE-G6 readout, before HUMAN-H7's tag, and
  this ticket's own final code head — never one per ticket. A red full run
  sets `blockedOn` and is bisected over the tickets since the last green full
  run. **Fallback cut (D6):** production measured 413 lines after deliverable
  4 (≥ 330 trigger), so the full-run reader (`scripts/ci/full-run.sh` + test)
  moved into L4.3 (164r) by dated note; the lint is never cut; until L4.3
  lands, gate full runs are read by hand (`gh run view <id> --json
  jobs,conclusion`). If a dispatch is refused because `main`'s workflow lacks
  `workflow_dispatch`, the final code head's full-path PR run stands as the
  ticket's full run, the spike is run locally, and R4.18 dispatches on `main`
  after H7.

## Consequences
- **Safety argument.** The docs audit (Ground truth 3, re-run in AC 2 of the
  ticket): no `build.rs`, no `.cargo/config`, no symlink or gitlink under
  `docs/` or `research/`; gated steps/tests read `spec/`, `plugins/`,
  `schema/`, `crates/`, `foreign/` — never committed content under `docs/` or
  `research/` (a *docs read* is reading committed content under those prefixes;
  a job's own output written there, like the spike sheet, is not one). The
  readers scan re-checks this at every run and fails on any new un-allowlisted
  hit; `check-bm-tools.sh` runs on both paths because it does read docs.
- **Threat model.** Same-repository writers are trusted. Fork PRs run their
  own `ci.yml` and can upload artifacts to this repository, so the
  head-repository check is load-bearing at both ends: `decide` requires
  `head.repo == repository`, and the artifact match requires
  `workflow_run.repository_id == head_repository_id == <this repo>` — a fork's
  run or a fork's artifact can never mint or satisfy an anchor here.
- **Fail-closed.** Only the exact last line `fast` selects the fast path;
  `ci.yml` never sets `CI_ANCHOR_LISTING`; an anchor is written only by a
  trusted, successful, `full` job's last two steps; editing
  `docs-readers.allow` to silence a real read is a fail-closed violation.
- **Measured before/after (AC 8).** Baseline 2026-10-01..20: 4,406
  job-minutes; ≈ 11 job-minutes per head of either kind; 93 job-minutes per
  round-3 ticket. Projection on the same mix: −77 to −80% (≈ 900–1,000
  job-minutes); a docs-only boundary head drops ≈ 11 min → ≈ 1 min; a code
  head ≈ 11 min → ≈ 7.5 min. This PR's own measured heads are recorded in
  `docs/build/runs/R4.2a.md`; the after-state across R4.3…R4.16 is DF-R4.2a-1
  (owner R4.16, DONE before GATE-G6).

## Alternatives considered
- **`paths-ignore` / `[skip ci]`:** leave a head with zero checks, which
  `ci-boundary.sh` reads as `pending` — and no `push` run backs it up under
  D-A. Rejected.
- **`actions/cache` anchors:** PR-scoped, not shared across PRs — the anchor
  must be repo-wide for a later docs-only PR head to find it. Rejected.
- **Full run per ticket:** in phase 1 a PR `full` path already runs every
  test; a per-ticket dispatch adds only the spike (≈ 11 min × ≈ 45 tickets for
  nothing a PR full path does not test). Rejected; D4's per-gate cadence
  stands.

## Revisit trigger
Reopen when: a gated step or test starts reading committed content under
`docs/` or `research/` — including one the readers scan cannot see (a test
that walks the repo root with `read_dir`, `join("../..")` or `git ls-files`);
L4.3's `permissions` or matrix lands (each leg mints its own `$RUNNER_OS`
anchor); HUMAN-H7's required-checks change lands; the repository turns
private; or the `ubuntu-latest` → Ubuntu 26 migration moves the runner.
