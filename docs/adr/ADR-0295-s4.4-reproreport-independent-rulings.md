# ADR-0295: S4.4 `ReproReport{independent}` rulings — declared-material distinctness as the interim `independent` rule, `verdict` as the spec vocabulary derived from `outcome`, `repro_report.bundle_id` binding at the `reproduced` gate

- **Status:** Accepted
- **Date:** 2026-09-26
- **Ticket:** S4.4 (`065_S4.4__results-leaderboard-publication.md`)
- **Requirement ids:** R-2.10.5 (§6.5 results-store/publication C1) ·
  R-2.9.3 (§5h.3 reproducible-bundle C1/Stage-4 row —
  "`ReproReport` sidecar with `independent`")
- **Spec:** §5h.3 §2 (`ReproReport` record shape, `reproduce` op,
  `set_status` `reproduced` gate, `PublicationPolicy`, foreign
  import/export) · §6.5 §2.2 (`snapshots(definition_ref)`); owning ADRs
  ADR-0139/0140/0141 (bundle construction, validation stages,
  publication lowering) · ADR-0279 (results store) · OQ-334
  (reproduction distinctness establishment)

## Context

S4.2 landed the scoped bundle kinds, S8–S9, the status ladder,
`PublicationPolicy` withholding, and the foreign import/export
machinery; S4.3 landed the §6.5 results-store C1 surfaces. The §10.x
stage content named for this ticket — "`arm`/`experiment`/`lineage`
kinds with S8–S9, `ReproReport{independent}`, `BundleStatusRecord`,
`PublicationPolicy`, foreign import/export" — was therefore almost all
in place, with three genuine gaps:

1. `ReproReport` carried no `independent` member, no `reproducer`
   identity, and no `verdict` in the spec's four-valued vocabulary —
   so the `set_status{to: reproduced}` gate (which reads
   `repro_report{verdict, independent}`) was unreachable through any
   report `kernel.reproduce` could produce.
2. The gate did not bind the report to the subject bundle — a report
   for a different bundle was accepted as evidence.
3. §6.5 §2.2's `snapshots(definition_ref) → [snapshot_id]` read existed
   in `hh-results` but had no `hh-embed` boundary op.

OQ-334 is the open ruling on *how* "distinct installation and signer"
is established (signer identity alone, an organisational claim, or
both; whether a same-organisation reproducer counts). It is due
Stage 4 for the C2 `reproduced` status — the R-2.9.3 stage row assigns
"independent-reproduction status" to C2/Stage 5 and S5.4 owns the
runtime arm — but the C1 `ReproReport{independent}` field lands now
and needs a computable rule.

## Decision

1. **`independent` computes over declared identity material, fail-
   closed.** `compute_independence(producer, instrument, reproducer,
   reproducer_instrument)` compares the *signer* axis
   (`provenance.attestation.anchor.signer` — the one scheme a signing
   claim takes, CC1) and the *installation* axis
   (`instrument.installation_id`). `true` requires both sides to
   declare both axes and both to differ; every other case computes
   `false` with a named basis (`same_signer`, `same_installation`,
   `reproducer_signer_undeclared`, `producer_signer_undeclared`,
   `reproducer_installation_undeclared`,
   `producer_installation_undeclared`) recorded on
   `evidence.independent_basis`. This is a declared-material
   *comparison*, not cryptographic establishment — the reproducer's
   claim is recorded verbatim (`CC2`: authority is conferred, never
   read from content) and the kernel computes the flag.

2. **A caller-supplied `independent` is never read.** The
   `kernel.reproduce{reproducer{provenance, instrument}}` param
   accepts declared identity material only; an `independent` member
   inside it is ignored by construction. An absent `reproducer`
   declaration means the kernel itself re-checked the bundle — the
   report stamps the kernel's provenance as reproducer (repeatability,
   never independence, and the flag computes `false` honestly).

3. **`verdict` is the spec's four-valued spelling derived from
   `outcome`.** `pass → reproduced`, `drift → not_reproduced`,
   `nondeterministic | inconclusive → inconclusive`,
   `refused → n/a{reason}` (the `MetricValueKind::Na` member shape —
   refusal is not a reproduction verdict). `outcome` stays on the
   record as the interim C0 spelling (CC8 additive); consumers read
   `verdict`.

4. **The `reproduced` gate binds the report to the subject.**
   `set_status{to: reproduced}` now requires
   `repro_report.bundle_id == bundle_ref` in addition to
   `verdict = reproduced` and `independent = true` — a `ReproReport`
   is evidence for its named bundle, never a transferable badge (CC2).

5. **`lab.leaderboard.snapshots` is the §2.2 read over the persisted
   index.** `{definition|definition_ref}` → `{definition_id,
   snapshots: [snapshot_id]}` — oldest first, the same index
   `snapshot_leaderboard` appends to. No new semantics.

## Consequences

- In-tree produced bundles declare no signer/installation material,
  so `independent` computes `false` for them — honest repeatability.
  A distinct-signer reproduction from a declared foreign installation
  computes `true` today, which is exactly the evidence shape the C2
  `reproduced` status will need once OQ-334's establishment ruling
  lands (S5.4).
- `ReproReport` serialisation gains `verdict`, `reproducer`,
  `reproducer_instrument`, `independent`; `report_id` covers the new
  members, so historical `report_id`s re-derive identically only for
  reports sealed under the old member set — report ids are
  content-addressed, never a lookup key across dialects.
- The `reproduced` gate is stricter than S4.2's (the `bundle_id`
  binding): a fabricated cross-bundle report is now refused. This is
  a gate tightening, not a vocabulary change — the same
  `StatusGateFailed` refusal.
- The schema registry grows one op (`lab.leaderboard.snapshots`);
  generated artifacts regenerated and committed.

## Alternatives considered

- **Mint `independent` only after §05g attested establishment
  (defer the whole flag to S5.4).** Rejected: the C1/Stage-4 row
  explicitly names `ReproReport{independent}` for this ticket; the
  fail-closed declared-material rule is a strict floor under any
  future establishment rule (it can only tighten, never loosen).
- **Treat `instrument.version` as the installation.** Rejected:
  kernel versions are not installations — same version on two hosts
  is not distinct, different versions on one host are not
  independent. Fabricating the axis would mint `independent` on
  incomparable material.
- **Accept a top-level `signer` string member on provenance.**
  Rejected: a signing claim is an attestation anchor (CC1, one
  scheme per concern); a parallel member would fork the vocabulary.

## Revisit trigger

OQ-334's ratified ruling lands (expected at S5.4's R2 reproduction
work): if it fixes a different establishment standard — e.g. a signed
challenge from the reproducer's root, or an organisational-binding
claim — `compute_independence` must gain that establishment as an
*additional* requirement for `true`, and `evidence.independent_basis`
records the standard applied.
