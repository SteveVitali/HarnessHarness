# ADR-0230: S1.3 provenance crate shape — hh-provenance below hh-identity, conservative Stage-1 minting, baseline hand-stamps on the canonical record

- **Status:** Accepted
- **Date:** 2026-09-15
- **Ticket:** S1.3
- **Requirement ids:** R-2.1.5 (anchors CC1, CC2); discharges DF-S1.2-1; opens DF-S1.3-1/-2/-3
- **Spec:** §8.1 (R-2.1.5 — record, minting table, lattice, endorsements, monitor checks);
  §8.3 (`VersionedRef.provenance`, the widening-successor publish rule); §8.5 (schema
  ownership); §9.1 (Stage-0 hand-stamps) · ADR-0033, ADR-0034, ADR-0035 (as amended)

## Context
S1.3 lands the §8.1 provenance & authority model. Four placement/shape questions had to be
decided, none free:

1. **Layering vs. identity.** DF-S1.2-1 requires `VersionedRef.provenance` to *be* the
   canonical `ProvenanceRecord` (CC1 — no second record). But `ProvenanceRecord` itself
   carries references (`Derivation.inputs`, `TaintTag` capability refs, attestation anchors).
   If those fields were typed `VersionedRef`, the record embedded in a `VersionedRef` would
   recursively contain the type that contains it — an illegal type and a cyclic crate
   dependency.
2. **Minting gaps at Stage 1.** The §8.1 minting table's `environment` class requires a
   closed-schema value from a closed-world tool *declared in the sealed definition*, and the
   `≤ delegate` participant-claim class requires the Hosting ABI to vouch for the claim.
   Neither surface exists at Stage 1 (the `seal` basis lands here; the definition-graph and
   Hosting ABI wiring are later). `default_authority` must still be **total**.
3. **hh-baseline hand-stamps.** §9.1 allows Stage 0 to hand-stamp `principal`/`definition`/
   `external`, but the baseline had grown its own throwaway `ProvenanceRecord`/`AuthorityClass`
   — a second record type in the tree (a live CC1 violation once the canonical one landed).
   Its three-class order was also *inverted* relative to canonical: `external < definition <
   principal` vs the canonical `external < … < principal < definition` (ADR-0033 D2).
4. **Back-compat for `hh_identity::Provenance`.** S1.2 consumers resolve
   `hh_identity::{Origin, Provenance}`; the swap to the canonical record must be additive
   (CC8), not a path break.

## Decision
- **`hh-provenance` sits BELOW `hh-identity` in the build graph.** Provenance records carry
  *identity coordinates* — `version_id` / content-address `String`s — for every reference
  field (`Origin`'s `*_ref`s, `Derivation.inputs`, `TaintTag`, `AttestationAnchor`). A
  `ProvenanceRecord` never embeds a `VersionedRef`; the typed HIR `Ref<T>` projection lands
  above, at S1.4. `hh-identity` depends on `hh-provenance` and re-exports
  `hh_provenance::{Origin, ProvenanceRecord}`; `pub type Provenance = ProvenanceRecord` keeps
  the old path resolving to the one canonical type (CC8 additive; it *is* the record, never a
  second scheme — CC1).
- **Conservative Stage-1 minting (floors, never coercion).** `default_authority` is total:
  `Origin::tool` mints `external` (DF-S1.3-3 — `environment` awaits sealed-definition
  closed-world declarations and is reachable now only via the `validator` endorsement basis);
  `Origin::participant` mints `unverified` (DF-S1.3-2 — the `≤ delegate` claim class awaits
  the Hosting ABI; unvouched content is the distinct bottom, never coerced into `external`,
  T-LCD-07). These are floors the minting table *rises from* when the surfaces land — not
  new classes, so no dialect bump.
- **hh-baseline is a thin adapter over `hh-provenance`.** The throwaway
  `ProvenanceRecord`/`AuthorityClass` are retired; `provenance.rs` re-exports the canonical
  types and keeps the three hand-stamp helpers, which now mint through the canonical paths:
  `principal()` → `Origin::human(.., Principal)`; `external()` → `Origin::tool` (mints
  `external`, per the DF-S1.3-3 floor); `definition()` → a `human(author)` record carrying a
  self-consistent `seal` attestation at `authority = definition` — the only legitimate mint
  for `definition` (§8.1 #3). Every baseline stamp passes `ProvenanceRecord::validate`.
- **Semantic correction recorded (not a regression):** under the canonical order
  `principal < definition`, the baseline `context_label` meet for a definition+principal
  context now yields `principal` (was `definition` under the retired subset's inverted
  order). This is the *correct* §8.1 semantics — the principal's task text caps the assembled
  context. The `context.rs` test `label_is_principal_join_without_lifted_content` is updated
  to assert `Principal` with a comment citing this ADR; the meet fold's identity is corrected
  to `kernel` (the canonical top).
- **HIR-node/edge carriage deferred** (DF-S1.3-1): AC-R-2.1.5-1's full form needs the HIR/1
  document type (R-2.1.2, S1.4). This ticket lands the record, `require_provenance`/
  `validate` (`MissingProvenance`), the mandatory-provenance event table, and text-leaf
  classification + the opacity report — the executable Stage-1 half.

## Consequences
- Good: exactly one `ProvenanceRecord`/`AuthorityClass` in the tree (CC1, grep-verified);
  authority is derived by the minting table everywhere — the baseline hand-stamps included —
  and every stamped record validates (CC2); `hh-identity`'s widening-publish rule now reads
  the real `AuthorityClass` (DF-S1.2-1 closed); the layering makes the S1.4 typed `Ref<T>`
  projection a pure addition above this crate.
- Cost: reference fields are untyped `String` coordinates until S1.4's `Ref<T>` projection
  (typed linkage is deferred, not lost — the coordinates are the same strings `version_id`
  carries). `ResolveOutcome::Resolved(VersionedRef)` grew past clippy's
  `large_enum_variant` threshold — allowed with a comment (boxing would change the public
  enum's shape for no hot-path gain; the swap is additive).
- The two conservative mints are deferred behaviour, filed as DF-S1.3-2/-3 with their
  unblock conditions; both are *floors* so later rise is additive, not a migration.

## Alternatives considered
- **`ProvenanceRecord` embeds `VersionedRef` (or `hh-provenance` above `hh-identity`).**
  Rejected: recursive type / cyclic crate dependency — a record carried *inside* a
  `VersionedRef` cannot contain one. A parallel "typed record" above identity was rejected
  as a second scheme (CC1).
- **Baseline keeps its own 3-class `AuthorityClass` "because it's throwaway."** Rejected:
  two `ProvenanceRecord` types in the tree is exactly the CC1 violation this ticket exists
  to prevent; the throwaway status does not exempt the invariant.
- **Mint `tool → environment` optimistically.** Rejected: would mint a class the definition
  never declared — authority by location/self-claim (CC2 violation); `external` is the
  honest floor and `validator` endorsement is the designed interim route.
- **Keep `context_label` returning `definition` for the baseline.** Rejected: that would
  require preserving the inverted Stage-0 order inside the canonical enum — falsifying the
  lattice. The corrected meet is the spec's semantics.

## Revisit trigger
- S1.4 lands `Ref<T>`: re-point provenance ref fields at typed refs if the projection
  requires it (still no recursion — `Ref<T>` is a coordinate, not an embedded record).
- The Hosting ABI (Stage 2) or sealed-definition tool declarations land: discharge
  DF-S1.3-2/-3 by extending the minting table — never by adding classes.
