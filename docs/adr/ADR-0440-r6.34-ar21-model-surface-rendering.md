# ADR-0440: AR-21 — the model port renders the compiled `ModelSurface`; durable rendering refs

- **Status:** Proposed
- **Date:** 2026-11-10
- **Ticket:** R6.34 (E2-T0 docs bundle, manifest row 292)
- **Requirement ids:** contributing REQ-XE-103, REQ-XE-109 (governing); REQ-XE-107, REQ-XE-108 (consumed by R6.34's wire-fidelity half)
- **Spec:** `docs/experiments-spec.md` §10.5 row **AR-21** ("Model port renders the compiled `ModelSurface`; durable rendering refs", kind ADR, first needed by E2-T0); §7.3 gap list **G1, G3, G6, G18, G19, G20, G21** and the REQ-XE-103/104/105/106/107/108/109 rows; §7.4 canonicalization note ("what stays unused once G5 closes"); `spec/CANONICAL_SPEC.md` §3.2.2 (the context builder executes the compiled renderer spec — the single-renderer rule); design note `docs/design/38_hir-native-gaps.md` finding F1 (VERIFIED) and Part 2 rows G1, G3, G6, G18–G21 (design label ADR-E2-A — design spellings are proposals; this ADR fixes the record, later rows cite it, never the design note)
- **Rung (ADR-0024 obligation):** architecture record for the E2 block — no RPC, no schema source, no new dependency, no new event class or `RecordKind`, no store/dispatch authority, no spend. The E2-T1+ tickets that consume it land at their own rungs.

## Context

E2 re-verified E1's gap list at `09fe8523` and found six more (G18–G23).
The structural finding (design 38 F1, VERIFIED): the live request is built
by `GatewayModel`'s hand-written renderer
(`crates/hh-embed/src/gateway_model.rs` ~684–902) which never consumes the
`ModelSurface` that `lower_profile`
(`crates/hh-compiler/src/lower.rs` ~127–410) already compiles with
descriptions, input schemas, layout sections, error and result specs and a
transcript renderer. Canonical §3.2.2 requires that the context builder
executes the compiled renderer spec and fills the one
`ProviderRequestPlan` — the hand-written path is a second implementation
of the render contract, a CC1 hazard that deepens with every wire-fidelity
fix. Fifteen of the twenty-three gaps close by making the model port
render the compiled surface (§7.3 G21). Separately, §7.3's replay
invariant (X-04/CC1): replayed assistant bytes must come from the durable
`hh.model_io/1` blobs, never a second store of response bytes.

## Decision

1. **The model port renders the compiled `ModelSurface`.** When a session
   is armed with a compiled `ModelSurface`, the model port SHALL render
   the request — layout sections, `tools[]`, transcript, error and result
   renderings — from that surface (REQ-XE-103). The compiled artifacts
   (`ModelSurface.layout`, `CompiledToolSurface{description, schema,
   error_format, result_render}`, `transcript_renderer`) are the render's
   inputs; no second renderer is written beside them. A session armed
   with no compiled surface renders byte-identically to the pre-change
   `GatewayModel` path — the opt-in rule every closure ticket pins.
2. **Rendering inputs are durable references, never re-synthesized
   bytes.** The replayed assistant turn (G6), provider tool-call ids
   (G19) and verbatim tool-call arguments (G20) are read from the
   `hh.model_io/1` blob the completed row's `response_ref` names — the
   one durable record of response bytes. The armed exec observation's
   model-view rendering (G18) is applied from the capability's
   `ResultRenderSpec` to the raw output behind the observation manifest's
   `raw_output_ref`, and the rendered view's content address is recorded
   on the observation row **before** the request that carries it, so
   replay re-serves the recorded rendering — record rendering, not just
   admission (the ADR-0135-style rule). Payload members added for this
   are additive under CC8's absent-not-null rule; no new event class is
   minted.
3. **Gap coverage.** This record governs §7.3's G1 (system-role layout),
   G3 (`tools[]` from `CompiledToolSurface`), G6 (assistant replay), G18
   (rendered observation + durable rendering ref), G19
   (`id_normalisation`), G20 (verbatim arguments) and G21 (who renders).
   The opt-in `model_port`/`transcript_render` member spellings that
   declare the per-gap choices are fixed by their implementing tickets
   (E2-T1 at R6.34, E2-T2 at R6.35) under this record's single-renderer
   rule; design 38 Part 2's member spellings were proposals.

## Consequences

- R6.35 (E2-T2) arms `GatewayModel` with the compiled surface through the
  existing `hharness_compiler::compile` path — no second renderer.
- R6.34's wire-fidelity members and R6.36's `tools[]`/completion-surface
  work declare choices the surface-bound renderer executes; a definition
  declaring none renders byte-identically.
- G18's plumbing (R6.37) lands the rendered observation's content
  address on the observation row before the carrying request — replay
  reads the recording, never re-executes the renderer on replayed runs.
- The §7.4 C05 canonicalization rule (`stream`/`stream_options` dropped
  downstream only) stays declared but goes unused once G5's `transport`
  member closes (§7.4's own note).

## Alternatives considered

- **Keep patching `GatewayModel`'s hand-written render** — rejected: it
  is already a second implementation beside the compiled `ModelSurface`
  (F1); each fix deepens the CC1 violation §3.2.2 forbids.
- **A parallel renderer crate beside the model port** — rejected: a
  second home for the render contract; the compiled surface is the one
  spec (CC1).
- **Replaying assistant bytes from the ledger row members alone** —
  rejected: the rows carry `args_raw` (canonicalized) and no assistant
  text or provider ids; fabricating the missing bytes would be a second,
  lossy store. The durable `hh.model_io/1` blob is the one response-byte
  record (X-04).

## Revisit trigger

Reopen if (a) the compiled `ModelSurface` proves inexpressible for a
governing REQ-XE-* row (the `UnexpressibleSurface` route — a profile or
spec gap, not a renderer fork), (b) the `hh.model_io/1` frame vocabulary
cannot durably carry a replay input a declared `transcript_render` member
needs (an amendment candidate, never a second byte store), or (c) GATE-G24
refuses AR-24 and the stage-one E2 chain is re-planned.
