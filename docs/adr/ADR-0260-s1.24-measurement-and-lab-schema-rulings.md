- **Spec:** §5h.4 · §5h.6 · §5h.8 · §6.3 · §6.4 · §6.5/§9.2 · ADR-0142/0143/0144 · ADR-0197/0198 · ADR-0202/0203 · ADR-0154…0163 · ADR-0209 D2

  `DebtPolicy`, `SnapshotClaim`, `CompatibilityRecord`, `ExperimentSpec`,

## Context

S1.24 lands the last Stage-1 schema slices before the Stage-3 Lab machinery:
five spec sections' worth of records that must share one canonical
vocabulary with the already-landed kernel planes. At this ticket's start:

- The debt vocabulary existed in three places: `hh_hir::DebtStatus` (a
  3-value interim from S1.4), `hh_compiler::profile::ExpiryCondition`
  (the profile home's spelling) and `hh-ontology` had no debt module at
  all. `AssumptionDebtRecord` was the `/0` ratified form
  (`{rule_id, hypothesis: Text, evidence_refs, owner, expiry_condition,
  removal_test_ref, status}`); §5h.6's `/1` adds the typed hypothesis,
  scope, typed `removal_test`, `debt_class`, `revalidation`, `created_by`
  — and `DebtHomes/1` gives each home a default debt class and a
  required-field policy. The L2 benchmark-conditioning check
  (`BenchmarkConditionedRule`/`C-LCD-4`) was landed in `hh-assembly` at
  S1.9; the L1 held-out predicate and the import-side check were not.
- `ModelDiscoveryClaim` (hh-ontology) carried no snapshot/lineage/
  cutoff members; `applies_to_families` was a name-spelling seam
  (DF-S1.22-3).
- The ledger had `RunKind::Experiment` (landed S1.5) but no manifest
  member carrying the experiment binding, and no `lifecycle.debt.*`/
  `measurement.*` Lab classes.
- No crate owned the Lab-facing records; putting them in `hh-ontology`
  would mix the kernel's home-plane vocabulary with Lab-owned documents
  (CC10), and putting them in `hh-registry`/`hh-compiler` would couple
  the records to services that only cite them (CC5).

## Decision

1. **`hh-lab` is the Lab schema plane** (new persistent crate; deps
   `hh-wire`/`hh-identity`/`hh-provenance`/`hh-ontology`/`hh-hir`/
   `hh-budget` only — no service edges, CC5/CC10). It owns the records the
   Lab authors: `bench.rs` (environment-family/task/suite/validity/split
   records + the import-side `HeldOutInEnvironment` check), `model.rs`
   (`ForeignRef`, `SnapshotClaim`, `CompatibilityRecord`), `experiment.rs`
   (`ExperimentSpec`/`CellPlan`/`RunPlan`/`OrderPlan` + `experiment_id`/
   `run_plan_id` derivation + the closed `RegisterRefusal` sum checked
   against `SpecContext`), `analysis.rs` (the §6.4 records +
   `ComparisonReport`), `debt.rs` (the derived `DebtIndexRow`/`DebtReport`/
   `DebtNotice`/`AssumptionDebtHealth` views — projections, never sources
   of truth). `hh-ontology::lab` owns only the shared *vocabulary* the
   kernel also reads (`EnvironmentFamily`, `SplitLabel`,
   `ContaminationStratum`, `HandleCapability`, `SubmissionKind`,
   `VerifierIsolation`, `EpisodeModel`, `TaskValidityState`,
   `BenchmarkNetworkMode`, `EnvironmentFamilyRecord` — the last because
   `hh-registry` registers it).
2. **The canonical debt vocabulary lives in `hh-ontology::debt`** (CC1/
   CC7): `DebtStatus{active, expiring, expired, retired}`, `ExpiryKind`,
   `ExpiryCondition{kind, value?}`, `DebtClass`, `DeficiencyClass` (12-sum
   incl. `unknown{…}`), `EvidenceKind`/`EvidenceRef`, `EvidenceGrade`
   (derived, never stored), `PredictedEffect`, `ModelSelector`,
   `DebtScope`, `HypothesisSubject`/`HypothesisTyped`,
   `RemovalTest`/`RemovalTestKind` (12 kinds), `RemovalVerdict`,
   `OwnerRef`, `DebtRef`, `DebtHome`/`DEBT_HOMES` (the closed 17-home
   inventory as data), `DebtPolicy`, `Revalidation*`,
   `UnexecutableReason`. `hh-compiler::profile` re-exports; the interim
   `hh_hir::DebtStatus` is replaced by the canonical sum. **Legacy
   spellings decode with a documented mapping:** `open → active`,
   `discharged → retired`, `violated → expired`; a bare expiry-condition
   string decodes as `{kind}`; bare `evidence_refs` strings decode as
   `{kind: source, ref}` (CC8 — old bodies decode, new bodies emit the
   canonical spellings).
3. **`AssumptionDebtRecord/1` is additive on the /0 ratified form.** The
   /0 required members are unchanged (`removal_test_ref` stays the
   ratified member); /1 adds optional `debt_class`, `hypothesis_typed`,
   `scope`, `expiry`, `runway_ms`, `revalidation`, `removal_test`,
   `created_by`, `created_at`, `supersedes`. The per-home required-field
   policy is enforced by `validate_for_home` against `DebtHomes/1` +
   `DebtPolicy`: the `harness_rule.assumption_debt` home is model-scoped,
   so its records additionally require `debt_class`, an instantiated
   `removal_test` and `scope.model_selectors`; a record on an unlisted
   kind is `UnknownDebtHome`.
4. **Removal-test validation splits member-level from context-level.**
   `hh_hir::debt::validate_removal_test` always runs the member-level
   checks (beneficiaries ⊆ scope, mandatory payloads, `InsufficientRunway`
   from `until − created_at < min_runway`, `OwnerUnreachable`,
   well-formedness); the resolver-parameterized checks
   (`UnresolvedTemplate`, `MissingMatchSpec`, `NotARetirementDiff`,
   `UnresolvedProbeRef`, `UnresolvedZeroUseScope`,
   `MissingSplitAssignment`, `UnsealedArtifact`) run only when the caller
   supplies the resolver — `RemovalTestContext::member_level()` supplies
   none. HIR `validate`/`seal` run the member-level half and fail
   `HirError::RemovalTestRefusal` (mapped through `hh-assembly`'s
   `C-KERN-*` mirror); registry admission runs the same
   `validate_for_home` with its own context. Missing/unknown homes map to
   `ConditionedRuleIncomplete`; other refusals stay typed — nothing is
   silently accepted (CC3).
5. **`ForeignRef` is a claim, never a `ContentAddress`** (I-2):
   `{system, digest, label?, provenance}` carries the foreign system's own
   digest spelling verbatim; `SnapshotClaim.weights_digest` and
   `trained_under[]` use it, and `training_cutoff_claim{value?,
   provenance ∈ {provider_stated, inferred, unknown}}` rides the claim —
   the kernel never mints a local address over foreign bytes it does not
   hold.
6. **Deterministic ids are derivations, never authored:**
   `experiment_id = H(canonical(spec − experiment_id))`;
   `run_plan_id = H(experiment_id ∥ arm_id ∥ configuration_version_id ∥
   task_id ∥ replicate_index)` (scheduling/transport fields excluded);
   `suite_id`/`split_hash` over the canonical manifest/splits map;
   `task_id` is the semantic-projection id (canonical record minus
   `foreign`, `instrument.validity/contamination`, `provenance`) so a
   re-imported task keeps its id across annotation churn.
7. **`DebtPolicy` defaults are declared placeholders** per the ADR-0214
   stage-deferral text (the OQ-446-class owner-reachability and
   scheduling parameters are Stage-4+ MUST-data): the schema records the
   full member set `{required_fields_by_home, min_runway,
   hypothesized_max_age, evidence_max_age, warn_within, grace_period,
   max_open_removal_tests, priority, notice_sinks, schedule,
   dead_weight_designs_allowed}` with the proposed defaults recorded as
   data; no runtime consumer exists yet (DF-S1.24-1).
8. **The manifest `experiment` member is the row-key source** (§6.5
   row-key fields at C0): `RunKind::Experiment` runs bind
   `{experiment_id, plan_id, scheduling_policy, reattempt_policy,
   budgets, design_ref, pre_registration_ref, match_spec_ref,
   suite_manifest_ref, leaderboard_targets}` (the two content addresses
   required + pinned); `agent` subject runs carry the all-or-nothing
   `{experiment_run_id, arm_id, cell_id, design_ref?,
   pre_registration_ref?, replicate_index, attempt_no, comparable}`
   binding; other kinds never carry the member — all enforced by
   `RunManifest::validate`.
9. **DF-S1.22-3 is closed:** `MetricDeclaration.applies_to_families` is
   the typed `BTreeSet<EnvironmentFamily>` (canonical spellings
   unchanged — old name-spelling bodies decode, CC8); the registry gains
   `RegistryRecord::EnvironmentFamily` + `resolve_environment_family` so a
   family-scoped metric resolves against a registered record, never a
   bare name.

## Consequences

- The Lab records exist as canonical data *before* the Stage-3 engines:
  `register`/`expand`/estimators/the results store consume declared
  shapes instead of inventing them (the §9 staged-ladder rule — schemas
  at C0/S1, engines at C0/S3).
- Debt is now enforceable at seal: an uninstantiable removal test or an
  incomplete model-scoped record fails `validate`/`register` with a typed
  refusal — the debt ledger is no longer advisory text.
- The vocabulary unification means exactly one `DebtStatus`/`ExpiryKind`/
  `ExpiryCondition` exists in the tree (CC1 verified by construction);
  legacy bodies decode through the documented mapping, so no landed
  fixture or stored record breaks (CC8).
- `hh-lab`'s derived views (`DebtIndexRow`/`DebtReport`) are projections
  over the canonical records — the debt manager (S6.1b) consumes them;
  they can never diverge into a second source of truth.
- Residual seams recorded, not hidden: `ModelProfile/1`'s
  `debt.hypothesis` stays a plain string at the profile home
  (DF-S1.24-3); `DebtPolicy`'s defaults are placeholders pending the
  ADR-0214-gated parameters; resolver-backed removal-test checks need a
  registry/registry-snapshot context the schema plane does not own
  (DF-S1.24-1).

## Alternatives considered

- **Put the Lab records in `hh-ontology`** — rejected: ontology is the
  kernel's home-plane vocabulary (CC10); Lab-authored documents are a
  different ownership plane. The shared *vocabulary* (`EnvironmentFamily`,
  `EnvironmentFamilyRecord`) did land there because the kernel
  (`hh-registry`) reads it.
- **Run every removal-test check at seal** — rejected: the resolver
  checks need registry/snapshot context that does not exist inside HIR
  validation; refusing on missing resolvers would make every
  context-free validation fail (T-LCD-15 — honest `n/a`, not a fabricated
  check). The split keeps seal strict on what is statically decidable.
- **Re-type `ModelProfile/1`'s `debt.hypothesis` to `Text`** — rejected:
  a breaking change to a landed dialect; `hypothesis_typed` carries the
  structured form additively and DF-S1.24-3 tracks unification at
  `ModelProfile/2`.
- **One `RemovalTest` payload shape for all 12 kinds** — rejected: the
  kinds carry genuinely different mandatory members; a closed sum with
  per-kind payload validation is the honest form (CC3 — nothing silently
  optional).
