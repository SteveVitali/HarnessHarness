# ADR-0432: `hh-live-pricing/2` compute rows, the priced §3.10 quote, and the phase spend ledger (AR-14)

- **Status:** accepted (lands with manifest 267/R6.14)
- **Date:** 2026-11-07
- **Ticket:** R6.14 (COST-RECORD + RECONCILE)
- **Amendment register item:** AR-14 (experiments spec §10.5)

## Context

Spec §3.10 makes one compute pricing path: the quote template in integer
µ$ rounded up per line, computed from the declaration and a pinned rate
table (`source` URL + `retrieved` UTC per row — REQ-XB-213). R6.13's
`pre-quote` emitted declaration quantities only (`pricing:
n/a{compute_pricing: R6.14}`); REQ-XD-051 recorded that label as interim.
REQ-XB-217 wants model and compute spend in one phase spend ledger
extending ADR-0363's `SPEND.jsonl` row shape with `kind`, `authority`,
`basis`, `phase`, `window` — with per-kind ceilings (REQ-XH-006).

## Decision

1. **`hh-live-pricing/2`.** `docs/build/reports/live/pricing.json` gains
   a `compute` section: rows `{sku, unit, price_micros, source,
   retrieved}` in integer micro-units — `e2-standard-8` 268040 µ$/h,
   `pd-balanced` 137 µ$/GiB-h, `ipv4` 5000 µ$/h, `egress` 120000 µ$/GiB,
   `nat_gateway` 44000 µ$/h. On-demand rates; no free tier; no
   sustained-use discount. The model table and `cap_usd`/`allocations`
   members are byte-unchanged; `check-live-evidence.sh` accepts `/1|2`.
   A `hh-live-pricing/1` document needs no migration.
2. **The priced quote.** `receipt_lib.py::quote_doc` is the *only*
   compute pricing code path: `hh-compute-quote/1` carries planning,
   bound and dead-man ceilings in integer µ$ (ceil per line, exact
   rational arithmetic), every ceiling term present (restart hours H_rs,
   residual-disk hours h_r, egress labelled `estimated`), the retry and
   carried-artifact-load terms of REQ-XH-118, and the deterministic
   `pq-<16hex>` quote id. `authorization.ceiling_micros` names the
   ceiling verbatim.
3. **`hh-compute-cost/1`.** Written once per window at teardown step 9
   (`scripts/gce-backend/cost_lib.py`), intervals from resource lifecycle
   timestamps (creation from the provision receipt; stop/delete ends
   from the teardown receipt — never run windows), `billable_seconds =
   max(60, s)` per running interval, five lines (instance, disk, IPv4,
   egress, NAT), `attribution.utilization_ppm`, `billed: pending`. A
   rewrite refuses; reconciliation is an appended dated record carrying
   `supersedes_estimate_of` (REQ-XB-215/216).
4. **One phase spend ledger** at
   `docs/build/reports/live/PHASE_SPEND.jsonl` (ADR-0363's home, a
   distinct file — round-4 `SPEND.jsonl` is never rewritten). Row shape:
   ADR-0363's `{ts, ticket, leg, cost_usd, cumulative_usd, record}` plus
   `{type, row_id, kind ∈ {model, compute}, authority ∈ {ollama_usage,
   gcp_billing}, basis ∈ {estimate, billed}, phase, window, supersedes?}`.
   Per phase one `ceilings` row per kind declares the ceiling. Model
   lines draw only on `ollama_usage`, compute lines only on
   `gcp_billing` — a crossing refuses (X-02). A `billed` row supersedes
   its estimate by `row_id` reference; folds take billed where present.
   The ledger also carries the controller-side settlement rows
   `measurement.provider.usage.observed` and
   `measurement.cost.reconciled` (REQ-XC-127; REQ-XC-121) with the
   window id — appended by `scripts/ollama-settle.sh` +
   `scripts/gce-backend/settle_lib.py`, never rewritten.
5. **Codec homes (CC1).** Python `cost_lib.py`/`settle_lib.py` under
   `scripts/gce-backend/` own every row shape above; Rust folds stay
   records-in (`hh-env::admitted_costs`,
   `hh-runner::slot_costs`) over supplied facts — no second spelling of
   the ledger, cost record or quote.

## Consequences

- GCP billing stays the compute authority (ADR-0363 D4): estimates hold
  until an operator billing read appends `basis: billed`.
- `gce-backend.sh teardown` writes the cost record, cites it from the
  receipt's `cost_record` member, and appends the compute estimate row.
- R6.18/R6.30/R6.33/R6.46 consume the quote formula; CAP6.2 folds the
  ledgers; R6.40/R6.47 owe the live settlement act.

## Revisit trigger

Revisit when (a) GCP reprices any pinned compute row (the register
`retrieved` dates are the staleness bound), (b) the first billed
reconciliation appends `basis: billed` rows against these estimates —
the `within|outside` spread then measures the estimate methodology — or
(c) a phase spend leg needs a third `kind` or `authority` value, which
is a new AR item, not an in-place edit.
