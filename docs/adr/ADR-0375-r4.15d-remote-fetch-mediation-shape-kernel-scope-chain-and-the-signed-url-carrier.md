## Context

The GATE-G7-adopted §trust-fields text fixes the *what*: a
`FetchTrustPolicy` MUST-data record, three admission classes, cleartext
refused, `expires` enforced, `bundle.member.fetched` durable before the
member reads `present`, and — the load-bearing clause — "the fetch
itself is a `net_egress` effect under Π mediation (`hh-env` egress
rules; an unmediated fetch refuses typed)". Two design questions the
text does not fix:

1. **Whose run and whose scopes?** `security.egress.decided` is
   minted effect-scoped — its `turn_id`/`model_call_id`/`tool_call_id`/
   `effect_id` must name *open* §5a.2 scopes or the append refuses
   (`ScopeNotOpen`). A kernel-side `kernel.fetch` is not an agent tool
   call: there is no session turn, model call or tool call to inherit.
   The alternatives were (a) mint kernel-spelled scope ids on a
   kernel-owned fetch run, or (b) emit a fetch-shaped audit that skips
   the `security.egress.*` rows entirely.

2. **How does a `signed_url` carrier stay `credential_free_uri`?**
   R-ID-7 refuses credential material in locators — but the class's
   whole point is a URI that carries a signature. The adopted text
   answers "the URI stays `credential_free_uri` — credentials ride
   `hh-secrets` `SecretRef`s at the fetch site / mediated egress";
   the mechanics of that answer needed a spelling.

## Decision

1. **The fetch act rides the real `EgressMediator` on a kernel-owned
   fetch run.** `EmbedService` lazily opens a `purpose = "fetch"` run
   (`RunKind::Fleet` — the same manifest kind `ensure_registry_run`
   spells for kernel-internal runs) holding the kernel's own scope
   chain — `lifecycle.turn.started{kernel-fetch-turn}` →
   `model.call.requested{kernel-fetch-mc}` →
   `action.tool.proposed{kernel-fetch-tc}` →
   `action.effect.intended{Store::effect_id(run, mc, tc, 0)}`, the
   derived §5a.2 spelling. `FetchTransport::leg` mints an attribution
   token bound to that effect id and drives `mediator.handle` for every
   admitted `https:` GET — `security.egress.requested` durable before
   the decision, `security.egress.decided` durable before the wire, the
   decision computed by the *same* `decide_egress` an agent egress
   takes. The scope ids are honest names for the kernel's own fetch
   act — they fabricate no agent attribution because there is none to
   fabricate: `env_handle = "kernel"`, `participant_ref =
   "hh-embed.fetch"`.

2. **The declared `FetchTrustPolicy` lowers to a `mediated`-mode
   `ContainmentPolicy`.** One `allow` rule per `admitted_origins[]`
   entry (`host`/`host:port` parse mirroring `origin_admitted` —
   `host:junk` stays a never-matching exact host, fail-closed), the
   `signed_url` carrier's wildcard GET rule only when the class is
   declared, `default_unmatched = deny`, `non_public_destinations =
   allow_listed` — the same containment floor an agent run's net
   section would produce, derived, never invented.

3. **`trust` is supplied as the verbatim policy document on
   `kernel.fetch`.** The record's `version_id()` is the coordinate a
   bundle's `resolved_dependencies` pins; the op takes the document
   itself (the fetch site resolves its pin). Absent `trust`, every
   remote location refuses `policy_absent` — its refusal row still
   lands on the fetch run; the wire machinery is never built. Pool legs
   are unaffected and need no policy.

4. **The `signed_url` carrier's placeholder is the one safe form.** A
   credential-ish query parameter whose value is an `mh_secret:`
   placeholder stays `credential_free_uri` (R-ID-7's letter and intent:
   no credential material in the locator — the *coordinate* is not the
   *value*); a literal value refuses `transport_refused` before policy
   is even consulted. The mediator's sentinel drain now substitutes
   `path` and `body` as well as headers — the spellings
   `collect_sentinels` already detected — so a placeholder riding a
   presigned query is resolved by the broker at the wire and never
   forwarded as a literal sentinel.

5. **`content_addressed` admits, then refuses transport-typed.** The
   class is adopted (`ipfs:`/CID-class locations classify and pass the
   class gate) but the ADR-0365 TLS scope carries no IPFS transport —
   the leg answers `transport_unsupported` honestly, ledgered like
   every other attempt (the ticket's own "typed `Unsupported` if out"
   arm). Adding an IPFS transport is a future ticket's ADR-scoped
   admission, never a silent fabricate.

6. **`require_ledgered_arrival` is honored as declared.** The adopted
   MUST-data carries `true`; a `false` declaration parses but the rows
   are still appended when a run exists — the member's deposit only
   ever follows the append attempt, never precedes it.

## Consequences

- The fetch's audit trail is *the same shape* as every other mediated
  egress — `security.egress.requested/decided` rows on the fetch run,
  `bundle.member.fetched` per attempt, durable before the member reads
  `present`. A reader folding `security.egress.*` sees kernel fetches
  without a new event vocabulary.
- The kernel scope-chain ids (`kernel-fetch-*`) are reserved spellings
  on the fetch run — they collide with nothing (scope ids are
  run-local) and read honestly in the audit.
- `FetchTrustPolicy.require_ledgered_arrival = true` makes a ledger
  append failure refuse the op with the bytes undeposited — the
  durable-before-visible rule fails closed.
- The `signed_url` placeholder exception narrows R-ID-7's sweep exactly
  at the `mh_secret:` spelling — literal credential values still refuse
  unconditionally.
- ~3,013 changed lines excl. fixtures/generated vs the 900 budget —
  recorded as a Deviation in the run ledger (the seventeenth
  consecutive overrun — GATE-G6 accounting).

## Alternatives considered

- **Fetch-shaped audit without `security.egress.*` rows** (the run
  ledger's earlier sketch): rejected — the adopted text's "Π mediation"
  clause wants the decision itself on the one decision path
  (`decide_egress` + durable requested/decided), not a parallel
  spelling a reader must learn to fold; a fetch-audit without them is
  the unmediated shape the text refuses.
- **`record_run_id` param naming the caller's run**: rejected — a
  caller-supplied run invites ledgering a kernel act onto an agent
  run's audit partition (attribution confusion); the kernel-owned
  `purpose = "fetch"` run is the honest home, lazily created and
  re-leased on expiry like `ensure_registry_run`.
- **Refusing `require_ledgered_arrival: false` in `from_json`**:
  rejected — the member is a bool; coercing `false` to `true` rewrites
  the site's declared document. Honored as declared; the append is
  still attempted, never skipped.
- **`localhost` in the hermetic origin spelling**: the test-CA fixture
  dials `127.0.0.1` (the cert's IP SAN) — `localhost` resolves `::1`
  first on this host; the IP-SAN spelling is the faithful fixture
  (the same arm `tls_ip_san_verifies` proves).

## Revisit trigger

Revisit (1) if a caller-legitimate shape emerges where the fetch act
should attribute to the *calling* run's chain (e.g. an env-side driver
fetching under a session's tool call — the `LocationFetcher` seam
already admits it); revisit (2)/(4) if `signed_url` carriers need
`accepted_signers`-verified attestations over the location set (the
adopted "may" — the member is parsed and carried, never consulted); and
revisit (5) if an IPFS/content-addressed transport is admitted by a
future ADR (the `transport_unsupported` arm is the standing refusal).
