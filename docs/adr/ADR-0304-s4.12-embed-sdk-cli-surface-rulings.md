# ADR-0304: S4.12 `hh-embed/1` SDK + CLI surface rulings

- **Status:** Accepted
- **Date:** 2026-09-28
- **Ticket:** S4.12
- **Requirement ids:** R-2.11.4 (AC-R-2.11.4-{13,15}), R-2.11.1
  (AC-R-2.11.1-{13,15})
- **Spec:** §7.1 (CLI/serving surface, D-2 notification sink), §7.4
  (SDK/embedding contract); ADR-0177 D10 (relower), ADR-0173/0174
  (`serve`), ADR-0098 (`acp`)

## Context

S4.12 completes the `hh-embed/1` embedding contract's C1 item and
lands the CLI's remaining surface verbs (`serve`, `acp`,
`leaderboard *`, `profile *`, `async`/`defer`, `participant`) as
pure contract clients. The rulings the slice needed: how unattended
defer/detach is carried on the contract, how the opener's contract
descriptor is bound, how registry-backed profile records feed
compiler resolution, how `lab.serve` produces surface artifacts, and
how `set_coordinate` orders its durable record against the applied
change.

## Decision

- **D1 — `--async`/`--defer` lower onto
  `OpenSpec::New.notification_sink{kind:"file", path}`; the durable
  rows are the authority, the sink file is a derived view.** The CLI
  flags carry only the sink path; `open_session` validates the sink
  shape kernel-side (`crates/hh-embed/src/open.rs`), so a malformed
  sink refuses before a session exists. Each successful session call
  sweeps the durable `security.permission.*`/`lifecycle.run.suspended`
  rows since `sink_seq` to the sink file (`crates/hh-embed/src/
  service.rs` — at-least-once, never the ledger). A session the
  kernel cannot answer (`CannotAnswer`/unattended ask) defers onto
  the sink rather than blocking: `hh` exits with the `deferred`
  class, the run stays live, and the sink file is the resume surface.
- **D2 — `open_session.contract_json` is an opaque, contract-carried
  surface descriptor.** The additive member (AC-R-2.11.4-15) is
  recorded verbatim on the session, surfaced on `describe`'s session
  row, and never interpreted — the opener binds it, the kernel does
  not parse it.
- **D3 — `model_profile`/`profile_test_report` are opaque registry
  record kinds decoded through the one `RegistryStore`.** The
  registry admits both kinds behind the same canonical envelope +
  `trust_record_ref` admission every other record obeys (no
  profile-specific bypass). Compiler-side resolution reads them
  through the single `RegistryProfiles`/`ProfileView` lens
  (`crates/hh-embed/src/bundle_ops.rs`): pinning `{profile_ref:
  <coord>, pinned: true}` extracts the coordinate from the canonical
  HIR shape, and linking enforces a registered passing
  `ProfileTestReport` (`ProfileUntested` otherwise — never a silent
  fallback).
- **D4 — `lab.serve` lowers through the kernel path; surface
  artifacts are compiler-lowered members.** The op decodes the
  bundle and lowers its `target:<t>` member via `hh_compiler`
  (`crates/hh-embed/src/bundle_ops.rs`) — `hh serve` is a verbatim
  pass-through (`hh → lab.serve`), never a second lowerer. `hh acp`
  takes the `lab.serve{target:acp}` artifact and drives a session
  through `hh-acp::EmbedDriver` — an `hh-embed/1` client over stdio
  transport (`crates/hh-acp/src/embed.rs`, `transport.rs`) — so the
  ACP surface speaks the same contract every surface speaks.
- **D5 — `set_coordinate` is durable-before-visible.** The
  `model` coordinate resolves through the registry
  (`UnknownCoordinate` — code 1602, additive — for an unregistered or
  revoked value; any other coordinate name is the same typed
  refusal, never coerced to a default). The §3.2.2 relower re-runs
  stages 3–5 under the new profile while re-checking `runtime_plan`
  identity (a divergence is `PlanError`), issues a new
  `bundle_id`, and `model.surface.relowered{old_bundle_id,
  new_bundle_id, old_profile_ref, new_profile_ref, dropped_items[],
  rewritten_items[], reason}` is minted *before* the coordinate takes
  effect — the ledger row is the authority the next model call reads.
  The new bundle member is pool-addressed so `kernel.bundle`/
  `get_artifact` resolve it.

## Consequences

- Every external surface (CLI, ACP driver, MCP lab, web) is a client
  of the one `hh-embed/1` contract; no surface carries its own
  ledger path or its own lowerer (CC1/CC7).
- The sink-file semantics make defer/detach a delivery detail, not a
  state fork — a crash after `deferred` loses nothing the ledger
  doesn't already hold.
- `set_coordinate`'s event-first ordering means an interrupted
  relower leaves a consistent record: either the event exists (and
  the bundle member resolves) or the coordinate never applied.
- DF-S3.5-1 closes: `lab.assembly.compile` is `implemented: true`
  over both bindings with the canonical `CompiledBundle` codec.

## Alternatives considered

- **Client-side sink-file writes** — rejected: a surface-owned
  delivery path would let the file diverge from the durable rows
  and would bypass kernel validation; the sweep-from-ledger model
  keeps one authority.
- **A second coordinate grammar for `set_coordinate.value`** —
  rejected: the op accepts the coordinate string or the
  `profile_binding` value shapes verbatim; minting a third spelling
  would split resolution into two grammars (CC10).
- **Coercing unknown coordinates to a default profile** — rejected:
  a silent substitute widens what the caller asked for and violates
  T-13; `UnknownCoordinate` is typed and honest.
- **Driving ACP through a kernel-side session helper** — rejected:
  the driver is records-in/records-out surface code (K-2); putting
  it kernel-side would make `hh-embed` depend on a surface concern.

## Revisit trigger

Reopen when (a) a non-`file` notification sink kind is declared
(`sink:` scheme extension), (b) `contract_json` needs kernel
interpretation (a contract-negotiation arm), (c) a second
`set_coordinate` coordinate name is admitted (the match arm and the
`UnknownCoordinate` boundary grow), or (d) `lab.serve` targets need
per-target lowering policies beyond the single `target:<t>` member
path.
