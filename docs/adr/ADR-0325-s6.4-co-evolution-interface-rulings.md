## Context

S6.4 lands sub-stage 6d — the
co-evolution interface, the final
Stage-6 slice. The governing
invariant is absolute: HarnessHarness
never trains, loads, merges,
quantizes, or serves weights; training
is a foreign participant reachable
only through claims and records. The
run had to rule on (a) what material
a `training_export/1` may carry and
what a typed loss row names, (b) how
an imported `SnapshotClaim` binds
without ever pinning, (c) where the
reverse debt sweep lives and what
a model-conditioned record owes at
seal, (d) how the co-evolution cycle
orchestrates without becoming a new
run kind, (e) how consolidation is
proven without becoming an applied
diff, and (f) the interface's own
debt record under the assumption-debt
discipline it exports.

## Decision

- **D1 — the export is a pure
  projection; losses are typed rows,
  never drops.** `project_training_
  export(run, envelopes, policy, ctx)`
  is a `&[Json]`-in fold (no
  `hh-ledger` edge — records-in/
  records-out, AC-R-2.9.8-1). Samples
  bind `input_digest`/`output_digest`
  + a `RewardRecord` per admissible
  class (`measurement.metric.emitted`,
  `measurement.oracle.metric.emitted`,
  `measurement.oracle.verdict`,
  `oracle.verdict`); every member the
  policy cannot express lands a loss
  row (`no_slot`/`unavailable`/
  `narrowed`/`truncated`/`redacted`),
  never a fabricated digest or a
  silent skip. Held-out/private rows
  and a reasoning-reading critic
  reward source are typed refusals
  (`HeldOutInExport`,
  `InadmissibleRewardSource`), and a
  corpus-reader subset violation is
  `ReaderViolation` — the export can
  only *narrow*, never widen (I-0).
- **D2 — import never pins; the
  reverse sweep is a records-out
  partition.** `import_snapshot`
  mints `status: reported` /
  `pinned: false` / `imported: true`,
  produces `trained_under` (named
  pairs) + `unknown` (every other
  sealed definition) compatibility
  rows, and collects `scoped_rules[]`
  — the debts whose selectors the
  claim's snapshot intersects — as
  sweep inputs. `post_import_sweep`
  partitions every scoped debt:
  covered ⇒ `expiring` with the
  imported snapshot as evidence;
  uncovered ⇒ `lifecycle.debt.
  removal_test.scheduled`; unscoped
  ⇒ `unchanged`. The manager mints
  the rows (`kind: post_import`,
  never cadence) and reports
  `entry_not_projected` honestly.
  `guard_at_bind` confines
  unknown-compatibility evolution
  arms to `exploratory` —
  `CompatibilityBroken` refuses
  outright (`ExploratoryOnly` is a
  refusal, not a downgrade).
- **D3 — a retrained-snapshot pin
  owes the `model_version_change`
  expiry + a covering selector.**
  `validate_removal_test` treats an
  evolution-origin or
  `model_conditioned` record without
  `scope.model_selectors` — or
  without the `model_version_change`
  expiry in either the ratified or
  additive member — as
  `missing_snapshot_scope`
  (AC-R-2.9.8-12), and `check_
  retrained_pin_scope` refuses the
  campaign-side pin as
  `ConditionedRuleIncomplete`. The
  pin's debt is what makes a
  generation change observable —
  ADR-0194 D6 landed as an
  executable seal-time check.
- **D4 — the cycle is a sidecar over
  ordinary campaigns; budget is
  `matched_total`.**
  `CoEvolutionCycleRecord`/`Cycle
  Driver` deposits/restores through
  LabDocs — no new `run_kind`,
  registry kind, design kind, or
  event family (CC7). Phase order is
  the closed
  `harness_search → weight_update →
  re_evaluation → consolidation`
  sequence (`IllegalPhase` on any
  deviation); harness phases carry
  real `SearchBudgetRecord`s while
  weight phases declare
  `compute_claim{confidence:
  reported}` — declared, never
  charged. `cycle_next`/`cycle_stop`
  arbitrate by the policy's
  `switch_rule`/`max_cycles`/
  `broken_policy`.
- **D5 — consolidation is a view
  + a proven retirement, never an
  applied diff.** `consolidation_
  candidates` partitions the
  campaign fold into scoreable
  candidates and the closed
  never-consolidate set
  (judge-calibration, task-only,
  safety-gated/veto, terminal,
  incomplete-debt); `cycles_active`
  counts the durable prefix's
  `active` transitions — never a
  caller assertion.
  `consolidation_verdict` yields
  `consolidated`/`partially_
  consolidated` only when the
  target, retention, and family
  reports all pass on the
  *post-training* snapshot —
  `MissingComparisonReport` when
  evidence is absent — and
  `consolidation_retirement_record`
  shapes the `RetirementRecord` the
  R-2.9.6 human-sealed `retire`
  consumes (R-2.9.5 retirement stays
  the only applied mutation).
- **D6 — `lab/org-policy-v1` is a
  `matched_cap` recipe; every fleet
  default carries its removal test.**
  The exemplar pins full-factorial
  `MatchSpec`s over
  `tokens.*`/`approvals.requested`/
  `time.human_wait_ms`/`spend`/
  `message_human`, held-out split
  binding, pinned pricing, and
  instrument-charged simulated
  responders (`charged_to =
  instrument`; AC-R-2.12.6-12's
  T-LCD-14 leg). `fleet_default_
  debt_records` mints one
  `hypothesized` record per default
  (`defer_with_escalation_chain`,
  `foreground_cascade`,
  `continuation_delay_ms`,
  `stall_timeout_ms`) with the
  recipe's `retirement_experiment`
  template and an honest unbound
  `until` when the caller supplies
  no expiry — a missing cadence is
  honest data, never a fabricated
  bound.
- **D7 — the interface carries its
  own debt record with the
  null-trainer removal test.**
  `interface_debt_record` is
  `model_conditioned` on the caller-
  named model generation:
  `model_version_change` expiry, a
  `range{family, *}` selector the
  post-import sweep covers, and a
  `conformance_run` removal test
  naming the null-trainer round-
  trip — the spec-debt register's
  ADR-0202/0203/0204 rows landed as
  an executable record
  (AC-R-2.9.8-13). The `NullTrainer`
  is the conformance fixture —
  claim-shaped, `method:
  "null_trainer"`, declared spend —
  the only trainer the interface
  ever meets in-tree.
- **D8 — the surface is seventeen
  schema ops behind one tier gate.**
  Every `lab.coevolution.*` /
  `lab.org_policy.*` op and
  `lab.debt.post_import_sweep` is
  `experimental` +
  `serves_measurement`-gated on the
  `hh-embed/1` boundary; a
  `--no-default-features` build
  keeps every op declared (CC7) and
  answers `Unsupported{by:
  "tier-c4"}` — the `check-
  removability` S6.4 stanza runs
  both legs (the no-features test
  + the schema-persistence walk).

## Consequences

- No weights-shaped member exists
  anywhere: exports carry digests
  and references; the import is
  claims-only; `weights_digest` is a
  `foreign` claim throughout (N9).
- `expiry_condition =
  model_version_change` on a
  model-conditioned record is now a
  seal-time requirement — pre-S6.4
  records that only asserted the
  class must either carry selectors
  or ride the `unclassified` class.
- The cycle is auditable end-to-end
  with zero new event classes: its
  evidence is the existing
  `ComparisonReport` vocabulary over
  ordinary experiments.
- Every fleet default is now debt-
  backed — a default retained past
  its record's expiry without the
  recipe's verdict is a legible
  `expired_used` condition (T-LCD-05).
- The co-evolution tier removes
  cleanly: `--no-default-features`
  compiles, the ops stay declared,
  and the three no-tier legs assert
  the `Unsupported` refusal.

## Alternatives considered

- **A real (fixture-provider)
  trainer in-tree:** rejected — the
  `NullTrainer` proves the full
  export→import→sweep loop without
  pre-deciding a provider adapter a
  later surface ticket owns (CC10);
  a live trainer round-trip is
  operator/external work, not an
  acceptance leg the ticket names.
- **Consolidation as an automated
  `HirDiff` apply:** rejected —
  ADR-0204's design is proposal →
  retirement experiment → human
  seal; auto-applying would make the
  least-reversible leg the least
  governed.
- **Cycle as a new `run_kind`:**
  rejected — a dedicated kind would
  fork the ledger's event taxonomy
  for what is orchestration metadata;
  the sidecar keeps every phase an
  ordinary, comparable campaign
  (CC7/CC9).
- **Sweep inside `import_snapshot`:**
  rejected — the import is a pure
  record fold; the manager owns the
  mint/write path so `kind:
  post_import` attribution and the
  `lifecycle.debt.*` classes stay
  one-owner (CC1).

## Revisit trigger

- Reopen D1 if `training_export/2`
  needs member kinds the loss
  vocabulary cannot name — the
  closed refusal/loss set extends,
  never narrows.
- Reopen D3 if the registry learns
  a second expiry trigger for
  model-scoped claims — the two
  member shapes (`expiry_condition`
  vs `expiry.condition`) must stay
  in lockstep.
- Reopen D5 if consolidation gains
  a non-retirement discharge path —
  the verdict's proof shape is
  bound to the retirement kind.
- Reopen D8 if the tier split
  changes — the schema-persistence
  stanza asserts CC7 for exactly the
  seventeen ops landed here.
