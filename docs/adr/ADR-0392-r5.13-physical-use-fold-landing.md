## Context

PADR-R5-2 B.1 item 4 admits: "physical incurred/billed use and unknown
exposure persist separately from logical scope totals; logical reversal
does not replenish a physical ceiling; unknown bounds/exposure refuse
enforced matching and unsafe dispatch." B.3 fixes "no new primary
dimension" and requires propagated leaf/ancestor copies to count once
under the existing scoped Account deduplication, in experiment/results.
B.5 adds: recovery settlement is idempotent — duplicate/recovery
settlement counts once; no replenished physical capacity after logical
reversal. The landed baseline had no physical-use view at all: `totals`
excludes reverted-effect charges (a *logical* reversal), and both
consumers (`hh-experiment::consumed_vector`, the hh-results
`consumption` fold) summed every `control.budget.consumed` row — the
propagated ancestor copies of one charge were counted per node, a real
double count whenever a subject run carried a funding slice. The
landing choices below are this ticket's owned decisions inside the
admitted semantics.

## Decision

1. **The physical-use view is computed by the owning fold, never a
   stored counter.** `BudgetTree::physical_use` rebuilds `PhysicalUse`
   from `charges_by_source`, `spend_rows` and the new
   `unknown_exposures` fold state — the same rebuild equality as every
   other projection (durable rows in, view out; `Account::physical_use`
   delegates). Nothing is appended, no event class or wire member is
   added.
2. **Each `(source_event, dimension)` charge counts once at its
   leaf-most node.** Within one charge batch the propagated ancestor
   copies carry identical `amount`; the leaf-most row — the budget that
   is an ancestor of no other row's budget in the group — is the
   canonical copy, exactly the rule `Account::totals` applies. Replayed
   folds are idempotent (`charged`/`charged_nodes`); a repeated
   reconcile (`charge` with the same `(source, dim)`) is an empty
   no-op, so the physical view never double-counts a retried or
   recovered settlement — execution cost transfers once.
3. **`incurred` applies no revert exclusion.** `totals` excludes
   reverted-effect charges by projection — the *logical* reversal the
   spec names; the physical view keeps them: physical incurred/billed
   use survives logical reversal and `released`/`released{completion}`
   rows never subtract it (physical capacity is monotone, never
   replenished by release or refund-like rows).
4. **Unknown exposure is a typed list, never a numeric zero.** The fold
   reads the durable terminal call rows: `model.call.completed` whose
   `usage.available` is not `true` (including a missing `usage` member —
   conservative) and `model.call.failed` carrying no `usage` member are
   `UnknownExposure{model_call_id, event_id, reason}` rows
   (`usage_unavailable` / `ambiguous_failure`), deduplicated on the
   terminal row's `event_id`. They are never summed into `incurred` —
   an ambiguous response cannot turn unknown into zero.
5. **Subject and instrument stay separate.** `incurred_by_charged_to`
   stratifies `incurred` by R-ACC-3's closed `charged_to ∈ {subject,
   instrument}`; instrument charges never merge into the subject
   stratum, and each run's tree folds only its own rows — a separate
   instrument run/Account (R5.11) shares nothing.
6. **`billed` is the deduplicated spend view.** `billed_micro_units`
   sums `measurement.cost.attributed` micro-units per currency over the
   already deduplicated `spend_rows` fold (`(source_event, spend)`);
   `confidence`/`provenance`/`coverage` stay on the `SpendRow`s —
   preserved beside the view, never coerced.
7. **Consumers deduplicate on the Account's own key.** `hh-experiment`'s
   `consumed_vector` and the hh-results `consumption` fold count keyed
   `control.budget.consumed` rows once per `(source_event.event_id,
   dimension)` — the same dedup key the Account's `is_charged`
   idempotency uses. Rows without `source_event` (pre-R5.6 fixture
   shape) count individually — they are already the one-row-per-charge
   form, so legacy projections are unchanged.
8. **Over-reservation counts in full.** An actual charge above the
   reservation claim is physical use in full (`over_reservation`
   stays flagged on the row's attribution), never clamped to the claim
   and never refused after the fact.

## Consequences

- The owner fold now exposes logical capacity and physical use as
  separate reads (`remaining`/`check`/`totals` unchanged and compatible;
  `physical_use` additive) — R5.14's pending consumers, R5.19's enforced
  matching and R5.23's population can read the deduplicated physical
  view through owning records rather than re-deriving it (no runner-side
  ledger).
- `BudgetTree::fold` reads two more durable classes
  (`model.call.completed`/`model.call.failed`) — projection-only reads;
  module docs updated. No new home-plane or event class (CC10).
- `consumption.dimensions` and `budget_utilization` now report the
  charge, not the charge × path depth — a bug fix inside the admitted
  dedup semantics, not a contract change; rows without `source_event`
  behave exactly as before.
- Unknown exposure is *surfaced*, not enforced — dispatch refusal under
  unknown/unfunded exposure is the R5.19 predicate (prepared-call
  ordering), explicitly owed there.

## Alternatives considered

- Folding `model.call.attempt.*` rows as additional unknown-exposure
  sources — rejected: the terminal row is the call's usage authority;
  attempt rows are sub-records of the same call and would double-count
  the one exposure.
- Treating a `model.call.failed` *with* usage as incurred without a
  charge — rejected: `incurred` is the Account's charged record (B.3
  keeps use/dedup facts under `control.budget.*` +
  `measurement.cost.attributed`); an uncharged known usage is the
  accountability report's orphan check, not a second physical source.
- Counting physical use at the *root* (the aggregate node) instead of
  leaf-most — rejected: `totals`' leaf-most rule is the established
  dedup convention; the amounts are identical either way, and leaf-most
  preserves charge-site attribution (`charged_to`, budget scope).
- Subtracting releases/refunds from `incurred` — rejected outright:
  the admitted text forbids replenished physical capacity from reversal
  or release.

## Revisit triggers

- If R5.19's enforced matching needs physical exposure to *refuse*
  dispatch (not merely expose it), revisit the read-only view decision
  (Decision 1) — the view is the owning record such a check would read.
- If terminal call rows gain further usage-ambiguous states (e.g. an
  `unknown`/`in-flight` class or a probed ambiguity distinct from
  failed-no-usage), revisit the two-class unknown fold (Decision 4).
- If a future charge path emits unequal `amount`s for one
  `(source_event, dimension)` across propagation nodes, revisit the
  leaf-most count-once rule (Decisions 2, 7) — it assumes the batch's
  copies are identical, which `Account::charge` guarantees today.
