## Context

The H-allow re-proof loop (Wc → Wc8) diagnosed seven machinery defects one full evidence window at a time. Each evidence window is 5–8 h and ~38 oracle trials, its readout offers only `run | not_run`, and evidence rules forbid in-window fixes — so every ordinary HTTP-proxy defect cost a window plus a gate, roughly a day of wall time each (the diagnosis `docs/build/planning/2026-11-15_hallow-diagnosis.md` §1.3–1.4). The debugging instrument was the evidence window itself; the defects are the kind a real `apt`/`curl`/`uv` client run through the mediator exposes in minutes.

## Decision

A new window class `smoke` is admitted (amendment row A1):

- **$0 model** — `model_line: none`; no `deliver-secret`, no model key in-window, no metered calls (REQ-XB-219 verbatim).
- **Compute under a gate envelope** — GATE-G28i records the envelope: up to 3 smoke windows, each ceiling ≤ 1,250,000 µ$ by the §3.10 formula re-minted from the live rate table, Σ ceilings ≤ 3,500,000 µ$. Each smoke's declaration and quote is appended to the readout under the envelope before that window's PROV; a quote outside the envelope stops for a separate operator answer.
- **In-window code changes permitted** (R-10) — the runner may be rebuilt in-window from commits on the smoke branch; the PROV runner-commit match applies at provisioning to the declared starting commit; every in-window rebuild records its commit and the sha256 of each rebuilt binary in the smoke record; the REQ-XC-330 carried-binary sha256 pin is waived for smoke windows only and never for evidence windows; every in-window change lands with its regression before Wc9, and Wc9 runs on one declared, pinned commit.
- **Results are labelled** "non-evidence smoke (internal; never re-proof evidence)" — never folded into `hh-reproof-packet/1` or `hh-reproof-register/1`, never cited as re-proof or parity evidence, never an input to the frozen-list outcome.
- **Evidence windows keep every existing rule** — no in-window fixes, `retry_trials: 0`, typed outcomes, never rescued.

## Consequences

R6.45l's loop (≤ 3 windows on the exact window recipe, H-allow r = 1 on `prove-plus-comm`, `torch-tensor-parallelism`, `query-optimize`, plus `pytorch-model-cli` iff epoch-4 is minted, and H-pub `query-optimize`) iterates inside its D: diagnose from the cell report, verifier streams and mediator store; patch on the smoke branch; rebuild only the affected binary; re-run only the affected cell. Every in-window patch must land a hermetic regression that fails without it before Wc9, and join the conformance leg where real-client-shaped. Smoke records live at `docs/build/reports/smoke/` under the A1 label with PHASE_SPEND rows `window: smokeN`. The class buys debugging speed without touching the evidentiary value of the Wc line.

## Alternatives considered

- **Keep using evidence windows for debugging** — the recorded cost driver: each defect a full window plus a gate. Rejected by the ruling.
- **Relax evidence-window rules (in-window fixes on Wc9)** — destroys the evidentiary value the class separation protects; R-10's waiver is smoke-class only. Rejected.
- **Fix forward with no window at all** — the defects only manifest under the real recipe (real mirrors, real clients, real timing); hermetic fixtures missed seven of them. Rejected.

## Revisit trigger

Revisit if a smoke result is ever proposed as evidence (the class forbids it — a new ruling would be required), if the envelope needs more than 3 windows or a fourth ceiling class, or if the smoke/evidence boundary needs to move (e.g. an in-window change proposed without a landed regression).
