# ADR-0377: L4.2 standing rows converted to maintainer policy — the trigger classification homes become BL-47/BL-48 index rows

- **Status:** Accepted
- **Date:** 2026-10-22
- **Ticket:** L4.2
- **Requirement ids:** BL-41 · BL-42 · BL-43 · R-2.12.4 (governance
  half) · the 2026-10-20 standing-rows ruling ("Convert to maintainer
  policy" — `docs/build/LEDGER.md` decision table)
- **Spec:** none — a repository-policy act, not a contract change
- **Rung (ADR-0024 obligation):** non-contract — build-memory and
  maintainer-policy record; no runtime surface.

## Context

The 2026-10-20 launch re-charter ruling converted the three standing
backlog rows to maintainer policy: BL-41's write-integrity rules
(LEDGER-OF-1…6), BL-42's quiet/dormant revisit-trigger catalogue and
BL-43's fired-and-answered catalogue. The three rows close
`converted-to-policy`; the policy lands in `MAINTAINING.md` +
`GOVERNANCE.md`, and the trigger catalogue becomes the generated,
drift-checked `docs/adr/REVISIT_TRIGGERS.md`.

One mechanics problem needed an owned decision: `check-backlog.sh`
(BM-RECON-01) requires every live ADR id to appear in exactly one
`sources` cell on a non-`closed` row (`home-closed`). BL-42/BL-43's
`sources` cells are not merely notes — they are the catalogue's
classification authority (the ticket: generated "from the ADRs'
`## Revisit trigger` sections + BACKLOG classification"). Closing the
rows with the ids still on them would fail the checker 129 times over.

## Decision

- BL-41, BL-42 and BL-43 flip to `closed` with dated
  `converted-to-policy` landings citing the ruling row and the policy
  files. BL-41's LEDGER-OF sources are not checker-gathered ids, so its
  cells stay as the discharged-record provenance.
- The classification authority does not die with the rows: two new
  standing rows are minted as pure index homes — **BL-47** carries the
  quiet-conditional set, **BL-48** the fired-and-answered set. Both are
  `accepted` (acknowledged standing state, never debt): they exist
  because the checker requires every live ADR id exactly one non-closed
  home, and because the generator reads the class from the home row.
  They are the catalogue's backing index, not owed work — their
  obligation is MAINTAINING.md's triage procedure, which no ticket waits
  on. The fired-unanswered class needs no index row: those ids stay
  homed on the rows that own their residuals (the row-bound convention).
- `MAINTAINING.md` §"ADR revisit triggers" + §"Spec-debt revalidation
  (RK-06)" carry the converted policy; `GOVERNANCE.md` carries the
  decision-authority half (R-2.12.4's governance face).

## Consequences

- `check-backlog` stays green with the three rows closed — every live
  ADR id still has exactly one non-closed home.
- The catalogue is a projection, never hand-maintained:
  `scripts/gen-revisit-triggers.sh` reads each ADR's `## Revisit
  trigger` plus the BL-47/BL-48/other-row classification, emits
  `docs/adr/REVISIT_TRIGGERS.md`, and CI drift-checks it.
- "No standing debt rows at launch" reads as: no row obligating
  outstanding work. BL-47/BL-48 are index state; R4.16's reconcile may
  still re-verify that claim at closure.
- A maintainer who adds or re-homes a trigger updates a `sources` cell
  and regenerates — the classification act is a backlog edit, the
  readable artefact stays derived.

## Alternatives considered

- **Keep BL-42/BL-43 `accepted` with converted-to-policy notes** — the
  ticket's AC says `closed`; `accepted` would leave the debt rows open
  under a kinder status.
- **A single index row holding both sets** — loses the class: the
  checker reads only `sources` cells, so the quiet/fired-answered split
  needs two homes.
- **Teach `check-backlog.sh` a closed-home exemption** — the checker is
  the build-memory contract, not a ticket-local file; weakening it to
  fit this ticket would falsify the contract for every future build.
- **Fold the classification into the ADR files** — ADR bodies are
  frozen once landed; a re-home could never be recorded there.

## Revisit trigger

Reopen if `check-backlog`'s source-home contract is ever revised so
that live ADR ids need no backlog home (e.g. a dedicated index column or
a checker that reads the generated catalogue directly) — BL-47/BL-48's
index rows would then be pure ceremony and can fold. Also reopen if the
fired-unanswered set is given its own standing index row (today it is
the row-bound class by construction).
