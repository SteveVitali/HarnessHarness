# ADR-0218: S0.1 schema-export → codegen → drift-check pipeline

- **Status:** Accepted
- **Date:** 2026-09-15
- **Ticket:** S0.1
- **Requirement ids:** R-2.11.4⁰ᵃ, R-2.12.3 (program)
- **Spec:** §7.4 (Contract identity; ADR-0178 D2), §10.6 (S2 boundary slice); CC7; ADR-0050 (e)

## Context
CC7 (single schema source, V6) requires: "every class-document schema is exported from the
kernel's single schema source and shared with the §7 kernel↔surfaces binding; plugin/client
bindings are generated and CI-checked; schema drift is a build failure, never a runtime
negotiation." §7.4's Stage-0 slice names the "schema export → codegen pipeline; generated
bindings with the CI drift check". §10.6 requires "far-side types generated from the kernel's
schema with a CI drift check; one codegen round-trip." The pipeline is "the one Stage-0 output
that persists" (S0.2/S0.3 are throwaway).

## Decision
- **Single source:** `hh-embed-schema` defines every Stage-0 wire type once; its
  `export_schema()` is derived from the same definitions, and a unit test asserts the export and
  the Rust types stay in lockstep.
- **Content address:** `schema_hash()` = `sha256:<hex>` over the canonical (sorted-key, compact)
  bytes of the export. This is the `schema_hash` component of `ContractIdentity` (§7.4; ADR-0178
  D2). (Interim; see ADR-0219.)
- **Codegen:** `hh-codegen` reads the export and emits two checked-in artifacts —
  `schema/hh-embed-1.schema.json` (the canonical export) and
  `crates/hh-embed-client-generated/src/generated.rs` (the typed client + `hello` glue asserting
  `(contract_major, schema_hash)`). Emitted Rust is normalized with the pinned `rustfmt` so the
  generated file is byte-identical to what `cargo fmt` produces (otherwise `cargo fmt --check`
  and the drift check would disagree).
- **Codegen round trip:** a client *generated* from the export drives `hello →
  ContractIdentity` against the running kernel over stdio and asserts `(contract_major,
  schema_hash)` (`hh-kernel/tests/codegen_round_trip.rs`). Green = the generated stub, the schema
  source and the running kernel all agree.
- **Drift check (CC7):** `scripts/check-drift.sh` regenerates and fails on any diff; the CI job
  "Schema drift check" gates the build. A mismatch between the generated client's
  `EXPECTED_SCHEMA_HASH` and the live source is additionally caught at test time
  (`client_behavior.rs`). Proven to fail (exit 1) when the schema source changes without
  regeneration.

## Consequences
- Good: schema drift is a hard build failure, exactly as CC7 demands; the round trip is a real,
  deterministic end-to-end check; the generated client is a compiled artifact, so codegen output
  that does not compile is caught.
- Cost: the Stage-0 generator covers the Stage-0 message set (three types + the transport glue),
  not arbitrary schemas. It grows additively with the contract (CC8).
- The generated client is an *in-ecosystem* (E1) stand-in for the real E2/E3 generated clients,
  which bind at Stage 3 / Stage ≥ 5. It exercises the pipeline before those ecosystems exist.

## Alternatives considered
- **Emit unformatted code and exclude `generated.rs` from `cargo fmt`.** Rejected: an ignore file
  is easy to get wrong and the two checks would still risk disagreement; running `rustfmt` in
  codegen (the codex precedent) is simpler and self-consistent.
- **Make the round trip a pure in-process check (no subprocess).** Rejected: the acceptance is
  "`hello` negotiates over stdio", so the round trip must cross the real stdio boundary (binding
  (b)).

## Revisit trigger
When the single schema source moves to a derive-based exporter (ADR-0217 revisit) or the lab (E2)
/ surface (E3) generated clients bind (Stage 3 / Stage ≥ 5), re-evaluate the generator and extend
the drift check to the far-side bindings (AC-R-2.11.4-2 over all three transport bindings).
