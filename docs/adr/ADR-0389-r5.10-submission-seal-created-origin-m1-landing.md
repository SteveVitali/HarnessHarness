# ADR-0389: R5.10 submission seal and created-origin M1 — landing decisions

- **Status:** Accepted
- **Date:** 2026-11-02
- **Ticket:** R5.10
- **Requirement ids:** REQ-E-203, REQ-E-102 (primary); REQ-E-103, REQ-E-201, REQ-E-204 (contributing)
- **Spec:** docs/evidence-and-adoption-spec.md §2.2 steps 1–2 + AC-2-1; PADR-R5-1 (admitted GATE-G9, packet A — A.1 item 3, A.5, A.7, A.9); execution-partition X4; ticket docs/tickets/179_R5.10__seal.md
- **Rung (ADR-0024 obligation):** implementation landing record — the admitted seal-then-finish + created-origin M1 contract's concrete shape on `hh-env`/`hh-control`/`hh-ledger`; no RPC, no wire/schema change, no new event class, no new dependency

## Context

PADR-R5-1 A.1 item 3 admits the ordering "stop participant actions →
drain committed work to observed/unknown → revoke access → finalize
usage → seal immutable end-state/submission (failed sealing yields no
grade)", and the dossier names the M1 correction a §9.3-adjacent
existing-contract fix: the M1 measurement table (`hh-telemetry`
`MEASUREMENT_POINTS`) already declares opens/closes
`lifecycle.run.created` → `lifecycle.run.finished`, while the driver
stamped `wall_ms` from the turn-1 open — under-reporting adoption
delay, approval waits and restart downtime. Partition X4 fixes the
owner seam: "stop participant access, drain observed/unknown, finalize
charges and immutable submission, then finish … owner API for seal/ref
is fixture-testable".

## Decision

1. **The created origin is a recorded member, never a `ts` read.**
   `open_run` stamps `created_at_ms{value, measured_at:"runtime"}` into
   the seq-0 `lifecycle.run.created` payload on the store's own clock —
   the same authority the fenced sink's `now_ms()` answers. The member
   rides `RunManifest::from_json`'s `extra` bucket, so re-read
   manifests serialize byte-identically; pre-R5.10 rows simply lack it.
2. **`wall_ms` measures created→finished on the producing clock.** The
   driver reads the seq-0 `created_at_ms` member — never the turn-1
   `started_at_ms` — so adoption delay, waits, restart downtime and the
   drain/seal legs accrue, and postterminal instrument work never
   inflates M1. An unstamped origin reports `n/a{observability}`; a
   producing clock reading earlier than the recorded origin (rollback,
   untrustworthy restart) reports `n/a{untrustworthy_origin}` — never a
   clamped or backdated finish. `turn_e2e_ms` keeps the turn-origin M2
   semantics (instrument and end-to-end spans stay separate).
3. **The seal is durable rows, not a new class.** Per dossier A.3's
   "prefer … extensions over new classes" (F7), the seal's facts are
   existing-class rows the run's fenced writer commits before the
   terminal: `action.environment.snapshot{purpose:"submission_seal"}`
   (the content-addressed end-state pin), `action.environment.detached
   {reason:"submission_seal"}` (the participant-access revocation) and
   a final `action.environment.meters_sampled` over the post-detach
   finalized buckets. `lifecycle.run.finished` carries a
   `submission_seal` member — the per-handle `WorkspaceSeal` member
   form — only when the durable-dispatch seam's `envs` is armed;
   seam-less (host/replay) runs stay byte-identical (A.7).
4. **Pin-then-revoke inside one pass; revocation is unconditional on
   the pin.** `path_baseline`/`fs_tree` reads gate on
   `verify_environment` (Ready), so detaching first would refuse the
   pin leg; the stop/drain barrier has already quiesced participant
   work, making a ready-time baseline the honest end-state. A pin-leg
   failure never leaves access live — the revoke leg always runs, and
   `status:"refused"` records the named legs with the refs that did
   land (a grader sees `end_state_ref: None` for a submission that
   never sealed — no grading a mutable workspace).
5. **Recovery re-cites, never re-appends.** A `Detached` handle bearing
   the durable `submission_seal` pair reports `status:"prior"` with the
   prior pass's `snapshot_ref`/event refs — the crash-between-seal-and-
   finish window restores without a second revocation row. Detached
   without the pair, suspended/failed/torn-down/unreachable handles
   report `unavailable{…}` — never a fabricated pin.
6. **Size deviation accepted as recorded.** The landed diff is 1,084
   changed source/test lines against the ≤850 split trigger. The
   trigger stop was recorded at checkpoint `904ae83b`; the scoped
   split review adjudicated **AMEND** (ruling `184e4840` — X4's
   seal+M1 unit is one indivisible owner seam; either leg alone lands
   an unexercised or consumer-less predicate). The deviation is
   carried conspicuously into PHASE LOG / BUILD_INDEX / PR.

## Consequences

- New runs' seq-0 payloads differ from pre-R5.10 bytes (the additive
  member); the ledger `acceptance` golden pins were re-pinned with
  provenance comments.
- Old-prefix finishes (a mid-flight pre-R5.10 run resumed under new
  code) report `wall_ms` `n/a{observability}` — the unknown origin
  cannot prove enforcement (spec §2.2 step 2).
- `EnvDriver::seal_workspace` is the owner API future consumers
  (R5.11's sealed-submission oracle input, R5.14's pending consumers,
  B3's deadline enforcement) cite; none re-derives the seal.

## Alternatives

- `lifecycle.run.sealed` as a new event class — rejected: the
  dossier admits payload/member extensions over new classes (F7), and
  the seal pair + finished member already carry the fact durably.
- Detach-then-baseline ordering — rejected: `verify_environment`
  refuses non-Ready handles; it would make sealing impossible, not
  safer.
- Reading the created origin off the envelope `ts` — rejected:
  §5h.1 §2.6's recorded-member rule (a `ts` difference is never a
  duration source).

## Revisit triggers

- If R5.19/B3 need the created origin bound to a different authority
  (e.g. HLC or a lease record rather than the seq-0 member), revisit
  the `created_at_ms` member shape.
- If a later owner needs seal legs that span multiple environments
  atomically (a failed leg currently still revokes the ready ones and
  records `refused`), revisit per-handle independence.
- If instrument/observer runs ever need end-state pins without access
  revocation, revisit the single `seal_workspace` verb (a `taken_by`
  leg already distinguishes subject vs instrument snapshots).
