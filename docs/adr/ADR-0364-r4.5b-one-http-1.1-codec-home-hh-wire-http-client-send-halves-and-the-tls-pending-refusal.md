# ADR-0364: R4.5b one HTTP/1.1 codec home — `hh-wire::http` client send halves + the `tls_pending` refusal

- **Status:** Accepted
- **Date:** 2026-10-21
- **Ticket:** R4.5b
- **Requirement ids:** R-2.3.1 · R-2.3.2 · R-2.7 · R-2.8 · DF-S1.18-1
  (partial) · BL-31 · CC1 · ADR-0301 D1 · ADR-0363 (the live-leg posture
  this leg runs under)
- **Spec:** §7.2 (binding (c) codec home) · §5b (the model boundary's
  `Transport` port)
- **Rung (ADR-0024 obligation):** C0 — the codec is a wire primitive, not a
  contract shape; the transport it feeds is the Stage-1 `Transport` slot.

## Context

R4.5b lands the first *real* `hh_gateway::Transport`: a model call must
leave the process over HTTP/1.1. The ticket's instruction was "reuse the
existing codec; if layering prevents reuse, extract to the lowest
sensible crate and re-point callers; record the choice in an ADR — a
third HTTP implementation is the defect CC1 exists to prevent."

Recon showed `hh-wire/src/http.rs` was already the one codec home —
`read_request`/`read_response`/`write_response`/`split_target`, all typed
`HttpError` — but it was *server-shaped*: the client send halves were
missing, and two private copies had grown to fill the gap
(`hh-env::egress`'s `LocalHttpTransport` and `hh-mcp::http`'s
client/server helpers). The choice was therefore not *which* codec to
reuse but whether to extend `hh-wire` or grow a fourth partial copy
beside `hh-gateway`.

TLS is deliberately out of scope: R4.5c owns rustls; a `https:` endpoint
must refuse typed, never downgrade.

## Decision

- **D1 — `hh-wire::http` is the single HTTP/1.1 codec home, client halves
  included.** The module gains the client-side send/read halves
  (`write_request`, the head-then-body response read covering
  `Content-Length`, `chunked` and close-delimited bodies, `parse_http_url`
  and `connect` helpers) beside the existing server halves. No second
  codec, no copy, no alternate spelling of the wire contract.
- **D2 — the two private copies are re-pointed, not kept.** `hh-env`'s
  egress `LocalHttpTransport` and `hh-mcp`'s HTTP helpers now consume
  `hh-wire::http`; the duplicated framing code is deleted.
- **D3 — `HttpModelTransport` is the first live `Transport`.** It speaks
  plain HTTP to loopback endpoints only (R4.5b's authorized leg: local
  Ollama over `HH_LOCAL_BASE_URL`). It streams response bytes into
  `(arrival_ms, WireFrame)` pairs for the dialect translator, answers
  `discover` via `GET /models` for the OpenAI-compatible family, maps
  HTTP/network/provider failures onto the transport error classes, and
  converts `Retry-After` seconds to the recorded `retry_after_ms`.
- **D4 — `https:` is a typed refusal, never a downgrade.** An endpoint
  whose scheme is `https` returns `UnsupportedFeature{tls_pending}`
  until R4.5c lands rustls beneath this same codec. Silent plaintext
  fallback would be the dishonest-degrade shape the boundary forbids.

## Consequences

- One codec, one bug surface: TLS (R4.5c), the Anthropic/OpenAI lanes
  (R4.5d) and the streaming consumers (R4.7/R4.7a) all mount on
  `hh-wire::http` — the later tickets are extensions of this home, not
  new implementations.
- `hh-env` and `hh-mcp` drop private framing code; their wire behaviour
  is unchanged (the codec is byte-equivalent — the re-point is covered
  by their existing batteries).
- The model lane's `Transport` port is exercised by a real
  implementation for the first time (DF-S1.18-1's local-family member —
  the hosted/provider families and `probe_profile` stay open per that
  row).
- A `https:` endpoint fails closed with a named pending feature; an
  operator pointing at one gets the honest `tls_pending` refusal and the
  R4.5c pointer, not a silent downgrade.

## Alternatives considered

- **A fresh `hh-gateway`-local HTTP client.** Loses on CC1 — a third
  codec spelling, and every later consumer (R4.5c–R4.7a) would have to
  migrate off it.
- **Extract the codec to a new lower crate.** `hh-wire` is already the
  lowest wire-primitive home and already carries the server halves; a
  new crate would split one codec across two homes — the duplication in
  miniature that D1 exists to kill.
- **Silent TLS-downgrade or a stub "tls later" socket path.** Rejected —
  honest refusal over silent degrade; `UnsupportedFeature{tls_pending}`
  is the typed answer the contract already defines.

## Revisit trigger

R4.5c (rustls admission) retires `tls_pending`; if a second wire shape
(HTTP/2, h3) is ever admitted, this ADR's "one codec" rule is revisited
by a new ADR — never by a parallel implementation.
