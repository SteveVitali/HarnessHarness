# ADR-0280: S3.4c estimator-kernel rulings

- **Status:** Accepted
- **Date:** 2026-09-23
- **Ticket:** S3.4c (`049_S3.4c__estimator-kernel.md`)
- **Requirement ids:** R-2.10.4⁰ᵇ
- **Spec:** §6.4 (the analysis/estimator kernel: A1/A2/A3 `contrast`/A8/
  A12, transfer rows) · ADR-0157 (pure versioned class-aware analysis;
  labels; outcome bounds) · ADR-0158 (method set: task = cluster /
  pairing key / resampling unit; `T_clt = 100`, `T_bca = 30`; Wilson +
  Beta(1,1) small-n rule; `permutation_signflip` default) · ADR-0159
  (frontier/benefit/transfer) · ADR-0277 (the `lab.eval.*` records-in
  surface vs the store-backed `lab.analysis.*` surface) · ADR-0279
  (S3.4b results store)

## Context

S3.4c makes the §6.4 estimator kernel executable: `hh-analysis` projects
the durable `ResultsRow` set into `EvalRun`s and runs the Stage-3 kinds —
`summarize`, `compare`, `interaction` (the A3 contrast), `equivalence`,
and `transfer` rows — with the A12 multiplicity pass over every produced
comparison. The owning ADRs fix the contracts; the mechanism choices
below were left to the ticket:

1. **Where the kernel lives.** `hh-eval` owns the records-in evaluators
   (`compare`, `render_scorecard`, `equivalence_run`, `transfer`);
   `hh-results` owns the row store. The §6.4 kernel — projection,
   dispatch, report assembly, the multiplicity pass — needed a home that
   keeps the estimator layer reusable and the store unaware of reports.
2. **`T_CLT`'s landed value.** ADR-0158 sets `T_clt = 100`; S3.3 landed
   `T_CLT = 30` in `hh_eval::scorecard`, so the clustered-CLT floor the
   estimator-selection rule applies was off by the constant's own
   contract.
3. **How a report is served without recomputation.** AC-R-2.10.4-12/KA-12
   require identical inputs to reproduce the identical report — and the
   stored report must be *served*, not re-estimated, so identity has to
   be computable before any estimator runs.
4. **What `report_id` binds.** The identity must cover the input set —
   spec, watermark set, run set, registry/pricing pins, seed and draws —
   and nothing mutable (e.g. row *versions* beyond the watermark pin, or
   wall time) may leak in.
5. **Whether A12 is an analysis kind.** `AnalysisSpec.kind` enumerates
   the analysis; multiplicity corrects every comparison report,
   including kinds that produce several.
6. **`AnalysisSpec`'s pre-S3.4c shape.** The landed record carried no
   `kind`/`spec_ref`/`label` — the only expressible analysis was the A1
   record. Extending it had to stay CC8-additive so stored specs decode.
7. **The sign-flip permutation tail.** ADR-0158's default test needs a
   deterministic p over the paired per-task deltas; exact `2^n`
   enumeration is only feasible below a ceiling.
8. **The C0/C1 kind split.** §6.4's full kind set (`frontier`, `rank`,
   search-baseline decomposition, …) is C1/S4.3 scope; absent kinds must
   refuse typed, never silently summarize.
9. **`equivalence_run`'s return shape.** The kernel needs the underlying
   `CompareOutcome` (the A8 report preserves the comparison evidence);
   the landed wrapper returned only the `EquivalenceReport`.
10. **Missing-data posture at the projection.** A row without a task
    coordinate or with an unparseable consumption dimension must not be
    silently bucketed or zero-filled.

## Decision

1. **`hh-analysis` is a new leaf crate** — `project` (ResultsRow +
   manifest + facts → `EvalRun`), `kernel` (kind dispatch +
   summarize/compare/contrast/equivalence/transfer), `multiplicity`
   (the A12 pass), `report` (the `analysis_report_body/1` assembly +
   `report_id`), `engine` (`analyze_and_record` over `LabDocs`), `error`
   (the typed refusal set). The kernel never opens a store: callers
   supply rows, manifests, facts, contexts, declarations, design, arms,
   pre-registration and the watermark set — the same records-in contract
   ADR-0277 fixed for `lab.eval.*`. The only inbound dependency edge is
   `hh-embed` (removable: delete the crate + `analysis_ops` + the
   dispatch arm + the `labi` flag and the workspace is unchanged).
2. **`T_CLT` corrected to 100** — the ADR-0158 constant, with the
   estimator-selection `substituted{from,to,reason}` record already
   landed doing the labelling. Rows under the floor fall back through
   `bootstrap_paired` and carry the substitution record — never a silent
   method swap.
3. **The report body is a named `LabDocs` doc keyed by `report_id`.**
   `analyze_and_record` computes `report_id` from the spec +
   `generated_from` *before* estimating; a hit on
   `get_named(ANALYSIS_REPORT, report_id)` serves the stored body
   verbatim and rebuilds only the envelopes — the estimators never run
   twice. The `AnalysisRecord` is deposited under `analysis` and the
   `AnalysisReport` envelope's `result_ref` names the body doc.
4. **`report_id = H("analysis.report" ∥ spec_hash ∥ generated_from)`** —
   `generated_from = {row_watermark, run_ids_hash, run_ids,
   metric_registry_version, price_table_version, seed}` over the sorted
   input run set. Nothing else enters: no clock, no row-version id, no
   ordering artifact — so the same recorded inputs reproduce the id and
   the served body is byte-identical.
5. **A12 is a pass, not a kind.** `apply_multiplicity` runs over every
   `ComparisonReport` the kernel produced: the sign-flip raw p, Holm
   across the pre-registered primary family (`primary_metrics`), BH
   q-values across the exploratory remainder, and `family_size` /
   `method` / `label` attached to each comparison. Nothing is suppressed
   — an exploratory label is a report fact, never an exclusion.
6. **`AnalysisSpec` extended additively** — `kind` (absent ⇒
   `summarize`, the only pre-S3.4c shape), `spec_ref` (the registered
   `hh-experiment/1` doc the design/arms/pre-registration resolve
   through; `None` = design-free summarize), `label` (the requested
   report label). Older encodings decode unchanged; `Multiplicity`
   gained `raw_ppm`/`adjusted_ppm`/`label` the same way.
7. **Sign-flip p: exact enumeration `n ≤ 20`, seeded Monte-Carlo above.**
   `SIGNFLIP_EXACT_MAX_N = 20` — the `2^20` walk is cheap enough to be
   exact (no smoothing needed; the observed assignment is always a hit);
   above it a `draws`-sized XorShift64 sign-flip sample under the spec's
   seed approximates the tail, +1-smoothed so p never reports an
   impossible zero. p-values ride *with* the effect and interval, never
   alone (ADR-0158).
8. **Non-C0 kinds refuse `KindNotImplemented`.** `frontier`, `rank`,
   `power`, and the search-baseline kinds answer the typed refusal —
   AC-R-2.10.4-3/-7/-11's C1 halves land at S4.3 with the comparison
   machinery, not here (CC10: this ticket does not pre-decide their
   shapes).
9. **`equivalence_run_full` is the additive internal; `equivalence_run`
   stays the report-only wrapper.** The kernel binds the
   `CompareOutcome` for the preserved-evidence half of the A8 report;
   the landed signature is unchanged so no S3.3 caller moved (CC1 — one
   estimator, two views).
10. **Projection refuses, never defaults.** A row with no task
    coordinate is `MissingClusterKey` (ADR-0158: the task is the
    cluster); an unknown consumption dimension, a non-terminal row read
    as scored, or an absent source field is a typed `BadField`/`Refusal`
    — typed `n/a` cells pass through as `MetricValueKind::Na` and are
    never coerced to zero.

## Consequences

- The analysis kernel is pure over its input record — every refusal is
  reproducible and the boundary (`lab.analysis.analyze`) is a resolver +
  persister, not a second estimator.
- Cached reports are honest: a `report_id` hit returns the stored body
  with the label/status derived from that body (an exploratory report
  stays exploratory on a confirmatory re-ask).
- The `Multiplicity` extension makes A12 auditable — `raw_ppm` /
  `adjusted_ppm` / `family_size` / `method` / `label` sit on each
  comparison row, so the FWER/q bookkeeping is inspectable without
  re-running the pass.
- `T_CLT = 100` changes which cells take the CLT path vs the bootstrap
  substitution — the report labels the substitution, and the KA-2
  coverage battery holds either way.
- Non-C0 kinds refuse honestly; the `KindNotImplemented` arm is the
  removable seam S4.3 fills.

## Alternatives considered

- **Folding the kernel into `hh-eval`.** Rejected — `hh-eval` stays the
  records-in estimator layer other consumers reuse; the projection +
  persistence + multiplicity orchestration is a different concern and a
  different removability unit.
- **Folding it into `hh-results`.** Rejected — the store would learn the
  report contract and the kernel would hold storage handles; the
  records-in/records-out split keeps both honest.
- **`report_id` over the full input hash including row bodies.**
  Rejected — the watermark set + run ids are the durable identity the
  store already pins; hashing row bodies would couple report identity to
  derived artifacts the spec's reproducibility rule does not name.
- **A `multiplicity` kind.** Rejected — A12 corrects every produced
  comparison report; a standalone kind would duplicate the comparison
  pipeline and invite suppression-by-omission.
- **Returning `Refused` for missing task coordinates with a default
  cluster.** Rejected — a fabricated cluster key silently pools
  incompatible strata; `MissingClusterKey` is the honest answer.

## Revisit trigger

Reopen when any of: (a) S4.3 lands the C1 kinds and the
`KindNotImplemented` arm shrinks; (b) a second boundary (e.g.
`lab.analysis.diff_reports`) needs the kernel's comparison rows and the
records-in surface widens; (c) the enumeration ceiling or the
Monte-Carlo `draws` default changes under an ADR-0158 amendment; (d)
report identity must additionally pin a schema version once
`analysis_report_body/2` exists.
