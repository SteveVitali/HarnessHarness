# ADR-0341: R2.9b egress/containment residual — typed lowering-loss rows, the C2 wire guards, the `approved_host_body` closer, and the four security metrics

- **Status:** Accepted
- **Date:** 2026-10-07
- **Ticket:** R2.9 (the pre-registered `R2.9b` half)
- **Requirement ids:** DF-S1.12-4 · DF-S1.12-6 · DF-S2.4-3 · R-2.8.2 ·
  R-2.8.3 · R-2.8.4 · BL-18
- **Spec:** §5g.3 (detectors, leak scan), §5g.4 (containment, mediated
  egress, `tls.terminate`, `inspect_hooks`, `approved_host_body`),
  §5g.4 §6 (process metrics) · ADR-0340 (the R2.9a half this stacks on) ·
  ADR-0266 (mediator rulings) · ADR-0059 (canary/leak battery) ·
  ADR-0062 (fail-closed containment)
- **Rung (ADR-0024 obligation):** C0–C2 — the C2 members
  (`tls.terminate`, `inspect_hooks`, the `approved_host_body` closer) are
  enforcement machinery over declared policy, exercised against fixture
  transports; the real TLS-terminating transport stays
  DF-S2.4-2/BL-31.

## Context

R2.9a's ADR-0340 landed the producer seams and carried the residual set
to R2.9b. Opening R2.9b, four gaps remained: (a) `lowering_loss` was a
reason-string row — the report could not name *which declared field* a
backend failed, so the proxy-hijack metric and the fail-closed attach
test both had to parse prose; (b) `tls.terminate = true` silently passed
on the fixture `LocalHttpTransport` and a declared `inspect_hooks` set
had no execution seam; (c) `approved_host_body` was a declared residual
whose closer never ran — a body could ride an endorsed approval to an
approved host with no recorded reader coverage; (d) the Stage-3
`leak_scan` domain was event payloads only, and the four §5g.4 §6
metrics were catalogue declarations with no runtime emission.

## Decision

**D1 — `LoweringLoss` is a typed row, not a reason string.**
`LoweringLoss{declared_field, backend, reason, kind, consequence}` is the
one report record (`LossItem` remains as the compatibility alias);
`kind` is the local closed sum mirroring §3.2.5's `LossClass` spellings
(the dependency direction forbids importing `hh-compiler`), and
`consequence ∈ {fail_closed, stratified}` says whether the loss must
fail attach or merely demote the run's stratification claim.
`ContainmentReport` and the `lowering_loss` blob carry the typed rows;
each backend reports its own unsatisfiable declared fields
(`net.tls.terminate`, `net.tls.inspect_hooks`, `net.upstream_proxy`,
`proc.env`, …).

**D2 — attach fail-closes on `consequence = fail_closed` losses in
relied-on groups, never on prose.** `attach` reads the typed
`consequence` member; a `stratified` loss (a capability the backend
records but cannot enforce — e.g. `net.proxy_env` under `mediated`)
annotates the report without refusing the attach. The pre-R2.9b
reason-string sniff is gone: the gate's input is the typed field.

**D3 — the C2 guards run at the mediator, post-allow, pre-wire.**
`EgressMediator::forward` runs, after the policy allow: the TLS guard
(`policy.tls.terminate` + a TLS protocol leg + a transport whose
`terminates_tls()` is `false` ⇒ typed `Refused{tls_terminate_unsupported}`
with a durable `decided{deny, source: tls_guard}` — the wire never
fires), then the declared `inspect_hooks` set in declaration order over
an `InspectView` of the sentinel-spelling request (an unregistered
declared ref ⇒ `inspect_hook_unavailable`; a `deny` verdict ⇒
`inspect_hook_denied`), then the body-reader closer. `EgressTransport`
gains `terminates_tls()` (default `false` — the reference
`LocalHttpTransport` honestly reports no termination; the real
TLS-terminating transport is BL-31) and the decided row gains
`guard_detail` (which hook/guard produced the post-allow verdict) and
`tls_terminated`.

**D4 — proxy surfaces are `stratified` losses; hooks see sentinel
spellings only.** `net.upstream_proxy` and `proc.env` (a process
environment inheriting `*_proxy` variables) under `mediated` record as
`stratified` losses — the run is stratified, never counted as mediated.
The `InspectView` a hook receives carries the post-substitution
(sentinel) spellings; the broker's material stays behind the
substitution — a hook can never read a credential value.

**D5 — `security.containment.applied` carries
`lowering_loss_fields`.** The applied row durably lists the declared
loss-field spellings (closed, content-free tags); the proxy-hijack
metric reads them without resolving the loss-report blob — the report
stays content-free at the event.

**D6 — the `approved_host_body` closer is `readers(body) ⊇
recipients(p)` at both decision points.** `EgressRequest` gains
`body_readers: Option<ReaderSet>`, plumbed at dispatch from
`flow.param_labels["body"]`. The closer runs on every allow — including
approval-cache hits, whose key is deliberately body-blind:
`ReaderSet::Public` covers every destination; `Restricted` covers the
normalized destination host only when the host is a member; `None`
(unlabeled) is unproven coverage ⇒ typed `deny{reader_coverage,
source: flow_guard}`. An *undeclared* `approved_host_body` residual is
a readiness/declaration gap — the runtime never invents a verdict for a
channel the policy didn't declare.

**D7 — the four §5g.4 §6 metrics are pure folds over durable rows,
emitted at settle.** `hh-eval::security_metrics::fold(&[FactRow])`
reads the projected rows — `egress.ask_rate` (asked / decided, ppm),
`containment.violation_rate` (violated / applied, ppm),
`proxy.hijack_attempt_rate` (applied rows carrying a proxy-surface
`lowering_loss_fields` tag / applied, ppm),
`session.revoked_continuation_denied` (count of
`security.credential.denied{reason = revoked}`). `None` where the domain
never ran — the caller leaves the metric unemitted and the cell renders
`n/a{not_run}`, never a fabricated 0. Native `settle` (hh-experiment)
and the hosted path (hh-embed) both emit `measurement.metric.emitted`
with `applies_to` the subject run; the catalogue registers the two new
declarations beside the existing two.

**D8 — `leak_scan_run`'s domain is the run's whole durable surface.**
`ScanTarget` gains `Manifest`; the sweep covers every committed event
payload, the seq-0 manifest (`to_json`), every blob-pool object, and
each `measurement.export.delivered` row re-tagged under its
`sink_delivery` surface so a leak attributes to the delivery leg. One
detector set composes over all four surfaces (CC1).

## Consequences

- The report and audit shapes are richer (`lowering_loss` rows,
  `lowering_loss_fields`, `guard_detail`, `tls_terminated`,
  `body_readers`) — all additive members; the class tables register
  them and pre-R2.9b rows fold unchanged (absent members).
- `mediated` runs declaring `tls.terminate` refuse typed at the wire
  until a terminating transport exists (BL-31) — honest refusal, not a
  silent plaintext passthrough.
- The approval cache stays body-blind by design; correctness lives in
  the per-request closer re-run, not in a wider cache key (a wider key
  would silently cache a body the cache never saw).
- `leak_scan_run` stays a verifier/battery path — never a live-path
  interceptor.

## Alternatives considered

- **Enriching the approval-cache key with a body-readers hash.**
  Rejected — the cache never saw the body; a key member asserting
  coverage would be a claim the record can't back. The closer re-run is
  the honest seam (D6).
- **Resolving the `lowering_loss` blob inside the proxy metric.**
  Rejected — metrics fold durable row members; a blob read would couple
  the fold to store I/O and content the event deliberately doesn't
  carry (D5 keeps the tag content-free).
- **`leak_scan` as a live export-time interceptor.** Rejected — ADR-0059
  D2 fixes it as the test-battery verifier; the C2 surface scans the
  committed record, and a live-path canary still reports
  `leak_detected{mediation}` via the broker seam.
- **Emitting `n/a` metric rows.** Rejected — the `emitted` row carries a
  produced value; the typed `n/a{not_run}` is the *absence* of a row,
  which is what the fold's `None` means (D7).

## Revisit trigger

DF-S2.4-2/BL-31 (the real TLS-terminating transport) reopens D3's
capability check (`terminates_tls` becomes a negotiated property, and
the cipher/version members of `TlsConfig` gain enforcement semantics).
A second body-content channel beyond `approved_host_body` would grow
`ResidualKind` and revisit D6's closer placement (one closer per
declared residual kind, never a generic content check).
