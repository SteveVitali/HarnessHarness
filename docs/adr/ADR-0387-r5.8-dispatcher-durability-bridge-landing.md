# ADR-0387: R5.8 Dispatcher durability bridge — `DurableEffectRef` landing decisions

- **Status:** Accepted
- **Date:** 2026-11-02
- **Ticket:** R5.8
- **Requirement ids:** REQ-E-002 (primary); REQ-B-105, REQ-C-006, REQ-D-203/204/205/206/207, REQ-E-012, REQ-E-110, REQ-E-205 (contributing)
- **Spec:** docs/evidence-and-adoption-spec.md §2; PADR-R5-2 (admitted GATE-G9, packet B — B.1–B.10 seam semantics, non-admission ledger); ticket docs/tickets/177_R5.8__effect.md
- **Rung (ADR-0024 obligation):** implementation landing record — the admitted owner-bound `DurableEffectRef*` seam's concrete shape on `hh-env`/`hh-control`/`hh-embed`; no RPC, no wire/schema change, no new event class, no new backend, no new dependency

## Context

GATE-G9 admitted PADR-R5-2: the control/env `Dispatcher` validates an
already-intended coordinate and its scoped writer, owns
authorization→settlement once, and returns a `DurableEffectRef` that
suppresses duplicate driver lifecycle rows (dossier B.2/B.3; design
`14_integration-design.md` F4; execution-partition input working set:
control `EffectGate`/callsite, env `DispatchInput`/`dispatch`/outcome,
embed injected bridge, bench adapter seams). The dossier's non-admission
ledger fixes the surface: a Rust-only seam whose members resolve to
existing `action.effect.*`/permission records — never a new persisted
event class, never a driver-owned second lifecycle.

## Decision

1. **`DurableEffectRef` is a Rust record, not a wire row.** Members are
   `effect_id` (the adopted coordinate), `coordinate_ref` (the
   `action.effect.intended` event id), `writer_lease_ref`
   (`{lease_id}@{generation}` of the fenced writer) and `settlement_ref`
   (the terminal `action.effect.*` event id; for open legs the
   `security.permission.pending` / `action.effect.input_required` /
   `action.tool.rejected` record explaining the parked/served state).
   `to_json()` gives the canonical member form; nothing is persisted
   under a new name (dossier B.10 — existing event/class table stays
   authoritative).
2. **`Dispatcher::dispatch_adopted(intended, …)` validates before any
   append.** Scoped writer (`lease.run_id`, `current_lease_generation`,
   expiry), then the coordinate's fold must be exactly `Intended`
   (`adopt_duplicate_lifecycle` otherwise), then the presented dispatch
   is checked against members the coordinate's `intended` row recorded
   (`adopt_args_mismatch`, `adopt_capability_mismatch`). All refusal
   spellings are typed `EnvError::ResumeRefused{adopt_*}` raised
   pre-mutation. The existing `dispatch` body became `dispatch_at(
   Option<effect_id>, …)`; `dispatch()` derives `f(run, mc, tc,
   ordinal)` exactly as before — upstream task semantics and the
   derived-coordinate path are unchanged.
3. **The control callsite validates refs instead of re-appending.**
   `GateOutcome.durable_effect_ref` names the settled coordinate;
   `LedgerSink::dispatch_seam()` (default `None`) hands the gate the
   store + fenced writer + env driver as `DispatchSeam`; the new
   defaulted `EffectGate::dispatch_durable` leg is tried first and
   `None` falls back to `dispatch` verbatim (host/fixture mode
   preserved byte-identical). `validate_durable_outcome` checks
   `effect_id`, that `emitted` is empty, that `coordinate_ref` and
   `settlement_ref` resolve on the durable prefix with the expected
   classes — then suppresses both the emitted-append and the driver's
   terminal append (PADR-R5-2's duplicate suppression). Submission-ref
   and the `open_effects`/trigger legs are unchanged.
4. **The embed bridge is the injected gate, not a second runtime.**
   `DispatchGate` wraps `EmbedGate` (delegated `dispatch`/`finish_record`
   — the host path is byte-identical) and owns `exec_caps:
   BTreeMap<surface_id, ExecCap>` — owned records carrying the resolved
   `SurfaceBinding`/`ScopeBindings`/`ToolCapabilityRecord`/`PinnedRef`,
   the declared class, and the bound `Box<dyn ToolExecutor>` + `Monitor`.
   `EmbedService::arm_exec_capabilities` re-binds every cap's executor
   declaration against the capability `execution_requirement`
   (`hharness_env::executor::bind`) — insufficient isolation/dedup/domain
   is a typed `exec_cap_unbound` refusal; `local_host` never substitutes
   for an admitted confinement floor (no `LocalExecutor` substitution).
   `drive()` selects the gate once (`take`/restore on `SessionState`,
   same pattern as `driver`/`fail_plan`).
5. **Outcome mapping keeps open legs honest.** `Suspended`/`Paused` map
   to `SettledOutcome::Pending` (the driver's open-effects parking; the
   dispatcher's `respond`/resume machinery remains the resumption path —
   owed to the operations tickets). `Duplicate{stored_observation}`
   serves the stored observation when present, else a refused outcome
   *without* a ref so the driver appends the honest
   `action.effect.refused` terminal under `ef`. `ObservedCached` maps to
   `Observed`. Gate-level `Err` becomes `Refused` with no ref — the
   driver lands the refused terminal; a mid-pipeline `Err` that already
   landed a terminal surfaces as the fold's typed transition refusal
   (loud, never silent).
6. **Size deviation recorded conspicuously.** ~2,594 changed
   source/test lines vs the contract's ≤1000 split flag — the bridge
   spans three crates plus two acceptance batteries mirroring the
   existing battery fixtures. R5.6/R5.7 AMEND precedent: the seam is
   atomic (dispatch↔gate↔arm cannot land half-bound); recorded for the
   scoped split review ruling rather than silently shipped.

## Consequences

- One intended coordinate traverses the seven stages exactly once; the
  fence, scope-open, and fold-transition rules land through `Store` —
  never through a driver-side convention.
- The replay/arm sinks (`dispatch_seam` default `None`) keep the
  byte-identical host/fixture path; scripted `EffectGate`s need no
  changes (the new trait member is defaulted).
- `DurableEffectRef`'s members are inspectable joins the driver's
  `finish`/`submit` rows already accept — R5.43's contributor evidence
  for REQ-E-002's full predicate is still owed (R/P and
  actual-execution E are not claimed by this engineered slice).

## Revisit triggers

- A dispatch path whose `intended` rows carry `ordinal` must derive
  `f(run, mc, tc, ordinal)` — the free-coordinate adoption contract
  assumes the task runtime's own coordinate discipline (the driver's
  `ef-N` shape).
- A future `LedgerSink` implementation exposing `dispatch_seam` without
  a live fenced writer must answer `None`, or a gated run could bind a
  reader as if it were the writer.
