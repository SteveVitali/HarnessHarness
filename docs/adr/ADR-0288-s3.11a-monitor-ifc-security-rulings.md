# ADR-0288: S3.11a monitor/IFC security rulings

- **Status:** Accepted
- **Date:** 2026-09-24
- **Ticket:** S3.11a (`057_S3.11a__security-eval-monitor-ifc.md`)
- **Requirement ids:** R-2.1.5, R-2.8.1, R-2.8.2 (S3 slices)
- **Spec:** §5g.1–§5g.2 · §8.1 · owning ADRs ADR-0031/0052/0055/0056/0059 ·
  ADR-0017 (`authority_delta`)

## Context

S3.11a lands the Stage-3 monitor/IFC security executables: the
definition-level `FlowPolicy` evaluated beside capability `FlowContract`
rules, the exact policy-edit classifier, the `hir/provenance` `_meta`
lowering/lift pair, the shape/sanitizer endorsement emitters,
`remedy_taken` propagation, and the advisory `taint_precision` + remedies/
approvals process metrics. The ticket owned these rulings:

1. **What the policy-edit classifier enumerates.** AC-R-2.8.2-9 requires
   an *exact* `narrowing | widening | incomparable` verdict for a
   `flow_policy` edit, and §5g.2 §5 restricts who may apply each class
   (delegate-class proposers: narrowing only; evolution: refused outright
   for non-narrowing). The general `allowed(P) ⊆ allowed(P′)` question is
   undecidable over open `FlowInput` domains — the spec's classification
   space must be made finite without inventing semantics.
2. **What the taint gate's default class is.** AC-R-2.8.2-10's recipe
   (`taint gate ∈ {off, advisory, deterministic}` × remedies ×
   quarantine) must end in a *decided* default enforcement class for
   tainted content no Π row names — a report that ends "it depends" is
   not a decision.
3. **What the `_meta` carrier member looks like and who sets the lifted
   authority.** §8.1 P7 carries provenance across foreign tool APIs in
   the typed extension slot; the lift must never read an authority claim
   from the foreign payload (a server can write any string) yet must
   still produce a canonical `ProvenanceRecord` and a named loss report.

## Decisions

- **D1 — the classification space is the caller-declared finite
  `ProposalSpace`.** `hh_provenance::flow_policy::ProposalSpace` is an
  explicit `Vec<PolicyPoint>` — each point a concrete `FlowInput`
  member set (`domain`, `world`, `capability`, `args`, `param_labels`,
  `recipients`, `L⁺`, the committed projection, detector verdicts).
  `classify_policy_edit(P, P′, space)` enumerates every point and
  compares allowed sets: `narrowing ⇔ allowed(P′) ⊆ allowed(P)`
  (equality included — a no-op edit narrows), `widening ⇔` pure strict
  superset, `incomparable` = mixed. `rules_allow` fails closed: only
  `Allow`/`Declassified` verdicts count as authorization — `deny`,
  `ask`, `fallthrough`, and any `EvaluationError` do not. This is
  ADR-0056 D5's decidable encoding: the *space* is a declared input, so
  the classifier is exact over it by construction and never claims
  exactness over the unenumerated domain. `apply_policy_edit` then gates
  on the proposer's `Origin`: `evolution` → `EvolutionOrigin` on any
  non-narrowing edit (the §03 `authority_delta = widening` rejection);
  other `is_delegate_class` origins → `WideningRequiresHuman` on
  `widening`/`incomparable`; `human`/`kernel`/`definition` apply any
  class. `incomparable` is widening for authority purposes — the
  returned class feeds `HirDiff.classification.authority_delta`
  (ADR-0017). (`crates/hh-provenance/src/flow_policy.rs`)

- **D2 — the taint gate's default class is `deny`.** The Π gate is
  consulted when `eff ≤ external ∨ taint ≠ ∅` and the class is not
  `read_only ∧ closed` (`monitor.rs` step 4); `PolicyTable`'s
  deny-by-default floor decides every tainted cell no row names —
  `deny > ask > allow` precedence with `unwrap_or(Deny)`. The AC-H2-10
  recipe runs the three enforcement classes under `MatchSpec` and the
  `compare` report records the default class the deterministic arms
  converge on: **`deny` is the default class** — a tainted proposal no
  rule authorizes is never allowed by omission, and Π-12's unattended
  transform (`ask → deny` absent a `definition` pre-authorization)
  applies to the default path identically. The `advisory` arm may raise
  restriction, never widen. `taint_precision` stays a *reported* metric
  (I-F1) — the gate's class is decided by Π rows and this default,
  never by a judge verdict.

- **D3 — `_meta["hir/provenance"]` carries the compact projection;
  the lift fixes authority by source, never by payload.** The member is
  `{origin_ref, authority, scope, taint_tags[], readers[]}` with
  `readers: []` spelling `Public` (`lower_provenance_meta`,
  `META_PROVENANCE_KEY = "hir/provenance"` — the single canonical
  member shape; `readers` rides the same member at C2, AC-R-2.8.2-13).
  `lift_provenance_meta` takes a `MetaLiftSource` — `ExternalServer` →
  `origin = import`, `authority = unverified`; `DeclaredOpenWorldTool` →
  `origin = tool(capability)`, `authority = external`; `Participant` →
  `unverified` (T-LCD-07). The payload's own `authority` string is
  *never* consulted: a class is fixed by the caller-declared source, so
  a foreign server cannot self-endorse. Lifting returns the record plus
  the explicit carried/lost report — a target that cannot carry
  `hir/provenance` is named in the loss list (`role_map_collapse`
  reports the class distinctions a reduced-role target cannot express).
  (`crates/hh-provenance/src/lower.rs`)

## Consequences

- The classifier's exactness is bounded by the declared space — a
  caller that under-declares points gets an exact answer over the wrong
  set (the AC-H2-9 battery cross-checks the classifier against
  exhaustive enumeration on the fixture space).
- `Monitor.flow_policies` joins capability `FlowContract.rules` +
  definition `FlowPolicy.rules` into one evaluator pass preserving the
  §5g.2 §2.3 tier order (deny tier first); a policy-rule flow decision
  supersedes the Π fallthrough, an OOP `AuthorizeInput` round-trips the
  policies byte-identically.
- `Proposal.remedy_taken` rides the wire and lands on the decided
  record (`KernelDecision.remedy_taken`, `security.permission.decided`
  payload member, absent-not-null when `None`, CC8).
- The `_meta` lift cannot launder authority: the strongest claim a
  foreign payload can produce is `external` and only when the sealed
  definition declared the tool closed-schema/`open`-world.

## Alternatives considered

- **Symbolic/interval classification of `flow_policy` edits** — rejected:
  undecidable over open domains in general; a partial symbolic answer
  would silently degrade to "unknown" exactly where the gate needs a
  verdict. The declared finite space keeps the verdict total and honest.
- **Tainted-default `ask`** — rejected: ask-by-default turns every
  unlabelled taint cell into a human-interaction obligation (and a
  `deny` under Π-12 anyway); `deny` is the honest floor the ADR-0031
  discipline already uses for unmatched cells.
- **Reading `authority` from the `_meta` payload** — rejected: it is
  attacker-controlled text; only the caller-declared `MetaLiftSource`
  can fix the class (the minting table's discipline — DF-S1.3-3's
  conservative floor).

## Revisit trigger

- A ticket lands the remedy-ingress/approval-consumption surface that
  *produces* `remedy_taken` at dispatch time (DF-S2.7-1 member (b)):
  revisit whether `apply_policy_edit` should also bind the consumed
  remedy to the applying permission record.
- The observation-shaping ticket lands `labels_leaves` (DF-S2.7-1
  member (a)): revisit whether `PolicyPoint` needs per-leaf label
  members for classification fidelity.
- A spec ruling gives `_meta` a second typed-extension member (e.g. a
  capability manifest): the single-member shape of D3 is the seam to
  extend — never a second provenance spelling.
