# ADR-0425: The integer-µ$ pricing unit — `rate_unit` on the pricing-table carrier, one rounding rule, `NoPrice{unrepresentable_rate}` (AR-09)

- **Status:** Accepted
- **Date:** 2026-11-07
- **Ticket:** R6.7 (manifest row 260; experiments supplement §10.5 AR-09)
- **Requirement ids:** REQ-XC-116 (absorbs REQ-XC-008)
- **Spec:** experiments supplement §4.5; design/33 F11 + §3 ADR-C2-B;
  canonical §8.2 `PricingTable` row (amended member, this record)
- **Rung (ADR-0024 obligation):** C0 — the budget/pricing contract this
  ticket already owns; no schema or ledger-class change

## Context

Three pricing-unit conventions coexist (design/33 F11, VERIFIED):
`PricingRow` rates are integer micro-units **per token** (so the
published glm-5.3-flash $0.15/M = 0.15 µ$/token is unrepresentable —
C1 F14); the router's `DeclaredPricing`/`PriceRate` is µ$ **per 1k**;
and `docs/build/reports/live/pricing.json` spells float USD per 1k.
REQ-XC-116 pins the resolution: `PricingTable` SHALL carry
`rate_unit ∈ {micro_per_token, micro_per_1k_tokens}` (default the
former), price a call as one exact nano-sum rounded once (ceil to the
µ$), itemize roles by floor plus a `rounding` role, refuse a
non-integral rate as `NoPrice{unrepresentable_rate}`, and carry the
glm-5.3-flash row at 150 / 30 / 500 µ$ per 1k.

The binding constraint is AC-2: every pre-existing pricing test
(`hh-budget` unit tests, `r5_13`, `golden_usage`, `account`) and the
r4_5d cell **stay byte-unchanged**. All five construction sites spell
`PricingTable { table_id, version, currency, rows }` and
`PricingRow { … }` as struct literals — stable Rust admits no new
mandatory field to an already-literal-constructed public struct, and
`#[non_exhaustive]` would forbid construction entirely.

## Decision

1. **`rate_unit` is carried by the pricing-table carrier, not a new
   `PricingTable` field.** `RateUnit { MicroPerToken, MicroPer1kTokens }`
   is the closed sum; `PricingTable::rate_unit()` returns
   `MicroPerToken` — the spec's default — by construction, so every
   pre-existing table literally carries the declared unit. A
   non-default unit rides `RatedPricingTable { table, rate_unit }`
   (`PricingTable::at_unit`), which annotates the unit and never
   re-spells the rows — no second rate representation (CC1).
   `price`, `attribute_spend` and `Account::attribute_spend` are
   generic over the `PricingUnit` trait (`rate_unit()` +
   `pricing_table()`), so the one pricing path serves both carriers;
   every existing call site passes a `PricingTable` and compiles
   unchanged.
2. **One rounding rule.** `price` accumulates the exact per-call
   nano-µ$ sum `Σ rate·qty·scale` in `i128` (`scale = 1000` at
   `micro_per_token`, `1` at `micro_per_1k_tokens`), then rounds once —
   `ceil` to the µ$. Roles itemize each role's `floor` share; a
   `rounding` role carries the residual `money − Σ floor`, present iff
   the residual is non-zero. A `micro_per_token` call's nano-sum is a
   multiple of 1000 by construction, so pre-existing itemizations are
   byte-identical — the `rounding` role can never appear there.
3. **`NoPrice{unrepresentable_rate}` at the declaration boundary.**
   Stored `i64` rates are always integral in-unit, so the refusal lives
   where an external denomination becomes a row:
   `RateUnit::rate_from_micro_per_1m` and
   `PricingRow::from_micro_per_1m` refuse a rate not integral at the
   declared unit (`SpendError::NoPrice` with `detail` naming
   `unrepresentable_rate`), never rounding it into place.
4. **The glm-5.3-flash row** is committed as
   `ollama_glm_5_3_flash() -> RatedPricingTable`: the published §4.1
   rates ($0.15 / $0.03 / $0.50 per 1M) converted through
   `from_micro_per_1m` to 150 / 30 / 500 µ$ per 1k, `valid_from
   2026-10-22` (the provider credit-period date), source citing
   experiments-spec §4.1; key `glm-5.3-flash@ollama`
   (`provider_model_id@serving_route`, the Ollama lane's route).
5. **`DeclaredPricing` disposition: declared out of scope for paid
   studies** (the spec's second allowed option). `DeclaredPricing`
   stays exactly what R4.5e built — the router's dated, freshness-bound
   worst-case reservation estimate behind the `PricingView` trait — and
   is **not** a paid-consumer pricing source. Every paid consumer
   (reservation/charge, slot cost fold, spend ledger, caps, quotes,
   evaluator, site spend pages) reads the one `PricingTable` type
   through `PricingUnit`. No second representation is added.
6. **`derivation.table_priced` keeps its frozen §8.2 members**
   (`table_ref, table_version, tier?, ttl_class?`) — the spend row's
   JSON is unchanged; the unit is a carrier property, re-derived from
   the pinned table coordinate.
7. **The r4_5d comment is corrected** (`1000 micro/token ⇒ $1/1k`, not
   `⇒ $1/1M` — F11's flagged misread), comment only, no test semantics
   change.

## Consequences

- glm-5.3-flash prices exactly: the golden trial (10 007 uncached +
  5 003 cached + 2 001 visible + 997 reasoning) costs 3 151 µ$,
  itemized 1 501 / 150 / 1 000 / 498 + `rounding` 2.
- Every paid consumer reads one table type through one path; X-02's
  "integer-µ$ is the unit every mechanical cap enforces" holds.
- `micro_per_1m_tokens` is deliberately **not** in the sum — a rate
  below $0.001/M would need it (F11's limitation); the ADR records the
  extension point, not the member.
- The Responses lane and any `rate_unit` durable codec are unaffected
  here; when a `PricingTable` JSON codec lands (none exists — F11),
  `rate_unit` MUST be a member so a pinned snapshot re-derives the
  unit.

## Alternatives considered

- **`rate_unit` as a new `PricingTable` field** — impossible under
  AC-2: the five frozen literal sites cannot spell it.
- **`Option<RateUnit>` field or `#[non_exhaustive]`** — same literal
  break (or forbids construction outright).
- **A sentinel inside `input_cache_write`/`source`** — a silent
  convention inside typed members; rejected as a hidden second
  representation.
- **Deriving `DeclaredPricing` from `PricingTable`** — allowed by the
  spec, but it would couple the router's reservation view (a dated,
  freshness-bounded worst-case estimate with its own stale-refusal
  semantics) to the spend table; declaring it out of scope for paid
  studies preserves both contracts with zero new representation.
- **A `micro_per_1m_tokens` arm now** — no current Ollama rate needs
  it; the closed sum grows by amendment when one does.

## Revisit trigger

When a durable `PricingTable` JSON codec lands (bundle snapshot),
`rate_unit` must be a required member of it; when a provider rate
below $0.001/M appears, add `micro_per_1m_tokens` by amendment; if a
paid study ever needs the router's `DeclaredPricing` path for real
spend, re-derive it from `PricingTable` rather than maintaining the
second table.
