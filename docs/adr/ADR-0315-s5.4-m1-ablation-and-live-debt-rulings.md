## Context

S5.4 lands four coupled pieces: the M1 attribution seam
(A10's additive extension — `component_targets` /
`attribution_design` desugaring, the `retirement`
recipe, `AttributionReport/1` rows over typed
`ComponentTarget`s), the *live* half of the assumption-
debt manager (trigger evaluation over the §05b
observables plus profile-change and evidence-
supersession triggers the compiler record evaluator does
not own, a `DebtIndex` fold, and notice routing), the
provider-drift compatibility path (synthetic
`SnapshotClaim` from `DRIFT`, `run_regression_suite`
verdicts, the `drifted ⇒ expiring` bridge), and the R2
bundle-level gates (profile pinning, image digests).
Eight spellings needed owned rulings — each a seam the
spec leaves to the implementation, each now with exactly
one spelling (CC1/CC7):

1. **How manager-level triggers coexist with the §05b
   record evaluator.** The compiler's
   `evaluate_record` folds the observable legs
   (retirement date, grace expiry, probe state, evidence
   age, non-inferiority, revalidation) into
   `StatusTransition`s; §5h.6 adds profile-change,
   evidence-supersession and probation-overrun triggers
   the record evaluator cannot see. Two evaluators would
   create two spellings of "expired".
2. **What a `ComponentTarget` reference grammar is.**
   §5h.7 names slot/variant/rule/parameter/leaf; the
   definition's typed kinds (decision points, text
   leaves) needed one closed enumeration and one
   canonicalization of the spec's `leaf` name.
3. **Whether a hosted row can ever join an M1 arm.**
   AC-R-2.9.7-10 renders hosted rows `n/a{class}` —
   except a hosted participant under `model_io`
   interception admits `observation_substitution` at
   configuration granularity. The exception needed
   exactly one admissibility predicate, never a widening.
4. **What "the two allocations are never pooled"
   (AC-R-2.9.7-4) means on the record.** A uniform
   allocation below every slot's search floor must render
   null effects — not silently drop the target — and the
   concentrating allocation must name what it funds.
5. **What the `retirement` recipe is.** R-2.9.7 names it
   as a designed ablation that answers "may this
   component leave"; the verdict grammar (pass / fail /
   inconclusive) needed one closed sum and the minimal
   present-tense removal must not invent component
   structure.
6. **How the regression-suite verdict folds.**
   AC-R-2.9.8-5 gives three verdicts
   (`verified` / `drifted{rules[]}` / `broken{ref}`) but
   leaves the fold order — a check that is both failing
   and drifted must have one canonical precedence.
7. **What a `DRIFT`-derived `SnapshotClaim` looks
   like.** The provider-drift path runs with no trainer
   (AC-R-2.9.8-10): the synthetic claim must be honest
   about what the host never observed — weights, policy
   exposure, cutoff provenance — and `guard_at_bind`
   must still refuse a *missing* claim.
8. **How R2 handles profile refs and image digests.**
   §8.3's R2 basis (inputs + base image pins) must extend
   to profile pinning and image digests without
   fabricating evidence: an empty closure is satisfied,
   a missing pin is a named basis row, never a silent
   upgrade or downgrade.

## Decision

**D1 — One evaluator: `evaluate_debt` delegates the §05b
legs and merges manager-level causes.** `hh_lab::debt::
evaluate_debt` calls the compiler's public
`evaluate_debt_record` wrapper for every profile rule's
debt record, then folds the triggers only the manager
can observe: `profile_change` (kind ⇢ cause —
`remove`/`retire` harden immediately, `amend`/`add` warn
through `model_version_change`-family causes),
`evidence_supersession` (a superseded evidence ref on a
record is `evidence_superseded`, warns only on `open`),
and `probation_overrun` (warn on `open`, expire on
`expiring`; `expired`/`retired` are terminal and never
re-warn). A hard transition subsumes warn causes for the
same rule; causes are sorted and deduplicated, so the
transition record has exactly one canonical spelling.

**D2 — `ComponentTargetKind` is a closed sum; `leaf`
canonicalizes to `text_leaf`.** Kinds: `slot`,
`variant`, `rule`, `parameter`, `procedure`,
`text_leaf`, `decision_point`. `component_targets`
enumerates the definition's typed coordinates and
accepts kind/substring filters; the spec's `leaf` alias
lowers to `text_leaf` at the boundary and unknown kinds
refuse (`invalid_component_target_kind`). More than 64
targets refuse — the report is a named artifact, not an
unbounded enumeration.

**D3 — One admissibility predicate for hosted rows.** An
attribution arm may join a hosted subject only when the
triple `intervention: "observation_substitution"` ∧
`interception: "model_io"` ∧ `granularity:
"configuration"` holds; every other hosted row renders
`n/a{class}` with the class named (never a fitted
scalar, never a zero). The predicate is checked in the
kernel, so the CLI and the embed op share the refusal.

**D4 — Budget regimes never pool and never silently
drop.** `budget.regime ∈ {uniform, concentrated}`. Under
`uniform` with `per_target_ms` below the estimand's
search floor, effects are emitted with `effects: null`
and the `below_search_floor` reason — the target stays
in the report and `budget_allocation_ref` names the
allocation beside it (AC-R-2.9.7-4). Under
`concentrated`, `concentrated_on` must name a subset of
the declared targets and only those targets receive
funded effects; the rest carry the unfunded reason.
`UnmatchedBudget` remains the experiment-boundary
refusal — arms outside the matched configuration-level
Δ never reach the kernel.

**D5 — `retirement` is an estimand-preserving recipe
with one verdict grammar.** The `retirement` recipe
lowers to M1 over the target set with
`removal_verdict ∈ {pass, fail, inconclusive}`: a target
whose LOI interval excludes 0 fails removal (it carries
value), a funded null effect passes, a below-floor or
hosted `n/a` cell is `inconclusive`. The verdict is a
row member — the recipe never mutates the definition.

**D6 — The verdict fold is drift-first.** A suite with
no results is `unknown`; all `pass` is `verified`; any
drifted check yields `drifted{rules[]}` with the rule
ids sorted and deduplicated (only *those* rules read
`expiring` through `regression_drifted_rules` — a
`broken` suite names its evidence ref but never
expires rules it cannot attribute); a fail or
unsupported check without any drift is
`broken{evidence_ref}`.

**D7 — Synthetic claims are honest about what drift
never observed.** `synthetic_snapshot_claim` mints a
claim with `snapshot_id = "drift:<drift_ref>"`, no
weights digest, unknown policy exposure, unknown cutoff
provenance, and no serving route — every member the
trainer path would fill reads its honest unknown. The
claim is still a *present* claim: `guard_at_bind(None)`
refuses `UnpinnedSnapshot` while any claim, including
policy-exposure-unknown, binds. `snapshot_span` renders
the drift arm's span over the registry.

**D8 — R2 gains two basis rows, and `[]` satisfies.**
`resolved_dependencies` carries `profile_refs[]` and
`images[]`; the level derivation emits `B-R2-profile`
(every profile ref `pinned: true`) and `B-R2-images`
(every image ref carries a string `digest`). An empty
member is satisfied by the section — the reproduction
basis never fabricates a pin it was not given, and a
missing pin lowers R2 with the gap named.

**D9 — The manager surface is records-in/records-out
Group L ops (AC-R-2.9.6-10).**
`lab.debt.{evaluate,index,report}`,
`lab.model.{snapshot_claim,regression}` and
`lab.analysis.{component_targets,attribution_design}`
exchange `DebtIndexRow`, `RemovalVerdict`,
`DebtReport`, `SnapshotClaim`, `RegressionVerdict` and
attribution documents through `hh-embed/1` — no private
verbs, and the embed fold is byte-identical to the
in-process `hh_lab::debt::debt_index` fold (asserted by
test). `hh-web` V10 reads `measurement.debt.*` /
`lifecycle.debt.*` rows and the `lab.debt.report`
surface; `hh-cli` exposes the same ops as nouns.

## Consequences

- The debt record's transition history is a single
  ledger: compiler legs and manager legs land in the
  same `StatusTransition` list, so `DebtIndex` folds
  stored status plus history without a reconciliation
  pass. The cost is that `hh-lab` depends on the
  compiler's record evaluator — the dependency direction
  was already established (S5.1).
- The 64-target cap means a designed ablation over a
  whole large profile must decompose by kind or filter —
  the report refuses rather than truncating.
- `drifted ⇒ expiring` is intentionally narrow: only a
  `drifted` verdict projects rule ids into the debt
  evaluator, so a `broken` suite never mass-expires
  rules. A provider swap that *should* retire rules must
  produce a drift verdict or an explicit retirement
  recipe run.
- R2's two new basis rows are additive: bundles without
  profile refs or images keep their prior derivation
  (`[]` satisfies), so the change is CC8-compatible.
- New owned vocabulary (kind names, `B-R2-*` basis ids,
  `drift:<ref>` snapshot ids, verdict reasons) is
  stamped in the schema and catalogue; a change to any
  spelling is a new ADR.

## Alternatives considered

- **A separate manager-side transition record** instead
  of merging causes into `evaluate_record`'s output.
  Rejected: two transition grammars for one lifecycle
  (CC1), and the index fold would have to reconcile
  orderings.
- **Emitting only funded targets in the report.**
  Rejected: a below-floor uniform allocation would
  silently drop the slots it could not measure — exactly
  the pooled-budget trap AC-R-2.9.7-4 exists to catch.
- **A trainer-side `broken ⇒ expired` bridge.**
  Rejected: `broken` cannot attribute failure to named
  rules; expiring all debt records on a broken suite
  would widen authority the evidence does not confer
  (CC2).
- **Requiring a weights digest on synthetic claims.**
  Rejected: the drift path runs with no trainer and no
  weights access — fabricating the digest would invent
  evidence (CC3).

## Revisit trigger

Reopen when the trainer (Stage 6) lands and regression
suites run over real pairs — the `drifted`/`broken`
precedence and the synthetic-claim shape should be
re-checked against trainer-observed evidence; likewise
when a fifth `ComponentTarget` kind or a hosted
intervention beyond `observation_substitution` is
proposed (the admissibility predicate must stay closed).
