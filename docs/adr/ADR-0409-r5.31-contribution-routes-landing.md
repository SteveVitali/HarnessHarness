# ADR-0409: R5.31 §8.1 ordinary contribution and failure-report routes — landing decisions

- **Status:** Accepted
- **Date:** 2026-11-03
- **Ticket:** R5.31 (Ordinary contribution and failure-report routes)
- **Requirement ids:** REQ-A-205, REQ-B-004 (primary ownership — the
  full-target R/P and actual-execution predicates stay owed per the
  coverage register); REQ-C-007, REQ-G-008, REQ-G-101, REQ-G-102,
  REQ-G-103, REQ-G-105, REQ-G-107 (contributing-only)
- **Spec:** docs/evidence-and-adoption-spec.md §8.1/§8.2 (lanes, report
  fields, verifyfixed, starter mapping, AC-8-1);
  docs/tickets/201_R5.31__contrib.md; design 18_contribution-path F1–F5
- **Rung (ADR-0024 obligation):** implementation landing record — the
  lane architecture, the route-checker contract and the CODEOWNERS
  reconcile; no RPC, no schema, no new dependency, no new event class

## Context

§8.1 reuses CONTRIBUTING, the issue/PR forms and the private security
route for ordinary contributions: a no-run failure report, an
existing-run/receipt report, a docs lane, and two routes that stay gated
(the optional packaged component and scientific replication). Ordinary
contributors need no internal question register, build ledger, or
manifest ritual; maintainers own program traceability and merges.
Reports attach only cleared data; a failed receipt leads to a candidate
verifyfixed that preserves the original. Before this ticket the bug
form asked for a reproduction and environment but no exit code, dirty
state, receipt identifiers, or sanitization attestation; CONTRIBUTING
had one undifferentiated report paragraph; and CODEOWNERS still said
"everything lands through the manifest ticket chain" — a guidance
discrepancy (design F1) that read as manifest bureaucracy on ordinary
PRs. No static check kept the route prose honest.

## Decision

1. **CONTRIBUTING.md is the lane home; the lanes are the documented
   contract.** "Report a problem or propose a change" splits into:
   `Report a failure without a run` (the §8.1 no-run field set —
   command, expected/actual, exit code/signal, revision + dirty state,
   OS/architecture, toolchain, features/backend/prerequisites,
   sanitized stderr, doctor-conditional), `Report a wrong run or
   receipt` (run/attempt/configuration/input + event/grade/procedure
   ids, expected-vs-observed semantic fields, the native receipt via
   the real `hh run export`/`hh bundle validate` locator, or the
   access/loss reason — suppressing it blocks the report),
   `Before you attach evidence` (the secrets/rights inspection and the
   uncleared-secrets block), `Propose a change` (docs ride the checks
   table), `Show a fix works: verifyfixed` (pin revision/input/recipe/
   rights, preserve the original, scratch copies, regression fails
   without, candidate comparison, unable-to-reproduce ≠ fixed,
   distinct verifier classes), `Two routes that are not open yet`
   (component + replication explicitly gated) and the starter
   owner→checks map.
2. **The bug form mirrors the documented fields.** `bug_report.yml`
   gains `exit` (code/signal), dirty-state wording on `commit`,
   toolchain/features/backend/prerequisites on `context`, an optional
   `receipt` textarea (ids + export locator or the access/loss reason),
   a `setup / build / startup (no run)` area option and a required
   `cleared` sanitization attestation. `config.yml`'s private
   security-advisory route is unchanged.
3. **`scripts/check-contributing.sh` is the static both-modes check.**
   Working-tree and `--head` (clean clone of committed HEAD) modes,
   twelve check ids (`lanes`, `no_run`, `receipt`, `privacy`,
   `verifyfixed`, `no_ritual`, `gated`, `form_fields`, `commands_real`,
   `blocked`, `codeowners`, `links`). `commands_real` extracts the
   dispatch arms from `crates/hh-cli/src/cli.rs` and refuses any `hh`
   citation the CLI does not implement — `hh bug-bundle`,
   `hh recompute`, `hh replicate` stay unadvertised. It ends with an
   honest `live: skipped(…)` line — never a pass.
4. **CODEOWNERS' broad wording is reconciled, governance preserved.**
   `* @SteveVitali` review authority is unchanged; the comment now
   scopes the manifest ticket chain to assigned build tickets and
   states ordinary PRs carry no build-ledger or question-register
   ritual. The §8.1 "later reconcile" clause lands here because the
   broad wording was itself the manifest-bureaucracy defect AC-2
   names; review ownership is untouched.
5. **The workflow step is `ci-mode: both`.** The checker reads
   committed CONTRIBUTING/.github content and resolves repo-relative
   links into docs/ — a docs-only head that drifts a lane or breaks a
   link it cites must not take the fast path green (the
   check-examples/ADR-0408 precedent).
6. **Later contributor evidence stays owed.** R5.50 owns the packaged
   component predicate; R5.52 owns outside review/replication
   evidence; R5.53 owns participant observations for the
   contributing-only ids. This ticket records engineered D/E only and
   never marks a deferred full-target predicate met (I-07).

## Consequences

- Ordinary reports/PRs have one documented contract and one static
  check; a docs-only head that drops a field, ungates a future route,
  or re-imposes manifest ritual fails the lane.
- The lanes assert real CLI routes only — no fictitious bug-bundle or
  replication interface can be documented without dispatch evidence.
- The issue form's required `cleared` attestation makes the secrets
  rule a mechanical block, not a courtesy.
- CODEOWNERS wording is living guidance; the reconcile is a
  comment-scope fix. A future maintainer-model change re-runs this
  lane (the `codeowners` check pins owner review + scoped wording).

## Alternatives considered

- **A second receipt-report issue form** — rejected: design F1 reuses
  the existing forms; the `receipt` textarea is optional so a no-run
  reporter is never blocked by a field it cannot fill.
- **Deferring the CODEOWNERS reconcile** — rejected: the broad wording
  directly contradicts the no-ritual route this ticket must provide;
  the spec's reconcile clause is governance-preserving exactly as
  landed (review authority unchanged).
- **A gated (`mode != 'fast'`) CI step** — rejected: the checker reads
  committed content a docs-only head can drift; `ci-mode: both` is the
  landed precedent.
- **An interactive/live lane** — rejected: §8.1 creates no routine PR
  live calls; the lane is recorded `skipped(…)` until a separately
  authorized ADR-0363 leg exists.

## Revisit triggers

- If a contribution lane is added, renamed, or merged (a new starter
  kind, a docs reorganization), re-read the `lanes` heading set — the
  checker asserts the current headings verbatim, and a lane lands by
  updating the doc and the expected set together.
- If the packaged-component or replication gate opens (R5.50/R5.52
  land their checked recipes), re-read the `gated` leg — the
  not-open-yet section must become the real route, not an
  advertisement layered on top.
- If `cli.rs`'s dispatch shape stops matching the `("a", "b")` /
  `("a", _)` arm patterns, re-read the `commands_real` extractor —
  it derives the command contract from the owning source, never a
  second table.
- If issue-form fields are restructured (type/id renames), re-read the
  `form_fields` leg — it asserts the documented ids literally.
- If review ownership moves off `* @SteveVitali` or per-area owners
  land, re-read the `codeowners` leg — it pins the current
  governance-preserving shape.
