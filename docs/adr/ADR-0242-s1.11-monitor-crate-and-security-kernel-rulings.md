## Context
S1.11 lands the reference monitor's C0/Stage-1 slice: the `AuthorityHandle`
record and table projection, root minting ∩ `authority_cap`, `authorize`
steps 0–3 and 6, the Π interpreter and default table in both modes, the
complete-mediation append rule, assessors (i)–(ii), the kernel
`context_label` stamp, the TCB enumeration and the static no-text/no-model
check. The spec fixes the record shapes, the decision order, the Π rows and
the invariants but leaves these concrete rulings to the slice:

1. **Where the complete-mediation rule lives and what it keys on.** §5g.1
   I-H7 makes it an *append rule* ("the ledger refuses
   `action.effect.committed` unless a `security.permission.decided{decision
   = allow}` for that `effect_id` and attempt cycle precedes it in `seq`;
   exactly one `decided` per attempt cycle"). `hh-ledger` already validates
   effect lifecycle transitions; the `decided` gate needs a fold shape that
   is strict at append and honest on rebuild, and a definition of which
   `decided` rows are *final* (ADR-0070 D3's `timed_out`/`cancelled` closures
   and the `ask` verdict are not gate verdicts).
2. **How `authorize` stays pure while consuming assessor output.** §2.3(ii)
   makes deterministic argument analysis the kernel's own assessment and
   ADR-0100 makes assessors executor-registered pure functions run at
   `resolve`. A Stage-1 `authorize` that is a pure function over records
   cannot *run* assessors — it needs their results as recorded inputs.
3. **What `scope ⊆` means while OQ-132 is open.** ADR-0212's interim defers
   the closed `ResourcePattern` grammar (path roots, command classes, host
   sets, secret names); grant coverage still needs a decidable matcher now.
4. **How `Permission.issuer` maps to I-H2's conferral rule.** I-H2 reads
   `issuer.authority ≥ principal ∧ issuer.origin ∉ {model, evolution,
   participant}` — but `Permission.issuer` is `{authority, reference}` (a
   declared class plus an identity coordinate), not a `ProvenanceRecord`.
   The `origin` half needs a defined read.
5. **Which `authorize` steps exist at Stage 1.** §9 lists "steps 0–3 and 6"
   plus "the Π interpreter and default table in both modes" — step 4 is the
   taint gate *through* Π, and steps 5/7/8 (persistence ceiling, approvals
   feasibility, lease cache) are Stage-2 by the same table.
6. **How E2's "totality over `argument_order`" is checked.** S1.10's
   `e2_check` verified map *entries* against the capability schema but took
   "arg_map covers argument_order" as constructional — an authored surface
   field absent from `SurfaceArgMap` compiled clean. AC-R-2.8.1-10's static
   half makes that a compile failure.

## Decision
- **§1 — one persistent crate `crates/hh-monitor`,** deps
  `hh-wire`/`hh-identity`/`hh-provenance`/`hh-ontology`/`hh-hir`/
  `hh-assembly`/`hh-compiler`/`hh-ledger` only (CC4/CC5 — a pure function
  over canonical records; no clock, randomness, environment, network, model
  client or `Text` leaf on any path). The no-`Text`/no-model boundary is
  enforced three ways: by construction (no `Text` in any signature), by the
  `tcb` source scan, and by the `guard::DecisionGuard` runtime trip
  (`ModelCallDuringDecision`).
- **§2 — the mediation fold is keyed on `(effect_id, attempt_no)` and writes
  final verdicts only** (`hh_ledger::effect::DecisionFolds`,
  `validate_decision`/`apply_decision`). `decided{decision ∈ {allow, deny}}`
  are the gate verdicts; `ask`, `timed_out`, `cancelled` and request-closure
  rows never write the fold. The decision's effect is `scope.effect_id`
  falling back to `payload.effect_id`; the attempt is `payload.attempt_no`
  else the effect's pending attempt. At *append* the fold is strict: a
  second final `decided` for the same key is `LedgerError::DuplicateDecision`
  and `committed` without a prior `allow` is `LedgerError::Undecided`. At
  *rebuild* the fold is lenient (first final verdict wins — the durable
  record was already validated), so a rebuilt store reproduces the same gate
  state.
- **§3 — assessor results arrive as recorded data on the `Proposal`.**
  `Proposal.inputs: AssessmentInputs` is the closed record of what the
  executor-registered assessors computed at `resolve` (path canonicalisation
  and writable-root containment, command class, host-in-allowlist,
  sole-recipient, compensation registered, child containment, secret
  transport, destination∈grant.scope, spend-over-soft, pre-authorization) —
  recorded, never re-read (ADR-0100). Every member is `Tri{yes,no,unknown}`
  where `unknown` never satisfies a `yes`-condition; the risk fold maps any
  unverifiable input to the dangerous answer (`unknown ⇒ irreversible ∧
  external`, §2.3/Π-11). `kernel_assessed` projects the declared
  `EffectAttributes` (i) joined with the recorded argument analysis (ii);
  `apply_self_report` applies (iv) raise-only — a model "LOW" can never
  lower a kernel "HIGH".
- **§4 — the interim scope matcher is `{literal, prefix-*, *}` over
  canonicalized paths.** Under ADR-0212 OQ-132 the closed `ResourcePattern`
  grammar is open; the interim rule is: `*` covers everything; `p/*` covers
  `p/` descendants (prefix on the canonicalized form); a literal matches
  verbatim. `ScopeBindings::Unknown` (ADR-0087's `scope_bindings_unknown`)
  has *no* canonical scope, so only an unscoped `*` grant covers — a
  pattern grant can never cover an unknown binding (the fail-closed half of
  ADR-0087 D3). Command classes, host sets and secret names defer to the
  OQ-132 grammar (their `AssessmentInputs` members are already closed and
  recorded).
- **§5 — I-H2's `issuer.origin` reads the `Permission` node's provenance
  origin, not the issuer reference.** `mint_root_handles` checks
  `issuer.authority ≥ principal` from the declared `issuer.authority` class
  and the *node's* conferring origin (seal-endorsed `definition` at mint) for
  the `{model, evolution, participant}` exclusion — a `Permission` entity
  whose own provenance is model/evolution/participant-origin may never
  confer (`IllegitimateIssuer`). The minted handle's `issuer` is
  `definition`-authority provenance; `origin_basis = seal`; `basis_ref` is
  the definition ref. The mint takes no content input at all (H-3 by
  construction — the sealed document, the principal's provenance and an id
  allocator only).
- **§6 — `delegate(parent, spec, coords, alloc)` attenuates, never clips.**
  The request packs as `ChildSpec{holder, requested, ceiling, budget_req}`.
  Every requested grant must be covered by a `delegable` parent grant — same
  domain, class covered, scope ⊆ under §4's matcher, `count`/`time`/`budget`
  tightening (`bound_le`/`json_le`: a parent bound must appear on the child
  at `≤`) — else `AuthorityWidening`/`NotDelegable`/`BudgetExceedsParent`, a
  request never rounded up. `ceiling = min(requested, parent.ceiling)`; the
  §2.5-row-1 floor refuses `environment` mints carrying `fs_write`/`exec`/
  `secret_access`; a dead parent is `ParentNotLive`. `revoke` cascades
  through `parent_handle` descendants in one fold (`HandleTable::revoke`).
- **§7 — `authorize` runs steps 0–3 and 6; step 4 lands as its
  authority-form half.** The Π gate is consulted when `eff ≤ external ∨
  taint ≠ ∅` and the class is not `read_only ∧ closed` (Π-1's exemption);
  otherwise the ADR-0031 floor decides (`floor_verdict`: `allow` except
  `irreversible ∧ external`, `secret_access`, `spend`, `permission_request`
  ⇒ `ask`). Π-12's unattended `ask → deny{UnattendedAsk}` applies to both
  paths. Steps 5 (persistence ceiling), 7 (approvals feasibility — the
  Stage-1 `ask` *is* its unconditional form, options carried) and 8 (lease
  cache) are Stage-2; `KernelDecision` omits `assessment_inputs_ref`,
  `cache_key`, `remedy_taken` rather than nulling them (CC8 — absent, not
  stubbed).
- **§8 — the closed decision sums are declared complete.** `DenyReason` is
  the §3 closed sum verbatim (including the Stage-2 members
  `ScopeCeilingExceeded`, `ApprovalsExhausted`, `ApprovalTimedOut`,
  `ContainmentUnverified`, `containment` — declared, not emitted); `Decider`
  is the one CF-153/CF-312 sum `{policy, cache, hook, auto_reviewer, human}`
  with only `policy` produced at Stage 1. Growth is a dialect bump (CC8).
- **§9 — `e2_check` proves totality, not assumes it.** `check_equivalence`
  now reads the surface's `argument_order` and fails compilation when a
  declared surface field is absent from `arg_map` ("surface field {arg} is
  absent from the SurfaceArgMap") — AC-R-2.8.1-10's static half, so an
  unmapped surface field can never reach the monitor's runtime
  `UnmappedArgument` silently.
- **§10 — the TCB is enumerable data plus a token scan.** `tcb::TCB_INSIDE`/
  `TCB_OUTSIDE` carry the §2.6 lists verbatim (adding to them is an ADR —
  declared, non-overlapping, tested). `static_check` scans this crate's
  sources with string literals blanked and token-boundary matching — the
  belt over the type-level guarantee (no `Text` in any signature); a
  `model_call(` *call site* trips it while deciding on a `model_call`
  *effect domain* does not.
- **§11 — `HandleId` spelling is detection-only.** `HandleId::parse`
  recognises the `hnd-*` shape for `leak` scans and event decoding but
  confers nothing — authority resolves only from live `HandleTable` rows
  (I-H1; `ac_2_forged_handle_id_confers_nothing`).

## Consequences
- `action.effect.committed` cannot be appended without a preceding
  `decided{allow}` for the same `(effect_id, attempt_no)` — the rule is in
  the ledger, so no monitor caller can bypass it (I-H7; the four
  `committed`-emitting test call sites now emit the decision first).
- `security.permission.decided` rows are self-describing gate inputs:
  `effect_id`, `decision`, `effective_authority`, `effective_risk_class`,
  `handle_ids[]`, `policy_ref`, `decider`, and the closed
  `reason`/`options`/`remedies` members — the `checks[]` trail makes every
  verdict reconstructible from the record (ADR-0066 D5).
- The interim matcher is sound-but-incomplete by design: it can only fail
  *closed* (a scope the grammar cannot yet express reads as uncovered, never
  over-covered). When OQ-132 lands the closed `ResourcePattern` grammar the
  matcher gains forms; no existing verdict may move toward `allow` without a
  `policy_delta`-visible change.
- New obligations opened: DF-S1.11-1 (the §5g.1 §9 Stage-2 halves —
  `approval`-basis handles, `permission_request`, lifetimes H-7, steps
  5/7/8, `replay`/`assessment_inputs_ref`, reviewer/hook admission), DF-S1.11-2
  (the Stage-3/4 executable acceptance — AT-H1-01…-09/-12…-15, delegation
  through the one `spawn`, check 8 at C3), DF-S1.11-3 (AC-R-2.8.1-16's
  out-of-process `authorize` byte-equality — Stage 2).

## Alternatives considered
- **Mediation inside `hh-monitor` as a `commit_guard` the caller must
  invoke.** Rejected — I-H7 says *append rule*; a caller-invoked guard is
  bypassable. The fold lives in `Store::append`'s validation loop beside the
  effect fold it extends (one scheme per concern — CC1: the same
  `(effect_id, attempt_no)` key space the lifecycle already uses).
- **Running the deterministic assessors inside `authorize`.** Rejected —
  §2.1 makes every operation "pure over records"; ADR-0100 makes assessors
  executor-registered and run at `resolve`. Re-running at authorize would
  both break purity (an assessor could read content) and make replay
  non-deterministic. Recorded `AssessmentInputs` on the proposal keep the
  decision a function of the record (and `assessment_inputs_ref` is the
  Stage-2 field that pins them).
- **Emitting the Stage-2 `KernelDecision` members as `null`/empty.**
  Rejected — a nulled field is a lie about the record shape; absent members
  keep `/1` honest and let Stage 2 add them as declared fields (CC8).
- **A heuristic scope matcher (substring/glob-anywhere) as the interim.**
  Rejected — a matcher that can over-cover is a grant-widening hole;
  literal/prefix/`*` is the largest matcher provably containment-safe under
  path canonicalisation.

## Revisit trigger
S2's landing of steps 5/7/8, `approval`-basis handles and `replay` (the
`DenyReason`/`Decider` Stage-2 members gain emitters; `KernelDecision` grows
its declared fields); OQ-132's closed `ResourcePattern` grammar replacing
the §4 interim matcher; OQ-133's command-class list; or a spec amendment
changing the Π floor rows, the `DenyReason` sum or the §2.2 step order.
