# ADR-0306: S4.14a supply-chain trust & third-party install rulings

- **Status:** Accepted
- **Date:** 2026-09-28
- **Ticket:** S4.14a
- **Requirement ids:** R-2.8.5 (C1; AC-R-2.8.5-{4,6,7,8,9}),
  R-2.8.7 (C1 Stage-4; AC-R-2.8.7-{3,8,10,12,13}), R-2.12.2¹
- **Spec:** §5g.5 (extension trust, `TrustRootPolicy`, drift
  policy, install procedure); §5g.7 §4/§5 (delegated approval,
  `auto_review`, repeated-denial fallback); §5d.4 P (the ACP
  permission transport); §8.3/§8.4 (supersession, placements);
  ADR-0063…0071 (the owning ADR set); OQ-177 (the
  delegated-approval interim)
- **Rung (ADR-0024 obligation):** **C0/C1** — supply-chain trust — C0 enforcement + the C1 extension lifecycle.

## Context

S4.14a lands the extension supply-chain trust surface at C1 plus
the third-party install path: `TrustRootPolicy` gates
(source allowlists, required attestation predicates, signature
quarantine, `max_attestation_age` → `StalePin`), surface pins and
the three drift policies, advisory `review`/`approve_seal_diff`,
update/supersession with named regressions, revocation
propagation, the `ApproverGrant` lifecycle, the calibrated
`auto_review` binding, the ACP `session/request_permission`
round-trip with structured losses, foreign plugin import/export,
and `container`/`remote` placements. Five rulings the slice
needed:

1. **What an `ApproverGrant` conferral is.** OQ-177 left the
   interim as ambient responder state; AC-R-2.8.7-3 requires the
   grant *record* to confer. Where the record lives, who may
   mint it, and whether a delegate may re-grant were all open.
2. **Where the `auto_review` binding is enforced.** The
   calibrated-reviewer facts (`permissions ⊆ parent ∩
   read-only`, `net_egress = ∅`, evidence floor, calibration
   ref) live on sealed `Validator{kind: judge}` records — a
   registry the monitor never reads (CC1).
3. **How the ACP permission projection names its losses.** The
   kernel ask carries members ACP's option vocabulary cannot
   express (`modify`, `escalate`, `abort_run`, `max_uses`,
   `deadline`); dropping them silently is a CC3 violation and
   refusing the whole ask starves the transport.
4. **What a dropped surface pin on update means.** A successor
   manifest that removes `trust.surface_pin` silently widens the
   trust posture; the assessment must name it or the widening
   gate misses the regression.
5. **How foreign plugin trust claims admit.** Foreign manifests
   (Claude `plugin.json`, Gemini `gemini-extension.json`, Codex
   `agent-plugin`) carry trust-shaped members; admitting them as
   grants would let import confer authority (CC2).

## Decision

- **D1 — The `ApproverGrant` is a ledgered record; the record
  confers, never the name (OQ-177's interim resolved).**
  `grant_approver` mints `{grant_ref, grantor, grantee,
  capability_prefixes[], max_risk, expires_at?, revoked_at?}`
  with `grant_ref` content-addressed over the minted record;
  the caller appends `security.permission.grant_issued` and
  `ApprovalState::project` folds it (`crates/hh-monitor/src/
  approval.rs`; the class row + hosted-lowering pair are
  registered in `crates/hh-ledger/src/classes.rs`). Legitimacy
  is typed: a `principal+` grantor bootstraps; otherwise the
  grantor must be the `grantee` of a live grant that
  `covers_grant`s the sub-grant — delegation never widens
  (prefixes ⊆ the covering grant's, `max_risk ≤` its ceiling).
  `revoke_approver` is grantor-or-principal+ only; a delegate
  cannot revoke upward. The respond-path gate accepts an
  `EndorserRef::ApproverGrant{grant_ref}` only while a live
  grant covers the pending's capability and the decided risk;
  an illegitimate response decides nothing and the pending
  survives.
- **D2 — The `auto_review` binding is caller-asserted and
  every clause is a typed refusal.** `check_auto_review_binding`
  takes a `ReviewerBinding` the caller constructs from the
  sealed validator record — the monitor checks the admitted
  facts, never the registry (CC1). Each broken clause is its own
  variant (`Uncalibrated`, `PermissionWidening`,
  `EgressAdmitted`, `EvidenceBelowFloor`) — an uncalibrated
  reviewer never serves a resolve. A reviewer *failure* resolves
  `deny` above `reversible` risk (`auto_review_failure_denies`);
  read-only/reversible failures fall back to `pass` so the
  human stage still sees the ask. The durable verdict row is
  `security.permission.reviewed{permission_id, rule_ref,
  validator_ref, verdict, calibration_ref?, evidence_refs[],
  failure?}` — `calibration_ref` is the AC-R-2.8.7-13 debt
  record's coordinate.
- **D3 — ACP permission lowers preserve the kernel members
  under `params._hh` and report every unexpressible member as a
  named `hh-edge-loss/1` loss.** `preserved_wire_member` carries
  `permissionId`, `effectId`, `effectiveRiskClass`,
  `reasonCode` verbatim plus a `lossReport` when
  `permission_losses` finds `modify`/`escalate`/`abort_run`/
  `max_uses`/`deadline` at the top level or under
  `options_presented[]` — the wire projection never silently
  narrows (AC-R-2.8.7-10, CC3). Inbound, `inbound_losses`
  surfaces agent-side members (`options[].kind` spellings,
  `maxUses`, `deadline`) on `PermissionRequest::losses` so the
  Π gate names what it could not express back. The response
  lift stays deny-by-default: any outcome spelling outside
  `{allowed, selected, denied, cancelled}` parses to `Deny`.
- **D4 — A dropped `trust.surface_pin` on update is a named
  `LabelRegression`, and the widening gate fires on both legs.**
  `update_assessment` compares old/new manifests on two axes:
  new contribution paths (hook paths today) set `widening` and
  `requires_human`; a `surface_pin` present on the predecessor
  and absent on the successor appends
  `regressions[{field: "trust.surface_pin", now: "unpinned"}]`.
  Regressions are data the human gate reads — never a silent
  narrowing of the assessed delta.
- **D5 — Foreign plugin formats import quarantined, and
  foreign trust members are claims, never grants.** The
  `ForeignPluginFormat` closed sum admits `claude`,
  `gemini`, `codex`; every import lands `quarantined` with a
  `LossReport` naming the members that did not lift. Gemini
  `trust` members lift as *claims* on the record (advisory,
  external authority) — they never mint a grant, an admission,
  or an attestation (CC2 — imported content cannot confer).
  Export/re-import is a lossy-by-declaration round trip: what
  the foreign shape cannot hold is named in the report.

## Consequences

- Grant legitimacy is fully replayable: `ApprovalState::project`
  rebuilds the live grant set from `grant_issued`/`grant_revoked`
  rows, so a rebuild legitimates exactly the same responses as
  the live path (CC1 — no second source of truth).
- A delegate chain can delegate approval, but the
  `covers_grant` check makes monotonic narrowing structural —
  there is no code path that widens through delegation.
- The `auto_review` stage's safety properties are checkable
  data: an arm declaring `approval_mode = auto_review` without a
  calibrated binding is a typed refusal the recipe measures,
  not a latent misconfiguration.
- ACP peers and honest clients can read exactly what the
  permission projection kept and lost; a denial on an
  unrecognised outcome can never flip to allow by accident.
- Foreign imports can never widen into admission — the worst a
  crafted `plugin.json` achieves is a quarantined record with a
  complete loss list.

## Revisit trigger

Reopen when (a) OQ-177 is superseded by a first-class grant
*surface* (a registry kind rather than a ledger class — D1's
record then migrates behind the same conferral rule), (b) the
monitor gains registry read access for sealed validator records
(D2's caller-asserted binding then upgrades to a checked ref —
until then the binding stays input data, CC1), (c) the ACP
schema adopts a native home for the `_hh`-preserved members or
the lost option kinds (D3's loss names then drop to zero), (d)
a foreign format defines an attestation leg the import can
verify (D5's claims-not-grants floor then lifts for that
format's verified members only), or (e) `remote` placement
acquires a measured isolation verdict (the session's honest
`isolation()` reporting then feeds the admission gate rather
than only the audit row).
