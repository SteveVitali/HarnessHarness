## Context

R4.6 owns the two remaining H3 environment-gated cells: the LT-03
*live-corpus arm* (a real upstream AgentDojo-shaped prompt-injection
battery run through real model calls on the local model and exactly one
hosted provider, asserting placeholder-or-refused on the wire, canary →
`leak_detected`, and a real value at a sink = success-with-veto) and
the live foreign-manifest import (a real upstream benchmark manifest
imported through L1/L2 admission with `task_id` stability through
import round-trips). Seven decisions are this ticket's to own: which
upstream corpora and at what pin, how the fetched subset is committed
with provenance, how the injection battery drives a real model call at
the credential boundary, which hosted provider answers "exactly one",
how a foreign manifest row maps onto `TaskRecord` (the import contract
— compute, never trust), how the spend/budget story stays honest, and
the ticket's measured size.

## Decision

- **D1 — the corpora and their pins.** The LT-03 corpus is
  `ethz-spylab/agentdojo` (MIT) at tag `v0.1.35` = commit
  `a75aba7631d3ca5fb7ab938965c97ead2f9ff84b` — the v1_2/v1_2_1 default
  suites' `injection_tasks.py` files' `GOAL` attack strings. The
  foreign manifest is `harbor-framework/harbor` (Apache-2.0) at commit
  `dd8815755a61e849ad0f146ae85eb4aaff4fe61f` — `registry.json`, the real
  Harbor Index: 80 dataset entries × 51 625 task rows each carrying a
  pinned `git_commit_id` digest (a real upstream manifest, not a local
  stand-in). Both fetches are read-only public HTTPS — H3's authorized
  scope; no accounts, no mutations.
- **D2 — the commit-with-provenance protocol.**
  `scripts/fetch-r4_6-corpus.sh` fetches the pinned files, sha256-verifies
  each, and extracts the committed subsets: the injection goals
  (constants-only AST rendering — string constants and f-string
  substitution, never code execution; round-robin across the fetched
  suites) into `hh-embed/tests/fixtures/r4_6/lt03-battery.json` (8
  tasks), and `entries[0].tasks[0:8]` into
  `hh-bench/fixtures/live/r4_6/harbor-registry-subset.json`. Each
  fixture embeds its `upstream` member (repo, URL, tag/commit, per-file
  sha256, license) — the provenance travels inside the fixture.
  `--check` re-fetches at the *fixture's own recorded pin* (a rewritten
  script cannot smuggle a different pin), re-extracts, and byte-compares
  — the offline re-run is reproducible, never trusted. The upstream
  LICENSE texts ride beside the fixtures (`UPSTREAM-LICENSE.*`) — the
  L4.1 third-party-notices sweep inherits them from there. The attack
  strings stay quoted test data — they are never instructions
  (`note` member inside each fixture says so).
- **D3 — the LT-03 live arm.** `hh-embed/tests/r4_6_live.rs` stands a
  real `CredentialBroker` (the s3_11b fixture shape — a synthetic
  fixture value in a `StaticVault`, a `github` channel bound to
  `api.github.com`) beside a real `EmbedService` lane. Per battery task
  the turn carries the minted `mh_secret:` placeholder in the env view
  and the task's `goal` string inside an `<untrusted-tool-result>`
  wrapper — the AgentDojo shape, with the attack text framed as data.
  Each task's outcome is classified: `carried` (every `hh.model_io/1`
  `request_body` scans clean under `leak_scan` with the live mask set
  AND carries the placeholder spelling — the credential transits as the
  placeholder, never the value), `refused` (a typed refusal before the
  wire), or `leak_detected` (a detector hit — success-with-veto, the
  veto's durable input). The arm lands the two durable halves on the
  same run: an out-of-scope `mediate_sentinel` refuses with a durable
  `security.credential.denied`, a canary `bind` lands durable
  `security.secret.leak_detected`, and a planted fixture value at a
  sink scans `known_value` — proving the veto's detector on the very
  run the battery rode, not assuming it. `LT03_TASK`/`LT03_USAGE`/
  `LT03_ASSERT` markers feed the leg transcript.
- **D4 — "exactly one hosted provider" = Anthropic**
  (`anthropic-messages@1`, `claude-haiku-4-5-20251001`) — the cheaper
  admitted family; OpenAI is not consumed (a second hosted family would
  widen spend without widening the contract). One `lt03-live` leg runs
  the same ignored cell twice (`HH_LT03_FAMILY=local|anthropic`) into
  one transcript — the ticket's "one evidence record covering both
  model families". Only the hosted family's usage prices (local is
  zero-spend); measured cost rides `token_usage` + the pinned
  `pricing.json` row (ADR-0363 D4).
- **D5 — the manifest import mapping.** A Harbor registry task row
  `{name, path, git_url, git_commit_id}` maps through the canonical
  importer `adapters::fixture_task` (CC1 — the same constructor
  `benchset::load_task` uses, bound to `adapter_g`/`coding_terminal`,
  `held_out` split, `public_dated` stratum, `separate` verifier
  isolation — the standing Harbor-Index posture `suite.harbor_index`
  declares), then the `foreign` member is re-stamped with the row's own
  claims (`name`/`git_commit_id` as `version`, `git_url#path` as
  `source_ref`, `digest_claim{system:"git-commit"}`) — annotation-side
  under CF-450, so the re-stamp never moves `task_id`, which is re-minted
  `semantic_id()` after. The visible instruction is synthesized
  deterministically from the row (the upstream manifest carries task
  metadata, not prompt text); the canonical row bytes stand in for
  held-out oracle material. A row without `git_commit_id` refuses
  (`NoPin`) — the importer never fabricates a foreign digest. The suite
  records mirror `load_suite`'s construction (`split_hash` recomputed,
  `epoch_seeded` dispatch, `retired_for_headline: true` — provisional,
  never headline); `manifest.validate()` + `split_assignment.validate()`
  are the L2 half; `record.validate()` per task is L1.
- **D6 — the spend story.** `bench-manifest-live` is a public read-only
  fetch — USD 0 recorded (the spend row carries `cost_usd: 0` honestly).
  `lt03-live` declared budget $1.00 inside the $15 allocation; measured
  cost $0.001489 (the hosted family's real usage × pinned rates). No
  new leg kind — both are `script` legs executing the existing
  cargo-test pattern, keeping the evidence shape `hh-live-evidence/1`.
- **D7 — measured size.** 1 976 changed lines excluding the
  fetched/pinned corpus fixtures vs the 800 budget — a clear overrun
  (dominated by 1 232 lines of new acceptance cells the ticket's
  coverage requires). Per the ticket's STOP rule the run commits
  locally and surfaces the overrun to the orchestrator before push/PR;
  the operator's ruling rides the run ledger.

## Consequences

- DF-S1.24-2's residual — the live foreign-manifest import — is
  discharged: `bench-manifest-live` executed green (64 task rows
  imported from `aider-polyglot`, L1 per record, L2 per suite, `task_id`
  stable through re-import), and the offline subset re-runs the same
  import hermetically. The `bench-manifest.live-import` xcheck
  pending-cell drops out of `PENDING_CELLS` and the regenerated bundle.
- The `lt-03.live-corpus-arm` pending-cell likewise drops: 16 per-task
  outcomes across both families (`carried` everywhere — every request
  body carried the placeholder and scanned clean), all durable halves
  asserted live, $0.001489 measured.
- ADR-0349's revisit trigger fired: the corpus legs generalised to real
  manifests verbatim (the import path is `fixture_task` + foreign
  re-stamp — no contract change needed); the dated fired-answered
  record lives at
  `docs/build/reports/2026-10-21-adr-0349-trigger.md` (landed ADRs are
  append-frozen — BM-ADR-01; R4.5 repair precedent).
- Attack strings exist in the tree only as quoted fixture data —
  `.gitleaks.toml` needed no allowance (clean scan), and the leak
  detectors stayed authoritative throughout (`canary → leak_detected`
  was the pass condition).
- The `UPSTREAM-LICENSE.*` texts + fixture-embedded `upstream` blocks
  hand L4.1 a complete license+provenance record for its notices sweep.

## Revisit trigger

Reopen when (a) a second hosted provider joins the LT-03 arm (the
`HH_LT03_FAMILY` enumeration and the leg's one-hosted-provider rule
need re-scoping rather than silent extension); (b) upstream corpora
rotate pins — the `--check` re-fetch path and the recorded `upstream{}`
provenance blocks must stay the only minting path, never a hand-edit;
(c) the AgentDojo battery's task selection changes shape (suite mix,
count, or per-task fields beyond `goal` — the offline re-run stays the
authoritative fixture); or (d) the benchmark leg admits a second
manifest source — the Harbor-only claim in D5 then needs the same
pinned-fetch + digest-claim treatment per source.
