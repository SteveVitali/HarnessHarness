# ADR-0353: R2.21 cross-implementation packaging — the committed `hh-xcheck-bundle/1` replay bundle, and the environment-pending disposition of the foreign cells

- **Status:** Accepted
- **Date:** 2026-10-09
- **Ticket:** R2.21
- **Requirement ids:** BL-01 · DF-S0.3-2 · DF-S1.2-2 · DF-S1.5-3 ·
  DF-S1.8-1 · DF-S1.27-1 · DF-S1.24-2 (live cell) · DF-S1.13-3 (LT-03
  live-corpus arm) · R-2.12.1 · R-2.12.2 · R-2.12.3 · R-2.12.6 · CC1 ·
  CC7
- **Spec:** §10.7 (cross-implementation verification — the second-
  implementation discipline) · §10.6 (GATE-G1 revalidation posture) ·
  §8.4 (the `PluginManifest/1` checker corpus).
- **Rung (ADR-0024 obligation):** C1 — every landed leg executes at the
  offline/fixture ceiling: `hh-xcheck export` emits the bundle from the
  committed corpora, `hh-xcheck selfcheck` replays it hermetically
  through the E1 implementation, and `hh-xcheck verify` is a pure
  comparator over an `answers.json` — no foreign toolchain, no network,
  no credentials are touched, and none is claimed (`pending_cells[]` in
  `bundle.json` carries the open foreign cells verbatim).

## Context

R2.21 (BL-01) carries the cross-implementation verification cluster:
the S0.3b spike proved two foreign runtimes (E2 Python, E3 Node) could
reproduce E1's identities over an ad-hoc shared corpus, but that
machinery is throwaway (`spikes/s0.3b-online-spike`, outside the
workspace) and pinned to Stage-0 corpus shapes. The DF rows the ticket
addresses all need the same durable artifact before any foreign run:
the *current* committed corpora packaged language-neutrally, with the
pinned answers and a checker contract a second implementation is held
to. Three rulings were the ticket's to make:

1. **What is packaged, and from where.** The corpora live scattered —
   `hh-identity`'s golden tree/record pins, `hh-ledger`'s byte-stable
   WAL transcript test, `hh-registry`'s snapshot corpus builder, the
   `plugin-manifests` fixtures, plus the parse-size bands S0.3b timed.
   A bundle could copy outputs (hashes only) or inputs-plus-outputs.
   Only inputs-plus-outputs lets a foreign implementation actually
   *replay*: the manifest bytes, the WAL frames, the registry log, the
   manifest fixtures — with `expected` as the comparator target.
2. **Where the replay logic lives.** Re-running per-crate unit tests
   is not a foreign-checkable artifact; a bundle must be self-describing
   (its own `CHECKER.md` contract travels inside it) and checkable by
   a language-neutral CLI.
3. **How the foreign half is recorded.** HUMAN-H3's foreign-toolchain
   environment is not provisioned (credentials provided: no). The
   ticket's honesty floor forbids minting a foreign claim — the pending
   cells had to be recorded *in the artifact* so the packaging itself
   cannot be misread as coverage.

## Decision

1. **New crate `hh-xcheck`, format `hh-xcheck-bundle/1`.**
   `hh_xcheck::export::export_bundle` writes six arms under
   `crates/hh-xcheck/fixtures/cross-impl/` (committed):

   | arm | input packaged | expected |
   |---|---|---|
   | `identity-trees` | per-fixture tree manifests + canonical renderings | `tree/1` ids (DF-S1.2-2) |
   | `identity-records` | blob/text bytes + record canonical preimages | `version_id`/`semantic_id` (DF-S1.2-2) |
   | `ledger-transcript` | `events.wal` verbatim + scenario + envelopes | per-frame hashes, `head_hash` (DF-S1.5-3) |
   | `registry-snapshot` | `registry.json` canonical log + scenario | `expected-outputs.json` bytes + digest (DF-S1.8-1) |
   | `plugin-manifests` | the committed `valid/`+`invalid/` fixtures | `admit:<id>`/`refuse:<kind>` verdicts (DF-S1.27-1) |
   | `canonical-parse` | 4×16 KiB + 2×64 KiB canonical frames | `sha256` digests — DF-S0.3-2's far-side timing input |

   `export` is deterministic: a fresh export is byte-identical to the
   committed bundle, and the test battery pins that (CC7-style drift
   gate — a stale bundle cannot be committed silently). The ledger arm
   additionally refuses to export if the transcript drifts from the
   pinned golden head.

2. **The bundle is self-describing.** `CHECKER.md` (authored at the
   crate root, embedded and copied into the bundle) defines the
   language-neutral contract: canonical-JSON rule, SHA-256 spelling,
   `idp/1`, `tree/1`, the WAL `prev_hash` fold, the plugin verdict
   spellings, and the `answers.json` shape. `bundle.json` carries the
   per-member `sha256` inventory, the arm table with its DF row each,
   and `pending_cells[]` — the foreign cells this ticket leaves open,
   each marked `environment-pending` on `HUMAN-H3`.

3. **`self_check` + `verify_answers`.** `self_check` replays the
   committed bundle through the E1 primitives hermetically —
   manifest→canonical→id, WAL→chain head, log→snapshot outputs,
   manifest bytes→verdicts — proving the packaging reproduces E1's
   pinned answers (55 cases green in the battery). `verify_answers` is
   the comparator for the future foreign run: per-case agreement by
   name, missing or disagreeing answers fail loudly. To expose the
   corpus *inputs* for serialization, `hh-identity` gained additive
   accessors only — `Tree::entries`/`canonical_json` and
   `corpus::golden_tree_fixtures`/`golden_record_fixtures`; no pinned
   value changed (the golden corpus battery is unchanged and green).

4. **Environment-pending disposition.** No foreign-toolchain cell
   closes in this ticket. DF-S0.3-2, DF-S1.2-2, DF-S1.5-3, DF-S1.8-1,
   DF-S1.27-1, DF-S1.24-2's live cell and DF-S1.13-3's LT-03 live arm
   each carry a dated progress/environment-pending note; BL-01 records
   the landed packaging leg against the still-open foreign half.
   Verification layer recorded: `fixture-verified` — no
   `staging-verified`/`live-executed` claim.

## Consequences

- The deferred cluster now has a durable, committed, byte-stable target:
  a foreign run is `hh-xcheck selfcheck <bundle>` + produce
  `answers.json` + `hh-xcheck verify` — no knowledge of the Rust
  workspace required.
- The S0.3b machinery's role is retired to design reference; the spike
  tree stays throwaway and unreferenced.
- When HUMAN-H3 lands, the same bundle verifies E2/E3 answers with no
  new packaging work — only the run sheet (`spikes/s0.3b-online-spike/
  run-sheet.py` or successor) drives the foreign side.
- A corpus change that isn't deliberate fails `export_is_byte_
  deterministic_against_committed_bundle` — the bundle can never drift
  silently from the corpora it packages.
- Cost: ~1.9k changed lines excl. generated fixtures — over the 900
  budget line; held as a coherent unit rather than decomposed because
  every module is one load-bearing leg of one artifact (the bundle),
  matching the R2.19/R2.20 precedent.

## Alternatives considered

- **Ship expected outputs only** (hashes, no inputs): cheaper, but a
  foreign implementation could not replay — it would only confirm
  E1's own numbers. Rejected: §10.7 needs the foreign *computation*.
- **Extend `hh-bench`'s fixture tree** instead of a new crate: the
  bench corpus is adapter-facing (task materialization), not the
  cross-implementation checker; mixing the contracts would conflate
  two spec sections. A dedicated crate keeps CC10-style ownership
  clean and keeps `hh-xcheck` removable (nothing depends on it — CC6).
- **Mark DF rows DONE on packaging**: rejected outright — the honesty
  floor; `OPEN` + dated progress notes + `pending_cells[]` in the
  artifact is the truthful record.

## Revisit trigger

HUMAN-H3 provides the foreign-toolchain environment (or HUMAN-H4's
cross-camp review signs the E1-only posture): run the bundle under
E2/E3 via the run sheet, land `answers.json` + the `verify` evidence,
and flip the DF rows to DONE with real artifact paths. A corpus
schema change (`hh-json/1`, `idp/1`, `tree/1`, WAL format) forces a
deliberate re-export — the determinism test is the tripwire.
