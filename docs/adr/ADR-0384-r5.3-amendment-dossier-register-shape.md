# ADR-0384: Round-5 amendment dossier — one common register, proposal-ids only

- **Status:** Accepted
- **Date:** 2026-10-30
- **Ticket:** R5.3
- **Requirement ids:** REQ-H-004 (primary), REQ-E-210 (contributing)
- **Spec:** docs/evidence-and-adoption-spec.md §9.3/§9.4, AC-9-1/AC-9-2; ticket docs/tickets/171_R5.3__adr-exec.md AC-1/AC-2
- **Rung (ADR-0024 obligation):** non-contract build-planning record (no contract schema, wire or runtime semantics); governs dossier mechanics only

## Context

GATE-G8's scoped authorization permits admission-dossier preparation only:
three bounded tickets (R5.3 rows 1–2, R5.4 row 3, R5.5 rows 4–7) must prepare
proposals for the seven §9.3 amendment rows before GATE-G9 disposes them. The
supplement fixes *what* may be proposed but not *where the proposals live*
or *how three stacked tickets share one register*. Left unspecified, each
ticket could mint its own dossier file and naming scheme, which would break
the "one primary owner per adopted target" rule (§9.4/AC-9-2) and blur the
line between proposal and admitted ADR (docs/adr is reserved for decided
records with generated index/trigger surfaces).

## Decision

1. **One common register file** —
   `docs/build/planning/2026-10-30_amendment-dossier.md` — holds the
   seven-row amendment register plus per-row packets. R5.3 creates it with
   packets for rows 1–2 and owner-bound slots for rows 3–7; R5.4 returns the
   row-3 packet, R5.5 the rows 4–7 packets, each into its own slot.
2. **Proposal ids, never ADR numbers.** Proposed amendments are cited as
   `PADR-R5-<row>`; an ADR number is allocated only when a later admitted
   ticket executes (GATE-G9 disposition → landing ticket). No dossier
   content lands in `docs/adr/`; the generated index and revisit-trigger
   catalogue describe decided ADRs only.
3. **Unadmitted-name marking.** Every interface/event/field/view name inside
   the dossier carries `∗` and the register states the naming rule once:
   candidates are not existing RPC/wire commitments (I-02), and any admitted
   name lands once in the owning codec/class table/home (CC1/CC7/CC10).
4. **Non-admission ledger.** The register ends with an explicit negative
   space (unallocated names, no public adoption RPC, no alternate
   codec/store, no duplicated lifecycle/totals, no inferred grading
   authority, no new backend/dependency, no implementing source edits) so the
   barred set is reviewable rather than implicit.
5. **No agent acceptance/signature** appears in the register; GATE-G9's
   readout carries the operator disposition per the gate contract.

## Consequences

- R5.4 and R5.5 have a named seam (`slot` rows) and a file to return into;
  the slot-status column is the audit GATE-G9 uses to confirm all three
  sibling packets returned.
- The dossier is a planning artifact under `docs/build/planning/` (living
  build record), not a decided contract; it is safe for stacked-ticket
  extension without rewriting history — siblings append their packet and
  flip their slot status.
- Proposals stay citable (`PADR-R5-1`, `PADR-R5-2`) in later tickets,
  deferrals and gate readouts without implying admission.

## Alternatives considered

- **One dossier file per ticket.** Rejected: fragments the seven-row
  register the supplement defines as one admission unit; GATE-G9 would
  review three documents and the "collect sibling packets into the
  seven-row amendment register" deliverable would have no home.
- **Draft ADRs under `docs/adr/`.** Rejected: docs/adr records decided ADRs
  with generated index/trigger surfaces; placing unadmitted drafts there
  would imply an admission the gate has not granted and could confuse the
  adr-index generator.
- **Edit the supplement's §9.3 table in place.** Rejected: the supplement
  is a ratified record amended through the ADR/manifest protocol; proposals
  must not masquerade as edits to it.

## Revisit trigger

Reopen if GATE-G9 or a later disposition changes where amendment proposals
are homed (e.g., an admitted proposal pipeline), if the supplement's §9.3
register gains or loses rows, or if the build adopts per-row dossier files —
the slot/status audit then needs a matching amendment, never a silent edit.
