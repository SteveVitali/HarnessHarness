# ADR-0351: R2.19 embed/MCP surface legs — the definition-publishing surface, the sequenced SSE push log, and the WS-H3 caller-credential mediator

- **Status:** Accepted
- **Date:** 2026-10-09
- **Ticket:** R2.19
- **Requirement ids:** DF-S1.25-1 · DF-S4.11-1 · DF-S4.11-2 · BL-27 ·
  R-2.10.2 · R-2.11.3 · R-2.11.4 · CC1 · CC3 · CC7 · SV-5
- **Spec:** §03 (the document plane — a ref'd definition resolves
  through the publishing store) · §7 (surfaces — the Streamable-HTTP
  MCP binding's SSE half) · §5g.3 (the WS-H3 credential mediation
  surface — `CallerCredential` resolution to a subject or a typed
  refusal, never a guess).
- **Rung (ADR-0024 obligation):** C1 — the legs execute at the
  offline/fixture ceiling: the registry is the embedded snapshot, the
  SSE arm is loopback `TcpListener`, the OAuth leg is the kernel's own
  `minted_scoped` issue path. The real OAuth-provider and TLS-handshake
  exchanges stay environment-gated (BL-31) and are honest typed
  refusals, not fakes.

## Context

R2.19 discharges the three embed/MCP surface residuals the Stage-1
slice deferred honestly: `DefinitionInput::Ref` (DF-S1.25-1 — a `ref`
was a typed `UnresolvedRef` because no definition-publishing surface
existed), the Streamable-HTTP SSE half (DF-S4.11-1 — the POST drain
existed since S5.7/S5.8; `GET /mcp` → `text/event-stream`, push and
`Last-Event-ID` resume did not), and the WS-H3 credential mediator
(DF-S4.11-2 — `oauth`/`mtls` `CallerCredential` shapes parsed and
link-tested but no resolution leg existed). Five rulings were the
ticket's to make:

1. **What the definition-publishing surface is.** The spec's §03
   document plane wants a ref to resolve through "the published store"
   — the embedded `RegistryStore` already content-addresses sealed
   definitions under `hh/` + `local/` namespaces (R-2.10.2). A second
   publishing table would be a second spelling (CC1).
2. **Which grammar a `DefinitionInput::Ref` spells.** The `base:`
   desugar already resolves `version:<vid>` / bare version id /
   `ns/name[@label]` through `hh_lab::assembly::desugar::base_definition`
   — one grammar or two was the CC1 question.
3. **Which resolve mode the ref runs under.** The desugar reads at
   `Audit` (authoring-time); an open session *runs* the resolved
   definition — the mode choice decides whether revoked/below-floor
   versions can ever open.
4. **How `GET /mcp` stays open honestly.** `LabServer` is `!Send` (the
   `EmbedService`'s `!Send` ports), so a per-connection worker thread
   cannot hold it; and the S5.7/S5.8 POST drain (`pending`) must not
   lose its consumers — one notification mint or two was the
   consistency question.
5. **Where credential mediation lives and what mTLS answers.** The
   `CallerAuth` grant table says *which* sealed binding a token may act
   as; it says nothing about whether the credential itself is valid.
   The kernel's `hh_secrets::CredentialBroker` `minted_scoped` leg is
   the authorization-server arm this slice can honestly run; mTLS needs
   a TLS handshake the loopback transport never runs.

## Decision

- **D1 — the embedded registry IS the definition-publishing surface;
  document opens auto-register, idempotently.** `resolve_definition`
  registers every sealed `Document` input into the service's
  `RegistryStore` as `RegistryRecord::SealedDefinition` under the
  kernel provenance before the open answers (`open.rs`). The version
  id is content-addressed — re-registering the same sealed bytes is
  the store's idempotent hit, and a real registration failure refuses
  the open rather than landing a definition nothing can re-resolve
  (CC3 — the durable path is the point). `lab.registry.publish`
  remains the named-entry arm (`ns/name[@label]`), and the embedded
  registry's `flush_registry_events` makes every registration durable
  under the run's fenced writer.
- **D2 — one ref grammar; `Execute` mode for open, `Audit` for
  authoring.** `DefinitionInput::Ref` resolves through the one
  `base_definition` desugar grammar — `version:<vid>` | bare version
  id | `ns/name[@label]` (CC1 — a second spelling would drift).
  `base_definition` gained a `ResolveMode` parameter: the desugar's
  `base:` read stays `Audit` (authoring-time reads admit what the
  floor allows); the open path passes `Execute` — the resolved
  definition is the one the session runs, so the stricter gates
  (revoked admission, the conformance floor) apply. An unresolvable
  spelling stays the typed `UnresolvedRef{reference}` — never a
  document-parse fallback, never a guess.
- **D3 — the local blob pool is the version-spelling fast path; a
  registry hit re-deposits through the one artifact chain.** For
  `version:<vid>`/bare-id spellings the resolver first tries
  `persisted_definition` — the `artifacts/<version_id>` redirect a
  prior open deposited (blob-hash + pinned-root verified, CC3); the
  common case is a ref to a definition this service already sealed.
  A registry hit deposits the sealed definition's canonical bytes
  through the *same* blob-pool + `artifacts/` + `sealed_defs` path a
  `document` open takes — one content-addressed artifact chain, so a
  ref-opened definition is byte-identical to a document-opened one.
- **D4 — SSE is a single-threaded nonblocking multiplex over one
  `&mut LabServer`; one mint serves both consumers.** `serve_http`
  runs a nonblocking round-robin — accept, read, dispatch, push —
  because `LabServer` is `!Send` and cannot move to a worker. `GET
  /mcp` under a valid session + resolved credential answers `200
  content-type: text/event-stream`, replays the retained log after
  `Last-Event-ID` (absent → tail; malformed → live, never a guessed
  cursor), then pushes live frames — one connection per stream while
  POSTs keep dispatching on the same loop. `LabServer::push_notification`
  is the single mint: it appends to a sequenced, binding-scoped
  `events` log (`seq` is the `id:` and the `Last-Event-ID` key;
  `binding_id` scopes delivery to the subscribing caller) *and* the
  legacy `pending` queue `subscriptions/listen` drains — one
  notification, both consumers, never a second spelling. The log is
  capped (`EVENT_LOG_CAP`); an evicted tail resumes at the head —
  the caller re-reads resource/task views rather than receiving a
  fabricated replay.
- **D5 — credential mediation is a kernel-owned seam; `oauth` verifies
  through `minted_scoped`, `mtls` refuses `transport_absent`; the
  verdict type re-exports through the kernel boundary.**
  `EmbedService::surface_verify_caller_token` answers the broker's
  `MintedVerdict` (`Valid | Invalid | Expired | Revoked`) and
  `surface_mint_caller_token` is the kernel's own `minted_scoped`
  issue path — every row (`granted`/`decided`/`bound`/`used`) lands
  durable under the contract run's fenced writer before the token
  answers (SV-5); the token itself goes to the caller, never into a
  ledger or record. `LabServer::resolve_credential` composes the
  grant table with the mediator: `stdio_launch` stays the launch's
  own evidence, `oauth` must verify under the binding's declared
  `audience` (a table entry alone never resolves an OAuth grant — a
  forged, wrong-audience, expired or revoked token answers its typed
  refusal), and `mtls` refuses `transport_absent` — no TLS handshake
  exists at this slice and no subject is fabricated (BL-31). Every
  refusal is a `401` carrying the `CredentialRefusal` spelling —
  observable, never a guessed identity. `MintedVerdict` is the
  broker's own closed sum re-exported through `hh_embed::service` —
  the surface speaks the one type without a `hh-mcp-lab → hh-secrets`
  edge (the removability gate: surfaces reach the kernel boundary
  only).

## Consequences

- `open_session{definition:{ref}}` opens the pinned sealed definition
  a prior `document` open or `lab.registry.publish` registered;
  `get_artifact` serves the ref-opened bytes identically — the
  content-addressed chain is one.
- `GET /mcp` streams `text/event-stream`; `resources/subscribe` plus a
  touching `tools/call` pushes `notifications/resources/updated` with
  monotonic `id:`; a reconnect with `Last-Event-ID` replays without
  loss; bogus bearer → `401`; GET without a session → `400`.
- OAuth callers authenticate against the kernel's own AS leg —
  `mint_caller_token` + a declared `oauth{audience}` binding resolves
  and dispatches; forged/expired/revoked tokens are typed `401`s.
- mTLS grants reach the mediator and refuse honestly
  (`transport_absent`) — DF-S4.11-2's residual is the
  environment-gated exchange legs: a real OAuth provider and the TLS
  handshake's peer-identity map (BL-31).
- `hh-mcp-lab` gained no dependency edge — `MintedVerdict` travels
  through `hh_embed::service`; `check-removability` verifies the
  S4.11 surface stays a leaf.
- The `pending` drain contract is unchanged — existing POST/stdio
  consumers (`subscriptions/listen`) see the same notifications, one
  mint.

## Revisit trigger

Reopen when a ticket lands a TLS-terminating transport or a real OAuth
provider leg (BL-31 — `mtls` gains its handshake's peer-identity map and
`oauth` gains a provider challenge→token exchange; DF-S4.11-2's residual
discharges), when the embedded registry gains a second record kind that
needs publishing (D1's auto-register rule must name which kinds open
registers), when the SSE backlog cap proves too shallow for a real
consumer (D4's evicted-tail resume rule must be re-justified), or when a
surface other than `hh-mcp-lab` binds the mediator seam and the
`audience`→binding table needs a second home.
