# ADR-0251: S1.17 typed-capability rulings — `ToolCapability` in HIR, V-E1 split between record and document checks, the semantic projection of run-time selection fields, and the derived (never stored) registry verbs

- **Status:** Accepted
- **Date:** 2026-09-17
- **Ticket:** S1.17
- **Requirement ids:** R-2.5.1
- **Spec:** §5d.1 (the C0/Stage-1 slice per the §5d.1 §9 stage map) ·
  ADR-0087…0089 · ADR-0031 (risk projection) · ADR-0034 P7 (lifted
  declarations) · CF-104/CF-210
- **Rung (ADR-0024 obligation):** **C0** — MUST-code: the record schema, V-E1
  at `validate`/`register`, the registry verbs (`register`, `publish`,
  `resolve`, `lookup`, `snapshot`, `project_risk`, `required_grants`,
  `estimate`, `catalog`, `search_projection`, `bind`), the native source and
  `lifecycle.capability.registered` are Stage-1 items. `search_projection` /
  `catalog` provider-hosted lifting is `R-2.5.1¹` (C1/Stage 4); remote/ACP
  capability sources stay later.

## Context
S1.17 lands the typed-capability slice: `ToolCapability` was already a HIR
kind (S1.4); this ticket makes it a *registry* record body with its own
validation battery and verb surface. The spec fixes the invariants — V-E1 is
a `register` error (not a warning), the semantic projection excludes
run-time selection fields, a lifted declaration registers `quarantined` —
but leaves these concrete rulings to the slice:

1. **Where the scope/argument vocabulary lives.** `hh-monitor::args` had
   grown `ScopeKind`/`ScopeBinding`/`SurfaceArgMap` evaluation — that is a
   *semantic* vocabulary V-E1 validates, so a monitor-side copy would fork
   the schema (CC7).
2. **How V-E1 splits across `validate` and `register`.** Some checks are
   record-local (effects non-empty, scope totality, `param_path ∈
   input_schema`, lifted ⇒ `unverified`, `exact` cost needs
   `measured_ref`); others are document-level (closed-sum spelling,
   T-LCD-01 model-identity statics, the I-DISCOVERY discovery-capability
   presence check).
3. **What `capability`'s registry identity covers.** The `hir.node` semantic
   id is the capability's identity — the envelope (`registrar`,
   `registered_at`, `trust_record_ref`) is registry metadata and must not
   enter it.
4. **What `quarantined` means for a capability.** A lifted source or a
   declared effect with no attribute vector is honest-but-unverified —
   `resolved` would over-claim, refusal would lose the record.
5. **Whether `lookup` is governed.** `resolve` enforces admission; a raw
   read of a quarantined record must still be possible (a caller cannot
   inspect what it cannot fetch).

## Decision
- **§1 — `hh-hir::tools` owns the vocabulary.** `ScopeKind` (the closed
  eight-member sum), `ScopeBinding`, `scope_bindings` parsing, scope
  matching, `SurfaceArgMap` evaluation and the run-time `ExposureMode` sum
  live in `hh-hir` (one schema source — CC7); `hh-monitor::args` re-exports
  them. The evaluator is total over the closed transform set: an unmapped
  surface argument is `UnmappedArgument`, a scope-bearing parameter without
  a binding is `UnscopedParameter`, `scope_bindings_unknown` marks
  `*`-only coverage — never an empty result or a permissive fallback.
- **§2 — V-E1 splits by reach.** `tools::validate_capability(rec,
  authority)` runs the record-local checks (1/3/4/7/8 + resources
  tri-state); `validate` adds the document-level checks (2/5/6/9/10 + the
  I-DISCOVERY `NoDiscoverySurface` check — a definition admitting
  `deferred`/`indexed` without a `discover_surfaces` capability fails, the
  AC-R-2.5.3-2 static half). `register` runs `validate_capability` with
  the *node's* provenance authority — authority is conferred, never read
  from content (CC2). Failures collect into `CapabilityValidation`,
  never fail-fast.
- **§3 — the semantic projection drops selection-only members.**
  `exposure_hint` and `cost_model.measured_ref` serialize into the
  *version* basis but not the *semantic* basis — a rename of either cannot
  re-mint the capability (V-E1-9; AC-R-2.5.1-2). The `cost_model` member
  itself stays semantic.
- **§4 — quarantine is the honest admission for lifted/unknown.** A
  `mcp_listing`/`participant_supplied` source, or a `declared` effect set
  carrying a member with no attribute vector (`unknown_domain`), registers
  `quarantined` (CF-210): the record exists, `lookup` reads it, `resolve`
  under `execute` refuses it, `project_risk` projects the most dangerous
  class (`{irreversible, non_idempotent, external}` — ADR-0031 §2).
- **§5 — the verb surface is derived, never stored.** `project_risk`,
  `required_grants`, `estimate`, `catalog` and `search_projection` are pure
  functions of the record (and the snapshot for `catalog`) — the §5d.1 §2
  views the monitor and the index read, deterministic per snapshot
  (AC-R-2.5.1-7). `estimate` reports every registered `DimensionId`,
  undeclared ones `unknown` — never 0 (AC-R-2.5.1-9's rule); `measured` is
  a basis flag on the declaration, never a value read off a measurement.
- **§6 — `lookup` is the raw read.** `store.lookup(version_id)` returns the
  stored `ResolvedRecord` projection under the `Audit` axis (the same
  `project` path `resolve` uses, minus the execute-mode gates); an unknown
  id is `Unresolved`, never an empty result. `resolve` stays the governed
  path.
- **§7 — `lifecycle.capability.registered` is audit-grade.** The class row
  reuses `REGISTRY_FIELDS` (ids/spellings only — content-free); the
  capability registration path emits it after the admission write.
- **§8 — `bind` stays the `hh-env` seam.** `executor::bind_capability`
  checks the `execution_requirement` against the `ExecutorDeclaration`
  (isolation, dedup, interrupt support); a `pure` capability requires no
  domain coverage — the earlier draft required `ModelCall` coverage on
  `pure`, which would have forced a spurious executor grant (fixed and
  tested).

## Consequences
- `ToolCapability` is registrable, resolvable, risk-projectable and
  grant-projectable with no second schema anywhere: `hh-monitor`,
  `hh-containment` and `hh-compiler` all read `hh_hir::tools`.
- A pure capability under `native` provenance registers `resolved`; a lifted
  one registers `quarantined` with `unverified` authority — never coerced.
- `version_id` covers the surface; `semantic_id` does not — renaming a
  surface re-mints the pinned `version_id` a `capability_ref` carries while
  `capability_refs` (the semantic-id list on a `SurfaceBinding`) is
  untouched (AC-R-2.5.2-2).

## Alternatives considered
- **`hh-monitor` keeps the scope vocabulary** — rejected: V-E1 validates
  the same sums at register time; two copies is exactly the fork CC7
  forbids.
- **Quarantine ⇒ refusal at `register`** — rejected: the lifted record is
  evidence; refusing loses the audit trail a later `pin` attestation needs.
- **`lookup` routed through `resolve`** — rejected: quarantined records are
  uninspectable, and the raw read is a separate spec verb.

## Revisit trigger
R-2.5.1¹ (C1/Stage 4) lifts `search_projection`/`catalog` to the
provider-hosted source; re-open if the derived-verb projections need a
stored form or the quarantine axis needs a fourth admission value.
