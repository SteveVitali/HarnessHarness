# ADR-0455: Refusal-bearing drives gate the L1-fold leg — a vacuous pass is impossible (REQ-XD-104 semantics)

- **Status:** Accepted — operator ruling 2026-11-26: verbatim "Adopt refusal-gates" (sha256 `dff7b4c6191603c1c26ef8f26c77024c63e10d821d6255412c0407262b031184`, structured-answer button ruling in the post-round session). The gate amendment + regression landed on `codex/harnessharness-r6.53` the same day, closing DF-R7.3-1.
- **Date:** 2026-11-26
- **Ticket:** R7.8 — open-deferral sweep (manifest 341); deferral row DF-R7.3-1
- **Requirement ids:** REQ-XD-104 (drive-equality gate), DF-R7.3-1
- **Spec:** `hh-w1 l1-fold` leg dispositions / `crates/hh-runner/src/l1_gate.rs::compare_drives`
- **Rung (ADR-0024 obligation):** an explicit non-contract note — this ADR governs
  experiment-fold leg-disposition semantics in `crates/hh-runner`, not the canonical
  kernel contract ladder.

## Context

Two landed folds expose the same false-positive class (DF-R7.3-1):

- **p4x G-L1 record (R7.3):** all 16 H drives exited rc = 1 (machinery — the drive never
  armed) and folded as empty `L1Drive`s. `compare_drives` saw zero request pairs, so the
  request level emitted nothing, and the trajectory levels gate only when `stable ==
  total` — a partial prefix never evaluates the tail — so `l1_2`'s s(S)-prefix gate
  minted a **vacuous `pass` ×8 on 0 evaluated turns**. `corpus_boundary` l1_1 seqs pass
  the same way.
- **X1 fold (R7.4):** the 46 `detail_lost` slots' disposition was taken as
  `recorded{early_exit:zero_model_calls, detail_lost}` — unresolved for every purpose
  (never imputed, never a subject pass or clean fail), counted in gate (d)'s unresolved
  accounting and in the confirmation quote's executed-slot cost census at 0 µ$.

A drive-level mitigation already landed: the driver stamps `refusal{machinery}` onto
the folded H doc — but `compare_drives` itself cannot gate on that member. Gating a
refusal-bearing drive changes REQ-XD-104 semantics, so it needs this ADR rather than a
driver edit. The defect class: a drive that never ran is not evidence of equality; a
`pass` minted on zero evaluated turns is a false positive in the gate ledger.

## Decision (operator-adopted ruling 2026-11-26 — landed)

1. **A drive-level `refusal` on either the O or H folded doc gates the leg.** The leg's
   disposition layer inspects the folded docs' refusal member before turn evaluation;
   a refusal-bearing drive yields a **typed leg outcome distinct from `pass`** — e.g.
   `l1_drive_refused{<spelling>}` carrying the refusal spelling verbatim — never a
   vacuous pass on 0 evaluated turns.
2. **The distinction is leg-level, not request-level.** The refusal outcome sits beside
   the request/trajectory divergence classes (`gated: true` at leg scope); the existing
   s(S) request-prefix and stable==total trajectory machinery is byte-identical
   underneath.
3. **No re-derivation.** Absent a refusal member, fold semantics are unchanged: request
   divergences gate at `turn ≤ stable`, `excluded` at `turn == stable + 1`, trajectory
   levels only on `stable == total`, `downstream` diagnostic-only. Landed legs are
   never rewritten.
4. **Regression obligation on landing.** A committed fold where a refusal-bearing H
   drive mints the gated outcome — a checker-visible distinction between a real and a
   vacuous leg pass — plus a fixture asserting an armed drive's fold is unchanged.

## Consequences

- The vacuous-pass class is killed at the gate: a refusal-bearing drive produces an
  auditable typed outcome that unresolved accounting (gate (d)-class) can count,
  matching the honest-refusal convention.
- Historical legs are append-only records: any past leg that recorded `pass` over a
  refusal-bearing drive stands as written; corrections are dated notes, not rewrites.
- The X1 `detail_lost` dispositions stand — they were already unresolved, never passes.
- Cost: `compare_drives` callers must surface the leg-level outcome; the fold's output
  shape gains one typed member.

## Alternatives considered

1. **Driver-only stamping (status quo at mint).** The `refusal{machinery}` stamp exists
   but `compare_drives` ignores it — the gate still mints `pass`. Rejected: it leaves
   the false positive live.
2. **Refuse the fold upstream of `compare_drives`.** A hard error loses the
   leg-level distinction between "drive refused" and "drive ran and diverged", and
   breaks the append-only fold shape. Rejected.
3. **Keep the vacuous pass plus an annotation.** A `pass` minted on 0 evaluated turns
   is a false positive however labeled. Rejected.

## Revisit trigger

Revisit if a second refusal-class leg surfaces needing finer-grained
partial-refusal semantics (e.g. a drive armed for k < n turns — the adopted rule
treats any `refusal` member as leg-gating), or if a leg-scope `drive_refusal`
needs a durable `hh-l1-diff/1` record of its own (today it mints none — it sits
outside the REQ-XD-104 diff whitelist by design).
