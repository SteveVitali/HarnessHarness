# ADR-0235: S1.5 hash-chain, WAL, and lease mechanics — `ledger.event` domain hashing, commit markers with torn-tail drop, and generation-fenced file leases

- **Status:** Accepted
- **Date:** 2026-09-15
- **Ticket:** S1.5
- **Requirement ids:** R-2.2.1
- **Spec:** §5a.1 §2 (interface contract), §5a.1 §5 (failure modes) · ADR-0026 §5,
  ADR-0027 §4, ADR-0029 §2–§3, ADR-0030 §6, ADR-0067 §4

## Context
Three mechanics had to be pinned concretely:

1. **The chain hash.** §5a.1 §3 fixes `hash = H(leaf_tag ∥ canonical(envelope −
   {hash}) ∥ prev_hash)` and ADR-0029 §2 pins the `idp/1` digest; the leaf tag byte,
   the domain string, the `prev_hash` *encoding* inside the preimage, and the genesis
   value needed fixing (CC1: through `hh-identity`'s `idp_id`, not a new hasher).
2. **Durable-before-visible.** §5a.1 §5 requires atomic multi-event batches with no
   partial visibility and a torn tail a replay discards wholesale; the on-disk record
   layout that makes "committed" decidable after a crash needed choosing.
3. **The single fenced writer.** `acquire_writer`/`renew`/`release`, `WouldBlock`,
   `Fenced`, strictly-increasing `lease_generation`, and takeover-after-TTL are spec'd;
   the persistence mechanism (so a stale *process*, not just a stale in-memory token,
   is fenced) and the takeover-vs-block split needed a ruling — takeover *policy* is
   R-2.2.3's (ADR-0130 §4), so this stage needed the minimal honest rule.

## Decision
- **Hash:** `hash = idp_id("ledger.event", 0x00 ‖ canonical(envelope − {hash}) ‖
  prev_hash)` — the `ledger.event` domain tag keeps event hashes disjoint from blob
  (`blob` domain) and effect-id (`ledger.effect`) digests; `0x00` is the RFC-6962
  leaf/domain separator byte (the node side arrives with the audit tree heads);
  `prev_hash` enters the preimage as its literal ASCII bytes — a fixed-shape
  `sha256:<hex>`/sentinel token, so the binding is unambiguous without an encoding
  layer. Seq-0 `prev_hash` is the
  reserved literal `"genesis"` for a fresh run, or the lineage link's `head_hash`
  (verified against the source run at `open_run`) for a `forked_from`/`continued_from`
  anchor (ADR-0029 §3; ADR-0131 §5). `verify` recomputes the full chain plus seq
  density/order/parent/parent-resolution and reports `Tampered{at_seq, kind}` with
  `kind ∈ {content_modified, chain_broken, seq_gap, reordered, duplicate_seq,
  duplicate_event_id, dangling_parent}`.
- **WAL:** `events.wal` is canonical JSONL: one `{"k":"e","v":<envelope>}` line per
  event, then one `{"k":"c","n":<last_seq>}` commit marker per batch. `append` writes
  all event lines, `sync_all`s, writes the marker, `sync_all`s again, and only then
  mutates the in-memory projection and notifies subscribers — durable-before-visible
  literally. Replay keeps lines only up to the last commit marker whose `n` matches
  the accumulated durable prefix; trailing lines after it are a torn tail, dropped as
  a unit (never surfaced, never partial). A corrupt line or marker mid-log truncates
  replay at that point; `verify` then checks only the durable prefix it loads.
- **Lease:** `lease.json` is written `create_new` on acquisition and tmp+`rename` on
  renewal/release/takeover; it carries `{lease_id, holder, generation, acquired_at_ms,
  expires_at_ms, status}`. `acquire_writer` → `WouldBlock{active_holder}` while a live
  lease exists; once `expires_at_ms` passes (wall clock — id/lease material, never a
  ledger fact), takeover proceeds and **bumps `generation`**. Every envelope carries
  `lease_generation`; `append`/`renew`/`release` with a stale generation or expired
  token → `Fenced{lease_generation, current_generation}`, and the ledger itself appends
  an audited `lifecycle.lease.fenced` row (kernel producer, audit-grade) on takeover.
  Within one process `&mut Store` is the structural single-writer guard; the file lease
  is the cross-process one on a single host.
- **`open_run` acquires the writer lease** (generation 1) as part of seq-0, per §5a.1
  §2's contract row.

## Consequences
- Good: crash consistency is a *file-format* property (the commit marker decides), not
  an in-memory flag — the AC-11/KP-9-class tests exercise a real torn tail by truncating
  the WAL on disk; replay correctness follows from line order alone; the hash preimage
  is fully specified, so the golden corpus pins bytes another implementation can match;
  `Fenced` + the audited `lifecycle.lease.fenced` row satisfy AC-11's audit clause.
- Cost: two `sync_all`s per batch bounds throughput (fine at Stage 1; the §5a.1 §8
  throughput metric is a Stage-4 concern); wall-clock TTL is the stale-holder mechanism
  — a clock that jumps can shorten a lease (acceptable: TTL is advisory fencing, the
  generation is the authoritative token); takeover is unconditional-on-expiry at this
  stage — R-2.2.3 owns the richer policy (grace, claims).

## Alternatives considered
- **Hash over the stored line bytes** — rejected: the spec's preimage is over the
  *canonical envelope form*; stored/wire forms may differ (CF-058), so hashing bytes
  would couple verification to layout.
- **fsync-directory + single `COMMIT` record per batch interleaved as events** —
  equivalent; a distinct `{"k":"c"}` marker line was chosen so a reader never mistakes
  a marker for an envelope.
- **Advisory `flock`** — rejected: platform-variable and invisible to readers;
  `lease.json` is inspectable state and carries the generation for audit.
- **Refuse takeover entirely at Stage 1** — rejected: AC-11's fenced-writer case
  *requires* a takeover to test (stale holder resumes after takeover).

## Revisit trigger
Reopen when R-2.2.3 lands takeover policy (ADR-0130 §4 — grace, wakeup claims, the
pause/takeover/resume battery), when multi-host stores are required, or when the
Stage-4 throughput metric (WS-B1 §6.6 item 10) forces batch-sync amortisation.
