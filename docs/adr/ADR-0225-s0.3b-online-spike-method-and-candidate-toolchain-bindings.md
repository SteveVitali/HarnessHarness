# ADR-0225: S0.3b online cross-candidate spike — method, matched-budget cross-candidate measurement, single-executor deviation, and the E2/E3 candidate→toolchain bindings (CC4)

- **Status:** Accepted
- **Date:** 2026-09-15
- **Ticket:** S0.3b
- **Requirement ids:** R-2.12.3 (measurement), R-2.5.5 (S1 spike, cross-candidate), R-2.2.5 (S2 boundary, cross-candidate)
- **Spec:** §10.6 (S1/S2 spikes, rules R1–R6), §9.1 (Stage-0 gating); `research/synthesis/l1-spike-spec.md` §2–§6; ADR-0050 §3/§5/§6 (options, trigger 5), ADR-0009 step 4, ADR-0223/0224 (S0.3 method/verdict)

## Context
The operator released an **online** spike budget (LEDGER GATE DECISIONS, GATE-G1 row, 2026-09-15)
to close the machine-achievable cells S0.3 deferred offline (DF-S0.3-1, DF-S0.3-3): the official
MCP/ACP SDK round-trip (M-S1-7), the cross-candidate half of gate G1 (E2/E3 reproduce a
byte-identical hash chain), and the cross-candidate scoring of E2/E3 (C5/C7) plus the E5b/E5c
splits (C12 transport). Standing these up needs the **candidate (E2/E3) toolchains** and the
**official SDKs over the network** — none runnable under the S0.3 offline/hermetic budget. No
external **model** spend is authorized; MCP/ACP round-trips use LOCAL reference peers.

CC4 forbids naming any language in the spec, tickets, sheet or ledger — ecosystems appear only by
candidate id (E1/E2/E3). The concrete candidate→toolchain binding therefore lives **only here**,
in this build ADR (as ADR-0217 did for E1).

## Decision
- **Candidate→toolchain bindings (this ADR is the sole record; CC4).** Per ADR-0050 §5:
  - **E1** — compiled, memory-safe systems ecosystem = **Rust** (already bound, ADR-0217).
  - **E2** — managed-runtime, dynamically-typed research ecosystem = **Python** (3.14.7).
  - **E3** — managed-runtime, gradually-typed web-native ecosystem = **TypeScript / Node** (Node 25.2.1).
  - Official SDKs stood up against local reference peers (ADR-0050 §C2 lineage): **E2** MCP
    `mcp` 2.2.0 + ACP `agent-client-protocol` 0.12.1; **E3** MCP `@modelcontextprotocol/sdk` 1.30.0
    + ACP `@zed-industries/agent-client-protocol` 0.4.5. Vendored under the throwaway spike tree
    (`e2-python/.venv`, `e3-node/node_modules`); no model API is called.
- **Shared corpus, matched-budget (CC9).** The E1 kernel emits ONE canonical corpus file
  (`corpus/shared-corpus.json`, the fixed `run-g1` corpus, l1-spike-spec §3.3) and the E1 reference
  head hash. **Every** candidate reads the SAME corpus bytes (its sha256 is pinned in
  `reference.json` and re-checked per candidate) and builds the chain with its OWN canonical
  serializer — the real test that the canonical form is implementation-independent (ADR-0029
  property 5, gate G1). The E1 reference head is proven byte-identical to the durable
  `run_session` chain, so it is the E1 kernel's real chain, not a re-derivation.
- **Matched cross-candidate S1 measurement.** C5/C7 inputs use the SAME formulas as S0.3 for every
  candidate: the CPU/concurrency fan-out core-normalized as `ratio / (N / min(cores, N))` (the
  l1-spike-spec "ideal 1.0 if perfectly parallel on ≥50 cores" framing), cancel latency, tail lag,
  and footprint as one runtime holding N in-process idle-session ledgers (RSS/N) — never one
  interpreter per session. Each candidate uses its ecosystem's NATIVE concurrency for the fan-out
  (its OS-thread / worker equivalent); the result IS the C5 property ADR-0050 scored, measured not
  assumed.
- **Matched E-kernel↔E-kernel crossing for the splits (CC9).** E5b (E3 kernel + E2 lab, subprocess
  + JSON-RPC over stdio) and E5c (E2 kernel + E3 surface, localhost HTTP) report per-run crossing
  overhead as `(split − the SAME kernel run natively)/N`, isolating pure transport, plus the
  **cross-ecosystem** far-side hash-equality of every event (M-S2-7): the far side re-canonicalises
  the chain with its own serializer and every event hash must match. The **polyglot** C12 conjunct
  (two-toolchain CI + cross-ecosystem serialization COST multiplier) stays **deferred (DF-S0.3-2,
  Stage 3)** and is not pulled forward.
- **Single-executor deviation from R1 (recorded).** l1-spike-spec R1 wants a *fresh agent per
  candidate*; one build agent implemented all arms here. **Compensating control:** each candidate's
  kernel is an independent from-spec implementation in its own tree with **no shared code**, and the
  objective **byte-identity gate G1** (E2/E3 must reproduce E1's exact 64-hex head over the shared
  corpus) is a stronger anti-ecosystem-bias check than subjective review — a hidden bias could not
  produce a byte-identical chain. The **R2 cross-camp human reviewer signature** is NOT produced
  (it is a human deliverable) and remains an explicit OPEN residual of DF-S0.3-3.
- **Repeat-scored N ≥ 3.** Every measurement is run **N = 5** and reported as median · min–max
  (`run-sheet.py`), never a point.
- **Committed-but-throwaway trees.** The spike tree (`spikes/s0.3b-online-spike/`, incl. vendored
  SDK dirs) is outside the Cargo workspace, not a kernel dependency, deletable at the Stage-0
  boundary — extending the R4 deviation of ADR-0220/0223 for reproducibility/CC3. No harness claim
  is made at Stage 0 (R5); these are internal tier-B numbers.

## Consequences
- Good: the cross-candidate arms the offline budget could not reach are now real, reproducible
  numbers; G1 byte-identity is proven across three independent ecosystem implementations; M-S1-7 is
  measured through real official SDKs; the honesty rules hold (shared corpus, matched formulas, no
  fabricated candidate, polyglot conjunct honestly deferred).
- Cost: a single executor (not a fresh agent per candidate); the R2 human signature is not produced;
  the E5c/E5b polyglot CI + cross-ecosystem serialization COST stays deferred to Stage 3.
- The candidate→toolchain binding now exists in a build ADR (this one), satisfying CC4's "bind only
  in a build ADR."

## Alternatives considered
- **Give E2/E3 the pre-canonicalised strings.** Rejected: that would make G1 a tautology; the point
  is each ecosystem's OWN serializer reproducing the bytes.
- **Spawn a fresh subagent per candidate (honour R1 literally).** Viable but the byte-identity gate
  is a stronger objective bias check; recorded as the compensating control instead. May be done if
  an R2 reviewer is arranged.
- **Measure the polyglot two-toolchain CI + cross-ecosystem serialization cost now.** Rejected:
  scoped to Stage 3 (DF-S0.3-2, §9.4); the ticket explicitly does not pull it forward.
- **Fabricate the R2 signature or skip recording it.** Refused: it is a human deliverable; it stays
  an OPEN residual.

## Revisit trigger
An R2 cross-camp human reviewer is arranged (close the DF-S0.3-3 R2 residual), or Stage 3 exercises
the kernel↔lab boundary with the real E2 lab (close DF-S0.3-2: polyglot CI + cross-ecosystem
serialization cost), or the candidate/toolchain set changes — then re-run the affected arm and amend
the sheet + the ADR-0050 amendment log.
