## Context

§6.4 binds the recipient handoff decision — not the hosting,
collection or distribution — to an owner: for each item record
`source`/`version`, license/consent evidence, `recipients`/
`uses`, `owner`/`decision` and `expiry` (unknown rights are
withheld, never inferred; no secret-bearing bundle; held-out
solutions/oracle material/model I/O default restricted; public
numerical rows and sensitive/low-entropy identifiers are
inspected too); bounded handoff under the §6.4 scope/ceiling
table (public review ≤512 MiB/asset · ≤2 GiB compressed/8 GiB
expanded · ≤10 GiB first wave; controlled review ≤20 GiB
originals; read-only grant ≤30 days · object/version links ≤1 h ·
no write/delete/list rights; full archive quoted separately;
recipient prebuilt ≤2 GiB download/8 GiB expansion · $0;
optional versioned hosting only after operator approval);
sanitized replacement changes IDs with transform/version,
permitted mapping and exact per-procedure loss — changed bytes
never retain native hashes/R1; expiry/GC/deletion emits permitted
superseding status/tombstones and disables dependent procedures —
a delete marker is not deletion; shorter rights override
retention honestly; and AC-6-3 requires the
rights/owner/contact/host/region/quotas/actual-dates/full-archive
binding **before** collection or distribution (controlled closure
never becomes public closure; original/derivative linkage only
when permitted). Before this ticket `hh-bundle` held the codec
and decode bounds (R5.24), the typed closure walk/report
(R5.22), the `trust::admit` fetch legs and the §6.3 admission
cards (R5.26) — but no owner procedure turned a handoff plan or
a sanitized replacement into a sealed verdict record (I-02).

## Decision

1. **One module, two owner-bound interfaces** —
   `crates/hh-bundle/src/rights.rs` beside `closure.rs`/
   `cards.rs` (the recipient-procedure home; records-in/
   records-out, no public RPC per Packet C C.4):
   `admit_handoff(&Decoded, &HandoffPlan, now_ms) →
   Result<HandoffReport, BundleError>` and
   `sanitize_replace(&Decoded, member, new_bytes,
   &SanitizeTransform) → Result<SanitizedItem, BundleError>`.
   Nothing executes and nothing materializes: the decoded bundle,
   the plan's declarations and the caller's store clock are the
   inputs; durable/transport/secret primitives stay in their own
   owners (`hh-ledger`, `fetch`/`trust`, `hh-secrets`,
   `hh-identity`).
2. **`admit_handoff`'s legs are the §6.4 clause verbatim** —
   plan-level violations are typed `RightsRefused` errors, never
   a verdict: `authority` (`optional_hosting` scope or an
   `s3:`/`account:`/`http(s)://` host locator →
   `separate_authority` — S3/account/provisioning needs its own
   operator decision) → `metadata` (contact/region bound —
   `missing_input`; `quoted_at`/`decided_at` parse and are ≤ now
   — `missing_input`/`future_date`; `review_before` must parse —
   the recorded review deadline) → `grant` (`access_grant` only:
   grant ≤30 days and link ≤1 h — `quota_breach`;
   write/delete/list rights → `grant_overreach`) → `quotas`
   (declared compressed/expanded/first-wave bytes against the
   scope's ceilings — `quota_breach`; a breach stops/requotes,
   never discards to fit). The per-item loop then writes
   withheld/refused rows inside the report, never silent
   admissions: unknown member → withheld `unknown_member`;
   absent rights record or `decision: unknown` → withheld
   `unknown_rights`; `withheld` → withheld; `restricted` in
   `public_review` → refused `scope_mismatch` (controlled closure
   is not public closure); `restricted`/`release` in the
   controlled/access scopes without the named recipient →
   withheld `unauthorized_recipient`; record expiry ≤ now →
   withheld `fetch_expired`; held-out roles
   (`solution`/`oracle`/`model_io`) with no license/consent
   evidence → withheld — default restricted; member size over the
   asset ceiling → `quota_breach` refusal. `present` members'
   bytes are scanned — `hharness_secrets::detect` hit →
   `secret_material`, a declared `restricted_identifiers` byte
   match → `sensitive_identifier` (hard refusals); a `present`
   member without carried bytes withholds `missing_bytes`;
   `fetch` members need a `FetchEntry` plus `trust::admit` per
   location leg (`LocationExpired` → `fetch_expired`, any other
   arm → `unauthorized_fetch`); `redacted`/`gc` withhold by
   status. Departures need a `expired`/`deleted`/`gc`
   disposition, non-empty evidence and an `occurred_at` ≤ now on
   an existing member — a bare marker is `marker_not_deletion`;
   each real departure emits a `rights-tombstone/1` row and the
   role→procedure `disabled_procedures` map (`verify` always;
   `ledger_page`/`trace` → `replay`; `definition` →
   `replay`+`fresh`; `compiled_bundle` → `replay`;
   `rows`/`analysis` → `recompute`; `model`/`instrument`/
   `configuration`/`resolved_dependencies` → `fresh`+`recompute`)
   — dependent procedures disable even after earlier passes.
3. **The verdict and retention records stay honest.** `verdict`
   is `refused` when any item row refused, else `withheld` when
   any withheld, else `admitted` — withheld items never fold
   into an admission. `quotas` records every ceiling beside the
   observed declarations; `retention` records
   `effective_until = min(earliest item expiry, declared
   review_before)` with `override: shorter_rights` when an item's
   rights expire earlier — shorter rights override retention
   honestly.
4. **`sanitize_replace` is the cleared sanitized replacement** —
   new identity + supersession + dependent claims recalculated:
   the member must exist (`malformed`); transform `kind`/
   `version` are required (`missing_input`);
   `mapping_permitted:false` → `unpermitted_mapping` (the
   original↔derivative linkage is preserved only when
   permitted); the replacement bytes are scanned before any
   record emits (`secret_material`/`sensitive_identifier`);
   the replacement address is
   `hharness_identity::address(new_bytes, media)` — a **new**
   content identity, and identical bytes → `unchanged_bytes`
   (changed bytes never retain native hashes/R1); dependent
   claims are recalculated by walking the manifest document for
   string fields equal to the original address → `{field, from,
   to}` rows; the exact per-procedure loss is `{procedure, loss:
   "native_identity", r_levels: "R0"}` over the transform's
   declared procedures; the outcome seals a
   `rights-supersession/1` record.
5. **Records stay separate and `idp/1`-sealed** —
   `rights-record/1` per-item binding inputs; `handoff-report/1`
   the verdict record; `rights-tombstone/1` the departure status;
   `rights-supersession/1` the sanitized replacement — the same
   record family as `closure-report/1`, `replay-card/1`,
   `fresh-card/1`, `analysis-recompute/1`. `report_id`/
   `supersession_id` are `idp/1` over the record minus the id —
   the `ReproReport`/`AdmissionCard` seal rule. Per-item
   `{member, decision, detail}` rows are recorded members the
   reader compares, never verdict inputs silently waived.
6. **One typed refusal vocabulary.** Plan-level violations are
   `BundleError::RightsRefused{code, detail}` over the closed
   `rights::code` set (`unknown_rights`, `withheld`,
   `secret_material`, `sensitive_identifier`,
   `unauthorized_fetch`, `fetch_expired`, `quota_breach`,
   `grant_overreach`, `marker_not_deletion`, `scope_mismatch`,
   `separate_authority`, `unauthorized_recipient`,
   `missing_input`, `future_date`, `unchanged_bytes`,
   `unpermitted_mapping`, `malformed`); per-item denials are
   decision rows inside the report — a secret-bearing or
   over-quota handoff produces no verdict at all. No second
   codec, no new event class, no new dependency (CC1/CC9/CC10);
   `now_ms` is the caller's store clock — the evaluation is
   deterministic.

## Consequences

- A recipient can admit, withhold or refuse a bounded local
  handoff plan under the §6.4 scope ceilings — per-item rights/
  access/expiry/loss validated, departures tombstoned with
  dependent procedures disabled, retention effective dates honest
  — and a cleared sanitized replacement mints a new identity with
  supersession, recalculated dependent claims and the exact
  per-procedure loss record.
- `tests/r5_27.rs` (18 checks) exercises every AC leg over an
  in-memory `Decoded` rig (manifest literal + `MemberBytes` — no
  store needed; handoff works on decoded artifacts) —
  compile-red at base `bc446fb7` (the module does not exist
  there).
- REQ-F-006/F-207/F-208 keep `planned; unmet` — this ticket
  records achieved engineered D/E separately from the owed legs:
  the named contributor R5.52 (outside review) and every
  R/P/actual-execution predicate. REQ-F-201/F-202/G-104/G-203
  are stamped contributing-only.
- No crate edge added (`hh-secrets`/`hh-identity`/`hh-ledger`
  were already dependencies), no event class, no schema/wire
  change, no new dependency; the live driver boundary is
  unchanged.
- AMEND ruling `963ff8f5`: 1,502 changed source/test lines vs
  ≤650 — recorded Deviation accepted (one authored owner unit;
  the interfaces are inside one conjunctive §6.4 clause, not
  documented seams; leg (a) alone still over trigger; ~2.3× in
  the accepted band).

## Alternatives

- **Executing or materializing fetch inside the handoff** —
  rejected: §6.2 fetch never executes; the handoff evaluates the
  declared `FetchEntry`/`trust::admit` legs only, and a refused
  leg is a recorded refusal, never a silent fetch.
- **A public `hh handoff`/`hh sanitize` command** — rejected:
  C.4 keeps the owner records-in/records-out; the recipe/CLI
  owner is R5.28.
- **Admitting a marker as deletion** — rejected: §6.4's "a
  delete marker is not deletion"; a departure without
  disposition/evidence/actual date is `marker_not_deletion`.
- **Folding withheld items into an `admitted` verdict** —
  rejected: AC-6-3 withholds the *affected* procedure/claim;
  per-item rows stay separate and any withheld row makes the
  verdict `withheld`.
- **Retaining the original identity or hash on sanitized
  bytes** — rejected: §6.4 changes IDs and forbids native-hash/
  R1 retention; the replacement is a fresh `hh-identity` address
  and identical bytes refuse `unchanged_bytes`.
- **Splitting `admit_handoff`/`sanitize_replace` across modules
  or tickets to fit the trigger** — rejected per the scoped
  review: §6.4 is one conjunctive clause making the two
  interfaces implementation surfaces, not documented seams;
  AC-1/AC-2 span both; leg (a) alone still exceeds the line.

## Revisit triggers

- If a later operator decision admits an optional-hosting
  contract (private versioned S3 within the §6.4 hosting row),
  revisit Decision 2's unconditional `separate_authority` arm —
  today no such authority exists and the refusal stands.
- If the §6.4 scope/ceiling table or grant bounds change
  (asset/package/first-wave numbers, the 30-day grant or 1-hour
  link lifetime), amend Decision 2's `grant`/`quotas` legs —
  the ceilings are the frozen table verbatim.
- If manifest member roles or the §6.3 procedure set change,
  re-check `procedures_for`'s role→procedure map — dependent-
  procedure disable is keyed on it.
- If `hh-secrets`' detector vocabulary or the
  restricted-identifier declaration shape changes, re-run the
  whole r5_27 battery — `scan_bytes` inherits both verbatim.
- If a sanitized-derivative derived set is admitted for
  R1-style rederivation (ADR-0404's trigger), re-read Decision
  4's loss rows — changed bytes never retain native hashes;
  only `{procedure, native_identity, R0}` losses emit today.
