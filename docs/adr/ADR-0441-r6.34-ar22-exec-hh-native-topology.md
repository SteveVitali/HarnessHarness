# ADR-0441: AR-22 — exec over `hh-embed/1`, helper `stdio = merged`/`exec_defaults`, and the HH-native participant topology under the C-05 ladder

- **Status:** Proposed
- **Date:** 2026-11-10
- **Ticket:** R6.34 (E2-T0 docs bundle, manifest row 292)
- **Requirement ids:** contributing REQ-XE-118, REQ-XE-119, REQ-XE-120
- **Spec:** `docs/experiments-spec.md` §10.5 row **AR-22** ("Exec over `hh-embed/1`; helper `stdio = merged`, `exec_defaults`; HH-native participant topology with the C-05 ladder", kind ADR, first needed by E2-T0); §7.3 gap list **G17, G22** and the REQ-XE-118/119/120/121 rows; §0.3.2 ruling **C-05** (quoted verbatim in Decision 3); §3.2 (B2's runner layering — REQ-XB-103); design note `docs/design/38_hir-native-gaps.md` Part 2 rows G17/G22, §6.4 (participant topology, design label ADR-E2-B — design spellings are proposals; this ADR fixes the record)
- **Rung (ADR-0024 obligation):** architecture record for the E2 block — no RPC/schema change lands by this record itself (AR-25's `open_session.exec` member is the separate SCHEMA change at R6.38 under CC7); no new dependency, no spend. The helper protocol member is internal and is not an `hh-embed` schema change.

## Context

Two stage-one spec changes ride this record. **G22:** exec arming does not
exist over `hh-embed/1` — `arm_exec_capabilities` is a Rust method
(`crates/hh-embed/src/service.rs` ~1580–1604) reachable only in-tree, so
no boundary caller can arm a definition's exec capabilities. **G17:**
the helper's exec semantics differ from the reference's in four recorded
ways — separate stdout/stderr pipes rather than one merged stream, a `cwd`
that defaults `"."` rather than the image's WORKDIR, no capability-declared
`env` constants, and a deadline kill aimed at the host-side process group
whose in-container effect is UNVERIFIED. **Topology:** an HH-native slot
needs the kernel participant's process shape fixed without adding a
runner→`hh-embed` dependency edge (B2's REQ-XB-103 forbids it).

## Decision

1. **Exec arms over `hh-embed/1` by explicit member.** `open_session`
   gains an optional `exec` member arming the sealed definition's exec
   capabilities over the session's environment handle, re-running the
   existing `bind` check (REQ-XE-118). The member is explicit, never
   inferred; arming refuses typed when the executor cannot satisfy the
   capability's `execution_requirement`. Its schema spelling is AR-25's
   separate SCHEMA row (`hh-embed-schema` → regenerate; CC7) — this
   record fixes the behaviour, not the wire member.
2. **`exec_defaults` and the merged-stdio helper leg.** Exec capabilities
   declare `exec_defaults{timeout_ms, stdio, cwd, env}` (REQ-XE-119). The
   helper protocol gains `stdio = merged` (stderr dup'd onto the stdout
   pipe at spawn), `cwd` defaults to the image WORKDIR under the
   CELL-SPEC contract, capability-declared `env` constants merge into the
   exec request, in-cell process-tree kill runs through `setsid`/
   `timeout --kill-after` inside the cell so the whole tree dies, and a
   timeout renders `returncode = -1` plus the declared exception text.
   The helper protocol is internal — no `hh-embed` schema change.
3. **The HH-native participant is an `hh-kernel` child process over
   binding (b)** — symmetric with a hosted harness process and inside
   B2's layering (REQ-XE-120). The slot worker spawns `hh-kernel` with
   `HH_STORE_ROOT` set to the slot store; the kernel child is that
   store's sole writer during the agent phase (no store root has two
   writers). Over `hh-embed/1` the worker calls `open_session` with the
   sealed definition and the `exec` member, provisions the cell through
   `env.open{connection_info}` reusing B2's helper cell-spec and egress
   admissions (no second provisioning path, CC1), drives the session,
   and at agent end or deadline calls `env.close{detach}` and lets the
   child exit; seal/verify/teardown re-attaches the detached cell through
   `EnvDriver` after the worker reopens the slot store. HH-native model
   lanes route through the proxy's token-gated loopback listener with
   the same pins and capture points as O — one semaphore (REQ-XE-121).
   This topology holds **only under rung (1) or (2) of the C-05
   ladder**. The ruling stands verbatim (§0.3.2):
   > REQ-XB-103 stands. Fallback ladder for HH-native slots: (1) the
   > detach/reattach spike passes; (2) the kernel child keeps cell
   > custody through seal and verify over binding (b), with no new
   > crate edge (UNVERIFIED); (3) only then an in-process binding (a)
   > exception by an ADR amending AR-04, raised to the operator through
   > a scoped `decompose-spec` insert. Never relaxed silently.
   The detach/reattach handoff is UNVERIFIED and is E2-T8's first spike;
   if both rungs fail, rung (3) requires a new ADR amending AR-04 raised
   to the operator — never a silent relaxation.

## Consequences

- R6.38 lands the AR-25 schema member and the arm path over binding (b);
  R6.39 lands the helper `stdio = merged`, `exec_defaults` decode, env
  constants, WORKDIR default and in-cell kill; R6.41 lands the HH-native
  slot worker topology after the E2-T8 spike.
- A rung-(3) outcome is a new amendment record raised to the operator,
  not an implementation detail (C-05's "never relaxed silently").
- The merged-order fixture, podman-stub argv goldens and the typed
  timeout rendering pin G17's closures; the live leg stays
  `#[ignore]`-gated under ADR-0363.

## Alternatives considered

- **Arming exec through a kernel-internal RPC extension or a fixture
  port** — rejected: the boundary is `hh-embed/1`; a side channel would
  be a second arming contract (CC1) and would skip the `bind` check.
- **In-process binding (a) for the slot kernel** — rejected except as
  rung (3): it is exactly the fallback the C-05 ladder gates behind an
  operator-raised amendment of AR-04.
- **Host-side process-group kill for exec timeouts** — rejected: the
  in-container tree's fate is UNVERIFIED; the in-cell `setsid`/`timeout`
  route makes the kill's scope real.

## Revisit trigger

Reopen if (a) the E2-T8 detach/reattach spike fails and rung (2) cannot
be verified — the rung-(3) amendment then goes to the operator before any
binding-(a) work; (b) the AR-25 `open_session.exec` member needs shape
changes at schema review (regeneration, never a patch); or (c) the
helper's merged-stdio or in-cell-kill semantics prove unimplementable
against the admitted cell backends, requiring a scoped amendment.
