# ADR-0239: S1.8 registry-store rulings — store shape and persistence, identity domain tags, yank poisons the version, `lifecycle.registry.*` spellings, minimal `query`/`slot_choices`, AC-1's second implementation

- **Status:** Accepted
- **Date:** 2026-09-16
- **Ticket:** S1.8
- **Requirement ids:** R-2.10.2⁰
- **Spec:** §6.2 (R-2.10.2 C0/Stage-1 slice) · ADR-0151 (e) · ADR-0152 (e) ·
  ADR-0153 (e) · ADR-0036/0037/0038 (identity, name histories, snapshots) ·
  READINESS_REPORT §10 minor C-17

## Context
S1.8 lands the registry *store* — the C0 slice of the C1 component-variation
registry (ADR-0151…0153). The spec fixes the contract (one identity model, one
envelope, three status axes, `hh/`+`local/` at Stage 1, never loads an
implementation on read, never model-facing) but leaves these concrete rulings
to the slice:

1. **Where the store lives and how it persists.** §6.2 §9's stage table says
   "file/ledger-backed store" for Stage 1. `hh-ledger` is the one event store,
   but a `hh-ledger` run is lease-bound and per-run; the registry's state must
   outlive any run and must replay deterministically for AC-1.
2. **Identity domain tags.** `hh-identity` mints ids under per-kind domain
   tags; `registry/1` has 25 kinds, only some of which have dedicated
   `hh_identity::RecordKind`s.
3. **Yank semantics.** `hh-identity::NameIndex::resolve(Execute)` fell back to
   the latest non-yanked *entry* — which lets a re-publish of the same version
   resurrect a pulled version, making `yank` unobservable.
4. **Event class spellings.** Spec §6.2 §6 names
   `lifecycle.registry.{registered, published, conformance_recorded,
   deprecated, yanked, revoked, imported, snapshot}`; two of those are
   ambiguous (deprecate/yank act on *names*; revoke acts on a *version*) and
   R10's refused-admission event needs a class distinct from `registered`.
5. **`query`/`slot_choices`/`substitutable` scope.** AC-R-2.10.2-1 names them
   for byte-equality, but their conformance-floor/vector/catalog semantics are
   Stage 2–3 rows of the same stage table.
6. **AC-1's "two independent implementations".** A cross-*toolchain* check
   needs foreign toolchains — not runnable under the Stage-1 offline/hermetic
   budget (the DF-S1.2-2/DF-S1.5-3 constraint).
7. **`ClassRecord.cardinality`.** READINESS_REPORT §10 minor C-17 is open:
   §5h.4's `{one-per-suite, locality}` vs §3.3's `{exactly-one, optional,
   ordered-many}` awaits a WS ruling.

## Decision
- **§1 — one persistent crate, one canonical log.** `crates/hh-registry` is the
  C0/Stage-1 E1 build binding (deps `hh-wire`/`hh-identity`/`hh-provenance`/
  `hh-ontology`/`hh-hir`/`hh-ledger` only — CC4/CC5). Persistence is a single
  canonical `registry.json` — a JSON array of typed lines (`record` /
  `name_history` / `supersedes` / `revocation` / `policy` / `diagnostic`) in
  the one canonical encoding (`hh-wire`), rewritten atomically (tmp + rename)
  on each mutation and replayed on `open` into `hh-identity`'s `NameIndex` and
  `Lineage` — **reused, never re-implemented** (CC1: no second name-history or
  lineage scheme). `registered_at`/`published_at_seq` are transaction seqs
  (line indexes), never wall clocks (§8.3 #2). Lifecycle `RegistryEvent`s are
  produced for the caller to append through the run's single fenced writer —
  the store emits, the ledger persists; the two concerns stay separable for the
  C1 service (S4.1) that will own the ledger binding.
- **§2 — identity domain-tag mapping.** `identify(record)` mints
  `{version_id, semantic_id?}` through the one `idp/1` construction
  (`hh_identity::idp_id` — `sha256:<hex>` self-describing ids). The domain tag
  is the dedicated `hh-identity` `RecordKind` where one exists (`variant`,
  `sealed_definition`, `capability`, `extension`, `model_profile`, `validator`,
  `identity_profile`); every other `registry/1` kind tags as `registry.<kind>`
  (N3 per-kind separation, additive — CC8; no new hash scheme — CC1). The
  semantic id hashes the canonical body minus the surface/name fields (N6), so
  a rename mints a new `version_id` over the same `semantic_id` and `sameness`
  reports L1 (AC-7).
- **§3 — a yank poisons the version it binds.** `NameIndex::resolve(Execute)`
  falls back to the latest entry whose *version* no yanked entry names — not
  merely the latest non-yanked entry. Otherwise re-publishing the same
  `version_id` under the name would silently resurrect a pulled version and
  `yank` would have no observable effect (CC3). Audit mode still reports the
  true head (the yanked entry), so the pulled state is visible; reproduce pins
  whatever the snapshot bound. Additive `hh-identity` change (CC8); the Stage-1
  identity tests pass unchanged.
- **§4 — `lifecycle.registry.*` class spellings, qualified by target.** The
  landed rows are `lifecycle.registry.{registered, admission_refused,
  published, name_deprecated, name_yanked, version_revoked, snapshotted,
  conformance_recorded}` — audit-grade, kernel-origin, content-free payloads
  (ids/kind spellings only; bodies pin to the record store, CC3). Deviation
  from the spec's spellings: `admission_refused` is split out because R10's
  refused-admission event is a different fact from a successful `registered`
  (the instrument must be able to count refusals without parsing diagnostics);
  `name_*`/`version_*`/`snapshotted` disambiguate the three lifecycle targets
  (a name is deprecated or yanked; a version is revoked; a snapshot is taken).
  `imported` is not landed — `import` is Stage 4. Payloads carry the `kind`
  the spec requires.
- **§5 — `query`/`slot_choices`/`substitutable` land at their deterministic
  core.** Closed, quantifier-free predicates over declared envelope/record
  fields (`UnknownField` on anything else), ordering by declared fields with
  `version_id` tie-break, no free-text relevance — exactly what AC-1's
  byte-equality needs. `slot_choices` orders deterministically and surfaces
  `param_schema` sweepable/budget_relevant flags; `substitutable` requires
  same-class and covered declarations. Conformance floors, the derived vector
  and `catalog` are Stage 2–3 (the same stage table rows) — not silently
  half-landed.
- **§6 — AC-1's second implementation, within E1.** Byte-equality is proven
  two ways: (a) two stores independently replayed from the one canonical log
  return identical `resolve`/`query`/`slot_choices` bytes, and (b)
  `corpus::naive_resolve` — a from-the-bytes resolver that never touches
  `RegistryStore` — agrees on every snapshot binding. The cross-*toolchain*
  half (E2/E3) is DF-S1.8-1, verified jointly with DF-S1.2-2/DF-S1.5-3 at
  Stage 3.
- **§7 — `cardinality` takes the §3.3 sum.** `ClassRecord.cardinality ∈
  {exactly-one, optional, ordered-many}` (the §3.3 contract shape the registry
  publishes); the §5h.4 `one-per-suite/locality` reading stays open minor
  C-17 — choosing the §3.3 sum does not pre-decide it (a later WS ruling that
  lands the §5h.4 spelling is a `registry/2` schema change, the closed-world
  growth path AC-2 names).
- **§8 — the Stage-1 suite driver is the reference test harness.** The two
  `ConformanceSuite`s declare out-of-process drivers; at Stage 1 the driver is
  the in-crate deterministic suite runner (the reference-runtime test-harness
  role, ADR-0152 (d)) producing `conformance_report`s stamped
  `produced_by = registry_ci` — registerable records, never model-facing.

## Consequences
- The store replays to byte-identical state from `registry.json` alone;
  `verify()` re-checks canonical bytes against memory, so tampering with the
  log or a record is detected (`verify_detects_tampering_and_reopen_preserves_state`).
- `hh-identity`'s execute-resolve is stricter than before (a yanked version can
  no longer re-enter through a re-bind) — an additive strengthening; existing
  identity tests unchanged and green.
- The event-class spellings deviate from the spec's literal strings; the set
  and semantics cover the same lifecycle plus R10's refusal row. The C1
  service (S4.1) must emit these spellings (or amend by ADR) — they are now
  the landed vocabulary.
- `query`/`slot_choices`/`substitutable` exist with deterministic behavior but
  no floors/vector; Stage 2–3 extends them without changing the predicate
  grammar (CC8).
- AC-1 holds within E1; the foreign-toolchain half is a recorded deferral, not
  silently claimed.

## Alternatives considered
- **Persist registry state inside a `hh-ledger` run.** Rejected: the run is
  lease-bound per-run state; the registry outlives runs and AC-1's replay
  determinism must not depend on a writer lease. Events still flow *to* the
  ledger — the ledger remains the one event store.
- **A registry-local name index instead of replaying into `NameIndex`.**
  Rejected on CC1 — name-history semantics (label uniqueness, yank/deprecate,
  widening-successor) are `hh-identity`'s; a second implementation would
  diverge.
- **Exact spec spellings `deprecated`/`yanked`/`revoked`/`snapshot`.** Rejected:
  the qualified spellings carry the target distinction the operations actually
  have, and `admission_refused` makes R10 refusals countable as events rather
  than diagnostic text. Recorded here as the owned deviation.
- **Defer `query`/`slot_choices` entirely to Stage 2–3.** Rejected: AC-1 names
  them in the byte-equality criterion — they must exist to be compared.

## Revisit trigger
A WS ruling closing minor C-17 with the §5h.4 cardinality spellings; the C1
service ticket (S4.1) needing ledger-native registry persistence or different
event spellings; or Stage-3 polyglot CI closing DF-S1.8-1 with a
cross-implementation divergence.
