# ADR-0319: S5.8 surface-ecosystem and compatibility rulings

- **Status:** Accepted
- **Date:** 2026-10-02
- **Ticket:** S5.8
- **Requirement ids:** R-2.11.4 (the C1
  slice — AC-R-2.11.4-11), R-2.2.5²
  (`memory` snapshots, `restore_in_place`,
  attested microVM images), R-2.2.3²
  (`control.wakeup.*` → MCP tasks/push,
  hosted `resume`, hibernation-aware
  leases); CC1/CC2/CC3/CC5/CC6/CC7/CC8.
- **Spec:** §7.4 (R-2.11.4 C1 — the
  generated-client ecosystem, deprecation
  machinery, the compatibility matrix, the
  OQ-130 confirmation); §5a.5 (R-2.2.5²);
  §5a.3 (R-2.2.3²); owning rulings
  ADR-0170…0179, ADR-0131/0132,
  ADR-0136/0137, ADR-0175.
- **Rung (ADR-0024 obligation):** **C1** — the surface-ecosystem/compat slice — the C1 rung.

## Context

S5.8 lands the compatibility machinery the
surface ecosystem needs at contract major 1:
the deprecation signal the stability map
advertises, the generated compatibility
matrix, the executable surface inventory that
is AC-R-2.11.4-11's evidence, and the
`R-2.2.5²`/`R-2.2.3²` extension legs
(hibernation snapshots, in-place restore,
image attestation, wakeup push lowering,
hosted resume). The run had to rule on where
each mechanism lives so none of them widens a
contract boundary or fabricates a surface
projection the kernel does not own.

## Decision

- **D1 — Deprecation is declared on the op,
  counted at dispatch, folded in the
  ledger.** `OpSpec.deprecated` carries the
  `OpDeprecation` record; the stability map
  and the schema export emit it; a call to a
  deprecated op mints durable
  `lifecycle.contract.deprecated_use{method,
  client}` under the session's writer lease
  (or the contract run when no session
  leases), and `Store::deprecated_uses`
  folds `(method, client) → count` as a
  rebuildable projection — the WAL rows are
  the record, the map is a view
  (`hh-ledger/tests/s5_8.rs`).
- **D2 — The compatibility matrix is a
  generated artifact, not a document.**
  `schema/compat-1.matrix.json` is emitted
  by `hh-codegen` from the schema source
  and drift-checked by `check-drift.sh`
  alongside the schema export and the
  generated client (CC7): the
  `(contract_major, schema_hash) → negotiate`
  table cannot silently disagree with the
  contract it describes (ADR-0178 D8).
- **D3 — The OQ-130 confirmation is a
  compile-time audit.** AC-R-2.11.4-11's
  "no private verb" claim is executable:
  `hh-kernel/tests/surface_inventory.rs`
  scans every method-position literal in
  each surface crate and asserts it names a
  registered op (or expands under a
  registered namespace for `format!`
  templates). The report it generates is
  committed at
  `docs/build/reports/S5.8-surface-inventory.md`;
  trigger 6 stays unfired and Q-L1-14 stays
  un-narrowed. The E3 ecosystem bind remains
  operator work (DF-S4.10-1, gate pending).
- **D4 — `memory` is a declared snapshot
  kind; hibernation snapshots in the suspend
  batch.** `env.snapshot{kind}` accepts
  `memory`; providers declare it in the same
  tri-state as every capability
  (`supported`/`unsupported`/`unknown` — an
  undeclared kind answers `unknown`, never a
  guess). `env.suspend{on_idle:"hibernate"}`
  takes the memory snapshot *inside* the
  suspend batch, so the hibernation and its
  restore image are one durable act
  (ADR-0131's suspension semantics).
- **D5 — `restore_in_place` is a driver
  capability, refused typed when absent.**
  The provider declares it; the driver
  routes it; heal/replace prefers a memory
  snapshot when the provider offers one —
  snapshot-first healing keeps the restored
  state provably on-record before the
  replacement proceeds.
- **D6 — Attested microVM images carry an
  attestation pairing on the
  `EnvironmentRecord`, checked at
  resolve.** Image identity and attestation
  are separate members — a foreign digest or
  tag never satisfies an `attested`
  evidence claim, and the containment
  backend selection stays fail-closed
  (`user_space_kernel`/`microvm` require
  `substrate_attestation`; missing
  attestation refuses).
- **D7 — `control.wakeup.*` lowers to MCP
  tasks/push durable-first.**
  `EmbedService::deliver_due_wakeups` is the
  kernel-internal trigger pass: the Store
  mints `control.wakeup.occurred`/`fired`
  before any surface sees a delivery, the
  session's `delivered_wokens` set dedups
  `(subscription, occurrence)` (the same
  key the run-loop drain uses), and the MCP
  carrier pushes a narrowed
  `notifications/tasks{taskId}` — the
  client re-reads `tasks/get`; a binding
  that never declared `capabilities.tasks`
  gets nothing and nothing is fabricated.
  A recorded writer session that is
  provably gone re-attaches once through
  `attach{kind:"resume",mode:"takeover",
  cause:"wakeup"}`; a `SessionDetached`
  means a live writer delivers on its own
  cadence and the drain skips.
- **D8 — The hosted `session/resume`
  mapping infers `cause` from the durable
  record.** `OpenSpec::Resume` gains an
  optional `cause` from the closed set
  (`crash`/`takeover`/`wakeup`/`operator`/
  `continuation`); the ACP driver's
  dead-writer resume opens a read-only
  `attach`, walks the tail, and declares
  `wakeup` only when an awaiting-*/
  `hibernated` suspension is followed by a
  `control.wakeup.fired` row — the durable
  record decides, never the caller's claim
  (AC-R-2.2.3-13). A live writer keeps
  pure-replay semantics. Suspended runs
  stay exempt from liveness takeover
  (ADR-0131 §4 — the exemption is the
  shortening, not the lease; covered by
  `durable_execution::ac_2_2_3_5_suspended_run_is_exempt_from_liveness_takeover`).

## Consequences

- A deprecated op stays callable — the
  contract is additive (CC8); the
  `deprecated_use` row is the audit trail a
  future major uses to justify removal.
- `delivered_wokens` is session state, not
  ledger state — a restarted writer drains
  from the durable `fired` rows and the
  dedup re-arms from the record.
- The `cause` inference reads only durable
  rows; it mints nothing (the scan `attach`
  is read-only and closed best-effort).

## Alternatives considered

- **Pushing full task status in
  `notifications/tasks`** — rejected: the
  narrowed `taskId`-only push keeps the
  durable `tasks/get` read authoritative;
  shipping a computed status in a
  notification invites divergent projections
  (CC3/CC5).
- **A surface-owned wakeup table** —
  rejected: a far-side table would be a
  second authority for deliveries the WAL
  already records; the session-level dedup
  is the only non-durable state the
  lowering needs.
- **Trusting the caller's resume `cause`**
  — rejected: CC2 — the cause is inferred
  from durable evidence; a caller could
  otherwise launder an operator restart as
  a wakeup (or vice versa) and corrupt the
  audit trail.
- **Hibernation as a separate op** —
  rejected: `suspend{on_idle:"hibernate"}`
  keeps suspension one durable act with its
  snapshot; a two-call form would leave a
  window where a suspended run has no
  restore image.

## Revisit trigger

Reopen if the E3 ecosystem bind lands
(HUMAN-H1) and the in-tree generated client
stops being the proxy; if a second delivery
class (e.g. SSE push per DF-S4.11-1) must
coexist with the drain-through-response
shape; if `delivered_wokens` needs to
survive a writer restart within one surface
session; or if a new `Trigger` variant
changes the `occurred`/`fired` row shape the
drain and the cause inference read.
