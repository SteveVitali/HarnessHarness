# ADR-0307: S4.14b security enrichments — backend, attestation, rotation, hosted composition and label-branch rulings

- **Status:** Accepted
- **Date:** 2026-09-28
- **Ticket:** S4.14b
- **Requirement ids:** R-2.8.4¹ (AC-R-2.8.4-{12,13}),
  R-2.8.1¹ (AC-R-2.8.1-4), R-2.8.3¹ (AC-R-2.8.3-7),
  R-2.8.6¹ (AC-R-2.8.6-{8,10}), R-2.1.5¹ (AC-R-2.1.5-6),
  R-2.8.2 Stage-4 slice (AC-R-2.8.2-6)
- **Spec:** §5g.4 (containment classes, per-phase layers);
  §5g.6 §2 (signed checkpoints, rotation claims, the audit
  index); §5g.1/§5g.3 (delegation, credential supply, LT-07);
  §5g.2 (label branches, `branch` remedy); §5e.3 T7 / §6.6
  (hosted children, C-10); ADR-0051…0068 (owning set);
  ADR-0164/0165 (hosting seam)

## Context

S4.14b lands the Stage-4 security enrichments across six
crates. Five seams needed owned rulings — each is a choice the
spec leaves to the implementation and each now has exactly one
spelling (CC1/CC7):

1. **How the new containment backend classes are spelled and
   selected.** `R-2.8.4¹` names `user_space_kernel`/`microvm`
   plus the transparent-redirect class; the `isolation_class`
   field needed one closed vocabulary and one selection rule
   (`policy → backend`).
2. **What `attested` evidence is.** Stronger backends mint
   stronger claims only when a supplied attestation resolves —
   a backend may never claim `attested` for evidence it cannot
   mint, and `unknown` is never coerced upward.
3. **What identity rotation looks like at the ledger.** The
   `idp/1 → idp/2` boundary needed one record shape: how the
   covered prefix is re-digested (`rehash`), how the two
   profiles are bridged (`security.audit.bridge`), and what a
   `rotation` checkpoint claims.
4. **Where hosted children compose.** `ChildProcess::Hosted` is
   a `Ref<OpaqueProcess>`; the kernel must spawn one without
   resolving the opaque record itself (the Hosting ABI is an
   instrument-level boundary, not a kernel read).
5. **What a label branch's exits are.** `spawn_branch` needed
   the closed exit set — how the child returns (or doesn't),
   what label the re-entered content lands at, and what a
   `branch` remedy consumption mints.

## Decision

- **D1 — Backend spellings and `for_policy` selection.** The
  `BackendClass` closed set is `{process_sandbox, namespaces,
  user_space_kernel, microvm, transparent_redirect, external}`
  (`crates/hh-containment/src/backend.rs`); the
  `ContainmentPolicy.proc.isolation_class` member carries the
  same spellings and `for_policy(policy)` is the *one*
  selection function — `hh-embed`'s provisioning sites never
  pattern-match classes themselves. `net_plane()` distinguishes
  `BridgedChannel` (a socket the harness owns) from
  `TransparentRedirect` (no bridged channel — the network
  namespace rewrites destinations; probes skip the socket
  check). `user_space_kernel` and `microvm` carry `Attestation`
  requirements: without a supplied `attestation_ref` they
  refuse `attestation_missing` at provisioning — never
  silently degrade (CC3).
- **D2 — Attestation is evidence the backend can mint, never a
  claim it wishes.** `ContainmentBackend::attestation()`
  returns `Option<Attestation>`; `attach` evidence stamps
  `Attested` only for classes whose `attestation()` minted —
  `probed`/`reported` stay honest otherwise. An attestation is
  a ref (`attestation_ref`), not an embedded blob — the
  substrate record lives outside the row, cited by digest.
- **D3 — Rotation is one record pair, never a rewrite.** A
  declared `RotationPlan{from_idp, to_idp, bridge, rehash, …}`
  mints a `security.audit.bridge` row (the cross-profile
  identity mapping record) and a `kind = rotation` checkpoint
  whose claim carries `identity_profile`, `rehash{idp,
  chain_hash, tree_head}` (the covered prefix re-digested
  under `to_idp`), `bridge_record_ref` and `attestation_ref?`
  (`crates/hh-ledger/src/rotation.rs`; `store::checkpoint`
  refuses `kind = rotation` — the dedicated op owns the
  members). Stored ids are never rewritten: pre-rotation
  claims verify under `idp/1`, the auditor rehashes the
  covered prefix under the claim's profile, post-rotation
  claims chain `prev_checkpoint` to the rotation claim
  (AC-R-2.8.6-8).
- **D4 — The lab-wide audit index and the bundle attestation
  member.** `AuditIndex` (`crates/hh-ledger/src/audit.rs`) is
  the ADR-0067 D5 "where the writer cannot write" store:
  append-only `(run_id, checkpoint_ref, tree_size, tree_head,
  signatures)` rows; a different `tree_head` at a held
  `(run_id, tree_size)` is `Equivocation`; a byte-equal
  re-record is a no-op. The bundle carries the same tuple as
  `traces.<run>.audit_tree_head`
  (`crates/hh-bundle/src/manifest.rs` `AuditTreeHead`) — the
  newest *signed* checkpoint's claim, verbatim (absent —
  never fabricated — when the run minted none).
- **D5 — `HostedPlane`: the hosted-child composition seam.**
  `crates/hh-subagent/src/hosted.rs` defines the object-safe
  JSON seam (`open_child` / `send_verb` / `cancel`) that
  `spawn` composes a `hosted` child through; the kernel never
  resolves `OpaqueProcess` itself. `open_child` is idempotent
  on `child_run_id` (the deterministic `sub-<H(decision,
  H(spec))>` id rides the spec — KP-21 at the boundary: a
  retried spawn lands on the same session). The child manifest
  stamps `participant_class = hosted`,
  `hosting_mechanism = <resolved>`; the spawned row carries
  `hosted{session_ref, hosting_mechanism,
  capability_declaration_ref?}` so the interrupted-spawn
  adoption path rebuilds the manifest from the durable row —
  never a second `open_child`. `send_verb` is where uncovered
  calls are refused (`UncoveredCall`/`UnknownVerb`;
  undeclared ⇒ `unknown`, never granted — ADR-0053 D-4,
  AC-R-2.8.1-4); `cancel` is the C-10 failure verb — a hosted
  child fails at the boundary, nothing reaches inside.
- **D6 — Label-branch exits are a closed three-member set.**
  `BranchExit ∈ {abandon, labeled_return, attested_return}`
  (`crates/hh-subagent/src/branch.rs`):
  `abandon` records `control.subagent.branch_exited{exit:
  abandon}` with no re-entry; `labeled_return` re-enters the
  result at `external` with the union taint — a declared label
  that drops a tag is `BranchTaintEscaped`; `attested_return`
  lifts a capacity-bounded closed-schema value to
  `environment` and clears taint under a
  `security.label.endorsed{capacity_bits}` row — a free-text
  schema is `BasisNotAllowed` (shape endorsement never
  endorses prose). Spawn refuses `ceiling > clearance` as
  `ClearanceExceeded`; a `branch` remedy consumption mints the
  same `spawned` row with `isolation = label_branch`, `ctx0`
  and `clearance` kernel-stamped (ADR-0054 D4). Child-side
  approvals never authorize the parent's effects — a
  delegate-class endorsement of a parent effect is
  `IllegitimateEndorsement` (AC-R-2.8.2-6 closed).

Also landed under the same ticket, without owning rulings:

- **Per-phase `policy_rule` layers** — `hh_env::set_phase`
  re-derives the environment's containment through
  `meet::effective()` over the sealed layer document; an
  undeclared phase refuses, a non-`policy_rule` basis refuses
  `BasisNotAllowed`, an unentitled loosening is
  `ContainmentWidening` (AC-R-2.8.4-13).
- **LT-07** (`AC-R-2.8.3-7`) — the three prongs are enforced
  where the spec put them: `ScopeExceedsChannel` at the broker
  `grant` for child-scope asks; hosted `credential_supply`
  declared-only at `HostingService::open`/`deliver_credential`
  (`CredentialChannelUndeclared`; the value never crosses the
  verb surface).

## Consequences

- `process.hosted` joins the spawnable `ChildProcess` set —
  pinned-ref-only, same rule as `harness_def` (a selector is
  never admitted). A `hosted` spec without a `HostedPlane`
  refuses `ModeUnsupported` — there is no silent degrade to
  native composition.
- The spawned-row schema gains `hosted{…}`, `ctx0`,
  `clearance`; the `LedgerExport` schema gains
  `audit_tree_head` — all additive members, absent on rows
  written before this ticket (CC8).
- `hh-subagent` does **not** depend on `hh-hosting`: the seam
  is a trait in the kernel crate, implemented by the hosting
  side (or a test double) — the dependency direction stays
  contract-only (CC5) and the plane is absent in any build
  that excludes hosting (removability: `hosted_plane = None`
  ⇒ `ModeUnsupported`, the honest refusal).
- The lab-wide audit index is in-memory in `hh-ledger` —
  durability behind the auditor's own store is §5g.6's
  later-stage retention row (see DEFERRALS).

## Alternatives considered

- **Kernel-side `OpaqueProcess` resolution** (spawn reads the
  definition store directly) — rejected: the Hosting ABI is an
  instrument-level boundary and `OpaqueProcess` resolution is
  adapter/placement mechanics; pushing it into `hh-subagent`
  would invert the CC5 direction and couple the kernel to the
  hosting tier.
- **`audit_tree_head` computed by the bundle assembler** —
  rejected: the member attests to the writer's *signed claim*,
  never to a head the assembler computed; only the claim's own
  `tree_size`/`tree_head`/`signatures` are copied.
- **Re-recording index rows as faults** — rejected:
  re-attestation is a delivery artifact, not disagreement;
  only a *different* head at a held `(run_id, tree_size)` is
  `Equivocation`.

## Revisit trigger

- A second hosting transport needing more than the three-verb
  seam (`open_child`/`send_verb`/`cancel`) — e.g. mid-session
  credential rotation or pause/resume verbs — reopens D5's
  verb surface (the seam is deliberately minimal at Stage 4).
- Durable audit-index persistence (writer-remote storage,
  index compaction) reopens D4's in-memory form when §5g.6's
  lab-wide retention policy lands.
- `remote`/`container` placements that put the hosted child
  outside the Lab-provisioned environment reopen the C-10
  boundary model (D5 assumes the adapter reaches the boundary).
