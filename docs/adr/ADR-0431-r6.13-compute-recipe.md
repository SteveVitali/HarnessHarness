# ADR-0431: The AR-15 compute recipe — admitted `gcloud`, declaration/receipt schemas, nine-step teardown (R6.13)

- **Status:** Accepted
- **Date:** 2026-11-07
- **Ticket:** R6.13 (manifest 266)
- **Requirement ids:** REQ-XB-201…212, REQ-XB-219, REQ-XB-220, REQ-XB-223, REQ-XB-224, REQ-XH-008, REQ-XH-009, REQ-XH-023, REQ-XD-051, REQ-XB-215
- **Spec:** experiments §3.9, §3.10, §3.11, §6.7, §10.1.5, §10.3, §10.5; design/32 recipe + F14; Appendix B Q-X17/Q-X37/Q-X38/Q-X60
- **Rung (ADR-0024 obligation):** C1 — new script-level boundary contract (`hh-compute-decl/1`, `hh-compute-receipt/1`); no amendment of the frozen spec or any kernel contract

## Context

§3.9/§3.11 requires a safe, deterministic, auditable GCE recipe that must
be provable **offline** before any real GCP use: typed declarations,
receipts, a nine-step unskippable teardown, and the stdin-only secret
path. §10.5 admits `gcloud` and the pinned Podman package set — nothing
else. AR-15 owns the choice of provisioning tool and the boundary
schemas. Q-X60 names the restart default; Q-X37/Q-X38 name the dead-man
and teardown posture; Q-X17 names the secret delivery constraint.

## Decision

1. **One provisioning home: `scripts/gce-backend.sh` (bash 3.2) + a
   plain `gcloud` CLI — no Terraform, no new tool.** A single script
   keeps every cloud call greppable and auditable; the battery greps
   `scripts/` to prove `gcloud` appears nowhere else. Nine subcommands:
   `quote`, `provision`, `verify`, `prepull`, `deliver-secret`,
   `status`, `harvest`, `teardown`, `inventory`. `startup.sh` is the
   committed, leak-scanned boot script.
2. **`hh-compute-decl/1` closed schema** — validator
   (`validate_decl.py`) refuses unknown/missing fields, image families,
   unpinned packages (`>=`, ranges), non-IAP ingress, Spot models,
   service accounts, missing dead-man `D`, and restart windows > 1 h.
   `mode: full | restart-only`; restart-only is harvest-and-teardown
   only (Q-X60).
3. **`hh-compute-receipt/1` closed schema** — one receipt per
   provision/verify/prepull/harvest/teardown: verbatim command list
   (redacted argv, rc, stdout sha256, bounded excerpt), resources,
   verification block, teardown-only `post_state`, settlement clock,
   and the `cost_record: n/a{compute_cost_record: R6.14}` hook. Every
   receipt is leak-scanned before persistence; a hit refuses the write
   (exit 5). `validate_receipt.py` enforces the shape; the
   prior-phase-project guard refuses re-use of another phase's id.
4. **Nine-step teardown is structural, not advisory** — drain → harvest
   under a sha256 manifest (verified locally, required before delete) →
   serial/usage → full-class inventory → delete → re-inventory →
   (phase-close) project delete with `DELETE_REQUESTED` → kill helpers
   → receipt. Steps are recorded in order in the receipt; harvest
   failure refuses before any delete; leftover billables refuse;
   `WARNING`/failed lists mark `inconclusive{…}` (exit 6), never
   "empty". The only admitted deviation is *stopped instance + retained
   disk* under a declared dated `DF-*` row inside `h_r`.
5. **Secret path is stdin-only (§3.11, Q-X17)** — `deliver-secret` is
   the sole Ollama-key channel: the value streams over `gcloud compute
   ssh` stdin into tmpfs `/run/hh/secrets/NAME` (0400, owner `hh`),
   never argv/metadata/startup/disk/receipts. Refused for a $0 or
   unauthorized model window and under restart-only. Receipts record
   `provided: yes/no` only.
6. **`quote` is `pre-quote`, quantities only (§3.10, REQ-XD-051)** —
   emits the declaration quantities and their §3.10 symbols (incl.
   `H_rs`, `h_r`, `E_gib` labelled `estimated`), makes zero network
   calls, and carries `pricing: n/a{compute_pricing: R6.14}`. Pricing
   and `hh-compute-cost/1` are R6.14's.
7. **`compute-open.sh` (REQ-XB-211) + `compute-gate-span.sh`
   (REQ-XH-009)** — the open-compute index lists provision receipts with
   no matching teardown; empty output is required for phase/round
   closure. Gate-span fails a window whose provision→teardown span
   crosses a gate's wait unless the readout records `vm_stays_up`.
8. **Offline proof, not live proof** — `check-gce-backend.sh` puts a
   fake `gcloud`/`ssh` on PATH, records argv, serves canned state, and
   exercises every refusal, receipt shape, teardown ordering, and the
   secret path: 79/79 deterministic. No credential, provisioning, or
   spend is made or claimed; REQ-XB-212 live evidence is R6.47's.

## Consequences

- The recipe is provable offline; the same script is what a live run
  executes, so the fixture-verified refusals/ordering are the live
  semantics (modulo real-GCP latency/errors).
- Any future provisioning tool change is an ADR and a battery rewrite —
  `gcloud` is the admitted surface only.
- `hh-compute-cost/1` does not exist; R6.14 owns it and the
  `billed: pending` wiring.

## Alternatives considered

- **Terraform/Pulumi** — refused: a new provisioning tool needs an ADR
  and adds a state file and provider graph where §10.5 admits only
  `gcloud`; a single auditable bash recipe is the smaller trusted base.
- **gcloud config / deployment manager templates** — refused: hides the
  argv the receipt must record verbatim; flags are the audit surface.
- **Skipping re-inventory after delete** — refused: F14 requires the
  second inventory to prove every billable class is empty or declared
  residue.

## Revisit trigger

Re-open if (a) a second provisioning surface is admitted (new tool, new
cloud, or a second `gcloud` call site) — the single-home assertion and
this ADR must be re-cut; (b) `hh-compute-decl/1` or
`hh-compute-receipt/1` gains or drops members — the schemas are closed
and this record documents the field set; (c) R6.14 lands pricing and
the `cost_record`/`billed: pending` hook is wired; or (d) REQ-XB-212's
live evidence (R6.47) surfaces a fixture/live divergence the battery
cannot express.
