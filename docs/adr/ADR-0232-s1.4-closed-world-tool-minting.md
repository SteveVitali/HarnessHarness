# ADR-0232: S1.4 closed-world tool minting — the sealed definition carries the MintingContext `default_authority_in` consults (closes DF-S1.3-3)

- **Status:** Accepted
- **Date:** 2026-09-15
- **Ticket:** S1.4
- **Requirement ids:** R-2.1.2, R-2.1.5 (§8.1 #3 minting); discharges DF-S1.3-3
- **Spec:** §8.1 (the minting table — `environment` requires a closed-schema structured
  value from a closed-world tool declared in the sealed definition); §3.1.5 (`seal`);
  §3.1.3 (`ToolCapability.effects`) · ADR-0033, ADR-0230 (the Stage-1 floor this lifts)

## Context
DF-S1.3-3 (opened by ADR-0230) held `Origin::tool` at the `external` floor because the
`environment` mint requires *a closed-world tool declared in the sealed definition* — and
no sealed-definition surface existed for `default_authority` to consult. S1.4 lands `seal`
and the `ToolCapability` effect declarations, so the wiring the deferral asked for can now
be built — or found still missing. Two sub-questions: (a) what counts as "declared
closed-world" in a sealed definition; (b) where the declaration set lives so minting can
consult it without a global registry.

## Decision
- **`hh-provenance` gains `MintingContext` + `default_authority_in`** (CC8 additive —
  `default_authority` delegates with the empty context, so the Stage-1 floors are the
  defaults, unchanged). `MintingContext { closed_world_tools: BTreeSet<String> }` is the
  only thing `environment` minting consults: `Origin::tool { capability, .. }` mints
  `environment` iff `capability ∈ closed_world_tools`; otherwise the `external` floor
  stands. Free text never rises — text values still mint through `default_text_authority`
  capped at `external` for non-kernel/non-human origins (R-TEXT).
- **The sealed definition computes and carries the context.** `seal` populates
  `SealedDefinition.closed_world_tools` from the document's `ToolCapability` members: a
  capability is closed-world iff `effects = Pure`, or `effects = Declared(set)` is
  non-empty with every declared effect `world = closed`. The declaration is *inside the
  sealed definition* — the definition pins which of its own tools may mint `environment`;
  there is no ambient/global closed-world list. `SealedDefinition::minting_context()`
  hands the set to `default_authority_in` as a `MintingContext`.
- **The `validator` endorsement route is unaffected** — the external → environment raise
  for a `ClosedSchemaValue` under a kernel endorser stays exactly as §8.1 specifies; the
  minting route is additive alongside it.

## Consequences
- Good: DF-S1.3-3 closes for real — `environment` is reachable by the minting table, not
  only by endorsement, and the acceptance test
  (`seal_identity.rs::closed_world_tools_mint_environment`) proves a capability declared in
  a sealed definition mints `environment` through the definition's own context while an
  undeclared tool still mints `external` and free text stays capped.
- Cost: `environment` minting is now context-dependent — a caller must hold the
  `SealedDefinition` (or its `MintingContext`) to mint above `external` for a tool. That is
  the §8.1 semantics (the declaration is definitional), but it means no free function can
  mint `environment` without the definition in hand; call sites that mint tool origins
  outside a sealed definition continue to get `external`.

## Alternatives considered
- **Leave the floor, document the seam** (keep DF-S1.3-3 OPEN/PARTIAL) — the deferral's
  close condition is exactly this wiring; with `seal` and effect declarations landed there
  was no remaining blocker. Rejected as an unnecessary open deferral.
- **A registry-level closed-world list** (capability ids declared closed-world once,
  consulted everywhere) — breaks locality: §8.1 binds the declaration to *the sealed
  definition*, so two definitions may disagree about the same capability id; a global set
  would let a tool mint `environment` under a definition that never declared it. Rejected.
- **Deriving closed-world from `ToolEffects::Declared` containing any closed effect** —
  over-admits: a tool with one closed and one open effect is not closed-world. The
  all-effects-closed (or `Pure`) predicate is the conservative reading. Chosen.

## Revisit trigger
Reopen if the `ToolEffects` sum grows a variant that changes what "closed-world" means for
a capability (a dialect-level assessment under CC8), or if a later stage needs minting
consultation to include non-sealed (e.g. run-scope) declarations.
