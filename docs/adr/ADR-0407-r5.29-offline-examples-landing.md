## Context

§7.2 binds the early **offline** example families: **EX-01**
(setup → scripted quickstart → attach by the returned run id →
annotated durable excerpts → native export → clean-recipient
verify → isolated-replay admission) and **EX-02** (the informative
Lab lesson — two tasks × two arms × five repetitions = 20 subjects
through the real register/expand/open/next/claim/launch/grade/
settle/close chain, projected rows, a persisted analysis report
and clean-recipient recomputation). The examples must be runnable
**versioned** records carrying semantic controls: the verdict is
semantic, never process exit; a wrong count/mean, a constant
teaching-only fixture, an incorrect verdict, a stale pin, and any
producer fallback all fail; a configured sample or budget never
becomes a confirmation default; separated build/runtime costs and
fixture limitations are stated on the record itself. Before this
ticket every owner the examples compose had landed — the scripted
`EmbedModel` lane (R5.8), `hh-recipe/1` (R5.28, ADR-0406), the
`finite_manifest_contrast` estimator and routed persisted report
(R5.16/R5.16b/R5.17), `assemble_receipt`/`population-receipt/1`
(R5.23), `kernel.reproduce` R0 (R5.24), `recompute_analysis`
(R5.25, ADR-0403), `admit_replay` (R5.26, ADR-0404) — but the
EX-01/EX-02 rows existed only as design prose (design 15); no
pinned, checked, versioned card ran them.

## Decision

1. **`example-card/1` is the versioned card record** — committed
   under `scripts/examples/` (`ex-01.json`, `ex-02.json`; the
   lesson's pinned data is `ex-02-fixture.json`,
   `ex-02-fixture/1`). `ExampleCard::from_json` decodes a closed
   member set `{schema, case:"ex-01"|"ex-02", title, card_version,
   fixture_label, prerequisites{rust, network:false,
   credentials:"none", spend_usd:0, companion}, pins{<name>:
   {path, sha256}}, checks[], negative_controls[], costs{build,
   runtime}, limitations[], run}` — a member outside the set
   refuses `unsupported_shape`, an absent required member
   `missing_field`, a wrong-typed member `type_mismatch`, an
   unadmitted `case` `unknown_case`. The card *is* the reader-
   facing record: separated build/runtime costs, the honest
   `fixture_label`, prerequisites and limitations are mandatory
   members that ride every report verbatim — never dropped.
2. **One checked runner lives at `hharness::examples`** —
   `run_example(&mut EmbedService, &ExampleCard, work, repo_root)
   → Result<ExampleReport, ExampleError>` in
   `crates/hharness/src/examples.rs` (2,128 lines; runner version
   `hh-examples/1`). The facade is the composition home beside
   `recipe.rs` (I-02): the runner drives binding (a)'s in-process
   `EmbedService::handle` plus the owner seams
   (`run_recipe`, `analyze_and_record`, `recompute_analysis`,
   `admit_replay`, `decode_dir`/`decode_page`,
   `ResultsStore`/`LabDocs`/`ExperimentView`) — records-in/
   records-out, no public RPC, no second codec/store/runner, no
   `hharness → hharness-cli` edge, every durable mutation through
   a boundary op or the owning interface. The **pin leg**
   recomputes every declared `sha256:` over the pinned file's
   actual bytes (`hharness_wire::sha256::sha256_hex`) — drift
   refuses `stale_pin` **before any execution**; a card never
   re-pins itself.
3. **`ExampleReport` is the semantic record** — `{runner_version,
   case, card_version, verdict, checks[]{id, verdict, detail},
   records, costs, limitations, fixture_label}` with
   `verdict ∈ pass | fail` and each check `pass | fail |
   expected_refusal` (an expected refusal recorded verbatim — the
   assertion passed while the operation stayed refused; never
   counted as a pass of the refused operation). `pass` requires
   every declared check green; a card-declared check the runner
   never produced is `check_missing`; `detail` records actual
   ids/counts/refs, never "ok". `to_json` emits canonical JSON.
4. **`ExampleError` is a closed sum, never re-classified** —
   `Refused{code, detail}` over the six-code set
   (`stale_pin`, `unknown_case`, `unsupported_shape`,
   `missing_field`, `type_mismatch`, `check_missing`);
   `Boundary{method, detail}` wraps a boundary op's error body
   verbatim; `Owner{seam, detail}` wraps an owner interface's own
   error verbatim.
5. **The EX-01 driver checks the scripted quickstart honestly** —
   `hello` (the negotiated result recorded verbatim) →
   `open_session` on the pinned `clients/ts/fixture-definition.json`
   → `submit{hh.submit}` → attach **by the returned run id** → the
   six excerpts each resolve to actual event id/seq/payload/causes
   (run/definition/submission; the `model.call.*` →
   `action.effect.intended` join on `tool_call_id`; intended +
   `security.permission.decided{allow, policy_ref}`; the
   authorized→prepared→committed→observed chain with observed
   bytes; `lifecycle.run.finished` vs `verification.*` +
   `measurement.metric` rows; `context.assembled` + the replay
   copy's `lifecycle.replay.*` markers) → `kernel.bundle{run_id,
   deliver_sink}` → a **clean recipient** (a fresh `EmbedService`
   on a separate scratch store — `kernel.check_completeness` +
   `kernel.reproduce{level:R0}` → `reproduced`; the recipient reads
   only the exported dir, no producer-side object) → `decode_dir`
   + `admit_replay` over the isolation-flagged replay copy. The
   scripted lane produces no `compiled_bundle` member, so the
   admission answers its typed `CardRefused{missing_input}` —
   recorded verbatim as `expected_refusal` (deviation G3), with a
   tampered-copy `not_admitted` control; the exercised replay-
   adjacent evidence is the clean-recipient completeness + R0
   `reproduced` leg.
6. **The EX-02 driver runs the informative lesson through the
   landed owners** — the committed `ex-02-fixture/1` carries the
   pinned grade table (task1 A=1/5 B=4/5, task2 A=3/5 B=2/5) plus
   **independently pinned `expected` counts** the durable rows are
   reconciled against → **one `run_recipe` per task** (a plan's
   grade map is `arm → per-cell-replicate`; two tasks in one
   experiment would share one grade vector — the constant fixture
   AC-2 forbids) → each `population-receipt/1` verdict `closed` →
   the durable `measurement.metric.emitted` rows re-read through
   freshly opened `Store`/`ResultsStore`/`LabDocs` handles (a
   recipient-side rebuild — no producer-side objects) → the merged
   `ExperimentView` (union of both experiments' `plans`/
   `amendments` — the bound 20-slot universe `finite_manifest_
   contrast`'s `tasks>=2` floor requires) → `analyze_and_record`
   (`beta{1,1}` registered prior only — DF-R5.17-1) over all 20
   row keys → persisted `analysis_report_body/1`; a repeat serve
   returns the identical `report_id` (idempotent, never recompute)
   → `DeclaredReceipt` + `recompute_analysis` (frozen pins + the
   all-planned population reconcile) → `reproduced`. Semantic
   checks: `subjects_20`, `cells_pinned` (durable grade rows
   recompute to the pinned sequences — a wrong count/mean fails),
   `informative_contrast` (per-task cells present, contrasts
   unequal nondegenerate — a constant fixture fails),
   `report_identity`, `recipient_recompute`, `exploratory_label`
   (`AnalysisStatus::Exploratory` — a configured sample/budget
   never becomes a confirmation default), `refusal_controls` (bad
   lease, missing row, duplicate settle — the owners' typed errors
   verbatim).

## Consequences

- A reader can run both committed cards on scratch stores — one
  `cargo test -p hharness` compile of the existing tree, runtime
  seconds, $0 — and receive semantic `ExampleReport`s whose every
  check resolves to actual durable ids/seq/payloads; the cards'
  costs, limitations and fixture labels ride the reports verbatim.
- `tests/r5_29.rs` (7 checks) exercises both cards end-to-end plus
  the AC-2 negatives — `ex02_stale_pin_refuses` (typed `stale_pin`
  before execution), `ex02_wrong_count_fails` (the independent
  `expected` pin catches a flipped grade), `ex02_constant_fixture_
  fails_the_lesson` (`informative_contrast` fails while the
  degenerate interval still records), `ex02_withheld_recompute_
  input_refuses_no_fallback` (typed `Withheld{member}` — never a
  producer-side fallback), `card_decode_refusals` (the closed
  member/refusal surface) — compile/missing-file red at base
  `4dd6159e` (the module, cards and test do not exist there).
- REQ-A-008 and REQ-F-101…105 are stamped **contributing-only** —
  achieved engineered D/E recorded separately from the owed legs
  (primary owner R5.45's AC-3 plus every R/P/actual-execution
  predicate); no deferred full-target predicate becomes MET
  because this ticket closed.
- No crate edge added (every owner dependency was already a facade
  member), no schema/wire change, no new event class, no new
  dependency; the scripted `EmbedModel` lane is real execution
  through the existing runtime — actual task/provider/participant
  execution stays gated; fixture-verified evidence never upgrades
  to live.
- AMEND ruling `ff31b141`: 2,564 changed source/test lines vs ≤850
  (~3.0× — the new build high-water mark, exceeding the prior
  ≤2.6× envelope; band is precedent-not-limit, ~2.8–4.3× the
  packet estimate is in-family) — recorded Deviation accepted.

## Alternatives

- **Examples as shell scripts or README prose beside
  `scripts/`** — rejected: §7.2 requires runnable *versioned*
  cards with semantic controls; prose cannot pin bytes, declare
  checks, or record verbatim costs/limitations a runner enforces.
- **A second runner crate or a shadow result/receipt store** —
  rejected: §2.1 forbids a second runner/store and I-02 gives the
  facade the composition home; `hharness` already depends on every
  owner the drivers touch.
- **EX-02 as one experiment with two tasks** — rejected: a plan's
  grade map is `arm → per-cell-replicate`, so two tasks in one
  experiment share one per-cell grade vector — the constant
  fixture AC-2 explicitly fails. Two recipe runs + the merged
  `ExperimentView` is the honest bound population.
- **A producer-side shortcut for the recipient legs** (passing the
  live service/store handles to the export/replay/recompute
  legs) — rejected: the recipient reads only the exported dir and
  freshly opened handles over durable facts; a withheld input is a
  typed `Withheld{member}`, never a fallback.
- **Counting `admit_replay`'s typed refusal as a failure or as a
  pass** — rejected: the scripted lane produces no
  `compiled_bundle`, so `CardRefused{missing_input}` is the honest
  outcome — recorded verbatim as `expected_refusal` with the
  tampered-copy control, while the clean-recipient R0 `reproduced`
  leg carries the exercised verify evidence.
- **Splitting EX-01/EX-02 into two dispatches to fit the trigger**
  — rejected per the scoped review: packet 3 OFFLINE binds them as
  one owner unit (no contingency), the documented family boundary
  is EX-01/02-vs-EX-03/04, the inter-row seam is undocumented, and
  every proposed leg stays over the trigger — non-curative.

## Revisit triggers

- If a later admission adds an example family under
  `scripts/examples/` (the EX-03/EX-04 integration tickets), the
  `case` member's admitted set grows by a versioned card/runner
  amendment — never a silent case; this record's per-family
  drivers are the precedent.
- If the scripted `EmbedModel` lane mints a `compiled_bundle`
  member for the pinned definition, re-read the
  `replay_admission` leg — today `CardRefused{missing_input}` is
  the recorded `expected_refusal`; a produced bundle makes
  `admitted` the required verdict.
- If `finite_manifest_contrast`'s `tasks>=2` floor or required-
  member map changes, or `hh-recipe/1`'s `RecipePlan` member set /
  the boundary op vocabulary changes, re-run the whole r5_29
  battery — the EX-02 driver inherits the estimator floor and
  threads plan members verbatim.
- If the pinned files (`clients/ts/fixture-definition.json`, the
  committed fixture bytes) change, the cards' `sha256:` pins
  refuse `stale_pin` — a re-pin is a card-version amendment, not
  an in-place edit.
- If DF-R5.17-1's parameterized-prior repair lands (R5.40), the
  `beta{1,1}` pin on the lesson is unaffected — re-check only if
  the registered arm vocabulary itself changes.
