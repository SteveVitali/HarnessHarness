# ADR-0335: R2.4 environment lifecycle ops + automatic snapshot cadence — the declared-cadence producer at the sink seam, the seven env.* boundary ops gated on driver capabilities, and the canonicalized root check

- **Status:** Accepted
- **Date:** 2026-10-06
- **Ticket:** R2.4
- **Requirement ids:** DF-S2.9-3 · DF-S2.10-1 · BL-13 · R-2.2.4 ·
  R-2.2.5 · R-2.11.1 · R-2.11.4
- **Spec:** §5a.1 (environment binding — `connection_info{snapshot_cadence}`,
  the snapshot record, `taken_by`) · §5a.2 (environment operations —
  diff/restore/upload/download directions) · §5a.5 (loss posture,
  suspend/hibernate) · §7 (the `hh-embed/1` verb surface) · ADR-0136…0138
  (the env verb table) · ADR-0272 (the env/snapshot capability map)
- **Rung (ADR-0024 obligation):** C2 — the seven `env.*` ops land as
  additive `hh-embed/1` members (CC7/CC8) routed through the one boundary
  dispatch over the `tier-c1`-gated `hh-env` machinery (absent tier or
  absent declared capability answers `Unsupported`/`UnknownCapability`,
  never silent degrade, CC6).

## Context

DF-S2.9-3 (the automatic snapshot *producer*) and DF-S2.10-1 (the seven
unbacked env verbs) were the surviving environment/snapshot residual —
BL-13. S2.9 landed the snapshot *chooser* (`snapshot_for` at-or-below the
cut, `derive_from_snapshot`); S2.10 landed the manual `env.snapshot` op;
S5.8 landed the driver legs (provider `memory` snapshots,
`restore_in_place`, hibernate-in-suspend). What remained was the schedule
(no ticket owned when to pay the walk) and the verb bindings (each verb
refused `stage_pending` because no honest path existed). The CAP.2
composed battery carried the last `#[ignore]`d xfail —
`cap2_fork_at_turn_boundary_without_explicit_snapshot`.

The mechanism choices below were the ticket's to fix: where the cadence
fires, how the op family maps onto driver capabilities, and how the
root-containment check compares paths.

## Decision

**D1 — the cadence seam is the sink, not the turn loop.**
`KernelSink` (`crates/hh-embed/src/runtime.rs`) carries an optional
`EnvDriver` + bound env handle. On every append it scans the batch for
the two durable triggers — `lifecycle.turn.finished` (`on_turn_end`) and
each settled terminal effect row `action.effect.observed`/`refused`/
`unknown`/`abandoned` (`every_n_effects:N`, counting the durable rows,
not the loop's internal bookkeeping) — and calls
`EnvDriver::cadence_take` *after* the triggering rows land. The
`on_idle` trigger fires in `service.rs` at the `drive()` park leg
(`DriverError::Port` — the inbox emptied mid-turn). The sink placement
is what makes the ordering guarantee hold by construction: the trigger
rows are durable before the take runs, and `lifecycle.run.finished`
lands in a later append, so the cadence snapshot row always precedes the
run-sealing row — `fork{env: snapshot}` on a completed run can compose
without a manual `env snapshot`.

The alternative — cadence inside `hh-control`'s turn loop — would take
the snapshot *before* the turn-finished row is durable (racing the seal)
or require a second pass after it (a producer that fires after the run
is finished). The sink sees the appended batch, so the trigger is
defined over durable fact, not loop intent.

**D2 — cadence declarations parse once, at provision, fail-closed.**
`connection_info{snapshot_cadence}` parses via the one
`SnapshotCadence::parse` (CC1): `never` (default), `on_turn_end`,
`on_idle`, `every_n_effects:N` with `N ≥ 1`. Any other spelling is a
`SchemaViolation` at `provision_environment`. A *parseable* cadence on a
class whose capability declaration supports no snapshot kind refuses
`snapshot_cadence_unsatisfiable` at provision — a declaration that can
never fire is a lie told at open, so it fails there rather than
silently skipping at every boundary.

**D3 — kind selection is capability-led, skips are honest, failures are
audited.** `cadence_take` chooses `memory` when the handle is
`suspended` and the class declares the `memory` snapshot kind supported;
`fs_tree` when the handle is `ready` and `fs_tree` is declared. A
state-ineligible boundary (e.g. `on_turn_end` on a `suspended` handle
with no `memory` capability) takes nothing and mints nothing — a skip
is not a failure. An attempted take that fails mints
`action.environment.failed{op:"snapshot.cadence"}` with the driver
reason — durable evidence of the miss, never run-fatal. `TakenBy` gains
the `cadence` and `suspend` spellings so automatic and hibernation takes
are distinguishable from manual ones in the snapshot row.

**D4 — the seven ops ride the existing env.* vocabulary, each gated on
its named capability.** The op names/params stay inside the landed
`env.*` verb family (the ticket's own note); each dispatch in
`hh-embed/src/envops.rs` resolves the session's bound env handle and
routes through `EnvDriver`:

- `env.open` — provision + attach + bind the session's handle; mints
  `action.environment.selected`. Read-only sessions refuse.
- `env.attach`/`env.close` — attach rides the containment-attestation
  path (a provider handle attaches through its declared backend, not the
  local fs path); `close{mode:"detach"}` is the survivable form, default
  is `teardown`.
- `env.diff{baseline}` — resolves a *named* `fs_tree` snapshot row and
  re-walks the live roots (`hh_helper::fstree::diff`).
- `env.restore{snapshot_ref, mode?}` — `successor` (the spec default;
  `fs_tree` only) derives a successor workspace, verifies the walk
  byte-for-byte, mints `action.environment.restored{to_env_handle_id,
  snapshot_ref, verified}` + `replaced`, and rebinds the session;
  `mode:"in_place"` is the provider mechanism gated on the declared
  `restore_in_place` capability (`local_host` answers
  `UnknownCapability`).
- `env.upload`/`env.download` — §5a.2's content-addressed transfer pair:
  upload takes exactly one of `content` (utf-8) or `content_address`
  into a writable root; download reads a readable path into the blob
  pool and returns the `ContentAddress` (raw bytes never cross the
  boundary). Both mint the new audit rows
  `action.environment.uploaded`/`downloaded` (additive
  `CLASS_TABLE`/`HOSTED_LOWERING` members). Provider-class handles
  refuse the fs surface as `UnknownCapability{fs.upload|fs.download}` —
  the kernel fs does not reach remote environments.

Tri-state capability semantics are preserved end-to-end: `Supported`,
`Unsupported`, and `Unknown` stay distinct through `EnvError` → the
boundary's typed errors (`Unsupported{by}`, `UnknownCapability`,
`InvalidState`, `EnvironmentUnavailable`). No op fabricates a result;
`R-NOSIDE` holds — no `EnvHandleId` crosses a result payload.

**D5 — root checks canonicalize both sides.** `Roots::is_writable`/
`is_readable` compare canonicalized operands via the one
`canonicalize_path` (lexical `.`/`..`, then the deepest *existing*
ancestor's symlinks resolve — std's `canonicalize` fails on a
not-yet-created leaf). A declared root spelled through a symlinked
prefix (macOS `/var` → `/private/var`) still answers true for the real
path; an escape through a symlink still answers false.

## Consequences

- The last composed xfail is un-ignored:
  `cap2_fork_at_turn_boundary_without_explicit_snapshot` declares
  `on_turn_end` and forks at the boundary snapshot with no manual take.
- `suspend{on_idle:"hibernate"}` lands the memory snapshot in the same
  durable batch, stamped `taken_by:"suspend"` and threaded into
  `action.environment.suspended{hibernation_snapshot}`.
- Boundary error mappings tighten to honest kinds: ops that used to
  answer `EnvironmentUnavailable` for an undeclared capability now
  answer `UnknownCapability` (the conformance + CAP.2 expectations were
  updated — the capability is *known to be absent*, not the environment
  being unreachable).
- The `hh-cli` env verb family dispatches through the boundary with
  ledger effect byte-identical to the op call (K-1); the `stage_pending`
  catch-all now covers only genuinely unimplemented verbs.
- New refusal-cited capability spellings enter the driver vocabulary:
  `fs.upload`, `fs.download`, `restore.successor`, `attach.backend`
  (recorded here per the ticket note).

## Alternatives considered

- **Cadence in `hh-control` (the turn loop).** Rejected — the take would
  precede the durable trigger row or race `lifecycle.run.finished`; the
  sink placement makes the ordering structural (D1).
- **A separate verb family for lifecycle ops.** Rejected by the ticket's
  own note — `env.*` is the landed vocabulary; a second spelling is a
  defect (CC1).
- **Lexical root prefix checks.** Rejected — symlinked prefixes made the
  declared root and the real path disagree on macOS (and any
  symlinked-root deployment); canonicalizing both sides at the check is
  the honest comparison (D5).
- **Treating a cadence miss as run-fatal.** Rejected — a snapshot is
  best-effort policy; the durable `action.environment.failed` row is the
  audit trail, and aborting the run over a missed cadence would invert
  the honesty ordering (the miss is data, not a halt).

## Revisit trigger

Reopen if a driver class needs cadence kinds beyond `memory`/`fs_tree`
(e.g. a `process_table` or `volume` kind), if `on_idle` needs finer
granularity than the park boundary (e.g. idle-time thresholds), or if
`env.restore` grows a mode that is neither `successor` nor `in_place`
(e.g. a partial/subtree restore) — each changes the seam or the
capability map this ADR fixes.
