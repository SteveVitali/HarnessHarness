# ADR-0248: S1.15 audit-trail rulings — the Rule-C partition encoding, Rule-P halves, byte-exact `verify`, `audit_view` as a ledger fold, and the staged obligation set

- **Status:** Accepted
- **Date:** 2026-09-17
- **Ticket:** S1.15
- **Requirement ids:** R-2.8.6
- **Spec:** §5g.6 (the C0/Stage-1 slice per §5g.6 §9) · ADR-0066 D1–D8 ·
  ADR-0067 D1–D5 · ADR-0068 D2–D3 · ADR-0026/0029 · ADR-0033/0035 · ADR-0234/0235
- **Rung (ADR-0024 obligation):** **C0** — MUST-code: the audit-grade class
  list, the Rule C/P append checks, `verify` over the chain, the
  `AuditObligation` records and the `audit_view` fold are §5g.6 §9 Stage-1
  items; `AuditField`, `DecisionScope`, `TamperedKind::{NonCanonicalBytes,
  Producer}` and the manifest's `audit_policy_ref`/`signer_key_ids` stay
  MUST-data.

## Context
S1.15 lands the audit trail's Stage-1 slice: the audit-grade class catalogue
with its `audit_fields`/`content_refs` partition (Rule C), kernel-only
producers with `authority = kernel` provenance (Rule P), the completed
`decided`/`granted` payload dossiers, `AuditObligation` records, `verify`
over the per-run hash chain, and `audit_policy_ref`/`signer_key_ids` in the
manifest. The spec fixes the position — *the audit trail is the run ledger
read through `audit_view`: no second store, no sampling, no audit-only write
path* (ADR-0066 D1) — but leaves these concrete rulings to the slice:

1. **How the Rule-C partition is declared.** AC-R-2.8.6-12 makes "audit
   fields over the offload threshold" a schema error, and I-A1 limits audit
   fields to ids/hashes/closed enums/integers/`ContentAddress`es/provenance
   records — but the §6.1 dossier enumerates members only for the
   `security.permission.*`/`action.effect.*` families; classes whose payload
   dossier is another subsystem's contract (registry rows, `model.call.*`,
   the manifest on `run.created`) need a partition declaration that does not
   fabricate field lists the owning ticket has not landed.
2. **What the total bound is.** ADR-0234 installed an interim 4 KiB
   whole-payload cap as Rule-C enforcement; AC-R-2.8.6-12 names the bound as
   *the offload threshold* (`offload_threshold`, 64 KiB). The two disagree —
   the interim cap would refuse the completed `decided`/`granted` dossiers
   this ticket must emit.
3. **What `verify` must catch.** ADR-0067 D5 requires byte-exact
   verification; the existing replay path intentionally discarded unparseable
   and uncommitted lines — a torn-tail heuristic that would silently forgive
   mid-file edits.
4. **Where `audit_view` lives.** The other Stage-1 views are folded by
   `hh-telemetry`; folding the audit trail inside a telemetry crate would
   invert the dependency (the audit trail is the ledger's own read —
   ADR-0066 D1, not an observability product).
5. **How the obligation set stages.** I-A3 names obligations whose link
   machinery is Stage-2+ (`subagent_anchor`, `evolution_link`,
   `producer_resolution`, `fleet_anchor`); a Stage-1 evaluator must report
   them declared, never absent and never vacuously-failed.
6. **How far the payload completion goes.** The §6.1 dossier lists members
   the Stage-1 records cannot honestly produce (`requested_at`,
   `decider_ref`, `decider_provenance`, `originating_permission_id`,
   `wait_ms`, `rendering_ref`); emitting them absent data would fabricate.

## Decision
- **§1 — the partition is per-class data on `ClassSpec`.** `audit_fields:
  &[AuditField{name, max_bytes}]` + `content_refs: &[&str]` are class-table
  members; `append` refuses any payload member covered by neither list
  (`SchemaViolation`), refuses a member past its declared bound or a
  partition total past `spec.offload_threshold` (`AuditFieldsTooLarge`),
  refuses a non-pinned value in a `content_refs` member (`SchemaViolation`),
  and refuses `content_kind = free_text` on an audit-grade row (the Json
  model's expressible form of I-A1's "no `Text` leaf"). `"*"` is the **open
  partition** — every member an audit field at `AUDIT_FIELD_MAX_BYTES` —
  used exactly where the payload dossier is another subsystem's contract
  (registry, `model.call.*`, `run.created`'s manifest, the Stage-2 emitter
  classes). Enumerated partitions cover the classes whose dossiers are fixed
  here (effect phases, `decided`/`granted`/`revoked`, containment, credential
  and secret rows, budget audit rows, `control.decision`, the checkpoint
  record, memory rows, `export.delivered`, `ledger.redacted`/`gc`).
- **§2 — the AC-R-2.8.6-12 bound is `spec.offload_threshold`.** The AC's
  words are the contract ("would exceed the offload threshold"); per-member
  `AuditField` bounds (512 B default, 4 KiB for record/list-shaped members)
  do the small-field work. `AUDIT_PAYLOAD_MAX_BYTES` is deprecated — it was
  ADR-0234's interim whole-payload cap, superseded now that the partition is
  declared.
- **§3 — Rule P is two checks, enforced at `append` and re-checked in
  `verify`.** `producer.component_class ∈ class.producers`
  (`KERNEL_PRODUCERS` = `{"kernel"}` for every audit-grade row) *and*
  `provenance.authority = kernel`. Both failures are `AuditProducerInvalid`
  with a `detail` naming which half failed; `verify` re-checks both over the
  committed prefix (`TamperedKind::Producer`) so a forged stored row is tamper
  evidence, not just an append-time refusal. `kernel_origin` non-audit rows
  keep their §5a.1 §5 component check unchanged.
- **§4 — `verify` is byte-exact via `replay_committed_raw`.** The WAL
  replay retains each committed line's raw bytes; `verify` requires every
  stored line to equal its canonical re-rendering (`NonCanonicalBytes` — a
  rewritten-but-parseable line, whitespace or key reorder included), then the
  existing semantic checks run (recomputed hash → `ContentModified`,
  `prev_hash` link → `ChainBroken`, density/order/dupes → `SeqGap`/
  `Reordered`/`DuplicateSeq`/`DuplicateEventId`, `DanglingParent`, `Producer`).
  An unparseable line *followed by more content* is mid-file corruption
  (`NonCanonicalBytes`); an unparseable or uncommitted *tail* is the torn
  write the commit-marker protocol already tolerates — `verify` stays clean.
  Tail *truncation* of committed data is the signed-checkpoint half (Stage 2)
  and is honestly out of scope.
- **§5 — `audit_view` is folded inside `hh-ledger`.** `ViewKind::AuditView`
  dispatches to `crate::audit::audit_view`, a pure fold over the durable
  prefix stamped by `View::stamped` like every view — `events_seen`,
  `chain_ok` (the pure recompute; `verify` is the byte-exact disk check),
  `checkpoints` (empty until Stage 2), `scopes_unclosed`, `content_refs`
  presence accounting against the blob pool (`present`/`redacted`/`gc`/
  `missing`), `producer_violations` (the Rule-P recheck over stored rows),
  `coverage` (the obligation evaluation), `cross_run`, `redactions`,
  `sink_deliveries`, and the `completeness` vector whose Stage-2 halves
  render `{n/a: reason}` — never `false`-by-absence, never fabricated.
  `Store::manifest`/`open_scopes`/`blob_present` are the read accessors the
  fold needs.
- **§6 — the obligation set is declared-complete, stage-honest.**
  `OBLIGATIONS` carries the nine I-A3 rows evaluable at Stage 1
  (`tool_mediation`, `effect_terminal`, `grant_scope`, `credential_use`,
  `abandoned_escalated`, `unknown_escalated`, `budget_hard_escalated`,
  `endorsement_basis`, `persisted_widening`); `terminal_only` rows evaluate
  only once `lifecycle.run.finished` has committed (an in-flight subject is
  pending work, not a violation). `DEFERRED_OBLIGATIONS` names the four rows
  whose link machinery lands at Stage 2+ (`subagent_anchor`,
  `evolution_link`, `producer_resolution`, `fleet_anchor`) — reported under
  `obligations_deferred`, never silently absent.
- **§7 — the payload completion is honest, not padded.**
  `KernelDecision` gains `decision_scope` (the closed
  `{once, session, persisted}` sum — `once` for every Stage-1 `authorize`
  decision) and `to_json` emits the `checks[]` trail and `options_presented`
  (the dossier spelling — `options` renamed; nothing consumed the old
  member). `AuthorityHandle` gains `scope` (`session` for seal-minted roots —
  `HandleExpiry::Run` — and inherited by delegation); `granted_payload`
  emits it. `requested_at`, `decider_ref`, `decider_provenance`,
  `originating_permission_id`, `wait_ms`, `rendering_ref` are declared in
  `DECIDED_FIELDS`/`DECIDED_REFS` and honestly absent — the approval path
  that produces them is Stage 2.
- **§8 — the manifest declares audit policy and signers.**
  `audit_policy_ref` (a pinned `AuditPolicy` `version_id`, `UnresolvedRef`
  on a mutable tag) and `signer_key_ids[]` are optional members, emitted only
  when present — the golden transcript's bytes are unchanged (CC8).

## Consequences
- An audit-grade payload is closed-world: any member outside the declared
  partition is a schema error at `append`, and the same rows are rechecked by
  `verify` — a forged or rewritten committed line is `Tampered`, never
  silently reinterpreted.
- The completed dossiers flow: `decided` rows now carry `checks[]` (the
  reason is reconstructible from the record — ADR-0066 D5's premise) and the
  closed `decision_scope`; `granted` rows carry `scope`.
- `audit_view` answers "what happened, is the chain intact, and which
  obligations are unmet" from the durable prefix alone — and Stage 2 lands
  checkpoint emitters and the deferred obligations' link machinery into
  declared slots, never renames.
- Deferred: compact-range tree heads, signed checkpoints,
  inclusion/consistency proofs, cross-run anchors, the auditor subscriber,
  `lifecycle.escalation.*` emitters, redaction endorsement, the completeness
  veto and the AC-H6 battery (Stage 2+, `DF-S1.15-*`).

## Revisit trigger
The Stage-2 audit ticket (signed checkpoints, proofs, redaction/`gc` ops,
the deferred obligations' emitters) revisits the `n/a` completeness halves
and `DEFERRED_OBLIGATIONS` — the view members and obligation ids are fixed
data now, so Stage 2 fills them, never re-shapes them. A dossier tightening
(the `"*"` partitions becoming enumerated as the owning subsystem tickets
land) revisits `AuditField` bounds per class — additive member declarations,
never a schema break.
