# ADR-0296: S4.5a Hosting ABI rulings — the JSON HostingPlane seam, ABI-vouched delegate minting, per-dimension probe drive, kernel-minted audit rows, `hosted:scaffold` + `C-PARAM-6`, adapter-derived enforcement

- **Status:** Accepted
- **Date:** 2026-09-26
- **Ticket:** S4.5a (`066_S4.5a__hosting-abi.md`)
- **Requirement ids:** R-2.10.6 (the Hosting ABI proper) · R-2.10.1² (hosted
  desugaring populated) · R-2.10.3² (hosted levels through the ABI verbs) ·
  R-2.11.1² (the `participant` noun)
- **Spec:** §6.6 (hosting handshake, verbs, boundary rule, probes, quarantine,
  placement, budget_enforcement, hosted metrics) · §6.1 (hosted desugaring) ·
  §6.3 (hosted levels) · §7.1 (participant noun); owning ADRs ADR-0164…0166 ·
  ADR-0149/0150 · ADR-0154…0156 · ADR-0013 (4) · ADR-0281 (S3.4d schemas)
- **Deferral discharged:** DF-S1.3-2 (ABI-vouched participant mint ≤ delegate)

## Context

S4.5a lands the Hosting ABI proper — the `hh-hosting/1` handshake, the
closed baseline/capability/excluded verb sets, session-ABI lifting through
Adapter A, the P-01…P-16 probe catalogue, P0 quarantine, the boundary rule,
placement, `budget_enforcement`, the hosted metrics, and the three
²-suffixed deltas. The ABI is thin and observational (N2): it reports what
it saw and refuses what it cannot vouch for; it never upgrades a
participant's claim into a harness fact. The rulings below are the owned
calls where the spec's machine text left the shape open.

## Decision

1. **The embed surface is a JSON `HostingPlane` seam, never a crate edge.**
   `hh-embed` handles `lab.hosting.{describe,probe,attach}` over canonical
   records-in/records-out JSON through a `HostingPlane` callback the host
   installs (`crates/hh-embed/src/hosting_ops.rs`); no normal dependency
   edge from `hh-embed` (or any base crate) to `hh-hosting` exists — the
   hosting tier stays removable (CC6) and the embed service stays
   contract-only (CC5). `crates/hh-cli` likewise depends only on the
   generated client for its normal contract; `hh-hosting` appears only as
   a dev-dependency in tests.

2. **ABI-vouched participant content mints at most `delegate`; vouching is
   conferred, never inferred.** `MintingContext.vouched_participants`
   carries the participant refs the attach path explicitly vouched for;
   `default_authority_in` mints `delegate` for participant-origin content
   in that set and `unverified` otherwise (`hh-provenance/origin.rs`).
   Participant origins remain delegate-class and can never endorse. This
   discharges DF-S1.3-2's activation condition exactly: an unvouched claim
   is never coerced upward (CC2).

3. **Audit-grade rows stay kernel-minted; participant reports ride the
   payload.** Participant-provenance cannot mint kernel-origin classes
   (`model.call.completed`, `measurement.cost.attributed`, the hosted
   lifecycle/audit rows). Hosted lift therefore mints those rows with
   kernel provenance and preserves the participant's report as explicit
   payload markers — `participant_reported`, `synthesized`, `mediation` —
   which the hosted metric folds read to compare measured vs. reported
   values (`hh-eval/hosted_metrics.rs`). A participant's cost claim is
   recorded as a claim; it is never minted as a measurement.

4. **Probes are driven per dimension; verdicts are derived, never
   trusted.** `lab.hosting.probe` drives the P-01…P-16 catalogue one
   dimension at a time through the plane (`probe`/`drive_probe` op
   spellings), builds `ConformanceRecord.hosted_entries` from probe
   outcomes, and derives the verdict via
   `ConformanceRecord::derive_verdict` — an authored `verdict` field is
   never adopted. P0 drift (`basic_turn`, `interrupt`,
   `tool_calling_supplied`, `policy_deny`, `coordinate_model`,
   `end_state`) quarantines the participant version through
   `RegistryStore::quarantine` + `lifecycle.registry.quarantined`;
   non-P0 drift annotates the record without quarantine.

5. **`budget_enforcement` and `limits_enforced` are adapter-derived,
   never participant-declared.** The hosted launch outcome's
   `limits_enforced`, `budget_enforcement`, `mediation` and
   `capability_vector` stamps come from the Hosting ABI's adapter report
   (`hh-hosting/budget.rs` derives the enforcement class); a hosted arm
   claiming `limits_enforced = full` is refused as unverifiable. A hosted
   experiment arm routes through the `HostedLauncher` seam before the
   subject run opens; an absent or refusing launcher fails closed
   (`HostedLaunchUnavailable`) and returns the claimed slice to the pool —
   a hosted run is never silently downgraded to native.

6. **R-2.10.1²: `hosted.parameters`/`hosted.values` ride a synthesized
   `hosted:scaffold` layer.** `hosted_scaffold` decodes the hosted block's
   `parameters` as `ParameterSpec` records and returns them with `values`
   as a `PackagedDefault`-kinded layer at precedence below every authored
   layer, so authored `values`/`parameters` overrides win on precedence
   (`hh-lab/src/assembly/desugar.rs`). On a hosted root, stage 3 enforces
   `affects ⊆ {configuration, product}` and `sweepable` admissible only
   over a capability coordinate the declaration records `supported`
   (ADR-0013 (4); `unknown` is never coerced) — emitted as the new
   `C-PARAM-6 InadmissibleHostedParameter` diagnostic
   (`hh-assembly/diagnostics.rs`, `validate.rs`). The code growth is the
   dialect-bump fixture this ticket owns: `C-PARAM-6` is spec-pinned by
   R-2.10.1²'s admissibility rule, carries the spec-required name, and
   lands with its acceptance test
   (`hh-lab/tests/assembly_service.rs::hosted_parameter_space_populates_and_gates`).

7. **`usage_report_agreement` is symmetric.** A participant-reported
   dimension with no measured counterpart and a measured dimension the
   participant omits both count as disagreement; agreement is the mean of
   per-dimension min/max ratios. Missing data is never scored as
   agreement (N2).

## Consequences

- The Hosting ABI can be vouched only where a plane is installed; describe
  on an unknown participant ref refuses, attach is idempotent on the
  attach pair, and every hosted stamp is attributable to a Lab-minted row.
- `C-PARAM-6` is an error-severity code on hosted roots only; native
  parameter spaces are unchanged (CC8 additive on the code table per the
  dialect-bump-with-fixture rule).
- Secrets never enter ledgers: credential channels validate against the
  participant declaration's `credential_supply`; the ledger records
  `provided: yes/no` only.

## Revisit trigger

A live (non-hermetic) hosted harness enters the tree: the `HostingPlane`
JSON seam and `HostedLauncher` SPI must be re-audited so a remote adapter
cannot mint stamps the offline fixtures cannot distinguish — in
particular, `budget_enforcement`/`limits_enforced` derivation and the
`participant_reported` vs. measured cost split must verify against real
usage attestations, and `usage_report_agreement`'s symmetric scoring is
re-tuned if the live ABI exposes unmeasured dimensions the offline model
treats as disagreement.
