# ADR-0250: S1.16 sandboxed-execution rulings — the seven-stage dispatcher, attribution tokens on every signal, scope-safe tool terminals, capture-path redaction, and the Stage-1 input derivations

- **Status:** Accepted
- **Date:** 2026-09-17
- **Ticket:** S1.16
- **Requirement ids:** R-2.5.5
- **Spec:** §5d.5 (the C0/Stage-1 slice per the §5d.5 tier row and §9.1) ·
  ADR-0100…0102 · ADR-0030 §6 (fencing) · ADR-0052 D6 (mediation) ·
  ADR-0087 (scope bindings) · ADR-0101 D4–D5 · ADR-0238
- **Rung (ADR-0024 obligation):** **C0** — MUST-code: the seven stages,
  `ExecutorDeclaration`/`bind`, `CaptureItem` + the sealed manifest, token
  mint/resolve/hash, the `ErrorClass` sum with the three-origin rule and
  kernel-derived retryability, deadline/interrupt/streaming/dedup, and
  redaction placement are Stage-1 items; the out-of-process helper binary
  and the EP2 backend stay S2.1.

## Context
S1.16 lands the sandboxed tool-execution slice: `Dispatcher` runs
`resolve → authorize → prepare → commit → execute → capture → observe`
over a `ToolExecutor`, and every durable row is kernel-minted. The spec
fixes the invariants — no unmediated effect, no unverifiable attribution,
redaction before capture persistence — but leaves these concrete rulings
to the slice:

1. **Who mints `security.permission.decided`.** The monitor computes the
   `KernelDecision`; the durable row is the write-ahead gate `committed`
   checks (`Undecided` without it) — it must be a kernel-origin append in
   the same run stream.
2. **Where the `reversible` baseline comes from.** `prepared` on a
   `reversible` effect requires `baseline_ref`; the executor's own fs diff
   needs the same pre-state — two baselines would fork the evidence.
3. **How signals attribute.** The helper emits `ExecutorSignal`s; a forged
   or stale token must never let a payload ride an effect it wasn't minted
   for (AC-R-2.5.5-2/8).
4. **What the `action.tool.*` terminals may carry.** `observed`/`refused`
   close the `effect_id` scope inside the same batch as the tool terminal —
   a `tool_call`-scope terminal carrying `effect_id` is a
   `ScopeNotOpen` violation.
5. **How the assessor inputs are derived.** Π rows consume
   `command_parse`, `compensator_covered`, `child_contained` — the Stage-1
   dispatcher must produce them without fabricating checks it cannot run.
6. **Where redaction sits.** A hostile executor echoes a known secret; the
   mask must apply before the manifest or the raw blob, and the hit must be
   a `security.secret.leak_detected` row (AC-R-2.5.5-8).

## Decision
- **§1 — the dispatcher mints `decided` from the monitor's verdict.** It
  is a kernel append (`decided_payload` carries `attempt_no`, `proposal`,
  `taint`); a non-`allow` decision mints `action.effect.refused` *and*
  `action.tool.rejected` (the `tool_call` terminal) — `ask` is
  `refused{ask_required}` at Stage 1, the control envelope owns the loop.
  `committed` is minted only after `allow`; the ledger's `Undecided` gate
  is the durable backstop (complete mediation — AC-R-2.2.5-1, R-2.5.5-2).
- **§2 — the path baseline is taken at `prepare`.** One
  `driver.path_baseline` snapshot supplies both the `prepared.baseline_ref`
  a `reversible` class requires and the pre-state the post-exec
  `fs_change` diff reads — one evidence object, no fork.
- **§3 — every signal resolves the minted token.** `TokenMinter` mints at
  prepare (`attribution_token_hash` on `prepared`); the sink resolves each
  `ExecutorSignal.token` through `TokenResolver` — a miss appends
  `action.effect.unattributed{signal_kind, evidence_ref, detection}` (a
  scope-free marker; non-attribution is the fact recorded) and the payload
  never enters the manifest. `mint`/`expire`/`resolve`/`hash_of` are the
  whole surface.
- **§4 — tool terminals carry the `tool_call` chain only.**
  `action.tool.{completed,rejected}` close `ToolCall`; they are minted with
  `{turn_id, model_call_id, tool_call_id}` and never `effect_id` — `observed`
  /`refused` closed the effect scope earlier in the batch. The dedup-path
  `rejected` drops `tool_call_id` too (the coordinate's scopes are already
  closed by the first dispatch's terminals) and anchors at
  `{turn_id, model_call_id}`.
- **§5 — the assessor inputs are honest derivations, not blanket
  `Unknown`.** `command_parse` is `Some` only for `Exec`/`SpawnProcess`
  (the closed-grammar classifier is domain-scoped — a `{path, content}`
  arg shape is not a `Failed` parse that would poison every non-command
  effect); `compensator_covered`/`compensation_registered` are `Yes` when a
  `compensation_plan_id` is supplied (the plan's compensator was sealed
  against the proposer's scope at plan commit — the Stage-1 rule);
  `child_contained` is `Yes` for an empty `requested_grants` (vacuous
  containment) and `Unknown` otherwise (Π-9 denies on `Unknown`).
- **§6 — redaction is on the capture path, before persistence or
  visibility.** Every `CaptureItem` payload (and `Terminal.detail_ref`) is
  masked via `DetectorSet`; a non-placeholder hit on an
  *executor-reported* payload emits `security.secret.leak_detected` at the
  mediation point. `fs_change` items are `kernel_derived` provenance —
  produced by the driver's baseline diff, never executor-reported.
- **§7 — `read_only` has no write-ahead.** `prepared` may be followed
  directly by `observed` for a `read_only` class; every other class commits
  under the fencing token before `action.tool.started`.
- **§8 — classification surjectivity + kernel retryability.** Every
  `TerminalReport` maps to exactly one `ErrorClass`×`ErrorOrigin`:
  declared `error_classes` ⇒ `tool` origin; an undeclared class ⇒
  `protocol_error`/`transport`. `retryable` is kernel-derived
  (idempotent/read-only/reversible classes × the retryable class set); the
  executor's `retryable_hint` can only lower it (I-3 — the executor
  reports, never decides). `Timeout` on `read_only` ⇒ `observed
  {not_applied}`; on `compensable` ⇒ `unknown` ⇒ `probe`, never
  redispatched.
- **§9 — the manifest excludes ephemeral items; chunking is
  identity-invariant.** `EffectCaptureManifest::seal` refuses a straggler
  ephemeral item; the content projection strips transport coordinates so
  `capture_manifest_ref` is stable across chunking (AC-R-2.5.5-5).
- **§10 — Stage-1 executors.** `LocalExecutor` runs the child in-process
  (honest `IsolationClass::None`); `LocalHelperExecutor` crosses the
  spawn boundary the S2.1 helper will own (helper-protocol schema in
  `protocol.rs`). `bind` refuses `InsufficientDedup`/`InsufficientIsolation`
  and `InterruptSupport::Unknown` reports `unknown`, never coerced.

## Consequences
- The complete-mediation ACs are executable: a forged `committed` fails
  `Undecided` at the ledger (the test walks `intended → authorized →
  prepared` without a `decided` row), a forged token resolves
  `Unknown` and would mint `unattributed`.
- `unknown` leaves the `effect_id` scope open for `probed` (conditional
  closer — ADR-0238); `probed{undeterminable}` stays open for the retry
  path.
- A repeated idempotency key returns `Duplicate{prior_effect_id}` without
  re-entering the executor — the dedup gate fires before `proposed`.

## Alternatives considered
- **`decided` minted inside `Monitor::authorize`** — rejected: the monitor
  is a pure decider; the ledger row is the dispatcher's write-ahead, so
  minting stays where the run stream is held.
- **Per-item streams in the manifest** — rejected: ephemeral chunks are
  transport, not capture; their exclusion is what makes the manifest ref
  chunking-invariant.
- **Executor-reported `fs_change`** — rejected: the kernel's own
  baseline diff is the honest observer; executor reports would launder
  self-attestation.

## Revisit trigger
S2.1 lands the live helper binary + EP2 backend; re-open if the
attribution/token or signal schema needs to move across the real process
boundary, or if `compensator_covered`/`child_contained` need the real
delegate-machinery covering checks.
