# ADR-0245: S1.14 telemetry-crate rulings — crate shape, projection-only views, the model-attempt coordinate, the subprocess propagation seam, and explicit loss

- **Status:** Accepted
- **Date:** 2026-09-17
- **Ticket:** S1.14
- **Requirement ids:** R-2.9.1
- **Spec:** §5h.1 (the C0/Stage-1 slice per §5h.1 §9) · ADR-0042 D1–D6 ·
  ADR-0026/0027/0029 · ADR-0033/0034/0035 · ADR-0036 · ADR-0021
- **Rung (ADR-0024 obligation):** **C0** — MUST-code: the three pure views,
  the measurement-emission payload builders, the propagation derivation and
  the export lowering are §5h.1 §2 inside-list items; `Span`,
  `PropagationContext`, `TelemetryLossReport`, `measurement.export.delivered`
  and `measurement.metric.emitted` stay MUST-data.

## Context
S1.14 lands the observability backbone's Stage-1 slice: the closed
scope-kind/measurement-point taxonomy, `TokenVector` normalization, the
clock conventions, `SinkPolicy` + L0–L3, the subprocess propagation seam, the
process-metric catalogue, the export lowering, and the three pure views
(`trace_view`, `cost_view`, `metric_view`). The spec fixes the binding
position — *a span/trace model is a deterministic projection over the run
ledger, never a second store* (ADR-0042 D1/D2) — but leaves these concrete
rulings to the slice:

1. **Where the code lives.** The measurement points span model/tool/effect/
   permission/validation scopes produced by half a dozen subsystems, but the
   *instrumentation* is a single contract. A per-producer split would smear
   the closed M-table across crates; folding it into `hh-ledger` would put
   sink policy and token normalization inside the event store.
2. **How `model_attempt` is scoped.** The ledger's `Scope` record has no
   `model_attempt_id` field — attempts are coordinated by `model_call_id` +
   `attempt_no` on `model.call.attempt.*` events. `trace_view` must still
   render one `Span` per attempt nested under the logical call.
3. **What the propagation seam is at Stage 1.** §2.3 names MCP `_meta`, ACP
   `_meta`, the subprocess environment and request headers; §9 assigns only
   the subprocess seam to Stage 1 (MCP/ACP lowering slots are Stage 2). The
   provisional id derivation (`H(root_run_id)[0:16]` / `H(event_id)[0:8]`,
   OQ-115's ratified default) must be fixed *now* so Stage-2 emitters reuse
   it rather than re-deriving.
4. **How loss is represented.** Lowering (`export`) and propagation can drop
   fields, truncate bytes, convert units and fail on unmappable scopes; the
   contract says the report is a first-class record, never silence.
5. **Which ledger classes this item owns.** `measurement.export.delivered`
   and `measurement.metric.emitted` are new classes; their durability,
   audit-grade and provenance flags must be placed in ADR-0035's mandatory
   table correctly or the append path rejects them.

## Decision
- **§1 — one persistent crate `crates/hh-telemetry`** (deps `hh-wire`,
  `hh-identity`, `hh-provenance`, `hh-ontology`, `hh-ledger`, `hh-budget`
  only — no `Text` leaf authored, no model call on any path). It owns the
  measurement-point table, the codecs, the views, the sink policy, the
  catalogue and the export lowering; it owns **no store**. The crate never
  opens a `Store` itself — views take `&[EventEnvelope]`/`&Store` read
  paths and return `View` structs stamped by `hh_ledger::views::View::stamped`
  (deterministic `view_hash`, `VIEW_POLICY_VERSION`, `derived_from`
  watermark) — the same stamping S1.5's views use, so a telemetry view is
  indistinguishable in kind from any other projection (ADR-0042 D1/D2).
- **§2 — `model_attempt` is a *derived* scope coordinate.** `trace_view`
  opens an attempt span on `model.call.attempt.started` under the synthetic
  scope id `<model_call_id>/a<attempt_no>` and closes it on the attempt's
  terminal class. The ledger's scope validator never sees the synthetic id
  (no envelope carries it); the id exists only in the view. This keeps the
  spec's "one `Span` per scope-opening event" rule honest without inventing
  a ledger field the event schema does not have.
- **§3 — propagation is the subprocess env seam only**, rendered as
  `HH_TRACEPARENT`/`HH_TRACESTATE`/`HH_BAGGAGE`. Ids derive through `idp/1`
  canonical hashing with domain separation (`telemetry.trace_id`,
  `telemetry.span_id` — `hh_identity` domains), i.e. OQ-115's provisional
  derivation is implemented verbatim: `trace_id = H(root_run_id)[0:16]`,
  `span_id = H(event_id)[0:8]`, `sampled = 1`, tracestate member
  `hh=run:<run_id>;ev:<event_id>`. `inbound_context` resolves an `hh`
  member to an `EventRef` `Link`; malformed context is `InvalidInboundContext`
  — ignored and logged `structural`, never parented (the spec's explicit
  failure rule). `PropagationUnsupported(target)` renders as a loss-report
  entry, not a silent skip. MCP `_meta`, ACP `_meta` and request-header
  carriers are the Stage-2 lowering-slot row (DF-S1.14-1).
- **§4 — loss is data, always.** `TelemetryLossReport` is a typed record
  (`dropped_fields`, `truncated_fields{field, max_bytes}`,
  `unit_conversions{field, from, to}`, `unmappable_scopes`) carried on every
  `Delivery` and referenced by `measurement.export.delivered`'s
  `loss_report_ref`. `max_field_bytes` truncation *records* the truncation;
  a scope that cannot map to the sink's convention lands in
  `unmappable_scopes`. Nothing is coerced to zero or dropped silently —
  CC3's "nothing silently lost" applied to lowering.
- **§5 — class placement.** `measurement.export.delivered{sink_id,
  view_kind, seq_range, content_classes, loss_report_ref}` is appended
  audit-grade + provenance-mandatory (it is the *record* of what left the
  system — ADR-0035's table puts it beside `measurement.cost.attributed`),
  `Led`-durable (the only exporter append). `measurement.metric.emitted`
  carries mandatory provenance but is not audit-grade — §2.2 restricts it
  to non-derivable observations produced by oracles/judges over the scorer
  boundary, a Stage-3 producer, so the row is `Led`-durable and
  provenance-mandatory without the kernel-origin audit flag. `hh-identity`
  gains `RecordKind::SinkPolicy` (`sink_policy`, version-only — the
  `sink_id` is the comparison coordinate) so policies are pinnable records
  like every other governed declaration.

## Consequences
- The ledger remains the only store; deleting the crate loses nothing
  durable — every rendered span recomputes from the durable prefix.
- Attempt spans are stable across rebuilds because `<model_call_id>/a<n>`
  is a pure function of envelope fields.
- Stage-2 MCP/ACP propagation adds carriers, not a new id scheme; the
  domain-separated derivation is fixed here.
- Every export is self-describing about what it lost; the run bundle can
  carry `TelemetryLossReport` verbatim (R-2.9.3).
- Deferred: M5/M6/M13/M14/M15 emitter classes (`context.*`,
  `action.environment.*`, `control.wakeup.*`) land with their owning
  subsystems — the measurement-point table declares them with their
  §9 stage stamps now so Stage-2 lands emitters, never renames (CC8);
  see DF-S1.14-1.

## Revisit trigger
The Stage-2 tickets landing `context.*`/`action.environment.*`/`control.wakeup.*`
emitter classes wire M5/M6/M13–M15's emitters into the declared table — revisit
the `pending` stamps then; the §03 lowering-slot ticket landing MCP/ACP carriers
reuses the §3 derivation rather than re-deciding it (OQ-115 stays open to Stage
3's interchange ruling — a confirmed `surface_ids` decision revisits the
derivation, not the seam).
