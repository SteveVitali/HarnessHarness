## Context

`swe-bench-astropy-2`'s ten egress-cohort slots are
`inconclusive{verifier_unavailable:no_parseable_verdict}`: the S4-EGRESS
run record states the task's declared `max_test_timeout_sec: 60` cannot
host its own `run-tests.sh` bootstrap (`apt-get install gcc` +
`python -m venv` + `pip install -e .`), and the derived image's pip
bake carries no pytest — an honest bound, not a machinery failure.
R5.58 re-executes those slots; the enforced verifier bound must first
be relaxed by a *declared machinery admission* — recorded verbatim
(before → after, basis, scope, envelope check), never a silent bound
change.

Two decls circulate for this task and the contract requires naming the
*actually enforced* one without presuming: the run ledger's prose
states `60` s while upstream `task.yaml` declares `360.0`. The durable
record settles it without presumption: `action.effect.prepared`
payloads in both the frozen-run store (`~/tb-work/s4-confirm/…r0-c0`)
and the egress-supplement store (`~/tb-work/s4-egress/…r0-c0`) carry
`deadline: 360000` ms on `tc-verdict` **and** `tc-vendored` — the spec
carried the task.yaml decl (`360`), the driver's `min(declared,
900 s)` enforced it, and the `60.0` spec-gen default never fired. The
run ledger's stated `60` is recorded verbatim in the admission packet
as the contrast it is; it is not the enforced value.

Honesty bound (recorded in the packet): the recorded slots' verifier
leg ended at walls of 6.4–17.7 s — long before *either* bound could
fire. `verdict_verbatim.rc: 127` is `pytest: command not found`: the
bootstrap ran under the driver's `cd /app` while the project lives at
`/app/astropy`, so patch/`sed`/`pip install -e .` no-op'd and pytest
never installed; the vendored channel's `No module named pytest` is
the derived image's missing pytest bake. The admission removes the
declared bound as a blocker for the full bootstrap on re-run; it does
**not** assert the bound was the recorded proximate cause, and it
manufactures no verdict — a bootstrap that still fails records
`unresolved`/`inconclusive{reason}` verbatim.

## Decision

1. **`hh-env::verifier_bound` is the one home of the bound
   machinery.** `verifier_deadline_ms(declared_sec)` is the sanctioned
   form of the recorded driver derivation — `min(declared, 900 s)` in
   milliseconds for both verifier dispatches — and
   `enforced_decl_sec(record)` reads the spec's enforced decl
   (`ext["max_test_timeout_sec"]` as `Int` or the task-cfg float
   spelling; the recorded spec-gen default `60` when the member is
   absent; a malformed member refuses — an unreadable decl never
   silently becomes the default).
2. **`admit_verifier_bound` is the declared, transactional
   relaxation.** It refuses typed
   (`Unsupported{verifier_bound.admission}`) unless every leg holds:
   the spec's `ext["task_id"]` equals the admission's named task
   verbatim (absent or different ⇒ refuse — no other task's bound
   moves); `enforced_before_sec` equals the spec's *currently
   enforced* decl (a mislabeled before — e.g. the ledger's stated `60`
   on a spec that enforced `360` — refuses by construction);
   `0 < enforced < admitted ≤ 900` (the frozen §9.2 envelope — a
   larger need is a separately recorded admission); and the verbatim
   members (`basis`, `prior_disposition`, `supplement_epoch`,
   `authorization`, `scope`) are non-empty. Only then does it stamp
   `ext["max_test_timeout_sec"] = admitted` — the spec field itself
   carries the relaxed decl, so the deadline derivation needs no
   second code path — plus `ext["verifier_bound_admission"]` with
   before → after, both deadlines, basis, scope, prior disposition,
   epoch, envelope check and authorization verbatim.
3. **`slot_echo` carries the row vocabulary.** The re-run's ten slot
   rows echo `verifier_bound_admitted`, `prior_disposition`,
   `supplement_epoch` verbatim (`supplement_epoch:
   verifier-bound-rerun`); a spec without a declared admission echoes
   nothing.
4. **Scope is the recorded bound.** This admission names
   `swe-bench-astropy-2`'s verifier leg only. The ten cell-spec files
   at the supplement work root (`~/tb-work/s4-egress/specs/`,
   external scratch) carry the decl change verbatim — `360 → 900`,
   one member per file, byte lengths preserved; the other 90 specs
   keep their declared decls byte-identically (80×`60`, 10×`600`).
   `max_agent_timeout_sec`, staging/work bounds, the deadline ladder,
   the frozen protocol (`protocol_id
   9edc5327f89e2d66f8003bedc2530bc3e7d37326aad82cdfcab70465eda60a5f`,
   seed v3) and the 30-task manifest are untouched — a machinery-bound
   admission records on the rows, never a manifest re-pick (§4.1).

## Consequences

- `cargo test -p hharness-env --test r5_57` → **13/13**: the named
  task relaxes and stamps the verbatim record; the derivation is the
  driver's verbatim; the `60` spec-gen default and the float-spelling
  member read honestly; refusals pin the different/absent-task legs,
  the mislabeled-before leg, the envelope cap (`901` refuses, `900`
  admits), the non-relaxing leg, the empty-verbatim-members leg and
  the malformed-decl leg — each leaving the spec byte-identical; the
  fails-without leg pins no relaxation path absent the admission; the
  row echo carries the verbatim members.
- The admission machinery itself enforces the contract's honesty
  clause: `before: 60` cannot be stamped on this task's spec because
  `360` is what it enforced — "never presume" is a typed refusal, not
  a convention.
- R5.58 can re-execute the ten slots under `supplement_epoch:
  verifier-bound-rerun` with the admitted bound derivable from the
  spec surface — no scratch bound edit. If the bootstrap still cannot
  produce a verdict the honest `inconclusive{reason}`/`unresolved`
  records stand; nothing in this admission manufactures one.
- The recorded failure shape stands verbatim in the packet — the
  vendored channel's missing pytest either resolves genuinely on
  re-run (the bootstrap installs it) or stays recorded.

## Alternatives considered

- **Edit the spec files silently:** rejected — a machinery-bound
  admission is a declared record with scope, basis and envelope check;
  a silent edit is precisely what the ticket forbids.
- **Derive the deadline from the admission member rather than
  restamping `max_test_timeout_sec`:** rejected — two decl sources
  would let a spec disagree with itself; the stamped field keeps the
  derivation single-pathed (`min(declared, 900 s)` verbatim), and a
  spec lacking the admission keeps the prior enforced decl.
- **Admit a bound beyond `900`:** rejected — outside the frozen §9.2
  verifier envelope; requires its own separately recorded admission,
  never a silent wider bound (the typed refusal is the mechanism).
- **Honor the run ledger's stated `60` as the before:** rejected — the
  durable record (`deadline: 360000` on both verifier dispatches, both
  runs) is the *actually enforced* decl; the machinery refuses a
  before the spec does not enforce, so presuming `60` fails closed.
- **A shared/global envelope-widening flag:** rejected — the admission
  is named-task scoped; anything broader is a different admission with
  its own record.

## Revisit trigger

- R5.58's re-run produces a verdict (or a different inconclusive
  shape) under the admitted bound: record it verbatim on the rows;
  this ADR's machinery claim stands independent of the outcome.
- A second task needs a relaxed verifier bound: the admission pattern
  generalizes only through a new recorded admission with its own
  named-task scope, basis and envelope check.
- The spec surface moves `max_test_timeout_sec` off `ext` or the §9.2
  envelope changes: re-derive `enforced_decl_sec`'s member read and
  the cap const.
- The run ledger's stated `60` gets a durable correction leg (e.g. a
  driver that enforced it): the packet's contrast section is the
  append-only venue — the enforced-before evidence here is not
  rewritten.
