# ADR-0237: S1.6 accounting mechanics — ledgered refusal outcomes, affine reservations, conservative E1, advise dedup channel, kernel-origin class registration

- **Status:** Accepted
- **Date:** 2026-09-16
- **Ticket:** S1.6
- **Requirement ids:** R-2.1.6
- **Spec:** §8.2 (R-2.1.6) §2–§5 · ADR-0039, ADR-0040 (D3, "as amended"), ADR-0041
  (P3), ADR-0234 (the interim ruling pattern this extends)

## Context
The budget ops are ledger-bound: every state transition is a `control.budget.*` row
the `BudgetTree` projection replays. Several mechanics needed concrete rulings where
§8.2 names the outcome but not the wire shape:

1. **Refusals.** `allocate`/`reserve` can refuse (containment, conservation); AC-4
   requires the refusal to be *ledgered*, and the event family is closed — there is
   no `control.budget.refused` class.
2. **Reservation accounting.** A reservation is a claim consumed by charges and
   freed by release; "claim left" must never silently drop or alias (CC3).
3. **E1's read_only carve-out.** §8.2 lets a `read_only` effect's exhaustion proceed
   without draining; the effect risk class is an R-2.2.2 payload field that does not
   exist at S1.6.
4. **E4 dedup/re-arm.** Soft-threshold reminders must fire once per compaction
   epoch; the ledger needs a channel for "the reminder was delivered" that exists
   today.
5. **Event-class registration.** The new `control.budget.*`/`control.decision`/
   `measurement.cost.attributed` rows need persistence-policy entries; the §5a.1 §6
   audit list does not name them.

## Decision
- **Refusals ride the same class.** A refused `allocate`/`reserve` appends
  `control.budget.allocated`/`control.budget.reserved` with `outcome = "refused"`
  and a typed `refusal{}` member; the fold records `outcome = "held"`/`"allocated"`
  only for successes. The refusal is in the log (AC-4) without widening the closed
  family.
- **Reservations are affine:** `claim_left = quantity − consumed − released`. A
  charge naming a reservation consumes up to the remaining claim and the same batch
  emits `control.budget.released{reservation_excess}` for the unused excess —
  consumption beyond the claim charges and flags `over_reservation = true`, never
  refuses (the reservation is a sizing hint, not a ceiling). `release` of a fully
  settled claim is `UnknownReservation` — a claim is consumed, released, or dies
  with the lease; it is never aliased and never silently dropped.
- **E1 is conservative at S1.6:** `exhaust` refuses `EffectsInFlight` while ANY
  unresolved `action.effect.*` is open — never interrupting a committed effect is
  the strictest safe reading; the `read_only` exemption lands when the risk class
  is a payload field (DF-S1.6-1 → S1.7).
- **E4 dedup is ledgered** as `context.observation.recorded{kind:"budget_reminder"}`:
  `advise` re-arms after `context.compaction.completed` raises the epoch and refuses
  a repeat inside one epoch. The §05c `context.artefact.*`/`verification.artefact.
  followed` compliance chain is Stage-3's; this is the same dedup semantics on the
  channel that exists.
- **Grace and approvals are ledgered decisions:** an E3 grace claim appends
  `control.decision{kind:"grace_call"}`; an approvals-budget exhaustion appends
  `security.permission.decided{decision: deny, reason: approvals_exhausted}` — the
  ask→deny conversion is a ledgered denial, never a silent ask (AC-13).
- **Registration:** the new classes register `kernel`-origin, `ledger` durability,
  not audit-grade (absent from §5a.1 §6's audit list — the ADR-0234 interim-ruling
  pattern). `action.effect.*` stays audit-grade/kernel-only.

## Consequences
- The projection is total: replaying the WAL rebuilds the identical tree
  (`rebuild_from_the_ledger_matches_the_incremental_projection`), including refused
  rows — no state lives off-ledger.
- Over-reservation is a flagged charge, not a refusal — post-hoc usage can exceed a
  claim honestly.
- E1 is stricter than the spec floor at S1.6; DF-S1.6-1 records the refinement
  obligation so the carve-out is not lost (the deferral names the unblocker).

## Alternatives considered
- **A separate `control.budget.refused` class.** Rejected: the §8.2 family is the
  closed payload set; `outcome`/`refusal` members carry the same fact without a
  second class.
- **Refuse over-reservation charges.** Rejected: §8.2 treats the claim as advisory
  (reserve-before-spend is an optimization, not a second ceiling) — the honest
  record is `over_reservation = true` on the charge.
- **Drop dedup rows / infer from `context.assembled`.** Rejected: an inference
  would be a second accounting scheme (CC1) and re-arming on compaction needs the
  epoch boundary the ledger already records.

## Revisit trigger
S1.7 lands `effect.risk_class` (closes DF-S1.6-1's conservative E1); the Stage-3
artefact/compliance events landing may subsume the `budget_reminder` observation
channel; a spec amendment adding a refused class to the family supersedes the
`outcome`-member ruling.
