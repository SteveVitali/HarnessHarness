# ADR-0283: S3.6 Replay, fault-battery, and counterfactual rulings

- **Status:** Accepted
- **Date:** 2026-09-23
- **Ticket:** S3.6 (`052_S3.6__replay-fault-and-counterfactual.md`)
- **Requirement ids:** R-2.2.4⁰ᵇ, R-2.2.3⁰ᶜ, R-2.2.1, R-2.2.2
- **Spec:** §5a.4 (`R-2.2.4⁰ᵇ` — both replay modes, `ReplayValidityReport`,
  recording rules, the `counterfactual` hook with the factual arm) · §5a.3
  (`R-2.2.3⁰ᶜ` — the kill-point battery KP-1…9/13/15 × four classes,
  recovery metrics) · §5a.1/§5a.2 (the fault battery, `effects_by_key`,
  the duplicate-effect veto) · ADR-0135 (replay/counterfactual) ·
  ADR-0130/0132 (recovery) · ADR-0028 (reconstruct mode)

## Context

S3.6 lands the replay driver and the fault battery. The ticket owned these
rulings:

1. **Where the deterministic driver lives.** Replaying a run re-drives the
   *control loop* over recorded inputs — that is `hh-control`'s strategy
   machine, not the ledger's. The verdict, however, is a pure fold over
   durable state.
2. **What the record must carry for `deterministic`.** A declaring
   variant's replay consumes recorded model rounds (`model.call.requested`
   ∥ `completed`/`failed` with `response_ref` + parsed `calls`), effect
   terminals, the external cue stream, and clock/random reads — anything
   unrecorded is an honest `re_executed`/`degraded`, never fabricated.
3. **How the `stop_rule = submit` marker re-derives at replay.** `act`
   intents name `tool_call_id` only (I2 — never arg bytes); the gate that
   detected `hh.submit` live must be reconstructible at replay without the
   arg surface.
4. **Which durable rows are *external* cues.** `context.artefact.delivered`
   rows include kernel-internal deliveries (harness-rule nudges,
   `procedure_index`) that a replayed driver re-derives itself — feeding
   them back as `human_input` would double-apply them.
5. **Downgrade-vs-refuse for `replay_mode` overreach (DF-S2.9-2).** S2.9's
   coverage→mode ladder always downgrades and records
   (`effective_replay` + `downgrade_reason`); whether a strict
   `CoverageInsufficient` refusal posture should exist was left to this
   ticket's replay semantics.
6. **Where deduplication's durable half lives.** The duplicate-effect veto
   must survive restart — an in-memory `DedupStore` alone loses the record.
7. **What the fault seams may inject.** The kill-point battery needs
   controlled deaths at declared boundaries only — never arbitrary
   corruption.

## Decision

1. **Two-crate split.** `hh-ledger::replay` owns `ReplayValidityReport`
   (the `deterministic | re_executed | degraded | invalid` ladder as a
   pure fold over the branch record, the source prefix's confinement
   evidence, and caller-supplied probe/fingerprint/divergence inputs),
   `replay_started`/`replay_finished` emitters, `reconstruct` (views + env
   binding rebuilt, nothing re-executed), `key_lookup` +
   `stored_observation`. `hh-control::replay` owns the deterministic
   re-drive: `extract_recorded`, `ReplayModel`/`ReplayGate`/`ReplaySink`
   ports, `deterministic_replay` with a seed prefix for branch replay, and
   the `control.decision`/`context.assembled` canonical comparison.
   `hh-embed::replay_ops` owns the `replay`/`counterfactual` ops.
2. **The recording rule is evidence, not assumption.** `deterministic`
   requires `variant_declares` *and* every consumed source
   `confined_to_events`: `model.call.completed` must carry `calls` +
   `response_ref` (runs recorded before this rule degrade to
   `re_executed`); `control.clock.read`/`control.random.read` are the
   declaring variant's nondeterminism record. The verdict is `invalid`
   (never reconciled) on a `ReplayDivergence{at_seq, expected, got}`.
3. **`sub-{effect_id}` re-derivation.** `extract_recorded` folds
   `action.tool.proposed{tool_call_id → surface_id}` into
   `RecordedInputs::proposed_surfaces`; `ReplayGate` resolves the intent's
   `tool_call_id` through it and re-mints `submission_ref =
   sub-{effect_id}` exactly when the recorded surface is the submit
   surface — the same rule the live gate applied, so the recorded
   `stop{submission_ref}` decision reproduces byte-equal.
4. **External cues = principal deliveries only.** `external_cues` carries
   `context.artefact.delivered{kind ∈ {instruction, capability}}` (the
   `submit.input` path), `security.permission.decided{decider: human}` →
   `Approval`, `lifecycle.run.resumed` → `Resumed`, `control.budget.amended`
   → `FollowUp`, and a principal-cancelled `stop` decision → `Interrupt`.
   Internal deliveries are reproduced by the driver's own machinery.
5. **Downgrade-with-record is the semantics (closes DF-S2.9-2).** The
   ladder's `effective_replay`/`downgrade_reason` record *is* the honest
   surface: the `ReplayValidityReport` never claims `deterministic` beyond
   what confinement evidence supports, and the deterministic driver
   refuses `variant_not_declaring` outright rather than fabricate. A
   strict `CoverageInsufficient` refusal knob is declined — the record +
   report already name the gap, and refusal would break the common fork
   path (observability < `ledger` is normal). `LedgerError::
   CoverageInsufficient` remains declared for a future policy knob.
6. **`effects_by_key` is the durable dedup tier.** The dispatcher's
   in-memory `DedupStore` is checked first; on miss the durable fold
   (`effects_by_key_view` ∥ `key_lookup`) answers `idempotency_key →
   (effect_id, phase, outcome)`; a duplicate under a committed key appends
   `action.tool.rejected{reason: dedup}` and returns
   `DispatchOutcome::Duplicate` with the prior `effect_id` and the stored
   observation where the class serves it — `duplicate_effect_count` stays
   0 (AC-R-2.2.3-3).
7. **Fault seams are declared, not free-form.** `KillPoint::STAGE3_SET` =
   KP-1…9/13/15; `Store::inject_durability_faults` arms KP-9 batch
   atomicity, `Store::arm_restore_kill` arms KP-13 mid-restore,
   `Dispatcher::inject_kill_point` arms the KP-1…8 dispatch boundaries,
   and KP-15 is executor death with the runtime alive. Each injection
   point is a typed seam — the battery never mutates the WAL.

## Consequences

- Both replay modes are executable: `reconstruct` rebuilds views + env
  binding without executing; `deterministic` re-drives the declaring
  variant with executor calls = 0 by construction (`ReplayGate` has no
  executor). AC-R-2.2.4-{2,4–8,11} halves are green; the counterfactual
  hook opens `n` factual + `n` counterfactual arms off one fork
  point/snapshot with `arm_role`, `charged_to = instrument`, per-arm
  seeds, and the `ComparisonReport` blob naming the factual dispersion.
- The kill-point battery runs KP-1…9/13/15 × {read_only, reversible,
  compensable, irreversible} against the recovery oracle; KP-9 is
  absent-as-a-unit; KP-13 restore is idempotent; KP-15 is helper death
  with the runtime alive. `search_budget`/`eval_budget` are recorded per
  cell (T-LCD-14).
- The five recovery metrics (AC-R-2.2.3-12) compute over the durable
  rows: `recovery_latency_ms` pairs takeover `lease.acquired{writer}` with
  `resumed_at_ms`; `wasted_calls` counts calls open at `from_seq`;
  `unknown_effects_per_resume` is the ppm rate; `heal_count` and
  `wakeups_skipped{reason}` count theirs — `n/a`, never 0, where
  unmeasured.
- The recovery `lifecycle.run.resumed` row gained `resumed_at_ms` (the
  `Cue.resumed` delivery stamp) — additive member, CC8-clean.

## Alternatives considered

- **Validity verdict inside `hh-control`:** rejected — the report is a
  ledger fold (`branch_record` + confinement evidence); putting it in the
  control crate would make the driver own the record's meaning (CC10).
- **Feeding all `context.artefact.delivered` rows as external cues:**
  rejected — nudge/procedure deliveries are reproduced by the replayed
  driver; re-feeding them double-applies and diverges honestly-but-falsely.
- **Strict `CoverageInsufficient` refusal at fork:** declined (decision 5)
  — the record + validity report carry the honest answer; refusal would
  pre-decide a policy question the evidence already answers.
- **Synthesizing `submission_ref` from the recorded stop decision:**
  rejected — it would couple the gate to decision order; the
  `tool_call_id → surface` map is the recorded fact the live gate saw.

## Revisit trigger

Reopen if (a) a `replay_mode` policy surface lands that wants the strict
refusal knob (`CoverageInsufficient` is already declared), (b) a variant
declares `deterministic_replay` while reading a nondeterminism source the
recording rules do not capture (a new `SourceKind`), or (c) the submit
surface's `submission_ref` spelling changes (the `sub-{effect_id}`
derivation is a gate-internal convention, not a wire contract).
