# ADR-0278: S3.4a experiment-engine rulings

- **Status:** Accepted
- **Date:** 2026-09-22
- **Ticket:** S3.4a (`047_S3.4a__experiment-engine.md`)
- **Requirement ids:** R-2.10.3⁰ᵇ · R-2.10.2 (catalog slice)
- **Spec:** §6.3 (the single-worker experiment engine — `register`/`expand`/
  `open`/`next`/`claim`/`launch`/`settle`/`pause`/`resume`/`close`, the
  `measurement.experiment.*` event family, settlement by outcome class,
  matched-budget enforcement at four points) · §6.2 (`slot_choices`,
  `param_schema`, `budget_relevant`, `registry_snapshot_id`) · ADR-0154 /
  ADR-0155 / ADR-0156 · ADR-0184 D2 · ADR-0213 (OQ-363 interim rule)

## Context

S3.4a lands the Stage-3 single-worker experiment engine (`hh-experiment`)
over the ledger/doc-store machinery landed in S3.1–S3.3. The owning ADRs fix
the contracts (the refusal set, the event family, the settlement table, the
four enforcement points); the mechanism choices below were left to the
ticket:

1. **How `oracle_failure` is recorded.** §6.3 §2.3 rules `oracle_failure` ⇒
   "row kept; regrade only — the agent is never re-run". The regrade itself
   is §06.5's overlay-run machinery (a separate requirement); what the
   *settlement row* carries in the interim needed pinning.
2. **Which cancellations may re-plan.** §2.3's cancellation table splits
   `cancelled{operator|hosting}` (re-plannable under `on_cancel = replan`)
   from `cancelled{principal|parent}` (always final). The settlement code
   must distinguish by `cancelled.by`, not by outcome class alone.
3. **The deterministic order key shape.** AC-R-2.10.3-4 requires the
   `interleaved`/`interleaved_blocked` orders to produce a *task-blocked,
   arm-interleaved* sequence reproducible from `permutation_seed` alone.
4. **Where E-3's under-utilisation annotation lives.** "Utilisation
   distributions" are computed per settle (`budget_utilization` on
   `RunOutcome`); the arm-level `under_utilised` annotation needs a median
   over the arm's counted runs, which is only stable at close. The declared
   floor needed a `MatchSpec` member name.
5. **How E-4's close-time re-check renders.** `budget_match.status` is a
   closed two-value sum (`matched | imbalanced`); unmeasured matched
   dimensions and insufficient-replicate cells needed renderings inside
   that set.
6. **Where the AC-R-2.10.2-12 coverage check resolves `budget_relevant`
   parameters.** The variant `param_schema` lives behind registry reads the
   lab layer cannot perform; the resolver shape at `SpecContext`/`EngineContext`
   needed pinning.
7. **How AC-R-2.10.2-6's "registry is never model-facing" is enforced
   statically.** A registry operation bound as a `ToolCapability` must refuse
   at `validate_assembly`; the diagnostic code and the detection rule needed
   pinning.
8. **The `lab.experiment.*` boundary shape.** Group L names the ops; whether
   the engine's resolvers ride params or service lookups follows ADR-0277's
   records-in/records-out precedent.

## Decision

1. **`run_settled` carries `regrade: true` for `oracle_failure`** — the row
   is final (`plan_final = true`), `accepted = false`, and the ledger gains
   no `run_replanned`/`run_excluded`. The regrade overlay run is §06.5's
   machinery and lands with the results store; the settled row is the
   durable marker that a regrade is owed (ADR-0155 D5; ADR-0141
   `derived-from{regrade}`).
2. **Cancellation replannability is keyed on `stop.cancelled.by`** — only
   `operator`/`hosting` consult `ReattemptPolicy.on_cancel`;
   `principal`/`parent` are final unconditionally (§2.3).
3. **Order keys are `(block, task_rank : replicate : arm_rank)`** — `block`
   is the replicate index under `interleaved_blocked` (else one block);
   `task_rank`/`arm_rank` derive under the `experiment.order.task` /
   `experiment.order.arm` domains from `permutation_seed` (idp-keyed, S-6
   reproducible). `serial` stays declaration order; `random_permuted` keeps
   `H(seed ∥ run_plan_id)`.
4. **`MatchSpec.utilization_floor` is an optional ppm member** (additive,
   serde-skip when absent); `ExperimentReport` gains `utilization`
   (`{arm → {dim → {median, min, max, n}}}` — the 512-byte audit-field cap
   keeps per-run samples on `run_settled`, the distribution summary on
   `closed`) and `under_utilised[]`. Under-utilisation is annotation only —
   it never re-prices an arm (ADR-0041 M1).
5. **`budget_match[]` re-checks comparand groups over realised runs** —
   pairwise consumption-medians vs the declared `tolerance_ppm`;
   `status ∈ {matched, imbalanced}` (an unmeasured matched dimension is
   `imbalanced`, never a third value). Insufficient-replicate cells render
   `na_cells[]{cell_id, reason: not_run}` (`InsufficientReplicates`), beside
   the plan doc's `level_ineligible` cells.
6. **`SpecContext`/`EngineContext` gain `budget_enforcement` and
   `budget_relevant_params` resolvers** — `None` = cannot resolve → the
   check defers (the engine's `Unresolvable`/skip contract, never a guess).
   A `budget_relevant` parameter that differs across a comparand group's
   arms must have every `affects` dimension covered by each arm's
   `MatchSpec`, else `UnmatchedBudget` (T-LCD-14). A `matched_cap` dimension
   not `enforced` on every arm is `IncommensurableMatch` (CF-350).
7. **`C-LCD-5 RegistryOperationBound`** — `validate_assembly` stage 7 refuses
   a `ToolCapability` whose `source.kind` names the registry, or an inline
   assembly entity binding a `lab.registry.*` verb (the closed REGISTRY_OPS
   list). The model-facing registry is the tool catalog (ADR-0151 R6;
   ADR-0094).
8. **`lab.experiment.*` is records-in/records-out** (ADR-0277 precedent) —
   the caller supplies resolver material (`budgets`, `suite_tasks`,
   `arm_configs`, `ineligible_levels`, `fingerprints`, `drifted_capabilities`,
   `sealed_artifacts`, `budget_enforcement`, `budget_relevant_params`,
   `min_replicates`, `retirement_diff`); the engine resolves nothing it was
   not given.

## Consequences

- Oracle faults never re-execute the subject; the regrade obligation is a
  ledger-visible marker the results-store ticket (S3.4b) consumes as an
  overlay run.
- Cross-mode arms are legal inside one spec (comparand groups) — the
  `lab/control-strategy-family-v1` exemplar's `iso_cost` companion rides
  this; a cross-mode `compare` stays `IncommensurableMatch`.
- The closed-payload additive members keep older folds reading: unknown
  members are carried, never required.
- OQ-363 stays conditionally deferred under ADR-0213 — the `iso_cost`
  companion duplicates runs rather than sharing them across MatchSpecs
  (duplicate-run control; DEFERRALS progress note).

## Alternatives considered

- **Regrade by re-running the subject.** Rejected — §2.3 is explicit that
  the agent is never re-run for a grader fault.
- **`budget_match.status` third value for unmeasured dims.** Rejected — the
  spec's closed set is `{matched, imbalanced}`; "cannot be shown matched" is
  `imbalanced`.
- **Per-settle `under_utilised`.** Rejected — a median over a partial run
  set is unstable; the distribution rows land per settle and the annotation
  is emitted at close where the medians are final.
- **Service-side registry resolution in `hh-embed`.** Rejected for the same
  reason ADR-0277 rejected it for `lab.eval.*` — the boundary stays
  records-in/records-out; the store-backed ops (`lab.analysis.*`,
  `lab.results.*`) remain S3.4b–c's.

## Revisit trigger

- S3.4b lands the regrade overlay: at that point `run_settled.regrade`
  markers must be consumable into `derived-from{regrade}` overlay runs —
  if the marker proves insufficient (e.g. needs the oracle's pin), amend by
  adding the member rather than reinterpreting `regrade`.
- OQ-363 resolves: if `iso_cost`/`matched_cap` run-sharing is ratified, the
  duplicate-run control retires and the comparand-group key shape may
  change.
