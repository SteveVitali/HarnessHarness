# ADR-0254: S1.19 context-builder rulings — the `hh-context` crate, the six-slot/floor table, the `link_layout` check set, the `assemble` pipeline order, and the three `context.*` class registrations

- **Status:** Accepted
- **Date:** 2026-09-17
- **Ticket:** S1.19
- **Requirement ids:** R-2.4.1, R-2.4.2 (C0 slice)
- **Spec:** §5c.1 · §5c.2 (the `default`-policy slice) · ADR-0072…0077 · ADR-0026 · ADR-0034 · ADR-0035 · ADR-0066
- **Rung (ADR-0024 obligation):** **C0** — MUST-code: the context
  vocabulary (closed `CandidateKind`/`Retention`/`PriorityClass`/
  `CacheTier`/`OmissionReason`/`Revalidation`/`ValidityPolicy` sums), the
  `Layout`/`SlotDeclaration`/`Reservation`/`ContextPlan` records, the six
  reserved slots with kernel floors, `link_layout`'s LC-1/LC-3 halves, the
  `ContextPolicy` contract + `default` policy, the `assemble` kernel
  (`admit → reserve → select → enforce_budget → check_invariants → plan`),
  `ContextWindowExceeded → stop`, and the `context.assembled` /
  `context.artefact.delivered`/`activated` / `context.retrieval.completed`
  payload builders + class registrations. Compaction machinery, non-`default`
  policies' runtime wiring, and the turn-loop emitter call sites stay at
  their spec'd stages.

## Context
S1.19 lands the context builder / policy engine's C0 slice. The spec fixes
the *shape* — six reserved slots, kernel floors, a policy that may narrow
but never widen, a `context.assembled` row per model call — but leaves the
crate boundary, the exact check assignment to `link_layout` vs `assemble`,
the eviction-order mechanics, and the ledger grades of the three new
classes to the build. Each open seam needed a ruling that the acceptance
criteria then pin.

## Decision
1. **The context builder is its own crate** (`crates/hh-context`), not an
   extension of `hh-ledger` or `hh-baseline`. §5c.1 names the builder a
   component with `home = context_plane` distinct from the ledger and the
   baseline harness; the dependency direction is `hh-context →
   {hh-identity, hh-provenance, hh-ledger, hh-hir, hh-budget, hh-wire}`
   (the builder consumes ledger classes, identity mints, labels and budget
   arithmetic — nothing depends back, CC10). `hh-baseline`'s older
   in-crate context stub stays untouched (additive, CC8); the crate is the
   canonical home the turn-loop ticket wires.
2. **The six reserved slots are `{kernel, definition, principal,
   transcript, external, unverified}`** with kernel-fixed floors
   `{kernel, definition, principal, delegate, external, unverified}` and
   tiers `{static, static, dynamic, transcript, dynamic, dynamic}`
   (`plan::RESERVED_SLOTS`; ADR-0074). `transcript`'s floor is `delegate`
   — transcript items are delegate-class by construction; the floor
   admits them and nothing lower. Every `Layout` carries all six; a
   profile may raise a floor, never lower it.
3. **`link_layout` checks exactly the *declarable* halves.** The check set
   is: all six reserved slots present; every `min_authority` ≥ its
   reserved floor and ≥ `unverified`; `admitted_states` may not contain
   `superseded`/`revoked`/`expired` (the never-admissible set); a
   non-`transcript`-tier slot may not admit `transcript_item` (LC-1's
   declaration half — the `transcript` tier is the only tier
   `transcript_item` may occupy); `kernel`/`definition`/`transcript` carry
   their kernel-fixed tiers; a `static` slot admits no volatile kind
   (LC-3's declaration half). The *run* halves live in `assemble`
   (per-candidate: a volatile candidate never enters a `static` slot — the
   LC-3 run check). The earlier draft's "tiers monotonic in precedence"
   reading was dropped: `external`/`unverified` legitimately sit after
   `transcript` in precedence while remaining `dynamic` — LC-1 constrains
   *which tier a kind may occupy*, not the tier sequence of the slot list.
4. **`assemble` is one deterministic pass**: `admit` (per candidate —
   kind ∈ `slot.admits`, `label.authority ≥ slot.min_authority`, lifecycle
   state ∈ `slot.admitted_states`, readers ⊆ slot readers, volatile ⇒
   non-static slot; collect `omitted[]` with a typed `OmissionReason`),
   `reserve` (floors charged first), `select` (the policy's choice over
   the admitted set — `default` picks highest-precedence admissible slot),
   `enforce_budget` (deterministic eviction in `PriorityClass` declaration
   order, lowest eviction rank first, ties by `(candidate_id)`;
   `Retention::Required` overflow ⇒ `ContextWindowExceeded`), then
   `check_invariants` + `plan` mint (`plan_id` = `idp("context_plan",
   canonical(plan-minus-id))` — I-DET: identical inputs mint identical
   ids; the estimator's identity is a plan input so estimator swaps move
   `plan_id`, AC-R-2.4.1-8).
5. **Policy violation is the refusal for any widening.** A `ContextPolicy`
   receives only the admitted candidates and must return `(candidate,
   slot)` pairs inside each candidate's admissible set; dropping a
   `required` candidate or choosing a slot outside the admissible set is
   `PolicyViolation` and **no plan is minted** (AC-R-2.4.1-4). Policies
   narrow only — the kernel owns floors, admission and budget; the policy
   owns selection among what survives.
6. **`ContextWindowExceeded` maps to `stop`.** At Stage 0/1 there is no
   compaction variant to invoke, so the builder's typed error is the
   `stop` decision surface (the compaction `CompactionRequired` path is
   R-2.4.2's Stage-2 machinery; the ticket's own AC requires the mapping
   be typed and total now).
7. **The three new classes are `row_prov` rows — durable, provenance-
   mandatory, not audit-grade.** §5c.1's audit note rules
   `context.assembled`/`context.artefact.*` "hashed leaves citable by
   `audit_ref`, not audit-grade classes" (ADR-0066 d2); §5c.3 rules
   `context.retrieval.completed` `durability = ledger`, provenance
   mandatory (ADR-0079 d8; ADR-0035 d4). They follow the
   `context.artefact.delivered` precedent — component-emitted
   (`kernel_origin: false`, `requires_provenance: true`), `O::Events`,
   no ledger scope open/close (the ledger `ScopeKind` chain is
   `run ⊃ turn ⊃ model_call ⊃ tool_call`; telemetry's
   `ContextAssembly` scope is a *measurement* scope, not a scope field).
   The audit-grade halves stay `context.memory.{written,invalidated,read}`
   under `MEMORY_FIELDS` (already landed).

## Consequences
- `hh-context` is the single home for context-plane records, plans,
  policies and the memory/retrieval slices (CC7) — downstream tickets
  (turn loop, compaction, procedures) consume its types rather than
  re-declaring them.
- `link_layout` refuses illegal *layouts* at declaration time;
  `assemble` refuses illegal *placements* at run time — the LC-1/LC-3
  split is explicit and each half is tested (AC-R-2.4.1-14 +
  `assemble_stale_view_and_pair_atom_checks`).
- Registering `context.artefact.activated` moved it out of hh-telemetry's
  `pending` set; the `pending_classes_are_declared_not_violations` test
  now exercises `verification.artefact.followed` (still Stage-3-pending)
  — the test's meaning is preserved.
- `plan_id` determinism gives the AC-R-2.2.1-4 replay check its
  `view_hash`/`plan_id` anchor for free.

## Alternatives considered
- **Fold into `hh-baseline`'s context module.** Rejected: the baseline is
  the throwaway reference harness; the builder is a permanent kernel
  component other crates must consume (CC10, the S1.18 crate-boundary
  precedent).
- **Tier-monotonic `link_layout` (tiers non-decreasing in precedence).**
  Rejected as over-strong: it forbids the spec's own default layout
  (`transcript` tier at precedence 3 followed by `dynamic` externals).
  LC-1's actual rule is per-kind tier legality.
- **Audit-grade `context.assembled`.** Rejected by spec text
  (ADR-0066 d2's "not audit-grade" ruling); per-item provenance stays
  mandatory through `row_prov`.
- **`ContextWindowExceeded → compact` inline.** Deferred: compaction is a
  Stage-2 variant (R-2.4.2); the honest C0 mapping is `stop`.

## Revisit trigger
The Stage-2 turn-loop ticket (S2.x) wires the real emitters; the
compaction ticket (R-2.4.2 Stage-2 rows) re-reads decision 6 when
`CompactionRequired` gets a producer. Reopen if the §5c acceptance battery
(Stage-3) requires `context.assembled` to be audit-grade or opens a
`context_assembly` ledger scope field.
