# ADR-0354: R3.1 flake adjudication — inclusive minted-token expiry, loopback fixture drain, and the `derived_from.view_hash` parity member

- **Status:** Accepted
- **Date:** 2026-10-14
- **Ticket:** R3.1
- **Requirement ids:** LEDGER OPEN FINDINGS (the #133 `ac5` entry) ·
  GATE-G4 flags G4-1 / G4-2 / G4-7 · AC-R-2.2.1-3 (rebuild-identical
  views) · CC1 (one parity-allowlist convention).
- **Spec:** §5g.3 (credential mediation — `minted_scoped`, LT-05's
  "minted tokens fail after expiry") · §5a.1 §4 (rebuildable
  projections — `derived_from` + `view_hash`).
- **Rung (ADR-0024 obligation):** C1 — every leg runs at the offline /
  fixture-verified ceiling; no staging or live claim is made or implied.

## Context

GATE-G4 flagged three recorded CI flake signatures for round-3
adjudication (G4-1, G4-2, G4-7). The ticket forbade retry-around
non-answers — each leg had to be root-caused:

1. **G4-1 — `credential_mediator_oauth_resolves_and_refuses`** (six
   recorded firings R2.22–R2.26). The test mints a zero-TTL caller
   token (`mint_caller_token(audience, 0)`) and asserts
   `resolve_credential` answers `CredentialExpired`.
   `CredentialBroker::mint` computes `expires_at_ms = now + ttl`; the
   old `verify_minted` compared `now_ms > expires_at_ms`, so a
   verify landing in the *same millisecond* as a zero-TTL mint saw
   `Valid` — a wall-clock boundary race, real defect.
2. **G4-2 — `ac5_attended_and_unattended_share_one_configuration`**:
   once on #133 push run `38020320703`, `.payload.derived_from.view_hash`
   differed between the attended and unattended legs.
3. **G4-7 — `hh-embed r2_14` loopback `Connection reset`** (fired once,
   R2.21 `52e46d4`). `LocalHttpTransport` writes the request head and
   body in two `write_all` calls; the fixture sink stopped reading at
   `\r\n\r\n` and closed, so a split segment left body bytes unread at
   close → kernel RST → client `read_to_end` saw `Connection reset`.

## Decision

1. **Minted-token expiry is inclusive** (the `now < exp` reading —
   RFC 7519's convention). `verify_minted` compares
   `now_ms >= expires_at_ms → Expired`, matching the two sibling
   conventions already in the crate (`CallerBinding::live_at` is
   `now < expires`; the `mediate` path's RFC-3339 compare is
   `expires_at <= ts_now`). A zero-TTL mint is born expired.
   `hh-secrets/tests/r2_10.rs::r2_10_minted_token_expires_at_the_expiry_instant`
   pins both sides of the boundary (`expires_at_ms - 1` → `Valid`,
   `expires_at_ms` → `Expired`, zero-TTL → `Expired` at mint instant).
2. **`derived_from.view_hash` joins the ac5 `ends_with` allowlist**
   with the derivation input named in the test comment. Root cause:
   `context.assembled` is an observation-plane row, so a *later*
   assembly's `derived_from.view_hash` is the `idp/1` stamp of the
   `context_view` fold over the durable prefix — which carries the
   earlier rows' measured `assembly_ms.value` wall. The divergence is a
   mechanical consequence of the already-allowlisted measured member,
   not an independent input; excluding measured walls from the
   projection would weaken the AC-R-2.2.1-3 rebuild contract, so the
   allowlist is the honest shape (CC1 — the sibling `MECHANICAL`
   convention, extended not duplicated).
3. **Loopback fixture sinks consume the declared request** — head plus
   the `Content-Length` body — before answering and closing. Both
   fixtures (`hh-embed/tests/r2_14.rs`, `hh-env/tests/egress_mediation.rs`)
   gained `read_request`; the fixture is now protocol-correct HTTP and
   the close is a clean FIN. No retry was added anywhere.

## Consequences

- All three legs ran 25/25 green locally post-change (≥20 in-process
  runs each, per the ticket's acceptance floor). The open findings are
  repaired-closed on `docs/build/LEDGER.md`.
- `view_hash` variance can still occur whenever `assembly_ms.value`
  crosses a millisecond in one leg — that is the *named* input, stated
  in the test comment; a semantic `derived_from` divergence still
  rejects.
- `read_request` keeps the sink's 5 s read deadline; a truncated or
  malformed request still terminates on EOF/timeout, never hangs.

## Alternatives considered

- **Retry the flaky tests** — rejected by the ticket and by the record:
  all three legs had real, identified defects; a retry would have
  masked them.
- **Make `view_hash` run-stable** (exclude measured members from the
  `context_view` fold) — rejected: the fold is the honest projection
  (full event `content`); carving out fields would split the contract
  and weaken rebuild-verifiability. The parity rule is about *ledger
  differences a consumer can act on*, and a derived hash over an
  already-excluded measured member is not one.
- **Transport-side single `write_all` or `shutdown(Write)`** — would
  lower the RST probability but not remove it (segmentation is not
  caller-controlled); the fixture read is the protocol-correct fix.

## Revisit trigger

If a flake recurs on one of these three legs, or if `assembly_ms`
stops being a measured wall (e.g. a logical-clock assembly stamp), the
allowlist members and the fixture drain should be re-audited — the
`derived_from.view_hash` allowance is only honest while its sole
run-varying input is the named measured member.
