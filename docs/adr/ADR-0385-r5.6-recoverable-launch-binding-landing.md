# ADR-0385: R5.6 recoverable launch — `launch_bound` landing decisions

- **Status:** Accepted
- **Date:** 2026-11-02
- **Ticket:** R5.6
- **Requirement ids:** REQ-E-201 (contributing; primary R5.7), REQ-D-006/REQ-E-207 (contributing)
- **Spec:** docs/evidence-and-adoption-spec.md §2.1/AC-2-1; PADR-R5-1 (admitted GATE-G9, packet A); ticket docs/tickets/175_R5.6__launch.md
- **Rung (ADR-0024 obligation):** implementation landing record — the admitted `launch_bound` durable contract's concrete encoding on the existing owners; no wire/schema change

## Context

GATE-G9 admitted PADR-R5-1: `launch_bound` — `{intent_ref, lease_ref,
funding_slice_ref, subject_root_budget_id, grade_binding{mode, pins_ref,
selection_policy_ref, instrument_budget_ref}}` — persisted intent →
allocate/open → bind subject/root → publish → arm on the experiment run's
`measurement.experiment.*` family, recovery linking existing manifests or
idempotently aborting/releasing, never a second subject. The dossier names
the record and order but leaves the id scheme, crash-window mechanics, the
abort surface and the legacy-mode binding values to the landing ticket
(AC-1/AC-2 of docs/tickets/175_R5.6__launch.md).

## Decision

1. **One class, phased rows.** `measurement.experiment.launch_bound`
   registered once (`hh-ledger/src/classes.rs` `row_prov`; `measurement`
   family ⇒ P7 plane home unchanged) carries `phase ∈ {intent, bound,
   aborted}`. `intent` commits before any allocation; `bound` commits
   atomically with `run_launched` + `run_bound` (publish before arm);
   `aborted` records the owned release.
2. **Deterministic idempotency pair.** `intent_ref =
   lbi-<idp(run, plan, attempt)>` and `subject_run_id =
   subj-<idp(run, plan, attempt)>` (`hh-identity::idp`, the S4.6
   `sub-<H(decision, H(spec))>` precedent) — the `(run_plan_id,
   attempt_no)` pair *is* the key; `open_run_with_id`/`has_run` link a
   half-created subject instead of minting a second.
3. **Adopt-or-refuse funding.** A live `slice` node scoped
   `{experiment, run_plan_id}` links under a live intent (exactly one);
   under no live intent it is `OrphanLaunchFunding` (never spent —
   `abort_launch` releases it); >1 is `LaunchBindingConflict`. The subject
   run's own `pool` root mirrors the slice spec — `subject_root_budget_id`,
   distinct from the funding slice (REQ-E-207) — minted via native
   `Account::allocate`; an existing root must carry the same spec/scope.
4. **Owned abort.** `abort_launch(run_plan_id)` completes live plan-scoped
   slices (idempotent `complete`, released row) and stamps `aborted`; a
   published attempt refuses — bound funding is never released from under
   an armed subject.
5. **Frozen inputs as conflict key.** `inputs{…}` on the intent row is the
   byte set a recovery must reproduce (experiment/plan/cell/arm/task/
   config/replicate/seed/participant_class); divergence refuses
   `LaunchBindingConflict`, as do divergent subject manifest bytes.
6. **`mode:"legacy"` grade binding.** `pins_ref` = the `CellPlan` content
   address; `instrument_budget_ref` = `spec.budgets.instrument`;
   `selection_policy_ref` absent — the required-grade opt-in freeze lands
   with the R5.9/R5.10/R5.14 owners; absence preserves legacy byte-for-byte
   (PADR-R5-1 A.7).
7. **Fault seam, never production.** `EngineContext::launch_fault_hook`
   fires at `LaunchPhase` boundaries (the `SpawnHook` precedent) — an `Err`
   is an injected kill for the acceptance battery only.
8. **Reader surface.** `launch_binding(run_plan_id)` projects the durable
   record — the only exposed contract; `lab.experiment.launch` adds
   `intent_ref`/`subject_root_budget_id` (additive members, no schema
   edit).

## Consequences

- `launch` re-derives nothing that can diverge post-crash: id, intent,
  slice, subject, root and head are all durable-derived; a kill at any of
  the five boundaries recovers to exactly one binding or the owned abort.
- Hosted relaunch re-invokes the `HostedLauncher` SPI (the adapter owns the
  session lifecycle) — a divergent fresh report fails the manifest-bytes
  equality as `LaunchBindingConflict` rather than silently binding a
  different subject.
- R5.7's adoption validates `run/plan/attempt/root` against the `bound`
  record through `launch_binding` — the same fenced writer, never a second
  subject.

## Alternatives considered

- **Two classes (`launch_intent` + `launch_bound`).** Rejected: one
  admitted name, one class-table home — `phase` is the honest encoding of
  the dossier's intent→bound→aborted lifecycle.
- **Pre-minted budget ids.** Rejected: would expand `Account`'s API for
  cosmetic determinism; the durable scan (`live_plan_slices`,
  `subject_root`) already supplies the link — reuse native allocation.
- **Silent slice re-allocation on orphan.** Rejected: orphan funding must
  refuse (AC-2), never be absorbed into a second slice.
- **`abort` consuming the claim.** Rejected: the claim converts to an
  attempt only at `run_launched`; abort leaves the plan claimable.

## Revisit trigger

When the required-grade opt-in lands (R5.9/R5.10/R5.14), `grade_binding`
gains `mode:"required"` + `selection_policy_ref`; when R5.7 lands the
adoption read must consume `launch_binding` unchanged (breaking it is a
contract change returned for amendment).
