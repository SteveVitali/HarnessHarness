# ADR-0359: R3.7 crypto-dependency choice — `ring` =0.17.14 for the `dpop` verifier, `ring::aead` reserved for R3.8

- **Status:** Accepted
- **Date:** 2026-10-15
- **Ticket:** R3.7
- **Requirement ids:** BL-19 · DF-S1.13-1 · DF-S1.13-4 · R-2.8.3 ·
  ADR-0342 (D2 revisit trigger — fired) · ADR-0050 C11 ·
  HUMAN-H5 (the 2026-10-14 operator ruling this ADR executes) ·
  CC1 · CC3 · hermetic-deps contract (amended here)
- **Spec:** §5g.3 (credential mediation — `SenderConstraint::Dpop`
  proof-of-possession; `wrapped_long_lived` delivery)
- **Rung (ADR-0024 obligation):** C0/C1 — the admitted primitives verify
  inside the offline/fixture ceiling; no environment leg.

## Context

ADR-0342 D2 ruled `SenderConstraint::Dpop` typed-refused on every
delivery mode: pure-std has no asymmetric signature verifier and the
workspace's "pure std, hermetic — do not add dependencies" contract
forbade importing one. Its revisit trigger named two openings — a
pure-std in-workspace verifier, or a deps-contract amendment. On
2026-10-14 the operator's HUMAN-H5 ruling picked **disposition (b)**:
the contract is amended by this ADR to admit a named, vetted external
crypto crate from the `ring`/`aws-lc`/`rustls` family, pinning a
version **published ≥ 7 days before selection**. R3.7 is chartered to
land this ADR as its first deliverable — before any `Cargo.toml`
dependency line — and to state the admitted scope precisely enough
that R3.8's AEAD leg either consumes the pin or authors a sibling ADR,
never a silent add.

## Decision

- **D1 — the admitted crate is `ring = 0.17.14` (exact `=0.17.14`
  pin).** Selected from the H5 family on ADR-0050 C11 criteria:
  - *Publish-age evidence.* crates.io records `0.17.14` published
    `2025-03-11T19:42:03.889273Z` — ~19 months before the 2026-10-15
    selection date, far past the operator's ≥ 7-day rule. It is the
    newest `0.17.x` release and is **not yanked**.
  - *Maintenance.* RUSTSEC-2025-0010 (INFO) marks only `ring < 0.17`
    unmaintained; `0.17.x` is the maintained line, and Debian ships
    `0.17.14` in trixie/forky/sid.
  - *Advisory posture at selection.* RUSTSEC-2025-0009 /
    CVE-2025-4432 (an `aead`/QUIC overflow-checking panic) is patched
    at `>= 0.17.12`; `0.17.14` carries the fix — material to R3.8's
    `aead` reservation (D4). No open advisory covers `0.17.14` at the
    selection date.
  - *Smallest admitted surface for the needed primitive.* `aws-lc-rs`
    pulls `aws-lc-sys` (a large C build surface); `rustls` is a TLS
    stack that pulls `ring`/`aws-lc-rs` regardless — both admit far
    more than proof-of-possession needs. `ring` gives the asymmetric
    verifier with the smallest API surface of the family.
- **D2 — admitted API scope (closed; CC1/CC3).**
  - *Now (R3.7):* `ring::signature::{UnparsedPublicKey, ED25519,
    ECDSA_P256_SHA256_ASN1}` — verification only — plus
    `ring::signature::{Ed25519KeyPair, EcdsaKeyPair}` and
    `ring::rand::SystemRandom` for **test-time fixture signing**
    (proofs are real signatures generated by the crate at test time —
    fixture-verified, never live-attested; OQ-170 key custody stays
    out of scope).
  - *Reserved for R3.8:* `ring::aead` (sealing/opening) and
    `ring::rand::SystemRandom` (key/nonce generation) — the same
    crate and pin, per H5's allowance ("R3.8 may consume the pin for
    AEAD if the ADR explicitly scopes it"). Any further `ring` module
    R3.8's design needs (e.g. `hkdf` key derivation) is its own
    sibling ADR.
  - *Not admitted:* every other `ring` module (`digest`, `hmac`,
    `pbkdf2`, `agreement`, `quic`, `constant_time`, `io`, `test`,
    internals) and every other crate. `hh-secrets` is the only
    workspace member that may name `ring`; all other members stay
    dependency-free (the hermetic contract otherwise stands).
- **D3 — pinning & supply-chain posture (ADR-0050 C11).** The member
  dependency is `ring = "=0.17.14"`; the committed `Cargo.lock` pins
  every resolved package's version + sha256 digest, so builds are
  reproducible and the fetched bytes are digest-checked. `cargo
  audit`/`cargo vet` are **not** installed or CI-wired today — this
  ADR records that honestly: the selection-time advisory review
  above is the recorded check, and wiring `cargo audit` into CI is a
  named improvement, not a claimed present control. CI gains an
  explicit `cargo fetch --locked` step so the one registry read is a
  visible, auditable build step.
- **D4 — the offline clause is amended, not silently broken.** The
  old contract's "all runtime code is pure standard library … CI runs
  offline" narrows to: *no crates are fetched at build/test time
  beyond the one lockfile-pinned `ring` graph; `cargo build
  --offline`/`--frozen` work on a warm cache or after `cargo fetch`;
  a cold-cache `cargo build` performs exactly one registry fetch of
  lockfile-pinned packages.* Committing a `cargo vendor` tree was
  measured and rejected: the full lockfile vendor closure is ~88 MiB /
  ~1.3k files (largely `windows-sys`/`windows-targets` packages this
  build never compiles — cargo requires every lockfile package present
  under `vendored-sources`), ~7× the repository's packed git history.
  `cargo vendor` remains the documented air-gap reproduction path for
  an environment that genuinely has no registry reach.
- **D5 — `unsafe` exception, recorded deliberately.** The workspace
  norm is `#![forbid(unsafe_code)]`. `ring` contains `unsafe` Rust,
  C shims, and hand-written assembly internally — this ADR admits
  that foreign-code exception **inside the named crate only**; every
  workspace member keeps `forbid(unsafe_code)` and no workspace code
  gains `unsafe`. `ring`'s build also invokes a C compiler (`cc`) for
  its assembly preludes — the toolchain requirement is amended: a
  C toolchain is now required to build the workspace (macOS/Linux/CI
  provide one).
- **D6 — the contract amendments land in this PR, with this ADR.**
  The root `Cargo.toml` header note, the root `AGENTS.md` "Pure std,
  hermetic" / "Don't add runtime dependencies" clauses and workspace
  description line, `crates/AGENTS.md`, and `README.md`'s hermetic
  claim are amended to name this ADR and the admitted scope — the
  dependency is never a silent `Cargo.toml` edit.

## Consequences

- `SenderConstraint::Dpop` verifies instead of refusing: `bind`,
  `mint`/`verify_minted`, and `mediate`/`mediate_sentinel` check a
  real asymmetric signature (`hh-secrets/src/dpop.rs`, the CC1 one
  construction); every failure mode stays `Refused{sender_constraint_
  unmet}` and the refusal still lands before the delivery effect.
- One crates.io dependency graph enters `Cargo.lock` (`ring` + its
  platform-gated transitives — `untrusted`, `cfg-if`, `libc`,
  `getrandom`, `cc`, `shlex`, `wasi`, `windows-*`; only the
  target-relevant subset is fetched/compiled on any host).
- Cold builds need one pinned registry fetch (D4); a C compiler is a
  build prerequisite (D5). CI's `cargo fetch --locked` makes both
  visible.
- R3.8 consumes `ring =0.17.14` for `aead`/`rand` under this scope
  with no new ADR; anything beyond needs a sibling ADR.
- A new `cargo audit` CI wiring remains a recorded improvement, not
  a landed control.

## Alternatives considered

- **`aws-lc-rs`** — same family, but `aws-lc-sys` is a far larger C
  build surface (cmake/`cc` machinery, bigger vendored closure) for
  the same verification primitive; rejected on minimal-surface
  grounds.
- **`rustls`** — a TLS stack, not a signature-verification crate; it
  pulls `ring`/`aws-lc-rs` anyway, so it adds surface without adding
  the needed primitive; rejected.
- **A pure-std in-workspace verifier (H5 disposition (a))** — the
  operator explicitly ruled against in-workspace crypto construction;
  out of scope for this ADR to revisit.
- **Committed `cargo vendor` tree** — preserves the literal
  zero-network cold build, but ~88 MiB of foreign sources (~7× the
  packed git history, mostly never-compiled Windows shims) for one
  signature verifier; rejected on proportionality; documented as the
  air-gap path instead (D4).
- **`ring 0.17.13`/earlier** — satisfy the ≥ 7-day rule but carry the
  unpatched RUSTSEC-2025-0009 `aead` panic relevant to R3.8's
  reserved surface; rejected — take the patched tip of the
  maintained line.

## Revisit trigger

Reopen when: a RUSTSEC advisory lands against `0.17.14`'s admitted
surface (the pin bumps by sibling ADR, not silent `cargo update`);
`ring` is declared unmaintained; R3.8 (or any later ticket) needs a
`ring` module outside D2's scope (sibling ADR); or the operator
chooses the committed-vendor posture for a stricter air-gap
requirement.
