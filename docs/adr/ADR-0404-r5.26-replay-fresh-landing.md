## Context

§6.3's procedure rows bind the recipient's admission decision —
not the execution — to an owner: the **Replay / optional R1** card
(disposable source copy with prefix/head/derived-object inventory;
provider/effect execution disabled with *independently counted*
attempted dispatches; exact declared decision/assembly and original
prefix agreement; replay markers may append; R1 deletes required
derived objects only in the copy and rederives each required hash
from the authoritative prefix), the **Fresh / optional R2|R3**
cards (new subject/calls/cost/grade; R2's pinned configuration/
models/environment + recorded seeds + validators + preregistered
margins/minimum n + all native basis; R3's registered seed
distribution/design, n ≥ k, MatchSpec, admitted equivalence
margins, observed fingerprints — one fresh demo awards no level,
and R3 is not cumulative R2), and the **Independent replication/
transfer** card (distinct installation/signer plus an actual
outside relationship — assistance/authority/attestation; new
phase/attempts; fixed comparison criterion and target; an
own-task/new-model transfer is a new question; an author-only
clean directory proves neither independence nor generalization).
Before this ticket `hh-bundle` held the bundle codec, the
`levels::derive` basis evaluator, `repro.rs`'s
`compute_independence` and the R5.22 closure walk — but no owner
procedure turned a replay attempt or fresh claim into a verdict
record; `kernel.reproduce` in `hh-embed` executes live replay and
stays the only driver (I-02).

## Decision

1. **One module, two owner-bound interfaces** —
   `crates/hh-bundle/src/cards.rs` beside `closure.rs` (the
   recipient-procedure home; records-in/records-out, no public RPC
   per Packet C C.4):
   `admit_replay(&Decoded, run_id, &ReplayAttempt) →
   Result<AdmissionCard, BundleError>` and
   `admit_fresh(&Decoded, run_id, &FreshClaim) →
   Result<AdmissionCard, BundleError>`. Nothing executes: the
   disposable copy's event stream, re-driven emission payloads and
   the claim's declaration are the inputs; the live replay driver
   stays in `hh-embed`.
2. **`admit_replay`'s legs are the §6.3 row verbatim:** `inputs`
   (definition + `compiled_bundle` member bytes, recorded provider
   response rows, a declared `control.decision` replay and both
   isolation flags — missing is a typed `CardRefused`, never a
   verdict) → `prefix` (the source stream's hash/chain recomputes
   and the copy's prefix is envelope-exact against the original —
   deviation or source corruption is `original_mutation`) →
   `suffix` (appended rows may only be `lifecycle.replay.*`
   markers continuing seq/prev_hash with recomputing hashes;
   provider `model.call.*` and effect `action.effect.*` classes
   are counted, every other class is `replay_suffix`) → `counters`
   (the card recounts the appended attempt classes itself — the
   shim's declared counts must agree exactly, and any nonzero
   attempt is `attempted_live_dispatch` **even when the transport
   blocked it**) → `decisions` (the replayed `control.decision`
   and `context.assembled` payload sequences equal the recorded
   sequences canonically — `changed_derivation`) → `rederivation`
   (R1 only: the required derived set — manifest `version_id`,
   every envelope `hash`, every `present` member address and the
   run's ledger `tree` — must each be rederived from authoritative
   bytes; a missing required object, a mismatched hash or an
   unknown name fails; not claimed is `n_a{not_claimed}`). The
   original stays immutable — the card reads `source`, never
   mutates it; a mutated original is a fail, never a
   delete-then-fake.
3. **`admit_fresh` gates before it evaluates** — typed
   `CardRefused`, §6.3's admission preconditions verbatim:
   `unfunded` (no funded replication — $0 stays, zero dispatch),
   `unavailable{model_retired}`, `not_fresh` (no new
   subject/calls/cost/grade declared),
   `charging_attribution` (the reproduction instrument must
   retain subject usage attribution); then the level-scoped
   required inputs — R2 `unavailable{seeds|margins|validators}`,
   R3 `unavailable{seed_distribution|matchspec|margins|seeds}`,
   transfer `new_question` (own-task/new-model),
   `outside_relationship` (authority/assistance/attestation
   undeclared), `no_new_phase`, `unavailable{comparison}` —
   before `not_independent` through the landed
   `compute_independence` (fail-closed: an author-only clean
   directory or key admits nothing). The evaluated legs are
   `native_basis` — every requirement entry of the level's basis
   set satisfied through `levels::derive` (the one evaluator —
   CC1; R2's set for R2/transfer, R3's for R3) — and `arms`
   (`planned_arms ≥ min_arms` with `min_arms ≥ 2`: one fresh demo
   awards no level). Leg failures land `not_admitted` rows; gates
   refuse.
4. **Cards stay separate (§6.3/F1).** Each procedure mints its own
   record — `replay-card/1` or `fresh-card/1` with required
   `procedure`/`level` members — in the family of `hh-repro/1`
   (verify), `closure-report/1` (closure) and
   `analysis-recompute/1` (recompute). `prerequisites`,
   `resources`, `counters` and `independence` are recorded as
   separate members and never fold into `verdict`; the verdict is
   `admitted` only when every leg passed, else
   `not_admitted{failures[]}` carrying `{leg, code, detail}` rows.
   `card_id` is `idp/1` over the card minus the id — the same
   seal rule `ReproReport` uses.
5. **One typed refusal vocabulary.** Gates are
   `BundleError::CardRefused{code, detail}` over the closed
   `cards::code` set (`missing_input`, `unsupported`,
   `isolation_disabled`, `unfunded`, `not_fresh`,
   `charging_attribution`, `unavailable`, `not_independent`,
   `outside_relationship`, `no_new_phase`, `new_question`) — a
   named prerequisite/policy gate is a refusal, never a drift row;
   no second codec, no new event class (CC9/CC10).

## Consequences

- A recipient can admit or refuse an isolated-replay claim
  (with the optional R1 rederivation leg) and a fresh-execution
  or transfer claim through the native owner — with the §6.3
  negatives enforced: attempted live dispatch fails even when
  blocked, original mutation and replay-suffix confusion fail,
  retired models/missing seeds/MatchSpec/parity/floor block
  fresh claims, and no funded replication or author-only
  independence admits anything.
- `tests/r5_26.rs` (20 checks) exercises every AC leg over a
  scratch-Store producer → `assemble` → `Decoded` fixture, the
  copy built as the decoded prefix plus chain-minted
  marker/attempt envelopes — compile-red at base `d5f355fb`
  (the module does not exist there).
- REQ-A-005/A-105/B-104/D-010/D-202 keep `planned; unmet` —
  this ticket records achieved engineered D/E separately from
  the owed legs: the named contributor R5.45 (trace) and every
  R/P/actual-execution predicate. REQ-A-103/C-003/F-005/F-007/
  F-204/F-205 are stamped contributing-only.
- No crate edge added, no event class, no schema/wire change, no
  new dependency; the live driver boundary is unchanged.
- AMEND ruling `7f0fbe76`: 1,823 changed source/test lines vs
  ≤750 — recorded Deviation accepted (one authored owner unit;
  the replay-vs-fresh seam is real but undocumented; leg (a)
  alone still over trigger; ~2.4× in the accepted band).

## Alternatives

- **Executing the replay inside the card** — rejected: §6.3
  makes the admission decision records-in/records-out and the
  live replay driver already lives in `hh-embed`
  (`kernel.reproduce`); a second driver violates I-02/CC1.
- **A public `hh replicate`/`hh bug-bundle` command** — rejected:
  §6.3 forbids inventing the commands; the recipe/CLI owner is
  R5.28.
- **Folding attempt counters or prerequisites into the verdict**
  — rejected by §6.3's "keep … separate" (AC-1/F1): they are
  recorded members the reader compares, never verdict inputs
  silently waived.
- **Splitting replay vs fresh across modules to fit the
  trigger** — rejected per the scoped review: the partition
  packet binds them into one owner unit, AC-1's pair-separation
  property and AC-2's single negative span both cards, the
  shared `AdmissionCard`/rig is load-bearing, and leg (a) alone
  still exceeds the line.
- **Trusting the shim's declared attempt counts** — rejected:
  §6.3 requires independently counted attempted dispatches; the
  card recounts the appended classes and requires agreement
  (`counter_dishonest`), then fails any nonzero attempt.

## Revisit triggers

- If a later procedure card (verify/recompute/rights/outside
  review) needs a different `AdmissionCard` member shape or
  failure-row vocabulary, amend this record's Decision 4 — the
  card family evolves by version, never silently.
- If the permitted replay-marker vocabulary grows beyond
  `lifecycle.replay.*` (e.g. an admitted replay-attestation
  class), revisit the `suffix` leg's closed class partition —
  appended provider/effect classes stay `attempted_live_dispatch`
  regardless.
- If R5.27's rights work admits a sanctioned derived-object set
  beyond `version_id`/envelope hashes/`present` members/ledger
  `tree` (e.g. a sanitized-derivative derived set), re-read the
  `rederivation` required set — sanitized bytes never retain
  native hashes (§6.4).
- If `levels::derive` or `compute_independence` changes its
  entry vocabulary or basis semantics, re-run the whole r5_26
  battery — `admit_fresh` inherits both evaluators verbatim.
