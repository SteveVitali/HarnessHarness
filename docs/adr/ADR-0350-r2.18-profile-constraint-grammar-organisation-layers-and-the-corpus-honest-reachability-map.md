# ADR-0350: R2.18 assembly residual — the `ProfileConstraint` grammar shape, C2 organisation-layer ordering, and the AC-CC-11 corpus's honest-reachability classification

- **Status:** Accepted
- **Date:** 2026-10-09
- **Ticket:** R2.18
- **Requirement ids:** DF-S1.9-2 · BL-10 · R-2.1.3 · R-2.1.4 · R-2.3.3 ·
  AC-CC-11 · ADR-0023 (D4) · ADR-0124 (§5) · ADR-0148 · CC1 · CC7
- **Spec:** §3.3.13 (the staged op set) · §3.3.8 (the diagnostics corpus
  gate) · §3.2.3 (the `version_pattern` closed grammar) · §5b
  (`profile_binding`, organisation layers) · §5g.4 (the
  `organisation > user > project` cap ordering).
- **Rung (ADR-0024 obligation):** C0/C2 — the constraint grammar and the
  corpus gate execute at the offline/fixture ceiling; the organisation-layer
  ordering is the C2 slice of §5b landing its declared semantics (typed
  refusal where the grammar cannot express a rule, never silent).

## Context

R2.18 discharges DF-S1.9-2's three remaining cells: the §5b
`profile_binding` *constraint* grammar (the narrowed-binding form on the
document side — the `ModelRoleTable` surface landed at S5.1), the C2
organisation layers, and AC-CC-11's one-fixture-per-code corpus gate.
Five rulings were the ticket's to make:

1. **The shape of the document-side constraint.** `profile_binding` already
   admitted `unbound` and a pinned `ProfileRef`; the third form had to
   express "constrain the admissible profile set without pinning one"
   (ADR-0023 D4) while staying portable (T-LCD-04). The members it spells
   and where satisfaction is enforced were undecided.
2. **What `version_pattern` narrowing means.** A constraint pattern over
   the bound profile's own `version_pattern` is a pattern-over-pattern
   relation — it needs a defined semantics, and the closed `Pattern`
   grammar had a home in `hh-compiler::profile` that the document side
   (`hh-assembly`) cannot depend on (deps point downward).
3. **Where the constraint is enforced.** Validation-time vs link-time:
   only link has the bound profile to test against.
4. **What the C2 organisation-layer ordering concretely forbids.**
   §5g.4 says "organisation > user > project may only narrow" — the
   compose engine needed a crisp rule for when a lower-authority
   `authority_cap` is an inversion.
5. **How AC-CC-11's "one fixture per code" reads honestly.** The closed
   `Code` table holds 95 codes (57 named + 38 `C-KERN-*`
   variants); not every code is document-reachable —
   some are minted only by downstream consumers (`hh-compiler::link`,
   `hh-lab::assembly::service`, `hh-hir::validate`), and some are
   registered with no emitting path at all today. A corpus that demands
   a fixture per code would either fake reachability or stall the gate.

## Decision

- **D1 — `ProfileConstraint` is a closed-member, narrowing-only
  grammar.** The document-side form is
  `profile_binding: {constraint: {selector?, required_capabilities?,
  fallback_profile?}}`, decoded by the canonical codec into
  `grammar::ProfileConstraint` — no longer an opaque `Json`.
  `ConstraintSelector{provider_api_family?, model_family?,
  version_pattern?, roles_admitted?}` spells the profile record's own
  member names (CC7 — one vocabulary). Every declared member *narrows*;
  absent members constrain nothing, so a vacuous `{}` stays typed
  (it decodes to the vacuous constraint — the binding admits any
  profile), never an error. `constraint` and the pin members
  (`profile_ref`/`pinned`) are mutually exclusive — a member carrying
  both refuses typed; unknown members are `C-LOAD-1` diagnostics at
  `/assembly/profile_binding`, never silently dropped. `hh-lab`'s
  override grammar now decodes the member through the one exported
  codec (`profile_binding_from_json`) — CC7, one decoder.
- **D2 — `version_pattern` narrowing is conservative subsumption; the
  grammar moved home.** `VersionPattern` (`exact | prefix |
  range{family, lo?, hi?} | any`) moved to `hh-ontology::eval` as the
  one canonical definition — `hh-compiler` re-exports it, the document
  codec spells it (CC7, the `ModelRole` convention).
  `pattern_subsumes(outer, inner, outer_family, inner_family)` answers
  `true` only when `inner` admits a subset of what `outer` admits;
  **unprovable subsumption refuses** — an `exact`-vs-`range` or a
  cross-family claim the closed grammar cannot prove is a `C-LINK-4`,
  never a silent pass. Specificity (`exact > range > prefix > any`)
  unchanged.
- **D3 — satisfaction binds at link; `fallback_profile` is the
  document-side §5 escape.** `link` decodes the sealed assembly's
  `profile_binding` through the grammar codec (a malformed constraint
  reaching link refuses — never skipped) and runs
  `check_profile_constraint` against the bound chain head: family
  equalities, conservative subsumption, `roles_admitted` coverage, and
  `required_capabilities` axes must read `declared | probed` —
  `unknown` never coerces (the router's G-2 rule). A violation is
  `LinkError{VersionConflict}` minting `C-LINK-4` — the same class a
  pin the chain doesn't contain raises. `constraint.fallback_profile`
  supplies the fallback coordinate when the caller passes none; a
  fallback binds only with a *dated* debt hypothesis
  (`expiry.is_dated()` — ADR-0124 §5) and marks `is_fallback` for the
  bundle's `fallback_used` record. `bound_profile_coordinates` names
  the constraint's `fallback_profile` so stages 6a/6b sweep it.
- **D4 — the C2 ordering is a cap-inversion rule scoped per subject.**
  `compose` collects each `organisation` layer's `authority_cap`
  subjects at their lowest precedence; a `user`/`project`/`experiment`/
  `session` layer setting an `authority_cap` over the same `of`
  subject at equal-or-higher precedence is `C-COMP-1
  AuthorityViolation` naming the inverted layer. `packaged-default` is
  kernel-authored — outside the user-authority ordering. Fragments may
  never author the derived `layers[]`/`resolved` members — doing so is
  `C-COMP-4`, a typed refusal rather than a silent drop.
- **D5 — the corpus's honest-reachability classification is the gate;
  unemittable codes are exempted-with-reasons, not faked.** The
  INDEX classifies every code in the closed table: `F` (committed
  fixture — rejected with exactly that code, path prefix and
  `source_layer` asserted), `X` (minted only by a named downstream
  owner — the per-variant fixtures live with the owner's corpus; all
  37 non-e2e `C-KERN-*` variants sit here behind `kern_code`'s
  exhaustive match, the compile-time drift control), `U` (registered
  but unemittable today — the row carries the honest reason), `N`
  (`C-INT-1` — asserted absent; a fixture minting the uncoded-rejection
  floor is a defect by definition). The nine `U` rows name their
  reasons — `C-CLASS-7` (register-time `dialect_covers` refuses first),
  `C-PROF-3` (no landed check), `C-LCD-1` (no `host` `EdgeKind`),
  `C-LOC-1` (C1+ locators), `C-TRUST-1` (a bind-failure spelling, not
  this diagnostic), `C-LINK-8`/`-9` and `C-SEAL-1` (the `CompileError`
  kind carries the refusal; the diagnostic code is never minted),
  `C-RES-1` (a status spelling) — and `C-REF-2`/`-3` sit `X` with
  honest no-producer owners. **The emitter-vs-exemption adjudication
  for these eleven codes is the deferred residual** (DF-S1.9-2 stays
  OPEN): a later ticket either lands their emitters or rules them
  permanently external. The drift test pins INDEX ↔ `Code::all()` — a
  code added without an INDEX row fails, a stale row fails; the gate
  cannot silently rot.
- **Latent defects the corpus surfaced (fixed).** `Code::all()` was
  missing `ClassSlotUnbound` (C-CLASS-2 — a registered code the
  closed-table enumeration dropped); `KERN_VARIANTS` was missing eight
  `HirError` mirrors (`RemovalTestRefusal`, `EmptyEffectSet`,
  `UnmappedParameter`, `UnscopedParameter`,
  `LiftedDeclarationsNotUnverified`, `ExactCostUnmeasured`,
  `DerivedEffectsMismatch`, `NoDiscoverySurface`); the `from_str`
  spelling map was missing `C-PARAM-6` and `C-EXT-1`..`-4`; plus a
  whitespace typo at `grammar.rs`. The corpus's
  INDEX↔`Code::all()`↔`kern_code` pinning is what made each visible —
  the gate paid for itself before it landed.

## Consequences

- `profile_binding` now has three fully-decoded forms; the constraint
  keeps the document portable (T-LCD-04) while making the admissible
  set a checked datum rather than a comment.
- Every `ProfileConstraint` member is load-bearing at link — a
  constraint that cannot be satisfied refuses `C-LINK-4` with the
  offending member named.
- `VersionPattern` has one home (`hh-ontology::eval`); the compiler
  re-exports, the document codec spells — adding a pattern arm is one
  edit, CC7.
- The corpus is a *true* reachability map: 36 fixture-emitted (35
  named codes + the `C-KERN-UnresolvedRef` e2e leg) / 49 external
  (12 named owners + 37 `C-KERN-*` mirror rows) / 9
  unemittable-with-reasons / 1 asserted-absent over the 95-code
  table. Emitters landing later move
  `U`→`F` — the INDEX is append-amendable, the drift test enforces it.
- `C-COMP-1` now names two distinct violations (experiment-layer
  widening at S3.2; the org-ordering inversion here) — both are the
  same "a lower authority may only narrow" contract; the diagnostic
  names the inverted layer.
- `is_fallback` is set whenever the bound chain came through the
  fallback path (caller-passed or constraint-declared) — the bundle's
  `fallback_used` record stays honest.

## Alternatives considered

- **Opaque `Json` constraint, interpreted downstream.** Rejected — an
  unvalidated member bag would make every consumer re-parse (a second
  spelling of the contract, CC1) and could silently ignore unknown
  members; the closed codec makes malformed input a typed `C-LOAD-1`.
- **Constraint enforced at `validate_assembly` (document stage).**
  Rejected — the document stage has no bound profile to test against;
  `bound_profile_coordinates` already names the coordinates for stages
  6a/6b, and satisfaction is a link-time relation by construction.
- **Permissive subsumption (assume satisfied when unprovable).**
  Rejected — it would let a constraint pass silently whenever the
  patterns' shapes don't compose; conservative refusal is the honest
  refusal rule (a `C-LINK-4` the author can relax deliberately beats a
  silent admit).
- **Mandate a fixture per code (no U class).** Rejected — it would
  either force fake fixtures for codes with no document path (worse
  than no coverage — a fabricated rejection teaches nothing) or block
  the gate on emitters owned by later tickets. Exemption-with-reasons
  keeps the gate honest and the residual visible.
- **Org ordering as a layer-kind precedence table.** Rejected — the
  landed rule is scoped per `of` subject and composes with the
  existing precedence machinery rather than adding a second ordering
  relation.

## Revisit trigger

Reopen when a ticket lands an emitter for any of the nine `U`-classified
codes (the row moves `U`→`F` and DF-S1.9-2's residual shrinks — the
emitter-vs-exemption adjudication closes when all eleven
no-document-path codes are dispositioned), when `EdgeKind` gains a
`host` spelling (binds `C-LCD-1`), when the resolver gains an
`Ambiguous` producer or assembly resolve publishes (binds `C-REF-2`/`-3`),
or when `version_pattern` gains an arm whose subsumption the closed
grammar cannot decide (D2's conservative rule must be re-justified).
