# ADR-0222: S0.2 Stage-0 exit-class mapping and interim exit-code numerals

- **Status:** Accepted
- **Date:** 2026-09-15
- **Ticket:** S0.2
- **Requirement ids:** R-2.11.1⁰ᵃ
- **Spec:** §7 (headless driver: exit classes `ok | invocation_error | validation_error | infrastructure_failure | budget_exhausted`; line 110 pre-ledger classes; OQ-470/OQ-384 open); inherited under ADR-0212 (Stage 0–1 MUST-data placeholders)

## Context
The Stage-0 headless driver (§7 C0 slice) must terminate with one of exactly five exit classes:
`ok | invocation_error | validation_error | infrastructure_failure | budget_exhausted`. §7 states
the exit-code **numerals** are MUST-data still open under **OQ-384** (WS-K1/K4, due before Stage
1) and that the mapping of post-`hello` kernel refusals onto `ExitClass` is open under **OQ-470**
(due Stage 2). The baseline nonetheless needs a *total* map from its terminal `StopReason` set —
`Completed`, `BudgetExhausted{dimension}`, `ContextWindowExceeded`, `ParseRefused`, `ToolTimeout`,
`TransportFailed` — onto the five classes, plus the two pre-run classes (`invocation_error`,
`validation_error`) that never open a run.

## Decision
The Stage-0 mapping is:
- `Completed → ok`
- `BudgetExhausted{dimension} → budget_exhausted`
- `ContextWindowExceeded | ParseRefused | ToolTimeout | TransportFailed → infrastructure_failure`
  (the terminal-but-not-clean, not-budget bucket at Stage 0)
- pre-run: `MissingBudget`, unknown/malformed command, unknown format → `invocation_error`
  (no run opens); a failed `definition validate` → `validation_error` (no run opens).

Interim exit-code numerals (until OQ-384 closes): `ok=0`, `invocation_error=2`,
`validation_error=3`, `infrastructure_failure=4`, `budget_exhausted=5`. A property test asserts
the `StopReason → ExitClass` map is total; the numerals are carried as MUST-data (ADR-0212).

## Consequences
- Good: the driver's termination is deterministic and total (every run ends in exactly one
  class); `invocation_error`/`validation_error` provably never open a run (AC-K1-10 shape);
  the numerals are stable for the S0.3 spike and the baseline's own tests.
- Cost: `ContextWindowExceeded`/`ParseRefused` are folded into `infrastructure_failure` because
  Stage 0 has only five classes and no `outcome_class` taxonomy yet; when §7's full exit-class
  table lands (S1.26) these may split out, and the interim numerals may change when OQ-384 closes.

## Alternatives considered
- **Invent extra exit classes for parse/context stops.** Rejected: §7 fixes exactly five Stage-0
  classes; adding a sixth would violate the contract and CC1 (one scheme per concern).
- **Fail the run (panic) on a non-clean stop.** Rejected: a non-clean stop is a real, typed
  terminal state the trace records; mapping it to `infrastructure_failure` keeps the run
  accountable rather than crashing.

## Revisit trigger
When S1.26 lands the full §7 exit-class table (derivation over `outcome_class × StopReason`) and
when OQ-384 (numerals) / OQ-470 (post-`hello` refusal mapping) close: re-derive the mapping from
the ratified table, adopt the final numerals, and retire the interim assignment here.
