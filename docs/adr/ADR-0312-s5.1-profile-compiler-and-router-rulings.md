# ADR-0312: S5.1 Profile Compiler + router rulings

- **Status:** Accepted
- **Date:** 2026-09-30
- **Ticket:** S5.1
- **Requirement ids:** R-2.3.3 (Profile Compiler rule family —
  probes, chains, renderer families, expiry as ledger events,
  AC-R-2.3.3-9/-11), R-2.3.2 (router policy family —
  `bandit`, AC-R-2.3.2-12), R-2.3.4² (K6 semantic cache —
  mandatory verifier + `readers` scoping), R-2.1.4¹ᵇ
  (`validate_assembly` stage 6b `C-PROF-2` at plan time)
- **Spec:** §3.3.1/§5b.3 (profile chains, expiry, the
  recorded-intent contract), §3.2.10/§6.1 (compile pipeline,
  validation stages), §5b.4 (`model.call.*` /
  `model.profile.*` event set), CF-313 (the `ModelRoleTable`
  as the realized model set), ADR-0121 d.2 (role table
  projection), ADR-0124/0125/0126 (profile selector/link/debt
  rulings), ADR-0189 (estimator-as-conditioned-rule), CC1/CC2/
  CC3/CC7/CC8/CC10.
- **Rung (ADR-0024 obligation):** **C1** — the profile compiler + router family — the C1 rung.

## Context

S5.1 lands the Profile Compiler rule family and the router
`bandit` family end-to-end. Seven spellings needed owned
rulings — each a seam the spec leaves to the implementation,
each now with exactly one spelling (CC1/CC7):

1. **How `bandit` joins the closed `RoutingPolicyKind` sum.**
   A bandit is an estimator, not a static policy — its
   admissibility condition, parameter surface and selection
   rule each needed one closed spelling (R-2.3.2;
   AC-R-2.3.2-12).
2. **How K6's verifier and `readers` scope are spelled.** The
   semantic cache admits marginal hits only through a
   verifier — which verifier, where the verdict rides, and
   how `readers` bounds the principal's scope each needed one
   rule (R-2.3.4²).
3. **Where plan-time `C-PROF-2` lives.** Stage 6b is the
   compiled-surface check; `validate_assembly` itself is
   compile-free. The seam that invokes the compiler — and the
   registry view it reads through — needed owning
   (R-2.1.4¹ᵇ).
4. **How non-`C-PROF-2` compile failures report at plan.**
   `UnexpressibleSurface` is 6b's named check; the compiler's
   link gates mint *no assembly diagnostics* for several
   refusal kinds — passing an empty set through verbatim
   would lose the verdict entirely (CC3).
5. **How expiry lands as ledger events.** The profile debt
   state machine's triggers (date, probe failure, evidence
   staleness, dependency drift) and the four `model.profile.*`
   event classes needed one evaluation surface.
6. **How the run realizes its `ModelRoleTable`** (CF-313):
   the `profile_binding` spec member's value grammar, the
   `primary` default, coordinate canonicalization,
   `model_profile_ref`'s gate, and the `expired_used` record
   each needed one rule (AC-R-2.3.3-11).
7. **How a compatibility-token change gates the next call.**
   The observed-token check and the pending-relower surface
   needed one claim kind and one gate (AC-R-2.3.3-9).

## Decision

1. **`bandit` is a `RoutingPolicyKind` member gated like an
   estimator** (ADR-0189's rule): a bandit policy is a
   conditioned rule — `link`/`select` refuse a bandit policy
   carrying no complete `AssumptionDebtRecord`
   (`missing_debt_record`, never coerced). Parameters are a
   closed object (`min_n`, UCB exploration coefficient, the
   `lambda` cost dock); reward projects through `BanditView`
   over the declared `task_class` — cells never pool across
   task classes. Selection is a deterministic argmax over
   `(projected_reward, binding_order)` of its declared inputs;
   unknown cells read the cold-start prior, never an invented
   score (CC3).
2. **K6 marginal hits require a registered verifier; the
   verdict is durable.** An `exact` hit serves without a
   verifier; a `marginal` (similarity ≥ threshold) serves
   only after the registered verifier passes and then
   promotes — `marginal` without a verifier refuses
   `marginal_without_verifier`, a verifier `fail` refuses
   `verifier_failed`. `readers` is a mandatory key member:
   a lookup outside the declared reader set refuses
   (`readers_violation`) — a delegate-written entry never
   serves into a principal context its `readers` doesn't
   name. The verdict rides `model.cache.resolved`'s
   `verifier_verdict` member; `false_hit_rate` accrues
   per-profile; drift-marked and revoked dependencies
   withhold, never serve.
3. **Stage 6b lives in `AssemblyService::assemble`, plan
   mode only.** After ordinary validation succeeds and before
   `finalize`, the service parses the sealed assembly,
   collects `bound_profile_coordinates` (the pinned
   `assembly.profile_binding` plus the pinned root
   `native.profile`, deduplicated) and runs
   `hh_compiler::compile` with `targets: Vec::new()` —
   the goal is the *profile* compiled-surface check, not
   target lowering. The profile view is
   `hh_lab::assembly::profiles::RegistryProfiles` — the one
   resolver `plan` and `lab.assembly.compile` share (the
   adapter moved from `hh-embed` at S5.1 so the two planes
   read identically, CC1/CC7). Stage 6b never runs when the
   report already failed, when no profile coordinates bind,
   or under `Seal` mode (the compile boundary owns the sealed
   pipeline's verdict); a hosted root keeps stage 6
   `n/a{class}`.
4. **Only `UnexpressibleSurface` mints `C-PROF-2`; a link
   refusal with no minted diagnostics warns.** The mapping is
   one function (`stage6b_diags`):
   `UnexpressibleSurface → C-PROF-2` error;
   `PlanError → C-PLAN-2` error (a plan-construct failure is
   a plan concern); `NoProfile → C-LINK-2` error (the binding
   names nothing); compiler-minted diagnostic sets
   (`LinkError{diagnostics}`, `InvalidDefinition`) pass
   through verbatim — they carry their own stage, code and
   severity. A `LinkError`/`InvalidDefinition` carrying *no*
   diagnostics (unresolvable coordinate → `version_conflict`,
   `profile_untested`/`profile_invalid`, `capability_drift`,
   `expired_without_intent`) surfaces as a stage-6 **warning**
   under the mapped `C-LINK`/`C-PLAN-1` code with the typed
   `LinkErrorKind` name in the detail — never a silent pass.
   Warning, not error, because 6b's named check is
   *expressibility*: the coordinate's own refusal belongs to
   the link gate at compile (CC10 — the plan records that the
   check could not run, it does not pre-empt compile's
   verdict). Any other `CompileError` maps to `C-PLAN-1`
   error.
5. **Expiry evaluates deterministically over declared
   observables; the events are ledger rows.**
   `hh_compiler::expiry::evaluate_expiry` is a pure fold over
   `ExpiryObservables` → `StatusTransition` — date/window
   operands, probe-failure and dependency-expiry triggers,
   evidence-staleness runway and experiment settlement each
   produce at most one transition per evaluation; `expired`
   and `retired` are terminal inside this fold (`expired →
   retired` only through the human-sealed retirement path).
   The four event classes mint through
   `hh_gateway::events`: `model.profile.status.changed`
   `{profile_ref, rule_id?, from, to, trigger}`,
   `model.profile.probed{profile_ref, probe_run_id,
   records[]}`, `model.profile.expired_used{profile_ref,
   intent_ref}` (appended to any run compiled under expired),
   and `model.surface.relowered{reason:
   compatibility_token_changed}`. Compile under expired
   rules requires `intent_ref` — absent it refuses
   `expired_without_intent` (§5b.3 d.6), present it lands the
   `expired_used` record in the linked graph.
6. **`open_session` realizes the `ModelRoleTable` and records
   it honestly.** The `spec.profile_binding` member is
   `map<ModelRole, ProfileRef | intent-bearing entry>` —
   values take `set_coordinate`'s grammar (a bare coordinate
   or the `{profile_ref}`/`{profile}` spellings) plus an
   optional `intent_ref`. A role outside the closed
   `ModelRole` set is `SchemaViolation{unknown_role}` — the
   pre-ratification `summarizer`/`shim_interpreter`
   spellings never decode (CF-468). `primary` defaults to the
   definition's pinned `native.profile`; every role binds the
   scripted kernel port's `RouteCandidate` under its
   canonicalized `profile_ref` (resolved through the registry
   → canonical `id@version`; unresolvable → the declared
   coordinate verbatim — a claim, never a substituted
   record). `configuration_id.model_ref` is the table's
   `semantic_id` (the idp/1 address — two spec blocks
   differing only in the table differ in the configuration
   id); `configuration_id`'s `profile` input is the primary
   profile's `content_hash`. The manifest records
   `extra["profile_binding"] = {roles: map<ModelRole,
   ProfileRef>, fallback_used: false}` and
   `model_profile_ref` = the resolved record's `version_id`
   (the only spelling `open_run`'s pin gate admits —
   absent when `primary` binds no resolvable record).
   A bound profile that resolves `expired` requires the row's
   `intent_ref`: absent → `Refused{expired_without_intent}`;
   present → the manifest's `expired_used[]` member records
   `{profile_ref, intent_ref}` and the run mints
   `model.profile.expired_used`. `RealizedSettings.
   model_role_table_realized` carries the table's canonical
   JSON at `open_new`; resume/attach re-projections keep the
   scripted-port map (the durable record is the manifest
   member).
7. **A compatibility-token change raises
   `SnapshotClaimKind::CompatibilityTokenChanged` and gates
   dispatch until relowered.** Snapshot observation compares
   the served endpoint's declared compatibility token with
   the bound one — a changed token mints the claim, and the
   next `open_call` refuses until the surface relowers and
   `model.surface.relowered{compatibility_token_changed}`
   lands; an unchanged or unobserved token is silent
   (observation never invents a verdict).

## Consequences

- The full profile-compiler rule family is executable
  offline: probing is a pure driver fold, expiry is a pure
  observable fold, chain resolution reads the one
  `RegistryStore` view, and renderer/tool-shape family
  expressibility is a typed `UnexpressibleSurface` verdict
  (`AC-CP-05`'s shape).
- `C-PROF-2` is now an honest plan-time error: a bound
  profile whose rules can't express the implied C0 surface
  fails `lab.assembly.plan` deterministically, at stage 6,
  before spend — while unresolvable/untested bindings warn
  rather than silently passing or over-blocking.
- `bandit` joins the closed policy sum under the same
  conditioned-rule gate every estimator obeys; selection is
  deterministic and replayable over the declared view.
- K6's semantic cache is safe-by-construction offline: no
  marginal hit serves unverified, `readers` scoping is
  structural (a key member, not an advisory), and every
  verdict is durable on `cache_resolved`.
- The manifest's `profile_binding`/`expired_used` members and
  the `model.profile.*` events give AC-R-2.3.3-11 its
  durable surface; `configuration_id` now derives the
  realized model set's identity rather than a literal
  scripted-port string.
- Every new member/variant is additive (CC8): C0-decoded
  records carry the new spellings only when present; the
  `ModelRole` closed set and `RoutingPolicyKind` sum keep
  the single-schema discipline (CC7).

## Alternatives considered

- **Run stage 6b inside `validate_assembly` behind a
  profiles parameter.** Rejected: the validator's signature
  is the shared Stage-0 contract every caller (not just the
  lab service) already invokes compile-free; 6b needs a
  registry-backed `ProfileView`, and the assembly service is
  the seam that owns both plan mode and the registry — the
  validator's stage-6 row already documents 6b as
  `n/a{not_run}` at that level.
- **Fail plan on every link-gate refusal 6b reaches**
  (unresolvable coordinate, untested profile). Rejected:
  expressibility is 6b's named check; the link gates own
  their refusals at compile — a plan-time error would
  pre-empt a verdict the compile boundary owns (CC10) and
  would refuse plan over fixtures whose pinned coordinate is
  a declared-but-unregistered claim. A warning records the
  unchecked verdict instead of silently dropping it (CC3).
- **Treat `profile_binding` values as `ProfileRef` only.**
  Rejected as the *sole* grammar: `set_coordinate` already
  admits the `{profile_ref: {profile}}`/`{profile}` spellings
  and the member needs `intent_ref` for expired bindings —
  one decoder serves both surfaces (CC1) rather than two
  grammars drifting.
- **Let `model_profile_ref` carry the canonical
  `id@version`.** Rejected: the `open_run` pin gate admits
  only a resolvable ref — the record `version_id` — while
  `id@version` is the readable coordinate the
  `profile_binding` member records. Two members, two honest
  spellings, no gate-widening (CC2).
- **Pool bandit reward across `task_class`.** Rejected: a
  cell's reward is conditioned on its declared task class —
  pooling would read another class's evidence as this
  class's prior (the AC's "never pools" leg).

## Revisit trigger

Reopen when (a) a spec revision promotes the link-gate
failures to plan-time errors — the warning arm in
`stage6b_diags` narrows to `UnexpressibleSurface` only, or
(b) the hosted/online budget lands a non-scripted port and
`realized_role_table`'s scripted `RouteCandidate` projection
becomes a real binding step over served endpoints, or (c)
the `summarizer`-era spellings re-ratify and `ModelRole`
grows — `from_json`'s closed gate and the codec's round-trip
proofs would need the new member.
