# ADR-0287: S3.10 control/verification/eval rulings

- **Status:** Accepted
- **Date:** 2026-09-24
- **Ticket:** S3.10 (`056_S3.10__control-verification-eval.md`)
- **Requirement ids:** R-2.6.1, R-2.6.2, R-2.7.1, R-2.7.2a, R-2.7.3 (S3 slices)
- **Spec:** §5e.1–§5e.2 · §5f.1–§5f.4 · owning ADRs ADR-0103…0117 ·
  ADR-0156 D2

## Context

S3.10 wires the Stage-3 control/verification executables: the completion
gate call site, `plan_execute`, the deterministic `followed` table, the
AC-F2 recorded-`model_io` battery, the three fault-injection veto
predicates, ledger-only reconciliation rebuild equality, the
programmatic-critic experiment, and the `gen_ai.evaluation.result`
lowering. The ticket owned these rulings:

1. **Who owns completion admissibility.** A `stop{completed}` decision
   could be refused at the guard seam (pre-gate) or evaluated by the
   completion gate. Two owners would fork the semantics — a guard-level
   refusal invents a second admissibility predicate beside Γ and F2–F7.
2. **How `plan_execute` lands step zero.** The naive act-loop treats
   "a plan exists" as "step-0 dispatched"; a valid plan's first step
   would be skipped.
3. **Who pays for ledger-only reconciliation.** The D2/D3/D5/D6
   detectors run over the durable prefix with no model involvement —
   subject-charging would contaminate headline values (AC-R-2.7.1-8).
4. **Which `followed` verdicts are deterministic.** AC-R-2.7.1-9 names
   `tool_surface`, typed `procedure`, kernel rule and soft-budget rule;
   prose artefacts need an honest `n/a{no_detector}` rather than a
   proxy detector.
5. **What `critic_experiment` is.** A bespoke experiment driver would
   fork pairing/interval/multiplicity semantics from `compare`.
6. **What `gen_ai.evaluation.result` carries.** The OTel eval event has
   five carried members; everything else on the verdict must be a named
   loss (CC3) — the AC names the five classes the loss report must
   spell.
7. **How `ledger_facts/1` extends.** The veto predicates need criterion
   refs, visibility, charged-to attribution, invoked-criteria and
   metadata-access facts the projection did not carry.

## Decisions

- **D1 — the gate owns completion admissibility, alone.**
  `guards.rs` never pre-refuses an admitted `stop{completed}`; the
  driver sequences `completion.proposed → claim.recorded →
  claim.reconciled → gate.evaluated → completion.decided` and only the
  gate's verdict decides. A D6 open effect is a gate `hold`, not a
  guard refusal — the `completion_refused` cue the gate emits is what
  re-drives the strategy. (One owner, one refusal semantics — CC1.)

- **D2 — `plan_landed` is a durable phase.** `plan_execute` opens in a
  `plan_landed` phase so a validated plan's step-0 dispatch is a
  distinct, replayable transition — never an implicit consequence of
  "plan exists". Invalid plans emit `control.plan.emitted{valid:false}`
  and re-plan ≤ `max_continue_nudges`.

- **D3 — ledger-only reconciliation is instrument-charged.** The
  deterministic D2/D3/D5/D6 detectors append `verification.claim.
  reconciled` rows under `charged_to = instrument`; per-claim
  deterministic-check cost is instrument cost (AC-R-2.7.2a-8). The
  subject's headline values can never read these rows.

- **D4 — the deterministic `followed` detector table.**
  `hh-verification::followed` is the single table: `tool_surface` →
  `args_conform` (the validated `action.tool.proposed` is the
  evidence); typed `procedure`/`procedure_index` → `procedure_invoked`
  (`hh_context::procedure::detect_followed` — invoked capability ∈
  `allowed_capabilities` ∧ index `delivery_id` ∈ the call's cause set);
  kernel/soft-budget rules → `postcondition` (the admitted decision
  row); `memory`/`instruction` → deterministic only when a
  `validates` edge exists, else the eval plane renders
  `n/a{no_detector}` — never a proxy (ADR-0014).

- **D5 — `critic_experiment` is a `compare` call.** The experiment is
  `hh_eval::critic_experiment::critic_experiment(definition,
  placement, design)` — `arm_a = critic_on`, `arm_b = critic_off`,
  `varied_factor = "environment"`, the five pinned metrics
  (`task_success`, `harness_overhead.verification`, `evaluator_calls`,
  `false_stop_rate`, `missed_failure_rate`) — so pairing, intervals,
  multiplicity and deviation accounting are the same machinery every
  matched comparison uses. The placement's `removal_test` is the
  deterministic handle `critic_experiment:{critic_ref}:{placement}` —
  removing the critic while keeping the placement leaves the handle
  dangling and the experiment refuses to resolve.

- **D6 — the `gen_ai.evaluation.result` lowering.** `hh-telemetry::
  genai::lower_verdict` lowers `verification.validator.verdict`:
  `gen_ai.evaluation.name` ← `criterion_ref|target`,
  `score.value` ← numeric `value.value`, `score.label` ←
  boolean/categorical, `explanation` ← `findings[].code` +
  `status_detail`, `status` ← `status`, `gen_ai.response.id` ←
  `response_ref|verdict_id`. The five AC-named classes are explicit
  loss entries — `validator_ref`/`detector`/`oracle_class` (judge
  identity), `evidence_refs`/`inputs_digest`/`evidence_head_seq`/
  `freshness_ok` (evidence), `calibration*` (calibration),
  `independence*` (independence), `cost_ppm`/`charged_to` (cost) —
  then the enumeration sweep names anything else (CC3). The lowering
  is a public function beside `lower_run`'s `model.*` scope — the
  caller composes the run's other lowerings, per the module contract.

- **D7 — `ledger_facts/1` extends additively.** `VerdictRow` +=
  `criterion_ref`/`visibility`/`charged_to`; `LedgerFacts` +=
  `invoked_criteria`/`metadata_accesses` — all optional members,
  strict-decode allowlist updated, no member renamed (CC8).

## Consequences

- Completion admissibility has exactly one semantic — replays, holds
  and success-with-veto all read the same gate output.
- `plan_execute` step-0 is a replayable transition; `control.plan.
  emitted` records are the validation audit.
- Instrument-charged reconciliation keeps subject headlines clean and
  gives per-claim deterministic-check cost accounting.
- `followed` is deterministic where the spec names a detector and
  honestly `n/a{no_detector}` on prose — the per-profile share is a
  real metric, never an inflated one.
- `critic_experiment` cannot drift from the comparison machinery; its
  refusal vocabulary is `CompareError`'s.
- The eval lowering round-trips its five carried members and names the
  five loss classes — `gen_ai.evaluation.result` exports are auditable.

## Revisit trigger

The out-of-process validator binding lands (DF-S1.21-2's remaining
half — a second codec/transport may want its own lowering beside
`lower_verdict`), the kill-after-`committed`-before-`observed` probe
composite needs a driver surface beyond the landed halves, or a
`critic_experiment` consumer needs arms beyond `{on, off}` (a
multi-placement experiment would revisit the two-arm `CompareInput`
shape).
