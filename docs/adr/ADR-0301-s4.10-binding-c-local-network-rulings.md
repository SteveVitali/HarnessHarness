# ADR-0301: S4.10 binding (c) `local_network` rulings

- **Status:** Accepted
- **Date:** 2026-09-27
- **Ticket:** S4.10
- **Requirement ids:** R-2.11.2¹
- **Spec:** §7.2 (P1–P9, binding (c), WS-H3/K2); ADR-0170…0172; ADR-0184 D2

## Context

R-2.11.2¹ lands the C1 read-only web instrument. The browser speaks to
the kernel through *binding (c)* — `local_network`: JSON-RPC 2.0 over
loopback HTTP/1.1 — under the WS-H3/K2 authentication scheme and the
§7.2 P1–P9 posture. The ticket owns the transport shape, the token
scheme, the event-drain answer, the serialisation boundary, the
cross-run `run_index` read the V1 browser needs, and the surface-side
records (`client` declaration, delivery mints, `responder` provenance)
the posture requires durable.

## Decision

- **D1 — one shared HTTP codec (`hh-wire::http`).** The binding-(c)
  server, `NetClient` and `hh-web` all speak through
  `hh-wire/src/http.rs`: request-head parse + `Content-Length` body +
  response write/read, `MAX_HEAD_BYTES`/`MAX_HEADERS`/caller body caps.
  No chunked encoding, no keep-alive reuse, no pipelining, no 1xx — the
  instrument needs none, and every transport refusal is a typed
  `HttpError`, never a partial parse (CC1: exactly one wire-shape
  implementation).
- **D2 — `POST /hh-embed/1` + `GET /hh-embed/1/events`.** One canonical
  JSON-RPC request per POST; the response is the *same*
  `EmbedService::handle` result binding (a)/(b) produce — byte-identical
  by construction (test: `net_post_parity_with_handle`). The events
  drain is a `GET` returning NDJSON of the pending notification queue
  (`stream.frame` + `upcall.*`), `wait_ms` clamped at 5 s — a serial
  server cannot park on one long-poll.
- **D3 — the gate is transport-level, ordered, no-detail.** Before
  dispatch: `?token=` → 400 (P9 — a capability never rides a URL);
  `Host` != bound authority → 400 (P3/DNS-rebind); any `Origin` or
  `Sec-Fetch-*` → 403 (this binding never speaks to a browser origin —
  a cross-site fetch's metadata is a refusal signal, not CORS
  negotiation); `Authorization: Bearer` compared constant-time → 401
  with `WWW-Authenticate` and no diagnostic (P2 — on loopback too).
- **D4 — `responder` provenance on permission decisions.**
  `RespondPermissionParams.responder{subject_ref, surface_session_ref,
  surface_ref}` is an additive optional member (CC8); when present the
  durable `security.permission.decided` payload carries
  `responder_provenance` verbatim — the web channel names its decider,
  the CLI does not (P12).
- **D5 — `run_index` is a Group-R session-free op.** V1 lists runs
  before any attach exists; a cross-run index is not a run read, so the
  op is session-free (precedent: `lab.results.*` reads). The fold lives
  at `Store::run_index` (`hh-ledger/src/store.rs`) — one pass over the
  manifest table + the terminal row per run; result-bound paging via
  `next_cursor`.
- **D6 — `client` declaration rides `open_session`.**
  `OpenSessionParams.client{kind, surface_ref, sink, ui_caps}` (additive,
  CC8) stamps `lifecycle.session.attached/detached{binding, client{kind}}`
  via `commit_kernel_row_for` — attach sessions hold no lease, so the
  kernel writes the row itself. `client.kind == "web"` is the trigger for
  the serving-side delivery mint (D7) and the session-state flag the
  surface posture audits.
- **D7 — servings to declared `web` sessions mint
  `measurement.export.delivered{sink_id: surface:<session_id>,
  view_kind, seq_range, content_classes}` on the subject run.** A
  content-bearing serving that cannot commit its audit row is refused,
  never silently unrecorded (CC3). Stream frames do *not* mint — a
  frame relay replays already-served records; minting on drains would
  self-amplify (the delivered row is itself a durable event).
- **D8 — token delivery is stderr/`--token-file` (mode 0600) only.**
  `hh-kernel serve --http` mints a ≥128-bit `/dev/urandom` token unless
  `--token` supplies one; `--token-file` writes it for the launcher;
  the bound line prints to stderr (`hh-kernel-serve-http bound=…
  token=…` or `token_file=<redacted>`). Never stdout (composable
  callers), never a ledger, never a URL (P9).
- **D9 — serial by construction.** `EmbedService` is not `Send`/`Sync`
  (boxed control/strategy ports); the (c) server accepts one connection
  at a time on the accept thread. The canonical contract's result order
  is the append order — serial serving is the honest shape for a
  single-operator instrument. `serve_net_n(listener, svc, token, n)` is
  the bounded variant the tests drive (`NetClient` on a spawned thread,
  the service on the caller's).

## Consequences

- The binding speaks only to declared programmatic clients (the
  generated `NetClient`, `hh-web`) — browser cross-site traffic is
  refused at the transport, and the *surface* enforces the browser-
  origin posture a layer up (ADR-0302).
- `run_index`/`client`/`responder` are additive schema members — the
  generated client regenerates (CC7/CC8), and `check-drift` pins it.
- Serial serving means a wedged client connection stalls the loop —
  `set_read_timeout(30s)` bounds it; a production-scale server is a
  different ticket's problem (removable tier).
- The gate duplication risk (kernel binding vs surface gate) is managed
  by sharing the `hh-wire::http` codec and mirroring the vocabulary —
  not by sharing the gate itself (the two postures differ: the binding
  rejects *all* origins; the surface admits its own).

## Alternatives considered

- **A thread-per-connection pool behind `Arc<Mutex<EmbedService>>`** —
  rejected: the service's boxed ports are not `Send`; serialising all
  requests through the mutex buys nothing over a serial accept and adds
  a real deadlock surface (long-poll + calls interleaved).
- **Unix-socket binding instead of HTTP** — rejected: §7.2 names
  `local_network` HTTP explicitly; a browser cannot speak to a unix
  socket.
- **Cookie/session auth for the browser leg** — rejected: the surface
  is the browser's only HTTP peer; the kernel binding speaks to the
  surface's server-side `NetClient`, which carries the bearer — one
  scheme per channel (WS-H3/K2), no session state anywhere.
- **Deliver `run_index` as a `project` view kind** — rejected: `project`
  is session-scoped by contract; a cross-run listing is not a run
  projection and faking the scoping would mint a bogus session row.

## Revisit trigger

Reopen when (a) a second concurrent operator needs the binding
(concurrency model), (b) the surface ecosystem binds its generated
client and shares the wire shape (HUMAN-H1), or (c) a non-loopback
deployment is authorised (OQ-401 — a fourth binding decision, not a
flag on this one).
