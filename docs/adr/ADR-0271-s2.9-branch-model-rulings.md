# ADR-0271: S2.9 branch-model rulings — the logical HEAD/WAL split, the `forked_from` anchor bound at the coerced cut, the `env` binding sum with `shared_live` refused, snapshot content-addressing excluding `at_seq`, the rollback order, the recorded replay-downgrade ladder, the source-prefix pin, and the live `rewind` frame

- **Status:** Accepted
- **Date:** 2026-09-19
- **Ticket:** S2.9
- **Requirement ids:** R-2.2.4⁰ᵃ, R-2.2.1 (fork)
  (AC-R-2.2.1-{9,15} · AC-R-2.2.4-{1,3,9,12})
- **Spec:** §5a.1 (fork/navigate/rollback, HEAD navigation, the
  `lifecycle.run.forked`/`lifecycle.run.rolled_back`/`lifecycle.head.moved`
  classes) · §5a.4 (`R-2.2.4⁰ᵃ` coherent fork points) · §5a.2 (the saga
  `compensate_run` substrate) · §5g.6 (audit/GC/redaction composition);
  ADR-0026…0035 (ledger owning set), ADR-0027 §6 (the `forked_from`
  lineage anchor), ADR-0131 §5 (HLC seeding on child runs), ADR-0032
  (the saga), ADR-0137 (env snapshots).

## Context

S2.9 lands the branch model: `coherent_fork_points` (already folded at
S2.3), the inter-run `fork`, `fs_tree` snapshot compose, `rollback`
with its compensation list + rewind note, `navigate`/HEAD movement,
subscription `Rewind` frames, GC pinning of source prefixes, the
rebuildable `branch_tree` index, and composition with the S2.5
audit/GC/redaction machinery. The spec fixes the invariants (append-only
history, the coherence gate, the compensation order); the mechanism
choices below were left to the ticket:

1. **How HEAD navigation coexists with the append-only WAL.** The
   `seq`/`prev_hash` chain is a dense linear log that must never be
   rewritten; `navigate`/`rollback` move "the head" without deleting
   events. Whether HEAD is a cursor column, a truncation marker, or a
   fold determines whether `verify` and rebuild still hold.
2. **Where the `forked_from` anchor's `at_seq`/`head_hash` are filled.**
   `coerce_to_boundary` retargets the cut inside `Store::fork`, after
   the caller built the child manifest — the caller cannot know the
   final anchor.
3. **What `env` absent means.** §5a.1 types `env ∈ {snapshot,
   trace_only}`; the pre-S2.9 `fork` had no env member at all and every
   existing caller forks without one. A default of `snapshot` would
   refuse every legacy fork (no snapshot exists); silently binding the
   parent's live workspace would violate single-writer discipline.
4. **Whether `at_seq` belongs inside the snapshot's content address.**
   AC-R-2.2.4-9 requires unchanged workspaces to share one address;
   `at_seq` differs on every take — hashing it breaks the dedup
   invariant.
5. **The rollback ordering.** Compensation, the rewind note, the
   `rolled_back` row, and the `head.moved` row must each be durable
   before the next — a crash mid-rollback must leave an honest partial
   record, never a lie.
6. **How replay-mode overreach surfaces.** `replay_mode: exact` on a
   run whose observability lacks `ledger` cannot be honored; refusing
   outright makes common forks fail, silently downgrading invents a
   claim.
7. **What pins a fork's source prefix.** The source run's own GC/redact
   would happily collect content its early prefix references — the
   branch needs a durable pin that outlives process memory.

## Decisions

**D1 — logical HEAD is a fold of the WAL; `head.moved` is a row, never
a rewrite.** `seq`/`prev_hash` chain the *WAL tip* (`wal_tip_seq`/
`wal_tip_hash`) — every append extends the dense linear log regardless
of the logical head. `RunState.head` folds `lifecycle.head.moved` rows
(`to_seq`/`to_event_id`, `Root` ⇒ the head is absent — `head()` is a
typed error, never a forged root). `read` serves the whole prefix;
`rebuild` replays the same fold, so navigation survives restart
byte-identically. `navigate`/`rollback` commit their rows through the
same `commit_kernel_row` path as live appends — one fold for both
(`INV`-parity).

**D2 — `Store::fork` fills `forked_from` at the coerced cut.** The
child manifest's `forked_from{run_id, at_seq, head_hash}` is set by the
store after `check_fork_point`/`coerce_to_boundary` resolves `at`, bound
to the source event's hash there; `open_run`'s `check_lineage_link`
re-verifies it like any caller-supplied anchor (ADR-0027 §6). The
caller names the *requested* cut; the store names the *bound* one.

**D3 — `env` is `{snapshot, trace_only, none}`; `shared_live` is the
typed refusal; absent ⇒ `none`.** `none` records "no environment bound —
the child provisions later" (the pre-S2.9 posture, kept byte-compatible
with every existing caller). `snapshot` requires a real `fs_tree`
snapshot at/below the cut — absent is `EnvironmentUnavailable`, never a
live-tree copy. `trace_only` binds none and forces `read_only` on the
record + session. `shared_live` refuses —
`Refused{shared_mutable_env}`: a mutable live environment is never
shared between branches.

**D4 — `at_seq` is provenance, excluded from the snapshot's content
address.** `SnapshotRecord::compute_ref` hashes the canonical member
form minus `at_seq` — identical trees share one `snapshot_ref`
(AC-R-2.2.4-9) while the member form and the row still carry the
observation point. The record itself persists as a blob named by the
row's `manifest_ref`; `SnapshotRecord::from_json` *re-derives* the ref
(never trusts a carried one) and `snapshot_for(store, at)` chooses the
newest `fs_tree` row with `at_seq ≤ at`.

**D5 — rollback order: coherent check → `compensate_run_after(at)` →
note blob → `rolled_back` → `head.moved` + `Rewind`.** The saga walks
applied-after-`at` compensable effects in reverse commit order
(`<orig>~comp` ids, escalation on failure — ADR-0032's machinery,
scope-bounded by `at`). The rewind note (`kind: rollback.record`) is
`put_blob`'d first so the row's `record_ref` pins it; `rolled_back`
carries the small members; `head.moved` is the actual rewind and
delivers `EventFrame::Rewind` to live subscribers. Uncompensable
effects are named in `uncompensable`; the env half restores in place
(`restore_in_place` removes what the manifest does not cover) and
writable roots no snapshot covers land in `uncaptured`.

**D6 — the coverage→replay ladder is recorded, never silent, never
invented.** The embed `fork` computes `effective_replay` from the
source's `observability_level` (`exact` needs `ledger`; `structural`
needs `model_io|ledger`; else `observational`) and the record carries
`replay_mode`/`effective_replay`/`downgrade_reason` verbatim — the
ledger stores what it is given. `CoverageInsufficient` exists for a
strict-refusal posture; S2.9 always downgrades-and-records (DF-S2.9-2).

**D7 — the `forked` row's envelope `refs` are the source-prefix pin.**
`Store::fork` collects every content address the source prefix `0..=at`
references (envelope `refs` + declared `audit_fields`/`content_refs`
payload members) plus the env snapshot blob, and puts them on the
child's `lifecycle.run.forked` envelope — `pin_reason` already honours
another run's `refs`, so `gc`/`redact` on the source refuse
`Pinned{referenced_by_run}` for anything the branch still names
(CC3). Tombstones compose unchanged: a redacted blob stays
`Missing{redacted}` to the child's readers.

**D8 — `Rewind` is an ephemeral public frame.** `EventFrame::Rewind`
adapts to `Frame::Rewind{to_seq, to_event_id, reason}` at
`durability: ephemeral` — the `head.moved` durable row also streams;
the rewind frame is the consumer's rebase cue, never the record.
`navigate`/`rollback` require a writer session — a `trace_only` child
is `attach` (read-only) and refuses them (I6's enforcement; the record
carries `read_only`).

## Consequences

- Navigation is cheap and total — no prefix copy, no WAL surgery; the
  only new durable bytes per move are one `head.moved` row.
- `branch_tree` is a pure projection (`Store::branch_tree` +
  `views::branch_tree`) — rebuild it, never trust a side index.
- A fork is fully auditable from the WAL alone: `forked_from` (verified
  anchor), `run.forked` (the BranchRecord + pin set), and the source's
  unchanged head hash (AC-R-2.2.1-9).
- Deferred (DF-S2.9-1): the replay driver, replay-validity report and
  counterfactual hook (`⁰ᵇ`) are S3.6's; `replay_mode` is recorded,
  not yet executed. Deferred (DF-S2.9-3): nothing takes `fs_tree`
  snapshots on a cadence — `fork{env: snapshot}` on an unsnapshotted
  run is the honest `SnapshotUnavailable` refusal.

## Alternatives considered

- **WAL truncation on navigate.** Rejected outright — append-only is
  the load-bearing contract; `verify` would have to explain missing
  links.
- **Caller-supplied `forked_from`.** Rejected (D2): the coerced cut is
  only known inside `fork`; a caller-filled anchor either breaks the
  manifest validator (empty hash) or binds the wrong event.
- **`env: snapshot` default.** Rejected (D3): it would refuse every
  existing fork (no snapshot machinery ran pre-S2.9); `none` is the
  honest absent-member meaning.
- **Hashing `at_seq` into `snapshot_ref`.** Rejected (D4): it breaks
  AC-R-2.2.4-9's dedup for zero benefit — the row already carries
  `at_seq`.
- **Refuse `replay_mode: exact` under insufficient coverage.**
  Rejected for S2.9 (D6): no replay driver exists to consume the mode
  yet; the recorded downgrade keeps the claim honest until S3.6.

## Revisit trigger

Reopen D1 if `read` must ever hide post-head events (the WAL-then-head
split is load-bearing for audit); D3 if `env` gains a real
`shared_live` executor (single-writer proof obligations land with it);
D4 if snapshots gain time-varying semantics (the ref basis and the
chooser's `at_seq` must move together); D5 if compensation order gains
a partial-undo mode (the scoped saga's boundary moves); D6 when S3.6
lands the replay driver — `CoverageInsufficient` becomes a live
refusal posture; D7 if `refs` payloads gain a non-`idp/1` address form.
