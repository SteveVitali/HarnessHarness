# ADR-0379: L4.4 crate rename — `hh-*` → `hharness-*` by scripted sweep; directories, binaries, and contract spellings preserved

- **Status:** Accepted
- **Date:** 2026-10-23
- **Ticket:** L4.4
- **Requirement ids:** the 2026-10-20 naming ruling (umbrella `hharness`,
  component packages `hharness-<component>`) · the ADR-0210 allocation
  record (OQ-068 `_meta` keys `dev.cognition/*` → `hharness/…`, ACP
  `_meta.hh` → `_meta.hharness`) · OQ-068
- **Spec:** none — mechanical identity migration; no contract change.
- **Rung (ADR-0024 obligation):** non-contract — publish identity only;
  wire/schema/behaviour surfaces byte-frozen by construction.

## Context

Before the publish dry-run the workspace's 53 crates must carry the
`hharness-*` package names the 2026-10-20 ruling allocated. Three
naming classes collide in the same source tree: (a) **package names**
(`hh-wire`, `hh-ledger`, …) — these rename; (b) **contract spellings**
that share the `hh-`/`hh_` prefix but are not crate names — wire ids
(`hh-embed/1`, `hh-helper/1`, `hh-kernel/<ver>`), `HH_*` environment
variables, the `hh/` registry namespace, `_hh/` methods, `hh://` URIs,
`hh.*` OTLP/baggage attributes, the `hh` tracestate member, binary
names (`hh`, `hh-kernel`, `hh-helper`, …) — these never rename;
(c) **filesystem spellings** — `crates/hh-*`/`plugins/hh-*`
directories and `src/bin/hh_*.rs` basenames — which stay because
append-only build records cite thousands of historical paths and the
directory trail is the provenance a renamer must not sever.

A hand edit cannot hold (a)/(b)/(c) apart across ~900 files; the
ticket therefore requires the rename to be a **scripted, deterministic,
idempotent sweep** (`scripts/rename-crates.sh`) with a crates.io
availability gate before any mutation, plus a stubbed self-test
(`scripts/ci/test-rename-crates.sh`).

## Decision

1. **Publish-set derivation.** The rename map is derived from
   `cargo metadata --no-deps --format-version 1`: every publishable
   `hh-<x>` package → `hharness-<x>`; the umbrella `hharness` is added;
   the set is sorted deterministically. Idempotent: already-`hharness-*`
   packages re-derive to the empty map and the script exits as a no-op.

2. **Availability gate before mutation.** One
   `GET https://crates.io/api/v1/crates/<name>` per name, ≥ 1 s apart,
   descriptive User-Agent, dated output per name. 404 = free,
   200 = taken, anything else = inconclusive. Any taken/inconclusive
   name exits non-zero and stops the run — no partial rename, the
   operator is asked. (Executed 2026-10-23T00:34:59Z–00:36:13Z:
   54/54 names free; verbatim table in `docs/build/runs/L4.4.md`.)

3. **Package/library spelling.** Packages become `hharness-<x>`; Rust
   library names default to the package name, so `hh_<x>` →
   `hharness_<x>` and `use`/`::` paths are rewritten. Binaries keep
   their names (`hh`, `hh-kernel`, `hh-helper`, `hh-mcp-serve`,
   `hh-codegen`, `hh-xcheck`, `hh-plugin-fixture`, `hh-compact-evict-oldest`,
   `hh-memory-store`, `hh-tracker-fixture`, `hh-github-issues`,
   `hh-web`, plus the single-purpose bins) — the `[[bin]]`/`[lib]`/path
   values are protected inside the sweep.

4. **Directories stay `crates/hh-*`/`plugins/hh-*`.** Append-only
   build records cite thousands of historical paths; renaming the
   directories severs that provenance for zero contract gain. Path
   spellings (directory basenames inside path-API calls, `path =`
   values, slash/dot/colon-glued tokens) are sweep-protected.

5. **Collision names.** Where a package name equals a kept binary
   name (`hh-kernel`, `hh-helper`, `hh-xcheck`, `hh-web`,
   `hh-codegen`, the packaged variants), the bare token is *ambiguous*
   — prose and log prefixes mostly mean the binary. Collision names
   therefore rewrite only in unambiguous package positions: `-p`/
   `--package` arguments, quoted package-compare strings in
   scripts/YAML, and all-package quoted lists.

6. **OQ-068 `_meta` conform (ADR-0210).** `dev.cognition/hir` →
   `hharness/hir`, `dev.cognition/propagation` → `hharness/propagation`,
   `dev.cognition/input_required` → `hharness/input_required`; the ACP
   interim vendor member `_meta.hh` → `_meta.hharness`
   (`("hh", Json::…)` → `("hharness", Json::…)`, `.get("hh")` →
   `.get("hharness")`, accessor `acp_hh_members` →
   `acp_hharness_members`). The allocation record supersedes the
   interim spellings.

7. **Protected trees.** `docs/build/`, `docs/tickets/`, `docs/adr/`,
   `research/`, `spec/`, `spikes/`, `Cargo.lock`, generated artifacts
   and the script pair itself are never swept — records are
   append-only; generated files regenerate via `hh-codegen`
   (check-drift leg), `THIRD_PARTY_NOTICES.md` and `cargo fmt --all`.

8. **Boundary grammar.** `/`, `.` and `:` are token boundaries —
   `hh-embed/1`, `crates/hh-x`, `b.hh-bundle`, `hh-bundle:<ver>`,
   `hh-embed:fleet` holder ids, `otel.service:hh-bundle`,
   `realm="hh-lab"` and `<bin>: <log>` prefixes all preserve by
   construction; `..hh_x::` struct-update spread still rewrites.

## Consequences

- 53 workspace packages renamed `hh-*` → `hharness-*`; 20 binary
  names byte-identical; `cargo metadata` derives the post-rename set
  with zero `hh-*` packages remaining.
- The `hh-embed/1` schema `owner_layer` debt metadata now spells
  `hharness-embed` (it names the owning crate layer) — the honest
  consequence is a `schema_hash` roll; `compat-1.matrix.json` and the
  TS client's `EXPECTED_SCHEMA_HASH` regenerate together under CC7.
- `use hh_*` paths are `hharness_*` across the tree; docs prose cites
  new package names while every binary/contract spelling survives.
- Second invocation is a no-op; the fixture self-test covers taken/
  inconclusive/success/idempotence and the protected surfaces.
- One pre-existing checker defect surfaced (and fixed) in-run:
  `check-removability.sh`'s EXT set missed R4.7's packaged
  `hh-github-issues` variant — added, matching `hh-tracker-fixture`'s
  identical dep shape.

## Alternatives considered

- **Rename directories too** — rejected: it severs append-only build
  provenance; the ticket rules directories stay.
- **Rename binaries** — rejected: binary names are operator-facing
  contract (`hh doctor`, `hh-kernel serve`, `HH_KERNEL_CMD`).
- **Global text substitution** — rejected: cannot separate package
  tokens from `hh-embed/1`-class contract spellings; the boundary
  grammar is the mechanism the ticket demands.
- **Defer the `_meta` conform** — rejected: L4.4 is the last
  mechanical window before publish dry-run; ADR-0210 already allocated
  the `hharness` namespace.

## Revisit trigger

Reopen when: the publish dry-run surfaces a namespace conflict on
crates.io or in registries; a foreign implementation pins the old
`hh-*` package spellings (interop naming note owed); the `hh`
tracestate/registry namespace allocation changes; or a future
directory rename is ever scheduled (requires its own ADR + a
path-rewrite pass over build records).
