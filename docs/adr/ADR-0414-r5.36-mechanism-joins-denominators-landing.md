## Context

§4.2 binds REQ-D-005/106 and REQ-E-004/107/209: versioned registry
names, native units/bounds/direction, detector/extractor ids, windows
and reducers must be declared **before** collection; for every
completed compaction `c` the subject window is
`(completion_seq(c), subject_execution_stop_seq]` — windows include
later compactions, retain overlapping `(c,event)` joins, and admit no
grading-time event. Numerators/denominators must recompute from
retained native evidence; repeated deliveries count (intensity may
exceed one); the reducers sum within subject, divide, average the
*available* subject ratios within task, then take the equal-task
contrast — events are never pooled as trials and tasks never weighted
by opportunities. The negative vocabulary is typed: missing
key/id/extractor ⇒ `no_detector`, zero denominator ⇒
`estimator_undefined`, absent summary ⇒ `inapplicable`; unavailable
required detectors stay in the frozen multiplicity family. Before this
ticket `LedgerFacts` carried no event seq on the effect/artefact row
projections (the join coordinate did not exist), no projected
execution-stop boundary existed at all, and `context_metrics::fold`
emitted only the pre-§4.2 count/summary rows — no windows, no registry,
no typed negatives.

## Decision

1. **`LedgerFacts` projects `seq` and `subject_stop_seq` — additive
   members only.** `EffectRow`/`ArtefactRow` gain `seq` (the durable
   ledger sequence is already on every `FactRow`; the projection only
   copies it). `subject_stop_seq` is the earliest durable evidence the
   subject's execution ended: `min` over (a) the first
   `action.environment.phase.changed{to: verify|teardown}` (the agent
   phase ends — grading begins), (b) the first
   `control.decision{kind:"stop"}` (the context producer's
   execution-stop row), (c) `lifecycle.run.finished`. `None` = no
   recorded stop; every windowed detector then reports `no_detector`,
   never an unbounded or last-event guess. The `ledger_facts/1` codec
   gains both members and its `reject_unknown` list admits them —
   additive decode-compat only; no pre-existing member is renamed or
   reinterpreted. Post-execution rows (seq above the boundary) can
   never join — the AC-2 test moves the boundary earlier and the
   counts shrink identically.
2. **`MECHANISM_REGISTRY` is the versioned declaration.** One
   `MechanismDecl` per §4.2 row — 21 rows at `version: 1`, family
   `mechanism`: registry name, native unit (`ratio | intensity |
   count`), bounds (`[0,1]` | `[0,∞)` — intensity never clamped),
   direction, detector/extractor id, reducer chain, `windowed`, and
   `required`. The retired capability/argument-similarity heuristic
   stays under its own distinct name
   `reliability.repeated_action_similarity` as `required: false` — an
   approximation never joins the family and is never relabelled into
   the exact `reliability.repeated_action_rate` (exact idempotency-key
   join).
3. **`MechanismOutcome` is the closed honest vocabulary.**
   `Value{numerator, denominator}` (hand-countable — the retained
   `MechanismJoin{metric, compaction_seq, event_seq, key}` rows
   recompute it) | `Count{value}` (`0` is a value) | `NoDetector` |
   `EstimatorUndefined` | `Inapplicable`. No silent zero-fill, no
   coercion into a ratio: `subject_ratio` returns `Option` and only a
   `Value` with a nonzero denominator resolves.
4. **`SubjectMechanism` takes declared detector metadata; nothing is
   inferred.** Eligible pressure opportunities, trigger marks,
   intended variant (a started row whose `variant_ref` differs is a
   fallback — an assigned-arm deviation, never a silently relabelled
   arm), the fact extractor's extractable-forgotten set, pre/post
   labels (retained, never reduced), summary presence/applicability/
   followed, opacity probe values and the same-unit subject totals are
   inputs the design pins; `None` ⇒ `no_detector`/`inapplicable` per
   the §4.2 mapping, not a guess.
5. **`detect()` emits the whole 21-key metrics map per subject**;
   `report()` folds every presented subject and keeps every registry
   member in the family (`available | mixed | unavailable`) — a
   required member with zero resolved subjects stays listed.
   `contrast()` computes `Σ_t w_t·(mean_B,t − mean_A,t)` with
   `w_t = 1/T` over tasks both arms resolved; unpaired tasks are
   retained beside, never folded; the contrast carries the registry's
   declared unit.
6. **Later contributor evidence stays owed.** The registered protocol
   freeze of detector/extractor versions and windows before any
   collection belongs to R5.41; the study report (R5.49) and the wire
   contract (R5.20) keep their full-target predicates; this ticket
   records engineered D/E only (I-07).

## Consequences

- A golden trace's every reported numerator/denominator is
  hand-countable from the retained joins; a post-execution grading
  row is structurally excluded, not filtered by convention.
- `ledger_facts/1` gains two additive members — old projections
  decode under the same strict `reject_unknown` codec; the new
  members appear only when the projector emits them.
- The family report's `unavailable` status makes a missing required
  detector visible rather than laundering it into a dropped row —
  the frozen-multiplicity clause is machine-checkable.
- The equal-task contrast discloses its inputs (paired means,
  coverage, unpaired tasks), so an unequal-coverage cell cannot
  silently become a pooled average.

## Alternatives considered

- **Deriving the stop bound from the last agent-phase event or the
  last event seq** — rejected: grading rows are durable events too;
  only a boundary defined on the phase/decision/finished vocabulary
  separates subject execution from post-execution grading. The
  three-way `min` is the earliest *durable* evidence, so a run that
  ends without a verify phase still closes its windows at
  `lifecycle.run.finished`.
- **Persisting a `mechanism_report/1` schema** — rejected: the report
  is a fold over `LedgerFacts`; a second persisted shape would
  duplicate the facts codec (CC1). The wire-admission decision lives
  with R5.20's retained-view owner.
- **Emitting the metrics map incrementally so partial families could
  ship** — rejected at the split review: `detect()` is one predicate
  over the whole registry; a partial emit either violates §4.2's
  required-member retention or ships `no_detector` stubs whose AC-2
  cells cannot run.
- **Clamping intensity to `[0,1]` for the ratio consumers** —
  rejected: §4.2 states repeated deliveries count and intensity may
  exceed one; the bound is a declared `[0,∞)` registry fact, never a
  silent post-hoc clamp.

## Revisit triggers

- If the context producer gains a new durable execution-stop row (a
  `kind` beyond `stop`, a new terminal lifecycle class, a phase name
  beyond `verify|teardown`), re-read the `subject_stop_seq` fold —
  the `min` must include the earliest evidence or post-execution
  rows could join.
- If §4.2's registry is amended (a renamed metric, a new required
  member, a version bump, a changed window bound), re-read
  `MECHANISM_REGISTRY` — versioned names are the declaration, and a
  spec change bumps `version`, never edits a row in place.
- If `ledger_facts/1` is versioned (`/2`) or a member is removed,
  re-read the additive-member decision — strict decode treats an
  unknown member as corruption by design.
- If the fact extractor/summary/opacity metadata moves onto durable
  events, re-read `SubjectMechanism`'s declared-metadata boundary —
  durable inputs would replace the pinned fields, and the
  `no_detector` paths would re-scope.
