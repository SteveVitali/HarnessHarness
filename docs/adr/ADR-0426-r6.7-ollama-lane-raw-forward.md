# ADR-0426: The Ollama upstream lane — same-dialect dialect documents, auth from `auth_kinds`, the raw-forward leg (AR-11)

- **Status:** Accepted
- **Date:** 2026-11-07
- **Ticket:** R6.7 (manifest row 260; experiments supplement §10.5 AR-11)
- **Requirement ids:** REQ-XC-104 (absorbs REQ-XC-001)
- **Spec:** experiments supplement §4.1, §4.2; design/33 F3 + §3
  ADR-C2-E + §4 hint 2; ADR-0366 (hosted dialects — amended member);
  ADR-0364 D1 (one codec home)
- **Rung (ADR-0024 obligation):** C0 — gateway dialect/transport
  contract this work already owns; the `WireDialect` member set is
  unchanged, and the admitted-dialect set grows by amendment, not
  schema

## Context

The paid program's only upstream is Ollama Cloud, and its facts are
verified (spec §4.1): OpenAI chat and Anthropic Messages surfaces at
`ollama.com/v1`, **Bearer auth only** — the Anthropic endpoint rejects
`x-api-key` alone — with `tool_choice`, `count_tokens`,
`cache_control`, `metadata`, `n`, logprobs and batches unsupported;
automatic, uncontrollable caching whose per-call count only the
native API documents.

Design/33 F3 (VERIFIED) found the gateway's live transport cannot
serve that lane: `send` re-serializes the body canonically (key order
and whitespace change — verbatim receipts are impossible), returns
only decoded `WireFrame`s, and hard-codes `x-api-key` on the Messages
family — wrong for Ollama's Messages surface, which is Bearer-only.
F3 proposes a `forward_raw` primitive reusing the same dial, TLS and
`hh-wire` codec, with the auth form a property of the lane's declared
`auth_kinds` (the ADR-0366 amendment this record lands).

## Decision

1. **Two Ollama lane dialect documents** — `ollama-chat@1` and
   `ollama-messages@1` — declared in `dialects.rs` beside the hosted
   pair. Each is built by clone-and-override from its family's
   document (`openai-compatible@1`, `anthropic-messages@1`): the wire
   grammar is the family's own — one spelling, one rule set (CC1) —
   and only the lane's honest hosting facts differ:
   - `auth_kinds: [bearer]` on both — every Ollama surface is
     Bearer-only; a credential-less bind is `CredentialUnavailable`.
   - `plan_schema` drops `tool_choice` (both lanes) and `metadata`/
     the cache-control keys (Messages lane) — unsupported upstream;
     admits `reasoning_effort` (chat lane) and `output_config` +
     `budget_tokens` (Messages lane; accepted, never claimed
     enforced).
   - `cache_semantics: uncached`, `cache_state_visible: false`,
     `count_tokens: none` — the per-call cached count is native-API
     only, and the proxy answers `count_tokens` itself.
   - `family_of` maps `ollama-messages` → `Messages` so the family's
     decoders apply.
   - The Responses lane is **not** built — conditional under C-32.
2. **Auth header derives from `auth_kinds`, not the wire family.**
   `HttpModelTransport::lane_auth_header` replaces the family match:
   `bearer` → `Authorization: Bearer`, `api_key_header` → `x-api-key`;
   a declared kind with no header form is a typed
   `unsupported_feature` refusal; an explicitly requested form the
   lane does not declare is `unsupported_feature`; an unprovided
   credential still binds no header on the default path (the
   `send`-path contract — upstream decides). For every pre-existing
   dialect the emitted bytes are identical (`anthropic-messages@1`
   declares `api_key_header` → `x-api-key`; the OpenAI pair declares
   `bearer` → Bearer) — the change is a refactor for them and the fix
   for the Ollama Messages surface.
3. **`forward_raw(credential, endpoint_ref, op, kept_headers, body,
   auth) → RawExchange{status, headers, body, chunk_stamps[]}`** on
   `HttpModelTransport` — the new primitive: same `dial`, TLS
   termination and `hh-wire` codec as `send`; the request body goes
   out **verbatim** (no plan re-serialization) and the response is
   captured raw with per-chunk arrival stamps (JSON and SSE alike).
   Any completed HTTP response is an exchange — a non-2xx is captured
   verbatim for the caller, never classified away. A caller-supplied
   auth header in `kept_headers` is refused `invalid_request` — the
   wire form is the lane's own.
4. **`raw_frames(exchange)`** replays the captured bytes through the
   family's own decoders (`SseDecoder` + `Translator` per recorded
   chunk; `completion_frames` for a JSON body) — the same frames the
   `send` path yields for the same wire bytes, stamped at their
   chunk's recorded arrival.
5. **The credential is confined to the forwarding process.** The
   value resolves inside `forward_raw`'s call frame through the
   existing `header_secret` port and is dropped on return; no member
   of `RawExchange`, no error, and no record carries it (AC-7's
   `leak_scan` is the acceptance leg).
6. **`hh-wire` gains the streaming response writer + reason phrases**
   design/33 §4 hint 2 scopes to this ticket:
   `write_response_head_chunked`, `write_chunk`, `finish_chunked`
   (the proxy's buffered release writes them) and `reason()` phrases
   for 402 / 429 / 502 / 503 / 504. One codec home (ADR-0364 D1).

## Consequences

- `POST /v1/messages` through the Ollama lane reaches upstream with
  `Authorization: Bearer` and no `x-api-key`; the chat lane likewise
  (AC-4 fixture acceptance).
- The captured bytes are exactly the wire bytes — verbatim receipts
  and byte-faithful replay are now possible for R6.10's proxy.
- No second auth-header spelling exists: `send`/`post_op`/`discover`/
  probes and `forward_raw` share `lane_auth_header`.
- `forward_raw` is additive — `open_call`/`send`'s plan path is
  untouched; non-Ollama traffic keeps its contract.

## Alternatives considered

- **Keep the family-keyed auth match and add a per-lane override** —
  a second authority for the same fact; the `auth_kinds` member is
  already the declared set and the closed `AuthKind` sum already names
  every form (CC10).
- **`forward_raw` returning classified `ModelError`s on non-2xx** —
  would discard the verbatim error body the proxy must relay; the
  exchange keeps the bytes and the caller classifies.
- **Building `ollama-responses@1` now** — conditional under C-32, out
  of Round 6 scope; the lane set covers the two required surfaces.
- **Reusing `post_op`** for the lane — it re-parses JSON and cannot
  stream or capture raw bytes; the proxy needs byte fidelity for
  receipts.

## Revisit trigger

A third Ollama surface (Responses — C-32) admitted for Round 6 or
later revisits the lane set; a provider auth form outside `{bearer,
api_key_header}` revisits `auth_form_header`'s coverage; a
`forward_raw` caller wanting pipelined or keep-alive exchanges
revisits the `Connection: close` posture.
