# ADR-0340: R2.9a egress/containment residual — gate-stage endorsement, the resume restatement rule, env-dimension budget children, and fork credential custody

- **Status:** Accepted
- **Date:** 2026-10-07
- **Ticket:** R2.9
- **Requirement ids:** DF-S1.12-1 · DF-S1.12-2 · DF-S2.4-1 · R-2.8.2 ·
  R-2.8.3 · R-2.8.4 · BL-18
- **Spec:** §5g.4 (containment, egress mediation, approval cache), §5g.7
  (approvals — I-H7), §8 (budget tree) · ADR-0266 (the S2.4 mediator
  rulings this ticket consumes) · ADR-0061 (attribution), ADR-0062
  (fail-closed containment)
- **Rung (ADR-0024 obligation):** C0–C1 — the landed members are
  deterministic machinery over durable rows; the TLS-terminating transport
  stays DF-S2.4-2/BL-31, `tls.terminate`/`inspect_hooks` and the T-CON
  residual are R2.9b's half.

## Context

R2.9 is the largest Round-2 ticket; its `## Notes` pre-registered the
split and this run lands **R2.9a = DF-S1.12-1/-2 + DF-S2.4-1 producer
seams**. Three seams were unwired when the run opened: (a) the dispatch
`net_egress` route (landed at CAP.3 — `Dispatcher` calls
`EgressMediator::gate`/`forward`); (b) the ask-endorsement ingress — a
mediated `default_unmatched = ask` suspends the effect behind the
mediator's own `security.permission.pending` trail, but nothing consumed
the operator's `security.permission.decided` answer on resume; (c) the
`fork` credential rebind — `EnvDriver::rebind_credentials_for_fork`
existed (DF-S1.13-2 machinery) but `EmbedService` held no
`CredentialBroker` to call it with. DF-S1.12-2 owed the
`resources → BudgetNode` mapping: `ResourceLimits` declared bounds had no
durable budget node. And the wire needed an honest answer to who decided
— a policy `allow` and a human endorsement mint indistinguishable
`decided` rows without `decided_by`.

## Decision

**D1 — `hh.env.*` is a registered dimension family, not a reuse of the
kernel metered dims.** `hh-ontology` registers
`hh.env.{cpu_ms, memory_bytes, disk_bytes, pids, open_files}` as
extension dimensions (`DimensionId::ExtEnv*`); the kernel metered dims
(`time.wall_ms`, `network.bytes_out`, `network.calls`) keep their
meanings for the env node's *other* caps. Env-capacity bounds and
metered-traffic bounds have different failure surfaces (a `pids` cap is
an admission guard, not a meter), so conflating them would silently
charge one ledger against the other's ceiling.

**D2 — the env's resource budget is a pool child under the run's *durable*
root, discovered from the ledger, never `manifest.budget`.**
`EnvDriver::allocate_resource_budget` maps every declared
`ResourceLimits` member onto `resource_budget_spec` hard caps and
allocates `BudgetSpec::hard_caps(Pool)` under the run's root node — the
`control.budget.allocated` row with no `parent`, found by folding the
durable prefix (S-1: runtime state derives from the record, not the
manifest's spec *reference*). No root ⇒ typed `BudgetRefused` (never an
unbudgeted bound set); a widening child refuses at `Account::allocate`
(CC9 — the parent's remaining is the envelope). The id lands on
`EnvHandle.budget_node_refs`; `spawn_handle` (fork/replace children)
inherits the parent's bounds and allocates *its own* child — custody
never shares a budget coordinate across handles.

**D3 — the monitor's answer resolves at the *gate*, and the wire stays
deferred.** `EgressMediator::endorse_gate(req, response, endorser,
chain)` is the resume ingress: `deny`/`more_info` ⇒
`security.egress.decided{deny, decided_by: monitor}` durable and the
outcome terminates; `allow_once` allows this request only; `allow_lease`
runs `amend(AddEgressAllow)` at the lease's scope bound, mints
`security.containment.amended` before any wire byte, inserts the
narrowing-only cache entry when `session_cache` admits it, and returns
`GateAllow{decided_by: Monitor, amended_policy}`. `GateAllow` carries
`decided_by` so `forward` mints `decided{allow, monitor}` at the wire
point under correct attribution — a human endorsement never masquerades
as a policy rule (the `decided` row's provenance is load-bearing, CC3).

**D4 — the resume leg is a durable-prefix fold, not session state; a
recorded verdict is never re-minted.** `egress_ask_state(store, run,
effect_id)` scans the prefix: the mediator's pending (identified by
`request.capability_ref.semantic_id = "net_egress"` + `effect_id`) →
re-suspend behind the same `permission_decided` wakeup, minting nothing;
a *final* `security.permission.decided{allow|deny}` naming the pending's
`permission_id` → reconstruct the `ApprovalResponse` + endorser and call
`endorse_gate` where `gate` would have run. Non-final rows (`ask`,
`more_info` cycles) never resolve the pending. Separately: the monitor's
own `decided{allow}` was durable before the ask suspended, so
`authorize`'s re-derived identical verdict **skips the mint** — a second
final decided for `(effect_id, attempt)` is `DuplicateDecision` (I-H7); a
*contradicting* verdict still appends and the fold fails honestly.

**D5 — fork credential custody passes the parent *handle record*, and the
broker lives on the service.** `EmbedService.credential_broker` is
kernel-held (`DenyAllResolver` by default — fail-closed; a composed host
installs its resolver through `set_credential_resolver`).
`rebind_credentials_for_fork(store, lease, broker, parent: &EnvHandle,
child_id)` takes the parent record — not a driver-table lookup — so a
cross-run fork (`work.rs::fork{env: snapshot}` — child driver, child run,
fresh lease) rebinds without the parent ever entering the child's handle
table; `envops env.derive{mode: fork_snapshot}` is the second call site.
`virtualize_for_fork` mints fresh placeholders (the parent's nonce never
crosses — SV-10), preserves expiry ceilings (SV-6), and lands
`security.credential.bound` rows on the child's run; a non-derive parent
edge refuses `InvalidState`.

**D6 — the endorsement `decided` row omits `effect_id`.**
`respond_permission`'s final `security.permission.decided` for a
`net_egress`-capability pending carries `permission_id` only: the row
*endorses the ask*, it is not the effect's gate decision (the monitor's
`decided{allow}` already holds that slot — carrying `effect_id` would be
`DuplicateDecision`, I-H7). The effect link stays on the `pending` row
and the `permission_decided` wakeup; `egress_ask_state` joins on
`permission_id`.

**D7 — `security.containment.amended` lifts into
`annotations_from_ledger.containment_amended[]`.** A scored run's egress
policy can never silently move mid-run: `hh-results` folds each durable
amendment into `{seq, from_version_id, to_version_id, basis, scope,
effect_id}` annotations (J3's floor — amended and unamended replicates
are distinguishable).

## Consequences

- The egress ask lifecycle is closed end-to-end offline: `requested` →
  pending → re-suspend-or-endorse → `decided{monitor}` → `forward` (or
  refused terminal) — every step durable, attribution honest.
- `respond_permission` needs no mediator awareness: it mints the same
  decided shape minus `effect_id`; dispatch derives the `ApprovalResponse`
  from the durable row (the endorsement survives takeover — D4 is a fold).
- Env bounds are real budget tree members: a run can `reserve`/`consume`
  against them and widening refuses structurally.
- The `DenyAllResolver` default means an unwired host's fork rebind
  yields zero bindings — the child inherits declared spellings that
  resolve to nothing (fail-closed, never the parent's value).
- Deferred: `security.egress.resolved` remains unfilled (the resolver's
  answer rides `decided`'s evidence); `tls.terminate`-required policies
  and `inspect_hooks` are R2.9b; the real TLS transport is BL-31.

## Alternatives considered

- **`manifest.budget` as the parent ref.** Rejected — it is the run's
  spec *reference*, not the allocated node id; folding
  `control.budget.allocated` is the only durable source (D2).
- **A new `security.permission.decided` member for endorsements**
  (`endorsement: true` on the same row with `effect_id`). Rejected — the
  append-path fold keys on `(effect_id, attempt)` regardless; omitting
  the coordinate is the honest distinction between "gate decision" and
  "ask endorsement" (D6).
- **Re-running `gate()` on resume.** Rejected — it would mint a second
  `requested` + pending trail, double-charging `approvals.requested` and
  forking the pending's identity (the `permission_id` must be stable for
  the wakeup join).
- **Rebind by driver-table lookup (`self.handle(parent_id)`).** Rejected
  — a cross-run child driver cannot hold the parent's handle; the record
  parameter makes custody explicit at the call site (D5).
- **Inherit the parent's `budget_node_refs` on fork.** Rejected — a
  shared node would let one handle's consumption starve the other
  invisibly; each handle allocates its own pool child (CC9 holds per
  handle).

## Revisit trigger

R2.9b lands `tls.terminate`-required enforcement / `inspect_hooks` /
per-backend `lowering_loss` + the four metrics, and DF-S2.4-3's Stage-3
leak-scan surfaces; DF-S2.4-2/BL-31 (the real TLS transport) reopens D3's
`decided_by` surface if a second non-monitor endorsement channel appears
(e.g. policy-pinned auto-endorse — the enum would grow a member, not a
bool). If `respond_permission` ever needs to *replace* a gate decision
rather than endorse an ask, D6's omission rule and the fold's
single-decision invariant must be re-decided together.
