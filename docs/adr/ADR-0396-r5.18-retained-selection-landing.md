## Context

Packet B admits durable retained selection as one owner-bound seam:
persist retained/omitted identities plus the legal tool/result, batch
and required-group joins, and rebuild the context view from that
selection so wire bytes can later be proven equal to it (B.1 row 2,
REQ-E-206). B.3 sketches the payload as `{policy_binding_ref, params,
retained_ids[], omitted_ids[], joins{tool_result_pairs, batch_groups,
required_groups}}` homed on the context plane; B.10 rejects a rebuilt
transcript without the durable selection (unprovable treatment,
resurrection hazard). The admission fixes *what* must be durable and
the rebuild-equality invariant; it does not fix the record's concrete
member names, its carrier row, the parameter vocabulary, or the
refusal/outcome alphabet the verifier reports — those are this
ticket's owned landing decisions.

## Decision

1. **Carrier: the additive `selection` member on
   `context.compaction.completed`.** The durable selection rides the
   existing completion row (`record.selection` →
   `events::compaction_completed`), minted at every `mint_record`
   site — the producer mints, the run's fenced writer lands (I-02,
   CC3). No new event class, no side store, no schema or generated
   artifact change: the payload rows gain one member, so pre-R5.18
   rows simply decode without it (durable/wire compatible).
   `retained_selection/1` is the member's schema marker
   (`RETAINED_SELECTION_SCHEMA`).
2. **Shape: `RetainedSelection{input, retained[], omitted[], status,
   pipeline_index, fallback_variant?}`.** `input` (`SelectionInput`)
   is the shared input representation the prepared call consumes
   (R5.19 leg): `policy{variant_ref, parameters}` + the assessed
   envelope (`trigger`, `window_cap`, `needed`,
   `target_fraction_ppm`, `occupancy`) + `cut_points` + the flattened
   `items[]` rows (`context_item_id`, `candidate_id`, `slot_id`,
   `retention`, `source_seq`, `tokens`, `paired_with`, `batch_id`,
   `tool{capability, invocation_ref}`) — everything a rebuild needs,
   no ledger read. A kernel-authored row carries `candidate_id:
   null`. Canonical `to_json`/`from_json` over the crate's `codec`
   helpers — integer-canonical, `reject_unknown`, closed shape.
3. **Parameter vocabulary: `CompactionStrategy::selection_parameters()`.**
   Default `{}` (a parameter-free variant); `ClearToolResults` emits
   `{capabilities[], older_than, completed_invocations{ref → seq}}` —
   the exact completion-age join the variant consumed, frozen at
   admission (B.1: "actual `evict_oldest` and `clear_tool_results`
   bindings/parameters freeze at admission"). `mint` records the
   *applied* variant's parameters — including the fallback-leg's own
   when the ladder fell through — and `compact_family`'s
   model-owned call sites pass `{}`.
4. **Replay is the production path, never a second selection.**
   `replay_selection` validates the record, rebuilds `CompactInput`
   from `input` alone, re-runs `assess` plus the recorded variant's
   `propose`/`execute` (`hh/evict-oldest@1`,
   `hh/clear-tool-results@1` — the admitted native bindings), and
   returns the recomputed sets. `verify_selection` reports
   `SelectionVerdict`: `Reproduced` only on exact omitted/retained
   and outcome equality (recorded `applied` accepts a replayed
   `Untriggered` no-requirement rung; recorded `failed` accepts any
   non-application — the ladder-exhausted record it is), `Diverged`
   on any mismatch — never a silent reconcile (the ADR-0135 §3 replay
   posture).
5. **Refusals and outcomes stay explicit and distinct (AC-2).**
   `SelectionRefusal` = `UnknownPolicy`, `DuplicateIds`,
   `ProtectedGroup` (required-retention *or* kernel-authored in
   `omitted`), `OrphanPair`, `OrphanBatch`, `MissingCompletionAge`,
   `TriggerAbsent` (`trigger: null` decodes `None`, never a
   fabricated default), `UnknownItem`, `Malformed`.
   `SelectionOutcome` = `Untriggered`, `Applied`, `Ineffective`,
   `Failed`; `via_fallback` is carried beside the kind, never folded
   into it.

## Consequences

- Every compaction completion row now carries the replayable durable
  selection: the exact admitted policy/parameters and the joins the
  selection was judged against are auditable from the row alone.
- The recorded `input` *is* the shared input representation the R5.19
  prepared-call leg consumes — the sealed-request leg reads the
  record rather than re-deriving a parallel context view (no second
  context representation, I-02/CC1).
- Unknown/unbound variant refs refuse at replay (`UnknownPolicy`),
  satisfying the B.6 posture without touching decode: a record from a
  future binding still parses, then refuses at verify.
- REQ-E-206 remains **unmet** at full-target scope: this ticket lands
  the persist+rebuild equality slice; the retained-view→wire proof
  (serialization of exactly that view, no omitted-item resurrection,
  capturing-transport checks) is R5.20 AC-3's predicate and stays
  owed, with REQ-E-003/REQ-E-104 aliased to the same owner.
- Recorded size deviation: ~1,691 changed source/test lines against
  the ≤700 contract trigger (~2.4×) — adjudicated AMEND by the scoped
  split review (single atomic unit; a persist/replay cut would land
  persisted-but-unverifiable records — the B.10 rejection — and both
  legs would still exceed); recorded here per the `b9ec0189` ruling,
  never a precedent for unmeasured growth.

## Alternatives considered

- **A standalone `context.selection.*` event class** — rejected: B.3's
  candidate is satisfied by one additive member on the row that already
  records the rung; a second class duplicates the completion fact and
  splits the fenced write the rebuild-equality invariant audits.
- **Persist only ids + parameters, re-read the ledger at replay** —
  rejected: rebuild equality must be provable from the durable
  selection alone (B.10); the flattened join rows are what make the
  pair/batch/required-group joins auditable without trusting live
  state.
- **Split at the persist/replay seam (worker's Option A)** — rejected
  by the `b9ec0189` scoped review: no documented seam (B.2 binds both
  halves to one owner; decomposition line-150 omits persist-vs-replay),
  the cut splits the admitted invariant, and each leg still exceeded
  the trigger.
- **Synthesize a default trigger for `trigger: null`** — rejected:
  absence is a distinct typed refusal (`TriggerAbsent`); a fabricated
  default would let a malformed record replay as if legal.

## Revisit trigger

Reopen if: (a) the R5.19/R5.20 prepared-call or wire legs require a
different `selection` member, join vocabulary or refusal name — amend
this record's Consequences; (b) a newly admitted compaction variant
needs persisted parameters beyond `selection_parameters()`'s shape —
the vocabulary extends by admission, never silently; (c) a decode or
replay divergence surfaces on a landed durable row — a new ADR records
the corrected protocol.
