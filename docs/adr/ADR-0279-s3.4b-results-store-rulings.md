# ADR-0279: S3.4b results-store rulings

- **Status:** Accepted
- **Date:** 2026-09-22
- **Ticket:** S3.4b (`048_S3.4b__results-store.md`)
- **Requirement ids:** R-2.10.5⁰
- **Spec:** §6.5 (results store / experiment ledger / lab-internal
  leaderboard) · ADR-0161 / ADR-0162 / ADR-0163 · ADR-0139/0140 (bundle
  members, R-levels) · ADR-0026/0029 (envelope chain) · ADR-0041 (M-modes)

## Context

S3.4b lands the Stage-3 results store (`hh-results`): `ResultsRow/1`,
`project_row`, immutable row versions under the fixed key
`(configuration_version_id, run_id)`, `build_cells`, the watermark-pinned
reads, the header-only bundle catalogue, `verify_row`/`verify_citation`,
and the lab-internal `leaderboard()` with gates L1–L5. The owning ADRs fix
the contracts; the mechanism choices below were left to the ticket:

1. **How a `bundle_id` resolves to manifest bytes.** A bundle's
   `version_id` is a derived identity — `idp/1` under the `bundle` domain
   over the manifest preimage — *not* the `blob`-domain digest the pool
   file is named by. The catalogue's `refresh` must map one to the other
   without a second index of record.
2. **What `catalogue status = validated` means.** `validate_bundle` runs
   S1–S8; some stages are assemble/reproduce-phase concerns, not admission
   tests. The catalogue needed one defensible bar.
3. **Which row version an `at`-pinned read serves.** `head(key)` names the
   newest version; a query pinned at an early watermark must not see a
   version whose watermark set the pin does not cover.
4. **How L1's `claimed_level ≥ min_claimed_level` reads.** The manifest
   declares `claimed_level`; the catalogue also computes `level_now` (the
   basis the current pool still carries). Which one gates admission needed
   pinning.
5. **How the matched-budget rule (AC-R-2.10.5-9) lands at this layer.**
   `validate_match` already refuses mismatched arms at declaration; the
   leaderboard's remaining job — stratum identity, the close-time
   `budget_match`/`under_utilised` consumption, and the unmatched reason
   spelling — needed pinning.
6. **The L1–L5 gate labels vs §6.5 §2.4's L1–L9.** The spec's L-rules name
   the full leaderboard contract (including Stage-4 L6–L9); the Stage-3
   lab-internal ladder needed an explicit mapping.
7. **A latent `commit_envelopes` defect.** HLC stamping recomputes event
   hashes after `append` has already assigned `prev_hash`, so the second
   and later durable events in a batch stored stale predecessor links —
   `verify_run` on any lineage-bearing run reported
   `Tampered{chain_broken}`.

## Decision

1. **`bundle_id → manifest` resolves by recomputation over the blob pool.**
   `catalogue::manifest_index` scans the pool's digests, decodes every
   `hh-bundle/1` manifest, and keys it by `compute_id()`. The catalogue is
   itself the derived index that amortizes the pass per refresh — no new
   store of record, nothing trusted by declaration (the manifest bytes
   recompute to the id or the entry stays `manifest_available = false`).
2. **`validated` = `validate::check_completeness` (S1/S2/S4/S7) green** —
   the same admission bar the kernel's `bundle` boundary applies;
   S3/S5/S6/S8 are assemble/reproduce-phase checks the catalogue does not
   run. `level_now` is computed separately over current member presence
   (§6.5 §2.1's GC/redaction rule: entries persist, `level_now` drops).
3. **An `at`-pinned read serves the newest *recorded* version whose
   watermark set `at` covers.** `query_rows`/`get_row` walk the stored
   version history instead of inspecting only the head; a rescore over
   covered sources supersedes in the pinned view, one over uncovered
   sources does not appear. A pin beyond a run's durable head refuses
   `WatermarkAhead` before any row resolves.
4. **L1 gates on the manifest's declared `claimed_level`.**
   `LeaderboardDefinition` carries `min_claimed_level: Option<ReproLevel>`
   (`None` = no claimed gate); a covering catalogue entry needs
   `status ≥ min_status` *and* `claimed_level ≥ min_claimed_level`.
   `level_now` never admits — it is the degradation view, not the claim;
   its role at admission is the AC-R-2.10.5-4 (Stage-4) flag surface.
5. **The leaderboard consumes the engine's E-4 close record, never
   re-derives it.** `closed.budget_match[]{arms, status}` supplies the
   comparand-group verdict: `unmatched` ⇒ L3 exclusion reason
   `unmatched_budget`, `imbalanced` ⇒ the `budget_imbalanced` flag;
   `closed.under_utilised[]` ⇒ the `under_utilised` flag. Flags annotate
   the entry — they never exclude. Arms without a usable `MatchSpec`
   (absent or `mode = none`) are L3-excluded as `unmatched_budget` — at
   Stage 3 that arm is unreachable through the engine (declaration
   refuses it), so the gate is defensive; budget *body* equality is the
   declaration-time `validate_match` gate, which resolves refs the
   results layer cannot see.
6. **The lab-internal L1–L5 is the Stage-3 gate ladder, not §2.4's
   numbering.** The implementation's gates are: L1 bundle (spec L1), L2
   eligibility — cell-table `included` + metric class/observability
   applicability + concrete value (spec L2's admission half), L3 budget
   match — stratum = `MatchSpec` canonical idp (spec L3's keys + L4's
   matched-budget precondition), L4 deterministic ordering (spec L5's
   rank determinism), L5 comparability (the binding's `comparable` flag).
   Spec-L5's distribution payload rides `distribution()`/`CellTable`;
   L6–L9 are Stage-4 scope.
7. **`commit_envelopes` re-chains durable events after HLC stamping.**
   Once stamps land, each durable event's `prev_hash` is re-assigned from
   the immediately preceding recomputed event and its hash recomputed;
   the batch's first `prev_hash` keeps the caller's value (the WAL tip or
   a fork/continuation's lineage anchor, §5a).

## Consequences

- The catalogue needs no bundle side-index — every answer derives from
  ledger facts + pool bytes, and `catalogue_refresh` re-derives it. The
  cost is one pool scan per `refresh(all)`; acceptable at lab scale and
  the catalogue persists its own fold (`catalogue.json`) between
  refreshes.
- `at`-reads are honest about coverage: a rescore whose overlay the pin
  cannot see simply does not appear — the version set, not the head,
  defines the served row.
- `min_claimed_level` admits on the *declared* claim; a bundle claiming
  R1 without basis still validates only if S4's `claimed ≤
  max_supported`/`declared ≤ derived` checks pass, so the claim a lab
  gates on is already engine-verified.
- `unmatched_budget` is a named exclusion reason a Stage-3 engine cannot
  produce end-to-end; the flag arms (`budget_imbalanced`,
  `under_utilised`) are the executable half AC-R-2.10.5-9 exercises here.
- The HLC fix touches every lineage-bearing commit path; the workspace
  suite (144 test binaries) is the regression net.

## Alternatives considered

- **A sidecar `bundle_id → blob` index written at `put_blob`.** Rejected —
  a second index is a second thing to keep consistent; recomputation is
  the one-scheme answer (CC1) and the catalogue already amortizes it.
- **`validated` = full `validate` (S1–S8).** Rejected — reproduce-phase
  stages are not admission tests; `check_completeness` is the kernel's
  own bar, and running extra stages would make the catalogue stricter
  than the boundary it mirrors.
- **`at`-reads served at the current head with watermark filtering.**
  Rejected — a head projected over sources the pin does not cover is not
  a covered row; skipping it silently loses the key, selecting the newest
  covered version is the repeatable answer.
- **Gating L1 on `level_now` instead of `claimed_level`.** Rejected —
  §2.1 makes `level_now` the GC/degradation signal (entries persist,
  `verifiable_by` drops); admission reads the claim the bundle was
  assembled and validated under.
- **Re-deriving `budget_match` in the leaderboard.** Rejected — the
  engine's close-time medians/tolerance computation is the one
  comparison; re-deriving duplicates the verdict and can disagree.
- **Leaving the HLC/`prev_hash` defect for a later ticket.** Rejected —
  `verify_row`/`verify_citation` cannot stand on a chain that does not
  verify; the fix is small, additive, and covered by the workspace suite.

## Revisit trigger

Reopen when any of: (a) Stage-4 lands `publish`/`snapshots`/`L6–L9` and
the gate ladder must be renumbered to the spec's L1–L9; (b) a foreign or
bypassed producer can write experiment runs without `validate_match`
(imports, R-2.10.5² hosted strata), making the `unmatched_budget` arm
reachable and worth hardening; (c) `level_now` becomes an admission
input under a reader-set `verifiable_by` rule; (d) the pool grows enough
that the per-refresh manifest scan needs a durable derived index.
