# ADR-0358: R3.6 assembly emitter adjudication — `CompileError` diagnostics carriage for `C-LINK-8`/`-9` and the nine permanent owner rulings

- **Status:** Accepted
- **Date:** 2026-10-15
- **Ticket:** R3.6
- **Requirement ids:** DF-S1.9-2 · BL-10 · R-2.1.3 · R-2.1.4 · AC-CC-11 ·
  ADR-0350 (revisit trigger, fired) · CC1 · CC3 · CC7 · CF-492
- **Spec:** §3.3.8 (the diagnostic taxonomy and the closed `stage` set) ·
  §3.3.13 (the staged Stage-3+ op set) · §3.2.2/§3.2.10 (the compiler
  stages and typed failure modes) · §3.3.4 (`verify_resume`) · §5b/§6.3
  (profile binding and the experiment factor rule)
- **Rung (ADR-0024 obligation):** C0/C1 — every ruling executes inside the
  offline/fixture ceiling; no environment leg.

## Context

ADR-0350's honest-reachability INDEX left eleven codes un-adjudicated:
each of `C-PROF-3`, `C-LINK-8`, `C-LINK-9`, `C-SEAL-1`, `C-RES-1`,
`C-LOC-1`, `C-TRUST-1`, `C-LCD-1`, `C-CLASS-7` (the corpus's `U` rows)
and `C-REF-2`, `C-REF-3` (`X` rows naming no real producer) had no
document path minting the diagnostic. Its revisit trigger named this
ticket's question verbatim: land a real emitter for each, or rule the
row permanently external/unemittable with a reason that names the owner
and the re-open precondition. Two questions needed deciding: how a
`CompileError` refusal that is *not* a `LinkError` carries its minted
`C-*` row to consumers (the `LinkError{diagnostics}` convention already
existed for the link-kind refusals), and where each unproduced code's
refusal is actually owned — a ruled row that says "unemittable" without
naming the producer is a defect, not a disposition (the ticket's own
contract).

## Decision

- **D1 — `C-LINK-8` is minted at the `resolve_chain` refusal.** The
  profile-selector tie is a real document path: `plan`'s stage-6b
  compiled-surface check (and any `compile` call) runs `link`, whose
  `resolve_chain(profile_refs)` tie arm is reachable whenever two bound
  profiles share `(precedence, version_pattern.specificity())` and
  neither `extends` the other. `CompileError::AmbiguousSelector` gains
  a `diagnostics: Vec<AssemblyDiagnostic>` member — the
  `LinkError{diagnostics}` carriage convention extended to the two
  standalone link-stage refusal variants (CC1: one minted diagnostic,
  carried once). `link` mints `C-LINK-8` (`stage: link`,
  `path: /assembly/profile_binding`) with the caller's kernel
  provenance at the `resolve_chain` call site; the pure resolver stays
  provenance-free and attaches `[]`.
- **D2 — `C-LINK-9` is minted at both refusal sites.** `link`'s
  dialect-narrowing check mints `C-LINK-9` with the caller's kernel;
  `hh_compiler::family::check_dialect_transform` (the AC-R-2.5.2-5
  op-check, whose callers are not yet wired) mints the same row under
  `ProvenanceRecord::kernel("compiler", 0)` — the `link_precheck`
  `kernel("assembly", 0)` precedent — so the code is never lost when
  the function gains a caller.
- **D3 — boundary consumers translate, never re-spell silently.**
  `hh_lab::assembly::service::stage6b_diags` gains explicit arms:
  `AmbiguousSelector`/`DialectNarrowingUndeclared` pass a non-empty
  `diagnostics` member through verbatim and still spell `C-LINK-8`/`-9`
  (never the `C-PLAN-1` floor) when raised with `[]` outside the link
  pipeline; `SealError` translates to an armed `C-SEAL-1` spelling for
  the defect case. `lab.assembly.compile`'s error record now carries
  `diagnostics` verbatim for every carriage variant — the op's own
  docstring promised the member; it was absent (CC3 fix, not a feature).
  `hh-compile`'s `error_json` surfaces the member for both variants.
- **D4 — the nine remaining codes are ruled, not emitted.** Each stays
  `U` with a reason naming the producing component and the re-open
  precondition (the INDEX rows carry the full text):
  - `C-REF-2` — armed mapping, no producible trigger:
    `reg_err` maps `RegistryError::Ambiguous` → `C-REF-2` and
    `RegistryStore::resolve` produces that error from
    `ResolveOutcome::Ambiguous`, but `hh_identity::names::NameIndex::
    resolve` deterministically selects the latest live head and
    `resolve_extensions`' `latest` selector takes
    max(registered_at, version_id). Re-opens on any resolver path
    returning >1 admissible candidate.
  - `C-REF-3` — publish-admission owned: `NameCollision` is raised by
    `RegistryStore::publish` only; resolve never publishes, and the one
    publish surface (`service::apply`) spells every publish refusal
    `C-PLAN-1`. Re-opens on a resolve-time collision check or per-kind
    publish spellings.
  - `C-CLASS-7` — registry-admission owned: `register`/`check_variant`
    refuse the incompatible dialect before a document carries it to
    resolve. Re-opens on a per-record dialect audit over the consumed
    snapshot.
  - `C-PROF-3` — experiment-plane owned: the §3.3.2/§6.3 pin-across-
    profile-factors rule is enforced at `hh_lab::experiment`
    registration as `ExperimentRefusal::ProfilePinnedAcrossProfiles` —
    the experiment plane's own refusal taxonomy, never an
    `AssemblyDiagnostic`. Re-opens on a diagnostics bridge or a
    plan-time `non_portable` check.
  - `C-LCD-1` — armed but unreachable: `validate`'s 7-L4 scan is wired,
    but HIR/1's closed `EdgeKind` set carries no hosting kind — an
    authored `host` edge dies earlier as `C-KERN-*`. Re-opens on a
    hosting `EdgeKind` or member encoding.
  - `C-LOC-1` — instantiate-owned: `BindFailure{locality_unsupported}`
    plus `component_bound` lifecycle events, never diagnostics
    (Stage-1 binds `in_process` only — DF-S1.9-1). Re-opens on a
    diagnostic-reporting bind surface or a validate-time placement
    check.
  - `C-TRUST-1` — runtime-owned: `VariantRuntime::bind`'s `TrustDenied`
    surfaces as `BindFailure` + `component_bound` events. Re-opens on a
    trust-gated runtime in a diagnostic path or a validation-stage
    trust check.
  - `C-RES-1` — resume-verdict owned: `verify_resume`'s `Incompatible`
    verdict is reported by `hh-embed::open` as
    `EmbedError::DefinitionChanged{reasons}` (boundary strings). Re-
    opens on a diagnostics bridge at the resume surface.
  - `C-SEAL-1` — defect-gated: `SealError{non_canonical}` fires only
    when stage-5's re-encode self-check catches the compiler's own
    output failing to round-trip — no authored document reaches it.
    Stage-6b is armed to spell it (D3). Re-opens on a content-dependent
    seal check or a `seal` stage spelling.
- **D5 — the `seal` stage spelling is a registered spec gap.**
  §3.3.8's closed `Stage` set (`desugar | compose | resolve |
  validate:1–7 | link | lower | instantiate | resume`) has no `seal`
  arm, so a diagnostic produced by stage-5 seal cannot name its stage
  honestly. Recorded as CF-492 — the register, not this ADR, owns the
  ratification path. Until then the armed 6b translation reports
  `validate:6b` as its producing stage (the existing convention: `stage`
  names the producing check, e.g. `C-PLAN-2` reports `validate:6b` for a
  link error).

## Consequences

- The corpus map stays honest *and* closes: 36 fixture-emitted / 49
  external-owned / 9 unemittable-with-reasons / 1 asserted-absent —
  the totals ADR-0350 recorded are unchanged, but the composition
  moved: `C-LINK-8`/`-9` move `U` → `X` (minted, suite-covered);
  `C-REF-2`/`-3` move `X` → `U` (the codes are minted nowhere —
  naming a crate whose *error type* exists is not emission coverage).
- `C-LINK-8`/`-9` now reach every consumer: the compile verb's
  `diagnostics` member, the `hh-compile` `error_json`, the bundle's
  diagnostics surface, and plan diagnostics verbatim — one minted row,
  one code (CC1), no boundary re-spelling.
- `CompileError::AmbiguousSelector`/`DialectNarrowingUndeclared` gained
  a member — additive in Rust's struct-variant idiom; every in-tree
  construction site was updated (exhaustive match enforcement).
- `resolve_chain` stays a pure resolver: the diagnostic is minted where
  the kernel provenance exists (the link call site), not threaded into
  the signature (a provenance parameter would ripple into
  `resolve_profile`'s public shape for no caller).
- Every ruled row's reason names why no in-tree emitter exists, the
  owning external producer, and the re-open precondition — a reviewer
  can check each claim against the code.
- `stage6b_diags`'s `other` arm can no longer silently absorb a known
  link-stage refusal into `C-PLAN-1` — the three named variants are
  spelled explicitly.
- DF-S1.9-2's final residual discharges; BL-10 closes.

## Alternatives considered

- **Boundary-mint only (no variant member).** `stage6b_diags` could
  translate `AmbiguousSelector{detail}` → `C-LINK-8` without touching
  `CompileError`. Rejected — the code's spelling would then exist only
  in plan reports; `lab.assembly.compile` and `hh-compile` would keep
  reporting the kind string, and any second consumer minting the code
  would be a second spelling (CC1). The `LinkError{diagnostics}`
  carriage convention is the established mechanism — extend it, don't
  bypass it.
- **Mint inside `resolve_chain`.** Rejected — it is a pure resolver
  with no kernel provenance; threading `kernel` through its public
  signature (and `resolve_profile`'s) buys nothing for its callers,
  and the only surfaced path is `link`'s. The link call site owns the
  stamp.
- **Fold the variants into `LinkErrorKind`.** Rejected —
  `AmbiguousSelector`/`DialectNarrowingUndeclared` are spec-named typed
  failure modes (§3.2.10); collapsing them into the link-kind closed
  sum changes the contract's shape to save a member.
- **`F` fixtures for `C-LINK-8`/`-9`.** Impossible, not avoided — the
  corpus driver is `load_canonical` inside `hh-assembly`, and
  `hh-assembly` cannot depend on `hh-compiler` (deps point downward).
  `X` is the honest class for every link-stage code — the same class
  `C-LINK-2..7` already carry.
- **Emitter for `C-SEAL-1` via a fault-injection seam.** Rejected — a
  fixture that corrupts the compiler's own output to reach the
  self-check would be a synthetic mint, exactly the dishonesty the
  corpus exists to prevent (CC3). The armed translation + `U` reason +
  CF-492 is the honest account.
- **`X` rulings for `C-REF-2`/`-3` (the kinds exist downstream).**
  Rejected — `X` means the *diagnostic code* is minted by a named
  owner crate; `RegistryError`/`ExperimentRefusal` are different error
  types entirely. `U` with the owner named is the honest class.

## Revisit trigger

Reopen when any ruled row's named precondition lands (a resolver
ambiguity path for `C-REF-2`, a resolve-time collision or per-kind
publish spelling for `C-REF-3`, a resolve-time dialect audit for
`C-CLASS-7`, an experiment-plane diagnostics bridge or plan-time
`non_portable` check for `C-PROF-3`, a hosting `EdgeKind` for
`C-LCD-1`, a diagnostic-reporting bind surface for `C-LOC-1`/`-TRUST-1`,
a resume diagnostics bridge for `C-RES-1`, a content-dependent seal
check or `seal` stage for `C-SEAL-1`); when CF-492 is ratified (the
`seal` stage spelling may change `C-SEAL-1`'s reporting stage); or if a
carriage variant is added to `CompileError` (the D3 consumers' arms
must extend — exhaustive match enforces it).
