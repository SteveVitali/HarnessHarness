# ADR-0408: R5.30 §7.3 example CI modes and bounded refresh — landing decisions

- **Status:** Accepted
- **Date:** 2026-11-03
- **Ticket:** R5.30 (Example CI modes and bounded refresh workflow)
- **Requirement ids:** REQ-F-106, REQ-F-107, REQ-F-108 (primary
  ownership — the full-target R/P and actual-execution predicates
  stay owed per the coverage register)
- **Spec:** docs/evidence-and-adoption-spec.md §7.3 (CI lane table,
  AC-7-2); docs/tickets/200_R5.30__ci.md; design 15 F4
- **Rung (ADR-0024 obligation):** implementation landing record —
  the check-lane architecture, the displayed-block marker convention
  and the refresh-policy home; no RPC, no schema, no new dependency,
  no new event class

## Context

R5.29/ADR-0407 landed the `example-card/1` records under
`scripts/examples/` and the checked runner `hharness::examples`
(battery `crates/hharness/tests/r5_29.rs`). §7.3 then requires the CI
surface that keeps those records honest: (a) a **static both-modes**
check proving committed example equivalence/pins — links,
displayed-versus-canonical command blocks, checker/pin/annotation/
claim/procedure mappings, missing/stale fails, no build or network;
(b) a **full-offline** leg executing the committed cards after the
build on one Linux leg, over canonical inputs only (a full-mode
executor must not make transitive committed docs/research reads);
(c) **separate working-tree, committed-HEAD and live checks** — an
uncommitted edit is never the tested head and a skipped leg never a
pass; and (d) **documented code/freshness/study refresh with
supersession**. Before this ticket no displayed docs surface named
the card commands, no static checker existed, and the offline
battery ran only inside the workspace test step without a named
lane.

## Decision

1. **`scripts/check-examples.sh` is the static both-modes check.**
   No build, no network; it validates, at the chosen tree: every
   `scripts/examples/ex-<NN>.json` decodes as `example-card/1`
   against the closed member set and admitted `case` set **extracted
   from the canonical runner source** (`CARD_MEMBERS` /
   `matches!(case, …)` in `crates/hharness/src/examples.rs` — the
   check derives the contract, it never mirrors a second table);
   every `pins.<name>.{path,sha256}` recomputes over the pinned
   file's bytes (missing or drifted fails, traversal outside the
   tree refuses); every declared `checks[]` id resolves to a
   check-id literal the runner emits; every committed non-card JSON
   under `scripts/examples/` is pinned by some card. It ends with an
   honest `live: skipped(…)` line — never a pass.
2. **The displayed↔canonical surface is a marked block in
   `docs/getting-started.md`.** The new "Learn offline" section
   carries `<!-- examples:begin -->…<!-- examples:end -->` fencing
   an `sh` block listing each card's `run` member exactly once, in
   card order (the `<!-- quickstart:… -->` marker precedent of
   `check-quickstart.sh`). Because the displayed side lives under
   `docs/`, a docs-only head that drifts it is exactly what the
   both-mode lane exists to catch; the checker's workflow step
   therefore carries `# ci-mode: both — …`, and
   `check-ci-gating.sh` fails if that annotation is dropped.
   `scripts/examples/README.md` is the second displayed surface —
   every card and its `run` verbatim.
3. **`--head` is the committed-HEAD check.** It clones `HEAD` into a
   scratch dir and runs the identical validation inside the clone
   (the `check-quickstart.sh` precedent): a dirty or staged-but-
   uncommitted tree can never be reported as the tested head, and a
   committed drift fails there too. The working-tree check reviews
   the authored state; the two lanes are distinct and both reported.
4. **`scripts/run-examples.sh` is the bounded full-offline lane** —
   scratch `HH_STORE_ROOT`/`HH_WORKSPACE_ROOT`,
   `cargo test -p hharness --test r5_29`, diagnostics captured under
   the scratch dir (bound ≤50 MiB; scratch ≤1 GiB), no credentials,
   services, provider or task dispatch, USD 0; it reads no committed
   docs/research path — the gated-step readers scan enforces that.
   Its `ci.yml` step is `mode != 'fast'` on `ubuntu-latest` beside
   the clean-clone Quickstart leg.
5. **The refresh workflow lives in MAINTAINING.md** (living mode) —
   "Example checks and refresh": the three check classes, the
   trigger→action table (code/schema/runtime/checker/toolchain/
   feature → scoped regressions + affected cards; artifact/access/
   expiry/redaction → closure/loss/supersession with dependents
   disabled; provider/model/price/environment drift → stale
   fresh-run claims and authorized diagnostics only; oracle/grade/
   method/cohort error → the §2.2 correction path), card-version
   supersession (a re-pin is an amendment, not an in-place edit;
   historical negatives preserved) and the release/30-day
   refresh-due rule (not false, not permission to spend; no
   automatic collection).
6. **No Rust change.** The runner, cards and battery are consumed
   unchanged; the checker is a lint over committed bytes and cannot
   fabricate a semantic verdict — execution honesty stays with
   `run_example`'s `ExampleReport`.

## Consequences

- A docs-only PR that edits the displayed block, a card, a pin or a
  pinned file fails the fast path via the both-mode step; any other
  head runs the same check plus the gated offline battery.
- `scripts/ci/test-check-examples.sh` (both-mode self-test leg)
  proves the negatives: broken card, stale pin, stale/missing
  displayed block, runner-unmapped check id, unpinned fixture data,
  `--head` immunity to working-tree dirt, committed drift failing,
  and a stripped `ci-mode: both` annotation failing
  `check-ci-gating.sh`.
- REQ-F-106/107/108 achieved **engineered D/E** — the checks exist,
  are self-tested and are wired under ADR-0362's exact classifier;
  R/P legs and any actual-execution claims remain owed to their
  owners (no live leg ran; `skipped(…)` recorded).
- The `ci.yml` anchor pair, fast-path classifier and
  maintainer/gate full-dispatch cadence are unchanged; security
  policies and branch protections untouched.

## Alternatives

- **Placing the displayed block only in `scripts/examples/README.md`
  (outside docs/)** — rejected: the both-mode lane exists to catch a
  docs-only head drifting displayed commands; a non-docs display
  surface can never exercise the fast path, and the `ci-mode: both`
  annotation would mark a step that reads nothing under docs/.
- **Executing the cards in the static lane** — rejected: §7.3's
  static lane is ≤60 s with no build; execution stays in the gated
  full-offline leg where the workspace is already built.
- **A Rust-side checker for the static lane** — rejected: it would
  need a build on the fast path, violating the lane bound; the
  shell/python lint extracts the contract from the canonical runner
  source instead of duplicating it.
- **Editing `check-quickstart.sh` to also check the cards** —
  rejected: it owns the verbatim README quickstart at committed
  HEAD; the example cards are a separate contract with their own
  displayed surface — a second checker keeps each honest.
- **A scheduled or live CI leg** — rejected: §7.3 creates no
  routine PR live calls and no automatic collection; the live lane
  is recorded `skipped(…)` until a separately authorized ADR-0363
  leg exists.

## Revisit triggers

- If a later admission adds an example family or card shape
  (EX-03/EX-04, a card with `network: true` or `spend_usd > 0`, a
  different filename convention), re-read the `ex-<NN>.json`
  card-vs-fixture rule and the prerequisites type checks — the
  static check asserts the current committed shapes, and a new
  family lands by versioned amendment, not a silent file.
- If the displayed examples surface moves out of `docs/` or a
  second docs page displays card commands, re-read the
  `ci-mode: both` requirement — the annotation is load-bearing
  exactly while a committed docs/ read exists.
- If `example-card/1`'s member set or the runner's check-id
  vocabulary changes (ADR-0407's triggers), the extracted contract
  follows automatically but a newly declared card check that no
  driver emits fails — update the driver, never the card alone.
- If `check-quickstart.sh`'s clone discipline changes, re-read the
  `--head` mode — it is the same committed-HEAD precedent applied
  to the example cards.
- If the 30-day launch metadata review cadence is adopted or ends,
  re-read MAINTAINING.md's refresh-due clause — it binds review
  naming, never spend authority.
