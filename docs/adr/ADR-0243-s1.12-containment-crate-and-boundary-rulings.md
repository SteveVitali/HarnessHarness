# ADR-0243: S1.12 containment-crate rulings — crate shape, the recorded `ContainmentGate` seam, the Stage-1 entitlement table, the path matcher, and `Ep2Model`'s honesty rules

- **Status:** Accepted
- **Date:** 2026-09-16
- **Ticket:** S1.12
- **Requirement ids:** R-2.8.4
- **Spec:** §5g.4 (the C0/Stage-1 slice per §5g.4 §9) · §05a B5 · §05d E5 ·
  ADR-0060 D1 · ADR-0061 D5 · ADR-0062 D3 · ADR-0064 · ADR-0118 · ADR-0165 ·
  ADR-0191 · ADR-0024
- **Rung (ADR-0024 obligation):** **C0** — MUST-code: `ContainmentPolicy/1`
  with `kernel_default`/`KERNEL_PROTECTED`/`KERNEL_DENY`, `effective()`, the
  `ContainmentBackend` contract, `Ep2Model` and its hermetic probe battery,
  `attach`/`evaluate`, `unreachable_permissions`, `verify`, the
  `security.containment.{applied,violated,unverified}` payload builders and
  the monitor's containment precondition are §5g.4 §2.4 inside-list items;
  `ContainmentReport`s, `lowering_loss` findings and the recorded
  `ContainmentGate` stay MUST-data.

## Context
S1.12 lands the egress/network-policy & sandbox-boundary item's Stage-1
slice — the "trusted floor": the typed `ContainmentPolicy/1`, the monotone
meet, the deny-by-default admission layer, the `process_sandbox`/`Ep2Model`
backend *model* with its hermetic probe battery, the containment event
classes, and the precondition edge into the monitor. The spec fixes the
record shape, the fail-closed rule and the staged scope but leaves these
concrete rulings to the slice:

1. **Who evaluates containment.** §5g.4 §4 and §6 make the monitor's
   precondition read a *policy decision it does not evaluate*: containment
   is a function of the environment's attached policy and its enforcement
   evidence, not of Π rows. An `authorize` that ran `attach`/`evaluate`
   inside itself would stop being a pure function over recorded inputs.
2. **The `effective()` entitlement table.** §2 requires "widening only by
   entitlement" but the spec does not name which class may loosen which
   field. The table must be total — every widening either lands or carries
   a `ContainmentWidening` — and must not invent a removal pathway the
   staged `amend()` does not yet own.
3. **The path matcher.** §3's resolution rule (resolving aliases before
   validation, `.git/hooks` never writable) needs a decidable component
   matcher now; the ADR-0212/OQ-132 interim is the precedent for an
   in-crate matcher that is conservative in the deny direction.
4. **What `Ep2Model` may honestly claim.** §8 rules EP2 "the smallest
   standard process-sandbox layer" and rules *out* attestation, external
   backends, credential injection, DNS/IP/L7/TLS inspection and deny-mode
   in-process firewalling at Stage 1. The model must declare only what it
   checks and report loss on the rest — including fields whose schema is
   landed but whose enforcement is Stage-2+ (`resources.*`, `tls.*`,
   `proxy.*`, netns knobs).
5. **Which failures `warn_and_degrade` may degrade.** §5 permits degraded
   operation *with stamped warnings* for availability/evidence problems —
   but a stored policy whose bytes do not match the declared
   `policy_version` is an integrity finding, not an availability problem.
6. **What an absent report means at the precondition.** AC-R-2.8.4-14
   refuses `ContainmentUnverified` "before any check". The spec's
   read-only exemption lives in the main flow ("read-only actions are
   exempt from the containment check" — a *post*-step-3 refinement that
   needs the risk class), so a recorded gate cannot see it.

## Decision
- **§1 — one persistent crate `crates/hh-containment`,** deps
  `hh-identity`/`hh-provenance`/`hh-wire`/`hh-ledger`; `hh-monitor`
  consumes only the closed `ContainmentGate` sum
  (`Clear | Denied{policy_boundary} | Unverified{field_group}`) as a
  *recorded input* on `Proposal` — the monitor never sees the policy or
  the backend. This mirrors ADR-0242 §2's recorded-assessor-inputs
  discipline: `authorize` stays a pure function over canonical records,
  and the gate becomes part of the replayed decision evidence.
- **§2 — the Stage-1 entitlement table** (`meet.rs`): narrowing always
  lands; loosening lands only under entitlement — `kernel` any field;
  `principal` `net.mode`, `net.rules` allow-adds, `fs.write.allow` and
  `amendment.strict`; `definition` `fs.mounts`, `resources.*` raises,
  `max_processes`/`syscall_filter` raises, and `net.rules` allow-adds
  *with a non-empty `justification`*; lower classes no loosening. Deny-kind
  sets union; allow-kind sets intersect (a lower layer's omission removes);
  stricter bools win. **`None` on an `Option` bound means "no
  declaration",** never a removal — policy layers are full records and a
  silent lower layer must not destroy an established bound; true removal
  is a Stage-2 `amend()` pathway.
- **§3 — the gate semantics:** `floor_gate` maps `attach()`-absent to
  `Unverified{field_group: "attach"}` and a stale/identity-mismatched
  report to `Unverified{field_group: "report"}` (the two whole-attach
  spellings; per-field groups spell the declared field name); `Amendable`
  is denial at Stage 1 (`AmendableUsedAsDenial`) because `amend()` is
  Stage-2; every refused admission records the gate in `report.gates`.
  An absent report refuses **all** domains including `fs.read` — the
  spec's read-only exemption is a post-step-3 refinement the recorded
  gate cannot see, and refusing early is the conservative side.
- **§4 — the path matcher** (`paths.rs`): `within` is component-bounded
  and **never rewrites `..`** — a candidate containing a parent
  component is denied outright, not normalised; relative protected
  patterns match a *window* of components at any depth (so
  `.git/hooks/post-commit` is denied everywhere it appears) and always
  extend to descendants. Host normalisation is the same pure shape the
  Stage-2 `normalize`/`decide_egress` consumes — suitability is folded
  into `normalize_host` (`dns`/`local`/`reserved` classify
  `NonPublicDestination`) so a refused `net.rules` declaration surfaces
  at `effective()`, not first at enforcement.
- **§5 — `Ep2Model` honesty rules:** the model declares exactly the
  Stage-1 `process_sandbox` enforcement surface; every field it does not
  enforce appears in `lowering_loss` with its class (`UnsupportedResource`
  for relied-on resource bounds, `UnsupportedSyscallFilter`,
  `TlsTerminationNotImplemented`, `ProxyConfigurationUnsupported`,
  `ExternalChannelCannotContain`, …). `Ep2Model` **never reports
  `attested`** — attestation is above `process_sandbox` (§8). `apply`
  refuses `Ephemeral`, `SubprocessConfined` and above-process classes
  with `UnsupportedIsolationClass`, refuses `Backend::External` with
  `ExternalBackendNotImplemented`, and refuses `net.mode =
  public`/`bridged` without `residual_channels` (I-H3); `bridged` +
  `deny` mode is `Ep2ModelImpossible` (the one honest case where
  "no network" cannot be built). `verify` accepts
  `attested`/`reported`/`probed` evidence and `unknown` under
  `warn_and_degrade`, and **refuses `stale_report` and
  `policy_ref_mismatch` under either mode** — a byte-mismatch on the
  attached policy is an integrity finding, never a degrade.
- **§6 — recorded shapes:** `security.containment.{applied,violated,
  unverified}` payloads are content-free — blob references only for the
  probe/lowering-loss detail; `unverified.field_group ∈ {attach, report,
  <declared field name>}`; `apply` surfaces `PermissionUnreachable`
  findings at attach time (the seal-side emission lands with the
  `EnvHandle` slot in S1.16 — DF-S1.12-3). `Proposal.containment` is
  added under `Proposal/1`: the proposal is a function input, never a
  ledgered record, so no persisted bytes exist to migrate; the
  `KernelDecision` evidence members (`reason`, `checks`) already absorb
  the new precondition rows without a version change.

## Consequences
- The monitor's precondition is auditable and replayable: the gate is
  recorded inside `Proposal`, ordering is tested (`ac14`), and Π is
  provably unconsulted on a containment refusal.
- `None`-as-silence makes the meet well-behaved over full-record layers —
  a lower layer that simply doesn't mention `resources.cpu_seconds` no
  longer errors — at the documented cost that bound *removal* has no
  Stage-1 pathway (deferred to `amend()`).
- The path matcher is conservative: a `..` component is a denial, not a
  rewrite, so a symlink/traversal probe can never be laundered through
  normalisation. Re-opening the ADR-0212 matcher is additive.
- `Ep2Model` cannot overclaim: any unenforceable declaration is a
  `lowering_loss` row, and `lowering_loss` containing a *relied-on* bound
  makes `floor_gate` answer `Unverified` — the AC-R-2.8.4-10 fail-closed
  behaviour is structural, not per-case.
- Degraded mode degrades only availability/evidence; integrity
  (`policy_ref_mismatch`, `stale_report`) refuses either way.

## Alternatives considered
- **Monitor evaluates the policy itself.** Rejected — `authorize` must
  stay a pure function over recorded records (ADR-0242 §2), and
  containment is a per-environment decision, not a Π row.
- **`None` = removal.** Rejected — layers are full records; silence would
  make a *narrower-appearing* layer destroy bounds and would couple
  `effective()` to the Stage-2 `amend()` semantics it does not own.
- **Rewriting `..` (path canonicalisation).** Rejected — a traversal
  component must be a denial with a typed `Denial`, not a silent rewrite
  that changes the meaning of the check.
- **`warn_and_degrade` degrades integrity findings.** Rejected —
  "helper absent" and "the attached bytes are not the declared policy"
  are different failure classes; degrading the second would let a
  tampered slot ride a warning.
- **Separate `hh-sandbox`/`hh-egress` crates.** Rejected — the Stage-1
  slice is one coherent floor (policy + meet + admit + backend + gate);
  splitting would create an orphan crate boundary the spec does not
  name. Revisit if the Stage-2 mediator grows its own crate.

## Revisit trigger
Reopen when S2.1 lands a real out-of-process EP2 backend (the
`ContainmentBackend` trait and probe battery must run through it, and
`Ep2Model`'s model semantics become the expected answer for the live
backend); when S2.4 lands `amend()`/the mediator (the `None`-as-silence
rule gains a real removal pathway and `Amendable` stops meaning denial);
when S4.14b lands above-process isolation (`attested` evidence and the
unsupported-class refusals change); or when OQ-132's closed
`ResourcePattern` grammar lands (the interim path/host matchers move to
the shared grammar).
