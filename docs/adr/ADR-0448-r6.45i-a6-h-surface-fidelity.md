- **Date:** 2026-11-16

- **Rung (ADR-0024 obligation):** an explicit non-contract note — this ADR governs the experiments-program first pass, not the canonical kernel contract ladder.

## Context

Two confirmed H-surface infidelities against the pinned Harbor behavior (diagnosis D15/D17, with the Wc7 `query-optimize` H-pub record as evidence):

- **D15 — deadlines.** `hh_w1` sets `agent_deadline_ms` 900,000 and `verify_deadline_ms` **600,000** for every cell. Harbor derives deadlines from each task's `task.toml` — `query-optimize` declares `[verifier].timeout_sec = 1800`. HH graded with a stricter deadline than the O surface: §3.8's "same verification semantics" violated. Wc7's `query-optimize` H-pub shows pytest durations 821/805/812 s with `ctrf` 6/6 passing and `reward.txt = 1` — yet `verifier_unavailable:verifier_timeout` at 600 s.
- **D17 — kill on lapse.** On deadline the runner killed only the host-side `podman exec` client and called `terminate_group("agent")` for **every** phase — a pattern the verifier's tree never matches. The leaked attempt-1 verifier finished after its deadline; attempt 2 launched while attempt 1 ran (shared CPU, inflated walls); collected files could mix attempts; the timeout path discarded the captured streams — the exact evidence a lapse produces.

## Decision

A6 (amendment row, recorded as an ADR per the insert spec):

- H-surface agent and verifier deadlines **derive from each task's `task.toml`** (`[agent].timeout_sec`, `[verifier].timeout_sec`) with the **same semantics as the pinned Harbor version** — timeout multipliers, the absent-value default and whether the agent deadline covers setup read from Harbor's code at the pin and recorded in R6.45j's implementation record (the ADR's source-line appendix lands with it). `cfg.{agent,verify}_deadline_ms` become fallbacks only; `cell-report.json` records `deadline_ms` and `deadline_source: task_toml|cfg_default` per phase.
- A lapsed exec's **own in-cell process tree is terminated** — each phase exec runs as a process-group/session leader or carries a unique per-exec marker; death is **confirmed by a `/proc` walk** before `rm_glob`, the next attempt or copy-out. The phase-blind `"agent"` pattern is dropped. Streams captured up to the lapse are **kept** — a timed-out verifier still lands its stdout/stderr as evidence. Attempts never overlap; collected files belong to exactly one attempt and record the attempt number.
- This **implements §3.8's existing "same verification semantics as Harbor"** — a fidelity correction, not a method change; the method is unchanged because the spec already requires parity with Harbor's semantics.

## Consequences

R6.45j's ACs pin the behavior: the `timeout_sec = 1800` fixture gets 1,800,000 ms with source `task_toml`; a leaked verifier tree with no "agent" cmdline is killed to confirmed death before attempt 2; the Wc7 `query-optimize` regression (ctrf 6/6, `reward.txt = 1`, 812 s) classifies `decided`, reward 1, under 1800 s. `max_grade_attempts` is confirmed against the governing REQ and Harbor's pin — changed only if the spec says so, else the observation is recorded.

## Alternatives considered

- **Keep the global 600 s verify deadline** — the standing `query-optimize` discordance is this infidelty's signature; a stricter-than-oracle deadline manufactures machinery failures. Rejected.
- **Widen `terminate_group` to phase-named patterns** — fragile: the phase's processes may not carry the pattern (the verifier tree doesn't). The per-exec group/marker kill is the mechanism-independent answer. Rejected.
- **Method amendment rather than fidelity correction** — wrong frame: §3.8 already demands Harbor's semantics; the gap is in the implementation, not the method. Rejected.

## Revisit trigger

Revisit if the pinned Harbor version's deadline semantics change at a re-pin, if a task family ships `task.toml` values outside the admitted bounds (the above-ceiling/malformed refusal path), or if overlapping-attempt evidence surfaces again after the fix — a new defect, not this correction's failure.
