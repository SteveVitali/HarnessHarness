# ADR-0347: R2.15 verification-plane legs — postcondition consumption, the `call:` belief-probe subject spelling, the recorded-judge port, and live-run metric emission

- **Status:** Accepted
- **Date:** 2026-10-08
- **Ticket:** R2.15
- **Requirement ids:** R-2.7.1 · R-2.7.2a · R-2.7.2b · R-2.7.3 ·
  DF-S1.21-1 · DF-S1.21-2 · DF-S1.21-3 · BL-17 · ADR-0316
- **Spec:** §5f (verification: claims, reconciliation, validators,
  critics, the completion gate) · ADR-0110 (the validator contract's
  `declare`/`bind`/`collect`/`check` ops) · ADR-0111 (conditioned rules
  carry assumption debt) · ADR-0114 D1 (the registered metric
  declarations) · ADR-0115 D5 (uncited findings) · ADR-0316
  (`verification.belief.probe` durable, `provisional` constitutive,
  strata never merged).
- **Rung (ADR-0024 obligation):** C0 — every deliverable runs at the
  offline/fixture ceiling; the judge port replays durable
  `model_io` records, never a live model.

## Context

R2.15 discharges the verification-plane residual: DF-S1.21-1's
`postconditions`/`diff_sanity` consumption (the environment-side legs —
the conditioned rule, the declared-postcondition runner, and
`Effect.postcondition_results[]` — landed at S2.11; the reconciliation
consumer was owed), DF-S1.21-2's out-of-process validator conformance
suite + computed-metric emission on live runs, DF-S1.21-3's
`CriticDeclaration{kind = judge}`-class binding where reachable over
recorded `model_io`, and ADR-0316's belief-probe emitters (the class
row was registered; the runtime firing was owed). Four design rulings
were the ticket's to make:

1. **How a declared postcondition's verdict reaches reconciliation.**
   The claim channel names effects and criteria; a declared
   `postconditions[]` validator is bound on the *capability*, so its
   verdict ids ride the effect row — never the claim's evidence list.
   Whether reconciliation sees those verdicts at all was undecided.
2. **What a belief `subject` names.** ADR-0316 made the record durable
   and `provisional` constitutive but left the subject spelling open.
   The model can name what it minted (its `tool_call_id`, an effect id
   it observed in context) — never the kernel's freshly allocated
   `ef-N` for a call still in flight.
3. **What a judge binding means under `offline-only`.** The
   `LoopPolicy.judged` detector + `JudgePort` seam landed earlier with
   no offline admissible binding; DF-S1.21-3 allows the honest half —
   binding over *recorded* `model_io` — or a typed deferral.
4. **Where computed metrics mint.** The ADR-0114 D1 declarations were
   registered and `evalfold::compute` landed; the durable
   `measurement.metric.emitted` class existed with no emitter call
   site on a real run.

## Decision

- **D1 — postcondition verdicts bind through the cited effect.**
  `fold_effect_states` lifts each `action.effect.observed` row's
  `postcondition_results[]` onto `EffectStateRow`; `bind_claim` admits
  a `verification.validator.verdict` row whose id a cited effect
  declared, beside the directly cited and in-contract-criterion paths.
  A failed declared postcondition on a cited effect is therefore a
  bound non-affirmative verdict: `claim_contradicted` gains the
  `(Achieved, Verdict{!affirmative})` arm and `c0_divergence_class`
  maps it to `UnverifiedVerification` — a claimed success the record
  contradicts is a divergence, never a silent pass.
- **D2 — `subject` spellings resolve against durable rows, never
  model text.** `effect:<id>` resolves the latest
  `action.effect.observed` scoped to the effect; `call:<tool_call_id>`
  resolves the same row two hops through the call's
  `intended`/`committed` `intent.tool_call_id` join (the model knows
  the call id it minted, not the kernel's `ef-N`); `verdict:<id>`
  resolves the latest `verification.validator.verdict` naming the id.
  The `observed_ref` is the durable `row:<event_id>` handle; unknown
  spellings, unmatched rows and absent members resolve `None` — the
  record keeps `observed_ref: null` and `divergent: false`, never a
  fabricated comparison.
- **D3 — `RecordedJudge` is the offline `Validator{kind = judge}`
  binding.** A `JudgePort` folded from the durable prefix: the latest
  `verification.validator.verdict`/`verification.critic.verdict` row
  per `validator_ref`/`critic_ref` at `detector = judged` supplies the
  replayed confidence (the row's explicit `confidence`, else a graded
  ppm `value`; a bool/lattice value records nothing). A bound
  `validator_ref` with no recorded judged verdict abstains —
  indistinguishable from `judge: None`, minting no hit and rendering
  no fabricated zero-confidence claim. The judged `stop` clamp stays:
  a judged detector is never sole grounds for stopping. The live
  `CriticDeclaration{kind = judge}` bound at `link` on live judge
  calls stays OPEN (DF-S1.21-3) — `offline-only` is the honesty
  ceiling.
- **D4 — metrics emit at `finish`, before `run.finished`.**
  `Driver::emit_computed_metrics` folds the durable prefix through
  `evalfold::compute` and appends one `measurement.metric.emitted`
  per registered ADR-0114 D1 metric in the typed ontology
  `MetricValue` form (`n/a{reason}` first-class — free-form fold
  reasons map onto the closed `NaReason` sum, defaulting to
  `observability`), `detector = deterministic`, `oracle_ref =
  oracle/evalfold`, `applies_to = run:<id>`. The rows land before
  `lifecycle.run.finished` so the finished row stays terminal.
- **D5 — the `declare` doc is a canonical render of the declaration,
  and the fixture runs the real semantics.** `declaration_json` in
  `hh-verification` is the one canonical render of
  `ValidatorDeclaration` (CC1); the `hh-plugin-fixture` `validator`
  mode drives the real `validators::declare`/`bind`/`build_bundle`
  over `plugin_abi/1` — the conformance suite exercises the true
  contract out of process, not a re-spelling of it (CC7). Contract
  failures answer in-band typed docs (`incomplete_declaration`,
  `validator_has_effects`, `payload_hash_mismatch`, evidence refusals)
  — distinguishable from a plugin crash (`op_failed`).

## Consequences

- A capability's declared postconditions are load-bearing end to end:
  declared → run per terminal (S2.11) → durable on the effect row →
  bound to claims → a contradiction diverges. `postcondition_results
  []` stays additive — an absent member means no declared checks, not
  a pass.
- Belief probes fire deterministically over *recorded* model output
  (`calls[].args_raw`); `judged` probe rules decode but never fire in
  the deterministic emitter — the strata stay separate per ADR-0316.
  A debtless `belief_probe` rule refuses `open`/`resume` typed
  (`MalformedProfileRule`) — a conditioned rule is never silently
  dropped.
- The offline judge binding is honest by construction: it can only
  ever answer what a durable judged verdict already recorded; it
  cannot fabricate a judgment, and its abstention is indistinguishable
  from no binding.
- Metric rows are replay-derivable (INV-9): `evalfold::compute` is a
  pure fold of the prefix, so the emitted values reproduce byte-
  identically on resume.
- Owned vocabulary is additive (CC8): the `call:` subject spelling,
  `row:<event_id>` observed handles, `DriverError::
  MalformedProfileRule`, the fixture's `--validator-*` flags.

## Alternatives considered

- **Binding postcondition verdicts only when the claim cites the
  verdict id.** Rejected: the claim channel names effects, not check
  internals — requiring the model to cite `verdict:diff_sanity:ef-N`
  would make declared postconditions unenforceable in practice, the
  exact hole DF-S1.21-1 names.
- **`subject` naming only `effect:<id>`.** Rejected: the model cannot
  know the kernel's freshly allocated `ef-N` for a call whose effect
  is still in flight; the `call:` join names the handle the model
  actually minted. A `latest`-style magic spelling was rejected as
  ambiguous under concurrent effects.
- **A live `StubJudge` fixture inside the driver.** Rejected: an
  in-process canned judge is a fabricated judgment wearing a port —
  the recorded replay is the honest `offline-only` binding; the live
  `link`-time critic binding stays deferred typed.
- **Emitting metrics in a post-finish sweep.** Rejected: appending
  after `lifecycle.run.finished` makes the terminal row non-terminal;
  inside `finish` keeps the run's event order honest and the fold
  deterministic.

## Revisit trigger

Reopen D2/D3 when a live judge or validator service is admissible
(the `offline-only` ceiling lifts — R2.21 or the environment-gated
critic tickets): `RecordedJudge` then composes with, never replaces,
a live `JudgePort`, and the subject spellings may gain a `handle:`
form for verbatim `EvidenceRef`s. Reopen D4 if metrics move to a
subscription/telemetry-driven emission — the `measurement.metric.
emitted` rows must then dedupe against the finish-time set.
