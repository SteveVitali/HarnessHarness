# ADR-0241: S1.10 compiler-crate rulings — crate shape, snapshot views, the canonical profile contract, the C0 family set, recorded-intent expiry, the closed failure set

- **Status:** Accepted
- **Date:** 2026-09-16
- **Ticket:** S1.10
- **Requirement ids:** R-2.1.3
- **Spec:** §3.2 (the C0/Stage-1 slice per §3.2.14) · ADR-0019/0020/0021/0022
  (as amended) · ADR-0025 D2 · ADR-0087 · ADR-0090 · ADR-0103 · ADR-0106 ·
  ADR-0124 §5 · ADR-0143 D2 · ADR-0148 · CF-049/CF-056/CF-199
- **Rung (ADR-0024 obligation):** **C0** — the single-machine, in-process,
  offline core; the compiler reads only declared inputs (no clock, randomness,
  environment, network or live registry).

## Context
S1.10 lands the §3.2 compilation model's C0/Stage-1 slice: stages 0 (accept),
1 (link), 2 (lower-native) and 5 (seal), `RuntimePlan/1`, `ModelProfile/1`,
the assumption-debt record, `SurfaceArgMap`/`EquivalenceEvidence`, the total
trace map, the static `lcd_report`, `derivation_key`/`bundle_id`, and the
`hh-compile` out-of-process seam. The spec fixes the stage table, the failure
taxonomy and the profile *shape* but leaves these concrete rulings to the
slice:

1. **How stage 1 reads profiles/variants without resolving.** §3.2.2 gives
   `link` a validated graph, profile refs and target refs; §3.3 owns every
   resolution. The compiler still must *read* bound profile records and
   pinned variants — the read seam needs a shape that cannot re-resolve
   (DF-S1.9-3's "zero resolutions" is structural, not a test hope).
2. **The `ModelProfile/1` member sets.** §3.2.3 fixes the closed
   `ProfileRule.kind` enum, the `CapabilityDeclaration` field list, and the
   `tests{…}` member. The implementation must carry the spec's sets verbatim —
   a hand-rolled enum is a second schema source (CC7).
3. **What a `tool_shape` rule may name at C0.** `tool_shape` selects a
   `SurfaceFamilyRef{family_id, variant_id}` **by id** (CF-199), but
   `SurfaceFamily` records are C1/Stage-5 registry kinds — the C0-admitted
   family set needs a declared ruling, not an open lookup.
4. **How "compiling under `expired` requires an explicit recorded intent"
   (§3.2.3/ADR-0020 §7) is expressed** in a pure function with no ledger to
   record into.
5. **The §3.2.10 failure set.** `TargetError` and `ProtocolVersionMismatch`
   have no stage-1 emitter — the closed set still must be *declared* (CC8) so
   a later emitter adds a site, never a new variant.

## Decision
- **§1 — one persistent crate `crates/hh-compiler`,** deps
  `hh-wire`/`hh-identity`/`hh-provenance`/`hh-ontology`/`hh-hir`/`hh-assembly`/
  `hh-registry` only (CC4/CC5 — no service, no implementation loading, no
  ambient state). `compile(inputs) → CompiledBundle` runs stages 0→1→2→5 over
  declared inputs only; `hh-compile` is the AC-CP-11/T-LCD-12 out-of-process
  seam (canonical `CompileInputs` bytes on stdin → canonical bundle or typed
  diagnostics on stdout; a non-zero exit on any refusal).
- **§2 — read seams are snapshot-confined views, never resolvers.**
  `ProfileView::profile(coordinate)` reads a `ModelProfile/1` by its bound
  coordinate; `VariantView::variant(version_id)` reads **only** by pinned
  `version_id` — the signature carries no selector and no resolver, so "zero
  resolutions" holds by construction (DF-S1.9-3, closed this run). `link`
  calls `hh_assembly::link_precheck` first and refuses any surviving
  `version_selector` as `C-LINK-1`/`LinkError{unbound_slot}`; the
  `CountingVariantView` test witness records that only pinned ids are ever
  requested.
- **§3 — the profile contract is the spec's, verbatim.** `ProfileRuleKind` is
  the §3.2.3 closed thirteen-kind set (`tool_shape, naming, schema_dialect,
  description_template, error_format, result_render, prompt_layout,
  interaction_mode, transcript_render, compaction_reminder, sampling_defaults,
  caching_markers, procedure_target`); `ProfileCapabilities` is the
  `CapabilityDeclaration` field list (`reasoning_replay{field, opaque}` typed
  as a record; `compatibility_token{value, provenance}` carried, never read
  as authority; measured bounds `context_window`/`max_output` as
  `Option<u64>`); `tests{…}` is a required `Json` member carried as data —
  the §5b compliance machinery owns its semantics at Stage 5. An earlier
  in-run draft invented its own kind set; the two-pass review caught it and
  the enum/codec were corrected to the canonical spellings — the gap table in
  `runs/S1.10.md` records the finding.
- **§4 — the C0 surface-family set is `["native_fc"]`.** At C0 the only
  compiled shape is the primitive `native_fc` family (§3.2.3: "C0 admits
  `interaction_mode = native_fc` only"; §5d: primitive surfaces are C0,
  `SurfaceFamily` records are C1/Stage-5). A `tool_shape` rule naming any
  other `family_id`, and a non-`native_fc` `interaction_mode`, are
  `UnexpressibleSurface` — an error, never a warning (AC-CP-05).
- **§5 — the recorded intent is a compile input.** `compile_for_expired: bool`
  is a field of `CompileInputs` — declared data inside the derivation, never
  an environment read. Expired/violated debt without it is
  `LinkError{missing_debt_record}` carrying the `C-LINK-6` diagnostics; with
  it the same diagnostics land as warnings and the rules list in
  `lcd_report.conditioned_rules` (T-LCD-05/AC-CP-06 Stage-1 half).
- **§6 — the §3.2.10 failure set is closed and complete in `CompileError`.**
  `TargetError` and `ProtocolVersionMismatch` are declared variants marked
  `#[allow(dead_code)]` — stage-3/4 emitters fill the *sites*, the taxonomy
  does not grow (CC8). `SealError{non_canonical}` is exercised now: stage 5
  re-encodes and re-parses the bundle and recomputes `bundle_id` before
  returning.
- **§7 — one identity primitive.** `derivation_key = idp/1` over the domain
  `compiler.derivation` (canonical inputs: definition `version_id`, bound
  variant `version_id`s, profile content hashes, target-spec versions,
  compiler version); `bundle_id = idp/1` over `compiler.bundle` (canonical
  outputs minus `bundle_id`); profile `content_hash = idp/1` over
  `model_profile.1` (record minus `content_hash`). No second hashing or
  canonicalization scheme (CC1).

## Consequences
- The sealed definition is the only stage-0 input; `accept_bytes` rebuilds it
  from canonical bytes so the out-of-process run exercises the same refusal
  path (AC-CP-01 byte-identity proven in-process twice and once through
  `hh-compile`).
- Stage-3/4 surfaces (`ModelSurface`, per-target artefacts, `lift`,
  `relower`) are absent by design; the bundle carries their slots as
  `ModelSurfaceState::Deferred`/empty maps so `bundle_id` covers the staged
  fields honestly.
- `E4–E6` evidence is staged `n/a{stage_3|open-world}` — never a false
  `pass`/`fail` (T-LCD-15); open-world capabilities record
  `n/a(open-world)` exactly.
- New obligations opened: DF-S1.10-1 (the §3.2.12 stage-3 acceptance halves —
  AC-CP-02/-06-retire/-09/-13 → S3.2).

## Alternatives considered
- **Resolving profile *names* at link (a `resolve_profile` call inside stage
  1).** Rejected — §3.3 owns every resolution; a resolver in the signature
  would make "zero resolutions" a testable hope instead of a type-level fact
  (DF-S1.9-3).
- **A C0 `ModelProfile/1` kind subset smaller than the spec's thirteen.**
  Rejected — `kind` is "a closed enum per profile-schema version"; landing a
  narrower set under the `/1` tag would be a silent dialect bump (CC8). The
  full set is admitted at the schema layer; only `interaction_mode` and
  `tool_shape` carry C0 expressibility checks.
- **Emulating `expired`-rule compilation with a warning always.** Rejected —
  ADR-0020 §7 requires an explicit recorded intent; a bare warning would let
  expired rules through silently.
- **Hand-rolling a second debt-record type for `HarnessRule.conditioned_on`.**
  Rejected — one CF-049 field shape across all homes (CC1); the profile
  record reuses it field-for-field.

## Revisit trigger
S3.2's stage-3/4 landing (the `ModelSurface`/`TargetArtefact` emitters fill
`TargetError`/`ProtocolVersionMismatch` and the deferred bundle members); the
§5b Profile Compiler (rule family, probes, chains beyond two levels — C1/Stage
5) growing `ModelProfile/2`; or a spec amendment changing the
`CapabilityDeclaration` list or the kind enum.
