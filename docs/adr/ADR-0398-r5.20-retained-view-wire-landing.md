## Context

Packet B admits the retained-view→wire seam across two owners: the
gateway's prepared call (R5.19 — `PreparedCall` ordering, landed)
and the embed render. The dossier's "before" named the gap exactly:
the render replays the durable prefix and so *resurrects* omitted
transcript — wire bytes could not be proven equal to the retained
selection. R5.18 landed the durable selection + `verify_selection`
replay; R5.19 landed the sealed ordering. This ticket owns the T2
integration the partition and the R5.19 split-review's B3→T2
boundary name: the render must serialize exactly the verified
selected view.

## Decision

1. **The latest `context.compaction.completed{selection}` member in
   the prefix is the authoritative retained view.** `GatewayModel`'s
   transcript render decodes it strictly
   (`RetainedSelection::from_json`) and replay-verifies it
   (`retained::verify_selection` — the production assess/propose/
   execute path, consumed unchanged). `Reproduced` is the only
   consumable verdict.
2. **The join key is the assembler's own `context_item_id`
   derivation** (`hh.embed.context_item/1` over the canonical
   observation payload — one `pub(crate)` constant shared by the
   runtime's mint and the render's join). An omitted item never
   re-enters the rendered observation join; the pair's call stays
   with the honest `no_observation_recorded` placeholder; items
   recorded after the selection render normally.
3. **A malformed record, an unknown/unbound variant, or a recorded
   selection the production path cannot reproduce is a typed
   `MalformedHistory` plan refusal** (`plan_error` → typed call
   failure — a "strategy label without execution" never dispatches).
   Resurrecting the view silently is the fidelity lie the spec
   forbids; refusing is the only honest posture. A memberless row
   leaves the legacy full-view render — fidelity is unavailable,
   never a treatment claim.
4. **`view_hash` (the landed §5b.1 member spelling) is stamped on
   `requested_members` when a selection informed the render** — the
   consumed member's own idp address, the same derivation
   `prepare` computes as `view_ref` over the same member, so the
   policy→selection→assembly→sealed-request→actual-wire join is
   byte-exact.

## Consequences

- The wire now carries exactly the verified retained view for both
  admitted native policies (`evict_oldest`, `clear_tool_results`),
  restart, retry and ladder fallback; the capturing-transport
  battery (`hh-embed/tests/r5_20.rs`) proves the joins byte-exact.
- A compaction recorded by an unadmitted variant produces a record
  the render cannot verify — subsequent calls refuse typed rather
  than silently resurrect (REQ-E-206's "unknown/unbound variants
  refuse").
- Fixture-verified only: the loopback provider captures literal
  socket bytes; no live-provider claim (ADR-0363). Actual provider
  execution, the R/P legs and actual-execution E stay owed to their
  named later owners per the coverage register.

## Alternatives

- Filter by event identity instead of `context_item_id` — rejected:
  the selection's durable identities are item addresses; a second
  derivation would fork the join contract (CC1).
- Render full view on an unverifiable record — rejected: silently
  claims no treatment ran (a fidelity lie) and resurrects omitted
  content.
- New event class / second serializer — rejected (B.7: the existing
  renderer is reused; the `model.call.requested` row gains only the
  already-admitted `view_hash` member).

## Revisit triggers

- An admitted additional compaction variant → extend the admitted
  set and the replay/render coverage.
- A live provider leg → the fixture-verified ceiling stands until
  the named live-evidence procedure runs.
