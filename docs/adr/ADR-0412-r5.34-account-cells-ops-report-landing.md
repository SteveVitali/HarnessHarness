- **Date:** 2026-11-03
- **Ticket:** R5.34 (Account refusal, exhaustion and operational reporting machinery)
- **Requirement ids:** none primary — contributing-only slice: REQ-B-105,

- **Spec:** docs/evidence-and-adoption-spec.md §5.2 (O6 reservation
  refusal, O7 exhaustion/drain cells) and §5.3 (counts, limits and
  verifyfixed); docs/tickets/204_R5.34__operations.md; design D3 F4
  O6/O7 and F5 counts; O3 partition packet (O6/O7 cells + fixed 8×3

- **Rung (ADR-0024 obligation):** implementation landing record — the
  O6/O7 evidence-cell vocabulary and folds and the §5.3 stage-count

  (one dev-dependency for fixture reach), no new event class, no

## Context

§5.2 and D3-F4 require two further operational cells beyond the landed
O1–O5/Kp4 apparatus (ADR-0410, ADR-0411): **O6** — a real Account with
zero remaining `model_calls` must refuse the reservation **before** any
independently observed transport entry or dependent mutation, on the
identical positive path O1 demonstrated reachable — and this refusal is
not terminal exhaustion; **O7** — an already-committed effect waits
behind a declared bounded barrier (bound set before execution,
observation intervals, fail-safe, grace = 0), the actual `time.wall_ms`
reaches the Account bound on durable-origin deadline inputs, new
dispatch is blocked, the committed claim drains to released/unknown,
the exhaustion/stop rows land, no marker lands after the stop, and
rebuild shows the committed/incurred work preserved — expiry before
commit is `unreachable`, never a pass. §5.3 and D3-F5 require the
reporting machinery those cells are counted by: the fixed 8×3 = 24
planned trials under a frozen seeded permutation with balanced controls
per block, the P→A→R→T stage fold plus V, the published ratios A/P,
R/A, T/R, V/T with a zero denominator `undefined` (never a fabricated
rate), the `[V/P,(V+U)/P]` planned-slot missingness bound (a bound, not
a confidence interval), O8's `detected/3` reported separately as
detector sensitivity rather than an invariant pass, all outcome kinds
retained (no post-outcome exclusions), at most one setup diagnostic
rerun per cell under a **new** identity with the original record never
replaced, a failed negative control blocking acceptance, and an
integrity/confinement/unexpected-destination/resource breach stopping
the matrix immediately. Before this ticket `ops.rs` had no Account
cell vocabulary and no report machinery at all.

## Decision

1. **`AccountFailure` — the O6/O7 closed negative set** (19 members:
   missing_observer, sentinel_mutation, same_path_unproven,
   missing_refusal, dispatch_on_refusal, dependent_mutation,
   exhaustion_mislabel, unbounded_barrier, committed_missing,
   expiry_before_commit, missing_deadline, unreached_bound,
   new_dispatch_after_stop, missing_drain, missing_stop, later_marker,
   duplicate_charge, committed_reverted, missing_detector). Every
   member blocks its cell; none launders a negative into a pass.
   `AccountOutcome` is `Pass` or `Failed(AccountFailure)`.
2. **`o6_outcome(&O6Cell)`** — the reservation-refusal fold. Required
   facts: observer present, sentinel intact, the identical positive
   reserve/dispatch path demonstrated reachable (O1 comparator —
   `SamePathUnproven` without it), the starved call's reserve refused
   durably (`control.budget.reserved{outcome:refused}` /
   `InsufficientBudget` on `model_calls`), **zero** independently
   counted transport entries on the refused call
   (`DispatchOnRefusal`), no sink delta/marker/`requested` dependent
   mutation, and no `control.budget.exceeded`/stop spelling — a
   refusal spelled terminal is `ExhaustionMislabel`: O6 is refusal,
   not exhaustion.
3. **`o7_outcome(&O7Cell)`** — the exhaustion/drain fold. Required
   facts in order: observer/sentinel; the barrier carried a declared
   bound + observation interval + fail-safe before execution
   (`UnboundedBarrier`); `expiry_before_commit` checked **before**
   every positive leg — the bound reached before commit is
   `ExpiryBeforeCommit`, the cell's unreachable precondition, never a
   pass; a committed fact (held reservation / durable request)
   preceded the barrier (`CommittedMissing`); a durable-origin
   deadline was actually enforced (`MissingDeadline`); the real
   `time.wall_ms` reached the bound (`UnreachedBound` — an
   armed-but-unreached condition cannot pass); new dispatch blocked
   past the bound (`NewDispatchAfterStop`); the committed claim
   drained — `released{release}`, terminal `failed{cancelled}` or a
   recorded `unknown` (`MissingDrain`); `control.budget.exceeded` +
   `control.decision{stop, budget_exhausted{time.wall_ms}}` landed
   (`MissingStop`); no marker appended after the stop
   (`LaterMarker`); no second `consumed` row for the same (source
   event, dimension) (`DuplicateCharge`); the rebuilt Account still
   shows the committed/incurred work (`CommittedReverted` — the drain
   never retroactively prevents committed work); required detector/
   count rows present (`MissingDetector`).
4. **The §5.3 report machinery is the cells' own fold.** `OpsCell`
   (O1–O8) + `OPS_CELLS`; `OPS_REPETITIONS = 3` (24 planned trials);
   `OPS_SETUP_RERUN_CAP = 1`. `TrialOutcome` retains every outcome
   kind — pass, defect_detected, refusal, tier_off, unreachable,
   missing_detector, timeout, oracle_failure, unknown, cancellation,
   failed — none dropped post-outcome. `TrialRecord` carries the
   invoked/boundary_observed/fully_observable/violation legs plus the
   negative-control flags. `OpsReport::plan(seed)` freezes the
   permutation: three repetition blocks, each a seeded Fisher–Yates
   over all eight cells (dependency-free splitmix64 `mix64`) —
   balanced controls per block by construction, identical
   inputs/backend except the declared condition.
5. **Append-only records; reruns get new identities.**
   `record()` refuses `ReportError::ReplacedOriginal` on a colliding
   trial id — the original row survives. `setup_rerun(cell, rep)`
   mints a new trial id (`o{cell}r{rep}s{n}`) for a planned slot only
   (`UnplannedTrial`), capped at one per cell
   (`SetupRerunCapExceeded`); the failed original's retained row
   stands. `integrity_stop` records the first breach reason;
   `acceptance_blocked` is true on a stop or any failed negative
   control.
6. **Honest counts.** `counts(cell)` folds P/A/R/T/V over retained
   records; `stage_ratio` publishes ppm or
   `Ratio::Undefined{zero_denominator}` — a zero denominator is never
   a rate; `missingness_bound` emits `[V/P, (V+U)/P]` with
   `U = P − T`; `o8_detected` reports `detected/3` separately
   (detector sensitivity, not an invariant pass). `render()` emits
   `ops_report/1` — per-cell counts, the four published ratios, the
   bound, outcome tallies, the O8 detector line, and the stop/
   acceptance-blocked flags.
7. **The battery drives the real seams.** `tests/r5_34.rs` runs real
   Store/WAL + `ManualClock` + real `Account` (root + instrument
   budgets) + the landed `prepared` transport path behind a counting
   diagnostic `Transport` (independent entry observation) +
   `MarkerSink`/`Sentinel`/`OpsObserver` from R5.32's apparatus:
   O6 — funded positive path completes → `model_calls` remaining 0 →
   second call `Unfunded` + durable `reserved{refused}`, zero
   transport entries, no mutation/exhaustion rows; O7 — committed
   reserve behind declared barrier (5 s bound / 1 s observations /
   10 s fail-safe, grace = 0) → durable-origin deadline reached →
   `DeadlineExpired` zero sends → `released{release}` drain → new
   prepare refused → elapsed wall charged → `check` exceeded →
   `exhaust` lands exceeded+stop; rebuild + reopened-WAL preserve the
   committed work; replayed `charge` adds no second `consumed` row.
8. **`hharness-gateway` dev-dependency** on `hharness-env` — fixture
   reach only (the counting `Transport` impl sits beside the prepared
   plan's wire types). Dev-dependencies do not ship; `cargo tree`
   shows env absent from gateway's normal graph; the removability
   edge checks exempt dev-deps by construction.

## Consequences

- The O6 refusal cell proves a starved reservation fails **before**
  transport — the independently counted entries are the comparator;
  a refusal spelled as terminal exhaustion is a named defect, not a
  pass.
- The O7 cell's precondition is honest: expiry before commit is
  `unreachable`/failed, an armed-but-unreached bound cannot pass, and
  the drain must preserve committed work on rebuild.
- The stage-count report is falsifiable: append-only records, capped
  new-identity reruns, zero-denominator `undefined`, a missingness
  bound that never pretends to be a confidence interval, and O8 kept
  separate as detector sensitivity.
- `pub mod ops` stays a read-only internal instrument — no RPC,
  schema, production dependency or event-class admission. Actual
  24-trial live execution remains gated to R5.44; these fixtures
  cannot close it.

## Alternatives considered

- **A shared `Pass`/`Fail` outcome enum across O1–O8** — rejected:
  each cell family's failure vocabulary is its own closed set
  (`TrialFailure`, `PermissionFailure`, `AccountFailure`); collapsing
  them would launder the named negatives the ACs require.
- **Letting the rerun replace the original record** — rejected:
  §5.3 requires a new identity and no replacement; keeping the failed
  original preserves P and the failure evidence.
- **Confidence-interval missingness reporting** — rejected by the
  spec: `[V/P,(V+U)/P]` is a planned-slot bound, not an interval;
  `Ratio::Undefined` keeps zero denominators honest.
- **Splitting the report machinery from the O6/O7 cells (the ruled-on
  apparatus-vs-battery proposal)** — rejected by the 2026-11-03
  scoped review (`planning/2026-11-03_R5.34-split-review.md`): the
  O3 packet binds cells + seeded permutation + reporting to one owner
  working set in one scope sentence; the report is the AC-1/AC-2
  evidence fold for every cell (OpsReport enumerates OPS_CELLS and
  folds their TrialRecords — the §5.3 acceptance surface, same shape
  as R5.23's `assemble_receipt`); ops.rs has zero `#[cfg(test)]`, so
  leg (a) would land an instrument exercised by nothing while leg (b)
  alone ~1,163 lines still crosses the ≤800 trigger — a non-curative
  impl-vs-battery cut.

## Revisit triggers

- If `AccountFailure` grows members or the O6/O7 evidence spec
  changes (barrier bounds, drain vocabulary, charge reconciliation),
  re-read the folds — the closed set and the battery must move
  together.
- If the §5.3 report contract changes (permutation construction,
  ratio set, rerun cap, outcome vocabulary, `ops_report/1` members),
  re-read `OpsReport` — counts and renders must move with it.
- If `OpsCell`/the seeded permutation gains a cell or repetition,
  re-read `OPS_CELLS`/`OPS_REPETITIONS`/the O8 `detected/3`
  denominator — the 8×3 shape is load-bearing in every fold.
- If `ops` ever gains write/dispatch authority, re-read ADR-0410's
  read-only confinement — the Account folds and the report inherit
  it unchanged.
- If the `hharness-gateway` dev-dep edge is repurposed (a production
  dep, a second fixture consumer), re-read the acyclicity argument —
  dev-deps do not ship but a production edge would invert the layer
  direction.
