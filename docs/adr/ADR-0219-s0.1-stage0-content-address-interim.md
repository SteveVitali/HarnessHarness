# ADR-0219: S0.1 Stage-0 content address is an interim for idp/1

- **Status:** Accepted
- **Date:** 2026-09-15
- **Ticket:** S0.1
- **Requirement ids:** R-2.11.4⁰ᵃ
- **Spec:** §7.4 (`schema_hash: ContentAddress over the canonical schema export (idp/1)`);
  ADR-0036 (research, identity/canonical form); inherited under ADR-0212 (Stage 0–1 deferral)

## Context
§7.4 specifies `ContractIdentity.schema_hash` as a **ContentAddress over the canonical schema
export in `idp/1` form**. The `idp/1` canonical form and the `ContentAddress` type (ADR-0036,
ADR-0029) are landed by ticket **S1.2** (identity/versioning) — they do not exist at Stage 0. S0.1
still needs a stable, verifiable content address for `schema_hash` so `hello` negotiation and the
drift check are real.

## Decision
At Stage 0, `schema_hash = "sha256:" + hex(SHA-256(canonical_schema_bytes))`, where
`canonical_schema_bytes` is the sorted-key, compact, integers-only JSON serialization of the
schema export (`hh-wire::json`). SHA-256 is implemented in pure std with NIST known-answer tests.
This is an **interim** realization of the `idp/1` ContentAddress: same role (a deterministic
content address that pins the schema), Stage-0 canonicalization. It is recorded as a DEFERRALS row
(V/D) so the migration to the `idp/1` canonical form is tracked and verified when S1.2 lands.

## Consequences
- Good: `schema_hash` is a genuine, test-covered content address now; negotiation and drift are
  not stubbed.
- Cost: when `idp/1` lands (S1.2), the canonicalization (and therefore the hash value) changes;
  every checked-in `EXPECTED_SCHEMA_HASH`/`schema.json` is regenerated then, and the migration
  must confirm the Stage-0 hash is superseded (not two coexisting schemes — CC1).

## Alternatives considered
- **A placeholder/zero hash until S1.2.** Rejected: it would make `hello` negotiation and the
  SchemaMismatch path fabricated rather than real, violating "mismatch is typed, never silent".
- **Adopt a full RFC 8785 JCS canonicalizer now.** Rejected: premature — `idp/1` (ADR-0029/0036)
  is the owning decision and lands at S1.2; a second canonicalization scheme here would risk a
  CC1 violation. The Stage-0 form is deliberately minimal and clearly labelled interim.

## Revisit trigger
When S1.2 lands the `idp/1` canonical form and `ContentAddress` (ADR-0036): migrate `schema_hash`
to derive from `idp/1`, regenerate the pinned artifacts, close the DEFERRALS row, and confirm no
second canonicalization scheme remains (CC1).
