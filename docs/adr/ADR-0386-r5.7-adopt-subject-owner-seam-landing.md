# ADR-0386: R5.7 adopt-subject — `adopt_subject*` owner-seam landing decisions

- **Status:** Accepted
- **Date:** 2026-11-02
- **Ticket:** R5.7
- **Requirement ids:** REQ-E-201, REQ-C-103 (primary; merged aliases REQ-E-001/101)
- **Spec:** docs/evidence-and-adoption-spec.md §2.1/AC-2-1; PADR-R5-1 (admitted GATE-G9, packet A — A.2 owner map, A.3 payload homes, non-admission ledger); ticket docs/tickets/176_R5.7__adopt.md
- **Rung (ADR-0024 obligation):** implementation landing record — the admitted `adopt_subject(binding, environment, ports)*` in-process owner interface's concrete shape on `hh-embed` arming/drive; no RPC, no wire/schema change, no new event class

## Context

GATE-G9 admitted PADR-R5-1: `adopt_subject(binding, environment,
ports)∗` — the embed arming/drive seam that reuses the existing runtime,
one subject and the current fenced writer; stale/duplicate/mismatched
adoption refuses. The dossier's non-admission ledger fixes the surface:
an in-process owner interface, **never a public RPC**; adoption facts
extend existing lifecycle/binding payloads; no new event class. The
seam's signature, validation order, writer mechanics and durable record
are the landing ticket's decisions (AC-1/AC-2 of
`docs/tickets/176_R5.7__adopt.md`).

## Decision

1. **In-process Rust seam, no boundary op.** `EmbedService::adopt_subject(
   AdoptBinding, &EnvironmentInput, &AdoptPorts)` in
   `crates/hh-embed/src/adopt.rs` — a `pub` library call for the
   `hharness` recipe (I-02: the recipe orchestrates; kernel semantics stay
   behind the existing boundary). `AdoptBinding{experiment_run_id,
   run_plan_id, binding: &LaunchBinding, subject_writer}` presents the
   claim; `AdoptPorts{host_caps}` declares the surfaces (the same shape
   `supplies.host_capabilities` realizes); `AdoptOutcome` returns the
   session, binding join, writer generation, armed mode and head cursor.
2. **Re-read the durable record, never trust the presentation.** The
   presented `LaunchBinding` must equal `launch_binding(run_plan_id)`'s
   fold — the admitted R5.6 reader. Adoption runs the *same*
   `ExperimentView::fold` read-only (the reader's own projection) so the
   check never takes the experiment run's writer — a recipe's live engine
   holder is never fenced for a read. Mismatch, absence or a non-`bound`
   phase is `adopt_stale_binding`/`adopt_binding_not_bound`.
3. **Validation is read-only until `renew`.** run (`has_run`,
   `run_kind`, no `lifecycle.run.finished`), plan/attempt/config (the
   subject's launch-stamped `measurement.experiment.bound` row — the
   bound record's own proof; the frozen `inputs` live only on the
   intent-phase row), root (parentless `control.budget.allocated` ==
   `subject_root_budget_id`), environment (any prior
   `action.environment.declared` must re-derive the same
   `{class, resolved image}`), generation and duplicate (no live writer
   session) are all checked against the durable prefix and the in-memory
   session table *before* the first mutation. Every refusal is typed
   (`Refused{adopt_*}`) and lands before any subject-run write.
4. **`renew` is the writer check.** `store.renew(subject_writer)` proves
   the exact `lease_id + generation + unexpired` against the durable
   lease record and extends the TTL — a fenced/expired/superseded writer
   is `adopt_writer_stale` with no subject-run mutation; the session then
   writes through the *same* lease (one subject, one writer — never a
   second writer minted).
5. **Environment once.** A never-provisioned subject runs the one
   `provision_environment` path (durable `declared/provisioning/
   provisioned/attached` rows); a run carrying a matching declared env
   reuses the durable record (env handle id recorded, `env_json` null —
   `open_resume`'s durable-resume posture) and never mints a second
   environment.
6. **`lifecycle.session.attached{mode:"adopt"}` is the adoption fact.**
   The existing class gains `intent_ref`/`run_plan_id`/`attempt_no`
   members — dossier A.3's "adopt facts extend existing lifecycle/
   binding payloads; prefer extensions over new classes" (CC10: no new
   class, no class-table change).
7. **Arm or resume by the persisted leaf pair.** `leaf.arm` +
   `leaf.checkpoint` present ⇒ `arm_resume_driver` (`armed:"resumed"`);
   else `arm_driver` (`armed:"armed"`) with the smallest supported
   composition: `driver_surfaces(ports.host_caps)`, `hh/react-minimal`
   control, `static` compute, no sealed definition, no budget input, the
   scripted `EmbedModel` lane, the `context.memory` fold rebuilt from the
   durable prefix. Absent capabilities (no `harness_def_ref`, no router/
   model_port lane, no supplies) stay typed refusals downstream — never
   fabricated.
8. **Session construction mirrors `open_new`/`open_resume`** — the same
   `SessionState`, `persist_leaf`, `KernelContext::fold` and realized
   settings from the subject manifest; no second runtime, no copied
   driver.

## Consequences

- The recipe's adoption path is `launch → adopt_subject → submit/drive/
  close` through the existing ops; R5.8's `DurableEffectRef*` consumes
  the adopted driver's effect lifecycle (contributing evidence, not
  claimed here).
- A re-adoption while a live writer session drives the run is
  `adopt_duplicate`; a post-restart adoption resumes the persisted leaf
  and reuses the durable environment — no second run, second writer or
  second environment ever results.
- Validation folds read the durable prefix directly; nothing about the
  experiment run's writer is touched for a read.

## Alternatives rejected

- **New RPC or event class for adoption** — barred by the dossier's
  non-admission ledger (in-process seam; payload extension only).
- **`acquire_writer` for adoption** — would fence the launch's own
  `subject_writer` and mint a second writer; `renew` validates and keeps
  the single writer.
- **Engine-bound `launch_binding` call** — `attach_run` takes the
  experiment-run writer for a pure read; the identical fold is run
  read-only instead (`WouldBlock` on a live recipe engine avoided).
- **Validating against the intent row's `inputs`** — the bound record
  the reader projects carries `inputs: Null`; the subject's own `bound`
  row is the durable proof of the frozen coordinates.

## Revisit trigger

- If a later owner (R5.8 `DurableEffectRef*`, R5.14 pending) needs
  adoption to join the effect/settlement lifecycle, revisit the session
  record members — not the seam shape.
