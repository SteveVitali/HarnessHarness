# ADR-0286: S3.9 protocol-edge rulings

- **Status:** Accepted
- **Date:** 2026-09-24
- **Ticket:** S3.9 (`055_S3.9__tool-protocol-edges.md`)
- **Requirement ids:** R-2.5.4⁰, R-2.5.2⁰, R-2.5.3 (S3 slice)
- **Spec:** §5d.4 (protocol edges) · §5d.2/§5d.3 (S3 slices) · owning ADRs
  ADR-0087…0102 · ADR-0146 D2 · ADR-0092 D5 · ADR-0021 D5

## Context

S3.9 lands the Stage-3/C0 protocol edges: `import_listing`/`refresh` for
`mcp_listing`, `sync_source`/deltas/`freeze`/`unavailable`/`adopt`, the
dual-era probe-first MCP stdio client, the stateless MCP server,
`ProtocolBinding`, the E5 distinguishability battery, the
`attribution_completeness` veto, helper-overhead distributions, and the
minimal profiles' `edit_file` primitive shapes. The ticket owned these
rulings:

1. **How negotiation orders the two MCP eras.** §5d.4 requires
   probe-first negotiation that never silently downgrades below the
   pinned supported version; the era set and the refusal spelling are
   this ticket's.
2. **What a foreign listing's declarations carry.** Foreign metadata is
   unverified by construction; the question is which members ride
   `_meta` home and which are declared losses.
3. **Which rows a `SurfaceFailure` produces at each detection site.**
   §5d.2 ledgeres every `SurfaceFailure` as `action.tool.surface_rejected`;
   §5e.2 ledgeres malformed/unknown-surface output as
   `control.output.rejected`; the two spellings overlap on
   `unparseable`/`unknown_surface` and the emission split needed a
   ruling.
4. **What `attribution_completeness` reads.** AC-R-2.5.5-1 names two
   surfaces — model-call cost coverage and security-signal attribution
   (`action.effect.unattributed`) — and both must feed the veto.
5. **How AC-E3-6's provider lift-back lands when the provider target is
   lift-less.** ADR-0021 D5 rules `provider_tool_api` consumed-by-model
   (no lifting contract); the AC's round-trip arm needed a home.
6. **Which AC-E3 halves need run machinery that does not exist at C0.**
   The cache-token arm of E3-4, the form-variance arm of E3-5, the
   per-call `activated` arm of E3-7, and the `input_required`
   run-mapping arm of E4-12 all touch emitters/executors the turn loop
   does not yet wire.

## Decision

1. **Negotiation is probe-first with a pinned era set.**
   `McpClient` probes `server/discover` before any other request; the
   legacy era (`2025-06-18`, no `server/discover`) is entered only after
   the probe's typed refusal, and any negotiated version outside the
   pinned set `{2026-07-28, 2025-06-18}` refuses
   `ProtocolVersionMismatch` — never a clamped downgrade. Each session
   mints a `ProtocolBinding{protocol, role, spec_pin, era,
   negotiated_version, peer, declared/observed capabilities,
   extensions, transport, negotiation_event_ref}`.
2. **Imports are quarantined at `unverified` with `unknown_domain`
   effects.** `import_listing`/`refresh` register every lifted
   declaration `admission = quarantined`, `authority = unverified`;
   `unknown_domain` projects the worst risk class until `seal`
   (ADR-0031 §2). Declared hints ride `source.declared_claims`
   verbatim — a foreign `readOnlyHint` is *recorded*, never read, so the
   default-policy decision stays `ask` (AC-E4-3). A listing's `pin`
   over `listing_hash` never transfers to the imported records; refresh
   mints `supersedes{edit}` versions and `verify_resume` reports
   `capability_changed_under_run`. Own-export import recovers the
   carried `_meta` set with a loss report naming exactly
   `{cost_model.measured_ref, execution_requirement, exposure_hint}`.
3. **`sync_source` is the single delta/adopt path.** All six
   `SyncTrigger`s run `listing → CatalogEntry[] → catalog_delta →
   adopt`; `freeze` keeps `catalog_id` and marks removed entries
   `unavailable("removed")`; `adopt` opens a new epoch stamping imported
   surfaces `authority = unverified`.
4. **`action.tool.surface_rejected` fires at both detection sites.**
   Monitor/arg-eval failures (`unmapped_argument`, `domain_violation`)
   emit the row at dispatch (no `Effect`, no executor). Parser-detected
   classes whose spelling the two closed sums share (`unparseable`,
   `unknown_surface`) **dual-emit**: `control.output.rejected` keeps the
   §5e.2 format-failure accounting (`format_failures_running`,
   `stop{format_failure}`) and `action.tool.surface_rejected` is the
   action-plane span terminal carrying the §5d.2 payload. The §5e.2-only
   classes (`schema_violation`, `constraint_violation`,
   `precondition_violation`, `truncated`, `refusal`, `empty`) are not
   §5d.2 spellings and emit the control row alone — no spelling is
   re-mapped (a fabricated mapping would lie about the closed sum). On
   a never-bound call `binding_ref` carries the surface name the model
   attempted; the member is mandatory and the attempted name is the
   honest would-be ref. Rejected bytes never ride either row —
   `raw_call_hash`/`detail_ref` are content addresses (ADR-0066 Rule C).
5. **`attribution_completeness` reads both attribution surfaces.** The
   denominator is completed `model.call.attempt.completed` rows; the
   numerator counts `measurement.cost.attributed` coverage, and any
   `action.effect.unattributed` signal marker trips the veto outright
   (the marker survives the `ledger_facts/1` round trip — a reloaded
   run still trips, CC3). The veto runs in `evaluate_vetoes`; tripped
   ids land on `EvalRun::veto_tripped` and the scorecard counts the run
   as success-with-veto — excluded from the headline cell, counted
   beside it (ADR-0045 D6). `0/0` is `n/a`, never `0`.
6. **AC-E3-6's lift-back arm executes on `mcp`; the provider artefact
   discharges its half by record.** `lift` on `provider_tool_api` stays
   the typed refusal ADR-0021 D5 declares (T-LCD-11 is discharged by the
   loss report + the T1–T7 `normalization.name_to_semantic_id` map —
   the surface→semantic identity the response path needs). The landed
   executable pins: a surface admitting `{direct, deferred}` is *not*
   unexposed (only an all-deferred meet drops `unexposed{deferred}`),
   the provider artefact carries the surface with its identity map, and
   the lift∘lower ∪ loss_report round trip runs on `mcp` under both
   minimal profiles (AC-E4-1). The S-386 revealed-deferred provider
   regression stays with DF-S1.17-1.
7. **Four AC arms defer to the rows that already own their machinery.**
   AC-E3-4's cache-read-token arm and AC-E3-7's per-call `activated`
   (and the `delivered{artefact_id = surface_id}` tool-surface bridge)
   need the exposure-aware turn loop — DF-S1.17-3's emitter wiring.
   AC-E3-5's regex-vs-natural-language *form* arm needs a discovery
   surface family — at C0 only `native_fc` compiles
   (`crates/hh-compiler/src/link.rs`); DF-S1.17-1 owns the form fixture.
   AC-E4-12's run-mapping arm (`input_required` → non-terminal effect +
   `control.decision{ask}` + `message_human` + same-`effect_id`
   `attempt_no + 1` retry) needs an MCP-backed executor in the dispatch
   path — none exists at C0 and quarantined foreign tools never
   dispatch — recorded as DF-S3.9-1. Every deferred arm's executable
   half is landed and pinned in this ticket.
8. **`harness_overhead.execution_ms` is a declared distribution, not a
   scalar.** `action.tool.completed` carries
   `{execution_ms, executor_class, isolation_class}`; the catalogue row
   folds to per-stratum distributions and renders typed `n/a` on empty
   strata (never a fabricated zero).

## Consequences

- AC-R-2.5.1-{4–6,9,11,12}, AC-R-2.5.2-{6,7,11},
  AC-R-2.5.3-{4,5,6,9}, AC-R-2.5.4-{1–4,8,9,11,12} all have executable
  halves in-tree (`hh-mcp` 7, `hh-registry` 9, `hh-compiler` 9,
  `hh-eval` 5, `hh-telemetry` 2, `hh-env`/`hh-control`/`hh-embed` run
  rows).
- `surface_rejection_rate`'s numerator now counts both detection sites;
  the metric's computation stays `NotComputed` (AC-R-2.5.2-12 is not
  this ticket's row).
- AC-E3-7 and the E3-4 cache arm remain `OPEN` under DF-S1.17-3 /
  DF-S1.17-1 with the landed halves noted; DF-S3.9-1 opens for the
  `input_required` run mapping.

## Alternatives considered

- **One row per failure, not two.** Rejected — §5d.2 and §5e.2 both
  name their classes; dropping `control.output.rejected` breaks the
  format-failure fold and AC-R-2.6.2-5, dropping `surface_rejected`
  breaks the §5d.2 span terminal and `surface_rejection_rate`'s
  numerator. Dual emission is the only reading that satisfies both.
- **Re-spell §5e.2-only classes into `SurfaceFailure` members.**
  Rejected — the sums are closed; `schema_violation` is not a §5d.2
  spelling and re-spelling fabricates a mapping the spec does not
  declare.
- **Implement `lift` for `provider_tool_api` to satisfy AC-E3-6
  literally.** Rejected — ADR-0021 D5's ruling is deliberate (the
  artefact is consumed by the model; there is nothing to recover that
  the loss report and normalisation record do not already declare).
- **Emit `activated` for tool calls from `dispatch` now.** Rejected —
  the T-LCD-13 chain for surfaces joins on `delivery_id`s the exposure
  bridge does not yet produce (DF-S1.17-3); emitting a half-joined row
  would mint an unverifiable record.

## Revisit trigger

The exposure-aware turn loop lands (DF-S1.17-3's emitters), an
MCP-backed executor enters the dispatch path (DF-S3.9-1's unblocking
ticket), or a discovery `SurfaceFamily` beyond `native_fc` compiles —
each deferred arm's verification column then runs.
