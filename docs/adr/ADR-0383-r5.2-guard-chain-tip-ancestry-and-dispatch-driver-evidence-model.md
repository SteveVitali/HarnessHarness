# ADR-0383: Guard chain-tip ancestry repair + guarded dispatch-driver evidence model

- **Status:** Accepted
- **Date:** 2026-10-30
- **Ticket:** R5.2
- **Requirement ids:** REQ-H-008 (primary), REQ-H-001, REQ-H-005, REQ-H-011 (context)
- **Spec:** docs/evidence-and-adoption-spec.md §9.4–9.5, AC-9-2; ticket docs/tickets/170_R5.2__dispatch.md AC-1/AC-2
- **Rung (ADR-0024 obligation):** non-contract build-tooling record (no contract schema, wire or runtime semantics); extends ADR-0382 under its revisit trigger

## Context

R5.2 must prove the actual guarded native dispatch and resume path: the
retained guard (hh-supplement-guard/1) must causally pass before any launch
and after the boundary/state transition, with ordered calls, counts, versions
and input identities retained. Two gaps surfaced at execution:

1. The R5.1 guard's `chain-tip` check asserted literal equality between
   `chainTip` and `buildBranchBase`. Equality holds only before the first
   stacked ticket lands; after R5.1's closeout advanced `chainTip` to
   `codex/harnessharness-evidence-r5.1` the guard failed on the exact state it
   exists to approve (route `DISPATCH R5.2`, verdict `FAIL`). The stock ledger
   convention and every stock fixture keep `buildBranchBase` immutable while
   `chainTip` advances per landed ticket, and §9.4's "forks-from/base agrees
   with verified chain tip" means consistent ancestry, not identity.
2. The launch path itself had no executable proof: orchestrate-build's
   `dispatchTarget: subagent` route was documented but never driven or
   rejection-tested on this harness (Devin Desktop `run_subagent`, callable
   only by the root coordinator; worker nesting depth is 1).

## Decision

1. **`chain-tip` semantics repaired to ancestry** in
   `docs/build/tools/supplement_guard.py::check_git_ancestry`: both refs must
   resolve and `git merge-base --is-ancestor <buildBranchBase> <chainTip>`
   must hold (equality is the degenerate pre-first-ticket case);
   `pinnedBaseSha` must still be a 40-hex sha and an ancestor of `chainTip`.
   Non-git roots degrade to the recorded note-skip as before. Reviewed,
   recorded extension only — no check family, schema, version or diagnostic
   code was renamed; the 13-case R5.1 battery stays green (13/13).
2. **Fixture honesty repairs (BM-TEST-01):** the `old-gate-g1` fixture patch
   no longer pins the living `nextTicket` value (it derives it), and the
   R5.1 runner's diagnostic matcher is fixed-string (`grep -F "[$expected]"`)
   — a bracketed pattern matched as a character class could satisfy a case
   with the wrong diagnostic.
3. **`hh-dispatch-driver/1` v1.0.0** (`docs/build/tools/dispatch_driver.py`):
   `plan` performs the ordered preflight — `dispatch-target` = `subagent`,
   guard invoked and required `PASS` + `DISPATCH` route, independent
   chain-tip/base ancestry, recorded `ci-boundary/1` read for the previous
   ticket's PR (missing is never green), first-eligible-row resolution — then
   emits one `hh-dispatch-envelope/1` (primitive `run_subagent`, profile
   `subagent_general`, title, prompt, recorded guard digests/counts/versions,
   expected base sha, transcript contract) inside `hh-dispatch-decision/1`,
   or refuses with named diagnostics and emits nothing. Each gate is
   independently load-bearing (single-point neutering flips EMIT).
4. **`hh-dispatch-transcript/1` + `validate`:** the coordinator executes the
   envelope on the native primitive and returns the transcript; `validate`
   requires `guard.pre` before the spawn and `guard.post` after the
   transition (pre/post digests identical), the contracted spawn count,
   prompt/profile/row identity by sha, an answer per spawn (no-progress is
   not a launch), `tree_status: clean`, writes confined to the named report
   path, `spend_usd: 0`, and for the resume leg a `ledger_reread` before the
   resumed stub acts. An absent or mocked guard leg is `guard-required` —
   documentation-only evidence is a failure.
5. **Stub legs are coordinator-executed.** Nesting depth 1 makes the literal
   spawn a coordinator action; this ticket emits the exact stub envelopes
   (harmless, read-only prompts; report under the gitignored `docs/build/logs/`),
   the coordinator runs them, and the transcripts are validated before close.
   Refusal classes are proven without any spawn on mutated inputs.

## Consequences

- The guard now holds on every stacked state, not only the pre-first-ticket
  one; `chain-tip` fires when the tip does not descend from the build base
  (a real stale-base signal), `git-ancestry` when the pinned sha is not an
  ancestor.
- Every dispatch boundary gains an executable, replayable contract: envelope
  bytes + transcript + validation record are the evidence DF-R5.1-1's
  GATE-G17 readout collects (guard invocation counts/versions/digests at real
  boundaries, zero-dispatch for old GATE-G1, refused pending/failed states).
- Fixture sandboxes get real git refs so ancestry legs run rather than skip.
- The driver is a proof harness, not a second orchestrator: it never mutates
  build state and emits only envelopes a coordinator chooses to execute.

## Alternatives considered

- **Keep literal `chainTip == buildBranchBase`.** Rejected: it makes the guard
  unusable for its stated purpose on every post-first-ticket boundary and
  contradicts the stock ledger convention and §9.4.
- **Advance `buildBranchBase` per ticket instead.** Rejected: the field is
  the immutable setup base by convention; mutating it would falsify history.
- **Headless/headless-CLI launch path.** Rejected for this proof: the ledger's
  admitted route is `dispatchTarget: subagent`; switching would need its own
  scoped integration decision (and `--max-iters 1` bounding per §9.4), which
  this ticket does not authorize.
- **Simulated/mock spawn inside the worker.** Rejected: AC-1 requires the
  actual selected native path; a mock cannot evidence `run_subagent`.

## Revisit trigger

Reopen if the ledger state schema renames `chainTip`/`buildBranchBase`, the
manifest kind or CURRENT STATE key sets change, a different dispatch tier is
admitted for the round (`dispatchTarget`), the native primitive/profile set
changes, or `hh-dispatch-transcript/1` needs fields a real coordinator leg
cannot supply — the schema then bumps to `/2`, never a silent edit.
