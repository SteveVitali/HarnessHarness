# ADR-0247: S1.14 sink-policy and export rulings — the L0–L3 content-class sum, `SinkPolicy` invariants, sampling discipline, and the export lowering shape

- **Status:** Accepted
- **Date:** 2026-09-17
- **Ticket:** S1.14
- **Requirement ids:** R-2.9.1
- **Spec:** §5h.1 §2.4/§3/§6 · ADR-0044 D1–D6 · ADR-0042 D3/D4 ·
  ADR-0057 (secret redaction upstream and unconditional) · ADR-0061
  (sinks are `net_egress` destinations)
- **Rung (ADR-0024 obligation):** **C0** — MUST-code: `SinkPolicy`
  validation, the export lowering (`export_view`/`export_events`/`deliver`)
  and the consent gate are §5h.1 §2.4 inside-list items; `ContentClass`,
  `SinkPolicy`, `Sampling`, `TelemetryLossReport` and the catalogue rows
  stay MUST-data.

## Context
The spec fixes the content classes (L0 accounting / L1 structural / L2
content / L3 diagnostic), the `SinkPolicy` field list and the invariants —
a sink without `content` never sees a byte of a `ContentAddress` payload,
`content` requires consent, sampling never touches the ledger and never
feeds a `metric_view` — but leaves these concrete rulings to the slice:

1. **How `content_classes` is checked.** `content_classes` is a *set* over a
   closed sum; the spec's invariants are set-theoretic (`content` ⇒ consent,
   `content` + `diagnostic` disjoint, `accounting`-only ⇒ scalars and
   bucketed magnitudes). The policy type must make invalid combinations
   unrepresentable-at-construction, not catchable later at export.
2. **What sampling may govern.** Sampling below `all` is refused for the
   ledger and for any sink a `metric_view` is computed from — but *export*
   sampling of trace spans is legitimate. The boundary must be enforced at
   the policy and at the export path, and dropped spans must appear in the
   loss report.
3. **Where `max_field_bytes` truncation lands.** Truncation is a lowering
   decision: the sink's byte budget applies at export, not at append (the
   ledger already stores canonical payloads; the blob store owns large
   content). The truncation must be *recorded* per field.
4. **What `deliver` appends.** `measurement.export.delivered` is the only
   ledger append an exporter may make; it must carry `seq_range` and
   `loss_report_ref` so `audit_view`'s `sink_deliveries` half can reconcile
   deliveries against the durable prefix.
5. **How the catalogue's applicability is expressed.** §8 names ~45 process
   metrics; each declares `requires_observability`,
   `applies_to_classes`/`computed_from` event classes and a unit. Rows whose
   classes don't exist yet must be *declared pending*, not absent (CC8), and
   must fail `registry_check` loudly if they under-declare observability.

## Decision
- **§1 — `ContentClass` is the closed L0–L3 sum** (`accounting`,
  `structural`, `content`, `diagnostic`) with a strict codec;
  `SinkPolicy::validate` enforces at construction: `content ⊆ classes` ⇒
  `requires_consent` (missing consent ⇒ `MissingConsent`), `content` and
  `diagnostic` are disjoint (`ContentDiagnosticMixed`), `sampling` is
  coherent (`ratio` requires `ratio ∈ (0,1]`; `parent_based` requires the
  parent field), `rate_limit` and `max_field_bytes` are positive, and a
  `metric_view` sink cannot sample below `all` (`ForbiddenSampling`).
  `SinkPolicy::version_id` is `idp/1` over canonical bytes — policies are
  pinnable, diffable records (`RecordKind::SinkPolicy`, ADR-0245 §5).
- **§2 — sampling governs export copies only.** `Sampling::selects(event)`
  is deterministic (`ratio` hashes the `event_id` under the sink's domain —
  same event, same decision, so replays don't re-decide); dropped events
  land in the loss report as `dropped_fields`/counted rows. The ledger path
  is unreachable from `Sampling` — `read(run)` iterates the durable prefix
  unconditionally, and `metric_view` folds `Store` events, never an export
  batch — the spec's "vacuous by construction" invariant is structural,
  tested by `ac_r_2_9_1_11` (AC-R-2.9.1-11).
- **§3 — truncation and lowering-loss are per-field entries.**
  `export_view`/`export_events` apply `max_field_bytes` at the field level,
  emitting `truncated_fields{field, max_bytes}` for each cut; content-class
  mismatches emit `dropped_fields`; `ContentAddress`-bearing fields on a
  non-`content` sink are replaced by `{ref, len, digest}` projections — the
  spec's "addresses, lengths and digests only" rule — and secret redaction
  is *upstream* (the ledger's `redacted` records; `SinkPolicy.redaction`
  governs content classes and personal data only, per ADR-0057/CF-133).
- **§4 — `deliver` is the accountable append.** `deliver(store, sink,
  view_kind, seq_range, loss)` validates the sink, appends
  `measurement.export.delivered{sink_id, view_kind, seq_range,
  content_classes, loss_report_ref}` through the canonical `Store::append`
  (kernel-origin, audit-grade, provenance-mandatory per ADR-0035's table),
  and returns the `Delivery` — the exporter holds no authority handle and
  no second write path exists (ADR-0042 D2/D3). `sink_deliveries` folds
  these rows back out for the audit view's reconciliation half.
- **§5 — the catalogue is declared-complete, pending-honest.** Every §8
  name is a `ProcessMetric` row; rows reading classes that don't exist yet
  (`context.*`, `action.environment.*`, `lifecycle.hosted.*`) are stamped
  `pending` with the missing classes named — `pending_classes_are_declared`
  asserts they're declared-not-violations, and `registry_check` still
  resolves every *registered* class's `min_observability` (ADR-0246 §5).
  `ArtifactExposure` (ADR-0044 D6) is declared as the §3 schema with the
  `detector` stratification; its `delivered/activated/followed` classes are
  §05c/§05f's and pending likewise.

## Consequences
- An `accounting`-only sink provably cannot receive content bytes — the
  projection is structural, and the consent gate is checked before any
  export (AC-R-2.9.1-8's Stage-1 schema half).
- No code path can compute a metric from a sampled export: `metric_view`
  has no `SinkPolicy` parameter.
- Every export's fidelity is self-describing; `audit_view` (S1.15) consumes
  `sink_deliveries` + `TelemetryLossReport` verbatim.
- Deferred: the out-of-process exporter subscriber runtime + sink egress
  mediation (live sinks are `net_egress` destinations under EP3 — Stage 2+,
  DF-S1.14-4); the two convention-shaped sink fixtures and AC-R-2.9.1-6's
  loss-report round-trip (Stage 3, DF-S1.14-2).

## Revisit trigger
The Stage-2 kernel/subscriber ticket landing the live exporter path revisits
`deliver`'s in-process call site (the append contract is fixed — the runtime is
the seam); Stage 3's two convention-shaped sink fixtures revisit `unmappable_
scopes` mappings (declared data, versioned in the run bundle — additive, not a
re-decision of the lowering shape).
