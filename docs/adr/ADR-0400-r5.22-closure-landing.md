## Context

Packet C binds the recipient-closure slice to one in-process owner
interface: `closure_walk` (C.1 item 3 — typed reference closure
with visited set, limits and edge provenance) and `closure_report`
(item 4 — the access/loss/procedure verdict record). §6.2 requires
that every root class be enumerated by its owning codec — never a
hash regex over payload bytes, never a second class table — and
that `present` be proven by the recipient's own member bytes, never
a producer assertion. R5.21 landed the `evidence-package/1` record
the claim/procedure roots hang off; R5.22 lands the walk that
closes over them plus the ordinary, payload/IR/cause/lineage and
composition roots. Population assembly (R5.23), procedure/R0/
recompute/replay consumers (R5.24–26), rights (R5.27) and the
outside reviewer (R5.52) remain their named owners.

## Decision

1. **`crates/hh-bundle/src/closure.rs` owns the interface.** One
   public entry — `closure_walk(&Decoded, WalkOpts) → ClosureReport`
   — with `WalkOpts{procedure, recipient_class, checked_at, limits,
   fetch}`; the report is the walk's own fold, not a second
   contract. `pub mod closure` + re-exports in `lib.rs`; nothing
   else in the crate's surface changed (lib.rs +5 lines).
2. **The owning codecs enumerate references; every edge carries
   provenance.** Roots: `members[]` rows; `section_member_refs`
   + `derived_from`; `composition.contains[].member` recursion
   into `hh-bundle/1` manifests; `subject.lineage`; the decoded
   `evidence-package/1` member's `claims[].native_refs`/
   `report_refs`, `attempts`/`grade_attempts`/`exports`/
   `native_heads`/`watermarks`/`legacy_refs` coordinate refs;
   `traces.<run>` tree/pages/`blob_index`/head/checkpoints/
   `audit_tree_head`/`lineage_prefixes` (expanded recursively per
   declaring index); decoded page events' `causes[]`/`refs[]`/
   `ir_refs[]` (owner `hh-ledger.envelope:<class>`) and the class
   table's declared `content_refs` (owner
   `hh-ledger.class_table:<class>` — an unregistered class is an
   `unknown_class` closure failure); `lifecycle.run.created`
   payloads' `manifest_refs` (owner `hh-bundle.run_refs`). Each
   `ClosureEdge` records `{parent, role, field, media, size,
   owner, kind, target}`; visited dedup keys on exactly the
   `{parent, role, field, media, size}` tuple.
3. **The walk is bounded and cycle-safe.** `ClosureLimits{
   max_edges: 8192, max_depth: 8, max_events: 1<<20}`; an exhausted
   bound is a `traversal_limit` traversal failure — never a partial
   pass. An expansion-stack set over `trace:`/`manifest:` nodes
   refuses re-entry: a self-nesting `contains:` manifest (or
   lineage loop) is a `cycle` failure, and the walk terminates.
4. **Resolution is truthful and declaring-index-scoped.** A
   `present` edge resolves only when the recipient's own
   `Decoded.members` bytes recompute to the address
   (`idp_id("blob", bytes)`) and agree with the declared size —
   else `digest_mismatch`/`bad_size`/`missing_bytes`. `fetch` edges
   materialize through the landed `fetch::fetch` only when the
   caller supplies `FetchPermit{pool, trust, remote, now_ms}` —
   exact identity, admitted locator/trust/expiry, verified arrival,
   never executed; absent a permit they withhold (`fetch`), and a
   refused/expired/wrong-bytes attempt surfaces `fetch`'s own
   reason verbatim as the unresolved code. `redacted`/`gc` withhold
   as recorded losses. A nested `contains:` manifest's members,
   pages and blob rows resolve against *their own* index
   (`declared_status` carried on the edge), never the parent's.
   No member row falls back to `blob_index` status, then unindexed
   member bytes, then the self-verifying tree coordinate, then the
   decoded event/run coordinate; otherwise `missing_member`.
   There is no producer home/store/cache/path/credential fallback:
   the walk's whole world is `&Decoded` plus the caller-supplied
   fetch seams.
5. **`closure-report/1` is a versioned sidecar record.** Fields:
   `{schema, bundle_id, profile_version, procedure,
   recipient_class, checked_at, required, resolved, withheld,
   unresolved, verdict, failures[], edges[], fetched[]}` — pure
   over bundle bytes plus permitted fetch. `verdict` ∈ `closed` |
   `withheld` | `failed` (any traversal failure or unresolved edge
   → `failed`; explicit losses only → `withheld`). The report
   never joins `max_supported_level` — a sidecar cannot raise a
   level. `fetched[]` carries the verbatim
   `bundle.member.fetched` payload rows remote attempts produced,
   so the caller lands them durable before the member reads
   `present` (`require_ledgered_arrival`). The closed failure-code
   set (`missing_member`, `missing_bytes`, `digest_mismatch`,
   `bad_size`, `missing_run`, `unresolved_coordinate`,
   `head_mismatch`, `malformed_member`, `unknown_class`,
   `unsupported_schema`, `traversal_limit`, `cycle`) is exported
   under `closure::code`.
6. **Legacy manifests still walk.** A pre-R5.21 manifest (no
   `evidence_profile` section) reports `profile_version: null` and
   closes over its declared edges truthfully — the profile roots
   are additive, never required. A declared `evidence-package/<n>`
   outside the admitted family is `unsupported_schema`; a member
   that fails `EvidenceProfile::from_json` propagates its refusal
   code as the traversal failure.

## Consequences

- `tests/r5_22.rs` (9 checks) exercises every AC leg in scratch
  stores — compile-red at base `79b13533` (the module does not
  exist there): full-bundle closure with owner-typed provenance,
  dedup + all three limits, `fetch`/`redacted`/`gc` truthfulness
  (incl. permitted-fetch materialization), payload-only loss and
  wrong-digest failures, `unsupported_schema`/`unknown_class`,
  self-nesting cycle termination, typed fetch refusals with no
  producer fallback, legacy-manifest walk, and the sidecar
  non-level-join.
- REQ-F-005 keeps `planned; unmet` — this ticket records achieved
  engineered D/E separately from the owed legs: recompute
  (R5.25), replay (R5.26), outside reviewer (R5.52), the §6.3
  procedure cards, and every R/P/actual-execution predicate.
  REQ-A-103/REQ-E-208 are stamped contributing-only.
- No crate edge added to hh-bundle (the class table and codecs
  are already dependencies); no event class, no schema/wire
  change, no new dependency, no hash-regex discovery, no reverse
  dependency.

## Alternatives considered

- **A hash-scanning fallback enumerator** — rejected: §6.2/C.10
  name the owning codecs as the only enumerators; a regex over
  payload bytes cannot carry owner, role or provenance and would
  mis-report closure on non-address substrings.
- **A `closure_report` function separate from the walk** —
  rejected: the report is the enumeration's own fold (C.1 items
  3–4 read as one interface); a second entry would invite a
  consumer to fold a different edge set than the walk's.
- **Treating unindexed member bytes as `present`** — rejected in
  favor of resolution by bytes only after the status/blob-index
  legs: an edge with no declaring row resolves on bytes because
  the recipient carries them, but a declared `redacted`/`gc`/
  `fetch` loss is never laundered into `present` by carried bytes
  — the declaring index speaks first.
- **Best-effort partial closure on limit exhaustion** — rejected:
  §6.2's recipient predicate is over the whole required set; a
  `closed` verdict over a truncated walk is a false pass, so
  exhaustion is a `traversal_limit` failure.
- **Silent skip of unregistered event classes** — rejected: an
  unregistered class's payload-ref partition is unknowable to the
  recipient, so the walk cannot prove it enumerated every required
  edge — `unknown_class` fails closure.

## Revisit triggers

- If R5.23's population assembly or the R5.24–27 procedure
  consumers need a different edge vocabulary, verdict partition or
  `closure-report/<n>` member shape, amend this record's
  Consequences — the report is sidecar-class and evolves by
  version, never silently.
- If a producer-crate per-owner enumerator batch is ever admitted
  (the conditional seam this ticket's partition row documents —
  "if per-owner enumerators are broad, split support-only producer
  batches"), re-read Decision 2: today the class-table
  `content_refs` declaration *is* the owner-supplied closure input
  and no producer-crate batch exists (C.1 item 6 forbids the
  crate edge).
- If a successor bundle schema (`hh-bundle/2`) or profile major
  `≥2` is admitted, revisit the `unsupported_schema` boundary —
  cross-version traversal then routes through negotiation, never
  silent decode.
