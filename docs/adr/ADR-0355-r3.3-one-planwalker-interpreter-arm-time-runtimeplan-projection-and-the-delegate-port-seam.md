# ADR-0355: R3.3 control-delegation legs — the one `PlanWalker` interpreter, arm-time `RuntimePlan` projection, and the delegate port seam

- **Status:** Accepted
- **Date:** 2026-10-14
- **Ticket:** R3.3
- **Requirement ids:** DF-S1.20-1 · BL-14 · R-2.6.1 · R-2.6.3 · R-2.2.3 ·
  CC1 (one interpreter, one codec, one producer) · CC2 (delegation
  authority is conferred by the child-lease/grant machinery) · CC3
  (durable-before-visible).
- **Spec:** §5e (control strategy — `react/steerable` `delegation_reason`,
  `woken{peer_message}`, the `RuntimePlan/1` variants
  `hh/workflow@1`/`hh/program@1`, `compute_policy = static`) · §4.4 (the
  R-2.6.3 child-lease delegation slice) · §5e.1 (the one control-family
  β-parameterised interpreter).
- **Rung (ADR-0024 obligation):** C1 — every leg runs at the offline /
  fixture-verified ceiling; no staging or live claim is made or implied.

## Context

DF-S1.20-1's R2.6 progress note named exactly three residuals, all
control-plane interpreter legs the staged park honestly deferred:

1. **`react/steerable` delegation on a real run** — the
   `delegation_reason` refusal path (the R-2.6.3 subsystem) existed at
   `check`, but no variant emitted a `delegate` decision and no driver
   executed one end-to-end.
2. **`woken{peer_message}` interpretation** — the S4.8 parent-mediated
   delivery producer mints the occurrence, but the steerable
   interpreter had no distinct reading: the shared `woken` cue table
   only understood the steer/follow-up lanes.
3. **`hh/workflow@1`/`hh/program@1` real-run semantics** — the two
   variants parked on a staged `wait` since Stage-1 registration; the
   `compute_policy = static` driver landed at S4.7 but nothing consumed
   the compiled `RuntimePlan/1` control spine.

Two seams had no honest producer. The driver had no way to reach the
spawn substrate (a delegate decision cannot confer authority itself —
CC2 — and the R3.2 child-lease producers are the only lawful
substrate). And `ControlContext.plan` carried `[]` on the embed arm
paths: a compiled `RuntimePlan` lives in the `CompiledBundle`, not in
the sealed definition, so arming a `workflow`/`program` session had no
plan to walk.

## Decision

1. **`hh/workflow@1` and `hh/program@1` bind one `PlanWalker`**
   (`crates/hh-control/src/walk.rs`) — the single sequential
   `RuntimePlan/1` interpreter for the control family, parameterised by
   the same `StrategyParams`/`Boundary` mechanism the react family
   uses. `step{instruction}` proposes the model, `step{invoke}` acts,
   `branch-on-validator` verifies and fails closed to `else` on any
   non-affirmative verdict, `loop` walks bounded bodies,
   `delegate` emits the delegate decision and awaits the child terminal,
   `stop-rule` nodes are reserved for envelope evaluation (never a
   sequential step), and exhaustion stops `completed`. Position rides
   `state.extension.walk` so checkpoint bytes restore mid-walk; a
   corrupt position is a typed invariant violation; `ModelEmitted`
   provenance on a compiled-plan variant refuses typed — never a
   zero-step success, never the staged park standing in for an
   interpreter (§5e.1's ADR-0256 D6 staging is superseded for these two
   variants).
2. **`ctx.plan` re-derives at arm through the one producer.** The embed
   `arm_driver`/`arm_resume_driver` project the control spine by running
   `link` → `lower_native` over the sealed definition — the same
   deterministic pipeline the `CompiledBundle` seals — rather than
   persisting a second plan copy in the sealed document, the manifest,
   or the `leaf.arm` record (CC1: no second spelling; the walk position
   is the only per-run state, and it rides the checkpoint). A
   `requires.procedure` variant whose sealed doc won't link or lower
   refuses the arm with a typed reason; a missing sealed doc leaves
   `plan = []` and the driver refuses `missing_procedure` — honest
   refusals at the earliest point, never a silent substitute.
3. **The delegate seam is a port, not a strategy assertion.** A model
   call on the configured delegation surface mints
   `control.delegate.proposed` — a new registered durable audit class —
   before execution (CC3). The driver's `StoreSeam` exposes the run's
   `Store` + writer lease; `DelegatePort::delegate` executes through it
   and returns a closed `DelegateOutcome`; refusals return to β as
   `EnvelopeSignal::Refused`. A missing store seam is `UnbackedPort`; a
   missing `delegation_reason` is refused at `check` as
   `missing_delegation_reason` (unchanged contract, now exercised);
   unavailable substrate is `delegation_unavailable`. The orchestrator
   half, `SpawnDelegatePort`
   (`crates/hh-orchestrator/src/delegate.rs`), parses the spec through
   the canonical `SubagentSpec` codec and calls the real
   `hh_subagent::spawn` under the `ParentBinding` — attenuation, budget,
   and depth stay in the child-lease substrate (CC2), the decision
   `EventRef` is the spawn idempotency key, and the orchestrator never
   re-implements a parent-authority check.
4. **`woken{peer_message}` is a context artefact, not a steering cue.**
   The steerable interpreter selects on the wakeup *trigger*: a
   `peer_message` occurrence lands as a peer-message context artefact
   (the S4.8 `context.artefact.delivered{kind: peer_message}` row's
   consumer) and feeds the next `propose` as context — it is never a
   `steer`/`follow_up` cue regardless of which delivery lane carried it.
   The same trigger arriving on the steer lane still steers; the lane
   is transport, the trigger is semantics (CC1 — one interpretation
   table, not two).

## Consequences

- The control family's three remaining DF-S1.20-1 residual legs are
  discharged; BL-14 closes.
- The sealed definition stays unchanged — no schema drift; the arm-time
  projection is a pure function of the same inputs the compile op used,
  and `relower`'s byte-equality check already pins determinism.
- `arm_driver`/`arm_resume_driver` run `link` + `lower_native` only for
  `requires.procedure` variants — react/plan_execute arms pay nothing.
- `control.delegate.proposed` is a new `control.*` class in the
  `hh-ledger` class table (durable, audit-grade) — a schema addition,
  registered per the crates-level convention.
- The size budget flagged: ~1,410 changed source lines vs the ticket's
  1,200 (the walker's frame/restore machinery is the bulk). Recorded
  here and in the run ledger rather than split mid-implementation — a
  post-hoc split would orphan the acceptance batteries.

## Alternatives considered

- **Persist `RuntimePlan` in `leaf.arm` / the manifest.** Loses: a
  second plan copy drifting from the sealed definition, a new
  checkpoint-adjacent codec to keep honest, and no benefit — the
  projection is deterministic and cheap at arm.
- **Interpret `peer_message` as a steer cue.** Loses: a peer message is
  addressed content, not an operator correction — routing it through
  the steer lane would let one principal's message masquerade as
  operator intent (the boundary's whole point), and would duplicate the
  interpretation table (CC1).
- **Keep the staged park for `workflow`/`program` and take typed
  refusals.** The ticket permits a spelled refusal where staging
  genuinely does not admit the semantics — but the compute driver
  (S4.7), the child-lease producers (R3.2), and the `RuntimePlan/1`
  node set were all landed; the admission conditions held, so the
  honest answer was the interpreter, not another deferral.
- **A `delegate` builtin inside `SpawnDelegatePort` that re-checks
  parent authority.** Loses (CC2): authority attenuation lives in the
  child-lease/grant machinery exactly once; duplicating it in the
  orchestrator is a second TCB to keep honest.

## Revisit trigger

Reopen if a fourth `RuntimePlan/1` variant joins the control family
(re-check whether `PlanWalker` stays one interpreter or the family
splits), if `link`/`lower_native` gains run-context inputs that make
the arm-time projection diverge from compile-time output (the `relower`
check must then extend to embed arms), or if the embed boundary learns
to persist `CompiledBundle` artefacts run-side (at which point
`ctx.plan` should read the bundle, not re-derive).
