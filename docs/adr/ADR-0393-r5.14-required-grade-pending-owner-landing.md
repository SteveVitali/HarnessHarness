## Context

PADR-R5-1 admits `grade_pending` as an **admission state** between
execution settlement and grade admission — never a seventh outcome
class — with one shared disposition function
(`hh-eval::selection::plan_disposition`) deciding `Pending | Graded |
OracleFailure` for every scored consumer. R5.9 deliberately left the
consumer wiring to R5.14. The scoped review (`07b6be09`) ruled SPLIT on
the ≤1000-line trigger (measured 1,185 for the owner core alone): this
leg lands the owner model — the admitted `plan_disposition_at` read, the
`settle_graded`/`record_selection_revision`/`grade_pending` mechanics,
and the scheduler/close owner callsites — plus the producer battery
`tests/r5_14a.rs`. Consumer wiring (results projection/query/export,
eval compare, embed analysis) is seq 183a's scope.

## Decision

1. **One admitted read, owner-side:** `disposition::plan_disposition_at(
   store, docs, experiment_run, run_plan_id, pins)` composes the frozen
   `spec.ext.required_grade` pins, the subject's sealed end-state and
   stop-derived class, durable `selection_revision` folds, and
   instrument-verdict rows at pinned watermarks through
   `select_grade_at` + `plan_disposition`. `DispositionPins`
   (`experiment_until`, `overlay_runs[]`) are the read's
   reproducibility contract — equal pins read equal dispositions; the
   read never writes.

2. **Strict freeze decode.** `required_grade_freeze` accepts exactly
   `{mode:"required", selection_policy_ref, tasks:{task:{oracle_ref,
   eligible[]}}}`; an unknown mode/member/task pin is a typed
   `UnknownRequiredFeature` refusal at `launch` (A.6) — never a silent
   downgrade to legacy. Absent `ext.required_grade` freezes
   `mode:"legacy"` byte-identically.

3. **`settle` mints the admission state, not an outcome.** In required
   mode a stop-derived `Scored` settle appends
   `run_settled{grade_pending:true}` + `execution_settled{dedup_key}`
   once — execution cost settled exactly once; the scored-success
   interpretation awaits `settle_graded`. Non-scored classes settle
   unchanged.

4. **`settle_graded` is the producer admission op.** It resolves
   `plan_disposition_at` and records `measurement.experiment.
   plan_disposition`; a still-pending read returns without a write and a
   recorded disposition replays verbatim (exactly-once — no second row,
   no recharge, no replan, no new n).

5. **`record_selection_revision` is the durable revision home.**
   `validate_revision` re-materialises the set and validates
   `RevisionLog::append` semantics (authorized, append-only, set-bound,
   watermark-bound, immutable) before the
   `measurement.experiment.selection_revision` row lands.

6. **Owner gates:** `PlanState.grade_pending` blocks `eligible_at`
   (never relaunch), counts `open_at`/`pending_plans` (unresolved slot);
   `close(false)` refuses `CloseBlocked{grade_pending=[…]}` naming the
   slots; `close(true)` enumerates them in `ExperimentReport.pending`
   (declared audit member on `measurement.experiment.closed`, list
   bound). `PLAN_DISPOSITION` folds resolve the slot — graded/scored →
   accepted; oracle_failure/non-scored → final.

7. **`cause_run` parses `run_id:event_id` on the LAST separator**
   (hh-eval `selection.rs`). Run ids are colon-bearing
   (`subj-<idp(run,plan,attempt)>` → `subj-sha256:…`, `sha256:…`
   content addresses) while event ids are colon-free, so the rightmost
   segment is the event coordinate. The naive prefix split made every
   `subj-*` subject uncitable — `UncitedCauses` excluded every attempt,
   an unsatisfiable admitted contract leg (a) was the first producer to
   exercise. Same contract, correct parse; **R5.9 revisit flag** —
   member-qualified `(run, seq, member)` coordinates for multi-member
   eligible sets remain owed there (the owner already refuses
   `ConflictingCoordinate` rather than silently merging same-coordinate
   multi-member facts — typed refusal, never a silent downgrade).

8. **Three classes, one table (CC10):**
   `measurement.experiment.execution_settled`,
   `measurement.experiment.plan_disposition`,
   `measurement.experiment.selection_revision` registered in both class
   tables with the experiment-event provenance rows; `pending` declared
   on `measurement.experiment.closed`.

## Alternatives considered

- Deferring the `cause_run` fix to the R5.9 revisit and shipping only
  Pending-side legs — rejected: `Graded`/`OracleFailure` dispositions
  would be unreachable by any producer (every `subj-*` citation fails),
  leaving the leg's happy path unverifiable and the admission contract
  unsatisfiable in production. The fix preserves the admitted contract —
  it corrects the coordinate parse, not the citing rule.
- Citing the subject with a colon-free alias — rejected: it would
  fabricate a second identity scheme (CC1); the coordinate's run_id is
  the run's id.
- `settle_graded` charging a separate grading slice — rejected: the
  admitted text settles execution cost exactly once; grading reads
  durable rows, it does not re-execute.
- A seventh outcome class for pending — rejected outright by the
  admitted text; `grade_pending` is an admission state.

## Revisit triggers

- If a future event-id scheme admits colon-bearing event ids, revisit
  the last-segment `cause_run` parse (Decision 7) — the unambiguous
  form then needs an escaped or length-prefixed coordinate; the R5.9
  revisit flag on member-qualified coordinates is the owning record.
- If the admitted contract admits multi-member eligible sets sharing one
  `(instrument_run, seq)` coordinate, revisit the member-qualified
  coordinate seam (Decision 7) — currently a typed
  `ConflictingCoordinate` refusal.
- If consumers need pending enumerated in a *completed* (non-partial)
  close, revisit Decision 6 — today unresolved slots force the close to
  refuse or go partial by design.
- If seq 183a needs the overlay revision watermarks named by callers
  rather than self-computed, revisit the `DispositionPins` shape
  (Decision 1) — the experiment pin is caller-named, overlay pins are
  caller-named `(run, until)` pairs.
