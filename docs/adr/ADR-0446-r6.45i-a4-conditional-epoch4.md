# ADR-0446: Conditional epoch-4 authority — mint iff the scan check confirms a derivation gap (§10.5 amendment row A4)

- **Status:** Accepted — operator ruling R-6, interactive 2026-11-15 (LEDGER `## GATE DECISIONS` `intervention-2026-11-15` row, verbatim)
- **Date:** 2026-11-16
- **Ticket:** R6.45i (manifest 309i — records); the authority is exercised or discharged by R6.45k's D16 scan check (manifest 309k)
- **Amendment register item:** A4 (experiments spec §10.5, "First-pass intervention amendments")
- **Requirement ids:** REQ-XB-116 (versioned-successor epoch pattern), X-06 (verify-phase additions only — never agent-phase), S-3 (the standing exclusion if no gap)
- **Spec:** experiments spec §3.5 (allowlist derivation — agent base ∪ `tests/*` scan ∪ oracle-observed), §10.5 row A4
- **Rung (ADR-0024 obligation):** an explicit non-contract note — this ADR governs the experiments-program first pass, not the canonical kernel contract ladder.

## Context

`pytorch-model-cli`'s `tests/test.sh` runs `uvx --index https://download.pytorch.org/whl/cpu …`, yet `download.pytorch.org` is absent from the epoch-3 verify set even though that set is defined as agent base ∪ the static `tests/*` scan (`scan_hosts_in_text`) ∪ oracle-observed (diagnosis D16 — CONFIRMED as data, cause unknown). Either the scan missed the host (a derivation defect) or the freeze derived from a member set that excluded this dev member. Minting an epoch without knowing which would either bless a scan bug or paper over a derivation gap.

## Decision

R-6 (verbatim in the GATE DECISIONS row): authority to mint an **epoch-4** freeze under `protocol_id fp-w1-q-x55` **if, and only if, R6.45k's scan check confirms a derivation gap**. The check runs `scan_hosts_in_text` over every re-proof member's and successor's `tests/*` bytes and diffs the result against the epoch-3 verify set:

- **If a scanned host is missing** — find why (derivation input set / scan bug), fix it with a regression, then mint epoch-4 under the REQ-XB-116 versioned-successor pattern (epoch-2/3's amendment-document record): verify-phase additions only, never agent-phase (X-06).
- **Else** — record the result; the member's `allowlist_gap{download.pytorch.org}` exclusion stands (S-3), and no epoch is minted.

## Consequences

R6.45k owns the check and the conditional mint; Wc9 runs under epoch-4 if minted, else epoch-3 (`sha256:787db9e1…` carried verbatim). `pytorch-model-cli` joins the smoke member set only if epoch-4 lands. The conditional structure means a missing host can never silently become a grant — the gap must be *confirmed* first, and the exclusion stands otherwise.

## Alternatives considered

- **Mint epoch-4 unconditionally now** — would add a host without knowing whether the derivation is broken; a scan bug would stay live and silently under-grant elsewhere. Rejected.
- **Exclude `pytorch-model-cli` outright** — pre-judges the check: if the derivation is buggy, other members' sets are suspect too and exclusion treats the symptom. Rejected.

## Revisit trigger

Discharges at R6.45k's recorded scan result — either epoch-4 minted under the recorded pattern, or the exclusion stands. Revisit only if the scan check itself proves unsound (a new gap found post-mint) — a new amendment row.
