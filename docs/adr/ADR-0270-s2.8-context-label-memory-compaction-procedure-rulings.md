# ADR-0270: S2.8 context-label/memory/compaction rulings — `ProcedureProfile/1` on `ext["hh/procedure"]`, the closed predicate/grammar decoders, the evict-oldest net-reclaim rule, the `scope_ended` floor, the skill-lift mapping, and the `index_all_under_budget` selector

- **Date:** 2026-09-19
- **Ticket:** S2.8

## Context

S2.8 lands the kernel-stamped `context_label`, memory labels and the
memory C0/C2 slices, the `R-2.4.2⁰` compaction machinery with
`evict_oldest`, the retrieval/lifecycle filters, and the `R-2.4.5⁰`
`ProcedureProfile/1` + `lift_skill` slice. The spec fixes the invariants
(I-CUT…I-FALLBACK, the lifecycle precedence walk, the compliance chain);
the mechanism choices below were left to the ticket:

1. **Where `ProcedureProfile/1` lives and how malformed/unknown members
   decode.** The profile is document data on the `Procedure` node — the
   extension-members channel is the declared extension point (CC8), but
   a permissive parse would silently drop authored constraints.
2. **Which predicates are checkable at C0.** The predicate grammar is a
   closed sum; `env_requires`/`capability_present`/`artifact_present`
   need a live environment/store the validator does not have. Refusing
   them would make most real procedures unwritable; ignoring them would
   silently admit ungated procedures.
3. **How `evict_oldest` measures "enough".** I-RECLAIM measures the
   *executed* view's `tokens_freed` — net of the omission placeholders
   each forgotten range costs (`OMISSION_ITEM_TOKENS`). A rung that
   stopped at *gross* target could produce an `ineffective` proposal and
   exhaust the ladder into `CompactionImpossible` while evictable items
   remained.
4. **Where `scope_ended` sits in the precedence walk.** The lifecycle
   precedence is `revoked > superseded > expired > stale_by_dependency >
   valid > unknown`; a scope floor that lives inside the contract check
   would let a missing contract mask the floor.
5. **How `lift_skill` maps vendor front-matter.** `allowed-tools` is a
   *claim* in the skill text; treating it as a grant would widen
   authority from unverified content (CC2).
6. **What the C0 `ProcedureSelector` is.** OQ-198 leaves the selection
   method open; the C0 default must be deterministic and budget-capped.

## Decisions

**D1 — `ProcedureProfile/1` is stored on `ext["hh/procedure"]` and
decoded fail-closed.** `hh-hir::procedure::ProcedureProfile::from_json`
refuses non-objects and unknown members (`SchemaViolation`); the typed
sub-decoders (`Predicate`, `FailureClass`, `Handler`, `ProcedureParameter`,
`select_target`) each own their member grammar. The profile is *data*
(CC7): validation is `validate_procedure` inside `hh_hir::validate`,
never a second schema.

**D2 — uncheckable predicates are counted, never errors.**
`check_preconditions` evaluates the closed `Predicate` sum against a
`PreconditionEnv`; a predicate whose domain is not available at
validation time (`env_requires`, `capability_present`,
`artifact_present` at C0) lands in `PreconditionReport.uncheckable` and
the validator records `uncheckable_preconditions` on the run — the
document stays sealable, the uncheckable count is honest data (AC-R-2.4.5-11).

**D3 — `failure_handlers` are total over declared ∪ derivable classes.**
`required_failure_classes` = the profile's `failure_classes` ∪ the
classes the steps can raise (`Invoke` → `permission_denied`,
`Delegate` → `delegate_failed`/`permission_denied`, `Verify` →
`validator_failed{validator}`, `Loop` → `budget_exhausted`, any
executable step → `step_failed:any`, non-empty preconditions →
`precondition_failed`). `covers` treats `*`/`any` as wildcards inside
`step_failed`/`validator_failed`. A missing handler is
`HandlerIncomplete` — typed, never a warning.

**D4 — `evict_oldest` stops on the *net* reclaim estimate.** The loop
adds indivisible groups in `PRIORITY_CLASSES` order (commentary →
observations → images → memory → procedure bodies → transcript tail)
until `freed − runs·OMISSION_ITEM_TOKENS ≥ target_reclaim`; the proposal
`estimate` is the same net figure. `execute` recomputes `tokens_freed`
net of placeholders, so a hard `min_reclaim` can never be short-changed
by a rung that stopped on gross. `OMISSION_ITEM_TOKENS = 8`,
`DEFAULT_TARGET_FRACTION_PPM = 500_000` (OQ-197), and the kernel rung is
`hh/evict-oldest@1` — the same deterministic algorithm the
`hh-compact-evict-oldest` out-of-process witness runs (AC-R-2.4.2-1);
the last rung never depends on a plugin host.

**D5 — `scope_ended` is an implicit precedence-floor expiry.**
`lifecycle_state` checks `MemoryStore::scope_ended` *before* the
contract walk: a `run`-scoped version whose scope ended is
`expired{reason: "scope_ended"}` whether or not its contract declared
the dependency — the scope is the floor, not a contract member
(AC-R-2.4.4-8).

**D6 — `lift_skill` produces claims, never grants.** The lift emits one
`Procedure` whose body is one `Instruction(Text)` at `external` text
authority; `allowed-tools` lands as `DeclaredClaim`s on the lift result
while `allowed_capabilities` stays empty — only a `seal`-time
`authorizes` edge can cover an invoked capability (`EffectUncovered`
otherwise). `scripts/*` → `Opaque(CompiledPayload{exec})`,
`references/*`/`assets/*` → content-addressed `Artifact`s,
`compatibility` → `env_requires` predicates, vendor `PathTrigger`s →
`path_glob` preconditions + `retrieval_hints`, `metadata.version` → a
`version_label` claim. Render purity stays `validate`'s gate — the lift
produces the doc faithfully and `RenderTimeExecution` refuses it.

**D7 — the C0 selector is `index_all_under_budget` (OQ-198), and the
chain is `selected` → `delivered{procedure_index}` → `activate` →
`activated{loaded}` → `detect_followed`.** `select_procedures` emits
`context.procedure.selected{method, candidates[], delivered[]}`,
delivers `procedure_index` candidates `handle_only` under the
`procedures` slot's `budget_share`, and never delivers a procedure whose
checkable preconditions failed. `activate` expands the handle into the
deterministic `context.artefact.activated{detector: deterministic,
signal: loaded}` row plus the `procedure_body` candidate the next
assemble admits. `detect_followed` returns the deterministic evidence
only when the invoked capability ∈ `allowed_capabilities` and the
index's `delivery_id` ∈ `causes[]` — the verdict row is the verification
plane's; this module returns evidence, never a verdict.

**D8 — `TriggerKind::PathTouched` reads `triggers[].path_glob` off the
`procedure_pointer`'s structured content.** The retrieval layer matches
the touched path against the declared globs (segment-aware, same matcher
as `Predicate::PathGlob`); a hit surfaces the pointer under
`query_kind: trigger` — the body is never injected into the tool output
(AC-R-2.4.3-12).

**D9 — the compiler test fixture tightens to the new gate, never the
reverse.** `hh-compiler/tests/common::procedure_node` now populates
`allowed_capabilities` from the steps' `Invoke` tools and declares a
total `abort` handler set covering every reachable class — the seal gate
(`CapabilityNotAllowed`, `HandlerIncomplete`) made the previously-bare
fixture invalid, and the fixture was brought up to spec rather than
loosening the check.

## Consequences

- `validate` is now *non-vacuous* over procedures: malformed profiles,
  unknown predicates, unbound `$param` refs, incomplete handlers,
  composition cycles, risk-floor violations and disallowed `Invoke`s are
  typed `HirError`s at seal — `uncheckable_preconditions` is data, not
  an error.
- `compact` is the kernel driver: `assess` → variant ladder →
  `proposal.fallback` → kernel `evict_oldest` → `CompactionImpossible`
  (hard) / unchanged view (soft); `context.compaction.started` +
  `context.compaction.completed{status, tokens_freed}` always ledger the
  attempt.
- `mark_scope_ended(PersistenceScope::Run)` is the one call a driver
  makes at run close; every `run`-scoped version then reads
  `expired{scope_ended}` on the next `lifecycle_state`/`retrieve`.
- The net-reclaim fix means `evict_oldest` can evict *one more* group
  than the gross figure suggests when placeholder cost straddles the
  bound — deterministic and documented, and AC-tested
  (`ac_r_2_4_2_5_evict_oldest_never_stops_short_of_net_reclaim`).

## Alternatives considered

- **Permissive profile decode / warnings.** Rejected: a SHOULD-level
  constraint that silently drops would violate CC3 and make the sealed
  artifact misrepresent its author.
- **Refuse uncheckable predicates.** Rejected: `env_requires` etc. are
  the common case for real procedures; counting them preserves the gate
  without sealing paralysis.
- **Gross-target evict_oldest.** Rejected by construction (D4): the
  executed-view net is what I-RECLAIM measures, so the rung must aim at
  the net.
- **`scope_ended` as a contract member.** Rejected: the floor must hold
  even when the author omitted the dependency — it is a store-level
  fact, not a per-version claim.
- **`allowed-tools` as grants.** Rejected (CC2): unverified extension
  text cannot widen capability authority; claims land on the lift result
  for the seal-time `authorizes` edge to cover.

## Revisit trigger

Reopen D2 if a live `PreconditionEnv` lands for `env_requires`/
`capability_present`/`artifact_present` (the uncheckable count should
shrink, not disappear); D3 if the spec relaxes handler totality (the
wildcard classes stay); D4 if omission placeholders become variable-cost
(the stop rule and `estimate` must track the same net formula); D5 if
`scope_ended` gains per-scope semantics beyond `run`/`session`; D6 when
the `authorizes`-edge consumer lands — the claim set may gain a
satisfiability witness; D7 if OQ-198 resolves to a non-`index_all`
method — the selector event shape is stable, only `method` changes.
