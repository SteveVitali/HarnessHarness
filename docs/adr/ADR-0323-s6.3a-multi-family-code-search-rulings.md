# ADR-0323: S6.3a multi-family code-search + hosted-coordinate rulings

- **Status:** Accepted
- **Date:** 2026-10-02
- **Ticket:** S6.3a
- **Requirement ids:** R-2.9.5 (6c —
  multi-family code search, hosted
  coordinates); R-2.8.5² (model install
  under the experiment's
  `authority_cap`); AC-R-2.9.5-5
  (research-grade walls); AC-15
  (matched-total commensurability);
  CC1/CC2/CC3/CC6/CC7/CC9/CC10.
- **Spec:** §5h.5 (R-2.9.5 6c); §6.6
  (hosted coordinates); §5g.5
  (R-2.8.5²); owning rulings ADR-0195
  (the S0–S10 machine — D12's moved-head
  surface), ADR-0196 (the proposer class
  + D7's hosted edge), ADR-0190 (the
  scheduler's slot-history seam),
  ADR-0209 (C4 maturity grades).

## Context

S6.2 landed the first automated family —
`ahe`, construction-pinned to one
component class. S6.3a lands sub-stage
6c: the *multi-family* code-search
surface. The run had to rule on how the
new families stay honest
(`research-grade` is a wall, not a
label), how `CompiledPayload` candidates
enter without weakening the typed
surface, how a candidate survives a
moved lineage head, how a hosted
participant's coordinates admit into a
native campaign, and how a model install
stays inside the experiment's declared
authority ceiling.

## Decision

- **D1 — the family set is closed and
  `research-grade` is mandatory, not
  claimed.** `PROPOSER_FAMILIES` is the
  closed `{ahe, rho, gene_bank,
  code_search}`; `RESEARCH_FAMILIES` =
  `{rho, gene_bank, code_search}`.
  A campaign naming a research family
  must carry `research-grade` in
  `maturity_flags` (`SchemaViolation`
  at `spec.validate`), and S8 seals
  only `label = "preview"` reports on
  such a campaign
  (`SealRefused{research_grade_not_
  preview}`) — a research result never
  enters a committable acceptance row
  nor a leaderboard claim (CC9; ADR-0209
  D3).
- **D2 — `target_classes[]` is the
  multi-class surface; `ahe` stays
  one-class.** The spec carries both
  `target_class` (the family's primary
  class — still mandatory for
  automated campaigns) and
  `target_classes[]` (the 6c multi-set).
  `ahe` campaigns refuse
  `target_classes` beyond
  `{target_class}` (the 6b rule holds);
  research families may name several
  members of `EVOLVABLE_TARGET_CLASSES`
  — which now includes `code_payload`
  (`CompiledPayload` bodies, always
  typed + declared-interface-bearing +
  out-of-process).
- **D3 — `CompiledPayload` candidates
  stay typed by construction.** The
  `code_search` variant emits diffs
  that rewrite a `ProcedureStep::Opaque`
  leaf's `bytes_hash` under the *same*
  `declared_interface` — the interface
  is the contract the leaf satisfies;
  bytes are content-addressed, never
  embedded. The campaign's S1 gate runs
  `hh_hir::validate` on the assembled
  target and maps the typed
  `OpaqueWithoutInterface` error to the
  same refusal at rebase — never a bare
  schema slip.
- **D4 — `rebase` replays the same
  edit, never a different one.** A
  candidate in `{searched, validated,
  transferred, security_checked}` may
  `rebase` onto the moved head: the new
  `base_ref` must equal the head
  (`StaleBase`), the rebased diff's
  semantic-op target set must equal the
  stored diff's (`StaleBase` — a
  different edit is a new candidate),
  and apply/invert/`validate` re-run on
  the new base. `rebased` re-enters at
  S5 — `rebased → validated` is the
  only forward leg; nothing downstream
  survives the move. The
  `transitioned` row carries
  `rebase{of, onto}` + `target_ref`;
  the fold rebuilds `CandidateRecord.
  rebase_of` so restart is
  byte-identical (RC-8).
- **D5 — hosted admission is
  records-in over `hh-hosting/1`, and
  it is checked twice.** The spec's
  `hosted_descriptor_refs` resolve
  `HostedCoordinateDescriptor` bodies
  through `LabDocs` (`get_named` first,
  content-ref fallback —
  `UnresolvableEvidence` when neither
  lands). At `open`, every declared
  `hosted_coordinates` member must
  resolve `capability = supported` in a
  descriptor whose `abi` /
  `participant_class` is exactly
  `hh-hosting/1` + `hosted` (else
  `HostedCoordinateUnsupported` — the
  campaign refuses to open rather than
  admitting a coordinate it cannot
  enforce). At S1, a proposal's
  `coordinate_values` must be scalar
  (a structured value is a structural
  coordinate edit — refused, D7 is
  value-scoped), name an admitted
  coordinate, and resolve `enforced`
  under `budget_enforcement` —
  `reported_only` answers
  `ReportedOnlyDimension` (AC-15),
  undeclared answers
  `HostedCoordinateUnsupported`. The
  intake `proposed` row stamps the
  admitted coordinate keys + install
  leg for the durable audit trail
  (CC3).
- **D6 — the experiment's
  `authority_cap` is the install
  ceiling (R-2.8.5²).**
  `CandidateProposal.install`
  (`{name, kind, requested_grants[]}`)
  is checked at S1: no declared cap ⇒
  refused; a grant outside the cap ⇒
  `AuthorityWidening`.
  `EvolutionCampaign::install` then
  hands the same envelope to
  `hh_registry::lifecycle::install_plan`
  — cap first, then the registry's own
  proposer-grant and `model_install`
  trust-view gates (which map through
  as `AuthorityWidening` /
  `PolicyWidening`, never swallowed).
  The durable
  `security.extension.install_requested`
  row mints on the campaign run before
  any fetch, caused-by the candidate's
  last transition.
- **D7 — `voi` allocation reads the
  slot-history layer only.**
  `SlotAllocation::{voi,
  concentrate{floors}}` join
  `uniform`/`fractional_design`; floors
  sum ≤ 1_000_000 ppm
  (`BudgetSplittingTrap`) and every
  floor names a declared slot (a
  target class, an admitted hosted
  coordinate, or `native`). A `voi`
  campaign whose corpus lacks the
  `slot_history` layer is
  `SchemaViolation` at open — the VOI
  input is the scheduler's recorded
  slot history (ADR-0190's seam), never
  live task state.
- **D8 — the selectors share one
  argmax.** `ParentSelectionPolicy::
  {gene_bank{niche},
  rho{trajectory_ref}}` both resolve
  through `select_parent_apply` — the
  policy arms restrict the pool
  (`niche` filter with a lineage-wide
  elite fallback; `trajectory_refs`
  membership with `None` on an
  anchorless query — a pick is never
  invented) and the deterministic
  argmax decides within it (CC1).
  `LineageEntry` gains `niche` +
  `trajectory_refs` as folded members,
  and the conformance port decodes them
  off the lineage JSON.
- **D9 — RHO declares its corpus
  dependency.** `RhoProposer::declare`
  reports `needs_reference_trajectories
  = yes`; `propose` answers
  `CorpusUnreadable` when the corpus
  omits the `reference_trajectories`
  layer and `NoAddressableFailure`
  when the layer anchors no trajectory.
  The emitted hypothesis cites the
  anchor in `reference_trajectories` —
  the same member the `rho{trajectory_
  ref}` selector reads on the lineage.
- **D10 — one embed op for the new
  driver verb.** `lab.evolution.rebase`
  joins the Group L surface — same
  capability gate
  (`serves_measurement`), same tier
  (experimental), same EVO_ERR set,
  records-in/records-out
  (`{run, candidate_id, proposal,
  base_doc}` → `{state: "rebased"}`).
  Schema + generated client regenerated
  through `hh-codegen` (CC7); the
  `transitioned` class's
  `audit_fields` grew `target_ref` /
  `rebase` / `coordinates` / `install`
  members (append-only growth — the
  older members are untouched, CC8).

## Consequences

- The 6c surface is preview-walled end
  to end: research families declare
  `research-grade`, the campaign
  refuses to open without the flag,
  and S8 refuses a non-`preview`
  acceptance label — the wall is a
  gate, not a convention.
- `rebase` keeps post-S4 evidence
  attached to the candidate while
  forcing re-evaluation from S5 — the
  moved head invalidates search-time
  evidence but not the candidate's
  registration (the `rebase{of,onto}`
  pair keeps the lineage legible).
- Hosted participation stays
  records-in: the campaign never calls
  a hosting API — it reads deposited
  `hh-hosting/1` descriptors and
  refuses what it cannot enforce.
- `hh-evolution` keeps its kernel-side
  dependency set — the hosted seam is
  documents (`LabDocs`), not a new
  crate edge; the removability stanza
  is unchanged.

## Revisit trigger

Reopen if a fifth proposer family is
admitted or a research family asks to
land `instrument-grade` (the closed
set + the mandatory flag are this
stage's bound); if `CompiledPayload`
candidates need to cross the interface
boundary (a new diff grammar arm, not
a `bytes_hash` rewrite); if `rebase`
must carry a *changed* edit (a new
S1 leg, never a relaxation of the
semantic-op equality); if a hosted
coordinate needs a structured value
(a structural-edit grammar belongs
to the descriptor ABI, not
`coordinate_values`); if `voi` needs
an input beyond `slot_history` (a new
corpus layer is a spec + codec
change); or if `authority_cap` must
grant rather than bound (delegation
upward is a manifest + ADR item, not
a campaign field).
