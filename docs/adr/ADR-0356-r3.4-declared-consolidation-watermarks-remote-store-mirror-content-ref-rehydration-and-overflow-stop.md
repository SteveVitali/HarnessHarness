# ADR-0356: R3.4 context/memory residuals — declared consolidation watermarks, the remote-store mirror, content-ref fold rehydration, and overflow-to-stop routing

- **Status:** Accepted
- **Date:** 2026-10-15
- **Ticket:** R3.4
- **Requirement ids:** DF-S1.19-1 · DF-S1.19-2 · BL-15 · R-2.4.1 · R-2.4.2 ·
  R-2.4.3 · R-2.4.4 · R-2.4.5 · CC1 (consolidation/reclamation ride the landed
  machinery, never a second mechanism) · CC3 (durable-before-visible) ·
  CC6 (removable halves refuse honestly) · CC8 (closed sums gain members,
  never renames).
- **Spec:** §5c (context builder, memory store, consolidation §5c.3,
  retrieval, `ContextWindowExceeded` semantics) · §5c §9 (the staging the
  two DF rows discharge) · R-2.2 (the retention scheduler the reclamation
  leg consumes).
- **Rung (ADR-0024 obligation):** C1 — every leg runs at the offline /
  fixture-verified ceiling; no staging or live claim is made or implied.

## Context

DF-S1.19-1's R2.5 progress note named exactly six residual producer/wiring
members, and DF-S1.19-2's the five residual battery cells. Three of them
had no honest home before this ticket:

1. **Consolidation had no durable record.** `hh-context::consolidate`
   computed `ConsolidationRecord`s, but nothing declared the rule in HIR,
   nothing registered a `context.memory.consolidated` class, and nothing
   scheduled a cadence — so a `session_start` rule would re-fire on every
   resume (no watermark survived the arm boundary).
2. **The fold could not honour `content_ref`.** `KernelContext::fold` ran
   over the event prefix alone; durable `context.memory.written` rows carry
   `content_ref` (an idp/1 address into the ledger blob pool), so a resumed
   run reconstructed every memory as a text-empty skeleton — and a later
   rebind row that forgot the ref would *downgrade* a live body to the
   skeleton.
3. **Overflow had no route to the stop protocol.** `assemble` returns the
   typed `ContextWindowExceeded`, but `AssembledRequest` had no carrier, so
   an over-cap plan could reach the model call — the exact failure the
   §5c `stop` mapping exists to prevent.

The other members (non-`default` policy binding, `by_run`, non-`lexical`
indexes, the hosted/proxy halves, `MemoryUsage`-fed reclamation) were
unwired producers: machinery landed, no runtime path reaching it.

## Decision

1. **Consolidation is a declared rule, executed — never invented.** HIR's
   `RuleAction` gains `consolidate_memories{scope, cadence, guards,
   consolidator, retention?}` (CC8 member-add; landed spellings unchanged);
   `rule_from_action` resolves the sealed declaration into the
   `ConsolidationRule` the driver executes, malformed members failing
   typed. The driver fires eligible rules at the run's durable boundaries —
   `session_start` at open (ahead of the first `decide`), `idle` at finish,
   `rate_limit` at both — and an armed rule with no memory boundary is the
   typed `UnbackedPort{kind: "consolidate"}` refusal, never a silent skip.
2. **`context.memory.consolidated` is the one watermark (I-FOLD).** The
   audit-grade durable row records `{rule_id, cadence, trigger,
   input_watermark, last_success_watermark, applied[], skipped_*,
   deferred[], usage, retention_*}`; the fold carries
   `last_success_watermark` forward so the cadence gate reads the durable
   prefix, never a shadow copy — `session_start` does not re-fire across a
   resume. A rule's declared `retention` runs the *landed* R-2.2
   `evaluate_retention` scheduler over the memory blob pool (CC1 — no
   second mechanism); each `lifecycle.ledger.tier_transition` lands durable
   before the consolidated row reports `bound`/`reclaimed` (CC3).
3. **The remote store is a coherent mirror, not a second truth.**
   `KernelStore::{Local, Remote}`: the `Remote` arm is `RemoteStore<
   Box<dyn StoreChannel>>` over the packaged `hh-memory-store`
   `plugin_abi/1` channel. Every mutation lands on the far side *and* the
   mirror; retrieval indexes, lifecycle, usage and stale state fold the
   mirror. `forward_read` ships each indexed `record_read` to the far side
   so `memory_usage` agrees on both sides of the channel — one stamp per
   side, never a double-counted mirror read. A channel fault is a typed
   `ChannelFault` latched on the store, never guessed through.
4. **Fold rehydration is honest or absent.** `KernelContext::fold` takes
   the ledger `Store`; a row's `content_ref` resolves through
   `Store::get_blob` (JSON bytes → `MemoryContent::Structured`, else
   `Text`). A missing or unreadable blob leaves the row a skeleton —
   `index_text()` empty, provenance intact — never fabricated body text.
   Rebind-generated `context.memory.written` rows preserve the source
   `content_ref`, so a duplicate row can never downgrade a body.
5. **Overflow routes to the stop protocol.** `AssembledRequest.overflow`
   carries `Option<CompactionRequired>`; `stage01_disposition` maps the
   builder's `ContextWindowExceeded` to `Stop{CompactionRequired}`, and
   the driver stops `context_exhausted{required_tokens, cap}` — the closed
   spelling on `control.decision`/`lifecycle.run.finished` — with the
   overflow durable on the `context.assembled` row first. No model call
   fires on an overflowed plan; the reserved omission item's tokens count
   toward the requirement (the kernel-reserved candidate is never a user
   omission).
6. **`by_run` and non-`lexical` indexes are projections of what was
   written.** The artifact-layer projection indexes every
   `context.memory.written` by run at fold time; `by_run{run_id, classes}`
   and `structural` queries enumerate it through `retrieve_indexed` over
   the `structural_index` — the same fold source for local and remote.

## Consequences

- DF-S1.19-1 and DF-S1.19-2 discharge `DONE`; BL-15 closes.
- `context.memory.consolidated` is a new audit-grade `context.*` class in
  the `hh-ledger` class table — a registered schema addition; the hosted
  lowering maps it `hint`-grade like the sibling memory classes.
- The `MemoryPort` trait gains `consolidate`; `DriverConfig` gains
  `consolidation_rules`; `AssembledRequest` gains `overflow` — all
  additive; every pre-existing constructor/fold replays unchanged.
- Size: ~1,260 changed source lines (excl. generated + the new
  `tests/r3_4.rs` battery, 1,542 lines, and ~77 lines of constructor
  updates in existing batteries) — under the ticket's 1,500 budget; the
  pre-registered R3.4a/b split was not needed.

## Alternatives considered

- **Persist consolidation state in a shadow table / session memory.**
  Loses (I-FOLD): the watermark must survive resume, fork and rebuild
  identically — the durable row *is* the state; any side copy is a second
  truth to keep honest.
- **A new reclamation path beside `evaluate_retention`.** Loses (CC1):
  R2.2's scheduler already owns tier transitions, leases and the durable
  `lifecycle.ledger.tier_transition` record; a memory-specific copy would
  diverge on exactly the edge cases the scheduler is tested on.
- **Fold-time body fabrication for missing blobs** (empty string treated
  as content). Loses: an unreadable `content_ref` is corruption or a
  pruned blob — serving invented text is precisely the silent-degrade the
  honest-refusal rule forbids; the skeleton keeps the row's identity and
  provenance and withholds the body.
- **Let overflow reach the model call with a truncated plan.** Loses: the
  §5c contract is `ContextWindowExceeded → stop`; a silent truncation
  serves a plan the policy never approved and misreports occupancy.
- **Interpret `context_policy` variants by fuzzy matching.** Loses:
  `policy_for_variant` is one exact normalization table (`hh/` and
  `context_policy/` spellings, optional `@1`); an unknown ref answers the
  typed refusal at arm — a silent `default` substitution would arm a
  policy the definition never declared (CC6).

## Revisit trigger

Reopen if a second `ConsolidatorKind` lands (re-check whether the
watermark row's `applied[]` shape stays one rebind vocabulary or gains a
per-consolidator arm), if a remote `StoreChannel` ever supports
server-side index state (re-check the read-forwarding contract — the
`memory_usage` agreement is then the channel's obligation, not the
mirror's), or if the omission item stops being kernel-reserved (the
stress battery's accounting exclusion must then move into the policy).
