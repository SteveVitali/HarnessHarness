# ADR-0366: R4.5d hosted provider dialects — the Anthropic Messages + OpenAI documents, the Chat Completions surface choice, and coordinate-only credentials

- **Ticket:** R4.5d

  + AC-R-2.3.1-11 members) · BL-31 · R-2.3.1 · R-2.3.3 · ADR-0253 ·
  ADR-0363 (the `live-executed` evidence class + spend ledger the legs

- **Spec:** §5b.1/§5b.2 (the model boundary — `Transport`/

## Context

R4.5b landed the live `Transport` for the *local* family
(`openai-compatible@1` over plain-HTTP loopback) and R4.5c admitted the
TLS stack HTTPS needs. DF-S1.18-1's residual then named the
hosted-provider members: provider-faithful dialect documents for the two
families the operator ruled (2026-10-20, Round-4 GATE DECISIONS —
"Anthropic + OpenAI + local"), a live `CredentialPort` that turns a
broker `credential_ref` into a header without ever letting the value
touch a record, streaming decode per family, usage → cost, and
AC-R-2.3.1-11's live out-of-process variant. Four decisions are this
ticket's to own: what the provider documents bind, which OpenAI surface
to admit, how Anthropic's protocol-mandatory `max_tokens` becomes
contract, and where the credential material may live.

## Decision

- **D1 — the hosted pair are `WireDialect` documents bound on the same
  normalized codec.** `anthropic-messages@1` and `openai@1` are
  first-class documents in `hh-gateway::dialects` beside
  `openai-compatible@1` — `to_json()` canonical bodies, `content_id()`
  `dialect.1` addresses, debt-recorded rules per family (ADR-0119 d.5:
  every class-mapping rule carries its assumption/counter-case/pinned
  evidence/removal test). Provider-owned facts that a document cannot
  express declaratively live in the family's adapter —
  `anthropic.rs`'s `MessagesTranslator` reshapes the Messages SSE
  grammar (`event:`/`data:` envelopes, `content_block_*` deltas,
  `input_json_delta` partial-JSON assembly, `thinking_delta`/
  `signature_delta`, usage split across `message_start`/`message_delta`)
  into the canonical `WireFrame` stream; `HttpModelTransport` dispatches
  on the document's declared `family` for path (`/messages` vs
  `/chat/completions`), accept header, translator pick and auth shape.
  No second wire codec, no second event vocabulary (CC1; ADR-0364 D1).

- **D2 — the admitted OpenAI surface is Chat Completions, not the
  Responses API.** `openai@1` spells hosted OpenAI's canonical Chat
  Completions surface (`api.openai.com/v1/chat/completions`):
  `Authorization: Bearer`, SSE `chat.completion.chunk` deltas
  terminated by `data: [DONE]`, usage on the terminal chunk
  (`stream_options.include_usage`) or the non-streaming body,
  `implicit_prefix` cache semantics. The R4.5b-landed
  `ChatChunkTranslator` is already corpus-proven across the thirteen
  normalized shapes, so the family decodes through machinery that
  exists — a faithful adapter over a proven grammar. The Responses API
  would have required a second translator plus its own corpus for no
  contracted delta; if a later ticket needs it, it is a new dialect
  document and a new ADR, not an extension of this one.

- **D3 — Anthropic's protocol-mandatory `max_tokens` is a required
  `provider_params` key, not a silent default.** The Messages API
  rejects a request without `max_tokens`. The dialect document encodes
  this as `plan_schema.required_keys = ["max_tokens"]`: a lane that
  reaches the render without it fails a typed refusal at plan
  validation (`required_keys` enforcement upstream of the wire), never
  a provider round-trip spent discovering the omission and never an
  invented ceiling. The member rides `provider_params` so the schema
  surface is unchanged (CC7 — drift stays clean).

- **D4 — credentials are coordinate-only; the header material exists
  only inside `send`.** `BrokerCredentialPort` (the live
  `CredentialPort`) resolves the `credential_ref` *coordinate* at bind —
  R4.5d admits the `env:NAME` spelling (`SecretSource::LaunchEnv`, the
  channel `live-verify.sh` provisions `ANTHROPIC_API_KEY`/
  `OPENAI_API_KEY` through); other source kinds answer a typed
  `CredentialUnavailable` refusal, never a fallback. `bind` proves the
  coordinate serves a value, discards the value, and returns a handle
  carrying only `binding_id` (`launch_env:NAME`) + `provided`. The
  ledger's `credential_binding_id` records the coordinate; the value is
  re-resolved by `header_secret` *inside* `HttpModelTransport::send`
  immediately before bytes leave and dropped on return — it never lands
  in a `WireFrame`, a ledger row, an error message, a child env, a log
  line, or an evidence record (records say `provided: yes/no`,
  ADR-0363 D2). The AC-R-2.3.1-11 live out-of-process variant binds
  `HttpModelTransport` + `BrokerCredentialPort` in the `hh-gateway-stub`
  slot on `transport: "live"`: only the coordinate crosses the stub's
  canonical-JSON boundary; the material stays in the stub process's
  launch env.

## Consequences

- Three provider families now ride one codec + one normalized event
  vocabulary: `openai-compatible@1` (local), `openai@1`, and
  `anthropic-messages@1` — each decoding its committed corpus
  byte-identically (`golden_corpus_thirteen_shapes` legs re-run per
  family; the `anthropic_*`/`openai_*` cells in
  `crates/hh-gateway/tests/r4_5d.rs`).
- The credential path is proven leak-free by test
  (`transport_injects_*` + `credential_bind_*` cells sweep frames,
  events and records for a planted value — it never appears) and by
  the live legs' leak sweeps (`docs/build/reports/live/2026-10-21-*.json`).
- Spend is accounted: both live legs debit `SPEND.jsonl` at the
  pinned-pricing measured cost (ADR-0363 D4); the R4.5d USD 5
  allocation is untouched beyond ≈$0.001 measured.
- A `credential_ref` naming an unprovided or unadmitted source fails
  closed at bind/arm time — honest refusal, never a bare request.
- `openai@1`'s Chat Completions choice means the Responses API remains
  unadmitted surface; a provider that deprecates Chat Completions
  triggers this ADR's revisit rule, not a silent re-point.

## Alternatives considered

- **OpenAI Responses API as the `openai@1` surface.** Rejected (D2): a
  new translator + corpus for no contracted delta; Chat Completions is
  the canonical hosted surface and reuses the proven grammar (CC1).
- **Credential material resolved once at bind and retained in the
  handle.** Rejected (D4): a `CredentialHandle` crossing
  boundaries — lane documents, the OOP stub request — must carry no
  material; coordinate-only is what lets the same handle spell appear
  in a ledger row safely. Re-resolving inside `send` also shortens the
  value's lifetime to the call.
- **Defaulting `max_tokens` when absent.** Rejected (D3): a fabricated
  ceiling is a silent degrade; the provider's protocol requirement is
  contract, enforced as a typed refusal.
- **A third transport per provider.** Rejected (D1/CC1): one
  `HttpModelTransport`, family dispatched from the bound dialect
  document — a per-provider transport is the second-spelling defect.

## Revisit trigger

- A provider deprecating the admitted surface (Chat Completions;
  Messages `2023-06-01`) or changing its SSE grammar opens a new ADR —
  the dialect document's `version` bumps, never an in-place re-spell.
- Admitting a non-`env:` credential source kind (`vault:`/`keyring:`/
  `external:`) extends `source_from_ref`/`source_from_binding` under a
  new ADR — the coordinate grammar is closed today.
- `probe_profile` + live-signal routing (R4.5e, the DF-S1.18-1 closer)
  consumes these documents' cache/usage semantics; a contradiction
  there revisits the semantics declared here.
