# ADR-0302: S4.10 `hh-web` surface rulings

- **Status:** Accepted
- **Date:** 2026-09-27
- **Ticket:** S4.10
- **Requirement ids:** R-2.11.2¹
- **Spec:** §7.2 (the instrument, V1–V11, P1–P13, the security battery,
  the op allow-list, R-D-1…8); ADR-0170…0172; ADR-0301
- **Rung (ADR-0024 obligation):** **C2** — the web surface + instrument — the C2 surface rung.

## Context

The C1 instrument is a *browser surface over binding (c)* — the third
party in §7.2's picture (browser ↔ surface ↔ kernel). The ticket owns
the surface's trust model: which requests the gate admits, which ops
the API forwards, how sessions and provenance are injected, how the
declared `SinkPolicy` and the secret scrub apply to served payloads,
and what the static shell may do before a token exists.

## Decision

- **D1 — the gate is the whole posture, before routing and before any
  body byte is interpreted.** `hh_web::gate` enforces, in order:
  `?token=` → 400 (P9); `Host` == bound authority → 400 (P3/DNS-rebind);
  `Origin` present and not own/trusted → 403, `Origin: null` → 403;
  `Sec-Fetch-Site` ∉ {same-origin, none} → 403; `Authorization: Bearer`
  constant-time → 401 on every non-shell route (P2). Mutating calls
  additionally require `x-hh-script: 1` + `Content-Type:
  application/json` + same-origin fetch metadata (P4) — a simple HTML
  form cannot produce any of the three. `GateConfig::validate` refuses
  off-loopback binds without `--trusted-origins` (P5). Every refusal is
  a bare status — no diagnostic (P2).
- **D2 — the API is one route, the op table is closed.** `POST /api`
  carries `{op, params}`; `ops::classify` admits the C1 set and nothing
  else — unlisted ops (`submit`, `fork`, `rollback`, `open_session`,
  `close`, `register`, `kernel.export`, …) get `Refused{op_not_admitted}`
  before the kernel is touched. The browser therefore *cannot* open a
  run, write a record, or mint a session — AC-8's "no surface path
  opens a run outside an experiment" holds by enumeration, not by
  convention.
- **D3 — the surface owns sessions and provenance; the browser owns the
  run id.** `Sessions` lazily opens one `attach` (read-only) session per
  inspected run and a `resume` writer session only when a declared write
  needs it — both declared `client{kind:"web", sink, ui_caps}` (ADR-0301
  D6). Browser params never carry `session_id`/`responder`/
  `idempotency_key` — `call_for_run` strips and re-injects them
  (`responder{subject_ref, surface_session_ref}` + `web:<seq>`
  request ids — P12). The surface greets `hello` lazily once (`kind:
  "web"`), so the kernel's `NotInitialized` gate stays honest.
- **D4 — ViewModels are labelled assemblies of canonical results, never
  recomputations.** `views.rs` dispatches `view.<id>` to the canonical
  op set for the view (V1 `run_index`; V2 `lab.eval.render_scorecard`;
  V3 `project{context_view}` + the `context.assembled` rows; V5
  `run_summary`/`checkpoint`/`account`/`head`/`read`-tail; V6
  `lab.leaderboard.*`; V7 `trace_view`/`cost_view`/`effect_ledger` +
  permission rows; V8 the durable `security.permission.*` partition; V9
  session/delivery lifecycle rows + `kernel.status`; V10 fleet run_index
  + `control.work_item.*`/`measurement.debt.*`; V11 `run_summary`/
  `account`/`head`/`describe`/`list_leases`). The browser renders the
  envelope (`{view, …members}`) — R-D-1…8 ride the records verbatim
  (`n/a{reason}`, `report_id`/`view_hash`, badges), and a `view.<id>`
  outside the ten is `op_not_admitted` (AC-15).
- **D5 — the V8 inbox fold is a set difference over durable rows, not a
  permission decision.** `v8_inbox` reads the canonical
  `security.permission.*` partition and serves `pending − decided`. The
  *classification* is the ledger's own class distinction; the offered
  options render verbatim from each pending row (AC-7's "renders only
  its `options[]`"). The surface decides nothing — `respond_permission`
  lands through the declared write path with injected provenance.
- **D6 — the `SinkPolicy` is declared upstream and enforced
  twice.** The surface declares its policy in `client.sink` (the kernel
  lowers rows by it and mints `measurement.export.delivered`); the
  surface independently enforces the *serving* half on assembled
  ViewModels: `content`/`diagnostic`-class members outside the policy's
  `content_classes` are replaced with `{"withheld": "<class>"}` and
  strings beyond `max_field_bytes` truncate with a marker. A
  `{accounting}`-only sink sees the run's shape, never its content
  (P8's "the sink, not the surface, decides").
- **D7 — every served payload sweeps `hh_secrets::redact` before it
  leaves** (AC-6(g)): the LT battery's canary battery runs over the
  canonical JSON text — a planted value (or a pattern hit) tombstones as
  `REDACTED[detector:label]`, never echoes. The kernel masks at source;
  the surface's sweep is SV-3 defence-in-depth at the wire. Detector
  set: registered patterns + `--canary <id>:<value>` declarations (the
  mask set stays empty — live credentials are the broker's, never the
  surface's).
- **D8 — the static shell is the only unauthenticated surface** (P2's
  single exception): `GET /`, `/app.js`, `/app.css` carry no data — the
  shell is the token-entry page itself. Every response (shell included)
  carries the P7 hardening set (`default-src 'self'`, `frame-ancestors
  'none'`, `base-uri 'none'`, `form-action 'none'`, `no-referrer`,
  `nosniff`, `no-store`, `Connection: close`). UI and API share the
  bound origin (P13); the JS fetches same-origin only, always with the
  bearer + script header.
- **D9 — serial server, `Serve`/`serve_n` bounded.** Same construction
  as the kernel binding (ADR-0301 D9): the instrument's human is its
  only caller; one connection at a time keeps the request order the
  audit order. `serve_n` bounds the loop for the socket-level tests.

## Consequences

- The browser can mint *only* the three declared writes, each a named
  kernel op with responder provenance + a request id — there is no
  ambient surface mutation (P12, AC-1's "no surface operation mutates a
  record without a kernel/Lab call").
- `open_session` is *not* admitted at the API — the surface mints its
  own sessions; the browser can never hijack another session's handle
  or open a run (AC-8).
- Refusals are bare statuses; admitted failures carry the kernel's
  typed `{error, message}` verbatim (AC-10's tampered-fixture render is
  the kernel's `Tampered{kind}` passthrough, honest).
- The shell's unauthenticated stance is the documented P2 exception —
  it leaks no data (a static build artifact); all data routes are
  authed. A stricter reading (token-in-fragment delivery) was rejected
  as URL-adjacent — the paste-token form keeps the capability out of
  URLs entirely (P9).

## Alternatives considered

- **A per-view route table** (`GET /view/runs`, `POST /approve`) —
  rejected: more routes = more gate surface; one `POST /api` keeps the
  admission table enumerable and the P4 legs uniform.
- **Streaming events over SSE/WebSocket** — rejected for C1: the serial
  server cannot multiplex push; the monitor's `from_seq` read-tail
  cursor is canonical, honest, and keeps ephemeral discipline (frames
  are never persisted client-side — AC-5).
- **Admitting `open_session{attach}` to the browser** — rejected: a
  raw-session handle in browser params invites session confusion; the
  run-id → session mapping is the surface's own record (D3).
- **Kernel-side scrub only** — rejected: AC-6(g) says "leak nothing
  through any response or export"; the surface's `redact` sweep makes
  the surface's own assembled members (ViewModel labels, withheld
  markers, error passthroughs) subject to the same invariant.

## Revisit trigger

Reopen when (a) the launcher slice (C2/Stage 5) adds write ops
(`submit`, `fork`, editor ops — the admission table widens then, not
now), (b) the surface ecosystem binds its generated client (HUMAN-H1 —
the `NetClient` stand-in is the declared proxy), or (c) multi-user or
non-loopback serving is authorised (the P5 gate + serial model both
change then).
