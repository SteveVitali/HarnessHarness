# ADR-0285: S3.8 context/memory evaluation rulings

- **Status:** Accepted
- **Date:** 2026-09-24
- **Ticket:** S3.8 (`054_S3.8__context-memory-eval.md`)
- **Requirement ids:** R-2.4.1…R-2.4.5 (S3 slices)
- **Spec:** §5c.1–§5c.5 (the Stage-3 executables: `clear_tool_results`,
  `structural_index`, the compliance chain, `trace_predicate` oracles,
  `opacity_dynamic`, re-lowering, `select_target`, `test_procedure`,
  skills round trip, hook guards) · owning ADRs ADR-0072…0086 ·
  ADR-0156 D1

## Context

S3.8 lands the Stage-3 context/memory executables. The ticket owned
these rulings:

1. **What `structural_index` extracts.** §5c.3 declares the
   `structural{anchors, mentioned_idents}` query and leaves the index's
   extraction to OQ-203; Stage 3 needs *some* deterministic index, and
   an AST-derived code index is explicitly OQ-203's open question.
2. **Whether `CompileHint::Instruction` is an authored override.**
   `select_target`'s override leg must distinguish "the author asked for
   a target" from "the surface spelled the default" — otherwise every
   C0 procedure reads as an override and the typed-refusal leg never
   runs.
3. **What an infeasible explicit target does.** §5c.5's
   `select_target` is total over procedures; a requested
   `workflow_node`/`subagent_task` that cannot serve must not silently
   fall back to `instruction` (AC-R-2.4.5-4).
4. **Which rows the context metrics fold emits.** §5c.2–§5c.4 name the
   process metrics (reacquisition, repeated action, recall probe,
   overhead, the compliance chain, `memory.validity_rate`, withheld,
   over-invalidation, P(activated | delivered)); each needs a fold
   definition and a catalogue declaration.
5. **What `test_procedure` reports.** AC-R-2.4.5-6 wants
   `ProcedureConformance` under instrument-budget semantics with typed
   refusals — an unbudgeted arm, an arm without `MatchSpec`, a revoked
   fixture (`stale_by_dependency`), an undecidable fixture
   (`unknown`).
6. **What skill export loses.** §5c.5's export lifts a procedure back
   to a skill tree; claims (`allowed-tools`) are never grants, scripts
   become opaque payloads with declared `exec` effects, and every
   dropped field is a declared loss.
7. **What a hook guard may return.** The guard vocabulary is
   `{narrow, additional_context?, replacement_proposal?}` — `allow` is
   refused as a typed guard error (AC-R-2.4.5-12), checked before the
   generic narrow-shape validation so the refusal names the real fault.

## Decision

1. **`structural_index` is a token-shape view.** Anchors are path-like
   tokens (`/` separator or dotted file names) plus artifact paths;
   `mentioned_idents` are tokens with an explicit identifier boundary
   (`_`, `::`, or an internal camel-case transition) at ≥ 4 chars. The
   index is a `View`-stamped fold (`ViewKind::StructuralIndex`),
   rebuild-equal under the same fold; `structural_pagerank` is integer
   math over the `mentions` edges. A `structural` query is executable
   at Stage 3 — the C0 `IndexUnavailable` refusal for it is retired
   (the acceptance test now asserts the executable contract);
   `similarity` stays `EmbedderUnpinned`. The on-demand fold is the
   second implementation: indexed and on-demand retrieval agree
   deterministically (AC-R-2.4.3-7).
2. **`CompileHint::Instruction` is the default spelling.** Only a
   *non-default* hint or an explicit profile/definition target is an
   authored override; the default outcome reports
   `reason = default_instruction`.
3. **Explicit infeasible targets refuse typed.** `subagent_task`
   returns `DelegationUnavailable`, an infeasible `workflow_node` a
   typed infeasibility, a body exceeding the surface budget
   `UnexpressibleSurface` — never a silent instruction fallback. An
   unexpressible *default* still falls through to `instruction`.
4. **The fold emits counts plus two derived rates.** Counts:
   `harness_overhead.{tokens,model_calls}`, `compaction.{applied,
   tokens_freed,model_calls}`, `reacquisition_count`,
   `repeated_action_count`, `memory.{delivered,activated,followed,
   promoted,withheld,over_invalidation}`; rates in ppm:
   `recall_probe_hit_rate`, `memory.validity_rate =
   delivered/(delivered+withheld)`, `memory.activated_given_delivered =
   activated/delivered` — `None`/`n/a` on an empty denominator, never
   a fabricated zero. Every emitted row has a `MetricDeclaration`.
   `trace_predicate` oracles (`reacquisition`/`repeated_action`/
   `recall_probe`) fold events alone and render `n/a{class}` when the
   evidence rows are absent.
5. **`test_procedure` returns `ProcedureConformance{validity, cost}`.**
   Unbudgeted arm → typed refusal; no `MatchSpec` → `MissingMatchSpec`;
   a revoked or transitively-stale fixture → `stale-by-dependency`;
   undecidable → `validity = unknown`; a clean fixture reports `valid`
   with its measured cost under the instrument budget.
6. **Export declares losses and keeps claims distinct.** `export` on a
   non-procedure input is a typed refusal; the skill tree carries
   `allowed-tools` as claims (`allowed_capabilities` empty until
   sealing), scripts as opaque `CompiledPayload` with declared `exec`
   effects, references/assets as content-addressed artifacts, and a
   `declared_losses` list. Lift → export round-trips the carried
   members.
7. **Guard `allow` is `GuardReturnsAllow`.** Guard validation checks
   the `allow` return before the narrow-shape check so the refusal is
   typed by cause; `narrow` may carry `additional_context` /
   `replacement_proposal` and nothing else; guard `invoke`s must name
   granted reads.

## Consequences

- The AC-R-2.4.1-12/-13, AC-R-2.4.2-8/-9, AC-R-2.4.3-9,
  AC-R-2.4.4-11/-12, AC-R-2.4.5-4…7/-10/-12 rows are executable: five
  new registered recipes (`lab/context-builder-v1`,
  `lab/memory-compliance-v1`, `lab/memory-validity-v1`,
  `lab/procedure-execution-v1`, `lab/retrieval-index-v1`), the
  `trace_predicate` oracle set, the `context_metrics` fold, the
  re-lower `dropped_items` evidence, the `select_target` corpus sweep,
  `test_procedure`, and the skills round trip.
- The `structural` query's C0 `IndexUnavailable` contract is
  superseded by the executable Stage-3 contract (the acceptance test
  change is the record).
- An AST-derived structural index remains OQ-203's open question; the
  token-shape extraction is this stage's declared scope, swappable by
  a later index without a schema change.

## Alternatives considered

- **Fold `memory.validity_rate` as withheld/(delivered+withheld).** The
  spec's direction is Higher-is-better for a validity rate; the
  delivered share is the honest spelling.
- **Silent fallback to `instruction` on infeasible explicit targets.**
  Rejected — AC-R-2.4.5-4 requires the typed refusal to be observable;
  fallback would make an authored target silently meaningless.
- **A dedicated `ExportError` per loss kind.** The declared-losses list
  on the export result already names each loss; a second error
  channel would duplicate the accounting (CC3).

## Revisit trigger

OQ-203 resolves to an AST-derived structural index, or a profile needs
a structural extraction the token shapes cannot express — the index's
extraction predicates are the seam (`is_anchor`/`is_ident`), the view
and ranker stay.
