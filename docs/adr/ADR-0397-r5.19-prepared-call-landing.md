## Context

Packet B admits the retained-view→wire call as one owner-bound seam
with a fixed order: **retained view → existing serialization +
primary bounds → whole-vector Account reservation → sealed provider
plan → durable request → deadline-bounded dispatch → durable
actual/unknown usage → charge/release → guard** (B.1 item 5; B.2
names the gateway the seam owner). B.3 homes the prepared/sealed
call facts on the existing `model.call.*`/`measurement.*` families
(`{selected_view_ref, sealed_plan_ref, request_ref,
dispatched_bytes_ref, attempt_joins[], policy{intended, served}}` —
a hash without accessible content cannot demonstrate treatment).
B.5 fixes the recovery semantics (retries reuse the same
reservation; a restart never resets a real elapsed deadline;
logical reversal never replenishes physical capacity). The
admission fixes *what* the order is and *where* its facts live; it
does not fix the staged-call API shape, the admitted bound
vocabulary, the deadline's durable inputs, the minted payload
members, or the refusal/verdict alphabet — those are this ticket's
owned landing decisions.

## Decision

1. **Home and shape: `hharness_gateway::prepared` — a staged
   `PreparedCall`.** `prepare(account, lease, dialect, endpoints,
   credentials, PrepareInputs)` runs legs 1–5 of the order and
   returns a staged call holding `view_bytes`/`view_ref` (the
   serialized `retained_selection/1` member, consumed unchanged —
   `to_canonical_string`, idp address), `request_bytes`/`request_ref`
   (the sealed wire bytes — exactly what reaches the transport),
   `sealed_plan_ref` (`plan.content_id()`), the held
   `reservation_id`, `deadline_ms` and the `estimate_count` floor.
   `dispatch(account, lease, presented_plan, transport, sleeper,
   attempt_policy)` runs legs 5–8 against the staged facts only.
   Durable rows mint through the run's fenced writer
   (`Producer::kernel("hh-gateway/1")` + kernel provenance — the
   `Account::mint` convention); scope `turn_id`/`model_call_id`
   follows the `model_call ⊂ turn` chain. No new dependency edge:
   gateway already owns budget/ledger/telemetry.
2. **Bound vocabulary: five token primaries + `model_calls`
   required; `retries`/`time.wall_ms` admitted when declared.**
   `REQUIRED_BOUND_DIMS` =
   `tokens.input.{uncached,cache_read,cache_write}` +
   `tokens.output.{visible,reasoning}` + `model_calls` — every
   required role must carry a bound (`model_calls` ≥ 1: a call
   dispatches at least once); any other dimension refuses
   `UnadmittedBound`. The declared input roles must cover the
   *existing* serialization's `codec::estimate_tokens` floor —
   under the floor is `Underbounded` (the reservation cannot
   honestly cover the request). `tokens.input/output.total` stay
   derived — never bound, never charged (REQ-E-207).
3. **The reservation rides inside the sealed plan.** `prepare`
   takes the whole-vector `Account::reserve` (R5.12, consumed
   unchanged — `Unfunded` maps the typed `BudgetError` and the
   owner already ledgers `reserved{outcome:refused}`), then sets
   `plan.budget_reservation_id` **before** `codec::serialize(&plan)`
   so the gateway's reserve-before-spend check reads the
   reservation off the sealed plan itself. Endpoint allowlist and
   credential *coordinate* bind at prepare through the admitted
   ports (`InvalidPlan`, `CredentialUnavailable`) — no secret
   material enters `PrepareInputs`.
4. **Deadline = `created_at_ms` + tightest path `time.wall_ms`
   hard cap — one function of durable inputs.** The origin is the
   seq-0 `lifecycle.run.created` `created_at_ms.value` member
   (R5.10, consumed unchanged); the cap is the minimum `time.wall_ms`
   hard over the leaf→root budget path (an ancestor cap constrains
   the same elapsed clock). `created_origin_deadline` recomputes it
   from the ledger and the store's own clock at prepare, at
   dispatch, at every attempt, and at drain — identical across
   resume/approval waits, never session arithmetic. Absent cap →
   no deadline; cap with absent origin → `OriginMissing`;
   `now < origin` → `UntrustworthyOrigin` (never a fabricated or
   backdated origin); `now ≥ deadline` → `DeadlineExpired`.
5. **Dispatch gates in order: deadline → sealed-byte verify →
   outstanding reservation → durable request → bounded attempts.**
   Re-derived deadline first (`DeadlineExpired` + drain); the
   presented plan must serialize to exactly the sealed request
   bytes (`PreparedBytesMutated{sealed_ref, observed_ref}`); the
   reservation must still be outstanding (`MissingReservation` — an
   unfunded call dispatches zero). `model.call.requested` lands on
   the **first** dispatch only — the `model_call` scope opens once
   and retries reuse it (`AlreadyTerminal` on a second dispatch
   after a terminal). The payload reuses `events::call_requested`
   with `view_hash` = `view_ref`, `plan_hash` = `sealed_plan_ref`,
   `request_ref`, `budget_reservation_id` and `token_estimate` —
   B.3's `selected_view_ref`/`sealed_plan_ref`/`request_ref`
   candidates carried on the admitted row.
6. **Attempts run the prepared bytes; the terminal class stays
   verbatim.** `run_attempts` drives the retry policy over the same
   `request_bytes` every attempt (B.5: retries reuse the same
   reservation); a per-attempt deadline gate stops with a genuine
   local `cancelled` (`deadline_expired:` sentinel,
   `retry_class=permanent`) — never a socket timeout. Drained
   `model.call.attempt.*` rows append in emission order before the
   terminal (the `ModelGateway::stream` precedent). Terminal:
   `model.call.completed{usage{available,record}}` /
   `model.call.failed{error{…}}` — the provider's typed class lands
   verbatim: `timeout{…}` stays `timeout{…}` (a socket timeout is
   never remote cancellation, AC-2), served-model drift under
   `substitution_allowed=false` → `failed{served_model_mismatch}`,
   a terminal-less stream → `failed{stream_decode}`.
7. **Reconcile through the owning `Account` — charge per admitted
   primary, release the remainder, drain on expiry.** The durable
   terminal's `usage` becomes the charge vector plus
   `model_calls:1` and `retries:attempts-1` (the call is physical
   use even when token usage is absent); one `charge` per
   `(source_event=terminal EventRef, dimension)` with
   `reservation_id` — the landed dedup makes a replayed reconcile a
   no-op. `release` frees what no charge touched; expiry's
   `drain_reservation` releases the outstanding claim exactly once
   (`released{reason:release}`) — a release never refunds physical
   use. Absent usage charges nothing and stays unknown exposure on
   the durable rows (the R5.13 fold's `usage_unavailable` /
   `ambiguous_failure` — never zero). Charge/release failures are
   typed skips: the terminal row and the physical-use fold keep the
   exposure; the call never silently re-charges.
8. **Typed refusal/verdict alphabet (AC-2).**
   `PrepareRefusal` = `Unbounded`, `UnadmittedBound`,
   `Underbounded`, `Unfunded`, `InvalidPlan`,
   `CredentialUnavailable`, `OriginMissing`,
   `UntrustworthyOrigin`, `DeadlineExpired`, `Ledger` — every
   variant is a pre-dispatch verdict: zero bytes, and no ledger
   rows beyond the owner's own `reserved{refused}`.
   `DispatchVerdict` = `Completed{message, usage, attempts}`,
   `Failed{error, usage_charged, attempts}`, `DeadlineExpired`,
   `PreparedBytesMutated`, `MissingReservation`, `AlreadyTerminal`,
   `Ledger` — each names the durable rows it staged.

## Consequences

- Every prepared call leaves an auditable durable chain: the
  `requested` row binds `view_hash`/`plan_hash`/`request_ref`/
  `budget_reservation_id`/`token_estimate`; attempt rows join per
  attempt; the terminal carries actual or explicitly-unknown
  usage — the B.3 candidate set landed on admitted classes.
- Unbounded and unfunded calls dispatch zero bytes with zero call
  rows; expiry blocks new dispatch and drains the committed claim
  to a known state — B.5's recovery semantics realized.
- REQ-E-207 / REQ-E-006 / REQ-D-006 (and merged aliases
  REQ-E-005/105/106) gain their primary-owner engineered D/E
  evidence row (`crates/hh-gateway/tests/r5_19.rs`, 9/9); the
  targets keep `planned; unmet` — R/P and actual-execution legs
  (fixture-vs-live enforcement, cold-start match, the R5.20 wire
  join and downstream consumers) stay owed per the coverage
  register; R5.6/R5.12/R5.13 contributor evidence is consumed, not
  re-discharged.
- Recorded size deviation: 1,933 changed source/test lines against
  the ≤1000 contract trigger (~1.93×) — adjudicated AMEND by the
  scoped split review (single atomic ordering unit; the proposed
  prepare/dispatch cut splits AC-1/AC-2 mid-predicate and leg (b)
  would still exceed); recorded here per the `4ec29023` ruling,
  never a precedent for unmeasured growth.

## Alternatives considered

- **New `model.call.prepared.*` event classes** — rejected: B.3
  homes the prepared/sealed facts on the existing `model.call.*`
  family; a second class duplicates the scope lifecycle and splits
  the audit the charged `model_call_id` chain already provides.
- **Mint `model.call.requested` at prepare** — rejected: the
  durable request is the dispatch-opening fact; minting at prepare
  would ledger un-dispatched calls and force a cancel/absence
  vocabulary the admission does not name.
- **Session-clock deadline (prepare-time `now + ttl`)** —
  rejected: a resume or approval wait would move or reset the real
  elapsed deadline; only the durable origin × durable cap survives
  restart/wait (B.5).
- **Charge the declared bounds, not the recorded usage** —
  rejected: `charge` reconciles *actual/unknown* usage through the
  owner (B.1 item 5); declared bounds are the reserve's ceiling,
  never the spend.
- **Split at the prepare/dispatch seam (worker's Option A)** —
  rejected by the `4ec29023` scoped review: no documented seam
  (B.2 binds the whole order to one owner; B3's sole contingency is
  consumed by the R5.10/R5.19 boundary), the cut splits AC-1/AC-2
  mid-predicate (prepare refusals verify only via zero dispatch;
  dispatch refusals need a prepared artifact; B.5 retry-reservation
  spans both), and leg (b) ~1,230 still exceeds the trigger.
- **Treat a socket timeout as remote cancellation** — rejected:
  `timeout{…}` stays `timeout{…}`; the run's own deadline stop is
  the only `cancelled` spelling, and it is a genuine local
  cancellation (AC-2).

## Revisit trigger

Reopen if: (a) the R5.20 wire integration leg requires different
minted members on `model.call.requested`/terminal rows — amend this
record's Consequences; (b) a newly admitted primary/overhead
dimension enters the cap match — `REQUIRED_BOUND_DIMS`/
`OPTIONAL_BOUND_DIMS` extend by admission, never silently; (c) a
predecessor contract consumed here changes (`Account::reserve`/
`charge`/`release`/`physical_use`, `created_at_ms` origin,
`retained_selection/1`, `codec::serialize`/`estimate_tokens`) — a
new ADR records the corrected seam; (d) a durable row from a landed
call decodes or reconciles divergently — a new ADR records the
corrected protocol.
