# ADR-0303: S4.11 `hh-mcp-lab` surface rulings

- **Status:** Accepted
- **Date:** 2026-09-28
- **Ticket:** S4.11
- **Requirement ids:** R-2.11.3¹ (AC-R-2.11.3-{3–5,7–9,12–13})
- **Spec:** §7.3 (`R-2.11.3¹`); ADR-0173…0175, ADR-0184 D2; deferral
  ADRs ADR-0210–0216 inherited
- **Rung (ADR-0024 obligation):** **C2** — the hh-lab/1 MCP surface — the C2 surface rung.

## Context

The C1 MCP-server slice puts a *surface* in front of the kernel: an
MCP-only caller (`stdio` or Streamable HTTP) must be able to launch,
read, and cancel runs under **kernel-held authority** — the surface
owns no ledger path of its own. The rulings the slice needed: how the
connection's durable state is represented, how each `tools/call` is
recorded, how launch causality crosses into the child's manifest, how
handles/reads/charges/refusals are shaped, and which halves are
honestly stubbed rather than invented.

## Decision

- **D1 — the MCP connection's durable state is a `run_kind = surface`
  run per caller binding.** `SurfaceSession::open` mints one
  `RunManifest::minimal(Surface)` — the agent-only cells
  (`configuration_id`, `configuration_version_id`, `environment_*`)
  cleared per ADR-0183 §C (the `open_run` invariant refuses them on
  non-agent runs) — carrying `caller_binding`, `exposure_version_id`,
  `catalogue_hash`, `protocol_bindings`, and `caller_process` in
  `extra`. Sessions are lazy (first `tools/call`); `ensure_session`
  rebinds after a restart by scanning `run_kind = surface` manifests
  for the binding id and re-acquiring the writer lease — the run is
  the session, never a second one. A `control.budget.allocated` pool
  root (`budget_id = binding.budget_node`, `mode: pool`) lands at open.
- **D2 — every `tools/call` is one surface-session turn with the full
  effect chain.** `lifecycle.turn.started` → `action.effect.intended`
  → (`security.permission.decided{allow}` + `action.effect.authorized`
  for mutating calls | `authorized` alone for `read_only`) →
  `action.effect.prepared{idempotency_key = H(run, effect, args,
  capability_version)}` → the write-ahead `committed` (mutating) or
  direct `observed` (read) → `refused` on any typed refusal →
  `control.budget.consumed{tool_calls: +1, charged_to: instrument}`
  keyed on the terminal event ref (`(source, dimension)` idempotency —
  a rebuilt session never double-charges) → `lifecycle.turn.finished`.
- **D3 — launch causality rides `OpenSpec::New.spawn_event`
  → `manifest.spawn_event`.** The schema grows the additive member
  `{run_id, event_id}` (`SpawnEventRef`); `launch_run` fills it with
  `{surface run, committed-ref}` before `open_session` runs — the
  child's manifest therefore names the *effect* that spawned it, and
  `open_run`'s resolver refuses a dangling ref. The write-ahead order
  (`committed` lands before the op) is what makes the anchor exist
  when the child is created.
- **D4 — handles are deterministic names, never capabilities.** Mint
  is `hnd-<kind>-<idp-of-ref>`; the mint lands as `lifecycle.surface.call.minted`
  rows on the caller's surface run and rebuilds from them on resume.
  Resolution is owner-binding-scoped: `UnknownHandle` for an alias the
  caller's table never admitted (a foreign mint confers nothing),
  `NoCoveringGrant` on an owner mismatch, `HandleExpired` on expiry.
  `surface_ids` in served payloads carry the run/session/experiment
  coordinates the handles name.
- **D5 — reads pass through `ExposurePolicy`, and serving mints
  `measurement.export.delivered` on the READ run.** `read_ledger`,
  `run_status`, `get_trace`, `list_pending_approvals` fold the page
  through the binding's policy (`content_classes`, `readers`,
  `redaction`, `page_limit`, `max_field_bytes`) — withheld rows are
  listed, never silent — and the served span lands
  `{sink_id: surface:mcp:<binding>, view_kind, seq_range,
  content_classes}` on the run being read (the same row shape the web
  instrument's `record_delivery` writes — one class, one meaning).
  A `run` argument that isn't a minted handle refuses `UnknownHandle`,
  never an empty page.
- **D6 — the budget gate precedes `open_session`.** `launch_run`
  without `budget` refuses `MissingBudget`; a requested dimension the
  ontology doesn't name — or the pool doesn't declare — is
  `MissingBudget` (never a silent skip; an undeclared request cannot
  launch unbudgeted); a `hard` head over the pool's remaining is
  `InsufficientBudget` with `{dimension, requested, available,
  budget_id}` — all refuse before any environment/`environment.*` row
  or child run exists. The child's root budget is the request's
  `BudgetInput::Node` sealed verbatim into `manifest.budget`.
- **D7 — supply-surface bindings are Π-evaluated against their OWN
  artifact.** `callable ⇔ revealed` holds per binding: the served
  `tools/list` is the binding's own `hh-mcp-target/1` doc filtered by
  `hidden`; a name it doesn't carry is `unknown_tool` even when the
  Lab group exposes that spelling. `deny` lands `intended → refused{
  DeniedByPolicy}` and never executes; `ask` mints durable
  `security.permission.pending` on the caller's surface run and
  answers `PermissionAskRequired` + `pending_effects[]` (never
  auto-approved — DF-S4.11-3 owns the answer path); `allow` runs the
  declared stub executor — the same effect chain, no invented effects.
- **D8 — caller kind is the only endorsement authority.** The
  `respond_approval` gate is `human_principal`-only — every other kind
  refuses `IllegitimateEndorsement` *with the durable refused row*
  (the gate sits after `intended` so the record exists). Caller kind →
  attendance on launch: `human_principal` → `interactive`,
  `agent`/`provider_client` → `async`, `service` → `unattended` (the
  service ceiling — a service binding cannot declare presence it
  doesn't have).
- **D9 — authority comes from the transport, never the message.**
  `CallerBinding` resolves from `stdio_launch` credentials (the OS
  identity *is* the grant) or the `BindingTable` bearer map;
  `oauth`/`mtls` credential *shapes* parse and their `caller_binding.
  <kind>` assumption-debt carriers are required at `link` (AC-12), but
  the H3 mediator that resolves them is DF-S4.11-2 — a stubbed seam,
  not a guessed subject. `_meta`/request content never confers.
- **D10 — two transports, one dispatch.** stdio is newline-delimited
  JSON-RPC (`-32700` on parse failure, the loop continues); Streamable
  HTTP is `POST /mcp`, one JSON-RPC frame per request —
  `Mcp-Session-Id` issued on `initialize`, required after (`404` on
  stale), `OriginPolicy` gate (`403`), bearer grant → `401` +
  `WWW-Authenticate`. A notification answers `202`. The SSE half is
  honestly unstaged (DF-S4.11-1).
- **D11 — audit-grade rows carry declared members only; every write
  goes through the `surface_*` seam.** `EmbedService::surface_open_
  run/acquire_writer/append/commit_row/events/manifest/run_ids/
  head_event_id/account/inject_durability_faults/alloc_id/now_ms/
  ts_now` is the whole surface→ledger boundary — the Rule C partitions
  are honoured (`action.effect.*` carries `{effect_id, capability,
  capability_version, args_canonical_hash, *_risk_class,
  idempotency_key, outcome, outcome_ref, fencing_token, reason,
  error}` — `arguments`/`dossier` verbatim never ride an audit row,
  I7; `security.permission.pending` carries the §5g.7
  `PermissionRequest` partition; result bytes are `idp` digests in
  `outcome_ref`, refusal detail is a bounded `error` member).
- **D12 — `op_call` completes `hello` lazily.** The kernel's
  `NotInitialized` gate stays honest: the first wrapped op issues
  `hello{contract_major: 1, client{kind: "mcp_server"}, capabilities:
  {serves_host_executor, serves_permission_channel,
  accepts_ephemeral_frames}}` once and retries — the surface never
  pre-declares a session state it hasn't negotiated.
- **D13 — the exposure definition is data, linked before serve.**
  `hh-lab/1` is a JSON document → `parse_exposure` → `lower` → the
  served `ServedArtifact`. `link` refuses a doc missing a declared
  carrier's `assumption_debt` record (`tasks_carrier`,
  `legacy_era_projection`, `caller_binding.<kind>` per credential —
  AC-R-2.11.3-12). Every Lab tool is `op = <a real hh-embed/1 method>`
  or `op = ""` with a declared `lowering.class ∈ {exact, narrowed}` —
  AC-13's "no undeclared surface verbs" holds by enumeration, and
  `tools/list` is byte-identical across transports.

## Consequences

- The surface cannot write the ledger outside `surface_*`; the MCP
  wire and the durable record are one decision chain, so HTTP and
  stdio answer identically (byte-parity tested on discovery frames).
- `spawn_event` makes the C1 launch a first-class causal record — the
  fleet-anchor pattern (S4.9's `dispatch_note`) reuses it.
- The unresolved pieces are explicit debt (DF-S4.11-{1..3}): SSE
  notifications, the H3 credential mediator, the surface-run ask
  reply. None are faked: each refuses typed or is structurally absent.
- The dispatch is serial (one binding → one session → one lease);
  concurrent calls per binding are a later-stage question, not C1's.

## Alternatives considered

- **`arguments` verbatim on `action.effect.intended`** — rejected:
  Rule C refuses undeclared members on audit-grade rows, and I7 wants
  bounded audit + content refs anyway; `args_canonical_hash` is the
  audit member, the bytes stay off-ledger.
- **A `launched` row carried on the child run instead of
  `spawn_event`** — rejected: the manifest member is the *causal
  carrier* the spec's row-key vocabulary already defines; a payload
  row would duplicate the coordinate without `open_run` validating it.
- **Auto-approving Π `ask` with `service`/`agent` attendance** —
  rejected: an ask is a decision owed to a principal; fabricating the
  grant would widen authority the binding never conferred (CC2). The
  honest row is `pending` + a typed refusal.
- **Mounting the pending ask on the launched run** — rejected: the ask
  belongs to the *caller's* surface turn (the child may not exist);
  the surface run is where the decision must be answered (DF-S4.11-3
  owns the reply path).

## Revisit trigger

Reopen when (a) the SSE/notification half of Streamable HTTP lands
(DF-S4.11-1), (b) the H3 credential mediator resolves oauth/mtls
bindings (DF-S4.11-2), (c) the surface-run permission reply path
exists (DF-S4.11-3 — the `respond_approval` arg shape may need a
run-less arm), or (d) a second caller-binding kind needs per-turn
concurrency (the serial turn model's assumption).
