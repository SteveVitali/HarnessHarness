# ADR-0240: S1.9 assembly-crate rulings — crate shape, assembly-in-document, one resolver feeding `seal`, resolve idempotence, resume as a typed verdict, `link_precheck`, the boundary as data

- **Status:** Accepted
- **Date:** 2026-09-16
- **Ticket:** S1.9
- **Requirement ids:** R-2.1.4
- **Spec:** §3.3 (the C0/Stage-1 slice per §3.3.13) · ADR-0023/0024/0025 (as
  amended) · ADR-0148 (the closed taxonomy) · ADR-0143 D2 (the L2 rule) ·
  ADR-0036 (`registry_snapshot_id`) · ADR-0037 (`StaleIndex`) · CF-056
- **Rung (ADR-0024 obligation):** **C0** — the single-machine, in-process,
  offline core. `hh_assembly::boundary::RUNG` publishes it as data.

## Context
S1.9 lands the configuration & composition model — the `Assembly` grammar, the
class catalog, `load`/`validate_assembly`/`resolve`/`identity`/`diff`/
`instantiate`/`verify_resume`, and the diagnostic taxonomy. The spec fixes the
op contracts and the failure-mode names but leaves these concrete rulings to
the slice:

1. **Where the model lives.** §3.3.13 says "assembly grammar in the `hir/1`
   schema" — the assembly section is a document member, not a separate file
   format or a registry record.
2. **How `resolve` reaches a sealed definition (CF-056).** `compose → resolve
   → validate_assembly → seal` is the only path; `resolve` must therefore be
   the *single* resolver and `seal` the single mint.
3. **What "idempotent" costs.** §3.3.4 requires `resolve(sealed) = sealed`.
   `hh_hir::ops::seal` re-endorses member provenance and mints fresh
   `version_id`s, so re-sealing a sealed document is *not* a no-op.
4. **How `verify_resume`'s diff gates surface.** The `Compatible` verdict's
   `HirDiff` runs through `hh_hir::diff`'s gates (authority-widening,
   conditioned-rule, narrowing); §3.3.5 requires every caller-facing rejection
   to be a coded `AssemblyDiagnostic`, never a bare `HirError` leak.
5. **Where `link`'s refusal lives at Stage 1.** AC-CC-10 (CF-056) — the
   compiler's stage 1 refuses an unpinned selector with
   `LinkError{unbound_slot}`; the compiler itself is S1.10.
6. **Constraints in the diff.** §3.3.4 names `AddNode`/`RemoveNode` "for
   entities and constraints" — but HIR/1 has no constraint node kind;
   constraints live in the assembly section.
7. **`context.artefact.delivered`.** `verify_resume`'s T-LCD-13 rule reads it
   as the removal witness; it must be a registered ledger class (the context
   builder is a later ticket).

## Decision
- **§1 — one persistent crate `crates/hh-assembly`,** deps
  `hh-wire`/`hh-identity`/`hh-provenance`/`hh-ontology`/`hh-hir`/`hh-ledger`/
  `hh-registry`/`hh-budget` only (CC4/CC5 — no implementation loading, no
  service). The assembly is a **data-only member** (`assembly`) of the HIR/1
  document (Q-L1-09: never host-language content); `load`/`encode` are the
  canonical-codec pair over that member with a declared per-field
  `MergePolicy` table (the schema's merge policy, longest-prefix-wins, is
  declared for every grammar field — `merge_policy_is_declared_for_every_
  grammar_field_and_longest_prefix_wins`). Unknown non-`ext` keys are
  `C-LOAD-3` errors.
- **§2 — `resolve` is the one resolver feeding `seal` (CF-056).**
  `resolve(doc, &mut ResolveEnv{registry, catalog, snapshot_id, mode,
  registrar, resolved_at})` substitutes every `$param:`/`$entity:` marker, pins
  every `ComponentVariantRef` snapshot-confined and every entity `Ref`
  doc-internal, scans secrets to channel names only (`C-SEC-1`), records
  `resolved{registry_snapshot_id, resolved_at}`, materialises the native
  slot bindings into the document, and calls `hh_hir::ops::seal`. `execute`
  mode resolves against the execute index — a revoked head in the pinned
  closure is `C-REF-4 StaleIndex` (ADR-0037).
- **§3 — idempotence by reconstruction, not re-seal.** When the input is
  already resolved *and* every node carries `version.sealed`, `resolve`
  re-verifies the pins and then rebuilds the `SealedDefinition` from the
  document's existing coordinates — `definition_ref` from the root node's
  `{semantic_id, version_id}`, `closed_world_tools` by the same pure fold
  `seal` runs — instead of calling `seal` again. `resolve(sealed)` is
  byte-identical (`resolve_is_idempotent`); a partially-sealed or unresolved
  input still takes the full seal path.
- **§4 — `verify_resume` is a typed verdict, not a merge.** The four Core
  rules (dialect equal; every slot's `class_id` equal; delivered tools
  add-only; budget decreases only when the accounting gate allows) produce
  `Incompatible{reasons[{path, rule}]}` over the closed `ResumeRule` set —
  never fail-fast. A `Compatible` verdict carries the `HirDiff` and its
  `diff_ref` (the diff's `idp/1` content address — the `lifecycle.definition.
  changed` payload coordinate). The diff's gate refusals surface as `C-KERN-*`
  `AssemblyDiagnostic`s (§3.3.5), same as the `diff` op's.
- **§5 — `link_precheck` is the Stage-1 `link` refusal.** AC-CC-10's check —
  "refuses an unpinned selector with `LinkError{unbound_slot}`" — lands here
  as `link_precheck(sealed) → Result<(), Vec<AssemblyDiagnostic>>` emitting
  `C-LINK-1` per unbound slot, so the rule is executable now; the compiler's
  stage 1 (S1.10) *calls* it and consumes the sealed definition
  (DF-S1.9-3).
- **§6 — constraints diff at leaf granularity.** HIR/1 has no constraint node
  kind, so a constraint edit diffs as `ReplaceField` ops at
  `assembly.constraints[i]…` paths — a faithful reading of the spec's
  "AddNode/RemoveNode for entities and constraints" (entities get node ops;
  assembly-section members get field ops). `authority_delta` remains
  `hh-hir`'s classification.
- **§7 — `context.artefact.delivered` is registered now** (`hh-ledger`
  classes table: ledger-durable, provenance-bearing, P1) so `verify_resume`'s
  removal witness is a real class the context builder will emit — the row's
  payload shape is §5a.1's.
- **§8 — the boundary is data.** `boundary::MUST_BE_CODE`/`MUST_BE_DATA`/
  `LadderRung`/`RUNG` publish §3.3.3's lists and this crate's rung (`C0`) as
  library constants — auditable, diffable, asserted by
  `the_must_lists_and_rung_are_declared`. The spec's table remains the
  authority; the constants paraphrase it (each ADR's rung statement is the
  rung obligation's letter; the cross-ADR audit is DF-S1.9-4).
- **§9 — the catalog is a view, never a second store (CC7).**
  `Stage1Catalog` serves the two mandatory `exactly-one` classes from
  `hh_registry::suites`; `RegistryCatalog` reads `ClassRecord`s from a
  `RegistryStore` (optionally snapshot-confined) name-free — the record at
  the deterministically-greatest `version_id` carrying the `class_id` — and
  `VariantRecord`s by pinned `version_id` through `store.get`.

## Consequences
- The sealed definition is producible *only* through `resolve` — the grammar
  has no code-bearing leaf, and `seal` re-checks the benchmark-conditioned
  rule (AC-CC-13 runs at both `validate_assembly` stage 7-L2 and `seal`).
- A resumed-into `resolve` of a persisted sealed definition cannot drift
  identity: reconstruction returns the existing `version_id`s.
- `verify_resume` reports *every* violated rule at once (the reasons vector),
  and a `Compatible` verdict already carries the `diff_ref` the caller writes
  to `lifecycle.definition.changed`.
- Constraint provenance in diffs is field-granular — a later dialect that
  grows constraint nodes changes the op shapes (HIR/2 backlog, not in place).
- `RegistryCatalog::class`'s greatest-`version_id` choice is deterministic and
  name-free; when the assembly *service* (§6) lands, name-scoped catalog reads
  are an additive extension (CC8).

## Alternatives considered
- **A separate `AssemblyDiff` object.** Rejected — §3.3.4 is explicit: `diff`
  is `HirDiff`, "not a separate object"; the assembly wrapper only mirrors
  kernel errors into the taxonomy.
- **Re-sealing on every `resolve` and claiming idempotence over the semantic
  projection.** Rejected — the spec's `resolve(sealed) = sealed` is over the
  sealed *result*; re-sealing mints new `version_id`s, so canonical bytes (and
  the `version_id`-keyed manifest coordinate) would differ.
- **Assembly as a registry record or its own file dialect.** Rejected —
  §3.3.13 fixes the grammar "in the `hir/1` schema"; a second document type
  would fork the identity model (CC1/CC7).
- **Emitting `lifecycle.component.bound` inside `instantiate` directly to a
  store.** Rejected — `instantiate` *produces* the envelopes; the caller
  appends through the run's single fenced writer (the ledger owns durability;
  the same emit-then-append split as `hh-registry`).

## Revisit trigger
The Stage-3 `compose`/layers landing (§3.3.13) — `source_layer` coverage and
`authority_cap` enforcement turn DF-S1.9-2 into real code paths; S1.10's
compiler consuming `link_precheck` (DF-S1.9-3); the Stage-2 out-of-process
variant host widening `Placement` beyond `InProcess` (DF-S1.9-1); or a HIR/2
dialect growing a constraint node kind (§6's leaf-granular diff ruling).
