# ADR-0390: R5.11 instrument oracle attempt — landing decisions

- **Status:** Accepted
- **Date:** 2026-11-02
- **Ticket:** R5.11
- **Requirement ids:** REQ-E-007 (primary); REQ-E-102, REQ-E-103, REQ-E-204 (contributing)
- **Spec:** docs/evidence-and-adoption-spec.md §2.2 step 4 + AC-5-1/AC-5-2 + AC-2-1; PADR-R5-1 (admitted GATE-G9, packet A — A.1 item 5, A.3, A.5, A.7); execution-partition X5; ticket docs/tickets/180_R5.11__oracle.md
- **Rung (ADR-0024 obligation):** implementation landing record — the admitted executed-instrument-oracle contract's concrete shape on `hh-bench`/`hh-ledger`; no RPC, no wire/schema change, no new dependency

## Context

PADR-R5-1 A.1 item 5 admits: "Bench persists the instrument invocation
before running the unchanged pinned oracle on the sealed submission
(executable/environment/access, exit, raw stdout/stderr/reward,
timeout/refusal, grade mapping, instrument finish/cost); invoked/verdict
refs bind subject, submission, oracle, attempt, policy and cost …
crash/timeout/empty/non-finite/refusal is `oracle_failure` permitting
capped instrument-only regrade — never a participant rerun, recharge or
new n." A.3 homes the events "under existing verification/measurement
planes" with no committed names; X5 names `hh-bench` the owner and the
typed reward/infra pipeline the mapper. The landing choices below are
this ticket's owned decisions.

## Decision

1. **Two new classes under the existing `verification.*` plane.**
   `verification.oracle.invoked` and `verification.oracle.verdict`
   register in `hh-ledger`'s class table as durable +
   provenance-mandatory `row_prov` rows (the `verification.*` prefix
   already homes P4 and `default_charged_to` resolves `instrument` —
   R-ACC-3); the exhaustive `HOSTED_LOWERING` column carries them at
   `hint`. New classes, not reuse of `verification.validator.*`: those
   rows own the claim-verdict payload shape folded by `bind.rs`, and a
   foreign payload would pollute claim binding.
2. **`attempt_no` is durable-derived, not runner state.** The runner
   counts committed `verification.oracle.invoked` rows matching the
   `{subject_run, submission_ref, oracle_ref}` triple; `> max_attempts`
   refuses `AttemptCap` — so the frozen instrument-only regrade cap is
   enforced against the ledger across crashes and restarts, and an
   invocation→verdict crash retains its ambiguity (A.5) instead of
   double-counting or forgetting.
3. **Invocation-before-execution is a write ordering, not a flag.**
   `OracleRunner::attempt` appends the invoked row (causes cite the
   subject run's `submission_seal` snapshot) before calling the
   executor; an append failure yields `InvocationNotPersisted` and the
   oracle never runs. Refusal legs (pin/digest/seal/cap) validate before
   any row — a refused attempt appends nothing.
4. **The seal proof is structural.** `seal_ref` must resolve to an
   `action.environment.snapshot{purpose:"submission_seal"}` row on the
   subject run — the R5.10 end-state pin — else `UnsealedSubmission`;
   a mutable workspace is never graded. `submission.compute_id()` must
   equal the frozen `submission_ref` and the executor's
   `oracle_digest()` the frozen `oracle_digest` — mismatches refuse
   `DigestMismatch`; `oracle_ref` must equal
   `task.instrument.grader.adapter_ref` — `PinMismatch`.
5. **Bounds are enforced on the observation, never trusted.**
   `timed_out = obs.timed_out || wall_ms > wall_ms_bound`; captured
   `stdout+stderr` over `output_bytes_bound` is an oracle failure that
   retains digests, byte counts and a 200-char evidence head — never a
   silent truncation passed off as the pin.
6. **Isolation is spelled, never upgraded.** `separate` records
   `separate_verifier:true` + held-out/access-revoked refs; `shared`/
   `hosted` record `separate_verifier:false` +
   `tamper:"n/a{no_detector}"` (§5h.4 §2.4 row A's spelling).
7. **`to_grade_attempt` is the R5.9 producer fact.** Each retained
   `OracleAttempt` maps to `selection::GradeAttempt` —
   `(instrument_run_id, verdict_seq)` durable coordinate, subject/
   submission/oracle pins, cause coordinates citing the subject run's
   seal plus the instrument run's invoked/verdict rows,
   `Decided(MetricValueKind::Decimal(reward_ppm))` / `OracleFailure`.
   Consumer wiring (`plan_disposition_at`, pending admission) stays
   owed to R5.14; actual upstream execution to R5.43.
8. **The instrument run is the `RunKind::Experiment` minimal-manifest
   idiom** the results tests use — a non-agent run with its own fenced
   writer that never enters subject aggregates; attempt rows append
   only there, so the subject run gains no feedback and no relaunch.

## Consequences

- Any consumer can resolve attempts by scanning
  `verification.oracle.*` rows; the `OracleAttempt` record carries the
  resolved coordinates for the selection contract.
- Over-bound and refused attempts are retained as first-class durable
  failures — denominators never silently drop them (I-03, I-07).
- `OracleExecutor` is an injected port: deterministic fixtures here;
  the real adapter/subprocess path wires the same trait under the
  separately authorized execution stage (offline slice, $0).

## Alternatives

- Reusing `verification.validator.invoked`/`verdict` — rejected:
  foreign payload shape on a folded class pollutes claim binding.
- A runner-held attempt counter — rejected: memory is not durable
  truth; a restart would re-spend the frozen cap or orphan an invoked
  row.
- Trusting the executor's own timeout/output claims — rejected:
  bounds are the launch-frozen policy; the runner enforces them on the
  raw observation.
- An `oracle` member on the subject run — rejected: instrument facts
  never land on the subject stream (no feedback, instrument charge).

## Revisit triggers

- If R5.14 needs per-attempt cost attribution beyond `cost_ref`
  binding (actual Account debit rows), revisit the verdict's cost
  members when B1/B2's Account seam lands.
- If a hosted-verifier isolation mode needs separate evidence members
  (rather than shared-mode `no_detector`), revisit the isolation
  payload for `hosted`.
- If a later consumer needs attempt discovery without a full event
  scan, revisit whether an index/projection should fold
  `verification.oracle.*` rows.
