## Context

A3's newcomer audit (F6) proved the clean-recipient R0 path broken:
`kernel.reproduce` read the terminal `lifecycle.run.*` row's
`payload.status` — the *task-outcome* plane (`succeeded`,
`failed_honest`, `met`, …) — and compared it against the manifest's
`subject.status`, which the producer folds from
`lifecycle.run.finished` *presence* (`open`/`finished`). Every
completed run therefore reported `lifecycle_status` drift
(`declared finished` vs `derived succeeded`) on byte-perfect
evidence. §6.3 additionally binds the recipient decode to refuse
archive path/link escapes and excessive expansion *before*
execution; `decode_dir` did neither.

## Decision

1. **The R0 fold derives `open`/`finished` from
   `lifecycle.run.finished` presence — the producer's own rule**
   (`crates/hh-embed/src/bundle_ops.rs` `kernel_reproduce`): derived
   `finished` iff a `lifecycle.run.finished` envelope landed, `open`
   when lifecycle rows exist without one, inconclusive only when
   the export carries no lifecycle rows. The outcome-plane members
   (`payload.status`, `stop_reason`, `outcome_class`) are never
   read — task failure can validate. This is §9.3's pre-admitted
   existing-contract fix, not an amendment; the `lifecycle_status`
   drift comparison is unchanged.
2. **`decode_dir` refuses escape and expansion before
   materialization** (`crates/hh-bundle/src/codec.rs`): `bundle.json`
   and every `members/` entry must be regular files inside the tree
   — a link, directory or special entry is `MemberEscape`; a member
   file larger than its declared index `size` refuses
   `MemberExpansion` (undeclared/zero sizes bind at the native blob
   bound `DEFAULT_BLOB_MAX_BYTES`, the largest byte string a
   producer store writes). A member *smaller* than declared is not
   expansion: it materializes and the staged `bad_size`/hash checks
   report it — "changed bytes fail the verdict; expansion refuses"
   stays a semantic distinction, not a conflation.
3. **Two typed `BundleError` variants** (`MemberEscape{member}`,
   `MemberExpansion{member, limit}`) carry the refusals to the
   boundary's `Refused{reason}` closed sum via `bundle_err` — no
   new public contract, no second refusal codec.
4. **Verifyfixed evidence is fixture-engineered, honestly
   labelled.** The original A3 bundle bytes are unavailable — the
   battery reproduces the F6 signature over fresh fixture bundles
   (producer deleted before the recipient leg) and records the
   unfixed fold's derivation as a *labelled diagnostic equivalent*
   (§5.3 REQ-D-208: "missing historical bytes permit only a
   labelled diagnostic equivalent"), never an original-rerun claim.

## Consequences

- Clean-recipient `kernel.reproduce{level:R0}` now passes byte-perfect
  bundles whose runs completed `succeeded`/`failed_honest` —
  `hh bundle validate|reproduce` behave as the A3 audit expected.
- Any pre-existing `members/` entry that is not a regular file now
  refuses decode where it silently read through a link; no produced
  bundle changes — `encode_dir` writes only regular files.
- The old bytes are never touched: the repair lives in the fold and
  the decode bound, not in the archive format (admitted durable/wire
  compatibility).

## Alternatives

- **Map outcome statuses onto the lifecycle vocabulary** — rejected:
  that preserves the F6 category error (conflating planes) instead
  of repairing it; §6.3 fixes the vocabulary at `open`/`finished`.
- **Refusal at `decode_bundle_arg` (embed) rather than the codec** —
  rejected: the bundle codec owns the `hh-bundle/1` directory form;
  every recipient op (`check_completeness`, `reproduce`, later
  recompute/replay owners) shares the bound.
- **Refuse non-declared-size equality outright** — rejected: a
  smaller member is "changed bytes" (verdict fail), not expansion;
  refusing it would conflate the two AC-2 predicates.

## Revisit triggers

- If a later owner admits a second lifecycle class on the terminal
  row (e.g. a `suspended` terminal state), re-read Decision 1 — the
  producer and recipient folds must be amended together (one
  presence rule, one vocabulary; I-06).
- If the native blob bound (`DEFAULT_BLOB_MAX_BYTES`) changes or
  per-member expansion ceilings become member-class-dependent,
  revisit Decision 2's undeclared-size bound — the declared `size`
  leg is unaffected.
- If a foreign/`fetch`-materialized delivery legitimately carries
  link members, revisit Decision 2 — current producers emit only
  regular files; admitting links needs a transport-level contract,
  not silent decode leniency.
