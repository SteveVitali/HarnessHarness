# ADR-0274: S2.12 attended-CLI + registry-enforcement rulings

- **Status:** Accepted
- **Date:** 2026-09-20
- **Ticket:** S2.12 (`043_S2.12__attended-cli-item-and-registry-enforcement.md`)
- **Requirement ids:** R-2.11.1 · R-2.12.1 · R-2.10.2 (S2 slice) · R-2.3.4 (snapshot)
- **Spec:** §7.1 (R-2.11.1) · §8.3 (R-2.12.1) · §6.2 (R-2.10.2 S2) · §5b.4 (R-2.3.4 WS-L4)

## Context

S2.12 lands the attended CLI item (C1) and the registry-enforcement
slices. The spec fixes the contracts (the lifecycle verbs, the
registry op set, the `ModelSnapshotRecord` member shape, revocation's
default-validity invariant); the mechanism choices below were left to
the ticket:

1. **How `--until-seq` reaches `project`.** C1 names a bounded
   projection for `run inspect`; the CLI flag spelling and its
   relation to the existing `--at-seq` needed a ruling.
2. **How reader-set withholding surfaces on CLI output** (the
   DF-S2.10-2 half of AC-R-2.11.1-16). The leak-prevention invariant
   covers `json`/`jsonl` output; the tombstone shape and the CLI's
   reader set were open.
3. **`ModelSnapshotRecord`'s identity scheme.** §5b.4 names the
   members `{provider, model_id, snapshot_id?, pinned, provenance =
   reported, observed_fingerprint?}`; the `idp/1` domain and which
   members form the semantic projection needed a ruling (N6).
4. **The fingerprint probe's shape and match rule** (ADR-0120 d.4/(e)).
   A "probe" is a declared request; the digest domain and the closed
   verdict needed pinning.
5. **How a drift observation is raised.** ADR-0203 D5 names the
   synthetic `SnapshotClaim` signal; its precedence against the
   served-model substitution arm and the gateway's authority boundary
   (report, never decide — I-NOAUTH) needed pinning.
6. **Group L dispatch ordering.** `lab.registry.*` ops are
   experimental + `serves_measurement`-capability-gated; where in the
   service dispatch order the implementation gate sits needed a
   ruling (it was the conformance failure driver).
7. **Transitive revocation propagation.** `Lineage::revoke` must make
   dependent records stale; the walk order (dependants of the revoked
   member, then *their* dependants) and the `stale_by_dependency`
   cause member needed a ruling.
8. **`EnvironmentRecord`'s identity.** The record kind needed an
   `idp/1` domain distinct from every sibling (N3).
9. **The parked-detach interim** (DF-S1.26-2). The Stage-2 slice owns
   the run-lifecycle surface; whether the `detached:"parked"` interim
   becomes a declared member or a §2.5 row needed a ruling.

## Decision

- **D1 — `run inspect --until-seq N`.** The ticketed spelling is
  `--until-seq`; `--at-seq` is accepted as an alias. The value is a
  strict integer — a bad value is a typed `invocation_error`
  (`bad_flag_value`), never a kernel call. The flag is registered in
  `VALUE_FLAGS` and lands on `project{until_seq}` verbatim.
- **D2 — the withholding tombstone.** `emit_result` (the `json`
  result record) and `render_event` (the `jsonl` stream) run
  `withhold_uncovered(doc, io.principal)`: a `content`-class item
  whose `readers` (item-level or `provenance.readers`) is a restricted
  set not containing the principal gets `content`/`payload` replaced
  by `{withheld: {reason: "reader_set_uncovered"}}`; metadata (`seq`,
  `class`, `authority`, `readers`) stays visible; `public`/absent
  readers never withhold; recursion covers nested arrays/objects. The
  CLI surface's reader set is `{io.principal}` — the one principal ref
  the invocation names. `run start --jsonl`/`run events` byte-parity
  (O-1) holds *with* tombstones applied — both surfaces share the
  seam.
- **D3 — `RecordKind::ModelSnapshot`.** New kind with domain
  `model_snapshot` (distinct under N3). `version_id` covers the full
  canonical record; `semantic_id` is the `{provider, model_id}`
  projection under `model_snapshot.semantic` — a provider-side
  snapshot roll or a new fingerprint observation is a new *version* of
  the same semantic line. `dependency_stamp() == version_id()`, so any
  observed change is a new stamp — exactly what
  `stale_by_dependency` reads.
- **D4 — the fingerprint probe.** `probe_request()` returns the
  declared canonical request (`hh.fingerprint/v1`, fixed prompt set,
  `temperature = 0`, bounded `max_tokens`) — instrument-charged, never
  a hidden side-channel. `fingerprint_response(bytes)` is the `idp/1`
  digest under `model_snapshot.fingerprint`. The verdict is the closed
  sum `{match, drift, unknown}` — `match` iff byte-equal, `drift` on
  any mismatch, `unknown` on absent evidence (absence is never drift —
  ADR-0118 d.2).
- **D5 — `observe()` and `SnapshotClaim`.** One response's served
  fields fold against the pinned record: the observation's record is
  always returned (the honest record of what the wire said), plus a
  `SnapshotClaim` when the observation contradicts the pin.
  Served-model substitution is checked first
  (`SnapshotClaimKind::ServedModelSubstitution`); fingerprint drift is
  an independent check (`FingerprintDrift`), not gated on
  `served_model` being absent — a snapshot roll under a stable name
  still raises. `snapshot_id = observed` carries the observed
  coordinate. The gateway reports the signal; the consequence is the
  router/registry's (I-NOAUTH).
- **D6 — Group L dispatch order.** `lab.registry.*` ops route through
  `registry_ops.rs` after the declared gate order: hello → init → op
  lookup → upcall rejection → experimental opt-in → capability →
  implementation gate → dispatch. Durable registry mutations go
  through the single fenced ledger-event writer; the
  `serves_measurement` capability + experimental tier are unchanged.
- **D7 — transitive stale on revoke.** `Lineage::revoke` walks the
  dependants of the revoked member transitively (BFS over the
  dependency map), marking each `stale_by_dependency{member, reason,
  since_seq}`; declaring a dependency on an already-revoked member
  produces the same stale marking. Revocation is a record, not a flag
  (append-only).
- **D8 — `EnvironmentRecord` digest.** `idp("environment")` over the
  canonical record; `RecordKind::EnvironmentRecord` rides the same
  kind/schema/identity machinery as its siblings.
- **D9 — DF-S1.26-2 stays OPEN.** The parked-detach interim
  (`ok` + `detached:"parked"`) is retained: a new `ExitClass` member
  would widen a closed sum without a spec row. The deferral carries a
  progress note (attended-mode lifecycle verbs landed; the interim
  member persists pending the §2.5 decision).

## Consequences

- `json`/`jsonl` output can no longer carry covered-out secret bytes —
  the LT battery is executable over the gate.
- `ModelSnapshotRecord` is a first-class identity kind; fingerprint
  drift invalidates dependents via the normal dependency-stamp path —
  no bespoke invalidation channel.
- The fingerprint probe is a declared, billable instrument — a provider
  that reports no fingerprint yields `unknown`, never a fabricated
  claim.
- Group L ops are reachable only through the gated dispatch path —
  experimental + capability enforcement is uniform with every other
  group.

## Alternatives considered

- **Withhold the whole event/item row.** Rejected — hides the
  *existence* of evidence; the tombstone keeps the audit shape (seq,
  class, readers) visible while covering only the covered bytes.
- **`semantic_id` covering `snapshot_id`.** Rejected — a provider-side
  snapshot roll is a new version of the same model line, not a new
  semantic coordinate; pinning it into the projection would make every
  roll a fresh `semantic_id` and break pooling.
- **Drift check gated on `served_model` presence.** Rejected — it
  missed drift under a stable served name (the failure mode the probe
  exists to catch); landed as an independent check.
- **A bespoke fingerprint-mismatch event kind.** Rejected —
  `SnapshotClaim` is the ADR-0203 D5 signal; a parallel channel would
  split the discovery stream.

## Revisit trigger

- The §7.1 §2.5 table gains a detach exit-class row (closes DF-S1.26-2
  and retires the `detached` interim).
- A provider wire exposes a fingerprint *claim* distinct from the
  probe observation (e.g. a signed model attestation) — the
  `provenance = reported` member would then carry a richer origin.
