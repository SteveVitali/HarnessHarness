# ADR-0380: L4.5 publish readiness — the publish set per crate, the declared rust-version, the v0.1.0 release target set, and docs.rs settings

- **Status:** Accepted
- **Date:** 2026-10-23
- **Ticket:** L4.5
- **Requirement ids:** `R-2.12.4` (packaging half) · the 2026-10-20
  distribution rulings ("Also publish to crates.io" · "Libraries +
  installable bins")
- **Spec:** none — packaging identity; no contract change.
- **Rung (ADR-0024 obligation):** non-contract — publish/release
  mechanics only; wire/schema/behaviour surfaces untouched.

## Context

L4.5 makes `cargo publish` and the GitHub Release pure operator acts at
HUMAN-H7. Four decisions are owned here: which of the 54 workspace
crates publish, what `rust-version` to declare, which targets the
release builds, and how each publishable crate documents on docs.rs.

## Decision

### (a) The publish set — "Libraries + installable bins", applied per crate

The ruling publishes reusable libraries and crates carrying installable
binaries; fixtures, packaged plugin variants and test-support carry
`publish = false`. Applied per crate:

- **`publish = false` (5)** — the recorded set, mirrored as a constant in
  `scripts/publish-order.sh` and `scripts/check-publish-metadata.sh`;
  drift in either direction is red in CI:
  - `hharness-plugin-fixture` — the `plugin_abi/1` conformance fixture
    (and the shared plugin-side runtime the packaged variants consume);
    test-support, not a distributable.
  - `hharness-tracker-fixture` — the `work_source_adapter` reference
    fixture variant.
  - `hharness-compact-evict-oldest`, `hharness-memory-store`,
    `hharness-github-issues` — packaged plugin variants distributed under
    `plugins/` through the plugin packaging path, not crates.io.
- **Publishable (49)** — the other 48 members (46 libraries + the
  bin-only `hharness-kernel` and `hharness-codegen`) plus the umbrella
  `hharness` facade. `hharness-codegen` and `hharness-xcheck` stay
  publishable: both are installable tooling (schema/client codegen for
  downstream consumers; the cross-implementation conformance replay)
  under the ruling's letter.
- The umbrella `hharness` re-exports every publishable *library* crate
  under short module names (`hharness::ledger`, …); its `tier-c1`/
  `tier-c4` features forward the owning crates' tier features, and the
  C4 members (`fleet`/`evolution`/`debt`) are optional deps so
  `--no-default-features` truly removes them (CC6 preserved through the
  facade).
- Path dependencies on publishable crates carry `version = "0.1.0"`;
  the only path dep on a `publish = false` crate (`hh-varhost`'s
  dev-dependency on `hharness-plugin-fixture`) stays path-only — cargo
  strips it from the published manifest.
- Ordering: `scripts/publish-order.sh` derives the topological order
  over normal+build edges (dev-deps excluded — they would form false
  cycles, e.g. `hh-varhost` ⇄ `hh-plugin-fixture`), re-checks every
  publish-set name against crates.io at run time (a collision is
  **STOP-and-ask**, never a silent rename or drop), then runs
  `cargo publish --workspace --dry-run`, whose `tmp-registry` overlay
  lets in-flight siblings satisfy each other's verification.

### (b) `rust-version = "1.94"` — the pinned toolchain, declared deliberately

Only Rust 1.94 (+ stable) is installed on the build host, so no older
toolchain can prove a lower MSRV offline — and the ticket forbids new
deps. The workspace therefore declares the pinned toolchain as the
MSRV, and CI makes it verified rather than asserted: the `MSRV check`
step in `ci.yml` extracts `workspace.package.rust-version` at run time,
installs exactly that toolchain, and runs
`cargo +<rust-version> check --workspace --all-targets`.

### (c) The v0.1.0 release target set — 4 targets, Windows excluded

`release.yml` (tag `v*` or `workflow_dispatch` dry mode) builds `hh`,
`hh-kernel`, `hh-helper` per target, archives them as
`hharness-<version>-<target>.tar.gz`, emits per-archive `.sha256` plus
a combined `SHA256SUMS` verified before release attachment:

- `aarch64-apple-darwin` — `macos-latest` (native arm64);
- `x86_64-apple-darwin` — cross-built on `macos-latest` via
  `rustup target add` (no hosted Intel runner is relied upon);
- `x86_64-unknown-linux-gnu` — `ubuntu-latest` (native);
- `aarch64-unknown-linux-gnu` — `ubuntu-24.04-arm` (native arm64 hosted
  runner, available to this public repo). If the dry-mode run shows that
  runner unavailable: **STOP and ask** — a target is never silently
  dropped.
- **Windows excluded for v0.1.0**: `hh-helper`'s containment backends are
  seatbelt (macOS) and podman (Linux) only — a Windows build would ship
  without its containment floor (see Revisit trigger).

### (d) docs.rs readiness

The four crates whose API surface is tier-gated —
`hharness-embed` (`tier-c4`), `hharness-env`, `hharness-helper`,
`hharness-ledger` (`tier-c1`) — and the facade carry
`[package.metadata.docs.rs] all-features = true` so tier-gated APIs
render even if a future edit moves them out of `default`.
`scripts/check-docsrs.sh` documents every publishable crate under its
declared docs.rs settings (`cargo doc -p <crate> --no-deps`, warnings
denied); it runs in CI (ubuntu leg) and was green over all 47
publishable library crates at this ADR's date.

## Consequences

- `cargo publish --workspace` at HUMAN-H7 publishes 49 crates in the
  script's derived order; the 5 `publish = false` crates are skipped by
  cargo automatically.
- Two new CI legs on the ubuntu matrix leg (MSRV check, publish-metadata
  + docs.rs checks) — each gated behind the docs-only fast path, so a
  docs-only head pays nothing.
- Every packaged `.crate` embeds the workspace README (cargo copies
  `readme` files outside the package root); `documentation` points at
  `docs.rs/hharness`.
- The publish dry-run verifies compile — including the facade's
  re-export of the entire public surface and the workspace-versioned
  path-dep graph.

## Alternatives considered

- **`rust-version` below 1.94** — unverifiable offline (no older
  toolchain installed; fetching one violates the ticket's offline
  bound); rejected in favour of the honest pinned-floor declaration.
- **Windows build with containment absent** — ships a floor-less helper;
  rejected (revisit trigger below).
- **`macos-13` Intel runner for `x86_64-apple-darwin`** — its hosted
  availability is winding down; cross-build on the arm64 runner keeps
  the leg deterministic; rejected as the primary path.
- **Publishing `hharness-codegen`/`hharness-xcheck` as `publish = false`**
  — the ruling is "libraries + installable bins"; both carry installable
  bins and are useful to consumers (codegen for embedders, the foreign
  replay checker); kept publishable.
- **Per-crate READMEs** — churn for zero metadata gain; the shared
  workspace README is packaged into each crate instead.

## Revisit trigger

Reopen when: a Windows containment backend lands for `hh-helper` (the
excluded `x86_64-pc-windows-*`/… targets join the set); a lower-MSRV
claim is needed and a toolchain to prove it exists (the declaration
drops below the pin and the CI step verifies it); GitHub retires or
gates `ubuntu-24.04-arm` for public repos; the publish set's rule
changes (a fixture/plugin becomes distributable or a surface crate
becomes internal); or crates.io metadata requirements change
(e.g. keyword/category vocabulary).
