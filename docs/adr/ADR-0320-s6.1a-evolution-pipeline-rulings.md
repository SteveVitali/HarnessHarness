## Context

GATE-G3 released Stage 6 with the §9.7
preconditions MET. S6.1a lands the first
Stage-6 slice: the human-proposed evolution
pipeline as an instrument-grade Lab recipe —
a new `hh-evolution` crate carrying the
closed S0–S10 candidate state machine, the
typed gate refusals, the durable campaign
event family, and the driver that folds every
decision from the ledger prefix. The run had
to rule on where the pipeline lives, which
check owns which evidence, and how the slice
removes cleanly under CC6.

## Decision

- **D1 — The engine is records-in /
  records-out; the experiment engine is the
  sole evaluation substrate.** `hh-evolution`
  never runs a task: S4/S5/S10 consume the
  registered `ExperimentSpec` (bound via
  `ext.evolution_campaign`) and a deposited
  `ComparisonReport`, and check the match
  shape themselves — the campaign does not
  trust an unexamined spec even if the
  engine's own checks were bypassed (M3
  `matched_total` on every arm, budgeted,
  `budget_match.status = matched` in the
  report). No second store, no second
  authority path (CC1/CC3/CC10).

- **D2 — The candidate state machine is
  closed and every transition is a durable
  `measurement.evolution.candidate
  .transitioned{from,to,stage}` row** on the
  campaign's single `run_kind = experiment`
  run; the `CampaignView` is a pure fold of
  the prefix (`ensure` rebuilds it wholesale,
  restart equality is structural), and every
  refusal lands a `rejected{stage, code}`
  row before the error returns — a refused
  candidate is terminal, the record is never
  lost (CC3).

- **D3 — `evolution_link` graduated to a
  live audit obligation on the hypothesized
  transition.** The evaluator checks every
  `transitioned{to:"hypothesized"}` row
  carries a non-empty `hypothesis_ref` and
  non-empty `evidence_refs[]` — the S2
  binding pair the deferred note named.
  `proposed` needs no link (it is the intake
  row) and `applied` is covered by the diff's
  own `derived-from` record; the obligation
  therefore inspects only the hypothesized
  transition. `DEFERRED_OBLIGATIONS` keeps
  `subagent_anchor` and
  `producer_resolution` (DF-S1.15-1 progress
  note).

- **D4 — `ExperimentKind::RetirementBatch`
  joins the retirement gate set.** A batch of
  k single-rule removal arms sharing one base
  arm is `is_retirement()` — same
  removal-diff and `matched_cap`/`cold_start`
  match-shape rules as `retirement`, applied
  per removal arm (R-2.10.3⁴; the S10
  `retire` gate accepts either kind).

- **D5 — Stage-kind admission is a gate,
  not a comment.** `check_stage_experiment`
  enforces the §05h §4 stage tables: the eval
  stages (S4 `search_eval`/`search`, S5
  `held_out_eval`) admit only
  comparison-bearing kinds (`comparative`,
  `equivalence`); the removal-test stage
  (S10) admits only `is_retirement()` kinds.
  Violations land `StageKindMismatch
  {experiment_id, kind, stage}` — the `stage`
  member is stamped at the refusing stage
  (`S4`/`S5`/`S10`) since the shared check
  serves all three.

- **D6 — `hh-evolution` is a C4-tier
  removable slice.** `hh-embed`'s `tier-c4`
  feature gates it as an optional dependency
  beside `hh-fleet`; a `--no-default-features`
  build compiles and answers every
  `lab.evolution.*` op with
  `Unsupported{by: "tier-c4"}` — the ops stay
  in the schema (CC7 single source), the
  absence is a typed refusal, never silent
  degrade (CC6). `check-removability.sh`
  gained the S6.1a stanza proving the crate
  is edge-free upward with `hh-embed` its
  only (optional) consumer.

- **D7 — `RoutingPolicyKind::Learned` is
  executable only on the matched evidence
  chain.** `params.evolution` must carry
  `search_budget_ref`, `artifact_benefit_ref`,
  `match_mode = "matched_total"`,
  `budget_match = "matched"`, and an
  `expiry_condition` containing
  `"model_version_change"` — anything less
  stays a typed `LearnedEvidenceIncomplete`
  refusal (AC-R-2.3.2-14; the router never
  serves a learned policy on incomplete
  provenance).

- **D8 — Shadow canary only; a split
  rollout is exploratory and never commits.**
  `canary{mode}` admits `shadow` alone;
  `split` lands
  `SplitRolloutNotCommittable`. Abort/veto at
  settle lands the durable
  `reverted{from: canary, reason}` row — the
  sealed-ancestor restore rides
  `hh-hir`'s `invert` on the caller's side
  (`apply(base, invert(diff))`), so the
  ledger holds the decision and HIR owns the
  bytes (CC1). `S8` publishes only under
  `exp/<campaign_id>/` (AC-R-2.12.2-14;
  `check_publish_namespace`).

- **D9 — Evolution-origin memory is
  promote-gated on a human reviewer.**
  `Origin::Evolution{candidate_id,
  hypothesis_ref}` versions promote only with
  a human reviewer origin plus validator
  endorsement; refusals mint durable
  `context.memory.promotion_refused` and map
  to `LifecycleError::PromotionRefused` in
  the memory ABI (AC-R-2.4.5-9).

## Consequences

- The S6.1a battery drives one candidate
  `proposed → retired` through the live
  engine (29 tests) and the refusal legs land
  durable `rejected` rows — the acceptance is
  executable end-to-end, not per-stage only.
- `G3-1`'s seal spellings
  (`seal_refused{not_human}` /
  `not_definition`) and `G3-2`'s `exp/`
  confinement are the typed refusals.
- `lab/org-policy-v1` is **not** this
  ticket's deliverable — R-2.12.6 owns it
  through S4.9/S5.6/S6.4.

## Revisit trigger

Reopen if an automated proposer family lands
(S6.2's `automated` protocol — the
`human_proposed`/`proposer_family = "human"`
gates and the S8 human-seal authority need
their delegated-authority halves ruled); if a
split rollout must commit `active` (S9's
shadow-only rule is conservative — a
committable split needs a committable-rollout
kind on the state machine plus its ledger
spelling); if `evolution_link` must cover the
`proposed`/`applied` transitions too (the
current obligation inspects only the
hypothesized row — widen it at the
obligation, never by weakening the record);
or if a stage needs a kind outside
`{comparative, equivalence}`/`is_retirement`
(e.g. a reproduction-backed eval — the
stage-kind tables are a closed set per §05h
§4).
