## Context

S6.1a landed the campaign state machine
for the human-proposed family; S6.2 lands
the first *automated* family — the
`evolution_proposer` component class, its
conformance suite, the AHE-shaped
first-party variant — plus the four
evolvable-side slices the stage assigns it
(the gated adaptive-search strategies, the
`predictor` compute variant, the
coordination/topology tightening rule, and
the §5c optimisation legs). The run had
to rule on where the proposer sits (a
source, never a bypass), how the corpus's
new layer vocabulary stays closed, how the
search-budget gate sees the proposer's own
spend, and how the conformance suite's
executable leg reaches out-of-process.

## Decision

- **D1 — the proposer is a source, never
  a bypass.** `AheProposer::propose` emits
  a `CandidateProposal` (+ bound
  `FailureHypothesis`, or the typed
  `NoAddressableFailure` — never `[]`),
  and every emission re-enters
  `EvolutionCampaign::propose`, where S1's
  gates re-check it verbatim: base/head
  consistency (`StaleBase`), origin =
  `evolution` for automated families,
  the one `target_class` bound, semantic-
  op bounds, exclusion/MUST-code sets, and
  all four tightening deltas
  (authority/budget/validity/
  coordination). The proposer holds no
  ledger handle and mints no row.
- **D2 — one class is a construction-time
  pin, not a check.** `AheProposer::new`
  binds the target class;
  `propose` refuses `target_classes ≠
  [pinned]` (`ConstraintUnsatisfiable`),
  and the campaign spec refuses
  `protocol = automated` without
  `proposer_variant_ref` + exactly one
  evolvable `target_class` (the §5c set —
  `evolution_proposer` itself excluded,
  G5/X6).
- **D3 — `coordination_delta = loosening`
  is refused at S1 and S7 like widening.**
  `CoordinationPolicy`/`topology` are
  evolvable *under the same tightening
  rule* as budget/validity — the
  `CoordinationLoosening` refusal reuses
  the widening grammar (K-4 / ADR-0193's
  ADR-0053-D5 shape); the classifier is
  the single judge (CC1) and both the
  proposal leg and the S7 security
  re-check read it.
- **D4 — `CorpusSpec.layers` is a closed
  vocabulary; `memory_lineage` is a
  layer, not a side channel.** The
  §5c memory-lineage leg rides the corpus
  (`EvidenceCorpus.memory_lineage` +
  `LineageLink`); a `memory:`-prefixed
  evidence ref without the declared layer
  is a schema violation at S0; a held-out/
  private/secrets layer name is
  `HeldOutLeak` at S0 and
  `CorpusUnreadable` at the proposer's own
  boundary (belt and braces — the proposer
  never trusts the spec it was handed).
- **D5 — the proposer's spend lives in the
  declared `SearchBudgetRecord` slice.**
  G8 resolves each arm's `search_budget`
  ref and requires a complete allocation
  (ppm shares summing to 1); automated
  families must name the `proposer` facet
  so model/judge calls charge it — no
  `proposer` facet is
  `SearchBudgetIncomplete`. `predictor`
  in `hh-control` is the same shape: inert
  (`Unchanged`, never a stop) without a
  declared slice, cold-start falls back to
  the rules floor stamped as
  `predictor.cold_start`, drift-reset
  cells score nothing, and
  `budget_share_cap` overrun degrades
  never binds. Scheduling-rule edits are
  tightening-only targets
  (`budget_share_cap_ppm` up /
  `drift_reset_ppm` down = `Loosening`,
  refused).
- **D6 — adaptive strategies record, then
  pick.** `voi_weighted` /
  `disagreement_weighted` mint
  `measurement.experiment.inclusion_probabilities`
  before the pick (`per_plan` table,
  `charged_to = instrument`); touched
  reports carry `estimated{estimator,
  ref}` naming the durable allocation
  record. `successive_halving` mints
  `halving_bracket{bracket, eta, kept[],
  dropped[], per_plan}` and prunes the
  dispatchable set to the bracket's live
  set — empty ⇒ `Wait` (or `Done` when
  nothing remains open). Every draw is a
  pure function of (seed, round,
  dispatchable set) — INV-9 replay-stable.
- **D7 — the executable leg has an
  out-of-process witness, gated the way
  the host already gates.** The
  `evolution_proposer` conformance suite
  is the four-kind shape (static /
  contract / property / executable); the
  in-process port drives the first-party
  variant, and `hh-plugin-fixture
  --mode proposer` answers the three ops
  over `plugin_abi/1` `invoke` — proven
  by a real `hh-helper` spawn in
  `hh-varhost/tests/proposer.rs` (skipped
  with a loud note where the helper is
  absent, like the isolation lanes).
- **D8 — `hh-registry` is a kernel-side
  edge for `hh-evolution`.** The
  conformance driver reports the
  registry's `ConformanceVerdict` (CC7 —
  the verdict sum has one owner); the
  `check-removability` S6.1a allowlist is
  amended to name it rather than re-shaping
  the sum per crate.

## Consequences

- A third-party `plugin_abi/1` proposer
  variant implements `declare` /
  `propose` / `select_parent` over the
  same port contract; the fixture is the
  reference witness.
- 6c (S6.3a/b) widens the family set and
  the class set; nothing here hard-codes
  one beyond the construction-time pin and
  the spec's `target_class` member.
- `predictor` is admitted by
  `policy_for("predictor")` — the earlier
  `policy_for_refuses_unadmitted` unit
  test is amended (the variant's admission
  is the ticket's own requirement).

## Revisit trigger

Reopen if a second automated family or a
second evolvable class is admitted (the
one-family/one-class pin is this stage's
bound — 6c widens it deliberately); if
`CorpusSpec.layers` needs a caller-coined
name outside the closed vocabulary (a new
layer is a spec + codec change, never a
silent admission); if `successive_halving`
must prune mid-settle rather than at
dispatch (the bracket's `kept[]` is read
at `next`, never retro-fitted); if the
`predictor` variant must spend without a
`SearchBudgetRecord` slice (D5's inert-
without-slice rule would need a new
budget owner); or if the out-of-process
suite leg must run under a placement other
than `subprocess_confined` through
`hh-helper` (D7's witness inherits the
host's gating shape).
