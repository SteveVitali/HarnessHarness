# ADR-0399: R5.21 evidence-package/1 profile — record, identity and coordinate landing decisions

- **Status:** Accepted
- **Date:** 2026-11-03
- **Ticket:** R5.21 (Native evidence profile and immutable snapshot
  coordinates)
- **Requirement ids:** REQ-F-001, REQ-F-002, REQ-A-101, REQ-A-103
  (primary targets — achieved engineered D/E recorded; full-target
  predicates stay owed per the coverage register; merged aliases
  REQ-E-208/REQ-E-010/108/109 and the §6.1 field map are *not*
  discharged by this scoped slice)
- **Spec:** docs/evidence-and-adoption-spec.md §6 (§6.1 profile and
  immutable coordinates, §6.5 legacy); Packet C (PADR-R5-3∗,
  admitted GATE-G9) items 1–2 and 5, C.3 field map, C.5 recovery,
  C.7 compatibility; docs/tickets/191_R5.21__profile.md
- **Rung (ADR-0024 obligation):** implementation landing record — the
  admitted `evidence-package/1` profile's concrete shape inside
  `hh-bundle/1`; no RPC, no new dependency, no new event class (CC10:
  the profile is a manifest member, not a ledger kind)

## Context

Packet C admits `evidence-package/1` as an additive, versioned typed
member/role profile inside `hh-bundle/1`, owned by the bundle
codec/validator — a derived index over the §6.1 member groups,
recomputable from the named authorities at the recorded watermark,
never a second authoritative store or receipt authority. R5.21 lands
the owner-bound slice its AC-1/AC-2 test: the versioned record,
create-if-absent attempt/grade-attempt/export identities, typed
head/watermark snapshot coordinates, and the unknown-version refusal.
`closure_walk`/`closure_report` (C.1 items 3–4) are R5.22's surface;
population assembly is R5.23's; producer wiring into `kernel.bundle`
is a later owner's seam.

## Decision

1. **`crates/hh-bundle/src/profile.rs` owns the record.** Schema id
   `evidence-package/1`, `PROFILE_VERSION = 1`, member role
   `evidence_profile`, media type
   `application/vnd.hh.evidence-package+json`. The R-group members
   (`profile_version`, `source_versions`, `claims`, `protocol_ref`,
   `phase`, `slot_set`, `attempts`, `grade_attempts`, `exports`,
   `native_heads`, `watermarks`, `pins`, `access`) are required *even
   when partial* — an empty list is allowed, an absent member is
   `missing_required_member`. The C-group reference sets
   (`oracle_observation_refs`, `treatment_joins`,
   `rows_analysis_refs`, `operational_evidence_refs`) belong to claim
   classes this leg does not exercise and decode as tolerated
   additive members; `legacy_refs`/`presentation_refs` are optional.
   Unknown members decode absent (additive — C.6).
2. **Identity/coordinate records are typed; metadata groups are
   required-present Json.** `AttemptRef`, `GradeAttemptRef`,
   `ExportRef`, `NativeHead`, `Watermark`, `Coord` carry
   to_json/from_json codecs because the identity and refusal
   semantics operate on them; `source_versions`/`claims`/`slot_set`/
   `pins`/`access` are validated for required-member presence and
   preserved verbatim — the codec asserts nothing it cannot check.
3. **`ProfileIndex` is the create-if-absent mint.** One identity owns
   one record: re-minting an id with byte-identical canonical JSON is
   `Retained` (idempotent — a same-day re-mint keeps one record);
   the same id against different bytes refuses
   `conflicting_identity`. A same-day *retry* is a distinct identity
   (ordinal + predecessor) retained beside the first — unique
   evidence, never collapsed, never an added n.
4. **`EvidenceProfile::check()` is the record-level closed set:**
   `conflicting_identity` (repeated ids), `grade_retry_adds_n`
   (`counts_subject` on an ordinal>1/superseding grade, or a second
   counting grade for one `attempt_id` — I-03's no-n-inflation),
   `build_note_as_wal` (a `build-note` kind in `native_heads[]` — a
   labelled build-memory snapshot is never a WAL coordinate, §6.5),
   `head_mismatch`/`missing_head` (an `exports[].last_event` or named
   coordinate that disagrees with / lacks the recorded head),
   `watermark_mismatch` (a projection watermark ahead of its recorded
   head), `malformed` (non-WAL head kind, unlabelled legacy ref).
   `check()` is pure over the record; bundle agreement is S2's.
5. **Assembly verifies declared coordinates, never caller-asserts.**
   `AssembleInputs.evidence_profile: Option<EvidenceProfile>` — when
   present, `check()` runs, then every declared `native_heads`/
   `watermarks`/`exports` coordinate naming the subject run is
   compared against the durable prefix the assembler itself derived
   (head `{seq,event_id,hash}`, watermarks, lineage prefixes); a
   disagreement is a `ProfileRefused` error and no member lands. The
   member deposits under role `evidence_profile` and the manifest
   stamps `evidence_profile{schema,profile_version,member}`.
6. **`BundleManifest.evidence_profile` is additive.** The new section
   serializes only when non-null (the `composition` pattern):
   pre-R5.21 manifests decode byte-identically, mint new version_ids
   unchanged, and validate without profile checks — legacy
   bytes/fields/levels remain valid (C.7). The section joins
   `levels::section_member_refs` so S3's member-resolution closure
   covers `evidence_profile.member`.
7. **`validate` S2 owns recipient-side profile checks.** When the
   section names a materialized member: the record must decode — a
   `schema`/`profile_version` outside the admitted family fails
   `unknown_profile_version` (the *claim* refused while the bundle
   still decodes; inspection preserved, C.5/C.6) — pass `check()`,
   and agree with the bundle's durable coordinates (subject heads +
   lineage prefixes + `traces[run].head` for exports; subject
   watermarks as the ceiling for profile watermarks; every subject
   run carries a `subject`-kind head). Failures are `fail` check rows
   in the completeness fold, never silent diagnostics.
8. **Typed refusal surface.** `BundleError::ProfileRefused { code:
   &'static str, detail }` carries `profile::code`'s closed
   vocabulary — the same codes the validation check rows report.

## Consequences

- `tests/r5_21.rs` (9 checks) exercises every AC leg against the real
  `Store`/`assemble`/`validate` seams in scratch stores — compile-red
  at base (the module, manifest field and input member are all new).
- REQ-F-001/002 and REQ-A-101/103 keep `planned; unmet` — this ticket
  records achieved engineered D/E separately from the owed legs:
  closure traversal (R5.22), population receipt (R5.23), R0
  (R5.24), recompute (R5.25), replay (R5.26), outside reviewer
  (R5.52) and the AC-6-1 producer-inaccessible recipient checks.
- No crate edge added to hh-bundle (producers pass the record in);
  no event class, no schema/wire change, no new dependency.

## Alternatives considered

- **Profile inside `ext[]` / a freeform section member** — rejected:
  `ext` is preserved-never-validated; the dossier names a typed
  member/role profile owned by the codec/validator.
- **Caller-asserted coordinates accepted verbatim** — rejected: the
  snapshot must be derived evidence; a stale or forged head under a
  valid signature would pass — the assembler compares against the
  durable prefix it reads (C.9 check 3).
- **A second create-if-absent map per record family** — rejected:
  the three id spaces are disjoint and the byte test is the conflict
  oracle either way; one map keeps the mint contract single.
- **Rejecting watermarks below head** — rejected: a projection
  watermark is a fold coordinate, legitimately behind the tip; only
  ahead-of-head and unbound watermarks are wrong.

## Revisit triggers

- If R5.22's closure walk needs the C-group reference sets typed
  (`oracle_observation_refs`, `treatment_joins`, `rows_analysis_refs`,
  `operational_evidence_refs`), revisit Decision 2 — today they
  decode as tolerated additive members under the same version.
- If a profile major `2` is admitted, revisit the
  `unknown_profile_version` boundary — the refusal then routes
  through versioned negotiation, never silent decode.
