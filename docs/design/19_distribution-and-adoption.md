**Q-6 recommendation:** one outside verifier plus 4–6 technical evaluators; overlap allowed but disclose familiarity and never double-count. Seek roughly half harness researchers/engineers and half integrators; at least two new to HarnessHarness, one receipt-first and one missing-live-prerequisite route. Roles overlap; report coverage shortfalls. Recruit through approved voluntary opt-in or separately authorized invitations; no scraped lists/bulk mail.

Start with F3 clean-install verify/recompute: pinned tools, empty recipient environment, no producer fallback; network disabled during procedures. Keep both verdicts, relationship, assistance and costs. F3 prebuilt ceiling: ≤2 wall-hours, 2 cores/4 GiB RAM, 12 GiB scratch, ≤2 GiB download/8 GiB expansion; source setup separately ≤2 hours, 4 cores/8 GiB, 20 GiB disk. Unmeasured ceilings, not promises; stop/requote on breach. $0 provider fees still incurs local cost. Fresh replication is separately quoted/admitted, outside this tranche.

Formative session: **60 minutes total**, roughly 5 context/consent, 40 participant-led tasks including setup, 15 interpretation/debrief. Record actual time and unfinished tasks at cap. Prior installation time is separate/unknown, never hidden; distinguish prepared and first-install hosts. One optional ≤15-minute consented recheck per affected participant retains the original result.

Observe unaided first; help on a blocker if wanted. Record first assistance time/type (hint, corrected command, environment fix, author execution); assisted completion stays distinct. Record role, broad familiarity, platform/toolchain, prerequisite gaps, setup and active time. Unsupported/unfunded live branches stay receipt/fixture-only, with useful-task milestone unmet.

| Question / branch | Observation → revision |
|---|---|
| What is this; what must I prepare? | Explain runtime/Lab, select route → wrong expectation/hidden cost revises entry card. |
| Did the task produce correct output; what can I change? | Separate setup, artifact/check and bounded edit → blocked execution remains blocked; lifecycle/grade confusion requires repair. |
| Which receipt claim can I check? | Find adverse result, procedure/access limits → hash/recompute mistaken for efficacy requires rewrite/recheck. |
| How do I recover/report without a run? | Find troubleshooting/G2 exit → hidden exit/missing sanitized fields revises guide/form. |
| What would help your own work? | Identify contribution steps/acceptance; explain trust/rejection and missing evidence → unclear ownership revises G2; retain “not useful”. |

Freeze a versioned comprehension rubric **before sessions**: (1) runtime executes/records; Lab plans/analyzes, (2) terminal success differs from independent task grade, (3) verify/recompute does not solve a fresh task or prove efficacy, (4) named rights/access/limitations constrain the claim. Score each asked item correct/incorrect/unclear using these criteria; not-asked is separate. Record rubric version, scorer and assistance; assisted explanations never enter unaided counts. Retain disagreements and original answers when rescoring; do not revise criteria to improve results.

One exposure risk, false scientific interpretation or broken advertised command stops affected promotion until corrected/rechecked. Navigation friction seen twice prioritizes repair, not prevalence estimation; one reproducible defect may suffice. If all task entrants are blocked, repair readiness before further recruitment; receipt comprehension cannot replace task success. Confidence ratings do not validate trustworthiness.
