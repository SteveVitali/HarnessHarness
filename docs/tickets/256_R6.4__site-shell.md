## In scope — deliverables

1. **Tokens** — `scripts/site/assets/tokens.css`: every token role of design/39 §Design tokens in both themes, the 8-slot series palette in F2's order, focus ring per tokens. [REQ-XF-101, REQ-XF-102, REQ-XF-103]
2. **`test_tokens.py`** (under `scripts/site/`; directory resolved at build time) — parses `tokens.css`, computes WCAG 2 ratios: every text and status token ≥ 4.5:1 and every meaningful non-text token (axis, band edge, needle, focus) ≥ 3:1 against panel and paper in both themes; a committed mutation lowering one token fails it (mutation (m) at test level). Commits the ratio table as the palette/contrast validator record. [REQ-XF-102, REQ-XF-103]
3. **Signature components** — needle readout (interval rule with caps + needle tick, never a bar from zero), noise-floor band, disposition stamps (eight glyphs; verbatim text + glyph + colour; filterable, never colour-only, never collapsed into "N/A", hidden or silently sorted away), receipt rail (folds to one line on narrow screens), calibration block component (fields per REQ-XF-139; R6.5 fills them), graph-paper ground (hero and empty skeletons only, never behind data); type scale, space scale, card, chip and table specs. Component guards: a chart may not mix status and series tokens; scatter/frontier components accept monogram + direct label only, never a series token. [REQ-XF-101, REQ-XF-103, REQ-XF-104, REQ-XF-105]
4. **Theme** — saved choice, then `prefers-color-scheme`, applied before first paint by an inline hashed script (design/39 F13); the toggle is `<button aria-pressed>`; with JS off the media query still applies. [REQ-XF-101]
5. **Fonts** — system mono/sans stacks only, tabular slashed-zero numerals; no font file and no font request anywhere in the output. [REQ-XF-106]
6. **Glyph and monograms** — `favicon.svg` (double frame + needle) emitted verbatim; a stdlib (`zlib`/`struct`) rasterizer writing `favicon.png` and the 1200×630 OG image (no numbers on it), byte-stable across two builds; the wordmark; `scripts/site/config/harnesses.json` (two-character monograms + display names, no numbers) with a uniqueness and coverage test; no third-party or vendor logo anywhere. [REQ-XF-107]
7. **Shell and URL map** — base templates (header with label slot, nav, footer with calibration block), every §9.2 path including the `/method/` hub, each rendering its designed absent state: typed reason, awaited schema, gate id, numberless skeleton; a committed golden all-absent site and a test that a skeleton carries no digit (the checker leg for mutation (r) is R6.6's). [REQ-XF-114]
8. **Mock pages** — the home page on phase-1 fixtures and one fixture specimen page that shows every REQ-XF-101 element and all eight stamps in both themes (REQ-XF-101's "golden HTML/CSS for fixture pages"); both carry the fixture label and are internal-profile only. [REQ-XF-101, REQ-XF-105]
9. **Mock build + presentation packet** — one stdlib command that builds the mock deterministically into a given directory, and, in the run record, the GATE-G21 packet: the command, the output tree's sha256, the page × theme × viewport matrix (1440×900, 1280×800, 390×844, 320×640; light and dark — design/39 F13), the `test_tokens.py` ratio table, and a "where to look" list mapping each signature element to a page. Screenshots are never committed as site assets. [REQ-XF-101]
