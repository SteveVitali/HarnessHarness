## Goal
Hosted CI is free on this public repository, but the chain waits for it at every boundary, and it also takes slots from the
account-wide concurrent-job limit that the operator's other repositories share. Measured from 2026-10-01 to 2026-10-20:
654 jobs and 4,406 job-minutes (each job's duration rounded up to a whole minute). 46% of those minutes were `push` runs
that duplicate a `pull_request` run on the same commit. 58% were heads that changed only `docs/` or `research/`, and
each of those still ran the full ≈ 11-minute job. The non-gating S2 boundary spike takes ≈ 3.3 minutes of every full
job. Round 3 averaged 4.8 PR runs per ticket, 3.6 of them docs-only.

This ticket makes four changes:
- one `pull_request` run per PR head;
- a fail-closed docs-only fast path that keeps the check's name and its `success` conclusion;
- the S2 spike on `workflow_dispatch` full runs only;
- one full run per gate, never one per ticket.

Projected effect on October's mix: −77 to −80% of job-minutes, and docs-only boundary heads drop from ≈ 11 minutes to
≈ 1 minute.

## Design decisions fixed by this contract
**D-A. Triggers, concurrency, permissions.**
```yaml
on:
  push:
    branches: [main]
  pull_request:
  workflow_dispatch:
permissions:
  contents: read
  actions: read
concurrency:
  group: ci-${{ github.event_name }}-${{ github.event.pull_request.number || github.ref }}-${{ github.event_name == 'workflow_dispatch' && github.run_id || 'x' }}
  cancel-in-progress: ${{ github.event_name != 'workflow_dispatch' }}
```
- A chain branch gets CI only through its PR. `implement-spec` opens the PR at the first push.
- `main` pushes still run, full. A newer `main` merge cancels the older one, as today; HUMAN-H7 records the final SHA.
- A dispatch run is never cancelled.

**D-B. The docs-only fast path.** It is decided inside the job, so the check always reports under its own name.
Path filters and `[skip ci]` are rejected because they leave a head with zero checks, which `ci-boundary` reads as
pending.
1. **Docs path:** a path that starts with `docs/` or `research/`, trailing slash included. `docsx/` is not a docs path.
   Every other path is non-docs, including `README.md`, `spec/`, `.github/` and `scripts/ci/`.
2. **Fingerprint** (`scripts/ci/fast-path.sh nondocs-tree <commit>`): the sha256 of `git ls-tree -r -z --full-tree
   <commit>` with the docs-path entries removed. **`<commit>` is always `HEAD` of the job's own checkout**: the merge
   commit on `pull_request`, the pushed or dispatched commit otherwise. Never `github.event.pull_request.head.sha`
   (absent at depth 1, and it would ignore a non-docs change on the base branch: fail-open). Use `sha256sum`, falling back to `shasum -a 256` (macOS). It works on a
   depth-1 checkout. Because `ci.yml` and `scripts/ci/` are in the fingerprint, any edit to the machinery forces a full
   run.
3. **Anchor:** an artifact named exactly `ci-anchor-v1-<job>-<runner-os>-<fingerprint>`:
   - `<job>` is `build-test-drift`, passed as `CI_ANCHOR_JOB`;
   - `<runner-os>` is `$RUNNER_OS`, so a later matrix gets one anchor per leg.
   It holds a 4-line record (`nondocs=`, `head=`, `run=`, `event=`) and is uploaded with `retention-days: 14` and
   `overwrite: true` (re-runs). Only the job's last two steps write it (D-B5), and only on a `full` path that succeeded
   on a trusted event: `push` to `main`, `workflow_dispatch`, or a `pull_request` whose head repository is this one.
4. **Decision** (`fast-path.sh decide`). The last stdout line is exactly `fast` or `full`; reasons go to stderr and to a
   `::notice title=ci-fast-path::` or `::notice title=ci-full-path::` annotation, plus one `$GITHUB_STEP_SUMMARY` line.
   `fast` only when **all** of these hold:
   - (a) `CI_EVENT_NAME` is `pull_request`;
   - (b) `CI_HEAD_REPO` equals `CI_REPOSITORY`, both non-empty;
   - (c) `CI_ANCHOR_JOB` matches `^[a-z0-9-]+$`, and `RUNNER_OS` is `Linux` or `macOS`;
   - (d) no entry under a docs path has mode `120000` or `160000`;
   - (e) the listing for the exact anchor name holds at least one artifact with `expired == false` and
     `workflow_run.repository_id == workflow_run.head_repository_id == CI_REPOSITORY_ID`.
   The listing comes from `gh api -X GET repos/$CI_REPOSITORY/actions/artifacts -f name=<name> -f per_page=20`, or,
   **only when `CI_ANCHOR_LISTING` names a file**, from that file (the self-test hook; `ci.yml` never sets it). Parse it
   with `python3` (stdlib `json`), not `jq`. Any error, empty output, unparsable JSON or missing variable answers `full`.
5. **Wiring:**
   - After checkout, these steps run in order. Each is preceded by a `# ci-mode: both — <reason>` comment (the readers scan reads
     the working tree, not docs, but it must run on every head):
     - the three self-tests, `bash scripts/ci/test-fast-path.sh`, `test-check-ci-gating.sh` and `test-full-run.sh`
       (one step is fine);
     - `bash scripts/ci/check-ci-gating.sh .github/workflows/ci.yml` (the lint, including its `--readers` scan);
     - the decision step, `id: path`, `shell: bash` (so pipefail is on), with `GH_TOKEN: ${{ github.token }}` and the
       `CI_*` variables from `github.*`:
       `mode=$(bash scripts/ci/fast-path.sh decide | tail -n 1) || mode=full; [ "$mode" = fast ] || mode=full; echo "mode=$mode" >> "$GITHUB_OUTPUT"`.
   - Every other existing step carries `if: steps.path.outputs.mode != 'fast'`, so a missing or empty output runs the
     step: the toolchain, fmt, fetch, build, test, drift and the gated spike.
   - Steps that read committed content under `docs/` or `research/` run on both paths with a `# ci-mode: both — <reason>` comment. `check-bm-tools.sh` is one.
   - The anchor steps, "Compute anchor" (`id: anchor`) and then "Upload anchor", are the **last two** steps. Both carry
     `if: success() && steps.path.outputs.mode == 'full' && (github.event_name != 'pull_request' || github.event.pull_request.head.repo.full_name == github.repository)`.
   - The `ci.yml` header gains a short block that states the step-mode convention and cites the ADR.

**D-C. The spike.** The spike step and the sheet upload carry
`if: steps.path.outputs.mode != 'fast' && github.event_name == 'workflow_dispatch'`. `continue-on-error: true` stays.
The upload gains `overwrite: true`.

**D-D. Full runs and their reader.**
- A full run is `gh workflow run ci.yml --ref <branch>`. The decision answers `full` for a dispatch, so every step and
  the spike run.
- `scripts/ci/full-run.sh read <sha> [--repo <owner/name>]` lists the `workflow_dispatch` runs of
  `.github/workflows/ci.yml`, newest first, and takes the first whose head commit is in the local clone and has the same
  `nondocs-tree` as `<sha>`. Its last line and exit code are exactly one of:
  - `full-run: pass <run-id> @<sha7> (<n> jobs)` (0);
  - `full-run: fail <run-id> (<job>: <conclusion>)` (3);
  - `full-run: pending <run-id>` (4);
  - `full-run: missing (…)` (3);
  - `full-run: unknown (<reason>)` (5).
- A pass needs status `completed`, conclusion `success`, and every job `success`. It is read-only: `gh` with its
  built-in `--jq`, plus `git`.
