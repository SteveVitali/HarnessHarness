## Acceptance criteria

- **AC-1 (derivation procedure):** a committed procedure folds verify-phase-attributed deny
  evidence — durable `security.egress.decided` deny rows (see `crates/hh-runner/src/verdict.rs`'s
  `denied_hosts` fold) plus mediator/proxy observations in harvested cell reports — into a typed
  candidate transitive verify-host set with a provenance record per host (which window/cell/
  decision row supplied it). Emitted as a `hh-…/1` committed record; deterministic — same inputs,
  byte-identical output.
- **AC-2 (retroactive acceptance):** applied to the committed smoke1 record
  (`docs/build/reports/smoke/2026-11-16-smoke1.json` and its retained harvest evidence), the
  procedure emits exactly {`download-r2.pytorch.org`, `ossci-datasets.s3.amazonaws.com`,
  `yann.lecun.com`} — no hand-listing anywhere in the path.
- **AC-3 (freeze-checker leg):** `scripts/check-fp-allowlist-amendment-epoch5.sh` (or its named
  successor leg beside `scan-verify.sh`) carries a runtime-evidence leg: the derived set is checked
  against the freeze's verify set, and an observed host absent from the freeze fails the leg with
  a typed reason — never silently extended, never silently dropped.
- **AC-4 (honesty):** derivation distinguishes verify-phase attribution from agent-phase denies
  (the `pytorch-model-cli` `allowlist_gap{download.pytorch.org}` class is agent-phase, X-06 — never
  derived); an empty evidence input emits an empty set + `n/a{no_runtime_evidence}`, not a guess.
- **AC-5 (verification):** `cargo fmt --all --check`; `cargo clippy -p <touched> -- -D warnings`;
  the package tests incl. a fails-without regression for AC-2; doc-surface checkers if docs change;

  is too short for the reports tree); supplement guard PASS/recorded-baseline noted.
