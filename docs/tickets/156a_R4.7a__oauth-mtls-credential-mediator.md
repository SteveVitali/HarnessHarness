## In scope — deliverables

1. **OAuth provider exchange** — a GitHub device-flow client (device code request, polling with `slow_down`/`expired`
   handling, token → subject via `GET /user`) feeding the existing `oauth{audience}` mediator leg; the access token is
   held broker-side and never ledgered; hermetic tests against a local issuer fixture cover success, denial, expiry,
   slow_down and forged tokens.
2. **mTLS** — `serve --http` (or the Lab MCP HTTP surface) optionally behind the R4.5c TLS server requiring client certs;
   the verified peer identity maps to a subject through a declared mapping table; `transport_absent` refusal remains only
   where TLS is not configured.
3. **Live leg `oauth-device`** (operator present) — the script prints the verification URL + user code to the operator's
   terminal (never to a ledger), polls, resolves the subject, and records `provided: yes`, the subject login hash
   (sha256) and the outcome; mTLS leg over the local test CA recorded as fixture-verified (local CA by ruling).
4. DF-S4.11-2 → DONE; ADR-0303/0351 trigger notes; BL-27 evidence for R4.16.
