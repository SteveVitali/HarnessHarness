## Goal

Complete the proxy's behaviour under failure and its mechanical spend enforcement. Stage 1, PROXY-CORE-b, builds on R6.10's deposit ordering:
- the `buffered` and `buffered_heartbeat` release modes;
- a lane-declared non-streaming read deadline;
- the §4.8 failure taxonomy with no proxy retries;
- crash recovery that settles orphans `bounded{0, reserved}`;
- `released: client_gone` receipts that are still charged;
- the Ollama catalog-identity tuple, whose change sets `drift_observed` and stops collection.

Stage 2, BUDGET, enforces [§4.4](../experiments-spec.md#s4):
- one phase proxy run per paid phase, whose root pool equals A_eff × (1 − m), with m read from the gate record, and a carried-over pool per window ([§10.1.1](../experiments-spec.md#s10-1), REQ-XH-120);
- equal per-slot slices sized by REQ-XC-126;
- a worst-case reservation taken before queueing, a halt when the bound is violated, and ≤ 3 upstream concurrency FIFO;
- no-cache planning values;
- the invariant `consumed + reserved ≤ hard` at every durable prefix.

## In scope — deliverables

**Stage 1 — PROXY-CORE-b** (commit checkpoint `R6.11 stage 1/2: release + failure` before Stage 2).
1. Release `buffered` for non-streaming requests and `buffered_heartbeat` for streaming ones: `: hh-proxy` SSE comments at the declared interval, and the surface's error event on a late failure. No delta is forwarded before the receipt is durable. [REQ-XC-110]
2. A lane-declared `nonstream_read_deadline_ms`, independent of `stream_idle_timeout_ms` (120 s). [REQ-XC-111]
3. The §4.8 taxonomy: `max_attempts = 1`; upstream status, body and `Retry-After` passed through verbatim; the proxy's own refusals are typed 401/404/400/402; one disposition per row. [REQ-XC-123]
4. Crash recovery on restart: synthesize `model.call.failed{proxy_aborted}` for every dispatched call without a terminal row, charge it `bounded{lo: 0, hi: reserved}`, and release the remainder. [REQ-XC-124]
5. A client that abandons before release gets a receipt with `released: client_gone` and is charged. The receipt carries the `queue_wait` and latency fields that the measured-stage p99 report reads. [REQ-XC-322]
6. The catalog-identity tuple goes in `ModelSnapshotRecord.snapshot_id` (`pinned = false`, `provenance = reported`). The full `/api/tags` and `/api/show` bodies go on `model.profile.probed` at run start, run end and each phase or block boundary. A tuple change sets `drift_observed` and stops collection; a cosmetic formatting change does not. The served-model expected set is lane-declared. [REQ-XC-119, REQ-XC-009]

**Stage 2 — BUDGET.**
7. One proxy run per paid phase, with the root pool equal to the root cap and one `slice` per slot. Slot exhaustion is a ledgered 402 reserve refusal, never `exhaust`. Only root exhaustion emits `control.budget.exceeded`, plus escalation and `decision{stop}`, after in-flight calls terminate; after that every admission is `refused_phase_stopped`. [REQ-XC-112]
8. A worst-case reservation before queueing, `ceil(rate_in·(body_bytes + template_overhead) + rate_out·max_output_bound)` at the uncached input rate, with `max_output_bound` = 131 072. `max_tokens` insertion is optional and recorded; the first pass inserts none. [REQ-XC-113, REQ-XC-003 per S-14]
9. Reported input tokens are checked against the reservation bound; a violation halts admissions phase-wide (`reservation_bound_violated`). [REQ-XC-114]
10. Upstream concurrency ≤ the declared bound (≤ 3) across slots and native lanes, queued FIFO in HH, with `queue_wait_ms` per call. 429, 5xx, queue-full and broken or empty streams are receipted infrastructure events; slot classification under REQ-XC-323 is R6.25's. [REQ-XC-115, REQ-XC-011 per S-15]
11. A slice validator: each slice ≥ the arm's P90 $/trial + w; slices are equal within a comparison; feasibility counts C × s. A refusal below s − w is marked premature (`inconclusive{infra:budget_reservation}`), and one at or above it is `budget_refused`. Each refusal records `requested`/`available`. [REQ-XC-126]
12. Reservations use no-cache planning values until a measured stage records the cached share per endpoint. [REQ-XC-210]
13. Root cap = A_eff × (1 − m), with A_eff = min(A, available credit) and m read from the gate record (.20 at FP-S and FP-E in the first pass). The carried pool = cap − Σ prior windows' consumed and orphans at `bounded.hi`, read from harvested proxy ledgers. An unharvested or unverified ledger refuses the next window. [REQ-XH-005, REQ-XH-120]
14. The budget allocation record cites the verbatim operator authorization. The provider balance or a period reset is never treated as authorization, and a missing authorization refuses typed. [REQ-XC-004]
