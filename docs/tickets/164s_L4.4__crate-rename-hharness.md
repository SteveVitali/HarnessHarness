## In scope — deliverables

1. **ADR — rename mechanics:** (a) lib names: default to the package name (`hharness_wire`), with `use` paths rewritten by
   the script — or keep `[lib] name = "hh_*"` — the ADR decides and records why (public-library ergonomics vs diff size);
   (b) **directories:** default keep `crates/hh-*` (the append-only build records cite thousands of these paths;
   renaming breaks provenance links) unless the ADR finds a stronger reason; (c) binary names unchanged; (d) env vars
   (`HH_*`) and wire/schema ids (`hh-embed/1`, …) unchanged — they are contract names, not crate names.
2. `scripts/rename-crates.sh` — **first, before any file is touched**, a crates.io availability check over the exact
   to-be-published set: every package `cargo metadata --no-deps --format-version 1` reports as publishable (`publish` not
   `[]`/`false` — at L4.4 that is all 51, since L4.5 sets `publish = false` later; checking the superset is conservative)
   mapped `hh-<x>` → `hharness-<x>`, plus the umbrella `hharness`; one `GET https://crates.io/api/v1/crates/<name>` per
   name (descriptive User-Agent, ≥ 1 s apart; 404 = free, 200 = taken, anything else = inconclusive). Any taken or
   inconclusive name **STOPS and asks the operator before anything is renamed** (non-zero exit, no partial rename). The
   dated per-name output is recorded verbatim in the run ledger (`docs/build/runs/L4.4.md`). Then — idempotent,
   deterministic — it rewrites manifests, dependency keys, `use`/path references,
   scripts, workflows, codegen inputs; then regenerates generated artifacts.
3. Full verification: fmt, build, test, drift, removability, xcheck-foreign — all green; the generated client + schema
   regenerate cleanly.
4. Living docs (README, AGENTS.md, crates/AGENTS.md, CONTRIBUTING, MAINTAINING) updated to the new names; build records untouched.
