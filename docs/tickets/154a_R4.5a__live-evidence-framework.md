`live-executed` (what it means, what it never means), the evidence record format, the redaction rule, the

`scripts/live-verify.sh` runner that sources `~/.config/harnessharness/live.env` (a symlink to a gitignored `.env` in the
operator's main checkout) into the kernel broker's launch
environment (names only, never echoed, never inherited by children). Proved on a zero-spend local leg.

## In scope — deliverables

1. **ADR (next free number) — the `live-executed` evidence class:** a claim is `live-executed` only when a committed
   evidence record proves an executed call against a real external or local service; it never upgrades a leg that
   was not executed; `foreign-run-verified` and `fixture-verified` stay distinct. Record format `hh-live-evidence/1`
   at `docs/build/reports/live/<date -u +%F>-<leg>.json` (under the allowed `reports/` root): date -u, ticket, leg id,
   provider, endpoint host (no path secrets), model id as reported, sha256 of the redacted request/response transcript
   (redacted transcript committed beside it when ≤ 64 KiB), token usage, cost USD (from a pinned pricing table with
   source + retrieval date), run ledger head digest (when a run is involved), result + assertion summary, git HEAD,
   harness, `provided: yes/no` per NAME used, cumulative spend after, and — for audit — the provider request id(s) and
   the non-secret response metadata headers (an allowlist of header names fixed in the ADR, e.g. `request-id` /
   `x-request-id`, served model/version, processing-time and rate-limit headers; never auth headers, cookies or keys) so
   the operator can spot-audit any record against the provider console.
2. **Spend ledger** `docs/build/reports/live/SPEND.jsonl` (append-only) + `pricing.json` (per-model rates, source,
   date; local = 0) + the per-ticket allocation table (round total USD 100: R4.5d 5 · R4.5e 5 · R4.6 15 · R4.7b 5 ·
   R4.7e 15 · L4.6 30 · reserve 25; all other live legs 0). `live-verify.sh` refuses (exit 3, "SPEND CAP — ask the
   operator") any leg whose declared budget exceeds the ticket allocation or the remaining cap; spending reserve
   needs the operator's recorded words. The ADR states that `SPEND.jsonl` is an estimate from `pricing.json`: the
   provider consoles' billing is the authority, and the operator reconciles the ledger total against the consoles at
   GATE-G6 (recorded in the readout).
3. **`scripts/live-verify.sh <leg> [--budget USD]`** — sources `live.env` without `set -x`/echo, checks required NAMES
   (`provided: no` → exit 4 "provision via HUMAN-H6"), runs the leg's gated test(s), runs the leak detectors over
   every artifact before writing it (CC1 — reuse `hh-secrets` detectors), writes the evidence record + spend entry.
   `scripts/live-verify.sh --check-names [<leg>|--all]` prints NAME → `provided: yes/no` only (never a value) — the
   scripted form of HUMAN-H6's pre-flight.
4. **Gating convention** — live tests are `#[ignore = "live — ADR-<n>: scripts/live-verify.sh <leg>"]` (or an
   equivalent the ADR chooses) so `cargo test` reports them as ignored, never passed; AGENTS.md's "`ignore`d tests
   cite a `DF-*` row" rule is amended to "…cite a `DF-*` row or the live-evidence ADR".
5. **Evidence validator** — a test (home per ADR, e.g. `crates/hh-telemetry/tests/live_evidence.rs`) that parses every
   committed record against `hh-live-evidence/1`, checks the spend ledger sums ≤ 100 and every record's spend entry
   exists — invariants only (BM-TEST-01).
6. **Proof leg `local-reachability`** — GET the OpenAI-compatible model listing at `HH_LOCAL_BASE_URL`, assert
   `HH_LOCAL_MODEL` is served; evidence record committed (USD 0).
7. **AGENTS.md gotcha 5** re-worded: `live-executed` claims are permitted only with a cited evidence record;
   `staging-verified`/`public` stay forbidden until L4.6/R4.18 earn them. OPERATIONAL_READINESS gains the class in its legend.

8. **Secret-scan gate (the repo is already public — this is the first row that commits live evidence):**
   `scripts/live-verify.sh` runs gitleaks over the **staged diff** before any evidence commit (`gitleaks protect --staged`
   or `gitleaks git --staged`, per the installed version — the form used is recorded; `--redact` always) with the
   committed config; any finding refuses (non-zero exit, nothing committed) and STOPS-and-asks the operator. A one-off
   **full-history baseline** `gitleaks detect --log-opts=--all --redact` runs once in this ticket: the known **7 fake
   test-fixture hits** (fake `ghp_live…` / `sk-live-…` literals in `crates/hh-secrets/tests/acceptance.rs`,
   `crates/hh-secrets/tests/sv.rs`, `crates/hh-telemetry/tests/acceptance.rs`) are allowlisted by path + rule in a
   committed root `.gitleaks.toml`, each entry with its reason; the baseline's count + finding fingerprints (redacted —
   never the matched text) are recorded in the run ledger. Any baseline hit outside those 7 is NOT allowlisted: STOP and
   ask (rotate the credential first). L4.3 reuses this exact `.gitleaks.toml` in CI (CC1 — one config).
