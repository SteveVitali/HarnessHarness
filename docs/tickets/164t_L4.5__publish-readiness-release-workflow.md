## In scope — deliverables

1. Workspace-inherited metadata: `version = "0.1.0"`, `repository`, `homepage`, `documentation`, `readme`, `keywords`,
   `categories`, `rust-version`, `description` per crate; path dependencies carry `version = "0.1.0"`. `rust-version` is
   declared deliberately: the pinned toolchain `1.94` unless an MSRV check (an older rustup toolchain — no new deps)
   proves a lower floor; a CI step builds the workspace at exactly that version (`cargo +<rust-version> check --workspace
   --all-targets`) so the declaration is verified, not asserted.
2. `publish = false` on fixtures/plugins/test-support (list recorded in an ADR with the rule applied per crate); the
   umbrella `hharness` (facade re-exporting the public API crates; README section on installing the binaries).
3. `scripts/publish-order.sh` — topological publish order + `cargo publish --workspace --dry-run` (or per-crate
   `cargo package` in order) green; name availability re-checked against crates.io at run time over the final publish
   set (record `date -u` + per-name result). A collision at L4.5 is a **STOP-and-ask** to the operator — never a silent
   rename or a quiet drop from the publish set.
4. `.github/workflows/release.yml` — on tag `v*` and `workflow_dispatch` (dry mode: build + checksum artifacts, no release):
   the ADR's targets (4 by recommendation), `SHA256SUMS`, attaches to the GitHub Release; SHA-pinned actions; the dry-mode run executed on this PR's
   branch and its artifact list recorded.
5. CHANGELOG `0.1.0` section filled from the round's landed work.
6. **Release ADR** (next free number; the ticket writes it — the following is the planning recommendation): (a) the
   publish set and the rule applied per crate; (b) the `rust-version` decision above; (c) the **v0.1.0 target set** —
   `aarch64-apple-darwin`, `x86_64-apple-darwin` (cross-built on the arm64 runner via `rustup target add` if no Intel
   runner is available — no new deps), `x86_64-unknown-linux-gnu`, and `aarch64-unknown-linux-gnu` **included** because
   GitHub-hosted `ubuntu-24.04-arm` runners build it natively for a public repo without new deps (if the dry-mode run
   shows that runner unavailable: STOP and ask — never silently drop a target); **Windows excluded** for v0.1.0 — the
   sandboxed-exec helper's backends are seatbelt (macOS) and podman (Linux) only, so a Windows build would ship without
   its containment floor (recorded as a revisit trigger); (d) **docs.rs readiness** — `[package.metadata.docs.rs]` where
   needed (e.g. `features`/`all-features` so `tier-c*`-gated APIs render) and a scripted check that documents each
   publishable crate under its docs.rs settings (`cargo doc -p <crate> --no-deps` with those features) green.
