## In scope — deliverables

1. **One HTTP/1.1 client codec home (shared decision owned here):** reuse the existing codec rather than adding a third
   (CC1) — if crate layering prevents `hh-gateway` from reusing `hh-env`/`hh-mcp`'s, extract the request/response codec
   into the lowest sensible home (e.g. `hh-wire`, the transport-primitives crate) and re-point the existing callers;
   record the choice in an ADR. R4.5c layers TLS beneath this codec; R4.5d/R4.7/R4.7a consume it.
2. **`HttpModelTransport: hh_gateway::Transport`** — plain HTTP for loopback endpoints (an `https` endpoint answers a
   typed `UnsupportedFeature{tls_pending}` until R4.5c); streaming responses decoded to `(arrival_ms, WireFrame)`;
   `discover` implemented for the OpenAI-compatible model listing.
3. **`GatewayModel: ModelPort`** in the composing crate (`hh-embed`): request assembly via the dialect document,
   credential via `CredentialPort` (`NoCredentials` for the local leg), frames → `ModelOutcome` (stop reason, parsed
   calls, usage on `completed`), the R2.7 routing/emission seam unchanged; a recording wrapper persists model_io so the
   existing replay path reproduces the run offline.
4. **Run-path selection** — the realized model binding (role table → profile → endpoint) selects `GatewayModel`; with no
   live binding the scripted lane runs byte-identically (regression test over an existing battery).
5. **Live leg `local-run`** (via `live-verify.sh`): a reference definition under `crates/hh-embed/fixtures/live/`
   (or the ADR's chosen path) whose profile points at `HH_LOCAL_BASE_URL`/`HH_LOCAL_MODEL`; `hh run` completes a small
   tool-using task (`hh.submit` with a checkable answer); `hh` verify on the run ledger passes; replay from the recorded
   model_io is byte-identical; evidence record committed.
6. Dated progress note on DF-S1.18-1 (the live Transport member landed for the local family).
