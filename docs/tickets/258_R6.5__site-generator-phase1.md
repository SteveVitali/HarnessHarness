## Goal

Make spec §9.3 true — a Python-stdlib generator under `scripts/site/` that reads only the committed packets named in `inputs.json`, projects them into the generated, committed, drift-checkable `hh-site-data/1` layer in integer units with per-value provenance, and implements no statistic beyond the closed derivations D-1…D-8 — and then use it to render the phase-1 and always-present pages of §9.2 (`/`, `/phase-1/`, `/method/`, `/spend/`, `/limits/`, `/changelog/`, `/data/`, `/about/`) from the real phase-1 packets and the R6.3 record's bounds block, through R6.4's approved templates. Every displayed value is traceable, interval-first and decimal-honest; negative and withheld outcomes carry the same structure and prominence as positive ones.

## In scope — deliverables

**Stage 1 — F2-b: generator core and data contract** (commit a checkpoint when green, before stage 2)

1. `scripts/site/build.py` + an `hhsite/` package, stdlib only, with a declared minimum Python version and an import-audit test; no crate reads `docs/`. [REQ-XF-117]
2. `scripts/site/config/inputs.json` — every input named by path, schema and phase, never globbed; unknown schema or missing input exits 2. [REQ-XF-119]
3. The `hh-site-data/1` envelope and files under `docs/results/site-data/` (`manifest.json`, `phase1.json`, `spend.json`, `method.json`, `claims.json`, `changelog.json`; later files as typed-absent stubs or omitted per §9.3): canonical JSON (sorted keys, compact separators, trailing newline), integer micro-units and ppm, no wall-clock timestamp, a `profile` field (`internal`; the public profile's refusals are R6.6's); registered in `docs/README.md` as mode generated. [REQ-XF-120]
4. Value objects `{v, lo, hi, unit, interval{kind, level_ppm}, n{tasks, k}, src{path, sha256, ptr}, label}`; absent values only as typed objects (`not_computed`, `not_yet_available`, `refused`, `undefined`), never null or 0. [REQ-XF-122]
5. The derivation registry D-1…D-8, each unit-tested, plus a code-audit test that finds no derivation outside it; a view whose estimator is not in the packet shows "not computed (<reason>)". [REQ-XF-118]
6. The precision formatter (D-2): no digit finer than about one-tenth of the interval half-width, never more digits than the packet holds. [REQ-XF-021]
7. Provenance: every displayed value carries `data-src` (path#pointer) and `data-sha`; a resolver test verifies hash, pointer and formatted value. [REQ-XF-121]
8. Hygiene: the projection copies no local or host-specific field (`/Users/`, `/home/`, `~/` refused). [REQ-XF-125]
9. Figure anatomy and scales over R6.4's components: `<figure>` with title, definition/direction subtitle, chart, receipt rail, "How to read this" block and an always-present data table; rates on a fixed 0–100 % domain, cost axes as labelled log scales, interval rule with caps and needle tick, unseparated intervals as outlines; cost-view primitives ($/trial, $/solve, total vs authorized; Pareto among complete entries, captioned descriptive); everything pre-rendered and readable without JS. [REQ-XF-108, REQ-XF-109]

**Stage 2 — F2-e: phase-1 and always-present pages**

10. `/` with real phase-1 tiles and the three "what we don't claim" lines; `/phase-1/` (bounds verbatim, tranche counts, cross-check, estimator outcomes, dispositions, costs); `/method/`, `/spend/` (round 5 shows `compute: unrecorded{pre_schema}`), `/limits/`, `/changelog/`, `/data/` (packet index + recompute recipe), `/about/`; `claims.json` derivation. [REQ-XF-141, REQ-XH-020]
11. Phase-1 caveats copied verbatim from the record's `bounds` block; tranche 3's `verified` appears only with bound 1 and "descriptive, no margin registered", never as "parity verified". [REQ-XF-141]
12. Page headers carry the REQ-XD-092 labels that apply to the phase, card state and evidence class, plus "internal record; not outside-verified" until a graduation record exists. [REQ-XF-116]
13. The calibration block filled on every page: experiment id, site version, source commit, packet-set digest and file count, generator version, evidence class, recompute command. [REQ-XF-139]
14. Typed-disposition fixtures (one per negative, inconclusive, declined and withheld outcome, incl. R5.59's `unmet{s1_failed}`) render with the same structure and prominence as positive ones. [REQ-XH-020]
