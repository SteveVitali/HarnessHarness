## Driver design (implementation notes — the `HH_*_DRIVER` wiring)

Mapped against committed surfaces + the retained W2 session (`~/hh-retained/w2/`). The
drivers compose existing machinery only — no new schema, record kind, or codec.

**Controller-side drivers** (cloned from retained `~/hh-retained/w2/bin/hh-ps0-driver`):
`hh-pp0-driver`, `hh-corpus-driver`, `hh-l1-driver` — each validates its env
(`HH_{PP,CORPUS,L1}_BASE_URL` + `HH_{PP,CORPUS,L1}_SLOT_TOKEN(S)`), writes the slot token(s)
to a `umask 077` remote file over `gcloud compute ssh` stdin (never argv), invokes the on-VM
driver, and `scp`s the folded evidence back to `HH_{PP_EVIDENCE_DIR,CORPUS_DIR,L1_DIR}`.

**On-VM session shim** `ws1-proxy-session.py` (clone of retained `w2-proxy-session.py`,
committed `scripts/gce-backend/`): spawns `hh-model-proxy`, `configure{store_root, run_id,
listen 127.0.0.1:<port>, lane, credential_env OLLAMA_API_KEY, authorization, mode}` →
`register_slot{slot_id, effort, slice_micros}` per declared slot → writes `session.json`
grants → holds to sentinel → `revoke_slot`/`seal_recording`/`stop`. Adds `--mode
live|record|replay` + `--replay-file` over W2's live-only shim: `record` for the corpus leg
(proxy mints `hh.model_proxy.recording/1` per sealed slot), `replay` for the L1 legs
(recordings + canonicalizer + strict + keying per §7.4), `live` for PP0. Registered
model-port band 49152/49153 — never 8080 (model-port guard, R6.45n).

**On-VM leg drivers** (`scripts/gce-backend/ws1-{pp0,corpus,l1}-driver.py`, modeled on
committed `w2-ps0-driver.py`): orchestrate cells, read the proxy run's `events.wal` for
receipts/captures, fold the leg records.

**The hosted-arm cell drive — `hh-w1 arm-run`** (new subcommand in
`crates/hh-runner/src/bin/hh_w1.rs`, reusing `h_run_once` internals): `stage_task` → layer
image (`hh-layer-<arm>-<task>` from the R6.32b carried-export digests, loaded at LOAD by
digest) → `MediatedCell` + `admit_allowlist_mediated` + `mediated_phase_schedule` +
egress-mediator spawn (same as `h_run_once`'s mediated arm) → `render::render(rec,
SlotInputs{slot_token, model_port, instruction, home, user, agent_wall_timeout_s,
proxy_budget_ceiling_usd_micros, slot_id}, RenderUse::HostedArm)` gives the closed
`{argv, env, files}` (token elided in the recorded `hh-harness-render/1` via
`rendered_record`) → relay topology unchanged (in-cell `hh-cell-relay` binds
`127.0.0.1:model_port`/`egress_port` → host unix sockets) except the host-side `model.sock`
is answered by a unix→TCP forwarder to the session proxy's `127.0.0.1:<listen>` (a small
python bridge spawned per-cell — the Wc stub's shape, forwarding) → `exec_guarded` for
agent (`agent_ms` from `task.toml`) + verifier (`/tests/test.sh`) → cell report + mediator
rows + trajectory artifacts out.

**PP0 fold** — per (task × arm) trial: `hh-pp0-ag-evidence/1` `{schema, harness, trial_ref,
checks:{AG3,AG5,AG6,AG8: pass|fail|n/a}}` — AG3 terminal exit state (cell report), AG5
egress rows ⊆ proxy route + `expected_denied` (mediator rows), AG6 every model call
receipted (proxy events.wal ↔ trajectory count), AG8 no endpoint-attributable protocol
errors. Outcome fields `withheld{sealed_until_results}` — never verdict (REQ-XH-121).
Held arm → `withheld{admission:AG<n>|pp0_infra_hold}` verbatim.

**Corpus fold** — 28 record-mode slots (7 dev tasks × 4) → `seal_recording` →
`hh.model_proxy.recording/1` per trajectory → `hh-l1-corpus/1` + partition digest
(`f7ddbc1f…` binds dev/gate-A/gate-B by task — gate-A = 8 trajectories).

**L1 fold** — replay-mode proxy serves each gate-A recording (strict, declared
`hh-l1-canon` version): L1.0 = real mini cells ×2 against the replay listener → request
captures → stable prefix; L1.1 = kernel-embedded `hh run start` of the frozen HIR
(`hh_kernel acc91fd0…`, set `c451ed97…`) against strict replay + observation replay →
first-divergence `hh-l1-diff/1`; L1.2 = same H against replay + live exec → compare
through the stable prefix only. `l1_pass_id` recomputed from exact H identity +
canon version + corpus digest → `hh-l1-conformance/1`. **Open design point:** the
in-cell observation-replay executor for L1.1 (fixture `l1_obs::ObsReplay` is in-crate;
the live seam needs a replay env/exec adapter — the kernel env plane or a cell-side
observation shim — flag at implementation if no committed surface admits it).

**Secrets/credentials:** `OLLAMA_API_KEY` rides the session shim's launch env only
(credential_env naming); slot tokens over ssh stdin/tmp files only; historical W2
session.json grants never reused — fresh `register_slot` mints. All output drained +
transcripts persisted (`exec_guarded` + driver tee), preserved on timeout.

**H-drive seam resolved (2026-11-17):** the kernel's model calls bind through
`slots["model_port"]` on the run's AgentProcess — `hh/gateway_http` with
`{dialect, endpoint, provider_model_id, credential_ref?, provider_params?}`
(the r4_5b/r4_5d_live fixtures bind `endpoint: "env:HH_LOCAL_BASE_URL"`).
The L1 H legs are therefore `hh run start` of the frozen HIR with the
`model_port` slot's `endpoint` set to the replay session's
`http://127.0.0.1:<listen>` — the replay proxy serves the recorded
responses and receipts/captures each upstream-bound request (the
comparison inputs). **Still open:** L1.1's observation-replay exec —
the fixture `l1_obs::ObsReplay` is in-crate only; the live seam needs
either a replay environment variant for the run's `environment`/env
plane or a cell-side observation shim. If no committed variant admits
it, L1.1 records `withheld{l1_obs_replay:env_variant_absent}` and the
conformance record carries the honest partial-leg result — never a
fabricated pass.
