## Driver design (implementation notes — the `HH_*_DRIVER` wiring)

Mapped against committed surfaces + the retained W2 session (`~/hh-retained/w2/`). The
drivers compose existing machinery only — no new schema, record kind, or codec.

**Controller-side drivers** (cloned from retained `~/hh-retained/w2/bin/hh-ps0-driver`):
`hh-pp0-driver`, `hh-corpus-driver`, `hh-l1-driver` — each validates its env
(`HH_{PP,CORPUS,L1}_BASE_URL` + `HH_{PP,CORPUS,L1}_SLOT_TOKEN(S)`), writes the slot token(s)
to a `umask 077` remote file over `gcloud compute ssh` stdin (never argv), invokes the on-VM
driver, and `scp`s the folded evidence back to `HH_{PP_EVIDENCE_DIR,CORPUS_DIR,L1_DIR}`.

**On-VM session shim** `ws1-proxy-session.py` (clone of retained `w2-proxy-session.py`,
committed `scripts/gce-backend/`): spawns `hh-model-proxy`, `configure{store_root, run_id,
listen 127.0.0.1:<port>, lane, credential_env OLLAMA_API_KEY, authorization, mode}` →
`register_slot{slot_id, effort, slice_micros}` per declared slot → writes `session.json`
grants → holds to sentinel → `revoke_slot`/`seal_recording`/`stop`. Adds `--mode
live|record|replay` + `--replay-file` over W2's live-only shim: `record` for the corpus leg
(proxy mints `hh.model_proxy.recording/1` per sealed slot), `replay` for the L1 legs
(recordings + canonicalizer + strict + keying per §7.4), `live` for PP0. Registered
model-port band 49152/49153 — never 8080 (model-port guard, R6.45n).

**On-VM leg drivers** (`scripts/gce-backend/ws1-{pp0,corpus,l1}-driver.py`, modeled on
committed `w2-ps0-driver.py`): orchestrate cells, read the proxy run's `events.wal` for
receipts/captures, fold the leg records.

**The hosted-arm cell drive — `hh-w1 arm-run`** (new subcommand in
`crates/hh-runner/src/bin/hh_w1.rs`, reusing `h_run_once` internals): `stage_task` → layer
image (`hh-layer-<arm>-<task>` from the R6.32b carried-export digests, loaded at LOAD by
digest) → `MediatedCell` + `admit_allowlist_mediated` + `mediated_phase_schedule` +
egress-mediator spawn (same as `h_run_once`'s mediated arm) → `render::render(rec,
SlotInputs{slot_token, model_port, instruction, home, user, agent_wall_timeout_s,
proxy_budget_ceiling_usd_micros, slot_id}, RenderUse::HostedArm)` gives the closed
`{argv, env, files}` (token elided in the recorded `hh-harness-render/1` via
`rendered_record`) → relay topology unchanged (in-cell `hh-cell-relay` binds
`127.0.0.1:model_port`/`egress_port` → host unix sockets) except the host-side `model.sock`
is answered by a unix→TCP forwarder to the session proxy's `127.0.0.1:<listen>` (a small
python bridge spawned per-cell — the Wc stub's shape, forwarding) → `exec_guarded` for
agent (`agent_ms` from `task.toml`) + verifier (`/tests/test.sh`) → cell report + mediator

**PP0 fold** — per (task × arm) trial: `hh-pp0-ag-evidence/1` `{schema, harness, trial_ref,

**Resolution — the L1 H-leg seams (2026-11-17, supersedes the two
notes above):** re-reading spec §7.4's leg table, L1.0 is "O twice
against REPLAY(S) in fresh cells" — O executes LIVE; arm-run +
replay-mode session covers it verbatim (the earlier note's claim that
O needs obs replay was the fixture's determinism, not the spec's
requirement). The obs-replay executor is needed only for **H in
L1.1**, and it is already committed: `l1_obs::ObsReplayExecutor`
implements `hh_env::executor::ToolExecutor`, and `dispatch.rs`

a runner-side drive that instantiates the HIR run with (a)
`slots[model_port]` → the replay listener (L1.1/L1.2), (b) the
executor bound as `ObsReplayExecutor` for L1.1 vs the normal
cell/`HelperExecutor` path for L1.2, (c) upstream-request capture for
the `L1Drive` docs the committed `l1_gate` fold compares. No schema
or contract change is needed — the surface composes existing seams.
Until it lands, `ws1-l1-driver.py` continues to emit typed withholds
for the H legs.

**L1 host surface — implementation blueprint (2026-11-17):** all
committed seams verified; the surface composes them, no schema or
contract change:

- **Service:** `EmbedService::open(ServiceConfig{store_root, ws,
  holder})` in-process (the cap_2_composed pattern); boundary ops via
  `handle(Request{method, params})`.
- **Run/session:** `open_session{kind:"new", spec}` on the frozen
  HIR doc with `spec.exec` = `ExecArmDecl{env:"session", surfaces}`
  naming the exec tool surfaces and `slots["model_port"]` =
  `hh/gateway_http` `{dialect:"openai-compatible@1", endpoint:
  "http://127.0.0.1:<listen>", provider_model_id}` — the realized
  `model_lane` → `GatewayModel` at `drive` (service.rs:~1693,
  R4.5b/DF-S1.18-1), the replay proxy as upstream, its receipts the
  upstream-bound request captures.
- **Executor substitution (L1.1):** armed caps live on the session's
  `exec_caps: Vec<ExecCap>`; `ExecCap.executor: Box<dyn ToolExecutor>`
  is pub. Add a bounded `EmbedService` accessor —
  `rebind_exec_executor(sess_id, surface_id, Box<dyn ToolExecutor>)`
  — the L1 host swaps each cap's executor to
  `l1_obs::ObsReplayExecutor::new(obs_a)` before `drive`. `executor::
  bind` refusal on a requirement the double cannot satisfy is the
  honest typed row, never a downgrade.
- **L1.2:** the same surface with `spec.exec` armed normally —
  `HelperExecutor`/cell env — no substitution.
- **Drive:** `drive(sess_id)` runs the compiled-H control loop
  (model calls → replay endpoint; exec → the substituted executor);
  `surface_events(run_id)` + proxy receipts yield the `L1Drive` doc
  (requests, parsed/executed actions, termination, submission,
  extra_request, refusal) the `l1_gate` fold consumes.
- **Surface name:** `hh-w1 l1-h-run --hir <doc> --spec <open-spec>
  --endpoint <url> --obs <raws.json> --mode obs_replay|live --out
  <drive.json>`; `ws1-l1-driver.py` invokes it per (trajectory, leg).
