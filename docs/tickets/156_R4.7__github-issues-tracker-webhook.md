## In scope — deliverables

1. **`github-issues` adapter** — `work_source_adapter/1.0` ops (`capabilities`, `occurrences`, `suspended`,
   `activate_run`, `list`, `get`) over the GitHub Issues REST shapes, packaged as a plugin variant run through
   `hh-varhost` at `subprocess_confined`; hermetic tests over recorded request/response fixtures (recorded from the
   sandbox run, secrets redacted).
2. **Signed ingress** — `fleet.webhook_ingress` verifies `X-Hub-Signature-256` over the raw body with the secret
   resolved by `key_ref` through the broker; delivery-id occurrence keys + replay-window dedupe reused (CC1).
3. **Tunnel + registration script** `scripts/live-github.sh` — starts the ingress listener on loopback, starts
   `cloudflared tunnel --url http://127.0.0.1:<port>`, reads the quick-tunnel URL, registers the hook via the API,
   creates a test issue/comment, waits for the signed delivery, then deletes the hook and closes the issue (trap-guarded).
4. **Live legs** (`live-verify.sh github-live`): capability probe, `list`/`get` against the sandbox, signed delivery →
   reconciler → `WorkItem` (dedupe + stale-window no-op checked), out-of-process placement per AC-R-2.12.6-9;
   evidence committed; the hook's deletion confirmed in the record.
5. DF-S5.6-1 → DONE; row 082 dated note (the checkbox stays the operator's — BM-GATE-07); R-2.12.6 evidence for R4.16.
