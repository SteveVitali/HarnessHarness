## Goal

Close G18 (spec §7.3): today, in the live exec path, the model never sees command output — it receives a ledger record or `{"kind":"no_observation_recorded"}`. After this row, every armed exec observation produces a model-view rendering, applied from the capability's `ResultRenderSpec` (R6.36) to the raw output, with the rendering's content address recorded durably **before** the request that carries it; replay and resume re-serve the recorded rendering (REQ-XE-109). This is the last E2 row before the AR-24 amendment gate (GATE-G24).

## In scope — deliverables

1. On a surface-armed session, every armed exec observation resolves the durable `raw_output_ref`, applies the capability's `ResultRenderSpec`, stores the rendered string as a durable blob, and records its content address on `context.observation.recorded` (an additive payload member, absent-not-null) before the request that carries it is built. *(REQ-XE-109)*
2. The transcript renderer (R6.35's single renderer) places the recorded rendering in the `tool` message; replay and resume dereference the recorded address and never re-render. *(REQ-XE-109)*
3. Unarmed sessions and definitions without a `ResultRenderSpec` keep today's behaviour byte-identically (including `no_observation_recorded` where it is emitted today).
4. Regression battery (e.g. `crates/hh-embed/tests/r6_37.rs`): live-model-over-replay fixture and kill-point test.

## Out of scope

- New renderer kinds or parameters (R6.36); submit-marker detection on the settled raw output (R6.38); `exec_defaults`, merged stdio and timeout rendering (R6.39); any new event class (CC10). No spend.
